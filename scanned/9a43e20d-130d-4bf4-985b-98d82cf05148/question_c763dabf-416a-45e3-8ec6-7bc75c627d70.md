Target: `Shipit::Stack#next_commit_to_deploy` (app/models/shipit/stack.rb) `deployable_commits` selection under `maximum_commits_per_deploy`. Attacker action: forge cross-sha `success` on the earliest blocking commit in a batch so that `deployable_commits(commits_with_max_applied)` now returns a later, attacker-uninvolved commit as deployable, causing the victim stack to deploy further than the legitimate CI state of the batch would allow. Preconditions: victim stack has `maximum_commits_per_deploy` set and multiple undeployed commits, the earliest of which shares a sha reachable by the attacker. Call sequence: `StatusHandler#process` -> commit flips -> `Stack#next_commit_to_deploy` -> `deployable_commits` -> `find(&:deployable?)` returns further commit -> `trigger_continuous_delivery`/`trigger_deploy`. Binding: organization whose webhook unblocked the earliest commit in the batch == organization owning the batch/stack; it does not. Scoped impact: Critical, alters the selected deploy target (which commit ships) for a foreign tenant's stack. Proof idea: minitest test asserting `stack.next_commit_to_deploy` returns a different commit before vs. after the foreign-repo webhook is applied to the earliest commit in the undeployed batch.
