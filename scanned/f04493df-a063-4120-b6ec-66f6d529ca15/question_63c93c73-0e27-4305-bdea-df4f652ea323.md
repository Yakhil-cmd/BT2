[File: dynamic_object_field.move] [Symbol: borrow_or_add / borrow_mut_or_add macros] These macros evaluate `exists<$Name>(o,name)` and conditionally call add(o,name,$default) before borrowing. If `$default` itself is an expression with side effects that mutates `o` (the same &mut UID) before the borrow completes — e.g., $default constructs a new object and, as part of construction, adds another dynamic field to the same parent — can this reentrant self-mutation invalidate the just-computed `exists` result, leading add() to abort with EFieldAlreadyExists or, worse, to silently add a duplicate marker whose address collides with the first, corrupting the parent's dynamic field table? Proof idea: pass a $default expression that itself calls dynamic_object_field::add on the same UID and name before returning the default value, and check for double-registration or field-table corruption.
