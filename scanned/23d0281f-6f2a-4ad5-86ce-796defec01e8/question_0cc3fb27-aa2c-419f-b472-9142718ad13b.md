Target: Shipit::Webhooks::Handlers::Handler#stacks/#repository_name and Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#process. Attacker action: open a pull request on a repository they do not administer but that has any Shipit repository record with a matching `full_name`, sending `pull_request.head.ref` set to an arbitrary string containing shell metacharacters (e.g. `$(id)`) and a `pull_request.number` chosen to collide with an existing stack's `environment`. Preconditions: `provisioning_behavior_allow_all?` is enabled for the target repository. Call sequence: `OpenedHandler#process` -> `ReviewStackAdapter#create!` -> `stack_attributes` sets `branch: params.pull_request.head.ref` and `environment: \"pr#{params.number}\"` directly from the payload with no sanitization, and this `branch` later feeds `StackCommands#fetch`/`git_clone` args. Binding that breaks: the `branch` value written into the `Stack` row must equal a ref actually reachable/approved on the named repository, but any string in the JSON body is accepted verbatim. Scoped impact: Critical — an attacker-controlled string becomes a `git clone --branch <value>` shell argument reaching `Command#start`. Proof idea: minitest posting a crafted `pull_request_opened` payload with a branch value containing shell metacharacters and asserting the resulting `Command#args` passed to `PTY.spawn`.
