CheckSuiteHandler#process has no rescue or explicit tenant check when `Repository.from_github_repo_name(repository_name)` returns nil for a not-yet-created Repository row, relying entirely on `|| Stack.none` in Handler#stacks. Attacker action: POST a check_suite webhook signed with a webhook_secret for a GitHub organization that HAS a Shipit App installation configured (so `Shipit.github(organization: repository_owner)` succeeds and `verify_signature` passes) but where `repository.full_name` names a repository string that is not yet a `Shipit::Repository` row, then rely on any later reconciliation code (e.g. repository auto-creation elsewhere) to create a Repository row using attacker-supplied `repository.full_name` casing/content. Precondition: none beyond a configured org. Call sequence: verify_signature passes (legitimate org secret) -> CheckSuiteHandler#process finds Stack.none -> no-op. Binding: this specific path resolves to Stack.none, so no mutation occurs -- explicitly confirming this is NOT an exploitable gap in this handler by itself (negative-control finding), scoped as informational rather than Critical. Impact: none directly in this file; documents that `Stack.none` correctly closes off further processing for unknown repositories, which should be preserved when this handler is touched by future changes. Proof: minitest test posting a valid check_suite payload for a `repository.full_name` that has no matching Repository row and asserting `RefreshCheckRunsJob.perform_later` is never enqueued.
