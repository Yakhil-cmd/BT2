In CheckSuiteHandler#process, `params.check_suite.head_branch` is an ExplicitParameters-validated String with no format or ownership constraint. Attacker action: open a pull request from a fork and name the branch identically to another tenant's protected branch (e.g. 'production'), then emit (or have GitHub emit) a check_suite webhook whose `check_suite.head_branch` equals 'production' for the attacker's own repository. Precondition: Repository A has a Stack with branch 'production'; attacker owns Repository A (webhook verified with A's own secret, which is legitimate for A). Call sequence: Handler#stacks scopes by Repository.from_github_repo_name(repository_name) so this is same-repo -- but if any stack under the SAME repository shares that branch string, `stacks.where(branch: ...)` returns it without checking `check_suite.head_sha`'s actual ancestry against `head_branch`. Binding: the `head_branch` string in the payload == the branch the resolved Stack#branch actually tracks with a HEAD matching `head_sha`. Impact: Critical if this reaches `stack.schedule_merges` via Commit#add_status state transitions triggered later by refreshed check runs, ultimately an unauthorized deploy trigger for a stack the attacker's PR never targeted. Proof: minitest test creating two Stacks with same branch name under different repos, verifying CheckSuiteHandler#process only touches the Repository matching payload's full_name, and asserting no cross-stack mutation when head_sha does not belong to that stack's history.
