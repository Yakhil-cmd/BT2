Target: `Shipit::CCMenuUrlController#client` and `#fetch`. Attacker action: an unprivileged but authenticated Shipit browser user (any GitHub user who can complete OAuth, e.g. not a maintainer of the target stack's repo) requests `GET /stacks/:owner/:repo/:env/ccmenu` for a stack they have no permission over. Preconditions: `current_user` is any signed-in user; `Stack.from_param!(params[:stack_id])` resolves to a stack outside the user's normal write/deploy authorization scope but the route itself has no per-stack authorization check before `#fetch` executes. Call sequence: `#client` calls `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` -- note it does NOT pass `stack_id:`, so the created/found `ApiClient` has `stack_id` nil, meaning `stack_id?` is false and `Shipit::Api::BaseController#stacks` returns `Stack.all`, giving this token read access to every stack, not just the one requested in `#fetch`. The URL returned embeds this unscoped token. Binding: the stack an API request touches ∈ the stacks `current_api_client.stack_id` authorises -- here stack_id is nil so the authorised set is *every* stack, not just the one the URL nominally names. Scoped impact: Critical, a URL minted for one stack silently grants `read:stack` on all stacks across all tenants/repositories.
