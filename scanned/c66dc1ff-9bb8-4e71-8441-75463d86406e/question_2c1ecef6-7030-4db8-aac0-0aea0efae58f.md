Target: Shipit::Command#start and Command#unbundled_env (lib/shipit/command.rb). Attacker action: a PR/review-stack branch's `shipit.yml` sets `machine.environment.PATH` (consumed by `DeploySpec#machine_env`) to a directory the attacker controls followed by the real PATH, and a step in `deploy.steps` invokes a bare command name (e.g. `bundle install`). Preconditions: review-stack config is read from the PR's own branch, and `TaskCommands#env`/`DeployCommands#env` calls `.merge(deploy_spec.machine_env)` after the hardcoded `'PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}"` set in `Command#unbundled_env`. Call sequence: `Stack#trigger_deploy` -> `DeployCommands#perform` -> `Command#start` -> `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)`. Binding: the `PATH` key resolved at spawn time == the value fixed by `Command#unbundled_env`'s `BASE_ENV.merge('PATH' => ...).merge(@env.stringify_keys)`, i.e. `@env` (attacker's `machine_env`) is merged LAST and can overwrite `PATH`. Scoped impact: Critical RCE on the deploy host if `@env['PATH']` from `machine_env` wins the merge and a step calls a bare binary name resolvable from attacker's PATH entry. Proof idea: minitest instantiate `Command.new('bundle install', env: {'PATH' => '/tmp/attacker:' + ENV['PATH']}, chdir: '.')` and assert `command.unbundled_env['PATH']` starts with `/tmp/attacker`.
