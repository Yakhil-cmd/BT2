Target: Shipit::Command#parse_arguments and Command#initialize (lib/shipit/command.rb). Attacker action: an unprivileged contributor adds a `deploy.steps` or `tasks.<id>.steps` entry to `shipit.yml` on their fork/PR branch containing a Hash form step, e.g. `{'echo $FOO' => {'timeout' => '999999999999999999'}}`, where the Hash's second element is attacker-controlled. Preconditions: `Shipit.respect_bare_shipit_file?` true and the stack pulls `shipit.yml` from the PR/review-stack branch. Call sequence: `DeploySpec#task_definitions` -> `TaskDefinition.new` stores `@steps` verbatim -> `TaskCommands#perform` builds `Command.new(command_line, env:, chdir:)` -> `Command#parse_arguments` merges `argument.values.first` into `options` and keeps `argument.keys.first` as the arg string. Binding: the bytes handed to `PTY.spawn` == the step string exactly as written in `shipit.yml`, unless overridden through the options Hash. Scoped impact: Critical, RCE via `timeout` option is bounded, but this proves that `options.merge!` accepts attacker-defined non-timeout keys silently. Proof idea: minitest asserting `Command.new({'true' => {'unexpected_option' => 'x'}}, chdir: '.').args == ['true']` and no unexpected key influences argv.
