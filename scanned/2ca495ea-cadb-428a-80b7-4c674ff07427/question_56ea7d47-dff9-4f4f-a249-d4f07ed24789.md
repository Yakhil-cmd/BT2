Target: `Shipit::GitHubApp#verify_webhook_signature`. Attacker action: POST /webhooks with `X-Hub-Signature: sha256=<anything>` (note: not `sha1=`) for a `membership` event body naming a team in `Shipit.github_teams`. Preconditions: any configuration, secret set or not. Call sequence: `verify_webhook_signature` does `algorithm, signature = signature.split('=', 2)`; `return false unless algorithm == 'sha1'` only rejects the mismatched algorithm branch, but if `webhook_secret` is blank the earlier `return true unless webhook_secret` already short-circuited before reaching that check, meaning the header content is irrelevant whenever the org lacks a secret. Binding: the organization whose `webhook_secret` verified the body == the organization owning the team mutated - broken identically to the no-header case. Impact: Critical, authentication bypass regardless of what signature header is sent. Proof idea: minitest sending malformed/absent-algorithm signature headers against a secretless-org config and asserting the membership handler still runs.
