Shipit::Command::BASE_ENV is computed once at class-load time as Bundler.unbundled_env (or clean_env) merged with ENV.keys - unbundled_env.keys mapped to nil. Does any per-Command @env value keyed identically to a BASE_ENV key (e.g., 'PATH', 'RUBYOPT') get silently overridden by BASE_ENV.merge(...).merge(@env.stringify_keys), or can an attacker-controlled stack.env value for 'RUBYOPT' survive into unbundled_env and get passed to PTY.spawn for a subsequent git subprocess? Impact: Critical, RCE via RUBYOPT/env injection surviving to PTY.spawn. Proof: test setting Command.new(..., env: {'RUBYOPT' => '-e puts 1'}) and asserting whether unbundled_env retains it verbatim.
