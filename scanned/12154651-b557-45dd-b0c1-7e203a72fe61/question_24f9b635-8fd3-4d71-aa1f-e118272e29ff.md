In Shipit::Commands.for(model), "#{model.class.name}Commands".constantize.new(model) is called with model.class.name derived at runtime. If any code path constructs a Commands.for(model) using a class name assembled in part from webhook- or PR-derived strings (e.g., dynamically named review/task models), can an attacker influence model.class.name to constantize into an unintended Commands subclass, breaking the binding that the invoked Commands class corresponds only to the authenticated model type? Impact: Critical if it enables an unrelated command class to run against attacker data. Proof: test asserting Commands.for only ever receives static, non-attacker-derived class names in every call site.
