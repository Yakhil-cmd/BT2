Target: Shipit::ReviewStack#env and Shipit::PullRequest#labels. Attacker action: as an unprivileged contributor with the ability to add arbitrary labels to their own open pull request (label creation on one's own PR requires no special repo permission if the repo allows public label application, or via the labeled webhook payload directly), add a label named e.g. 'PATH' or 'GITHUB_TOKEN' or 'GIT_ASKPASS' or 'BUNDLE_GEMFILE'. Preconditions: repository.review_stacks_enabled true, a ReviewStack exists for the PR (created by OpenedHandler). Call sequence: LabeledHandler#process -> stack persists pull_request.labels including the attacker label name; later Shipit::TaskCommands#env or Shipit::DeployCommands#env calls @stack.env which calls ReviewStack#env merging pull_request.labels.each_with_object({}){|label_name, labels| labels[label_name.upcase] = 'true'} with NO key allowlist, then TaskCommands#env further merges this into the hash eventually passed to Command.new(env:) -> Command#unbundled_env -> PTY.spawn. Binding: the set of keys ReviewStack#env may introduce into the deploy/task environment must be disjoint from control-plane keys like GITHUB_TOKEN, GIT_ASKPASS, PATH, BUNDLE_GEMFILE, LD_PRELOAD that Command#unbundled_env and TaskCommands#env rely on for their own semantics -- i.e. attacker-controlled label-derived keys ∩ privileged keys == empty set, and this invariant is never enforced anywhere in this file. Impact: Critical, RCE/credential exfiltration -- an attacker-chosen label name becomes an unescaped environment KEY reaching PTY.spawn, capable of overriding GITHUB_TOKEN or PATH for every subsequent shell step of every deploy/task run against this stack. Proof idea: minitest test (mirrors test/lib/shipit/task_commands_test.rb pattern) setting stack.pull_request.labels = ['github_token'] or ['path'] and asserting Shipit::TaskCommands.new(task).env['GITHUB_TOKEN'] or ['PATH'] is overridden to 'true' rather than the value Command#unbundled_env / Shipit.github.token would have produced.
