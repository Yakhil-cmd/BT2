In app/controllers/shipit/webhooks_controller.rb#verify_signature, repository_owner is read via params.dig('repository','owner','login') from the same unverified request.raw_post that Shipit.github(organization: repository_owner).verify_webhook_signature then checks. Can an attacker who controls a repository under OrgA (and therefore legitimately owns OrgA's webhook_secret) send a POST /webhooks whose top-level 'repository' object names OrgA (so signature verification passes) but whose nested payload fields (e.g. pull_request.base.repo.full_name or a second 'repository' key read later by Handler#repository_name) name OrgB's repository, so that PushHandler#process or PullRequest::ReviewStackAdapter#create! writes/archives a Stack belonging to OrgB? Binding: repository_owner used in verify_signature == the repository named in Handler#repository_name used by the handler. Impact: Critical, cross-repository write into OrgB's Stack from a payload authenticated only by OrgA's secret. Proof: WebhookController integration test with two Stack fixtures in different Repository/Organization rows, a raw_post whose top-level owner differs from a nested repository.full_name, signed with the top-level org's secret, asserting the wrong Stack was mutated.
