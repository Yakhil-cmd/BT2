lib/shipit/command.rb#unbundled_env merges BASE_ENV.merge('PATH'=>...).merge(@env.stringify_keys) with no allowlist on @env's keys, and #start passes this hash directly to PTY.spawn. Stack/Task construction assembles @env partly from TaskDefinition/shipit.yml 'env' keys read from the deployed branch's shipit.yml. If an attacker's fork PR is provisioned as a ReviewStack (per the missing fork check above) and its shipit.yml defines an env key such as 'GIT_ASKPASS' or 'LD_PRELOAD', does unbundled_env ever reject env keys outside an allowlist before they reach PTY.spawn? Binding: the set of keys in Command#unbundled_env == a fixed allowlist approved by the operator, not the key set found in an attacker-authored shipit.yml. Impact: Critical, RCE/credential exfiltration via environment key injection into PTY.spawn on the deploy host. Proof: unit test constructing a Command with env: {'GIT_ASKPASS' => '/tmp/evil'} sourced from a fake TaskDefinition, asserting unbundled_env includes the attacker key unmodified.
