Target: `StacksChainState::make_reward_set` in boot/mod.rs. Attacker action: an unprivileged staker submits two `RawRewardSetEntry` records with the same `reward_address` but different `stacker` principals (e.g. by delegating from two different accounts to the same PoX address) so that `make_reward_set`'s combination loop sums `stacked_amt` across both before computing `slots_taken`. Preconditions: two distinct stacker principals delegate-stack to the identical `reward_address`. Call sequence: `stake`/delegate path inserts two entries -> `make_reward_set` pops both, combines via the `while addresses.last()... == Some(&address)` loop, computes `slots_taken = stacked_amt / threshold`. Equality that breaks: reward slots granted to `reward_address` != the STX any single principal actually locked (slots reflect an address, not a principal's own locked value, letting one principal's slot count be inflated by another's stake redirected to the same address). Impact: Critical if attacker can direct another party's unrelated lock to their own reward address, capturing slots exceeding personal locked value. Proof idea: unit test with two `RawRewardSetEntry`s sharing `reward_address` but distinct `stacker`, asserting slot count exceeds `entry.amount_stacked / threshold` for either individual entry.
