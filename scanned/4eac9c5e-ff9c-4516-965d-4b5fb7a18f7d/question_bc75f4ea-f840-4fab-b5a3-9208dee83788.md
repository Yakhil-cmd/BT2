Target: Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository and #provision?. Attacker action: open a pull request on a fork of a Shipit-tracked repository (their own repo, review_stacks_enabled and provisioning_behavior_allow_all not configured there) but craft/replay a webhook 'pull_request' 'opened' event whose 'repository'->'full_name' names a different, review-stack-enabled repository they don't own, signed using their own org's webhook_secret matching 'repository'->'owner'->'login' left as their own org. Preconditions: attacker's org has a configured webhook_secret (they own their fork/org), target repository belongs to a different organization with review_stacks_enabled=true and provisioning_behavior_allow_all?=true. Call sequence: verify_signature passes because repository_owner == attacker's org; OpenedHandler#repository resolves via params.repository.full_name to the victim repository object, not the attacker's; ReviewStackAdapter#create! provisions a new ReviewStack under the victim repository. Binding: organization verifying (attacker org) == organization owning the repository whose ReviewStack is created (victim org) -- fails. Impact: Critical, unauthorized stack creation/provisioning (which runs Command/PTY-based provisioning tasks) on a foreign repository triggered by an unprivileged attacker's own signed webhook. Proof idea: integration test where WebhooksController receives a body signed by attacker org's secret but full_name points to victim repo; assert ReviewStack.create! was invoked for the victim repository.
