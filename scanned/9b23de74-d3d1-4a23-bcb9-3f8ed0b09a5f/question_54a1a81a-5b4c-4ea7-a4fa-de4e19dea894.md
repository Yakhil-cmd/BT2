Target: Shipit::GithubAuthenticationController#callback. Attacker action: POST /github/auth/github/callback (the route is registered for both `post :callback` and `get :callback`) with a forged omniauth.auth env value is not directly settable by a remote client, but the controller inherits ActionController::Base and never includes protect_from_forgery, so an attacker can host a cross-site auto-submitting form that POSTs to the victim's browser-authenticated /github/auth/github/callback while OmniAuth middleware is mid-flow, completing the callback as a cross-site request. Preconditions: OmniAuth callback URL reachable without a per-request state/nonce check enforced at this controller layer beyond what omniauth-oauth2 itself provides; no CSRF token required. Call sequence: cross-site POST reaches #callback, session[:user_id] = sign_in_github(auth) is set and session[:authenticated] = true, then redirect_to(request.env['omniauth.origin']) sends the browser to an attacker-supplied origin captured earlier in the flow. Binding: the User row session[:user_id] names == the GitHub account that completed this OAuth exchange in this session must hold, but a cross-site-completed callback breaks the assumption that the session belongs to the party who initiated it. Scoped impact: High - forced OAuth completion / session fixation surface enabling subsequent unauthorized actions against the victim's browser session. Proof idea: ActionController::TestCase POST :callback without a CSRF token or Origin/Referer check present, asserting the request succeeds (no `protect_from_forgery` rejection) and session[:authenticated] becomes true regardless of request origin.
