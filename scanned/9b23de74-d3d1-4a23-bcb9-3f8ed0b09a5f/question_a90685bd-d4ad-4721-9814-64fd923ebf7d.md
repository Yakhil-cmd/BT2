Target: Shipit::GithubAuthenticationController#callback redirect handling. Attacker action: attacker crafts a link to https://<shipit-host>/github/auth/github?origin=https://attacker.example/collect and gets a victim (already or about-to-be authenticated) to click it, initiating the OmniAuth flow with omniauth.origin set to the attacker's URL. Preconditions: no allow-list validation of request.env['omniauth.origin'] before it is used in redirect_to(return_url) inside #callback. Call sequence: victim authenticates via GitHub, #callback runs session[:user_id] = sign_in_github(auth), then redirect_to(return_url) where return_url = request.env['omniauth.origin'] unfiltered, sending the victim's browser (now carrying an authenticated Shipit session cookie in a first-party context, but with Referer/subsequent navigation to attacker.example) to the attacker's domain. Binding: none of the identity bindings enforce that redirect targets stay within the Shipit host, so a value an attacker fully controls (the origin param) drives a post-authentication redirect. Scoped impact: High - open-redirect-assisted phishing/token-leak vector immediately following authentication, usable to harvest Referer-embedded state or chain into further social engineering against an authenticated victim. Proof idea: ActionController::TestCase GithubAuthenticationControllerTest setting @request.env['omniauth.origin'] = 'https://attacker.example/x', calling get :callback with valid auth, asserting the response redirects to the exact attacker-controlled URL with no host validation.
