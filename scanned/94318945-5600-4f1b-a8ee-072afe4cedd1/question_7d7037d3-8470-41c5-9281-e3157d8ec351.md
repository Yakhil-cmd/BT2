Target: PullRequest::OpenedHandler#process and #repository (app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb). Attacker action: open a pull request against a public GitHub repository configured in Shipit with review_stacks_enabled and provisioning_behavior_allow_all, causing GitHub to emit a pull_request 'opened' webhook signed with that repo's real org secret (org owns the repo, so this webhook is legitimately signed) - but attacker sets pull_request.head.ref to a crafted branch name containing shell/path metacharacters (e.g., 'a; rm -rf /' or '../../../etc') that flows into ReviewStackAdapter#find_or_create! and ultimately into Stack branch/task execution. Preconditions: repository.review_stacks_enabled=true, provisioning_behavior_allow_all?=true. Call sequence: OpenedHandler#process -> ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create! using params.pull_request.head.ref verbatim as the stack's branch attribute, later consumed by Command#start/PTY.spawn during deploy (git checkout branch). Binding: the ref approved by an authorized user (a legitimate branch name pattern) == the ref that reaches Command#start's argument list; if unsanitized, attacker-controlled ref bytes reach process spawn arguments. Impact: Critical - RCE on the deploy host via an attacker-influenced string reaching Command#start/PTY.spawn through a malicious branch name in a pull request they opened. Proof: minitest opening a review stack via ReviewStackAdapter with a shell-metacharacter-laden branch name and asserting the value passed to Command#start (or the git checkout command list) is not shell-interpreted / is properly escaped as an argv element, not a shell string.
