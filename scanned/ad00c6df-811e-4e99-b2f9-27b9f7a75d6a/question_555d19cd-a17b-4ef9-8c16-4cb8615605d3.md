[File: lib/shipit/environment_variables.rb#interpolate] Attacker-controlled env value containing a literal '$' followed by a second variable name, e.g. FOO='$BAR', is used as the *value* of a step's interpolated variable; test whether `interpolate`'s single-pass `gsub` re-scans the substituted (already-escaped) text for a second `$WORD` expansion, which would break the 'escaped exactly once' binding. Precondition: env hash contains FOO='$BAR' and BAR='$(id)', PR-controlled via a deploy env parameter or label. Binding: interpolate performs exactly one substitution pass over the ORIGINAL argument string, never re-interpolating substituted text, so `$FOO` in a step resolves to the escaped literal '$BAR', not to BAR's value. Impact: Critical (RCE) if double-expansion occurs. Proof: minitest Command.new('echo $FOO', env: {'FOO' => '$BAR', 'BAR' => '$(id)'}, chdir:'.').run, asserting output is the escaped literal '$BAR' and not the executed result of $(id).
