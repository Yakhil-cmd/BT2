After a forged `status` webhook (payload repository = attacker's repo) creates a `success` Status on a victim commit, does `Commit#deployable?` (`!locked? && (stack.ignore_ci? || (success? && !blocked?))`) return true for that commit within the victim's Stack? Preconditions: victim Stack has `continuous_deployment: true` and the target commit is `next_commit_to_deploy`. Call sequence: forged status -> `Status.replicate_from_github!` -> `after_commit :schedule_continuous_delivery` -> `Commit#schedule_continuous_delivery` -> `ContinuousDeliveryJob` -> `Stack#trigger_continuous_delivery` -> `trigger_deploy`. Binding: `commit.deployable? == true` must only be reachable from a Status whose Stack matches the commit's own Stack authenticated by that Stack's org's `webhook_secret`; it is not. Impact: Critical - unauthorized continuous deployment of attacker-influenced code path on victim's deploy host. Proof idea: StackTest asserting `@stack.trigger_continuous_delivery` triggers `Deploy.count` increment after only calling `commit.create_status_from_github!(state: 'success')` with a payload whose `repository.full_name` differs from `@stack.repository.full_name`.
