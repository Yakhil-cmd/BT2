[Target: Command#start + Command#interpolate_environment_variables + EnvironmentVariables.with(env).interpolate] `Command#interpolated_arguments` calls `interpolate_environment_variables(@args)` which does `EnvironmentVariables.with(env).interpolate(argument)` per-argument before they reach `PTY.spawn`. Since `@task.definition.steps`/`deploy_spec.dependencies_steps!` are read from the checked-out `shipit.yml` at `@task.until_commit`, and interpolation substitutes `env` values (including `GITHUB_TOKEN`, `SHIPIT_USER`, task-supplied `@task.env`) directly into the command-line string. Binding: every `$VAR`-style token interpolated into `interpolated_arguments` resolves ONLY to keys present in the SAME `env` hash passed to `Command.new`, and the resulting interpolated string is what actually reaches `PTY.spawn`, not a re-interpolated/nested expansion that could pull in `GITHUB_TOKEN` inside a step string an unprivileged PR author wrote into their OWN fork's `shipit.yml` (in scope for review-stack tasks) to have it echoed into task output. Impact: Critical, credential exfiltration — if `shipit.yml` steps can reference `$GITHUB_TOKEN` and have it interpolated then streamed via `@task.write(line)` in `TaskExecutionStrategy::Default#capture!`'s `command.stream!`, the token appears in task output visible to the PR author. Proof: test with a review-stack task whose `steps` include `echo $GITHUB_TOKEN`, asserting task output does NOT contain the literal token value (either because it's not interpolated into visible output or is redacted).]
