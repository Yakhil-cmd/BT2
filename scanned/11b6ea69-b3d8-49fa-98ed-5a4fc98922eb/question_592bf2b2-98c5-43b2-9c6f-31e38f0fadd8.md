[Target: GitHubApp#verify_webhook_signature] For any organization configured in `secrets.github` without a `webhook_secret` key (per docs/setup.md's optional field and `@webhook_secret = @config[:webhook_secret].presence`), `verify_webhook_signature` returns `true` unconditionally via `return true unless webhook_secret`. Attacker sends POST /webhooks with `repository.owner.login` set to that unsecured org's login, `X-Hub-Signature` header omitted or garbage, and any event/payload naming a stack under that org. Call sequence: `verify_signature` calls `Shipit.github(organization: repository_owner).verify_webhook_signature(nil_or_garbage, raw_post)` which returns true without ever touching HMAC; `#create` dispatches to the real handler. Binding: `webhook_secret.present?` == true must hold for `repository_owner` to gain any authentication; for an org with no secret configured this equality is vacuously bypassed by design, and any handler mutation under that org executes for an unauthenticated caller. Impact: Critical, authentication bypass — full webhook forgery for any organization whose admin left `webhook_secret` blank (a documented 'optional' field), enabling e.g. `PushHandler` to trigger arbitrary `sync_github` on that org's stacks. Proof: test configuring a `GitHubApp` with `config: { webhook_secret: nil }`, posting a `push` event with no `X-Hub-Signature` header, asserting `GithubSyncJob` is still enqueued.]
