Target: StackStxOp::check (stackslib/src/chainstate/burn/operations/stack_stx.rs). Attacker action: broadcast a PreStxOp from their own UTXO, then a StackStxOp whose parse_data payload sets num_cycles to 0 or to a value > POX_MAX_NUM_CYCLES. Preconditions: attacker owns the spent Bitcoin UTXO, cycle phase irrelevant, pox-4/pox-5 active. Call sequence: StackStxOp::parse_from_tx builds the op, StackStxOp::check only warn!()s on invalid num_cycles and always returns Ok(()) (no `return Err` branch), so the op reaches process_stacking_ops -> stack-stx contract-call in pox-5. Impact: Critical, permanent freezing or premature unlocking of the staker's own locked STX if pox-5 does not independently reject it. Proof idea: Rust integration test constructing a StackStxOp with num_cycles=0, feeding it through process_stacking_ops on a booted chainstate, and asserting locked-until height == committed height or that the op is rejected end-to-end.
