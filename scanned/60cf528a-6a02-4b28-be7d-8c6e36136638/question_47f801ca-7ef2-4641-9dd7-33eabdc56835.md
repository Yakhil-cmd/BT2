Target: Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository and #process. Attacker action: open a pull request on a fork under their own control, then craft/relay a pull_request 'opened' webhook body where repository.owner.login is their own org (so signature verifies) but repository.full_name is set to a victim repository string that already exists in Shipit as a review-stacks-enabled repository, with provisioning_behavior_allow_all. Preconditions: victim Repository has review_stacks_enabled true and provisioning_behavior_allow_all?; attacker's org has a valid webhook_secret they can sign with (their own webhook delivery). Call sequence: verify_signature passes (own org secret over own-org-owned bytes), OpenedHandler#repository resolves Repository.from_github_repo_name(params.repository.full_name) to the victim repo, provision? returns true, ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create! creates a review stack under the victim repository using attacker-supplied pull_request.number/head.sha/ref. Binding: organization whose webhook_secret verified the bytes (attacker org) == organization owning the repository whose review_stacks are mutated (victim org) -- broken. Scoped impact: Critical, unauthorized creation of a deployable review Stack against a foreign repository/commit chosen by the attacker. Proof idea: test posting a pull_request opened webhook with mismatched owner login vs full_name and asserting Shipit::Stack.review_stacks count increases for the victim repository.
