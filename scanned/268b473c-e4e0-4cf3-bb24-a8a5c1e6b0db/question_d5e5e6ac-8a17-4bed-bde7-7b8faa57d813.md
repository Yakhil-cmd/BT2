If two independent stacks (different `Repository#full_name`, different `webhook_secret` owners) happen to reference the same git blob/tree producing an identical commit `sha` (e.g. both start from GitHub's default empty-tree commit or a common upstream commit prior to fork divergence), does `Commit.where(sha: params.sha)` in `StatusHandler#process` return rows from both stacks, and is there any `stack_id` or `repository_id` filter added to that `where` clause? Binding: `Commit.where(sha: ...)` scope == `Commit.where(sha: ..., stack_id: stacks.commits.select(:id))` filtered by `Handler#stacks` -- this filter does not exist. Impact: any two tenants sharing a common ancestor commit sha are fully cross-contaminated for CI state (Critical). Proof: unit test creating two stacks with a shared-sha commit each, invoking `StatusHandler.call` with one org's payload, asserting both commits received the status.
