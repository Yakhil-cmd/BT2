Target: `Shipit::DeploySpec::FileSystem#machine_env`/`discover_machine_env` merged in `cacheable_config` (app/models/shipit/deploy_spec/file_system.rb). Attacker action: open a PR that edits `shipit.yml`'s `machine.environment` block to define `PATH` pointing at a directory inside the checked-out repo containing an attacker-supplied binary named identically to a step's first word (e.g. `git`). Preconditions: review/CI checkout of the PR branch is used as the source for `shipit.yml` before any human approval gate runs. Call sequence: `discover_machine_env.merge(machine_env)` -> `TaskCommands#env` merges this into env -> `Command#unbundled_env` merges `@env.stringify_keys` *over* `BASE_ENV.merge('PATH' => ...)`, letting the PR's `PATH` win -> `PTY.spawn` resolves the first argv word against the attacker-controlled `PATH`. Binding: the `PATH` value used to resolve the executable in `PTY.spawn` == the Shipit-operator-configured `Shipit.shell_paths`/`ENV['PATH']`, never a value sourced from an unreviewed `shipit.yml`. Impact: Critical - RCE on the deploy host by binary-planting via `machine.environment.PATH`. Proof idea: unit test building a `DeploySpec::FileSystem` from a fixture `shipit.yml` with `machine.environment.PATH` set to a fixture directory containing a fake `git` script, asserting `Command#unbundled_env['PATH']` still places `Shipit.shell_paths` ahead of (or excludes) the attacker path, or documenting that it does not.
