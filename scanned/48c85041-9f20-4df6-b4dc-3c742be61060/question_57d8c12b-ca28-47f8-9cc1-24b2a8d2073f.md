[File: mainnet/contracts/market/v0-4-market.clar, Scope: Critical] Function: accrue-and-cache. Attacker A calls deposit(aid=USDC, amount=large, recipient=A) as the first transaction in block N, temporarily lowering utilization and causing index-cache to store a low-rate lindex for that timestamp. A then calls redeem(aid=USDC, amount=large, recipient=A) later in the same block, withdrawing the same capital, but victim B's borrow(aid=USDC,...) executed BETWEEN A's deposit and redeem is charged interest for the block using the cached index primed at A's artificially low utilization. Sequence: [Block N: A deposit()] -> [Block N: B borrow()] -> [Block N: A redeem()]. Invariant: ORDERING NEUTRALITY. B's accrued debt for the block is computed against a utilization that ceases to exist by the time the block ends. Impact: theft of unclaimed yield - suppliers who should have earned interest on B's borrow at the true utilization receive less because the cache never re-evaluates after A's round-trip. Proof: simnet test with A's deposit+redeem sandwiching B's borrow in one block; compare accrued lindex/index for suppliers/B against a control block without A's sandwich.
