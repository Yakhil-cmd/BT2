[File: mainnet/contracts/market/v0-4-market.clar, Scope: Critical] Function: accrue-and-cache / borrow. Attacker A calls borrow(aid=STX, amount=X) at the start of block N, driving vault-stx's total-debt up and utilization up, which is read once by accrue-and-cache and written into index-cache {timestamp: stacks-block-time, aid: STX} for the whole block. Victim B, an existing zSTX (rehypothecated) holder, calls redeem(aid=zSTX,...) later in the SAME block N; B's zToken price is resolved off the SAME cached lindex that was computed at A's post-borrow utilization, not the utilization B's own transaction would see if it were first. Sequence: [Block N: A borrow() first -> caches index/lindex at A's utilization] -> [Block N: B redeem() second -> reads cached lindex]. Invariant broken: ORDERING NEUTRALITY. B receives redemption value priced off a utilization A manufactured seconds earlier in the same block, not off the accrual B would get standing alone. Impact: theft of unclaimed yield (B's redemption is under- or over-priced versus a same-block ordering B did not choose). Proof: two-account simnet test - run B's redeem alone in a block and record payout; replay with A's borrow immediately before B's redeem in the same block-time and assert the payout differs.
