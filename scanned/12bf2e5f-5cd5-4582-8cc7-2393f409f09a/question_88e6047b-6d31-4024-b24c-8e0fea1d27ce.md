Target: Shipit::GithubAuthenticationController#callback. Attacker action: attacker POSTs directly to /github/auth/github/callback (routed for POST per config/routes.rb) with a forged omniauth.auth env hash is not directly settable by an external POST body since OmniAuth middleware populates request.env['omniauth.auth'], but because the controller has no protect_from_forgery and the route accepts POST, attacker crafts a cross-site auto-submitting form that POSTs to /github/auth/github/callback from another origin while the victim's browser sends the victim's own omniauth-in-flight cookies. Preconditions: default Shipit config, no CSRF token check on this controller. Call sequence: cross-site POST reaches callback, session[:authenticated] gets set to true and session[:user_id] assigned without any origin check, then redirect_to(request.env['omniauth.origin']) sends the browser to an attacker-controlled origin string taken unfiltered from omniauth.origin. Binding broken: the origin the browser is redirected to == an origin under the operator's own domain. Impact: Critical, forced/cross-site OAuth completion combined with open redirect can be chained to steal the resulting session or complete auth flows the victim never intended, letting an attacker complete authentication bypass on behalf of a session they control. Proof idea: ActionDispatch::IntegrationTest posting to github_authentication_callback_path with omniauth.origin set to 'https://evil.example' in the Rack env and asserting response redirects to that unfiltered external URL.
