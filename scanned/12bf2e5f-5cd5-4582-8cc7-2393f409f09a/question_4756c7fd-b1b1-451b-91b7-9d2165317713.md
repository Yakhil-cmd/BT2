Target: Shipit::GithubAuthenticationController#callback redirect_to(return_url) where return_url = request.env['omniauth.origin'] || root_path. Attacker action: attacker crafts a link to /github/auth/github?origin=<attacker_url> (or relies on OmniAuth's origin param handling) that an operator/victim clicks, so that after the victim completes a legitimate OAuth login, the browser is redirected to an attacker-controlled external URL carrying no Shipit secret but establishing a phishing landing right after real authentication. Preconditions: default Shipit OmniAuth setup with no explicit allow-list validating omniauth.origin against the app's own host. Call sequence: GET /github/auth/github with origin param -> OmniAuth stores it in request.env['omniauth.origin'] -> callback fires -> redirect_to(return_url) sends browser to attacker's URL unfiltered. Binding broken: the redirect target after this OAuth exchange == a URL under the Shipit host's own domain. Impact: High (open redirect chained with real session state) potentially escalating to Critical if combined with a phishing page that harvests the session cookie value shown to the user or requests re-authentication capturing credentials; scoped to the victim who clicked the link. Proof idea: ActionDispatch::IntegrationTest setting request.env['omniauth.origin'] = 'https://evil.example/phish' and asserting the callback response Location header equals that external string rather than being constrained to root_path or same-host paths.
