[File: mainnet/contracts/market/v0-market-vault.clar] Target: `collateral-add`/`collateral-remove` ordering around `accrue-and-cache`. Attacker A calls `collateral-remove` on their own healthy position first in block N, which forces an `accrue-and-cache` computation using zTokens' current exchange rate before B's rehypothecated collateral value is repriced. Victim B, who supplies the same asset and holds rehypothecated zToken collateral, calls `collateral-add` in the same block; the market credits B's new collateral at the stale pre-A-withdrawal exchange rate, undervaluing B's deposit relative to what a fresh accrual would give, reducing B's effective borrowing power for the rest of the block. Sequence: block N: (1) A withdraws, freezing rate in cache; (2) B deposits and is under-valued. Invariant broken: ORDERING NEUTRALITY. B loses: reduced borrowing headroom for the remainder of block N, which can cause a legitimate B `borrow` call in the same block to revert (temporary freeze of B's funds/utility). Impact: High - temporary freezing of funds. Proof: simnet test comparing B's `get-position` collateral value with and without A's preceding `collateral-remove` in the same block.
