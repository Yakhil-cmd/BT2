Target: `Shipit::ReviewStack#env` and `Shipit::DeployCommands#env` (lib/shipit/deploy_commands.rb) which calls `super` (TaskCommands#env) merging `@stack.env` before returning to `Command.new(command_line, env:, chdir:)` in `TaskCommands#perform`. Attacker action: label a PR-backed review stack's pull request with a label literally named `LD_PRELOAD`, and in the same branch commit a file at the checkout root named `true` compiled as an ELF shared object with a malicious `.init` constructor. Preconditions: `review_stacks_enabled`, an existing non-archived `Shipit::ReviewStack`, `deploy_spec.deploy_steps!` non-empty (e.g. capistrano detected). Call sequence: `LabeledHandler#capture_labels`/`LabelCapturingHandler#capture_labels` writes `LD_PRELOAD` into `pull_request.labels` -> `Shipit::ReviewStack#env` sets `env['LD_PRELOAD']='true'` -> `DeployCommands#perform` builds `Command.new(deploy_step, env:, chdir: steps_directory)` -> `Command#unbundled_env` places `LD_PRELOAD=true` into the spawned process env -> `PTY.spawn` invoked from `chdir` equal to the attacker's checkout, so the dynamic linker resolves the relative path `true` to the attacker's malicious shared object and executes its constructor in every subsequent process image launched with that env. Binding: keys in `Command#unbundled_env` == keys permitted by `deploy_spec.machine_env`/`VariableDefinition`; `LD_PRELOAD` is in neither set yet reaches `PTY.spawn`. Scoped impact: Critical RCE on the deploy host, silently loaded into the deploy step's own subprocess tree. Proof idea: minitest asserting `DeployCommands.new(deploy).env` contains an unwhitelisted `LD_PRELOAD` key sourced purely from `stack.pull_request.labels`, with no call to `EnvironmentVariables.with(env).permit(...)`.
