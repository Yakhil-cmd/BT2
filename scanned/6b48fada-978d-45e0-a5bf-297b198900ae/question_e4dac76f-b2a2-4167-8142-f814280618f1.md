[Function: accrue / system-borrow] No new borrow is needed: A merely calls the public (accrue) function repeatedly across several blocks (or once, letting `next-index` compute a large `debt-delta` since `old-debt`/`new-debt` scale with the whole `principal-scaled` book) to push `total-debt` (derived from `principal-scaled * index`) up to CAP-STX-DEBT purely via accrued interest, with no cap headroom added by any principal. Victim B, a liquidator (an ordinary unprivileged principal, not the DAO) attempting to call `liquidate` on a different insolvent borrower C's position that also lives in this vault, needs vault-stx to accept a repay/seize flow that internally checks debt bounds; if any liquidation-driven top-up path re-checks `(<= (+ debt amount) CAP-DEBT)` it now reverts, so B cannot execute the liquidation and C's bad debt keeps accruing against all suppliers. This is a case where accrued interest alone (not any single principal's borrow) trips CAP-DEBT, freezing the debt cap for every future borrower/liquidator interaction that must pass through it. Impact: temporary freezing of funds. Proof: simnet test that lets time pass (mine many blocks) with an existing large borrow near the cap, call accrue to cross CAP-STX-DEBT, then have B attempt the liquidation-path call and assert it reverts, while an equivalent scenario without the elapsed accrual succeeds.
