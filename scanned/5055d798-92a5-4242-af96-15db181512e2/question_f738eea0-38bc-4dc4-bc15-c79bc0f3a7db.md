Target: Shipit::Command#parse_arguments (lib/shipit/command.rb) Hash-shaped step parsing, e.g. `{'./script/deploy' => {'timeout' => 30}}`. Attacker action: contributor's shipit.yml step is written as a Hash whose options include an `'env'` key alongside `'timeout'`, e.g. `{'./script/deploy' => {'timeout' => 30, 'env' => {'PATH' => '/tmp/evil'}}}`. Preconditions: none beyond the PR being merged or checked. Call sequence: `parse_arguments` does `options.merge!(argument.values.first)`, taking the entire options hash (including any unexpected 'env' key) and merging it into `options`, though only `options['timeout']`/`options[:timeout]` is ever read by Command#initialize -- verify no other code path pulls `options['env']` into `@env`, which would let a step definition smuggle an env override bypassing `EnvironmentVariables#permit` entirely. Binding: options merged from a step Hash must never reach `@env`/`Command#unbundled_env` except through the `env:` keyword explicitly passed by TaskCommands#env (already permit-filtered). Scoped impact: Critical if broken (bypasses the name whitelist entirely); currently a boundary/regression check. Proof idea: minitest constructing Command.new({'echo hi' => {'env' => {'PATH' => '/tmp/evil'}}}, chdir: '.', env: {}) and asserting `command.env` and `command.unbundled_env['PATH']` are unaffected by the smuggled 'env' option key.
