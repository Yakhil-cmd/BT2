Because `StatusHandler#process` supplies `stack_id` from whichever `Commit` in `Commit.where(sha: params.sha)` is currently being iterated, can the same webhook body create multiple `Status` rows, one per stack, none of which belong to the repository that sent the webhook? Binding: number of `Status` rows created by one verified webhook request == number of stacks whose repository matches the payload's `repository.full_name` (should be <= stacks of one repo, is unbounded across repos in practice). Impact: cross-tenant `Status` fan-out write (Critical). Proof: minitest with 3 commits sharing one sha across 3 different stacks/repos, asserting `Status.count` increases by 3 from a single-repo webhook.
