`Stack#next_commit_to_deploy` (app/models/shipit/stack.rb) calls `deployable_commits` which relies on each commit's `#deployable?`. If a cross-repo status webhook (per `StatusHandler#process`) marks a previously-pending victim commit `success`, does `next_commit_to_deploy` return that commit for a stack whose repository never received a verified webhook confirming that state? Binding: repository verified by `verify_signature` in `Shipit::WebhooksController` == repository of the stack whose `next_commit_to_deploy` result changes. Impact: cross-repository stack state mutation feeding an unauthorized deploy target selection (Critical). Proof: minitest asserting `stack.next_commit_to_deploy` changes identity after cross-repo status injection.
