`Commit#blocked?` (commit.rb) is `stack.commits.reachable.newer_than(stack.last_deployed_commit).older_than(self).any?(&:blocking?)`, scoped correctly to `stack.commits`. But if the attacker's cross-repo status injection (`StatusHandler#process`) turns a *blocking* victim commit from `pending`/`failure` to `success`, does `blocked?` return false for a later victim commit even though no webhook from the victim repository ever authenticated that transition? Binding: the repository that authenticated the `Status` making a commit non-`blocking?` == the repository owning the `Stack` whose `blocked?` computation depends on that commit. Impact: cross-repository unblocking of a deploy gate (Critical). Proof: minitest showing `later_commit.blocked?` flips to false solely via a cross-repo webhook naming a different `repository.full_name`.
