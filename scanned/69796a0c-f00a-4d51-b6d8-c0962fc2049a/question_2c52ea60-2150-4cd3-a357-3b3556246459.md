MembershipHandler#process performs team.members.delete(member) on action == 'removed' using only User.find_or_create_by_login!(params.member.login) to resolve `member`, meaning any login string in the payload — including one for a victim account never actually removed from the real GitHub team — is looked up/created and then dropped from local Membership records. Attacker action: POST /webhooks membership 'removed' naming a victim's login who legitimately holds Shipit.github_teams authorization, team.id equal to that real team's github_id, signed with a webhook_secret for an org the attacker controls that happens to pass verify_signature's per-organization app lookup (via the repository_owner fallback path). Preconditions: attacker can get any Shipit::GithubHook::Organization-configured org's webhook_secret to sign a request whose repository_owner resolves to that org, independent of which org actually owns the target team. Call sequence: verify_signature -> MembershipHandler#process -> team.members.delete(member) removes the victim's Membership row. Binding: the organization that verified the webhook signature must equal the organization owning the team from which a Membership is deleted. Scoped impact: Critical - a payload from one repository/organization mutates (revokes) another tenant's team membership and thus its Shipit.github_teams authorization, a denial of legitimate access via cross-tenant write. Proof idea: minitest with a victim Membership fixture tied to org A's team, POST membership 'removed' signed for org B, asserting the Membership persists (test fails if it's deleted), demonstrating WEBHOOK PROVENANCE must hold for deletions too.
