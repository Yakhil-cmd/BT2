Target: Api::BaseController#stacks and #identify_user vs require_permission!. Attacker action: POST any authenticated API request with header X-Shipit-User: <victim-login> alongside a legitimately-obtained but unrelated ApiClient token, e.g. triggering a deploy task via TasksController#trigger. Preconditions: attacker has any valid ApiClient token scoped to some stack with deploy:stack permission (e.g. from a leaked but low-privilege CCMenu-style unscoped client) and knows a victim's GitHub login. Call sequence: current_user -> identify_user -> User.where('lower(login) = ?', user_login.downcase).first, trusting the raw header with no signature; stack.trigger_task(params[:task_name], current_user, ...) attributes the triggered deploy to the spoofed current_user. Binding: current_user must equal the GitHub identity that authenticated this request (IDENTITY_BINDING), but identify_user derives current_user solely from an unauthenticated header. Scoped impact: Critical, unauthorized deploy attribution — an unprivileged token holder can trigger a deploy recorded as performed by an arbitrary victim user, letting the actual actor evade audit/authorization tied to user identity elsewhere in the app. Proof idea: integration test asserting Task#user (or similar) after TasksController#trigger with X-Shipit-User set to a victim login equals that victim rather than the actual authenticated api client's creator.
