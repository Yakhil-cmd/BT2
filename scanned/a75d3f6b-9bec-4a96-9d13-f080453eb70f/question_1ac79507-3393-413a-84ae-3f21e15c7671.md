Shipit::User.find_or_create_by_login! calls Shipit.github.api.user(login) using the default (non-organization-scoped) Shipit.github client for whatever login string it is given, regardless of which organization's webhook triggered the lookup (e.g., from ReviewStackAdapter#user or the Merge-Requested-By parsing in find_or_create_author_from_github_commit). Given multi-org configurations, does the identity created bind github_id/login to the correct authenticating organization's namespace, or can two different organizations' webhooks referencing the same login string collide into a single shared Shipit::User record, letting an attacker in org A pre-create a User record later trusted as an org B actor? Impact: Critical, cross-organization identity collision used for authorization. Proof: test creating a User via org A's webhook then triggering org B's webhook with the same login and asserting whether the same User row (and its authorized? standing) is reused across organizations.
