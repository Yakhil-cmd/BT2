target: Shipit::WebhooksController#verify_signature and #repository_owner (app/controllers/shipit/webhooks_controller.rb). Attacker action: an unprivileged GitHub user who owns a repo on an org already installed in Shipit opens a pull_request against a repo they do not maintain, causing GitHub to POST the real, correctly-signed webhook. Preconditions: two orgs are configured in Shipit (Shipit.github(organization:) resolves distinct GithubApp instances by login, per lib/shipit/github_app.rb) and the target repository has review_stacks_enabled. Call sequence: WebhooksController#create -> #verify_signature picks the app via repository_owner (params.dig('repository','owner','login')) -> Webhooks.for_event('pull_request') -> OpenedHandler#process -> ReviewStackAdapter#create!. Binding that breaks: repository_owner (the org whose webhook_secret verified the body) == the org whose Stack/ReviewStack row create! writes into. Scoped impact: Critical - a payload for one repository could mutate another repository's Stack row if repository.full_name (used by OpenedHandler#repository via Shipit::Repository.from_github_repo_name) is inconsistent with repository.owner.login used for signing. Proof idea: minitest integration test posting a payload where params['repository']['owner']['login'] == 'org-a' (verified) but params['repository']['full_name'] == 'org-b/other-repo', asserting whether the created ReviewStack's repository differs from the org that authenticated the signature.
