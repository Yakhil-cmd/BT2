[Function: deposit] A funds a fresh wallet and calls deposit with an amount computed off-chain to be exactly `(- CAP-SUPPLY current-assets)` fetched via a read-only call in the same block as B's pending deposit (front-running via same-block ordering since Clarity has no private mempool protection at this layer). Victim B is any depositor whose transaction is included after A's in block ordering. Sequence: Block N, tx index k: A's deposit; Block N, tx index k+1: B's deposit of a modest amount reverts. Invariant broken: ORDERING NEUTRALITY. B loses: ability to deposit that block and must wait for A to redeem or CAP-SUPPLY to be raised, i.e., an indefinite freeze of B's intended action until governance or A acts. Impact: temporary freezing of funds (High). Proof idea: Clarinet test issuing both txs in one simulated block with controlled ordering, asserting B's tx-result differs based on order.
