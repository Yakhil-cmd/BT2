Target: Shipit::MergeStatusController#show response header assignment 'X-Frame-Options' = 'ALLOWALL'. Attacker action: attacker hosts a page that iframes https://shipit.example.com/merge_status?stack_id=<victim_org>/<repo>/production and overlays UI to trick a logged-in operator into clicking through to /merge_status/*/pull/:number enqueue or dequeue links rendered inside the frame. Preconditions: victim operator has an active Shipit session cookie; SameSite attribute on that cookie is not 'Strict'. Call sequence: browser loads the framed page under the victim's authenticated session, force_github_authentication passes because the browser attaches the victim's cookie, and the frame is not blocked because X-Frame-Options is ALLOWALL. Binding: the response allowed to be framed cross-origin was produced after force_github_authentication and authorized? passed for the victim, yet no framing restriction re-validates the origin of the clicking party. Scope: High, unauthenticated third party riding an authenticated operator's session into a state-changing merge-queue action via clickjacking. Proof idea: integration test asserting response.headers['X-Frame-Options'] == 'ALLOWALL' on #show and combine with a CSRF test on #enqueue to demonstrate the framed click reaches a mutating endpoint.
