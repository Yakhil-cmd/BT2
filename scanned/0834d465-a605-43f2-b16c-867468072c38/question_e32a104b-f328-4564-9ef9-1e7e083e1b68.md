Attacker action: POST /webhooks X-Github-Event=check_suite with repository.owner.login = 'OrgA' (verifier) but repository.full_name = 'OrgB/target-repo' and check_suite.head_sha equal to a real commit sha on OrgB/target-repo's tracked branch, signed with OrgA's webhook_secret. Preconditions: OrgA, OrgB both configured with distinct webhook_secrets; OrgB/target-repo has a Stack tracking the branch containing that sha. Call sequence: verify_signature passes for OrgA -> CheckSuiteHandler#process -> Handler#stacks resolves OrgB's Repository -> RefreshCheckRunsJob enqueued for OrgB's stack. Binding: organization whose webhook_secret verified the bytes (OrgA) == organization owning the stack the handler enqueues work for (OrgB); this is REPOSITORY_SCOPE. Scoped impact: Critical, cross-repository job enqueue potentially influencing OrgB's deploy-gating check-run refresh using attacker-chosen data signed only by OrgA.
