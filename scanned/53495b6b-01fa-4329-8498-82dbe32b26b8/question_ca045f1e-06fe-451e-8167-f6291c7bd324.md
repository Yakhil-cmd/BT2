[Target: Shipit::TaskCommands#env] An attacker who can trigger a deploy for a stack they don't administer (via a compromised low-permission ApiClient scoped only to 'deploy:stack' for one stack, or via forged Commit#author from the previous finding) causes TaskCommands#env to set 'SHIPIT_USER' => "#{@task.author.login} (#{normalized_author_name}) via Shipit" and 'GIT_COMMITTER_NAME'/'GIT_COMMITTER_EMAIL' from @task.user&.name / @task.user&.email, both of which are String values interpolated directly into the environment hash passed to Command.new(..., env:) and ultimately merged in Command#unbundled_env at lib/shipit/command.rb:104 before PTY.spawn. Preconditions: @task.author or @task.user resolves to an attacker-forged Shipit::User record (login/name/email attacker-controlled since User#name and #email come from github_user attributes settable via User.create_from_github with attacker-controlled github_user stub data from Octokit responses proxied through Shipit.github.api.user). Call sequence: TaskCommands#env -> Command.new(command_line, env:, chdir:) -> Command#start -> PTY.spawn(unbundled_env, *interpolated_arguments). Binding: every VALUE placed into Command#env by TaskCommands#env == a value that was present in the shipit.yml/task definition an authorized operator approved, not raw attacker-controlled GitHub profile strings. Impact: Critical RCE surface -- Command#interpolate_environment_variables via EnvironmentVariables.with(env).interpolate(argument) means these attacker-controlled env values, if referenced inside a step's shell argument as $SHIPIT_USER or $GIT_COMMITTER_NAME, are inlined into the argv passed to PTY.spawn. Proof: minitest asserting Command#interpolated_arguments substitutes an attacker-supplied GIT_COMMITTER_NAME containing shell metacharacters into the resulting argv array unescaped.
