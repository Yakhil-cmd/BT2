Target: Shipit::ReviewStack#env and Shipit::TaskCommands#env / Shipit::Command#unbundled_env. Attacker action: attacker opens a PR against their own fork and adds a label such as 'GITHUB_TOKEN' or 'PATH' to their own pull request (an action available to any user who can label their own PR when the repo allows). Preconditions: review_stacks enabled, ReviewStack provisioned. Call sequence: LabeledHandler/UnlabeledHandler -> PullRequest#labels updated -> ReviewStack#env merges pull_request.labels.map(&:upcase) => 'true' into stack.env -> TaskCommands#env merges @stack.env into command env -> Command#unbundled_env merges @env.stringify_keys over BASE_ENV -> PTY.spawn(unbundled_env, ...). Binding: every KEY in the environment hash reaching PTY.spawn must come from an allowlist an authorized user approved, not from an arbitrary label string an unprivileged PR author chose. Impact: Critical, RCE/credential-tampering surface - attacker-chosen environment KEY (e.g. GITHUB_TOKEN, PATH, LD_PRELOAD) overwrites the deploy process's environment for their own ReviewStack's task execution. Proof: minitest test labeling a PR with name 'GITHUB_TOKEN', then asserting Shipit::TaskCommands.new(task).env['GITHUB_TOKEN'] == 'true', clobbering the previously-set GitHub token value.
