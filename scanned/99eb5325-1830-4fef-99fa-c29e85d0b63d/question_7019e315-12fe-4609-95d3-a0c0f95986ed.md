Target: Shipit::Command#unbundled_env and Shipit::TaskCommands#env key precedence. Attacker action: attacker submits a deploy 'env' hash via a shipit.yml deploy.variables definition whose 'name' field is set to a sensitive key like 'GITHUB_TOKEN' or 'PATH' (shipit.yml lives on the attacker's own fork branch and is read directly when this branch is later checked out for a ReviewStack task). Preconditions: ReviewStack provisioned for attacker's PR, custom tasks/deploy variables read from DeploySpec::FileSystem on the checked-out fork branch before human review. Call sequence: TaskCommands#deploy_spec (DeploySpec::FileSystem.new(@task.working_directory, @stack)) parses attacker's shipit.yml on the fork branch -> deploy.variables permitted via EnvironmentVariables.with(env).permit(variable_definitions) -> TaskCommands#env merges deploy_spec.machine_env then @task.env -> Command#unbundled_env -> PTY.spawn. Binding: EXECUTION TRUST - every key in the environment reaching PTY.spawn must originate from a spec an authorized (non-fork) actor approved, not from shipit.yml on an unreviewed fork branch. Impact: Critical RCE/credential exfiltration, since deploy.variables names and machine.environment keys defined in the fork's own shipit.yml are never checked against an allowlist tied to an authorized reviewer before reaching the spawned process's environment. Proof: minitest constructing a DeploySpec from a fork-authored shipit.yml with machine.environment defining 'GITHUB_TOKEN', asserting TaskCommands#env['GITHUB_TOKEN'] is overridden by that fork-controlled value with no reconciliation against the value Command#unbundled_env originally computed from Shipit.github.
