CheckSuiteHandler's declared param schema (`params do requires :check_suite do requires :head_sha, String; requires :head_branch, String end end`) enforces type String but no format/length constraint. Attacker action: POST a check_suite webhook, correctly signed for the attacker's own repository, with `check_suite.head_sha` set to an arbitrary string (not a valid SHA, e.g. containing SQL wildcard characters or extremely long content) and `head_branch` set to an arbitrary string. Precondition: none beyond owning one repository with a webhook_secret. Binding: the value class ExplicitParameters accepts (String, any bytes) == the value class the Stack/Commit `.where` scope safely tolerates without ever reaching Command/PTY.spawn. Impact: bounded to High (unauthenticated verification of scoping, not RCE) since no cross-tenant write is shown here without additional preconditions -- explicitly note this question is a scoping/negative-control test, not by itself Critical. Proof: minitest test posting a check_suite payload with a malformed head_sha/head_branch to the attacker's own repository and asserting no other repository's rows are touched and no shell process is spawned.
