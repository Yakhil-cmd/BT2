In `ReviewStackAdapter#create!`, `environment: "pr#{params.number}"` derives the ReviewStack's environment string directly from `params.number` (the PR number in the payload), which then feeds `Stack#base_path = Rails.root.join('data','stacks', repo_owner, repo_name, environment)` used as the `chdir:` for `Command#start`/`FileUtils.mkdir_p`. Since `ReopenedHandler`'s params schema only requires `number` to be an `Integer` with no bound on repository ownership matching `params.repository.full_name`'s already-resolved `Shipit::Repository`, can an attacker who controls a PR on a repository they can open PRs against (any repo with review stacks enabled) choose a PR number that collides with another already-existing `pr<N>` ReviewStack environment on the SAME repository (e.g. via GitHub's reused PR numbering across forks/transfers) to have `find_by(environment:)` resolve and mutate a stack whose branch/pull_request were established by a different PR/author?
