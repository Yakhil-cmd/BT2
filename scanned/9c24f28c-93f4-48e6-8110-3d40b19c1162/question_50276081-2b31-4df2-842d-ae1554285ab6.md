ReviewStackAdapter#user calls `Shipit::User.find_or_create_by_login!(params.sender['login'])` and that returned identity is passed as the acting user to `stack.archive!(user, ...)`/used to attribute PR review-stack actions, sourced from `params.sender['login']` in the webhook JSON body. Can an attacker submit a 'reopened' payload where `sender.login` is a fabricated string equal to the login of a `Shipit.github_teams` member, so `find_or_create_by_login!` creates or reuses a `User` row whose `authorized?` may later be evaluated in other authorization paths, breaking the identity binding for any code that trusts `Shipit::PullRequest#user` or the stack's actor history? Binding: `session[:user_id]`/authenticated GitHub identity == the identity recorded as the acting user for the archive/unarchive action. Impact: Critical, an unauthenticated request attributing/recording actions under an arbitrary victim GitHub login with no OAuth login ever performed. Proof: integration test posting a pull_request reopened payload with sender.login set to a privileged user's login and asserting a `User` record is created/reused and attached to the stack's `PullRequest` without any session or OAuth handshake.
