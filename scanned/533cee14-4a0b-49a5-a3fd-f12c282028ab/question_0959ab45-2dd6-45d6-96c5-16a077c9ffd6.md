Target: Api::BaseController#require_permission! and ApiClient#check_permissions!. Attacker action: hold a valid token for an ApiClient whose permissions array includes only 'read:stack', and call an endpoint declared with require_permission(:deploy, :stack) (e.g. RollbacksController#create) directly, bypassing any stack_id restriction by using a client with stack_id nil (global). Preconditions: ApiClient permissions = ['read:stack'], stack_id nil. Call sequence: authenticate_api_client succeeds; before_action require_permission!(:deploy, :stack) invokes current_api_client.check_permissions!('deploy', 'stack') which raises InsufficientPermission since required_permission 'deploy:stack' not in permissions. Binding: the permission checked (operation:scope from the route declaration) must equal a permission actually present in current_api_client.permissions, and this equality must hold before any stack-mutating code executes. Scoped impact: Critical if check_permissions! were bypassable — this test targets confirming the 403 path fires correctly, guarding against regression that would let a read-only token trigger deploy.trigger_rollback. Proof idea: minitest POST to rollbacks#create with a read:stack-only client asserting 403 forbidden and that no Rollback record is created.
