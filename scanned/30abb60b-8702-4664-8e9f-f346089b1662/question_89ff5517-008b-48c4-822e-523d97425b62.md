Target: Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository. Attacker action: attacker sends a webhook 'opened' payload where repository.full_name names a *different* repository than the one whose webhook_secret verified the request (cross-repo payload). Preconditions: attacker controls a repository X with its own webhook_secret configured in Shipit for a GitHub App/organization; attacker crafts repository.full_name in the JSON body to reference repository Y (a different tenant). Call sequence: WebhooksController verifies signature against org owning app credentials -> OpenedHandler#repository resolves Shipit::Repository.from_github_repo_name(params.repository.full_name) using attacker-supplied full_name, not tied back to the verifying app/org. Binding: WEBHOOK PROVENANCE — the organization whose webhook_secret verified the body == the organization owning the repository named in repository.full_name (must be checked; if unchecked, cross-repo write). Scoped impact: Critical — a payload authenticated for repo X's app could create/mutate a ReviewStack under repo Y if full_name resolution isn't scoped to the authenticating app/org. Proof idea: minitest posting a verified payload (correct signature for org A's webhook_secret) with repository.full_name set to org B's repo, asserting whether a Repository lookup crosses the tenant boundary.
