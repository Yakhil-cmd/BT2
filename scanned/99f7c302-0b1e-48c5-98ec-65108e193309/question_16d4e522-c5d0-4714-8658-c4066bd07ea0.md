Target: Shipit::CCMenuUrlController#fetch and #client. Attacker action: an authenticated low-privilege browser user (any current_user, not necessarily a stack maintainer) visits GET /stacks/:stack_id/ccmenu_url for a stack they can view but should not control API access to. Preconditions: CCMenuUrlController has no require_permission! call comparable to Api::BaseController's before_action. Call sequence: #client does ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client') then #fetch mints uri.query = {'token' => client.authentication_token}, embedding stack.to_param but not binding the token's stack_id to that stack (ApiClient.create_with never sets stack:). Binding: the stack_id encoded in the emitted URL == the stack the minted ApiClient's stack_id restricts it to. Since the created ApiClient has no stack set, current_api_client.stack_id? is false, so BaseController#stacks returns Stack.all for this client if used via a scoped endpoint. Impact: Critical — the token minted for one stack's CCMenu link in fact authorizes read:stack against every stack in the instance. Proof idea: unit test on ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: u, name: 'CCMenu Client') asserting stack_id is nil, then assert BaseController#stacks (simulated) returns Stack.all, not just the requested stack.
