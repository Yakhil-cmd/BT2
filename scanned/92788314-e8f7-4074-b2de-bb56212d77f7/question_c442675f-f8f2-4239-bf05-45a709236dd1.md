Target: Shipit::User.find_or_create_author_from_github_commit and the MergeRequest::MERGE_REQUEST_FIELD regex match feeding find_or_create_by_login!. Attacker action: push a commit (or open a PR whose merge commit message an attacker fully controls before any merge, e.g. via a webhook 'push' event carrying a forged commits array processed through Commit.from_github during a GithubSyncJob) with commit message 'Merge-Requested-By: <victim-login>' where <victim-login> is an existing privileged Shipit user's GitHub login. Preconditions: victim-login exists as a Shipit::User with elevated authorized? via Shipit.github_teams membership. Call sequence: Commit.from_github calls User.find_or_create_author_from_github_commit(commit) which regex-matches the raw commit message and calls find_or_create_by_login!(match_info[1]) with zero verification that the actual GitHub commit author/committer or any authenticated actor is the named victim-login. Binding: the GitHub identity that authored/authenticated the commit == the User record attributed as author via the Merge-Requested-By commit-message field; no equality check exists. Impact: Critical, cross-identity attribution allows an attacker's commit message to falsely attribute authorship to a privileged Shipit user, which can influence merge-queue/authorization logic keyed off commit author. Proof idea: minitest test constructing a github_commit resource with commit.message containing 'Merge-Requested-By: victim_login' authored by an unrelated github_id, then asserting Commit.from_github's returned author equals the victim User record rather than the actual commit author.
