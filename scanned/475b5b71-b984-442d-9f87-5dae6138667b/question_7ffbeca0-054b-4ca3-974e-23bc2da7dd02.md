In Shipit::WebhooksController#verify_signature, the GitHub App resolved by Shipit.github(organization: repository_owner) authenticates the raw body via github_app.verify_webhook_signature, but Shipit::WebhooksController#create then dispatches params['repository']['full_name'] to Shipit::Webhooks.for_event(event) handlers unchanged. Can an attacker who owns 'attacker/repo' craft a push webhook whose repository.owner.login is 'attacker' (so it verifies against attacker's own webhook_secret) but whose repository.full_name / repository.owner.login differs from the Stack's actual github_repo, such that repository_owner (the org that authenticated) != the org owning the Stack row a handler mutates? Impact: Critical, cross-repository write to another tenant's Stack. Proof: integration test posting to /webhooks with mismatched owner login vs full_name, asserting the wrong Stack.id received a Commit/Status.
