Shipit::WebhooksController#verify_signature resolves `Shipit.github(organization: repository_owner)` purely from `params.dig('repository','owner','login')` in the UNSIGNED, not-yet-verified JSON body, then uses that org's `webhook_secret` to verify `X-Hub-Signature` against `request.raw_post`. If the attacker POSTs a body whose `repository.owner.login` names an org A configured in Shipit, but whose `repository.full_name`/other repo fields inside the same body name a *different* org B's repository, and the attacker owns a real GitHub webhook for org A (thus can produce a valid signature for org A's secret over an arbitrary body), can Webhooks::Handlers process the payload as authoritative for org B's Stack/Commit records? Binding: the organization whose webhook_secret verified the payload == the organization owning the repository/stack the resulting handler mutates (WEBHOOK PROVENANCE). Scoped impact: Critical, cross-tenant write - a payload signed by org A's secret mutates org B's Stack/Commit/Task rows. Proof: integration test computing a valid sha1 HMAC with org A's configured webhook_secret over a push payload whose repository.full_name is org B/repo, POST to /webhooks, and assert whether Shipit's push handler updates org B's stack.
