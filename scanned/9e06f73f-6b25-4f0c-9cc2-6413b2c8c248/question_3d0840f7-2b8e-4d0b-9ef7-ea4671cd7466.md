Since Shipit::Api::BaseController#authenticate_api_client builds token = parts.select(&:present?).join('--') from HTTP Basic Auth username/password before calling ApiClient.authenticate, and ApiClient.authenticate calls message_verifier.verify(token).to_i (an id lookup, not a signature-tied-to-scope check), can an attacker who only knows a target ApiClient's numeric id (e.g., leaked in a URL, log, or by enumeration) but not the signed token still fail authentication, or does any code path let a raw id or a resigned but stack-mismatched token pass ApiClient.authenticate? Precondition: attacker sends Basic auth with username=<guessed id>, password=''. Binding: token verified by SimpleMessageVerifier must equal a token this engine actually issued for the id looked up; the code must never accept an unsigned or resigned id. Impact: Critical if bypassable, authentication bypass of Api::BaseController. Proof: unit test on ApiClient.authenticate with a raw unsigned decimal string and with a token signed by a different SimpleMessageVerifier instance, asserting both return nil.
