WebhooksController#create re-parses `JSON.parse(request.raw_post)` independently from the `params` hash used by `verify_signature` (which relies on Rails' own body-parsing into `params`). Can an attacker send a body where Rails' JSON parameter parsing (used for `repository_owner`) diverges from a subsequent manual `JSON.parse(request.raw_post)` used by `#create` (e.g. duplicate JSON keys, or a body that Rails silently coerces/wraps differently), so that the field verified by `verify_signature` names one organization while the field actually handed to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` names another? Binding: the parsed structure inspected for verification purposes must be byte-identical to the parsed structure passed to handlers. Impact: Critical, a parser-differential webhook confusion enabling cross-org handler execution. Proof: test with a JSON body containing duplicate 'repository' keys with different owners, asserting the org used for HMAC verification differs from the org whose Repository/Stack row the handler subsequently touches.
