WebhooksController#verify_signature logs `signature=#{request.headers['X-Hub-Signature']}` on every successful (or failed) attempt at Rails.logger.info level. Since the attacker fully controls this header's value in a bypass attempt (org with no webhook_secret), can this ever leak the *real* `webhook_secret` of a properly configured org (e.g. if an operator debugging pastes a real HMAC value from a legitimate webhook into logs later scraped), and is this reachable by an unprivileged attacker without task/log read access? Binding: log output from an attacker-triggered request must not expose another org's real webhook_secret. Impact: Low/out-of-scope for this attacker model (no read access to Rails.logger output), documented here only to confirm no direct in-band leak occurs to the HTTP response itself (`head(422)` returns no body). Proof: test asserting the 422/200 HTTP response body never contains signature or secret material regardless of input.
