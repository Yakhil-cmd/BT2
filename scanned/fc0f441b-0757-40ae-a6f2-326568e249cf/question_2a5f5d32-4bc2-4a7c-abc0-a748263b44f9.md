StatusHandler’s `params` block requires only `sha`/`state` and optional fields, with `accepts :branches`. Given `Commit.where(sha: params.sha)` can match multiple `Commit` rows across different `Stack`s/`Repository`s that happen to share the same sha (e.g. an empty/no-op commit, a cherry-pick, or a merge commit shared across forks), can a single verified-but-org-mismatched status webhook update CI status on ALL matching commits simultaneously across multiple tenants in one request? Binding: one payload's status update must be scoped to exactly the repository named in that same payload, not to every Commit row in the database sharing that sha. Impact: Critical, one forged webhook can taint CI status for multiple unrelated stacks at once. Proof: test creating two Commit fixtures with identical sha in different Stacks/Repositories, posting one status webhook verified under an unconfigured org, and asserting both commits' statuses changed.
