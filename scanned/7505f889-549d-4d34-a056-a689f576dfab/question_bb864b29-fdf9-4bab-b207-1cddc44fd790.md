Preconditions: the victim commit's metadata (tree hash, parents, author/committer identities and dates, message) is public (true for any open-source or public commit). Call sequence: `WebhooksController#create` verifies signature against attacker's own org -> `StatusHandler#process` -> `Commit.where(sha:)` matches the victim's row (Shipit's `Commit` table is not repository-namespaced on `sha`) -> status written to victim's stack. Binding: `Status` rows must be scoped by `(sha, repository)` not `sha` alone; the engine only enforces the former in the query. Scoped impact: Critical, remote, fully attacker-controlled cross-tenant CI state forgery requiring no compromise of the victim. Proof idea: minitest constructing two `Commit` fixtures with an identical `sha` under different `stack_id`s, verifying `StatusHandler.call` (bypassing HTTP, calling the handler directly with a payload naming only the attacker's repo) still mutates the victim's commit.
