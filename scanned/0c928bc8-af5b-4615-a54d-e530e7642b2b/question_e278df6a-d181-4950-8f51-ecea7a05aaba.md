`MembershipHandler#process` performs `team.members.delete(member)` for `action == 'removed'` with `member = User.find_or_create_by_login!(params.member.login)`, all keys taken from the unsigned body once past the loose `organization.login` check. Can an attacker signed for organization A submit a `membership` `removed` event where `organization.login` = 'A' but `team.id`/`team.slug` reference organization B's team, and `member.login` names a legitimate member of B's team (a real GitHub user, not the attacker), removing that user from B's team without B's org ever having sent a webhook? Binding: the organization verified via `webhook_secret` must equal the organization that owns the `Team.find_or_create_by!(github_id: params.team.id)` row being mutated, and the `member` removed must belong to that same verified organization's roster. Impact: Critical, unauthorized removal of a real user from another organization's team, potentially revoking their deploy authorization (`Shipit.github_teams`) without consent. Proof: minitest test pre-seeding a `Team`/membership under org B, POSTing a signed `membership removed` event from org A naming B's team/member, asserting the membership row was deleted.
