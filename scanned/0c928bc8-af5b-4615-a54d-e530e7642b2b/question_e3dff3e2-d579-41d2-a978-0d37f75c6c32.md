In `Shipit.github`, `github_app_config(organization)` does `secrets.github.deep_transform_keys(&:downcase)` then `github_organization = organization.downcase.to_sym`. Since `repository_owner` in `WebhooksController` comes straight from the unsigned body (`params.dig('repository','owner','login')`), can an attacker submit an owner login that differs only in case or Unicode normalization from a legitimately configured organization key (e.g. mixed-case variant of a real org), causing `Shipit.github(organization: repository_owner)` to resolve to the SAME `GitHubApp`/`webhook_secret` as the real org while `repository.full_name` in the body still names a different, unrelated repository under that same organization key but a distinct actual GitHub org account? Binding: the string-normalized organization key resolved for verification must equal the organization that actually owns the GitHub repository referenced by `repository.full_name`. Impact: Critical, cross-tenant dispatch via case-normalization confusion. Proof: minitest test configuring `secrets.github` with one org key, sending a body with a differently-cased `repository.owner.login` and a `repository.full_name` under an unrelated actual namespace, asserting the handler still executes against that mismatched repository.
