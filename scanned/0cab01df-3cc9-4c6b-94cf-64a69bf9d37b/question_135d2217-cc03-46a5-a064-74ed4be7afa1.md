Can an unprivileged attacker who owns/administers their own GitHub organization (thus controlling that org's `webhook_secret` configured in `Shipit.github`) POST a 'membership' webhook with `team.id` set to an integer that collides with a `github_id` already used by a team in `Shipit.github_teams` from a DIFFERENT organization, causing `MembershipHandler#find_or_create_team!`'s `Team.find_or_create_by!(github_id: params.team.id)` to find the EXISTING privileged Team row instead of creating a new one for their org, then call `team.add_member(member)` with their own login? Precondition: two orgs are configured in `Shipit.github`, one of which (org B) has a team listed in `Shipit.github_teams`; attacker only controls org A's webhook_secret. Call sequence: `WebhooksController#create` -> `verify_signature` (verified against org A's secret, matching `repository_owner`/`organization.login` = org A) -> `Shipit::Webhooks.for_event('membership')` -> `MembershipHandler#process` -> `find_or_create_team!` looks up by `github_id` alone, ignoring `organization`. Binding: WEBHOOK PROVENANCE breaks because the org whose webhook_secret verified the body (org A) != the org owning the Team row mutated (org B, since lookup is keyed only on `github_id`). Impact: Critical, authorization escalation into `Shipit.github_teams`, granting attacker's GitHub login `authorized?` == true and full Shipit access. Proof: minitest stub two `Shipit.github` configs, create a `Team` with `github_id: 42, organization: 'org-b'`, add it to `Shipit.github_teams`, POST membership payload signed with org A's secret containing `team.id: 42`, `organization.login: 'org-a'`, `member.login: 'attacker'`, assert a `Membership` row now links 'attacker' to that team and `User.find_by(login: 'attacker').authorized?` is true.
