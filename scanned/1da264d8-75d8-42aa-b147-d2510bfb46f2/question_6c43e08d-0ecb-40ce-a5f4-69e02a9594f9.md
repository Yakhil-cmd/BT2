Target: Shipit::Webhooks::Handlers::PullRequest::ReviewStackAdapter#create! and #user. Attacker action: attacker opens a pull request from their own fork against a tracked repository; params.sender['login'] is attacker's own GitHub login, and params.pull_request.head.ref is attacker-chosen. Preconditions: repository.review_stacks_enabled with provisioning_behavior allow_all. Call sequence: WebhooksController#create (pull_request/opened, signed by the repository owner's webhook_secret, which is legitimate since attacker owns the PR event source repo context) -> OpenedHandler -> ReviewStackAdapter#find_or_create! -> create! -> stack_attributes uses branch: params.pull_request.head.ref verbatim -> ReviewStack created with that branch -> later shipit.yml is fetched FROM that branch and its steps executed via Command#start with no marker distinguishing a fork-authored branch from a trusted one. Binding: the branch/ref used to fetch shipit.yml and execute its Command steps must equal a ref an authorized maintainer approved for execution, not the raw PR head ref supplied by an unprivileged PR author. Impact: Critical RCE - an attacker's own shipit.yml (containing arbitrary machine.environment or deploy steps) on their PR's head ref is executed by Command#start/PTY.spawn on the deploy host once ReviewStack is provisioned, with no fork-authored flag gating execution. Proof: minitest test creating a ReviewStack via ReviewStackAdapter#create! with attacker-controlled head.ref, then asserting DeploySpec::FileSystem reads shipit.yml from that exact untrusted ref and Command#unbundled_env includes attacker-supplied machine.environment keys.
