Preconditions: attacker pushes a commit with message 'Merge-Requested-By: some-admin-login' to their own fork/branch tracked by a stack. Call sequence: WebhooksController#create (push event, signed by attacker's own org's webhook_secret if attacker owns the repo) -> PushHandler -> Commit.from_github -> User.find_or_create_author_from_github_commit -> find_or_create_by_login!(match_info[1]) -> DeploysController#new later calls @stack.build_deploy(@commit, current_user), and the commit.author is now attributed to 'some-admin-login'. Binding: Commit#author must equal the GitHub identity that authored the commit bytes, not an arbitrary login string embedded in the commit message by the pusher. Impact: Critical - an attribution/authorization row (Commit#author_id) is written for an identity the attacker chose, not the actual pusher, enabling downstream deploy-permission or audit logic keyed on commit.author to misattribute the deploy trigger. Proof: minitest test asserting commit.author.login differs from the webhook's actual pusher login after find_or_create_author_from_github_commit runs on an attacker-crafted message.
