[File: coin_reservation.rs] Symbol: `mask_or_unmask_id` used for both encode and cross-chain-replay protection. Attacker-controlled input: a masked `ObjectRef` produced on chain A (with `ChainIdentifier` A) replayed verbatim as a transaction input on chain B (with `ChainIdentifier` B), per the module doc's own threat model requiring the attacker to 'mine an address and currency type such that dynamic_field_key(address, type) = V such that V ^ FOREIGN_CHAIN_IDENTIFIER = TARGET_ACCUMULATOR_OBJECT_ID ^ TARGET_CHAIN_IDENTIFIER'. Required state: attacker holds funds on chain B and knows both `ChainIdentifier`s (both public, derived from genesis checkpoint digest). Call path: `parse(object_ref, chain_identifier_B)` -> `mask_or_unmask_id` unmasking with the wrong chain identifier -> potentially resolves to an unrelated but real accumulator object id if the XOR collision lands on a valid existing id belonging to the attacker's own address rather than requiring an actual preimage attack against a *specific* victim. Invariant: cross-chain masked refs must only resolve successfully (i.e., find an existing accumulator object AND match `sender`) on their originating chain, never spuriously succeed elsewhere. Corrupted value: `unmasked_object_id` incorrectly resolving to a live accumulator on the wrong chain. Scoped impact: theoretically negligible (256-bit search space) per the module's own security argument, but should be regression-tested to ensure `sender != owner` and 'not found' rejections both fire correctly for any cross-chain replay attempt, since a bug in either chain identifier derivation (e.g., default/zero `ChainIdentifier` used in test/staging configs) collapses the search space to zero. Proof idea: test with `ChainIdentifier::default()` (all-zero) as one of the two chains, confirming masking becomes a no-op and a masked-id produced by RPC on a default-identifier network is trivially unmasked and directly usable as a real, un-obfuscated `ObjectID`, and verify whether any production code path could plausibly leave `ChainIdentifier` at its default/zero value.
