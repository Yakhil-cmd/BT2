Target: Shipit::SameSiteCookieMiddleware#call (lib/shipit/same_site_cookie_middleware.rb). Attacker action: attacker's site issues a cross-origin GET to https://shipit-host/merge_status?referrer=... from a victim's browser that has an active Shipit session cookie. Preconditions: SameSiteCookieMiddleware is mounted (per README) and the connection is SSL; the victim previously logged in. Call sequence: middleware unconditionally appends '; SameSite=None' to every Set-Cookie unless already set -> subsequent cross-site GET/PUT requests from the attacker's page carry the session cookie automatically. Binding: the origin that legitimately issued the session == the origin from which requests using that cookie are being made; SameSiteCookieMiddleware makes this binding false for every cookie. Scoped impact (High): cross-origin requests ride a victim's session into any GET-based state read or into insufficiently CSRF-protected state changes. Proof idea: Rack unit test around SameSiteCookieMiddleware#call over an SSL request confirming SameSite=None is added to a Set-Cookie header unconditionally.
