In Shipit::WebhooksController#verify_signature (app/controllers/shipit/webhooks_controller.rb), the organization used to select the verifying Shipit.github(organization: repository_owner) app is read from #repository_owner, which does params.dig('repository','owner','login') on the SAME unauthenticated JSON body being verified. Precondition: a Shipit deployment configures two GitHub orgs per docs/setup.md 'Using Multiple Github Applications', and one org (call it NoSecretOrg) was set up without a webhook_secret (documented as optional), so GitHubApp#verify_webhook_signature returns true unconditionally for it. Attacker action: POST /webhooks with X-Github-Event: pull_request, body.repository.owner.login = 'NoSecretOrg', but body.repository.full_name = 'VictimOrg/victim-repo' (a real repository Shipit tracks under a different, secret-protected org). Call sequence: verify_signature picks NoSecretOrg's app and accepts unconditionally, then LabeledHandler#repository calls Shipit::Repository.from_github_repo_name(params.repository.full_name) which resolves to VictimOrg/victim-repo, and #handle calls stack.archive!/unarchive! on that repo's ReviewStack. Binding that breaks: the org whose webhook_secret verified the payload (NoSecretOrg) != the org owning the repository/stack mutated (VictimOrg) -- WEBHOOK PROVENANCE. Scoped impact: Critical, cross-repository/cross-tenant write -- an attacker with no relationship to VictimOrg archives or re-provisions VictimOrg's ReviewStack, running its shipit.yml provisioning steps. Proof idea: minitest integration test posting this payload with GithubHook stubbed only for NoSecretOrg's nil-secret behavior, asserting the victim stack's provision_status/archived state changed despite no signature matching VictimOrg's secret.
