MembershipHandler (app/models/shipit/webhooks/handlers/membership_handler.rb) processes GitHub 'membership' events which report a user being added/removed from a team. Since this event is scoped to whatever organization's webhook_secret verified it (per verify_signature's org lookup), can an attacker who administers a webhook on their own personal organization (distinct from Shipit.github_teams' configured org) send a 'membership' payload naming a team.slug that collides with one of Shipit.github_teams, causing MembershipHandler to grant/update Membership rows that feed User#authorized?'s team check? Binding: the organization owning the team named in the membership payload == the organization whose webhook_secret verified this request == an org actually listed in Shipit.github_teams. Impact: Critical, escalation into Shipit.github_teams authorization from an unrelated attacker-owned organization. Proof: test configuring Shipit.github_teams for org-real/team-x, POSTing a signed membership event from org-attacker (webhook_secret of org-attacker) naming team.slug='team-x', asserting a Membership row is created that makes User#authorized? true.
