Target: Shipit::ReviewStack#env (app/models/shipit/review_stack.rb) feeding lib/shipit/command.rb Command#unbundled_env and Command#start's PTY.spawn. Attacker action: open a pull request against a repository with review_stacks_enabled and add a label to that PR (labels are settable by the PR's own author on their own PR) named e.g. 'github_token' or 'bundle_gemfile'. Preconditions: repository.review_stacks_enabled, provisioning behavior allows the PR to provision a ReviewStack. Call sequence: ReviewStack#env -> `pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = 'true' }` -> merged into Stack#env -> Commands#env / TaskCommands#env -> Command.new(..., env:) -> Command#unbundled_env `BASE_ENV.merge(...).merge(@env.stringify_keys)` -> PTY.spawn(unbundled_env, *args). Binding that breaks: the set of KEYS permitted to reach PTY.spawn's environment == an allowlist approved by an authorized user; here the key set is exactly the set of label names the PR author chose, with no allowlist at all. Impact: Critical - environment-key injection into the deploy host's spawned process for a repository the attacker doesn't administer. Proof idea: minitest asserting that a ReviewStack whose pull_request has label 'FOO_BAR' produces `commands.env['FOO_BAR'] == 'true'` and that this key was never present in Shipit.env or shipit.yml machine_env, i.e. it originated purely from attacker-chosen label text.
