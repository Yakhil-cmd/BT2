Precondition: Stack S has `stack.ignore_ci?` false, `blocked?` false, and no prior real status. Call sequence: fork push -> attacker computes identical sha -> `POST /webhooks` status event from Repo A -> `StatusHandler#process` -> `Commit#create_status_from_github!` -> `Commit#add_status` -> `stack.schedule_merges`. Binding: the `Stack` a `state: success` status is intended to describe (Repo A's) == the `Stack` whose `Commit#deployable?` it flips (Repo B's) — violated. Scoped impact: Critical, unauthorized deploy trigger for another tenant. Proof idea: minitest test creating two stacks/commits sharing one sha, posting a status webhook scoped to the attacker's repo, asserting the victim stack's commit becomes `success?`.
