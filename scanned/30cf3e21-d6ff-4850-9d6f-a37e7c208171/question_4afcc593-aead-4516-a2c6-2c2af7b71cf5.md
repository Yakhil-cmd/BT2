Target: `Shipit::Webhooks::Handlers::PullRequest::LabeledHandler#pull_request_has_provisioning_label?` and `Repository#provisioning_label_name`. Attacker action: attacker adds a label to their own PR whose `name` exactly matches `repository.provisioning_label_name` (a value they can read from the repo's public label list) to force `unarchive?` to return true and trigger `create!`/`unarchive!`, causing `shipit.yml` on their fork's branch to be scheduled for execution. Preconditions: `provisioning_behavior_prevent_with_label?` or `_allow_with_label?` configured. Call sequence: `LabeledHandler#process` -> `#handle` -> `stack.unarchive!` -> provisioning queue -> eventual checkout/execution of `shipit.yml` from `params.pull_request.head.ref`. Binding: the label name and the branch executed must both be attributable to an authorized approver before `shipit.yml` steps run; no fork-authorship flag exists to gate execution of PR-branch-sourced `shipit.yml`. Impact: Critical — unauthorized execution of attacker-authored deploy steps (RCE-equivalent) since nothing marks the `ReviewStack`'s branch as fork-authored before its `shipit.yml` is executed. Proof: minitest triggering `labeled` webhook with attacker-added label, asserting `ReviewStack` reaches provisioned/unarchived state and the `shipit.yml` fetched belongs to the attacker's fork ref with no maintainer approval recorded.
