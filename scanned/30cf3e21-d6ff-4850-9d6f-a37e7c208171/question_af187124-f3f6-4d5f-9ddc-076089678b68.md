Target: `Shipit::Webhooks::Handlers::PullRequest::LabeledHandler#pull_request_state` / `respond_to_label_change?`. Attacker action: attacker reopens a previously-closed/merged PR from their fork and immediately adds the provisioning label, relying on `pull_request_state == 'open'` being read straight from the payload's `pull_request.state` field rather than re-fetched from GitHub. Preconditions: `review_stacks_enabled`. Call sequence: `respond_to_label_change?` trusts `params.pull_request.state` (attacker-supplied JSON) to gate `unarchive!`, with no cross-check against actual GitHub PR state via an authenticated API call. Binding: `pull_request.state` used for authorization must equal the true current state as known by an authenticated GitHub API call, not the unauthenticated webhook's self-reported field. Impact: Critical — an attacker forging/racing a webhook body with `state: 'open'` for an already-closed/merged malicious PR could provision/unarchive a `ReviewStack` executing stale or crafted `shipit.yml` content outside the intended lifecycle. Proof: minitest sending a `labeled` webhook where `pull_request.state` is 'open' but the PR is otherwise inconsistent, asserting `unarchive!` proceeds without any authenticated re-check.
