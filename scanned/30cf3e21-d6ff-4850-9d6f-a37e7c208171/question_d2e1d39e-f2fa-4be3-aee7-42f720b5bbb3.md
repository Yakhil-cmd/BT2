Target: `Shipit::Webhooks::Handlers::Handler#repository_name` and `#stacks`. Attacker action: attacker POSTs a webhook signed correctly by their own org's `webhook_secret` but whose JSON body nests `repository.full_name` pointing at a repository belonging to another org that also happens to install the same GitHub App / share config. Preconditions: `Repository.from_github_repo_name` performs a lookup with no ownership cross-check back to `repository_owner`. Call sequence: `WebhooksController#create` -> `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` -> `Handler#stacks` -> `Repository.from_github_repo_name(repository_name)`. Binding: `repository_owner` (verified) must equal the owner segment of `repository_name` used by every handler; today nothing enforces `repository_owner == repository_name.split('/').first`. Impact: Critical — cross-repository/cross-tenant mutation of `Stack`, `ReviewStack`, `Commit` or `Task` rows belonging to a repository not owned by the verifying org. Proof: minitest constructing a payload where these two fields diverge, stub `Shipit.github(organization:)` to succeed for attacker org, and assert whether `PushHandler#process` still finds and mutates the victim stack.
