Target: `Shipit::WebhooksController#verify_signature` and `Shipit::Hook`. Attacker action: an unprivileged GitHub user creates their own organization/repo, obtains a legitimate GitHub App installation on that repo, and POSTs to `/webhooks` a `push` event body whose top-level `repository.full_name` names a DIFFERENT, unrelated Shipit-tracked repository, signed with their own org's `webhook_secret`. Preconditions: `Shipit.github(organization: repository_owner)` resolves per-org secrets via `repository_owner` read from `params.dig('repository','owner','login')`; `PushHandler#stacks` calls `Repository.from_github_repo_name(repository_name)` using `payload.dig('repository','full_name')` — a second, independently-controlled field. Call sequence: `verify_signature` verifies HMAC against `repository_owner` (from `repository.owner.login`) while `Handler#repository_name`/`#stacks` trust `repository.full_name` for the actual mutation via `stack.sync_github(expected_head_sha: params.after)`. Binding: the org whose `webhook_secret` verified the signature (`repository_owner`) must equal the org owning `repository.full_name` used to select `stacks`; assert `repository_owner_from_signature == repository.full_name.split('/').first`. Impact: Critical — cross-repository write, an attacker-owned org's signed webhook can trigger `sync_github` on a stack belonging to a repository the attacker does not own if `repository.owner.login` and `repository.full_name`'s owner segment are ever allowed to diverge in the raw JSON body. Proof: minitest `ActionDispatch::IntegrationTest` POSTing to webhooks path with `X-Hub-Signature` computed over a body where `repository.owner.login` == attacker org but `repository.full_name` == 'victim-org/victim-repo', asserting no stack sync occurs / signature check rejects it.
