Target: `Shipit::Webhooks::Handlers::PullRequest::ReviewStackAdapter#create!` and `#stack_attributes`. Attacker action: attacker opens a pull request from their own fork with `head.ref` set to an arbitrary branch name (e.g. containing shell metacharacters or path-traversal segments like `../../etc`), triggering a `pull_request` `opened` webhook. Preconditions: repository has `review_stacks_enabled` and `provisioning_behavior_allow_all?` true. Call sequence: `OpenedHandler#process` -> `ReviewStackAdapter#find_or_create!` -> `#create!` -> `scope.create!(stack_attributes)` where `branch: params.pull_request.head.ref` is written verbatim; this `branch` later feeds `Stack#base_path`/checkout commands executed via `Command`/`PTY.spawn`. Binding: the `ref` approved by a repository maintainer must equal the `ref` later passed as a shell/path argument to `Command#start`; no approval step exists between PR-open and `ReviewStack` creation. Impact: Critical — RCE on the deploy host via an attacker-controlled branch name reaching a checkout/deploy command's arguments or the working-directory path. Proof: minitest creating a `ReviewStack` via `ReviewStackAdapter` with a malicious `head.ref` and asserting the resulting `stack.branch` is used unsanitized in `stack.base_path` / task command construction.
