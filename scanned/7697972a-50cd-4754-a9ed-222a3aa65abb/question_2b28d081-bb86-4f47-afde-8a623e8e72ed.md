In pox-5.clar's register-for-bond, verify-signer-key-grant is checked against `(get-signer-info signer)` for the NEW signer, but the staker's caller-supplied signer-manager <signer-manager-trait> is only invoked via signer-manager-validate-stake for authorization of the stake itself, not to prove signer-key-grants[{signer-key, signer-manager}] was granted specifically for THIS staker's bond-index and amount. Can an unprivileged staker deploy their own signer-manager-trait contract whose validate-stake! always returns (ok true) regardless of staker/amount-ustx/amount-sats/is-bond arguments, register for a bond under a signer they don't actually control key material for (as long as that signer's grant exists for ANY signer-manager, since verify-signer-key-grant only checks signer + signer-key existence, not that contract-caller's signer-manager matches the grantee recorded for that signer-key), and thereby obtain protocol-bond-memberships crediting a signer relationship the real signer key holder never authorized for this staker? Equality broken: every stacking action (a staker joining a signer) == an action authorized by a signer-key-grant issued to that specific signer-manager for that staker. Impact: High, authorizing a stacking action the signer never signed for these parameters, letting an attacker manufacture signing weight for a signer they don't control. Proof: Rust integration test deploying a permissive signer-manager-trait contract and calling register-for-bond, asserting the signer-key-grants entry used doesn't correspond to attacker's signer-manager, then checking signer-shares-staked-for-cycle for that signer increased.
