Target: Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#process / ReviewStackAdapter#create!. Attacker action: attacker who owns an unrelated repository (Repo B) that also has a GitHub App/webhook configured on the same Shipit host sends a crafted POST /webhooks with header identifying App/secret for Repo B but body.repository.full_name set to 'victim-org/victim-repo' (Repo A). Preconditions: Shipit mounts one webhooks endpoint validating only the signature of whichever app's webhook_secret matches, per WebhooksController; no code compares the authenticated app's registered repo/org to payload.repository.full_name. Call sequence: WebhooksController -> signature verification selects an app -> Webhooks::Handlers::PullRequest::OpenedHandler.call(params) -> Handler#repository_name reads payload.dig('repository','full_name') -> Repository.from_github_repo_name(params.repository.full_name) -> ReviewStackAdapter#create! -> ReviewStack created under Repo A's Repository row. Binding: the organization/repository whose webhook_secret authenticated the payload must equal params.repository.full_name used to look up Repository.from_github_repo_name -- this equality is never checked. Impact: Critical, cross-repository write: a ReviewStack (and its provisioned deploy resources) is created against victim-org/victim-repo triggered by an app authenticated only for the attacker's own repo. Proof: minitest integration test to WebhooksController posting a pull_request 'opened' payload whose repository.full_name differs from the app config that validated the signature, asserting a Shipit::ReviewStack row is created scoped to the mismatched repository.
