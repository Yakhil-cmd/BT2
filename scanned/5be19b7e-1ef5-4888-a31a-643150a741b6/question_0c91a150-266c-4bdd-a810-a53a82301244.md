Target: `Shipit::Commit#message=` (app/models/shipit/commit.rb) and `CommitMessage#pull_request_number`/`#pull_request_title` used by `#identify_merge_request`. Attacker action: attacker crafts a commit message on their fork containing a pull request number pattern matching an existing `MergeRequest` on the target stack (e.g. `Merge pull request #<N> from ...`) where `<N>` is a real, unrelated merge request they do not own. Preconditions: stack already has a `MergeRequest` with number `N` created by a legitimate merge. Call sequence: `GithubSyncJob#append_commit` -> `Commit.from_github` -> `before_create :identify_merge_request` -> `stack.merge_requests.find_by(number: message_parser.pull_request_number)` -> `self.author = merge_request.merge_requested_by`. Binding: the `pull_request_number` extracted from attacker-controlled commit text == the `MergeRequest#number` whose `merge_requested_by` is trusted to set `Commit#author`; nothing checks that the commit's actual sha/head matches that merge request's `merge_commit`. Scoped impact: Critical - cross-record identity binding on a Commit row lets an attacker impersonate the requester of an unrelated legitimate merge. Proof idea: minitest pushes a synthetic commit with a colliding PR number message and asserts `commit.author == merge_request.merge_requested_by` despite the commit not being that merge's actual commit.
