Target: `Shipit::Commands#base_path`-derived env via `Stack#env` and `Commands#git`. Attacker action: attacker forks the repository and edits `shipit.yml`/`machine.environment` keys on their fork branch to include env keys named identically to security-sensitive keys already merged by `Commands#base_env` (`GITHUB_TOKEN`, `GIT_ASKPASS`), aiming to have their PR's `shipit.yml` override those keys once a `ReviewStack` deploy runs their spec. Preconditions: repository has `review_stacks_enabled`, `provisioning_behavior_allow_all?`, and continuous deployment/ci-ignore for review stacks. Call sequence: PR opened -> `ReviewStackAdapter#create!` -> stack provisioned and later its `shipit.yml` (from attacker's own head ref) parsed into `DeploySpec` -> merged into `Command#env` via `EnvironmentVariables`/`unbundled_env` with no allowlist restricting which KEYS the fork-supplied spec may set -> `Command#start` calls `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)`. Binding: the set of environment KEYS an authorized user's deploy spec is permitted to set == the set of KEYS actually merged into `unbundled_env` from a fork-authored `shipit.yml`; no allowlist enforces this equality. Scoped impact: Critical - RCE-adjacent credential exfiltration/override: attacker's fork-controlled `shipit.yml` can overwrite `GITHUB_TOKEN`/`GIT_ASKPASS` keys reaching `PTY.spawn`, letting attacker-controlled scripts read or redirect the deploy host's GitHub credentials. Proof idea: minitest builds a `ReviewStack` whose spec sets `machine.environment.GITHUB_TOKEN = 'attacker-value'`, builds the resulting `Command`, and asserts `command.unbundled_env['GITHUB_TOKEN']` equals the attacker-supplied value rather than the value authenticated by `Shipit.github.token`.
