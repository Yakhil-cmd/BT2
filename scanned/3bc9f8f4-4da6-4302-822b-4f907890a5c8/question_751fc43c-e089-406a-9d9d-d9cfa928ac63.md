Target: Api::BaseController#authenticate_api_client BasicAuth workaround module. Attacker action: send a request with `Authorization: Digest ...` or a malformed scheme header alongside a `token` query param on a non-CCMenu `Api::*` endpoint (e.g. StacksController). Preconditions: none. Call sequence: `BasicAuth.basic_credentials?` requires `auth_scheme(request).downcase == 'basic'`; verify that for non-CCMenu controllers there is no equivalent `params[:token]` fallback, so `authenticate_api_client` must render 401 rather than silently accepting a query-string token as CCMenuController does. Binding: only `Api::CCMenuController` (by explicit override) accepts query-string tokens; every other `Api::*` controller inherits BaseController's basic-auth-only path. Scoped impact if this boundary is violated: Critical, token leakage/reuse via URL for endpoints with `write:stack`/`deploy:stack` permissions instead of just `read:stack`. Proof idea: minitest against StacksControllerTest sending `get :index, params: { token: valid_token }` with no Authorization header and asserting `:unauthorized`, confirming the query-token bypass is confined to CCMenuController.
