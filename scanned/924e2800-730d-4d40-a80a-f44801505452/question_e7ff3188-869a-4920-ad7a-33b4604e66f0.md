`WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb) authenticates only that the payload's `repository.owner.login` org's `webhook_secret` signed the body; it establishes no binding to which `Commit`/`Stack` rows `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` may touch. For the `status` event with `StatusHandler`, does a request whose `repository.full_name` is `attacker-org/attacker-repo` but whose `sha` matches a commit in `victim-org/victim-repo` pass `verify_signature` and still mutate the victim's `Commit`? Binding: org verified by `verify_signature` == org owning every row a called `Handler#process` mutates; `StatusHandler` breaks this while `PushHandler`/`CheckSuiteHandler` (via `Handler#stacks`) preserve it. Impact: authenticated-payload boundary bypass writing outside the verified org (Critical). Proof: minitest integration test posting to `/webhooks` with attacker-org signature and asserting mutation on a commit under a different org's stack.
