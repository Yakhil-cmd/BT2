Target: Shipit::User.find_or_create_author_from_github_commit and the MergeRequest::MERGE_REQUEST_FIELD regex match. Attacker action: push a commit to a branch that is later fetched/synced by Shipit (e.g. via GithubSyncJob after a push webhook) whose commit message body is 'Merge-Requested-By: victim-login'. Preconditions: a Shipit::User with login 'victim-login' already exists (e.g. a real operator). Call sequence: Commit.from_github -> User.find_or_create_author_from_github_commit matches the regex on attacker-controlled commit.commit.message -> find_or_create_by_login!('victim-login') -> the created/found Commit's author is now 'victim-login' regardless of who actually authored/pushed the commit. Binding: the GitHub identity that authenticated/pushed the commit == the User assigned as Commit#author. Scoped impact: Critical - identity/authorization spoofing: attacker attributes a commit (and any deploy triggered from it) to an arbitrary existing Shipit user, corrupting audit trail and deploy-authorization checks that key off task/commit author. Proof idea: CommitsTest stubbing a github commit resource with message 'commit\\n\\nMerge-Requested-By: victim-login' and asserting Commit.from_github(...).author.login == 'victim-login' even though the request that produced the commit was never authenticated as that user.
