DeploySpec::FileSystem reads shipit.yml/shipit.<env>.yml from the checked-out working directory populated by TaskCommands#clone/#checkout using the fork's head sha, and supports inherit_from performing 'a deep-merge... performed on the file therein' per README. Can an attacker on a fork PR set inherit_from to a path traversal string (e.g. '../../../etc/passwd' or an absolute path) causing DeploySpec::FileSystem to read and deep-merge file content from outside the repository checkout into the effective deploy_spec, and from there into TaskCommands#env's deploy_spec.machine_env merge, breaking 'the file an authorized reviewer approved as shipit.yml == the file bytes actually merged into the executed deploy spec'? Impact: Critical - arbitrary local file read feeding into the environment/commands passed to Command#start's PTY.spawn, and potential command construction from unintended file contents. Proof idea: minitest constructing a DeploySpec::FileSystem with a shipit.yml declaring inherit_from: '../../../../tmp/evil.yml' and asserting the loader refuses to escape the checkout directory.
