PullRequest#emit_hooks(reason) calls Hook.emit('pull_request', stack, action: reason, pull_request: self, stack:) after every create/update, broadcasting attacker-controlled fields (title, labels, head sha) verbatim to registered Hook receivers (potentially external webhook delivery configured by the operator). Does Hook.emit's payload ever get sanitized/authorized per-stack, i.e. does 'the stack an operator configured a hook receiver for == the stack whose attacker-influenced pull_request payload is delivered to that receiver' hold, or could a cross-stack Hook subscription leak one repository's PR title/label data (potentially containing secrets pasted by mistake, or crafted SSRF payloads if the receiver treats fields as URLs) to a receiver scoped to a different stack? Impact: High information disclosure / SSRF vector if Hook receivers interpolate pull_request fields into outbound requests. Proof idea: minitest asserting Hook.emit is called with stack: matching self.stack exactly, and that no global/other-stack receiver receives this payload.
