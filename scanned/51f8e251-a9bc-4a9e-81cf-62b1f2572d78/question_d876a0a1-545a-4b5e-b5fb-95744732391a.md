Target: Shipit::Command#interpolate_environment_variables / Shipit::EnvironmentVariables#interpolate. Attacker action: attacker-controlled shipit.yml 'deploy.override' step includes a literal '$TASK_ID' or '$SHIPIT_LINK'-style token adjacent to attacker text such that Shellwords.escape output is concatenated in a way that reintroduces shell metacharacters at word-boundary (e.g. step string 'echo $FOO`id`' where $FOO is a task variable the attacker also defines and controls via deploy.variables). Preconditions: repository allows a custom deploy.variables entry the attacker names, and the task-trigger UI/API applies EnvironmentVariables#permit against that same attacker-defined variable list. Call sequence: TaskCommands#perform builds Command.new(command_line, env:, chdir:) -> Command#interpolated_arguments -> Command#interpolate_environment_variables -> EnvironmentVariables#interpolate substitutes $FOO with Shellwords.escape(value) inline into the raw step string, but backtick/command-substitution sequences the attacker placed outside the $VAR token in the step string itself are never escaped, only inside the value. Binding: the interpolated_arguments string that reaches PTY.spawn must equal a string containing no attacker-introduced shell metacharacters outside of Shellwords-escaped variable substitutions -- since the step text itself is attacker-authored shipit.yml, this never holds. Impact: Critical, RCE: unescaped shell metacharacters written directly into the deploy step string by the PR author execute on the deploy host. Proof: minitest test (mirroring command_test.rb's malicious_string case) building a Command from an attacker-controlled step containing a bare backtick sequence outside any $VAR token and asserting Command#run executes the injected subcommand.
