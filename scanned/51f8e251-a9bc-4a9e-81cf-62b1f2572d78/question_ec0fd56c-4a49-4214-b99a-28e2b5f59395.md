Target: Shipit::Commit#pull_request_head_sha (Commit.from_github). Attacker action: attacker crafts a merge commit on a branch such that commit.parents.last.sha (used to set pull_request_head_sha when record.pull_request? is true) can be made to reference an arbitrary sha of the attacker's choosing rather than the actual PR head, by manipulating the merge history on their own fork before opening the PR against the tracked repository. Preconditions: repository merges/tracks commits via the standard push/PR sync path calling Commit.from_github. Call sequence: GithubSyncJob -> Stack#commits.create_from_github! -> Commit.from_github -> `record.pull_request_head_sha = commit.parents.last.sha if record.pull_request?` -> downstream merge-queue logic (max_divergence checks) trusts pull_request_head_sha to represent the actual reviewed PR head. Binding: pull_request_head_sha stored on the Commit row must equal the sha GitHub reports as the PR's actual head at merge time, not merely 'the last parent of this merge commit' which an attacker controls via fork history. Impact: Critical, merge-queue divergence/safety checks (merge.max_divergence) can be bypassed by an attacker shaping merge-commit parentage, allowing an unreviewed sha to be treated as the validated PR head for auto-merge decisions. Proof: minitest test constructing a merge commit resource whose parents.last.sha is set to an attacker-chosen sha unrelated to the PR's real head, asserting Commit.from_github.pull_request_head_sha equals that attacker-chosen value with no cross-check against the GitHub PR API's actual head sha.
