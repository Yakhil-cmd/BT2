Target: Shipit::Stack#links / Shipit::EnvironmentVariables#interpolate. Attacker action: attacker adds a shipit.yml 'links' entry on their PR branch (or influences BRANCH/ENVIRONMENT values feeding interpolation) with a URL template containing '$GITHUB_TOKEN' or another sensitive env key name, hoping the rendered link (surfaced in the Shipit UI to any viewer, including maintainers) embeds a secret value. Preconditions: EnvironmentVariables#interpolate operates over `context = EnvironmentVariables.with(env)` where env is Stack#env, which does not itself include GITHUB_TOKEN, but TaskCommands#env (used at Command#start time) does -- the question tests whether Stack#links' env source is properly restricted to the same minimal set at all call sites. Call sequence: Stack#links -> EnvironmentVariables.with(env).interpolate(url) for each links_spec value sourced from attacker-authored shipit.yml. Binding: the environment variables addressable via '$NAME' interpolation inside a links URL template must equal only the documented non-secret Stack#env keys (BRANCH, etc.) and must never resolve to Command#unbundled_env's GITHUB_TOKEN/GIT_ASKPASS -- verify Stack#env's key set is actually disjoint from secret keys at this call site. Impact: Critical if disjointness fails (credential exfiltration surfaced in UI to any viewer of the stack page, including the unauthenticated read paths for public stack pages if configured), otherwise not exploitable. Proof: minitest test setting shipit.yml links to '${GITHUB_TOKEN}' style template and asserting Stack#links output does not contain the real GITHUB_TOKEN value, using Stack#env's actual key set.
