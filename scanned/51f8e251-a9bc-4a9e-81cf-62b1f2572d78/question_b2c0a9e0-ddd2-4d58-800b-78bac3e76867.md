Target: Shipit::TaskCommands#env (SHIPIT_USER / EMAIL keys). Attacker action: attacker opens a PR whose head commit's author email field (github_commit.commit.author.email) is set to an arbitrary string like '</script>attacker@evil.com' or a value crafted to be interpreted downstream by a notification integration that reads Task#author.email. Preconditions: User.find_or_create_from_github stores email verbatim via appropriate_email_for without validation beyond org-domain filtering (which the attacker's own email need not satisfy if preferred_org_emails is blank for that install). Call sequence: Commit.from_github -> User.find_or_create_author_from_github_commit -> User#github_user= sets email -> Task#author delegates to commit.author -> TaskCommands#env['EMAIL'] = @task.author.email -> Command#start injects it as an environment value read by deploy scripts (e.g. capistrano notification steps). Binding: the EMAIL value present in Command#unbundled_env must equal a value that has been validated as belonging to the authenticated committer identity, not an arbitrary GitHub profile email field the attacker set on their own throwaway account. Impact: High, injection of attacker-chosen string into deploy-script environment consumed by downstream tooling (e.g. shell-interpreted notification scripts), scoped to the deploying stack's task output/environment. Proof: minitest test creating a github_commit stub with a crafted author email containing shell metacharacters, asserting TaskCommands#env['EMAIL'] carries it unescaped into Command#unbundled_env.
