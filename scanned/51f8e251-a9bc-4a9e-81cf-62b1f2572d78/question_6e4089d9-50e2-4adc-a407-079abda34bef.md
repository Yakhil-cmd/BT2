Attacker action: attacker sends POST to a Shipit task-trigger endpoint (Api::TasksController#trigger or TasksController#create) is not directly reachable unprivileged per rules, but attacker instead crafts a shipit.yml on their PR branch defining a custom task whose 'variables' list includes a variable named identically to a privileged env key such as 'GITHUB_TOKEN' or 'GIT_ASKPASS', hoping filter_envs' allowlist-by-name check permits it through because the allowlist is built from the same file the attacker wrote. Preconditions: the deploy_spec read for filter_envs is DeploySpec::FileSystem::new(task.working_directory, stack) — sourced from the currently checked-out shipit.yml on the attacker's branch itself, not from a pinned/approved reference. Impact: Critical, attacker-defined task variable names can collide with and override sensitive Command#unbundled_env keys (e.g. redefine GIT_ASKPASS) because the allowlist source is attacker-controlled.
