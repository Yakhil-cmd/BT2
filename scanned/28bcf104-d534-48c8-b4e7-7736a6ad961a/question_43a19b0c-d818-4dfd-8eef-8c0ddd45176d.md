Attacker action: sends Basic-Auth credentials to any Api::BaseController subclass (e.g. GET /api/stacks) with username and password chosen so that `parts.select(&:present?).join('--')` reconstructs a byte string equal to a signature the attacker can compute offline for a small decimal id (e.g. id=1), attempting to brute force ApiClient ids 1..N against SimpleMessageVerifier#verify without ever having seen Shipit.api_clients_secret. Preconditions: Shipit.api_clients_secret (or fallback secret_key_base) unknown to attacker, small number of ApiClient rows exist. Call sequence: Api::BaseController#authenticate_api_client -> BasicAuth.authenticate yields username/password parts -> joined token -> ApiClient.authenticate(token) -> message_verifier.verify(token) using HMAC over the raw decimal id via SimpleMessageVerifier#encode/#decode which are identity functions (data.to_s / data). Binding: only a token produced by ApiClient#authentication_token (i.e. signed with the real secret) should verify; brute-forcing ids without the secret must never satisfy verify. Scoped impact: Critical (authentication bypass) if and only if it can be shown that the verifier accepts a token the attacker constructed without knowledge of the secret - otherwise this is a dead end and should be reported as such.
