Target: Shipit::Command#start / #unbundled_env (lib/shipit/command.rb) and Shipit::TaskCommands#env (lib/shipit/task_commands.rb). Attacker action: opens a PR that edits `shipit.yml` on their fork branch adding `machine: {environment: {GIT_ASKPASS: '/tmp/attacker_script', GITHUB_TOKEN: 'evil'}}`. Preconditions: Review Stacks enabled for the repo, ReviewStack fetches `shipit.yml` from the PR's head branch before any maintainer review. Call sequence: DeploySpec::FileSystem loads the attacker's shipit.yml -> `machine_env` returns attacker-chosen keys -> TaskCommands#env merges `.merge(deploy_spec.machine_env)` unconditionally (no key allowlist) -> Command#unbundled_env merges `@env.stringify_keys` on top of BASE_ENV which already contains 'GITHUB_TOKEN' -> PTY.spawn receives an environment where attacker has overwritten GITHUB_TOKEN/GIT_ASKPASS. Binding: env_keys_permitted_by_TaskDefinition#filter_envs == env_keys_actually_spawned_by_Command#unbundled_env. Impact: Critical - credential exfiltration/RCE: `machine.environment` is merged with no key allowlist (unlike `EnvironmentVariables#permit` used for deploy_variables), letting a PR author overwrite GITHUB_TOKEN or GIT_ASKPASS reaching PTY.spawn. Proof idea: minitest test stubbing a `cached_deploy_spec` with `machine.environment` containing 'GITHUB_TOKEN' and asserting `TaskCommands#env['GITHUB_TOKEN']` differs from `Shipit.github.token`, i.e. the attacker's shipit.yml value wins in the PTY.spawn environment.
