, [UInt(delegated_ustx), Principal(delegate_to), ...])` -> pox-5's `delegate-stx` records `delegated_ustx` in delegation state without verifying the delegator's balance at delegation time (balance is only checked later, if at all, when the delegate actually locks). Equality that breaks: `delegated_ustx` recorded == STX the sender actually owns and can commit; an unbounded value lets a delegate later attempt to stack more than the delegator owns. Impact: Critical if this lets `stack-aggregation-commit`-style paths (via delegate's signer-manager) lock a `stacked_ustx` no other equality catches, producing an over-committed lock claim vs real balance — freezing/crediting reward-slot weight beyond real ustx. Proof idea: Rust test submitting `DelegateStxOp{delegated_ustx: u128::MAX, ...}` for a low-balance sender then attempting a follow-on stack on behalf of that principal at close to `delegated_ustx`; assert the actual locked amount never exceeds the sender's true balance.
