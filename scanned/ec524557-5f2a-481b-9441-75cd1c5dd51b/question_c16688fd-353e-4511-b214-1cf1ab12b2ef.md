In app/controllers/shipit/webhooks_controller.rb, `verify_signature` calls `Shipit.github(organization: repository_owner)` and `repository_owner` reads `params.dig('repository', 'owner', 'login')` from the UNSIGNED, still-unverified JSON body before HMAC verification occurs. Attacker action: an internet user (any repository owner) POSTs to /webhooks with `X-Hub-Signature` computed using their own org's `webhook_secret` but with `repository.owner.login` and `repository.full_name` set to a victim org/repo. Precondition: Shipit is configured with `Shipit.github` for multiple organizations (per README multi-app setup). Call sequence: `WebhooksController#verify_signature` -> `Shipit.github(organization: repository_owner)` picks the attacker's own app/secret because `repository_owner` is attacker-controlled -> `verify_webhook_signature` succeeds against the attacker's secret -> `Webhooks.for_event(event).each { |handler| handler.call(params) }` runs handlers (e.g. `Handlers::PushHandler`, `MembershipHandler`) using the victim `repository.full_name`/`organization.login` value. Binding that breaks: the organization whose `webhook_secret` verified the body (attacker's org) != the organization named in `params['repository']['owner']['login']` that the handler subsequently writes against. Scoped impact (Critical): a payload signed by attacker's org's webhook_secret mutates or creates records (Stack, Team, Membership, Commit, Status) scoped to a victim's repository/organization -- cross-tenant write. Proof idea: minitest integration test in test/controllers/webhooks_controller_test.rb that stubs `Shipit.github(organization: 'attacker-org')` to return a verifier that always succeeds, POSTs a `push` event whose `repository.owner.login == 'victim-org'`, and asserts a `GithubSyncJob`/`Commit`/`Stack` write happened against the victim's `Repository` despite the verifying org differing from the repository owner.
