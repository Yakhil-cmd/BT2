In app/models/shipit/webhooks/handlers/membership_handler.rb, `MembershipHandler#process` calls `find_or_create_team!` which reads `params.organization.login` to set `team.organization` and `Team.find_or_create_by!(github_id: params.team.id)`, entirely trusting the body's `organization.login` and `team.id` fields rather than the organization whose `webhook_secret` the controller used to verify the request. Attacker action: attacker who controls a GitHub App installation/org (Shipit.github organization X) sends a `membership` event whose `organization.login` names organization Y and `team.id` collides with (or newly creates) a team the attacker wants to be a member of. Precondition: multi-org Shipit config; attacker owns org X and its `webhook_secret`. Call sequence: `WebhooksController#verify_signature` verifies against org X's secret (payload's `repository_owner`/`organization.login` fallback used for verification is also attacker-controlled) -> `MembershipHandler#find_or_create_team!` creates/updates a `Team` row with `organization: 'Y'` -> `team.add_member(User.find_or_create_by_login!(params.member.login))` adds an arbitrary GitHub login (including the attacker's own) as a member of a Team scoped to org Y. Binding: the organization whose webhook_secret verified the payload == `params.organization.login` written into `Team#organization`/`Membership`. Scoped impact (Critical): escalation into `Shipit.github_teams` authorization for org Y using only org X's webhook_secret -- since `Membership` rows drive `User#authorized?` (`teams.where(id: Shipit.github_teams.map(&:id)).exists?`), an attacker can grant themselves membership in a team that unlocks Shipit UI/deploy access without ever being vetted by org Y. Proof idea: minitest test posting a `membership` webhook whose HMAC is verified using org X's `webhook_secret` fixture but `organization.login == 'shopify'`/team id matching `shipit_teams(:shopify_developers)`, then asserting `Membership.exists?(team: shopify_developers, user: attacker_user)` and `attacker_user.authorized?` becomes true.
