lib/shipit/command.rb `Command#unbundled_env` merges `BASE_ENV.merge('PATH' => ...).merge(@env.stringify_keys)` where `@env` originates, for review-stack/task execution, from `Shipit.env` plus `shipit.yml`'s `machine.environment` (per README) -- there is no allowlist on the KEYS of `@env`, only `EnvironmentVariables#permit` (used only for the `env` param on deploy/rollback API calls) restricts VALUES for a fixed set of names. Attacker action: an attacker with fork-PR access supplies a `shipit.yml` on their own branch (executed by `ReviewStack` since branch is attacker-controlled per `stack_attributes[:branch]`) declaring `machine.environment` with a key like `GIT_ASKPASS` or `LD_PRELOAD` or overriding `PATH`/`BUNDLE_GEMFILE`. Precondition: `review_stacks_enabled` with `provisioning_behavior_allow_all?`. Call sequence: PR opened -> `ReviewStackAdapter#create!` -> `ReviewStack` provisioned -> `DeploySpec::FileSystem` reads the attacker's `shipit.yml` from the attacker's own fork branch -> `machine.environment` merged into `Command.new(..., env:)` -> `Command#unbundled_env` merges those attacker-chosen KEYS unfiltered -> `PTY.spawn(unbundled_env, *interpolated_arguments, ...)`. Binding: every key in `Command#unbundled_env` originates from a spec an authorized user approved == false, since the fork-authored `shipit.yml` was never reviewed. Scoped impact (Critical): attacker-controlled environment KEYS (not just values) reach `PTY.spawn`, enabling RCE on the deploy host via mechanisms like `GIT_ASKPASS`/`LD_PRELOAD`/`PATH` hijack. Proof idea: minitest test building a `Command` with `env: {'LD_PRELOAD' => '/tmp/evil.so'}` sourced from a simulated fork `shipit.yml`, asserting `command.unbundled_env['LD_PRELOAD']` is passed unfiltered into the args given to `PTY.spawn` (stub `PTY.spawn` and assert the env hash key is present).
