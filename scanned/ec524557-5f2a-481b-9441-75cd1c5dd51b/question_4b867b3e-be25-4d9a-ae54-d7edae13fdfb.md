lib/shipit/environment_variables.rb `#interpolate` performs `Shellwords.escape(@env.fetch(variable) { ENV[variable] })` -- if the requested `$VARIABLE` name is not in the caller-provided `@env` hash, it silently falls back to the *process* `ENV`, i.e., the Shipit server's own real environment (potentially containing `GITHUB_TOKEN`, `DATABASE_URL`, etc., unless explicitly cleared). Attacker action: an attacker who controls a fork's `shipit.yml`/deploy step defines a command argument like `echo $DATABASE_URL` or `echo $GITHUB_TOKEN` where that variable name is deliberately absent from the whitelisted `env:` hash passed to `Command.new`. Precondition: any deploy/rollback/review-stack step whose command string is attacker-influenced (fork shipit.yml under `allow_all`/`allow_with_label` provisioning). Call sequence: `Command#interpolated_arguments` -> `interpolate_environment_variables` -> `EnvironmentVariables#interpolate` -> falls back to `ENV[variable]` (host process env) -> value written into the shell command line -> captured into task output (`EphemeralCommitChecks#write`/`Task` output) which is rendered back to the PR author/build log. Binding: the variable KEY permitted for interpolation (from the deploy-spec-approved set) == the KEY actually resolved by `interpolate`; the silent `ENV[variable]` fallback breaks this since no allowlist gates it. Scoped impact (Critical): exfiltration of host process environment secrets (potentially `GITHUB_TOKEN` or other deploy-time secrets) into task output visible to an unprivileged PR author. Proof idea: minitest test per test/unit/environment_variables_test.rb style: set `ENV['SHIPIT_SECRET_TEST'] = 'super-secret'`, construct `Command.new('echo $SHIPIT_SECRET_TEST', env: {}, chdir: '.')`, run it, and assert the secret value appears in the command output -- demonstrating the leak path.
