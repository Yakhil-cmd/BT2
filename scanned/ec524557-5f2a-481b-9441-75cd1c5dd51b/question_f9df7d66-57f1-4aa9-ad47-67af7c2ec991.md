In app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb, `#stack_attributes` sets `branch: params.pull_request.head.ref` directly from attacker-supplied JSON with no validation that the ref belongs to a fork the repository owner has vetted, and `ReviewStackAdapter#create!` persists a `ReviewStack` whose `branch` is later fed to git checkout/deploy commands. Attacker action: attacker opens a pull request from their own fork whose `head.ref` contains shell metacharacters or path-traversal-like segments (e.g. `../../etc`, or a name crafted to interpolate as `$VAR` per `Command#interpolate_environment_variables`), then the `opened` webhook is delivered with a valid signature (attacker's own PR against a repo they can open PRs on). Precondition: `repository.review_stacks_enabled` and `provisioning_behavior_allow_all?` true (common ReviewApp config). Call sequence: `OpenedHandler#process` -> `ReviewStackAdapter#create!` -> `stack_attributes[:branch]` stored on `ReviewStack` -> later `ReviewStack` provisioning enqueues commands via `StackCommands`/`Command.new(..., chdir: stack.deploy_path/base_path)` which interpolates `$`-prefixed tokens in arguments (`lib/shipit/environment_variables.rb#interpolate`). Binding: the ref approved by a maintainer (none exists) == the ref executed by `Command#start`/`PTY.spawn`; no such approval gate exists so the binding is vacuously false for fork-authored branches. Scoped impact (Critical): attacker-controlled branch name reaches `Command#interpolated_arguments` -> `PTY.spawn`, i.e., RCE on the deploy host. Proof idea: minitest test constructing a `ReviewStack` with `branch: '$(touch /tmp/pwned)'` or a `$ENV_VAR`-shaped branch, running the `checkout`/`clone` `Command` built from `StackCommands`, and asserting the malicious substring appears verbatim in `Command#interpolated_arguments` fed to `PTY.spawn`.
