`Shipit::Webhooks::Handlers::MembershipHandler#process` builds/loads a `Team` via `find_or_create_team!` using `params.team.id`/`params.organization.login` straight from the webhook body, then calls `team.add_member(member)` or `team.members.delete(member)` based on `params.action`, with the only prior gate being `verify_signature`'s `repository_owner` check which for a `membership` event falls back to `params.dig('organization','login')`. Can an attacker who owns organization A (with its own `webhook_secret`) send a signed `membership` event where `organization.login` = 'A' (satisfying verification) but `team.id`/`team.slug` correspond to an existing `Shipit::Team` actually tied to organization B in `Shipit.github_teams`, adding themselves (`member.login`) as a member of B's team? Binding: the `organization.login` verified against `webhook_secret` must equal the organization that legitimately owns the `Team` record identified by `params.team.id`. Impact: Critical, escalation into another organization's team membership (`Shipit.github_teams` authorization), enabling privilege escalation for deploy authorization checks elsewhere. Proof: minitest test pre-creating a `Team` with `github_id` belonging to org B, then POSTing a signed `membership` event from org A naming that same `team.id`, asserting the attacker's `User` was added as a member.
