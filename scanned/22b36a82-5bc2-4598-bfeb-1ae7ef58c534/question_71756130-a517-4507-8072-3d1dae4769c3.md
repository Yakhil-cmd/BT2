`GitHubApp#verify_webhook_signature` only accepts `algorithm == 'sha1'` after `signature.split("=", 2)`. Can an attacker who knows (or brute-forces via error messages) that a target org's secret is configured, send `X-Hub-Signature: sha256=<anything>` or a malformed header lacking `=`, and does the resulting `head(422)` in `verify_signature`'s `rescue` path ever leak the `webhook_secret` or accept the request? Binding: signature algorithm accepted must equal the algorithm actually computed (`sha1`), and no code path other than genuine HMAC match should return true. Impact: Critical (auth bypass) if any malformed input is misinterpreted as verified; test should show it is correctly rejected but confirm no exception leaks secret material in logs (`Rails.logger.info` includes raw signature, not secret). Proof: minitest test asserting `verify_webhook_signature('sha256=deadbeef', body)` returns false and controller responds 422 without secret disclosure.
