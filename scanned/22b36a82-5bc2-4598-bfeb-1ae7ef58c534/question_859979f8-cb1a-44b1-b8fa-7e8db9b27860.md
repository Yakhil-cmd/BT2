`Shipit::Webhooks::Handlers::StatusHandler#process` looks up `Commit.where(sha: params.sha)` globally with no repository or organization scoping at all, then calls `commit.create_status_from_github!(params)` for every matching commit across ALL stacks/repos sharing that SHA. Can an attacker with a webhook correctly signed for their own low-security organization A (with a configured `webhook_secret`) send a `status` event naming a `sha` that happens to also exist in organization B's commit history (e.g. a shared base commit, cherry-pick, or merge commit), writing a forged CI status onto B's commit? Binding: the organization whose `webhook_secret` verified the payload must equal the organization owning every `Commit` row matched by `params.sha`. Impact: Critical, cross-repository write of a fabricated commit status onto another organization's commit. Proof: minitest test creating commits with identical SHA under two different stacks/repositories, POSTing a signed `status` webhook from org A naming that SHA, asserting org B's commit status was also mutated.
