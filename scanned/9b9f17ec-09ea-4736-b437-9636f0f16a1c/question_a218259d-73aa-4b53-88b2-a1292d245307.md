[Function: repay] Victim B holds collateral in asset Z that is only eligible under B's current egroup because of a paired debt asset X (BORROW-DISABLED-MASK differs per egroup for Z). Attacker A drains B's X debt to 1 via observing public state and dust-repays on-behalf-of=B, clearing X's debt bit. CALL SEQUENCE: block N, A's repay ft-X u1 on-behalf-of=B triggers mask-update removing X's debt bit, refresh recomputes mask, get-egroup resolves B into an egroup where Z's BORROW-DISABLED-MASK now flags Z's borrowing as disabled for B going forward (not retroactively removing collateral, but freezing further borrow against Z). B, later same block, attempts to borrow more against Z (a legitimate action B was mid-transaction planning), which now reverts with ERR-EGROUP-ASSET-BORROW-DISABLED. INVARIANT BROKEN: NON-INTERFERENCE - B's ability to execute a previously-valid borrow call is removed by A's unsolicited repay. IMPACT: High - temporary freezing of B's ability to borrow against already-posted collateral until B re-adds the X debt bit by re-borrowing X. Proof: simnet test asserting B's borrow against Z succeeds pre-A-repay and fails with ERR-EGROUP-ASSET-BORROW-DISABLED post-A-repay in the same block.
