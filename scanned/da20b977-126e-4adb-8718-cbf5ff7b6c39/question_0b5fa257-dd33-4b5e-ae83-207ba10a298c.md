In app/models/shipit/webhooks/handlers/pull_request/*.rb (OpenedHandler/ClosedHandler/ReopenedHandler/EditedHandler/AssignedHandler/LabeledHandler/UnlabeledHandler), every handler resolves `repository = Shipit::Repository.from_github_repo_name(params.repository.full_name)` from the same unsigned-relative-to-org body field used only to pick the verifying secret. Attacker action: attacker owns org-a (any GitHub user can create an org and install the Shipit GitHub App receiving a valid webhook_secret for org-a per README setup), signs a pull_request 'closed' payload with org-a's secret but sets repository.full_name to an org-b review-stack-enabled repository and pull_request.number to a real open PR number in org-b. Preconditions: org-b has review_stacks_enabled with a live ReviewStack tied to that PR number. Call sequence: verify_signature accepts (org-a secret matches org-a-authored bytes), ClosedHandler#process calls review_stack.archive! on org-b's ReviewStackAdapter-resolved stack. Binding: the org that verified the payload must equal the org whose ReviewStack/PullRequest row is archived/updated; ClosedHandler never checks that org-b's webhook_secret verified this request. Impact: Critical, unauthorized stack mutation (archiving/tearing down another tenant's review stack), a denial-of-availability-adjacent but explicitly-scoped cross-repo write. Proof idea: integration test with two stacks under different orgs, signed pull_request:closed payload naming org-b's repo but signed with org-a's secret, assert org-b's review stack transitions to archived.
