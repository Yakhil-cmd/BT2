In `stackslib/src/chainstate/stacks/boot/pox-5.clar`'s `register-for-bond`, an unprivileged staker with an existing L1-locked `protocol-bond-memberships` entry (`is-l1-lock: true`) calls `register-for-bond` again during the bond's L1 unlock window with `btc-lockup` as `(err sbtc-amount)` (sBTC path) instead of a fresh `l1-lockups` proof, so `old-sbtc` is read via `get-staker-custodied-sbtc tx-sender` (which returns 0 for an L1-locked membership) while the STACKS-side lock carried by `pox_rollover_v5` in `pox-locking/src/pox_5.rs` is rolled onto `new-sbtc` sats the staker only claims to hold, not sats actually re-verified as still locked on Bitcoin. Precondition: staker has an active `is-l1-lock: true` membership at bond N nearing `get-bond-l1-unlock-height`; call sequence: `register-for-bond(bond-index=N+6, signer-manager, amount-ustx, err(sats), signer-calldata)` -> `roll-sbtc tx-sender old-sbtc new-sbtc` -> `map-set protocol-bond-memberships` -> pox-locking `pox_rollover_v5`. Equality that breaks: sats credited by the original L1 lockup proof (PROOF TRUTH) no longer equals sats now custodied as `protocol-bonds-total-staked`, since `old-sbtc` is computed as 0 for the L1 path yet the new membership's `amount-sats` is fully counted toward reward shares. Impact: Critical, double-counting a commitment — the staker gets bond-N+6 reward shares backed by BTC that was only ever proven once, diluting other bond N+6 participants' `sBTC paid`.
