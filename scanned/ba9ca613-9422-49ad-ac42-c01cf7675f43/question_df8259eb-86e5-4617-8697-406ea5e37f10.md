Target: `Shipit::GithubAuthenticationController#callback`. Attacker action: attacker (an ordinary GitHub user) sets `session[:pending_stack_id]`-style data or any pre-auth session key by visiting an unauthenticated Shipit page, then shares that same session cookie with a victim (e.g. shared browser profile, CI runner, kiosk) before the victim completes `GET /auth/github/callback` with their own GitHub identity. Preconditions: engine mounted, no host-level session ID rotation configured. Call sequence: `callback` calls `sign_in_github(auth)` and sets `session[:user_id]`/`session[:authenticated]` but never calls `reset_session`, so the underlying session store record set up before authentication is preserved. Binding: the session identifier bound before authentication == the session identifier bound after authentication (CWE-384). Impact: Critical, authentication bypass — attacker who possesses the pre-auth session can recover the now-authenticated session and act as the victim on `stacks`/deploy endpoints. Proof idea: integration test capturing `session.id` (or the raw session cookie) before and after `get :callback`, asserting it changes; current code has it unchanged.
