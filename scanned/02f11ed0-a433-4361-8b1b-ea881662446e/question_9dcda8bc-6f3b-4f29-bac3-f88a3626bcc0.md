Target: `PullRequest::OpenedHandler#provision?`. Attacker action: attacker opens a PR without any label against a repository configured with `provisioning_behavior: :prevent_with_label` and `review_stacks_enabled: false`. Preconditions: repository has never had review stacks enabled; `provisioning_behavior_prevent_with_label?` true; PR carries no labels. Call sequence: webhook -> `provision?` -> third disjunct `(repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?)` is true regardless of `review_stacks_enabled` -> `ReviewStackAdapter#create!` -> `Shipit::ReviewStackProvisioningQueue.add(stack)`. Binding: `repository.review_stacks_enabled` (gate an operator toggles) must equal `true` for any provisioning to occur, but a stack is provisioned while it is `false`. Impact: Critical, unauthorized stack provisioning and eventual RCE via `TaskCommands#perform` reading `shipit.yml` from the attacker's branch. Proof idea: minitest asserting `provision?` returns true and a `ReviewStack` row is persisted with `review_stacks_enabled` false on the owning repository.
