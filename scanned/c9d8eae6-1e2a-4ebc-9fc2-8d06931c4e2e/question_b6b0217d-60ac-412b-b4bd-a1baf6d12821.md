[Target: Shipit::PullRequest#find_or_create_commit_from_github_by_sha!] Can an attacker who opens a pull request from a fork control `github_pull_request.head.sha` to reference a commit sha that exists in a *different* stack's `stack.commits` table (collision across repos is unlikely for real shas, but the lookup `stack.commits.by_sha(sha)` is stack-scoped) such that if it misses, `stack.github_api.commit(stack.github_repo_name, sha)` fetches using the *target* stack's credentials for a sha the attacker controls, and the resulting `Commit` gets created and attributed via `stack.commits.create_from_github!`? Binding: `stack.github_repo_name` used to fetch a commit == the repository that actually authored/owns `github_pull_request.head.sha`. Impact: Critical, cross-repository read using the target stack's GitHub App credentials for attacker-chosen shas, and creation of a `Commit` row under the wrong stack if a sha collision occurs between the attacker's fork and the upstream repo. Proof: minitest opening a PR against stack A with `head.sha` equal to a real commit that only exists in a fork, and asserting `stack.github_api.commit(stack.github_repo_name, sha)` is called with A's app credentials against a sha the attacker fully controls, then asserting the created `Commit`'s `author`/`committer` come from `User.find_or_create_author_from_github_commit`, which can be login-squatted per the `find_or_create_by_login!` binding above.
