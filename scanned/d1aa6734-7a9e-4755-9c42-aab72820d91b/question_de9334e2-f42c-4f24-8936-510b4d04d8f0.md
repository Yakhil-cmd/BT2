Target: Shipit::GithubAuthenticationController#callback. Attacker action: attacker crafts a cross-site POST to /github/authentication/callback (route accepts POST) from an attacker-controlled page while victim is logged into GitHub, without any CSRF token, since ActionController::Base here lacks protect_from_forgery. Preconditions: browser follows the OAuth redirect flow that OmniAuth strategy allows via POST; no origin/state validation is enforced by the controller itself. Call sequence: cross-site form POST -> callback -> session[:user_id] = sign_in_github(auth) -> redirect_to(request.env['omniauth.origin']). Binding: the party that completed the OAuth exchange in this session (the browser making the request) == the GitHub identity that the attacker intended, but with no CSRF protection the request origin cannot be trusted to equal the session owner's origin. Impact: Critical, authentication bypass / forced OAuth completion binding a session to an identity chosen by request flow rather than a validated same-site origin, usable to plant session state that resolves against a stack the victim can deploy. Proof idea: integration test posting to the callback route from a request lacking a valid CSRF token/Origin header and asserting the controller does not reject it.
