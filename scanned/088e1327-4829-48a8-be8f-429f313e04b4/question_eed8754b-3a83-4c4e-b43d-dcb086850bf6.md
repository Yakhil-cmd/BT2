Attacker action: holding a token scoped to stack A, send `GET /api/stacks/<A_slug>/tasks/<id>` where `<id>` is a `Deploy`/`Task` primary key belonging to stack B. Preconditions: `Task`/`Deploy` ids are sequential/globally unique across stacks (ActiveRecord global PK), making cross-stack id guessing trivial. Binding: task lookup ∈ tasks belonging to the stack `current_api_client.stack_id` authorises. Impact: Critical if any code path performs `Task.find(id)` directly instead of `stack.tasks.find(id)`, exposing another org's deploy metadata/output. Proof idea: test requesting a task id known to belong to a different stack through an A-scoped token's stack path, asserting 404 and no serialized attributes of the foreign task returned.
