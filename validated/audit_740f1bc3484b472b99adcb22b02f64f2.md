### Title
Cross-organization team-membership revocation via unscoped `github_id` lookup in `MembershipHandler#process` - (File: app/models/shipit/webhooks/handlers/membership_handler.rb)

### Summary
`MembershipHandler#process` looks up the target `Team` solely by the globally-unique GitHub `team.id` and never checks that the organization that verified the webhook signature actually owns that team. Because `WebhooksController#verify_signature` selects the signing secret using `repository_owner` (which for membership events falls back to `params.dig('organization','login')`), any organization onboarded into Shipit can sign a `membership`/`removed` payload with its own legitimate webhook secret while naming a team `id` that belongs to a *different* organization, causing `team.members.delete(member)` to strip a victim's authorization for a team they were never removed from by their real organization.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:

`organization_that_verified_signature (params.dig('organization','login') used in Shipit.github(organization: repository_owner)) == team.organization (the org that actually owns the Team record identified by params.team.id)`

Trace:
- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` (line 59-62) as `params.dig('repository','owner','login') || params.dig('organization','login')`. Real GitHub `membership` events have no `repository` key, so this resolves to the attacker-supplied `organization.login`. `Shipit.github(organization: repository_owner)` then loads the webhook secret configured for *that* org and verifies the signature against it. Since the attacker controls that org (it is a legitimately onboarded org in the multi-org config) and signs with its own real secret, verification passes.
- `MembershipHandler#process` (app/models/shipit/webhooks/handlers/membership_handler.rb:22-34) then calls `find_or_create_team!` (lines 38-43), which does `Team.find_or_create_by!(github_id: params.team.id)`. This lookup is keyed **only** on the numeric GitHub team id, which is global across GitHub, not scoped to the organization that signed the request. If a team with that `github_id` already exists (the victim's real team, belonging to a different org), it is simply found — the `organization:` assignment in the `find_or_create_by!` block only executes on record creation, so the existing team's real `organization` attribute is untouched and irrelevant to the lookup.
- For `action == 'removed'`, `team.members.delete(member)` (line 30) unconditionally removes the `Membership` row for `User.find_or_create_by_login!(params.member.login)` from that team — with no check that `params.organization.login` matches `team.organization`.

Attacker request: `POST /webhooks` with header `X-Github-Event: membership`, body `{action: 'removed', team: {id: <github_id of victim's real team>, name, slug, url}, organization: {login: 'attacker-owned-org'}, member: {login: 'victim-login'}}`, signed with `attacker-owned-org`'s own valid webhook secret.

Why existing guards fail: `verify_signature` only proves the request was signed by *some* legitimately configured organization — it says nothing about whether that organization owns the team referenced in the payload. `ExplicitParameters` (the `params do ... end` schema) validates types/presence only, not cross-object provenance. There is no `require_permission!`, `authorized?`, or team/organization consistency check anywhere in the `removed` branch.

### Impact Explanation
A successful request deletes the victim's `Shipit::Membership` row for a team in `Shipit.github_teams`, without any action from the victim or their real organization. Since `User#authorized?` (app/models/shipit/user.rb:80-82) grants access to Shipit stacks based on membership in `Shipit.github_teams`, this directly revokes the victim's authorization to use Shipit — an unauthorized, cross-tenant modification of authorization state. This matches the "escalation/loss into `Shipit.github_teams` authorization" High-severity category (here in the destructive direction: unauthorized de-authorization). The attack is repeatable against any team `github_id` and any victim login, and crosses tenant boundaries in a multi-org Shipit deployment, since the org that signs the request need not be the org that owns the affected team.

### Likelihood Explanation
Requires: (1) a multi-org Shipit configuration where the attacker controls/administers at least one onboarded organization (and therefore legitimately possesses that org's own webhook secret — this is normal, not privileged, for an org admin of their own org); (2) knowledge of the numeric GitHub `team.id` of the victim's target team (discoverable via GitHub's public/team APIs or by having seen a prior legitimate webhook); (3) knowledge of the victim's GitHub login (public). No Shipit session, API token, or Shipit-side secret is needed — only the attacker's own org's webhook secret, which they legitimately hold. Cost is a single crafted HTTP POST, fully repeatable and scriptable.

### Recommendation
In `MembershipHandler#find_or_create_team!`/`#process`, verify that the organization used to authenticate the webhook (`params.organization.login`, i.e. `repository_owner`) matches the `Team#organization` of the team resolved by `github_id` before performing `add_member`/`team.members.delete`. Reject (or drop) the event if `team.organization != params.organization.login` for an already-existing team. Additionally, `Team.find_or_create_by!` should scope the lookup by `(github_id, organization)` rather than `github_id` alone, or the handler should independently re-verify that the signing organization equals `team.organization` before mutating memberships.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb` (or a new membership-scoped test) a minitest such as:

```ruby
test ":membership removed event from a different org than the team's org still deletes the membership (vulnerability)" do
  team = shipit_teams(:shopify_developers)          # organization: 'shopify'
  victim = shipit_users(:walrus)                     # already a member of team via fixture
  assert team.members.include?(victim)

  @request.headers['X-Github-Event'] = 'membership'
  # Sign with a *different*, attacker-controlled org's secret (e.g. 'cyclimse'),
  # while referencing shopify's team id and repository/organization login not equal to team.organization
  payload = {
    action: 'removed',
    team: { id: team.github_id, slug: team.slug, name: team.name, url: team.api_url },
    organization: { login: 'cyclimse' },   # attacker-owned org, != team.organization ('shopify')
    member: { login: victim.login },
    repository: { owner: { login: 'cyclimse' } }
  }.to_json

  Shipit.github(organization: 'cyclimse').expects(:verify_webhook_signature).returns(true)

  assert_difference -> { Membership.count }, -1 do
    post :create, body: payload, as: :json
    assert_response :ok
  end

  refute team.reload.members.include?(victim)
end
```

Assertion of the broken binding: before the request, `team.organization ('shopify') != payload_organization ('cyclimse')` yet `Membership.count` still decreases and `team.members.include?(victim)` becomes false — demonstrating the org that verified the signature is not required to equal the org owning the team being mutated.           team = find_or_create_team!

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
