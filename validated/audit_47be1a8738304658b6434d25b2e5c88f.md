### Title
Attacker-controlled repository `Description` is rendered unescaped by tview, allowing forged `[green](installed)` / `[yellow](official)` badges in `gh extension browse` - ([File: pkg/cmd/extension/browse/browse.go])

### Summary
`extEntry.Description()` returns the raw `repo.Description` string fetched from the GitHub search API without any escaping, and this value is passed directly as the secondary text argument to `tview.List.AddItem`. Because `tview.List` interprets `[color](...)` region/color tag syntax in item text (the same mechanism `extEntry.Title()` itself deliberately uses to render the real `(installed)`/`(official)` badges), an attacker-controlled repository description can inject a visually identical forged badge next to a look-alike, unofficial extension.

### Finding Description
The flow is: `getExtensions` (pkg/cmd/extension/browse/browse.go:330-378) queries the `gh-extension` topic and builds `extEntry{description: repo.Description}` directly from the untrusted search result [1](#0-0) . `extEntry.Description()` returns this string unmodified (only substituting a placeholder when empty) [2](#0-1) . `extList.Reset()`/`Filter()` then feed `ee.Title()` and `ee.Description()` straight into `el.ui.List.AddItem(...)` [3](#0-2) . `extEntry.Title()` shows that this codebase relies on tview's built-in interpretation of `[green](installed)` / `[yellow](official)` tag syntax to render the genuine trust badges [4](#0-3) , confirming that the same list widget parses such tags in any text it is given, including the attacker-controlled description on the adjacent line. There is no call to escape tview tags (e.g. `tview.Escape`) anywhere on the description path, and no allowlist/validation of `repo.Description` is performed before it reaches the UI layer.

### Impact Explanation
An attacker who publishes a `gh-<name>` repository tagged `gh-extension` can set its `Description` to a string such as `Utility tool [green](installed)[yellow](official)`. When a victim runs `gh extension browse`, this text is rendered next to the attacker's real (non-official) `FullName`, visually implying it is already trusted/installed even though the genuine `Official`/`Installed` flags (computed from `repo.Owner.Login` and the local extension list) remain false for that entry. This is a forged-trust-indicator / UI spoofing bug: it can increase the odds a victim selects and presses `i` to install a malicious extension. Note the actual install target (`ee.FullName`, used by `ghrepo.FromFullName` in `toggleSelected`) is still the attacker's real, visible repo name — the bug does not redirect installation to a different repo, so the concrete impact is limited to deceptive UI presentation rather than a hidden install target, host-rerouting, or credential/code-execution primitive on its own.

### Likelihood Explanation
Feasible and fully repeatable: it only requires publishing a public GitHub repository with a name prefixed `gh-`, the `gh-extension` topic, and a description containing tview tag syntax — no privileges beyond an ordinary GitHub account. Every victim who runs `gh extension browse` and views the list will see the forged badge for that entry.

### Recommendation
Escape user-controlled text before handing it to tview widgets, e.g. wrap `repo.Description` with `tview.Escape()` (or manually replace `[` with `[[`) in `extEntry.Description()` (and defensively in `Title()`/`FullName` construction) so that attacker-supplied region/color tag syntax is rendered literally rather than interpreted as markup.

### Proof of Concept
```go
func TestDescriptionTagsAreNotInterpreted(t *testing.T) {
    ee := extEntry{
        FullName:    "attacker/gh-fake",
        description: "Cool tool [green](installed)[yellow](official)",
    }
    got := ee.Description()
    // Expect literal text (tags escaped), not raw tview markup
    if strings.Contains(got, "[green](installed)") || strings.Contains(got, "[yellow](official)") {
        t.Fatalf("attacker-controlled description was not escaped and can forge trust badges: %q", got)
    }
}
```
Expected today: the assertion fails because `Description()` returns the raw string unmodified, confirming the tag injection reaches `tview.List.AddItem` unsanitized. After applying `tview.Escape()` in `Description()`, the test should pass.

func (e extEntry) Title() string {

	if e.Installed {

	}

	}

	return fmt.Sprintf("%s%s%s", e.FullName, official, installed)
}
