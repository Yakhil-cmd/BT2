### Title
Interest accrual integer overflow permanently freezes a lending market - (File: `common/src/rates/index.rs`)

### Summary

Accrued debt is recomputed as `borrowed × borrow_index` in `i128`, but the borrow-index ceiling does not prevent that product from overflowing. Once aggregate debt crosses the representable RAY-value domain, every state-changing pool path that synchronizes the market reverts with `MathOverflow`, permanently blocking repayment, withdrawal, liquidation, and further index updates. [1](#0-0) [2](#0-1) 

### Finding Description

`global_sync` loads a market and accrues interest before processing each operation leg. [2](#0-1)  Each accrual step calls `calculate_supplier_rewards`, which computes both old and new total debt with non-saturating `Ray::mul` and then subtracts them. [1](#0-0)  Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, that cap is applied to the index only and does not bound `borrowed × index`. [3](#0-2) 

The fixed-point multiplication returns `MathOverflow` when the quotient no longer fits `i128`. [4](#0-3)  Because the panic occurs before `mark_accrued`, `last_timestamp` is never advanced; every subsequent operation retries the same accrual interval and reaches the same overflow. [5](#0-4) [6](#0-5) 

The repository’s boundary test demonstrates this condition with an ordinary unprivileged sequence: supply `BIG18`, supply collateral, borrow approximately 98% of the supplied liquidity, then invoke `update_indexes` after accrued growth. [7](#0-6)  The test asserts that `update_indexes` fails with `MathOverflow` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, and that both `withdraw` and `repay` subsequently fail with the same error. [8](#0-7) 

### Impact Explanation

This causes permanent freezing of user funds for the affected hub-asset market: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot unwind the insolvent position through pool legs because those paths all synchronize interest first. [2](#0-1) [9](#0-8)  Since the accrual panic prevents the timestamp from being committed, there is no permissionless path that skips accrual and restores operation. [5](#0-4) [6](#0-5) 

### Likelihood Explanation

The attacker does not need privileged access or malformed token behavior: they can supply liquidity and collateral, call `borrow`, and later call the permissionless `update_indexes` path. [7](#0-6)  The required market size is large, but the configured cap domain admits the demonstrated billion-token position, and sustained borrowing can occur before governance intervention or market exhaustion. [10](#0-9)  Once the condition is reached, the failure is deterministic and applies to every later synchronization attempt. [11](#0-10) 

### Recommendation

Bound the product domain rather than the index alone. Enforce an aggregate share limit derived from `i128::MAX` and `MAX_BORROW_INDEX_RAY` before borrowing, debt minting, or revenue-share minting, or widen total-debt accounting beyond `i128` so accrual can complete at the configured index ceiling. Apply the equivalent bound to `supplied × supply_index`, since `update_supply_index` also computes that product during accrual. [12](#0-11) 

### Proof of Concept

The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` provides a complete reproduction:

1. Supply `1_000_000_000 * 10^18` units of `BIG18`.
2. Supply sufficient `COL` collateral.
3. Borrow `980_000_000 * 10^18` units of `BIG18`.
4. Advance the ledger and call `update_indexes` for `BIG18`.
5. Observe `MathOverflow` before the borrow-index cap is reached.
6. Call `withdraw` for the supplier or `repay` for the borrower; both fail with `MathOverflow`.

The concrete setup and assertions are implemented in the repository. [13](#0-12)

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}
```

```rust
/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
