This bug class fundamentally does not map onto this codebase. The Erigon issue stems from variable-length RLP transaction decoding where trailing bytes are appended after a valid transaction and incorrectly accepted. In c-kzg-4844, every untrusted input type (`Bytes32`, `Bytes48`, `Blob`, `Cell`) is a fixed-size byte array defined at compile time (e.g. `uint8_t bytes[32]`, `uint8_t bytes[48]`) [1](#0-0) , and there is no length-prefixed or self-delimiting encoding scheme (like RLP) anywhere in the in-scope decoding paths (`bytes_to_bls_field`, `bytes_to_kzg_commitment`, `bytes_to_kzg_proof`) [2](#0-1)  that could have "trailing bytes" appended and silently ignored.

Every binding enforces exact length equality before calling into the C layer, so there is no path where extra bytes could be smuggled past validation: the Node.js binding's `get_bytes` rejects any `ArrayBuffer` whose length isn't exactly the expected size [3](#0-2) , and the Rust binding's `from_bytes` constructors reject any slice whose `len()` doesn't exactly match `BYTES_PER_PROOF`/`BYTES_PER_COMMITMENT`/`BYTES_PER_CELL` [4](#0-3) . The C# binding similarly throws on any length mismatch via `ThrowOnInvalidLength` [5](#0-4) .

Since there is no variable-length, self-terminating serialization format in this repository's in-scope decoding logic, there is no equality that "trailing bytes" could break here (no scenario where extra bytes are appended to a canonical fixed-size encoding and still parsed/accepted as valid by one implementation but rejected by another).

/**
 * Perform BLS validation required by the types KZGProof and KZGCommitment.
 *
 * @param[out]  out The output g1 point
 * @param[in]   b   The proof/commitment bytes
 *
 * @remark This function deviates from the spec because it returns (via an output argument) the g1
 * point. This way is more efficient (faster) but the function name is a bit misleading.
 */
static C_KZG_RET validate_kzg_g1(g1_t *out, const Bytes48 *b) {
    blst_p1_affine p1_affine;

    /* Convert the bytes to a p1 point */
    /* The uncompress routine checks that the point is on the curve */
    if (blst_p1_uncompress(&p1_affine, b->bytes) != BLST_SUCCESS) return C_KZG_BADARGS;
    blst_p1_from_affine(out, &p1_affine);

    /* The point at infinity is accepted! */
    if (blst_p1_is_inf(out)) return C_KZG_OK;
    /* The point must be on the right subgroup */
    if (!blst_p1_in_g1(out)) return C_KZG_BADARGS;

    return C_KZG_OK;
}

/**
 * Convert untrusted bytes into a trusted and validated KZGCommitment.

 * @param[in]   b   The commitment bytes

C_KZG_RET bytes_to_kzg_commitment(g1_t *out, const Bytes48 *b) {
