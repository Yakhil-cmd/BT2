### Title
Meta-transaction `SignedDelegateAction` can be front-run by any third party, griefing the intended relayer - ([File: runtime/runtime/src/actions.rs])

### Summary
NEAR's meta-transaction feature (NEP-366) lets a user sign a `DelegateAction` off-chain and hand it to a relayer, who wraps it in an on-chain `SignedDelegateAction` and pays gas/deposit costs on the user's behalf [1](#0-0) . Because the protocol places no restriction on *who* may act as the relayer for a given `SignedDelegateAction`, and the signed payload becomes publicly observable once broadcast, any unprivileged account can copy the exact bytes and submit its own wrapping transaction first. This is the direct analog of the ERC-2612 "permit front-running" griefing class: a publicly-visible, signature-authorized message that is meant to be paired with an external action can be captured and replayed by a third party ahead of the intended submitter, consuming the one-time authorization (nonce) and causing the legitimate submitter's paired transaction to fail.

### Finding Description
A `SignedDelegateAction` is just `{ delegate_action: DelegateAction, signature: Signature }` and its validity depends only on the signature over the action content and the sender's access-key nonce, not on who relays it [2](#0-1) . In `apply_delegate_action`, the runtime verifies the signature and delegates to `validate_delegate_action_key`, which loads the sender's access key, checks and then advances its nonce (or the selected gas-key nonce) — this is the sole gate that makes the action "consumed" [3](#0-2) [4](#0-3) . Nothing in this validation path checks the identity of the outer transaction's signer (the relayer) — any account can wrap the exact same `SignedDelegateAction` bytes into its own transaction and submit it.

The `nonce` field comment itself confirms the intent that it is meant only to stop the "same relayer" from double-submitting, not to stop a different, uninvited party from submitting it first: "Nonce to ensure that the same delegate action is not sent twice by a relayer" [5](#0-4) . The project's own design docs acknowledge that a relayer can lose gas/tokens due to races around the delegate action's execution, and that "some level of trust between the relayer and its user is therefore required" — but this text only discusses Alice griefing her own relayer, not a third party racing to consume the nonce first [6](#0-5) .

Once a rival submits the identical `SignedDelegateAction` (obtained from the honest relayer's broadcast transaction, from p2p gossip, or from any RPC/mempool visibility) and it lands in an earlier block, the sender's access-key nonce/gas-key nonce advances. When the honest relayer's originally-broadcast transaction is later applied, `validate_delegate_action_key` will reject it with `DelegateActionInvalidNonce` (see the exact replay-rejection behavior demonstrated in the test suite) [7](#0-6) . The honest relayer has already burned `SEND` costs to deliver the outer transaction/receipt to the sender's shard before the failure is detected on that shard [8](#0-7) , so the relayer loses real NEAR gas for a transaction that can never succeed, with no compensation, exactly mirroring the "permit + external call" griefing pattern where the victim's dependent call fails after the authorization is stolen by a front-runner.

### Impact Explanation
Impact is low-to-moderate and purely economic/availability related to relayers: no protocol invariant (balances, minting, unauthorized transfers) is broken, but an honest relayer's gas expenditure is wasted whenever its `SignedDelegateAction` submission is observed and copied by a third party before inclusion. This can be repeated systematically against any relayer service to grief its throughput and impose real (if small) financial cost per attempt, and it undermines the trust model relayers rely on, which the meta-tx design already flags as fragile.

### Likelihood Explanation
Likelihood is high for any relayer whose submissions are visible before finality (via network gossip, public mempools, or a malicious node relaying transactions it has seen). No special privilege is required — an ordinary account only needs to observe the `SignedDelegateAction` bytes and resubmit them wrapped in its own transaction with itself as signer/relayer, which is a fully unprivileged transaction-submission action.

### Recommendation
Bind the `SignedDelegateAction` to the intended relayer, e.g., by including the relayer's `AccountId` (and/or the outer transaction's signer) inside the signed payload that is hashed for NEP-461/NEP-483 signing, so that `validate_delegate_action_key` (or `apply_delegate_action`) can reject a `SignedDelegateAction` wrapped by any signer other than the one the sender authorized. Alternatively, document and mitigate at the relayer-protocol level (e.g., short-lived, relayer-specific commitments) since the core issue is that the signed message authorizes execution independent of the submitter's identity.

### Proof of Concept
1. Alice signs a `DelegateAction` (nonce N) naming relayer R and hands the `SignedDelegateAction` to R off-chain, per the documented flow [1](#0-0) .
2. R broadcasts a transaction wrapping this `SignedDelegateAction` (`Action::Delegate`/`Action::DelegateV2`).
3. Attacker M, observing the transaction/receipt on the network before it is included (e.g., via gossip, public RPC, or being a relaying node), copies the identical `SignedDelegateAction` bytes and wraps them in M's own transaction, submitting it with a higher priority/earlier inclusion.
4. M's transaction is applied first: `validate_delegate_action_key` succeeds and advances the nonce, matching the mechanics validated in `test_gas_key_delegate_v2_meta_transaction` [9](#0-8) .
5. R's original transaction is subsequently applied and fails with `DelegateActionInvalidNonce`, exactly as the test demonstrates for a replayed nonce [7](#0-6) , after R has already paid the `SEND` gas costs to deliver the outer transaction to Alice's shard [8](#0-7) .

pub(crate) fn apply_delegate_action(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    action_receipt: &VersionedActionReceipt,
    sender_id: &AccountId,
    signed_delegate_action: VersionedSignedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    if !signed_delegate_action.verify() {
        result.result = Err(ActionErrorKind::DelegateActionInvalidSignature.into());
        return Ok(());
    }
    let delegate_action = signed_delegate_action.delegate_action();
    if apply_state.block_height > delegate_action.max_block_height() {
        result.result = Err(ActionErrorKind::DelegateActionExpired.into());
        return Ok(());
    }
    if delegate_action.sender_id().as_str() != sender_id.as_str() {
        result.result = Err(ActionErrorKind::DelegateActionSenderDoesNotMatchTxReceiver {
            sender_id: delegate_action.sender_id().clone(),
            receiver_id: sender_id.clone(),
        }
        .into());
        return Ok(());
    }

    validate_delegate_action_key(state_update, apply_state, delegate_action, result)?;
    if result.result.is_err() {
        // Validation failed. Need to return Ok() because this is not a runtime error.
        // "result.result" will be return to the User as the action execution result.
        return Ok(());
    }

/// Validate access key which was used for signing DelegateAction:
///
/// - Checks whether the access key is present fo given public_key and sender_id.
/// - Validates nonce and updates it if it's ok.
/// - Validates access key permissions.
fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
