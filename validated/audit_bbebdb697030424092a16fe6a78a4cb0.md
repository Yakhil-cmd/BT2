### Title
Strategy vault collateral can become unreachable after account-mapping TTL expiry - (File: contracts/defindex-strategy/src/lib.rs)

### Summary
Medium severity: the strategy stores the only route from a vault to its controller account in the persistent `VaultAccount(vault)` entry, so archival of that entry can temporarily freeze the vault’s collateral until the entry is restored. [1](#0-0) [2](#0-1) 

### Finding Description
`deposit` pulls tokens from `from`, supplies them to the controller with the strategy contract as caller, and stores the returned controller `account_id` in `VaultAccount(from)`. [3](#0-2)  `withdraw` does not accept an account id; it can only recover one through `resolve_vault_account`, then calls `controller.withdraw` with the strategy as caller. [4](#0-3)  `resolve_vault_account` returns `0` when no stored id is available, and the code explicitly notes that the mapping is the only route back to the collateral. [5](#0-4) 

### Impact Explanation
Once the persistent `VaultAccount` mapping archives, the strategy cannot locate the controller account holding the vault’s collateral and `withdraw` cannot proceed through its only account-resolution path. [6](#0-5) [7](#0-6)  This causes temporary freezing of user funds; absent restoration or an alternate recovery path, the collateral remains economically unreachable through the strategy interface. [8](#0-7) 

### Likelihood Explanation
The issue requires the vault account mapping to remain unrenewed long enough for its persistent TTL to expire. [9](#0-8)  Normal `deposit`, `balance`, and `withdraw` flows renew the entry only when they successfully resolve it, so an inactive vault can reach the archived state without any privileged action. [10](#0-9) [11](#0-10) 

### Recommendation
Maintain an independently recoverable association between each vault and its controller account, and provide an unprivileged recovery path that verifies that association before re-registering the vault account. [12](#0-11)  At minimum, document the exact persistent key that must be restored and add regression coverage for withdrawal after TTL expiry and restoration. [1](#0-0) 

### Proof of Concept
1. An unprivileged vault calls `Strategy::deposit(amount, from = vault)`, which supplies the measured tokens through `controller.supply(strategy, stored_id, spoke_id, payment)` and stores `VaultAccount(vault) = account_id`. [3](#0-2) 
2. Leave the strategy inactive until the persistent `VaultAccount(vault)` entry archives. [9](#0-8) 
3. Call `Strategy::withdraw(amount, from = vault, to = vault)`; the function has no account-id argument and depends entirely on `resolve_vault_account`. [13](#0-12) 
4. The collateral remains in the old controller account, while the strategy interface provides no fallback route to identify or withdraw it until the archived mapping is restored. [8](#0-7)

    fn withdraw(
        env: Env,
        amount: i128,
        from: Address,
        to: Address,
    ) -> Result<i128, DeFindexStrategyError> {
        renew_instance(&env);
        if amount <= 0 {
            return Err(DeFindexStrategyError::AmountNotPositive);
        }
        from.require_auth();

        let ctx = Ctx::try_load(&env)?;
        let account_id = resolve_vault_account(&env, &ctx.controller, &from, false);
        if account_id == 0 {
            return Err(DeFindexStrategyError::InsufficientBalance);
        }

        let balance = ctx.collateral(account_id);

        if amount > balance {
            return Err(DeFindexStrategyError::InsufficientBalance);
        }

        let is_full_withdraw = amount == balance;
        let withdraw_amount = if is_full_withdraw { 0 } else { amount };
        ctx.controller.withdraw(
            &ctx.strategy,
            &account_id,
            &ctx.to_payment(withdraw_amount),
            &Some(to),
        );

        if is_full_withdraw {
            clear_vault_account(ctx.env, &from);
        }

        Ok(ctx.collateral(account_id))

/// Stores `vault`'s controller account id in persistent storage and
/// extends its TTL.
fn set_vault_account(env: &Env, vault: &Address, account_id: u64) {
    let key = DataKey::VaultAccount(vault.clone());
    let storage = env.storage().persistent();
    storage.set(&key, &account_id);
    storage.extend_ttl(&key, TTL_THRESHOLD_USER, TTL_BUMP_USER);
}

/// Removes `vault`'s stored account id mapping, if any.
fn clear_vault_account(env: &Env, vault: &Address) {
    env.storage()
        .persistent()
        .remove(&DataKey::VaultAccount(vault.clone()));
}

/// Extends the TTL of `vault`'s stored account id mapping if it exists.
fn extend_vault_account_ttl(env: &Env, vault: &Address) {
    let key = DataKey::VaultAccount(vault.clone());
    let storage = env.storage().persistent();
    if storage.has(&key) {
        // Same TTL tier as the controller account it points at.
        storage.extend_ttl(&key, TTL_THRESHOLD_USER, TTL_BUMP_USER);
    }

fn resolve_vault_account(
    env: &Env,
    controller: &ControllerClient,
    vault: &Address,
    clear_if_gone: bool,
) -> u64 {
    let stored: u64 = env
        .storage()
        .persistent()
        .get(&DataKey::VaultAccount(vault.clone()))
        .unwrap_or(0);
    if stored == 0 {
        return 0;
    }
    match controller.try_account_exists(&stored) {
        Ok(Ok(true)) => {
            extend_vault_account_ttl(env, vault);
            stored
        }
        // Only an explicit `false` clears: the mapping is the only route back to its collateral.
        Ok(Ok(false)) => {
            if clear_if_gone {
                clear_vault_account(env, vault);
            }
            0
        }
        _ => panic_with_error!(env, DeFindexStrategyError::AccountLookupFailed),
    }
