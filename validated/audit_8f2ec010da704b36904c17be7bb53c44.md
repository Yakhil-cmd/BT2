No vulnerability found for this question.

**Rationale:** The cowlib advisory describes an unbounded `zlib:inflate/2` call in SPDY header decompression with no output-size cap, allowing a small compressed payload to expand without limit. `polkadot-sdk` does not depend on `cowlib` at all [1](#0-0) , and every decompression entry point that accepts attacker/peer-supplied compressed bytes (PoV blocks, validation code blobs, WASM runtime blobs) goes through `sp_maybe_compressed_blob::decompress`, which enforces an explicit `bomb_limit` by wrapping the decoder in `.take((bomb_limit + 1) as u64)` and erroring out with `Error::PossibleBomb` if the output exceeds that bound before ever allocating unbounded memory [2](#0-1) .

This bound is applied consistently at the actual attacker-reachable boundaries: PoV decompression in the PVF execute worker [3](#0-2) , validation code decompression in the prepare worker [4](#0-3) , and WASM runtime blob decompression in the client executor [5](#0-4) . Tests explicitly confirm oversized/bomb payloads are rejected rather than exhausting memory [6](#0-5) .

Since the codebase already implements the exact bounded-output check that the cowlib advisory identifies as missing, there is no analogous unbounded-decompression vulnerability here. Additionally, per the scan methodology, generic decompression-bomb/memory-exhaustion/resource-growth claims without a broken guard are explicitly out of scope.

fn read_from_decoder(
	decoder: impl Read,
	blob_len: usize,
	bomb_limit: usize,
) -> Result<Vec<u8>, Error> {
	let mut decoder = decoder.take((bomb_limit + 1) as u64);

	let mut buf = Vec::with_capacity(blob_len);
	decoder.read_to_end(&mut buf).map_err(|_| Error::Invalid)?;

	if buf.len() <= bomb_limit {
		Ok(buf)
	} else {
		Err(Error::PossibleBomb)
	}
}

fn decompress_zstd(blob: &[u8], bomb_limit: usize) -> Result<Vec<u8>, Error> {
	let decoder = zstd::Decoder::new(blob).map_err(|_| Error::Invalid)?;

	read_from_decoder(decoder, blob.len(), bomb_limit)
}

/// Decode a blob, if it indicates that it is compressed. Provide a `bomb_limit`, which
/// is the limit of bytes which should be decompressed from the blob.
pub fn decompress(blob: &[u8], bomb_limit: usize) -> Result<Cow<'_, [u8]>, Error> {
	if blob.starts_with(&ZSTD_PREFIX) {
		decompress_zstd(&blob[ZSTD_PREFIX.len()..], bomb_limit).map(Into::into)
	} else {
		Ok(blob.into())
	}
}
