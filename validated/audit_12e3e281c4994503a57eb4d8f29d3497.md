### Title
Accrual value overflow permanently freezes a heavily utilized market - (File: common/src/rates/simulate.rs)

### Summary
A market whose scaled debt value grows beyond the `i128` range causes accrual to revert with `MathOverflow` before the borrow-index ceiling can cap further growth. Because every pool mutation synchronizes interest before applying the requested operation, that market can become permanently unable to process supply, borrow, withdrawal, repayment, liquidation, or bad-debt cleanup. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` converts aggregate `borrowed` shares back into RAY-denominated value with `scaled_to_original(env, borrowed, borrow_index)` before calculating utilization and applying the bounded borrow-index update. [1](#0-0) 

`scaled_to_original` calls `Ray::mul`, which computes `scaled * index / RAY` through `mul_div_half_up`. Although the intermediate multiplication is widened to `I256`, a final result that does not fit `i128` panics with `GenericError::MathOverflow`. [3](#0-2) [4](#0-3) [5](#0-4) 

The failure occurs before `update_borrow_index` executes, so the protocol's maximum-index bound cannot clamp accrual and prevent the revert. `update_indexes` exposes the same accrual to any authenticated, unprivileged caller, and all pool legs load the market through `synced_market`, which always calls `interest::global_sync` first. [6](#0-5) [7](#0-6) [8](#0-7) [2](#0-1) 

The repository's boundary test confirms the condition: with approximately one billion whole units of an 18-decimal asset supplied and 98% borrowed, repeated yearly accrual eventually fails in `scaled_to_original` while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`; subsequent withdrawal and repayment attempts both fail with `MATH_OVERFLOW`. [9](#0-8) 

### Impact Explanation
Once the aggregate debt value crosses the representable RAY boundary, the affected market has no recovery path that avoids accrual: depositors cannot withdraw, borrowers cannot repay, liquidators cannot settle debt, and cleanup cannot socialize the position. This constitutes permanent freezing of user funds and protocol insolvency for the affected market rather than an ordinary fail-closed input rejection. [2](#0-1) [10](#0-9) 

### Likelihood Explanation
An unprivileged attacker can construct the prerequisite state through normal `supply` and `borrow` calls if a listed market, its configured caps, collateral, and available token supply permit a sufficiently large high-utilization position. Reaching the boundary requires an extreme balance and sustained compounding, so likelihood is limited, but no privileged call or malformed input is needed to trigger the terminal overflow afterward; ordinary accrual or an authenticated `update_indexes` call is sufficient. [11](#0-10) [6](#0-5) 

### Recommendation
Bound accrual by representable aggregate debt value, not only by `MAX_BORROW_INDEX_RAY`. Before computing `scaled_to_original`, calculate a safe index ceiling such as `floor(i128::MAX * RAY / borrowed)` when `borrowed > 0`, clamp `new_borrow_index` to the lower of that value and the configured index ceiling, and recompute interest distribution consistently for the shortened growth. Also add an explicit market-level guard that rejects new borrow or supply mutations once projected accrual would become unrepresentable, and test withdrawal, repayment, liquidation, and `update_indexes` at the boundary. [12](#0-11) [3](#0-2) 

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the reachable failure. It supplies `BILLION * 10^18` base units of an 18-decimal market, funds collateral, borrows 98% of that liquidity, advances time annually, invokes `update_indexes`, and asserts `MATH_OVERFLOW`; the final borrow index remains below the configured cap, while subsequent `withdraw` and `repay` calls fail through the same pre-operation accrual. [13](#0-12) 

The reachable sequence is: `supply` the debt asset, supply sufficient collateral in another market, `borrow` approximately 98% of the debt asset, wait through repeated accrual intervals, then call `update_indexes` with the affected `HubAssetKey`. Once the first accrual fails, each later user-facing operation on that market attempts `global_sync` and fails before processing its own accounting. [14](#0-13) [2](#0-1)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Accrues interest for each market in `hub_assets` and emits one state event
/// per market.
///
/// Always commits state so same-ledger simulation records the write footprint
/// needed if time advances before transaction inclusion.
pub(crate) fn accrue(env: &Env, hub_assets: Vec<HubAssetKey>) {
    renew_instance(env);

    for hub_asset in hub_assets.iter() {
        let mut cache = Cache::load(env, &hub_asset);
        interest::global_sync(env, &mut cache);
        events::emit_market_state(env, cache.commit());
    }

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
