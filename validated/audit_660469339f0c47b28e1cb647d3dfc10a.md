### Title
Webhook signature verified against `repository.owner.login`, while every event handler acts on the unrelated `repository.full_name` field, breaking the "authenticated organization = written repository" binding - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to check the HMAC signature against using `repository_owner` (`params.dig('repository','owner','login')` or `organization.login`) [1](#0-0) . All actual event processing, however, resolves the target `Repository`/`Stack` from a completely different field of the same attacker-supplied JSON body: `repository.full_name`, via `Handler#repository_name`/`#stacks` and every concrete handler (`PushHandler`, `StatusHandler`, `LabelCapturingHandler`, `ClosedHandler`, `LabeledHandler`, `UnlabeledHandler`, `OpenedHandler`, `ReopenedHandler`) [2](#0-1) [3](#0-2) [4](#0-3) . There is no code that requires `repository.owner.login` (the field the signature was verified against) to equal the owner embedded in `repository.full_name` (the field used to pick the write target).

### Finding Description
The binding that should hold is: `organization that authenticated the request == organization that owns the repository being written to`. Concretely, `repository_owner` picks the `GitHubApp` instance (and thus the secret) used to verify the HMAC: `Shipit.github(organization: repository_owner)` then `github_app.verify_webhook_signature(...)` [5](#0-4) . Once verification passes, the raw JSON `params` are dispatched unmodified to handlers (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`) [6](#0-5) , and every handler independently re-parses `repository.full_name` from the same body to find the `Stack`/`Repository` to mutate [2](#0-1) .

Crucially, per the documented multi-organization configuration (`docs/setup.md`), each GitHub organization onboarded to Shipit gets its own `GitHubApp` config, including its own, **optional**, `webhook_secret` [7](#0-6) , and `GitHubApp#verify_webhook_signature` explicitly treats a blank/unset secret as "always verified": `return true unless webhook_secret` [8](#0-7) .

Combining these two facts: if any one organization configured on the instance has no `webhook_secret` set (a supported, documented configuration, cf. `config/secrets.development.example.yml` showing `webhook_secret: # nil`) [9](#0-8) , an unauthenticated caller can `POST /webhooks` with:
- `repository.owner.login` (or `organization.login`) set to that no-secret organization — this makes `verify_signature` pass unconditionally, since `Shipit.github(organization: <no-secret org>)` returns a `GitHubApp` with `webhook_secret` blank.
- `repository.full_name` set to `"<any-other-org>/<any-repo>"` that Shipit tracks as a `Stack` — this is the field every handler actually acts on.

Before the attack: signature verification for org X is meant to authorize only events genuinely originating from org X's repositories.
After the attack: the "verified organization" (X, with no secret) and the "repository actually written to" (`full_name` pointing at org Y's stack) are different entities, and the engine performs Y's mutation anyway. The equality `verified_organization == full_name.owner` is never checked anywhere in `WebhooksController` or `Handler`.

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" boundary explicitly called out as in-scope. Concrete consequences per handler, using only the attacker-forgeable `full_name`/event fields:
- `PushHandler#process` calls `stack.sync_github(expected_head_sha: params.after)` for any not-archived stack matching `full_name` and the pushed branch [3](#0-2) . For stacks with `continuous_deployment` enabled, syncing new commits feeds `ContinuousDeliveryJob`, which will deploy the stack once new commits are detected and it is not occupied [10](#0-9)  — i.e. an attacker with no relationship to that stack's real repository/organization can trigger a deploy cycle by forging a push notification against an unrelated, unprotected org.
- `StatusHandler#process` creates a `Status` on any `Commit` matching an attacker-chosen `sha` regardless of which org actually owns that commit's repository [4](#0-3) , which can be used to forge CI/check state on commits belonging to a repository unrelated to the "authenticating" organization.
- Pull-request handlers (`OpenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `ClosedHandler`, `ReopenedHandler`, `LabelCapturingHandler`) archive/unarchive/create review stacks for the repository resolved purely from `full_name` [11](#0-10) [12](#0-11) .

This meets the High-severity bar ("unauthenticated read/trigger of stack state... or an unauthorized deploy") when a continuous-deployment-enabled stack is targeted, because the ability to trigger stack sync/deploy pipelines is gated solely on an unrelated organization's optional webhook secret.

### Likelihood Explanation
The `/webhooks` endpoint is deliberately public/unauthenticated (it is the GitHub webhook intake, `skip_before_action :verify_authenticity_token`) [13](#0-12) , so no session, API token, or GitHub App key is required to reach it — satisfying the "unprivileged attacker" requirement. The precondition is that the deployment uses the multi-organization config and at least one onboarded organization has an unset `webhook_secret`, which is an explicitly documented and supported configuration (`webhook_secret: # nil`) rather than a misuse of the engine [7](#0-6) [9](#0-8) . Given that, exploitation only requires crafting a JSON body with mismatched `repository.owner.login` vs `repository.full_name`, which is trivial. I could not verify from the index whether any additional cross-checks exist elsewhere (e.g., in `Repository`/`Stack` lookup) that would reject a `full_name` whose owner differs from the verified org — none were found in `Handler`, `PushHandler`, `StatusHandler`, or the PR handlers examined.

### Recommendation
In `WebhooksController#verify_signature` (or in the base `Shipit::Webhooks::Handlers::Handler`), require that the organization used to select/validate the webhook secret matches the owner embedded in `repository.full_name` (and `organization.login` for org-level events) before dispatching to handlers, e.g. reject the request if `repository_owner != payload.dig('repository','full_name')&.split('/')&.first`. Additionally, consider making `webhook_secret` mandatory (removing the `return true unless webhook_secret` bypass in `lib/shipit/github_app.rb`) so that a misconfigured/no-secret organization cannot become an "always trusted" impersonation vector for other organizations' repositories.

### Proof of Concept
Given a Shipit instance configured with two GitHub orgs, `open-org` (no `webhook_secret` configured) and `target-org` (has a Stack `target-org/prod-app` with `continuous_deployment: true`):

```
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/main",
  "after": "<sha-of-a-real-commit-already-on-github-for-target-org/prod-app>",
  "repository": {
    "owner": { "login": "open-org" },
    "full_name": "target-org/prod-app"
  }
}
```
1. `WebhooksController#verify_signature` computes `repository_owner` = `"open-org"`, fetches `Shipit.github(organization: "open-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally [8](#0-7)  — no `X-Hub-Signature` header is even required.
2. `PushHandler.call(params)` resolves `stacks` via `Repository.from_github_repo_name("target-org/prod-app")` [2](#0-1)  and calls `stack.sync_github(expected_head_sha: ...)` on the `main` branch stacks of `target-org/prod-app` [3](#0-2) .
3. If continuous deployment is enabled for that stack, the resulting commit sync causes `ContinuousDeliveryJob` to deploy it [10](#0-9)  — triggered entirely by an attacker who has no relationship to `target-org`, using only the fact that some unrelated `open-org` has no webhook secret configured.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
