### Title
Webhook signature verification key (`repository.owner.login`) is disconnected from the stack lookup key (`repository.full_name`), enabling cross-repository payload injection - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects a `GitHubApp` (and hence the HMAC secret) using `repository.owner.login`, while every event `Handler` (e.g. `PushHandler`) resolves the target `Stack` using the completely independent `repository.full_name` field of the same JSON body. Nothing in the request pipeline enforces that these two attacker-supplied fields describe the same repository, so a validly-signed-but-unrelated payload can carry a forged `full_name` pointing at any tracked stack.

### Finding Description
The binding that must hold is:
`organization_whose_secret_verified_body == organization_owning_repository_named_in_payload`

Tracing the code:
- `repository_owner` reads `params.dig('repository','owner','login')` and is used only to pick the `GitHubApp`/secret via `Shipit.github(organization: repository_owner)` in `verify_signature`. [1](#0-0) [2](#0-1) 
- `verify_webhook_signature` computes an HMAC over the raw body using that app's `webhook_secret`. Critically, if `webhook_secret` is blank it returns `true` unconditionally, accepting **any** body regardless of the `X-Hub-Signature` header. [3](#0-2) 
- `docs/setup.md` documents `webhook_secret` as **optional**, so a deployment (especially any org onboarded later, or a multi-org Shipit instance) can legitimately have an app configured with no secret.
- Once `verify_signature` passes, `WebhooksController#create` dispatches the raw parsed JSON to the registered `Handler` for the event. [4](#0-3) 
- `Handler#stacks` (and every subclass such as `PushHandler`) resolves the *target* repository/stack using `payload.dig('repository','full_name')` via `Repository.from_github_repo_name`, a field completely independent from `repository.owner.login`. [5](#0-4) [6](#0-5) 

Root cause: the "who authenticated this body" key (`owner.login`) and the "which record to mutate" key (`full_name`) are two separate, independently attacker-controllable JSON leaves in the same request, and no code path ever asserts `full_name.split('/').first == owner.login`.

Exploit flow: an attacker crafts a raw JSON body with `repository.owner.login = "some-org-with-no-webhook-secret"` (any org configured in Shipit whose GitHub App entry has no `webhook_secret`, which the docs allow) and `repository.full_name = "victim-org/victim-repo"`, `ref = "refs/heads/<victim-stack-branch>"`, and an arbitrary `after` SHA. Because that org's `webhook_secret` is blank, `verify_webhook_signature` returns `true` for any/no signature, `verify_signature` passes, and `PushHandler` looks up and syncs the stack belonging to `victim-org/victim-repo` using attacker-chosen `after`/`ref` values — with no dependency on any secret belonging to `victim-org`.

Existing guards do not stop this: `drop_unhandled_event` only filters by event type, `ExplicitParameters` schemas only validate field presence/types (not cross-field consistency with `owner.login`), and `GithubOrganizationUnknown` only fires if the chosen `owner.login` doesn't match *any* configured org — it does not require it to match the org that owns `full_name`.

### Impact Explanation
For any Shipit deployment containing at least one configured GitHub App without a `webhook_secret` (an explicitly documented, optional configuration), an unauthenticated internet request can trigger `GithubSyncJob`/status updates/etc. against **any other tenant's tracked repository and stack**, using attacker-controlled `after`/`ref`/state fields. This is a cross-repository/cross-tenant write triggered by a payload that never proves possession of the target repository's or org's credentials — matching the Critical category "a payload for one repository mutating another's stack."

### Likelihood Explanation
Exploitability depends on the operator configuring at least one org's GitHub App without a `webhook_secret` (allowed and documented), and knowledge of that org's login name (public GitHub information) plus the target's `full_name`/branch (typically visible on the public Shipit stacks list). No secrets, sessions, or tokens are required, and the request is a single unauthenticated `POST /webhooks`, fully repeatable against arbitrary tracked repositories.

### Recommendation
Bind the two identities: derive the app/secret to verify against, and separately re-derive the "owner" implied by `repository.full_name`, and reject the request (`422`) if they differ. Do not treat a blank/omitted `webhook_secret` as "always verified" — instead treat it as a hard configuration error (fail closed) rather than a signature bypass.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "forged full_name with an unsecured org's owner.login syncs a victim stack" do
  victim_stack = shipit_stacks(:shipit) # e.g. repository full_name "shopify/shipit-engine"

  Shipit.github_apps["unsecured-org"] = Shipit::GitHubApp.new("unsecured-org", { webhook_secret: nil })

  forged_payload = {
    "ref" => "refs/heads/#{victim_stack.branch}",
    "after" => "deadbeef",
    "repository" => {
      "owner" => { "login" => "unsecured-org" }, # selects app w/ blank webhook_secret
      "full_name" => victim_stack.repository.github_repo_name # attacker-forged target
    }
  }.to_json

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # invalid/garbage signature

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "deadbeef"]) do
    post :create, body: forged_payload, as: :json
  end
end
```
This asserts `organization_whose_secret_verified_body` ("unsecured-org") diverges from `organization_owning_repository_named_in_payload` (the victim's real org), yet `GithubSyncJob` is still enqueued for the victim's `stack_id`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
