### Title
Webhook signature verification is scoped by `repository.owner.login`, but repository/stack resolution is scoped by `repository.full_name` — an unsigned webhook from any secret-less org can impersonate any tracked repository - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb], [File: lib/shipit/github_app.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp`/secret used to authenticate a webhook using `params.dig('repository','owner','login')`, while `Handler#stacks` (and thus `Repository.from_github_repo_name`) resolves the target repository/stacks using the independent, attacker-controlled `payload.dig('repository','full_name')` field. Because nothing enforces that these two fields agree, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected organization has no `webhook_secret` configured, an attacker who controls (or merely names) any organization in Shipit's config that lacks a `webhook_secret` can send a completely unsigned webhook whose `repository.full_name` points at any other tracked victim repository, triggering `GithubSyncJob` (or other handlers) against the victim's real `Stack`.

### Finding Description
The broken binding: the code implicitly assumes `params.dig('repository','owner','login') == owner-segment of payload.dig('repository','full_name')`, i.e. that the org whose secret verified the request is the same org that owns the resolved `Repository`/`Stack`. This is never checked.

- `verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-30,59-62` computes `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and looks up `github_app = Shipit.github(organization: repository_owner)`, then calls `github_app.verify_webhook_signature(sig, raw_post)`. [1](#0-0) [2](#0-1) 

- `GitHubApp#verify_webhook_signature` in `lib/shipit/github_app.rb:76-83` short-circuits to `true` whenever that organization has no `webhook_secret` configured (`return true unless webhook_secret`), meaning no HMAC/signature check occurs at all for such an org. [3](#0-2) 

- Once the controller-level check passes, `Handler#stacks`/`#repository_name` in `app/models/shipit/webhooks/handlers/handler.rb:32-38` reads a completely separate, unsigned JSON field, `payload.dig('repository', 'full_name')`, and resolves it via `Repository.from_github_repo_name`. [4](#0-3) 

- `Repository.from_github_repo_name` in `app/models/shipit/repository.rb:53-56` does an exact `owner`+`name` lookup with no relation back to which org verified the request. [5](#0-4) 

Attack: attacker sends `POST /webhooks` with `X-Github-Event: push` and a JSON body where `repository.owner.login = "attacker-org"` (an org present in Shipit's GitHub App configuration but with no `webhook_secret` set) and `repository.full_name = "victim-owner/victim-repo"` (an existing tracked repository owned by a different, properly secured org). `verify_signature` selects `attacker-org`'s `GitHubApp`, whose `verify_webhook_signature` returns `true` immediately because `webhook_secret` is blank — no signature is checked, so the attacker needs no secret at all. The `PushHandler` (subclass of `Handler`) then calls `stacks`, which resolves `Repository.from_github_repo_name("victim-owner/victim-repo")` to the real victim `Repository`, and its `.stacks`, enqueuing `GithubSyncJob` against the victim's real, actively-deployed `Stack`.

Existing guards do not catch this: `verify_signature` only ever validates the signature against the org named in `repository.owner.login`; it never cross-checks that value against `repository.full_name`'s owner segment, nor does it require that the resolved `Repository`'s owner match `repository_owner`. `drop_unhandled_event` and `check_if_ping` are unrelated event-type filters. `ExplicitParameters` schemas in the handlers only validate shape/types, not cross-field consistency with the authenticating org.

### Impact Explanation
Any organization configured in Shipit without a `webhook_secret` becomes a skeleton key: an attacker who can either register such an org's presence in config (out of scope if they can't touch config) or, more realistically, exploit an already-existing secret-less org configuration, can forge unsigned webhooks that resolve to and mutate/act on an arbitrary victim repository's `Stack` records via `payload.dig('repository','full_name')`. This is a cross-tenant write: a payload "authenticated" for organization X causes actions (`GithubSyncJob`, and potentially other push/pull_request handlers acting on `stacks`) against organization Y's repository/stack, which matches "a payload for one repository mutating another's stack" — Critical severity. The attack is fully repeatable against any tracked repository as long as one secret-less org exists in the deployment's GitHub App configuration.

### Likelihood Explanation
The precondition — an organization configured in `Shipit.github(organization: ...)`/`GitHubApp` config with a blank `webhook_secret` — is operator-controlled, not universally guaranteed to exist. Whether this is realistic depends on deployment configuration: if every configured GitHub App entry always sets a `webhook_secret`, this specific bypass via blank secret doesn't apply, though the underlying design flaw (owner used for auth ≠ owner used for resolution) remains latent and could be exploited differently if an attacker ever obtains any org's real webhook secret for an unrelated, low-value org. Given the uncertainty about whether the target deployment always configures `webhook_secret` for every org, this finding's severity is real but its likelihood is conditional on that specific misconfiguration.

### Recommendation
Enforce that the organization used to select/verify the webhook signature is the same as the owner of the resolved repository: after resolving `Repository.from_github_repo_name(payload.dig('repository','full_name'))`, assert `repository.owner == repository_owner` (the value used in `verify_signature`) before acting, and reject (422) on mismatch. Additionally, treat a blank/missing `webhook_secret` for any configured organization as a hard configuration error rather than an implicit "always trust" bypass in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "push webhook verified via a secret-less org cannot enqueue GithubSyncJob for a differently-owned victim repository" do
  victim_repo = shipit_repositories(:shipit) # owner: 'shopify', name: 'shipit-engine' — has webhook_secret configured
  victim_stack = shipit_stacks(:shipit)

  # Attacker-controlled org with no webhook_secret configured in Shipit.github_teams/app config
  attacker_owner = "attacker-org"

  payload = {
    repository: { full_name: victim_repo.github_repo_name, owner: { login: attacker_owner } },
    ref: "refs/heads/#{victim_stack.branch}",
    after: "deadbeef"
  }.to_json

  # No signature computed/sent at all — relying on attacker-org's blank webhook_secret
  post shipit.webhooks_path, params: payload, headers: {
    "X-Github-Event" => "push",
    "Content-Type" => "application/json"
  }

  assert_response :ok
  # Binding check: repository resolved from payload.full_name (victim) must equal
  # repository owned by attacker_owner (the org that "verified" the request) — it does not.
  assert_not_equal victim_repo.owner, attacker_owner

  # Yet the sync job fires for the victim's real stack:
  assert_enqueued_with(job: GithubSyncJob, args: [victim_stack])
end
```
This demonstrates the divergence: `repository.owner.login` (`attacker-org`, used for signature org lookup) never equals the owner of the `Repository` resolved via `full_name` (`shopify`), yet the request still succeeds and mutates the victim's stack state, because the blank-secret branch of `verify_webhook_signature` short-circuits authentication entirely.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
