### Title
API token scoped to one stack can read CI/build status of any stack via the CCMenu endpoint - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController` overrides the shared `stack` resolver used by every other API controller and, in doing so, drops the scoping check that restricts a stack-scoped `ApiClient` token to only the stack it was created for. Any valid API token — even one deliberately scoped to a single stack — can be used to fetch the CCMenu XML (build/deploy status) of any other stack in the installation.

### Finding Description
Every other controller inheriting from `Shipit::Api::BaseController` resolves the current stack through the `stacks`/`stack` helpers, which intersect the request with the token's authorized scope: [1](#0-0) 

`stacks` returns `Stack.where(id: current_api_client.stack_id)` when the client is scoped (`stack_id?` true), and only `Stack.all` for unscoped/admin tokens. `stack` then calls `stacks.from_param!(...)`, so a stack-scoped token can never resolve a stack outside its own `stack_id`.

`Api::CCMenuController`, however, redefines `stack` to bypass this scoping entirely and resolve directly against the whole `Stack` table: [2](#0-1) 

It still declares `require_permission :read, :stack`, which only checks that the token has the `read:stack` *permission string* — `ApiClient#check_permissions!` never checks `stack_id`: [3](#0-2) 

The binding that should hold is: `ApiClient.stack_id (authorized stack)` == `stack_id resolved and acted upon in the request`. In `CCMenuController` this equality is never enforced — the token's authorized scope and the stack actually touched diverge, because `stack` resolves via unscoped `Stack.from_param!` instead of the scoped `stacks.from_param!` used everywhere else (e.g. `CommitsController`, `DeploysController`): [4](#0-3) [5](#0-4) 

### Impact Explanation
This is a cross-stack authorization escalation: an `ApiClient` deliberately scoped to a single, low-sensitivity stack (e.g. created via `CCMenuUrlController` for a public CI-status widget with only `read:stack` permission) can be replayed against `GET /api/stacks/:owner/:repo/:env/ccmenu` for any other stack in the install, exposing that stack's build/deploy status, lock state, and last build label/time — an unauthenticated-for-that-resource read of stack state, matching the "stack a token authorises versus a stack it touches" boundary explicitly in scope.

### Likelihood Explanation
Any holder of a legitimately-issued, narrowly-scoped API token (for example the token exposed by `CCMenuUrlController`, which is intentionally handed out for embedding in third-party CI dashboards) can trivially exploit this by substituting a different `stack_id` in the URL — no additional privileges, races, or front-running are required. The route is unauthenticated by session (basic-auth token or `?token=` query param only), lowering the bar further.

### Recommendation
Remove the custom `stack` override in `Api::CCMenuController` (or reimplement it using the inherited `stacks.from_param!(params[:stack_id])`) so stack-scoped tokens cannot resolve stacks outside `current_api_client.stack_id`. Add a regression test asserting that a token scoped to stack A receives a 404/403 when requesting the CCMenu of stack B.

### Proof of Concept
1. As an authenticated Shipit user, request the CCMenu URL for stack `A` via `GET /ccmenu/A/production` (`CCMenuUrlController#fetch`), which creates/returns an `ApiClient` scoped to stack `A` with only `read:stack` permission and returns a signed token. [6](#0-5) 
2. Use that token to call `GET /api/stacks/<owner>/<repo-B>/<env>/ccmenu` for an unrelated stack `B` that the token was never granted access to, e.g. `curl -u <token>: https://shipit.example.com/api/stacks/other-owner/other-repo/production/ccmenu`.
3. The request succeeds and returns stack `B`'s build/deploy status XML, because `CCMenuController#stack` resolves `Stack.from_param!(params[:stack_id])` without checking `current_api_client.stack_id`.

# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
