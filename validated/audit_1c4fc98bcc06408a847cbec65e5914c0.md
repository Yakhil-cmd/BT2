### Title
Unauthenticated cross-repository ReviewStack archive/unarchive via decoupled webhook owner authentication vs. handler repository resolution - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb`)

### Summary
`WebhooksController#verify_signature` authenticates a webhook using `params.dig('repository','owner','login')` looked up against `Shipit.github(organization:)`, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's config has no `webhook_secret`. `LabeledHandler`/`ReviewStackAdapter`, however, resolve the target `Repository`/`ReviewStack` from a completely different field, `params.repository.full_name`, with no check that it matches the authenticating owner. This lets an attacker who controls (or names) a Shipit-configured, secret-less organization forge a `pull_request`/`labeled` payload whose `repository.owner.login` is that secret-less org, while `repository.full_name` names an arbitrary victim repository, causing `LabeledHandler` to archive/unarchive the victim's review stack.

### Finding Description
The broken binding, stated as an equality that must hold but does not:

`params.dig('repository','owner','login')` (the value used by `verify_signature` to select the `GitHubApp`/secret that authenticates the request) **must equal** the owner embedded in `params.repository.full_name` (the value `LabeledHandler#repository` uses via `Repository.from_github_repo_name` to select which repository's stacks are mutated).

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0)  and fetches `Shipit.github(organization: repository_owner)`, then calls `verify_webhook_signature` [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` returns `true` immediately if the resolved org's config has no `webhook_secret` — `return true unless webhook_secret` [3](#0-2) . If Shipit has an entry for some org (e.g. a sandbox/staging org, or any org configured without a secret by mistake or by design), any payload claiming that `repository.owner.login` sails through with zero HMAC verification.
3. Once past `verify_signature`, `Shipit::Webhooks.for_event('pull_request').each { |handler| handler.call(params) }` dispatches to `LabeledHandler` with the raw, forged `params` [4](#0-3) .
4. `LabeledHandler#repository` resolves the target repository using **`params.repository.full_name`**, not `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) . `from_github_repo_name` simply splits `"owner/name"` and does `find_by(owner:, name:)` [6](#0-5)  — it never cross-checks against `params.repository.owner.login`.
5. `LabeledHandler#stack` builds a `ReviewStackAdapter` scoped to `repository.review_stacks` and resolves the specific stack by `environment: "pr#{params.number}"` [7](#0-6) [8](#0-7) . Note: this lookup is by repository + PR number, **not** by commit SHA — `LabeledHandler`/`ReviewStackAdapter` never query a commit or status by bare SHA, so the "shared commit SHA collision" mechanism described in the prompt does not exist in this code path; the actual root cause is the owner/full_name decoupling described above, and it works regardless of SHA overlap.
6. `handle` then calls `stack.archive!` or `stack.unarchive!` depending on the label state [9](#0-8) , mutating the victim repository's `ReviewStack` (deprovisioning/reprovisioning), attributed to `params.sender.login` (also attacker-controlled) via `Shipit::User.find_or_create_by_login!` [10](#0-9) .

Exploit request: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or any garbage value), and JSON body where `repository.owner.login` = `"secretless-org"` (an org configured in Shipit's `github` config without a `webhook_secret`) but `repository.full_name` = `"victim-org/victim-repo"`, `action` = `"labeled"`, `pull_request.number` matching a real open review-stack PR on the victim repo, and `pull_request.labels` set to flip the provisioning label state.

Existing guards fail because:
- `verify_signature` only gates on `repository.owner.login`; it never validates that `repository.full_name` starts with that same owner.
- `drop_unhandled_event` only checks the event type is handled, not payload consistency.
- The `ExplicitParameters` schema (`params do ... end` in `LabeledHandler`) validates types/presence of fields but not their mutual consistency (owner vs. full_name).
- No model validation ties an incoming webhook's authenticating org to the `full_name` used for resolution.

### Impact Explanation
An unprivileged attacker can archive or unarchive an arbitrary victim `ReviewStack` (any repo with review stacks enabled) by authenticating via any Shipit-configured organization that happens to have no `webhook_secret` set, while targeting an unrelated repository via `repository.full_name`. This is a payload from one (mis)configured/attacker-influenced organization mutating another repository's stack state — deprovisioning (tearing down) or re-provisioning a victim's review environment, and creating `User` records attributed to arbitrary `sender.login` values. This matches the Critical category: "a payload for one repository mutating another's stack." Repeatable against any repository with `review_stacks_enabled`, for as many PR numbers as exist, at zero cost per request.

### Likelihood Explanation
The precondition is a Shipit deployment configuring at least one GitHub organization without a `webhook_secret` (whether intentionally, e.g. an internal/staging org, or by misconfiguration) — this is exactly the "no-secret organization" gap referenced in the question. Given that, the attack requires no credentials, no GitHub App key, no session, and no knowledge of any real webhook secret — only knowledge of the victim's `owner/repo` full name and an open PR number with a `pr{number}` review stack, both of which are typically public/guessable. This is a low-cost, highly repeatable attack once the precondition holds.

### Recommendation
In `WebhooksController#verify_signature`/handlers, enforce that the owner used to select the authenticating `GitHubApp` (`repository.owner.login`) matches the owner embedded in `repository.full_name` before dispatching to any handler; reject the request otherwise. Additionally, do not allow `GitHubApp#verify_webhook_signature` to silently authenticate (return `true`) when `webhook_secret` is blank — require every configured organization to have a webhook secret, or explicitly deny webhooks for organizations without one.

### Proof of Concept
Minitest under `test/controllers/shipit/webhooks_controller_test.rb` (or `test/models/shipit/webhooks/handlers/pull_request/labeled_handler_test.rb`):
1. Configure `Shipit.github_configs`/stub so organization `"secretless-org"` exists in config with no `webhook_secret`, and `Shipit.github(organization: "secretless-org")` returns a `GitHubApp` where `verify_webhook_signature` is `true` for any input (assert this directly first, matching `webhook_secret` being blank).
2. Create a victim `Repository` (`owner: "victim-org", name: "victim-repo"`, `review_stacks_enabled: true`, provisioning behavior configured) and an existing open `ReviewStack` at `environment: "pr42"` that is unarchived.
3. `POST /webhooks` with header `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and body: `{"action":"labeled","number":42,"pull_request":{...,"state":"open","labels":[{"name": <provisioning label>}],"head":{"sha": "<any sha>", "ref":"branch"}},"repository":{"full_name":"victim-org/victim-repo","owner":{"login":"secretless-org"}},"sender":{"login":"attacker"}}`.
4. Assert response is `200 OK` (not `422`), and assert the victim `ReviewStack` (`environment: "pr42"`, owned by `victim-org/victim-repo`) is now archived/unarchived per the label logic — i.e., `stack.reload.archived?` flips — proving a payload "authenticated" by `secretless-org` mutated `victim-org/victim-repo`'s stack, violating the equality that the authenticating owner must equal the mutated repository's owner.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
