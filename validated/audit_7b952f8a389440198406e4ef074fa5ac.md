### Title
Allowance Check Bypassed via Non-Approve Nonce Gap Lets Attacker Drain CN Proposer KAIA — (`kaiax/gasless/impl/tx_pool.go`)

---

### Summary

`checkBalanceForSwap` conditionally skips the `allowance(sender, router) >= amountIn` guard when `swapNonce != senderNonce`, assuming an approve tx will fill the gap. A plain (non-approve) tx at nonce N can consume that gap, causing the swap tx at nonce N+1 to be re-evaluated as a standalone swap with zero allowance. The lend tx fires and transfers KAIA from the CN proposer to the attacker; `swapForGas` then reverts due to zero allowance, and the lend is never repaid.

```go
senderNonce := g.getCurrentStateNonce(swapArgs.Sender)  // = N
noApproveTxPreceeds := swapNonce == senderNonce          // (N+1 == N) = false
if noApproveTxPreceeds {

``` [1](#0-0) 

Because `noApproveTxPreceeds` is `false`, the allowance check is entirely skipped. The swap tx is admitted to the pool with zero allowance.

**Phase 2 — Plain transfer mined**

The plain transfer at nonce N executes. State nonce advances to N+1. The txpool resets and re-evaluates promotions.

**Phase 3 — Promotion (`isSwapTxReady`)**

```go

if swapTx.Nonce() == nonce {           // N+1 == N+1 → true
    approveTx = nil                     // treated as standalone swap
}
return g.IsExecutable(nil, swapTx)
``` [2](#0-1) 

The swap tx is now at the current state nonce, so it is reclassified as a standalone swap (no approve tx required).

**Phase 4 — `VerifyExecutable(nil, swapTx)` — no allowance check**

`VerifyExecutable` only checks nonce alignment (SP3) and `amountRepay` correctness (SP4). The attacker sets `amountRepay = repayAmount(nil, swapTx) = R1 + R3`, which passes SP4. No allowance check is performed anywhere in this path. [3](#0-2) 

**Phase 5 — Bundle construction (`ExtractTxBundles`)**

**Phase 6 — Execution**

- `lendTx` executes: CN proposer sends `lendAmount(nil, swapTx) = R3` KAIA to the attacker. **This succeeds and is irreversible.**
- `swapTx` executes: calls `swapForGas(token, amountIn, ...)` with zero allowance → **reverts**.

Each transaction is independent; the lend tx is not rolled back. The CN proposer loses `R1 + R3` (lend tx gas + swap tx gas fee) with no repayment.

### Impact Explanation

The CN block proposer's KAIA balance is drained by `R1 + R3` per attack iteration. The attacker receives the lent KAIA and pays only the gas for the plain transfer at nonce N. This is an unauthorized KAIA withdrawal from the CN proposer, satisfying the required impact gate (unauthorized transfer of KAIA from a system-managed fund).

---

### Likelihood Explanation

The attack requires only two public RPC calls (submit plain transfer, submit swap tx) and waiting for one block. No privileged access, governance keys, or validator collusion is needed. It is repeatable indefinitely, limited only by the CN proposer's KAIA balance.

---

### Recommendation

Re-check allowance at promotion time inside `isSwapTxReady` (or `VerifyExecutable`) when `approveTx == nil`. Specifically, when the swap tx is being promoted as a standalone swap, verify `allowance(sender, router) >= amountIn` against current state before calling `IsExecutable`. Alternatively, re-run `checkBalanceForSwap` with the updated state nonce at promotion time so the `noApproveTxPreceeds` branch is re-evaluated correctly.

### Proof of Concept

1. Attacker (state nonce = N) submits a plain KAIA transfer at nonce N via public RPC.
2. Attacker submits a swap tx at nonce N+1 targeting a whitelisted token/router, with `allowance(sender, router) = 0` and `amountRepay = R1 + R3`.
3. `checkBalanceForSwap` admits the swap tx (allowance check skipped because `N+1 != N`).
4. Plain transfer is mined; state nonce advances to N+1.
5. Txpool reset: `isSwapTxReady` sees `swapTx.Nonce() == stateNonce` → promotes as standalone swap; `VerifyExecutable` passes (no allowance check).
6. `ExtractTxBundles` builds bundle `[lendTx, swapTx]`.
7. `lendTx` executes: CN proposer sends R3 KAIA to attacker. Succeeds.
8. `swapTx` executes: `swapForGas` reverts (zero allowance). CN proposer loses R1 + R3 KAIA.
9. Repeat from step 1 to drain the CN proposer.

func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
