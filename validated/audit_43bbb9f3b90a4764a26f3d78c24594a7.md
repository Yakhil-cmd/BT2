### Title
Unauthenticated `ServiceChainParentChainInfoResponseMsg` Allows Malicious Peer to Overwrite Bridge Operator Nonce and Gas Price — (File: `node/sc/sub_bridge_handler.go`)

---

### Summary

The `SubBridgeHandler.handleParentChainInfoResponseMsg` function in `node/sc/sub_bridge_handler.go` accepts a `ServiceChainParentChainInfoResponseMsg` P2P message from any connected bridge peer and unconditionally overwrites the parent-chain operator's nonce and gas price without any cryptographic verification of the message sender's authority. A malicious peer that has established a bridge P2P connection can send a forged `parentChainInfo` response at any time — including before or instead of the legitimate MainBridge — and force the SubBridge to use an attacker-controlled nonce and gas price for all subsequent cross-chain value-transfer and anchoring transactions.

---

### Finding Description

The `SubBridgeHandler` on the child chain (SubBridge) periodically calls `SyncNonceAndGasPrice()` to request the parent-chain operator account's nonce and gas price from the connected MainBridge peer. The response is handled by `handleParentChainInfoResponseMsg`:

```go
// node/sc/sub_bridge_handler.go:273-307
func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
    var pcInfo parentChainInfo
    if err := msg.Decode(&pcInfo); err != nil { ... }
    sbh.LockParentOperator()
    defer sbh.UnLockParentOperator()
    ...
    sbh.setParentOperatorNonce(pcInfo.Nonce)   // ← attacker-controlled
    sbh.setParentOperatorNonceSynced(true)
    sbh.setRemoteChainValues(pcInfo)            // ← sets gas price
    ...
}
``` [1](#0-0) 

There is **no verification** that the peer sending this message is the legitimate MainBridge. The message handler in `HandleMainMsg` dispatches on message code alone:

```go
case ServiceChainParentChainInfoResponseMsg:
    if err := sbh.handleParentChainInfoResponseMsg(p, msg); err != nil { ... }
``` [2](#0-1) 

The `parentChainInfo` struct carries `Nonce`, `GasPrice`, and `KIP71Config` fields, all of which are applied directly to the bridge operator account:

```go
type parentChainInfo struct {
    Nonce          uint64
    GasPrice       uint64
    KIP71Config    params.KIP71Config
    IsMagmaEnabled bool
}
``` [3](#0-2) 

The nonce is then used verbatim when constructing cross-chain transactions:

```go
types.TxValueKeyNonce: sbh.getParentOperatorNonce(),
``` [4](#0-3) 

The gas price is applied to the bridge operator account and used in `GenerateTransactOpts`:

```go
func (sbh *SubBridgeHandler) setRemoteGasPrice(gasPrice uint64) {
    sbh.subbridge.bridgeAccounts.pAccount.SetGasPrice(big.NewInt(int64(gasPrice)))
    sbh.remoteGasPrice = gasPrice
}
``` [5](#0-4) 

The bridge peer handshake (`Handshake`) only negotiates network ID, chain ID, and block head — it does not establish any signing authority or restrict which message codes a peer may send: [6](#0-5) 

The `ServiceChainParentChainInfoResponseMsg` code (`0x04`) is a valid message code in the service-chain protocol and is accepted from any registered bridge peer: [7](#0-6) 

---

### Impact Explanation

A malicious peer that connects to the SubBridge P2P port can send a forged `ServiceChainParentChainInfoResponseMsg` with:

1. **Nonce set to an already-used value** — all subsequent bridge transactions (value transfers, anchoring) will be submitted with a stale nonce and be rejected by the parent chain, permanently halting cross-chain value transfer until the operator manually resets the nonce.

2. **Nonce set to a very large value** — the bridge operator's nonce is set far ahead of the real on-chain nonce, causing all bridge transactions to be queued but never executed (nonce gap), effectively freezing the bridge.

3. **Gas price set to zero or below the base fee** — all bridge transactions will be rejected by the parent chain's tx pool (`ErrGasPriceBelowBaseFee`), triggering the `handleParentChainInvalidTxResponseMsg` path which removes the transactions from the pool without retry for anchoring transactions.

The concrete protected-state impact is: **unauthorized nonce consumption and gas-price manipulation for the bridge operator account on the parent chain**, causing bridge value-transfer transactions (KAIA, ERC-20, ERC-721) and anchoring transactions to fail, effectively freezing cross-chain asset settlement.

---

### Likelihood Explanation

- The SubBridge P2P port is reachable by any peer that knows the bridge's enode address (semi-public in service-chain deployments).
- The attacker only needs to establish a valid bridge P2P handshake (network ID + chain ID match), which requires no privileged key.
- The attack can be triggered at any time by sending a single `ServiceChainParentChainInfoResponseMsg` packet — no prior request is needed; the handler does not check whether a request was outstanding.
- The `nonceSynced` flag is set to `true` by the forged response, so the SubBridge immediately begins using the attacker-controlled nonce for all subsequent transactions.

---

### Recommendation

1. **Track outstanding nonce requests**: Record a pending-request flag or nonce when `SyncNonceAndGasPrice` is called, and reject `ServiceChainParentChainInfoResponseMsg` messages that arrive without a corresponding outstanding request (analogous to how `OnAccounts` in snap sync checks `s.accountReqs[id]`).

2. **Restrict sender**: Verify that the responding peer is the same peer to which the request was sent, and reject responses from any other peer.

3. **Cross-validate with on-chain state**: After receiving the nonce response, verify it against the actual on-chain nonce via `remoteBackend.NonceAt` before applying it, treating the P2P response as a hint rather than authoritative state.

---

### Proof of Concept

**Attacker steps:**

1. Connect to the SubBridge P2P endpoint with a valid service-chain handshake (matching `networkId` and `chainID`).
2. Without waiting for any request, send a `ServiceChainParentChainInfoResponseMsg` (code `0x04`) with a crafted `parentChainInfo`:
   ```go
   pcInfo := parentChainInfo{
       Nonce:          math.MaxUint64 - 1,  // far-future nonce
       GasPrice:       0,                   // below base fee
       IsMagmaEnabled: false,
   }
   p2p.Send(rw, ServiceChainParentChainInfoResponseMsg, pcInfo)
   ```
3. The SubBridge's `handleParentChainInfoResponseMsg` decodes the message, sets `nonceSynced = true`, and applies `Nonce = MaxUint64-1` and `GasPrice = 0` to the bridge operator account.
4. All subsequent bridge value-transfer and anchoring transactions are constructed with nonce `MaxUint64-1` and gas price `0`, causing them to be rejected by the parent chain's tx pool.
5. Cross-chain KAIA/token transfers and block anchoring are permanently halted until an operator manually intervenes. [8](#0-7) [9](#0-8) [10](#0-9)

// handleParentChainInfoResponseMsg handles parent chain info response message from parent chain.
// It will update the ParentOperatorNonce and remoteGasPrice of ServiceChainProtocolManager.
func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
```

// Handshake executes the Kaia protocol handshake, negotiating version number,
// network IDs, difficulties, head and genesis blocks.
func (p *baseBridgePeer) Handshake(network uint64, chainID, td *big.Int, head common.Hash) error {
	// Send out own handshake in a new thread
	errc := make(chan error, 2)
	var status statusData // safe to read after two values have been received from errc

	go func() {
		errc <- p2p.Send(p.rw, StatusMsg, &statusData{
			ProtocolVersion: uint32(p.version),
			NetworkId:       network,
			TD:              td,
			CurrentBlock:    head,
			ChainID:         chainID,
		})
	}()
	go func() {
		e := p.readStatus(network, &status)
		if e != nil {
			errc <- e
			return
		}
		errc <- e
	}()
	timeout := time.NewTimer(handshakeTimeout)
	defer timeout.Stop()
	for range 2 {
		select {
		case err := <-errc:
			if err != nil {
				return err
			}
		case <-timeout.C:
			return p2p.DiscReadTimeout
		}
	}
	p.td, p.head, p.chainID = status.TD, status.CurrentBlock, status.ChainID
	return nil
