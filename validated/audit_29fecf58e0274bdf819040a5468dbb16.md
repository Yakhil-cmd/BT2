### Title
Webhook signature verification selects the signing organization from `repository.owner.login`, but every event handler acts on the independently-attacker-controlled `repository.full_name` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks *which* GitHub App/organization secret to validate a webhook against using `repository.owner.login` (or `organization.login`), but every `Shipit::Webhooks::Handlers::Handler` subsequently resolves the `Repository`/`Stack` to act on using the separate `repository.full_name` field of the same JSON body. These two fields are never checked for consistency, so the "organization that authenticated" and the "repository that is written" are not bound together.

### Finding Description
`verify_signature` derives the authenticating organization purely from attacker-supplied JSON: [1](#0-0) [2](#0-1) 

It fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature`, which is a straight HMAC check against that organization's configured secret: [3](#0-2) 

Critically, `return true unless webhook_secret` — if the organization resolved by `repository_owner` has no `webhook_secret` configured (shown as the literal default/example value in the shipped config templates), **any** payload for that organization is accepted with zero cryptographic proof: [4](#0-3) 

Once `create` passes this check, it dispatches to handlers using the *raw parsed params*, and every handler resolves the target repository/stack from a **different** field, `repository.full_name`, with no cross-check against the `repository.owner.login`/`organization.login` value that was used to select the verifying secret: [5](#0-4) [6](#0-5) 

`PushHandler`, for instance, uses this repository/stack resolution to trigger a full commit sync from GitHub for the resolved stack, using an attacker-supplied `after` SHA: [7](#0-6) 

**The break:** the equality that should hold is
`organization_used_to_verify_signature(repository.owner.login) == owner(repository.full_name)`.
Nothing in `WebhooksController` or `Handler` enforces this. An attacker who can produce a valid signature for *any one* configured Shipit organization (including one deliberately or accidentally left with a blank `webhook_secret`, which is exactly what the shipped `secrets.development.shopify.yml` template shows) can set `repository.owner.login`/`organization.login` to that low-value/unsecured organization while setting `repository.full_name` to `"other-org/critical-repo"` — a completely different, security-sensitive repository/stack that Shipit tracks under a different, properly-secured GitHub App configuration. The request will pass `verify_signature` (checked against the weak/absent org secret) and then be processed as an authentic event for the unrelated target repository's `Stack`.

### Impact Explanation
This breaks the deployment-trust binding between "the organization whose secret authenticated the request" and "the repository the request is allowed to mutate," enabling cross-repository/cross-organization writes with attacker-controlled data (SHA to sync, commit statuses, membership/team mutations, review-stack provisioning, etc.) against a repository the attacker never authenticated for. Depending on which handler fires (`push`, `status`, `check_suite`, `membership`, `pull_request`), this can seed forged commit/status state that downstream deploy-safety checks rely on, or trigger unwanted syncs/provisioning on a victim stack — i.e., unauthorized cross-repository writes.

### Likelihood Explanation
Exploitability depends entirely on operator configuration: it requires that at least one organization registered with this Shipit instance has a blank/misconfigured `webhook_secret` (or that the attacker otherwise possesses a valid secret for *some* configured organization other than the target). This is a realistic misconfiguration because the project's own example config (`config/secrets.development.shopify.yml`) ships `webhook_secret: # nil` as the template value, and nothing in the code prevents mixing a "weak" org with "strong" orgs on the same instance. It does not require a Shipit session, an `ApiClient` token, or the target repository's own secret — only knowledge of the target's `owner/name` (public GitHub data) and a signature valid for a different, weaker organization on the same instance.

### Recommendation
Bind the two identities together before dispatching to handlers: after `verify_signature` succeeds, assert that the owner portion of `payload.dig('repository','full_name')` equals the `repository_owner` value that was actually used to select the verifying secret (and reject/`422` on mismatch). Additionally, refuse to treat `webhook_secret` as optional/bypassable — either require every configured organization to have a non-blank secret, or fail closed (reject) rather than fail open (`return true`) when `webhook_secret` is absent.

### Proof of Concept
1. Instance is configured with two GitHub orgs in `Shipit.github`: `weak-org` (no `webhook_secret` set, matching the shipped template) and `victim-org` (properly secured, with a tracked repository `victim-org/critical-repo`).
2. Attacker POSTs to `/github/webhooks` with:
   - `X-Github-Event: push`
   - `X-Hub-Signature: sha1=anything` (irrelevant since `weak-org` has no secret)
   - Body: `{"repository": {"owner": {"login": "weak-org"}, "full_name": "victim-org/critical-repo"}, "ref": "refs/heads/production", "after": "<attacker-chosen sha>"}`
3. `verify_signature` computes `repository_owner = "weak-org"`, loads `Shipit.github(organization: "weak-org")`, and `verify_webhook_signature` returns `true` immediately because `webhook_secret` is blank [8](#0-7) .
4. `PushHandler` resolves `repository_name` from `full_name` = `"victim-org/critical-repo"` [9](#0-8)  and enqueues `sync_github(expected_head_sha: <attacker sha>)` against the real, secured `victim-org/critical-repo` stack — despite the request never being authenticated against `victim-org`'s own webhook secret.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
