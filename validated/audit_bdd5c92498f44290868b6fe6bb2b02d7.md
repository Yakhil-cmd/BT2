### Title
Architecture-Dependent G2 Subgroup Check in Precompile 0x08 Causes Consensus Divergence — (`crypto/bn256/bn256_fast.go` / `crypto/bn256/bn256_slow.go`)

### Summary

`bn256_fast.go` (amd64/arm64, gnark backend) and `bn256_slow.go` (non-amd64/non-arm64, cloudflare backend) implement materially different validation semantics for G2 points in the BN254 pairing precompile (0x08). gnark's `G2.Unmarshal` enforces a prime-order subgroup check; cloudflare's does not. A G2 point that is on the twist curve but outside the prime-order subgroup is **rejected with an error** on gnark nodes and **silently accepted** on cloudflare nodes, producing different EVM outcomes and diverging state roots.

### Finding Description

**Build-tag dispatch:**

`bn256_fast.go` activates on `amd64 || arm64` and aliases `G2` to `gnark.G2`.
`bn256_slow.go` activates on `!amd64 && !arm64` and aliases `G2` to `cloudflare.G2`. [1](#0-0) [2](#0-1) 

**gnark `G2.Unmarshal` — enforces subgroup membership:**

```go
if !g.inner.IsOnCurve() {
    return 0, errors.New("point is not on curve")
}
if !g.inner.IsInSubGroup() {
    return 0, errors.New("point is not in correct subgroup")
}
``` [3](#0-2) 

**cloudflare `G2.Unmarshal` — only checks curve membership:**

```go
if !e.p.IsOnCurve() {
    return nil, errors.New("bn256: malformed point")
}
```

No `IsInSubGroup()` call exists anywhere in the cloudflare `G2.Unmarshal` path. [4](#0-3) 

**Precompile execution path:**

`runBn256Pairing` calls `newTwistPoint`, which calls `G2.Unmarshal`. If `Unmarshal` returns an error, `runBn256Pairing` returns `nil, err`, causing the precompile to revert. [5](#0-4) [6](#0-5) 

### Impact Explanation

For a crafted G2 point `Q'` that is on the BN254 twist curve `E'(Fp2)` but **not** in the prime-order `r`-torsion subgroup:

| Node architecture | `G2.Unmarshal` result | Precompile outcome | EVM `call` return | Calling contract |
|---|---|---|---|---|
| amd64 / arm64 (gnark) | error | `nil, err` → revert | `0` (failure) | reverts |
| non-amd64/arm64 (cloudflare) | success | `false32Byte` | `1` (success) | receives `0x00…00` |

These are **different EVM outcomes**. A transaction whose execution depends on the precompile result (e.g., a contract that branches on the pairing check or that does not revert on `success=0`) will produce a different post-state on the two node types, yielding **different state roots** and splitting consensus. [7](#0-6) 

### Likelihood Explanation

- The divergence is triggered by any public transaction that calls precompile `0x08` with a G2 point on the curve but outside the prime-order subgroup. No privileged access is required.
- Constructing such a point is straightforward: take any generator of the full twist group and multiply by a scalar that is not a multiple of the cofactor.
- The divergence only manifests when the network contains **both** amd64/arm64 nodes (gnark) and non-amd64/non-arm64 nodes (cloudflare). In practice, most Kaia nodes run on amd64/arm64, which limits the immediate exploitability but does not eliminate it — the code explicitly supports both paths via build tags, and any non-standard-architecture node would diverge.

### Recommendation

Unify subgroup-check behavior across both backends. The simplest fix is to add an explicit `IsInSubGroup()` call in cloudflare's `G2.Unmarshal` (and `G1.Unmarshal`) to match gnark's behavior, or to add a wrapper in `newTwistPoint` / `newCurvePoint` that performs the check independently of the backend. [8](#0-7) [9](#0-8) 

### Proof of Concept

1. Find a point `Q'` on the BN254 twist curve `E'(Fp2)` with order `h2 * r` (i.e., not in the `r`-torsion). This can be done by taking the standard G2 generator and multiplying by a scalar `s` such that `s` is not divisible by `h2`, then verifying `[r]Q' ≠ 0`.
2. Construct a transaction calling a contract that invokes precompile `0x08` with input `(G1_generator, Q')`.
3. Submit the transaction to a network with mixed amd64 and non-amd64 nodes.
4. Observe: on amd64/arm64 nodes (gnark), the precompile reverts → transaction reverts → no state change. On non-amd64/non-arm64 nodes (cloudflare), the precompile returns `false32Byte` → transaction succeeds → state changes are committed.
5. The resulting state roots diverge, splitting consensus. [3](#0-2) [4](#0-3) [6](#0-5)

func (g *G2) Unmarshal(buf []byte) (int, error) {
	if len(buf) < 128 {
		return 0, errors.New("invalid G2 point size")
	}

	if allZeroes(buf[:128]) {
		// point at infinity
		g.inner.X.A0.SetZero()
		g.inner.X.A1.SetZero()
		g.inner.Y.A0.SetZero()
		g.inner.Y.A1.SetZero()
		return 128, nil
	}
	if err := g.inner.X.A1.SetBytesCanonical(buf[0:32]); err != nil {
		return 0, err
	}
	if err := g.inner.X.A0.SetBytesCanonical(buf[32:64]); err != nil {
		return 0, err
	}
	if err := g.inner.Y.A1.SetBytesCanonical(buf[64:96]); err != nil {
		return 0, err
	}
	if err := g.inner.Y.A0.SetBytesCanonical(buf[96:128]); err != nil {
		return 0, err
	}

	if !g.inner.IsOnCurve() {
		return 0, errors.New("point is not on curve")
	}
	if !g.inner.IsInSubGroup() {
		return 0, errors.New("point is not in correct subgroup")
	}
	return 128, nil
}

// Unmarshal sets e to the result of converting the output of Marshal back into
// a group element and then returns e.
func (e *G2) Unmarshal(m []byte) ([]byte, error) {
	// Each value is a 256-bit number.
	const numBytes = 256 / 8
	if len(m) < 4*numBytes {
		return nil, errors.New("bn256: not enough data")
	}
	// Unmarshal the points and check their caps
	if e.p == nil {
		e.p = &twistPoint{}
	}
	var err error
	if err = e.p.x.x.Unmarshal(m); err != nil {
		return nil, err
	}
	if err = e.p.x.y.Unmarshal(m[numBytes:]); err != nil {
		return nil, err
	}
	if err = e.p.y.x.Unmarshal(m[2*numBytes:]); err != nil {
		return nil, err
	}
	if err = e.p.y.y.Unmarshal(m[3*numBytes:]); err != nil {
		return nil, err
	}
	// Encode into Montgomery form and ensure it's on the curve
	montEncode(&e.p.x.x, &e.p.x.x)
	montEncode(&e.p.x.y, &e.p.x.y)
	montEncode(&e.p.y.x, &e.p.y.x)
	montEncode(&e.p.y.y, &e.p.y.y)

	if e.p.x.IsZero() && e.p.y.IsZero() {
		// This is the point at infinity.
		e.p.y.SetOne()
		e.p.z.SetZero()
		e.p.t.SetZero()
	} else {
		e.p.z.SetOne()
		e.p.t.SetOne()

		if !e.p.IsOnCurve() {
			return nil, errors.New("bn256: malformed point")
		}
	}
	return m[4*numBytes:], nil
}

	p := new(bn256.G2)

		return nil, err
	}

func runBn256Pairing(input []byte) ([]byte, error) {
	// Handle some corner cases cheaply
	if len(input)%192 > 0 {
		return nil, errBadPairingInput
	}
	// Convert the input into a set of coordinates
	var (
		cs []*bn256.G1
		ts []*bn256.G2
	)
	for i := 0; i < len(input); i += 192 {
		c, err := newCurvePoint(input[i : i+64])
		if err != nil {
			return nil, err
		}
		t, err := newTwistPoint(input[i+64 : i+192])
		if err != nil {
			return nil, err
		}
		cs = append(cs, c)
		ts = append(ts, t)
	}
	// Execute the pairing checks and return the results
	if bn256.PairingCheck(cs, ts) {
		return true32Byte, nil
	}
	return false32Byte, nil
}
