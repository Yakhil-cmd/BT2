### Title
Cross-tenant `Status` write via unscoped `Commit.where(sha:)` in `StatusHandler#process` - (File: app/models/shipit/webhooks/handlers/status_handler.rb)

### Summary
`WebhooksController#verify_signature` only proves that the payload's signature matches the `webhook_secret` of the organization named in `params.dig('repository','owner','login')`. `StatusHandler#process` then looks up `Commit.where(sha: params.sha)` with no filter on stack or organization, so any commit row in any stack sharing that sha gets a `Status` created from an attacker-controlled, only-self-authenticated payload.

### Finding Description
The broken binding, stated as an equality that must hold but does not:

`organization_that_signed(payload) == organization_owning(Stack_of_every_Commit_mutated)`

Trace:
- `WebhooksController#create` parses raw JSON body and dispatches to handlers, after `before_action :verify_signature` [1](#0-0)  succeeds.
- `verify_signature` resolves `Shipit.github(organization: repository_owner)` from `params.dig('repository','owner','login')` and calls `verify_webhook_signature`, i.e., it authenticates the request only against the org named inside the attacker-supplied JSON body [2](#0-1) [3](#0-2) .
- `GitHubApp#verify_webhook_signature` HMACs the raw body with that org's own `webhook_secret` [4](#0-3) . This only proves the attacker owns/controls the named repo/org's secret — it says nothing about which `Commit`/`Stack` rows the payload is allowed to touch.
- `StatusHandler#process` then does `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` with **no** join/filter on `stack_id`, `repository`, or organization [5](#0-4) .
- `Commit#create_status_from_github!` unconditionally creates a `Status` scoped to `stack_id` (the commit's own stack, which may belong to any org) via `statuses.replicate_from_github!(stack_id, github_status)` [6](#0-5) [7](#0-6) .

Because `sha` is a global git content hash, it is not namespaced per repository/organization in the DB lookup — the `commits` table index is on `(stack_id, sha)` (per `db/migrate/20170524104615_index_commits_on_stack_id_and_sha.rb`) but the query in `StatusHandler` does not use `stack_id` at all, it queries across the whole table. Two independent repositories (e.g., forks, or repos scaffolded from the same template producing an identical empty initial commit) can legitimately have a `Commit` row with the same `sha` under different `Stack`s owned by different GitHub organizations, each with its own `webhook_secret`.

Exploit flow: attacker owns repo A (org "attacker"), configures/has a valid `webhook_secret` for org "attacker" in Shipit. They create a commit whose sha collides with a `Commit` already tracked by victim stack B (owned by org "victim") — trivially achievable with content-independent-of-remote objects such as the well-known empty-tree/empty-commit sha, or any commit cherry-picked/duplicated verbatim (same tree, same parent-less commit, same author/committer identity and timestamps) into their own repo. They POST a `status` webhook signed with their own valid secret, with `repository.owner.login = "attacker"` and `sha` equal to the victim's tracked commit. `verify_signature` passes (valid signature for org "attacker"). `StatusHandler#process` finds and mutates the victim's `Commit` row anyway, creating a `Status` with attacker-chosen `state`/`context`/`description`/`target_url`, because the equality above is never checked.

None of the existing guards prevent this: `verify_signature` checks signature-validity for the org named in the payload, not that the org owns the target commit/stack; `drop_unhandled_event` only filters unknown event types; the `ExplicitParameters` schema in `StatusHandler.params` validates shape (`sha`, `state`, etc. as strings) but not ownership; there is no `stacks` scope or `require_permission!` call anywhere in this webhook path since it is unauthenticated-by-design (trusted only via signature-to-org binding, which this handler ignores).

### Impact Explanation
An attacker can create a `Shipit::Status` row against a victim tenant's `Commit`/`Stack` using only a webhook signed for their own, unrelated repository — this is a "payload for one repository mutating another's commit" scenario, matching the Critical severity bucket in the rules. Concretely this can flip `commit.state` to `success`, unblocking deploy gating (`Commit#deployable?`, `Commit#blocked?`) for arbitrary CI contexts on the victim stack [8](#0-7) , and can trigger downstream side effects (`enable_ci_on_stack`, `schedule_continuous_delivery`, hook emissions) on a stack the attacker never authenticated for [9](#0-8) . This is repeatable against any stack whose tracked commit sha the attacker can reproduce (shared empty/template commits are a realistic, common case across many forks/orgs), and blast radius spans every tenant stack sharing that sha, not just one victim.

### Likelihood Explanation
Preconditions: the attacker needs (a) a repository they control with a working Shipit webhook integration and valid `webhook_secret` for their own org — a low, self-service bar; (b) a git commit whose sha is byte-identical to one already tracked in a victim's `Commit` table. SHA-1 git commit hashes are content-addressed and independent of the remote repository, so this is achievable deterministically (e.g., duplicating a parent-less/empty commit with fixed author/committer/timestamp metadata, a documented technique via `git commit-tree`). No live GitHub interaction, no secrets belonging to the victim, and no privileged Shipit role are required — only a POST to `/webhooks` with a properly HMAC-signed body using the attacker's own secret. This is fully repeatable and requires no elevated access at any point.

### Recommendation
Scope `Commit.where(sha:)` in `StatusHandler#process` (and similarly in any other sha-based handler) by the organization/repository authenticated by `verify_signature`, e.g. join through `Stack`/`Repository` and filter to stacks belonging to `repository_owner`/`params.repository.full_name` before iterating, so a signature valid for org A can only mutate commits belonging to stacks owned by org A.

### Proof of Concept
minitest (`ActionDispatch::IntegrationTest` or `ActionController::TestCase`, extending `test/controllers/webhooks_controller_test.rb` style):

```ruby
test ":status payload signed for org A must not create a Status on a commit belonging to org B's stack" do
  # Arrange: two stacks/orgs sharing the same commit sha
  victim_stack  = shipit_stacks(:shipit)            # owned by org "shopify" per fixtures
  attacker_stack = shipit_stacks(:cyclimse)         # a different org/tenant
  shared_sha = "4b825dc642cb6eb9a060e54bf8d69288fbee4904" # git empty-tree sha, reproducible by anyone

  victim_commit = victim_stack.commits.create!(sha: shared_sha, author: shipit_users(:shipit),
    committer: shipit_users(:shipit), authored_at: Time.now, committed_at: Time.now, message: "victim commit")

  request.headers['X-Github-Event'] = 'status'
  # Signed/valid only for attacker's own org, naming attacker's own repository
  body = {
    sha: shared_sha, state: 'success', context: 'ci/travis',
    branches: [{ name: 'master' }],
    repository: { full_name: 'attacker/own-repo', owner: { login: 'attacker-org' } }
  }.to_json

  Shipit.github(organization: 'attacker-org').stubs(:verify_webhook_signature).returns(true)

  assert_no_difference -> { victim_commit.statuses.count } do
    post :create, body:, as: :json
  end
  # Binding check: organization that signed ("attacker-org") != organization owning victim_commit.stack
  # If the assert_no_difference fails (a Status IS created), the binding is broken and the vulnerability is confirmed.
end
```

Note: the binding equality to validate before/after is `repository_owner_param ("attacker-org") == victim_commit.stack.repository.owner` — currently `StatusHandler#process` never checks this, so the PoC's `assert_no_difference` fails against current code, demonstrating the vulnerability.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
