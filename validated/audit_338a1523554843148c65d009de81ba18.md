### Title
NULL/undefined `payload` dereference in `getAllAuthorsAndOutputAddresses()` crashes node when processing a `definition` message inside a nonserial content-hash-stripped unit - ([File: network.js])

### Summary
`network.js`'s `getAllAuthorsAndOutputAddresses()` dereferences `payload.definition[1].base_aa` for `app === 'definition'` messages without first checking that `payload` is truthy, unlike the sibling `payment` branch which explicitly guards with `&& payload`. This mirrors the reported ipw2x00 bug class: an object (`crypt`/`crypt->ops`) that can legitimately be null is dereferenced without a null-check, causing a crash reachable from data that an ordinary, unprivileged unit poster controls.

The `payment` branch explicitly checks `payload` truthiness before dereferencing (`payload.outputs`), because `validation.js` allows units with `content_hash` set (nonserial, stripped units, e.g. `final-bad`/pruned units) where `message.payload` is absent (`hasFieldsExcept(objUnit, [...]) ` for content_hash units excludes `messages` entirely, and pruned/voided serial units also have their `messages` deleted in the DB while stubs sometimes retain a `messages` array with a payload-less message during transitional states, e.g. `archiving.getCachedOutput` which explicitly checks `!message.payload` before use, mirroring the defensive pattern missing here) [2](#0-1) . The `definition` branch has no equivalent guard and directly indexes `payload.definition[1]`, so if `payload` is `undefined` for a `definition`-app message, this throws a `TypeError: Cannot read properties of undefined`.

This function is called from `notifyWatchers()`, which runs for every joint accepted by the node (`saveJoint` / catchup / light-vendor flows) right after a unit is written or read back:

``` [3](#0-2) 

Because this is an uncaught synchronous exception inside a hot code path used for every accepted unit (not wrapped in try/catch), a single crafted unit that leads to a `definition`-app message with a missing/falsy `payload` at this point in processing crashes the node process (denial of service against that node's ability to keep validating/serving new units), matching the "network unable to confirm new units" impact bucket.

### Impact Explanation
An uncaught exception thrown from `getAllAuthorsAndOutputAddresses()` inside `notifyWatchers()` will propagate up through the unit-acceptance pipeline and crash the node process (Node.js default behavior on an uncaught synchronous exception is process termination unless a global handler swallows it). If reachable by a normal peer/unit poster without needing to compromise a hub or peer, this results in a full node going offline and being unable to further validate/relay/confirm units — a network-availability impact, not merely a resource-only bug.

### Likelihood Explanation
Reaching this exact code path requires an `objUnit.messages` array containing an `app: 'definition'` message whose `payload` is falsy at the time `notifyWatchers` runs. The `definition` app is validated with `isNonemptyObject(payload)` in `validation.js` for freshly-submitted, unstripped units, so the primary/likely trigger is on the archiving/voiding/pruning and content-hash-stripping code paths, where the same `objUnit.messages` structure can retain a message entry with `app` set but `payload` removed, or on catch-up/read-joint flows returning partially-stripped joints. Establishing the exact minimal trigger message shape requires deeper end-to-end tracing (e.g. through `main_chain.js` voiding logic, `storage.readJoint`, and catchup `light/get_definition` flows) that was not fully confirmed in this pass; this is flagged as an area of uncertainty.

### Recommendation
Add the same defensive `&& payload` (and ideally `&& payload.definition && payload.definition[1]`) guard to the `definition` branch in `getAllAuthorsAndOutputAddresses()` in `network.js`, mirroring the existing check on the `payment` branch, so a missing/stripped payload is silently skipped instead of throwing.

### Proof of Concept
Conceptual reproduction (not a live exploit, since the exact producing pathway needs confirmation):
1. Get a unit accepted whose `objUnit.messages` includes an entry `{ app: 'definition', payload_hash: ..., payload_location: ... }` where `payload` is absent/falsy by the time it reaches `notifyWatchers`/`getAllAuthorsAndOutputAddresses` (e.g. via the voiding/stripping/catchup path that yields partially reconstructed joints with messages but no payload).
2. When `notifyWatchers(objJoint, ...)` is invoked for that unit, `getAllAuthorsAndOutputAddresses(objUnit)` executes the `else if (message.app === 'definition' && payload.definition[1].base_aa)` line, throwing `TypeError: Cannot read properties of undefined (reading 'definition')`, crashing the process.
