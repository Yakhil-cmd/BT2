## Title
API client stack-scope binding bypassed in CCMenu endpoint - allows cross-stack unauthorized reads - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` lookup helper that `Shipit::Api::BaseController` provides, and in doing so drops the API-client stack scoping that every other API controller relies on. An `ApiClient` created with a `stack_id` is meant to be restricted to that single stack for every operation — the equality that should hold is `stack acted upon == stack the client's token authorizes`. In `CCMenuController` that equality is broken: any client holding a `read:stack`-permissioned token, even one explicitly scoped to a single stack, can query CI status/build info for any other stack in the installation.

### Finding Description
`Shipit::Api::BaseController` resolves the current stack through a scope that is filtered by the authenticated client's `stack_id`: [1](#0-0) 

This is what every other API resource controller (`StacksController`, `DeploysController`, `TasksController`, etc.) relies on: if `current_api_client.stack_id?` is true, `stacks` is restricted to `Stack.where(id: current_api_client.stack_id)`, so `stacks.from_param!(...)` raises/404s for any stack outside the client's scope. This is exercised in the test suite: [2](#0-1) 

`CCMenuController`, however, defines its own `stack` method that calls `Stack.from_param!` directly, completely bypassing the `stacks` scoping helper and the client's `stack_id` restriction: [3](#0-2) 

The controller only enforces `require_permission :read, :stack` — a permission check, not a stack-identity check — via `ApiClient#check_permissions!`, which merely verifies the `"read:stack"` string is in the client's `permissions` array and has no notion of which specific stack the client is bound to: [4](#0-3) 

So the binding that should hold — `stack a token authorizes == stack it touches` — is violated specifically in this one controller: a token minted with `stack_id` set to Stack A can fetch CCMenu XML (build status, last build label/time, web URL) for Stack B, C, or any other stack, as long as `read:stack` is present in its permission list.

### Impact Explanation
This lets a holder of a narrowly-scoped, low-trust API token (e.g., a CI-status widget integration meant to see only its own stack) read deploy/build state — status, last build result, web URL — for every other stack managed by the Shipit instance, including stacks belonging to different repositories/teams that the token was never meant to access. This is an unauthorized cross-stack read of stack state, matching the High-impact category ("escalation into `Shipit.github_teams` authorization ... unauthenticated read of stack state, task streams or deploy output").

### Likelihood Explanation
Any deployment of shipit-engine that issues scoped `ApiClient` tokens (e.g., via `CCMenuUrlController`, which itself creates a stack-agnostic-looking read-only client) is affected. The scoped-client feature is a documented/intended access-control mechanism, so any consumer who legitimately holds one scoped token can trivially enumerate other stacks' `stack_id` param values (`owner/repo/environment`) and query them.

### Recommendation
Make `CCMenuController#stack` go through the same client-scoped lookup used elsewhere, e.g. `stacks.from_param!(params[:stack_id])` instead of `Stack.from_param!(params[:stack_id])`, so the `current_api_client.stack_id` restriction is honored consistently with `BaseController`.

### Proof of Concept
1. Create (or obtain) an `ApiClient` scoped to Stack A with `permissions: ['read:stack']` (this is exactly how `here_come_the_walrus` fixture / `CCMenuUrlController#client` mints tokens): [5](#0-4) 
2. Using that client's `authentication_token`, call `GET /api/{other_owner}/{other_repo}/{other_environment}/ccmenu.xml?token=<token>` for Stack B — a stack the client was never scoped to.
3. Observe the request succeeds (200 OK) and returns Stack B's build status/name/URL, because `CCMenuController#stack` never checks `current_api_client.stack_id`, unlike `Api::StacksController#show`/`#index`, which would 404/empty-scope the same token for Stack B.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
