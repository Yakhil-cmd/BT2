### Title
`gh repo sync` passes attacker-controlled default branch name as unsanitized positional argument to `git branch`, enabling argument/flag injection - (File: pkg/cmd/repo/sync/git.go)

### Summary
`syncLocalRepo` fetches `opts.Branch` from `api.RepoDefaultBranch(srcRepo)` when the `--branch` flag is unset, and this value is later passed as a raw positional argument to `git branch <branch> <ref>` in `gitExecuter.CreateBranch`. Since the branch name is not validated or preceded by a `--` separator, an attacker who controls the source repository (their own fork or an upstream they administer) can set the default branch to a string beginning with `-` (e.g. `--track` or `-D`) so that `git branch` interprets it as a flag rather than a branch name, altering the intended git operation on the victim's local repository.

### Finding Description
In `pkg/cmd/repo/sync/sync.go`, when `opts.Branch == ""`, the code calls `api.RepoDefaultBranch(apiClient, srcRepo)` and assigns the result directly to `opts.Branch` with no validation of its contents: [1](#0-0) 

That value flows into `executeLocalRepoSync`, which, for a branch that does not exist locally, calls: [2](#0-1) 

`gitExecuter.CreateBranch` then builds the `git branch` command with the branch name as a bare positional argument, not prefixed or separated with `--`: [3](#0-2) 

Because `git.Client.Command` builds `exec.Command` with an argument array (no shell), classic shell injection is not possible, but git's own argument parser will treat a leading `-` in `branch` as an option to `git branch` rather than a ref/branch name. For example, if the attacker sets the default branch name to `--track`, the invocation becomes `git branch --track FETCH_HEAD`, causing `git branch` to interpret `--track` as a flag and `FETCH_HEAD` as the branch-name operand, producing an unintended branch creation with an unintended name/behavior instead of creating a branch literally named `--track`. The subsequent `--set-upstream-to` call also places the same attacker-controlled string as the trailing positional argument, similarly subject to reinterpretation as a flag: [4](#0-3) 

By contrast, `UpdateBranch` is not affected the same way because the branch value is embedded inside a `refs/heads/%s` string before being passed to `update-ref`, so a leading dash cannot make the resulting argument itself start with `-`: [5](#0-4) 

No sanitization, `--` separator, or ref-name validation exists in `syncLocalRepo`/`executeLocalRepoSync`/`CreateBranch` to prevent a dash-prefixed default branch name from being treated as a flag.

### Impact Explanation
The exploitable surface is limited to the `git branch` invocation performed by `CreateBranch` (the `UpdateBranch`/`update-ref` path is not vulnerable due to the `refs/heads/` prefix). Depending on the specific flag value chosen, this can cause `git branch` to behave unexpectedly (e.g., create/track a branch under an unintended name, or fail with an option-parsing error), resulting in local ref manipulation that does not match user/documented intent. This does not lead to shell/command execution (arguments are passed via `exec.Command`, not a shell), and does not appear to provide file write outside the repo, credential exposure, or authentication bypass — it is a scoped "unintended git flag execution / local ref manipulation" issue as characterized in the question, with correspondingly limited severity (denial-of-sync / incorrect local branch state) rather than full compromise.

### Likelihood Explanation
Exploitation requires the victim to run `gh repo sync` (or `gh repo sync --source <attacker-repo>`) against a repository whose default branch the attacker controls — a realistic precondition since default branch names are freely settable on any repo/fork the attacker owns, and `--source` allows pointing at an arbitrary repo. It also requires that the destination does not already have a local branch matching that name (the vulnerable path is the `CreateBranch` branch of the `if hasLocalBranch` conditional). No token or MITM access is needed, only that the victim be induced to sync from the attacker's repository.

### Recommendation
Validate `opts.Branch` (and any other externally-supplied ref/branch name) against git's ref-name rules and explicitly reject or escape names beginning with `-` before use. Additionally, insert a `--` separator before variable branch-name arguments in all `git branch`/`git checkout`/similar invocations, e.g. `g.client.Command(ctx, "branch", "--", branch, ref)`, so git can never interpret the value as an option regardless of its contents.

### Proof of Concept
Go test using the existing `gitClient`/`mockGitClient` pattern in `pkg/cmd/repo/sync`:
1. Stub `api.RepoDefaultBranch` (via httpmock) to return `--track` for the source repo.
2. Run `syncLocalRepo` with no local branch of that name, forcing the `CreateBranch` path.
3. Use a git-stub (fake `git` executable capturing argv, similar to existing git command test doubles in the repo) to assert the exact arguments passed to `exec.Command`.
4. Assert the raw args are `["branch", "--track", "FETCH_HEAD"]` (flag interpreted) instead of the intended literal branch name `--track`, demonstrating the argument is not protected by a `--` separator or validation before reaching `git.Command.Run`/`Output`.

func (g *gitExecuter) CreateBranch(branch, ref, upstream string) error {
	ctx := context.Background()
	cmd, err := g.client.Command(ctx, "branch", branch, ref)
	if err != nil {
		return err
	}
	if _, err := cmd.Output(); err != nil {
		return err
	}
	cmd, err = g.client.Command(ctx, "branch", "--set-upstream-to", upstream, branch)
	if err != nil {
		return err
	}
	_, err = cmd.Output()
	return err
}
