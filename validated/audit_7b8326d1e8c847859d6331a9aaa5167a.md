Based on my investigation, I found a real, currently-unpatched instance of a proxy privilege-escalation bug class that the codebase itself already identified and fixed once elsewhere. I could not fully confirm the exact origin-authorization internals of `paras_registrar::swap` within the remaining iterations (see caveat in Impact/PoC), so I flag that explicitly rather than asserting it.

### Title
`NonTransfer` proxy on the Westend relay-chain runtime falsely declares itself a superset of `Auction`, allowing escalation to the explicitly-excluded `Registrar::swap` call - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`substrate/frame/proxy` authorizes `add_proxy`/`remove_proxy` purely through `InstanceFilter::is_superset`, not through `filter` [1](#0-0) . The Polkadot SDK already found and fixed exactly this class of bug on `asset-hub-westend`, where `NonTransfer` falsely claimed to be a superset of `Governance` even though `Governance`'s filter admitted `Treasury`/`ConvictionVoting`/`Referenda`/`Whitelist` calls that `NonTransfer`'s filter denied [2](#0-1) , with a regression test added to guard the whole lattice [3](#0-2) . The same anti-pattern is still present, unguarded, in the Westend relay-chain runtime's own `ProxyType` implementation.

### Finding Description
In `polkadot/runtime/westend/src/lib.rs`, `ProxyType::is_superset` contains a blanket arm:
```rust
(ProxyType::NonTransfer, _) => true,
``` [4](#0-3) 

This claims `NonTransfer` is a superset of every other `ProxyType`, including `Auction`. But `NonTransfer`'s `filter` only admits three specific `Registrar` calls and explicitly comments that it omits `swap`:
```rust
RuntimeCall::Registrar(paras_registrar::Call::register{..}) |
RuntimeCall::Registrar(paras_registrar::Call::deregister{..}) |
// Specifically omitting Registrar `swap`
RuntimeCall::Registrar(paras_registrar::Call::reserve{..}) |
``` [5](#0-4) 

Meanwhile `ProxyType::Auction`'s filter admits the *entire* `Registrar` call family unconditionally:
```rust
ProxyType::Auction => matches!(
    c,
    RuntimeCall::Auctions(..) |
        RuntimeCall::Crowdloan(..) |
        RuntimeCall::Registrar(..) |
        RuntimeCall::Slots(..)
),
``` [6](#0-5) 

This is the identical shape of the already-fixed bug: `is_superset` declares a subset relationship that `filter` does not honor. Since `pallet_proxy::do_proxy` only checks `!def.proxy_type.is_superset(proxy_type)` before allowing `add_proxy`/`remove_proxy` [7](#0-6) , a delegate holding only a `NonTransfer` proxy over a real account can call `Proxy::proxy(real, None, add_proxy{delegate: attacker, proxy_type: Auction})` — which passes because `NonTransfer.is_superset(Auction) == true` — and then use the new `Auction` proxy entry to submit `Registrar::swap` on behalf of `real`, a call `NonTransfer` was deliberately designed to deny.

### Impact Explanation
If proven exploitable end-to-end, this lets an account entrusted with only `NonTransfer` proxy rights (explicitly meant to exclude fund/registration-sensitive operations) escalate to submitting `paras_registrar::swap` as the real account — potentially swapping parachain/parathread registrations tied to that account. The severity ultimately depends on `paras_registrar::swap`'s own authorization requirements (i.e., whether it further requires the dispatch origin to be the para manager or root); I was unable to retrieve and verify the body of `pub fn swap` in `polkadot/runtime/common/src/paras_registrar/mod.rs` before the session ended, so I cannot confirm the final blast radius (e.g., whether `real` must itself already be a para manager for `swap` to have effect). This is analogous to the Visor Finance root cause — a management-scoped permission being reachable through an account that was only supposed to hold a restricted role — but the exact monetary/control impact here is unconfirmed pending that check.

### Likelihood Explanation
Likelihood is high for reaching the escalation itself: no privileged role, governance action, or stolen key is needed — only a normal, intentionally-restricted `NonTransfer` proxy grant (a standard, commonly-used relationship) and two ordinary signed `Proxy::proxy` extrinsics. The blocking factor for real-world impact is solely whatever authorization `paras_registrar::swap` performs on its own origin, which was not fully verified in this session.

### Recommendation
Apply the same fix pattern used in `prdoc/pr_12769.prdoc` [2](#0-1) : audit every `is_superset` arm in `polkadot/runtime/westend/src/lib.rs` (and the structurally identical `rococo`, `collectives-westend`, `substrate/bin/node/runtime`, and `substrate/frame/staking-async/runtimes/rc` runtimes, which all contain the same `(ProxyType::NonTransfer, _) => true` blanket arm [8](#0-7) ) against the calls actually admitted by each subset's `filter`, and add a lattice-wide regression test mirroring `proxy_type_superset_relation_matches_call_filters` [9](#0-8)  to every runtime that defines a custom `InstanceFilter`.

Logic was traced statically through `pallet_proxy::do_proxy`'s `is_superset` gate [10](#0-9)  and the conflicting `NonTransfer`/`Auction` filter definitions [11](#0-10) , mirroring the already-proven, already-fixed `NonTransfer`/`Governance` case in the same repository. A minimal integration test analogous to `non_transfer_proxy_is_not_a_superset_of_governance` [12](#0-11)  but targeting `ProxyType::Auction`'s `Registrar::swap` admission against `westend_runtime::ProxyType` would confirm it; I was not able to run this within the session, and I was unable to retrieve `paras_registrar::swap`'s dispatch-origin check to confirm final impact before iterations ran out — this should be verified before treating the finding as bounty-final.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
