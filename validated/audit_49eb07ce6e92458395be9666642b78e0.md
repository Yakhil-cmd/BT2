### Title
Low-decimal collateral debt can enter an unliquidatable band where every `liquidate` offer reverts, leaving bad debt to be socialized - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
CVE-2019-0157 is an "insufficient input validation → denial of service" class. The analog in XOXNO Lending is the whole-unit liquidation path for collateral legs below `MIN_BORROWABLE_ASSET_DECIMALS` (3 decimals). Because such legs only seize whole token units, there is a debt band in which neither quote-promotion rule in `whole_unit_repayment` applies and the raw curve quote backs less than one whole unit. In that state every possible `liquidate` payment is either trimmed to a leg that seizes zero units or fails validation, so the call always reverts with `InvalidPayments`. An unprivileged borrower can deliberately size a borrow to land inside this band; once the position goes below HF = 1 it cannot be liquidated until interest accrual or a price move moves it out, and if the account is insolvent its debt is eventually written off against suppliers.

### Finding Description
For an account whose only supply position is a collateral asset with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS`, `normalize_repayment_plan` raises the ideal repayment via `whole_unit_repayment` only when one of two rules matches:

- Rule 1: `floor(U / (1 + b)) >= D + R` → quote becomes the whole debt `D` (full close, seize one unit) — `math.rs` lines 275-280.
- Rule 2: the curve quote seizes less than one unit plus margin, and `raised = ceil((U + m) / (1 + b)) < D` → quote becomes `raised` — `math.rs` lines 281-289.

Otherwise the curve quote is returned unchanged (`math.rs` line 288 `return quote_usd`). Because a sub-3-decimal leg seizes only whole units — `calculate_seized_collateral` floors a partial seizure to `to_asset_floor(env, feed.asset_decimals)` at `math.rs` lines 401-416 — a curve quote that backs less than one whole unit produces `seizure_ray == 0`, the leg is skipped (`math.rs` lines 419-421), and a plan left with no seizure reverts with `InvalidPayments` (controller error #16).

The unliquidatable band is therefore `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))` combined with a curve quote backing less than one unit. This exact dead zone is acknowledged in the docs: "While `floor(U / (1 + b)) - R < D <= ceil((U + m) / (1 + b))`, neither rule 1 nor rule 2 applies. If the curve quote then backs less than one unit, every offer reverts until accrual or a price move ends that state" (`docs/reference/formulas.md` lines 305-308, `docs/reference/invariants.md` lines 434-437, `skills/xoxno-lending-liquidations/SKILL.md` lines 131-133). ### Impact Explanation
A borrower controls the debt size at `borrow` time and can pick `D` inside the band. After a price drop pushes the account below HF = 1, no liquidator can construct a valid `liquidate(caller, account_id, payments, seize_mode)` call: sub-quote offers seize zero units and revert; full-debt offers above the quote are not trimmed to the band because the band exists precisely where the quote-promotion rules don't fire. The debt sits unliquidatable while it accrues interest, worsening the shortfall. If the account is or becomes insolvent, the residue falls to `clean_bad_debt` / `force_socialize_bad_debt`, which writes the debt down against the market's supply index — i.e., a temporary freeze of liquidation that matures into loss socialization onto unrelated suppliers (protocol insolvency / theft of supplier funds). The borrowed tokens were already drawn, so pool cash is permanently reduced while repayment cannot be forced through the normal channel.

### Likelihood Explanation
Likelihood is medium-low:

- Requires a listed collateral with fewer than 3 decimals (a governance listing decision, but the constraint itself is enforced only at `decimals < 3`, not against the unit-value/debt-band interaction).
- Requires the position to be solvent-but-unhealthy (`C >= D`, `HF < 1`) with debt inside a narrow band whose width is roughly `U·b/(1+b) + m + R`; the borrower can aim for this deliberately since `D` is chosen at borrow time and the band bounds are computable from public prices.
- The position must hold ≥ 1 whole unit (required anyway for a debt-bearing sub-3-decimal account, which must keep ≥ 2 whole units).
- The deadlock is self-resolving only via interest accrual or oracle price movement; for slow-moving or RWA-style priced assets this window can be long.

### Recommendation
Close the dead band deterministically instead of leaving the quote unchanged. When the account's only supply leg is sub-3-decimal, holds a whole unit, and the curve quote backs less than one unit, promote the ideal repayment to `min(ceil((U + m) / (1 + b)), D)` even when `raised >= D` — i.e., treat a `raised >= D` quote as a full close at `D` with the leg rounding up to one unit (cap the seizure at `actual_ray` as already done for `repays_all_debt`). Alternatively, add a `require_liquidatable` style check at `borrow`/`multiply` time that rejects debt amounts landing inside the band for sub-3-decimal-only accounts, so the state is unreachable rather than unrecoverable.

### Proof of Concept
Sketch against the existing test harness (`tests/test-harness/tests/controller/zero_decimal_collateral.rs` and `liqvid_rwa_collateral.rs` provide the primitives):

1. List collateral `LIQ` with `decimals = 0..=2`, unit price `U`, bonus `b`, threshold `LT`.
2. Alice supplies `k ≥ 2` whole units and calls `borrow` with `D` chosen so that `floor(U/(1+b)) - R < D <= ceil((U + m)/(1+b))` and the curve quote `ideal(D, HF)` satisfies `ideal·(1+b) < U + m`.
3. Drop the oracle price so `HF < 1` while staying solvent (`C >= D`).
4. Liquidator calls `get_liquidation_estimate` → `max_payment_wad` is the unchanged curve quote (no rule fires); then `liquidate(liquidator, id, payments, SeizeMode::Transfer)` reverts with `Error(Contract, #16)` (`InvalidPayments`) because the computed seizure floors to zero whole units and the leg is dropped.
5. Repeat with every payment size in `[1, debt]`: payments below the quote seize 0 units (revert); the quote itself reverts; no larger valid payment exists because the quote was never raised to `D`.
6. Advance ledger time minimally / hold price: the account remains unliquidatable until accrual pushes `D` above `raised` or below `unit_at_bonus - R`. If the position is insolvent, only `clean_bad_debt`/`force_socialize_bad_debt` can clear it, socializing the loss to the market's suppliers via the supply-index write-down in `contracts/pool/src/interest.rs::apply_bad_debt_to_supply_index`.

The existing test `lqv_one_unit_sale_applies_below_three_decimals_only` (`tests/test-harness/tests/controller/liqvid_rwa_collateral.rs` lines 957-988) and `zdc_sub_unit_liquidation_reverts_without_charging` (`zero_decimal_collateral.rs` lines 510-525) demonstrate both halves of the mechanism — the quote-promotion path and the zero-seizure revert — and can be composed to pin the band.
