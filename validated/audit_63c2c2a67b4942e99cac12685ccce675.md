### Title
Webhook signature is verified against `repository.owner.login` while handlers act on the independently-parsed `repository.full_name`, allowing cross-repository/cross-organization forged events - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`verify_signature` picks the GitHub App/secret to validate a webhook's HMAC using `repository_owner`, a value read from `params.dig('repository','owner','login')` (or `organization.login`). Every event handler that mutates state, however, resolves the target `Repository`/`Stack` using a completely separate field, `repository.full_name`, without ever confirming that `full_name`'s owner segment equals the `repository_owner` used for signature verification.

### Finding Description
`verify_signature` does: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` looks up the GitHub App configuration (and its `webhook_secret`) purely for the organization named in `repository.owner.login`, and `verify_webhook_signature` returns `true` unconditionally when that organization's `webhook_secret` is unset: [3](#0-2) 

Meanwhile, every handler (push, pull_request opened/closed/labeled/etc.) resolves the actual `Repository`/`Stack` to modify from a different JSON key, `repository.full_name`: [4](#0-3) [5](#0-4) [6](#0-5) 

`repository.owner.login` and `repository.full_name`'s owner segment are two independent, unauthenticated strings in the JSON body; nothing enforces `repository.owner.login == full_name.split('/').first`. Because Shipit supports multiple organizations, each configured with its own optional `webhook_secret` (docs even mark it "optional"), a self-hosting operator commonly has at least one organization with no `webhook_secret` configured: [7](#0-6) 

This equality is the binding that should hold but doesn't: `organization authenticated (repository.owner.login used to pick verification secret) == organization actually written (owner segment of repository.full_name used to resolve Repository/Stack)`. An unauthenticated network attacker (no session, no `ApiClient` token, no `webhook_secret`, no `GITHUB_TOKEN`) can POST directly to the public `/webhooks` endpoint with:
- `repository.owner.login` = the name of any organization configured in this Shipit instance whose `webhook_secret` is blank (this satisfies `verify_signature`'s `head(422) unless verified` check trivially, since `verify_webhook_signature` short-circuits `true`), and
- `repository.full_name` = `"other-org/other-repo"`, an entirely different, secured organization's repository that has a tracked `Stack`/`Repository` in the same Shipit instance.

The handler then acts on the victim repository's stack using attacker-controlled payload fields (branch, SHA, pull-request action, labels, etc.), even though the signature verification never touched anything belonging to that victim organization.

### Impact Explanation
Depending on which handler fires, this yields writes against a stack the attacker does not control and never proved a valid signature for:
- `PushHandler` triggers `stack.sync_github(expected_head_sha: ...)` for a stack belonging to a different, secured organization, with an attacker-chosen `after` SHA and branch. [8](#0-7) 
- `PullRequest::OpenedHandler`/`ClosedHandler`/`LabeledHandler`/`UnlabeledHandler` create, archive, or unarchive review stacks and update `PullRequest` records for the victim repository, driven entirely by attacker JSON, since `review_stack`/`stack` resolution only depends on the unauthenticated `full_name`. [9](#0-8) 

This is a cross-repository/cross-organization state-mutation path reachable with zero credentials, satisfying the "cross-repository writes" / "unauthorized deploy" impact bar, since forged push events can drive `sync_github` and downstream continuous-deployment logic for a repository the attacker has no relationship to.

### Likelihood Explanation
Reachability requires only that the Shipit deployment host more than one GitHub organization and that at least one of them (any one, not necessarily the victim) is configured without a `webhook_secret` — a state the setup docs explicitly present as an acceptable, optional configuration: [10](#0-9) 
No credentials, tokens, or prior access to the target organization are needed; the attacker only needs network access to the publicly documented `/webhooks` endpoint.

### Recommendation
In `WebhooksController#verify_signature` (and/or in `Webhooks::Handlers::Handler#stacks`/`#repository`), require that the owner segment of `repository.full_name` (or `organization.login` for org-scoped events) matches the `repository_owner` value used to select the verifying GitHub App/secret, rejecting the request otherwise. Additionally, consider requiring `webhook_secret` to be mandatory for every configured organization so that `verify_webhook_signature` can never short-circuit to `true`.

### Proof of Concept
1. Shipit is configured with two organizations, e.g. `OrgOne` (no `webhook_secret`) and `victim-org` (has `webhook_secret` and a tracked `Stack` for `victim-org/victim-repo`), as in [11](#0-10) .
2. Attacker (unauthenticated) POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "attacker-chosen-sha",
  "repository": { "owner": { "login": "OrgOne" }, "full_name": "victim-org/victim-repo" }
}
```
No `X-Hub-Signature` header (or any value) is required because `repository_owner` resolves to `OrgOne`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally ( [12](#0-11) ).
3. `WebhooksController#create` dispatches to `PushHandler`, which resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` ( [4](#0-3) ) and calls `stack.sync_github(expected_head_sha: "attacker-chosen-sha")` for the victim's stack — despite the request never being validated against `victim-org`'s secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
