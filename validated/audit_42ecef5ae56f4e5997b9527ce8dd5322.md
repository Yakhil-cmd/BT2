### Title
`NonTransfer` proxy on the Westend/Rococo relay-chain (and the `staking-async` relay runtime) falsely claims to be a superset of `Auction`, letting it self-escalate to dispatch the explicitly-denied `paras_registrar::swap` call - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`pallet_proxy` gates `add_proxy`/`remove_proxy` purely on `ProxyType::is_superset`, independent of `ProxyType::filter` [1](#0-0) . On Westend's (and Rococo's, and the new `staking-async` relay runtime's) relay-chain `ProxyType`, `NonTransfer` declares itself a superset of every non-`Any` type, including `Auction`, while `NonTransfer`'s own filter explicitly *excludes* `paras_registrar::Call::swap` and `Auction`'s filter admits the entire `Registrar(..)` call family (which includes `swap`) [2](#0-1) . This is precisely the same bug class Parity already identified and fixed for Asset Hub Westend in PR #12769, where `NonTransfer` falsely claimed `Governance` as a subset [3](#0-2)  — the same anti-pattern was never corrected on the relay-chain `ProxyType` definitions.

### Finding Description
`pallet_proxy::do_proxy` allows a delegate acting through a proxied call to add/remove a proxy of type `X` for the real account only if the delegate's own `def.proxy_type.is_superset(X)` holds; otherwise `filter` alone governs ordinary calls [4](#0-3) .

On the Westend relay chain:
- `ProxyType::NonTransfer::filter` admits `Registrar::register`, `Registrar::deregister`, `Registrar::reserve` but comments "Specifically omitting Registrar `swap`" [5](#0-4) .
- `ProxyType::Auction::filter` admits the full wildcard `RuntimeCall::Registrar(..)`, which includes `swap` [6](#0-5) .
- `ProxyType::is_superset` declares `(NonTransfer, _) => true` for any other non-`Any` type, i.e. `NonTransfer.is_superset(Auction) == true` [7](#0-6) .

Because `is_superset` (not `filter`) is what `pallet_proxy` checks before allowing `add_proxy`/`remove_proxy`, a delegate holding only a `NonTransfer` proxy — which was deliberately denied the ability to invoke `swap` directly — can call `Proxy::add_proxy(real, Auction, 0)` on behalf of `real` (since `NonTransfer.is_superset(Auction)` is `true`), granting itself (or another account it controls) an `Auction` proxy over `real`. It can then dispatch `RuntimeCall::Registrar(paras_registrar::Call::swap { .. })` on behalf of `real` through that new `Auction` proxy, since `Auction`'s filter admits the unrestricted `Registrar(..)` wildcard. This exactly mirrors the already-patched Asset Hub Westend `NonTransfer`/`Governance` lattice violation (PR #12769) [3](#0-2) , and the same regression-style test exists for Asset Hub (`proxy_type_superset_relation_matches_call_filters`, `non_transfer_proxy_is_not_a_superset_of_governance`) [8](#0-7)  but no equivalent fix or test exists for the relay-chain `ProxyType` in `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs` (same comment pattern observed at line 962: "Specifically omitting Registrar `swap`" alongside an `Auction` filter [9](#0-8) ), or `substrate/frame/staking-async/runtimes/rc/src/lib.rs` (identical `NonTransfer`/`Auction`/Registrar-swap comment pattern at lines 1352-1418) [10](#0-9) .

### Impact Explanation
A `NonTransfer` proxy is a common delegation pattern meant to let a delegate manage governance/utility-style operations on behalf of a delegator while explicitly withholding sensitive administrative calls (the code comments make the intent to exclude `Registrar::swap` explicit). The `is_superset`/`filter` lattice mismatch lets that delegate bypass the intended restriction and dispatch `paras_registrar::swap` as `real`, which — depending on `swap`'s semantics inside `paras_registrar` (mutual/witness-gated swap of para IDs/leases/deposits between two parachain registrations) — could affect a parachain's registration identity/slot on the real account's behalf without the delegator's explicit authorization for that specific call family. This is an unauthorized-dispatch/privilege-escalation issue directly analogous to the Dokploy report: a lower-privilege grant (`member:create`-like `NonTransfer`) is used to mint a higher-privilege grant (`owner`-like `Auction`) that the truster never intended to be reachable, and once minted it cannot be filtered back out by the delegator's original restriction.

### Likelihood Explanation
Requires only a `NonTransfer` proxy relationship already granted to the attacker's account by a legitimate delegator (a routine, unprivileged proxy-delegation pattern any signed account can create for itself or receive), and two ordinary signed `Proxy::proxy` calls (`add_proxy` then the `Registrar::swap` dispatch). No governance, root, or validator/collator privilege is needed — only that the attacker already holds any proxy of type `NonTransfer` over the victim account, which is a normal, low-trust delegation many users create. I was not able to fully verify the internal authorization/witness requirements of `paras_registrar::Call::swap` itself (the function body was not read in this pass) — that would need to be inspected to confirm the precise, concrete state change achievable, so severity/exploitability of the final `swap` call should be independently confirmed before treating this as more than a proxy-privilege-lattice violation.

### Recommendation
Apply the same fix used in PR #12769 to every affected relay/parachain `ProxyType::is_superset` implementation: remove the blanket `(ProxyType::NonTransfer, _) => true` claim and instead only declare `is_superset` relations that are provably consistent with `filter` (i.e., every call the "subset" admits must also be admitted by the claimed "superset"), or narrow `Auction`'s filter to the specific `Registrar::{register,deregister,reserve}` variants instead of the full `Registrar(..)` wildcard, consistent with what `NonTransfer` itself admits. Add a lattice-consistency test (mirroring `proxy_type_superset_relation_matches_call_filters`) to `polkadot/runtime/westend`, `polkadot/runtime/rococo`, and `substrate/frame/staking-async/runtimes/rc`.

### Proof of Concept
No executable PoC was run. This analysis is based on static code review only:
- Confirmed via direct file reads: `polkadot/runtime/westend/src/lib.rs` lines 950-1030 (full `ProxyType` filter/`is_superset` definitions) and `substrate/frame/proxy/src/lib.rs` lines 994-1022 (`do_proxy`'s `is_superset`-gated `add_proxy`/`remove_proxy` check).
- The `rococo` and `staking-async` `rc` runtime instances were confirmed to contain the identical comment pattern ("Specifically omitting Registrar `swap`" plus a `Registrar(..)`-wildcard `Auction` filter) via partial reads/grep, but their full `is_superset` bodies were not re-verified line-by-line in this pass due to iteration limits.
- `paras_registrar::Call::swap`'s internal authorization logic was located (`polkadot/runtime/common/src/paras_registrar/mod.rs`) but its body was not read; the concrete on-chain effect and any additional authorization/witness gating inside `swap` remain unverified and should be checked by a follow-up session before treating this beyond a proven proxy-filter/is_superset lattice inconsistency.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
