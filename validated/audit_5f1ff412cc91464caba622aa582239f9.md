### Title
Bad-debt socialization writes down depositors' share price by more than it removes from the accounted asset pool, permanently freezing part of suppliers' claimable value - ([File: mainnet/contracts/vault/v0-vault-sbtc.clar])

### Summary
`socialize-debt` in each vault contract (`v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`) computes two different "token amount" quantities for the same `scaled-amount` of bad debt and uses them inconsistently, exactly the same class of bug as the `manualRebalance` finding: two values that are treated as interchangeable ("amounts of the same unit") but are actually computed with different formulas and therefore diverge, and the mismatch is applied across two different state variables that must stay consistent (`lindex` vs. `assets`/`total-borrowed`).

### Finding Description
`socialize-debt` is invoked by the `market` contract's `liquidate` flow when a borrower's collateral is fully exhausted but scaled debt remains, in order to write off (socialize) the unpaid debt across all suppliers of that vault: [1](#0-0) 

Inside `socialize-debt`, two quantities are derived from the same `scaled-amount` input: [2](#0-1) 

- `debt-reduction = scaled-amount * idx / INDEX-PRECISION` — the debt value at the **current** borrow index `idx`, i.e. it fully includes interest that has accrued since each underlying borrow was originated.
- `principal-reduction = scaled-amount * borrowed / scaled-principal` — a ratio computed against `total-borrowed` (raw principal only, tracked without interest, since interest realizes into `assets` separately via `system-repay`) and `scaled-principal` (the sum of scaled units, each scaled by the borrow index *at the time each loan was taken*). This ratio is effectively a weighted-average *historical* index, not the current one.

Because `idx` only ever increases (interest accrues monotonically) while the historical weighted-average index embedded in `borrowed/scaled-principal` is always ≤ the current `idx`, `debt-reduction` is systematically **larger** than `principal-reduction` for the same `scaled-amount` whenever any interest has accrued on the position being written off.

The contract then uses the **larger** value (`debt-reduction`) to write down the depositors' share-price index: [3](#0-2) 

but uses the **smaller** value (`principal-reduction`) to decrement the accounted asset pool (`total-borrowed`, `assets`) that will feed all future `total-assets()`/`lindex` computations: [4](#0-3) 

This is structurally identical to the H-01 pattern: two values (`currentLockRatio`/`newLockRatio` in the report, `debt-reduction`/`principal-reduction` here) that look like the same kind of quantity, are not actually comparable/interchangeable, and the code mixes them across two places that must agree.

### Impact Explanation
`lindex` (the liquidity/share index redeemable by depositors) is marked down by the full accrued-interest-inclusive loss (`debt-reduction`), but the underlying asset pool that will be used to compute `total-assets()` in every subsequent accrual is only reduced by the smaller `principal-reduction`. The delta (`debt-reduction - principal-reduction`, the accrued-interest portion of the written-off debt) is removed from depositors' claimable value via the `lindex` markdown, but is never actually removed from the tracked asset base. That value is effectively orphaned inside the vault's accounting: depositors as a class (the unprivileged suppliers) are charged for more loss than what is removed from the pool, permanently understating their redeemable claims relative to the vault's real backing. This is a socialization loss applied to all suppliers of the vault that is larger than the actual bad debt removed, i.e. a permanent freezing of value that should be redeemable by depositors — meeting the "permanent freezing of funds/unclaimed yield" impact class.

### Likelihood Explanation
`socialize-debt` executes automatically and without any additional permission check beyond `check-caller-auth` (restricted to the `market` contract) whenever a liquidator drives a borrower's position to zero collateral with remaining debt via `liquidate`: [5](#0-4) 

Any position that accrues interest over time before being fully liquidated (essentially all realistic bad-debt scenarios, since accrual happens continuously) will trigger this mismatch, so no special attacker action beyond normal liquidation of an under-collateralized/insolvent position is needed. This makes the bug highly likely to fire in the ordinary bad-debt-socialization path rather than requiring a contrived setup.

### Recommendation
Use one consistent, correctly-scaled "amount" for both the `lindex` write-down and the `total-borrowed`/`assets` decrement in `socialize-debt`. Either:
- Decrement `total-borrowed`/`assets` by the interest-inclusive `debt-reduction` (consistent with the `lindex` markdown), or
- Compute the `lindex` markdown using `principal-reduction` (consistent with what is actually removed from `total-borrowed`/`assets`).

Additionally verify that `total-assets()` and `lindex` remain mutually consistent after `socialize-debt` executes, ideally via an invariant test that redeems all shares immediately after a socialization event and checks the sum of redeemed value against pre-socialization total assets minus the true bad debt.

### Proof of Concept
1. Borrower B borrows from a vault; time passes so that `idx` (the vault's borrow index) grows meaningfully above `INDEX-PRECISION` for B's scaled debt (i.e., real accrued interest exists on B's position, while `scaled-principal`/`borrowed` reflect the historical, lower index at origination).
2. Collateral price drops; a liquidator (an unprivileged principal) calls `market.liquidate` against B, fully draining B's collateral while leaving scaled debt outstanding, which triggers `socialize-debt-asset` → vault `socialize-debt` with `scaled-amount` = B's full remaining scaled debt.
3. Inside `socialize-debt`, `debt-reduction` (computed with current `idx`) is strictly greater than `principal-reduction` (computed with the lower historical average index ratio) because interest accrued.
4. `lindex` is written down using `debt-reduction` (the larger figure), reducing every depositor's redeemable value proportionally to that larger loss.
5. `total-borrowed`/`assets` are only reduced by `principal-reduction` (the smaller figure), so the vault's actual backing (`total-assets()` computed post-transaction from these vars) is higher than what the `lindex` computation assumed.
6. Any depositor who redeems shares after this event receives less value than the vault's true remaining backing justifies; the accrued-interest delta is permanently unaccounted for and unclaimable by anyone, demonstrating the freezing of supplier funds caused directly by the mismatched-unit calculation in `socialize-debt`.
