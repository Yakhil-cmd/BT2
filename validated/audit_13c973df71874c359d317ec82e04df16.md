### Title
Bridge Operators Can Transfer Assets When Bridge Is Stopped — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`)

### Summary

The Kaia service-chain bridge has an `isRunning` flag that the owner can set to `false` to stop all value transfers. The user-facing **request** functions correctly enforce this guard, but the operator-facing **handle** functions (`handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`) do not check `isRunning`, allowing bridge operators to transfer KLAY, ERC20, and ERC721 assets out of the bridge even when it is stopped.

### Finding Description

`BridgeTransfer.sol` declares `bool public isRunning = true` and exposes `setRunningStatus(bool)` (owner-only) as an emergency stop mechanism. [1](#0-0) 

The three user-facing request paths all enforce the guard:

- `_requestKLAYTransfer`: `require(isRunning, "stopped bridge")` [2](#0-1) 
- `_requestERC20Transfer`: `require(isRunning, "stopped bridge")` [3](#0-2) 
- `_requestERC721Transfer`: `require(isRunning, "stopped bridge")` [4](#0-3) 

However, the three operator-facing **handle** functions that actually move assets out of the bridge carry only `onlyOperators` (and `nonReentrant` for KLAY) — no `isRunning` check:

- `handleKLAYTransfer` — sends native KLAY via `.call.value(_value)("")` [5](#0-4) 
- `handleERC20Transfer` — calls `safeTransfer` or `mint` [6](#0-5) 
- `handleERC721Transfer` — calls `transferFrom` or `mintWithTokenURI` [7](#0-6) 

### Impact Explanation

When the bridge owner invokes `setRunningStatus(false)` as an emergency measure (e.g., counterpart chain compromise, bridge exploit in progress), operators can still call any of the three `handle*Transfer` functions to:

- Transfer arbitrary amounts of KLAY held by the bridge to any address.
- Transfer or mint arbitrary ERC20 tokens to any address.
- Transfer or mint arbitrary ERC721 tokens to any address.

This directly violates the invariant that a stopped bridge performs no asset movements. The corrupted value is the bridge's KLAY balance and token holdings — assets that should be frozen are instead drained.

### Likelihood Explanation

The default operator threshold is 1 (a single operator suffices to execute a value transfer vote). Any registered bridge operator can unilaterally call `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer` while `isRunning == false`. The trigger requires only a valid operator account, which is a semi-trusted but distinct role from the owner who issued the stop.

### Recommendation

Add an `isRunning` check to all three handle functions, mirroring the guard already present in the request functions. The cleanest approach is to add a `require(isRunning, "stopped bridge")` at the top of each function body (or introduce a shared `onlyRunning` modifier in `BridgeTransfer`):

```solidity
// BridgeTransfer.sol
modifier onlyRunning() {
    require(isRunning, "stopped bridge");
    _;
}
```

Then apply it to `handleKLAYTransfer`, `handleERC20Transfer`, and `handleERC721Transfer` alongside `onlyOperators`.

### Proof of Concept

1. Deploy `Bridge` with `modeMintBurn = false`; fund it with 100 KLAY.
2. Register an operator (`op1`); set operator threshold to 1.
3. Owner calls `setRunningStatus(false)` — bridge is stopped.
4. Confirm user requests revert: `bridge.connect(user).fallback({value: 1 ether})` → reverts with `"stopped bridge"`.
5. Operator calls:
   ```solidity
   bridge.connect(op1).handleKLAYTransfer(
       txHash, from, attacker, 100 ether, nonce, blockNum, "0x"
   );
   ```
6. Transaction succeeds; attacker receives 100 KLAY from the stopped bridge. The `isRunning == false` guard is never evaluated.

    function handleKLAYTransfer(
        bytes32 _requestTxHash,
        address _from,
        address payable _to,
        uint256 _value,
        uint64 _requestedNonce,
        uint64 _requestedBlockNumber,
        bytes memory _extraData
    )
        public
        onlyOperators
        nonReentrant
    {
        _lowerHandleNonceCheck(_requestedNonce);

        if (!_voteValueTransfer(_requestedNonce)) {
            return;
        }

        _setHandledRequestTxHash(_requestTxHash);

        handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber;
        _updateHandleNonce(_requestedNonce);

        emit HandleValueTransfer(
            _requestTxHash,
            TokenType.KLAY,
            _from,
            _to,
            address(0),
            _value,
            _requestedNonce,
            lowerHandleNonce,
            _extraData
        );

        (bool ok, ) = _to.call.value(_value)("");
        require(ok, "handleKLAYTransfer: transfer failed");
