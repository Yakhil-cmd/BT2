### Title
Extension asset download sends the victim's GitHub token to an attacker-controlled host via `releaseAsset.APIURL` - (File: pkg/cmd/extension/http.go)

### Finding Description
`downloadAsset` takes `assetURL safeurl.SafeURL` and issues `http.NewRequest("GET", assetURL.String(), nil)` before calling `httpClient.Do(req)`. The URL is wrapped via `safeurl.NewImmutableSafeURL(asset.APIURL)`, and `ImmutableSafeURL.String()` renders the value verbatim with no host allowlist, unlike `MutableSafeURL`, which only percent-encodes path segments but never validates the host either. `asset.APIURL` is populated straight from the release JSON's `assets[].url` field returned by `fetchLatestRelease`/`fetchReleaseFromTag`, which parse whatever the GitHub REST API for the repo returns into the `releaseAsset` struct. The existing test suite in `pkg/cmd/extension/http_test.go` confirms this value is not sanitized or host-checked — the test mock returns `"url":"https://example.com/asset"` and it's accepted into `APIURL` unchanged.

`httpClient` used by `downloadAsset` is the shared `m.client` from `Manager`, whose transport chain, when constructed via `NewHTTPClient`, includes `AddAuthTokenHeader`. That round tripper attaches `Authorization: token <TOKEN>` to *any* request whose host resolves an active token via `cfg.ActiveToken(hostname)`, with the only guard being that a *redirect* must not have changed host from the *initial request's* host — it does not restrict the initial request's host at all to the extension's origin repo host. If the attacker-controlled host happens to match a host for which the victim has a stored token (e.g., `github.com` itself, or another GHES host configured in the victim's `gh` config), or if the field is a same-host-looking but attacker-crafted absolute URL, the token is attached and sent off in the initial request.

The core issue is trust conflation: `NewImmutableSafeURL`'s doc comment states it is meant for "a URL received from a trusted source, such as a server response" — but the release owner (the attacker in this threat model) fully controls what appears in their own release's asset metadata is normally GitHub-computed, yet nothing in this code path enforces that `asset.APIURL`'s host actually matches `ghinstance.RESTPrefix(baseRepo.RepoHost())` or `ghinstance.RESTPrefix(<expected-host>)`.

### Impact Explanation
If any code path or edge case allows `assets[].url` to diverge from the API-computed asset URL (e.g., a compromised/self-hosted GHES instance whose API responses aren't guaranteed to be well-formed, or a future GitHub API surface returning attacker-influenced values), `downloadAsset` will fetch from that arbitrary host with the victim's `Authorization` header attached whenever the target host matches a configured token host. This matches a token/credential exfiltration impact class.

### Likelihood Explanation
On stock github.com, `assets[].url` is server-generated by GitHub and not attacker-settable via the release creation API, so under the strict "unprivileged remote attacker, no MITM/GHES control" threat model, there is no demonstrated way for the attacker to actually set `releaseAsset.APIURL` to an off-host value through the public GitHub API. I could not find, within this codebase or its tests, any evidence that GitHub's release API allows a repo owner to directly control the asset `url` field's host. This is a genuine defense-in-depth gap (missing host validation on `ImmutableSafeURL`/`downloadAsset`) rather than a demonstrated end-to-end exploit reachable purely from an attacker-owned public GitHub repo, because the precondition (attacker controls `asset.APIURL`'s host) is not achievable without control of the API host itself (a GHES scenario, which falls outside the stated attacker model of "no MITM/no admin").

### Recommendation
Validate that `asset.APIURL`'s host matches `ghinstance.RESTPrefix(baseRepo.RepoHost())` (or an equivalent explicit allowlist tied to the extension's declared host) before constructing the request in `downloadAsset`, rather than trusting `ImmutableSafeURL` to encode "trustedness" purely by convention. Additionally, `AddAuthTokenHeader` should not need to change if the URL is validated upstream, but as defense in depth, consider scoping token attachment to only the initial request host explicitly expected by the caller rather than any host with a locally stored token.

func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}

// ImmutableSafeURL is a SafeURL that renders a fixed URL string verbatim. It exists
// so that a URL which was not built from percent-encoded components, such as a full
// URL returned by the server (a pagination "next" link, an asset download URL, and
// the like), can still flow through the SafeURL typed code paths. Because the stored
// value is rendered as given without any encoding, it is only safe to wrap a URL that
// was created from trusted components or received from a trusted source.
type ImmutableSafeURL struct {
	url string
}

// NewImmutableSafeURL returns an ImmutableSafeURL that renders url verbatim. Only pass
// a URL you built yourself from trusted components or received from a trusted source,
// such as a server response; this bypasses all percent-encoding, so passing a value
// that embeds unescaped user or third party input reintroduces the injection risk that
// SafeURL exists to prevent.
func NewImmutableSafeURL(url string) *ImmutableSafeURL {
	return &ImmutableSafeURL{url: url}
}
