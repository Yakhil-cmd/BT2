### Title
Diff-header spoofing in `parse_diff_into_files` lets attacker-controlled hunk content truncate/hide security-relevant diff lines from LLM review - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`parse_diff_into_files` (and its sibling `extract_file_paths_from_diff`) splits raw `git diff` text on the literal substring `"diff --git "` rather than on line-start boundaries, then re-parses each fragment's first line with `^a/(.+?) b/(.+)$`. Any content line inside a real hunk (added, removed, or unchanged context) that happens to contain that exact substring followed by an `a/X b/Y`-shaped tail causes a spurious file boundary, truncating the real hunk and silently dropping the lines that follow from what gets sent to the security reviewer.

### Finding Description
`get_git_diff` produces a plain unified diff (no `-z`, no NUL framing) restricted by `_diff_pathspec`, which is correctly realpath-scoped to the repo. The scoping of *which files* are diffed is fine; the vulnerability is in how the diff *text* is subsequently re-split into per-file chunks for the LLM review step: [1](#0-0) 

`file_diffs = diff_output.split("diff --git ")` performs a plain substring split anywhere in the text, not just at the start of a line. Git's real headers always start at column 0, but nothing prevents a tracked file's *content* from containing the literal text `diff --git a/foo b/bar` inside a line that is itself part of a hunk (e.g. `+    cmd = "diff --git a/x b/y"` in a shell script, doc, or test fixture). Because the split is substring-based, the fragment boundary lands in the middle of that content line, and the residual text after `"diff --git "` (`a/x b/y...`) is exactly what the anchored regex `^a/(.+?) b/(.+)$` expects, so it is accepted as a brand-new fake file header.

Consequences:
- The **real** file's fragment is truncated at the injection point — everything after it (the actual subsequent hunk lines, which may contain the genuinely malicious/new code) is cut off from that file's collected `diff_lines`.
- The new fake fragment restarts with `in_hunks = False`; since the injected fake header is not followed by a fresh `@@` marker (the original hunk's `@@` already occurred earlier, before the split point), `in_hunks` never becomes `True` again, so `diff_lines` for the fake fragment stays empty and `if diff_lines:` is false — the fragment (and the genuine tail content it contains) is dropped entirely.
- Even if the fake header's file path (`bar`/`y`) happens to look "reviewable," the content attributed to it is nonsensical mid-hunk noise, while the true tail of the original file's new code never reaches `analyze_code_security`/`agentic_review`.

None of `_diff_pathspec`, `_temp_index`, `_is_ancestor`, or the caller-side `_is_reviewable_source` filter validate that the header-split boundaries correspond to actual `diff --git` header lines emitted by git — they all trust the naive split's output as "one entry per file."

### Impact Explanation
This is a **Security-control bypass**: code changes that are physically applied to the working tree/commit can be made invisible to the Stop-hook / commit-review LLM security scan by embedding a single crafted line (containing `diff --git a/X b/Y`) inside a hunk. Everything textually after that line in the same hunk is silently excluded from the content handed to `analyze_code_security` / `agentic_review`, meaning genuinely new vulnerable code can slip past the review gate that this plugin exists to enforce, matching "Security-control bypass that silently disables or routes around blocking, review, or permission boundaries." [2](#0-1) 

### Likelihood Explanation
Feasibility is high and requires no elevated privilege: the attacker only needs to be able to get a line of text into a file that will later be diffed under this plugin's review (a normal PR/commit, or content an agent is instructed to write). The trigger string is short and plausible in real-world files (shell scripts, CI configs, docs about git, or test fixtures referencing `diff --git`). It is fully deterministic and repeatable — the same crafted diff always produces the same truncation.

### Recommendation
Anchor the file-boundary split to actual header lines instead of a raw substring search: split on `re.split(r'(?m)^diff --git ', diff_output)` (or iterate `diff_output.split('\n')` and only start a new file entry when a *line* begins with `diff --git `), so that occurrences of the literal text inside `+`/`-`/context content can never be mistaken for a real header. Apply the same fix to `extract_file_paths_from_diff`, which shares the identical flaw.

### Proof of Concept
Unit test for `plugins/security-guidance/hooks/gitutil.py::parse_diff_into_files`:

```python
def test_parse_diff_into_files_survives_embedded_diff_git_line():
    diff_output = (
        "diff --git a/app/handler.py b/app/handler.py\n"
        "index 111..222 100644\n"
        "--- a/app/handler.py\n"
        "+++ b/app/handler.py\n"
        "@@ -1,2 +1,5 @@\n"
        " def handler(req):\n"
        "+    # contains literal text: diff --git a/x b/y\n"
        "+    os.system(req.params['cmd'])  # <-- should be reviewed\n"
        "+    return 'ok'\n"
    )
    files = parse_diff_into_files(diff_output)
    # Expect the injected os.system line to still be present in the
    # collected diff content for app/handler.py.
    assert any(
        fp == "app/handler.py" and "os.system(req.params" in content
        for fp, content in files
    ), f"malicious tail line was silently dropped: {files}"
```

Expected current behavior: the assertion fails — `os.system(req.params['cmd'])` is missing from the returned tuples because the embedded `diff --git a/x b/y` text splits the hunk and the tail is dropped, demonstrating the review-bypass. [1](#0-0)

```python
def parse_diff_into_files(diff_output):
    """
    Parse unified diff output into a list of (file_path, diff_content) tuples.
    Only includes files with source code extensions.
    """
    if not diff_output or not diff_output.strip():
        return []

    files = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue

        # Extract filename from first line: "a/path/to/file b/path/to/file"
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue

        file_path = header_match.group(2) or header_match.group(1) or ''

        # Filter to source code files only
        if not _is_reviewable_source(file_path):
            continue

        # Extract the diff content (from first @@ onwards)
        diff_lines = []
        in_hunks = False
        for line in lines[1:]:
            if line.startswith('@@'):
                in_hunks = True
            if in_hunks:
                diff_lines.append(line)

        if diff_lines:
            files.append((file_path, '\n'.join(diff_lines)))

    return files
```
