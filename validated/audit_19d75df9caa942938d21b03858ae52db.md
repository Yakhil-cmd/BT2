### Title
Incomplete deny-list in `ProxyType::NonTransfer` lets a "no-transfer" proxy move funds and assets on Asset Hub Rococo - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`ProxyType::NonTransfer` on Asset Hub Rococo is documented as "can execute any call that does not transfer funds or assets" but is implemented as a deny-list (`!matches!(c, ...)`) that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`. [1](#0-0) 
This mirrors the exact bug class already identified and fixed in the sibling Asset Hub Westend runtime (PR 12771) and in the staking-async parachain runtime (PR 12922), but the fix was never ported to Asset Hub Rococo. [2](#0-1) [3](#0-2) 

### Finding Description
`pallet_proxy::do_proxy` dispatches the wrapped call under the delegate's origin filtered only by `def.proxy_type.filter(c)`. [4](#0-3) 
On Asset Hub Rococo, `ProxyType::NonTransfer::filter` fails open: it denies only five explicitly named call families and admits everything else by default. [5](#0-4) 

The already-fixed Westend runtime shows precisely which call families were missing from this deny-list and had to be added: `ForeignAssets`, `PoolAssets` (other `pallet-assets` instances that transfer value like `Assets`), `AssetConversion` (swaps/liquidity moving the caller's assets), `Psm` (mint/redeem swapping stablecoins), `PolkadotXcm` (`transfer_assets`/`teleport_assets`/`send`/`execute` moving assets cross-chain), `Revive` (contract calls/instantiation carrying a `value`), `Vesting::vested_transfer`, and `Indices::transfer`/`force_transfer` (repatriating the reserved deposit). [6](#0-5) 

A `grep` over `asset-hub-rococo/src/lib.rs` confirms these same pallet identifiers (`ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, `Scheduler`, `Treasury`, `Indices`, `Vesting`) are present and configured throughout the file (117 matches), indicating the runtime wires the same set of value-moving pallets that Westend had to explicitly deny — yet the Rococo `NonTransfer` deny-list at lines 608-615 was never updated to include them. This is the structural analog of the MacCMS10 report: a denylist enumerating "dangerous operations" that omits several equally dangerous ones, letting attacker-controlled input reach unintended functionality that the filter was meant to block.

### Impact Explanation
A delegator who grants a `ProxyType::NonTransfer` proxy — expecting the delegate to be unable to move funds or assets — is instead exposed to the delegate performing `ForeignAssets`/`PoolAssets` transfers, `AssetConversion` swaps that redirect the caller's assets, `PolkadotXcm` teleports/reserve-transfers moving assets off-chain, `Revive` contract calls carrying `value`, `Vesting::vested_transfer`, and `Indices::transfer`/`force_transfer` repatriating a reserved deposit — all under the delegator's own signed origin. This is a direct authorization-bypass leading to unauthorized asset movement/theft from the proxied account, matching the "High: theft/unauthorized dispatch" bug class prioritized by the assessment method.

### Likelihood Explanation
Likelihood is high for any delegator who has legitimately granted a `NonTransfer` proxy (a routine, permitted, non-privileged action under `pallet_proxy::add_proxy`) to a delegate they trust only for non-value-moving operations. The delegate needs no special privileges, governance control, or stolen keys — only the `NonTransfer` proxy grant itself, which is the entire premise of that proxy type. The gap is deterministic and always reachable once the proxy exists; it requires no race condition or unusual chain state.

### Recommendation
Port the same fix applied in PR 12771/PR 12922 to `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`: extend the `ProxyType::NonTransfer` deny-list to explicitly exclude `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, `Vesting::vested_transfer`/`force_vested_transfer`, and `Indices::transfer`/`force_transfer` (and any other pallet configured in this runtime that moves the caller's funds/assets), consistent with the documented "no transfer" semantics. Longer term, consider switching `NonTransfer` to an allow-list (fail-closed) pattern, as used on the relay-chain runtimes' `ProxyType::NonTransfer`, so newly added pallets are denied by default rather than silently admitted. [7](#0-6)

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
