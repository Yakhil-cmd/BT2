### Title
Webhook signature verification is keyed to `repository.owner.login`, not the repository actually mutated by the handler (`repository.full_name`), allowing cross-organization review-stack provisioning - ([File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate the signature against using `repository_owner`, which is read from the top-level `repository.owner.login` field of the attacker-controlled JSON body. `OpenedHandler#process`, however, resolves which `Shipit::Repository` to mutate using a *different* field from the same JSON body: `repository.full_name`. Nothing binds these two fields together, so a payload whose `owner.login` names an org with no `webhook_secret` configured (verification is auto-satisfied) can carry a `full_name` pointing at a victim org's tracked repository, causing `ReviewStackAdapter#find_or_create!` to create and provision a new `Shipit::Stack` under that victim repository.

### Finding Description
The claimed binding is: `repository_owner` (org whose GitHub App verified the webhook) `==` owner of `repository.review_stacks` mutated by the handler.

- `WebhooksController#verify_signature` picks the app config via `Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository', 'owner', 'login')` [1](#0-0) .
- `Shipit.github` looks up per-organization config via `github_app_config(organization)`, raising only if the organization key is entirely absent [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) .
- The very same parsed JSON body is then dispatched, unmodified, to handlers: `params = JSON.parse(request.raw_post); Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `OpenedHandler#repository` resolves the target repository using `params.repository.full_name` — a field completely independent of `repository.owner.login` and not cross-checked against it — via `Shipit::Repository.from_github_repo_name` [5](#0-4) , and `Repository.from_github_repo_name` merely splits `"owner/name"` and does a DB lookup, with no relation to the org that verified the request [6](#0-5) .
- `OpenedHandler#process` then unconditionally provisions: `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` when `provision?` is true (i.e., the victim repo has `review_stacks_enabled` and `provisioning_behavior_allow_all?`) [7](#0-6) .
- `ReviewStackAdapter#create!` persists a new `Shipit::Stack`/`ReviewStack` scoped to the victim's `repository.review_stacks`, attaches the attacker-supplied `branch` from `pull_request.head.ref`, and enqueues it for provisioning via `Shipit::ReviewStackProvisioningQueue.add(stack)` [8](#0-7) .

The `OpenedHandler` params schema only `requires :repository do requires :full_name, String end` — it never requires or validates `repository.owner.login`, so no `ExplicitParameters` check forces consistency between the field used for auth (`owner.login`) and the field used for the mutation target (`full_name`) [9](#0-8) .

**Exploit flow**: Attacker (no secrets, no session) POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a JSON body where `repository.owner.login = "org-a"` (a real Shipit-configured org whose `webhook_secret` happens to be unset — a real multi-tenant misconfiguration scenario per the existing multi-org support in `Shipit.github_app_config`) and `repository.full_name = "org-b/victim-repo"` (Org B's real tracked repository, configured with `review_stacks_enabled: true` and `provisioning_behavior: allow_all`). `verify_signature` resolves the "org-a" GitHub App, whose blank `webhook_secret` makes `verify_webhook_signature` return `true` regardless of the (attacker-fabricated or even missing) `X-Hub-Signature` header. Verification passes, then `OpenedHandler` uses `full_name` to find and provision a new stack under Org B — an org and repository the attacker never authenticated against.

Existing guards do not stop this: `verify_signature` only proves the request holds a valid signature (or none required) for whichever organization the attacker names in `owner.login` — it does not prove anything about the `full_name`/repository the handler acts on. `drop_unhandled_event` and the `ExplicitParameters` schema only check event/field shape, not owner consistency. `check_if_ping` and `GithubOrganizationUnknown` handling are irrelevant to this divergence.

### Impact Explanation
The attacker gets an unauthorized `Shipit::Stack` (review stack) created and queued for provisioning under a victim organization's repository (`Shipit::ReviewStackProvisioningQueue.add(stack)`), which triggers the review-stack's provisioning/deploy task infrastructure without any legitimate signal from Org B. This is a payload nominally "from" Org A mutating Org B's stack state — matching the Critical category "a payload for one repository mutating another's stack ... or an unauthorized deploy." It is repeatable against any victim repository with `review_stacks_enabled` + `allow_all` (or `allow_with_label` if the attacker also controls PR labels, which they do as a PR author) as long as some org configured in Shipit lacks a `webhook_secret`.

### Likelihood Explanation
This requires: (1) a multi-org Shipit deployment (`secrets.github` keyed by org) where at least one configured org entry has a blank `webhook_secret` — a real-world misconfiguration risk since `webhook_secret` is optional per `GitHubApp#initialize` (`@webhook_secret = @config[:webhook_secret].presence`) [10](#0-9) ; and (2) a victim repository tracked by Shipit with `review_stacks_enabled` and a permissive `provisioning_behavior`. Given those, the attacker's cost is a single unauthenticated HTTP POST with no signature required, fully repeatable and scriptable against any tracked repository whose owner-org secret is well-configured, so long as some other configured org's secret is blank.

### Recommendation
Bind webhook signature verification to the same repository that the handler will act on: derive `repository_owner` consistently and additionally verify that the org used to select the GitHub App for signature verification matches the owner of `Shipit::Repository.from_github_repo_name(payload.repository.full_name)`. At minimum, require `webhook_secret` to be present for every configured organization (fail closed instead of `return true unless webhook_secret`), and reject webhooks where `repository.owner.login` does not match the owner segment of `repository.full_name`.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb`:
```ruby
test "cross-organization owner spoofing allows provisioning a review stack under a different org's repository" do
  victim_repo = shipit_repositories(:shipit) # owner e.g. "shopify"
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)

  # Configure a second org "org-a" with no webhook_secret (blank secret => verify_webhook_signature always true)
  Shipit.stubs(:github_app_config).with('org-a').returns({ app_id: 1, installation_id: 1 }) # no webhook_secret key
  Shipit.stubs(:github_default_organization).returns('org-a') # simulate multi-org mode

  payload = JSON.parse(payload(:pull_request_opened))
  payload["repository"]["owner"] = { "login" => "org-a" }              # verified org (Org A, no secret)
  payload["repository"]["full_name"] = victim_repo.github_repo_name    # actual mutated repo (Org B)

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # garbage, irrelevant when secret blank

  assert_difference -> { Shipit::Stack.count } do
    post :create, body: payload.to_json, as: :json
    assert_response :ok
  end

  new_stack = victim_repo.review_stacks.last
  assert_not_nil new_stack
  assert_equal victim_repo, new_stack.repository # Org B's repository mutated by an Org A-verified request
end
```
Assert the equality before/after: before the request, `repository_owner` ("org-a") != owner of `repository.full_name` ("shopify"/victim org) — after processing, a `Shipit::Stack` exists under the victim's `review_stacks`, proving the mismatch was never checked.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
