### Title
Permanently Locked Bridged KAIA Due to Non-Receivable Recipient with No Cancel/Refund Path — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

When a user initiates a KAIA bridge transfer to a recipient address that cannot receive native tokens (e.g., a contract whose fallback always reverts), the destination-side `handleKLAYTransfer` call permanently fails. Because the source bridge has no cancel or refund mechanism, the locked KAIA is irrecoverable. The bridge's `lowerHandleNonce` is frozen at that nonce, and the Value Transfer Recovery (VTR) daemon loops forever retrying the same failing nonce.

---

### Finding Description

**Source-side lock — no refund path**

`_requestKLAYTransfer` accepts `msg.value`, deducts the fee, and emits `RequestValueTransfer` with the remainder. The KAIA is now held by the bridge contract. There is no cancel or refund function anywhere in the contract hierarchy. [1](#0-0) 

**Destination-side permanent revert**

`handleKLAYTransfer` sets `handleNoncesToBlockNums[_requestedNonce]` and calls `_updateHandleNonce` *before* the low-level transfer, but the entire transaction is atomic. If `_to.call.value(_value)("")` returns `ok == false`, the `require` reverts the whole transaction, rolling back every storage write including `handleNoncesToBlockNums[_requestedNonce]`. [2](#0-1) 

**`lowerHandleNonce` frozen**

`_updateHandleNonce` advances `lowerHandleNonce` only while `handleNoncesToBlockNums[i] > 0` for consecutive `i` starting from `lowerHandleNonce`. Because the failing nonce's entry is never durably written, `lowerHandleNonce` is permanently frozen at nonce N. [3](#0-2) 

**VTR infinite retry**

`updateRecoveryHintFromTo` reads `RecoveryBlockNumber` from the destination bridge. `RecoveryBlockNumber` is updated inside `_updateHandleNonce` (line 151) and is therefore also never advanced past the block preceding nonce N. The VTR daemon detects `requestNonce != handleNonce` with a stable `handleNonce`, marks the hint as a recovery candidate, and keeps re-submitting the same failing nonce. [4](#0-3) [5](#0-4) 

---

### Impact Explanation

| Asset | Effect |
|---|---|
| KAIA locked in source bridge for nonce N | Permanently inaccessible — no refund, no redirect |
| `lowerHandleNonce` on destination bridge | Frozen at N forever |
| `recoveryBlockNumber` | Never advances past the block before N |
| VTR daemon | Loops indefinitely retrying nonce N, consuming operator gas |

Subsequent nonces (N+1, N+2, …) can still be handled because `_lowerHandleNonceCheck` only requires `lowerHandleNonce <= _requestedNonce`; however the locked KAIA for nonce N is unrecoverable and the VTR subsystem is permanently degraded. [6](#0-5) 

---

### Likelihood Explanation

The trigger requires only a standard user call to `requestKLAYTransfer` (or the payable fallback) with `_to` set to any contract whose receive/fallback reverts — a common pattern in multisigs, vaults, and access-controlled contracts. No privileged role is needed. The user may do this accidentally (e.g., sending to a contract address that was later upgraded to reject native tokens) or intentionally as a griefing attack against the bridge's VTR subsystem.

---

### Recommendation

1. **Add a skip/cancel mechanism**: Allow the bridge owner (or a quorum of operators) to mark a nonce as permanently skipped, advancing `lowerHandleNonce` past it and releasing the VTR loop.
2. **Emit a failure event instead of reverting**: Replace `require(ok, ...)` with a conditional that emits a `HandleValueTransferFailed` event and still records `handleNoncesToBlockNums[_requestedNonce]`, so `lowerHandleNonce` can advance even when delivery fails.
3. **Source-side refund**: Add a time-locked refund path in `_requestKLAYTransfer` so that if a nonce is not handled within a deadline, the sender can reclaim their KAIA.

---

### Proof of Concept

```solidity
// Step 1 — deploy a non-receivable contract on the destination chain
contract RevertOnReceive {
    receive() external payable { revert("no KAIA"); }
    fallback() external payable { revert("no KAIA"); }
}

// Step 2 — user locks KAIA in the source bridge (nonce = N)
sourceBridge.requestKLAYTransfer{value: 1 ether}(
    address(revertOnReceive), // _to
    1 ether,                  // _value
    ""                        // _extraData
);
// KAIA is now locked in sourceBridge; requestNonce advances to N+1.

// Step 3 — operators attempt to handle nonce N on the destination bridge
destBridge.handleKLAYTransfer(
    requestTxHash, from, payable(address(revertOnReceive)),
    1 ether, N, blockNum, ""
);
// ↑ reverts with "handleKLAYTransfer: transfer failed"
// handleNoncesToBlockNums[N] is never set.

// Step 4 — verify lowerHandleNonce is frozen
assert(destBridge.lowerHandleNonce() == N);   // stuck forever
assert(destBridge.recoveryBlockNumber() < N); // VTR rescans from here

// Step 5 — the 1 KAIA in sourceBridge is permanently unrecoverable.
// No cancel, no refund, no redirect function exists.
```

// updateRecoveryHint updates a hint for the one-way value transfers.
func updateRecoveryHintFromTo(prevHint *valueTransferHint, from, to *BridgeInfo) (*valueTransferHint, error) {
	var err error
	var hint valueTransferHint

	logger.Trace("updateRecoveryHintFromTo start")
	if prevHint != nil {
		logger.Trace("recovery prevHint", "rnonce", prevHint.requestNonce, "hnonce", prevHint.handleNonce, "phnonce", prevHint.prevHandleNonce, "cand", prevHint.candidate)
	}

	hint.blockNumber, err = to.bridge.RecoveryBlockNumber(nil)
	if err != nil {
		return nil, err
	}

	requestNonce, err := from.bridge.RequestNonce(nil)
	if err != nil {
		return nil, err
	}
	from.SetRequestNonce(requestNonce)
	to.SetRequestNonceFromCounterpart(requestNonce)
	hint.requestNonce = requestNonce

	handleNonce, err := to.bridge.LowerHandleNonce(nil)
	if err != nil {
		return nil, err
	}
	to.UpdateLowerHandleNonce(handleNonce)

	if prevHint != nil {
		hint.prevHandleNonce = prevHint.handleNonce
		hint.candidate = prevHint.candidate
	}
	hint.handleNonce = handleNonce

	logger.Trace("updateRecoveryHintFromTo finish", "rnonce", hint.requestNonce, "hnonce", hint.handleNonce, "phnonce", hint.prevHandleNonce, "cand", hint.candidate)

	return &hint, nil

// checkRecoveryCandidateCondition checks if vtr is recovery candidate or not.
// candidate is introduced to check any normal request just before checking start.
//
// For example,
//
// ======== ======== ======== ========
// Round    R Nonce  H Nonce  Result
// ======== ======== ======== ========
// 1        10       10       false
// <burst requests just before checking>
// 2        1000     10       ? (it can be normal but candidate)
// 3        2000     10       true
func checkRecoveryCandidateCondition(hint *valueTransferHint) bool {
	return hint.requestNonce != hint.handleNonce && hint.prevHandleNonce == hint.handleNonce
}

// checkRecoveryCondition checks if recovery for the handle value transfers is needed or not.
func checkRecoveryCondition(hint *valueTransferHint) bool {
	if checkRecoveryCandidateCondition(hint) && hint.candidate {
		hint.candidate = false
		return true
	}
	if checkRecoveryCandidateCondition(hint) && !hint.candidate {
		hint.candidate = true
		return false
	}
	hint.candidate = false
	return false
}
