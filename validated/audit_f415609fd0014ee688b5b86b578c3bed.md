### Title
Attacker-Controlled `NType` in NEIGHBORS Response Injects Fake CN Nodes into CN FlatStorage — (`networks/p2p/discover/table_lookup.go`, `udp.go`, `table_data.go`)

### Summary

A legitimately-bonded attacker peer can respond to a FINDNODE request with a NEIGHBORS packet containing `rpcNode{NType: NodeTypeCN}` for attacker-controlled keys. Because `nodeFromRPC` blindly trusts the wire-level `NType` field and `findNodesOnce` only filters BN nodes (not type-mismatched nodes), the attacker's nodes pass through `bondall → Bond → addNode` and are permanently inserted into the CN `flatStorage`. They are then served via `RandomNodes(NodeTypeCN)` to the dial scheduler, which dials them as CN peers — enabling eclipse-induced transaction censorship and block withholding.

### Finding Description

**Step 1 — Entry point (permissionless P2P).**
`doRefresh()` calls `kademliaRefresh(NodeTypeEN)`, which calls `lookup(target, NodeTypeEN, ...)`. [1](#0-0) 

**Step 2 — FINDNODE sent to bonded attacker peer.**
`findNodes` spawns goroutines calling `findNodesOnce(seed, targetID, NodeTypeEN, max)`, which calls `tab.udp.findnode(...)`. [2](#0-1) 

**Step 3 — `nodeFromRPC` trusts attacker-supplied `NType`.**
Inside `findnode()`, for each `rn` in the NEIGHBORS response, `nodeFromRPC` creates a `Node` with `NType` taken directly from the wire:

```go
n := NewNode(rn.ID, rn.IP, rn.UDP, rn.TCP, nil, rn.NType)
``` [3](#0-2) 

There is no check that `rn.NType` matches the `targetType` of the FINDNODE request.

**Step 4 — `removeBn` does not filter type-mismatched nodes.**
Back in `findNodesOnce`, only BN nodes are removed. Fake CN nodes (returned in response to a NodeTypeEN FINDNODE) pass through: [4](#0-3) 

**Step 5 — `bondall → Bond → addNode` inserts fake CNs into CN flatStorage.**
`bondall` calls `Bond(false, n)` for each node. After a successful ping/pong with the attacker-controlled fake CN node, `addNode(n)` is called. `addNode` routes solely on `n.NType`:

```go
if s := tab.storages[n.NType]; s != nil {
    s.add(n)
}
``` [5](#0-4) 

The CN storage is a `flatStorage` with `math.MaxInt64` capacity — it never evicts. [6](#0-5) 

**Step 6 — Fake CNs served to dial scheduler.**
`refillCandidates` calls `RandomNodes(buf, NodeTypeCN)`, which reads directly from the corrupted CN flatStorage: [7](#0-6) [8](#0-7) 

**Step 7 — `dynamicCandidateAllowed` does not protect EN nodes.**
The only dial-time guard is `dynamicCandidateAllowed`, which is a no-op for any node where `selfType != NodeTypeCN`:

```go
if ds.selfType != discover.NodeTypeCN || targetType != discover.NodeTypeCN {
    return true
}
``` [9](#0-8) 

EN nodes (and CN nodes with `cnPeerAddrs == nil`) receive no filtering. Fake CNs are dialed unconditionally.

### Impact Explanation

- **Transaction censorship**: EN nodes send transactions to fake CNs (`broadcastTxsFromEN` targets `CONSENSUSNODE` peers). Fake CNs silently drop them, preventing inclusion in blocks.
- **Block withholding**: Fake CNs do not relay blocks from real CNs to the EN, causing the EN to fall behind the canonical chain.
- **Propagation**: The corrupted CN flatStorage is served in FINDNODE responses to other nodes, spreading fake CN entries network-wide. [10](#0-9) 

### Likelihood Explanation

- Requires only a legitimately-bonded peer (permissionless UDP ping/pong).
- The attacker must run fake CN nodes that respond to pings — trivial with any Kaia-compatible node.
- No cryptographic break, no privileged key, no majority collusion required.
- Triggered automatically every 30 minutes by `refreshLoop` or on-demand via `Refresh()`. [11](#0-10) 

### Recommendation

In `findNodesOnce`, after `bondall`, filter out any node whose `NType` does not match `targetType`:

```go
func (tab *Table2) findNodesOnce(...) []*Node {
    r, err := tab.udp.findnode(...)
    if targetType != NodeTypeBN {
        r = removeBn(r)
    }
    // Add: discard nodes whose NType doesn't match the requested targetType
    r = filterByType(r, targetType)
    return tab.bondall(r)
}
```

Alternatively, enforce the type check inside `addNode` by comparing `n.NType` against the storage key, or inside `Bond` by rejecting nodes whose self-reported type (from the ping handshake) contradicts the expected type.

### Proof of Concept

1. Start a local Kaia node (EN) with a discovery table pointing to an attacker-controlled bootnode.
2. The attacker bootnode completes the ping/pong bond with the victim EN.
3. When the victim EN sends `FINDNODE(targetType=EN)`, the attacker responds with a NEIGHBORS packet containing `rpcNode{ID: attackerKey, IP: attackerIP, UDP: 30303, TCP: 30303, NType: NodeTypeCN}`.
4. The attacker's fake CN node responds to the victim's ping with a valid PONG.
5. Assert: `tab.storages[NodeTypeCN].all()` contains the attacker's node.
6. Assert: `tab.RandomNodes(buf, NodeTypeCN)` returns the attacker's node.
7. Assert: The dial scheduler dials the attacker's node as a CN candidate.
8. Assert: Transactions broadcast by the EN reach the fake CN but not real CNs.

func (tab *Table2) findNodesOnce(seed *Node, targetID NodeID, targetType NodeType, max int) []*Node {
	r, err := tab.udp.findnode(seed.ID, seed.addr(), targetID, targetType, max)
	// A timeout with no NEIGHBORS at all means the seed is unresponsive
	if errors.Is(err, errTimeout) && len(r) == 0 {
		tab.recordFindFailure(seed)
		return nil
	}
	// Drop bootnodes from the response unless the caller is explicitly looking for them
	if targetType != NodeTypeBN {
		r = removeBn(r)
	}
	// Out of the find results, return only reachable (bonded) nodes.
	return tab.bondall(r)
}

		return false
