Based on my research, git-sync configures a global, unscoped `credential.helper` (`git config --global credential.helper "cache --timeout 3600"`) and stores every credential — the main `--username`/`--password`, every entry from `--credential` (intended for specific submodule URLs per the docs), and GitHub App tokens — via `StoreCredentials`/`git credential approve` into this single shared, global cache.

### Title
Overly Broad Shared Git Credential Cache Allows Cross-URL/Cross-Submodule Credential Disclosure - ([File: main.go])

### Summary
git-sync configures one global `credential.helper` (`cache --timeout 3600`) shared by the top-level repo and *all* submodules, then feeds every distinct credential (main repo credential, each `--credential` entry meant for a specific submodule URL, GitHub App tokens) into this same store via `StoreCredentials`. `git credential approve` and git's default credential matching operate at protocol+host granularity unless `credential.useHttpPath` is set, which git-sync does not set. This mirrors the reported bug class: multiple call paths/consumers (here, fetches for the main repo and for each submodule) that are intended to have narrowly scoped access (one specific URL's credential) instead share access to a common privileged resource (the global credential cache), violating least privilege.

### Finding Description
`SetupDefaultGitConfigs` sets `credential.helper` globally with no `credential.useHttpPath` scoping [1](#0-0) . All credentials — from `--username`/`--password`, from each `--credential` object (explicitly documented as being for "specific URLs, for example when using submodules") [2](#0-1) , and from GitHub App token refresh [3](#0-2)  — are stored through the same `StoreCredentials` function using `git credential approve` [4](#0-3) . Because git's credential subsystem by default matches stored entries by protocol and host only (not full path), a credential approved for `https://host/repoA` is also handed out by `git credential fill` for any other path/repo under the same `https://host`, including a submodule the top-level repository points to that the operator did not intend to grant that credential to. This is the same root cause pattern as the reported issue: multiple distinct, narrower-scoped consumers (submodule fetch for repo A vs. submodule fetch for repo B, vs. the main repo fetch) are all funneled through one shared privileged store, so a credential meant for use case A becomes usable for use case B.

### Impact Explanation
If a repository (or one of its submodules, which are content controlled by whoever can push to that submodule's source, i.e. potentially a different trust domain than the one that owns a given `--credential` entry) references another URL on the same host, git will silently attach a credential that was scoped by the operator to a different repo/submodule. This can leak a password/token to an unintended repository host path, and in the SSRF/submodule redirection sense, could let a malicious or compromised submodule source cause git to authenticate to a same-host URL it should not have access to — disclosure of credentials/tokens outside intended scope.

### Likelihood Explanation
This requires a git-sync configuration using multiple `--credential` entries or GitHub App auth alongside submodules pointing at multiple paths on a shared host (a documented, encouraged configuration per the README) [5](#0-4) , plus git's default (non-path-scoped) credential matching behavior, which git-sync does not override. No attacker-controlled flags or malicious-operator assumptions are needed beyond the operator using the documented multi-credential/submodule feature; the weakness is in git-sync's own credential storage configuration.

### Recommendation
Set `credential.useHttpPath = true` (or otherwise scope stored credentials so they are only offered for the exact URL they were approved for), or use per-URL credential helpers instead of a single global `credential.helper` shared across the main repo and all submodules.

### Proof of Concept
1. Configure git-sync with `--repo=https://host/orgA/main.git` and `--credential='{"url":"https://host/orgB/subA.git","username":"userA","password":"tokenA"}'`.
2. Suppose `main.git`'s `.gitmodules` contains a submodule pointing to `https://host/orgB/subB.git` (a different, unintended path on the same host — this could be added by anyone with push/PR access to `main.git`, i.e., an attacker-controlled ref/commit).
3. During `git submodule update`, git's credential helper is queried for `https://host` and, because `credential.useHttpPath` is unset, returns the credential approved for `subA.git` (`tokenA`) for the `subB.git` fetch.
4. `tokenA`, scoped by the operator to `orgB/subA.git`, is now used against `orgB/subB.git`, disclosing/misusing a credential outside its intended scope — reachable purely by an attacker adding/altering a submodule URL in repo content that git-sync syncs, per [6](#0-5) .

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}
```

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
```
