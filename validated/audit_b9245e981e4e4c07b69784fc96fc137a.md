### Title
Stale Fundamental oracle leg inflates blended collateral price - ([File: contracts/price-aggregator/src/engine.rs])

### Summary
A two-source oracle averages its primary and anchor legs when both return observations, even when one `Fundamental` leg is many hours stale but still inside its configured staleness limit. Because the cross-leg age-spread check applies only when both legs are `Market`, a fresh Reflector price can be blended with a stale RedStone `Fundamental` price and remain usable if their prices stay within tolerance. [1](#0-0) 

### Finding Description
Each feed is marked stale only according to its own `max_stale_seconds` and the oracle-level `max_price_stale_seconds`. [2](#0-1)  The blend marks a pair stale when either leg is stale or when the age gap exceeds `MAX_LEG_AGE_SPREAD_SECONDS`, but the age-gap check is enabled only when both legs have `FeedNature::Market`. [3](#0-2)  When both observations exist, the final price is their midpoint and is rejected only for staleness, deviation, non-positive price, or sanity-band violation. [4](#0-3) [5](#0-4) 

The production XLM configuration pairs a Reflector TWAP with a 1-hour staleness limit and a RedStone source marked `Fundamental` with a 46,800-second staleness limit; the oracle-level limit is 57,600 seconds. [6](#0-5)  Therefore, a RedStone observation that is several hours old, yet not older than 46,800 seconds, can be averaged with the fresh Reflector leg. [7](#0-6)  The configured 11,000 BPS upper ratio allows the stale leg to differ by approximately 10% before deviation fails, so the midpoint can carry nearly half of that stale-price error into collateral valuation. [8](#0-7) 

The controller fetches aggregator prices through `prices` and uses the returned values for risk checks in the invocation context. [9](#0-8) [10](#0-9) 

### Impact Explanation
An attacker can deposit collateral while its fresh market price has fallen, then call the user-facing `supply` and `borrow` paths to borrow more debt than the current market value supports. The existing audit scenario demonstrates this sequence: a stale $1.00 RedStone anchor is averaged with a fresh $0.91 primary, inflating collateral valuation by more than 4%, and a 70,000 USDC borrow succeeds while the equivalent fresh-anchor control fails with `INSUFFICIENT_COLLATERAL`. [11](#0-10) [12](#0-11) 

This can leave the protocol with undercollateralized debt and cause insolvency or loss for suppliers if the inflated collateral cannot be recovered through liquidation. [12](#0-11) 

### Likelihood Explanation
No attacker action is needed to make the external anchor stale; the attacker only waits for the RedStone leg to lag while remaining inside its configured staleness window and for the market move to remain inside the configured price tolerance. [13](#0-12)  Production deployments deliberately allow long `Fundamental` staleness windows, including 46,800 seconds for XLM and 57,600 seconds for USDC. [14](#0-13) [15](#0-14)  Once that ordinary feed lag occurs, any unprivileged account can exploit it through normal `supply` and `borrow` calls. [16](#0-15) 

### Recommendation
Apply `MAX_LEG_AGE_SPREAD_SECONDS` to every two-source blend, not only pairs where both legs are `Market`, or otherwise reject a blended result whenever its leg timestamps differ by more than a bounded amount. [3](#0-2)  Alternatively, use only the fresh leg when one source is materially older, or return `PriceFeedStale` when the newest leg is older than the shortest configured source freshness bound. [17](#0-16)  Keep the per-source and aggregate staleness checks as additional bounds, but do not let a long `Fundamental` anchor window dilute a fresh market observation. [18](#0-17) 

### Proof of Concept
1. Configure a dual-source XLM oracle like production: fresh Reflector TWAP leg with `max_stale_seconds = 3600`, RedStone leg with `nature = Fundamental` and `max_stale_seconds = 46800`, and `upper_ratio_bps = 11000`. [19](#0-18) 
2. Set the Reflector observation to a fresh $0.91 while retaining a RedStone observation at $1.00 with a timestamp 46,000 seconds old. The stale leg is therefore within its configured limit, while the leg ratio is approximately 1.099 and remains below the 1.10 tolerance. [20](#0-19) [21](#0-20) 
3. As an unprivileged borrower, call `supply` with XLM collateral and then `borrow` for USDC. Resolution produces an approximately $0.955 midpoint rather than reverting because the `Fundamental` nature disables the cross-leg age-spread check. [22](#0-21) 
4. The repository’s regression scenario already encodes this result with a $1.00 frozen anchor, $0.91 fresh primary, 82,800-second anchor lag under an 86,400-second limit, and a successful 70,000 USDC borrow versus an `INSUFFICIENT_COLLATERAL` control. [23](#0-22) [11](#0-10) [12](#0-11)

        Legs::Partial { reading, slot } => Outcome::partial(reading, slot),

                primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market;
            let age_spread = primary.timestamp.abs_diff(anchor.timestamp);

                || anchor.stale
                || (spread_bounded && age_spread > MAX_LEG_AGE_SPREAD_SECONDS);
            let ts = primary.timestamp.min(anchor.timestamp);

                !within_tolerance_band(env, anchor.price_wad, primary.price_wad, &oracle.tolerance);

            let price_wad = midpoint_price_or_zero(anchor.price_wad, primary.price_wad);
            Outcome {
                price_wad,
                timestamp: ts,

                second_wad: anchor.price_wad,

    key: &PriceKey,

    source: &PriceSource,

        evaluate_source(session, key, source, oracle.asset_decimals, depth)?
    else {
        return Ok(None);
    };
    let timestamp = observation.timestamp;
    let stale = component_stale
        || is_stale(
            session.now_secs(),
            timestamp,
            oracle.max_price_stale_seconds,
        );
    Ok(Some(Reading {
        price_wad: observation.price_wad,
        timestamp,
        stale,
        nature: source_nature(source),
    }))
}

/// Returns whether the ratio `larger * BPS / smaller` of `anchor` and
/// `primary`, rounded half up, is at most `tolerance.upper_ratio_bps`
/// (`10_500` allows a 5% gap). Returns `false` when the smaller value is not
/// positive or the ratio overflows `i128`.
pub(crate) fn within_tolerance_band(
    env: &Env,
    anchor: i128,
    primary: i128,
    tolerance: &OracleTolerance,
) -> bool {
    let high = anchor.max(primary);
    let low = anchor.min(primary);
    let Some(upper_ratio_bps) = fp_core::try_mul_div_half_up(env, high, BPS, low) else {
        return false;
    };

    upper_ratio_bps <= i128::from(tolerance.upper_ratio_bps)
}

/// Returns the average of `anchor_price` and `primary_price`, truncated
/// toward zero. Returns `0` if the sum overflows `i128`.
pub(crate) fn midpoint_price_or_zero(anchor_price: i128, primary_price: i128) -> i128 {
    anchor_price
        .checked_add(primary_price)
        .map(|sum| sum / 2)
        .unwrap_or(0)
}

    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
