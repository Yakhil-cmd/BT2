This confirms `stack = scope.find_by(environment: "pr#{params.number}")` is scoped to `repository.review_stacks` where `repository` is resolved purely from `params.repository.full_name`, with no cross-check against `repository.owner.login` (the field used for signature verification).

### Title
Cross-tenant ReviewStack archival via divergent `repository.owner.login` vs `repository.full_name` fields in webhook payload - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the signing GitHub App/secret using `params.dig('repository','owner','login')`, while `ClosedHandler#repository` (and the other `PullRequest` handlers) resolve the target `Shipit::Repository` using `params.repository.full_name` split into owner/name. These are two independent, attacker-controlled fields in the same JSON body, so an attacker who legitimately owns a Shipit-onboarded organization/repository ("B") and knows its `webhook_secret` can sign a payload with `repository.owner.login = "B"` but `repository.full_name = "A/repoA"`, passing signature verification against B's secret while causing the handler to mutate Repository A's `ReviewStack`.

### Finding Description
The intended binding is: **organization whose `webhook_secret` verified the signature == organization owning the repository the handler mutates**, i.e. `repository_owner_used_for_signing == owner_segment_of(repository.full_name)`.

Trace:
- `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and calls `Shipit.github(organization: repository_owner)` to fetch the `GitHubApp` (and its `webhook_secret`) used to verify `X-Hub-Signature` [1](#0-0) .
- `WebhooksController#create` then forwards the *entire raw parsed JSON body* unmodified to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [2](#0-1) .
- `ClosedHandler#repository` resolves the target repository using a *different* field: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which splits `full_name` on `/` and does `find_by(owner:, name:)` [3](#0-2) , [4](#0-3) .
- `ClosedHandler#process` then calls `review_stack.archive!`, where `review_stack` is a `ReviewStackAdapter` scoped to `repository.review_stacks` (Repository A's stacks) and looks up the specific stack by `environment: "pr#{params.number}"` with no re-check against `repository.owner.login` [5](#0-4) , [6](#0-5) .

Nothing in `verify_signature`, `drop_unhandled_event`, the `ExplicitParameters` schema (which only requires `repository.full_name` to be a `String`, not that it agrees with `repository.owner.login`), or `ReviewStackAdapter` cross-validates these two fields.

Attacker's exact request: an admin of a Shipit-onboarded organization "orgB" (who legitimately knows their own `webhook_secret` because they configured the GitHub App/webhook for their own org, per the documented multi-org config schema in `docs/setup.md`/`config/secrets.development.shopify.yml`) sends `POST /webhooks` directly (not via GitHub) with `X-Github-Event: pull_request`, a body containing `action: "closed"`, `repository: { full_name: "orgA/repoA", owner: { login: "orgB" } }`, and an arbitrary `pull_request`/`number`/`sender` matching an existing ReviewStack `environment` on Repository A. The `X-Hub-Signature` is computed with orgB's own `webhook_secret` over this exact raw body.

`verify_signature` looks up `Shipit.github(organization: "orgB")`, validates against orgB's real secret → passes. `ClosedHandler` then resolves `Repository.from_github_repo_name("orga/repoa")` → Repository A, and archives Repository A's ReviewStack matching `pr#{number}`.

### Impact Explanation
An unprivileged-relative-to-Repository-A attacker (who only controls their own onboarded organization B) can force `Shipit::ReviewStack#archive!` on any `Repository` record known to Shipit by guessing/enumerating `full_name` and PR `number`/`environment`. This is a cross-repository/cross-tenant state mutation: the archival deprovisions and removes the review stack (`stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!`) for Repository A without B ever having any Shipit relationship with A. The same divergence affects `OpenedHandler`, `ReopenedHandler`, `LabeledHandler`, and `UnlabeledHandler`, all of which resolve `repository` the same way, so the attacker can also provision/unarchive/toggle Repository A's review stacks. This matches "a payload for one repository mutating another's stack" — Critical.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured for multiple GitHub organizations (the `github: { org: {...} }` schema documented in `docs/setup.md`), and the attacker must be a legitimate administrator of one onboarded organization who therefore knows that organization's `webhook_secret` (which they set up themselves per the standard onboarding flow). Given that, the attack requires zero interaction with GitHub itself — the attacker computes an HMAC over an arbitrary JSON body and POSTs it directly to `/webhooks`, no live GitHub webhook delivery is needed, and it is fully repeatable against any repository/PR number combination.

### Recommendation
In `WebhooksController#verify_signature` and/or the base `Handler`, ensure the organization used to select the signing key is the same organization that owns the resolved target `Repository`: e.g., resolve `Repository.from_github_repo_name(params.dig('repository','full_name'))` first, verify that its `owner` matches `repository_owner` (`params.dig('repository','owner','login')`), and reject (422) on mismatch, in addition to (or instead of) relying solely on `repository.owner.login` to pick the webhook secret.

```ruby

test "cross-org webhook cannot archive another organization's review stack" do
  # Repository A belongs to org "orga", has an existing ReviewStack with environment "pr7"
  repo_a = shipit_repositories(:shipit) # owner: 'shopify' or similar, acts as org A
  review_stack = create_review_stack_for(repo_a, environment: "pr7") # not yet archived

  # Attacker controls org "cyclimse" (configured with its own webhook_secret in test fixtures)
  payload = {
    action: "closed",
    number: 7,
    pull_request: { id: 1, number: 7, url: "u", title: "t", state: "closed",
                     additions: 1, deletions: 1,
                     head: { sha: "abc", ref: "some-branch" },
                     user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { full_name: repo_a.full_name, owner: { login: "cyclimse" } },
    sender: { login: "attacker" }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", cyclimse_webhook_secret, payload)

  @request.headers["X-Github-Event"] = "pull_request"
  @request.headers["X-Hub-Signature"] = signature

  refute review_stack.reload.archived?
  post :create, body: payload, as: :json
  assert_response :ok

  # BUG: Repository A's review stack got archived by a signature valid only for org "cyclimse"
  assert review_stack.reload.archived?
end
```
Both sides of the binding: **signing org ("cyclimse") == owner of mutated repository ("orga"/repo_a.owner)** are unequal before the request; the test demonstrates that `ClosedHandler` still mutates `repo_a`'s stack despite this inequality, proving the broken binding.
