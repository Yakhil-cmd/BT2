**Basis for rejection:**

1. **Premise is factually false.** `get_signers_weights` in `signer_set.rs` contains no `PRECISION`-based rounding whatsoever — it only reads pre-computed weights out of the `.signers` contract's `cycle-signer-set` map via `get-signers`, converting the Clarity tuple's `weight` field to `u64`. [1](#0-0)  A repo-wide grep confirms no `PRECISION` constant exists anywhere in `.rs` files; the term only appears in `pox-5.clar` (reward-accumulator math, unrelated to weight apportionment) and in TS test helpers. [2](#0-1) 

2. **The actual weight-assignment logic** lives in `pox_5_make_signer_set`, which aggregates stake **per signing key** (not per calling principal) before any division: entries are summed into a `HashMap` keyed by `entry.signer_key`. [3](#0-2)  If an attacker splits one large stake into many small `stake` calls but registers them all under the same signer key (the normal case), the amounts are combined before the floor/remainder computation, giving no gain at all.

3. **Even splitting across distinct signer keys is bounded**, not unbounded. The apportionment uses a largest-remainder (Hare) method: `threshold = total_ustx_locked.div_ceil(reward_slots)`, base weight = `floor(stacked/threshold)`, and at most one extra "leftover" unit is awarded per signer key, capped by `leftover = reward_slots - base <= reward_slots`. [4](#0-3)  Because floor is sub-additive (`floor(a)+floor(b) <= floor(a+b)`), summing floors over split pieces can only be ≤ the single-stake floor, and the leftover round can add at most one unit per new signer key created — so the maximum total weight obtainable by splitting a fixed amount of true stake `X` into any number of pieces is bounded by the same `ceil(X/threshold)` a single stake could already reach in the best case. This exact bound (`weight ∈ {base_weight, base_weight+1}` per entry, and `total_weight == base + min(leftover, n_signers)`) is asserted by the repo's own property tests. [5](#0-4) 

4. Consequently there is no way to make the sum of weights assigned across an attacker's principals for a cycle exceed `ceil(locked_STX / threshold)`, which is the same bound a single non-split stake is already subject to. The rounding error is a documented, tested, ≤1-unit-per-key artifact of the largest-remainder apportionment scheme, not an exploitable divergence between locked STX and granted signing weight.

No further code path, guard, or state transition needs to be traced because the premised mechanism (`PRECISION`-based rounding inside `get_signers_weights`) does not exist in the codebase, and the real mechanism (`pox_5_make_signer_set`'s Hare apportionment) is already bounded and verified by proptest invariants.

        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //

        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
