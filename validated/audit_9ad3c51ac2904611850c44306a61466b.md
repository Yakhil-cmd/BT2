### Title
Accrual can push a scaled market value past `i128::MAX`, permanently freezing the market - (File: common/src/rates/simulate.rs)

### Summary

Medium. A sufficiently large, high-utilization market can reach an index at which the next accrual calculates `scaled_balance * index` outside the `i128` domain and panics before the borrow-index cap can help. Because every market mutation accrues first, that market then rejects withdrawals, repayments, liquidation, and further index updates, permanently freezing all funds in it absent a privileged contract upgrade. [1](#0-0) [2](#0-1) 

### Finding Description

Each accrual step first converts total scaled debt and supply back to RAY asset values using the currently stored indexes through `scaled_to_original`. [3](#0-2) [4](#0-3)  That conversion calls `Ray::mul`, whose fixed-point multiply panics with `MathOverflow` when the result does not fit in `i128`. [5](#0-4) [6](#0-5) 

The borrow-index cap is applied only to `new_index` after accrual has already calculated the candidate index and then values the whole scaled debt at that candidate. [7](#0-6) [8](#0-7)  Consequently, the cap bounds the stored index but does not bound the intermediate `borrowed * new_borrow_index` or `supplied * supply_index` values.

The public `update_indexes` path calls `global_sync`, while `withdraw`, `repay`, borrow-side legs, supply-side legs, and liquidation settlement all load their market through `synced_market`/`load_leg`, which calls `global_sync` first. [9](#0-8) [2](#0-1)  Once the next positive accrual cannot produce a representable market value, each of these entry paths reverts before it can mutate the market.

The repository already contains a reproduction using one-billion whole 18-decimal-token supply and 98% utilization; it demonstrates `MathOverflow`, shows the borrow-index cap did not engage, and confirms that both withdrawal and repayment subsequently fail. [10](#0-9) 

### Impact Explanation

All suppliers in the affected market lose the ability to withdraw, borrowers cannot repay, and liquidators cannot seize collateral or clean the market because those operations must accrue first. [11](#0-10) [12](#0-11)  This is permanent freezing of user funds and can also leave protocol debt permanently unresolved unless governance upgrades the contract to recover the state. [13](#0-12) 

### Likelihood Explanation

The trigger requires a very large admitted market and sustained utilization high enough for interest to approach the representable-value boundary. [14](#0-13)  A single unprivileged address can nevertheless create the state using `supply` and `borrow` across accounts it owns, or can trigger `update_indexes` on an existing market that has naturally reached the boundary. [15](#0-14) [16](#0-15)  The substantial capital requirement and dependence on configured caps/rate curves reduce likelihood, but neither requires invalid authorization, leaked keys, malformed parameters, or privileged access.

### Recommendation

Enforce the full fixed-point domain at entry: before minting supply or debt shares, ensure the resulting scaled total multiplied by `MAX_SUPPLY_INDEX_RAY` or `MAX_BORROW_INDEX_RAY` remains below `i128::MAX`, using checked division such as `scaled <= i128::MAX / max_index`. [17](#0-16) [7](#0-6)  Accrual should additionally use non-panicking multiplication for market-value calculations and define a safe terminal behavior when the configured index cap is reached, rather than allowing every future market operation to revert. [18](#0-17) 

### Proof of Concept

An attacker controlling both accounts can reproduce the existing harness scenario:

```rust
let spoke_id = HARNESS_SPOKE;
let debt_asset = HubAssetKey { hub_id, asset: big18 };
let principal = 1_000_000_000i128 * 10i128.pow(18);
let debt = principal * 98 / 100;

controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(debt_asset.clone(), principal)],
);

let collateral_account = controller.supply(
    attacker,
    0,
    spoke_id,
    vec![(collateral_asset, sufficient_collateral)],
);

controller.borrow(
    attacker,
    collateral_account,
    vec![(debt_asset.clone(), debt)],
    Some(attacker),
);

// After utilization accrues to the representable-value boundary:
controller.update_indexes(attacker, vec![debt_asset.clone()]);
// Subsequently, every path that accrues this market reverts:
controller.withdraw(supplier, supplier_account, vec![(debt_asset.clone(), 1)], None);
controller.repay(attacker, collateral_account, vec![(debt_asset, 1)]);
```

The harness implementation supplies one billion `BIG18`, borrows 98%, advances accrual until `try_update_indexes_for(&["BIG18"])` returns `MathOverflow`, and then confirms that both `try_withdraw_raw` and `try_repay` fail with the same error. [19](#0-18)

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```
