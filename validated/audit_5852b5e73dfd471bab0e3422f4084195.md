### Title
Cross-tenant webhook forgery in `LabeledHandler` — signature validated against `repository.owner.login`'s org while stack resolution uses independent `repository.full_name` field, allowing an org-attacker-signed payload to `unarchive!`/`archive!` an org-victim `ReviewStack` — ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the verifying GitHub App/secret using `params.dig('repository','owner','login')`, while `LabeledHandler#repository` (and therefore `ReviewStackAdapter`'s `scope`) resolves the target repository from the independent field `params.repository.full_name` via `Repository.from_github_repo_name`. Nothing in the code enforces that these two attacker-supplied JSON fields refer to the same repository/organization, so a payload signed under org-attacker's (possibly blank) secret can name org-victim's repository and cause `stack.unarchive!`/`stack.archive!` to run against org-victim's real review stack.

### Finding Description
Binding claimed: `verifying_org == organization_owning(stack)`.

- `verifying_org` is computed as `params.dig('repository', 'owner', 'login')` (or `params.dig('organization','login')`) and used to select the GitHub App config: [1](#0-0) [2](#0-1) 
- `organization_owning(stack)` is computed independently, from `params.repository.full_name`, via `LabeledHandler#repository`: [3](#0-2) 
- The actual repository/stack lookup uses `Repository.from_github_repo_name`, a plain case-insensitive DB lookup on `owner`/`name` parsed from `full_name`, with no relation to the signing organization: [4](#0-3) 
- `stack` is then resolved as `repository.review_stacks.find_by(environment: "pr#{params.number}")` through `ReviewStackAdapter`, and `handle` calls `stack.archive!`/`stack.unarchive!` based on label/behavior logic: [5](#0-4) [6](#0-5) 

Because `owner.login` and `full_name` are two separate, attacker-controlled fields inside a raw JSON body POSTed to `/webhooks` (an explicitly in-scope attacker capability), there is no cross-check that `full_name.split('/').first == owner.login`. `verify_signature` only proves that the payload was signed with the secret configured for whatever organization name the attacker put in `owner.login` — it says nothing about the repository named in `full_name`. Additionally, `GitHubApp#verify_webhook_signature` unconditionally returns `true` when `webhook_secret` is blank for that org's config: [7](#0-6) , which further lowers the bar if org-attacker's configured secret is blank (a documented/sample default: [8](#0-7) ).

Exploit flow: attacker (who owns/controls org-attacker, onboarded in Shipit) crafts a JSON body with `action: "labeled"`, `repository.owner.login: "org-attacker"`, `repository.full_name: "org-victim/repo"`, `pull_request.number` matching an existing archived `ReviewStack` environment (`pr<number>`) for org-victim, and appropriate label state to satisfy `unarchive?`. They compute/obtain a valid `X-Hub-Signature` for org-attacker's secret (or rely on it being blank) and POST directly to `/webhooks`. `verify_signature` passes because it only validates against org-attacker's app config. `LabeledHandler#process` then resolves org-victim's real `Repository`/`ReviewStack` via `full_name` and calls `stack.unarchive!`, mutating org-victim's stack state. `Shipit::ContinuousDeliveryJob#perform` (queued/periodic) will subsequently observe `stack.continuous_deployment?` and `!stack.occupied?` and may trigger a real deploy on the now-unarchived victim stack: [9](#0-8) .

No existing guard prevents this: `drop_unhandled_event`/`check_if_ping` only gate on event type; the `ExplicitParameters` schema only enforces field presence/types, not cross-field consistency; `Repository` validations only constrain owner/name character sets, not consistency with the signing org.

### Impact Explanation
An attacker who controls any org onboarded in Shipit (or any org with a blank `webhook_secret`) can force state changes (`archive!`/`unarchive!`) on an arbitrary victim organization's existing review stack purely by naming it in the `repository.full_name` field of a forged `/webhooks` POST. This is a "payload for one repository mutating another's stack" — explicitly Critical per the rules. `unarchive!` re-enables provisioning and, combined with `ContinuousDeliveryJob`, can result in an unauthorized deploy being triggered against the victim's infrastructure. The attack is repeatable against any repository/stack whose owner/name and PR-derived environment (`pr<number>`) the attacker can guess or observe (trivial for public repos).

### Likelihood Explanation
Preconditions: attacker needs (a) the ability to send a correctly-signed webhook for *some* organization configured in Shipit — achievable either by owning a legitimately onboarded org (triggerable through normal GitHub actions like labeling their own PR) or by exploiting a blank `webhook_secret` config, and (b) knowledge of the victim's existing `ReviewStack` `full_name`/PR number, both discoverable for public repositories. No Shipit session, API token, or GitHub secret is required beyond what the attacker already legitimately has for their own org. This is a low-cost, fully repeatable, unauthenticated (with respect to the victim) attack.

### Recommendation
In `WebhooksController#verify_signature`, after determining `repository_owner`, also derive the owner encoded in `params.dig('repository','full_name')` and reject the request (422) unless they match. Alternatively, have all handlers (including `LabeledHandler`, `ReviewStackAdapter`, and siblings using `from_github_repo_name`) validate that the resolved `Repository#owner` equals the verified `repository_owner` captured by the controller (e.g., pass it down and assert equality before performing any `archive!`/`unarchive!`/`create!` mutation).

### Proof of Concept
Add a controller-level minitest in `test/controllers/webhooks_controller_test.rb` style (or as a `LabeledHandler`/`ReviewStackAdapter` unit test), asserting the binding explicitly:

```ruby
test "labeled webhook signed for org-attacker cannot mutate org-victim's stack" do
  victim_repo = shipit_repositories(:shipit) # owner "shopify", already onboarded
  victim_stack = create_archived_stack(repository: victim_repo) # environment "pr123"

  # Attacker owns/controls "org-attacker" in Shipit's github config (or it has a blank secret)
  attacker_org = "org-attacker"

  payload = {
    "action" => "labeled",
    "number" => 123,
    "pull_request" => {
      "id" => 1, "number" => 123, "url" => "https://api.github.com/x",
      "title" => "t", "state" => "open", "additions" => 1, "deletions" => 1,
      "head" => { "sha" => "abc", "ref" => "feature" },
      "user" => { "login" => "attacker" },
      "assignees" => [],
      "labels" => [{ "name" => "pull-requests-label" }]
    },
    # verifying_org: signature computed/accepted for attacker_org
    "repository" => { "full_name" => "#{victim_repo.owner}/#{victim_repo.name}", "owner" => { "login" => attacker_org } },
    "sender" => { "login" => "attacker" }
  }.to_json

  # binding under test, BEFORE:
  assert_not_equal attacker_org, victim_repo.owner # verifying_org != organization_owning(stack)

  request.headers['X-Github-Event'] = 'pull_request'
  # signature computed with attacker_org's own (known/blank) secret
  request.headers['X-Hub-Signature'] = attacker_signature_for(attacker_org, payload)

  assert_changes -> { victim_stack.reload.archived? }, from: true, to: false do
    post :create, body: payload, as: :json
  end

  # binding still broken AFTER: request verified under attacker_org, yet victim_repo's stack was mutated
  assert_not_equal attacker_org, victim_repo.owner
end
```

This demonstrates that `verify_signature` accepts the request under `attacker_org`'s configuration while `LabeledHandler`/`ReviewStackAdapter` executes `stack.unarchive!` against `org-victim`'s real, pre-existing `ReviewStack`, proving the two organization identifiers are never reconciled.

            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
