### Title
Cross-repository stack read via `Stack.from_param!` bypassing `current_api_client.stack_id` scope - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Api::CCMenuController#stack` is defined as `Stack.from_param!(params[:stack_id])`, which resolves any stack in the entire Shipit instance by `owner/repo/environment` string, ignoring the `current_api_client.stack_id` scoping that `Api::BaseController` normally enforces for all other API controllers. Any token with `read:stack` permission — even one created via `CCMenuUrlController` and scoped to a single stack — can be used to read the CCMenu XML status of any stack in the instance by guessing/knowing its `owner/repo/environment` triple.

### Finding Description
The broken binding is: `repository_named_in_stack_id_param.authorized_for(current_api_client)` should equal `current_api_client.stack_id == resolved_stack.id` (or `stack_id.nil?`), but it is never checked.

`Api::BaseController` defines the correctly scoped accessor: [1](#0-0) 
`stacks` restricts the resolvable set to `Stack.where(id: current_api_client.stack_id)` when the client is scoped to a single stack, and `stack` calls `stacks.from_param!`.

`Api::CCMenuController` overrides this with its own private `stack` method that calls the bare model method instead: [2](#0-1) 
`Stack.from_param!` has no notion of the calling client at all — it simply looks up by owner/name/environment strings across the whole `stacks` table: [3](#0-2) 

Permission enforcement (`require_permission :read, :stack` → `check_permissions!`) only checks the token's permission *strings* (e.g. `read:stack`), not which stack it's bound to: [4](#0-3) 
So a token created with `stack_id` pinned to stack A (e.g. via `CCMenuUrlController#client`, which creates a `read:stack`-only `ApiClient` bound to one stack) still passes `check_permissions!` when used against stack B's CCMenu URL, because nothing compares `current_api_client.stack_id` to the resolved stack's id in this controller.

Attack: an attacker who obtains/guesses any valid `read:stack` token issued for repository A (e.g. leaked/shared CCMenu URL for a public/permitted repo) requests `GET /api/stacks/{private_owner}/{private_repo}/{environment}/ccmenu?token=<tokenForA>`. `Stack.from_param!` resolves the private stack regardless of the token's `stack_id`, and the controller renders its CCMenu XML (build status, activity, last build label/time, web URL) for a repository the attacker/token was never authorized against.

### Impact Explanation
The response leaks stack existence and build/deploy status (`lastBuildStatus`, `activity`, `lastBuildTime`, `lastBuildLabel`, `webUrl`) for any stack in the Shipit instance, to a holder of any `read:stack`-scoped token, regardless of which repository that token was actually issued for. This is unauthenticated-relative-to-target-repo read of stack state, matching the High severity category ("unauthenticated read of stack state"). It requires only guessing/knowing `owner/repo/environment` and is repeatable against every stack in the instance with a single valid token.

### Likelihood Explanation
Preconditions: the attacker must possess *some* valid `read:stack` API token (these are routinely generated per-stack via the "Fetch URL" CCMenu button visible to any user with dashboard access, per `CCMenuUrlController`), and know/guess the target stack's `owner/repo/environment` triple, which is often public or predictable GitHub repo naming. No GitHub permission on the target repo is needed, and no Shipit operator privilege. This is low-cost and fully repeatable.

### Recommendation
Change `Api::CCMenuController#stack` to use the scoped accessor from `BaseController` instead of the raw model method, i.e. remove the private `stack` override (or redefine it as `stacks.from_param!(params[:stack_id])`) so that clients pinned via `stack_id` cannot resolve stacks outside their scope.

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb
test "a token scoped to one stack cannot read another stack's ccmenu via cross-repo stack_id" do
  public_repo = Repository.create!(owner: 'acme', name: 'public-repo')
  public_stack = Stack.create!(repository: public_repo, environment: 'production')

  private_repo = Repository.create!(owner: 'acme', name: 'private-repo')
  private_stack = Stack.create!(repository: private_repo, environment: 'production')

  scoped_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: 'scoped',
    stack: public_stack,
    permissions: ['read:stack']
  )

  get :show, params: { stack_id: private_stack.to_param, token: scoped_client.authentication_token }

  # Binding under test: current_api_client.stack_id (public_stack.id)
  # must equal resolved stack.id (private_stack.id) for access to be granted.
  assert_not_equal scoped_client.stack_id, private_stack.id
  assert_response :not_found # EXPECTED after fix; currently returns :ok leaking private_stack's XML
end
```
