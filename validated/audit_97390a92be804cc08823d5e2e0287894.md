### Title
Stale Votes from Deregistered Bridge Operators Count Toward Quorum, Enabling Unauthorized Value Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator` removes an operator from the active set but does not clear that operator's outstanding votes from `VotesData.voteCounts`. When a subsequent active operator votes on the same nonce, the stale vote from the deregistered operator is counted, causing the threshold check to pass with fewer active operators than the configured threshold requires. This can trigger unauthorized `handleKLAYTransfer`, `handleERC20Transfer`, or `handleERC721Transfer` executions.

### Finding Description

`BridgeOperator` tracks per-nonce vote state in a `VotesData` struct:

```solidity
struct VotesData {
    address[] voters;
    mapping(address => bytes32) voted;
    bytes32[] voteKeys;
    mapping(bytes32 => uint8) voteCounts;
}
```

The quorum check in `_voteCommon` is:

```solidity
if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
    return true;
}
``` [1](#0-0) 

This check only compares the raw accumulated count against the threshold. It does not verify that each counted vote came from an address that is still in `operators` at the time of resolution.

`deregisterOperator` removes the operator from `operators` and `operatorList`, but leaves `vote.voted[operator]` and `vote.voteCounts[voteKey]` untouched for all open nonces:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    delete operators[_operator];
    // operatorList swap-and-pop ...
    // vote state for all open nonces is NOT cleared
}
``` [2](#0-1) 

The contract's own NatSpec comment acknowledges this explicitly:

> "Note that outstanding votes by the deregistered operator are not revoked. This enables a subtle counterintuitive scenario." [3](#0-2) 

### Impact Explanation

The broken invariant is: *only votes from currently active operators should count toward the threshold for executing a value transfer*.

When the invariant is violated, `_voteValueTransfer` returns `true` and the handle functions proceed to transfer assets:

- `handleKLAYTransfer` sends native KAIA via `_to.call.value(_value)("")`
- `handleERC20Transfer` mints or transfers ERC20 tokens
- `handleERC721Transfer` mints or transfers ERC721 tokens [4](#0-3) [5](#0-4) 

The result is an unauthorized cross-chain asset transfer: bridged KAIA, ERC20, or ERC721 tokens are released on the destination chain with fewer active-operator approvals than the threshold mandates.

### Likelihood Explanation

The scenario is reachable whenever:
1. An operator votes on a pending nonce (normal operation).
2. The bridge owner deregisters that operator (e.g., key rotation, compromise response).
3. Any remaining active operator votes on the same nonce.

Step 3 is performed by a legitimately active operator following normal bridge operation. No attacker capability beyond being a registered operator is required to cast the triggering vote. The deregistered operator's stale vote persists indefinitely in contract storage across all open nonces.

### Recommendation

In `deregisterOperator`, iterate over all open (non-closed) nonces for both `VoteType.ValueTransfer` and `VoteType.Configuration` and subtract the deregistered operator's vote count from `voteCounts` (and clear `voted[_operator]`). Alternatively, at quorum-check time in `_voteCommon`, filter `voters` to only count addresses for which `operators[voter]` is still `true`.

### Proof of Concept

Setup: operators = {A, B, C}, threshold = 2.

1. Operator A calls `handleKLAYTransfer(..., nonce=7, ...)` → `_voteCommon` records `voted[A] = voteKey`, `voteCounts[voteKey] = 1`. Threshold not yet met.
2. Owner calls `deregisterOperator(A)` → `operators[A]` deleted, `operatorList` updated. `voteCounts[voteKey]` remains `1`.
3. Operator B calls `handleKLAYTransfer(..., nonce=7, ...)` → `_voteCommon` increments `voteCounts[voteKey]` to `2`. Check: `2 >= 2` → returns `true`.
4. `closedValueTransferVotes[7] = true`, KAIA transferred to recipient.

The transfer executed with only one currently-active operator approval (B), while the threshold was intended to require two active operators. A's authority was revoked but its vote was not. [6](#0-5) [7](#0-6)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }
```

    // deregisterOperator deregisters the operator.
    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
