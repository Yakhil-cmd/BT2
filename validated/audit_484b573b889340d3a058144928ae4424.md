### Title
Premature bad-debt socialization due to using the liquidation-penalty upper bound (`LIQ-PENALTY-MAX`) instead of the borrower's actual graduated penalty when deciding if remaining collateral can still cover debt - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
In `liquidate`, the decision of whether a borrower's position has "no collateral left" (which triggers bad-debt socialization onto all vault suppliers) is computed using the *bound* `liq-penalty-max`, not the *actual* graduated `liq-penalty` that was computed and applied to the collateral asset actually being liquidated. This mirrors the M-13 root cause: a boundary/limit value is substituted for the value that should have been derived as the real computation target, producing an incorrect result that a third, uninvolved party (vault depositors) bears the cost of.

### Finding Description
Inside `liquidate`, the protocol first computes the *graduated* liquidation penalty for the current LTV via `calc-liquidation-params` → `calc-liq-factor-bound`, which interpolates between `liq-penalty-min` and `liq-penalty-max` based on how deep into the liquidation curve the position is: [1](#0-0) 

This `liq-penalty` value is the one actually applied to compute how much collateral is seized for the debt asset being processed in this call: [2](#0-1) 

However, when the function later decides whether the borrower has any *other* repayable collateral left (to decide if the remaining debt should be socialized to all suppliers instead of liquidated normally), it recomputes a hypothetical "other-debt-repayable" amount using `liq-penalty-max` — the static upper bound configured for the egroup — instead of the dynamically computed `liq-penalty` for the position's actual LTV: [3](#0-2) [4](#0-3) 

Because `liq-penalty-max >= liq-penalty` in every graduated (non-fully-liquidated) case, dividing `other-coll-usd` by `(BPS + liq-penalty-max)` systematically understates the debt that the borrower's remaining collateral could actually cover compared to using the correct, lower `liq-penalty`. This bias pushes `other-debt-repayable` toward `u0` more often than it should, which flips `no-collateral-left` to `true` and triggers `socialize-debt-asset`, spreading the borrower's still-coverable debt onto every vault supplier via `vault-socialize-debt`: [5](#0-4) 

### Impact Explanation
This is exactly the class of harm the rules single out as in-scope: "a socialization charged to all suppliers." The attacker/trigger (a liquidator submitting a `liquidate` call, or simply the borrower's position crossing the partial-liquidation curve) causes debt that is realistically still collateralized to instead be socialized across the entire supplier base of the debt vault, diluting all depositors' shares (temporary/permanent freezing or loss of supplied yield/principal for uninvolved LPs) — a distinct unprivileged party from the caller.

### Likelihood Explanation
This triggers any time a graduated liquidation (`liq-pct-scaled < BPS`, i.e., `liq-penalty < liq-penalty-max`) leaves a borrower with a second collateral asset whose USD value, when discounted by the (incorrectly conservative) `liq-penalty-max` rather than the true `liq-penalty`, rounds down to zero debt tokens even though it is non-zero when discounted correctly. This is a realistic, not merely theoretical, edge case for small remaining collateral balances near the graduated-liquidation zone, which is precisely the target scenario for the "graduated" liquidation design.

### Recommendation
Use the dynamically computed `liq-penalty` (the same value used to size `coll-usd-expected` for the primary collateral) — not the static `liq-penalty-max` bound — when computing `other-debt-repayable`, so the "no collateral left" determination reflects the same economic terms that were actually applied to the borrower's position.

### Proof of Concept
1. Configure an egroup with `LIQ-PENALTY-MIN` and `LIQ-PENALTY-MAX` sufficiently far apart (e.g., 500 bps vs 1500 bps).
2. Set up a borrower with two collateral assets and one debt asset such that the position sits in the graduated zone (`liq-pct-scaled` well below `BPS`), so the effective `liq-penalty` applied is much closer to `liq-penalty-min`.
3. Size the second ("other") collateral asset so that `(other-coll-usd * BPS) / (BPS + liq-penalty)` (correct) is non-zero in `debt-decimals` token units, but `(other-coll-usd * BPS) / (BPS + liq-penalty-max)` (as currently coded) rounds to zero.
4. Call `liquidate` on the first collateral/debt pair; observe `other-debt-repayable` evaluates to `u0`, `no-collateral-left` becomes `true`, and the remaining debt for the second collateral asset is socialized via `socialize-debt-asset` even though it was economically still coverable by the borrower's second collateral asset.

;; Scale penalty between min and max using liquidation factor
;; liq-penalty = liq-penalty-min + (liq-factor * (liq-penalty-max - liq-penalty-min) / BPS)
;; Capped at bound-max to handle cases where liq-factor > BPS
(define-private (calc-liq-factor-bound (liq-factor uint) (bound-min uint) (bound-max uint))
  (min bound-max (+ bound-min (mul-bps-down liq-factor (- bound-max bound-min)))))

;; Calculate debt to repay based on liquidation factor
;; debt-repay = liq-factor * debt / BPS
(define-private (calc-liq-debt-repay (debt uint) (liq-factor uint)) 
  (mul-bps-down liq-factor debt))

;; Calculate collateral to seize (includes liquidator bonus)
;; collateral-repay = debt-repay * (BPS + liq-penalty) / BPS
(define-private (calc-liq-collateral-repay (debt-repay uint) (liq-penalty uint)) 
  (mul-bps-down debt-repay (+ BPS liq-penalty)))

;; Calculate actual debt repayment when collateral is capped
;; debt-repay-real = (collateral-amount-usd * BPS) / (BPS + liq-penalty)
(define-private (calc-liq-debt-repay-real (collateral-amount-usd uint) (liq-penalty uint)) 
  (div-bps-down collateral-amount-usd (+ BPS liq-penalty)))

;; Graduated liquidation parameter calculation

  (current-ltv uint)
  (ltv-liq-partial uint)
  (ltv-liq-full uint)
  (liq-penalty-min uint)
  (liq-penalty-max uint)
  (curve-exponent uint)
  (total-debt-usd uint))
  
  (let ((liq-pct-linear (calc-liq-factor current-ltv ltv-liq-partial ltv-liq-full))

        (max-debt-usd (calc-liq-debt-repay total-debt-usd liq-pct-scaled)))
    {
      liq-pct-scaled: liq-pct-scaled,
      liq-penalty: liq-penalty,
