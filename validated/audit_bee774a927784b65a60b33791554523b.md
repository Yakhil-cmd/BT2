Confirming the key finding: `verify-l1-lockups`/`validate-l1-lockup` in `pox-5.clar` only dedups Bitcoin outpoints *within a single call* (via the `seen-outpoints` accumulator built fresh on each invocation) — there is no persistent, contract-level map recording L1 outpoints already credited by a prior `register-for-bond` call.

### Title
Reusable Bitcoin L1 lockup proof lets a staker double-credit the same on-chain BTC lock across multiple bond registrations - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`register-for-bond` accepts an `(ok { outputs, staker-unlock-bytes })` L1 proof branch, whose sats total is computed by `verify-l1-lockups` → `validate-l1-lockup` [1](#0-0) . `validate-l1-lockup` checks the header, script, amount, merkle proof, and unlock height for each output, and rejects duplicate outpoints only via a `seen-outpoints` list that is initialized empty at the start of *each* `verify-l1-lockups` call [2](#0-1) [3](#0-2) . Nothing in the contract records that a given `(txid, output-index)` was already consumed by a prior transaction.

### Finding Description
The dedup structure `seen-outpoints` lives entirely inside the `fold` accumulator of one `verify-l1-lockups` call [4](#0-3) . There is no `define-map` persisting used L1 lockup outpoints across calls (confirmed by the absence of any such map in `pox-5.clar`). The only cross-call state gate is `ERR_ALREADY_REGISTERED`/`bond-overlaps-new-position?`, which is keyed on the *staker's own* current membership, not on the underlying BTC outpoint [5](#0-4) .

This means the same real Bitcoin timelock UTXO (one genuine BTC lockup) can be cited as proof in `register-for-bond` calls from two different Stacks principals (or once a bond ends/rolls over, from the same principal into a fresh bond), each minting an independent `protocol-bond-memberships` entry and its own STX lock via the pox-locking `pox_lock_v5`/`pox_rollover_v5` path [6](#0-5) . Each registration is a self-consistent Clarity-level proof (correct script, correct merkle proof, valid header) yet the L1 sats variable feeds `min-ustx-for-sats-amount`, `add-staker-to-bond-cycles`, and the total-staked accounting [7](#0-6) , so the same BTC collateral is counted as backing multiple bonds/signer allocations simultaneously — breaking the equality "sats credited by an L1 proof == sats actually locked on Bitcoin, once."

### Impact Explanation
This double-counts a single BTC commitment into multiple Stacks-side bond memberships, each of which locks independent STX and earns independent signer/staker sBTC rewards and reward-cycle shares. That is unbacked/duplicated stake backing (the L1 collateral is not fungible across N registrations) and inflates reward-slot allocation for the colluding registrants beyond what is actually secured by locked Bitcoin — matching the in-scope "sats credited by an L1 proof that were never locked on Bitcoin" / "double-counting a commitment" class, at Critical severity under the given rubric (double-counting a commitment / unbacked reward eligibility).

### Likelihood Explanation
Exploitation requires only an unprivileged account (any allowlisted staker) resubmitting the same publicly-visible on-chain lockup transaction bytes/proof to `register-for-bond` — no admin, signer, or miner privilege is needed, and the proof data (raw tx, merkle path, header) is public once the original lockup confirms on Bitcoin. The main constraint is the allowlist gate (`protocol-bond-allowances`) and the "not-yet-a-bond-member" check, both of which are per-Stacks-principal, not per-BTC-outpoint, so a single BTC lockup can be replayed by any number of distinct allowlisted principals, or by the same principal into successive bonds after each one's membership is cleared.

### Recommendation
Add a persistent map (e.g., `used-l1-lockup-outpoints: {txid, output-index} -> bool`) checked and set inside `validate-l1-lockup`, so once an outpoint has backed a `register-for-bond` call it can never be credited again in any future call, mirroring the intra-call `seen-outpoints` guard but scoped contract-wide and permanent.

### Proof of Concept
1. Staker A locks `sats` BTC into the canonical P2WSH timelock script committed to Staker A's principal (as built by `construct-lockup-output-script`) and waits for confirmation.
2. Staker A calls `register-for-bond(bond-index, signerA, amountUstxA, (ok {outputs:[proof], staker-unlock-bytes}), none)` — this succeeds, locks `amountUstxA` STX, and custodies the sats claim for bond membership A.
3. A second allowlisted principal, Staker B (or Staker A again after the first bond's term rolls over/clears), submits `register-for-bond` with the *same* `outputs:[proof]` tuple (identical `tx`, `header`, `output-index`, merkle data) but their own `amount-ustx`. `validate-l1-lockup`'s checks (script match, header match, amount match, merkle proof, `seen-outpoints` dedup) all pass because `seen-outpoints` is empty at the start of this new, independent call.
4. `register-for-bond` succeeds again, creating a second `protocol-bond-memberships` entry and locking additional STX, backed by the same already-cited Bitcoin lockup — no contract-side state prevents reuse across the two separate transactions.

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)

fn handle_lockup_pox_v5(
    global_context: &mut GlobalContext,
    function_name: &str,
    value: &Value,
) -> Result<Option<StacksTransactionEvent>, VmExecutionError> {
    debug!(
        "Handle special-case contract-call to {:?} {function_name} (which returned {value:?})",
        boot_code_id(POX_5_NAME, global_context.mainnet)
    );
    runtime_cost(
        ClarityCostFunction::StxTransfer,
        &mut global_context.cost_track,
        1,
    )?;

    let parsed = parse_pox_stake_result(value).map_err(|e| {
        locking_error_to_vm_error(e, &format!("pox-5 {function_name}: bad response"))
    })?;
    let (staker, locked_amount, unlock_height) = match parsed {
        ParsedStakeResult::Ok {
            staker,
            amount_ustx,
            unlock_burn_height,
        } => (staker, amount_ustx, unlock_burn_height),
        ParsedStakeResult::ContractErr => return Ok(None),
    };

    // A staker rolling from one bond/stake position into another is already
    // locked; carry the lock forward instead of acquiring a fresh one (which
    // would fail with `PoxAlreadyLocked`). A first-time call locks fresh.
    let already_locked = {
        let mut snapshot = global_context.database.get_stx_balance_snapshot(&staker)?;
        snapshot.has_locked_tokens()?
    };

    let lock_result = if already_locked {
        pox_rollover_v5(
            &mut global_context.database,
            &staker,
            unlock_height,
            locked_amount,
        )
        .map(|_| ())
    } else {
        pox_lock_v5(
            &mut global_context.database,
            &staker,
            locked_amount,
            unlock_height,
        )
    };
