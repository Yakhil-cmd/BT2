Based on my investigation of `substrate/frame/people/src/lib.rs`, I found a real analog to the CVE's pattern — an unprivileged user binding a resource "on behalf of" another user's namespace without proving ownership, causing unwanted state changes and a targeted denial of service.

### Title
Unauthorized binding of arbitrary `AccountId`s to another person's alias/identity via `set_alias_account`/`set_personal_id_account` - (File: substrate/frame/people/src/lib.rs)

### Summary
`pallet-people`'s `set_alias_account` and `set_personal_id_account` extrinsics let any already-recognized "person" (an unprivileged, non-governance role — anyone who has proven personhood) bind an **arbitrary** `T::AccountId` chosen by the caller to their own `PersonalAlias`/`PersonalId`, without any proof that the caller controls the private key of that account. The only checks performed are that the target account is not *already* bound elsewhere [1](#0-0) , [2](#0-1) . This mirrors CVE-2017-18270's invariant violation: a local, unprivileged actor creates/mutates a namespaced resource ("keyring"/mapping) that belongs to another user, setting unwanted defaults and causing denial of service for the legitimate owner.

### Finding Description
`set_alias_account(origin, account, call_valid_at)` derives the caller's `RevisedContextualAlias` from their own proven personhood (`Self::ensure_revised_personal_alias(origin)`), then inserts a mapping from the **caller-supplied** `account` parameter into that alias, and increments `sufficients` on that account: [3](#0-2) 

The only guard preventing arbitrary victim selection is that the target account must not already be present in `AccountToPersonalId` or `AccountToAlias`: [1](#0-0) [4](#0-3) 

There is no signature/ownership check binding `account` to the caller — no `T::OffchainSignature` verification akin to `pallet-identity::set_username_for`'s optional signature acceptance path. The identical pattern exists in `set_personal_id_account`: [5](#0-4) 

Consequences for the victim (an ordinary user who never opted in):
- `frame_system::Pallet::<T>::inc_sufficients(&account)` is applied to the victim's account without consent [6](#0-5) , [7](#0-6) .
- `AccountToAlias`/`AccountToPersonalId` now map the victim's account to the attacker's identity, permanently (until the attacker, not the victim, calls `unset_alias_account`/`unset_personal_id_account`) [8](#0-7) .
- If the victim later legitimately proves personhood and tries to register that same account via `set_alias_account` or `set_personal_id_account`, they are rejected with `Error::AccountInUse` [9](#0-8) , [10](#0-9)  — a deterministic denial of service on that specific account until the attacker releases the binding.
- The doc-comment confirms the intended usage is that this binding lets the *bound account* dispatch calls as that alias via `under_alias`/`AsPersonalAliasWithAccount` [11](#0-10) , [12](#0-11)  — i.e., the design assumes the bound account belongs to the alias owner, which is never verified.

### Impact Explanation
This is a state-integrity break, not a fund-theft or issuance bug: an unprivileged, non-governance actor can unilaterally pollute another arbitrary account's `sufficients` counter and register/lock the People-pallet account-binding namespace for a victim account without consent, deterministically blocking that specific account from being used for personhood/alias registration (`AccountInUse`) until the attacker (not the victim) reverses it. This matches the CVE's "setting unwanted defaults or causing denial of service" bug class but is scoped to the People pallet's own account-binding feature rather than consensus-critical balances/issuance.

### Likelihood Explanation
Reachable via a normal signed extrinsic once an attacker has proven personhood through the pallet's ordinary (non-governance) recognition flow; no privileged role, stolen key, or malicious relayer/validator is required — only knowledge of the target victim's public `AccountId`, which is always public. The precondition ("account not already bound") is trivially satisfiable for essentially any account that hasn't opted into the People pallet yet.

### Recommendation
Require the `account` parameter to prove ownership, e.g. by requiring `account` to co-sign the binding (similar to the `signature: Option<T::OffchainSignature>` acceptance path in `pallet-identity::set_username_for`), or by requiring `account` itself to submit/accept the binding (pending-acceptance queue analogous to `PendingUsernames`) rather than allowing the alias/identity owner to unilaterally claim an arbitrary account.

### Proof of Concept
Failed guard: `set_alias_account`/`set_personal_id_account` never verify that the caller controls the private key of `account`; they only check `AccountToPersonalId`/`AccountToAlias` non-membership [1](#0-0) , [10](#0-9) . A minimal integration test analogous to the existing `substrate/frame/people/src/tests.rs::test_set_personal_id_account` [13](#0-12)  would: (1) recognize an attacker as a person; (2) call `set_personal_id_account`/`set_alias_account` with `account` set to a victim's address that has never interacted with the People pallet; (3) assert `AccountToPersonalId::get(victim) == Some(attacker_id)` and `sufficients(victim) == 1`, both without any action/signature from the victim; (4) assert that a subsequent call by the real victim (after being recognized as a person) to bind the same account fails with `Error::AccountInUse`. I did not execute this PoC against a live network; the above is derived purely from static code inspection of the guards present in the dispatchables, and no test run was performed.

		#[pallet::call_index(1)]
		pub fn set_alias_account(
			origin: OriginFor<T>,
			account: T::AccountId,
			call_valid_at: BlockNumberFor<T>,
		) -> DispatchResultWithPostInfo {
			let rev_ca = Self::ensure_revised_personal_alias(origin)?;
			let now = frame_system::Pallet::<T>::block_number();
			let time_tolerance = Self::account_setup_time_tolerance();
			ensure!(
				call_valid_at <= now && now <= call_valid_at.saturating_add(time_tolerance),
				Error::<T>::TimeOutOfRange
			);
			ensure!(T::AccountContexts::contains(&rev_ca.ca.context), Error::<T>::InvalidContext);
			ensure!(!AccountToPersonalId::<T>::contains_key(&account), Error::<T>::AccountInUse);

			let old_account = AliasToAccount::<T>::get(&rev_ca.ca);
			let old_rev_ca = old_account.as_ref().and_then(AccountToAlias::<T>::get);

			let needs_revision = old_rev_ca.is_some_and(|old_rev_ca| {
				old_rev_ca.revision != rev_ca.revision || old_rev_ca.ring != rev_ca.ring
			});

			// Ensure it changes the account associated, or it needs revision.
			ensure!(
				old_account.as_ref() != Some(&account) || needs_revision,
				Error::<T>::AliasAccountAlreadySet
			);

			// If the old account is different from the new one:
			// * decrease the sufficients of the old account
			// * increase the sufficients of the new account
			// * check new account is not already in use
			if old_account.as_ref() != Some(&account) {
				ensure!(!AccountToAlias::<T>::contains_key(&account), Error::<T>::AccountInUse);
				if let Some(old_account) = &old_account {
					frame_system::Pallet::<T>::dec_sufficients(old_account);
					AccountToAlias::<T>::remove(old_account);
				}
				frame_system::Pallet::<T>::inc_sufficients(&account);
			}

			AccountToAlias::<T>::insert(&account, &rev_ca);
			AliasToAccount::<T>::insert(&rev_ca.ca, &account);

			if old_account.is_none() || needs_revision {
				Ok(Pays::No.into())
			} else {
				Ok(Pays::Yes.into())
			}
		}

		#[pallet::call_index(4)]
		pub fn set_personal_id_account(
			origin: OriginFor<T>,
			account: T::AccountId,
			call_valid_at: BlockNumberFor<T>,
		) -> DispatchResultWithPostInfo {
			let id = Self::ensure_personal_identity(origin)?;
			let now = frame_system::Pallet::<T>::block_number();
			let time_tolerance = Self::account_setup_time_tolerance();
			ensure!(
				call_valid_at <= now && now <= call_valid_at.saturating_add(time_tolerance),
				Error::<T>::TimeOutOfRange
			);
			ensure!(!AccountToPersonalId::<T>::contains_key(&account), Error::<T>::AccountInUse);
			ensure!(!AccountToAlias::<T>::contains_key(&account), Error::<T>::AccountInUse);
			let mut record = People::<T>::get(id).ok_or(Error::<T>::NotPerson)?;
			let pays = if let Some(old_account) = record.account {
				frame_system::Pallet::<T>::dec_sufficients(&old_account);
				AccountToPersonalId::<T>::remove(&old_account);
				Pays::Yes
			} else {
				Pays::No
			};
			record.account = Some(account.clone());
			frame_system::Pallet::<T>::inc_sufficients(&account);
			AccountToPersonalId::<T>::insert(&account, id);
			People::<T>::insert(id, &record);

			Ok(pays.into())
		}

#[test]
fn test_set_personal_id_account() {
	TestExt::new().execute_with(|| {
		generate_people_with_index(0, 3);

		// (In our test, we treat PersonalId as a simple u64.)
		// Verify that there are no mappings for personal id 1 and account 42.
		assert!(AccountToPersonalId::<Test>::get(42).is_none());
		assert!(People::<Test>::get(1).unwrap().account.is_none());

		// Create an origin that represents a personal identity.
		// (Recall that your pallet’s Origin enum has a variant PersonalIdentity.)
		let origin = RuntimeOrigin::from(PeopleOrigin::PersonalIdentity(1));
		// Call the extrinsic to set personal id account.
		assert_ok!(PeoplePallet::set_personal_id_account(origin, 42, 0), Pays::No.into());

		// Check that the mapping is now present.
		assert_eq!(AccountToPersonalId::<Test>::get(42), Some(1));
		assert_eq!(People::<Test>::get(1).unwrap().account, Some(42));

		// Now update the mapping by calling the extrinsic again.
		let origin = RuntimeOrigin::from(PeopleOrigin::PersonalIdentity(1));
		// Here we change the account to 43.
		assert_ok!(PeoplePallet::set_personal_id_account(origin, 43, 0), Pays::Yes.into());
		// The old mapping for account 42 should be removed.
		assert!(AccountToPersonalId::<Test>::get(42).is_none());
		assert_eq!(AccountToPersonalId::<Test>::get(43), Some(1));
		assert_eq!(People::<Test>::get(1).unwrap().account, Some(43));

		// Test that a non-personal identity origin (for example, a Signed origin)
		// does not work (the call should error with BadOrigin).
		let origin = RuntimeOrigin::signed(44);
		assert_noop!(
			PeoplePallet::set_personal_id_account(origin, 44, 0),
			sp_runtime::DispatchError::BadOrigin
		);

		// Test that trying to use an account that is already in use fails.
		// First, set a mapping for personal id 2 using account 45.
		let origin = RuntimeOrigin::from(PeopleOrigin::PersonalIdentity(2));
		assert_ok!(PeoplePallet::set_personal_id_account(origin, 45, 0), Pays::No.into());
		// Then try to set personal id 3 to use the same account 45.
		let origin = RuntimeOrigin::from(PeopleOrigin::PersonalIdentity(3));
		assert_noop!(
			PeoplePallet::set_personal_id_account(origin, 45, 0),
			Error::<Test>::AccountInUse
		);
	});
}
