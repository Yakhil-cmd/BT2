### Title
Rococo `NonTransfer` proxy claims `is_superset` over `Auction`/`OnDemandOrdering` while its own filter denies calls those types admit, enabling proxy self-escalation - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
`polkadot/runtime/rococo/src/lib.rs` implements `ProxyType::is_superset` for the relay-chain `ProxyType` enum with a catch-all rule `(ProxyType::NonTransfer, _) => true`, declaring `NonTransfer` a superset of *every* other proxy type, including `Auction` and `OnDemandOrdering`. `pallet_proxy` uses `is_superset` (not `filter`) to authorize `add_proxy`/`remove_proxy` performed *through* an existing proxy (`do_proxy`). Because `NonTransfer`'s own `filter` explicitly excludes `Registrar::swap` and all `OnDemandAssignmentProvider` calls, while `Auction`'s filter unconditionally admits the whole `Registrar` pallet (including `swap`) and `OnDemandOrdering`'s filter admits `OnDemandAssignmentProvider`, a `NonTransfer` delegate can add itself (or another account) as an `Auction`/`OnDemandOrdering` proxy for the real account and then dispatch calls that `NonTransfer`'s filter was specifically designed to forbid. This is the exact bug class Parity already fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend (`prdoc/pr_12769.prdoc`), but the fix was not applied to the equivalent lattice mismatches still present on Rococo.

### Finding Description
`pallet_proxy::do_proxy` enforces a critical invariant when a proxy call itself contains `add_proxy`/`remove_proxy`: [1](#0-0) 

The comment states: "Proxy call cannot add or remove a proxy with more permissions than it already has," enforced via `def.proxy_type.is_superset(proxy_type)`. This means `is_superset` must be a *sound over-approximation* of `filter`: if `A.is_superset(B) == true`, then every call admitted by `B.filter` must also be admitted by `A.filter`. Parity's own regression test formalizes this invariant for Asset Hub Westend: [2](#0-1) 

and the accompanying prdoc documents the exact bug class that was fixed there: [3](#0-2) 

The Rococo relay-chain `ProxyType` implementation has the identical mismatch, uncorrected. Its `is_superset` uses a blanket rule: [4](#0-3) 

`(ProxyType::NonTransfer, _) => true` declares `NonTransfer` a superset of `Auction`, `Society`, `OnDemandOrdering`, `CancelProxy`, `IdentityJudgement`, and `Governance` alike. But `NonTransfer`'s filter is a deliberately curated allow-list that *specifically excludes* certain calls: [5](#0-4) 

The comment explicitly documents `// Specifically omitting Registrar `swap`` — `NonTransfer` only admits `Registrar::register`, `deregister`, and `reserve`.

However, `ProxyType::Auction`'s filter admits the *entire* `Registrar` pallet unconditionally: [6](#0-5) 

`RuntimeCall::Registrar { .. }` matches every `Registrar` call, including `swap` — the exact call `NonTransfer` was designed to deny. The same mismatch exists for `OnDemandOrdering`: [7](#0-6) 

`NonTransfer`'s filter (lines 922-966) never lists `RuntimeCall::OnDemandAssignmentProvider`, yet `is_superset` claims `NonTransfer ⊇ OnDemandOrdering`.

**Root cause across the boundary:** a `NonTransfer` delegate account (attacker-controlled, not privileged) is a normal signed extrinsic user who has been legitimately granted a limited proxy by a victim via `add_proxy`. The attacker then dispatches `Proxy::proxy(real, None, Box::new(RuntimeCall::Proxy(pallet_proxy::Call::add_proxy { delegate: attacker, proxy_type: ProxyType::Auction, delay: 0 })))`. Inside `do_proxy`, the filter closure checks `def.proxy_type.is_superset(&ProxyType::Auction)` where `def.proxy_type == NonTransfer`; this returns `true` via the blanket rule, so the nested `add_proxy` call is **not filtered out** and executes, adding an `Auction` proxy on the real account under attacker control. The attacker (now holding a real `Auction` proxy entry in `Proxies::<T>`) then calls `Proxy::proxy(real, None, Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap { .. })))`. This time `def.proxy_type == Auction`, and `Auction.filter` admits the `Registrar` call including `swap`, so it dispatches successfully — even though the delegator only ever intended to grant `NonTransfer` and the `NonTransfer` filter explicitly forbids `swap`.

### Impact Explanation
`Registrar::swap` allows para ID reassignment/lease-swap logic controlled by the manager account; permitting a proxy holder to invoke it when the delegator explicitly withheld that permission is an authorization bypass / privilege escalation within `pallet_proxy` — the delegator's real account performs an unauthorized dispatch it did not consent to. The `OnDemandOrdering` gap similarly lets a `NonTransfer` proxy reach `OnDemandAssignmentProvider` calls (on-demand coretime purchase/ordering, which spends the delegator's funds) that the `NonTransfer` filter was never meant to expose. This matches the CWE-915 (mass assignment / unauthorized property modification leading to authorization bypass) class in the Budibase report: an entity trusted for a narrower scope (`NonTransfer`) is used, via an unchecked lattice relation, to mint itself broader effective permissions (`Auction`/`OnDemandOrdering`) that its own declared boundary forbids.

### Likelihood Explanation
Requires only a normal, unprivileged signed account that has already been granted a `NonTransfer` proxy by any other account (a common, expected configuration pattern — `NonTransfer` is advertised as the "safe, no-fund-movement" proxy type). No governance, no validator/collator access, and no stolen keys are needed; the attacker only needs a nested `Proxy::proxy(add_proxy)` call and a follow-up `Proxy::proxy` call, both ordinary signed extrinsics with normal fees. This is directly reachable through the production `pallet_proxy` dispatch path already wired into the Rococo runtime.

### Recommendation
Apply the same fix used for Asset Hub Westend (`prdoc/pr_12769.prdoc`) to Rococo's `ProxyType::is_superset`: remove the blanket `(ProxyType::NonTransfer, _) => true` rule and enumerate only the pairs whose filters are true subsets, e.g. keep `NonTransfer ⊇ {Governance, IdentityJudgement, CancelProxy, Society}` (verified subset by call filter) and drop `Auction` and `OnDemandOrdering` from that claim (or, alternatively, widen `NonTransfer`'s filter to also admit `Registrar::swap` and `OnDemandAssignmentProvider`, which is not the documented intent). Additionally, port the `proxy_type_superset_relation_matches_call_filters` lattice regression test (from `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2493-2516`) into the Rococo/relay-chain runtime test suite so this bug class cannot silently reappear on any other pair, and audit all other `ProxyType::is_superset` implementations in the repo for the same pattern.

A minimal reproduction (not executed here, to be run by a Devin agent with `cargo test -p rococo-runtime` or an emulated integration test) would:
1. Fund account A (delegator) and account B (delegate).
2. `Proxy::add_proxy(A, B, ProxyType::NonTransfer, 0)`.
3. `Proxy::proxy(B, A, None, Box::new(RuntimeCall::Proxy(add_proxy{ delegate: B, proxy_type: ProxyType::Auction, delay: 0 })))` — expect this to currently succeed (bug) rather than be `CallFiltered`.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
