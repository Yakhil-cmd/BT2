### Title
Staking Info Received Over P2P Is Accepted Without Content Validation, Enabling Reward Distribution Corruption — (`datasync/downloader/queue.go`)

---

### Summary

During fast-sync, a node downloads `StakingInfo` from peers and persists it to the database. The `validate` callback inside `DeliverStakingInfos` is a deliberate no-op (marked `// TODO-Kaia-Snapsync update validation logic`). No field of the received `P2PStakingInfo` is checked against the corresponding block header. A malicious peer can therefore inject fabricated staking data that is stored verbatim and later used to drive KAIA reward distribution and validator-set selection.

---

### Finding Description

`DeliverReceipts` validates every receipt batch against the committed `header.ReceiptHash`:

```go
// datasync/downloader/queue.go
validate := func(index int, header *types.Header) error {
    if types.DeriveReceiptsRoot(types.Receipts(receiptList[index]), header.Number) != header.ReceiptHash {
        return errInvalidReceipt
    }
    return nil
}
``` [1](#0-0) 

`DeliverStakingInfos` performs no equivalent check:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [2](#0-1) 

The accepted data is then written unconditionally to the database in `commitFastSyncData`:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
``` [3](#0-2) 

The same absence of content validation applies to the `SyncStakingInfo` recovery path, which only checks the block number, not the content:

```go
if d.stakingInfoRecoveryBlocks[0] != stakingInfo.BlockNum {
    logger.Error("failed to receive expected block", ...)
    return
}
d.stakingModule.PutStakingInfoToDB(stakingInfo.BlockNum, staking.ToStakingInfo(stakingInfo))
``` [4](#0-3) 

The P2P entry point `handleStakingInfoMsg` passes the decoded payload directly to the downloader with no pre-filtering:

```go
var stakingInfos []*staking.P2PStakingInfo
if err := msg.Decode(&stakingInfos); err != nil { ... }
if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil { ... }
``` [5](#0-4) 

---

### Impact Explanation

`StakingInfo` drives two critical on-chain operations before the Kaia hardfork:

1. **Reward distribution** — `assignStakingRewards` and `assignStakingRewardsFlex` use `StakingInfo.StakingAmounts`, `RewardAddrs`, `KEFAddr`, `KIFAddr`, and `KPFAddr` to split every block's minted KAIA among validators and treasury funds. [6](#0-5) 

2. **Validator-set selection** — `StakingInfo.NodeIds` and `StakingAmounts` determine which nodes are eligible validators. [7](#0-6) 

A malicious peer that supplies fabricated `StakingInfo` can:
- Redirect KAIA block rewards to attacker-controlled `RewardAddrs`
- Redirect KEF/KIF/KPF treasury allocations to attacker-controlled addresses
- Inflate or zero out specific validators' staking amounts, skewing proportional reward splits
- Exclude legitimate validators or include illegitimate ones in the validator set

These are direct unauthorized KAIA transfers and invalid reward distributions affecting system-managed funds.

---

### Likelihood Explanation

- Any peer connected during fast-sync can send a `StakingInfoMsg`; no privilege is required beyond a standard P2P connection.
- Fast-sync is the default mode for new nodes joining the network before the Kaia hardfork.
- The `SyncStakingInfo` admin RPC path (`admin_syncStakingInfo`) is also exploitable by a peer that controls the response to a targeted request, since only the block number is checked.
- The corrupted database entry persists across restarts and is used for every subsequent block in the affected staking interval (up to `StakingUpdateInterval` blocks, default 86,400).

---

### Recommendation

Implement content validation in `DeliverStakingInfos` analogous to `DeliverReceipts`. Because `StakingInfo` is derived from the AddressBook contract state, the correct validator is to re-derive the staking info from the state root committed in `header.Root` and compare it to the received data:

```go
validate := func(index int, header *types.Header) error {
    received := stakingInfoList[index]
    if received == nil {
        return errInvalidStakingInfo
    }
    // Re-derive from committed state root and compare
    expected, err := stakingModule.getFromStateByNumber(header.Number.Uint64())
    if err != nil {
        return err
    }
    if !stakingInfoEqual(expected, staking.ToStakingInfo(received)) {
        return errInvalidStakingInfo
    }
    return nil
}
```

At minimum, verify that `received.BlockNum` matches `header.Number.Uint64()` and that the node/reward address arrays are non-empty and consistent in length, rejecting any response that fails these structural checks.

---

### Proof of Concept

1. Attacker runs a Kaia node and connects to a victim node that is fast-syncing (pre-Kaia hardfork).
2. When the victim sends `StakingInfoRequestMsg` for block hashes `[h1, h2, ...]`, the attacker responds with `StakingInfoMsg` containing `P2PStakingInfo` structs where:
   - `BlockNum` matches the requested block numbers (passes the only check in `SyncStakingInfo`)
   - `RewardAddrs` are replaced with attacker-controlled addresses
   - `StakingAmounts` are inflated for attacker-controlled validators
3. `handleStakingInfoMsg` → `DeliverStakingInfos` → `queue.DeliverStakingInfos` accepts the data because `validate` always returns `nil`.
4. `commitFastSyncData` calls `PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))`, persisting the fabricated data.
5. On subsequent block processing, `GetStakingInfo(num)` returns the corrupted entry from the database, and `assignStakingRewards` distributes KAIA block rewards to the attacker's addresses instead of the legitimate validators. [8](#0-7) [9](#0-8)

```go
func (d *Downloader) commitFastSyncData(results []*fetchResult, stateSync *stateSync) error {
	// Check for any early termination requests
	if len(results) == 0 {
		return nil
	}
	select {
	case <-d.quitCh:
		return errCancelContentProcessing
	case <-stateSync.done:
		if err := stateSync.Wait(); err != nil {
			return err
		}
	default:
	}
	// Retrieve the a batch of results to import
	first, last := results[0].Header, results[len(results)-1].Header
	logger.Debug("Inserting fast-sync blocks", "items", len(results),
		"firstnum", first.Number, "firsthash", first.Hash(),
		"lastnumn", last.Number, "lasthash", last.Hash(),
	)
	blocks := make([]*types.Block, len(results))
	receipts := make([]types.Receipts, len(results))
	for i, result := range results {
		blocks[i] = types.NewBlockWithHeader(result.Header).WithBody(result.Transactions)
		receipts[i] = result.Receipts
		if result.StakingInfo != nil {
			d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
			logger.Info("Imported new staking information", "number", result.StakingInfo.BlockNum)
		}
	}
	if index, err := d.blockchain.InsertReceiptChain(blocks, receipts); err != nil {
		logger.Debug("Downloaded item processing failed", "number", results[index].Header.Number, "hash", results[index].Header.Hash(), "err", err)
		return fmt.Errorf("%w: %v", errInvalidChain, err)
	}
	return nil

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
