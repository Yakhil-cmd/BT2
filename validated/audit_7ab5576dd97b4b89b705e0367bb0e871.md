## Analog Found

### Title
CCMenu API tokens are not stack-scoped, allowing cross-stack unauthenticated stack-state reads - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
The `ApiClient` model supports an optional `stack` binding intended to scope a token to a single stack: an `ApiClient` `belongs_to :stack, optional: true`, and `Api::BaseController#stacks`/`#stack` enforce that binding by restricting the query set to `current_api_client.stack_id` when present. [1](#0-0) [2](#0-1) 

`Api::CCMenuController`, however, both creates a token that is never bound to a stack and reimplements `stack` to read directly from the URL parameter, discarding that binding entirely. [3](#0-2) 

### Finding Description
The intended equality that must hold is: **stack a token authorises == stack it touches**.

1. `CCMenuUrlController#client` mints (or reuses) an `ApiClient` for the current user with `permissions: %w[read:stack]`, keyed only by `creator` and a fixed `name: 'CCMenu Client'` — it never sets `stack:`, so `stack_id` is `nil` for this client, regardless of which stack's CCMenu URL was requested: [4](#0-3) 

2. This unscoped token is embedded directly in a URL returned to the browser (`?token=...`), meant to be consumed by any external CI dashboard tool polling a single stack's status: [5](#0-4) 

3. `Api::CCMenuController` authenticates purely off that URL `token` param (no session, no Basic Auth) and then overrides `stack` to resolve straight from `params[:stack_id]`, bypassing the normal `Api::BaseController#stacks` scoping that would have filtered by `current_api_client.stack_id`: [6](#0-5) 

4. `require_permission :read, :stack` only checks that the client's `permissions` array contains `read:stack` — it never checks *which* stack the client is scoped to: [7](#0-6) 

Since `stack_id` is `nil` on this client type, and the controller-level `stack` override ignores whatever scoping might otherwise apply, the token that a user obtained to monitor Stack A's CCMenu status is fully valid to read the CCMenu status (`deploys_and_rollbacks.last`, i.e., last deploy id, completion time, running state) of **any** stack in the installation by simply changing `stack_id` in the URL — even stacks the token holder has never been granted access to and never authenticated against via GitHub.

### Impact Explanation
This is unauthenticated read of stack state for stacks outside the credential's intended scope, meeting the High-severity bar: "unauthenticated read of stack state, task streams or deploy output." Any party who obtains one legitimate CCMenu token (e.g., from a CI dashboard config, a shared build widget, or by observing network traffic to one authorized stack) can iterate over all stack IDs and read deploy status for stacks they have no authorization for, entirely bypassing GitHub-team based authorization (`Shipit.github_teams`).

### Likelihood Explanation
Exploitation requires only a single, low-sensitivity credential (a CCMenu URL token, which by design is meant to be embedded in third-party polling tools and is not treated as highly secret) and knowledge/enumeration of `stack_id` values (which are typically `owner/repo/environment` slugs, often guessable or discoverable). No privileged account, session, or GitHub credentials are needed, making this straightforward to exploit for anyone who has legitimately obtained one CCMenu token.

### Recommendation
Bind the `ApiClient` created in `CCMenuUrlController#client` to the specific `stack` (set `stack:` at creation, scoped per stack rather than reused per user), and remove the `stack` override in `Api::CCMenuController` so it goes through `Api::BaseController#stacks`, which already enforces `current_api_client.stack_id` scoping.

### Proof of Concept
1. As an authenticated user with access to Stack A, visit `GET /ccmenu/*stack_a_id` — receive `{ "ccmenu_url": ".../api/*stack_a_id/ccmenu.xml?token=<TOKEN>" }` [8](#0-7) 
2. Take `<TOKEN>` and request `GET /api/*stack_b_id/ccmenu.xml?token=<TOKEN>` for an arbitrary Stack B the user has no relationship to.
3. `authenticate_api_client` in `Api::CCMenuController` accepts the token (valid signature, unrelated to any stack), `require_permission :read, :stack` passes (client has `read:stack` permission), and `stack` resolves to Stack B directly from `params[:stack_id]`, returning Stack B's deploy status. [9](#0-8)

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
