### Title
Fresh skill install leaves partially-written files on validation/fetch failure (no staging) - ([File: internal/skills/installer/installer.go])

### Summary
`installSkill` in `internal/skills/installer/installer.go` writes each skill file directly into the final target directory (`baseDir/skill.Name`) as it streams files from the GitHub API, with no staging directory or atomic rename. If any file in the middle of the list fails to install (blocked path traversal, fetch error, or metadata-injection error), files written before the failure remain on disk in the live agent skills directory. Note that `ResolveRef` itself (`internal/skills/discovery/discovery.go:207`) only resolves which git ref to use via REST calls and performs no filesystem writes — the actual partial-write exposure is downstream in the installer, not in `ResolveRef`.

### Finding Description
`Install` (`internal/skills/installer/installer.go:56`) resolves the target directory and calls `installSkill` (`installer.go:251`) for a fresh install. `installSkill` creates `skillDir := filepath.Join(baseDir, skill.Name)` with `os.MkdirAll`, then iterates over `discovery.DiscoverSkillFiles` results, and for each file: fetches the blob via `discovery.FetchBlob`, validates the destination path with `safepaths`, optionally injects metadata into `SKILL.md` via `frontmatter.InjectGitHubMetadata`, and calls `os.WriteFile` directly into `skillDir` [1](#0-0) .

If a later file in the same skill triggers a validation failure — e.g., a crafted archive/tree entry that resolves to a path-traversal after an earlier benign file was already written, or a `frontmatter.InjectGitHubMetadata` error on `SKILL.md`, or a transient fetch failure on file N of M — the function returns an error immediately, but files 1..N-1 already written via `os.WriteFile` are never removed. The caller `Install` propagates `firstErr` but does not clean up `skillDir` [2](#0-1) . This is unlike the `update` flow (`pkg/cmd/skills/update/update.go`), which explicitly stages installs in a sibling temp directory and only atomically swaps contents into the live directory via `swapDirectoryContents`, with rollback on any failure [3](#0-2) . The fresh-install path (`installer.Install` → `installSkill`) has no equivalent staging/rollback.

Because `gh skills` agent hosts typically auto-load any file present under the skills directory, an attacker who publishes a skill whose file list is ordered so that an executable/script file is written before a later file that trips validation (e.g., a bad frontmatter or an out-of-scope path in a later blob) can leave that executable resident in the live, scanned skills directory even though the overall `gh skills install` command reports failure.

### Impact Explanation
Scoped impact is limited to leaving unwanted/attacker-authored file(s) present in the target skills directory after a reported failure, rather than a clean atomic all-or-nothing install. Whether this rises to "RCE" depends entirely on whether the agent host that scans/loads the skills directory executes arbitrary files it finds there regardless of a companion `SKILL.md`/manifest being valid — that behavior is external to this repo (in the third-party agent runtime, e.g. Copilot/Claude skill loaders) and is not verifiable from this codebase. Within this repo the concrete, provable impact is: unintended executable-remnant file left in the developer's local skills directory (arbitrary file write outside the intended "successful install" boundary), which is a real but narrower issue than a demonstrated RCE primitive purely from this code.

### Likelihood Explanation
Feasible and repeatable: the attacker fully controls a published skill's repo tree order, file contents, and can intentionally cause a failure partway through file list processing (e.g., by using `path/../` in a later blob's path to trigger `safepaths` rejection, or malformed frontmatter to trigger the `frontmatter.InjectGitHubMetadata` error, or a file whose blob later returns an error). No privileged access is required — only publishing a skill repo that the victim then installs via `gh skills install owner/repo`.

### Recommendation
Make fresh installs staged and atomic like the update path: build each skill in a temporary sibling directory (`os.MkdirTemp` next to `baseDir`), perform all fetches/validation/writes there, and only `os.Rename`/move the fully-validated staged directory into place (or use the existing `swapDirectoryContents`-style logic) once every file for that skill has succeeded. On any error, discard the staging directory and leave the final `skillDir` untouched (or restore to its pre-install state if there was a previous version, mirroring `updateSkillInPlace`).

### Proof of Concept
Extend `installer_test.go`'s `TestInstallSkill` with a case where the tree returns two blobs: a benign `helper.sh` first, then a second entry with an invalid path (`../../evil`) causing a `safepaths.PathTraversalError`. Assert:
```go
err := installSkill(opts, skill, destDir)
require.Error(t, err)
entries, _ := os.ReadDir(filepath.Join(destDir, skill.Name))
assert.Empty(t, entries, "no partial files should remain after a failed install")
```
Currently this assertion fails because `helper.sh` remains written in `destDir/<skillName>/helper.sh` despite the overall install failing — confirming partial-write remnants are left in the target directory. [4](#0-3)

func installSkill(opts *Options, skill discovery.Skill, baseDir string) error {
	// Use skill.Name (not InstallName) for a flat directory layout.
	skillDir := filepath.Join(baseDir, skill.Name)
	if err := os.MkdirAll(skillDir, 0o755); err != nil {
		return fmt.Errorf("could not create directory %s: %w", skillDir, err)
	}

	files, err := discovery.DiscoverSkillFiles(opts.Client, opts.Host, opts.Owner, opts.Repo, skill.TreeSHA, skill.Path)
	if err != nil {
		return fmt.Errorf("could not list skill files: %w", err)
	}

	safeSkillDir, err := safepaths.ParseAbsolute(skillDir)
	if err != nil {
		return fmt.Errorf("could not resolve skill directory path: %w", err)
	}

	for _, file := range files {
		fetchedContent, err := discovery.FetchBlob(opts.Client, opts.Host, opts.Owner, opts.Repo, file.SHA)
		if err != nil {
			return fmt.Errorf("could not fetch %s: %w", file.Path, err)
		}

		// Install path: the blob is written to disk verbatim, so the raw bytes
		// must be preserved.
		content := fetchedContent.Raw()

		relPath := strings.TrimPrefix(file.Path, skill.Path+"/")

		safeDest, err := safeSkillDir.Join(relPath)
		if err != nil {
			var traversalErr safepaths.PathTraversalError
			if errors.As(err, &traversalErr) {
				return fmt.Errorf("blocked path traversal in %q", relPath)
			}
			return fmt.Errorf("could not resolve destination path: %w", err)
		}
		destPath := safeDest.String()

		if dir := filepath.Dir(destPath); dir != skillDir {
			if err := os.MkdirAll(dir, 0o755); err != nil {
				return fmt.Errorf("could not create directory: %w", err)
			}
		}

		if filepath.Base(relPath) == "SKILL.md" {
			content, err = frontmatter.InjectGitHubMetadata(content, opts.Host, opts.Owner, opts.Repo, opts.Ref, skill.TreeSHA, opts.PinnedRef, skill.Path)
			if err != nil {
				return fmt.Errorf("could not inject metadata: %w", err)
			}
		}

		if err := os.WriteFile(destPath, []byte(content), 0o644); err != nil {
			return fmt.Errorf("could not write %s: %w", destPath, err)
		}
	}

	return nil
}

// updateSkillInPlace installs the resolved update into a staging directory
// alongside the existing skill directory and, on success, atomically swaps
// the staged contents into place via same-filesystem renames. This
// guarantees:
//
//   - The skill directory's own inode is preserved, so symlinks, mounts, and
//     external references that point at it stay valid.
//   - Stale files from the previous version are removed.
//   - A failure at any point (install, read, rename) leaves the existing
//     skill completely untouched: existing files are first moved aside into
//     a backup directory and restored if any subsequent step fails.
func updateSkillInPlace(opts *UpdateOptions, u pendingUpdate, apiClient *api.Client, gitRoot, homeDir string) error {
	if u.local.dir == "" {
		return fmt.Errorf("cannot update %s: no install location recorded", u.local.name)
	}

	parent := filepath.Dir(u.local.dir)
	if err := os.MkdirAll(parent, 0o755); err != nil {
		return fmt.Errorf("could not ensure parent directory %s: %w", parent, err)
	}

	// Stage as a sibling of the existing skill directory so the swap stays
	// on the same filesystem and every rename is atomic.
	staging, err := os.MkdirTemp(parent, "."+u.skill.Name+".gh-skill-update-")
	if err != nil {
		return fmt.Errorf("could not create staging directory: %w", err)
	}
	defer os.RemoveAll(staging)

	installOpts := &installer.Options{
		Host:    u.local.repoHost,
		Owner:   u.local.owner,
		Repo:    u.local.repo,
		Ref:     u.resolved.Ref,
		SHA:     u.resolved.SHA,
		Skills:  []discovery.Skill{u.skill},
		Dir:     staging,
		GitRoot: gitRoot,
		HomeDir: homeDir,
		Client:  apiClient,
	}
	if _, err := installer.Install(installOpts); err != nil {
		return err
	}

	stagedSkillDir := filepath.Join(staging, u.skill.Name)
	if _, err := os.Stat(stagedSkillDir); err != nil {
		return fmt.Errorf("installer did not produce %s: %w", stagedSkillDir, err)
	}

	if err := os.MkdirAll(u.local.dir, 0o755); err != nil {
		return fmt.Errorf("could not ensure skill directory %s: %w", u.local.dir, err)
	}

	return swapDirectoryContents(u.local.dir, stagedSkillDir)
}
