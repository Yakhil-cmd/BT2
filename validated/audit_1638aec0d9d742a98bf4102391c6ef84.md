## Title
Webhook organization used for signature verification is decoupled from the repository whose Stack is mutated - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the `webhook_secret` to validate a request against based on `repository.owner.login` (or `organization.login`), but the handlers that actually act on the payload (`PushHandler`, `StatusHandler`, `MembershipHandler`) resolve the target `Stack`/`Commit`/`Team` using a *different* field of the same attacker-supplied JSON body (`repository.full_name`, `sha`, `team.id`). Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for that organization, and because `webhook_secret` is explicitly documented/shipped as an optional (`nil`) setting, any organization configured in `Shipit.github` without a webhook secret becomes a skeleton key: a request whose `repository.owner.login`/`organization.login` names that unsecured org will pass verification, while `repository.full_name` (used to look up the target `Stack`) can point at a repository belonging to a *different, secured* organization.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb` picks the App/secret to validate against solely from `repository_owner`: [1](#0-0) 

That resolves to `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`, and in `lib/shipit/github_app.rb`: [2](#0-1) 
`verify_webhook_signature` returns `true` unconditionally whenever `webhook_secret` is blank for that org — a configuration explicitly presented as optional/nil in the setup docs and example secrets file: [3](#0-2) 

Once verification passes, `WebhooksController#create` dispatches to handlers using only `event`, not the verified organization: [4](#0-3) 

Handlers then resolve the `Stack`/`Repository`/`Commit` to mutate from a *different* JSON field — `repository.full_name` — with no cross-check against `repository.owner.login`/`organization.login` used for the signature lookup: [5](#0-4) [6](#0-5) [7](#0-6) 

This is the same class of bug as the report: the entity that is authenticated/authorized (the organization whose secret validated the payload, analogous to the on-chain "chain" that authorized a message) is not the same entity the action is actually performed against (the repository named in `full_name`, analogous to the destination address the message actually reaches). Nothing cryptographically binds `repository.owner.login`/`organization.login` to `repository.full_name` inside the same signed payload check — the controller trusts whichever org name is convenient for bypassing the HMAC check, then the handler trusts a separate field for the target.

### Impact Explanation
If any one GitHub organization configured in `Shipit.github` is left without a `webhook_secret` (documented and shipped as the default/optional state), an unauthenticated network attacker can:
1. Send a forged `push` webhook with `repository.owner.login` set to that unsecured org (so `verify_signature` short-circuits to `true`), but `repository.full_name` set to `"secured-org/tracked-repo"` for a `Stack` belonging to a *different*, properly secured organization.
2. `PushHandler` will then call `stack.sync_github(expected_head_sha: ...)` on that unrelated stack, and/or `StatusHandler` can inject fabricated commit statuses for arbitrary SHAs (`Commit.where(sha: params.sha)`), which can flip CI-gating (`required_statuses`) used by continuous delivery/auto-merge logic (`Stack#continuous_delivery_step`, `next_commit_to_deploy`), potentially causing an **unauthorized deploy** for a stack the attacker has no credentials for. This satisfies the Critical impact bar ("unauthorized deploy").

### Likelihood Explanation
Likelihood is moderate-to-high in real deployments: the multi-org configuration schema explicitly supports per-organization `webhook_secret` values that are individually optional/nilable, and the shipped example configuration ships with `webhook_secret: # nil`, so it is plausible that at least one configured organization (e.g., a low-traffic or test org added to `Shipit.github`) has no secret set, while other tracked orgs are the ones an attacker actually wants to target. No credentials, tokens, or repository access are required — only knowledge that some org in the multi-org config lacks a secret, and the target stack's full repo name, both of which are visible from the Shipit UI/API to any authenticated-elsewhere or even anonymous stack browsing.

### Recommendation
Cross-validate that the organization used to select/verify the webhook secret matches the organization portion of `repository.full_name` (or `organization.login`) before dispatching to handlers, and reject payloads with mismatched organization fields. Additionally, disallow organizations from being fully unauthenticated: require a webhook secret for every configured GitHub App, or fail closed (422) rather than returning `true` when `webhook_secret` is blank.

### Proof of Concept
1. Configure `Shipit.github` with two orgs: `secured-org` (has `webhook_secret` set) and `open-org` (no `webhook_secret`, i.e. `nil`), both installed and with tracked stacks.
2. As an anonymous attacker (no GitHub credentials, no Shipit account), POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-controlled-sha>",
  "repository": {
    "full_name": "secured-org/tracked-repo",
    "owner": { "login": "open-org" }
  }
}
```
3. `verify_signature` calls `Shipit.github(organization: "open-org").verify_webhook_signature(...)`, which returns `true` because `open-org` has no `webhook_secret` configured — no valid `X-Hub-Signature` header is even required.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("secured-org/tracked-repo")`, entirely bypassing `secured-org`'s webhook secret, and triggers `sync_github` on that stack.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
