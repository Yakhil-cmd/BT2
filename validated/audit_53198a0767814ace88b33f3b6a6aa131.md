### Title
Cross-organization webhook forgery via `repository.owner.login` / `repository.full_name` binding mismatch - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
In multi-tenant Shipit deployments (multiple GitHub organizations configured under `secrets.github`), `WebhooksController#verify_signature` selects which organization's `webhook_secret` to use for HMAC verification based on `repository.owner.login` (or `organization.login`) taken from the *unauthenticated* JSON body, but the handlers that actually act on the payload (`Handler#repository_name`) look up the target repository/stack using a *different* field, `repository.full_name`. Because the same raw body is used both to pick the verification key and to determine what gets written, an actor who legitimately controls one onboarded organization's GitHub App webhook secret can forge events that write to stacks belonging to a completely different organization.

### Finding Description
`Shipit.github(organization:)` supports per-organization GitHub App configuration, each with its own `webhook_secret`, keyed by organization name in `secrets.github` [1](#0-0) .

The webhook signature check derives the organization to verify against purely from attacker-controlled payload fields:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

Once the signature is verified (matched against `Shipit.github(organization: repository_owner)`'s `webhook_secret`), the raw payload is dispatched unmodified to every registered handler for the event:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [3](#0-2) 

However, the base `Handler` class (used by `PushHandler`, all `PullRequest::*Handler`s, etc.) resolves the *actual* target repository/stack from a different field, `repository.full_name`, which is never cross-checked against `repository.owner.login`:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [4](#0-3) 

`StatusHandler` similarly trusts `sha`/`state`/`context` fields straight from the payload without any repository-ownership check at all, applying the status to any `Commit` matching that `sha` in the whole database:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [5](#0-4) 

**The binding that is broken**: `verified_organization (repository.owner.login) == organization_whose_repository_is_written (repository.full_name)` is assumed but never enforced. An attacker who is a legitimate administrator of `org-a`'s GitHub App (and thus knows `org-a`'s `webhook_secret`) can set `repository.owner.login = "org-a"` (to select the correct signing key) while setting `repository.full_name = "org-b/some-repo"` (a repository they do not control) and sign the tampered body with `org-a`'s secret. `verify_signature` passes because the HMAC matches `org-a`'s key; `PushHandler`/`StatusHandler`/pull-request handlers then act on `org-b`'s stacks.

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" trust boundary explicitly called out as in-scope. Concretely:
- `PushHandler` triggers `stack.sync_github(expected_head_sha: ...)` for any stack matching the forged `repository.full_name`, which can enqueue `GithubSyncJob` work and (for stacks with `continuous_deployment` enabled) contribute to triggering deploys for a repository the attacker does not control — an unauthorized cross-repository write / potential unauthorized deploy path.
- `StatusHandler` lets the attacker inject a fabricated CI status (e.g., forged "success") for any commit SHA that happens to exist for another organization's stack, which can unblock deploy-gating logic that depends on commit statuses.
- Pull-request handlers (`OpenedHandler`, `LabeledHandler`, `ReopenedHandler`, etc.) can archive/unarchive or provision Review Stacks belonging to another organization's repository.

This satisfies the "cross-repository writes / unauthorized deploy" impact bar for High/Critical severity in a multi-tenant Shipit installation.

### Likelihood Explanation
Requires the attacker to legitimately control (or have been granted) a GitHub App installation/webhook secret for at least one organization onboarded to the shared Shipit instance — a realistic scenario for the documented multi-org configuration format (`secrets.github` keyed by organization, each with independent `webhook_secret`) [6](#0-5) . No GitHub App private key, `GITHUB_TOKEN`, Shipit session, or API client token is needed — only the ability to send an arbitrary HTTP POST with a body signed using a webhook secret the attacker legitimately possesses for their own organization.

### Recommendation
After verifying the signature, cross-validate that `repository.owner.login` (the organization whose secret authenticated the request) matches the owner encoded in `repository.full_name` (and any `organization.login` field) before dispatching to handlers. Reject the webhook (422) on mismatch. Alternatively, have `Handler#repository_name` (and `StatusHandler`) validate that the resolved `Repository`'s owner equals the organization that successfully verified the signature.

### Proof of Concept
1. Shipit is configured for two organizations, e.g. `secrets.github["org-a"]` and `secrets.github["org-b"]`, each with its own GitHub App and `webhook_secret` (per `lib/shipit.rb#github_app_config`).
2. Attacker administers `org-a`'s GitHub App and thus knows `org-a`'s `webhook_secret`.
3. Attacker crafts a `push` (or `status`/`pull_request`) JSON payload:
   ```json
   {
     "ref": "refs/heads/main",
     "after": "<attacker-chosen sha>",
     "repository": {
       "owner": { "login": "org-a" },
       "full_name": "org-b/victim-repo"
     }
   }
   ```
4. Attacker computes `X-Hub-Signature: sha1=HMAC-SHA1(org-a_webhook_secret, raw_body)` and POSTs to `/github/webhooks` (or configured mount path) with `X-Github-Event: push`.
5. `WebhooksController#verify_signature` computes `repository_owner = "org-a"`, loads `Shipit.github(organization: "org-a")`, and the signature check passes (it was legitimately signed with `org-a`'s secret).
6. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("org-b/victim-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on a stack the attacker has no authorization over in `org-b`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
