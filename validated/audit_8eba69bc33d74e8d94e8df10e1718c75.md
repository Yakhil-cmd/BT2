### Title
Interest accrual can permanently freeze a high-value market through `i128` overflow - (File: `common/src/rates/simulate.rs`)

### Summary
`accrue_step` reconstructs total borrowed and supplied values before applying the configured index ceiling. For a sufficiently large market, the index can grow enough that `scaled_to_original` overflows `i128` even though the index remains below `MAX_BORROW_INDEX_RAY`. Once that state is reached, any call that synchronizes the market panics, permanently blocking repayment, withdrawal, liquidation, and further index updates. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The permissionless controller entrypoint `update_indexes(caller, assets)` requires only caller authorization and forwards the supplied hub assets to the pool. [4](#0-3) [5](#0-4) 

Each accrual step first computes `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original`, and only afterward computes and caps the next borrow index. [1](#0-0) [6](#0-5) 

`scaled_to_original` performs the fixed-point multiplication directly, while `MAX_BORROW_INDEX_RAY` is an absolute index ceiling of `1e36` raw units rather than a bound on the representable total value. [2](#0-1) [3](#0-2) 

Consequently, a very large scaled supply or debt can exceed `i128::MAX` when multiplied by an index far below the configured index cap. Because all pool mutation legs load the market through `synced_market`, which invokes `interest::global_sync` before executing the operation, the same overflow occurs before repayments, withdrawals, borrows, liquidations, and other market mutations. [7](#0-6) [8](#0-7) 

### Impact Explanation
This permanently freezes the affected `(hub_id, asset)` market. Suppliers cannot withdraw, borrowers or third parties cannot repay, liquidators cannot clear positions, and permissionless index updates cannot recover the market because each path panics during the mandatory accrual step. [9](#0-8) [10](#0-9) [11](#0-10) 

The result is permanent freezing of user funds and a market unable to operate normally, rather than a temporary transaction failure. [12](#0-11) 

### Likelihood Explanation
Reaching the condition requires a very large raw market balance and sustained borrowing over an extended accrual period, so it is not triggerable from an empty or small market. [13](#0-12) 

Once such a market exists, however, any unprivileged authenticated caller can invoke `update_indexes` with the affected `HubAssetKey`; no governance role, private key, oracle manipulation, or external-service access is required for the final state transition. [4](#0-3) [5](#0-4) 

The repository’s own regression test demonstrates the condition: an 18-decimal market with one billion whole units at 98% utilization eventually fails `update_indexes` with `MathOverflow`, after which both withdrawal and repayment fail with the same error. [14](#0-13) 

### Recommendation
Bound the product `scaled_position * index` before applying index growth. In particular:

- Calculate accrued debt as `borrowed * (new_index - old_index)` using checked arithmetic instead of materializing the complete `borrowed * new_index` value.
- Clamp `new_borrow_index` to the greatest index for which `borrowed * new_index` remains representable, and apply the analogous bound to `supplied * supply_index`.
- Alternatively, store raw unscaled debt and supply totals or use a wider checked intermediate representation before converting back to `i128`.
- Add a regression test that continues calling `repay`, `withdraw`, and `update_indexes` after the index reaches the representable-value boundary. [15](#0-14) [16](#0-15) 

### Proof of Concept
1. Establish a high-decimal market containing approximately `1e18` raw units per whole token and a very large supplied balance, then borrow a sustained high-utilization amount such as 98% of that supply. [17](#0-16) 
2. Allow ledger time to advance while repeatedly invoking the permissionless `update_indexes` path until `borrowed * borrow_index` approaches `i128::MAX`. [5](#0-4) [18](#0-17) 
3. On the next accrual, `scaled_to_original(env, borrowed, borrow_index)` panics before `update_borrow_index` can clamp the newly computed index. [1](#0-0) [2](#0-1) 
4. Subsequent `withdraw` and `repay` transactions also panic because both operations call `synced_market` and therefore run the same accrual before their position logic. [9](#0-8) [19](#0-18)

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
