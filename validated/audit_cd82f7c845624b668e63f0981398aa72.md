### Title
Unvalidated route addresses let an attacker-supplied pool execute arbitrary token transfers under the caller's signed auth tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The advisory class is "untrusted input passed unsanitized into a sink that executes it" (jQuery DOM injection). The analog in XOXNO Lending is the controller's routed strategy path: a caller-supplied `swap_xdr` payload names arbitrary pool and token addresses, and neither the controller nor the swap aggregator keeps an allowlist of those addresses. An attacker-deployed "pool" placed inside a route can invoke `token.transfer(victim, attacker, amount)` for any token the victim holds, and the Soroban host attaches that transfer as a child of the victim's signed authorization tree — so a victim who signs the simulation-produced tree loses their entire wallet balance of tokens the protocol never listed.

### Finding Description
The controller's strategy entrypoints (`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`, `flash_position`) accept a `swap_xdr` bytes payload and forward it to the configured swap aggregator's `execute_strategy(sender, total_in, swap_xdr)`, granting one exact input transfer auth. The router decodes `StrategyPayload{amounts, assets, ops}` and invokes whatever `pool`/`token` addresses the payload's `assets` registry names, with no venue-address allowlist — `dispatch_hop` calls `invoke_contract(&hop.pool, ...)` for Soroswap/Aquarius/Phoenix/Sushi/Comet opcodes. The threat model itself documents the consequence: "a route can put third-party code on the call stack below the caller's authorization," and a transfer such code makes from the caller "executes if the caller signs that tree," with the loss being "the caller's wallet, not the routed amount."

### Impact Explanation
Theft of user funds beyond the routed amount. The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates a rogue hop pool draining Alice's full 77,770,000,000 balance of an unlisted wallet token while her `swap_collateral` call still receives a fair output and passes all risk gates — the victim sees a successful, correctly-priced swap.

### Likelihood Explanation
Reachable by a single unprivileged attacker: deploy a malicious contract exposing a `swap` entrypoint, embed its address in a crafted `swap_xdr`, and have a victim sign the simulated authorization tree (wallets/clients that don't decode nested auth children will present it as a normal swap). The exploit requires the victim to sign the poisoned tree — the host rejects it only if the signed tree omits the rogue child — so success depends on client-side auth-tree hygiene, which the protocol itself acknowledges is the only bound. Balance-delta checks, `min_out`, and post-swap health-factor gates do not prevent it.

### Recommendation
Enforce an allowlist (or registry) of venue pool contracts and token addresses in the swap aggregator or controller, validated against decoded route assets before any `invoke_contract`. Alternatively, forward only the caller's auth for the exact input transfer and never allow third-party code to sit beneath the caller's authorization entry (e.g., perform venue calls under invoker-contract auth in a sub-invocation that cannot escalate into caller-signed token transfers). Clients should also decode simulated auth trees and reject any children beyond the single input transfer.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` implements the full attack: `RogueHopPool::swap` calls `token::Client::transfer(victim, attacker, WALLET_BALANCE)` on a token the protocol never listed; `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows the stolen transfer recorded under Alice's `swap_collateral` auth entry with her wallet drained and attacker credited; `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` shows signing the simulation-produced tree executes the theft while the honest tree reverts.
