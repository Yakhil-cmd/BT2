The earlier PR #12769 fix (`NonTransfer` vs `Governance` in asset-hub-westend) suggests this exact bug class — a `ProxyType::is_superset` claim not matching the actual `filter` permissions — has occurred before in this codebase. Let me check if the same class of bug still exists elsewhere, particularly in the Rococo/Polkadot/Kusama relay chain `ProxyType::NonTransfer` vs `ProxyType::Auction`, since I noticed `NonTransfer` explicitly omits `Registrar::swap` while `Auction` admits all `Registrar` calls.Let me verify whether this same `ProxyType::Auction` vs `ProxyType::NonTransfer` `Registrar::swap` gap exists on live Polkadot/Kusama mainnet relay chains (not just testnets), and confirm the origin check for `swap` accepts the proxied `Signed` origin.## Analysis

The OAuth2-introspection bug class is: a cached/derived authorization decision (the introspection cache) is trusted without re-validating all the specific permission fields (scope) that gate the actual protected action. The direct FRAME analog is `pallet_proxy`'s `is_superset` check, which is a coarse authorization decision ("type A may grant type B") that is *not* re-validated against the actual per-call `filter` permissions of the granted type when a delegate adds a sub-proxy for itself. This exact class was already fixed once in this codebase for `ProxyType::NonTransfer` vs `ProxyType::Governance` on Asset Hub Westend (`prdoc/pr_12769.prdoc`), but the identical pattern still exists, unfixed, between `ProxyType::NonTransfer` and `ProxyType::Auction` on the Westend and Rococo relay-chain runtimes.

### Title
`ProxyType::NonTransfer` falsely declares itself a superset of `ProxyType::Auction`, letting a `NonTransfer` proxy self-escalate to call `Registrar::swap` - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
On both the Westend and Rococo relay-chain runtimes, `ProxyType::NonTransfer::filter` explicitly *excludes* `paras_registrar::Call::swap` (the source comment reads `// Specifically omitting Registrar `swap``), while `ProxyType::Auction::filter` admits *all* `Registrar` calls via the unrestricted pattern `RuntimeCall::Registrar(..)`. However, `ProxyType::is_superset` treats `NonTransfer` as a superset of every other `ProxyType` (`(ProxyType::NonTransfer, _) => true`), including `Auction`. Since `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` purely on `is_superset` (not `filter`), a delegate holding only a `NonTransfer` proxy can add itself an `Auction` sub-proxy and then use it to invoke `Registrar::swap`, defeating the explicit restriction its own proxy type was designed to enforce. This is structurally identical to the already-patched issue described in `prdoc/pr_12769.prdoc` (`NonTransfer` vs `Governance` on Asset Hub Westend).

### Finding Description
`pallet_proxy::Pallet::do_proxy` adds a call filter to the impersonated origin that specifically guards proxy-management calls: [1](#0-0) 

For `add_proxy`/`remove_proxy`, the only check performed is `def.proxy_type.is_superset(proxy_type)`; it never re-checks the target `proxy_type`'s `filter` against what the acting `def.proxy_type` itself is allowed to do. This design is safe only if every `ProxyType::is_superset` relation is provably backed by an equivalent-or-broader `filter`.

On Westend's relay-chain runtime: [2](#0-1) 

`NonTransfer` explicitly omits `Registrar::swap`. But: [3](#0-2) 

`Auction` admits *all* `Registrar` calls, including `swap`. And: [4](#0-3) 

`is_superset` returns `true` for `(NonTransfer, Auction)` via the catch-all arm `(ProxyType::NonTransfer, _) => true`. The identical pattern (filter omitting `swap`, `Auction` filter admitting all `Registrar` calls, and the same catch-all `is_superset`) exists in Rococo's relay-chain runtime: [5](#0-4) 

The gated action, `paras_registrar::Pallet::swap`, accepts a normal `Signed` origin as long as that account is the para's manager: [6](#0-5) [7](#0-6) 

Since `pallet_proxy::do_proxy` dispatches the wrapped call with `RawOrigin::Signed(real)`, a delegate acting through a `NonTransfer` proxy for a para-manager account `real` satisfies `ensure_root_para_or_owner` for any call it can smuggle through, including `swap`, once it has escalated to an `Auction` sub-proxy.

This exact bug class (declared `is_superset` not backed by an equivalent `filter`) was already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend: [8](#0-7) 

and a lattice-consistency regression test was added there: [9](#0-8) 

No equivalent test exists (nor is the underlying inconsistency fixed) for the relay-chain `NonTransfer`/`Auction` pair on Westend or Rococo.

### Impact Explanation
A delegate holding a `NonTransfer` proxy (intentionally restricted, per its own doc comment, from calling `Registrar::swap`) can escalate by adding itself an `Auction` sub-proxy and then dispatching `Registrar::swap` as the real account. `swap` mutates parachain-vs-parathread lifecycle state and swaps auction/lease information for the impersonated account's para, an action the delegator explicitly did not authorize when granting only a `NonTransfer` proxy. This is an authorization-bypass/privilege-escalation of the exact class (CWE-863: incorrect authorization) as the referenced advisory, and of the exact bug class already fixed once in this codebase via `prdoc/pr_12769.prdoc`.

### Likelihood Explanation
The attacker needs no privileged role: any account that has been granted only a `NonTransfer` proxy by a para manager (a common, low-trust delegation intended for automation/limited-permission use) can trigger this deterministically, with no race condition, no governance action, and no external dependency. The trigger is two ordinary signed extrinsics (`Proxy::add_proxy` then `Proxy::proxy`).

Caveat on eligibility: this bug is reachable only on the Westend and Rococo relay-chain runtimes present in this `polkadot-sdk` repository; Polkadot/Kusama mainnet relay-chain runtime source lives in the separate `polkadot-fellows/runtimes` repository, not in `polkadot-sdk`, so it cannot be confirmed from this codebase whether the live mainnet chains share this exact `ProxyType` definition, and this fork does not contain a `polkadot/runtime/polkadot` or `polkadot/runtime/kusama` directory to check directly.

### Recommendation
Either remove the blanket `(ProxyType::NonTransfer, _) => true` arm from `is_superset` and enumerate exactly the types it actually dominates, or (preferably) add a lattice-consistency test analogous to `proxy_type_superset_relation_matches_call_filters` (already added for Asset Hub Westend) to the Westend and Rococo relay-chain runtimes, asserting for every `(superset, subset)` pair where `superset.is_superset(subset)` holds, that every call admitted by `subset.filter` is also admitted by `superset.filter`. This would have caught the `NonTransfer`/`Auction`/`Registrar::swap` gap immediately, the same way it caught the `NonTransfer`/`Governance` gap on Asset Hub Westend.

### Proof of Concept
No test was executed against this codebase; the following is the reproduction procedure derived directly from reading the enforcement code, not an executed/validated run:

1. Setup: `real` is a `Signed` account that is the manager of `ParaId(P)` (via `Registrar::reserve`/`register`), and has an active auction/lease-eligible parathread.
2. `real` grants `delegate` a `ProxyType::NonTransfer` proxy: `Proxy::add_proxy(real, delegate, NonTransfer, delay=0)`.
3. `delegate` calls `Proxy::proxy(real, Some(NonTransfer), Proxy::add_proxy(delegate2_or_self, Auction, 0))`. This passes `do_proxy`'s injected filter because `NonTransfer.is_superset(Auction) == true` (`polkadot/runtime/westend/src/lib.rs:1027`), even though `NonTransfer::filter` denies `Registrar::swap` directly.
4. `delegate` (now holding an `Auction` proxy for `real`) calls `Proxy::proxy(real, Some(Auction), Registrar::swap(P, other_para))`. This passes because `Auction::filter` admits any `RuntimeCall::Registrar(..)` (`polkadot/runtime/westend/src/lib.rs:1008`).
5. Expected (per `NonTransfer`'s documented intent): `swap` should be unreachable through a `NonTransfer` proxy. Actual: `swap` executes as `real`, via the `Auction` proxy that `NonTransfer` was wrongly permitted to self-grant.

Matching evidence for the analogous, already-fixed case is in `prdoc/pr_12769.prdoc` and the regression test in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2486-2559`, confirming the project treats this class of `is_superset`/`filter` mismatch as a genuine security defect warranting a dedicated fix and lattice-wide regression test — a test of that kind is absent for the Westend/Rococo relay-chain `ProxyType` shown here.

	/// Ensure the origin is one of Root, the `para` owner, or the `para` itself.

			if para_info.manager == who {

				return Ok(());
			}
		}

		Self::ensure_root_or_para(origin, id)
	}

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
