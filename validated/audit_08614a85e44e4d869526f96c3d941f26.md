### Title
Cross-org webhook forgery via `webhook_secret`-absent org selection bypasses HMAC verification and mutates an unrelated repository's stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`verify_signature` picks which GitHub App/org config (and thus which `webhook_secret`) to verify against using the **unverified** `repository.owner.login` field, while the actual mutation target used by every webhook handler is derived independently from `repository.full_name`. Because `GitHubApp#verify_webhook_signature` returns `true` whenever the selected org has no `webhook_secret` configured, an attacker who knows that any one configured org in a multi-org Shipit install has a blank `webhook_secret` can forge a webhook whose `repository.owner.login` points at that unprotected org while `repository.full_name` names a completely different repository/stack, causing an unauthenticated write against a tenant that never authenticated the request.

### Finding Description
Binding claimed to hold: `org used to pick webhook_secret for HMAC verification == org that owns the row mutated by the handler`.

Trace:
- `repository_owner` is computed straight from the raw, unauthenticated JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) .
- That value selects the `GitHubApp` instance, and therefore the `webhook_secret`, used for verification: `github_app = Shipit.github(organization: repository_owner)` followed by `github_app.verify_webhook_signature(...)` [2](#0-1) .
- `verify_webhook_signature` short-circuits to `true` when the selected org has no secret configured: `return true unless webhook_secret` [3](#0-2) .
- Meanwhile, every handler resolves the repository/stack to mutate using `payload.dig('repository', 'full_name')` — a field entirely disconnected from `repository.owner.login`: `repository_name` in the base `Handler` class [4](#0-3) , and concretely in `ClosedHandler#repository`, which does `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .

Attacker request: POST `/webhooks` with `X-Github-Event: pull_request`, any `X-Hub-Signature` value, and a JSON body where `repository.owner.login` = `"orgB"` (an org configured in `Shipit.github_setup` with no `webhook_secret`) and `repository.full_name` = `"orgA/target-repo"` (the real victim repository, belonging to a different, properly-secured org). `verify_signature` resolves `Shipit.github(organization: "orgB")`, whose `webhook_secret` is blank, so verification returns `true` regardless of the actual, unmatched signature. The request proceeds to `create`, which dispatches to handlers keyed purely off `full_name`, so `ClosedHandler` (or any other handler) mutates `orgA/target-repo`'s stack — a repository whose real `webhook_secret` was never checked.

Existing guards don't prevent this: `drop_unhandled_event` only filters by event type, not by org; `ExplicitParameters` schemas validate structure/types, not cross-field consistency between `owner.login` and `full_name`; `GithubOrganizationUnknown` only guards against *unconfigured* orgs, not against configured-but-secretless orgs, which is exactly the exploited case.

### Impact Explanation
An attacker forges an accepted webhook (authentication bypass) and causes a write (e.g., PR-closed archiving a review stack, PR-opened/label handlers creating or mutating review stacks, commits) against a repository/stack belonging to an org whose signature was never actually checked. This is a payload for one (secretless) org mutating a different org's stack — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team" / "forged webhook accepted." The blast radius spans every stack whose repository is registered under any org configured without a `webhook_secret`, and the attack is trivially repeatable against arbitrary target repositories by only changing `full_name` in the JSON body each time.

### Likelihood Explanation
Preconditions: the Shipit multi-org configuration must include at least one org entry (in `Shipit.github_setup`) with a blank/absent `webhook_secret` — a real, documented misconfiguration state supported by the code (`@webhook_secret = @config[:webhook_secret].presence`, which is legitimately nil-able) rather than a hypothetical. No GitHub secrets, session, or API token is required; only knowledge that such an org exists, which is discoverable via repeated probing (any org with an unset secret makes every signature attempt on that org key succeed). Given that, the attack is a single unauthenticated HTTP POST, fully repeatable and cheap.

### Recommendation
Decouple the org used for signature selection from any field that also drives handler routing, and never allow a "secretless" org config to make signature verification return `true` unconditionally — treat a missing `webhook_secret` as a hard misconfiguration (raise/log and reject) rather than as an implicit bypass. Additionally, validate that `repository.full_name`'s owner matches `repository.owner.login` (or `organization.login`) before dispatching, and verify against the org actually implied by `full_name`, not a separately attacker-suppliable field.

### Proof of Concept
```ruby
test "webhook with mismatched repository.full_name vs repository.owner.login does not mutate unrelated org's stack" do
  # Setup: two orgs configured, "orgB" has NO webhook_secret (misconfiguration), "orgA" has a real secret.
  Shipit.github_setup = {
    'orgA' => { webhook_secret: 'realsecret', app_id: 1, installation_id: 1, private_key: TEST_KEY },
    'orgB' => { app_id: 2, installation_id: 2, private_key: TEST_KEY } # no webhook_secret
  }

  stack = shipit_stacks(:shipit) # belongs to repo under "orgA"
  review_stack = create_review_stack(stack) # simulate an open review stack to be archived

  payload = {
    action: 'closed',
    number: 1,
    pull_request: { id: 1, number: 1, url: '...', title: 't', state: 'closed',
                     additions: 0, deletions: 0,
                     head: { sha: 'abc', ref: 'branch' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { full_name: 'orgA/target-repo', owner: { login: 'orgB' } }, # mismatch
    sender: { login: 'attacker' }
  }.to_json

  post shipit.webhooks_path,
       params: payload,
       headers: {
         'X-Github-Event' => 'pull_request',
         'X-Hub-Signature' => 'sha1=deadbeef', # bogus, never matches orgA's real secret
         'Content-Type' => 'application/json'
       }

  # Equality check BEFORE: org selected for verification ("orgB") != org owning mutated repo ("orgA")
  # Equality check AFTER: must still be false for safety, i.e. request must be rejected.
  assert_response :unprocessable_entity, "signature verification must fail; org selected for HMAC != org owning the target repo"
  assert_not review_stack.reload.archived?, "no cross-org mutation of orgA's stack should occur from an orgB-signed (secretless) payload"
end
```
If, instead, the response is `200 OK` and `review_stack` becomes archived, the divergence is proven exploitable and the finding stands as Critical.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
