## Title
Asset holders permanently lose the ability to move a `spender_attested` asset once the definer updates the attestor list, freezing already-issued balances - ([File: validation.js])

### Summary
Obyte assets can be defined with `spender_attested: true`, which requires every *output* address of a payment in that asset to be currently attested by one of the asset's attestors [1](#0-0) . The attestor list is not fixed at asset-definition time — the definer can freely replace it later via an `asset_attestors` message [2](#0-1) . Because attestation status is evaluated against the *current* (latest, stable) list at the time of each subsequent transfer, addresses that legitimately received the asset while attested can be retroactively excluded, after which they can never again produce a valid output for that asset — not even to themselves. This mirrors the reported bug class where removing an item from a mutable allow-list makes already-deposited/held funds permanently non-withdrawable for the "last holders."

### Finding Description
When validating a payment in a `spender_attested` asset, `validatePaymentInputsAndOutputs` requires that **all** output addresses be attested as of `last_ball_mci`: [1](#0-0) 

`storage.filterAttestedAddresses` determines attestation status purely from the *current* set of attestor addresses passed in via `objAsset.arrAttestorAddresses`, which is populated by `readAsset`/`loadAssetWithListOfAttestedAuthors` using the **latest** `asset_attestors` unit for that asset (i.e., whichever attestor list is currently in force), not the list that was active when the holder originally received the funds: [3](#0-2) [4](#0-3) 

The attestor list itself can be replaced at will by the asset's definer with only two checks — the update must come from `objAsset.definer_address`, and the new list must be non-empty and sorted (`checkAttestorList`): [5](#0-4) 

There is no mechanism analogous to "grandfathering" or allowing existing holders one final withdrawal window when they are dropped from the list — every future transfer (including a self-transfer/change output) for a dropped holder will fail the "some output addresses are not attested" check, exactly like the reported UXDController bug where an asset removed from the whitelist can never again pass `redeem`'s whitelist check.

### Impact Explanation
Because the attestor check applies to **outputs**, not just newly-issued authors, an address that legitimately holds an attested asset can be locked out of spending its own balance entirely once the definer updates the attestor list to exclude it (or narrows the list to only the definer's own address). The holder cannot send the balance anywhere — not to another attested party, not back to itself — because every candidate output address must independently satisfy attestation. This is a definer-controlled fund freeze of already-issued, legitimately-held asset balances, matching the High-severity impact described in the report (assets that were valid at deposit time become permanently stuck once removed from the controlling allow-list).

### Likelihood Explanation
Any asset issuer can create a `spender_attested` asset and unilaterally control the attestor list from then on via a simple `asset_attestors` message that only requires being the definer address [6](#0-5) . No special privileges beyond being the asset's own definer are needed, and the same primitive (`asset_attestors`) is explicitly supported for AA-issued assets as well (`case 'asset_attestors'` in `aa_validation.js`), so an AA-defined asset can trigger the same freeze programmatically for any address the AA (or its owner) chooses to exclude.

### Recommendation
When validating whether output addresses are attested for a transfer, evaluate attestation status against the attestor list that was in effect either (a) at the time the spender's *input* balance was originally received/attested, or (b) allow spending to be validated if the address was ever attested up to the point it held the balance, rather than requiring attestation under the list currently in force at transfer time. Alternatively, disallow shrinking/replacing the attestor list in a way that excludes addresses that currently hold nonzero balances of the asset, or provide holders a grace period/explicit exit path (e.g., allow a removed address to always be a valid output for its own pre-existing balance) so that funds legitimately acquired cannot become permanently unspendable.

### Proof of Concept
1. Definer D creates asset A with `spender_attested: true`, initial `attestors: [D, X]`.
2. Attestor X attests address B. D issues/transfers units of asset A to B; validation succeeds because B is attested under the current list (`filterAttestedAddresses` finds B via attestor X) — passes the check at [7](#0-6) .
3. D later posts an `asset_attestors` message for asset A with a new list `attestors: [D]` only (valid per `validateAttestorListUpdate`, since D is the definer and the list is non-empty/sorted) [2](#0-1) .
4. B now attempts to transfer (or send change to itself) any amount of asset A. `readAsset` loads the new (latest) attestor list `[D]` [8](#0-7) , and `filterAttestedAddresses` finds no attestation of B by D, so `arrAttestedOutputAddresses.length !== arrOutputAddresses.length` and the unit is rejected with "some output addresses are not attested" [9](#0-8) .
5. B's entire balance of asset A is now permanently unspendable, regardless of destination, purely due to a definer-controlled list update — no code path allows B to recover or move the funds.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}
