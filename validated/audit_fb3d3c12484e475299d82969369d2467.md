### Title
Webhook signature verification selects the wrong GitHub App secret from unverified payload data, allowing cross-organization forged events - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which `GitHubApp` (and thus which `webhook_secret`) to use for HMAC verification based on `repository_owner`, a value read straight out of the still-unverified JSON body. The event handlers that subsequently mutate application state (`PushHandler`, `StatusHandler`, `MembershipHandler`, etc.) resolve their target `Stack`/`Commit`/`Team` from a *different* field of that same unverified body (`repository.full_name`, `sha`, `organization.login`) without ever re-checking that it belongs to the organization whose secret actually validated the signature. This breaks the binding: "organization whose webhook secret authenticated the request" == "organization/repository whose state the handler mutates."

### Finding Description
`Shipit::WebhooksController` runs `verify_signature` as a `before_action`: [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  # Fallback to the organization sub-object if repository isn't included in the payload
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`repository_owner` is fully attacker-controlled: it is read from the JSON body *before* the signature has been validated. Shipit supports hosting multiple GitHub organizations, each with its own `GitHubApp` config and (optional) `webhook_secret`: [3](#0-2) 

`GitHubApp#verify_webhook_signature` vacuously returns `true` whenever no secret is configured for that organization: [4](#0-3) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

Meanwhile, every `Handler` resolves the actual target of the event from a field of the payload that is never cross-checked against `repository_owner`: [5](#0-4) 

```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
```

`StatusHandler` is even less scoped — it matches on the SHA alone, across every `Stack` in the installation: [6](#0-5) 

`PushHandler` triggers a GitHub sync for whatever stack matches `repository.full_name`: [7](#0-6) 

Because `repository_owner` (used to choose the verifying secret) and `repository.full_name` / `sha` (used to choose the mutated state) are independent, attacker-controlled fields of the same unverified JSON body, an attacker who can produce a valid signature for *any one* configured organization (e.g. one that intentionally has no `webhook_secret` set, or whose secret has leaked) can set `repository.owner.login`/`organization.login` to that weakly-secured org while setting `repository.full_name`/`sha` to point at a Stack or commit that actually belongs to a completely different, properly-secured organization hosted on the same Shipit instance. The request passes `verify_signature` (verified against the wrong org's key) and is then dispatched to handlers that blindly act on the victim org's data.

### Impact Explanation
This allows forging GitHub webhook events (`push`, `status`, `membership`, `pull_request`) targeting a victim organization's `Stack`/`Commit`/`Team` records using only the credentials (or lack thereof) of an unrelated, weaker organization configured on the same Shipit instance. Concretely:
- `StatusHandler` lets an attacker post arbitrary CI status (`success`/`failure`, description, `target_url`) for **any commit sha in the database**, regardless of which org's secret validated the request. Forging a fake "success" status can make an otherwise-unreviewed commit `deployable?`, feeding directly into merge-queue/deploy eligibility for a repository the attacker never had rights to.
- `PushHandler` can trigger `stack.sync_github` for arbitrary victim stacks.
- `MembershipHandler` mutates `Team`/`Membership` records tied to `Shipit.github_teams` authorization, using organization/team data taken from the same unverified payload.

This is a cross-organization/cross-repository write achieved by defeating the authentication binding between "who signed this webhook" and "what state gets changed," fitting the Critical "cross-repository writes" / "unauthorized deploy, rollback or merge" impact bar.

### Likelihood Explanation
Exploitability requires the target Shipit instance to be configured for multiple GitHub organizations (an officially documented and supported configuration — `docs/setup.md`, "Using Multiple Github Applications") where at least one configured organization has no `webhook_secret` set (also officially documented as "optional") or a secret the attacker can obtain. Given webhook secrets are explicitly optional and multi-org hosting is a first-class documented feature, this is a realistic deployment scenario, not a hypothetical one.

### Recommendation
- After signature verification succeeds, re-derive the acting organization strictly from the verified `GitHubApp`'s own configured organization, and require every handler to confirm that the `Repository`/`Stack`/`Team` it is about to mutate actually belongs to that same organization before applying any change.
- Reject events outright if `repository.owner.login`/`organization.login` used for secret selection does not match the resolved `Repository#owner` of `repository.full_name` (or the `Team#organization` for membership events).
- Do not allow `verify_webhook_signature` to return `true` for organizations lacking a `webhook_secret` when the instance hosts more than one organization; consider requiring a secret whenever `github_organizations` has more than one entry.

### Proof of Concept
1. Configure Shipit with two organizations: `weak-org` (no `webhook_secret`) and `victim-org` (secured, hosting a private `Stack`/commit).
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "repository": { "owner": { "login": "weak-org" }, "full_name": "irrelevant/anything" },
  "sha": "<victim-org commit sha>",
  "state": "success",
  "context": "ci/tests",
  "target_url": "https://attacker.example"
}
```
No `X-Hub-Signature` header is required (or any arbitrary value works), because `verify_signature` resolves `Shipit.github(organization: 'weak-org')`, whose `verify_webhook_signature` returns `true` unconditionally (`webhook_secret` is nil).
3. `Shipit::Webhooks::Handlers::StatusHandler#process` runs `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`, writing a forged "success" status onto the victim-org commit — with the request never having been authenticated by `victim-org`'s secret at all.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
