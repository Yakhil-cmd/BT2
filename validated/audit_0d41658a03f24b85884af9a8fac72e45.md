### Title
Attacker-Controlled `NType=NodeTypeBN` in NEIGHBORS Response Injects Nodes into All Four Discovery Storages — (`networks/p2p/discover/table_data.go`, `table_lookup.go`, `udp.go`)

### Summary
A bonded peer (any node that completes a ping/pong handshake) can return a NEIGHBORS packet with `rn.NType = NodeTypeBN` for attacker-controlled nodes. Because `nodeFromRPC` passes `rn.NType` directly to `NewNode` without validation, and because `findNodesOnce` only calls `removeBn()` when `targetType != NodeTypeBN`, attacker nodes survive the filter during BN lookups. After bonding succeeds, `addNode` inserts them into all four per-type storages (CN, PN, EN, BN), corrupting `RandomNodes` output for every type.

### Finding Description

`nodeFromRPC` in `udp.go` constructs a node directly from wire data:

```go
n := NewNode(rn.ID, rn.IP, rn.UDP, rn.TCP, nil, rn.NType)
``` [1](#0-0) 

No check is performed on `rn.NType`. The only guard against BN-typed nodes appearing in non-BN lookups is `removeBn`, called conditionally in `findNodesOnce`:

```go
if targetType != NodeTypeBN {
    r = removeBn(r)
}
return tab.bondall(r)
``` [2](#0-1) 

When `targetType == NodeTypeBN`, this filter is skipped entirely. BN lookups are triggered for every node type via `doRefresh`:

```go
tab.simpleRefresh(NodeTypeBN)
``` [3](#0-2) 

All node types have `discoverTargets[NodeTypeBN] = 3`, so this path is always active: [4](#0-3) 

Once `bondall` succeeds (attacker's node responds to ping), `Bond` calls `addNode(n)`: [5](#0-4) 

`addNode` unconditionally inserts into all four storages when `NType == NodeTypeBN`:

```go
if n.NType == NodeTypeBN {
    for _, s := range tab.storages {
        s.add(n)
    }
``` [6](#0-5) 

The four storages are CN, PN, EN, and BN: [7](#0-6) 

### Impact Explanation

`RandomNodes(buf, targetType)` reads directly from `tab.storages[targetType]`: [8](#0-7) 

After injection, attacker-controlled nodes appear in `RandomNodes` results for every type (CN, PN, EN, BN). The p2p dial scheduler uses these results to establish outbound connections. With enough injected nodes, the victim's entire outbound peer set can be eclipsed, causing it to receive blocks and trie data exclusively from attacker-controlled peers. This enables consensus divergence (chain split) on the honest victim node.

### Likelihood Explanation

- **Attacker prerequisite**: Only a completed UDP ping/pong bond is required — a permissionless P2P operation available to any internet-reachable node.
- **Trigger frequency**: BN lookups run every 30 minutes (`refreshInterval`) for every node type, giving repeated opportunities.
- **No cryptographic break required**: The attacker signs their own valid discovery packets; only the `NType` field is forged.
- **Amplification**: A single bonded attacker peer can inject up to `maxNeighbors` nodes per NEIGHBORS packet, each with `NType=NodeTypeBN`.

### Recommendation

In `nodeFromRPC`, reject or sanitize `rn.NType` values that cannot be verified from the wire. Specifically, never accept `NodeTypeBN` from a NEIGHBORS response — bootstrap node status must be established from the local configuration (`cfg.Bootnodes`), not from peer-supplied data. A minimal fix:

```go
// In nodeFromRPC, after constructing n:
if n.NType == NodeTypeBN {
    n.NType = NodeTypeUnknown // or reject with an error
}
```

Alternatively, `addNode` should cross-check against `tab.nursery` before treating any dynamically discovered node as a bootstrap node.

### Proof of Concept

1. Start a victim node (any type).
2. Bond an attacker node with the victim via normal UDP ping/pong.
3. When the victim sends `FINDNODE` with `TargetType=NodeTypeBN`, respond with a NEIGHBORS packet containing attacker-controlled node entries with `NType=NodeTypeBN`.
4. The attacker's node responds to the victim's bonding ping.
5. After `Bond` completes, inspect `tab.storages[NodeTypeCN]`, `[NodeTypePN]`, `[NodeTypeEN]`, `[NodeTypeBN]` — the attacker's node appears in all four.
6. `RandomNodes` for any type now returns the attacker's node.
