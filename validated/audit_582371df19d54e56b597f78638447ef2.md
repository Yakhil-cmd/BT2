## Title
Webhook signature verification is scoped by an attacker-controlled `repository.owner.login`, while writes are scoped by a different, unverified `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

## Summary
`WebhooksController#verify_signature` selects which GitHub organization's `webhook_secret` to validate the HMAC signature against using `repository_owner`, a field read directly from the untrusted JSON body. Every webhook handler, however, resolves the `Stack`/`Repository` it will mutate using a *different* field from the same untrusted body: `repository.full_name`. Because these two fields are never checked for consistency, and because signature verification is a no-op whenever a configured organization has no `webhook_secret` (a supported, documented configuration, see `config/secrets.development.shopify.yml`), an attacker can craft one payload that authenticates as an unsecured/known organization while writing to a Stack belonging to an entirely different repository/organization.

## Finding Description
The binding that should hold is:

`organization used to compute the HMAC that authenticated the payload == organization/repository that the payload is allowed to mutate`

`WebhooksController#verify_signature` computes the org to check against like this: [1](#0-0) 

and `repository_owner` is taken straight from the parsed, unauthenticated body: [2](#0-1) 

`verify_webhook_signature` explicitly short-circuits to `true` when the resolved organization has no `webhook_secret` configured: [3](#0-2) 

Multi-organization configuration, including organizations with a `nil` webhook secret, is a first-class, documented setup (`Shipit.github(organization:)`), as shown in the sample secrets file: [4](#0-3) 

Once `verify_signature` passes, the full raw payload (including any attacker-controlled `repository.full_name`) is dispatched to handlers, unmodified: [5](#0-4) 

Every handler, however, resolves the actual `Repository`/`Stack` to act on using a *separate* field, `repository.full_name`, from that same payload: [6](#0-5) 

`PushHandler`, for instance, uses this repository resolution to find every non-archived Stack on the matching branch and forces it to sync to an attacker-chosen `after` SHA: [7](#0-6) 

So the field that is authenticated (`repository.owner.login` / `organization.login`, used only to pick a webhook secret) is never the field that is acted upon (`repository.full_name`, used to select which `Stack` gets synced/mutated). An attacker only needs the payload to name, as its "owner", any organization that Shipit has configured with a blank/`nil` `webhook_secret` (which `verify_webhook_signature` explicitly treats as "always verified") — while setting `repository.full_name` to point at a Stack belonging to a completely different, secured organization.

## Impact Explanation
This breaks the "organization authenticated vs. repository written" binding called out in scope. A forged `push` event lets an unauthenticated external actor force `Stack#sync_github` on a Stack it has no relationship to, with an attacker-chosen `expected_head_sha`. For stacks configured with `continuous_deployment` enabled (a documented Shipit feature), a forged sync of a new/attacker-desired revision can result in an unauthorized deploy being triggered without ever presenting a valid signature for the organization that owns the targeted Stack. This matches the in-scope "unauthorized deploy" impact category.

## Likelihood Explanation
Any Shipit installation that manages more than one GitHub organization, and where at least one configured organization has no `webhook_secret` (an explicitly supported and documented configuration, not a coding error), is exposed. The attacker does not need any credential, session, or repository access — only the ability to send an HTTP request that satisfies the `verify_signature` `before_action`. This is a design flaw in the controller's field selection, not a misuse of a private key or secret, so the likelihood is high wherever this legitimate multi-org configuration pattern is used.

## Recommendation
Bind signature verification to the same repository identity that handlers act on: derive both `repository_owner` (for choosing the webhook secret) and the mutated `Repository`/`Stack` from a single, consistent field (e.g. `repository.full_name`), and reject payloads where `repository.owner.login`/`organization.login` doesn't match the owner segment of `repository.full_name`. Additionally, disallow (or at minimum warn strongly against) configuring an organization with a blank `webhook_secret` while other organizations are configured with one, since this makes `verify_webhook_signature`'s `return true unless webhook_secret` a universal bypass for any payload that merely names that organization as owner.

## Proof of Concept
1. Shipit is configured for two GitHub orgs: `org-empty` (no `webhook_secret` set, as in `config/secrets.development.shopify.yml`) and `org-secured` (a real, secret-protected org that owns a monitored Stack, e.g. `org-secured/app` on `main`).
2. Attacker sends `POST /webhooks` with header `X-Github-Event: push` and any/no valid `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "org-empty" },
    "full_name": "org-secured/app"
  }
}
```
3. `verify_signature` calls `repository_owner`, which returns `"org-empty"`, looks up `Shipit.github(organization: "org-empty")`, and `verify_webhook_signature` returns `true` immediately because that org's `webhook_secret` is blank — no valid signature is required at all.
4. `Shipit::Webhooks.for_event('push')` dispatches the full payload to `PushHandler`, which resolves the target Stack via `repository.full_name` = `"org-secured/app"`, and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on the secured org's Stack — a Stack the attacker never authenticated against.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
