### Title
Position NFT transferred to a contract that cannot authorize permanently freezes the entire lending account and its collateral - ([File: contracts/position-nft/src/contract.rs](contracts/position-nft/src/contract.rs))

### Summary
In XOXNO Lending, `account_id == token_id`: ownership of a lending account is defined solely by `PositionNft::owner_of`, which the controller reads live on every owner-gated call (`withdraw`, `borrow`, delegate management, etc.). The collection exposes the stock OpenZeppelin `stellar-tokens` `NonFungibleToken` entrypoints `transfer` and `transfer_from` unchanged. Neither performs any check that `to` is able to authorize future calls — there is no receiver-consent hook in the Soroban NFT flow (the direct analog of ERC721 `transferFrom` lacking `onERC721Received`). A holder who transfers their position NFT to a contract address that has no code path to call `require_auth`/`transfer`/`withdraw` permanently locks the whole account: collateral cannot be withdrawn and the token cannot be moved again.

### Finding Description
`PositionNft` deploys OZ `NonFungibleToken` with `ContractType = Enumerable` and exports `transfer`/`transfer_from` without modification [1](#0-0) . The controller stores no owner; `try_account_owner` calls `owner_of(account_id)` live, so whoever the NFT names is the account owner [2](#0-1) . All value-moving verbs (`withdraw`, `borrow`, `add_delegate`) authenticate against that live owner — the integration test confirms the previous holder is rejected with `Error(Contract, #44)` (NotAuthorized) immediately after transfer [3](#0-2) . The `update` path inside `transfer`/`transfer_from` only enforces that `from` is the current owner and that the spender is authorized; `to` is written as the new `Owner(token_id)` unconditionally [4](#0-3) . Neither the NFT contract nor the controller restricts `to` to non-contract addresses, and no `create_account`/`supply(account_id = 0)` path prevents minting to a contract caller either [5](#0-4) . Only the controller can `burn`, and it burns only after the account's entries are deleted — an owner-gated operation the frozen contract cannot initiate [4](#0-3) .

### Impact Explanation
Permanent freezing of user funds. Because the NFT *is* the account, a transfer to an incapable contract freezes all supplied collateral: no address can authorize `withdraw`, and no protocol mechanism exists to reclaim the position (no admin sweep; `burn` is controller-only and runs only after account deletion). If the account carries debt, anyone can `repay` and it can still be `liquidate`d when HF < 1, so debt does not create insolvency; but a supply-only account's collateral is unrecoverable forever. This mirrors the reported bug exactly, except here the entire lending position (all collateral assets across all hubs) is lost rather than a single ERC721.

### Likelihood Explanation
Reachable by a single unprivileged address via `position-nft::transfer(from, to, token_id)` or `transfer_from(spender, from, to, token_id)` where `to` is a contract without NFT/controller-handling logic — a realistic outcome when positions are deposited into marketplaces, vaults, or multisig wrappers that do not implement XLEND-specific forwarding (the test suite itself shows contracts routinely hold and move positions, e.g. `FlashPositionTestReceiver` transferring the NFT mid-callback [6](#0-5) ). Requires user error (choosing a bad `to`), hence Medium rather than High — consistent with the source finding's severity.

### Recommendation
Enforce that the recipient of a position can actually operate it: e.g. have `create_account`/`supply(account_id = 0)` require that `caller` is an account (non-contract) address, or — since Soroban contracts prove capacity via auth — require the receiving contract to authorize the transfer by having `transfer`/`transfer_from` wrap the move in `to.require_auth()` (recipient-consent pattern, the Soroban equivalent of `safeTransferFrom`). Alternatively expose a dedicated two-step handover (`transfer_offer`/`claim`) so ownership only moves once the recipient proves control.

### Proof of Concept
1. Alice calls `controller::supply(caller = alice, account_id = 0, ...)`; controller mints NFT id `N` to Alice (`PositionNft::mint`).
2. Alice supplies 10,000 USDC collateral to account `N` (supply-only, no debt).
3. Alice calls `position-nft::transfer(from = alice, to = C, token_id = N)` where `C` is any contract with no code path invoking `require_auth` on its own address or calling `controller::withdraw`/`position-nft::transfer`.
4. `owner_of(N)` now returns `C`. Alice's `controller::withdraw(caller = alice, account_id = N, ...)` reverts `NotAuthorized` — exactly as the old owner is rejected in `nft.sh` [7](#0-6) .
5. No entrypoint lets `C` move the token or withdraw; `burn` is controller-gated and the controller only burns during owner-initiated account deletion. The collateral backing account `N` is permanently frozen.

        renew_instance(e);
        let owner = Base::owner_of(e, token_id);
        Base::update(e, Some(&owner), None, token_id);
