**Rationale:** The `ecrecover()`/signer-address-zero bug class requires manual ECDSA signature recovery logic in-program (as in the Solidity example, where `ecrecover` can return `address(0)` for invalid signatures and that unchecked zero-address result is treated as a valid signer). The Raydium CP-Swap program is an Anchor/Solana program, and none of the in-scope, unprivileged-reachable instructions (`initialize`, `initialize_with_permission`, `deposit`, `withdraw`, `swap_base_input`, `swap_base_output`, `collect_creator_fee`, `collect_creator_fee_permissionless`) perform any manual signature recovery or `ecrecover`-style verification. Solana's `secp256k1`/`libsecp256k1` dependencies appear only transitively in `Cargo.lock` [1](#0-0) [2](#0-1) , and the only textual "signature" occurrences in the on-chain program source (`oracle.rs`, `pool.rs`) are unrelated to cryptographic signature recovery — they are single incidental matches in comments/doc strings, not signer-verification logic [3](#0-2) [4](#0-3) . Account/PDA authorization in this program instead relies on Anchor account constraints and the `AUTH_SEED` PDA signing convention, not on manually-recovered ECDSA signer addresses, so there is no reachable analog to the reported bug class within the allowed scope.
