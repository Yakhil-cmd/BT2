The external report concerns a DeFi contract (`PaprController`) lacking deadline parameters on Uniswap V3 swap-executing functions, allowing MEV bots to exploit stale slippage limits on long-pending transactions. Nearcore has no analogous concept of AMM swaps, slippage limits, or price-based MEV sandwiching — it is a blockchain execution layer, not a DeFi protocol.

Moreover, the core issue the report describes — “no deadline for pending transactions” — is not applicable to nearcore because nearcore transactions already carry an implicit deadline via the block hash anchor and `transaction_validity_period`: transactions become `InvalidTxError::Expired` once too many blocks pass beyond their anchoring block hash. [1](#0-0)  This mechanism is exercised in `test_expired_tx`, which confirms that stale/pending transactions using an old block hash are rejected outright rather than executed with outdated parameters. [2](#0-1)  There is also a dedicated fork-based test validating this expiry boundary behavior. [3](#0-2) 

Since nearcore has no swap/AMM/slippage surface and already enforces a deadline-equivalent (block-hash-based transaction validity period) that rejects stale transactions rather than allowing them to execute with outdated parameters, there is no reachable, in-scope analog to this bug class.

/// Test that expired transaction should be rejected
#[tokio::test]
async fn test_expired_tx() {
    // Create setup with very short transaction validity period (1 block)
    let accounts = vec!["test1".parse().unwrap(), "test2".parse().unwrap()];
    let setup = create_test_setup_with_accounts_and_validity(
        accounts,
        "test1".parse().unwrap(),
        "test1".parse().unwrap(),
        1, // Very short validity period
    );
    let client = new_client(&setup.server_addr);

    // Get initial block info
    let initial_block = client.block(BlockReference::latest()).await.unwrap();
    let old_block_hash = initial_block.header.hash;

    // Wait for at least 2 more blocks to be produced so transaction becomes expired
    wait_or_timeout(100, 10000, || async {
        let current_block = client.block(BlockReference::latest()).await.unwrap();
        if current_block.header.height >= initial_block.header.height + 2 {
            ControlFlow::Break(())
        } else {
            ControlFlow::Continue(())
        }
    })
    .await
    .expect("Should produce at least 2 more blocks");

    // Try to send transaction with the old block hash (should be expired)
    let signer = InMemorySigner::test_signer(&"test1".parse().unwrap());
    let tx = SignedTransaction::send_money(
        1,
        "test1".parse().unwrap(),
        "test2".parse().unwrap(),
        &signer,
        Balance::from_yoctonear(100),
        old_block_hash,
    );
    let bytes = borsh::to_vec(&tx).unwrap();

    // This should fail with "Expired" error
    match client.broadcast_tx_commit(to_base64(&bytes)).await {
        Err(err) => {
            assert_eq!(
                *err.data.unwrap(),
                serde_json::json!({"TxExecutionError": {
                    "InvalidTxError": "Expired"
                }})
            );
        }
        Ok(_) => panic!("Expected transaction to be rejected as expired"),
    }
}
