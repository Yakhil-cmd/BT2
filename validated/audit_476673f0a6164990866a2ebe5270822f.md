### Title
Unsanitized attestation `Subject.Name`/digest rendered via `tableprinter` in `printVerifiedSubjects` enables terminal escape-sequence injection - ([File: pkg/cmd/release/verify/verify.go])

### Summary
`printVerifiedSubjects` reads `s.Name` and the constructed `digestStr` directly from the verified in-toto `Statement.Subject` list and passes them unsanitized to `table.AddField`/`table.Render`, which write to `io.Out`. Unlike other output paths in this codebase (e.g. `pkg/iostreams/untrusted.go`, `pkg/cmd/gist/view/view.go`, `pkg/cmd/skills/list/list.go`) that explicitly wrap externally-sourced text in `iostreams.Untrusted` or `asciisanitizer` before printing to a terminal, this function performs no such sanitization.

### Finding Description
`verifyRun` calls `config.AttVerifier.VerifyAttestation` [1](#0-0)  and then unconditionally passes the result to `printVerifiedSubjects` [2](#0-1) . Inside `printVerifiedSubjects`, the DSSE payload is unmarshaled into an in-toto `v1.Statement`, and for each `Subject`, `s.Name` and a digest string are added directly as table fields and rendered to `io.Out` with no escaping or control-character stripping: [3](#0-2) .

The verification policy only pins the Sigstore/Fulcio certificate identity to GitHub's release-signing SAN (`^https://<trustdomain>\.releases\.github\.com$`) via `buildVerificationPolicy` [4](#0-3) ; it does not constrain or sanitize the *content* of `Subject.Name` within the signed statement. If GitHub's release-attestation generation embeds the release asset's own filename (attacker-controlled at upload time) as the subject name, an attacker who publishes a release with a maliciously-named asset (e.g. containing `\x1b[2K\r` or OSC sequences) could cause that raw string to flow, still under a validly-signed attestation, into `printVerifiedSubjects` and onto the victim's terminal unescaped.

This contrasts with the codebase's established output-safety convention: `iostreams.Untrusted.String()` sanitizes ANSI/control sequences automatically on any `fmt` print path [5](#0-4) , and multiple other commands (`gist view`, `skills list`, `run view`) explicitly sanitize external/attacker-influenced text before writing to `io.Out`/`ContentOut` [6](#0-5) [7](#0-6) . `printVerifiedSubjects` has no equivalent guard.

### Impact Explanation
If exploitable, this would allow terminal spoofing/output manipulation (fake success banners, cursor manipulation, hidden output, or OSC title-bar hijacking) on the victim's terminal when they run `gh release verify` against an attacker-controlled release, which maps to a "terminal escape sequence injection / output spoofing" class finding rather than remote code execution or credential theft.

### Likelihood Explanation
This finding is **conditionally valid but unconfirmed** on two points I could not fully verify with the available tooling:
1. Whether GitHub's server-side release-attestation generation actually places attacker-controlled asset filenames verbatim into `Subject.Name` (this logic is server-side, not in this repo, and not indexed here).
2. Whether the underlying `github.com/cli/go-gh/v2/pkg/tableprinter.AddField/Render` (an external dependency, not part of this repo) performs its own escape-sequence stripping before writing bytes — I could read only the thin repo-local wrapper in `internal/tableprinter/table_printer.go` [8](#0-7) , which does not itself sanitize, but the actual field-writing logic lives in the external dependency I don't have access to.

Because part of the exploit chain depends on server-side attestation content generation (outside this repo) and part depends on an external dependency's internal behavior, I cannot confirm end-to-end exploitability from this repo's code alone.

### Recommendation
Regardless of whether the dependency already sanitizes, apply the codebase's established defense-in-depth pattern: wrap `s.Name` and `digestStr` in `iostreams.NewUntrusted(...)` (or run them through the `asciisanitizer` transform, as done in `pkg/cmd/skills/list/list.go`) before calling `table.AddField`, so the terminal output is safe independent of upstream/dependency guarantees.

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

package tableprinter

import (
	"io"
	"strings"
	"time"

	"github.com/cli/cli/v2/internal/text"
	"github.com/cli/cli/v2/pkg/iostreams"
	"github.com/cli/go-gh/v2/pkg/tableprinter"
)

type TablePrinter struct {
	tableprinter.TablePrinter
	isTTY bool
	cs    *iostreams.ColorScheme
}

// IsTTY gets whether the TablePrinter will render to a terminal.
func (t *TablePrinter) IsTTY() bool {
	return t.isTTY
}

// AddTimeField in TTY mode displays the fuzzy time difference between now and t.
// In non-TTY mode it just displays t with the time.RFC3339 format.
func (tp *TablePrinter) AddTimeField(now, t time.Time, c func(string) string) {
	var tf string
	if tp.isTTY {
		tf = text.FuzzyAgo(now, t)
	} else {
		tf = t.Format(time.RFC3339)
	}
	tp.AddField(tf, WithColor(c))
}

var (
	WithColor    = tableprinter.WithColor
	WithPadding  = tableprinter.WithPadding
	WithTruncate = tableprinter.WithTruncate
)

type headerOption struct {
	columns []string
}

// New creates a TablePrinter from an IOStreams.
func New(ios *iostreams.IOStreams, headers headerOption) *TablePrinter {
	maxWidth := 80
	isTTY := ios.IsStdoutTTY()
	if isTTY {
		maxWidth = ios.TerminalWidth()
	}

	return NewWithWriter(ios.Out, isTTY, maxWidth, ios.ColorScheme(), headers)
}

// NewWithWriter creates a TablePrinter from a Writer, whether the output is a terminal, the terminal width, and more.
func NewWithWriter(w io.Writer, isTTY bool, maxWidth int, cs *iostreams.ColorScheme, headers headerOption) *TablePrinter {
	tp := &TablePrinter{
		TablePrinter: tableprinter.New(w, isTTY, maxWidth),
		isTTY:        isTTY,
		cs:           cs,
	}

	if isTTY && len(headers.columns) > 0 {
		// Make sure all headers are uppercase, taking a copy of the headers to avoid modifying the original slice.
		upperCasedHeaders := make([]string, len(headers.columns))
		for i := range headers.columns {
			upperCasedHeaders[i] = strings.ToUpper(headers.columns[i])
		}

		// Make sure all header columns are padded - even the last one. Previously, the last header column
		// was not padded. In tests cs.Enabled() is false which allows us to avoid having to fix up
		// numerous tests that verify header padding.
		var paddingFunc func(int, string) string
		if cs.Enabled {
			paddingFunc = text.PadRight
		}

		tp.AddHeader(
			upperCasedHeaders,
			WithPadding(paddingFunc),
			WithColor(cs.TableHeader),
		)
	}

	return tp
}

// WithHeader defines the column names for a table.
// Panics if columns is nil or empty.
func WithHeader(columns ...string) headerOption {
	if len(columns) == 0 {
		panic("must define header columns")
	}
	return headerOption{columns}
}

// NoHeader disable printing or checking for a table header.
//
// Deprecated: use WithHeader unless required otherwise.
var NoHeader = headerOption{}
