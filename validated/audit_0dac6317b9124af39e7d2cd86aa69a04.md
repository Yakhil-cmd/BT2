### Title
Unbounded memory allocation via `io.ReadAll` in `fetchRawFile` when downloading large/attacker-controlled files - ([File: pkg/cmd/repo/read-file/http.go])

### Summary
`fetchRawFile` reads the entire HTTP response body into memory with `io.ReadAll(resp.Body)` and no size limit, `http.MaxBytesReader`, or check against `Content-Length`/the previously-fetched `file.Size`. An attacker who controls the repository content (or a GHES-like host the victim points `gh` at) can cause the raw-content response to be arbitrarily large or effectively unbounded (e.g., via chunked transfer-encoding with no `Content-Length`), driving unbounded memory consumption on the victim's machine when they run `gh repo read-file <path> --repo attacker/repo`.

### Finding Description
In [1](#0-0)  `fetchRawFile` issues a GET request with `Accept: application/vnd.github.raw` to the Contents API and returns `io.ReadAll(resp.Body)` directly with no cap. This is invoked from `loadContent` in [2](#0-1)  whenever the earlier `fetchFile`/`fetchContent` call reported `Encoding == "none"` (i.e., the Contents API considered the file "large"), which happens for any file over the 1 MB inline-content threshold — the code path is reachable purely by having a large file in an attacker-controlled repository or ref (including forks and PR branches), no privileges required. Although `contentsResponse.Size` is known before `loadContent` runs (see [3](#0-2) ), that size value is never compared against a limit, nor is the raw-content response bounded independently — an attacker-controlled backend serving that Accept type is not obligated to match the previously reported size at all, so `fetchRawFile` will buffer whatever the server sends, including a very large or effectively unbounded chunked body.

### Impact Explanation
This matches GitHub's "Denial of Service"/resource-exhaustion class rather than remote code execution or credential leakage: a crafted repo/ref/host response can force `gh repo read-file` to allocate memory proportional to an attacker-chosen response size, exhausting RAM or triggering the OS OOM killer on the victim's machine with a single command invocation and no user interaction beyond running the command against attacker-supplied `--repo`/`--hostname` input.

### Likelihood Explanation
Easily reproducible: any attacker who can host a file (or control an API-compatible endpoint the victim points `gh` at with `--repo`/`GH_HOST`) can serve a large or streaming raw-content body. No authentication, elevated privileges, or victim interaction beyond running the ordinary `gh repo read-file` command is required, making this straightforward and repeatable.

### Recommendation
Bound the read with `io.LimitReader` or `http.MaxBytesReader` in `fetchRawFile` (e.g., cap at a sane maximum such as a few hundred MB, or use the previously-fetched `contentsResponse.Size` plus a safety margin) and return a clear error when the limit is exceeded, rather than calling `io.ReadAll` unconditionally.

### Proof of Concept
```go
func TestFetchRawFile_UnboundedBody(t *testing.T) {
    reg := &httpmock.Registry{}
    defer reg.Verify(t)
    reg.Register(
        httpmock.REST("GET", "repos/attacker/repo/contents/bigfile"),
        func(req *http.Request) (*http.Response, error) {
            pr, pw := io.Pipe()
            go func() {
                buf := bytes.Repeat([]byte("A"), 1<<20) // 1MB chunk
                for {
                    if _, err := pw.Write(buf); err != nil {
                        return
                    }
                }
            }()
            return &http.Response{
                StatusCode: 200,
                Body:       pr,
                Header:     http.Header{"Content-Type": {"application/vnd.github.raw"}},
                // no Content-Length -> chunked, effectively unbounded
            }, nil
        },
    )
    httpClient := &http.Client{Transport: reg}
    repo, _ := ghrepo.FromFullName("attacker/repo")
    done := make(chan error, 1)
    go func() {
        _, err := fetchRawFile(httpClient, repo, "bigfile", "")
        done <- err
    }()
    select {
    case <-done:
        t.Fatal("fetchRawFile returned/consumed unbounded stream without a size limit")
    case <-time.After(5 * time.Second):
        // expected: still reading indefinitely / memory growing unbounded, demonstrating no cap exists
    }
}
```
Expected assertion: with a fix (`io.LimitReader`/`http.MaxBytesReader`), `fetchRawFile` should return a bounded-size error quickly instead of reading indefinitely.

// fetchRawFile retrieves the raw bytes of a file, used for files larger than the
// 1 MB inline content limit of the Contents API.
func fetchRawFile(httpClient *http.Client, repo ghrepo.Interface, filePath, ref string) ([]byte, error) {
	apiPath, err := contentsAPIPath(repo, filePath, ref)
	if err != nil {
		return nil, err
	}

	req, err := http.NewRequest("GET", apiPath.String(), nil)
	if err != nil {
		return nil, err
	}
	req.Header.Set("Accept", "application/vnd.github.raw")

	resp, err := httpClient.Do(req)
	if err != nil {
		return nil, err
	}
	defer resp.Body.Close()

	if resp.StatusCode > 299 {
		return nil, api.HandleHTTPError(resp)
	}

	return io.ReadAll(resp.Body)
}

func loadContent(httpClient *http.Client, repo ghrepo.Interface, file *repoFile, ref string) error {
	if file.Encoding != "none" {
		return nil
	}

	raw, err := fetchRawFile(httpClient, repo, file.Path, ref)
	if err != nil {
		return err
	}
	file.Content = raw
	return nil
}
