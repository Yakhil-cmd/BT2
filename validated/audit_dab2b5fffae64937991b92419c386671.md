### Title
Unsanitized `username`/`password` interpolation into `git credential approve` stdin allows credential-protocol attribute injection - ([File: pkg/cmd/auth/shared/gitcredentials/updater.go])

### Summary
`Updater.Update` builds the stdin for `git credential reject`/`git credential approve` by directly interpolating `hostname`, `username`, and `password` into a `heredoc.Docf` template with no escaping of newline characters. If `username` (sourced from `GetCurrentLogin`, i.e., a GraphQL `viewer.login` string returned by whatever host `gh` is pointed at) contains embedded `\n` sequences, an attacker-controlled host can inject additional `key=value` lines (e.g., `host=`, `protocol=`, `path=`) into the credential record before `git` reaches the legitimate `password=%s` line.

### Finding Description
`Updater.Update` at [1](#0-0)  constructs the `approve` stdin as:
```
protocol=https
host=%s
username=%s
password=%s
```
with `hostname`, `username`, `password` substituted verbatim, with no newline/control-character sanitization. `username` originates from `GetCurrentLogin`, which decodes an untrusted JSON field (`viewer.login`) from whatever GraphQL endpoint the victim authenticated against, and returns it unchanged: [2](#0-1)  This value flows into `Login` → `opts.CredentialFlow.Setup(hostname, username, authToken)` at [3](#0-2)  and ultimately into `Updater.Update`.

Correction to the proposed exact mechanism: git's `git credential <op>` reads a *single* credential record per invocation, terminating input parsing at the first blank line (or EOF), then performs the requested action and exits — it does not loop to parse a second record from leftover stdin in the same process. So a literal `\n\n` (blank line) in `username` mainly truncates the record early, causing the real `password=` line (which appears after the blank line in the template) to never be associated with the record git actually acts on — this can cause the intended approval to silently fail to persist the password, rather than "storing" it a second time.

However, the same missing-sanitization root cause is still exploitable via a *single* embedded `\n` (no need for a full blank line) in `username`: e.g. `username = "victim\nhost=evil.example.com"`. Because this does not create a blank line, git parses it as additional `key=value` attribute lines *within the same record* being built, and a later attribute assignment for the same key generally overrides the earlier one in `credential.c`'s field parsing. This lets the attacker override `host=` (or `protocol=`/`path=`) for the very record whose `password=` line follows — the real OAuth token from that record gets approved/stored by the configured credential helper keyed to the attacker-chosen host instead of the intended `hostname`.

No sanitization, allowlisting, or escaping of `username`/`password` exists before this interpolation.

### Impact Explanation
This is a wrong-host credential-storage/routing issue: the victim's real OAuth token can end up cached by the OS credential helper (credential-store/keychain/wincred) against a host string chosen by the attacker. Any subsequent `git` HTTPS operation against that attacker-chosen host on the victim machine would then have the real token attached automatically by the credential helper, exfiltrating it to the attacker's server. This matches the "wrong-host request routing" / credential-disclosure impact class.

### Likelihood Explanation
Requires the victim to run interactive `gh auth login` against a host controlled or influenced by the attacker (e.g., a malicious/compromised GitHub Enterprise Server endpoint the victim points `gh` at, or an SSRF/DNS-controlled endpoint), with the paste-token path so `username == ""` triggers `GetCurrentLogin` (the web OAuth device flow instead returns its own username value, but that value is also sourced from the same attacker-controlled server in that scenario). This is a plausible but non-trivial precondition — it does not work against real github.com since GitHub's actual `viewer.login` values cannot contain newlines.

### Recommendation
Sanitize/reject `hostname`, `username`, and `password` values before interpolating them into the git-credential-protocol stdin in `Updater.Update` — at minimum reject or strip `\n`/`\r` characters, or construct the record via a structured writer that percent/URL-encodes values rather than raw `heredoc.Docf` string interpolation.

### Proof of Concept
```go
func TestUpdater_Update_UsernameInjection(t *testing.T) {
    // Simulate attacker-controlled GetCurrentLogin response
    maliciousUsername := "victim\nhost=evil.example.com"
    u := &Updater{GitClient: gitClientBackedByCredentialStore(t)}
    err := u.Update("legit.githubenterprise.com", maliciousUsername, "REAL_OAUTH_TOKEN")
    require.NoError(t, err)

    // Assert: credential store now contains an entry for evil.example.com
    // holding REAL_OAUTH_TOKEN, instead of (or in addition to) legit.githubenterprise.com.
    creds := readGitCredentialStoreFile(t)
    require.NotContains(t, creds, "host=legit.githubenterprise.com\npassword=REAL_OAUTH_TOKEN")
    require.Contains(t, creds, "host=evil.example.com\npassword=REAL_OAUTH_TOKEN")
}
```
Fuzz plan: fuzz `username`/`password` inputs to `Updater.Update` against a real `git credential-store` backend, decoding the resulting credential file after each call, and assert that exactly one record exists and that its `host` field equals the `hostname` argument passed to `Update`.

func GetCurrentLogin(httpClient httpClient, hostname, authToken string) (string, error) {
	query := `query UserCurrent{viewer{login}}`
	reqBody, err := json.Marshal(map[string]interface{}{"query": query})
	if err != nil {
		return "", err
	}
	result := struct {
		Data struct{ Viewer struct{ Login string } }
	}{}
	apiEndpoint, err := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "token "+authToken)
	res, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}
	defer res.Body.Close()
	if res.StatusCode > 299 {
		return "", api.HandleHTTPError(res)
	}
	decoder := json.NewDecoder(res.Body)
	err = decoder.Decode(&result)
	if err != nil {
		return "", err
	}
	return result.Data.Viewer.Login, nil
