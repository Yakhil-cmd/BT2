### No vulnerability found for this question.

**Rationale:** The scenario requires the victim to voluntarily invoke `gh run download -D .git/hooks`, deliberately pointing the destination at a sensitive path — this is victim-controlled input, not attacker-controlled input. The attacker only controls the artifact name/content, not `--dir`. Path confinement itself works as intended: `absoluteDestinationDir.Join(a.Name)` and `destDir.Join(zf.Name)` in `ExtractZip` both reject any path traversal via `isSubpathOf` [1](#0-0) , so the artifact contents can only ever land inside the directory the victim explicitly chose — exactly matching normal `gh run download` behavior for any `--dir` value.

Additionally, file writes use `os.O_WRONLY|os.O_CREATE|os.O_EXCL`, which fails if the destination file already exists rather than overwriting it [2](#0-1) . So even in the contrived scenario, a pre-existing `pre-commit` hook would not be silently overwritten; extraction would abort with an error instead [3](#0-2) .

Since the exploit requires the victim to manually target a security-sensitive directory with `--dir` (not something an attacker can induce via any parsed/attacker-controlled field like repo name, artifact URL, or ref), this falls outside the threat model of an unprivileged remote attacker acting through ordinary `gh` usage. This is "user chooses a dangerous destination" rather than a flaw in destination-confinement logic reachable via attacker-controlled input.

func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
