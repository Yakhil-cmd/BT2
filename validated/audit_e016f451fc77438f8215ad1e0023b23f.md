Based on the traced code path, this vulnerability is valid.

### Title
Unauthenticated PR labels are merged unfiltered into subprocess environment, enabling interpreter loader-variable injection (`PERL5LIB`, `PYTHONPATH`, etc.) - ([File: lib/shipit/command.rb])

### Summary
`ReviewStack#env` merges every PR label name (upcased) verbatim as an environment variable with value `"true"`, and this hash flows unmodified through `TaskCommands#env` into `Command#unbundled_env`, which is passed directly to `PTY.spawn`. No allowlist, denylist, or `EnvironmentVariables#permit` filtering is applied to this specific merge point, so an attacker who can label their own PR (an unprivileged GitHub action) controls arbitrary environment variable names/values seen by every deploy-step subprocess, including interpreter loader variables like `PERL5LIB` or `PYTHONPATH`.

### Finding Description
The broken binding: `(pull_request.labels.map(&:name).map(&:upcase)).to_set ∩ (Command#unbundled_env keys reaching PTY.spawn).to_set == ∅` is claimed by the codebase's design intent but is **not actually empty** — it should be but isn't enforced.

Trace:
1. `LabelCapturingHandler#capture_labels` stores raw GitHub label names on the PR with no validation: `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [1](#0-0) 
2. `ReviewStack#env` unconditionally merges every label, upcased, as `"true"`, with no allowlist: [2](#0-1) 
3. `TaskCommands#env` merges `@stack.env` (which is `ReviewStack#env` for PR-driven stacks) directly into the environment hash used for every step, then further merges `deploy_spec.machine_env` and `@task.env`, with no filtering of the stack-env keys: [3](#0-2) 
4. `Command#unbundled_env` merges `@env` (built from the above) into `BASE_ENV`/`PATH` with no key filtering, and `start` passes this directly to `PTY.spawn`: [4](#0-3) 
5. `EnvironmentVariables#permit`, the only allowlist mechanism in the codebase, is not applied to this merge path — it is a separate opt-in sanitizer used elsewhere (e.g., for `deploy_variables`/task definitions), not wired into `TaskCommands#env` or `Command#unbundled_env`. [5](#0-4) 

Existing tests confirm this is intentional current behavior, not a hardened boundary: [6](#0-5)  and [7](#0-6)  both assert arbitrary label names become env vars.

Attacker's exact request: open (or already have) a pull request against a repository with review-stack provisioning enabled, then apply a label literally named `perl5lib` (or `pythonpath`, `node_path`, `rubylib`) via the standard GitHub "Labels" UI/API on their own PR — no Shipit credentials required, since GitHub webhooks for `pull_request` `labeled`/`unlabeled` events are handled by `LabelCapturingHandler`/`LabeledHandler` and validated only via `verify_signature` against GitHub's webhook secret, which is orthogonal to label content. This has no bearing on label *name* content, so any string is accepted verbatim.

Root cause: `ReviewStack#env` treats PR labels as a trusted key/value environment source with no character restriction, no allowlist, and no reservation of sensitive/interpreter-loader variable names.

### Impact Explanation
If the target repository's `shipit.yml` deploy/dependency steps invoke `perl`, `python`, `node`, or `ruby` without explicit `-I`/override flags (a very common, unremarkable configuration), the attacker's label sets that interpreter's loader-path variable in the subprocess environment. If any writable path segment (working directory, dependency install directory, etc.) contains or can be made to contain a module/file matching an import used by the deploy script, that attacker-controlled code executes with the privileges of the Shipit deploy host — this is Critical: RCE on the deploy host via `Command`/`PTY.spawn`. The attack is repeatable per label change and scoped to any repository the attacker can label a PR on that has review-stack provisioning configured; it does not cross repository/tenant boundaries directly, but is a full compromise of the deploy host process for that repository/stack.

### Likelihood Explanation
Preconditions: the repository must have review stacks enabled (common for PR-based Shipit workflows) and the target deploy/dependency step must invoke an interpreter without `-I` overrides (plausible but not universal — depends on target's `shipit.yml`). Attacker cost is trivial: applying a GitHub label requires only write access to labels on one's own PR/fork context (label application on your own PR is generally permitted for anyone who can open PRs, or requires triage access depending on repo settings — note: applying labels typically requires at least triage/write permission on the target repo in stock GitHub, which may reduce but not eliminate the unauthenticated angle if the repo allows outside collaborators to label). Given that constraint, likelihood is moderate-to-high in environments where label permissions are loosely configured, but the core code-level vulnerability (unfiltered label-to-env merge) is unconditionally present.

### Recommendation
Do not allow PR label names to populate arbitrary environment variable keys. Either (a) prefix all label-derived env vars with a fixed, non-colliding namespace (e.g., `SHIPIT_LABEL_<NAME>`) so they can never match real loader/system variable names, or (b) run label-derived keys through `EnvironmentVariables#permit` against an explicit allowlist before merging in `ReviewStack#env`, and additionally maintain a denylist of security-sensitive variable names (`PERL5LIB`, `PYTHONPATH`, `NODE_PATH`, `RUBYLIB`, `LD_PRELOAD`, `LD_LIBRARY_PATH`, etc.) that can never be set via this mechanism regardless of allowlist configuration.

### Proof of Concept
```ruby
# test/models/shipit/review_stack_env_injection_test.rb
require "test_helper"

module Shipit
  class ReviewStackEnvInjectionTest < ActiveSupport::TestCase
    LOADER_VARS = %w[PERL5LIB PYTHONPATH NODE_PATH RUBYLIB]

    test "loader variable names from PR labels are not filtered before reaching Command#unbundled_env" do
      stack = shipit_stacks(:review_stack)
      stack.pull_request.labels = LOADER_VARS.map(&:downcase)

      # Binding under test: label-derived keys intersected with keys reaching PTY.spawn must be empty.
      stack_env_keys = stack.env.keys.to_set
      injected = LOADER_VARS.to_set & stack_env_keys
      assert_not_empty injected, "expected loader vars to leak into ReviewStack#env (binding violated)"

      task = shipit_tasks(:shipit_restart)
      task.stack = stack
      task_env = Shipit::TaskCommands.new(task).env

      LOADER_VARS.each do |var|
        assert_equal "true", task_env[var], "#{var} should have been filtered, but was injected"
      end

      command = Shipit::Command.new("echo hi", env: task_env, chdir: ".")
      spawned_env = command.unbundled_env

      LOADER_VARS.each do |var|
        assert_equal "true", spawned_env[var],
          "#{var} reached PTY.spawn env unfiltered - loader-path hijack possible"
      end
    end
  end
end
```
