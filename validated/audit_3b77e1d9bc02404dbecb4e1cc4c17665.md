### Title
Permanent market freeze through RAY debt-value overflow - ([File: common/src/rates/index.rs](common/src/rates/index.rs)) [1](#0-0) 

### Summary
A sufficiently large borrowed position can make `borrowed × borrow_index` overflow `i128` during interest accrual, before the borrow-index cap can protect the market. [1](#0-0) [2](#0-1) 

### Finding Description
Every mutable market operation loads the market and performs `global_sync`, which repeatedly calls `accrue_step` before the operation's state changes. [3](#0-2) [4](#0-3) 

During accrual, `calculate_supplier_rewards` computes `borrowed.mul(old_borrow_index)` and `borrowed.mul(new_borrow_index)`, while `Ray::mul` panics with `MathOverflow` when the intermediate result exceeds `i128`. [1](#0-0) [5](#0-4) 

The borrow-index cap is applied only to the newly calculated index and does not prevent the separately calculated debt values from overflowing. [6](#0-5) 

The existing regression test demonstrates that a `1e36`-RAY-scale debt book under sustained high utilization reaches this value ceiling while the borrow index remains below `MAX_BORROW_INDEX_RAY`. [7](#0-6) 

### Impact Explanation
Once the threshold is crossed, any controller call that touches the market first triggers accrual and reverts with `MathOverflow`. [3](#0-2) [8](#0-7) 

This permanently freezes supplier withdrawals, borrower repayments, liquidations, index updates, revenue claims, and recapitalization for that market, leaving user funds locked even though the underlying token balance may remain in the pool. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
An unprivileged attacker can establish the condition through ordinary `supply`, `borrow`, and `update_indexes` calls by supplying the borrowable asset, borrowing it at high utilization, and allowing the borrow index to grow. [11](#0-10) [12](#0-11) 

The attack requires an unusually large high-decimal market and sustained high utilization long enough for the index to grow beyond approximately `i128::MAX / borrowed`, so the likelihood is lower than for an immediately triggerable call. [13](#0-12) 

### Recommendation
Use overflow-safe wider arithmetic for `borrowed * index` and `supplied * index`, or clamp the index before performing these products with an explicit `borrowed <= i128::MAX / index` bound. [14](#0-13) [1](#0-0) 

Market supply and borrow caps should also enforce a scaled-value limit based on the maximum possible index rather than only the current index, so an admitted book cannot later cross the RAY-value ceiling. [15](#0-14) 

### Proof of Concept
1. In an 18-decimal market, call controller `supply` with `account_id = 0`, the active `spoke_id`, and `(hub_id, BIG18) = 1_000_000_000 * 10^18` to create the liquidity-supplying position. [16](#0-15) 

2. Supply enough listed collateral to a second owned account and call controller `borrow` with `(hub_id, BIG18) = 98%` of the supplied amount. [17](#0-16) 

3. Maintain high utilization until the borrow index has grown enough that `borrowed * borrow_index` exceeds `i128::MAX`; calling controller `update_indexes` with `[hub_id, BIG18]` then returns `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [18](#0-17) 

4. Subsequent `withdraw` and `repay` calls on the same market also revert with `MathOverflow`, demonstrating that neither suppliers nor borrowers can exit or reduce risk. [10](#0-9)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {

    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
