### Title
Blank `webhook_secret` string bypasses webhook signature verification, allowing forged pushes to mutate any org's stacks - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#initialize` applies `.presence` to `webhook_secret`, silently converting a configured empty string (`''`) into `nil`. `verify_webhook_signature` treats a `nil` secret as "no verification required" and returns `true` unconditionally, so any unauthenticated POST to `/webhooks` naming that org is accepted and dispatched to `PushHandler`, which triggers `stack.sync_github` on that org's real stacks.

### Finding Description
The broken binding: the code assumes `webhook_secret.present? == organization_has_configured_signing_secret`. In reality, for an org configured with `webhook_secret: ''` (e.g., from an unset ENV var interpolated in `secrets.yml`), `@webhook_secret = @config[:webhook_secret].presence` at [1](#0-0)  turns `''` into `nil`. Then `verify_webhook_signature` at [2](#0-1)  executes `return true unless webhook_secret`, so it verifies *any* request as authentic for that org — no signature is checked at all.

The controller path: `WebhooksController#verify_signature` at [3](#0-2)  resolves the `GitHubApp` via `Shipit.github(organization: repository_owner)` where `repository_owner` comes straight from the attacker-controlled JSON body (`params.dig('repository', 'owner', 'login')`, [4](#0-3) ). If that returned `true`, `create` proceeds to dispatch to handlers such as `PushHandler`, which finds real, non-archived stacks matching the branch and calls `stack.sync_github(expected_head_sha: params.after)` [5](#0-4) , mutating that org's stack state based on entirely attacker-supplied `ref`/`after` values.

Exploit flow: attacker sends `POST /webhooks` with `X-Github-Event: push`, no (or any garbage) `X-Hub-Signature`, and a JSON body with `repository.owner.login` set to the misconfigured org's login and `repository.full_name`/`ref` pointing at that org's real stack/branch. Because `webhook_secret` resolved to `nil`, `verify_webhook_signature` short-circuits to `true`, `head(422)` is never called, and the push is processed as legitimate.

Existing guards don't help: `drop_unhandled_event` only filters unhandled event types, not authenticity [6](#0-5) ; `check_if_ping` is unrelated; there is no separate check that a secret was actually configured before trusting `verify_webhook_signature`'s result.

### Impact Explanation
An attacker who can send an arbitrary HTTP POST (no credentials needed) can trigger `stack.sync_github` for any stack belonging to an org whose `webhook_secret` resolves to blank/empty, effectively forging pushes and driving Shipit to sync/deploy based on attacker-chosen `ref`/SHA values. This matches "authentication bypass (forged webhook accepted)" and "a payload... mutating another's stack" — Critical severity. The blast radius is scoped to organizations that have this specific misconfiguration (blank string secret), but for those orgs, it is a full, repeatable bypass against every one of their stacks/webhooks.

### Likelihood Explanation
This requires a real, but plausible, misconfiguration: `webhook_secret` set to an empty string rather than omitted/nil, most commonly by interpolating an unset environment variable into `secrets.yml` (e.g., `webhook_secret: <%= ENV['GH_WEBHOOK_SECRET'] %>` when the var is unset, yielding `''`). This is an operator configuration mistake, not something exploitable against a properly configured Shipit deployment. Attacker cost is trivial once the precondition holds (a single unauthenticated HTTP POST), and it is fully repeatable.

### Recommendation
In `GitHubApp#initialize`, do not silently coerce blank secrets: either raise/log loudly if `webhook_secret` is configured but blank, or treat blank as "unconfigured" only when the key is entirely absent (`@config.key?(:webhook_secret)` check) versus explicitly set to `''`. More robustly, fail closed: `verify_webhook_signature` should reject requests (`return false`) when no secret is configured, unless there's an explicit opt-in flag acknowledging unsigned webhooks are intentional, rather than defaulting to trust-everyone. At minimum, add a startup/boot validation that rejects any github app config with a blank (but present) `webhook_secret` key.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (or a new test file)
test "blank webhook_secret allows forged push to mutate the org's stack" do
  Shipit.stubs(:github_organizations).returns(['shopify'])
  Shipit.stubs(:secrets).returns(stub(github: { 'shopify' => { webhook_secret: '', app_id: 1, installation_id: 1 } }))

  stack = shipit_stacks(:shipit).tap { |s| s.update!(repo_owner: 'shopify') }
  stack.expects(:sync_github).with(expected_head_sha: 'deadbeef')

  post :create, body: {
    ref: "refs/heads/#{stack.branch}",
    after: 'deadbeef',
    repository: { owner: { login: 'shopify' }, full_name: "shopify/#{stack.repo_name}" }
  }.to_json, params: {}, headers: { 'X-Github-Event' => 'push' } # no X-Hub-Signature header

  assert_response :ok
end
```
Assert both sides of the binding: `GitHubApp.new('shopify', webhook_secret: '').send(:webhook_secret)` is `nil` (not `''`), and `verify_webhook_signature(nil_or_garbage_signature, anything)` returns `true` — demonstrating that "org configured a secret" and "org's requests are verified" have diverged.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",

    end
