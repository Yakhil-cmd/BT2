### Title
Proposer Can Suppress Candidate Failure Reports by Writing Nil `header.VRank`, Corrupting CFS Scores and Enabling Undeserved Block Rewards — (`kaiax/vrank/impl/consensus.go`, `kaiax/vrank/impl/getter.go`, `kaiax/vrank/impl/scoring.go`)

---

### Summary

`VerifyHeader` explicitly accepts `len(header.VRank) == 0` for any non-epoch block without further validation. A malicious block proposer can therefore write `nil` to `header.VRank` even when `EvaluateCandidates` produced a non-empty failure report. Every honest node will accept the block, `cfReport` will return an empty list for that block, and `applyBlocksForCPMatrix` will record zero failures — permanently suppressing CFS increments for the colluding candidates. At epoch-end those candidates can pass the vrank threshold and enter `ValActive`, receiving KAIA block rewards they did not earn.

---

### Finding Description

**`VerifyHeader` — the missing enforcement gate** [1](#0-0) 

For non-epoch blocks the check is simply:
```go
if len(header.VRank) == 0 {
    return nil
}
```
No further validation is performed. A proposer that deliberately writes `nil` instead of the encoded failure list passes this gate unconditionally.

**`cfReport` — reads nil as "no failures"** [2](#0-1) 

```go
if len(header.VRank) == 0 {
    return []common.Address{}, nil
}
```
The function cannot distinguish "no candidates failed" from "proposer suppressed the report."

**`applyBlocksForCPMatrix` — no failures recorded** [3](#0-2) 

```go
for _, candidate := range cfReport {   // empty → zero iterations
    cpMatrix.Increment(candidate, reporter)
}
```
The proposer is still counted via `cpMatrix.AddProposer(reporter)` (line 183), so `ProposerCount()` — and therefore the byzantine-filter threshold `F = ProposerCount()/3` — is accurate. But the per-candidate failure count for that block is zero, permanently.

**`PrepareHeader` — the honest path that the attacker bypasses** [4](#0-3) 

An honest proposer calls `encodeCandidateFailureVRank`, which calls `EvaluateCandidates` and encodes the result. A malicious proposer simply skips this and sets `header.VRank = nil`. Nothing in `VerifyHeader` can detect the omission.

**Byzantine filter does not protect against suppression** [5](#0-4) 

`byzantineFilter` discards the **F highest** per-reporter scores to defend against reporters that *inflate* scores. It provides no protection against reporters that *suppress* scores (contribute 0 instead of 1). A single malicious proposer who omits failures for every block they propose reduces the candidate's score by exactly the number of blocks that proposer produced in the epoch — potentially enough to push the candidate below the pass threshold.

---

### Impact Explanation

Failing `CandTesting` nodes that collude with a malicious proposer can have their CFS scores artificially lowered. If the suppression is sufficient to keep their score below the epoch-end threshold, they pass the vrank test, transition into `ValActive`, and receive KAIA block rewards they did not earn. This is unauthorized reward distribution from the protocol's reward pool.

---

### Likelihood Explanation

Any single active validator who controls their node software can execute this attack. It does not require majority-validator collusion, compromised keys, or external service compromise. The proposer simply sets `header.VRank = nil` before broadcasting the block. The attack is repeatable every time that validator is selected as proposer, and its effect accumulates silently across the epoch.

---

### Recommendation

`VerifyHeader` must not treat `len(header.VRank) == 0` as unconditionally valid for non-epoch blocks. One approach: require the proposer to include a BLS-signed commitment to the `EvaluateCandidates` result so that other validators can verify the report is complete. A simpler short-term fix is to require that `header.VRank` is always the RLP encoding of the failure list (including `0xc0` for an empty list), and reject bare `nil` for non-epoch blocks after the permissionless fork. This forces the proposer to at least commit to an explicit "no failures" claim, which can then be cross-checked against quorum-signed consensus messages if a dispute mechanism is added later.

---

### Proof of Concept

1. Candidates A and B are in `CandTesting`. They deliberately do not send `VRankCandidate` messages for block N.
2. The malicious proposer P calls `EvaluateCandidates(N, round)` and receives `[A, B]`.
3. P sets `header(N+1).VRank = nil` and broadcasts the block.
4. Every honest node calls `VerifyHeader`: `len(header.VRank) == 0` → `return nil`. Block accepted.
5. Later, `cfReport(N+1)` is called by `applyBlocksForCPMatrix`: `len(header.VRank) == 0` → returns `[]`.
6. `cpMatrix.Increment` is never called for A or B for block N+1.
7. Repeat for every block P proposes in the epoch.
8. At epoch-end, `GetCFS` returns suppressed scores for A and B; they pass the vrank threshold, enter `ValActive`, and collect block rewards.

func (v *VRankModule) encodeCandidateFailureVRank(number uint64) ([]byte, error) {
	if number == 0 {
		return nil, nil
	}
	parentNum := number - 1
	parent := v.Chain.GetHeaderByNumber(parentNum)
	if parent == nil {
		logger.Error("Failed to read parent header for VRank", "num", number, "parentNum", parentNum)
		return nil, vrank.ErrHeaderNotFound
	}
	parentRound, err := v.RoundReader.Round(parent)
	if err != nil {
		logger.Error("Failed to read parent round for VRank", "err", err, "parentNum", parentNum)
		return nil, err
	}
	report, err := v.EvaluateCandidates(parentNum, uint64(parentRound))
	if err != nil {
		logger.Error("Failed to evaluate VRank candidates", "err", err, "prevBlockNum", parentNum, "prevRound", parentRound)
		return nil, err
	}
	if len(report) == 0 {
		return nil, nil
	}
	encoded, err := vrank.EncodeReport(report)
	if err != nil {
		logger.Error("Failed to encode VRank report", "err", err, "report", report)
		return nil, err
	}
	return encoded, nil

func generateCFSFromCPMatrix(cpMatrix vrank.CPMatrix) map[common.Address]uint64 {
	F := cpMatrix.ProposerCount() / 3
	return byzantineFilter(cpMatrix, F)
}

// byzantineFilter computes CFS scores from pre-aggregated per-candidate failure data.
//
// cpMatrix[candidate][reporter] is the number of times reporter included candidate
// in cfReport over the epoch. F is the number of highest reporter totals to discard
// per candidate, defending against up to F byzantine reporters that may inflate scores.
func byzantineFilter(cpMatrix vrank.CPMatrix, F int) map[common.Address]uint64 {
	cfs := make(map[common.Address]uint64)
	for cand, reporterToScore := range cpMatrix {
		scores := slices.Collect(maps.Values(reporterToScore))
		slices.Sort(scores)
		if F >= len(scores) {
			// since `scores` contain non-zero scores only, F >= len(scores) can happen, in which case all scores are discarded.
			scores = nil
		} else {
			scores = scores[:len(scores)-F]
		}
		var sum uint64
		for _, t := range scores {
			sum += t
		}
		cfs[cand] = sum
	}
	return cfs
}
