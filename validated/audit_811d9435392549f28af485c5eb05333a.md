### No vulnerability found for this question.

This scenario is explicitly excluded by the audit rules. The described attack requires the attacker to convince the victim to manually run `gh auth login --hostname attacker.ghe.com`, which is social engineering — explicitly listed as out of scope ("No local access, no admin or org rights, no leaked token, no MITM, no social engineering").

Beyond that, the code behaves exactly as designed: `RESTPrefix`/`GetScopes` faithfully send requests to whatever hostname the user explicitly configured via `--hostname`, which is the entire point of GHE.com tenant support — each customer's tenant genuinely lives at `<tenant>.ghe.com`, so there is no way for `gh` to distinguish a "real" tenant subdomain from an "attacker" one purely from the string itself [1](#0-0) . The trust decision of which hostname to authenticate against is made by the user at the CLI invocation, not derived from any attacker-controlled remote content (repo, ref, issue body parsed programmatically, API response, etc.) that `gh` processes unprompted [2](#0-1) . There is no reachable path where attacker-published repo/issue/PR content is automatically consumed by `gh` to redirect a token to a different host without the user explicitly typing that hostname themselves.

func RESTPrefix(hostname string) string {
	if isGarage(hostname) {
		return fmt.Sprintf("https://%s/api/v3/", hostname)
	}
	if ghauth.IsEnterprise(hostname) {
		return fmt.Sprintf("https://%s/api/v3/", hostname)
	}
	if strings.EqualFold(hostname, localhost) {
		return fmt.Sprintf("http://api.%s/", hostname)
	}
	return fmt.Sprintf("https://api.%s/", hostname)
}
