### Title
RAY-value overflow in accrual permanently freezes a whale-scale market before the borrow-index cap can engage - (File: common/src/rates/index.rs)

### Summary
The heap-buffer-overflow bug class (unvalidated size/shape arithmetic overflowing the real allocation domain) maps onto the pool's interest accrual: every compounding step multiplies the scaled debt/supply totals by the running indexes in `i128`/`I256`-bounded `mul_div` calls. The borrow index is capped at `MAX_BORROW_INDEX_RAY`, but the *debt value* `borrowed * borrow_index` can overflow `i128` long before the index reaches that cap. Once that happens, `accrue_step` panics on `MathOverflow` for every chunk forever — and every controller verb accrues first, so the market is permanently frozen: no repay, no withdraw, no liquidation. The codebase's own harness test proves this end-to-end.

### Finding Description
`accrue_step` in `common/src/rates/simulate.rs` computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` and `calculate_supplier_rewards` computes `borrowed.mul(new_borrow_index)` — both panicking `mul_div` paths with no saturation. `update_borrow_index` clamps `new_index` to `MAX_BORROW_INDEX_RAY` but only *after* multiplying, and it never bounds `borrowed * index`. So when `borrowed` (scaled debt in RAY) is large enough that `borrowed * borrow_index > i128::MAX` while `borrow_index < MAX_BORROW_INDEX_RAY`, the accrual step panics.

`global_sync` in `contracts/pool/src/interest.rs` runs `accrue_chunk` unconditionally whenever `needs_accrual()`, and every pool mutation (supply, borrow, withdraw, repay, liquidate, update_indexes) accrues first. Once `borrowed * borrow_index` exceeds `i128::MAX`, every subsequent call panics at the same multiplication — the panic is self-perpetuating because nothing can reduce `borrowed` or `borrow_index` without first completing an accrual.

The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates this concretely: an 18-decimal market with ~10^27-token supply borrowed at 98% utilization on the XLM rate curve crosses the `i128` value ceiling while `borrow_index < MAX_BORROW_INDEX_RAY`, after which `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all fail with `MATH_OVERFLOW`.

### Impact Explanation
Permanent freezing of funds: all supplier principal and borrower collateral routed through the frozen market become unrecoverable — withdrawals, repayments, and liquidations all revert at accrual. This is not a temporary freeze: there is no code path that can shrink `borrowed` or roll back `borrow_index` without first executing the panicking multiplication. Positions in other markets are unaffected, but the entire (hub, token) book is bricked.

### Likelihood Explanation
Medium. The trigger requires a whale-scale market: scaled debt must be large enough that `borrowed * index` overflows `i128` (roughly `borrowed > i128::MAX / index`; at index ~170x RAY the test needed ~10^27 base units of supplied liquidity, i.e. a billion 18-decimal tokens). An unprivileged attacker must actually deposit and borrow that much real value and sustain ~98% utilization for the multi-year accrual horizon the XLM curve needs to push the index past ~170x. Caps must permit it (`max_cap_for_decimals` is a legitimate listing domain, so this does not require misconfiguration beyond generous caps). The capital requirement is the only real mitigation — once staged, the freeze is deterministic and irreversible.

### Recommendation
In `accrue_step` / `calculate_supplier_rewards` / `update_supply_index`, order the clamp before the value multiplication or use saturating variants where the subsequent consumer is a cap comparison: clamp `borrow_index` to `min(computed, MAX_BORROW_INDEX_RAY)` and compute interest on the clamped index, and compute `borrowed * index` through `mul_div_floor_saturating` (or a widened `I256` comparison) so a value-domain overflow degrades to "index pinned at cap" rather than a panic. Alternatively, derive the effective debt-value ceiling (`i128::MAX / borrowed`) and clamp the borrow index to `min(MAX_BORROW_INDEX_RAY, ceiling)` each step, so accrual converges to the cap instead of trapping.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: supply `BILLION * 10^18` of an 18-decimal asset via `controller::supply` (caps lifted to `max_cap_for_decimals`), supply collateral in another market, call `controller::borrow` for 98% of it, then advance time in one-year steps calling `controller::update_indexes`. Within ~40 simulated years `try_update_indexes_for("BIG18")` reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and `try_withdraw_raw`/`try_repay` revert identically — the market and all funds in it are permanently frozen. pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
