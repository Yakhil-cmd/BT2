### Title
Attacker-controlled PR label names are merged unfiltered as environment variable names into `Command#unbundled_env`, allowing shell-meta variables like `IFS` to alter tokenization of operator-authored deploy commands - ([File: lib/shipit/command.rb])

### Summary
`ReviewStack#env` upcases every PR label name and merges it into the environment hash with the fixed value `"true"`, with no denylist of shell-significant variable names. [1](#0-0)  That hash flows through `TaskCommands#env` / `DeployCommands#env` / `RollbackCommands#env` and is merged last into `Command#unbundled_env`, which is the environment `PTY.spawn` uses to execute the operator's `shipit.yml` step. [2](#0-1) [3](#0-2)  Because steps are stored and executed as a single flat command-line string (`Command`'s `@args` is a one-element array holding the whole `command_line`), `PTY.spawn` runs it through `/bin/sh -c`, so an attacker who can label a PR with the literal name `IFS` (or `BASH_ENV`, `ENV`, `PS4`, etc.) injects that shell-significant variable into the spawned shell's environment, unfiltered.

### Finding Description
Binding claimed: `Command#start` executes argv == the literal `command_line` string declared in `shipit.yml`, unaltered by attacker-controlled shell semantics.

Trace:
1. `LabelCapturingHandler#capture_labels` writes `params.pull_request.labels.map(&:name)` verbatim into `PullRequest#labels` for any active (non-archived) stack, with no validation restricting label text (schema only requires `String`). [4](#0-3) 
2. `ReviewStack#env` reads those labels and merges `label_name.upcase => "true"` into the base env - `IFS` labeled produces `env["IFS"] = "true"`. [1](#0-0) 
3. `TaskCommands#env` merges `@stack.env` in the middle of its chain, and `DeployCommands#env` / `RollbackCommands#env` merge additional keys afterward - none of these strip or deny reserved names such as `IFS`. [2](#0-1) [5](#0-4) 
4. `Command.new(command_line, env:, chdir:)` stores the whole step as a single-element `@args` array (confirmed by existing test fixtures: `assert_equal ['bundle exec cap $ENVIRONMENT deploy'], command.args`). [6](#0-5) 
5. `Command#unbundled_env` merges `BASE_ENV`, then `PATH`, then `@env.stringify_keys` **last**, so attacker-derived keys win over anything an operator set with the same name. [7](#0-6) 
6. `Command#start` calls `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` with a single string in `interpolated_arguments` - Ruby's `Process.spawn`/`PTY.spawn` semantics run a single multi-word string through `/bin/sh -c`, so the shell (inheriting the poisoned `IFS`) re-tokenizes the whole command line. [8](#0-7) 
7. `EnvironmentVariables#interpolate`, used to substitute `$VAR` references before the shell sees them, only calls `Shellwords.escape` on the substituted values. [9](#0-8)  `Shellwords.escape` backslash-escapes shell metacharacters and whitespace, but has no knowledge of an attacker-chosen `IFS` character set, so ordinary letters in interpolated values (and in the literal, un-quoted text the operator wrote in `shipit.yml`, e.g. `bundle exec cap $ENVIRONMENT deploy`) remain unprotected against arbitrary-character word-splitting once `IFS` is overridden.

Existing guards do not stop this: `LabelCapturingHandler`'s `params` schema only validates label `name` is a `String`, with no allowlist of characters; `EnvironmentVariables#permit` is a separate whitelist mechanism not invoked on this path (only `#interpolate` is used here); there is no denylist of reserved/shell-significant variable names anywhere in `ReviewStack#env`, `TaskCommands#env`, or `Command#unbundled_env`.

### Impact Explanation
An attacker who can label a pull request on a repository that has Shipit review stacks enabled (`opened`/`labeled`/`unlabeled`/`reopened` events reaching an active, non-archived stack) can set `IFS` (value fixed to `"true"`, i.e. delimiter characters `t`,`r`,`u`,`e`) in the environment of every subsequent shell-invoked step for that stack's deploys, rollbacks, and tasks. Because the entire `command_line` is executed via `/bin/sh -c`, this changes how the shell tokenizes the operator-approved command, up to and including which token becomes `argv[0]` (the executed binary) — i.e., a command can execute that the `shipit.yml` step did not declare. This is scoped to the attacker's own review-stack PR/stack (blast radius is limited to that stack's deploy/task execution, not other tenants' stacks), matching the "unauthorized deploy/command execution via `Command`/`PTY.spawn`" Critical category for that stack.

### Likelihood Explanation
Preconditions: the target repository must have review stacks enabled and reachable to the attacker's own PR (a common, documented Shipit feature), and at least one deploy/rollback/task step must be a plain unquoted shell command line (the common case, as shown by the repo's own fixtures like `bundle exec cap $ENVIRONMENT deploy`). No Shipit secrets, sessions, or tokens are required — GitHub's real, signed `labeled` webhook is emitted automatically when the attacker labels their own PR through the normal GitHub UI. Cost is a single label action; it is repeatable at will.

### Recommendation
- Deny-list (or strip) shell-significant / security-sensitive variable names (`IFS`, `PATH`, `ENV`, `BASH_ENV`, `PS4`, `LD_PRELOAD`, etc.) from label-derived and any other externally-influenced env sources before merging in `ReviewStack#env` / `TaskCommands#env` / `Command#unbundled_env`, or apply an explicit allowlist (similar to `EnvironmentVariables#permit`) to label-derived keys.
- In `Command#start`, avoid the single-string form passed to `PTY.spawn`; execute steps via an explicit `sh -c` argv pair with a controlled, minimal environment for the shell wrapper, or pass real argv arrays instead of pre-concatenated command-line strings where possible.
- Ensure `unbundled_env` cannot be overridden with reserved names regardless of merge order.

### Proof of Concept
Add to `test/unit/command_test.rb`:
```ruby
test "attacker-controlled IFS changes shell tokenization of the command line" do
  baseline = Command.new('bundle exec cap production deploy', env: {}, chdir: '.')
  poisoned = Command.new('bundle exec cap production deploy', env: { 'IFS' => 'true' }, chdir: '.')

  # both report the same literal command_line/args (operator's declared step)
  assert_equal baseline.args, poisoned.args

  # but the environment reaching PTY.spawn differs by the attacker-controlled IFS
  assert_nil baseline.unbundled_env['IFS']
  assert_equal 'true', poisoned.unbundled_env['IFS']

  # demonstrate divergence: run each through the real shell path and observe different argv/behavior
  out_baseline = baseline.run
  out_poisoned = poisoned.run
  refute_equal out_baseline, out_poisoned
end
```
And to `test/lib/shipit/task_commands_test.rb` (extending the existing label test):
```ruby
test "#env lets a PR label set IFS in the process environment" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ["IFS"]
  task = shipit_tasks(:shipit_restart)
  task.stack = stack

  env = Shipit::TaskCommands.new(task).env
  assert_equal "true", env["IFS"]
end
```

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end

    def unbundled_env
      BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)
    end

      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
