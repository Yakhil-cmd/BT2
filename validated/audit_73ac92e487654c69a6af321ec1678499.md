### Title
Webhook signature verification is bypassed entirely for organizations without a configured `webhook_secret`, allowing forged `pull_request` `closed` events to archive arbitrary `ReviewStack`s - (File: `lib/shipit/github_app.rb`, `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb`)

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the target organization has no `webhook_secret` configured, so `WebhooksController#verify_signature` accepts any unsigned, attacker-forged payload for that org. An attacker can therefore submit a forged `pull_request` `action=closed` event naming any PR number/repository under that org, causing `ClosedHandler` to call `review_stack.archive!` on the bound `ReviewStack`, and — on a stack with `merge_queue_enabled` true — indirectly perturb merge-queue state that would otherwise only change on a genuine GitHub-authenticated event.

### Finding Description
The claimed binding is: `verify_webhook_signature(signature, raw_post) == true` should hold **only if** `HMAC-SHA1(webhook_secret, raw_post) == signature`. Instead, the code is: [1](#0-0) 

`return true unless webhook_secret` means that for any org whose GitHub App config omits `webhook_secret`, the equality degenerates to `true == true` for *every* payload, regardless of signature. `WebhooksController#verify_signature` looks up the app via `Shipit.github(organization: repository_owner)`, where `repository_owner` is read straight from the attacker-controlled JSON body (`params.dig('repository','owner','login')`): [2](#0-1) [3](#0-2) 

Because the org is selected by the payload itself and the secret check is a no-op when unset, the attacker fully controls which trust boundary is exercised. Once past this gate, `Shipit::Webhooks.for_event('pull_request')` dispatches to `ClosedHandler`, which requires only `action`, `number`, and nested PR/repository/sender fields — all attacker-suppliable — and calls `review_stack.archive!` on the stack resolved from `repository.full_name` and PR number: [4](#0-3) 

None of the listed guards intervene: `drop_unhandled_event` only checks the event name exists in the handler registry; `ExplicitParameters` only validates payload shape, not origin; there is no `force_github_authentication`, `User#authorized?`, or `current_api_client` check on this unauthenticated controller at all. The signature check is the only authentication mechanism, and it is a no-op for misconfigured/unconfigured orgs.

### Impact Explanation
An attacker who can identify (or control) a repository whose owning org has no `webhook_secret` configured in Shipit can, from an unauthenticated `POST /webhooks` request, force the archival of that repository's `ReviewStack` for an arbitrary PR number. This is a state-changing write to a repository's stack that never authenticated the request. Per the question's stated scenario (`merge_queue_enabled` true and a green head), this can interact with merge-queue advancement logic and downstream `merge!` execution — an unauthorized deploy/merge outcome, matching the Critical "authentication bypass (forged webhook accepted)" / "unauthorized deploy, rollback or merge" categories. The attack is repeatable against any repository under an org lacking a secret, and could affect multiple tenants sharing that Shipit instance if any of their configured orgs omit the secret.

### Likelihood Explanation
This requires the specific precondition, stated in the question, that the target org's GitHub App config has no `webhook_secret` set — this is an operator/deployment configuration gap, not something the code enforces or prevents. Shipit's setup docs and `template.rb`/`secrets.yml` samples do configure `webhook_secret` normally, but the code path in `lib/shipit/github_app.rb` line 77 makes omission silently fail open rather than fail closed. Given that precondition, exploitation cost is trivial: a single unauthenticated HTTP POST with a fabricated JSON body, no valid signature, no credentials, and no rate limiting to defeat.

### Recommendation
Change `verify_webhook_signature` to fail closed when no `webhook_secret` is configured (`return false unless webhook_secret`, or reject the org from being registered as a valid webhook target at all), so that organizations without a properly configured secret cannot receive any webhook-driven state changes. Additionally, consider validating that `repository_owner`/`repository.full_name` in the payload actually corresponds to a repository Shipit expects, rather than trusting attacker-supplied JSON to select which app/secret config to check against.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "closed handler archives review stack when org has no webhook_secret configured" do
  # Arrange: an org config with no webhook_secret
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(
    Shipit::GitHubApp.new('no-secret-org', { app_id: 1, installation_id: 1, private_key: 'x' }) # no :webhook_secret key
  )

  stack = shipit_stacks(:review_stack) # merge_queue_enabled: true, PR-bound
  refute stack.archived?

  payload = {
    action: 'closed',
    number: stack.pull_request_number,
    pull_request: { id: 1, number: stack.pull_request_number, url: 'x', title: 't', state: 'closed',
                     additions: 1, deletions: 1, head: { sha: 'a'*40, ref: 'branch' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { full_name: stack.repository.full_name, owner: { login: 'no-secret-org' } },
    sender: { login: 'attacker' }
  }.to_json

  # Act: no valid signature at all
  post shipit.webhooks_path,
       params: payload,
       headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=deadbeef', 'Content-Type' => 'application/json' }

  # Assert: forged request is accepted (bug) and stack was archived without authentication
  assert_response :ok
  assert stack.reload.archived?, "ReviewStack was archived by an unauthenticated forged webhook"
end
```
Binding before: `verify_webhook_signature(bad_sig, payload) == false` expected. Binding after (actual, buggy behavior): `verify_webhook_signature(bad_sig, payload) == true` because `webhook_secret` is `nil`, letting the forged `closed` event through and causing `stack.archived? == true`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
