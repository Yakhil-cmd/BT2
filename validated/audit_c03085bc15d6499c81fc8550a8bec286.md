### Title
`collect_creator_fee` and `collect_creator_fee_permissionless` bypass pool pause controls, allowing fund outflow even when the pool is fully disabled - (File: `programs/cp-swap/src/instructions/collect_creator_fee.rs`, `programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs`)

### Summary
The pool's `deposit`, `withdraw`, `swap_base_input`, and `swap_base_output` instructions all check the pool's `status` bitmap via `PoolState::get_status_by_bit` before moving funds, allowing an admin to pause deposits, withdrawals, or swaps when an exploit or extreme market condition is detected. However, `collect_creator_fee` and `collect_creator_fee_permissionless`, which transfer accumulated creator fees out of the pool's token vaults, perform no such check, so these outflows cannot be paused through the same mechanism.

### Finding Description
`PoolState` stores a `status` byte with per-bit flags for `Deposit`, `Withdraw`, and `Swap`, checked via `get_status_by_bit` in the corresponding instructions: `deposit` [1](#0-0) , `withdraw` [2](#0-1) , and `swap_base_output` [3](#0-2) . This bitmap can be updated by an authorized signer to halt fund movement in each of these paths.

`collect_creator_fee` (creator-signed) and `collect_creator_fee_permissionless` (callable by anyone, since fees always go to the recorded `pool_creator`) both transfer the pool's accumulated `creator_fees_token_0`/`creator_fees_token_1` out of `token_0_vault`/`token_1_vault` without ever loading or checking `pool_state.status`: [4](#0-3) [5](#0-4) .

Because `PoolStatusBitIndex` only defines `Deposit`, `Withdraw`, and `Swap` [6](#0-5) , there is no bit that governs creator-fee collection, and no code path applies any of the existing bits to it.

### Impact Explanation
If the protocol needs to freeze all fund outflows from a pool (e.g., a detected exploit, oracle malfunction, or a compromised/malicious `pool_creator` address accruing fees improperly), setting `status` to fully disabled (all three bits set) still leaves an open channel for withdrawing tokens from the pool vaults via `collect_creator_fee_permissionless`, which is callable by any unprivileged account. This undermines the intended emergency-pause guarantees for the pool and allows continued fund outflow during an incident.

### Likelihood Explanation
Triggering this requires no special privileges beyond a pool that has accrued nonzero `creator_fees_token_0`/`creator_fees_token_1` (a normal outcome of swaps with creator fees enabled), and the account constraints for `collect_creator_fee_permissionless` are satisfiable by any caller since the recipient is fixed to `pool_state.pool_creator` and the payer only funds ATA creation. This makes exploitation of the pause bypass straightforward whenever an admin disables the pool.

### Recommendation
Add a status check (e.g., a new `PoolStatusBitIndex::CollectFee` bit, or reuse the `Withdraw` bit) in both `collect_creator_fee` and `collect_creator_fee_permissionless`, mirroring the `get_status_by_bit` check already used in `deposit`, `withdraw`, and the swap instructions, so fee collection can be halted together with other outflows when the pool is paused.

### Proof of Concept
1. Perform swaps on a pool with `enable_creator_fee = true` so `creator_fees_token_0`/`creator_fees_token_1` accrue in `PoolState`.
2. Admin calls `update_pool_status` (or equivalent) to set `status` fully disabled (bits for `Deposit`, `Withdraw`, `Swap` all set), intending to halt all fund movement.
3. Any unprivileged account submits `collect_creator_fee_permissionless` with the pool's vault/mint accounts and the recorded `pool_creator`; since the instruction never inspects `pool_state.status`, the transfer of `creator_fees_token_0`/`creator_fees_token_1` from the vaults to the creator's ATA succeeds despite the pause, as shown at [7](#0-6) .

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
