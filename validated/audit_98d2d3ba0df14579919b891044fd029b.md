### Title
Path traversal via unsanitized release asset `Name` written to disk in `gh release download` - (File: pkg/cmd/release/download/download.go)

### Summary
`gh release download` writes each release asset to disk using the asset's `Name` field taken verbatim from the GitHub API response, without ever passing it through `filepath.Base` or any traversal-safe join helper (unlike the sibling `internal/skills/installer` and `internal/zip` packages, which explicitly use `safepaths.Absolute.Join` to reject `..` components). A release/attachment name is attacker-controlled content published on the platform (any user who can create a release with an asset on a repo the victim later runs `gh release download` against), analogous to the Nextcloud report where an attacker-supplied filename embedded in server-provided metadata is trusted verbatim and used to name a file saved to disk.

### Finding Description
In `downloadRun`, each `shared.ReleaseAsset` from the release API response is turned into a `downloadTarget{name: a.Name}` with no sanitization: [1](#0-0) 

That `name` flows into `downloadAsset` → `destinationWriter.Check`/`Copy`, where the final on-disk path is computed only via `filepath.Join(w.dir, name)`: [2](#0-1) [3](#0-2) 

`filepath.Join` does not strip `..` traversal segments — it only cleans redundant separators — so an asset named e.g. `../../.bashrc` or `../../../.ssh/authorized_keys` results in a destination path outside `opts.Destination`. The only asset-name validation present is `isWindowsReservedFilename`, which checks against a fixed list of Windows device names and does nothing for traversal sequences: [4](#0-3) [5](#0-4) 

By contrast, the *only* place a server-supplied filename is sanitized in this same file is the archive `Content-Disposition` case, which explicitly applies `filepath.Base(serverFileName)`: [6](#0-5) 

This shows the codebase's own developers recognize the need to sanitize server-provided/attacker-influenced filenames before using them as disk paths in this exact command — but that treatment was not applied to the (equally attacker-controlled) per-asset `Name` field used in the far more common, non-archive download path. This is consistent with how other download/write paths in this repo (`internal/skills/installer/installer.go`, `internal/zip/zip.go`) are hardened with `safepaths.Absolute.Join`, which returns a `PathTraversalError` for exactly this class of input: [7](#0-6) [8](#0-7) 

### Impact Explanation
An attacker who can publish a release with a maliciously named asset (e.g. on a public/OSS repo accepting external contributions, or on the attacker's own repo that they get a victim to download from) can cause `gh release download` to write file contents outside the user-specified `--dir`/`--output` destination, anywhere the invoking user has write permission (e.g., overwriting `~/.bashrc`, SSH `authorized_keys`, shell profile files, or files with unexpected/misleading extensions to be later executed) — matching the "file write ... outside the intended path" criterion.

### Likelihood Explanation
Requires the victim to run `gh release download` (with `-p`/pattern matching or default "download all assets") against a repository controlled or contributed-to by the attacker; this is a normal, common `gh` workflow (e.g., downloading assets from a fork/PR-linked release, or from any third-party project), so the reachable path is realistic without any admin/MITM/local-attacker prerequisite. Exploitation still depends on GitHub's release-asset upload API not itself rejecting `/`/`..` in asset names server-side, which could not be verified from this repository (it is server-side, out of scope for the CLI code) — this is the main source of uncertainty in the finding.

### Recommendation
Sanitize `a.Name` before use, mirroring the existing `filepath.Base` treatment applied to the archive `Content-Disposition` filename, or better, route the destination path construction through `internal/safepaths.Absolute.Join` (already used by `internal/zip` and `internal/skills/installer`) so any `..`-containing or absolute asset name is rejected rather than silently joined.

### Proof of Concept
1. Attacker creates a release in a repository (own repo, or a repo where they can attach a release asset) with an asset uploaded under the name `../../../../tmp/pwned.sh` (or a path targeting the victim's home directory such as `../../.bashrc`).
2. Victim runs, from an arbitrary working directory:
   ```
   gh release download v1.0.0 -R attacker/repo -D safe-output-dir
   ```
3. Because `downloadTarget.name` is the raw asset name and `destinationWriter.makePath` does `filepath.Join(w.dir, name)` with no `filepath.Base`/traversal check, the file is written at a path resolved outside `safe-output-dir`, potentially overwriting a sensitive file the victim did not intend to touch.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}

func isWindowsReservedFilename(filename string) bool {
	// Windows terminals should prevent the creation of these files
	// but that behavior is not enforced across terminals. Prevent
	// the user from downloading files with these reserved names as
	// they represent an exploit vector for bad actors.
	// Reserved filenames defined at:
	// https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file#win32-file-namespaces
	reservedFilenames := []string{"CON", "PRN", "AUX", "NUL", "COM0",
		"COM1", "COM2", "COM3", "COM4", "COM5",
		"COM6", "COM7", "COM8", "COM9", "COM¹",
		"COM²", "COM³", "LPT0", "LPT1", "LPT2",
		"LPT3", "LPT4", "LPT5", "LPT6", "LPT7",
		"LPT8", "LPT9", "LPT¹", "LPT²", "LPT³"}

	// Normalize type case and remove file type extension from filename.
	filename = strings.ToUpper(strings.Split(filename, ".")[0])

	return slices.Contains(reservedFilenames, filename)
}

func ExtractZip(zr *zip.Reader, destDir safepaths.Absolute) error {

		fpath, err := destDir.Join(zf.Name)

			var pathTraversalError safepaths.PathTraversalError

			}

		}

		if err := extractZipFile(zf, fpath); err != nil {
			return fmt.Errorf("error extracting %q: %w", zf.Name, err)
		}
	}
	return nil
