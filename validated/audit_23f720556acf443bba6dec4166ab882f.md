### Title
Insolvent liquidation can seize all collateral while underpaying by one token unit per debt leg - ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary

`NormalizedRepaymentPlan.seize_all` treats any repayment within the USD value of one base unit per repayment leg as equivalent to the collateral-backed liquidation quote. For an insolvent account, this causes `calculate_seized_collateral` to seize every collateral position even though the liquidator paid less than the amount that economically backs that collateral. The slack is not capped in USD and scales with the number, decimals, and prices of the repaid debt markets.

### Finding Description

The liquidation entrypoint is permissionless:

`Controller::liquidate(liquidator, account_id, debt_payments, seize_mode)`

For an insolvent account, `normalize_repayment_plan` computes the collateral-backed quote as `ideal_repayment_usd`, then sets `seize_all` when:

```rust
repay_usd + one_unit_per_leg_usd(repaid_tokens) >= ideal_repayment_usd
```

This logic is in `contracts/controller/src/positions/liquidation/math.rs`.

`one_unit_per_leg_usd` adds the full oracle-priced USD value of one native token unit for every repayment leg. A native unit is only “dust” if the asset has sufficient decimals and a sufficiently low whole-token price. For a 3-decimal debt asset priced at `$1,000`, one unit is worth `$1`; at a higher token price it can be substantially more. The total allowance is the sum across every repaid debt leg.

When `seize_all` is true, `calculate_seized_collateral` replaces each pro-rata seizure with the position’s entire held value:

```rust
let capped_ray = if repayment.seize_all {
    actual_ray
} else {
    seizure_ray.min(actual_ray)
};
```

Consequently, a liquidator can submit positive payments across the account’s debt legs whose total is below the collateral-backed quote by less than the summed one-unit allowance, yet receive every collateral position.

After seizure, the account has no collateral but retains the unpaid debt. `check_bad_debt_after_liquidation` in `contracts/controller/src/positions/liquidation/apply.rs` can immediately classify the remaining debt as socializable bad debt because its collateral total is zero, causing the underpayment to become a supplier loss.

### Impact Explanation

This is theft of collateral value and protocol insolvency.

Without `seize_all`, a repayment `R` should support seizure of approximately:

```text
R × (1 + liquidation_bonus)
```

With `seize_all`, the liquidator receives all collateral `C` provided that:

```text
R + Σ one_unit_usd(debt_leg) >= floor(C / (1 + base_bonus))
```

The unbacked portion scales with:

```text
number_of_repaid_debt_legs × debt_token_price / 10^debt_token_decimals
```

The liquidator can use `SeizeMode::Transfer` when collateral liquidity exists, or `SeizeMode::Credit(0)` to move the supply shares into a new account controlled by the liquidator. The residual debt is then socialized through the normal bad-debt path, transferring the shortfall to suppliers.

### Likelihood Explanation

The path requires:

1. An account with `health_factor < 1`.
2. `total_collateral < total_debt`.
3. At least one positive repayment on each debt leg used for the rounding allowance.
4. The sum of one native unit from those legs to cover the difference between the submitted payment and the collateral-backed quote.

An unprivileged liquidator can invoke `liquidate` on any eligible account. `Credit(0)` creates a receiving account owned by the liquidator and avoids requiring collateral cash in the pool. The economic severity depends on the debt assets’ decimals, prices, and the borrow-position limit; low-decimal or high-priced debt assets materially increase the exploitable allowance.

### Recommendation

Do not treat one native unit per repayment leg as universally negligible.

Replace the `seize_all` allowance with a strict USD-denominated dust bound, such as a fixed protocol-configured WAD threshold, and require:

```text
repay_usd + dust_allowance_usd >= ideal_repayment_usd
```

The threshold should not scale with the number or price of debt legs. Alternatively, when `repay_usd < ideal_repayment_usd`, always calculate seizure pro-rata from the actual repayment and leave the unseized collateral on the account for subsequent liquidation or bad-debt cleanup.

### Proof of Concept

Assume an insolvent account has:

- Total collateral `C = $10,500`
- Base liquidation bonus `5%`
- Collateral-backed quote `I = floor(C / 1.05) = $10,000`
- Two repaid debt assets, each with 3 decimals and a price of `$1,000` per whole token

Each native debt unit is worth `$1`, so `one_unit_per_leg_usd` contributes `$2`.

The liquidator calls:

```text
liquidate(
    liquidator = attacker,
    account_id = victim,
    debt_payments = [
        ((hub_1, debt_asset_1), payment_1),
        ((hub_2, debt_asset_2), payment_2)
    ],
    seize_mode = SeizeMode::Credit(0)
)
```

with the two positive payments totaling `$9,999`.

The plan satisfies:

```text
$9,999 + $2 >= $10,000
```

so `seize_all` becomes true. `calculate_seized_collateral` then sets every collateral leg’s `capped_ray` to `actual_ray`, crediting the attacker-controlled account with all `$10,500` of collateral rather than the approximately `$10,498.95` backed by the payment.

The account retains the unpaid debt and has no remaining collateral, allowing the subsequent cleanup path to socialize the enlarged residual loss.
