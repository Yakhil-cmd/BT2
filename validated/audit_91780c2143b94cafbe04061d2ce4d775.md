## Analysis

The RustFS bug's core defect is a **permission-delegation short-circuit**: a component that authorizes minting a new, more-privileged credential (`deny_only` in RustFS) does not actually verify that the new credential's effective rights are contained within the caller's own rights.

The Polkadot SDK equivalent of "minting a new credential with implicit inherited privilege" is **`pallet_proxy`'s `add_proxy`/`remove_proxy` self-service escalation guard**, which is enforced purely through `ProxyType::is_superset` rather than by actually checking that the new proxy type's `filter` is a subset of the delegate's own `filter`: [1](#0-0) 

This exact bug class — a `ProxyType` declaring itself `is_superset` of another type whose `filter` admits calls the "superset" type's own `filter` denies — was already found and fixed for `asset-hub-westend` (`NonTransfer` vs `Governance`) via PR referenced in `prdoc/pr_12769.prdoc`, with a regression test added: [2](#0-1) [3](#0-2) 

The identical class of bug still exists, unfixed, in `polkadot/runtime/westend/src/lib.rs`, between `ProxyType::NonTransfer` and `ProxyType::SudoBalances`.

### Title
`NonTransfer` proxy on Westend relay chain falsely claims superset of `SudoBalances`, enabling privilege escalation to Root-dispatched Balances calls - (File: `polkadot/runtime/westend/src/lib.rs`)

### Summary
`ProxyType::NonTransfer`'s call filter explicitly denies the Balances pallet and the Sudo pallet ("Specifically omitting Sudo pallet" / "Specifically omitting the entire Balances pallet"), but `ProxyType::is_superset` unconditionally declares `NonTransfer` a superset of every other `ProxyType`, including `SudoBalances`, whose filter admits `Sudo::sudo(Balances(..))`. Because `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` solely on `is_superset` (not on `filter`), a `NonTransfer` delegate can self-grant a `SudoBalances` proxy and use it to dispatch Balances calls as `Root` — exactly the permission `NonTransfer` was designed to withhold.

### Finding Description
`ProxyType::filter` for `NonTransfer` is an explicit allow-list that omits both `RuntimeCall::Sudo(..)` and the entire `Balances` pallet: [4](#0-3) 

`ProxyType::filter` for `SudoBalances` admits `Sudo::sudo` calls wrapping a `Balances` call, plus `Utility`: [5](#0-4) 

`ProxyType::is_superset` collapses to a blanket rule that treats `NonTransfer` as a superset of *every* other type, without checking that `NonTransfer`'s filter actually dominates each type's filter: [6](#0-5) 

`pallet_proxy::do_proxy` enforces privilege containment for nested `add_proxy`/`remove_proxy` calls purely via `is_superset`, never re-checking `filter` for the added proxy type itself: [7](#0-6) 

Combining these: a delegate who only holds a `NonTransfer` proxy for account `real` can call `Proxy::proxy(real, None, Proxy::add_proxy { delegate: <self_or_accomplice>, proxy_type: SudoBalances, .. })`. The inner filter check (`def.proxy_type.is_superset(&SudoBalances)`) passes because `NonTransfer` unconditionally claims superset status. The delegate then calls `Proxy::proxy(real, None, Sudo::sudo { call: Balances::force_transfer/force_set_balance/... })` through the newly minted `SudoBalances` proxy. `SudoBalances::filter` admits this call. Once dispatched, `pallet_sudo::sudo` — if `real` is the chain's Sudo key — executes the inner call with `RawOrigin::Root`, which bypasses `BaseCallFilter` entirely (as documented for Root elsewhere in the codebase, e.g. `substrate/frame/scheduler/src/lib.rs:36-39`), giving the delegate full, filter-free control over Balances on behalf of `real` — precisely the capability `NonTransfer`'s own filter comment says is "specifically omitted."

This mirrors the RustFS analog precisely: a restricted delegated credential (`NonTransfer` proxy ≈ restricted service account) is used to *mint a new, more powerful credential* (`SudoBalances` proxy ≈ unrestricted service account) through a broken containment check (`is_superset` blanket rule ≈ `deny_only` short-circuit), inheriting privileges the restricted credential itself was never granted.

### Impact Explanation
If the account that granted the `NonTransfer` proxy (`real`) is the chain's Sudo key holder — a normal and expected relationship on Westend, where the Sudo pallet remains active and root delegates limited administrative/session-key duties to a `NonTransfer` proxy believing Balances/Sudo access is withheld — the delegate escalates to Root-level, filter-free `Balances` calls (e.g. `force_transfer`, `force_set_balance`), a direct integrity/confidentiality breach of the delegation contract and unauthorized dispatch of privileged calls. Even when `real` is not the sudo key, the code-level invariant that `is_superset` must not exceed what `filter` actually grants is broken, matching the class of bug Parity already patched once (PR #12769) but missed in this location.

### Likelihood Explanation
No privileged role, governance action, or stolen key is required by the attacker: obtaining a `NonTransfer` proxy grant from any account is a normal, permissionless, everyday proxy-pallet operation (`add_proxy` is callable by any signed account for any delegate). The only condition for full-severity impact is that the delegator is the Sudo key holder — a realistic scenario on Westend, where Sudo remains wired and is commonly used by chain operators who may delegate day-to-day (non-transfer) operations to bots/co-signers.

### Recommendation
Fix `ProxyType::is_superset` in `polkadot/runtime/westend/src/lib.rs` to stop unconditionally treating `NonTransfer` as a superset of all other types; only declare superset relationships that are provably backed by `filter` containment (as was done for asset-hub-westend in PR #12769), and add a lattice regression test analogous to `proxy_type_superset_relation_matches_call_filters` for the relay-chain runtime.

### Proof of Concept
Failed guard: `substrate/frame/proxy/src/lib.rs:1010` (`!def.proxy_type.is_superset(proxy_type) => false`) passes for `(NonTransfer, SudoBalances)` because of `polkadot/runtime/westend/src/lib.rs:1027` (`(ProxyType::NonTransfer, _) => true`), despite `NonTransfer::filter` (lines 954-982, explicitly omitting Sudo/Balances) not admitting the calls `SudoBalances::filter` (lines 987-993) admits.

Minimal integration-test reproduction (pattern mirroring the existing `substrate/frame/proxy/src/tests.rs` harness / `cumulus/.../tests/tests.rs::non_transfer_proxy_is_not_a_superset_of_governance`), to be run against `westend-runtime`:
```rust
use polkadot_runtime::ProxyType; // westend runtime
use frame_support::traits::InstanceFilter;

#[test]
fn non_transfer_is_not_a_superset_of_sudo_balances() {
    let sudo_balances_call = RuntimeCall::Sudo(pallet_sudo::Call::sudo {
        call: Box::new(RuntimeCall::Balances(pallet_balances::Call::force_transfer { .. })),
    });
    assert!(ProxyType::SudoBalances.filter(&sudo_balances_call));
    assert!(!ProxyType::NonTransfer.filter(&sudo_balances_call)); // denied, as documented
    // BUG: is_superset still returns true, letting NonTransfer mint a SudoBalances proxy.
    assert!(ProxyType::NonTransfer.is_superset(&ProxyType::SudoBalances));
}
```
This assertion currently passes on the unfixed code (confirming the vulnerable state); the fix should make `is_superset` return `false` here, matching `filter` containment. I have not executed this against a live/public network; the above is a local unit-level reproduction path using the existing `pallet_proxy`/runtime `ProxyType` test harness, not a network claim.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
