### Title
Cross-organization commit status forgery via webhook signature/repository binding mismatch enabling unauthorized continuous deployment - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to use for HMAC verification based on `repository_owner`, a value read directly from the untrusted webhook payload [1](#0-0) . Once the signature is accepted, the `status` webhook handler writes a commit status to **any** commit in the database matched purely by SHA, with no verification that the SHA belongs to the organization/repository whose secret was used to authenticate the request [2](#0-1) . This breaks the binding "organization that authenticated == repository that is written," directly analogous to the ETH/WETH identity-mismatch bug: a check meant to scope an action to one entity silently fails to enforce that scoping when a different-but-related identity is involved.

### Finding Description
`Shipit::WebhooksController` computes the signing organization from the payload itself:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 
and verifies the HMAC using that organization's configured secret:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(...)
``` [4](#0-3) 

Any organization onboarded into the multi-tenant Shipit instance (i.e. any customer/team that has set up their own GitHub App/webhook secret for their own repositories) can compute a valid signature for a payload whose `repository.owner.login` is their own org — the field the controller trusts for verification.

The `status` event handler then processes the event using only the SHA in the payload, with no re-check that the commit's stack/repository actually corresponds to the authenticated organization:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [2](#0-1) 

Unlike `PushHandler`/`CheckSuiteHandler`, which scope lookups through `stacks` (derived from `Repository.from_github_repo_name(repository_name)`) [5](#0-4) , `StatusHandler` performs a completely unscoped `Commit.where(sha:)` lookup, so it will match a commit belonging to a completely unrelated organization's stack as long as the SHA matches. Since git SHAs of public repositories are public information (visible in commit URLs, PR pages, etc.), an attacker who controls one legitimate, low-privilege organization in the Shipit instance can target any known commit SHA belonging to a different organization's stack.

The forged status feeds directly into deploy-gating logic:
```ruby
def deployable?
  !locked? && (stack.ignore_ci? || (success? && !blocked?))
end
...
def schedule_continuous_delivery
  return unless deployable? && stack.continuous_deployment? && stack.deployable?
  ContinuousDeliveryJob.set(wait: RECENT_COMMIT_THRESHOLD).perform_later(stack)
end
``` [6](#0-5) 
and `ContinuousDeliveryJob` unconditionally deploys once a commit is deemed deployable:
```ruby
def perform(stack)
  return unless stack.continuous_deployment?
  return if stack.continuous_delivery_schedule && !stack.continuous_delivery_schedule.can_deploy?
  return if stack.occupied?
  stack.trigger_continuous_delivery
end
``` [7](#0-6) 

### Impact Explanation
An attacker who administers any single organization onboarded to a shared Shipit instance can forge a `success` status webhook for a specific, publicly-known commit SHA belonging to a *different* organization's stack that has `continuous_deployment` enabled. This triggers `ContinuousDeliveryJob`, causing an unauthorized deploy of the victim organization's stack — matching the Critical "unauthorized deploy" impact criterion, without needing any Shipit session, `ApiClient` token, or the victim organization's own webhook secret.

### Likelihood Explanation
Requires only that the attacker legitimately administers one organization already integrated with the shared Shipit instance (a normal, unprivileged tenant relationship) and knows a target commit SHA from a public repository. No repository write access, GitHub App private key, or victim credentials are needed — only crafting a raw HTTP POST to the public `/webhooks` endpoint with a valid signature for their own organization.

### Recommendation
Scope `StatusHandler#process` (and any other unscoped handler) to only update commits belonging to stacks whose repository matches the payload's `repository.full_name`, and additionally verify that the organization used to authenticate the webhook signature (`repository_owner`) matches the owning organization of the repository named in the payload before processing any handler. I.e., enforce `repository_owner_used_for_verification == organization_owning(payload.repository.full_name)` as an invariant in `WebhooksController#verify_signature` or in the base `Handler`.

### Proof of Concept
1. Attacker controls `attacker-org`, a legitimate but low-privilege organization onboarded to the shared Shipit instance, and knows its configured `webhook_secret`.
2. Attacker identifies a target commit SHA `S` belonging to `victim-org/victim-repo`, a stack with `continuous_deployment: true`, from GitHub's public commit history.
3. Attacker POSTs to `/webhooks` with `X-Github-Event: status`, a body containing `{"repository":{"owner":{"login":"attacker-org"}}, "sha": "S", "state": "success", ...}`, and `X-Hub-Signature` computed with `attacker-org`'s known secret.
4. `verify_signature` resolves `Shipit.github(organization: "attacker-org")` and successfully verifies the signature.
5. `StatusHandler#process` runs `Commit.where(sha: "S")`, finds the victim's commit (unscoped by repository/org), and creates a `success` status on it.
6. If this makes the commit `deployable?`, `schedule_continuous_delivery` enqueues `ContinuousDeliveryJob`, which deploys `victim-org/victim-repo`'s stack without any authorization from that organization.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

        request.raw_post
      )
