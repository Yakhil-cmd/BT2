### Title
Memory-leak DoS via unbounded `eventBus` listener accumulation when processing crafted/unresolvable private payment chains - (File: wallet.js)

### Summary
The ImageMagick advisory describes a memory leak triggered on an error/incomplete-processing path when a crafted input (APP1JPEG) is parsed but never fully released, allowing resource exhaustion. `ocore`'s private-payment handling in `wallet.js` has an analogous bug class: any paired device (chat correspondent) or hub-routed peer can send a `private_payments` message whose chains reference units that never actually arrive/validate, permanently leaking `eventBus` listeners and their captured closures with no cleanup path, causing unbounded memory growth.

### Finding Description
`handlePrivatePaymentChains` [1](#0-0)  accepts an attacker-controlled `body.chains` array, performs only shallow structural checks, and for each chain registers a listener keyed by `'private_payment_validated-'+unit+'-'+json_payload_hash+'-'+output_index`: [2](#0-1) 

This listener is only ever released by:
1. the key event firing (`eventBus.emit(key, ...)`), which happens solely inside `handleSavedPrivatePayments` once the referenced unit is fully downloaded/validated [3](#0-2) , or
2. `cancelAllKeys()` calling `eventBus.removeAllListeners(key)`, which only runs on a synchronous validation error during the *same* call [4](#0-3) .

If the attacker supplies a syntactically valid chain whose head `unit` is a bogus hash that is never actually broadcast/received (or the unit never becomes retrievable), `handleOnlinePrivatePayment` takes the `ifNew` branch, saves a row to `unhandled_private_payments`, and returns `ifQueued` without ever completing validation [5](#0-4) . The corresponding `eventBus.once(key, ...)` listener in `wallet.js` registered for that never-resolving `unit`/`json_payload_hash`/`output_index` combination is left dangling forever.

The only periodic cleanup, `cleanBadSavedPrivatePayments`, deletes stale rows from `unhandled_private_payments` after 24 hours but never emits the corresponding `key` event, so it does not release the matching listener — and this cleanup runs for full nodes only ("full only") [6](#0-5) . `handledChainsCache`, which is meant to deduplicate identical chain payloads, is populated only on the success path (`handledChainsCache[cache_key] = Date.now();` after `async.eachSeries` completes without `err`) [7](#0-6) , so chains that never resolve are never cached and each resend/variation creates a brand-new, uniquely-keyed, permanently orphaned listener plus its retained closures (`arrChains`, `assocValidatedByKey`, `ws`, `cb`, etc.).

### Impact Explanation
A single malicious or misbehaving paired device (a chat correspondent authorized to exchange private payments) or a hub relaying `private_payments` messages can repeatedly submit distinct crafted chains referencing units that will never validate. Each submission permanently retains an `EventEmitter` entry and its closure in the process's memory, since `key` is unique per (unit, payload hash, output_index) and thus bypasses Node's per-event max-listener warnings while still growing the internal `_events` map unbounded. Sustained exploitation drives memory exhaustion on the hub/wallet node, denying service — a concrete "network/node unable to continue confirming/serving" style outcome caused entirely by processing attacker-supplied data, matching the required Medium/High impact bar (denial of service via resource exhaustion), analogous to the referenced ImageMagick memory-leak advisory.

### Likelihood Explanation
Reaching this path requires only being a device correspondent that can send the `private_payments` subject to a wallet/hub (`handleMessageFromHub` → `handlePrivatePaymentChains`) [8](#0-7) , no special privilege beyond normal pairing is needed, and the malformed/unresolvable chain only needs to pass the shallow structural `isNonemptyObject`/`isNonemptyArray` checks [9](#0-8) . Repeating the request with varied bogus unit hashes/payloads is trivial and cheap for the attacker, while each request costs the victim a permanently retained listener/closure.

### Recommendation
- Ensure `eventBus.once(key, ...)` listeners are always eventually removed, e.g. via a timeout that both removes the listener and cleans up `assocValidatedByKey`/`unhandled_private_payments` state if the key event does not fire within a bounded window.
- Have `cleanBadSavedPrivatePayments` (and its light-node equivalent, which currently doesn't exist) emit `key` with `false` (or otherwise notify pending listeners) before/when deleting stale `unhandled_private_payments` rows so registered listeners are released.
- Track and cap the number of pending/unresolved private-payment validations per peer/device, rejecting or evicting oldest entries once a limit is exceeded.

### Proof of Concept
1. As a paired device correspondent, send a `private_payments` hub message whose `chains[0]` head element has `unit` set to a syntactically valid but never-published/never-retrievable unit hash, with a well-formed `payload` (asset/inputs/outputs populated so it passes the `arrChains.every` check).
2. The hub/wallet processes it via `handlePrivatePaymentChains` → `network.handleOnlinePrivatePayment` → `ifNew`/`savePrivatePayment`, returning `ifQueued`, which registers a permanent `eventBus.once(key, ...)` listener.
3. Never actually broadcast the referenced unit; the row in `unhandled_private_payments` is either never cleaned (light node) or cleaned after 24h without releasing the listener (full node).
4. Repeat step 1 with new fabricated unit hashes/payloads in a loop; observe `eventBus._events` (or Node heap snapshots) growing unbounded with orphaned listeners and retained `arrChains` closures, eventually exhausting process memory.

function handlePrivatePaymentChains(ws, body, from_address, callbacks){
	var arrChains = body.chains;
	if (!ValidationUtils.isNonemptyArray(arrChains))
		return callbacks.ifError("no chains found");
	if (!arrChains.every(c =>
		isNonemptyArray(c) &&
		c.every(e =>
			isNonemptyObject(e) &&
			isNonemptyString(e.unit) &&
			isNonemptyObject(e.payload) &&
			isNonemptyString(e.payload.asset) &&
			isNonemptyArray(e.payload.inputs) &&
			isNonemptyArray(e.payload.outputs) &&
			e.payload.inputs.every(isNonemptyObject) &&
			e.payload.outputs.every(isNonemptyObject)
		)
	))
		return callbacks.ifError("malformed private chain");
	try {
		var cache_key = objectHash.getBase64Hash(arrChains);
	}
	catch (e) {
		return callbacks.ifError("chains hash failed: " + e.toString());		
	}
