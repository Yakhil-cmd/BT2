### Title
Unvalidated `field`/`operator` in explicit `conditions` allows silent block-rule bypass via `Rule.from_dict`/`Condition.from_dict` - (File: plugins/hookify/core/config_loader.py)

### Summary
`Rule.from_dict` only falls back to the hardcoded, always-valid legacy `pattern`→`field` inference when the `conditions` list is empty; if any non-empty `conditions` list is present in frontmatter, that entirely replaces the safe legacy path, and `Condition.from_dict` performs no validation of the `field`/`operator` values. A rule file (repo-shipped or produced by `/hookify` generation) containing a `block` action with an explicit condition using a misspelled/unsupported `field` will silently never match, neutering the block while appearing to be a normal, enabled block rule.

### Finding Description
`Rule.from_dict` (`plugins/hookify/core/config_loader.py:44-84`) builds `conditions` from an explicit `conditions:` frontmatter list when present [1](#0-0) , and only derives conditions from the legacy `pattern` field when the explicit list produced nothing (`if simple_pattern and not conditions:`), using a fixed, always-known-good `field` mapping (`bash`→`command`, `file`→`new_text`, else→`content`) [2](#0-1) .

`Condition.from_dict` accepts any `field`/`operator` string with no whitelist or validation, defaulting `field` to `''` when absent [3](#0-2) .

In `rule_engine.py`, `_rule_matches` requires **every** condition to match (`for condition in rule.conditions: if not self._check_condition(...): return False`) [4](#0-3) . `_check_condition` calls `_extract_field(condition.field, ...)`, and if the field isn't one of the tool's known keys/special names, `_extract_field` returns `None`, immediately failing the condition (`if field_value is None: return False`) [5](#0-4) [6](#0-5) .

Because a `block`-action rule only fires if `_rule_matches` returns `True`, any explicit condition with a subtly wrong `field` (e.g. `feild`, `cmd`, `text`, wrong case) makes the rule permanently non-matching, i.e. the block silently never triggers — a strictly weaker outcome than the legacy pattern path, which cannot produce an invalid field. Since `/hookify` generation output and repo-shipped `.claude/hookify.*.local.md` rule files are both attacker-influenceable frontmatter sources feeding directly into `Rule.from_dict` via `load_rule_file`/`load_rules` [7](#0-6) , this lets an attacker craft or induce generation of a rule that *looks* like an effective `block` rule (has a `block` action, a message, `enabled: true`) but never actually blocks anything.

### Impact Explanation
A user believing a dangerous-command or dangerous-write guard (`action: block`) is active is not actually protected, because the explicit-condition path silently fails to match due to an unvalidated `field`. This directly violates the stated invariant that default/explicit field inference must not weaken enforcement, and can lead to unauthorized file writes/reads or command execution proceeding unblocked, matching the "Unauthorized file read or write outside the user-approved workspace" impact category.

### Likelihood Explanation
Feasible and repeatable: any repo-shipped `.claude/hookify.*.local.md` file, or any output of `/hookify` rule generation containing an explicit `conditions:` block with a minor typo/unsupported field name, reproduces this deterministically — there is no randomness or race condition involved, and no validation anywhere in `Condition.from_dict`, `Rule.from_dict`, or `_check_condition`/`_extract_field` catches it.

### Recommendation
- In `Condition.from_dict`, validate `field` against a whitelist of fields understood by `_extract_field` (`command`, `new_text`/`new_string`, `old_text`/`old_string`, `content`, `file_path`, `reason`, `transcript`, `user_prompt`) and raise/reject the rule (or fall back to a fail-closed default) if it's unrecognized, instead of silently constructing an unmatched condition.
- In `_extract_field`/`_check_condition`, distinguish "field name is invalid/unsupported" from "field value legitimately absent", and log/warn loudly (or fail-closed for `block` rules) rather than silently returning `False`.
- Consider validating rules at load time (`load_rule_file`) and refusing to enable a `block` rule whose conditions cannot ever match any known field.

### Proof of Concept
Unit test to add to `plugins/hookify/core/config_loader.py` / `rule_engine.py` test suite:
```python
frontmatter = {
    "name": "block-rm",
    "enabled": True,
    "event": "bash",
    "action": "block",
    "conditions": [
        {"field": "cmd", "operator": "regex_match", "pattern": r"rm\s+-rf"}  # typo: should be "command"
    ],
}
rule = Rule.from_dict(frontmatter, "Blocked dangerous rm command")

engine = RuleEngine()
result = engine.evaluate_rules([rule], {
    "hook_event_name": "PreToolUse",
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /"},
})

# Expected (vulnerable) behavior: result == {} -- the block rule never fires
# Desired (fixed) behavior: rule load should reject/warn on invalid field,
# or evaluate_rules should still deny the dangerous command.
assert result == {}, "confirms block rule is silently bypassed due to invalid field name"
```
Compare against the legacy equivalent (`"pattern": r"rm\s+-rf"` instead of `conditions`), which correctly infers `field="command"` and blocks the same input — demonstrating the behavioral divergence between legacy and explicit condition parsing.

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
