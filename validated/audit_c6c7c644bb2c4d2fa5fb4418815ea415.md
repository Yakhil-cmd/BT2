### Title
`GitHubApp#verify_webhook_signature` accepts unsigned/forged webhooks when an org's `secrets.yml` entry omits `webhook_secret` - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever `webhook_secret` is `nil`/blank for the resolved GitHub organization, before ever inspecting the `X-Hub-Signature` header or HMAC of the request body. Since `WebhooksController#verify_signature` resolves the organization purely from attacker-controlled `repository.owner.login` (or `organization.login`) in the JSON payload, an unprivileged internet user can send a forged `POST /webhooks` for any org configured without a `webhook_secret` and have it fully processed.

### Finding Description
The claimed binding is: `verified == (org.webhook_secret.present? AND HMAC-SHA1(secret, raw_body) == signature)`. The actual code breaks this binding: [1](#0-0) 

`verify_webhook_signature` returns `true` unconditionally at line 77 (`return true unless webhook_secret`) whenever the resolved app's config has no `webhook_secret` key, never reaching the `algorithm`/`SecureCompare.secure_compare` HMAC check. So `verified == true` while the right-hand side of the intended binding (`webhook_secret present AND HMAC match`) is false — the two sides diverge.

The controller path that reaches this: [2](#0-1) [3](#0-2) 

`repository_owner` is read straight from the untrusted JSON body (`params.dig('repository', 'owner', 'login')`), used to select the `GitHubApp` via `Shipit.github(organization: repository_owner)`, and then `verify_signature` accepts the request whenever `verify_webhook_signature` returns true — which it does unconditionally for any org lacking `webhook_secret`. No other guard (`drop_unhandled_event`, `check_if_ping`) inspects authenticity; they only filter by event type. The `GithubOrganizationUnknown` rescue only protects against organizations that aren't configured at all — it does nothing for organizations that are configured but missing `webhook_secret`.

Attack: attacker crafts any webhook JSON body (e.g., a `push` event) with `repository.owner.login` set to an org name that exists in the host's `secrets.github` config but has no `webhook_secret` entry (e.g., an app-only/installation-only org entry), sends it to `POST /webhooks` with any/garbage `X-Hub-Signature` header (or omitted). `verify_signature` calls `verify_webhook_signature('garbage', raw_body)`, which returns `true` at line 77 without evaluating `signature` or `message` at all, and the forged event is dispatched to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` in `create`.

### Impact Explanation
For any org whose `secrets.github` entry lacks `webhook_secret` (plausible for orgs configured only for API/app authentication, e.g., `app_id`/`installation_id` without a webhook integration), an attacker with zero credentials can forge arbitrary GitHub webhook events (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) for that org's repositories. This can trigger `GithubSyncJob` enqueuing (fake `push` heads), status/check writes on real commits, team/membership mutation (`membership` events create/delete `Membership`/`Team`/`User` records), and other webhook-driven side effects — all without ever possessing the real `webhook_secret`. This is an authentication bypass on the primary trust boundary for inbound GitHub events, matching the Critical category ("forged webhook ... accepted").

### Likelihood Explanation
Requires only that the deployment's `secrets.github` config contains at least one organization entry without a `webhook_secret` key (a plausible, config-dependent but not far-fetched setup — e.g., an org onboarded with only App credentials or one where the operator simply forgot to set `webhook_secret`). No other Shipit or GitHub secret is needed by the attacker: no session, no API token, no private key. Cost is a single unauthenticated HTTP POST, fully repeatable and scriptable against any repository under that org.

### Recommendation
Change `verify_webhook_signature` to fail closed when no `webhook_secret` is configured, e.g.:
```ruby
def verify_webhook_signature(signature, message)
  return false if webhook_secret.blank?
  ...
end
```
Additionally, consider making `webhook_secret` a required field validated at boot/config-load time so misconfigured orgs fail fast rather than silently accepting all webhooks.

### Proof of Concept
Unit test (`test/lib/shipit/github_app_test.rb` style, no live GitHub):
```ruby
config_without_secret = { app_id: 1, installation_id: 2 } # no webhook_secret key
app = Shipit::GitHubApp.new('org-without-secret', config_without_secret)

# Binding under test: verified == (webhook_secret present? && HMAC matches)
# Expected (secure) result: false, since webhook_secret is absent -> RHS is false
assert_equal false, app.verify_webhook_signature('garbage', 'any body')
```
Integration test (`test/controllers/webhooks_controller_test.rb` style):
```ruby
test "forged webhook accepted for org missing webhook_secret" do
  Shipit.stubs(:github).with(organization: 'org-without-secret')
    .returns(Shipit::GitHubApp.new('org-without-secret', { app_id: 1, installation_id: 2 }))

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef'
  body = JSON.parse(payload(:push_master))
  body['repository']['owner']['login'] = 'org-without-secret'

  assert_enqueued_with(job: GithubSyncJob) do
    post :create, body: body.to_json, as: :json
  end
  assert_response :ok # should be :unprocessable_entity after fix
end
```
Both currently pass with `verified == true` despite no valid signature, demonstrating the bypass; after applying the recommended fix, both assert `false`/`422`.

### Citations

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

**File:** app/controllers/shipit/webhooks_controller.rb (L24-49)
```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
