The CVE-2019-19221 bug class is a C-specific memory-safety defect: `archive_wstring_append_from_mbs` calls `mbrtowc`/`mbtowc` without properly validating buffer bounds, producing an out-of-bounds *read* on malformed multibyte sequences. This requires unchecked pointer/index arithmetic over raw bytes — a bug class that Rust's `str`/`String`/slice APIs structurally prevent via bounds-checked, UTF-8-validating conversions (`core::str::from_utf8`, `String::from_utf8`, etc.), which return `Result` and never read past the provided slice.

I searched the codebase for analogous string/byte decoding entry points reachable from real user input:
- `substrate/client/tracing/src/logging/fast_local_time.rs` uses `str::from_utf8_unchecked` only on an internally-constructed, ASCII-only buffer that the code itself fully controls — not attacker-supplied bytes. [1](#0-0) 
- `substrate/primitives/runtime/src/offchain/http.rs` `Header::name`/`Header::value` use `str::from_utf8_unchecked`, but the comment states these are always constructed from valid `&str` inputs, not raw untrusted bytes from an external network response body. [2](#0-1) 
- `substrate/frame/contracts/src/wasm/runtime.rs` `debug_message` explicitly validates with `core::str::from_utf8(&data).ok()` before use, silently dropping invalid UTF-8 rather than reading out of bounds. [3](#0-2) 
- `substrate/primitives/runtime-interface/src/pass_by.rs` marshals FFI string arguments via `String::from_utf8`, returning an error on invalid UTF-8 rather than performing unchecked decoding. [4](#0-3) 
- `substrate/frame/revive/uapi/src/precompiles/utils.rs` `decode_bytes` does raw slice indexing (`input[28..32]`, `input[32+offset..32+offset+bytes_len]`) without prior bounds validation, but Rust slice indexing panics (aborting the call) rather than reading out-of-bounds memory, and any out-of-range access is a checked panic, not an information-disclosure read as in the CVE. [5](#0-4) 

None of these constitute a demonstrable memory-safety out-of-bounds read analogous to the libarchive CVE, because Rust's safe string/slice APIs either bounds-check-and-error or bounds-check-and-panic, never silently reading adjacent memory. No unsafe, unchecked multibyte/locale-aware decoding of attacker-controlled bytes reachable through a signed extrinsic, contract call, or XCM message was found.

pub fn decode_bytes(input: &[u8], out: &mut [u8]) -> usize {
	let mut buf = [0u8; 4];
	buf[..].copy_from_slice(&input[28..32]);
	let offset = u32::from_be_bytes(buf) as usize;

	let mut buf = [0u8; 4];
