### Title
Webhook signature authenticates one organization while the handler writes GitHub CI status/state for a different, unrelated repository - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` authenticates an inbound GitHub webhook using the `webhook_secret` of the organization named inside the *unverified* JSON payload (`repository.owner.login` / `organization.login`), but the event handlers that subsequently execute (`StatusHandler`, `PushHandler`) act on a *different* field of that same untrusted payload (`repository.full_name`, or, for `StatusHandler`, no repository scoping at all) without ever confirming it belongs to the organization whose secret validated the signature.

### Finding Description
`verify_signature` derives the signing organization purely from payload content, not from anything cryptographically bound to the signature itself: [1](#0-0) [2](#0-1) 

In a multi-tenant deployment, each GitHub organization can have its own `webhook_secret` (`Shipit.github_organizations` / `Shipit.github_app_config`): [3](#0-2) 

The signature is only checked against the HMAC of the *raw body* using whichever secret corresponds to `repository_owner`: [4](#0-3) 

Nothing enforces that `repository.owner.login` (used to select the verifying secret) is consistent with `repository.full_name` (used to select what is *written*), because both fields live in the same attacker-controlled JSON body. An org that legitimately possesses its own `webhook_secret` (any Shipit-configured GitHub organization/admin) can set `repository.owner.login` to its own org (so the signature validates) while setting `repository.full_name` to an arbitrary victim `owner/repo` string, or, for the `status` event, the handler doesn't scope by repository at all: [5](#0-4) 

`StatusHandler#process` looks up commits **globally by SHA**, with no ownership check tying the commit back to `repository_owner`/`repository.full_name`. Any org whose webhook secret is known to the requester can therefore forge a `status` event and create a status record for *any* commit SHA in *any* stack hosted by the same Shipit instance: [6](#0-5) 

This directly binds the "organization that authenticated" (signature side, based on `repository.owner.login`) against the "repository/commit that is written" (execution side, based on `repository.full_name` / bare `sha`), and those two are never checked for equality.

### Impact Explanation
Forging a `status` webhook for a foreign repository's commit lets an attacker (who only needs to know/administer one Shipit-configured organization's webhook secret, plus a target commit SHA — trivially obtainable from any public repo) inject a fabricated CI status into another organization's stack. `Commit#create_status_from_github!` → `add_status` schedules merge processing and continuous delivery when the injected status transitions state to `pending`/`success`: [7](#0-6) [8](#0-7) 

`ProcessMergeRequestsJob` then merges pending PRs once `all_status_checks_passed?`, and `Commit#schedule_continuous_delivery` can trigger an automatic deploy: [9](#0-8) [10](#0-9) 

This is an unauthorized-deploy/unauthorized-merge primitive achieved purely by an org-authenticated (but repository-unauthorized) attacker — matching the required Critical/High impact bar (unauthorized deploy/merge, cross-repository write).

### Likelihood Explanation
Requires the attacker to control (or have legitimate credentials for) at least one GitHub organization/repo that is configured in the same multi-tenant Shipit installation with its own `webhook_secret` — a relatively low bar in any shared/self-hosted multi-org Shipit deployment, since knowing your own org's webhook secret is not privileged with respect to *other* tenants' repositories. The `WebhooksController` endpoint is unauthenticated apart from the signature check, and the payload shape/fields required by `StatusHandler`/`PushHandler` are minimal and fully attacker-controlled JSON.

### Recommendation
After verifying the HMAC signature, cross-check that the organization whose secret validated the signature actually owns the repository referenced by `repository.full_name` (or any repository tied to commits looked up by `sha`) before dispatching to handlers. `StatusHandler` in particular should scope its `Commit` lookup by the stack/repository derived from `repository_owner`, not by a bare global SHA match.

### Proof of Concept
1. Configure/administer GitHub organization `attacker-org` in the target multi-tenant Shipit instance (its `webhook_secret` is known to you).
2. Pick a victim commit SHA `deadbeef...` that exists in a Shipit stack for `victim-org/victim-repo` (public commit SHAs are not secret).
3. Build a `status` event payload:
```json
{
  "sha": "deadbeef...",
  "state": "success",
  "context": "ci/forged",
  "repository": {"owner": {"login": "attacker-org"}, "full_name": "attacker-org/whatever"}
}
```
4. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(attacker-org webhook_secret, raw_body)>`.
5. POST to `/webhooks` with `X-Github-Event: status`. `verify_signature` resolves `repository_owner = "attacker-org"`, validates against `attacker-org`'s secret, and succeeds.
6. `StatusHandler#process` runs `Commit.where(sha: params.sha)`, matches the victim's commit (owned by an unrelated org/stack), and calls `commit.create_status_from_github!`, injecting a forged `success` status that can trigger `ProcessMergeRequestsJob`/continuous delivery on the victim's stack.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

      already_deployed = deployed?

      yield
      reload # to get the statuses into the right order (since sorted :desc)

      unless already_deployed

      end

        end
        stack.schedule_merges if new_status.pending? || new_status.success?
      end

    def perform(stack)
      merge_requests = stack.merge_requests.to_be_merged.to_a
      merge_requests.each do |merge_request|
        merge_request.refresh!
        merge_request.reject_unless_mergeable!
        merge_request.cancel! if merge_request.closed?
        merge_request.revalidate! if merge_request.need_revalidation?
      end

      return false unless stack.allows_merges?

      merge_requests.select(&:pending?).each do |merge_request|
        merge_request.refresh!
        next unless merge_request.all_status_checks_passed?

        begin
          merge_request.merge!
        rescue MergeRequest::NotReady
          ProcessMergeRequestsJob.set(wait: 10.seconds).perform_later(stack)
          return false
        end
      end
