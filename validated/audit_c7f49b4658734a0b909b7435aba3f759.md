### Title
Insolvent account with collateral above the $5 dust cap and a debt-token unit larger than the collateral-backed quote is permanently unliquidatable and un-cleanable — bad debt freezes against lenders until privileged intervention - ([File: contracts/controller/src/positions/liquidation/math.rs](contracts/controller/src/positions/liquidation/math.rs))

### Summary
The MySQL Optimizer CVE is a crash/hang DoS where a crafted input puts the server into an unrecoverable state requiring restart. The analog on XOXNO Lending is a reachable account state in which *every* permissionless remediation path reverts: `liquidate` always fails with `InvalidPayments`, and `clean_bad_debt` always fails with `CannotCleanBadDebt`. The only exits are a favorable oracle move or the owner-only `force_socialize_bad_debt`. A single unprivileged borrower can create this state deliberately, stranding unbacked debt that keeps accruing borrow interest against suppliers.

### Finding Description
Two gates interact to produce the stuck state:

1. **Dust gate.** `is_socializable_bad_debt` admits cleanup only when `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5 in WAD) [1](#0-0) . `socialize_bad_debt` enforces this for the permissionless `clean_bad_debt` path and reverts with `CannotCleanBadDebt` otherwise [2](#0-1) . The straddle is explicit: collateral strictly above $5 shuts the dust gate while insolvency persists (verified in `certora/controller/spec/boundary_rules.rs`).

2. **Insolvent liquidation trim.** In `normalize_repayment_plan`, an insolvent snapshot routes the excess trim through `process_excess_payment` with `keep_within_quote = insolvent` [3](#0-2) . That path floors each kept leg to *whole token units*: `new_amount = (usd - excess)/price` then `to_token_floor(decimals)` [4](#0-3) . When the collateral-backed quote `floor(C/(1+base))` is below the USD value of one debt-token unit, the kept amount is 0, the leg is dropped, and the entire offer is refunded. With no remaining leg, `process_liquidate` reverts via `require_non_empty_payments(env, &result.repaid)` [5](#0-4) . The codebase itself pins this behavior in `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`: $9 collateral backing a $10-per-unit debt token → zero-payment estimate, `InvalidPayments` revert, debt untouched [6](#0-5) .

So an account holding, e.g., $9–$5.01 of collateral and a debt denominated in an asset whose single base unit exceeds `floor(C/(1+base))` can neither be liquidated (every offer is refunded/dropped → revert) nor permissionlessly cleaned (`C > $5` → revert). Interest keeps accruing at the borrow rate, typically exceeding the collateral's supply yield, so the hole deepens rather than self-resolving.

### Impact Explanation
Unbacked debt is stuck on the affected market's books with no permissionless way to write it down. Suppliers of the borrowed asset cannot recover funds against that debt until governance schedules and executes `ForceSocializeBadDebt` on the Sensitive delay tier [7](#0-6) . This is a temporary freezing of lender funds plus a growing protocol insolvency, matching the CVE's availability-only impact shape.

### Likelihood Explanation
Reachable by one unprivileged address through `supply` + `borrow` followed by a normal price decline — no privileged calls, timing races, or oracle manipulation beyond ordinary market movement. Preconditions: a listed borrow asset whose base-unit price exceeds roughly the dust threshold divided by `(1 + base bonus)` (e.g., a 3-decimal token priced at ≥ ~$5 per unit satisfies this trivially), and the collateral landing in the ($5, unit_price×(1+b)) band. An attacker can also engineer it deterministically by sizing collateral/debt so a modest dip enters the band. Likelihood is gated by market configuration and price volatility rather than attacker capability.

### Recommendation
Give the insolvent trim an escape hatch so bad debt above the dust cap is still drainable: e.g., when the collateral-backed quote is below one debt unit, promote the kept leg to one whole unit (accepting the resulting dust-level over-credit) or allow a zero-unit kept leg that simply burns the collateral as revenue without repayment. Alternatively, extend `clean_bad_debt`'s collateral cap dynamically — admit socialization whenever `total_collateral <= max(BAD_DEBT_USD_THRESHOLD, smallest repayable debt-unit value)` — so that the permissionless gate covers every state the liquidation trim cannot serve.

### Proof of Concept
1. Deploy controller/pool with a debt market `EXP` priced at $10 per base unit (unit = $10) and a collateral market `COL` with normal LTV/LT and 5% base bonus.
2. Unprivileged attacker: `supply` COL worth ~$60, `borrow` 2 EXP ($20 debt ceiling per unit price; actual chosen so that after the crash D ≈ $20 > C).
3. Crash `COL` so total collateral `C = $9` (<$10 one-unit quote bound, and > $5 dust cap). Now `D > C` (insolvent) and `C > BAD_DEBT_USD_THRESHOLD`.
4. `clean_bad_debt(caller, account_id)` → reverts `CannotCleanBadDebt` (#114) via `is_socializable_bad_debt`.
5. `liquidate(liquidator, account_id, [(EXP, 2 units)], Transfer)` → `normalize_repayment_plan` computes `ideal = floor(C/(1+base)) ≈ $8.57 < $10`; `process_excess_payment` floors the kept EXP amount to 0 units, drops the leg, refunds the whole offer; `result.repaid` is empty → `require_non_empty_payments` → `InvalidPayments` (#16). Identical outcome for every payment size and both `SeizeMode`s, matching `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`.
6. Repeat 4–5 at any later ledger: still stuck. Debt accrues at the borrow rate while collateral only earns the supply rate, so the shortfall widens. Only `force_socialize_bad_debt` (owner) or an EXP price drop / COL price recovery ends the state.

Uncertainty note: whether any listed market actually carries a base-unit price above the ~$5 quote bound depends on deployment configuration; if all borrow assets price a base unit well below $5, the stuck window collapses and the finding reduces to a non-issue. The code path itself, however, is exercised and pinned by an in-repo test, so the mechanism is confirmed — only deployment exposure is unverified.

/// $9 of collateral backs $8.57, less than one $10 EXP unit: the estimate
/// keeps no repayment and refunds the whole offer, and execution reverts.
#[test]
fn test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote() {
    let (mut t, account_id) = insolvent_book_with_a_ten_dollar_unit(usd(9) / 1_000);
    let exp = t.resolve_asset("EXP");
    let payments = vec![&t.env, (hub_asset(exp.clone()), 2)];
    let estimate =
        t.ctrl_client()
            .get_liquidation_estimate(&account_id, &payments, &SeizeMode::Transfer);
    assert_eq!(estimate.max_payment_wad, 0);
    assert!(estimate.seized_collaterals.is_empty());
    let refund = estimate.refunds.get(0).expect("EXP refund");
    assert_eq!((refund.asset, refund.amount), (exp, 2));

    let liquidator = t.get_or_create_user(LIQUIDATOR);
    t.resolve_market("EXP").token_admin.mint(&liquidator, &2);
    let result = map_try_ok_value(t.ctrl_client().try_liquidate(
        &liquidator,
        &account_id,
        &payments,
        &SeizeMode::Transfer,
    ));
    assert_contract_error(result, errors::INVALID_PAYMENTS);
    assert_eq!(t.token_balance_raw(LIQUIDATOR, "EXP"), 2);
    assert_eq!(t.borrow_balance_raw(ALICE, "EXP"), 2);
}
