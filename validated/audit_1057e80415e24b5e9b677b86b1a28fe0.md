### Title
Webhook signature bypass via attacker-chosen `organization`/`repository.owner` letting an unsigned payload for one org's (unconfigured-secret) GitHub App trigger sync of another org's repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) to validate the signature against using `repository_owner`, a value taken directly from the untrusted JSON body (`repository.owner.login` or, if absent, `organization.login`). Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for that organization, an attacker can name any organization with a missing `webhook_secret` in the payload's `organization`/`repository.owner` fields while leaving `repository.full_name` pointing at a *different*, properly-secured organization's repository, causing the unsigned request to pass verification and be dispatched to `PushHandler` for that other repository.

### Finding Description
The broken binding: `organization_whose_secret_verified_bytes` (derived from `repository_owner` = `payload.dig('repository','owner','login') || payload.dig('organization','login')`) must equal `organization_owning_repository.full_name_used_by_handler` (derived from `payload.dig('repository','full_name')`), but the controller never enforces this.

- `repository_owner` reads `repository.owner.login`, falling back to `organization.login` if the repository sub-object/owner is omitted. [2](#0-1) 
- `lib/shipit/github_app.rb:76-77` — `verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank, regardless of the signature header content. [3](#0-2)

Attacker request: `POST /webhooks`, header `X-Github-Event: push`, garbage/empty `X-Hub-Signature`, body `{"repository":{"full_name":"OrgB/repo"},"organization":{"login":"OrgC"}}` (no `repository.owner`), where the deployment has multiple GitHub App configs and `OrgC`'s `webhook_secret` is unset. `repository_owner` resolves to `OrgC`; `Shipit.github(organization: 'OrgC')` returns an app with `webhook_secret` nil; `verify_webhook_signature` returns `true` unconditionally; the controller proceeds to dispatch the push payload, whose `repository.full_name` is `OrgB/repo`, into `PushHandler`, enqueuing `GithubSyncJob` for any stack matching `OrgB/repo` and the pushed branch.

Existing guards don't stop this: `drop_unhandled_event` only filters by event type; `check_if_ping` is irrelevant; the `rescue Shipit::GithubOrganizationUnknown` branch only fires if the named org isn't configured at all (here `OrgC` *is* configured, just without a secret); `PushHandler`'s `ExplicitParameters` schema only requires `ref`/`after`, not a verified `repository.owner`; nothing cross-checks that the org whose secret validated the request equals the org owning `repository.full_name`.

### Impact Explanation
Any organization configured in a multi-tenant Shipit deployment without a `webhook_secret` becomes a "skeleton key": an attacker sends a `push` webhook naming that org as `organization.login` (or as `repository.owner.login`) but pointing `repository.full_name` at an arbitrary other tenant's repository, forcing `GithubSyncJob` to run against that repository's stacks with attacker-chosen `expected_head_sha` framing, unauthenticated. While the commits fetched are pulled from the real upstream GitHub API (not forged content), the *trigger* itself is fully unauthenticated and cross-tenant — a payload nominally belonging to `OrgC` mutates state (sync scheduling, `mark_as_accessible!`/`mark_as_inaccessible!`, cache invalidation via `CacheDeploySpecJob`) for `OrgB`'s stack. This matches the "payload for one repository mutating another's stack" Critical category, and is repeatable against any repository/stack as long as one org in the tenant set lacks a `webhook_secret`.

### Likelihood Explanation
Requires a multi-organization GitHub App configuration (`config/secrets.yml` with per-org `github:` sub-keys, as documented in `docs/setup.md` "Using Multiple Github Applications") where at least one configured org has no `webhook_secret` set — a configuration explicitly shown as a valid template (`webhook_secret: # nil`) in `test/dummy/config/secrets_double_github_app.yml` and `config/secrets.development.example.yml`. Given that template, attacker cost is a single unauthenticated HTTP POST with no secrets required; fully repeatable.

### Recommendation
Remove the vacuous-true bypass in `GitHubApp#verify_webhook_signature`, or bind the verification target to the actual repository owner rather than an attacker-controlled `organization` field decoupled from `repository.full_name`; additionally require that `repository.owner.login`/`organization.login` match the owning org of `repository.full_name` before dispatching handlers, and fail closed (reject) rather than pass when no `webhook_secret` is configured for a multi-org tenant.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
