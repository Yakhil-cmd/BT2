### Title
Stack-scoped `ApiClient` bypasses its stack binding via the global `/api/hooks` endpoint - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
`Shipit::ApiClient` can be scoped to a single stack via its `stack_id` column, and its permissions (`read:hook`/`write:hook`) are supposed to be enforced only against that stack's own hooks. `Shipit::Api::HooksController`, however, only restricts hook access to the requested `stack_id` when the request itself carries a `stack_id` route param; when no `stack_id` is present (the top-level `resources :hooks` route), it operates on **global** hooks that fire for events of every stack in the installation, without ever checking whether `current_api_client` is restricted to a specific stack.

### Finding Description
`ApiClient#stack_id?` is meant to bind the token to one stack: `BaseController#stacks` narrows the visible stack set to that one stack when the client is scoped: [1](#0-0) 

But `HooksController` never calls `stacks`/`stack` unless `params[:stack_id]` is present: [2](#0-1) 

and the global route exists specifically for hooks with no stack scope, mounted alongside the stack-scoped one: [3](#0-2) 

The permission check only verifies the client has the generic `write:hook`/`read:hook` permission string — it never checks `current_api_client.stack_id` against the target hook's `stack_id`: [4](#0-3) 

A global `Hook` (created with `stack_id: nil`) receives delivery for **every** stack's events, because `Hook.deliver` resolves listeners via `for_stack`, which always includes global hooks regardless of which stack emitted the event: [5](#0-4) 

So the equality the app is supposed to preserve is: `stack a token authorizes == stack a hook the token manages is scoped to`. Before the request, an `ApiClient` with `stack_id = A` and `write:hook` is meant to only create/update/delete hooks where `hook.stack_id == A`. After hitting `POST /api/hooks` (no `stack_id` param), the client instead creates/updates a hook with `stack_id = nil`, which is delivered for events of **every** stack (B, C, …) that the client was never authorized to touch — breaking the binding.

### Impact Explanation
An attacker holding an `ApiClient` token scoped to a single, low-value stack (with only `write:hook`/`read:hook` permission) can register (or edit/delete) a **global** webhook that receives deploy/task/rollback/commit-status/merge payloads for every stack managed by the Shipit instance. This is an escalation from "authorized to manage hooks of stack A" to "unauthenticated read of stack state / deploy output" for all other stacks, matching the High-severity impact category of unauthorized read of stack state or deploy output via a scope the token was never granted. It can also be used to delete or tamper with existing global hooks (`update`/`destroy` on `hooks.find(params[:id])`, unscoped when no `stack_id` given) belonging to the whole installation, not just the client's own stack.

### Likelihood Explanation
Requires only possession of a legitimately-scoped `ApiClient` token (a normal, low-privilege credential many integrations hold) — no special account, no GitHub write access, no session. Because the request URL is identical to the documented global-hooks endpoint (`resources :hooks` under `/api`), and the permission check never inspects `stack_id`, the client hits this path with a single unmodified request (omit `stack_id` from the URL). This is a straightforward, low-effort call.

### Recommendation
In `Shipit::Api::HooksController`, when `current_api_client.stack_id?` is true, always scope `hooks` to that stack (reject/`404` any access to the global collection), instead of only scoping when `params[:stack_id]` happens to be present. Equivalently, `ApiClient#check_permissions!`/`hooks` should enforce `current_api_client.stack_id.nil? || current_api_client.stack_id == stack_id` for every hook operation.

### Proof of Concept
1. Create `ApiClient` `X` with `stack_id = A` (belongs only to Stack A) and permissions `['write:hook']` (a legitimate, low-privilege integration token).
2. Authenticate as `X` and call `POST /api/hooks` (note: no `stack_id` in the path) with `delivery_url` pointing to an attacker-controlled server and `events: ['deploy']`.
3. `HooksController#hooks` computes `stack_id` as `nil` (because `params[:stack_id]` is absent), so `hooks.create(params)` creates a `Hook` with `stack_id: nil` — a **global** hook.
4. Any deploy/task/commit-status event on any stack in the installation (`Hook.deliver(event, stack_id, payload)` → `for_stack(stack_id)` → includes `Hook.global`) is now delivered to the attacker's `delivery_url`, exposing deploy metadata/commit SHAs/output links for stacks the client `X` was never authorized to access.

    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
