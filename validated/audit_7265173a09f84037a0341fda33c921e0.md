### Title
Path traversal in `gh release download` via malicious asset name allows writes outside `--dir` - (File: pkg/cmd/release/download/download.go)

### Summary
The `destinationWriter.makePath` function joins the release asset's attacker-controlled `Name` field directly with the destination directory using `filepath.Join`, without any path-traversal confinement check (unlike `pkg/cmd/run/download`, which uses `internal/safepaths.Absolute.Join` to reject traversal). An unprivileged attacker who publishes a release with an asset named e.g. `../../.ssh/authorized_keys` can cause `gh release download` to write file contents outside the intended `--dir`.

### Finding Description
In `downloadRun` (`pkg/cmd/release/download/download.go:196-208`), asset names come straight from the GitHub API response (`shared.Release.Assets[].Name`, defined in `pkg/cmd/release/shared/fetch.go:73-87`), which is fully attacker-controlled since any GitHub user can publish a release in their own repo with an asset carrying an arbitrary `name`. These names are only filtered by `--pattern` glob matching (`matchAny`, line 197) and a Windows-reserved-name check (line 203) — neither blocks `..` path segments or absolute paths.

The name flows into `downloadTarget.name` (line 241), then through `downloadAssets` → `downloadAsset` (line 300) → `dest.Check(fileName)` / `dest.Copy(fileName, ...)`. Both call `w.makePath(name)`: [1](#0-0) 

`filepath.Join` internally calls `filepath.Clean`, which resolves `..` segments, so `filepath.Join("/home/victim/downloads", "../../.ssh/authorized_keys")` legitimately escapes the destination directory instead of erroring. `Copy` then does `os.MkdirAll(filepath.Dir(fp), 0755)` and `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` at lines 435-442, writing/truncating the attacker-chosen path with attacker-supplied release-asset bytes.

By contrast, the equivalent artifact-download path in `pkg/cmd/run/download` (and `internal/zip/zip.go`, `internal/skills/installer/installer.go`) uses `internal/safepaths.Absolute.Join`, which computes `filepath.Rel` between the joined path and the base directory and returns a `PathTraversalError` if the relative path starts with `..` (`internal/safepaths/absolute.go:38-57`). No such check exists in the release-download code path.

### Impact Explanation
This is an arbitrary file write/overwrite outside the user-specified `--dir`. A victim running `gh release download` (without `--pattern`, or with a pattern like `*` that still matches a crafted name such as `evil*` combined with traversal, e.g. `../../evil`) against an attacker's release can have files silently written to any path the invoking OS user has write access to — including shell startup files (`~/.bashrc`), git hooks in a nearby repository, SSH `authorized_keys`, or (with enough directory traversal) `gh`'s own config. This matches GitHub's "arbitrary file write" bounty impact class.

### Likelihood Explanation
Feasibility is high and requires no special privileges: any GitHub account can publish a release with a crafted asset name (the GitHub API does not restrict special characters like `/` and `..` in asset names contrary to intra-repo blob names). The victim only needs to run the ordinary command `gh release download [tag]` (or `--pattern` matching the crafted name) against that repository/release, which is a normal, expected workflow (e.g., for tooling or fork-based CI configurations that a user might follow from a README).

### Recommendation
Replace the raw `filepath.Join` in `makePath` with confinement logic consistent with the rest of the codebase — e.g., resolve `w.dir` to an `internal/safepaths.Absolute` once, then use `Absolute.Join(name)` for each asset name, returning a `PathTraversalError` when the asset's name would escape the destination directory. Additionally, reject/sanitize any asset name containing path separators or `..` segments (mirroring how `pkg/cmd/release/upload/upload.go` calls `sanitizeFileName` on upload) before it ever reaches `makePath`.
