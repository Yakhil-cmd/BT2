### Title
Webhook signature verification org-selection is decoupled from the repository actually acted upon, enabling unauthenticated webhook forgery when any configured GitHub App has no `webhook_secret` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` chooses which GitHub App (and therefore which `webhook_secret`) to validate an incoming webhook against using a value taken directly from the unverified request body. The handlers that actually act on the payload resolve the *target repository* from a different field of the same body. These two lookups are never required to agree, so an attacker can pick an organization whose app has no `webhook_secret` configured to satisfy signature verification, while pointing the payload's `repository.full_name` at a completely unrelated, victim repository/stack.

### Finding Description
`verify_signature` derives the organization used for verification purely from attacker-controlled JSON: [1](#0-0) [2](#0-1) 

`repository_owner` is read from `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`), and `Shipit.github(organization: repository_owner)` returns the `GitHubApp` config for that org, whose secret is then used to verify `X-Hub-Signature`.

Crucially, `GithubApp#verify_webhook_signature` treats a missing secret as "always valid": [3](#0-2) 

`return true unless webhook_secret` — i.e., for any organization configured without a `webhook_secret`, signature verification is a no-op that always passes. The setup docs explicitly mark the webhook secret as optional, and the test fixtures ship a second app (`OrgTwo`) with `webhook_secret: # nil`, showing multi-org deployments with an unsecured app are an expected, supported configuration: [4](#0-3) [5](#0-4) 

Meanwhile, the event handlers that actually process the request never re-check `repository_owner`; they resolve the target repository purely from `payload.dig('repository', 'full_name')`: [6](#0-5) 

and act on it directly, e.g. `PushHandler` triggers `stack.sync_github` for any stack matching that repository/branch: [7](#0-6) 

The trust binding the app relies on is: `organization authenticated (repository.owner.login used for signature lookup) == repository acted upon (repository.full_name used by handlers)`. Because both values are attacker-supplied fields of the same unauthenticated JSON body, and only the first is covered by "verification" (which itself is a no-op for secret-less orgs), the equality does not hold. An attacker sets `repository.owner.login` (or `organization.login`) to an org with no `webhook_secret`, and sets `repository.full_name` to any other org/repo connected to the Shipit instance.

### Impact Explanation
This breaks the authentication boundary of the entire webhook ingestion pipeline: any webhook event type registered in `Shipit::Webhooks::DEFAULT_HANDLERS` (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) can be forged for an arbitrary repository/stack managed by the instance, without possessing the victim org's `webhook_secret`, GitHub App credentials, or any Shipit session/API token. This is an authentication bypass on an unauthenticated, network-reachable endpoint (`/webhooks`), matching the Critical severity bucket ("authentication bypass ... unauthorized deploy"). Concretely, a forged `push` event can trigger `Stack#sync_github` (re-sync commits) on a victim stack; other handlers can create bogus commit statuses, teams, or users tied to the target repo — all steps that feed into the deploy/merge decision pipeline.

### Likelihood Explanation
The only precondition is that the Shipit instance is configured with more than one GitHub App/organization and at least one of them (e.g., a low-value test/staging org) has no `webhook_secret` set — a configuration explicitly presented as optional in the docs and exercised in the engine's own fixtures. No credentials, session, or repository write access are required; the attacker only needs to know (or guess) the login of any org configured without a secret and send a crafted POST to the public `/webhooks` endpoint.

### Recommendation
Bind signature verification to the repository actually acted upon, not to an independently-controlled field:
- Verify the webhook signature using the secret associated with the organization that owns `repository.full_name` (the same field handlers use), not a separately-chosen `repository.owner.login`/`organization.login`.
- Do not allow a "no secret configured" organization to implicitly authorize events for repositories belonging to other organizations; either require a `webhook_secret` for every configured GitHub App or scope such an app's trust strictly to its own installation's repositories, verified against the installation ID rather than a payload string.
- Reject payloads where the derived `repository_owner` does not match the owner of `repository.full_name`.

### Proof of Concept
Given a `secrets.yml` with two orgs, `OrgOne` (has `webhook_secret`) and `OrgTwo` (no `webhook_secret`), and a Shipit stack tracking `OrgOne/victim-repo`:

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored because OrgTwo has no webhook_secret

{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "OrgTwo" },     // used to select org for signature check -> always passes
    "full_name": "OrgOne/victim-repo"   // used by PushHandler to resolve the actual stack acted upon
  }
}
```

`WebhooksController#verify_signature` calls `Shipit.github(organization: "OrgTwo")`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured), so the request passes verification. `PushHandler` then resolves `stacks` from `repository.full_name == "OrgOne/victim-repo"` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on the victim stack — a forged, unauthenticated push event accepted and acted upon for a repository the attacker has no relationship with.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
