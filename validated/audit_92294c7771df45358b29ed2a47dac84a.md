### Title
Stale Votes from Deregistered Bridge Operators Enable Unauthorized Asset Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator` removes an operator from the `operators` mapping and `operatorList` array but does not clear that operator's existing entries in the `votes` mapping. A deregistered operator's prior votes persist and can combine with votes from remaining active operators to meet the threshold, causing bridge value transfers (KLAY, ERC20, ERC721) to execute after the operator was supposed to have been revoked.

### Finding Description

`deregisterOperator` only deletes `operators[_operator]` and removes the address from `operatorList`: [1](#0-0) 

It does not touch the `votes` mapping: [2](#0-1) 

When `_voteCommon` is called by a subsequent active operator, it reads `vote.voteCounts[_voteKey]`, which already includes the deregistered operator's contribution: [3](#0-2) 

The threshold check at line 96 compares the accumulated count (including the stale vote) against `operatorThresholds`, so the transfer executes even though one of the contributing votes came from an operator who was deregistered before the threshold was reached.

The code itself acknowledges this in a comment but treats it as an operational concern rather than fixing it: [4](#0-3) 

### Impact Explanation

When the threshold is reached using a stale vote from a deregistered operator, `_voteValueTransfer` sets `closedValueTransferVotes[_requestNonce] = true` and returns `true`, causing `handleKLAYTransfer`, `handleERC20Transfer`, or `handleERC721Transfer` to execute the asset transfer: [5](#0-4) [6](#0-5) 

The result is an unauthorized transfer of KAIA, ERC20, or ERC721 tokens from the bridge contract to an arbitrary recipient, driven in part by a vote that should have been invalidated.

### Likelihood Explanation

The scenario requires:
1. A compromised operator A votes on a malicious value-transfer nonce N.
2. The owner deregisters A (intending to block the transfer).
3. A remaining honest operator B votes on nonce N (e.g., because the underlying cross-chain request is legitimate from B's perspective, or B is also compromised).
4. A's stale `voteCounts` entry causes the threshold to be met, executing the transfer.

With a threshold of 2 and 3 operators, deregistering one compromised operator still leaves the stale vote active. The owner has no on-chain mechanism to cancel it. This is a realistic operational scenario during incident response.

### Recommendation

In `deregisterOperator`, iterate over all open nonces for both `VoteType.ValueTransfer` and `VoteType.Configuration` and clear the deregistered operator's `voted` entry and decrement the corresponding `voteCounts`. Alternatively, add a dedicated `revokeVote(address operator, VoteType voteType, uint64 nonce)` function callable by the owner to explicitly cancel a specific stale vote. At minimum, the `_voteCommon` function should verify that `msg.sender` (the current voter) is still a registered operator at the time of the threshold check — but since `_voteCommon` is called only via `onlyOperators`-gated functions, the real fix must happen at deregistration time by purging the stale state.

### Proof of Concept

```
Setup: operators = [Owner, A, B], threshold(ValueTransfer) = 2

1. Operator A calls handleKLAYTransfer(..., nonce=5, ...) 
   → votes[0][5].voted[A] = voteKey
   → votes[0][5].voteCounts[voteKey] = 1  (threshold not met)

2. Owner calls deregisterOperator(A)
   → operators[A] = false, operatorList shrinks
   → votes[0][5].voted[A] = voteKey  ← STILL PRESENT
   → votes[0][5].voteCounts[voteKey] = 1  ← STILL PRESENT

3. Operator B calls handleKLAYTransfer(..., nonce=5, ...) with same args
   → votes[0][5].voteCounts[voteKey]++ → 2
   → 2 >= operatorThresholds[0] (= 2) → returns true
   → closedValueTransferVotes[5] = true
   → _to.call.value(_value)("") executes — KAIA transferred

Result: KAIA transferred using A's vote after A was deregistered.
```

```text
    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
```

```text
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
```
