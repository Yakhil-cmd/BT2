### Title
Unvalidated `omniauth.origin` used in `redirect_to` enables open redirect after OAuth login - (File: `app/controllers/shipit/github_authentication_controller.rb`)

### Summary
`Shipit::GithubAuthenticationController#callback` builds `return_url` directly from `request.env['omniauth.origin']`, which OmniAuth populates from the attacker-controllable `origin` query parameter sent to the `:request` action, and passes it unfiltered into `redirect_to`. There is no host/path allowlist, so an attacker can force the freshly-authenticated victim's browser to be redirected to an arbitrary external URL, completing an open redirect immediately after a real OAuth login.

### Finding Description
The broken binding is: *the redirect target implicitly approved by the operator (a same-origin Shipit path) == the redirect target executed by `callback`*. In code, `callback` does: [1](#0-0) 

`return_url = request.env['omniauth.origin'] || root_path` is taken verbatim with no scheme/host check before `redirect_to(return_url)`. `request.env['omniauth.origin']` is populated by the OmniAuth gem's own strategy `request_phase` from the `origin` request parameter (or `HTTP_REFERER`) supplied to `GET /github/auth/github` (mapped via `scope '/github/auth/github', ... get '/', action: :request`): [2](#0-1) 

Attack flow:
1. Attacker sends the victim a link: `GET /github/auth/github?origin=https://attacker.example`.
2. OmniAuth's request phase stores `https://attacker.example` as the OAuth `origin`, then redirects the victim into the real GitHub OAuth flow.
3. Victim completes GitHub login legitimately.
4. GitHub redirects back to `GET /github/auth/github/callback`; OmniAuth's callback middleware restores `omniauth.origin` into `request.env`.
5. `callback` sets `session[:user_id]`, `session[:authenticated] = true`, then executes `redirect_to(return_url)`, sending the now-authenticated victim's browser to `https://attacker.example`.

No guard in the engine validates that `return_url` is a same-origin/local path — there is no `only_path`/host allowlist check anywhere in `callback`, and none of the listed protections (`verify_signature`, `force_github_authentication`, `User#authorized?`, model validators) apply to this controller, since they guard entirely different code paths (webhooks, stack authorization, model persistence), not the OAuth redirect target.

### Impact Explanation
An unauthenticated internet user can craft a link that, once clicked and the OAuth flow completed, causes the victim's browser (with a freshly minted Shipit session) to be redirected to an attacker-controlled site immediately after authentication. This can be used to stage convincing post-login phishing pages, chain into further token/credential harvesting, or abuse the trust of a "just logged into Shipit" flow. This matches the "session fixation / forced OAuth completion" High-impact category — no secrets, tokens, or Shipit privileges are required, and the technique is repeatable against any victim who clicks the crafted link, independent of any specific repository or stack.

### Likelihood Explanation
Preconditions are minimal: default Shipit OAuth/OmniAuth-GitHub setup as documented, and a victim willing to click a link and complete GitHub sign-in (which they may already be doing legitimately, e.g., via a phished or "helpful" login link). The attacker needs no Shipit session, API token, or GitHub App secret — only the ability to construct a URL with an `origin` query parameter, which is standard, publicly documented OmniAuth behavior. This is trivially repeatable against any user of the instance.

### Recommendation
Validate `return_url` before redirecting: restrict it to a same-origin relative path (e.g., verify it starts with `/` and does not begin with `//`, or explicitly check `URI.parse(return_url).host` against the app's own host) before calling `redirect_to`. Fall back to `root_path` for any origin that fails validation.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
module Shipit
  class GithubAuthenticationControllerTest < ActionController::TestCase
    test ":callback redirects only within the app even with attacker-supplied origin" do
      auth = OmniAuth::AuthHash.new(
        credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
        extra: OmniAuth::AuthHash.new(
          raw_info: OmniAuth::AuthHash.new(
            id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
            login: 'shipit-user', avatar_url: 'https://example.com',
            api_url: 'https://github.com/api/v3/users/shipit-user'
          )
        )
      )
      @request.env['omniauth.auth'] = auth
      @request.env['omniauth.origin'] = 'https://attacker.example'

      get :callback

      # Broken binding demonstrated: attacker-controlled external URL is honored.
      assert_equal 'https://attacker.example', response.redirect_url
      # Expected (fixed) behavior would instead assert:
      # refute_match(/\Ahttps?:\/\/attacker\.example/, response.redirect_url)
    end
  end
end
```
This demonstrates that `response.redirect_url` equals the attacker-supplied external `omniauth.origin` value with no host validation, confirming the open redirect.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end
