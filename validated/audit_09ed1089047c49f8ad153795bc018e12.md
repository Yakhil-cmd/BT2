### Title
RAY value overflow during accrual permanently freezes a large market - (File: common/src/rates/scaling.rs)

### Summary

The pool accrues interest before every market operation, and accrual converts scaled supply and debt back to RAY-denominated values through `scaled_to_original`. [1](#0-0)  If that result no longer fits in `i128`, the fixed-point multiplication panics with `MathOverflow`, reverting the entire transaction. [2](#0-1)  Once a sufficiently large market reaches that state, `update_indexes`, `repay`, `withdraw`, liquidation, and every other operation that syncs the market repeatedly fail, freezing the funds held in that market. [3](#0-2) [4](#0-3) 

### Finding Description

`global_sync` chunks elapsed time and calls `accrue_step` for each chunk. [5](#0-4)  `accrue_step` first computes `borrowed_original` and `supplied_original` with `scaled_to_original`. [6](#0-5)  That helper multiplies the scaled RAY share amount by the market index, and the underlying `mul_div_half_up` implementation panics when the quotient exceeds `i128::MAX`. [1](#0-0) [2](#0-1) 

Every pool mutation loads the market through `synced_market`, so this panic occurs before repayment, withdrawal, borrowing, liquidation accounting, revenue claims, and manual index updates. [7](#0-6)  The regression test demonstrates that a market containing one billion 18-decimal tokens at 98% utilization eventually fails inside `scaled_to_original`; after that, both withdrawal and repayment return `MathOverflow`. [4](#0-3) 

The configured borrow-index cap does not prevent the failure because the market-value multiplication can overflow before `update_borrow_index` reaches `MAX_BORROW_INDEX_RAY`. [8](#0-7) [9](#0-8) 

### Impact Explanation

This causes a permanent freeze of all supplier and borrower funds in the affected market until a privileged code change or state repair occurs. [10](#0-9)  Because every relevant verb accrues first, users cannot withdraw collateral, repay debt to unlock collateral, liquidate unhealthy positions, or socialize bad debt through paths that load the frozen market. [7](#0-6) [11](#0-10) 

The condition is self-perpetuating: the failed accrual reverts without committing a new timestamp or index, so subsequent calls begin from the same state and hit the same overflow. [12](#0-11) [13](#0-12) 

### Likelihood Explanation

Triggering this condition requires an unusually large market and enough elapsed accrual for the scaled value to cross the `i128` boundary. [14](#0-13)  An unprivileged borrower or supplier can create the relevant balance through ordinary `supply` and `borrow`, wait for the index to grow, and then submit permissionless `update_indexes(caller, [hub_asset])`; no privileged action is needed at the trigger step. [15](#0-14) [11](#0-10) 

The main mitigating factors are the large principal required, governance-defined asset caps and rate-model parameters, and the long accrual horizon reflected by the test. [16](#0-15)  Those conditions narrow the practical attack surface, but the failure is deterministic once the accounting values cross the representable boundary. [17](#0-16) 

### Recommendation

Make accrual saturation-safe instead of panicking on market-value overflow. [6](#0-5) 

Concretely, use saturating `mul_div` conversion when deriving `borrowed_original` and `supplied_original` for utilization, or clamp the result to `i128::MAX` before calculating the rate. [18](#0-17)  Similarly, avoid panicking multiplications in `calculate_supplier_rewards` after the borrow index reaches its configured cap; once the index is capped, accrued interest can be computed from the capped value rather than an unrepresentable intermediate. [19](#0-18) 

A defense-in-depth option is to derive a utilization value directly from capped scaled amounts or use `mul_div_floor_saturating` for this specific calculation. [18](#0-17)  Regression coverage should retain the whale-market test and additionally verify that the index cap is reached without freezing repayment or withdrawal. [20](#0-19) 

### Proof of Concept

1. Create a listed 18-decimal market whose configured caps admit a very large position. [21](#0-20) 
2. Supply `1_000_000_000 * 10^18` units to the market and borrow approximately 98% of that value from an account holding sufficient collateral. [22](#0-21) 
3. Advance ledger time until the scaled debt or supply value exceeds `i128::MAX`. [23](#0-22) 
4. Call the permissionless controller entrypoint `update_indexes(caller, [hub_asset])`; the pool executes `Cache::load`, `global_sync`, and `accrue_step`. [11](#0-10) [6](#0-5) 
5. `scaled_to_original` panics with `MathOverflow`, so the accrual and transaction revert. [1](#0-0) [24](#0-23) 
6. A subsequent `withdraw` or `repay` fails the same way because those paths call `synced_market` before attempting their operation. [7](#0-6) [10](#0-9)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `floor(x * y / d)`, saturating to `i128::MAX` (or `i128::MIN` for a negative
/// quotient) instead of panicking if the result does not fit in `i128`. Panics with
/// `GenericError::DivisionByZero` if `d == 0`.
pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
