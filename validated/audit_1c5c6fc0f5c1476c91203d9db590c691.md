### Title
Unauthenticated `MergeStatusController#show` allows cross-stack merge-request-state disclosure via unverified `referrer` param - ([File: app/controllers/shipit/merge_status_controller.rb])

### Summary
`MergeStatusController` explicitly skips Shipit's session authentication for `show` and `check` (`skip_authentication only: %i[check show]`), and identifies the target `Stack`/`MergeRequest` purely from the unauthenticated `referrer` query parameter rather than from any credential. This breaks the intended binding between "the caller who is allowed to see a stack's merge/deploy state" and "the stack whose state is disclosed," because the mapping is fully attacker-controlled. [1](#0-0) 

### Finding Description
Normally, access to stack state in Shipit requires either a Shipit session (`Authentication#force_github_authentication`) or an authenticated `ApiClient` scoped to a specific stack (`Api::BaseController#stacks`/`#stack`). [2](#0-1) [3](#0-2) 

`MergeStatusController`, however, is designed to be embeddable as a GitHub PR-status widget and deliberately opts out of this check for `show`/`check`: [4](#0-3) 

When no `stack_id` param is present, the controller resolves the target `Stack` purely by parsing the `referrer` request parameter with a regex (`ReferrerParser`) to extract `repo_owner`/`repo_name`/`pull_request_number`, and looks up whichever stack in the whole `Stack` table matches that repository/branch: [5](#0-4) [6](#0-5) 

The only "authorization" gate inside `show` is `current_user.logged_in?`, which is satisfied even by an `AnonymousUser`... actually no — `render('logged_out')` is returned unless `current_user.logged_in?`; since `find_current_user` requires a valid `session[:user_id]`, an anonymous unauthenticated caller gets `logged_out` instead of state, which limits the practical impact of `show`. However, `check`, which is also unauthenticated, does **not** perform this `logged_in?` check at all and returns the stack's computed `merge_status` (`ok`/failure string, plus JSON) directly to any caller who can control the `referrer` (or `stack_id`) parameter, without any session or token: [7](#0-6) 

Because `referrer` is a value the client fully controls, an unauthenticated party can craft `referrer=https://github.com/<any-owner>/<any-repo>/pull/<n>` (or, if `params[:stack_id]` is also accepted unauthenticated for this action, the raw stack id/param) for any repository tracked by this Shipit install, causing `check` to disclose that stack's current merge/CI/deploy-blocking status. This is a binding break between "the identity that is allowed to observe a stack's state" (none, by design of `skip_authentication`) and "the stack whose state is computed and returned" (attacker-chosen via `referrer`), i.e., an unauthenticated read of stack state.

### Impact Explanation
This matches the explicitly accepted High-impact class: "unauthenticated read of stack state, task streams or deploy output." Any internet client can enumerate the CI/merge/deploy status of arbitrary stacks/repositories configured on the Shipit instance without any session, ApiClient token, or GitHub credential, by simply supplying a crafted `referrer` value pointing at a different repository/PR than the one actually referring the request.

### Likelihood Explanation
Likelihood is high for the `check` action: it requires no authentication artifacts at all (no signature, no session, no token), and the `referrer` header/param is trivially forgeable since it is read from `params[:referrer]`, not the actual HTTP `Referer` header validated against origin. The endpoint is intentionally public (used for embedding as a status badge), which is by design, but the design does not restrict disclosure to the stack the caller is actually authorized to view — there is no check that the requester is legitimately associated with the target repo/PR.

### Recommendation
- For the `check` action, require the same `current_user.logged_in?`/authorization check already partially applied in `show`, or otherwise restrict disclosure to information that is not repo/CI-status sensitive.
- Do not trust `params[:referrer]` as an authorization input; if referrer-based repo resolution is required, validate it against the actual `Referer`/`Origin` HTTP header rather than an attacker-suppliable parameter of the same name.
- Consider requiring `stack_id` plus a scoped credential (or at least confirming the requesting page truly belongs to the PR being queried) before exposing `merge_status`.

### Proof of Concept
1. Identify a Shipit instance hosting `MergeStatusController` (route mounted per `config/routes.rb`) and a repository/stack of interest, e.g. `victim-org/victim-repo`, PR `#42`.
2. Send an unauthenticated request:
   `GET /merge_status/check?referrer=https://github.com/victim-org/victim-repo/pull/42`
   (or via the JSON format: `GET /merge_status/check.json?referrer=...`)
3. Because `check` skips authentication and resolves the stack solely from the `referrer` param via `ReferrerParser`, the response discloses `stack_status` (e.g. `ok` / failure string / JSON `{stack_status: ...}`) for `victim-org/victim-repo`'s merge queue/deploy state, without the caller ever authenticating. module Shipit
  class MergeStatusController < ShipitController
    skip_authentication only: %i[check show]

    etag { cache_seed }
    layout 'merge_status'

    def show
      response.headers['X-Frame-Options'] = 'ALLOWALL'
      response.headers['Vary'] = 'X-Requested-With'

      if stack
        return render('logged_out') unless current_user.logged_in?

        if stale?(last_modified: [stack.updated_at, merge_request.updated_at].max, template: false)
          render(stack_status, layout: !request.xhr?)
        end
      else
        render(html: '')
      end
    rescue ArgumentError
      render(html: '')
    end

    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
    end

# frozen_string_literal: true

module Shipit
  module Authentication
    extend ActiveSupport::Concern

    included do
      before_action :force_github_authentication
      helper_method :current_user
    end

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
