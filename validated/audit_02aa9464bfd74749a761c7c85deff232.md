### Title
Flash-loan reserve skew of an Aquarius stable-swap pool lowers the LP fair-value oracle price and enables unfair liquidations / under-collateralized borrows - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The Deus Finance bug class (in-transaction oracle manipulation funded by a flash loan) maps onto the `AquariusStableLp` price source. `read()` evaluates the LP share price from the pool's *live* reserves inside the same transaction that prices collateral for `borrow`, `liquidate`, `swap_collateral`, etc. For a stable pool the fair price is `D * min(price_a, price_b) / share_supply`, and the StableSwap invariant `D` is monotonically decreasing in reserve imbalance. A single unprivileged address can take the pool's exact-balance cash `flash_loan` (or use `flash_position`), dump one leg into the Aquarius pool to skew reserves, and have the deformed `D` flow into the health-factor calculation before repaying the loan in the same transaction.

### Finding Description
`aquarius::read` fetches `reserve_a`, `reserve_b`, `total_shares` and `amp` with live cross-contract calls at evaluation time (`aquarius_pool_reserves_call`, `aquarius_total_shares_call`, `aquarius_amp_call`), then calls `fair_stable_lp_price_wad` for stable sources. [1](#0-0) 

`fair_stable_lp_price_wad` solves `D` from the skewed reserves (`solve_stable_d(env, xa_wad, xb_wad, amp)`) and multiplies by `min(price_a, price_b)`. Because `D` shrinks as reserves become imbalanced, any swap that imbalances the pool strictly lowers the reported LP price relative to the balanced-pool value. [2](#0-1) 

The controller consumes this price synchronously: `Context::cached_price` / `load_markets` fetch prices once per invocation and `calculate_account_risk_totals` values collateral and debt with them in the same call that executes `borrow`/`liquidate`. [3](#0-2) [4](#0-3) 

There is no smoothing (TWAP, reserve snapshot, or delayed observation) on the LP leg; the only bounds are `min_pool_value_wad` (a floor on total pool value, not on imbalance) and the asset's sanity band. Configured oracles use a single `AquariusLp`/`AquariusStableLp` source with `tolerance` = 0 bps, so there is no second independent source to veto a deformed reading — deviation within the wide sanity band passes. [5](#0-4) 

Note the asymmetry that makes this exploitable rather than noise: for a *constant-product* source the fair price `2*sqrt(v_a*v_b)/supply` is exactly invariant under a fee-less swap (the product of reserves is the invariant), so the constant-product path is largely self-defending. The stable path is not — `D` is imbalance-sensitive by construction, which is where the class lands.

### Impact Explanation
Two reachable consequences within the band:

1. **Unfair liquidation (theft of collateral via bonus):** an attacker flash-borrows capital, swaps on the Aquarius stable pool to imbalance reserves, depresses the LP fair price so a victim account holding LP collateral crosses `health_factor < WAD`, calls `liquidate` (or `swap_collateral`/`repay_debt_with_collateral`), seizes collateral at the HF-based bonus, then unwinds the swap and repays the flash loan — all in one transaction. The liquidator's profit is the seized bonus on collateral whose true (balanced) price never justified liquidation.
2. **Under-collateralized borrow:** if the attacker supplies LP collateral, the same depression lowers their LTV headroom — not useful — but inflating is also possible in the stable case by moving reserves toward balance after a donation/pre-existing imbalance, or by momentarily *increasing* `min(price_a, price_b)`'s effective contribution when `D` is dominated by the expensive leg; more practically, the downward path can push a third party's HF below 1 to trigger liquidation cascades.

Because `flash_loan` only requires restoring the exact balance plus fee, the manipulation capital is free intra-transaction; the cost is only the swap fee and the permanent imbalance loss on the stable pool.

### Likelihood Explanation
- Requirements: a listed market whose oracle has an `AquariusStableLp` source (production code path exists; mainnet configs show single-source LP oracles with 0-bps tolerance and wide sanity bands), a victim LP-collateral position near the liquidation boundary, and a stable pool shallow enough that a flash-loan-sized swap moves `D` by more than the victim's HF margin while staying inside `[min_sanity_price_wad, max_sanity_price_wad]`.
- The sanity band and `min_pool_value_wad` bound the manipulation and reject extreme deformations (`InsufficientAquariusLiquidity` / out-of-band `InvalidPrice`), so the attack is limited to targets within the band width of liquidation — a Medium rather than Critical severity profile.
- All entrypoints used (`flash_loan`/own flash receiver, own Aquarius swap, `liquidate`) are explicitly in scope and unprivileged.

### Recommendation
- Bound imbalance, not just value: in `fair_stable_lp_price_wad` (or `aquarius::read`) reject or clamp when `|xa_wad - xb_wad| / D` exceeds a configured threshold, since a healthy stable pool prices near `2*min_price` per share.
- Prefer `D` computed from a manipulation-resistant quantity (e.g., price-weighted reserves `xa*pa` vs `xb*pb` balance check) or require the observed implied per-share value to agree with `2*min(price_a,price_b)` within a tolerance before accepting the stable invariant result.
- Require a second independent price source (a `Feed` leg) with a nonzero `OracleTolerance` for any LP collateral asset, so a single deformed pool read cannot drive risk decisions alone.
- Optionally tighten per-asset sanity bands for LP assets to a fraction of the expected daily volatility.

### Proof of Concept
1. Victim V supplies Aquarius stable-LP shares as collateral and borrows; HF = 1.05.
2. Attacker calls `pool::flash_loan` (exact-balance cash flash) for the pool's token-A liquidity into their receiver contract.
3. Inside the callback, the attacker swaps the borrowed token-A for token-B on the Aquarius stable pool. Reserves shift to `(a + Δ, b − δ)`, `D` falls by, e.g., 6% — inside the configured sanity band.
4. In the same transaction the attacker calls `controller::liquidate(liquidator, V, debt_asset, payments, SeizeMode::Transfer)`. `cached_price` resolves the LP collateral through `aquarius::read`, which recomputes `D` from the skewed reserves; `weighted_collateral` drops >5%, HF < 1, and the plan seizes collateral with bonus priced off the deformed oracle.
5. The attacker swaps back on Aquarius (minus fees), repays the flash loan principal + fee, and keeps the liquidation bonus net of swap cost.
6. Profit condition: `bonus_bps * seized_value > swap fees + stable-pool imbalance loss` — satisfiable whenever the victim's HF margin is smaller than the achievable in-band `D` deformation, which depends only on pool depth relative to available flash liquidity.
