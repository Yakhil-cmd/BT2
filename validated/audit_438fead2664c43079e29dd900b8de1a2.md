### Title
Unvalidated `omniauth.origin` redirect in `callback` enables post-auth open redirect - (File: app/controllers/shipit/github_authentication_controller.rb)

### Summary
`GithubAuthenticationController#callback` redirects the just-authenticated browser to `request.env['omniauth.origin']` with no host allowlist check. Because the `origin` parameter is attacker-controllable on the OAuth-initiation URL and OmniAuth persists it verbatim across the OAuth round trip, an attacker can craft a login link that forces a victim's freshly authenticated session to be redirected to an arbitrary external host.

### Finding Description
The broken binding: `return_url.host == Shipit.host` is assumed but never checked; the actual code is `return_url = request.env['omniauth.origin'] || root_path` followed directly by `redirect_to(return_url)` [1](#0-0) .

Origin is normally set internally and safely — e.g. `force_github_authentication` builds the authentication-initiation link itself with `origin: request.original_url`, which is always same-host [2](#0-1) . However, nothing prevents an attacker from directly sending a victim to `/github/auth/github?origin=https://evil.example` themselves — this route is handled by the `OmniAuth::Builder` middleware mounted at `/github/auth` [3](#0-2) . OmniAuth's request phase stores the `origin` request param into the session and later exposes it back to the callback controller as `env['omniauth.origin']`, without any validation that it is same-host — that check would have to be added by the application (this engine), and it is not present anywhere in `callback`.

Exploit flow:
1. Attacker sends victim a link: `https://shipit.example.com/github/auth/github?origin=https://evil.example/`.
2. Victim, already possessing a valid GitHub OAuth session or completing the OAuth prompt, is redirected through GitHub and back to `.../github/auth/github/callback`.
3. `callback` runs, correctly sets `session[:user_id]` for the victim on the legitimate host, then executes `redirect_to(return_url)` where `return_url` is the attacker's `https://evil.example/` [4](#0-3) .
4. The victim's browser is sent off-host immediately after establishing a valid, authenticated Shipit session cookie.

No existing guard (`force_github_authentication`, `User#authorized?`, `require_permission!`, CSRF/webhook signature checks) inspects or restricts the `omniauth.origin` value at the callback step; those checks apply to session validity and team membership, not to the redirect target.

### Impact Explanation
The victim's browser, holding a freshly authenticated Shipit session cookie, is redirected to an attacker-chosen host. This matches the High-severity category "session fixation / forced OAuth completion" — the attacker forces completion of an OAuth flow whose resulting navigation they control, which can be used for phishing (attacker page appears immediately after a legitimate GitHub auth flow, increasing credibility) and to chain with other bugs that leak state via URL fragments/query strings. It does not by itself leak the Shipit session cookie (which stays with `shipit.example.com` unless `SameSite`/cookie scoping is broken elsewhere), but it does hand the attacker full control of the post-login navigation for any victim who clicks the crafted link — repeatable against any victim, not scoped to a single repository/stack.

### Likelihood Explanation
Preconditions are minimal: no Shipit secrets, no privileged role, and no pre-existing session are required by the attacker. The attacker only needs to get a victim (any user with GitHub access to the Shipit instance) to click a link of the form `/github/auth/github?origin=<attacker-url>`. This is inherent to the default OmniAuth `origin` mechanism and Shipit's controller does not add the missing host check, so likelihood is high given a social-engineering delivery vector (link, not code execution).

### Recommendation
Validate `return_url` before redirecting — only allow same-host, relative, or explicitly allowlisted URLs, e.g.:
```ruby
return_url = request.env['omniauth.origin']
return_url = root_path unless return_url.present? && Shipit::UrlValidator.same_host?(return_url, request)
```
implementing a helper that parses the URL and confirms `URI.parse(return_url).host` is `nil` (relative) or equals `request.host`, falling back to `root_path` otherwise.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback does not redirect to an attacker controlled host" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(raw_info: OmniAuth::AuthHash.new(
      id: 44, name: 'Shipit User', email: 'u@example.com',
      login: 'shipit-user', avatar_url: 'https://example.com',
      api_url: 'https://github.com/api/v3/users/shipit-user'
    ))
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example/'

  get :callback

  # Binding under test: redirect_to(return_url).host == request.host
  refute_equal 'evil.example', URI.parse(response.location).host
end
```
Running this against current code fails (`response.location == 'https://evil.example/'`), demonstrating the unchecked redirect.
