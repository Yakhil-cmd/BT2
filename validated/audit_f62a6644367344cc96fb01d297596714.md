### Title
Attacker-controlled `sshUser` from codespace RPC response can inject SSH options into the ssh argv - (File: internal/codespaces/ssh.go)

### Summary
`(App).SSH` in `pkg/cmd/codespace/ssh.go` builds `connectDestination` from `sshUser`, a value returned by `invoker.StartSSHServerWithOptions` (an RPC call answered by a process running inside the codespace), and passes it unsanitized as a single positional argv element to the local `ssh` binary via `internal/codespaces/ssh.go`'s `newSSHCommand`. Because this value is inserted into `argv` without validation, a codespace-side process that returns a hostname/user string beginning with `-` could have it parsed by the local `ssh` client as an option (e.g. `-oProxyCommand=...`), potentially leading to local command execution on the developer's machine.

### Finding Description
The flow is:
1. `(App).SSH` at [1](#0-0)  obtains `sshUser` from `invoker.StartSSHServerWithOptions(ctx, startSSHOptions)`, an RPC response returned by the ssh-server-host service running inside the codespace container.
2. `connectDestination` is derived directly from this value with no validation: [2](#0-1) .
3. This is passed into `codespaces.Shell(...)` and ultimately into `newSSHCommand`, which appends it as the `dst` argv element right after `-C`: [3](#0-2) .
4. `exec.CommandContext(ctx, exe, cmdArgs...)` invokes the real `ssh` binary with this argv, with no shell interpretation, but OpenSSH's own argument parser (BSD-style getopt) treats any token beginning with `-` as an option regardless of position in argv, not strictly positional. If `sshUser` (or the constructed `user@localhost` string) begins with a dash, e.g. `-oProxyCommand=<command>`, ssh could interpret this token as an option rather than the destination, resulting in execution of `ProxyCommand` on the victim's local machine — outside the codespace sandbox entirely.

No sanitization, allow-listing, or `--` separator is used before the destination argument, and the codebase does not validate that `sshUser` (or `opts.profile`) is a well-formed username/hostname without a leading `-`.

I was not able to fully confirm the exact type/validation of the RPC-returned `sshUser` field (`StartSSHServerWithOptions` return signature in `internal/codespaces/rpc/invoker.go`) within the available iterations — this should be verified with a background session, as should whether OpenSSH's actual parser genuinely allows an option to be recognized after `-C` and a positional-looking destination has already been supplied (this depends on precise OpenSSH getopt behavior for the installed client version).

### Impact Explanation
If exploitable, this allows a compromised/malicious codespace-side ssh-server-host process (i.e., something an attacker fully controls inside a codespace/devcontainer they authored) to escape the remote environment and execute arbitrary commands on the developer's local host merely by the victim running `gh codespace ssh` against that codespace. This matches the "RCE in gh" / arbitrary code execution class.

### Likelihood Explanation
Exploitability hinges on: (a) the victim connecting to an attacker-authored codespace/devcontainer whose SSH-host RPC server is customized to return a hostile `sshUser` string, and (b) OpenSSH's client-side argument parser actually reinterpreting a `-`-prefixed positional destination as an option in this specific invocation context. Because this requires control over the codespace-side RPC implementation (typically the attacker's own environment, which the attacker already fully controls), the primary value of the exploit is sandbox escape from the codespace to the local host, not a totally trust-free remote attack — this narrows the likelihood versus a pure "any GitHub content" exploit.

### Recommendation
- Validate `sshUser` (and `opts.profile`) against a strict allow-list pattern (e.g. POSIX username / hostname charset, disallowing a leading `-`).
- Always separate ssh options from the destination with a literal `--` in the argv passed to `exec.Command`, or prefix `dst` with `./`-style neutralization equivalent (e.g., reject/escape leading dashes) before adding it to `cmdArgs`.
- Apply the same treatment to `connArgs`/`dst` construction in `internal/codespaces/ssh.go`'s `newSSHCommand` and `newSCPCommand`.

### Proof of Concept
Suggested Go test in `internal/codespaces/ssh_test.go` (or equivalent):
```go
func TestNewSSHCommand_HostileDestination(t *testing.T) {
    cmd, _, err := newSSHCommand(context.Background(), 1234, "-oProxyCommand=touch /tmp/pwned", nil, nil)
    require.NoError(t, err)
    // Assert that the destination is not adjacent/ambiguous as an option,
    // e.g. require args contain a literal "--" before the destination,
    // or that dst does not begin with '-'.
    argv := cmd.Args
    idx := indexOf(argv, "-oProxyCommand=touch /tmp/pwned")
    require.True(t, idx > 0 && argv[idx-1] == "--", "destination must be preceded by -- to prevent option injection")
}
```
Complementary integration-style test: stub the RPC invoker (`rpc.Invoker`) to return `sshUser = "-oProxyCommand=touch /tmp/pwned"` from `StartSSHServerWithOptions`, run `(App).SSH`, and record the constructed `exec.Cmd.Args` (via a fake `safeexec.LookPath`/PATH shim) to confirm whether the hostile value reaches argv unguarded by `--`.

```go
func newSSHCommand(ctx context.Context, port int, dst string, cmdArgs []string, command []string) (*exec.Cmd, []string, error) {
	connArgs := []string{
		"-p", strconv.Itoa(port),
		"-o", "NoHostAuthenticationForLocalhost=yes",
		"-o", "PasswordAuthentication=no",
	}

	cmdArgs = append(cmdArgs, connArgs...)
	cmdArgs = append(cmdArgs, "-C") // Compression
	cmdArgs = append(cmdArgs, dst)  // user@host

	if command != nil {
		cmdArgs = append(cmdArgs, command...)
	}
```
