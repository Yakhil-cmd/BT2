### Title
Bridge `handle*Transfer` Functions Bypass `isRunning` Stop-Mode Guard — (`File: contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`)

---

### Summary

The service-chain bridge contracts expose a `isRunning` flag that the owner sets to `false` to halt all value transfers. The outbound request functions (`_requestKLAYTransfer`, `_requestERC20Transfer`, `_requestERC721Transfer`) correctly enforce `require(isRunning, "stopped bridge")`. The inbound handle functions (`handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`) carry no such check. When the bridge is stopped, operators can still call these handle functions and move KAIA or mint/transfer bridged ERC20/ERC721 tokens on the destination chain.

---

### Finding Description

`BridgeTransfer.sol` declares `bool public isRunning = true` and exposes `setRunningStatus(bool)` (owner-only) to halt the bridge. [1](#0-0) 

The outbound request path enforces the guard in all three asset types: [2](#0-1) [3](#0-2) [4](#0-3) 

The inbound handle functions carry **no** `isRunning` check:

- `handleKLAYTransfer` (lines 62–100): transfers KAIA to `_to` via a low-level `.call.value(_value)("")`. [5](#0-4) 

- `handleERC20Transfer` (lines 32–73): mints or transfers ERC20 tokens. [6](#0-5) 

- `handleERC721Transfer` (lines 29–71): mints or transfers ERC721 tokens. [7](#0-6) 

The operator threshold defaults to `1` (a single operator suffices to execute a handle call): [8](#0-7) 

---

### Impact Explanation

When the bridge owner calls `setRunningStatus(false)` — the expected emergency-stop or migration-pause action — the invariant "no assets move while the bridge is stopped" is broken. Any registered operator can still call `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer` with arbitrary parameters and:

- Drain KAIA held by the bridge contract.
- Mint unbacked ERC20/ERC721 tokens on the destination chain (in `modeMintBurn` mode).
- Transfer ERC20/ERC721 tokens held by the bridge contract (in lock/unlock mode).

This is an **unauthorized transfer and mint of KAIA and bridged assets** — directly within the allowed impact gate.

---

### Likelihood Explanation

- The default operator threshold is 1, so a single operator key is sufficient.
- Operators are semi-trusted relayers; a compromised or malicious operator key is a realistic threat model, and the entire purpose of `isRunning` is to provide a circuit-breaker against exactly this scenario.
- The bridge owner has no other mechanism to prevent inbound handle calls once an operator key is compromised; stopping the bridge via `setRunningStatus(false)` is the documented mitigation, yet it is ineffective for the handle path.

---

### Recommendation

Add `require(isRunning, "stopped bridge")` at the top of each handle function, mirroring the guard already present in the request functions:

```solidity
// BridgeTransferKLAY.sol – handleKLAYTransfer
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferERC20.sol – handleERC20Transfer
function handleERC20Transfer(...) public onlyOperators {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferERC721.sol – handleERC721Transfer
function handleERC721Transfer(...) public onlyOperators {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}
```

### Proof of Concept

```
Setup
─────
1. Deploy Bridge (modeMintBurn = false), fund it with 100 KAIA.
2. Register operatorA (threshold = 1, default).
3. Owner calls setRunningStatus(false)  →  isRunning = false.

Attack
──────
4. operatorA calls:
       handleKLAYTransfer(
           txHash,          // any bytes32
           victim,          // _from (ignored for asset movement)
           attacker,        // _to  ← receives KAIA
           100 ether,       // _value
           0,               // _requestedNonce (≥ lowerHandleNonce)
           1,               // _requestedBlockNumber
           ""               // _extraData
       )

5. _lowerHandleNonceCheck passes (nonce 0 ≥ lowerHandleNonce 0).
6. _voteValueTransfer passes (threshold = 1, operatorA is the sole voter).
7. Line 98: `_to.call.value(100 ether)("")` executes.
8. 100 KAIA transferred to attacker.
9. isRunning was false — the stop-mode guard was never consulted.
```

The same sequence applies to `handleERC20Transfer` (minting or transferring ERC20) and `handleERC721Transfer` (minting or transferring ERC721), with the same absent `isRunning` check.
