### Title
Whitespace-stripped set-based diff filtering can reclassify a genuinely new dangerous line as pre-existing context, hiding it from the LLM security reviewer - ([File: plugins/security-guidance/hooks/gitutil.py])

### Summary
`filter_preexisting_from_diff()` matches added and removed diff lines only on `line[1:].strip()`, using a `set` for the removed side. A full-file rewrite (e.g. via the Write tool) that moves a dangerous call (like `os.system(cmd)`) into a new control-flow branch, but leaves its stripped text identical to a line that was removed elsewhere in the file, is converted from a `+` (added) line into a `' '` (context) line. Because the downstream `analyze_code_security` diff-review prompt explicitly instructs the LLM to never flag anything in context lines — "even if a context line contains ... any other vulnerability — it is PRE-EXISTING and must be ignored" — this laundering silently removes the newly introduced dangerous line from review.

### Finding Description
`filter_preexisting_from_diff` ( [1](#0-0) ) builds `removed_lines` as a `set` of `line[1:].strip()` for every `-` line in the diff, and then for every `+` line checks membership of `line[1:].strip()` in that set. If it matches, the line is rewritten as a context line (`' ' + line[1:]`) instead of `+`: [2](#0-1) 

The function's own comment concedes this is imprecise: `.strip()` matches across indentation/reindentation and the set allows one removed line to mask N unrelated added lines with the same stripped text — the code explicitly documents this as an "accepted trade-off": [3](#0-2) 

This filtered diff (with the malicious line now `' '`-prefixed) is passed to `parse_diff_into_files` → `analyze_code_security(diff_files, is_diff=True)`. The prompt built there explicitly and unconditionally tells the reviewer to treat any space-prefixed line as pre-existing and to ignore vulnerabilities in it, even hard-coded secrets: [4](#0-3) . There is no structural/AST or control-flow check — matching is purely lexical on stripped text — so a dangerous line relocated into a brand-new `if` branch (changing when/whether it executes) but textually identical (after strip) to some unrelated removed line elsewhere in the file will be silently reclassified as unchanged/context and skipped by the reviewer.

The only mentioned "backstop" in the code comment is "the diff-review prompt's previous-findings recheck," which is a mechanism for re-verifying findings the LLM already surfaced in an earlier fire this session (`_dedup_against_state` / `previous_findings` in `llm.py`, lines 680-707, 767-784) — it has no bearing on lines the reviewer was never told about because `filter_preexisting_from_diff` converted them to context before the prompt was built. So the stated backstop does not actually cover this scenario.

### Impact Explanation
This is a diff-content laundering bug that causes the automated LLM security reviewer to silently miss a genuinely new, exploitable vulnerability (e.g., a newly-introduced `os.system(cmd)` reachable via a new conditional branch) introduced in the same tool call that rewrites the file. The user/developer relying on the Stop-hook / commit-review security guidance receives no warning about a real, newly created attack surface, defeating the core "reviewed diff content must faithfully represent newly introduced risk" invariant of the plugin. Impact is scoped to false-negative suppression of a security finding rather than a direct compromise (no command execution, no approval bypass, no credential exposure caused by the hook itself) — it degrades a defense-in-depth review mechanism.

### Likelihood Explanation
Requires the diff to go through `filter_preexisting_from_diff`, which only activates when `removed_lines` is non-empty (i.e., a full-file rewrite where lines are shown as `-` then `+`, as with the Write tool overwriting an existing file) and at least one added line matches a removed line after `.strip()` (`preexisting_count > 0`, lines 687-690). An attacker who controls file content (an ordinary/unprivileged actor able to get Claude to write attacker-authored or attacker-influenced code, e.g. via a crafted PR/task/repo content) can trivially engineer this: reindent a dangerous call so it appears literally the same after `.strip()` as a line elsewhere in the same file's previous content, while wrapping it in a new conditional. This is a straightforward, deterministic, repeatable text-matching gap, not a probabilistic model failure — feasibility is high given the documented indentation-insensitive, one-to-many set matching.

### Recommendation
Replace whitespace-stripped set equality with a structural diff (e.g., use Python's `difflib.SequenceMatcher`/`unified_diff` opcode matching on exact lines, or at minimum require exact (non-stripped) line equality plus positional/context proximity, e.g. LCS-based alignment) so that reindentation is tolerated only when the line's surrounding hunk position and control-flow nesting are otherwise unchanged. At minimum, only reclassify a `+` line as context if it matches a `-` line while preserving indentation depth AND the enclosing block structure (e.g., don't collapse to a set — align on a proper diff of removed vs. added line sequences to prevent one `-` line masking N unrelated `+` lines).

def filter_preexisting_from_diff(diff_files, cwd, baseline_sha):
    """
    Filter out pre-existing content from diff files.
    When a file is fully rewritten (Write tool replaces entire content),
    git shows all lines as removed (-) then re-added (+). This function
    detects such rewrites and strips lines from the + section that also
    appeared in the - section, so the LLM reviewer only sees truly new code.
    """
    if not baseline_sha:
        return diff_files

    filtered = []
    for file_path, diff_content in diff_files:
        lines = diff_content.split('\n')

        # Collect removed and added lines (stripping the +/- prefix)
        removed_lines = set()
        added_lines = []
        for line in lines:
            if line.startswith('-') and not line.startswith('---'):
                removed_lines.add(line[1:].strip())
            elif line.startswith('+') and not line.startswith('+++'):
                added_lines.append(line[1:].strip())

        if not removed_lines:
            # New file, no pre-existing content to filter
            filtered.append((file_path, diff_content))
            continue

        # Check what fraction of added lines were pre-existing
        preexisting_count = sum(1 for l in added_lines if l in removed_lines)
        if preexisting_count == 0:
            filtered.append((file_path, diff_content))
            continue
