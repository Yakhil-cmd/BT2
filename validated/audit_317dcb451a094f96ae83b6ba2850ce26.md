### Title
Webhook organization used for signature verification is not bound to the repository actually mutated by the handler pipeline - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to check the HMAC against using a payload field (`repository.owner.login` / `organization.login`), but the event handlers that subsequently act on the same payload key off a *different* payload field (`repository.full_name`) to find and mutate `Stack`/`Repository` records. Nothing enforces that the organization whose secret validated the request is the same organization whose repository gets written to, breaking the binding `organization_authenticated == repository_written`.

### Finding Description
In `app/controllers/shipit/webhooks_controller.rb`: [1](#0-0) 

`verify_signature` looks up the GitHub App config to verify against using `repository_owner`: [2](#0-1) 

`Shipit.github(organization: repository_owner)` resolves to a specific org's `webhook_secret` (multi-tenant support is confirmed by the `GithubOrganizationUnknown` rescue path handling unknown orgs). The verification itself is a plain HMAC compare against the raw body using that org's secret: [3](#0-2) 

Once verification passes, `create` dispatches the *entire, unfiltered* `params` hash to every registered handler for the event: [4](#0-3) 

But the handlers do not consult `repository.owner.login` (the field used for signature verification) at all — they resolve the target `Repository`/`Stack` purely from `repository.full_name`: [5](#0-4) [6](#0-5) 

Because the signature check only proves "this body was HMAC-signed by *some* org's registered `webhook_secret`," and the org used for that lookup is attacker-controlled (`repository.owner.login`), while the acted-upon repository comes from an unrelated field (`repository.full_name`) that is never cross-checked against the verifying organization, an attacker who legitimately owns/administers *any* org configured in this multi-tenant Shipit instance (and therefore knows that org's `webhook_secret`, since GitHub delivers/allows viewing webhook secrets to org admins for apps they install) can forge a payload where:
- `repository.owner.login` = their own org → causes `verify_signature` to validate against their own known secret.
- `repository.full_name` = `"victim-org/victim-repo"` → causes `PushHandler#process` (and any other full_name-driven handler) to locate and mutate a completely different tenant's `Stack`.

### Impact Explanation
This is a cross-repository/cross-tenant write: a request cryptographically authenticated for organization A results in mutations to stacks owned by organization B, using only credentials the attacker legitimately possesses for their own org. For `PushHandler`, this triggers `stack.sync_github(expected_head_sha: params.after)` for an arbitrary victim stack, i.e., an attacker can force GitHub sync jobs for repositories/branches they do not control by forging the sha and ref fields, using only their own org's webhook secret. Any other handler that resolves its target purely from `repository.full_name` (or similar payload identifiers) inherits the same cross-tenant write exposure. This satisfies the "cross-repository writes" / "unauthorized" category since the boundary broken is exactly `organization_authenticated (used for signature) != repository_written (used for mutation)`.

### Likelihood Explanation
Exploitability requires only that the Shipit deployment is configured for more than one GitHub organization (multi-tenant `github_apps`/`config.github` setup, which the codebase explicitly supports via the `GithubOrganizationUnknown` rescue path) and that the attacker is a legitimate (unprivileged, relative to the victim org) admin/owner of at least one of those configured orgs — no access to the victim's secrets, tokens, or repositories is needed. Crafting the JSON body with mismatched `repository.owner.login` vs `repository.full_name` is trivial (a normal HTTP POST to `/webhooks` with the correct `X-Hub-Signature` computed from their own known secret).

### Recommendation
Bind organization identity for signature verification to the exact same field used by the handler pipeline to select the target repository, and reject if they disagree:
- In `WebhooksController#verify_signature`, resolve the organization strictly from the same `repository.full_name`/`repository.owner.login` value that `Handler#repository_name` will subsequently use, and fail closed if the resolved repository does not belong to the verifying organization's known repositories.
- Additionally, have each `Handler` verify that the repository resolved from `payload.dig('repository','full_name')` actually belongs to the organization that was used to validate the signature, rather than trusting `full_name` unconditionally.

### Proof of Concept
1. Deploy Shipit configured with two organizations, `org-a` (attacker-controlled, webhook secret `S_A` known to the attacker as an org admin) and `org-b` (victim, owns stack tracking `org-b/victim-repo`).
2. Attacker crafts a `push` webhook JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "org-a" },
    "full_name": "org-b/victim-repo"
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<hmac-sha1(S_A, body)>` using their own known `org-a` secret.
4. POST to `/webhooks` with `X-Github-Event: push`.
5. `verify_signature` calls `Shipit.github(organization: "org-a")` (derived from `repository.owner.login`), validates successfully against `S_A`. [1](#0-0) 
6. `create` dispatches to `PushHandler`, which resolves `repository_name` = `"org-b/victim-repo"` and calls `stack.sync_github(expected_head_sha: params.after)` for the victim's stack — a mutation on `org-b`'s stack triggered by a signature that only ever proved knowledge of `org-a`'s secret. [6](#0-5)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
