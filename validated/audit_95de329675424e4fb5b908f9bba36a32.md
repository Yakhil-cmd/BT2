### Title
`git commit --amend` during a Claude turn causes `compute_v2_review_set` to silently exclude the amended dangerous change from review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` only folds committed changes into the reviewed set when `head_at_capture` is a linear ancestor of the current `HEAD`. A `git commit --amend` (or any history-rewriting commit operation) replaces the captured commit with a sibling rather than a descendant, so `_is_ancestor` returns `False` and the amended file's change is never added to `dirty_now`. Because `review_set = dirty_now ∩ changed_since`, the amended file — which legitimately differs from the pre-turn stash baseline and thus appears in `changed_since` — is dropped from the final intersection whenever the working tree is otherwise clean, so it is never surfaced to the Stop-hook LLM review.

### Finding Description
`compute_v2_review_set` [1](#0-0)  computes the review set as an intersection of two independently derived sets:
- `dirty_now`: files reported dirty by `git status --porcelain` at Stop time, unioned with `git diff --name-only head_at_capture..HEAD` **only if** `head_at_capture` is an ancestor of the current HEAD [2](#0-1) .
- `changed_since`: files that differ from the `git stash create` baseline SHA captured at UserPromptSubmit [3](#0-2) .

The final `review_set = dirty_now & changed_since` [4](#0-3) .

Exploit flow:
1. UPS captures `baseline_sha` (via `capture_git_baseline`, a `git stash create` snapshot of HEAD+worktree) and `head_at_capture` (`HEAD` SHA at that point).
2. During the turn, a file is modified and committed, then the commit is amended (e.g., `git commit -m "x" && git commit --amend`), or any other command sequence that rewrites the just-created commit rather than extending it linearly.
3. Since the amended commit is not a descendant of `head_at_capture` in the ancestry graph, `_is_ancestor(repo, head_at_capture, current_head)` returns `False` [5](#0-4) , so the `dirty_now |= _git_name_only(head_at_capture..HEAD)` branch never executes and `diff_base` stays `"HEAD"`.
4. After the amend, the working tree is clean, so `git status --porcelain` reports no tracked-dirty or untracked files — `dirty_now` ends up empty for that file.
5. Meanwhile `changed_since` (diff against `baseline_sha`) still correctly contains the amended file, since its content differs from the pre-turn snapshot.
6. `review_set = dirty_now ∩ changed_since = ∅` for that file — it is silently excluded from the Stop-hook LLM security review even though it represents new, unreviewed, potentially dangerous content.

This breaks the stated invariant ("the review set must stay bound to the right repo, baseline, and touched paths") because the intersection design assumes `dirty_now` always reflects all commits made since capture, but the linear-ancestor check is a narrower condition than "content changed since baseline," causing false negatives for non-linear commit history (amend, rebase, reset --soft + recommit, cherry-pick replacing the tip, etc.).

### Impact Explanation
A dangerous code change (e.g., a backdoor or command-injection payload) introduced by Claude and then folded into a `git commit --amend` during the same turn would bypass the Stop-hook's LLM security review entirely, since the file drops out of `compute_v2_review_set`'s output. This matches the stated Immunefi impact: "Unauthorized local command execution that bypasses Claude Code approval or deny controls" — the review/approval gate for git-tracked code changes can be circumvented via ordinary git commands (amend) without any special privilege, and the dangerous change is "treated as old and skipped" from a security-review standpoint.

### Likelihood Explanation
This requires only ordinary git operations available within a normal Claude Code session (commit followed by amend, or other non-fast-forward commit rewriting) in a cloned repo — no elevated privileges, no exploitation of parsing bugs, and no social engineering beyond driving Claude (or a compromised/malicious instructed turn) to run `git commit --amend`. Amending a just-made commit is an extremely common, unremarkable git workflow, making this readily and repeatably triggerable. The condition only requires the working tree to be clean after the amend (the typical post-amend state), which is the default outcome.

### Recommendation
Do not gate the committed-changes contribution to `dirty_now` on `_is_ancestor`. Instead, always compute the diff of tracked file paths between `baseline_sha` (or `head_at_capture`) and current `HEAD`/worktree, or simplify by relying solely on `changed_since` (diff vs. the stash baseline) as the authoritative review set rather than intersecting with a `dirty_now` set that is blind to non-linear commit rewrites. At minimum, when `head_at_capture != current_head` and `_is_ancestor` is `False` (i.e., HEAD moved non-linearly — amend, rebase, reset, force-checkout to a new commit), fall back to unioning in `_git_name_only(head_at_capture, current_head)` treating them as unrelated commits (equivalent to a full diff between the two trees) rather than skipping the union entirely.

### Proof of Concept
Integration test plan (pytest style, following patterns in the existing test suite for `compute_v2_review_set`):
1. Initialize a temp git repo with an initial commit (`baseline.txt`).
2. Call `capture_git_baseline(cwd)` to get `baseline_sha`, and `_git_rev_parse_head(cwd)` to get `head_at_capture` — simulating UPS.
3. Write a dangerous payload into `evil.py` (e.g., `os.system(user_input)`), stage and commit it: `git add evil.py && git commit -m "add feature"`.
4. Amend the commit without further changes needed to trigger the ancestry break: `git commit --amend -m "add feature (amended)"`.
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. **Expected (correct) assertion**: `evil.py`'s absolute path is present in the returned `review_paths`.
7. **Actual (vulnerable) result**: `evil.py` is absent from `review_paths` because `_is_ancestor(head_at_capture, current_head)` is `False` (amend produces a non-descendant commit) and the working tree is clean, so `dirty_now` is empty and the intersection with `changed_since` yields nothing for `evil.py`.

This test directly exercises `compute_v2_review_set` and `_is_ancestor` and demonstrates the review-set drops a dangerous, genuinely-changed file after a routine `git commit --amend`.

```python
def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
    if not isinstance(untracked_at_baseline, dict):
        untracked_at_baseline = {}

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
