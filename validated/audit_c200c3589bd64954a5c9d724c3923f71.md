The CVE describes a stored-XSS bug class: a web application (Frappe Learning) accepts file uploads for a user profile "bio" field and fails to sanitize SVG content before rendering it back to other users in a browser, allowing embedded `<script>` execution. That bug class requires a client that parses and renders untrusted HTML/SVG in a browser DOM context on behalf of other users.

Polkadot SDK is blockchain runtime/node code, not a web application that stores and re-renders user-submitted markup or files for other users to view. The closest conceptual analog I could find is `pallet-identity`'s `IdentityInfo` struct, which stores user-supplied fields like `display`, `legal`, `web`, `image`, `twitter`, etc. as opaque `Data` (raw bytes with a length-prefix encoding), with no rendering, parsing, or sanitization step anywhere in the pallet [1](#0-0) [2](#0-1) . These fields are consensus-level storage values accessed via SCALE-encoded reads/RPC; there is no code path in FRAME that renders this data as HTML/SVG/script in a shared browser context for other users, so the "malicious content executed in another user's session" invariant from the report has no reachable equivalent boundary here.

The one place SVG-with-embedded-`<script>` actually appears in this repo is a local developer tooling script (`typegraph.sh`) that generates a type-graph SVG for local viewing and intentionally injects a `<script>` for interactive highlighting; this is a build/dev tool, not attacker-reachable via any signed extrinsic, XCM message, or contract call, and is explicitly excluded by the scan's rules against tests/tooling/config-only findings [3](#0-2) [4](#0-3) .

No real user entry point (signed extrinsic, contract call, XCM message) in this codebase stores content that is later parsed/rendered as HTML/SVG for other users, so the bug class from the Frappe Learning report does not have a demonstrable analog here.

#!/usr/bin/env bash
# Build an interactive type-graph SVG of every type defined in `pallet-revive-types`. Nodes are the
# structs, enums, and type aliases declared in this crate; edges are containment relationships
# (struct fields, enum variant payloads, type-alias targets). External types such as `Vec`,
# `Option`, `H256`, `Address`, etc. are filtered out.
#
# The resulting SVG embeds a small script that, when the file is opened in any browser, lets you
# click a node to highlight every type that transitively depends on it.
#
# Pipeline:
#   1. `cargo +nightly rustdoc` emits a JSON dump of the crate's public and private items.
#   2. `jq` walks the JSON, collects local nodes (`crate_id == 0`), and for each one chases the
#      field/variant indirection back to the referenced types, keeping only references that resolve
#      to other local nodes.
#   3. `dot` lays the graph out as SVG.
#   4. `awk` injects an inline `<style>` and `<script>` block before `</svg>` so the resulting file
#      is self-contained and clickable.
#
# Usage: ./typegraph.sh [output.svg]
#        Defaults to <workspace target>/types-typegraph.svg.
