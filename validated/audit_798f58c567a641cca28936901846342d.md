### Title
Forged `membership` webhook with a low-security organization's login lets an attacker de-authorize any operator via `MembershipHandler#process` `removed` branch - (File: `app/models/shipit/webhooks/handlers/membership_handler.rb`)

### Summary
`WebhooksController#verify_signature` authenticates the request against the GitHub App configured for `repository_owner`, which for `membership` events is taken from the attacker-controlled `organization.login` field of the JSON body. `MembershipHandler#find_or_create_team!` looks up the target `Team` solely by `github_id`, ignoring which organization actually authenticated the request. Combining these lets an attacker who controls (or names) any organization slot in `Shipit.github.*` that has no `webhook_secret` set forge a `removed` event that deletes a `Membership` belonging to a completely different, secured organization's team.

### Finding Description
The broken binding is: `Shipit.github(organization: params.dig('organization','login')).verify_webhook_signature(...)` (the organization that cryptographically authenticated the request) **should equal** `Team.find_by(github_id: params['team']['id']).organization` (the organization that actually owns the team/membership being mutated). The code never establishes this equality.

- `WebhooksController#repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`) falls back to `params.dig('organization', 'login')` for events like `membership` that have no `repository` key.
- `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-30`) fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature`. Crucially, `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) contains `return true unless webhook_secret` — if the named organization's app config has no `webhook_secret` (the documented default in every example secrets file, e.g. `config/secrets.development.example.yml:11`, `test/dummy/config/secrets_double_github_app.yml:7`), **any** payload is accepted, signature or not.
- `MembershipHandler#process` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-34`) then calls `find_or_create_team!`, which does `Team.find_or_create_by!(github_id: params.team.id)` (`membership_handler.rb:38-43`). This lookup is keyed only by `github_id`; it does not verify that `params.organization.login` matches the `organization` column of the found `Team`. If a `Team` row already exists (created earlier by a legitimate `membership` webhook from the real, secured org), the forged payload's `organization.login` is simply ignored — the existing team is returned as-is.
- The handler then executes `team.members.delete(member)`, and `member` is resolved via `User.find_or_create_by_login!(params.member.login)` — an attacker-supplied login, e.g. the login of a real operator.

Exploit flow:
1. Attacker learns the `github_id` of a real team already tracked in Shipit (team IDs are visible via GitHub's public/team API or from prior legitimate webhook traffic) and the `login` of a target operator who is a member of it.
2. Attacker sends `POST /webhooks` with header `X-Github-Event: membership`, and JSON body: `{"action":"removed","team":{"id":<real_team_github_id>,"name":"x","slug":"x","url":"https://x"},"organization":{"login":"<any-org-with-no-webhook_secret>"},"member":{"login":"<target-operator-login>"}}`.
3. `repository_owner` resolves to the attacker-named organization (not the team's real owning org).
4. If that organization's `GitHubApp` has `webhook_secret` unset (the default/documented configuration), `verify_signature` passes unconditionally.
5. `MembershipHandler` finds the pre-existing `Team` by `github_id` (ignoring the mismatched `organization.login`) and destroys the `Membership` row for the target user, revoking their access if `Shipit.github_teams` membership gates `User#authorized?` (`app/models/shipit/user.rb:80-82`).

Existing guards do not stop this: `drop_unhandled_event` only checks the event type is handled; `ExplicitParameters` schema only validates types/presence, not organizational consistency; there is no `require_permission!`/session check on webhook endpoints (webhooks are inherently unauthenticated except via signature); and `verify_signature`'s only real check — the HMAC signature — is a no-op precisely when `webhook_secret` is blank for the named organization.

### Impact Explanation
A single unprivileged HTTP request causes a write to Shipit's own authorization table (`Membership`) for a team owned by a different, properly secured organization, de-authorizing a legitimate operator (denial of access) without any valid credential. This matches the "Critical" category of "a payload for one repository/organization mutating another's ... team" and constitutes an authentication-bypass-driven state mutation. The attack is repeatable against any team whose `github_id` the attacker can learn, and blast radius spans every organization configured under `Shipit.github` in a multi-org (`config.github.<org>`) deployment, since only one weakly-configured organization slot is needed to forge events attributed to any other.

### Likelihood Explanation
Preconditions: (1) Shipit configured with multiple GitHub organizations (`Shipit.github(organization: ...)` schema) where at least one has `webhook_secret` unset — a state explicitly shown as the default in this repo's own example configs (`webhook_secret: # nil`); (2) the target `Team` row must already exist in Shipit's database (created by a prior legitimate webhook), which is normal for any operational Shipit instance using team-based authorization; (3) attacker needs only the team's public GitHub `id` and the target user's GitHub login, both discoverable without any Shipit credentials. No GitHub App private key, webhook secret, or Shipit session is required. This is a low-cost, fully repeatable, unauthenticated attack given the common "secret left blank" configuration.

### Recommendation
- In `MembershipHandler#find_or_create_team!`, verify that `params.organization.login.downcase == team.organization.downcase` before performing any mutation; reject (raise/log and no-op) on mismatch.
- In `WebhooksController#verify_signature`, do not treat a missing/blank `webhook_secret` as automatic verification success; require an explicit opt-in (e.g. a configuration flag) to run unsigned in development/test only, and fail closed in all other cases.
- Bind `repository_owner` resolution more strictly per event type instead of a generic `organization.login` fallback, and cross-check it against the resource actually being mutated (team/repository) before any write.

### Proof of Concept
Minitest plan (extending `test/controllers/webhooks_controller_test.rb`):
```ruby
test "forged membership 'removed' event from an unrelated, secret-less org destroys an operator's membership" do
  # Arrange: existing team owned by a *secured* org ("shopify") with a real membership
  team = Team.create!(github_id: 999, name: 'Ops', slug: 'ops', organization: 'shopify', api_url: 'https://x')
  operator = shipit_users(:walrus) # existing user with a valid github_access_token
  Membership.create!(team:, user: operator)

  # Attacker names an org ("attacker-org") whose GitHubApp has no webhook_secret configured
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(
    GitHubApp.new('attacker-org', { webhook_secret: nil })
  )

  request.headers['X-Github-Event'] = 'membership'
  payload = {
    action: 'removed',
    team: { id: 999, name: 'Ops', slug: 'ops', url: 'https://x' },
    organization: { login: 'attacker-org' }, # binding is broken here
    member: { login: operator.login }
  }.to_json

  assert_difference -> { Membership.count }, -1 do
    post :create, body: payload, as: :json
    assert_response :ok
  end
end
```
Both sides of the claimed binding — `repository_owner` ("attacker-org", verified) vs. `team.organization` ("shopify", the actual owner) — remain unequal after the request, yet the mutation (`Membership.count` decreasing) still occurs, proving the vulnerability.       github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

      head(422) unless verified

      Rails.logger.info([

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
