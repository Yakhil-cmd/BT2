### Title
Missing zero-check on `kip71.gastarget` governance parameter causes divide-by-zero panic halting all nodes — (`params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter uses `noopFormatChecker`, which accepts zero as a valid value. `NextMagmaBlockBaseFee` divides by `gasTarget` without a zero guard. A governance vote setting `kip71.gastarget = 0` causes a `big.Int.Div` panic on every node when processing any block with non-zero gas used, halting the chain.

---

### Finding Description

In `kaiax/gov/param.go`, the `Kip71GasTarget` entry uses `noopFormatChecker`: [1](#0-0) 

`noopFormatChecker` unconditionally returns `true`, so zero is accepted as a valid governance value. [2](#0-1) 

By contrast, `Kip71BaseFeeDenominator` — also used as a divisor — explicitly rejects zero: [3](#0-2) 

In `params/kip71_config.go`, `NextMagmaBlockBaseFee` guards `BaseFeeDenominator == 0` with a fallback: [4](#0-3) 

But there is **no equivalent guard for `gasTarget`**. The function uses `gasTarget` as a divisor in two places: [5](#0-4) [6](#0-5) 

The only early exit that avoids division is `if parentGasUsed == gasTarget` (line 90). If `gasTarget == 0` and `parentGasUsed == 0`, this returns safely. But if `gasTarget == 0` and `parentGasUsed > 0` (any block containing transactions), execution falls into the `else if parentGasUsed > gasTarget` branch and reaches `x.Div(x, new(big.Int).SetUint64(0))`, which panics in Go's `math/big`. [7](#0-6) 

---

### Impact Explanation

`NextMagmaBlockBaseFee` is called on every post-Magma block in four production paths:

- **Block validation** — `blockchain/block_validator.go` calls it inside `VerifyMagmaHeader` for every incoming header. [8](#0-7) 
- **Block production** — `work/worker.go` calls it in `commitNewWork`. [9](#0-8) 
- **Tx pool reset** — `blockchain/tx_pool.go` calls it after every head update. [10](#0-9) 
- **Fee history API** — `node/cn/gasprice/feehistory.go` calls it per block. [11](#0-10) 

A panic in any of these goroutines crashes the node process. Because all nodes execute this function when processing each block, setting `kip71.gastarget = 0` causes every node to crash on the first block that includes at least one transaction, producing a complete chain halt and consensus divergence on all honest nodes.

---

### Likelihood Explanation

`kip71.gastarget` is listed as a **mutable** governance parameter: [12](#0-11) 

In "single" governance mode (Kaia Mainnet), the governing node can cast a vote for `kip71.gastarget = 0`. Post-Kore, the governance contract controller can set it via `ContractGov`. The `noopFormatChecker` means the governance layer accepts the value without rejection, and `ParamSet.Set` stores it directly: [13](#0-12) 

`ToKip71Config()` then passes the zero value straight into `KIP71Config.GasTarget`: [14](#0-13) 

---

### Recommendation

1. **Fix the format checker** for `Kip71GasTarget` in `kaiax/gov/param.go` to reject zero, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```

2. **Add a defensive guard** in `NextMagmaBlockBaseFee` in `params/kip71_config.go`, analogous to the existing `BaseFeeDenominator` guard:

```go
if kc.GasTarget == 0 {
    return makeEvenByFloor(lowerBoundBaseFee)
}
```

---

### Proof of Concept

1. Governance actor submits a vote for `kip71.gastarget = 0`. The `noopFormatChecker` accepts it; `NewVoteData` / `NewGovData` succeed.
2. After the governance epoch, `GetParamSet` returns `GasTarget = 0`. `ToKip71Config()` produces `KIP71Config{GasTarget: 0, ...}`.
3. The next block arrives with `parentGasUsed > 0` (any block with transactions).
4. `NextMagmaBlockBaseFee` is called. `parentGasUsed (> 0) > gasTarget (0)` → enters the increase branch.
5. Line 102: `x.Div(x, new(big.Int).SetUint64(0))` → **panic: division by zero**.
6. The panic propagates unrecovered through block validation, block production, and tx pool reset goroutines, crashing all nodes.
7. Chain halts; no further blocks can be produced or validated.
