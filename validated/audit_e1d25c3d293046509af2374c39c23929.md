Based on tracing `coin_registry.move`, this is a **real, exploitable griefing/front-running vulnerability** — the mechanics described in the question are accurate given the code.

### Title
Permissionless `migrate_legacy_metadata` Front-Run Permanently Strands OTW-Based `Currency<T>` Registration - (File: `crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

### Summary
`migrate_legacy_metadata<T>` is a public, unauthenticated entry point that requires only a `&CoinMetadata<T>` reference (which can be frozen/shared/owned, and is trivially readable/borrowable by anyone once such an object exists on-chain) to permanently claim the derived-object slot `CurrencyKey<T>()` for `Currency<T>` in the shared `CoinRegistry`.

### Finding Description
`migrate_legacy_metadata` calls the `migrate_legacy_metadata_impl!` macro, which asserts `!registry.exists<T>()` and then calls `derived_object::claim(&mut registry.id, CurrencyKey<T>())`, creating and sharing a `Currency<T>` with `regulated: RegulatedState::Unknown`, `supply: SupplyState::Unknown`, `treasury_cap_id: None`: [1](#0-0) 

Separately, a project using the OTW flow calls `new_currency_with_otw`, which builds a `Currency<T>` with a fresh `object::new(ctx)` id (not yet derived) and marks `is_otw: true`: [2](#0-1) 

`finalize` then transfers this `Currency<T>` (as a TTO) to the registry address when `is_otw` is true: [3](#0-2) 

The second, permissionless step, `finalize_registration`, receives that object and attempts to re-derive it at the canonical `CurrencyKey<T>()` slot via `derived_object::claim`: [4](#0-3) 

Because `derived_object::claim` aborts if the derived slot is already occupied (see `EObjectAlreadyExists` behavior exercised in `crates/sui-framework/packages/sui-framework/tests/derived_object_tests.move` and the `claim_twice` transactional test), if an attacker calls `migrate_legacy_metadata<T>` for the type `T` *before* the team's `finalize_registration` executes, the slot is permanently occupied by the attacker-triggered legacy `Currency<T>` (with `RegulatedState::Unknown`/`SupplyState::Unknown`, no `treasury_cap_id`). Every subsequent call to `finalize_registration<T>` will then abort at `derived_object::claim`, and there is no other public function that accepts `Receiving<Currency<T>>` to recover or re-route the object.

### Impact Explanation
The OTW-created `Currency<T>` object becomes permanently stuck, owned by the `CoinRegistry`'s address (`object::sui_coin_registry_address()`), reachable only via `Receiving<Currency<T>>`, but every attempt to consume it aborts. This is a permanent, irrecoverable object lock/state corruption of the project's canonical coin-registry entry: the registry will forever show the attacker's degraded stub (`Unknown` regulated/supply state, no treasury cap linkage) instead of the legitimate, fully-configured `Currency<T>` (correct `treasury_cap_id`, `regulated`/`supply` state set via `make_regulated`/`make_supply_fixed`/`make_supply_burn_only`, and the `is_new_currency` marker). Note that this does **not** lock the `TreasuryCap<T>` itself (returned directly to the caller in the same transaction as `new_currency_with_otw`, independent of the `Currency` object) and does not enable unauthorized minting, so it does not by itself cause direct fund theft or supply-cap violation — the damage is confined to permanently corrupting/orphaning the on-chain metadata registry entry for that type. This is best characterized as harmful smart-contract behavior / permanent object lock, not a Critical (fund theft) impact.

### Likelihood Explanation
High likelihood for any project that (a) has already published a legacy `Coin<T>` via `coin::create_currency` (yielding a `CoinMetadata<T>`) and later wants to formally register via `new_currency_with_otw`/`finalize_registration`, or (b) is observed publishing an OTW-init transaction on a public mempool before its `finalize_registration` transaction lands — an attacker can race a `migrate_legacy_metadata<T>` call against the visible legacy `CoinMetadata<T>` object.

### Recommendation
Ensure `migrate_legacy_metadata` and `finalize_registration` compete safely for the derived slot — e.g., have `finalize_registration` (or a companion function) allow reclaiming/absorbing an existing `Unknown`-state legacy entry produced by `migrate_legacy_metadata` when a legitimate OTW `Currency<T>` arrives, or add a recovery/`update`-style path that lets the OTW-originated `Currency<T>` overwrite/merge into a pre-existing migrated stub rather than aborting unconditionally on `derived_object::claim`.

### Proof of Concept
1. Attacker (or anyone) observes a legacy `CoinMetadata<T>` object already exists on-chain for type `T` (frozen, shared, or otherwise readable).
2. Attacker calls `coin_registry::migrate_legacy_metadata<T>(registry, &legacy_metadata, ctx)` — this succeeds, calling `derived_object::claim(&mut registry.id, CurrencyKey<T>())` and sharing a `Currency<T>` with `Unknown` states.
3. The legitimate team publishes their package with `init` calling `new_currency_with_otw<T>`, then `finalize`, transferring their `Currency<T>` to the registry address.
4. Team (or anyone) calls `finalize_registration<T>(registry, receiving_currency, ctx)`.
5. `derived_object::claim(&mut registry.id, CurrencyKey<T>())` aborts because the slot is already occupied by the attacker's migrated `Currency<T>` from step 2, permanently stranding the OTW `Currency<T>` at the registry address with no recovery path.

/// Internal macro to keep implementation between build and test modes.
macro fun migrate_legacy_metadata_impl<$T>(
    $registry: &mut CoinRegistry,
    $legacy: &CoinMetadata<$T>,
): Currency<$T> {
    let registry = $registry;
    let legacy = $legacy;

    assert!(!registry.exists<$T>(), ECurrencyAlreadyRegistered);
    assert!(is_ascii_printable!(&legacy.get_symbol().to_string()), EInvalidSymbol);

    Currency<$T> {
        id: derived_object::claim(&mut registry.id, CurrencyKey<$T>()),
        decimals: legacy.get_decimals(),
        name: legacy.get_name(),
        symbol: legacy.get_symbol().to_string(),
        description: legacy.get_description(),
        icon_url: legacy
            .get_icon_url()
            .map!(|url| url.inner_url().to_string())
            .destroy_or!(b"".to_string()),
        supply: option::some(SupplyState::Unknown),
        regulated: RegulatedState::Unknown,
        treasury_cap_id: option::none(),
        metadata_cap_id: MetadataCapState::Unclaimed,
        extra_fields: vec_map::empty(),
    }
}
