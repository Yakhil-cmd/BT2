### Title
Unbounded `extraData` in Service-Chain Bridge Request Functions Causes Persistent Relay DoS — (File: `node/sc/bridge_manager.go`, `contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `contracts/service_chain/bridge/BridgeTransferERC20.sol`)

---

### Summary

The Kaia service-chain bridge's `requestKLAYTransfer` and `requestERC20Transfer` functions accept an unbounded `bytes _extraData` parameter. The off-chain relay (`node/sc/bridge_manager.go`) reads the emitted `RequestValueTransfer` event and constructs a `handleKLAYTransfer`/`handleERC20Transfer` transaction on the counterpart chain. The handle transaction carries four additional fixed-size ABI fields absent from the request transaction (`_requestTxHash`, `_from`, `_requestedNonce`, `_requestedBlockNumber`), adding ~128 bytes of calldata overhead. An attacker who crafts a request with `extraData` sized just below the source chain's `MaxTxDataSize = 128 KB` limit will produce a handle transaction that exceeds that same limit on the destination chain. The relay's `processingPendingRequestEvents()` re-queues the failed event and retries it indefinitely, permanently blocking all subsequent bridge transfers from being automatically relayed until an operator manually intervenes.

### Finding Description

**Source-chain request functions accept unbounded `extraData`:**

`requestKLAYTransfer` in `BridgeTransferKLAY.sol`:
```solidity
function requestKLAYTransfer(address _to, uint256 _value, bytes calldata _extraData) external payable {
``` [1](#0-0) 

`requestERC20Transfer` in `BridgeTransferERC20.sol`:
```solidity
function requestERC20Transfer(address _tokenAddress, address _to, uint256 _value, uint256 _feeLimit, bytes memory _extraData) public {
``` [2](#0-1) 

Neither function validates the length of `_extraData`. The emitted `RequestValueTransfer` event carries the raw bytes verbatim. [3](#0-2) 

**Calldata size asymmetry between request and handle transactions:**

The source-chain request calldata (ABI-encoded) is:
```
selector(4) + to(32) + value(32) + extraData_offset(32) + extraData_len(32) + extraData(N) = 132 + N bytes
```

The destination-chain handle calldata is:
```
selector(4) + requestTxHash(32) + from(32) + to(32) + value(32) + nonce(32) + blockNumber(32)
+ extraData_offset(32) + extraData_len(32) + extraData(N) = 260 + N bytes
