### Title
Git credentials are only ever approved into the credential cache and never revoked, allowing stale/compromised credentials to remain usable for up to an hour - (File: main.go)

### Summary
`git-sync`'s `StoreCredentials` function is the single code path used to hand credentials to git, regardless of source (`--credential`, `--askpass-url`, or the GitHub App token flow). It always calls `git credential approve` and never calls `git credential reject`, while the credential helper is globally configured to cache entries for a fixed duration. This mirrors the reported bug class of "privileges granted... cannot be revoked": once a credential is accepted into the cache, git-sync has no mechanism to invalidate it early.

### Finding Description
`SetupDefaultGitConfigs` configures the global git credential helper as an in-memory cache with a 3600-second timeout: [1](#0-0) 

Every credential source in git-sync funnels through `StoreCredentials`, which only performs `git credential approve`: [2](#0-1) 

This function is invoked from three places on every `refreshCreds` cycle: static `--credential` entries (including password-file based ones meant to support token rotation), the dynamic `--askpass-url` callback, and the GitHub App installation-token refresh: [3](#0-2) [4](#0-3) [5](#0-4) 

There is no corresponding `git credential reject` (or `credential-cache exit`) call anywhere in the codebase, so nothing ever removes a previously approved credential from the cache before the 3600-second timeout expires, and no distinction is made between fetching a *fresh* credential and merely *adding another* one — repeated approvals accumulate rather than replace.

### Impact Explanation
Because credentials are only ever appended/approved and never actively revoked:
- If `--askpass-url` starts returning invalid or empty credentials (e.g., an operator intentionally rotates/kills the auth service to cut off access, or a leaked token is detected and the URL is reconfigured to stop serving it), the previously cached, now-stale credential set via `git credential approve` remains usable by any subprocess/spawned git command against the matching URL for up to an hour, defeating the intended revocation.
- The `--credential`/`--password-file` "token rotation" comment implies operators expect that updating the password file (or backing token) immediately changes what git-sync uses, but the old value already cached under `credential.helper cache --timeout 3600` is still fed to git until the timeout lapses or the process restarts (which flushes the temp `GIT_CONFIG_GLOBAL` and, being an in-memory `credential-cache` daemon keyed by socket, may or may not persist depending on daemon lifecycle) — this creates a window of persistent, unauthorized use of a credential the operator believed was revoked.
- This does not grant new privileges to an external attacker directly reachable via git-sync's own attack surface (no untrusted input controls which credential is approved), so it is a lower-severity "stale credential persists past intended revocation" issue rather than a remote-exploitable one.

### Likelihood Explanation
This triggers under normal, expected operational conditions (any credential rotation or `--askpass-url` failover/GitHub App key rotation) — it does not require a malicious operator, leaked key, or mocked-only path. It's a deterministic behavior of the current `approve`-only design combined with the fixed cache timeout, not a hypothetical edge case.

### Recommendation
Add explicit revocation: call `git credential reject` (or restart the `git credential-cache` helper) whenever `refreshCreds` detects a credential has changed or the `--askpass-url`/token source fails, so stale credentials cannot linger in the cache past the point they are known to be invalid. Consider making the cache timeout configurable and shorter by default, and reject the previous credential entry before approving a new one for the same URL.

### Proof of Concept
1. Run `git-sync` with `--askpass-url` pointing at a service returning valid `username`/`password`.
2. On first `refreshCreds` cycle, `CallAskPassURL` → `StoreCredentials` → `git credential approve` caches the credential for 3600s via the `cache --timeout 3600` helper. [6](#0-5) 
3. Reconfigure or take down the askpass URL service (simulating credential revocation/rotation), so subsequent `CallAskPassURL` calls fail and return an error from `refreshCreds`. [7](#0-6) 
4. Because no `git credential reject` is ever issued, any git operation against the matching URL within the cache TTL still succeeds using the old, supposedly-revoked credential — observable by manually invoking `git credential fill` for that URL from within the container before the timeout expires.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

func (git *repoSync) CallAskPassURL(ctx context.Context) error {
	git.log.V(3).Info("calling auth URL to get credentials")

	var netClient = &http.Client{
		Timeout: time.Second * 1,
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	httpReq, err := http.NewRequestWithContext(ctx, http.MethodGet, git.authURL, nil)
	if err != nil {
		return fmt.Errorf("can't create auth request: %w", err)
	}
	resp, err := netClient.Do(httpReq)
	if err != nil {
		return fmt.Errorf("can't access auth URL: %w", err)
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusOK {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("auth URL returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("auth URL returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}
	authData, err := io.ReadAll(resp.Body)
	if err != nil {
		return fmt.Errorf("can't read auth response: %w", err)
	}

	username := ""
	password := ""
	for line := range strings.SplitSeq(string(authData), "\n") {
		keyValues := strings.SplitN(line, "=", 2)
		if len(keyValues) != 2 {
			continue
		}
		switch keyValues[0] {
		case "username":
			username = keyValues[1]
		case "password":
			password = keyValues[1]
		}
	}

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil
}

// RefreshGitHubAppToken generates a new installation token for a GitHub app
// and stores it as a credential.
func (git *repoSync) RefreshGitHubAppToken(ctx context.Context, githubBaseURL, privateKey, privateKeyFile, clientID string, appID, installationID int) error {
	git.log.V(3).Info("refreshing GitHub app token")

	privateKeyBytes := []byte(privateKey)
	if privateKey == "" {
		b, err := os.ReadFile(privateKeyFile)
		if err != nil {
			git.log.Error(err, "can't read private key file", "file", privateKeyFile)
			os.Exit(1)
		}

		privateKeyBytes = b
	}

	pkey, err := jwt.ParseRSAPrivateKeyFromPEM(privateKeyBytes)
	if err != nil {
		return err
	}

	now := time.Now()

	// either client ID or app ID can be used when minting JWTs
	issuer := clientID
	if issuer == "" {
		issuer = strconv.Itoa(appID)
	}

	claims := jwt.RegisteredClaims{
		Issuer:    issuer,
		IssuedAt:  jwt.NewNumericDate(now),
		ExpiresAt: jwt.NewNumericDate(now.Add(10 * time.Minute)),
	}

	jwt, err := jwt.NewWithClaims(jwt.SigningMethodRS256, claims).SignedString(pkey)
	if err != nil {
		return err
	}

	url, err := url.JoinPath(githubBaseURL, fmt.Sprintf("app/installations/%d/access_tokens", installationID))
	if err != nil {
		return err
	}

	req, err := http.NewRequestWithContext(ctx, http.MethodPost, url, nil)
	if err != nil {
		return err
	}

	req.Header.Set("Authorization", "Bearer "+jwt)
	req.Header.Set("Accept", "application/vnd.github+json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusCreated {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("GitHub app installation endpoint returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("GitHub app installation endpoint returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}

	tokenResponse := struct {
		Token     string    `json:"token"`
		ExpiresAt time.Time `json:"expires_at"`
	}{}
	if err := json.NewDecoder(resp.Body).Decode(&tokenResponse); err != nil {
		return err
	}

	git.appTokenExpiry = tokenResponse.ExpiresAt

	// username must be non-empty
	username := "-"
	password := tokenResponse.Token

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil
}
