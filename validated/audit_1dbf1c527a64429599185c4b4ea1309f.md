### Title
Silent block-rule bypass via missing `field` in explicit `conditions` frontmatter - (File: `plugins/hookify/core/config_loader.py`)

### Summary
`Rule.from_dict` and `Condition.from_dict` in `plugins/hookify/core/config_loader.py` accept explicit `conditions` entries without requiring a `field` key, silently defaulting it to `''`. Unlike the legacy `pattern` path, which always infers a valid field from `event`, a `conditions`-based rule with a missing `field` becomes permanently unmatchable, silently disabling an `action: block` rule while appearing syntactically valid.

### Finding Description
`Rule.from_dict` [1](#0-0)  branches on whether `conditions` is present in the frontmatter. When present as a list, each item is passed to `Condition.from_dict`, which defaults `field` to `''` if absent [2](#0-1) . In contrast, the legacy `pattern` path always computes a concrete, non-empty `field` from `event` (`command`/`new_text`/`content`) [3](#0-2) , so it can never produce an inert condition.

At enforcement time, `RuleEngine._rule_matches` requires all conditions to match, and `_check_condition` calls `_extract_field(condition.field, ...)` [4](#0-3) . `_extract_field('', ...)` never matches any of the explicit branches (`tool_input` keys, `reason`/`transcript`/`user_prompt`, or the per-tool `command`/`new_text`/`file_path` checks) [5](#0-4) , so it returns `None`. `_check_condition` then returns `False` whenever `field_value is None` [6](#0-5) , making the rule permanently non-matching regardless of `action: block`.

Because the simplistic hand-rolled YAML parser (`extract_frontmatter`) happily accepts list-of-dict items missing a `field:` sub-key (it only requires `operator:`/`pattern:` to be present) [7](#0-6) , a rule file generated by `/hookify rule creation` or shipped in a repo's `.claude/hookify.*.local.md` can look like a legitimate `action: block` rule (e.g. blocking `rm -rf` or `curl | sh`) but never actually fire. `load_rule_file`/`load_rules` do not validate that conditions resolve to a usable field, and errors are swallowed as warnings only for structurally invalid dicts, not for this silently-inert case [8](#0-7) .

### Impact Explanation
A rule author (human, or an LLM-driven `/hookify` generation flow, or a repo-shipped rule file from an untrusted contributor) can produce a `.claude/hookify.*.local.md` file that appears to enforce `action: block` on dangerous Bash commands or file edits, but the block never triggers because the `conditions` entries omit `field`. Any user relying on this rule for protection will have dangerous commands (e.g. `rm -rf`, destructive edits, `curl … | sh`) silently pass through the PreToolUse hook without the intended `permissionDecision: "deny"` [9](#0-8) , i.e. local command execution proceeds without the deny control the user believes is active.

### Likelihood Explanation
No privileged access is required — only the ability to author or ship a `.claude/hookify.*.local.md` file (via `/hookify rule creation`, LLM-generated frontmatter, or a repo-committed rule file). Omitting a `field:` key in a `conditions` list item is an easy, plausible mistake (or deliberate sabotage) since the parser and `Condition.from_dict` never flag it as an error — the rule loads successfully and looks valid. This is fully deterministic and repeatable.

### Recommendation
In `Condition.from_dict`, reject or raise on a missing/empty `field` instead of defaulting to `''`, and in `Rule.from_dict`/`load_rule_file`, validate that every condition resolves to a known field before treating the rule as loaded (log and skip/fail-loud on invalid rules rather than silently loading a rule that can never match). Additionally, make `_extract_field` explicitly return `None`/error for unknown fields and have `load_rules` warn prominently when an `action: block` rule has zero matchable conditions.

### Proof of Concept
Unit test to add to `plugins/hookify` test suite:
```python
from hookify.core.config_loader import extract_frontmatter, Rule
from hookify.core.rule_engine import RuleEngine

content = """---
name: block-rm-rf
enabled: true
event: bash
action: block
conditions:
  - operator: regex_match
    pattern: "rm -rf"
---
Block dangerous deletion.
"""

fm, msg = extract_frontmatter(content)
rule = Rule.from_dict(fm, msg)

engine = RuleEngine()
result = engine.evaluate_rules([rule], {
    "hook_event_name": "PreToolUse",
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /important-data"}
})

# Expected (intended policy): result should deny the command
assert result.get("hookSpecificOutput", {}).get("permissionDecision") == "deny"
# Actual observed behavior: result == {} (rule silently never matches)
```
Expected assertion failure demonstrates that the `action: block` rule is silently inert due to the missing `field`, confirming the block-rule evasion via legacy-vs-explicit condition parsing divergence.

    @classmethod
    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""
        # Handle both simple pattern and complex conditions
        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:
            cond_list = frontmatter['conditions']
            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event
            event = frontmatter.get('event', 'all')
            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:
                field = 'content'

            conditions = [Condition(
                field=field,
                operator='regex_match',
                pattern=simple_pattern
            )]

        return cls(
            name=frontmatter.get('name', 'unnamed'),
            enabled=frontmatter.get('enabled', True),
            event=frontmatter.get('event', 'all'),
            pattern=simple_pattern,
            conditions=conditions,
            action=frontmatter.get('action', 'warn'),
            tool_matcher=frontmatter.get('tool_matcher'),
            message=message.strip()
        )

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules

    def _matches_tool(self, matcher: str, tool_name: str) -> bool:
        """Check if tool_name matches the matcher pattern.

        Args:
            matcher: Pattern like "Bash", "Edit|Write", "*"
            tool_name: Actual tool name

        Returns:
            True if matches
        """
        if matcher == '*':
            return True

        # Split on | for OR matching
        patterns = matcher.split('|')
        return tool_name in patterns

    def _check_condition(self, condition: Condition, tool_name: str,
                        tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> bool:
        """Check if a single condition matches.

        Args:
            condition: Condition to check
            tool_name: Tool being used
            tool_input: Tool input dict
            input_data: Full hook input data (for Stop events, etc.)

        Returns:
            True if condition matches
        """
        # Extract the field value to check
        field_value = self._extract_field(condition.field, tool_name, tool_input, input_data)
        if field_value is None:
            return False

        # Apply operator
        operator = condition.operator
        pattern = condition.pattern

        if operator == 'regex_match':
            return self._regex_match(pattern, field_value)
