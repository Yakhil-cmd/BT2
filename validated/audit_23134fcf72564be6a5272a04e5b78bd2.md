### Title
ssh_config directive injection via unsanitized `SSHUser` from codespace RPC response - ([File: pkg/cmd/codespace/ssh.go])

### Summary
`App.printOpenSSHConfig` takes `result.user` (the `User` field from the codespace's own `StartSSHServer` RPC response, controlled by whatever devcontainer image/agent the codespace runs) and inserts it verbatim into a `text/template`-rendered OpenSSH config block via `{{.SSHUser}}` with no validation or escaping. Since `text/template` performs no OpenSSH-config escaping (it's designed for HTML/text substitution, not config-file safety), a malicious remote agent can return a `User` value containing a newline to inject arbitrary additional `ssh_config` directives (e.g., a new `ProxyCommand`, `Match`, or `Include` line) into the block written to the user's `~/.ssh/config`-included file.

### Finding Description
In `pkg/cmd/codespace/ssh.go`, `printOpenSSHConfig` calls `invoker.StartSSHServer(ctx)` and stores the returned username directly: `_, result.user, err = invoker.StartSSHServer(ctx)` [1](#0-0) . This value flows unmodified into `codespaceSSHConfig.SSHUser` [2](#0-1)  and is rendered by a `text/template` whose `Host` stanza places `{{.SSHUser}}` on its own `User` line, with subsequent lines for `ProxyCommand`, `UserKnownHostsFile`, `StrictHostKeyChecking`, etc. [3](#0-2) . `text/template` does not perform any output-context escaping (unlike `html/template`), so any newline characters or arbitrary text in `SSHUser` are emitted byte-for-byte into the generated config text via `t.Execute(a.io.Out, conf)` [4](#0-3) .

The `StartSSHServer` RPC response is answered by the codespace's own SSH server host service, which is code running inside the codespace container defined by the (attacker-controlled) devcontainer image/config. This makes `User` a value fully controlled by whoever authored the devcontainer, i.e., an attacker who gets a victim to open/create a codespace from a malicious repo. If that value contains `\n    ProxyCommand /bin/sh -c 'touch pwned'` (or similar), and the victim redirects this output into their SSH config (as instructed by the tool's own documented usage: `gh codespace ssh --config > ~/.ssh/codespaces` then included via `Include`), a subsequent plain `ssh` invocation to that host will execute the injected `ProxyCommand`.

There is no validation of `result.user`/`SSHUser` anywhere along this path — no character allowlist, no rejection of control characters, no escaping for OpenSSH config syntax.

### Impact Explanation
This allows arbitrary `ssh_config` directive injection, most critically a new/overriding `ProxyCommand`, which OpenSSH executes as a shell command whenever the user later runs plain `ssh <host>` (not just `gh cs ssh`) against the generated Host alias. That constitutes command execution on the victim's machine, triggered without the victim's awareness at config-generation time — matching a "command/code execution on the victim host" impact class.

### Likelihood Explanation
The precondition is that a victim runs `gh codespace ssh --config` (or `gh cs ssh --config`) against a codespace created from an attacker-authored devcontainer image, and later uses the redirected config with plain `ssh`. This is a documented, intended workflow (shown in the command's own `Example` text) [5](#0-4) , so it is a realistic usage pattern, but it does require the victim to actively opt into generating and trusting the OpenSSH config for a codespace whose devcontainer they do not control (e.g., opening a PR/fork's codespace). The RPC response format/whether the underlying protobuf `User` field is constrained by any schema-level character restriction could not be fully verified from the indexed files (the actual `.proto`/generated struct definitions for the `StartRemoteServerRequest`/response were not found in the indexed portion of `internal/codespaces/rpc`); if the field is a free-form protobuf `string`, no schema-level restriction would exist.

### Recommendation
Validate/sanitize `result.user` (and any other RPC-supplied string interpolated into the SSH config template) before rendering: reject or strip any character outside a safe username character set (e.g., `^[A-Za-z0-9_.-]+$`), and reject the codespace's config generation entirely (with an error) if the returned `User` does not match. Additionally, consider using `ssh_config`-aware quoting rather than raw template substitution for any RPC-sourced field embedded in the generated file.

### Proof of Concept
```go
// pkg/cmd/codespace/ssh_test.go (illustrative)
func TestPrintOpenSSHConfig_UserInjection(t *testing.T) {
    maliciousUser := "codespace\n\tProxyCommand /bin/sh -c 'touch /tmp/pwned'\n\t#"
    conf := struct {
        Name, EscapedRef, SSHUser, GHExec, AutomaticIdentityFilePath string
    }{
        Name: "test", EscapedRef: "main", SSHUser: maliciousUser,
        GHExec: "gh", AutomaticIdentityFilePath: "/home/u/.ssh/codespaces.auto",
    }
    tmpl := template.Must(template.New("ssh_config").Parse(heredoc.Doc(`
        Host cs.{{.Name}}.{{.EscapedRef}}
            User {{.SSHUser}}
            ProxyCommand {{.GHExec}} cs ssh -c {{.Name}} --stdio -- -i {{.AutomaticIdentityFilePath}}
    `)))
    var buf bytes.Buffer
    require.NoError(t, tmpl.Execute(&buf, conf))
    // Assert the rendered output contains a second, attacker-controlled ProxyCommand line
    // outside the original template's intended keys.
    lines := strings.Split(buf.String(), "\n")
    proxyCommandCount := 0
    for _, l := range lines {
        if strings.Contains(strings.TrimSpace(l), "ProxyCommand") {
            proxyCommandCount++
        }
    }
    require.Equal(t, 1, proxyCommandCount, "injected ProxyCommand line was added by malicious SSHUser value")
}
```
This test demonstrates that a crafted `SSHUser` value produces two `ProxyCommand` lines in the generated block (the legitimate one and the injected one), confirming the injection is reachable through unescaped template substitution. A full end-to-end reproduction would additionally stub `invoker.StartSSHServer` (via the `rpc.Invoker` interface) to return the malicious user string and verify the same injected content appears in `a.io.Out` from `printOpenSSHConfig`.
