Confirmed: `Repository.from_github_repo_name` performs a global lookup by `owner`/`name` parsed from `github_repo_name.downcase.split('/')` with no scoping to the organization used for signature verification [1](#0-0) , and `Repository#github_app` re-derives the GitHub App config from the row's own `owner` column rather than from whatever organization the webhook was verified against [2](#0-1) .

### Title
Webhook signature is verified against the organization inferred from `repository.owner.login`/`organization.login`, but the write target is resolved from the independent, unverified `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App (and thus which `webhook_secret`) is used to validate `X-Hub-Signature` by reading `repository_owner`, computed as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [3](#0-2) [4](#0-3) . Once the signature check passes, `Shipit::Webhooks.for_event(event)` dispatches the full, unfiltered payload to handlers such as `PushHandler`, which resolve the target stack purely from `payload.dig('repository', 'full_name')` via `Handler#stacks`/`#repository_name` [5](#0-4)  and `Repository.from_github_repo_name` [1](#0-0) . Nothing in the controller or handler enforces that the organization used to authenticate the signature is the same organization that owns the repository actually acted upon — an equality that is assumed but never checked, exactly as the `GasOracle` "assumed 18-decimal scale" bug assumed a relationship between two independently-scaled inputs without validating it.

### Finding Description
In Shipit's multi-organization GitHub App configuration (`Shipit.github(organization:)` / `github_app_config`), each organization can be provisioned with its own `webhook_secret` [6](#0-5) . The webhook signature check only proves "this HMAC was produced with organization X's secret" — it says nothing about which repository the payload's body claims to target. `Handler#repository_name` and `Repository.from_github_repo_name` never cross-check that the `full_name` owner matches the `repository_owner`/`organization.login` value that determined the verifying secret [7](#0-6) . `Repository#github_app` derives the GitHub App purely from the persisted `owner` column of the matched repository, independent of the webhook's asserted `repository_owner` [8](#0-7) .

Additionally, `verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for the resolved organization: `return true unless webhook_secret` [9](#0-8) . Combined with the unchecked `repository.full_name` field, any organization onboarded into a multi-tenant Shipit deployment without a configured `webhook_secret` becomes a completely unauthenticated ingress point whose payload can name an arbitrary `repository.full_name` belonging to a *different*, fully-secured organization, and `PushHandler#process` will happily call `stack.sync_github(expected_head_sha: params.after)` on that unrelated stack [10](#0-9) .

The binding that should hold as an equality but does not:
`organization authenticated by verify_signature (via repository_owner)` == `organization owning the repository resolved and mutated by the handler (via repository.full_name)`.

### Impact Explanation
An attacker who controls (or spoofs, in the no-secret-configured case) webhooks for one onboarded organization/repository can force `sync_github` to run against a stack belonging to a wholly different, unrelated repository/organization in the same Shipit instance — a cross-tenant, cross-repository write not authorized by the organization that was actually authenticated. This matches the "cross-repository writes" Critical-impact category defined in the rules.

### Likelihood Explanation
Exploitability depends on a deployment configuration where at least one onboarded organization has no `webhook_secret` set (or where an attacker otherwise controls a valid signer for organization A) — a legitimate, documented multi-organization setup path, not a hypothetical. I was not able to fully verify from the indexed files whether `docs/setup.md` mandates a `webhook_secret` for every organization or treats it as optional per-org; this is a caveat on likelihood that would need direct confirmation via a running Devin session against the full docs.

### Recommendation
In `WebhooksController#verify_signature` and `Handler#repository_name`/`#stacks`, enforce that the organization used to select the verifying `webhook_secret` matches the owner of the `repository.full_name` actually being acted upon (i.e., assert `repository_owner.downcase == repository_name.split('/').first`), rejecting the webhook with `422` on mismatch. Additionally, consider making `webhook_secret` mandatory for every configured organization so `verify_webhook_signature` cannot silently pass unauthenticated requests.

### Proof of Concept
1. Configure two organizations in `secrets.github`: `org-a` (no `webhook_secret` set) and `org-b` (a properly configured target with an existing `Repository`/`Stack`).
2. `Shipit.github(organization: 'org-a').verify_webhook_signature` returns `true` unconditionally per `return true unless webhook_secret` [11](#0-10) .
3. POST to `/webhooks` with header `X-Github-Event: push` and body `{"repository": {"owner": {"login": "org-a"}, "full_name": "org-b/target-repo"}, "ref": "refs/heads/main", "after": "<sha>"}`.
4. `repository_owner` resolves to `"org-a"`, so `verify_signature` uses `org-a`'s (absent) secret and passes unconditionally [4](#0-3) .
5. `PushHandler#stacks` resolves `Repository.from_github_repo_name("org-b/target-repo")` and calls `stack.sync_github` on `org-b`'s stack, despite the request never being authenticated by anything belonging to `org-b` [10](#0-9) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
