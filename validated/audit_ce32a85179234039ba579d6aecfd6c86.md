### Title
Git pathspec magic in repo-controlled filenames lets diff scope be excluded/broadened, bypassing security review - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`get_git_diff` and its helper `_diff_pathspec` build the `git diff -- <paths>` argument list directly from repo-relative filenames without disabling git's pathspec "magic" syntax (`--literal-pathspecs` / `core.literalPathspecs` / `:(literal)` prefixing). A file whose name is a valid git pathspec magic signature (e.g. beginning with `:!`, `:^`, or `:(exclude)`/`:(glob)`/`:(icase)`) is passed through unmodified and is interpreted by git as an exclude/glob directive rather than a literal filename.

### Finding Description
`_diff_pathspec` (gitutil.py:70-88) only guards against directory-escape: it `realpath`s both `cwd` and each candidate path and drops any relative result starting with `..`, so symlink/`.. `escapes outside the repo are correctly rejected [1](#0-0) . It performs no sanitization of the *content* of the resulting relative path string before splicing it after `--`.

`get_git_diff` then runs `git diff --no-color --no-ext-diff <base> [--unified=99999] -- <rel paths...>` via `GIT_CMD`, which never sets `--literal-pathspecs`, `GIT_LITERAL_PATHSPECS`, or `-c core.literalPathspecs=true` [2](#0-1) [3](#0-2) .

The `paths` fed into `get_git_diff` are review-set filenames derived straight from `git status --porcelain`/`git diff --name-only` output in `compute_v2_review_set` [4](#0-3) , i.e. arbitrary repo-controlled filenames — nothing prevents a filename in the tracked/untracked working tree from being, e.g., `:!secret.py`, `:(exclude)auth.py`, or `:(glob)**`. Git's pathspec parser treats any pathspec beginning with `:!`/`:^` (short exclude magic) or `:(...)` (long magic, `exclude`/`glob`/`icase`/`top`/`attr`) as a directive, not a literal path, unless literal-pathspec mode is forced.

Because `_diff_pathspec` returns these strings verbatim in the `--` pathspec list, an attacker who can place such a filename in the working tree (fully within the "repo-controlled file paths" attacker capability, e.g. via a crafted PR/commit or the agent creating a file at an attacker-suggested name) can:
- exclude another, legitimately-modified security-sensitive file from the diff scope (`:!auth.py` or `:(exclude)auth.py`) so it never appears in `diff_output`, causing `parse_diff_into_files` to omit it and the Stop-hook/commit-review pipeline to `_skip(6)`/`_skip(7)` (no diff / no source files) or simply never send that file's content to the reviewer [5](#0-4) ;
- or broaden matching via `:(glob)`/`:(icase)` magic so the pathspec's semantics diverge from the intended "diff exactly the touched files" scope.

This is a real scope-escape distinct from, and not caught by, the existing symlink/`..`-escape guard: the path never leaves the repo directory tree in the filesystem sense, but it escapes the intended *semantic* scope of "diff only this literal file."

### Impact Explanation
This breaks the invariant that git path scoping in the review pipeline must always resolve to the intended literal target files. A crafted filename can cause the security-review diff collection (Stop-hook and commit-review) to silently drop the very file that was modified from the reviewed diff, which is a logic-level bypass of a required security guard (the automated vulnerability review), matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state."

### Likelihood Explanation
No special privilege is required — only the ability to introduce a file with a specific name into the working tree, which is squarely within "repo-controlled file paths" (an attacker-influenced PR, checked-out branch, or agent-created file). The magic-prefix characters (`:`, `!`, `^`, `(`) are all valid in POSIX filenames, making this reliably reproducible whenever such a file is part of the changed/untracked set passed to `get_git_diff`.

### Recommendation
Force literal pathspec interpretation everywhere `get_git_diff`/`_diff_pathspec` build pathspec arguments: add `-c core.literalPathspecs=true` to `GIT_CMD` (or set `GIT_LITERAL_PATHSPECS=1` in the subprocess env), or prefix each generated pathspec with `:(literal)` in `_diff_pathspec`, so relative paths derived from real filenames can never be reinterpreted as exclude/glob/icase magic.

### Proof of Concept
Integration test plan:
1. Init a git repo, commit an initial file `auth.py` with `SECRET = 1`.
2. Create/modify two files in one turn: `auth.py` (real security-relevant change) and a second file literally named `:!auth.py` (or `:(exclude)auth.py`), both tracked/dirty.
3. Call `compute_v2_review_set`/`get_git_diff(repo, baseline_sha, paths=[<abs path to auth.py>, <abs path to ':!auth.py'>])`.
4. Assert expectation: diff output should contain the hunk for `auth.py`'s changes.
5. Actual (bug): because `_diff_pathspec` passes `:!auth.py` unmodified as a magic pathspec, `git diff -- auth.py ':!auth.py'` excludes `auth.py` from the result — `auth.py`'s changes are absent from `diff_output`, demonstrating the review-scope bypass. Fix verification: after adding `-c core.literalPathspecs=true` (or `:(literal)` prefixing), the same test should show `auth.py`'s diff hunk present regardless of the crafted filename.
