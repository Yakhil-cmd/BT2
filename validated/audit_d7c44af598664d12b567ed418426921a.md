### Title
Webhook signature check keys off `repository.owner.login` but handlers dispatch on `repository.full_name`, letting an attacker forge events for any tracked repository whose organization has no `webhook_secret` configured - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization config (and thus which `webhook_secret`) to validate the inbound signature against using `repository_owner`, taken from the payload's `repository.owner.login` (falling back to `organization.login`). The actual side effects of the request, however, are computed by the event handlers using a *different* field of the same attacker-controlled JSON body: `repository.full_name` (`Shipit::Webhooks::Handlers::Handler#repository_name` / `#stacks`). These two fields are never cross-validated, and `GithubApp#verify_webhook_signature` explicitly short-circuits to `true` when no `webhook_secret` is configured for the organization resolved from `repository_owner`.

### Finding Description
`app/controllers/shipit/webhooks_controller.rb` runs `verify_signature` before `create`: [1](#0-0) [2](#0-1) 

```
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```

`GithubApp#verify_webhook_signature` in `lib/shipit/github_app.rb` returns `true` unconditionally when the resolved organization has no `webhook_secret` set: [3](#0-2) 

The docs explicitly describe `webhook_secret` as optional/conditional ("If you've set a webhook secret during the App creating, you should copy it here"), so multi-org deployments where one organization has no secret configured are a documented, supported configuration, not a misuse of the engine.

Once past `verify_signature`, `WebhooksController#create` dispatches the *same raw JSON body* to handlers, which resolve the target repository from an entirely different field: [4](#0-3) 

```
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
```

Concrete handlers such as `PushHandler`, `StatusHandler`, and `CheckSuiteHandler` act on commits/stacks resolved this way: [5](#0-4) [6](#0-5) [7](#0-6) 

Because `repository.owner.login` (used for auth) and `repository.full_name` (used for authorization of side effects) are independent, attacker-controlled fields in the same unsigned/weakly-signed JSON, an unprivileged attacker can:
1. Set `repository.owner.login` (or `organization.login`) to an organization configured in Shipit that has **no** `webhook_secret` — verification passes unconditionally regardless of the (missing or bogus) `X-Hub-Signature`.
2. Set `repository.full_name` to any repository actually tracked by Shipit, belonging to a *different*, secured organization.
3. Send a forged `push`, `status`, or `check_suite` event; the handler resolves `stacks`/`Commit.where(sha: ...)` purely from `repository.full_name` and acts on it.

This breaks the binding "organization that authenticated == repository that is written."

### Impact Explanation
- Forged `status` events let the attacker call `Commit#create_status_from_github!` for arbitrary shas/states on a targeted stack. `Commit#add_status` then triggers `stack.schedule_merges` and, when the commit becomes `deployable?`, `schedule_continuous_delivery` enqueues `ContinuousDeliveryJob` (`app/models/shipit/commit.rb:165-169,281-287,383`). On a stack with continuous deployment enabled and CI-status-gated deploys, this can cause an **unauthorized deploy** — meeting the Critical bar.
- Forged `push` events enqueue `GithubSyncJob`, and forged `check_suite` events enqueue `RefreshCheckRunsJob`, both operating on the spoofed target repository's stacks — an authorization boundary crossed without any credential for that organization/repository.
- The prerequisite (some configured organization lacking `webhook_secret`) is explicitly documented as optional configuration, not a deployment misconfiguration outside scope.

### Likelihood Explanation
Requires: (a) Shipit configured for at least one organization without a `webhook_secret` (documented-supported setup), and (b) the target repository/stack already tracked by Shipit under a different organization. No credentials, session, or GitHub write access are needed — only a raw unauthenticated HTTP POST to the public `/webhooks` endpoint with a crafted JSON body and mismatched owner/full_name fields.

### Recommendation
Cross-validate that `repository.owner.login` (or `organization.login`) used to select the verifying `webhook_secret` matches the owner segment of `repository.full_name` used by the handlers, rejecting the request on mismatch. Additionally, consider making `webhook_secret` mandatory (fail closed) rather than defaulting `verify_webhook_signature` to `true` when absent.

### Proof of Concept
1. Configure Shipit with two orgs: `unsecured-org` (no `webhook_secret`) and `secured-org` (has `webhook_secret`, `secured-org/target-repo` tracked as a stack).
2. POST to `/webhooks` with header `X-Github-Event: status` and no valid `X-Hub-Signature`, body:
```json
{
  "repository": { "owner": { "login": "unsecured-org" }, "full_name": "secured-org/target-repo" },
  "sha": "<commit-sha-of-target-stack>",
  "state": "success",
  "context": "ci/forged"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "unsecured-org")`, whose `verify_webhook_signature` returns `true` (no secret configured) regardless of signature.
4. `StatusHandler` resolves the commit via `Commit.where(sha:)` (stack derived from `secured-org/target-repo`) and creates a forged successful status, potentially triggering `schedule_continuous_delivery` and an unauthorized deploy on `secured-org/target-repo`.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
