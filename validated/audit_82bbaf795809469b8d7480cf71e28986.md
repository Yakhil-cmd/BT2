### Title
Missing zero-address check on `creator` in `initialize_with_permission` permanently freezes creator fees via `collect_creator_fee_permissionless` - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`InitializeWithPermission::creator` is an `UncheckedAccount` supplied by the pool-creating `payer` and is never validated to be non-zero before being persisted as `pool_state.pool_creator`. Since `collect_creator_fee_permissionless` lets *anyone* trigger the payout of accumulated creator fees to an ATA owned by whatever address is stored in `pool_creator`, a pool created with `creator = Pubkey::default()` (the all-zero System Program address) will have all of its accumulated creator fees permanently and irretrievably sent to an ATA that nobody controls, exactly mirroring the `$passThrough` zero-address burn pattern in the referenced report.

### Finding Description
In `initialize_with_permission.rs`, the `creator` field is declared as an unchecked, non-signing account: [1](#0-0) 

It is copied verbatim into pool state with no validation: [2](#0-1) 

`PoolState::initialize` simply stores whatever `Pubkey` was passed, including `Pubkey::default()` (all-zero, the System Program ID): [3](#0-2) 

Later, `collect_creator_fee_permissionless` is explicitly designed to be callable by *any* unprivileged account; it derives `creator_token_0`/`creator_token_1` as ATAs owned by whatever `pool_state.pool_creator` holds, and transfers the full accumulated creator fees there: [4](#0-3) [5](#0-4) 

If `creator == Pubkey::default()` (or any other un-owned/undesired address), any caller can create the associated token account for the zero address and permanently sweep the pool's accumulated creator fees into it — funds that can never be recovered because there is no private key for the System Program address. This is the same root cause as the reported issue: an address field that is never checked for the zero/degenerate value, combined with a permissionless "sweep" function that anyone can call to move funds to that address.

Note: the regular `initialize.rs` path uses `creator: Signer<'info>`, so the zero-address pubkey (owned by the System Program) cannot realistically sign a transaction there. The vulnerable path is specific to `initialize_with_permission`, where `creator` does not need to sign.

### Impact Explanation
This permanently freezes/burns the pool's creator fees (a portion of every swap's fee, accrued on every trade routed through the pool) with no way to ever recover them, since the destination address has no controlling keypair. Depending on pool activity and the `creator_fee_rate`, this can amount to significant ongoing loss of protocol/creator fee revenue for the lifetime of the pool, since `pool_creator` cannot be changed after `initialize`.

### Likelihood Explanation
Reaching `initialize_with_permission` requires the caller to already hold a `Permission` PDA (granted by the admin via `create_permission_pda`), but once granted, that authorized "pool creator" is an otherwise unprivileged actor who fully controls the `creator` argument passed to the instruction — it is not tied to their own signing key. A permissioned integrator/pool-creator could pass `Pubkey::default()` by mistake (e.g., an uninitialized variable in off-chain tooling), or a malicious permissioned actor could intentionally do so to grief later fee accrual, since neither `initialize_with_permission` nor `PoolState::initialize` enforces `creator != Pubkey::default()`.

### Recommendation
Add an explicit non-zero check on `creator` in `InitializeWithPermission`, e.g.:
```rust
require_keys_neq!(creator.key(), Pubkey::default(), ErrorCode::InvalidCreator);
```
either as an Anchor `constraint` on the `creator` account or at the top of `initialize_with_permission`, before `pool_state.initialize(...)` is called with it.

### Proof of Concept
1. An address holding a valid `Permission` PDA calls `initialize_with_permission`, passing `creator = Pubkey::default()` (System Program ID) as the `creator` account. No constraint rejects this; `pool_state.pool_creator` is set to `Pubkey::default()`.
2. Swaps occur on the pool, accruing `creator_fees_token_0`/`creator_fees_token_1` in `pool_state` per `update_fees`: [6](#0-5) 
3. Any unprivileged account calls `collect_creator_fee_permissionless`, paying to create the `creator_token_0`/`creator_token_1` ATAs owned by `Pubkey::default()`, and the instruction transfers all accumulated creator fees to those ATAs.
4. Because `Pubkey::default()` is the System Program address (no corresponding private key), the tokens in those ATAs are permanently unrecoverable — equivalent to the `passThroughTokens` burn scenario in the referenced report.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
