### Title
Webhook Signature Verified Against an Attacker-Chosen Organization While the Repository Actually Mutated Is Read From an Unverified Field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects *which* GitHub App/`webhook_secret` to validate the request against based on `repository_owner`, a value taken straight from the unauthenticated JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). The event handlers that actually act on the payload (e.g. `PushHandler`, `StatusHandler`, `CheckSuiteHandler`, the `PullRequest::*` handlers) instead resolve the target `Repository`/`Stack` from a separate field, `payload.dig('repository', 'full_name')` (via `Handler#repository_name`). Nothing ties these two lookups together, so the organization whose secret is used to "authenticate" the request is not guaranteed to be the organization that owns the repository being written to. ### Finding Description
This is the same bug class as the reported "mismatched array lengths" issue: two related values that should be checked for consistency are processed independently, with no equality check binding them together.

- `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(signature, request.raw_post)`. [4](#0-3) 
- `repository_owner` is read straight out of the untrusted JSON body: [5](#0-4) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's `webhook_secret` is not configured (it is documented as *optional* in `docs/setup.md`), i.e. any HMAC (or none at all) is accepted: [6](#0-5) 
- Once "verified", `WebhooksController#create` dispatches the *entire raw payload* to the event handlers, which independently resolve which `Repository`/`Stack` to mutate using `payload.dig('repository', 'full_name')`: [7](#0-6) [8](#0-7) 

In a multi-organization Shipit install (a documented, supported configuration — `secrets.github` keyed by organization, see `docs/setup.md` "Using Multiple GitHub Applications" and `lib/shipit.rb#github_app_config`), `Shipit.github(organization:)` resolves a distinct `GitHubApp`/secret per organization key present in `secrets.github`. Nothing requires `repository.owner.login` (used only to pick the verifying secret) to equal the owner encoded in `repository.full_name` (used only to pick the repository actually mutated). An attacker can therefore submit a single POST to `/webhooks` where:
- `repository.owner.login` (and/or `organization.login`) names an organization entry that has no `webhook_secret` configured, causing `verify_webhook_signature` to return `true` for *any* signature header (or even none), and
- `repository.full_name` names a repository belonging to a *different*, "protected" organization actually managed by the Shipit instance.

Because the handlers never re-check that the org used for verification matches the org of the repository they mutate, the forged request is processed as if it were a legitimate, signed GitHub webhook for the target repository/stack.

### Impact Explanation
This breaks the trust binding "organization that authenticated == repository that is written," letting an unauthenticated network attacker drive Shipit's webhook-triggered state machine for any stack in the instance as long as *any one* configured organization lacks a `webhook_secret`:
- `PushHandler` can trigger `stack.sync_github(expected_head_sha: ...)` on arbitrary tracked branches/stacks.
- `StatusHandler`/`CheckSuiteHandler` can inject fabricated commit statuses or trigger check-run refreshes that gate deploy safety checks.
- `PullRequest::*` handlers can provision/deprovision review stacks, capture labels, or drive merge-queue behavior for repositories the attacker does not control.

Depending on the exact handler reached, this can cause unauthorized deploy/rollback triggers or corrupted deploy-safety signals for repositories the attacker has no legitimate access to — a cross-repository write / unauthorized-deploy class impact, without requiring any session, API token, or knowledge of any organization's real webhook secret.

### Likelihood Explanation
Requires: (1) the Shipit instance is configured with multiple GitHub organizations (a documented feature), and (2) at least one configured organization has no `webhook_secret` set (webhook secret is explicitly documented as optional). Given that, exploitation requires only a single unauthenticated HTTP POST with a crafted JSON body — no credentials, tokens, or prior access needed. Likelihood is tied to operator configuration choices rather than attacker sophistication, so it is conditional but realistic in supported multi-tenant deployments.

### Recommendation
- Require `webhook_secret` to be present for every configured GitHub organization (fail closed instead of `return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`).
- After signature verification, assert that the organization used to select the verifying secret (`repository_owner`) matches the owner encoded in `payload.dig('repository', 'full_name')` before dispatching to handlers, rejecting the request otherwise.

### Proof of Concept
Given a Shipit instance configured with two organizations in `secrets.github` — `OrgA` (no `webhook_secret` set) and `OrgB` (has `webhook_secret` set, owns a tracked repository/stack):

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=0000000000000000000000000000000000000000   # arbitrary/garbage

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "OrgA" },
    "full_name": "OrgB/protected-repo"
  }
}
```

- `repository_owner` resolves to `"OrgA"` → `Shipit.github(organization: "OrgA")` → `verify_webhook_signature` returns `true` immediately because `OrgA` has no `webhook_secret` (`lib/shipit/github_app.rb:77`).
- `head(422)` is skipped, request proceeds to `create`, and `PushHandler` resolves the target stack via `Repository.from_github_repo_name("OrgB/protected-repo")`, triggering `stack.sync_github` for `OrgB`'s stack — without ever presenting a valid signature for `OrgB`. # frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
