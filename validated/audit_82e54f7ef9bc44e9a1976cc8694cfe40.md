### Title
Stack-scoped API token can read merge/build status of any stack via CCMenu, bypassing stack authorization scope - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController` overrides the scope-checked `stack` accessor from `Shipit::Api::BaseController` with an unscoped lookup, breaking the binding: *the stack an `ApiClient` token is authorized to touch* == *the stack the request actually operates on*.

### Finding Description
`BaseController` centralizes stack access-scoping for all API controllers: [1](#0-0) 
`stacks` restricts the queryable set to `current_api_client.stack_id` when the `ApiClient` is scoped to a single stack, and `stack` resolves `params[:stack_id]` only within that restricted relation — this is exactly the "stack a token authorises" boundary.

`CCMenuController`, however, defines its own `stack` method that ignores this scoping entirely and resolves any stack directly from the global `Stack` relation: [2](#0-1) 

It still declares `require_permission :read, :stack`, which only checks that the token has the `read:stack` permission bit set — `ApiClient#check_permissions!` never looks at `stack_id`: [3](#0-2) 

So a token that is *scoped to stack A* (i.e., `ApiClient.stack_id == A.id`, intended to only ever see stack A) can be used with `params[:stack_id] = B` to fetch stack B's merge/build status through `GET /:stack_id.xml` (CCMenu/CCTray endpoint), which is authenticated only by `params[:token]`: [4](#0-3) 

The response leaks the target stack's name, merge status (including whether it is `locked`/`backlogged`), last build time/label, and its `webUrl`: [5](#0-4) 

Equality broken before vs. after: before the request, `token.stack ⊆ {A}`; the CCMenu endpoint's actual data access is `stack ∈ Stack.all`, i.e., the trust binding `token.authorized_stack == request.accessed_stack` fails for this one endpoint even though it holds for every other API controller that uses the base `stack`/`stacks` helpers (`StacksController`, `DeploysController`, etc., which call `stacks.from_param!`).

### Impact Explanation
This is an unauthenticated-relative-to-scope read of stack state (merge/build status, lock status, last deploy id/time, canonical stack URL) for any stack in the installation, using a token that was deliberately restricted to a single stack. This matches the High-severity category "unauthenticated read of stack state ... or deploy output" since the holder of a narrowly-scoped credential gains read access across all stacks/repositories managed by the Shipit instance, defeating the purpose of per-stack token scoping (e.g., handing a CI system or external dashboard a token limited to its own repository).

### Likelihood Explanation
Likelihood is high for anyone who already holds a stack-scoped `ApiClient` token (a routine, low-privilege credential meant to be handed to third-party integrations such as CCTray dashboards). The attack requires no code execution, no signature forgery, and no interaction with other users — only substituting a different `stack_id` path/query parameter in an otherwise normal, documented CCMenu request.

### Recommendation
Make `CCMenuController#stack` reuse the scoped `stacks`/`stack` helpers from `BaseController` instead of calling `Stack.from_param!` directly, e.g. `@stack ||= stacks.from_param!(params[:stack_id])`, so the `current_api_client.stack_id` restriction applies uniformly to this controller as it does elsewhere.

### Proof of Concept
1. As an admin, create an `ApiClient` with `permissions: ['read:stack']` and `stack_id` set to Stack A's id (a token meant only for Stack A's CI dashboard). Obtain its `authentication_token`.
2. As the holder of that token (no other privilege), issue: `GET /:token_stack_id_agnostic_path` — concretely `GET /api/ccmenu/<stack_B_param>.xml?token=<the_stack_A_scoped_token>` (route mounted via `CCMenuController#show`, using `params[:stack_id]` for Stack B and `params[:token]` for authentication, per `authenticate_api_client` in `ccmenu_controller.rb:33-36`).
3. Observe the response renders Stack B's `lastBuildStatus`, `lastBuildTime`, `lastBuildLabel`, and `webUrl` via `app/views/shipit/ccmenu/project.xml.builder`, despite the token being scoped only to Stack A — confirming the scope bypass.
