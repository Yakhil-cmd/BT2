### Title
Webhook Signature Verification Silently Bypassed for Organizations Without a `webhook_secret`, Enabling Forged `membership` Events to Grant Unauthorized Access - ([File: lib/shipit/github_app.rb], [File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the org's `webhook_secret` is blank, and `WebhooksController` selects which org's app (and therefore secret) to verify against using an attacker-controlled field from the unauthenticated request body itself. Combined with the `membership` webhook handler writing directly to `Team`/`Membership` records that are later trusted by `User#authorized?` for application login authorization, this breaks the binding "the organization whose signature is verified" = "the organization whose data is trusted and acted upon," allowing an unauthenticated network attacker to forge a `membership` event and escalate into `Shipit.github_teams` authorization.

### Finding Description
The webhook signature check derives the signing key exclusively from data inside the very payload it is trying to authenticate: [2](#0-1) 

`repository_owner` is read straight from the JSON body (`params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`), and is used to pick the `GitHubApp` instance to verify against: [3](#0-2) 

That `GitHubApp` instance's verification method has a critical fallback: [4](#0-3) 

`return true unless webhook_secret` means that for *any* org configured without a `webhook_secret` (documented as "optional" in `docs/setup.md`), the HMAC check is skipped entirely — an attacker needs no secret, no valid `X-Hub-Signature` header, and no GitHub App credentials to have their POST body treated as an authentic GitHub webhook. [5](#0-4) 

The `membership` handler then writes directly to the database based on this unauthenticated payload, creating a `Team` (keyed by attacker-supplied `github_id`) and adding an arbitrary, attacker-chosen GitHub login as a member: [6](#0-5) 

Because the login used to look up/create the `User` is a bare unauthenticated login string with no possession-of-account proof (`User.find_or_create_by_login!(params.member.login)`), this binds an arbitrary account handle to a `Membership` row. Application authorization is later decided purely from this local state: [1](#0-0) [7](#0-6) 

There is no live re-verification against GitHub team membership at authorization time — it is a cached/local table poisoned by the webhook.

### Impact Explanation
This breaks the binding "GitHub organization whose signature is verified" ↔ "GitHub organization whose team/membership data is written and later trusted for authorization." An attacker who knows (or guesses) that any configured org lacks a `webhook_secret` can forge `membership` events to inject `Membership` rows tying any GitHub login to any `Shipit.github_teams`-eligible `Team`. If that login subsequently completes real GitHub OAuth (which only needs to prove the *login*, not team membership, since Shipit's own authorization check is local-only per `User#authorized?`), the attacker is granted access to the Shipit instance — an escalation into `Shipit.github_teams` authorization, matching the "High" impact bucket in this engine's rules.

### Likelihood Explanation
Likelihood depends on at least one configured GitHub App/org having no `webhook_secret` set — a state the project's own setup docs present as an accepted, optional configuration rather than a deviation from documented deployment. No credentials, sessions, or repository write access are required to send the forged POST to `/webhooks`; only knowledge (or a brute-force/observability guess) of which org(s) lack a secret and the target `Shipit.github_teams` handle/`github_id`, both discoverable via the public `docs/setup.md` conventions or app UI.

### Recommendation
- Fail closed instead of open: when `webhook_secret` is blank, reject webhooks (or restrict processing to non-privileged, informational events) rather than treating them as verified.
- Do not derive the verification key from attacker-controlled payload fields; verify against every configured secret (or a global default) and only accept the request if at least one genuinely matches.
- For `membership` events specifically, consider re-confirming org/team membership via a live GitHub API call (using the app's own installation token) before mutating `Team`/`Membership` records, rather than trusting the webhook body outright.

### Proof of Concept
1. Deploy Shipit with a multi-org config (`config/secrets.yml`) where at least one org, e.g. `victim-org`, has `webhook_secret:` left blank (a documented, supported configuration per `docs/setup.md`), and add `victim-org/some-team` to `Shipit.github_teams`.
2. As an unauthenticated attacker, `POST /webhooks` with header `X-Github-Event: membership` and no valid `X-Hub-Signature` (or an arbitrary bogus one), body:
```json
{
  "action": "added",
  "team": {"id": 999, "name": "some-team", "slug": "some-team", "url": "https://example.com"},
  "organization": {"login": "victim-org"},
  "member": {"login": "attacker-github-login"}
}
```
3. `verify_signature` resolves `GitHubApp` for `victim-org`, finds `webhook_secret` blank, and `verify_webhook_signature` returns `true` unconditionally — request proceeds.
4. `MembershipHandler#process` creates/finds `Team` with `github_id: 999`, `organization: "victim-org"`, and adds `attacker-github-login` as a member, creating a `Membership` row.
5. The attacker completes normal GitHub OAuth as `attacker-github-login` (owns that GitHub account); `User#authorized?` finds the pre-planted `Membership` and grants access to the Shipit application without ever legitimately belonging to `victim-org/some-team`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
