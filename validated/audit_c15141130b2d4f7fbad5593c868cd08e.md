This confirms a real bug-class match: the Ranger CVE is about mishandled exclude/resource-hierarchy policies causing a parent-level restriction bypass. The Polkadot SDK analog is `pallet-proxy`'s `InstanceFilter::is_superset`/`filter` lattice — a "superset" `ProxyType` must admit every call its declared "subset" admits, otherwise a restricted proxy can grant itself a more powerful proxy type and escalate. This exact bug class was already found and fixed for `asset-hub-westend`'s `NonTransfer`/`Governance` pair (PR #12769) and `staking-async-parachain`'s `ForeignAssets`/`PoolAssets` (PR #12922). ### Title
`ProxyType::NonTransfer` falsely declares itself a superset of `ProxyType::Auction`, letting a `NonTransfer` proxy escalate to call `Registrar::swap`, which its own filter explicitly excludes - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
The Apache Ranger CVE (`GHSA-22v7-w6c5-v4rr`) is a case where a resource-level **exclude** entry is mishandled so that a broader/parent authorization silently re-admits access that should have been denied. The exact analog exists in `pallet-proxy`'s `InstanceFilter` lattice on several Polkadot SDK relay-chain/parachain runtimes: `ProxyType::NonTransfer.filter()` explicitly *excludes* `paras_registrar::Call::swap` (commented "Specifically omitting Registrar `swap`"), yet `ProxyType::NonTransfer.is_superset()` unconditionally claims to be a superset of every other `ProxyType`, including `ProxyType::Auction`, whose `filter()` admits `RuntimeCall::Registrar(..)` with no restriction (i.e. it does admit `swap`). Because `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` purely via `is_superset` (not `filter`), a delegate holding only a `NonTransfer` proxy can add itself an `Auction` sub-proxy and then invoke the excluded `Registrar::swap` on behalf of the real account.

This is the identical bug class already found and fixed by Parity in this same repository for two other runtimes:
- `asset-hub-westend`: `NonTransfer` falsely superset of `Governance` (issue #12724, fixed by PR referenced in `prdoc/pr_12769.prdoc`) [1](#0-0) [2](#0-1) 
- `staking-async-parachain`: `NonTransfer` deny-list omitting `ForeignAssets`/`PoolAssets` (fixed by `prdoc/pr_12922.prdoc`) [3](#0-2) 

The same `is_superset`/`filter` mismatch, however, remains present and unpatched for the `NonTransfer` vs. `Auction` pair in `polkadot/runtime/westend`, `polkadot/runtime/rococo`, and `substrate/frame/staking-async/runtimes/rc`.

### Finding Description
`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` solely on `def.proxy_type.is_superset(proxy_type)`, not on `filter`: [4](#0-3) 

In `polkadot/runtime/westend/src/lib.rs`, `NonTransfer`'s filter admits `Registrar::register`, `Registrar::deregister`, `Registrar::reserve`, but explicitly *omits* `Registrar::swap`: [5](#0-4) 

`Auction`'s filter admits the entire `Registrar` call family unconditionally (which includes `swap`): [6](#0-5) 

Yet `is_superset` declares `NonTransfer` a superset of every other `ProxyType`, including `Auction`: [7](#0-6) 

This means a `NonTransfer` delegate can call `Proxy::add_proxy(delegator, ProxyType::Auction, ...)` (allowed because `NonTransfer.is_superset(Auction) == true`), then call `Proxy::proxy(delegator, None, Registrar::swap{...})` through the new `Auction` proxy, reaching a call that the delegator's original `NonTransfer` grant was specifically designed to deny. The identical gap exists in `polkadot/runtime/rococo/src/lib.rs` (lines 960–1007) and `substrate/frame/staking-async/runtimes/rc/src/lib.rs` (lines 1356–1418), all sharing the same `is_superset` pattern `(ProxyType::NonTransfer, _) => true`.

### Impact Explanation
`Registrar::swap` requires the caller to satisfy `ensure_root_para_or_owner`, i.e. Root, the para's owner, or the para itself: [8](#0-7) 

so the attack does not grant Root privilege; it grants a bounded but real privilege escalation strictly beyond what the delegator authorized. `swap` mutates the para's on-chain lifecycle, its lease-holding/parathread status, and switches "auction information and the auction deposit": [9](#0-8) 

A delegator who explicitly restricted a delegate to `NonTransfer` (precisely to keep `swap` out of reach) has that restriction silently defeated — an unauthorized-dispatch/access-restriction-bypass matching the Ranger analog, scoped to accounts that own a `ParaId` and use `pallet-proxy` delegation on these runtimes.

### Likelihood Explanation
The precondition is narrow (delegator must own a `ParaId` and have granted a `NonTransfer` proxy), and the same class of bug in this repo's own `asset-hub-westend`/`staking-async-parachain` runtimes was treated as bounty-worthy and patched (`prdoc/pr_12769.prdoc`, `prdoc/pr_12922.prdoc`), confirming Parity's own severity assessment of this bug class. No privileged role or governance action is needed by the attacker — only prior possession of a `NonTransfer` proxy grant, which is a standard, commonly delegated proxy type.

### Recommendation
Fix `ProxyType::is_superset` on `polkadot/runtime/westend`, `polkadot/runtime/rococo`, and `substrate/frame/staking-async/runtimes/rc` the same way it was fixed for `asset-hub-westend`'s `NonTransfer`/`Governance` pair: either stop declaring `NonTransfer` a blanket superset of all other types, or extend `NonTransfer`'s `filter` to admit `Registrar::swap` (and any other calls admitted by declared "subset" types) so the lattice invariant `subset.filter(c) ⟹ superset.filter(c)` holds for every pair, and add the same kind of lattice regression test used in `asset-hub-westend-runtime`'s `tests.rs`.

### Proof of Concept
Reproduction follows the pattern of the existing regression test `non_transfer_proxy_is_not_a_superset_of_governance` in `asset-hub-westend`'s test suite, adapted to the unpatched pair: [10](#0-9) 

Equivalent assertion for `polkadot/runtime/westend`'s `ProxyType`:
1. `assert!(ProxyType::Auction.filter(&RuntimeCall::Registrar(paras_registrar::Call::swap{ id, other })))` → `true` (admitted by `Auction`).
2. `assert!(!ProxyType::NonTransfer.filter(&RuntimeCall::Registrar(paras_registrar::Call::swap{ id, other })))` → `true` (denied by `NonTransfer`, per the "Specifically omitting Registrar `swap`" comment).
3. `assert!(ProxyType::NonTransfer.is_superset(&ProxyType::Auction))` → currently returns `true`, which is the violated invariant — it should be `false` given (1) and (2).

This has not been executed against a live network; it is derived directly from the two `filter` implementations and the unconditional `is_superset` match arm shown above, mirroring the exact assertions Parity itself used to confirm and fix the analogous `asset-hub-westend` regression (issue #12724 / PR behind `prdoc/pr_12769.prdoc`). A full integration PoC would additionally dispatch `Proxy::add_proxy(delegator, ProxyType::Auction, 0)` from a `NonTransfer`-delegated signer, then `Proxy::proxy(..., Registrar::swap{...})`, and assert the call succeeds (via `ProxyExecuted{ result: Ok(()) }`) despite the delegator never granting `Auction`/`swap` access — following the same harness style as `pure_proxy_stash_can_delegate_to_staking_operator` in `asset-hub-westend`'s test file.
