### Title
Permanent market freeze via `i128` overflow in `scaled_to_original` during interest accrual before the borrow-index cap engages - (File: `common/src/rates/simulate.rs`)

### Summary
Analog to CVE-2016-1405 (crafted input → process crash → denial of service): a market that grows large enough in scaled-share × index terms hits an `i128` overflow panic inside `accrue_step` — which every mutating pool entrypoint runs first via `global_sync` — before `update_borrow_index`'s `MAX_BORROW_INDEX_RAY` ceiling can clamp growth. From that point on, every verb on the market reverts, permanently freezing all supplied funds, blocking repayments, withdrawals, and liquidations.

### Finding Description
Every market mutation runs `global_sync`, which loops `accrue_chunk` over `MAX_COMPOUND_DELTA_MS`-sized windows [1](#0-0) . Each chunk calls `accrue_step`, which computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` before the index cap is applied [2](#0-1) . `scaled_to_original` performs `mul_div` on `Ray` values; the underlying `mul_div_*` panics with `MathOverflow` when the `i128` result does not fit [3](#0-2) . `update_borrow_index` multiplies before it clamps to `MAX_BORROW_INDEX_RAY`, so the value-space product `borrowed × new_borrow_index` can exceed `i128::MAX` while `new_borrow_index` is still below the cap [4](#0-3) .

The repo's own harness test confirms this: on a large market at ~98% utilization, `update_indexes` eventually fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and afterwards `withdraw` and `repay` revert with the same error because every verb accrues first [5](#0-4) .

### Impact Explanation
Permanent freezing of funds for an entire market. Once `borrowed × borrow_index` (or `supplied × supply_index`) overflows `i128`, `global_sync` panics on every subsequent call, so `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, `claim_revenue`, and `update_indexes` all revert. Suppliers can never exit; the borrower's collateral is locked; bad debt cannot be processed; the market is dead.

### Likelihood Explanation
Reachable by a single unprivileged address through normal `supply`/`borrow` calls, provided the market reaches a very large scale (`scaled` shares near `i128::MAX` divided by the index, i.e. roughly a billion tokens at 18 decimals in the test's reproduction) and sustained high utilization for an extended period so the index compounds toward the cliff. The cliff occurs *before* the `MAX_BORROW_INDEX_RAY` cap, so the cap cannot save the market. The capital requirement and long accrual horizon make exploitation expensive rather than impossible; no privileged action, oracle manipulation, or governance step is needed — the test constructs it purely via `supply_raw`, `borrow_raw`, and `update_indexes`.

### Recommendation
Saturate or clamp rather than panic at the value layer inside accrual. Concretely: in `accrue_step` (and `Cache` readouts), use `mul_div_floor_saturating` for `borrowed_original`/`supplied_original` or cap `borrowed`/`supplied` scaled shares at `i128::MAX / MAX_BORROW_INDEX_RAY` at mint time (`calculate_scaled_supply`/`calculate_scaled_borrow` and market `max_cap`), so the index ceiling `MAX_BORROW_INDEX_RAY` is always reached before any `i128` value overflow. Alternatively, have `update_borrow_index` clamp the index *before* multiplying when `old_index > MAX / factor`.

### Proof of Concept
The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` already demonstrates the full path: an attacker creates a market on an 18-decimal asset, supplies ~10^9 tokens, borrows ~98% of it, and advances time; `try_update_indexes_for` returns `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw` and `repay` both revert with `MATH_OVERFLOW` [6](#0-5) .

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);

        .checked_mul(y)
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
