### Title
Sequential Bridge Event Processing Without Error Isolation Causes Permanent DoS on All Subsequent Value Transfers — (`node/sc/bridge_manager.go`)

---

### Summary

`processingPendingRequestEvents` in `BridgeInfo` processes pending cross-chain value transfer events sequentially. When `handleRequestValueTransferEvent` returns a permanent error for event at nonce N (e.g., `"can't get counterpart token from bridge"` for an ERC20/ERC721 transfer whose counterpart token is not registered on the destination bridge), the function re-queues the failing event together with all higher-nonce events and returns. Because the sorted queue always surfaces the lowest nonce first, the failing event permanently heads the queue on every subsequent tick, blocking all value transfers with nonces > N indefinitely.

---

### Finding Description

`processingPendingRequestEvents` (lines 239–260) pops up to `maxPendingNonceDiff/2 = 500` events from `pendingRequestEvent` (a nonce-sorted map) and iterates over them:

```go
for idx, ev := range ReadyEvent {
    if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
        continue
    }
    if err := bi.handleRequestValueTransferEvent(ev); err != nil {
        bi.AddRequestValueTransferEvents(ReadyEvent[idx:])   // re-queues failing + all subsequent
        logger.Error(...)
        return
    }
}
``` [1](#0-0) 

`handleRequestValueTransferEvent` (lines 292–360) contains a permanent failure path for ERC20/ERC721 transfers: if the counterpart token is not registered on the destination bridge, it returns a hard error:

```go
if ctTokenAddr == (common.Address{}) {
    return errors.New("can't get counterpart token from bridge")
}
``` [2](#0-1) 

`AddRequestValueTransferEvents` re-inserts the failing event (nonce N) and all events with nonces N+1, N+2, … back into the sorted map: [3](#0-2) 

Because `GetPendingRequestEvents` uses `Pop` (which removes items in ascending nonce order), the failing event at nonce N is always the first item returned on the next invocation: [4](#0-3) 

The `loop()` goroutine calls `processingPendingRequestEvents` on every new event and every 1-second ticker tick: [5](#0-4) 

The result is an infinite cycle: pop → fail at N → re-queue [N, N+1, …] → return → repeat. No event with nonce > N is ever processed.

The `valueTransferRecovery` mechanism does not mitigate this: it re-adds unhandled events via `AddRequestValueTransferEvents`, but the failing event is already present in the queue (the `Exist` check prevents duplicate insertion), and subsequent events remain behind it. [6](#0-5) 

---

### Impact Explanation

All ERC20, ERC721, and KAIA value transfers with request nonces higher than the stuck event's nonce are permanently blocked. In mint-burn mode, the user's tokens have already been burned on the source chain; in lock-unlock mode, they are locked. The destination chain never mints or unlocks the corresponding assets. This constitutes a permanent loss of bridged assets for every user whose transfer nonce is greater than N.

---

### Likelihood Explanation

The trigger requires a token to be registered on the source bridge (`onlyRegisteredToken` enforced by `BridgeTransferERC20`) but its counterpart to be absent from the destination bridge's `registeredTokens` mapping. This arises from:

1. Bridge operator registers a token on the child bridge but omits the counterpart registration on the parent bridge (realistic misconfiguration).
2. Bridge operator deregisters a token from the destination bridge after `RequestValueTransfer` events are already queued.

Once a user submits a transfer for such a token (an unprivileged action, since the token is legitimately registered on the source side), the DoS is triggered. The `valueTransferRecovery` subsystem does not resolve it. [7](#0-6) 

---

### Recommendation

In `processingPendingRequestEvents`, isolate per-event errors instead of re-queuing the failing event at the head of the queue. Options:

1. **Skip-and-continue**: log the error, skip the failing event, and continue processing subsequent events. Re-queue only the skipped event for later retry (e.g., with a backoff counter).
2. **Dead-letter queue**: move permanently failing events to a separate dead-letter structure so they do not block the main processing loop.
3. **Pre-validation**: before queuing an event in `ProcessRequestEvent` / `AddRequestValueTransferEvents`, verify that the counterpart token is registered on the destination bridge and reject events that would permanently fail. [8](#0-7) 

---

### Proof of Concept

1. Bridge operator registers ERC20 token `T` on the child bridge but does **not** register its counterpart on the parent bridge.
2. Alice submits `requestERC20Transfer(T, bob, 100, ...)` on the child bridge → emits `RequestValueTransfer` with nonce 5.
3. Carol submits `requestKLAYTransfer(...)` → emits `RequestValueTransfer` with nonce 6.
4. The bridge operator's `processingPendingRequestEvents` pops events [5, 6].
5. Processing nonce 5: `handleRequestValueTransferEvent` calls `bi.counterpartBridge.RegisteredTokens(nil, T)` → returns `address(0)` → returns `errors.New("can't get counterpart token from bridge")`.
6. `AddRequestValueTransferEvents([ev5, ev6])` re-queues both; function returns.
7. On the next tick, the same failure repeats. Carol's KAIA transfer (nonce 6) is permanently blocked.
8. Alice's tokens are burned on the child chain; no tokens are ever minted on the parent chain. Carol's KAIA is locked; it is never released on the parent chain. [9](#0-8) [10](#0-9)

	ticker := time.NewTicker(time.Second)

	logger.Info("start bridge loop", "addr", bi.address.String(), "onChildChain", bi.onChildChain)

// processingPendingRequestEvents handles pending request value transfer events of the bridge.
func (bi *BridgeInfo) processingPendingRequestEvents() {
	ReadyEvent := bi.GetReadyRequestValueTransferEvents()
	if ReadyEvent == nil {
		return
	}

	logger.Trace("Get ready request value transfer event", "len(readyEvent)", len(ReadyEvent), "len(pendingEvent)", bi.pendingRequestEvent.Len())

	for idx, ev := range ReadyEvent {
		if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
			logger.Trace("handled requests can be ignored", "RequestNonce", ev.GetRequestNonce(), "lowerHandleNonce", bi.lowerHandleNonce)
			continue
		}

		if err := bi.handleRequestValueTransferEvent(ev); err != nil {
			bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
			logger.Error("Failed handle request value transfer event", "err", err, "len(RePutEvent)", len(ReadyEvent[idx:]))
			return
		}
	}
}

// AddRequestValueTransferEvents adds events into the pendingRequestEvent.
func (bi *BridgeInfo) AddRequestValueTransferEvents(evs []IRequestValueTransferEvent) {
	for _, ev := range evs {
		if bi.pendingRequestEvent.Len() > maxPendingNonceDiff {
			flatten := bi.pendingRequestEvent.Flatten()
			maxNonce := flatten[len(flatten)-1].Nonce()
			if ev.Nonce() >= maxNonce || bi.pendingRequestEvent.Exist(ev.Nonce()) {
				continue
			}
			bi.pendingRequestEvent.Remove(maxNonce)
			vtPendingRequestEventCounter.Dec(1)
			logger.Trace("List is full but add requestValueTransfer ", "newNonce", ev.Nonce(), "removedNonce", maxNonce)
		}

		bi.SetRequestNonceFromCounterpart(ev.GetRequestNonce() + 1)
		bi.pendingRequestEvent.Put(ev)
		vtPendingRequestEventCounter.Inc(1)
	}

// recoverPendingEvents recovers all pending events by resending them.
func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))
	}

	vtHandleEventMeter.Mark(int64(len(vtr.parentEvents)))
	events = make([]IRequestValueTransferEvent, len(vtr.parentEvents))
	for i, event := range vtr.parentEvents {
		events[i] = event
	}
	vtr.cBridgeInfo.AddRequestValueTransferEvents(events)

	return nil
