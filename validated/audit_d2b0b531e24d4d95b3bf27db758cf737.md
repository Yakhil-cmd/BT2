### Title
Signature verification selects org by `repository.owner.login` while handlers select the mutated repository by `repository.full_name`, allowing a webhook with a missing-secret org's login to forge writes to a different org's stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`verify_signature` picks the `GitHubApp` (and thus the `webhook_secret`) to verify against using `repository_owner`, which is read from the unsigned `params.dig('repository','owner','login')` field. Every webhook handler (`Handler#stacks`/`Handler#repository_name`, `PushHandler`, `PullRequest::OpenedHandler`, etc.) instead resolves the target `Repository`/`Stack` using the separate `repository.full_name` field from the same unsigned JSON body. Because `GitHubApp#verify_webhook_signature` auto-passes (`return true unless webhook_secret`) when the selected org has no configured secret, an attacker can pick an org with no `webhook_secret` for `repository.owner.login` to sail through verification while setting `repository.full_name` to a different, secret-protected org/repo to mutate that org's stack.

### Finding Description
The broken binding: the question assumes `org selected for signature verification == org owning the mutated row`. In this code, that equality does **not** hold, because two different unsigned fields drive each side:
- Signature verification org: `repository_owner` = `params.dig('repository','owner','login')` [1](#0-0)  feeding `Shipit.github(organization: repository_owner)` [2](#0-1) .
- Mutated-row org/repo: `payload.dig('repository', 'full_name')`, used by `Handler#repository_name`/`#stacks` and by every `PullRequest::*Handler#repository` (`Shipit::Repository.from_github_repo_name(params.repository.full_name)`) [3](#0-2) [4](#0-3) .

Root cause: `GitHubApp#verify_webhook_signature` treats an absent `webhook_secret` as automatically verified: `return true unless webhook_secret` [5](#0-4) . Shipit explicitly supports multi-org configs where `webhook_secret` is documented as optional per org [6](#0-5) , and the test fixture for double-org setups indeed configures blank `webhook_secret` for both orgs [7](#0-6) .

Exploit flow: with a multi-org Shipit deployment where `OrgA` (installed for legitimate but low-security reasons, or misconfigured) has no `webhook_secret` and `OrgB` has one, an attacker with no secrets sends `POST /webhooks` with any `X-Hub-Signature` value and a JSON body where `repository.owner.login = "OrgA"` (any string, causing `verify_signature` to select `OrgA`'s `GitHubApp`, whose `verify_webhook_signature` returns `true` unconditionally since it has no secret) but `repository.full_name = "OrgB/some-repo"`. `verify_signature` passes with `head(422)` not called, then `create` dispatches to handlers, which resolve `Repository.from_github_repo_name("OrgB/some-repo")` and mutate `OrgB`'s stacks/PRs (e.g., archive/unarchive a review stack, label-driven provisioning changes, closing a PR's review stack) without ever needing `OrgB`'s `webhook_secret`.

Existing guards fail to close this: `drop_unhandled_event` only filters unknown event names [8](#0-7) ; `GithubOrganizationUnknown` only fires if `repository_owner` doesn't match any configured org at all, not if it matches a different, low-security org [9](#0-8) ; and no code cross-checks that `repository.owner.login` matches the owner segment of `repository.full_name`.

### Impact Explanation
An unprivileged internet attacker (no session, no token, no secrets) can forge a webhook that mutates a *different* organization's stack — archiving/unarchiving review stacks, syncing arbitrary commits into a stack via `PushHandler#process` calling `stack.sync_github`, closing PR-triggered review stacks, or updating labels/pull-request metadata that drives deploy/merge-adjacent automation — attributed to a target org whose `webhook_secret` the attacker never possessed. This is repeatable against every repository under the target org and any stack event handler that trusts `repository.full_name`, matching "a payload for one repository mutating another's stack" (Critical). The blast radius spans all tenants configured in `Shipit.github`'s multi-org table whenever at least one configured org lacks a `webhook_secret`.

### Likelihood Explanation
Requires: (1) a multi-org Shipit deployment (`Shipit.github(organization:)` keyed config, as documented and tested), and (2) at least one configured org with no `webhook_secret` set — a state the docs explicitly call "optional" and Shipit's own test fixtures use by default. Given that precondition, exploitation costs nothing beyond crafting one HTTP POST; no GitHub account, no signing key, no valid signature is needed. It is fully repeatable and requires no timing or race condition.

### Recommendation
Bind signature verification org selection to the same field handlers use to resolve the target repository (`repository.full_name`'s owner segment), and reject the request (rather than silently pass) whenever `repository.owner.login` and the owner parsed from `repository.full_name` diverge. Additionally, treat a missing `webhook_secret` for a configured org as a hard misconfiguration to reject (or require) rather than an auto-pass in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "cross-org forged webhook must not mutate a different org's stack" do
  # Setup: OrgA has no webhook_secret; OrgB has repo 'OrgB/target-repo' with a stack/PR to be archived
  stack = shipit_stacks(:review_stack) # belongs to a repo under OrgB
  stack.update!(archived_since: nil)

  payload = {
    "action" => "closed",
    "number" => stack.pull_request.number,
    "pull_request" => { "id" => 1 },
    "repository" => {
      "owner" => { "login" => "OrgA" },       # no webhook_secret -> auto-verified
      "full_name" => stack.github_repo_name   # actually targets OrgB's stack
    },
    "sender" => { "login" => "attacker" }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # bogus, never validated for OrgA

  post :create, body: payload, as: :json

  # Both sides of the claimed binding:
  assert_equal 'OrgA', JSON.parse(payload).dig('repository', 'owner', 'login') # org used for signature check
  assert_not_equal 'OrgA', stack.repository.owner                              # org actually owning the mutated row

  assert_response :ok
  assert_not stack.reload.archived? # FAILS today: attacker-controlled cross-org archive succeeds
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end
