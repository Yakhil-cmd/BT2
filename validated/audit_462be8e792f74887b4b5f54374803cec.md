### Title
`ProxyType::NonTransfer` deny-list in Asset Hub Rococo fails open, letting a non-transfer proxy move the delegator's funds via `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`pallet-proxy`'s `InstanceFilter` for `ProxyType::NonTransfer` on Asset Hub Rococo is documented as "any call that does not transfer funds or assets," but is implemented as a **deny-list** that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`. Every other pallet in the runtime capable of moving the delegator's funds — `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, and value-moving `Indices`/`Vesting` calls — is missing from the deny-list and therefore silently reachable. This is structurally the same fail-open pattern as the Traefik advisory: a security boundary ("this proxy must not move value") that is enforced via an incomplete negative check rather than a positive allow-list, so anything not explicitly enumerated is granted by default rather than denied by default.

### Finding Description
`InstanceFilter<RuntimeCall> for ProxyType` on Asset Hub Rococo defines `NonTransfer` as: [1](#0-0) 

This mirrors the exact bug that was already identified and fixed in the *sibling* Asset Hub Westend runtime (`prdoc/pr_12771.prdoc`, `prdoc/pr_12769.prdoc`) and in the `staking-async` parachain runtime (`prdoc/pr_12922.prdoc`): [2](#0-1) 

Compare the patched Westend deny-list, which explicitly denies `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, `Indices::transfer`/`force_transfer`, `ConvictionVoting`, `Referenda`, `Whitelist`, `Scheduler`, `Treasury`: [3](#0-2) 

Asset Hub Rococo's list was never updated to match, and still only denies `Balances | Assets | NftFractionalization | Nfts | Uniques`: [1](#0-0) 

Reachability: `pallet_proxy::do_proxy` dispatches the wrapped call through the delegate's authorized origin, gated solely by `def.proxy_type.filter(c)` for any call that isn't itself `add_proxy`/`remove_proxy`/`remove_proxies`/`kill_pure`: [4](#0-3) 

Because `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` all exist as pallets in the Asset Hub Rococo `RuntimeCall` (confirmed by 117 references to these identifiers throughout the runtime file), a delegator who granted only a `NonTransfer` proxy — intending "cannot transfer funds or assets" — has in fact granted the delegate the ability to:
- transfer `ForeignAssets`/`PoolAssets` balances directly,
- swap/withdraw liquidity via `AssetConversion`,
- execute arbitrary `PolkadotXcm::transfer_assets`/`teleport_assets`/`send`/`execute` to move funds off-chain,
- call `Revive` contract dispatch with a nonzero `value`.

None of this requires governance, a privileged role, or a malicious peer — it is a normal, signed `Proxy::proxy` extrinsic from any account holding a `NonTransfer` delegation, which is the entry point ordinary users use for exactly this feature.

### Impact Explanation
This is a High-severity authorization-control-bypass: a delegator who intentionally restricts a proxy to `NonTransfer` (e.g., to let a bot/automation act on their behalf without being able to drain funds) is exposed to fund theft/misappropriation by that same delegate through pallets omitted from the deny-list. Given Asset Hub is Parity's live production reference-runtime chain, and this pattern was already the subject of two prior confirmed/fixed reports (issue #12466 and staking-async pr_12922) on other runtime instances, it is a proven bug class, just unpatched here.

### Likelihood Explanation
High likelihood of exploitation with zero special privilege: any account that has been granted (or accepts) a `NonTransfer` proxy delegation on Asset Hub Rococo can immediately call `ForeignAssets`/`PoolAssets`/`AssetConversion`/`PolkadotXcm`/`Revive` calls that move the delegator's funds, contradicting the delegator's explicit, documented intent and the pallet's own doc-comment ("Can execute any call that does not transfer funds or assets").

### Recommendation
Update `ProxyType::NonTransfer::filter` in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` to mirror the fix already applied to Asset Hub Westend (`prdoc/pr_12771.prdoc`): explicitly deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, and value-moving `Indices`/`Vesting` calls, consistent with the documented "cannot transfer funds or assets" invariant. More durably, consider migrating the `NonTransfer` filter from a deny-list to an allow-list (or adding a CI-enforced test, as already exists for Westend) so newly-added pallets default to denied rather than silently inheriting proxy reachability.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
