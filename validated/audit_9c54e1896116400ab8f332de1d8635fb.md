### Title
GitHub App installation token is disclosed to any submodule on the same host due to git's default host-scoped (not path-scoped) credential matching - ([File: main.go])

### Summary
`RefreshGitHubAppToken` stores the GitHub App installation token via `StoreCredentials`, which calls `git credential approve` with the full `git.repo` URL [1](#0-0) . However, git-sync never sets `credential.useHttpPath`, and by git's own default HTTP credential-matching semantics, `git credential fill` matches stored credentials on protocol+host only, ignoring the URL path/repo component. Consequently, any submodule URL on the same host (e.g. `github.com`) receives the same installation token as the primary repo, regardless of which org/repo it points to.

### Finding Description
`git.StoreCredentials` writes a credential record via `git credential approve` using the literal URL passed in (`git.repo` for the App token) [2](#0-1) . `RefreshGitHubAppToken` invokes this with `git.repo` and username `"-"`, password set to the freshly minted installation token [3](#0-2) .

git-sync's global git config setup (`SetupDefaultGitConfigs`) only sets `credential.helper` to `cache --timeout 3600`, `gc.*` settings, and `core.askPass` — it never sets `credential.useHttpPath` [4](#0-3) . By git's documented default (`git help gitcredentials`), when `credential.useHttpPath` is unset/false, the "context" git passes to credential helpers (and thus the matching key used by `cache`/`approve`/`fill`) is `protocol://host[:port]` only — the path/repo segment of the URL is *not* part of the match. This means a credential approved for `https://github.com/org/repo` is returned by `git credential fill` for *any* URL sharing `https://github.com`, including `https://github.com/attacker/other`.

Attack flow under the stated threat model (attacker controls repo content/refs that git-sync fetches, submodules enabled):
1. Operator configures GitHub App auth flags for `--repo=https://github.com/org/repo` with submodules recursion enabled (a supported, documented configuration, see README AUTHENTICATION > "github app" section).
2. `refreshCreds` calls `RefreshGitHubAppToken`, which stores the installation token keyed to `https://github.com/org/repo` [5](#0-4) .
3. The attacker (who can influence the content of a ref/branch git-sync syncs, e.g. via a mergeable PR branch or an unprotected branch) adds/edits `.gitmodules` in the primary repo to point a submodule at `https://github.com/<other-org>/<private-or-attacker-repo>` — same host, different repo.
4. During checkout, git recursively runs `git submodule update`, which internally calls `git fetch`/`git clone` for the submodule URL. Because `credential.useHttpPath` is unset, git's HTTP transport requests credentials for context `https://github.com`, and the cached App-token credential (approved for the primary repo URL) is returned and sent as the `Authorization` header for the submodule's HTTP requests.
5. If the App installation has org-wide or multi-repo read access, this results in the token being used against a repository outside of the repo the operator intended to grant access to — a confused-deputy condition. If that target repo is private and normally inaccessible to the attacker, its contents get fetched and published into the git-sync `--root`/`--link` output, which the attacker (per this threat model) may be able to read as a non-root user sharing the volume.

No existing code path restricts credential scope per-submodule, sets `useHttpPath`, or validates that `.gitmodules` URLs remain within the same repo/org as `--repo`. There is no `protocol.allow`/host-allowlist enforcement for submodule URLs either.

### Impact Explanation
This is a secret/credential-confinement failure: a short-lived but privileged GitHub App installation token, intended only for the configured `--repo`, is transparently reused by git for arbitrary same-host submodule fetches. Depending on the App's installation scope, this can result in disclosure of private repository content the operator never intended git-sync to access, and that content being published to a location an unprivileged, repo-content-controlling attacker can read — matching a "secret leakage leading to unauthorized data disclosure" / "publishing wrong or partial content" impact class.

### Likelihood Explanation
Preconditions: GitHub App auth flags configured (`--github-app-*`, all documented, supported flags) and submodule recursion enabled (default git submodule behavior when `.gitmodules` is present and processed — no `--submodules=off`-style guard was found preventing this). The attacker only needs the ability to add/modify `.gitmodules` in a ref/branch that git-sync syncs, which is within the stated attacker capability ("controls repo content and refs that git-sync fetches"). This relies purely on git's own documented default credential-matching behavior (not misconfiguration by the operator), since git-sync itself never opts into path-scoped matching.

### Recommendation
- Set `credential.useHttpPath = true` globally (or scoped per-host) in `SetupDefaultGitConfigs`/`StoreCredentials` so git's credential matching includes the path, preventing cross-repo credential bleed on the same host.
- Alternatively/additionally, scope the App token credential entry using `credential.<url>.*` config tied to the exact `git.repo` path rather than relying on the ambient `cache` helper context.
- Consider restricting/validating submodule URLs against an allowlist of hosts/paths the operator expects, independent of credential scoping.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}
