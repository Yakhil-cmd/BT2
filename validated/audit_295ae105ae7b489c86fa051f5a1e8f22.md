### No vulnerability found for this question.

**Analysis supporting this conclusion:**

The claimed divergence requires a blob byte pattern that makes `blob_to_polynomial` succeed while containing a "non-canonical near-modulus" field element. This precondition does not hold: `blob_to_polynomial` calls `bytes_to_bls_field` for every 32-byte chunk [1](#0-0) , and `bytes_to_bls_field` explicitly rejects any non-canonical scalar via `blst_scalar_fr_check` before converting to `fr_t`, returning `C_KZG_BADARGS` [2](#0-1) . Therefore no byte value at or above `BLS_MODULUS` (including the `BLS_MODULUS-1` boundary framed in the question, which is actually canonical, or any value `>= BLS_MODULUS`, which is non-canonical) can ever produce a valid in-range `fr_t` that "sneaks through" — the conversion either fails uniformly (in both single and batch code paths) or produces the unique canonical field element.

Given that `blob_to_polynomial` either fails identically in both call sites or produces bit-identical `fr_t` values, the downstream functions `compute_challenge` [3](#0-2)  and `evaluate_polynomial_in_evaluation_form` [4](#0-3)  are pure, deterministic functions of the canonical polynomial and blob bytes — they contain no `n`-dependent or path-dependent branching. `verify_blob_kzg_proof` [5](#0-4)  and the per-`i` loop inside `verify_blob_kzg_proof_batch` [6](#0-5)  invoke identical helper functions on identical inputs, so `ys_fr[i]` computed in the batch path is bit-for-bit equal to `y_fr` computed in the single-blob path for the same blob and commitment. The `n==1` short-circuit in `verify_blob_kzg_proof_batch` [7](#0-6)  even makes this explicit by directly delegating to `verify_blob_kzg_proof`.

Thus the equality "`ys_fr[i]` from the batch path == `y_fr` from the single path for the same blob" holds in all cases, before and after considering non-canonical byte inputs, because canonicity is enforced deterministically and uniformly at the `bytes_to_bls_field` boundary shared by both call paths. No divergence is reachable through the described `CALL_SEQUENCE`.

void compute_challenge(fr_t *eval_challenge_out, const Blob *blob, const g1_t *commitment) {
    Bytes32 eval_challenge;
    uint8_t bytes[CHALLENGE_INPUT_SIZE];

    /* Pointer tracking `bytes` for writing on top of it */
    uint8_t *offset = bytes;

    /* Copy domain separator */
    memcpy(offset, FIAT_SHAMIR_PROTOCOL_DOMAIN, DOMAIN_STR_LENGTH);
    offset += DOMAIN_STR_LENGTH;

    /* Copy polynomial degree (16-bytes, big-endian) */
    bytes_from_uint64(offset, 0);
    offset += sizeof(uint64_t);
    bytes_from_uint64(offset, FIELD_ELEMENTS_PER_BLOB);
    offset += sizeof(uint64_t);

    /* Copy blob */
    memcpy(offset, blob->bytes, BYTES_PER_BLOB);
    offset += BYTES_PER_BLOB;

    /* Copy commitment */
    bytes_from_g1((Bytes48 *)offset, commitment);
    offset += BYTES_PER_COMMITMENT;

    /* Make sure we wrote the entire buffer */
    assert(offset == bytes + CHALLENGE_INPUT_SIZE);

    /* Now let's create the challenge! */
    blst_sha256(eval_challenge.bytes, bytes, CHALLENGE_INPUT_SIZE);
    hash_to_bls_field(eval_challenge_out, &eval_challenge);
}

static C_KZG_RET evaluate_polynomial_in_evaluation_form(
    fr_t *out, const fr_t *poly, const fr_t *x, const KZGSettings *s
) {
    C_KZG_RET ret;
    fr_t tmp;
    fr_t *inverses_in = NULL;
    fr_t *inverses = NULL;
    uint64_t i;
    const fr_t *brp_roots_of_unity = s->brp_roots_of_unity;

    ret = new_fr_array(&inverses_in, FIELD_ELEMENTS_PER_BLOB);
    if (ret != C_KZG_OK) goto out;
    ret = new_fr_array(&inverses, FIELD_ELEMENTS_PER_BLOB);
    if (ret != C_KZG_OK) goto out;

    for (i = 0; i < FIELD_ELEMENTS_PER_BLOB; i++) {
        /*
         * If the point to evaluate at is one of the evaluation points by which the polynomial is
         * given, we can just return the result directly.  Note that special-casing this is
         * necessary, as the formula below would divide by zero otherwise.
         */
        if (fr_equal(x, &brp_roots_of_unity[i])) {
            *out = poly[i];
            ret = C_KZG_OK;
            goto out;
        }
        fr_sub(&inverses_in[i], x, &brp_roots_of_unity[i]);
    }

    ret = fr_batch_inv(inverses, inverses_in, FIELD_ELEMENTS_PER_BLOB);
    if (ret != C_KZG_OK) goto out;

    *out = FR_ZERO;
    for (i = 0; i < FIELD_ELEMENTS_PER_BLOB; i++) {
        fr_mul(&tmp, &inverses[i], &brp_roots_of_unity[i]);
        fr_mul(&tmp, &tmp, &poly[i]);
        fr_add(out, out, &tmp);
    }
    fr_from_uint64(&tmp, FIELD_ELEMENTS_PER_BLOB);
    fr_div(out, out, &tmp);
    fr_pow(&tmp, x, FIELD_ELEMENTS_PER_BLOB);
    fr_sub(&tmp, &tmp, &FR_ONE);
    fr_mul(out, out, &tmp);

out:
    c_kzg_free(inverses_in);
    c_kzg_free(inverses);
    return ret;
}

C_KZG_RET verify_blob_kzg_proof(
    bool *ok,
    const Blob *blob,
    const Bytes48 *commitment_bytes,
    const Bytes48 *proof_bytes,

    fr_t evaluation_challenge_fr, y_fr;
    g1_t commitment_g1, proof_g1;

    *ok = false;

    /* Allocate space for our polynomial */
    ret = new_fr_array(&poly, FIELD_ELEMENTS_PER_BLOB);

    ret = bytes_to_kzg_commitment(&commitment_g1, commitment_bytes);

    if (ret != C_KZG_OK) goto out;

    /* Evaluate challenge to get y */

    ret = verify_kzg_proof_impl(ok, &commitment_g1, &evaluation_challenge_fr, &y_fr, &proof_g1, s);

out:

    return ret;
}
