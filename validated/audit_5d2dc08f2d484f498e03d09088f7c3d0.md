### Title
Unhandled `throw` in `definition template` authentifier evaluation crashes the node - (File: `definition.js`)

### Summary
The Asterisk CVE is a remote-input-triggered crash caused by an unhandled failure path deep in negotiation logic (SDP handling in `res_pjsip_session.c`). The analogous class in `ocore` is an attacker-controlled unit whose address definition uses the `definition template` operator, which — when the referenced template unit is missing/duplicated at authentifier-verification time — hits a bare `throw Error(...)` instead of returning an error via the callback, inside an async DB-query callback that is not wrapped in try/catch by its caller.

### Finding Description
`validateAuthentifiers` in `definition.js` recursively evaluates an address definition while checking signatures for any posted unit. For the `definition template` branch: [1](#0-0) 
if the referenced `definition_template` unit is not found or not uniquely resolved (`rows.length !== 1`), the code executes `throw Error("not 1 template")` — instead of calling `cb2(false)`/propagating an error result like the sibling `validateDefinition` implementation does for the same operator (which properly returns an error through `cb(...)` with try/catch around `JSON.parse`/`replaceInTemplate`): [2](#0-1) 
This throw (and the unguarded `JSON.parse`/`replaceInTemplate` calls right after it) happens inside a `conn.query(...)` result callback, i.e., inside an asynchronous callback with no enclosing try/catch in `validateAuthentifiers` or in its caller in `validation.js` (`validateAuthors`/`validate`). An exception thrown from an async DB callback cannot be caught by the synchronous `try` blocks in `validate()`; it becomes an uncaught exception on the event loop.

`network.js` installs a global handler that deliberately crashes the whole process on any uncaught exception: [3](#0-2) 

### Impact Explanation
Any unprivileged author can construct/post a unit whose signing address definition contains a `['definition template', [unit, params]]` clause referencing a `definition_template` unit that is not stable/good, or that later becomes ambiguous (e.g., two competing good-and-stable `definition_template` messages for the same `unit` value at validation time), or simply omitted/never confirmed. When any node — including hubs/full nodes processing the broadcast/posted unit — reaches `validateAuthentifiers` and evaluates that branch, `rows.length !== 1` throws synchronously inside the async DB callback, escapes as an uncaught exception, and per `network.js`'s handler, crashes the node process. This is a network-wide denial-of-service: any single crafted unit sent by an ordinary unprivileged unit poster (not a peer/hub-privileged actor) can crash any node that validates it, preventing that node from confirming new units — matching the "network unable to confirm new units" impact class.

### Likelihood Explanation
Likelihood is high: no special privileges, no cryptographic breaks, and no race condition beyond ordinary confirmation timing are required — an attacker only needs to author an address definition that uses `definition template` pointing to a template unit that is not (yet, or ever) uniquely stable/good, then post a unit signed by that address. This condition (0 or >1 matching rows) is achievable by an ordinary user, e.g., by referencing a template unit before it stabilizes, or by never posting the corresponding `definition_template` message at all.

### Recommendation
In `definition.js`'s `validateAuthentifiers`, `definition template` branch, replace the bare `throw Error("not 1 template")` with a graceful failure path consistent with the `validateDefinition` counterpart: return `cb2(false)` (treat as authentifier-verification failure) instead of throwing, and wrap the subsequent `JSON.parse`/`replaceInTemplate` calls in try/catch, calling `cb2(false)` on any exception rather than letting it propagate uncaught.

### Proof of Concept
1. Attacker creates address `A` whose definition is `['definition template', ['<template_unit_hash>', {param1: 'value1'}]]`, where `<template_unit_hash>` either does not exist as a stable, good `definition_template` message, or corresponds to more than one such message under conditions allowed by the DAG (e.g., non-serial competing units before finality).
2. Attacker posts/broadcasts a unit signed by address `A` (this only requires being a normal unit poster, no elevated privilege).
3. When any node performs authentifier validation for this unit via `validateAuthentifiers` → the `definition template` case in `definition.js:802-819`, the `conn.query` callback finds `rows.length !== 1` and executes `throw Error("not 1 template")`.
4. Because this throw occurs inside an asynchronous database callback (not inside any try/catch reachable by `validate()`'s synchronous exception handling), it becomes an uncaught exception.
5. `network.js`'s `process.on('uncaughtException', ...)` handler logs the error and re-throws it, crashing the entire node process.

Note: I was unable to fully trace every intermediate frame between `validateAuthors` in `validation.js` and `validateAuthentifiers` in `definition.js` (e.g., the exact call site and whether any wrapping try/catch exists specifically around that call) due to iteration limits; a Devin session with full file access would allow confirming the exact call chain and any missed catch blocks before implementing the fix.
