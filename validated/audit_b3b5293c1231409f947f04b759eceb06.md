### Title
Webhook signature verification is keyed off an unauthenticated payload field disconnected from the repository the event handlers act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
The reentrancy report ("external calls before critical state writes") maps to a real analog in Shipit's webhook trust boundary: the field used to select **which GitHub App/organization's secret authenticates the request** (`repository.owner.login`) is a different, unauthenticated field from the one used to determine **which repository/stack the event handlers actually mutate** (`repository.full_name`). Just as the audited contract wrote state based on data that hadn't yet been validated against the external call's outcome, `WebhooksController` authorizes the request against one identity while the handlers act on another.

### Finding Description
`WebhooksController#verify_signature` extracts the organization to authenticate against straight from the untrusted, unparsed JSON body, before any signature check has occurred: [1](#0-0) [2](#0-1) 

It then verifies the signature using that organization's configured `GitHubApp`: [3](#0-2) 

Critically, `verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank for that organization's config (`return true unless webhook_secret`). Shipit explicitly supports multi-organization deployments where each org has its own independent `webhook_secret` in `secrets.github`: [4](#0-3) [5](#0-4) 

Once the request passes `verify_signature` (trivially, if the org picked via `repository.owner.login` has no `webhook_secret` configured), the full unauthenticated JSON body is dispatched to event handlers, which resolve the target `Stack`/`Repository` using a **completely different field**, `repository.full_name`, with no cross-check that it matches the organization used for authentication: [6](#0-5) [7](#0-6) [8](#0-7) 

This breaks the binding: **organization that authenticated == repository that is written**. If any organization configured in this Shipit instance has `webhook_secret` unset/blank (the docs show it as an optional field, and per-org configs are independent), an unprivileged attacker who knows this can craft a payload where `repository.owner.login` = the no-secret org (satisfying `verify_signature`) but `repository.full_name` = any other repository tracked by this Shipit instance (e.g., `Shopify/shipit-engine`), and forge arbitrary push/pull_request/status events for that unrelated repository with no valid signature at all.

### Impact Explanation
This allows an unprivileged, unauthenticated attacker to forge GitHub webhook events (push, pull_request open/close/label, commit status, check_suite) for any repository/stack tracked by the Shipit instance, as long as one organization in a multi-org config lacks a `webhook_secret`. Depending on which handler fires, this can trigger `stack.sync_github` (syncing/deploy-triggering commit refs), archive/unarchive review stacks, or fabricate commit statuses used elsewhere to gate merges/deploys — i.e., an unauthorized influence over deploy/merge state across repositories the attacker does not control. This matches the "unauthorized deploy/rollback/merge" and "cross-repository writes" Critical/High impact classes.

### Likelihood Explanation
Likelihood is moderate to high in any deployment using the documented multi-organization GitHub App configuration (`docs/setup.md`), since `webhook_secret` is explicitly documented as optional per-org and administrators may reasonably leave it blank for a low-risk/staging org while relying on the `sha1=` signature scheme for others. No credentials, tokens, or GitHub App access are required by the attacker — only knowledge (or discovery via `422`/timing responses) that a configured organization has no webhook secret.

### Recommendation
Do not select the authenticating GitHub App from the same untrusted payload whose repository claim is later trusted for state mutation. Concretely:
1. Verify the payload's `repository.full_name` belongs to the organization (`repository.owner.login`) used to select the `GitHubApp`/secret before dispatching to handlers, rejecting mismatches.
2. Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is blank in production; require every configured organization to have a non-blank `webhook_secret`, or fail closed instead of open.
3. Ensure `verify_signature`'s early `head(422)` actually halts the filter chain and the handler dispatch (add an explicit `return` for defense-in-depth, even though Rails should halt on `performed?`).

### Proof of Concept
Given a multi-org `secrets.github` config where organization `staging-org` has `webhook_secret: nil` and organization `Shopify` has a real secret protecting repository `Shopify/shipit-engine`:

1. Attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "staging-org" },
    "full_name": "Shopify/shipit-engine"
  }
}
```
2. `repository_owner` resolves to `staging-org`; `Shipit.github(organization: 'staging-org').verify_webhook_signature(...)` returns `true` immediately because `staging-org`'s `webhook_secret` is blank — no valid `X-Hub-Signature` is required at all.
3. `PushHandler` then resolves the target repo/stack via `payload.dig('repository','full_name')` = `Shopify/shipit-engine` and calls `stack.sync_github(expected_head_sha: params.after)`, acting on the `Shopify` repository despite the request never having been authenticated for that organization.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
