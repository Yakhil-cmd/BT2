### Title
Stack-scoped ApiClient token can create a global Hook and exfiltrate deploy/task data from every other stack - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
`Shipit::Api::HooksController#create` derives the `stack_id` of the hook being created solely from an optional request parameter, never from the scope encoded on the authenticated `ApiClient`. A token that is scoped to a single stack (`ApiClient#stack_id`) and merely holds the generic `write:hook` permission can call the un-nested `/api/hooks` route (which never populates `params[:stack_id]`) and create a hook with `stack_id: nil`, i.e. a *global* hook that receives every stack's `deploy`, `rollback`, `task`, `commit_status`, `lock` and `merge` events, forever, regardless of which stack the token was actually authorized for.

### Finding Description
`ApiClient` permissions are checked purely by name (`read:hook`/`write:hook`) via `ApiClient#check_permissions!`, with no coupling to the client's own `stack_id`: [1](#0-0) 

The stack that a hook is attached to is computed independently, from the request rather than from the caller's authorization scope: [2](#0-1) [3](#0-2) 

`stack_id` is only set `if params[:stack_id].present?`. The engine exposes both a stack-nested hooks route and a top-level, unscoped one: [4](#0-3) 

`BaseController#stacks`/`#stack` correctly restrict a scoped client to its own stack when the *nested* route is used, but that restriction is never applied to the top-level `/api/hooks` route, and `stack_id` in `HooksController` simply becomes `nil` when the request omits it: [5](#0-4) 

A `Hook` with `stack_id: nil` is a *global* hook, and `Hook.deliver` fans out global hooks to every stack's events (`for_stack` includes `stack_id: [nil, stack_id]`): [6](#0-5) 

The binding that should hold is: `stack authorized by ApiClient.stack_id == stack whose events are delivered to the hook's delivery_url`. By hitting the unscoped `create` action, an attacker breaks this equality — the token's authorization is bound to stack A, but the hook it creates touches every stack (A, B, C, …).

The events delivered include task/deploy payloads serialized with the `env` attribute, which can carry deploy-time environment variables configured by other stacks' operators: [7](#0-6) 

### Impact Explanation
This is an unauthenticated (from the perspective of other stacks) read of stack state, task streams, and deploy output/env: a client credentialed for one stack can register a delivery URL that receives commit/deploy/rollback/task/lock/merge events for every stack managed by the Shipit instance, including any values injected via each stack's `env` whitelist. This matches the High-severity criteria in scope ("escalation into ... unauthenticated read of stack state, task streams, or deploy output").

### Likelihood Explanation
Any holder of a legitimately-issued, stack-scoped `ApiClient` token with the `write:hook` permission — a low, plausible permission grant for e.g. a CI integration meant to be notified about only its own stack's deploys — can perform this action with a single unauthenticated-relative-to-other-stacks API call; no additional privileges, secrets, or session are required beyond the token they already legitimately possess.

### Recommendation
In `Shipit::Api::HooksController`, force `stack_id` to the caller's own scope when the `ApiClient` is stack-scoped, instead of trusting `params[:stack_id]`:
```ruby
def stack_id
  return current_api_client.stack_id if current_api_client.stack_id?
  stack.id if params[:stack_id].present?
end
```
and reject attempts by a stack-scoped client to create/update a global hook (`stack_id` absent) with a `403`.

### Proof of Concept
1. Create/obtain an `ApiClient` scoped to `stack_id: A` with permissions `["write:hook"]` (a normal, low-privilege grant for stack A's own tooling).
2. Send `POST /api/hooks` (the top-level, unscoped route) with `delivery_url` pointing to an attacker-controlled endpoint and `events: ["deploy", "task", "rollback", "commit_status"]`, omitting `stack_id`.
3. `HooksController#create` computes `stack_id` as `nil` (`params[:stack_id]` absent) and calls `Hook.where(stack_id: nil).create(params)`, persisting a global `Hook`.
4. From now on, every deploy/rollback/task/commit_status/lock/merge event for *every* stack in the instance — not just stack A — is POSTed to the attacker's `delivery_url` via `Hook.deliver`/`DeliverHookJob`, leaking other stacks' commit, task, and `env` data.

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
