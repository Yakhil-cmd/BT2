### Title
Unvalidated decoded length in `isChashValid()` causes an uncaught exception (node crash) on malformed addresses/asset chashes - ([File: chash.js])

### Summary
`isChashValid()` only checks the *encoded* string length (32 or 48 chars) before decoding it with `base32.decode()`/`Buffer.from(..., 'base64')`, but never checks that the *decoded* buffer has the expected byte length (20 bytes for the 160-bit chash, 36 bytes for the 288-bit chash) before it is fed into `buffer2bin()` and `separateIntoCleanDataAndChecksum()`.

### Finding Description
`isValidAddress()`/`isValidChash()` in `validation_utils.js` call `chash.isChashValid(str)` after only checking the string is exactly 32 (or 48) characters via a regex (`/^[A-Z2-7]{32}$/`) [1](#0-0) . Base32 encoding is not one-to-one at the byte level for arbitrary bit padding, and `thirty-two`'s decoder can, for certain crafted 32-character inputs, return a decoded `Buffer` whose length is not exactly 20 bytes (160 bits). `isChashValid()` does not check `chash.length` before calling `buffer2bin(chash)`: [2](#0-1) 

`buffer2bin()` just converts whatever length buffer it is given into a bit-string of `chash.length*8` bits [3](#0-2) . That bit-string is then passed into `separateIntoCleanDataAndChecksum()`, which explicitly throws an uncaught `Error("bad length="+len+...)` whenever `bin.length` is not exactly 160 or 288: [4](#0-3) 

This `throw` is **not** wrapped in the `try/catch` inside `isChashValid()` — only the initial `base32.decode`/`Buffer.from` call is guarded [5](#0-4) . This is the same root-cause pattern as `string_scan_range()` in radare2 (CVE-2018-11381): a length/offset derived from untrusted input is used to drive a scanning/parsing routine without first validating it matches an expected fixed size, and the routine throws/reads out of its expected structure when fed a malformed length.

Because `isValidAddress()` is called from many unauthenticated, attacker-reachable paths — including unit author/definition-address validation, output/input address checks, AA trigger address checks, asset issuer/definer validation, and `is_valid_address()` in oscript formulas evaluated by AAs — any crafted 32-character base32 string that decodes to a buffer whose bit length isn't 160 (or a 48-character base64 string whose bit length isn't 288) will cause an uncaught exception to propagate up through unit/joint validation.

### Impact Explanation
`network.js` installs a global `process.on('uncaughtException', ...)` handler whose comment explicitly states its purpose is to **crash the whole node process** to avoid ending up in an inconsistent state: [6](#0-5) 

If the thrown `Error("bad length=...")` from `separateIntoCleanDataAndChecksum()` is not caught anywhere in the call chain from `validation.js`/`aa_composer.js` down to `chash.isChashValid`, it becomes an uncaught exception and crashes the node. A single crafted unit (posted by any unprivileged party, containing a malformed address string as an author address, output address, AA trigger data, or asset condition) or a malicious AA trigger/oscript `is_valid_address()` call could crash any full node that attempts to validate it — a "network unable to confirm new units" scenario if this is done broadly, or a targeted crash of individual nodes/hubs processing the unit.

### Likelihood Explanation
Medium-to-High reachability: `isValidAddress()`/`isValidChash()` are called from many unauthenticated code paths (unit validation, definition validation, AA trigger/oscript evaluation) that process attacker-supplied strings before any other sanitization. However, I was not able to fully verify (without running `thirty-two`'s decoder) whether a 32-character base32 string can actually decode to a buffer of an unexpected byte length, or whether callers of `isChashValid` universally wrap it in try/catch further up the stack (e.g., `formula/evaluation.js`'s `is_valid_address` case does not appear to wrap the call, but I could not exhaustively confirm every call site tolerates a thrown exception). This uncertainty should be verified by a background agent before treating this as confirmed-exploitable.

### Recommendation
In `chash.js`, after decoding `encoded` in `isChashValid()`, explicitly verify `chash.length` equals the expected byte length (20 for 160-bit, 36 for 288-bit) before calling `buffer2bin`/`separateIntoCleanDataAndChecksum`, and return `false` instead of allowing an exception to propagate. Additionally, wrap the entire body of `isChashValid()` (not just the initial decode) in a `try/catch` that returns `false` on any error, consistent with how validation code elsewhere (e.g. `validateDefinition`, `handleDuplicateAddressDefinition`) defensively catches `objectHash.getChash160` exceptions.

### Proof of Concept
Conceptual PoC (needs runtime verification of `thirty-two`'s decode behavior for edge-case inputs):
1. Find/construct a 32-character base32 string (matching `/^[A-Z2-7]{32}$/`) that `base32.decode()` decodes to a `Buffer` whose length in bits is not 160 (e.g., due to non-canonical trailing-bit padding accepted by the decoder).
2. Use this string as the `address` field of a unit author, an output address, or as an argument to `is_valid_address()` in an AA's oscript trigger data.
3. Submit the unit/trigger to a node; `isValidAddress` → `isChashValid` → `separateIntoCleanDataAndChecksum` throws `Error("bad length=...")`, which is uncaught and triggers the node's `uncaughtException` handler, crashing the process per `network.js` lines 4530–4543.

function separateIntoCleanDataAndChecksum(bin){
	var len = bin.length;
	var arrOffsets;
	if (len === 160)
		arrOffsets = arrOffsets160;
	else if (len === 288)
		arrOffsets = arrOffsets288;
	else
		throw Error("bad length="+len+", bin = "+bin);
	var arrFrags = [];
	var arrChecksumBits = [];
	var start = 0;
	for (var i=0; i<arrOffsets.length; i++){
		arrFrags.push(bin.substring(start, arrOffsets[i]));
		arrChecksumBits.push(bin.substr(arrOffsets[i], 1));
		start = arrOffsets[i]+1;
	}
	// add last frag
	if (start < bin.length)
		arrFrags.push(bin.substring(start));
	var binCleanData = arrFrags.join("");
	var binChecksum = arrChecksumBits.join("");
	return {clean_data: binCleanData, checksum: binChecksum};
}
