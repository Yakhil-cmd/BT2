### Title
CCMenu API endpoint does not enforce ApiClient stack scoping, allowing a token authorized for one stack to read the build status of any stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
Shipit lets an operator create an `ApiClient` scoped to a single `Stack` (the `stack_id` column) with the `read:stack` permission, so that a third party (e.g. a CI dashboard or a CCMenu client for a specific pipeline) can only read the status of that one stack. The generic API layer enforces this binding, but `Api::CCMenuController` bypasses it: it resolves the target stack directly from `Stack.from_param!` instead of the scoped `stacks` helper used everywhere else, so a token scoped to stack A can be replayed against any `stack_id` to read stack B's build status.

### Finding Description
`Api::BaseController` defines the trust binding between an authenticated `ApiClient` and the stacks it may touch: [1](#0-0) 

`stacks` is deliberately restricted to `current_api_client.stack_id` when the client is stack-scoped, and every other API controller (e.g. `StacksController`, `TasksController`) resolves the requested stack through this `stacks`/`stack` pair, which is exactly what enforces "token authorizes stack A" == "controller resolves stack A".

`Api::CCMenuController`, however, overrides both the authentication method and the stack resolution method, and in doing so drops the scoping check: [2](#0-1) 

Specifically:
- `authenticate_api_client` accepts a bare `params[:token]` via `ApiClient.authenticate(params[:token])` (in addition to inheriting Basic Auth from the parent), so any leaked/observed token works here.
- `require_permission :read, :stack` only checks that the token's `permissions` array contains `read:stack` (see `ApiClient#check_permissions!`) — it never checks `stack_id`: [3](#0-2) 

- `stack` is redefined as `Stack.from_param!(params[:stack_id])`, calling the class method directly on `Stack` rather than on the scoped `stacks` collection that `BaseController#stack` uses: [4](#0-3) 

The equality that should hold is: `stack a token authorizes == stack the controller acts on`. For every other API controller this holds because they resolve stacks through `stacks.from_param!`. In `CCMenuController` this equality is broken: the token only needs `read:stack` in its permission list; the `stack_id` scope column on the `ApiClient` record is never consulted, so `params[:stack_id]` alone decides which stack's data is returned — for any value, regardless of what the token was actually issued for.

### Impact Explanation
An `ApiClient` scoped to a single stack (a normal, documented way to hand out a narrowly-scoped credential, e.g. `here_come_the_walrus` fixture with `stack: shipit`) can be replayed against `GET /api/stacks/:any_other_stack_id/ccmenu.xml?token=...` to read that other stack's `name`, `activity`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, and `webUrl` — data belonging to a stack the credential was never granted access to. This is an authorization-scope escalation: unauthenticated (from the perspective of that other stack) read of stack build state, matching the "High — unauthenticated read of stack state" impact category, without needing a Shipit session, GitHub credentials, or privileged account beyond possessing any valid `read:stack`-permissioned token (even one deliberately scoped narrowly).

### Likelihood Explanation
Likelihood is high for any deployment that issues stack-scoped tokens (a supported, documented feature via `ApiClient.stack` and `BaseController#stacks`) and shares them with less-trusted third parties expecting the "one client, one stack" guarantee (this is the exact use case the `stack_id` scoping column exists for). The attack requires only knowledge of one valid, narrowly-scoped token and the numeric/param id of a different stack — both are low-friction to obtain (stack ids/names are often public or guessable, and CCMenu-style tokens are commonly embedded in third-party dashboards / CI status widgets).

### Recommendation
Make `Api::CCMenuController#stack` go through the same scoped lookup as the rest of the API:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
(reuse `BaseController#stacks`, which already respects `current_api_client.stack_id`), and/or add an explicit check `current_api_client.stack_id.blank? || current_api_client.stack_id == stack.id` before rendering.

### Proof of Concept
1. As a Shipit admin, create (or use) an `ApiClient` scoped to stack `shipit` only, with permission `read:stack` (fixture `here_come_the_walrus` in `test/fixtures/shipit/api_clients.yml` already matches this: `stack: shipit`, `permissions: [read:stack]`). [5](#0-4) 
2. Obtain that client's `authentication_token` (e.g. it was handed to a partner dashboard for stack `shipit` only).
3. Send `GET /api/stacks/<other-stack-param>/ccmenu.xml?token=<here_come_the_walrus token>` where `<other-stack-param>` is any other existing stack (e.g. `soc` from fixtures).
4. `authenticate_api_client` succeeds via `ApiClient.authenticate(params[:token])`; `require_permission :read, :stack` passes because the token has `read:stack`; `stack` resolves via `Stack.from_param!(params[:stack_id])` with no scope check, returning the *other* stack's record; the XML response discloses that stack's `lastBuildStatus`, `lastBuildLabel`, `webUrl`, etc. — data outside the token's intended `stack_id` scope. (Note: I could not execute this request against a running instance from this read-only environment; the trace above is derived directly from the controller/model code shown, and I was unable to fully confirm whether `Stack.from_param!` performs any implicit organization-level restriction beyond what is shown in the visible portion of `app/models/shipit/stack.rb` — a Devin session with repo access would be needed to run the request end-to-end and confirm the HTTP response.)

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
