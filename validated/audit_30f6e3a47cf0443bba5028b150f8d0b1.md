### Title
Panic (index out of range) in `getOrgAndRepo` due to unvalidated `workflow.repository` field in attestation predicate - (File: pkg/cmd/attestation/inspect/bundle.go)

### Finding Description
`getOrgAndRepo` strips a known prefix (`https://github.com/` or `https://<tenant>.ghe.com/`) from `predicate.BuildDefinition.ExternalParameters.Workflow.Repository`, then does `parts := strings.Split(after, "/"); return parts[0], parts[1], nil` without checking `len(parts) >= 2`. [1](#0-0) . The `Workflow.Repository` value originates from the attestation bundle's DSSE statement predicate, which is attacker-controlled content in a bundle published/attached by an unprivileged attacker (e.g., in a repo's attestations, a gist, or artifact that the victim runs `gh attestation inspect` against). If the prefix match succeeds (e.g., `after` is exactly `https://github.com/` with nothing after, or `https://github.com/onlyowner` with no slash), `after` will contain zero or one path segment, so `parts` has length < 2, and `parts[1]` triggers an out-of-bounds slice index panic, crashing the `gh` process. [2](#0-1) 

### Impact Explanation
This is a denial-of-service against the `gh attestation inspect` command: an attacker can craft/publish an attestation bundle whose statement predicate contains `externalParameters.workflow.repository` set to a string like `"https://github.com/"` (no org/repo segments) or `"https://github.com/org"` (missing repo segment). When the victim inspects this bundle, the process panics instead of returning a handled error. This does not achieve code execution, credential exfiltration, or file write outside intended paths — it is limited to an unhandled panic/crash (client-side denial of service), which is a lower-severity finding than the categories emphasized in scope, but is a concrete, reproducible defect in unvalidated attacker-controlled input handling.

### Likelihood Explanation
Fully attacker-controlled: the attacker only needs to publish an attestation bundle (or arbitrary predicate JSON that gets parsed) with a malformed `workflow.repository` string beginning with the expected prefix but lacking a second path segment. No privileges, tokens, or victim interaction beyond running `gh attestation inspect` on the attacker-supplied bundle are required. This is deterministic and 100% reproducible.

### Recommendation
Validate `len(parts) == 2` (or more strictly, non-empty org and repo segments) after the split in `getOrgAndRepo`, returning a descriptive error (e.g., `fmt.Errorf("failed to get org and repo from %s", repoURL)`) instead of indexing unconditionally into `parts`.

### Proof of Concept
```go
func TestGetOrgAndRepo_MalformedRepository(t *testing.T) {
	// repoURL has the expected prefix but no "/" separating org and repo
	_, _, err := getOrgAndRepo("", "https://github.com/onlyorgnorepo")
	if err == nil {
		t.Fatal("expected error, got nil (or panic occurred before this line)")
	}
}
```
Running this against the current implementation with `after = "onlyorgnorepo"` yields `parts = ["onlyorgnorepo"]`, and `parts[1]` panics with "index out of range [1] with length 1". A full integration PoC would construct an `api.Attestation` whose bundle's statement predicate JSON contains `"externalParameters":{"workflow":{"repository":"https://github.com/onlyorgnorepo"}}` and pass it to `getAttestationDetail`, observing the process panic instead of returning an error. func getOrgAndRepo(tenant, repoURL string) (string, string, error) {
	var after string
	var found bool
	if tenant == "" {
		after, found = strings.CutPrefix(repoURL, "https://github.com/")
		if !found {
			return "", "", fmt.Errorf("failed to get org and repo from %s", repoURL)
		}
	} else {
		after, found = strings.CutPrefix(repoURL,
			fmt.Sprintf("https://%s.ghe.com/", tenant))
		if !found {
			return "", "", fmt.Errorf("failed to get org and repo from %s", repoURL)
		}
	}

	parts := strings.Split(after, "/")
	return parts[0], parts[1], nil
}
