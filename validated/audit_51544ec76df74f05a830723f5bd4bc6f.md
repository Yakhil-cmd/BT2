### Title
Memory/CPU Exhaustion via Unbounded Recursive Stringification of Untrusted Unit Content Before Depth/Size Validation - ([File: validation.js])

### Summary
`validate()` in `validation.js` computes the unit hash (`objectHash.getUnitHash`) at line 133, which internally recurses over the *entire* untrusted unit content (including `author.definition`) via `getSourceString`/`getJsonSourceString` in `string_utils.js`, **before** the depth/size guard `isTooDeeplyNestedOrHasTooManyNodes(objUnit)` is ever invoked at line 154. An unprivileged unit poster can therefore submit a joint whose `author.definition` (or nested message payload objects) contains an extremely deep/wide nested structure that gets fully recursively stringified — consuming stack and heap — before any size limit is checked. [1](#0-0) [2](#0-1) 

### Finding Description
`validate(objJoint, callbacks, external_conn)` first calls `objectHash.getUnitHash(objUnit)` to check the claimed unit hash: [1](#0-0) 

`getUnitHash` → `getStrippedUnit` → `content_hash: getUnitContentHash(objUnit)` → `getNakedUnit(objUnit)`, which is a full deep clone of the entire unit including `authors[i].definition` (only `payload`/`payload_uri` are stripped from messages): [3](#0-2) 

That naked unit is then passed to `getBase64Hash` → `getSourceString`/`getJsonSourceString`, which recursively walks the whole object graph, building nested string concatenations (`variable.map(stringify).join(',')`) with no depth or node-count limit: [4](#0-3) 

Only *after* this recursive hashing work is done does `validate()` call the actual defense, `isTooDeeplyNestedOrHasTooManyNodes(objUnit)`, which enforces `depthLimit=100` and `nodesLimit=10000`: [2](#0-1) [5](#0-4) 

Because `author.definition` is a free-form nested array structure (`['and', [...]]`, `['or', [...]]`, etc.) supplied by the unit's author and is not validated for shape/size until much later (inside `validateAuthor`/`validateDefinition` in `definition.js`), an attacker can craft a joint with a definition containing thousands of nested array/object levels or hundreds of thousands of sibling nodes. The recursive `stringify` in `getJsonSourceString`/`getSourceString` will process that entire structure — allocating a new string for every node and joining large arrays — while computing the unit hash, well before the 100-deep / 10 000-node guard is reached. This mirrors the Netty `RedisArrayAggregator` bug class: unbounded recursive/iterative allocation while parsing untrusted nested input, with the size/depth check applied only after the expensive processing has already happened.

### Impact Explanation
This is directly reachable by any unprivileged peer submitting a unit/joint for validation (the standard `validate()` entry point used for all incoming units). A single crafted joint can force the node to perform recursive stringification over an attacker-chosen number of nodes/depth, consuming CPU and heap memory proportional to the crafted structure size before the existing depth/size guard has a chance to reject it. Repeated submission of such joints can exhaust available memory or drive excessive CPU usage on validating nodes, degrading the node's ability to validate legitimate units — a denial-of-service condition consistent with "network unable to confirm new units" impact category.

### Likelihood Explanation
High likelihood: the vulnerable code path (`getUnitHash` before `isTooDeeplyNestedOrHasTooManyNodes`) is unconditionally executed for every incoming unit in `validate()`, requires no special privileges, no prior stable unit, and no cooperation from other nodes — only a single crafted joint with a deeply/widely nested `author.definition`.

### Recommendation
Move the `isTooDeeplyNestedOrHasTooManyNodes(objUnit)` (and `isObjectWellFormed`) checks to occur **before** `objectHash.getUnitHash(objUnit)` is computed, so that oversized/overly-nested units are rejected prior to any recursive hashing work. Additionally, consider adding an explicit depth/node-count bound inside `getSourceString`/`getJsonSourceString` themselves (defense in depth), independent of caller ordering, since these functions are also used elsewhere (e.g., `getUnitHashToSign`, ball hashing) on attacker-influenced data.

### Proof of Concept
1. Construct a joint whose `unit.authors[0].definition` is a deeply nested definition tree, e.g. programmatically nest `['and', [ ['sig', {...}], INNER ]]` tens of thousands of levels deep (or alternatively make it very wide, with hundreds of thousands of `or` branches at a shallow depth to blow past the 10 000-node limit while staying under whatever transport size cap exists).
2. Set `unit.unit` to any string (it does not need to match — the hash mismatch is only detected *after* `getUnitHash` finishes computing, so the expensive computation still runs to completion) and submit the joint to `validate()` via the normal joint-processing path.
3. Observe that `objectHash.getUnitHash` → `getNakedUnit` → `getSourceString`/`getJsonSourceString` recurses over the entire crafted `definition` tree, consuming CPU/heap proportional to its size, prior to the `isTooDeeplyNestedOrHasTooManyNodes` check at `validation.js:154` being reached.

function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
}

function isTooDeeplyNestedOrHasTooManyNodes(obj, depthLimit = 100, nodesLimit = 10000) {
	let nodeCount = 0;

	function check(variable, depth){
		if (depth > depthLimit || nodeCount > nodesLimit)
			return true;
		if (variable === null || typeof variable !== "object")
			return false;
		if (Array.isArray(variable)) {
			nodeCount += variable.length;
			for (let v of variable)
				if (check(v, depth + 1))
					return true;
		}
		else {
			nodeCount += Object.keys(variable).length;
			for (let key in variable)
				if (check(variable[key], depth + 1))
					return true;
		}
		return false;
	}

	return check(obj, 1);
}
