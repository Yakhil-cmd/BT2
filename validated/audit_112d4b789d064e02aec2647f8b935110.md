### Title
Release asset filename path traversal allows writes outside the destination directory - (File: pkg/cmd/release/download/download.go)

### Summary
`downloadAsset` passes the release asset's `Name` field, taken verbatim from the GitHub API response, directly into `destinationWriter.Copy`/`makePath`, which builds the output path with `filepath.Join(w.dir, name)`. Because the value is never sanitized against directory-traversal sequences (e.g., `..`), a release asset whose `name` contains `../` segments can cause `gh release download` to write attacker-controlled bytes outside the chosen `--dir`, e.g. into `.git/hooks/` or `.github/workflows/` of the victim's working tree.

### Finding Description
`downloadRun` builds `downloadTarget{url, name: a.Name}` straight from `shared.ReleaseAsset.Name` [1](#0-0)  which is populated directly from the GitHub API JSON response with no path sanitization [2](#0-1) .

`downloadAsset` forwards this `fileName` unchanged into `dest.Check`/`dest.Copy` [3](#0-2) [4](#0-3) .

`makePath` computes the on-disk path with `filepath.Join(w.dir, name)` [5](#0-4) , and `filepath.Join` calls `Clean`, which resolves `..` components relative to `w.dir` rather than rejecting them. `Copy` then creates parent directories with `os.MkdirAll` and writes the file with `os.OpenFile(... O_CREATE|O_TRUNC ...)` [6](#0-5) , so any traversal in `name` is honored.

Note that the only place in this file that does sanitize a server-supplied name is the archive-fallback branch, which applies `filepath.Base(serverFileName)` when deriving a filename from the `Content-Disposition` header [7](#0-6) . No equivalent sanitization exists for `a.Name`, the field used for every named, pattern-matched asset download (the common `gh release download <tag>` / `-p` path). The only other validation applied to `a.Name` is a Windows reserved-filename check [8](#0-7) , which does not address path traversal.

Exploit flow: an attacker who can publish a release with a crafted asset (e.g., in their own repo, a fork, or any repo the victim is asked to run `gh release download` against) sets the asset `name` to something like `../../.git/hooks/post-checkout` or `../../.github/workflows/evil.yml`. When the victim runs `gh release download` in a git working directory, `makePath` resolves the join to a location outside the intended `--dir`, and `Copy` writes the attacker's bytes there — potentially overwriting a git hook or CI workflow file that will later execute.

### Impact Explanation
If GitHub's asset-name validation does not itself reject slashes/`..` in asset display names (this could not be confirmed from the CLI repo alone, since asset name validation happens server-side, not in this codebase), this is a file-write-outside-intended-path primitive that can be escalated to code execution by targeting `.git/hooks/*` (executed automatically by later git operations) or `.github/workflows/*` (executed by GitHub Actions on subsequent pushes), matching the "arbitrary file write / code execution on the victim host" impact class.

### Likelihood Explanation
Requires only that the victim run `gh release download` (with default `--dir` `.` or any target directory) against a repository/release controlled by, or containing an asset uploaded by, the attacker — no elevated privileges are needed on the attacker's side, matching the stated threat model. Feasibility hinges entirely on whether the GitHub release-asset upload API permits `/`/`..` characters in the asset `name` field; that server-side constraint could not be verified from this repository, which is the main source of uncertainty in this finding.

### Recommendation
In `destinationWriter.makePath`/`Copy`, sanitize `name` before joining, e.g. `name = filepath.Base(filepath.Clean(name))` (mirroring the treatment already given to `serverFileName`), and/or verify with `filepath.Rel`/prefix-check that the resolved path stays within `w.dir` before writing, rejecting the download otherwise.

### Proof of Concept
```go
func TestDestinationWriter_PathTraversal(t *testing.T) {
    tmp := t.TempDir()
    dw := destinationWriter{dir: tmp}
    // Simulate a malicious asset name from the release API
    maliciousName := "../../evil-outside-dir.txt"
    err := dw.Copy(maliciousName, strings.NewReader("pwned"))
    require.NoError(t, err)

    // Assert the file did NOT land inside tmp
    resolved := filepath.Join(tmp, maliciousName)
    _, statErr := os.Stat(resolved)
    require.NoError(t, statErr) // demonstrates the escape actually happened

    rel, _ := filepath.Rel(tmp, resolved)
    require.True(t, strings.HasPrefix(rel, ".."), "file escaped destination directory: %s", resolved)
}
```
Extend with an httpmock-based integration test that stubs a release containing an asset named `../../.git/hooks/post-checkout`, runs `downloadRun`, and asserts no file exists under `.git/` after the command completes.
