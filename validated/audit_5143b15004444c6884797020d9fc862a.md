### Title
Below-threshold signer double-counts phantom STX-only sBTC rewards via bond co-claim in `claim-rewards` / `settle-rewards` - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`pox-5.clar`'s reward-accounting path lets a signer who was **not** a member of a reward cycle's active signer set (i.e., whose staked amount never crossed `SIGNER_SET_MIN_USTX` and who therefore has zero weight/shares in that cycle per `signer_set.rs`'s `pox_5_make_signer_set`) still advance that cycle's `signer-rewards-per-token-for-cycle` snapshot for its STX-only stakers when the signer's *bond* participant triggers a reward claim. This breaks the equality "rewards distributed to a signer's stakers for a cycle == rewards actually earned/committed for that signer in that cycle," crediting a staker (`alice`) with claimable sBTC rewards for a cycle her signer never participated in.

### Finding Description
The regression test `below-threshold signer leaks phantom stx-only rewards via bond co-claim` (`contrib/core-contract-tests/tests/pox-5/pox-5.test.ts:6064-6158`) demonstrates the exact mechanics:

- `signer1` has a bond participant (`bob`) whose backing uSTX is far below `SIGNER_SET_MIN_USTX`, and an STX-only staker (`alice`) whose stake is also insufficient on its own to reach the threshold. Combined, `bob`'s bond uSTX + `alice`'s STX-only stake still stay under `SIGNER_SET_MIN_USTX`, so `signer1` is correctly excluded from the active signer set for cycle 1 (`isSignerInCycle({ signer: signer1, cycle: 1 })` is `false`, and `getSignerSharesStakedForCycle(signer1, 1, null)` is `0`) [1](#0-0) .
- A second signer (`signer2`) with an independently-above-threshold STX-only staker (`charlie`) advances the *global* STX-only rewards-per-token for cycle 1, which is necessary to expose the bug (otherwise the global stays zero and the flaw is masked) [1](#0-0) .
- Rewards are funded and `calculateRewards` is run, followed by `signer1`'s bond claim (`testSigner.claimRewards([0n], 1n)`), which internally in `pox-5.clar` calls the reward-settlement logic (referred to in the surrounding comments as `settle-rewards`) for signer1's cycle-1 STX-only window [2](#0-1) .
- The test's comment states the root cause directly: *"Trigger the bond claim. settle-rewards runs on signer1's STX-only cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle."* i.e. the bond-claim code path invokes the same rewards-per-token settlement routine used for STX-only accounting even when the signer's STX-only shares for that cycle are `0`, and that routine advances (writes) `signer-rewards-per-token-for-cycle` using the *global* rewards-per-token snapshot without gating on whether the signer was actually a cycle member [3](#0-2) .
- The assertion `expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n)` is explicitly annotated as *"Fails on the unfixed code because the snapshot was advanced past a window signer1 didn't earn in"* [4](#0-3) .

The underlying design in `pox-5.clar` computes `signer-manager`-level `get-earned-staker-rewards` from the delta between the signer's settled and current global rewards-per-token snapshot [5](#0-4) , and `claim-staker-rewards` in `signer-manager.clar` trusts this settlement unconditionally, transferring sBTC out based on it [6](#0-5) . Because the equality "signer's settled rewards-per-token snapshot advances only for cycles where the signer had nonzero shares" is not enforced when the *bond* claim path triggers settlement for the co-located STX-only accounting, a staker whose signer never met `SIGNER_SET_MIN_USTX` can be credited rewards for a cycle it was not part of.

### Impact Explanation
This is a reward-accounting equality break: sBTC rewards become claimable by a staker (`alice`) for a reward cycle her signer never participated in and never earned any share of. Left unaddressed at scale, this either double-counts/over-distributes finite sBTC rewards (paying out sBTC that was not backed by that signer's actual contribution for the cycle) or drains reward funds intended for legitimately-participating signers/stakers — matching the "sBTC rewards paid that were not earned or counted twice" analog class called out in scope. Given reward payouts are financial (sBTC transferred out via `claim-staker-rewards`/`sbtc-token transfer`), this is a High-severity reward integrity defect.

### Likelihood Explanation
The trigger requires only: (1) a signer whose combined bond + STX-only stake stays below `SIGNER_SET_MIN_USTX` for a given cycle (an ordinary, easily-arranged condition, not requiring any privileged role), (2) at least one other signer whose STX-only stakers push the global rewards-per-token above zero for that cycle, and (3) the below-threshold signer's bond participant calling the permissionless `claim-rewards` entry point. All actions are performed by ordinary unprivileged stakers/signer operators using public entry points (`stake`, `registerForBond`, `claimRewards`), so likelihood is high — the unit test reproduces it deterministically without any admin/miner/other-user-key assumptions.

### Recommendation
Gate the rewards-per-token settlement update so that a signer's `signer-rewards-per-token-for-cycle` snapshot is only advanced for cycles in which that signer was actually a member of the active signer/reward set (i.e., `is-signer-in-cycle`/nonzero shares for that cycle). The bond-claim path must not invoke the STX-only settlement logic for a cycle/signer pair where `get-signer-shares-staked-for-cycle` is zero, or must explicitly skip/zero the earned delta in that case, ensuring `earned = shares * (global_rpt_now - global_rpt_at_settlement)` never yields a nonzero credit for zero-share windows.

### Proof of Concept
The existing regression test in the repository already reproduces the issue end-to-end: [7](#0-6) 
1. `signer1` registers a bond with `bob` whose backing uSTX is below `SIGNER_SET_MIN_USTX`.
2. `alice` stakes STX-only to `signer1`, sized so `alice`'s stake + `bob`'s bond uSTX together stay below `SIGNER_SET_MIN_USTX` — confirmed via `isSignerInCycle({ signer: signer1, cycle: 1 })` returning `false`.
3. `signer2` (independently above threshold) receives an STX-only stake from `charlie`, advancing the global STX-only rewards-per-token for cycle 1.
4. sBTC is transferred into the pox-5 contract and rewards are calculated (`calculateRewards`).
5. `signer1`'s bond participant triggers `claimRewards([0n], 1n)`.
6. Result: `getEarnedStakerRewards(alice, 1, null)` becomes nonzero even though `signer1` earned `0` for cycle 1 and was never a cycle member — demonstrating rewards credited that were never earned.

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
