### Title
Unbounded recursion in `replaceInTemplate()` allows attacker-controlled `definition_template` messages to crash full nodes during address-definition evaluation - (File: definition.js)

### Summary
`MAX_UNIT_LENGTH` is 5,000,000 bytes [1](#0-0) , and a `definition_template` message's payload is validated only with `isArrayOfLength(payload, 2)` — no depth or complexity check is performed on its contents [2](#0-1) [3](#0-2) . This is analogous to the polkit CVE-2025-7519 bug class: a deeply nested, attacker-supplied tree structure that is walked with unbounded recursion causes a stack-related failure. In ocore this manifests as unbounded JS recursion (`RangeError: Maximum call stack size exceeded`) in `replaceInTemplate`/`replaceInVar`, reachable by any unprivileged unit poster.

### Finding Description
`replaceInTemplate` recursively substitutes `$name` placeholders throughout an entire template array/object tree with no depth limit at all: [4](#0-3) 

This function is invoked whenever an address (or asset) definition contains the `['definition template', [unit, params]]` opcode. The referenced `unit`'s `definition_template` payload is fetched from storage, `JSON.parse`d, and passed straight into `replaceInTemplate` before being fed into `evaluate`: [5](#0-4) 

Critically, when the `definition_template` message itself was originally posted (in an ordinary, unprivileged unit), its payload only had to pass a superficial check — `isArrayOfLength(payload, 2)` — both in the general unit validator and in the AA validator: [3](#0-2) [2](#0-1) 

Unlike every other recursive walker in the codebase — `validate()` in `aa_validation.js` (`MAX_DEPTH = 100`) [6](#0-5) [7](#0-6) , `evaluate()` in `formula/validation.js` (`depth > 100` check) [8](#0-7) , `evaluate()` in `definition.js` (bounded indirectly by `MAX_COMPLEXITY`/`MAX_OPS`) [9](#0-8) , and the light-wallet getter-args guard `isTooDeeplyNestedOrHasTooManyNodes` (`depthLimit = 100`) [10](#0-9)  — `replaceInTemplate` has **no** such depth guard, and no equivalent check is applied to the raw template content when it is first stored as a `definition_template` message.

Given `MAX_UNIT_LENGTH = 5e6` bytes [1](#0-0) , an attacker can trivially craft a `definition_template` payload consisting of tens or hundreds of thousands of nested array levels (e.g. `[[[[...1...]]]]`), each level costing only 2 bytes (`[`/`]`), well within the unit size cap. Because `evaluate()`'s `'definition template'` case does not itself bound the size/depth of the template it fetches before calling `replaceInTemplate`, and `replaceInTemplate` recurses synchronously with no `setImmediate`/depth-check pattern (unlike `formula/validation.js`'s `evaluate`), this drives an unbounded synchronous call stack.

### Impact Explanation
Any node (full node or witness) that evaluates an address definition referencing the malicious `definition template` — which happens during ordinary unit validation whenever a unit is authored by (or co-signed by) an address using that opcode — will recurse until it hits the V8 stack limit, throwing an uncaught `RangeError`. Because this exception is thrown synchronously inside a DB-callback chain rather than being funneled through the `cb`/`try/catch` used for `NoVarException`, it is **not caught** by the surrounding `try { ... } catch(e) { if (e instanceof NoVarException) ... else throw e; }` block in `evaluate()`'s `'definition template'` case [11](#0-10)  — a `RangeError` will be rethrown, propagating up as an unhandled exception and crashing the node process (or, in the wallet's shared-address flow via `validateAddressDefinitionTemplate`/`Definition.replaceInTemplate`, crashing the wallet process at proposal-review time) [12](#0-11) . If triggered identically across all full nodes/witnesses that must validate the same unit, this can prevent the network from confirming units referencing that address definition, i.e. cause a denial of validation/availability rather than a memory-corruption bug (JS engines don't exhibit OOB-write-style memory corruption from stack overflow the way the original C-based polkit bug does).

### Likelihood Explanation
High reachability: any unpriviledged party can post a `definition_template` message (no special permission required) and later reference it from any address definition (their own or a shared/multi-sig address they co-author) using `['definition template', [unit, params]]`. No existing validation path rejects deeply nested templates prior to `replaceInTemplate` being invoked.

### Recommendation
- Add a strict depth/size guard on `definition_template` payloads at the time they are posted (in `validation.js`'s `definition_template` case and in `aa_validation.js`'s `'definition_template'` case), analogous to `isTooDeeplyNestedOrHasTooManyNodes`.
- Add an explicit depth counter/limit inside `replaceInVar`/`replaceInTemplate` in `definition.js`, mirroring the `MAX_DEPTH` pattern used in `aa_validation.js`'s `validate()`.
- Ensure any exception thrown from deep recursion is caught and converted into a normal validation error (`cb("...")`) rather than rethrown, so a single malformed template cannot crash the validating process.

### Proof of Concept
1. Post unit A containing message `{app: 'definition_template', payload: [T, {}]}` where `T` is a deeply nested array such as `JSON.parse('[' .repeat(200000) + '1' + ']'.repeat(200000))` (well under 5 MB unit size limit).
2. Post unit B whose author address definition (or an address referencing it via the `address`/`definition template` composition) is `['definition template', ['<hash of unit A>', {}]]`.
3. When any node validates a unit spent from/authored by that address (via `validateDefinition`/`validateAuthentifiers` in `definition.js`), it fetches template T, calls `replaceInTemplate(T, {})`, which recurses ~200,000 levels deep in `replaceInVar`, exceeding V8's default call-stack limit and throwing an uncaught `RangeError` that is not handled by the local `try/catch`, crashing the validating node process.

```javascript
function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
```

```javascript
function isTooDeeplyNestedOrHasTooManyNodes(obj, depthLimit = 100, nodesLimit = 10000) {
	let nodeCount = 0;

	function check(variable, depth){
		if (depth > depthLimit || nodeCount > nodesLimit)
			return true;
		if (variable === null || typeof variable !== "object")
			return false;
		if (Array.isArray(variable)) {
			nodeCount += variable.length;
			for (let v of variable)
				if (check(v, depth + 1))
					return true;
		}
		else {
			nodeCount += Object.keys(variable).length;
			for (let key in variable)
				if (check(variable[key], depth + 1))
					return true;
		}
		return false;
	}

	return check(obj, 1);
```
