### Title
Blacklisted pool owner can permanently freeze accrued protocol revenue - (File: `contracts/pool/src/ops/revenue.rs`)

### Summary

`Controller::claim_revenue` is permissionless but exposes no beneficiary parameter. [1](#0-0)  The pool claim always pays the Ownable owner rather than an administrator-selected payout address. [2](#0-1) 

### Finding Description

The controller's `claim_revenue(caller, assets)` entrypoint can be invoked by any authorizing caller and claims revenue for the supplied hub assets. [1](#0-0) 

The pool's corresponding `claim_revenue(env, hub_asset)` entrypoint accepts only the market key and delegates to `ops::revenue::apply`. [3](#0-2) 

`ops::revenue::apply` reads `ownable::get_owner(env)` and transfers the entire claimed amount to that stored owner address. [4](#0-3)  The pool architecture identifies the controller as that owner, and construction stores the supplied administrator as the Ownable owner. [5](#0-4) [6](#0-5) 

The claim burns claimable revenue shares and debits cash before the token transfer, but the outbound `transfer` occurs in the same invocation and has no alternate-recipient fallback. [7](#0-6) [8](#0-7)  Therefore, if the underlying asset contract rejects transfers to the pool owner, such as after blacklisting or deauthorizing the controller, every claim reverts and leaves the revenue unclaimed. [4](#0-3) 

### Impact Explanation

All currently accrued and subsequently accrued protocol revenue for the affected asset remains locked as unclaimed yield while the fixed pool owner cannot receive that asset. [2](#0-1)  Because neither the controller nor pool claim interface exposes a payout address, there is no in-contract path to redirect the revenue to another beneficiary. [1](#0-0) [3](#0-2) 

### Likelihood Explanation

The trigger requires the asset issuer or token administrator to blacklist, deauthorize, or otherwise reject transfers to the pool owner. [8](#0-7)  This is an external administrative action with lower likelihood than ordinary user error, but once it occurs the claim failure is deterministic and repeatable. [4](#0-3) 

### Recommendation

Decouple the revenue payout destination from Ownable ownership by adding a `recipient` or `beneficiary` parameter to the pool claim and having the controller pass its configured accumulator. [9](#0-8) [4](#0-3)  Alternatively, store a dedicated revenue-recipient address that governance can rotate independently of the pool owner, while keeping the pool entrypoint owner-authorized. [3](#0-2) 

### Proof of Concept

1. Deploy the pool with the controller as its Ownable owner and create a market for an asset whose issuer can blacklist or deauthorize recipients. [6](#0-5) 
2. Accrue positive protocol revenue in that market so `burn_claimable_revenue` produces a nonzero transfer amount. [10](#0-9) 
3. Have the asset administrator blacklist or deauthorize the controller so `transfer(pool, controller, amount)` panics. [8](#0-7) 
4. Call `Controller::claim_revenue(caller, vec![hub_asset])` from any unprivileged account. [1](#0-0) 
5. The nested pool claim reaches `ownable::get_owner` and attempts the fixed-owner payout, the token transfer fails, and the entire claim aborts. [4](#0-3) 
6. Repeating the call cannot succeed because neither endpoint supplies an alternative recipient. [11](#0-10) [9](#0-8)

/// Claims all currently claimable revenue and pays it to the Ownable owner.
/// Emits a market state snapshot in all cases. If nothing is claimable, returns
/// a mutation with `actual_amount` zero and performs no transfer.
pub(crate) fn apply(env: &Env, hub_asset: HubAssetKey) -> PoolAmountMutation {
    let outcome = accounting(env, hub_asset);

    if outcome.mutation.actual_amount != 0 {
        let owner = ownable::get_owner(env)
            .unwrap_or_else(|| panic_with_error!(env, GenericError::OwnerNotSet));
        outcome
            .cache
            .transfer_out(&owner, outcome.mutation.actual_amount);
```

pub(crate) fn accounting(env: &Env, hub_asset: HubAssetKey) -> RevenueOutcome {
    let mut cache = ops::renewed_market(env, &hub_asset);

    let net_transfer = cache.burn_claimable_revenue();

    guards::require_utilization_below_max(env, &cache);
    guards::require_supply_for_debt(env, &cache);
    cache.debit_cash(net_transfer);

    cache.commit();
```
