### Title
Unsanitized CR/ANSI injection via PR title, branch names, and metadata in `printHumanPrPreview` - (File: pkg/cmd/pr/view/view.go)

### Summary
`printHumanPrPreview` writes several attacker-controlled fields — `pr.Title`, `pr.Author.DisplayName()`, `pr.HeadRefName`, `pr.BaseRefName`, label names, milestone title, reviewer/assignee names, and project names — directly to `opts.IO.Out` via `fmt.Fprintf`/`fmt.Fprintln`, bypassing the codebase's own terminal-safety mechanisms. Unlike other content-rendering paths (gist view, run view log, skills list), this function never routes these strings through `iostreams.Untrusted`, `ContentOut`, or `asciisanitizer`, so raw `\r` and other control bytes reach the terminal unmodified.

### Finding Description
`printHumanPrPreview` ( [1](#0-0) ) prints the header line with `cs.Bold(pr.Title)` and the "wants to merge" line with `pr.Author.DisplayName()`, `pr.BaseRefName`, `pr.HeadRefName` directly into `out := opts.IO.Out`. These fields originate from the GraphQL API response for a PR that any unprivileged user can author (title, head branch name) or that is derived from an author's display name.

The codebase has an explicit, purpose-built defense for exactly this class of problem: the `iostreams.Untrusted` type, whose `String()` method sanitizes ANSI/control sequences via `asciisanitizer` before any `fmt` print path emits it ( [2](#0-1) ), and the `ContentOut` writer, which wraps `Out` in an `asciisanitizer` transform for "external content" the application did not author ( [3](#0-2) , start="499" end="508"). Other view/render surfaces consistently use these primitives — e.g. `gh gist view` wraps file content in `iostreams.NewUntrusted` ( [4](#0-3) ) and `gh skills list` calls a `sanitizeForTerminal` helper before printing table fields ( [5](#0-4) ).

`printHumanPrPreview`, `prReviewerList`, `prAssigneeList`, `prLabelList`, and `prProjectList` do none of this — they format `pr.Title`, `pr.Author.DisplayName()`, branch names, label names, milestone titles, and project names as plain Go strings straight into `fmt.Fprintf` calls on `opts.IO.Out` ( [6](#0-5) ). The only field that receives any transformation is `pr.Body`, which passes through `markdown.Render` (glamour) — but title, author, and ref-name fields skip that path entirely and are never checked by `iostreams.ContainsEscapeSequence` or any CR-stripping logic. A PR title such as `"Fix bug\r✔ gh: Paste your GitHub token: "` would be written with a literal `\r` byte, which most terminals interpret as "return to column 0," letting the attacker-controlled string overwrite/redraw content on the same line once the terminal continues printing.

### Impact Explanation
This matches "Terminal output/prompt spoofing" — an attacker can craft a PR/issue title or head branch name (fully attacker-controlled, requires no privileges beyond opening a PR) that redraws the current terminal line with forged prompt-like text (e.g., mimicking a credential prompt) when a victim runs `gh pr view`. Combined with victim confusion, this could lead to credential disclosure if the victim types a token in response to spoofed text, or could mask/alter what appears to be gh's trusted status output.

### Likelihood Explanation
Any GitHub user can open a pull request against a public repo the victim maintains, or open a PR from a fork, setting a title or branch name containing `\r`. The victim only needs to run `gh pr view <number>` on a TTY (the default interactive path, `connectedToTerminal` branch, [7](#0-6) ). This is fully attacker-repeatable and requires no MITM, no local access, and no elevated privileges — matching the stated threat model.

### Recommendation
Wrap all remotely-controlled string fields printed in `printHumanPrPreview` and its helpers (`pr.Title`, `pr.Author.DisplayName()`, `pr.HeadRefName`, `pr.BaseRefName`, `prReviewerList`, `prAssigneeList`, `prLabelList`, `prProjectList`, milestone title, reviewer/assignee/comment author names) in `iostreams.Untrusted` (or otherwise pass them through the `asciisanitizer` transform / `ContentOut`) before printing, consistent with how `gh gist view` and `gh skills list` already treat remote content. Add a regression test asserting `\r` and ESC-based cursor-movement sequences never appear in the rendered output of `printHumanPrPreview` for a PR whose title/branch names contain such bytes.

### Proof of Concept
```go
func TestPrintHumanPrPreview_NoCROrEscapeInjection(t *testing.T) {
    io, _, out, _ := iostreams.Test()
    io.SetStdoutTTY(true)

    pr := &api.PullRequest{
        Title:       "Legit title\r? Paste your GitHub token: ",
        HeadRefName: "main\r\x1b[2Khijacked-branch",
        Number:      1,
        Author:      api.Author{Login: "attacker"},
    }
    opts := &ViewOptions{IO: io, Now: time.Now}

    err := printHumanPrPreview(opts, ghrepo.New("OWNER", "REPO"), pr)
    require.NoError(t, err)

    rendered := out.String()
    assert.NotContains(t, rendered, "\r", "rendered PR preview must not contain raw CR bytes")
    assert.NotContains(t, rendered, "\x1b", "rendered PR preview must not contain raw ESC bytes")
}
```
This test currently fails because `pr.Title` and `pr.HeadRefName` are printed unsanitized at [8](#0-7) .

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}
