### Title
`EnvironmentVariables#interpolate` falls back to Shipit's own process `ENV` for unset `$VAR` references, leaking host secrets into task output - ([File: lib/shipit/environment_variables.rb])

### Summary
`EnvironmentVariables#interpolate` resolves `$WORD` references first against the task/stack-scoped `@env` hash, but silently falls back to Shipit's own process `ENV` when the name is absent from `@env`. Since `deploy.override`/`rollback.override`/task `steps` in `shipit.yml` are read from the very commit being deployed (including PR/review-stack branches), a contributor can add a step referencing any process environment-variable name and have its value escaped and streamed into the visible task log.

### Finding Description
The binding that should hold is: for any `$VAR` interpolated by `Command#interpolated_arguments` while running a task, `value(VAR) == @task.env[VAR] || @stack.env[VAR] || deploy_spec.machine_env[VAR]` (i.e., values approved as part of the deployed ref/spec) — never `Shipit_process.ENV[VAR]`.

That binding is broken in `lib/shipit/environment_variables.rb`: [1](#0-0) 
`interpolate` does `@env.fetch(variable) { ENV[variable] }` — when the referenced variable name is not a key in the merged task env, it reads from `ENV`, the Shipit Rails process's own environment (which may hold `SECRET_KEY_BASE`, DB credentials, etc., especially since the app loads such secrets via `ENV` per `lib/shipit.rb`/`docs/setup.md`).

Code path:
1. `TaskCommands#env` builds the merged env from `Commands#env` (defaults), `@stack.env`, fixed task metadata, `deploy_spec.machine_env`, and `@task.env` — this is the only place values are supposed to be sourced from: [2](#0-1) 
2. `TaskCommands#perform`/`install_dependencies` build a `Command` per step from `deploy_spec.deploy_steps!`/`dependencies_steps!`, which come directly from the checked-out `shipit.yml` (`deploy.override`, etc.) of the commit being deployed: [3](#0-2) 
3. When the task runs, `Command#interpolated_arguments` calls `EnvironmentVariables.with(env).interpolate(argument)` for each argument, and `Command#stream`/`start` spawns and streams that interpolated text: [4](#0-3) [5](#0-4) 
4. This behavior is directly reproduced by the existing test `"#interpolate_environment_variables fallback to ENV"`, confirming `ENV['SHIPIT_TEST']` leaks into command output when not present in the task's `env`: [6](#0-5) 

The `shipit.yml` content for the step comes from the deployed commit itself (checked out into `@task.working_directory` before `DeploySpec::FileSystem.new` reads it), so a contributor pushing to a branch/PR that becomes deployable (e.g. a review-stack PR branch, or any branch merged into a tracked stack branch) fully controls the step text, including which `$VAR` names are referenced — while having no control over, and no visibility into, what is set in Shipit's own process `ENV`.

None of the existing guards address this: `EnvironmentVariables#permit` (used for `deploy.variables`/`task.variables` whitelisting of user-*supplied* `env` params from the UI/API) is a separate code path from `interpolate`, and is not invoked when building the merged `env` hash consumed by `interpolate`. `filter_deploy_envs`/`filter_task_envs` restrict what a human can pass in via HTTP params, but do not restrict what names a `shipit.yml` step's `$VAR` references may resolve against.

### Impact Explanation
If any secret that Shipit's own process reads from `ENV` (e.g., `SECRET_KEY_BASE`, database URLs/passwords, other credentials loaded via `ENV` per `lib/shipit.rb`) is not also present as a key in the task/stack env, a shipit.yml step such as `echo $SECRET_KEY_BASE` will resolve, shell-escape, and stream that value into the task output page, which is visible to the PR author/contributor whose commit is being deployed. This matches "exfiltration of ... deploy-time secrets" (Critical). The blast radius is scoped to whichever repository/stack is deployed with the malicious step, but is trivially repeatable against any repository onboarded to the same Shipit instance, since the leaked value (Shipit process env) is shared across all stacks/tenants on that host.

### Likelihood Explanation
Preconditions: (1) the attacker's `shipit.yml` change must reach a commit that gets deployed by Shipit — either via a review-stack deploy of the attacker's own PR branch (if the repo has review stacks configured, note `continuous_deployment: false` by default per `ReviewStackAdapter#stack_attributes`, so an authorized user typically must click "Deploy"), or via the change being merged to the tracked branch; (2) a secret must actually be present in the Shipit host process's `ENV` under a variable name the attacker can guess (common ones like `SECRET_KEY_BASE`, `DATABASE_URL`, `RAILS_MASTER_KEY` are plausible guesses). Attacker cost is a single crafted commit/PR; the exploit is fully repeatable per deploy of that content.

### Recommendation
Remove the `ENV[variable]` fallback in `EnvironmentVariables#interpolate`; unresolved variables should error or resolve to an empty string, matching the existing `nil`-coercion behavior already tested for missing task-scoped variables (`"#interpolate_environment_variables coerce nil to empty string"`). If a fallback to process configuration is needed, it should go through an explicit, curated allowlist (e.g., `Shipit.env`), not the raw process `ENV`.

### Proof of Concept
In `test/unit/command_test.rb`, replace/extend the existing `"#interpolate_environment_variables fallback to ENV"` test:
```ruby
test "#interpolate_environment_variables must not leak Shipit's process ENV" do
  previous = ENV['FOO_SECRET']
  ENV['FOO_SECRET'] = 'leaked'
  command = Command.new('echo $FOO_SECRET', env: {}, chdir: '.')
  assert_not_includes command.interpolated_arguments, 'leaked'
ensure
  ENV['FOO_SECRET'] = previous
end
```
This currently fails (asserts the opposite of current behavior), demonstrating that `@env.fetch(variable) { ENV[variable] }` in `lib/shipit/environment_variables.rb:25` leaks the host process's environment value into interpolated (and therefore streamed) command output.

    def interpolate(argument)
      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
    end
