### Title
Sanity-check failure path deletes the currently published worktree before the replacement is ready, breaking the atomic-symlink contract - ([File: main.go])

### Summary
The reported Astaria bug is a state-mutation ordering flaw: the contract mutates state (transfers funds out) and only afterward computes a value (`balanceOf(this)`) that should have been captured *before* the mutation, corrupting global accounting for every future user. The strongest reachable analog in `git-sync` is in `repoSync.SyncRepo`, where the code removes the *currently published* worktree directory before a replacement worktree exists and before the symlink is repointed, i.e. it acts on post/mid-mutation state instead of preserving the pre-mutation state until the new state is safely committed.

### Finding Description
`SyncRepo` first resolves the worktree currently referenced by the published symlink: [1](#0-0) 

If the remote hash equals the currently synced hash but the on-disk worktree fails `sanityCheckWorktree`, the code immediately deletes that worktree's directory via `removeWorktree` (which calls `os.RemoveAll` on the path the symlink currently targets), and only afterward marks `currentHash = ""`: [2](#0-1) 

`removeWorktree` performs the destructive action unconditionally once called: [3](#0-2) 

The symlink itself (`git.link`) is not repointed at this stage — that only happens later, inside the `if changed { ... }` block via `publishSymlink`, after `createWorktree`/`configureWorktree` finish: [4](#0-3) 

This is the same root-cause pattern as H-33: an operation (deleting the live/published data) is executed using the *current* published state before the replacement state exists, rather than deferring the destructive action until after the new worktree is created and the symlink is atomically flipped. The documented atomicity contract explicitly promises consumers that the symlink "is updated atomically and should always be valid," implying the target must remain intact until the new one is ready — this code path violates that invariant by removing the target out from under the still-published symlink.

### Impact Explanation
Between the `os.RemoveAll` call and the eventual `publishSymlink` call, the symlink at `--link` points to a directory that no longer exists. Any consumer (e.g., an application container in the sidecar pattern) reading through the symlink during this window will see `ENOENT` or a broken/partial tree instead of the last-known-good content. If `createWorktree`/`configureWorktree` subsequently fail (e.g., transient git error, disk pressure, credential refresh failure encountered mid-loop, or process restart/crash between the delete and the publish), `SyncRepo` returns an error and no new worktree/symlink is ever published, leaving the consumer permanently broken until a future successful sync — a persistent sync/service denial rather than the intended graceful continuation on a stale-but-valid checkout. This directly maps to the accepted impact class "publishing wrong or partial content" and "persistent sync denial."

### Likelihood Explanation
This path triggers whenever `sanityCheckWorktree` fails for the currently-synced hash (e.g., the worktree directory was tampered with, partially written, or corrupted between syncs, or the repo's `.git` metadata is inconsistent — situations reachable from environment/host issues or an attacker with write access to the shared volume, which is explicitly in scope as "path handling under --root"). No special flags are required; this is on the default `SyncRepo` loop path. The window of exposure is small in the common case (create+configure are usually fast) but grows with clone size, submodule updates, or transient git/network failures, and any failure during that window results in the described denial.

### Recommendation
Do not delete the currently published worktree until the replacement worktree has been fully created, configured, and the symlink has been atomically repointed to it. Instead of calling `removeWorktree(ctx, currentWorktree)` immediately upon sanity-check failure, treat the failure the same way a hash change is treated: leave the old worktree in place, build the new worktree under a fresh path (`createWorktree` already guards against path collisions), publish the symlink to the new worktree, and only then clean up the old (now-stale) worktree via the existing `removeStaleWorktrees`/`touch`-based staleness mechanism, mirroring the existing safe pattern already used later in the same function (touch-then-defer-delete on `currentWorktree.Path()` after a successful publish).

### Proof of Concept
1. Start `git-sync` with `--period` short enough to observe overlap, syncing a ref that has already succeeded once (so `currentHash == remoteHash`).
2. Externally corrupt or partially delete a file inside the currently published worktree directory (`$ROOT/.worktrees/<hash>`) so that `sanityCheckWorktree` returns `false` on the next loop iteration — this is directly reachable to anyone with write access to the shared `--root` volume (e.g., a compromised sidecar or shared `emptyDir` in Kubernetes).
3. Simultaneously (or via induced fault injection, e.g., killing the `git` binary mid-`worktree add`) cause `createWorktree` in the same `SyncRepo` call to fail.
4. Observe that: (a) `$ROOT/link` now points to a path that `os.RemoveAll` has already deleted, so any consumer reading through the symlink gets `ENOENT`; (b) `SyncRepo` returns an error, so `git.cleanup` and subsequent retries operate with `currentHash == ""`/no valid worktree, and the consumer-visible symlink remains broken across failed retries until a fully successful sync occurs — reproducing the "persistent sync denial" / "publishing wrong or partial content" outcome.

// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}
