`POX_5_SIGNER_DOMAIN` in `pox-5.clar` explicitly includes `chain-id: chain-id`, where `chain-id` is Clarity's built-in global that resolves to the actual executing chain's ID (distinct for mainnet vs. testnet), not a hardcoded or omitted value. [1](#0-0)  This matches the Rust-side helper `make_pox_5_signed_data_domain`, which parameterizes the SIP-018 domain tuple by `chain_id: u32` and is used to build `make_pox_5_signer_grant_message_hash` / `make_pox_5_signer_grant_signature`. [2](#0-1)  Because the domain's `chain-id` field feeds into `structured_data_message_hash`, a signature generated under one chain's domain produces a different message hash — and thus fails verification — under another chain's domain, exactly as intended by SIP-018 domain separation. [3](#0-2) 

The target cited in the question, `make_pox_addr` in `stackslib/src/chainstate/stacks/boot/mod.rs`, constructs a `PoxAddress` from version/hashbytes and has no relationship to signer-grant domain construction, chain-id handling, or signature verification, so there is no code path connecting that function to the claimed cross-chain replay. [4](#0-3) 

The premise that `POX_5_SIGNER_DOMAIN` "omits chain-id" is factually incorrect — the domain includes chain-id sourced from Clarity's `chain-id` global, and both the Clarity contract and the Rust signature-generation/verification helpers correctly separate signatures by chain, matching the pattern already established for pox-4. No divergence in the claimed equality was found.

    /// Compute the hash of the `grant-authorization` message that is signed
    /// by a signer key when authorizing a `signer-manager` contract to
    /// register the corresponding signer via pox-5's `grant-signer-key`.
    pub fn make_pox_5_signer_grant_message_hash(
        signer_manager: &PrincipalData,
        auth_id: u128,
        chain_id: u32,
    ) -> Sha256Sum {
        let domain_tuple = make_pox_5_signed_data_domain(chain_id);
        let data_tuple = Value::Tuple(
            TupleData::from_data(vec![
                (
                    ClarityName::from_literal("topic"),
                    Value::string_ascii_from_bytes("grant-authorization".into()).unwrap(),
                ),
                (
                    ClarityName::from_literal("signer-manager"),
                    Value::Principal(signer_manager.clone()),
                ),
                (ClarityName::from_literal("auth-id"), Value::UInt(auth_id)),
            ])
            .expect("Error creating signature hash"),
        );
        structured_data_message_hash(data_tuple, domain_tuple)
    }

    /// Sign a pox-5 `grant-authorization` message with `signer_key`.
    pub fn make_pox_5_signer_grant_signature(
        signer_manager: &PrincipalData,
        auth_id: u128,
        chain_id: u32,
        signer_key: &Secp256k1PrivateKey,
    ) -> Result<MessageSignature, &'static str> {
        let msg_hash = make_pox_5_signer_grant_message_hash(signer_manager, auth_id, chain_id);
        signer_key.sign(msg_hash.as_bytes())
