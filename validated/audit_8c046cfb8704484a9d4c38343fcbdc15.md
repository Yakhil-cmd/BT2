### Title
Signature-selection org (`repository_owner`) is decoupled from the actual mutated repository (`Handler#repository_name`), allowing cross-tenant webhook forgery when any configured org has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC secret using `repository_owner`, which falls back from `repository.owner.login` to `organization.login` when the `repository.owner` key is absent. `Handlers::Handler#repository_name`, used by every handler to look up the actual `Repository`/`Stack` to mutate, reads `repository.full_name` directly and does not require `repository.owner` to be present. An attacker can therefore craft a body whose `organization.login` points at an org with no `webhook_secret` configured (or whose secret is otherwise weak/absent), while `repository.full_name` points at an arbitrary victim repository, causing signature verification to pass for the wrong reason and the handler to still act on the victim's records.

### Finding Description
Broken binding: `organization whose secret admitted this request (repository_owner)` == `organization that owns the repository mutated by the handler (Handler#repository_name -> Repository.from_github_repo_name)`. This equality is not enforced.

- `repository_owner` in `app/controllers/shipit/webhooks_controller.rb:59-62` computes: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [1](#0-0) 
- `verify_signature` (lines 24-30) uses this value to pick the `GitHubApp` instance and check the HMAC signature against `@webhook_secret` for that org. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) returns `true` unconditionally when `webhook_secret` is blank: `return true unless webhook_secret`. [3](#0-2) 
- After signature acceptance, `WebhooksController#create` dispatches the full raw payload to handlers selected purely by the `X-Github-Event` header via `Shipit::Webhooks.for_event(event)`. [4](#0-3) 
- Every handler resolves its target repository independently via `Handler#repository_name`, which reads `payload.dig('repository', 'full_name')` with no cross-check against `repository.owner` or `organization.login`. [5](#0-4) 

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "organization": {"login": "secretless-org"},
  "repository": {"full_name": "victim-org/victim-repo"},
  "ref": "refs/heads/master",
  "after": "deadbeef..."
}
```
Because `repository.owner` is omitted, `repository_owner` resolves to `"secretless-org"` (an org configured in `github_apps` with no `webhook_secret`), so `verify_webhook_signature` short-circuits to `true` without checking any signature. `PushHandler#process` then runs `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }` against `victim-org/victim-repo`'s real `Stack` records, resolved via `Repository.from_github_repo_name(repository_name)` in `Handler#stacks`. [6](#0-5) 

Existing guards do not stop this: `drop_unhandled_event` only checks that the event type has a registered handler, not tenant identity; `ExplicitParameters` schemas (e.g. `PushHandler`'s `requires :ref, :after`) validate payload shape, not organization consistency; there is no code anywhere that asserts `repository.owner.login == organization.login` or that the org used for signing matches the org owning `repository.full_name`.

### Impact Explanation
An attacker who knows (or can guess) that some configured GitHub org/app entry lacks a `webhook_secret` can forge webhooks that mutate a completely different, victim organization's `Stack`/`Repository`/`Task`/`Team` records — e.g. triggering `sync_github` on push events, altering commit status via `StatusHandler`, adding/removing team members via `MembershipHandler`, or manipulating pull-request-driven stack state via the `PullRequest::*Handler`s — all against repositories the attacker does not own and never authenticated for. This is a record-mutation-for-unauthenticated-tenant scenario, matching the Critical category ("a payload for one repository mutating another's stack, commit, task or team").

### Likelihood Explanation
Preconditions: at least one org/app entry in the host's Shipit `github_apps` configuration must have no `webhook_secret` set (the code explicitly supports and short-circuits this case), and that org's login must be discoverable/guessable by the attacker (e.g. a legacy/default/demo app entry, or one visible via the Shipit UI/API for public stacks). No Shipit session, API token, or GitHub secret is required — only network access to `POST /webhooks` and knowledge of a valid configured-but-secret-less organization login and a target repository's `full_name`. This is fully repeatable for any handler type by varying `X-Github-Event` and is not rate-limited by any check in this controller.

### Recommendation
Enforce that the organization used to authenticate the webhook is the same organization that owns the repository being mutated: require `repository.owner.login` (or `organization.login`) to be present and to match the actual persisted `Repository#owner`/namespace of `repository.full_name` before dispatching to handlers, and reject payloads where these fields are missing or inconsistent. Additionally, do not treat an org with a blank `webhook_secret` as an automatic pass; either require all configured orgs to have a `webhook_secret`, or restrict secret-less orgs from being usable as the authenticating identity for any repository outside their own namespace.

### Proof of Concept
Minitest under `test/controllers/webhooks_controller_test.rb` (existing suite):
1. Seed two GitHub app configs: `victim-org` with a real `webhook_secret`, and `secretless-org` with `webhook_secret` unset/nil.
2. Create a real `Stack`/`Repository` under `victim-org/victim-repo`.
3. For each of `push`, `status`, `membership`, `check_suite`, and each `pull_request` action:
   - POST to `/webhooks` with `X-Github-Event` set accordingly, no `X-Hub-Signature` header (or an arbitrary invalid one), and JSON body containing `"organization": {"login": "secretless-org"}` plus `"repository": {"full_name": "victim-org/victim-repo"}` (owner key omitted) and the handler-required fields.
   - Assert response is `200 OK` (not `422`), i.e. `verify_signature` passed using `secretless-org`'s (absent) secret — asserting `repository_owner` resolved to `"secretless-org"` while `Handler#repository_name` resolved to `"victim-org/victim-repo"`.
   - Assert the corresponding side effect occurred on the victim's real record (e.g. `Stack#sync_github` invoked, `Team` membership changed, `CommitStatus`/`CheckRun` updated for `victim-org/victim-repo`), proving the equality `repository_owner == organization owning mutated repository` was violated while the mutation still succeeded.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)

    end
