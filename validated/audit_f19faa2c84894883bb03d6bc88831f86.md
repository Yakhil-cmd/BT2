### Title
Uncaught exception via non-finite number in unit header causes node crash - (File: object_length.js)

### Summary
`object_length.getHeadersSize()`, invoked from `validation.js` while validating a freshly posted unit, recurses over the *entire* unit header — including the `authors` array — before that array's per-field structure has been validated. If any numeric value nested anywhere in the still-unvalidated header is non-finite (`Infinity`/`-Infinity`/`NaN`), the internal `getLength()` helper `throw`s synchronously, and unlike the sibling call `getTotalPayloadSize()` (which is wrapped in `try/catch`), the `getHeadersSize()` call site has no exception handling at all.

### Finding Description
In `validation.js:257-266` (function `validate`), two size-computation helpers are called back-to-back: [1](#0-0) 

`getTotalPayloadSize()` is defensively wrapped in `try { ... } catch(e) { return callbacks.ifJointError(...) }`, but `getHeadersSize()` on line 257 is called completely unprotected.

`getHeadersSize()` builds `objHeader` from a `_.cloneDeep(objUnit)` with only a handful of top-level fields stripped (`unit`, `headers_commission`, `payload_commission`, `oversize_fee`, `actual_tps_fee`, `main_chain_index`, `messages`, `parent_units`). Notably, `tps_fee` deletion is commented out, and fields such as `authors`, `witnesses`, `alt`, `witness_list_unit`, `last_ball`, `last_ball_unit`, `earned_headers_commission_recipients` remain in the object that gets measured: [2](#0-1) 

`getLength()` recursively walks this object and explicitly throws for any non-finite number: [3](#0-2) 

```
case "number":
    if (!isFinite(value))
        throw Error("invalid number: " + value);
```

Crucially, `getHeadersSize()` is invoked at `validation.js:257`, which is *before* the per-author field/type validation that happens later in the same function (author address/definition/authentifier checks occur starting at line ~271-320 and in `validateAuthor`, called only after the mutex lock at line 357). Nothing before line 257 constrains the shape or numeric ranges of values nested inside `objUnit.authors`, `objUnit.witnesses`, `objUnit.alt`, etc. (only top-level `hasFieldsExcept(objUnit, [...])` is checked at line 190, which does not recurse into these sub-objects).

Since the joint arrives as raw JSON text and is deserialized with `JSON.parse`, an attacker can smuggle a non-finite JS number into any nested attacker-controlled field via an over-large numeric literal such as `1e400`, which `JSON.parse` legally converts to `Infinity` even though `Infinity` itself is not valid JSON syntax. For example, adding an extra numeric property with value `1e400` inside an `authors[i]` object (or inside `alt`, `witnesses`, etc.) will not be rejected by any check preceding `getHeadersSize()`, and will cause `getLength()` to throw synchronously and uncaught out of `validate()`.

This mirrors the CVE-2022-41841 bug class: a crash triggered by malformed/edge-case input reached during an early parsing/measurement phase that runs before the input has been fully structurally validated — here, a thrown JS exception plays the role of the null-pointer crash.

### Impact Explanation
An uncaught exception thrown out of `validation.validate()` propagates up the synchronous call stack of whichever caller triggered validation (unit received from network, submitted via light client, etc.). ocore installs a global `process.on('uncaughtException', ...)` handler that deliberately re-throws to crash the process: [4](#0-3) 

Thus a single crafted, syntactically valid but semantically malformed unit that reaches `validate()` can crash the receiving full node/hub process, denying it the ability to process/confirm any further units until manually restarted — a network-availability impact (nodes disagreeing on / failing to process new units), matching the required impact bar of "a network unable to confirm new units."

### Likelihood Explanation
The path is reachable by any unprivileged unit poster: any peer or light client can construct and broadcast/post a unit whose JSON representation embeds an over-large numeric literal (e.g. `1e400`) in an unvalidated location such as an extra field within an `authors[i]` entry, `witnesses`, or `alt`. No special privileges, hub cooperation, or prior state are required — only that the unit reaches `validation.validate()` before author/witness field-level validation executes. This makes the trigger straightforward to construct and highly likely to be exploitable, contingent only on the exact ordering of checks in this large function (verified above: `getHeadersSize` runs at line 257, well before author-field validation).

### Recommendation
- Wrap the `getHeadersSize(objUnit)` call in `validation.js` in the same `try/catch` pattern already used for `getTotalPayloadSize`, converting any thrown error into `callbacks.ifJointError(...)`/`ifUnitError(...)` instead of letting it escape uncaught.
- Additionally, harden `getLength()` itself (or its caller) so that non-finite numbers and other structural anomalies are treated as ordinary validation failures rather than thrown exceptions, consistent with the comment in `extractTempData()`: "invalid message, but we don't want to throw exceptions here, so just ignore, and validation will fail later."
- Consider moving basic type/finiteness screening of all unit fields (recursively) earlier, before any size/length computation is performed, so that no code path can reach an unguarded `throw` while processing untrusted, not-yet-validated unit data.

### Proof of Concept
1. Craft a unit JSON with a valid top-level structure that would otherwise pass early checks (valid `unit` hash for the crafted body, valid `version`/`alt`, valid `parent_units`/`last_ball`/`last_ball_unit`, valid `headers_commission`/`payload_commission` placeholders, etc.).
2. Inside `authors[0]` (or any other field consumed by `getHeadersSize`'s cloned header but not yet field-validated at line 257), add an extra property whose value is the literal `1e400`, e.g.:
   ```json
   "authors": [{
     "address": "SOME32CHARADDRESS...",
     "authentifiers": { "r": "..." },
     "x": 1e400
   }]
   ```
   Since `JSON.parse('{"x":1e400}')` yields `{ x: Infinity }`, this is valid JSON on the wire but produces a non-finite JS number after parsing.
3. Submit/broadcast this unit so it reaches `validation.validate()` (e.g., via `post_joint` for light clients, or normal broadcast for a full node peer).
4. `validation.js` reaches line 257 `objectLength.getHeadersSize(objUnit)` → `getLength(objHeader, ...)` recurses into the still-unvalidated `authors` array, hits the injected `Infinity`, and throws `Error("invalid number: Infinity")` uncaught.
5. This exception is not caught anywhere in the call chain and reaches `process.on('uncaughtException', ...)` in `network.js`, which re-throws, crashing the node process.

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
}
