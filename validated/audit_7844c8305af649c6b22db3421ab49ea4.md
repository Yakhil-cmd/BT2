### Title
Webhook signature verified against `repository.owner.login` (or `organization.login`) while all event handlers act on the unvalidated `repository.full_name` — cross-organization stack sync/deploy trigger via signature confusion in a multi-tenant Shipit install

### Summary
`WebhooksController#verify_signature` selects **which** GitHub App / webhook secret to check the HMAC against using `repository_owner`, a field read directly out of the *unverified* JSON body. Every webhook handler, however, resolves the actual `Repository`/`Stack` to act on using a **different** field from the same unverified body: `repository.full_name`. Because nothing enforces that `repository.owner.login` and the owner segment of `repository.full_name` agree, an attacker who knows the webhook secret for *one* configured GitHub organization (Org A) can forge a signed payload that is verified using Org A's secret but whose `repository.full_name` points at a stack belonging to a *different* configured organization (Org B), causing Shipit to sync/act on Org B's stack using a signature that was never issued for Org B.

### Finding Description
`WebhooksController#verify_signature` computes the signing organization purely from attacker-controlled JSON: [1](#0-0) [2](#0-1) 

`repository_owner` reads `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`) straight from `request.raw_post` before any signature check has occurred. `Shipit.github(organization: repository_owner)` then looks up the `GitHubApp` instance (and its `webhook_secret`) for that specific organization key, as configured for multi-tenant installs (`docs/setup.md` "Using Multiple Github Applications", `test/dummy/config/secrets_double_github_app.yml`), and only that organization's secret is used for `verify_webhook_signature`: [3](#0-2) [4](#0-3) 

After verification, `create` dispatches the **entire unmodified `params`** hash to the registered handlers: [5](#0-4) 

All handlers (base `Handler`, `PushHandler`, pull-request handlers, etc.) resolve the target `Repository` via a *separate* field, `repository.full_name`, not `repository.owner.login`: [6](#0-5) [7](#0-6) 

Nowhere is `repository.owner.login` (used to select the verifying secret) checked for consistency with `repository.full_name` (used to select the acted-upon repository/stack). This breaks the intended binding: **organization whose secret authenticated the request == repository that gets written/synced**.

### Impact Explanation
In a multi-organization Shipit deployment (explicitly supported and documented: `docs/setup.md` lines 182-209, `lib/shipit.rb#github_organizations`), each organization has its own GitHub App and independent `webhook_secret`. An entity that legitimately controls Org A's GitHub App configuration (and therefore knows Org A's webhook secret — a normal, unprivileged condition for *that* org's own administrator, who has no access to Shipit itself or to Org B's secrets) can:

1. Craft a JSON body: `{"repository": {"owner": {"login": "OrgA"}, "full_name": "OrgB/victim-repo"}, "ref": "refs/heads/master", "after": "<attacker-chosen-sha>"}`.
2. Sign it with Org A's `webhook_secret` over `X-Hub-Signature`.
3. POST it to Shipit's shared `WebhooksController#create` endpoint.

`verify_signature` resolves `Shipit.github(organization: "OrgA")` and successfully verifies the HMAC using Org A's own secret. The event then reaches `PushHandler`, which resolves `Repository.from_github_repo_name("OrgB/victim-repo")` and calls `stack.sync_github(expected_head_sha: attacker_sha)` on Org B's stack — enqueuing `GithubSyncJob` for a stack the attacker has no credentials for. This is an unauthorized cross-organization write against a stack (`Stack#sync_github` → fetches/records commits, can mark the stack deployable, and can feed into continuous-delivery scheduling depending on stack config), triggered entirely with a signature that was never issued for Org B's organization/repository. This matches the report's underlying bug class ("field acted on but never covered by/consistent with what was verified") — here the *organization that authenticated* the webhook is not the same as *the repository that gets acted on*.

### Likelihood Explanation
Requires only that: (a) the target Shipit instance is configured for multiple GitHub organizations (a documented, supported configuration), and (b) the attacker controls the webhook secret of any one of those configured organizations — which is normal, unprivileged knowledge for that organization's own GitHub App administrator, not a Shipit credential. No Shipit session, `ApiClient` token, or `api_clients_secret` is needed; only the ability to send an HTTP POST with a valid HMAC for one tenant's secret.

### Recommendation
In `WebhooksController#verify_signature` (or in the base `Handler`), enforce that the organization used to select the verifying `webhook_secret` matches the owner segment of `repository.full_name` (and, for `membership`/`organization`-scoped events, that `organization.login` matches too) before dispatching to handlers. Reject the webhook if these fields disagree, rather than trusting `full_name` unconditionally downstream.

### Proof of Concept
```ruby
# Shipit configured with two orgs, each with a distinct webhook_secret, per
# test/dummy/config/secrets_double_github_app.yml / docs/setup.md "Using Multiple
# Github Applications".

payload = {
  "ref" => "refs/heads/master",
  "after" => "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository" => {
    "owner" => { "login" => "OrgA" },        # used by verify_signature
    "full_name" => "OrgB/victim-repo"        # used by PushHandler / Repository.from_github_repo_name
  }
}.to_json

signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", org_a_webhook_secret, payload)

post "/webhooks", params: payload, headers: {
  "X-Github-Event" => "push",
  "X-Hub-Signature" => signature
}
# verify_signature resolves Shipit.github(organization: "OrgA") and passes,
# but PushHandler acts on OrgB's stack via repository.full_name.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
