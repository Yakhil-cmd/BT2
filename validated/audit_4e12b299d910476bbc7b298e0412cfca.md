### Title
Unescaped git pathspec magic in `_diff_pathspec` lets a repo-controlled filename expand the review diff beyond the intended touched-file scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` converts the review-set's absolute paths into repo-relative strings and appends them raw after `--` for `git diff`, without escaping git's pathspec "magic" syntax (leading `!`/`:` shorthand, or glob metacharacters `*`, `?`, `[`). A file that is part of the review set (because it is genuinely dirty/changed and passed the normal cwd-containment check) can have a repo-root-relative path whose literal bytes match one of these magic forms, changing the entire pathspec's matching semantics for the `git diff` invocation in `get_git_diff`.

### Finding Description
`_diff_pathspec` (`plugins/security-guidance/hooks/gitutil.py:70-88`) realpath-normalizes each touched/dirty path and drops any that resolve outside `cwd` via the `r.startswith("..")` check — this correctly stops path *traversal* out of the repo. [3](#0-2)  But it never guards against git's own pathspec grammar: any pathspec string beginning with `!` or `:` is parsed by git as a *magic signature* (e.g. `!pattern` / `:(exclude)pattern` for negation, `:(glob)`, `:(icase)`, etc.), and unescaped `*`, `?`, `[` are treated as shell-style globs by git's default (non-literal) pathspec matcher — none of which is neutralized here (no `:(literal)` prefix, no `--literal-pathspecs`/`core.literalPathspecs=true`, `GIT_CMD` only sets `core.fsmonitor=false` and `core.hooksPath=/dev/null`). [1](#0-0) 

The review set (`compute_v2_review_set` in `diffstate.py`) is built entirely from filenames git itself reports via `git status --porcelain` / `git diff --name-only`, so a repo committing a file whose repo-root-relative path literally starts with `!` (e.g. `!secret.py`) or contains glob metacharacters is a legitimate, git-accepted filename — Claude editing/creating such a file during a normal session is enough to put it into `review_paths`, which then flows through `get_git_diff` → `_diff_pathspec` → the final `git diff ... -- !secret.py` command in `get_git_diff` (`plugins/security-guidance/hooks/gitutil.py:391-427`). [4](#0-3) 

When a pathspec list contains only negative/exclusion patterns (as happens if the sole or dominant entry is `!something`), git's matcher treats the implicit positive match as "everything", so the resulting diff is no longer scoped to the intended touched file(s) — it becomes an **unrestricted, full-repository diff** excluding only the pattern named. This defeats the entire purpose documented in `get_git_diff`'s own docstring/comment: "Caller restricted to specific paths... an empty pathspec would mean an UNRESTRICTED diff — the bug this whole change exists to fix." [5](#0-4)  The magic-character bug reintroduces exactly that unrestricted-diff condition through a different path, silently, with no error and no metric flagging it.

### Impact Explanation
The Stop-hook / commit-review pipeline feeds `get_git_diff`'s output into the LLM-based security reviewer (`parse_diff_into_files` → `agentic_review`/`analyze_code_security`) and, in the agentic path, grants the reviewing agent Read/Grep access "over the repo" scoped by `touched_paths`/the diff content. [6](#0-5)  An attacker who can get a maliciously named file (`!...`, `:(exclude)...`, or containing `*`/`?`/`[`) into the working tree — via a crafted repo, a PR checkout, or any file the agent is asked to create/rename — can force the diff-scoping mechanism to pull in content from files never intended to be part of the review scope, i.e. an unauthorized-scope expansion of what is read and surfaced (including into LLM prompts / external API calls), breaking the "git path scoping must never escape the intended repo target" invariant and matching the "Unauthorized file read... outside the user-approved workspace or target scope" impact class.

### Likelihood Explanation
Requires only a normal, unprivileged repository content interaction: a file whose git-reported relative path begins with `!` or `:` (both valid on POSIX filesystems and valid git tracked/untracked filenames) being part of the naturally computed dirty/changed set. No special git or OS privilege is needed, and the condition is deterministic and repeatable — reproducible with a plain `git status`/`git diff` invocation.

### Recommendation
Prefix every generated pathspec entry with the literal-pathspec magic signature, e.g. build entries as `":(literal)" + r"` instead of the raw `r`, or invoke the underlying `git diff` calls with `--literal-pathspecs` (equivalently set `GIT_LITERAL_PATHSPECS=1` in the environment passed to `subprocess.run`, or `git -c core.literalPathspecs=true diff ...`). This makes every pathspec argument matched byte-for-byte, eliminating both the negation-magic and glob-expansion classes of scope escape.

### Proof of Concept
Unit/integration test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. In a temp git repo, create and commit a benign file `a.py`, then create an untracked/dirty file literally named `!b.py` (or `":(exclude)b.py"`) at repo root.
2. Call `_diff_pathspec(repo, [os.path.join(repo, "!b.py")])` and assert the returned pathspec, when passed to `git diff --name-only -- <pathspec>`, only ever reports `!b.py` itself — not an unrestricted list of all tracked/dirty files in the repo.
3. Regression form: call `get_git_diff(repo, baseline_sha, paths=[os.path.join(repo, "!b.py")])` and assert the returned diff text contains only the hunk for `!b.py` and NOT hunks for unrelated files (e.g. `a.py` or any other dirty file outside the intended review set).
4. Expected (buggy) behavior today: the diff includes unrelated files because the pathspec is interpreted as a pure exclusion, i.e. "everything except b.py". Expected (fixed) behavior: diff is scoped exactly to `!b.py`.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
