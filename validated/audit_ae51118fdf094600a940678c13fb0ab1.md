There is a dedicated sanitization mechanism (`pkg/iostreams/untrusted.go`) used specifically for exactly this class of problem — untrusted, attacker-controlled repo content being printed to a TTY — but `ListPorts` in `pkg/cmd/codespace/ports.go` does not use it before calling `tp.AddField(port.Label())`.

### Title
Terminal escape-sequence injection via devcontainer.json port label rendered unsanitized to a TTY - (File: pkg/cmd/codespace/ports.go)

### Summary
`(*App).ListPorts` reads `.devcontainer/devcontainer.json` from the codespace's repository via `getDevContainer`, extracts `portsAttributes[<port>].label` verbatim in `portInfo.Label()`, and feeds it straight into `tableprinter.New(a.io, ...).AddField(...)` / `tp.Render()` [1](#0-0) [2](#0-1) . Neither `getDevContainer`'s JSON decoding nor `internal/tableprinter.TablePrinter` performs any ANSI-escape stripping, so raw control bytes reach `os.Stdout` whenever the victim's terminal is a real TTY and they run `gh codespace ports` (non `--json` path).

### Finding Description
- `getDevContainer` fetches the raw file content, does light JSON-repair (`normalizeJSON`, trailing-comma removal) and `json.Unmarshal`s it into `devContainer{PortAttributes map[string]portAttribute}` with `Label string` — no content sanitization is applied to the `label` field at any point [3](#0-2) .
- `portInfo.Label()` returns this attacker-controlled string unmodified [2](#0-1) .
- In `ListPorts`, when `exporter == nil` (i.e., the user did not pass `--json`), the code builds a `tableprinter.TablePrinter` via `tableprinter.New(a.io, ...)` and calls `tp.AddField(port.Label())` then `tp.Render()` [4](#0-3) .
- `internal/tableprinter.New`/`NewWithWriter` wraps `github.com/cli/go-gh/v2/pkg/tableprinter` and only handles width, padding, truncation, and color — it does not strip control/escape sequences from field values, and the `isTTY` flag governs only truncation/coloring behavior, not sanitization [5](#0-4) .
- The codebase already contains a purpose-built defense for this exact hazard — `pkg/iostreams/untrusted.go`, referenced from `content.go`, whose comments and usages elsewhere (`pkg/cmd/repo/read-file`, `pkg/cmd/gist/view`, `pkg/cmd/pr/diff`, `pkg/cmd/release/download`, `pkg/cmd/api`) exist precisely to sanitize untrusted repository-derived content before printing to a TTY — but `ports.go` never calls into it before `AddField`.
- Attack surface: an attacker publishes/controls a repository (or a fork/PR branch) that a victim opens as a Codespace (or that gets referenced via `gh codespace ports` against an attacker-authored `.devcontainer/devcontainer.json`), sets `portsAttributes.<port>.label` to a string embedding ANSI/VT100 sequences (e.g., `\x1b[2J\x1b[H`, OSC title-set `\x1b]0;...\x07`, or cursor-manipulation sequences). When the victim lists ports on that codespace in an interactive terminal, the bytes are written verbatim to `a.io.Out` (stdout), which a real TTY will interpret.

### Impact Explanation
This matches GitHub's "terminal escape sequence / control character injection" impact class: an attacker-authored repository can cause arbitrary terminal control on the victim's TTY (clearing the screen, spoofing the terminal title/prompt to enable spoofing follow-on commands, hiding/obscuring text, or in vulnerable terminal emulators triggering more severe behavior) purely by the victim running a benign, read-only `gh codespace ports` command against a codespace tied to an attacker-controlled repo. No credential/token exfiltration or RCE is directly demonstrated, but the escape sequences can be used for terminal spoofing / social-engineering amplification (e.g., faking subsequent shell prompts).

### Likelihood Explanation
- Preconditions: victim must have (or create) a codespace for an attacker-controlled/forked repository containing a malicious `.devcontainer/devcontainer.json`, and must run `gh codespace ports` in an interactive terminal (default, non-`--json` path) — `IsStdoutTTY()` must be true [6](#0-5) .
- This is a fairly common workflow (listing ports of a codespace created from a contributor's fork/PR), and the attacker fully controls the `devcontainer.json` label field with no length or character restriction visible in the code.
- Feasibility is high and repeatable — every listing of ports for that codespace triggers it.

### Recommendation
Sanitize/strip ANSI escape and other control sequences from `portInfo.Label()` (and any other repo-derived text passed to `tp.AddField`) before rendering when `a.io.IsStdoutTTY()` is true — reuse the existing `pkg/iostreams` untrusted-content sanitization helpers (as used in `pkg/cmd/repo/read-file`, `pkg/cmd/gist/view`, etc.) or apply a generic control-character stripper in `internal/tableprinter.AddField`/`TablePrinter` itself so all consumers get protection by default.

func getDevContainer(ctx context.Context, apiClient apiClient, codespace *api.Codespace) <-chan devContainerResult {
	ch := make(chan devContainerResult, 1)
	go func() {
		contents, err := apiClient.GetCodespaceRepositoryContents(ctx, codespace, ".devcontainer/devcontainer.json")
		if err != nil {
			ch <- devContainerResult{nil, fmt.Errorf("error getting content: %w", err)}
			return
		}

		if contents == nil {
			ch <- devContainerResult{nil, nil}
			return
		}

		convertedJSON := normalizeJSON(jsonc.ToJSON(contents))
		if !jsonc.Valid(convertedJSON) {
			ch <- devContainerResult{nil, errors.New("failed to convert json to standard json")}
			return
		}

		var container devContainer
		if err := json.Unmarshal(convertedJSON, &container); err != nil {
			ch <- devContainerResult{nil, fmt.Errorf("error unmarshalling: %w", err)}
			return
		}

		ch <- devContainerResult{&container, nil}
	}()
	return ch
}

// New creates a TablePrinter from an IOStreams.
func New(ios *iostreams.IOStreams, headers headerOption) *TablePrinter {
	maxWidth := 80
	isTTY := ios.IsStdoutTTY()
	if isTTY {
		maxWidth = ios.TerminalWidth()
	}

	return NewWithWriter(ios.Out, isTTY, maxWidth, ios.ColorScheme(), headers)
}

// NewWithWriter creates a TablePrinter from a Writer, whether the output is a terminal, the terminal width, and more.
func NewWithWriter(w io.Writer, isTTY bool, maxWidth int, cs *iostreams.ColorScheme, headers headerOption) *TablePrinter {
	tp := &TablePrinter{
		TablePrinter: tableprinter.New(w, isTTY, maxWidth),
		isTTY:        isTTY,
		cs:           cs,
	}

	if isTTY && len(headers.columns) > 0 {
		// Make sure all headers are uppercase, taking a copy of the headers to avoid modifying the original slice.
		upperCasedHeaders := make([]string, len(headers.columns))
		for i := range headers.columns {
			upperCasedHeaders[i] = strings.ToUpper(headers.columns[i])
		}

		// Make sure all header columns are padded - even the last one. Previously, the last header column
		// was not padded. In tests cs.Enabled() is false which allows us to avoid having to fix up
		// numerous tests that verify header padding.
		var paddingFunc func(int, string) string
		if cs.Enabled {
			paddingFunc = text.PadRight
		}

		tp.AddHeader(
			upperCasedHeaders,
			WithPadding(paddingFunc),
			WithColor(cs.TableHeader),
		)
	}

	return tp
}
