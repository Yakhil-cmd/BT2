### Title
Stale delegate grant resurrects when a position NFT returns to its previous owner - (File: contracts/controller/src/storage/account.rs)

### Summary
`ControllerKey::Delegates(account_id)` stores a single `DelegateGrant` stamped with `granted_by`. When the position NFT is transferred, the old owner's grant is neither deleted nor replaced — `get_delegates` merely filters it out while a different owner holds the token. If the NFT ever returns to `granted_by` and no intervening owner called `remove_delegate` or `add_delegate` (which overwrites the entry), the dormant grant becomes fully active again without the returning owner's consent. Delegates can `borrow`/`withdraw` to arbitrary recipients, so a revived delegate can drain the position's LTV headroom.

### Finding Description
`get_delegates` returns the stored grant only if `grant.granted_by == owner`, but leaves stale entries in storage [1](#0-0) . `remove_delegate` explicitly deletes a mismatched grant — but only if the *new* owner chooses to call it [2](#0-1) . `add_delegate` overwrites the entry wholesale, also only on an owner call [3](#0-2) . The protocol's own docs confirm the resurrection: "The stale grant stays in storage and re-arms if the token returns to `granted_by`" [4](#0-3)  and "it becomes inactive while someone else holds the NFT and can revive if the NFT returns before an intervening owner updates delegates" [5](#0-4) . This is the exact Footium bug class: approvals that should be revoked on ownership change instead persist in a non-iterable mapping and silently re-arm.

### Impact Explanation
Theft of user funds. Once the NFT returns to the original owner, the revived delegate — a position manager contract, possibly compromised or malicious — can call `borrow`/`withdraw` on the account with itself as recipient, extracting collateral/borrowed assets up to the health-factor limit with no authorization from the current owner at that point in time. The test `remove_delegate_purges_stale_grant_preventing_resurrection` pins that without an intervening `remove_delegate`, the grant would resurrect on return [6](#0-5) .

### Likelihood Explanation
Requires (a) the original owner to have granted a delegate, (b) an NFT transfer round-trip back to that owner (re-purchase, temporary loan of the position, marketplace trade reversal), and (c) no intervening owner calling `add_delegate`/`remove_delegate`. Interim owners have no incentive or visibility requirement to purge stale grants — the same gas-cost/tracking burden as the Footium issue. An unprivileged delegate then unilaterally triggers the theft. Medium likelihood / Medium severity.

### Recommendation
On any change detected in `get_delegates`/`is_owner_or_delegate` where `granted_by != owner`, eagerly delete `ControllerKey::Delegates(account_id)` instead of returning an empty list — mirroring what `remove_delegate` already does for mismatched grants [7](#0-6) . Alternatively, stamp grants with a monotonically increasing transfer epoch (incremented by the NFT/controller on each transfer) rather than `granted_by`, so stale grants can never re-arm.

### Proof of Concept
1. Alice owns `account_id` and calls `add_delegate(account_id, manager)` where `manager` is an active position manager.
2. Alice transfers NFT `token_id = account_id` to Bob (position sale).
3. Bob never calls `add_delegate`/`remove_delegate`; the `DelegateGrant{granted_by: Alice}` entry remains in persistent storage.
4. Bob transfers the NFT back to Alice (e.g., Alice repurchases the position).
5. `get_delegates(env, account_id, alice)` now returns `[manager]` again — `granted_by == owner` holds once more.
6. `manager` calls `borrow(caller=manager, account_id, assets=[...], to=manager)` or `withdraw(..., to=manager)`; `is_owner_or_delegate` passes and manager extracts assets to its own recipient, stealing Alice's collateral headroom — despite Alice having reasonably believed the grant died with the sale.

pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))
}

pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
```

fn remove_delegate_purges_stale_grant_preventing_resurrection() {
    let env = Env::default();
    env.mock_all_auths();
    let admin = Address::generate(&env);
    let contract_id = env.register(Controller, (admin,));
    let nft = setup_position_nft(&env, &contract_id);

    let alice = Address::generate(&env);
    let bob = Address::generate(&env);
    let delegate = Address::generate(&env);
    let account_id = u64::from(position_nft::PositionNftClient::new(&env, &nft).mint(&alice));

    env.as_contract(&contract_id, || {
        assert!(add_delegate(&env, account_id, &alice, &delegate));
        assert_eq!(get_delegates(&env, account_id, &alice).len(), 1);
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &alice,
        &bob,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert!(!remove_delegate(&env, account_id, &bob, &delegate));
        assert!(
            !env.storage()
                .persistent()
                .has(&ControllerKey::Delegates(account_id)),
            "stale grant must be purged from storage, not merely read as empty"
        );
    });

    position_nft::PositionNftClient::new(&env, &nft).transfer(
        &bob,
        &alice,
        &u32::try_from(account_id).unwrap(),
    );

    env.as_contract(&contract_id, || {
        assert_eq!(
            get_delegates(&env, account_id, &alice).len(),
            0,
            "the purged grant must not resurrect when the NFT returns to its original owner"
        );
    });
