### Title
Webhook signature verification is bound to the payload's `repository.owner.login` (or `organization.login`), not to the `repository.full_name`/commit actually mutated, allowing cross-organization/cross-repository commit-status forgery — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate the `X-Hub-Signature` against using `repository_owner`, computed as `params.dig('repository', 'owner', 'login')` with a fallback to `params.dig('organization', 'login')` [1](#0-0) . `Shipit::GitHubApp#verify_webhook_signature` explicitly returns `true` ("authenticated") whenever no `webhook_secret` is configured for that organization [2](#0-1) , and the setup docs document `webhook_secret` as an optional, nil-able per-organization key in multi-org configurations [3](#0-2) . Once "verified" this way, the request body is dispatched to handlers that act on data taken from *other* fields of the same JSON body — in particular `StatusHandler` looks up commits **only by `sha`**, with no repository/organization scoping at all: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` [4](#0-3) .

### Finding Description
The trust binding that should hold is:

```
organization/app whose webhook_secret authenticated the payload  ==  repository/commit that the payload's handler is allowed to mutate
```

This binding is broken in two compounding ways:

1. **Verification key is attacker-selectable and can be a no-secret organization.** `repository_owner` (used to pick the verifying `GitHubApp`/secret via `Shipit.github(organization: repository_owner)`) is read straight from the untrusted JSON body [5](#0-4) . If the Shipit installation is configured for multiple GitHub organizations (as documented) and at least one configured organization has no `webhook_secret` set — a supported, documented configuration — then any payload whose `repository.owner.login` (or `organization.login`) equals that unsecured organization sails through `verify_signature` with **no signature required at all** [2](#0-1) .

2. **The mutation target is not tied to the verified identity.** Once past `verify_signature`, `WebhooksController#create` dispatches the raw, attacker-controlled JSON to `Shipit::Webhooks.for_event(event)` handlers unchanged [6](#0-5) . `StatusHandler#process` never re-checks `repository.owner.login`/`full_name` against anything — it resolves the target purely by commit `sha`, globally across the whole `Commit` table, and writes a new `Status` for whatever commit matches [7](#0-6) . Nothing ties the `sha` back to the "authenticated" organization/repository at all.

Combined: an unprivileged, unauthenticated attacker who knows (a) that some organization on the instance has no webhook secret configured, and (b) the SHA of a commit belonging to a completely different, secured stack/repository (learnable from GitHub's public commit history, Shipit's own UI, or CI logs) can send an unsigned/forgeable `status` webhook with `repository.owner.login` set to the unsecured org and `sha` set to the target commit. `verify_signature` passes because that org has no secret, and `StatusHandler` then creates an arbitrary, attacker-chosen commit status (e.g. `state: success`, fabricated `context`) on the target commit belonging to an unrelated org/repo.

### Impact Explanation
Commit statuses gate Shipit's `ci.require` checks and merge/deploy eligibility. By forging a `success` status for CI contexts that a stack's `shipit.yml` requires, an attacker can make an otherwise CI-failing or unreviewed commit appear deployable/mergeable, leading to an **unauthorized deploy** of a commit on a stack the attacker has no legitimate access to — matching the Critical impact category ("unauthorized deploy, rollback or merge"). The root cause is a structural equality violation between "who authenticated" (`repository.owner.login`/`organization.login`, keyed to a possibly-unsecured org config) and "what gets written" (arbitrary `sha`, unscoped to any repository).

### Likelihood Explanation
Exploitability depends on the instance being configured with more than one GitHub organization where at least one has no `webhook_secret` set — a state explicitly supported and documented by Shipit's own setup docs and secrets templates (`webhook_secret: # nil`) [3](#0-2) . No credentials, API tokens, or session are required — this is a purely unauthenticated network request to `/github/:owner/webhook` (or equivalent path) that any user with the target commit's SHA can send.

### Recommendation
- Enforce that `verify_signature`'s resolved organization matches the organization implied by every payload field the corresponding handler will act on (e.g., require `repository.full_name`'s owner to equal `repository.owner.login`/`organization.login` used for verification).
- Scope `StatusHandler` (and any handler resolving records by an identifier alone) to the repository/organization that was actually verified, not just a bare `sha`/id lookup.
- Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is blank in multi-organization deployments; require a secret per configured organization, or reject the webhook if unset.

### Proof of Concept
1. Configure (or find) a Shipit instance with multiple GitHub orgs, where org `unsecured-org` has `webhook_secret: nil` and org `victim-org` hosts a stack with `ci.require: ["ci/tests"]`.
2. Attacker learns the SHA of a commit `abc123` on `victim-org/victim-repo` (public GitHub commit).
3. Attacker sends:
```
POST /github/webhook  (X-Github-Event: status; no signature needed)
{
  "sha": "abc123",
  "state": "success",
  "context": "ci/tests",
  "repository": { "owner": { "login": "unsecured-org" }, "full_name": "unsecured-org/anything" }
}
```
4. `verify_signature` resolves `repository_owner = "unsecured-org"`, fetches its `GitHubApp` (no `webhook_secret`), and `verify_webhook_signature` returns `true` unconditionally.
5. `StatusHandler#process` runs `Commit.where(sha: "abc123")`, finds the `victim-org/victim-repo` commit (unscoped by repo), and creates a forged `success` status satisfying `ci.require`, enabling an unauthorized deploy/merge on `victim-org`'s stack.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
```
