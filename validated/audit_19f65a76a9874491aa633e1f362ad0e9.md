### Title
CR/line-feed injection in skill content bypasses terminal sanitization, enabling output/prompt spoofing in `renderAllFiles` - (File: pkg/cmd/skills/preview/preview.go)

### Summary
`renderAllFiles` renders remote skill file content (fetched via `discovery.FetchBlob`) directly to the terminal using `iostreams.Untrusted.String()` for sanitization. That sanitizer strips/escapes ANSI escape (`ESC`, `0x1B`) and most other C0/C1 control bytes, but by explicit design it passes `\t`, `\n`, and `\r` through unmodified. A published skill's `SKILL.md` body or any extra file can therefore embed raw carriage returns that reposition the terminal cursor to the start of a line and overwrite previously printed, trusted text (e.g. file names, headers, or subsequent prompt text), enabling output spoofing.

### Finding Description
`renderAllFiles` writes fetched skill content straight to `opts.IO.Out`: [1](#0-0) 

The SKILL.md body is rendered via `opts.renderFile`, and extra files are rendered via `fileContent.String()`, where `fileContent` is an `iostreams.Untrusted` returned by `discovery.FetchBlob`: [2](#0-1) 

`Untrusted.String()` is the sanitization boundary used throughout the codebase for exactly this purpose (rendering attacker-controlled remote content to the terminal): [3](#0-2) 

However, both the primary sanitizer (`asciisanitizer.Sanitizer`) and its documented fallback (`stripControl`) intentionally preserve carriage return as a "safe" whitespace character alongside tab and newline: [4](#0-3) 

This is corroborated by the HTTP-client-level sanitization test, which shows `\r\n` passing through untouched while other C0 control bytes (e.g. `\u0001`–`\u0006`) are converted to caret notation: [5](#0-4) 

Because `\r` is never neutralized, an attacker who publishes a skill (a repo, fork, or PR the victim points `gh skills preview` at) can embed a bare `\r` followed by forged text (e.g. `? Paste your GitHub token: `) in `SKILL.md`'s body, frontmatter-adjacent text, or any additional file. When `renderAllFiles` streams that content to `opts.IO.Out` (or the pager, when the pager is disabled or configured to pass raw control bytes), the `\r` returns the cursor to column 0 and the attacker's text overwrites the line gh had just printed — for example, overwriting the `── file.txt ──` header or a portion of the SKILL.md rendering — with fabricated content that looks like gh's own trusted output, including a spoofed credential prompt line.

The other sanitization mechanisms in the codebase (`iostreams.ContainsEscapeSequence`, `CopyGuardedContent`, the `--allow-escape-sequences` gate in `gh repo read-file` / `gh pr diff`) only check for the ESC byte (`0x1B`) and do not consider `\r` a hazard either: [6](#0-5) 
None of these checks are invoked from `renderAllFiles`, so no additional guard against `\r` exists on this path.

### Impact Explanation
This allows a remote, unprivileged GitHub user (skill publisher) to spoof gh's terminal output during `gh skills preview`, e.g. redrawing a line to mimic `? Paste your GitHub token:` or fabricating a fake success/warning message, which can be used to trick a victim into typing a credential or confirming an action they didn't intend. This matches the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class (High).

### Likelihood Explanation
Exploitation only requires publishing a public repository/skill with a crafted `SKILL.md` or auxiliary file containing `\r` characters, then getting a victim to run `gh skills preview <attacker-repo>`. No special privileges, MITM, or token access are needed; the mechanism is fully reachable through the documented preview flow, and is deterministic/repeatable.

### Recommendation
Extend the sanitization boundary (`iostreams.Untrusted.String()` / `stripControl`, and any ad hoc control-character checks such as `ContainsEscapeSequence`) to also neutralize bare `\r` (and ideally other cursor-repositioning sequences) when content is destined for interactive terminal display — e.g., replace `\r` not immediately followed by `\n` with a visible placeholder (`^M`) or strip it, rather than treating it as safe whitespace. Apply this consistently to all paths that print `Untrusted` content directly to `opts.IO.Out`/pager, including `renderAllFiles` and `renderInteractive` in `pkg/cmd/skills/preview/preview.go`.

### Proof of Concept
Go unit test sketch (extending `pkg/iostreams/untrusted_test.go` and `pkg/cmd/skills/preview/preview_test.go`):
```go
func TestUntrusted_String_neutralizesCR(t *testing.T) {
    u := NewUntrusted("── real-file.txt ──\rPaste your GitHub token: ")
    assert.NotContains(t, u.String(), "\r")
}
```
Currently this assertion fails because `Untrusted.String()` preserves `\r` verbatim, as shown by the existing sanitization behavior: [4](#0-3) .

Integration-level PoC: stub a skill blob response (via `httpmock`) whose extra-file content is `"safe text\r? Paste your GitHub token: "`, invoke `previewRun`/`renderAllFiles` with a non-interactive `IOStreams`, and assert the captured stdout never contains a raw `\r` byte. This currently fails, confirming the finding.

// FetchBlob retrieves the content of a blob by SHA. The blob is base64-encoded
// inside the JSON response and decoded here, so it is returned as
// iostreams.Untrusted and callers must choose sanitized display or raw
// round-tripping.
func FetchBlob(client *api.Client, host, owner, repo, sha string) (iostreams.Untrusted, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "blobs", sha)
	if err != nil {
		return iostreams.Untrusted{}, err
	}
	var resp struct {
		SHA      string `json:"sha"`
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(host, "GET", apiPath.String(), nil, &resp); err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not fetch blob: %w", err)
	}

	if resp.Encoding != "base64" {
		return iostreams.Untrusted{}, fmt.Errorf("unexpected blob encoding: %s", resp.Encoding)
	}

	// GitHub API returns base64 with embedded newlines; use the StdEncoding
	// decoder via a reader to handle them transparently.
	decoded, err := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(resp.Content)))
	if err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not decode blob content: %w", err)
	}

	return iostreams.NewUntrustedBytes(decoded), nil

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is

// stripControl is a defensive fallback used only if the sanitizing transform
// errors, which the asciisanitizer does not do in practice. It drops C0 control
// bytes other than tab, newline, and carriage return so the result can never
// carry an escape sequence.
func stripControl(s string) string {
	return strings.Map(func(r rune) rune {
		if r < 0x20 && r != '\t' && r != '\n' && r != '\r' {
			return -1
		}
		return r
	}, s)
}
