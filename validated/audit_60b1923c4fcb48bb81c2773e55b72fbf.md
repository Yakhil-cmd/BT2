### Title
Attacker-driven RAY value overflow permanently freezes a market — all exits and repayments revert in accrual - (File: common/src/rates/simulate.rs)

### Summary
A whale can push a market's debt book past the i128 RAY value ceiling so that `scaled_to_original(borrowed, borrow_index)` overflows inside `accrue_step`. Because every controller verb accrues first, the market permanently freezes: `withdraw`, `repay`, `borrow`, `liquidate`, and `update_indexes` all panic with `MathOverflow`. The borrow-index cap (`MAX_BORROW_INDEX_RAY`) never engages because the value overflow fires first.

### Finding Description
Interest accrual runs `accrue_step` for each chunk, which immediately computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` as `half_up(scaled × index / RAY)` over raw i128 [1](#0-0) . The borrow index is capped at `10^36` raw RAY, but that cap is applied inside `update_borrow_index` *after* the value conversion, so it does not prevent the multiplication `borrowed × borrow_index` from exceeding `i128::MAX` [2](#0-1) . The protocol's own formula reference concedes "value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [3](#0-2) . The admitted token-to-RAY maximum is `~1.7e38 / 10^(27-d)` — about 170 billion whole tokens at 18 decimals — and valid caps and bounded indexes "do not guarantee that future accrual fits."

The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the reachable path end-to-end: supply `10^9 × 10^18` base units, borrow 98% at the steep segment of the rate curve (max ~200% APR per the documented bound), let the index compound past ~170x, and the next accrual panics; subsequently `try_withdraw_raw` and `try_repay` both revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` [4](#0-3) .

This is the missing-bounds-check analog: like `read_reloc` dereferencing without `_bfd_clear_contents`, accrual multiplies two attacker-influenced quantities (`borrowed` shares × `borrow_index`) without checking the product against the i128 domain before it is needed, and the resulting trap is permanent because the check runs on every entrypoint.

### Impact Explanation
Permanent freezing of user funds. Once the market crosses the RAY value ceiling, every supplier in that market loses the ability to withdraw, every borrower loses the ability to repay, and no liquidator can act — all operations fail inside the mandatory `global_sync` accrual before reaching position logic [5](#0-4) . `clean_bad_debt`/`recapitalize` also accrue, so there is no governance-free recovery path. The only mitigation is administrative (e.g., pausing is useless since accrual is unconditional), and there is no code path that caps `borrowed × index` growth or emits a ceiling alarm [6](#0-5) .

### Likelihood Explanation
Requires a whale-scale book (~10^9 whole tokens of an 18-decimal asset supplied and ~98% borrowed) and sustained max-utilization rates over multiple compounding years — the test reaches the cliff via 98% utilization on the XLM curve. An attacker must fund the principal (though the borrowed leg returns most of it and collateral can be recycled), and other borrowers/suppliers accelerate or retard the timeline. Low probability for ordinary markets, real for markets with large caps and aggressive rate curves; Medium severity consistent with the DoS-only, hard-to-trigger profile of the CVE class.

### Recommendation
Add a bounds check in `accrue_step` before the value conversions: cap `borrowed_original`/`supplied_original` computation by clamping `borrow_index` (or short-circuiting accrual) when `borrowed > i128::MAX / borrow_index × RAY`, so the index cap engages before the product overflows. Alternatively, store a "frozen-accrual" flag per market that lets exits bypass `global_sync` once the ceiling is hit, or enforce a supply/borrow cap derived from `i128::MAX / MAX_BORROW_INDEX_RAY` at listing/entry so an admitted book can never reach the overflow.

### Proof of Concept
See `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs` (lines 321–361): an unprivileged `supply_raw` + `borrow_raw` sequence, followed by time advance, makes `update_indexes` fail with `MATH_OVERFLOW`, after which `try_withdraw_raw(1)` and `try_repay` revert identically — a permanent freeze reachable entirely through `supply`/`borrow`/`update_indexes`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
