### Title
Webhook signature verification org (`repository.owner.login`) is never cross-checked against the handler's authorization target (`repository.full_name`), enabling cross-repository writes when any one configured org has `webhook_secret: nil` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In the multi-org GitHub App configuration, `WebhooksController#verify_signature` selects which `GitHubApp` (and thus which `webhook_secret`) to verify against using `repository_owner`, derived solely from `params.dig('repository', 'owner', 'login')`. Every downstream `Handler` instead resolves the repository to mutate from `payload.dig('repository', 'full_name')`, a sibling field of the same attacker-controlled JSON object. Neither the controller nor `Shipit::Webhooks::Handlers::Handler` ever asserts that `full_name`'s owner segment equals `repository.owner.login`, so if any one org in a multi-org deployment is misconfigured with `webhook_secret: nil`, an attacker can forge a payload whose `repository.owner.login` picks that org's (trivially-bypassed) signature check while `repository.full_name` names a completely different org/repo, causing the handler to write to that other repository's stacks.

### Finding Description
The broken binding: the code implicitly assumes
`payload['repository']['owner']['login'] == payload['repository']['full_name'].split('/').first`
This is true for genuine GitHub-emitted payloads, but nothing enforces it for attacker-supplied POST bodies, and it is never checked in code.

Path:
- `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`) reads only `params.dig('repository', 'owner', 'login')` (falling back to `organization.login` only if `repository` is absent).
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) contains `return true unless webhook_secret` — if the resolved org's `webhook_secret` is `nil`/blank (a documented, real-world config shape per `test/dummy/config/secrets_double_github_app.yml` and `docs/setup.md`'s multi-org example, which shows `webhook_secret: # nil` for each org), **any signature is accepted, including no signature at all**.
- On success, `WebhooksController#create` (`app/controllers/shipit/webhooks_controller.rb:10-15`) parses the raw body and dispatches to handlers via `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`.
- `Handler#repository_name` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`) and every concrete handler (e.g. `PullRequest::OpenedHandler#repository`, `PushHandler#stacks`) resolve the target `Repository`/`Stack` from `payload.dig('repository', 'full_name')` — a completely independent read of the same JSON object, with no comparison back to `repository_owner`.

Attacker's exact request: POST `/webhooks` with header `X-Github-Event: push` (or `pull_request`) and body:
```json
{
  "repository": { "owner": { "login": "MisconfiguredOrgA" }, "full_name": "VictimOrgB/target-repo" },
  "ref": "refs/heads/main",
  "after": "<any sha attacker wants recorded>"
}
```
`verify_signature` resolves `Shipit.github(organization: "MisconfiguredOrgA")`, whose `webhook_secret` is `nil`, so `verify_webhook_signature` returns `true` unconditionally regardless of the `X-Hub-Signature` header sent (or omitted). The request passes verification, then `PushHandler` (or any handler) loads `Repository.from_github_repo_name("VictimOrgB/target-repo")` and mutates its stacks — a repository that belongs to an entirely different, potentially properly-secured org.

Existing guards that fail to prevent this: `drop_unhandled_event` only checks the event type is registered; `verify_signature`'s `rescue Shipit::GithubOrganizationUnknown` only fires if the *owner* org name is entirely unknown to `Shipit.github`, not if it's known-but-misconfigured; `ExplicitParameters` schemas (`requires :repository { requires :full_name, String }`) validate types/presence but never cross-field-validate against `owner.login`; there is no model validation or controller check anywhere binding `repository_owner` to `repository.full_name`'s owner segment.

### Impact Explanation
An attacker who knows (or brute-forces, since org names are typically public GitHub org slugs) that any single org in a multi-org Shipit deployment has `webhook_secret: nil` can forge webhooks that are authenticated "as" that misconfigured org, but are processed as pushes/pull-request events for any *other* org's repository tracked by the same Shipit instance. This yields unauthorized writes: `Stack#sync_github` gets called with attacker-chosen `expected_head_sha`, `ReviewStack`s get archived/unarchived/created, and pull request records get mutated for a repository the attacker never proved control over — a cross-tenant authentication bypass matching the Critical "payload for one repository mutating another's stack, commit, task or team" category. It is repeatable for the lifetime of the misconfiguration and against every repository tracked under every other org on the same Shipit instance.

### Likelihood Explanation
Preconditions: multi-org GitHub App configuration (documented and shipped as a first-class scheme, see `test/dummy/config/secrets_double_github_app.yml`, `docs/setup.md`), and at least one configured org left with `webhook_secret: nil` — explicitly shown as the default/placeholder value in every example secrets file in this repo (`config/secrets.development.example.yml:11`, `config/secrets.development.shopify.yml:9,18`, `test/dummy/config/secrets_double_github_app.yml:7,46`). No secrets, sessions, or GitHub credentials are needed; only knowledge of the misconfigured org's name and the victim repo's `owner/name`, both public. Attacker cost is a single unauthenticated HTTP POST.

### Recommendation
In `Shipit::WebhooksController#verify_signature` (or in `Handler#initialize`), assert that the resolved authorization owner matches the repository actually being acted upon, e.g.:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end

def repository_full_name_owner
  params.dig('repository', 'full_name')&.split('/', 2)&.first
end
```
and reject (`head 422`) whenever `repository_full_name_owner` is present and differs from `repository_owner`. Additionally, treat a `nil`/blank `webhook_secret` as a hard misconfiguration error (raise/refuse to boot, or fail-closed instead of `return true unless webhook_secret`) rather than silently disabling signature verification for that org.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb`:
```ruby
test "rejects push whose repository.full_name owner differs from repository.owner.login" do
  # OrgA configured with webhook_secret: nil (see test/dummy/config/secrets_double_github_app.yml)
  request.headers['X-Github-Event'] = 'push'
  payload = JSON.parse(payload(:push_master))
  payload['repository']['owner']['login'] = 'OrgOne'          # misconfigured org, webhook_secret: nil
  payload['repository']['full_name']       = 'OrgTwo/victim-repo' # different org's repo

  post :create, body: payload.to_json, as: :json

  full_name_owner = payload['repository']['full_name'].split('/').first
  assert_equal payload['repository']['owner']['login'], full_name_owner,
    "repository_owner used for signature verification must match repository.full_name owner"
  assert_response :unprocessable_entity
end
```
Against current code, `Shipit.github(organization: 'OrgOne')` resolves a `webhook_secret: nil` app, `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`), the request is accepted (`:ok`, not `:unprocessable_entity`), and the handler proceeds to act on `OrgTwo/victim-repo` — the assertion `assert_equal payload['repository']['owner']['login'], full_name_owner` passes only because the test payload is self-consistent by construction, but `assert_response :unprocessable_entity` fails, proving no enforcement point rejects the mismatched-owner payload.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
