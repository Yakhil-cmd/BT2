### Title
CCMenuController bypasses ApiClient stack scoping, allowing a stack-scoped token to read any stack's build status - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::BaseController` enforces that an `ApiClient` with a non-null `stack_id` may only access the specific `Stack` it was scoped to, via `stacks` / `stack` helper methods (`current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all`). `CCMenuController` re-defines `stack` to call `Stack.from_param!(params[:stack_id])` directly, entirely skipping this scoping, so `require_permission :read, :stack` only checks that the permission string `read:stack` is present in the token's permission list — never that the token's `stack_id` matches the requested stack.

### Finding Description
`BaseController#stack` is `@stack ||= stacks.from_param!(params[:stack_id])`, where `stacks` is scoped to `current_api_client.stack_id` when present [2](#0-1) . This is the sole enforcement point that binds an `ApiClient`'s authorized stack to the stack it may touch. Every other API controller (`CommitsController`, `TasksController`, `StacksController`, etc.) inherits this method unmodified, so a scoped client like the `here_come_the_walrus` fixture (`stack: shipit`, `permissions: [read:stack]`) can only ever resolve `stack` to the `shipit` stack [4](#0-3) , as verified by the test "an api client scoped to a stack will only see that one stack" [5](#0-4) .

`CCMenuController`, however, overrides `stack` with `@stack ||= Stack.from_param!(params[:stack_id])` [1](#0-0) , which resolves against `Stack.from_param!` (all stacks), not the scoped `stacks` relation. `require_permission :read, :stack` only invokes `current_api_client.check_permissions!(:read, :stack)` [6](#0-5) , which merely checks `permissions.include?('read:stack')` [7](#0-6)  — it never consults `stack_id`. So the binding "the stack a token authorizes" (its `stack_id`) versus "the stack it touches" (`params[:stack_id]`) is broken specifically in this controller: any client holding the generic `read:stack` permission — including one deliberately scoped to a single stack — can pass an arbitrary `stack_id` param and read another stack's build/deploy status.

### Impact Explanation
This is an authorization boundary break matching the rule's explicit binding "a stack a token authorises versus a stack it touches," and falls under the High-severity category "unauthenticated read of stack state ... or deploy output" in the sense that it is an unauthorized read of stack state relative to the token's intended scope. An attacker holding any `ApiClient` credential scoped to one stack (e.g. obtained via the intentionally narrowly-scoped CCMenu token flow in `CCMenuUrlController`, or any other client legitimately restricted to a single stack for defense-in-depth) can read the name, last build label/status/time, activity, and web URL of every other stack in the deployment — including private/internal stack names, deploy status, and lock state — none of which the token's `stack_id` was meant to permit.

### Likelihood Explanation
Any holder of a valid API token with the common `read:stack` permission can trigger this by simply requesting `GET /api/stacks/:other_stack_id/ccmenu.xml` with their own token; no privilege escalation, session, or additional secret is required beyond a token that already exists for a legitimate, narrower purpose. This is straightforward and requires no special conditions beyond possessing any single scoped API token.

### Recommendation
Remove the `stack` override in `CCMenuController` (and the `Stack.from_param!` bypass in `CcmenuUrlController`'s underlying flow if applicable) so it uses the inherited, `ApiClient`-scoped `stack` method from `BaseController`, ensuring `stack_id` restrictions are enforced consistently across all API endpoints.

### Proof of Concept
```ruby
# Client scoped only to stack "shipit" with read:stack permission (fixture: here_come_the_walrus)
client = shipit_api_clients(:here_come_the_walrus)
other_stack = shipit_stacks(:cyclimse) # a stack the client is NOT scoped to

request.headers['Authorization'] = "Basic #{Base64.encode64("#{client.authentication_token}:")}"
get :show, params: { stack_id: other_stack.to_param }

assert_response :ok
assert_payload 'name', other_stack.to_param
# Expected: :forbidden, because the token's stack_id != other_stack.id
# Actual: 200 OK, leaking other_stack's build status/name/lock state
``` [8](#0-7)
