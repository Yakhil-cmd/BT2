## Analog Found

### Title
Revoking/changing an asset's `spender_attested` attestor list can permanently freeze previously-attested holders' coins - (File: validation.js, storage.js)

### Summary
The UXD report describes a case where a whitelist check is applied both at deposit-time and at withdrawal-time, and when the whitelist state changes after deposit, the depositor's already-legitimate funds become permanently unspendable. ocore has a structurally identical pattern for `spender_attested` assets: the definer maintains a mutable list of trusted attestor addresses, and a holder's coin can only be spent if the holder's address is *currently* attested by one of the *currently* configured attestors — re-checked at every subsequent spend, not just at the time the coin was received.

### Finding Description
An asset definition can set `spender_attested: true`, and the definer can later change the trusted attestor set via an `asset_attestors` message, validated in `validateAttestorListUpdate` [1](#0-0) . `storage.loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses` compute `arrAttestedAddresses` by joining the `attestations` table against the asset's *current* `arrAttestorAddresses` list [2](#0-1) .

When a payment of such an asset is validated, the check is applied identically to (a) the address that is spending an existing output (owner of the input) and (b) the address that receives a new output:
- Input/owner check: `objAsset.spender_attested && objAsset.arrAttestedAddresses.indexOf(owner_address) === -1` → `"owner address is not attested"` [3](#0-2)  (and the equivalent private-payment path) [4](#0-3) .
- Output check: all `arrOutputAddresses` must appear in the freshly computed `arrAttestedOutputAddresses` [5](#0-4) .

Because the owner-address check is re-evaluated on *every* subsequent transfer using the asset's *current* attestor list, a coin holder who was validly attested at the time they received the asset can lose the ability to move that exact same coin later if the definer edits the attestor list (e.g., removes the attestor who vouched for that holder, or replaces the whole list) — exactly mirroring the UXD bug class where a whitelist check applied consistently at both entry and exit points causes previously-legitimate holdings to become stuck once the whitelist state changes.

### Impact Explanation
A holder's funds in a `spender_attested` asset become permanently frozen/unspendable the moment the definer updates the attestor list in a way that no longer covers that holder's existing attestation, even though the holder did nothing wrong and legitimately acquired the asset while properly attested. There is no fallback path in `validatePaymentInputsAndOutputs`/`validatePayment` that grandfathers already-attested holders — the check is always evaluated against the live attestor set [6](#0-5) . This is a fund-freezing issue reachable purely by the asset definer posting a normal `asset_attestors` message plus a routine payment, i.e. no privileged network/consensus role is required beyond being the asset definer, and it directly harms an ordinary asset holder who has no way to re-enable their own spend.

### Likelihood Explanation
Any asset issuer choosing `spender_attested: true` can trigger this simply by publishing a new `asset_attestors` unit that omits an attestor previously used to vouch for existing holders [1](#0-0) . This is a normal, supported protocol operation (no special privilege beyond being the asset's own definer, which is expected to control this list), so the precondition is easy to hit — intentionally or accidentally — whenever attestor rotation happens after coins have already changed hands.

### Recommendation
Decouple "has this coin ever been legitimately attested at receipt time" from "is the owner attested under the current list." One option is to record, at the time an output is created for a `spender_attested` asset, which attestor(s)/attestation state applied, and permit spending an existing output based on the attestor set that was current when that output was produced (or accept spends as long as at least one *historical* valid attestation exists for the owner), rather than re-validating owner attestation against the live attestor list on every subsequent transfer.

### Proof of Concept
1. Definer creates asset `A` with `spender_attested: true` and initial `attestors: [X]` [7](#0-6) .
2. Attestor `X` attests address `Alice`; `Alice` receives outputs of asset `A` (passes the output-attestation check) [5](#0-4) .
3. Definer posts `asset_attestors` updating the attestor list to `[Y]`, removing `X` [1](#0-0) .
4. `Alice` now tries to spend/transfer her existing `A` output. `storage.filterAttestedAddresses` recomputes `arrAttestedAddresses` using the new attestor list `[Y]`; since `Alice`'s attestation came from `X` (no longer in the list), the query returns no match for `Alice` [8](#0-7) .
5. `validatePaymentInputsAndOutputs` rejects the input with `"owner address is not attested"`, permanently blocking `Alice` from moving the coin she legitimately received [3](#0-2) .

```javascript
function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}
```

```javascript
// filter only those addresses that are attested (doesn't work for light clients)
function filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAddresses, handleAttestedAddresses){
	conn.query(
		"SELECT DISTINCT address FROM attestations CROSS JOIN units USING(unit) \n\
		WHERE attestor_address IN(?) AND address IN(?) AND main_chain_index<=? AND is_stable=1 AND sequence='good' \n\
			AND main_chain_index>IFNULL( \n\
				(SELECT main_chain_index FROM address_definition_changes JOIN units USING(unit) \n\
				WHERE address_definition_changes.address=attestations.address AND main_chain_index<=? AND is_stable=1 AND sequence='good' ORDER BY main_chain_index DESC LIMIT 1), \n\
			0)",
		[objAsset.arrAttestorAddresses, arrAddresses, last_ball_mci, last_ball_mci],
		function(addr_rows){
			var arrAttestedAddresses = addr_rows.map(function(addr_row){ return addr_row.address; });
			handleAttestedAddresses(arrAttestedAddresses);
		}
	);
}

// note that light clients cannot check attestations
function loadAssetWithListOfAttestedAuthors(conn, asset, last_ball_mci, arrAuthorAddresses, bAcceptUnconfirmedAA, handleAsset){
	if (arguments.length === 5) {
		handleAsset = bAcceptUnconfirmedAA;
		bAcceptUnconfirmedAA = false;
	}
	readAsset(conn, asset, last_ball_mci, bAcceptUnconfirmedAA, function(err, objAsset){
		if (err)
			return handleAsset(err);
		if (!objAsset.spender_attested)
			return handleAsset(null, objAsset);
		filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAuthorAddresses, function(arrAttestedAddresses){
			objAsset.arrAttestedAddresses = arrAttestedAddresses;
			handleAsset(null, objAsset);
		});
	});
```
