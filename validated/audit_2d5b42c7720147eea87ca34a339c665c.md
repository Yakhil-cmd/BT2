### Title
`Api::CCMenuController#stack` bypasses the ApiClient's stack scope, allowing a stack-scoped token to read the CI/deploy status of any stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
The bug class in the external report is "a check that binds an operation to a specific scope is missing before the operation executes" (missing `externalAssetVault != 0` guard before an external call in `_deposit()`, while the sibling method `_repayAsset()` has it). The equivalent binding in this engine is: **the `Stack` a scoped `ApiClient` token is authorized to touch, versus the `Stack` the controller action actually operates on**. `Api::BaseController` establishes this binding correctly, but `Api::CCMenuController` (reachable via a distinct, unauthenticated-looking `Shipit::ApiClient` token) overrides the accessor and drops the scoping check, exactly the "same-class, sibling-method-has-the-check-but-this-one-doesn't" pattern from the report.

### Finding Description
`Shipit::Api::BaseController` establishes the trust binding "an `ApiClient` may only touch the `Stack` it is scoped to": [1](#0-0) 

- `stacks` restricts the queryable set to `Stack.where(id: current_api_client.stack_id)` when the client is scoped to a stack.
- `stack` resolves `params[:stack_id]` **within that restricted relation** via `stacks.from_param!(...)`.

Every other API controller (e.g. `Api::DeploysController`, `Api::TasksController`) inherits this `stack` method unmodified, so a stack-scoped `ApiClient` (e.g. fixture `here_come_the_walrus`, scoped to stack `shipit`, permission `read:stack`) cannot resolve any other stack: [2](#0-1) 

`Api::CCMenuController`, however, redefines `stack` to bypass the scoping relation entirely and resolve directly against the global `Stack` table: [3](#0-2) 

```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```

This is the missing-check analog: the sibling accessor in `BaseController` enforces the `current_api_client.stack_id` binding before resolving a stack; this override performs the same "resolve stack from params" operation but omits that check, just like `_deposit()` omitting the `externalAssetVault` guard that `_repayAsset()` has.

`require_permission :read, :stack` only checks that the token *has* the `read:stack` permission string; it never checks the token's `stack_id` matches the stack being rendered: [4](#0-3) 

The `show` action then renders the target stack's latest deploy/rollback status (running state, id, ended_at) into the CCMenu XML using whatever `stack` resolves to.

### Impact Explanation
Before the attacker's request (intended behavior): `ApiClient` scoped to stack A with `read:stack` can only call `GET /api/stacks/<A>/ccmenu` (or any other stack A endpoint); `stacks.from_param!` raises/404s for stack B.

After the attacker's request: the same token, sent to `GET /api/stacks/<B>/ccmenu`, resolves `stack` directly via `Stack.from_param!(params[:stack_id])`, bypassing the `current_api_client.stack_id` restriction, and returns stack B's deploy/rollback status.

Equality that is broken: `stack the ApiClient token authorizes == stack the controller action touches` becomes false for `Api::CCMenuController#show`.

This matches the in-scope High-impact category "unauthenticated read of stack state, task streams or deploy output": a token that is only supposed to authorize reads of its own scoped stack can be used to read state (current deploy status, running/pending state, deploy id) of any other stack in the installation, including private/production stacks it was never granted access to.

### Likelihood Explanation
Likelihood is Medium: it requires possession of any valid `ApiClient` token that is scoped to a stack (e.g. a CCMenu client automatically minted by `CCMenuUrlController#client` for any logged-in user, or any org-issued scoped API client) — this is a normal, low-privilege credential in day-to-day use of Shipit (every user who visits a stack's CCMenu link gets one, per `Api::CCMenuUrlController`). No repository write access, GitHub credentials, or admin privilege is required — only a token that legitimately exists for one stack. The `stack_id` is a public/predictable path component (`owner/repo/environment`), so enumerating other stacks is trivial.

### Recommendation
In `Api::CCMenuController`, remove the private `stack` override (or reimplement it using the inherited, scope-respecting `stacks` relation), so that stack-scoped tokens are restricted the same way as in `Api::BaseController`:

```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

### Proof of Concept
1. As a legitimate user with access to Stack A, visit `Api::CCMenuUrlController#fetch` for stack A; Shipit creates/returns a scoped `ApiClient` (`permissions: %w[read:stack]`, `stack: A`) and its `authentication_token`.
2. Use that token as the `token` query param against a different stack B's CCMenu endpoint:
   `GET /api/stacks/<B_owner>/<B_repo>/<B_env>/ccmenu?token=<token_scoped_to_A>`
3. `authenticate_api_client` (overridden in `CCMenuController`) validates the token via `ApiClient.authenticate(params[:token])` — succeeds since the token itself is valid, regardless of scope.
4. `require_permission :read, :stack` passes because the token has `read:stack` in its `permissions` array (no stack-id comparison).
5. `stack` resolves via `Stack.from_param!(params[:stack_id])` directly to stack B, bypassing the `current_api_client.stack_id` check that `Api::BaseController#stacks`/`#stack` would have enforced.
6. `show` renders stack B's latest deploy/rollback status (`running?`, `id`, `ended_at`) to a token that was only ever authorized for stack A. [5](#0-4) [6](#0-5) [7](#0-6)

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```

```ruby
require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
```
