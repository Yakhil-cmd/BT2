### Title
Coalesced hook-hash delivery drops synced revisions from webhook/exechook notification, permitting an attacker to publish content changes that are silently un-notified to downstream consumers - ([File: pkg/hook/hook.go])

### Summary
The reported Arcadia issue is fundamentally a TOCTOU/coalescing bug: a state-mutating event (the donation) is applied against a share-valuation snapshot that is read non-atomically relative to other mutating operations (deposit/withdraw), letting an attacker who observes/controls timing capture value meant for a different set of participants. The closest reachable analog in `git-sync` is the `hookData`/`HookRunner` "last-hash-wins" coalescing mechanism combined with `SyncRepo`'s worktree lifecycle: because hash notifications to hooks are coalesced onto a size-1 channel, and because `cleanup()`/`removeStaleWorktrees` (invoked every loop after `SyncRepo`) can remove intermediate worktrees before a queued hook has consumed their hash, an attacker who controls the upstream repository content (pushing rapid successive commits within one `--period` window) can force git-sync to skip firing the exechook/webhook for one or more successfully-published revisions and can also cause the exechook to run with a worktree path that has already been deleted.

### Finding Description
`repoSync.SyncRepo` publishes each new revision via `publishSymlink`, then calls `syncHooks.afterPublish(newWorktree.Hash())`, which sends the hash to `exechookRunner`/`webhookRunner` via `HookRunner.Send` → `hookData.send`: [1](#0-0) 

The `send` function is explicitly non-atomic with respect to consumption: it always overwrites `d.hash` and only opportunistically pushes an event onto the buffered (size-1) channel; if the channel already has a pending event, the new hash silently overwrites the previous one before it was even read: [2](#0-1) 

The comment on line 135-137 confirms the intended semantics: "we might not send every single hash." This means if the main sync loop publishes revision A, then quickly (within one hook processing cycle) publishes revision B, and the hook consumer hasn't yet drained the channel for A, the hook will run only for B — A's publication event is dropped entirely from the hook's perspective, even though it was fully published via the symlink and briefly visible to filesystem consumers.

Compounding this, `Exechook.Do` resolves the worktree directory to run the command in using `getWorktree(hash)`: [3](#0-2) 

and `git.worktreeFor(hash)` merely computes a path under `.worktrees/<hash>` without verifying existence: [4](#0-3) 

Because `cleanup()` (called every iteration of the main loop after `SyncRepo`) prunes stale worktrees via `removeWorktree`/`os.RemoveAll`: [5](#0-4) [6](#0-5) 

there is a race window in which the asynchronous `HookRunner.Run` goroutine can consume a coalesced or delayed hash whose worktree directory has already been removed by the main loop's cleanup, causing the exechook to run against a nonexistent path.

### Impact Explanation
An attacker controlling the content/cadence of pushes to the upstream repository (a normal, unprivileged capability the tool is designed to sync from) can force git-sync to silently skip webhook/exechook invocation for intermediate published revisions by pushing multiple commits faster than the hook consumer drains events, or than `--period` allows separate wake-ups. This falls under the accepted impact category of "publishing wrong or partial content" from the perspective of the hook contract: the documented behavior ("The call is made after the symlink is updated") is violated for any revision whose hook event was coalesced away, meaning downstream automation (e.g., a webhook triggering a deployment) never learns about a published revision that briefly became the canonical `--link` target. Additionally, the potential exechook failure against an already-removed worktree can produce persistent hook-retry failures (`r.sendOneTimeResultAndTerminate(false)` / backoff loop), which in `--one-time` mode causes git-sync to report failure via `os.Exit(1)` even though the underlying sync itself succeeded — a form of sync/notification denial that is attacker-triggerable purely through repository push cadence.

### Likelihood Explanation
This requires no privileged access to the git-sync host, no leaked credentials, and no cooperating operator — only the ability to push commits to the synced repository/ref at a cadence tighter than `--period` (or faster than the hook consumer's `Do()` execution + drain time), which is exactly the untrusted-repo-content threat surface in scope. It is a real, code-confirmed race (`hookData.send`'s explicit last-write-wins semantics plus unsynchronized worktree cleanup), not a hypothetical. However, actual triggering requires specific timing conditions (rapid multi-commit pushes within a hook-processing window) and only manifests when `--exechook-command` or `--webhook-url` is configured, constraining likelihood to a medium/context-dependent level rather than trivially always-exploitable.

### Recommendation
- Change `hookData` to queue all pending hashes (or at least guarantee delivery of the *last known-good, still-existing* worktree) rather than silently dropping intermediate ones, and document this explicitly as intended behavior if the coalescing is retained by design (as it currently appears to be).
- Have `cleanup()`/`removeStaleWorktrees` skip removing a worktree if it is still referenced by a hash not yet consumed by any registered `HookRunner` (e.g., by tracking in-flight/pending hashes from `hookData.get()` across all runners before pruning).
- In `Exechook.Do`, verify the worktree path exists before executing and produce an explicit, distinguishable error/log entry (rather than a generic exec failure) so operators can differentiate "hook logic failed" from "worktree already recycled due to coalescing."

### Proof of Concept
Conceptual reproduction (not run, derived directly from code paths cited above):
1. Configure `git-sync --repo=<attacker-controlled repo> --root=<root> --link=link --period=2s --exechook-command=<script>`.
2. As the attacker (repo owner/pusher), within a window shorter than the time it takes `exechookRunner` to execute `Do()` and loop back to read `hookData.events()` again, push two or more commits in rapid succession such that a single `--period` tick's `SyncRepo` call is not the limiting factor — e.g., trigger two separate sync loop iterations (`--period` short, e.g. 100ms) each publishing a new hash before the exechook for the first has been dequeued.
3. Observe (via exechook logs / `GITSYNC_HASH` env values received by the script, or via `hookRunCount` metric) that the exechook fires only for the final hash of the burst; the intermediate hash, though published via the symlink swap (`publishSymlink`) and visible during that iteration, never triggers the exechook/webhook.
4. Separately, race the timing so that `cleanup()` (`removeStaleWorktrees`) deletes the worktree directory for a hash before `HookRunner.Run`'s goroutine executes `Do()` for that (now-coalesced-away-or-delayed) hash, causing `Exechook.Do`'s `cmdrunner.Run` to fail with "no such file or directory" against `git.worktreeFor(hash).Path()`.

// Send sends hash to hookdata.
func (r *HookRunner) Send(hash string) {
	r.data.send(hash)
}

// Run waits for trigger events from the channel, and run hook when triggered.
func (r *HookRunner) Run(ctx context.Context) {
	var lastHash string

	// Wait for trigger from hookData.Send
	for range r.data.events() {
		// Retry in case of error
		for {
			// Always get the latest value, in case we fail-and-retry and the
			// value changed in the meantime.  This means that we might not send
			// every single hash.
			hash := r.data.get()
			if hash == lastHash {
				break
			}

			if err := r.hook.Do(ctx, hash); err != nil {
				r.log.Error(err, "hook failed", "hash", hash, "retry", r.backoff)
				updateHookRunCountMetric(r.hook.Name(), "error")
				// don't want to sleep unnecessarily terminating anyways
				r.sendOneTimeResultAndTerminate(false)
				time.Sleep(r.backoff)
			} else {
				updateHookRunCountMetric(r.hook.Name(), "success")
				lastHash = hash
				r.sendOneTimeResultAndTerminate(true)
				break
			}
		}
	}
}

func (h *Exechook) Do(ctx context.Context, hash string) error {
	ctx, cancel := context.WithTimeout(ctx, h.timeout)
	defer cancel()

	worktreePath := h.getWorktree(hash)

	env := os.Environ()
	env = append(env, envKV("GITSYNC_HASH", hash))

	h.log.V(0).Info("running exechook", "hash", hash, "command", h.command, "timeout", h.timeout)
	stdout, stderr, err := h.cmdrunner.Run(ctx, worktreePath, env, h.command, h.args...)
	if err == nil {
		h.log.V(1).Info("exechook succeeded", "hash", hash, "stdout", stdout, "stderr", stderr)
	}
	return err

// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}

// cleanup removes old worktrees and runs git's garbage collection.  The
// specified worktree is preserved.
func (git *repoSync) cleanup(ctx context.Context) error {
	// Save errors until the end.
	var cleanupErrs multiError

	// Clean up previous worktree(s).
	if n, err := git.removeStaleWorktrees(); err != nil {
		cleanupErrs = append(cleanupErrs, err)
	} else if n == 0 {
		// We didn't clean up any worktrees, so the rest of this is moot.
		return nil
	}

	// Let git know we don't need those old commits any more.
	git.log.V(3).Info("pruning worktrees")
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		cleanupErrs = append(cleanupErrs, err)
	}

	// Expire old refs.
	git.log.V(3).Info("expiring unreachable refs")
	if _, _, err := git.Run(ctx, git.root, "reflog", "expire", "--expire-unreachable=all", "--all"); err != nil {
		cleanupErrs = append(cleanupErrs, err)
	}

	// Run GC if needed.
	if git.gc != gcOff {
		args := []string{"gc"}
		switch git.gc {
		case gcAuto:
			args = append(args, "--auto")
		case gcAlways:
			// no extra flags
		case gcAggressive:
			args = append(args, "--aggressive")
		}
		git.log.V(3).Info("running git garbage collection")
		if _, _, err := git.Run(ctx, git.root, args...); err != nil {
			cleanupErrs = append(cleanupErrs, err)
		}
	}

	if len(cleanupErrs) > 0 {
		return cleanupErrs
	}
	return nil
}
