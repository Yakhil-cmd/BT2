## Title
Webhook signature scope (`repository.owner.login`) is decoupled from the repository actually mutated (`repository.full_name`), allowing cross-repository ReviewStack re-provisioning - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to validate against using `params.dig('repository','owner','login')`, while `PullRequest::ReopenedHandler` (and sibling handlers) resolve the repository to mutate using the independent `params.repository.full_name` field. Because both fields come from the same attacker-controlled raw JSON body and are never cross-checked, an attacker who can get a payload verified under any configured organization that has no `webhook_secret` set can name an arbitrary victim repository in `repository.full_name` and trigger `ReviewStackAdapter#find_or_create!`/`#unarchive!` for that victim's stack.

### Finding Description
The broken binding, stated as an equality that the code should enforce but doesn't:
`repository_owner` used in `WebhooksController#verify_signature` (`params.dig('repository','owner','login')`) MUST equal the owner encoded in `params.repository.full_name` used by `ReopenedHandler#repository` to resolve `Shipit::Repository.from_github_repo_name`.

Code path:
- `WebhooksController#verify_signature` picks the `GitHubApp` via `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature` [1](#0-0) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` unconditionally returns `true` when no `webhook_secret` is configured for that organization: `return true unless webhook_secret` [3](#0-2) .
- `Shipit.github_app_config`/`Shipit.github` raise `GithubOrganizationUnknown` (→ 422) only if the named organization is not configured at all; a configured organization with `webhook_secret: nil` (the documented example default) passes silently [4](#0-3) .
- After verification succeeds (using the org resolved from `repository.owner.login`), `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the **entire, unfiltered** JSON body to the handler [5](#0-4) .
- `ReopenedHandler#repository` resolves the *actual target repository* from a **different** field, `params.repository.full_name`, with no re-validation against `repository.owner.login` [6](#0-5) .
- `ReopenedHandler#process` → `stack.unarchive!` (via `ReviewStackAdapter`) uses `params.pull_request.head.ref`/`sha` and `params.number` straight from the same attacker body to create or de-archive the victim's `ReviewStack`, provisioning it via `Shipit::ReviewStackProvisioningQueue.add(stack)` [7](#0-6) [8](#0-7) .

The `ExplicitParameters` schema for `ReopenedHandler` only `requires :repository do requires :full_name, String end` - it never requires or checks `repository.owner.login` for consistency [9](#0-8) . Nothing in the controller or handler enforces that the organization used to select the signing secret is the same organization that owns the repository being mutated.

Exploit flow: attacker crafts a raw JSON body with `repository.owner.login` (or top-level `organization.login`) set to any org name that is configured in Shipit's `secrets.github` but has `webhook_secret` unset/nil, and sets `repository.full_name` to `"victim-org/victim-repo"` (a repository actually tracked by Shipit with `review_stacks_enabled` and a permissive provisioning policy). `verify_signature` looks up the no-secret org, trivially "verifies" (no HMAC needed), and the request proceeds to `ReopenedHandler#process`, which loads the real victim `Repository` via `full_name` and calls `ReviewStackAdapter#find_or_create!`/`unarchive!` with attacker-chosen `head.sha`/`head.ref`.

Existing guards that fail to prevent this: `verify_signature` only rejects genuinely *unknown* organizations, not known-but-secretless ones; `drop_unhandled_event` only checks the event type, not payload consistency; the `ExplicitParameters` schema validates types/presence, not cross-field integrity; no model validation ties `repository.owner.login` to `repository.full_name`.

### Impact Explanation
An attacker can trigger unauthorized re-provisioning (build/deploy trigger) of a victim's ReviewStack, choosing the head sha/ref used for that build, for any repository tracked by the Shipit instance - a payload for one repository/organization mutating another repository's stack. This matches the Critical category "a payload for one repository mutating another's stack, commit, task, or team." It is repeatable against any repository whose review stacks are enabled with an allowing provisioning policy, as long as one configured org in the deployment lacks a `webhook_secret`.

### Likelihood Explanation
Requires: (1) `Shipit.secrets.github` configured with per-organization keys (multi-tenant style) where at least one configured organization has no `webhook_secret` set - this is exactly the documented example default (`webhook_secret: # nil`) [10](#0-9) ; (2) victim repository has `review_stacks_enabled` and an "allow" provisioning policy. No Shipit session, API token, or GitHub secret is needed by the attacker - they only need to know one configured org name (often discoverable/guessable) with no secret and the victim's `owner/repo` name. This is a single unauthenticated HTTP POST to `/webhooks`, fully repeatable.

### Recommendation
Cross-validate that the organization used to resolve/verify the webhook signature matches the owner encoded in `repository.full_name` (and any other “target repository” field consumed by handlers) before dispatching. Additionally, treat an organization configured without a `webhook_secret` as invalid/reject-by-default in production, or require the value used for repository resolution and signature-org resolution to be derived from the same, single, already-verified field.

### Proof of Concept
Minitest under `test/controllers/webhooks_controller_test.rb` style:
```ruby
test "signature verified against a secretless org must not authorize mutating a different repo" do
  # Configure two orgs: "empty-org" (no webhook_secret) and "victim-org" (has a secret)
  Shipit.stubs(:github).with(organization: 'empty-org').returns(stub(verify_webhook_signature: true))
  victim_repo = shipit_repositories(:shipit) # owner: victim-org, review_stacks_enabled: true, allow_all
  stack = create_archived_review_stack_for(victim_repo)

  body = JSON.parse(payload(:pull_request_reopened))
  body["repository"]["owner"]["login"] = "empty-org"       # verified org (no secret)
  body["repository"]["full_name"] = victim_repo.github_repo_name # actually mutated repo
  body["pull_request"]["head"]["sha"] = "attacker-controlled-sha"

  request.headers['X-Github-Event'] = 'pull_request'
  # no X-Hub-Signature header needed since empty-org has no secret

  Shipit::Webhooks::Handlers::PullRequest::ReviewStackAdapter
    .any_instance.expects(:find_or_create!).returns(stack) # or assert stack.reload not archived

  post :create, body: body.to_json, as: :json
  assert_response :ok
  assert_not stack.reload.archived?
end
```
Assert left side (`repository_owner` = `"empty-org"`, verified via no-secret org) diverges from right side (`repository.full_name`'s owner = `"victim-org"`), yet the victim's stack is still mutated - proving the binding is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
