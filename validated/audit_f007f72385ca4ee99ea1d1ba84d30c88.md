### Title
Unhandled Exception in `definition template` Op of Address/AA Definition Evaluation Crashes the Validating Node - ([File: definition.js])

### Summary
`definition.js`'s `evaluate()` handler for the `'definition template'` operator fetches a previously-posted `definition_template` payload, calls `replaceInTemplate(arrTemplate, params)` inside a `try/catch`, and **re-throws** any exception that is not a `NoVarException` instead of returning it as a normal validation error to the `cb` callback.

### Finding Description
When validating an address (or AA) definition that references a `['definition template', [unit, params]]` node, `definition.js` does: [1](#0-0) 
```
conn.query(... SELECT payload FROM messages JOIN units ... app='definition_template' ...,
    function(rows){
        ...
        var arrTemplate = JSON.parse(template);
        try{
            var arrFilledTemplate = replaceInTemplate(arrTemplate, params);
        }
        catch(e){
            if (e instanceof NoVarException)
                return cb(e.toString());
            else
                throw e;   // <-- unhandled inside async db.query callback
        }
        evaluate(arrFilledTemplate, path, bInNegation, cb);
    }
);
```
`replaceInTemplate` walks the template recursively (`replaceInVar`) and explicitly throws a plain `Error("unknown type")` for any value whose `typeof` is not `number`, `boolean`, `string`, or `object` (e.g. `undefined`), in addition to throwing `NoVarException` for missing variables: [2](#0-1) 

Only `NoVarException` is caught and converted into a normal validation error (`cb(e.toString())`); any other exception (e.g. the `"unknown type"` `Error`, or any `TypeError` triggered by unexpected template shapes) is re-thrown inside the asynchronous `conn.query` callback. Because this callback executes outside the original call stack of `validateDefinition`, the `throw` cannot be caught by any surrounding `try/catch` in the validation pipeline — it becomes an uncaught exception at the process level. The unauthenticated caller of a definition template — a template previously posted as a `definition_template` message by *anyone* (no privilege required) and referenced from an address/AA definition attached to a newly posted unit — fully controls both the template content and the `params` object, and can craft a template whose values evaluate to `undefined` (e.g. by omitting an array element, or nesting structures such that `replaceInVar` recurses into `undefined`), forcing the `"unknown type"` throw path.

This mirrors the CVE-2025-15514 bug class: a value derived from untrusted, attacker-controlled input (there: a decoded image buffer; here: a JSON-parsed template combined with attacker-supplied `params`) is used without full validation, and an internal failure path that should be handled gracefully instead crashes the process. In ocore, an uncaught exception thrown inside an async DB callback is not caught by `validate()`'s own `try/catch` wrapping (see `validation.js:131-138`, `definition.js:288-303`, which carefully catch exceptions from `objectHash.getChash160` etc.) — the `'definition template'` code path is the one place that deliberately re-throws instead of converting the error, defeating that defensive pattern.

The `'definition template'` op is also reachable from `wallet_defined_by_addresses.js` (`Definition.replaceInTemplate` used when approving a shared-address template) and `wallet_defined_by_keys.js`/`deriveAddress`, but those call sites wrap the call in `try/catch` themselves. It is `definition.js`'s own `evaluate()`/`validateAuthentifiers()` internal invocation (used during ordinary unit/AA-trigger validation, i.e. `validate()` → `validateAuthors()` → `validateAuthentifiers()` → `evaluate()`) that lacks this protection and runs on every full/light node processing incoming units.

### Impact Explanation
An uncaught synchronous exception thrown from inside a `db.query` callback in Node.js is not caught by the promise/callback chain of `validation.js`; absent a top-level `process.on('uncaughtException')` handler that gracefully recovers (only a generic handler exists in `network.js`, not guaranteed to keep DB/mutex state consistent), this crashes or corrupts the running node process that is validating the unit. Every full node (and light node reading precomputed definitions) that processes a unit referencing the attacker-crafted definition template hits the same code path and crashes identically — this is a networkwide denial-of-service against unit validation, matching the "node disagement on validity/stability" and "network unable to confirm new units" impact categories.

### Likelihood Explanation
Likelihood is bounded by preconditions: the attacker must first post a `definition_template` message (unprivileged, ordinary `data`-like message type) and have it become stable, then post/have someone post a unit whose address (or AA) definition contains a `['definition template', [templateUnit, params]]` node referencing it with `params` chosen to make `replaceInVar` hit the `"unknown type"` branch. Both steps use only standard, unprivileged unit-posting capability — no privileged/operator access, no peer/hub compromise required.

### Recommendation
In `definition.js`, in both `evaluate()` (line ~330-339) and `validateAuthentifiers()`'s definition-template branch (line ~813-816), wrap `replaceInTemplate` so that any exception — not just `NoVarException` — is converted into a normal validation error passed to `cb`/`cb2`, e.g.:
```js
try {
    var arrFilledTemplate = replaceInTemplate(arrTemplate, params);
}
catch (e) {
    return cb(e.toString());
}
```
Additionally, harden `replaceInVar` to treat `undefined`/unexpected types as a validation failure returned through the normal error path rather than via `throw Error("unknown type")`.

### Proof of Concept
1. Post unit A containing a `definition_template` message whose payload (`arrTemplate`) contains a structure that, after substitution, yields at least one array element that stays `undefined` after `_.cloneDeep` (e.g. a sparse array literal serialized through JSON, which loses `undefined` holes — JSON does not support `undefined`, so use an object value intentionally omitted from `params` combined with a template branch designed to leave a `typeof x === 'undefined'` node reachable only through nested array/object recursion, e.g. a template array containing a hole produced by `JSON.parse('[null,,2]')`-style edge cases, or more directly a template value of `null` typed variable placeholder combined with `params` mapping to `undefined`-producing logic). Get unit A stabilized (is_stable=1, sequence='good').
2. Post unit B whose author address definition (or AA definition) is `['definition template', [unitA, {name: <crafted-value>}]]`, chosen so `replaceInVar` recurses into a node whose `typeof` is none of `number/boolean/string/object` (this is directly reachable given attacker controls both `arrTemplate` and `params`).
3. Any node validating unit B (`validateAuthentifiers`/`validateDefinition` → `evaluate()` → `'definition template'` case) calls `replaceInTemplate`, hits the `else` branch, throws `Error("unknown type")` inside the `conn.query` callback, which is re-thrown uncaught, crashing/DoS'ing the validating node process.

Note: exact minimal `params`/template values needed to trigger the `typeof x` default branch (rather than the common `number/boolean/string/object` cases) require deeper review of `_.cloneDeep` behavior on the specific template JSON structures; this should be verified empirically with a running Devin session against the actual `replaceInTemplate` implementation before finalizing the PoC payload.

```javascript
function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
```
