### Title
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when an organization's `webhook_secret` is unset - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#verify_webhook_signature` short-circuits with `return true unless webhook_secret` before any HMAC comparison is performed, and `webhook_secret` is derived via `@config[:webhook_secret].presence`, so an empty string or `nil` secret makes signature verification a no-op. `WebhooksController#verify_signature` then treats the request as authentic and dispatches it to handlers, regardless of the `X-Hub-Signature` header content.

### Finding Description
The intended binding is: `verified == true` implies HMAC-SHA1(`webhook_secret`, `request.raw_post`) matches the value in `X-Hub-Signature`, for the real per-organization secret. In code: [1](#0-0) 

`webhook_secret` is set from config with `.presence` [2](#0-1) , so any config value of `nil` or `''` makes `webhook_secret` falsy, hitting `return true unless webhook_secret` before the signature is ever parsed or compared.

`WebhooksController#verify_signature` calls this method and only rejects the request (`head(422)`) when `verified` is `false` [3](#0-2) ; when `verified` is `true` because the secret is absent, the request proceeds to `create`, which parses `request.raw_post` as JSON and dispatches it to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .

The organization used to select the `GitHubApp`/config is taken directly from the attacker-controlled payload: `repository_owner` reads `params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')` [5](#0-4) , and `Shipit.github(organization: repository_owner)` looks up that org's config [6](#0-5) . So an attacker can name any configured organization in the JSON body and get that org's `GitHubApp` instance.

The documentation itself describes the webhook secret as optional ("Webhook secret (optional): Fill it with some randomly generated string..."), so an operator following the setup guide verbatim can end up with `webhook_secret` unset for one or more organizations, in which case this bypass is live for that organization's webhooks. No other guard (`check_if_ping`, `drop_unhandled_event`, `verify_signature` itself) performs any additional authenticity check — `verify_signature` is the only gate.

Note: the "sha1-only algorithm" half of the question does not hold up as a separate bypass — GitHub always sends `X-Hub-Signature` (sha1) alongside `X-Hub-Signature-256` when a secret is configured, so restricting to `sha1` does not cause legitimate requests to be rejected or create an exploitable divergence by itself; it only matters in combination with the falsy-secret case above.

### Impact Explanation
When an organization's `webhook_secret` is falsy, any unauthenticated internet user can POST forged JSON payloads to `/webhooks` naming that organization/repository, and have them processed by the registered handlers (`push_handler.rb`, `status_handler.rb`, `check_suite_handler.rb`, `membership_handler.rb`, `pull_request/*`) as if GitHub had sent them. Depending on which handlers are active, this can result in unauthorized status/check writes, merge-queue state changes, or other stack mutations recorded as authentic GitHub events — an authentication bypass matching the "forged webhook accepted" Critical category. The blast radius is scoped to organizations whose `webhook_secret` is left blank; other organizations with a real secret configured remain protected since the HMAC comparison still runs for them.

### Likelihood Explanation
Exploitation requires no attacker secrets and no privileged role — only that the targeted Shipit deployment has at least one GitHub organization configured with an empty/nil `webhook_secret`, which the project's own setup documentation calls out as optional. This is a plausible, low-effort misconfiguration (or a deliberate simplified setup) rather than a hypothetical one, making likelihood non-trivial wherever that documented shortcut is taken. Attack cost is a single crafted HTTP POST, fully repeatable.

### Recommendation
Fail closed instead of open: require `webhook_secret` to be present for any organization that receives webhooks, and reject (422) requests when it is missing rather than treating a missing secret as "signature verified." At minimum, log/alert loudly and refuse to process webhooks for organizations without a configured secret, and remove or clarify the "optional" wording in `docs/setup.md` to state that omitting it disables signature verification entirely.

### Proof of Concept
```ruby
# test/unit/github_app_test.rb (conceptual, no live GitHub required)
test "verify_webhook_signature bypasses verification when webhook_secret is blank" do
  config = { webhook_secret: '', app_id: 1, installation_id: 1, private_key: nil }
  app = Shipit::GitHubApp.new('acme', config)

  # Binding under test: verified == true must imply a valid HMAC-SHA1 over the real secret.
  # Left side (actual):
  actual = app.verify_webhook_signature('sha1=totally-forged-value', 'arbitrary-raw-post-body')
  # Right side (expected under the binding):
  expected = false # no valid HMAC was computed/matched

  assert_equal expected, actual # fails: actual is true, demonstrating the bypass
end
```
This confirms `verified` becomes `true` for a forged signature purely because `webhook_secret` is falsy, violating the stated binding, and would let `WebhooksController#verify_signature` accept the forged request for that organization.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
```
