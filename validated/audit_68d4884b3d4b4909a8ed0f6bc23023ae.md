### Title
API-scoped ApiClient token can read CCMenu build status of any stack, bypassing its `stack_id` authorization scope - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::ApiClient` tokens can be restricted to a single stack via `stack_id`, and `Api::BaseController#stacks`/`#stack` enforce that scope for every other API resource. `Api::CCMenuController` overrides `#stack` to look the target stack up unscoped, so a token that is only authorized for stack A can be used with an arbitrary `stack_id` in the URL to read the CCTray build status of stack B.

### Finding Description
`ApiClient` can be scoped to one stack: `belongs_to :stack, optional: true` [1](#0-0) . The base API controller enforces this scope for resource lookup:
```
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
``` [2](#0-1) 

Every other stack-scoped API controller (e.g. `Api::StacksController`) resolves its target stack through this scoped `stacks`/`stack` helper, so a token bound to stack A cannot address stack B [3](#0-2) .

`Api::CCMenuController`, however, defines its own `#stack` method that bypasses the scoped helper entirely:
```
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
``` [4](#0-3) 

It only enforces `require_permission :read, :stack` [5](#0-4) , which checks that the permission string `read:stack` is present in the token's permission list via `ApiClient#check_permissions!` [6](#0-5)  — it never checks whether the requested stack matches `current_api_client.stack_id`. The route accepts an arbitrary `stack_id` segment: `get '/ccmenu' => 'ccmenu#show', as: :ccmenu` under `scope '/stacks/*stack_id' ...` [7](#0-6) .

This breaks the binding: **stack a token authorizes (`ApiClient#stack_id`) ≠ stack it touches (`params[:stack_id]` resolved by `CCMenuController#stack`)**.

### Impact Explanation
A token created for stack A with only `read:stack` permission (e.g. the auto-created "CCMenu Client" from `CCMenuUrlController`, which is created with `permissions: %w[read:stack]` and scoped implicitly to whatever stack requested it) [8](#0-7)  can be replayed against `/api/stacks/<owner>/<name>/<env>/ccmenu` for any other stack in the installation, disclosing that stack's build/deploy status (`lastBuildStatus`, `lastBuildLabel`, lock state, etc.) even though the token's authorization scope should confine it to a single stack. This is an unauthorized cross-stack read of stack/task state through a valid, but wrongly-scoped, credential — matching the "unauthenticated/unauthorized read of stack state" impact bucket.

### Likelihood Explanation
High likelihood of exploitation once a scoped, low-privilege token is obtained (e.g. leaked CCMenu URL, which explicitly embeds the token in a query string per `CCMenuUrlController#fetch` [9](#0-8) ). No privilege escalation or additional secrets are required — only changing the `stack_id` path segment on an otherwise legitimate, valid request.

### Recommendation
Change `Api::CCMenuController#stack` to resolve the stack through the scoped `stacks` collection (i.e. delegate to `BaseController#stack`, or implement `stacks.from_param!(params[:stack_id])`) instead of calling `Stack.from_param!` directly, so the `current_api_client.stack_id` restriction is enforced consistently with all other stack-scoped API endpoints.

### Proof of Concept
1. Create (or have Shipit auto-create via `CCMenuUrlController#fetch`) an `ApiClient` scoped to Stack A with permission `read:stack` only.
2. Note the token embedded in the returned `ccmenu_url` (`ApiClient#authentication_token`) [10](#0-9) .
3. Send `GET /api/stacks/<owner>/<repoB>/<envB>/ccmenu?token=<token>` for Stack B (a different stack the client was never granted access to).
4. `authenticate_api_client` in `CCMenuController` accepts the token via `ApiClient.authenticate(params[:token])` [11](#0-10) , `require_permission :read, :stack` passes because the token has `read:stack`, and `#stack` resolves Stack B unscoped, returning Stack B's CCTray XML with its build status — despite the token being authorized only for Stack A.
