### Title
Global TPS-fee congestion counter can be inflated by a single cheap unit via `max_aa_responses`, causing network-wide fee spikes and transient rejection of legitimate units - (File: storage.js)

### Summary
`storage.js`'s `getCurrentTps`/`getRecentTps` compute a global, shared "transactions per second" statistic from all currently unstable units, weighting each unit by `getCountUnitsPayingTpsFee(objUnitProps)`, which adds `count_primary_aa_triggers * max_aa_responses` on top of 1 for every unit that triggers an AA [1](#0-0) . This global counter directly drives `getCurrentTpsFee`/`getCurrentTpsFeeToPay` and `getMinAcceptableTpsFeeMultiplier`, which set the minimum acceptable `tps_fee` for every unit submitted by every user on the network [2](#0-1) [3](#0-2) . Because a single unprivileged unit poster fully controls `max_aa_responses` (bounded only by `constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER`) on their own unit, they can inflate their own contribution to this shared, global counter far beyond the actual load their unit represents, without waiting for any AA execution to occur.

### Finding Description
`validateAATrigger` in `validation.js` allows any unit whose payment output targets exactly one AA address to carry an arbitrary `max_aa_responses` value up to `constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER` [4](#0-3) . This value is copied into the cached unstable-unit props via `getTrigger`/unit properties and is used, while the unit is merely unstable (not yet even validated by an actual AA execution), to inflate the global TPS estimate:

- `getCountUnitsPayingTpsFee` returns `1 + count_primary_aa_triggers * max_aa_responses` for any unit with an AA trigger [1](#0-0) .
- `getCurrentTps` sums this weight for every unstable unit since `last_stable_mci` (or within a shift window) to compute the network-wide tps [5](#0-4) .
- `getRecentTps` similarly sums this weight over a rolling 60-second window across all unstable units [6](#0-5) .
- `getCurrentTpsFee`/`getCurrentTpsFeeToPay` derive the minimum tps fee from this inflated tps value using an exponential curve, so the effect of inflating the count is amplified [2](#0-1) .
- `getMinAcceptableTpsFeeMultiplier` jumps the multiplier to 5x once `getRecentTps` exceeds 15 [3](#0-2) .
- `validateTpsFee` in `validation.js` uses `storage.getCurrentTpsFee`/`getMinAcceptableTpsFeeMultiplier` to reject (with a transient/soft error) any unit whose `tps_fee` balance doesn't meet the resulting `min_acceptable_tps_fee`, applying this globally-computed threshold to every unit from every author, not just the one that set a high `max_aa_responses` [7](#0-6) .

Since `max_aa_responses` merely declares an upper bound the poster is willing to pay for/accept (it is not actual observed AA response count — that is only known after the AA executes), the attacker never needs to actually cause `MAX_RESPONSES_PER_PRIMARY_TRIGGER` responses to happen; setting the field to its maximum on a single, cheap trigger unit posted to any AA is enough to add up to `constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER` "phantom" units to the global load estimate while the trigger unit is unstable.

### Impact Explanation
This is a manipulation of a global, network-wide statistic (directly analogous to the reported `TimeLockStrategy` daily-limit manipulation) that causes inconvenience/DoS for legitimate users: while the attacker's unstable unit(s) remain unconfirmed, every other unit in the network faces an inflated `min_tps_fee`/`min_acceptable_tps_fee` requirement, and unrelated legitimate senders who don't overpay tps fees get their otherwise-valid units soft-rejected with `createTransientError` in `validateTpsFee` [8](#0-7) . This matches the accepted impact category "a network unable to confirm new units" at a reduced/degraded rate, and requires no privileged role — only posting an ordinary AA-triggering unit.

### Likelihood Explanation
Any unprivileged unit poster can trigger this by including a payment output to an AA address together with `max_aa_responses` set near `constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER` in their own unit; `validateAATrigger`'s only checks are that the value is a non-negative integer not exceeding the constant and not zero for new units [4](#0-3) . No cooperation from an AA, hub, or other node is required, and the effect (inflated `getCurrentTps`/`getRecentTps`) persists for as long as the unit(s) remain unstable, which can be repeated by posting further such units.

### Recommendation
Do not let a self-declared, unexecuted `max_aa_responses` value count toward the global tps/load estimate before the AA has actually produced that many responses. Options: base `getCountUnitsPayingTpsFee` for unstable (not-yet-executed) units on a fixed/conservative default (e.g. 1, or the actual `count_aa_responses` once known) rather than the caller-supplied `max_aa_responses`; or charge/weight the declared `max_aa_responses` fee locally to the triggering address only rather than folding it into the shared network-wide tps statistic that gates all other unrelated units.

### Proof of Concept
1. Attacker composes and posts a normal unit (`objUnit`) with a payment output to any existing AA address and sets `objUnit.max_aa_responses = constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER` (the maximum allowed value) — accepted by `validateAATrigger` since it only checks the numeric bound [4](#0-3) .
2. While this unit is unstable, `storage.getCountUnitsPayingTpsFee` counts it as `1 + 1 * MAX_RESPONSES_PER_PRIMARY_TRIGGER` "units" instead of 1 [1](#0-0) .
3. `getCurrentTps`/`getRecentTps` therefore report a tps far above the real network throughput, and `getCurrentTpsFee`/`getMinAcceptableTpsFeeMultiplier` compute an inflated `min_acceptable_tps_fee` for every unit submitted network-wide [9](#0-8) .
4. Any other legitimate user whose unit's paid `tps_fee` balance is below this inflated threshold gets a transient rejection in `validateTpsFee` until the attacker's unit stabilizes or enough time passes [8](#0-7) .
5. Repeating step 1 with fresh units (each cheap, single-author, single AA-output) sustains the inflated global counter indefinitely, degrading network-wide unit confirmation for everyone else — mirroring the reported global daily-limit manipulation causing legitimate-user inconvenience.

function getRecentTps(bForceRecalc = false) {
	const period = 60; // seconds
	const ts = Math.round(Date.now() / 1000);
	if (ts - last_recent_tps_ts < period && !bForceRecalc)

	}
	last_recent_tps = count / period;
	last_recent_tps_ts = ts;
	return last_recent_tps;
}
