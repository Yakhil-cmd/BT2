### Title
Stop hook review set can be emptied to zero via `git commit --amend`/history rewrite after `capture_git_baseline`, silently skipping a dangerous change - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` intersects `dirty_now` (current `git status` vs. index/HEAD) with `changed_since` (diff vs. the UPS-captured baseline) to build the file set reviewed by the Stop hook. When Claude commits a dangerous change and then rewrites history on top of it (e.g. `git commit --amend`, interactive rebase/reword, squash), `dirty_now` becomes empty because the working tree is clean relative to the new HEAD, while the linear-ancestor fast-path that would otherwise re-include committed files never fires because the rewritten HEAD is not a git-ancestor descendant of `head_at_capture`. The intersection with an empty set yields an empty review set, so the dangerous file is dropped from review even though `changed_since` (diff against `baseline_sha`) still contains it.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is called at `UserPromptSubmit` via `handle_user_prompt_submit` (`plugins/security-guidance/hooks/security_reminder_hook.py:446-515`), saving `baseline_sha` (a `git stash create` SHA, or HEAD if clean) and `head_at_capture` (`_git_rev_parse_head`).

At `Stop`, `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:
```
tracked_dirty, untracked = _git_status_porcelain(repo)
...
dirty_now = tracked_dirty | new_untracked
diff_base = "HEAD"
current_head = _git_rev_parse_head(repo)
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
...
changed_since = _git_name_only(repo, baseline_sha) | new_untracked   # if baseline_sha
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
``` [1](#0-0) 

`_is_ancestor` (`plugins/security-guidance/hooks/gitutil.py:377-387`) checks `git merge-base --is-ancestor <head_at_capture> <current_head>`, which is only true when HEAD moved strictly forward (plain commit/merge). `git commit --amend`, rebase, or reword/squash produce a new commit whose SHA is not a descendant of the pre-rewrite commit, so `_is_ancestor` returns `False`. [2](#0-1) 

Exploit flow (normal git operations only, no privilege needed beyond what Claude Code already grants the agent in a session):
1. UPS captures `baseline_sha` = stash/HEAD before the turn, `head_at_capture` = old HEAD.
2. Claude edits a file introducing a dangerous change and runs `git commit` (new HEAD, `head_at_capture` is ancestor — still reviewable at this point).
3. Claude (or the same automated flow) runs `git commit --amend` (e.g., to fix the commit message, or squash a fixup) — the working tree becomes clean relative to the *new* HEAD, and the new HEAD is not an ancestor-descendant of `head_at_capture`.
4. At Stop: `_git_status_porcelain` returns no tracked dirty files and no new untracked files → `dirty_now = ∅`. The ancestor fast-path is skipped (`_is_ancestor` is `False`), so `dirty_now` stays `∅`.
5. `changed_since = _git_name_only(repo, baseline_sha)` still correctly contains the dangerous file (diff vs. the true pre-turn baseline), but `review_set = dirty_now & changed_since = ∅ & {dangerous_file} = ∅`.
6. The Stop hook logs `diff_files_count`/`review_set_count == 0` and exits without ever running `analyze_code_security` on the dangerous file (`plugins/security-guidance/hooks/security_reminder_hook.py:1824-1827` `_skip(7)` path), and `capture_git_baseline` is then re-run to move the baseline forward — permanently losing the ability to detect the change in subsequent diffs.

This breaks the stated invariant ("review set must stay bound to the right repo, baseline, and touched paths") because the reviewable set silently collapses to empty for a file that legitimately changed since baseline, purely due to ordinary history-rewriting git commands available to the agent/session, not any privilege escalation.

### Impact Explanation
This is a Logic-level bypass of the security-guidance Stop-hook review guard: a dangerous code change introduced during a Claude Code turn can be committed and then amended/rebased before Stop fires, causing the vulnerability-scanning LLM review to never see the change and the "areas of concern"/vulnerability-flagging enforcement (`sys.exit(2)` continuation loop) to never trigger. This directly matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — the guard (Stop-hook Haiku review) is bypassed entirely for the affected file.

### Likelihood Explanation
Fully reachable through routine developer/agent workflow: commit-then-amend, interactive rebase reword, or squash are extremely common patterns an autonomous coding agent (or a user directing it) would naturally perform, e.g. "fix the commit message" or "squash these into one commit" after introducing a change. No special git configuration, admin rights, or social engineering is required — just two ordinary git commands executed inside the working tree the agent already controls during a normal session. The bug is deterministic given the described sequence, so it is highly repeatable.

### Recommendation
Do not gate the committed-changes term of `review_set` on strict linear ancestry alone. When `head_at_capture != current_head` but `_is_ancestor` is false (history was rewritten), fall back to including files from `changed_since` directly (i.e., treat `dirty_now` as `changed_since` in that case, or explicitly union in `_git_name_only(repo, baseline_sha)` results) rather than intersecting an empty `dirty_now` with a nonempty `changed_since`. More generally, `review_set` should never be forced to `∅` when `changed_since` (diff vs. `baseline_sha`) is nonempty — the baseline diff is the ground truth for "did anything change since the last review," and `dirty_now` should only be used to *expand*, not to *zero out*, that set.

### Proof of Concept
Unit/integration test in the existing `compute_v2_review_set` test suite (mirroring existing git-fixture based tests for this function):
1. Init a git repo, commit an initial file, capture `baseline_sha = capture_git_baseline(repo)` and `head_at_capture = _git_rev_parse_head(repo)`.
2. Write a dangerous change to `app.py` (e.g., `eval(user_input)`), `git add`, `git commit -m "wip"`.
3. Run `git commit --amend -m "final message"` (no content change, just amend) — working tree is now clean relative to new HEAD.
4. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, untracked_at_baseline={})`.
5. Assert: expected — `review_paths` contains `app.py`. Actual (bug) — `review_paths == []` because `dirty_now` is empty and `_is_ancestor(repo, head_at_capture, new_head)` is `False`, forcing `review_set = ∅`.

This demonstrates the invariant violation: a dangerous, baseline-diff-visible change (`changed_since` nonempty) is dropped from the review set solely due to an intervening `git commit --amend`.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
