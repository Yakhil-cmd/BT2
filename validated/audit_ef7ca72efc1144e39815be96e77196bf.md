### Title
Webhook signature verification selects the GitHub App/organization from attacker-controllable query-string params while the actual event payload is re-parsed from the raw body - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which `GitHubApp` (and therefore which `webhook_secret`) to validate the HMAC signature against using `repository_owner`, which reads from the framework's `params` accessor. `#create`, however, processes the event using a payload obtained by directly re-parsing `request.raw_post`. Because these two payload sources are not guaranteed to be the same object once query-string parameters are involved, an attacker can make the signature-verification path authenticate against an organization/app config of their choosing (e.g., one with no `webhook_secret` configured, or one whose secret they know) while the JSON body handled by `#create` actually targets a different, victim repository/organization.

### Finding Description
`verify_signature` computes the app used for HMAC verification purely from `repository_owner`, which is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) [2](#0-1) . `params` here is Rails' unified parameter hash, which is built by merging `query_parameters` on top of the JSON body's `request_parameters` for same-named top-level keys - i.e. a query-string value for a top-level key such as `repository` or `organization` can replace the corresponding value derived from the JSON body for the purposes of `params`.

`#create`, on the other hand, does not use the (potentially query-string-tainted) `params` object to determine what to process; it re-parses the untouched raw body directly: `params = JSON.parse(request.raw_post)` and dispatches to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [3](#0-2) .

This creates exactly the "authenticated organization" vs. "processed repository" binding break called out in the analog rules: the organization whose `webhook_secret` is used to accept the request is not necessarily the organization/repository whose data is actually processed by the event handlers. `GitHubApp#verify_webhook_signature` further compounds this because a webhook secret is optional and, when absent, verification is a no-op: `return true unless webhook_secret` [4](#0-3) .

Handlers such as `PushHandler` operate on whatever repository/branch is present in the body-derived payload without any re-check against the organization used during signature verification: it looks up the target `Stack`s by branch and triggers `sync_github` [5](#0-4) , i.e. once past `verify_signature`, the payload is trusted for whatever repository it names.

### Impact Explanation
This is the webhook analog of `hasRole` trusting a role flag without checking the token that is supposed to back it: the code checks "is this signed by *some* configured app" (chosen via attacker-influenced `repository_owner`) instead of checking "is this signed by the app that owns the repository this payload actually claims to modify." Concretely:

- If a Shipit deployment has multiple orgs configured (`Using Multiple Github Applications`, documented in `docs/setup.md`) and even one of them has no `webhook_secret` set (it's explicitly optional per the setup docs), an attacker can supply a query string that makes `repository_owner` resolve to that no-secret org, causing `verify_webhook_signature` to trivially return `true`, while the JSON body actually targets a *different*, secret-protected victim repository/organization.
- Successfully forging accepted `push` or `status` events lets an attacker trigger `Stack#sync_github`, influence CI status handling used by the merge queue, or otherwise inject fabricated GitHub state into Shipit without possessing any repository write access, App private key, or webhook secret for the targeted repo - an authentication bypass on an unauthenticated endpoint that can lead to unauthorized deploy-relevant state changes.

### Likelihood Explanation
The `/webhooks` endpoint is unauthenticated by design (it's meant to be called by GitHub), so this is reachable by any unprivileged network attacker who knows (or guesses) the Shipit host. The prerequisite - at least one configured GitHub App entry without a `webhook_secret`, or one whose secret is known/leaked - is realistic given the docs explicitly present the webhook secret as optional. Constructing the query string vs. body-key mismatch requires no special access, only careful crafting of the HTTP request (moving `repository.owner.login`/`organization.login` into the query string while leaving the real target data in the JSON body).

### Recommendation
Do not derive `repository_owner` from Rails' `params` (which can be influenced by the query string). Instead:
- Parse `repository_owner` from the same `JSON.parse(request.raw_post)` payload that `#create` actually processes, and use that single parsed value consistently for both signature verification and event dispatch.
- Reject requests whose organization cannot be unambiguously and exclusively derived from the raw body (ignore/strip query string parameters entirely for this purpose).
- Consider making `webhook_secret` mandatory (or logging/alerting when it is absent) rather than silently treating a missing secret as "verification passed."

### Proof of Concept
1. Configure Shipit with at least two GitHub App organizations per the documented multi-org format, where `OrgA` has no `webhook_secret` set and `OrgB` (the real target) has one configured, per `docs/setup.md`'s "Using Multiple Github Applications" section.
2. Craft an HTTP POST to `/webhooks` with:
   - Query string: `?repository[owner][login]=OrgA`
   - Header `X-Github-Event: push`
   - Body (raw JSON, real target): `{"ref":"refs/heads/main","after":"<sha>","repository":{"owner":{"login":"OrgB"},"name":"victim-repo"}, ...}`
   - Any (or no) `X-Hub-Signature` header.
3. `verify_signature` computes `repository_owner` from `params`, which - due to Rails' query-string merge behavior on the top-level `repository` key - resolves to `OrgA` and thus `Shipit.github(organization: 'OrgA')`.
4. Because `OrgA` has no `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally, regardless of the actual signature.
5. `#create` proceeds to `JSON.parse(request.raw_post)`, which still contains the real `OrgB`/`victim-repo` data, and dispatches it to `PushHandler`, causing Shipit to process a forged push event for `OrgB`'s repository without ever validating against `OrgB`'s webhook secret.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
```
