### Title
Permissionless bad-debt cleanup can be indefinitely griefed by third-party dust top-ups of the victim's existing collateral leg - (File: contracts/controller/src/positions/supply.rs)

### Summary
`clean_bad_debt` is permissionless but gated on the insolvent account's remaining collateral being at or below a fixed dust threshold (~$5). Any unprivileged address may supply additional funds into an existing supply leg of a foreign account. An attacker can therefore repeatedly top up an insolvent account's collateral just above the dust threshold, making every `clean_bad_debt` call revert while the account stays insolvent — a denial of service of the bad-debt socialization path payable in small amounts of the attacker's own funds.

### Finding Description
The permissionless cleanup path `process_clean_bad_debt` → `clean_bad_debt_standalone` → `socialize_bad_debt` admits an account only when `BadDebtGate::DustCapped` holds, i.e. `is_socializable_bad_debt(total_debt, total_collateral)` — debt exceeds collateral *and* collateral is at or below the dust threshold (`CannotCleanBadDebt` otherwise). [1](#0-0) 

Meanwhile `process_supply` only restricts third parties from opening *new* asset slots: `require_third_party_existing_supply` allows any caller to top up a hub asset the victim already holds, with no health-factor requirement on the target account (supply needs no price/HF check). [2](#0-1)  The invariants document this deliberately: "Anyone may top up an account they do not own, but only for hub assets it already holds a supply position in" (INV-AUTH-03), and cleanup requires "ceil risk debt greater than half-up unweighted collateral and collateral at or below the fixed $5 dust threshold" (INV-LIQ-04). [3](#0-2) 

Combining the two: whenever an insolvent account's collateral drifts to ≤ the dust cap (the exact precondition for cleanup), a griefer calls `supply` with a small amount on one of the account's existing collateral legs, pushing `total_collateral` above the threshold. `clean_bad_debt` then reverts with `CannotCleanBadDebt`. This is repeatable each time the gate is met again.

### Impact Explanation
Bad debt remains on the protocol's books instead of being socialized via the permissionless path: the index write-down and debt write-off in `bad_debt::execute_bad_debt_cleanup` never run, leaving the market's measured shortfall (and supplier haircut) unresolved. The only remaining path is the owner-gated `force_socialize_bad_debt`, so an attacker can force reliance on a privileged runbook — a temporary/permanent freezing of the cleanup mechanism and continued accrual of unpaid debt, matching "temporary freezing of funds / protocol insolvency persistence" impact classes. The griefing cost is small: only enough to push collateral above the ~$5 dust cap per attempt, though the donated funds are lost to the attacker (they become revenue at eventual cleanup).

### Likelihood Explanation
Reachable by any unprivileged address holding a few units of any listed asset the insolvent account already supplies. Requirements: the target account must be insolvent with collateral near the dust threshold — precisely the state where cleanup is needed — and must hold at least one supply leg the attacker can top up (always true, since dust collateral is the precondition). No privileged role, oracle manipulation, or timing dependence is required. Severity is bounded to Medium because the owner-gated `force_socialize_bad_debt` runbook remains available, each griefing iteration costs the attacker real funds, and collateral cannot be pushed arbitrarily high without exceeding the debt (which would exit the insolvency gate only by making the account healthy — economically self-defeating at dust scale).

### Recommendation
Add a stale-check to the dust gate, e.g. measure collateral "at cleanup admission" excluding third-party top-ups — options: (a) record per-account a cleanup-eligibility flag/timestamp once collateral first falls below the dust cap and allow cleanup while debt remains outstanding regardless of later top-ups; (b) let the griefer's top-up be counted but net donated collateral against the same-market debt before re-evaluating the gate; or (c) accept an opt-in `seize_mode`/`cap` argument on `clean_bad_debt` letting the caller proceed when excess collateral is attributable to donations within a window. Simplest robust fix: cache `total_collateral_at_insolvency` when the account is first observed insolvent and treat the DustCapped gate on that value.

### Proof of Concept
1. `ALICE` supplies 10 USDC of collateral and borrows `ETH`; price moves so the account is insolvent with residual collateral valued at $4 (below the $5 dust cap).
2. Liquidator calls `clean_bad_debt(alice_id)` → would succeed (`total_debt > total_collateral` and collateral ≤ dust).
3. Attacker `BOB` front-runs / repeats: `controller::supply { caller: BOB, account_id: alice_id, assets: [(existing_usdc_leg, 2 USDC)] }`. `require_third_party_existing_supply` passes because the leg exists; collateral is now ~$6.
4. `clean_bad_debt(alice_id)` reverts `CannotCleanBadDebt` — `is_socializable_bad_debt` fails the dust cap.
5. Each time interest/price drift returns collateral under the cap, BOB repeats step 3 for ~$1–2 per iteration; permissionless cleanup stays bricked and the bad debt is never socialized until governance runs the owner-gated force-socialize runbook.

pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

/// Restricts third parties to existing supply positions. New accounts are
/// exempt because the caller becomes their owner.
fn require_third_party_existing_supply(
    env: &Env,
    account_id: u64,
    resolved_account_id: u64,
    caller: &Address,
    account: &Account,
    aggregated: &AggregatedPayments,
) {
    if account_id != 0
        && !account::is_owner_or_delegate(env, resolved_account_id, caller, &account.owner)
    {
        for (hub_asset, _) in aggregated.iter() {
            assert_with_error!(
                env,
                account.supply_positions.contains_key(hub_asset.clone()),
                GenericError::NotAuthorized
            );
        }
    }
}
