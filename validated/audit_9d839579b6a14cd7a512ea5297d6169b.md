### Title
Missing Zero-Value Guard on `kip71.gastarget` Governance Parameter Enables Division-by-Zero Chain Halt — (`params/kip71_config.go`, `kaiax/gov/param.go`)

---

### Summary

The `kip71.gastarget` governance parameter accepts zero as a valid value because its `FormatChecker` is `noopFormatChecker`. Once ratified, a zero `GasTarget` causes `NextMagmaBlockBaseFee` to execute an integer division by zero (`big.Int.Div` panics on a zero divisor) on every block whose parent consumed any gas. This crashes all nodes simultaneously, halting the chain. The sibling parameter `kip71.basefeedenominator` has an explicit non-zero guard, confirming the developers are aware of the division-by-zero risk but omitted the equivalent guard for `GasTarget`.

---

### Finding Description

**Root cause — missing `FormatChecker` guard (`kaiax/gov/param.go`)**

`Kip71GasTarget` is declared with `noopFormatChecker`, which unconditionally returns `true` for any canonicalized `uint64` value, including `0`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` — which is also a divisor in the same formula — explicitly rejects zero:

```go
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // ← zero rejected
    },
``` [2](#0-1) 

**No consistency check for `Kip71GasTarget` (`kaiax/gov/headergov/impl/header.go`)**

`checkConsistency` returns `nil` for `Kip71GasTarget` without any bounds validation:

```go
case gov.GovernanceDeriveShaImpl, ..., gov.Kip71GasTarget, ...:
    return nil
``` [3](#0-2) 

**Division-by-zero crash site (`params/kip71_config.go`)**

`NextMagmaBlockBaseFee` guards `BaseFeeDenominator` against zero but has no equivalent guard for `GasTarget`:

```go
if kc.BaseFeeDenominator == 0 {          // ← guarded
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget                // ← NOT guarded
...
// parentGasUsed > gasTarget (i.e., > 0) branch:
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // panics when gasTarget == 0
``` [4](#0-3) 

`NextMagmaBlockBaseFee` is called from every critical execution path: block validation (`blockchain/block_validator.go`), the tx pool (`blockchain/tx_pool.go`), the block worker (`work/worker.go`), and the gas-price oracle (`node/cn/gasprice/gasprice.go`). A panic in any of these paths crashes the node process.

---

### Impact Explanation

Once a governance vote for `kip71.gastarget = 0` is ratified (takes effect at the next epoch boundary), every subsequent block whose parent consumed any gas triggers a `big.Int.Div`-by-zero panic in `NextMagmaBlockBaseFee`. Because this function is invoked during both block production and block verification, **all nodes crash simultaneously**. The chain halts: no new blocks can be produced or accepted, all pending transactions are stuck, and KAIA fee collection and reward distribution stop. Recovery requires an out-of-band coordinated upgrade to override the parameter.

---

### Likelihood Explanation

In Mainnet `single` governance mode, only the governing node can cast votes. The governing node is a semi-trusted entity — trusted to govern but not to break the chain. An accidental or malicious vote of `kip71.gastarget = 0` (e.g., a scripting error, a UI bug, or a compromised signing key) passes all existing validation layers (format check, consistency check) without rejection. In `none` governance mode, any council member can trigger this with a single vote that wins the epoch.

---

### Recommendation

Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`, mirroring the existing guard on `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```

Additionally, add a defensive zero-check in `NextMagmaBlockBaseFee` for `GasTarget` (analogous to the existing `BaseFeeDenominator` guard) to prevent a panic even if the parameter somehow reaches zero through other paths.

---

### Proof of Concept

1. Governing node calls `governance_vote("kip71.gastarget", 0)` via the RPC API.
2. The vote passes `NewVoteData` (format check: `noopFormatChecker` returns `true` for `uint64(0)`).
3. The vote passes `checkConsistency` (returns `nil` for `Kip71GasTarget`).
4. At the next epoch boundary, the vote is ratified and `GasTarget` is set to `0` in the effective `ParamSet`.
5. On the first block after the epoch where `parentGasUsed > 0` (virtually every block), `NextMagmaBlockBaseFee` executes:
   ```
   gasTarget := 0
   parentGasUsed > gasTarget  →  true
   y := x.Div(x, big.NewInt(0))  →  panic: division by zero
   ```
6. All nodes crash. The chain halts. [1](#0-0) [5](#0-4) [3](#0-2)
