The analog maps to pool guards: `require_backed_market` blocks `supply` while `require_utilization_below_max` blocks `withdraw`. Let me verify the bad-debt path that can create both conditions simultaneously.### Title
Bad-debt write-down clamped at the supply-index floor can lock a market: `supply` fails the backing gate while `withdraw` fails the utilization gate - (contracts/pool/src/interest.rs)

### Summary
XOXNO Lending has no vault-proportionality limits, but the same deadlock shape exists per-market through two independent guards. `require_backed_market` gates only `supply`, and `require_utilization_below_max` gates `withdraw`, `borrow`, and `claim_revenue`. `apply_bad_debt_to_supply_index` clamps a wiped-out supply index up to `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of zeroing it, which leaves residual supplier claims with no backing. In that state, and while any other debt remains in the market, the two guards fire simultaneously: new supply reverts `PoolInsolvent` and every withdrawal reverts `UtilizationAboveMax`. The market is frozen for both entry and exit until a third party donates through `recapitalize` (which mints no shares) or a borrower repays.

### Finding Description
- `require_utilization_below_max` is an absolute post-state check: `ceil(debt_value) / floor(supply_value) <= max_utilization`, applied to non-liquidation withdrawals [1](#0-0) . The pool README confirms that once utilization reaches the cap, no withdrawal of any size passes, because burning shares only lowers the denominator [2](#0-1) .
- `require_backed_market` gates only `supply`: `backing = cash + ceil(debt)` must cover `floor(supply claim)`, else `PoolInsolvent` [3](#0-2) .
- `apply_bad_debt_to_supply_index` reduces `supply_index` by `remaining/total`, then clamps the result with `.max(SUPPLY_INDEX_FLOOR_RAW)` [4](#0-3) . When `bad_debt >= total_supplied_value`, `reduction_factor` is 0 but the index is clamped up to `RAY/1000`, leaving a positive `floor(supply × index)` claim while the debt was burned by `cache.burn_debt` [5](#0-4) . The docs acknowledge this: "The non-zero floor can leave residual claims without backing. Supply then fails the backing gate until recapitalization fills the shortfall" [6](#0-5) .
- The deadlock: with the index floored, `floor(supply_value)` is a tiny positive claim. If the market still has other outstanding debt (`borrowed > 0`), utilization is `ceil(debt)/floor(supply)` which exceeds any `max_utilization < RAY`, so `withdraw` and `claim_revenue` revert `UtilizationAboveMax`, while `supply` reverts `PoolInsolvent` from the shortfall. `require_supply_for_debt` also blocks `net_settle`-style exits that would zero supply.
- `clean_bad_debt` is permissionless: `process_clean_bad_debt` only requires `caller.require_auth()`, non-flash context, open debt, `total_debt > total_collateral`, and collateral at or below the ~$5 dust cap [7](#0-6) . Debt size is uncapped on the permissionless path, so a small/dust-collateral account with large unpayable debt (post price collapse) can write the supply index down to the floor in a thin market.
- Recovery mirrors the original report's donation limitation: `recapitalize` credits at most the shortfall, refunds the excess, and mints no shares — an unfreezing donor is not compensated [8](#0-7) .

### Impact Explanation
All suppliers in the affected market are temporarily unable to withdraw (utilization gate) and no one can supply fresh capital to dilute the shortfall (backing gate). Borrows and revenue claims are also blocked. Funds remain locked until someone makes an uncompensated `recapitalize` donation covering the phantom-claim shortfall, or remaining borrowers repay enough debt to bring utilization under `max_utilization`. This is a temporary freeze of user funds reachable by a single unprivileged transaction.

### Likelihood Explanation
Requires a market with residual debt and a bad-debt cleanup large enough to clamp the supply index at `RAY/1000` — i.e., socialized debt approaching the market's total supplied value. That is realistic in thin or young markets where one dust-collateral account's debt dominates supply after a sharp collateral price drop. Medium: the freeze is temporary and permissionless recovery exists, but it costs the rescuer real funds, so rational recovery may be delayed.

### Recommendation
- Make the two gates consistent: when `require_backed_market` would block supply due to a floor-clamp residual, exempt withdrawals (or pro-rata withdrawals capped at `cash`) from `require_utilization_below_max`, so exit is never jointly disabled.
- Alternatively, zero out residual scaled supply (or burn it into revenue) when the write-down hits `SUPPLY_INDEX_FLOOR_RAW`, eliminating the unbacked claim instead of clamping the index up.
- Validate at `update_params` / market config that `max_utilization` cannot interact with the index floor to strand claims, analogous to the upstream fix that constrains limit composition.

### Proof of Concept
1. Market X has total supplied value S and outstanding debt D from honest borrowers, with `D/S` below `max_utilization`.
2. An insolvent account exists with dust collateral ≤ $5 and debt B in market X, where B approaches or exceeds S (permissionless gate `is_socializable_bad_debt` only caps collateral, not debt).
3. Attacker calls `clean_bad_debt(account_id)`. `seize::apply` burns the debt and calls `apply_bad_debt_to_supply_index`; since `B >= S`, `reduction_factor = 0` and `supply_index` clamps to `RAY/1000`, leaving `floor(supplied × floor)` > 0 while `cash + debt` no longer covers it.
4. Any `supply` → `PoolInsolvent` (backing shortfall > 0). Any `withdraw` or `claim_revenue` → `UtilizationAboveMax` (`ceil(D)/floor(small supply)` > `max_utilization`). The market is frozen for entry and exit.
5. Only an uncompensated `recapitalize` donation or voluntary borrower repayment restores operations.

pub(crate) fn require_utilization_below_max(env: &Env, cache: &Cache) {
    if cache.supplied() == Ray::ZERO || cache.params().max_utilization >= Ray::ONE {
        return;
    }

    let borrowed = cache.borrowed().mul_ceil(env, cache.borrow_index());
    if borrowed == Ray::ZERO {
        return;
    }
    let supplied = cache.supplied().mul_floor(env, cache.supply_index());
    assert_with_error!(
        env,
        supplied > Ray::ZERO && borrowed.div_ceil(env, supplied) <= cache.params().max_utilization,
        CollateralError::UtilizationAboveMax
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

enum BadDebtGate {

    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);

pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();

    RecapitalizationOutcome {
        cache,
        mutation: PoolAmountMutation {
            actual_amount: applied,
        },
        refund,
    }
}
