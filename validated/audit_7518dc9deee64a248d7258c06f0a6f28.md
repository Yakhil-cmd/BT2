### Title
`payout_stakers_alive_staked` marks era/page as claimed before transferring funds, permanently losing rewards if the DAP-based staker reward pot is underfunded — ([File: substrate/frame/staking-async/src/pallet/impls.rs])

### Summary
Same bug class as Ajna's H-08: reward accounting is finalized ("claimed") *before* the actual token transfer is attempted, and the transfer is allowed to silently fail/be skipped for a given nominator without any mechanism to retry or re-claim later. In `pallet-staking-async`'s DAP (transfer-based, non-minting) reward path, `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` is written to storage unconditionally before `payout_from_provider` runs, and `make_payout_from_provider` treats a failed `T::Currency::transfer` as a no-op (logs an error, emits no event, returns `None`) rather than reverting the dispatch. Because the claimed-flag is already set, a subsequent call for the same `(era, stash, page)` returns `Error::<T>::AlreadyClaimed`, so the skipped reward can never be recovered.

### Finding Description
`payout_stakers_alive_staked` (dispatched via the permissionless, anyone-can-call `payout_stakers`/`payout_stakers_alive_staked` extrinsics) performs, in order:

1. Checks `Eras::<T>::is_rewards_claimed(era, &stash, page)` and errors with `AlreadyClaimed` if already set.
2. **Immediately marks the page as claimed**: `Eras::<T>::set_rewards_as_claimed(era, &stash, page);` [1](#0-0) 
3. Computes `validator_staker_payout_for_page` and `reward_split.nominator_payout` from era reward points and exposure — a pure calculation independent of actual pot balance.
4. Calls `Self::payout_from_provider(...)` (when `use_dap_payout` is true, i.e., the non-minting/transfer-based DAP path is active) [2](#0-1) .

`payout_from_provider` calls `make_payout_from_provider` for the validator and for each nominator in the exposure page [3](#0-2) . `make_payout_from_provider` performs `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)`. If this transfer errors (e.g., the era's `staker_rewards_pot` account does not hold enough funds), the function only logs an error and **returns `None`** — no event is emitted, no error is propagated, and the extrinsic still completes successfully: [4](#0-3) 

Because step 2 already persisted the claimed flag for `(era, stash, page)` regardless of the outcome of step 4, and there is no `UnpaidRewards`-style deferred-claim ledger analogous to the one recently added to `pallet-election-provider-multi-block`'s signed pallet (`UnpaidRewards`/`claim_unpaid_reward`, see [5](#0-4) ), any nominator or validator whose transfer failed due to pot underfunding has no path to claim the owed amount later — a repeat call to `payout_stakers_alive_staked(era, stash, page)` immediately hits `AlreadyClaimed`.

The era staker-reward pot (`RewardPot::Era(era, RewardKind::StakerRewards)`) is funded once via `snapshot_era_rewards`, which transfers whatever balance currently sits in the *general* staker pot at era-rotation time into the era-specific pot, using `Preservation::Preserve` and `Fortitude::Polite` reducible balance [6](#0-5) . This snapshot amount is not cross-checked against the sum of validator+nominator entitlements computed later from era reward points and exposures — the two figures are derived independently (DAP emission accounting vs. reward-points/exposure accounting). Any rounding drift, double-counting, delayed inflation top-up, or a validator/nominator claiming pages out of order relative to when the pot was topped up can leave the pot short by the time a later page/stash payout is attempted, exactly mirroring the Ajna scenario where `ajnaBalance < rewardsEarned_`.

### Impact Explanation
A staker (validator or nominator) permanently loses their earned era reward whenever the transfer-based DAP payout path is active and the era's staker-reward pot balance is insufficient at the moment their specific `(era, stash, page)` payout is processed. Because `set_rewards_as_claimed` fires unconditionally and there is no fallback ledger, this is an irreversible loss of user funds under a plausible, non-privileged condition (pot underfunding via legitimate emission/rounding drift, not attacker-controlled state manipulation). This matches the High severity classification given to the analogous Ajna finding, since it is a direct, unrecoverable loss of legitimately earned rewards for ordinary users with no special privileges.

### Likelihood Explanation
Likelihood depends on operational conditions of the DAP-based non-minting payout path (`DisableMintingGuard` active, i.e. `use_dap_payout == true`) actually going live and on the era pot's funding being tight relative to aggregate entitlements. I could not fully verify from the indexed files (i) whether `snapshot_era_rewards`'s funding amount is guaranteed by protocol invariant to always cover the full sum of `validator_staker_payout_for_page` + all nominators' payouts for every page of every stash in that era, or (ii) whether there is a defensive check elsewhere (e.g. in `Eras`/`session_rotation.rs`) enforcing that the pot is topped up to exactly match total reward-point-derived entitlements before payouts are permitted. This uncertainty limits confidence to Medium-High rather than a confirmed exploit; a concrete PoC would need to construct an era where the general staker pot balance at snapshot time is deliberately smaller than the sum of computed per-stash/per-page payouts (e.g., via commission/exposure edge cases or multiple eras draining the same rotating pot slot before all pages are claimed).

### Recommendation
- Do not call `Eras::<T>::set_rewards_as_claimed` until the transfer(s) in `payout_from_provider` have been confirmed to fully succeed, or
- Track any shortfall explicitly (mirroring the `UnpaidRewards`/`claim_unpaid_reward` pattern already implemented in `pallet-election-provider-multi-block`) so a failed/partial payout can be permissionlessly claimed later once the pot is refilled, instead of being dropped and marked claimed.
- Alternatively, make `make_payout_from_provider`'s transfer failure propagate as a hard error from `payout_stakers_alive_staked` (reverting the whole dispatch, including the claimed-flag write) rather than being swallowed as a logged no-op.
- Add an invariant check (e.g. in `try-runtime`/integration tests) that `snapshot_era_rewards`'s funded amount is always `>=` the sum of all computed staker/nominator entitlements for that era before any page can be marked claimed.

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

	/// Transfer `amount` from [`Config::RewardSource`] pot to `to`, or mint if `None`.
	fn transfer_or_mint(to: &T::AccountId, amount: BalanceOf<T>) -> Result<(), ()> {
		if let Some(source) = T::RewardSource::account() {
			T::Currency::transfer(&source, to, amount, Preservation::Preserve).map_err(|_| ())?;
			T::RewardSource::paid(amount);
		} else {
			let _r = T::Currency::mint_into(to, amount);
			debug_assert!(_r.is_ok());
		}
		Ok(())
	}

	/// Pay the round's winner. On success emits `Rewarded`. On failure, always defers into
	/// [`UnpaidRewards`] (`RewardPaymentDeferred`), evicting the oldest entry first
	/// (`UnpaidRewardEvicted`) if it's already full.
	fn pay_reward(round: u32, to: &T::AccountId, amount: BalanceOf<T>) {
		if Self::transfer_or_mint(to, amount).is_ok() {
			Self::deposit_event(Event::<T>::Rewarded(round, to.clone(), amount));
			return;
		}

		sublog!(
			warn,
			"signed",
			"reward pot insufficient; deferring {:?} to {:?} for round {}",
			amount,
			to,
			round
		);
		let entry = UnpaidReward { round, who: to.clone(), amount };
		UnpaidRewards::<T>::mutate(|unpaid| {
			if unpaid.is_full() {
				// Entries are pushed in round order, so index 0 is the oldest.
				let evicted = unpaid.remove(0);
				Self::deposit_event(Event::<T>::UnpaidRewardEvicted(
					evicted.round,
					evicted.who,
					evicted.amount,
				));
			}
			let _ = unpaid.try_push(entry).defensive_proof("an element was just evicted; qed");
		});
		Self::deposit_event(Event::<T>::RewardPaymentDeferred(round, to.clone(), amount));
	}

	pub(crate) fn snapshot_era_rewards(era: EraIndex) -> EraRewardAllocation<BalanceOf<T>> {
		let staker_era_pot = Self::create(era, RewardKind::StakerRewards);
		let incentive_era_pot = Self::create(era, RewardKind::ValidatorSelfStake);

		let general_staker_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::StakerRewards));
		let general_incentive_pot =
			T::RewardPots::pot_account(RewardPot::General(RewardKind::ValidatorSelfStake));

		// Leave ED in the general pots to keep them alive.
		let staker_balance = T::Currency::reducible_balance(
			&general_staker_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);
		let incentive_balance = T::Currency::reducible_balance(
			&general_incentive_pot,
			Preservation::Preserve,
			Fortitude::Polite,
		);

		let actual_staker = if !staker_balance.is_zero() {
			match T::Currency::transfer(
				&general_staker_pot,
				&staker_era_pot,
				staker_balance,
				Preservation::Preserve,
			) {
				Ok(_) => staker_balance,
				Err(e) => {
					log!(error, "Era {:?}: staker reward transfer failed: {:?}", era, e);
					defensive!("Failed to transfer staker rewards to era pot");
					Zero::zero()
				},
			}
		} else {
			Zero::zero()
