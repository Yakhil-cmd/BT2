### Title
Duplicate `CLPoolAddr` in `assignStakingRewards` / `assignStakingRewardsFlex` Causes Permanent KAIA Staking-Reward Loss via Map Overwrite — (`File: kaiax/reward/impl/getter.go`)

---

### Summary

`assignStakingRewards` and `assignStakingRewardsFlex` build a reward-allocation map using plain assignment (`alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount`). If two consolidated validators share the same `CLPoolAddr`, the second assignment silently overwrites the first. The `remaining` counter is decremented for both validators, so the overwritten amount is neither credited to the pool address nor returned to the proposer — it is permanently lost from the distributed staking reward.

---

### Finding Description

In `getDeferredRewardFullKore` and `getDeferredRewardFullFlex`, staking rewards are distributed by calling `assignStakingRewards` / `assignStakingRewardsFlex`. Both functions iterate over `ConsolidatedNodes()` and, for each node that has a `CLStakingInfo` (post-Prague), split the reward between the CN reward address and the CL pool address:

```go
// assignStakingRewards  (lines 521-525)
cnAmount, clAmount := cn.Split(reward)
alloc[cn.RewardAddr] = cnAmount                    // plain assignment
alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount      // plain assignment
```

```go
// assignStakingRewardsFlex  (lines 475-477)
cnAmount, clAmount := cn.Split(reward)
alloc[cn.RewardAddr] = cnAmount
alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
```

`ConsolidatedNodes()` guarantees uniqueness of `RewardAddr` across entries, so the CN-side assignment is safe. However, **no uniqueness constraint is enforced on `CLPoolAddr`**. The comment in `consolidateNodes` only states "One CLStakingInfo per validator is guaranteed by CLRegistry" — one CL entry per validator node, not one unique pool address across all validators.

If two validators (with distinct `RewardAddr` values) register the same `CLPoolAddr`, the second iteration overwrites `alloc[sharedPool]` with the second validator's `clAmount`, discarding the first validator's `clAmount`. Meanwhile, `remaining.Sub(remaining, reward)` is executed for both validators, so the first validator's full reward (CN + CL) is subtracted from `remaining`. The lost `clAmountA` is neither in `alloc` nor in `remaining`. [1](#0-0) [2](#0-1) 

---

### Impact Explanation

`FinalizeState` iterates `spec.Rewards` and calls `state.AddBalance(addr, amount)` for each entry. [3](#0-2) 

Because the overwritten `clAmountA` never appears in `spec.Rewards`, it is never credited to any account. The invariant `sum(alloc) + remaining == stakersReward` is broken: `sum(alloc) + remaining == stakersReward - clAmountA`. The missing KAIA is permanently destroyed — it is minted (counted in `spec.Minted`) but never added to any balance, violating the total-supply accounting.

---

### Likelihood Explanation

**Low.** Requires two validators to register the same `CLPoolAddr` in the CLRegistry. This can occur accidentally (two operators deploying the same pool contract bytecode at the same address on a private/test chain) or deliberately (a malicious validator registering a pool address already used by another validator). The CLRegistry enforces "one CLStakingInfo per validator nodeId" but does not enforce uniqueness of `CLPoolAddr` across validators. [4](#0-3) 

---

### Recommendation

Replace the plain map assignment for `CLPoolAddr` with an accumulating pattern, consistent with how `IncRecipient` works in `RewardSpec`:

```go
// Instead of:
alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount

// Use:
if existing, ok := alloc[cn.CLStakingInfo.CLPoolAddr]; ok {
    existing.Add(existing, clAmount)
} else {
    alloc[cn.CLStakingInfo.CLPoolAddr] = new(big.Int).Set(clAmount)
}
```

Apply the same fix to both `assignStakingRewards` and `assignStakingRewardsFlex`. Additionally, consider enforcing `CLPoolAddr` uniqueness at the CLRegistry level.

---

### Proof of Concept

**Setup (post-Prague, Kore rule):**

```
StakingInfo:
  NodeIds:          [N1, N2]
  RewardAddrs:      [R1, R2]
  StakingAmounts:   [10_000_000, 10_000_000]  // both above minStake
  CLStakingInfos:
    {CLNodeId: N1, CLPoolAddr: P_SHARED, CLStakingAmount: 5_000_000}
    {CLNodeId: N2, CLPoolAddr: P_SHARED, CLStakingAmount: 5_000_000}  // same pool!

MinimumStake = 5_000_000
stakersReward = 1e18 kei
```

**Execution of `assignStakingRewards`:**

1. First loop builds `cnTotalStakingMap`:
   - `R1 → 15_000_000` (10M CN + 5M CL)
   - `R2 → 15_000_000`
   - `totalExcessInt = (15M-5M) + (15M-5M) = 20_000_000`

2. Second loop:
   - CN1: `reward = 10M/20M * 1e18 = 5e17`. `Split` → `cnAmount1 = 333...e15`, `clAmount1 = 166...e15`. `alloc[R1] = cnAmount1`, `alloc[P_SHARED] = clAmount1`. `remaining -= 5e17`.
   - CN2: `reward = 5e17`. `Split` → `cnAmount2 = 333...e15`, `clAmount2 = 166...e15`. `alloc[R2] = cnAmount2`, **`alloc[P_SHARED] = clAmount2`** ← overwrites! `remaining -= 5e17`.

3. Result: `remaining = 0`, but `sum(alloc) = cnAmount1 + cnAmount2 + clAmount2 = 5e17 + clAmount2 < 1e18`. `clAmount1 ≈ 1.67e17` kei is permanently lost. [5](#0-4) [6](#0-5)

func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}

func (si *StakingInfo) consolidateNodes() *[]consolidatedNode {
	// because Go map is not ordered, rList keeps track of the occurrence order of RewardAddrs.
	// to later arrange the consolidatedNodes.
	cmap := make(map[common.Address]*consolidatedNode)
	rList := make([]common.Address, 0, len(si.RewardAddrs))
	nToR := make(map[common.Address]common.Address)

	for i, n := range si.NodeIds {
		r := si.RewardAddrs[i]
		// Unique nodeId is guaranteed by AddressBook.
		nToR[n] = r
		if cn, ok := cmap[r]; ok {
			cn.NodeIds = append(cn.NodeIds, n)
			cn.StakingContracts = append(cn.StakingContracts, si.StakingContracts[i])
			cn.StakingAmount += si.StakingAmounts[i]
		} else {
			cmap[r] = &consolidatedNode{
				NodeIds:          []common.Address{n},
				StakingContracts: []common.Address{si.StakingContracts[i]},
				RewardAddr:       r,
				StakingAmount:    si.StakingAmounts[i],
			}
			rList = append(rList, r)
		}
	}

	// CLStakingInfo can only exist after Prague HF.
	if len(si.CLStakingInfos) > 0 {
		for _, clsi := range si.CLStakingInfos {
			// If the nodeId of CLStakingInfo is not found in nToR, it means the validator is not in the AddressBook.
			// So we skip it.
			if r, ok := nToR[clsi.CLNodeId]; ok {
				// One CLStakingInfo per validator is guaranteed by CLRegistry.
				cmap[r].CLStakingInfo = clsi
			}
		}
	}

	carr := make([]consolidatedNode, 0, len(cmap))
	for _, r := range rList {
		carr = append(carr, *cmap[r])
	}
	return &carr
}
