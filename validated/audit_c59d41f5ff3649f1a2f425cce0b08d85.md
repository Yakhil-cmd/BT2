### Title
No-secret-organization webhook bypass allows cross-repository forged `pull_request`/`unassigned` events to mutate another stack's `PullRequest` record - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used to authenticate a webhook by `repository.owner.login` (or `organization.login`), while every handler — including `AssignedHandler` — resolves the target `Repository`/`Stack` from the independent `repository.full_name` field. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected organization's config has no `webhook_secret`. An attacker can therefore pick an org with a blank `webhook_secret` for `repository.owner.login` to pass signature verification for free, while pointing `repository.full_name` at a completely different, unrelated (and properly secret-protected) stack's repository, causing the handler to mutate that victim's persisted `PullRequest` record.

### Finding Description
The broken binding is: **the org that authenticated the signature check == the org whose repository/stack is mutated by the handler**. In this codebase these are two different reads of the payload that are never cross-checked.

- `verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` returns `true` immediately when the resolved org's config has no `webhook_secret`, i.e. `return true unless webhook_secret` [3](#0-2) . This is a real, documented configuration mode (multi-org setup, each org's `webhook_secret` optional) [4](#0-3) .
- Once the request passes this gate, `WebhooksController#create` dispatches the *entire raw payload* to handlers registered for the event type, with no re-binding to the authenticating org: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [5](#0-4) .
- `AssignedHandler#pull_request` resolves the target record using `params.repository.full_name` — a completely different field than the one used for authentication — via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` and then joins to `stacks: :repository` filtered by that repository's id [6](#0-5) .
- `AssignedHandler#process` then calls `pull_request.update(github_pull_request: params.pull_request)` for any matched record [7](#0-6) , and `PullRequest#github_pull_request=` overwrites `github_id`, `number`, `api_url`, `title`, `state`, `additions`, `deletions`, `user`, `assignees`, `labels`, and resolves/creates a `head` `Commit` by fetching `stack.github_api.commit(stack.github_repo_name, sha)` for the attacker-chosen `head.sha` [8](#0-7) .

**Exploit flow**: The attacker crafts a JSON body with `repository.owner.login = "OrgTwo"` (a configured org with no `webhook_secret`) so `verify_signature` passes unconditionally, but sets `repository.full_name = "victim-org/victim-repo"` (a different, properly-secured org/stack) and `action = "unassigned"`, `number = <existing PR number on the victim stack>`, and an arbitrary `pull_request.head.sha`/`assignees`/`labels`. `check_if_ping` and `drop_unhandled_event` do not block `pull_request` events; `verify_signature` accepts the forged body because it only inspects `repository.owner.login`; `AssignedHandler` then looks up and updates the victim's real `PullRequest` record because it only inspects `repository.full_name`.

**Why existing guards fail**: There is no code anywhere that asserts `params.repository.owner.login` and the owner implied by `params.repository.full_name` are the same value. The `ExplicitParameters` schema on `AssignedHandler` only validates types/presence of fields, not cross-consistency with the field used for authentication [9](#0-8) . `GithubOrganizationUnknown` only guards against an org name that isn't configured at all, not against an org whose config exists but has no secret [10](#0-9) .

### Impact Explanation
This lets a payload authenticated under one (no-secret) organization mutate the persisted `PullRequest` state of a stack belonging to an entirely different, secured organization/repository — a "payload for one repository mutating another's stack/commit" scenario. Concretely, an attacker can: overwrite title/state/labels/assignees of a real PR record on the victim stack, and force-create a `Commit` row in the victim stack's `commits` table for an arbitrary (but real, existing-on-GitHub) `sha` via `find_or_create_commit_from_github_by_sha!`. Because the target stack has `continuous_deployment` enabled, if that commit later carries (or already carries) a passing status/check on GitHub, `Commit#schedule_continuous_delivery` / `ContinuousDeliveryJob` can pick it up as `next_commit_to_deploy` and trigger an unauthorized deploy through the normal continuous-delivery pipeline (`app/jobs/shipit/continuous_delivery_job.rb`, `Stack#trigger_continuous_delivery`) [11](#0-10) [12](#0-11) . This is repeatable against any stack whose repository owner has published `full_name`, as long as any org in the Shipit config lacks a `webhook_secret` and a matching `PullRequest` row already exists for that stack/number. This matches the "unauthorized deploy" / "payload for one repository mutating another's stack" Critical category, though the deploy trigger depends on an externally-controlled precondition (the target commit already having a passing CI status on GitHub), which the attacker cannot guarantee outright.

### Likelihood Explanation
Preconditions: (1) Shipit must be configured with multiple GitHub organizations, at least one with a blank `webhook_secret` (an explicitly supported and documented configuration per `docs/setup.md`); (2) the victim stack must have an existing `PullRequest` record for the targeted `number` (created by a prior legitimate `opened`/`synchronize` event) and `continuous_deployment` enabled. Given these, the attacker's cost is a single unauthenticated `POST /webhooks` request with a crafted JSON body — no secrets, sessions, or GitHub write access required. The finding is fully reproducible without live GitHub for the "record mutated" portion (the `github_id`/`title`/`state`/`labels`/`assignees` overwrite), which requires no outbound GitHub API call; only the `head.sha` commit-creation path requires either an existing local `Commit` with that sha or a stubbed `github_api.commit` call in tests.

### Recommendation
Bind webhook authentication to the same repository identity used by handlers: derive the verifying `GitHubApp`/org from `params.repository.full_name`'s owner (or verify that `repository.owner.login` matches the owner segment of `repository.full_name`) before dispatching to handlers. Additionally, do not allow `verify_webhook_signature` to silently return `true` for organizations with a blank `webhook_secret` in production — require an explicit `webhook_secret` for every configured organization, or reject requests to any org lacking one.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb` (or an equivalent minitest under `test/`):

```ruby
test "pull_request/unassigned webhook authenticated via a no-secret org can mutate another stack's PullRequest" do
  # Setup: victim stack belongs to "shopify/shipit-engine" (owner has a webhook_secret configured)
  victim_stack = shipit_stacks(:shipit)
  victim_repo_full_name = victim_stack.repository.github_repo_name # e.g. "shopify/shipit-engine"
  pr = victim_stack.pull_requests.create!(number: 999, user: shipit_users(:walrus), head: shipit_commits(:first))

  # "OrgTwo" is configured with webhook_secret: nil (no-secret org) per test/dummy/config/secrets_double_github_app.yml
  payload = {
    action: "unassigned",
    number: pr.number,
    pull_request: {
      id: 1, number: pr.number, url: "http://example.com", title: "forged",
      state: "open", additions: 1, deletions: 1,
      head: { sha: shipit_commits(:second).sha, ref: "master" },
      user: { login: "attacker" },
      assignees: [],
      labels: []
    },
    repository: { owner: { login: "OrgTwo" }, full_name: victim_repo_full_name },
    sender: { login: "attacker" }
  }.to_json

  # No X-Hub-Signature needed: OrgTwo has no webhook_secret, so verify_webhook_signature returns true unconditionally.
  post shipit.hooks_path, params: payload, headers: { 'X-Github-Event' => 'pull_request', 'CONTENT_TYPE' => 'application/json' }

  assert_response :ok
  pr.reload
  # Binding under test: repository.owner.login (authenticator) == owner(repository.full_name) (mutated stack owner)
  # Before: "OrgTwo" != owner_of(victim_repo_full_name)
  # After the request, the victim's PullRequest record was mutated anyway — the equality was never enforced.
  assert_equal "forged", pr.title
  assert_equal shipit_commits(:second), pr.head
end
```

This test demonstrates that a payload "authenticated" solely by the no-secret `OrgTwo` config is accepted and dispatched to `AssignedHandler`, which mutates a `PullRequest` record belonging to a stack/repository under a different, secured owner — confirming the cross-tenant write.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def github_pull_request=(github_pull_request)
      self.github_id = github_pull_request.id
      self.number = github_pull_request.number
      self.api_url = github_pull_request.url
      self.title = github_pull_request.title
      self.state = github_pull_request.state
      self.additions = github_pull_request.additions
      self.deletions = github_pull_request.deletions
      self.user = User.find_or_create_by_login!(github_pull_request.user.login)
      self.assignees = github_pull_request.assignees.map do |github_user|
        User.find_or_create_by_login!(github_user.login)
      end
      self.labels = github_pull_request.labels.map(&:name)
      self.head = find_or_create_commit_from_github_by_sha!(github_pull_request.head.sha)
    end

    def find_or_create_commit_from_github_by_sha!(sha)
      if commit = stack.commits.by_sha(sha)
        commit
      else
        github_commit = stack.github_api.commit(stack.github_repo_name, sha)
        stack.commits.create_from_github!(github_commit)
      end
    rescue ActiveRecord::RecordNotUnique
      retry
    end
