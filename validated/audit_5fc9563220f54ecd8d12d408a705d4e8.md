### Title
Unchecked return value of `os.RemoveAll` during worktree cleanup masks stale-data deletion failures - (File: main.go)

### Summary
The external report flags an "unchecked returned value" bug class: functions that can fail (`transfer`/`transferFrom` in the Solidity analog) are called without checking their success, silently swallowing failures. The closest reachable analog in `git-sync` is in `repoSync.SyncRepo`, where the error returned by `os.RemoveAll` when cleaning up a stale worktree directory is discarded outright.

### Finding Description
In `SyncRepo`, after a successful publish, git-sync attempts to remove an old worktree directory left over from a prior version/hash mismatch: [1](#0-0) 

Unlike every other filesystem operation in this same function and file (e.g. `publishSymlink`, `removeWorktree`, which check and wrap errors from `os.Symlink`, `os.Rename`, `os.RemoveAll`): [2](#0-1) [3](#0-2) 

this particular `os.RemoveAll(currentWorktree.Path().String())` call at line 1992 ignores the returned `error` completely — no logging, no error propagation, nothing. If the removal fails (permission issue, disk pressure, a file busy/locked, or a symlink/directory structure crafted via a malicious ref that resists `RemoveAll`), the failure is invisible to operators and to the sync loop's health/metrics.

### Impact Explanation
Because failures here are silent:
- Stale worktree directories accumulate under `--root` indefinitely across sync cycles, consuming disk space without any diagnostic signal, since the normal periodic cleanup path (`removeDirContentsIf`) is a separate code path that this special-case call bypasses.
- Operators have no way to detect via logs or metrics that this cleanup step is repeatedly failing, which can eventually degrade or crash the container via disk exhaustion — a persistent-sync-denial style failure mode that manifests over time rather than immediately.
- This is a data-hygiene/observability defect rather than one that permits code execution, credential leakage, or writes outside `--root` — it is confined to already-owned worktree paths inside `--root`.

### Likelihood Explanation
This is a normal (non-privileged) code path exercised on every hash change where the current worktree does not match the expected path for the current hash (e.g., after an in-place upgrade from an older git-sync version, or when the remote ref history is rewritten so that `git.worktreeFor(currentHash)` diverges from the actual current worktree). No attacker-controlled flags or credentials are required, and it does not depend on malicious-operator or leaked-key assumptions — a repo owner who force-pushes/rewrites history controls how frequently this divergence occurs, since `currentHash` and `worktreeFor` comparisons are driven by fetched commit hashes.

### Recommendation
Check and log (and ideally propagate or count via a metric) the error from `os.RemoveAll` at main.go:1992, consistent with how `removeWorktree` handles the same operation:
```go
if err := os.RemoveAll(currentWorktree.Path().String()); err != nil {
    git.log.Error(err, "can't remove stale worktree", "path", currentWorktree.Path())
}
```
This restores parity with the error handling pattern used elsewhere in the file and gives operators visibility into disk-cleanup failures before they become a persistent denial-of-sync condition.

### Proof of Concept
1. Deploy git-sync pointed at a repo, let it sync hash `A` into worktree path derived from `A`.
2. Simulate the "in-place upgrade" divergence condition by making `currentWorktree` differ from `git.worktreeFor(currentHash)` for the same hash (e.g., pre-populate `--root` with a worktree directory laid out per the older git-sync path convention, as covered by existing tests for this migration case) and make that directory's removal fail (e.g., mount a read-only bind mount over a file inside it, or hold a file handle open on a platform where that blocks unlink).
3. Observe that `SyncRepo` returns success (`changed, remoteHash, nil`) and logs "updated successfully" with no error or warning about the failed `os.RemoveAll`, even though the stale directory remains under `--root` indefinitely on every subsequent sync iteration.

// publishSymlink atomically sets link to point at the specified target.  If the
// link existed, this returns the previous target.
func (git *repoSync) publishSymlink(worktree worktree) error {
	targetPath := worktree.Path()
	linkDir, linkFile := git.link.Split()

	// Make sure the link directory exists.
	if err := os.MkdirAll(linkDir.String(), defaultDirMode); err != nil {
		return fmt.Errorf("error making symlink dir: %w", err)
	}

	// linkDir is absolute, so we need to change it to a relative path.  This is
	// so it can be volume-mounted at another path and the symlink still works.
	targetRelative, err := filepath.Rel(linkDir.String(), targetPath.String())
	if err != nil {
		return fmt.Errorf("error converting to relative path: %w", err)
	}

	const tmplink = "tmp-link"
	git.log.V(2).Info("creating tmp symlink", "dir", linkDir, "link", tmplink, "target", targetRelative)
	if err := os.Symlink(targetRelative, filepath.Join(linkDir.String(), tmplink)); err != nil {
		return fmt.Errorf("error creating symlink: %w", err)
	}

	git.log.V(2).Info("renaming symlink", "root", linkDir, "oldName", tmplink, "newName", linkFile)
	if err := os.Rename(filepath.Join(linkDir.String(), tmplink), git.link.String()); err != nil {
		return fmt.Errorf("error replacing symlink: %w", err)
	}

	return nil
}

// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}
