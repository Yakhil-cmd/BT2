### Title
Open redirect in `GithubAuthenticationController#callback` via `request.env['omniauth.origin']` - ([File: app/controllers/shipit/github_authentication_controller.rb])

### Summary
`GithubAuthenticationController#callback` reads the OmniAuth-provided origin URL and redirects the user's browser there without validating it belongs to the Shipit host. Since `origin` is attacker-controllable via `github_authentication_path(origin: ...)` / the `omniauth-github` callback flow, this enables an open redirect immediately after a genuine GitHub OAuth login and session establishment.

### Finding Description
The broken binding: the code assumes `request.env['omniauth.origin'] == a URL scoped to the Shipit host`, but no such constraint is enforced anywhere in the path.

Code path: [1](#0-0)  shows `callback` setting `return_url = request.env['omniauth.origin'] || root_path`, establishing `session[:user_id]` and `session[:authenticated] = true`, then calling `redirect_to(return_url)` with no validation of `return_url`'s host or scheme.

The `origin` param is legitimately used internally by `force_github_authentication` to redirect back to `request.original_url` after login: [2](#0-1) . This confirms `origin` is a normal, externally-reachable query parameter on the auth entry route (`github_authentication_path(origin: ...)`), which OmniAuth's `omniauth-github` strategy stores as `request.env['omniauth.origin']` and forwards unchanged to the callback. Nothing in `Authentication` or `GithubAuthenticationController` validates that `origin` is a same-host, relative, or otherwise safe URL before it's echoed back in the redirect.

Attack flow: attacker sends an operator a link like `/github/auth/github?origin=https://attacker.example`. The operator, who may already trust the Shipit domain, completes real GitHub OAuth. Shipit sets `session[:authenticated] = true` and `session[:user_id]`, then redirects the operator's now-authenticated browser to `https://attacker.example`. The existing test suite only asserts the happy-path login without an origin parameter and does not check redirect target validation: [3](#0-2) .

No existing guard (`force_github_authentication`, `User#authorized?`, session checks, etc.) constrains the `return_url` value used in `redirect_to`.

### Impact Explanation
This matches the High severity category "session fixation / forced OAuth completion": the attacker forces a real OAuth completion against Shipit and then redirects the freshly authenticated session away from the Shipit origin to an attacker-controlled page, which is a strong phishing continuation vector (e.g., presenting a fake "re-enter your GitHub token" page while `session[:authenticated]` is already true, making the fake page appear as a legitimate post-login step). No Shipit or GitHub secret is directly exfiltrated by this bug alone (it does not itself leak `github_access_token` or `api_clients_secret`), so it should not be scored Critical; it is a High-severity forced-redirect/open-redirect issue tied to the authentication flow, repeatable against any operator who clicks a crafted link, and not scoped to a particular repository/stack (affects the engine's auth entry point globally).

### Likelihood Explanation
Preconditions are minimal: default engine mount, no allow-list on `origin`, and any internet user can craft the link; the only requirement is getting an operator to click the URL, which is a normal phishing distribution cost, not a privileged capability. It is fully repeatable — one crafted URL per victim, no rate limits or secrets needed.

### Recommendation
Validate `return_url` before redirecting: only allow relative paths (e.g., via `url_for` matching `root_path` scheme) or restrict it to paths matching `Shipit::Engine.routes` recognized paths, e.g.:
```ruby
return_url = request.env['omniauth.origin']
return_url = root_path unless return_url.present? && return_url.start_with?('/') && !return_url.start_with?('//')
```
or better, use Rails' `url_for(only_path: true)` checks / an explicit allow-list of hosts, rejecting any absolute URL whose host differs from `request.host`.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback redirects only to safe same-host paths, not attacker-controlled URLs" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(raw_info: OmniAuth::AuthHash.new(
      id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
      login: 'shipit-user', avatar_url: 'https://example.com',
      api_url: 'https://github.com/api/v3/users/shipit-user'
    ))
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://attacker.example'

  get :callback

  assert session[:authenticated], "session should be authenticated"
  refute_redirected_to 'https://attacker.example',
    "callback must not redirect to an external, attacker-controlled origin"
end
```
This demonstrates that after the fix, `return_url` (left side of the binding) is constrained to Shipit-hosted paths, matching the assumed right side (`a URL under the Shipit host`), whereas the current code fails this assertion.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
