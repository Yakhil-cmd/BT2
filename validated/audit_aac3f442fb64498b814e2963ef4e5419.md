**Rationale:** Prototype pollution (CVE-2020-28273 in `set-in`) is a JavaScript-specific bug class where an attacker-controlled key path (e.g. `__proto__`, `constructor.prototype`) is used to write into an object's prototype chain, corrupting behavior across the whole runtime. This bug class has no structural analog in Rust/FRAME:

- The closest structural match in this codebase is `json_patch::merge` in [1](#0-0)  and its duplicate in the Penpal genesis test helper [2](#0-1) , both of which recursively merge `serde_json::Value::Object` maps.
- `serde_json::Value::Object` is backed by a plain `Map`/`BTreeMap`, not a JS-style object with a prototype chain. There is no `__proto__`, `constructor`, or `prototype` special-cased key that traverses upward to a shared prototype object — every key is just a flat map entry. Reaching into "unexpected" keys in Rust cannot escalate into cross-object or cross-instance corruption the way JS prototype pollution does.
- Even setting bug-class analogy aside, none of these `merge`/`json_eval_value_at_key` call sites are reachable through a real permissionless user entry point (signed extrinsic, contract call, or XCM message). They are exercised only by node-side/offline tooling: the `chain-spec-builder` CLI (`substrate/bin/utils/chain-spec-builder/src/lib.rs`) [3](#0-2) , and genesis-preset construction during node/chain-spec building via `update_code_in_json_chain_spec` [4](#0-3) . These run before chain launch or as local operator tooling, not from untrusted network input during consensus/dispatch.
- `retain_initialized_fields` in `substrate/frame/support/src/generate_genesis_config.rs` [5](#0-4)  is also genesis-config/macro-generated tooling, not a live extrinsic path.

Since the bug class fundamentally requires a prototype chain that does not exist in Rust's `serde_json::Value`/`Map` representation, and the only structurally similar merge logic in this codebase is confined to offline chain-spec/genesis tooling rather than a signed-extrinsic, contract, or XCM entry point, there is no demonstrable Polkadot SDK analog satisfying the required attacker model.

pub fn update_code_in_json_chain_spec(chain_spec: &mut json::Value, code: &[u8]) -> bool {
	let mut path = json_path!["genesis", "runtimeGenesis", "code"];
	let mut raw_path = json_path!["genesis", "raw", "top"];

	if json_contains_path(&chain_spec, &mut path) {
		#[derive(Serialize)]
		struct Container<'a> {
			#[serde(with = "sp_core::bytes")]
			code: &'a [u8],
		}
		let code_patch = json::json!({"genesis":{"runtimeGenesis": Container { code }}});
		crate::json_patch::merge(chain_spec, code_patch);
		true
	} else if json_contains_path(&chain_spec, &mut raw_path) {
		#[derive(Serialize)]

		crate::json_patch::merge(chain_spec, code_patch);
