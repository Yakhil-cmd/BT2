### Title
Stack-scoped `ApiClient` tokens can read CI status of any stack via `CCMenuController` - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::BaseController` enforces that a stack-scoped `ApiClient` (one created with a `stack_id`) can only see the stack it was authorized for, by routing all stack lookups through the `stacks` scope. `Shipit::Api::CCMenuController` overrides `#stack` and bypasses that scope entirely, looking the stack up directly from the global `Stack` relation using only the attacker-supplied `params[:stack_id]`. This breaks the binding "the stack a token authorizes" == "the stack the token touches," the same class of bug as the external report (a value that is supposed to be constrained/derived from a trusted binding is instead taken unchecked from attacker input, causing scope leakage).

### Finding Description
`BaseController` defines the authorization boundary for stack access: [1](#0-0) 

`stacks` restricts the visible set of stacks to `current_api_client.stack_id` when the client is scoped, and `stack` (used by every other API controller, e.g. `require_permission :read, :stack` checks) is derived from that restricted relation.

`CCMenuController`, however, redefines `#stack` to bypass `stacks` and query `Stack` directly: [2](#0-1) 

`require_permission :read, :stack` only calls `ApiClient#check_permissions!`, which checks that the string `"read:stack"` is present in the token's `permissions` array — it never checks `current_api_client.stack_id`: [3](#0-2) 

So an `ApiClient` record created with a `stack_id` (a token meant to authorize CCMenu/CI status reads for exactly one stack, as seen in the fixture `here_come_the_walrus` which is `stack: shipit, permissions: [read:stack]`) is authenticated purely on the `permissions` array, while the actual stack object acted upon is taken unchecked from the request's `params[:stack_id]`. [4](#0-3) 

### Impact Explanation
This is an authorization-scope escape: possession of a token that the operator intentionally restricted to a single stack (`ApiClient#stack_id`) is sufficient to read the CI/deployment status — name, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`, `activity` — of any stack on the instance by simply changing `stack_id` in the URL. This is an unauthorized read of stack state performed by a credential that was deliberately scoped away from that data, matching the "escalation into `Shipit.github_teams` authorization" / "unauthenticated read of stack state" High-impact bar, since the attacker gains read access outside the boundary their token was explicitly granted.

### Likelihood Explanation
Exploitation requires only possession of any valid, stack-scoped `ApiClient` token with `read:stack` permission (e.g. a legitimately-issued token limited to one project/stack) and knowledge/guessing of another stack's identifier (`repo/name` or numeric id), which is not secret and is enumerable through the normal UI/API for any user with dashboard access. No privileged account, session, or GitHub credential is required beyond the low-privilege scoped token itself.

### Recommendation
Make `CCMenuController#stack` honor the same scoping as the rest of the API by looking the stack up through `stacks.from_param!(params[:stack_id])` instead of `Stack.from_param!(params[:stack_id])`, consistent with `BaseController#stack`.

### Proof of Concept
1. Admin issues (or a user self-serves via `CCMenuUrlController`) an `ApiClient` token scoped to Stack A: `permissions: ["read:stack"], stack_id: A.id`.
2. Attacker (holder of that token) sends:
   `GET /api/stacks/<B.to_param>/ccmenu?token=<token>` where `B` is an unrelated stack they were never granted access to.
3. `authenticate_api_client` succeeds (token is valid), `require_permission :read, :stack` passes (`permissions` includes `read:stack`), and `stack` resolves `B` directly via `Stack.from_param!`, ignoring `current_api_client.stack_id == A.id`.
4. The response renders `B`'s CI/build status XML, which the token was never authorized to view.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end
