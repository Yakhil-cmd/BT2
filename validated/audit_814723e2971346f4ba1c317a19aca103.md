### Title
Path traversal via crafted release asset name allows arbitrary file write outside destination directory - (File: pkg/cmd/release/download/download.go)

### Summary
`gh release download` builds the destination path for each release asset by calling `filepath.Join(w.dir, name)` in `destinationWriter.makePath`, where `name` is the attacker-controlled `Name` field from the GitHub Releases API. Unlike the analogous artifact-download code path in `pkg/cmd/run/download/download.go`, which validates joined paths with `safepaths.Absolute.Join`, this code performs no containment check, so a release asset named e.g. `../../.ssh/authorized_keys` can cause the downloaded file to be written outside `opts.Destination`.

### Finding Description
The attacker publishes a public repository/release whose asset `Name` (returned in the GitHub API response) contains path traversal sequences, e.g. `../../.ssh/authorized_keys`. When the victim runs `gh release download` against that repo:

1. `downloadRun` iterates `release.Assets` and builds `downloadTarget{name: a.Name}` directly from the API-provided name with no sanitization [1](#0-0) .
2. `downloadAssets` -> `downloadAsset` calls `dest.Check(fileName)` and then `dest.Copy(fileName, resp.Body)` with the unmodified attacker-controlled `fileName` [2](#0-1) [3](#0-2) .
3. `destinationWriter.makePath` computes the on-disk path via a bare `filepath.Join(w.dir, name)`, with no confinement check against `w.dir` [4](#0-3) .
4. `Copy` then calls `os.MkdirAll(dir, 0755)` on `filepath.Dir(fp)` and opens/writes the file at `fp` with `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)`, creating any missing intermediate directories and overwriting existing files without any path-containment check [5](#0-4) .

`filepath.Join` calls `filepath.Clean` internally, which resolves `..` segments lexically (not symlink-aware) — so `filepath.Join("/home/victim/downloads", "../../.ssh/authorized_keys")` resolves to a path outside the download directory. This is exactly the class of bug that `internal/safepaths.Absolute.Join` was built to prevent (it explicitly checks `isSubpathOf` and returns a `PathTraversalError` otherwise) [6](#0-5) . The `run download` artifact-download code path already adopted `safepaths` for this same class of untrusted-name-to-filesystem-path problem, but `release/download` was not updated to use it, leaving this specific command vulnerable. There is no filename sanitization (e.g. `filepath.Base`) applied to `a.Name` prior to use, in contrast to the archive-name fallback path which does apply `filepath.Base(serverFileName)` [7](#0-6)  — that protection only covers the Content-Disposition-derived archive filename, not asset names taken from `release.Assets`.

### Impact Explanation
An attacker who controls a public GitHub repository/release can control the `Name` field of an asset returned by the Releases API. A victim who runs `gh release download` (with default `--dir .` or any destination) against that repo/release will have the malicious asset's bytes written to an attacker-chosen path outside the intended destination directory, subject only to OS permissions of the invoking user. This can overwrite security-sensitive files such as `~/.ssh/authorized_keys`, shell profile files, or other startup files reachable by the victim's OS user, constituting an arbitrary file write/overwrite outside the intended destination — matching GitHub's "file write leading to code execution or account compromise" bounty impact class.

### Likelihood Explanation
High feasibility and full repeatability: this requires no special privileges beyond publishing a public repository with a release, which any GitHub user can do. The victim simply needs to run the ordinary `gh release download <tag>` (or `gh release download` for latest) command pointed at the attacker's repo — a common, unsuspicious workflow (e.g., following a README instruction, downloading a "build artifact" release). No token leakage, MITM, or local access is required.

### Recommendation
In `pkg/cmd/release/download/download.go`, replace the raw `filepath.Join(w.dir, name)` in `destinationWriter.makePath` with a confinement-checked join, mirroring the pattern already used in `pkg/cmd/run/download/download.go`: convert `w.dir` to a `safepaths.Absolute` (via `safepaths.ParseAbsolute`) once, then call `.Join(name)` for each asset, propagating a `PathTraversalError` as a hard failure instead of writing the file. Alternatively/additionally, reject or sanitize asset names containing path separators or `..` segments (e.g. via `filepath.Base` plus an explicit check that the result has no remaining `..`/separator components) before they reach `makePath`/`Copy`.

```go
// pkg/cmd/release/download/download_test.go (new test)
func TestDownloadAsset_PathTraversalInAssetName(t *testing.T) {
	tmp := t.TempDir()
	reg := &httpmock.Registry{}
	defer reg.Verify(t)
	reg.Register(
		httpmock.REST("GET", "attacker-asset-url"),
		httpmock.StringResponse("malicious content"),
	)
	httpClient := &http.Client{Transport: reg}

	dest := destinationWriter{dir: tmp}

	// Simulates a release asset whose Name field, as returned by the
	// GitHub API, contains a path traversal sequence.
	err := downloadAsset(&dest, httpClient, safeurl.NewImmutableSafeURL("attacker-asset-url"), "../../evil-outside-dest", false)

	// Expected (fixed) behavior: an error is returned (e.g. PathTraversalError)
	// and no file is created outside tmp.
	assert.Error(t, err)

	escapedPath := filepath.Join(filepath.Dir(tmp), filepath.Dir(tmp), "evil-outside-dest")
	_, statErr := os.Stat(escapedPath)
	assert.True(t, os.IsNotExist(statErr), "file must not be written outside destination")
}
```
Current (vulnerable) behavior: `downloadAsset` succeeds, `err == nil`, and `evil-outside-dest` is created two directories above `tmp` — demonstrating the write escapes `opts.Destination`.

```go
// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
```
