### Title
Cross-tenant webhook forgery via no-secret-org signature bypass lets an attacker mutate any `PullRequest`'s labels and poison a foreign review stack's deploy environment - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` used to authenticate a webhook solely from `params.dig('repository','owner','login')`, while the `pull_request` handlers (e.g. `LabelCapturingHandler`) resolve the target `Repository`/`Stack` solely from `params.repository.full_name`. Nothing binds these two attacker-controlled fields together, so an attacker who names an org with no `webhook_secret` configured in `repository.owner.login` can forge a signature-free request whose `repository.full_name` points at a completely different, victim-owned repository, writing to that victim's `PullRequest#labels` and `ReviewStack#env`.

### Finding Description
The broken binding, stated as an equality that the code implicitly assumes but never enforces:
`github_app_used_for_signature.organization == repository_that_gets_mutated.owner`

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` and does `github_app = Shipit.github(organization: repository_owner)` then `github_app.verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 
2. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org's config has no `webhook_secret`: `return true unless webhook_secret`. [3](#0-2) 
3. `Shipit::WebhooksController#create` then dispatches `params` (the raw, fully attacker-controlled JSON) unchanged to `Shipit::Webhooks.for_event(event)` handlers. [4](#0-3) 
4. `LabelCapturingHandler` (and the sibling `reopened`/`labeled`/`unlabeled`/`opened`/`closed` handlers) resolve the target repository from `params.repository.full_name` — a field completely independent from `repository.owner.login` used in step 1 — and locate the `Stack` via `ReviewStackAdapter#stack` (`environment: "pr#{params.number}"`). [5](#0-4) [6](#0-5) 
5. For `action == "reopened"` on a non-archived stack, `capture_labels` persists attacker-supplied label names onto the victim's `PullRequest`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))`. [7](#0-6) [8](#0-7) 
6. `ReviewStack#env` merges those attacker-chosen label names (uppercased) into the stack's environment, each set to `"true"`: `labels[label_name.upcase] = "true"`. [9](#0-8) 
7. This merged env reaches deploy/task command execution directly — confirmed by existing tests asserting `Shipit::DeployCommands.new(deploy).env["WIP"] == "true"` and the equivalent for `TaskCommands`, i.e., attacker-controlled label names become real environment variable names/values for shell commands. [10](#0-9) [11](#0-10) 
8. `Commit#deployable?` on such a stack requires only `!locked? && (stack.ignore_ci? || ...)`, so when `ignore_ci` is true the commit is deployable independent of CI state, meaning the poisoned environment reaches an actual deploy execution without any CI gate. [12](#0-11) 

Why existing guards fail: `verify_signature` only checks HMAC validity for the org named in `repository.owner.login`; it never checks that this org matches the org embedded in `repository.full_name` that the handler actually operates on. `ExplicitParameters` schemas (`params do ... end`) only validate shape/types, not cross-tenant consistency. `drop_unhandled_event` and `check_if_ping` are unrelated gates. No model validation ties `PullRequest#labels` writes to an authenticated originating repository.

### Impact Explanation
An unauthenticated attacker who merely knows (a) the name of any Shipit-configured GitHub org lacking a `webhook_secret`, and (b) the `full_name` of any victim repository with an active review stack, can:
- Write to `PullRequest#labels` for a stack belonging to a repository/org they never authenticated against — a payload for one (no-secret) repository mutating another repository's stack/PR record, which matches the Critical category "a payload for one repository mutating another's stack, commit, task or team."
- Inject arbitrary attacker-chosen environment variable names (set to `"true"`) into that victim stack's deploy/task environment via `ReviewStack#env`, which flows into shell command execution env for deploys/tasks.
- Combined with `ignore_ci: true` on the victim stack, `Commit#deployable?` bypasses the CI gate entirely, so the poisoned environment can influence a real deploy execution.

This is repeatable against every review-stack-enabled repository in the Shipit instance, as long as one no-secret-org exists to authenticate through, and blast radius spans all tenants/stacks reachable via `Repository.from_github_repo_name`.

### Likelihood Explanation
Preconditions: (1) at least one GitHub org configured in Shipit (`Shipit.github(organization:)`) without a `webhook_secret` — an operator misconfiguration rather than an inherent flaw, but explicitly acknowledged as reachable by the question's target; (2) a victim review stack with `ignore_ci: true` and a non-archived state; (3) attacker knows the victim's `repository.full_name` and PR number to target the `environment: "pr#{number}"`. All of this is obtainable from public GitHub information (repo name is public, PR numbers are sequential/public). Attacker cost is a single unauthenticated `POST /webhooks` request; the action is trivially repeatable and scriptable.

### Recommendation
Reject webhooks whose `repository.owner.login` (used to select the authenticating `GitHubApp`) does not match the owner embedded in `repository.full_name` used by handlers. Additionally, do not treat a blank `webhook_secret` as auto-verified — require an explicit `webhook_secret` for every configured organization, or reject/quarantine events from orgs with no configured secret.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure two orgs in `Shipit.github_config`: `"no-secret-org"` with no `webhook_secret`, and the victim org (e.g., `"victim-org"`) with a real `webhook_secret` unknown to the attacker.
2. Create `victim_repo = Shipit::Repository.create!(owner: "victim-org", name: "victim-repo")` and an associated non-archived `ReviewStack` with `ignore_ci: true`, `environment: "pr42"`, and an attached `PullRequest` with `labels: []`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or a garbage one), and body:
```json
{
  "action": "reopened",
  "number": 42,
  "repository": { "owner": { "login": "no-secret-org" }, "full_name": "victim-org/victim-repo" },
  "pull_request": { ... , "labels": [{"name": "FORCE_DEPLOY"}] },
  "sender": { "login": "attacker" }
}
```
4. Assert response is `200 OK` (bypassing `head(422)` in `verify_signature`).
5. Assert `victim_repo.review_stacks.find_by(environment: "pr42").pull_request.reload.labels == ["FORCE_DEPLOY"]`.
6. Assert `stack.env["FORCE_DEPLOY"] == "true"` via `ReviewStack#env`.
7. Assert that no request ever used `victim-org`'s `webhook_secret` (mock/spy `GitHubApp#verify_webhook_signature` only invoked for `no-secret-org`'s app instance), proving the victim repository was mutated without ever authenticating against its own secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
