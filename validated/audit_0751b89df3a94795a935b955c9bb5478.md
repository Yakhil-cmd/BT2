### Title
Double integer division in `min-ustx-for-sats-amount` truncates the required uSTX collateral to zero, letting stakers register for sBTC bonds with under-collateralized (or zero) STX lockup - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`pox-5.clar`'s `min-ustx-for-sats-amount` computes the minimum uSTX a staker must lock to back a given sats amount using two chained integer divisions. Each division floors its result, so for small `sats-amount` / `stx-value-ratio` / `min-ustx-ratio` combinations the intermediate and final results can floor to `0`, exactly the rounding-to-zero bug class described in the external report (`interval` floor-dividing borrowing interest to `0`).

### Finding Description
The function is:
```
(/ (* (/ (* stx-value-ratio sats-amount) u100) min-ustx-ratio) u10000)
``` [1](#0-0) 

This is a **compounded** floor division: the inner division `(stx-value-ratio * sats-amount) / 100` is floored first, and that already-truncated value is then multiplied by `min-ustx-ratio` and floored again by `/ u10000`. Compared to a single division, this doubles the truncation error and makes it far easier for the final minimum-uSTX requirement to collapse to `0` even when `sats-amount` is not `0`. For example, with `stx-value-ratio = 10` and `sats-amount` small enough that `stx-value-ratio * sats-amount < 100`, the inner term already floors to `0`, and the outer division then guarantees the whole result is `0` regardless of `min-ustx-ratio`.

This value is used by `register-for-bond` to enforce the collateral floor a staker must lock in STX to back their sats allocation in a bond period, as shown by the test helper that reimplements the same truncating formula: `minUstxForSats` explicitly notes it performs "Integer division at each step, matching the contract's truncation." [2](#0-1) 

Because `register-for-bond` only checks `amountUstx >= min-ustx-for-sats-amount(...)`, when the computed minimum floors to `0`, a staker can register for a bond slot (and accrue rewards proportional to their allotted `sats` share via `calculate-bond-rewards` / `get-earned`) while locking little or no STX, breaking the intended equality between STX collateral locked and sats-denominated reward entitlement. [3](#0-2) 

### Impact Explanation
This falls under "High - signing weight or reward slots exceeding locked value": a staker's bond reward-slot entitlement (denominated in `sats`) is no longer properly backed by the STX collateral the protocol design requires, because the collateral-floor formula can truncate to zero. The staker still earns bond yield (`accrued-rewards-per-sat`, `get-earned`) proportional to their allotted sats share without providing the intended uSTX backing.

### Likelihood Explanation
Likelihood depends on `stx-value-ratio`, `min-ustx-ratio`, and the granularity of `sats-amount` chosen when a bond is set up (`setupBond`) and when a staker registers with a small allotment. Any bond configuration combined with a sufficiently small per-staker `sats` allocation reachable through `register-for-bond`'s allowlist mechanism can trigger the truncation; this does not require any privileged role, only a bond that has already been set up (by the admin) and a staker choosing/being allotted a small sats amount.

### Recommendation
Compute `min-ustx-for-sats-amount` with a single division at the end (defer all divisions until the last step) or scale up intermediate precision (e.g., multiply first, divide once by `100 * 10000`), and/or enforce a non-zero minimum uSTX floor when `sats-amount > 0`, mirroring the interest-rounding fix recommended in the analogous report (minimum interval / increased precision).

### Proof of Concept
1. Deployer calls `setup-bond` with `stx-value-ratio = 10`, `min-ustx-ratio = 100` (1%), and allowlists a staker for a small `sats-amount`, e.g. `sats-amount = 5`.
2. `min-ustx-for-sats-amount(5, 10, 100)` evaluates as `(/ (* (/ (* 10 5) 100) 100) 10000)` = `(/ (* (/ 50 100) 100) 10000)` = `(/ (* 0 100) 10000)` = `0`. [1](#0-0) 
3. The staker calls `register-for-bond` with `amountUstx = 0`, which passes the `amountUstx >= min-ustx-for-sats-amount(...)` check, registering the staker for the bond's `sats` allocation with zero locked STX collateral.
4. When `calculate-bond-rewards` runs, the staker's registered `sats` share accrues rewards (`accrued-rewards-per-sat`) exactly as if properly collateralized, despite having locked no (or negligible) STX. [3](#0-2)

/**
 * Contract's `min-ustx-for-sats-amount`: the floor uSTX a staker must lock for
 * `sats`. Integer division at each step, matching the contract's truncation.
 */
export function minUstxForSats(
  sats: bigint,
  stxValueRatio: bigint,
  minUstxRatio: bigint,
): bigint {
  return (((stxValueRatio * sats) / 100n) * minUstxRatio) / 10000n;
}
