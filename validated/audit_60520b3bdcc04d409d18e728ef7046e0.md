### Title
Cross-tenant unsigned webhook forgery via organization/repository owner mismatch in `verify_signature` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to verify against using `repository_owner`, which falls back to the attacker-supplied `organization.login` field whenever `repository.owner.login` is absent. In a multi-organization Shipit deployment, if any configured organization has no `webhook_secret` set (explicitly documented as optional), an attacker can name that organization in `organization.login` to make `verify_webhook_signature` short-circuit to `true`, while pointing the actual mutation at `repository.full_name` belonging to a different, properly-secured organization.

### Finding Description
The broken binding, stated as an equality that the code implicitly assumes but never enforces:

`organization_used_for_signature_check (params.dig('organization','login'))` == `organization_owning(params.dig('repository','full_name'))`

This is false in general, and nothing in the code path enforces it.

Code path:
1. `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')`. [1](#0-0) [2](#0-1) 
2. In multi-org config mode, `Shipit.github` looks up that organization's config via `github_app_config(organization)` and instantiates a `GitHubApp` scoped to it; if the org key doesn't exist it raises `GithubOrganizationUnknown` (caught, 422). [3](#0-2) 
3. `GitHubApp#verify_webhook_signature` returns `true` immediately if that org's `webhook_secret` is blank, entirely skipping HMAC verification: `return true unless webhook_secret`. [4](#0-3) 
4. On `verified == true`, no `head` is called, the filter chain continues to `create`, which re-parses the raw body and dispatches to all registered handlers for the event with the full attacker-controlled payload: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [5](#0-4) 
5. For `pull_request` events, handlers such as `LabelCapturingHandler`/`OpenedHandler`/`LabeledHandler` resolve their target purely from `params.repository.full_name`, with zero reference back to which organization's secret was used to authorize the request: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [6](#0-5) 

Attacker request: `POST /webhooks` with header `X-Github-Event: pull_request`, no `X-Hub-Signature`, and body:
```json
{"action":"opened","number":1,"pull_request":{...valid schema...},
 "organization":{"login":"unconfigured-org"},
 "repository":{"full_name":"configured-org/repo","owner":{}},
 "sender":{"login":"attacker"}}
```
If `unconfigured-org` is a real organization configured in Shipit's multi-org `secrets.github` block with `webhook_secret: # nil` (a state the project's own docs treat as a normal/optional configuration), `verify_webhook_signature` returns `true` unconditionally, and the forged event is processed and mutates state (labels, review-stack archive/unarchive, PR records) for `configured-org/repo`, an organization that does have a real `webhook_secret` and never issued this request.

Existing guards do not prevent this: `drop_unhandled_event` only filters by event type, not organization; `GithubOrganizationUnknown` only guards against organizations absent from config entirely, not organizations present but lacking a secret; and no handler cross-checks the verified organization against `repository.full_name`'s owner.

### Impact Explanation
An unauthenticated attacker can inject fully forged GitHub events (`pull_request` opened/labeled/unlabeled/reopened, `push`, `status`, `check_suite`) against any repository/organization tracked by the Shipit instance, as long as at least one other configured organization on that instance has no `webhook_secret`. This lets the attacker: write/clear `PullRequest#labels`, trigger `stack.archive!`/`stack.unarchive!`, and drive `ReviewStackAdapter` provisioning/deprovisioning for a completely different tenant's stacks — a payload for one (weakly configured) organization mutating another (properly secured) organization's stack/task/PR state. This is repeatable for every event type registered in `Shipit::Webhooks.default_handlers` [7](#0-6) , and blast radius spans every organization/repository hosted on the same multi-tenant Shipit instance. This matches "Critical: a payload for one repository mutating another's stack" in the impact rubric.

### Likelihood Explanation
Preconditions: the Shipit instance must use the multi-organization `secrets.github` schema (documented as a supported, first-class configuration in `docs/setup.md`) [8](#0-7) , and at least one configured organization must have `webhook_secret` unset — which the docs and shipped example configs explicitly present as optional/acceptable (`webhook_secret: # nil`) [9](#0-8) . Attacker cost is a single unauthenticated HTTP POST with no signature and no knowledge of any secret; the only unknown is the name of a configured-but-secretless organization, which is discoverable via a response-code oracle (200 on success vs. 422 for unknown org vs. an unhandled exception/500 when a real secret exists but no `X-Hub-Signature` is sent, since `signature.split` is called on `nil`). The attack is fully repeatable against arbitrary target repositories by varying `repository.full_name` in the forged body.

### Recommendation
`verify_signature` should never allow a payload to be trusted for one organization based on a different, weaker organization's (lack of) secret. Concretely: derive the verifying organization strictly and consistently from `repository.owner.login` when a `repository` object is present (do not fall back to the unauthenticated `organization.login` for repository-scoped events), and additionally require that handlers only process a payload if the organization used to satisfy `verify_webhook_signature` actually owns `repository.full_name`. Also make `GitHubApp#verify_webhook_signature` fail closed (return `false`, not `true`) when `webhook_secret` is blank, so a misconfigured org can't be used as a universal signature bypass; if unsigned webhooks must be allowed for some setups, that should be an explicit opt-in checked against the specific target repository, not a global short-circuit.

### Proof of Concept
Under `test/controllers/webhooks_controller_test.rb`, using the existing double-org fixtures (`OrgOne`/`OrgTwo` with `webhook_secret: nil` per `test/dummy/config/secrets_double_github_app.yml`) but overriding one org (`OrgTwo`) to have a real `webhook_secret`:

```ruby
test "forged organization with no webhook_secret can mutate a different, secured organization's repository" do
  # OrgOne has no webhook_secret; OrgTwo has a configured webhook_secret and owns shopify/shipit-engine's stand-in repo
  repository = shipit_repositories(:shipit) # belongs to "configured-org/repo" equivalent
  repository.update!(provisioning_behavior: :allow_all)

  payload = payload_parsed(:pull_request_opened)
  payload["organization"] = { "login" => "OrgOne" } # secretless org, attacker-chosen
  payload["repository"]["owner"] = {}                # force fallback to organization.login
  payload["repository"]["full_name"] = repository.full_name # OrgTwo's real repo
  payload["pull_request"]["labels"] = [{ "name" => "attacker-label" }]

  @request.headers['X-Github-Event'] = 'pull_request'
  # no X-Hub-Signature header sent

  assert_difference -> { Shipit::Stack.count }, 1 do
    post :create, body: payload.to_json, as: :json
    assert_response :ok # equality falsely holds: OrgOne's (absent) secret authorized OrgTwo's repository
  end
end
```
Assertion on the binding: `Shipit.github(organization: "OrgOne").verify_webhook_signature(nil, raw_body)` returns `true` (via `return true unless webhook_secret`) while `Shipit::Repository.from_github_repo_name(payload["repository"]["full_name"])` resolves to a repository under `OrgTwo`, i.e. `verifying_org ("OrgOne") != repository_owner ("OrgTwo")`, yet the request is accepted (`200 OK`) and a stack/PR record is created/mutated — proving the binding is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
