### Title
Unbounded eventBus listener/closure accumulation from unresolved private-payment chains never freed - ([File: wallet.js])

### Summary
`handlePrivatePaymentChains` in [1](#0-0)  registers `eventBus.once(key, ...)` listeners that hold references to the entire `arrChains` payload and closures over `assocValidatedByKey`, `cancelAllKeys`, and `from_address`. These are only released when the corresponding `unhandled_private_payments` row is later validated (fires the event) via `handleSavedPrivatePayments` in [2](#0-1) . If validation instead lands in the `ifWaitingForChain` branch — which happens whenever the past units of the chain never arrive — the row simply stays queued forever and the key event is never emitted, so the listener and its retained memory are never freed.

### Finding Description
A private-payment counterparty (a paired device correspondent, not requiring hub compromise) sends a `private_payment_chains` device message. `handlePrivatePaymentChains` computes a `cache_key` from the whole chain content and, for each chain, a `key = 'private_payment_validated-'+unit+'-'+hash+'-'+output_index`, then calls `network.handleOnlinePrivatePayment` [3](#0-2) . For light wallets receiving a multi-element chain (`conf.bLight && arrPrivateElements.length > 1`), the payment is unconditionally queued into `unhandled_private_payments` and `callbacks.ifQueued()` fires immediately [4](#0-3) , so back in `wallet.js` an `eventBus.once(key, ...)` listener is registered and `cb()` is called right away, letting `async.eachSeries` finish and `bParsingComplete = true` [5](#0-4) .

The queued chain is only re-validated by the periodic `handleSavedPrivatePayments` job [2](#0-1) , driven by `updateLinkProofsOfPrivateChain`/`validateAndSavePrivatePaymentChain`. If the chain's past units are never delivered (an attacker can construct a chain whose earlier elements reference legitimate-looking but never-completable unit references, or simply never provide the dependent joints), `privatePayment.validateAndSavePrivatePaymentChain` keeps returning `ifWaitingForChain` [6](#0-5) , and `handleSavedPrivatePayments`'s `ifWaitingForChain` handler just calls `cb()` without ever emitting the `key` event [7](#0-6) . Consequently:
- The `eventBus.once(key, ...)` listener registered in `wallet.js` (holding `arrChains`, `assocValidatedByKey`, `from_address`, `cancelAllKeys`) is never invoked and never removed.
- The `unhandled_private_payments` row (containing the full serialized chain JSON) persists in the DB, retried every 5–12 seconds forever (`setInterval(handleSavedPrivatePayments, 5*1000)` / `requestUnfinishedPastUnitsOfSavedPrivateElements` every 12s, see `startLightClient` [8](#0-7) ).
- `handledChainsCache[cache_key]` dedup in `wallet.js` [9](#0-8)  only stops literally identical chains; an attacker can trivially vary blinding factors/amounts/junk fields to produce a fresh `cache_key` and a fresh `key` per message, defeating the cache and creating a brand-new leaked listener each time.

This directly mirrors the Xenstore CVE pattern: memory (here, JS heap: closures, event listeners, and queued chain JSON) allocated to service a request is retained until a response condition is satisfied by the counterparty, and a party who never satisfies that condition (never provides/finishes the chain) prevents the memory from ever being freed.

### Impact Explanation
An unprivileged paired device (private-payment counterparty) can repeatedly send crafted, never-completable private-payment chains to a victim light wallet. Each such message permanently leaks:
1. An `eventBus.once` listener plus its closure (`arrChains` and related state) in the node process, and
2. A DB row in `unhandled_private_payments` that is retried indefinitely every few seconds.

Repeating this at will causes unbounded growth of both in-process memory (Node's global EventEmitter, `handledChainsCache`) and disk-backed unhandled queue, eventually leading to memory exhaustion / crash of the victim's wallet node — a Denial of Service that prevents the wallet from processing further private payments or, in severe cases, from confirming any transactions at all. This qualifies as "a network unable to confirm new units" from the victim node's perspective, matching the medium severity of the analog CVE.

### Likelihood Explanation
Any device paired with the victim (a normal, expected trust relationship for a private-payment counterparty) can trigger this with a single `private_payment_chains` message; no special privileges, mining power, or protocol-level exploit is required — only sending chains whose past units are deliberately withheld. The attack is repeatable at will and trivially varied to bypass the `handledChainsCache` dedup, making exploitation straightforward for a malicious or compromised correspondent.

### Recommendation
- Bound the lifetime of `eventBus.once(key, ...)` registrations in `handlePrivatePaymentChains`: attach a timeout that removes the listener (`eventBus.removeListener`) and invalidates `assocValidatedByKey` if the corresponding `unhandled_private_payments` row is not resolved within a fixed period.
- Enforce a hard limit on how many chains/messages can remain in `ifWaitingForChain` state per correspondent device, and purge (with listener cleanup) `unhandled_private_payments` rows older than a bounded age even for chains still "waiting" (currently `cleanBadSavedPrivatePayments` only purges rows whose head unit itself never resolves, not rows generically stuck in `ifWaitingForChain`).
- Cap `handledChainsCache` size/age more strictly and/or key it per-sender to prevent an attacker from generating unbounded distinct keys.

### Proof of Concept
1. Pair a light-wallet victim device with an attacker-controlled device (normal correspondent relationship for private payments).
2. Attacker sends a `private_payment_chains` message via `sendMessageToDevice`/hub containing a valid-looking multi-element chain whose intermediate `unit` references a unit the attacker never actually broadcasts/delivers (so `findUnfinishedPastUnitsOfPrivateChains` in `private_payment.js` always finds unfinished past units).
3. On the victim, `handlePrivatePaymentChains` immediately queues the payment (`ifQueued`) and registers a permanent `eventBus.once(key, ...)` listener; `handleSavedPrivatePayments` retries every 5s and always returns `ifWaitingForChain`, never emitting `key`.
4. Attacker repeats step 2 with slightly modified blinding/amount values (new `cache_key`/`key` each time) at high frequency.
5. Observe steadily growing `eventBus` listener count and `unhandled_private_payments` table size on the victim node, eventually leading to memory exhaustion.

		var cache_key = objectHash.getBase64Hash(arrChains);
	}
	catch (e) {
		return callbacks.ifError("chains hash failed: " + e.toString());		
	}
	if (handledChainsCache[cache_key]) {
		eventBus.emit('all_private_payments_handled', from_address);
		eventBus.emit('all_private_payments_handled-' + arrChains[0][0].unit);

	profiler.increment();

				var arrAuthorAddresses = rows.map(function(row){ return row.address; });

				forwardPrivateChainsToOtherMembersOfSharedAddresses(arrChains, arrAuthorAddresses, from_address, true);
			});
		}
		profiler.print();
	};
	
	async.eachSeries(
		arrChains,

			var objHeadPrivateElement = arrPrivateElements[0];
			if (!!objHeadPrivateElement.payload.denomination !== ValidationUtils.isNonnegativeInteger(objHeadPrivateElement.output_index))
				return cb("divisibility doesn't match presence of output_index");
			var output_index = objHeadPrivateElement.payload.denomination ? objHeadPrivateElement.output_index : -1;
			try {
				var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
			}
			catch (e) {
				return cb("head priv element hash failed " + e.toString());
			}
			var key = 'private_payment_validated-'+objHeadPrivateElement.unit+'-'+json_payload_hash+'-'+output_index;
			assocValidatedByKey[key] = false;
			network.handleOnlinePrivatePayment(ws, arrPrivateElements, true, {
				ifError: function(error){
					console.log("handleOnlinePrivatePayment error: "+error);
					cb("an error"); // do not leak error message to the hub
				},
				ifValidationError: function(unit, error){
					console.log("handleOnlinePrivatePayment validation error: "+error);
					cb("an error"); // do not leak error message to the hub
				},
				ifAccepted: function(unit){
					console.log("handleOnlinePrivatePayment accepted");
					assocValidatedByKey[key] = true;
					cb(); // do not leak unit info to the hub
				},

					console.log("handleOnlinePrivatePayment queued, will wait for "+key);

						if (!bValid)
							return cancelAllKeys();

						if (bParsingComplete)

						else
							console.log('parsing incomplete yet');
					});
					cb();
				}
			});

		function(err){
			bParsingComplete = true;
			if (err){
				cancelAllKeys();
				return callbacks.ifError(err);
			}
			checkIfAllValidated();
			handledChainsCache[cache_key] = Date.now();
			callbacks.ifOk();
			// forward the chains to other members of output addresses
			if (!body.forwarded)
				forwardPrivateChainsToOtherMembersOfOutputAddresses(arrChains, true);
		}
	);

function handleOnlinePrivatePayment(ws, arrPrivateElements, bViaHub, callbacks){
	if (!ValidationUtils.isNonemptyArray(arrPrivateElements))
		return callbacks.ifError("private_payment content must be non-empty array");
	
	var unit = arrPrivateElements[0].unit;
	var message_index = arrPrivateElements[0].message_index;
	var output_index = arrPrivateElements[0].payload.denomination ? arrPrivateElements[0].output_index : -1;
	if (!ValidationUtils.isValidBase64(unit, constants.HASH_LENGTH))
		return callbacks.ifError("invalid unit");
	if (!ValidationUtils.isNonnegativeInteger(message_index))
		return callbacks.ifError("invalid message_index");
	if (!(ValidationUtils.isNonnegativeInteger(output_index) || output_index === -1))
		return callbacks.ifError("invalid output_index");

	var savePrivatePayment = function(cb){
		// we may receive the same unit and message index but different output indexes if recipient and cosigner are on the same device.
		// in this case, we also receive the same (unit, message_index, output_index) twice - as cosigner and as recipient.  That's why IGNORE.
		db.query(
			"INSERT "+db.getIgnore()+" INTO unhandled_private_payments (unit, message_index, output_index, json, peer) VALUES (?,?,?,?,?)", 
			[unit, message_index, output_index, JSON.stringify(arrPrivateElements), bViaHub ? '' : ws.peer], // forget peer if received via hub
			function(){
				callbacks.ifQueued();
				if (cb)
					cb();
			}
		);
	};
	
	if (conf.bLight && arrPrivateElements.length > 1){
		savePrivatePayment(function(){
			updateLinkProofsOfPrivateChain(arrPrivateElements, unit, message_index, output_index);
			rerequestLostJointsOfPrivatePayments(); // will request the head element
		});
		return;
	}

	joint_storage.checkIfNewUnit(unit, {
		ifKnown: function(){
			//assocUnitsInWork[unit] = true;
			privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {
				ifOk: function(){
					//delete assocUnitsInWork[unit];
					callbacks.ifAccepted(unit);
					eventBus.emit("new_my_transactions", [unit]);
				},
				ifError: function(error){
					//delete assocUnitsInWork[unit];
					callbacks.ifValidationError(unit, error);
				},
				ifWaitingForChain: function(){
					savePrivatePayment();
				}
			});
		},
		ifNew: function(){
			savePrivatePayment();
			// if received via hub, I'm requesting from the same hub, thus telling the hub that this unit contains a private payment for me.
			// It would be better to request missing joints from somebody else
			requestNewMissingJoints(ws, [unit]);
		},
		ifKnownUnverified: savePrivatePayment,
		ifKnownBad: function(){
			callbacks.ifValidationError(unit, "known bad");
		}
	});
}

function handleSavedPrivatePayments(unit){
	//if (unit && assocUnitsInWork[unit])
	//    return;
	if (!my_device_address) return; // skip if we don't have a wallet
	if (!unit && mutex.isAnyOfKeysLocked(["private_chains"])) // we are still downloading the history (light)
		return console.log("skipping handleSavedPrivatePayments because history download is still under way");
	var lock = unit ? mutex.lock : mutex.lockOrSkip;
	lock(["saved_private"], function(unlock){
		var sql = unit
			? "SELECT json, peer, unit, message_index, output_index, linked FROM unhandled_private_payments WHERE unit="+db.escape(unit)
			: "SELECT json, peer, unit, message_index, output_index, linked FROM unhandled_private_payments CROSS JOIN units USING(unit)";
		db.query(sql, function(rows){
			if (rows.length === 0)
				return unlock();
			var assocNewUnits = {};
			async.each( // handle different chains in parallel
				rows,
				function(row, cb){
					var arrPrivateElements = JSON.parse(row.json);
					var ws = getPeerWebSocket(row.peer);
					if (ws && ws.readyState !== ws.OPEN)
						ws = null;
					
					var validateAndSave = function(){
						var objHeadPrivateElement = arrPrivateElements[0];
						try {
							var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
						}
						catch (e) {
							console.log("getBase64Hash failed for private element", objHeadPrivateElement.payload, e);
							if (ws)
								sendResult(ws, {private_payment_in_unit: row.unit, result: 'error', error: e.toString()});
							deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
						}
						var key = 'private_payment_validated-'+objHeadPrivateElement.unit+'-'+json_payload_hash+'-'+row.output_index;
						privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {
							ifOk: function(){
								if (ws)
									sendResult(ws, {private_payment_in_unit: row.unit, result: 'accepted'});
								if (row.peer) // received directly from a peer, not through the hub
									eventBus.emit("new_direct_private_chains", [arrPrivateElements]);
								assocNewUnits[row.unit] = true;
								deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
								console.log('emit '+key);
								eventBus.emit(key, true);
							},
							ifError: function(error){
								console.log("validation of priv: "+error);
							//	throw Error(error);
								if (ws)
									sendResult(ws, {private_payment_in_unit: row.unit, result: 'error', error: error});
								deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
								eventBus.emit(key, false);
							},
							// light only. Means that chain joints (excluding the head) not downloaded yet or not stable yet
							ifWaitingForChain: function(){
								console.log('waiting for chain: unit '+row.unit+', message '+row.message_index+' output '+row.output_index);
								cb();
							}
						});
					};
					
					if (conf.bLight && arrPrivateElements.length > 1 && !row.linked)
						updateLinkProofsOfPrivateChain(arrPrivateElements, row.unit, row.message_index, row.output_index, cb, validateAndSave);
					else
						validateAndSave();
					
				},
				function(){
					unlock();
					var arrNewUnits = Object.keys(assocNewUnits);
					if (arrNewUnits.length > 0)
						eventBus.emit("new_my_transactions", arrNewUnits);
				}
			);
		});
	});
}
