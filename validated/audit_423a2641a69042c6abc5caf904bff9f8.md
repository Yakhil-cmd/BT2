### Title
Unbounded scaled-debt accrual overflows before the index cap and permanently freezes a market - (File: common/src/rates/index.rs)

### Summary

The borrow-index ceiling only limits the index value, not the resulting `borrowed * borrow_index` book value, so an oversized high-utilization market can reach an `i128` multiplication overflow before the ceiling is reached. [1](#0-0) [2](#0-1) 

### Finding Description

`update_borrow_index` clamps the new index to `MAX_BORROW_INDEX_RAY`, but `calculate_supplier_rewards` then multiplies the market’s scaled debt by that index and performs a checked subtraction. [1](#0-0) [2](#0-1) 

For sufficiently large `borrowed`, the permitted index range still allows the scaled debt value to exceed `i128::MAX`, producing `MathOverflow` before the index cap can prevent it. [3](#0-2) [4](#0-3) 

`global_sync` calls one accrual step per bounded time chunk and only marks the market accrued after all chunks complete, so a panic anywhere in the loop prevents the timestamp and indexes from being committed. [5](#0-4) 

An unprivileged caller can trigger the state through `Controller::update_indexes(caller, vec![hub_asset])`; the controller only requires the caller’s authorization before forwarding the requested markets to the pool. [6](#0-5) 

The same accrual runs before market mutations, so once the overflow boundary is reached, user `withdraw`, `repay`, and `liquidate` calls against that market fail as well. [7](#0-6) [8](#0-7) 

### Impact Explanation

This permanently freezes all supplier funds in the affected `(hub_id, asset)` market: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot settle positions because each path performs accrual first. [9](#0-8) [7](#0-6) 

The repository’s long-horizon regression test demonstrates that the value ceiling is reached before `MAX_BORROW_INDEX_RAY` and that both withdrawal and repayment then revert with `MathOverflow`. [10](#0-9) [11](#0-10) 

### Likelihood Explanation

A single unprivileged user can create one account supplying liquidity in the target market and another account supplying collateral, then borrow enough of the target asset to create the oversized scaled-debt position. [12](#0-11) 

The attack requires a very large token position and sustained high utilization, but no privileged role, malformed input, leaked key, or external-service failure; the attacker can keep the debt open and invoke the public `update_indexes` path once the market crosses the value-overflow boundary. [6](#0-5) 

### Recommendation

Bound index growth by the market’s scaled balances, not only by global index constants. Before applying a new borrow index, compute the maximum index for which `borrowed.mul(index)` remains within `i128`, using `I256` or an equivalent wide intermediate, and clamp `new_borrow_index` to that market-specific bound. Apply the same value-capacity check to `supplied * supply_index` in `update_supply_index` and to both products in `supply_index_reward_shortfall`. [13](#0-12) [14](#0-13) 

### Proof of Concept

The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` supplies a billion-token 18-decimal market, borrows at 98% utilization, advances ledger time until `update_indexes` returns `MathOverflow`, and confirms that the index cap was not reached. [15](#0-14) 

The same test then demonstrates the resulting freeze by asserting that a one-unit withdrawal and a repayment both fail with `MathOverflow`. [16](#0-15) 

The reachable transaction sequence is `supply(attacker, 0, spoke_id, [(target, liquidity)])`, `supply(attacker, 0, spoke_id, [(collateral, collateral_amount)])`, `borrow(attacker, account_id, [(target, debt_amount)], None)`, followed later by `update_indexes(attacker, [target])`; after the overflow, subsequent `withdraw`, `repay`, or `liquidate` calls touching `target` revert. [12](#0-11) [17](#0-16)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
