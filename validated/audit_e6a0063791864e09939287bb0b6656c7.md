### Title
Liquidation of insolvent accounts pays a positive bonus, enlarging the bad debt socialized to suppliers - (File: contracts/controller/src/positions/liquidation/curve.rs)

### Summary
When an account's unweighted collateral `C` falls below its debt `D`, `estimate_liquidation_amount` bypasses the HF-preserving bonus cap and quotes a repayment of `floor(C / (1 + base))` at the **base bonus**. Each liquidation therefore removes `repay * (1 + base)` of collateral against `repay` of debt on a position that is already under-collateralized. Because `1 + base > 1` and `C < D`, every liquidation strictly worsens the collateralization ratio `C/D` — the same defect as the StakeWise osETH finding. Here the consequence is worse than an unhealthier position: the residual deficit is ultimately socialized to suppliers through `apply_bad_debt_to_supply_index`, so the bonus paid on underwater accounts is extracted from other users' deposits.

### Finding Description
`estimate_liquidation_amount` contains an explicit insolvency branch:

```rust
Some(_) if snap.total_collateral < snap.total_debt => {
    let one_plus_base = Wad::ONE.checked_add(env, bounds.base.to_wad(env));
    let backed = snap.total_collateral.div_floor(env, one_plus_base);
    return (backed.min(snap.total_debt), bounds.base);
}
``` [1](#0-0) 

The HF-preserving cap `max_hf_preserving_bonus_bps` (`floor(HF * BPS / p) - BPS`) exists precisely to keep `1 + bonus <= C/D`, i.e. to guarantee liquidation never lowers the health factor — the docs and Certora rules confirm this intent ( [2](#0-1) ). Yet the insolvency branch discards the cap and returns `bounds.base` unconditionally. `bounds.base` is the USD-weighted average of stamped per-asset liquidation bonuses and is strictly positive for any normally configured collateral (e.g. ~500–900 bps in tests).

Seizure then takes `repay * (1 + base)` USD of collateral pro-rata in `calculate_seized_collateral` via `total_seizure_usd = repay_usd * one_plus_bonus` ( [3](#0-2) ). For `C < D` and `b = base > 0`:

```
C' = C - x(1+b),  D' = D - x   ⟹   C'/D' < C/D   (since C < D < (1+b)D)
```

HF = `p * C / D` falls by the same factor. Repeating partial liquidations on an underwater account above the $5 `BAD_DEBT_USD_THRESHOLD` monotonically drains the collateral that should back the residual debt. The leftover unbacked debt is then socialized: `clean_bad_debt` / post-`liquidate` auto-cleanup calls `apply_bad_debt_to_supply_index`, writing down the debt market's supply index and imposing the loss on that market's suppliers ( [4](#0-3) ).

The harness test `deep_underwater_account_still_liquidates_to_the_dust_gate` demonstrates the reachable path: a $10k-collateral / $12k-debt account sits above the dust gate and accepts repeated profitable partial liquidations, each paying the liquidator a positive margin ( [5](#0-4) ).

### Impact Explanation
Each liquidation of an insolvent account transfers `repay * base` USD of collateral value to the liquidator over and above the debt extinguished. That excess does not come from a healthier borrower — the borrower is already underwater — so it is a direct transfer from the pool of collateral that backs the eventual socialized loss, i.e. from suppliers in the debt market. A liquidator (or the borrower's own second account racing liquidators, or any MEV-style keeper) can slice the liquidation into many partials to extract `base%` of every repaid dollar until collateral falls to the $5 dust gate, maximizing the bonus extracted per unit of debt cleared. The protocol loses more collateral per dollar of debt repaid than a zero-bonus insolvent liquidation would, so supplier write-downs are strictly larger than necessary — theft of user funds / aggravated protocol insolvency by an unprivileged caller of `liquidate`.

### Likelihood Explanation
Reachable by any address via `liquidate(liquidator, account_id, debt_payments, seize_mode)` — the liquidator need only authenticate and hold the debt tokens, and self-liquidation is permitted ( [6](#0-5) , [7](#0-6) ). The only precondition is an insolvent account (`C < D`, `HF < 1`) with collateral above the $5 dust threshold — a normal occurrence after any sharp price move that outpaces liquidations, exactly the environment where liquidation volume is highest. No timing, governance, or privileged access is required, and splitting into partials is unrestricted (the V-6 split analysis only bounds profitability in the HF-preserving regime, not the insolvent branch). Severity Medium: extraction rate is bounded by `base` per liquidation and total extractable value by `C - D/(1)`… i.e. roughly `base/(1+base)` of the underwater collateral, and only on accounts that reach insolvency before full liquidation.

### Recommendation
On the insolvent branch, clamp the paid bonus so seizure never exceeds the debt repaid's proportional share of collateral — i.e. pay `min(base, max(C/D - 1, 0))` (equivalently `min(base, cap)` where `cap` can be computed as `floor(C * BPS / D) - BPS`, the insolvent analogue of the HF-preserving cap). Concretely, change the branch to `(min(D, floor(C / (1 + min(base, cap)))), min(base, cap))` with `cap = floor(C*BPS/D) - BPS` floored at zero. This still quotes the full collateral-backed repayment so liquidations remain profitable up to the true backing (`C/D`), while ensuring each slice leaves `C'/D' >= C/D` and the bonus never comes out of suppliers' eventual recovery. Alternatively, pay the bonus only out of the `C - D` surplus when one exists, and zero otherwise.

### Proof of Concept
Single collateral/debt market at $1, liquidation threshold 80%, stamped base bonus 5% (as in the standard harness config):

1. Alice supplies $10,000 USDC and borrows $8,000 of DEBT. `C = 10_000`, `D = 8_000`.
2. DEBT appreciates / USDC crashes so `C = 10_000`, `D = 12_000` (HF ≈ 0.667 < 1; collateral >> $5 so `clean_bad_debt` reverts).
3. Liquidator calls `liquidate` with a full offer of the DEBT leg. The insolvency branch returns `repay = min(12_000, floor(10_000/1.05)) = 9_523.81` at bonus 5%; seizure = `9_523.81 * 1.05 = 10_000` — all collateral gone, residual debt `2_476.19` is 100% bad debt socialized to DEBT-market suppliers.
   Compare a proportional (bonus-0 or capped) liquidation: repaying `x` could seize only `x * C/D = 0.833x`, so the same `9_523.81` repayment would have left `2_063` of collateral backing `2_476` of residual debt — suppliers would recover $2,063 more. The liquidator's $476.19 "bonus" is paid entirely from supplier funds.
4. Partial variant: liquidator repays only $1,000 → seizes $1,050. Now `C' = 8_950`, `D' = 11_000`, ratio `0.8136 < 0.8333`: the position is strictly unhealthier, matching the StakeWise finding, and each subsequent slice repeats the drain until the dust gate lets cleanup write the enlarged deficit into the supply index.

Numerically verifiable against the plan math: `estimate_liquidation_amount` returns `(backed.min(D), base)` with `backed = floor(C/1.05)`, and `calculate_seized_collateral` seizes `repay * 1.05` pro-rata, so post-state `C'/D' < C/D` for every partial repayment `x < backed`.

fn deep_underwater_account_still_liquidates_to_the_dust_gate() {
    let mut t = setup();
    t.supply(BOB, "ETH", 100.0);

    // Alice: $100k USDC collateral, 6 ETH = $12,000 debt.
    t.supply(ALICE, "USDC", 100_000.0);
    t.borrow(ALICE, "ETH", 6.0);
    let alice_id = t.resolve_account_id(ALICE);
    t.get_or_create_user(LIQUIDATOR);

    // Crash USDC 10x -> collateral $10,000 against $12,000 of debt.
    t.set_price("USDC", usd_cents(10));

    std::println!(
        "V3 A4-01b start: collateral_usd={:.2} debt_usd={:.2} hf={:.4} liquidatable={}",
        t.total_collateral(ALICE),
        t.total_debt(ALICE),
        t.health_factor(ALICE),
        t.can_be_liquidated(ALICE)
    );

    // The permissionless dust gate refuses an account of this size.
    assert_contract_error(
        t.try_clean_bad_debt_by_id(alice_id),
        errors::CANNOT_CLEAN_BAD_DEBT,
    );
    std::println!("V3 A4-01b clean_bad_debt at $10k collateral: REVERT (CannotCleanBadDebt)");

    let repay_usd = 0.5 * 2000.0;
    let mut steps = 0;
    for step in 1..=14 {
        if !t.account_exists(alice_id) {
            std::println!(
                "V3 A4-01b: account GONE at step {} — cleanup fired automatically",
                step
            );
            break;
        }
        let coll_before = t.total_collateral(ALICE);
        let liq_usdc_before = t.token_balance(LIQUIDATOR, "USDC");

        match t.try_liquidate(LIQUIDATOR, ALICE, "ETH", 0.5) {
            Ok(()) => {
                steps = step;
                let got_usd = (t.token_balance(LIQUIDATOR, "USDC") - liq_usdc_before) * 0.10;
                let coll_after = if t.account_exists(alice_id) {
                    t.total_collateral(ALICE)
                } else {
                    0.0
                };
                std::println!(
                    "V3 A4-01b step {:>2}: repaid ${:.0} -> seized ${:.2} \
                     (margin {:+.2}%)  collateral ${:.2} -> ${:.2}",
                    step,
                    repay_usd,
                    got_usd,
                    (got_usd - repay_usd) / repay_usd * 100.0,
                    coll_before,
                    coll_after
                );
            }
            Err(e) => {
                std::println!("V3 A4-01b step {:>2}: liquidate REVERTED {:?}", step, e);
                break;
            }
        }
    }

    std::println!(
        "V3 A4-01b end: account_exists={} after {} profitable partial liquidations",
        t.account_exists(alice_id),
        steps
    );
    assert!(
        steps >= 2,
        "partial liquidation must remain available below hf=0.80"
    );
```

pub(crate) fn build_liquidation_plan(
    env: &Env,
    account: &Account,
    raw_payments: &Vec<HubPayment>,
    cache: &mut Context,
) -> LiquidationPlan {
    if account.borrow_positions.is_empty() {
        panic_with_error!(env, CollateralError::HealthFactorTooHigh);
    }

    for (hub_asset, _) in raw_payments.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
    }

    let totals = risk::calculate_account_risk_totals(
        env,
        cache,
        &account.supply_positions,
        &account.borrow_positions,
    );
    assert_with_error!(
        env,
        totals.health_factor < Wad::ONE,
        CollateralError::HealthFactorTooHigh
    );
