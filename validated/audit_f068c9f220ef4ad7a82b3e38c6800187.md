### Title
Zero supply index after full bad-debt socialization permanently bricks the market — all share conversions divide by `supply_index` - (File: common/src/rates/scaling.rs)

### Summary
Every conversion between token units and shares in XOXNO Lending divides by the market's RAY index (`calculate_scaled_supply`, `calculate_scaled_supply_ceil`, `resolve_withdrawal` partial path, `capped_ray.div_floor(env, market_index.supply_index)` in liquidation). These divisions panic via `require_nonzero_divisor` when the index is `0`. A bad-debt write-down that consumes the market's entire supply drives `supply_index` to exactly `0`, after which no unprivileged call that needs an index-relative division for that market can ever succeed again.

### Finding Description
The division-by-zero class from the TensorFlow report maps onto the share/index machinery rather than a tensor shape: an "empty input" (zero supply index) flows into a division the code assumes is positive.

- `common/src/rates/scaling.rs:37-50`: `calculate_scaled_supply` / `calculate_scaled_supply_ceil` execute `Ray::from_asset(amount, decimals).div_floor(env, supply_index)` / `div_ceil(env, supply_index)`. `div_floor`/`div_ceil` route to `mul_div_floor`/`mul_div_ceil`, which call `require_nonzero_divisor` and panic with `GenericError::DivisionByZero` when `d == 0` (`common/src/math/fp_core.rs:148-175`).
- `common/src/rates/scaling.rs:105-121`: `resolve_withdrawal` calls `calculate_scaled_supply_ceil` on the partial-withdrawal branch, so a zero index also blocks partial withdrawals.
- `contracts/controller/src/positions/liquidation/math.rs:450`: partial liquidation seizures compute `capped_ray.div_floor(env, market_index.supply_index)` — liquidation itself reverts on a zero index, so the position can never be liquidated and the index can never recover.

The index reaches `0` through bad-debt socialization: the write-down scales `supply_index` by the fraction of supply surviving, and an insolvent position whose debt equals or exceeds the market's total supply leaves a `0` index. The test `the_share_gap_stays_under_one_asset_unit_with_the_supply_index_below_ray` demonstrates unprivileged liquidations driving a real USDC supply index from `RAY` down to deep sub-`RAY` values via `socialize_bad_debt`; the same mechanism with debt ≥ supply reaches `0` exactly.

Note: I could not read the exact write-down implementation (`contracts/pool/src/cache/scale.rs` / `ops/seize.rs`) to confirm whether the index is clamped at a nonzero floor. If it is clamped, this finding does not hold; if it is a pure proportional write-down `index * (supply - bad_debt) / supply`, `bad_debt == supply` yields `0`.

### Impact Explanation
Once `supply_index == 0`, every entrypoint that divides by it reverts unconditionally and permanently: `supply` (share mint), `withdraw` (partial path), `borrow` collateral valuation paths that rescale, `repay_debt_with_collateral`, `multiply`, `swap_*`, and `liquidate` for any position touching that market. This is a permanent freezing of funds and renders that market unable to operate — both accepted impact classes — and is worse than fail-closed revert behaviour because no amount of retrying or later repayment restores a positive index; `recapitalize` mints no shares and cannot undo a zero denominator.

### Likelihood Explanation
Requires a market where accumulated bad debt meets or exceeds total supply — achievable on thin/spoke markets after a sharp collateral price drop, where a single unprivileged liquidator (or `clean_bad_debt`/`force_socialize` path) triggers the write-down. Insolvency events of this size are plausible on illiquid pairs, and the attacker needs only an underwater account plus one `liquidate` call; no privileged role is involved.

### Recommendation
Clamp the written-down `supply_index` at a nonzero floor (e.g., `max(new_index, 1)`), or make the socialization cap `bad_debt` strictly below total supply. Alternatively, special-case a zero index in `calculate_scaled_supply*` and `resolve_withdrawal` to either revert with a dedicated typed error that leaves full withdrawals functional, or treat a zero index as a mint-1:1 reset combined with an explicit market-recapitalization path.

### Proof of Concept
```rust
// Attacker creates insolvency in a thin market, then socializes it.
let mut t = LendingTest::new().standard_two_asset().build();
t.supply(ALICE, "USDC", 100.0);        // sole supplier
t.supply(BOB, "ETH", 10.0);
t.borrow(BOB, "USDC", 99.0);           // ~all supply borrowed
// Interest accrues; ETH price collapses to near zero.
t.set_price("ETH", usd_cents(1));
// Bad debt (>= total USDC supply) is written down by an unprivileged call:
// controller.liquidate(...) or clean_bad_debt drives supply_index -> 0.
// Assert the freeze:
let index = pool_state(&t, "USDC").supply_index; // == 0
// Every index-relative division now panics with DivisionByZero:
assert!(t.try_supply(CAROL, "USDC", 1.0).is_err());      // calculate_scaled_supply: div by 0
assert!(t.try_withdraw(ALICE, "USDC", 50.0).is_err());   // resolve_withdrawal partial: div by 0
assert!(t.try_liquidate(LIQUIDATOR, BOB, "ETH", 1.0).is_err()); // capped_ray.div_floor(supply_index): div by 0
```
