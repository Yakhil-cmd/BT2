### Title
Unmeasured declared-amount repay refunds attacker-injected overpayment out of pool custody - (File: contracts/pool/src/ops/repay.rs)

### Summary
`pool::repay` trusts the declared `action.amount` as if tokens were already transferred in. When outstanding debt is zero (or less than `amount`), the excess is computed purely from the declared amount and refunded via `Cache::transfer_out` to an arbitrary `payer`, with no auth gate and no `require_reserves`/cash-book debit. A single unprivileged call to `repay` on a debt-free market therefore drains real token custody to the attacker — the on-chain analog of injecting unsanitized input into a query: the attacker-controlled amount is substituted into the debt-resolution "filter" and the resulting overpayment is paid out of other users' funds.

### Finding Description
In `contracts/pool/src/ops/repay.rs`:

- `apply` runs `accounting` and then unconditionally calls `outcome.cache.transfer_out(payer, outcome.overpayment)` (`repay.rs:30-33`).
- `accounting` resolves `overpayment = amount - current_debt` via `cache.resolve_repay(amount, position)` (`repay.rs:44`). With zero debt, `overpayment == amount`, `net_repay == 0`, and the `RepayRoundsToZeroShares` assert passes because `net_repay == 0` (`repay.rs:48-52`).
- The inbound transfer is only described in a comment ("The controller transfers the repay amount into the pool before this call", `repay.rs:3`); the pool never measures or verifies it. The refund leg debits neither `cash` nor passes `require_reserves` — it transfers straight from custody.
- The same pattern exists in `ops/recapitalize.rs:52-55` (`refund = amount - applied`), confirmed by `contracts/pool/tests/flows.rs:3589-3611` (`test_unfunded_repay_overpayment_refund_also_pays_out_of_custody`), which demonstrates a direct `repay` call with no inbound transfer paying the full declared amount out of pool custody, and `flows.rs:3488-3512` showing the only bound is the SAC transfer reverting above custody.

There is no caller authentication on this path: the test invokes `t.client().repay(&payer, …)` directly on the pool contract and succeeds.

### Impact Explanation
An attacker calls `pool.repay` on any listed market with no outstanding debt (or any market where declared `amount > debt`), passing `payer = attacker` and `amount` equal to the pool's entire token balance. The full balance is "refunded" to the attacker while the books are untouched (`credit_cash(0)`, no `cash` debit on the refund leg). This is direct theft of all supplier funds in that market — theft of user funds and protocol insolvency, satisfying the Critical/High acceptance criteria.

### Likelihood Explanation
Reachable by any unprivileged address in a single transaction: `repay(payer: attacker, action: PoolAction { hub_asset, amount: pool_balance, position: zero-debt })`. No collateral, position, or oracle condition is needed; the only prerequisite is a market whose outstanding debt is below the declared amount — trivially satisfiable by choosing `amount = custody` on an idle market, or `amount = debt + custody` otherwise. The cost is bounded by transaction fees; payout is bounded only by pool custody of that token.

### Recommendation
Gate all pool mutation entrypoints (or at minimum `repay` and `recapitalize`) to the controller address, and/or measure the inbound transfer on-chain: record `token.balance(pool)` before and after the caller's transfer (or use `transfer_amount_measured` inside the pool leg) and compute `overpayment`/`refund` from the *measured* received amount, not the declared `action.amount`. Additionally, debit `cash` (or pass `require_reserves`) for the refund leg so refunds can never exceed unbooked custody.

### Proof of Concept
As pinned by `contracts/pool/tests/flows.rs:3590-3611`:

```rust
// contracts/pool/tests/flows.rs — direct pool call, no controller, no inbound transfer
let custody_before = token.balance(&t.pool);
assert_eq!(before.borrowed, 0); // debt-free market

// Declare amount == full custody; nothing is transferred in.
let credited = t
    .client()
    .repay(&payer, &t.ract(0, custody_before)) // payer = attacker address
    .get_unchecked(0)
    .actual_amount;

assert_eq!(credited, 0);                                  // no debt retired
// assert_unfunded_refund_drained_custody: pool balance -> 0, attacker gains custody_before
```

`resolve_repay` returns `overpayment = amount` when `current_debt_ceil == 0`, `apply` calls `cache.transfer_out(payer, overpayment)` (`repay.rs:32`), and the SAC `transfer` executes from real pool custody because the refund path never checks `cash`/`require_reserves`. Repeat per market to drain each token's pool balance.
