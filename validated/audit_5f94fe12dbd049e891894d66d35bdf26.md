### Title
`kip71.gastarget` Governance Parameter Accepts Zero, Causing Division-by-Zero Panic in Block Validation — (`File: params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter has no non-zero format check, allowing the governing node to set it to `0`. When any subsequent block has non-zero gas usage, `NextMagmaBlockBaseFee` performs an integer division by `gasTarget` (which is now `0`), causing a Go runtime panic that crashes every node attempting to validate that block.

---

### Finding Description

`Kip71GasTarget` is registered in the governance parameter table with `noopFormatChecker`, meaning any `uint64` value — including `0` — passes validation and can be committed on-chain via a governance vote: [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` has an explicit non-zero guard in its `FormatChecker`: [2](#0-1) 

And `NextMagmaBlockBaseFee` also has a runtime fallback for `BaseFeeDenominator == 0`: [3](#0-2) 

No equivalent guard exists for `GasTarget`. When `gasTarget == 0` and `parentGasUsed > 0`, execution enters the `parentGasUsed > gasTarget` branch and reaches: [4](#0-3) 

`new(big.Int).SetUint64(0)` as the divisor causes `big.Int.Div` to panic with a runtime division-by-zero.

The consistency check in `checkConsistency` does not validate `Kip71GasTarget` beyond format: [5](#0-4) 

---

### Impact Explanation

`NextMagmaBlockBaseFee` is called from `VerifyMagmaHeader`, which is called from `validateHeader` in the block validator on every post-Magma block: [6](#0-5) 

A Go runtime panic in this path is unrecovered and crashes the node process. Once the governance change activates, every honest node that attempts to import any block with non-zero `GasUsed` will crash. This constitutes a **persistent chain halt / consensus divergence** on all honest nodes — an invalid block/state acceptance path is broken for the entire network.

---

### Likelihood Explanation

In `single` governance mode, the governing node can unilaterally submit a vote for `kip71.gastarget = 0`. The vote passes format checking (no-op), passes consistency checking (no check for this parameter), and takes effect after one epoch. Any block with at least one transaction then triggers the panic. The trigger is a single governance transaction from the governing node.

---

### Recommendation

Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`, mirroring the existing guard for `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0  // gasTarget is a divisor; zero causes panic
    },
    ...
}
```

Additionally, add a runtime guard in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator` guard:

```go
if gasTarget == 0 {
    // To avoid panic, treat as no-op (base fee unchanged)
    return makeEvenByFloor(parentBaseFee)
}
```

---

### Proof of Concept

1. Governing node submits a header governance vote: `kip71.gastarget = 0`.
2. Vote passes format check (`noopFormatChecker`) and consistency check (no check for this param).
3. After one epoch, the parameter activates.
4. Any block with `GasUsed > 0` is produced.
5. All nodes call `validateHeader` → `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`.
6. `parentGasUsed > 0 == gasTarget` → enters `parentGasUsed > gasTarget` branch.
7. `x.Div(x, new(big.Int).SetUint64(0))` → **Go runtime panic: integer divide by zero**.
8. Node process crashes. Chain halts on all honest nodes. [7](#0-6)
