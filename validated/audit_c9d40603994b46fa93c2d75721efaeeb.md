### Title
Pre-permissionless `verifySeals` uses council (not qualified) as signer set, allowing demoted validator seals to satisfy quorum — (`blockchain/block_validator.go`)

---

### Summary

In the pre-permissionless branch of `verifySeals`, the signer set used to count valid committed seals is unconditionally overwritten with the full **council** (which includes demoted validators), rather than the **qualified** set. Because the quorum threshold is computed from `qualifiedLen`, a demoted validator's seal counts toward quorum, allowing a block to pass seal validation with fewer qualified-validator signatures than the protocol requires.

---

### Finding Description

`verifySeals` in `blockchain/block_validator.go` has two branches: permissionless (line 250) and pre-permissionless (lines 285–317). In the pre-permissionless branch:

```go
signerSet := qualifiedSet.Copy()          // line 294 — dead code
if !rules.IsPermissionless {              // line 295 — always true here
    council, err := v.mValset.GetCouncil(blockNum)
    ...
    signerSet = valset.NewAddressSet(council).Copy()  // line 300 — overwrites qualified
}
validSeal, err := countValidCommittedSeals(committers, signerSet)  // line 302
```

Because execution only reaches line 294 when `rules.IsPermissionless` is already `false`, the condition `!rules.IsPermissionless` on line 295 is always `true`. The initial `qualifiedSet.Copy()` assignment is dead code; `signerSet` is always replaced with the full council. [1](#0-0) 

`countValidCommittedSeals` accepts any address present in `signerSet` (council), including demoted validators: [2](#0-1) 

The quorum threshold, however, is computed from `qualifiedLen` (the qualified set size), not the council size: [3](#0-2) 

Using `F` from `IstanbulSealer`: [4](#0-3) 

**Concrete arithmetic (4 qualified, 1 demoted):**

| Variable | Value |
|---|---|
| council | [A, B, C, D, E] |
| qualified | [A, B, C, D] (E demoted) |
| qualifiedLen | 4 |
| committeeSize | 4 |
| F(4,4) | ceil(4/3)−1 = 1 |
| quorum | 2×1+1 = **3** |
| committers | [A, B, **E**] |
| validSeal | **3** (A, B, E all in council) |
| result | **PASSES** (only 2 qualified signed) |

**Live consensus vs. verifySeals discrepancy:**

During live consensus, `handleCommit` enforces `c.current.committee.Contains(src)` — only committee members (a subset of qualified validators) can contribute commit messages: [5](#0-4) 

`verifySeals` uses the broader council, creating a gap: a block that would be rejected by live consensus can pass static header validation.

---

### Impact Explanation

A malicious qualified proposer can craft a block whose `CommittedSeals` field includes a seal from a demoted validator (E), replacing one required qualified-validator seal. E can produce a valid cryptographic committed seal independently (it holds its private key). The crafted block passes `verifySeals` and is accepted by any node importing it through the sync/downloader path. This constitutes **invalid block acceptance** — a block with fewer qualified-validator signatures than the protocol requires is treated as valid, enabling consensus divergence between live-consensus nodes and syncing nodes, and allowing the malicious proposer's block (and its state transitions, including reward distribution) to be canonicalized on syncing nodes.

---

### Likelihood Explanation

Requires one malicious qualified proposer and one cooperating demoted validator. A demoted validator has insufficient stake and a clear incentive to collude. This is not majority-validator collusion. The attack is executable through the standard P2P sync path without any privileged access.

---

### Recommendation

Replace the council-based signer set with the qualified set in the pre-permissionless branch. The `signerSet` should remain `qualifiedSet` (line 294) and the overwrite block (lines 295–301) should be removed. The quorum and the signer set must be drawn from the same population.

```go
// Correct: use qualifiedSet for both membership check and seal counting
signerSet := qualifiedSet.Copy()
// Remove the council-overwrite block entirely
validSeal, err := countValidCommittedSeals(committers, signerSet)
```

### Proof of Concept

Set up a pre-permissionless `BlockValidator` where:
- `council = [A, B, C, D]`, `qualified = [A, B, C]` (D is demoted)
- `qualifiedLen = 3`, `committeeSize = 3`
- `F(3,3) = ceil(3/3)−1 = 0`, `quorum = 1`
- `committers = [A, D]` (1 qualified + 1 demoted)

Call `verifySeals`. With `signerSet = council`, both A and D pass `Remove`, `validSeal = 2 ≥ 1`, and the function returns `nil` — even though only 1 qualified validator signed. For a larger network (qualifiedLen=4, quorum=3), use `committers = [A, B, E]` (2 qualified + 1 demoted) to demonstrate a block passing with only 2 of 4 required qualified signatures.

```go
func countValidCommittedSeals(committers []common.Address, signerSet *valset.AddressSet) (int, error) {
	validSeal := 0
	for _, addr := range committers {
		if !signerSet.Remove(addr) {
			return 0, istanbul.ErrInvalidCommittedSeals
		}
		validSeal++
	}
	return validSeal, nil
}
```

```go
func (m *IstanbulSealer) F(_ uint64, qualifiedLen, committeeSize int) int {
	if qualifiedLen > int(committeeSize) {
		return int(math.Ceil(float64(committeeSize)/3)) - 1
	}
	return int(math.Ceil(float64(qualifiedLen)/3)) - 1
}
```
