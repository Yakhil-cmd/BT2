### Title
Signature verification keyed on top-level `repository.owner.login` is not bound to the org that owns `repository.full_name`, allowing unsigned cross-org webhook forgery - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used to authenticate a webhook by reading `params.dig('repository', 'owner', 'login')`, but every downstream handler (e.g. `LabelCapturingHandler#repository`) resolves the target repository independently from `params.repository.full_name`. Because these two fields are both attacker-controlled in the same unsigned JSON body, an attacker can set `repository.owner.login` to an org whose `GitHubApp#webhook_secret` is `nil` (auto-verified per `GitHubApp#verify_webhook_signature`'s `return true unless webhook_secret`) while pointing `repository.full_name` at a different, secret-protected org's repository.

### Finding Description
The binding the system implicitly assumes is:
`organization whose webhook_secret verified the request bytes == organization owning params.repository.full_name used to mutate state`

This binding is broken. The verification path is: [1](#0-0) 
which resolves the app via `repository_owner`: [2](#0-1) 
and `GitHubApp#verify_webhook_signature` trivially passes when that resolved org has no configured secret: [3](#0-2) 

Once `verify_signature` passes (headers `head(422)` is only called on `unless verified`, but note it doesn't halt/return — this is a separate issue but not the one in scope), `WebhooksController#create` dispatches the raw JSON to all registered handlers: [4](#0-3) 
For `pull_request` events, `LabelCapturingHandler` is one of the dispatched handlers: [5](#0-4) 

`LabelCapturingHandler#repository` resolves the target repository purely from `params.repository.full_name`, with no cross-check against `repository.owner.login` or the organization that authenticated the request: [6](#0-5) 
`Repository.from_github_repo_name` simply parses the owner/name out of that string and does a DB lookup with no further validation: [7](#0-6) 

Attacker's exact request: a `pull_request` webhook (`X-Github-Event: pull_request`, action `labeled`) with body:
```json
{
  "action": "labeled",
  "number": 1,
  "pull_request": { ...valid schema..., "labels": [{"name": "attacker-label"}] },
  "repository": { "owner": { "login": "no-secret-org" }, "full_name": "protected-org/protected-repo" },
  "sender": { "login": "attacker" }
}
```
No `X-Hub-Signature` header is required (or it can be anything, since `webhook_secret` is nil for `no-secret-org`). `verify_signature` calls `Shipit.github(organization: 'no-secret-org')`, gets a `GitHubApp` with `webhook_secret` nil, and `verify_webhook_signature` returns `true` unconditionally. `create` then dispatches to `LabelCapturingHandler`, whose `repository` method resolves `protected-org/protected-repo` from the DB and `capture_labels` calls `pull_request.update!(labels: ...)` on that stack's `PullRequest`, mutating state for a repository under a completely different, secret-protected organization that never authenticated this request.

Existing guards do not stop this: `drop_unhandled_event` only checks event type presence, `verify_signature` only checks the org derived from `owner.login` (which the attacker fully controls and deliberately mismatches from `full_name`), and `ExplicitParameters` schema validation (`params do ... end` in the handler) only validates types/presence, not cross-field consistency between `repository.owner.login` and `repository.full_name`. There is no check anywhere that `repository.full_name`'s owner segment matches `repository.owner.login`.

### Impact Explanation
An unprivileged attacker who merely knows (a) the name of any org configured in Shipit with no `webhook_secret` (or can otherwise get a request accepted, e.g. a misconfigured org) and (b) the `owner/name` of a target repository under a *different*, secret-protected org, can forge unsigned webhook payloads that mutate that target repository's stacks — specifically overwriting `PullRequest#labels` via `LabelCapturingHandler#capture_labels`, and (per the sibling `LabeledHandler`/`UnlabeledHandler` which share the identical `repository` resolution pattern) archiving/unarchiving/deprovisioning review stacks. This is a payload for one (weakly-configured) organization mutating another (fully-secured) organization's stack/PR state — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." It is fully repeatable against any repository whose `owner/name` the attacker knows, with no rate limiting on the attacker's side, and requires no session, token, or repository permission on the target repo/org.

### Likelihood Explanation
Preconditions: Shipit must be configured in multi-org mode (`github_organizations`) with at least one organization lacking `webhook_secret` (shown to be a documented supported configuration in `config/secrets.development.example.yml` and `test/dummy/config/secrets_double_github_app.yml`, e.g. `OrgTwo: webhook_secret: # nil`). The attacker does not need any relationship to the target org/repo — only knowledge of its `owner/name` string, which is typically public. The attack is a single unauthenticated HTTP POST to `/webhooks`; cost is trivial and fully repeatable/scriptable against arbitrary repositories in the same Shipit instance.

### Recommendation
Bind signature verification to the organization that actually owns the resolved target resource, not an attacker-controlled top-level field used only for key selection. Concretely: after resolving `repository.full_name` in each handler (or centrally before dispatch), verify that `repository.owner.login` (or its downcased form) matches the owner segment of `repository.full_name`, and reject (422) on mismatch, before any handler mutates state. Additionally, consider disallowing/warning on `webhook_secret: nil` configurations in any organization that is not the sole configured organization, since it turns that org into an authentication bypass vector for the whole instance.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "cross-org spoofing: unsigned webhook from no-secret org mutates protected org's stack" do
  protected_repo = shipit_repositories(:shipit) # owner "shopify", secret-protected in secrets
  stack = create_review_stack_for(protected_repo) # some existing PR/stack fixture

  # Confirm binding assumption BEFORE exploit:
  # authenticating_org (from repository.owner.login) == owning_org (from repository.full_name.split('/').first)
  # should always hold for legitimate traffic.

  payload = payload_parsed(:pull_request_labeled)
  payload["repository"]["owner"]["login"] = "no-secret-org"   # org with webhook_secret == nil
  payload["repository"]["full_name"] = protected_repo.full_name # "shopify/shipit-engine"
  payload["pull_request"]["labels"] = [{ "name" => "attacker-injected" }]

  Shipit.github(organization: "no-secret-org").stubs(:webhook_secret).returns(nil)

  @request.headers['X-Github-Event'] = 'pull_request'
  # No valid X-Hub-Signature for "shopify" is sent/needed

  post :create, body: payload.to_json, as: :json

  assert_response :ok
  assert_includes stack.reload.pull_request.labels, "attacker-injected"
  # Assert the two sides of the binding diverged:
  authenticating_org = payload["repository"]["owner"]["login"]        # "no-secret-org"
  owning_org         = payload["repository"]["full_name"].split("/").first # "shopify"
  assert_not_equal authenticating_org, owning_org
end
```
This demonstrates that `authenticating_org` (whose lack of secret caused auto-verification) diverges from `owning_org` (whose repository/stack was actually mutated), confirming the broken binding with no live GitHub access required.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
