### Title
Nested groups/escaped metacharacters bypass `_has_redos_structure`, letting overlapping-alternation ReDoS regexes into `security-patterns.yaml` compile and run on every file edit - (File: plugins/security-guidance/hooks/extensibility.py)

### Summary
`_has_redos_structure` uses character classes `[^()]*` in both `_REDOS_SHAPES` and `_ALT_UNDER_REP` to scan for catastrophic-backtracking shapes, but these classes forbid *any* literal `(`/`)` character inside a branch — including ones introduced by nested capturing groups or backslash-escaped metacharacters (`\(`, `\)`). A regex whose overlapping alternation is wrapped in nested groups (e.g. `((a)|(aa))+`) or contains escaped parens never matches either detector pattern at all, so `_validate_pattern` accepts it, `re.compile` succeeds, and the rule is stored and later executed via `re.search` in the PostToolUse hook on every file write.

### Finding Description
`_validate_pattern` (plugins/security-guidance/hooks/extensibility.py:199-244) calls `_has_redos_structure(regex)` before accepting a user-supplied `regex` field from `security-patterns.yaml`/`.json`/`.local.*` files loaded by `_load_user_patterns` (line 147). `_has_redos_structure` (line 272-289) relies on:

- `_REDOS_SHAPES[0] = r"\([^()]*[+*][^()]*\)[+*?]"`
- `_ALT_UNDER_REP = r"\(([^()]*)\|([^()|]*)(?:\|[^()]*)*\)[+*]"`

Both patterns require the content between the outer `(` and `)` to consist entirely of non-parenthesis characters (`[^()]*`). Any additional literal `(`/`)` inside the group — whether from a genuinely nested sub-group (`((a)|(aa))+`) or from an escaped metacharacter that still contains a raw `(`/`)` byte in the string (`\(`, `\)`) — prevents `[^()]*` from spanning the branch, so the whole pre-compiled `_REDOS_SHAPES`/`_ALT_UNDER_REP` fails to match anywhere in the string. The function therefore returns `False` even though the regex contains the exact overlapping-alternation-under-repetition shape the heuristic is meant to catch (`(a|aa)+`-equivalent structure, semantically identical once wrapped: `((a)|(aa))+`).

Because `_has_redos_structure` returns `False`, `re.compile(regex)` (line 229) succeeds (it's syntactically valid), and the rule is appended to `_user_patterns`, which is consumed by the PostToolUse pattern checker (`security_reminder_hook.py`) and run with `re.search` against file content on every subsequent edit in the session — reintroducing classic catastrophic backtracking (ambiguous decomposition of a run of `a`s across two overlapping branches) against a Python `re` engine that does exponential backtracking on non-matching input.

### Impact Explanation
An attacker who controls `.claude/security-patterns.yaml` in a repository (or a project-local file) can smuggle in a ReDoS regex that the built-in filter is specifically designed to reject, since the filter's blind spot is deterministic and repo-content-controlled. Once loaded, the rule is checked with `re.search` on every file edited in the session (PostToolUse hook), so any file whose content triggers catastrophic backtracking (e.g. a long run of `a` characters followed by a non-matching character) hangs the hook process — a hook-wide denial of service affecting every subsequent file write/edit in the session, matching a DoS/availability impact class.

### Likelihood Explanation
Precondition is only that the attacker can add or influence `.claude/security-patterns.yaml` (or the `.local` variant) in a repository that the victim opens with Claude Code — no elevated privileges, no social engineering beyond typical malicious-PR/repo-content delivery. The bypass requires no fuzzing sophistication beyond wrapping an already-known bad alternation pair in a redundant capturing group, e.g. `((a)|(aa))+`, or escaping literal parens in the branch text — both trivially constructible, deterministic, and 100% repeatable since the flaw is in the static structure of the detection regex itself, not in randomness.

### Recommendation
Replace the flat single-level regex heuristics with a real regex-structure walker that recursively normalizes/strips backslash-escaped characters (treating `\(`, `\)`, `\\` etc. as opaque literal tokens, not paren-class members) and recurses into nested groups before applying the prefix/overlap check to each group's alternation, or fall back to a real ReDoS detection library (e.g. running the candidate regex against adversarial worst-case inputs with a timeout, or using a proper regex AST via `sre_parse`/`re._parser` to detect nested quantified alternation with overlapping prefixes at any nesting depth). At minimum, additionally enforce a hard execution-time budget when the rule is actually run in `check_patterns()` (e.g., via a signal/thread-based timeout around `re.search`) so a missed static detection cannot become an unbounded hang — defense in depth rather than relying solely on the static heuristic.

### Proof of Concept
```python
import re
from plugins.security_guidance.hooks import extensibility as ext

# 1. Structural bypass via nested groups (semantically identical to (a|aa)+)
bypass_nested = r"((a)|(aa))+$"
assert ext._has_redos_structure(bypass_nested) is False  # heuristic misses it

# 2. Confirm catastrophic backtracking actually occurs
pattern = re.compile(bypass_nested)
evil_input = "a" * 30 + "!"   # non-matching tail forces exhaustive backtracking
import time
start = time.time()
pattern.search(evil_input)
elapsed = time.time() - start
assert elapsed > 5  # demonstrates exponential blowup vs. milliseconds for safe patterns

# 3. End-to-end: entry passes _validate_pattern and would be stored as a rule
entry = {"rule_name": "evil", "reminder": "x", "regex": bypass_nested}
rule = ext._validate_pattern(entry, source="Project")
assert rule is not None and rule.get("regex") == bypass_nested
```
Differential fuzz test plan: generate randomized regex strings of the shape `((<branch1>)|(<branch2>))[+*]` and `(\(<literal>\)|\(<literal2>\)...)[+*]` where one branch is a prefix of the other, run each through `_has_redos_structure` and independently measure `re.search` wall-clock time on crafted non-matching inputs with a timeout; flag any case where `_has_redos_structure` returns `False` but measured time exceeds a threshold (e.g., >1s) — this reliably reproduces the nested-group and escaped-metacharacter false negatives described above.
