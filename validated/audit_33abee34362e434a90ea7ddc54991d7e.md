### Title
Silent CLStakingInfo Overwrite in `consolidateNodes()` Causes Incorrect Prague-Era Reward Distribution — (File: `kaiax/staking/staking_info.go`)

---

### Summary

In `consolidateNodes()`, when two NodeIds sharing the same `RewardAddr` both have `CLStakingInfo` entries returned by the CLRegistry, the second entry silently overwrites the first via a bare assignment (`cmap[r].CLStakingInfo = clsi`). The first CL pool's staking amount is permanently dropped from all downstream reward calculations in `assignStakingRewards()` and `assignStakingRewardsFlex()`, causing incorrect KAIA reward distribution every block after the Prague hardfork.

---

### Finding Description

`consolidateNodes()` in `kaiax/staking/staking_info.go` merges AddressBook entries that share a `RewardAddr` into a single `consolidatedNode`. It then attaches `CLStakingInfo` entries from the CLRegistry using the `CLNodeId → RewardAddr` mapping:

```go
for _, clsi := range si.CLStakingInfos {
    if r, ok := nToR[clsi.CLNodeId]; ok {
        // One CLStakingInfo per validator is guaranteed by CLRegistry.
        cmap[r].CLStakingInfo = clsi   // bare overwrite
    }
}
``` [1](#0-0) 

The comment's guarantee — "One CLStakingInfo per validator is guaranteed by CLRegistry" — is scoped to CLNodeId uniqueness, not to `(CLNodeId, RewardAddr)` uniqueness. The CLRegistry has no knowledge of AddressBook `RewardAddr` groupings and cannot enforce that two distinct NodeIds sharing the same `RewardAddr` do not each register a CL entry.

The AddressBook explicitly supports multiple NodeIds per `RewardAddr` (the entire purpose of `consolidateNodes()`):

```go
// NodeIds          = [N1, N2, N3]
// RewardAddrs      = [R1, R1, R3]
// → consolidated into CN1 = {[N1,N2], R1, A1+A2}
``` [2](#0-1) 

The test suite itself acknowledges the overwrite scenario with the comment **"not feasible in real"**, but provides no enforcement:

```go
// CL1 will be ignored when being consolidated since it has duplicate CL (not feasible in real)
{CLNodeId: n3, CLPoolAddr: clPool2, CLStakingAmount: clStakingAmount2},
``` [3](#0-2) 

When the overwrite occurs, the surviving `CLStakingInfo` is the last one processed (iteration order of `si.CLStakingInfos`). The first CL pool's address and staking amount are completely erased from the consolidated node.

---

### Impact Explanation

Both Prague-era reward functions consume the corrupted `consolidatedNode`:

**`assignStakingRewards()`** (Kore path, Prague-enabled):

```go
cnTotalStakingAmount := cn.StakingAmount
if isPrague && cn.CLStakingInfo != nil {
    cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount  // only A3, not A1+A3
}
totalExcessInt += cnTotalStakingAmount - minStake
``` [4](#0-3) 

```go
cnAmount, clAmount := cn.Split(reward)
alloc[cn.RewardAddr] = cnAmount
alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount  // P1 receives nothing; P3 receives wrong amount
``` [5](#0-4) 

**`assignStakingRewardsFlex()`** (Osaka/flex path) has the identical pattern: [6](#0-5) 

**Exact corrupted values** for a consolidated node with CN staking `S`, CL1 amount `A1` (dropped), CL2 amount `A3` (kept):

| Value | Correct | Actual |
|---|---|---|
| Total staking used for share calculation | `S + A1 + A3` | `S + A3` |
| CL pool P1 reward | `A1 × reward / (S+A1+A3)` | **0** |
| CL pool P3 reward | `A3 × reward / (S+A1+A3)` | `A3 × reward / (S+A3)` (inflated) |
| CN reward addr reward | `S × reward / (S+A1+A3)` | `S × reward / (S+A3)` (inflated) |
| Remainder to proposer | correct | **increased by lost A1 share** |

The `Split()` function uses `cn.StakingAmount` and `cn.CLStakingInfo.CLStakingAmount` directly: [7](#0-6) 

The lost `A1` share is subtracted from `remaining` (line 529) but never placed in `alloc`, so it silently flows to the proposer as unaccounted remainder — an unauthorized reward transfer from CL pool P1 to the block proposer every block.

---

### Likelihood Explanation

The trigger requires two conditions that are both individually supported by the protocol:

1. **Multiple NodeIds per RewardAddr** — explicitly supported and tested by AddressBook consolidation.
2. **Each NodeId registers a CL entry** — each NodeId is independently eligible to register in the CLRegistry.

The CLRegistry contract (`contracts/testing/reward/CLRegistryMock.sol`) returns raw arrays with no cross-reference to AddressBook `RewardAddr` groupings: [8](#0-7) 

Neither `parseCallResult()` nor `parsePermissionlessCallResult()` validates that CLNodeIds belonging to the same consolidated node are unique: [9](#0-8) 

The assumption is documented as "not feasible in real" but is not enforced anywhere in the production code path. Any validator operating multiple NodeIds under one `RewardAddr` who registers CL entries for more than one of those NodeIds will silently trigger this bug every block.

---

### Recommendation

1. **Detect and reject duplicate CL entries per consolidated node** in `consolidateNodes()`:

```go
for _, clsi := range si.CLStakingInfos {
    if r, ok := nToR[clsi.CLNodeId]; ok {
        if cmap[r].CLStakingInfo != nil {
            // Log error: duplicate CLStakingInfo for consolidated node r; skip
            continue
        }
        cmap[r].CLStakingInfo = clsi
    }
}
```

2. **Alternatively, accumulate CL amounts** across all CLStakingInfos that map to the same consolidated node, summing `CLStakingAmount` and tracking all `CLPoolAddr` entries, so no CL pool is silently dropped.

3. **Add a validation step** in `parseCallResult()` / `parsePermissionlessCallResult()` that checks for CLNodeIds belonging to the same AddressBook `RewardAddr` group and rejects or warns on such configurations.

---

### Proof of Concept

**Setup (Prague hardfork active):**

- AddressBook: `NodeIds=[N1, N3]`, `RewardAddrs=[R1, R1]`, `StakingAmounts=[10M, 10M]`
- CLRegistry: `{CLNodeId=N1, CLPoolAddr=P1, CLStakingAmount=5M}`, `{CLNodeId=N3, CLPoolAddr=P3, CLStakingAmount=5M}`

**In `consolidateNodes()`:**

- Consolidated node for R1: `{NodeIds=[N1,N3], StakingAmount=20M}`
- Processing CL for N1: `cmap[R1].CLStakingInfo = {N1, P1, 5M}`
- Processing CL for N3: `cmap[R1].CLStakingInfo = {N3, P3, 5M}` ← **overwrites P1**

**In `assignStakingRewards()` with `stakersReward = 1 KAIA`, `minStake = 5M`:**

- `cnTotalStakingAmount = 20M + 5M = 25M` (should be `20M + 5M + 5M = 30M`)
- `Split(1 KAIA)` with `cnAmount=20M, clAmount=5M, total=25M`:
  - `clAmount = 5M/25M × 1 KAIA = 0.2 KAIA` → sent to **P3**
  - `cnAmount = 0.8 KAIA` → sent to **R1**
  - **P1 receives 0 KAIA** (should receive `5M/30M × 1 KAIA ≈ 0.167 KAIA`)

The `0.167 KAIA` that should have gone to P1 instead flows to the proposer as remainder — a per-block unauthorized reward transfer from CL pool P1 to the block proposer, active every block after Prague hardfork for any validator in this configuration. [10](#0-9) [11](#0-10)

// Sometimes a node would register multiple NodeIds in AddressBook,

func (si *StakingInfo) consolidateNodes() *[]consolidatedNode {
	// because Go map is not ordered, rList keeps track of the occurrence order of RewardAddrs.
	// to later arrange the consolidatedNodes.
	cmap := make(map[common.Address]*consolidatedNode)
	rList := make([]common.Address, 0, len(si.RewardAddrs))
	nToR := make(map[common.Address]common.Address)

	for i, n := range si.NodeIds {
		r := si.RewardAddrs[i]
		// Unique nodeId is guaranteed by AddressBook.
		nToR[n] = r
		if cn, ok := cmap[r]; ok {
			cn.NodeIds = append(cn.NodeIds, n)
			cn.StakingContracts = append(cn.StakingContracts, si.StakingContracts[i])
			cn.StakingAmount += si.StakingAmounts[i]
		} else {
			cmap[r] = &consolidatedNode{
				NodeIds:          []common.Address{n},
				StakingContracts: []common.Address{si.StakingContracts[i]},
				RewardAddr:       r,
				StakingAmount:    si.StakingAmounts[i],
			}
			rList = append(rList, r)
		}
	}

	// CLStakingInfo can only exist after Prague HF.
	if len(si.CLStakingInfos) > 0 {
		for _, clsi := range si.CLStakingInfos {
			// If the nodeId of CLStakingInfo is not found in nToR, it means the validator is not in the AddressBook.
			// So we skip it.
			if r, ok := nToR[clsi.CLNodeId]; ok {
				// One CLStakingInfo per validator is guaranteed by CLRegistry.
				cmap[r].CLStakingInfo = clsi
			}
		}
	}

	carr := make([]consolidatedNode, 0, len(cmap))
	for _, r := range rList {
		carr = append(carr, *cmap[r])
	}
	return &carr
}

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
