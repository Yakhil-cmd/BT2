### Title
RAY value overflow during interest accrual permanently freezes an entire market - (File: contracts/pool/src/interest.rs)

### Summary
Every pool mutation loads the market through `synced_market`, which calls `interest::global_sync` before the requested operation is processed. During accrual, utilization is calculated from `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`, so a sufficiently large scaled balance can overflow `i128` even while the borrow index itself remains below `MAX_BORROW_INDEX_RAY`. Once that happens, every later accrual—including `withdraw`, `repay`, `borrow`, `liquidate`, and `update_indexes`—reverts before `last_timestamp` is committed, permanently locking the market.

### Finding Description
`Cache::load` stores raw scaled share totals and indexes separately, but `Cache::calculate_utilization` multiplies each scaled total by its index to reconstruct total RAY value. [1](#0-0)  Accrual then requests these values for every nonzero elapsed-time chunk. [2](#0-1) 

The index cap is applied only to `old_index * interest_factor`; it does not guarantee that `borrowed * borrow_index` or `supplied * supply_index` remains representable. [3](#0-2)  All mutating pool batches call `synced_market` first, and `update_indexes` independently calls `global_sync` for every requested market. [4](#0-3) [5](#0-4) 

The repository’s own regression test demonstrates the reachable failure: an 18-decimal market holding a billion whole tokens and approximately 98% utilization eventually reaches a point where the next accrual raises `MathOverflow` inside `scaled_to_original`, while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

### Impact Explanation
This causes permanent freezing of all funds in the affected market. After the first overflowing accrual attempt reverts, `mark_accrued` is never reached and `last_timestamp` remains behind the ledger; every subsequent withdrawal, repayment, liquidation, settlement, revenue claim, or index update repeats the same overflowing accrual before it can touch the requested position. [7](#0-6)  Consequently, suppliers cannot withdraw and borrowers cannot repay, while collateral in other markets can continue falling in value without liquidation of this market’s debt leg. [8](#0-7) 

### Likelihood Explanation
Likelihood is medium because exploitation requires a very large, highly utilized market and sustained interest accrual rather than a single ordinary amount. Nevertheless, the state is reachable through normal permissionless `supply` and `borrow` flows and passive ledger time; after creation, any unprivileged caller can trigger the freeze with `update_indexes`, and `clean_bad_debt`, liquidation, withdrawal, or repayment cannot bypass accrual. The regression fixture confirms that the overflow occurs before the protocol’s borrow-index ceiling protects it. [9](#0-8) 

### Recommendation
Enforce a market-level representable RAY-value ceiling before minting supply or debt shares, instead of only bounding the indexes. In particular:

- Check `calculate_scaled_supply` and `calculate_scaled_borrow` against `i128::MAX / MAX_INDEX` or equivalent share caps derived from each configured asset cap.
- Reject admissions whose `scaled_amount * index` cannot remain representable at the maximum future index.
- Alternatively, make accrual use saturating or widened value arithmetic for utilization and preserve a reachable repayment/withdrawal path.
- Add a release-mode regression test proving `withdraw`, `repay`, `liquidate`, and `update_indexes` remain callable after the largest admitted market reaches `MAX_BORROW_INDEX_RAY`.

### Proof of Concept
1. Configure or select an 18-decimal market with caps large enough to admit one billion whole tokens and no effective maximum-utilization rejection.
2. Call controller `supply` to deposit approximately `1_000_000_000e18` base units.
3. Supply collateral in another market and call controller `borrow` to take approximately 98% of the market as debt.
4. Wait through repeated annual accrual periods at high utilization.
5. Call permissionless controller `update_indexes` for the debt market.
6. `global_sync` reaches `calculate_utilization`; `scaled_to_original(borrowed, borrow_index)` overflows `i128` and returns `MathOverflow` before the capped borrow-index branch becomes relevant.
7. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` calls all accrue first and hit the same panic, leaving market cash and positions inaccessible. [10](#0-9)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
