### Title
Deregistered Bridge Operator's Stale Votes Are Never Revoked, Enabling Unauthorized Bridge Asset Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator()` removes an operator from the active set but does not clear that operator's existing votes from the `votes` mapping. A deregistered (potentially compromised) operator's vote persists and can still contribute to reaching the threshold for executing a bridge value transfer (KLAY, ERC20, ERC721) or configuration change. This is the direct Kaia analog of the Visor H-02 bug class: a permission/approval that is granted but can never be revoked.

### Finding Description

In `contracts/service_chain/bridge/BridgeOperator.sol`, the `VotesData` struct stores per-nonce votes in a private mapping: [1](#0-0) 

When an operator votes via `_voteCommon()`, their vote is recorded in `votes[voteType][nonce].voted[msg.sender]` and the corresponding `voteCounts` is incremented: [2](#0-1) 

When `deregisterOperator()` is called, it only removes the operator from `operators` and `operatorList`. It does **not** touch the `votes` mapping — the operator's recorded vote and its contribution to `voteCounts` remain intact: [3](#0-2) 

The code itself acknowledges this in a comment at lines 148–158, noting that "outstanding votes by the deregistered operator are not revoked" and that the owner "shall recognize this issue." However, there is no mechanism to revoke the stale vote — the owner cannot clear it.

`_voteValueTransfer()` checks only `closedValueTransferVotes[_requestNonce]` and the `onlyOperators` modifier on the *caller* of the handle function, not on the historical voters: [4](#0-3) 

So when a second legitimate operator votes on the same nonce, `voteCounts` reaches the threshold using the deregistered operator's stale vote, and the transfer executes: [5](#0-4) 

The same path applies to `handleERC20Transfer` and `handleERC721Transfer`: [6](#0-5) [7](#0-6) 

### Impact Explanation

A deregistered operator's vote can satisfy part of the multi-sig threshold for a bridge value transfer. If the operator was deregistered because their keys were compromised, the attacker controlling those keys has already cast a vote. When any remaining legitimate operator votes on the same nonce (e.g., during normal bridge operation), the transfer executes — with the compromised operator's vote counting. This results in **unauthorized transfer of KAIA, ERC20, or ERC721 bridged assets** to an attacker-controlled address.

### Likelihood Explanation

The scenario requires:
1. A threshold ≥ 2 (non-default but common in production multi-operator setups).
2. A compromised operator to have voted on a pending nonce before being deregistered.
3. A legitimate operator to subsequently vote on the same nonce.

Step 3 is routine bridge operation. The window between an operator being compromised and the owner detecting and deregistering them is realistic. The code comment explicitly acknowledges this scenario occurs.

### Recommendation

In `deregisterOperator()`, iterate over all pending nonces and clear the deregistered operator's vote from `votes[voteType][nonce].voted[operator]` and decrement the corresponding `voteCounts`. Alternatively, add a dedicated `revokeVote(address operator, uint8 voteType, uint64 nonce)` function callable by the owner to explicitly nullify a specific operator's vote before deregistration takes effect.

### Proof of Concept

Setup: threshold = 2, operators = {Owner, A, B}.

1. Operator A calls `handleKLAYTransfer(txHash, from, to, value, nonce=5, ...)` → `_voteCommon` records `votes[ValueTransfer][5].voted[A] = voteKey` and `voteCounts[voteKey] = 1`. Threshold not reached; transfer does not execute.
2. Owner discovers A's keys are compromised and calls `deregisterOperator(A)`. `operators[A]` is deleted, but `votes[ValueTransfer][5].voted[A]` and `voteCounts[voteKey] = 1` remain.
3. Operator B (legitimate) calls `handleKLAYTransfer(txHash, from, to, value, nonce=5, ...)` with the same arguments → same `voteKey = keccak256(msg.data)`. `voteCounts[voteKey]` becomes 2 ≥ threshold. `closedValueTransferVotes[5] = true`. Transfer executes, sending `value` KAIA to `to` — authorized in part by the compromised operator A's stale vote. [3](#0-2)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // deregisterOperator deregisters the operator.
    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
