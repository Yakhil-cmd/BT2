### Title
Issue/PR title, body, and assignee names are printed to the terminal without ANSI/control-sequence sanitization - ([File: pkg/cmd/issue/view/view.go])

### Summary
`printRawIssuePreview` and `printHumanIssuePreview` in `pkg/cmd/issue/view/view.go` write `issue.Title`, `issue.Body`, and assignee display names (via `issueAssigneeList`) directly to the terminal with plain `fmt.Fprintf`/`fmt.Fprintln`, without passing them through the repo's own `iostreams.Untrusted` sanitizer. This lets any GitHub user who can open an issue/PR or be assigned to one embed terminal escape sequences (CSI/OSC/DCS) that get rendered raw when a maintainer runs `gh issue view`.

### Finding Description
The repository has a dedicated `iostreams.Untrusted` type [1](#0-0)  whose `String()` method strips ANSI/control sequences via `asciisanitizer`, explicitly intended for "HTTP response bodies... anything that originates outside the CLI." It is used, for example, in `pkg/cmd/gist/view/view.go`. However, `pkg/cmd/issue/view/view.go` does not use this wrapper anywhere for issue content.

In `printRawIssuePreview`, `issue.Title` and `issue.Body` (attacker-controlled fields from the GraphQL API response) are printed with raw `fmt.Fprintf`/`fmt.Fprintln`: [2](#0-1) [3](#0-2) 

In `printHumanIssuePreview`, the title is also printed raw at the top of the human-readable view: [4](#0-3) 

`issueAssigneeList` builds the assignee list from `assignee.DisplayName()` (a GitHub display name, which some GitHub Enterprise/legacy account settings allow to contain arbitrary user-supplied strings) and joins them with no sanitization before they are printed: [5](#0-4) [6](#0-5) 

The body in the human view does pass through `markdown.Render`, but that is a Markdown renderer, not an ANSI/control-sequence sanitizer, and does not neutralize raw CSI/OSC/DCS byte sequences embedded in the text: [7](#0-6) . The raw (non-TTY/plumbing) path in `printRawIssuePreview` performs no processing on the body at all.

Because none of `issue.Title`, `issue.Body`, or assignee display names are wrapped in `iostreams.Untrusted` before being handed to `fmt.Fprintf`/`fmt.Fprintln`, an attacker who authors an issue/PR title or body (or who is assignable/DisplayName-controllable) can smuggle terminal escape sequences straight to the victim's terminal when they run `gh issue view`.

### Impact Explanation
An attacker-controlled issue/PR title or body can contain terminal escape sequences (e.g., OSC 8 hyperlink spoofing, cursor-repositioning/overwrite sequences, or terminal title/clipboard manipulation depending on emulator) that get emitted verbatim to the victim's terminal. This can be used for terminal output/prompt spoofing — for example, obscuring the true content, faking a prompt, or manipulating what the victim believes they are confirming — matching the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class described in the question.

### Likelihood Explanation
Any unprivileged GitHub user can open an issue or PR (or comment) on a repository with a title/body of their choosing; no special privileges are needed. The maintainer only needs to run the ordinary `gh issue view <number>` command. This is fully repeatable and does not depend on any race condition or unusual configuration.

### Recommendation
Wrap `issue.Title`, `issue.Body`, and any user-supplied display strings (assignee names, comment bodies, etc.) in `iostreams.Untrusted` before printing, mirroring the pattern already used in `pkg/cmd/gist/view/view.go`, so that `fmt.Fprintf`/`fmt.Fprintln` automatically sanitize them via `Untrusted.String()`.

### Proof of Concept
Go test sketch for `pkg/cmd/issue/view/view_test.go`:
```go
func TestPrintRawIssuePreview_StripsEscapeSequences(t *testing.T) {
    issue := &api.Issue{
        Title: "Evil\x1b]0;pwned\x07 Title",
        Body:  "Body with \x1b[31mCSI\x1b[0m and \x1b]8;;http://evil\x07OSC\x1b]8;;\x07 payload",
    }
    out := &bytes.Buffer{}
    err := printRawIssuePreview(out, issue)
    require.NoError(t, err)
    output := out.String()
    require.NotContains(t, output, "\x1b]0;")
    require.NotContains(t, output, "\x1b[31m")
    require.NotContains(t, output, "\x1b]8;;")
}
```
This test currently fails because the raw escape sequences pass through unmodified, confirming the finding.

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}

func issueAssigneeList(issue api.Issue) string {
	if len(issue.Assignees.Nodes) == 0 {
		return ""
	}

	AssigneeNames := make([]string, 0, len(issue.Assignees.Nodes))
	for _, assignee := range issue.Assignees.Nodes {
		AssigneeNames = append(AssigneeNames, assignee.DisplayName())
	}

	list := strings.Join(AssigneeNames, ", ")
	if issue.Assignees.TotalCount > len(issue.Assignees.Nodes) {
		list += ", …"
	}
	return list
}
