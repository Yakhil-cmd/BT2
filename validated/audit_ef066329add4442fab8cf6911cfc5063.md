### Title
Silent Error Swallow in `fillAllocated` Causes Unauthorized KAIA Burn During Treasury Rebalancing — (`blockchain/system/rebalance.go`)

---

### Summary

In `blockchain/system/rebalance.go`, the `fillAllocated` helper returns `nil` (success) instead of the actual error when `contract.GetAllocatedCount` fails. This causes `RebalanceTreasury` to silently proceed with an empty allocation map at the KIP-103 or KIP-160 fork block, zeroing all designated treasury accounts while distributing nothing to the intended recipients — effectively burning the entire rebalanced KAIA supply.

---

### Finding Description

`RebalanceTreasury` builds its allocation plan in two steps: `fillZeroed` (accounts to drain) and `fillAllocated` (accounts to fund). The two helpers are structurally symmetric, but their error paths diverge:

**`fillZeroed` — correct:**
```go
numRetiredBigInt, err := contract.GetZeroedCount(nil)
if err != nil {
    logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
    return err   // propagates the error
}
```

**`fillAllocated` — buggy (line 219):**
```go
numNewbieBigInt, err := contract.GetAllocatedCount(nil)
if err != nil {
    logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
    return nil   // swallows the error — BUG
}
``` [1](#0-0) 

When `GetAllocatedCount` fails, `fillAllocated` returns `nil`, leaving `result.After.Allocated` as an empty map. `RebalanceTreasury` then continues unaware of the failure:

1. **Validation 4** (`totalZeroedAmount < totalAllocatedAmount`) passes trivially because `totalAllocatedAmount == 0`.
2. **Execution 1** zeros every address in `result.Before.Zeroed` — their KAIA balances are set to `0`.
3. **Execution 2** iterates over the empty `result.After.Allocated` map — no funds are distributed.
4. `remainder = totalZeroedAmount − 0 = totalZeroedAmount` is added to `result.Burnt`. [2](#0-1) 

The entire zeroed treasury balance is burned with zero allocation to the intended recipients.

A second layer of error suppression exists in `SystemModule.FinalizeState`: even if `RebalanceTreasury` did return an error, the caller logs it and returns `nil`, so the block is finalized regardless. [3](#0-2) 

---

### Impact Explanation

At the single KIP-103 (`IsKIP103ForkBlock`) or KIP-160 (`IsKIP160ForkBlock`) block, if `GetAllocatedCount` reverts or returns an error:

- All zeroed treasury accounts lose their entire KAIA balance (set to `0`).
- No allocated accounts receive any funds.
- The full zeroed amount is recorded as `Burnt` and permanently destroyed.
- `FinalizeState` returns `nil`, so the block is accepted and the state root is committed with the incorrect balances.
- Because all nodes execute the same buggy path, they agree on the wrong state root — the chain continues with the corrupted treasury state and no consensus alarm is raised.

This matches the allowed impact gate: **unauthorized burn of system-managed KAIA funds** and **persistent corruption of canonical state** at a privileged fork block.

---

### Likelihood Explanation

The trigger requires `GetAllocatedCount` to fail at the exact fork block. This can occur if:

- The KIP-103/KIP-160 contract address is misconfigured or not yet deployed.
- The contract's `GetAllocatedCount` function reverts (e.g., due to a contract-side bug or an ABI mismatch after an upgrade).
- A transient EVM error occurs during the call.

The window is a single block, but the damage is permanent and irreversible once the state root is committed.

---

### Recommendation

Change `return nil` to `return err` in `fillAllocated`:

```diff
 numNewbieBigInt, err := contract.GetAllocatedCount(nil)
 if err != nil {
     logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
-    return nil
+    return err
 }
```

Additionally, `SystemModule.FinalizeState` should propagate the `RebalanceTreasury` error rather than swallowing it, so that a failed rebalancing halts block finalization rather than silently producing a wrong state root.

---

### Proof of Concept

1. Deploy a `TreasuryRebalanceMock` contract whose `getAllocatedCount` function always reverts.
2. Configure `Kip103ContractAddress` (or `Kip160ContractAddress`) to point to this contract.
3. Mine to the fork block. `RebalanceTreasury` calls `fillAllocated`; `GetAllocatedCount` reverts; `fillAllocated` returns `nil`.
4. `RebalanceTreasury` proceeds: zeroed accounts are drained, allocated map is empty, all funds are burned.
5. `FinalizeState` returns `nil`; the block is committed with the corrupted state.
6. Inspect zeroed account balances — all are `0`. Inspect allocated account balances — unchanged. Total KAIA supply is reduced by the full zeroed amount with no corresponding allocation. [4](#0-3) [5](#0-4)

func (result *rebalanceResult) fillZeroed(contract RebalanceCaller, state *state.StateDB) error {
	numRetiredBigInt, err := contract.GetZeroedCount(nil)
	if err != nil {
		logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
		return err
	}

	for i := 0; i < int(numRetiredBigInt.Int64()); i++ {
		ret, err := contract.Zeroeds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Zeroeds from TreasuryRebalance contract", "err", err)
			return err
		}
		result.Before.Zeroed[ret] = state.GetBalance(ret)
		result.After.Zeroed[ret] = state.GetBalance(ret) // will be set as zero if rebalance succeeds
	}
	return nil
}

func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {
	numNewbieBigInt, err := contract.GetAllocatedCount(nil)
	if err != nil {
		logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
		return nil
	}

	for i := 0; i < int(numNewbieBigInt.Int64()); i++ {
		ret, err := contract.Allocateds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Allocateds from TreasuryRebalance contract", "err", err)
			return err
		}

		result.Before.Allocated[ret.Addr] = state.GetBalance(ret.Addr)
		result.After.Allocated[ret.Addr] = ret.Amount
	}
	return nil
}

// RebalanceTreasury reads data from a contract, validates stored values, and executes treasury rebalancing (KIP-103, KIP-160).
// It can change the global state by removing old treasury balances and allocating new treasury balances.
// The new allocation can be larger than the removed amount, and the difference between two amounts will be burnt.
func RebalanceTreasury(state *state.StateDB, chain backends.BlockChainForCaller, header *types.Header) (*rebalanceResult, error) {
	var (
		err    error
		caller RebalanceCaller

		result   = newRebalanceReceipt()
		isKIP160 = chain.Config().IsKIP160ForkBlock(header.Number)
		isKIP103 = chain.Config().IsKIP103ForkBlock(header.Number)
	)

	if isKIP160 {
		caller, err = rebalance.NewTreasuryRebalanceV2Caller(chain.Config().Kip160ContractAddress, backends.NewBlockchainContractBackend(chain, nil, nil))
	} else if isKIP103 {
		caller, err = NewKip103ContractCaller(state, chain, header)
	} else {
		return nil, errors.New("rebalancing shouldn't be executed unless the block number is kip103 or kip160 hard fork")
	}
	if err != nil {
		return nil, err
	}

	// Retrieve 1) Get Zeroed
	if err = result.fillZeroed(caller, state); err != nil {
		return result, err
	}

	// Retrieve 2) Get Allocated
	if err = result.fillAllocated(caller, state); err != nil {
		return result, err
	}

	// Validation 1) Check the target block number
	if blockNum, err := caller.RebalanceBlockNumber(nil); err != nil || blockNum.Cmp(header.Number) != 0 {
		return result, ErrRebalanceIncorrectBlock
	}

	// Validation 2) Check whether status is approved. It should be 2 meaning approved
	if status, err := caller.Status(nil); err != nil || status != 2 {
		return result, ErrRebalanceBadStatus
	}

	// Validation 3) Check approvals from zeroeds
	if err = caller.CheckZeroedsApproved(nil); err != nil {
		return result, err
	}

	// Validation 4) Check the total balance of zeroeds are bigger than the distributing amount
	totalZeroedAmount := result.totalZeroedBalance()
	totalAllocatedAmount := result.totalAllocatedBalance()
	if isKIP103 && totalZeroedAmount.Cmp(totalAllocatedAmount) < 0 {
		return result, ErrRebalanceNotEnoughBalance
	}

	// Execution 1) Clear all balances of zeroeds
	for addr := range result.Before.Zeroed {
		state.SetBalance(addr, big.NewInt(0))
		result.After.Zeroed[addr] = big.NewInt(0)
	}
	// Execution 2) Distribute KAIA to all allocateds
	for addr, balance := range result.After.Allocated {
		// if an allocated has KAIA before the allocation, it will be burnt
		currentBalance := state.GetBalance(addr)
		result.Burnt.Add(result.Burnt, currentBalance)

		state.SetBalance(addr, balance)
	}

	// Fill the remaining fields of the result
	remainder := new(big.Int).Sub(totalZeroedAmount, totalAllocatedAmount)
	result.Burnt.Add(result.Burnt, remainder)
	result.Success = true
	return result, nil
