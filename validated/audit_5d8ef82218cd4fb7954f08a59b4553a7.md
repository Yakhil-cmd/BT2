### Title
Webhook signature verification is bound to the payload's `repository.owner.login`, not the repository the event handlers actually mutate - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App / webhook secret to check the HMAC signature using an organization name that is read out of the *unauthenticated* JSON body itself, while the event handlers that subsequently run (`PushHandler`, `StatusHandler`, etc.) resolve the target `Stack`/`Commit` using a *different* field of that same body (`repository.full_name` or a bare `sha`). Nothing enforces that these two identities match, so a payload can be signed (or exempted from signing) for one organization while acting on a repository that belongs to a completely different, unrelated organization.

### Finding Description
`WebhooksController#verify_signature` picks the GitHub App config to verify against based on `repository_owner`, which is taken directly from the untrusted request body: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for that organization: [3](#0-2) 

Shipit explicitly supports multiple GitHub organizations, each with its own independent (and optionally unset) `webhook_secret`: [4](#0-3) [5](#0-4) 

Once the request passes (or bypasses) this org-scoped check, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` is invoked with the raw parsed body, and every handler independently determines *which* repository/commit to mutate from other fields of that same body — with no re-check that they belong to the organization that was actually verified: [6](#0-5) 

- `Handler#stacks` resolves the target via `payload.dig('repository', 'full_name')`, a field independent from `repository_owner`: [7](#0-6) 
- `PushHandler#process` then calls `stack.sync_github` on whatever stack that full_name resolves to: [8](#0-7) 
- `StatusHandler#process` is even less scoped — it matches purely by commit SHA across the *entire* installation, with no repository check at all: [9](#0-8) 

The broken equality is: `organization authenticated by verify_signature (repository_owner from payload) == owner of the repository/commit actually written by the handler (full_name / sha from the same untrustworthy payload)`. These are never checked against each other, and the second value is used to select real, tracked `Stack`/`Commit` records belonging to potentially unrelated organizations.

### Impact Explanation
An organization configured in `Shipit.secrets.github` without a `webhook_secret` (a documented, supported configuration — see `config/secrets.development.example.yml`) causes `verify_webhook_signature` to auto-pass for any payload claiming to originate from that organization. An attacker can send a forged, entirely unsigned webhook request that sets `repository.owner.login` (or `organization.login`) to the secret-less organization, while setting `repository.full_name` (for push events) or `sha` (for status events) to a real repository/commit tracked under a *different*, secret-protected organization. This lets the attacker:
- Trigger `stack.sync_github` on a victim stack they do not administer (`PushHandler`).
- Inject arbitrary commit statuses (`StatusHandler`, unscoped by repository) onto commits belonging to victim stacks, which can influence deploy/merge readiness gates that key off commit status (`MergeStatusController`, deploy validations).

This crosses the "unauthorized deploy/merge" and cross-repository-write bar because it lets an attacker who controls no more than one loosely-configured/unverified organization affect state of stacks belonging to organizations they have no relationship to.

### Likelihood Explanation
Requires the Shipit installation to use the documented multi-organization GitHub App configuration with at least one organization lacking a `webhook_secret` (an explicitly supported, sample configuration in the repo's own docs/config templates), and requires the attacker to know or predict a target commit SHA (trivial for public repositories) or repository full name (always public). No GitHub App private key, `ApiClient` token, or Shipit session is required — only the ability to POST to the public webhook endpoint. This is realistic in shared/multi-tenant Shipit deployments that onboard low-trust organizations alongside trusted ones.

### Recommendation
Do not select the verification secret based on data inside the unauthenticated payload. Alternatively, after verifying signature for organization `O`, re-derive and enforce that every entity a handler mutates (`repository.full_name`, `sha`'s owning repository) actually belongs to organization `O`, rejecting the webhook otherwise. Also make `StatusHandler` (and any other cross-repository-unscoped handler) scope commit lookups by the verified repository, not by a bare, installation-wide SHA match.

### Proof of Concept
1. Configure Shipit with two GitHub orgs: `victim-org` (has `webhook_secret` set, has a tracked stack `victim-org/app`) and `attacker-org` (no `webhook_secret` configured, per the supported schema in `config/secrets.development.example.yml`).
2. POST to `/github_authentication`... actually to the webhooks endpoint with header `X-Github-Event: status` and no valid `X-Hub-Signature`, body:
```json
{
  "sha": "<real sha of a commit in victim-org/app>",
  "state": "success",
  "context": "ci/forged",
  "repository": { "owner": { "login": "attacker-org" } }
}
```
3. `verify_signature` looks up `Shipit.github(organization: "attacker-org")`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` unconditionally (`app/controllers/shipit/webhooks_controller.rb:24-30`, `lib/shipit/github_app.rb:76-83`).
4. `StatusHandler#process` matches `Commit.where(sha: params.sha)` — the victim's real commit — and creates a status on it, entirely bypassing `victim-org`'s webhook secret (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

**File:** lib/shipit.rb (L170-200)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
