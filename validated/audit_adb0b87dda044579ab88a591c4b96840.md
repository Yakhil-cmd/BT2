All path-construction and ".." handling I found in the Polkadot SDK are CLI/build-time or node-operator-controlled surfaces — e.g. `chain-spec-builder` reading `--chain-spec-path`/`--runtime` paths [1](#0-0) , `ChainSpec::from_json_file`/`GenesisSource::File` loading a local file path [2](#0-1) , benchmarking CLI reading `--runtime`/`--chain`/`--genesis-patch` files [3](#0-2) , and the PVF worker's `pivot_root`/`change_root` sandbox which explicitly self-tests that `..` cannot escape the new root [4](#0-3) . None of these paths are attacker-controlled by an unprivileged signed extrinsic, contract call, XCM message, or proof submission — they are all local operator/CLI inputs or node-internal sandboxing, so the CVE-2017-14849 pattern (remote attacker supplying a path with `..` that bypasses validation to escape an intended directory) has no reachable analog through the runtime's actual attack surface.
