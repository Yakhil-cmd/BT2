## Analysis: Cross-repository commit-status forgery via unscoped SHA lookup in `StatusHandler`

### Root cause

Webhook signature verification in `WebhooksController#verify_signature` selects **which** GitHub App/organization's `webhook_secret` to validate against using a value pulled straight from the payload itself:

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
end
``` [1](#0-0) 

A passing signature only proves *"this payload was signed by organization X's installed GitHub App"* — it says nothing about which repository/stack the payload is allowed to mutate inside Shipit's own database. Most handlers correctly re-derive the target scope from the same payload via `Handler#repository_name`/`#stacks`, which filters by `payload.dig('repository', 'full_name')`:

```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [2](#0-1) 

`StatusHandler`, however, does **not** use this scoping at all. It resolves the record to mutate purely by commit SHA, globally, across every repository/stack ever tracked by the Shipit instance:

```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [3](#0-2) 

The binding that should hold is: **organization authenticated by the verified signature == repository/stack whose `Commit` row is written**. Because `StatusHandler` never checks `payload['repository']` against the `Commit`'s owning `Repository`/`Stack`, this equality is never enforced — any organization with its own (legitimately obtained, unprivileged relative to the victim) GitHub App installation can emit a signed `status` webhook that writes a fabricated status onto a `Commit` row belonging to a completely different, unrelated repository/stack, as long as the git commit SHA happens to match.

### Why the SHA can match across repos

Git commit hashes are deterministic over tree, parent(s), author/committer identity+timestamp, and message. Forking a public GitHub repository preserves full git history, so identical commits in a fork and its upstream have byte-identical SHA1s. An attacker who:
1. Forks (or otherwise obtains push/status-API access to) any repository, and
2. Has that repository's org install a GitHub App configured in Shipit's `github` secrets (its own, unprivileged installation — no access to the victim stack/org is needed),

can call GitHub's Statuses API on a commit in their own fork whose SHA matches a commit that exists upstream in a Shipit-tracked stack. GitHub signs and delivers this `status` event with the attacker's own org's `webhook_secret`, which passes `verify_signature` (verification is legitimately scoped to the attacker's own org). `StatusHandler` then finds and overwrites the `Commit` row for the victim stack purely by SHA, with attacker-chosen `state`, `context`, `description`, and `target_url`.

### Impact

Commit statuses are read by Shipit to gate merges/deploys (e.g., required checks such as CI status). Forging a `success` status with a matching `context` on a victim stack's commit can make it appear "green"/mergeable/deployable to reviewers or to any automated merge-queue logic that relies on `Commit#statuses`, without the attacker ever having any access to the victim repository, org, or Shipit account — an unauthorized deploy/merge enablement and a cross-repository database write, both explicitly listed Critical impacts.

### Recommendation

`StatusHandler#process` must scope the `Commit` lookup by the repository identified in the verified payload (the same `stacks`/`repository_name` mechanism the other handlers already use), e.g. `stacks.flat_map(&:commits).where(sha: params.sha)`, rather than a bare `Commit.where(sha: params.sha)` across the whole instance.

### Proof of Concept (conceptual)
1. Victim organization "victim-org" has stack `victim-org/app` tracked by Shipit, with commit `abc123...` present.
2. Attacker forks `victim-org/app` into `attacker-org/app` (or otherwise reconstructs an identical commit object), preserving SHA `abc123...`.
3. Attacker's own GitHub App installation (configured under `attacker-org` in Shipit's `config/secrets.yml`, per the documented multi-org setup) is used to `POST` a `status` webhook for `attacker-org/app` at `abc123...` with `state: "success", context: "ci/required-check"`.
4. GitHub signs the payload with `attacker-org`'s `webhook_secret`; `WebhooksController#verify_signature` resolves `Shipit.github(organization: 'attacker-org')` and verification passes.
5. `StatusHandler#process` executes `Commit.where(sha: 'abc123...')`, matches the victim's `Commit` row (belonging to `victim-org/app`), and writes the forged status onto it — with no cross-check that `payload['repository']` corresponds to that commit's actual repository/stack. # frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
