### Title
Type-coercion flaw lets a final-bad, never-stabilized unit's stripped output be resurrected from the local pruned-joint cache during payment validation - (File: `validation.js`)

### Summary
`validation.js`'s `validatePaymentInputsAndOutputs` recovers output data (`address`, `amount`, `denomination`, `asset`) for spent inputs whose owning unit has already had its content stripped locally, by falling back to an in-memory holdover cache (`assocCachedPrunedJoints`) maintained by `archiving.js`. The guard that is supposed to restrict this fallback to outputs that were *already stable* before being pruned uses a raw `<` comparison against `src_output.main_chain_index`, which can be `null` for units pruned via the "uncovered"/non-serial path. In JavaScript, `null < N` coerces `null` to `0`, so the guard is satisfied for units that were never included on the main chain at all, i.e. never reached consensus/stability.

### Finding Description
The vulnerable check is: [1](#0-0) 

```js
if (!src_output.address) {
    if (src_output.sequence === 'final-bad' && src_output.main_chain_index < storage.getMinRetrievableMci()) { // already stripped locally
        const objCachedOutput = archiving.getCachedOutput(input.unit, input.message_index, input.output_index);
        ...
        src_output.address = objCachedOutput.address;
        src_output.amount = objCachedOutput.amount;
        src_output.denomination = objCachedOutput.denomination;
        src_output.asset = objCachedOutput.asset;
```

The comment "already stripped locally" implies the check is meant to be reached only for units whose stability was already established (`main_chain_index` set, `< min_retrievable_mci`). But this branch is only reachable when `bStableInParents` is `false` (otherwise `final-bad` + `bStableInParents` returns an error earlier at [2](#0-1)  ). `bStableInParents` is `false` whenever `main_chain_index` is `null` — which is exactly the case for units purged as "uncovered" non-serial joints (never assigned an MCI), pruned via `purgeUncoveredNonserialJoints` in `joint_storage.js`: [3](#0-2) 

Those units are archived and their full joint is cached for recovery purposes here: [4](#0-3) 

Because `null < storage.getMinRetrievableMci()` evaluates to `true` for any positive `min_retrievable_mci` (JS coerces `null` to `0`), the validation code treats an *unconfirmed, never-stable, discarded* unit the same as a *stable, pruned* unit, and pulls its stripped-output data from the local pruned-joint cache to satisfy input lookups.

### Impact Explanation
This lets locally-cached data for a unit that was never validated as stable by the network (only locally purged as non-serial/uncovered "final-bad" garbage) feed directly into the core payment-input resolution path (`total_input`, `arrInputAddresses`, asset/denomination checks). While the newly-posted spending unit currently inherits the `final-bad`/non-good sequence from the fabricated source output at [5](#0-4) , the wrong data still perturbs the authoritative input/output accounting used across validation (owner-address checks, denomination checks, asset checks, total_input sums) for a unit that a peer node may have already accepted (i.e., nodes can disagree about which locally-purged data is authoritative), creating a path toward node disagreement on unit validity given the same underlying unit sequence differs by node based on purely-local, TTL-based, race-prone cache contents rather than consensus state.

### Likelihood Explanation
Exploitation requires an attacker to get a unit locally archived by a target node via the "uncovered" (non-serial) purge path — reachable simply by posting units that lose the free/non-serial race locally — and then reference that unit's now-stripped output as an input in a subsequent unit within the ~1 hour TTL window of `assocCachedPrunedJoints`. This requires no special privileges; it's reachable purely as an ordinary unit poster interacting with `joint_storage.purgeUncoveredNonserialJoints` and `validation.validatePaymentInputsAndOutputs`.

### Recommendation
Explicitly null-check `src_output.main_chain_index` before the numeric comparison (e.g. `src_output.main_chain_index !== null && src_output.main_chain_index < storage.getMinRetrievableMci()`), and additionally assert `bStableInParents` semantics so the pruned-joint cache fallback can only ever be reached for genuinely-stabilized, stripped units — never for non-serial/uncovered units lacking a main-chain index.

### Proof of Concept
1. Attacker crafts unit `U1` that ends up flagged `is_free=1`, `sequence='final-bad'`, `content_hash IS NULL`, and with no children/dependencies, causing the target node to purge it via `purgeUncoveredNonserialJoints` (`joint_storage.js` lines 230-246), stripping its `outputs.address`/`amount` in the DB while `archiving.js`'s `cachePrunedJoint` retains the full joint in memory for the TTL window.
2. Within the TTL window, attacker posts a follow-up unit `U2` whose input references `U1`'s stripped output.
3. In `validatePaymentInputsAndOutputs`, the DB lookup for `U1`'s output returns `main_chain_index = null`, `sequence = 'final-bad'`, `address = null`.
4. The check `src_output.main_chain_index < storage.getMinRetrievableMci()` evaluates `null < N` as `true`, so the code fetches `U1`'s cached joint data via `archiving.getCachedOutput` and populates `src_output.address/amount/denomination/asset` from data that was never confirmed stable by the network, feeding it into subsequent input/output accounting for `U2`.

**File:** archiving.js (L5-19)
```javascript
// in-memory holdover of joints we just voided (stripped final-bad units), so that for a while after pruning
// we can still serve their full content to peers and recover from spends that raced the pruning locally
const PRUNED_JOINT_CACHE_TTL_ms = 60 * 60 * 1000;
let assocCachedPrunedJoints = {};

function cachePrunedJoint(objJoint){
	assocCachedPrunedJoints[objJoint.unit.unit] = { objJoint: objJoint, expiry_ts: Date.now() + PRUNED_JOINT_CACHE_TTL_ms };
}

function getCachedPrunedJoint(unit){
	const cached = assocCachedPrunedJoints[unit];
	if (!cached)
		return null;
	return cached.objJoint;
}
```
