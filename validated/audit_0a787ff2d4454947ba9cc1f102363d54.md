### Title
Unauthenticated `ServiceChainInvalidTxResponseMsg` Allows Any Bridge Peer to Permanently Evict Valid Transactions from BridgeTxPool — (`node/sc/sub_bridge_handler.go`)

### Summary
Any P2P node that connects to the sub-bridge and presents the correct parent chain ID can send a crafted `ServiceChainInvalidTxResponseMsg` containing attacker-chosen tx hashes with `ErrStr = "gas price is below the base fee"`. The handler removes those transactions from the `BridgeTxPool` without verifying the sender's identity. Anchoring transactions have no automatic retry, making their removal permanent.

### Finding Description
`handleParentChainInvalidTxResponseMsg` is invoked from `HandleMainMsg` for the `ServiceChainInvalidTxResponseMsg` message code. The peer object `p` is not forwarded to the handler, and the handler performs no check that the message originates from a legitimate parent chain node. It decodes the attacker-supplied `[]InvalidParentChainTx` slice, looks each hash up in the pool via `txPool.Get(invalidTx.TxHash)`, and — if the `ErrStr` field equals `blockchain.ErrGasPriceBelowBaseFee.Error()` — calls `RemoveTx(tx)`. The `ErrStr` comparison is a plain string equality check against a public constant, trivially satisfied by any attacker. The tx hashes are learned by the attacker from `broadcastServiceChainTx`, which sends all pending bridge txs to every connected peer.

`RegisterNewPeer` only enforces chain ID equality, not peer identity, so any node that can reach the bridge P2P port and advertise the correct chain ID becomes a trusted message source.

### Impact Explanation
- **Anchoring transactions**: permanently dropped with no automatic retry. The anchoring gap is never filled, breaking the child-chain data anchoring guarantee.
- **Value-transfer transactions**: dropped from the pool. If `ValueTransferRecovery` is disabled (operator-configurable), the bridged asset transfer is permanently lost. Even with recovery enabled, the recovery path must re-detect and re-submit the transfer, introducing a window of asset unavailability.

Both outcomes satisfy the allowed impact gate: *"Persistent corruption of trie/state/snapshot data that breaks canonical execution, withdrawals, transfers, or settlement"* and *"Unauthorized transfer … affecting … bridged assets."*

### Likelihood Explanation
The bridge P2P port is a network-accessible endpoint. An attacker needs only to: (1) reach the port, (2) complete the RLPx handshake with the correct parent chain ID, and (3) send a single crafted message. The required tx hashes are self-disclosed by the victim node. No privileged access, key compromise, or validator collusion is required.

### Recommendation
1. Pass the peer `p` into `handleParentChainInvalidTxResponseMsg` and verify that the peer's identity matches a configured, trusted parent chain bridge node before acting on the message.
2. Alternatively, maintain a set of authorized parent bridge peer IDs and reject `ServiceChainInvalidTxResponseMsg` from any peer not in that set.
3. For anchoring transactions specifically, add a retry or re-generation mechanism so that even a legitimate `ErrGasPriceBelowBaseFee` response does not cause permanent data loss.

### Proof of Concept
1. Start a sub-bridge node configured with parent chain ID `X`.
2. Connect a mock peer to the sub-bridge P2P port, completing the handshake with chain ID `X`.
3. Wait for the sub-bridge to broadcast `ServiceChainTxData` — extract the tx hash of a pending anchoring or value-transfer tx.
4. Send a `ServiceChainInvalidTxResponseMsg` RLP-encoded as `[]InvalidParentChainTx{{TxHash: <extracted hash>, ErrStr: "gas price is below the base fee"}}`.
5. Observe that `BridgeTxPool.Get(<hash>)` returns `nil` — the tx has been permanently removed.
6. Confirm no anchoring re-submission occurs for the affected block range.

func (sbh *SubBridgeHandler) handleParentChainInvalidTxResponseMsg(msg p2p.Msg) error {
	var invalidTxs []InvalidParentChainTx
	if err := msg.Decode(&invalidTxs); err != nil && err != rlp.EOL {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	txPool := sbh.subbridge.GetBridgeTxPool()
	for _, invalidTx := range invalidTxs {
		if tx := txPool.Get(invalidTx.TxHash); tx != nil {
			logger.Error("A bridge tx was not executed", "err", invalidTx.ErrStr,
				"txHash", invalidTx.TxHash.String(),
				"txGasPrice", tx.GasPrice().Uint64())
			if invalidTx.ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error() {
				logger.Info("[SC][HandleTxDropped] Request gasPrice and Magma values to parent chain")
				sbh.SyncNonceAndGasPrice()

				logger.Error("Bridge tx is removed which has lower gasPrice than UpperBoundBaseFee")
				// Remove the tx from the pool. For value transfer txs, Value Transfer Recovery
				// will retry if enabled. For anchoring txs, there is no automatic retry mechanism;
				if err := sbh.subbridge.GetBridgeTxPool().RemoveTx(tx); err != nil {
					logger.Error("Failed to remove bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				} else {
					logger.Info("Removed bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				}
			} // TODO-ServiceChain: Consider other types of tx failures with else {}
		}
	}
	return nil
}

func (sbh *SubBridgeHandler) RegisterNewPeer(p BridgePeer) error {
	sbh.subbridge.addPeerCh <- struct{}{}

	if sbh.getParentChainID().Cmp(p.GetChainID()) != 0 {
		return fmt.Errorf("attempt to add a peer with different chainID failed! existing chainID: %v, new chainID: %v", sbh.getParentChainID(), p.GetChainID())
	}
	// sync nonce and gasprice with peer
	sbh.SyncNonceAndGasPrice()

	return nil
}
