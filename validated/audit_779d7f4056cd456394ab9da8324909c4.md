### Title
Hookify `event: file` PreToolUse Rules Bypassed via `NotebookEdit` Tool - (File: `plugins/hookify/hooks/pretooluse.py`)

### Summary
The hookify plugin lets users write local, project-level `PreToolUse`/`PostToolUse` "block" or "warn" rules (e.g., "block edits to `.env`", "block writes containing secrets") scoped to `event: file`, intended to cover all file-editing tool calls. The dispatcher that decides which rules apply for a given tool call hardcodes the set of file-editing tools as `Edit`, `Write`, `MultiEdit`, omitting `NotebookEdit`, so `file`-scoped rules are silently never evaluated when a notebook is edited — an unprotected path exists alongside the protected ones, mirroring how `delegateBySig()` provided an unrestricted path around the restricted `delegate()` override.

### Finding Description
`plugins/hookify/hooks/pretooluse.py` computes the event bucket used to select which rules to load and evaluate: [1](#0-0) 
Only `Bash` maps to `event='bash'`, and only `tool_name in ['Edit', 'Write', 'MultiEdit']` maps to `event='file'`; any other tool name (notably `NotebookEdit`, which also mutates file contents) leaves `event=None`.

That `event` value is passed straight into `load_rules(event=event)`, which filters out any rule whose `event` doesn't match: [2](#0-1) 

Because a `NotebookEdit` call produces `event=None`, `load_rules(event=None)` returns **all** rules regardless of their `event` field (the `if event:` guard is falsy), but then `RuleEngine._rule_matches` still requires `rule.tool_matcher` to match `tool_name` when `tool_matcher` is set, and otherwise falls through to evaluating `rule.conditions` via `_extract_field`: [3](#0-2) 

`_extract_field` only special-cases `Bash`, `Write`/`Edit`, and `MultiEdit` for fields like `file_path`/`new_text`/`content`; there is no branch for `NotebookEdit`, so `condition.field` resolution falls through to `None` for the fields users write rules against (`file_path`, `new_text`, `content`, `old_text`), and `_check_condition` returns `False` whenever `field_value is None`: [4](#0-3) [5](#0-4) 

The net effect: a user-authored `event: file` rule such as blocking edits to `.env`/credential files, or blocking writes containing a secret pattern, is checked against `Edit`, `Write`, and `MultiEdit`, but is never evaluated — and can never match — when the same file content is modified through `NotebookEdit` (writing/editing a `.ipynb` cell, which can contain arbitrary text content, embedded shell commands via `!`-magics, or be used to write to co-located file paths through notebook JSON), because both the event classification and the field-extraction logic omit that tool entirely. The check was correctly implemented for the "obvious" file-editing tools but not for the equivalent notebook-editing entry point — the same root-cause shape as overriding `delegate()` while leaving `delegateBySig()`, a second entry point into the same protected operation, unrestricted.

### Impact Explanation
This is a hook-bypass in a local trust boundary that a project or user relies on to block dangerous or unwanted file operations (the exact class explicitly listed as in-scope: "hook bypass ... trust boundaries"). Any project that ships or relies on a hookify `event: file` block rule (e.g., preventing edits to `.env`, lockfiles, CI config, or secret-bearing files) can have that protection silently and completely bypassed by using `NotebookEdit` instead of `Edit`/`Write`/`MultiEdit` to achieve the same file mutation, with no warning, no block, and no indication to the user that the rule was skipped. Because hookify's rules are the only enforcement layer for these custom policies (there is no LLM-based fallback like `security-guidance`'s Stop-hook review), the bypass is a silent, complete loss of the configured guardrail rather than a partial degradation.

### Likelihood Explanation
High reachability, no special privileges needed: any Claude Code session (agent or user) that calls the standard, already-available `NotebookEdit` tool while a hookify rule is configured for `event: file` will trigger the bypass automatically — there is no attacker-crafted input, malformed config, or unusual tool usage required, just normal use of a supported first-party tool.

### Recommendation
Fix the tool-to-event classification in `plugins/hookify/hooks/pretooluse.py` to include `NotebookEdit` in the `file` event bucket (mirroring how `security-guidance`'s `security_reminder_hook.py` already includes `NotebookEdit` alongside `Edit`/`Write`/`MultiEdit`), and extend `RuleEngine._extract_field` in `plugins/hookify/core/rule_engine.py` to resolve `file_path`/`new_text`/`content`/`old_text` for `NotebookEdit`'s actual input shape (`notebook_path`, cell `new_source`/`old_source`, etc.), so that `event: file` rules are enforced consistently across every tool that can mutate file contents, not only the three enumerated ones.

### Proof of Concept
1. In a project, add `.claude/hookify.block-env.local.md`:
```
---
name: block-env-edit
enabled: true
event: file
action: block
conditions:
  - field: file_path
    operator: regex_match
    pattern: \.env$
---
Editing .env files is blocked by policy.
```
2. Ask Claude to edit `.env` directly with the `Edit` tool → hookify correctly returns `permissionDecision: deny` and blocks the operation, because `pretooluse.py` classifies `Edit` as `event='file'` and `RuleEngine._extract_field` resolves `file_path` for `Edit`.
3. Ask Claude to perform the equivalent file mutation via `NotebookEdit` (e.g., targeting a `.env`-adjacent file path parameter accepted by the tool, or using notebook cell content to write out the same file via an embedded shell/`!`-magic in supported notebook kernels) → `pretooluse.py` computes `event=None` for `NotebookEdit`; `load_rules(None)` loads the rule anyway, but `RuleEngine._extract_field` has no `NotebookEdit` branch so `field_value` for `file_path` is `None`, `_check_condition` returns `False`, and the rule never matches — the operation proceeds unblocked, with no warning shown, despite the identically-scoped policy that blocks the same effective action through `Edit`/`Write`/`MultiEdit`.

```python
def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)
```

```python
    def _rule_matches(self, rule: Rule, input_data: Dict[str, Any]) -> bool:
        """Check if rule matches input data.

        Args:
            rule: Rule to evaluate
            input_data: Hook input data

        Returns:
            True if rule matches, False otherwise
        """
        # Extract tool information
        tool_name = input_data.get('tool_name', '')
        tool_input = input_data.get('tool_input', {})

        # Check tool matcher if specified
        if rule.tool_matcher:
            if not self._matches_tool(rule.tool_matcher, tool_name):
                return False

        # If no conditions, don't match
        # (Rules must have at least one condition to be valid)
        if not rule.conditions:
            return False

        # All conditions must match
        for condition in rule.conditions:
            if not self._check_condition(condition, tool_name, tool_input, input_data):
                return False

        return True
```

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```
