## Title
Webhook signature is verified against a secret selected from an unauthenticated field that differs from the field used to select the target repository/stack, allowing a valid-secret holder for one GitHub organization to forge events for stacks belonging to a different organization - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks which GitHub App/webhook secret to verify a payload against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted, attacker-supplied JSON body, *before* any signature check has occurred. The downstream event handlers, however, resolve the actual `Repository`/`Stack` to act on using a *different* field of the same body: `repository.full_name` (`Shipit::Webhooks::Handlers::Handler#repository_name`). Nothing binds "the organization whose secret validated this payload" to "the repository the handler will actually mutate."

### Finding Description
`verify_signature` computes:
```
app/controllers/shipit/webhooks_controller.rb:24-30
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where `repository_owner` (line 59-62) is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` — both taken from the raw, unverified request body. [1](#0-0) [2](#0-1) 

The instance is configured with a separate GitHub App/secret per organization when using multiple organizations, as documented: [3](#0-2) 

`Handler#stacks`/`#repository_name` instead resolves the target repository from `payload.dig('repository', 'full_name')`:
```
app/models/shipit/webhooks/handlers/handler.rb:32-38
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [4](#0-3) 

`PushHandler#process` then acts on whatever stacks match that `full_name`: [5](#0-4) 

Because the HMAC-SHA1 signature is computed over the *entire* raw request body (`request.raw_post`) using `OpenSSL::HMAC.hexdigest` inside `verify_webhook_signature`, an attacker who legitimately possesses the webhook secret for organization **A** (e.g., because they administer a GitHub org/repo that is itself onboarded to this Shipit instance and configured the webhook secret) can freely construct any JSON body and sign it with A's secret — including a body where `repository.owner.login = "A"` (so `verify_signature` picks A's secret and the check passes) while `repository.full_name = "B/some-other-repo"` (a repository belonging to a completely different, unrelated organization B also tracked by this Shipit instance). [6](#0-5) 

The binding broken is: **"organization that authenticated" (`repository_owner` used to pick the HMAC secret) ≠ "repository that is written" (`repository.full_name` used by the handler to select the `Stack`)**. Before the attacker's request: organization A's secret only lets them affect their own repositories. After: the same secret lets them forge push/status/check_suite/membership events that are dispatched against any other organization's stacks tracked by the same Shipit instance, since no code cross-checks that `repository.owner.login == repository.full_name`'s owner.

### Impact Explanation
This crosses an authentication boundary the rules explicitly call out (organization authenticated vs. repository written) and enables **cross-repository writes** without holding the target organization's credentials: e.g. `PushHandler` enqueues `GithubSyncJob`/triggers `stack.sync_github` for a foreign stack, `StatusHandler` creates commit statuses on a foreign stack's commits, `CheckSuiteHandler` enqueues `RefreshCheckRunsJob`, and `MembershipHandler` can create/delete `Team`/`Membership`/`User` records tied to the "organization" field, potentially influencing `Shipit.github_teams` authorization for teams unrelated to the attacker's own org. None of this requires GitHub write access to the victim repository — only a valid webhook secret for *some* organization configured on the same Shipit instance.

### Likelihood Explanation
Requires (a) a multi-organization Shipit deployment (documented, supported feature) and (b) the attacker legitimately possessing the webhook secret for at least one onboarded organization (e.g., as that org's GitHub App/webhook administrator) — a much weaker requirement than compromising the target organization. Given Shipit is explicitly designed to support multiple organizations sharing one instance, this is a realistic operational configuration, though it does depend on such a multi-org deployment and does not apply to single-organization installs.

### Recommendation
After signature verification succeeds using the secret picked by `repository_owner`, validate that `repository.full_name`'s owner segment matches `repository_owner` (or, more robustly, verify the signature using the secret associated with the organization actually owning `repository.full_name`, and reject if they diverge) before dispatching to any handler.

### Proof of Concept
1. Configure two organizations in `secrets.yml` per `docs/setup.md` multi-org example, `OrgA` (attacker-controlled, secret known) and `OrgB` (victim, stack tracked by Shipit).
2. Attacker crafts a `push` webhook JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(OrgA_webhook_secret, raw_body)>`.
4. POST to `/github/auth`... `/webhooks` (as routed) with `X-Github-Event: push`.
5. `verify_signature` reads `repository_owner` = `"OrgA"`, fetches OrgA's `github_app`, and `verify_webhook_signature` succeeds since the attacker signed with OrgA's real secret over the full raw body.
6. `create` dispatches to `PushHandler`, which resolves `stacks` via `repository_name` = `"OrgB/victim-repo"`, triggering `stack.sync_github` on OrgB's stack — despite the attacker never having OrgB's webhook secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
