The Postiz report concerns a Node.js web-application SSRF where a public HTTPS URL passes an allow-list check but then redirects the server-side HTTP client to an internal resource. This bug class requires: (1) an attacker-controlled URL parameter, (2) a server that validates only the initial destination, and (3) an HTTP client that transparently follows redirects into a private network.

In `Jortegata/polkadot-sdk--015`, the only HTTP-request-issuing component is the offchain worker HTTP API (`substrate/client/offchain/src/api/http.rs`, `substrate/primitives/runtime/src/offchain/http.rs`, `substrate/primitives/io/src/lib.rs`), exposed through `sp_io::offchain::http_request_start` and consumed by `sp_runtime::offchain::http::Request`. This is not an analog because:

- The URL passed to `http_request_start` originates from **runtime/offchain-worker code chosen by the node operator**, not from untrusted, attacker-supplied extrinsic/XCM/contract input reaching a public HTTP endpoint. There is no "validate-then-fetch-with-redirect" public API surface comparable to Postiz's `/api/public/stream`. [1](#0-0) 
- The requesting side is standard `hyper` request construction with no URL allow-list/deny-list check that could be bypassed via a redirect; there's simply no such validation step to defeat. [2](#0-1) 
- The worker (`HttpWorker`) dispatches the request via `self.http_client.request(request)` and directly relays whatever response/redirect handling the underlying `hyper` client is configured to do; this is not reachable by an unprivileged remote attacker submitting a signed extrinsic, contract call, or XCM message — it requires the node to already be running attacker-influenced offchain worker logic, which is outside the required "no privileged prerequisites" threat model. [3](#0-2) 

No other production code path in this repository accepts an attacker-controlled URL and performs a server-side fetch with revalidation gaps analogous to the Postiz redirect bypass. There is no signed-extrinsic, contract, or XCM entry point that triggers outbound HTTP requests at all — offchain workers run locally per node and are not driven by chain-state attacker input in the way this SSRF class requires. This does not meet the required entry-point criteria in the scan instructions (real user entry via signed extrinsic/contract/XCM/proof submission), so no valid Polkadot SDK analog exists.

	/// Mimics the corresponding method in the offchain API.
	pub fn request_start(&mut self, method: &str, uri: &str) -> Result<HttpRequestId, ()> {
		// Start by building the prototype of the request.
		// We do this first so that we don't touch anything in `self` if building the prototype
		// fails.
		let (body_sender, receiver) = mpsc::channel(0);
		let body = StreamBody::new(receiver);
		let body = BoxBody::new(body);
		let mut request = hyper::Request::new(body);
		*request.method_mut() = hyper::Method::from_bytes(method.as_bytes()).map_err(|_| ())?;
		*request.uri_mut() = hyper::Uri::from_maybe_shared(uri.to_owned()).map_err(|_| ())?;

		let new_id = self.next_id;
		debug_assert!(!self.requests.contains_key(&new_id));
		match self.next_id.0.checked_add(1) {
			Some(new_id) => self.next_id.0 = new_id,
			None => {
				tracing::error!(
					target: LOG_TARGET,
					"Overflow in offchain worker HTTP request ID assignment"
				);
				return Err(());
			},
		};
		self.requests
			.insert(new_id, HttpApiRequest::NotDispatched(request, body_sender));

		tracing::trace!(
			target: LOG_TARGET,
			id = %new_id.0,
			%method,
			%uri,
			"Requested started",
		);

		Ok(new_id)
	}

impl<'a, I: AsRef<[u8]>, T: IntoIterator<Item = I>> Request<'a, T> {
	/// Send the request and return a handle.
	///
	/// Err is returned in case the deadline is reached
	/// or the request timeouts.
	pub fn send(self) -> Result<PendingRequest, HttpError> {
		let meta = &[];

		// start an http request.
		let id = sp_io::offchain::http_request_start(self.method.as_ref(), self.url, meta)
			.map_err(|_| HttpError::IoError)?;

		// add custom headers
		for header in &self.headers {
			sp_io::offchain::http_request_add_header(id, header.name(), header.value())
				.map_err(|_| HttpError::IoError)?
		}

		// write body
		for chunk in self.body {
			sp_io::offchain::http_request_write_body(id, chunk.as_ref(), self.deadline)?;
		}

		// finalize the request
		sp_io::offchain::http_request_write_body(id, &[], self.deadline)?;

		Ok(PendingRequest { id })
	}
