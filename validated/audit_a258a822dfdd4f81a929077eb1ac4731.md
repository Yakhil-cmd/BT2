The reported issue describes an unprivileged design flaw: veRAACToken's `propose()`, `castVote()`, and `execute()` in the RAAC governance contract lack any check against an "emergency withdrawal" state, letting any signed user manipulate governance while voting-power calculations are unreliable.

Searching the Polkadot SDK for an analogous entry point (a real, unprivileged signed extrinsic that can create/vote/execute a governance proposal while the chain is in some "emergency" state) does not turn up an equivalent gap:

1. **`pallet-safe-mode`** implements exactly the recommended fix from the report: when safe-mode is entered, `Pallet::is_allowed`/`Contains::contains` blocks *all* calls except those explicitly whitelisted via `WhitelistedCalls`, which is enforced through `BaseCallFilter` at the `frame_system` dispatch layer — i.e., unprivileged calls (including governance calls like `propose`/`vote`) are rejected with `CallFiltered` unless explicitly allowed. [1](#0-0) [2](#0-1) 

2. In the reference node runtime, `SafeModeWhitelistedCalls` only allows `System`, `SafeMode`, and `TxPause` calls to bypass safe-mode — governance pallets such as `Democracy`/`Referenda`/`Council` are *not* whitelisted, so they would be blocked, not left open, during an emergency/safe-mode period. [3](#0-2) 

3. `pallet-democracy`'s own emergency-related dispatchable, `emergency_cancel`, is gated behind a privileged `CancellationOrigin` (e.g. council supermajority or Root), not a plain signed extrinsic — so there is no unprivileged path analogous to the RAAC report's `propose()`/`castVote()`/`execute()` being callable by any user during instability. [4](#0-3) [5](#0-4) 

Since the attacker model requires no privileged role, and the FRAME governance/emergency machinery either requires privileged origins for emergency actions or explicitly filters out unprivileged governance calls during an emergency (safe-mode) state — the opposite of the reported flaw — there is no demonstrable analog of this vulnerability class reachable via an unprivileged signed extrinsic in this codebase.
