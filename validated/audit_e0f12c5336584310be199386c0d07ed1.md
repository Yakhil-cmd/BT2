### Title
Cross-organization webhook spoofing when any configured GitHub org omits `webhook_secret` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
In a multi-organization Shipit deployment (`secrets.github` keyed by organization, see `docs/setup.md` §"multiple Github applications"), the webhook signature is verified against the secret of the organization named in the payload itself, not against the organization that actually owns the repository being mutated. Any handler then acts on `repository.full_name`/`repository.owner.login` taken from the same unauthenticated JSON body, independent of which organization's secret validated the request.

### Finding Description
`WebhooksController#verify_signature` derives the organization used for signature verification directly from attacker-controlled payload fields: [1](#0-0) [2](#0-1) [3](#0-2) 

It calls `Shipit.github(organization: repository_owner)`, which looks up that organization's config and builds a `GitHubApp` with that org's `webhook_secret`: [4](#0-3) 

`GitHubApp#verify_webhook_signature` explicitly **skips verification entirely if the organization has no `webhook_secret` configured**: [5](#0-4) 

This "empty secret" configuration is documented as a normal, supported state (`webhook_secret: # nil`) in `docs/setup.md` and `config/secrets.development.example.yml`: [6](#0-5) 

Once the request passes `verify_signature` (either legitimately or via the org-without-secret bypass), the actual event handlers never re-check that the organization which was authenticated matches the organization owning the repository they mutate. They instead trust `repository.full_name` from the same unauthenticated JSON body to locate the `Repository`/`Stack`: [7](#0-6) [8](#0-7) 

The binding that should hold is: **organization authenticated by signature == organization owning the repository being written**. Because `repository_owner` (used only to pick a secret) and `repository_name`/`repository.full_name` (used to select the target `Stack`) are independently attacker-controlled fields inside the same JSON body, an attacker can decouple them: pick a configured organization that has no `webhook_secret` (satisfying `verify_signature` unconditionally per `github_app.rb:76-77`) while setting `repository.full_name` to any other organization's repository that Shipit tracks.

### Impact Explanation
On any Shipit instance configured with multiple GitHub organizations (per the documented `github:` multi-org schema) where at least one organization has not set a `webhook_secret`, an unauthenticated network attacker can forge webhooks for **every other organization's repositories** managed by that same instance. Depending on handler:
- `PushHandler` triggers `stack.sync_github(expected_head_sha:)` on arbitrary stacks belonging to unrelated organizations — this can be chained with the sync/CI-status logic to influence which commits are marked ready, ultimately enabling unauthorized deploys.
- `MembershipHandler` creates/deletes team memberships for the `Shipit.github_teams` authorization system used by `User#authorized?`, so an attacker can add arbitrary GitHub logins to teams that grant Shipit access — escalation into `Shipit.github_teams` authorization.
- `StatusHandler`/`CheckSuiteHandler` can forge green CI/check statuses for commits in other orgs' repos, which stacks rely on before allowing deploy.

This satisfies the "High" impact bar (escalation into `Shipit.github_teams` authorization) and arguably contributes toward "unauthorized deploy" once combined with CI-status spoofing.

### Likelihood Explanation
Requires the multi-org config with at least one organization missing `webhook_secret` — a state the project's own setup docs present as valid/optional, not a hardening violation of "documented mounting." No GitHub credentials, session, or `ApiClient` token are needed; only an HTTP POST to `/github/webhooks` (or wherever mounted) with attacker-chosen JSON and headers `X-Github-Event` / `X-Hub-Signature` (any garbage signature, since it's skipped) is required.

### Recommendation
- Cross-check the organization used to select the webhook secret against `repository.owner.login`/`organization.login` actually referenced by the payload before dispatching to handlers, rejecting mismatches.
- Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is blank for a *specific* organization in multi-org mode; either require a secret per org or fail closed.
- Have handlers validate that the resolved `Repository`'s owner matches the organization whose secret validated the request.

### Proof of Concept
1. Shipit configured with two orgs in `secrets.github`: `trusted-org` (has `webhook_secret` set, hosts sensitive `Stack`s) and `empty-org` (webhook_secret left blank, per documented optional config).
2. Attacker POSTs to the webhooks endpoint with header `X-Github-Event: push`, an arbitrary `X-Hub-Signature`, and body:
```json
{
  "repository": { "owner": { "login": "empty-org" }, "full_name": "trusted-org/critical-service" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>"
}
```
3. `repository_owner` resolves to `empty-org` → `Shipit.github(organization: 'empty-org')` → `verify_webhook_signature` returns `true` immediately (`webhook_secret` blank) regardless of the bogus `X-Hub-Signature`.
4. `PushHandler#process` uses `payload.dig('repository','full_name')` = `trusted-org/critical-service` to locate and sync stacks belonging to `trusted-org`, entirely bypassing that org's own webhook secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
