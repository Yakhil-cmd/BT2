### Title
Sustained high-utilization accrual can permanently freeze an entire market before the index cap - (File: common/src/rates/simulate.rs)

### Summary
A market can reach a state where every subsequent accrual panics while converting scaled balances back to RAY values. Because each pool mutation accrues first, the panic permanently blocks withdrawals, repayments, liquidations, and later index updates for that market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` unconditionally reconstructs total borrowed and supplied value with `scaled_to_original`, which performs the index multiplication before interest is calculated or the borrow-index cap is applied. [1](#0-0) [4](#0-3) 

`update_borrow_index` does cap the resulting index at `MAX_BORROW_INDEX_RAY`, but it first multiplies the old index by the interest factor and does not account for the market’s scaled principal. [5](#0-4) 

Consequently, a sufficiently large book can cross the `i128` RAY-value ceiling while its stored borrow index remains below the protocol cap. [6](#0-5) [7](#0-6) 

### Impact Explanation
Once `borrowed * borrow_index` or `supplied * supply_index` exceeds the representable range, `global_sync` aborts before committing a new timestamp or market state. [8](#0-7) [9](#0-8) 

All normal pool legs load a synced market, so later calls repeat the same arithmetic panic rather than bypassing accrual. [10](#0-9) 

The repository’s regression test demonstrates the end state: `update_indexes`, a one-unit withdrawal, and a repayment all revert with `MathOverflow`, permanently freezing supplier cash and borrower repayment/liquidation paths for the affected market. [11](#0-10) 

### Likelihood Explanation
The reachable path requires a very large market and sustained high utilization over multiple accrual periods, so it is not an immediate one-transaction denial of service. [12](#0-11) 

The concrete test uses an eighteen-decimal market with one billion whole tokens supplied, ninety-eight percent borrowed, and a steep rate curve with a 175 percent maximum borrow rate. [13](#0-12) [14](#0-13) 

Although the test raises market caps to the maximum representable domain, the resulting state is still admitted by the protocol’s own cap bound, and accrual can then be triggered by any caller through the controller’s maintenance path. [15](#0-14) [16](#0-15) 

### Recommendation
Do not perform unbounded `i128` reconstruction of aggregate market value during accrual. [1](#0-0) 

Accrual should either use wider intermediate arithmetic for utilization, debt growth, rewards, and supply distribution, or apply a market-aware bound before any index multiplication can exceed `i128`. [17](#0-16) 

The bound should account for both stored `borrowed` and stored `supplied`, not only `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`, and the failure mode should leave repayment and withdrawal paths executable rather than trapping in the mandatory pre-mutation sync. [5](#0-4) [10](#0-9) 

### Proof of Concept
The in-repository proof constructs a large eighteen-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows ninety-eight percent of it, advances time yearly, and calls the controller’s `update_indexes` maintenance path for the market. [18](#0-17) 

The first failing accrual returns `MathOverflow` while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, showing that the static index cap did not prevent the aggregate-value overflow. [19](#0-18) 

Subsequent `withdraw` and `repay` attempts hit the same panic because they must accrue the market before applying their state transitions. [20](#0-19) [2](#0-1)

pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// Always commits state so same-ledger simulation records the write footprint

    renew_instance(env);

    for hub_asset in hub_assets.iter() {

        interest::global_sync(env, &mut cache);
        events::emit_market_state(env, cache.commit());
    }
