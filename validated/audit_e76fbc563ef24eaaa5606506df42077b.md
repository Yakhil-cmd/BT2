### Title
Terminal escape sequences in agent session log content (tool call args/content) reach the terminal unsanitized via `shared.LogRenderer.Render`/`Follow` - ([File: pkg/cmd/agent-task/shared/log.go])

### Summary
`printLogs`/`followLogs` fetch raw session logs via `CAPIClient.GetSessionLogs` and pass them to `shared.LogRenderer.Render`/`Follow`, which extracts JSON fields (`Content`, tool-call `Arguments`, file paths, commit messages) from attacker-influenceable agent output and writes them to the terminal through `renderRawMarkdown`/`renderFileContentAsMarkdown` → `markdown.Render` (glamour) → `fmt.Fprint(w, rendered)`. None of these steps strip or escape raw ANSI/OSC control sequences before they hit `opts.IO.Out`/the pager.

### Finding Description
The call chain is: `printLogs` (`pkg/cmd/agent-task/view/view.go:370-405`) / `followLogs` (`pkg/cmd/agent-task/create/create.go:263-287`) → `capiClient.GetSessionLogs` → `renderer.Render`/`renderer.Follow` (`pkg/cmd/agent-task/shared/log.go:31-89`) → `renderLogEntry` (`log.go:91-268`) → content-rendering helpers `renderRawMarkdown`/`renderFileContentAsMarkdown`/`renderContentAsJSONMarkdown` (`log.go:271-382`).

`renderLogEntry` extracts `choice.Delta.Content`, tool call `Arguments` fields (e.g. `Path`, `Command`, `Thought`, `PrDescription`, file contents for `view`/`create`/`str_replace` tool calls) directly from JSON-decoded SSE chunks that originate from the agent/session backend. These strings are fed into `renderMarkdownWithFormat` (`log.go:311-329`), which calls `markdown.Render` (glamour, `pkg/markdown/markdown.go:38-40`) and then does `fmt.Fprint(w, rendered)` with no filtering of raw control bytes (ESC, CSI, OSC sequences). Glamour/chroma syntax highlighting preserves the literal source bytes inside code fences (used for `bash`, `view`, `create`, `str_replace`, and JSON tool call outputs), so any embedded escape sequence in file content, command text, or thought/PR-description text is written verbatim to `w` (which is `opts.IO.Out` or a pager) along with glamour's own ANSI styling codes. There is no allowlist/host check relevant here (this isn't a network/URL issue), and no control-character stripping utility is invoked anywhere in this path — `Render` only validates the SSE `data:` prefix and JSON shape (`log.go:58-89`), not the content of string fields once unmarshalled. ### Impact Explanation
An attacker who can influence content that ends up in the agent's chat-completion stream (e.g. a file in a repository that the victim points `gh agent-task create`/`view --log` at, whose contents get echoed back by a `view`/`create`/`str_replace` tool call, or PR-description/thought text reflecting attacker content) can embed OSC 52 (clipboard write), OSC 8 (crafted hyperlink text spoofing), or cursor/screen manipulation sequences. When rendered to a real terminal (not a pager that strips such sequences), this enables terminal state manipulation, prompt/output spoofing, or clipboard exfiltration — matching GitHub's "terminal escape sequence / output spoofing" impact class for CLI tools.

### Likelihood Explanation
Requires the victim to run `gh agent-task create`/`gh agent-task view --log`/`--follow` against a task/session whose agent output includes attacker-influenced content (e.g. a file with embedded escape bytes that the agent's `view`/`create` tool call surfaces, or a crafted PR description/thought reflected by the agent). This is plausible given normal workflows where agents operate on attacker-supplied repository content, but depends on the agent actually reflecting raw bytes rather than sanitizing/escaping them upstream (which I could not verify from the CAPI server side — out of scope for this repo). Within the client code shown, there is no defense-in-depth stripping, so if the upstream content contains raw escapes, they reach the terminal.

### Recommendation
Sanitize/escape raw control characters (ESC, and specifically CSI/OSC introducer sequences) from all string fields extracted from log entries (`Content`, tool-call `Arguments` values, `PrDescription`, `Thought`, file paths/content) before they are wrapped in markdown/code fences and rendered, e.g. by running them through a control-character stripper (keeping only `\n`/`\t`) prior to `renderMarkdownWithFormat`, similar to sanitization already applied to other untrusted text surfaces in the CLI.

```go
func (r *logRenderer) Render(logs []byte, w io.Writer, io *iostreams.IOStreams) (bool, error) {
	lines := slices.DeleteFunc(strings.Split(string(logs), "\n"), func(line string) bool {
		return line == ""
	})

	for _, line := range lines {
		raw, found := strings.CutPrefix(line, "data: ")
		if !found {
			return false, errors.New("unexpected log format")
		}

		// The only log entry type we're interested in is a chat completion chunk,
		// which can be verified by a successful unmarshal into the corresponding
		// type AND the Object field being equal to "chat.completion.chunk". The
		// latter is to avoid accepting an empty JSON object (i.e. "{}"). Also,
		// if the entry is not what we expect, we should just skip and avoid
		// returning an error.
		var entry chatCompletionChunkEntry
		err := json.Unmarshal([]byte(raw), &entry)
		if err != nil || entry.Object != "chat.completion.chunk" {
			continue
		}

		if stop, err := renderLogEntry(entry, w, io); err != nil {
			return false, fmt.Errorf("failed to process log entry: %w", err)
		} else if stop {
			return true, nil
		}
	}

	return false, nil
}
```

```go
// renderRawMarkdown renders the given raw markdown string to the given writer.
// Use for complete markdown content from tool calls that need no conversion.
func renderRawMarkdown(md string, w io.Writer, io *iostreams.IOStreams) error {
	// Glamour doesn't add leading newlines when content is a complete
	// markdown document. So, we must add the leading newline.
	formatFunc := func(s string) string {
		return fmt.Sprintf("\n%s\n\n", s)
	}

	return renderMarkdownWithFormat(md, w, io, formatFunc)
}

// renderMarkdownWithFormat renders the given markdown string to the given writer.
// If a formatFunc is provided, the md string is ran through it before
// rendering. This can be used to add newlines before and after the content.
func renderMarkdownWithFormat(md string, w io.Writer, io *iostreams.IOStreams, formatFunc func(string) string) error {
	rendered, err := markdown.Render(md,
		markdown.WithTheme(io.TerminalTheme()),
		markdown.WithWrap(io.TerminalWidth()),
	)

	if err != nil {
		return fmt.Errorf("failed to render markdown: %w", err)
	}

	rendered = strings.TrimSpace(rendered)
	if formatFunc != nil {
		rendered = formatFunc(rendered)
	}

	fmt.Fprint(w, rendered)

	return nil
}
```

```go
// renderFileContentAsMarkdown renders the given content as markdown
// based on the file extension of the path.
func renderFileContentAsMarkdown(path, content string, w io.Writer, io *iostreams.IOStreams) error {
	lang := filepath.Ext(filepath.ToSlash(path))

	if lang == ".md" {
		return renderRawMarkdown(content, w, io)
	}

	md := fmt.Sprintf("```%s\n%s\n```", lang, content)
	// Glamour adds leading newlines when content is only a code block,
	// so we only want to add a trailing newline.
	formatFunc := func(s string) string {
		return fmt.Sprintf("%s\n\n", s)
	}

	return renderMarkdownWithFormat(md, w, io, formatFunc)
}
```

```go
func printLogs(opts *ViewOptions, capiClient capi.CapiClient, sessionID string) error {
	ctx := context.Background()

	renderer := opts.LogRenderer()

	if err := opts.IO.StartPager(); err == nil {
		defer opts.IO.StopPager()
	} else {
		fmt.Fprintf(opts.IO.ErrOut, "error starting pager: %v\n", err)
	}

	if opts.Follow {
		var called bool
		fetcher := func() ([]byte, error) {
			if called {
				opts.Sleep(defaultLogPollInterval)
			}
			called = true
			raw, err := capiClient.GetSessionLogs(ctx, sessionID)
			if err != nil {
				return nil, err
			}
			return raw, nil
		}

		return renderer.Follow(fetcher, opts.IO.Out, opts.IO)
	}

	raw, err := capiClient.GetSessionLogs(ctx, sessionID)
	if err != nil {
		return fmt.Errorf("failed to fetch session logs: %w", err)
	}

	_, err = renderer.Render(raw, opts.IO.Out, opts.IO)
	return err
}
```
