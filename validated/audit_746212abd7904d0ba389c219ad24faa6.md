The CVE-2019-3794 bug class (missing `X-Frame-Options` header enabling clickjacking) applies specifically to HTML frontend pages rendered in a browser where a user can be tricked into clicking UI elements loaded in an invisible iframe. The Polkadot SDK's relevant network-facing service is the JSON-RPC server implemented in `substrate/client/rpc-servers/src/lib.rs` and `substrate/client/rpc-servers/src/utils.rs`, which serves JSON-RPC responses over HTTP/WS with configurable CORS via `tower_http::cors::CorsLayer` [1](#0-0) [2](#0-1) . This server does not render HTML or serve any interactive frontend that a user clicks through; its middleware stack only handles host filtering, a health-check proxy, and CORS, with no HTML templating or UI surface [3](#0-2) .

Clickjacking's violated invariant — preventing a legitimate page's clickable UI from being overlaid/framed by an attacker page — requires a browser-rendered, session-authenticated frontend with actionable buttons/forms (as in Cloud Foundry UAA's login/consent pages). No such component exists in this repository's production scope; the node only exposes a JSON-RPC API consumed programmatically (or via `polkadot.js.org`, a separate external application, not part of this codebase) [4](#0-3) . Forcing this Web2 UI/browser-security header issue onto a headless JSON-RPC node service would not be a demonstrable analog, so no finding is reported.

pub(crate) fn try_into_cors(
	maybe_cors: Option<Vec<String>>,
) -> Result<CorsLayer, Box<dyn StdError + Send + Sync>> {
	if let Some(cors) = maybe_cors {
		let mut list = Vec::new();

		for origin in cors {
			list.push(HeaderValue::from_str(&origin)?)
		}

		Ok(CorsLayer::new().allow_origin(AllowOrigin::list(list)))
	} else {
		// allow all cors
		Ok(CorsLayer::permissive())
	}
}
