### Title
Webhook signing-organization is never bound to the repository the payload actually mutates - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit supports per-organization GitHub App configuration, keyed by organization login (evidenced by the `Shipit.github(organization:)` lookup and the dedicated `GithubOrganizationUnknown` rescue clause) [1](#0-0) . The webhook signature is verified using the secret belonging to whatever organization the *attacker's own payload* claims to be from, but every downstream handler resolves the target repository/stack from a completely different, uncorrelated field of the same attacker-controlled JSON body. No code ever checks that the organization whose secret validated the signature actually owns the repository being acted upon.

### Finding Description
`WebhooksController#verify_signature` derives `repository_owner` from the payload itself (`params.dig('repository','owner','login')` or `params.dig('organization','login')`), fetches that organization's `GithubApp` config, and validates `X-Hub-Signature` against that organization's `webhook_secret` [2](#0-1) [3](#0-2) . `GithubApp#verify_webhook_signature` is a pure HMAC check over the raw body using that organization's configured secret [4](#0-3) .

Once the signature is accepted, `create` dispatches the entire raw payload to handlers [5](#0-4) . Every handler resolves the target repository independently via `Handler#repository_name`, which reads `payload.dig('repository', 'full_name')` — a separate JSON field never cross-checked against `repository_owner` [6](#0-5) .

Because the attacker fully controls the raw JSON body they sign, they can set `repository.owner.login` (or `organization.login`) to an organization whose webhook secret they know (e.g., an org they administer that is also onboarded to the same Shipit instance), while setting `repository.full_name` to any *other* onboarded organization/repository. The signature check only proves "this body was signed with Org A's secret" — it never proves "this body concerns a repository owned by Org A." The binding `verified_signing_org == acted_upon_repository_owner` is never enforced.

Concrete exploitation paths once the signature check is satisfied for the attacker's own organization:
- `PushHandler#process` looks up stacks purely from `repository.full_name` and enqueues a sync for `params.after` on the matching branch of the victim's stack [7](#0-6) .
- `StatusHandler#process` is even less scoped: it looks up commits **globally by sha**, with no repository/organization filter at all, and writes a CI status onto them [8](#0-7) . Any commit sha belonging to any repository tracked by the shared Shipit instance can have a forged `success`/`failure` status attached by an attacker who only controls a different, unrelated organization's webhook secret.

### Impact Explanation
A forged `success` status on a specific commit sha in a victim's repository can satisfy required-status-check gating used by Shipit to permit merges/deploys, and a forged `push` event can force `GithubSyncJob` to advance a victim stack to an attacker-chosen `after` sha. Both can result in an unauthorized deploy/merge on a stack the attacker does not own or have write access to — this falls in the "Critical: unauthorized deploy, rollback or merge" bucket, since it crosses from one organization's trust boundary into another's without ever touching that victim organization's real webhook secret.

### Likelihood Explanation
Exploitability depends entirely on the deployment supporting multiple organizations with distinct GitHub Apps/webhook secrets in one Shipit instance (a documented, supported configuration, as shown by the org-keyed `Shipit.github` lookup and `GithubOrganizationUnknown` handling). Any actor who legitimately administers the webhook secret for *any one* onboarded organization — not the victim's — can attack every other organization/repository/commit tracked by the same Shipit instance. No access to the victim's secrets, tokens, or Shipit session is required.

### Recommendation
After signature verification, require the derived `repository_owner`/organization to match the owner encoded in `repository.full_name` used by handlers before processing, and scope `StatusHandler`'s commit lookup by repository/stack rather than by a global `sha` search across all tracked repositories.

### Proof of Concept
1. Attacker administers Org A's webhook config for a repository onboarded in the shared Shipit instance and knows Org A's `webhook_secret`.
2. Attacker crafts a `push` (or `status`) JSON payload where `repository.owner.login` = `"org-a"` but `repository.full_name` = `"org-b/victim-repo"` (Org B being any other org tracked by the same instance).
3. Attacker computes `X-Hub-Signature` over that raw body using Org A's known secret and POSTs to `/github/webhooks`.
4. `verify_signature` resolves `Shipit.github(organization: "org-a")` and successfully verifies the signature against Org A's secret [9](#0-8) .
5. `PushHandler`/`StatusHandler` then act on `org-b/victim-repo`'s stack/commit using data entirely controlled by the attacker [10](#0-9) [7](#0-6) .

**Uncertainty note:** I could not fully retrieve `lib/shipit.rb`'s `Shipit.github` implementation (tool budget exhausted before I could read its body), so I cannot show the exact multi-organization config structure line-by-line; the org-keyed lookup and `GithubOrganizationUnknown` rescue in `webhooks_controller.rb` strongly imply it exists, but confirming the precise config schema would need a follow-up read of `lib/shipit.rb`.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
