### Title
Credential cache scoped by host, not path — cross-repo/submodule credential disclosure via `git credential.helper cache` — ([File: main.go])

### Summary
`git-sync` configures Git's credential subsystem to (1) globally enable a caching helper with a long TTL and (2) `approve` (store) whichever username/password it is given for a URL, but never scopes or revokes that approval to the specific path it was intended for and never enables `credential.useHttpPath`. This mirrors the reported NFT bug: an "approval" granted for one specific resource is never invalidated/scoped, so it can later be reused to access a different resource that should not have been authorized — in this case, a different repository/submodule path on the same host.

### Finding Description
`SetupDefaultGitConfigs` sets the credential helper globally with a 3600-second cache and never sets `credential.useHttpPath`: [1](#0-0) 

Credentials (from `--username`/`--password[-file]`, `--credential`, `--askpass-url`, or the GitHub App token flow) are all funneled into `StoreCredentials`, which calls `git credential approve` for a given `url`: [2](#0-1) 

This approval is invoked from `refreshCreds`, once per credential entry, before every sync (including submodule-related credentials supplied via `--credential`): [3](#0-2) 

By default, Git's credential matching (and the `cache` helper's lookup key) is `protocol://host[:port]` — it ignores the URL path unless `credential.useHttpPath=true` is configured. Since git-sync never sets that option, once a credential is approved for `https://host/orgA/main-repo`, it remains cached and will be handed out by the `cache` daemon for **any** URL matching `https://host`, including `https://host/orgA/../attacker-controlled-path` or a submodule URL on the same host that an attacker introduces via repo content (e.g. `.gitmodules`), for the full 3600-second cache window — regardless of whether that submodule/path was ever supposed to be reachable with those credentials. The credential "approval" is never scoped down or revoked per-repository/per-path, analogous to `getApproved[_tokenId]` never being cleared after a transfer in the reported Solidity bug: a grant intended for one specific target persists and is honored for a different target than the one it was created for.

The e2e test `e2e::submodule_sync_over_http_different_passwords` demonstrates the intended isolation model (one credential per submodule host, each on a distinct port/container), which only works because each submodule happens to sit on a different host in the test; it does not exercise same-host, different-path submodules, so the missing `useHttpPath` scoping is not caught: [4](#0-3) 

### Impact Explanation
If an attacker who can influence repository content (a `.gitmodules` entry, since git-sync recursively updates submodules per `configureWorktree`) adds a submodule pointing to a different path/repo on the same host as the primary `--repo` (or as a prior `--credential` entry), git's credential cache will transparently supply the previously-approved username/password (or GitHub App installation token, or askpass-url secret) to that attacker-chosen submodule endpoint for up to `credential.helper cache --timeout 3600`. This results in credential/token disclosure to a path the operator never intended to grant access to — impacting confidentiality of secrets mounted into the sidecar (`--password-file`, `--github-app-*`, `--askpass-url` secrets), and could be used to exfiltrate long-lived tokens to an attacker-controlled repo path.

### Likelihood Explanation
Reachable purely from untrusted repo content: any commit that git-sync fetches (main repo or nested submodule) can add/modify `.gitmodules` to introduce a same-host submodule URL, without needing operator/config changes, malicious node, or leaked keys. It requires the target Git host to allow arbitrary paths to be created/pointed-to by an attacker with only push access to a monitored branch/ref (a realistic "attacker-pushed commit" scenario per the analog scope), and does depend on git-sync being configured with HTTP(S) credentials (`--username`/`--password-file`, `--credential`, `--askpass-url`, or GitHub App auth) with submodules enabled (the default `--submodules=recursive`).

### Recommendation
- Set `credential.useHttpPath=true` globally in `SetupDefaultGitConfigs` (or configure per-URL scoping) so cached/approved credentials are only replayed for the exact path they were approved for.
- Reduce `credential.helper cache --timeout` and call `git credential reject` for the previous URL/credential before approving a new one when the target host/path changes across a sync (analogous to clearing `getApproved[_tokenId]` on transfer).
- When using `--credential` for submodules, prefer per-repository config (`http.<url>.extraHeader`/scoped credential helpers) rather than a single global cache shared by the whole process across all repos and submodules.

### Proof of Concept
1. Configure git-sync with `--repo=https://git.example.com/org/main.git --username=svc --password-file=/secrets/pw --submodules=recursive` (default credential helper config from `SetupDefaultGitConfigs`, no `useHttpPath`).
2. `refreshCreds`/`StoreCredentials` runs `git credential approve` for `url=https://git.example.com/org/main.git`, cached for 3600s via the `cache` helper: [2](#0-1) .
3. An attacker with push access to `main.git` (or a repo it already vendors as a submodule) adds a `.gitmodules` entry pointing to `https://git.example.com/attacker/exfil.git` and commits it.
4. During the next sync, `configureWorktree` runs `git submodule update --init [--recursive]`: [5](#0-4) . Because credential matching is host-scoped (no `useHttpPath`), Git's `credential-cache` transparently supplies the `svc`/password credentials for `https://git.example.com/attacker/exfil.git`.
5. The attacker-controlled server at that path receives the Basic-Auth credentials in the HTTP request, disclosing the secret intended only for `org/main.git`.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
