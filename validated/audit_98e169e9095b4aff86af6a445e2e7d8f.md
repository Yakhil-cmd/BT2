### Title
Last-Vote-Wins in `none`-Mode Header Governance Allows Minority GC Member to Override Majority and Redirect KAIA Reward Distribution — (`File: kaiax/gov/headergov/impl/header.go`)

---

### Summary

In `none`-mode header governance, the ratification rule is "the last vote in the epoch wins per parameter." All votes are permanently public (inscribed in block headers). A single GC member who is the last proposer before the epoch boundary can observe every earlier vote and cast a counter-vote that unilaterally overrides the collective preference of all other GC members, changing protected governance parameters — including `reward.mintingamount`, `reward.ratio`, and `governance.governingnode` — that directly control KAIA minting and reward distribution.

---

### Finding Description

`getExpectedGovernance` in `kaiax/gov/headergov/impl/header.go` collects all votes cast in the previous epoch, sorts them by ascending block number, and iterates through them, with each successive vote for the same parameter overwriting the previous one: [1](#0-0) 

```go
func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
    prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
    prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
    govs := make(gov.PartialParamSet)

    sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
    slices.Sort(sortedVoteBlocks)

    for _, voteBlock := range sortedVoteBlocks {
        vote := prevEpochVotes[voteBlock]
        govs.Add(string(vote.Name()), vote.Value())   // last writer wins
    }
    return headergov.NewGovData(govs)
}
```

The README explicitly documents this rule: [2](#0-1) 

> `none` mode: all members of the GC can vote. For each governance parameter, **the last vote in the epoch will be ratified.**

The default governance mode is `none`: [3](#0-2) 

Because every vote is written into `header.Vote` and is immediately visible on-chain, any GC member can:
1. Monitor all votes cast by other GC members throughout the epoch.
2. Wait until the final block(s) of the epoch where they are the proposer.
3. Cast a vote for any parameter with any value, overriding every earlier vote.

The `VerifyGov` check at the epoch boundary only verifies that the proposer's announced `header.Governance` matches the locally-derived last-vote result — it does not check whether the last vote represents a majority or consensus: [4](#0-3) 

---

### Impact Explanation

The parameters controllable via `none`-mode governance include:

- `reward.mintingamount` — controls KAIA minted per block (inflation).
- `reward.ratio` — controls the split of block rewards among validators, KIF, and KEF.
- `reward.kip82ratio` — controls the proposer/staker split.
- `governance.governingnode` — controls who holds unilateral authority in `single` mode.
- `governance.govparamcontract` — controls which contract governs parameters post-Kore. [5](#0-4) 

A single GC member who is the last proposer before the epoch boundary can redirect KAIA reward distribution for the entire next epoch (604,800 blocks on Mainnet-equivalent networks) by overriding the collective vote. This constitutes unauthorized reward distribution manipulation affecting KAIA.

---

### Likelihood Explanation

- **Trigger**: Any GC member in a network running `none`-mode governance. `none` is the default mode (`DefaultGovernanceMode = "none"`).
- **Observability**: All votes are public and immediately readable from block headers via `governance_votes` API.
- **Timing**: The attacker only needs to be the proposer for one block near the end of the epoch. In a network with N validators, the probability of being the last proposer before the epoch boundary is approximately 1/N per epoch, but the attacker can also time their `governance_vote` API call to coincide with their next scheduled proposal slot near the epoch end.
- **No collusion required**: A single GC member acting alone is sufficient.

---

### Recommendation

**Short term:**
- In `none` mode, require a quorum (e.g., majority of GC members) to agree on a value before it is ratified, rather than using last-vote-wins.
- Alternatively, freeze the vote tally at a fixed cutoff block before the epoch boundary (e.g., `epoch - N` blocks) so that late votes cannot override earlier ones.

**Long term:**
- Document the strategic risk of `none` mode explicitly.
- Consider a commit-reveal scheme or time-weighted voting to eliminate the late-vote advantage.
- Add a test that demonstrates a minority voter overriding a majority preference by voting last.

---

### Proof of Concept

**Setup**: Network with `governance.governancemode = "none"`, epoch = 604800, 5 GC members (A, B, C, D, E).

1. At block 100 of epoch K, GC members A, B, C, D each call `governance_vote("reward.mintingamount", 6400000000000000000)`. Their votes are inscribed in their respective proposal blocks.
2. GC member E monitors the chain via `governance_votes` API and observes all four votes.
3. E waits until block 604799 (last block of epoch K) where E is the proposer.
4. E calls `governance_vote("reward.mintingamount", 9600000000000000000)`.
5. At block 604800 (epoch boundary), the proposer runs `getExpectedGovernance(604800)`, which iterates votes sorted by block number. E's vote at block 604799 is last, so `govs["reward.mintingamount"] = 9600000000000000000` overwrites all four earlier votes.
6. `header.Governance` is set to `{"reward.mintingamount": 9600000000000000000}`. `VerifyGov` passes because the announced value matches the locally-derived last-vote result.
7. From block 604800 onward, KAIA minting is 9.6 KAIA/block instead of the 6.4 KAIA/block that 4 out of 5 GC members voted for — a 50% inflation increase imposed by a single minority member. [6](#0-5) [7](#0-6)

```go
// VerifyGov checks the following:
// (1) governance must be empty in non-epoch block,
// (2) if there are no votes in the previous epoch, governance must be empty,
// (3) if any vote exists in the previous epoch, governance must not be empty,
// (4) the json must not contain unknown fields,
// (5) the parsed json must exactly match the map derived locally from the previous epoch's votes.
func (h *headerGovModule) VerifyGov(header *types.Header) error {
	// (1)
	if header.Number.Uint64()%h.epoch != 0 {
		if len(header.Governance) > 0 {
			logger.Error("governance is not allowed in non-epoch block", "num", header.Number.Uint64())
			return ErrGovInNonEpochBlock
		} else {
			return nil
		}
	}

	// (2), (3)
	expected := h.getExpectedGovernance(header.Number.Uint64())
	if len(header.Governance) == 0 {
		if len(expected.Items()) != 0 {
			return ErrGovVerification
		}

		return nil
	}

	// (4)
	var gb headergov.GovBytes = header.Governance
	actual, err := gb.ToGovData()
	if err != nil {
		logger.Error("DeserializeHeaderGov error", "num", header.Number.Uint64(), "governance", gb, "err", err)
		return err
	}

	// (5)
	if !reflect.DeepEqual(expected, actual) {
		logger.Error("Governance mismatch", "expected", expected, "actual", actual)
		return ErrGovVerification
	}

	return nil
```

```go
func (h *headerGovModule) AddVote(blockNum uint64, vote headergov.VoteData) {
	h.mu.Lock()
	defer h.mu.Unlock()

	epochIdx := calcEpochIdx(blockNum, h.epoch)

	if _, ok := h.groupedVotes[epochIdx]; !ok {
		h.groupedVotes[epochIdx] = make(headergov.VotesInEpoch)
	}
	h.groupedVotes[epochIdx][blockNum] = vote
}
```
