### Title
Reward-commission distribution (`distribute_reward_commissions`) processes all vote/commission accounts synchronously in a single epoch-boundary block, unlike stake rewards which are explicitly partitioned - ([File: runtime/src/bank/partitioned_epoch_rewards/calculation.rs])

### Summary
`Bank::process_new_epoch` performs epoch-boundary reward work by calling `begin_partitioned_rewards`, which first calls `distribute_reward_commissions` [1](#0-0) . That function loads and rewards *every* commission/vote account for the epoch in one synchronous pass via `load_and_reward_commission_accounts` [2](#0-1)  and then stores them all at once with `store_commission_accounts_partitioned` [3](#0-2) . Both happen entirely inside the single epoch-boundary block that runs `begin_partitioned_rewards` [4](#0-3) .

This mirrors the external report's bug class: an unbounded loop over a growing collection of accounts (there, connected vaults; here, all rewarded vote/commission accounts) performed inside a single bounded-resource unit of work (there, one `performUpkeep` transaction with a 5M gas cap; here, one block that must be produced/replayed within the cluster's target slot time). By contrast, the *stake* reward portion of the same subsystem was deliberately redesigned to avoid exactly this hazard: `get_reward_distribution_num_blocks` explicitly caps and chunks stake-reward stores across up to 10% of an epoch's slots [5](#0-4) , and `distribute_partitioned_epoch_rewards` distributes only one partition's worth of stake rewards per block [6](#0-5) . No equivalent partitioning exists for the vote-account commission distribution path.

### Finding Description
`load_and_reward_commission_accounts` iterates in parallel (via `thread_pool.install`) over `reward_commissions`, one entry per distinct commission-receiving pubkey (by default every voting vote account, or, under `custom_commission_collector`, an arbitrary external collector pubkey) [7](#0-6) . For each entry it performs an account read (`get_account_with_fixed_root_no_cache`), potential rent/collector-type checks, and lamport arithmetic. `store_commission_accounts_partitioned` then performs a single `store_accounts` write for the entire resulting set [3](#0-2) . Both operations, along with metric computation, execute inline inside `begin_partitioned_rewards`, which is called synchronously from `process_new_epoch` on the epoch-boundary block [8](#0-7) .

The number of iterations scales with `num_filtered_vote_accounts`, which is the count of the VAT-filtered vote-account snapshot capped at `MAX_ALPENGLOW_VOTE_ACCOUNTS` [9](#0-8) . While this cap bounds the worst case somewhat, all of that bounded (but potentially large) work is still forced into the single epoch-boundary block rather than being spread across multiple blocks the way stake rewards are. If this per-block workload (account loads + rent/collector checks + a single large `store_accounts` batch) grows large enough — e.g., under `custom_commission_collector`, where many distinct external collector accounts could each require a separate rent/incinerator check — replay/production of that one block can take meaningfully longer than the cluster's target slot time, directly analogous to the external report's `performUpkeep` exceeding its 5M gas budget due to an unbounded `recalculateVaultsCreditCapacity` loop tied to vault count.

### Impact Explanation
If the epoch-boundary block's reward-commission work exceeds the effective slot-time budget, validators may fail to produce or replay that block within its slot window, causing skipped slots at every epoch boundary, or in the worst case cluster-wide slowdown/liveness degradation precisely at epoch transitions (an epoch-boundary halt/stall analog). This differs from the deliberately partitioned stake-reward design and represents a place where the reward-distribution path retains the same "do unbounded work in one block" pattern that the rest of the subsystem was built to avoid.

### Likelihood Explanation
Likelihood is currently bounded by `MAX_ALPENGLOW_VOTE_ACCOUNTS` and by the modest cost of the per-account work (a few lamport/rent checks) relative to typical validator-set sizes today. However, likelihood increases if the VAT filter/limit is raised, if `custom_commission_collector` proliferates many distinct external collector pubkeys that each trigger `collector_type_checked` rent computations, or under account-read latency spikes (e.g., cold/large accounts DB), making this a real but currently secondary-order risk rather than an immediately exploitable one.

### Recommendation
Partition `distribute_reward_commissions`/`load_and_reward_commission_accounts`/`store_commission_accounts_partitioned` across multiple blocks the same way `store_stake_accounts_in_partition` is chunked via `get_reward_distribution_num_blocks`, so that vote-account commission distribution work is bounded per-block regardless of the total number of rewarded vote/commission accounts.

### Proof of Concept
Not independently reproducible from the indexed codebase alone (no benchmarking harness for `distribute_reward_commissions` timing at scale was found in the search); the analog is derived structurally from comparing `distribute_reward_commissions` (single-block, unbounded per-call cost) against the explicitly partitioned `distribute_partitioned_epoch_rewards`/`get_reward_distribution_num_blocks` stake-reward path [5](#0-4) . Confirming actual wall-clock impact would require a benchmark run with a large (`MAX_ALPENGLOW_VOTE_ACCOUNTS`-sized or large `custom_commission_collector` set) commission-account set measuring `load_and_reward_commission_accounts_us` and `store_commission_accounts_us` against the target slot time — this repo's index does not contain such a benchmark.

    fn load_and_reward_commission_accounts(
        &self,
        reward_commissions: &RewardCommissions,
        thread_pool: &ThreadPool,
    ) -> RewardCommissionAccounts {
        let reserved_account_keys = &self.reserved_account_keys;
        let rent = &self.rent_collector().rent;
        let feature_snapshot = self.feature_set.snapshot();
        let relax_post_exec_min_balance_check = feature_snapshot.relax_post_exec_min_balance_check;
        let custom_commission_collector = feature_snapshot.custom_commission_collector;
        let total_non_incinerator_burned_lamports = AtomicU64::new(0);
        let total_incinerator_lamports = AtomicU64::new(0);

        let accounts_with_rewards: Vec<_> = thread_pool.install(|| {
            reward_commissions
                .par_iter()
                .filter_map(
                    |(
                        commission_pubkey,
                        RewardCommission {
                            commission_bps,
                            commission_lamports,
                            burned_lamports,
                            is_vote_account,
                        },
                    )| {
                        let maybe_commission_account =
                            self.get_account_with_fixed_root_no_cache(commission_pubkey);
                        let mut commission_account = if custom_commission_collector {
                            // If the account doesn't exist, the vote commission
                            // may be enough lamports to cover rent-exemption
                            // and properly create the commission account.
                            maybe_commission_account.unwrap_or_default()
                        } else {
                            // Before SIMD-0232, commission accounts were always
                            // vote accounts, which cannot be closed unless the
                            // account hasn't voted for at least a full epoch.
                            // This means that `maybe_commission_account` should
                            // always exist.
                            let Some(commission_account) = maybe_commission_account else {
                                debug!(
                                    "commission account {commission_pubkey} missing at \
                                     distribution time"
                                );
                                return None;
                            };
                            commission_account
                        };
                        if *burned_lamports != 0 {
                            total_non_incinerator_burned_lamports
                                .fetch_add(*burned_lamports, Relaxed);
                        }
                        let pre_lamports = commission_account.lamports();
                        if let Err(err) =
                            commission_account.checked_add_lamports(*commission_lamports)
                        {
                            debug!("reward redemption failed for {commission_pubkey}: {err:?}");
                            total_non_incinerator_burned_lamports
                                .fetch_add(*commission_lamports, Relaxed);
                            return None;
                        }
                        if !is_vote_account {
                            match Self::collector_type_checked(
                                commission_pubkey,
                                pre_lamports,
                                &commission_account,
                                reserved_account_keys,
                                rent,
                                relax_post_exec_min_balance_check,
                            ) {
                                Ok(ExternalCollectorType::SystemAccount) => {}
                                Ok(ExternalCollectorType::Incinerator) => {
                                    total_incinerator_lamports
                                        .fetch_add(*commission_lamports, Relaxed);
                                }
                                Err(err) => {
                                    debug!(
                                        "reward redemption failed for {commission_pubkey} due to \
                                         commission account error: {err:?}"
                                    );
                                    total_non_incinerator_burned_lamports
                                        .fetch_add(*commission_lamports, Relaxed);
                                    return None;
                                }
                            }
                        }
                        Some((
                            *commission_pubkey,
                            RewardInfo {
                                reward_type: RewardType::Voting,
                                lamports: *commission_lamports as i64,
                                post_balance: commission_account.lamports(),
                                commission_bps: *commission_bps,
                            },
                            commission_account,
                        ))
                    },
                )
                .collect()
        });

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }
