### Title
Unhandled exception during unit-hash-to-sign computation for a malformed unit field (e.g. `alt`) crashes the whole node — ([File: object_hash.js])

### Summary
`getUnitHashToSign()` in `object_hash.js` serializes the naked unit object to compute the hash that authors sign. It is called synchronously, without a `try/catch`, from `validateAuthors()` in `validation.js` while a single posted unit/joint is being validated. Fields such as `alt` are accepted by the top-level field whitelist but are never type-checked before this serialization step runs. If `getSourceString`/`getJsonSourceString` (the same serialization family used by `object_length.getLength`, which explicitly `throw`s on unrecognized JS types) encounters a value type it does not know how to encode, it throws. Because this throw happens outside any `try/catch` in the synchronous portion of unit validation, it propagates as an uncaught exception. `network.js` installs a global `process.on('uncaughtException', …)` handler that deliberately re-throws to crash the whole node process “to avoid ending up in an inconsistent state.” A single unprivileged peer that posts one malformed unit can therefore crash every full node that receives and validates that unit — this is the same bug class as CVE-2024-6350 (a malformed, attacker-supplied packet reaching a low-level serialization/parsing routine and causing an unhandled fault that terminates the process).

### Finding Description
- `validate()` in `validation.js` runs a pipeline of validation steps via `async.series`, one of which is `validateAuthors(conn, objUnit.authors, objUnit, objValidationState, cb)`. [1](#0-0) 
- `validateAuthors()` immediately computes `objValidationState.unit_hash_to_sign = objectHash.getUnitHashToSign(objUnit);` before doing anything asynchronous, and this call is **not** wrapped in a `try/catch`. [2](#0-1) 
- `getUnitHashToSign()` builds a "naked" copy of the whole unit (headers + messages metadata, including top-level fields like `alt`, `witness_list_unit`/`witnesses`, `parent_units`, `last_ball`, `last_ball_unit`) and feeds it into `getSourceString`/`getJsonSourceString` for hashing. [3](#0-2) [4](#0-3) 
- The sibling serialization helper used for size accounting, `object_length.getLength`, demonstrates that this whole family of serializers is written to `throw Error("unknown type=" + …)` for any value whose `typeof` is not `string`, `number`, `object`, or `boolean` (e.g. `undefined`), confirming that these generic object-walking serializers are not defensive against unexpected field shapes. [5](#0-4) 
- Earlier steps in `validate()` whitelist the unit's top-level fields (including `alt`) via `hasFieldsExcept`, but do not constrain the *type* of `alt` (e.g. that it must be a string) before `validateAuthors` is reached. [6](#0-5) 
- Any synchronous exception thrown during this stage of validation is not caught by `validate()`'s `async.series` error handler (that handler only receives errors passed to `cb(err)`, not thrown exceptions) and bubbles up out of the `mutex.lock`/`db.takeConnectionFromPool` callback chain, ultimately surfacing as a Node.js `uncaughtException`.
- The global handler in `network.js` explicitly re-throws to terminate the process rather than attempting recovery, by design ("crash the process to avoid ending up in an inconsistent state"). [7](#0-6) 

This mirrors the CVE-2024-6350 bug class: a malformed, low-privilege-supplied input (there, a crafted 802.15.4 MAC frame; here, a crafted joint/unit with an unexpected field type) reaches a low-level parsing/serialization routine that has an unguarded fault path, and that fault directly aborts the whole running process.

### Impact Explanation
Any single node or light client relaying/receiving the crafted joint over the P2P layer runs it through `validate()`. Reaching the unguarded `getUnitHashToSign()` call crashes the *entire* ocore process on that node — not just rejection of the bad unit. Because this is triggered inside core unit validation (which every full node performs on every joint it receives), a broadcasted malformed unit can be used to repeatedly crash relay nodes/hubs/witnesses across the network, disrupting the network's ability to confirm new units until operators intervene or a process supervisor restarts the node (directly analogous to the CVE's "watchdog reset clears the error condition" behavior).

### Likelihood Explanation
The attack requires only the ability to construct and broadcast a single unit/joint — no privileged keys, no existing balance, and no cooperation from other peers, since crafting a syntactically-valid-but-type-invalid `alt` (or similar unchecked) field is possible for any unprivileged unit poster. The exact reachability depends on whether `getSourceString`/`getJsonSourceString` truly lacks defensive type handling for every field position reachable this way; I was not able to view the full body of `getSourceString` in `string_utils.js` (only an unrelated 106–210 slice was retrievable), so I cannot 100% confirm the precise throwing branch inside `getSourceString` itself — this is inferred from the parallel, confirmed-throwing behavior of the sibling `object_length.getLength` serializer and from the absence of any type check on `alt` before this call. This is the one uncertain link in the chain and should be verified directly against `getSourceString`'s implementation before treating this as fully proven.

### Recommendation
- Add explicit type validation for all unit-header fields (especially `alt`, `witness_list_unit`, `witnesses`) before any serialization/hash computation is attempted.
- Wrap `objectHash.getUnitHashToSign(objUnit)` in `validateAuthors()` in a `try/catch` and convert failures into a normal `ifUnitError`/`ifJointError` callback rather than letting them escape as uncaught exceptions, consistent with how nearby hash calculations (`getUnitHash`, payload hash, payload commission) are already defensively wrapped. [8](#0-7) [9](#0-8) 
- Audit `getSourceString`/`getJsonSourceString` in `string_utils.js` for any code path that can `throw` on attacker-controlled data reachable from unit validation, and make them return graceful errors instead of throwing.

### Proof of Concept
1. Craft a unit whose top-level `alt` field (or another whitelisted-but-untyped field) is set to a JS value/type that the object serializer does not expect (e.g. `undefined`-producing shape, deeply nested unsupported type) while keeping all previously-checked fields (`payload_hash`, `payload_location`, sorted `authors`, valid addresses, commissions, etc.) internally consistent so the unit reaches `validateAuthors()`.
2. Broadcast this joint to any full node/hub.
3. The node calls `validate()` → `validateAuthors()` → `objectHash.getUnitHashToSign(objUnit)`, which throws synchronously and uncaught.
4. `process.on('uncaughtException', …)` in `network.js` logs the error and re-throws, terminating the node process.
5. Repeating step 2 against other nodes/hubs on the network disrupts their ability to keep validating/confirming new units.

function getUnitHashToSign(objUnit) {
	var objNakedUnit = getNakedUnit(objUnit);
	for (var i=0; i<objNakedUnit.authors.length; i++)
		delete objNakedUnit.authors[i].authentifiers;
	var sourceString = (typeof objUnit.version === 'undefined' || objUnit.version === constants.versionWithoutTimestamp) ? getSourceString(objNakedUnit) : getJsonSourceString(objNakedUnit);
	return crypto.createHash("sha256").update(sourceString, "utf8").digest();
}

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
}
