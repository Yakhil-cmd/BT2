The ALPINE-CVE-2026-8458 report describes a libcurl connection-pool reuse bug affecting Negotiate-authenticated HTTP connections — a C library networking issue entirely internal to `curl`'s connection cache/matching logic. Searching the repository shows `curl` only appears as an external CLI tool invoked from shell scripts, CI/test-fixture downloaders, and documentation examples [1](#0-0) [2](#0-1) [3](#0-2) , none of which are production runtime/consensus code reachable by an unprivileged on-chain actor.

There is no analogous "wrong connection reuse due to missing authentication-context check" pattern in the FRAME/XCM/bridges production code paths (extrinsic dispatch, XCM origin/reserve conversion, bridge proof verification, etc.). The closest conceptually related code — libp2p connection/notification-substream state machines [4](#0-3)  and the RPC `ConnectionManager` pool used by `remote-externalities` tooling [5](#0-4)  — are node-internal networking/tooling components, not exposed to an attacker via a signed extrinsic, contract call, or XCM message, and reuse peer/service identity keyed on `PeerId`/`ConnectionId`/URI rather than any authentication-service selector, so the specific "wrong service reused" invariant from the CVE does not map onto them. No credible Polkadot SDK analog satisfying the required real user-entry-point criteria was found; a dependency-only/tooling-only finding is explicitly excluded by the method.

/// Manages WebSocket client connections for parallel workers.
///
/// The pool is shared across all worker clones, so dropping a provider is seen by every worker. The
/// connecting URI is stored next to each client so the pool can be filtered without locking.
#[derive(Clone)]
pub(crate) struct ConnectionManager {
	clients: Arc<tokio::sync::RwLock<Vec<(String, Arc<tokio::sync::Mutex<Client>>)>>>,
}

impl ConnectionManager {
	pub(crate) fn new(clients: Vec<(String, Arc<tokio::sync::Mutex<Client>>)>) -> Result<Self> {
		if clients.is_empty() {
			return Err("At least one client must be provided");
		}

		Ok(Self { clients: Arc::new(tokio::sync::RwLock::new(clients)) })
	}

	pub(crate) async fn num_clients(&self) -> usize {
		self.clients.read().await.len()
	}

	/// Drop the `failed` provider from the pool (matched by URI).
	///
	/// The last remaining provider is never removed, so that the pool is never emptied.
	pub(crate) async fn remove_client(&self, failed: &Client) {
		let mut clients = self.clients.write().await;
		if clients.len() <= 1 {
			return;
		}

		let before = clients.len();
		clients.retain(|(uri, _)| uri != failed.uri());
		if clients.len() < before {
			warn!(
				target: LOG_TARGET,
				"⚠️ dropping RPC provider `{}` ({} provider(s) left)",
				failed.uri(),
				clients.len(),
			);
		}
	}

	async fn slot(&self, worker_index: usize) -> Arc<tokio::sync::Mutex<Client>> {
		let clients = self.clients.read().await;
		clients[worker_index % clients.len()].1.clone()
	}

	/// Get a client for `worker_index` to issue RPC calls with.
	pub(crate) async fn get(&self, worker_index: usize) -> Client {
		self.slot(worker_index).await.lock().await.clone()
	}

	/// Reconnect the client assigned to `worker_index`, unless `failed` is already stale.
	pub(crate) async fn recreate_client(&self, worker_index: usize, failed: Client) {
		self.slot(worker_index).await.lock().await.recreate(failed.version).await;
	}
}
