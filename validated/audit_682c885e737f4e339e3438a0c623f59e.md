### Title
Borrow-index growth overflows `i128` before the index cap engages, permanently freezing a whale-scale market - (File: contracts/pool/src/cache/scale.rs)

### Summary
The Consul report is an authenticated request that drives the server into a fatal state on an otherwise-normal path. The XOXNO Lending analog is a market-level freeze: once a pool's total scaled debt times its borrow index exceeds `i128::MAX`, `scaled_to_original` panics inside accrual, and because every user-facing verb accrues indexes first, the market becomes permanently unrecoverable — no repay, withdraw, borrow, liquidation, or `update_indexes` ever succeeds again.

### Finding Description
`Cache::calculate_utilization` at `contracts/pool/src/cache/scale.rs:23-24` computes `scaled_to_original(self.borrowed, self.borrow_index)` and `scaled_to_original(self.supplied, self.supply_index)` on every operation, multiplying RAY-scaled share totals by RAY indexes (intermediate domain up to ~10^54 worth of value in raw terms). `scaled_to_original` routes through `mul_div_*` primitives in `common/src/math/fp_core.rs:108-143`, which widen to `I256` for the product but panic with `GenericError::MathOverflow` when the *result* does not fit `i128` (`to_i128`, fp_core.rs:300-303).

The protocol does define an index ceiling — `MAX_BORROW_INDEX_RAY` / `MAX_SUPPLY_INDEX_RAY` in `common/src/constants/pool.rs:19-23` — but the value overflow is hit before the index reaches the cap, so the cap never engages. On a high-decimals asset (18 decimals) with a steep interest-rate curve at sustained high utilization, `borrowed_scaled * borrow_index` crosses `i128::MAX` while `borrow_index` is still orders of magnitude below the cap.

The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-362`) demonstrates this end to end: after enough accrued time, `try_update_indexes` fails with `MATH_OVERFLOW`, and subsequent `try_withdraw_raw` and `try_repay` fail identically because they accrue first. The test explicitly notes "the index cap did not engage before the value overflow" and "the market is frozen: no repay, no withdraw, no liquidation" (:354-356).

### Impact Explanation
Permanent freezing of funds in the affected `(hub_id, asset)` market. Every state-changing entrypoint — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `claim_revenue`, `recapitalize`, `update_indexes` — loads the market `Cache` and accrues, so all of them revert with the same `MathOverflow` panic once the cliff is crossed. Suppliers' deposits and borrowers' collateral in that market are locked forever; there is no admin verb that rewinds the index or bypasses accrual. This matches the "permanent freezing of funds / contract unable to operate" acceptance criterion.

### Likelihood Explanation
Reachable by unprivileged addresses through normal `supply` and `borrow` calls — no role is needed. The condition requires a large market (the test uses ~10^9 × 10^18 raw units of an 18-decimals asset at ~98% utilization on the XLM-shaped curve) and sustained accrual over many ledger-years, so it is not something an attacker can trigger quickly — but it is a deterministic, irreversible cliff that grows closer monotonically with time and utilization; nothing in the code prevents or recovers from it. Medium severity: catastrophic impact gated by extreme-but-permitted market scale and long accrual.

### Recommendation
Apply the index ceiling *before* the value-overflow domain is reached, or compute utilization in a saturating domain: e.g., clamp `borrow_index`/`supply_index` growth at a bound chosen so that `MAX_SHARES * index` cannot exceed `i128::MAX`, or add a saturating `scaled_to_original` variant for the utilization path (a saturated utilization merely reports ~100%, which is economically correct), so accrual completion never depends on an `i128`-bounded product of two RAY-scale values. The fix must ensure `update_indexes`, repay, and withdraw remain callable at the cliff so the market stays unwindable.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`. It builds an 18-decimals `BIG18` market plus a collateral market, supplies `BILLION * 10^18`, borrows 98% of it, advances time one year per iteration until `try_update_indexes_for(&["BIG18"])` errors, then asserts:
- the error is `errors::MATH_OVERFLOW`,
- `last.borrow_index < MAX_BORROW_INDEX_RAY` (cap never engaged),

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

    pub(crate) fn calculate_utilization(&self) -> Ray {
        if self.supplied == Ray::ZERO {
            return Ray::ZERO;
        }
        let total_borrowed = scaled_to_original(&self.env, self.borrowed, self.borrow_index);
        let total_supplied = scaled_to_original(&self.env, self.supplied, self.supply_index);

        utilization(&self.env, total_borrowed, total_supplied)

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
