### Title
L1 BTC lockup proofs can be replayed across multiple `register-for-bond` calls, letting a staker credit sats that are no longer actually locked on Bitcoin - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond`'s L1 path credits a staker with `sats-total` sBTC-equivalent collateral based solely on a one-time Merkle-proof of a Bitcoin transaction output (`validate-l1-lockup`). The proof only establishes that the output *existed* in a Bitcoin block at some point in the past; pox-5 never re-checks that the output is still unspent at the moment of (a later) registration, and it keeps no persistent record of outpoints already consumed across separate transactions/bonds. The dedup list (`seen-outpoints`) is scoped only to the single call's `fold` and is discarded afterward.

### Finding Description
`verify-l1-lockups` → `validate-l1-lockup` verifies, for each output supplied in `btc-lockup`, that:
- the script matches `construct-lockup-output-script` for this staker (`get-bitcoin-tx-output?`, `parse-block-header`, `verify-block-header`),
- the claimed `amount` equals the on-chain output amount,
- the outpoint hasn't been seen twice *within this call* (`seen-outpoints`),
- the Merkle proof is valid. [1](#0-0) 

None of these checks establish that the UTXO is still unspent "now." A merkle-proof of transaction inclusion is permanent historical proof; it says nothing about the output's current spent/unspent status. There is no on-chain map (e.g. keyed by `{txid, output-index}`) that records outpoints already used by a *previous, separate* `register-for-bond` transaction, so the same lockup proof remains fully valid to submit again in a future call, e.g. after the staker's bond membership has ended (the timelock matured, the staker swept/spent the real BTC) and they then reuse the exact same historical proof to join a new bond.

`register-for-bond` itself keys `protocol-bond-memberships` solely by `tx-sender` (one active membership at a time), so simultaneous double use in a single moment is constrained, but the check is against *current* membership state, not against whether the underlying BTC output is still actually locked: [2](#0-1) [3](#0-2) 

Because the amount credited (`sats-total`/`amount-sats`) is what drives the staker's collateral (`get-total-shares-staked-for-cycle`, reward-share weighting versus `min-ustx-for-sats-amount`), a staker who has already exited a bond and spent the real BTC (once its on-chain timelock matures) can present the *identical* historical Merkle proof again to `register-for-bond` for a new bond period. pox-5 will accept it as valid proof of a fresh lockup, crediting `amount-sats` again with no new BTC actually locked for that period — the equality "sats credited to a bond == sats currently locked on Bitcoin" is broken.

### Impact Explanation
This falls under "sats credited by an L1 proof that were never locked on Bitcoin" for the new bond period, and also "double-counting a commitment." A staker gains bond membership, signer-weighting, and reward eligibility backed by BTC collateral that is not actually locked during that period, since the timelock already matured and the coins moved. This is a Critical-severity issue per the stated impact criteria (unbacked crediting of a "locked" commitment).

### Likelihood Explanation
Likelihood is moderate to high: it requires no special privileges — any staker who previously completed an honest L1 lockup, exited after the timelock matured, and spent the BTC can trivially resubmit the same historical proof data (which remains publicly reconstructable from the Bitcoin blockchain) to a subsequent `register-for-bond` call. No admin, signer, or other party's key is needed.

### Recommendation
Persist a global (not per-call) record of consumed L1 lockup outpoints (e.g. a map keyed by `{txid, output-index}` set at successful registration and checked/rejected on reuse), or otherwise cryptographically bind each lockup proof to a single-use registration (e.g. requiring proof that the specific UTXO is still unspent via a currently-valid inclusion+non-spend attestation, or requiring a fresh on-chain lockup transaction per bond period that cannot be reused). At minimum, extend `validate-l1-lockup`/`verify-l1-lockups` to check outpoints against a durable `map-insert`-based registry rather than the ephemeral per-call `seen-outpoints` list.

### Proof of Concept
1. Staker locks BTC in the canonical P2WSH timelock script and calls `register-for-bond` with a valid Merkle proof for that output; `verify-l1-lockups`/`validate-l1-lockup` accept it, crediting `sats-total` sats and creating `protocol-bond-memberships` for bond `N`. [4](#0-3) 
2. The bond period ends; the timelock matures and the staker sweeps/spends the real BTC elsewhere (a normal, expected action once unlocked).
3. Later, the staker calls `register-for-bond` again for a new bond `M`, submitting the *same* historical `{height, tx, output-index, header, leaf-hashes, tx-count, tx-index, amount, unlock-burn-height}` tuple as `btc-lockup`. `validate-l1-lockup` re-verifies the same Merkle proof — which is still and will always be valid, since it only proves historical inclusion — and re-credits `sats-total`. [5](#0-4) 
4. `register-for-bond` accepts the registration and records `amount-sats: sats-total` in `protocol-bond-memberships`/`protocol-bonds-total-staked`, granting reward/signer-weight backed by BTC collateral that is no longer actually locked. [6](#0-5)

(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
