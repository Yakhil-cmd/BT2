### Title
`liquidate` bypasses the per-asset liquidation grace period by writing off grace-protected debt through `socialize-debt-asset` - ([File: local-testing/contracts/market/market.clar])

### Summary
Attacker A (a borrower) holds debt majority in asset X, which is under an active per-asset liquidation grace period (`liquidation-grace-periods` for X), and a minor debt in asset Y, which is not grace-protected. When a liquidator liquidates A's Y debt and this drains all of A's collateral, the `liquidate` function's bad-debt-socialization path iterates over *every remaining debt entry* of A's position — including X's debt — and force-writes it off via `socialize-debt-asset` → `vault-socialize-debt`, without ever checking `is-liquidation-paused` for X. Victim B, who supplied liquidity to vault X, absorbs A's entire X debt as a loss via the `lindex` write-down in vault X's `socialize-debt`, even though X's liquidation was supposedly shielded by grace.

### Finding Description
`is-liquidation-paused` gates only the `debt-aid` explicitly passed into a given `liquidate` call: [1](#0-0) 

The `asserts!` in `liquidate` therefore only blocks liquidation when the *caller-selected* `debt-aid` (here, Y) is paused/in grace: [2](#0-1) 

However, after seizing collateral for the Y liquidation, `liquidate` computes `no-collateral-left` from the *entire* position (all collateral assets), and if true, folds `socialize-debt-asset` over `fresh-debt-list`, which is derived from `pos-full`'s full debt list (all debt assets, including X), independent of any per-asset grace status: [3](#0-2) 

`socialize-debt-asset` performs no grace/pause check at all before calling `vault-socialize-debt` for each debt entry and permanently removing the scaled debt from the borrower's obligation: [4](#0-3) 

`vault-socialize-debt` (dispatch) routes to the specific vault's `socialize-debt`, which directly writes down `lindex` (the supplier index) proportionally to the loss, reducing what every depositor of that vault — including B — can redeem: [5](#0-4) [6](#0-5) 

Root cause: the grace period is meant to be an asset-scoped shield against liquidation of X, but the bad-debt socialization branch (triggered by liquidating a *different* debt asset, Y, in the same position) writes off X's debt through a code path that never consults `liquidation-grace-periods` for X. The shared state A's transaction leaves behind that B's (via the vault) transaction/state reads is the borrower's `debt` list in `pos-full` and the collateral list in the market-vault position — once Y's liquidation empties collateral, X's untouched-but-grace-protected scaled debt is swept into `socialize-debt-asset` regardless of X's `liquidation-grace-periods` entry.

### Impact Explanation
B, a liquidity supplier to vault X, loses collateral-equivalent value equal to A's entire scaled X debt with zero liquidation penalty ever charged to A on the X portion, because the write-off happens via socialization rather than an actual liquidation of X (which was blocked by the grace period check). This is a direct, permanent loss of principal for vault X depositors and constitutes protocol insolvency for vault X to the extent of the socialized amount — Critical severity.

### Likelihood Explanation
No privileged access is required. A only needs to hold a position with debt split across a grace-protected asset (majority) and a non-grace asset (minor); any market price movement that pushes the position underwater, plus a routine liquidation call by any unprivileged liquidator on the non-grace debt (Y), triggers the bypass. This is fully repeatable whenever a per-asset (or global) grace period is active for an asset with concentrated debt, which is a normal operational state after `set-pause-liquidation` unpause or `set-liquidation-grace-period`.

### Recommendation
In the bad-debt-socialization fold, filter `fresh-debt-list` to exclude (or separately track and defer) any debt entries whose asset is currently `is-liquidation-paused`. Only debts for assets not under an active grace/pause should be eligible for `socialize-debt-asset`; grace-protected debt should remain on the borrower's books until its grace period ends, even if the rest of the position's collateral has been exhausted.

### Proof of Concept
1. Deploy `market.clar`, `market-vault`, and vaults X and Y in Clarinet simnet; onboard both assets as debt+collateral with an egroup.
2. As DAO, set `set-pause-liquidation` then unpause with a grace period on asset X (`set-liquidation-grace-period X <window>`), leaving the grace window open.
3. Account A: supply small collateral, borrow majority debt in X and minor debt in Y.
4. Move price feeds to crash A's collateral value, pushing LTV above `ltv-liq-full`.
5. Account C (liquidator, unprivileged third wallet) calls `liquidate(A, collateral-ft, Y-debt-ft, debt-amount, ...)` repaying Y's debt, draining all remaining collateral.
6. Assert: `bad-debt-socialized` is `true` in the emitted event and X's scaled debt for A is now `0` (`get-account-scaled-debt A X == 0`), while no `liquidate` event for asset X was ever emitted and `is-liquidation-paused(X)` returned `true` throughout.
7. Assert: vault X's `total-assets`/`lindex` dropped by exactly A's pre-socialization X scaled-debt value, and B's redeemable balance in vault X (computed via `lindex`) decreases by that same amount with no corresponding liquidation penalty recorded for X.

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
