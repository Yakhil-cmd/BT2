### Title
Webhook signature verification org != repository org resolved by handler, enabling cross-tenant `push` forgery — (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to verify against using `params.dig('repository','owner','login')`, while `Handler#stacks` (used by `PushHandler`) resolves the target repository/stacks using the independent `params.dig('repository','full_name')` field. Because these two attacker-controlled fields are never cross-checked, an attacker can pick an org for `owner.login` whose config has no `webhook_secret` (making signature verification a no-op) while pointing `full_name` at a real, victim-owned repository, causing `PushHandler` to sync that victim's stack(s) on an unauthenticated request.

### Finding Description
The broken invariant, stated as an equality that should hold but doesn't:
`organization_used_to_verify_signature (params.repository.owner.login)` MUST equal `organization_that_owns_the_mutated_repository (params.repository.full_name.split('/').first)`.

Code path:
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner` from `params.dig('repository','owner','login')` (`app/controllers/shipit/webhooks_controller.rb:59-62`) and does `github_app = Shipit.github(organization: repository_owner)`, then `github_app.verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) contains `return true unless webhook_secret`. If the org selected via `repository_owner` has no `webhook_secret` configured in its per-org config block, **verification unconditionally passes**, regardless of the actual signature header sent.
- Once past `verify_signature`, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` is called (`app/controllers/shipit/webhooks_controller.rb:12`), and for a `push` event this invokes `PushHandler.call(params)`.
- `PushHandler` (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`) uses `stacks.not_archived.where(branch:)`, and `stacks` comes from the base `Handler#stacks` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`), which resolves via `Repository.from_github_repo_name(payload.dig('repository', 'full_name'))` — an entirely separate JSON field from the one used for signature verification.
- `Repository.from_github_repo_name` (`app/models/shipit/repository.rb:53-56`) splits `full_name` on `/` to find the exact owner/repo row, with no relation to `repository.owner.login`.

Exploit flow: attacker crafts a `push` webhook body where `repository.owner.login` = an org they know (or can determine) has no `webhook_secret` configured (e.g., a legacy/misconfigured tenant in a multi-org Shipit deployment), and `repository.full_name` = `"victim-org/victim-repo"`. `verify_signature` calls `Shipit.github(organization: "no-secret-org")`, gets a `GitHubApp` with `webhook_secret` blank, and `verify_webhook_signature` returns `true` without checking the HMAC at all. The request proceeds to `PushHandler`, which resolves `victim-org/victim-repo`'s stacks via `full_name` and calls `stack.sync_github(expected_head_sha: params.after)` on every matching non-archived stack — with no relationship to the org that "authenticated" the request.

Regarding the `review_stacks_enabled: false` portion of the question: this precondition does not actually affect `PushHandler`. `PushHandler` operates purely on regular `Stack` records via `Repository#stacks` (`app/models/shipit/repository.rb:47`), and never touches `review_stacks`, `ReviewStackAdapter`, or any provisioning-behavior logic (that logic lives only in the `PullRequest::*Handler` classes, e.g. `LabeledHandler#respond_to_label_change?` at `app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:78-83`, and `OpenedHandler#process` at `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:41-46`). So the "provision precedence bug" does not amplify `PushHandler`'s impact; the impact from `PushHandler` is present regardless of `review_stacks_enabled`, and stems solely from the owner/full_name signature-selection mismatch.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type is registered; `ExplicitParameters` schema for `PushHandler` only requires `ref`/`after`, not `repository.owner.login == repository.full_name`'s org; there is no code anywhere that cross-validates the two fields.

### Impact Explanation
An attacker who controls (or can misuse) any org configuration lacking a `webhook_secret` can forge a `push` event that causes `PushHandler` to call `stack.sync_github(expected_head_sha: params.after)` against an arbitrary victim repository's stacks (matching the affected `full_name` and branch), triggering GitHub sync/deploy pipeline activity for a repository that never authenticated the request. This is a cross-tenant authentication bypass — "a payload for one repository mutating another's stack" — matching the Critical impact category. The blast radius spans every tenant/stack whose repo `full_name` and branch the attacker can guess or enumerate; it is repeatable per request with no rate limiting evident in this code path.

### Likelihood Explanation
Exploitability is conditional on the deployment having at least one configured GitHub org (in `secrets.github`) whose config lacks a `webhook_secret` — this is a realistic/plausible operational misconfiguration in multi-org Shipit deployments, and the code explicitly supports it silently (`@webhook_secret = @config[:webhook_secret].presence`, `return true unless webhook_secret`) with no warning or hard failure. If that condition holds, the attacker cost is a single unauthenticated `POST /webhooks` request with `X-Github-Event: push` and a crafted JSON body — no GitHub credentials, no Shipit session, and no valid signature required.

### Recommendation
Derive the organization used for signature verification and the organization used to resolve the target repository from the same trusted value — i.e., after selecting `github_app` via `repository_owner`, additionally verify `params.dig('repository','full_name').split('/').first.casecmp?(repository_owner)` before dispatching to handlers, and reject (422) on mismatch. Additionally, treat a missing/blank `webhook_secret` for a configured org as a hard misconfiguration error (fail closed) rather than silently returning `true` in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb`):
```ruby
test "push forged via owner/full_name split bypasses signature check for a different repo" do
  # Arrange: stub Shipit.github(organization: 'no-secret-org') to a GitHubApp with blank webhook_secret
  no_secret_app = Shipit::GitHubApp.new('no-secret-org', {}) # no :webhook_secret key
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(no_secret_app)

  victim_stack = shipit_stacks(:shipit) # belongs to victim_repo, e.g. "shopify/shipit-engine"
  victim_repo  = victim_stack.repository

  body = JSON.parse(payload(:push_master))
  body['repository']['owner']['login'] = 'no-secret-org'       # binding LHS: org used for signature
  body['repository']['full_name']      = victim_repo.github_repo_name # binding RHS: org actually mutated
  body['ref'] = "refs/heads/#{victim_stack.branch}"

  request.headers['X-Github-Event']  = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # deliberately invalid

  # Assert LHS != RHS (the invariant is violated by construction)
  refute_equal 'no-secret-org', victim_repo.owner

  # Act & Assert: request is accepted (200) and victim stack is synced despite invalid signature
  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: body['after']]) do
    post :create, body: body.to_json, as: :json
  end
  assert_response :ok
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
