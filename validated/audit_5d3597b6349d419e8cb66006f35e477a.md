### Title
Unallowlisted route venues let a rogue hop pool drain the caller's wallet under their own authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The controller's strategy swaps forward a fully attacker/caller-supplied route (`StrategySwap` XDR) to the configured router, and the router invokes whatever pool and token contracts the payload names — there is no venue allowlist. A malicious "pool" contract executed inside a hop can call `token.transfer(victim, attacker, amount)` on any token the victim holds, and Soroban records that invocation as a child of the victim's `swap_collateral`/`swap_debt`/`multiply`/`repay_debt_with_collateral` authorization entry. If the victim signs the simulated auth tree (which wallets present as "sign to swap"), the rogue pool steals funds completely unrelated to the routed amount. This is the SSRF analog: the protocol's call stack is forged into reaching attacker-chosen contracts that then act with the user's authority.

### Finding Description
`swap_tokens` authorizes only a single exact input transfer to the router and measures balance deltas afterward, but imposes no constraint on which contracts the route touches [1](#0-0) . All account strategies (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`) take the route bytes as a user argument and pass them through unchanged. The project's own threat model confirms the router "calls the pool and token addresses its payload names and keeps no allowlist of them," and that a token transfer such code makes from the caller "is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree" [2](#0-1) . The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates it end-to-end: a `RogueHopPool::swap` executes `wallet_token.transfer(alice, attacker, WALLET_BALANCE)` and the recorded auth for Alice's `swap_collateral` contains exactly that stolen transfer as its sole sub-invocation; Alice's wallet goes to 0 while she still receives a fair swap output [3](#0-2) [4](#0-3) .

### Impact Explanation
Theft of user funds. The stolen amount is the victim's arbitrary wallet balance of any token (`WALLET_BALANCE = 77_770_000_000` in the test), not the routed amount, and neither the payload `min_out` nor the controller's final health/collateral gates bound it — the swap itself settles fairly and passes all risk checks while the wallet is drained [5](#0-4) .

### Likelihood Explanation
Reachable by any unprivileged address: the attacker deploys a rogue pool contract, crafts a route through it, and serves it to a victim (e.g., via a malicious quote/UI). The on-chain path is proven by the test; the residual requirement is that the victim signs the simulated auth tree, which wallets display as the authorization for the swap they requested — the injected `transfer` is a nested detail most signers will not inspect. Medium.

### Recommendation
Constrain route execution so third-party code cannot sit below the caller's authority: e.g., governance-allowlist the pool/venue addresses the router may invoke, or have the controller pin permitted venue addresses per market. Alternatively, isolate the caller's authorization by having strategies pull user funds into the controller before entering the route and requiring the route to touch only protocol-known contracts. Short of a code fix, clients must decode `routeXdr` and reject any auth tree containing children beyond the expected input transfer — the SDK already ships `verifyRouteBytes` for this [6](#0-5) .

### Proof of Concept
See `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: `Scene::new` registers a router double and a `RogueHopPool` constructed with `(victim=alice, wallet_token, to=attacker, amount=WALLET_BALANCE)`; `try_swap` calls `ctrl.try_swap_collateral(alice, account_id, USDC, 5_000e7, ETH, route)`; the router invokes `hop_pool.swap`, which performs `wallet_token.transfer(alice, attacker, 77_770_000_000)`. The test asserts Alice's recorded auth entry is `swap_collateral` with the stolen transfer as its only sub-invocation, `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and `supply_balance_raw(alice, ETH) == 25_000_000` — the swap output is delivered fairly while the wallet is emptied [7](#0-6) .

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
