### Title
Webhook signature verification uses `repository.owner.login` while stack lookup uses `repository.full_name`, letting a no-secret org's webhook forge pushes against any other repository's stack - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook using `payload.dig('repository','owner','login')` to pick the `GitHubApp` config, but `Shipit::Webhooks::Handlers::Handler#stacks` (used by `PushHandler`) resolves the target `Repository`/`Stack` using the independent `payload.dig('repository','full_name')` field. Because these two attacker-controlled JSON fields are never checked for consistency, an attacker who owns/controls a GitHub organization configured in Shipit with a blank `webhook_secret` can forge a `push` payload whose `owner.login` matches that no-secret org (trivially "authenticated") while `full_name` names a completely different, victim repository/stack.

### Finding Description
The broken binding: the code implicitly assumes `payload['repository']['owner']['login'] == owner_of(Repository.from_github_repo_name(payload['repository']['full_name']))`, but nothing enforces this.

- `verify_signature` computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0)  and looks up `Shipit.github(organization: repository_owner)` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org's `webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) . If the attacker sets `repository.owner.login` to a Shipit-configured org that has no `webhook_secret` set, this check passes for any (or missing) signature.
- Once past `verify_signature`, `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler#process`, which calls `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` [4](#0-3) .
- `Handler#stacks` resolves the affected repository via `Repository.from_github_repo_name(repository_name)`, where `repository_name = payload.dig('repository', 'full_name')` [5](#0-4)  — a completely separate JSON field from the one used for authentication.

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: push`, a body where `repository.owner.login` = the no-secret org (any signature/no signature accepted), and `repository.full_name` = `"victim-org/victim-repo"` (an unrelated repository actually configured in Shipit, whose real org does have a secret). `verify_signature` passes because it only checks the no-secret org's (irrelevant) secret. `PushHandler` then finds and syncs the victim stack using the attacker-supplied `after` SHA, appending/moving the victim stack's head and potentially triggering continuous delivery.

None of the existing guards catch this: `drop_unhandled_event` only checks event type is handled; `verify_signature`'s only check is against the org named in `owner.login`, never cross-checked against `full_name`; the `ExplicitParameters` schema for `PushHandler` only requires `ref` and `after`, not `repository.owner.login == repository.full_name`'s owner.

### Impact Explanation
An unauthenticated attacker can cause a `push` payload — carrying an arbitrary `after` SHA — to be applied to any repository/stack tracked by Shipit, as long as some org in the Shipit config has a blank `webhook_secret`. This is a payload for one repository mutating another repository's stack, matching the Critical impact category. If the victim stack's environment has continuous delivery/auto-deploy enabled, the injected commit range can be auto-deployed, and per the question's scenario, that deploy runs under the bot identity (`Shipit.user`, derived from the configured `bot_login`), amplifying to unauthorized deploy execution. This is repeatable against any repository whose full name the attacker can guess/know, as long as one no-secret org exists in the Shipit configuration.

### Likelihood Explanation
Preconditions: Shipit must have at least one GitHub organization configured with a blank `webhook_secret` (explicitly supported/documented in `config/secrets.development.example.yml` and `config/secrets.development.shopify.yml`, which show `webhook_secret: # nil` as a valid configuration) [6](#0-5) . Given that, the attacker needs no credentials, no session, and no knowledge of the victim's actual `webhook_secret` — only the victim's repository `full_name`, which is typically public knowledge. This is a single unauthenticated HTTP POST, fully repeatable.

### Recommendation
In `Shipit::WebhooksController#verify_signature`, or in `Handler#stacks`, enforce that the organization used to authenticate the webhook (`repository.owner.login`) matches the owner of the `Repository` resolved from `repository.full_name`, rejecting the request (422) if they diverge. Additionally, consider treating a blank/missing `webhook_secret` as a misconfiguration to warn/reject on for any organization that has active stacks, rather than silently trusting all payloads for that org.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Configure two orgs: `no-secret-org` (webhook_secret nil) and `victim-org` (webhook_secret set), matching `Shipit.github_app_config`.
2. Create a `victim-org/victim-repo` `Repository` with a `Stack` on branch `master`, with a known current head SHA.
3. Build a forged push payload: `repository.owner.login = "no-secret-org"`, `repository.full_name = "victim-org/victim-repo"`, `ref = "refs/heads/master"`, `after = "<attacker-controlled-sha>"`.
4. POST to `/webhooks` with `X-Github-Event: push` and no valid `X-Hub-Signature` (or an arbitrary one).
5. Assert response is `:ok` (i.e., signature check passed because `no-secret-org` has blank `webhook_secret`).
6. Assert `Stack#sync_github` was called (e.g., via `Stack.any_instance.expects(:sync_github).with(expected_head_sha: "<attacker-controlled-sha>")`) for the `victim-org/victim-repo` stack, proving cross-tenant mutation authenticated by an unrelated org's (absent) secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
