### Title
Accrual-time RAY-value overflow permanently freezes a whale market — repay, withdraw, and liquidation all revert via a shared accrue-first panic - (File: common/src/rates, exercised by contracts/pool/src/interest.rs)

### Summary
CVE-2016-9888 is a null-deref crash reachable by an attacker-supplied input, i.e. a crash-class bug turned into denial of service against library consumers. The analog in XOXNO Lending is a deterministic arithmetic crash, not a fail-closed check: once `borrowed_scaled * borrow_index` can no longer be represented in `i128`, `scaled_to_original` inside `accrue_step` panics with `MathOverflow` during `global_sync`. Because every pool verb (`repay`, `withdraw`, `seize_positions`, `supply`, `update_indexes`) syncs the market before acting, the panic is permanent and unrecoverable — the market's cash and all supplier/borrower funds in it are frozen forever. A dedicated harness test confirms the freeze and shows it fires before the `MAX_BORROW_INDEX_RAY` index cap can protect the market.

### Finding Description
`interest::global_sync` runs on every state-changing pool entry via `ops::synced_market`, calling `accrue_step` for each compound chunk [1](#0-0) . `accrue_step` internally converts scaled totals to original values with `scaled_to_original` (`scaled * index`), a checked multiply that raises `GenericError::MathOverflow` when the RAY-domain product exceeds `i128`. The protocol's own numeric-limits documentation acknowledges this: "Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [2](#0-1) . The integration test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the cliff end-to-end: after enough compounding at ~98% utilization, `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all fail with `MATH_OVERFLOW`, with `borrow_index` still below its cap [3](#0-2) . No guard short-circuits accrual when the value ceiling is near, and there is no alarm or recovery path — debt cannot be repaid (repay accrues first), collateral cannot be seized (seize syncs first via `ops::synced_market` [4](#0-3) ), and `clean_bad_debt`/`recapitalize` similarly cannot operate on the frozen market.

### Impact Explanation
Permanent freezing of user funds: once the market's borrow value crosses the representable RAY domain, every token held as pool cash for that market is locked, every supplier's claim is unwithdrawable, and the borrower cannot repay — a strictly worse outcome than insolvency, because not even governance-authorized cleanup (`seize_positions`, `recapitalize`) can touch the state, since they too sync the market first.

### Likelihood Explanation
Triggering it requires an extreme position: roughly 170 billion whole tokens of supply with ~98% utilization sustained for years at the steep end of the interest curve (the test uses a 10^18-decimals market with lifted caps). The setup needs large capital and lifted supply caps, but every step is a permissionless `supply`/`borrow`/`update_indexes` call by ordinary addresses, and no on-chain check prevents reaching the state. That places it at Medium: real and permanent, but gated by economically heavy preconditions.

### Recommendation
Cap accrual by clamping the borrow index growth when `scaled_to_original` would overflow (e.g., freeze interest accrual at the largest representable debt value instead of panicking), or add a pre-accrual representability check that truncates `last_timestamp` advancement so exits remain possible. At minimum, let `seize`/`recapitalize` paths operate on last-stored state without forcing an overflowing accrual, preserving a recovery path for frozen markets.

assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);

The same panic reaches `liquidate`, `clean_bad_debt`, and `flash_loan`, since each routes through `ops::synced_market` → `global_sync` → `accrue_step`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
