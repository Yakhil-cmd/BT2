### Title
Signature verification keyed on `repository.owner.login` while stack targeting uses independently-attacker-controlled `repository.full_name`, allowing cross-tenant forged `push` webhooks - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/handler.rb, app/models/shipit/webhooks/handlers/push_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) to validate the webhook using `repository.owner.login` from the attacker-supplied JSON body, but `Shipit::Webhooks::Handlers::Handler#stacks` (used by `PushHandler`) looks up the target `Repository`/`Stack` using a *different, independently attacker-controlled* field: `repository.full_name`. Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected organization's config has a blank `webhook_secret`, an attacker who knows of any configured organization without a `webhook_secret` can forge a `push` payload that authenticates as that org while pointing `repository.full_name` at an entirely different, victim-owned repository/stack.

### Finding Description
The broken binding the code is supposed to enforce is: *the organization/repository that authenticated the webhook (`repository.owner.login`, checked against a secret) MUST equal the organization/repository whose stacks are mutated (`repository.full_name`, used for the `Repository` lookup)*. In this codebase these are two unrelated dictionary reads.

- `Shipit::WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` via `params.dig('repository','owner','login') || params.dig('organization','login')` (line 61) and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) does `return true unless webhook_secret`, i.e., if the resolved organization's config has no `webhook_secret`, **any** body/signature pair is accepted, with no HMAC check at all.
- Once accepted, `WebhooksController#create` dispatches to `PushHandler.call(params)`.
- `PushHandler#process` (app/models/shipit/webhooks/handlers/push_handler.rb:12-17) calls the inherited `stacks` helper.
- `Handler#stacks` / `Handler#repository_name` (app/models/shipit/webhooks/handlers/handler.rb:32-38) resolve the target via `Repository.from_github_repo_name(payload.dig('repository','full_name'))` — a completely separate key from `repository.owner.login` used for signature routing.

Because the raw JSON body is fully attacker-controlled (`request.raw_post` is parsed with no cross-field consistency check), an attacker can submit:
```json
{
  "repository": { "owner": { "login": "no-secret-org" }, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/main",
  "after": "<sha victim already has, e.g. current green head>"
}
```
`verify_signature` resolves `no-secret-org`'s `GitHubApp`, whose `webhook_secret` is blank, so it returns `true` regardless of the (missing/garbage) `X-Hub-Signature` header. `PushHandler` then resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: params.after)` on every non-archived stack on that branch, for a stack the attacker never authenticated against and does not own. No other guard intercepts this: `drop_unhandled_event` only checks the event type exists; there is no `ExplicitParameters` rule tying `repository.owner.login` to `repository.full_name`; `force_github_authentication`/`User#authorized?`/`require_permission!` are irrelevant since `WebhooksController` is unauthenticated by design and relies solely on the HMAC signature for trust.

### Impact Explanation
This is a payload for one repository (an org lacking a `webhook_secret`) mutating another repository's stack — squarely a Critical-class finding under the engine's own trust model, since `sync_github` can append commits/update `deployed_revision` bookkeping and, on a `merge_queue_enabled` stack, drive the merge queue forward once a green head is observed, resulting in unauthorized merge/continuous-delivery actions on the victim stack. The attacker gains this per POST request, is fully repeatable, and is not limited to a single victim — any Repository record already registered in Shipit can be targeted as long as one org anywhere in the multi-tenant `secrets.github` config is missing a `webhook_secret`.

### Likelihood Explanation
Preconditions: Shipit must be run in the multi-organization credentials mode (`secrets.github` keyed by org) with at least one configured organization whose entry omits `webhook_secret`; the victim stack must exist and have `merge_queue_enabled` for the amplified merge impact (the base repo-confusion vulnerability itself doesn't require merge_queue). No GitHub, Shipit, or victim-repo secret is needed by the attacker — they only need to know (or guess/enumerate) the name of the no-secret organization and the victim's `owner/repo` full name, both of which are typically public/discoverable. This is a low-cost, fully repeatable attack via a single unauthenticated `POST /webhooks`.

### Recommendation
Bind the identity used for signature verification to the identity used for record lookup: derive both `repository_owner` and the `Repository` target from the *same* validated field, and reject the request if `repository.owner.login` does not match the owner portion of `repository.full_name`. Additionally, treat a blank `webhook_secret` as a misconfiguration to be logged/rejected rather than an implicit bypass — do not `return true` from `verify_webhook_signature` when no secret is configured for the resolved organization; instead fail closed (`head 422`) unless the operator explicitly opts into unsigned webhooks for that org.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`), no live GitHub:
1. Configure `Rails.application.credentials.github` (or stub `Shipit.secrets.github`) with two orgs: `"no-secret-org" => { app_id:, installation_id:, private_key: ... }` (no `webhook_secret`) and `"victim-org" => { ..., webhook_secret: "victims-secret" }`.
2. Create `victim_repo = shipit_repositories(:shipit)` (or new) with `full_name: "victim-org/victim-repo"`, and `victim_stack` on branch `main` with `merge_queue_enabled: true`, plus a `merge_request` ready to merge / a green head commit.
3. POST to `/webhooks` with header `X-Github-Event: push`, **no valid** `X-Hub-Signature` (e.g. `sha1=deadbeef` or omitted), and JSON body:
   ```json
   { "repository": {"owner": {"login": "no-secret-org"}, "full_name": "victim-org/victim-repo"},
     "ref": "refs/heads/main", "after": "<victim head sha>" }
   ```
4. Assert response is `200`/`:ok` (not `422`), proving signature bypass.
5. Assert `victim_stack.sync_github` was invoked (e.g., stub/expect `Stack#sync_github` to receive `expected_head_sha:` equal to the forged `after`) — i.e., assert `repository_owner_used_for_auth ("no-secret-org") != repository_full_name_used_for_target ("victim-org/victim-repo")` yet the sync still executed, and (for the merge-queue amplification) assert `MergeRequest#merge!`/queue-advance is triggered on the victim stack as a result.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
