### Title
Crafted rename source path containing `" b/"` causes `diff --git` header mis-split, silently dropping the real changed file from security review - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`extract_file_paths_from_diff` and `parse_diff_into_files` both parse the `diff --git a/X b/Y` header line with the lazy regex `^a/(.+?) b/(.+)$` [1](#0-0) [2](#0-1) . Because git's own `diff --git` header is inherently ambiguous when a path contains the literal substring `" b/"`, an attacker can rename a file from a crafted old path to a security-relevant new path such that the regex's non-greedy group1 absorbs the wrong prefix and group2 becomes contaminated with attacker-controlled text (e.g. `node_modules/`) from the *old* path, causing `_is_reviewable_source` to misclassify and drop the genuinely new, reviewable file.

### Finding Description
Both extraction functions split the diff on `"diff --git "` and match only the first line with `re.match(r'^a/(.+?) b/(.+)$', lines[0])`, using `group(2)` (the "b/" path) as the authoritative file path [3](#0-2) [4](#0-3) . Git constructs this header line as the literal concatenation `a/<old-path> b/<new-path>` with a single space+`b/` separator and does not quote paths unless they contain control characters — a space or the substring `" b/"` inside a path does **not** trigger quoting.

If the old path itself contains `" b/"` (e.g. `old = "decoy b/node_modules/fake"`), the header becomes:
```
diff --git a/decoy b/node_modules/fake b/evil.py
```
The regex's first `" b/"` match (non-greedy `.+?`) occurs after `"decoy"`, so `group(1) = "decoy"` and `group(2) = "node_modules/fake b/evil.py"` — NOT the true new path `evil.py`. This corrupted string is passed straight into `_is_reviewable_source(file_path)` [5](#0-4) , which checks `SKIP_PATH_PATTERNS` (including `'node_modules/'`) as a substring match against the normalized path [6](#0-5) [7](#0-6) . Since the corrupted `file_path` now contains `node_modules/`, the function returns `False`, and the file is silently skipped in both `extract_file_paths_from_diff` (`continue`, line 608) and `parse_diff_into_files` (`continue`, line 640) — even though the real new file `evil.py` is a genuinely reviewable, security-relevant Python file. There is no fallback that uses the unambiguous `--- a/<path>` / `+++ b/<path>` lines that appear later in the same file's diff (those lines are unambiguous because the full remainder of the line after the fixed `a/`/`b/` prefix is the path), so the parser relies entirely on the ambiguous combined header.

### Impact Explanation
This causes a genuinely security-relevant file change (e.g. injected malicious code, backdoor, hardcoded secret) to be completely excluded from `extract_file_paths_from_diff`'s reviewable-path list and from `parse_diff_into_files`'s (file_path, diff_content) tuples, which feed the Stop-hook's LLM security review described in `security_reminder_hook.py`'s docstring [8](#0-7) . The malicious file's content never reaches the reviewer, defeating the plugin's core security-review guarantee — a trust-boundary bypass of the review/export logic scoped to this plugin.

### Likelihood Explanation
The only precondition is the ability to create/rename a file with an attacker-chosen name inside the working repository — an unprivileged capability available to any agent session performing ordinary file operations (`mv`/`git mv`, or Write+rename via Bash), fully within the "ordinary repository content" trust boundary. The attack is deterministic and 100% reproducible: any old path containing `" b/"` followed by a `SKIP_PATH_PATTERNS`/`SKIP_FILE_SUFFIXES` token will reliably suppress review of the renamed-to file, regardless of that file's actual (malicious) content.

### Recommendation
Do not parse the ambiguous `diff --git a/X b/Y` header with a regex to recover file paths. Instead:
- Use the unambiguous `--- a/<path>` and `+++ b/<path>` lines (or `/dev/null` for adds/deletes) that git always emits per-file, taking the entire remainder of the line as the path with no further splitting.
- Or better, drive file identification entirely from `git diff --name-only -z` / `git status --porcelain -z` (already used elsewhere in this file, e.g. `_git_name_only`, `_git_status_porcelain`) which use NUL-separated, unambiguous output, and correlate those paths with the diff hunks instead of regexing the `diff --git` header.

### Proof of Concept
Differential/unit test in the existing test suite for `gitutil.py`:
1. Create a temp git repo; add a file at `decoy b/node_modules/fake` with benign content, commit it.
2. `git mv "decoy b/node_modules/fake" "evil.py"`; write malicious content into `evil.py` (e.g. `os.system(user_input)`); stage it.
3. Capture `git diff --no-color --cached` (or via `get_git_diff`) as `diff_output`.
4. Assert:
   - `extract_file_paths_from_diff(diff_output)` does **not** include `"evil.py"` (bug reproduced — expected: it should include it).
   - `parse_diff_into_files(diff_output)` does **not** contain a tuple whose `file_path == "evil.py"` even though the actual git diff clearly shows `evil.py` added/renamed with reviewable Python content.
   - Compare against ground truth via `git diff --name-status -z` on the same diff, which correctly reports `evil.py` as the changed path — demonstrating the parser diverges from git's actual file identity.

```python
def _is_reviewable_source(file_path):
    # Normalize for component matching: a path like `.next/x.js` or
    # `pkg/node_modules/y.ts` should both be excluded; matching against
    # `'/' + path` lets each pattern be checked as `'/' + p in '/' + path`
    # without false-positiving on `rebuild/` matching `build/`.
    norm = "/" + file_path.replace("\\", "/")
    if any(("/" + p) in norm for p in SKIP_PATH_PATTERNS):
        return False
    if file_path.endswith(SKIP_FILE_SUFFIXES):
        return False
    ext = os.path.splitext(file_path)[1].lower()
    if ext in SOURCE_CODE_EXTENSIONS:
        return True
    base = os.path.basename(file_path).lower()
    # Accept dot-suffixed variants too: `Dockerfile.dev`, `Makefile.am`,
    # `Jenkinsfile.release`. splitext gives ext='.dev'/'.am' for these so they
    # miss both the extension check and the exact-basename check otherwise.
    if base in SOURCE_CODE_BASENAMES \
            or base.split(".", 1)[0] in SOURCE_CODE_BASENAMES:
        return True
```

```python
def extract_file_paths_from_diff(diff_output):
    """
    Extract file paths from unified diff output (without content).
    Only includes files with source code extensions.
    Returns a list of file paths.
    """
    if not diff_output or not diff_output.strip():
        return []

    paths = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue
        file_path = header_match.group(2) or header_match.group(1) or ''
        if not _is_reviewable_source(file_path):
            continue
        paths.append(file_path)

    return paths
```

```python
def parse_diff_into_files(diff_output):
    """
    Parse unified diff output into a list of (file_path, diff_content) tuples.
    Only includes files with source code extensions.
    """
    if not diff_output or not diff_output.strip():
        return []

    files = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue

        # Extract filename from first line: "a/path/to/file b/path/to/file"
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue

        file_path = header_match.group(2) or header_match.group(1) or ''

        # Filter to source code files only
        if not _is_reviewable_source(file_path):
            continue

        # Extract the diff content (from first @@ onwards)
        diff_lines = []
        in_hunks = False
        for line in lines[1:]:
            if line.startswith('@@'):
                in_hunks = True
            if in_hunks:
                diff_lines.append(line)

        if diff_lines:
            files.append((file_path, '\n'.join(diff_lines)))

    return files
```
