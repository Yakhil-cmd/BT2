### Title
Cross-leg age-spread check silently skipped for non-Market anchor feeds lets a frozen anchor skew the blended price and over-inflate collateral - (File: contracts/price-aggregator/src/engine.rs)

### Summary
The dual-source blend applies the `MAX_LEG_AGE_SPREAD_SECONDS` freshness cross-check only when **both** legs are `FeedNature::Market`. When the anchor leg is a `Fundamental`-nature feed (RedStone "Fundamental" feeds are used in production configs), the spread bound is silently dropped: the anchor only has to satisfy its own per-source `max_stale_seconds` window, which can be tens of thousands of seconds. A frozen anchor inside that window is blended 50/50 with the fresh primary via `midpoint_price_or_zero`, pulling the accepted price up to half the configured tolerance band away from the true price, and the outcome is marked valid.

### Finding Description
In `blend` the spread guard is gated on `primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market` [1](#0-0) . Each leg's individual staleness is only measured against `feed.max_stale_seconds` [2](#0-1)  and `oracle.max_price_stale_seconds` [3](#0-2) , both of which are configured per-source (e.g., 86,400 s for RedStone anchors). `Outcome::failure` rejects only on the aggregate `stale`/`deviation` flags [4](#0-3) , so a leg that is many hours old but inside its own window produces `stale == false`, and as long as the two prices sit within `tolerance.upper_ratio_bps` the midpoint is accepted. The harness test `audit_borrow_withdraw_liquidate_stale_anchor_blends_5pct_skew_into_ltv` proves the consequence: an anchor frozen at $1.00 while the true price is $0.91 inflates measured collateral by >4% and lets `borrow` succeed where the honest config reverts with `INSUFFICIENT_COLLATERAL` [5](#0-4) .

This mirrors CVE-2017-11565: a protection assumed to cover the deployment (age-spread bounding of the two oracle legs) is silently lost because the guard condition was written for only one shape of feed (`Market`/`Market`), leaving `Market`/`Fundamental` pairs — which exist in real configs — unprotected.

### Impact Explanation
An unprivileged borrower waits for (or benefits from) a Fundamental anchor feed that stops updating while remaining inside its own staleness window and inside the tolerance band of the primary. They then call `controller.borrow` (or open/adjust via `multiply`/`flash_position`) against collateral valued at a midpoint skewed up to roughly half the tolerance band. With 5% tolerance this is ~2.5% free valuation, and it compounds with LTV — the test shows >4% inflation and a borrow that honest pricing would reject. The borrowed assets are real pool funds; if the skew exceeds the liquidation buffer the position becomes bad debt, i.e., protocol insolvency borne by suppliers. The same skew under-collateralizes withdrawals and can block correct liquidations (frozen anchor can also suppress or inflate HF in either direction depending on which leg freezes).

### Likelihood Explanation
Reachable by any address through `borrow`/`multiply`/`flash_position` whenever an anchor leg goes stale-within-window — a normal operational event (feed writer downtime) rather than an attack prerequisite. No privileged action is required; the skew persists for the entire `max_stale_seconds` window (up to ~23 h on 86,400 s configs) because each transaction re-accepts the frozen reading. Severity is Medium–High depending on configured tolerance bands and market LTVs; the effect is bounded by ~half the tolerance band per event but repeatable across assets and accounts.

### Recommendation
Apply `MAX_LEG_AGE_SPREAD_SECONDS` (or a per-oracle spread bound) regardless of leg `nature` — the correctness of a midpoint requires the two legs to describe the same point in time for any feed type. Alternatively/additionally, cap each leg's effective staleness at `min(feed.max_stale_seconds, oracle.max_price_stale_seconds, a global freshness ceiling)` and mark the outcome stale when a Fundamental leg's timestamp lags the primary beyond the spread bound.

### Proof of Concept
Replicated by the existing harness test `tests/test-harness/tests/controller/audit_borrow_withdraw_liquidate_stale_anchor_blend.rs`: configure XLM oracle with a Reflector (Market) primary and a RedStone anchor marked `FeedNature::Fundamental` with `max_stale_seconds = 86_400`; freeze the anchor at $1.00 with an 82,800 s-old timestamp while the primary moves to $0.91; supply XLM collateral and call `controller.borrow` — the borrow succeeds with collateral inflated >4%, where the fresh-anchor control reverts `INSUFFICIENT_COLLATERAL`.

    fn failure(&self, oracle: Option<&AssetOracle>) -> Option<OracleError> {
        if let Some(err) = self.err {
            return Some(err);
        }
        let Some(oracle) = oracle else {
            return Some(OracleError::OracleNotConfigured);
        };
        if self.stale {
            return Some(OracleError::PriceFeedStale);
        }
        if self.deviation {
            return Some(OracleError::UnsafePriceNotAllowed);
        }
        if self.price_wad <= 0 {
            return Some(OracleError::InvalidPrice);
        }
        if self.price_wad < oracle.min_sanity_price_wad
            || self.price_wad > oracle.max_sanity_price_wad
        {
            return Some(OracleError::SanityBoundViolated);
        }
        None
    }

#[test]
fn audit_borrow_withdraw_liquidate_stale_anchor_blends_5pct_skew_into_ltv() {
    let exploit = run(true);
    let control = run(false);

    let inflation = exploit.collateral_usd / control.collateral_usd;
    assert!(
        inflation > 1.04,
        "stale-anchor blend must inflate collateral >4% vs the honest fresh-anchor \
         valuation: exploit={} control={} ratio={}",
        exploit.collateral_usd,
        control.collateral_usd,
        inflation
    );

    assert!(
        exploit.borrow.is_ok(),
        "stale-anchor skew must let the attacker borrow beyond true capacity: {:?}",
        exploit.borrow
    );

    // Pin the reason: an unrelated fixture break that reverts for any other
    // cause would otherwise "prove" the stale anchor enabled the borrow.
    assert_contract_error(control.borrow, errors::INSUFFICIENT_COLLATERAL);
