### Title
Cross-org `pull_request`/`unlabeled` forgery via mismatched `repository.owner.login` (used for signature verification) vs `repository.full_name` (used for mutation) — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
The claimed mechanism (a malformed `X-Hub-Signature` with no `=` producing `algorithm`/`signature = nil` into `SecureCompare.secure_compare`) does **not** bypass verification: `GitHubApp#verify_webhook_signature` rejects any signature whose `algorithm != 'sha1'` *before* it ever reaches `secure_compare`, so malformed signatures are safely rejected whenever a `webhook_secret` is configured for the resolved org. However, a real and more direct cross-tenant bypass exists in the same code: `WebhooksController#verify_signature` resolves the GitHub app/secret to check using `repository_owner` (`params.dig('repository','owner','login')`), while every `PullRequest` handler (including `UnlabeledHandler`) resolves the repository/stack to *mutate* using a completely independent field, `params.repository.full_name`. Nothing ties these two fields together, so an attacker can pick an org for verification and a different org's repo for mutation.

### Finding Description
The broken binding: `repository_owner_used_for_verification == owner(repository.full_name)_used_for_mutation` is assumed but never enforced.

Trace:
- `Shipit::WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) computes `repository_owner` from `params.dig('repository','owner','login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83): `return true unless webhook_secret` — if the org resolved via `repository_owner` has **no** `webhook_secret` configured (the shipped example configs `config/secrets.development.example.yml` and `test/dummy/config/secrets_double_github_app.yml` literally default `webhook_secret:` to nil), verification is skipped entirely for **any** signature value, well-formed or not.
- On `create`, the raw JSON body is fanned out unmodified to all `pull_request` handlers via `Shipit::Webhooks.for_event('pull_request').each { |handler| handler.call(params) }` (app/controllers/shipit/webhooks_controller.rb:10-15, app/models/shipit/webhooks.rb:9-18).
- `UnlabeledHandler#repository` and `#stack` (app/models/shipit/webhooks/handlers/pull_request/unlabeled_handler.rb:59-69) resolve the repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a **different** field than the one used for signature verification — and then call `stack.archive!`/`stack.unarchive!` on that repository's real `ReviewStack`.

Exploit: attacker crafts a `pull_request`/`action: unlabeled` payload where `repository.owner.login = "attacker-org"` (a Shipit-configured org with no `webhook_secret`, e.g. a personal org the attacker registered in a multi-org Shipit deployment) but `repository.full_name = "victim-org/victim-repo"`. `verify_signature` resolves `Shipit.github(organization: "attacker-org")`, whose `verify_webhook_signature` returns `true` unconditionally because that org has no secret — the signature header content is irrelevant. The request passes the `before_action` chain, and `UnlabeledHandler` then loads the real `victim-org/victim-repo` `Repository`/`ReviewStack` (via `full_name`) and archives/unarchives it, all without ever validating against `victim-org`'s actual `webhook_secret`.

Existing guards do not stop this: `drop_unhandled_event` only checks the event name; `ExplicitParameters` schema only validates types/presence, not cross-field consistency between `repository.owner.login` and `repository.full_name`; `Repository` model validations only constrain the `owner`/`name` character format, not their relationship to the verified organization.

### Impact Explanation
An attacker who controls (or registers) any single Shipit-configured GitHub organization without a `webhook_secret` can forge `pull_request` webhooks (including `unlabeled`) that archive/unarchive review stacks belonging to **any other** organization's repository tracked by the same Shipit instance, purely by setting `repository.full_name` to the victim's repo while keeping `repository.owner.login` pointed at their own no-secret org. This is cross-tenant/cross-repository state manipulation matching the Critical category ("a payload for one repository mutating another's stack"). It is fully repeatable against any repository name the attacker can guess/enumerate, for every PR handler that keys its side effects off `params.repository.full_name` (Opened/Closed/Reopened/Labeled/Unlabeled/LabelCapturing handlers all share this same repository-resolution pattern).

### Likelihood Explanation
This requires a Shipit deployment configured with multiple GitHub organizations (the documented "Using Multiple Github Applications" schema in docs/setup.md) where at least one org has no `webhook_secret` set — a state the shipped example config files themselves default to (`webhook_secret: # nil`). Given that precondition, the attack costs nothing beyond a single unauthenticated HTTP POST with a crafted JSON body; no valid signature, session, or credentials of any kind are required, and it is trivially repeatable.

### Recommendation
Cross-validate that `repository.owner.login` (or the org derived from it) matches the owner segment of `repository.full_name` before dispatching to handlers, and/or resolve the target `Repository`/org strictly from the same field used to select the signing secret. Additionally, consider treating a missing `webhook_secret` as a hard configuration error in production rather than an implicit "skip verification," to eliminate the no-secret bypass path entirely.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "cross-org unlabeled payload archives a victim repo's review stack when the payload's repository.owner org has no webhook_secret" do
  # Setup: two orgs configured, "attacker-org" (no webhook_secret) and "victim-org" (secret set)
  # Victim repo + provisioned, non-archived ReviewStack already exists for "victim-org/victim-repo"
  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'not-even-a-valid-signature' # malformed, irrelevant

  body = payload_parsed(:pull_request_unlabeled)
  body['repository']['owner']['login'] = 'attacker-org'      # used only for verify_signature
  body['repository']['full_name'] = 'victim-org/victim-repo' # used by UnlabeledHandler to locate/mutate the stack

  assert_changes -> { victim_stack.reload.archived? } do
    post :create, body: body.to_json, as: :json
  end
  assert_response :ok
end
```
Assertion equality to validate: before the request, `verified_org == "attacker-org"` while `mutated_repository.full_name == "victim-org/victim-repo"` — these differ, proving the invariant "the organization whose webhook_secret verified the event owns the review stack/repository the PR handler mutates" is violated.     def verify_webhook_signature(signature, message)
```ruby
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
