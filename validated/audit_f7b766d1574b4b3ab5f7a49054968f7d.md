### Title
`StatusHandler#process` mutates `Commit`/`Status` rows for any repository sharing a commit `sha`, with `params.branches` and `repository.full_name` accepted but never enforced - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`StatusHandler` accepts `branches` and (via the base `Handler`) has access to `repository.full_name`, but `#process` only ever reads `params.sha`, running `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` with no repository/stack scoping at all. Any attacker who owns a GitHub repository whose commit history shares a SHA with a victim's tracked commit (trivial via forking, since unmodified commits keep identical SHA1s across forks) can send a validly-signed `status` webhook from their own repo and have Shipit write/overwrite a `Status` on the victim's `Commit`.

### Finding Description
The claimed binding is: `params.repository.full_name == <owning repo of commit matched by params.sha>` (and/or `params.branches` reflecting a branch of that same repo). Tracing `app/models/shipit/webhooks/handlers/status_handler.rb:15-24`, the schema declares `accepts :branches, Array do requires :name, String end`, but `#process` (lines 20-24) does:
```
Commit.where(sha: params.sha).each do |commit|
  commit.create_status_from_github!(params)
end
```
Neither `params.branches` nor `params.repository.full_name` nor the base `Handler#stacks`/`#repository_name` helpers (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) are called anywhere in this handler. `Commit.where(sha: ...)` is a global, unscoped lookup across all stacks/repositories in the installation - the only index found is `stack_id`+`sha` (`db/migrate/20170524104615_index_commits_on_stack_id_and_sha.rb`), not a uniqueness constraint restricting `sha` to one repo.

`verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-49` validates the HMAC signature against the GitHub App/org secret for `repository_owner` (`params.dig('repository','owner','login')`), i.e., it authenticates that the request truly comes from the named repository's webhook config - it does not, and cannot, bind the `sha` field to that same repository. An attacker who owns/forks a repo controls its webhook secret setup implicitly (their own repo's webhook delivers a signature Shipit can verify against their own configured GitHub App installation) and can freely set `sha` to any 40-hex value, including one that coincides with a commit already ingested into a victim's tracked stack (trivially achievable by forking the victim repo before divergence, since git preserves SHA1 across forks for identical commits).

### Impact Explanation
A successful forged `status` webhook causes `Commit#create_status_from_github!` (`app/models/shipit/commit.rb:165-169`) to create a `Status` row on the victim's `Commit`, potentially transitioning `commit.state` (e.g., to `success`), which per `add_status` (`app/models/shipit/commit.rb:366-386`) triggers `Hook.emit(:deployable_status, ...)` and `stack.schedule_merges` when state becomes `pending`/`success` - i.e., it can make Shipit believe CI passed on a victim's commit and enqueue merge/deploy-eligibility processing for a stack the attacker does not own. This is a cross-tenant record mutation triggered by an attacker-controlled repository's payload, matching the "payload for one repository mutating another's stack/commit" Critical category.

### Likelihood Explanation
Preconditions: the victim stack must have already ingested a `Commit` row with a given `sha` (normal for any tracked repo); the attacker needs a repo of their own with a webhook configured through the same Shipit/GitHub App installation, and a commit sharing that SHA - achievable by forking the victim repo prior to any divergent commit, or by any other means of producing an identical git object (same tree/parents/author/timestamp). No Shipit secrets, sessions, or team membership are required - only the ability to push/fork and trigger a `status` webhook, which is fully within the stated unprivileged attacker capabilities. This is repeatable against any repository/stack combination where a shared SHA can be engineered.

### Recommendation
Scope the lookup in `StatusHandler#process` to the requesting repository: resolve `stacks` via `Repository.from_github_repo_name(payload.dig('repository','full_name'))` (as `Handler#stacks` already provides) and restrict `Commit.where(sha: params.sha, stack: stacks)` (or otherwise join through the repository's stacks) before calling `create_status_from_github!`, so a commit is only mutated if it belongs to a stack owned by the repository that authenticated the webhook.

### Proof of Concept
Minitest under `test/models/shipit/webhooks/handlers/status_handler_test.rb` (or equivalent):

```ruby
test "process does not update a commit belonging to a different repository even when sha collides" do
  victim_stack = shipit_stacks(:shipit)  # tracks e.g. "Shopify/shipit-engine", branch "master"
  victim_commit = victim_stack.commits.create!(sha: "a" * 40, ...)

  payload = {
    "sha" => victim_commit.sha,
    "state" => "success",
    "context" => "ci/attacker",
    "branches" => [{ "name" => "master" }],       # named to match victim's branch
    "repository" => { "full_name" => "attacker/own-repo" }, # attacker's own repo, not victim's
  }

  before_status = victim_commit.reload.status.state
  Shipit::Webhooks::Handlers::StatusHandler.call(payload)
  after_status = victim_commit.reload.status.state

  # Broken binding demonstrated: mutation happens regardless of branches/repository.full_name values
  assert_not_equal before_status, after_status  # currently PASSES today, proving unscoped mutation
end

test "identical mutation occurs whether branches/repository.full_name match victim or not" do
  victim_commit = shipit_stacks(:shipit).commits.create!(sha: "b" * 40, ...)

  payload_matching = { "sha" => victim_commit.sha, "state" => "failure", "context" => "c",
                        "branches" => [{ "name" => "master" }],
                        "repository" => { "full_name" => "Shopify/shipit-engine" } }
  payload_attacker = payload_matching.merge(
    "branches" => [{ "name" => "totally-unrelated" }],
    "repository" => { "full_name" => "attacker/unrelated-repo" }
  )

  Shipit::Webhooks::Handlers::StatusHandler.call(payload_matching)
  state_a = victim_commit.reload.state
  victim_commit.statuses.destroy_all
  Shipit::Webhooks::Handlers::StatusHandler.call(payload_attacker)
  state_b = victim_commit.reload.state

  assert_equal state_a, state_b  # proves branches/repository.full_name are inert
end
```

```ruby
        end
```

```ruby
# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end
```
