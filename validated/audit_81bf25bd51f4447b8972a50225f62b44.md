### Title
Unprivileged whale can permanently freeze a market by driving accrued debt value past the i128 RAY capacity, panicking every subsequent accrual - (File: common/src/rates/scaling.rs)

### Summary
Interest accrual converts scaled debt to original value via `scaled_to_original(scaled, index)`, which panics on i128 overflow. Because every state-mutating pool op accrues first (`interest::global_sync`), once the borrow index grows enough that `borrowed × borrow_index` exceeds the RAY/i128 domain, every operation on that market — repay, withdraw, liquidate, update_indexes — reverts permanently. An unprivileged user can set this up by supplying and borrowing a very large position at sustained high utilization, where the index compounds ~170x before the `MAX_BORROW_INDEX_RAY` cap engages.

### Finding Description
`accrue_step` (common/src/rates) unscales `borrowed` and `supplied` each chunk to compute utilization and interest. `scaled_to_original` calls `scaled.mul(env, index)` which traps `MATH_OVERFLOW` when the product exceeds i128 capacity [1](#0-0) . `global_sync` runs this before any pool mutation and is also invoked by the permissionless `update_indexes` [2](#0-1) [3](#0-2) . The index cap (`MAX_BORROW_INDEX_RAY` = 10^36, ~10^9x) never engages because the value ceiling is hit first at ~170x index growth on a whale-scale 18-decimal book [4](#0-3) .

### Impact Explanation
Permanent freezing of funds / market insolvency freeze: once the accrual panics, no verb can execute on that market — suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and `clean_bad_debt`/`recapitalize` paths also accrue first. All supplied cash in that market is locked indefinitely. This maps the incident class (network-wide outage from degraded state) onto a single-market liveness failure reachable with only `supply`, `borrow`, and `update_indexes` calls.

### Likelihood Explanation
Requires a whale-scale position (test uses ~10^27 raw units of an 18-decimal asset with caps lifted) and years of sustained ~98% utilization on a steep rate curve. No privileged action is needed — `supply` and `borrow` are permissionless and `update_indexes` requires only caller auth [5](#0-4) . Caps set at listing bound the scaled-position domain, but `require_cap_within_asset_domain` validates the cap at index=1 scale and does not account for plausible index growth, as the threat model itself notes [6](#0-5) . High capital requirement and long horizon reduce likelihood; severity is bounded by Medium.

### Recommendation
Compute utilization and interest on values that cannot overflow: e.g., saturate or short-circuit accrual when `scaled_to_original(borrowed, borrow_index)` exceeds the RAY domain instead of panicking, or cap `borrowed`/`supplied` scaled shares at listing/index time so `scaled × index` stays representable for the maximum possible index (10^36). Alternatively, make `global_sync` clamp the borrow index earlier (below the value-overflow point) so accrual becomes a no-op rather than a trap. At minimum, validate supply/borrow caps against `cap_scaled × MAX_BORROW_INDEX_RAY ≤ i128::MAX` in `require_cap_within_asset_domain`.

### Proof of Concept
Existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the full path [7](#0-6) :

1. Unprivileged `BOB` supplies `10^9 × 10^18` of an 18-decimal asset (`supply`); `ALICE` supplies collateral and borrows 98% of it (`borrow`) — all permissionless entrypoints.
2. Time advances; each year anyone calls `controller.update_indexes(caller, [hub_asset])`.
3. After the index compounds ~170x (well below `MAX_BORROW_INDEX_RAY`), `update_indexes` fails with `MATH_OVERFLOW` inside `scaled_to_original`.
4. `withdraw` and `repay` fail identically — every verb accrues first, so the market is frozen with all supplier funds locked.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
