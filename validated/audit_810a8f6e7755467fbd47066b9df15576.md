Confirmed: this vulnerability is real and demonstrable within the engine's own code.

### Title
Webhook signature is verified against `repository.owner.login`'s org while the handler mutates the repository named by `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret`) using `repository_owner` = `payload.dig('repository','owner','login')`, but every `Handler` subclass (and `Handler#stacks`) resolves the target `Repository` using `repository_name`/`params.repository.full_name`. These two payload fields are never cross-validated, so an attacker can supply a `full_name` naming a repository owned by a *different* org than `owner.login`.

### Finding Description
The broken binding is: `Repository.from_github_repo_name(payload.dig('repository','full_name')).owner` MUST equal `payload.dig('repository','owner','login')` (the org whose secret verified the signature), but the code never enforces this.

- `WebhooksController#verify_signature` does: `github_app = Shipit.github(organization: repository_owner)` then `github_app.verify_webhook_signature(sig, raw_post)`, where `repository_owner` reads only `repository.owner.login` (`app/controllers/shipit/webhooks_controller.rb:24-49,59-62`).
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally `unless webhook_secret` is configured for that org (`lib/shipit/github_app.rb:76-83`), and `docs/setup.md` explicitly documents `webhook_secret` as optional, and the test fixtures (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets.yml`) show orgs configured with a nil `webhook_secret`.
- Every event handler (`Handler#stacks`, `PullRequest::OpenedHandler#repository`, `ClosedHandler#repository`, `LabeledHandler#repository`, `UnlabeledHandler#repository`, `ReopenedHandler#repository`, `LabelCapturingHandler#repository`) resolves the repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — reading `full_name`, not `owner.login` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`, `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:50-54`, etc.).

Attack: attacker controls an org `attacker-org` configured in Shipit with a blank `webhook_secret` (or any org lacking a secret — a documented, supported, common configuration for a "public-repo watcher" style app). Attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and body:
```json
{ "action": "opened", "number": 1, "pull_request": {...}, "sender": {"login": "attacker"}, "repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"} }
```
`verify_signature` calls `Shipit.github(organization: "attacker-org")`, whose `verify_webhook_signature` returns `true` because that org's `webhook_secret` is blank — no signature is even required. The request passes to `Shipit::Webhooks.for_event('pull_request')`, and `OpenedHandler#repository` resolves `victim-org/victim-repo` via `full_name`, and if that repository has `review_stacks_enabled` + suitable `provisioning_behavior`, `ReviewStackAdapter#find_or_create!` creates a `Stack` row on the victim repository (`app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb:72-85`), or `ClosedHandler`/`Labeled/UnlabeledHandler` archive/unarchive an existing one.

Existing guards fail to prevent this: `verify_signature` never checks `full_name`'s owner against `repository_owner`; `ExplicitParameters` schemas only validate types/presence, not cross-field consistency; `drop_unhandled_event` and `check_if_ping` are unrelated; model validations on `Repository`/`Stack` only constrain format, not ownership provenance.

### Impact Explanation
An attacker who controls (or merely names, since GitHub doesn't require the attacker to own `attacker-org` for a webhook payload they self-POST directly to `/webhooks` — they aren't going through GitHub's dispatch, they're calling the endpoint directly) any org string configured in Shipit with no `webhook_secret` can create, archive, or unarchive review-stack `Stack` records for an arbitrary victim repository/org, entirely bypassing that repository's own authentication expectations. This is a cross-tenant write: the party that "authenticated" (weakly, via a blank secret) is not the party whose data is mutated. This matches the Critical category "a payload for one repository mutating another's stack." Blast radius spans all repositories/orgs configured in the same Shipit instance whenever at least one configured org has no `webhook_secret`.

### Likelihood Explanation
Preconditions: at least one org configured in `Shipit.secrets.github` must have a blank/absent `webhook_secret` (explicitly supported/documented as optional), and the victim repository must have `review_stacks_enabled` with a provisioning behavior that reacts to the crafted event. Attacker cost is a single unauthenticated HTTP POST to `/webhooks` with attacker-chosen JSON — no secrets, sessions, or GitHub App credentials needed, and it is fully repeatable against any repository name.

### Recommendation
In `WebhooksController#verify_signature`, after resolving `github_app`, additionally verify that `repository_owner` matches the owner segment of `payload.dig('repository','full_name')` (reject mismatches with `422`). Alternatively/complementarily, in `Handler#repository`/`Handler#stacks`, cross-check that the resolved `Repository#owner` equals the org used for signature verification, refusing to process otherwise. Also consider requiring `webhook_secret` to be present for all configured orgs (fail closed when blank) rather than treating blank as "verification not required."

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "cross-org payload can mutate a victim repository's stacks when attacker org has no webhook_secret" do
  victim_repo = shipit_repositories(:shipit) # owner: 'shopify' or similar, review_stacks_enabled: true, provisioning_behavior: allow_all
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(
    Shipit::GitHubApp.new('attacker-org', webhook_secret: nil)
  )

  request.headers['X-Github-Event'] = 'pull_request'
  payload = {
    action: 'opened',
    number: 999,
    pull_request: {
      id: 1, number: 999, url: 'https://api.github.com/x', title: 't', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'abc', ref: 'feature' },
      user: { login: 'attacker' },
      assignees: [], labels: []
    },
    repository: { owner: { login: 'attacker-org' }, full_name: victim_repo.github_repo_name },
    sender: { login: 'attacker' }
  }.to_json

  assert_difference -> { victim_repo.stacks.count }, 1 do
    post :create, body: payload, as: :json
  end
  # Assert the equality was violated: attacker-org (verifier) != victim_repo.owner (mutated)
  assert_not_equal 'attacker-org', victim_repo.owner
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
