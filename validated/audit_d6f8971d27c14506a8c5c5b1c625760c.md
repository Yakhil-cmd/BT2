### Title
Single-address asset definer can unilaterally freeze legitimate holders of a `spender_attested` asset via attestor-list updates - (File: validation.js, function: `validateAttestorListUpdate`)

### Summary
When an asset is created with `spender_attested: true`, all subsequent transfers/issues of that asset are gated on the current, single latest attestor list for the asset. The list is fully controlled by one address — the asset's `definer_address`, which is simply the author of the asset-defining unit and is not required to be a multisig, voting contract, or timelocked governance address. That address can post an `asset_attestors` message at any time, instantly replacing the trusted attestor set with no delay and no consent from asset holders. Because the protocol always looks at only the *latest* attestor list when checking whether a spender is attested, a definer can drop or swap attestors and instantly render previously-attested, entirely honest holders unable to move their existing balance — an analog of the Stakehouse DAO being able to unilaterally strip a non-malicious node runner's rights, without a two-step/governed transfer of the controlling role.

### Finding Description
Asset creation records `definer_address` as the author of the asset-defining unit, and this is the only address ever allowed to update the attestor list: [1](#0-0) [2](#0-1) 

The definer needs no governance, voting, or timelock contract — it can be (and in practice usually is) a single EOA, exactly like the Stakehouse DAO address which "is not required to be an address that corresponds to a governance contract."

Once an `asset_attestors` update is included and becomes stable, only the *most recent* attestor list for the asset matters — older attestor addresses (and any attestations issued under them) are discarded for the purpose of authorizing spends: [3](#0-2) 

Payment validation for a `spender_attested` asset requires that the payer/issuer be found in the current attested-address set derived from that latest list: [4](#0-3) [5](#0-4) 

The attestor-list update itself is validated with essentially only an ownership check (`objUnit.authors[0].address !== objAsset.definer_address`) and a well-formedness check — there is no cooldown, no requirement that removed attestors' prior attestations remain valid for some grace period, and no requirement that the definer be a multi-party or timelocked contract: [2](#0-1) [6](#0-5) 

Thus a single compromised or malicious definer key can, in one unit, drop the attestor(s) who attested a particular honest holder (or add new attestors it colludes with while removing old ones), instantly cutting off that holder's ability to spend a balance they already legitimately hold in the asset — mirroring the Stakehouse pattern where a single unaccountable, non-timelocked, non-governed address can restrict a non-malicious party's use of assets they otherwise control.

### Impact Explanation
Any holder or payer of a `spender_attested` asset who is not directly colluding with the definer can be frozen out of spending their existing coins at the sole discretion of the definer address, with no timelock, multisig requirement, or on-chain governance enforced by the protocol. This is a direct asset-freezing impact reachable by any ordinary asset issuer role (a role explicitly in scope) acting maliciously or being compromised, analogous to the Stakehouse DAO unilaterally banning/rotating a non-malicious node runner. Because the change takes effect as soon as the `asset_attestors` unit is stable, affected holders have no recourse and no advance warning window.

### Likelihood Explanation
Likelihood is Medium: it requires the specific asset's definer key to be compromised or turn malicious (exactly the threat model in the referenced report), which is plausible for any asset whose definer is a single EOA — the default and most common configuration, since the protocol imposes no requirement for the definer to be a governance/multisig address. No cryptographic break or consensus flaw is needed; the definer merely posts a single, correctly-signed `asset_attestors` message.

### Recommendation
- Require (or strongly recommend/tooling-enforce) that `definer_address` for assets using `spender_attested`/attestor-gated transfer be a multisig or otherwise governed address rather than a single EOA.
- Introduce a delay/grace period before an attestor-list change takes effect for spending validation, so holders attested under the previous list retain the ability to move already-held balances for some window after a list change, and/or preserve validity of attestations issued under a still-recent prior list rather than only the single latest one.
- Consider emitting an explicit warning/require higher friction (e.g., two-step confirmation unit) for attestor-list updates that remove existing attestors, distinguishing "add attestor" from "remove attestor" operations.

### Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true`, `attestors: [X]`.
2. Attestor `X` attests honest address `H`; `H` receives/holds units of asset `A` and legitimately expects to be able to spend them per `validatePayment`/`filterAttestedAddresses`.
3. `D`'s key is compromised (or `D` turns malicious) and posts `asset_attestors` for asset `A` with `attestors: [Y]` (dropping `X`).
4. Once this unit is stable, `storage.readAsset`'s `addAttestorsIfNecessary` picks this newest list `[Y]` as the only attestor set (`storage.js:1922-1946`).
5. `H` attempts to spend previously-held `A` coins; `filterAttestedAddresses` no longer finds `H` attested (attestor `X` is gone), so `validatePayment` returns `"none of the authors is attested"` (`validation.js:2115-2122`), permanently freezing `H`'s existing, legitimately-acquired balance — despite `H` having done nothing wrong.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}
