### Title
Signature verification is bound to `repository.owner.login`/`organization.login` while the actual mutated Stack is resolved from `repository.full_name`, allowing a no-secret tenant to trigger `sync_github` on another tenant's repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) using `repository_owner`, which is read from the same attacker-controlled JSON body and can be made to point to a different, unsecured organization than the one actually referenced by `repository.full_name`. Because `Handler#stacks` (used by `PushHandler#process`) resolves the target `Stack` solely from `repository.full_name`, the organization that "verifies" the payload and the organization that owns the mutated stack can diverge, breaking the intended binding: `verifying_org == owning_org`.

### Finding Description
The broken binding, made explicit:
- Left side: `organization_that_verified_signature = Shipit.github(organization: repository_owner).webhook_secret_owner`
- Right side: `organization_whose_stack_is_mutated = Repository.from_github_repo_name(payload.dig('repository','full_name')).owner`

These are computed from independent, both attacker-controlled, fields of the same JSON body:

- `repository_owner` in the controller is computed as:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

If the attacker omits the `repository.owner` sub-key (while still including `repository.full_name`), this falls back to `organization.login`, letting the attacker fully decouple "who signs" from "whose repo is named."

- `verify_signature` then does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
head(422) unless verified
``` [2](#0-1) 

- `GitHubApp#verify_webhook_signature` unconditionally returns `true` if no secret is configured for that org:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [3](#0-2) 

- `Shipit.github(organization:)` only raises `GithubOrganizationUnknown` (→ HTTP 422) if the org key is completely absent from the multi-org `secrets.github` config; if `attacker-org` is a *registered* tenant with a blank `webhook_secret`, the app resolves normally with `@webhook_secret = nil`:
```ruby
def github(organization: github_default_organization)
  if github_default_organization.nil?
    config = secrets.github
  else
    config = github_app_config(organization)
    raise GithubOrganizationUnknown, organization if config.nil?
  end
  @github[organization] ||= GitHubApp.new(organization, config)
end
``` [4](#0-3) 

- After verification "succeeds," `create` re-parses the same raw body and dispatches to `PushHandler`:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [5](#0-4) 

- The base `Handler` resolves the target repository/stacks purely from `repository.full_name`, with no reference to `repository_owner` or any verified organization:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [6](#0-5) 

- `PushHandler#process` then calls `sync_github` on any matching stack:
```ruby
def process
  stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [7](#0-6) 

which enqueues `GithubSyncJob` for the real stack:
```ruby
def sync_github(expected_head_sha: nil)
  GithubSyncJob.perform_later(stack_id: id, expected_head_sha:)
end
``` [8](#0-7) 

No component re-checks that the organization used to verify the HMAC (attacker-org, no secret) matches the organization that owns the acted-upon repository (shopify). `ExplicitParameters` for `PushHandler` only requires `:ref` and `:after`, not `repository.owner`, so it does not constrain or reject the crafted payload. `drop_unhandled_event` and `check_if_ping` only filter on event type and do not enforce this binding either.

### Impact Explanation
A push-event payload crafted by anyone who controls a Shipit-registered organization/app config with no `webhook_secret` set can trigger `GithubSyncJob` (and thus a GitHub resync of commits/branch state) for any other tenant's `Stack`, purely by naming that victim's `repository.full_name` in the JSON body while letting signature verification resolve against their own, secret-less org. This is a cross-tenant/cross-repository state mutation triggered without possessing any valid signature for the victim's repository, matching the "payload for one repository mutating another's stack" Critical category.

### Likelihood Explanation
This is **not** exploitable against a single-tenant Shipit deployment using the legacy single `secrets.github` config, because in that mode `Shipit.github(organization:)` ignores the `organization` argument entirely and always uses the one global app/secret (`github_default_organization.nil?` branch) [9](#0-8) . The attack is only feasible in a **multi-organization deployment** (multiple orgs each with independent GitHub App config under `secrets.github`) where at least one registered org's config has a blank/absent `webhook_secret`. That is an operator/tenant misconfiguration, not something the attacker unilaterally controls, but it is a realistic misconfiguration in multi-tenant setups (e.g., an org onboarded without setting up its secret yet). Given that precondition, the attack requires zero credentials — a single unauthenticated `POST /webhooks` request with a crafted JSON body and no `X-Hub-Signature` header — and is fully repeatable against arbitrary target repositories/stacks.

### Recommendation
- In `WebhooksController#verify_signature`, do not let `verify_webhook_signature` succeed unconditionally when `webhook_secret` is blank for a resolved org; either require every configured org to have a non-blank `webhook_secret`, or reject (422) webhooks for orgs with no secret rather than treating them as always-verified.
- Enforce that the organization used for signature verification matches the owner of `repository.full_name` actually acted upon by the handler (i.e., derive `repository_owner` strictly from `repository.full_name`'s owner segment, not from `organization.login`, and never allow it to fall back to unrelated payload fields).
- Add a validation step before dispatching to handlers that the verified organization equals `Repository.from_github_repo_name(payload.dig('repository','full_name'))`'s registered owner/organization.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "push event verified by no-secret attacker org cannot sync a victim org's stack" do
  # Preconditions: multi-org secrets.github with:
  #   github.attacker-org  (no webhook_secret)
  #   github.shopify       (webhook_secret set)
  # victim_stack belongs to repository "shopify/shipit-engine"

  request.headers['X-Github-Event'] = 'push'
  body = {
    ref: 'refs/heads/master',
    after: 'deadbeef',
    repository: { full_name: 'shopify/shipit-engine' }, # no "owner" key
    organization: { login: 'attacker-org' }
  }.to_json

  # No X-Hub-Signature header at all.
  assert_no_enqueued_jobs do
    post :create, body:, as: :json
  end
  # A correct implementation must NOT enqueue GithubSyncJob for victim_stack,
  # because "attacker-org" (no secret) != "shopify" (repository owner).
end
```
Both sides of the binding must be asserted: `repository_owner` resolved by the controller (`"attacker-org"`) vs. the organization owning `repository.full_name` (`"shopify"`); the test should assert `GithubSyncJob` is **not** enqueued for the victim stack when these differ, given the stated no-secret multi-org configuration.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
