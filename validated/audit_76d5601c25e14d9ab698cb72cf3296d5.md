The CVE describes CMIS-SQL injection via unsanitized string concatenation into a query language, exploitable through a public password-reset email field in Alfresco. This bug class requires an entry point where attacker-controlled input is concatenated into a query/command string without escaping.

Polkadot SDK storage access does not follow this pattern. Runtime storage keys are constructed via typed SCALE encoding and cryptographic hashing (`Twox128`/`Blake2`), not string concatenation into an interpretable query language, and the codebase explicitly documents the requirement to hash untrusted, user-supplied keys to prevent collision/interference: [1](#0-0)  and the analogous double-map warning [2](#0-1) . Storage key construction functions like `storage_map_final_key` always hash the key material before use rather than interpolating raw attacker strings into a query [3](#0-2) .

The only SQL usage found in scope is a compile-time `sqlx` query cache file used with parameterized queries (`$1` placeholder, not string interpolation) for the `revive` RPC's local transaction index, which is not attacker-reachable input construction [4](#0-3) . Offchain worker HTTP requests take a URL string directly from runtime code (not from an untrusted external network input reachable by an anonymous attacker through a signed extrinsic) and are non-deterministic/off-chain by design, so no state mutation or cross-pallet effect can result from them [5](#0-4) .

No user-facing extrinsic, XCM instruction, or bridge message handler was found that builds a query/command string by concatenating unsanitized attacker input in a way that changes query semantics (the CMIS-SQL injection invariant violated in the original CVE). Storage/RPC access in this codebase uses typed encoding and hashed keys rather than free-form query strings, so the specific missing-check (unescaped user input altering query structure) has no reachable analog here.

	fn storage_map_final_key<KeyArg>(key: KeyArg) -> Vec<u8>
	where
		KeyArg: EncodeLike<K>,
	{
		let storage_prefix = storage_prefix(Self::pallet_prefix(), Self::storage_prefix());
		let key_hashed = key.using_encoded(Self::Hasher::hash);

		let mut final_key = Vec::with_capacity(storage_prefix.len() + key_hashed.as_ref().len());

		final_key.extend_from_slice(&storage_prefix);
		final_key.extend_from_slice(key_hashed.as_ref());

		final_key
	}
