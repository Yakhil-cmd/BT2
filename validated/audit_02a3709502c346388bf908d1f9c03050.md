### Title
Path traversal via release asset `Name` allows writes outside destination directory - (File: pkg/cmd/release/download/download.go)

### Summary
`gh release download` uses the release asset's `Name` field verbatim to build the destination file path via `destinationWriter.makePath`, which calls `filepath.Join(w.dir, name)` with no confinement check. An attacker who publishes a release (on any repo the victim points `gh` at, e.g. via `-R owner/repo`) with an asset name containing `../` sequences or an absolute path can cause the CLI to write the downloaded content outside `opts.Destination`.

### Finding Description
`downloadRun` builds `downloadTarget{name: a.Name}` directly from `shared.ReleaseAsset` values fetched from the GitHub API (`a.Name` maps to JSON field `name`), with no sanitization [1](#0-0) . This name flows into `downloadAsset` and then `dest.Copy(fileName, resp.Body)` [2](#0-1) [3](#0-2) .

`destinationWriter.makePath` computes the file path as `filepath.Join(w.dir, name)` with no bound/confinement check [4](#0-3) . `Copy` then creates any needed parent directories with `os.MkdirAll` and opens the file for writing, again with no path confinement check [5](#0-4) .

`filepath.Join` cleans `..` segments algebraically but does not prevent the result from escaping `w.dir` when `name` contains traversal sequences (e.g. `../../.ssh/authorized_keys`), and if `name` were itself an absolute path, `filepath.Join` combined with an absolute second element still resolves relative to root, not `w.dir`, on Unix (`filepath.Join("dest", "/etc/passwd")` → `dest/etc/passwd`, though on some interpretations/other join semantics an absolute name can still escape intended relative confinement expectations). The primary concrete exploit is the classic `../` relative traversal case.

This is unlike the comparable artifact-download code path (`pkg/cmd/run/download`), which explicitly uses `internal/safepaths.Absolute.Join` to reject any join that would escape the destination directory (`PathTraversalError`) [6](#0-5) , and `internal/zip/zip.go`'s `ExtractZip` similarly guards zip entries. The release-asset download path in `download.go` has no equivalent guard — `makePath`/`Copy` never validate that the joined path remains a subpath of `w.dir`.

Exploit flow: an attacker with write access to some repository (their own repo, a fork, etc. — no special privileges over the victim needed) creates a release and uploads/sets an asset whose `name` field is `../../.ssh/authorized_keys` (or similar, e.g. targeting `.bashrc`, `.git/hooks/pre-commit`). If the victim runs `gh release download <tag> -R attacker/repo` (or is otherwise induced to target that repository), `downloadAsset`/`Copy` will create parent directories via `MkdirAll` and write the attacker-controlled asset content to the traversed path, since no confinement check exists.

### Impact Explanation
This permits arbitrary file write on the victim's filesystem, limited to paths reachable via relative traversal from the destination directory (typically the user's home directory tree, since `gh` is usually run from a directory under `$HOME`). Overwriting files such as shell startup files (`.bashrc`, `.zshrc`), SSH `authorized_keys`, or git hooks can lead to code execution or persistent backdoors on the victim host the next time an affected file is sourced/executed. This corresponds to a file-write/code-execution class finding.

### Likelihood Explanation
Exploitability requires only that: (1) the attacker can publish a release with an asset name they control (trivial — any repo owner/writer, including on their own repository or fork), and (2) the victim runs `gh release download` against that repository/release (common when following instructions, testing PRs, or being directed to `-R attacker/owner`). No token, MITM, or special privilege is required beyond controlling the release/asset metadata of a repo the victim targets. This is a straightforward, repeatable traversal — no race conditions or symlink tricks needed.

### Recommendation
Confine the computed destination path to `w.dir` before writing, mirroring the `internal/safepaths.Absolute.Join` pattern used in `pkg/cmd/run/download`. Concretely, in `destinationWriter.makePath`/`Copy`, resolve `w.dir` to a `safepaths.Absolute`, join with `name`, and reject (return an error) if the result is not a subpath of `w.dir`. Also reject asset names containing an absolute path outright.

```go
    opts := &DownloadOptions{
        HttpClient: func() (*http.Client, error) { return &http.Client{Transport: reg}, nil },
        BaseRepo:   func() (ghrepo.Interface, error) { return ghrepo.New("OWNER", "REPO"), nil },
        Destination: dest,
        IO: iostreams.Test(),
    }

    err := downloadRun(opts)
    require.NoError(t, err)

    // Assert the file was NOT written outside `dest` (this currently FAILS,
    // demonstrating the vulnerability):
    escapedPath := filepath.Join(tmpDestParent, "evil.txt")
    _, statErr := os.Stat(escapedPath)
    assert.True(t, os.IsNotExist(statErr), "asset should not escape destination directory, but was written to %s", escapedPath)

    // Confirm nothing legitimate was written inside dest either, proving escape:
    _, err2 := os.Stat(filepath.Join(dest, "../../evil.txt"))
    _ = err2

```
Expected (current, vulnerable) behavior: the file is written to `tmpDestParent/evil.txt`, i.e. two levels above the intended `dest` directory, because `makePath` does `filepath.Join(dest, "../../evil.txt")` with no confinement check. After applying the recommended `safepaths.Absolute.Join`-based fix, `downloadRun`/`Copy` should return a `PathTraversalError` instead of writing the file.

```go
func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
```

```go
// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
```
