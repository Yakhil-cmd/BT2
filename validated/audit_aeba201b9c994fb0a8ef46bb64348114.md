### Title
Unprivileged Pool Creation with Freeze-Authority Mints Enables Permanent Freezing of Vault Funds — ([File: programs/cp-swap/src/utils/token.rs])

### Summary
`initialize` and `initialize_with_permission` allow any unprivileged caller to create a pool for arbitrary `token_0_mint`/`token_1_mint` accounts. The only mint-safety gate is `is_supported_mint`, which never inspects the mint's `freeze_authority` field. A pool can therefore be created for a token whose issuer holds freeze authority; once the pool's vault token account is frozen, all instructions that move tokens into or out of that vault (`deposit`, `withdraw`, `swap_base_input`, `swap_base_output`) permanently revert, locking already-deposited LP funds in the vault forever.

### Finding Description
In `initialize` (`programs/cp-swap/src/instructions/initialize.rs`) and `initialize_with_permission` (`programs/cp-swap/src/instructions/initialize_with_permission.rs`), the mints are validated only via `is_supported_mint`: [1](#0-0) 

The check itself, defined in `programs/cp-swap/src/utils/token.rs`, unconditionally accepts any plain SPL Token mint and, for Token-2022 mints, only rejects a hard-coded set of extensions — never the mint's `freeze_authority` (which is a base `Mint` field, not an extension, for both Token and Token-2022): [2](#0-1) 

The vault token accounts (`token_0_vault`, `token_1_vault`) are then created and owned by the pool `authority` PDA via `create_token_account`: [3](#0-2) 

Because the underlying mint's freeze authority is never checked, the token issuer (or anyone the issuer authorizes) can freeze either vault token account at any time after the pool is created and funded via `transfer_from_user_to_pool_vault`: [4](#0-3) [5](#0-4) 

Once a vault is frozen, `transfer_checked` CPIs into/out of it fail at the SPL token program level, so `deposit`, `withdraw`, `swap_base_input`, and `swap_base_output` — all of which move tokens via this same `transfer_from_user_to_pool_vault`/vault-transfer path — will revert whenever they touch the frozen vault.

### Impact Explanation
Any funds already deposited into the frozen vault (LP-provided liquidity plus swap proceeds) become permanently unwithdrawable: `withdraw` cannot pull tokens out of a frozen vault, and `swap_base_input`/`swap_base_output` cannot deliver output tokens from a frozen vault. This is a permanent freezing of LP/user funds, not merely a temporary inconvenience, since the freeze authority is external to the program and the pool has no mechanism to migrate or recover vault funds. This qualifies as a Medium/High severity issue per the accepted impact criteria (permanent freezing of user/LP funds).

### Likelihood Explanation
`initialize` is explicitly open to any signer ("Address paying to create the pool. Can be anyone"), and `initialize_with_permission` is reachable by any creator satisfying the permissioned-creator checks — both are in-scope, unprivileged entry points. An attacker (or a malicious/compromised token issuer) only needs to create a pool using a mint they control with `freeze_authority` set, wait for liquidity to accumulate, then freeze the vault ATA. This requires no special access beyond normal token creation and a single `initialize` transaction, making the path realistically and cheaply reachable.

### Recommendation
During `initialize`/`initialize_with_permission`, read the base `Mint` state of `token_0_mint`/`token_1_mint` and reject (or explicitly flag) mints where `freeze_authority.is_some()`, mirroring the fix implemented in the referenced report. If tokens with freeze authority must be supported (e.g., regulated stablecoins), gate them behind an explicit allowlist/admin approval (similar to the existing `SupportMintAssociated` mechanism) rather than allowing any unprivileged caller to onboard such a mint.

### Proof of Concept
1. Attacker creates an SPL Token (or Token-2022) mint `M` and sets themselves as `freeze_authority`.
2. Attacker calls `initialize` with `token_0_mint = M`, providing an unprivileged `creator` signer; `is_supported_mint` passes because freeze authority is never checked (`programs/cp-swap/src/utils/token.rs:335-360`).
3. Attacker (or a victim LP) deposits liquidity via `deposit`, transferring `M` tokens into `token_0_vault` (PDA-owned ATA) via `transfer_from_user_to_pool_vault`.
4. Attacker, using the mint's freeze authority, calls `token_2022::freeze_account`/`token::freeze_account` on `token_0_vault`.
5. Any subsequent `withdraw`, `swap_base_input`, or `swap_base_output` touching `token_0_vault` fails at the SPL token CPI layer, permanently locking all deposited `M` (and the paired token) inside the pool.

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount
        {
            return Ok(false);
        }
    }
    Ok(true)
}

pub fn create_token_account<'a>(
    authority: &AccountInfo<'a>,
    payer: &AccountInfo<'a>,
    token_account: &AccountInfo<'a>,
    mint_account: &AccountInfo<'a>,
    system_program: &AccountInfo<'a>,
    token_program: &AccountInfo<'a>,
    signer_seeds: &[&[u8]],
) -> Result<()> {
    let space = {
        let mint_info = mint_account.to_account_info();
        if *mint_info.owner == token_2022::Token2022::id() {
            let mint_data = mint_info.try_borrow_data()?;
            let mint_state =
                StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
            let mint_extensions = mint_state.get_extension_types()?;
            let required_extensions =
                ExtensionType::get_required_init_account_extensions(&mint_extensions);
            ExtensionType::try_calculate_account_len::<spl_token_2022::state::Account>(
                &required_extensions,
            )?
        } else {
            TokenAccount::LEN
        }
    };
    create_or_allocate_account(
        token_program.key,
        payer.to_account_info(),
        system_program.to_account_info(),
        token_account.to_account_info(),
        signer_seeds,
        space,
    )?;
    initialize_account3(CpiContext::new(
        *token_program.key,
        InitializeAccount3 {
            account: token_account.to_account_info(),
            mint: mint_account.to_account_info(),
            authority: authority.to_account_info(),
        },
    ))
}
