### Title
Unauthenticated stack merge-status disclosure via `MergeStatusController#check` - (File: app/controllers/shipit/merge_status_controller.rb)

### Summary
`MergeStatusController#check` is exempted from authentication via `skip_authentication only: %i[check show]` and, unlike `#show`, never checks `current_user.logged_in?` before rendering the stack's merge status. This lets any unauthenticated internet client fetch a tracked stack's `locked`/`failure`/`backlogged`/`success` state for any repository by supplying a crafted `referrer` (or `stack_id`) parameter.

### Finding Description
The broken binding: `#show` enforces `current_user.logged_in? == true` before rendering stack state (`return render('logged_out') unless current_user.logged_in?`, [1](#0-0) ), but `#check` has no equivalent check at all — it goes straight to `stack_status` and renders it, [2](#0-1) . Both actions are exempted from `force_github_authentication` by the same `skip_authentication only: %i[check show]` line, [3](#0-2) , so `force_github_authentication` in `Shipit::Authentication` never runs and never redirects to `github_authentication_path` for either action, [4](#0-3) .

`stack_status` calls `stack.merge_status(backlog_leniency_factor: 1.0)`, which returns `'locked'`, `'failure'`, `'backlogged'`, or `'success'` based on the stack's lock state, branch CI status, and backlog size, [5](#0-4) [6](#0-5) . The `stack` is resolved from `params[:referrer]` parsed by `ReferrerParser` into `repo_owner`/`repo_name`, or from `params[:branch]`/default `environment: 'production'`, with no identity check anywhere in that resolution path, [7](#0-6) .

Attacker request: `GET /merge_status/check?referrer=https://github.com/<org>/<repo>/pull/<n>&branch=<branch>&format=json` with no session cookie. `#check` resolves the stack, computes `stack_status`, and responds with `render(json: { stack_status: })` or `render(plain: stack_status, status: 503)` — fully bypassing the `Shipit.github_teams` membership gate that governs all other stack-visibility surfaces.

### Impact Explanation
Any unauthenticated party can enumerate the lock/CI/backlog state (`locked`, `failure`, `backlogged`, `success`) of any stack tracked by this Shipit instance, for arbitrary repositories/branches, with unlimited repeatability since there is no session or token requirement. This is a read-only information disclosure (no write, no RCE, no credential exposure) but it does defeat the intended `Shipit.github_teams` authorization gate for stack-state visibility, matching the "unauthenticated read of stack state" High-severity category in the rules.

### Likelihood Explanation
No preconditions beyond knowing (or guessing) a tracked repository's owner/name and a PR URL or branch name — both are public/easily discoverable. No secrets, tokens, or privileged roles are required; the request is a single unauthenticated GET. This is trivially and repeatedly exploitable against any/all stacks on the instance.

### Recommendation
Add the same guard used in `#show` to `#check`: return an unauthenticated/generic response (e.g., HTTP 401/403, or a neutral "unknown" status) unless `current_user.logged_in?` (and ideally `current_user.authorized?`), or remove `:check` from `skip_authentication` entirely if the endpoint isn't intended to be a public health-check. If a public check is required (e.g., for CI badges), it should expose only a minimal boolean signal rather than the full `stack_status` enum, and should not resolve based on attacker-supplied `referrer`/`branch`/`stack_id` without any repo-membership binding.

### Proof of Concept
```ruby
# test/controllers/shipit/merge_status_controller_test.rb (conceptual addition)
test "#check leaks stack_status without authentication" do
  stack = shipit_stacks(:shipit)
  # no session[:user_id] set, no login
  get merge_status_check_path(referrer: "https://github.com/#{stack.repo_owner}/#{stack.repo_name}/pull/1", format: :json)

  assert_response :success # or 503 if not 'success'
  body = JSON.parse(response.body)
  assert_includes %w[locked failure backlogged success], body["stack_status"]
  refute_redirected_to Shipit::Engine.routes.url_helpers.github_authentication_path
end
```
This asserts that, with zero session/authentication, the JSON body reveals `stack_status` and no redirect to `github_authentication_path` ever occurs — confirming the missing `current_user.logged_in?` binding present in `#show` is absent in `#check`.
