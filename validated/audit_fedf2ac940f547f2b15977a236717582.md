### Title
CCMenu status URL grants an unscoped, all-stacks read token instead of the single-stack token it claims to authorize - ([File: app/controllers/shipit/ccmenu_url_controller.rb])

### Summary
`CCMenuUrlController#fetch` builds a per-stack "CCMenu" monitoring URL by embedding `stack_id` in the path, but the `ApiClient` token attached to that URL is created without any `stack` scoping, so the token is valid for reading every stack in the Shipit instance rather than only the stack the URL claims to represent.

### Finding Description
`app/controllers/shipit/ccmenu_url_controller.rb` builds the CCMenu URL for one specific stack (`stack.to_param`, resolved via `Stack.from_param!(params[:stack_id])`), and appends a `token` query parameter generated from an `ApiClient`: [1](#0-0) 

The client is created like this: [2](#0-1) 

Note that `stack:` is never passed to `ApiClient.create_with`/`find_or_create_by!`. `ApiClient` supports an optional `stack` association specifically meant to scope a token to a single stack: [3](#0-2) 

When a token is *not* scoped to a stack (`stack_id` is nil), `Api::BaseController#stacks` resolves to **all** stacks instead of a single one: [4](#0-3) 

`Api::CCMenuController` (which serves the CCMenu XML) authenticates directly off the `token` query-string parameter (bypassing normal session/basic-auth) and only requires the `read:stack` permission, not a stack match: [5](#0-4) 

The binding that should hold is: **stack the token authorizes == stack the URL/token is generated for and intended to expose**. Because `CCMenuUrlController#client` omits `stack:`, the created/reused `ApiClient` is global (`stack_id` is `nil`), so `current_api_client.stack_id?` is `false` and the effective authorization is "all stacks" for anyone holding that single `token` string — not just the one stack named in the URL path. The `find_or_create_by!(creator: current_user, name: 'CCMenu Client')` scoping also means every stack for which a given user requests a CCMenu URL reuses/returns the exact same unscoped token, further widening blast radius: one leaked URL/token exposes every stack's status the requesting user could see, not the single stack it was requested for.

This is the same trust-binding class described in the external report (a value the system treats as scoped/limited is silently broader than what governs the actual access decision), just manifesting on the "stack a token authorizes vs. the stack it actually touches" axis: the path segment `stack_id` implies per-stack scoping, but the underlying `ApiClient.stack_id` (the actual authorization check) is never set.

### Impact Explanation
CCMenu URLs are designed to be embedded in external/unauthenticated tools (CI dashboards, IRC/status bots, browser widgets) specifically because they carry their own bearer credential (`token`) instead of requiring a Shipit login. If such a URL for stack A leaks (which is the expected usage pattern — it is meant to be pasted into third-party tooling), the holder of that URL can strip the `stack_id` path segment and substitute any other stack's ID served by the same Shipit instance (`/api/stacks/<other_id>/ccmenu.xml?token=...`), and `Api::CCMenuController` will happily authenticate and return that other stack's build/deploy status because the token's permission (`read:stack`) has no stack constraint. This is an unauthenticated read of stack state that the URL was never intended to disclose, matching the "High — unauthenticated read of stack state" impact category.

### Likelihood Explanation
Likelihood is High for any environment where CCMenu URLs are actually used as designed: they are explicitly meant to leave the trust boundary of the authenticated web UI (embedded in third-party CI status tools), so leakage/exposure of the URL itself is the expected operating mode, not an edge case. No additional privilege, session, or GitHub App credential is required by the discoverer of the URL — only the query-string `token` already present in the leaked link plus knowledge/enumeration of another stack's numeric or slug ID (stack IDs/params are visible in ordinary Shipit URLs across the app to any authenticated user, and are low-entropy sequential integers or repo/env-based slugs).

### Recommendation
Scope the `ApiClient` created in `CCMenuUrlController#client` to the specific stack, e.g. pass `stack:` when creating/finding the client (and key the `find_or_create_by!` lookup on `stack:` as well as `creator:`), so the token's `stack_id` matches the stack embedded in the URL:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, stack: stack, name: 'CCMenu Client')
end
```
Additionally, `Api::CCMenuController` should independently verify that `current_api_client.stack_id.nil? || current_api_client.stack_id == stack.id` before rendering, so that even a pre-existing unscoped/global `read:stack` client cannot be silently reused across every stack via this endpoint.

### Proof of Concept
1. As an authenticated Shipit user, request a CCMenu URL for Stack A: `GET /stacks/:stack_a_id/ccmenu_url` (via `CCMenuUrlController#fetch`) → response contains `https://<host>/api/stacks/<stack_a_id>/ccmenu.xml?token=<TOKEN>`.
2. Confirm the underlying `ApiClient` has `stack_id: nil` and `permissions: ["read:stack"]` (verifiable in the DB / by inspecting `ApiClient.find_by(name: 'CCMenu Client', creator: user)`).
3. Take the leaked `<TOKEN>` and request a different stack: `GET /api/stacks/<stack_b_id>/ccmenu.xml?token=<TOKEN>`.
4. Observe `Api::CCMenuController#show` returns `200 OK` with Stack B's build status (`lastBuildStatus`, `lastBuildLabel`, etc.), even though the token was only ever advertised/generated for Stack A. Repeat for any/all stack IDs in the instance to enumerate build status for the entire fleet from a single leaked CCMenu link.

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

module Shipit
  module Api
    class CCMenuController < BaseController

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
