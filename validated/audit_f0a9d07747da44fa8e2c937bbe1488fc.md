### Title
API token stack-scoping bypass in CCMenu endpoint - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::ApiClient` records can be created with an optional `stack_id` to restrict a token to a single stack [1](#0-0) , and `Api::BaseController#stacks`/`#stack` enforces this by intersecting the requested stack with the token's authorized `stack_id` [2](#0-1) . `Api::CCMenuController`, however, defines its own `stack` method that fetches the stack directly by param, without going through the scoped `stacks` helper, silently breaking that binding [3](#0-2) .

### Finding Description
The intended invariant, verified by the test suite, is: *the stack a token authorizes* (`ApiClient#stack_id`) *must equal the stack a request touches*. `Api::BaseController` implements this by scoping `stacks` to `Stack.where(id: current_api_client.stack_id)` whenever the client is stack-bound, and every default `stack` resolver goes through that scoped relation [2](#0-1) . This is exercised by the test `"an api client scoped to a stack will only see that one stack"` [4](#0-3) .

`Api::CCMenuController` inherits from `BaseController` and only requires `:read, :stack` permission — a permission check that validates the *type* of operation, not *which* stack id is authorized (`ApiClient#check_permissions!` only compares against the `permissions` array, never `stack_id`) [5](#0-4) . Because `CCMenuController` overrides `stack` to call `Stack.from_param!(params[:stack_id])` directly instead of using the inherited, properly-scoped `stack`/`stacks` methods, the stack-id restriction on the token is never applied to this specific action [3](#0-2) . The route is mounted for any `stack_id` path segment [6](#0-5) , so any valid stack-scoped token can be replayed against an arbitrary `stack_id` in the URL.

The binding broken, expressed as an equality that should hold but doesn't:
`ApiClient#stack_id` (stack the token is authorized for) ≠ `stack_id` param used by `CCMenuController#show` (stack whose state is actually returned).

### Impact Explanation
A CCMenu-scoped token — explicitly the lowest-trust API credential in this engine, generated by `CCMenuUrlController` and meant to be embedded in third-party CI-dashboard tools/URLs [7](#0-6)  — or any admin-issued single-stack-scoped `ApiClient`, can be used to read build/deploy status (`lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`) for every other stack in the Shipit instance, not just the one it was authorized for [8](#0-7) . This is an unauthorized read of stack state across repository/stack boundaries, matching the "High" impact bucket (unauthenticated/unauthorized read of stack state).

### Likelihood Explanation
Exploitation requires only possession of any valid, stack-scoped API token/CCMenu URL — which is the class of credential this feature is designed to hand out broadly (embedded in CI dashboard tools, monitoring widgets, etc.), and no additional privilege, signature knowledge, or session is needed beyond that token. The attacker simply substitutes a different `stack_id` in the request path.

### Recommendation
Have `Api::CCMenuController#stack` reuse the inherited, permission-scoped `stack`/`stacks` accessor from `BaseController` (i.e. `stacks.from_param!(params[:stack_id])`) instead of calling `Stack.from_param!` directly, so that a stack-scoped `ApiClient#stack_id` is always intersected with the requested stack before rendering.

### Proof of Concept
1. Admin creates (or the app auto-creates via `CCMenuUrlController`) an `ApiClient` scoped to Stack A (`stack_id = A.id`, `permissions: ["read:stack"]`), and issues its `authentication_token` to a third-party CI dashboard.
2. That token holder sends `GET /api/stacks/<Stack B owner>/<Stack B repo>/<Stack B env>/ccmenu` (or `?token=<token>` per `CCMenuController#authenticate_api_client`) for Stack B, which they were never granted access to.
3. `Api::CCMenuController#stack` resolves `Stack.from_param!(params[:stack_id])` directly to Stack B, bypassing the `current_api_client.stack_id` restriction, and returns Stack B's CI/build XML status — data the token was never authorized to see.
