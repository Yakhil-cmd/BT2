### Title
Insolvent account whose debt legs are coarser than the collateral-backed quote is permanently unliquidatable and uncleanable — ([File: contracts/controller/src/positions/liquidation/math.rs])

### Summary
`liquidate` on an insolvent account trims each repayment leg down to whole base units of the debt token. When one base unit of every debt token is worth more than the collateral-backed quote `floor(C / (1 + base))`, every kept leg rounds to zero and is dropped, so `liquidate` always reverts with `InvalidPayments`. Because the backed quote depends only on collateral value — not on debt size — interest accrual never fixes this. While collateral stays above the fixed $5 dust cap, permissionless `clean_bad_debt` also reverts, so the bad debt is parked indefinitely and keeps accruing interest against suppliers.

### Finding Description
On an insolvent account (`snap.total_collateral < snap.total_debt`), `normalize_repayment_plan` sets `ideal_repayment_usd = curve_repayment_usd = floor(C / (1 + base))` [1](#0-0) . Any offered payment above the ideal is trimmed via `process_excess_payment` with `insolvent = true`, which rounds each kept leg down to whole debt-token units and drops legs whose kept amount rounds to zero [2](#0-1) . The docs confirm a plan left with no seizure reverts `InvalidPayments` (16) [3](#0-2) .

The harness test `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote` reproduces exactly this: $9 of collateral backs a quote of ~$8.57, while the debt token's unit is $10, so the estimate shows `max_payment_wad = 0`, all legs are refunded, and `liquidate` reverts [4](#0-3) .

Crucially the quote is collateral-backed only: debt growth does not raise it, so unlike the documented solvent whole-unit band (which accrual ends), this state has no self-healing path while `C / (1 + base)` stays below the smallest debt unit. The escape hatches are blocked too:

- `clean_bad_debt` requires `total_collateral ≤ 5 WAD` (`is_socializable_bad_debt`), and reverts `CannotCleanBadDebt` above it [5](#0-4) .
- `repay`/`withdraw` by the borrower are voluntary and won't happen.
- Only the owner-only `force_socialize_bad_debt` governance path can remove the account, which the scan rules treat as privileged recovery rather than a permissionless mitigation.

### Impact Explanation
A single unprivileged borrower can park an insolvent account that no liquidator can ever touch and no keeper can clean. The debt keeps accruing borrow interest, the corresponding supply claims keep growing at the supply index, and the deficit is eventually socialized across the debt market's suppliers via `apply_bad_debt_to_supply_index` — i.e., direct loss of supplier funds / protocol insolvency proportional to the parked debt, growing with time. This matches the Medium-severity complete-DoS class of the reference CVE mapped onto liquidation availability, with an insolvency consequence.

### Likelihood Explanation
Reachable by any borrower: supply collateral, borrow 2+ units of a listed debt market whose base unit value is high relative to collateral (low-decimal or high-price asset), then wait for — or trade into — a price move that puts `C/(1+base)` below one debt unit while `C > $5`. No privileged action, oracle dishonesty, or timing is required beyond ordinary market movement; the attacker can also self-select debt size so the gap is wide. Persistence is conditional on prices, but there is no in-protocol exit.

### Recommendation
In the insolvent trim, allow the single closest kept leg to retain one whole unit (ceil-round the last leg instead of dropping it) when the kept set would otherwise be empty but the offer covers at least one unit; alternatively, permit a partial liquidation that seizes collateral at zero effective bonus up to the backed quote, or route accounts whose smallest debt unit exceeds the backed quote directly into the `clean_bad_debt`/socialization path regardless of the $5 dust cap.

### Proof of Concept
Mirrors `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`:

1. Attacker supplies ~$25 of USDC collateral and borrows 2 units of a listed debt token `EXP` priced at $10 per base unit.
2. USDC price falls (or EXP rises) until `C = $9 < D`: account is insolvent with HF < 1.
3. `curve_repayment_usd = floor(9 / 1.05) ≈ $8.57 < $10`, so every offered amount trims to zero kept units; `liquidate` reverts `InvalidPayments` for any payment vector.
4. `clean_bad_debt(account_id)` reverts `CannotCleanBadDebt` because `C = $9 > $5`.
5. The account's debt accrues indefinitely; no permissionless path removes it.

/// $9 of collateral backs $8.57, less than one $10 EXP unit: the estimate
/// keeps no repayment and refunds the whole offer, and execution reverts.
#[test]
fn test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote() {
    let (mut t, account_id) = insolvent_book_with_a_ten_dollar_unit(usd(9) / 1_000);
    let exp = t.resolve_asset("EXP");
    let payments = vec![&t.env, (hub_asset(exp.clone()), 2)];
    let estimate =
        t.ctrl_client()
            .get_liquidation_estimate(&account_id, &payments, &SeizeMode::Transfer);
    assert_eq!(estimate.max_payment_wad, 0);
    assert!(estimate.seized_collaterals.is_empty());
    let refund = estimate.refunds.get(0).expect("EXP refund");
    assert_eq!((refund.asset, refund.amount), (exp, 2));

    let liquidator = t.get_or_create_user(LIQUIDATOR);
    t.resolve_market("EXP").token_admin.mint(&liquidator, &2);
    let result = map_try_ok_value(t.ctrl_client().try_liquidate(
        &liquidator,
        &account_id,
        &payments,
        &SeizeMode::Transfer,
    ));
    assert_contract_error(result, errors::INVALID_PAYMENTS);
    assert_eq!(t.token_balance_raw(LIQUIDATOR, "EXP"), 2);
    assert_eq!(t.borrow_balance_raw(ALICE, "EXP"), 2);
