### Title
Post-NFT-transfer authority desync: former owner retains spend rights via stale `Account.owner` — ([File: contracts/controller/src/account.rs])

### Summary
The bug class from CVE-2026-56721 — two different identifiers deciding authorization vs. the object acted on — maps onto XOXNO Lending's dual ownership records: the position-NFT owner (`storage::account_owner`, checked by `require_account_owner`) and the cached `Account.owner` field (checked by `require_owner_or_delegate`). After an account NFT is transferred, `Account.owner` still names the previous owner until `adopt_account` runs, so the seller retains full spend authority over an account they no longer own.

### Finding Description
Every fund-moving entrypoint (`withdraw`, `borrow`, `multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `flash_position`, `migrate_from_blend`) gates on `require_owner_or_delegate(env, account_id, caller, &account.owner)`, which reads the stored `Account.owner` field ( [1](#0-0) , [2](#0-1) ). A separate, correct notion of ownership exists in `require_account_owner`, which compares the caller against `storage::account_owner` (the current NFT holder) ( [3](#0-2) ). `Account.owner` is only set at account creation via `nft_mint_call` ( [4](#0-3) ). The test `test_adopt_account_prunes_old_owner_bookkeeping` shows transfer and adoption are two distinct, non-atomic steps: `nft_transfer(ALICE, BOB, account_id)` followed by `adopt_account(BOB, account_id, ...)` ( [5](#0-4) ). In that window, `require_owner_or_delegate` still admits ALICE because `caller == account.owner`, even though the NFT — the source of truth checked by `require_account_owner` — belongs to BOB. This is exactly the reported class: the auth check passes on one identity field while the economic object (NFT-backed account) belongs to another.

### Impact Explanation
The previous owner can call `withdraw(account_id, withdrawals, to: self)` or `borrow(account_id, borrows, to: self)` to drain all collateral and take protocol debt against an account they have already sold, stealing the buyer's funds and/or leaving the account insolvent. Theft of user funds qualifies under the stated acceptance criteria.

### Likelihood Explanation
Any listed NFT sale or OTC account transfer creates the window; the victim's purchase is only safe if `adopt_account` executes before the seller's next transaction, which the protocol does not enforce atomically (the harness itself performs them as separate calls). A malicious seller can front-run the buyer's `adopt_account` call in the same ledger sequence.

### Recommendation
Re-derive spend authority from the single source of truth: make `require_owner_or_delegate` resolve the current owner via `storage::account_owner(account_id)` (NFT owner) instead of the cached `Account.owner`, or sync `Account.owner` during NFT `transfer`/`adopt_account` and prune stale delegate entries keyed under the old owner in `is_owner_or_delegate` ( [6](#0-5) ).

### Proof of Concept
1. ALICE owns `account_id` with supplied USDC collateral; `Account.owner == ALICE`.
2. ALICE calls position-NFT `transfer(ALICE, BOB, account_id)` — e.g., as part of a paid sale. `storage::account_owner` now returns BOB; `Account.owner` still reads ALICE.
3. Before BOB calls `adopt_account`, ALICE calls `controller.withdraw(ALICE, account_id, [(usdc, 0 /* withdraw all */)], Some(ALICE))`.
4. `process_withdraw` calls `require_owner_or_delegate`, which returns early on `caller == account.owner` (ALICE), so the withdrawal succeeds and pays ALICE.
5. BOB's subsequent `adopt_account` adopts an emptied account; the pool paid out collateral belonging to the NFT buyer.

Caveat: I could not read the position-NFT `transfer`/`adopt_account` implementation in the remaining iterations to confirm whether `adopt_account` is permissionless or whether NFT transfer invokes a hook that syncs `Account.owner`. If transfer already rewrites `Account.owner` atomically, the window closes and this analog does not hold.

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

fn test_adopt_account_prunes_old_owner_bookkeeping() {
    let mut t = LendingTest::new().with_market(usdc_preset()).build();

    let account_id = t.create_account(ALICE);
    assert_eq!(t.resolve_account_id(ALICE), account_id);

    let attrs = t.get_account_attributes(ALICE);

    t.nft_transfer(ALICE, BOB, account_id);
    t.adopt_account(BOB, account_id, attrs.spoke_id, attrs.mode);

    // The new owner's bookkeeping resolves the transferred account.
    assert_eq!(t.resolve_account_id(BOB), account_id);
