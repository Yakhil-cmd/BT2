### Title
Webhook signature verification is bound to `repository.owner.login`, not to the repository/organization actually written to - allowing cross-organization forged webhook events - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App (and thus the HMAC secret) to validate a webhook against using only `repository.owner.login` (or `organization.login`) from the *unauthenticated* JSON body, while the code that determines which `Repository`/`Stack` the event actually acts on uses a different field, `repository.full_name`, from that same attacker-controlled body. Nothing ties these two together, so an attacker can forge a payload whose `repository.owner.login` names an organization with a weak/blank `webhook_secret` while its `repository.full_name` (and hence `Repository.from_github_repo_name`) points at a stack that lives under a completely different, properly-secured organization.

### Finding Description
`verify_signature` picks the app/secret purely from the payload: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever the selected organization has no `webhook_secret` configured — an explicitly supported, documented configuration state: [3](#0-2) [4](#0-3) 

Meanwhile every webhook handler derives the *acted-upon* repository from a different payload field, `repository.full_name`, via the shared `Handler#repository_name`/`#stacks` helpers: [5](#0-4) 

and `Repository.from_github_repo_name` splits that string on `/` to look up an arbitrary, unrelated `Repository` row: [6](#0-5) 

Multi-organization installs are an explicitly supported configuration (`config/secrets.development.shopify.yml`, `docs/setup.md` "Using Multiple Github Applications"): [7](#0-6) 

**Binding broken:** `organization authenticated (repository.owner.login → GitHubApp#webhook_secret)` ≠ `repository actually written to (repository.full_name → Repository.from_github_repo_name → Stack)`.

Before the attack: an org (`OrgOne`) is configured with no/blank `webhook_secret` (a supported, documented state) alongside a separately secured org (`OrgTwo`) that owns the real target stack. After the attack: an unauthenticated POST to `/webhooks` with `X-Github-Event: push` (or `status`), body `{"repository":{"owner":{"login":"OrgOne"},"full_name":"OrgTwo/target-repo"}, "ref":"refs/heads/main", "after":"<attacker-chosen sha>"}` passes `verify_signature` (secretless `OrgOne` accepts any/no signature) yet triggers `PushHandler#process` against `OrgTwo`'s stacks (`stack.sync_github(expected_head_sha: ...)`), or a `status` event forging arbitrary CI status (`Commit#create_status_from_github!`) for `OrgTwo`'s commits — both without ever knowing `OrgTwo`'s real webhook secret.

### Impact Explanation
This lets an unprivileged attacker who only needs to know (or guess) that *some* configured organization has an absent/weak webhook secret forge state-changing webhook events (sync triggers, commit statuses that feed into continuous-delivery gating and the merge queue, review-stack provisioning via `pull_request` events, etc.) against stacks belonging to a *different*, fully secured organization. Depending on which handler is abused (e.g., forged commit statuses feeding `Shipit.yml`'s `merge.required_statuses`/continuous delivery, or forged `pull_request` events driving review-stack provisioning), this can escalate to an unauthorized deploy/merge trigger — matching the "unauthorized deploy, rollback or merge" High/Critical impact bucket.

### Likelihood Explanation
Requires no credentials, no session, and no repository access — only knowledge that at least one configured GitHub organization on the instance has no `webhook_secret` set (a state the project's own example config treats as normal/default: "webhook_secret: # nil"). Multi-org configuration is an officially documented and supported deployment mode, so the precondition is realistic in any installation onboarding several organizations where not all of them have set a webhook secret.

### Recommendation
Bind signature verification to the same identity that is used to resolve the acted-upon resource: verify the payload against the `GitHubApp` corresponding to the repository/organization actually resolved from `repository.full_name` (or, better, require and cross-check that `repository.owner.login` matches the owner segment of `repository.full_name` before organization selection), and disallow accepting a webhook whose claimed owner differs from the owner encoded in the repository identifier subsequently used to look up `Stack`/`Repository` records. Consider also disallowing (or clearly documenting the risk of) unset `webhook_secret` in multi-organization deployments, since it silently disables authentication for that organization's endpoint while still being reachable to route events into any other organization's repositories.

### Proof of Concept
Preconditions: instance configured with two orgs, e.g. matching `test/dummy/config/secrets_double_github_app.yml` pattern — `OrgOne` (`webhook_secret: nil`) and `OrgTwo` (`webhook_secret: <strong-secret>`), each with stacks for their own repos.

```
POST /webhooks HTTP/1.1
X-Github-Event: push
Content-Type: application/json

{
  "repository": {
    "owner": { "login": "OrgOne" },
    "full_name": "OrgTwo/target-repo"
  },
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"
}
```
- `verify_signature` calls `Shipit.github(organization: "OrgOne")` → its `webhook_secret` is blank → `verify_webhook_signature` returns `true` unconditionally [3](#0-2) , regardless of `X-Hub-Signature` header (which can be omitted).
- `PushHandler#process` is then invoked with the parsed body; `stacks` resolves `Repository.from_github_repo_name("OrgTwo/target-repo")` [5](#0-4)  and triggers `stack.sync_github(expected_head_sha: "deadbeef...")` on `OrgTwo`'s stack [8](#0-7) , an org whose webhook secret the attacker never possessed.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
