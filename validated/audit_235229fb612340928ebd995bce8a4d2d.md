### Title
Third-party collateral top-ups keep an insolvent account straddled above the $5 dust gate, indefinitely stalling permissionless bad-debt cleanup - (File: contracts/controller/src/positions/supply.rs)

### Summary
The Routinator CVE is a "drip-feed" liveness attack: an unbounded remote party keeps an operation nominally alive with tiny increments so the completion threshold is never reached. The XOXNO Lending analog is the `clean_bad_debt` dust gate: permissionless socialization of an insolvent account requires `total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5 WAD). Because `supply` lets any third party add to a victim's **existing** supply positions, an attacker can keep drip-feeding small amounts of the victim's own collateral asset to hold `total_collateral` a hair above $5, so `is_socializable_bad_debt` never admits the account and bad debt is never written off through the public path.

### Finding Description
- `process_supply` → `require_third_party_existing_supply` only asserts that each paid `hub_asset` is already a key in the victim's `account.supply_positions`; it does not require ownership and does not cap the top-up. Any `caller` may pass the victim's `account_id` and grow that account's collateral. [1](#0-0) 
- `clean_bad_debt` (permissionless, `caller.require_auth()` only) computes `totals` and admits the account only when `is_socializable_bad_debt(total_debt, total_collateral)`, i.e. `debt > collateral` **and** `collateral <= BAD_DEBT_USD_THRESHOLD`. [2](#0-1) 
- The Certora boundary rules confirm the straddle explicitly: `BAD_DEBT_USD_THRESHOLD + 1` of collateral blocks the dust gate while the account stays insolvent — one unit above the cap is enough, and the gate is value-based, not count-based. [3](#0-2) 
- The only fallback is the owner-gated `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`), i.e. a Sensitive-tier governance delay, exactly mirroring the Routinator fix gap where a configurable escape existed but the default path could be stalled. [4](#0-3) 
- Meanwhile `accrue_chunk`/`global_sync` keep compounding `borrow_index`, so the stranded debt grows against the same supplier base while cleanup is denied. [5](#0-4) 

### Impact Explanation
Protocol insolvency persistence: an account with $5.01 of collateral and arbitrarily large debt cannot be cleaned via `clean_bad_debt`. The debt keeps accruing interest (widening the eventual supplier write-down at `apply_bad_debt_to_supply_index`), the account's debt legs keep occupying spoke borrow usage, and socialization is deferred until either governance executes `force_socialize_bad_debt` or liquidators consume the collateral — which the attacker can repeatedly re-top to re-straddle. This is temporary freezing of the protocol's bad-debt resolution path sustained by an unprivileged address with attacker-controlled small cost per refresh.

### Likelihood Explanation
Medium. Prerequisites: a victim account that already has a supply position in a cheap asset (always true while collateral > 0, otherwise the gate is already open). Cost per maintenance interval is ~$5 of a collateral token, which the attacker loses if the account is later liquidated or force-socialized — so it is a pure grief with real but bounded cost, feasible for any duration the attacker funds. The account remains partially liquidatable, which limits severity: the stall is on the *cleanup* path, not on liquidation itself.

### Recommendation
Make the dust gate robust to adversarial top-ups, e.g.:
- Exclude third-party-credited supply value added after the account became insolvent from `total_collateral` for the `clean_bad_debt` gate (e.g. snapshot collateral at first insolvency check, or tag supply legs with a "third-party top-up" flag and count only owner-supplied value).
- Alternatively, restrict `process_supply` to owner/delegate for accounts whose health factor is below 1, so collateral cannot be grown by outsiders precisely when the account is underwater.
- A cheaper mitigation: allow permissionless cleanup up to a higher cap when `debt >> collateral` (e.g. admit when `debt - collateral > K`), so a $5 straddle cannot shield a large write-off.

### Proof of Concept
1. Victim account holds existing supply leg in asset X and borrows; price drop makes `total_debt > total_collateral` with `total_collateral` between $0 and $5 → `clean_bad_debt` succeeds (baseline).
2. Instead, victim's collateral sits at $5.01+ (or attacker calls `supply(victim_account_id, spoke, [(X, ε)])` pushing it above $5 — allowed because X is already a supply position of the victim).
3. Any caller invoking `clean_bad_debt(victim_account_id)` reverts with `CannotCleanBadDebt` (controller #114) while `D > C` holds — confirmed by `bad_debt_straddle_blocks_dust_gate` and `test_force_socialize_bad_debt_above_dust_threshold` (harness: `try_clean_bad_debt_by_id` → `CANNOT_CLEAN_BAD_DEBT` at collateral > $5, insolvent). [6](#0-5) 
4. If a liquidation pushes collateral back below $5, the attacker re-tops ε to re-straddle; debt accrues throughout via `global_sync` chunks.

Note: residual uncertainty — whether maintainers consider the owner `force_socialize_bad_debt` path and continued partial liquidations sufficient mitigation. If so, this is a documented-gate-limitation rather than a vulnerability, and the finding should be downgraded/dismissed.

pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
