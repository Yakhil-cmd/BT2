### Title
Uncaught exception in `definition template` authentifier evaluation crashes the node - (File: definition.js)

### Summary
`definition.js`'s `validateAuthentifiers()` throws a synchronous JS `Error` inside an *asynchronous* `conn.query()` callback when a referenced `definition template` unit cannot be resolved to exactly one row. Because this throw happens inside a database-driver callback rather than inside the calling stack that `validation.js` wraps with error-returning callbacks (`ifUnitError`/`ifJointError`/etc.), it is not converted into a normal validation error. It propagates as an uncaught exception, which `network.js` explicitly re-throws to crash the process (`process.on('uncaughtException', ... ) { ...; throw err; }`). This mirrors the next-auth `callbackUrl` bug class: malformed/edge-case attacker-controlled input triggers an unhandled exception in a code path that is supposed to gracefully reject invalid input, causing the handling process to fail/crash instead of just rejecting the request.

### Finding Description
`validateAuthentifiers()` evaluates an address definition tree against the authentifiers supplied in a posted unit. One of the supported definition operators is `definition template`, which looks up a previously-posted `definition_template` message by unit hash and inlines it with supplied parameters: [1](#0-0) 

```
case 'definition template':
    var unit = args[0];
    var params = args[1];
    conn.query(
        "SELECT payload FROM messages JOIN units USING(unit) ... WHERE unit=? AND app='definition_template' ...",
        [unit, objValidationState.last_ball_mci],
        function(rows){
            if (rows.length !== 1)
                throw Error("not 1 template");
            ...
        }
    );
    break;
```

If `rows.length !== 1` (e.g., the referenced `unit` doesn't exist, isn't yet stable, or isn't a `definition_template` message — trivially achievable by pointing to an arbitrary/fake unit hash), the code `throw`s inside the SQL callback instead of invoking `cb2` with an error, which is how every other branch in this function reports failure (e.g., `cb2(false)`, or the sibling `case 'address'` handler's `try/catch` around a similarly risky operation at lines 784-798).

Contrast this with the analogous, correctly-guarded code path in `validateDefinition()` (used for pre-validation elsewhere), which returns a normal callback error instead of throwing: [2](#0-1) 

```
if (rows.length !== 1)
    return cb("template not found or too many");
```

The `validateAuthentifiers` path lacks this safety net. Because `evaluate()`'s recursion here is driven by `conn.query`'s async callback, the thrown error is not caught by any synchronous `try/catch` in the call chain (`validateAuthor` → `validateAuthentifiers` → `evaluate`, in `validation.js`/`definition.js`), and bubbles up as a Node.js `uncaughtException`.

`network.js` installs a global handler for exactly this situation, and deliberately re-throws to crash the process to avoid leaving it in an inconsistent state: [3](#0-2) 

```
process.on('uncaughtException', (err) => {
	console.log('Uncaught exception:', err);
	...
	throw err; // crash the process to avoid ending up in an inconsistent state
});
```

### Impact Explanation
Any address whose definition (or a definition referenced transitively via an `address`/`definition template` operator, including asset-condition or private-payment authentifier checks that also traverse `evaluate()`) uses `['definition template', [some_unit, params]]` pointing at a nonexistent, not-yet-stable, or otherwise non-matching unit will cause **every full node that validates a unit exercising that definition path to crash** with an uncaught exception. Since address definitions are entirely user-controlled (a normal unprivileged unit poster defines their own address, or references such an address via an `address` sub-definition, in an ordinary payment/message unit), this gives any single unsophisticated user the ability to crash full nodes that attempt to validate the unit — a network-wide denial of service that prevents new units from being confirmed until node operators patch/restart, which matches the required "network unable to confirm new units" impact bar.

### Likelihood Explanation
High likelihood of exploitability: constructing an address whose definition is `['definition template', ['<44-char-base64-of-a-nonexistent-or-mismatched-unit>', {}]]` is straightforward and requires no special privileges — it's a standard address-definition feature. Triggering the vulnerable code path only requires posting one ordinary unit authored by (or referencing via `address`) such an address. This is reachable by any unprivileged unit poster.

### Recommendation
In `definition.js`'s `validateAuthentifiers()`, replace the `throw Error("not 1 template")` with a graceful failure through the callback chain (`cb2(false)` or invoke the fatal-error mechanism used elsewhere in this function), mirroring the safe handling already present in `validateDefinition()` (`return cb("template not found or too many")`). Additionally audit all other `throw` statements inside `conn.query` callbacks within `definition.js`/`validation.js` evaluation paths for the same class of issue, since any of them that are reachable from attacker-controlled unit content will similarly crash the process instead of rejecting the invalid unit.

### Proof of Concept
1. Attacker creates address `T`, with an initial/changed definition of `['definition template', ['AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=', {}]]` where the referenced unit hash does not correspond to any stable `definition_template` message (e.g., a random 44-byte base64 string).
2. Attacker posts (or has any other unit reference, via an `['address', 'T']` sub-condition in another address's definition) a unit authored by `T`, with any authentifier value for the relevant path so that `evaluate()` descends into `T`'s definition.
3. During validation, `evaluate()` reaches `case 'definition template'`, runs the `conn.query`, finds 0 matching rows, and executes `throw Error("not 1 template")` inside the async callback.
4. The exception is uncaught by any surrounding logic in `validateAuthor`/`validateAuthentifiers`/`validation.validate`, propagates to Node's event loop, fires `process.on('uncaughtException')` in `network.js`, and the process re-throws and terminates — crashing every full node that attempts to validate this unit.
