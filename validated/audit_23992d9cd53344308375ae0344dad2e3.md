### Title
Cross-tenant `Team` membership mutation via unauthenticated webhook when any configured GitHub org has no `webhook_secret` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/membership_handler.rb`, `lib/shipit/github_app.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to check against purely from the attacker-supplied `organization.login` field, and `GitHubApp#verify_webhook_signature` unconditionally returns `true` if that selected app has no `webhook_secret` configured. `MembershipHandler#find_or_create_team!` then looks up (or mutates) a `Team` solely by the attacker-supplied `github_id`, never checking that the team's real `organization` matches the org that was actually verified, letting a forged, "verified" request for one org add/remove members on a `Team` belonging to a completely different org.

### Finding Description
The claimed binding is: `verified_org` (the organization whose secret validated the HMAC in `verify_signature`) `== team.organization` (the organization actually owning the `Team` record mutated by `MembershipHandler#process`).

Trace:
- `repository_owner` returns `params.dig('organization', 'login')` verbatim for `membership` events (no `repository` key present). [1](#0-0) 
- `verify_signature` resolves the app purely from that attacker string and checks the signature against only that app's secret. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved app's `webhook_secret` is blank/unset - no signature is required at all in that case. [3](#0-2) 
- `Shipit.github(organization:)` looks the config up case-insensitively by the attacker-supplied string; any org key configured in `secrets.github` can be targeted, and an unknown one raises `GithubOrganizationUnknown` (handled, returns 422). [4](#0-3) 
- `MembershipHandler#find_or_create_team!` looks a `Team` up **only by `github_id`** (an attacker-chosen integer in the payload). The `do |team| ... team.organization = params.organization.login end` block only runs when a **new** record is created - if a `Team` with that `github_id` already exists (belonging to a different, legitimate org), it is fetched unchanged and then mutated (`team.add_member(member)` / `team.members.delete(member)`) with no check that `team.organization == repository_owner`. [5](#0-4) 

Exploit flow (multi-org Shipit deployment where org `OrgX` is configured in `secrets.github` but its `webhook_secret` was left blank, while org `OrgA` has a real, secret-protected `Team`):
1. Attacker learns/guesses the `github_id` of an existing `Team` owned by `OrgA` (visible in Shipit's own UI/API, GitHub team pages, or brute-forced sequential IDs).
2. Attacker POSTs to `/webhooks` with `X-Github-Event: membership`, no valid `X-Hub-Signature`, and body `{"action":"added","team":{"id":<OrgA's github_id>,...},"organization":{"login":"OrgX"},"member":{"login":"attacker-login"}}`.
3. `repository_owner` returns `"OrgX"`; `Shipit.github(organization: "OrgX")` resolves `OrgX`'s app; `verify_webhook_signature` returns `true` because `OrgX` has no secret configured - the request is accepted with `status 200`, no valid signature required.
4. `MembershipHandler` finds `OrgA`'s existing `Team` by `github_id` and executes `team.add_member(User.find_or_create_by_login!("attacker-login"))`, adding the attacker's GitHub login as a member of `OrgA`'s Shipit `Team` - a tenant they never authenticated as.

Why existing guards fail: `verify_signature` only proves the request matches *some* configured org's secret (or that org has none), it never asserts that org equals the org that owns the `Team`/`Membership` being written; `drop_unhandled_event` and `ExplicitParameters` schema validation only check payload shape, not organizational ownership; there is no `Repository`/`Stack` model validation involved because `Team`/`Membership` records carry no such per-request tenant check.

### Impact Explanation
An unauthenticated attacker can add or remove arbitrary GitHub users from any `Team` record already present in Shipit's database, across organizational boundaries, as long as any one configured org in a multi-org deployment has an empty/missing `webhook_secret`. If `Shipit::Team`/`Membership` feeds into `Shipit.github_teams`/authorization checks elsewhere in the app, this could escalate to unauthorized access grants for a different organization's resources - matching "Critical: cross-tenant Team/Membership mutation" / "High: escalation into `Shipit.github_teams` authorization" depending on how team membership is consumed downstream (not independently re-verified in this pass). This is repeatable per request and scales to any `Team` row whose `github_id` the attacker can determine.

### Likelihood Explanation
Requires: (a) a multi-org Shipit deployment (`secrets.yml`'s `github:` keyed by org), (b) at least one configured org whose `webhook_secret` is blank/unset (a realistic but non-default misconfiguration - `verify_webhook_signature`'s "no secret means always verified" fallback exists for the single-app/legacy config, but is silently reused for every configured org in multi-org mode), and (c) knowledge of the target `Team`'s numeric `github_id` for the org actually being attacked. Given those preconditions the attack is trivial (single unauthenticated HTTP POST, no signature needed) and fully repeatable.

### Recommendation
In `MembershipHandler#find_or_create_team!`, scope the lookup/creation by both `github_id` **and** `organization: params.organization.login`, and additionally assert `team.organization == repository_owner`/the verified org before performing any mutation, raising/dropping the event otherwise. Separately, `GitHubApp#verify_webhook_signature`'s "return true unless webhook_secret" fallback should not silently apply per-org in multi-org configurations - require every configured org to have a `webhook_secret` (fail closed) when `Shipit.github_organizations` has more than the legacy single entry.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "membership webhook naming an org with no webhook_secret cannot mutate another org's team" do
  # OrgA has a real webhook_secret and owns team github_id=123 with existing member "alice"
  # OrgX is configured in secrets.github with webhook_secret: nil (blank)
  team = shipit_teams(:org_a_team) # github_id: 123, organization: "OrgA"
  refute_includes team.members.map(&:login), "mallory"

  payload = {
    action: 'added',
    team: { id: team.github_id, name: team.name, slug: team.slug, url: team.api_url },
    organization: { login: 'OrgX' }, # attacker-chosen, unrelated org
    member: { login: 'mallory' }
  }.to_json

  post shipit.webhooks_path, params: payload, headers: {
    'X-Github-Event' => 'membership',
    'CONTENT_TYPE' => 'application/json'
    # deliberately no X-Hub-Signature
  }

  assert_response :ok
  team.reload
  # Assert the binding: verified_org ("OrgX") must equal team.organization ("OrgA") for this mutation to be legitimate — it does not.
  refute_equal 'OrgX', team.organization
  refute_includes team.members.map(&:login), "mallory" # currently FAILS: mallory is added
end
```
This demonstrates that a payload naming `OrgX` (the org whose secret verified the request) is accepted and mutates `OrgA`'s team, violating the required `verified_org == team.organization` equality.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
