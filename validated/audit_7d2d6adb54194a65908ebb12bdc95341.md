### Title

Overflow in RAY-scaled debt valuation permanently freezes a market - (File: `common/src/rates/simulate.rs`)

### Summary

A market with sufficiently large scaled debt can reach a state where `borrowed * borrow_index` no longer fits in `i128`. The first operation in every accrual step recomputes this value, so once the bound is crossed, every subsequent market mutation reverts with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description

`Controller::update_indexes` is permissionless and requires only caller authorization before forwarding a caller-selected `Vec<HubAssetKey>` to the pool. [3](#0-2) [4](#0-3) 

The pool handler loads each market and calls `interest::global_sync`. [5](#0-4) [6](#0-5) 

`global_sync` invokes `accrue_step`, whose first valuation is `scaled_to_original(borrowed, borrow_index)`. [7](#0-6) [1](#0-0) 

`scaled_to_original` calls `Ray::mul`, which uses checked `mul_div_half_up` arithmetic and panics with `MathOverflow` when the quotient cannot fit in `i128`. [2](#0-1) [8](#0-7) [9](#0-8) 

The borrow-index ceiling does not prevent this condition: `update_borrow_index` only clamps the newly calculated index, while the oversized `borrowed * old_borrow_index` product is computed before that call. [10](#0-9) [11](#0-10) 

This is not limited to the manual index endpoint: every pool leg loaded through `load_leg` calls `synced_market`, and `synced_market` always runs `global_sync` before the requested operation. [12](#0-11) 

Consequently, `supply`, `borrow`, `withdraw`, `repay`, liquidation withdrawal/repayment legs, flash paths, strategy debt creation, bad-debt seizure, revenue claims, and recapitalization cannot execute for the affected `(hub_id, asset)` market. [13](#0-12) [14](#0-13) 

### Impact Explanation

Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot process positions touching the market, and governance cannot even update that market's rate model because `upgrade_liquidity_pool_params` accrues first. [15](#0-14) 

The failure is persistent rather than a one-transaction revert because the stored scaled debt and stored borrow index remain above the value-representation bound. [12](#0-11) [1](#0-0) 

The result is permanent freezing of the market's user funds absent a code upgrade or an added recovery path. [14](#0-13) [12](#0-11) 

### Likelihood Explanation

Triggering the condition requires an unusually large market and sustained high utilization; it is not reachable merely by submitting malformed input. [16](#0-15) 

The repository's long-horizon reproduction uses an 18-decimal market, one billion whole supplied tokens, and approximately 98% utilization to drive the next accrual into `MathOverflow`. [17](#0-16) [18](#0-17) 

Once that state exists, a single unprivileged address can trigger or confirm the failure through `Controller::update_indexes(caller, assets)`, where `assets` contains the affected `HubAssetKey`. [3](#0-2) [4](#0-3) 

### Recommendation

Enforce a market-level worst-case scaled-value bound when minting supply or debt: require `scaled * MAX_INDEX / RAY <= i128::MAX`, using `MAX_BORROW_INDEX_RAY` for debt and `MAX_SUPPLY_INDEX_RAY` for supply. [10](#0-9) [19](#0-18) 

Apply the same bound to protocol-revenue share minting, since revenue shares are included in total `supplied` before later accrual steps. [20](#0-19) [21](#0-20) 

Additionally, calculate utilization in a widened representation or with an explicit saturation policy before any `i128` conversion, so a large but otherwise valid market cannot turn accrual into an unconditional panic. [1](#0-0) [22](#0-21) 

A recovery path should also be defined for markets that already crossed the bound, such as a migration that safely reduces scaled debt or clamps/recalculates indexes without first unscale-multiplying the oversized value. [15](#0-14) [23](#0-22) 

### Proof of Concept

1. Configure an 18-decimal borrowable market with caps high enough to admit approximately `1e9` whole tokens, plus a separate collateral market capable of supporting a borrow near 98% of the target market's liquidity. [17](#0-16) 

2. Supply `1_000_000_000 * 10^18` base units to the target market and borrow approximately `0.98e9 * 10^18` base units through a sufficiently collateralized account. [18](#0-17) 

3. Allow interest to accrue while utilization remains in the curve's high-rate region; call `Controller::update_indexes(caller, vec![HubAssetKey { hub_id, asset }])` to advance the stored indexes. [3](#0-2) [6](#0-5) 

4. Once `borrowed * borrow_index` exceeds `i128::MAX`, the call fails in `scaled_to_original` before the borrow-index ceiling can protect the operation. [11](#0-10) [9](#0-8) 

5. Subsequent `withdraw`, `repay`, `supply`, `borrow`, liquidation, and `update_indexes` calls fail identically because their market legs all execute `global_sync` first. [12](#0-11) [24](#0-23)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// Runs a multi-entry batch: renews the instance, applies `leg` per entry, and emits one
/// market state batch event (none for an empty batch).
///
/// Each leg returns a result `R` plus a [`MarketStateSnapshot`] for the event batch.
pub(crate) fn run_batch<E, R>(
    env: &Env,
    entries: Vec<E>,
    mut leg: impl FnMut(&Env, &E) -> (R, MarketStateSnapshot),
) -> Vec<R>
where
    E: IntoVal<Env, Val> + TryFromVal<Env, Val> + Clone,
    R: IntoVal<Env, Val> + TryFromVal<Env, Val> + Clone,
{
    renew_instance(env);

    let mut results = Vec::new(env);
    let mut snapshots = Vec::new(env);
    for entry in entries.iter() {
        let (result, snapshot) = leg(env, &entry);
        results.push_back(result);
        snapshots.push_back(snapshot);
    }

    events::emit_market_state_batch(env, snapshots);
    results
