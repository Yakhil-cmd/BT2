### Title
Borrower can engineer an un-liquidatable account state where every `liquidate` offer reverts — (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
The original bug class is "inconsistent state accepted at write time, then a later permissionless entrypoint reverts unconditionally, causing a DoS until external intervention." In `MetadataRenderer.addProperties`, mismatched `properties`/`items` lengths were accepted, and `onMinted` later reverted with "Division or modulo by 0" on every mint. The XOXNO analog is in liquidation planning: `whole_unit_repayment` deliberately leaves the curve quote unchanged inside a gap band, and any offer that backs less than one whole collateral unit seizes nothing and reverts with `InvalidPayments`. A borrower can position their account inside that band, after which *every* `liquidate` call reverts until interest accrual or a price move exits the state.

### Finding Description
For a solvent account (`C ≥ D`) whose **only** supply position is in an asset with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` (below 3 decimals, i.e. whole-unit collateral), `normalize_repayment_plan` routes the quote through `whole_unit_repayment` [1](#0-0) .

`whole_unit_repayment` computes:

- `unit_at_bonus = floor(U / one_plus_b)` and `raised = ceil((U + margin) / one_plus_b)` [2](#0-1) 
- Rule 1 (full close) applies only when `unit_at_bonus >= D + R`, returning `snap.total_debt` [3](#0-2) 
- Rule 2 (raise to one unit) applies only when `raised < D`; otherwise the quote is returned unchanged [4](#0-3) 

This leaves a live gap: `unit_at_bonus − R < D ≤ raised`. Inside it, neither rule fires, so `ideal` stays at the curve quote — which by the enclosing `if quote_usd * one_plus_b < unit_with_margin` guard backs **less than one whole unit** [5](#0-4) . A sub-3-decimal leg seizes whole units only, so a seizure that rounds below one unit is dropped, and a plan left with no seizure reverts with `InvalidPayments` [6](#0-5) . The protocol's own documentation confirms the outcome: "if the curve quote backs less than one unit, every offer reverts until accrual or a price move ends that state" [7](#0-6) .

The entry/exit asymmetry is the core issue: the code can *enter* this band (borrow amount chosen so `D` lands between `unit_at_bonus − R` and `raised`), but no unprivileged call can settle a liquidation while inside it.

### Impact Explanation
While the account sits in the band, `liquidate` and any flow that internally executes a liquidation revert for every possible `debt_payments` input — this is a temporary freezing of funds and a contract-unable-to-operate condition scoped to the account. Because HF is already below 1, the debt keeps accruing against fixed collateral; if prices drift further the account can become bad debt that still cannot be closed out through the normal liquidation path while the band persists. The mirror of the original finding (auctions blocked until a new governance proposal) is that here liquidation — the protocol's solvency backstop — is blocked until external state (accrual or oracle price) changes, with no transaction a liquidator can craft to escape it.

### Likelihood Explanation
Reachable by a single unprivileged address with no privileged input:

1. Call `supply` with a single collateral position in a listed asset with `asset_decimals < 3`.
2. Call `borrow` sizing `D` into the band `floor(U/(1+b)) − R < D ≤ ceil((U + U·1e−6 + 1)/(1+b))`.
3. Manipulate HF below 1 via a price move (or wait for accrual), then every `liquidate(liquidator, account_id, debt_payments, seize_mode)` reverts regardless of `debt_payments`.

The band exists whenever `raised ≥ D > unit_at_bonus − R`, i.e. whenever one whole unit of the collateral is worth roughly the debt. Since `margin = max(U/1_000_000, 1)` and `R` is the summed one-unit value of debt legs, the gap width is on the order of `R + margin` — small but non-zero and deliberately targetable. Unlike the original report (which needed a governance misinput), here the borrower chooses the poisoned state directly. A mitigating factor is that the state self-resolves via accrual or price movement, matching the "temporary freezing" impact class rather than a permanent one. Note this behavior is described in the protocol's own liquidation runbook, which a judge may treat as a documented design consequence — but no documentation states the revert-by-all-offers outcome is *intended*, only that it occurs.

### Recommendation
Close the gap in `whole_unit_repayment` so no reachable state makes every offer revert. Two options:

- When `unit_repayment >= snap.total_debt` but `unit_at_bonus < full_close_ceiling`, promote the quote to `snap.total_debt` (full close) rather than returning `quote_usd`. Selling the single unit at full debt is always executable and keeps HF non-decreasing.
- Alternatively, when the unchanged quote backs less than one whole unit and `raised >= D`, return `snap.total_debt` directly instead of the curve quote, so the plan always resolves to either the one-unit seizure or a full close.

Add a regression test: single sub-3-decimal collateral leg, `D` inside `(unit_at_bonus − R, raised]`, HF < 1 — assert `liquidate` succeeds with a full-close rather than reverting with `InvalidPayments`.

// Setup: account with exactly ONE supply position in an asset where
// feed.asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS (e.g. 0 decimals),
// holding k whole units, and one debt position.

// In whole_unit_repayment:
//   - rule 1 skipped: unit_at_bonus < D + R          (math.rs:278)
//   - rule 2 skipped: unit_repayment (raised) >= D    (math.rs:287)
//   - returns curve quote that backs < 1 unit         (math.rs:266 guard)
//
// Seizure rounds to zero whole units -> leg dropped ->
// plan.validate / InvalidPayments revert.
let payments = vec![&env, (debt_hub_asset.clone(), offer)];

**File:** skills/xoxno-lending/math.md (L399-411)
```markdown
Whole-unit quote for a collateral leg below 3 decimals. It applies only when the account is solvent (`C ≥ D`), the curve quote `ideal` is below `D`, the leg is the account's only supply position, and it holds at least one whole unit (one base unit at the asset's decimals). Let `U` be the WAD USD value of one whole unit. The first matching rule applies:

```text
R             = Σ over debt legs of the WAD USD value of one base unit of that debt token
unit_at_bonus = floor(U × WAD / one_plus_b)
margin        = max(floor(U / 1_000_000), 1)                           // raw WAD
raised        = ceil((U + margin) × WAD / one_plus_b)
if unit_at_bonus ≥ D + R:                                      ideal = D       // full close; the leg rounds up to one unit
elif half_up(ideal × one_plus_b / WAD) < U + margin and raised < D: ideal = raised  // seize one unit, refund the margin
else:                                                          ideal unchanged
```

The raised seizure takes one unit and refunds the unseized margin, rounded down to whole debt-token units. The raised quote is a ceiling: a smaller offer is not raised, an offer that backs less than one unit seizes nothing and reverts with `InvalidPayments`, and an offer between `U / one_plus_b` and `raised` still takes one unit. The raised quote is not promoted to full debt (`D − raised` can be below 5 WAD). The HF-preserving cap keeps `one_plus_b ≤ C / D`, so a one-unit sale does not lower `C / D`, and such an account stays liquidatable below `HF = 1`. The exception is `unit_at_bonus − R < D ≤ raised`: no rule changes the quote, and if the curve quote backs less than one unit, every offer reverts until accrual or a price move ends that state.
```
