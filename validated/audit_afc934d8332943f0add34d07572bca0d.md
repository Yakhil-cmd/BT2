### Title
Duplicate crediting of the same L1 lockup output across multiple `register-for-bond` calls due to per-call-only outpoint tracking - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`verify-l1-lockups` / `validate-l1-lockup` in `pox-5.clar` only guard against duplicate outpoints *within a single call* by folding over a `seen-outpoints` accumulator that is initialized empty on every invocation and is never persisted to contract state.

### Finding Description
`verify-l1-lockups` builds a fresh `seen-outpoints: (list)` each time it is invoked, and `validate-l1-lockup` asserts `(is-none (index-of? seen-outpoints outpoint))` only against that ephemeral, call-scoped list [1](#0-0) . There is no persisted map (e.g. `credited-outpoints` or similar) recording which Bitcoin `(txid, output-index)` pairs have already been used to credit sats toward a staker's bond in a prior transaction/registration. Because the same physical L1 lockup transaction remains minable/provable via Merkle proof indefinitely (the on-chain Bitcoin header and tx don't disappear), a staker could resubmit the same lockup proof set across separate `register-for-bond`-style calls (e.g., for a new bond index, a rollover, or a repeated registration) and have `verify-l1-lockups` return the same `sum` of sats again, since nothing prevents re-validating an already-consumed outpoint in a later transaction.

### Impact Explanation
If the same sats amount can be credited more than once toward `staker-shares-staked-for-cycle` / `signer-shares-staked-for-cycle` / `total-shares-staked-for-cycle` (as updated in `add-staker-to-bond-for-cycle` [2](#0-1) ), this double-counts a stacking commitment that was never actually re-locked on Bitcoin, inflating a staker's/signer's stacked-shares-based reward weight without new underlying collateral. This matches the double-counting-a-commitment class described in the rules (Critical/High impact) since reward share and signer weight would exceed the actual sats locked.

### Likelihood Explanation
Requires only an unprivileged staker to call the bond-registration path twice with proofs referencing the same L1 outputs; no admin or miner collusion needed, since the same Merkle/txid data remains verifiable at any later time. Whether this is actually reachable depends on additional caller-side checks (e.g., whether `register-for-bond` also checks a bond-level or global “already registered this bond-index” state) that were not fully traced in the code I could review before this session ended.

### Recommendation
Persist consumed outpoints in a durable map (e.g. `map-set used-l1-outpoints { txid, output-index } true`) checked and set during `validate-l1-lockup`, independent of any single call's fold accumulator, so that a given L1 lockup output can only ever be credited once across the contract's lifetime.

### Proof of Concept
Not fully constructible from static review alone — I could not confirm within the available context whether the caller of `verify-l1-lockups` (the `register-for-bond` public function, not shown in the excerpts I was able to retrieve) applies an additional global replay guard before calling this helper. This is a gap in my verification: I was unable to inspect the full body of `register-for-bond` and its interaction with bond-index state to confirm whether resubmission of the same lockup proofs is actually reachable end-to-end, or whether it's blocked by an "already registered" bond check elsewhere. Given this uncertainty, I cannot assert with full confidence that this is exploitable as described.

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
