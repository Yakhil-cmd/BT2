### Title
`Condition.from_dict` silently defaults missing `field`/`operator`/`pattern` keys, letting a malformed explicit condition permanently disable a `block` rule while a semantically-equivalent legacy `pattern` rule always works - (File: `plugins/hookify/core/config_loader.py`)

### Summary
`Condition.from_dict` in `plugins/hookify/core/config_loader.py` builds a `Condition` from an attacker-influenced frontmatter dict without validating that `field`, `operator`, or `pattern` are actually present, silently substituting `''`/`'regex_match'` defaults instead. Because `rule_engine.RuleEngine._rule_matches` requires ALL of a rule's `conditions` to match (AND semantics) and `_extract_field` returns `None` for an unrecognized/empty field, a single malformed or mistyped condition entry in the "explicit conditions" form permanently and silently neutralizes an entire `block` rule, whereas the "legacy `pattern`" form in `Rule.from_dict` deterministically infers the correct field from `event` and cannot fail this way.

### Finding Description
`Rule.from_dict` (`plugins/hookify/core/config_loader.py:44-84`) supports two rule authoring styles:

- Legacy `pattern:` style — the field to check is deterministically inferred from `event` (`command` for bash, `new_text` for file, `content` otherwise) at `config_loader.py:56-73`. This path cannot produce an invalid/empty `field`.
- Explicit `conditions:` style — each list entry is passed to `Condition.from_dict` at `config_loader.py:22-29`:
```python
@classmethod
def from_dict(cls, data: Dict[str, Any]) -> 'Condition':
    return cls(
        field=data.get('field', ''),
        operator=data.get('operator', 'regex_match'),
        pattern=data.get('pattern', '')
    )
```
There is no validation that `field` is non-empty or recognized, and no error raised if a key is missing.

At enforcement time, `RuleEngine._rule_matches` (`plugins/hookify/core/rule_engine.py:96-125`) requires every condition to match:
```python
for condition in rule.conditions:
    if not self._check_condition(condition, tool_name, tool_input, input_data):
        return False
```
`_check_condition` calls `_extract_field(condition.field, ...)` (`rule_engine.py:144-160, 182-254`), which returns `None` for an empty/unrecognized `field` (it falls through all the `if field in tool_input` / tool-specific checks and reaches the final `return None`). A `None` field value makes `_check_condition` return `False` unconditionally, which per the AND logic in `_rule_matches` makes the *entire rule* never match — including any other, correctly specified, conditions in the same rule.

Because `load_rule_file`/`load_rules` (`config_loader.py:198-274`) never surface this as an error — the file parses "successfully," the rule loads, `enabled: true` is honored, and no warning is printed — a `block` rule built with the explicit `conditions:` form can be rendered permanently inert by nothing more than one condition entry that omits (or subtly mis-keys) `field:`. A semantically equivalent rule expressed via the legacy `pattern:` field could never suffer this failure mode, breaking the invariant that legacy and explicit forms provide equivalent security guarantees.

Given the attacker model in scope (repo-shipped rule file content or content that influences `/hookify` generation, per `plugins/hookify/commands/hookify.md`), an attacker can introduce (via a PR, a shared `.claude/hookify.*.local.md` file, or content that shapes what `/hookify` writes) a `block` rule that visually appears to enforce a security control (e.g. blocking `rm -rf`, blocking secret-containing edits, or requiring tests before stop) but whose explicit-conditions form has one entry with an incorrect/missing `field`, so the rule silently never fires for any user loading that rule file, while looking legitimate to a reviewer skimming the frontmatter.

### Impact Explanation
This is a Security-control bypass that silently disables a blocking rule: any `action: block` rule (e.g. "block dangerous rm", "block secret file writes", "require tests before stop" from the plugin's own examples in `plugins/hookify/README.md:189-208`) authored or shipped using the explicit `conditions:` form can be made permanently non-functional by a single subtly malformed condition, with no error, warning, or indication to the user that protection is disabled. Because hookify rules are the mechanism used to enforce guardrails on `Bash`/`Edit`/`Write`/`Stop` tool use, this directly routes around the intended blocking/review boundary.

### Likelihood Explanation
This requires only that an attacker can get a rule file into `.claude/hookify.*.local.md` (or influence `/hookify` output) with `conditions:` entries — no privilege beyond ordinary repository content contribution is needed. The custom hand-rolled YAML-like parser in `extract_frontmatter` (`config_loader.py:87-195`) is also fragile to indentation variance, making it plausible for such a malformed condition to be introduced accidentally or to be disguised as a normal-looking rule, increasing feasibility and repeatability (deterministic — same input always yields the same silently-broken rule).

### Recommendation
- In `Condition.from_dict`, require `field`, `operator`, and `pattern` to be explicitly present and validate `field` against a known allow-list (`command`, `file_path`, `new_text`/`new_string`, `old_text`/`old_string`, `content`, `reason`, `transcript`, `user_prompt`); raise/log a hard error (and refuse to load the rule, or force-disable it with an explicit warning) instead of silently defaulting to `''`/`'regex_match'`.
- In `Rule.from_dict`/`load_rule_file`, reject (or at minimum loudly warn and treat as disabled) any rule where a condition failed validation, especially for `action: block` rules, rather than loading a rule that can never match.
- Add a self-check/test that asserts legacy `pattern:`-based rules and their explicit `conditions:` equivalents produce identical match behavior for a representative corpus of well-formed and malformed inputs.

### Proof of Concept
Unit test to add to the hookify test suite (e.g. under a `plugins/hookify` test directory), demonstrating the differential:

```python
from hookify.core.config_loader import Rule
from hookify.core.rule_engine import RuleEngine

def test_legacy_pattern_blocks_dangerous_rm():
    frontmatter = {
        "name": "block-rm",
        "enabled": True,
        "event": "bash",
        "pattern": r"rm\s+-rf",
        "action": "block",
    }
    rule = Rule.from_dict(frontmatter, "blocked")
    engine = RuleEngine()
    result = engine.evaluate_rules([rule], {
        "hook_event_name": "PreToolUse",
        "tool_name": "Bash",
        "tool_input": {"command": "rm -rf /tmp/x"},
    })
    assert result.get("hookSpecificOutput", {}).get("permissionDecision") == "deny"


def test_explicit_conditions_with_missing_field_silently_disables_block():
    frontmatter = {
        "name": "block-rm-explicit",
        "enabled": True,
        "event": "bash",
        "action": "block",
        # Missing 'field' key on the condition entry (attacker/malformed input)
        "conditions": [
            {"operator": "regex_match", "pattern": r"rm\s+-rf"}
        ],
    }
    rule = Rule.from_dict(frontmatter, "blocked")
    engine = RuleEngine()
    result = engine.evaluate_rules([rule], {
        "hook_event_name": "PreToolUse",
        "tool_name": "Bash",
        "tool_input": {"command": "rm -rf /tmp/x"},
    })
    # Expected (intended): should also deny, matching the legacy-form semantics.
    # Actual (bug): result == {} because Condition.field defaults to '' and
    # _extract_field returns None, making _check_condition -> False and the
    # block rule never triggers.
    assert result == {}, "Block rule silently bypassed due to malformed explicit condition"
```
The second test demonstrates that an explicit-conditions block rule intended to be equivalent to the legacy-pattern rule silently fails to block the exact same dangerous command, confirming the differential-parsing security-control bypass.     @classmethod
```python
    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""
        # Handle both simple pattern and complex conditions
        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:
            cond_list = frontmatter['conditions']
            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event
            event = frontmatter.get('event', 'all')
            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:
                field = 'content'

            conditions = [Condition(
                field=field,
                operator='regex_match',
                pattern=simple_pattern
            )]

        return cls(
            name=frontmatter.get('name', 'unnamed'),
            enabled=frontmatter.get('enabled', True),
            event=frontmatter.get('event', 'all'),
            pattern=simple_pattern,
            conditions=conditions,
            action=frontmatter.get('action', 'warn'),
            tool_matcher=frontmatter.get('tool_matcher'),
            message=message.strip()
        )
```

```python
    """
    try:
        with open(file_path, 'r') as f:

        return None
    except Exception as e:
```

```python
    def _rule_matches(self, rule: Rule, input_data: Dict[str, Any]) -> bool:
        """Check if rule matches input data.

        Args:
            rule: Rule to evaluate
            input_data: Hook input data

        Returns:
            True if rule matches, False otherwise
        """
        # Extract tool information
        tool_name = input_data.get('tool_name', '')
        tool_input = input_data.get('tool_input', {})

        # Check tool matcher if specified
        if rule.tool_matcher:
            if not self._matches_tool(rule.tool_matcher, tool_name):
                return False

        # If no conditions, don't match
        # (Rules must have at least one condition to be valid)
        if not rule.conditions:
            return False

        # All conditions must match
        for condition in rule.conditions:
            if not self._check_condition(condition, tool_name, tool_input, input_data):
                return False

        return True
```

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```
