### Title
Unbounded in-memory buffering of untrusted git subprocess output enables memory/CPU DoS - ([File: pkg/cmd/cmd.go])

### Summary
`git-sync` executes every `git` subcommand (fetch, config list, rev-parse, worktree, etc.) through `pkg/cmd/cmd.go`'s `runWithStdin`, which captures the child process's stdout and stderr into plain, unbounded `bytes.Buffer` instances before returning them as strings. Because the content and size of that output is derived from the synced remote repository (ref names, verbose fetch reports, commit data), a party who can influence the content of the upstream repo/ref (an "attacker-pushed commit/ref" scenario explicitly in scope) can cause git-sync to buffer arbitrarily large output fully in memory for every sync cycle, producing sustained memory growth analogous to the "Unlimited gossip RPC size" OOM/CPU DoS class from the Teku disclosure.

### Finding Description
The relevant code is: [1](#0-0) 


There is no `io.LimitReader`, no maximum buffer size, and no streaming/discard path — every byte the `git` child process writes to stdout/stderr is retained in memory (twice: once in the `bytes.Buffer` and again as a Go `string` after `.String()`/`TrimSpace`). This runner is the single implementation used by all of `repoSync`'s git invocations, including `fetch` with `--verbose` (which reports every updated ref) and `config list -z` at startup: [2](#0-1) [3](#0-2) 

Git's verbose fetch/ref-update reporting and config output scale with the number/size of refs and repository state, both of which are controlled by whoever can push content to the source repository that git-sync is configured to follow. A party able to create refs/branches or push commits to that remote repository (an "attacker-pushed commit or ref" in the report's rules) can inflate the number of refs or the size/verbosity of fetch output over repeated polling cycles, so each `git.Run(ctx, ..., "fetch", ...)` call allocates output buffers proportional to that attacker-controlled input, with no cap on total size.

### Impact Explanation
Because `git.Run` is called every polling `--period` (default 10s or configurable) for `fetch`, `config list`, `rev-parse`, and other commands, an attacker who can grow the ref/branch count or make fetch reporting verbose-heavy can force git-sync's process to allocate large, transient buffers repeatedly. This is a resource-exhaustion (memory/CPU) issue that can degrade or crash the git-sync sidecar (`OOM`), leading to persistent sync denial for the consuming pod — matching the "persistent sync denial" impact category in scope.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to have some ability to write refs/branches or otherwise inflate the content of the repository that git-sync is configured to sync from (e.g., a public/community repo, a repo where PRs create refs, or any environment where git-sync tracks an untrusted or semi-trusted remote). No special git-sync flags beyond default `--repo`/`--period` operation are required; `--verbose` fetch reporting is already hardcoded on the fetch path.

### Recommendation
Wrap `cmd.Stdout`/`cmd.Stderr` with a bounded writer (e.g., an `io.MultiWriter` into a size-limited ring buffer or `io.LimitedWriter`) in `pkg/cmd/cmd.go`, truncating command output beyond a configurable cap (with a marker indicating truncation) instead of buffering unboundedly. Consider avoiding `--verbose` on `fetch` when not needed for logging, or gating verbose capture behind a log-level check so the buffer is discarded early when not needed.

### Proof of Concept
This finding is based on static code review of `pkg/cmd/cmd.go`'s buffering design and its unconditional use across all `repoSync` git invocations; I could not execute a live sync cycle against a crafted remote to empirically measure memory growth, so the magnitude of impact (exact ref count/verbosity needed to trigger OOM) is inferred rather than measured end-to-end. A concrete PoC would involve standing up a remote repository under attacker control, creating a very large number of refs/branches (or extremely long ref names / commit metadata), pointing a git-sync instance at it with default settings, and observing RSS growth across repeated `--period` fetch cycles via `/metrics` or OS-level memory monitoring — this last step would need to be run in a live environment to confirm quantitatively.

```go
func runWithStdin(ctx context.Context, log logintf, cwd string, env []string, stdin, command string, args ...string) (string, string, error) {
	cmdStr := cmdForLog(command, args...)
	log.V(5).Info("running command", "cwd", cwd, "cmd", cmdStr)

	cmd := exec.CommandContext(ctx, command, args...)
	if cwd != "" {
		cmd.Dir = cwd
	}
	if len(env) != 0 {
		cmd.Env = env
	}
	outbuf := bytes.NewBuffer(nil)
	errbuf := bytes.NewBuffer(nil)
	cmd.Stdout = outbuf
	cmd.Stderr = errbuf
	cmd.Stdin = bytes.NewBufferString(stdin)

	start := time.Now()
	err := cmd.Run()
	wallTime := time.Since(start)
	stdout := strings.TrimSpace(outbuf.String())
	stderr := strings.TrimSpace(errbuf.String())
	if ctx.Err() == context.DeadlineExceeded {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, ctx.Err(), stdout, stderr)
	}
	if err != nil {
		return stdout, stderr, fmt.Errorf("Run(%s): %w: { stdout: %q, stderr: %q }", cmdStr, err, stdout, stderr)
	}
	log.V(6).Info("command result", "stdout", stdout, "stderr", stderr, "time", wallTime)

	return stdout, stderr, nil
}
```

```go
// fetch retrieves the specified ref from the upstream repo.
func (git *repoSync) fetch(ctx context.Context, ref string) error {
	git.log.V(2).Info("fetching", "ref", ref, "repo", redactURL(git.repo))

	// Fetch the ref and do some cleanup, setting or un-setting the repo's
	// shallow flag as appropriate.
	args := []string{"fetch", git.repo, ref, "--verbose", "--no-progress", "--prune", "--no-auto-gc"}
	if git.depth > 0 {
		args = append(args, "--depth", strconv.Itoa(git.depth))
	} else {
		// If the local repo is shallow and we're not using depth any more, we
		// need a special case.
		shallow, err := git.isShallow(ctx)
		if err != nil {
			return err
		}
		if shallow {
			args = append(args, "--unshallow")
		}
	}
	if git.filter != "" {
		args = append(args, "--filter", git.filter)
	}
	if _, _, err := git.Run(ctx, git.root, args...); err != nil {
		return err
	}

	return nil
}
```
