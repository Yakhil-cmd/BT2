### Title
Supply-index floor clamp resurrects wiped-out supply shares, letting stale positions drain later deposits - ([File: contracts/pool/src/interest.rs](contracts/pool/src/interest.rs))

### Summary
The MicroPython report describes a use-after-free: a resized `bytes` object keeps referencing memory that was already freed. The structural analog in XOXNO Lending is a scaled supply position that keeps referencing claim value after the market's total supplied value was "freed" (socialized away) by bad debt. `apply_bad_debt_to_supply_index` scales the supply index down to write off bad debt, but clamps the result upward at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of letting it reach zero. After a full wipeout, every supply position retains a phantom positive claim backed by nothing, which `withdraw` will happily pay out of any cash the pool later receives — including fresh user deposits. [1](#0-0) [2](#0-1) 

### Finding Description
When the controller's `clean_bad_debt` flow seizes a borrow position, `ops::seize::apply` computes `bad_debt = unscale_borrow_ceil_ray(position)` and calls `apply_bad_debt_to_supply_index`, which computes `new_supply_index = supply_index * (total_supplied_value - capped) / total_supplied_value` and then clamps it to `max(SUPPLY_INDEX_FLOOR_RAW)`. When `capped == total_supplied_value` (a total wipeout), the intended remaining value is zero, but the index is instead pinned at `RAY/1000`. [3](#0-2) [4](#0-3) 

Crucially, `supplied` (total scaled shares) and each user's `scaled_amount` are **not** reduced — the write-down is applied only through the index. Since the clamped index is nonzero, `resolve_withdrawal` and `unscale_supply_floor` still return a positive gross amount for every stale share. The withdraw path's only guards are `require_reserves(net_transfer)` (cash on hand) and `require_supply_for_debt` (only fires when `supplied == 0`), so once any cash exists in the market, a stale position withdraws real tokens. The repo's own test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` demonstrates exactly this: after a clamp wipeout, the old scaled position withdraws an amount equal to a subsequent fresh deposit, leaving `cash < fresh_claim`. [5](#0-4) [6](#0-5) [7](#0-6) 

### Impact Explanation
Theft of user funds. Any holder of pre-wipeout scaled supply (including the attacker, who can supply before triggering the bad-debt cleanup) keeps a claim valued at `scaled * RAY/1000` even though the economic value of the supply pool was fully consumed by the written-off debt. The first stale claimant to call `withdraw` after fresh deposits land is paid out of those deposits; the fresh supplier is left holding shares the pool can no longer back. The README acknowledges the index is floored "to avoid a zero index," but does not document — and the test shows the contrary — that the floor leaves phantom claims withdrawable. [8](#0-7) 

### Likelihood Explanation
Reachable by a single unprivileged address: `clean_bad_debt` is a permissionless controller entrypoint, and `seize_positions` applies the borrow-side socialization unconditionally. The attacker needs (1) a supply position in the target market acquired beforehand, (2) an account with bad debt at least equal to the market's total supplied value so the reduction factor reaches zero and the clamp engages, and (3) new cash arriving afterward (a fresh deposit or repay). Steps 1 and 3 require only normal `supply`/`withdraw` calls; step 2 requires a sufficiently underwater position reaching cleanup, which is the intended use of `clean_bad_debt`. The main uncertainty is whether producing capped bad debt of that magnitude is practical on a live market — it requires debt exceeding the market's entire supplied value, which is a tail-risk condition; that keeps this at Medium rather than High. I did not fully verify the controller-side conditions under which `clean_bad_debt` is invocable versus gated, so exact preconditions may be tighter than described. [9](#0-8) 

### Recommendation
On a wipeout where `capped == total_supplied_value`, zero the accounting properly instead of clamping the index: either burn `supplied`/`revenue` shares alongside the index floor, or record that the market's claims are voided so `resolve_withdrawal` returns zero for pre-wipeout positions. At minimum, gate `withdraw`/`claim_revenue` with `require_backed_market` (backing shortfall check) so phantom claims cannot be paid from unrelated cash. Alternatively, drop `SUPPLY_INDEX_FLOOR_RAW` clamping and handle the zero-index case explicitly at deposit time (reset shares or reject new deposits into a wiped market until recapitalized). [10](#0-9) [11](#0-10) 

### Proof of Concept
Conceptual trace (mirroring `contracts/pool/tests/interest.rs:372-427`, which already proves the cache-level mechanics):

1. Market M has `supplied = S`, `supply_index = I`, `cash = 0` (fully lent out). Attacker holds scaled supply `s_attacker` in M via `supply`.
2. An account accrues unbacked debt in M; a liquidator calls `clean_bad_debt(account_id)`. `seize_positions` → `apply_bad_debt_to_supply_index(bad_debt ≥ S*I)` → `reduction_factor = 0` → `supply_index = SUPPLY_INDEX_FLOOR_RAW = RAY/1000`. `supplied` and `s_attacker` are unchanged.
3. A victim calls `supply(amount = D)` into M, crediting `cash = D` and minting fresh shares at the floored index.
4. Attacker calls `withdraw` with `amount = i128::MAX` (or `scaled_amount = s_attacker`). `resolve_withdrawal` returns `gross = unscale_supply_floor(s_attacker) > 0`; `require_reserves` passes because `cash = D ≥ gross`; the pool transfers real tokens.
5. Victim's claim `D` is now unbacked: `cash < unscale_supply_floor(victim_scaled)` — victim funds were stolen to pay a claim that should have been zeroed by the write-down.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });

pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(
        env,
        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

pub(crate) fn require_supply_for_debt(env: &Env, cache: &Cache) {
    if cache.supplied() == Ray::ZERO && cache.borrowed() != Ray::ZERO {
        panic_with_error!(env, CollateralError::PoolInsolvent);
    }

pub(crate) fn execute_bad_debt_cleanup(
    env: &Env,
    cache: &mut Context,
    account_id: u64,
    account: &Account,
    totals: &AccountRiskTotals,
) {
    let mut entries: Vec<PoolSeizeEntry> = Vec::new(env);
    for (hub_asset, position) in iter_typed_positions(&account.supply_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Supply,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Deposit,
            position: (&position).into(),
        });
    }
    for (hub_asset, position) in iter_debt_positions(&account.borrow_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Borrow,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Borrow,
            position: (&position).into(),
        });
    }
    let pool_addr = cache.cached_pool_address();
    pool_seize_positions_call(env, &pool_addr, &entries);
