### Title
Webhook signature verified against `repository.owner.login`'s org while `OpenedHandler` (and all `PullRequest` handlers) resolve the target `Repository` from the unrelated `repository.full_name` field — allowing cross-tenant `ReviewStack` creation - ([File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App/`webhook_secret` to validate the HMAC using `repository_owner`, i.e. `params.dig('repository','owner','login')`. `OpenedHandler#repository` instead resolves the target `Shipit::Repository` via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. Both `repository.owner.login` and `repository.full_name` are independent, attacker-controlled fields inside the same raw JSON body the attacker signs themselves, and nothing in the engine enforces that `full_name`'s owner segment equals `owner.login`.

### Finding Description
The binding the code implicitly assumes is: `repository_owner (params.dig('repository','owner','login'))` == owner segment of `repository.full_name`. This is never checked.

- `verify_signature` in [1](#0-0)  looks up `Shipit.github(organization: repository_owner)` and verifies the HMAC signature against that org's `webhook_secret`, where `repository_owner` is defined at [2](#0-1) .
- `OpenedHandler#repository` at [3](#0-2)  resolves the target `Repository` using `params.repository.full_name`, via `Shipit::Repository.from_github_repo_name` which splits on `/` into owner/name and does a DB lookup, at [4](#0-3) .
- Because the attacker crafts and signs the raw JSON body themselves (this is a plain HTTP POST, not a GitHub-relayed webhook the attacker cannot forge), they fully control both `repository.owner.login` and `repository.full_name` independently in the same request.

Exploit flow: attacker owns (or administers) a GitHub org "attacker-org" that is configured in Shipit with its own `webhook_secret` (a legitimate, tracked tenant). They compute the HMAC-SHA1 over a crafted body using their own known `webhook_secret`, set `X-Github-Event: pull_request`, `repository.owner.login = "attacker-org"` (so `verify_signature` picks attacker-org's app and the signature validates), but set `repository.full_name = "victim-org/victim-repo"` and `action = "opened"` with a controlled `pull_request.head.ref`. Because `OpenedHandler` only reads `full_name`, it calls `Shipit::Repository.from_github_repo_name("victim-org/victim-repo")`, and if that repository is a tracked `Shipit::Repository` with review stacks enabled (`provisioning_behavior_allow_all?` or matching label rule), `ReviewStackAdapter#create!` creates a `ReviewStack` scoped to the victim repository at [5](#0-4) , using attacker-supplied `branch` (`params.pull_request.head.ref`) and `environment`.

Existing guards fail because: `drop_unhandled_event`/`check_if_ping` don't inspect `full_name`; `verify_signature` only ever reads `repository_owner`; the `ExplicitParameters` schema for `OpenedHandler` at [6](#0-5)  requires `repository.full_name` be a `String` but does not require it match `repository.owner.login`; and `Repository.from_github_repo_name` performs no ownership/tenant check against the verifying org.

### Impact Explanation
An attacker who controls only their own org's webhook secret can cause `Shipit::ReviewStack` records (and the resulting provisioning/deploy pipeline, since `ReviewStackProvisioningQueue.add(stack)` is invoked) to be created against a repository belonging to a different, victim tenant — a payload for one repository mutating another's stack, matching the stated Critical impact category. This is repeatable against any tracked repository the attacker can guess/know the `owner/name` of, for every `pull_request` (and similarly `closed`, `labeled`, `unlabeled`, `reopened`, `edited`, `assigned`) handler that follows the same `params.repository.full_name` resolution pattern (all these handlers share the identical `repository` method pattern, confirmed via the `from_github_repo_name` usages found in `closed_handler.rb`, `labeled_handler.rb`, `unlabeled_handler.rb`, `reopened_handler.rb`, `assigned_handler.rb`, `edited_handler.rb`, `label_capturing_handler.rb`).

### Likelihood Explanation
Preconditions: (1) attacker must control at least one org tracked by Shipit (own its `webhook_secret`, e.g., by being a legitimate integrator for some org that Shipit trusts) or otherwise be able to produce a validly-signed payload for some tracked org, and (2) `Shipit::Repository.review_stacks_enabled` with `provisioning_behavior_allow_all?` (or matching label condition) must be true for the victim repository. Given those, the attack is a single crafted HTTP POST to `/webhooks` with a manually computed HMAC — no GitHub interaction, no privileged Shipit role, and fully repeatable.

### Recommendation
In `WebhooksController#verify_signature`, or in the shared `Handler` base class, enforce that the org used to select the `webhook_secret` (`repository_owner`) matches the owner segment of `repository.full_name` (and `organization.login` when used as fallback) before dispatching to any handler; reject the request (422) on mismatch. Alternatively, have each `PullRequest` handler cross-check `params.repository.owner.login` against `repository.owner` after resolving the `Repository`, and refuse to act if they differ.

### Proof of Concept
```ruby
test "pull_request payload with mismatched owner.login vs full_name should not create a ReviewStack for another org's repo" do
  victim_repo = shipit_repositories(:some_review_stacks_enabled_repo) # owner: "victim-org", name: "victim-repo"
  request.headers['X-Github-Event'] = 'pull_request'

  body = {
    action: 'opened',
    number: 99,
    pull_request: {
      id: 1, number: 99, url: 'http://x', title: 't', state: 'open',
      additions: 1, deletions: 0,
      head: { sha: 'abc', ref: 'attacker-branch' },
      user: { login: 'attacker' },
      assignees: [], labels: []
    },
    repository: { owner: { login: 'attacker-org' }, full_name: 'victim-org/victim-repo' },
    sender: { login: 'attacker' }
  }.to_json

  signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', Shipit.github(organization: 'attacker-org').send(:webhook_secret), body)}"
  request.headers['X-Hub-Signature'] = signature

  assert_no_difference -> { victim_repo.review_stacks.count } do
    post :create, body: body, as: :json
  end
  # Currently this FAILS (a ReviewStack IS created), demonstrating the vulnerability.
end
```
