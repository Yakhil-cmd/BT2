CVE-2019-14944 concerns command-line flag injection into `git` subprocess invocations via attacker-controlled RPC parameters in Gitaly, i.e., untrusted network input reaching `argv` construction for an external process. Searching the Polkadot SDK codebase for equivalent `Command::new`/`process::Command` construction patterns, all instances found are either:

- Node-side infrastructure with fixed, hardcoded arguments (PVF worker spawning in [1](#0-0) , security checks in [2](#0-1) ) where `extra_args` originate from operator/node configuration, not from any signed extrinsic, contract call, or XCM message payload.
- Developer/CI tooling such as benchmark test harnesses ( [3](#0-2) ), docker entrypoints ( [4](#0-3) ), and zombienet/staking-miner test scripts ( [5](#0-4) ), none of which are reachable via a runtime entry point exercised by an unprivileged, unauthenticated caller.

None of these paths are reachable through a signed extrinsic, an enabled contract call, or a permitted XCM execute/send/transfer originating from an attacker with no privileged role — the required "real user entry" per the analysis method. The PVF worker spawn arguments are fixed by the validator's own node code (`"execute-worker"`, `--node-impl-version`, `--socket-path`, `--worker-dir-path`) and are not derived from PVF/candidate data submitted by parachains or collators [6](#0-5) . Since the FRAME/XCM/pallet-contracts execution environment is a WASM sandbox with no OS process-spawning capability reachable from dispatched calls, there is no demonstrable analog to Gitaly's CLI-flag injection in a consensus-critical, attacker-reachable code path.

async fn spawn_process_for_security_check<I, S>(
	prepare_worker_program_path: &Path,
	check_arg: &'static str,
	extra_args: I,
) -> Result<(), String>
where
	I: IntoIterator<Item = S>,
	S: AsRef<std::ffi::OsStr>,
{
	let mut command = tokio::process::Command::new(prepare_worker_program_path);
	// Clear env vars. (In theory, running checks with different env vars could result in different
	// outcomes of the checks.)
	command.env_clear();
	// Add back any env vars we want to keep.
	if let Ok(value) = std::env::var("RUST_LOG") {
		command.env("RUST_LOG", value);
	}

	match command.arg(check_arg).args(extra_args).output().await {
		Ok(output) if output.status.success() => Ok(()),
		Ok(output) => {
			let stderr = std::str::from_utf8(&output.stderr)
				.expect("child process writes a UTF-8 string to stderr; qed")
				.trim();
			if stderr.is_empty() {
				Err("not available".into())
			} else {
				Err(format!("not available: {}", stderr))
			}
		},
		Err(err) => Err(format!("could not start child process: {}", err)),
	}
}
