## Title
Signature verification keyed on `repository.owner.login` does not bind to the `repository.full_name` the webhook handlers act on, allowing cross-repository/cross-organization writes - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

## Summary
In Shipit's multi-organization GitHub App mode, `Shipit.github(organization:)` looks up a *distinct* `webhook_secret` per organization key configured in `secrets.github` [1](#0-0) . `WebhooksController#verify_signature` selects which organization's secret to use for the HMAC check from `repository_owner`, which is read from `params.dig('repository','owner','login')` (falling back to `params.dig('organization','login')`) — a field inside the very payload the attacker fully controls when POSTing directly to the public `/webhooks` endpoint [2](#0-1) . However, every event handler determines the target `Repository`/`Stack` to mutate using a *different* field from the same payload: `payload.dig('repository', 'full_name')` via `Handler#repository_name` (or `params.repository.full_name` in the pull-request handlers) [3](#0-2) .

Nothing forces `repository.owner.login` (used to select/verify the signing secret) to equal the owner portion of `repository.full_name` (used to select which stack gets written to). An attacker who legitimately controls a GitHub organization/App installation configured in this same Shipit instance (and therefore knows a valid `webhook_secret` for their own org key) can HMAC-sign an arbitrary payload with their own secret while setting `repository.full_name` to point at a victim repository/stack belonging to a different organization onboarded to the same Shipit instance.

## Finding Description
The trust binding that should hold is:

`organization whose webhook_secret authenticated the HMAC == organization/repository that the handler is permitted to mutate`

Before the request: GitHub (or, since the endpoint is public, an attacker with a valid HMAC key) computes `sha1=<HMAC(raw_body, secret_of_org_X)>` where `org_X` is whatever value the payload puts at `repository.owner.login`.

`verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)   # repository_owner from payload
verified = github_app.verify_webhook_signature(sig, raw_post)
``` [4](#0-3) 

This only proves the sender knows the secret associated with the *organization key present in the payload* — it says nothing about the `repository.full_name` field that will actually be used downstream.

Downstream, `PushHandler`, `StatusHandler`, `CheckSuiteHandler`, and the `PullRequest::*` handlers all resolve the stack via `Repository.from_github_repo_name(payload.dig('repository','full_name'))` [3](#0-2) [5](#0-4) , and then perform writes such as `stack.sync_github(expected_head_sha:)`, `review_stack.archive!/unarchive!`, or `ReviewStackAdapter.find_or_create!` [6](#0-5) .

Because `Shipit.github_app_config` returns one secret per organization key configured under `secrets.github` [7](#0-6) , and each organization owner independently owns their App installation's `webhook_secret`, an organization admin (an "unprivileged" party with respect to *other* organizations/repos hosted on the same Shipit instance) can craft:
```json
{
  "repository": { "owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>"
}
```
sign it with `attacker-org`'s known `webhook_secret`, and POST it to `/webhooks` with `X-Github-Event: push`. `verify_signature` resolves `Shipit.github(organization: 'attacker-org')`, verifies successfully against the attacker's own secret, and `PushHandler` then acts on `victim-org/victim-repo`, calling `stack.sync_github(expected_head_sha: params.after)` for the victim's stack [8](#0-7) .

## Impact Explanation
This breaks the "GitHub organization authenticated" vs. "repository actually written" binding for a cross-repository write, matching the High/Critical impact category "cross-repository writes." An attacker in control of one organization's App installation can force `GithubSyncJob`s, review-stack archive/unarchive, and PR-close/reopen actions to run against a victim organization's stacks hosted on the same shared Shipit instance, forcing spurious re-syncs with attacker-controlled `expected_head_sha` values and manipulating review stack lifecycle (archive/create) for repositories they do not own or have write access to.

## Likelihood Explanation
This requires the Shipit instance to be configured in the multi-organization GitHub App mode (`secrets.github` keyed by multiple org names, each with its own `webhook_secret`), which is an explicitly supported configuration path in `lib/shipit.rb` (`github_default_organization`, `github_app_config`) [9](#0-8) . Any organization admin already onboarded to such a shared instance — with no elevated Shipit privileges — can exploit this by directly POSTing to the public `/webhooks` route, since no other secret (session, API token) is required.

## Recommendation
After verifying the HMAC, re-derive `repository_owner` from `repository.full_name`'s owner portion (or vice versa) and reject the payload if they don't match, or — better — verify the signature using the secret associated with the owner of `repository.full_name` rather than the separate, independently-controllable `repository.owner.login` field.

## Proof of Concept
1. Configure a Shipit instance with `secrets.github` containing two orgs: `attacker-org` (secret `S_A`, known to the attacker as its own App owner) and `victim-org` (hosting a tracked stack, secret unknown to attacker).
2. Craft body:
```json
{"ref":"refs/heads/main","after":"deadbeef...","repository":{"owner":{"login":"attacker-org"},"full_name":"victim-org/victim-repo"}}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(body, S_A)>`.
4. `POST /webhooks` with header `X-Github-Event: push` and the crafted body/signature.
5. `verify_signature` resolves `Shipit.github(organization: 'attacker-org')`, validates HMAC against `S_A` successfully [10](#0-9) .
6. `PushHandler#process` resolves `Repository.from_github_repo_name('victim-org/victim-repo')` via `stacks` [3](#0-2)  and invokes `stack.sync_github(expected_head_sha: 'deadbeef...')` on the victim's stack despite the request only being authenticated for `attacker-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks

            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
