### Title
Path traversal via server-supplied `file.Name` in `writeToOutput` when writing to a directory output - ([File: pkg/cmd/repo/read-file/read_file.go])

### Summary
When `--output` names (or resolves to) a directory, `writeToOutput` builds the final destination with `dest = filepath.Join(dest, file.Name)`, where `file.Name` is taken verbatim from the Contents API JSON response, unlike other file-writing code paths in this codebase (`internal/zip/zip.go`, `pkg/cmd/run/download/http.go`, `pkg/cmd/run/download/download.go`) that use `safepaths.Absolute.Join` to reject traversal. A malicious or attacker-controlled host response containing a `name` field with `..` segments can therefore make the write land outside the user-chosen output directory.

### Finding Description
`writeToOutput` in [1](#0-0)  determines `asDir` from a trailing separator or an existing directory at `output`, and when `asDir` is true it computes `dest = filepath.Join(dest, file.Name)` at [2](#0-1) . `file.Name` comes from the `name` field of the Contents API JSON response fetched by `fetchFile`, and the test fixtures confirm it is a plain pass-through of the server-supplied `name` value, e.g. [3](#0-2) . `filepath.Join` only `Clean`s the concatenated path; it does not restrict `..` segments from escaping the base directory (e.g. `filepath.Join("out", "../../evil.txt")` resolves to `../evil.txt`, outside `out`). The subsequent `lstatF(dest)`/`writeFileF(dest, ...)` calls at [4](#0-3)  operate on this already-escaped path with no re-confinement to the original output directory. This is inconsistent with `safepaths.Absolute.Join`, which explicitly detects and rejects such traversal by checking `isSubpathOf` the base directory, as used elsewhere in the codebase (`internal/zip/zip.go`, `pkg/cmd/run/download/http.go`, `pkg/cmd/run/download/download.go`).

Against the real GitHub Contents API, a git tree/blob entry name cannot itself contain a `/`, so this is not exploitable against genuine github.com/GHES tree data through the normal Contents API in the “directory” case. However, per the threat model here, an attacker who controls the *host* the victim points `gh` at (e.g. `GH_HOST` pointing at a malicious/compromised Enterprise or a MITM'd/attacker-run API endpoint that the victim explicitly configured) can return arbitrary JSON, including a crafted `name` field like `"../../evil.txt"`, without going through git's tree name restrictions.

### Impact Explanation
If exploited, `gh repo read-file <path> --output some-dir/` (or any output resolving to a directory) can write attacker-controlled file content to a path outside `some-dir/`, i.e., an arbitrary file write on the victim's machine, matching a "file write outside intended path" bounty impact class. It requires the victim to target a directory-style `--output` and depends on `file.Name` being attacker-influenced content — realistic under the "attacker controls responses from a host the victim points gh at" precondition, but not reachable via the stock github.com API/Contents endpoint alone due to git tree-name constraints.

### Likelihood Explanation
Preconditions: victim runs `gh repo read-file <path> --output <dir>/` (or an existing directory) against a repository/host whose Contents API JSON response is attacker-controlled (custom/malicious GH_HOST, compromised GHES, or a MITM position that the threat model already grants for "host the victim points gh at" scenarios) — not reachable against genuine github.com repository data because valid git tree/blob names cannot contain path separators. This narrows real-world likelihood to alternate-host scenarios, but it is a deterministic, single-request exploit once that precondition holds (no timing/race needed for this "Name" traversal path, distinct from the separate TOCTOU race in the "Preconditions" portion of the question, which is a much lower-severity local-race scenario given lstat-then-write without O_NOFOLLOW/O_EXCL is a known Go idiom without atomic enforcement).

### Recommendation
Sanitize/validate `file.Name` before joining, or better, use `safepaths.Absolute.Join` (as already done in `internal/zip/zip.go` and `pkg/cmd/run/download/http.go`) to confine the final `dest` to be a subpath of the resolved output directory, rejecting the join with a `PathTraversalError` if `file.Name` (or the resulting path) escapes it. Additionally, consider using `os.OpenFile` with `O_EXCL`/`O_NOFOLLOW` (or re-lstat immediately before opening in the same syscall sequence) to reduce the local TOCTOU window between the second `lstatF` and `writeFileF`.

### Proof of Concept
Extend `Test_writeToOutput` in `pkg/cmd/repo/read-file/read_file_test.go`:
```go
{
    name:   "directory target with traversal name escapes output dir",
    file:   &repoFile{Name: "../../evil.txt", Content: []byte("pwned")},
    output: "out/",
    lstat: func(path string) (*lstatResult, error) {
        if path == "out/" {
            return &lstatResult{isDir: true}, nil
        }
        return nil, fs.ErrNotExist
    },
    wantErr: "output path escapes the target directory", // expected after fix; currently succeeds and writes outside "out/"
},
```
Currently this test would pass through to `writeFileF` with `dest == "../../evil.txt"` (via `filepath.Join("out/", "../../evil.txt")`), demonstrating the write target escapes the `out/` directory. An httpmock-based integration test can additionally simulate an alternate `GH_HOST` Contents API response with `"name": "../../evil.txt"` to show the end-to-end `gh repo read-file ... --output out/` writes outside `out/`.

func writeToOutput(file *repoFile, output string, clobber bool) (string, error) {
	dest := output

	// A trailing separator signals the user intends dest to be a directory even if it does not exist yet.
	asDir := strings.HasSuffix(dest, "/") || strings.HasSuffix(dest, string(os.PathSeparator))

	if lr, err := lstatF(dest); err == nil {
		if lr.isSymlink {
			return "", fmt.Errorf("output path is a symlink")
		}
		if lr.isDir {
			asDir = true
		}
	} else if !os.IsNotExist(err) {
		return "", err
	}

	if asDir {
		dest = filepath.Join(dest, file.Name)
	}

	if lr, err := lstatF(dest); err == nil {
		if lr.isSymlink {
			return "", fmt.Errorf("output path is a symlink")
		}
		if !clobber {
			return "", fmt.Errorf("output path already exists: %q (use --clobber to overwrite)", dest)
		}
	} else if !os.IsNotExist(err) {
		return "", err
	}

	if dir := filepath.Dir(dest); dir != "" && dir != "." {
		if err := mkdirAllF(dir, 0755); err != nil {
			return "", err
		}
	}

	if err := writeFileF(dest, file.Content, 0644); err != nil {
		return "", err
	}

	return dest, nil
}
