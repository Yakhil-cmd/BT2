### Title
`ProxyType::is_superset` in the staking-async relay-chain runtime lets a `NonTransfer` proxy grant proxy types whose call filters exceed `NonTransfer`'s own filter - ([File: substrate/frame/staking-async/runtimes/rc/src/lib.rs])

### Summary
The Frappe CVE's root cause is that document sharing was not validated against the sharer's own permission set, letting a user grant a permission they didn't hold. The Polkadot SDK analog is `pallet_proxy`'s "is_superset" invariant: `add_proxy`/`remove_proxy` executed *through* a proxy is only authorized via `def.proxy_type.is_superset(proxy_type)` in `do_proxy` (`substrate/frame/proxy/src/lib.rs:1005-1021`), which assumes `is_superset(A, B) == true` implies `B`'s allowed call set is a subset of `A`'s allowed call set. In `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, `is_superset` declares `(ProxyType::NonTransfer, _) => true` unconditionally (lines ~1410-1417), while `NonTransfer::filter` explicitly excludes the `Sudo` pallet, the `Balances` pallet, and `Registrar::swap` (comments at lines 1348, 1336, 1358 say "Specifically omitting"). Yet `SudoBalances` and `Auction` proxy types have filters that permit exactly those excluded calls. This is the same bug class already fixed once in this codebase for `NonTransfer`/`Governance` on Asset Hub Westend (see `prdoc/pr_12769.prdoc`), but it recurs unpatched here for `SudoBalances` and `Auction`.

### Finding Description
`pallet_proxy::do_proxy` (`substrate/frame/proxy/src/lib.rs:994-1026`) adds a runtime call filter that only blocks a proxied `add_proxy`/`remove_proxy` when `!def.proxy_type.is_superset(proxy_type)`. This is the sole guard preventing a delegate from using its proxy authority to grant a *more* powerful proxy type to itself or an accomplice — mirroring the exact invariant the Frappe DocShare bug violated ("share a permission you don't have").

In `substrate/frame/staking-async/runtimes/rc/src/lib.rs`:
- `ProxyType::NonTransfer::filter` (~1327-1363) allows a curated call set and explicitly documents omissions: "Specifically omitting the entire Balances pallet", "Specifically omitting Sudo pallet", "Specifically omitting Registrar `swap`".
- `ProxyType::SudoBalances::filter` (~1370-1376) allows `RuntimeCall::Sudo(pallet_sudo::Call::sudo{ call: Balances(..) })` and `Utility`.
- `ProxyType::Auction::filter` (~1392-1398) allows unrestricted `RuntimeCall::Registrar(..)` (i.e., including `swap`), plus `Auctions`, `Crowdloan`, `Slots`.
- `is_superset` (~1410-1417) returns `true` for `(NonTransfer, _)` for *any* `_`, including `SudoBalances` and `Auction`.

Because `SudoBalances`'s and `Auction`'s allowed-call sets are **not** subsets of `NonTransfer`'s allowed-call set (Sudo/Balances and unrestricted Registrar respectively are excluded from `NonTransfer`), the `is_superset` claim is false for these pairs, breaking the authorization invariant `do_proxy` relies on.

### Impact Explanation
A delegator who grants an account only a `NonTransfer` proxy (intending to withhold Sudo/Balances access and to withhold `Registrar::swap`) is not actually protected: the `NonTransfer` delegate can dispatch, through its proxy, `Proxy::add_proxy{ delegate: X, proxy_type: Auction }` or `Proxy::add_proxy{ delegate: X, proxy_type: SudoBalances }` on the delegator's behalf. `do_proxy`'s filter accepts this because `is_superset` wrongly reports `NonTransfer ⊇ Auction`/`SudoBalances`. The newly-added proxy `X` can then call `Registrar::swap` (or, if the delegator account happens to be the chain's `Sudo::Key`, `Sudo(sudo(Balances::force_transfer))`) *as the delegator*, capabilities the `NonTransfer` proxy holder itself was never permitted to reach directly. This is a broken-access-control / privilege-escalation issue matching CWE-863 and the same class already remediated for `NonTransfer`/`Governance` in AssetHub Westend (`prdoc/pr_12769.prdoc`).

### Likelihood Explanation
Reachability requires only a normal, unprivileged account that has been granted a `NonTransfer` proxy by another account (a routine, expected `pallet_proxy` configuration, not a privileged role). No governance, root, or stolen keys are needed to trigger the mismatch — only `Proxy::proxy` with a `Box<Call::Proxy(add_proxy{ proxy_type: Auction, .. })>` inner call. The severity of the ultimate consequence (`Registrar::swap` vs `Sudo(Balances)`) depends on what `Registrar::swap`'s own origin check requires and whether the delegator is the sudo key — I could not fully verify `paras_registrar::Call::swap`'s origin requirements in the available index (the registrar pallet's `swap` implementation was not found via search), so the exploitability of `Auction` escalation past this point is unconfirmed. Similarly, whether `substrate/frame/staking-async/runtimes/rc/src/lib.rs` is actually compiled into a live Westend/Polkadot relay-chain build (vs. being a staking-async migration reference/test runtime) is not established from what I could inspect — the file header comment says "The Westend runtime" but I cannot confirm current deployment status.

### Recommendation
Fix `is_superset` in `substrate/frame/staking-async/runtimes/rc/src/lib.rs` to only claim `NonTransfer` is a superset of proxy types whose filters are provably subsets of `NonTransfer`'s filter (as was done for the AssetHub Westend `NonTransfer`/`Governance` case in `prdoc/pr_12769.prdoc`). Concretely, remove `(ProxyType::NonTransfer, _) => true` and instead enumerate only true subsets (e.g. `Staking`, `NominationPools`, `IdentityJudgement`, `CancelProxy`, `Governance`, `ParaRegistration`), excluding `SudoBalances` and `Auction`. Add a regression test analogous to `staking_proxy_can_manage_staking_operator`/`pure_proxy_stash_can_delegate_to_staking_operator` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs` asserting `NonTransfer.is_superset(&SudoBalances) == false` and `NonTransfer.is_superset(&Auction) == false`, and that a proxied `add_proxy` attempting to grant these types is rejected with `CallFiltered`.

### Proof of Concept
Deployment/config evidence found: `ProxyType::NonTransfer`'s filter and doc comments explicitly omit Balances/Sudo/`Registrar::swap` (`substrate/frame/staking-async/runtimes/rc/src/lib.rs` ~1327-1363), while its `is_superset` impl (~1410-1417) unconditionally returns true against every other `ProxyType`, including `SudoBalances` (~1370-1376) and `Auction` (~1392-1398). The authorization gate this violates is `pallet_proxy::Pallet::do_proxy`'s `!def.proxy_type.is_superset(proxy_type) => false` filter (`substrate/frame/proxy/src/lib.rs:1005-1013`).

I was not able to execute a local reproduction (no terminal access in this session) confirming the end-to-end dispatch outcome, nor confirm `paras_registrar::Call::swap`'s exact origin requirements or whether this `rc` runtime file is the currently deployed Westend/Polkadot relay-chain runtime. These are flagged as open verification items rather than claimed as demonstrated facts. The static-analysis evidence (filter definitions vs. `is_superset` table) is nonetheless a concrete, file/line-level contradiction of the same invariant that a sibling PR (`prdoc/pr_12769.prdoc`) already fixed elsewhere in this exact codebase for `NonTransfer`/`Governance`, which supports this being a real, currently-unfixed instance of the same bug class rather than a false positive.
