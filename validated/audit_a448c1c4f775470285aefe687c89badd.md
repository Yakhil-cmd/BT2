### Title
Unvalidated P2P Staking Info Injection During Fast/Snap Sync Corrupts Reward Distribution and Validator Set — (`File: datasync/downloader/queue.go`)

---

### Summary

During fast sync and snap sync, `P2PStakingInfo` objects received from peers are accepted and persisted to the database without any content validation against the corresponding block header. The `validate` callback in `DeliverStakingInfos` is an explicit no-op (marked `TODO-Kaia-Snapsync update validation logic`), while the analogous `DeliverReceipts` validates every receipt batch against `header.ReceiptHash`. A malicious peer can inject fabricated staking info — with attacker-controlled reward addresses and staking amounts — that is then written to the node's database and used for all subsequent block reward distribution and validator set selection.

---

### Finding Description

In `datasync/downloader/queue.go`, `DeliverStakingInfos` accepts a list of `*staking.P2PStakingInfo` from a peer and stores each one into the corresponding `fetchResult` without verifying that the content matches the block header for which it was requested:

```go
// datasync/downloader/queue.go
func (q *queue) DeliverStakingInfos(id string, stakingInfoList []*staking.P2PStakingInfo) (int, error) {
    q.lock.Lock()
    defer q.lock.Unlock()
    validate := func(index int, header *types.Header) error {
        // TODO-Kaia-Snapsync update validation logic
        return nil   // ← always accepts, no check against header
    }
    reconstruct := func(index int, result *fetchResult) {
        result.StakingInfo = stakingInfoList[index]
        result.SetStakingInfoDone()
    }
    return q.deliver(id, q.stakingInfoTaskPool, q.stakingInfoTaskQueue, q.stakingInfoPendPool, stakingInfoReqTimer, len(stakingInfoList), validate, reconstruct)
}
``` [1](#0-0) 

Contrast this with `DeliverReceipts`, which validates every receipt batch against the committed `header.ReceiptHash`:

```go
validate := func(index int, header *types.Header) error {
    if types.DeriveReceiptsRoot(types.Receipts(receiptList[index]), header.Number) != header.ReceiptHash {
        return errInvalidReceipt
    }
    return nil
}
``` [2](#0-1) 

The accepted `P2PStakingInfo` is then unconditionally written to the node's persistent database in both `commitFastSyncData` and `commitPivotBlock`:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
``` [3](#0-2) [4](#0-3) 

The same unvalidated path exists in `SyncStakingInfo` (the explicit staking-info recovery flow), where the only check is that `stakingInfo.BlockNum` matches the locally expected block number — but the *content* of the staking info (node IDs, reward addresses, staking amounts) is never verified against any on-chain commitment:

```go
if d.stakingInfoRecoveryBlocks[0] != stakingInfo.BlockNum {
    logger.Error("failed to receive expected block", ...)
    return
}
d.stakingModule.PutStakingInfoToDB(stakingInfo.BlockNum, staking.ToStakingInfo(stakingInfo))
``` [5](#0-4) 

The `P2PStakingInfo` struct carries `CouncilNodeAddrs`, `CouncilStakingAddrs`, `CouncilRewardAddrs`, and `CouncilStakingAmounts` — all of which are fully attacker-controlled when delivered by a malicious peer: [6](#0-5) 

---

### Impact Explanation

The persisted `StakingInfo` is the authoritative source for two critical operations:

1. **Block reward distribution**: `assignStakingRewards` iterates `si.ConsolidatedNodes()` (derived from `RewardAddrs` and `StakingAmounts`) to compute and transfer KAIA block rewards. An attacker who injects fabricated `CouncilRewardAddrs` redirects all staking rewards to attacker-controlled addresses for every block processed using that staking interval's data. [7](#0-6) 

2. **Validator set selection**: `NodeIds` from the staking info feeds the weighted-random proposer selection. Corrupted node IDs can exclude legitimate validators or insert attacker-controlled ones, breaking consensus liveness or safety for the syncing node. [8](#0-7) 

The corrupted value is the `StakingInfo` record written at key `"stakingInfo" || Uint64LE(sourceNum)` in the node's misc database, which persists across restarts and governs reward distribution for all blocks in the corresponding staking interval. [9](#0-8) 

---

### Likelihood Explanation

- **Trigger**: Any node performing fast sync or snap sync (the standard mode for new nodes joining the network) that connects to at least one malicious peer.
- **Attacker requirement**: Operate a Kaia P2P node that responds to `StakingInfoRequestMsg` with fabricated data. No privileged access, no key compromise, no majority-validator collusion required.
- **Detectability**: The syncing node logs `"Imported new staking information"` but performs no integrity check, so the injection is silent.
- **Scope**: Affects all blocks whose staking interval falls within the synced range, meaning reward misdirection persists for the entire staking interval (up to `StakingUpdateInterval` blocks, default 86400). [10](#0-9) 

---

### Recommendation

Implement content validation in `DeliverStakingInfos` analogous to `DeliverReceipts`. The staking info for a block at a staking-interval boundary should be derivable from the block's state root. The validate callback should recompute the expected staking info from the local state (or a committed hash thereof) and reject any delivery that does not match:

```go
validate := func(index int, header *types.Header) error {
    si := stakingInfoList[index]
    if si.BlockNum != header.Number.Uint64() {
        return errInvalidStakingInfo
    }
    // Recompute expected staking info from local state and compare
    expected, err := q.stakingModule.GetStakingInfo(header.Number.Uint64())
    if err != nil || expected == nil {
        return errInvalidStakingInfo
    }
    // Compare critical fields: NodeIds, RewardAddrs, StakingAmounts
    ...
    return nil
}
```

If recomputing from state is too expensive during sync, at minimum verify `si.BlockNum == header.Number.Uint64()` and add a cryptographic commitment to the block header for staking info (similar to `ReceiptHash`). [11](#0-10) 

---

### Proof of Concept

1. Attacker runs a Kaia node and registers as a peer with a victim node that is performing fast sync.
2. When the victim sends `StakingInfoRequestMsg` for block hashes at staking-interval boundaries, the attacker's node responds with `StakingInfoMsg` containing fabricated `P2PStakingInfo`:
   - `CouncilRewardAddrs`: attacker-controlled addresses
   - `CouncilStakingAmounts`: inflated values for attacker addresses
   - `BlockNum`: matching the requested block number (passes the only check in `SyncStakingInfo`)
3. `handleStakingInfoMsg` decodes the message and calls `downloader.DeliverStakingInfos`.
4. `queue.DeliverStakingInfos` calls `validate(index, header)` which returns `nil` unconditionally.
5. `commitFastSyncData` calls `d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))`, persisting the fabricated data.
6. For all subsequent blocks in that staking interval, `assignStakingRewards` reads the corrupted `StakingInfo` and transfers KAIA block rewards to the attacker's addresses instead of the legitimate validators' reward addresses. [12](#0-11) [13](#0-12) [14](#0-13)

func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
