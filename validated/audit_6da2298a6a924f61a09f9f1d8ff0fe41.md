Confirmed: `Handler#repository_name` and `Handler#stacks` in `app/models/shipit/webhooks/handlers/handler.rb` resolve the target repository/stack from `payload.dig('repository', 'full_name')`, which is a field completely independent from `repository_owner` (`params.dig('repository', 'owner', 'login')`) used in `WebhooksController#verify_signature`. `PushHandler#process` and `StatusHandler#process` then act on whatever repository/commit that `full_name`/`sha` field designates.

### Title
Webhook signature verification keyed on attacker-controlled `repository.owner.login` diverges from the `repository.full_name` the handlers act on - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) used to authenticate an inbound webhook based on `repository_owner`, a value read straight out of the untrusted, not-yet-verified JSON body. The handlers that subsequently execute (`PushHandler`, `StatusHandler`, etc.) instead resolve the target `Stack`/`Commit` using a different field of that same untrusted body, `repository.full_name`. In a multi-organization Shipit deployment, if any one configured organization has no `webhook_secret` set — which is exactly how every shipped example config in this repo is written (`webhook_secret: # nil` in `config/secrets.development.shopify.yml:9`, `test/dummy/config/secrets_double_github_app.yml:7,46`, and `docs/setup.md:194,203`) — `GitHubApp#verify_webhook_signature` unconditionally returns `true` for that organization, regardless of payload content.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-49` does: [1](#0-0) 
`repository_owner` is derived purely from the request body: [2](#0-1) 
`GitHubApp#verify_webhook_signature` in `lib/shipit/github_app.rb:76-83` short-circuits to `true` whenever the selected organization has no configured secret: [3](#0-2) 

Meanwhile, every event handler ignores `repository.owner.login` entirely and instead resolves the affected `Stack` via `repository.full_name`: [4](#0-3) 
`PushHandler#process` and `StatusHandler#process` then act on whatever stack/commit that `full_name`/`sha` designates: [5](#0-4) [6](#0-5) 

This breaks the intended binding: `repository_owner (verified) == owner(repository.full_name (acted upon))`. An attacker can set `repository.owner.login`/`organization.login` to any organization value that resolves (via `Shipit.github_app_config`) to a configuration with a blank `webhook_secret`, causing `verify_signature` to pass unconditionally, while setting `repository.full_name` to an entirely different repository/stack that is tracked under a different, properly-secured organization in the same Shipit instance. The handler layer has no knowledge of, and performs no cross-check against, which organization's key validated the request.

### Impact Explanation
This allows an unauthenticated attacker to forge GitHub webhook events (`push`, `status`, `check_suite`, `membership`, `pull_request`) for repositories they do not control, as long as the Shipit instance has at least one configured GitHub organization without a webhook secret. Concretely:
- Forged `push` events trigger `stack.sync_github(expected_head_sha: ...)` on arbitrary tracked stacks (`PushHandler#process`), influencing which commit is considered head-of-branch and eligible for deploy.
- Forged `status` events call `commit.create_status_from_github!(params)` (`StatusHandler#process`) for any commit by `sha`, letting an attacker fabricate a passing CI status on a commit, which can unblock deploys/merges that are gated on external status checks.

This matches the "unauthorized deploy" / "authentication bypass" class called out as acceptable impact, since it lets an unprivileged party inject state that the deploy pipeline treats as GitHub-authenticated truth.

### Likelihood Explanation
Exploitability is entirely dependent on the deployment's `secrets.yml`. Every multi-org example shipped in this repository (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`, `docs/setup.md`'s "Using Multiple Github Applications" section) shows `webhook_secret` left blank/nil, suggesting this is a realistic operational configuration, not a contrived edge case. Any operator who configures one org fully (with a secret) and a second org without one — or simply forgets to set a secret on one App among several — exposes every stack in the instance, not just the unprotected org's repositories.

### Recommendation
Bind the field used for authentication to the field used for authorization: after selecting `github_app` by `repository_owner`, verify that the owner segment of `repository.full_name` actually matches `repository_owner` before dispatching to handlers, and/or require a non-blank `webhook_secret` for every configured organization (fail closed instead of `return true unless webhook_secret`).

### Proof of Concept
1. Deploy Shipit with two organizations configured under `github:` in `secrets.yml`: `OrgWithSecret` (has stacks tracking `OrgWithSecret/target-repo`, `webhook_secret` set) and `OrgNoSecret` (no `webhook_secret` configured, as shown in the shipped example configs).
2. Send `POST /github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": { "owner": { "login": "OrgNoSecret" }, "full_name": "OrgWithSecret/target-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>"
}
```
with no valid `X-Hub-Signature` (or any arbitrary value).
3. `verify_signature` resolves `Shipit.github(organization: "OrgNoSecret")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` and the request proceeds.
4. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, which resolves stacks via `repository.full_name = "OrgWithSecret/target-repo"` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on the real, properly-secured stack — despite the request never being authenticated by `OrgWithSecret`'s secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
