## Analog Found: Organization-selection binding for webhook signature verification is not the same field the event body actually authenticates

### Title
Webhook signature verification can be bypassed by selecting a different organization than the one whose data is actually processed - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` picks *which* per-organization `webhook_secret` to check against by reading `repository_owner`, which is derived from Rails' merged `params` (query string + body), not from `request.raw_post` alone. `GitHubApp#verify_webhook_signature` further trivially returns `true` when that selected organization has no `webhook_secret` configured. Because multi-tenant Shipit deployments configure a `webhook_secret` per organization (`docs/setup.md`, `config/secrets.development.example.yml`) and the secret is optional per org, an attacker can pick an org with no configured secret to make verification a no-op, and any GitHub webhook event body (for any repository/org) will still be processed unauthenticated.

### Finding Description
`verify_signature` derives the organization used to select the `GitHubApp`/secret purely from the request's `params`: [1](#0-0) [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`params` in a Rails controller is the union of query-string parameters and JSON body parameters; for keys that are *absent* from the parsed JSON body but present in the query string, the query-string value survives (Rack/Rails only replaces top-level keys that also exist in the body). So an attacker who sends a JSON body lacking a top-level `repository` or `organization` key (or that omits the `owner.login`/`organization.login` sub-path) can still control `repository_owner` by adding `?organization[login]=<attacker-chosen-org>` to the URL.

`GitHubApp#verify_webhook_signature` then performs no verification at all if that selected organization has no secret configured: [3](#0-2) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

Multi-organization Shipit configurations explicitly support per-organization, *optional* `webhook_secret` entries: [4](#0-3) 

The equality that should hold is: **`organization used to select/verify the webhook secret == organization whose payload is actually acted upon`.** The mitigation-style gap here is analogous to H-06/H-06-mitigation: the check (`verify_signature`) is bound to one derivation of the "organization" field (merged `params`, attacker-influenceable via query string), while the actual processing (`create`) re-parses and acts on a second, independent derivation of the payload: [5](#0-4) 

```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
```

Because `create` re-derives the event data straight from `request.raw_post` (never re-checking the actual `repository.owner.login`/`organization.login` embedded in the body against the organization that was verified), the two are not actually bound together: signature verification can succeed (or be skipped) for organization A (attacker-chosen, no secret configured) while the event body that gets processed pertains to organization/repository B (any victim repository already known to Shipit, e.g. via `PushHandler`, `MembershipHandler`, `StatusHandler`, `CheckSuiteHandler`, `PullRequestHandler`).

### Impact Explanation
This breaks the "GitHub identity/organization that authenticated the webhook" vs. "the repository actually written to by webhook handlers" binding — one of the explicitly targeted analog categories. Concretely, once verification is bypassed for one lightly-configured org:
- `PushHandler` triggers `stack.sync_github(expected_head_sha:)` for any tracked stack matching `branch`, letting an attacker spoof arbitrary commit SHAs / trigger `GithubSyncJob` on stacks belonging to a completely different, victim organization/repository.
- `MembershipHandler` can add/remove arbitrary GitHub users from `Team`s used for `Shipit.github_teams` authorization, directly escalating into the "escalation into `Shipit.github_teams` authorization" High-severity impact bucket.
- `StatusHandler`/`CheckSuiteHandler`/`PullRequestHandler` can forge CI status/check results that gate deploys and merges.

This maps to the required High impact class: "escalation into `Shipit.github_teams` authorization" and enables unauthorized/forged deploy-triggering events without any credential.

### Likelihood Explanation
Requires: (1) the deployment uses the multi-organization `secrets.yml` schema (documented and supported), and (2) at least one configured organization has no `webhook_secret` set (explicitly described as "optional" in `docs/setup.md` and shown as commented-out/blank in the example secrets files). Given the setup docs present `webhook_secret` as optional, this is a realistic misconfiguration in real deployments with several orgs, some of which may be lower-trust/test orgs without a secret configured. No authentication, tokens, or repository access is required by the attacker — only knowledge of one such org's login and the target repository name/branch, both public information.

### Recommendation
- Verify the HMAC signature using the organization/app config *before* trusting any org-derived field taken from the mutable `params`, and derive `repository_owner` exclusively from `JSON.parse(request.raw_post)` (the same bytes the signature covers), not from Rails' merged `params`.
- After verification, re-validate that the organization whose secret was used to verify the signature matches the organization/repository actually referenced in the event body before dispatching to handlers.
- Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is unset for an organization in multi-org mode; instead fail closed (422) unless a secret is explicitly and intentionally configured to be absent for that org, or better, require a secret in multi-org configurations.

### Proof of Concept
1. Configure Shipit in multi-org mode with `github.orgA.webhook_secret` set and `github.orgB` present but with no `webhook_secret` (a supported/documented configuration).
2. Send:
   ```
   POST /webhooks?organization[login]=orgB
   X-Github-Event: push
   Content-Type: application/json

   {"ref":"refs/heads/main","after":"<attacker-chosen-sha>","repository":{"full_name":"victim-org/victim-repo"}}
   ```
   Note the JSON body has no top-level `organization` key, so Rails' merged `params.dig('organization','login')` resolves to the query-string value `orgB` while `params.dig('repository','owner','login')` is absent (body only has `full_name`, no `owner.login`).
3. `verify_signature` calls `Shipit.github(organization: 'orgB')`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` unconditionally, regardless of `X-Hub-Signature`.
4. `create` re-parses `request.raw_post` and dispatches to `PushHandler`, which calls `stack.sync_github(expected_head_sha: 'attacker-chosen-sha')` for any tracked stack on branch `main`, without ever having verified any signature tied to `victim-org/victim-repo`. [6](#0-5) [3](#0-2) [7](#0-6)

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
