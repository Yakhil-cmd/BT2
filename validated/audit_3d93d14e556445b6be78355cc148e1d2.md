### Title
Webhook signature verification is scoped by `repository.owner.login`, but the acted‑upon repository is resolved from `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App / `webhook_secret` to validate a webhook against using `repository.owner.login` (falling back to `organization.login`), while every `Shipit::Webhooks::Handlers::Handler` subclass resolves the `Repository`/`Stack` it actually mutates using the unrelated `repository.full_name` field of the same JSON body. An attacker who can produce *any* accepted signature for one configured GitHub organization (trivial when that organization has `webhook_secret` left `nil`, a state this engine explicitly documents/ships as a valid configuration) can point `repository.full_name` at a completely different, properly‑secured organization's repository and have the handler act on it.

### Finding Description
`WebhooksController#verify_signature` picks the app config to verify against like this: [1](#0-0) [2](#0-1) 

`repository_owner` is read from `params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')` — both are attacker-controlled JSON fields in the raw webhook body, and the app then fetches `Shipit.github(organization: repository_owner)` to get that organization's `webhook_secret`.

`GithubApp#verify_webhook_signature` short-circuits to `true` whenever that organization's `webhook_secret` is blank: [3](#0-2) 

A `nil`/blank `webhook_secret` per organization is a documented, first-class configuration state in this engine (not an undocumented mis-deployment): the example secrets templates literally ship it as `webhook_secret: # nil`, and the test dummy config sets it to `null`: [4](#0-3) [5](#0-4) 

Meanwhile, every webhook handler (push, status, check_suite, membership, pull_request, …) inherits from `Shipit::Webhooks::Handlers::Handler`, which resolves the target `Repository`/`Stack` for the *write* using a different payload field, `repository.full_name`: [6](#0-5) 

and `PushHandler#process` uses that scope to trigger a real state change (`stack.sync_github`) on whatever stacks match: [7](#0-6) 

This is exactly the "sandwich ack" bug class from the report: the field that is checked/authenticated (`repository.owner.login` / `organization.login`, used to select the verifying secret) is not the same field that is later trusted and acted upon (`repository.full_name`, used to select which repository/stack is mutated). Nothing forces these two fields to reference the same organization — the attacker fully controls the JSON body.

### Impact Explanation
An attacker who knows (or can enumerate) that at least one GitHub organization configured on a shared Shipit instance has no `webhook_secret` set can craft a webhook whose `repository.owner.login`/`organization.login` names that unsecured organization (satisfying `verify_webhook_signature`'s unconditional `true`), while `repository.full_name` names a repository belonging to a different, properly-secured organization. The request is accepted with no valid signature at all, and the handler dispatch (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`) then operates against the victim organization's actual `Repository`/`Stack` records — e.g. forcing `GithubSyncJob`/`sync_github` on push events, or (via the same base-class resolution logic) writing commit/status/membership state used elsewhere to gate deploys (`ci.require`). This is an unauthenticated write of stack state belonging to an organization the request never proved any knowledge of, satisfying the "High: unauthenticated read of stack state" / potential path to "unauthorized deploy" impact bar, since CI-status and commit-sync state feed directly into deploy eligibility checks.

### Likelihood Explanation
Requires only: (1) a multi-organization Shipit deployment (explicitly supported, as shown by the multi-org secrets templates), and (2) one configured organization with a blank `webhook_secret` — a state the project's own example configs present as normal/default. No GitHub credentials, `ApiClient` tokens, or repository write access are needed; the request is a single unauthenticated POST to the public webhooks endpoint.

### Recommendation
Bind signature verification and repository resolution to the same authenticated field. Concretely, have `verify_signature` and every `Handler#repository_name` derive the organization/repository from the identical, single payload path (e.g. always `repository.full_name`, splitting owner from it), and reject requests where `repository.owner.login`/`organization.login` disagree with `repository.full_name`'s owner segment. Additionally, consider treating a blank `webhook_secret` as "reject all webhooks for this org" rather than "accept unconditionally," or require operators to explicitly opt in to unsigned webhooks per organization.

### Proof of Concept
1. Configure Shipit with two organizations: `unsecured-org` (`webhook_secret: nil`) and `victim-org` (real, secret-protected, has a tracked stack for `victim-org/app`).
2. POST to `/github_authorization/../webhooks` (the mounted webhooks endpoint) with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "unsecured-org" }, "full_name": "victim-org/app" }
}
```
No `X-Hub-Signature` header (or any garbage value) is required.
3. `verify_signature` resolves `repository_owner` = `"unsecured-org"`, fetches its `GithubApp`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally.
4. `PushHandler#process` resolves `stacks` from `payload.dig('repository','full_name')` = `"victim-org/app"`, finds the real `victim-org` stacks, and calls `stack.sync_github(expected_head_sha: "deadbeef")` — a state-changing action on `victim-org`'s stack, triggered without ever presenting a valid signature for `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
