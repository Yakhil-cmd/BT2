### Title
Fork PR label names become unfiltered environment variables reaching `git` subprocess spawned during the `fetch` phase, allowing `LD_LIBRARY_PATH` injection - (File: `app/models/shipit/review_stack.rb`)

### Summary
`ReviewStack#env` merges every pull-request label name (uppercased) directly into the stack's environment hash with no key allowlist, and that hash flows unmodified through `StackCommands#env` into `Command#start`/`Command#unbundled_env`, which merges it last (overriding the base sanitized environment) before calling `PTY.spawn`. An unprivileged fork-PR author can therefore label their PR `ld_library_path` and inject `LD_LIBRARY_PATH=true` (or, since the value is currently fixed to `"true"`, at minimum override that variable's presence) into the `git fetch`/`git clone` invocations that Shipit runs against their own review stack.

### Finding Description
The broken binding: the invariant claimed is `fetch_step_env.keys ∩ RESERVED_DYNAMIC_LINKER_VARS == ∅`; the actual behavior is `fetch_step_env = BASE_ENV.merge(PATH).merge(@env)` where `@env ⊇ {label.upcase => "true" for label in pull_request.labels}` with no allowlist applied.

Code path:
1. `ReviewStack#env` merges `pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` into `super` unconditionally: [1](#0-0) 
2. `pull_request.labels` is populated straight from the webhook payload by `LabelCapturingHandler#capture_labels`, which persists `params.pull_request.labels.map(&:name)` with no content filtering: [2](#0-1) 
3. `StackCommands#env` (used by `#fetch` and `#fetch_commit`) merges the base env with `@stack.env`, i.e. the ReviewStack's label-derived hash, unmodified: [3](#0-2) 
4. `Command#start` spawns the process with `unbundled_env`, which merges `@env` (the caller-supplied env, including the label-derived keys) **last**, after `BASE_ENV` and `PATH`, so any key the attacker names — including `LD_LIBRARY_PATH` — overrides whatever sanitized/cleaned value the base environment had: [4](#0-3)  and is passed directly to `PTY.spawn`: [5](#0-4) 

Existing guards do not stop this: `EnvironmentVariables#permit` implements exactly the allowlist mechanism that would prevent this (`sanitize_env_vars` raises `NotPermitted` for keys not in `variable_definitions`) [6](#0-5) , but it is never invoked on the path from `ReviewStack#env` → `StackCommands#fetch`/`#fetch_commit`. Tests in the repo confirm the intended (undefended) behavior: labels reach the env verbatim, uppercased, with value `"true"`: [7](#0-6) , [8](#0-7) .

The `provisioning_behavior=prevent_with_label` gate only controls whether the review stack is provisioned/archived [9](#0-8) ; it does not restrict which label names are permitted or filter them before they become env vars, so any repository operator using this mode is equally exposed once a stack exists.

### Impact Explanation
Any attacker who can open/label a pull request against a repository with review stacks enabled can force arbitrary override of the environment used to spawn `git fetch`/`git clone` for their own stack, including security/linker-sensitive variables like `LD_LIBRARY_PATH`. Combined with content the attacker controls in their own fork/checkout directory (which becomes the working directory for subsequent `git fetch` invocations against the same cached path), this is a path toward code execution during a git subprocess spawn on the deploy host — matching the Critical/RCE-via-`Command`/`PTY.spawn` category. The blast radius is scoped to review stacks tied to the attacker's own PR/repository (not necessarily other tenants), but the underlying primitive — unfiltered, fork-controlled keys reaching `PTY.spawn`'s environment — is a genuine violation of the stated invariant.

### Likelihood Explanation
Preconditions: the repository must have review stacks enabled (`review_stacks_enabled`), which is a normal/documented Shipit feature; the attacker needs only to open a PR from a fork and apply a label to it (an action the audit's threat model explicitly grants to unprivileged attackers). No secrets, tokens, or privileged GitHub roles are required. This is trivially repeatable per PR/stack.

### Recommendation
Apply `EnvironmentVariables#permit` (or an explicit denylist of dynamic-linker/interpreter-affecting variables such as `LD_LIBRARY_PATH`, `LD_PRELOAD`, `DYLD_*`) to `ReviewStack#env`'s label-derived hash before merging, and/or change `Command#unbundled_env` to merge `@env` in a way that cannot clobber a fixed set of security-sensitive keys, rather than always letting caller-supplied `@env` win last.

### Proof of Concept
```ruby
# test/models/shipit/review_stack_test.rb (conceptual addition)
test "#env does not allow PR labels to override sensitive dynamic-linker variables" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ["ld_library_path"]

  env = stack.env
  # Broken binding demonstrated: env["LD_LIBRARY_PATH"] == "true"
  assert_nil env["LD_LIBRARY_PATH"], "fork-controlled label should not set LD_LIBRARY_PATH"
end

# test/unit/deploy_commands_test.rb style, showing it reaches the spawned fetch command
test "#fetch env does not inherit fork-controllable LD_LIBRARY_PATH from PR label" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ["ld_library_path"]
  commands = Shipit::StackCommands.new(stack)

  command = commands.fetch
  assert_nil command.env["LD_LIBRARY_PATH"]
  assert_nil command.unbundled_env["LD_LIBRARY_PATH"]
end
```
Both assertions currently fail against the traced code (`env["LD_LIBRARY_PATH"]` equals `"true"`), confirming the invariant "the fetch step inherits no fork-controllable key such as LD_LIBRARY_PATH" is violated.

    def permit(variable_definitions)
      return {} unless @env
      raise "A whitelist is required to sanitize environment variables" unless variable_definitions

      sanitize_env_vars(variable_definitions)
    end

    def interpolate(argument)
      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
    end

    private

    def initialize(env)
      @env = env
    end

    def sanitize_env_vars(variable_definitions)
      allowed_variables = variable_definitions.map(&:name)

      allowed, disallowed = @env.partition { |k, _| allowed_variables.include?(k) }.map(&:to_h)

      error_message = "Variables #{disallowed.keys.to_sentence} have not been whitelisted"
      raise NotPermitted, error_message unless disallowed.empty?

      allowed
    end
