## Title
Null pointer dereference in `getAllAuthorsAndOutputAddresses()` on a "definition" message without a payload crashes the node - (File: network.js)

### Summary
Similar to CVE-2025-57767, where Asterisk dereferenced a NULL return value from an untrusted-input parser without a check, `ocore`'s `network.js` function `getAllAuthorsAndOutputAddresses()` accesses `payload.definition[1].base_aa` for a `definition`-app message without first verifying that `payload` is truthy, unlike the sibling `payment` branch in the same loop which explicitly checks `payload` before use.

### Finding Description
In `getAllAuthorsAndOutputAddresses`, the code iterates over `objUnit.messages` and branches on `message.app`: [1](#0-0) 

```
for (var i=0; i<objUnit.messages.length; i++){
    var message = objUnit.messages[i];
    var payload = message.payload;
    if (message.app === "payment" && payload) {
        ...
    }
    else if (message.app === 'definition' && payload.definition[1].base_aa)
        arrBaseAAAddresses.push(payload.definition[1].base_aa);
}
```

Note that the `payment` branch defensively checks `&& payload` before touching `payload.outputs`, but the `definition` branch does not check `payload` (or `payload.definition`, or `payload.definition[1]`) before dereferencing `payload.definition[1].base_aa`. A `message.payload` can legitimately be absent/undefined at this stage — e.g. when `payload_location` is not `"inline"` (payload stripped, sent separately, or voided), which is a normal, attacker-controllable state for a unit sent over the wire before/while full validation completes. Dereferencing `.definition` on `undefined` throws a `TypeError`, and `.definition[1]` on an unexpected/short array (attacker fully controls the `payload.definition` JSON structure) can equally throw.

This function is invoked from the network layer when processing units received from peers, in the same code paths that decide which watched addresses/light clients to notify for a joint — i.e., it is reachable by any unprivileged unit poster who can get their joint relayed to a node, without needing any special privilege, similar to how the Asterisk bug was reachable via any unauthenticated SIP `Authorization` header.

### Impact Explanation
An uncaught `TypeError` thrown synchronously inside `network.js` request-handling code paths (not wrapped by validation's own try/catch, which primarily guards `objectHash`/hash-computation paths) can crash the Node.js process (unhandled exception), taking a full node offline. Because this triggers as part of ordinary joint processing/broadcast handling for a wide swath of nodes (any node watching an affected address or serving light clients), a single crafted unit could be used to crash multiple honest nodes simultaneously, degrading the network's ability to confirm new units — matching the "network unable to confirm new units" acceptance criterion for this class of finding.

### Likelihood Explanation
Likelihood is High: the attacker only needs to post/relay a single unit containing a `definition`-app message whose `payload` is missing (payload_location != "inline") or whose payload lacks a well-formed `definition` array, which is trivial to construct and does not require any signature validity beyond what's needed to get the unit relayed to peers.

### Recommendation
Guard the `definition` branch the same way the `payment` branch is guarded: require `payload && payload.definition && payload.definition[1] && payload.definition[1].base_aa` before pushing to `arrBaseAAAddresses`, mirroring the existing null-check pattern used for `payment` messages in the same function.

### Proof of Concept
Construct/relay a joint whose `unit.messages` array contains a message object `{ app: 'definition', payload_location: 'none' }` (or any state where `message.payload` is `undefined`) alongside normal well-formed messages elsewhere in the unit so it reaches the code path that calls `getAllAuthorsAndOutputAddresses(objUnit)`. When the function executes `payload.definition[1].base_aa` with `payload === undefined`, Node.js throws `TypeError: Cannot read properties of undefined (reading 'definition')`, crashing the process if uncaught by an enclosing handler.

Note: I was only able to confirm the vulnerable code within `getAllAuthorsAndOutputAddresses` itself via the index; the exact call sites and whether they wrap this call in a try/catch could not be fully traced within the tool budget available (the `grep_search`/`read_file` calls for exact caller context in `network.js` did not return before the iteration limit was reached). I recommend a Devin session with full repository access to confirm the precise call-site guarantees (e.g., whether `objUnit.messages` is always guaranteed to have `payload` populated by validation before this function runs) before treating this as fully confirmed.
