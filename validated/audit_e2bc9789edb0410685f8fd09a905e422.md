### Title
Non-network-aware signed packages lack chain-state binding, enabling replay of signatures across time, AA instances, and chain forks - ([File: signed_message.js])

### Summary
The Sherlock report describes GMX oracle signatures being replayable across a hard fork because the signing `SALT` is a hard-coded, construction-time value (`keccak256(block.chainid, ...)`) that is never re-checked against the live chain, so a signature valid on one branch of a fork remains valid on the other. The analogous weak point in `ocore` is `signed_message.js`, which lets a signer produce a "signed package" (verified elsewhere via `is_valid_signed_package()` in AA oscript, and used for order books, payment channels, and other off-chain-signed data) that is **not bound to any chain state at all** unless the signer opts in to `bNetworkAware`.

### Finding Description
`signMessage()` builds the object to be signed as just `{version, signed_message, authors}` when `bNetworkAware` is false, and only conditionally adds `last_ball_unit` (a pointer into a specific point of the DAG) when the caller explicitly requests network-awareness: [1](#0-0) 

The hash that is actually signed, `getSignedPackageHashToSign`, is a straight serialization of this object with no fork/chain-specific salt other than the static `version` string: [2](#0-1) 

On the verification side, `validateSignedMessage()` treats `last_ball_unit` as fully optional (`bNetworkAware = ("last_ball_unit" in objSignedMessage)`), and when it is absent, the signed message is validated with `bNoReferences: true` and no chain-state check whatsoever - it only re-derives the same hash and checks the signature/definition: [3](#0-2) [4](#0-3) 

Unlike ordinary DAG units, whose hash-to-sign includes `alt` (the network identifier) via `getStrippedUnit`/`getNakedUnit`, a signed package's whitelist of allowed fields is `["signed_message", "authors", "last_ball_unit", "timestamp", "version"]` - there is no `alt` field and no mandatory chain-state anchor: [5](#0-4) [6](#0-5) 

Just like the GMX `SALT`, `constants.version`/`constants.alt` are fixed, config-time constants (set once at process start based on `bTestnet`/`bDevnet`), not values that are re-derived from live, per-branch chain state: [7](#0-6) 

Consequently, when a signer chooses (or an AA/oscript author using `is_valid_signed_package` fails to require) `bNetworkAware=true` with a fresh `last_ball_unit`, the resulting signature is not tied to any particular chain state, fork, or point in time - exactly the missing "look up chain id/state each time" protection called out in the original report.

### Impact Explanation
A signed package produced for one context (e.g., an off-chain price attestation, an order in `order_book_exchange.oscript`, or a payment-channel authorization) can be replayed:
- Indefinitely in time, since there is no expiry or chain-state binding when `bNetworkAware` is false.
- Across a hard fork of the same network (same `version`/`alt`, different DAG history), since neither `version` nor `alt` nor (in the non-network-aware case) any DAG pointer distinguishes the branches.

Since these signed packages are consumed by AA oscript via `is_valid_signed_package()` to authorize fund-moving logic (order execution, payment-channel settlement), a counterparty or trigger sender can resubmit a stale, previously-valid signature to force an AA to accept outdated data/authorization, potentially causing unauthorized fund movement or a stuck/incorrect state in the AA - the same class of "invalid execution / incorrect settlement" impact described in the original finding.

### Likelihood Explanation
Reaching this path requires no special privilege: any AA trigger sender or private-payment/payment-channel counterparty can capture a previously-published signed package (which is often transmitted peer-to-peer or embedded in a trigger) and resend it as a new trigger's data. The vulnerability is latent unless AA authors always require and validate `last_ball_unit`/timestamp freshness themselves within the oscript logic; the protocol layer (`signed_message.js`) does not enforce chain-state binding by default.

### Recommendation
- Make chain-state binding mandatory for any signed package consumed via `is_valid_signed_package()`, i.e., require `last_ball_unit` (network-aware signing) rather than treating it as optional.
- Additionally include a monotonically increasing nonce/expiry or an explicit reference to the specific AA/context inside `signed_message` content, so that a valid signature cannot be reused verbatim in a different AA, trigger, or after a fork.
- Document/require AA authors using `is_valid_signed_package` to enforce that `last_ball_unit` is present and recent (bounded MCI distance) before trusting the signed content.

### Proof of Concept
1. Party A signs a message with `signMessage(msg, address, signer, /*bNetworkAware=*/false, cb)`, producing `{version, signed_message: msg, authors:[{address, definition, authentifiers}]}` with no `last_ball_unit` (per `signed_message.js` lines 27-61).
2. This package is used once as intended (e.g., an order fill or payment-channel authorization consumed by an AA via `is_valid_signed_package`).
3. Because the signed object contains no chain-state pointer, `getSignedPackageHashToSign` (object_hash.js lines 97-103) produces the identical hash regardless of current DAG state, current MCI, or which fork of a hard-forked network is being evaluated.
4. Party B (or A, maliciously) resubmits the exact same `signed_package` as trigger data to the same or a different AA instance, or on the other branch of a chain fork; `validateSignedMessage` (signed_message.js lines 241-253) accepts it again since it only checks the signature/definition against the static content, with no replay/freshness check enforced by the protocol.

function getSignedPackageHashToSign(signedPackage) {
	var unsignedPackage = _.cloneDeep(signedPackage);
	for (var i=0; i<unsignedPackage.authors.length; i++)
		delete unsignedPackage.authors[i].authentifiers;
	var sourceString = (typeof signedPackage.version === 'undefined' || signedPackage.version === constants.versionWithoutTimestamp) ? getSourceString(unsignedPackage) : getJsonSourceString(unsignedPackage);
	return crypto.createHash("sha256").update(sourceString, "utf8").digest();
}
