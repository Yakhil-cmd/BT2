### Title
Cross-organization webhook payload confusion allows repository from org B to be mutated using org A's webhook secret - (File: app/models/shipit/webhooks/handlers/handler.rb)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate a webhook using `payload.dig('repository','owner','login')`, but every `Handler` subclass resolves the target `Repository`/`Stack` using `payload.dig('repository','full_name')` via `Handler#repository_name`/`#stacks`. Because these two payload fields are never cross-checked, an attacker who legitimately controls one configured Shipit organization (and thus knows its `webhook_secret`) can forge a single JSON body where `repository.owner.login` names their own org (to pass signature verification) while `repository.full_name` names a victim org/repo (to select the mutation target).

### Finding Description
The broken binding is: `payload.dig('repository','owner','login')` (input to `Shipit.github(organization:)` in `WebhooksController#verify_signature`, `app/controllers/shipit/webhooks_controller.rb:25,59-62`) **must equal** the owner segment of `payload.dig('repository','full_name')` (input to `Handler#repository_name`, `app/models/shipit/webhooks/handlers/handler.rb:36-38`, used by `#stacks` at line 32-34 via `Repository.from_github_repo_name`). No code anywhere asserts this equality.

Trace:
- `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` and validates `X-Hub-Signature` against `github_app`'s `webhook_secret` over the raw POST body [1](#0-0) , where `repository_owner` reads `params.dig('repository','owner','login')` [2](#0-1) .
- `Shipit.github(organization:)` requires the named organization to be pre-configured in `secrets.github` (an operator-provisioned, per-org `webhook_secret`); unknown organizations raise `GithubOrganizationUnknown` and are rejected [3](#0-2) .
- Once signature verification passes, `#create` re-parses the same raw body and dispatches it unchanged to every matching `Handler` [4](#0-3) .
- `Handler#repository_name` and `#stacks` derive the target repo purely from `full_name`, with zero reference to `repository_owner`/the verified organization [5](#0-4) .
- Every concrete handler (`PushHandler`, `StatusHandler`, `MembershipHandler`, `CheckSuiteHandler`, and all `PullRequest::*Handler`s) inherits `#stacks` unchanged and mutates whatever `Stack`/`Repository`/`Commit`/`Team` records `full_name` resolves to, e.g. `PushHandler#process` calls `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` [6](#0-5) .

Exploit flow: attacker legitimately operates org `org-a`, which a Shipit operator has configured in `secrets.github` with a `webhook_secret` the attacker knows (this is a normal, non-privileged setup step available to any org that onboards to a multi-tenant Shipit instance). Attacker crafts a raw JSON body for any supported event (e.g. `push`) with `repository.owner.login = "org-a"` and `repository.full_name = "org-b/victim-repo"`, computes `HMAC-SHA1(webhook_secret_org_a, body)`, and POSTs it to `/webhooks` with `X-Github-Event: push` and the computed `X-Hub-Signature`. `verify_signature` looks up `org-a`'s app/secret (matching `owner.login`), validates successfully, and `#create` forwards the body to `PushHandler`, which resolves `stacks` against `org-b/victim-repo` and calls `sync_github` on it — a write against a repository/stack the attacker never authenticated for.

No existing guard prevents this: `drop_unhandled_event` only checks event type presence, `ExplicitParameters` schemas (e.g. `requires :ref`, `requires :after`) validate shape not ownership, and there is no `Repository`/`Stack` validation that ties an inbound webhook's verified organization to the mutated record.

### Impact Explanation
A payload authenticated as belonging to `org-a` mutates state (triggers `sync_github`, records commits/statuses, adds/removes team memberships via `MembershipHandler`, opens/merges review stacks via `PullRequest` handlers, updates check-suite status) for a completely different repository/organization (`org-b`) that never authorized the request. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task or team." Since the flaw is in the shared `Handler` base class, it is systemic and reachable through every registered event type/handler (`Shipit::Webhooks.default_handlers`), not a single isolated handler, giving a generic cross-tenant write primitive against any repository whose owner/name is knowable to the attacker.

### Likelihood Explanation
Exploitability requires the attacker to control at least one organization that a Shipit operator has configured with a webhook secret in `secrets.github` — a normal, low-privilege onboarding scenario for any multi-tenant Shipit deployment (`github_organizations`/`github_app_config` in `lib/shipit.rb:190-200` confirm multiple orgs can be configured). Given that, forging the divergent JSON body and computing the HMAC is trivial (no GitHub interaction needed, no other secrets required), and the attack is fully repeatable against any target repository name/owner combination and any event type.

### Recommendation
In `Handler#stacks`/`#repository_name`, require the verified organization to be passed down from the controller and assert it matches the owner segment of `repository.full_name` (or better, resolve the target repository via `Repository.from_github_repo_name(full_name)` and then confirm `repository.owner_login == verified_organization` before returning any stacks). Concretely: change `WebhooksController#create` to pass the verified `repository_owner`/`github_app` context into `handler.call`, and add a check in the base `Handler` class that raises/no-ops when `payload.dig('repository','owner','login')` (or `organization.login` fallback) does not match `payload.dig('repository','full_name').split('/').first`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (extend existing suite)
test "push event verified against org-a secret must not mutate org-b's stack" do
  org_a_secret = Shipit.github(organization: 'org-a').send(:webhook_secret) # configured secret attacker knows
  victim_stack = shipit_stacks(:shipit) # belongs to org-b/some-repo
  body = {
    ref: 'refs/heads/master',
    after: 'a' * 40,
    repository: {
      owner: { login: 'org-a' },        # verification side
      full_name: victim_stack.repository.full_name # mutation side, e.g. "org-b/some-repo"
    }
  }.to_json

  signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', org_a_secret, body)}"

  assert_equal 'org-a', JSON.parse(body).dig('repository', 'owner', 'login')
  assert_equal 'org-b', JSON.parse(body).dig('repository', 'full_name').split('/').first
  # explicit assertion that the binding is violated before tracing further

  Shipit::Stack.any_instance.expects(:sync_github).with(expected_head_sha: 'a' * 40) # asserts org-b's stack was touched

  post shipit.webhooks_path, params: body, headers: {
    'X-Github-Event' => 'push',
    'X-Hub-Signature' => signature,
    'CONTENT_TYPE' => 'application/json'
  }

  assert_response :ok
end
```
This test signs a payload with `org-a`'s secret while pointing `full_name` at `org-b`'s stack, and asserts that `sync_github` is invoked on the `org-b` stack despite the request being authenticated only for `org-a`, proving the binding failure end-to-end.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
