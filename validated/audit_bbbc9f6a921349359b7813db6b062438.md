### Title
Unbounded artifact download body written to disk without size cap in `downloadArtifact` - ([File: pkg/cmd/run/download/http.go])

### Summary
`downloadArtifact` streams the entire HTTP response body of an artifact ZIP directly to a temp file via `io.Copy` with no maximum size enforcement, relying only on `Content-Length` semantics that are never checked. An attacker who controls a workflow run whose artifacts the victim downloads (e.g., via `gh run download -R attacker/repo` or `gh run download` on a run from an attacker-influenced fork/PR) can cause the victim's `gh` process to write an arbitrarily large or effectively unbounded stream to disk, exhausting local storage.

### Finding Description
In `pkg/cmd/run/download/http.go`, `downloadArtifact` performs: [1](#0-0) 
`resp.Body` is copied into a temp file with no `io.LimitReader`, no `http.MaxBytesReader`, and no pre-check of `Content-Length` or an upper bound configured on the request/response. The URL passed in (`safeurl.SafeURL`) originates from `a.DownloadURL` returned by the artifact listing API and is fetched through `runDownload` in `pkg/cmd/run/download/download.go`: [2](#0-1) 
`safeurl`/`safepaths` protect against SSRF/path-traversal concerns, but neither protects against response body size. Once the victim invokes `gh run download` against a run belonging to (or accessible via) an attacker-controlled repository, the HTTP server serving the artifact content controls how much data is streamed back, and `io.Copy` will keep writing until the connection ends or disk space is exhausted, with no cap enforced by the CLI.

A repo-wide check confirms this pattern (unbounded `io.Copy` from network responses without size limiting) is not unique to this function, but no compensating control specific to `downloadArtifact` exists in this code path.

### Impact Explanation
This maps to a resource-exhaustion / denial-of-service impact: an attacker-controlled response can consume all available disk space on the victim's machine during a routine `gh run download`, potentially disrupting the victim's system (other processes failing due to no free disk) until the temp file is cleaned up or the process is killed. It does not provide code execution, credential exfiltration, or file-write outside the intended temp path, so impact is limited to local DoS/resource exhaustion.

### Likelihood Explanation
Feasible precondition: the victim must run `gh run download` against a run whose artifact `DownloadURL` is served (directly or via redirect) by a host the attacker influences—achievable if the victim is instructed to inspect/download artifacts from an attacker's public repository or fork with `-R`. The attack requires no privileges beyond publishing a repo/workflow run and controlling the response of the artifact download endpoint (or a host masquerading as one to the CLI). Repeatable and low-cost for the attacker.

### Recommendation
Enforce a maximum artifact size before/while streaming: check `resp.ContentLength` against a sane upper bound before starting the copy, and additionally wrap `resp.Body` with `io.LimitReader` (or `http.MaxBytesReader` semantics) so the copy aborts once the limit is exceeded, returning a clear error instead of filling disk indefinitely.

### Proof of Concept
```go
func TestDownloadArtifact_UnboundedBody(t *testing.T) {
    reg := &httpmock.Registry{}
    reg.Register(
        httpmock.REST("GET", "artifact-url"),
        func(req *http.Request) (*http.Response, error) {
            // simulate an endless/very large body with no Content-Length
            pr, pw := io.Pipe()
            go func() {
                buf := make([]byte, 1<<20) // 1MB chunks
                for {
                    if _, err := pw.Write(buf); err != nil {
                        return
                    }
                }
            }()
            return &http.Response{
                StatusCode: 200,
                Body:       pr,
                Header:     http.Header{},
            }, nil
        },
    )
    client := &http.Client{Transport: reg}
    dir, _ := safepaths.ParseAbsolute(t.TempDir())
    url := safeurl.NewImmutableSafeURL("https://artifact-url")

    done := make(chan error, 1)
    go func() { done <- downloadArtifact(client, url, dir) }()

    select {
    case <-time.After(2 * time.Second):
        t.Fatal("downloadArtifact did not abort on oversized/unbounded body; expected a size-limit error")
    case err := <-done:
        require.Error(t, err) // expect an explicit "artifact too large" style error once a cap is added
    }
}
```
Expected (post-fix) assertion: `downloadArtifact` returns an error once the copied size exceeds a configured maximum, rather than continuing to write indefinitely.
