### Title
Sustained high-utilization accrual overflows `i128` inside `scaled_to_original`, permanently freezing a market - (File: contracts/pool/src/interest.rs)

### Summary
CVE-2017-16879 is a crash/code-execution via a crafted input overflowing a fixed-size buffer. The analog on Soroban is an unprivileged-triggered arithmetic overflow that aborts execution. XOXNO Lending's index accrual has a known value-domain cliff: when a market's scaled debt book times its borrow index approaches `i128::MAX` (RAY-scaled values), the multiplication inside accrual panics with `MathOverflow`. Because every pool verb accrues first via `global_sync`, one overflowing accrual permanently freezes the market — no repay, no withdraw, no liquidation, no further index updates.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs:20` runs `accrue_chunk` for every elapsed-time window before any user operation proceeds. `accrue_chunk` calls `accrue_step`, which computes debt and supply values through `scaled_to_original` (`contracts/pool/src/cache/scale.rs:23-24`, wrapped in `Ray::mul` → `mul_div_half_up` in `common/src/math/fp_core.rs:108`). Those helpers panic with `GenericError::MathOverflow` when `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`.

`update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (`common/src/rates/index.rs:13-19`), but that cap only bounds the *index* — the *value* `scaled_shares × index` can cross the `i128` ceiling long before the index cap engages. The repository's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`) demonstrates this: at ~98% utilization on a steep rate curve, `update_indexes` begins failing with `MathOverflow`, after which `try_withdraw` and `try_repay` on the same market fail identically, and the index cap never engages.

The trigger entrypoints are permissionless: `controller::update_indexes` (or any verb that accrues — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`) on a market whose book has drifted into the overflow region.

### Impact Explanation
Permanent freezing of funds. Once `scaled_to_original` overflows during `global_sync`, every subsequent call on that market reverts at the accrual step, so suppliers can never withdraw, borrowers can never repay, and liquidators can never liquidate. All tokens held by the pool for that market are locked indefinitely, and accrued-but-uncollected protocol revenue is frozen too.

### Likelihood Explanation
Requires a market whose RAY-scaled debt book approaches `i128::MAX` — i.e., a very large book (on the order of the supply cap for a high-decimal asset) held at high utilization for a sustained period on the steep part of the rate curve, as demonstrated in the harness test (caps had to be lifted and ~98% utilization sustained for the cliff to arrive within 40 years). The overflow itself is deterministic once state drifts there; no privileged action is needed to trigger the freeze since `update_indexes` is callable by anyone. The setup cost (whale-scale supply/borrow) bounds likelihood, so this is a Medium-severity condition rather than a near-term exploit, but the failure mode is permanent.

### Recommendation
Before panic-prone unscaling, guard accrual: compute `borrowed * new_borrow_index` via `try_mul_div_half_up`/`I256` and clamp the effective index (or scaled totals) so the value-domain ceiling is never crossed, mirroring how `update_borrow_index` clamps `MAX_BORROW_INDEX_RAY`. Alternatively, when the product would overflow, freeze interest growth (hold `last_timestamp` advance) while still allowing exits, so repay/withdraw/liquidate remain reachable even at the domain boundary. Also correct the bound documented in `docs/reference/formulas.md`, which the test notes is wrong about when the cliff is reached.

### Proof of Concept
Reproduced by the in-repo harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`:

```rust
// 18-decimal market on the steep (XLM) curve, 98% utilization.
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);

// Advance years; permissionless update_indexes eventually panics.
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// -> Error(Contract, MathOverflow) while borrow_index < MAX_BORROW_INDEX_RAY

// Market is frozen: every verb accrues first and hits the same panic.
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

The panic originates in `Ray::mul` → `mul_div_half_up` (`common/src/math/fp_core.rs:108-118`) invoked from `scaled_to_original` during `accrue_step`, reached by `global_sync` (`contracts/pool/src/interest.rs:20-53`).
