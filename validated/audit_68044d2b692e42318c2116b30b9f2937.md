### Title
Webhook signature verification resolves a different (secret-less) organization than the one whose repository the handler writes to - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#repository_owner` falls back to `params.dig('organization','login')` when `repository.owner.login` is absent, so an attacker can pick any organization name for signature verification while the event's `repository.full_name` (used later by handlers such as `CheckSuiteHandler`) still refers to an arbitrary victim repository. If the org chosen for verification has no `webhook_secret` configured, `GitHubApp#verify_webhook_signature` returns `true` unconditionally, bypassing HMAC verification entirely.

### Finding Description
Binding claimed: `org_used_for_signature_verification == org_owning_repository.full_name_used_by_handler`.

- `repository_owner` is computed purely from attacker-supplied JSON: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) .
- `verify_signature` uses only this value to fetch the `GitHubApp` instance and check the HMAC: `github_app = Shipit.github(organization: repository_owner)` then `github_app.verify_webhook_signature(...)` [2](#0-1) .
- `verify_webhook_signature` short-circuits to `true` when the resolved org has no configured secret: `return true unless webhook_secret` [3](#0-2) .
- `CheckSuiteHandler#process` never re-derives or checks `repository_owner`; it only reads `params.check_suite.head_branch` / `head_sha` and matches against `stacks` (a scope presumably derived from the payload's `repository.full_name`), completely decoupled from whatever org was used in `verify_signature` [4](#0-3) .

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: check_suite`, body omitting `repository.owner.login` but including `organization.login = "no-secret-org"` (an org with no `webhook_secret` in Shipit config) and `repository.full_name = "victim-org/repo"`. `repository_owner` resolves to `"no-secret-org"`, `verify_webhook_signature` returns `true` because that org's `webhook_secret` is `nil`, and the request proceeds to `CheckSuiteHandler`, which acts on stacks/commits belonging to `victim-org/repo` — a repository whose actual owning organization was never authenticated.

Why guards fail: `drop_unhandled_event` only checks that a handler for the event exists; it performs no repository/org binding check [5](#0-4) . `verify_signature` and the handler dispatch (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`) never cross-check that the org resolved for signature verification actually owns the repository named in `params['repository']['full_name']` [6](#0-5) .

### Impact Explanation
An attacker with no Shipit credentials can forge a `check_suite` webhook for any repository/organization pair, as long as some organization configured in Shipit has no `webhook_secret` set. This lets them trigger `schedule_refresh_check_runs!` on commits belonging to a stack for a completely different, victim organization's repository, with a forged/unauthenticated payload — an authentication bypass with a write against a repository that never authenticated the request. This matches the Critical category "a payload for one repository mutating another's stack/commit" and "authentication bypass (forged webhook accepted)".

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one configured GitHub organization with no `webhook_secret` set (a real-world common misconfiguration, e.g., during onboarding or for orgs relying solely on IP allowlisting). Given that, the attack costs a single unauthenticated HTTP POST with a crafted JSON body — no secrets, sessions, or GitHub App keys are required. It is fully repeatable against any repository/stack whose `full_name` the attacker knows, for as long as one secret-less org exists in the Shipit config.

### Recommendation
Do not silently accept an organization with no configured `webhook_secret` as an implicit verification bypass; require signature verification to fail (or explicitly configure a secret) for all onboarded organizations. Additionally, bind signature verification's resolved organization to the org that actually owns `params['repository']['full_name']`/`params['repository']['owner']['login']` — reject any event where the two diverge, rather than allowing `organization.login` to substitute a different, potentially secret-less org just because `repository.owner.login` was omitted.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (concept)
test "check_suite webhook with organization fallback bypasses signature check for a different repository" do
  # Org A has no webhook_secret configured
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(
    Shipit::GitHubApp.new('no-secret-org', {}) # no :webhook_secret key
  )

  victim_stack = shipit_stacks(:shipit) # belongs to repository 'victim-org/repo'
  victim_commit = victim_stack.commits.create!(sha: 'a' * 40, branch: victim_stack.branch)

  payload = {
    organization: { login: 'no-secret-org' },       # used for signature verification (secret-less)
    repository: { full_name: 'victim-org/repo' },    # owner.login deliberately omitted
    check_suite: { head_sha: victim_commit.sha, head_branch: victim_stack.branch }
  }.to_json

  post :create, body: payload, params: {},
       headers: { 'X-Github-Event' => 'check_suite', 'X-Hub-Signature' => 'sha1=deadbeef' }

  assert_response :ok # verify_signature passed with a bogus signature
  # assert victim_commit.reload got scheduled for refresh despite no valid HMAC for its real org
end
```
Both sides of the binding: `repository_owner` resolves to `'no-secret-org'` (used in `verify_signature`), while `CheckSuiteHandler` acts on `victim-org/repo`'s stack/commit — the two orgs differ, proving the equality claimed in the question is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
