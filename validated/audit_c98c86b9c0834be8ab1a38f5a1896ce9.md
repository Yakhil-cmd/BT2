This confirms the multi-organization deployment model: `Shipit.github_organizations` lets a single Shipit instance host multiple GitHub App configs, one per organization key in `secrets.github`, each with its own `webhook_secret` [1](#0-0) . `WebhooksController#verify_signature` selects which organization's secret to check against based solely on `repository_owner`, which is read from `params.dig('repository','owner','login')` (or `organization.login`) in the untrusted JSON body [2](#0-1) [3](#0-2) . Once the HMAC check passes, `create` dispatches the full `params` hash unchanged to the event handlers [4](#0-3) . Every handler resolves the target `Stack`/`Repository` from a *different* field of the same body — `payload.dig('repository', 'full_name')` — via `Handler#repository_name`/`#stacks` [5](#0-4) , and this pattern repeats in `PushHandler#process` [6](#0-5)  and every PullRequest handler (`OpenedHandler`, `ReopenedHandler`, `ClosedHandler`, `LabelCapturingHandler`, etc.) [7](#0-6) [8](#0-7) . Nothing cross-checks that `repository.full_name`'s owner matches `repository.owner.login`/`organization.login` used to select the verification secret.

### Title
Webhook signature is verified against `repository.owner.login`'s GitHub App secret while handlers act on the independent, unverified `repository.full_name` field, enabling cross-organization stack forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
On a multi-tenant Shipit instance (multiple organizations configured under `secrets.github`, each with its own GitHub App/`webhook_secret`), the HMAC signature check binds trust to `repository.owner.login` (or `organization.login`), but the event handlers that actually mutate state key off `repository.full_name`, a sibling field in the same untrusted JSON body that is never covered by that binding.

### Finding Description
`Shipit.github_organizations` shows Shipit supports several organizations, each resolved to its own `GitHubApp` (and thus its own `webhook_secret`) via `Shipit.github(organization:)` [9](#0-8) . `WebhooksController#verify_signature` picks the app/secret with `Shipit.github(organization: repository_owner)`, where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [10](#0-9) [3](#0-2) . After the HMAC passes, the raw, unfiltered `params` are handed to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) . Every handler independently looks up the target `Repository`/`Stack` using `payload.dig('repository', 'full_name')` — a field never used or constrained during signature verification — through `Handler#repository_name` [5](#0-4) , `PushHandler#process` [6](#0-5) , and the PullRequest handlers' `#repository` methods (e.g. `OpenedHandler`, `ReopenedHandler`, `ClosedHandler`, `LabelCapturingHandler`) [7](#0-6) [8](#0-7) [11](#0-10) .

The binding that should hold is:
`organization whose secret authenticated the request == owner of the repository the handler mutates`

but the engine actually enforces only:
`organization(params.repository.owner.login) == secret-holder`, `Repository/Stack lookup key = params.repository.full_name` — two independent, unauthenticated fields.

An operator of any single legitimate organization onboarded to the same Shipit instance (i.e., someone who has a genuine, working GitHub App installation and thus knows/controls the real webhook payloads and signature for their own org, `org-attacker`) can:
1. Capture or reconstruct a valid `X-Hub-Signature` for a JSON body whose `repository.owner.login`/`organization.login` is `org-attacker` (satisfies `verify_signature` using `org-attacker`'s own real `webhook_secret`).
2. Set `repository.full_name` in that same body to `org-victim/some-repo` — a repository belonging to a completely different, unrelated tenant organization on the same Shipit instance.
3. Since handler dispatch never re-validates that `full_name`'s owner matches the authenticated `repository_owner`, the forged event is processed against `org-victim`'s `Stack`.

### Impact Explanation
This breaks the tenant isolation boundary of a multi-organization Shipit deployment. Depending on webhook event forged:
- `push` events (`PushHandler`) can trigger `stack.sync_github(expected_head_sha:)` for a victim-org stack with an attacker-chosen `after` SHA, which is used later as an authoritative revision reference for deploy eligibility checks — an unauthorized cross-repository state write.
- `pull_request` events can create, archive, or unarchive review stacks (`OpenedHandler#process` → `ReviewStackAdapter.find_or_create!`, `ClosedHandler#process` → `review_stack.archive!`, `ReopenedHandler#process` → `stack.unarchive!`) belonging to the victim org, causing unauthorized provisioning/deprovisioning of infrastructure tied to `org-victim`'s repository.

This lands in the "cross-repository writes" / "unauthorized deploy" category since state belonging to one tenant's repository is mutated using another tenant's authentication credential.

### Likelihood Explanation
Requires the Shipit instance to be configured for multiple organizations (the `secrets.github` keyed-by-org schema) and requires the attacker to already be a legitimate, onboarded tenant with a working GitHub App installation for their own org (so they can produce validly-signed payloads). This is a real, supported deployment topology per `docs/setup.md` and `lib/shipit.rb`'s `github_organizations`/`github_app_config` methods, but it is not the single-org default. Exploitation needs no additional secrets beyond what the attacker's own org already legitimately possesses.

### Recommendation
In `WebhooksController#create`/`verify_signature`, or in the shared `Handlers::Handler` base class, enforce that the `repository.full_name`'s owner segment matches the `repository_owner` (or `organization.login`) that was used to select and validate the HMAC secret, rejecting (422) any payload where the two diverge, before any handler is invoked.

### Proof of Concept
Not independently executable from the index alone since it requires a live multi-org Shipit deployment; conceptually:
```
POST /webhooks
X-Github-Event: pull_request
X-Hub-Signature: sha1=<valid HMAC over BODY using org-attacker's real webhook_secret>

BODY (org-attacker signs, but full_name targets org-victim):
{
  "action": "opened",
  "repository": { "owner": { "login": "org-attacker" }, "full_name": "org-victim/production-app" },
  "pull_request": { ... },
  "sender": { "login": "org-attacker-user" }
}
```
`verify_signature` resolves `Shipit.github(organization: "org-attacker")` and validates successfully [10](#0-9) ; `OpenedHandler#repository` then resolves `Shipit::Repository.from_github_repo_name("org-victim/production-app")` and provisions/mutates a review stack belonging to `org-victim` [12](#0-11) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",

      ].join(' '))
    end
