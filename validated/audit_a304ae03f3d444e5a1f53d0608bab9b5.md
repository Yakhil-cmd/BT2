### Title
Unrestricted SSRF in arbiter/arbstore HTTP client (no host/IP filtering, IPv4/IPv6 unrestricted) - (File: arbiters.js, arbiter_contract.js)

### Summary
The wallet's arbiter-contract subsystem builds outbound HTTP(S) requests to an `arbstore_url` that is ultimately tied to an `arbiter_address` chosen by a private-payment counterparty (the peer that proposes an arbiter contract), and performs the requests with Node's raw `http`/`https` clients with no validation of the resolved host, IP range, or protocol — the same bug class as the AutoGPT `Send Web Request` SSRF (unfiltered destination, including IPv6/loopback/link-local targets).

### Finding Description
`arbiters.js` exposes `getInfo()`/`getArbstoreInfo()`, which take an `arbiter_address` (attacker-controllable value that a peer places in an `arbiter_contract_offer` device message, see `createAndSend` in [1](#0-0) ), look up an `arbstore_url` associated with that address via the hub, and then issue a raw `https.get(url, ...)` request with `requestInfoFromArbStore`: [2](#0-1) 

The only validation performed on the URL before the request is that it is a "non-empty string" (`validationUtils.isNonemptyString(url)`), not that it targets a permitted network range: [3](#0-2) 

Similarly, `arbiter_contract.js` builds POST requests to the same class of attacker/hub-supplied host using Node's `http.request` with zero destination filtering: [4](#0-3) 

This function is called from `getArbstoreAddresses`, `openDispute`, `appeal`, and `getAppealFee` — all reachable from normal wallet flows once a peer (private-payment counterparty) has proposed/participated in an arbiter contract naming an arbiter address that resolves (via the arbstore directory record on the hub) to an attacker-controlled URL: [5](#0-4) [6](#0-5) 

Because an arbiter's `arbstore_url` is whatever the arbiter (or whoever controls that arbiter address's hub record) chooses to publish, any user can act as their own "arbiter" and register an arbstore URL pointing to an internal address (e.g. `http://[::1]`, `http://169.254.169.254`, `http://127.0.0.1`, or any RFC1918/link-local/IPv6 host) with no restriction in the client code that consumes it — mirroring the exact root cause of CVE-2025-22603 (IPv6/private destinations not filtered in the outbound web-request block).

### Impact Explanation
A malicious arbiter/counterparty can cause a victim's Obyte wallet node to issue outbound HTTP(S) requests to arbitrary internal or link-local/IPv6 addresses whenever the victim views arbiter info, opens a dispute, requests an appeal fee, or appeals a contract. This can be used to probe/interact with internal services reachable from the node's network (cloud metadata endpoints, internal admin panels, other local services), and the parsed JSON response is partially surfaced back to the caller (`cb(null, info)` / `cb(null, resp)`), which can leak internal-service response content to the attacker-influenced code path. This is a server-side request forgery with real internal-network exposure, matching Medium severity of the analog CVE.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the victim to interact with an arbiter-contract flow (view arbiter info, open a dispute, or check the appeal fee) involving an arbiter address that the attacker controls or has registered an arbstore URL for. No hub compromise or man-in-the-middle is required — the attacker only needs to act as (or impersonate) an arbiter in a normal contract flow, a legitimate/unprivileged interaction supported by the wallet.

### Recommendation
Before issuing any outbound request in `arbiters.js`/`arbiter_contract.js`, resolve and validate the target host: reject loopback, private (RFC1918), link-local, and IPv6 unique-local/loopback/link-local addresses, and re-validate the resolved IP (not just the hostname) to prevent DNS-rebinding, matching the fix pattern applied in the referenced AutoGPT commit.

### Proof of Concept
1. Attacker registers as an arbiter on a hub, publishing `arbstore_url = "http://[::1]:6611"` (or another internal service address) for their `arbiter_address`.
2. Attacker proposes/participates in an arbiter contract with the victim, referencing that `arbiter_address` (`arbiter_contract.js:createAndSend`).
3. When the victim's wallet calls `arbiters.getInfo(arbiter_address, cb)` (e.g., to show arbiter details) or later calls `openDispute`/`appeal`/`getAppealFee`, the code fetches `arbstore_url + '/api/...'` via `requestInfoFromArbStore`/`httpRequest` with no host restriction, causing the victim's node to send an authenticated-looking request to the internal target and return its response to the attacker-influenced arbiter-info flow.

*Note:* I could not find any host/IP allow-list or SSRF-guard utility elsewhere in the indexed codebase for these two files; if one exists outside the indexed portions, it was not found by search.

function httpRequest(host, path, data, cb) {
	var reqParams = Object.assign(url.parse(host),
		{
			path: path,
			method: "POST",
			headers: {
				"Content-Type": "application/json",
				"Content-Length": (new TextEncoder().encode(data)).length
			}
		}
	);
	var req = http.request(
		reqParams,
		function(resp){
			var data = "";
			resp.on("data", function(chunk){
				data += chunk;
			});
			resp.on("end", function(){
				try {
					data = JSON.parse(data);
					if (data.error) {
						return cb(data.error);
					}
					cb(null, data);
				} catch (e) {
					cb(e);
				}
			});
		}).on("error", cb);
	req.write(data);
	req.end();
}

function getInfo(address, cb) {
	cb = cb || function() {};
	db.query("SELECT device_pub_key, real_name FROM wallet_arbiters WHERE arbiter_address=?", [address], function(rows){
		if (rows.length && rows[0].real_name) { // request again if no real name
			cb(null, rows[0]);
		} else {
			device.requestFromHub("hub/get_arbstore_url", address, function(err, url){
				if (err) {
					return cb(err);
				}
				if (!validationUtils.isNonemptyString(url))
					return cb("invalid url received from hub");
				requestInfoFromArbStore(url+'/api/arbiter/'+address, function(err, info){
					if (err) {
						return cb(err);
					}
					if (!validationUtils.isNonemptyObject(info))
						return cb("invalid arbiter info received from arbstore");
					db.query("REPLACE INTO wallet_arbiters (arbiter_address, device_pub_key, real_name) VALUES (?, ?, ?)", [address, info.device_pub_key, info.real_name], function() {cb(null, info);});
				});
			});
		}
	});
}

function requestInfoFromArbStore(url, cb){

				cb(ex);
			}
		});
