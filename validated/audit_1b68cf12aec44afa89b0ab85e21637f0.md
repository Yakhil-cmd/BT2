### Title
`swap_debt` borrows the replacement asset without enforcing the spoke-asset halt/borrowable gates that `borrow` applies - (File: contracts/controller/src/strategies/swap_debt.rs)

### Summary
The n8n bug class is "a secondary/hidden code path that performs the same privileged operation while skipping a restriction enforced on the primary path." In XOXNO Lending the primary borrow path (`borrow` → `process_borrow`) gates each leg through `validate_position_entry_gates` → `require_can_borrow`, which enforces the listing's `paused`, `frozen` and `is_borrowable` flags via `require_listed_unhalted_config` and `FreezePolicy::BlockOnEntry`. The strategy entrypoint `swap_debt` mints a brand-new borrow position in `new_debt` through the shared `borrow_into_controller` leg helper, but neither `swap_debt.rs` nor `legs.rs` contains any flag or borrowability check — those functions live only in `positions/mod.rs` and `positions/debt.rs`, which the strategy path does not invoke for the borrow leg.

### Finding Description
`swap_debt` lets an account owner (or delegate) replace `existing_debt` with `new_debt` by borrowing `amount` of `new_debt`, swapping it into `existing_debt` and repaying the old position (`contracts/controller/src/lib.rs:258-278`). On the canonical `borrow` path, every borrowed asset must pass `require_can_borrow`, which requires an active hub, an active listing, `!paused`, `!frozen`, and `is_borrowable` (`contracts/controller/src/positions/mod.rs:188-213`, flag enforcement at `264-278`). In `swap_debt.rs` the only pre-validations are authorization and accounting; the new debt leg is created by `borrow_into_controller`, whose flag/borrowability gating is not present in `strategies/legs.rs` — the only cap still applied is the spoke borrow cap via `apply_leg_usage`/`UsageSide::Borrow` inside the debt merge (`contracts/controller/src/positions/mod.rs:101-127`, `contracts/controller/src/spoke_usage.rs:102-115`).

The result: an asset governance explicitly marked `can_borrow = false` (collateral-only listing), or emergency-halted via `paused`/`frozen`, can still be drawn out of the pool as fresh debt through `swap_debt` — a restriction the regular `borrow` entrypoint enforces is silently bypassed by the strategy path, exactly matching the hidden-option bypass shape of the n8n advisory.

### Impact Explanation
`is_borrowable = false` and the `paused`/`frozen` flags are the protocol's tools for ring-fencing assets that must never leave the pool as debt (e.g., collateral-only listings without liquidation-fee/price-stack suitability, or markets halted under incident response). A user holding any existing debt position can call `swap_debt` and pull liquidity of such an asset into a new debt position, keeping only the residual swapped value. This converts pool liquidity that governance intended to be non-borrowable into open debt — direct removal of suppliers' funds under a flag that is supposed to forbid it — satisfying "theft of user funds" and contributing to protocol insolvency if the borrowed asset cannot be safely liquidated.

### Likelihood Explanation
Reachable by any account owner or delegate with an existing debt position and a viable swap route; both conditions are user-controlled (the route venues are unallowlisted by design). It requires only that a spoke asset exist with `can_borrow = false` or a halt flag set — a routine configuration state (`upsert_spoke_asset` permits `can_borrow=false` listings, and flags ratchet via `set_spoke_asset_flags`/`edit_asset_in_spoke`, `contracts/controller/src/config/asset.rs:79-95`). No privileged access, timing race, or oracle manipulation is needed.

### Recommendation
In `swap_debt` (and audit `multiply`, `flash_position` and `migrate_from_blend`, which share `borrow_into_controller` — `flash_position.rs:59-91` checks `is_flashloanable` but shows no spoke-asset flag check on `debt`), call `require_can_borrow(env, &mut cache, account.spoke_id, new_debt)` before the borrow leg, or move the `require_can_borrow`/flag enforcement into `borrow_into_controller` itself so every path that mints debt inherits the halt and borrowability gates uniformly.

### Proof of Concept
1. Governance lists asset `C` in a spoke with `can_collateral = true`, `can_borrow = false` (collateral-only; `borrow` on `C` reverts via `require_can_borrow` → `AssetNotBorrowable`).
2. Attacker supplies collateral and borrows borrowable asset `X` normally, creating an `existing_debt = X` position.
3. Attacker calls `swap_debt(caller, account_id, existing_debt = X, amount, new_debt = C, swap = <route C→X>)`. The controller borrows `amount` of `C` into the controller, the router swaps `C → X`, and the proceeds repay the `X` debt.
4. Final state: the attacker owes `C` — a debt that `borrow` would have refused to open — and the pool's `C` liquidity has been drawn down. The post-flow solvency check (`strategy_finalize`) passes if HF ≥ 1, so the bypassed borrowability flag is the only gate that was skipped.

The same pattern applies to a `paused` or `frozen` spoke asset: `FreezePolicy::BlockOnEntry` is enforced inside `require_listed_unhalted_config`, which `swap_debt` never reaches for the new-debt leg, so an emergency-halted market can still be borrowed against through the swap-debt path.
