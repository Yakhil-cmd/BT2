### Title
Membership webhooks are accepted without any signature check whenever an organization has no `webhook_secret` configured, letting a forged `membership` event grant arbitrary `Shipit.github_teams` access - ([File: lib/shipit/github_app.rb], [File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`GitHubApp#verify_webhook_signature` fails open: if the organization's `webhook_secret` is blank, it returns `true` unconditionally, so any POST to `/webhooks` claiming that organization is accepted with no cryptographic check. `MembershipHandler#process` then blindly trusts the payload's `team.id`/`organization.login`/`member.login` and calls `team.add_member(member)`, so an attacker can grant a real (attacker-controlled) `User` a `Membership` in a team already resolved by `Shipit.github_teams`, with no actual GitHub team membership ever existing.

### Finding Description
Binding as claimed: `verified_organization == team.organization` (the org whose secret gated the webhook equals the org that owns the privileged oauth team). Trace:

- `WebhooksController#verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(...)`, `head(422)` only when `verified` is falsy. [1](#0-0) 
- `GitHubApp#verify_webhook_signature` returns `true` unless `webhook_secret` is present for that organization's config, i.e. it fails open for any organization that has no `webhook_secret` set. [2](#0-1) 
- `MembershipHandler#process` then does `team = find_or_create_team!` (matched/created purely from `params.team.id` / `params.organization.login`, no GitHub cross-check) and `member = User.find_or_create_by_login!(params.member.login)`, then unconditionally calls `team.add_member(member)` on `'added'`. [3](#0-2) 
- `Team.add_member` simply appends the membership row with no GitHub-side verification of team membership. [4](#0-3) 
- `Shipit.github_teams` resolves oauth-configured teams by handle and is what `User#authorized?` checks membership against. [5](#0-4) [6](#0-5) 

Exploit flow: an attacker sends `POST /webhooks` with `X-Github-Event: membership`, a JSON body with `organization.login` set to a target org whose Shipit config has no `webhook_secret`, `team.id` equal to the `github_id` of a `Team` row already tied into `Shipit.github_teams` (created at boot via `Team.find_or_create_by_handle`), `action: "added"`, and `member.login` set to the attacker's own GitHub username. Signature verification passes unconditionally because `webhook_secret` is blank for that org. `find_or_create_team!` finds the existing `Team` by `github_id` (no re-write of `organization` on find), `User.find_or_create_by_login!` creates/looks-up the attacker's real `User` row (via a real GitHub API lookup of that login, so it's a legitimate GitHub account, just not a member of the team), and `team.add_member(member)` writes the `Membership` row. The attacker then completes a normal OAuth login and `authorized?` now returns `true` for a team they never joined on GitHub. `drop_unhandled_event`/`check_if_ping` do not block `membership` events, and no other guard revalidates team membership against GitHub.

### Impact Explanation
This is an authentication/authorization bypass: an unprivileged GitHub user with no Shipit session, token, or secret can escalate into `Shipit.github_teams`-derived authorization for any organization configured without a `webhook_secret`, satisfying `require_permission!`/`authorized?` checks used to gate stack access. It is repeatable against any team whose `github_id` is guessable/known and any target organization lacking `webhook_secret`, and the created `Membership` persists until manually removed or a `removed` event overwrites it - meaning the compromise is durable, not just per-request.

### Likelihood Explanation
The precondition is that the target organization's Shipit config omits `webhook_secret` (a real, plausible operational gap since it's an optional-looking field defaulting to fail-open rather than fail-closed). No GitHub secret, private key, or Shipit credential is required from the attacker; they only need to know/guess a `team.id` (a GitHub team's numeric ID, which is often discoverable) and their own login. The attack is a single unauthenticated HTTP POST, trivially repeatable.

### Recommendation
Make `GitHubApp#verify_webhook_signature` fail closed when no `webhook_secret` is configured (reject the webhook / require an explicit opt-in for unsigned orgs) instead of `return true unless webhook_secret`. Additionally, `MembershipHandler` should not fully trust `team.id`/`organization.login`/`member.login` from the payload alone - cross-check against `Shipit.github_teams` configuration (organization/slug match) and, ideally, verify membership via the GitHub API before calling `team.add_member`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual, not to be placed under excluded test/ path in production fix,
# but illustrates the assertions needed)
test "membership webhook is accepted with no signature when org has no webhook_secret" do
  # Arrange: configure org "acme" with no webhook_secret, and a Team row with github_id 42
  # tied into Shipit.github_teams (organization: "acme", slug: "core").
  team = shipit_teams(:acme_core) # github_id: 42, organization: "acme"

  payload = {
    action: "added",
    team: { id: 42, name: "Core", slug: "core", url: "https://api.github.com/teams/42" },
    organization: { login: "acme" },
    member: { login: "attacker-handle" }
  }.to_json

  # Act: no X-Hub-Signature header at all
  post "/webhooks", params: payload, headers: { "X-Github-Event" => "membership", "CONTENT_TYPE" => "application/json" }

  assert_response :ok

  # Assert broken binding: verified_organization ("acme", unsigned) == team.organization ("acme")
  attacker = Shipit::User.find_by(login: "attacker-handle")
  assert attacker.present?
  assert team.members.include?(attacker)

  # Assert authorization escalation
  assert attacker.authorized?, "attacker should not be authorized without real GitHub team membership"
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action

          when 'removed'
