### Title
Cross-organization PullRequest metadata overwrite via mismatched webhook signing-org vs. payload `repository.full_name` - ([File: app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the HMAC secret to validate a webhook using `repository.owner.login` from the raw JSON body, while `AssignedHandler#repository`/`AssignedHandler#pull_request` resolve the target `Shipit::Repository`/`Shipit::PullRequest` using the independent `repository.full_name` field from the same body. Nothing cross-checks that these two attacker-supplied fields refer to the same organization, so a webhook correctly signed with an attacker-controlled org's secret can still target and overwrite a victim org's `PullRequest#github_pull_request`.

### Finding Description
The broken binding, stated as an equality that the code must (but does not) enforce:

`org_that_signed_the_request (derived from params.dig('repository','owner','login') in WebhooksController#repository_owner, used to pick the webhook_secret) == org_owning_the_repository_whose_PullRequest_is_mutated (derived from params.repository.full_name in AssignedHandler#repository / AssignedHandler#pull_request)`

Code path:
- `Shipit::WebhooksController#verify_signature` picks the app/secret via `Shipit.github(organization: repository_owner)` and validates `X-Hub-Signature` against `request.raw_post` using that org's `webhook_secret` [1](#0-0) . `repository_owner` is read straight from the attacker-controlled JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [2](#0-1) .
- `verify_webhook_signature` is a plain per-organization HMAC check: `OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message)` against that org's configured secret [3](#0-2) .
- Once signature verification passes, the raw body is dispatched to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `AssignedHandler`'s `params` schema only requires `repository.full_name`; it never requires or validates `repository.owner.login` against anything [5](#0-4) .
- `AssignedHandler#repository` resolves the target repository purely from that same `full_name` field: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) .
- `AssignedHandler#pull_request` then finds the real `Shipit::PullRequest` joined through `stack: :repository` on that resolved repository's id and the attacker-chosen `number` [7](#0-6) .
- `AssignedHandler#process` unconditionally overwrites it: `pull_request.update(github_pull_request: params.pull_request) if pull_request.present?` [8](#0-7) , with `params.pull_request` being fully attacker-fabricated JSON (title, head.sha, assignees, labels, etc.) per the schema [9](#0-8) .

Root cause: signature verification authenticates *that the request was signed by some org registered in Shipit*, not *that the org signing it is the org named in the payload's `repository.full_name`*. `repository.owner.login` (used to pick the verification secret) and `repository.full_name` (used to pick the mutated record) are two independently attacker-controlled fields of the same JSON body, and no code anywhere compares them.

Attacker request: attacker registers/administers their own repository "attacker-org/attacker-repo" with Shipit (a normal, unprivileged onboarding action fully within the described threat model — configuring a webhook on a repo they own), thereby knowing attacker-org's `webhook_secret`. They then craft a raw JSON body with `repository.owner.login = "attacker-org"` (so the controller looks up and validates against the secret they know) but `repository.full_name = "victim-org/victim-repo"`, `number` equal to a real open PR on a victim stack, `action = "assigned"`, and a fully fabricated `pull_request` object including an arbitrary `head.sha`. They compute `X-Hub-Signature: sha1=HMAC-SHA1(secret_attacker_org, raw_body)` themselves and POST directly to `/webhooks` — no live GitHub or victim secret needed.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type is handled; `verify_signature` validates authenticity of "some org," not consistency between the signing org and the payload's target repo; the `ExplicitParameters` schema for `AssignedHandler` never declares or checks `repository.owner.login`; there is no `force_github_authentication`/`User#authorized?`/`require_permission!` in play since this is an unauthenticated webhook endpoint by design; `Repository`/`Stack` model validations only validate format, not cross-org provenance.

### Impact Explanation
A successful request lets an attacker who controls only their own (attacker-org) GitHub webhook secret overwrite the `github_pull_request` JSON — including `head.sha`, title, assignees, and labels — of any real, open `Shipit::PullRequest` belonging to any other organization onboarded to the same Shipit instance, as long as they know/guess the target repository's `full_name` and an open PR `number` (both are public GitHub information). This is a cross-repository/cross-tenant write ("a payload for one repository mutating another's stack/... task"), matching the Critical severity category in the rules. Because `github_pull_request['head']['sha']` and other fields are consumed by downstream review-stack/merge/deploy logic that trusts this record, this can corrupt commit-status/merge decisions for the victim's stack. The attack is repeatable against any repository/PR number combination and any number of victim tenants sharing the Shipit instance.

### Likelihood Explanation
Preconditions: Shipit must be configured to serve multiple GitHub organizations, each with its own webhook secret looked up via `Shipit.github(organization: repository_owner)` — this is the documented multi-tenant configuration model this engine supports. Attacker cost is low: they only need to operate/administer one onboarded org (already assumed unprivileged-attacker-owned repo/webhook per the threat model) and craft a raw HTTP POST with a valid HMAC computed from their own known secret. No GitHub secrets, Shipit session, or API token are required, and the request can be replayed against arbitrary victim repositories/PR numbers.

### Recommendation
In `AssignedHandler` (and other handlers resolving repositories from body fields), require and verify that `params.repository.owner.login` (or the owner segment parsed from `full_name`) matches the organization that was used to authenticate the webhook signature — pass the verified `repository_owner` from `WebhooksController` through to handlers and assert equality with the resolved repository's organization before performing any lookup or mutation. More generally, `WebhooksController#verify_signature` should bind the verified organization into the request context and every handler should validate `repository.full_name`'s owner segment against it before trusting `full_name` for record resolution.

### Proof of Concept
Under `test/controllers/webhooks_controller_test.rb`-style setup (no live GitHub):
1. Seed two orgs in Shipit's github config: `attacker-org` (secret `SECRET_A`) and `victim-org` (secret `SECRET_V`).
2. Seed `victim_repo = Shipit::Repository.create!(name: 'victim-repo', owner: 'victim-org')`, a `stack` on it, and `pr = Shipit::PullRequest.create!(stack: stack, number: 42, github_pull_request: { 'head' => { 'sha' => 'original_sha' }, ... })`.
3. Build raw JSON body: `{ action: 'assigned', number: 42, repository: { full_name: 'victim-org/victim-repo', owner: { login: 'attacker-org' } }, pull_request: { ..., head: { sha: 'attacker_sha', ref: 'x' }, ... }, sender: { login: 'attacker' } }`.
4. Compute `sig = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', SECRET_A, raw_body)`.
5. POST to `/webhooks` with header `X-Github-Event: pull_request` and `X-Hub-Signature: sig`.
6. Assert response is `200`.
7. Assert `pr.reload.github_pull_request['head']['sha'] == 'attacker_sha'` — proving the victim org's `Repository`/`PullRequest`, never authenticated by `attacker-org`'s signature, was mutated using it.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
