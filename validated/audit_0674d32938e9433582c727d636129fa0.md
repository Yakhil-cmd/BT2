### Title
Webhook signature verification is decoupled from the `repository.full_name` used by handlers, allowing cross-repository `PullRequest` mutation via `EditedHandler` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to verify a webhook with using `repository.owner.login` (or `organization.login`), while every `PullRequest`-related handler (including `EditedHandler`) resolves the target repository/record using the independent, unvalidated `repository.full_name` field. Because nothing enforces that `full_name` belongs to the same owner used for verification, and because `GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for that owner, a payload "verified" under a secret-less/attacker-reachable organization can carry an arbitrary victim `repository.full_name`, causing `EditedHandler#process` to overwrite an existing victim `PullRequest`'s `title`/`state`/other fields.

### Finding Description
The broken binding is:
`verifying_org = params.dig('repository','owner','login') || params.dig('organization','login')` used in `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) is assumed to equal `target_repo_owner = params.repository.full_name.split('/').first` used inside `EditedHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb:63-65). Nothing in the code enforces this equality. [1](#0-0) [2](#0-1) 

`verify_signature` calls `Shipit.github(organization: repository_owner)` and then `github_app.verify_webhook_signature`, which is defined as: [3](#0-2) 

`verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank for that organization's config, i.e. `return true unless webhook_secret`. This means any organization configured in `secrets.github` without a `webhook_secret` (or the single-app config schema, where `Shipit.github(organization:)` ignores the `organization:` argument entirely per `github_default_organization`/`github` in `lib/shipit.rb:170-181` and falls back to the single global `secrets.github` config) allows an attacker to submit an unsigned/arbitrarily-signed webhook that passes `verify_signature`.

Once verification passes, `WebhooksController#create` dispatches the *raw, attacker-controlled* JSON to `Shipit::Webhooks.for_event(event)` handlers unchanged: [4](#0-3) 

`EditedHandler#process` then resolves the target repository purely from `params.repository.full_name`, a field independent of `repository.owner.login` used for signature verification: [5](#0-4) 

If a `PullRequest` exists for that resolved victim repository with a matching `number`, `pull_request.update(github_pull_request: params.pull_request)` is called, and `PullRequest#github_pull_request=` writes `title`, `state`, `additions`, `deletions`, `user`, `assignees`, `labels`, and `head` directly from attacker-supplied payload values: [6](#0-5) 

**Attacker's exact request:** POST `/webhooks` with header `X-Github-Event: pull_request` and JSON body:
```json
{
  "action": "edited",
  "number": <victim_pr_number>,
  "pull_request": {
    "id": 1, "number": <victim_pr_number>, "url": "...", "title": "PWNED",
    "state": "closed", "additions": 0, "deletions": 0,
    "head": {"sha": "<any 40-char sha existing in victim stack>", "ref": "x"},
    "user": {"login": "attacker"}, "assignees": [], "labels": []
  },
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": {"login": "attacker-org-or-secretless-org"}
  },
  "sender": {"login": "attacker"}
}
```
This bypasses `verify_signature` because the owner used for HMAC lookup (`attacker-org-or-secretless-org`) is decoupled from `repository.full_name` (`victim-org/victim-repo`) used by `EditedHandler`. `ExplicitParameters` schema for `EditedHandler` only requires `repository.full_name` (String) - it never cross-checks it against `repository.owner.login` - so this passes validation. `drop_unhandled_event` and `check_if_ping` do not restrict this. `force_github_authentication`, `User#authorized?`, and `require_permission!` are session/API-token guards that are never invoked on this unauthenticated webhook path.

### Impact Explanation
An unauthenticated attacker can overwrite `title`, `state`, `additions`, `deletions`, assigned `user`, `assignees`, `labels`, and `head` commit association of an arbitrary victim `PullRequest` record tied to a repository/stack they do not control, as long as (a) some org known to Shipit lacks a `webhook_secret` (or the deployment uses the single-app config schema without a secret), and (b) a `PullRequest` with the guessed/known `number` already exists for the victim repository. This is a cross-tenant write: one org's "verified" webhook mutates another repository's data, matching the "payload for one repository mutating another's stack/commit/task" Critical category. It is repeatable for any PR number/repo combination and does not require any secret, session, or API token.

### Likelihood Explanation
Requires: (1) a Shipit deployment where at least one configured GitHub organization has no `webhook_secret` set (a documented, valid, non-default configuration per `docs/setup.md`/`config/secrets.development.example.yml`, though out of scope to cite) — or single-app config mode without a secret; (2) knowledge of a target repository's `full_name` (public info) and an existing/guessable PR `number` (small integers, easily brute-forced or observed publicly on GitHub). No GitHub credentials, Shipit session, or API token needed. Attacker cost is a single unauthenticated HTTP POST. This is feasible and repeatable but conditioned on a specific webhook-secret misconfiguration that is a supported code path, not merely a hypothetical.

### Recommendation
Enforce that the organization used to verify the webhook signature matches the owner embedded in the same payload's `repository.full_name` (reject mismatches), and additionally require `Shipit.github(organization:).webhook_secret` to be present for any organization allowed to send webhooks (fail closed instead of `return true unless webhook_secret`). At minimum, in `WebhooksController#verify_signature`, derive/validate `repository_owner` consistently from `repository.full_name` rather than `repository.owner.login`, and have `GitHubApp#verify_webhook_signature` reject (not accept) when no secret is configured.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "edited webhook from secret-less org cannot mutate another repo's PullRequest" do
  victim_pr = shipit_pull_requests(:review_stack_review) # belongs to victim repo/stack
  original_title = victim_pr.title

  # Simulate an org with no webhook_secret configured (or single-app mode w/o secret)
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(
    Shipit::GitHubApp.new('attacker-org', {}) # no webhook_secret
  )

  payload = {
    action: 'edited',
    number: victim_pr.number,
    pull_request: {
      id: victim_pr.github_id, number: victim_pr.number, url: 'https://api.github.com/x',
      title: 'PWNED', state: 'closed', additions: 0, deletions: 0,
      head: { sha: victim_pr.head.sha, ref: 'x' },
      user: { login: 'attacker' }, assignees: [], labels: []
    },
    repository: {
      full_name: victim_pr.stack.repository.full_name, # victim repo
      owner: { login: 'attacker-org' } # decoupled owner used only for verification
    },
    sender: { login: 'attacker' }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  post :create, body: payload, as: :json

  # Binding assertion: repo used for verification ("attacker-org") != repo owning the mutated record
  assert_not_equal 'attacker-org', victim_pr.stack.repository.owner

  victim_pr.reload
  assert_equal original_title, victim_pr.title, "victim PullRequest.title must not change from attacker-controlled, mismatched-org payload"
end
```
This test asserts both sides of the equality (`verifying_org` vs `target_repo_owner`) diverge and that, before the fix, `victim_pr.title` becomes `"PWNED"` despite the webhook being "verified" under an unrelated organization — demonstrating the cross-repository write.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
