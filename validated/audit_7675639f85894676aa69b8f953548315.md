### Title
Unprotected `InitializeNonceAccount` instruction allows front-running of nonce account authority, enabling unauthorized fund withdrawal - (File: `programs/system/src/system_instruction.rs`)

### Summary
`initialize_nonce_account` in the System program sets a caller-supplied `nonce_authority` on any writable, uninitialized, system-owned account without requiring that account's key to sign the instruction, unlike every other nonce-mutating instruction in the same module. This mirrors the reported Solidity bug class of an `initialize()` function lacking access control, letting an attacker front-run the legitimate initializer and seize authority (ownership) of the account.

### Finding Description
`initialize_nonce_account` only checks that the target account is writable before writing an arbitrary `nonce_authority` into its state: [1](#0-0) 

No signer check is performed on the account being initialized, and the dispatch path in `system_processor.rs` passes the attacker-controlled `authorized` argument straight through without any additional authorization check: [2](#0-1) 

This is inconsistent with the rest of the nonce instruction set, which does require signer checks tied to the current authority/account key, e.g. `withdraw_nonce_account`'s `check_signer` calls and `advance_nonce_account`'s `signers.contains(&data.authority)` check: [3](#0-2) [4](#0-3) 

Because the runtime only requires an account to be listed as writable (not signed) for a program that already owns it to mutate its data, any unprivileged transaction can name a target pubkey as a writable account in a `SystemInstruction::InitializeNonceAccount` instruction. If that account is owned by the System program, sized for `nonce::State`, funded to the rent-exempt minimum, and still in `State::Uninitialized`, the transaction succeeds and sets the attacker's chosen key as `nonce_authority` — with zero involvement of the account's actual keyholder. Any legitimate multi-step nonce setup (allocate/fund in one transaction, initialize in a later one) creates exactly this window, letting an observer front-run the rightful owner's `InitializeNonceAccount` transaction.

### Impact Explanation
Once the attacker's key is set as `nonce_authority`, they satisfy the signer checks in `withdraw_nonce_account` and can drain the account's lamports to an address of their choosing: [5](#0-4) 

This is a concrete unsigned/unauthorized fund movement: lamports deposited by a legitimate user end up withdrawable by an attacker who never held the private key for that account, purely by racing the initialization step.

### Likelihood Explanation
Exploitation requires only a public mempool observation and a single ordinary transaction; no special privileges, leader access, or malicious validator behavior are needed. The precondition (an uninitialized, rent-exempt, system-owned account sized like a nonce account, funded but not yet initialized) arises naturally whenever nonce account setup is split across multiple transactions instead of being bundled atomically with `CreateAccount`.

### Recommendation
Require the target account itself (or an explicit signer matching the intended authority) to sign `InitializeNonceAccount`, consistent with the signer checks already present in `withdraw_nonce_account` and `advance_nonce_account`, so that the authority cannot be set by an unrelated third party.

### Proof of Concept
1. Legitimate user submits a transaction that allocates/assigns/funds an account to be System-owned, `nonce::State`-sized, and rent-exempt, without bundling `InitializeNonceAccount` in the same transaction.
2. Before the user's follow-up `InitializeNonceAccount` transaction lands, an attacker submits their own transaction containing `SystemInstruction::InitializeNonceAccount(attacker_pubkey)` naming the same account as a writable (non-signer) account — this succeeds per `initialize_nonce_account`'s writable-only check.
3. Attacker now controls `nonce_authority`; they submit `SystemInstruction::WithdrawNonceAccount` signed by their own key, draining the account's lamports via `withdraw_nonce_account`'s `check_signer(&data.authority)` path.

pub(crate) fn withdraw_nonce_account(
    from_account_index: IndexOfAccount,
    lamports: u64,
    to_account_index: IndexOfAccount,
    rent: &Rent,
    signers: &HashSet<Pubkey>,
    invoke_context: &InvokeContext,
    instruction_context: &InstructionContext,
) -> Result<(), InstructionError> {
    let mut from = instruction_context.try_borrow_instruction_account(from_account_index)?;
    if !from.is_writable() {
        ic_msg!(
            invoke_context,
            "Withdraw nonce account: Account {} must be writeable",
            from.get_key()
        );
        return Err(InstructionError::InvalidArgument);
    }

    let check_signer = |signer: &Pubkey| {
        if !signers.contains(signer) {
            ic_msg!(
                invoke_context,
                "Withdraw nonce account: Account {} must sign",
                signer
            );
            return Err(InstructionError::MissingRequiredSignature);
        }
        Ok(())
    };

    let state: Versions = from.get_state()?;
    match state.state() {
        State::Uninitialized => {
            if lamports > from.get_lamports() {
                ic_msg!(
                    invoke_context,
                    "Withdraw nonce account: insufficient lamports {}, need {}",
                    from.get_lamports(),
                    lamports,
                );
                return Err(InstructionError::InsufficientFunds);
            }
            check_signer(from.get_key())?;
        }
        State::Initialized(data) => {
            if lamports == from.get_lamports() {
                let durable_nonce =
                    DurableNonce::from_blockhash(&invoke_context.environment_config.blockhash);
                if data.durable_nonce == durable_nonce {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: nonce can only advance once per slot"
                    );
                    return Err(SystemError::NonceBlockhashNotExpired.into());
                }
                check_signer(&data.authority)?;
                from.set_state(&Versions::new(State::Uninitialized))?;
            } else {
                let min_balance = rent.minimum_balance(from.get_data().len());
                let amount = checked_add(lamports, min_balance)?;
                if amount > from.get_lamports() {
                    ic_msg!(
                        invoke_context,
                        "Withdraw nonce account: insufficient lamports {}, need {}",
                        from.get_lamports(),
                        amount,
                    );
                    return Err(InstructionError::InsufficientFunds);
                }
                check_signer(&data.authority)?;
            }
        }
    };

    from.checked_sub_lamports(lamports)?;
    drop(from);
    let mut to = instruction_context.try_borrow_instruction_account(to_account_index)?;
    to.checked_add_lamports(lamports)?;

    Ok(())
}
