### Title
Attacker-controlled GitHub linked-branch name reaches `git` argv unsanitized in `gh issue develop --checkout --worktree`, enabling argument injection - ([File: pkg/cmd/issue/develop/develop.go])

### Summary
`developRunCreate` takes the `branchName` returned by `api.CreateLinkedBranch` (or an existing linked branch name looked up via `api.ListLinkedBranches`) and passes it unchecked into `checkoutBranch`, which forwards it as the `branch` positional argument to `prShared.WorktreeCheckoutCommands` and ultimately to `git.Client.Command`. Unlike `pkg/cmd/pr/checkout/checkout.go`, which explicitly guards against this exact class of input with `strings.HasPrefix(pr.HeadRefName, "-")` before using an attacker-supplied ref name in git argv, `develop.go` has no equivalent check.

### Finding Description
In `developRunCreate` (pkg/cmd/issue/develop/develop.go:261-288), `branchName` is sourced from:
1. `api.CreateLinkedBranch` (api/queries_branch_issue_reference.go:15-49), which returns `mutation.CreateLinkedBranch.LinkedBranch.Ref.Name` directly from the GraphQL response with no validation, or
2. `findExistingLinkedBranchName`, which returns `branch.BranchName` from `api.ListLinkedBranches` (api/queries_branch_issue_reference.go:51-90), again taken verbatim from the API response.

That `branchName` is passed to `checkoutBranch` (develop.go:353) and used as:
- the ref in `gc.Fetch(...)` (develop.go:379),
- the `branch` argument to `prShared.WorktreeCheckoutCommands(gc, worktreeTarget, checkoutBranch, ...)` (develop.go:388-393), which builds argv slices like `{"-C", path, "checkout", "-b", branch, "--track", startPoint}` or `{"worktree", "add", "--track", "-b", branch, "--", target.Path, startPoint}` (pkg/cmd/pr/shared/worktree.go:38-52),
- `gc.CheckoutBranch`/`gc.CheckoutNewBranch` in the non-worktree path (develop.go:405-417),
- `gc.SetBranchConfig` (develop.go:280).

None of these call sites validate that `branchName` doesn't begin with `-` before it lands in `git.Client.Command` argv. This is the same hazard that `pkg/cmd/pr/checkout/checkout.go:150-152` explicitly guards against for `pr.HeadRefName` with `strings.HasPrefix(pr.HeadRefName, "-")`, confirming the maintainers recognize this exact input shape as unsafe when it originates from GitHub-hosted, attacker-influenced branch/ref names.

However, tracing the actual reachability: `branchName` for the create path is only attacker-influenced in that GitHub's linked-branch auto-naming derives a slug from the issue title, but GitHub's slug generation prefixes with the issue number and strips characters incompatible with git ref rules, which would prevent a leading `-` from surviving into the final ref name. The alternate path — reusing an existing linked branch via `findExistingLinkedBranchName`/`ListLinkedBranches` — requires the victim to pass `--name <value>` matching a name that exists in the *issue owner's own repository's* linked branches list, and the underlying ref must physically exist on that repo as `refs/heads/<name>` for `gc.Fetch` to succeed. GitHub's ref creation (whether via the `createLinkedBranch` mutation or a direct `git push`) is itself constrained by git's `check-ref-format` semantics enforced server-side, and it is not established in this codebase or otherwise confirmed here that GitHub's ref/branch-name API will accept and store a ref name beginning with `-` end-to-end (create, list, and fetch). I could not find server-side or client-side evidence in this repo confirming GitHub's API permits persisting such a name, and no test/mocked fixture in this repo demonstrates the round trip succeeding with a `-`-prefixed name reaching `git.Client.Command`.

### Impact Explanation
If confirmed exploitable, this would allow an attacker who controls a repo/issue to have `git` interpret a "branch name" as command-line flags (e.g. `--upload-pack=evil`, `-o`, `--exec`) instead of a ref, during `worktree add`/`checkout -b`/`fetch`, potentially achieving argument injection or remote code execution on the victim's machine — matching a "command execution on the victim host" bounty class.

### Likelihood Explanation
Low/unconfirmed. The exploit chain requires: (1) GitHub's `createLinkedBranch` API or a directly-created ref to actually accept and return a branch name starting with `-` (not verified against real GitHub behavior or this repo's validation), and (2) the victim to run `gh issue develop --name <matching-name> --checkout --worktree <path>` against the attacker's issue/repo. Without confirming GitHub's server-side ref validation allows such names to persist, this cannot be established as reliably reproducible from this codebase alone.

### Recommendation
Regardless of whether GitHub currently rejects such names, add defense-in-depth consistent with `pkg/cmd/pr/checkout/checkout.go`: reject/neutralize any `branchName` returned by `api.CreateLinkedBranch` or `api.ListLinkedBranches` that begins with `-` (e.g., `if strings.HasPrefix(branchName, "-") { return fmt.Errorf(...) }`) before it is used in `checkoutBranch`, and ensure `prShared.WorktreeCheckoutCommands` and any direct `git.Client.Command` invocations use `--` argument separators before ref/branch positional arguments.

### Proof of Concept
Could not construct a concrete, reproducible PoC within this session: doing so requires confirming (via a real GitHub API test or authoritative documentation, not available in this index) whether `createLinkedBranch`/ref creation actually permits and returns a `-`-prefixed branch name. A follow-up PoC would be: mock `api.CreateLinkedBranch` (via httpmock on the GraphQL endpoint) to return `branchName = "--upload-pack=evil"`, call `developRunCreate` with `--checkout --worktree <path>`, and assert via a git-stub `git.Client.Command` recorder whether the resulting argv contains the unguarded `-`-prefixed value (as in `pkg/cmd/pr/checkout/checkout_test.go` style tests), analogous to the existing `HasPrefix` regression test that presumably exists for `checkout.go`. func checkoutBranch(opts *DevelopOptions, branchRepo ghrepo.Interface, checkoutBranch string, worktreeTarget prShared.WorktreeTarget) (err error) {
	remotes, err := opts.Remotes()
	if err != nil {
		// If the user specified the branch to be checked out and no remotes are found
		// display an error. Otherwise bail out silently, likely the command was not
		// run from inside a git directory.
		if opts.Checkout {
			return err
		} else {
			return nil
		}
	}

	baseRemote, err := remotes.FindByRepo(branchRepo.RepoOwner(), branchRepo.RepoName())
	if err != nil {
		// If the user specified the branch to be checked out and no remote matches the
		// base repo, then display an error. Otherwise bail out silently.
		if opts.Checkout {
			return err
		} else {
			return nil
		}
	}

	gc := opts.GitClient

	if err := gc.Fetch(ctx.Background(), baseRemote.Name, fmt.Sprintf("+refs/heads/%[1]s:refs/remotes/%[2]s/%[1]s", checkoutBranch, baseRemote.Name)); err != nil {
		return err
	}

	if !opts.Checkout {
		return nil
	}

	if opts.Worktree != "" {
		commands, branchExists := prShared.WorktreeCheckoutCommands(
			gc,
			worktreeTarget,
			checkoutBranch,
			fmt.Sprintf("%s/%s", baseRemote.Name, checkoutBranch),
		)
		if err := runGitCommands(gc, commands); err != nil {
			return err
		}
		if branchExists {
			if err := gc.Pull(ctx.Background(), baseRemote.Name, checkoutBranch, git.WithRepoDir(opts.Worktree)); err != nil {
				_, _ = fmt.Fprintf(opts.IO.ErrOut, "%s warning: not possible to fast-forward to: %q\n", opts.IO.ColorScheme().WarningIcon(), checkoutBranch)
			}
		}
		return nil
	}

	if gc.HasLocalBranch(ctx.Background(), checkoutBranch) {
		if err := gc.CheckoutBranch(ctx.Background(), checkoutBranch); err != nil {
			return err
		}

		if err := gc.Pull(ctx.Background(), baseRemote.Name, checkoutBranch); err != nil {
			_, _ = fmt.Fprintf(opts.IO.ErrOut, "%s warning: not possible to fast-forward to: %q\n", opts.IO.ColorScheme().WarningIcon(), checkoutBranch)
		}
	} else {
		if err := gc.CheckoutNewBranch(ctx.Background(), baseRemote.Name, checkoutBranch); err != nil {
			return err
		}
	}

	return nil
}

func CreateLinkedBranch(client *Client, host string, repoID, issueID, branchID, branchName string) (string, error) {
	var mutation struct {
		CreateLinkedBranch struct {
			LinkedBranch struct {
				ID  string
				Ref struct {
					Name string
				}
			}
		} `graphql:"createLinkedBranch(input: $input)"`
	}

	input := githubv4.CreateLinkedBranchInput{
		IssueID: githubv4.ID(issueID),
		Oid:     githubv4.GitObjectID(branchID),
	}
	if repoID != "" {
		repo := githubv4.ID(repoID)
		input.RepositoryID = &repo
	}
	if branchName != "" {
		name := githubv4.String(branchName)
		input.Name = &name
	}
	variables := map[string]interface{}{
		"input": input,
	}

	err := client.Mutate(host, "CreateLinkedBranch", &mutation, variables)
	if err != nil {
		return "", err
	}

	return mutation.CreateLinkedBranch.LinkedBranch.Ref.Name, nil
}

func ListLinkedBranches(client *Client, repo ghrepo.Interface, issueNumber int) ([]LinkedBranch, error) {
	var query struct {
		Repository struct {
			Issue struct {
				LinkedBranches struct {
					Nodes []struct {
						Ref struct {
							Name       string
							Repository struct {
								Url string
							}
						}
					}
				} `graphql:"linkedBranches(first: 30)"`
			} `graphql:"issue(number: $number)"`
		} `graphql:"repository(owner: $owner, name: $name)"`
	}

	variables := map[string]interface{}{
		"number": githubv4.Int(issueNumber),
		"owner":  githubv4.String(repo.RepoOwner()),
		"name":   githubv4.String(repo.RepoName()),
	}

	if err := client.Query(repo.RepoHost(), "ListLinkedBranches", &query, variables); err != nil {
		return []LinkedBranch{}, err
	}

	var branchNames []LinkedBranch

	for _, node := range query.Repository.Issue.LinkedBranches.Nodes {
		branch := LinkedBranch{
			BranchName: node.Ref.Name,
			URL:        fmt.Sprintf("%s/tree/%s", node.Ref.Repository.Url, node.Ref.Name),
		}
		branchNames = append(branchNames, branch)
	}

	return branchNames, nil
}

// WorktreeCheckoutCommands returns the commands needed to place branch in
// target. startPoint must be a remote branch suitable for --track.
func WorktreeCheckoutCommands(client *git.Client, target WorktreeTarget, branch, startPoint string) ([][]string, bool) {
	branchExists := client.HasLocalBranch(context.Background(), branch)

	if target.Reuse {
		if branchExists {
			return [][]string{{"-C", target.Path, "checkout", branch}}, true
		}
		return [][]string{{"-C", target.Path, "checkout", "-b", branch, "--track", startPoint}}, false
	}

	if branchExists {
		return [][]string{{"worktree", "add", "--", target.Path, branch}}, true
	}
	return [][]string{{"worktree", "add", "--track", "-b", branch, "--", target.Path, startPoint}}, false
}
