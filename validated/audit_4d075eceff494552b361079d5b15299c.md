### Title
Unsanitized Skill Description Rendered in Terminal Prompts Enables Control-Character/Terminal Injection - (File: `pkg/cmd/skills/install/install.go`, `pkg/cmd/skills/search/search.go`)

### Summary
`gh` fetches a skill's `description` field from an attacker-controlled `SKILL.md` frontmatter in a remote repository and displays it directly in interactive selection prompts during `gh skill install` and `gh skill search`, without passing it through the ANSI/control-character sanitization the codebase uses elsewhere (`Untrusted` type and `sanitizeForTerminal`).

### Finding Description
The `discovery.Skill.Description` field is populated straight from parsed YAML frontmatter of a `SKILL.md` file fetched from a remote GitHub repository, with no sanitization applied: [1](#0-0) [2](#0-1) 

This raw string is then used directly to build prompt labels shown to the user in `gh skill install`'s interactive multi-select search: [3](#0-2) 

and in `gh skill search`'s install-selection prompt: [4](#0-3) 

The codebase clearly recognizes this class of bug elsewhere and has built dedicated defenses: a `sanitizeForTerminal` helper wrapping `asciisanitizer` used specifically in `gh skill list`'s table rendering, and a broader `Untrusted` wrapper type intended for any string sourced from outside the CLI (HTTP responses, remote file contents) whose `String()` method always strips ANSI/control sequences before printing: [5](#0-4) [6](#0-5) 

However, `skillSearchFunc` (used by `install.go`) and `promptInstall` (used by `search.go`) bypass both mechanisms and interpolate `s.Description` (and `s.qualifiedName()`, `s.Repo`) straight into prompt option strings passed to the prompter. This is directly analogous to the reported MetaMask Snap issue, where dApp-controlled `body` fields were interpolated into `snap.request` confirmation dialogs without encoding, allowing control-character/formatting injection into content the user trusts as coming from the tool itself.

### Impact Explanation
A malicious repository owner (or anyone with write access to a public repo referenced by `gh skill install owner/repo` or surfaced via `gh skill search`) can embed ANSI/terminal escape sequences or other control characters in the `description` frontmatter field of a `SKILL.md` file. When a victim runs `gh skill install` or `gh skill search` and browses/searches available skills, that payload is rendered into the interactive picker UI. Depending on terminal capabilities this can be used to obscure or spoof adjacent prompt text (e.g. making a different skill's confirm option look like the intended one, hiding the true repo/description, or manipulating terminal state) — a "CtrlChar/Markdown Injection" style attack against a trust surface the user relies on when deciding what to install.

### Likelihood Explanation
Reachable by any unprivileged attacker who publishes a public repository with skills (the `gh skill install`/`search` workflow explicitly targets discovering skills from arbitrary GitHub repos), requiring no special access — only that a user runs `gh skill install <attacker-repo>` or encounters the repo via `gh skill search`. This matches the "attacker-published content reachable during a normal gh command" pattern. Given that the maintainers already built and applied a `sanitizeForTerminal`/`Untrusted` mitigation to the sibling `gh skill list` table view, the omission in `install.go`/`search.go` appears to be an incomplete rollout of the same fix rather than an intentional decision.

### Recommendation
Sanitize `Skill.Description` (and any other remotely-sourced skill metadata such as name/repo strings surfaced from search results) before interpolating into prompt labels — either wrap it in `iostreams.Untrusted` and call `.String()`, or reuse the existing `sanitizeForTerminal` helper from `pkg/cmd/skills/list/list.go`, applying it consistently at the point descriptions are fetched (`fetchDescription` in `internal/skills/discovery/discovery.go`) so all consumers (list, install, search, preview) inherit the protection automatically.

### Proof of Concept
1. Publish a public repository containing a skill whose `SKILL.md` frontmatter is:
```yaml
---
name: evil-skill
description: "Safe skill\x1b[8mHIDDEN\x1b[0m - actually does something else"
---
```
2. Victim runs `gh skill install attacker/evil-repo` interactively (or `gh skill search`).
3. The raw `\x1b[...]` escape sequence in `description` is passed unfiltered through `skillSearchFunc`/`promptInstall` into the terminal prompt renderer, allowing the attacker to manipulate the displayed text (e.g., conceal words, alter colors, or otherwise mislead the user) at the exact point where they decide whether to trust and install the skill — unlike `gh skill list`, which sanitizes this same field via `sanitizeForTerminal` before display.

	}

	if err != nil {

	}
	return result.Metadata.Description
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
