### Title
CCMenu API token generated for a single stack grants read access to every stack in the Shipit instance - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`CCMenuUrlController#fetch` mints a fresh `ApiClient` token scoped only by the `read:stack` *permission*, but never binds it to the specific `stack` the URL was generated for. Because `ApiClient#stack` is optional and left `nil` here, the resulting token is treated by the API layer as instance-wide, letting anyone who obtains the token read the status, tasks and deploy output of every stack in the Shipit deployment, not just the one advertised by the CCMenu URL.

### Finding Description
The route `/ccmenu/*stack_id` is handled by: [1](#0-0) 

```ruby
def fetch
  uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
  uri.query = { 'token' => client.authentication_token }.to_query
  render(json: { ccmenu_url: uri.to_s })
end

def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```

`find_or_create_by!` is only keyed on `creator` and `name`; the created `ApiClient` record never has its `stack` foreign key set, so `stack_id` is `nil`. The token embedded in the returned `ccmenu_url` is `client.authentication_token`, a bare signed ID with no stack constraint baked in [2](#0-1) .

Every API request authenticates via `ApiClient.authenticate(token)` and then scopes visible stacks with: [3](#0-2) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
```

Since the CCMenu client's `stack_id` is `nil`, `stack_id?` is `false`, and `stacks` resolves to `Stack.all` — every stack, not just the one the CCMenu URL was generated for. This breaks the trust binding "a stack a token authorises" (the single stack shown in the generated CCMenu URL) versus "a stack it touches" (every stack in the instance), the exact analog class called out in the rules.

### Impact Explanation
The URL returned by `fetch` is designed to be handed to external, unauthenticated CI-status-monitor tooling (CCMenu clients, dashboards, status boards) and is commonly embedded in public or semi-public locations, since its whole purpose is to be polled without a Shipit session. Anyone who obtains this URL/token — which requires no session and no `ApiClient` privilege beyond being a normal logged-in user able to view one stack — gains `read:stack` API access to **all** stacks in the deployment: status, tasks, deploy history, and output for every application managed by that Shipit instance. This matches the "High" impact bucket: unauthenticated read of stack state, task streams, or deploy output, but for the entire fleet of stacks rather than the one the user was authorized to view via the UI.

### Likelihood Explanation
Any authenticated Shipit user (even one authorized only for a single stack) can trigger this endpoint by visiting a stack page (the ccmenu URL is surfaced in the stack settings UI). No special privilege, admin capability, or session/token beyond ordinary Shipit login is required to mint the over-broad token — it happens automatically and silently on the first `fetch` call for any stack. The main friction is that the token/URL then needs to leak into an unauthenticated context (e.g., a public CI dashboard), which is exactly the expected consumption pattern for CCMenu URLs.

### Recommendation
Bind the generated `ApiClient` to the specific stack when it is created, e.g.:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack], stack:)
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```
and add a uniqueness/lookup key that includes `stack_id` so that a distinct, stack-scoped `ApiClient` is created per stack instead of a single global one being reused/created without scope. Additionally, `BaseController#stacks` should be audited to ensure any historical unscoped CCMenu-type clients are migrated to explicit per-stack scoping.

### Proof of Concept
1. As any logged-in Shipit user with visibility of `stack-A`, `GET /ccmenu/stack-A/` (`CCMenuUrlController#fetch`).
2. The response contains a `ccmenu_url` with `?token=<T>`. Inspect `ApiClient.find_by(name: 'CCMenu Client', creator: current_user)` — its `stack_id` column is `nil`.
3. Using the same token `T` with HTTP Basic Auth (`Authorization: Basic base64(T)`), call `GET /api/stacks` or `GET /api/stacks/stack-B` for an unrelated `stack-B` that the CCMenu URL was never generated for.
4. The request succeeds and returns `stack-B`'s data, because `BaseController#stacks` falls back to `Stack.all` when `current_api_client.stack_id?` is `false` [3](#0-2) , proving the token intended for `stack-A` grants read access to every stack in the instance.
