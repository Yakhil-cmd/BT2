### Title
Cross-tenant `Commit`/`MergeRequest` mutation via unscoped SHA lookup in `StatusHandler#process` - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`StatusHandler#process` looks up commits solely `by sha`, with no repository/stack scoping, unlike the `stacks`/`repository_name` helpers defined in the base `Handler` class. Because git commit SHAs are content-addressed and shared identically between a fork and its upstream, an attacker who owns a fork can send (or trigger GitHub to send) an authenticated `status` webhook for their own repository referencing a SHA that is also the head of Org A's open pull request, and the resulting `Status` record is attached to Org A's `Commit`, driving Org A's `MergeRequest` to `rejected`/`ci_failing`.

### Finding Description
The binding the fix should uphold is: `organization authenticating the webhook (payload's repository.owner.login, verified via Shipit.github(organization: repository_owner).verify_webhook_signature)` == `organization owning the Stack/Commit/MergeRequest that gets mutated`. Tracing the code shows this equality is never enforced for the `status` event:

- `WebhooksController#verify_signature` only checks that the HMAC signature matches the secret for the organization named in the payload's own `repository.owner.login` field: [1](#0-0) . It authenticates "a payload was signed by org X's secret", not "the Commit/Stack being mutated belongs to org X".
- The base `Handler` class provides `stacks`/`repository_name` helpers, scoped from `payload.dig('repository', 'full_name')`, specifically so handlers can restrict their side effects to the stacks that belong to the authenticated repository: [2](#0-1) .
- `StatusHandler#process` does **not** use `stacks`/`repository_name` at all. It performs a global lookup: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`: [3](#0-2) . Any `Commit` row across **any** stack/repository/organization in the entire Shipit install that happens to share that SHA gets a new `Status` created for it.
- `Commit#create_status_from_github!` -> `add_status` creates the `Status` and schedules `ProcessMergeRequestsJob` for that commit's stack: [4](#0-3) , and the "add_status schedule a MergeMergeRequests job" test confirms this downstream effect: [5](#0-4) .
- `ProcessMergeRequestsJob#perform` then calls `merge_request.reject_unless_mergeable!` for every pending MR on that stack: [6](#0-5) .
- `MergeRequest#reject_unless_mergeable!` calls `any_status_checks_failed?`, which builds a `StatusChecker` from `head.statuses_and_check_runs` and rejects with `'ci_failing'` if `failure?`/`error?`: [7](#0-6) .

    def reject_unless_mergeable!
      return reject!('merge_conflict') if merge_conflict?
      return reject!('ci_missing') if any_status_checks_missing?
      return reject!('ci_failing') if any_status_checks_failed?
      return reject!('requires_rebase') if stale?

      false
    end

    def merge!
      raise InvalidTransition unless pending?

      raise NotReady if not_mergeable_yet?

      stack.github_api.merge_pull_request(
        stack.github_repo_name,
        number,
        merge_message,
        sha: head.sha,
        commit_message: 'Merged by Shipit',
        merge_method: stack.merge_method
      )
      begin
        if stack.github_api.pull_requests(stack.github_repo_name, base: branch).empty?
          stack.github_api.delete_branch(stack.github_repo_name, branch)
        end
      rescue Octokit::UnprocessableEntity
        # branch was already deleted somehow
      end
      complete!
      true
    rescue Octokit::MethodNotAllowed # merge conflict
      reject!('merge_conflict')
      false
    rescue Octokit::Conflict # shas didn't match, PR was updated.
      raise NotReady
    end

    def all_status_checks_passed?
      return false unless head

      StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec).success?
    end

    def any_status_checks_failed?
      status = StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec)
      status.failure? || status.error?
    end
