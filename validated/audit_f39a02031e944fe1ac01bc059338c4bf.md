## Title
Webhook signature verification is scoped by an attacker-controlled `repository.owner.login`/`organization.login` field that is decoupled from the `repository.full_name` field the handlers actually act on, allowing cross-organization webhook forgery - (`app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to use for HMAC verification based on `repository.owner.login` (or `organization.login`) taken directly from the unverified request body. Every webhook handler, however, resolves the target `Stack`/`Repository` from a different field in the same body: `repository.full_name` (`Handler#repository_name`). Because both fields live inside the same signed payload and nothing ties them together before the signature check, whoever knows the webhook secret for *any one* configured GitHub organization can forge a signature that Shipit accepts, while pointing `repository.full_name` at a stack belonging to a completely different organization/repository.

### Finding Description
`app/controllers/shipit/webhooks_controller.rb`: [1](#0-0) 

`repository_owner` is read straight from the request body being verified, not from anything already authenticated: [2](#0-1) 

That value is used to pick the `GithubApp`/secret via `Shipit.github(organization: repository_owner)`, and `verify_webhook_signature` only proves the caller knows the secret configured for *that* organization: [3](#0-2) 

Once the signature passes, `WebhooksController#create` hands the *entire* raw payload to the registered handlers unmodified: [4](#0-3) 

Every handler resolves its target stack via `repository.full_name`, a sibling field that was never checked against `repository.owner.login`: [5](#0-4) 

For example `PushHandler` uses that resolved stack set to enqueue a GitHub sync for the matched branch: [6](#0-5) 

**Binding broken:** the identity that authenticated the request (`repository.owner.login` → the org whose webhook secret matched) is treated as equal to the repository/stack that the request is allowed to act on (`repository.full_name`), but nothing in the code enforces that equality. Both fields are attacker-controlled, sibling members of the same signed JSON body — the signature only proves knowledge of *some* configured org's secret, not that the payload's `full_name` belongs to that org.

### Impact Explanation
An attacker who legitimately administers (or otherwise knows the webhook secret of) Organization A's GitHub App configured in Shipit can craft a raw HTTP POST to `/webhooks` with:
- `repository.owner.login` = `"orgA"` (so `verify_signature` selects and validates against Org A's known secret)
- `repository.full_name` = `"orgB/victim-repo"` (a stack belonging to an unrelated organization/customer, Org B, that the attacker has no access to)

The signature check passes (computed correctly with Org A's secret over the full crafted body), and the handler layer then acts on Org B's stack using the forged `full_name`. Depending on event type this enables:
- `push` events → `GithubSyncJob` enqueued for an arbitrary victim stack, forcing sync against attacker-chosen `expected_head_sha`.
- `status`/`check_suite` events → writing commit statuses/check runs on a victim stack's commits, which can flip `deployable?` and, combined with `continuous_deployment`, trigger unauthorized deploys.
- `pull_request`/`membership` events → archiving/unarchiving review stacks or mutating `Team`/`Membership` records for organizations the attacker does not control.

This is a cross-repository/cross-organization write achieved without any Shipit account, `ApiClient` token, or access to the victim organization — satisfying the "cross-repository writes" / "unauthorized deploy" High/Critical impact bar.

### Likelihood Explanation
Likelihood is moderate to low depending on deployment: it requires a Shipit instance configured with credentials for at least two GitHub organizations (a common multi-tenant setup, as shown by `config/secrets.development.shopify.yml` listing multiple orgs each with its own `webhook_secret`), and the attacker must know/control the webhook secret for at least one of them (e.g., they administer that org's GitHub App, a plausible scenario for a multi-tenant deploy tool serving several teams/orgs from one Shipit instance). No interception, GitHub App private key, or Shipit session is required — only knowledge of one org's webhook secret and the ability to send a raw HTTP request to the public webhooks endpoint.

### Recommendation
After selecting the GitHub App/secret via `repository_owner`, validate that `repository.full_name`'s owner segment matches `repository_owner` (or `organization.login`) before dispatching to handlers, rejecting the request (e.g., `head(422)`) on mismatch. Alternatively, derive the verifying secret from a value that is bound to the specific repository (not just its owner-login string) so that a payload naming a repository outside the authenticating organization can never validate.

### Proof of Concept
1. Configure Shipit with two orgs, `orgA` and `orgB`, each with its own `webhook_secret` (as in `config/secrets.development.shopify.yml`).
2. As an attacker who knows/controls `orgA`'s webhook secret, compute `sha1=HMAC(orgA_secret, body)` for a crafted push payload where:
   - `repository.owner.login` = `"orgA"`
   - `repository.full_name` = `"orgB/victim-repo"`
   - `ref` = `"refs/heads/<victim-branch>"`, `after` = attacker-chosen sha
3. POST to `/webhooks` with header `X-Github-Event: push` and `X-Hub-Signature: sha1=<computed>`.
4. `WebhooksController#verify_signature` resolves `Shipit.github(organization: "orgA")` and successfully verifies the signature.
5. `PushHandler#process` resolves stacks via `Repository.from_github_repo_name("orgB/victim-repo")` and enqueues `GithubSyncJob` for `orgB`'s stack — despite the attacker having no relationship to `orgB`.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"

      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
