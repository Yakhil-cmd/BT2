### Title
Cross-organization webhook confusion: `repository.owner.login` selects the verifying `GitHubApp`, but handlers resolve the mutated `Repository` from an independent `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb])

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the `webhook_secret` used to authenticate the request) from `params.dig('repository','owner','login')`, while `PullRequest` handlers (e.g. `EditedHandler#repository`, `ClosedHandler#repository`) independently resolve the target `Repository` from `params.repository.full_name` via `Repository.from_github_repo_name`. Both fields live in the same attacker-influenceable JSON body but nothing enforces that the owner encoded in `full_name` matches the `owner.login` used for signature selection, so a webhook that authenticates as organization A can mutate data belonging to organization B's tracked repository.

### Finding Description
The claimed binding is: `organization_used_for_verification == owner_of_repository_being_mutated`, i.e. `repository_owner` in `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:59-62`) must equal the owner segment resolved by `Repository.from_github_repo_name(params.repository.full_name)` in the handler (`app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb:63-65`, similarly `closed_handler.rb:49-53`, `assigned_handler.rb:67-69`, `unlabeled_handler.rb:59-63`).

`verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
``` [1](#0-0) 
where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [2](#0-1) .

`Shipit.github` → `github_app_config` downcases both the config keys and the requested organization, then selects a `GitHubApp` instance keyed strictly on that string [3](#0-2) . Crucially, `GitHubApp#verify_webhook_signature` treats an absent/blank `webhook_secret` as automatically verified: `return true unless webhook_secret` [4](#0-3) . Both the example dev config and the multi-org doc show `webhook_secret` can legitimately be left blank [5](#0-4) .

Meanwhile, `EditedHandler#repository` (and sibling PR handlers) resolve the target repository from a *different* field of the same JSON body, `params.repository.full_name`, via `Repository.from_github_repo_name`, which just downcases and looks up `owner/name` — with no cross-check against `repository.owner.login` used earlier for signature routing [6](#0-5) , [7](#0-6) .

**Exploit flow:** An attacker who controls (as GitHub App admin) an organization configured in Shipit's multi-org `github:` section with an unset `webhook_secret` (a supported, documented configuration) crafts a raw POST to `/webhooks` with:
- `X-Github-Event: pull_request`
- body: `repository.owner.login = "attacker-org"` (the org with no configured secret — verification auto-passes) and `repository.full_name = "victim-org/target-repo"` (a repository actually tracked under a *different*, properly-secured org config), plus a `pull_request.number` matching an existing tracked PR of `victim-org/target-repo`.

`verify_signature` resolves `Shipit.github(organization: "attacker-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally — no forged HMAC or secret knowledge is needed. The request proceeds to `EditedHandler`, which resolves `repository` from `full_name` = `victim-org/target-repo`, finds the existing tracked `PullRequest`, and calls `pull_request.update(github_pull_request: params.pull_request)` [8](#0-7)  — overwriting stored PR metadata (title, head sha/ref, labels, assignees) for a repository whose true owner never authenticated this webhook. The `ClosedHandler` path is more severe: it calls `review_stack.archive!` on the victim organization's review stack based purely on the forged `full_name` [9](#0-8) , causing an unauthorized state change (archival) of a stack belonging to an organization that never signed this request.

Existing guards do not stop this: `drop_unhandled_event`/`check_if_ping` only gate on event type; `verify_signature`'s `GithubOrganizationUnknown` rescue only fires when the named org key is entirely absent from config, not when it diverges from `full_name`'s owner; `ExplicitParameters` schemas only assert types/presence, never cross-field equality; `Repository` validations only constrain character format, not provenance.

### Impact Explanation
An attacker who administers just one configured (possibly secret-less) GitHub App entry in a multi-tenant Shipit deployment can, per request, mutate `PullRequest` records or archive `ReviewStack`s belonging to a completely different, properly secured organization's tracked repository, without ever knowing that organization's `webhook_secret`. This is a "payload for one repository mutating another's stack/commit/task" scenario — Critical per the stated impact categories. It is trivially repeatable against any tracked repository/PR number the attacker can guess or observe (PR numbers and repo full names are public), and scales across every tenant sharing the Shipit instance.

### Likelihood Explanation
Requires: (1) the target Shipit instance to use the multi-organization `github:` config scheme documented in `docs/setup.md`, and (2) at least one configured organization entry with a blank/absent `webhook_secret` (a state the codebase explicitly supports and the shipped example config demonstrates) — attacker must be an admin of that org's GitHub App registration, not of Shipit itself, and needs no Shipit secrets. Given these preconditions this is a low-cost, fully repeatable, unauthenticated-from-Shipit's-perspective attack; if all configured orgs strictly require secrets, the attacker cannot pass `verify_signature` at all for any org.

### Recommendation
Bind the org used for signature verification to the same identity used to resolve the mutated repository within a single request: derive both from `params.repository.full_name` (or otherwise assert `params.repository.owner.login.downcase == full_name.split('/').first.downcase`) before dispatching to handlers, and reject the request if they diverge. Additionally, require `webhook_secret` to be present for every organization entry (fail closed rather than fail open when blank), or at minimum warn/reject verification success for empty-secret orgs in production.

### Proof of Concept
`test/controllers/webhooks_controller_test.rb` (minitest, no live GitHub):
```ruby
test "webhook verified under org A mutates a repository owned by org B" do
  Shipit.stubs(:secrets).returns(ActiveSupport::OrderedOptions.new.tap { |s|
    s.github = {
      "attacker-org" => { webhook_secret: nil },
      "victim-org"   => { webhook_secret: "victim-secret" },
    }
  })
  victim_repo = Repository.create!(owner: "victim-org", name: "target-repo")
  stack = shipit_stacks(:shipit)
  stack.update!(repository: victim_repo)
  pr = shipit_pull_requests(:review_stack_review)
  pr.update!(number: 42, stack: stack)

  payload = payload_parsed(:pull_request_opened)
  payload["action"] = "edited"
  payload["number"] = 42
  payload["pull_request"]["title"] = "PWNED"
  payload["repository"]["owner"] = { "login" => "attacker-org" } # selects org with no secret -> auto-verified
  payload["repository"]["full_name"] = "victim-org/target-repo"  # targets a different org's repo

  @request.headers['X-Github-Event'] = 'pull_request'
  post :create, body: payload.to_json, as: :json

  assert_equal "PWNED", pr.reload.title,
    "org A's unsigned webhook should not be able to mutate org B's PullRequest"
end
```
Assert both sides of the binding explicitly: `Shipit.github(organization: "attacker-org")` (used for verification) is a different config entry than the config that should own `Repository.from_github_repo_name("victim-org/target-repo")` (`"victim-org"`), yet the mutation succeeds — proving the binding is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
