Found a concrete analog of the reported bug class: `pool_state.initialize(..., ctx.accounts.creator.key(), ...)` in `initialize_with_permission` sets `pool_creator` to `ctx.accounts.creator` [1](#0-0) , but `creator` in this instruction is declared as an unconstrained `UncheckedAccount` (not a `Signer`, and no `address =` or `constraint =` tying it to `payer` or `permission.authority`) [2](#0-1) . The permission check only verifies that the transaction `payer` owns a `Permission` PDA (`seeds = [PERMISSION_SEED, payer.key()]`) [3](#0-2) ; it never checks that the `creator` account matches `payer` or the permission's authority.

### Title
Permissioned pool creation lets a permission-holder assign arbitrary creator-fee rights to any account - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`initialize_with_permission` records `pool_state.pool_creator = ctx.accounts.creator.key()`, where `creator` is an unchecked, non-signing account fully controlled by the caller's transaction data. The only actual gatekeeping performed is that `payer` holds a `Permission` PDA. There is no on-chain binding between the vetted `payer`/permission holder and the `creator` field that receives perpetual creator-fee rights on the pool.

### Finding Description
`CreatePermissionPda` allows only the program admin (`crate::admin::ID` or `create_permission_pda_owner::ID`) to whitelist a specific `permission_authority` by creating a PDA at `[PERMISSION_SEED, permission_authority]` [4](#0-3) . `InitializeWithPermission` re-derives that PDA using `payer.key()` as the seed and loads it as a typed `Account<Permission>` [3](#0-2) , so only a `payer` who was pre-approved by admin can successfully pass this check (since the derived address must match a previously-initialized account owned by the program).

However, the instruction accepts a separate, fully attacker-supplied `creator: UncheckedAccount` with no constraint linking it to `payer` [5](#0-4) , and this arbitrary `creator` value—rather than the vetted `payer`—is what gets persisted as `pool_state.pool_creator` [1](#0-0) . `pool_creator` is subsequently the sole authorization check in both fee-collection paths: `CollectCreatorFee` requires `creator` to be a `Signer` whose address equals `pool_state.load()?.pool_creator` [6](#0-5) , and `CollectCreatorFeePermissionless` sends the accumulated `creator_fees_token_0/1` to whatever address is stored there [7](#0-6) [8](#0-7) .

This mirrors the reported bug class: an entity that passes one authorization gate (a read-scope token / a permission-holding `payer`) is able to silently self-assign a *different*, unauthorized privileged role (a signal provider / a fee-collecting `pool_creator`) without any additional binding check, because the field that grants ongoing privileged rights is taken directly from unauthenticated, attacker-controlled instruction data rather than from the verified identity.

### Impact Explanation
A permission-holder (or even an account that merely reuses/rents a permission slot) can set `pool_creator` to any address they choose — including addresses they don't control being locked out, or, more commonly, an address of their choosing to concentrate/launder creator-fee rights across many pools, or to intentionally assign an unrelated address that cannot claim/consent, permanently orphaning creator fees. Since `enable_creator_fee = true` is hardcoded for permissioned pools [1](#0-0) , real trading fees accumulate into `creator_fees_token_0/1` and are directed by this unchecked field, resulting in theft or permanent misdirection of LP/trader-derived creator fees.

### Likelihood Explanation
Requires the attacker to already hold (or obtain) a `Permission` PDA as `payer`, which is admin-gated — this materially reduces likelihood but does not eliminate it, since any permission-holder (a class presumably intended only to be trusted for pool *creation*, not for arbitrary fee-recipient assignment) can exploit this in a single transaction with no additional signature required from the `creator` account.

### Recommendation
Constrain `creator` in `InitializeWithPermission` to equal `payer.key()` (or explicitly require `creator` to be a co-signer), removing the free-form unchecked account, so `pool_creator` is always bound to the verified/permissioned identity.

### Proof of Concept
1. Admin creates a `Permission` PDA for `payer = Alice` via `create_permission_pda`.
2. Alice calls `initialize_with_permission`, signing as `payer`, but sets the `creator` account key to an address `Mallory` she controls (no signature required for `creator`).
3. `pool_state.pool_creator` is set to `Mallory` [1](#0-0) .
4. As trades occur, creator fees accrue in `pool_state.creator_fees_token_0/1`.
5. Mallory calls `collect_creator_fee` (signing) or anyone calls `collect_creator_fee_permissionless`, and funds are transferred to `Mallory`'s token accounts [8](#0-7) , even though `Mallory` was never the vetted, permission-checked party.

#[derive(Accounts)]
pub struct CreatePermissionPda<'info> {
    #[account(
        mut,
        constraint = (owner.key() == crate::admin::ID || owner.key() == crate::create_permission_pda_owner::ID) @ ErrorCode::InvalidOwner
    )]
    pub owner: Signer<'info>,

    /// CHECK: permission account authority
    pub permission_authority: UncheckedAccount<'info>,

    /// Initialize config state account to store protocol owner address and fee rates.
    #[account(
        init,
        seeds = [
            PERMISSION_SEED.as_bytes(),
            permission_authority.key().as_ref()
        ],
        bump,
        payer = owner,
        space = Permission::LEN
    )]
    pub permission: Account<'info, Permission>,

    pub system_program: Program<'info, System>,
}

pub fn create_permission_pda(ctx: Context<CreatePermissionPda>) -> Result<()> {
    let permission = ctx.accounts.permission.deref_mut();
    permission.authority = ctx.accounts.permission_authority.key();
    Ok(())
}

pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
