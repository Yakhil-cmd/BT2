### Title
`Shipit::Api::CCMenuController#stack` bypasses per-token stack scoping - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`CCMenuController` overrides `stack` to call `Stack.from_param!(params[:stack_id])` directly instead of using `BaseController#stacks.from_param!`, so it never intersects the requested stack with `current_api_client.stack_id`. Any CCMenu token (even one scoped/expected for a specific stack, or the unscoped `CCMenuUrlController`-minted token) can be used to fetch `ccmenu.xml` for any stack in the installation.

### Finding Description
The binding that should hold for every API endpoint is: `stack ∈ stacks` where `stacks = current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all` [1](#0-0) . `BaseController#stack` correctly enforces this by resolving through `stacks.from_param!`. `CCMenuController` however defines its own `stack` method that resolves through `Stack.from_param!(params[:stack_id])` directly, completely bypassing the `stacks` scope: [2](#0-1) .

`authenticate_api_client` is also overridden to authenticate solely via `params[:token]` (`ApiClient.authenticate(params[:token])`), consistent with the design of a link an operator can paste into a CI dashboard tool: [3](#0-2) . `require_permission :read, :stack` only checks `permissions.include?("read:stack")` — it never checks `stack_id`: [4](#0-3) .

`CCMenuUrlController#client` mints a `read:stack` `ApiClient` with no `stack:` set (so `stack_id` is `nil`), meaning `current_api_client.stack_id?` is false and, if routed through `BaseController#stack`, would resolve to `Stack.all` anyway: [5](#0-4) . Even if that were fixed to scope the client to the requesting stack, `CCMenuController#stack`'s bypass of `stacks` would still allow any token with `read:stack` permission — regardless of its `stack_id` — to read `ccmenu.xml` for an arbitrary stack, because the `stack_id` scoping is never applied in this controller.

Attack: user calls `GET /stacks/A/ccmenu_url`, receives `.../ccmenu.xml?token=T`. User then calls `GET /api/stacks/B/ccmenu.xml?token=T` for any other stack `B`. `authenticate_api_client` accepts `T` (valid `ApiClient`), `require_permission!(:read, :stack)` passes (client has `read:stack`), and `stack` resolves `B` via `Stack.from_param!` with no scoping check — returning `stack.deploys_and_rollbacks.last` for `B`.

### Impact Explanation
The attacker obtains an unauthenticated-for-that-stack read of deploy/build state (deploy status, last build label/time, lock status) for any stack in the Shipit installation, not just the one the token/link was intended for. This is a cross-tenant read of stack state using a token that was never scoped/authorized for that stack, matching "High - unauthenticated read of stack state." It is trivially repeatable against every stack in the instance with a single valid CCMenu token.

### Likelihood Explanation
Preconditions are minimal: the attacker needs any valid CCMenu token — either self-obtained via `/stacks/:id/ccmenu_url` (if they have `read:stack` access to at least one stack) or one intercepted/observed being used by an operator. No GitHub secrets, webhook secrets, or elevated Shipit roles are required. The only action is changing `stack_id` in a URL query string, making this a near-zero-cost, fully repeatable exploit.

### Recommendation
Change `Shipit::Api::CCMenuController#stack` to resolve through the same scoped `stacks` relation as `BaseController`, e.g. remove the private `stack` override entirely (inherit `BaseController#stack`) or explicitly implement `@stack ||= stacks.from_param!(params[:stack_id])`. Additionally consider scoping the `ApiClient` created in `CCMenuUrlController#client` to the specific stack (`stack: stack`) so unscoped tokens aren't minted at all.

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb
test "a token scoped to one stack cannot read another stack's ccmenu.xml" do
  stack_a = shipit_stacks(:shipit)
  stack_b = Stack.create!(repository: Repository.new(owner: 'foo', name: 'bar'), branch: 'main')
  client = ApiClient.create!(creator: @user, name: 'scoped', permissions: %w[read:stack], stack: stack_a)

  get :show, params: { stack_id: stack_b.to_param, token: client.authentication_token }

  # Binding under test: stack_b ∈ stacks(client) == Stack.where(id: client.stack_id)
  # client.stack_id == stack_a.id, so stack_b should NOT be in scope.
  assert_response :forbidden # or :not_found
  # Currently fails: assert_response :ok, and body contains stack_b's project name.
end
```
This demonstrates that `current_api_client.stack_id` (== `stack_a.id`) does not match the stack actually served (`stack_b`), violating the intended `stack ∈ stacks` binding.
