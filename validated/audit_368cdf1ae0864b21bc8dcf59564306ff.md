### Title
Webhook signature verification keys off `repository.owner.login` while all event handlers resolve the target repository via the independent `repository.full_name` field, letting a payload verified against an org with no `webhook_secret` write to a victim repository under a different, secured org - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App config (and thus the `webhook_secret` used to verify `X-Hub-Signature`) using `params.dig('repository','owner','login')`, but `LabeledHandler#repository` (and every other `pull_request` handler, via `Shipit::Repository.from_github_repo_name`) resolves the actual `Repository`/`Stack` to mutate using the independent `params.repository.full_name` field. Nothing enforces that the `owner.login` used for signature selection matches the owner segment embedded in `full_name`, so an attacker who names a spoofed `owner.login` for an org with no configured secret gets `verified = true` for free while pointing `full_name` at a victim repository belonging to a different, secret-protected org.

### Finding Description
The binding that should hold is: `repository_owner_used_for_signature_check == owner_of_the_repository_actually_mutated`. In the code, these are two different reads of attacker-controlled JSON that are never cross-checked.

- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository','owner','login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(header, raw_body)`.
- `GithubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) does `return true unless webhook_secret` — i.e. if the org keyed by `repository_owner` has `webhook_secret: nil` in config (a legitimate multi-tenant configuration, shown in `config/secrets.development.shopify.yml` and `test/dummy/config/secrets.test.json`), **any** payload is accepted as "verified", signature header or not.
- Once verification passes, `WebhooksController#create` dispatches to `Shipit::Webhooks.for_event('pull_request')`, including `LabeledHandler`.
- `LabeledHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:65-68) calls `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which is a pure DB lookup (`app/models/shipit/repository.rb:53-56`, split on `/` and `find_by(owner:, name:)`) — it never re-derives or compares against `repository.owner.login`.
- `LabeledHandler#handle` then calls `stack.archive!` (line 51), which via `ReviewStackAdapter#archive!` calls `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!(user, ...)` against a `ReviewStack` scoped to the resolved (victim) repository's `review_stacks`.

Attacker's request: a POST to `/webhooks` with `X-Github-Event: pull_request`, no (or garbage) `X-Hub-Signature`, and a JSON body where `repository.owner.login = "attacker-org"` (an org present in Shipit's config with `webhook_secret` unset/nil) but `repository.full_name = "victim-org/victim-repo"` (a real, secured repository in the Shipit DB), `action: "labeled"`, and a label matching the victim repository's configured provisioning label. `verify_signature` looks up `attacker-org`'s app config, finds no secret, and treats the request as verified. `LabeledHandler` then resolves the real victim `Repository` from `full_name` and executes `stack.archive!` against the corresponding `ReviewStack`, with `user` set from attacker-controlled `params.sender.login` (`Shipit::User.find_or_create_by_login!`).

None of the existing guards catch this: `verify_signature` never compares `repository_owner` to the owner segment of `full_name`; `drop_unhandled_event` only filters by event type; the `ExplicitParameters` schema in `LabeledHandler.params` only requires `repository.full_name` to be a `String`, it does not tie it to `owner.login`; and `Repository.from_github_repo_name` performs no ownership/authorization check, only a lookup by parsed name.

### Impact Explanation
An attacker with no Shipit credentials and no knowledge of any real webhook secret can cause `stack.archive!` (deprovisioning + archiving) to execute against an arbitrary victim `ReviewStack` belonging to a completely unrelated, secret-protected organization, as long as that victim repository/stack is known to the attacker and any org in the multi-tenant Shipit config has no `webhook_secret` set. This is a cross-tenant, unauthenticated write — a payload "authenticated" for org A causing a mutation on org B's stack — matching the Critical category "a payload for one repository mutating another's stack." It is repeatable per victim repository/PR-environment combination and scales across every tenant sharing the same Shipit instance.

### Likelihood Explanation
Preconditions: (1) the Shipit deployment hosts multiple GitHub orgs and at least one configured org has `webhook_secret` unset (a documented, non-exotic configuration — see `config/secrets.development.shopify.yml` and `test/dummy/config/secrets.test.json`, both showing `webhook_secret: nil`), and (2) the attacker knows the victim's `full_name` and has review-stack provisioning enabled with a known label/PR number scheme (both typically public/discoverable for public repos). Attacker cost is a single crafted HTTP POST with no signature. No GitHub App private key, no `secret_key_base`, no session, and no API token are needed. This is fully reproducible with a minitest controller test and directly demonstrates the confusion between `repository_owner` and `full_name`.

### Recommendation
In `WebhooksController#verify_signature`, derive the organization used for signature verification from the same field the handlers use to resolve the target repository (`repository.full_name`'s owner segment), or better, after successful signature verification, re-validate inside each handler (or centrally in `Handler#initialize`) that `payload.dig('repository','owner','login')` matches the owner segment of `payload.dig('repository','full_name')` before any repository is resolved. Additionally, consider treating a missing `webhook_secret` as a hard misconfiguration error (fail closed) rather than an implicit "verified" bypass in `GithubApp#verify_webhook_signature`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "pull_request labeled event cannot use one org's missing secret to mutate another org's repository" do
  # Precondition: 'attacker-org' is configured with no webhook_secret (per app config)
  Shipit.github(organization: 'attacker-org') # returns GithubApp with webhook_secret == nil

  victim_repository = shipit_repositories(:some_repository_with_secret_org) # owner = 'shopify' (has webhook_secret)
  victim_review_stack = shipit_review_stacks(:some_pr_stack) # belongs to victim_repository, environment "pr2"
  refute victim_review_stack.archived?

  body = {
    action: 'labeled',
    number: victim_review_stack.pull_request_number,
    pull_request: {
      id: 1, number: victim_review_stack.pull_request_number, url: 'https://api.github.com/x',
      title: 't', state: 'open', additions: 1, deletions: 0,
      head: { sha: 'abc', ref: 'some-branch' },
      user: { login: 'attacker' },
      assignees: [],
      labels: [{ name: victim_repository.provisioning_label_name }]
    },
    repository: {
      owner: { login: 'attacker-org' },        # org with NO webhook_secret configured
      full_name: victim_repository.github_repo_name # e.g. "shopify/victim-repo"
    },
    sender: { login: 'attacker' }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  # no X-Hub-Signature header at all

  post :create, body: body, as: :json

  assert_response :ok
  assert victim_review_stack.reload.archived?, "victim stack in a different, secured org was archived via a signature check that never covered it"
end
```
Both sides of the binding `repository_owner_for_signature_check ("attacker-org") == owner_of_mutated_repository ("shopify")` are shown unequal, yet the request is accepted (200) and the victim stack is archived, proving the vulnerability. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
