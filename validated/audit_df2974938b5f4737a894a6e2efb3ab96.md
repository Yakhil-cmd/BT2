### Title
`collect_creator_fee` and `collect_creator_fee_permissionless` bypass the pool's `Withdraw` pause bit - (File: programs/cp-swap/src/instructions/collect_creator_fee.rs, programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs)

### Summary
`PoolState.status` exposes a `Withdraw` bit that is meant to let the admin halt all fund extraction from a pool's vaults via `update_pool_status()`. The `withdraw()` instruction correctly enforces this bit, but `collect_creator_fee()` and `collect_creator_fee_permissionless()` — which also move tokens directly out of `token_0_vault`/`token_1_vault` to an external account — never check `get_status_by_bit(PoolStatusBitIndex::Withdraw)`, allowing vault outflows to continue even when withdrawals have been explicitly paused.

### Finding Description
`PoolState` encodes pause flags in a bitmask, documented at [1](#0-0) . `withdraw()` enforces the `Withdraw` bit before releasing vault funds to an LP: [2](#0-1) .

By contrast, `collect_creator_fee()` unconditionally transfers `creator_fees_token_0`/`creator_fees_token_1` straight out of the same `token_0_vault`/`token_1_vault` accounts with no status check at all: [3](#0-2) . The permissionless variant, callable by anyone (not just the creator) as long as the ATA destination matches the recorded `pool_creator`, has the identical unguarded transfer logic: [4](#0-3) .

This is the same class of inconsistency as the referenced GoGoPool finding: one path that removes value from a shared reserve (`withdrawGGP`) is pausable, while a functionally equivalent path (`claimAndRestake`) that also drains the same vault is not, defeating the purpose of the pause switch.

### Impact Explanation
When an admin sets the `Withdraw` bit to halt outflows from a pool (e.g., in response to a detected exploit, oracle/price anomaly, or other incident affecting `token_0_vault`/`token_1_vault`), `collect_creator_fee`/`collect_creator_fee_permissionless` still allow tokens to be pulled from those same vaults, since these instructions perform no status check. This breaks the admin's emergency control guarantee over vault outflows and can be triggered by an unprivileged party (`collect_creator_fee_permissionless` has no signer restriction beyond paying for ATA creation), continuing to drain vault balance during a period the operator intended to freeze all withdrawals.

### Likelihood Explanation
Any account can call `collect_creator_fee_permissionless()` at any time regardless of pool status, and the pool creator can always call `collect_creator_fee()`; both simply require nonzero accrued `creator_fees_token_0`/`creator_fees_token_1`, which accrue continuously from ordinary swap activity. No special conditions or race are needed — the bypass is deterministic and reachable from a single transaction whenever fees have accrued and the admin has paused withdrawals.

### Recommendation
Add a check for `pool_state.get_status_by_bit(PoolStatusBitIndex::Withdraw)` (returning `ErrorCode::NotApproved` when disabled) at the top of both `collect_creator_fee()` and `collect_creator_fee_permissionless()`, mirroring the guard already present in `withdraw()`, so that pausing withdrawals consistently halts all vault outflows.

### Proof of Concept
1. Admin calls `update_pool_status` setting `status` bit1 (`Withdraw`) to disabled via `pool_state.set_status_by_bit(PoolStatusBitIndex::Withdraw, PoolStatusBitFlag::Disable)` — see [5](#0-4) .
2. A user attempting `withdraw()` on that pool is correctly rejected with `ErrorCode::NotApproved` due to the check at [2](#0-1) .
3. Any signer instead invokes `collect_creator_fee_permissionless` (or the creator invokes `collect_creator_fee`) with `pool_state` pointing to the same paused pool. Because neither instruction reads `pool_state.status`, the transfer at [6](#0-5)  succeeds, moving `creator_fees_token_0`/`creator_fees_token_1` out of the vaults despite the active withdrawal pause.

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```

```rust
pub fn update_pool_status(ctx: Context<UpdatePoolStatus>, status: u8) -> Result<()> {
    require_gte!(255, status);
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    pool_state.set_status(status);
    pool_state.recent_epoch = Clock::get()?.epoch;
    Ok(())
}
```
