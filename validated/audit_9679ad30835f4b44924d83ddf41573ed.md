### Title
Permanent market freeze: accrual panics on `i128` value overflow before the borrow-index cap engages — (File: contracts/pool/src/interest.rs)

### Summary
The analog of CVE-2020-36774 (rebuild mishandled → crash/DoS) is the pool's per-call index accrual. Every state-changing verb first runs `global_sync` → `accrue_chunk` → `accrue_step`, which computes `scaled_to_original(borrowed, borrow_index)` = `scaled * index` in `i128` and panics with `GenericError::MathOverflow` on overflow (`common/src/rates/scaling.rs:14-16`, `common/src/math/fp.rs:14-16`). On a high-decimals market with whale-scale scaled debt, the borrow index grows past `i128::MAX / borrowed` (≈170× for 1e36 scaled ray) well before `update_borrow_index` can clamp it at `MAX_BORROW_INDEX_RAY`, so the panic is hit first — permanently, since indexes only grow.

### Finding Description
`accrue_step` multiplies the raw scaled `borrowed`/`supplied` by the indexes with no saturation (`common/src/rates/simulate.rs:60-61`, `common/src/rates/index.rs:80-81`). `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` but only *after* `scaled_to_original` has already trapped (`common/src/rates/index.rs:13-19`). Because `global_sync` runs before every controller verb, once `borrowed * borrow_index > i128::MAX` every subsequent call — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `update_indexes` itself — panics. The repo's own harness proves this: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` supplies `BILLION * 10^18` of an 18-decimal asset, borrows 98%, and advances years until `update_indexes` reverts with `MATH_OVERFLOW`, with `borrow_index < MAX_BORROW_INDEX_RAY`; afterwards `withdraw` and `repay` revert identically (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:315-356).

### Impact Explanation
Permanent freezing of funds for the affected (hub, token) market: suppliers cannot withdraw and borrowers cannot repay because the shared accrual path traps unconditionally. Even repaying cannot lower the scaled `borrowed` (repay accrues first and panics), and `liquidate`/`clean_bad_debt` hit the same `accrue_chunk`. All principal and accrued yield in the market is locked forever.

### Likelihood Explanation
Reachable by unprivileged addresses through public entrypoints: `supply(hub, token, amount)` followed by `borrow(...)` at ~98% utilization on a whitelisted high-decimals market with lifted caps, then passive time accrual (the test asserts the cliff within 40 years, reached in a few years at the XLM curve's steep segment). An attacker holding the dominant debt/share position can deliberately push a market over the cliff to freeze other suppliers' funds; griefing cost is the attacker's own locked capital. The condition can also arise organically, so no malicious intent is required.

### Recommendation
Make accrual arithmetic non-trapping at the value ceiling: saturate `scaled * index` (e.g., via `mul_div_floor_saturating`/`I256` path in `fp_core`) or clamp `borrow_index` inside `accrue_step` *before* `scaled_to_original` is computed, so the `MAX_BORROW_INDEX_RAY` cap halts index growth before the product overflows. Also consider capping accrued-value terms rather than panicking in `calculate_supplier_rewards`, and/or enforcing scaled-position ceilings at mint time in `calculate_scaled_supply`/`calculate_scaled_borrow` so `scaled * MAX_INDEX` can never exceed `i128::MAX`.

### Proof of Concept
Demonstrated end-to-end by the existing test (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356):
```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);          // unprivileged supply
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // unprivileged borrow, 98% util
// advance time yearly until:
//   try_update_indexes_for(&["BIG18"])  -> MathOverflow
// after which:
//   try_withdraw_raw(BOB, "BIG18", 1)   -> MathOverflow
//   try_repay(ALICE, "BIG18", 1.0)      -> MathOverflow
// with last.borrow_index < MAX_BORROW_INDEX_RAY
```
