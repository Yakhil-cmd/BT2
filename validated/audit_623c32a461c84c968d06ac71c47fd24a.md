### Title
Cross-organization `Team`/`Membership` poisoning via `MembershipHandler#process` bypasses `User#authorized?` - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`MembershipHandler#find_or_create_team!` looks up teams solely by the attacker-supplied `team.id` (GitHub numeric team ID), with no check that this ID belongs to the organization that produced a valid webhook signature. A tenant that legitimately controls one organization's webhook (a normal, unprivileged "own a repo/org, receive events" capability supported by Shipit's multi-org config) can therefore add an arbitrary GitHub login to a `Team` record belonging to a *different* organization, including one referenced in `Shipit.github_teams`, letting that login pass `User#authorized?` and bypass `Authentication#force_github_authentication`.

### Finding Description
The claimed binding is: `current_user.teams` (for the acting identity) == the set of teams that identity was genuinely added to *by the organization that owns that team*. This binding is broken because:

1. `WebhooksController#verify_signature` derives `repository_owner` from `params.dig('repository','owner','login') || params.dig('organization','login')` and validates the HMAC signature against the GitHub App config keyed by that same value [1](#0-0) . For a `membership` event, this is exactly `params.organization.login` — i.e., it only proves the payload was signed by *some* organization the attacker controls (Org A), not that the `team` referenced inside the payload belongs to Org A.
2. `MembershipHandler#find_or_create_team!` resolves the target `Team` purely by `github_id: params.team.id`, an attacker-controlled integer in the JSON body: `Team.find_or_create_by!(github_id: params.team.id) do |team| team.github_team = params.team; team.organization = params.organization.login end` [2](#0-1) . The `do |team| ... end` block (which sets `organization`) only runs when the record is newly created; if a `Team` row with that `github_id` already exists (e.g., created earlier by Org B's own legitimate `membership` webhook), it is returned unchanged, still tagged with Org B's real `organization`.
3. `MembershipHandler#process` then calls `team.add_member(member)` unconditionally for `action == 'added'` [3](#0-2) , and `Team#add_member` just appends the member [4](#0-3) , creating a `Membership` row for Org B's team even though the request was authenticated only against Org A's secret.
4. `User#authorized?` trusts any such `Membership` row without checking provenance: `Shipit.github_teams.empty? || teams.where(id: Shipit.github_teams.map(&:id)).exists?` [5](#0-4) .
5. `Authentication#force_github_authentication` gates every protected controller purely on `current_user.authorized?` [6](#0-5) .

Exploit flow: attacker legitimately controls Org A, which has a real Shipit GitHub App/webhook integration (Shipit explicitly supports multiple independently-configured organizations sharing one instance, as shown by the multi-org example in the setup docs/config). They send (or cause GitHub to send) a `membership` event for Org A with `team.id` set to the numeric GitHub team ID of a team already tracked by Shipit for victim Org B (one of `Shipit.github_teams`), and `member.login` set to their own GitHub username. This passes `verify_signature` (correctly signed by Org A's real secret) and results in a `Membership` linking the attacker's `User` to Org B's privileged `Team`. The attacker then logs into Shipit via normal GitHub OAuth (their own account), obtaining a valid `session[:user_id]`, and `current_user.authorized?` now returns `true`.

None of the existing guards catch this: `verify_signature` checks the signer but not the referential integrity between the signed org and the team ID being written; `ExplicitParameters` only validates types/presence, not cross-record ownership; `force_github_authentication`/`User#authorized?` only check membership existence, not how it was created.

### Impact Explanation
This is a full authentication/authorization bypass (escalation into `Shipit.github_teams`): a party with no relationship to the victim organization gains legitimate Shipit sessions treated as authorized members of that organization's protected teams, unlocking every `force_github_authentication`-gated controller (`StacksController`, `RepositoriesController`, `ApiClientsController`, deploy/rollback/merge actions, etc.) for stacks belonging to organizations the attacker never joined. It is repeatable against any organization whose numeric GitHub team ID is known or guessable (team IDs are small sequential integers and are often discoverable via GitHub's public API, prior webhook deliveries, or UI). Blast radius spans all tenants configured on the shared Shipit instance.

### Likelihood Explanation
Preconditions: Shipit must be configured for at least two organizations (a normal, documented multi-tenant setup) and use `Shipit.github_teams` for access restriction (also normal/recommended per setup docs). The attacker needs a working webhook integration for an org they legitimately control (something achievable by any GitHub org owner, not a Shipit secret) and needs to learn/guess the victim's target team's numeric `github_id`, which is a low-cost enumeration problem (sequential IDs, sometimes exposed publicly). No Shipit or GitHub secret from the victim org is required. Feasibility is high; it's a single crafted webhook POST plus a normal OAuth login.

### Recommendation
In `MembershipHandler#find_or_create_team!`, scope the lookup to also match `organization: params.organization.login` (not just `github_id`), and reject/raise if an existing `Team` with that `github_id` belongs to a different organization than the one that authenticated the webhook (i.e., `repository_owner`/`params.organization.login` used for signature verification). Additionally, verify in `WebhooksController` or the handler that `params.organization.login` used for `Team` mutation matches the organization whose secret validated the signature, closing the referential gap between "who signed this" and "what record it's allowed to touch."

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

# frozen_string_literal: true

module Shipit
  module Authentication
    extend ActiveSupport::Concern

    included do
      before_action :force_github_authentication
      helper_method :current_user
    end

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end

    def current_user
      @current_user ||= find_current_user || AnonymousUser.new
    end

    def find_current_user
      session[:user_id].present? && User.find_by(id: session[:user_id])
    end
  end
end
