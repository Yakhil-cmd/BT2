### Title
Unbounded oscript `feed_name`/`feed_value` in `data_feed`/`in_data_feed` lookups let a trigger sender crash the AA-processing node via an uncaught LevelDB stream error - (File: data_feeds.js)

### Summary
An unprivileged unit poster who triggers an Autonomous Agent whose oscript uses `data_feed[[...]]` or `in_data_feed[[...]]` controls the `feed_name` and `feed_value` operands via `trigger.data`. These values are validated only for basic type/emptiness (`isValidValue`, non-empty string) in `formula/evaluation.js` [1](#0-0)  and in the static validator [2](#0-1) , with no upper bound on string length or byte content. They are concatenated directly into LevelDB range-scan keys in `data_feeds.js` and any stream error is `throw`n from inside an asynchronous `'error'` event handler [3](#0-2)  and [4](#0-3) , which is outside any try/catch in the calling chain.

### Finding Description
`readDataFeedValue`/`readDataFeedByAddress` and `dataFeedExists`/`dataFeedByAddressExists` build LevelDB keys as `'df\n'+address+'\n'+feed_name+'\n'+prefixed_value` and open a `kvstore.createReadStream`/`createKeyStream` on them: [5](#0-4)  and [6](#0-5) .

Both functions register:
```
.on('error', function(error){ throw Error('error from data stream: '+error); });
```
This `throw` happens inside a Node.js EventEmitter callback, not inside the synchronous call stack of the original request. There is no surrounding `try/catch` anywhere up the call chain (`formula/evaluation.js` calls `dataFeeds.readDataFeedValue` and `dataFeeds.dataFeedExists` directly with plain callbacks, no try/catch around the async operation) [7](#0-6) [8](#0-7) . Consequently, if the underlying LevelDB stream ever emits an `'error'` event (e.g., due to malformed/oversized keys, resource exhaustion, or internal store errors triggered by extreme input), the thrown exception becomes an uncaught exception. `network.js` explicitly re-throws on `uncaughtException` to crash the process: [9](#0-8) .

The `feed_name` and `feed_value` formula operands that feed into these keys are validated only for type and non-emptiness — `validateDataFeed`/`validateDataFeedExists` check `oracles`, `min_mci`, `ifseveral`, `what`, `type` but impose no length/format constraint on `feed_name` or `feed_value` beyond "not empty": [2](#0-1) . At evaluation time, the runtime check `getDataFeed` similarly only validates emptiness/type of `feed_name`/`feed_value`, not length: [10](#0-9) . In contrast, the message-level (non-formula) `data_feed` payload validated in `validation.js`/`aa_validation.js` does enforce `MAX_DATA_FEED_NAME_LENGTH`/`MAX_DATA_FEED_VALUE_LENGTH` [11](#0-10)  and [12](#0-11)  — but this cap is *not* enforced for values produced dynamically from `trigger.data` and used only inside an oscript `data_feed[[...]]`/`in_data_feed[[...]]` lookup expression, since those values never pass through `validateDataFeed`'s per-field length checks.

An attacker who controls `trigger.data` (any unprivileged unit poster who triggers a public AA containing a `data_feed[[...]]`/`in_data_feed[[...]]` formula referencing `trigger.data`) can supply an arbitrarily long or specially-crafted `feed_name`/`feed_value` string (limited only by unit size limits, which are large relative to a LevelDB key/iteration boundary) to attempt to induce a LevelDB stream error, which is unconditionally re-thrown outside protective error handling and crashes the full node processing the AA trigger.

### Impact Explanation
This is analogous to the ZoneToCache case: a remote, unprivileged actor supplies crafted (but structurally "valid" per surface checks) data that is insufficiently validated before being handed to a lower-level component (LevelDB), and any failure there is propagated as an uncaught exception that crashes the whole node process (`process.on('uncaughtException', ...) => throw err`). For ocore, this means any node that evaluates the malicious AA trigger (all full nodes that process it, including witnesses maintaining consensus) can be crashed remotely, causing denial of service and potential network-wide inability to process/confirm units depending on that AA, matching the "network unable to confirm new units" acceptance criterion.

### Likelihood Explanation
Medium: Triggering the code path itself is trivial (post a normal payment unit to a publicly known AA address using a `data_feed`/`in_data_feed` oscript, controlling `feed_name`/`feed_value` via `trigger.data`) and requires no privileges. What is uncertain (see below) is whether the specific LevelDB/leveldown backend in use will actually emit an `'error'` event for a given oversized/crafted key rather than silently truncating or accepting it — this depends on the storage engine's internal limits, which could not be verified from the source alone.

### Recommendation
- Enforce the same `MAX_DATA_FEED_NAME_LENGTH`/`MAX_DATA_FEED_VALUE_LENGTH` (and disallow `\n`/control characters) bounds on `feed_name`/`feed_value` used in oscript `data_feed`/`in_data_feed` formulas as are already enforced for literal `data_feed` message payloads, both in `formula/validation.js`'s `validateDataFeed`/`validateDataFeedExists` and in the runtime `getDataFeed`/`in_data_feed` evaluators in `formula/evaluation.js`.
- Replace the `throw Error(...)` inside the LevelDB stream `'error'` handlers in `data_feeds.js` (`dataFeedByAddressExists` and `readDataFeedByAddress`) with a call to `handleResult`/`cb` carrying an error state (or a `nonfatal_error`/logged event), so stream errors cannot become uncaught exceptions that crash the process.

### Proof of Concept
Not independently executed against a live node; reachability is demonstrated statically:
1. Deploy or use a public AA whose oscript contains a branch like `if: "{data_feed[[oracles=trigger.data.oracle, feed_name=trigger.data.fn, feed_value=trigger.data.fv]]}"`.
2. Send a trigger unit (any unprivileged unit poster) with `trigger.data = { oracle: <valid address>, fn: "<very long / crafted string>", fv: "<very long / crafted string>" }`.
3. During AA response computation, `evaluation.js`'s `data_feed` case builds `evaluated_params` with no length checks [13](#0-12)  and calls `dataFeeds.readDataFeedValue(...)`, which opens a LevelDB range stream keyed on the attacker-controlled `feed_name`/value [14](#0-13) .
4. If the store implementation errors on the crafted key/range (e.g., due to size or encoding), the `'error'` handler throws, uncaught, crashing the node via the global `uncaughtException` handler [9](#0-8) .

Because the exact triggering condition of the LevelDB `'error'` event depends on the storage backend's internal behavior (not verifiable from source inspection alone), this PoC establishes the reachable, insufficiently-validated code path rather than a confirmed working payload against a specific KV backend.

function validateDataFeed(params) {
	var complexity = 1;
	if (params.oracles && params.feed_name) {
		for (var name in params) {
			var operator = params[name].operator;
			var value = params[name].value;
			if (Decimal.isDecimal(value)){
				if (!isFiniteDecimal(value))
					return {error: 'not finite', complexity};
				value = toDoubleRange(value).toString();
			}
			if (operator !== '=') return {error: 'not =', complexity};
			if (['oracles', 'feed_name', 'min_mci', 'feed_value', 'ifseveral', 'ifnone', 'what', 'type'].indexOf(name) === -1)
				return {error: 'unknown df param: ' + name, complexity};
			if (typeof value !== 'string')
				continue;
			switch (name) {
				case 'oracles':
					if (value.trim() === '') return {error: 'empty oracle', complexity};
					var addresses = value.split(':');
					if (addresses.length === 0) return {error: 'empty oracle list', complexity};
				//	complexity += addresses.length;
					if (!addresses.every(ValidationUtils.isValidAddress)) return {error: 'oracle address not valid', complexity};
					break;

				case 'feed_name':
					if (value.trim() === '') return {error: 'empty feed name', complexity};
					break;

				case 'min_mci':
					if (!(/^\d+$/.test(value) && ValidationUtils.isNonnegativeInteger(parseInt(value)))) return {
						error: 'bad min_mci',
						complexity
					};
					break;

				case 'feed_value':
					break;
				case 'ifseveral':
					if (!(value === 'last' || value === 'abort')) return {error: 'bad ifseveral: ' + value, complexity};
					break;
				case 'ifnone':
					break;
				case 'what':
					if (!(value === 'value' || value === 'unit')) return {error: 'bad what: ' + value, complexity};
					break;
				case 'type':
					if (!(value === 'string' || value === 'auto')) return {error: 'bad df type: ' + value, complexity};
					break;
				default:
					throw Error("unrecognized name after checking: "+name);
			}
		}
		return {error: false, complexity};
	} else {
		return {error: 'no oracles or feed name', complexity};
	}

function readDataFeedByAddress(address, feed_name, value, min_mci, max_mci, ifseveral, objResult, handleResult){
	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	var bAbortIfSeveral = (ifseveral === 'abort');
	var key_prefix;
	if (value === null){
		key_prefix = 'dfv\n'+address+'\n'+feed_name;
	}
	else{
		var prefixed_value;
		if (typeof value === 'string'){
			var float = string_utils.toNumber(value, bLimitedPrecision);
			if (float !== null)
				prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(float);
			else
				prefixed_value = 's\n'+value;
		}
		else
			prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(value);
		key_prefix = 'df\n'+address+'\n'+feed_name+'\n'+prefixed_value;
	}
	var options = {
		gte: key_prefix+'\n'+string_utils.encodeMci(max_mci),
		lte: key_prefix+'\n'+string_utils.encodeMci(min_mci),
		limit: bAbortIfSeveral ? 2 : 1
	};
	var handleData = function(data){
		if (bAbortIfSeveral && objResult.value !== undefined){
			objResult.bAbortedBecauseOfSeveral = true;
			return;
		}
		var mci = string_utils.getMciFromDataFeedKey(data.key);
		if (objResult.value === undefined || ifseveral === 'last' && mci > objResult.mci){
			if (value !== null){
				objResult.value = string_utils.getValueFromDataFeedKey(data.key);
				objResult.unit = data.value;
			}
			else{
				var arrParts = data.value.split('\n');
				objResult.value = string_utils.getFeedValue(arrParts[0], bLimitedPrecision); // may convert to number
				objResult.unit = arrParts[1];
			}
			objResult.mci = mci;
		}
	};
	kvstore.createReadStream(options)
	.on('data', handleData)
	.on('end', function(){
		handleResult(objResult.bAbortedBecauseOfSeveral);
	})
	.on('error', function(error){
		throw Error('error from data stream: '+error);
	});
}
