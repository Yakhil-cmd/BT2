### Title
`GitHubApp#verify_webhook_signature` accepts any/no signature when an org's `webhook_secret` is blank - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever the organization's config has no `webhook_secret` configured, before any HMAC is computed or compared. Since `WebhooksController#verify_signature` resolves the `GitHubApp` purely from the attacker-controlled `repository_owner`/`organization.login` field in the payload, any unauthenticated internet request naming that org's login is treated as "verified" and reaches all registered webhook handlers.

### Finding Description
The binding that should hold is: `verify_webhook_signature(signature, message) == true` **only if** `SecureCompare.secure_compare(signature_bytes, HMAC-SHA1(webhook_secret, message)) == true`. Instead, the code is: [1](#0-0) 

`return true unless webhook_secret` bypasses the equality entirely whenever `@webhook_secret = @config[:webhook_secret].presence` is `nil` — e.g. an org entry configured only with `oauth` for login purposes, without `webhook_secret` (a documented/plausible per-org config per `TOP_LEVEL_GH_KEYS`/`github_app_config` in `lib/shipit.rb`).

The controller path is: [2](#0-1) [3](#0-2) 

`repository_owner` is read straight from the untrusted JSON body (`params.dig('repository','owner','login')`), used to pick the `GitHubApp` via `Shipit.github(organization: repository_owner)`, and that same app's `verify_webhook_signature` is called. If that org's config lacks `webhook_secret`, `verified` is `true` unconditionally, regardless of the `X-Hub-Signature` header value (even garbage or absent), and `handler.call(params)` executes for `push`, `status`, `check_suite`, `membership`, `pull_request`, etc.

Existing guards do not prevent this: `drop_unhandled_event` only filters unknown event types, not unauthenticated ones; `GithubOrganizationUnknown` handling in `verify_signature` only guards against organizations that aren't configured at all, not ones configured without a secret. There is no validation anywhere forcing `webhook_secret` to be present for every configured organization.

### Impact Explanation
For any organization configured in `Shipit.github` without a `webhook_secret`, an unauthenticated attacker can forge arbitrary webhook events (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) naming that org, causing Shipit to create/modify commits, statuses, team memberships, and trigger jobs (`GithubSyncJob`, `RefreshCheckRunsJob`) as if GitHub had sent them. This is an authentication-bypass class finding matching the "Critical" bar (forged webhook accepted), but it is conditioned on a specific, non-default configuration state (an org entry present with a blank `webhook_secret`) rather than a defect present in every deployment.

### Likelihood Explanation
Requires a Shipit multi-org deployment (`secrets.github` keyed by org) where at least one configured organization omits `webhook_secret` (e.g. an org added only to grant OAuth login/teams, without also wiring up GitHub App webhooks for it). If such a config exists, exploitation is trivial and free for the attacker (no secrets needed, any HTTP client, one POST). If every configured org has a `webhook_secret` set (the setup docs/templates in `docs/setup.md` and `template.rb` show `webhook_secret` being generated/configured alongside each org's GitHub App), this path is unreachable in practice.

### Recommendation
Do not treat a missing `webhook_secret` as "verified." Either require `webhook_secret` to be present for every organization entry (fail closed / raise on boot if missing), or make `verify_webhook_signature` return `false` (reject) instead of `true` when `webhook_secret` is blank, unless there is an explicit intentional "webhooks disabled for this org" flag that is validated separately from a mere blank secret.

### Proof of Concept
```ruby
# test/unit/github_app_test.rb (minitest)
test "verify_webhook_signature rejects requests when webhook_secret is blank" do
  app = Shipit::GitHubApp.new('no-secret-org', { app_id: 1, installation_id: 1 }) # no webhook_secret
  forged_signature = 'sha1=0000000000000000000000000000000000000000'
  body = { repository: { owner: { login: 'no-secret-org' } } }.to_json

  # Binding under test: verified == (HMAC matches secret)
  # Left side (actual):
  actual = app.verify_webhook_signature(forged_signature, body)
  # Right side (expected, since no secret was ever proven known by attacker):
  expected = false

  assert_equal expected, actual # currently fails: actual is true
end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

**File:** app/controllers/shipit/webhooks_controller.rb (L24-49)
```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
