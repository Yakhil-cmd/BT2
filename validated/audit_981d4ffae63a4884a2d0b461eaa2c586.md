The reported issue is a DNS-rebinding TOCTOU in an HTTP SSRF guard (checking a resolved IP against private-range rules, then issuing the actual request against the original hostname, which gets re-resolved by the transport). This bug class requires an attacker-controlled hostname/URL that a privileged component resolves-then-uses for an outbound network fetch, triggered through a real user-facing entry point.

Searching the Polkadot SDK codebase for analogous "resolve-check-then-act-on-different-value" patterns turned up only node-level P2P networking code — e.g. `can_add_to_dht` in [1](#0-0)  and the litep2p equivalent [2](#0-1) , plus authority-discovery address resolution in [3](#0-2)  and [4](#0-3) . These govern which multiaddrs a node dials for libp2p peer discovery/connection — they are driven by authority-discovery-published DHT records and node configuration, not by attacker-controlled input passed through a signed extrinsic, permitted XCM message, or contract call. There is no outbound HTTP fetch here analogous to Mealie's recipe-import feature, and no "check IP once, then let a lower layer independently re-resolve the same hostname before making the privileged request" pattern reachable from a runtime dispatch path.

The runtime's actual HTTP-capable surface, the offchain worker HTTP API (`substrate/client/offchain/src/api/http.rs`), is node-local infrastructure invoked by offchain worker logic that runs off-chain and is not itself an extrinsic entry point receiving attacker-supplied URLs at dispatch time; no scope code exposes a signed-extrinsic/XCM/contract path that resolves a URL/host for an SSRF-style check and then issues the real request against a separately-resolved value. Without such a reachable check-then-act-on-a-different-resolution boundary tied to a real user entry point, there is no supported analog to this CVE in this codebase.

async fn resolve_authority_addresses(
	authorities: &HashSet<AuthorityId>,
	service: &mut sc_authority_discovery::Service,
	local_peer_id: PeerId,
) -> (HashSet<Multiaddr>, usize) {
	let mut addrs: HashSet<Multiaddr> = HashSet::new();
	let mut unresolved = 0;

	for id in authorities {
		let Some(raw) = service.get_addresses_by_authority_id(id.clone()).await else {
			unresolved += 1;
			log::debug!(target: LOG_TARGET, "Couldn't resolve addresses of authority: {id:?}");
			continue;
		};

		let original_len = raw.len();
		let filtered: Vec<Multiaddr> = raw
			.into_iter()
			.filter(|m| PeerId::try_from_multiaddr(m).map_or(true, |pid| pid != local_peer_id))
			.take(MAX_ADDRS_PER_AUTHORITY)
			.collect();

		if original_len > MAX_ADDRS_PER_AUTHORITY {
			log::debug!(
				target: LOG_TARGET,
				"Capped multiaddrs for authority {id:?}: {original_len} -> {MAX_ADDRS_PER_AUTHORITY}",
			);
		}
		log::debug!(target: LOG_TARGET, "Resolved authority {id:?}: {} multiaddr(s)", filtered.len());
		addrs.extend(filtered);
	}

	(addrs, unresolved)
}
