### Title
Sybil-Splitting of Signer Keys Lets an Attacker Steal Reward-Slot Signing Weight from Other Legitimate Signers - (File: stackslib/src/chainstate/nakamoto/signer_set.rs)

### Summary
`pox_5_make_signer_set` allocates the fixed pool of `reward_slots` signing-weight units across signers using a largest-remainder ("Hare") apportionment method [1](#0-0) . Because the "leftover" bonus round grants **at most one +1 bonus per distinct `signer_key` row** rather than per stacker/principal, an unprivileged staker can register several small stacks under multiple distinct signer keys (instead of one), win multiple leftover bonus slots that a single consolidated entry could never win (max +1), and thereby capture signing weight that exceeds what their locked STX proportionally deserves — directly at the expense of another legitimate signer who is displaced out of the reward set entirely.

### Finding Description
The apportionment algorithm:
1. Sums `amount_ustx` per unique `signer_key` into `signer_set` [2](#0-1) .
2. Computes `threshold = ceil(total_ustx_locked / reward_slots)` and gives each entry a `weight = stacked_amt / threshold` (`base`) plus `remainder = stacked_amt % threshold` [3](#0-2) .
3. Any unassigned "leftover" slots (`reward_slots - sum(base)`) are handed out **one per entry**, sorted by descending remainder (ties by key), via a single pass over `apportioned` that increments each entry's weight at most once [4](#0-3) .

Because step 3 gives each *row* (i.e., each distinct `signer_key`) at most one bonus increment, and a single principal can freely register many distinct signer keys via independent `stack-stx`/`delegate-stack-stx` calls, an attacker who splits their stake `A` into `K` separate signer-key entries (each below `threshold`, so `base=0`) can win up to `min(leftover, K)` bonus slots, versus at most `+1` if the same stake were consolidated under one key. Since a signer's total weight scales with the number of leftover-round wins it captures, and leftover slots are a shared, bounded resource, every extra bonus slot the attacker wins via splitting is one fewer bonus slot available to a genuine, non-splitting signer with a legitimately higher aggregate remainder — that signer can be pushed below the reward-set inclusion cutoff (`weight == 0` entries are dropped) [5](#0-4) .

The conservation invariant validated by the test suite confirms the mechanism precisely: `total_weight == base + min(leftover, n_signers)` [6](#0-5) . Increasing `n_signers` (by splitting one stake across many keys) directly increases the number of bonus slots that group of rows can absorb, up to `leftover`, which is exactly the lever an attacker controls.

### Impact Explanation
This breaks the intended equality "signing weight ∝ locked STX." An unprivileged staker can, without locking any additional STX, obtain more Nakamoto-signer voting weight than their stake proportionally warrants, while a genuine signer with equal or greater legitimate remainder is displaced from the signer set (weight driven to 0 and filtered out entirely). Since signer weight determines block-signing/voting authority in the Nakamoto consensus, this lets an attacker acquire disproportionate influence over block validation relative to locked value, and can strip an honest signer of a slot they are otherwise entitled to — matching the "signing weight ... exceeding locked value" High-impact criterion.

### Likelihood Explanation
No privileged role is required: any principal can freely call `stack-stx` / `delegate-stack-stx` multiple times from multiple accounts with distinct `signer-key`s, each below the per-cycle `threshold`. The attacker only needs enough total locked STX to have a competitive remainder relative to the pool of leftover slots and other signers' remainders — a condition that recurs naturally whenever total locked STX doesn't divide evenly by `reward_slots` (i.e., in essentially every reward cycle). No signature forgery, no admin key, and no race condition are needed; the manipulation is a straightforward, repeatable Stacking pattern.

### Recommendation
Cap the leftover-round bonus per unique *stacker principal* (or otherwise aggregate remainder credit across all signer keys controlled by the same principal) rather than per distinct `signer_key`, or bound the number of leftover slots any single principal's split entries can win to what a single consolidated entry of the same total stake would have received (i.e., still `+1` max regardless of how many keys the same controlling stake is spread across). At minimum, this splitting-incentive should be evaluated against the fairness goals of `pox_5_make_signer_set` and explicitly documented/tested as accepted risk, or mitigated.

### Proof of Concept
Using the exact `pox_5_make_signer_set` logic [7](#0-6) , with `reward_slots = 10`:

- `H1` (honest, one key): `amount_ustx = 700`
- `H2` (honest, one key): `amount_ustx = 50`
- Attacker's total controlled stake: `A = 241`
- Total locked = `700 + 50 + 241 = 991` → `threshold = ceil(991/10) = 100`

**Case A — attacker consolidates into 1 signer key (`amount=241`):**
- H1: `base=7, remainder=0`
- H2: `base=0, remainder=50`
- Attacker: `base=2, remainder=41`
- `base_sum=9`, `leftover=1` → highest remainder is H2 (50), so **H2 wins the bonus** → H2 weight = 1, Attacker weight = 2.

**Case B — attacker splits the same `A=241` into 3 signer keys (e.g. 81, 80, 80):**
- H1: `base=7, remainder=0`
- H2: `base=0, remainder=50`
- Attacker keys: each `base=0`, remainders 81, 80, 80 — all **higher than H2's 50**
- `base_sum=7`, `leftover=3` → all 3 attacker rows outrank H2 and each win a bonus slot.
- Result: Attacker total weight = `0+1 + 0+1 + 0+1 = 3` (up from 2), **H2 weight = 0 and is filtered out of the signer set entirely** (down from 1).

For the identical total locked STX (`241`), the attacker gained signing weight `2 → 3` (a 50% increase) purely by registering 3 signer keys instead of 1, and a genuine signer (`H2`) with real, legitimately higher-remainder locked STX lost its rightful reward slot. This is fully reproducible against `pox_5_make_signer_set` with the numbers above.

    pub(crate) fn pox_5_make_signer_set<I>(
        entries: &mut I,
        pox_constants: &PoxConstants,
    ) -> Result<Pox5SignerSetOutput, ChainstateError>
    where
        I: Iterator<Item = Result<RawPox5Entry, PoxEntryParsingError>>,
    {
        let mut signer_set = HashMap::new();
        let mut total_ustx_locked = 0u128;
        for entry_res in entries {
            let entry = match entry_res {
                Ok(x) => x,
                Err(PoxEntryParsingError::Skip(err_str)) => {
                    warn!(
                        "Error while iterating PoX-5 entries, impacting a single entry. Dropping entry from signer set";
                        "error" => err_str
                    );
                    continue;
                }
                Err(PoxEntryParsingError::Abort(err_str)) => {
                    error!(
                        "Abort-triggering error while iterating PoX-5 entries";
                        "error" => err_str
                    );
                    return Err(ChainstateError::PoxNoRewardCycle);
                }
            };

            total_ustx_locked += entry.amount_ustx;

            signer_set
                .entry(entry.signer_key)
                .and_modify(|existing_entry| *existing_entry += entry.amount_ustx)
                .or_insert_with(|| entry.amount_ustx);
        }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

        let mut signer_set: Vec<_> = apportioned
            .into_iter()
            .filter_map(|entry| {
                if entry.weight == 0 {
                    return None;
                }
                let weight = u32::try_from(entry.weight)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                Some(NakamotoSignerEntry {
                    signing_key: entry.signing_key,
                    stacked_amt: entry.stacked_amt,
                    weight,
                })
            })
            .collect();
