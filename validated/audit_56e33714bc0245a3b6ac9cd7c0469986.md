## Analog vulnerability found

The `importGenesisBatch` report describes a **binding that is supposed to constrain what a credential can act on, but is not actually enforced everywhere it needs to be**. The equivalent binding in this engine is: *the stack an `ApiClient` token is scoped to* (`ApiClient#stack_id`) *vs. the stack the request actually touches* (`params[:stack_id]`). In `Shipit::Api::CCMenuController` this binding is broken.

### Title
Stack-scoped API tokens can read build/deploy status of any stack via the CCMenu endpoint - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::ApiClient` supports scoping a token to a single stack via the optional `stack_id` column, and this scope is meant to be enforced centrally by `Api::BaseController#stacks`/`#stack`. `Api::CCMenuController` overrides `#stack` to bypass that enforcement, so a token scoped to stack A can read CCMenu build/deploy status for any stack B by simply changing the `stack_id` URL param.

### Finding Description
`Api::BaseController` centralizes stack scoping: [1](#0-0) 

`current_api_client.stack_id` is only consulted inside `#stacks`, which `#stack` relies on via `stacks.from_param!`. Permission checking (`require_permission`) only validates the `operation:scope` string is present in `ApiClient#permissions`; it never checks `stack_id`: [2](#0-1) 

`Api::CCMenuController` requires `read:stack`, but overrides `#stack` to query `Stack.from_param!(params[:stack_id])` directly — completely bypassing the `stacks` scoping method (and therefore `current_api_client.stack_id`): [3](#0-2) 

The model already ships with a stack-scoped client fixture used specifically to validate that scoping is enforced elsewhere (`Api::StacksController`): [4](#0-3) [5](#0-4) 

That same scoped-token guarantee is silently dropped in `CCMenuController`, because it never calls `stacks.from_param!`, only `Stack.from_param!`.

### Impact Explanation
Any `ApiClient` bearing `read:stack` — even one deliberately scoped to a single stack via `stack_id` — can enumerate and read CCMenu build/deploy status (last build result, activity, lock state, etc.) for **every** stack in the Shipit installation, not just the one it was authorized for. This is an authorization-scope bypass leading to unauthorized cross-stack read of stack state, matching the "High — unauthenticated/unauthorized read of stack state" impact class, since the token holder gains visibility into stacks/repositories outside its granted scope.

### Likelihood Explanation
Exploitation requires only possession of any valid `read:stack` token (the token format is a signed id, `ApiClient#authentication_token`, routinely distributed for CCMenu integrations) and knowledge/guessing of another stack's `owner/repo/environment` identifier, which is often predictable or discoverable (e.g., via `Api::StacksController#index` if any broader token is available, or via public repo naming conventions). No privileged access, session, or additional secret is needed beyond the token itself.

### Recommendation
Make `CCMenuController#stack` go through the scoped `stacks` collection instead of querying `Stack` directly, e.g.:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
removing the private override entirely and inheriting `BaseController#stack`, so `current_api_client.stack_id` scoping is uniformly enforced.

### Proof of Concept
1. Admin issues a stack-scoped `read:stack` token for `acme/app-a/production` (e.g., analogous to the `here_come_the_walrus` fixture, `stack_id` set to stack A).
2. Attacker (holder of that token) requests:
   `GET /api/stacks/acme/app-b/production/ccmenu?token=<stack-A-scoped-token>`
3. `CCMenuController#authenticate_api_client` accepts the token (`ApiClient.authenticate`), `require_permission :read, :stack` passes because the token has `read:stack` in its permissions array, and `#stack` resolves `Stack.from_param!('acme/app-b/production')` regardless of the token's `stack_id`.
4. Response returns build/deploy status XML for stack B, which the token was never authorized to access.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
