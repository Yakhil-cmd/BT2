### Title
Webhook signature check is bound to `repository.owner.login`/`organization.login` while payload processing acts on `repository.full_name` — a nil-secret organization can be used to spoof events for any other stack - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate an inbound GitHub webhook using `repository_owner`, derived from `params.dig('repository','owner','login')` (or `organization.login`) [1](#0-0) . The event handlers that actually act on the payload, however, resolve the target `Repository`/`Stack` from a completely different field: `payload.dig('repository','full_name')` [2](#0-1) . Nothing ever checks that these two fields refer to the same repository/organization. This is the same class of bug as the audited finding: a field that is authenticated (owner login used to pick a signing secret) is not the field that is acted upon (full_name used to select which stack gets written to).

### Finding Description
`GitHubApp#verify_webhook_signature` explicitly no-ops when the organization's configured `webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) . The engine's own sample multi-org configuration shows this is a supported configuration state, not a hardening requirement — each org config can independently have `webhook_secret: # nil` [4](#0-3) .

Because `repository_owner` (the value used to choose *which* org's secret to validate against) is read straight from the attacker-controlled JSON body [5](#0-4) , an unauthenticated caller can craft a request where:
- `repository.owner.login` (or `organization.login`) = an organization onboarded to this Shipit instance that has no `webhook_secret` configured → `verify_signature` passes unconditionally, no HMAC needed.
- `repository.full_name` = any other organization/repo that *is* protected and has real stacks configured in Shipit.

`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` then dispatches the entire raw payload to handlers [6](#0-5) , and every handler resolves its target purely from `repository.full_name` via `Handler#stacks`/`#repository_name`, with no cross-check against `repository_owner` [7](#0-6) . For example `PushHandler#process` uses this to find `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` for the spoofed repository, entirely unauthenticated with respect to that repository's real GitHub org [8](#0-7) .

### Impact Explanation
An attacker with no credentials, no `ApiClient` token, and no GitHub write access to the victim's repository can forge arbitrary webhook events (`push`, `status`, `check_suite`, `pull_request`, `membership`, etc.) against any stack hosted on the same Shipit instance, as long as any one organization configured on that instance has a blank `webhook_secret` (a supported, documented configuration state). This can trigger unauthorized `GithubSyncJob`s, forge commit statuses that satisfy `ci.require` checks, or otherwise manipulate merge/deploy-eligibility state for a repository the attacker does not control — crossing the "organization authenticated vs. repository written" trust boundary called out in the analog rules, and risking unauthorized deploy/merge behavior for a victim stack.

### Likelihood Explanation
Exploitability depends entirely on whether any onboarded organization has `webhook_secret` unset. This is not enforced by the engine (it's explicitly tolerated, `return true unless webhook_secret`), so likelihood is a function of the host application's own deployment configuration rather than a guaranteed universal bypass on every install — this is a real gap in the engine's binding logic, not merely a hypothetical.

### Recommendation
In `WebhooksController#verify_signature`, after signature validation, assert that `repository_owner` (used to pick the verifying secret) equals the owner segment of `repository.full_name` used later by handlers, rejecting the request (422) on mismatch. Alternatively, require `verify_webhook_signature` to fail closed (never return `true`) when `webhook_secret` is blank, or key signature verification off `repository.full_name`'s owner exclusively rather than a separately supplied `organization`/`repository.owner.login` field.

### Proof of Concept
1. Shipit instance has two organizations configured: `victim-org` (has `webhook_secret` set, has stacks with `victim-org/app`) and `attacker-org` (has `webhook_secret: nil`, per the documented supported config in `config/secrets.development.shopify.yml`).
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/app" }
}
```
3. `verify_signature` computes `repository_owner = "attacker-org"`, loads `Shipit.github(organization: "attacker-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally regardless of the (absent/garbage) `X-Hub-Signature` header [3](#0-2) .
4. `PushHandler#process` is invoked with the full payload, resolves stacks via `payload.dig('repository','full_name')` = `"victim-org/app"`, and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on the victim's real stack [8](#0-7) , without ever having presented a valid signature for `victim-org`.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
