### Title
CCMenu API token stack-scope bypass allows reading build status of any stack - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::CCMenuController` overrides the base controller's `stack` resolution method and looks the target stack up directly from `Stack`, instead of going through the scoped `stacks` helper that every other API controller uses to enforce an `ApiClient`'s `stack_id` binding. As a result, a per-stack scoped `ApiClient` token (e.g. the one automatically minted for the CCMenu widget) can be used to read the build/deploy state of *any* stack in the installation, not just the one it was issued for.

### Finding Description
`Shipit::Api::BaseController` defines the authoritative, permission-scoped stack lookup: [1](#0-0) 

`stacks` restricts the queryable set to `current_api_client.stack_id` when the client is bound to a single stack, and `stack` (used by `StacksController`, `TasksController`, etc.) always resolves through that scoped relation.

`CCMenuController`, however, defines its own `stack` method that ignores this scoping entirely: [2](#0-1) 

It calls `Stack.from_param!(params[:stack_id])` — the unscoped class method — rather than `stacks.from_param!(...)`. `require_permission :read, :stack` only checks that the token carries the `read:stack` permission bit; it never checks that the requested `stack_id` matches the token's bound `stack_id`.

Stack-scoped `ApiClient`s are a standard, low-privilege object in this engine. Every Shipit user can mint one for themselves through `CCMenuUrlController`, which creates (or reuses) an `ApiClient` scoped to a single stack with only the `read:stack` permission: [3](#0-2) 

`ApiClient#authenticate` verifies only the signed client id, not the scope, and `stack_id` is an optional column used purely for authorization narrowing: [4](#0-3) 

The binding this breaks: **the stack a token authorizes (`ApiClient#stack_id`) ≠ the stack it actually touches (`params[:stack_id]` in `CCMenuController#stack`)**. Before the request, the token is bound to Stack A only; after the request, the controller renders data for whatever `stack_id` the caller supplies, e.g. Stack B, with no re-check against the token's `stack_id`.

### Impact Explanation
Anyone who obtains a legitimate CCMenu token minted for one stack (a token intentionally scoped to a single, possibly low-sensitivity stack) can use it to query `GET /api/stacks/:stack_id/ccmenu.xml` for every other stack in the Shipit instance, revealing `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `activity`, and `webUrl` for stacks that token was never meant to see. In multi-tenant Shipit deployments where different teams' stacks are meant to be isolated by scoped tokens, this is an unauthorized cross-stack read of stack state — matching the "unauthenticated/under-scoped read of stack state" High-impact category, since the requesting principal only has partial/limited authorization, not general `read:stack` over all stacks.

### Likelihood Explanation
High. No special privileges are required beyond possessing any single-stack-scoped CCMenu token, which is trivially self-issued by any authenticated Shipit user for a stack they can already see, or which may leak via CI dashboard integrations (CCMenu URLs are often embedded in unauthenticated build-monitor tools). The bypass requires only changing the `stack_id` route/query parameter; no additional token or credential is needed.

### Recommendation
Have `CCMenuController#stack` resolve through the scoped `stacks` relation exactly like `BaseController#stack` does (i.e., `stacks.from_param!(params[:stack_id])`) so that a stack-scoped `ApiClient` cannot be used to query stacks outside its `stack_id` binding.

### Proof of Concept
1. As any authenticated Shipit user, visit `Stack A`'s page and fetch its CCMenu URL (`CCMenuUrlController#fetch`), obtaining a token whose backing `ApiClient` has `stack_id = A` and `permissions = ['read:stack']`.
2. Send `GET /api/stacks/{other_org}/{other_stack}/ccmenu.xml?token=<token>` for an unrelated `Stack B` that the token was never scoped to.
3. Observe that `CCMenuController#show` renders `Stack B`'s `lastBuildStatus`/`lastBuildLabel`/`activity`/`webUrl` successfully, even though the token is only authorized for `Stack A`, because `CCMenuController#stack` bypasses the `ApiClient#stack_id` scoping enforced everywhere else in the API.

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end
