### Title
Webhook signature verification binds the "organization" chosen from attacker-controlled payload data, not the "repository" acted upon - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization config (and therefore which `webhook_secret`) to use for HMAC verification based on `repository_owner`, which is read directly from the untrusted JSON payload (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). The downstream event handlers (e.g. `PushHandler`), however, resolve which `Stack`/`Repository` to act on using a *different* field of the same payload: `payload.dig('repository', 'full_name')` in `Handler#repository_name`. Because the field used to pick the verification secret (`owner.login`) is decoupled from the field used to pick the target repository/stack (`full_name`), and both are supplied by the same attacker-controlled request body, an attacker who legitimately owns a webhook secret for *organization A* can craft a payload whose `repository.owner.login = "A"` (so their own secret is selected and the signature check passes) while `repository.full_name = "B/victim-repo"` (a different, victim-owned Shipit stack).

### Finding Description
- `verify_signature` in [1](#0-0)  computes `repository_owner` from the payload and calls `Shipit.github(organization: repository_owner)` to obtain the `GitHubApp` whose `webhook_secret` is used to verify `X-Hub-Signature` over the raw POST body via `verify_webhook_signature` in [2](#0-1) .
- `Shipit.github(organization:)` in [3](#0-2)  looks up per-organization config (`github_app_config(organization)`), meaning each organization can have its own, independently issued `webhook_secret`.
- The signature only proves the request body was signed with *some* organization's secret (the one matching `repository.owner.login`); it says nothing about which repository the payload's other fields describe.
- Once verification passes, `WebhooksController#create` dispatches to handlers via `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` ( [4](#0-3) ), and handlers such as `PushHandler` resolve the acted-upon stacks purely from `payload.dig('repository', 'full_name')` via `Handler#stacks`/`Handler#repository_name` ( [5](#0-4) ) and `PushHandler#process` ( [6](#0-5) ), then calls `stack.sync_github(expected_head_sha: params.after)`.
- Nothing in the request path cross-checks that `repository.owner.login` (used for signature selection) matches the owner implied by `repository.full_name` (used for the actual write). This is the exact class of "binding break" described in the report: a trust decision made about one identifier (the organization that authenticated) is silently applied to a different identifier (the repository that is written).

### Impact Explanation
If exploitable, an attacker who legitimately controls a GitHub organization/App integration registered in Shipit (with their own valid `webhook_secret`) could forge a signed webhook that is verified against their own secret but whose payload `full_name` targets a stack belonging to a different, victim organization. Since `PushHandler` unconditionally enqueues `GithubSyncJob`/`stack.sync_github` for the resolved stack, this could inject fabricated `after`/`ref` values that drive resync/deploy behavior for a repository the attacker does not own — an unauthorized cross-repository action, matching the "cross-repository writes" / "unauthorized deploy" impact class.

### Likelihood Explanation
Exploitation strictly requires the attacker to already control a valid, configured GitHub organization + webhook secret within the same Shipit deployment (i.e., they must be an authorized integrator for at least one organization configured in `secrets.github`). This is a real precondition, not merely theoretical, in any Shipit deployment that hosts multiple independent organizations/GitHub Apps with separate secrets. Given the audit rule that only unprivileged-attacker analogs are accepted, and this path requires possessing a legitimately-issued `webhook_secret` for *some* org (a form of credential), the applicability is limited to multi-org deployments — it is a real crossed binding but the attacker must not be entirely unprivileged relative to the Shipit instance (they must be a legitimate org integrator, just not for the victim org).

### Recommendation
Bind the webhook signature verification to the same repository identity that handlers subsequently act upon. Concretely, after selecting the `GitHubApp`/secret via `repository_owner`, re-derive and cross-validate that `payload.dig('repository', 'full_name')` and/or `payload.dig('organization', 'login')` are consistent with `repository_owner` (e.g., `full_name.split('/').first.casecmp?(repository_owner)`) before dispatching to handlers, rejecting mismatches with `422`.

### Proof of Concept
1. Shipit is configured with two organizations, `attacker-org` and `victim-org`, each with its own GitHub App and `webhook_secret` (per `Shipit.github_app_config`).
2. Attacker, who legitimately controls `attacker-org`'s webhook secret, crafts a POST to `/github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker signs the raw body with `attacker-org`'s known `webhook_secret` and sets `X-Hub-Signature` accordingly.
4. `verify_signature` computes `repository_owner = "attacker-org"`, loads `attacker-org`'s `GitHubApp`, and successfully verifies the signature against the attacker's own secret ( [7](#0-6) ).
5. `create` dispatches to `PushHandler`, which resolves stacks via `Repository.from_github_repo_name("victim-org/victim-repo")` ( [5](#0-4) ) and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` for the victim's stack — despite the signature only proving authorization from `attacker-org`.

Note: I was not able to fully verify within the indexed code whether any additional cross-check exists elsewhere in the request pipeline (e.g., in routing or a before_action not surfaced by search) that would prevent this mismatch; a Devin session with full repository access should confirm there is no such guard before treating this as conclusively exploitable.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)

        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
