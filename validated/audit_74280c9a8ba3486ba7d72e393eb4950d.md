After searching the relevant FRAME and XCM asset-handling code, I could not find a genuine structural analog to the LooksRare bug in `polkadot-sdk`. The core issue in the report is that a caller-supplied "token type" tag (`ERC20`/`ERC721`) is trusted independently of the actual token contract's real behavior, causing the wrong price-oracle branch to be used for value calculation.

In `polkadot-sdk`, the closest conceptual construct is XCM's `Fungibility` enum (`Fungible`/`NonFungible`), but this is not an independently attacker-supplied flag decoupled from the actual asset's on-chain type:

- `Fungibility` is a Rust enum decoded directly from the wire format with structural validation baked into `Decode` (rejecting zero-amount fungibles), not a boolean tag interpreted separately from the amount/instance payload itself. [1](#0-0) 

- The asset matchers used by transactors (`MatchedConvertedConcreteId::matches_fungibles`/`matches_nonfungibles`, `IsConcrete`) explicitly cross-check that the declared `fun` variant (`Fungible` vs `NonFungible`) is consistent with the matcher being invoked, and reject any mismatch (e.g., a `NonFungible` asset presented where `matches_fungibles` is called returns `AssetNotHandled`). [2](#0-1) [3](#0-2) 

- The actual asset transfer/valuation logic dispatches to distinct pallets (`pallet-assets` fungibles vs `pallet-uniques`/`pallet-nfts` non-fungibles) via separate `FungiblesAdapter`/`UniqueInstancesAdapter` transactors keyed to the real pallet storage, not a user-chosen flag that independently selects a pricing code path. [4](#0-3) 

There is no FRAME pallet in this codebase implementing an entry-value/lottery-style mechanism where an untrusted signed extrinsic lets the caller declare an independent "asset kind" flag that is then used, disconnected from the token's real registered type, to select between two different price-oracle computations (e.g., `pallet-lottery` uses a fixed `price` per ticket set by `ManagerOrigin`, not user-supplied token pricing). [5](#0-4) 

Because the reported bug class depends on an application-specific design (a single whitelist covering both ERC20 and ERC721 with a self-declared type field driving price-oracle selection) that has no structural equivalent in the audited `polkadot-sdk` asset/XCM primitives, I cannot support a demonstrable analog here.

enum UncheckedFungibility {
	Fungible(#[codec(compact)] u128),
	NonFungible(AssetInstance),
}

impl Decode for Fungibility {
	fn decode<I: codec::Input>(input: &mut I) -> Result<Self, codec::Error> {
		match UncheckedFungibility::decode(input)? {
			UncheckedFungibility::Fungible(a) if a != 0 => Ok(Self::Fungible(a)),
			UncheckedFungibility::NonFungible(i) => Ok(Self::NonFungible(i)),
			UncheckedFungibility::Fungible(_) => {
				Err("Fungible asset of zero amount is not allowed".into())
			},
		}
	}
}
