### Title
Permanent Cache Poisoning of a Valid Unit via Misclassified "Input Unit Not Found" as a Fatal Error - (File: validation.js, network.js, joint_storage.js)

### Summary
`validatePaymentInputsAndOutputs()` in `validation.js` returns a plain string error ("input unit ... not found") whenever a payment input references a source unit that is not currently present in the local `units` table, instead of returning the structured `{error_code: "unresolved_dependency", ...}` object that the codebase uses elsewhere for exactly this situation (missing local data that may simply not have arrived/synced yet). A plain string error is treated by `validate()`'s dispatcher as a **permanent** `ifUnitError`, which causes `network.js`'s `handleJoint()` to permanently blacklist the unit via `purgeJointAndDependenciesAndNotifyPeers()` / `joint_storage.js`'s `assocKnownBadUnits` cache and the `known_bad_joints` table. This is the same bug class as the Astro advisory: a condition that should be treated as retryable/transient is instead treated as a fatal, permanently-cached negative result, and the caching layer (`checkIfNewUnit`) has no way to distinguish "genuinely invalid" from "temporarily unresolvable."

### Finding Description [1](#0-0) 
When validating a `transfer` payment input, the code looks up the referenced source unit/output:
```
conn.query(
    "SELECT amount, is_stable, sequence, address, main_chain_index, denomination, asset ... WHERE units.unit=?",
    [input.message_index, input.output_index, input.unit],
    function(rows){
        if (rows.length === 0)
            return cb("input unit "+input.unit+" not found");
```
This returns a bare string. Elsewhere in the very same function, when a referenced unit's output data has been locally pruned/stripped, the code deliberately returns the structured, retryable error instead: [2](#0-1) 
```
if (src_output.sequence === 'final-bad' && src_output.main_chain_index < storage.getMinRetrievableMci()) {
    const objCachedOutput = archiving.getCachedOutput(...);
    if (!objCachedOutput)
        return cb({error_code: "unresolved_dependency", arrMissingUnits: [input.unit], bRequestPrunedContent: true});
```
This shows the codebase's own convention: "we don't have this locally" → `unresolved_dependency` (transient, retryable). But the far more common case — the input unit simply hasn't propagated to this node yet (normal p2p/gossip race, or the node is mid-catch-up) — falls through the plain-string path instead.

The dispatcher in `validate()` only recognizes error objects with `error_code` as transient/dependency errors; any plain string is routed to the permanent path: [3](#0-2) 
```
if (typeof err === "object"){
    if (err.error_code === "unresolved_dependency")
        callbacks.ifNeedParentUnits(err.arrMissingUnits, err.bRequestPrunedContent);
    ...
}
else
    callbacks.ifUnitError(err);
```

`network.js`'s `handleJoint()` treats `ifUnitError` as a final, non-recoverable verdict and immediately purges/blacklists the unit and its dependents: [4](#0-3) 
```
ifUnitError: function(error){
    console.log(objJoint.unit.unit+" validation failed: "+error);
    ...
    purgeJointAndDependenciesAndNotifyPeers(objJoint, error, function(){
        delete assocUnitsInWork[unit];
    });
```

`purgeJointAndDependencies()` (invoked via `purgeJointAndDependenciesAndNotifyPeers`) writes the unit into the permanent bad-unit cache, both in memory and in the database: [5](#0-4) 
```
function purgeJointAndDependencies(objJoint, error, onPurgedDependentJoint, onDone){
	var unit = objJoint.unit.unit;
	const truncatedError = truncate(error);
	assocKnownBadUnits[unit] = truncatedError;
	...
	conn.addQuery(arrQueries, "INSERT "+conn.getIgnore()+" INTO known_bad_joints (unit, json, error) VALUES (?,?,?)", [unit, JSON.stringify(objJoint), truncatedError]);
```

From that point on, `checkIfNewUnit()` short-circuits any future receipt of the *exact same, valid* unit — the unit content and hash never change, so it's the same cache key forever — and rejects it without ever re-validating, even after the previously-missing input unit becomes available: [6](#0-5) 
```
function checkIfNewUnit(unit, callbacks) {
	if (storage.isKnownUnit(unit))
		return callbacks.ifKnown();
	if (assocUnhandledUnits[unit])
		return callbacks.ifKnownUnverified();
	var error = assocKnownBadUnits[unit];
	if (error)
		return callbacks.ifKnownBad(error);
```

This is directly analogous to the Astro bug: a condition that is not actually a permanent failure (a `PreconditionFailed`/transient miss) gets funneled into the "permanent failure" code path, and the result is then durably cached (here: `assocKnownBadUnits` + `known_bad_joints` row, there: `Cache-Control: immutable` + 500 status), poisoning all future attempts to deliver the legitimate content/unit.

Additionally, `validateParentsExistAndOrdered()` propagates this poison to any unit built on top of the wrongly-blacklisted unit: [7](#0-6) 
```
conn.query("SELECT error FROM known_bad_joints WHERE unit IN(?) AND creation_date>=?", [arrMissingParentUnits, BOOT_DATE], function(rows){
    (rows.length > 0)
        ? callback("some of the unit's parents are known bad: "+rows[0].error)
        : callback({error_code: "unresolved_dependency", arrMissingUnits: arrMissingParentUnits});
});
```
so a single spurious "input unit not found" verdict cascades to permanently reject every future descendant unit as well.

### Impact Explanation
Any node that, due to ordinary p2p propagation timing (the sending peer's unit arrives before the referenced input's ancestor unit, or the receiving node is mid-catch-up/resyncing), sees `rows.length === 0` for a payment input will permanently and irrevocably blacklist that unit — even though the unit is fully valid and the referenced ancestor unit is perfectly real and will shortly (or already has) become available on the network. The unit is then unrecoverable on that node: it will never be re-validated, never accepted, and any future units spending its outputs, and any children built on it, are cascade-poisoned via the `known_bad_joints` parent check. Because the poisoning happens keyed by unit hash and persists in a durable DB table (`known_bad_joints`), it also survives node restarts (aside from `initUnhandledAndKnownBad` which deliberately currently ignores loading old known-bads back into memory, so the effect is at least session-long, and the DB row remains for cross-checks such as `validateParentsExistAndOrdered`). This produces a node-level "network unable to confirm new units" condition for the affected unit and its descendants — funds referencing it become effectively frozen from that node's perspective, matching the required impact bar (freezing / inability to confirm valid units due to a race-condition misclassification, not any malicious-content issue).

### Likelihood Explanation
This does not require a malicious peer, malicious hub, or special privileges — any regular unit poster whose valid payment unit happens to reach a node before the ancestor unit it spends from (a normal race in a gossip-based DAG network, or during a node's temporary desync) triggers this path. It only requires ordinary, expected network timing variance, making it moderately likely to occur organically, and trivially reproducible by an attacker who deliberately posts a valid payment unit and floods/delays the delivery of its input's source unit to a specific target node.

### Recommendation
In `validation.js`'s payment-input lookup (around line 2452-2453), change the "unit not found" case to return the structured transient/dependency error consistent with the rest of the function, e.g.:
```
if (rows.length === 0)
    return cb({error_code: "unresolved_dependency", arrMissingUnits: [input.unit]});
```
so it routes through `callbacks.ifNeedParentUnits` in `network.js` (which re-requests the missing unit and retries validation) instead of through `ifUnitError`, which triggers permanent blacklisting via `joint_storage.saveKnownBadJoint`/`purgeJointAndDependencies`. Also audit other `cb("... not found")`/plain-string error sites in `validation.js` for the same class of premature permanent classification of local-data-missing conditions.

### Proof of Concept
1. Node B receives (or is fed) unit `U2` that includes a payment input referencing `unit: U1, message_index: 0, output_index: 0`, before Node B has received/stored `U1` in its `units`/`outputs` tables (achievable by controlling delivery order/timing to Node B, e.g., sending `U2` directly to B while delaying propagation of `U1`, or during B's catch-up window).
2. `validatePaymentInputsAndOutputs()` runs the `SELECT ... WHERE units.unit=?` query for `U1`, finds 0 rows, and returns the string `"input unit U1 not found"`.
3. `validate()`'s dispatcher sees a plain string and calls `callbacks.ifUnitError(err)`.
4. `network.js handleJoint()`'s `ifUnitError` handler calls `purgeJointAndDependenciesAndNotifyPeers(objJoint, error, ...)`, which sets `assocKnownBadUnits[U2] = error` and inserts a row into `known_bad_joints` for `U2`.
5. Shortly after, `U1` propagates normally to Node B and is accepted as valid.
6. `U2` is rebroadcast (unchanged, same hash) to Node B — `joint_storage.checkIfNewUnit(U2, ...)` finds `assocKnownBadUnits[U2]` set and immediately calls `ifKnownBad`, permanently rejecting the now-fully-valid unit without any re-validation.
7. Any subsequent unit that spends `U2`'s outputs or references `U2` as a parent is also rejected via the `known_bad_joints` lookup in `validateParentsExistAndOrdered`, cascading the poisoning to Node B's view of the DAG.

function purgeJointAndDependencies(objJoint, error, onPurgedDependentJoint, onDone){
	var unit = objJoint.unit.unit;
	const truncatedError = truncate(error);
	assocKnownBadUnits[unit] = truncatedError;
	db.takeConnectionFromPool(function(conn){
		var arrQueries = [];
		conn.addQuery(arrQueries, "BEGIN");
		conn.addQuery(arrQueries, "INSERT "+conn.getIgnore()+" INTO known_bad_joints (unit, json, error) VALUES (?,?,?)", [unit, JSON.stringify(objJoint), truncatedError]);
		conn.addQuery(arrQueries, "DELETE FROM unhandled_joints WHERE unit=?", [unit]); // if any
		conn.addQuery(arrQueries, "DELETE FROM dependencies WHERE unit=?", [unit]);
		collectQueriesToPurgeDependentJoints(conn, arrQueries, unit, truncatedError, onPurgedDependentJoint, function(){
			conn.addQuery(arrQueries, "COMMIT");
			async.series(arrQueries, function(){
				delete assocUnhandledUnits[unit];
				conn.release();
				if (onDone)
					onDone();
			})
		});
	});
}
