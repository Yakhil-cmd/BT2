### Title
Unvalidated P2P Staking Info Accepted During Fast Sync Enables Corrupted Reward Distribution — (File: `datasync/downloader/queue.go`)

---

### Summary

During fast sync, `P2PStakingInfo` delivered by any connected peer is accepted with a deliberately no-op validate function (marked `// TODO-Kaia-Snapsync update validation logic`). Unlike block bodies and receipts — which are validated against Merkle roots committed in block headers — staking info carries no cryptographic commitment in any header field. A malicious peer can therefore inject arbitrary `CouncilRewardAddrs`, `CouncilStakingAmounts`, `KEFAddr`, and `KIFAddr` values that are written directly to the node's persistent database. On pre-Kaia chains, `GetStakingInfo` reads from this database first and returns the corrupted value without falling back to state, causing all subsequent KAIA block reward distributions to use attacker-controlled addresses.

---

``` [7](#0-6) 
---

### Impact Explanation

On a pre-Kaia chain (or any chain that has not yet activated the Kaia hardfork), after fast sync completes the node begins executing new blocks. `FinalizeState` calls `GetStakingInfo`, which reads the corrupted DB entry and uses it to:

1. **Redirect KAIA block rewards** — `CouncilRewardAddrs` controls where the staking portion of every block reward is sent. An attacker who replaces these with their own addresses receives all staking rewards for every block processed after sync. [8](#0-7) 

2. **Redirect fund allocations** — `KEFAddr` and `KIFAddr` control where the KEF and KIF portions of every block reward are sent. [9](#0-8) 

3. **Skew weighted-random proposer selection** — `CouncilStakingAmounts` determines each validator's probability of being selected as block proposer. Inflating an attacker-controlled validator's amount gives it disproportionate proposer rights.

The corrupted value: the exact wrong `common.Address` values in `RewardAddrs`, `KEFAddr`, `KIFAddr`, and wrong `uint64` values in `StakingAmounts` — all sourced from the attacker's `P2PStakingInfo` response.

---

### Likelihood Explanation

- **Trigger**: Any P2P peer that connects during fast sync. No special privilege is required; a peer only needs to be reachable and respond to `StakingInfoRequestMsg`.
- **Condition**: The victim node must be fast-syncing to a block height that is pre-Kaia fork. This applies to private chains, testnets, and any chain that has not yet activated the Kaia hardfork.
- **Persistence**: Once written to the database, the corrupted entry is returned by `GetStakingInfo` on every subsequent call for that source block number, because the DB-hit path returns before reaching the state-verification path.
- **No existing guard**: The `validate` closure is explicitly a no-op with a TODO comment. There is no hash commitment for staking info in any block header field that could be checked post-hoc.

---

### Recommendation

1. **Derive staking info from state after sync** — After fast sync completes, for each staking-interval block whose staking info was received over P2P, call `getFromStateByNumber` to recompute the staking info from the verified state root and overwrite the DB entry. This is the same approach used for post-Kaia blocks.

2. **Remove the DB-first shortcut or add a state-consistency check** — In `GetStakingInfo`, before returning a DB-cached value for a pre-Kaia block, verify that the node has the corresponding state available and optionally re-derive the value. At minimum, add a flag that marks DB entries as "peer-supplied / unverified" and re-derives them on first use after sync.

3. **Fill the TODO** — Replace the no-op `validate` closure in `queue.DeliverStakingInfos` with a check that at least verifies the `BlockNum` matches the header's number, and ideally cross-checks a hash of the staking info against a field that can be committed in the block header in a future protocol upgrade.

---
```

```go
// getDeferredRewardFullKore is for non-Simple policy and after Kore.
func getDeferredRewardFullKore(config *reward.RewardConfig, execFee, burntFee, blobFee *big.Int, si *staking.StakingInfo) (*reward.RewardSpec, error) {
	var (
		spec             = reward.NewRewardSpec()
		minted           = new(big.Int).Set(config.MintingAmount)
		distributableFee = new(big.Int).Sub(execFee, burntFee)
	)

	// Distribute using RewardRatio first. Unlike Legacy, fees are not distributed here
	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.
	validators, kif, kef := config.RewardRatio.Split(minted)
	proposer, stakers := config.Kip82Ratio.Split(validators)
	ratioRemainder := calcRemainder(minted, proposer, stakers, kif, kef)
	kif.Add(kif, ratioRemainder)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.
	// After Prague, if the CLStaking is not nil, the proposer and staking rewards are proportionally distributed to both CN and CL.
	// For proposer rewards, see `specWithProposerAndFunds`.
	stakersAlloc, kip82Remainder := assignStakingRewards(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)
	stakers.Sub(stakers, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}
	spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
	return spec, nil
```

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```
