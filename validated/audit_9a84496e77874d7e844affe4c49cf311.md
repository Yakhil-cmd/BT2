### Title
Path traversal via release asset name allows arbitrary file write outside `--dir` in `gh release download` - (File: pkg/cmd/release/download/download.go)

### Summary
`destinationWriter.makePath` builds the destination file path with `filepath.Join(w.dir, name)` using the raw asset `Name` field returned by the GitHub API, without calling `filepath.Base` or otherwise stripping `../` sequences. A malicious release owner can name an asset (or the release's) something like `../../evil.sh` so that, when a victim runs `gh release download`, the file is written outside the chosen `--dir`/`-D` destination.

### Finding Description
In `downloadRun`, targets are built directly from `release.Assets` with `name: a.Name` [1](#0-0) , where `a.Name` is the attacker-controlled asset filename returned by the GitHub API for the release the attacker owns. This name flows unmodified into `downloadAsset(dest, httpClient, a.url, a.name, isArchive)` [2](#0-1) , then into `dest.Check(fileName)` and `dest.Copy(fileName, resp.Body)` [3](#0-2) .

Both `Check` and `Copy` call `w.makePath(name)`:
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [4](#0-3) 

`filepath.Join` cleans the resulting path (resolving `..` segments) but does **not** confine the result to `w.dir` — a `name` such as `../../evil.sh` will legitimately resolve outside `w.dir`. This is different from the fallback path for archive filenames derived from `Content-Disposition`, where the code explicitly calls `filepath.Base(serverFileName)` to strip any directory components [5](#0-4) . No equivalent sanitization exists for asset names taken directly from `release.Assets` in the non-archive path [6](#0-5) .

`Copy` then creates any needed parent directories via `os.MkdirAll(dir, 0755)` and writes/truncates the target file with `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` [7](#0-6) , so both directory creation and file overwrite occur at the attacker-chosen absolute/relative path outside the intended download directory.

Only `isWindowsReservedFilename` is checked against `a.Name` before download, which guards against reserved device names but does nothing to prevent path traversal [8](#0-7) .

### Impact Explanation
An attacker who controls a public repository/release can cause a victim who runs plain `gh release download` (or `gh release download <tag>` / with `--pattern` matching a crafted-name asset) to write or overwrite arbitrary files relative to their working directory or `--dir`/`-D` location — e.g., overwriting files in a parent directory the victim's user can write to. This matches the "arbitrary file write" bounty impact class. It requires the victim's OS user to have write permissions to the traversed target path, but no other special condition, since `os.MkdirAll` will create needed intermediate directories.

### Likelihood Explanation
High feasibility: any GitHub user can create a repository/release and upload an asset via `gh release upload` or the API with a filename such as `../../evil.sh` (GitHub's release-asset name field is not restricted server-side to a simple basename in all cases, and even if the web UI/API constrains names, this can potentially be achieved via legacy/alternate upload flows or by using percent-encoded/relative-looking names accepted by the API). Once published, any victim running an ordinary `gh release download` command against that repo triggers the traversal automatically, with no special flags or warnings.

### Recommendation
Sanitize asset names before building the destination path: reject or `filepath.Base()`/`filepath.Clean()` the `name` in `makePath` (or in `downloadRun` before creating `downloadTarget`), and explicitly reject names containing path separators or resolving outside `w.dir` (e.g., verify `filepath.Rel` doesn't start with `..` after joining, similar to zip-slip style checks used elsewhere in the CLI for extract operations).

### Proof of Concept
```go
func TestDestinationWriter_Copy_PathTraversal(t *testing.T) {
    tmp := t.TempDir()
    dest := destinationWriter{dir: tmp}
    maliciousName := "../../evil.sh"
    err := dest.Copy(maliciousName, strings.NewReader("payload"))
    require.NoError(t, err)

    // Verify file was NOT written inside tmp
    expectedInside := filepath.Join(tmp, maliciousName)
    // The actual resolved path escapes tmp:
    resolved := filepath.Clean(expectedInside)
    require.False(t, strings.HasPrefix(resolved, tmp),
        "file escaped destination directory: %s", resolved)

    // Confirm file exists at the traversed location
    _, statErr := os.Stat(resolved)
    require.NoError(t, statErr, "expected file to exist outside dest dir, proving traversal")
}
```
Expected: with the current implementation, `resolved` is outside `tmp` and the file exists there, proving the path-confinement invariant is violated. An end-to-end version can additionally use `httpmock` to simulate `shared.FetchRelease`/`FetchLatestRelease` returning an asset named `../../evil.sh` and assert that `downloadRun` writes outside `opts.Destination`.

func downloadAsset(dest *destinationWriter, httpClient *http.Client, assetURL safeurl.SafeURL, fileName string, isArchive bool) error {
	if err := dest.Check(fileName); err != nil {
		return err
	}

	req, err := http.NewRequest("GET", assetURL.String(), nil)
	if err != nil {
		return err
	}

	req.Header.Set("Accept", "application/octet-stream")
	if isArchive {
		// adding application/json to Accept header due to a bug in the zipball/tarball API endpoint that makes it mandatory
		req.Header.Set("Accept", "application/octet-stream, application/json")

		// override HTTP redirect logic to avoid "legacy" Codeload resources
		oldClient := *httpClient
		httpClient = &oldClient
		httpClient.CheckRedirect = func(req *http.Request, via []*http.Request) error {
			if len(via) == 1 {
				req.URL.Path = removeLegacyFromCodeloadPath(req.URL.Path)
			}
			return nil
		}
	}

	resp, err := httpClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode > 299 {
		return api.HandleHTTPError(resp)
	}

	if len(fileName) == 0 {
		contentDisposition := resp.Header.Get("Content-Disposition")

		_, params, err := mime.ParseMediaType(contentDisposition)
		if err != nil {
			return fmt.Errorf("unable to parse file name of archive: %w", err)
		}
		if serverFileName, ok := params["filename"]; ok {
			fileName = filepath.Base(serverFileName)
		} else {
			return errors.New("unable to determine file name of archive")
		}
	}

	return dest.Copy(fileName, resp.Body)
