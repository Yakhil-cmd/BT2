### Title
CCMenuController#stack bypasses ApiClient stack scoping, allowing cross-stack read access - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::BaseController#stack` restricts the resolvable stack to `current_api_client.stack_id` when the token is scoped, but `Shipit::Api::CCMenuController` overrides `#stack` to call `Stack.from_param!(params[:stack_id])` directly against the full `Stack` table, ignoring the token's scope. Any scoped API token can therefore read CCMenu deploy status for any stack, not just the one it was issued for.

### Finding Description
The binding that should hold: for a given `ApiClient` row with `stack_id == C`, `BaseController#stack("params[:stack_id] = S", S != C)` and `CCMenuController#stack("params[:stack_id] = S", S != C)` must both fail to resolve.

`BaseController` scopes stacks per token: [1](#0-0) 

`CCMenuController` redefines `stack` to bypass that scope entirely: [2](#0-1) 

`ApiClient.check_permissions!` only checks that the token has the `read:stack` permission string; it never validates that the requested stack matches `stack_id`: [3](#0-2) 

So the only place scope enforcement happens is in `BaseController#stack`/`#stacks`, and `CCMenuController` explicitly overrides that method to look up `Stack.from_param!` unscoped. As long as a token has `read:stack` permission (regardless of its `stack_id`), `GET /api/1.0/ccmenu?token=...&stack_id=<any-other-stack>` returns the CCMenu status XML (deploy id, `ended_at`, `running?`) for a stack the token was never scoped to, while the equivalent `GET /api/1.0/stacks/<other-stack>` (via generic `Api::StacksController`, which inherits `BaseController#stack` unmodified) would 404.

`authenticate_api_client` is also separately overridden in `CCMenuController` to read the token from `params[:token]` instead of Basic Auth, but this does not fix or relate to the scoping bypass — it authenticates the same `ApiClient` record, whose `stack_id` scope is what's being ignored by the overridden `stack` method.

### Impact Explanation
A `read:stack`-scoped API token issued for one stack can be used to read the CCMenu deploy-status feed of any other stack in the Shipit instance, disclosing which commit/deploy is running and whether a deploy is in progress for repositories the token holder has no authorization over. This is a cross-tenant read of stack state, matching the "High - unauthenticated/unauthorized read of stack state" category. It does not by itself allow mutation, deploys, or credential exfiltration, so it does not rise to the Critical categories (RCE, forged auth token acceptance, secret exfiltration, or unauthorized deploy/merge).

### Likelihood Explanation
Exploitation only requires possession of any valid `ApiClient` token with `read:stack` permission (a routine, low-privilege scope commonly granted for CI status badges) and knowledge or guessing of another stack's `id`/`to_param`. No GitHub secrets, session, or elevated role is needed. The request is a single unauthenticated-cost HTTP GET and is fully repeatable against any stack id.

### Recommendation
Remove the `stack` override in `Shipit::Api::CCMenuController` (or have it delegate to `stacks.from_param!` like the base class) so that CCMenu lookups honor `current_api_client.stack_id` scoping identically to every other `BaseController` subclass.

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb (extend existing file)
test "#show does not leak stacks outside the token's stack_id scope" do
  scoped_stack = shipit_stacks(:shipit)
  other_stack  = shipit_stacks(:shipit2) # any stack != scoped_stack

  api_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: 'scoped-token',
    stack_id: scoped_stack.id,
    permissions: ['read:stack']
  )

  # Equality that should hold: BaseController#stack resolution for out-of-scope
  # stack_id must fail identically to CCMenuController#stack resolution.
  get "/stacks/#{other_stack.repo_owner}/#{other_stack.repo_name}/#{other_stack.environment}.json",
      params: { token: api_client.authentication_token }
  assert_response :not_found # generic StacksController denies (baseline)

  get ccmenu_project_path(other_stack, token: api_client.authentication_token, format: :xml)
  assert_response :not_found # currently FAILS: CCMenuController returns :ok, exposing other_stack's status
end
```
