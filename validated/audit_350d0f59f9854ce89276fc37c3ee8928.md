### Title
Reward-distribution block cap does not bound per-block partition size, allowing attacker-created stake accounts to inflate per-block reward-distribution work - (File: runtime/src/bank/partitioned_epoch_rewards/mod.rs, runtime/src/bank/partitioned_epoch_rewards/epoch_rewards_hasher.rs, runtime/src/bank/partitioned_epoch_rewards/distribution.rs)

### Summary
`Bank::get_reward_distribution_num_blocks` clamps the number of reward-distribution blocks (`num_partitions`) to a maximum of `slots_per_epoch / 10`, but this cap only bounds the *number of blocks*, not the *number of stake accounts stored per block*. Since `hash_rewards_into_partitions` distributes all rewardable stake accounts by hash into exactly `num_partitions` buckets with no per-bucket size limit, once `total_stake_accounts` exceeds `stake_account_stores_per_block * max_blocks`, each bucket/block must process proportionally more accounts than `MAX_PARTITIONED_REWARDS_PER_BLOCK`/`stake_account_stores_per_block` intends.

### Finding Description
`Bank::get_reward_distribution_num_blocks` (`runtime/src/bank/partitioned_epoch_rewards/mod.rs:409-428`) computes:
```
num_chunks = total_stake_accounts.div_ceil(stake_account_stores_per_block)
num_chunks.clamp(1, (slots_per_epoch / 10).max(1))
``` [1](#0-0) 

This value (`num_partitions`) is stored in the `EpochRewards` sysvar and later passed to `hash_rewards_into_partitions`, which builds exactly `num_partitions` index buckets and hashes every rewardable stake pubkey into one of them with **no cap on bucket size**:
```rust
let mut indices = vec![vec![]; num_partitions];
for (i, reward) in stake_rewards.enumerated_rewards_iter() {
    let partition_index = hasher.clone().hash_address_to_partition(&reward.stake_pubkey);
    indices[partition_index].push(i);
}
``` [2](#0-1) 

Each distribution block then processes exactly one bucket via `store_stake_accounts_in_partition`, which iterates over all indices in that bucket, deserializes/rebuilds/stores every corresponding stake account:
```rust
fn store_stake_accounts_in_partition(...) -> DistributionResults {
    ...
    let indices = partition_rewards.partition_indices.get(partition_index as usize)...;
    for index in indices { ... build_updated_stake_reward(...) ... }
    self.store_accounts((self.slot(), &updated_stake_rewards[..]), ...);
}
``` [3](#0-2) 

Because `num_partitions` is capped at `slots_per_epoch / 10` regardless of `total_stake_accounts`, once an attacker inflates `total_stake_accounts` (by creating and delegating an arbitrarily large number of minimum-delegation stake accounts before the epoch boundary), `total_stake_accounts / num_partitions` grows unboundedly per block — well beyond the intended `MAX_PARTITIONED_REWARDS_PER_BLOCK = 4096` baseline defined in `accounts-db/src/partitioned_rewards.rs:10`. There is no guard anywhere in `distribute_partitioned_epoch_rewards`, `store_stake_accounts_in_partition`, or `hash_rewards_into_partitions` that re-limits per-block work to the configured `stake_account_stores_per_block`; the cap in `get_reward_distribution_num_blocks` only limits *block count*, trading off unbounded *per-block size* to keep the schedule fitting in 10% of the epoch. The test `test_get_reward_distribution_num_blocks_cap` in `runtime/src/bank/partitioned_epoch_rewards/mod.rs:729-794` explicitly documents and asserts this clamping behavior (e.g., `5 * stake_account_stores_per_block` rewards still yields the capped `3` blocks), confirming per-block size is not held constant as account count grows past the cap. [4](#0-3) 

Creating stake accounts and delegating minimum-delegation stakes is an ordinary permissionless action available to any funded user via `stake_instruction::create_account_and_delegate_stake` (as used throughout the codebase, e.g. `runtime/src/bank/tests.rs:3343-3350`), and there is no signer/authority/rent-exempt check that limits the total count of stake accounts a single user (or many colluding users) can create system-wide. [5](#0-4) 

### Impact Explanation
This maps to the "validator stall / slot-time blowout during reward distribution phase" scoped impact from the question. If `total_stake_accounts` vastly exceeds `stake_account_stores_per_block * (slots_per_epoch/10)`, each of the fixed number of distribution blocks must process (deserialize, mutate, and store) a proportionally larger slice of stake accounts than the 4096-per-block baseline this mechanism was designed around, consuming disproportionate per-block compute/storage/IO time in `store_stake_accounts_in_partition`/`self.store_accounts`. This is a consensus-relevant control (the constant is documented as "affects consensus") whose safety margin (10% of epoch, 4096 accounts/block) is defeated by attacker-controlled account counts, risking degraded block-production time for every validator during the fixed reward-distribution window at every epoch boundary — a repeatable, cluster-wide (not just single-node) slowdown since the schedule and partitioning are consensus-determined and identical for all validators.

### Likelihood Explanation
Preconditions are met by an unprivileged actor: only funds and standard `CreateAccount` + `DelegateStake` (or `create_account_and_delegate_stake`) instructions are needed, requiring no special authority. The attack is bounded only by the attacker's ability/willingness to pay rent-exempt minimums and minimum delegation (1 SOL per account under `upgrade_bpf_stake_program_to_v5` per `runtime/src/stake_utils.rs:20-27`) for however many accounts are needed to exceed the cap threshold, and it is fully repeatable every epoch. Note this requires funding many accounts, which is a real economic cost (proportional to N), so the practical severity depends on how large N needs to be to cause meaningful stall versus the cost to fund N stake accounts — this cost/benefit tradeoff was not conclusively evaluated given available context and would need further quantification (e.g., mainnet `slots_per_epoch`, current mainnet `stake_account_stores_per_block`) to assess true feasibility at scale. [6](#0-5) 

### Recommendation
Bound per-block partition size independently of the block-count cap. Options: (1) do not clamp `num_partitions` to `slots_per_epoch/10` when `total_stake_accounts` would force per-block sizes above `stake_account_stores_per_block`; instead allow more partitions/blocks (up to a hard epoch-length-based ceiling) or (2) after hashing into `num_partitions` buckets, re-split any bucket exceeding `stake_account_stores_per_block` into multiple sub-blocks, extending the distribution phase length dynamically while still respecting a maximum total distribution-phase length safeguard, and add explicit assertions/metrics alerting when the effective per-block account count computed from `hash_rewards_into_partitions` results exceeds `stake_account_stores_per_block`.

### Proof of Concept
```rust
// runtime/src/bank/partitioned_epoch_rewards/mod.rs (test module)
#[test]
fn test_get_reward_distribution_num_blocks_partition_size_unbounded() {
    let (mut genesis_config, _mint_keypair) =
        create_genesis_config(1_000_000 * LAMPORTS_PER_SOL);
    genesis_config.epoch_schedule = EpochSchedule::custom(32, 32, false);

    let mut accounts_db_config: AccountsDbConfig = ACCOUNTS_DB_CONFIG_FOR_TESTING;
    accounts_db_config.partitioned_epoch_rewards_config =
        PartitionedEpochRewardsConfig::new_for_test(10); // baseline: 10 accounts/block

    let bank = Bank::new_from_genesis(
        &genesis_config, Arc::new(RuntimeConfig::default()), Vec::new(), None,
        accounts_db_config, None, Some(SlotLeader::new_unique()), Arc::default(), None, None,
    );

    // slots_per_epoch/10 = 3 blocks max; baseline stores_per_block = 10
    // Attacker inflates total_stake_accounts far past 3*10 = 30
    let n_attacker_accounts: u64 = 100_000; // >> 30
    let stake_rewards = (0..n_attacker_accounts)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect::<PartitionedStakeRewards>();

    let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);
    assert_eq!(num_blocks, 3); // still capped at 3 blocks

    // Each block must then process ~100_000/3 ≈ 33,333 accounts,
    // more than 3000x the intended per-block baseline of 10 (or 4096 in prod),
    // demonstrating unbounded per-block work as attacker account count grows.
    let partition_indices = hash_rewards_into_partitions(
        &stake_rewards, &Hash::new_from_array([1; 32]), num_blocks as usize,
    );
    let max_partition_size = partition_indices.iter().map(|p| p.len()).max().unwrap();
    assert!(
        max_partition_size as u64 > 10 * 100, // far exceeds the configured per-block baseline
        "expected per-block partition size to be unbounded, got {max_partition_size}"
    );
}
```
Expected result: the test demonstrates that `num_blocks` remains capped at 3 while the per-block partition size (as consumed by `store_stake_accounts_in_partition`) grows linearly with attacker-controlled `total_stake_accounts`, violating the invariant that epoch-boundary per-block work is bounded independent of attacker-created accounts.

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

```rust
pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
        DistributionResults {
            stake_reward_lamports_minted,
            stake_reward_lamports_burned,
            block_reward_lamports_distributed,
            block_reward_lamports_burned,
            updated_stake_rewards,
        }
    }
