### Title
Zero `kip71.gastarget` Governance Vote Causes Division-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting All Honest Nodes — (`params/kip71_config.go` / `kaiax/gov/param.go`)

---

### Summary

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, accepting any `uint64` value including zero. A ratified governance vote setting `kip71.gastarget = 0` causes `NextMagmaBlockBaseFee` to perform `big.Int.Div(x, big.NewInt(0))` on every subsequent block whose parent consumed any gas, panicking all honest nodes and permanently halting the chain.

---

### Finding Description

**Missing zero-guard in `FormatChecker` — `kaiax/gov/param.go`**

`Kip71BaseFeeDenominator` explicitly rejects zero: [1](#0-0) 

`Kip71GasTarget` uses `noopFormatChecker`, which always returns `true`, accepting zero without restriction: [2](#0-1) 

`Kip71GasTarget` is absent from both `AlwaysDeprecated` and `PermissionlessDeprecated`, so it remains a live, voteable parameter: [3](#0-2) 

**Division-by-zero in `NextMagmaBlockBaseFee` — `params/kip71_config.go`**

The function already guards `BaseFeeDenominator == 0` with an explicit comment "To avoid panic": [4](#0-3) 

No equivalent guard exists for `GasTarget`. When `gasTarget == 0` and `parentGasUsed > 0` (the normal case in any live network), execution enters the `parentGasUsed > gasTarget` branch and panics at: [5](#0-4) 

The same panic is reachable in the `else` branch (gas used below target): [6](#0-5) 

Go's `(*big.Int).Div` panics unconditionally when the divisor is zero.

**Call sites that propagate the panic**

`NextMagmaBlockBaseFee` is called from block validation (`blockchain/block_validator.go`), block production (`work/worker.go`), and the tx-pool gas-price check (`blockchain/tx_pool.go`). A panic in any of these paths crashes the node process. [7](#0-6) 

**Governance trigger path**

In `none` governance mode any GC member casts the deciding vote for a parameter in an epoch; in `single` mode the governing node does. A vote `("kip71.gastarget", uint64(0))` passes `NewVoteData` validation (because `noopFormatChecker` returns `true`), is ratified at the next epoch block, and takes effect at the following epoch. From that point every block whose parent had `gasUsed > 0` causes a node-wide panic. [8](#0-7) 

---

### Impact Explanation

After the governance change activates, `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` panics on every block with non-zero parent gas usage. All honest nodes crash during block import, making it impossible to extend the canonical chain. This is a persistent consensus divergence / chain halt affecting all network participants. Protected state (KAIA balances, bridged assets, staking records) becomes inaccessible.

---

### Likelihood Explanation

Triggering requires a ratified governance vote. In `none` mode a single GC member can be the deciding voter; in `single` mode the governing node must act. The probability of accidental input (analogous to the "0 leverage cycles" user-error scenario in the seed report) is low but non-zero, and the consequence is irreversible without a coordinated emergency hardfork. Likelihood: **2 / 10**.

---

### Recommendation

1. **Add a zero-check to `Kip71GasTarget`'s `FormatChecker`** in `kaiax/gov/param.go`, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // reject zero to prevent division-by-zero
    },
    ...
},
```

2. **Add a defensive guard in `NextMagmaBlockBaseFee`** in `params/kip71_config.go`, consistent with the existing `BaseFeeDenominator` guard:

```go
if gasTarget == 0 {
    // To avoid panic, treat as if gas used equals target (no fee change)
    return makeEvenByFloor(parentBaseFee)
}
```

---

### Proof of Concept

1. Network runs in `none` governance mode (or attacker controls the governing node in `single` mode).
2. Cast a governance vote: `governance_vote("kip71.gastarget", 0)`. `NewVoteData` accepts it because `noopFormatChecker` returns `true`.
3. At the next epoch boundary the vote is ratified; the parameter takes effect at the following epoch.
4. The first block after activation whose parent had `gasUsed > 0` causes every node to call `NextMagmaBlockBaseFee` with `gasTarget = 0` and `parentGasUsed > 0`.
5. Execution reaches `x.Div(x, new(big.Int).SetUint64(0))` at line 102 of `params/kip71_config.go`.
6. Go runtime panics: `runtime error: integer divide by zero` (via `big.Int` internal check). All nodes crash. Chain halts permanently until an emergency patch is deployed. [9](#0-8) [2](#0-1)

**File:** kaiax/gov/headergov/README.md (L38-50)
```markdown
At every epoch block (i.e., `k*epoch` blocks), the node that becomes the proposer will check if the vote has been ratified.
If the vote is ratified, the node will announce the ratification in the block header `header.Governance`.
In other words, `header.Governance` can contain data only at epoch blocks.
If there are no votes in an epoch, the next starting block of the epoch will have an empty `header.Governance`.
It contains a JSON object of `{name: value}` for each ratified parameter.

The ratification condition is determined by the `governance.governancemode` parameter. Mainnet and Kairos both operate in `single` mode. There are two governance modes:

- `none` mode: all members of the GC can vote. For each governance parameter, the last vote in the epoch will be ratified.
- `single` mode: only one member of the GC, stipulated in the parameter `governance.governingnode`, can vote. All valid votes from the governing node in the epoch are ratified in block order. For each governance parameter, the last vote in the epoch will be ratified.

Parameter change ratified at `k*epoch` block takes effect starting from `(k+1)*epoch` block.
It is worth noting that the effective time of the ratification is `(k+1)*epoch + 1` before Kore.
```
