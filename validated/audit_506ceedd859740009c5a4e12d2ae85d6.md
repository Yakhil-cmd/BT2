### Title
Arbiter contract shared-address definition has no timeout/escape branch, permanently locking funds if the arbiter never resolves and the counterparty refuses to co-sign - (File: wallet_defined_by_addresses.js / arbiter_contract.js)

### Summary
The arbiter-contract feature builds a shared address whose spending condition only allows release of funds via (a) mutual signatures from both parties, or (b) a data-feed value posted by the designated arbiter address declaring a winner. There is no fallback path (e.g., a time-locked withdrawal) that lets either party reclaim funds if the arbiter never posts a resolution and the counterparty does not cooperate with a mutual close.

### Finding Description
`deriveSharedAddress()` builds the address definition for an arbiter contract as an `or` of five branches: mutual agreement between offeror/acceptor, two placeholder "has output" branches for a cooperative payout, and two branches requiring `["in data feed", [[arbiter_address], "CONTRACT_"+hash, "=", <party>]]`, i.e. the arbiter must post a data feed unit naming the winner. [1](#0-0) 

The two arbiter-decision branches are the only route to unilaterally move funds without the other party's signature: [2](#0-1) 

`openDispute()` sends the dispute to the arbstore/arbiter, and the contract only advances when the arbiter (or arbstore acting for it) eventually posts a decision; nothing in the contract lifecycle enforces that the arbiter must act within a bounded time. [3](#0-2) 

The only other way to move funds is `complete()`, which requires cooperative multi-signature spending built from the peer/arbstore addresses derived from the shared address definition — again requiring the cooperation of the counterparty (or a completed dispute) to construct a valid spend. [4](#0-3) 

There is no branch in the address definition, and no code path in `arbiter_contract.js`, that allows either the offeror or acceptor to reclaim the funds unilaterally after a timeout if the arbiter never posts to the data feed (e.g., the arbiter is defunct, unresponsive, or the arbstore service is discontinued) and the counterparty will not sign a mutual release. This mirrors the escrow bug: an optional/absent trusted third party (arbiter) is the sole gate to breaking a deadlock, and no emergency/time-locked withdrawal exists for the case where that third party never acts.

### Impact Explanation
If the arbiter never posts a `CONTRACT_<hash>` data feed value (whether due to going offline, being decommissioned, or simply neglecting the dispute) and the counterparty refuses to co-sign a mutual settlement, the funds held in the shared address are permanently locked with no way for either legitimate party to recover them. This is a direct fund-loss/freezing condition reachable by any wallet user who enters into an arbiter contract — a normal, expected usage of this feature — without any malicious peer, node, or hub involved.

### Likelihood Explanation
Arbiter contracts are a documented, user-facing wallet feature (`arbiter_contract.js`, paired-device messaging in `wallet.js`), so any two counterparties using it are exposed. Arbiters/arbstores are third-party services that can become unavailable (shut down, lose keys, stop operating) for entirely non-malicious reasons, and a counterparty has no incentive to cooperate once it prefers the status quo (e.g., the payer keeping funds in the shared address indefinitely). No special privileges or attacker capability are required — it is a realistic operational failure mode.

### Recommendation
Add a time-locked fallback branch to the shared-address definition produced by `deriveSharedAddress()` (e.g., an `and` of `["address", <payer_or_agreed_party>]` and a timestamp/mci-based condition activating after a configurable delay from contract creation), allowing unilateral withdrawal if the arbiter has not resolved the dispute within that window. Alternatively, require re-derivation/expiry of the shared address definition when the arbiter is unresponsive past the contract `ttl`, with the resulting funds returned to the original payer by default.

### Proof of Concept
1. Two parties (payer, payee) create an arbiter contract via `createAndSend()`/wallet UI, funding a shared address whose definition is generated by `deriveSharedAddress()`, naming `arbiter_address` as the dispute resolver.
2. Payer becomes dissatisfied and calls `openDispute()`, which forwards the case to the arbiter's arbstore.
3. The arbiter's arbstore service is discontinued, unreachable, or simply never issues a `data_feed` message for `CONTRACT_<hash>` (nothing enforces a deadline on this action).
4. The payee refuses to cooperate with a mutual `complete()`/cosign flow, since keeping funds stuck benefits them (e.g., pressuring the payer) or they are simply unresponsive.
5. Because the address definition in `deriveSharedAddress()` only allows spending via mutual signature or an arbiter-posted data feed, and neither ever occurs, the funds in the shared address remain frozen indefinitely with no available fallback transaction.

function complete(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, async function(objContract) {
		if (objContract.status !== "paid" && objContract.status !== "in_dispute")
			return cb("contract can't be completed");
		const err = await fillArbstoreAddresses(objContract);
		if (err)
			return cb(err);
		storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
			var opts;
			new Promise((resolve, reject) => {
				if (assetInfo && assetInfo.is_private) {
					var value = {};
					value["CONTRACT_DONE_" + objContract.hash] = objContract.peer_address;
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.my_address],
						signing_addresses: [objContract.my_address],
						change_address: objContract.my_address,
						messages: [{
							app: 'data_feed',
							payload_location: "inline",
							payload_hash: objectHash.getBase64Hash(value, true),
							payload: value
						}]
					};
					resolve();
				} else {
					opts = {
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						paying_addresses: [objContract.shared_address],
						change_address: objContract.shared_address,
						asset: objContract.asset
					};
					if (objContract.me_is_payer && !(assetInfo && (assetInfo.fixed_denominations || assetInfo.is_private))) { // complete
						require("./wallet_defined_by_addresses.js").readSharedAddressDefinition(objContract.shared_address, function (arrDefinition) {
							const index = objContract.is_incoming ? 2 : 1;
							const peer_amount = arrDefinition[1][index][1][1][1].amount;
							const arbstore_amount = arrDefinition[1][index][1][2] && arrDefinition[1][index][1][2][0] === 'has' ? arrDefinition[1][index][1][2][1].amount : 0;
							if (!isFinite(peer_amount) || !isFinite(arbstore_amount))
								throw new Error("invalid amounts in shared address definition: " + JSON.stringify(arrDefinition));
							if (peer_amount + arbstore_amount !== objContract.amount)
								throw new Error(`amounts in shared address definition do not sum up to contract amount: ${peer_amount} + ${arbstore_amount} !== ${objContract.amount}`);
							if (arbstore_amount > peer_amount)
								throw new Error(`arbstore cut is more than 50% of the total amount, peer_amount: ${peer_amount}, arbstore_amount: ${arbstore_amount}`);
							if (arbstore_amount === 0) {
								opts.to_address = objContract.peer_address;
								opts.amount = objContract.amount;
							} else {
								opts[objContract.asset && objContract.asset != "base" ? "asset_outputs" : "base_outputs"] = [
									{ address: objContract.peer_address, amount: peer_amount},
									{ address: objContract.arbstore_address, amount: arbstore_amount},
								];
							}
							resolve();
						});
					} else { // refund
						opts.to_address = objContract.peer_address;
						opts.amount = objContract.amount;
						resolve();
					}
				}
			}).then(() => {
				if (arrSigningDeviceAddresses.length)
					opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
				walletInstance.sendMultiPayment(opts, function(err, unit){
					if (err)
						return cb(err);
					var status = objContract.me_is_payer ? "completed" : "cancelled";
					setField(objContract.hash, "status", status, function(objContract){
						cb(null, objContract, unit);
					});
				});
			}).catch(err => {
				cb(err);
			});
		});
	});
}
