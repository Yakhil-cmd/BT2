### Title
Wrong Address Checked in `checkConsistency` for `GovernanceGoverningNode` Allows Arbitrary Non-Council Address to Be Ratified as New GoverningNode — (`kaiax/gov/headergov/impl/header.go`)

### Summary

`checkConsistency` validates the **current** `GoverningNode` against the council instead of the **proposed** new governing node (`vote.Value()`). In the normal state where the current `GoverningNode` is in the council, the check unconditionally returns `nil` for any `GovernanceGoverningNode` vote, regardless of the proposed value.

### Finding Description

In `checkConsistency` (`kaiax/gov/headergov/impl/header.go`, lines 159–178), the `GovernanceGoverningNode` case fetches the council and then checks:

```go
if slices.Contains(council, params.GoverningNode) {
    return nil
}
return ErrGovNodeNotInValSetList
```

`params.GoverningNode` is the **current** governing node, not `vote.Value()` (the proposed new one). The intended invariant — "the proposed new governing node must be a council member" — is never enforced. As long as the current `GoverningNode` is in the council (the normal state), any address can be proposed as the new `GoverningNode` and will pass validation.

Before the Permissionless fork, the voter restriction at lines 103–107 does not apply, so any council member who is the block proposer can cast this vote. After the Permissionless fork, only the `GoverningNode` itself can vote in single mode, which requires a privileged key.

### Impact Explanation

Once a `GovernanceGoverningNode` vote with a non-council address is ratified at the next epoch block, `GetParamSet` returns the new non-council address as `GoverningNode`. Since `QualifiedValidators(N) = Council(N) - DemotedValidators(N)`, a non-council address can never be a proposer. In single mode after Permissionless, only the `GoverningNode` can vote — but since it cannot be a proposer, it can never include a vote in a block header. Governance is permanently and irrecoverably locked: no parameter (including `GovernanceMode` itself) can ever be changed again.

### Likelihood Explanation

Pre-Permissionless: any single malicious council member who is selected as proposer can execute this in one block. No coordination or privileged key is required. Post-Permissionless: requires the `GoverningNode` key (out of scope per rules). The pre-Permissionless window is the exploitable surface in the code as written.

### Recommendation

Replace `params.GoverningNode` with `vote.Value().(common.Address)` in the council membership check:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)

        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    // Check the PROPOSED new governing node, not the current one
    if slices.Contains(council, vote.Value().(common.Address)) {
        return nil
    }
