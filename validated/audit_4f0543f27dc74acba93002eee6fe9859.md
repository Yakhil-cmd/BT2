### Title
Webhook signature is verified against the payload's claimed organization, but downstream handlers act on the payload's `repository.full_name` — an unchecked binding between the authenticating org and the written repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
This is the structural analog of the "unchecked transfer" class: the report is about code that trusts a value returned/asserted by an external call without validating it against the value that the caller actually depends on for correctness. Here, `WebhooksController#verify_signature` authenticates a webhook using one field of the untrusted payload (`repository.owner.login`, i.e. the organization) to select which GitHub App secret to check the HMAC against, but the actual state-mutating handlers keyed off the same payload act on a *different* field (`repository.full_name`) that is never cross-checked against the organization that was used to authenticate the request.

### Finding Description
`verify_signature` resolves the signing organization purely from attacker-controlled JSON before any authentication has occurred: [1](#0-0) 

and: [2](#0-1) 

`Shipit.github(organization: repository_owner)` selects the `webhook_secret` for whichever organization name appears at `repository.owner.login` (or `organization.login`) in the raw body, and then `verify_webhook_signature` checks the HMAC of the *entire* raw body against that org's secret: [3](#0-2) 

Because Shipit supports a multi-organization configuration (`config/secrets.development.shopify.yml`, `lib/shipit/github_app.rb:44-57`), each onboarded organization has and knows its own `webhook_secret`. A valid HMAC only proves the request was signed with *some* onboarded organization's secret and that the *exact bytes* of the body (including `repository.full_name`) are unmodified since signing — it does not prove that `repository.owner.login` (the org used to pick the secret) matches `repository.full_name` (the repository the handlers subsequently act on). Nothing in `verify_signature` or in `create` re-derives `repository_owner` from `repository.full_name` and compares them: [4](#0-3) 

An org admin who legitimately owns and knows the `webhook_secret`/App credentials for their own onboarded organization ("Org A") can therefore craft and self-sign an arbitrary JSON body in which `repository.owner.login` is set to `"Org A"` (so their own known secret validates the HMAC) while `repository.full_name` (and any other repository identifiers used by `Shipit::Webhooks` handlers to resolve the target `Stack`) is set to `"Org B/victim-repo"`, a repository that Org A has no GitHub permissions on and no `Shipit.github_teams` membership for.

### Impact Explanation
Depending on which handler is registered for the spoofed `X-Github-Event` (e.g. `push`, `status`, `check_suite`, `membership`), this crosses the "organization that authenticated versus the repository that is written" trust boundary called out as in-scope: an attacker who controls only their own organization's webhook secret can inject fabricated GitHub events (commit status/check-run updates, push notifications, membership changes) that Shipit will process as if authentically originating from Org B's repository/organization. Because CI status and check-suite results gate deploy safety checks (`required_statuses`, `hidden_statuses` in `DeploySpec`), forging these events for a victim stack can be used to spoof green CI/check status or fabricate commits for a repository the attacker does not control, i.e. cross-repository writes into another tenant's Shipit state and manipulation of deploy-gating signals — without ever holding a Shipit session, an `ApiClient` token, or write access to the victim repository.

### Likelihood Explanation
Requires only that the attacker legitimately administers (or is handed webhook credentials for) any one organization onboarded to the same multi-tenant Shipit instance — no privileged access to the target organization/repository, no Shipit session, and no interception of TLS is needed. The only "cost" is crafting a raw JSON body and computing an HMAC-SHA1 with a secret the attacker already possesses for their own org.

### Recommendation
After `verify_webhook_signature` succeeds, re-derive the organization from the same fields the downstream handler will use to resolve the target repository/stack (e.g., require `params.dig('repository','full_name')` to start with `"#{repository_owner}/"`, or resolve the target `Stack`/`Repository` first and confirm its `owner` equals `repository_owner`) and reject (422) on mismatch before dispatching to `Shipit::Webhooks.for_event(event)`.

### Proof of Concept
```
POST /github_webhooks HTTP/1.1
X-Github-Event: push
X-Hub-Signature: sha1=<HMAC-SHA1 of body below using Org A's known webhook_secret>

{
  "repository": {
    "full_name": "Org B/victim-repo",
    "owner": { "login": "Org A" }
  },
  "after": "<attacker chosen sha>",
  "ref": "refs/heads/master"
}
```
`verify_signature` resolves `repository_owner` = `"Org A"`, fetches Org A's `webhook_secret`, and the signature validates (attacker knows this secret). `create` then dispatches to the `push` handler which resolves the stack from `repository.full_name` = `"Org B/victim-repo"`, processing the forged event against Org B's stack. # frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
