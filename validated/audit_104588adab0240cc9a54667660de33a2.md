### Title
Permissionless third-party supply top-ups keep insolvent accounts above the bad-debt dust cap, indefinitely blocking `clean_bad_debt` — (File: contracts/controller/src/positions/liquidation/mod.rs)

### Summary
`clean_bad_debt` is the only permissionless path that socializes an insolvent account's residual debt, and it admits an account only when its remaining collateral is at or below a fixed ~$5 WAD dust cap (`is_socializable_bad_debt`, `BadDebtGate::DustCapped`). Separately, `supply` allows any unprivileged caller to top up a supply position on a foreign account as long as the account already holds that hub asset (`require_third_party_existing_supply` only rejects assets not already present). Combining the two, an attacker can repeatedly push a target insolvent account's `total_collateral` above the dust threshold, causing every `clean_bad_debt` call to revert with `CannotCleanBadDebt` and forcing reliance on the owner-gated `force_socialize_bad_debt` runbook. [1](#0-0) [2](#0-1) 

### Finding Description
`socialize_bad_debt` loads the account, computes `AccountRiskTotals`, and for the permissionless gate requires `is_socializable_bad_debt(total_debt, total_collateral)` — insolvent *and* collateral at or below `BAD_DEBT_USD_THRESHOLD` (~5 USD WAD). Any excess collateral fails the gate with `CollateralError::CannotCleanBadDebt`. [3](#0-2) 

The admission check in `process_deposit` → `require_third_party_existing_supply` confirms that a non-owner, non-delegate caller can add collateral to a foreign account for every hub asset already in `account.supply_positions`, and `merge_supply_leg` then credits the position — raising `total_collateral`. This is confirmed by harness tests: `try_supply_to_account(BOB, ALICE, "USDC", 1.0)` succeeds and increases Alice's collateral, and INV-AUTH-03 documents that third-party supply "can only top up supply assets already held". [4](#0-3) [5](#0-4) [6](#0-5) 

A typical insolvent account holds residual supply collateral, so the pre-existing-leg constraint is nearly always satisfiable. After each partial liquidation drains collateral back toward the cap, the attacker tops it up again; the donated funds are simply seized as revenue on eventual cleanup, so the griefer pays a bounded amount (~$5 scale) per cycle while permissionless socialization stays bricked.

### Impact Explanation
While the grief holds, no unprivileged keeper can socialize the bad debt: `clean_bad_debt` reverts, and `execute_bad_debt_cleanup`'s supply-index write-down never runs. The underwater account keeps accruing interest against suppliers, deepening the shortfall that is eventually written down on suppliers when cleanup finally occurs via the privileged `force_socialize_bad_debt`. The result is sustained deferral of bad-debt socialization — growth of protocol insolvency and temporary freezing of the cleanup path — reachable by a single unprivileged address with modest recurring cost, matching the CVE-2023-31622 class (crafted input causing sustained denial of a protocol function). [7](#0-6) [8](#0-7) 

### Likelihood Explanation
Medium. Prerequisites: a target account that is insolvent with at least one existing supply position — the common shape of a bad-debt candidate, since cleanup deliberately leaves residual collateral. Cost is one `supply` call of roughly the dust-cap value per round; the attacker cannot reclaim the top-up, so sustained griefing costs real funds, but each round is cheap and liquidation rounds that push collateral below the cap can be re-griefed immediately. No flash loan, privileged role, or timing window is needed — `supply` is caller-auth only and `clean_bad_debt` is permissionless. [9](#0-8) [10](#0-9) 

### Recommendation
Constrain third-party top-ups on insolvent or near-dust accounts: e.g., inside `process_deposit`, when the caller is neither owner nor delegate and the account's debt exceeds collateral (or after a risk check), reject the top-up or cap it so `total_collateral` cannot be pushed above `BAD_DEBT_USD_THRESHOLD`. Alternatively, change the bad-debt gate to compare `total_collateral` against the dust cap *net of* the just-supplied amounts, or accept an optional `max_collateral_wad` argument on `clean_bad_debt` so the cleaner can bound the collateral it agrees to socialize. Short of code changes, document the griefing vector and the operational dependence on `force_socialize_bad_debt` so monitoring triggers the governed runbook promptly.

### Proof of Concept
1. Alice's account is insolvent: debt $10, collateral reduced to ~$4 by partial liquidations — `clean_bad_debt` would now succeed (collateral ≤ $5 dust cap, `test_closed_market_still_allows_bad_debt_cleanup` shape).
2. Attacker Bob calls `controller.supply(caller=Bob, account_id=alice_id, spoke_id=alice_spoke, assets=[(hub_asset(usdc), 2_000_000)])` — 2 USDC into Alice's existing USDC supply leg. `require_third_party_existing_supply` passes because `supply_positions` contains `usdc`; `merge_supply_leg` credits it. [11](#0-10) 
3. Alice's `total_collateral` is now ~$6 > $5 cap. Any keeper's `clean_bad_debt(caller, alice_id)` reverts with `CannotCleanBadDebt` (#114) at the `assert_with_error!(env, admits, ...)` gate. [12](#0-11) 
4. Each time liquidation or price movement brings collateral back under the cap, repeat step 2. Permissionless socialization remains bricked; only the owner-gated `force_socialize_bad_debt` can close the account, while interest accrues on the bad debt.

Caveat: severity is bounded because the attacker donates real tokens each round and a privileged fallback exists, and the threat model acknowledges that accounts above the dust cap "may require the governed force-socialize runbook" — though the attacker-controlled variant of pushing an account above the cap is not a documented mitigation. [13](#0-12)

fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

/// Socializes debt exceeding collateral without a dust cap, outside flash loans.
pub(crate) fn process_force_socialize_bad_debt(env: &Env, account_id: u64) {
    validation::require_not_flash_loaning(env);
    socialize_bad_debt(env, account_id, BadDebtGate::InsolventOnly);

fn require_third_party_existing_supply(
    env: &Env,
    account_id: u64,
    resolved_account_id: u64,
    caller: &Address,
    account: &Account,
    aggregated: &AggregatedPayments,
) {
    if account_id != 0
        && !account::is_owner_or_delegate(env, resolved_account_id, caller, &account.owner)
    {
        for (hub_asset, _) in aggregated.iter() {
            assert_with_error!(
                env,
                account.supply_positions.contains_key(hub_asset.clone()),
                GenericError::NotAuthorized
            );
        }
    }
}

/// Checks supply entry gates and credits measured pool receipts.
pub(crate) fn process_deposit(
    env: &Env,
    caller: &Address,
    account: &mut Account,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    validate_position_entry_gates(
        env,
        account,
        aggregated,
        cache,
        AccountPositionType::Deposit,
    );
    let pool_addr = cache.cached_pool_address();
    let mut entries: Vec<PoolSupplyEntry> = Vec::new(env);
    for (hub_asset, amount_in) in aggregated.iter() {
        let asset_config: AssetConfig = cache.require_spoke_asset(account.spoke_id, &hub_asset);
        let received = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            caller,
            &pool_addr,
            amount_in,
            GenericError::AmountMustBePositive,
        );
        let position = account.get_or_create_supply_position(&hub_asset, &asset_config);
        entries.push_back(PoolSupplyEntry {
            action: make_pool_action(&position, received, hub_asset.clone()),
        });
    }

    let results = pool_supply_call(env, &pool_addr, &entries);
    for_each_leg(env, &entries, &results, |entry, result| {
        merge_supply_leg(env, account, &entry.action, &result, cache);
    });

### INV-AUTH-03 — Third-party supply cannot create a foreign asset slot

Authenticated third parties can repay, liquidate, recapitalize and perform
permissionless maintenance. Supply to an existing foreign account can only top
up supply assets already held; it cannot create a new asset slot.

Policy refresh and liquidation have separate gates. Permissionless access does

pub(crate) fn execute_bad_debt_cleanup(
    env: &Env,
    cache: &mut Context,
    account_id: u64,
    account: &Account,
    totals: &AccountRiskTotals,
) {
    let mut entries: Vec<PoolSeizeEntry> = Vec::new(env);
    for (hub_asset, position) in iter_typed_positions(&account.supply_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Supply,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Deposit,
            position: (&position).into(),
        });
    }
    for (hub_asset, position) in iter_debt_positions(&account.borrow_positions) {
        cache.apply_spoke_exit(
            account.spoke_id,
            UsageSide::Borrow,
            &hub_asset,
            position.scaled_amount,
        );
        entries.push_back(PoolSeizeEntry {
            hub_asset,
            side: AccountPositionType::Borrow,
            position: (&position).into(),
        });
    }
    let pool_addr = cache.cached_pool_address();
    pool_seize_positions_call(env, &pool_addr, &entries);

    cache.persist_spoke_usage();

    CleanBadDebtEvent {
        account_id,
        total_borrow_usd_wad: totals.total_debt.raw(),
        total_collateral_usd_wad: totals.total_collateral.raw(),
    }
    .publish(env);

    remove_account_and_burn_nft(env, account_id);
