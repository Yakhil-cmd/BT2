### Title
Stack-Scoped API Token Can Read Any Stack's CCMenu Status - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Api::CCMenuController#stack` bypasses the stack-scoping enforced by `Api::BaseController`, allowing an `ApiClient` token that is authorized (`stack_id`) for one stack to read CCMenu deploy-status data for *any* stack in the installation.

### Finding Description
`Shipit::Api::BaseController` defines the authorization binding: an `ApiClient` scoped to a stack must only ever resolve `stack`/`stacks` to that stack: [1](#0-0) 

This is the mechanism that turns `require_permission :read, :stack` into a per-record check — `check_permissions!` only validates the operation/scope name ("read:stack"), not which stack, so the actual authorization boundary lives entirely in `#stacks`/`#stack`: [2](#0-1) 

`Api::CCMenuController` inherits from `BaseController` and declares `require_permission :read, :stack`, but overrides the private `#stack` method to bypass the scoped lookup entirely and resolve directly against the global `Stack` table using the caller-supplied `params[:stack_id]`: [3](#0-2) 

The binding that should hold is: `stack the token authorizes == stack the controller touches`. Before the fix this holds for every other API controller that uses the inherited `#stack`/`#stacks` methods (e.g. `StacksController`), but `CCMenuController` breaks it — `Stack.from_param!(params[:stack_id])` ignores `current_api_client.stack_id`, so the equality collapses to "any stack the caller names in the URL," independent of what the token was actually issued for.

### Impact Explanation
Any valid `ApiClient` token — including one deliberately scoped to a single stack (e.g. one minted by `CCMenuUrlController` for read-only CCMenu access, `app/controllers/shipit/ccmenu_url_controller.rb:15-18`) — can be replayed against `Api::CCMenuController#show` with a different `stack_id` to read that other stack's deploy activity/status (`running?`, last build status/label/time, web URL) rendered by the `ccmenu/project` view. This is an unauthorized cross-stack read of deploy state, matching the accepted High-impact class "unauthenticated/escalated read of stack state or deploy output" — here achieved by escalating a single-stack-scoped credential into a read of arbitrary stacks.

### Likelihood Explanation
Exploitation only requires possession of any valid `ApiClient` authentication token (via Basic Auth header or `?token=` query param, both supported by `CCMenuController#authenticate_api_client`) plus knowledge/guessing of another stack's `owner/name/environment` param — no GitHub write access, webhook secret, or privileged account needed. Stack-scoped CCMenu tokens are routinely generated and shared for CI dashboard integrations (`CCMenuUrlController`), making this a realistic, low-effort escalation path for any holder of such a token.

### Recommendation
Remove the `#stack` override in `Api::CCMenuController` (or reimplement it using the inherited, scope-aware `#stacks` collection) so CCMenu lookups honor `current_api_client.stack_id` the same way every other API controller does:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

### Proof of Concept
1. Obtain a stack-scoped CCMenu token for `stack_a` (e.g. via `GET /stacks/:owner/:name/:env/ccmenu_url`, which creates an `ApiClient` with `stack_id = stack_a.id` and `permissions: ['read:stack']`) — `app/controllers/shipit/ccmenu_url_controller.rb:15-18`.
2. Call `GET /api/stacks/:owner_b/:name_b/:env_b/ccmenu.xml?token=<stack_a_token>` (or via Basic Auth header) targeting `stack_b`, a completely different stack the token was never scoped to.
3. `Api::CCMenuController#authenticate_api_client` successfully authenticates the token; `require_permission :read, :stack` passes because it only checks the permission name, not the stack; `#stack` resolves `stack_b` directly via `Stack.from_param!`, bypassing the `stacks` scope check that would have raised `ActiveRecord::RecordNotFound` for a stack outside the token's `stack_id`.
4. The response renders `stack_b`'s deploy activity, last build status/label/time and web URL — data the token was never authorized to see.
