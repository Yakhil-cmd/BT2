### Title
Webhook signature is verified against `repository.owner.login`, but the repository/stack acted upon is resolved from the unauthenticated `repository.full_name` field, letting an org whose webhook secret is known trigger syncs for other orgs' stacks - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to check the HMAC against using `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`) [1](#0-0) , and derives that value with `repository_owner` [2](#0-1) . Once the signature check passes, every registered `Shipit::Webhooks::Handlers::Handler` resolves the target `Repository`/`Stack` from a **different** field in the same JSON body: `payload.dig('repository', 'full_name')` [3](#0-2) . Nothing ties these two fields together, so the equality the code implicitly assumes — `repository.owner.login == full_name.split('/').first` — is never enforced.

### Finding Description
In Shipit's multi-organization mode, each onboarded GitHub organization has its own `webhook_secret` configured in `secrets.yml`, and `Shipit.github(organization:)` looks up the app config for that specific organization to verify the signature [4](#0-3) . The webhook endpoint is a single shared route for all organizations, and the signature is computed over the entire raw JSON body using the webhook secret belonging to whichever organization is named in `repository.owner.login`.

Because the request is not proxied unmodified from GitHub for the specific target repo but is simply an unauthenticated HTTP POST accepted at a shared endpoint, anyone who legitimately knows one organization's webhook secret (e.g., the administrator of `attacker-org`, a normal onboarded but unprivileged tenant in a shared Shipit instance) can hand-craft a JSON body where:
- `repository.owner.login` = `"attacker-org"` (so `verify_signature` selects `attacker-org`'s `GitHubApp` and the HMAC computed with `attacker-org`'s known secret validates), and
- `repository.full_name` = `"victim-org/victim-repo"` (an arbitrary other repository already tracked by the shared Shipit instance).

`PushHandler` (and every other handler) resolves the target purely from `full_name`: `Repository.from_github_repo_name(repository_name)&.stacks` [5](#0-4) , then for a forged `push` event calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the attacker-chosen branch [6](#0-5) . This enqueues `GithubSyncJob` for the victim's stack with an attacker-supplied `expected_head_sha` [7](#0-6) , causing Shipit to use the victim organization's own GitHub credentials to fetch commits and update the victim stack's state, entirely outside of any real GitHub webhook delivery for that repository.

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
