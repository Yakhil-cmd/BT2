### Title
Unauthenticated stack-existence oracle via forged `referrer` in `MergeStatusController#show` - (File: app/controllers/shipit/merge_status_controller.rb)

### Summary
`MergeStatusController#show` is exempted from authentication (`skip_authentication only: %i[check show]`) and resolves the target `Stack` from an attacker-supplied `params[:referrer]` string via `ReferrerParser`, with no ownership or session check. An anonymous request can therefore probe arbitrary `owner/repo` pairs and, by comparing the resulting response body (`logged_out` template vs. empty `html: ''`), determine whether a Shipit stack exists for that repository.

### Finding Description
The broken binding: the code implicitly assumes `stack_found => current_user.authorized_for(stack.repository)`, but in reality `stack_found` is derived purely from an unauthenticated, attacker-controlled string, independent of any authorization check — i.e. `stack.present?` (a fact about a possibly-private repository) is exposed to a party for whom `current_user.authorized?` was never evaluated on this action.

Path: request to `GET /merge_status?referrer=https://github.com/victim-org/victim-repo/pull/1` (no session cookie) → `force_github_authentication` is skipped for `show` [1](#0-0)  → `#show` calls `stack` [4](#0-3)  → `#stack` builds `referrer_parser.repo_owner`/`repo_name` from `ReferrerParser.new(params[:referrer])`, which just regex-matches `https://github.com/OWNER/REPO/pull/N` with no allow-list or ownership check [5](#0-4)  → a DB lookup (`Stack.where(repositories: {owner:, name:})...first`) returns a `Stack` row if one exists for that owner/repo [6](#0-5)  → back in `#show`, if `stack` is present, response is `render('logged_out')` (a populated HTML fragment); if absent, response is `render(html: '')` (empty body) [3](#0-2) .

These two responses are observably different (`logged_out.erb` renders non-trivial markup including "Please log in to ...") [7](#0-6) , so the response variance leaks the existence (and, by varying `branch`, the specific branch/environment configuration) of a stack for any `owner/repo`, without the attacker ever authenticating or being authorized. `force_github_authentication`, which is the only place `current_user.authorized?` is checked, is bypassed entirely for this action via `skip_authentication` [8](#0-7) .

### Impact Explanation
The disclosure is limited to a boolean/existence signal (and coarse branch/environment matching) about whether a Shipit-tracked stack exists for an arbitrary `owner/repo`, and does not expose task streams, deploy output, commit content, or secrets — the `stack_status`/detailed rendering branch still requires `current_user.logged_in?` to be true, which an anonymous attacker cannot satisfy. This matches the "unauthenticated read of stack state" category at a narrow level: it discloses stack *existence/configuration presence*, not deploy output or task logs, for any repository regardless of tenant, and is trivially repeatable across arbitrary owner/repo names.

### Likelihood Explanation
No Shipit credentials, session, or GitHub permissions are required — only the ability to send an unauthenticated HTTP GET with a crafted `Referer` header or `referrer` query parameter, which matches the described attacker capability exactly. The request is cheap and fully repeatable against any number of `owner/repo` combinations, requiring no special repository or Shipit configuration beyond the target stack existing in the Shipit instance.

### Recommendation
Do not resolve or touch any `Stack` record for anonymous users before the authorization/login check; instead check `current_user.logged_in?` first and short-circuit to `render('logged_out')` before invoking `stack`/`referrer_parser`, or otherwise ensure the branching logic yields identical response bodies for "stack absent" and "stack present but unauthenticated" cases (e.g., always render the same generic response when not logged in, regardless of the underlying lookup outcome).

### Proof of Concept
Minitest plan (`test/controllers/shipit/merge_status_controller_test.rb`, no live GitHub required):
1. Create a `Stack`/`Repository` fixture for `owner: 'victim-org', name: 'victim-repo'` (e.g. `production` environment).
2. Without setting any session (`session[:user_id]` absent so `current_user` is `AnonymousUser`), perform `get :show, params: { referrer: 'https://github.com/victim-org/victim-repo/pull/1' }`.
3. Assert `response.body` matches/contains the `logged_out` template content (e.g., `assert_match(/Please log in/, response.body)`).
4. Repeat with `referrer: 'https://github.com/nonexistent-org/nonexistent-repo/pull/1'` and assert `response.body` is empty (`assert_equal('', response.body)`), demonstrating that the two anonymous responses diverge based solely on stack existence, proving the binding `stack_found == current_user.authorized?` does not hold — existence is observable without authorization.
