### Title
Delegated position manager can redirect a user's borrowed and collateral funds to an arbitrary address - (File: contracts/controller/src/positions/debt.rs)

### Summary
Analogous to the Documenso report (a limited-scope ASSISTANT role performing an action reserved for the signer), XOXNO Lending's delegate/position-manager role is meant to *manage* an account on the owner's behalf, but `borrow` and `withdraw` let that role set an arbitrary payout `to` address. The only recipient check is `require_external_recipient`, which merely rejects the pool and controller contracts — it never requires `to` to be the account owner. A delegate can therefore drain collateral and originate borrows paid to itself, converting a scoped management grant into full theft of the owner's funds.

### Finding Description
- `Controller::borrow(caller, account_id, borrows, to)` and `Controller::withdraw(caller, account_id, withdrawals, to)` authenticate via `require_owner_or_delegate`, which admits any active governance-approved position manager listed in the account's delegates [1](#0-0) .
- `process_borrow` computes `recipient = to.unwrap_or_else(|| caller.clone())` and pays that address; the only gate is `require_external_recipient` [2](#0-1) .
- `process_withdraw` does the same for collateral [3](#0-2) .
- `require_external_recipient` only rejects the pool and the controller itself; any other address, including the delegate's own, is accepted [4](#0-3) .
- Like the Documenso V1 path that lets an assistant fill any field type (where V2 blocks SIGNATURE fields), this path grants the weaker role the same fund-moving capability as the owner, with no check that proceeds return to the owner.

### Impact Explanation
Theft of user funds. Any address the owner added as a delegate (which must only be an "active position manager", not a trusted owner-level party) can call `withdraw` with `to = delegate_address` to take all supplied collateral down to the solvency floor, and `borrow` with `to = delegate_address` to take borrowed assets, leaving the owner with the debt. Delegation is intended for strategy management (multiply, swaps), not for receiving payouts; nothing in the code bounds `to` to the owner.

### Likelihood Explanation
Medium. Exploitation requires the victim to have granted a delegate entry and the delegate to remain an active position manager. Once granted — e.g., a user opting into a third-party "managed position" service that later turns malicious or is compromised — the theft path is a single unprivileged call. Governance-approved manager status limits the attacker set, but a malicious or compromised approved manager can drain every delegating account.

### Recommendation
In `process_borrow` and `process_withdraw`, when `caller != account.owner`, force the recipient to `account.owner` (or reject `to` values that are neither the owner nor the caller's controller-internal flows). Alternatively restrict `to` to the owner unconditionally, matching the trust model that delegates manage positions but do not take possession of funds.

### Proof of Concept
1. Owner `O` creates an account via `supply`, supplies USDC collateral, and calls `add_delegate(account_id, M)` where `M` is an active registered position manager.
2. `M` calls `withdraw(caller=M, account_id, withdrawals=[(usdc_key, 0)], to=Some(M))`. `require_owner_or_delegate` passes (M is a listed active delegate), `require_external_recipient` passes (M is not pool/controller), and the full collateral position is paid to `M`.
3. `M` calls `borrow(caller=M, account_id, borrows=[(eth_key, X)], to=Some(M))`; borrowed ETH is paid to `M` while the debt stays on `O`'s account.
4. Result: `O`'s collateral and borrowing capacity are stolen by the limited-privilege delegate.

Caveat: this assumes delegates paying arbitrary `to` is not a deliberate ADR choice; docs/reference materials describe delegates only as "acting on behalf of" the owner, and I did not find documentation sanctioning delegate-directed payouts, but the decisions docs were not fully searched.

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}

pub(crate) fn require_external_recipient(env: &Env, cache: &mut Context, recipient: &Address) {
    let pool = cache.cached_pool_address();
    assert_with_error!(
        env,
        *recipient != env.current_contract_address() && *recipient != pool,
        FlashLoanError::InvalidFlashloanReceiver
    );
}
