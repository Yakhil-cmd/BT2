### Title
Unbounded `reward.mintingamount` Governance Parameter Allows Arbitrary KAIA Minting Per Block — (`kaiax/gov/param.go`)

### Summary

The `RewardMintingAmount` governance parameter uses `noopFormatChecker`, imposing no upper bound (and no non-negative check) on the voted value. In `"none"` governance mode, any council member who becomes block proposer can ratify an astronomically large minting amount, causing every subsequent block to mint an unbounded quantity of KAIA and distribute it to validators and funds via `FinalizeState`.

### Finding Description

`RewardMintingAmount` is defined in `kaiax/gov/param.go` with `FormatChecker: noopFormatChecker`, which unconditionally returns `true`: [1](#0-0) 

The `noopFormatChecker` itself: [2](#0-1) 

The `bigIntCanonicalizer` accepts any parseable decimal string, including arbitrarily large values and negative values: [3](#0-2) 

The `checkConsistency` function in `VerifyVote` explicitly places `RewardMintingAmount` in the "no additional checks" branch, returning `nil` without any consistency validation: [4](#0-3) 

By contrast, `RewardMinimumStake` and `RewardStakingRewardThreshold` both have `FormatChecker` functions that at minimum enforce `v.Sign() >= 0`: [5](#0-4) [6](#0-5) 

`RewardMintingAmount` has neither a non-negative check nor an upper bound.

In `"none"` governance mode, `VerifyVote` only requires the voter to be a council member and the block proposer: [7](#0-6) 

The single-mode restriction (`ErrVotePermissionDenied`) only applies post-Permissionless hardfork when `GovernanceMode == "single"`. In `"none"` mode, any council member who proposes a block can embed a vote for `reward.mintingamount = <huge value>` in `header.Vote`.

After the epoch ends, the ratified value is written to `header.Governance` and becomes the effective `MintingAmount` used in `NewRewardConfig`: [8](#0-7) 

Every subsequent block then mints the unbounded amount and distributes it via `state.AddBalance`: [9](#0-8) 

The minting amount flows directly into reward calculation without any cap: [10](#0-9) 

### Impact Explanation

A council member in `"none"` governance mode can ratify `reward.mintingamount` set to an arbitrarily large `*big.Int` (e.g., `2^200`). Starting from the next epoch, every block mints that quantity of KAIA and distributes it to validators and ecosystem funds via `state.AddBalance`. This constitutes unauthorized minting of KAIA at a rate that would immediately hyperinflate the token supply, destroying its economic value. The corrupted `MintingAmount` persists in the governance history and affects all subsequent blocks until another governance vote overrides it.

### Likelihood Explanation

In `"none"` governance mode (the default `DefaultValue: "none"` in `param.go`), any council member who becomes block proposer can trigger this with a single vote. On Kaia Mainnet, the mode is `"single"` (immutable), restricting the trigger to the governing node (a privileged actor). However, any chain or testnet that launched with `"none"` mode is fully exposed to any validator. The `GovernanceGovernanceMode` parameter is in `AlwaysDeprecated`, so the mode cannot be changed via governance votes, making the exposure permanent for `"none"`-mode chains. [11](#0-10) 

### Recommendation

Add a `FormatChecker` for `RewardMintingAmount` that enforces at minimum non-negativity and optionally a protocol-defined maximum (e.g., matching the current mainnet minting amount multiplied by a safety factor):

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok {
            return false
        }
        // Must be non-negative and below a reasonable cap
        return v.Sign() >= 0 && v.Cmp(maxMintingAmount) <= 0
    },
    ...
},
```

Additionally, add a consistency check in `checkConsistency` for `RewardMintingAmount` to reject values that exceed a configurable maximum, analogous to the existing `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` cross-parameter checks.

### Proof of Concept

1. Deploy a chain with `governance.governancemode = "none"` (the default).
2. As any council member, call `governance_vote("reward.mintingamount", "999999999999999999999999999999999999999999999999999999999999")` when the node is the block proposer. The vote passes `NewVoteData` (bigIntCanonicalizer succeeds, noopFormatChecker returns true) and `VerifyVote` (no consistency check for RewardMintingAmount).
3. Wait for the epoch to end. The ratified value is written to `header.Governance` and stored.
4. From the next epoch onward, `NewRewardConfig` reads `MintingAmount = 10^60`, and `FinalizeState` calls `state.AddBalance(proposerAddr, 10^60_kei)` every block.
5. The KAIA total supply is inflated by `10^60` kei per block, effectively minting unlimited KAIA to validators and funds. [12](#0-11) [13](#0-12)

```go
func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
```

```go
func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
```
