### Title
Push webhook signature verified against `repository.owner.login` while target Stack resolved from unrelated `repository.full_name`, enabling cross-tenant `sync_github` forgery - ([File: app/models/shipit/webhooks/handlers/push_handler.rb])

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp`/`webhook_secret` to validate the HMAC using `repository.owner.login` from the payload, but `Handler#stacks` (used by `PushHandler#process`) resolves the target `Repository`/`Stack` using the independent `repository.full_name` field. Because these two fields are never cross-checked, an attacker who legitimately owns an org configured in this multi-tenant Shipit instance can sign a webhook with their own `webhook_secret` while pointing `full_name` at a victim's repository, forcing `Stack#sync_github` to run against the victim's stack with an attacker-chosen `expected_head_sha`.

### Finding Description
The binding the system relies on is: `organization_that_signed(payload) == organization_owning_stack(payload)`, i.e. `params.dig('repository','owner','login') == extract_owner(params.dig('repository','full_name'))`. This binding is never enforced.

Path:
1. `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (line 61) and fetches the corresponding `GitHubApp` via `Shipit.github(organization: repository_owner)`, then verifies the HMAC signature against that org's `webhook_secret` (`lib/shipit/github_app.rb#verify_webhook_signature`, line 76-83).
2. Once verified, `WebhooksController#create` dispatches the parsed payload to `Shipit::Webhooks.for_event(event)` handlers, including `PushHandler`.
3. `PushHandler#process` (app/models/shipit/webhooks/handlers/push_handler.rb:12-17) calls `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }`.
4. `stacks` is defined in `Handler#stacks` (app/models/shipit/webhooks/handlers/handler.rb:32-38) as `Repository.from_github_repo_name(repository_name)&.stacks`, where `repository_name = payload.dig('repository', 'full_name')` — a completely separate payload field from the one used for signature verification.

An attacker who owns `Org-Attacker` (and therefore knows `Org-Attacker`'s `webhook_secret`, as configured in this multi-tenant setup) can send:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "Org-Attacker" },
    "full_name": "Org-Victim/prod-app"
  }
}
```
signed with `Org-Attacker`'s secret. `verify_signature` succeeds because it only checks the payload against `Org-Attacker`'s app config. `PushHandler` then resolves the actual `Repository`/`Stack` from `full_name = "Org-Victim/prod-app"`, entirely bypassing any tie to the organization that actually authenticated the request, and invokes `sync_github(expected_head_sha: <attacker-chosen-sha>)` on the victim's `main` stack.

No existing guard prevents this: `verify_signature` never re-checks `repository.full_name`'s owner against `repository_owner`; `drop_unhandled_event` and the `ExplicitParameters` schema for `PushHandler` only validate presence of `ref`/`after`, not repository identity; and `Handler#stacks`/`Repository.from_github_repo_name` perform no ownership cross-validation either.

### Impact Explanation
This is a payload for one tenant (Org-Attacker) mutating another tenant's (Org-Victim) `Stack` state — `sync_github` is invoked with an attacker-controlled `expected_head_sha` on a repository/stack the attacker does not own and never authenticated for. This matches the Critical category: "a payload for one repository mutating another's stack." The attack is repeatable against any `branch` of any stack in the instance simply by changing `full_name` and `ref` in the forged payload, as long as the attacker signs with their own legitimate org secret. Depending on what `sync_github` does downstream (updating `Stack#locked?`/HEAD tracking used later for deploy eligibility), this can influence deploy-eligible state for an arbitrary victim stack across tenant boundaries.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured in multi-tenant mode (`Shipit.github_organizations`/per-org `webhook_secret` config, i.e. `github_default_organization` non-nil), and the attacker must control at least one legitimately configured organization (`Org-Attacker`) in that same Shipit instance, which by the stated attacker model ("owns Org-Attacker with its own webhook_secret") is granted. No Shipit session, API token, or victim secrets are required. Cost is a single crafted HTTP POST to `/webhooks` with a valid HMAC computed from the attacker's own known secret — trivially feasible and fully repeatable.

### Recommendation
In `WebhooksController#verify_signature`, additionally validate that `repository.full_name`'s owner segment matches `repository.owner.login` (the value used to select the `webhook_secret`), rejecting the webhook (422) if they diverge. Alternatively, in `Handler#stacks`, take the verified `repository_owner` as an explicit parameter from the controller and assert it matches the owner segment of `repository.full_name` before resolving `Repository.from_github_repo_name`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "push webhook signed by attacker org cannot sync a victim org's stack" do
  attacker_secret = 'attacker-secret'
  Shipit.expects(:github).with(organization: 'Org-Attacker').returns(
    Shipit::GitHubApp.new('Org-Attacker', webhook_secret: attacker_secret)
  )

  victim_repo = shipit_repositories(:shipit) # owned by Org-Victim
  victim_stack = victim_repo.stacks.create!(environment: 'production', branch: 'main')

  Shipit::Stack.any_instance.expects(:sync_github).with(expected_head_sha: 'attacker-sha').once

  payload = {
    ref: 'refs/heads/main',
    after: 'attacker-sha',
    repository: {
      owner: { login: 'Org-Attacker' },
      full_name: "#{victim_repo.owner}/#{victim_repo.name}"
    }
  }.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', attacker_secret, payload)

  post :create, body: payload, params: {}, headers: {
    'X-Github-Event' => 'push',
    'X-Hub-Signature' => signature,
    'Content-Type' => 'application/json'
  }

  assert_response :ok
  # Assertion demonstrates the binding organization_that_signed('Org-Attacker') ==
  # organization_owning_stack('Org-Victim') is false, yet sync_github still ran.
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
