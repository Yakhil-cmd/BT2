### Title
Cosigner/Correspondent Name Spoofing via Insufficient Whitespace Sanitization Enables Impersonation of Trusted Contacts in Multi-Device Wallets - (File: wallet_defined_by_keys.js)

### Summary
The OnionShare bug allowed a chat participant to impersonate another by renaming to `Alice ` (name plus trailing/invisible whitespace) — the sanitizer stripped nothing but display was indistinguishable. `ocore` has the same class of bug in the paired-device correspondent-naming code paths: device names and cosigner names supplied by a remote paired device are sanitized only by stripping `<`/`>` characters, never whitespace, control or invisible unicode characters, and are never bound to an existing correspondent's known device_address. A malicious paired device can therefore present itself (or a co-signer entry) under a name that is visually identical to an already-trusted correspondent (e.g. `"Alice "`), tricking the user into approving a multi-signature wallet that they believe includes their real contact "Alice", while the actual signing key belongs to the attacker.

### Finding Description
Two related sinks accept attacker-controlled human-readable names without adequate normalization:

1. `device.js` `handlePairingMessage()` only strips HTML tags from the incoming `device_name`, not whitespace or non-printable/invisible characters, before storing it as the correspondent's display `name`: [1](#0-0) 

2. `wallet_defined_by_keys.js` `handleOfferToCreateNewWallet()` receives a `wallet_definition_template` plus a `other_cosigners` array (`{pubkey, device_address, name, hub}`) from a remote peer proposing a shared multi-sig wallet. The sender is free to set `cosigner.name` to anything; the only sanitization removes `<`/`>`: [2](#0-1) 

The only real check performed is that `cosigner.device_address === objectHash.getDeviceAddress(cosigner.pubkey)` (line 85) — i.e., that the pubkey/address pair is internally consistent — but there is **no check that the claimed `cosigner.name` matches any existing `correspondent_devices` record for that `device_address`**. This means the initiating device can label any of the other members (including itself) with an arbitrary display name, including the name of a contact the recipient already trusts, differing only by a trailing space or other invisible character (as in the CVE-2022-21696 report), which most UIs will render as visually identical to the real contact.

The resulting `create_new_wallet` event (emitted at line 108) is what the wallet UI uses to render the "who is joining this wallet" confirmation dialog that the user approves before a shared, multi-signature address is created — the trust decision is made based on this potentially-spoofed name.

### Impact Explanation
Because the identity check for “who is really cosigning this wallet with me” is name-based rather than bound to a known device_address, an attacker can spoof the identity of one of the user's trusted correspondents. The victim then approves creation of a multi-signature address believing a known contact (e.g. "Alice") holds one of the signing keys, when in fact the attacker's device holds it. Funds subsequently deposited to that shared address can be co-signed/spent by the attacker instead of, or together with, the intended party — a direct path to unauthorized spending / loss of custodial control over multisig funds, since the set of legitimate signers required to authorize a transaction now silently includes an attacker-controlled key.

### Likelihood Explanation
The attack requires only that the victim is willing to pair with, or receive a wallet-creation offer from, a device controlled by the attacker (e.g. via a shared pairing link/QR code, a common flow for adding new correspondents/bots) — no special privileges, and the victim only needs to recognize a name in a confirmation dialog, exactly as in the original OnionShare scenario. No cryptographic bypass is required; only convincing UI-level spoofing, which is trivial to achieve since sanitization does not strip whitespace/invisible characters.

### Recommendation
- In `handlePairingMessage()` and `handleOfferToCreateNewWallet()`, trim leading/trailing whitespace and strip other invisible/control/zero-width Unicode characters from `device_name` / `wallet_name` / `cosigner.name`, not just `<`/`>`.
- In `handleOfferToCreateNewWallet()`, cross-check each `cosigner.device_address` against the local `correspondent_devices` table; if a `device_address` is already a known correspondent, ignore/override the attacker-supplied `name` and use the locally stored name instead (never trust a remote peer's claim about a third party's identity).
- Consider normalizing (NFKC) and visually confusable-character detection before persisting or displaying any peer-supplied name field.

### Proof of Concept
1. Bob has an existing correspondent "Alice" (device_address `D_alice`).
2. Attacker (Mallory, device_address `D_mallory`) sends Bob a `create_new_wallet` device message with:
   ```
   {
     wallet: "...",
     wallet_definition_template: [...2-of-2 template...],
     wallet_name: "Family wallet",
     other_cosigners: [
       { pubkey: MalloryPubkey, device_address: D_mallory, name: "Alice ", hub: "..." }
     ]
   }
   ```
   (Note the trailing space, or any invisible Unicode character, after "Alice".)
3. `handleOfferToCreateNewWallet()` in `wallet_defined_by_keys.js` (lines 65-111) validates only that `D_mallory` matches `MalloryPubkey`, strips `<`/`>` (none present), and accepts the cosigner entry — `cosigner.name` remains `"Alice "`.
4. The `create_new_wallet` event fires with a cosigner list showing "Alice " — visually indistinguishable from Bob's real contact "Alice" — in the wallet UI's approval dialog.
5. Bob approves, believing his real contact Alice is the second signer. The resulting shared address is actually 2-of-2 between Bob and Mallory; Mallory can co-sign transactions from the shared wallet instead of, or in addition to, the real Alice.

function handleOfferToCreateNewWallet(body, from_address, callbacks){
	if (!ValidationUtils.isNonemptyString(body.wallet))
		return callbacks.ifError("no wallet");
	if (!ValidationUtils.isNonemptyString(body.wallet_name))
		return callbacks.ifError("no wallet_name");
	if (body.wallet.length > constants.HASH_LENGTH)
		return callbacks.ifError("wallet too long");
	if (body.wallet_name.length > 200)
		return callbacks.ifError("wallet_name too long");
	body.wallet_name = body.wallet_name.replace(/[<>]/g, '');
	if (!ValidationUtils.isArrayOfLength(body.wallet_definition_template, 2))
		return callbacks.ifError("no definition template");
	if (!ValidationUtils.isNonemptyArray(body.other_cosigners))
		return callbacks.ifError("no other_cosigners");
	for (var i=0; i<body.other_cosigners.length; i++){
		var cosigner = body.other_cosigners[i];
		if (!ValidationUtils.isNonemptyObject(cosigner))
			return callbacks.ifError("bad cosigner");
		if (!ValidationUtils.isStringOfLength(cosigner.pubkey, constants.PUBKEY_LENGTH))
			return callbacks.ifError("bad pubkey");
		if (cosigner.device_address !== objectHash.getDeviceAddress(cosigner.pubkey))
			return callbacks.ifError("bad cosigner device address");
		if (!ValidationUtils.isNonemptyString(cosigner.name))
			return callbacks.ifError("no cosigner name");
		if (cosigner.name.length > 100)
			return callbacks.ifError("cosigner name too long");
		cosigner.name = cosigner.name.replace(/[<>]/g, '');
		if (!ValidationUtils.isNonemptyString(cosigner.hub))
			return callbacks.ifError("no cosigner hub");
		if (cosigner.hub.length > 100)
			return callbacks.ifError("cosigner hub too long");
	}
	// the wallet should have an event handler that requests user confirmation, derives (or generates) a new key, records it, 
	// and sends the newly derived xpubkey to other members
	validateWalletDefinitionTemplate(body.wallet_definition_template, from_address, function(err, arrDeviceAddresses){
		if (err)
			return callbacks.ifError(err);
		if (body.other_cosigners.length !== arrDeviceAddresses.length - 1)
			return callbacks.ifError("wrong length of other_cosigners");
		var arrOtherDeviceAddresses = _.uniq(body.other_cosigners.map(function(cosigner){ return cosigner.device_address; }));
		arrOtherDeviceAddresses.push(from_address);
		if (!_.isEqual(arrDeviceAddresses.sort(), arrOtherDeviceAddresses.sort()))
			return callbacks.ifError("wrong other_cosigners");
		eventBus.emit("create_new_wallet", body.wallet, body.wallet_definition_template, arrDeviceAddresses, body.wallet_name, body.other_cosigners, body.is_single_address);
		callbacks.ifOk();
	});
}
