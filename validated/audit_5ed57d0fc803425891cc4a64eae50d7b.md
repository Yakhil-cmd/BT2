### Title
Skill publisher can forge `github-repo` provenance metadata to spoof trusted upstream origin - (File: pkg/cmd/skills/install/install.go)

### Summary
This is the closest reachable analog to the "NFT owner can rewrite `tokenURI`" bug class in this repository (GitHub CLI, `gh`). The `gh skill install` flow trusts self-declared, unverified metadata embedded by the *content publisher* (an unprivileged remote party) to make trust/provenance decisions and to render trust-affecting UI text, exactly as the SKALE finding lets an NFT holder rewrite the field a viewer relies on to judge the asset's authenticity.

### Finding Description
When installing a skill, `checkUpstreamProvenance` in [1](#0-0)  fetches the target skill's `SKILL.md` via the Contents API and parses its YAML frontmatter with `frontmatter.Parse` [2](#0-1) . It then reads the `metadata.github-repo` key directly out of that untrusted, attacker-authored file: [3](#0-2) 

There is no verification that this `github-repo` value is truthful — it is just a string a publisher puts in their own repo's Markdown frontmatter. Any GitHub user who can create a public repository can set `metadata.github-repo: https://github.com/<any-owner>/<any-repo>` in a `SKILL.md` file, i.e. claim an arbitrary "upstream" origin, in direct analogy to an NFT owner calling `setTokenURI` to point their token at someone else's metadata.

This forged value is used for two effects:
1. It changes the printed trust message shown to the user, e.g. `"This skill was originally published in %s"` [4](#0-3) , letting an attacker fabricate a false provenance/reputation claim (e.g., attribute their skill to a well-known, trusted org) even though the content actually being installed is the attacker's own.
2. If the user (interactively, or via `--upstream`) chooses to follow the "upstream," `gh` redirects the install target to the attacker-specified repo [5](#0-4) .

Separately, on genuine remote installs (`installSkill`), `frontmatter.InjectGitHubMetadata` does overwrite `github-repo`/`github-tree-sha`/etc. with the true source values after download [6](#0-5) [7](#0-6) , so the *final on-disk* metadata is accurate. The exposure is specifically in the pre-install `checkUpstreamProvenance` step, which reads and trusts the *original, unmodified* attacker content before any correction happens.

### Impact Explanation
An unprivileged, remote attacker (anyone who can host a repo with an `SKILL.md`) can spoof the displayed "originally published in" provenance to social-engineer a user into trusting attacker-controlled content as if it originated from a reputable source, or can lure a user (or a non-interactive `--upstream` invocation) into being redirected to install from a different attacker-chosen repository than the one the user explicitly requested. This is a trust-spoofing / social-engineering vector consistent with the "unverified content masquerading as trusted content" bug class from the report, though the blast radius is bounded: the tool already prints an explicit disclaimer that "Skills are not verified by GitHub and may contain prompt injections, hidden instructions, or malicious scripts" before/after install [8](#0-7) [9](#0-8) , so the ultimate content-execution risk is separately called out to the user regardless of the provenance claim.

### Likelihood Explanation
Moderate. Exploitation only requires publishing a public repository with a crafted `SKILL.md` frontmatter and getting a victim to run `gh skill install <attacker-repo> <skill>`; no elevated privileges, MITM, or leaked tokens are needed. The redirect behavior additionally requires the victim to accept the interactive prompt or run with `--upstream` (default install without `--upstream` in interactive mode still lets the user pick the re-publisher, and non-interactive mode without `--upstream` installs from the requested repo, not the spoofed one, per [10](#0-9) ), which somewhat limits automatic exploitation but not the provenance-message spoofing itself.

### Recommendation
Do not treat `metadata.github-repo` read from a skill's own `SKILL.md` as authoritative provenance. Either drop the "upstream" trust messaging entirely, or only trust such claims when independently corroborated (e.g., cryptographic attestation of provenance, or a signed/verified relationship between repos) rather than a plain string a publisher controls. At minimum, the UI copy should make clear that the "originally published in" claim is self-reported by the repository being installed from and not verified by GitHub.

### Proof of Concept
1. Attacker creates a public repo `attacker/evil-skills` containing `skills/git-commit/SKILL.md` with frontmatter:
   ```yaml
   ---
   name: git-commit
   description: Writes commits
   metadata:
     github-repo: https://github.com/monalisa/original-skills
   ---
   ```
   (mirrors the test fixture `republishedContent` used in [11](#0-10) , but with an attacker-chosen `github-repo` value that is unrelated to any real relationship).
2. Victim runs `gh skill install attacker/evil-skills git-commit`.
3. `checkUpstreamProvenance` fetches this file, extracts `existingRepo = "https://github.com/monalisa/original-skills"`, and prints: `"⚠ This skill was originally published in monalisa/original-skills"` [4](#0-3) .
4. The victim, trusting the false attribution, proceeds to install (or is redirected to install from) content they would not otherwise have trusted — the CLI has no way to verify the claimed relationship between `attacker/evil-skills` and `monalisa/original-skills`.

// to check if it contains github-repo metadata pointing to a different
// repository, indicating the skill was re-published from an upstream source.
// In interactive mode, the user is asked whether to install from the
// re-publisher or redirect to the upstream. Non-interactive mode always
// installs from the re-publisher.
// Returns (repo to redirect to, whether upstream was detected, error).
func checkUpstreamProvenance(opts *InstallOptions, client *api.Client, hostname string, skill discovery.Skill, commitSHA string) (ghrepo.Interface, bool, error) {
	u, err := safeurl.JoinPath("repos", opts.repo.RepoOwner(), opts.repo.RepoName(), "contents", skill.Path+"/SKILL.md")
	if err != nil {
		return nil, false, err
	}
	u.SetQuery("ref", commitSHA)
	var fileResp struct {
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(hostname, "GET", u.String(), nil, &fileResp); err != nil {
		return nil, false, nil //nolint:nilerr // best-effort check; failing to fetch is not fatal
	}
	if fileResp.Encoding != "base64" {
		return nil, false, nil
	}
	decoded, decodeErr := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(fileResp.Content)))
	if decodeErr != nil {
		return nil, false, nil //nolint:nilerr // best-effort; decode failure is not fatal
	}
	content := string(decoded)

	result, parseErr := frontmatter.Parse(content)
	if parseErr != nil || result.Metadata.Meta == nil {
		//nolint:nilerr // unparsable frontmatter means no upstream to detect
		return nil, false, nil
	}

	existingRepo, _ := result.Metadata.Meta["github-repo"].(string)
	if existingRepo == "" {
		return nil, false, nil
	}

	currentRepoURL := source.BuildRepoURL(hostname, opts.repo.RepoOwner(), opts.repo.RepoName())
	if existingRepo == currentRepoURL {
		return nil, false, nil
	}

// Parse extracts YAML frontmatter from a SKILL.md file.
// Frontmatter is delimited by --- on its own lines.
func Parse(content string) (*ParseResult, error) {
	trimmed := strings.TrimLeft(content, "\r\n")
	if !strings.HasPrefix(trimmed, delimiter) {
		return &ParseResult{Body: content}, nil
	}

	rest := trimmed[len(delimiter):]
	rest = strings.TrimLeft(rest, "\r\n")
	endIdx := strings.Index(rest, "\n"+delimiter)
	if endIdx == -1 {
		return &ParseResult{Body: content}, nil
	}

	yamlContent := rest[:endIdx]
	body := rest[endIdx+len("\n"+delimiter):]
	body = strings.TrimLeft(body, "\r\n")

	var rawYAML map[string]interface{}
	if err := yaml.Unmarshal([]byte(yamlContent), &rawYAML); err != nil {
		return nil, fmt.Errorf("invalid frontmatter YAML: %w", err)
	}

	var meta Metadata
	if err := yaml.Unmarshal([]byte(yamlContent), &meta); err != nil {
		return nil, fmt.Errorf("invalid frontmatter YAML: %w", err)
	}

	return &ParseResult{
		Metadata: meta,
		Body:     body,
		RawYAML:  rawYAML,
	}, nil
}

func InjectGitHubMetadata(content string, host, owner, repo, ref, treeSHA, pinnedRef, skillPath string) (string, error) {
	result, err := Parse(content)
	if err != nil {
		return "", err
	}

	if result.RawYAML == nil {
		result.RawYAML = make(map[string]interface{})
	}

	meta, _ := result.RawYAML["metadata"].(map[string]interface{})
	if meta == nil {
		meta = make(map[string]interface{})
	}
	delete(meta, "github-owner")
	meta["github-repo"] = source.BuildRepoURL(host, owner, repo)
	meta["github-ref"] = ref
	delete(meta, "github-sha")
	meta["github-tree-sha"] = treeSHA
	meta["github-path"] = skillPath
	if pinnedRef != "" {
		meta["github-pinned"] = pinnedRef
	} else {
		delete(meta, "github-pinned")
	}
	result.RawYAML["metadata"] = meta

	return Serialize(result.RawYAML, result.Body)
}
