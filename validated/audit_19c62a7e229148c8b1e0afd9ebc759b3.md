### Title
Asset definer can unilaterally update the `spender_attested` attestor list at no cost, invalidating counterparties' already-agreed transfers - (File: `validation.js`)

### Summary
`validateAttestorListUpdate()` lets the definer of a `spender_attested` asset post an `asset_attestors` message that replaces the entire attestor list at any time, for a trivial transaction fee, with no cooperation from or notice to holders/counterparties of that asset. Any payment of that asset that relies on the previously-published attestor list (constructed by an authorized/attested spender or destined to an attested recipient) can be invalidated by the definer changing the attestor set, mirroring the "no-cost front-run of an already-agreed term" pattern described in the Teller `updateCommitment` report.

### Finding Description
`validateAttestorListUpdate` is the only check performed before an `asset_attestors` message is accepted: [1](#0-0) 

It only requires that the message be single-authored and signed by the current `definer_address` of the asset — there is no timelock, no cap on frequency, no requirement that outstanding transactions be settled first, and no fee beyond the normal unit fee:

```
if (objUnit.authors[0].address !== objAsset.definer_address)
    return callback("attestor list can be edited only by definer");
```

This attestor list is subsequently used to gate every payment of the asset. When `spender_attested` is true, `validatePayment()` requires that at least one author be attested, and (for issues) that the issuer specifically be attested, based on the *current* attestor list as read via `storage.loadAssetWithListOfAttestedAuthors`: [2](#0-1) 

For output addresses, `validatePaymentInputsAndOutputs` additionally requires that every output address be attested at the moment of validation: [3](#0-2) 

Because the attestor list is a single mutable pointer (`storage.readAsset` always resolves to the *latest* stable `asset_attestors` unit for the asset), the definer can change who counts as "attested" between the moment a spender/recipient relies on the currently-published list (e.g. to accept a private-asset payment, or to plan a transfer to a specific counterparty) and the moment the payment is actually included and validated: [4](#0-3) 

The definer pays only the ordinary message fee, exactly the "no cost" property highlighted in the original report about `updateCommitment`.

### Impact Explanation
An asset definer can weaponize `asset_attestors` against a counterparty who is relying on the currently published attestor list to receive or transfer a `spender_attested` asset (public or private):
- Remove the counterparty's attestor (or the counterparty's own address if they were listed) right before their already-prepared payment/transfer is included, causing `"owner address is not attested"` / `"some output addresses are not attested"` failures. For private-asset payments in particular (already handed off out-of-band to the recipient per Obyte's private payment flow), this can strand/freeze the recipient's expected funds, forcing renegotiation.
- Swap in a different attestor set at the last moment so that an issue/transfer that a counterparty expected to be blocked (e.g., in a compliance/KYC-style asset) instead succeeds, or vice versa — unilaterally changing the economic/compliance terms of the deal the counterparty had agreed to.

This directly matches the "asset issuance and transfer conditions" attack surface and results in fund freezing / broken settlement for the counterparty, at zero cost to the attacker (the definer).

### Likelihood Explanation
Any asset issued with `spender_attested: true` is exposed; the definer address is always able to invoke this at will since it is a normal single-authored message with no additional restriction. No special privilege beyond being the asset definer (an "asset issuer" role explicitly in scope) is required, and the attack requires only that the definer observe or anticipate the counterparty's reliance on the current attestor list before the counterparty's transaction becomes final.

### Recommendation
Consider requiring a delay (e.g., a minimum number of stable MCIs) between an `asset_attestors` update and its effect on new payment validation, or allow spenders/recipients to pin the attestor-list version they relied on (similar to how last_ball references pin other state) so in-flight transactions cannot be invalidated by attestor list changes that occur after the payment was composed/handed off.

### Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true` and attestor list `[X]`.
2. Attestor `X` attests address `S` (spender). `S` receives/holds asset `A` and prepares a private payment to recipient `R`, relying on the fact that `S` is currently attested.
3. Before `S`'s payment unit is included and stabilized, `D` posts an `asset_attestors` message removing `X` (or replacing the list), which only requires validation in `validateAttestorListUpdate` (validation.js:2829-2848) — a single-authored message signed by `D`, costing only the normal unit fee.
4. Once `D`'s update becomes the latest stable attestor list before `S`'s payment's `last_ball_mci`, `validatePayment`/`validatePaymentInputsAndOutputs` (validation.js:2115-2122, 2630-2642) reject `S`'s payment with `"owner address is not attested"`, even though `S` was attested when the deal with `R` was struck — at no cost to `D` and no recourse for `S`/`R`.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}
