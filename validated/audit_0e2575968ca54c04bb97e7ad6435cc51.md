### Title
Cross-org webhook signature check keyed on `repository.owner.login` allows a forged `closed` event to archive another org's `ReviewStack` via `ClosedHandler` - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate a webhook against using `params.dig('repository', 'owner', 'login')`, a field fully controlled by the attacker inside the JSON body, while the handlers (`ClosedHandler`, `LabelCapturingHandler`) act on a separate, independently-controlled field, `params.repository.full_name`. An attacker who owns a legitimate GitHub App installation for their own org can sign a payload with their own valid secret while setting `repository.full_name` to a victim org's repo, causing `ClosedHandler#process` to call `review_stack.archive!` on the victim's stack. A follow-up forged `labeled` event is correctly blocked by the `!stack.archived?` guard in `LabelCapturingHandler#labeled_active_stack?` because the stack's archived state is persisted and reloaded from the database on each request.

### Finding Description
The broken binding: the code implicitly assumes `repository_owner` (used to pick the signing secret in `verify_signature`) `== owner_of(params.repository.full_name)` (used by the handler to select the target `Repository`/`Stack`). These are two independently-parsed JSON fields with no cross-validation.

- `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` reads `params.dig('repository', 'owner', 'login')` [1](#0-0) [2](#0-1) .
- `ClosedHandler#repository` and `review_stack` are built from `params.repository.full_name`, a separate JSON field [3](#0-2) .
- `ClosedHandler#process` unconditionally calls `review_stack.archive!` when `action == "closed"` [4](#0-3) [5](#0-4) .
- `ReviewStackAdapter#archive!` performs `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!` against whatever stack the `full_name`-derived scope resolves to [6](#0-5) .

Exploit flow: attacker owns `attacker-org/some-repo` with a real GitHub App installation and knows the corresponding webhook secret (because it's their own installation). They POST to `/webhooks` a hand-crafted body where `repository.owner.login = "attacker-org"` (so `verify_signature` fetches and validates against the secret they actually hold) but `repository.full_name = "victim-org/victim-repo"`, and sign the raw body correctly with `X-Hub-Signature` using their own secret. `verify_signature` passes because it only checks that the bytes match the HMAC for the org named in `repository.owner.login`, not that this org matches `repository.full_name`. `ClosedHandler` then resolves `Shipit::Repository.from_github_repo_name("victim-org/victim-repo")` and archives the victim's `ReviewStack`.

For the second, follow-up request: a forged `labeled` event with the same repository/full_name spoofing reaches `LabelCapturingHandler`. `labeled_active_stack?` requires `!stack.archived?` [7](#0-6) . Because each HTTP request instantiates a fresh `Handler`/`ReviewStackAdapter`, `stack` is looked up anew via `scope.find_by(environment:)` [8](#0-7) , which reloads the persisted `archived_at`/archived state written by the prior `archive!` call. Thus `stack.archived?` correctly reflects the DB state and blocks `capture_labels`, regardless of which org's secret signed the second request. The archived-state check is not bypassed because there is no separate in-memory/stale-state path — the guard is defense-in-depth that works as intended for this second call.

### Impact Explanation
The `closed` event lets an attacker who owns any single repository/org (with its own legitimate GitHub App installation and webhook secret) trigger `stack.archive!`, `deprovision`, and removal from the provisioning queue for a `ReviewStack` belonging to an entirely different, victim org/repository — a payload for one repository mutating another repository's stack, matching the Critical category (authorization bypass via forged webhook binding, cross-tenant stack mutation). This is repeatable against any `full_name` value the attacker chooses, as long as they hold a valid secret for the org they set in `repository.owner.login`. The `labeled` follow-up is correctly blocked; no additional escalation is confirmed there.

### Likelihood Explanation
Preconditions: attacker needs a legitimate GitHub App installation (i.e., must own/control at least one org/repo with Shipit's webhook integration enabled) and its associated webhook secret — both attainable by any unprivileged GitHub user who installs the Shipit GitHub App on their own repo, consistent with the stated attacker capability. No Shipit session, API token, or victim secrets are required. The attack is a single crafted HTTP POST with mismatched `repository.owner.login` vs `repository.full_name`, fully within attacker control, making it highly feasible and trivially repeatable against any known victim `full_name`.

### Recommendation
In `WebhooksController#verify_signature`, and in each handler's repository resolution, ensure the org used to validate the signature is bound to the same org referenced by `repository.full_name` used for stack mutation — e.g., derive both from `repository.full_name.split('/').first` consistently, or explicitly verify `repository.owner.login == repository.full_name.split('/').first` before dispatching to handlers, rejecting mismatched payloads with `head(422)`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual)
test "cross-org closed webhook archives victim stack, and follow-up labeled webhook is blocked by archived? guard" do
  attacker_org = "attacker-org"
  victim_repo  = create_repository(owner: "victim-org", name: "victim-repo")
  victim_stack = create_review_stack(repository: victim_repo, environment: "pr1")

  closed_payload = payload_parsed(:pull_request_closed)
  closed_payload["repository"]["owner"]["login"] = attacker_org      # picks attacker's real secret
  closed_payload["repository"]["full_name"]      = "victim-org/victim-repo" # targets victim stack
  closed_payload["number"] = 1

  post :create, body: closed_payload.to_json, headers: {
    'X-Github-Event' => 'pull_request',
    'X-Hub-Signature' => sign_with(attacker_org_secret, closed_payload.to_json)
  }

  assert victim_stack.reload.archived?  # Critical: cross-org archive succeeded

  labeled_payload = payload_parsed(:pull_request_labeled)
  labeled_payload["repository"]["owner"]["login"] = attacker_org
  labeled_payload["repository"]["full_name"]      = "victim-org/victim-repo"
  labeled_payload["number"] = 1
  labeled_payload["pull_request"]["labels"] = [{ "name" => "expected-label" }]

  post :create, body: labeled_payload.to_json, headers: {
    'X-Github-Event' => 'pull_request',
    'X-Hub-Signature' => sign_with(attacker_org_secret, labeled_payload.to_json)
  }

  assert_empty victim_stack.reload.pull_request.labels  # guard correctly blocked capture_labels
end
```
