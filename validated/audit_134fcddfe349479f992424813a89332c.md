**Rationale:** `TOKEN_ADDRESS` and `TOKEN_OFFER_EVENT_TYPE` in `types/src/account_config/events/token_offer_event.rs` are used exclusively to construct a static `StructTag`/`TypeTag` identifying the legacy `0x3::token_transfers::TokenOfferEvent` Move struct for event serialization/translation purposes [1](#0-0) . This constant is consumed by `storage/indexer/src/event_v2_translator.rs`'s `OfferTranslator`, which converts on-chain V2 module events back into the legacy V1 event format for the indexer/storage layer [2](#0-1) .

This code path is purely for indexing/storage event translation — it is not part of the transaction admission stack (mempool, vm-validator, VM prologue, authenticator parsing, public-key binding, or signer/multisig resolution). There is no logic here that resolves account public keys via struct tag lookup, nor any authenticator or signer-binding check that consults `TOKEN_ADDRESS`. A shadow module deployed at a different address with the same module/struct name would only affect on-chain resource resolution for that foreign account's own state (e.g., `find_resource` lookups in `api/src/accounts.rs`, which resolve resources by `(address, struct_tag)` pairs, not global struct-tag-only lookups) [3](#0-2) . It has no bearing on sender/signer authentication, replay protection, sequence/chain-id/domain binding, or fee-payer resolution during transaction admission.

Since the boundary conditions require the vulnerability to live within unprivileged transaction/authenticator/API admission logic and to break a sender/signer/replay/domain guarantee, and this symbol is confined to event-type tagging for indexer translation with no admission-time key-binding role, this falls outside the required impact set (explicitly excluded as "event-only mismatches").

impl EventV2Translator for OfferTranslator {
    fn translate_event_v2_to_v1(
        &self,
        v2: &ContractEventV2,
        engine: &EventV2TranslationEngine,
    ) -> Result<ContractEventV1> {
        let offer = Offer::try_from_bytes(v2.event_data())?;
        let struct_tag = StructTag::from_str("0x3::token_transfers::PendingClaims")?;
        let (key, sequence_number) = if let Some(state_value_bytes) =
            engine.get_state_value_bytes_for_resource(offer.account(), &struct_tag)?
        {
            let object_resource: PendingClaimsResource = bcs::from_bytes(&state_value_bytes)?;
            let key = *object_resource.offer_events().key();
            let sequence_number =
                engine.get_next_sequence_number(&key, object_resource.offer_events().count())?;
            (key, sequence_number)
        } else {
            // If the PendingClaims resource is not found, we skip the event translation to
            // avoid panic because the creation number cannot be decided.
            return Err(AptosDbError::from(anyhow::format_err!(
                "PendingClaims resource not found"
            )));
        };
        let offer_event = TokenOfferEvent::new(
            *offer.to_address(),
            offer.token_id().clone(),
            offer.amount(),
        );
        Ok(ContractEventV1::new(
            key,
            sequence_number,
            TOKEN_OFFER_EVENT_TYPE.clone(),
            bcs::to_bytes(&offer_event)?,
        )?)
    }
