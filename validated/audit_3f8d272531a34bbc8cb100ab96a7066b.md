### Title
Missing Cross-Parameter Validation Allows `GasTarget > MaxBlockGasUsedForBaseFee`, Permanently Suppressing KIP-71 Base Fee to Minimum — (File: `kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `checkConsistency` function in the header-governance module validates `Kip71LowerBoundBaseFee` against `Kip71UpperBoundBaseFee` but applies **no cross-parameter check** between `Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee`. A governance vote that sets `GasTarget > MaxBlockGasUsedForBaseFee` is accepted without error, after which `NextMagmaBlockBaseFee` can never enter the "increase" branch, causing every subsequent `header.BaseFee` to be driven to `LowerBoundBaseFee` and locked there permanently — breaking the KIP-71 fee-market and suppressing all fee burn and validator fee revenue.

---

### Finding Description

**Root cause — `checkConsistency` (`kaiax/gov/headergov/impl/header.go` lines 205–211)**

`Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee` both fall into the catch-all `return nil` branch:

```go
case gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    ...
    return nil
``` [1](#0-0) 

By contrast, `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` each have explicit cross-parameter guards:

```go
case gov.Kip71LowerBoundBaseFee:
    if vote.Value().(uint64) > params.UpperBoundBaseFee { return ErrLowerBoundBaseFee }
case gov.Kip71UpperBoundBaseFee:
    if vote.Value().(uint64) < params.LowerBoundBaseFee { return ErrUpperBoundBaseFee }
``` [2](#0-1) 

No analogous guard exists for `GasTarget ≤ MaxBlockGasUsedForBaseFee`.

Both parameters also carry `noopFormatChecker` (always `true`), so no per-field range check catches the violation either:

```go
Kip71GasTarget:                { FormatChecker: noopFormatChecker, ... }
Kip71MaxBlockGasUsedForBaseFee:{ FormatChecker: noopFormatChecker, ... }
``` [3](#0-2) 

**Broken invariant — `NextMagmaBlockBaseFee` (`params/kip71_config.go` lines 77–92)**

```go
gasTarget    := kc.GasTarget
upperGasLimit := kc.MaxBlockGasUsedForBaseFee

parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)   // ≤ MaxBlockGasUsedForBaseFee
if parentGasUsed == gasTarget { ... }
else if parentGasUsed > gasTarget { /* INCREASE baseFee */ }
else { /* DECREASE baseFee */ }
``` [4](#0-3) 

When `GasTarget > MaxBlockGasUsedForBaseFee`:

- `parentGasUsed = min(parentHeaderGasUsed, MaxBlockGasUsedForBaseFee)` is always **strictly less than** `GasTarget`.
- The `parentGasUsed > gasTarget` branch is **unreachable**.
- Every block computes a decreasing base fee until it hits `LowerBoundBaseFee` and stays there forever.

**Corrupted value**: `header.BaseFee` is permanently set to `LowerBoundBaseFee` (e.g., 25 Gwei) regardless of actual network congestion, instead of the market-determined value.

---

### Impact Explanation

| Effect | Mechanism |
|---|---|
| **Incorrect fee charge** | All transactions pay only `LowerBoundBaseFee`; the fee market is disabled |
| **Suppressed KAIA burn** | KIP-71 burns half the base fee; with base fee at minimum, burn approaches zero |
| **Incorrect reward distribution** | Validators receive less fee revenue than the protocol intends |
| **Invalid state transition** | `header.BaseFee` no longer reflects network congestion; every block's fee state is wrong |

This matches the Allowed Impact Gate: "fee charge, reward distribution … affecting KAIA" and "invalid state transition."

---

### Likelihood Explanation

- In **"none" governance mode** (any council member who is the block proposer may vote), a single council member can cast a vote for `kip71.gastarget = X` where `X > MaxBlockGasUsedForBaseFee`. The vote passes `checkConsistency` with no error, is ratified at the next epoch boundary, and the broken state takes effect immediately.
- In **"single" governance mode** the governing node is the trigger (privileged), but the protocol-level missing guard is the same root cause.
- The `FormatChecker` for both parameters is `noopFormatChecker`, so no per-field validation catches the violation at any layer.
- The existing `LowerBound`/`UpperBound` cross-check demonstrates the codebase's intent to enforce inter-parameter constraints; the `GasTarget`/`MaxBlockGasUsedForBaseFee` pair was simply omitted.

---

### Recommendation

Add a cross-parameter guard in `checkConsistency` for both `Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee`:

```go
case gov.Kip71GasTarget:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.MaxBlockGasUsedForBaseFee {
        return ErrGasTargetExceedsMaxBlockGasUsed
    }
    return nil
case gov.Kip71MaxBlockGasUsedForBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.GasTarget {
        return ErrMaxBlockGasUsedBelowGasTarget
    }
    return nil
``` [1](#0-0)

### Proof of Concept

**Setup**: Network running post-Magma with defaults: `GasTarget = 30_000_000`, `MaxBlockGasUsedForBaseFee = 60_000_000`, `LowerBoundBaseFee = 25 Gwei`.

**Step 1**: A council member (block proposer in "none" mode) casts a governance vote:
```
governance_vote("kip71.gastarget", 100_000_000)
```

**Step 2**: `checkConsistency` is called. `Kip71GasTarget` hits the `return nil` branch — no error. [5](#0-4) 

**Step 3**: At the next epoch boundary, the governance update is ratified: `GasTarget = 100_000_000 > MaxBlockGasUsedForBaseFee = 60_000_000`.

**Step 4**: For every subsequent block, `NextMagmaBlockBaseFee` computes:
```
parentGasUsed = min(actualGasUsed, 60_000_000)   // always ≤ 60M
// 60M < 100M = GasTarget → always takes the "decrease" branch
nextBaseFee = parentBaseFee - delta
// ... until parentBaseFee == LowerBoundBaseFee (25 Gwei)
// then: shortcut returns LowerBoundBaseFee forever
``` [6](#0-5) 

**Step 5**: `VerifyMagmaHeader` enforces `header.BaseFee == expectedBaseFee`. All honest nodes compute the same (wrong) expected value, so blocks are accepted — but every block's `header.BaseFee` is permanently `LowerBoundBaseFee`. The KIP-71 fee market is silently and permanently disabled. Fee burn and validator fee revenue are suppressed to their minimum for the lifetime of the chain unless a corrective governance vote is cast.
