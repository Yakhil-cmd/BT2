### Title
Cross-organization webhook confusion — signature verified against `repository.owner.login` but Stack lookup uses `repository.full_name` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's webhook secret to validate against using `repository_owner` (`params.dig('repository','owner','login')` or `params.dig('organization','login')`), while every `Shipit::Webhooks::Handlers::Handler` subclass resolves the Stack/Repository to act on using a *different* field of the same attacker-supplied JSON body: `payload.dig('repository','full_name')`. Nothing ties these two fields together, and per-organization `webhook_secret` is documented as optional. This breaks the binding "organization whose signature was verified == repository that gets acted upon."

### Finding Description
`Shipit.github(organization:)` supports multiple GitHub Apps, one per organization, each with its own optional `webhook_secret` (`docs/setup.md` "Using Multiple Github Applications" section). Verification picks the app/secret via: [1](#0-0) [2](#0-1) 

`verify_webhook_signature` unconditionally passes when no secret is configured for that org: [3](#0-2) 

Once signature verification passes (for whatever organization `repository.owner.login`/`organization.login` claims to be), the raw JSON body is handed unmodified to every registered handler: [4](#0-3) 

All handlers (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, PR handlers, etc.) resolve which `Repository`/`Stack` to mutate using a completely independent field, `repository.full_name`, with no cross-check against `repository.owner.login`: [5](#0-4) [6](#0-5) [7](#0-6) 

**Equality broken:** `organization authenticated by verify_signature (repository.owner.login) == organization whose repository/stack is actually written (repository.full_name)`. Before the attack, these two fields always agree because they both come from the same genuine GitHub delivery. After the attacker's crafted request, they can diverge arbitrarily since the whole JSON body is attacker-controlled and only the HMAC over the raw body — keyed by whichever org name appears in `repository.owner.login`/`organization.login` — is checked.

Because `webhook_secret` is optional per organization (`docs/setup.md` lines 182-209, `config/secrets.development.example.yml`), any deployment with at least one unsecured/low-security organization onboarded (or one whose secret has weaker distribution) allows an attacker to set `repository.owner.login` to that unsecured org (making `verify_signature` return `true` for free) while setting `repository.full_name` to `victim-org/victim-repo`, causing Shipit to process the event as if it came from `victim-org`.

### Impact Explanation
Using this mismatch, an attacker with no GitHub credentials for the victim org can:
- Forge `push` events that force `GithubSyncJob`/`stack.sync_github` for the victim's stack, and
- Forge `status` events to inject arbitrary commit statuses via `Commit#create_status_from_github!`, which affects deploy/merge gating shown by `MergeStatusController` (`stack.merge_status`) — directly threatening the "unauthorized deploy, rollback or merge" impact bucket, since commit status state feeds into whether a Stack/PR is considered deployable/mergeable.
- Forge `check_suite`/`membership` events for a fully unrelated organization.

This matches the High/Critical impact categories: escalation of trust across organizational boundaries and potential unauthorized deploy/merge decisions driven by forged CI signal, achieved purely by an unprivileged network attacker who never needs any Shipit session, API token, or GitHub credential for the target org.

### Likelihood Explanation
Requires only:
1. A multi-organization Shipit deployment (a documented, supported configuration).
2. At least one onboarded organization configured without a `webhook_secret` (explicitly marked optional in the docs) — realistic since it's opt-in and easy to forget, or an org whose secret is otherwise easier to obtain/guess than the victim's.
3. Knowledge of the victim's `owner/repo` full name (public information).

No authentication, session, or GitHub credential is needed to hit the public `/webhooks` endpoint.

### Recommendation
Enforce that the organization used to select/verify the webhook signature is the same organization actually acted upon:
- After determining `repository_owner` used for signature selection, require that `payload.dig('repository','full_name')&.split('/')&.first&.casecmp?(repository_owner)` (and similarly for `organization.login`-based events) before dispatching to handlers, rejecting mismatches with 422.
- Alternatively/additionally, make `webhook_secret` mandatory for every configured organization so no unauthenticated bypass path (`return true unless webhook_secret`) exists at all.

### Proof of Concept
1. Deploy Shipit with two organizations configured, `SafeOrg` (no `webhook_secret` set) and `VictimOrg` (protected `webhook_secret`), both with Shipit tracking `VictimOrg/prod-repo`.
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": { "owner": { "login": "SafeOrg" }, "full_name": "VictimOrg/prod-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-controlled sha already known/merged upstream>"
}
```
No `X-Hub-Signature` needs to be valid for `VictimOrg`; `Shipit.github(organization: "SafeOrg").verify_webhook_signature` returns `true` unconditionally (no secret configured), per `lib/shipit/github_app.rb` lines 76-83.
3. `WebhooksController#create` dispatches to `PushHandler`, which resolves the Stack via `repository.full_name` = `"VictimOrg/prod-repo"` (per `handler.rb` lines 32-38) and triggers `stack.sync_github` for the victim's real stack — an action normally gated by `VictimOrg`'s own webhook secret.
4. Repeat with `X-Github-Event: status` to inject a forged successful commit status on an arbitrary victim commit, influencing merge/deploy gating in `MergeStatusController`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
