### Title
Untrusted TUF `trusted_root.json` target content is printed to the terminal without sanitization, bypassing the codebase's `Untrusted`/`asciisanitizer` defense - ([File: pkg/cmd/attestation/trustedroot/trustedroot.go])

### Summary
`getTrustedRoot` fetches a TUF target payload with `tufClient.GetTarget(target)`, runs it through `json.Compact`, and writes the result straight to stdout with `fmt.Println(output)`. Unlike other parts of the CLI that wrap externally-sourced content in `iostreams.Untrusted` (which runs the `asciisanitizer` transform before any `fmt` print path), this command sends the raw fetched bytes directly to the terminal.

### Finding Description
The call chain is: `tufClient.GetTarget(target)` → `t` (raw bytes from the configured TUF mirror) → `json.Compact(output, t)` → `fmt.Println(output)`, at [1](#0-0) . `json.Compact` only removes insignificant whitespace and validates JSON syntax; it does not decode `\u00XX` escapes and it does not strip or neutralize any Unicode codepoint that JSON does not require to be escaped. Per RFC 8259 only `U+0000`–`U+001F` must be escaped inside a JSON string, so an attacker-controlled string field in the target document can freely contain unescaped `U+007F` (DEL), C1 control codes such as `U+009B` (an alternate CSI introducer, encoded as valid UTF-8), or Unicode bidi/format overrides like `U+202E` — none of which trip `json.Compact`'s validity check, and all of which pass through to `fmt.Println` verbatim.

This is a bypass of an intentional, existing defense: the repo defines `iostreams.Untrusted` specifically to prevent this class of bug, documenting that "the raw bytes are unexported so the only ways out are the methods below" and that `String()` "sanitizes... so any fmt print path... renders the content with ANSI escape sequences neutralized," per [2](#0-1) . `getTrustedRoot` never routes `t`/`output` through `Untrusted` or through the `io.Handler` abstraction used elsewhere in the attestation package; it uses a bare `*bytes.Buffer` and `fmt.Println` directly.

Reachability requires the victim to configure `--tuf-url`/`--tuf-root` at an attacker-influenced TUF mirror, per [3](#0-2) ; by design this flag lets the operator point at a custom/private TUF repository trusted "out of band," so content from that source is expected to be attacker/operator supplied in that scenario, and the same source also controls signing keys for the target, so a malformed/hostile document is plausible.

### Impact Explanation
Terminal control-character/Unicode-override injection can be used to hide or spoof text (e.g. Trojan-Source-style right-to-left override tricks, or CSI-like sequences via C1 codes on terminals honoring 8-bit control codes), potentially misleading the victim about the "trusted root" content they are about to persist and use for offline signature verification. This is a low-severity output-integrity/spoofing issue rather than code execution or credential exfiltration, since raw ESC (`0x1B`) itself cannot survive strict JSON escaping/`json.Compact` validation.

### Likelihood Explanation
Exploitation requires the victim to explicitly point `gh attestation trusted-root` at an attacker-controlled TUF mirror via the documented `--tuf-url`/`--tuf-root` flags (or a compromised default TUF mirror, which is out of scope for an unprivileged attacker). Given that precondition, the bypass itself is trivial and fully repeatable — no additional code path defends against it.

### Recommendation
Route the fetched target bytes through `iostreams.NewUntrustedBytes(t)`/`Untrusted.String()` (or an equivalent sanitizing print path already used elsewhere) before writing to stdout, or use the `io.Handler` abstraction consistently instead of raw `fmt.Println`.

### Proof of Concept
Unit test sketch for `getTrustedRoot` using a fake `tuf.Client`/`tufClientInstantiator` returning a JSON document whose string field contains an unescaped `U+202E` (RIGHT-TO-LEFT OVERRIDE) or C1 `U+009B` byte sequence, e.g. `{"field":"safe\u202Eexe.cmd"}` (valid JSON, since these codepoints don't require escaping). Assert that:
1. `json.Compact` succeeds (proving the payload is not rejected by JSON validation), and
2. the bytes written to stdout still contain the raw override/control codepoint instead of a sanitized/escaped representation — demonstrating the missing `Untrusted`/`asciisanitizer` pass that other commands apply, per [4](#0-3) .

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
