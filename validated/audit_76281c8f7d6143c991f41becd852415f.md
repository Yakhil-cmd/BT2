### Title
Git pathspec magic characters in touched file names are not neutralized before being spliced into `git diff --` args, letting a crafted filename widen or defeat the intended diff scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` converts touched-file absolute paths into repo-relative strings and hands them to `git diff` verbatim after `--`, without disabling git's pathspec "magic" syntax (glob wildcards, `:(...)` prefixes, `:!`/`:^` exclude magic). A file whose name contains such characters — fully legal on Linux/macOS filesystems — causes the "restrict diff to touched paths" pathspec to be reinterpreted by git as a glob or exclusion rule instead of a literal filename.

### Finding Description
`_diff_pathspec` at [1](#0-0)  takes each touched path, resolves symlinks with `os.path.realpath`, computes the path relative to the realpath'd `cwd`, drops anything that escapes the repo (`r.startswith("..")`), and otherwise appends the raw relative string to the pathspec list returned to the caller. That list is spliced directly after `--` into the `git diff` argv in `get_git_diff`: [2](#0-1) .

Git does not treat pathspec elements as pure literal strings by default: it applies fnmatch-style glob wildcards (`*`, `?`, `[...]`) and colon "magic" prefixes (`:(glob)`, `:(icase)`, `:!pattern`/`:^pattern` for exclusion, etc.) unless the caller sets `--literal-pathspecs` (or `core.literalPathspecs=true`, or prefixes each element with `:(literal)`). Neither `GIT_CMD` [3](#0-2)  nor `_diff_pathspec` does any of this.

Because the string that ends up in the pathspec list is exactly the on-disk relative filename, any repo-controlled file with a wildcard or colon-magic character in its name — a legal filename on POSIX systems — turns the intended single-file restriction into either:
- a glob that matches many more files than the one that was actually touched (scope widened beyond the intended file), or
- an exclude-only pathspec (`:!something`) which git treats specially and can leave the diff effectively unrestricted, exactly the "unrestricted diff" failure mode the surrounding code explicitly calls out as "the bug this whole change exists to fix" (see the comment at [4](#0-3) , which only guards against an *empty* pathspec, not a magic one).

The touched-path list is populated from tool-call file paths (Write/Edit `file_path`) recorded via `record_touched_path` in `diffstate.py` and consumed by the Stop-hook review pipeline through `compute_v2_review_set` / `get_git_diff`, so any file Claude creates or edits during a session — including files whose names originate from repo content, issue/PR text, or prompt-injected instructions — flows unsanitized into this pathspec.

No existing check filters pathspec-magic characters out of the relative path; the only filtering done is the outside-repo `..`-prefix check and symlink realpath normalization, which address a different threat (macOS `/var`↔`/private/var` and directory traversal) but not pathspec-syntax injection.

### Impact Explanation
This breaks the stated invariant "git path scoping must never escape the intended repo target." The `git diff` output produced under a widened or effectively-unrestricted pathspec is what gets sent, verbatim, to the LLM security reviewer over the network (Anthropic API call in `analyze_code_security`/`agentic_review`). A widened diff can pull in unrelated files' contents — including files the user did not intend to be reviewed this turn (other in-progress secrets, tokens, or sensitive local files sitting in the working tree) — and ship them to an external LLM endpoint. This matches the "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" impact category.

### Likelihood Explanation
Exploitation requires only that a file with a pathspec-magic character in its name (e.g. `*.py`, `[abc].txt`, or a name starting with `:`) exists in the working tree and gets touched (written/edited) by Claude during a session — no elevated privileges, no shell access beyond ordinary Claude Code tool use, and no bypass of any existing allowlist since none of the current checks inspect for these characters. Such a filename could arrive via a cloned repository, a PR checkout, or content an attacker convinces Claude to create through prompt injection in issue/PR text. This is a realistic but not trivial precondition (needs a specific filename to exist and be edited), giving it moderate likelihood.

### Recommendation
Force literal pathspec interpretation for every element added in `_diff_pathspec`, e.g. either prepend `:(literal)` to each relative path before returning it, or add `-c core.pathspecFromFile=` equivalent / include `"--literal-pathspecs"` as a global git option in `GIT_CMD` (or at minimum in the `git diff` invocations that consume `_diff_pathspec`'s output). Add regression tests that create files with names containing `*`, `?`, `[`, `]`, and leading `:` characters, mark them as touched, and assert the resulting diff only contains changes from that literal file and not from sibling files that would otherwise glob-match.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Initialize a temp git repo with an initial commit containing two files: `notes.txt` (baseline, untouched, contains a fake secret) and a second file whose name contains a pathspec-glob character, e.g. `a[1].py`.
2. Modify `a[1].py` and stage/commit or leave it dirty; call `get_git_diff(cwd, baseline_sha, paths=[os.path.join(cwd, "a[1].py")])`.
3. Assert the returned diff text does NOT include content from `notes.txt` — i.e., `"notes.txt" not in diff`. Under the current implementation, git interprets `a[1].py` as a character-class glob (matching `a1.py`/`aX.py` style names) rather than literal, so add a second file, e.g. `a1.py`, also modified, and assert that its diff leaks into the "restricted" pathspec even though only `a[1].py` was passed as the touched path — demonstrating the scope escape.
4. A second test: create a file named `:exclude-me` (or similarly colon-prefixed), touch it, and call `_diff_pathspec` directly; assert that the returned pathspec list, when used in `git diff -- <that string>`, either errors or yields the full unrestricted diff instead of being scoped to that one file, confirming the exclude/magic-prefix scope-escape path.
5. Fix validation: after prefixing each element with `:(literal)` (or adding `--literal-pathspecs`), re-run steps 2–4 and assert the diff is correctly scoped to only the touched file in every case.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
