### Title
Webhook signature verification is keyed by an attacker-controlled `repository.owner.login` field disjoint from the `repository.full_name` field the handlers actually act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to verify the incoming signature against by reading `repository.owner.login` (or `organization.login`) straight out of the unauthenticated JSON body, before any signature has been checked. [1](#0-0)  Once verification passes, the *entire* raw payload is dispatched to handlers, which resolve the target `Stack`/`Repository` using a completely different field, `repository.full_name`, that was never part of the org-selection/verification decision. [2](#0-1)  This is the direct analog of the AllBridge report's root cause: an action is authorized/priced using one piece of state, while the actual effect is computed from a different, unbound piece of state supplied in the same request.

### Finding Description
`verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
`repository_owner` comes from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, i.e. attacker-supplied, unsigned JSON. [3](#0-2) 

`Shipit.github` resolves this organization key against `secrets.github`, a hash that can contain multiple GitHub App configs keyed by organization name (the multi-org schema documented in `config/secrets.development.shopify.yml` and used in `test/dummy/config/secrets_double_github_app.yml`), each with its own independent `webhook_secret`. [4](#0-3) 

`GitHubApp#verify_webhook_signature` unconditionally returns `true` when that organization's `webhook_secret` is blank:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [5](#0-4) 

So the equality the code implicitly (and incorrectly) assumes is:
`organization used to pick the verifying secret (params.repository.owner.login) == repository the payload's effects are applied to (params.repository.full_name)`

These are never checked to be consistent. An attacker who knows (or guesses, since these are often left commented `# nil` in example/dev secrets, e.g. `config/secrets.development.example.yml` and `config/secrets.development.shopify.yml`) that *any* configured organization on the instance has no `webhook_secret` set can simply set `repository.owner.login`/`organization.login` in the payload to that organization's name. Verification is bypassed entirely (`return true unless webhook_secret`) while the actual `repository.full_name` in the same payload can name an entirely different, victim repository/stack whose commits/status/branch state the handlers then mutate:
```ruby
Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
``` [6](#0-5) 
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
``` [7](#0-6) 

For example `PushHandler` uses `repository.full_name` (via `stacks`) and attacker-controlled `ref`/`after` to trigger `stack.sync_github(expected_head_sha: params.after)` on any stack matching that name/branch, with no relationship at all to the `repository.owner.login` value that determined whether the signature check was even enforced. [8](#0-7) 

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" binding explicitly called out as in-scope. It allows an unauthenticated remote attacker to forge push/status/check_suite/pull_request events for any repository tracked by the Shipit instance, as long as one configured organization on that instance has no webhook secret configured — enabling unauthorized triggering of `sync_github`, fake commit statuses, and other write-side effects across repositories the attacker does not control, i.e. cross-repository writes.

### Likelihood Explanation
Requires a multi-organization Shipit deployment where at least one configured organization omits `webhook_secret` (a state the documented example/dev configs explicitly show, `webhook_secret: # nil`), and requires no other secret to be known by the attacker — only knowledge that such a lax organization exists on the instance, discoverable by simply omitting `X-Hub-Signature` entirely or guessing plausible org names. No privileged credentials are required, satisfying the unprivileged-attacker requirement.

### Recommendation
Never use a field pulled from the unauthenticated payload to select the verifying secret and then trust the same payload's other fields for effectful dispatch without re-validating that they belong to the same authenticated organization. Concretely: after `verify_signature` succeeds, re-derive `repository_owner` from the *verified* payload and assert `params.dig('repository', 'owner', 'login')` matches the organization whose `Repository` record `repository.full_name` actually resolves to, rejecting the request otherwise. Alternatively/additionally, require `webhook_secret` to be present and non-blank for every configured organization at boot, removing the "return true unless webhook_secret" bypass path entirely.

### Proof of Concept
1. Configure Shipit with two orgs, `trusted-org` (webhook_secret set) and `lax-org` (webhook_secret blank/nil) — mirroring the shipped example configs.
2. POST to `/webhooks` with `X-Github-Event: push`, no valid `X-Hub-Signature` for `trusted-org`, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker chosen sha>",
  "repository": {
    "full_name": "trusted-org/victim-repo",
    "owner": { "login": "lax-org" }
  }
}
```
3. `verify_signature` calls `Shipit.github(organization: 'lax-org')`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally. [9](#0-8) 
4. `PushHandler` resolves the stack via `repository.full_name` = `trusted-org/victim-repo` and calls `stack.sync_github(expected_head_sha: 'attacker chosen sha')`, mutating a repository entirely unrelated to `lax-org`. [10](#0-9)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
