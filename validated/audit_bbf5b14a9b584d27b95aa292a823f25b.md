### Title
Unchecked RAY value overflow during accrual permanently freezes a market - (File: `common/src/rates/simulate.rs`)

### Summary

A user can create a sufficiently large, highly utilized market whose scaled totals overflow `i128` during interest accrual before the borrow-index ceiling is reached. Since every pool mutation synchronizes interest before executing the requested operation, the first overflow permanently blocks withdrawals, repayments, liquidations, and later index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description

`accrue_step` reconstructs aggregate borrowed and supplied values by calling `scaled_to_original` on `borrowed * borrow_index` and `supplied * supply_index`. [3](#0-2) 

`scaled_to_original` performs an overflowing fixed-point multiplication rather than saturating or bounding the result. [4](#0-3) 

`global_sync` invokes `accrue_step` for each elapsed compounding chunk before any market mutation proceeds. [5](#0-4) 

Although the borrow index itself is capped at `10^36`, the aggregate-value multiplication can overflow while the stored index is still below that cap. The checked panic therefore occurs before the cap can stop further growth. [6](#0-5) 

### Impact Explanation

Once the market reaches the overflow boundary, every operation that touches it runs `global_sync` first and fails with `MathOverflow`. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot resolve the unhealthy account, and keepers cannot update indexes; the funds and debt in that market are permanently frozen. [1](#0-0) [7](#0-6) 

The regression test demonstrates the concrete consequence: an 18-decimal market containing one billion whole tokens at 98% utilization eventually fails inside `scaled_to_original`, and subsequent withdrawal and repayment attempts fail with `MATH_OVERFLOW`. [8](#0-7) 

### Likelihood Explanation

An unprivileged user can reach the precondition through the public `supply` and `borrow` entrypoints. They must provide very large but protocol-admitted balances and sustain high utilization long enough for interest growth to multiply the scaled totals past `i128::MAX`. [9](#0-8) [10](#0-9) 

The attack does not require privileged configuration or malformed external input. It does require substantial capital and a market configuration that permits the required supply and borrow amounts, so the practical likelihood is lower than a small-input trigger. [11](#0-10) 

### Recommendation

Prevent aggregate RAY-value reconstruction from overflowing before index capping:

- Compute utilization without materializing `borrowed * borrow_index` and `supplied * supply_index` as unbounded `i128` products, for example by dividing the smaller operand first or using a wider intermediate representation.
- If wider arithmetic is unavailable, cap the reconstructed aggregate values at `i128::MAX` and handle saturated utilization explicitly.
- Reject or clamp accrual when the market's scaled totals are already outside the safely reconstructible domain, rather than panicking inside `scaled_to_original`.
- Add a permanent invariant test asserting that every market mutation remains recoverable up to `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. [4](#0-3) [12](#0-11) 

### Proof of Concept

1. Create an 18-decimal market with permissive supply and borrow caps.
2. Supplier calls `supply` with `1_000_000_000 * 10^18` raw units.
3. Borrower supplies sufficient collateral and calls `borrow` for 98% of that amount.
4. Advance ledger time while repeatedly calling `update_indexes`.
5. Eventually `accrue_step` computes `borrowed_original` or `supplied_original`; the multiplication overflows before the stored borrow index reaches `MAX_BORROW_INDEX_RAY`.
6. `update_indexes` fails with `MathOverflow`.
7. Subsequent `withdraw`, `repay`, or `liquidate` calls fail at the same accrual step before their requested operation executes. [8](#0-7)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );
```

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
