### Title
Stale controller delegate grants reactivate when the position NFT returns to the granting owner - (File: contracts/controller/src/storage/account.rs)

### Summary
Controller delegate grants are keyed only by `account_id` and stamped with the granting owner’s address, with no transfer epoch, nonce, expiry, or deletion on NFT transfer. If owner A delegates to manager M, transfers the position NFT to owner B, and B later returns the NFT to A without updating delegates, M’s old grant becomes live again and can borrow or withdraw the account’s funds to M. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`get_delegates` treats a stored `DelegateGrant` as live whenever `grant.granted_by` equals the current NFT owner. The grant is only hidden while another address owns the NFT; it is not invalidated. [1](#0-0) 

The stored list persists in `ControllerKey::Delegates(account_id)` and is removed only when the current owner calls `remove_delegate` or overwritten when the current owner calls `add_delegate`. [4](#0-3) [5](#0-4) 

This creates the same bug class as a token remaining valid after the surrounding session is invalidated: changing the NFT owner temporarily suppresses the authorization, but returning the token restores the old authorization without a fresh owner signature. [6](#0-5) [7](#0-6) 

The resurrected delegate must still be an active registered position manager, but then passes `require_owner_or_delegate`; `borrow` and `withdraw` permit arbitrary external recipients other than the pool or controller. [6](#0-5) [8](#0-7) [9](#0-8) 

### Impact Explanation
A reactivated delegate can withdraw collateral or borrow up to the account’s solvency limit and direct the proceeds to itself, resulting in theft of user funds or unauthorized debt against the account. [10](#0-9) [11](#0-10) [12](#0-11) 

The affected user can lose all withdrawable collateral and receive a debt position for borrowed assets paid to the former delegate. [10](#0-9) [13](#0-12) 

### Likelihood Explanation
The path requires a prior valid delegation, an NFT ownership change, and a later transfer back to the original owner before an intervening owner writes the delegate list. [1](#0-0) [5](#0-4) 

That sequence is plausible for escrow, marketplace custody, contract-held positions, operational wallet changes, or accidental round-trip transfers, and the former delegate needs no owner interaction once the grant reactivates. [14](#0-13) [6](#0-5) 

### Recommendation
Version delegate grants with an ownership epoch incremented by every NFT mint/transfer, or include a controller-side ownership nonce in `DelegateGrant` and reject grants whose epoch differs from the current NFT ownership epoch. [15](#0-14) [1](#0-0) 

Alternatively, hook NFT ownership changes to purge `ControllerKey::Delegates(account_id)`, or require the former owner to re-authorize every delegate after regaining ownership. [5](#0-4) [16](#0-15) 

### Proof of Concept
```rust
// A owns account NFT `token_id == account_id`, and M is an active
// governance-approved position manager.
controller.add_delegate(alice, account_id, manager);

// A transfers the account to B. M is inactive under B because
// grant.granted_by != bob.
position_nft.transfer(alice, bob, token_id);

// B never calls add_delegate or remove_delegate, then returns the NFT.
position_nft.transfer(bob, alice, token_id);

// The stored A-stamped grant is live again. M authenticates as caller and
// drains collateral to itself; a zero withdrawal requests the full position.
controller.withdraw(
    manager,
    account_id,
    vec![(collateral_asset, 0)],
    Some(manager),
);

// Or M borrows against the collateral and takes the borrowed assets.
controller.borrow(
    manager,
    account_id,
    vec![(debt_asset, borrow_amount)],
    Some(manager),
);
```

The first transfer hides the old grant, but does not delete it; the second transfer makes `granted_by == alice` true again, after which `require_owner_or_delegate` accepts `manager` and the borrow/withdrawal paths send funds to `Some(manager)`. [1](#0-0) [5](#0-4) [6](#0-5) [8](#0-7) [9](#0-8)

```rust
/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
```

```rust
/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
```

```rust
/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
```

```rust
/// Authenticates the NFT owner and updates delegates; grants require an active
/// manager. Emits an event only when the current owner's delegate list changes.
fn set_account_delegate(
    env: &Env,
    caller: &Address,
    account_id: u64,
    delegate: &Address,
    add: bool,
) {
    caller.require_auth();
    require_account_owner(env, account_id, caller);
    if add {
        // Reject dormant grants that could gain authority on later manager activation.
        assert_with_error!(
            env,
            storage::get_position_manager(env, delegate).is_some_and(|c| c.is_active),
            GenericError::NotAuthorized
        );
    }

    let changed = if add {
        storage::add_delegate(env, account_id, caller, delegate)
    } else {
        storage::remove_delegate(env, account_id, caller, delegate)
    };
```

```markdown
An account delegate also needs active global position-manager registration.
Its grant is stamped with the granting owner's address, not a transfer epoch:
it becomes inactive while someone else holds the NFT and can revive if the
NFT returns before an intervening owner updates delegates. Owner revocation
is immediate; global deactivation takes effect when governance executes it.
Delegates can borrow/withdraw to their chosen recipient within account gates.
Those gates do not constrain them to acting in the owner's economic interest.
```

```rust
/// A delegate list stamped with the owner who granted it. The grant is live only while
/// `granted_by` owns the account's NFT: after an NFT transfer, `get_delegates` reads it as
/// empty for the new owner. The new owner's next `add_delegate` or `remove_delegate`
/// overwrites or deletes the stale entry. If the NFT returns to `granted_by` before such a
/// write, the original delegate list is live again.
#[contracttype]
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct DelegateGrant {
    pub granted_by: Address,
    pub delegates: Vec<Address>,
}
```
