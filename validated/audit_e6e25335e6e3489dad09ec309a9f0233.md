### Title
Permanent market freeze: accrual overflows i128 in `scaled_to_original` before the borrow-index cap engages, bricking every verb on the market — (File: common/src/rates/scaling.rs)

### Summary
The MySQL InnoDB DoS class (repeatable crash hanging the service) maps onto XOXNO Lending as a permanent, unrecoverable panic inside `global_sync`. Every pool mutation — supply, withdraw, borrow, repay, flash loan, seizure, bad-debt cleanup — first accrues interest via `interest::global_sync` → `accrue_step`, which unscales `borrowed` and `supplied` by the indexes through `scaled_to_original` (`common/src/rates/scaling.rs:14-16`, a `Ray::mul` that panics on overflow). On a whale-scale high-decimals market at sustained high utilization, `borrowed × borrow_index` exceeds `i128::MAX` **before** `MAX_BORROW_INDEX_RAY` (1e36) caps index growth — the cap never engages because the value multiplication overflows first. From that point every entrypoint on the market reverts with `MathOverflow`: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize, and `clean_bad_debt`/`update_indexes` fail too. The repository's own harness test proves it end-to-end (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`): after the cliff, `try_withdraw` and `try_repay` both fail with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.

### Finding Description
- `pool/src/interest.rs::global_sync` runs `accrue_chunk` on **every** mutation of an existing market (flow documented in `contracts/pool/README.md:159-167`).
- `accrue_step` computes interest by unscaling share totals: `half_up(borrowed × borrow_index' / RAY) − half_up(borrowed × borrow_index / RAY)` (`skills/xoxno-lending/math.md:236`), i.e. `scaled_to_original` — a checked `mul` that panics on overflow.
- `update_borrow_index` clamps the index at `MAX_BORROW_INDEX_RAY = 1e36`, but the value ceiling `borrowed × index ≤ i128::MAX ≈ 1.7e38` is a *tighter* bound whenever `borrowed` exceeds ~170 RAY of whole-token value. A market holding ~1e9 units of an 18-decimal asset is `1e36` raw RAY of shares, so index growth past ~170× trips the value overflow first — the test reaches it at 98% utilization on the steep XLM curve.
- Once tripped, the panic is sticky: `last_timestamp` cannot advance because `global_sync` itself panics, so no operation can ever skip the failing accrual. The freeze is permanent; there is no admin rescue path that avoids `Cache::load` → `global_sync` on that market's hot path (threat-model DoS rows note controller renewal is owner-authorized only for TTL, not for this).

Reachability is permissionless: any address can `supply` a whale book (the `supply` path has no dust floor — `poc_single_actor_spams_unbounded_dust_accounts` confirms 1-unit deposits are accepted and caps are lifted via governance-set exposure, but `lift_caps` shows the admitted scale), `borrow` against separate collateral to pin utilization near the steep curve segment, and then wait — or accelerate with permissionless `update_indexes` calls (`controller::update_indexes` is caller-auth per `scripts/permissionless_entrypoints.txt:74`). Time plus ordinary interest does the rest; once utilization stays high, accrual itself is the trigger and cannot be vetoed.

### Impact Explanation
Permanent freezing of all user funds in the affected market book: every supplier's shares, the pool cash backing them, and all borrower collateral routed through that market become unrecoverable because the shared `global_sync` precondition panics. This also blocks liquidation and `clean_bad_debt` on positions whose risk valuation touches the frozen market, and `recapitalize` cannot repair it because it too accrues first. Impact class: permanent freezing of funds / contract unable to operate — squarely in scope.

### Likelihood Explanation
Medium. Requires a whale-scale position (≈1e9 whole tokens of an 18-decimal asset, or a proportionally smaller book on a steeper/longer rate exposure) and sustained high utilization for a multi-year accrual horizon — an attacker must fund the book but can recycle the same capital as both supplier and borrower, and permissionless `update_indexes` plus normal user activity guarantees accrual cadence. The condition needs no privileged action, no oracle manipulation, and no cooperation from other users; it is a deterministic arithmetic cliff the protocol itself documents as residual risk ("Finite RAY value capacity can be exhausted before the index ceiling", `docs/explanation/threat-model.md:317-324`) without a runtime mitigation.

### Recommendation
- Make `accrue_step` saturate rather than panic: when `borrowed × borrow_index'` would exceed `i128::MAX`, clamp the index projection to `min(computed, floor(i128::MAX / borrowed × RAY))` — i.e. derive an effective value-aware index cap below `MAX_BORROW_INDEX_RAY` per market at sync time, so accrual converges to the cap instead of trapping.
- Alternatively, compute utilization in the accrual loop on clamped values and short-circuit to the capped index once the value ceiling is reached, preserving exit liquidity (withdraw/repay keep working at the capped index even though no further interest accrues).
- Add a regression asserting `try_withdraw`/`try_repay` succeed after the borrow index reaches its effective cap, extending `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`.

### Proof of Concept
From `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360` (already in-repo):

```rust
// BIG18: 18-decimal token, XLM curve, caps lifted.
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);          // attacker/whale supplies the book
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);             // pin utilization at ~98%

// advance years; each try_update_indexes_for is a permissionless call
// once borrowed * borrow_index' > i128::MAX inside global_sync -> accrue_step
// -> scaled_to_original, the tx reverts with MathOverflow.
assert_contract_error(failure, errors::MATH_OVERFLOW);
assert!(book(&t, "BIG18").borrow_index < MAX_BORROW_INDEX_RAY); // cap never engaged

// permanent freeze — every verb accrues first:
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Entry path reachable by a single unprivileged address: `controller::supply` (account_id 0 creates an owned account) → `controller::borrow` → `controller::update_indexes` / passage of time → `controller::withdraw`/`repay`/`liquidate`/`clean_bad_debt` all revert permanently.
