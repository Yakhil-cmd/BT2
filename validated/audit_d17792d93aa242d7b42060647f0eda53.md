### Title
Attacker-induced Aquarius LP price outage shields an underwater account from liquidation and bad-debt cleanup - (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
A single unprivileged address can permanently block liquidation and bad-debt cleanup of its own account by (1) supplying a dust amount of a listed Aquarius LP token as an extra collateral leg, and (2) withdrawing its own liquidity from the underlying Aquarius pool so the pool's WAD value falls below `min_pool_value_wad`. The aggregator then returns `InsufficientAquariusLiquidity` for that asset, the controller's strict price fetch panics, and every valuation-dependent path — `liquidate`, `clean_bad_debt`, `repay_debt_with_collateral`, `swap_*` — reverts, while the borrower's debt keeps accruing into protocol insolvency.

### Finding Description
The Aquarius provider refuses to emit a price when the pool's total value (recomputed on-chain as `price_wad * total_shares / share_unit`) drops below the configured `lp.min_pool_value_wad`, returning `OracleError::InsufficientAquariusLiquidity` [1](#0-0) . Pool value is fully attacker-controlled: withdrawing LP liquidity reduces reserves and the share price computation, so a liquidity provider can push the pool under the floor at will.

On the controller side, `Context::fetch_prices` demands a feed for every asset it requests and panics with `OracleError::OracleNotConfigured` on any missing entry [2](#0-1) , and `cached_price` panics for any uncached asset [3](#0-2) . `build_liquidation_plan` calls `risk::calculate_account_risk_totals` over the account's *entire* supply book [4](#0-3) , so one unpriceable dust collateral leg aborts the whole liquidation regardless of which debt leg is offered. The same all-positions valuation makes `clean_bad_debt` / force-socialization fail, since they value the same supply book.

Crucially, `supply` needs no price for a newly added leg (collateral value is only checked at borrow), so the borrower can add the shield leg even after the outage begins. Aquarius LP share tokens are listable collateral (the provider exists precisely to price them), and `min_pool_value_wad` is a real configured parameter in `configs/mainnet/markets.json`. The threat model itself documents this exact shape as DoS.1: "a borrower can add a dust leg of any listed collateral and choose which feed outage shields the account. For an Aquarius LP leg, liquidity providers can cause that outage by withdrawing pool value below `min_pool_value_wad`. The same leg blocks bad-debt cleanup and force-socialization" [5](#0-4) .

### Impact Explanation
Protocol insolvency. While the shield holds, the attacker's account cannot be liquidated or force-socialized; its debt accrues interest while collateral value collapses, and the eventual loss is socialized across suppliers via the bad-debt index write-down. The cost to the attacker is the LP capital left deposited (or forgone withdrawal value) plus a dust supply — small relative to a large borrow. This is not mere fail-closed availability: it selectively converts a reachable oracle error into uncollateralized debt.

### Likelihood Explanation
Requires a listed Aquarius LP market whose `min_pool_value_wad` is within reach of an attacker's liquidity share, and the attacker must hold (or acquire) a borrow with HF near 1. Pool value is continuously measurable on-chain, so the attack is timing-free: the borrower can wait until naturally underwater, then trigger the outage. No privileged role, no oracle dishonesty within bands, and no third-party cooperation is needed — LP withdrawal is an ordinary "own trade on Aquarius".

### Recommendation
Decouple leg-level price failure from whole-account liquidation: skip or zero-value collateral legs whose feed is unusable inside `calculate_account_risk_totals` for liquidation/cleanup paths (debt legs must still price), or allow liquidation plans to exclude unpriceable supply legs. Alternatively, make the Aquarius floor graceful — e.g., fall back to a conservative lower-bound price or last-good cached quote with a bounded staleness instead of `InsufficientAquariusLiquidity` — and keep `min_pool_value_wad` well above plausible single-LP withdrawal impact at admission time.

### Proof of Concept
1. Attacker supplies large collateral C (e.g., USDC) and borrows asset D near max LTV.
2. Attacker supplies a dust amount of listed Aquarius LP token L as an additional supply leg via `controller.supply` (no price needed).
3. Attacker holds LP shares in L's pool; calls Aquarius `withdraw` to reduce pool value below `min_pool_value_wad`.
4. Price of D rises / C falls so HF < 1. Any liquidator calling `controller.liquidate` reverts: `fetch_prices` → aggregator `prices()` omits L (`InsufficientAquariusLiquidity` internally) → `OracleNotConfigured` panic [6](#0-5) .
5. `clean_bad_debt` likewise reverts while valuing the same supply book.
6. When convenient, attacker re-adds liquidity, restores the price, and exits — or lets debt accrue into socialized bad debt.
