### Title
Bad-debt supply-index floor resurrects wiped supply shares and drains later deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` clamps a total bad-debt write-down to the nonzero `SUPPLY_INDEX_FLOOR_RAW` instead of invalidating the pre-wipe supply shares. [1](#0-0)  Because `PoolSeizeEntry` burn-side cleanup calls this function while leaving every unrelated supplier's scaled position intact, those shares retain a small positive claim despite the market's supplied value having been fully written down. [2](#0-1)  A subsequent deposit creates real cash backing, after which the stale shares can be withdrawn for unbacked tokens. [3](#0-2) 

### Finding Description
Bad-debt cleanup converts each remaining borrow leg into `bad_debt` and applies it to that market's supply index. [2](#0-1)  The write-down caps `bad_debt` at total supplied value and derives `new_supply_index = old_index * remaining / total`. [4](#0-3)  When `bad_debt >= total_supplied_value`, `remaining` is zero, but the index is then raised to `SUPPLY_INDEX_FLOOR_RAW`, leaving all historical scaled supply positions with approximately 0.1% of their original value. [5](#0-4) 

Those positions still evaluate through `resolve_withdrawal`, which returns all scaled shares and their floor-rounded token value on a withdraw-all request. [6](#0-5)  Withdrawal then checks only current pool cash, debits it, and transfers the calculated amount. [7](#0-6) [8](#0-7)  The repository's own regression test demonstrates that a stranded pre-wipe claim pays out a fresh supplier's deposit and leaves the fresh claim undercollateralized. [9](#0-8) 

### Impact Explanation
This is theft of later suppliers' funds and protocol insolvency: a holder of wiped shares receives cash that should belong only to post-wipe depositors. [10](#0-9)  The unbacked amount is proportional to the wiped share supply; every unit of remaining floor-index value can consume one unit of newly deposited cash. [1](#0-0) 

### Likelihood Explanation
A single unprivileged user can hold the pre-wipe supply position on one account and create the bad debt on another account. [11](#0-10)  After the debt becomes socializable, the attacker can invoke the public liquidation path as `liquidate(liquidator, account_id, debt_payments, SeizeMode::Credit(0))`; post-liquidation accounting automatically invokes `execute_bad_debt_cleanup` when `is_socializable_bad_debt` is true. [12](#0-11) [13](#0-12)  Permissionless cleanup can also call the same pool burn-side path directly, so completing the exploit does not require administrator privileges. [14](#0-13) 

### Recommendation
Do not preserve a nonzero supply index for shares that survived a complete write-down. Introduce a supply epoch/generation or equivalent wiped-market tombstone so pre-wipe positions resolve to zero, then restart issuance from a clean index for new positions; alternatively remove the index floor only where it can be guaranteed that all shares have been burned and no stale position can later unscale. [15](#0-14)  Add an end-to-end test that performs bad-debt cleanup, creates a new supply account, and proves a pre-wipe position's `withdraw(caller, account_id, [(asset, 0)], Some(recipient))` returns zero rather than draining the new deposit. [16](#0-15)

```rust
/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
```
