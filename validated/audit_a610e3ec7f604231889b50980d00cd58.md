### Title
`Shipit::WebhooksController#repository_owner` organization fallback lets an attacker sign a payload with org A's `webhook_secret` while `StatusHandler` writes a `CommitStatus` onto a commit belonging to org B's stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` derives the signing organization purely from `params.dig('repository','owner','login') || params.dig('organization','login')`, and `StatusHandler#process` resolves the target commit purely via `Commit.where(sha: params.sha)`, with no cross-check that the verifying organization actually owns the repository/stack that owns the matched commit. An attacker who controls a webhook-secret for one org (A) can forge a `status` event that verifies against A's secret yet mutates a `Commit`/`CommitStatus` belonging to a stack owned by a different org (B), as long as they know or reuse a `sha` that exists in Shipit's database for a commit under B.

### Finding Description
The broken binding: **verifying org (`repository_owner` resolved at `app/controllers/shipit/webhooks_controller.rb:61`) == owning org of the mutated `Commit`'s `Stack`**. This does not hold.

- `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `github_app = Shipit.github(organization: repository_owner)` and checks the `X-Hub-Signature` HMAC against that org's configured `webhook_secret`.
- `repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`) is:
  `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`.
  Since the entire raw POST body is attacker-supplied JSON (this is not GitHub calling in — it's any internet client hitting `/webhooks`), the attacker fully controls whether `repository.owner.login` is present. They can omit it and only set `organization.login = "A"`, causing verification to run against org A, whose secret they know because they administer a repo under A.
- `create` (`app/controllers/shipit/webhooks_controller.rb:10-15`) dispatches to `Shipit::Webhooks.for_event(event)` handlers, e.g. `StatusHandler`.
- `StatusHandler#process` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`) does `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`. This query is **global**, not scoped by `repository.full_name`, org, or stack — any commit row in the entire installation matching that `sha` gets a new `CommitStatus`, regardless of which org's secret validated the request.

Exploit flow: attacker sets `repository.full_name = "B/repo"` (or omits `repository` entirely, relying only on `organization.login`), sets `organization.login = "A"`, computes a valid `X-Hub-Signature` HMAC-SHA1 over the raw body using A's `webhook_secret` (which they legitimately possess as an admin of an A-owned repo hooked into Shipit), and sets `sha` to a known/guessable commit sha that exists under B's stack (commit shas are public git data, easily obtainable from B's public GitHub repo, PRs, etc.). `verify_signature` passes because it only checked A's secret. `StatusHandler#process` then writes a `CommitStatus` on B's commit — B's org secret, permissions, and webhook configuration are never consulted.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type is handled, not org binding; `ExplicitParameters` (`params do requires :sha ... end`) only validates the shape of `status`-event fields, not their relation to `repository_owner`; there is no model-level validation tying `Commit#stack`/`Stack#repository` to the org that signed the webhook.

### Impact Explanation
The attacker forges a `CommitStatus` (state/description/target_url/context) on an arbitrary commit belonging to an org/stack they do not control and never authenticated against, using only a secret they legitimately hold for an unrelated org. This is a cross-tenant integrity break: `CommitStatus` on a commit can gate `deployable?` (`app/models/shipit/commit.rb:227-229`) and drive `schedule_continuous_delivery` (`app/models/shipit/commit.rb:281-287`), i.e., forging a "success" status can unblock/trigger continuous deployment on someone else's stack, or forging a "failure"/blocking status can sabotage another org's release pipeline. This is repeatable against any commit sha the attacker can learn, across arbitrarily many tenants that share the same Shipit instance. This matches "a payload for one repository mutating another's stack/commit" in the Critical impact category.

### Likelihood Explanation
Preconditions: the attacker needs a valid `webhook_secret` for at least one org (A) configured in this Shipit instance — trivially satisfied if they administer/own any repository whose org is connected to Shipit, which is the baseline "unprivileged" actor described (any GitHub user who owns a repo can obtain their own org's webhook secret from their own GitHub settings, or via Shipit's own setup flow granting them a secret for their own org). They additionally need a commit `sha` belonging to victim org B's stack, which is public information for public repos. No Shipit session, API token, or GitHub App key is required. Cost is a single crafted HTTP POST with a correctly computed HMAC using a secret the attacker legitimately possesses. Fully repeatable.

### Recommendation
In `StatusHandler#process` (and other handlers matching commits/PRs by sha/number), scope `Commit.where(sha: params.sha)` further by the repository that authenticated the webhook — i.e. resolve the `Stack`/`Repository` from `params['repository']['full_name']` (or an equivalent authenticated identifier) and intersect/join against it, rejecting or ignoring commits that don't belong to that repository's stacks. Additionally, `verify_signature` should not silently fall back to `organization.login` when `repository.owner.login` is missing but a `repository.full_name` is present that names a different org; the org used for the HMAC check should be derived consistently with the org whose data the handler is about to mutate, and any handler that touches records must re-validate that those records' owning repository matches the org that was actually verified.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (illustrative)
test 'status event verified against org A mutates a commit under org B stack' do
  org_a_secret = 'org-a-secret'
  stub_github_org_secret('A', org_a_secret)

  stack_b = shipit_stacks(:shipit) # belongs to org B, e.g. repository full_name "B/repo"
  commit_b = stack_b.commits.create!(sha: '0' * 40, message: 'victim commit')

  payload = {
    'organization' => { 'login' => 'A' },
    'repository'   => { 'full_name' => 'B/repo' }, # no repository.owner.login
    'sha'   => commit_b.sha,
    'state' => 'success',
    'context' => 'forged'
  }.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', org_a_secret, payload)

  post '/webhooks', params: payload,
       headers: { 'X-Github-Event' => 'status', 'X-Hub-Signature' => signature, 'Content-Type' => 'application/json' }

  assert_response :ok
  # Left side of binding: org that verified the signature
  verifying_org = 'A'
  # Right side of binding: org owning the mutated commit's stack
  owning_org = stack_b.repository.owner # "B"
  refute_equal verifying_org, owning_org # binding broken

  assert commit_b.reload.statuses.exists?(context: 'forged'),
         "expected forged status on B's commit despite signature verifying only against A's secret"
end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    end
