### Title
`GaslessModule.ExtractTxBundles` Omits Deadline Re-Validation at Block-Building Time, Enabling Proposer KAIA Loss via Expired-Deadline Swap Bundles - (`kaiax/gasless/impl/builder.go`)

---

### Summary

The `GaslessModule` (KIP-247) bundles gasless swap transactions into `[LendTx, ApproveTx?, SwapTx]` bundles without re-checking the user-supplied `deadline` parameter against the timestamp of the block being built. The deadline is only validated at txpool admission time, and that check is performed against `g.Chain.CurrentBlock().Time()` — the **last committed block's timestamp** — not the timestamp of the block under construction. A malicious user can submit a `GaslessSwapTx` with `deadline = currentBlock.Time()`, which passes the txpool gate but is already expired relative to the next block. The proposer then executes `LendTx` (transferring KAIA to the user) and `ApproveTx`, after which `SwapTx` reverts on-chain because `block.timestamp > deadline`. The proposer loses the lent KAIA with no repayment.

---

### Finding Description

**Txpool admission path — deadline checked against the wrong timestamp:**

In `kaiax/gasless/impl/tx_pool.go`, `checkBalanceForSwap` is the function returned by `GetCheckBalance()` and is invoked when a transaction enters the pool:

```go
// tx.deadline >= currentTimestamp
deadline := swapArgs.Deadline
if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
    return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", ...)
}
```

The comparison is `deadline >= g.Chain.CurrentBlock().Time()`. This uses the **last committed block's timestamp**, not the timestamp of the block being built. In Kaia (1-second block interval), the next block will have timestamp `currentBlock.Time() + 1`. A swap with `deadline = currentBlock.Time()` satisfies `deadline >= currentBlock.Time()` and is admitted to the pool.
