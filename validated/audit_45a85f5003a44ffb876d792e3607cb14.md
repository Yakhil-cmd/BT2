## Confirmed multi-org config

`Shipit.github(organization:)` looks up per-organization config keyed by the org name, each with its own independent `webhook_secret` (or `nil`) [1](#0-0) . The org key used to select which app/secret to verify against is taken purely from the **request payload**, not from any authenticated context: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [2](#0-1) . Meanwhile, `verify_webhook_signature` unconditionally returns `true` when that selected org has no `webhook_secret` configured: `return true unless webhook_secret` [3](#0-2) . But every event handler resolves the actual `Repository`/`Stack` to act on using a **different** field of the same payload — `repository.full_name` — via `Handler#repository_name` and `Handler#stacks` [4](#0-3) , e.g. `PushHandler#process` triggers `stack.sync_github` for any not-archived stack matching that repo/branch [5](#0-4) .

### Title
Webhook signature key selection uses `repository.owner.login`, but event handlers act on `repository.full_name` from the same unauthenticated payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Finding Description
In the documented multi-org GitHub App configuration, each organization has an independent `webhook_secret`, and `webhook_secret` is explicitly optional per-org (`docs/setup.md`, `config/secrets.development.shopify.yml`) [6](#0-5) . `WebhooksController#verify_signature` picks which app/secret to validate the signature against solely from `repository_owner`, itself read straight out of the untrusted JSON body [2](#0-1) . If that org has no `webhook_secret` set, `GitHubApp#verify_webhook_signature` trivially passes for *any* signature, including a missing/garbage one [3](#0-2) .

The binding broken: the equality "organization whose credential authenticated the webhook == repository that gets written to" does not hold. An attacker can craft a payload where `repository.owner.login` names an org configured with no `webhook_secret` (satisfying signature verification trivially) while `repository.full_name` names a completely different, secured org's tracked repository (the value actually used by `Handler#repository_name`/`#stacks` to select the `Stack` to mutate) [4](#0-3) . Handlers such as `PushHandler` then act on that unrelated stack — enqueuing `GithubSyncJob` for it — using data that was never covered by any valid signature [5](#0-4) .

### Impact Explanation
This lets an unprivileged, unauthenticated network attacker forge push/status/pull_request/check_suite/membership events attributed to any repository tracked by the engine, as long as the deployment configures at least one organization without a `webhook_secret` (an explicitly supported/"optional" configuration per the docs). Depending on handler, this can trigger unwanted `GithubSyncJob` runs, spurious commit statuses, review-stack archive/unarchive actions, or team/user creation — event injection into a repository the attacker does not control, crossing the "organization authenticated vs. repository written" boundary the rules call out.

### Likelihood Explanation
Requires no credentials, no GitHub App installation, no session — only that the engine's multi-org config includes one org with `webhook_secret` unset (a state the shipped example configs explicitly show as valid/default), and knowledge of that org's name and of the target repository's `full_name`. Both are guessable/public.

### Recommendation
Bind the signature-verification organization to the same value used for repository/stack resolution, and require `verify_signature` to also assert that the resolved `Stack`'s repository organization matches `repository_owner`. Do not allow signature verification to unconditionally succeed when `webhook_secret` is blank in multi-org mode; if an org opts out of a webhook secret, at minimum ensure the acted-upon repository belongs to that same org.

### Proof of Concept
1. Configure two orgs in `secrets.github`: `orgA` (tracked target stack, `webhook_secret: "real-secret"`) and `orgB` (`webhook_secret: nil`).
2. POST to `/webhooks` with `X-Github-Event: push`, no/garbage `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-controlled sha>",
  "repository": { "owner": { "login": "orgB" }, "full_name": "orgA/target-repo" }
}
```
3. `verify_signature` resolves `Shipit.github(organization: "orgB")`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` regardless of signature.
4. `PushHandler` resolves the stack via `repository.full_name == "orgA/target-repo"` and enqueues `GithubSyncJob` for it, despite the request never being validated against `orgA`'s secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
