### Title
Attacker-controlled fork parent owner/repo name printed to terminal without ANSI sanitization enables terminal injection - ([File: pkg/cmd/repo/clone/clone.go])

### Summary
`cloneRun` prints `ghrepo.FullName(canonicalRepo.Parent)` (composed from `Owner.Login`/`Name` fields returned by the GitHub API) directly into `cs.Bold(...)` and `fmt.Fprintf(opts.IO.ErrOut, ...)` when a fork's upstream is set, without passing it through any escape-sequence sanitization, unlike other output paths in this codebase.

### Finding Description
In `cloneRun`, when `canonicalRepo.Parent != nil` and stdout is a TTY, the code does: [1](#0-0) 
`canonicalRepo.Parent` is populated straight from the `api.GitHubRepo` API response, and `ghrepo.FullName` simply concatenates `RepoOwner()` and `RepoName()` with `fmt.Sprintf("%s/%s", ...)`: [2](#0-1) 
The resulting string is fed straight to `cs.Bold(...)` and `fmt.Fprintf` on `opts.IO.ErrOut`, an `io.Writer`, not the sanitizing `ContentOut`/`Untrusted` wrapper types this codebase otherwise defines specifically for this purpose. The codebase demonstrates that the maintainers are aware of and actively defend against exactly this class of bug elsewhere: `iostreams.Untrusted` sanitizes any string that passes through `fmt` verbs [3](#0-2) , `ContentOut`/`SetContentSanitization` wrap external content with an `asciisanitizer` transform by default [4](#0-3) , and there are dedicated regression tests confirming raw ESC bytes must never reach the terminal from untrusted API/log content [5](#0-4) . None of these mechanisms are applied to the `canonicalRepo.Parent` full name printed in `clone.go`. GitHub.com's slug validation (alphanumeric/hyphen) prevents this on github.com, but on GitHub Enterprise Server or other hosts accepted by `gh` (`ghinstance`/`ghrepo` do not restrict hostnames or re-validate owner/repo charset from arbitrary API responses), a looser or misconfigured backend could return owner/repo strings containing control bytes, which would flow unfiltered into this `Fprintf` call.

### Impact Explanation
If an attacker can get the parent-repo owner login or name to contain ANSI/OSC control sequences (feasible against a non-GitHub.com host without github.com's strict slug validation, or via any host whose validation is bypassed/misconfigured), the victim's terminal renders the injected escape sequence when they clone a fork of that repo. This can hide/alter the "set as default repository" warning text or, with more advanced OSC/DCS sequences depending on terminal emulator, manipulate the terminal title, cursor position, or clipboard—matching a terminal/output-injection impact class. This does not directly grant code execution or credential theft on github.com itself given its strict naming rules, so impact is scoped and host-dependent.

### Likelihood Explanation
Requires the victim to clone a fork whose parent is attacker-controlled, on a TTY (`opts.IO.IsStdoutTTY()`), and only manifests against hosts that don't enforce github.com's owner/repo character restrictions. On github.com proper, this is not exploitable because repo/owner names are restricted to a safe charset; likelihood is low-to-moderate and enterprise/host-dependent, not universally reproducible.

### Recommendation
Wrap `ghrepo.FullName(canonicalRepo.Parent)` in the existing `iostreams.Untrusted` type (or run it through the `asciisanitizer` transform) before formatting/printing, consistent with how other untrusted external strings are handled elsewhere in the codebase (e.g. `pkg/iostreams/untrusted.go`).

```go
// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```

```go
// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}
```
