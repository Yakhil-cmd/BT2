### Title
Webhook signature verification silently bypassed for any organization without a configured `webhook_secret` - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever the resolved organization's `webhook_secret` is blank, without performing any HMAC comparison against `X-Hub-Signature` or the raw request body. Combined with `Shipit::WebhooksController#repository_owner`, which lets the attacker pick which organization's `GitHubApp` config is used purely from the unauthenticated JSON body, any organization configured without a `webhook_secret` (e.g. `somegithuborg` in `config/secrets.development.shopify.yml`) grants full webhook forgery for any repository it owns.

### Finding Description
The broken binding: the code should enforce `signature == HMAC(webhook_secret, raw_body)` for the organization owning the target repository, but instead enforces `webhook_secret.present? => true : (verified = true)`, i.e. **no check occurs at all** when `webhook_secret` is nil/blank.

Path:
1. `before_action :check_if_ping, :drop_unhandled_event, :verify_signature` runs on every `POST /webhooks` request [1](#0-0) .
2. `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)`, where `repository_owner` is read straight from the attacker-controlled JSON body (`params.dig('repository','owner','login')`) with no authentication [2](#0-1) [3](#0-2) .
3. `GitHubApp#verify_webhook_signature` immediately returns `true` if `webhook_secret` is blank, before touching `signature` or `message` [4](#0-3) .
4. `verified` is `true`, so `head(422) unless verified` does not fire, and `create` proceeds to dispatch `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [5](#0-4) .

Exploit: attacker sends `POST /webhooks` with header `X-Github-Event: push`, arbitrary/garbage `X-Hub-Signature`, and JSON body containing `repository.owner.login = "somegithuborg"` (an org configured with `webhook_secret: nil`, per `config/secrets.development.shopify.yml`) and `repository.full_name` pointing to a real tracked stack under that org. The push handler will process the forged payload as if it came from GitHub, mutating the targeted stack's commit/state records.

No other guard intervenes: `drop_unhandled_event` only checks event type presence, not signature; `check_if_ping` only short-circuits `ping` events; there is no `ExplicitParameters` schema or `require_permission!` on this unauthenticated controller. `Shipit.github_app_config` resolution correctly raises `GithubOrganizationUnknown` for truly unknown orgs, but does nothing to enforce that a *known* org actually has a secret configured.

### Impact Explanation
An attacker who knows (or can determine, e.g. from public config templates or a misconfigured deployment) that an organization lacks a `webhook_secret` can forge arbitrary GitHub webhook events (`push`, `status`, `check_suite`, `pull_request`, `membership`, etc.) for any repository/stack owned by that organization, with no credentials whatsoever. This is a full authentication bypass on the webhook endpoint for that organization, enabling attacker-controlled mutation of commit/task/stack state and one repository's payload can poison another under the same org boundary. Severity: Critical - authentication bypass leading to unauthorized writes of Shipit domain state driven entirely by attacker-supplied webhook payloads.

### Likelihood Explanation
The precondition is purely a configuration state already shown to exist in this repo's sample secrets file (`webhook_secret: # nil` for `somegithuborg`/`someothergithuborg`), meaning any deployment that copies this template without setting a secret is exploitable. No secrets, sessions, or privileged roles are needed by the attacker - only knowledge of the vulnerable org's key and a real tracked repository under it. The request is a single unauthenticated HTTP POST, fully repeatable against any number of stacks under the same misconfigured org.

### Recommendation
Change `GitHubApp#verify_webhook_signature` so a missing/blank `webhook_secret` fails closed (`return false unless webhook_secret`) rather than fails open, and/or enforce at boot/config-load time that every configured GitHub org must have a non-blank `webhook_secret`, raising a startup error otherwise.

### Proof of Concept
```ruby
# test/unit/github_app_test.rb (new test)
test "verify_webhook_signature returns false, not true, when webhook_secret is blank" do
  app = Shipit::GitHubApp.new('org', {}) # no webhook_secret configured

  # Binding under test: signature validity should not depend on secret presence.
  # Expected (secure) behavior: verified == false for garbage signature/body.
  # Actual (vulnerable) behavior: verified == true unconditionally.
  verified = app.verify_webhook_signature('garbage', 'garbage')

  refute verified, "expected signature verification to fail when no webhook_secret is configured, " \
                    "but it returned true unconditionally (auth bypass)"
end
```
This directly demonstrates `return true unless webhook_secret` at [6](#0-5)  causes verification to pass for arbitrary signature/body pairs, confirming the controller-level bypass reachable via `WebhooksController#verify_signature` [7](#0-6) .

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
