### Title
Missing Validation of New `governance.governingnode` Vote Value Allows Permanent Governance Lockout in Single Mode — (`File: kaiax/gov/headergov/impl/header.go`)

### Summary

In `single` governance mode, the `checkConsistency` function validates only that the *current* governing node is in the council, but never validates the *new* address being voted for. A governing node can vote to change `governance.governingnode` to `address(0)` or any non-council address. Once ratified, no real account controls the new governing node, permanently locking all header governance in single mode.

### Finding Description

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` handles the `GovernanceGoverningNode` case as follows: [1](#0-0) 

The check at line 175 (`slices.Contains(council, params.GoverningNode)`) tests whether the **current** governing node is in the council — it says nothing about the **new** value carried in `vote.Value()`. The new address is never inspected.

The `FormatChecker` for `GovernanceGoverningNode` in `kaiax/gov/param.go` accepts any `common.Address`, including `address(0)`: [2](#0-1) 

The test suite in `kaiax/gov/headergov/vote_test.go` explicitly lists `"0x0000000000000000000000000000000000000000"` as a **good vote** for `GovernanceGoverningNode`, confirming the zero address passes all format and consistency checks: [3](#0-2) 

The `Vote()` API in `kaiax/gov/headergov/impl/api.go` enforces only that the caller is the current governing node, then calls `checkConsistency` which passes for any valid address type: [4](#0-3) 

After ratification at the epoch boundary, `GoverningNode` is updated to the new value. In single mode, the `VerifyVote` guard then permanently blocks all future votes: [5](#0-4) 

Because `vote.Voter() != address(0)` is always true for any real proposer, every subsequent governance vote is rejected with `ErrVotePermissionDenied`.

### Impact Explanation

Once `GoverningNode` is ratified as `address(0)` (or any address not in the council), in `single` mode:

- No further `governance_vote` calls succeed at the API layer (`voter != gp.GoverningNode` always true).
- No block header can carry a valid `Vote` field (`VerifyVote` rejects all).
- All governance-controlled parameters are permanently frozen: `governance.unitprice`, `reward.mintingamount`, `reward.ratio`, `reward.kip82ratio`, `istanbul.committeesize`, KIP-71 base fee bounds, etc.
- Reward distribution amounts and fee parameters cannot be adjusted, constituting a permanent protected-state impact on KAIA issuance and fee accounting.

### Likelihood Explanation

The trigger requires the current governing node (a semi-trusted role) to cast a vote with an incorrect address — either by mistake (passing `address(0)` or a wrong hex string to `governance_vote`) or by a compromised key. The contract is already live and the epoch is long (604,800 blocks on mainnet), so the incorrect vote may not be noticed until after ratification. This mirrors the UniswapV3Factory scenario exactly: the contract continues to function normally (blocks are produced, transfers work) while the privileged role is silently locked.

### Recommendation

In `checkConsistency` for `GovernanceGoverningNode`, add validation of the **new** value (`vote.Value()`):

1. Reject `address(0)` as a new governing node.
2. Require the new governing node address to be present in the current council (so the new governing node can actually propose blocks and cast votes).

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if !slices.Contains(council, params.GoverningNode) {
        return ErrGovNodeNotInValSetList
    }
    // NEW: validate the proposed new governing node
    newNode, ok := vote.Value().(common.Address)
    if !ok || newNode == (common.Address{}) {
        return ErrInvalidKeyValue
    }
    if !slices.Contains(council, newNode) {
        return ErrGovNodeNotInValSetList
    }
    return nil
```

Long-term, consider a two-step governing node transfer (propose + accept) so the new governing node must confirm acceptance before the change takes effect.

### Proof of Concept

1. Chain is running in `single` governance mode with `GoverningNode = 0xALICE` (Alice is in the council and is the proposer).
2. Alice calls: `governance_vote("governance.governingnode", "0x0000000000000000000000000000000000000000")`.
3. `Vote()` passes: `voter == gp.GoverningNode` ✓; `NewVoteData` succeeds (zero address is a valid `common.Address`) ✓; `checkConsistency` passes (Alice is in council) ✓.
4. Alice's node inscribes the vote in `header.Vote` when she next proposes a block.
5. At the next epoch block, `getExpectedGovernance` collects the vote; `VerifyGov` confirms it matches; `GoverningNode` is ratified as `address(0)`.
6. From `(k+1)*epoch` onward: every call to `governance_vote` returns `ErrVotePermissionDenied`; every block header with a `Vote` field is rejected by `VerifyVote`. Governance is permanently locked. [1](#0-0) [4](#0-3) [2](#0-1) [3](#0-2)

func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)

			return err
		}

			return nil
		}
		return ErrGovNodeNotInValSetList

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
