### Title
Cross-tenant `PullRequest` write via `AssignedHandler#process` due to signature/target mismatch - (File: `app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb`)

### Summary
`WebhooksController#verify_signature` authenticates a webhook using the HMAC secret of whatever organization is named in `repository.owner.login` (or `organization.login`), but `AssignedHandler#process` resolves and mutates the target `PullRequest` using the independently-controlled `repository.full_name` field from the same attacker-supplied JSON body. Because these two fields are never checked for consistency, an attacker who owns a legitimate GitHub org connected to Shipit can forge a `pull_request` `assigned`/`unassigned` payload that authenticates as their own org while pointing `repository.full_name` at a victim repository, causing `pull_request.update(github_pull_request: params.pull_request)` to mutate a PR row that belongs to a repository the attacker never controls.

### Finding Description
The broken binding as an explicit equality: `repository_owner (from payload.repository.owner.login, used by verify_signature)` == `owning_org(params.repository.full_name)` — this is **false**, and nothing in the code enforces it.

Path:
1. `WebhooksController#verify_signature` computes `repository_owner` purely via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0)  and uses it to select the `GitHubApp` (and thus the HMAC `webhook_secret`) to verify the raw request body against `X-Hub-Signature` [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` only checks that the signature matches the secret configured for that one organization — it has no knowledge of, and does not validate, `repository.full_name` [3](#0-2) .
3. Once verified, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the entire raw JSON — including the attacker-chosen `repository.full_name` — to `AssignedHandler.call` [4](#0-3) .
4. `AssignedHandler#process` looks up the target `PullRequest` solely by `params.number` joined to `Repository.from_github_repo_name(params.repository.full_name)` — a field the attacker fully controls and which was never checked against `repository_owner` — and then unconditionally calls `pull_request.update(github_pull_request: params.pull_request)` [5](#0-4) .

The `ExplicitParameters` schema in `AssignedHandler` only validates types/presence of fields (String/Integer/Array), not that `repository.full_name`'s owner matches `repository.owner.login` or `repository_owner` used for signing [6](#0-5) . No other guard (`drop_unhandled_event`, `force_github_authentication`, model validations) inspects this cross-field relationship.

Attacker request: a raw HTTP POST to `/webhooks` with header `X-Github-Event: pull_request`, `X-Hub-Signature` computed with the HMAC secret configured for the attacker's own onboarded GitHub organization, and a JSON body where `repository.owner.login`/`organization.login` = attacker-org (so verification passes) but `repository.full_name` = `"victim-org/victim-repo"` and `number` = an existing victim PR number, with `action` = `"assigned"`.

Exploit flow: Shipit verifies the signature successfully because it was computed correctly for the attacker-org's secret; the handler then joins on the victim's repository via `full_name` and overwrites `github_pull_request` on the victim's `PullRequest` row with entirely attacker-controlled JSON (title, state, additions/deletions, head sha/ref, assignees, labels, etc.), none of which reflects reality on GitHub.

### Impact Explanation
An attacker who owns any GitHub organization onboarded into Shipit's multi-tenant `secrets.github` config (i.e., has a valid, distinct webhook secret for their own org) can corrupt arbitrary `PullRequest` records belonging to any other tenant repository known to Shipit, by supplying a fabricated `github_pull_request` payload (title, state, head sha/ref, assignees, labels). This is a cross-tenant data-integrity/row-write vulnerability: one repository's authenticated webhook credential mutates another repository's persisted stack/PR state, matching the "payload for one repository mutating another's stack/commit/task" Critical category. It is repeatable against any victim repo/PR number as long as the attacker's own org's webhook secret is known to them, with no rate limiting on repeats.

### Likelihood Explanation
Preconditions: the attacker must legitimately control (or their GitHub org must be) one of the organizations configured in Shipit's multi-tenant `secrets.github` (necessary in any real deployment using this webhook flow, since Shipit resolves the verifying secret per-org). Given that, the attacker needs no Shipit session, API token, or victim's secret — only their own org's webhook secret, which they know as the org owner/admin. The victim PR must already exist and be joined through `stack: :repository`. This requires no social engineering, no TLS interception, and no privileged Shipit role — it is entirely a signature/target binding gap in the webhook processing pipeline, making it highly feasible wherever multi-org GitHub App configuration is in use.

### Recommendation
In `WebhooksController#verify_signature` (or in the `Handler` base class), after signature verification, cross-check that the organization used to verify the signature (`repository_owner`) matches the actual owner segment of `repository.full_name` in the parsed payload before dispatching to any handler; reject the request (e.g., `head(422)`) on mismatch. Additionally, handlers such as `AssignedHandler`/`EditedHandler` should not trust `params.repository.full_name` alone to resolve records — they should also require that the resolved `Repository`'s owner matches the verified `repository_owner`.

### Proof of Concept
Minitest plan (mirrors existing `EditedHandler` test style, under `test/models/shipit/webhooks/handlers/pull_request/assigned_handler_test.rb`):
1. Create `victim_stack` with `Repository` owned by `"victim-org/victim-repo"`, and a `PullRequest` with `number: 42` associated to that stack.
2. Configure `Shipit.github(organization: "attacker-org")` with a distinct known `webhook_secret` (e.g., stub `secrets.github["attacker-org"]`).
3. Build a payload: `{ action: "assigned", number: 42, repository: { full_name: "victim-org/victim-repo", owner: { login: "attacker-org" } }, pull_request: { ...attacker-controlled fields... }, sender: { login: "attacker" } }`.
4. Compute `X-Hub-Signature` using `attacker-org`'s webhook secret over the raw JSON body.
5. POST to `/webhooks` with `X-Github-Event: pull_request` and the forged signature.
6. Assert response is `200 OK` (i.e., `verify_signature` passed).
7. Reload `victim_pull_request` and assert `github_pull_request` was overwritten with the attacker-supplied JSON (e.g., assert `victim_pull_request.reload.title == attacker_supplied_title`), proving `repository_owner("attacker-org") != owning_org("victim-org")` yet the write succeeded — demonstrating the broken binding.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def process
            return unless respond_to_assignee_change?

            pull_request.update(github_pull_request: params.pull_request) if pull_request.present?
          end

          private

          def respond_to_assignee_change?
            %w[assigned unassigned].include?(params.action)
          end

          def pull_request
            @pull_request ||= Shipit::PullRequest
                              .joins(:stack, stack: :repository)
                              .find_by(
                                number: params.number,
                                stacks: {
                                  repositories:
                                    {
                                      id: repository.id
                                    }
                                }
                              )
          end

          def repository
            Shipit::Repository.from_github_repo_name(params.repository.full_name) || Shipit::NullRepository.new
