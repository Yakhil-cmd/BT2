## Analysis

The claimed exploit chain requires the attacker to deliver a forged `status` webhook payload that GitHub itself never sent. Before the payload ever reaches `StatusHandler#process` (or `Commit#create_status_from_github!`), it must pass `WebhooksController#verify_signature`: [1](#0-0) 

which calls `GithubApp#verify_webhook_signature`: [2](#0-1) 

This performs an HMAC-SHA1 comparison using `webhook_secret`, a value the attacker explicitly does not possess per the threat model ("They hold no ... `webhook_secret`"). Without a valid signature, `head(422)` is returned and the request never reaches `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, so `StatusHandler#process` and `Commit#create_status_from_github!` are never invoked with attacker-controlled data. [3](#0-2) 

Because the equality that must diverge — "attacker-forged status payload == payload accepted as authentic by `verify_signature`" — cannot be established without the shared `webhook_secret`, the premise "a forged status makes a foreign commit deployable" is unreachable for the described attacker. The downstream logic in `Stack#build_deploy` (`ignored_safeties: force || !until_commit.deployable?`) and `trigger_continuous_delivery` behaves exactly as designed once a commit is legitimately marked deployable by real CI — this is the intended continuous-delivery behavior for stacks that have opted into `continuous_deployment: true`, not an authorization bypass: [4](#0-3) [5](#0-4) 

The existing signature-verification guard fully blocks the attacker from reaching the state the question depends on, and no bypass of that guard is demonstrated within this engine's code under the stated attacker capabilities (no secrets, no privileged role, no GitHub App installation on a repo they control that's registered with Shipit).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
