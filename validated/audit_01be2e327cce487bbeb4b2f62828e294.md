### Title
`compute_v2_review_set` drops amended-commit dangerous changes from the Stop-hook review set - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
When Claude (or a co-operating attacker-controlled automation flow) edits a dangerous file and then folds that edit into the *existing* HEAD commit with `git commit --amend`, `compute_v2_review_set` computes an empty review set even though the dangerous content was introduced during the session. The ancestry check used to detect "commits made this turn" fails for amended commits, and the working-tree-diff term is empty once the amend leaves the tree clean, so the intersection that forms `review_set` becomes empty and the Stop hook silently skips the file.

### Finding Description
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` builds the review set as:
```
review_set = dirty_now & changed_since
``` [1](#0-0) 

`dirty_now` starts from `git status` against the current `HEAD` (`_git_status_porcelain`), and is only augmented with commit-range files when `head_at_capture` is verified to be an *ancestor* of the current `HEAD`:
```
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
``` [2](#0-1) 

`head_at_capture` is the `HEAD` SHA recorded at `UserPromptSubmit` time via `handle_user_prompt_submit` [3](#0-2) .

If, during the turn, the exact commit that was `head_at_capture` is the one being amended (`git commit --amend` on the pre-existing HEAD, incorporating the newly-edited dangerous file), git rewrites that commit into a brand-new object with the *same parent* rather than a descendant. `head_at_capture` is therefore **not** an ancestor of the new `HEAD`, so `_is_ancestor` returns `False` and the "commits this turn" term is never added to `dirty_now`. Because the amend also leaves the working tree clean, `git status` (`_git_status_porcelain`) reports nothing dirty, so `dirty_now` ends up empty (assuming no other untracked/dirty files exist). `changed_since` (diffed against the stashed `baseline_sha`) still contains the dangerous file, but since `review_set = dirty_now & changed_since`, the empty `dirty_now` makes the final `review_set` empty regardless of `changed_since`'s contents.

This is reachable purely through normal, unprivileged git operations inside the attacker's own cloned repo/session: edit a file, then run `git commit --amend` on the commit that existed when the turn's baseline was captured. No admin privilege, key leakage, or social engineering is required — it is an ordinary developer workflow (fixup via amend) that an attacker-controlled agent turn or automation flow can trigger. The result is that `consume_stop_state`/`compute_v2_review_set`'s review-set computation silently treats the dangerous, just-introduced change as already reviewed/non-existent, breaking the stated invariant that the review set must track "files whose content differs from the pre-turn stash baseline" for content actually changed in the turn.

### Impact Explanation
This breaks the core security guarantee of the Stop-hook LLM review pipeline: a dangerous code change introduced during a Claude session can be committed via `--amend` and completely evade the git-diff-derived review set, so `analyze_code_security`/`agentic_review` never sees it and no `exit(2)` warning is raised. This is a silent skip of the intended "review everything Claude changed this turn" guarantee — a wrong-target/incomplete-review outcome with real security impact, since it lets a dangerous change ship without the mandatory review gate that the rest of the plugin (`ENABLE_CODE_SECURITY_REVIEW`, `ENABLE_STOP_REVIEW`) is built around.

### Likelihood Explanation
Highly feasible and fully repeatable: it requires only two ordinary git commands available to any user/agent in a normal session — edit a tracked file, then `git commit --amend`. No race condition, no special repo state, and no privilege beyond normal repository write access is needed. It reproduces deterministically whenever the amended commit is the same commit that was HEAD at the start of the turn (i.e., a single-commit turn using amend instead of a new commit — a common workflow pattern for "fixup the last commit").

### Recommendation
In `compute_v2_review_set`, don't gate the commit-range term on `_is_ancestor(head_at_capture, current_head)` alone. Additionally detect commit rewrites (amend/rebase) where `head_at_capture` is no longer reachable from `current_head`, and in that case fall back to diffing `baseline_sha` (or `head_at_capture` directly, non-range) against `current_head` (e.g. `git diff head_at_capture HEAD --name-only` rather than the `A..B` two-dot range, which requires ancestry) so amended/rewritten commits still surface changed files. Union that result into `dirty_now` (or drop the `dirty_now &` intersection requirement for this fallback path) so the amend case cannot produce an empty review set when `changed_since` is non-empty.

### Proof of Concept

2. Simulate `UserPromptSubmit`: call `capture_git_baseline(cwd)` and `_git_rev_parse_head(cwd)` to get `baseline_sha == head_at_capture == C0`.
3. Simulate the Claude turn: edit `victim.py` to add a dangerous pattern (e.g. `os.system(user_input)`), stage it, then run `git commit --amend --no-edit` (amending `C0` in place, producing `C0'`).
4. Call `compute_v2_review_set(cwd, baseline_sha=C0, head_at_capture=C0)`.

6. Expected (fixed) assertion: `review_set` (returned `review_paths`) contains `victim.py`, proving the dangerous amended change stays reviewable. [4](#0-3)

def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
    if not isinstance(untracked_at_baseline, dict):
        untracked_at_baseline = {}

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```
