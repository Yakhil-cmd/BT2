### Title
Unauthenticated Bridge Peer Can Invoke `kaia_sendTransaction` via `ServiceChainCall` to Sign and Submit Transactions from Unlocked Accounts — (`node/sc/main_bridge_handler.go`, `node/sc/mainbridge.go`)

---

### Summary

`handleCallMsg` in `MainBridgeHandler` accepts a raw `ServiceChainCall` P2P message from any connected bridge peer and writes its bytes verbatim into the internal `rpcConn` pipe, which feeds directly into a fully-functional `rpc.Server` that has `KaiaTransactionAPI` (including `kaia_sendTransaction`) registered. There is no method allowlist, no caller authentication, and no payload inspection. Any peer that can complete the bridge P2P handshake — which requires only a matching network ID and protocol version, not a pre-approved key — can invoke any registered RPC method, including `kaia_sendTransaction`, which will sign and submit a transaction using any account that is currently unlocked in the node's account manager.

---

### Finding Description

**Step 1 — Bridge peer connection requires no allowlist.**

`MainBridge.Start` creates a P2P server that listens on `MainBridgePort` and accepts inbound connections. The only admission checks are the RLPx ECDH handshake (any ephemeral key pair satisfies it) and the bridge-level status handshake, which only validates `NetworkId` and `ProtocolVersion`: [1](#0-0) 

No peer-ID allowlist, no IP restriction, and no pre-shared secret is enforced.

**Step 2 — `handleCallMsg` blindly pipes the message payload into the RPC server.** [2](#0-1) 

The raw bytes from the P2P message are written directly to `mb.rpcConn` with zero validation, filtering, or method restriction.

**Step 3 — `rpcConn` is one end of an in-process `net.Pipe` whose other end is served by a full `rpc.Server`.** [3](#0-2) 

The comment in `ServeCodec` confirms that codec options (the `0` flag) are no longer supported, so no method-level restrictions apply: [4](#0-3) 

**Step 4 — `SetComponents` registers all public `kaia`/`klay` APIs, including `KaiaTransactionAPI`, into that server.** [5](#0-4) 

**Step 5 — `KaiaTransactionAPI.SendTransaction` signs with the account manager's unlocked accounts.** [6](#0-5) 

The `sign` helper calls `AccountManager().Find(account)` and then `wallet.SignTx(account, tx, chainID)`: [7](#0-6) 

If the `from` address is unlocked, the transaction is signed and submitted to the tx pool with no further authorization.

---

### Impact Explanation

A remote attacker who can reach the bridge P2P port crafts a JSON-RPC payload:

```json
{"jsonrpc":"2.0","method":"kaia_sendTransaction",
 "params":[{"from":"0x<unlocked_addr>","to":"0x<attacker>","value":"0x<amount>"}],
 "id":1}
```

They send it as a `ServiceChainCall` P2P message. The main-bridge node signs and submits the transaction on behalf of the unlocked account, transferring KAIA to the attacker. The unlocked account's nonce is also consumed, potentially disrupting legitimate bridge operations.

---

### Likelihood Explanation

Bridge nodes routinely run with unlocked operator accounts — the bridge accounts must be unlocked to sign cross-chain value-transfer transactions. The bridge P2P port is a network-accessible service. Any attacker who knows the target's IP, port, network ID, and protocol version (all discoverable or guessable) can connect and exploit this path without any credentials.

---

### Recommendation

1. **Restrict the method namespace exposed via `ServiceChainCall`**: register only a minimal, read-only subset of APIs (e.g., `kaia_getBalance`, `kaia_getTransactionCount`) into `mb.rpcServer`, explicitly excluding any method that mutates state or signs transactions.
2. **Validate the RPC method name before forwarding**: parse the JSON-RPC payload in `handleCallMsg` and reject any method not on an explicit allowlist before writing to `rpcConn`.
3. **Authenticate bridge peers**: maintain a configured allowlist of trusted peer node IDs and reject `ServiceChainCall` messages from peers not on the list.

---

### Proof of Concept

1. Start a MainBridge-enabled Kaia node with one account unlocked (`--unlock 0xALICE`).
2. Connect a custom P2P client to `MainBridgePort`, complete the RLPx handshake with any ephemeral key, and send a valid `StatusMsg` with the correct `NetworkId` and `ProtocolVersion`.
3. Send a `ServiceChainCall` message whose payload is the RLP encoding of:
   ```json
   {"jsonrpc":"2.0","method":"kaia_sendTransaction",
    "params":[{"from":"0xALICE","to":"0xATTACKER","value":"0xDE0B6B3A7640000"}],
    "id":1}
   ```
4. Observe that the transaction appears in the tx pool, `0xALICE`'s balance decreases by 1 KAIA, and the nonce increments — all without the account owner's consent.

	msg, err := p.rw.ReadMsg()

		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)

	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}

		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil

func (mbh *MainBridgeHandler) handleCallMsg(p BridgePeer, msg p2p.Msg) error {
	logger.Trace("mainbridge writes the rpc call message to rpc server", "msg.Size", msg.Size, "msg", msg)
	data := make([]byte, msg.Size)
	err := msg.Decode(&data)
	if err != nil {
		logger.Error("error in mainbridge message handler", "err", err)
		return err
	}

	// Write to RPC server pipe
	_, err = mbh.mainbridge.rpcConn.Write(data)
	if err != nil {
		logger.Error("failed to write to the rpc server pipe", "err", err)
		return err
	}
	return nil
}

// Note that codec options are no longer supported.
func (s *Server) ServeCodec(codec ServerCodec, options CodecOption) {
	defer codec.close()

	// Don't serve if server is stopped.
	if atomic.LoadInt32(&s.run) == 0 {
		return
	}

	// Add the codec to the set so it can be closed by Stop.
	s.codecs.Add(codec)
	defer s.codecs.Remove(codec)

	c := initClient(codec, s.idgen, &s.services, BatchRequestLimit, BatchResponseMaxSize)
	<-codec.closed()
	c.Close()
}

// sign is a helper function that signs a transaction with the private key of the given address.
func (s *KaiaTransactionAPI) sign(addr common.Address, tx *types.Transaction) (*types.Transaction, error) {
	// Look up the wallet containing the requested signer
	account := accounts.Account{Address: addr}

	wallet, err := s.b.AccountManager().Find(account)
	if err != nil {
		return nil, err
	}
	// Request the wallet to sign the transaction
	return wallet.SignTx(account, tx, s.b.ChainConfig().ChainID)
}

func (s *KaiaTransactionAPI) SendTransaction(ctx context.Context, args SendTxArgs) (common.Hash, error) {
	if args.AccountNonce == nil {
		// Hold the addresse's mutex around signing to prevent concurrent assignment of
		// the same nonce to multiple accounts.
		s.nonceLock.LockAddr(args.From)
		defer s.nonceLock.UnlockAddr(args.From)
	}

	signedTx, err := s.SignTransaction(ctx, args)
	if err != nil {
		return common.Hash{}, err
	}

	return submitTransaction(ctx, s.b, signedTx.Tx)
}
