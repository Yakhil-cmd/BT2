The Tinyproxy bug is a C-specific defect: a hand-rolled HTTP/1.1 proxy using `strcmp` instead of a case-insensitive comparison to detect `Transfer-Encoding: chunked`, enabling request smuggling. I searched the polkadot-sdk codebase for any analogous custom HTTP header parsing, particularly around `Transfer-Encoding`/chunked-encoding detection, in both the offchain-worker HTTP client (`substrate/client/offchain/src/api/http.rs`) and the RPC server (`substrate/client/rpc-servers/src/lib.rs`, `substrate/client/rpc-servers/src/utils.rs`).

None of these components implement their own HTTP request-line/header parser. They all delegate to the `hyper` crate for HTTP parsing, which uses `HeaderName`/`HeaderMap` types that are inherently case-insensitive by construction [1](#0-0) , and chunked-transfer handling is performed internally by `hyper`'s body/frame machinery rather than by any custom `strcmp`-style comparison in this codebase [2](#0-1) . The RPC server similarly builds on `hyper`/`jsonrpsee` request handling without reimplementing header-name comparisons [3](#0-2) .

Beyond the parsing-library difference, this bug class also fails the required reachability test: there is no signed extrinsic, contract call, or XCM message path in FRAME/XCM/Cumulus that involves parsing raw HTTP headers or Transfer-Encoding values — the affected code (offchain worker HTTP client, RPC server ingress) is client/node infrastructure invoked by node operators or offchain workers, not a runtime state-transition path reachable by an unprivileged on-chain attacker. No unbacked issuance, unauthorized dispatch, freezing, or consensus-affecting outcome can be constructed from this bug class in this codebase.
