This confirms the vulnerability. The `stacks` scope in `Api::BaseController#stacks` (`Stack.where(id: current_api_client.stack_id)`) exists specifically to restrict an `ApiClient` bound to a single stack (`stack_id` foreign key set), but `CCMenuUrlController#fetch` creates a `CCMenu Client` with **no `stack_id` set at all** — `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` never sets `stack`, so `current_api_client.stack_id?` is false and `stacks` would return `Stack.all` anyway for that client. `check_permissions!` only checks the `permissions` array, never `stack_id`.
