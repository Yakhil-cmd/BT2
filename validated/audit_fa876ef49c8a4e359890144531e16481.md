### Title
Webhook signature verified against attacker-chosen organization while event is applied to a different repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and therefore which `webhook_secret`) to check the `X-Hub-Signature` against by reading `repository.owner.login` (or `organization.login`) directly out of the unauthenticated, attacker-controlled JSON body. The individual event handlers, however, resolve the `Stack`/`Repository` to act on using a *different* field from that same body: `repository.full_name` (via `Repository.from_github_repo_name`). Because both fields are supplied by the requester before any signature has been validated, an attacker can decouple "the organization whose secret is used to authenticate the request" from "the repository whose Stack state is mutated."

### Finding Description
`verify_signature` computes the organization used for signature verification purely from the request body: [1](#0-0) [2](#0-1) 

This picks a `GitHubApp` instance per organization via `Shipit.github(organization: repository_owner)`, and `verify_webhook_signature` explicitly returns `true` unconditionally when that organization's `webhook_secret` is blank/unset: [3](#0-2) 

Multi-tenant installs configure one `GitHubApp` per GitHub organization keyed by name (`github_app_config`), each with its own independent `webhook_secret`: [4](#0-3) 

Meanwhile, every event handler determines the actual `Stack`/`Repository` it mutates using `repository.full_name`, taken from the very same request body, independently of `repository_owner`: [5](#0-4) [6](#0-5) 

Because `repository.owner.login`/`organization.login` (used to select the verification secret) and `repository.full_name` (used to select the repository to act on) are two independent, attacker-supplied JSON fields, an attacker who is a member of/controls any organization onboarded to the multi-tenant Shipit instance with a blank `webhook_secret` (this is the documented default in the sample secrets files — `webhook_secret: # nil`) can forge a payload where:
- `repository.owner.login` = an org whose `webhook_secret` is nil (so `verify_webhook_signature` short-circuits to `true`), and
- `repository.full_name` = `victim-org/victim-repo`, an entirely different tenant's repository with a real `Stack` configured in this Shipit instance.

The signature check passes because it authenticates only the "owner" identity, but the handler code (`PushHandler`, `PullRequest::*Handler`, etc.) never re-checks that `repository.owner.login` matches the owner implied by `repository.full_name`. This breaks the intended binding: *organization authenticated == repository written*.

### Impact Explanation
This lets an unprivileged, unauthenticated attacker forge GitHub webhook events (`push`, `pull_request`, `status`, `check_suite`, `membership`, etc.) for any repository tracked by the Shipit instance, as long as at least one onboarded organization has no `webhook_secret` configured (a state explicitly shown as the default in the shipped secrets templates). Concretely this allows triggering `GithubSyncJob` for a victim stack's branch with an attacker-chosen `expected_head_sha`, forcing sync/CI-status state changes, or creating/archiving `review_stack`s for a victim repository — corrupting deploy/release state without any credential for the impacted organization. This maps to "High: unauthenticated read/write of stack state" territory, and if `merge`/`deploy` gating logic trusts commit or check-run status derived from spoofed webhook events, it can escalate into an unauthorized deploy path.

### Likelihood Explanation
Requires only: (1) the operator running a multi-organization Shipit install, and (2) at least one onboarded organization configured without a `webhook_secret` (shown as the default/expected value in `config/secrets.development.shopify.yml` and `docs/setup.md` where the secret is explicitly marked optional). No credentials, GitHub App keys, or Shipit session are needed — the attacker only needs to know one onboarded org's name and craft a raw POST to `/webhooks`.

### Recommendation
Bind the verified identity to the acted-upon resource: after verifying the signature for organization `O`, require that `repository.full_name`'s owner segment equals `O` (or, more simply, verify the signature using the same field the handlers use for repository resolution) before dispatching to handlers. Additionally, consider making `webhook_secret` mandatory (reject requests / refuse to boot) for any configured organization rather than silently trusting unsigned payloads when it is blank.

### Proof of Concept
1. Configure Shipit with two organizations in `secrets.github`: `attacker-org` (no `webhook_secret` set) and `victim-org` (owns a real Stack for `victim-org/victim-repo`).
2. As an anonymous attacker, POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "attacker-org" }
  }
}
```
3. `verify_signature` calls `Shipit.github(organization: "attacker-org")`; because `attacker-org`'s `webhook_secret` is blank, `verify_webhook_signature` returns `true` regardless of the (even absent) `X-Hub-Signature` header.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and enqueues `GithubSyncJob` for the victim stack with the attacker-chosen `expected_head_sha`, despite the request never being authenticated for `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
