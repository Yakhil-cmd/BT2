### Title
`WebhooksController` verifies HMAC against `repository.owner.login`/`organization.login` while every event handler dispatches on `repository.full_name` (or a global `sha`), letting a webhook accepted under one (unauthenticated) org confusion path drive state for an unrelated repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Finding Description
`WebhooksController#verify_signature` selects the GitHub App/secret to check the HMAC against using only `repository.owner.login` (falling back to `organization.login`), and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 

Crucially, `GitHubApp#verify_webhook_signature` returns `true` unconditionally when no `webhook_secret` is configured for that organization: `return true unless webhook_secret`. [3](#0-2) 

Shipit explicitly supports multi-organization configuration where each org has its own (optional) `webhook_secret`. [4](#0-3) 

Once a request clears `verify_signature`, the actual event `Handler` never re-checks which organization/repository was authenticated. `Handler#repository_name` and `#stacks` resolve the target purely from a separate JSON field, `repository.full_name`, which is not tied to the field used for the signature lookup: [5](#0-4) 

`PushHandler#process` then syncs any stack matching that resolved repository/branch to an attacker-supplied `after` SHA: [6](#0-5) 

Even more directly, `StatusHandler#process` looks up commits **globally by SHA with no repository scoping at all** and writes a CI status onto whatever commit matches, across all stacks/repos: [7](#0-6) 

This breaks the intended binding: `organization that authenticated the webhook == repository/commit that is written by the handler`. If an operator has configured at least one organization without a `webhook_secret` (a state the shipped example config treats as a normal/expected option, `webhook_secret: # nil`), an unauthenticated internet caller can:
1. Send a POST to `/webhooks` with `X-Github-Event: status` (or `push`), setting `repository.owner.login`/`organization.login` to the unsecured org name — `verify_webhook_signature` returns `true` with no secret check.
2. Because `StatusHandler` does not scope by repository/org at all, supply any `sha` value that happens to collide with a real commit belonging to a completely different, properly-secured repository/stack, and set an arbitrary `state`/`description`/`target_url` on it via `Commit#create_status_from_github!`.
3. For `push`, set `repository.full_name` to a real tracked repo (again unrelated to the org used for the signature check) to force `stack.sync_github(expected_head_sha: params.after)` on that stack.

### Impact Explanation
Commit statuses influence deploy-safety gating (CI/merge status checks) in Shipit; an attacker who can set an arbitrary status on an arbitrary commit without any valid webhook secret for that repository's actual organization can mark unsafe commits as green, potentially enabling merges/deploys that should have been blocked, or force a resync/deploy pipeline for an unrelated stack. This is a genuine authentication-binding failure (org authenticated ≠ repository/commit written), reachable by a fully unprivileged attacker under a realistic, explicitly-supported configuration (multi-org setups where not every org has a `webhook_secret`).

### Likelihood Explanation
Requires that the deployment has at least one configured GitHub organization without a `webhook_secret` — this is a supported and documented configuration option (`config/secrets.development.example.yml`, `config/secrets.development.shopify.yml` for multi-org setups), not a misuse of the engine. Given that, no credentials, tokens, or secrets are needed by the attacker; a single unauthenticated POST suffices. Likelihood is therefore conditional but plausible in the multi-org deployment model the engine itself documents and supports.

### Recommendation
- Do not treat a missing `webhook_secret` as "verification passed" — require every configured organization to have a `webhook_secret`, or explicitly fail closed if it is absent, rather than returning `true`.
- Bind the signature-verification identity to the same field(s) the handlers act on: verify using the org/repo derived from `repository.full_name` (not a separate `repository.owner.login`/`organization.login` lookup), and reject if they diverge.
- Scope `StatusHandler` and `CheckSuiteHandler` commit lookups by the resolved `Repository`/`Stack` (via `repository.full_name`) instead of a bare, cross-repository `Commit.where(sha: ...)` query.

### Proof of Concept
1. Configure two orgs in `secrets.yml`: `secure-org` (with `webhook_secret` set) and `open-org` (with `webhook_secret` left blank), per the documented multi-org schema.
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<sha of an existing commit belonging to secure-org/some-repo>",
  "state": "success",
  "organization": { "login": "open-org" }
}
```
3. `verify_signature` resolves `repository_owner` to `"open-org"`, calls `Shipit.github(organization: "open-org").verify_webhook_signature(...)`, which returns `true` unconditionally because `open-org` has no `webhook_secret`. [8](#0-7) 
4. `StatusHandler#process` runs `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`, setting a fabricated `success` status on the `secure-org` commit, with no relationship checked between `open-org` and that commit's actual repository. [7](#0-6)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )

    end

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
