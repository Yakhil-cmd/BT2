### Title
Zero `GasTarget` Governance Vote Causes Divide-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting All Honest Nodes — (`params/kip71_config.go`)

---

### Summary

`NextMagmaBlockBaseFee` divides by `gasTarget` without a zero-guard. The `BaseFeeDenominator` field has an explicit zero-guard in the same function, but `GasTarget` does not. A governance vote setting `kip71.gastarget = 0` is accepted by all validation layers, ratified at the next epoch, and then causes a Go runtime panic (`integer divide by zero`) on every node that calls `NextMagmaBlockBaseFee` with any non-zero `parentGasUsed`. This crashes block validators, block producers, and the tx-pool base-fee filter simultaneously, halting the chain.

---

### Finding Description

`NextMagmaBlockBaseFee` in `params/kip71_config.go` reads `GasTarget` from the governance parameter set and uses it as a divisor in two places:

```go
// line 102 (parentGasUsed > gasTarget branch)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))

// line 120 (parentGasUsed < gasTarget branch)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
``` [1](#0-0) 

The immediately preceding field, `BaseFeeDenominator`, is explicitly protected against zero:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64) // fallback
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
``` [2](#0-1) 

No equivalent guard exists for `GasTarget`.

The governance vote handler `checkConsistency` lists `gov.Kip71GasTarget` in the "no further checks" branch, meaning any `uint64` value — including `0` — passes vote verification:

```go
case gov.GovernanceDeriveShaImpl, ...,
    gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    ...:
    return nil
``` [3](#0-2) 

`NewVoteData` accepts `uint64(0)` for `Kip71GasTarget` without error (the type check passes; no range check exists). [4](#0-3) 

---

### Impact Explanation

`NextMagmaBlockBaseFee` is called from four production paths:

| Caller | Effect of panic |
|---|---|
| `blockchain/block_validator.go` | Every incoming block fails validation → node cannot sync |
| `work/worker.go` | Block production crashes → proposer cannot produce blocks |
| `blockchain/tx_pool.go` | Pending tx filtering crashes → tx pool broken |
| `node/cn/gasprice/feehistory.go` | Fee history RPC crashes | [5](#0-4) 

When `gasTarget = 0` and `parentGasUsed > 0` (any block containing transactions), the condition `parentGasUsed == gasTarget` (line 90) is false, so execution falls into the `parentGasUsed > gasTarget` branch and immediately panics at the division. The only safe escape is `parentGasUsed == 0` (empty blocks), which is not guaranteed and cannot be relied upon.

The corrupted value is the **next block's `BaseFee`** — it can never be computed, so no valid Magma-era block header can be produced or accepted. This is a persistent consensus divergence: all honest nodes crash on the first non-empty block after the governance change takes effect.

---

### Likelihood Explanation

- In `single` governance mode (Kaia Mainnet and Kairos), the governing node is the sole voter. One actor casting `kip71.gastarget = 0` is sufficient.
- In `none` mode, any GC member can cast the decisive vote.
- The vote passes `VerifyVote` (voter is proposer, value type is `uint64`) and `checkConsistency` (no range check for `Kip71GasTarget`).
- The ratified value takes effect at the start of the next epoch — a deterministic, predictable trigger point.
- The developer already identified this class of risk for `BaseFeeDenominator` and added a fallback, but omitted the same protection for `GasTarget`.

---

### Recommendation

Add a zero-guard for `GasTarget` mirroring the existing `BaseFeeDenominator` guard in `NextMagmaBlockBaseFee`:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // To avoid panic, fall back to a safe default
    gasTarget = DefaultGasTarget
}
```

Additionally, add a range check in `checkConsistency` for `gov.Kip71GasTarget` to reject zero values at vote time, analogous to the existing bounds checks for `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee`:

```go
case gov.Kip71GasTarget:
    if vote.Value().(uint64) == 0 {
        return ErrInvalidGasTarget
    }
    return nil
``` [6](#0-5) 

---

### Proof of Concept

1. On a Magma-enabled chain in `single` governance mode, the governing node calls:
   ```
   governance_vote("kip71.gastarget", 0)
   ```
2. The vote is inscribed in `header.Vote` when the governing node is proposer. `VerifyVote` passes (voter is proposer, `uint64(0)` is a valid type). `checkConsistency` returns `nil` for `Kip71GasTarget`.
3. At the next epoch block, the vote is ratified and written to `header.Governance`. `VerifyGov` passes.
4. From the next epoch onward, `GetParamSet(N).GasTarget == 0`.
5. Any block with `parentGasUsed > 0` triggers:
   ```
   NextMagmaBlockBaseFee(...) →
     gasTarget = 0
     parentGasUsed > 0 → enters "parentGasUsed > gasTarget" branch
     x.Div(x, new(big.Int).SetUint64(0)) → panic: integer divide by zero
   ```
6. `block_validator.go` panics on every received block → node crashes.
7. `worker.go` panics when building the next block → proposer crashes.
8. All honest nodes crash; the chain halts. [7](#0-6) [8](#0-7)
