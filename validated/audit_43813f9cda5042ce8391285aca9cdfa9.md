### Title
Membership webhook trusts caller-supplied `organization.login` independent of the org whose secret verified the request - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` picks the GitHub App/org config solely from `params.dig('repository','owner','login')` (or `organization.login` as a fallback only when `repository` is absent), and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org has no `webhook_secret` configured. The `membership` event handler (`Shipit::Webhooks::Handlers::MembershipHandler`) never reads `repository` at all — it uses the payload's own `organization.login`/`team.id`/`member.login` fields to find-or-create a `Team` and add a member. Because the field used for signature-org-selection (`repository.owner.login`) and the field used for the actual mutation (`organization.login`) are two independent, attacker-controlled JSON fields in the same forged request, an attacker can pick a no-secret org for the former and the victim org/team for the latter.

### Finding Description
The broken binding, stated as an equality that should hold but doesn't:

`org_used_to_verify_signature(repository.owner.login) == org_whose_state_is_mutated(organization.login)`

Trace:
1. `verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` via `repository_owner` (line 59-62): `params.dig('repository','owner','login') || params.dig('organization','login')`. It only falls back to `organization.login` when the `repository` key is entirely missing.
2. It calls `Shipit.github(organization: repository_owner)` and `github_app.verify_webhook_signature(signature, raw_post)`.
3. In `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83): `return true unless webhook_secret`. If the org selected by `repository_owner` has no `webhook_secret` configured in `secrets.github`, **any** signature (or none at all is even checked) verifies successfully.
4. `MembershipHandler#process` (app/models/shipit/webhooks/handlers/membership_handler.rb:22-43) never reads `params.repository` — its `params` schema only requires `action`, `team{id,name,slug,url}`, `organization{login}`, `member{login}`. It calls `find_or_create_team!`, which does `Team.find_or_create_by!(github_id: params.team.id) { |team| team.organization = params.organization.login }`, then `team.add_member(member)` or removes a member.

Attack request: a forged POST `/webhooks` with header `X-Github-Event: membership`, body:
```json
{
  "action": "added",
  "repository": {"owner": {"login": "attacker-no-secret-org"}},
  "organization": {"login": "victim-org"},
  "team": {"id": <existing victim team github_id>, "name": "Developers", "slug": "developers", "url": "https://example.com"},
  "member": {"login": "attacker-github-login"}
}
```
Because `repository.owner.login` = `attacker-no-secret-org` selects a `GitHubApp` instance with no `webhook_secret`, `verify_webhook_signature` returns `true` regardless of the `X-Hub-Signature` header (attacker doesn't even need a valid HMAC). Once past `verify_signature`, `MembershipHandler` looks up the pre-existing `Team` record by `github_id` (created earlier through legitimate sync from `victim-org`, matching `Shipit.github_teams`) and appends `attacker-github-login` as a member — granting the attacker membership in a team used for `Shipit.github_teams` authorization, without ever touching `victim-org`'s real webhook secret.

Existing guards don't stop this:
- `drop_unhandled_event` only checks the event name is registered, not the org consistency.
- `ExplicitParameters` schema on `MembershipHandler` only validates types/presence of `organization.login`, `team.*`, `member.login` — it does not cross-check against `repository.owner.login` or verify that the "verifying org" equals the "mutating org".
- There is no code anywhere that asserts `repository_owner == params.dig('organization','login')` for the `membership` handler.
- `require_permission!`/`User#authorized?`/`force_github_authentication` are irrelevant here since this is an unauthenticated webhook endpoint by design (webhooks are meant to be verified purely by HMAC signature, not session).

The root cause is twofold: (a) the signature-verification org-selection key (`repository.owner.login`) and the handler's mutation org key (`organization.login`) are never required to match, and (b) `verify_webhook_signature` silently no-ops (`return true`) when the selected org has no configured secret, rather than failing closed.

### Impact Explanation
An attacker who can send an arbitrary unauthenticated HTTP POST to `/webhooks` — no Shipit session, no API token — can, provided the operator has configured at least one organization in `secrets.github` without a `webhook_secret`, forge a `membership` event and cause Shipit to add themselves (or anyone) as a member of any existing `Shipit::Team` record whose `github_id` they can guess or learn (team IDs/slugs/URLs are visible via GitHub's own team pages, or via Shipit's own team management UI/API for shared repos). This is a privilege escalation into `Shipit.github_teams` authorization (High per the provided severity matrix) because these teams gate access to Shipit UI/permissions (`Shipit.github_teams`, `User#authorized?` depends on team membership in many Shipit deployments). The attack is repeatable indefinitely and against any `Team` row already synced in the database, not scoped to a specific repository the attacker owns.

### Likelihood Explanation
Exploitation strictly requires that the Shipit deployment has **at least one** GitHub organization configured in `secrets.github` with no `webhook_secret` set (multi-org config format, `TOP_LEVEL_GH_KEYS`/`github_app_config`). If every configured org has a secret set, `verify_webhook_signature` always requires a valid HMAC for whichever org is selected, and the attacker cannot forge the signature for the fallback org either — closing this particular path (though the org/mutation-target mismatch by itself, independent of the "no-secret" trick, still exists as a design smell but would then require a valid signature for *some* org, which the attacker doesn't have). This is a plausible but not universal misconfiguration; it depends on operator setup rather than a code guarantee, so likelihood is conditional on that configuration state. Given that precondition, attacker cost is trivial (a single crafted HTTP request, no secrets needed).

### Recommendation
1. In `Shipit::WebhooksController`, derive the org used for signature verification identically to the org the handler will mutate for every event type, or better, have each handler explicitly declare/return the org it's about to mutate and assert it equals `repository_owner` before proceeding.
2. Make `GitHubApp#verify_webhook_signature` fail closed (return `false`) when `webhook_secret` is blank instead of `return true unless webhook_secret`, unless there is a deliberate single-org legacy mode that should be handled differently and explicitly guarded.
3. In `MembershipHandler`, validate `params.organization.login` against the same repository/org context used for signature verification (or require `repository.owner.login` to match `organization.login` before creating/mutating a `Team`).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit
  class Team < Record
    REQUIRED_HOOKS = %i[membership].freeze

    has_many :memberships
    has_many :members, class_name: :User, through: :memberships, source: :user

    has_many :github_hooks,
             -> { where(event: REQUIRED_HOOKS) },
             foreign_key: :organization,
             primary_key: :organization,
             class_name: 'GithubHook::Organization',
             inverse_of: false

    class << self
      def find_or_create_by_handle(handle)
        organization, slug = handle.split('/').map(&:downcase)
        find_by(organization:, slug:) || fetch_and_create_from_github(organization, slug)
      end

      def fetch_and_create_from_github(organization, slug)
        return unless github_team = find_team_on_github(organization, slug)

        create!(github_team:, organization:)
      end

      def find_team_on_github(organization, slug)
        gh_api = Shipit.github(organization:).api
        teams = Shipit::OctokitIterator.new(github_api: gh_api) { gh_api.org_teams(organization, per_page: 100) }
        teams.find { |t| t.slug == slug }
      rescue Octokit::NotFound
      end
    end
