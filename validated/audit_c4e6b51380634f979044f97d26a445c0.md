### Title
Cross-organization webhook trust confusion allows forging commit statuses for any repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to validate a webhook against using a field read directly out of the *unverified* JSON body (`repository.owner.login`, falling back to `organization.login`), before the HMAC signature is checked. Once that org-specific signature is valid, the resulting handlers (e.g. `StatusHandler`) act on payload fields that are never cross-checked against the organization that was authenticated, and in the case of `StatusHandler` are not scoped to any repository at all. This breaks the binding "the organization whose secret authenticated the webhook" == "the repository/commit the webhook is allowed to mutate."

### Finding Description
`Shipit.github(organization:)` supports a multi-tenant configuration where each organization has its own GitHub App and its own `webhook_secret` [1](#0-0) . The webhook controller picks which of these secrets to verify against based on a value taken from the raw, not-yet-verified request body: [2](#0-1) [3](#0-2) 

Once a signature validates against *some* configured org's secret, `Shipit::Webhooks.for_event(event)` dispatches the full, attacker-shaped `params` hash to handlers [4](#0-3) . Handlers such as `StatusHandler` never re-validate that the payload's target actually belongs to the organization that authenticated the request — `StatusHandler#process` looks up commits **globally by SHA**, with no repository or organization scoping whatsoever: [5](#0-4) 

`commit.create_status_from_github!(params)` then persists whatever `state`/`context`/`description` the attacker supplied onto that commit's status record, which is used by `ci.require` checks that gate deployability, as documented in the engine's own README .

So the equality that should hold — `organization authenticated by verify_signature == organization/repository whose commit is being mutated` — is never enforced. `PushHandler` is scoped only to `stacks` reachable from `Handler#stacks` and branch name, again without confirming that the `stacks` collection is limited to the org that just authenticated [6](#0-5) .

### Impact Explanation
In a multi-org Shipit deployment (the exact scenario `Shipit.github_app_config`/`github_organizations` is built to support), an operator who legitimately administers **their own** low-privilege organization's GitHub App (and therefore knows/controls that org's `webhook_secret` as part of normal GitHub App setup — not a Shipit credential) can:
1. Set `repository.owner.login` (or `organization.login`) in a crafted JSON body to their own org, so `verify_signature` selects their own org's `GitHubApp` and validates successfully with a secret they legitimately possess.
2. Set the `sha`/`state`/`context` fields in the same payload to target a commit belonging to a **completely different, unrelated organization's stack**, because `StatusHandler` performs a global `Commit.where(sha:)` lookup with no ownership check.
3. Successfully forge a `"success"` CI status on a victim commit they have no access to, potentially satisfying that stack's `ci.require` configuration and enabling an unauthorized deploy by the legitimate operators of the victim stack.

This is a cross-organization/cross-repository write achieved purely by exploiting the mismatch between the field used to pick the verifying secret and the field(s) used by the handler to select the mutation target — no `ApiClient` token, GitHub App private key, or Shipit session is required, only administrative control of an unrelated, less-privileged organization onboarded to the same Shipit instance.

### Likelihood Explanation
Requires: (a) a Shipit instance configured with multiple GitHub App organizations, and (b) attacker's own org having a legitimately configured `webhook_secret` they can compute/sign with (a normal precondition of onboarding any org to Shipit, not a privileged Shipit credential). Given that precondition, exploitation is a single crafted HTTP POST with a valid HMAC for the attacker's own org — no race condition, timing, or brute force needed. Likelihood is Medium-High in genuinely multi-tenant deployments, and not applicable to single-org deployments (where `github_default_organization` is `nil` and the notion of "attacker's own org" doesn't exist).

### Recommendation
- In `StatusHandler` (and similarly in `PushHandler`/other handlers), scope `Commit`/`Stack` lookups to repositories that belong to the organization that was authenticated in `verify_signature`, not just to the SHA/branch supplied by the payload.
- Thread the authenticated `repository_owner` (or its resolved `GitHubApp`) from `WebhooksController` into `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, and have each handler assert that `params.repository.full_name`'s owner matches the authenticated organization before mutating any record.

### Proof of Concept
1. Shipit configured with two orgs, `attacker-org` and `victim-org`, each with distinct GitHub Apps/`webhook_secret`s [7](#0-6) .
2. Attacker (admin of `attacker-org`'s GitHub App) crafts a `status` event JSON body:
   ```json
   {
     "repository": { "owner": { "login": "attacker-org" }, "full_name": "attacker-org/whatever" },
     "sha": "<victim-org commit sha>",
     "state": "success",
     "context": "ci/required-check"
   }
   ```
3. Attacker computes `X-Hub-Signature` using `attacker-org`'s known `webhook_secret` and POSTs to `/webhooks`.
4. `verify_signature` resolves `repository_owner` = `"attacker-org"`, fetches `Shipit.github(organization: "attacker-org")`, and the signature validates successfully [8](#0-7) .
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)` and finds the victim commit regardless of organization, writing a forged `"success"` status onto it [5](#0-4) .

Note: I was unable to inspect `Commit#create_status_from_github!` or `Repository.from_github_repo_name` implementations directly (not returned by search), so the exact downstream persistence/query logic for those methods could not be fully verified from source in this session — a Devin session with full file access would be needed to confirm the precise column-level effects and any additional scoping that might exist there.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
