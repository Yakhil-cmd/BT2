## Analog Found: Uncaught exception in address "definition template" evaluation crashes the node (DoS)

The Wireshark CVE is a parser that throws an unhandled/unrecovered error on crafted input and crashes the process. The reachable analog in `ocore` is the **`'definition template'` branch of `evaluate()` inside `validateAuthentifiers()`** in `definition.js`, which — unlike its sibling implementation in `validateDefinition()` — has **no error handling at all** around a JSON parse and a template-substitution routine that can throw. Because this executes inside a `conn.query()` callback, any exception raised there becomes an uncaught exception, and `network.js` is explicitly configured to crash the whole process on uncaught exceptions.

### Title
Unhandled exception in `'definition template'` authentifier evaluation crashes the full node — (File: definition.js)

### Summary
`validateAuthentifiers()`'s `evaluate()` function implements the `'definition template'` opcode without any try/catch, while the equivalent code path in `validateDefinition()`'s `evaluate()` does wrap the risky calls in try/catch and converts failures into soft validation errors.

### Finding Description
Any address can be defined using the op `['definition template', [unit, params]]`, which at spend/authentifier-verification time re-fetches the template unit's payload and re-instantiates the definition on every subsequent unit that uses this address (per the comment "we need to re-validate the definition every time"): [1](#0-0) 

The vulnerable code: [2](#0-1) 

- `throw Error("not 1 template")` is executed synchronously inside the `conn.query` async callback — there is no enclosing try/catch anywhere in this call chain, so this throw becomes an uncaught exception.
- `JSON.parse(template)` is likewise unguarded.
- `replaceInTemplate(arrTemplate, params)` can throw `NoVarException` (missing param) or a generic `Error("unknown type")` (default branch of its internal switch), and neither is caught here.

Compare this to the parallel code in `validateDefinition()`'s `evaluate()`, which is the version used the first time a definition is validated, and which *does* handle these cases gracefully: [3](#0-2) 
There, a missing/duplicate template row returns a soft error via `cb("template not found or too many")`, and `NoVarException` from `replaceInTemplate` is caught and converted to a callback error. The `validateAuthentifiers()` copy at lines 802-819 was not given the same protection.

`replaceInTemplate`'s exception source: [4](#0-3) 

Because Node.js cannot catch an exception thrown inside an already-returned async callback with a try/catch from an outer synchronous frame, this exception propagates to the top of the event loop and triggers the global handler that deliberately crashes the process: [5](#0-4) 

### Impact Explanation
Any full node that validates a unit signed by (or referencing, via `evaluateAssetCondition`) an address whose definition uses `'definition template'` — where the referenced template unit later becomes unavailable/ambiguous at the applicable `last_ball_mci`, or where template re-instantiation with the address's fixed `params` triggers `NoVarException`/`"unknown type"` — will hit an uncaught exception and crash. Since `validate()`/`validateAuthentifiers` runs for every spending/signing unit of that address, an attacker who can arrange such a mismatch (e.g., by controlling timing/context of stability such that the `main_chain_index<=?` filter yields 0 or >1 rows for that address's referenced template unit at a later validation than at creation time) can repeatedly crash any node that processes such a unit — a network-wide denial of service against consensus/validation, not merely the attacker's own client.

### Likelihood Explanation
The `'definition template'` address-definition feature is a normal-user, unprivileged capability (any unit poster can define such an address and later spend from it), and the vulnerable branch runs during ordinary signature/authentifier validation for every subsequent posted unit — no special hub/peer/network privileges are required to reach it.

### Recommendation
Wrap the query callback body in `definition.js`'s `validateAuthentifiers()` `'definition template'` case in try/catch mirroring `validateDefinition()`'s handling: treat `rows.length !== 1`, JSON parse failures, and `replaceInTemplate` exceptions (including `NoVarException`) as validation failures (`cb2(false)` / `fatal_error = ...`) instead of allowing them to throw uncaught inside the async callback.

### Proof of Concept
1. Post a `definition_template` message with a template requiring param `$x`.
2. Define an address `A` with definition `['definition template', [<template_unit>, {x: 'value'}]]`; this passes the guarded `validateDefinition()` path once.
3. Arrange a later unit signed by/spending from `A` (or referencing `A` in an asset condition) to be validated at a `last_ball_mci` where the SQL `SELECT payload FROM messages JOIN units USING(unit) WHERE unit=? AND app='definition_template' AND main_chain_index<=? AND +sequence='good' AND is_stable=1` returns `rows.length !== 1` (e.g., the template unit is not yet/no longer stable at that mci, or duplicate matching), reaching `throw Error("not 1 template")` inside `definition.js` `evaluate()`'s `'definition template'` case at [6](#0-5) , which is uncaught and crashes the validating node via the handler at `network.js:4530-4543`.

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}

function NoVarException(error){
	this.error = error;
	this.toString = function(){
		return this.error;
	};
}
