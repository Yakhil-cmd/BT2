### Title
Division-by-Zero Panic in `consolidatedNode.Split()` Crashes Block Finalization When Proposer Has Zero-Rounded Staking Amounts — (`kaiax/staking/staking_info.go`)

---

### Summary

`consolidatedNode.Split()` divides by `totalAmount = cnAmountBig + clAmountBig` without guarding against the case where both values are zero. Both staking amounts are stored in KAIA units (rounded down from kei), so any validator whose CNStaking contract holds less than 1 KAIA **and** whose CL pool holds less than 1 KAIA will produce `totalAmount = 0`. When such a validator is selected as the block proposer after the Prague hardfork, `FinalizeState` calls `Split` and the Go runtime panics with a division-by-zero, crashing the proposer node and preventing block production.

---

### Finding Description

**Root cause — `consolidatedNode.Split`** [1](#0-0) 

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics when totalAmount == 0
    cnAmount := big.NewInt(0).Sub(amount, clAmount)
    return cnAmount, clAmount
}
```

The only guard is `c.CLStakingInfo == nil`. There is no guard for `totalAmount == 0`.

**How amounts become zero**

Both `StakingAmount` and `CLStakingAmount` are stored in KAIA (not kei), rounded down: [2](#0-1) 

```go
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
// ...
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64(),
```

Any balance below `1e18 kei` (1 KAIA) rounds to `0`. A validator whose staking contract holds 0.9 KAIA and whose CL pool holds 0.5 KAIA will have `StakingAmount = 0` and `CLStakingAmount = 0`, yet `CLStakingInfo != nil` because the CL registry entry exists.

**Call path into `Split` during block finalization**

`FinalizeState` (reward module) calls `GetDeferredReward`, which routes to `getDeferredRewardFullKore` or `getDeferredRewardFullFlex`, both of which call `specWithProposerAndFunds` / `specWithProposerAndFundsFlex`: [3](#0-2) 

```go

    if cn.CLStakingInfo == nil { break }          // only nil-check, no zero-amount check

    ...
}
```

The identical pattern appears in `specWithProposerAndFundsFlex` at line 583. [4](#0-3) 

The reward module's `FinalizeState` is called unconditionally for every block: [5](#0-4) 

And `FinalizeState` is invoked both during block production (proposer) and block import (all validators): [6](#0-5) 

---

### Impact Explanation

When the triggering state is present, `big.Int.Div` panics unconditionally (Go's `math/big` panics on division by zero). This panic propagates up through `FinalizeState` → `DefaultExecutor.FinalizeState` → `SubmitTransactions`, crashing the goroutine. The proposer cannot produce a block for that round. Because the same `FinalizeState` code path is executed by every node when importing a block, if a block were somehow produced under this state, all importing nodes would also panic, causing a network-wide consensus halt.

The direct protected-state impact is **incorrect reward distribution**: the proposer's block reward (minted KAIA + deferred fees) is never credited to any address, and the block cannot be finalized, constituting a loss of the block reward for that round.

---

### Likelihood Explanation

Requires all of the following after the Prague hardfork:

1. `config.Rules.IsPrague == true` and `si.CLStakingInfos != nil` — both are normal post-Prague conditions on mainnet.
2. The block proposer is registered in AddressBook with a staking contract whose balance is < 1 KAIA.
3. The same proposer has a CLRegistry entry whose CL pool balance is also < 1 KAIA.

Conditions 2 and 3 are unusual for a production validator but are not prevented by any on-chain enforcement. A validator can register a staking contract and CL pool with negligible balances. In a permissioned validator set, such a validator can still be selected as proposer. The scenario is therefore reachable by any validator who controls their own AddressBook and CLRegistry entries.

---

### Recommendation

Add a zero-total guard in `consolidatedNode.Split` before dividing:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount := new(big.Int).Add(cnAmountBig, clAmountBig)

    // Guard: if both amounts are zero, all reward goes to the CN address.
    if totalAmount.Sign() == 0 {
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
```

This matches the semantics of the `c.CLStakingInfo == nil` branch (all reward to CN) and is consistent with the documented rule that a validator with zero CL staking receives no CL portion.

func (p *StateProcessor) FinalizeState(header *types.Header, statedb *state.StateDB, txs []*types.Transaction, receipts types.Receipts) (*types.Block, error) {
	// We can assure that if the magma hard forked block should have the field of base fee
	if p.config.IsMagmaForkEnabled(header.Number) {
		if header.BaseFee == nil {
			logger.Error("Magma hard forked block should have baseFee", "blockNum", header.Number.Uint64())
			return nil, errors.New("Invalid Magma block without baseFee")
		}
	} else if header.BaseFee != nil {
		logger.Error("A block before Magma hardfork shouldn't have baseFee", "blockNum", header.Number.Uint64())
		return nil, ErrInvalidBaseFee
	}

	for _, module := range p.blockStateModules {
		if err := module.FinalizeState(header, statedb, txs, receipts); err != nil {
			return nil, err
		}
	}

	header.Root = statedb.IntermediateRoot(true)

	// Assemble and return the final block for sealing
	return types.NewBlock(header, txs, receipts), nil
}
