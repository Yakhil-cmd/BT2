### Title
Council Member Unilaterally Escalates to Sole Governing Node via Unvalidated Mode-Transition Votes — (`kaiax/gov/headergov/impl/header.go`)

### Summary
In `none` governance mode, any council member who proposes blocks can submit two votes within the same epoch — `GovernanceGovernanceMode='single'` and `GovernanceGoverningNode=<self>` — both of which pass all validation checks without any majority requirement or council-membership check on the proposed governing node. At the epoch boundary, both are applied atomically, making the attacker the sole governing node with exclusive authority over all future governance votes.

### Finding Description
`checkConsistency` handles `GovernanceGovernanceMode` with an unconditional `return nil`: [1](#0-0) 

For `GovernanceGoverningNode`, the only council-membership check is gated behind `params.GovernanceMode == "single"`, so in `none` mode it also returns `nil` immediately: [2](#0-1) 

Additionally, even in `single` mode the check at line 175 validates whether `params.GoverningNode` (the **current** governing node) is in the council — not whether the **proposed** new value is — so the proposed address is never validated at all: [3](#0-2) 

The single-mode vote restriction in `VerifyVote` only fires when the chain is **already** in `single` mode: [4](#0-3) 

`getExpectedGovernance` applies every vote in the epoch with no majority threshold — one vote per key wins: [5](#0-4) 

### Impact Explanation
After the epoch boundary the chain's `GovernanceMode` is `single` and `GoverningNode` is the attacker's address. From that point the Permissionless-fork guard in `VerifyVote` (lines 103–107) rejects every vote from any other council member. The attacker has exclusive authority to vote on `RewardMintingAmount`, `RewardRatio`, `RewardKip82Ratio`, and every other governance parameter — constituting a full governance privilege escalation over protected chain state.

### Likelihood Explanation
The attacker only needs to be a council member (a validator) and to propose at least two blocks in the same epoch. In a standard epoch of hundreds of thousands of blocks, any council member will propose many blocks. No key compromise, majority collusion, or external service access is required.

### Recommendation
1. In `checkConsistency` for `GovernanceGoverningNode`, validate that `vote.Value().(common.Address)` is a member of the current council regardless of the current governance mode.
2. Add a cross-parameter consistency check: if a `GovernanceGovernanceMode='single'` vote is present in the epoch, require that a valid `GoverningNode` (council member) is also set, or reject the mode change if no valid governing node is established.
3. Consider requiring a supermajority (e.g., >2/3 of council) for mode-transition votes rather than accepting a single vote.

### Proof of Concept
1. Start a chain in `none` governance mode with a council of ≥2 members (A and B).
2. In epoch N, have A propose block B1 carrying vote `GovernanceGovernanceMode='single'`.
3. In epoch N, have A propose block B2 carrying vote `GovernanceGoverningNode=A`.
4. Both blocks pass `VerifyHeader` → `VerifyVote` → `checkConsistency` without error.
5. At the epoch-N+1 boundary block, `getExpectedGovernance` emits both changes; `VerifyGov` accepts the governance header.
6. `PostInsertBlock` → `HandleGov` → `AddGov` persists the new param set.
7. Assert `GetParamSet(epoch+1).GovernanceMode == "single"` and `GetParamSet(epoch+1).GoverningNode == A`.
8. Have B attempt to submit any vote in epoch N+1; assert it is rejected with `ErrVotePermissionDenied`.
9. Have A submit `RewardMintingAmount=<inflated value>`; assert it is accepted and applied.

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}
