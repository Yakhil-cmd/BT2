**Analysis:** The premise that `TransferProof` lacks freshness binding to `old_balance` is incorrect. In `confidential_transfer`, the sender's `old_balance` used in the zero-knowledge statement is read fresh from current on-chain state at execution time — not taken from the submitted proof/calldata — and is fed into `assert_valid_transfer_proof`, which builds the sigma-protocol statement (`sigma_protocol_transfer::new_transfer_statement`) using that live `old_balance`. [1](#0-0) 

Because the `TransferProof`'s $\Sigma$-protocol commitment/response is cryptographically bound (via the homomorphism check in `sigma_protocol_transfer`) to this specific `old_balance` and the discrete-log secret key `dk`, replaying the exact same proof bytes after the sender's `available_balance` has changed (i.e., after the first successful transfer updated `sender_ca_store.available_balance`) means the freshly-read `compressed_old_balance` at the second submission will no longer match what the proof was originally constructed for. [2](#0-1) 

The homomorphism relation explicitly ties `\old{P}, \old{R}` (old balance components) into the witness/statement check, so a proof valid for one `old_balance` will fail verification (`session.assert_verifies`) against a different, updated `old_balance` — this is precisely the state-binding mechanism that prevents replay, functioning in place of an explicit nonce. [3](#0-2) 

Additionally, `confidential_transfer_raw` performs no separate admission-layer validation of its own — it purely deserializes bytes and forwards to `confidential_transfer`, which is a `public(friend)` function not directly reachable by unprivileged callers except through this raw entry point, and all replay-resistance is enforced at the Move proof-verification layer (`assert_valid_transfer_proof`), not at transaction admission (mempool/VM validator). [4](#0-3) 

This is a Move-application-layer cryptographic protocol concern, not a transaction-admission-boundary defect (sender/signer/sequence/chain-id/expiry/gas binding, authenticator parsing, or fee-payer confusion), so it falls outside the required admission-impact gate regardless of the freshness analysis above.
