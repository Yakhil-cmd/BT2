### Title
`NonTransfer` proxy falsely declares itself a superset of `SudoBalances`/`Auction` in the live Westend and Rococo relay-chain runtimes, letting an ordinary proxy delegate self-escalate to Sudo/root-adjacent calls - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`pallet_proxy::do_proxy` authorizes an `add_proxy`/`remove_proxy` call made *through* an existing proxy purely by consulting `ProxyType::is_superset`, not `ProxyType::filter`, of that call's target proxy type [1](#0-0) . In the Westend and Rococo relay-chain runtimes, `ProxyType::NonTransfer::is_superset` unconditionally returns `true` for every other proxy type [2](#0-1) [3](#0-2) , while `NonTransfer`'s own `filter` explicitly denies the Sudo pallet and part of the Registrar pallet that `SudoBalances`/`Auction` admit [4](#0-3) . This is the exact same class of bug that was already found and fixed for `asset-hub-westend`'s `NonTransfer`/`Governance` pair in [5](#0-4) , but the fix was never propagated to the relay-chain runtimes, which still ship the unconditional `(ProxyType::NonTransfer, _) => true` pattern.

### Finding Description
`pallet_proxy::proxy` dispatches the wrapped call with an added filter closure that intercepts nested `add_proxy`/`remove_proxy` calls and rejects them unless `def.proxy_type.is_superset(proxy_type)` holds: [6](#0-5) 

For any other call, only `def.proxy_type.filter(c)` is consulted. This means the *only* gate that stops a proxy delegate from escalating itself to a proxy type whose filter is wider than its own is `is_superset` — `filter` is not re-checked when `add_proxy`/`remove_proxy` is the target call.

In `polkadot/runtime/westend/src/lib.rs`, `ProxyType::NonTransfer` denies `RuntimeCall::Sudo` entirely (comment: "Specifically omitting Sudo pallet") and admits only `Registrar::register/deregister/reserve` (comment: "Specifically omitting Registrar `swap`") [7](#0-6) . Yet:
- `ProxyType::SudoBalances` admits `Sudo::sudo{ call: Balances(..) }` [8](#0-7) .
- `ProxyType::Auction` admits the *entire* `Registrar` call family (`RuntimeCall::Registrar(..)`, i.e. including `swap`) [9](#0-8) .
- `is_superset` nonetheless returns `true` for `(NonTransfer, SudoBalances)` and `(NonTransfer, Auction)` via the catch-all arm `(ProxyType::NonTransfer, _) => true` [2](#0-1) .

The identical unconditional `(ProxyType::NonTransfer, _) => true` pattern, together with an `Auction` filter that admits the full `Registrar` family while `NonTransfer` explicitly omits `Registrar::swap`, is present in `polkadot/runtime/rococo/src/lib.rs` [10](#0-9) ; Rococo additionally admits `OnDemandOrdering` (`RuntimeCall::OnDemandAssignmentProvider`) as a false subset even though `NonTransfer`'s filter never lists that call family [11](#0-10) .

This is precisely the bug class Parity itself documented and fixed for `asset-hub-westend`: the comment in the fixed code states "`Governance` is deliberately *not* listed here. `NonTransfer` denies the ... calls that `Governance` admits, so it is not a superset of it. Claiming otherwise would let a `NonTransfer` proxy grant itself a `Governance` proxy and widen its own permissions" [12](#0-11) , confirmed by the regression test referencing GitHub issue 12724 [13](#0-12)  and PR 12769 [5](#0-4) . That fix only patched `asset-hub-westend`; it was never mirrored into `polkadot/runtime/westend/src/lib.rs` or `polkadot/runtime/rococo/src/lib.rs`, both of which are live, Parity-operated testnet runtimes.

Attack path (all steps use ordinary, permitted, signed extrinsics — no privileged role, no governance, no stolen keys):
1. Some account `real` grants an ordinary `NonTransfer` proxy to delegate `D` via the public, fee-paying `Proxy::add_proxy(D, ProxyType::NonTransfer, 0)` extrinsic [14](#0-13) . Granting `NonTransfer` is a routine, low-trust delegation precisely because its filter is documented to deny Balances/Sudo.
2. `D` calls `Proxy::proxy(real, None, Box::new(Proxy::add_proxy{ delegate: D, proxy_type: SudoBalances, delay: 0 }))`. Inside `do_proxy`, the nested filter checks `def.proxy_type.is_superset(&SudoBalances)`, which wrongly returns `true`, so the nested `add_proxy` is *not* blocked by the filter and is dispatched with `real`'s origin, registering `D` as a `SudoBalances` proxy of `real`.
3. `D` then calls `Proxy::proxy(real, Some(SudoBalances), Box::new(Sudo::sudo{ call: Balances::force_set_balance{ who: D, new_free: MAX } }))`. This time `def.proxy_type` is `SudoBalances`, whose `filter` admits `Sudo::sudo{ call: Balances(..) }`, so the call is dispatched as `Signed(real)`.
4. Inside `pallet_sudo::sudo`, the call is only actually elevated to `Root` if `real == Sudo::key()`. Reachability of step 4's full impact therefore requires `real` to be the account holding the runtime's Sudo key; independent of that, steps 1–3 demonstrate that `D` — merely because it once received a `NonTransfer` proxy — can silently self-grant a `SudoBalances` (or `Auction`) proxy, an escalation the `NonTransfer` filter was explicitly written to prevent.

The `Auction`/`Registrar::swap` variant of the same bug requires no such precondition on `real`: any account that has been granted `NonTransfer` by `real` can self-escalate to an `Auction` proxy and then invoke `Registrar::swap` on `real`'s behalf, even though `NonTransfer`'s own filter comment explicitly says it omits `Registrar::swap`.

### Impact Explanation
- Any account that received a routine, documented-as-limited `NonTransfer` proxy grant can silently widen its own permissions to `SudoBalances` or `Auction` without the delegator's consent, purely because `is_superset` is wrong, not because `filter` was.
- Where the delegator is the account holding the Sudo key (a realistic operational pattern on Parity-operated testnets, where the Sudo key account may delegate day-to-day `NonTransfer` automation to a bot/operator), this becomes full unauthorized `Root`-level dispatch of arbitrary `Balances` calls (`force_set_balance`, `force_transfer`, etc.) — unbacked issuance / arbitrary balance manipulation.
- Independent of the Sudo precondition, every `NonTransfer` delegate on Westend and Rococo can escalate to `Auction` and invoke `Registrar::swap`, which the runtime authors deliberately excluded from `NonTransfer` (Rococo additionally exposes `OnDemandAssignmentProvider`). This is an integrity break of the documented proxy-permission boundary on a live chain, matching this report's requested class ("unauthorized dispatch").

### Likelihood Explanation
- Reaching the bug requires only two ordinary signed extrinsics (`add_proxy`, then `proxy`) that any account can submit against a chain that already has this `ProxyType`/`InstanceFilter`/`is_superset` implementation compiled in — no governance, no validator/collator collusion, no stolen keys.
- The only external precondition is that some account previously delegated an ordinary `NonTransfer` proxy to the attacker, which is a normal, expected, low-trust delegation pattern (that is exactly why `NonTransfer` denies Balances/Sudo by design).
- The full Sudo-key impact additionally requires the delegator to be the Sudo key holder; the `Auction`/`Registrar::swap` and Rococo `OnDemandOrdering` escalations have no such extra precondition and are reachable by any `NonTransfer` delegate.
- Parity has already fixed the identical `is_superset` pattern once (asset-hub-westend, PR 12769/issue 12724), showing this class of defect is a real, previously-exploited-in-principle design flaw in this proxy configuration, not a hypothetical one — it was simply not propagated to the relay-chain runtimes.

### Recommendation
Mirror the `asset-hub-westend` fix into `polkadot/runtime/westend/src/lib.rs` and `polkadot/runtime/rococo/src/lib.rs`: remove the unconditional `(ProxyType::NonTransfer, _) => true` arm and replace it with an explicit, filter-consistent list of subsets (as `asset-hub-westend` now does), excluding `SudoBalances`, `Auction` (and, on Rococo, `OnDemandOrdering`) unless `NonTransfer`'s `filter` is changed to actually admit every call those types admit. Add a lattice-consistency regression test analogous to `proxy_type_superset_relation_matches_call_filters` / `non_transfer_proxy_is_not_a_superset_of_governance` in `asset-hub-westend`'s test suite to both relay-chain runtimes so this class of bug cannot silently reappear.

### Proof of Concept
No live network execution was performed (out of scope per policy). The following is the minimal Rust/FRAME assertion that reproduces the flaw purely from the runtime's own `InstanceFilter`/`is_superset` implementation, in the style of the existing regression test in `asset-hub-westend`:

```rust
// Reproduces the same class of bug as
// cumulus/.../asset-hub-westend/tests/tests.rs::non_transfer_proxy_is_not_a_superset_of_governance,
// but for the still-unpatched Westend/Rococo relay-chain runtimes.
use westend_runtime::ProxyType;
use frame_support::traits::InstanceFilter;

let sudo_balances_call = RuntimeCall::Sudo(pallet_sudo::Call::sudo {
    call: Box::new(RuntimeCall::Balances(pallet_balances::Call::force_set_balance {
        who: ATTACKER.into(),
        new_free: u128::MAX,
    })),
});
let registrar_swap_call = RuntimeCall::Registrar(paras_registrar::Call::swap {
    id: 0.into(),
    other: 1.into(),
});

// `SudoBalances` and `Auction` admit calls that `NonTransfer` explicitly denies:
assert!(ProxyType::SudoBalances.filter(&sudo_balances_call));
assert!(!ProxyType::NonTransfer.filter(&sudo_balances_call));
assert!(ProxyType::Auction.filter(&registrar_swap_call));
assert!(!ProxyType::NonTransfer.filter(&registrar_swap_call));

// Yet `is_superset` wrongly claims NonTransfer ⊇ SudoBalances and NonTransfer ⊇ Auction,
// which is exactly the gate `pallet_proxy::do_proxy` uses to authorize a nested
// `add_proxy`/`remove_proxy` call made through an existing proxy relationship.
assert!(ProxyType::NonTransfer.is_superset(&ProxyType::SudoBalances)); // should be false
assert!(ProxyType::NonTransfer.is_superset(&ProxyType::Auction));      // should be false
```

Both assertions on the last two lines currently pass in `polkadot/runtime/westend/src/lib.rs`'s and `polkadot/runtime/rococo/src/lib.rs`'s `is_superset` implementations, confirming the lattice violation; per the already-merged `asset-hub-westend` fix and its accompanying regression test, both should return `false`. Full on-chain reproduction (attacker calling `Proxy::add_proxy`/`Proxy::proxy` to actually register the escalated `SudoBalances`/`Auction` proxy and dispatch the nested call) was not executed against a running node, since this report is limited to static code analysis of the reference runtimes; a background engineer with node/test-harness access should add the equivalent `ExtBuilder`-based integration test (mirroring `pure_proxy_stash_can_delegate_to_staking_operator` in `asset-hub-westend`'s test suite) to confirm end-to-end dispatch success before landing the fix.

		use frame::traits::{InstanceFilter as _, OriginTrait as _};

				},

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
