### Title
Webhook signature verification is bound to `repository.owner.login`, but handlers act on the unverified `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's `webhook_secret` to use for HMAC verification based solely on `params.dig('repository', 'owner', 'login')` (with an `organization.login` fallback) [2](#0-1) . Once the signature is accepted, the entire raw payload — including `repository.full_name`, which is never itself checked against `repository.owner.login` — is handed to the event handlers [3](#0-2) . Handlers such as `Shipit::Webhooks::Handlers::Handler#repository_name` and `PushHandler#process` resolve the target `Stack`/`Repository` purely from `payload.dig('repository', 'full_name')` [4](#0-3) [5](#0-4) .

### Finding Description
Shipit can be configured with several GitHub organizations, each carrying its own `webhook_secret` under `secrets.github.<org>` [1](#0-0) . When a webhook arrives, `verify_signature` computes `repository_owner` from the payload and calls `Shipit.github(organization: repository_owner)` to fetch **that organization's** secret and verify the HMAC over the raw body [6](#0-5) .

The equality this is supposed to guarantee is:
`organization whose secret signed the payload == organization that owns the repository the payload will mutate`

However, nothing enforces that `repository.owner.login` (used to pick the verifying secret) matches `repository.full_name` (used everywhere downstream to resolve the target `Repository`/`Stack`). An org administrator who legitimately controls one configured GitHub organization (and therefore possesses that org's real `webhook_secret`, since GitHub signs whatever body the org's installation sends) can produce a validly-signed request whose `repository.full_name` names a repository belonging to a **different** configured organization. Because the HMAC only proves *"this byte sequence was signed by org A's secret"*, not *"the repository referenced inside belongs to org A"*, the verified signature never actually covers the binding between `repository.owner.login` and `repository.full_name`.

### Impact Explanation
If exploited, this lets an attacker who owns/administers one onboarded GitHub organization (an unprivileged actor with respect to the *victim* organization/repository) submit signed `push`, `status`, or `check_suite` events that reference a victim's `repository.full_name`. `PushHandler` would then trigger `stack.sync_github(expected_head_sha: ...)` for the victim stack [5](#0-4) , and `status`/`check_suite` handlers would write commit statuses used to gate deploys — i.e., cross-organization/cross-repository writes to stack state that the attacker has no authorization over. This matches the "cross-repository writes" / "unauthorized deploy" impact tier.

### Likelihood Explanation
Exploitability strictly requires the attacker to be a legitimate webhook sender for *some* configured organization within the same Shipit instance (i.e., they must control one of the GitHub orgs/installations Shipit trusts). In a single-organization Shipit deployment (the common case, where `github_default_organization` returns `nil` and the top-level `secrets.github` schema is used) [7](#0-6) , this is not exploitable since there is only one secret and one implied owner. It only becomes a real cross-tenant issue on multi-organization deployments, which the code explicitly supports via `github_organizations`/`github_app_config` [8](#0-7) . This narrows likelihood, but it is a genuine, code-supported configuration, not a hypothetical.

### Recommendation
After verifying the HMAC signature, cross-check that `repository.owner.login` (or `organization.login`) equals the owner segment of `repository.full_name` before dispatching to any handler, and reject the request (422) on mismatch.

### Proof of Concept
1. Configure Shipit with two organizations, `org-a` and `org-b`, each with distinct `webhook_secret` values, both hosting stacks under `Shipit`.
2. As the operator of `org-a`'s GitHub App/webhook, construct a payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": {"login": "org-a"},
    "full_name": "org-b/victim-repo"
  }
}
```
3. Sign this payload with `org-a`'s real `webhook_secret` (which the attacker legitimately possesses) and POST it to `/webhooks` with `X-Github-Event: push` and the correct `X-Hub-Signature`.
4. `verify_signature` calls `Shipit.github(organization: 'org-a')`, verifies successfully against `org-a`'s secret [9](#0-8) .
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name('org-b/victim-repo')` and enqueues `sync_github` for `org-b`'s stack — a repository the attacker does not control [4](#0-3) [5](#0-4) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)

        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
