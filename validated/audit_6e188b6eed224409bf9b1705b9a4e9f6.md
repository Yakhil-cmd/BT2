### Title
Permanent market freeze from `i128` overflow when scaled share value exceeds `i128::MAX` during accrual - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
The Tapioca report describes a share→amount conversion (`share * totalAmount`) that overflows before its division, freezing user funds. XOXNO Lending has the same bug class in its RAY-index share model, in a worse position: `scaled_to_original` (`scaled * index / RAY`) runs inside `accrue_step`, which every state-mutating pool operation calls first. When total borrowed or supplied value crosses `i128::MAX` (~1.7e38 RAY units), the conversion panics with `MathOverflow` and every subsequent verb — `withdraw`, `repay`, `borrow`, `liquidate`, `clean_bad_debt`, `update_indexes`, `claim_revenue`, `recapitalize` — reverts on that market permanently.

### Finding Description
Positions are stored as RAY-scaled shares; value = `shares × index / RAY`. `accrue_step` computes `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` on every accrual chunk [1](#0-0) . `scaled_to_original` is `scaled.mul(env, index)`, i.e. `mul_div` [2](#0-1) . The `I256` widened path protects only the *intermediate product*; the final `to_i128` panics with `GenericError::MathOverflow` when the quotient itself does not fit `i128` [3](#0-2) .

Unlike Tapioca's case, the fix applied here (wide intermediate) removes the *premature* overflow, but the result value `supplied × index` can still legitimately exceed `i128::MAX`: index ceilings are `MAX_BORROW_INDEX_RAY = MAX_SUPPLY_INDEX_RAY = 1e36` (1000×RAY) [4](#0-3) , and cap validation only bounds the *input* cap (`i128::MAX / 10^(27−d)` token units), not `shares × index`. So for a high-supply token the total RAY value outgrows `i128` at an index far below the cap. The repo's own test demonstrates this: a 1-billion-whole-token 18-decimal market at ~98% utilization hits `MathOverflow` inside `scaled_to_original` in a few years on the steep curve segment, "the index cap never engages," and `withdraw`/`repay` revert with the same panic because every verb accrues first [5](#0-4) .

### Impact Explanation
Permanent freezing of funds for the entire market: once `supplied × supply_index` or `borrowed × borrow_index` exceeds `i128::MAX`, `accrue_step` panics before any state change. All suppliers' deposits, borrowers' collateral unlock paths, liquidations, bad-debt cleanup, and revenue claims on that (hub, token) book revert with `MathOverflow` forever — there is no accrual-bypassing escape hatch, and the indexes can never decrease again, so the condition is irreversible. Severity: High.

### Likelihood Explanation
An unprivileged actor needs a market where total supply (shares) times the index exceeds ~1.7e38 RAY. Spoke caps constrain each spoke, but `max_cap_for_decimals` admits caps up to `i128::MAX / 10^(27−d)` and the hub aggregates spokes; for an 18-decimal asset the cliff is ~1.7e11 whole tokens of value scaled by index growth — reachable for high-supply tokens after sustained borrowing pushes utilization into a steep slope segment. No privileged action is required to trigger the overflow; `update_indexes` itself is permissionless, so once the condition is latent any user can freeze the market.

### Recommendation
Bound the market so the RAY value can never reach `i128::MAX` before the index cap: e.g. clamp `borrowed`/`supplied` totals or enforce a value ceiling `total_shares × index ≤ i128::MAX − headroom` at supply/borrow entry (a `require_value_within_ray_domain` validation alongside `require_cap_within_asset_domain`). Alternatively, make `accrue_step` use saturating/division-first valuation (compute value as `index/RAY × shares` with a cap, or saturate utilization inputs) so accrual degrades gracefully instead of panicking, keeping exits and liquidation functional.

### Proof of Concept
Reproduced by the in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [6](#0-5) :

1. List an 18-decimal market (`BIG18`), set spoke caps to `max_cap_for_decimals(18)`, supply `1e9` whole tokens; supply collateral on `COL` and borrow 98% of the supply.
2. Advance time at sustained ~98% utilization; call `update_indexes` each year.
3. Once `borrowed × borrow_index / RAY > i128::MAX` (index ≈ 170×, far below the 1000× cap), `scaled_to_original` inside `accrue_step` panics `MathOverflow`.
4. `withdraw(BOB, "BIG18", 1)` and `repay(ALICE, "BIG18", …)` revert with the same `MathOverflow`; `liquidate`, `clean_bad_debt`, `claim_revenue`, and `recapitalize` fail identically since all accrue first. The market is permanently frozen.

/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
