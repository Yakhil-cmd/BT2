### Title
Webhook signature verified against attacker-chosen organization while handlers act on an unrelated repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
Shipit supports hosting multiple GitHub organizations behind one instance, each with its own GitHub App and `webhook_secret` [1](#0-0) . The inbound webhook controller selects which organization's secret to use for HMAC verification from an **attacker-controlled field in the unauthenticated payload**, but the handlers that actually mutate state key off a **different, independently-controlled field** in that same payload. The two fields are never checked for consistency, breaking the intended binding "organization that authenticated the request == repository being written to."

### Finding Description
`WebhooksController#verify_signature` picks the GitHub App/secret to verify against using: [2](#0-1) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```

`repository_owner` is read straight from the untrusted JSON body, before any signature has been validated. It only determines *which* per-organization secret (`Shipit.github(organization:)` / `github_app_config`, see `lib/shipit.rb:170-200`) is used to verify the signature.

Once the signature check passes, `create` dispatches the raw payload to handlers:

```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
```

All handlers resolve the target `Repository`/`Stack` from a **separate** field, `repository.full_name`, e.g. `Handler#repository_name` [3](#0-2) , and `PushHandler#process` [4](#0-3) , plus the same pattern in every `pull_request/*` handler (`Repository.from_github_repo_name(params.repository.full_name)`).

There is no code anywhere that asserts `repository.full_name`'s owner equals `repository_owner`/`organization.login` used in `verify_signature`. In a multi-organization deployment (an explicitly documented and tested configuration, e.g. `test/dummy/config/secrets_double_github_app.yml`, `test/unit/shipit_test.rb:11-22`), an operator who legitimately administers their own installed GitHub App for `OrgOne` knows `OrgOne`'s `webhook_secret` (or can simply replay/forge a signature computed with it, since they control that org's webhook configuration). They can then submit a payload where:
- `repository.owner.login` / `organization.login` = `"OrgOne"` (used only to select the secret for HMAC verification — passes),
- `repository.full_name` = `"OrgTwo/victim-repo"` (used by the handler to find and act on the target Stack).

The equality that should hold is:
`organization whose secret validated the request == organization that owns the repository the handler mutates`

but the code enforces:
`repository_owner (attacker-chosen) → secret lookup`, independent of
`repository.full_name (attacker-chosen) → mutated repository`

### Impact Explanation
This lets a party who legitimately controls one tenant/organization on a shared Shipit instance forge signed webhooks that are processed as if they came from GitHub for a *different* organization's repository. Depending on which event type is sent, this can:
- Force `GithubSyncJob` runs and status/commit events for a victim repository they don't have write access to, via `PushHandler`, `StatusHandler`, and the various `pull_request/*Handler`s, all of which key exclusively off `repository.full_name`.
- Manipulate review-stack/merge-queue state (archive/unarchive review stacks, alter labels-driven provisioning decisions) for repositories belonging to other tenants.

This is a cross-tenant/cross-repository write that the per-organization webhook secret design was specifically meant to prevent, matching the "cross-repository writes" / "unauthorized deploy, rollback, or merge" high/critical impact bucket in the given rules.

### Likelihood Explanation
High for any Shipit instance configured with **multiple GitHub organizations** (the multi-app mode is a first-class, documented feature). Anyone who is an admin of one of the configured organizations' GitHub Apps (i.e., "unprivileged" with respect to every *other* tenant on the same Shipit instance) can trivially craft the cross-repository payload — no GitHub write access to the victim repo, no Shipit session, and no privileged Shipit account are required.

### Recommendation
After a successful signature verification, explicitly bind the verified organization to every repository referenced in the payload before dispatching to handlers — e.g., verify that `repository.full_name.split('/').first` (and any other repository references embedded in the payload) case-insensitively matches `repository_owner`, and reject (422) otherwise. This restores the "authenticated organization == written repository" invariant instead of trusting two independently attacker-controlled fields to agree.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgOne` and `OrgTwo`, each with its own GitHub App/`webhook_secret` (supported per `docs/setup.md` "Using Multiple Github Applications").
2. As the legitimate administrator of `OrgOne`'s GitHub App, compute `X-Hub-Signature` for a `push` payload using `OrgOne`'s `webhook_secret`, `POST` it to `/webhooks` with header `X-Github-Event: push`, but set the JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "full_name": "OrgTwo/victim-repo", "owner": { "login": "OrgOne" } }
}
```
3. `verify_signature` computes `repository_owner = "OrgOne"`, fetches `OrgOne`'s app/secret, and the signature validates successfully.
4. `PushHandler#process` looks up stacks via `Repository.from_github_repo_name("OrgTwo/victim-repo")` and calls `stack.sync_github(expected_head_sha: ...)` — mutating a stack belonging to `OrgTwo`, an organization the attacker never authenticated against.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
