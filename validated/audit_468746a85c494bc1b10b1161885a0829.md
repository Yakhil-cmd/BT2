### Title
Stack scoping bypass in `Api::CCMenuController` lets a stack-scoped ApiClient token read state of any stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Api::BaseController` enforces that an `ApiClient` whose token is scoped to a specific stack (`current_api_client.stack_id?`) can only resolve `stack` from within its own stack set. `Api::CCMenuController` overrides `stack` and resolves it directly from `Stack.from_param!(params[:stack_id])`, dropping the `stacks` scoping entirely, while still relying on the generic `require_permission :read, :stack` check that only validates the *permission name*, not *which* stack it applies to.

### Finding Description
`Api::BaseController` defines the trust binding "the stack a token authorizes == the stack it touches": [1](#0-0) 
`stacks` restricts the queryable set to `current_api_client.stack_id` when the client is scoped, and `stack` resolves through that restricted set, so a stack-scoped token cannot address a stack outside its scope.

`Api::CCMenuController` inherits `require_permission :read, :stack`, which only calls `current_api_client.check_permissions!(:read, :stack)` — i.e. it verifies the client *has the `read:stack` permission string*, not that it is authorized for the *specific* `stack_id` in the request: [2](#0-1) 

But `CCMenuController` overrides the `stack` resolver to bypass the scoping entirely: [3](#0-2) 
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```
instead of the inherited, scope-respecting:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

This is the direct analog of the C4 finding's root cause: a check that verifies the wrong thing (`error != NO_ERROR` instead of `error != amount`) creates a false sense that the correct binding was enforced, while the real object being acted upon (the actual stack) is never checked against what the credential authorizes. Here, `require_permission :read, :stack` gives the appearance that stack access is authorized, but the actual `stack` object used to render output is fetched unscoped, breaking the equality `stack_authorized_by_token == stack_touched_by_request`.

### Impact Explanation
Any holder of a `read:stack`-scoped `ApiClient` token created for one stack (e.g. via `CCMenuUrlController`, or a stack-restricted client created through `ApiClientsController`) can call `GET /api/stacks/:stack_id/ccmenu` with an arbitrary `stack_id` belonging to a different, unrelated stack and receive that other stack's deploy/build status (`CCMenuController#show` renders `stack.deploys_and_rollbacks.last`). This is an unauthenticated-scope read of a stack's task/deploy state outside of the credential's intended boundary — matching the "High: unauthenticated read of stack state, task streams or deploy output" impact category, since the token was only meant to authorize reads for one specific stack.

### Likelihood Explanation
Any actor who legitimately possesses (or otherwise obtains) a stack-scoped `read:stack` ApiClient token can immediately exploit this by changing the `stack_id` path segment on an otherwise normal `ccmenu` request — no privilege escalation, no additional secret, and no code execution is required. Because `CCMenuUrlController` actively hands out CCMenu URLs containing this same token pattern, tokens of this exact scoped shape are a first-class, expected artifact of the application, making the crossing of trust boundary highly likely in real deployments that rely on the per-stack CCMenu URL feature.

### Recommendation
Remove the `stack` override in `Api::CCMenuController` (or reimplement it using the scoped `stacks` resolver) so that stack-scoped ApiClient tokens cannot resolve stacks outside their authorized `stack_id`:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

### Proof of Concept
1. As an authenticated user, create a CCMenu URL for Stack A via `CCMenuUrlController#fetch`, obtaining a token scoped only by `permissions: %w[read:stack]` (note: today this helper does not even set `stack_id`, but the same `stack` override applies equally to any `ApiClient` that *does* have `stack_id` set, e.g. one created and manually bound to a stack).
2. Using that token, issue `GET /api/stacks/<stack_B_id>/ccmenu?token=<token>` where Stack B is a different stack the token was never meant to authorize.
3. `authenticate_api_client` in `Api::CCMenuController` succeeds because the token is valid and has `read:stack` permission.
4. `require_permission :read, :stack` passes because it only checks the permission string, not the target stack.
5. `stack` resolves via `Stack.from_param!(params[:stack_id])` directly against the global `Stack` table, ignoring `current_api_client.stack_id`, returning Stack B's data in the XML response — an unauthorized cross-stack information disclosure. [4](#0-3) [5](#0-4) [6](#0-5)

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end
end

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
