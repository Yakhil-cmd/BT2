### Title
Unsynchronized global unit-cache mutation in AA dry-run execution allows stale/forgotten unit references to leak into live consensus state - ([File: aa_composer.js])

### Summary
`dryRunPrimaryAATrigger()` in `aa_composer.js` executes a full AA trigger (including all secondary triggers) against the shared, process-wide, in-memory caches owned by `storage.js` (`assocUnstableUnits`, `assocBestChildren`, `assocCachedUnits`, etc.), then rolls back the DB transaction and manually "un-does" the cache mutations with `revertResponsesInCaches()` → `storage.forgetUnit()`. Unlike the real trigger-execution and unit-writing paths, this function never acquires the `['write']` (or `['aa_triggers']`) mutex that normally serializes all mutation of these caches. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The reported Chrome bug class is a use-after-free: an object is released/invalidated while another code path still holds and dereferences a reference to it, corrupting shared state. `ocore` has an analogous pattern with unit objects instead of C++ heap objects:

1. `dryRunPrimaryAATrigger()` inserts fake outputs into a genesis-based MC unit and runs `handleTrigger()` for a full (possibly multi-hop, secondary-trigger) AA chain, exactly as the real trigger-execution path does. This causes real unit objects to be created and inserted into the *same global* `storage.assocUnstableUnits` / `storage.assocBestChildren` caches used by the live node (via the normal `validateAndSaveUnit` → `saveJoint`/`writer.js` code path), because these caches are plain module-level objects shared by every code path in the process, not scoped to the dry-run's DB connection or savepoint. [4](#0-3) 

2. When the dry run finishes, `onDone` calls `revertResponsesInCaches(arrResponses)`, which walks the produced response units, looks up `storage.assocUnstableUnits[first_unit]` for `parent_units`, and calls `storage.forgetUnit()` on every response unit — deleting them from `assocKnownUnits`, `assocCachedUnits`, `assocUnstableUnits`, `assocBestChildren`, etc. — then "fixes" `is_free` on the parents. [2](#0-1) [3](#0-2) 

3. Unlike the real trigger path (`handleAATriggers`/`handlePrimaryAATrigger`, guarded by `mutex.lock(['aa_triggers'])`, and unit writing in `writer.js`, guarded by `mutex.lock(['write'])`), `dryRunPrimaryAATrigger()` takes no lock at all before mutating these same global caches. Because the caches are shared and un-namespaced by transaction, a real, concurrently-executing trigger or unit write can observe (cache) a reference to the dry run's transient unit object — e.g., through `assocBestChildren[parent_unit]` entries used by `pickParents`/level/witnessed-level computations, or through `fixIsFreeAfterForgettingUnit`'s scan of `assocUnstableUnits` for children of a given parent — while it is still "live," and then have that reference invalidated out from under it once the dry run calls `forgetUnit()` on rollback. Because `fixIsFreeAfterForgettingUnit()` blindly sets `is_free=1` on any parent that currently appears to have no children left in `assocUnstableUnits`, if the dry run's transient units are the only entries that made a real unit's parent look "non-free" at that instant, forgetting them can incorrectly mark real in-flight parents as free/eligible for archival or reused as the DAG tip while a genuine child unit still exists on disk but is not (yet) reflected consistently in the shared cache — a form of node-local cache corruption/disagreement about DAG state. [5](#0-4) 

This mirrors the CVE-2023-0474 root cause at a design level: an operation (`revertResponsesInCaches`/`forgetUnit`, analogous to GuestView object teardown) frees/invalidates shared state that another concurrently running consumer (a real AA trigger or unit write, analogous to the "Chrome web app" reachable through the untrusted extension/GuestView) may still be relying on, because there is no ownership/lock discipline between the dry-run "throwaway" execution and the live consensus-critical caches.

### Impact Explanation
If exploitable, this can cause a node's in-memory view of `is_free`, best-children, and cached unit props to diverge from the true DAG/DB state. Because `is_free`, `assocBestChildren`, and `assocUnstableUnits` directly drive best-parent selection, level/witnessed-level computation, and MC advancement, corruption here can lead to the node computing different parents/levels than peers, i.e. node disagreement on unit validity/stability — one of the explicitly accepted impact categories. It could also cause legitimate unstable units to be prematurely treated as free/prunable, undermining the node's ability to keep confirming new units correctly on that node.

### Likelihood Explanation
Any unprivileged party able to trigger a dry run of an AA (a wallet or `AA trigger sender` requesting a hypothetical/preview execution, surfaced via `network.js`, which calls `dryRunPrimaryAATrigger`) can repeatedly and cheaply exercise this code path while the node is simultaneously processing real stabilizing MCIs / running real AA triggers — a condition that occurs naturally and continuously on a busy node, so the race window is real. However, I was not able to fully trace and confirm the exact call site and preconditions in `network.js` (only 3 textual matches were found for `dryRunPrimaryAATrigger`, and I ran out of tool budget before reading that context in full), nor could I construct a concrete minimal-timing proof that a real trigger's cache read interleaves with the dry run's `forgetUnit()` call in practice. This should be treated as a plausible but not fully proven race — confirming it requires reading the `network.js` call site and reproducing the interleaving.

### Recommendation
- Have `dryRunPrimaryAATrigger()` acquire the same `['write']` mutex (or a dedicated dry-run mutex that excludes `['write']`/`['aa_triggers']`) before mutating any process-global storage caches, and hold it until `revertResponsesInCaches()`/rollback has fully completed.
- Alternatively, refactor dry-run execution to operate on a cache overlay/snapshot instead of the live `storage.js` module-level caches, so no forget/cleanup step is needed and no real trigger can observe transient objects.
- Audit `fixIsFreeAfterForgettingUnit()` and `forgetUnit()` for safety when invoked concurrently with cache reads from unrelated trigger executions, and add assertions/consistency checks (already partially present via `readPropsOfUnits`'s `bFaster` comparison logic) around dry-run cleanup.

### Proof of Concept
Not fully constructed. A conceptual reproduction would require: (1) a client requesting `dryRunPrimaryAATrigger` for an AA chain with several secondary triggers (to maximize the window during which multiple transient unit objects live in `assocUnstableUnits`/`assocBestChildren`), executed concurrently with (2) real stabilization of an MCI that runs `handleAATriggers`/`writer.js` unit saving for units sharing a parent with the dry run's synthetic chain, then observing whether `is_free`/`assocBestChildren` state diverges from the true DB-persisted DAG after the dry run's `revertResponsesInCaches()` completes. I was unable to build and run this PoC in the time available and cannot confirm actual exploitability without further investigation (e.g., a Devin session with the full test/dev environment).

	// remove the rolled back units from caches and correct is_free of their parents if necessary
	console.log('will revert responses ' + JSON.stringify(arrResponses, null, '\t'));
	var arrResponseUnits = [];
	arrResponses.forEach(function (objAAResponse) {
		if (objAAResponse.response_unit)
			arrResponseUnits.push(objAAResponse.response_unit);
	});
	console.log('will revert response units ' + arrResponseUnits.join(', '));
	if (arrResponseUnits.length > 0) {
		var first_unit = arrResponseUnits[0];
		var objFirstUnit = storage.assocUnstableUnits[first_unit];
		var parent_units = objFirstUnit.parent_units;
		arrResponseUnits.forEach(storage.forgetUnit);
		storage.fixIsFreeAfterForgettingUnit(parent_units);
	}
}

// parent_units are parent units of the forgotten unit
function fixIsFreeAfterForgettingUnit(parent_units) {
	parent_units.forEach(function(parent_unit){
		if (!assocUnstableUnits[parent_unit]) // the parent is already stable
			return;
		var bHasChildren = false;
		for (var unit in assocUnstableUnits){
			var o = assocUnstableUnits[unit];
			if (o.parent_units.indexOf(parent_unit) >= 0)
				bHasChildren = true;
		}
		if (!bHasChildren)
			assocUnstableUnits[parent_unit].is_free = 1;
	});
}
