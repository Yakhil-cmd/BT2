## Analysis

The core bug pattern in the Paraspace report is: **a security-critical decision samples a piece of externally-mutable state at a single point in time, and an attacker can transiently distort that state, extract value/trigger an action, then revert the state to its original value before the sample is taken — leaving no trace for the control that only looks at "current vs. baseline."**

The closest reachable analog in `claude-code--018` is not financial, but structural: the `security-guidance` plugin's Stop-hook deep LLM review is *also* a single-point-in-time diff sample, and it is bypassable the same way.

### Title
Stop-hook security review is defeated by writing-then-reverting file content before the diff is sampled - (File: `plugins/security-guidance/hooks/diffstate.py`, `plugins/security-guidance/hooks/security_reminder_hook.py`)

### Summary
The `security-guidance` plugin's deepest defense — the Stop-hook LLM vulnerability scan — decides whether to review a turn purely by diffing the *current* working-tree state against a `git stash create` baseline captured at `UserPromptSubmit`. If a file is edited to introduce something malicious and then edited again to restore its original content before the Stop hook fires, the computed review set is empty and the entire LLM security review is skipped, exactly as a flash-loan price is restored after the profitable action so the "oracle" (spot state) shows nothing wrong when sampled.

### Finding Description
`compute_v2_review_set` derives the review set as the intersection of "files dirty vs. current HEAD" and "files whose content differs from the pre-turn stash baseline" [1](#0-0) . This is computed from live `git status`/`git diff --name-only` output at Stop time [2](#0-1) . If `review_set` is empty, `handle_stop_hook` treats the turn as having "no changes since baseline" and skips the LLM review entirely (`_skip(6)`, `_skip(9)`) [3](#0-2) .

Nothing in this control accounts for *intermediate* states: a file can be written with attacker-controlled/injected content (e.g., a prompt-injection payload instructing Claude to add a backdoor, exfiltration snippet, or disabled check), a Bash command can consume/execute that content, and then the file can be edited back to its original text — all inside the same turn, before Stop fires. At sample time the working tree again equals the baseline, so `dirty_now`/`changed_since` are empty, `review_set` is empty, and the deep review is silently skipped, with only the fast regex-based `PostToolUse` pattern rules as a fallback [4](#0-3) . Those pattern rules are explicitly described as "fast regex checks" for known patterns (hardcoded secrets, SQLi, command injection, path traversal) — not a semantic analysis — so any malicious construct that doesn't match a fixed regex is never re-examined once the file is reverted.

This mirrors the oracle bug's structure precisely: the control (`getAssetPrice` / Stop-hook diff) trusts a spot read of manipulable state (pool reserves / working-tree vs. stash baseline) instead of a manipulation-resistant signal, letting an attacker act, then restore the read state to its pre-manipulation value before the control samples it.

### Impact Explanation
An attacker who can influence Claude's actions during a turn (prompt injection from a fetched web page, a malicious file/README, a compromised MCP tool result, or a malicious skill/plugin instruction) can direct Claude to write and execute harmful content and then have it reverted before the turn ends. This defeats the plugin's primary LLM-based vulnerability detector for that turn, so no `PROVENANCE_BANNER`/finding is ever surfaced to the user, and the session-level record (`previous_findings`) never captures that anything happened. The commit-review and push-sweep code paths are diff-of-committed-history based and are not affected the same way, but the Stop hook is documented as the plugin's catch-all "final review" [5](#0-4) , so its silent bypass removes the main safety net against exactly this class of attacker-influenced session.

### Likelihood Explanation
Reaching this requires only unprivileged capability already assumed reachable in this environment: getting Claude to read attacker-influenced content (web fetch, file, tool output) during a normal session, which is the standard prompt-injection threat model for agentic coding tools. No credentials, no admin/operator access, and no break of cryptography are needed — only a two-step edit/revert pattern within one turn, which is a common and unremarkable coding action (e.g., "try X, then undo it").

### Recommendation
Do not gate the deep review purely on "does the final tree state differ from baseline." Track and review every file that was the target of a `Write`/`Edit`/`MultiEdit`/`Bash`-modification during the turn (i.e., `touched_paths`) regardless of whether its final content nets out to a no-op, and diff each intermediate write against its immediately-prior content rather than only baseline-vs-final. At minimum, treat "touched but net-zero diff" as a distinct, always-reviewed case rather than folding it into the same empty-`review_set` skip path used for genuinely untouched turns.

### Proof of Concept
1. Attacker plants an instruction via any externally-influenced source Claude reads during the session (fetched URL, file content, tool result) telling Claude to append a malicious snippet to `config.py`, run it via `Bash` (e.g., to read and exfiltrate `~/.aws/credentials` via a benign-looking network call), then remove the snippet again and restore `config.py` to its original bytes.
2. `UserPromptSubmit` captures `baseline_sha` via `capture_git_baseline` before any of this happens [6](#0-5) .
3. Claude performs write → execute → revert-write within the turn. Each individual `Write`/`Edit` triggers only the fast regex `PostToolUse` pattern check, which the payload is crafted to avoid matching.
4. At `Stop`, `compute_v2_review_set` finds the working tree identical to `baseline_sha` for `config.py`, `review_paths` is empty, and `handle_stop_hook` exits via `_skip(6)`/`_skip(9)` without ever invoking the LLM vulnerability scan [3](#0-2) .
5. No finding is ever surfaced, even though credentials were exfiltrated mid-turn — the "oracle" (git diff) was manipulated and restored before it was sampled.

The plugin has two layers:

1. **Pattern-based rules (PostToolUse, every edit)**: Fast regex checks that run on

def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
