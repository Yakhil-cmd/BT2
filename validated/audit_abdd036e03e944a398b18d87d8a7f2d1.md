### Title
Debt-value multiplication overflows i128 during accrual before the borrow-index cap engages, permanently freezing the market - (File: common/src/rates/index.rs)

### Summary
Every state-changing pool verb begins by accruing indexes (`global_sync` → `accrue_chunk` → `accrue_step` → `calculate_supplier_rewards`). That split computes `borrowed * new_borrow_index` and `borrowed * old_borrow_index` as `i128` `Ray` products in `calculate_supplier_rewards` (common/src/rates/index.rs:80-81). The borrow index is capped at `MAX_BORROW_INDEX_RAY` inside `update_borrow_index` (common/src/rates/index.rs:13-19), but the cap is applied to the index, not to the `scaled_debt × index` product. On a large, high-decimal market at sustained high utilization, `borrowed * index` crosses `i128::MAX` while `borrow_index` is still below its cap. From that point every accrual panics with `GenericError::MathOverflow`, and since accrual runs first on every entrypoint, `repay`, `withdraw`, `borrow`, `liquidate`, `clean_bad_debt`, and `update_indexes` all revert — permanently. The in-repo regression test documents this exact cliff: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:315-356) asserts `MATH_OVERFLOW` on `update_indexes`, `withdraw`, and `repay` after the cliff.

### Finding Description
- Root cause: `calculate_supplier_rewards` multiplies total scaled debt by the borrow index in `i128` via `Ray::mul` (which routes to `mul_div_half_up`, panicking on result overflow — common/src/math/fp_core.rs:108-118). The same unbounded product appears in `supply_index_reward_shortfall` and `update_supply_index` (`supplied.mul(old_index)`, common/src/rates/index.rs:34, 60-62). `calculate_scaled_cap` already uses the saturating `mul_div_floor_saturating` for exactly this reason (common/src/rates/scaling.rs:26-33), but the accrual path was not given the same treatment.
- The guard that is supposed to bound growth — `MAX_BORROW_INDEX_RAY` — caps the index ratio, not the value domain. A market whose scaled debt `borrowed` is large enough that `borrowed * index > i128::MAX` at `index < MAX_BORROW_INDEX_RAY` hits the value ceiling first. The test comment quantifies it: `1e36` raw RAY of principal vs an `i128::MAX` ceiling ~170× larger; the XLM curve's steep segment pushes the index past ~170× before the cap (tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:315-319).
- Reachability: `supply`, `borrow`, and `update_indexes` are unprivileged. An attacker (or simply organic whale flow) supplies a very large position on a high-decimals listed market, borrows near the utilization limit, and the first accrual that pushes `borrowed * borrow_index` past `i128::MAX` bricks the market — including for all other users' positions in that book. `global_sync` runs at the head of every verb (contracts/pool/src/interest.rs:20-33), so nothing can clear the state.

### Impact Explanation
Permanent freezing of funds and the market contract unable to operate: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and bad-debt cleanup cannot run — every path reverts in accrual. In a hub/spoke design each market book is separate, so the blast radius is the affected `(hub, token)` book, but all funds in that book are locked indefinitely with no admin escape (index timestamps can't be rolled back, and the panic occurs before any state write).

### Likelihood Explanation
Medium. It requires a genuinely large debt base relative to the RAY domain (test uses a billion whole 18-decimal tokens, i.e. scaled debt ≈ `1e36`×debt share) and sustained high utilization long enough for the borrow index to grow ~170× — the test reaches the cliff in under 40 simulated years at 98% utilization on the steep XLM curve segment. Caps and utilization limits mitigate but do not bound the `i128` value domain: the test explicitly disables max-utilization and lifts caps, yet `lift_caps` aside, nothing in the math prevents a sufficiently funded attacker from reaching the same state on a listed high-decimal market. No privileged action, oracle manipulation, or leaked key is needed — only capital and time.

### Recommendation
Compute the accrued-interest split in a widened domain or on the delta, not the product: e.g. `accrued = borrowed * (new_index - old_index)` (the index delta is small by construction via `MAX_COMPOUND_DELTA_MS` chunking), or use `I256` intermediates in `calculate_supplier_rewards`/`update_supply_index`/`supply_index_reward_shortfall` as the codebase already does via `mul_div_floor_saturating` for caps. Alternatively, enforce an economic bound: derive a hard cap on `scaled_to_original(borrowed, MAX_BORROW_INDEX_RAY)` fitting `i128` and enforce it at `borrow`/`supply` time via `require_cap_within_asset_domain`-style validation, so the index cap always engages before the value ceiling.

### Proof of Concept
Conceptual, matching the checked-in regression test:

1. On a listed 18-decimal market (`xlm_curve` params), call `supply` with `1_000_000_000 * 10^18` raw units (`t.supply_raw(BOB, "BIG18", principal)`).
2. Supply collateral in a second market and `borrow` 98% of the pool: `t.borrow_raw(ALICE, "BIG18", principal * 98 / 100)`.
3. Advance time in yearly steps, calling `update_indexes` (unprivileged). Each call accrues via `accrue_chunk` → `calculate_supplier_rewards` → `borrowed.mul(env, new_borrow_index)`.
4. When `borrowed * borrow_index` exceeds `i128::MAX` (observed in the test with `borrow_index < MAX_BORROW_INDEX_RAY`), `update_indexes` returns `Error(Contract, MATH_OVERFLOW)`.
5. Subsequent `withdraw(BOB, "BIG18", 1)` and `repay(ALICE, "BIG18", ...)` both revert with `MATH_OVERFLOW` in `global_sync` — the market is permanently frozen (asserted at tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:348-356). pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
```
