### Title
Cross-Stack Authorization Bypass via Unscoped `stack` Lookup in `CCMenuController` - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::BaseController` enforces the binding "the stack a token authorises == the stack a request touches" by scoping stack lookups through `stacks`, which restricts to `current_api_client.stack_id` when the client is stack-scoped: [1](#0-0) 
`Shipit::Api::CCMenuController` overrides `stack` and looks the stack up directly via `Stack.from_param!(params[:stack_id])`, bypassing that scoping entirely: [2](#0-1) 

### Finding Description
`ApiClient` tokens can be scoped to a single stack via `belongs_to :stack, optional: true` and the `stack_id` column: [3](#0-2) . Authorization is enforced in two independent layers by `BaseController`:
1. Permission-scope check (`check_permissions!`), which only checks whether the client has the literal string permission (e.g. `read:stack`), with no notion of *which* stack: [4](#0-3) 
2. Stack-identity scoping, implemented in `BaseController#stacks`/`#stack`, which is the mechanism that actually binds "the stack the token is authorized for" to "the stack acted upon": [1](#0-0) 

`CCMenuController` requires only the generic `read:stack` permission (layer 1) but re-defines `stack` to call `Stack.from_param!(params[:stack_id])` directly instead of `stacks.from_param!(params[:stack_id])`, dropping layer 2 entirely: [5](#0-4) 

As a result, any `ApiClient` token created with the `read:stack` permission — even one explicitly scoped to a single stack (`stack_id` set) — can pass an arbitrary `stack_id` param to `GET /api/stacks/:stack_id/ccmenu` and retrieve CI/build status for a stack it was never authorized to see. The fixture data shows this scoping is a real, intentional security boundary elsewhere: `here_come_the_walrus` is a token deliberately restricted to the `shipit` stack with only `read:stack`: [6](#0-5) , and other API controllers/tests rely on `stacks`/`stack` for exactly this restriction, e.g. `"an api client scoped to a stack will only see that one stack"`: [7](#0-6) .

The break is: `current_api_client.stack_id` (the stack the token is authorised to touch) ≠ `params[:stack_id]` resolved via unscoped `Stack.from_param!` (the stack actually touched) inside `CCMenuController`.

### Impact Explanation
This is an authorization/access-control defect of the same class flagged in the external report (missing/incorrect binding between the authorizing entity and the entity actually acted upon), applied to Shipit's API-client stack-scoping model instead of Solana account authority fields. Concretely, it allows a legitimately-issued, narrowly-scoped API credential (`read:stack` limited to one stack) to read `lastBuildStatus`, `lastBuildLabel`, lock status, and other build/deploy state for every stack in the Shipit instance, not just the one it was provisioned for. This is an unauthenticated-relative-to-that-stack read of stack state by a credential holder who should only ever see one stack — a scope/tenant isolation break, which is the class of issue explicitly called out as an acceptable High-severity impact ("unauthenticated read of stack state ... ").

### Likelihood Explanation
Any party holding a valid, narrowly-scoped `ApiClient` token (e.g. a CI system, or a Basic-Auth/`token` query-string credential distributed to a specific team for a specific stack, as generated by `CCMenuUrlController`: [8](#0-7) ) can trivially exploit this by substituting a different `stack_id` in the request URL — no additional privilege, secret, or session is required beyond the token they already legitimately possess. This makes exploitation straightforward once any scoped token exists.

### Recommendation
In `app/controllers/shipit/api/ccmenu_controller.rb`, remove the local `stack` override (or reimplement it to delegate to the inherited, scoped lookup):
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
so that CCMenu requests are constrained the same way as every other API controller, i.e. through `BaseController#stacks`, which honors `current_api_client.stack_id`.

### Proof of Concept
1. Create/obtain an `ApiClient` token scoped to `stack_id = A` with permission `read:stack` only (equivalent to the `here_come_the_walrus` fixture).
2. Authenticate to the CCMenu endpoint with that token but request a different stack's id:
   `GET /api/stacks/<stack_B_id>/ccmenu?token=<token_for_stack_A>`
   (or via HTTP Basic auth, per `CCMenuController#authenticate_api_client`: [9](#0-8) ).
3. Because `stack` resolves via `Stack.from_param!(params[:stack_id])` rather than the scoped `stacks.from_param!`, the request succeeds and returns Stack B's build/CI XML data, even though the token is only authorised for Stack A. Contrast with any other stack-scoped endpoint (e.g. `Api::StacksController#show`), where the same token against a foreign stack ID returns 404, as validated by the existing scoping test: [7](#0-6) .

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
