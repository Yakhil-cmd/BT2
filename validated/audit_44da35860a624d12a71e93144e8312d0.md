## Title
Unauthenticated `new_shared_address` device message lets a paired correspondent silently register an attacker-crafted shared-address definition without owner consent - (File: `wallet_defined_by_addresses.js`)

### Summary
This is the Obyte analog of the Mattermost bug class (CVE-2023-1774): a party is added to a shared/private structure (there, a private channel; here, a shared/multisig address) without the recipient's protocol validating that the sender is actually entitled to make that addition. In `ocore`, the `new_shared_address` device message is processed directly by `handleNewSharedAddress()` with no confirmation step and no check that the sending device is an authorized party to the address being introduced, unlike the legitimate `create_new_shared_address`/`approve_new_shared_address` flow which does require explicit local user approval.

### Finding Description
The intended way to create a shared/multisig address requires user confirmation on every member device: `create_new_shared_address` triggers a `create_new_shared_address` event for a confirmation dialog [1](#0-0) , and only after all members approve is the address materialized and `new_shared_address` sent out [2](#0-1) .

However, `wallet.js` also accepts `new_shared_address` unconditionally from *any* correspondent device and forwards it straight to `handleNewSharedAddress` with no confirmation dialog and no gating on how the sender learned of / is related to the addresses involved: [3](#0-2) 

`handleNewSharedAddress` only checks internal self-consistency of the payload (definition hashes to the claimed address, signer addresses match the definition's `address` leaves) — it never verifies that `from_address` (the sending device) corresponds to one of the addresses/devices in the definition, nor that the local user previously agreed to be part of this address: [4](#0-3) 

The only "membership" check performed afterwards is `determineIfIncludesMeAndRewriteDeviceAddress`, which merely checks whether one of the **victim's own addresses** appears somewhere in the attacker-supplied definition — it does not validate that the *inviter* (the sender of the message) has any legitimate standing to introduce this new shared address, and does not require any local approval before the record is persisted: [5](#0-4) 

If the victim's address is found, `addNewSharedAddress` inserts the shared address and its signing paths straight into `shared_addresses` / `shared_address_signing_paths` with no additional authorization and even auto-forwards it further to the victim's other cosigner devices: [6](#0-5) 

Because the attacker fully controls the `arrDefinition` sent in the payload, they can construct an `["or", [["address","VICTIM_ADDR"], ["address","ATTACKER_ADDR"]]]`-style definition. This is deterministically hashed to a new "shared address" that the victim's wallet will now silently track as a shared address belonging to them (it is inserted into `shared_addresses`), even though only the attacker's signature is actually required to spend from it under the `or` condition.

### Impact Explanation
This maps to "unauthorized spending" / fund loss: a wallet can be induced to treat an attacker-chosen address as one of the user's own (shared) addresses via an entirely unauthenticated, non-confirmed device message, when the true authorization semantics of that address may allow the attacker to unilaterally spend any funds later sent there — while the victim's UI may display it as a legitimate multisig/shared address they participate in. This bypasses the deliberate two-way `create_new_shared_address` → `approve_new_shared_address` consent flow that the protocol designed specifically to prevent unilateral address creation, exactly analogous to Mattermost failing to check the inviter's permission before granting private-channel membership.

### Likelihood Explanation
Any paired correspondent device (a "correspondent" relationship is a low bar — pairing codes are exchanged routinely, e.g., through bots, arbiter contracts, or ordinary pairing) can send this message at will; `handleMessageFromHub` dispatches `new_shared_address` to `wallet.js`'s handler for any known correspondent device without special privilege [7](#0-6) . No cryptographic proof of the inviter's membership or of local-user consent is required, making this trivially reachable by any paired peer.

### Recommendation
Before calling `addNewSharedAddress`, `handleNewSharedAddress` should require an explicit user-confirmation step (as is done for `create_new_shared_address`) or at minimum cryptographically verify that `from_address` corresponds to one of the addresses/devices declared as signers in the definition and that the definition was previously agreed via the pending-shared-address approval flow (matching a `pending_shared_addresses`/`pending_shared_address_signing_paths` record) rather than accepting arbitrary unsolicited definitions.

### Proof of Concept
1. Attacker pairs with victim's wallet as a normal correspondent.
2. Attacker crafts `arrDefinition = ["or", [["address", VICTIM_ADDRESS], ["address", ATTACKER_ADDRESS]]]`, computes `address = objectHash.getChash160(arrDefinition)`, and builds a `signers` map satisfying `extractAddressPathsFromDefinition` matching.
3. Attacker sends a `new_shared_address` device message with this body to the victim.
4. `handleNewSharedAddress` validates internal consistency only, finds the victim's own address referenced, and silently calls `addNewSharedAddress`, inserting the shared address/definition with no confirmation dialog shown to the victim [8](#0-7) .
5. The victim's wallet may now display/track `address` as a shared address of theirs; funds sent there can be spent unilaterally by the attacker due to the `or` condition, without any wallet consent step having occurred.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
