### Title
Governance-settable `kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, halting all post-Magma block production and validation — (`params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter accepts `0` as a valid value (its `FormatChecker` is `noopFormatChecker`). When set to `0`, `KIP71Config.NextMagmaBlockBaseFee()` performs an integer division by zero on any block whose parent had non-zero gas used, causing a Go runtime panic. Every call site — block building, block validation, and the tx-pool base-fee update — crashes, halting the chain until governance reverses the vote across at least one full epoch.

---

### Finding Description

**Root cause — missing zero-guard on `Kip71GasTarget`**

In `kaiax/gov/param.go`, the `Kip71GasTarget` parameter entry uses `noopFormatChecker`, which unconditionally returns `true`: [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` explicitly rejects zero: [2](#0-1) 

The code in `NextMagmaBlockBaseFee()` already guards against `BaseFeeDenominator == 0` with a fallback value: [3](#0-2) 

No equivalent guard exists for `GasTarget`. The function reads it directly: [4](#0-3) 

**The panic path**

When `GasTarget == 0` and the parent block had any gas used (`parentGasUsed > 0`), execution falls into the `parentGasUsed > gasTarget` branch and divides by zero: [5](#0-4) 

`big.Int.Div()` panics on a zero divisor in Go. The only safe exit is the `parentGasUsed == gasTarget` early return, which only fires when `parentGasUsed == 0` (an empty block). Any block containing at least one transaction triggers the panic.

**Call sites that crash**

Every post-Magma block-processing path calls `NextMagmaBlockBaseFee()`:

- Block builder (`work/worker.go` line 382): proposer node panics before sealing any block.
- Block validator (`blockchain/block_validator.go` via `VerifyMagmaHeader`): every importing node panics on header validation.
- Tx-pool base-fee update (`blockchain/tx_pool.go`): panics on base-fee refresh.
- Gas-price oracle (`node/cn/gasprice/gasprice.go`): panics on fee-history queries. [6](#0-5) [7](#0-6) 

---

### Impact Explanation

Once the ratified `kip71.gastarget = 0` takes effect at the next epoch boundary, every node on the network panics when processing the first non-empty block. No new blocks can be built or validated. The chain halts completely until a corrective governance vote is ratified and takes effect — a minimum of one additional full epoch (604,800 blocks, roughly one week on mainnet). KAIA transfers, staking withdrawals, bridge settlements, and all on-chain operations are frozen for that duration.

This matches the allowed impact gate: **invalid block/proof acceptance and consensus divergence on honest nodes** (all honest nodes crash simultaneously), and **persistent corruption of canonical execution** (no block can be finalized).

---

### Likelihood Explanation

The trigger requires the governing node (a semi-trusted actor in `single` governance mode) to cast a vote for `kip71.gastarget = 0`. The vote passes the `noopFormatChecker` without rejection. The scenario is analogous to the FiRM M-08 report: an emergency or misconfigured governance action that is semantically valid but operationally catastrophic. The asymmetry — `BaseFeeDenominator` is already protected, `GasTarget` is not — makes an accidental zero-vote plausible.

---

### Recommendation

1. **Add a non-zero `FormatChecker` for `Kip71GasTarget`**, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```

2. **Add a defensive guard in `NextMagmaBlockBaseFee()`** analogous to the existing `BaseFeeDenominator` guard, so that a zero `GasTarget` does not panic even if it somehow reaches the function:

```go
if kc.GasTarget == 0 {
    // Avoid division by zero; treat as if gas used equals target
    return makeEvenByFloor(parentBaseFee)
}
gasTarget := kc.GasTarget
``` [3](#0-2) 

---

### Proof of Concept

1. Governing node casts a header-governance vote: `governance_vote("kip71.gastarget", 0)`.
2. The vote passes `noopFormatChecker` and is recorded in `header.Vote` at the current block.
3. At the next epoch boundary, the vote is ratified and written to `header.Governance`.
4. At the epoch after that, `GetParamSet(N).GasTarget == 0` for all new blocks.
5. The block builder calls `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` in `work/worker.go:382`. The parent block has `GasUsed > 0` (any transaction was included). Execution reaches line 102 of `params/kip71_config.go`:
   ```go
   y := x.Div(x, new(big.Int).SetUint64(0))  // runtime panic: integer divide by zero
   ```
6. The proposer node crashes. Every other node crashes identically when calling `VerifyMagmaHeader` on the next block attempt.
7. The chain halts. Recovery requires a new governance vote, ratification, and activation — at minimum one full epoch. [1](#0-0) [8](#0-7) [9](#0-8)
