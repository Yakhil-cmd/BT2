### Title
Unverified swap venues can append arbitrary token transfers to the caller's authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
User-controlled route bytes can cause the configured swap aggregator to invoke an attacker-controlled pool, and that pool can request token transfers from the caller under the caller’s signed top-level authorization tree. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`swap_collateral` accepts a `caller`, an existing `account_id`, source and destination `HubAssetKey` markets, an `amount`, and opaque `swap` bytes. [1](#0-0) 

After withdrawing the source collateral, the controller authorizes only the expected `token_in.transfer(controller, router, amount_in)` and invokes `router.execute_strategy(controller, amount_in, swap)`. [4](#0-3) [5](#0-4) 

The router payload contains arbitrary pool addresses, and each swap instruction dispatches to the payload-selected `pool` without a venue or pool allowlist. [6](#0-5) [3](#0-2) 

For example, the Soroswap adapter queries and invokes the supplied pool address directly. [7](#0-6) [8](#0-7) 

A malicious pool implementing the expected venue ABI can invoke `unrelated_token.transfer(victim, attacker, amount)`, causing simulation to attach that transfer as a child of the victim’s controller authorization. [9](#0-8) [10](#0-9) 

The exact-input authorization protects only the controller’s tokens; it does not constrain additional authorization children signed by the user. [2](#0-1) [11](#0-10) 

### Impact Explanation
An attacker who supplies a poisoned route can steal any caller-held token for which the malicious pool inserts a signed `transfer` invocation, including tokens unrelated to the lending position. [12](#0-11) [13](#0-12) 

The demonstrated exploit transferred the victim’s entire unrelated wallet-token balance to the attacker while still producing valid swap output for the position. [12](#0-11) 

### Likelihood Explanation
The attacker needs no protocol privilege and can deploy the malicious pool contract, but exploitation requires a victim to submit a poisoned route and accept the authorization tree returned by simulation. [14](#0-13) [15](#0-14) 

If the victim signs only the honest root invocation without the malicious child, the host rejects the unauthorized transfer and rolls back the transaction. [16](#0-15) 

### Recommendation
Do not allow route payloads to name arbitrary venue contracts; enforce a governance-approved pool/venue registry or verified venue contract set before dispatch. [3](#0-2) 

Wallets and route providers should also reject simulated authorization trees containing any child invocation other than the expected input-token transfer. [17](#0-16) [18](#0-17) 

### Proof of Concept
1. The victim owns an account with supplied `USDC` collateral and a large balance of an unrelated token. [19](#0-18) 
2. The attacker deploys a fake pool configured with `(victim, unrelated_token, attacker, balance)` and encodes it as the pool address in a route. [20](#0-19) [14](#0-13) 
3. The victim calls `swap_collateral(victim, account_id, usdc_hub_asset, amount, eth_hub_asset, poisoned_route)`. [1](#0-0) [21](#0-20) 
4. During route execution, the fake pool calls `unrelated_token.transfer(victim, attacker, balance)`. [9](#0-8) 
5. Simulation records that token transfer beneath the victim’s `swap_collateral` authorization root. [22](#0-21) 
6. Once the returned tree is signed, the transaction succeeds, drains the unrelated token to the attacker, and deposits the expected swap output. [11](#0-10) [12](#0-11)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
