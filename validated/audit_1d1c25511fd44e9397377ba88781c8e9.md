### Title
Unicode bidi-override/zero-width characters in agent tool-call metadata are rendered unsanitized by `followLogs`, enabling terminal path/command spoofing - (File: pkg/cmd/agent-task/create/create.go)

### Summary
`followLogs` (create.go:263) streams agent-session logs through `shared.LogRenderer.Follow`/`Render`, which prints tool-call fields such as file paths, bash commands, and commit messages directly to the terminal via `fmt.Fprintf`/`renderToolCallTitle` with no stripping of Unicode bidirectional-override (e.g. U+202E) or zero-width characters. An attacker who can influence what the coding agent names, edits, or runs (e.g. a maliciously named file/branch/command in a repo the agent operates on) can make the terminal display a reversed or visually altered path/command/extension while the underlying string is different.

### Finding Description
`followLogs` in [1](#0-0)  calls `renderer.Follow(fetcher, opts.IO.Out, opts.IO)`, which repeatedly fetches raw SSE-style log bytes and calls `Render` in [2](#0-1) .

`Render`/`renderLogEntry` decode `chat.completion.chunk` entries and dispatch on tool-call name. Only two fields (`Content`, `ReasoningText`) are typed `iostreams.Untrusted`, whose `String()` runs the content through `asciisanitizer` to strip ASCII control bytes/escape sequences [3](#0-2) . All the other attacker-influenced fields decoded from `tc.Function.Arguments` (`bashToolArgs.Command`, `viewToolArgs.Path`, `createToolArgs.Path`/`FileText`, `strReplaceToolArgs.Path`, `reportProgressToolArgs.CommitMessage`) are plain `string` fields with **no** `Untrusted` wrapping and no sanitization at all before being printed [4](#0-3) . They are written straight into the terminal via `renderToolCallTitle` (`fmt.Fprintf(w, "%s: %s\n", toolName, title)`) [5](#0-4)  or embedded into a fenced code block and passed to glamour for markdown rendering [6](#0-5) .

Even for the `Untrusted`-typed fields, `asciisanitizer` (per its name and usage pattern elsewhere in the repo, e.g. `pkg/skills/list/list.go`) neutralizes ASCII C0/C1 control bytes and ANSI escape sequences, not general multi-byte Unicode code points such as U+202E (RIGHT-TO-LEFT OVERRIDE) or U+200B/U+200D (zero-width space/joiner). No code path in the repository (`grep` for "bidi", "RTL", "202E", "zero-width" returns nothing outside an unrelated `.golangci.yml` match) performs Unicode bidi-control or zero-width stripping before writing to a terminal.

`relativeFilePath` (used to compute the displayed path for `view`/`create`/`str_replace` tool calls) also does no sanitization, just string splitting [7](#0-6) .

Consequently, if a coding-agent tool call operates on a path, branch, or shell command containing a bidi-override character (which the agent could pick up from attacker-controlled repository content, e.g. a file or branch name it is instructed to view/create/edit), the terminal will render that path/command with visually reordered characters (classic "Trojan Source" style spoofing), potentially disguising a file's real name/extension or a bash command's real arguments from the user watching `gh agent-task create --follow`.

### Impact Explanation
This is a terminal output/prompt spoofing issue: a victim running `gh agent-task create --follow` could be shown a plausible-looking file path, extension, or shell command in the tool-call titles/code blocks while the real underlying string differs, matching the "Terminal output/prompt spoofing" bounty class. Because `gh agent-task create` never asks for further destructive confirmation itself (it only streams logs), the direct exploitable impact is limited to **display deception** — the user may be misled about what the remote coding agent did/ran, not that gh itself executes anything malicious locally.

### Likelihood Explanation
Preconditions: an attacker needs the coding-agent to process/create/reference a path, branch, or bash command it controls (e.g., through repository content, issue/PR content, or task descriptions that steer the agent into acting on adversarial file/branch names). This requires the agent to actually pick up and act on attacker-supplied naming, which is plausible but not fully attacker-controlled end-to-end (the agent's own decisions and the API mediate what shows up in the log stream). The vulnerable rendering code itself is directly reachable and unconditionally lacks bidi/zero-width filtering, so once such content reaches a tool call, the spoofing is deterministic and repeatable.

### Recommendation
Strip or escape Unicode bidirectional-control characters (U+202A–U+202E, U+2066–U+2069) and zero-width characters (U+200B, U+200C, U+200D, U+FEFF) from all attacker-influenced strings before they reach the terminal in `pkg/cmd/agent-task/shared/log.go` — specifically `bashToolArgs.Command`, `viewToolArgs.Path`/`createToolArgs.Path`/`strReplaceToolArgs.Path` (and their `relativeFilePath` output), `reportProgressToolArgs.CommitMessage`, and file content rendered in code blocks. Consider extending `iostreams.Untrusted`/`asciisanitizer` usage (or adding a dedicated Unicode sanitizer) to cover these fields, and apply it consistently rather than relying on ad hoc `Untrusted` typing of only two struct fields.

func (r *logRenderer) Follow(fetcher func() ([]byte, error), w io.Writer, io *iostreams.IOStreams) error {
	var last string
	for {
		raw, err := fetcher()
		if err != nil {
			return err
		}

		logs := string(raw)
		if logs == last {
			continue
		}

		diff := strings.TrimSpace(logs[len(last):])

		if stop, err := r.Render([]byte(diff), w, io); err != nil {
			return err
		} else if stop {
			return nil
		}

		last = logs
	}
}

// Render processes the given logs and writes the rendered output to w.
// Errors are returned when an unexpected log entry is encountered.
func (r *logRenderer) Render(logs []byte, w io.Writer, io *iostreams.IOStreams) (bool, error) {
	lines := slices.DeleteFunc(strings.Split(string(logs), "\n"), func(line string) bool {
		return line == ""
	})

	for _, line := range lines {
		raw, found := strings.CutPrefix(line, "data: ")
		if !found {
			return false, errors.New("unexpected log format")
		}

		// The only log entry type we're interested in is a chat completion chunk,
		// which can be verified by a successful unmarshal into the corresponding
		// type AND the Object field being equal to "chat.completion.chunk". The
		// latter is to avoid accepting an empty JSON object (i.e. "{}"). Also,
		// if the entry is not what we expect, we should just skip and avoid
		// returning an error.
		var entry chatCompletionChunkEntry
		err := json.Unmarshal([]byte(raw), &entry)
		if err != nil || entry.Object != "chat.completion.chunk" {
			continue
		}

		if stop, err := renderLogEntry(entry, w, io); err != nil {
			return false, fmt.Errorf("failed to process log entry: %w", err)
		} else if stop {
			return true, nil
		}
	}

	return false, nil
}

func renderFileContentAsMarkdown(path, content string, w io.Writer, io *iostreams.IOStreams) error {
	lang := filepath.Ext(filepath.ToSlash(path))

	if lang == ".md" {
		return renderRawMarkdown(content, w, io)
	}

	md := fmt.Sprintf("```%s\n%s\n```", lang, content)
	// Glamour adds leading newlines when content is only a code block,
	// so we only want to add a trailing newline.
	formatFunc := func(s string) string {
		return fmt.Sprintf("%s\n\n", s)
	}

	return renderMarkdownWithFormat(md, w, io, formatFunc)
}

// relativeFilePath converts an absolute file path to a relative one.
// We expect paths to be of the form: /home/runner/work/<repo-owner>/<repo-name>/path/to/file
// The expected output of that example is: path/to/file
func relativeFilePath(absPath string) string {
	relPath := strings.TrimPrefix(absPath, "/home/runner/work/")

	parts := strings.Split(relPath, "/")

	// The last two parts of the path are the
	// repo name and the repo owner.
	// If that's all we have (or less),
	// we return a friendly name "repository".
	if len(parts) > 2 {
		// Drop the repo owner and name, returning the remaining path.
		return strings.Join(parts[2:], "/")
	}
	return "repository"
}

func renderToolCallTitle(w io.Writer, cs *iostreams.ColorScheme, toolName, title string) {

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
