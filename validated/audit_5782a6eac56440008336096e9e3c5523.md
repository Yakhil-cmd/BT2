### Title
Third-party dust top-up on an insolvent account permanently blocks permissionless bad-debt socialization - ([File: contracts/controller/src/positions/liquidation/curve.rs](contracts/controller/src/positions/liquidation/curve.rs))

### Summary
Analogous to CVE-2017-5604 (a message carbon-copy is attributed to a forged sender), XOXNO Lending lets any unprivileged address inject collateral into a foreign account's existing supply leg via `supply`, and that attacker-attributed deposit is treated as the victim's own collateral by the bad-debt eligibility check. Permissionless `clean_bad_debt` requires `total_collateral <= BAD_DEBT_USD_THRESHOLD` ($5); a donation just above that threshold flips an insolvent account out of the dust-gated cleanup domain indefinitely, leaving bad debt unsocialized on the books.

### Finding Description
- `clean_bad_debt` is permissionless but gated by `BadDebtGate::DustCapped`, which calls `is_socializable_bad_debt(total_debt, total_collateral) = total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` (5 WAD USD) [1](#0-0) [2](#0-1) 
- `process_supply` permits any authenticated third party to top up an asset the target account already supplies: `require_third_party_existing_supply` only rejects assets not already in `account.supply_positions`, so an existing collateral leg is freely top-uppable by a stranger [3](#0-2) 
- The donated tokens are pulled from the attacker's balance but credited to the victim account's supply position via the measured-receipt path [4](#0-3) 
- The Certora spec confirms the "straddle" is a real, deliberately modeled state: an attacker who raises `total_collateral` strictly above `BAD_DEBT_USD_THRESHOLD` "blocks the permissionless dust-gated socialization path while staying insolvent" [5](#0-4) 
- Unlike `SeizeMode`-style flows there is no auth on who may collateralize the account; the carbons-style "forwarded" deposit is indistinguishable from owner-supplied collateral to the eligibility gate.

### Impact Explanation
Bad debt is only cleared by `clean_bad_debt` (dust-gated, permissionless) or `force_socialize_bad_debt` (governance-owner only, Sensitive timelock tier) [6](#0-5) [7](#0-6) . For roughly $5 of donated collateral per account, an attacker forces every insolvent account out of the permissionless path, so debt that should have been written off against the supply index keeps accruing interest, worsening protocol insolvency and delaying socialization until a timelocked governance operation executes for each affected account — a temporary freezing of the bad-debt cleanup function and prolonged protocol insolvency. The attacker can repeat the donation again any time collateral drifts back under the threshold (e.g., after partial liquidation or price moves), making the block indefinite.

### Likelihood Explanation
- Reachability: `supply(caller, account_id, spoke_id, assets)` is permissionless; the only restriction is that the asset already exists in the victim's supply positions — trivially true for any insolvent account, which by definition holds collateral [8](#0-7) 
- Cost: `BAD_DEBT_USD_THRESHOLD` is a fixed 5 USD [9](#0-8) , so blocking each account costs marginally more than $5 of the attacker choosing the collateral asset.
- No timing dependency: the donation persists; there is no cooldown, epoch, or owner confirmation between the top-up and the eligibility check.
- Severity is bounded (Medium) because governance retains `force_socialize_bad_debt` with no collateral cap, so the block is circumventable but requires a scheduled, delayed operation per account.

### Recommendation
Decouple eligibility for socialization from attacker-injectable state, or bound the injection:
- Compute the dust cap against collateral attributable to the account owner (e.g., exclude third-party top-ups), or
- Lower/eliminate reliance on the dust threshold by allowing `clean_bad_debt` to proceed whenever `total_debt > total_collateral` and seizing the excess collateral as part of cleanup (cleanup already reclassifies all remaining collateral as revenue [10](#0-9) ), or
- Require owner/delegate authorization for any `supply` into an account with outstanding debt whose collateral is within a band of `BAD_DEBT_USD_THRESHOLD` (e.g., disallow third-party top-ups while `total_debt > total_collateral`).

### Proof of Concept
1. Alice supplies 100 USDC and borrows 0.02 ETH; USDC price crashes to $0.30, so `total_debt > total_collateral` with `total_collateral ≈ $30`... or wait until collateral erodes to ≤ $5 — per the existing test shape (`test_force_socialize_bad_debt_above_dust_threshold`, collateral lands in the dust zone after liquidation) [11](#0-10) .
2. Attacker (BOB, unprivileged) calls `supply(bob, alice_account_id, alice_spoke_id, [(USDC_key, dust)])` with `dust` worth e.g. $5.01. `require_third_party_existing_supply` passes because USDC is already in Alice's `supply_positions`; measured receipt credits the position.
3. Any keeper calls `clean_bad_debt(caller, alice_account_id)`: `is_socializable_bad_debt` computes `total_collateral > 5 WAD`, so the call reverts with `CannotCleanBadDebt` (#114) [12](#0-11) .
4. The debt remains, continues accruing at `max_borrow_rate` chunks via `update_indexes`, and the market's supply index is never written down — until governance schedules and executes `ForceSocializeBadDebt` on the Sensitive tier. If price drift or a partial liquidation brings collateral back under $5, the attacker re-donates to re-block.

fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);

/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
}

### INV-LIQ-04 — Bad-debt socialization is explicit and total

Permissionless cleanup requires ceil risk debt greater than half-up unweighted
collateral and collateral at or below the fixed $5 dust threshold. Owner-only
forced cleanup omits the dust cap. Both require debt, readable account and NFT
state, valid required prices and no active flash guard. Listing flags and
global pause do not block standalone cleanup.

Cleanup reclassifies all remaining collateral shares as revenue and writes off
all remaining debt against each debt's market. It releases spoke usage and
atomically removes account entries and the NFT. It does not net same-market
supply against debt. Standalone cleanup emits `CleanBadDebtEvent` with
pre-cleanup USD totals, without a controller position-update batch.

#[test]
fn test_force_socialize_bad_debt_above_dust_threshold() {
    let mut t = setup();

    t.supply(BOB, "ETH", 100.0);
    t.supply(ALICE, "USDC", 100.0);
    t.borrow(ALICE, "ETH", 0.02);

    t.set_price("USDC", usd_cents(30));
    let account_id = t.resolve_account_id(ALICE);

    let collateral = t.total_collateral_raw(ALICE);
    let debt = t.total_debt_raw(ALICE);
    assert!(
        collateral > 5 * WAD,
        "fixture must sit strictly above the $5 dust gate: collateral_wad={collateral}"
    );
    assert!(
        debt > collateral,
        "fixture must be insolvent: debt_wad={debt} collateral_wad={collateral}"
    );

    let refused = t.try_clean_bad_debt_by_id(account_id);
    assert_contract_error(refused, errors::CANNOT_CLEAN_BAD_DEBT);

    let (si_before, _) = get_indexes(&t, "ETH");

    t.force_socialize_bad_debt_by_id(account_id);

    let (si_after, _) = get_indexes(&t, "ETH");
    assert!(
        si_after < si_before,
        "force-socialize must drop the ETH supply index: before={si_before}, after={si_after}"
    );
    t.assert_no_positions(ALICE);
}
