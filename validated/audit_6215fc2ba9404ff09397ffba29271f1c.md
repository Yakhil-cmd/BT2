### Title
KAIA Bridge Transfer Permanently Blocked by Reverting Recipient — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

### Summary

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` performs all nonce-state mutations (vote closure, `handleNoncesToBlockNums`, `_updateHandleNonce`, event emission) and then calls `_to.call.value(_value)("")`, requiring it to succeed. If `_to` is or becomes a contract whose fallback reverts, the entire transaction reverts — undoing every state mutation — and the nonce is permanently unhandleable. There is no owner-callable skip or recovery function in the bridge contract, so the KAIA deposited for that request is locked in the bridge forever.

### Finding Description

`handleKLAYTransfer` executes in this order:

1. `_lowerHandleNonceCheck(_requestedNonce)` — gate check
2. `_voteValueTransfer(_requestedNonce)` — threshold vote
3. `_setHandledRequestTxHash(_requestTxHash)` — mark tx hash
4. `handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber`
5. `_updateHandleNonce(_requestedNonce)` — advance `lowerHandleNonce`
6. `emit HandleValueTransfer(…)`
7. `(bool ok, ) = _to.call.value(_value)("")`
8. `require(ok, "handleKLAYTransfer: transfer failed")` [1](#0-0) 

If step 7 returns `ok = false` (because `_to` is a contract with a reverting fallback), step 8 reverts the entire transaction. All state mutations from steps 3–6 are rolled back. Because `handledRequestTx[_requestTxHash]` and `handleNoncesToBlockNums[_requestedNonce]` are never durably set, `_updateHandleNonce` can never advance `lowerHandleNonce` past this nonce: [2](#0-1) 

```solidity
for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) { … }
lowerHandleNonce = i;
``` [3](#0-2) 

Since `handleNoncesToBlockNums[stuck_nonce]` is always 0 (every attempt reverts), `lowerHandleNonce` is permanently pinned at the stuck nonce. The bridge contract has no `skipNonce`, `recoverKLAY`, or equivalent administrative function. The same pattern exists in `handleERC20Transfer` (via `safeTransfer` / `mint`) and `handleERC721Transfer` (via `transferFrom` / `mintWithTokenURI`): [4](#0-3) [5](#0-4) 

The Go-level bridge manager (`processingPendingRequestEvents`) re-queues the event on every error, so it retries the failing call indefinitely, wasting operator gas: [6](#0-5) 

### Impact Explanation

KAIA deposited by the source-chain user is held in the destination bridge contract. Because `handleKLAYTransfer` can never succeed for the stuck nonce, that KAIA is permanently locked with no on-chain recovery path. `lowerHandleNonce` is pinned, so `recoveryBlockNumber` also never advances for that bridge pair, degrading the accuracy of the value-transfer recovery subsystem.

### Likelihood Explanation

Any user can call `requestKLAYTransfer` specifying `_to` as:
- a contract already deployed with a reverting fallback, or
- an EOA that later has a contract deployed at the same address (CREATE2 or nonce-based) whose fallback reverts.

No special privilege is required. The source-chain `requestKLAYTransfer` performs no validation of `_to`: [7](#0-6) 

### Recommendation

Move the KAIA transfer **before** the nonce-state mutations, or — better — adopt a pull-payment pattern: record the owed amount in a mapping and let `_to` withdraw it separately. Alternatively, replace `require(ok, …)` with a non-reverting path that records the failed transfer and allows the bridge owner to redirect or refund the stuck KAIA via an administrative function.

### Proof of Concept

1. Deploy a contract `Revert` on the destination chain whose fallback always reverts.
2. On the source chain, call `bridge.requestKLAYTransfer(address(Revert), 1 ether, "0x")` with `msg.value = 1 ether + fee`.
3. The bridge emits `RequestValueTransfer` with `requestNonce = N`.
4. Bridge operator calls `handleKLAYTransfer(txHash, from, address(Revert), 1 ether, N, blockNum, "0x")`.
5. Steps 3–6 execute; then `address(Revert).call{value: 1 ether}("")` returns `ok = false`; `require` reverts the whole tx.
6. Repeat step 4 — always reverts.
7. Query `bridge.lowerHandleNonce()` — permanently returns `N`.
8. Query `bridge.handleNoncesToBlockNums(N)` — permanently returns `0`.
9. The 1 KAIA is locked in the bridge contract with no on-chain recovery.

    // handleKLAYTransfer sends the KLAY by the request.
    function handleKLAYTransfer(
        bytes32 _requestTxHash,
        address _from,
        address payable _to,
        uint256 _value,
        uint64 _requestedNonce,
        uint64 _requestedBlockNumber,
        bytes memory _extraData
    )
        public
        onlyOperators
        nonReentrant
    {
        _lowerHandleNonceCheck(_requestedNonce);

        if (!_voteValueTransfer(_requestedNonce)) {
            return;
        }

        _setHandledRequestTxHash(_requestTxHash);

        handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber;
        _updateHandleNonce(_requestedNonce);

        emit HandleValueTransfer(
            _requestTxHash,
            TokenType.KLAY,
            _from,
            _to,
            address(0),
            _value,
            _requestedNonce,
            lowerHandleNonce,
            _extraData
        );

        (bool ok, ) = _to.call.value(_value)("");
        require(ok, "handleKLAYTransfer: transfer failed");
    }
