### Title
Encrypted-transaction payloads bypass `EntryFunction`/`ModuleAddress` admission filters at mempool, consensus, and quorum-store boundaries - ([File: crates/aptos-transaction-filters/src/transaction_filter.rs])

### Summary
`TransactionMatcher::EntryFunction` and `TransactionMatcher::ModuleAddress` — the admission-control rules used by `mempool_filter`, `consensus_filter`, and `quorum_store_filter` to allow/deny transactions before they reach execution — unconditionally treat any encrypted transaction as non-matching, because the entry function is still ciphertext at admission time. A submitter can wrap a call that is explicitly denied by an operator's `EntryFunction`/`ModuleAddress` deny-rule inside `TransactionPayload::EncryptedPayload`, sail through every admission-time filter, and only have the true call revealed and executed after consensus decryption, long after the filter decision was already made.

### Finding Description
The filter matcher functions explicitly special-case the encrypted executable variant as a non-match: [1](#0-0) 

```
fn matches_entry_function(...) {
    ...
    TransactionPayload::EncryptedPayload(payload) => {
        if let Ok(executable) = payload.executable_ref() {
            match executable {
                TransactionExecutableRef::Script(_)
                | TransactionExecutableRef::Empty
                | TransactionExecutableRef::Encrypted => false,
                TransactionExecutableRef::EntryFunction(entry_function) => {
                    compare_entry_function(entry_function, address, module_name, function)
                },
            }
        } else { false }
    },
``` [2](#0-1) 

The same `Encrypted => false` pattern is repeated in `matches_entry_function_module_address` [3](#0-2) . `EncryptedPayload::executable_ref()` returns `TransactionExecutableRef::Encrypted` for both the `Encrypted` and `FailedDecryption` states — i.e. for the entire lifetime the transaction is visible to admission-time filters: [4](#0-3) 

This matcher backs the three admission-boundary filter configs applied before execution: `mempool_filter` (transaction submission), `consensus_filter` (proposal voting), and `quorum_store_filter` (batch voting) [5](#0-4) . Mempool applies this filter to every incoming transaction via `filter_transactions`, which calls `transaction_filter().allows_transaction(&transaction)` before the transaction is even inserted into the pool [6](#0-5) .

The only self-declared hint of the real entry function inside an encrypted payload is `claimed_entry_fun: Option<ClaimedEntryFunction>` [7](#0-6) , which is optional, chosen by the submitter, not exposed to `TransactionMatcher::EntryFunction`/`ModuleAddress`, and only checked much later — after consensus decryption — inside `try_into_decrypted` [8](#0-7) . Even that check is skippable simply by submitting the encrypted payload with `claimed_entry_fun: None` (as the SDK does by default) [9](#0-8) .

### Impact Explanation
Operators use `EntryFunction`/`ModuleAddress` deny-rules on `mempool_filter`/`consensus_filter`/`quorum_store_filter` as an admission-control safety mechanism — e.g., emergency incident response to block a known-vulnerable or exploited entry function from being submitted, proposed, or batched, without requiring a framework upgrade. Because the encrypted-executable branch of the matcher always returns `false` (never matches), any deny-rule targeting a specific entry function or module address is silently bypassed for any transaction resubmitted with an `EncryptedPayload`. The transaction is admitted through mempool, proposed by consensus, included in quorum-store batches, and only decrypted afterward for execution — i.e., a transaction that admission policy says "should fail admission" is executed and committed instead. This is a pre-validation mismatch at the exact admission boundary the task pivots call out.

### Likelihood Explanation
Exploitation requires only that (a) `FeatureFlag::ENCRYPTED_TRANSACTIONS` / encrypted-txn submission is enabled on the network (a supported, documented feature, not an experimental/permissioned one) and (b) the operator relies on `EntryFunction`/`ModuleAddress` matchers for admission-time denial. No privileged access or governance action is needed by the attacker — any account can submit an encrypted transaction via the API once encrypted-txn submission is allowed [10](#0-9) , and the entry-function content is entirely attacker-controlled and hidden until after all three filter stages have run.

### Recommendation
Do not treat `TransactionExecutableRef::Encrypted` as an automatic non-match for `EntryFunction`/`ModuleAddress` matchers. Either (a) reject/hold encrypted transactions from being admitted whenever an `EntryFunction`/`ModuleAddress` deny-rule is configured (fail closed rather than fail open), or (b) re-apply the same `EntryFunction`/`ModuleAddress` deny-rules against the decrypted payload immediately after `try_into_decrypted` succeeds, before the transaction is allowed to proceed to execution, and discard/hold the transaction if it violates a rule that would have blocked it at submission time.

### Proof of Concept
1. Enable `ENCRYPTED_TRANSACTIONS` and configure `mempool_filter` (or `consensus_filter`/`quorum_store_filter`) with a `Deny` rule using `TransactionMatcher::EntryFunction(module_addr, "vulnerable_module", "drain")`.
2. Submit a normal (unencrypted) transaction calling `vulnerable_module::drain` — confirm it is rejected with `MempoolStatusCode::RejectedByFilter` per `filter_transactions` [11](#0-10) .
3. Build the identical `vulnerable_module::drain` call, wrap it as `TransactionPayload::EncryptedPayload(EncryptedPayload::Encrypted(...))` using the SDK's `encrypt_payload` helper (omitting `claimed_entry_fun`) [12](#0-11) , and submit it via the API's encrypted-transaction path [10](#0-9) .
4. Observe the transaction passes `matches_entry_function`/`matches_entry_function_module_address` (both evaluate to `false`, so the `Deny` rule never matches) and is admitted into mempool, proposed, and batched.
5. After consensus decryption reveals `vulnerable_module::drain`, the transaction executes and commits — despite the operator's admission-time deny-rule that was specifically meant to block it.

/// Returns true iff the transaction's entry function matches the given account address, module name, and function name
fn matches_entry_function(
    signed_transaction: &SignedTransaction,
    address: &AccountAddress,
    module_name: &String,
    function: &String,
) -> bool {
    // Match all variants explicitly to ensure future enum changes are caught during compilation
    match signed_transaction.payload() {
        TransactionPayload::Script(_) | TransactionPayload::ModuleBundle(_) => false,
        TransactionPayload::Multisig(multisig) => multisig
            .transaction_payload
            .as_ref()
            .map(|payload| match payload {
                MultisigTransactionPayload::EntryFunction(entry_function) => {
                    compare_entry_function(entry_function, address, module_name, function)
                },
                MultisigTransactionPayload::Script(_) => false,
            })
            .unwrap_or(false),
        TransactionPayload::EntryFunction(entry_function) => {
            compare_entry_function(entry_function, address, module_name, function)
        },
        TransactionPayload::Payload(TransactionPayloadInner::V1 { executable, .. }) => {
            match executable.as_ref() {
                TransactionExecutableRef::Script(_)
                | TransactionExecutableRef::Empty
                | TransactionExecutableRef::Encrypted => false,
                TransactionExecutableRef::EntryFunction(entry_function) => {
                    compare_entry_function(entry_function, address, module_name, function)
                },
            }
        },
        TransactionPayload::EncryptedPayload(payload) => {
            if let Ok(executable) = payload.executable_ref() {
                match executable {
                    TransactionExecutableRef::Script(_)
                    | TransactionExecutableRef::Empty
                    | TransactionExecutableRef::Encrypted => false,
                    TransactionExecutableRef::EntryFunction(entry_function) => {
                        compare_entry_function(entry_function, address, module_name, function)
                    },
                }
            } else {
                false
            }
        },
    }
}

    /// Encrypts a transaction payload using the provided encryption key.
    /// This is a helper method used internally by `with_encrypted_payload` and `payload`.
    fn encrypt_payload(
        payload: TransactionPayload,
        sender: AccountAddress,
        signer_auth_keys: Vec<(AccountAddress, AuthenticationKey)>,
        encryption_key: &EncryptionKey,
        encryption_epoch: u64,
    ) -> Result<EncryptedPayload> {
        // Convert payload to executable
        let executable = payload.executable()?;
        let extra_config = payload.extra_config();

        // Generate decryption nonce
        let decryption_nonce: DecryptionNonce = rand::random();

        // Create DecryptedPayload for encryption
        let decrypted_payload = DecryptedPlaintext::new(executable, decryption_nonce);

        let associated_data = PayloadAssociatedData::new(sender, signer_auth_keys);

        // Encrypt the payload
        // Note: FPTXWeighted::encrypt requires CryptoRng from ark_std::rand, so we use StdRng
        let mut rng = StdRng::from_entropy();
        let ciphertext = FPTXWeighted::encrypt(
            encryption_key,
            &mut rng,
            &decrypted_payload,
            &associated_data,
        )?;

        // Compute payload hash from the executable
        // We need to compute hash before encryption, so we use the executable directly
        let payload_hash = CryptoHash::hash(&decrypted_payload);

        // Create encrypted payload
        Ok(EncryptedPayload::Encrypted(EncryptedInner {
            ciphertext,
            extra_config,
            payload_hash,
            encryption_epoch,
            claimed_entry_fun: None,
        }))
    }
