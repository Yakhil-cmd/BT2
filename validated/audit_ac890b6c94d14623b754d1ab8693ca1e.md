### Title
Unfiltered `GIT_SSH_COMMAND` injection via pull request label reaches `Command#start` for review-stack task/deploy steps (including `dependencies.override`) - ([File: app/models/shipit/review_stack.rb])

### Summary
`ReviewStack#env` merges every pull request label name (uppercased) directly into the stack's environment hash with no key allowlist, and this hash is unconditionally merged into `TaskCommands#env`/`StackCommands#env`, which is passed straight to `Command.new(..., env:)` and ultimately into `PTY.spawn` via `Command#unbundled_env`. An unprivileged fork PR author who can label their own PR (e.g. with a label literally named `git_ssh_command`) can therefore inject an arbitrary `GIT_SSH_COMMAND` into every subprocess Shipit spawns for that review stack, including the `dependencies.override`/`dependencies` steps and the stack's own git fetch/clone, letting them substitute the ssh binary git invokes.

### Finding Description
The broken binding: the env reaching `Command#start`/`PTY.spawn` for a review stack's steps should equal `{ base whitelisted keys } ∪ EnvironmentVariables.with(user_env).permit(variable_definitions)`, i.e. `GIT_SSH_COMMAND ∉ keys(final_env)`. In practice it does not hold.

Code path:
- `ReviewStack#env` [1](#0-0)  merges `pull_request.labels.each_with_object({}) { |n,h| h[n.upcase] = "true" }` into the stack env with **no allowlist**.
- `LabelCapturingHandler#capture_labels` persists label names verbatim from the webhook payload with only a `requires :name, String` schema check (no format/charset restriction, unicode/emoji even explicitly allowed per test) [2](#0-1) .
- `StackCommands#env` unconditionally merges `@stack.env` [3](#0-2) , and `TaskCommands#env` does the same [4](#0-3) , with no call to `EnvironmentVariables#permit` anywhere in this chain (unlike the `deploy.variables`/`rollback.variables`/task-variable paths, which are explicitly whitelisted via `filter_deploy_envs`/`filter_rollback_envs`/`TaskDefinition#filter_envs` and `EnvironmentVariables#permit` [5](#0-4) ).
- `TaskCommands#install_dependencies` builds the `dependencies.override` step commands from `deploy_spec.dependencies_steps!` [6](#0-5)  and passes the tainted `env:` straight to `Command.new` [7](#0-6) .
- `Command#unbundled_env` merges `@env.stringify_keys` (the tainted hash) on top of `BASE_ENV`/`PATH`, and `Command#start` passes this directly to `PTY.spawn` [8](#0-7) .

Exploit flow: an attacker opens/labels a PR from their own fork on a repository configured with `provisioning_behavior=allow_with_label` (using the required provisioning label to get a `ReviewStack` created, per `OpenedHandler`/`LabeledHandler`), then also applies a second label literally named `git_ssh_command` (case-insensitive, since it's upcased). GitHub emits `pull_request` `labeled` webhooks, `LabelCapturingHandler` persists `["provisioning-label", "git_ssh_command"]` into `PullRequest#labels`, and every subsequent `ReviewStack#env` call yields `"GIT_SSH_COMMAND" => "true"`. If the attacker instead crafts the label as an actual shell command path (GitHub label names allow arbitrary UTF‑8 text, confirmed by the emoji test `"Shipit 🚢"` [9](#0-8) ), that value becomes the literal `GIT_SSH_COMMAND` environment value inherited by any git invocation during `dependencies.override` steps or the stack's own `fetch`/`git_clone` commands run through `StackCommands` (which also merges `@stack.env`) [10](#0-9) .

Existing tests already document the unfiltered merge behavior as intended functionality (`ReviewStackTest#env includes the stack's pull request labels`, `DeployCommandsTest`, `TaskCommandsTest`) [11](#0-10) , confirming there is no guard rejecting or filtering dangerous keys like `GIT_SSH_COMMAND`, `LD_PRELOAD`, `BUNDLE_GEMFILE`, `PATH`, etc.

None of the existing guards apply here: `verify_signature`/`GitHubApp#verify_webhook_signature` only authenticate that the webhook came from GitHub for the given repo (an attacker's own fork repo emits legitimately-signed webhooks for their own PR), `ExplicitParameters` only validates presence/type of `name: String`, and `EnvironmentVariables#permit` is never invoked on `@stack.env`/label-derived env — it's only applied to the separate, explicitly user-submitted `deploy`/`rollback`/`task` variable hashes coming from controller params.

### Impact Explanation
This allows an unprivileged fork PR author to have `GIT_SSH_COMMAND` (or any other env var, since there is no allowlist) injected into every subprocess spawned for their own review stack — `dependencies.override` steps, the stack's `deploy`/`task` steps, and the underlying `git fetch`/`git clone` operations run by `StackCommands`. If any of these operations use an `ssh://`/`git@`-style remote (e.g., a private git-sourced gem dependency, or the stack's own git remote configured over ssh), git will invoke the attacker-controlled command instead of `ssh`, achieving Remote Code Execution on the Shipit deploy host under the Shipit process's privileges — this is repeatable on every deploy/task run of that review stack, and scoped to whichever repository the attacker can open a PR against with `allow_with_label` enabled. This matches the Critical "RCE on the deploy host via `Command`/`PTY.spawn`" impact category.

### Likelihood Explanation
Preconditions: the target repository must have `review_stacks_enabled` and `provisioning_behavior=allow_with_label` (or `allow_all`, which needs no label at all) so a `ReviewStack` gets created/kept active for the attacker's PR. No Shipit session, API token, or GitHub App secret is required — the attacker only needs to open a PR from their own fork and apply labels to it, both of which are ordinary unprivileged GitHub actions on a repo they can fork. This is low-cost and fully repeatable/scriptable against any repo using this provisioning mode.

### Recommendation
Do not merge raw, attacker-controlled pull request label names into the process environment unfiltered. Either: (1) drop the label→env feature entirely, or (2) apply an explicit allowlist (e.g., via `EnvironmentVariables#permit` against a fixed set of safe key names configured by the repo maintainer, not the PR author) before merging label-derived keys into `ReviewStack#env`, and (3) additionally block/strip well-known dangerous env keys (`GIT_SSH_COMMAND`, `LD_PRELOAD`, `BUNDLE_GEMFILE`, `PATH`, `GIT_*`, `RUBYOPT`, etc.) anywhere untrusted input feeds into `Command`'s `env:`.

### Proof of Concept
```ruby
# test/models/shipit/review_stack_test.rb (or a new minitest)
test "[allow_with_label] GIT_SSH_COMMAND injected via PR label reaches dependencies.override env" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ["git_ssh_command"]

  # Binding under test: GIT_SSH_COMMAND should NOT be present in the merged env
  refute stack.env.key?("GIT_SSH_COMMAND"), "expected label-derived env to be filtered"
end

test "[allow_with_label] dependencies.override step process env contains attacker-controlled GIT_SSH_COMMAND" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.labels = ["git_ssh_command"]
  task = shipit_tasks(:shipit_restart)
  task.stack = stack

  commands = Shipit::TaskCommands.new(task)
  command = commands.install_dependencies.first

  # This currently PASSES, proving the vulnerability: the tainted key reaches Command#env
  # and therefore Command#unbundled_env / PTY.spawn.
  assert_equal "true", command.env["GIT_SSH_COMMAND"]
end
```
Both assertions demonstrate the equality violation: `GIT_SSH_COMMAND` is expected to be absent from the env reaching `Command#start`, but the current code path (`ReviewStack#env` → `TaskCommands#env` → `Command.new(env:)` → `Command#unbundled_env`) places it there unconditionally whenever the label exists.

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end

    def unbundled_env
      BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)
    end
