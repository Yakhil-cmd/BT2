### Title
`min-ustx-for-sats-amount` double truncating division can floor the required STX collateral to zero for a protocol bond - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`min-ustx-for-sats-amount` computes the minimum uSTX a staker must lock to back a given amount of custodied sBTC for a protocol bond. It performs two sequential truncating integer divisions instead of a single combined division, which is exactly the "successive rounding-to-zero" pattern described in the Ethos report for `P`. For small-enough `sats-amount`/ratio combinations the intermediate result truncates to `0` before the final multiply, making the computed minimum floor `0` regardless of `min-ustx-ratio`, and `register-for-bond` accepts `amount-ustx = 0` as satisfying the requirement.

### Finding Description
`min-ustx-for-sats-amount` is defined as: [1](#0-0) 

```
(define-read-only (min-ustx-for-sats-amount
        (sats-amount uint)
        (stx-value-ratio uint)
        (min-ustx-ratio uint)
    )
    (/ (* (/ (* stx-value-ratio sats-amount) u100) min-ustx-ratio) u10000)
)
```

This is `(( (stx-value-ratio * sats-amount) / 100 ) * min-ustx-ratio) / 10000`. The inner division `(* stx-value-ratio sats-amount) / u100` truncates before the outer multiplication by `min-ustx-ratio`. Whenever `stx-value-ratio * sats-amount < 100`, this inner term truncates to `0`, and the whole expression evaluates to `0` no matter how large `min-ustx-ratio` is intended to be. This mirrors the Ethos `P` bug: a rounding-toward-zero step happens *before* the value that should offset it (the multiply by `min-ustx-ratio`) is applied, so precision is destroyed rather than merely reduced.

This function is the sole gate used in `register-for-bond` to enforce that a staker locks STX proportional to the sBTC (`sats-total`) they custody for a bond: [2](#0-1) 

```
;; Verify that they're sending enough STX
(asserts!
    (>= amount-ustx
        (min-ustx-for-sats-amount sats-total (get stx-value-ratio bond)
            (get min-ustx-ratio bond)
        ))
    ERR_INSUFFICIENT_STX
)
```

There is no other floor check on `amount-ustx` in `register-for-bond` (only `total-balance >= amount-ustx`, which is trivially true for `amount-ustx = 0`). If the computed floor is `0`, a staker can pass `amount-ustx = 0` and still register: the bond membership, the sBTC shares (`sats-total`), and the signer delegation for that bond are all recorded with zero uSTX actually required to be locked to satisfy the STX-collateral check.

### Impact Explanation
The `min-ustx-ratio` parameter is the protocol's mechanism for requiring stakers to co-lock STX in proportion to their custodied sBTC when joining a bond. Truncating this floor to zero breaks that intended equality: a staker's bond membership (sats-total counted into `protocol-bonds-total-staked`/per-cycle shares and signer delegation) can be established while contributing STX collateral below the value the bond parameters (`stx-value-ratio`, `min-ustx-ratio`) were configured to require — down to zero. This is a "signing weight/reward slots exceeding locked [STX] value" condition (a High-impact class per the rules), since the sBTC-side shares and signer delegation are granted without the matching STX ever being validated to be non-zero.

### Likelihood Explanation
The sBTC path of `register-for-bond` lets the caller choose `sbtc-amount` (`sats-total`) directly (the `(err sbtc-amount)` branch of `btc-lockup`), so an allow-listed staker fully controls `sats-total`. Any bond configured with `stx-value-ratio * sats-amount < 100` for the staker's chosen sats amount (which is easy to hit for small `sats-amount` or a `stx-value-ratio` on the order of 1–99) triggers the zero-floor. This does not require any privileged role beyond being on the bond's allowlist (an unprivileged, permitted staker action), and the bond's own configured `min-ustx-ratio`/`stx-value-ratio` are set by the bond admin for legitimate reasons unrelated to this truncation defect, so ordinary bond parameters combined with a small enough `sats-amount` choice by the staker are sufficient to trigger it.

### Recommendation
Combine the divisions into a single computation that only truncates once, e.g. compute the numerator fully before any division: `(/ (* stx-value-ratio sats-amount min-ustx-ratio) (* u100 u10000))`, or otherwise ensure the intermediate division cannot zero out a nonzero final result (e.g., round up on the inner division, or reorder operations so multiplication by `min-ustx-ratio` happens before dividing by `u100`). Additionally, consider enforcing an absolute minimum non-zero floor (independent of the ratio math) for any `sats-total > 0`.

### Proof of Concept
1. Bond is set up (via `setup-bond`) with `stx-value-ratio = 50` and `min-ustx-ratio = 1000` (10%), consistent with normal bond configuration.
2. An allow-listed staker calls `register-for-bond` with the sBTC path, choosing `sats-total = 1` (1 satoshi), well within any reasonable `max-sats` allowance.
3. `min-ustx-for-sats-amount(1, 50, 1000)` = `(/(* (/(* 50 1) 100) 1000) 10000)` = `(/(* 0 1000) 10000)` = `0`.
4. The assertion `(>= amount-ustx 0)` at [3](#0-2)  passes with `amount-ustx = 0`.
5. The staker's `sats-total = 1` is added to `protocol-bonds-total-staked` and per-cycle staker/signer shares, and the signer receives the corresponding delegation record, all while the staker locked `0` uSTX — violating the intended STX/sBTC co-collateralization ratio enforced by `min-ustx-ratio`.
