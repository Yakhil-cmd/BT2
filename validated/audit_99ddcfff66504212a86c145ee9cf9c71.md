This confirms `with_locked_state` locks only per-call (each callback is a separate short-lived flock transaction), not across the entire Stop-hook execution. This means `consume_stop_state`'s clear of `touched_paths` and `restore_unreviewed_stop_state`'s later re-write are two distinct lock windows, leaving a race window open between them during which a concurrent `UserPromptSubmit` (a normal, attacker-reachable git/session action — simply submitting the next turn) can run and advance `baseline_sha`.

### Title
Stop-hook baseline advances past unreviewed dangerous edits during UPS race, causing them to be permanently skipped from security review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`restore_unreviewed_stop_state` is meant to keep the "unreviewed edit" guard armed when the Stop hook exits early for a transient reason, but its baseline-restore is conditioned on `not state.get("baseline_sha")`. Because `consume_stop_state` clears `touched_paths` in an earlier, separate lock transaction than the later `restore_unreviewed_stop_state` call, a concurrent `UserPromptSubmit` for the next turn can observe an empty `touched_paths` list, conclude there is nothing to preserve, and overwrite `baseline_sha` with a fresh `git stash create` snapshot that already contains the unreviewed dangerous edit. When Stop's restore later runs, it silently declines to fix the now-stale reference because a `baseline_sha` is already present, permanently binding the review baseline to a snapshot that already includes the vulnerable code.

### Finding Description
The vulnerable sequence is:

1. `handle_stop_hook` calls `consume_stop_state` [1](#0-0) , which under its own lock transaction reads `touched_paths`/`baseline_sha` and immediately clears `touched_paths` to `[]` on disk [2](#0-1) .
2. Stop then does slow work — network reachability check, HTTP/LLM calls — before it ever calls `restore_unreviewed_stop_state` on a transient-failure path (`_skip(10, restore=True)` for unreachable API, or the HTTP-error branch after "no security issues found") [3](#0-2) [4](#0-3) .
3. Because Stop runs asynchronously in the background ("asyncRewake"), the user/agent can submit the next turn's `UserPromptSubmit` (`handle_user_prompt_submit`) during this window [5](#0-4) . Its `_save` callback only preserves the old baseline when `state.get("touched_paths")` is truthy [6](#0-5) . Since step 1 already cleared it to `[]`, the preservation guard does not trigger, and UPS overwrites `baseline_sha` with a brand-new `git stash create` snapshot of the current working tree — which already contains the dangerous, still-unreviewed edit.
4. Stop finally calls `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` [7](#0-6) . Its guard `if baseline_sha and not state.get("baseline_sha")` at line 135 sees a `baseline_sha` already present (the one just written by the racing UPS) and refuses to restore the old one, permanently discarding the pointer to the pre-edit baseline.
5. `touched_paths` gets merged back in, but this list is never consumed by `compute_v2_review_set` — the review set is computed purely from git-diff comparisons against `baseline_sha`/`head_at_capture` [8](#0-7) . On the next Stop fire, `changed_since = _git_name_only(repo, baseline_sha)` diffs against the new baseline, which already matches the dangerous file's on-disk content, so the file no longer appears "changed since baseline" and is excluded from `review_set` even though it is still substantively unreviewed. `touched_paths` restoration is therefore cosmetic/metrics-only and does not actually re-arm review.

This breaks exactly the stated invariant — the review set silently unbinds from the correct baseline, and a dangerous change is treated as "old" and skipped.

### Impact Explanation
A security-relevant code edit that Claude made (e.g., introducing a command-injection or hardcoded-secret pattern) can permanently escape the Stop-hook LLM review after a transient API/network hiccup coincides with the next-turn prompt — a routine occurrence in longer or automated multi-turn sessions. This is a logic-level bypass of a required security guard (the plugin's core Stop-hook enforcement), matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state."

### Likelihood Explanation
No special privilege is required — only ordinary use of Claude Code: a turn that edits a file, a transient Anthropic API error/unreachability (common in real deployments, proxies, or flaky networks), and the user/agent proceeding to the next turn before Stop's background hook finishes. All components involved (`consume_stop_state`, `handle_user_prompt_submit`, `restore_unreviewed_stop_state`) run automatically as part of normal hook flow, so the race is realistically triggerable, if timing-dependent (the window is bounded by the reachability-check/LLM-call latency in Stop before it reaches the restore call).

### Recommendation
Make the "preserve baseline" decision race-safe: instead of gating on `touched_paths` in `handle_user_prompt_submit`, use a single atomic transaction that Stop marks (e.g., a "stop_in_flight"/"awaiting_restore" flag set at the start of `consume_stop_state` and cleared only after `restore_unreviewed_stop_state`/final success), and have UPS refuse to advance `baseline_sha` while that flag is set. Alternatively, have `restore_unreviewed_stop_state` unconditionally restore `baseline_sha` to `snap_baseline` whenever it is invoked (not only when the current one is empty), since restoring is only ever called on a "this turn was not actually reviewed" path and no newer baseline should be considered authoritative over it.

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```

```python
def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
    if not isinstance(untracked_at_baseline, dict):
        untracked_at_baseline = {}

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```
