### Title
Unvalidated `no_seize` collateral lets a borrower permanently block their own liquidation — ([File: contracts/controller/src/positions/liquidation/plan.rs](contracts/controller/src/positions/liquidation/plan.rs))

### Summary

The analog of CVE-2016-4476 (unvalidated input that should have been rejected causes a denial of service) maps onto the spoke-asset halt flags. Entry validation (`paused`/`frozen`) and seizure validation (`no_seize`) are split: `no_seize` does not gate `supply`, so an unprivileged borrower can deposit a dust amount of a `no_seize`-flagged asset into a leveraged account. Because liquidation is strictly pro-rata across **all** supply positions and the liquidator cannot select a collateral subset, any nonzero `no_seize` leg makes `build_liquidation_plan` revert on every possible `liquidate` call. The account becomes permanently unliquidatable, and its debt can only be resolved as socialized bad debt written down against suppliers.

### Finding Description

`enforce_spoke_asset_flags` with `FreezePolicy::SeizureLeg` is invoked for every planned seizure leg inside `build_liquidation_plan` (`contracts/controller/src/positions/liquidation/plan.rs:81-89`), after `calculate_seized_collateral` has produced a proportional leg for every nonzero supply position. There is no way to exclude a collateral asset from the plan — the repayment/seizure coupling (INV-LIQ-02) forces pro-rata coverage of the whole collateral set. This is confirmed in `docs/reference/invariants.md` INV-HALT-02: *"Nonzero `no_seize` collateral can block the whole proportional liquidation, even if supplied after the flag is set."*

Meanwhile the entry side uses `FreezePolicy::AllowOnExit`/entry policy, which rejects only `paused` and `frozen` (endpoints doc: *"Seizure checks only `no_seize`"*; supply is not restricted by `no_seize`). So the protocol accepts a class of input — collateral that can never be seized — and records it as valid risk-bearing collateral, stamping its LTV/LT and letting it back borrows.

Attack path for a single unprivileged address:

1. Observe a hub asset whose spoke listing has `no_seize = true` (set for e.g. a delisting/regulatory halt). Entry is still allowed.
2. `supply(caller, 0, spoke_id, [(borrow_asset, X)])` to open an account, `borrow(...)` near the LTV limit.
3. `supply(caller, account_id, spoke_id, [(no_seize_asset, dust)])` — one extra position, any nonzero amount.
4. Every subsequent `liquidate(liquidator, account_id, payments, mode)` — Transfer or Credit — builds a plan containing the `no_seize` leg and reverts with `SpokeAssetSeizureHalted` before any token moves (`plan.rs:81-89`).
5. The account's debt accrues unboundedly until it is insolvent and under the $5 dust collateral gate, at which point `clean_bad_debt` (which bypasses listing flags per INV-LIQ-04) writes the debt down into the supply index — a realized loss to all suppliers of the debt markets.

### Impact Explanation

Permanent freezing of liquidation → protocol insolvency. The borrower escapes all liquidation risk for the cost of a dust deposit of an already-halted asset; interest accrues and the shortfall is eventually socialized into the supply index (`SUPPLY_INDEX_FLOOR_RAW`-bounded write-down), directly impairing every supplier of the borrowed market. `clean_bad_debt` only admits accounts whose remaining collateral ≤ $5, so a mid-size position can sit unliquidatable while bleeding index value for an arbitrary duration — no final solvency assertion exists after liquidation/cleanup (INV-LIQ-04 tail: "The index floor can leave a shortfall").

### Likelihood Explanation

Requires a market to carry `no_seize = true` while still accepting supply — precisely the transitional state the flag is designed for (halting seizure without freezing exits). The attacker needs only a funded address and two permissionless calls; no price manipulation, no privileged action, no race. Any borrower — including ones who become underwater for unrelated reasons — can add the dust leg at any time, including *after* governance sets the flag, since INV-HALT-02 explicitly covers collateral "supplied after the flag is set." Severity is bounded below Critical/High by the precondition that a `no_seize` listing exists, but that is exactly when unliquidatable accounts are most dangerous.

### Recommendation

Treat `no_seize` collateral as an invalid input at entry, the same way `paused`/`frozen` are: in `enforce_spoke_asset_flags`/`merge_supply_leg`, reject new supply into a `no_seize` listing (and reject it as a Credit liquidation receiver asset). Alternatively, permit seizure legs to be dropped from the plan when flagged and reprice the seizure over the remaining collateral — but the entry rejection is the minimal fix matching the flag's intent, since collateral that can never be seized contributes no liquidation value and should not back borrows anyway.

### Proof of Concept

Conceptual sequence against the harness (`LendingTest`):

```rust
// market "NS" listed with no_seize = true, entry still allowed
// market "D" borrowable
t.supply(ALICE, "D_collateral", 10_000.0);           // normal collateral
t.borrow(ALICE, "D", 3.0);                            // levered at limit
t.supply(ALICE, "NS", 0.000_001);                     // dust, nonzero
t.set_price("D_collateral", usd_cents(50));           // HF < 1
let res = t.try_liquidate_with_mode(LIQUIDATOR, ALICE, "D", 1.0, SeizeMode::Transfer);
assert_contract_error(res, errors::SPOKE_ASSET_SEIZURE_HALTED); // every offer reverts
let res2 = t.try_liquidate_with_mode(LIQUIDATOR, ALICE, "D", 1.0, SeizeMode::Credit(0));
assert_contract_error(res2, errors::SPOKE_ASSET_SEIZURE_HALTED); // Credit too
// Alice's debt accrues; only clean_bad_debt (dust-gated, flag-bypassing)
// can ever clear it, socializing the loss into the supply index.
```

Supporting code: `contracts/controller/src/positions/liquidation/plan.rs:81-89` (per-leg `SeizureLeg` enforcement over the whole collateral set), `docs/reference/invariants.md` INV-HALT-02 ("Nonzero `no_seize` collateral can block the whole proportional liquidation, even if supplied after the flag is set"), `contracts/controller/src/lib.rs:163-200` (permissionless, flag-bypassing `clean_bad_debt` as the only fallback).
