### Title
Path traversal in `gh release download` via unsanitized release asset name allows writes outside destination directory - (File: pkg/cmd/release/download/download.go)

### Summary
`destinationWriter.makePath` builds the output path with a plain `filepath.Join(w.dir, name)` where `name` is the attacker-controlled `shared.ReleaseAsset.Name` returned from the GitHub API for a release the attacker fully controls. Unlike other download paths in this codebase (`internal/zip/zip.go`, `pkg/cmd/run/download`) which use `internal/safepaths.Absolute.Join` to reject path traversal, this writer performs no traversal check, so an asset named e.g. `../../.bashrc` can escape `w.dir`.

### Finding Description
The call chain is `downloadRun` → `downloadAssets`/`downloadAsset` → `dest.Check(fileName)` / `dest.Copy(fileName, body)`, where `fileName` comes directly from `a.Name` for each `shared.ReleaseAsset` in `release.Assets` [1](#0-0) . `destinationWriter.makePath` joins this untrusted name with the destination directory using `filepath.Join(w.dir, name)` with no traversal or `filepath.Base` sanitization [2](#0-1) . Both `Check` and `Copy` operate on this unsanitized `fp` [3](#0-2) .

This is inconsistent with the rest of the codebase: `internal/safepaths.Absolute.Join` explicitly guards against this class of bug by rejecting joins whose relative path begins with `..` [4](#0-3) , and that type is used by other download code paths (`internal/zip/zip.go`, `pkg/cmd/run/download/download.go`), but `pkg/cmd/release/download/download.go` never uses `safepaths.Absolute` for asset names, confirming the gap.

Because `shared.ReleaseAsset.Name` is populated straight from the GitHub API release-assets response for the release/repo the victim points `gh` at, an attacker who owns that repo can name an asset anything they like, including `../../<target>`. A victim running `gh release download` against the attacker's release/tag with no `--pattern`/`--archive` filter (or a matching pattern) will have that asset's filename passed unmodified into `makePath`.

Regarding the TOCTOU/symlink-following variant proposed in the question: `check()` calls `os.Stat` and refuses to proceed if the target already exists (unless `--clobber`) [5](#0-4) , and `Copy` reuses `check(fp)` before `os.OpenFile(fp, O_WRONLY|O_CREATE|O_TRUNC, ...)` [6](#0-5) . Exploiting this race by "pre-planting a symlink" requires the attacker to already have a filesystem foothold on the victim's machine to create the symlink before the run, which is out of scope per the stated threat model (no local access). A remote, unprivileged GitHub attacker who only controls the release asset's `Name` field cannot create an actual symlink node on the victim's disk through this HTTP-download code path — a written asset is always a regular file's byte content, never a filesystem symlink object. So the symlink-race portion of the question is not a viable remote-attacker path and is rejected; only the plain path-traversal issue is valid.

### Impact Explanation
A malicious release/repo owner can craft an asset name containing `../` segments so that, when a victim runs `gh release download` against that release, the downloaded content is written to an arbitrary path outside the intended `--dir`/current directory (e.g., overwriting or creating files reachable by traversal, limited by the OS user's file permissions and by `check()`'s existing-file/`--clobber` guard for files that already exist). This matches an arbitrary file write / path-confinement-bypass class impact, but is capped by: (1) `check()` refusing to touch already-existing files unless `--clobber` is passed, so overwriting fixed sensitive files that already exist (e.g., `.bashrc`) additionally requires the victim to add `--clobber`, and (2) it cannot achieve symlink-following escalation since no local access is assumed.

### Likelihood Explanation
Preconditions: the victim must run `gh release download` (with no `--pattern`, or a pattern the traversal filename satisfies) against a release/tag on a repository controlled by the attacker (their own repo, or a fork/PR the victim is lured into using with `-R`). This is fully attacker-controlled and requires no privileges beyond publishing a release on their own repository, and is repeatable/deterministic — no race condition is required for the pure traversal-write case (writing new files outside the tree). The additional impact of overwriting a pre-existing file requires the victim to also pass `--clobber`, reducing but not eliminating likelihood.

### Recommendation
Sanitize/validate `name` in `destinationWriter.makePath` (and `Check`) before joining, e.g. reject or strip path separators via `filepath.Base(name)`, or adopt `internal/safepaths.Absolute.Join(w.dir, name)` (as already used in `internal/zip/zip.go` and `pkg/cmd/run/download`) so that any join resolving outside `w.dir` returns a `PathTraversalError` instead of silently escaping.

### Proof of Concept
Go test (in `pkg/cmd/release/download`) using `httpmock` to serve a release whose asset has `Name: "../../evil"`:

```go
func TestDownloadRun_AssetNameTraversal(t *testing.T) {
    tempDir := t.TempDir()
    destDir := filepath.Join(tempDir, "dest")
    os.MkdirAll(destDir, 0755)

    reg := &httpmock.Registry{}
    // stub release fetch returning an asset with Name "../../evil"
    reg.Register(
        httpmock.REST("GET", "repos/OWNER/REPO/releases/tags/v1.0.0"),
        httpmock.JSONResponse(map[string]interface{}{
            "tag_name": "v1.0.0",
            "assets": []map[string]interface{}{
                {"name": "../../evil", "url": "https://api.github.com/assets/1"},
            },
        }),
    )
    reg.Register(
        httpmock.REST("GET", "assets/1"),
        httpmock.StringResponse("PWNED"),
    )

    opts := &DownloadOptions{
        HttpClient: func() (*http.Client, error) { return &http.Client{Transport: reg}, nil },
        BaseRepo:   func() (ghrepo.Interface, error) { return ghrepo.New("OWNER", "REPO"), nil },
        Destination: destDir,
        TagName:    "v1.0.0",
        Concurrency: 1,
        IO: iostreams.Test(),
    }

    err := downloadRun(opts)
    require.NoError(t, err)

    // Expect the file to be written INSIDE destDir; assert it is NOT written
    // two levels above destDir (i.e., at tempDir/evil), which is the traversal target.
    escapedPath := filepath.Join(tempDir, "evil")
    _, statErr := os.Stat(escapedPath)
    require.NoError(t, statErr, "expected traversal write to escape destDir, demonstrating the vulnerability")
}
```

Expected result on the current code: `os.Stat(escapedPath)` succeeds because `filepath.Join(destDir, "../../evil")` resolves to `tempDir/evil`, confirming the write escaped the intended `--dir`. After applying the fix (using `safepaths.Absolute.Join`), `downloadRun` should instead return a `PathTraversalError` and no file should be created outside `destDir`.

```go
// Check returns an error if a file already exists at destination
func (w destinationWriter) Check(name string) error {
	if name == "" {
		// skip check as file name will only be known after the API request
		return nil
	}
	fp := w.makePath(name)
	if fp == "-" {
		// writing to stdout should always proceed
		return nil
	}
	return w.check(fp)
}

func (w destinationWriter) check(fp string) error {
	if _, err := os.Stat(fp); err == nil {
		if w.skipExisting {
			return errSkipped
		}
		if !w.overwrite {
			return fmt.Errorf(
				"%s already exists (use `--clobber` to overwrite file or `--skip-existing` to skip file)",
				fp,
			)
		}
	}
	return nil
}

// Copy writes the data from r into a file specified by name.
func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
```

```go
// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}

func (a Absolute) isSubpathOf(dir Absolute) (bool, error) {
	relativePath, err := filepath.Rel(dir.path, a.path)
	if err != nil {
		return false, err
	}
	return !strings.HasPrefix(relativePath, ".."), nil
}
```
