### Title
Webhook signature verification authenticates the sender's organization, but downstream handlers trust an unrelated `repository.full_name` field to select which repo/stack is written to - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit supports multi-tenant GitHub App configuration, where each GitHub organization has its own `webhook_secret` [1](#0-0) . `WebhooksController#verify_signature` selects which organization's secret to verify the HMAC signature against using `repository.owner.login` (falling back to `organization.login`) taken from the unauthenticated JSON body, *before* the signature has been checked [2](#0-1) . Once the signature passes for that organization, the event handlers (e.g. `PushHandler`, `Handler#repository_name`, the various `PullRequest` handlers) resolve the *actual* repository/stack to act on using a different, unchecked field: `repository.full_name` [3](#0-2) [4](#0-3) .

### Finding Description
The signature check and the repository/stack resolution use two different, independently-attacker-controlled fields from the same unsigned-until-verified JSON payload:

- `verify_signature` picks the org whose secret to verify against via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [5](#0-4) .
- The actual event processing looks up the target `Repository`/`Stack` via `payload.dig('repository', 'full_name')` (`Handler#repository_name`, used by `stacks`) [3](#0-2) , or `params.repository.full_name` in the `PullRequest` handlers [6](#0-5) .

Nothing in the code enforces that `repository.owner.login` (the field used for cryptographic authentication) is a prefix of, or otherwise consistent with, `repository.full_name` (the field used to decide which repository record is mutated). An attacker who legitimately controls a GitHub organization/webhook secret configured in Shipit (e.g. their own onboarded org in a multi-tenant deployment) can sign a payload with their own valid `webhook_secret`, set `repository.owner.login` to their own org login (so `verify_webhook_signature` succeeds against their own secret), but set `repository.full_name` to `"victim-org/victim-repo"`. `verify_signature` only calls `head(422)` without halting the action when verification fails/succeeds correctly for their own org - and since it succeeds (their own valid signature), the request proceeds. The handler then acts on the victim's repository using the `full_name` field, which was never covered by the signature check that gated processing.

This breaks the binding: *the organization that authenticated (via HMAC) ≠ the repository that is written (via `full_name`)*.

### Impact Explanation
Depending on event type this can drive unauthorized writes into a victim stack that the attacker has no GitHub access to: `push` events trigger `stack.sync_github(expected_head_sha: ...)` [7](#0-6) , `pull_request` events can create/archive review stacks and mutate `PullRequest` records for the victim repo [8](#0-7) [9](#0-8) . This matches "cross-repository writes" from an unprivileged party who only controls a different, unrelated organization's webhook credentials.

### Likelihood Explanation
This requires Shipit to be configured for multiple GitHub organizations (each with its own `webhook_secret`) and requires the attacker to control (or compromise) one legitimate organization's webhook secret slot in that multi-tenant configuration - a scenario the engine explicitly supports (`github_app_config`, `github_organizations`) [10](#0-9) . I could not fully confirm, within the available index, whether every downstream handler additionally validates `owner.login` against `full_name` somewhere else in the pipeline (e.g. in `Repository.from_github_repo_name` or model-level checks) — this would need to be verified against the full handler set and `Repository` model before treating this as conclusively exploitable end-to-end.

### Recommendation
In `WebhooksController#verify_signature`, cross-check that `repository.full_name` (or `organization.login` for org-level events) is consistent with the organization whose secret validated the signature (e.g. `repository.full_name.split('/').first.casecmp(repository_owner)`), and reject with 422 otherwise. Alternatively, resolve the target repository/stack strictly from the same organization field that gated signature verification, rather than trusting `full_name` independently in every handler.

### Proof of Concept
1. Configure Shipit with two GitHub orgs, `attacker-org` (attacker's own, with a known `webhook_secret`) and `victim-org` (unrelated, tracked by Shipit).
2. Craft a `push` webhook payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Sign the raw body with `attacker-org`'s known `webhook_secret` and send it as `X-Hub-Signature`, with `X-Github-Event: push`.
4. `verify_signature` resolves `Shipit.github(organization: "attacker-org")` and validates successfully (attacker-controlled secret) [11](#0-10) .
5. `PushHandler#process` resolves stacks via `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `sync_github` on the victim's stacks [7](#0-6) , despite the request never being authenticated against `victim-org`'s credentials.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
