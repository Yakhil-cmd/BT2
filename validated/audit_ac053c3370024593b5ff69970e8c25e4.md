## Finding: PSM pallet assumes external stablecoins maintain 1:1 peg with no price/depeg check

This is a demonstrable Polkadot SDK analog to the original report. The original bug is about a protocol pricing USDC as always worth exactly 1 USD (via Chainlink USD-feed) with no depeg check, letting an attacker exploit cheap/depegged USDC as if it were full-value collateral. The polkadot-sdk repo contains a newly-added `pallet-psm` (Peg Stability Module) that has the exact same root-cause pattern: it swaps an internal stablecoin against approved external stablecoins (explicitly named USDC/USDT in its own docs) strictly 1:1 by decimal-scaling, with **no oracle or market-price check** that the external asset is actually still worth $1.

### Title
PSM pallet mints internal stablecoin 1:1 against external stablecoins with no depeg check, allowing devalued collateral to be treated as full par value - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet_psm::Pallet::mint` converts a user-supplied amount of an approved external asset (e.g. USDC) into the internal stablecoin purely via decimal rescaling (`external_to_internal`), never checking whether the external asset is trading at its intended $1 value. [1](#0-0) 

### Finding Description
The pallet's own documentation states the PSM performs "1:1 swaps" between the internal stablecoin and pre-approved externals such as USDC/USDT, with the peg maintained purely through arbitrage incentives created by mint/redemption fees — not by any live price validation. [2](#0-1) [3](#0-2) 

Any signed account can call `mint` for an approved `external_asset`, and the only checks performed are: the per-external circuit breaker status, decimals-based conversion (`external_to_internal`/`internal_to_external`), minimum swap amount, fee cap, and aggregate/per-asset debt ceilings — there is no check against a real-time price feed or DEX/oracle price for the external asset. [4](#0-3) 

The circuit breaker (`AssetStatus`) that could halt minting for a depegging asset is a purely manual, governance-triggered control (`set_asset_status`, callable by `Full`/`Emergency` admin origins per the README), not an automatic response to a depeg event: [5](#0-4) 

This exactly mirrors the reported vulnerability class: the protocol hard-codes the assumption that an external stablecoin (USDC) always equals $1, and provides no mechanism to detect or react to a depeg before economic damage occurs.

### Impact Explanation
If the external asset (e.g. USDC) depegs below $1, an attacker can buy the devalued external asset cheaply on the open market and mint the internal stablecoin (pUSD) at full 1:1 nominal value through `mint`, extracting the difference at the expense of the PSM's solvency/backing ratio and diluting the value backing all outstanding internal-stablecoin holders, since `PsmDebt` records the mint as fully-backed 1:1 debt regardless of the external asset's real market value. [6](#0-5) 
The redeemable value of the internal stablecoin is only as strong as its weakest approved external asset at any given moment — nothing in the mint path checks this.

### Likelihood Explanation
No privileged role is required; `mint`/`redeem` require only `ensure_signed`, meaning any attacker-controlled account can act the moment an approved external asset (e.g. a real-world stablecoin like USDC or USDT) experiences even a temporary depeg, as historically demonstrated in the cited March 2023 USDC depeg event referenced by the original report. [7](#0-6) 

### Recommendation
Integrate a price-sanity check (oracle-based band, or automatic circuit-breaker trip on detected depeg) into the `mint` path before crediting internal-asset value 1:1 for an external deposit, or otherwise document/bound this as an accepted governance-monitored risk with fast-response tooling, since currently the only mitigant is manual governance intervention via `set_asset_status`.

### Proof of Concept
No PoC was executed. This is a design-level analysis based on reading `mint`/`redeem` and the circuit-breaker logic in `substrate/frame/psm/src/lib.rs`; no automated price/oracle check exists in the mint path, confirmed by full inspection of the guards executed prior to minting (circuit-breaker status, decimal conversion, min-swap, fee cap, debt ceilings only). A full integration-test PoC would deposit a mock "depegged" external asset via `mint` and show the internal asset is credited at undiminished 1:1 value regardless of the external asset's assumed real-world value; this was not executed as part of this analysis.

Note: `pallet-psm` appears to be a newly introduced, not-yet-widely-deployed pallet (only wired into the `kitchensink` example runtime and Westend Asset Hub testnet per the prdocs), so its eligibility under a live Parity bounty program should be independently confirmed. [8](#0-7) [9](#0-8)

		pub fn mint(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			external_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_minting(), Error::<T>::MintingStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			let internal_equivalent =
				Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?;
			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_equivalent);
			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
			ensure!(
				current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
				Error::<T>::ExceedsMaxPsmDebt
			);

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
			let new_debt = current_debt.saturating_add(internal_equivalent);
			ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);

			let psm_account = Self::psm_account(&internal_asset);
			T::Fungibles::transfer(
				external_asset.clone(),
				&who,
				&psm_account,
				effective_external,
				Preservation::Expendable,
			)?;
			T::Fungibles::mint_into(internal_asset.clone(), &who, internal_to_user)?;
			if !fee.is_zero() {
				T::Fungibles::mint_into(internal_asset.clone(), &info.fee_destination, fee)?;
			}

			PsmDebt::<T>::insert(&internal_asset, &external_asset, new_debt);

# PSM Pallet

A module hosting one or more Peg Stability Modules. Each PSM enables 1:1 swaps
between a specific internal stablecoin and that PSM's pre-approved external
assets on Substrate-based blockchains.

## Terminology

Throughout this pallet two distinct token roles are referenced:

- **Internal** — the stablecoin a PSM issues and burns (e.g. runtime's own USD-pegged stablecoin).
  Each PSM instance is keyed by its internal asset id; multiple instances can
  coexist, each with its own reserve, debt ceiling, fee destination and
  approved externals. Mint operations credit the user with the internal asset;
  redeem operations burn it. Fees are collected in the internal asset and
  forwarded to that instance's `PsmInfo::fee_destination`.
- **External** — third-party assets (e.g. USDC, USDT) approved on a
  specific PSM via `add_external_asset` and held in that PSM's reserve. Users
  deposit external to mint internal, and burn internal to redeem external. A
  PSM may approve multiple externals, each identified by `asset_id`.
