### Title
Webhook signature verification selects the signing organization from an unverified payload field, decoupling it from the repository actually acted upon - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App configuration (and therefore which `webhook_secret`) to validate a webhook against using a field read directly out of the still-unauthenticated JSON body, while the handlers that actually mutate Shipit state resolve the target `Stack`/`Repository` from a different field in that same body. Because Shipit is multi-tenant (one `GitHubApp` per configured GitHub organization) and any organization's `webhook_secret` may legitimately be blank, an attacker can pick an organization with no configured secret to satisfy signature verification, then point the payload's `repository.full_name` at a completely different, properly-secured organization's tracked stack.

### Finding Description
`repository_owner` is computed straight from the attacker-controlled body before any signature check occurs: [1](#0-0) 

That value is fed into `Shipit.github(organization: repository_owner)` to select the `GitHubApp` instance used purely to verify the HMAC signature: [2](#0-1) 

`Shipit.github` resolves a per-organization config from `secrets.github`: [3](#0-2) 

Critically, `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's `webhook_secret` is blank — i.e. no signature is required at all for that org: [4](#0-3) 

Once verification passes, the entire raw payload is dispatched to every handler for the event: [5](#0-4) 

But handlers resolve the target repository/stack from `repository.full_name`, a field that is never cross-checked against the `repository.owner.login`/`organization.login` value used to select the signing organization: [6](#0-5) 

This breaks the binding: `organization used to authenticate the request == organization owning the repository/stack that gets written`. An attacker can set `repository.owner.login` (or `organization.login`) to an organization configured in this Shipit instance without a `webhook_secret`, satisfying `verify_signature` with no secret knowledge whatsoever, while setting `repository.full_name` to `AnotherOrg/target-repo` — a stack belonging to a different, secured organization. The corresponding handler (e.g. `MembershipHandler`, `PushHandler`, `PullRequest::*Handler`) then acts on that unrelated stack.

### Impact Explanation
This is an unauthenticated, cross-organization forgery of GitHub webhooks against any stack tracked by the Shipit instance, as long as at least one configured organization lacks a `webhook_secret` (a legitimate/valid configuration state, as shown in `test/dummy/config/secrets_double_github_app.yml` where `webhook_secret` is commented/nil for both orgs). Depending on which handler fires, this enables cross-repository writes (creating commits/statuses on the target stack via `PushHandler`/`StatusHandler`), unauthorized lock/unlock or archive/unarchive actions on unrelated stacks (`PullRequest::*Handler`), or fabrication of `Team`/`User` records via `MembershipHandler`, which is the same primitive backing `Shipit.github_teams` authorization. This matches the "cross-repository writes" and "escalation into `Shipit.github_teams` authorization" impact categories, without requiring any session, `ApiClient` token, `webhook_secret`, or GitHub App private key from the attacker.

### Likelihood Explanation
Exploitation requires only that the Shipit deployment host more than one GitHub organization and that at least one of them has no `webhook_secret` set — a configuration explicitly supported (and demonstrated in the repo's own multi-org fixture) rather than a rare misconfiguration. Given that, the attack is a single unauthenticated HTTP POST with a crafted JSON body and mismatched `repository.owner.login` vs `repository.full_name` fields; no cryptographic material or credentials are needed.

### Recommendation
Bind the organization used for signature verification to the same value used for repository/stack resolution, and require them to be identical before processing: derive the target repository strictly from the same `repository.owner.login`/`organization.login` field used to pick the signing `GitHubApp`, and reject the webhook (or fall back to a global default) if `repository.full_name`'s owner segment disagrees with the field used to select the signing secret. Additionally, treat a missing `webhook_secret` for any organization as fully unauthenticated intake only for that organization's own repositories, never as a bypass usable to attest requests bound for other organizations' repositories.

### Proof of Concept
1. Configure Shipit with two organizations, e.g. `OrgNoSecret` (no `webhook_secret` set) and `OrgSecure` (has a `webhook_secret`, tracks a stack `OrgSecure/target-repo`).
2. Send, without any authentication:
```
POST /webhooks
X-Github-Event: membership
Content-Type: application/json

{
  "action": "added",
  "scope": "team",
  "member": { "login": "attacker-controlled-user" },
  "team": { "id": 1, "name": "core", "slug": "core", "url": "https://example.com" },
  "organization": { "login": "OrgNoSecret" },
  "repository": { "owner": { "login": "OrgNoSecret" }, "full_name": "OrgSecure/target-repo" }
}
```
3. `verify_signature` resolves `repository_owner` → `"OrgNoSecret"`, whose `GitHubApp#verify_webhook_signature` returns `true` unconditionally (no secret configured), so the request is accepted with `head(:ok)` despite carrying no valid signature for `OrgSecure`.
4. `MembershipHandler` (or `PushHandler`/`PullRequest::*Handler`, depending on chosen event) processes the payload and creates/mutates records tied to `OrgSecure/target-repo`, even though the request was never authenticated against `OrgSecure`'s webhook secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
