### Title
Webhook signature is validated against the organization named in the payload, but handlers act on a different `repository.full_name` from the same unverified payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController` picks which GitHub App/organization secret to use for HMAC verification purely from a field inside the untrusted JSON body, then hands the *entire* untrusted body to handlers that key off a *different* field of the same body to decide which `Repository`/`Stack`/`Team` to mutate. Nothing ties "the organization whose secret validated this signature" to "the repository/organization the handler actually writes to."

### Finding Description
`verify_signature` derives the org used for secret lookup entirely from the payload: [1](#0-0) [2](#0-1) 

`repository_owner` is read from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`) — both attacker-controlled JSON fields. `Shipit.github(organization: repository_owner)` selects the `GitHubApp` instance (and thus the `webhook_secret`) configured for that org, e.g. `somegithuborg` / `someothergithuborg` in a multi-tenant Shipit deployment: [3](#0-2) 

`verify_webhook_signature` only checks that the HMAC of the raw body matches *that org's* secret; it does not verify that any other field of the payload actually belongs to that org: [4](#0-3) 

Once the signature passes, the full raw JSON body (`params`) is dispatched, unmodified, to every registered handler for the event: [5](#0-4) 

But handlers resolve the target `Repository`/`Stack` from `payload.dig('repository', 'full_name')` — an independent field from the `repository.owner.login` used for signature selection: [6](#0-5) [7](#0-6) 

The `MembershipHandler` is even more direct: it trusts `params.organization.login` from the body to tag/attach a `Team`, and adds/removes arbitrary GitHub logins (`params.member.login`) to/from that team — which is the exact set (`Shipit.github_teams`) used for engine-wide authorization: [8](#0-7) [9](#0-8) 

**The broken binding**: "organization that authenticated the webhook" (`repository_owner` used to pick the `webhook_secret`) is assumed to equal "organization/repository the handler writes to" (`repository.full_name` / `organization.login` used by handlers), but these are two independent fields inside the same attacker-forgeable JSON body, and no code ever cross-checks them.

### Impact Explanation
An attacker who legitimately controls (or has webhook-delivery access to) **any one** GitHub organization configured on a shared/multi-tenant Shipit instance (e.g. their own customer org, `somegithuborg`) knows that org's `webhook_secret` (since GitHub reveals delivery signing only requires knowing the secret configured for their own org's webhook). They can then POST a forged event where:
- `repository.owner.login` (or `organization.login`) = their own org, so `verify_webhook_signature` succeeds using their org's secret, and
- `repository.full_name` / `organization.login` used deeper in the handler = a victim org/repository hosted on the same shared instance.

This lets an unprivileged-relative-to-victim attacker:
- Trigger `PushHandler` to force `stack.sync_github(expected_head_sha:)` against a victim's stack/branch.
- Trigger `PullRequest` handlers (`OpenedHandler`, `LabeledHandler`, `UnlabeledHandler`) to create/archive/unarchive review stacks belonging to a victim repository.
- Trigger `MembershipHandler` to add arbitrary GitHub logins to a `Team` that is part of `Shipit.github_teams`, escalating those accounts into the application's authorization set (`User#authorized?`).

This matches the "escalation into `Shipit.github_teams` authorization" (High) and, via forced stack sync/archive actions on a victim's deploy pipeline, borders on "unauthorized deploy/rollback" (Critical) territory depending on which handler is abused.

### Likelihood Explanation
Requires the attacker to control at least one organization already configured in `Shipit`'s multi-tenant `github:` secrets (a realistic scenario for shared/hosted Shipit instances serving multiple GitHub orgs), and to craft a raw JSON body with mismatched `repository.owner.login` vs `repository.full_name`/`organization.login`. No signature forgery, no session, no `ApiClient` token and no repository write access on the victim org is needed — only knowledge of one's own org's webhook secret, which the attacker legitimately possesses.

### Recommendation
After `verify_signature` succeeds for `repository_owner`, require that every attacker-controlled repository/organization reference used later by handlers (`repository.full_name`, `organization.login`, `sender.login`, etc.) is consistent with, or scoped to, the same verified organization — e.g., reject the webhook if `repository.full_name.split('/').first` (or `organization.login`) does not case-insensitively match the `repository_owner` that was used to select the signing secret.

### Proof of Concept
1. Configure Shipit with two orgs in `github:` config, `attacker-org` (attacker knows `webhook_secret`) and `victim-org` (hosts a real Shipit-tracked repo/stack).
2. Attacker computes `sha1=HMAC(attacker-org secret, body)` over a crafted JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<arbitrary sha>",
  "repository": { "full_name": "victim-org/victim-repo", "owner": { "login": "attacker-org" } }
}
```
3. POST to `/github/webhooks` with header `X-Github-Event: push` and `X-Hub-Signature: sha1=...`.
4. `verify_signature` calls `Shipit.github(organization: "attacker-org")` (from `repository.owner.login`) and validates successfully against `attacker-org`'s secret.
5. `PushHandler` then resolves `repository_name` from `repository.full_name` = `"victim-org/victim-repo"`, and calls `stack.sync_github(expected_head_sha: params.after)` on the victim's stack — an action never authorized by anyone associated with `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
```
