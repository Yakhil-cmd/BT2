The signature verification binds trust to `repository_owner` = `params.dig('repository', 'owner', 'login')`, but the event handlers (`Handler#stacks`) act on `payload.dig('repository', 'full_name')` — a *different* payload field that is never independently validated against the organization that was cryptographically verified.

### Title
Webhook organization used for signature verification is not the same field used to resolve the target repository, allowing cross-repository writes - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to verify the HMAC signature using `repository_owner`, derived from `params.dig('repository', 'owner', 'login')` (or `organization.login` as fallback) [1](#0-0) . However, once the signature check passes, the actual event handlers resolve which `Repository`/`Stack` to act on using a *different* field: `payload.dig('repository', 'full_name')` [2](#0-1) . Nothing ties `full_name`'s owner segment to the verified `repository_owner`.

### Finding Description
This mirrors the Based Loans bug class: a lookup key that is checked/authenticated (`repository.owner.login` verified against a per-organization webhook secret) is not the same key that is used downstream to select the acted-upon resource (`repository.full_name`, used to load `Repository.from_github_repo_name` and then all matching `Stack`s) [2](#0-1) . The signature is computed over the raw JSON body with `OpenSSL::HMAC` and does bind cryptographically to the full payload bytes [3](#0-2) , so an attacker cannot forge an arbitrary payload without knowing that organization's `webhook_secret`. This significantly narrows the exploit window: the attacker must already control (or be a legitimate installer for) at least one organization/app configured in `Shipit.github` with a valid `webhook_secret`, in order to produce a validly-signed payload. Within that payload, though, `repository.full_name` and `repository.owner.login` are independent JSON fields the attacker fully controls, and the controller only checks `owner.login` for secret selection — it never asserts that `full_name`'s owner prefix matches `owner.login` or the authenticated app/organization.

### Impact Explanation
If an attacker holding a valid `webhook_secret` for *any* configured GitHub organization (e.g., their own low-trust sandbox org onboarded to the same Shipit instance) sets `repository.owner.login` to their own org (so signature verification succeeds using their org's secret) but sets `repository.full_name` to `"some-other-org/victim-repo"`, the `PushHandler` will resolve `Repository.from_github_repo_name("some-other-org/victim-repo")` and enqueue `sync_github` / trigger sync for that victim stack [4](#0-3) . This is a cross-repository write/trigger primitive: it does not require the attacker to control the victim organization's webhook secret at all, only their own. This satisfies the Critical impact bucket ("cross-repository writes").

### Likelihood Explanation
Requires the target Shipit instance to be a multi-organization deployment (`Shipit.github(organization:)` keyed config) with more than one org configured, and the attacker must control a legitimate low-privilege GitHub organization/app already onboarded with its own `webhook_secret` in `secrets.github` [5](#0-4) . This is a real, not purely theoretical, multi-tenant configuration supported by the code (`github_app_config`, `TOP_LEVEL_GH_KEYS`) [6](#0-5) , so likelihood is credible but conditioned on multi-org setup and the attacker having their own onboarded organization — an unprivileged-attacker analog per the binding-break criteria (signature-authenticated organization vs. repository actually written).

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler#repository_name`/`#stacks`), assert that the owner segment of `payload.dig('repository', 'full_name')` matches the authenticated `repository_owner` (and matches the `organization` used to select the `GitHubApp`/secret) before dispatching to handlers. Reject the webhook (422) on mismatch.

### Proof of Concept
1. Attacker controls org `attacker-org`, which is a configured Shipit GitHub App with its own `webhook_secret` (`S_attacker`).
2. Attacker crafts a `push` payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<malicious-sha-attacker-wants-considered-head>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker signs the raw body with `S_attacker` and sends `X-Hub-Signature: sha1=<hmac>`.
4. `verify_signature` computes `repository_owner = "attacker-org"`, loads `Shipit.github(organization: "attacker-org")`, and successfully verifies the signature against `S_attacker` [7](#0-6) .
5. `PushHandler#process` resolves stacks via `Repository.from_github_repo_name("victim-org/victim-repo")` [2](#0-1)  and calls `stack.sync_github(expected_head_sha: params.after)` on the victim's stack [4](#0-3) , forcing the victim stack to sync to an attacker-chosen `expected_head_sha` without any credential over `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
