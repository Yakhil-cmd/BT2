## Title
Stack-scoped CI-status token can be replayed to read any stack's build/deploy state - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
The reported bug class is a verified-but-mismatched binding: an oracle's `.latestRoundData()` answer is trusted for a purpose it was never bound to (current price vs. last-updated price), letting an attacker exploit the mismatch between what was authorized and what is actually acted on. The same class of bug exists in `Shipit::Api::CCMenuController`: an `ApiClient` token that is scoped (authorized) to read one specific `Stack` is used to fetch the build status of an *arbitrary* stack, because the controller resolves the target stack independently of the scoping check.

### Finding Description
`Shipit::Api::BaseController` scopes stack lookups to the calling `ApiClient`'s authorized stack: [1](#0-0) 

`current_api_client.stack_id?` gates this: if the `ApiClient` record has a `stack_id` (i.e. it was created scoped to one particular stack), only that stack is visible; permission checks (`require_permission :read, :stack`) then operate on top of this scoped resolution. This is exercised and confirmed by `test/controllers/api/stacks_controller_test.rb`'s "an api client scoped to a stack will only see that one stack" test.

`CCMenuController`, however, overrides both authentication and the `stack` resolution method: [2](#0-1) 

Instead of calling the inherited scoped `stacks.from_param!(params[:stack_id])`, it calls `Stack.from_param!(params[:stack_id])` directly on the unscoped `Stack` model. The `require_permission :read, :stack` before_action only checks that the token carries the `read:stack` permission string (`ApiClient#check_permissions!`, `app/models/shipit/api_client.rb` lines 38-45) — it never checks that the requested `params[:stack_id]` matches the token's authorized `stack_id`.

Binding broken: **stack a token authorizes == stack the request actually touches**. Before the fix, this equality holds because `stacks`/`stack` in `BaseController` intersect the client's `stack_id` with the requested `params[:stack_id]`. In `CCMenuController`, the equality is broken: the token's `stack_id` scope is never consulted, so any stack ID supplied in the URL is served as long as the token has the generic `read:stack` permission bit and the token itself authenticates (via `params[:token]` in `authenticate_api_client`, bypassing Basic Auth).

### Impact Explanation
This matches the "stack a token authorises versus a stack it touches" analog explicitly called out as in-scope. A CI/CD status token deliberately scoped to a single stack (e.g., distributed to an external CI dashboard for one project) can be replayed against `/api/:any_stack_id/ccmenu.xml?token=...` to read the build/deploy status (`stack.deploys_and_rollbacks.last`) of any other stack in the Shipit instance, including stacks the token holder was never meant to see. This is an escalation beyond the token's authorized scope, matching the High-impact category of "unauthenticated [i.e., outside the token's actual authorization] read of stack state, task streams or deploy output."

### Likelihood Explanation
Exploitation only requires possession of any valid `read:stack`-permissioned `ApiClient` token that is scoped to a single stack via `stack_id` — such tokens are explicitly created and distributed for exactly this CCMenu use case (see `ccmenu_url_controller.rb`, which mints an `ApiClient` for CCMenu integrations) and are handed to third-party CI dashboard tools, which is a lower-trust distribution path than a full Basic-Auth API credential. No additional privilege, session, or GitHub credential is needed — the attacker only needs a `stack_id` value (visible in URLs) for the target stack.

### Recommendation
Change `CCMenuController#stack` to use the inherited, scoped `stacks.from_param!(params[:stack_id])` (or otherwise verify `current_api_client.stack_id.nil? || current_api_client.stack_id == requested_stack.id`) so the token's `stack_id` binding is enforced identically to every other API controller.

### Proof of Concept
1. Create/obtain a stack-scoped `ApiClient` with permission `read:stack` and `stack_id` set to Stack A only (as done by `Shipit::CCMenuUrlController#client`, or any equivalently scoped client such as the `here_come_the_walrus` fixture used in tests).
2. Obtain that client's `authentication_token` (the value normally embedded as `?token=` in the CCMenu URL for Stack A).
3. Send a GET request to `/api/<Stack B id or param>/ccmenu.xml?token=<Stack A's token>` where Stack B is a different stack the token was never authorized for.
4. `CCMenuController#authenticate_api_client` authenticates the token successfully (it is valid), `require_permission :read, :stack` passes because the token does have `read:stack`, and `stack` resolves to Stack B via unscoped `Stack.from_param!`, returning Stack B's latest deploy/build status in the XML response — despite the token only being authorized for Stack A. # frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
