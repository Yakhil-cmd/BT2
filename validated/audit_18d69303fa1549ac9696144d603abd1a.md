### Title
Unhandled `objectHash.getUnitHash()` exception in `aa_composer.js` can crash AA response composition, halting deterministic AA processing network-wide - (File: aa_composer.js)

### Summary
The go-merkledag advisory describes a class of bug where an object that can be mutated/composed into an "unencodeable" form causes a hashing/encoding routine to throw, and that throw occurs in a code path that isn't allowed to propagate an error, resulting in a panic. Ocore's `object_hash.js`/`string_utils.js` have the exact same "throws on malformed input" behavior (empty arrays/objects, `null`, non-finite numbers, `\x00` bytes all raise exceptions in `getSourceString`/`getJsonSourceString`), and virtually everywhere these hashing helpers are invoked in production code they are wrapped in `try/catch` — except for the AA response-unit composition path.

### Finding Description
`string_utils.js`'s `getSourceString`/`getJsonSourceString` throw `Error` for empty arrays, empty objects, `null` values, non-finite numbers, and other "unencodable" states: [1](#0-0) [2](#0-1) 

`object_hash.js#getUnitHash` calls these functions with no protection of its own: [3](#0-2) 

Nearly every caller of `objectHash.getUnitHash`/`getChash160`/`getBase64Hash` in the codebase defensively wraps the call in `try/catch` (e.g. `validation.js` line 131-138, `storage.js#isCorrectHash`, `wallet.js`, `signed_message.js`, `witness_proof.js`). The one exception found is in `aa_composer.js`, inside `handleTrigger`'s `sendUnit()` function, which builds and hashes the AA's response unit: [4](#0-3) 

Here `objUnit.unit = objectHash.getUnitHash(objUnit);` is called directly, with no `try/catch`, unlike the sibling call `completeMessage()` two lines above which *is* wrapped (`try { completeMessage(objBasePaymentMessage); } catch (e) { return bounce(...) }`). At this point `objUnit.messages` is composed from AA-template message payloads that were evaluated via the oscript/formula engine (`formulaParser`) using attacker-controlled trigger data (`trigger.data`, `trigger.address`, `trigger.output[...]`, state vars, etc.). The formula evaluator does apply some sanitization at specific operators (e.g. `sha256`, `chash160`, `json_stringify`, `state_var_assignment` all wrap `getJsonSourceString`/`getChash160` in try/catch — see `formula/evaluation.js` lines 1809-1846, 1848-1870, 1957-1981), but those guards only cover the *formula operators themselves*, not the final composed `objUnit` structure that is later fed into `getUnitHash()` in `aa_composer.js`. If any part of the composed message payload ends up containing a value that `getSourceString`/`getJsonSourceString` cannot encode (an empty array/object, `null`, or a non-finite number that slipped through prior checks), `getUnitHash(objUnit)` throws synchronously and uncaught inside `sendUnit()`.

This is directly analogous to the `go-merkledag` CVE-2022-23495 pattern: an object hashing/encoding routine that is guaranteed to throw on certain (reachable) malformed states is invoked from a code path that has no error-return mechanism and does not itself guard the call, causing a panic (in Go) / uncaught exception (in JS).

### Impact Explanation
`sendUnit()` executes inside `handleTrigger()`, which is invoked from `handlePrimaryAATrigger()` inside a DB transaction under the `aa_triggers` mutex lock, from `handleAATriggers()`: [5](#0-4) [6](#0-5) 

An uncaught exception thrown here is not caught by any `try/catch` in the call chain shown, so it propagates as an unhandled exception in Node.js, crashing the full node process. Because AA execution is meant to be fully deterministic (every full node executes the same formula against the same trigger/state to derive the same response unit), a trigger that is crafted to reach this uncaught-throw condition would crash *every* full node that attempts to process it identically. Since `aa_triggers` are processed under a mutex and persisted in the DB, the same trigger would be retried and re-crash the node on restart, blocking further processing of `aa_triggers` (and by extension, subsequent MC advancement / stabilization that depends on AA responses being resolved) — this matches the accepted impact category of "a network unable to confirm new units" rather than a simple isolated-node DoS, because the crash is a deterministic function of on-chain data reproduced identically by every conforming node.

### Likelihood Explanation
Exploitability depends on finding a concrete way to make a legitimate/attacker-controlled AA response message payload contain something `getSourceString`/`getJsonSourceString` cannot encode (empty array/object, `null`, or a non-finite number) after passing through the AA definition's own message templates and the partial sanitizations present in `formula/evaluation.js`. I was not able to fully trace, within the remaining tool budget, the complete path from AA-template `payload` field evaluation (e.g., via `evalAAStringAtPath`/general object evaluation in `aa_composer.js`, not shown in the excerpts retrieved) to confirm whether such a value can concretely survive into `objUnit.messages` before reaching line 1403. The absence of a `try/catch` at this specific call site — in contrast to the defensive pattern used at every other `getUnitHash`/`getChash160` call site in the codebase, including the adjacent `completeMessage()` call — is the concrete, confirmed root-cause weakness; whether a message payload construction path exists that bypasses the formula-evaluation guards to leave an un-encodable structure in `objUnit` is the part that would need further tracing (e.g., through `aa_composer.js`'s general "evaluate object field" recursion used to build `message.payload` for non-payment app messages such as `data`).

### Recommendation
Wrap the `objUnit.unit = objectHash.getUnitHash(objUnit);` call in `aa_composer.js` (and any other un-guarded internal call to `getUnitHash`/`getChash160`/`getBase64Hash` reachable from AA response composition) in a `try/catch`, treating a thrown error the same way `completeMessage` failures are treated — i.e., `bounce("unit hash failed: " + e.toString())` — so that a malformed/un-encodable AA response unit results in a graceful bounce rather than an uncaught process-crashing exception. Additionally, add a proactive well-formedness check (similar to `isTooDeeplyNestedOrHasTooManyNodes`/`isObjectWellFormed` used in `validation.js`) on the fully composed `objUnit` before hashing, to reject empty containers, `null`s, and non-finite numbers deterministically and produce a bounce message instead of a hard throw.

### Proof of Concept
Not constructed — a full PoC requires tracing the exact AA-template `payload` object-evaluation path (not fully available within the tool budget) that would need to leave an empty array/object, `null`, or non-finite number inside a `message.payload` before `sendUnit()` reaches line 1403 (`objUnit.unit = objectHash.getUnitHash(objUnit);`) without the surrounding formula-evaluation guards (`sha256`/`chash160`/`json_stringify`/`state_var_assignment` in `formula/evaluation.js`) intercepting it first. The concrete, verified finding is the missing `try/catch` around this specific `getUnitHash` call, which is inconsistent with every other call site of the same function in the codebase.

function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);

function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
}
