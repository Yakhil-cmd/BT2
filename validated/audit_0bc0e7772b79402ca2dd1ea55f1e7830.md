### Title
Denial of Service via Unbounded Private Payment Chains sent by a payment counterparty - (File: wallet.js, private_payment.js, indivisible_asset.js)

### Summary
`handlePrivatePaymentChains()` in `wallet.js` [1](#0-0)  accepts an array of private-payment chains (`body.chains`) from any correspondent/peer and only checks that each chain is a non-empty array of well-formed elements — it never bounds the number of chains, the length of each chain, or the total size of the payload before starting per-chain async validation via `network.handleOnlinePrivatePayment` → `private_payment.validateAndSavePrivatePaymentChain` [2](#0-1) . Each chain element triggers DB reads/writes (`storage.readAsset`, transaction BEGIN/COMMIT, `indivisible_asset.js`/`divisible_asset.js` validation and inserts) with no cap corresponding to `constants.MAX_*` anti-spam limits that exist elsewhere in the codebase (e.g. `MAX_MESSAGES_PER_UNIT`, `MAX_INPUTS_PER_PAYMENT_MESSAGE`, `MAX_SPEND_PROOFS_PER_MESSAGE` in `constants.js` [3](#0-2) ). This mirrors the Nova bug class: an authenticated/paired actor can make a "large number of calls" (here, chain elements) that are individually valid but collectively unbounded, exhausting DB and CPU resources without a corresponding quota check.

### Finding Description
- `handlePrivatePaymentChains` validates only structural correctness of `arrChains`, not their cardinality or depth, before iterating `async.eachSeries(arrChains, ...)` and, for light wallets, also calling `network.requestUnfinishedPastUnitsOfPrivateChains(arrChains)` [4](#0-3) .
- For each chain, `network.handleOnlinePrivatePayment` is invoked, which for light clients with a multi-element chain schedules `updateLinkProofsOfPrivateChain` and `rerequestLostJointsOfPrivatePayments()`, and otherwise proceeds straight into DB validation via `joint_storage.checkIfNewUnit` [5](#0-4) .
- `private_payment.validateAndSavePrivatePaymentChain` opens a DB transaction (`BEGIN`), performs an asset lookup and duplicate check query, then calls into `indivisible_asset.js`/`divisible_asset.js` `validateAndSavePrivatePaymentChain`, which in turn calls `parsePrivatePaymentChain` — an `async.forEachOfSeries` over the *entire* supplied chain, doing per-element DB reads (spend proof lookup, `graph.determineIfIncluded`) and, on success, a further `async.series` of INSERT/UPDATE queries per element [6](#0-5) .
- Nowhere in this call path (`wallet.js` → `network.js` → `private_payment.js` → `indivisible_asset.js`/`divisible_asset.js`) is there a check analogous to `MAX_MESSAGES_PER_UNIT`, `MAX_INPUTS_PER_PAYMENT_MESSAGE`, or similar constant limiting the number of chains per message or the number of elements per chain.
- A paired device / private-payment counterparty can therefore send a `private_payment_chains` message with an arbitrarily large `chains` array (or arbitrarily long individual chains), forcing the receiving wallet/hub to open many DB transactions, run recursive `graph.determineIfIncluded` graph traversals, and perform many inserts — all without ever needing valid signatures beyond what's needed to pass the lightweight structural checks in `handlePrivatePaymentChains`.

### Impact Explanation
This matches CWE-770 (Allocation of Resources Without Limits or Throttling), the same class as CVE-2013-1838: a reachable actor (a paired device / private-payment counterparty, which is explicitly in scope) can force unbounded resource consumption (DB transactions, CPU for graph traversal, memory for cached JSON) by repeatedly invoking normal, authorized functionality (sending private payment chains) with no per-message/per-chain quota. On a light wallet or a hub relaying private chains, this can degrade or halt normal transaction processing, i.e., a node becomes unable to confirm/process new legitimate private payments — satisfying the "network unable to confirm new units" acceptance criterion for this class of finding, scoped to the wallet/hub component that processes private payments.

### Likelihood Explanation
Reachability is straightforward: no signature validation or on-chain fee is required before the wallet begins processing (`handlePrivatePaymentChains` only checks object shape) [1](#0-0) . An attacker only needs to be an existing correspondent/paired device or route messages as if via a hub to a peer that accepts unsolicited private payments, which is a normal, low-privilege capability in the Obyte wallet protocol.

### Recommendation
Add explicit quotas analogous to the existing anti-spam constants in `constants.js`:
- Cap the number of chains accepted per `handlePrivatePaymentChains` invocation (e.g. a new `MAX_PRIVATE_CHAINS_PER_MESSAGE`).
- Cap the maximum chain length processed by `parsePrivatePaymentChain` / `buildPrivateElementsChain` (e.g. `MAX_PRIVATE_CHAIN_LENGTH`), rejecting or rate-limiting chains that exceed it before starting DB transactions.
- Consider per-correspondent rate limiting/throttling of private-payment chain submissions in `wallet.js`, mirroring the `tps_fee` mechanism already used to throttle spam for on-DAG units.

### Proof of Concept
A paired device or online peer sends repeated `private_payment_chains` messages where `body.chains` is an array containing hundreds or thousands of syntactically valid-looking (but ultimately rejected) chain elements, or a small number of chains each with an extremely long element list, to `handlePrivatePaymentChains` [7](#0-6) . Because validation happens per element inside DB transactions (`BEGIN`/queries/`COMMIT` in `private_payment.js` [8](#0-7) ) with no upfront cardinality check, the recipient wallet/hub spends disproportionate CPU/DB resources per incoming message compared to the cost imposed on the sender, who pays no on-chain fee for merely submitting (and having rejected) such chains.

	}
	if (handledChainsCache[cache_key]) {

		eventBus.emit('all_private_payments_handled-' + arrChains[0][0].unit);

	profiler.increment();

				},

// arrPrivateElements is ordered in reverse chronological order
function parsePrivatePaymentChain(conn, arrPrivateElements, callbacks){
	var bAllStable = true;
	var issuePrivateElement = arrPrivateElements[arrPrivateElements.length-1];
	if (!issuePrivateElement.payload || !issuePrivateElement.payload.inputs || !issuePrivateElement.payload.inputs[0])
		return callbacks.ifError("invalid issue private element");
	var asset = issuePrivateElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in issue private element");
	var denomination = issuePrivateElement.payload.denomination;
	if (!denomination)
		return callbacks.ifError("no denomination in issue private element");
	async.forEachOfSeries(
		arrPrivateElements,
		function(objPrivateElement, i, cb){
			if (!objPrivateElement.payload || !objPrivateElement.payload.inputs || !objPrivateElement.payload.inputs[0])
				return cb("invalid payload");
			if (!objPrivateElement.output)
				return cb("no output in private element");
			if (objPrivateElement.payload.asset !== asset)
				return cb("private element has a different asset");
			if (objPrivateElement.payload.denomination !== denomination)
				return cb("private element has a different denomination");
			var prevElement = null; 
			if (i+1 < arrPrivateElements.length){ // excluding issue transaction
				var prevElement = arrPrivateElements[i+1];
				if (prevElement.unit !== objPrivateElement.payload.inputs[0].unit)
					return cb("not referencing previous element unit");
				if (prevElement.message_index !== objPrivateElement.payload.inputs[0].message_index)
					return cb("not referencing previous element message index");
				if (prevElement.output_index !== objPrivateElement.payload.inputs[0].output_index)
					return cb("not referencing previous element output index");
			}
			validatePrivatePayment(conn, objPrivateElement, prevElement, {
				ifError: cb,
				ifOk: function(bStable, input_address){
					objPrivateElement.bStable = bStable;
					objPrivateElement.input_address = input_address;
					if (!bStable)
						bAllStable = false;
					cb();
				}
			});
		},
		function(err){
			if (err)
				return callbacks.ifError(err);
			callbacks.ifOk(bAllStable);
		}
	);
}


function validateAndSavePrivatePaymentChain(conn, arrPrivateElements, callbacks){
	parsePrivatePaymentChain(conn, arrPrivateElements, {
		ifError: callbacks.ifError,
		ifOk: function(bAllStable){
			console.log("saving private chain "+JSON.stringify(arrPrivateElements));
			profiler.start();
			var arrQueries = [];
			for (var i=0; i<arrPrivateElements.length; i++){
				var objPrivateElement = arrPrivateElements[i];
				var payload = objPrivateElement.payload;
				var input_address = objPrivateElement.input_address;
				var input = payload.inputs[0];
				var is_unique = objPrivateElement.bStable ? 1 : null; // unstable still have chances to become nonserial therefore nonunique
				if (!input.type) // transfer
					conn.addQuery(arrQueries, 
						"INSERT "+db.getIgnore()+" INTO inputs \n\
						(unit, message_index, input_index, src_unit, src_message_index, src_output_index, asset, denomination, address, type, is_unique) \n\
						VALUES (?,?,?,?,?,?,?,?,?,'transfer',?)", 
						[objPrivateElement.unit, objPrivateElement.message_index, 0, input.unit, input.message_index, input.output_index, 
						payload.asset, payload.denomination, input_address, is_unique]);
				else if (input.type === 'issue')
					conn.addQuery(arrQueries, 
						"INSERT "+db.getIgnore()+" INTO inputs \n\
						(unit, message_index, input_index, serial_number, amount, asset, denomination, address, type, is_unique) \n\
						VALUES (?,?,?,?,?,?,?,?,'issue',?)", 
						[objPrivateElement.unit, objPrivateElement.message_index, 0, input.serial_number, input.amount, 
						payload.asset, payload.denomination, input_address, is_unique]);
				else
					throw Error("neither transfer nor issue after validation");
				var is_serial = objPrivateElement.bStable ? 1 : null; // initPrivatePaymentValidationState already checks for non-serial
				var outputs = payload.outputs;
				for (var output_index=0; output_index<outputs.length; output_index++){
					var output = outputs[output_index];
					console.log("inserting output "+JSON.stringify(output));
					conn.addQuery(arrQueries, 
						"INSERT "+db.getIgnore()+" INTO outputs \n\
						(unit, message_index, output_index, amount, output_hash, asset, denomination) \n\
						VALUES (?,?,?,?,?,?,?)",
						[objPrivateElement.unit, objPrivateElement.message_index, output_index, 
						output.amount, output.output_hash, payload.asset, payload.denomination]);
					var fields = "is_serial=?";
					var params = [is_serial];
					if (output_index === objPrivateElement.output_index){
						var is_spent = (i===0) ? 0 : 1;
						fields += ", is_spent=?, address=?, blinding=?";
						params.push(is_spent, objPrivateElement.output.address, objPrivateElement.output.blinding);
					}
					params.push(objPrivateElement.unit, objPrivateElement.message_index, output_index);
					conn.addQuery(arrQueries, "UPDATE outputs SET "+fields+" WHERE unit=? AND message_index=? AND output_index=? AND is_spent=0", params);
				}
			}
		//	console.log("queries: "+JSON.stringify(arrQueries));
			async.series(arrQueries, function(){
				profiler.stop('save');
				callbacks.ifOk();
			});
		}
	});
}
