### Title
`pallet-proxy`'s `is_superset` lattice is broken for `ProxyType::NonTransfer` vs `ProxyType::Auction` (and `OnDemandOrdering` on Rococo), letting a `NonTransfer` proxy grant itself calls its own filter denies - ([File: polkadot/runtime/westend/src/lib.rs], [File: polkadot/runtime/rococo/src/lib.rs])

### Summary
This is the exact bug class described in the GitLab report (BIT-gitlab-2025-10871 / CVE-2025-10871): an actor with a *limited* role can assign itself a *different* role whose effective permissions exceed what it should hold, because the "is this role contained in mine" check does not match the actual permission set of the target role. In `pallet_proxy`, `ProxyType::is_superset` is exactly this containment check, and `do_proxy` uses it — not `filter` — to authorize `add_proxy`/`remove_proxy` calls made through an existing proxy [3](#0-2) . This class was already found and fixed once in this codebase for `asset-hub-westend`'s `NonTransfer`/`Governance` pair [4](#0-3) [5](#0-4) , with a repo-wide regression test added to check the lattice invariant on that specific runtime [6](#0-5) . That regression test, however, only covers `asset-hub-westend`; it is not present for the relay-chain runtimes.

### Finding Description
In `polkadot/runtime/westend/src/lib.rs` and `polkadot/runtime/rococo/src/lib.rs`, `ProxyType::is_superset` declares:
```
(ProxyType::NonTransfer, _) => true,
```
i.e. `NonTransfer` is unconditionally declared a superset of *every* other `ProxyType`, including `Auction` [7](#0-6) .

But `ProxyType::Auction`'s filter admits the entire `paras_registrar` call family:
```
RuntimeCall::Registrar(..)
``` [8](#0-7) , while `ProxyType::NonTransfer`'s filter explicitly restricts `Registrar` to only `register`, `deregister`, and `reserve`, with a code comment stating it deliberately omits `swap`:
```
RuntimeCall::Registrar(paras_registrar::Call::register{..}) |
RuntimeCall::Registrar(paras_registrar::Call::deregister{..}) |
// Specifically omitting Registrar `swap`
RuntimeCall::Registrar(paras_registrar::Call::reserve{..}) |
``` [9](#0-8) . The same pattern (identical comment, identical omission) exists in Rococo [10](#0-9) [11](#0-10) .

`paras_registrar::swap` lets an authorized caller (owner of `id`, or the para itself, or Root) swap the on-chain lifecycle/slot identity between two `ParaId`s [12](#0-11) , a call the delegator's own filter explicitly wanted to keep out of reach of a `NonTransfer` delegate.

Rococo additionally has `ProxyType::OnDemandOrdering`, whose filter admits `RuntimeCall::OnDemandAssignmentProvider(..)` in full [13](#0-12) , yet `NonTransfer`'s filter list never mentions `OnDemandAssignmentProvider` at all [14](#0-13) . Since the wildcard `is_superset` arm still claims `NonTransfer` is a superset of `OnDemandOrdering`, a `NonTransfer` delegate could add itself an `OnDemandOrdering` proxy and then call `place_order_allow_death`/`place_order_keep_alive`, which directly withdraw the delegator's free balance via `T::Currency::withdraw` [15](#0-14) [16](#0-15)  — i.e. a direct balance transfer despite `NonTransfer`'s entire purpose being to forbid exactly that.

Attacker entry point: an account holding only a `NonTransfer` proxy (a routinely-delegated, low-privilege role) calls `Proxy::proxy(real, None, Box::new(Proxy::add_proxy{ delegate: attacker, proxy_type: Auction (or OnDemandOrdering on Rococo), delay: 0 }))`. `do_proxy`'s inline filter only checks `def.proxy_type.is_superset(proxy_type)` [17](#0-16) , which returns `true` due to the wildcard arm, so `add_proxy` succeeds and installs the wider proxy — bypassing `filter`, which is only consulted for non-`Proxy` calls.

### Impact Explanation
An account granted only limited (`NonTransfer`) authority over another account's funds/identity can escalate itself to a materially different privilege set (`Auction`/`OnDemandOrdering`) that the delegator explicitly excluded, matching the "Missing Authorization" bug class of the source report (self-granted permissions exceeding intended scope). On Rococo this directly enables uncontrolled withdrawal of the delegator's free balance. This mirrors the already-acknowledged severity of the fixed AssetHub `NonTransfer`/`Governance` case (fixed as a runtime patch bump) [18](#0-17) .

### Likelihood Explanation
High for any account that has been granted a `NonTransfer` proxy on Westend or Rococo relay-chain runtimes: no privileged role or governance access is needed, only a routine, commonly-used low-trust delegation. The escalation requires a single `Proxy::proxy(..., add_proxy{...})` call with zero fee beyond normal extrinsic cost and no special timing.

### Recommendation
Apply the same fix pattern used for `asset-hub-westend`/`Governance` (PR referenced in `prdoc/pr_12769.prdoc`): remove `Auction` (and, on Rococo, `OnDemandOrdering`) from the calls implicitly covered by the `(ProxyType::NonTransfer, _) => true` wildcard, or make the wildcard exhaustive/explicit per-variant so it can't silently claim containment of a type whose filter is not actually a subset. Add a lattice-consistency regression test (analogous to `proxy_type_superset_relation_matches_call_filters` in `asset-hub-westend`) to the relay-chain runtime test suites so this class can't reappear.

### Proof of Concept
I did not execute a live reproduction; this is a static-analysis finding based on tracing `is_superset`/`filter` definitions and the `do_proxy` authorization logic. A minimal reproduction would be a `pallet_proxy` integration test in `polkadot/runtime/westend` (or `rococo`) mock:
1. Delegator grants `ProxyType::NonTransfer` to `attacker`.
2. `attacker` calls `Proxy::proxy(delegator, None, Box::new(RuntimeCall::Proxy(pallet_proxy::Call::add_proxy{ delegate: attacker2, proxy_type: ProxyType::Auction, delay: 0 })))` and observe it succeeds (`ProxyExecuted { result: Ok(()) }`), because `NonTransfer.is_superset(&Auction) == true`.
3. `attacker2` (or `attacker` itself) then calls `Proxy::proxy(delegator, None, Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap{...})))`, a call `NonTransfer.filter` denies but `Auction.filter` admits, and observe it dispatches instead of being `CallFiltered`.
4. On Rococo, substitute `ProxyType::OnDemandOrdering` and follow with `RuntimeCall::OnDemandAssignmentProvider(pallet_on_demand::Call::place_order_allow_death{...})` to demonstrate direct balance withdrawal.
This trace was not run against the harness; the evidence above is derived purely from reading `is_superset`/`filter`/`do_proxy` source, which is sufficient to establish the logical contradiction but not an executed test result.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
