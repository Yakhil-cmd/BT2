### Title
`pull_request` webhook signature verified against `repository.owner.login` while `LabelCapturingHandler` mutates the stack resolved from `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/org config used to check `X-Hub-Signature` based on `repository.owner.login` (via `repository_owner`), but `LabelCapturingHandler` resolves the repository/stack to mutate from `repository.full_name` independently. An attacker who controls a repository under an org with no configured `webhook_secret` can forge a payload whose `repository.owner.login` names that no-secret org (so `verify_webhook_signature` trivially returns `true`) while `repository.full_name` points at an unrelated, victim-owned repository, letting the forged `unlabeled` event write attacker-chosen labels onto that victim's `PullRequest`/`ReviewStack`.

### Finding Description
The broken binding: the code implicitly assumes `params.dig('repository','owner','login') == params.dig('repository','full_name').split('/').first`, i.e., that the org used to authenticate the webhook is the same org whose repository/stack the handler will mutate. This is never enforced.

- `WebhooksController#verify_signature` computes `repository_owner` purely from `params.dig('repository', 'owner', 'login')` (or the top-level `organization.login`) and uses it to select `Shipit.github(organization: repository_owner)` [1](#0-0) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is blank/unconfigured: `return true unless webhook_secret` [3](#0-2) .
- `LabelCapturingHandler` (used for `pull_request` `unlabeled`) never reads `repository.owner.login`; it resolves the repository purely from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [4](#0-3) , then finds the matching `ReviewStack`/`Stack` via `review_stack.stack` and, in `capture_labels`, persists `params.pull_request.labels.map(&:name)` onto that stack's `PullRequest` with `pull_request.update!(labels: ...)` [5](#0-4) .
- Those persisted label names later become uppercased environment keys via `ReviewStack#env`, which merges `label_name.upcase => "true"` into the stack's env for every label: `.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` [6](#0-5) , and this env flows into deploy/rollback/task commands (`DeployCommandsTest`/`TaskCommandsTest` confirm labels become env vars consumed by shell commands) [7](#0-6) [8](#0-7) .

Exploit flow:
1. Attacker owns/controls a repository under org `attacker-org`, which is not configured with a `webhook_secret` in Shipit (a legitimate, common state for orgs not integrated with Shipit).
2. Attacker (or anyone able to send arbitrary HTTP requests, since this is unauthenticated `POST /webhooks`) crafts a `pull_request` payload with `action: "unlabeled"`, `repository.owner.login: "attacker-org"`, but `repository.full_name: "victim-org/victim-repo"` where `victim-org/victim-repo` is a real Shipit-tracked review-stack-enabled repository, and `pull_request.number` matching an existing PR/review stack for that victim repo, with attacker-chosen `pull_request.labels`.
3. `verify_signature` looks up `Shipit.github(organization: "attacker-org")`; since that org has no `webhook_secret` configured, `verify_webhook_signature` returns `true` regardless of the (attacker-supplied, or even absent) signature header.
4. The event passes to `LabelCapturingHandler`, which resolves `victim-org/victim-repo`'s `ReviewStack`/`PullRequest` from `full_name` and overwrites its labels with attacker-chosen values.
5. Those labels become uppercased env vars on next deploy/rollback/task invocation for that stack.

Existing guards fail because none of `drop_unhandled_event`, `ExplicitParameters` schema validation, `force_github_authentication`, `User#authorized?`, `require_permission!`, or model validations check that the authenticating org matches the mutated repository's owner — `verify_signature` and the handler's repository resolution are two independently-computed, never-cross-checked values.

### Impact Explanation
This is a payload that authenticates against one repository/org's (non-existent) secret but mutates a completely different repository's stack — matching the Critical category "a payload for one repository mutating another's stack." The attacker can inject arbitrary environment variable names (as `TRUE`-valued flags) into any Shipit-tracked review stack, including ones marked as `production` environment, without any credential belonging to the victim. Since these env vars are merged into `Command`/`PTY.spawn` environments for deploy/rollback/task scripts (whose behavior is often branched on such flags, e.g., `SAFETY_DISABLED`-style toggles per the deploy spec's `variables`), this can influence or unlock dangerous deploy-script behavior on the victim's production stack, i.e., unauthorized deploy/rollback effects. It is repeatable against any victim repository as long as the attacker can find/create *some* org with no configured Shipit `webhook_secret` to use as the spoofed `repository.owner.login`.

### Likelihood Explanation
Preconditions: (1) at least one GitHub org known to Shipit's `github_teams`/orgs config without a `webhook_secret` set (common, since only orgs actually onboarded to Shipit typically have secrets, and unrelated/no-secret orgs are the norm for `Shipit.github(organization: ...)` fallback to `return true unless webhook_secret`); (2) the victim repository has review stacks enabled with an open PR (a common state for review-stack-based CI/CD). Attacker cost is a single crafted, unauthenticated HTTP POST to `/webhooks` with a synthetic `X-Github-Event: pull_request` header and JSON body — no valid signature is even required. This is trivially repeatable against any/all such review stacks.

### Recommendation
In `Shipit::WebhooksController`, verify the webhook signature using the org/secret derived from `repository.full_name` (the same value the handlers use to resolve the mutated repository), not `repository.owner.login`, and reject the event (422) if the two ever diverge. Alternatively, have `verify_signature` explicitly compare `params.dig('repository','owner','login')` against `params.dig('repository','full_name').split('/').first` and reject on mismatch before dispatching to handlers.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`, extending existing patterns):
```ruby
test "pull_request unlabeled event with mismatched owner/full_name mutates victim stack's labels" do
  # Setup: victim review stack for "victim-org/victim-repo" with a PullRequest, environment: "production"
  victim_repo = shipit_repositories(:some_repo) # owner: 'victim-org', name: 'victim-repo'
  victim_stack = shipit_stacks(:review_stack)   # environment: 'production', belongs to victim_repo, has pull_request
  original_labels = victim_stack.pull_request.labels.dup

  # Attacker org "attacker-org" has no webhook_secret configured in Shipit.github_teams/orgs
  payload = {
    action: "unlabeled",
    number: victim_stack.pull_request.github_pull_request... , # matching PR number
    pull_request: { ..., labels: [{ name: "SAFETY_DISABLED" }] },
    repository: {
      owner: { login: "attacker-org" },       # no secret configured -> verify_webhook_signature returns true
      full_name: "victim-org/victim-repo"      # handler resolves and mutates THIS repo's stack
    },
    sender: { login: "attacker" }
  }.to_json

  post :create, body: payload, params: {}, headers: {
    'X-Github-Event' => 'pull_request',
    'X-Hub-Signature' => 'sha1=deadbeef' # irrelevant/forged, unverified for attacker-org
  }

  assert_response :ok
  victim_stack.pull_request.reload
  # Equality claim being violated:
  # BEFORE: repository_owner ("attacker-org") != stack.repository.owner ("victim-org")
  # yet mutation still succeeds:
  assert_equal ["safety_disabled"], victim_stack.pull_request.labels
  refute_equal original_labels, victim_stack.pull_request.labels
  assert_equal "true", victim_stack.env["SAFETY_DISABLED"]
end
```
This demonstrates the org used for signature verification (`attacker-org`) is provably different from the org owning the mutated stack (`victim-org`), and the mutation (label/env injection) on the production-environment stack still occurs — confirming the invariant "a `pull_request` event only affects the repository/stack whose secret authenticated it" is violated.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
