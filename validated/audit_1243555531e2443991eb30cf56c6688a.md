### Title
Stale Governance Vote from Previous Governing Node Bypasses Single-Mode Authority Check — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

In `single` governance mode, the `governance_vote` API validates the caller is the current governing node at **queue time** and stores the vote in `myVotes`. However, `PrepareHeader()` blindly includes the queued vote in the next block the node proposes, and `VerifyVote()` only enforces the governing-node constraint **after the Permissionless fork**. Before that fork, a stale vote queued by the previous governing node passes all on-chain checks and is ratified at the next epoch boundary, changing protected protocol parameters (minting amount, reward ratios, unit price) without authorization from the current governing node.

---

### Finding Description

**Step 1 — Vote is queued with a point-in-time authority check.**

`Vote()` in `kaiax/gov/headergov/impl/api.go` checks whether the calling node is the governing node at the moment the API is called:

```go
if gMode == "single" && voter != gp.GoverningNode {
    return "", ErrVotePermissionDenied
}
// ...
api.h.PushMyVotes(vote)   // stored in h.myVotes slice
```

The vote is appended to the in-memory `myVotes` queue with no expiry and no record of which governing node was in power when it was queued.

**Step 2 — PrepareHeader includes the vote without re-checking authority.**

`PrepareHeader()` in `kaiax/gov/headergov/impl/header.go` calls `peekMyVote()` and unconditionally writes the first pending vote into `header.Vote`:

```go
if vote, ok := h.peekMyVote(); ok {
    voteBytes, err := vote.ToVoteBytes()
    // ...
    header.Vote = voteBytes
}
```

There is no check here that the node is still the governing node.

**Step 3 — VerifyVote does not enforce governing-node authority before Permissionless fork.**

`VerifyVote()` performs only two checks before the Permissionless fork:

1. The voter is in the council (`slices.Contains(council, vote.Voter())`).
2. The voter is the block proposer (`author != vote.Voter()`).

The governing-node check is gated behind `IsPermissionlessForkEnabled`:

```go
// In single mode, only the governing node can write header.Vote after Permissionless.
if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
    params.GovernanceMode == "single" &&
    vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
```

Before the Permissionless fork, this block is never entered. A stale vote from the previous governing node — who is still a council member and becomes a proposer — passes all checks.

**Step 4 — The stale vote is ratified.**

`getExpectedGovernance()` collects all votes from the previous epoch and uses the last vote per parameter as the ratified value. The stale vote is indistinguishable from a legitimate one and is included in `header.Governance` at the epoch boundary, permanently changing the parameter.

---

### Impact Explanation

The stale vote is ratified and changes one or more of the following protected protocol parameters:

- `reward.mintingamount` — unauthorized change to the per-block KAIA minting amount, directly affecting total KAIA supply and validator/fund rewards.
- `reward.ratio` — unauthorized redistribution of block rewards among proposer, KEF, and KIF.
- `governance.unitprice` — unauthorized change to the minimum gas price, affecting all transaction fees.
- `governance.governingnode` — unauthorized reversion of the governing node back to the old address, re-granting the old node permanent governance authority.

All of these are protected chain-state values whose modification without current governing-node authorization constitutes an unauthorized governance parameter change with direct asset impact (reward distribution, fee collection, KAIA minting).

---

### Likelihood Explanation

The preconditions are realistic and arise naturally during governance transitions:

1. Governance mode is `single` (the mode used on Kaia Mainnet and Kairos).
2. The governing node is changed via a ratified `governance.governingnode` vote — a normal governance operation.
3. The old governing node had a pending vote in `myVotes` at the time of the change (e.g., it called `governance_vote` earlier in the same epoch).
4. The old governing node is still in the council (council membership is separate from governing-node status) and is selected as a proposer before the Permissionless fork activates.

No special privileges beyond being a council member are required after the governing node change. The old node's `myVotes` queue is never cleared on governing-node rotation.

---

### Recommendation

**Option A (preferred):** In `PrepareHeader()`, re-validate that the node is still the governing node before including the vote:

```go
if vote, ok := h.peekMyVote(); ok {
    gp := h.GetParamSet(header.Number.Uint64())
    if gp.GovernanceMode != "single" || h.nodeAddress == gp.GoverningNode {
        // include vote
    }
}
```

**Option B:** In `VerifyVote()`, remove the `IsPermissionlessForkEnabled` gate so the governing-node check applies in all forks when `GovernanceMode == "single"`:

```go
if params.GovernanceMode == "single" && vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
```

**Option C:** Clear `myVotes` whenever the effective governing node changes (detected in `PostInsertBlock` when a `governance.governingnode` ratification is processed).

---

### Proof of Concept

1. Governance mode is `single`; Node A (`0xAAAA`) is the governing node; epoch = 604800.
2. At block 604500, Node A calls `governance_vote("reward.mintingamount", 1e30)`. The vote is stored in `h.myVotes`. [1](#0-0) 
3. At block 604800 (epoch boundary), a previously ratified `governance.governingnode` vote takes effect, changing the governing node to Node B (`0xBBBB`). Node A is still in the council.
4. At block 605001, Node A is selected as proposer. `PrepareHeader()` calls `peekMyVote()` and writes the stale `reward.mintingamount = 1e30` vote into `header.Vote` without checking if Node A is still the governing node. [2](#0-1) 
5. `VerifyVote()` is called during block validation:
   - Node A is in council → passes line 88.
   - Node A is the proposer → passes line 97.
   - `IsPermissionlessForkEnabled` is false → the governing-node check at lines 101–107 is **skipped**. [3](#0-2) 
6. `PostInsertBlock` calls `HandleVote`, which calls `AddVote`, storing the stale vote in `groupedVotes[epochIdx]`.
7. At block 1209600 (next epoch boundary), `getExpectedGovernance()` collects all votes from the previous epoch. The stale `reward.mintingamount = 1e30` vote is the only vote for that parameter and is ratified. [4](#0-3) 
8. From block 1814400 onward, `reward.mintingamount = 1e30` is the effective parameter, causing unauthorized KAIA minting at every block.

```go
func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
```

```go
func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
```
