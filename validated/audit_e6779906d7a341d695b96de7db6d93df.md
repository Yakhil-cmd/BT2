### Title
Cross-tenant stack manipulation via unauthenticated `pull_request` webhook — signature verified against `repository.owner.login` while handlers act on unrelated `repository.full_name` - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook using the organization derived from `params.dig('repository','owner','login')`, but the `pull_request` handlers (e.g. `ReopenedHandler`) look up the target repository/stack using a completely separate field, `params.repository.full_name`. Because nothing binds these two fields together, and because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved organization's config has no `webhook_secret`, an attacker can pick an org with no secret configured for the "owner.login" field to pass verification while pointing `repository.full_name` at an arbitrary victim repository/stack.

### Finding Description
The broken binding: the code implicitly assumes
`params.dig('repository','owner','login') == owner(params.repository.full_name)`,
i.e. that the organization used to select the `GitHubApp`/secret for HMAC verification is the same organization that owns the repository the event will be applied to. This is never actually checked.

Path:
1. `Shipit::WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')`. [1](#0-0) [2](#0-1) 
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` when the resolved organization's config has a blank `webhook_secret`: [3](#0-2) 
3. If verification passes, `create` dispatches the raw, attacker-controlled JSON body to the handlers for the event, with no further authentication: [4](#0-3) 
4. `ReopenedHandler` (and every other `pull_request` handler) resolves the target repository/stack purely from `params.repository.full_name`, a field completely independent from `repository.owner.login` used above: [5](#0-4) 
5. `ReviewStackAdapter#unarchive!` then unarchives/creates a `ReviewStack` on the target stack (looked up by `full_name`), acting as `params.sender.login` as the triggering user: [6](#0-5) 

Exploit flow: attacker crafts a JSON body where `repository.owner.login = "attacker-no-secret-org"` (a real org configured in Shipit but whose `github` config in `secrets.yml` lacks `webhook_secret`) while `repository.full_name = "victim-org/victim-repo"` (a real victim repository/stack configured with `blocking_statuses`). They POST it, unsigned or with an arbitrary `X-Hub-Signature` header, to `/webhooks` with `X-Github-Event: pull_request` and `action: "reopened"`. `verify_signature` resolves the GitHubApp for `attacker-no-secret-org`, finds no secret, and returns `true` regardless of the header — no HMAC computation over the body occurs at all. The dispatcher then hands the entire payload (including the victim's `full_name`) to `ReopenedHandler`, which resolves the victim's `Repository`/`ReviewStack` via `full_name` and unarchives/creates a `ReviewStack`, re-provisioning it and re-associating a `PullRequest` and `sender`-derived `User` on the victim's stack, all without ever validating a secret tied to that victim repository/org.

Existing guards fail because: `drop_unhandled_event` only checks the event type is registered, not repository identity; `verify_signature` binds trust to `repository.owner.login` only, never cross-checking it against `repository.full_name`; there is no `ExplicitParameters` constraint tying `repository.full_name`'s owner segment to `repository.owner.login`; and `GitHubApp#verify_webhook_signature`'s blank-secret bypass (`return true unless webhook_secret`) makes this trivially reachable for any org lacking a secret.

### Impact Explanation
An unprivileged internet user (no Shipit session, no GitHub webhook secret, not a maintainer of the victim repo) can forge a `pull_request`/`reopened` webhook that unarchives and re-provisions a `ReviewStack` belonging to an arbitrary victim repository configured in the same Shipit instance, as long as at least one other configured GitHub organization/app in Shipit has no `webhook_secret` set. Because the victim stack can have `blocking_statuses` configured, the unarchived/recreated `ReviewStack` participates again in deploy gating (`blocked?`), and the attacker also controls `pull_request.head.sha`/`ref` and can subsequently forge `status`/`check_run` events (through the same signature-bypass technique) to flip that gate. This is a payload for one repository (`attacker-no-secret-org/...`, verified) mutating another repository's stack/records (`victim-org/victim-repo`), matching the Critical category "a payload for one repository mutating another's stack, commit, task or team."

### Likelihood Explanation
Preconditions: (1) Shipit must have ≥2 configured GitHub organizations, one of which has no `webhook_secret` in its config (a realistic multi-tenant Shipit deployment misconfiguration, not requiring any secret knowledge by the attacker); (2) the victim organization/repo/stack must exist and have review-stacks/provisioning enabled with `blocking_statuses`. No attacker credentials, sessions, or GitHub secrets are required — only the ability to send an arbitrary HTTP POST to `/webhooks`, which is unauthenticated by design (webhook endpoint). This is fully repeatable against any repository in the instance and requires no interaction from the victim.

### Recommendation
Bind the verified organization to the acted-upon repository: derive `repository_owner` for signature verification from the same repository record the handlers use (e.g., parse the owner out of `params.repository.full_name`, or require they match and reject on mismatch), and remove/guard the blank-secret bypass in `GitHubApp#verify_webhook_signature` (fail closed, or require `webhook_secret` to be present for every configured organization at boot). Additionally, have handlers validate that `params.repository.full_name`'s owner segment equals the `repository_owner` used to authenticate the request before acting on any `Repository`/`Stack`.

### Proof of Concept
Minitest plan (webhooks controller test, no live GitHub):
1. Configure two orgs in `Shipit.github` test config: `"attacker-org"` with `webhook_secret: nil`, and `"victim-org"` with a normal `webhook_secret` set.
2. Create `victim_repo = Shipit::Repository.create!(name: "victim-repo", owner: "victim-org", ..., review_stacks_enabled: true, provisioning_behavior: :allow_all)` and a `victim_stack` (e.g. `ReviewStack`) with `blocking_statuses` configured, archived (`archived: true`, or pre-archive it).
3. Assert precondition: `victim_stack.archived?` is `true` (or the review stack does not yet exist).
4. Build payload: `{ action: "reopened", number: N, pull_request: {...valid fields..., head: {sha: "...", ref: "pr-branch"}}, repository: { owner: { login: "attacker-org" }, full_name: "victim-org/victim-repo" }, sender: { login: "attacker" } }`.
5. POST to `/webhooks` with header `X-Github-Event: pull_request` and an arbitrary/garbage `X-Hub-Signature` (e.g., `sha1=deadbeef`), no valid HMAC.
6. Assert response is `200 OK` (not `422`), proving `verify_signature` passed despite the bogus signature (equality check: `verify_webhook_signature` returned `true` for org "attacker-org" with `webhook_secret: nil`).
7. Reload `victim_stack` from DB and assert `victim_stack.archived? == false` (or that a new `Shipit::ReviewStack` was created under `victim_repo`) — proving the victim repository's stack (authenticated by nobody's secret) was mutated by a payload verified only against `attacker-org`'s configuration.
8. Equality check before/after: before, `authenticated_org = "attacker-org"` and `acted_upon_repo = nil`; after, `authenticated_org = "attacker-org"` while `acted_upon_repo = "victim-org/victim-repo"` — the two diverge, confirming the invariant "a pull_request event only affects the repository/stack whose secret authenticated it" is violated.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
