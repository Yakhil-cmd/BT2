### Title
Cross-tenant Stack mutation via mismatched `repository.owner.login` vs `repository.full_name` in webhook processing - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC key by reading `repository.owner.login` from the JSON body, while `Handler#stacks`/`#repository_name` (used by `PushHandler#process`) independently reads `repository.full_name` to locate the `Stack` to mutate. Nothing binds these two fields together, so a payload signed by org A's secret but naming org B's repo in `full_name` will pass verification and trigger `GithubSyncJob` on org B's `Stack`.

### Finding Description
The broken binding: the equality that should hold is `repository.owner.login == full_name.split('/').first`, i.e. the org whose secret authenticated the request must equal the owner of the repository the handler acts on.

Trace:
- `WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner)`, where `repository_owner` is `params.dig('repository','owner','login')` [1](#0-0) , and only checks `verify_webhook_signature(signature, raw_post)` against that org's `webhook_secret` [2](#0-1) .
- `Shipit.github` resolves per-organization config via `github_app_config(organization)` in a multi-org setup [3](#0-2) , so any org with its own registered `webhook_secret` can independently authenticate a request.
- Once verified, `WebhooksController#create` dispatches the full raw payload to `Shipit::Webhooks.for_event(event)` handlers, which never re-read `repository_owner` [4](#0-3) .
- `Handler#repository_name` reads `payload.dig('repository', 'full_name')` [5](#0-4) , and `Handler#stacks` resolves `Repository.from_github_repo_name(repository_name)` [6](#0-5) , which simply splits on `/` and does a DB lookup with no cross-check against the login that authenticated the request [7](#0-6) .
- `PushHandler#process` then runs `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` [8](#0-7) , enqueuing `GithubSyncJob` for whatever stack matches `full_name`, regardless of which org's secret was used to authenticate.

Exploit: attacker controls `attacker-org` with a valid app/`webhook_secret` registered in Shipit's multi-org GitHub config. They POST to `/webhooks` with header `X-Github-Event: push`, body `repository.owner.login = "attacker-org"`, `repository.full_name = "victim-org/victim-repo"`, `ref = "refs/heads/<victim-branch>"`, and a valid `X-Hub-Signature` computed with `attacker-org`'s real `webhook_secret` over the exact raw body. `verify_signature` picks `Shipit.github(organization: "attacker-org")`, which validates the HMAC successfully (since attacker legitimately owns that secret), and the request proceeds to `PushHandler`, which looks up and mutates the `victim-org/victim-repo` stack.

No existing guard prevents this: `verify_signature` never compares `repository_owner` against `full_name`'s owner segment; `drop_unhandled_event` only checks whether a handler exists for the event type; `ExplicitParameters` schemas in handlers only validate presence/types of `full_name`, not consistency with the authenticating org; `Repository.from_github_repo_name` performs a pure lookup with no authorization check.

### Impact Explanation
A payload authenticated with `attacker-org`'s legitimate webhook secret enqueues `GithubSyncJob` against `victim-org/victim-repo`'s existing `Stack`, forcing a GitHub sync that can trigger continuous delivery/deploys on a repository the attacker does not own or control. This is repeatable against any repository with a registered `Stack` on any branch and requires no privileged Shipit role — only that the attacker's own org is configured as a tenant in `Shipit.github`'s multi-org config. This matches the "Critical" category: a payload for one repository (attacker-org) mutating another's (victim-org) stack via cross-tenant write, using a signature that authenticates the wrong owner.

### Likelihood Explanation
Requires: (1) Shipit deployed with multi-org GitHub App config (`Shipit.github_organizations` non-trivial), (2) attacker's own org registered as a tenant with a real `webhook_secret` they legitimately possess, (3) a victim `Stack` existing for a targeted branch. All of these are consistent with the stated preconditions and require no secrets beyond what the attacker legitimately owns for their own org. The attack is a single crafted HTTP POST with a valid HMAC computed over their own secret — trivial and fully repeatable against any known victim repo/branch.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler`), after establishing which org's secret authenticated the request, validate that `repository.full_name`'s owner segment (and/or `organization.login`) matches `repository_owner` before dispatching to handlers; reject with 422 on mismatch. Alternatively, derive the target repository/organization strictly from the same field used for signature verification, and pass it explicitly into `Handler#stacks`/`repository_name` rather than re-parsing an independent field from the same payload.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "push signed by attacker-org does not mutate victim-org's stack" do
  victim_stack = shipit_stacks(:shipit) # owner: 'shopify' (or configure a victim org/repo & stack fixture)
  Shipit.stubs(:github_app_config).with('attacker-org').returns(webhook_secret: 'attacker-secret')

  payload = JSON.parse(payload(:push_master))
  payload['repository']['owner']['login'] = 'attacker-org'
  payload['repository']['full_name'] = victim_stack.repository.full_name # e.g. 'shopify/shipit-engine'
  body = payload.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', 'attacker-secret', body)

  @request.headers['X-Github-Event'] = 'push'
  @request.headers['X-Hub-Signature'] = signature

  # Assert attacker-org's secret is what verified the payload
  Shipit.github(organization: 'attacker-org').expects(:verify_webhook_signature).with(signature, body).returns(true)

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: payload['after']]) do
    post :create, body:, as: :json
  end
end
```
This asserts both sides of the equality: `repository_owner ("attacker-org")` verified the signature (left side), while `GithubSyncJob` is enqueued for `victim_stack` derived from `full_name`'s owner (right side, a different org) — confirming they diverge and the mutation goes through unauthorized.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
