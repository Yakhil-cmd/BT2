### Title
Unbounded `reward.mintingamount` Governance Vote Causes Unlimited KAIA Minting Per Block — (`File: kaiax/gov/param.go`)

### Summary

In Kaia's header governance system, the `reward.mintingamount` parameter uses `noopFormatChecker`, which imposes no upper bound on the value. In `none` governance mode (the default for non-mainnet chains), any council member can cast a vote setting `reward.mintingamount` to an arbitrarily large `*big.Int`. The vote is ratified at the next epoch with no additional consistency check, and every subsequent block mints that astronomical amount of KAIA directly into validator and fund balances via `FinalizeState`.

### Finding Description

The `RewardMintingAmount` parameter definition in `kaiax/gov/param.go` uses `noopFormatChecker`, which always returns `true`: [1](#0-0) 

This means any `*big.Int` value — including values orders of magnitude larger than the total KAIA supply — passes format validation. The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` explicitly returns `nil` for `RewardMintingAmount` with no additional state check: [2](#0-1) 

In `none` governance mode, the `VerifyVote` function only enforces the single-mode governing-node restriction; in `none` mode any council member may cast a vote: [3](#0-2) 

The `Vote` API enforces the same restriction only for `single` mode: [4](#0-3) 

`none` mode is the `DefaultValue` for `GovernanceGovernanceMode`: [5](#0-4) 

At every epoch block, `getExpectedGovernance` collects all votes from the previous epoch and ratifies the last vote per parameter with no value-range check: [6](#0-5) 

Once ratified, `NewRewardConfig` reads `paramset.MintingAmount` directly and passes it to the reward calculation functions: [7](#0-6) 

The reward calculation uses `config.MintingAmount` without any cap: [8](#0-7) 

### Impact Explanation

Every block after the ratified epoch mints the attacker-specified amount of KAIA and distributes it to validators and ecosystem funds. This constitutes unauthorized minting of KAIA (a protected asset). The corrupted value is `ParamSet.MintingAmount`, which flows directly into `RewardConfig.MintingAmount` and then into `spec.Minted` in every block's `FinalizeState`. The total KAIA supply can be inflated to an arbitrary value within a single epoch, permanently corrupting the token economy.

### Likelihood Explanation

In `none` governance mode (the default for any Kaia-derived chain that does not explicitly configure `single` mode), a single council member — a semi-trusted actor who is already a registered validator — can trigger this unilaterally. No majority collusion is required; the last vote in the epoch wins. The `governance.governancemode` parameter is in `AlwaysDeprecated` and cannot be changed via vote, so a `none`-mode chain is permanently exposed. [9](#0-8) 

### Recommendation

Add an upper-bound `FormatChecker` for `RewardMintingAmount` analogous to the existing checks for other parameters. For example, reject any value exceeding a protocol-defined maximum (e.g., `1e27` kei, roughly 1 billion KAIA). Additionally, add a `checkConsistency` case for `RewardMintingAmount` that enforces this bound at vote-verification time, preventing a ratified governance block from encoding an out-of-range value.

### Proof of Concept

1. Deploy a Kaia network with default `governance.governancemode = "none"` (the `DefaultValue`).
2. Council member A calls:
   ```
   governance_vote("reward.mintingamount", "999999999999999999999999999999999999999999999999999999999999")
   ```
3. `NewVoteData` succeeds: `bigIntCanonicalizer` parses the string to a valid `*big.Int`; `noopFormatChecker` returns `true`.
4. `VerifyVote` passes: voter is in council, is the block proposer, mode is `none` so no governing-node restriction, `checkConsistency` returns `nil`.
5. At the next epoch block, `getExpectedGovernance` collects the vote and writes it to `header.Governance`. `VerifyGov` confirms it matches the locally derived governance — it does.
6. `PostInsertBlock` → `HandleGov` → `AddGov` stores the ratified value. `GetParamSet` now returns `MintingAmount = 999...999`.
7. Every subsequent block: `NewRewardConfig` sets `rc.MintingAmount = 999...999`; `getDeferredRewardSimple` / `getDeferredRewardFull` mints this amount and credits it to validator and fund addresses via `FinalizeState`.
8. The KAIA total supply is inflated by `999...999` kei per block, permanently. [10](#0-9) [2](#0-1) [11](#0-10)

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

// getDeferredRewardSimple is for Simple policy.
func getDeferredRewardSimple(config *reward.RewardConfig, execFee, blobFee *big.Int) (*reward.RewardSpec, error) {
	spec := reward.NewRewardSpec()
	minted := new(big.Int).Set(config.MintingAmount)

	// Non-deferred mode
	if !config.DeferredTxFee {
		var proposer *big.Int
		if config.Rules.IsMagma {
			// In non-deferred mode, no fees to distribute here at the end of block processing.
			// Just distribute the minting reward to the proposer and stop.
			proposer = new(big.Int).Set(minted)
			execFee = big.NewInt(0)
		} else {
			// But Simple policy had a bug where transaction fees were distributed to the proposer here at the end of block processing
			// despite configured to non-deferred mode. To keep the backward compatibility, the buggy behavior retains until Magma.
			proposer = new(big.Int).Add(minted, execFee)
		}
		spec.Minted = new(big.Int).Set(minted)
		// Both exec fees and blob fees are burned during state transition in non-deferred mode,
		// not at finalization. TotalFee/BurntFee are completed by specWithNonDeferredFee (GetBlockReward only).
		spec.TotalFee = execFee // Note that we've set it to 0 for non-deferred + Magma (see above).
		spec.BurntFee = big.NewInt(0)
		spec.Proposer = proposer
		spec.IncRecipient(config.Rewardbase, proposer)
		return spec, nil
	}

	// Deferred mode
	burntFee := big.NewInt(0)
	if config.Rules.IsMagma {
		burntFee = getBurnAmountMagma(execFee)
	}
	proposer := new(big.Int).Add(minted, execFee)
	proposer.Sub(proposer, burntFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Proposer = proposer
	spec.IncRecipient(config.Rewardbase, proposer)
	return spec, nil
