## Title
Webhook signature verification keys off `repository.owner.login` while handlers act on `repository.full_name` from the same untrusted payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate a request against using `repository_owner`, a value read directly out of the *unauthenticated* JSON body (`params.dig('repository', 'owner', 'login')`), not out of any property of the actual HTTP connection or App installation that delivered the request. [1](#0-0) [2](#0-1) 

### Finding Description
`Shipit.github(organization: repository_owner)` looks up the per-organization `webhook_secret` from the multi-org config, and `verify_webhook_signature` then HMACs the raw body against that secret: [3](#0-2) 

The value used to pick *which* secret validates the signature (`repository.owner.login`) is an attacker-controlled field inside the very payload being verified, and it is never checked for equality against the field the downstream event handlers use to decide *which repository/stack the payload acts on* (`repository.full_name`, as exercised in the "create github repository which is not yet present in the datastore" test, which mutates only `repository.full_name`): [4](#0-3) 

This creates exactly the kind of authenticated-vs-acted-upon mismatch called out by the source report class (a check performed against one field, an operation performed against a different, unguarded field of the same structure): the equality that should hold is
`organization whose webhook_secret validated the signature == owner of the repository the handler will write to`,
but nothing in `verify_signature` or the payload processing enforces `repository.owner.login == owner-portion-of(repository.full_name)`.

A user who administers (and therefore knows the configured webhook secret for) their own GitHub organization "orgA" — which is legitimately registered as one of the multiple organizations in Shipit's `github:` config — can craft an arbitrary webhook body where `repository.owner.login` is set to `"orgA"` (so `verify_signature` validates using the secret they know) but `repository.full_name` (and any other repository fields the handler dispatches on) points at `"orgB/some-other-repo"`, a stack they do not control. Because the signature check never re-derives or cross-checks the acting repository from the same field used to pick the secret, the forged event is accepted as authentic and dispatched to `Shipit::Webhooks.for_event(event)` handlers for `orgB`'s stack. [5](#0-4) 

### Impact Explanation
This allows an attacker who only controls one organization/repository already onboarded to a shared, multi-org Shipit instance to forge authenticated-looking webhook events (`push`, `status`, `check_suite`, `membership`, etc.) targeting a different organization's stack, e.g. triggering `GithubSyncJob` against another team's repository/branch, injecting forged commit statuses/check-suite results that influence merge/deploy decisions on that other repository, or manipulating `Team`/`Membership` records for an org they don't administer. This is a cross-repository write / cross-organization forgery achieved purely with knowledge of a secret the attacker is legitimately entitled to (their own org's webhook secret), matching the Critical "cross-repository writes" impact bucket.

### Likelihood Explanation
Requires only that the Shipit deployment is configured for multiple GitHub organizations (a documented, supported configuration, see `config/secrets.development.shopify.yml`) and that the attacker administers one of those organizations' GitHub App installations (thus knows its `webhook_secret`) — no Shipit session, `ApiClient` token, or repository write access to the victim org is needed. [6](#0-5) 

### Recommendation
In `verify_signature`, after determining `repository_owner` and validating the signature, re-derive the repository/organization identity from an independent, structurally-bound field (or explicitly assert `repository.owner.login` matches the owner segment of `repository.full_name`/`organization.login` used later by handlers) before dispatching to `Shipit::Webhooks` handlers, rejecting the request if they disagree.

### Proof of Concept
1. Shipit is configured with two orgs, `orgA` and `orgB`, each with its own `webhook_secret` (as in the documented multi-org config).
2. Attacker administers `orgA`'s GitHub App and knows `webhook_secret_A`.
3. Attacker crafts body:
```json
{
  "repository": { "owner": { "login": "orgA" }, "full_name": "orgB/victim-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker chosen sha>"
}
```
4. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(webhook_secret_A, body)>` and sends `POST /webhooks` with `X-Github-Event: push`.
5. `verify_signature` computes `repository_owner = "orgA"`, fetches `webhook_secret_A`, verifies successfully, and the request proceeds to the push handler, which acts on `repository.full_name == "orgB/victim-repo"`. [7](#0-6)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
