## Analog Found

### Title
Arbiter shared-address definition bakes in a stale arbstore payout address that diverges from the address later used to compose the settlement payment, freezing contract funds - (File: arbiter_contract.js)

### Summary
`arbiter_contract.js` derives the multisig oscript definition for an arbiter contract by fetching the arbstore's payout address once at contract-creation time and permanently embedding it into the immutable shared-address definition. Later, when the contract is settled via `complete()`, the actual payout transaction is composed using a *different*, independently-fetched value for the arbstore's address. Because the shared address's oscript definition hard-codes the address captured at creation time, any divergence between that value and the address used at settlement time causes the payout to fail the address-and-amount condition baked into the definition, leaving contract funds permanently stuck.

### Finding Description
When an offeror creates an arbiter contract, `deriveSharedAddress()` calls `arbiters.getArbstoreInfo(contract.arbiter_address, ...)`, which fetches `info.address` (the arbstore's payout address) from the arbstore's own `/api/get_info` HTTP endpoint and caches it forever in the in-process map `arbStoreInfos` (no expiry/invalidation): [1](#0-0) 

This `arbstoreInfo.address` value is baked directly into the multisig oscript definition's `"has"` output condition as a fixed literal address and amount: [2](#0-1) 

The resulting `arrDefinition` is hashed to produce the immutable `shared_address` and posted on-chain (`createSharedAddressAndPostUnit`), so the arbstore payout address baked into it can never be changed thereafter: [3](#0-2) 

Independently, `objContract.arbstore_address` — the value actually used when composing the final settlement payment in `complete()` — comes from a *different* code path: `fillArbstoreAddresses()` → `getArbstoreAddresses()`, which queries the hub via `hub/get_arbstore_address` (backed by the `arbiter_locations` table and hub-side `conf.arbstores` mapping), not the arbstore's `/api/get_info` response used for the definition: [4](#0-3) 

At completion, `complete()` uses this independently-sourced `objContract.arbstore_address` as the literal payout address for `arbstore_amount`: [5](#0-4) 

Since the shared address's oscript definition requires an output exactly matching the address that was baked in at creation time (via `arbstoreInfo.address` from `getArbstoreInfo`), any mismatch between that value and the `arbstore_address` used later (obtained from the separate hub-registry lookup, or from a stale/updated `arbStoreInfos` cache entry) means the composed settlement transaction cannot satisfy the address-and-amount `"has"` condition embedded in the immutable definition. This mirrors the reported Vault bug class exactly: a factory-supplied/config-supplied address is captured once and permanently frozen into a contract, while another part of the system later relies on a possibly different current value for the same logical recipient.

### Impact Explanation
If the two address sources diverge (e.g., the arbstore updates its payout address via `/api/get_info` after the contract's shared address was already created and posted, or the hub-registered `arbstore_address` differs from the address the arbstore actually wants funds sent to), the completion payment built by `complete()` will not satisfy the oscript condition baked into the shared address. This causes the settlement unit to be rejected/invalid, so the escrowed contract funds held in the shared (multisig) address become permanently unspendable through the expected code path — a freezing-of-funds outcome. This matches the report's core concern (fees/payouts routed based on a stale, deployment-time-cached address rather than the current authoritative one) applied to the arbiter-contract escrow flow.

### Likelihood Explanation
This is reachable by any two unprivileged wallet users who negotiate and post an arbiter contract (a normal user-facing feature, not requiring any special privilege), and is triggered purely by the arbstore/hub-side address configuration changing between contract creation and completion — a plausible operational event (arbstore payout-address rotation, migration, or hub/arbstore registry inconsistency), not requiring an on-path attacker.

### Recommendation
Use a single, consistent, freshly-verified source for the arbstore payout address at both definition-derivation time and completion time. Before finalizing the definition and again immediately before composing the settlement payment, re-fetch and cross-check `arbiters.getArbstoreInfo(...).address` against `objContract.arbstore_address`; if they differ, refuse to compose the payment (or re-derive against the currently valid address recorded in the definition) rather than silently using a possibly mismatched value. Alternatively, cache the exact address baked into the posted shared-address definition and always source `complete()`'s payout target from that same immutable record instead of the independently-refreshed `hub/get_arbstore_address` value.

### Proof of Concept
1. User A and User B create an arbiter contract with arbiter `X`; at this time `arbiters.getArbstoreInfo(X)` returns arbstore payout address `P1`, which gets embedded into the shared address's oscript `"has"` condition (`arbiter_contract.js:519`).
2. The shared address is derived and posted on-chain (`createSharedAddressAndPostUnit`), permanently fixing `P1` as the required arbstore payout recipient.
3. Before the contract reaches `complete()`, the arbstore's registered address changes (hub-side `arbiter_locations`/`conf.arbstores` mapping is updated to `P2`, or the arbstore's `/api/get_info` now returns `P2`) — this is an operational, non-attacker event.
4. When `complete()` runs, `fillArbstoreAddresses()` fetches `objContract.arbstore_address = P2` (since it wasn't previously cached, or the wallet process restarted and re-queried).
5. `complete()` composes the settlement payment with `address: P2` for the arbstore cut (`arbiter_contract.js:769`), but the shared address's immutable oscript definition requires an output to `P1` with the exact precomputed amount.
6. The composed unit fails validation against the shared address's spending conditions, and the settlement transaction cannot be confirmed — the escrowed funds in the shared address remain stuck.

function getArbstoreInfo(arbiter_address, cb) {
	if (!cb)
		return new Promise(function(resolve, reject){
			getArbstoreInfo(arbiter_address, function(err, info){
				if (err) return reject(err);
				resolve(info);
			});
		});
	if (arbStoreInfos[arbiter_address]) return cb(null, arbStoreInfos[arbiter_address]);
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err) {
			return cb(err);
		}
		if (!validationUtils.isNonemptyString(url))
			return cb("invalid url received from hub");
		requestInfoFromArbStore(url+'/api/get_info', function(err, info){
			if (err)
				return cb(err);
			if (!validationUtils.isNonemptyObject(info))
				return cb("invalid info received from arbstore");
			const cut = parseFloat(info.cut);
			if (!info.address || !validationUtils.isValidAddress(info.address) || isNaN(cut) || cut < 0 || cut >= 1) {
				return cb("malformed info received from ArbStore");
			}
			info.url = url;
			arbStoreInfos[arbiter_address] = info;
			cb(null, info);
		});
	});
}

function getArbstoreAddresses(arbiter_address, cb) {
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err)
			return cb(err);
		device.requestFromHub("hub/get_arbstore_address", arbiter_address, function(err, arbstore_address){
			if (err) {
				return cb(err);
			}
			httpRequest(url, "/api/get_device_address", "", function(err, arbstore_device_address) {
				if (err) {
					console.warn("no arbstore_device_address", err);
					return cb(err);
				}
				cb(null, { arbstore_address, arbstore_device_address });
			});
		});
	});
}

function fillArbstoreAddresses(objContract, cb) {
	if (!cb)
		return new Promise(resolve => fillArbstoreAddresses(objContract, resolve));
	if (objContract.arbstore_device_address && objContract.arbstore_address)
		return cb();
	getArbstoreAddresses(objContract.arbiter_address, function(err, result) {
		if (err)
			return cb(err);
		var { arbstore_address, arbstore_device_address } = result;
		objContract.arbstore_address = arbstore_address;
		objContract.arbstore_device_address = arbstore_device_address;
		db.query("UPDATE wallet_arbiter_contracts SET arbstore_address=?, arbstore_device_address=? WHERE hash=?", [arbstore_address, arbstore_device_address, objContract.hash], function () { cb(); });
	});
}

function createSharedAddressAndPostUnit(hash, walletInstance, cb) {
	deriveSharedAddress(hash, true, function(err, arrDefinition, assocSignersByPath) {
		if (err)
			return cb(err);
		require("./wallet_defined_by_addresses.js").createNewSharedAddress(arrDefinition, assocSignersByPath, {
			ifError: function(err){
				cb(err);
			},
			ifOk: function(shared_address){
				setField(hash, "shared_address", shared_address, async function(contract) {
					const err = await fillArbstoreAddresses(contract);
					if (err)
						return cb(err);
					// share this contract to my cosigners for them to show proper ask dialog
					shareContractToCosigners(contract.hash);
					shareUpdateToPeer(contract.hash, "shared_address");

					const contacts_hash = getContactsHash(contract);

					// post a unit with contract text hash and send it for signing to correspondent
					var value = {"contract_text_hash": contract.hash, "arbiter": contract.arbiter_address, contacts_hash};
					var objContractMessage = {
						app: "data",
						payload_location: "inline",
						payload_hash: objectHash.getBase64Hash(value, true),
						payload: value
					};

					walletInstance.sendMultiPayment({
						spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own',
						asset: "base",
						to_address: shared_address,
						amount: exports.CHARGE_AMOUNT,
						arrSigningDeviceAddresses: contract.cosigners.length ? contract.cosigners.concat([contract.peer_device_address, device.getMyDeviceAddress()]) : [],
						signing_addresses: [shared_address],
						messages: [objContractMessage]
					}, function(err, unit) { // can take long if multisig
						if (err)
							return cb(err);

						// set contract's unit field
						setField(contract.hash, "unit", unit, function(contract) {
							shareUpdateToPeer(contract.hash, "unit");
							setField(contract.hash, "status", "signed", function(contract) {
								cb(null, contract);
							});
						});
					});
				});
			}
		});
	});
}
