### Title
Delegate can redirect borrow/withdraw proceeds to an arbitrary address, draining account funds — ([File: contracts/controller/src/positions/supply.rs])

### Summary
The Singularity bug class (insecure permissions enabling malicious redirection of operations) maps onto XOXNO Lending's delegate authorization: `borrow` and `withdraw` accept a caller-chosen `to: Option<Address>` recipient, and the only gate is `require_owner_or_delegate`. An approved position-manager delegate — not the account owner — can pass `to = <attacker address>` and send the account's borrowed or withdrawn collateral anywhere, not just to itself or the owner. The only recipient validation is `require_external_recipient`, which merely rejects the pool and controller contracts.

### Finding Description
- `process_withdraw` authenticates the caller via `require_owner_or_delegate` and then uses `to.unwrap_or(caller)` as the payout recipient, passing it through `require_external_recipient`, which only blocks protocol contracts (see `recipient_is_protocol_contract.rs` test: pool/controller rejected, anything else accepted). [1](#0-0) 
- `borrow` has the same shape: "sending the funds to `to` if provided or to the caller otherwise". [2](#0-1) 
- `is_owner_or_delegate` admits any caller that is a registered active position manager present in the account's delegate list; the delegate set is not required to return funds to the owner. [3](#0-2) 
- A delegate's legitimate role is to manage position strategies (`multiply`, `swap_collateral`, etc.) where proceeds redeposit into the account — none of that requires arbitrary external payout on `borrow`/`withdraw`. Nothing in the code or docs pins `to` to the account owner.

### Impact Explanation
Theft of user funds. Any account that has ever called `add_delegate` for a governance-approved manager gives that manager the ability to (a) withdraw all collateral and (b) borrow up to the account's LTV limits, with proceeds sent to an address the delegate controls. Since delegates are approved *managers* rather than owners, users plausibly grant delegation expecting bounded management authority — the permission set granted is broader than the permission users intend, exactly like world-writable state enabling redirection. Delegate grants also persist until `remove_delegate` or an NFT transfer deactivates them, so the exposure window is long.

### Likelihood Explanation
Requires the victim to have added a delegate (a normal flow for managed accounts), and the delegate to act maliciously or be compromised. Because the delegate must be a governance-approved active manager, this is a trusted-party-abuse scenario rather than a fully unprivileged attack — hence High rather than Critical. On the allowed-path side it is trivially reachable: `withdraw(caller=delegate, account_id, withdrawals, to=Some(attacker))`.

### Recommendation
In `process_withdraw` and `process_borrow`, restrict `to`: when the caller is a delegate rather than the owner, require `to` to be `None` or equal to `account.owner`. Alternatively, always pay withdrawals/borrows to the account owner and let managers route profits through the strategy entrypoints, which already redeposit into the account.

### Proof of Concept
1. Owner creates account `A`, supplies collateral, calls `add_delegate(owner, A, manager)` where `manager` is an active approved position manager.
2. `manager` calls `withdraw(caller=manager, account_id=A, withdrawals=[(USDC, 0)], to=Some(evil))` — zero means withdraw-all.
3. `require_owner_or_delegate` passes (delegate); `require_external_recipient` passes (`evil` is not pool/controller); pool pays `evil`. Solvency check trivially passes if account has no debt.
4. Repeat with `borrow(..., to=Some(evil))` up to the LTV limit to extract remaining borrowable value, leaving the account with maximal debt.

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
