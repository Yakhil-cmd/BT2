### Title
Path traversal in git extension pin-file write via unvalidated commit SHA - (File: pkg/cmd/extension/manager.go)

### Summary
`installGit` builds the pin marker filename with `fmt.Sprintf(".pin-%s", commitSHA)` where `commitSHA` comes directly from `fetchCommitSHA`'s HTTP response body, and `fetchCommitSHA` performs no format validation (no 40-hex-char check) before returning the raw body text. Because `filepath.Join` resolves `..` segments embedded in that string, a server response containing path-traversal sequences can move `pinPath` outside the extension's install directory, letting `os.OpenFile(pinPath, os.O_WRONLY|os.O_CREATE, 0600)` create/truncate a file at an attacker-chosen location on the victim's filesystem.

### Finding Description
- `Manager.installGit` (`pkg/cmd/extension/manager.go`) computes `commitSHA, err = fetchCommitSHA(m.client, repo, target)` when a `--pin` target is supplied, then: [1](#0-0) 
  builds `pinPath := filepath.Join(targetDir, fmt.Sprintf(".pin-%s", commitSHA))` and writes it with `os.OpenFile(pinPath, os.O_WRONLY|os.O_CREATE, 0600)`.
- `fetchCommitSHA` (`pkg/cmd/extension/http.go`) issues `GET repos/{owner}/{repo}/commits/{targetRef}` with `Accept: application/vnd.github.v3.sha`, and on any 2xx status simply returns `string(body)` unmodified — no regex/length check that the payload is a genuine SHA-1 hex string: [2](#0-1) 
- Against real `github.com`/`api.github.com` this endpoint legitimately always returns a 40-hex-character SHA, so the value is effectively trusted as safe. However, the attacker-controlled surface here is a "host the victim points gh at" (an enterprise/custom `GH_HOST` the victim has configured, or any endpoint whose responses the attacker controls per the rules of this audit) hosting the attacker's malicious repository. Such a server can return an arbitrary 2xx response body for the commits endpoint, e.g. `"../../../../../../home/victim/.ssh/authorized_keys"` or similar.
- `filepath.Join` lexically cleans `..` components, so `filepath.Join(targetDir, ".pin-../../../../../../home/victim/.ssh/authorized_keys")` resolves outside `targetDir`, and the subsequent `os.OpenFile(..., os.O_CREATE|os.O_WRONLY, 0600)` creates (or truncates, since the file may already exist depending on open flags — note `O_TRUNC` is not set here so an existing file's content is preserved but its permissions/mtime are touched, and if it doesn't exist a new empty file is created at the attacker-chosen path).
- No existing check (ghrepo/ghinstance host validation, safepaths, or a SHA format validator) intercepts this value between the HTTP response and the filesystem write.

### Impact Explanation
This is a scoped arbitrary file write outside the intended extension directory (file creation is the exploitable primitive since the flags used don't set `O_TRUNC`, but combined with predictable file naming this can be used to create marker/config files in attacker-chosen paths, or overwrite files that don't yet exist). This matches GitHub's "file write outside the intended path" bounty impact class. Actual code execution would additionally require the created path to be a location that is later executed/sourced (e.g., a shell rc file), which is plausible but not directly demonstrated here.

### Likelihood Explanation
Requires the victim to run `gh extension install <attacker-repo> --pin <ref>` (or otherwise trigger a pinned git-extension install/upgrade) against a host that the attacker controls the responses for — i.e., a non-`github.com` `GH_HOST`/enterprise endpoint the victim has configured, consistent with the stated attacker capability "controls responses from a host the victim points gh at". Against unmodified `github.com`, the commits API reliably returns a genuine SHA, so this is not exploitable there. The bug is deterministic and repeatable whenever the attacker-controlled host can be reached.

### Recommendation
Validate the response from `fetchCommitSHA` against the expected commit SHA format (e.g. `^[0-9a-f]{7,40}$`) before returning it, rejecting any response that doesn't match. Additionally, harden `installGit`/pin-file construction to reject or escape any `/`, `..`, or path-separator characters in `commitSHA` before using it in `fmt.Sprintf(".pin-%s", commitSHA)`, and consider using `filepath.Base` plus an explicit "resulting path must remain within targetDir" check before the `os.OpenFile` call.

func (m *Manager) installGit(repo ghrepo.Interface, target string) error {
	protocol := m.config.GitProtocol(repo.RepoHost()).Value
	cloneURL := ghrepo.FormatRemoteURL(repo, protocol)

	var commitSHA string
	if target != "" {
		var err error
		commitSHA, err = fetchCommitSHA(m.client, repo, target)
		if err != nil {
			return err
		}
	}

	name := strings.TrimSuffix(path.Base(cloneURL), ".git")
	targetDir := filepath.Join(m.installDir(), name)

	if err := m.cleanExtensionUpdateDir(name); err != nil {
		return err
	}

	_, err := m.gitClient.Clone(cloneURL, []string{targetDir})
	if err != nil {
		return err
	}
	if commitSHA == "" {
		return nil
	}

	scopedClient := m.gitClient.ForRepo(targetDir)
	err = scopedClient.CheckoutBranch(commitSHA)
	if err != nil {
		return err
	}

	pinPath := filepath.Join(targetDir, fmt.Sprintf(".pin-%s", commitSHA))
	f, err := os.OpenFile(pinPath, os.O_WRONLY|os.O_CREATE, 0600)
	if err != nil {
		return fmt.Errorf("failed to create pin file in directory: %w", err)
	}
	return f.Close()
}

// fetchCommitSHA finds full commit SHA from a target ref in a repo
func fetchCommitSHA(httpClient *http.Client, baseRepo ghrepo.Interface, targetRef string) (string, error) {
	url, err := safeurl.JoinPathWithHostPrefix(ghinstance.RESTPrefix(baseRepo.RepoHost()), "repos", baseRepo.RepoOwner(), baseRepo.RepoName(), "commits", targetRef)
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("GET", url.String(), nil)
	if err != nil {
		return "", err
	}

	req.Header.Set("Accept", "application/vnd.github.v3.sha")
	// TODO(api-client-rollout)
	// This has been deferred from moving to api.Client due to its custom Accept header and bare SHA response body.
	resp, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}

	defer resp.Body.Close()
	if resp.StatusCode == 422 {
		return "", commitNotFoundErr
	}
	if resp.StatusCode > 299 {
		return "", api.HandleHTTPError(resp)
	}

	body, err := io.ReadAll(resp.Body)
	if err != nil {
		return "", err
	}

	return string(body), nil
}
