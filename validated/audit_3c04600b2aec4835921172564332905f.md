### Title
Unsanitized issue/PR body passed to markdown renderer allows OSC 52 clipboard injection - (File: pkg/cmd/issue/view/view.go)

### Finding Description
`printHumanIssuePreview` renders `issue.Body` directly through `markdown.Render` and writes the result straight to the terminal: [1](#0-0) 

`issue.Body` is attacker-controlled (any GitHub user can author an issue/PR body). `markdown.Render` forwards to `charmbracelet/glamour` via `github.com/cli/go-gh/v2/pkg/markdown`, which converts markdown *structure* into ANSI styling but does not strip arbitrary control bytes embedded in plain text/paragraph nodes — raw `ESC ] 52 ; ... BEL` (OSC 52) sequences placed in the issue body pass through untouched to `out` (stdout), since glamour is a syntax renderer, not a terminal-safety sanitizer.

The codebase demonstrates that this project is aware of exactly this class of risk and has a fix pattern for it elsewhere: `pkg/cmd/gist/view/view.go` wraps untrusted file content in `iostreams.NewUntrusted(...)` and explicitly calls `content.String()` (which runs the content through `asciisanitizer` to neutralize escape sequences) **before** passing it to `markdown.Render`, with a comment stating "Markdown rendering emits application-styled output to Out, so its input is sanitized here": [2](#0-1) [3](#0-2) 

By contrast, `printHumanIssuePreview` (and the structurally identical `pr/create.go:renderPullRequestTTY`, `discussion/view.go:printHumanView`/`printHumanComment`, `release/view.go:renderReleaseTTY`, `repo/view/view.go`) feed the raw attacker-controlled body straight into `markdown.Render` with no `Untrusted`/`asciisanitizer` pass: [4](#0-3) [5](#0-4) [6](#0-5) 

This inconsistency — the gist-view code path treats markdown rendering input as needing sanitization, while issue/PR/discussion/release view code paths do not — indicates a genuine gap rather than a pure third-party dependency limitation, since the project's own convention shows the correct mitigation exists but wasn't applied uniformly.

### Impact Explanation
An attacker who authors an issue or PR body containing an OSC 52 escape sequence (`\x1b]52;c;<base64 payload>\x07`) can have that sequence emitted verbatim to the victim's terminal when the victim runs `gh issue view <number>` (or `gh pr view`, `gh discussion view`, `gh release view`, or during `gh pr create --dry-run` preview). A terminal emulator that supports OSC 52 will write the base64-decoded payload to the system clipboard. If the payload is a shell command staged with a trailing newline or combined with social engineering (or certain terminal auto-paste/bracketed-paste misconfigurations), a subsequent paste by the victim could execute attacker-chosen content. This matches the "Websites and Apps" arbitrary code execution / clipboard hijacking class described in the target.

### Likelihood Explanation
Highly feasible: any unauthenticated/unprivileged GitHub user can open a public issue or PR with a crafted body; no elevated permissions, tokens, or MITM are required. The victim only needs to run an ordinary `gh issue view` (or PR/discussion/release view) on a TTY, which is a routine, expected workflow. The precondition (a terminal emulator with OSC 52 enabled) is common (iTerm2, many modern terminal emulators, tmux with allow-passthrough).

### Recommendation
Apply the same sanitization pattern used in `pkg/cmd/gist/view/view.go` uniformly to every place that renders remote-authored text through `markdown.Render` for TTY output: wrap `issue.Body` (and PR/discussion/release bodies, comment bodies, README content, etc.) in `iostreams.NewUntrusted(...)` and pass `content.String()` into `markdown.Render`, so the `asciisanitizer` transform strips/neutralizes ANSI/OSC control sequences before glamour ever sees them. Alternatively, run the final rendered markdown output through the asciisanitizer transform before writing to `out`.

### Proof of Concept
```go
func TestPrintHumanIssuePreview_StripsOSC52(t *testing.T) {
    ios, _, stdout, _ := iostreams.Test()
    ios.SetStdoutTTY(true)

    issue := &api.Issue{
        Title: "test",
        Body:  "click me\x1b]52;c;bWFsaWNpb3VzIHBheWxvYWQK\x07",
    }
    opts := &ViewOptions{IO: ios, Now: time.Now}
    baseRepo := ghrepo.New("OWNER", "REPO")

    err := printHumanIssuePreview(opts, baseRepo, issue)
    require.NoError(t, err)

    out := stdout.String()
    assert.NotContains(t, out, "\x1b]52", "OSC 52 sequence must not reach the terminal")
}
```
Expected (current) result: the assertion fails because `markdown.Render` passes the OSC 52 bytes through unchanged, confirming the finding. After applying the `Untrusted`/`asciisanitizer` fix, the assertion passes.

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
