### Title
Partial skill install leaves executable remnants in the active skills directory on mid-install failure - (File: internal/skills/installer/installer.go)

### Summary
`installSkill` (invoked from `Install`, which processes files fetched via `discovery.FetchBlob` at internal/skills/discovery/discovery.go:918) writes each file for a skill directly into the real, active install directory (`baseDir/skill.Name`) one at a time, calling `os.WriteFile` per file as it loops. If any file later in the list fails (blob fetch error, path-traversal rejection, metadata injection error), the function returns an error but leaves every file already written on disk inside the live skill directory that agents subsequently load from.

### Finding Description
`Install` (internal/skills/installer/installer.go:56) calls `installSkill(opts, skill, targetDir)` for each skill. `installSkill` (internal/skills/installer/installer.go:251-309) does: [1](#0-0) 
It then loops over `files` (each entry attacker-controlled via the repo's git tree/blobs, reached through `discovery.FetchBlob` at discovery.go:918) and for each one calls `os.WriteFile(destPath, ...)` immediately: [2](#0-1) 
There is no staging directory, no temp-then-rename, and no cleanup of already-written files on error — contrast this with the sibling `updateSkillInPlace`/`swapDirectoryContents` logic in `pkg/cmd/skills/update/update.go`, which explicitly stages into a temp directory and only performs an atomic rename swap into the live directory after the entire install succeeds, restoring backups on any failure: [3](#0-2) 
The fresh-install path (`gh skills install`) has no equivalent staging/atomic-swap protection. An attacker who publishes a skill repo can order file entries so that early, benign-looking files (e.g., a script or hook file with executable content) are written first, and a later entry deliberately fails validation (e.g., a `../` path-traversal entry, an unreadable/invalid blob, or a name that fails `safeNamePattern`/`specNamePattern` checks). `installSkill` returns an error, but files already written under `baseDir/skill.Name` remain on disk. The `Install` function only records a lockfile entry on success and does not delete `skillDir` on failure: [4](#0-3) 
The existing test `fails on path traversal from malicious tree` (internal/skills/installer/installer_test.go:255-286) only asserts the traversal target itself was not created outside the directory — it does not assert that the legitimately-shaped `SKILL.md` written before the failing entry was rolled back, confirming partial writes are left in place.

### Impact Explanation
Files left behind in the live, agent-scanned skills directory (e.g., `.claude/skills/<name>/`, `.github/copilot/skills/<name>/`, etc., depending on `AgentHost.InstallDir`) can include scripts, hooks, or other content that AI coding agents or tooling may execute or load automatically when scanning skill directories. Because these leftover files are not tracked in the lockfile (the install failed) and are not surfaced to the user as "installed", they are a stealthy residue that a subsequent agent run, `gh skills` scan, or manual inspection could pick up and execute — matching the "arbitrary file write outside intended validated state / code execution on developer machine" class described in the target GitHub bounty scope.

### Likelihood Explanation
Fully attacker-controlled and repeatable: an unprivileged GitHub user only needs to publish a repository with a skill directory whose git tree lists a benign payload file before a file that is guaranteed to fail (a `../`-traversal path, a non-base64 blob encoding, or a name that fails the skill's name-validation regex). Every `gh skills install <attacker-repo>` run against that content deterministically writes the payload file, then fails and leaves it behind. No race, no privilege, no MITM required.

### Recommendation
Change `installSkill` (and the `Install`/`InstallLocal` flows) to stage all fetched/written files into a temporary sibling directory first, and only rename/move the fully-validated staged skill directory into `baseDir` once every file has been fetched and validated successfully — mirroring the pattern already implemented in `updateSkillInPlace`/`swapDirectoryContents` in `pkg/cmd/skills/update/update.go`. On any error, remove the staging directory and ensure the target `baseDir/skill.Name` is left untouched (or fully removed if this is a repeat failed install), rather than partially populated.

### Proof of Concept
Extend `TestInstallSkill` in `internal/skills/installer/installer_test.go`:
1. Stub a tree with two entries: `SKILL.md` (valid, written first) and `../../evil.sh` (path-traversal, written second/last), similar to the existing `fails on path traversal from malicious tree` case.
2. Call `installSkill(opts, skill, destDir)` and assert it returns an error (already done).
3. Additionally assert `os.Stat(filepath.Join(destDir, "code-review", "SKILL.md"))` returns `os.IsNotExist(err) == true` — i.e., the destination skill directory must be empty/removed after a failed install.
4. Currently this assertion fails: `SKILL.md` is present because it was written before the failing traversal entry was processed, proving the partial-write remnant issue.

func installSkill(opts *Options, skill discovery.Skill, baseDir string) error {
	// Use skill.Name (not InstallName) for a flat directory layout.
	skillDir := filepath.Join(baseDir, skill.Name)
	if err := os.MkdirAll(skillDir, 0o755); err != nil {
		return fmt.Errorf("could not create directory %s: %w", skillDir, err)
	}

	files, err := discovery.DiscoverSkillFiles(opts.Client, opts.Host, opts.Owner, opts.Repo, skill.TreeSHA, skill.Path)
	if err != nil {
		return fmt.Errorf("could not list skill files: %w", err)
	}

	safeSkillDir, err := safepaths.ParseAbsolute(skillDir)
	if err != nil {
		return fmt.Errorf("could not resolve skill directory path: %w", err)
	}

	for _, file := range files {
		fetchedContent, err := discovery.FetchBlob(opts.Client, opts.Host, opts.Owner, opts.Repo, file.SHA)
		if err != nil {
			return fmt.Errorf("could not fetch %s: %w", file.Path, err)
		}

		// Install path: the blob is written to disk verbatim, so the raw bytes
		// must be preserved.
		content := fetchedContent.Raw()

		relPath := strings.TrimPrefix(file.Path, skill.Path+"/")

		safeDest, err := safeSkillDir.Join(relPath)
		if err != nil {
			var traversalErr safepaths.PathTraversalError
			if errors.As(err, &traversalErr) {
				return fmt.Errorf("blocked path traversal in %q", relPath)
			}
			return fmt.Errorf("could not resolve destination path: %w", err)
		}
		destPath := safeDest.String()

		if dir := filepath.Dir(destPath); dir != skillDir {
			if err := os.MkdirAll(dir, 0o755); err != nil {
				return fmt.Errorf("could not create directory: %w", err)
			}
		}

		if filepath.Base(relPath) == "SKILL.md" {
			content, err = frontmatter.InjectGitHubMetadata(content, opts.Host, opts.Owner, opts.Repo, opts.Ref, skill.TreeSHA, opts.PinnedRef, skill.Path)
			if err != nil {
				return fmt.Errorf("could not inject metadata: %w", err)
			}
		}

		if err := os.WriteFile(destPath, []byte(content), 0o644); err != nil {
			return fmt.Errorf("could not write %s: %w", destPath, err)
		}
