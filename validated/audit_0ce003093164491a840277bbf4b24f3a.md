### Title
Signature verification keyed on `repository.owner.login` while stack mutation is keyed on `repository.full_name` allows cross-tenant `check_suite` forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate a request using `params.dig('repository', 'owner', 'login')`, but `Shipit::Webhooks::Handlers::Handler#stacks` (used by `CheckSuiteHandler`) resolves the target repository using `payload.dig('repository', 'full_name')`. These two fields are independently attacker-controlled in the JSON body and are never checked for consistency, so an attacker can authenticate with one org's (no-secret) identity while mutating a completely different org's stack.

### Finding Description
The broken binding the code implicitly assumes is:
`params.repository.owner.login == owner_prefix_of(params.repository.full_name)`

This is never enforced. Trace:

- `WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` explicitly returns `true` unconditionally when no `webhook_secret` is configured for that organization: `return true unless webhook_secret`. [3](#0-2) 
- After signature verification, `WebhooksController#create` dispatches the raw, unvalidated `params` hash straight to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` — nothing re-derives or re-checks the owner against the handler's target repository. [4](#0-3) 
- `Handler#stacks` resolves the mutated repository from a **different** field — `payload.dig('repository', 'full_name')` — via `Repository.from_github_repo_name`, independent of `repository.owner.login`. [5](#0-4) 
- `CheckSuiteHandler#process` then loads stacks belonging to whatever repository `full_name` pointed to, filtered only by `params.check_suite.head_branch`, and reschedules check-run refresh for commits matching `params.check_suite.head_sha`: `stacks.where(branch: ...).each { |stack| stack.commits.where(sha: ...).each(&:schedule_refresh_check_runs!) }`. [6](#0-5) 

Exploit request: attacker sends `POST /webhooks` with `X-Github-Event: check_suite`, a body where `repository.owner.login` (and/or `organization.login`) is set to an org configured in `Shipit.github_teams`/app config but **without** a `webhook_secret` set (so `verify_webhook_signature` short-circuits to `true` regardless of the `X-Hub-Signature` header), while `repository.full_name` is set to `"victim-org/victim-repo"` — a different, secret-protected org's repository that has a stack with `review_stacks_enabled: true` and `provisioning_behavior: allow_all`. `check_suite.head_branch`/`head_sha` are set to match an existing commit/branch on the victim stack (or, given `allow_all`, an externally-provisioned review stack for an arbitrary PR branch).

Existing guards do not catch this:
- `drop_unhandled_event` only checks the event type is registered, not repository ownership. [7](#0-6) 
- `ExplicitParameters` schema for `CheckSuiteHandler` only requires `head_sha`/`head_branch` be present strings — it never validates `repository.full_name` or cross-checks it against the authenticating org. [8](#0-7) 
- `Repository#from_github_repo_name` performs a straightforward `owner/name` lookup with no tie-back to which org's secret authenticated the request. [9](#0-8) 

### Impact Explanation
An unprivileged attacker who merely knows (a) the name of any Shipit-configured GitHub org that has no `webhook_secret` configured, and (b) the `owner/name` of a victim repository with a stack/review-stack, can trigger a "write for a repository that did not authenticate it" — the core Critical-impact class listed in scope ("a payload for one repository mutating another's stack, commit, task or team"). Concretely, `schedule_refresh_check_runs!` is invoked on the victim's commit/stack, and because the victim stack has `review_stacks_enabled: true` with `allow_all` provisioning, arbitrary externally-forked PR branches auto-provision review stacks that execute `shipit.yml`, amplifying this into pipeline execution against the victim's deploy pipeline. This is repeatable against any org lacking a `webhook_secret` combined with any target repository/stack, across tenants sharing the same Shipit instance.

### Likelihood Explanation
Preconditions: (1) at least one org configured in Shipit without a `webhook_secret` (plausible in multi-tenant setups where some orgs are configured loosely, or where an attacker controls/registers such an org in a self-hosted or app-marketplace deployment), and (2) a victim stack with `review_stacks_enabled: true`, `allow_all`. Attacker cost is a single unauthenticated HTTP POST with a crafted JSON body — no secrets, sessions, or tokens required. This is fully repeatable and scriptable against arbitrary target repositories once a no-secret org identity is found.

### Recommendation
Bind signature verification and stack resolution to the same field. Either:
1. Verify the webhook signature using the org owning `repository.full_name` (not `repository.owner.login`), or
2. After verifying signature via `repository_owner`, assert `repository.full_name.split('/').first.casecmp(repository_owner) == 0` before dispatching to handlers, rejecting the request (422) on mismatch.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "check_suite payload with mismatched owner.login and repository.full_name cross-tenant forges a stack mutation" do
  # Precondition: configure Shipit.github_teams / app config so org "no-secret-org"
  # has no webhook_secret, while "victim-org" does.
  victim_stack = shipit_stacks(:shipit) # owner: victim-org, review_stacks_enabled: true, allow_all
  commit = victim_stack.commits.last

  payload = {
    action: 'requested',
    check_suite: { head_branch: victim_stack.branch, head_sha: commit.sha },
    repository: {
      full_name: victim_stack.repository.full_name, # "victim-org/victim-repo"
      owner: { login: 'no-secret-org' }              # org with no webhook_secret
    },
    organization: { login: 'no-secret-org' }
  }.to_json

  assert_difference -> { Delayed::Job.where(...).count }, 1 do # schedule_refresh_check_runs! side effect
    post shipit.webhooks_path, params: payload,
      headers: { 'X-Github-Event' => 'check_suite', 'X-Hub-Signature' => 'sha1=deadbeef', 'Content-Type' => 'application/json' }
  end

  assert_response :ok
  # Assert: victim commit's check-run refresh was scheduled despite the request
  # never being signed with victim-org's webhook_secret.
end
```
The claimed binding `params.repository.owner.login == owner_of(params.repository.full_name)` is false in this test's crafted payload, and both sides diverge before and after the request — the handler still mutates the victim stack, confirming the gap.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
