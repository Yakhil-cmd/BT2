### Title
Unauthenticated P2P Peer Can Permanently Corrupt Staking DB via Unvalidated `PutStakingInfoToDB` During Recovery — (`kaiax/staking/impl/schema.go`, `kaiax/staking/p2p_staking_info.go`)

---

### Summary

When a node enters staking-info recovery mode (`isStakingInfoRecovery == true`), it accepts `P2PStakingInfo` messages from any P2P peer and writes them directly to the staking database via `PutStakingInfoToDB` with **zero validation** against the canonical AddressBook state. Because `GetStakingInfo` unconditionally trusts and returns the DB value when present — and never overwrites it with a state-derived value — a single malicious peer response permanently poisons the staking DB for the affected epoch, redirecting block rewards to attacker-controlled addresses for every block in that epoch.

---

### Finding Description

**`DecodeRLP` — no validation**

`P2PStakingInfo.DecodeRLP` blindly decodes all fields including `CouncilRewardAddrs` from the wire without any bounds, address, or consistency checks. [1](#0-0) 

**`ToStakingInfo` — no validation**

`ToStakingInfo` converts the decoded `P2PStakingInfo` to a `StakingInfo` with a direct field copy; no cross-check against AddressBook or any other authoritative source. [2](#0-1) 

**`PutStakingInfoToDB` — unconditional write**

`PutStakingInfoToDB` calls `WriteStakingInfo` directly with no validation, no signature check, and no comparison against the on-chain AddressBook state. [3](#0-2) 

**`GetStakingInfo` — DB value is trusted and never overwritten**

The critical invariant break: `GetStakingInfo` returns the DB value immediately if present, and the `WriteStakingInfo` call that would persist the state-derived value is only reached when the DB has **no** entry. Once a corrupted entry exists in the DB, the state is never consulted and the DB is never corrected. [4](#0-3) 

**`PostInsertBlock` — uses `GetStakingInfo` for every pre-Kaia block**

For every inserted pre-Kaia block, `PostInsertBlock` calls `GetStakingInfo`, which will return the corrupted DB value, propagating the attacker's reward addresses into block processing. [5](#0-4) 

---

### Impact Explanation

- `CouncilRewardAddrs` stored in the staking DB are consumed by the reward distribution logic (`assignStakingRewards`) to determine where block rewards are sent.
- Once the DB entry for a staking epoch is poisoned, every block in that epoch distributes rewards to the attacker's address instead of the legitimate validator reward addresses.
- Because `GetStakingInfo` returns the DB value early and `WriteStakingInfo` is only called when the DB is empty, the poisoned entry is **never overwritten** by the correct state-derived value — the corruption is permanent until the DB is manually cleared.
- Scope is limited to **pre-Kaia-fork** blocks: after the Kaia hardfork, `GetStakingInfo` bypasses the DB entirely and reads from state. [6](#0-5) 

---

### Likelihood Explanation

- Any P2P peer (no special privilege required) can send a `StakingInfoMsg`.
- The recovery state (`isStakingInfoRecovery == true`) is entered during normal initial sync or after a chain reorg — a common, unprivileged condition.
- The attacker only needs to be connected as a peer and respond to a `RequestStakingInfo` message with a crafted payload before any honest peer does.
- No cryptographic break, key compromise, or validator collusion is required.

---

### Recommendation

1. **Validate received staking info against the canonical state.** Before calling `PutStakingInfoToDB`, re-derive the staking info from the local AddressBook state for the given `sourceNum` (if the state is available) and reject any peer-supplied data that differs.
2. **If state is unavailable during recovery**, accept the peer-supplied data only tentatively and mark it as unverified; re-validate and overwrite once the state becomes available (i.e., remove the early-return guard in `GetStakingInfo` for unverified DB entries).
3. **Prefer state over DB.** Invert the lookup priority: always attempt state derivation first; use the DB only as a cache that can be invalidated.

---

### Proof of Concept

1. Start a syncing node in staking-info recovery mode (e.g., fresh node syncing a pre-Kaia chain).
2. Act as a malicious peer; intercept the `RequestStakingInfo` message.
3. Respond with a `P2PStakingInfo` whose `CouncilRewardAddrs` are replaced with attacker-controlled addresses for a target staking epoch.
4. The node's `handleStakingInfoMsg` → `DeliverStakingInfos` → `stakingInfoRecoveryCh` → `PutStakingInfoToDB` path writes the poisoned entry to the DB.
5. Assert via `GetStakingInfoFromDB(sourceNum)` that the attacker address is now stored.
6. Trigger `GetStakingInfo` for any block in that epoch; confirm it returns the attacker's `RewardAddrs` without consulting the AddressBook state.
7. Observe that subsequent reward distribution sends KAIA to the attacker address. [7](#0-6) [8](#0-7)

```go
func (s *StakingModule) GetStakingInfo(num uint64) (*staking.StakingInfo, error) {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(new(big.Int).SetUint64(num))
	sourceNum := sourceBlockNum(num, isKaia, s.stakingInterval)

	// Try cache first
	if si, ok := s.stakingInfoCache.Get(sourceNum); ok {
		return si.(*staking.StakingInfo), nil
	}

	// Only before Kaia, try the database
	if !isKaia {
		if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
			s.stakingInfoCache.Add(sourceNum, si)
			return si, nil
		}
	}

	// Read from the state
	si, err := s.getFromStateByNumber(sourceNum)
	if err != nil {
		return nil, err
	}

	// Only before Kaia, write to database
	if !isKaia {
		WriteStakingInfo(s.ChainKv, sourceNum, si)
	}

	// Cache it
	s.stakingInfoCache.Add(sourceNum, si)
	return si, nil
```

```go
func (s *StakingModule) PostInsertBlock(block *types.Block) error {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(block.Number())
	if !isKaia {
		// Make sure the staking info for the new block is persisted.
		// The StakingInfo(sourceNum) will be persisted here, even if GetStakingInfo is never called elsewhere.
		if _, err := s.GetStakingInfo(block.NumberU64()); err != nil {
			return err
		}
	}
	return nil
}
```
