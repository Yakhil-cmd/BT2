### Title
Path traversal in `(destinationWriter).makePath` allows writing/creating files and directories outside the download destination - (File: pkg/cmd/release/download/download.go)

### Summary
`makePath` at [1](#0-0)  builds the destination path with a plain `filepath.Join(w.dir, name)` and performs no containment check, unlike the other download/extraction code paths in the same codebase (`internal/zip.ExtractZip`, `pkg/cmd/run/download/http.go`, `pkg/cmd/copilot/copilot.go`) which all route through `safepaths.Absolute.Join` to reject `..` traversal. An attacker who controls a release asset name (or a server-supplied `Content-Disposition` filename for archive downloads) can supply a name containing `../` segments to cause `os.MkdirAll` and the subsequent file write to land outside `--dir`.

### Finding Description
`downloadRun` collects `release.Assets` from the GitHub API response and passes each asset's attacker-controlled `Name` field straight through as `downloadTarget.name` [2](#0-1) . This name is used unmodified by `dest.Check(fileName)` and `dest.Copy(fileName, resp.Body)` in `downloadAsset` [3](#0-2) .

Both `Check` and `Copy` call `makePath`, which does:
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [1](#0-0) 

`filepath.Join` calls `filepath.Clean`, so a name like `../../../../tmp/evil/payload` collapses relative to `w.dir` and can resolve to a path entirely outside the intended download directory. There is no equivalent of `safepaths.Absolute.Join`'s `PathTraversalError` check here.

In `Copy`, after `check(fp)` (which only checks pre-existence, not containment) the code does:
```go
if dir := filepath.Dir(fp); dir != "." {
	if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
		return
	}
}
``` [4](#0-3) 
followed by `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` [5](#0-4) . Neither step verifies `fp` is inside `w.dir`, so both directory creation and file write/overwrite can occur anywhere the running user has permission to write.

This contrasts with the sibling artifact-download and archive-extraction code, which do enforce containment via `safepaths`: `ghzip.ExtractZip`/`destDir.Join(zf.Name)` [6](#0-5) , and the run-artifact download path `downloadArtifact` → `ghzip.ExtractZip(zipfile, destDir)` [7](#0-6) , both of which reject traversal names. The `gh release download` per-asset path in `download.go` has no such protection — this looks like a gap that was fixed for archives/artifacts but never applied to individual release assets.

For the archive-download branch (`--archive`), the asset has an empty name and the file name is instead derived from `filepath.Base(serverFileName)` (Content-Disposition header) [8](#0-7) , which already strips path separators via `filepath.Base`, so that branch is not exploitable this way. The exploitable path is the plain per-asset download branch, where `a.Name` (the raw GitHub release asset filename, fully attacker-controlled by whoever publishes the release) flows unmodified into `makePath`.

### Impact Explanation
An attacker who publishes a release (their own repo, fork, or any repo the victim is instructed to run `gh release download` against) can name an asset with `../` segments. When the victim runs `gh release download`, the CLI will `MkdirAll` and write the asset's bytes to an attacker-chosen path outside the destination directory — e.g. into the victim's home directory, shell startup files, git hook files, or `gh`'s own config directory, potentially escalating to code execution when those files are later sourced/executed. This matches "arbitrary file write or overwrite outside the intended directory."

### Likelihood Explanation
Feasible precondition: GitHub's asset upload API may itself restrict characters allowed in asset filenames (this restriction lives on GitHub's server side, not in this client code, and was not verifiable from the repository alone). If GitHub allows `.` and `/`-adjacent characters, or if a URL-encoded/otherwise-normalized name reaches this code with `..`/separator sequences intact, the traversal is trivially repeatable and requires no special privileges beyond being able to publish a release with a crafted asset — an "unprivileged remote GitHub user" action per the threat model.

### Recommendation
Route `makePath` through the same `safepaths.Absolute.Join` containment check used elsewhere in the codebase (`internal/zip`, `pkg/cmd/run/download`, `pkg/cmd/copilot`), rejecting or sanitizing any asset name whose joined path resolves outside `w.dir`, before any `MkdirAll` or file write occurs.

### Proof of Concept
```go
// pkg/cmd/release/download/download_test.go
func TestDestinationWriter_PathTraversal(t *testing.T) {
	tmpBase := t.TempDir()
	destDir := filepath.Join(tmpBase, "dest")
	require.NoError(t, os.Mkdir(destDir, 0755))

	w := destinationWriter{dir: destDir}
	maliciousName := "../../evil/payload.txt"

	err := w.Copy(maliciousName, strings.NewReader("pwned"))
	require.NoError(t, err) // currently succeeds - no traversal error is raised

	// Assert no file/dir was created outside destDir
	_, statErr := os.Stat(filepath.Join(tmpBase, "evil", "payload.txt"))
	require.NoError(t, statErr, "file was written outside destination directory")
}
```
Expected (fixed) behavior: `Copy`/`makePath` should return a path-traversal error and never call `MkdirAll`/`OpenFile` outside `destDir`.

	if err := dest.Check(fileName); err != nil {

	}

	req, err := http.NewRequest("GET", assetURL.String(), nil)
	if err != nil {
		return err
	}

	req.Header.Set("Accept", "application/octet-stream")
	if isArchive {
		// adding application/json to Accept header due to a bug in the zipball/tarball API endpoint that makes it mandatory
		req.Header.Set("Accept", "application/octet-stream, application/json")

		// override HTTP redirect logic to avoid "legacy" Codeload resources
		oldClient := *httpClient
		httpClient = &oldClient
		httpClient.CheckRedirect = func(req *http.Request, via []*http.Request) error {
			if len(via) == 1 {
				req.URL.Path = removeLegacyFromCodeloadPath(req.URL.Path)
			}
			return nil
		}
	}

	resp, err := httpClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode > 299 {
		return api.HandleHTTPError(resp)
	}

	if len(fileName) == 0 {
		contentDisposition := resp.Header.Get("Content-Disposition")

		_, params, err := mime.ParseMediaType(contentDisposition)
		if err != nil {
			return fmt.Errorf("unable to parse file name of archive: %w", err)

			fileName = filepath.Base(serverFileName)
		} else {

	}
