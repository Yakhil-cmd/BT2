### Title
Borrow-index accrual overflow in `scaled_to_original` permanently freezes an entire market — (`File: common/src/rates/scaling.rs`)

### Summary
Every pool mutation runs `global_sync` accrual first, which calls `scaled_to_original(borrowed, borrow_index)` to compute utilization. That multiply panics on `i128` overflow. The `MAX_BORROW_INDEX_RAY` cap (1e36) bounds the *index*, but the debt *value* (`borrowed_scaled × borrow_index`) overflows `i128` long before the index cap engages. Once `borrowed × index` crosses `i128::MAX`, accrual reverts permanently: no repay, no withdraw, no liquidation, no `clean_bad_debt` — the market's tokens are frozen forever. Any unprivileged user can push a market toward this cliff by supplying and borrowing to sustain high utilization, and permissionless `update_indexes` makes the panic fire on the next accrual touch.

### Finding Description
- `accrue_step` computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` at every compound step (`common/src/rates/simulate.rs:60-62`). `scaled_to_original` is a plain `Ray::mul` with no saturation (`common/src/rates/scaling.rs:14-16`).
- `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (1e36), but a market holding e.g. ~1e9 whole 18-decimal tokens has a scaled book whose RAY value overflows `i128` at an index of roughly x170 — far below the 1e9× headroom the index cap implies (`docs/reference/formulas.md:432-437` acknowledges this gap).
- `global_sync` runs before every pool verb (`contracts/pool/src/interest.rs:20-33`; flow documented in `contracts/pool/README.md:159-168`), so once the panic condition is reached it can never be skipped — there is no accrual-bypass escape hatch, and `last_timestamp` is only advanced on success.
- The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` reproduces the exact freeze: `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`).

An unprivileged attacker seeds the state with `controller.supply` (huge principal in a high-decimal asset, e.g. 18 decimals) and `controller.borrow` to hold utilization on the steep segment of the rate curve; thereafter permissionless `controller.update_indexes` / `pool.update_indexes` advances the index each call until accrual panics.

### Impact Explanation
Permanent freezing of funds for every participant in that market: suppliers cannot `withdraw`, borrowers cannot `repay`, liquidators cannot `liquidate`, and bad debt cannot be cleaned — all paths accrue first and hit the same `MathOverflow` panic. The pool tokens backing the market are unrecoverable, satisfying the "permanent freezing of funds" / "contract unable to operate" acceptance bar for the affected (hub, asset) book.

### Likelihood Explanation
Medium-to-low. The attacker (or organic market growth) must push a market to extreme scale — the admitted token-domain maximum is ~1.7e11 whole tokens at 18 decimals (`max_cap_for_decimals`, `docs/reference/formulas.md:429`) — and sustain high utilization while the borrow index compounds past the value cliff (the harness reaches it within ~40 simulated years on a 175%-max-rate curve at 98% utilization; much faster on steeper curves). No privileged action is needed, but capital requirements are large and the freeze is time-dependent. Note the cliff is a documented arithmetic limit rather than a silent flaw, which lowers novelty but not exploitability — there is no mitigation or ceiling alarm in code.

### Recommendation
Saturate instead of panicking on the value side: make `scaled_to_original` (or the accrual call sites for `borrowed_original`/`supplied_original`) clamp to `i128::MAX`, or gate accrual so that when `borrow_index` approaches a configured value ceiling, interest stops accruing (rate forced to 0) rather than reverting — preserving repay/withdraw/liquidate paths. Alternatively, enforce per-market supply/borrow caps tightly enough that `borrowed_scaled × MAX_BORROW_INDEX_RAY < i128::MAX` holds by construction, and emit a warning event when utilization/rate trajectories approach the bound.

### Proof of Concept
Existing harness reproduction: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`.

```rust
let principal = BILLION * 10i128.pow(18);      // 18-decimal asset
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;               // 98% utilization
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);                 // unprivileged: just wait
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// borrow_index ~x170, still << MAX_BORROW_INDEX_RAY
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
// Market permanently frozen: every verb accrues via global_sync ->
// accrue_step -> scaled_to_original -> Ray::mul overflow.
```

Root cause chain: `pool::interest::global_sync` (`contracts/pool/src/interest.rs:39-53`) → `common::rates::accrue_step` (`common/src/rates/simulate.rs:60-61`) → `scaled_to_original` → `Ray::mul` panic (`common/src/rates/scaling.rs:14-16`).
