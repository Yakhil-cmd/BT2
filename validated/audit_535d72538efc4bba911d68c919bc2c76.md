### Title
Webhook status events are matched to commits by SHA alone with no repository binding, letting a signature verified for one GitHub organization forge CI status for commits belonging to a completely unrelated stack - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which organization's webhook secret to validate a request against using a field pulled straight out of the same JSON body it is about to trust: `repository_owner` (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). The resulting `GitHubApp` is only used to decide *whether the HMAC matches*; nothing downstream re-checks that the organization whose secret validated the signature actually owns the resource the handler is about to mutate. `Webhooks::Handlers::StatusHandler#process` then locates the target records with `Commit.where(sha: params.sha)` — a lookup that spans the entire `commits` table, with no `stack_id`/`repository` scoping to the `repository.full_name` also present in the same payload. [1](#0-0) [2](#0-1) 

### Finding Description
`GitHubApp#verify_webhook_signature` explicitly no-ops when the resolved organization has no `webhook_secret` configured:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [3](#0-2) 

This is a documented, first-class configuration state, not a misconfiguration: the shipped sample multi-org secrets templates set `webhook_secret: # nil` for every organization by default. [4](#0-3) [5](#0-4) 

In a multi-organization deployment (`Shipit.github(organization:)` keyed config, exercised in `test/unit/shipit_test.rb`), any single organization left with `webhook_secret: nil` becomes a universal signature bypass: an attacker just needs to set `repository.owner.login` (or `organization.login`) in the forged JSON body to that unsecured org's name, and `verify_signature` will pass regardless of the `X-Hub-Signature` header supplied — or its absence. [6](#0-5) [7](#0-6) 

Once past that gate, `WebhooksController#create` dispatches the raw parsed body to every registered handler for the event type, with no further authorization:

```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [8](#0-7) 

For a `status` event, `StatusHandler#process` resolves which `Commit` rows to mutate purely by SHA, with zero repository/stack scoping:

```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [9](#0-8) 

This breaks exactly the trust binding the analog targets: `organization whose signature was verified == organization/repository whose commit is being written` is never checked; only `sha == sha` is checked. Commit SHAs are public (visible on GitHub, in PR diffs, CI logs, etc.), so an attacker who can observe or predict the SHA of a commit belonging to *any* stack tracked by the Shipit instance — including a stack that belongs to a fully-secured organization — can forge a `status` webhook whose signature is verified against the unrelated, secret-less organization, and have it applied to that unrelated commit.

`Commit#create_status_from_github!` writes a `Status` row via `add_status`, which in turn feeds `Status#enable_ci_on_stack` and `Status#schedule_continuous_delivery`: [10](#0-9) 

CI-gated continuous delivery (`ci.require` in `shipit.yml`) and the deployability of a commit are driven by these `Status` rows, so forging a `state: "success"` status for a required context on a targeted stack's commit can clear the CI gate on a stack the attacker has no relationship to whatsoever.

### Impact Explanation
This lets an unauthenticated network attacker (no Shipit session, no `ApiClient` token, no GitHub credentials for the target organization) inject arbitrary commit statuses into any stack tracked by the Shipit instance, as long as any *other* configured GitHub organization in the same deployment has no `webhook_secret` set — a state the project's own sample secrets files present as the default. By forging a `success` status on a required CI context for a target commit, the attacker can clear `ci.require` gating and cause continuous delivery to proceed with a deploy that was never actually validated by CI, i.e. an unauthorized deploy driven entirely through the webhook surface.

### Likelihood Explanation
The only precondition is that the deployment configures more than one GitHub organization and leaves at least one without a `webhook_secret` — exactly the state shown in the shipped sample configs (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`). No credentials, no repository access, and no privileged account are required; only knowledge of a target commit's SHA, which is generally public. The `WebhooksController` endpoint is unauthenticated by design (that's the entire point of `verify_signature`), so this is directly reachable by any external attacker.

### Recommendation
- Scope `StatusHandler` (and any other handler resolving records purely by SHA) to the `stack`/`repository` derived from `params.repository.full_name`, not merely the SHA, e.g. `stacks.joins(:commits).where(shipit_commits: { sha: params.sha })`.
- Do not let `verify_webhook_signature` silently pass when `webhook_secret` is blank for a *specific* organization if other organizations in the same deployment do have secrets configured; either require all configured organizations to set a secret, or bind the verified organization identity to the resource being mutated so a bypass on org A cannot be used to write data belonging to org B.
- Reject webhook payloads where `repository.owner.login`/`organization.login` does not match the owner encoded in `repository.full_name`.

### Proof of Concept
1. Deploy Shipit with two GitHub organizations configured: `SecureOrg` (has `webhook_secret` set, owns the target stack/commit) and `OpenOrg` (no `webhook_secret`, as shown in the shipped sample secrets templates).
2. Identify a commit SHA for a stack under `SecureOrg` that has a required CI context per `ci.require` in its `shipit.yml` (SHAs are public via GitHub).
3. Send an unsigned POST to `/github/webhooks` (mounted `WebhooksController#create`) with header `X-Github-Event: status` and body:
```json
{
  "sha": "<target-commit-sha-under-SecureOrg>",
  "state": "success",
  "context": "ci/required-context",
  "description": "forged",
  "created_at": "<iso8601>",
  "repository": { "owner": { "login": "OpenOrg" }, "full_name": "OpenOrg/anything" }
}
```
4. `verify_signature` resolves `Shipit.github(organization: "OpenOrg")`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` unconditionally — the request is accepted with no valid `X-Hub-Signature`.
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)`, finds the `SecureOrg` commit purely by SHA, and calls `create_status_from_github!`, creating a `success` `Status` for the required CI context on that commit — clearing `ci.require` and unlocking continuous delivery for a stack the attacker had no access to.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
