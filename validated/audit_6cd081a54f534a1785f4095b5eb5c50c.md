### Title
Argument/flag injection into the `gh skill install` subprocess via attacker-controlled skill path in search results - ([File: pkg/cmd/skills/search/search.go])

### Summary
`promptInstall` builds `installArg` directly from the repo-relative skill directory path (`s.Path`/`s.SkillName`) returned by the GitHub Code Search API and passes it as a positional argument to `exec.Command(opts.ExecutablePath, "skills", "install", s.Repo, installArg, ...)`. Because these values come from file paths inside an attacker-published repository and are never validated against a leading `-`, an attacker can name a skill directory so that `installArg` is parsed by `gh skill install`'s cobra flag parser as a flag (e.g. `--dir=...`) instead of a positional skill name.

### Finding Description
`installArg` is derived from `s.SkillName` or, for namespaced skills, `strings.TrimSuffix(s.Path, "/SKILL.md")` [1](#0-0) . Both `s.SkillName` and `s.Path` originate from the GitHub Code Search API's `path` field for a `SKILL.md` file found in a repository the attacker fully controls [2](#0-1) . Git tree/blob path components can contain characters such as `-` and `=` (only `/` and NUL are disallowed), so an attacker can create a directory literally named e.g. `--dir=/tmp/pwned` or `--pin=x/../../etc` under `skills/` in their repo.

The resulting subprocess invocation `exec.Command(opts.ExecutablePath, "skills", "install", s.Repo, installArg, "--agent", host.ID, "--scope", scope)` does not use a shell (`os/exec` without `sh -c`), so classic shell-metacharacter injection is not possible, but the args are still parsed by cobra/pflag inside the invoked `gh skill install` command [3](#0-2) . If `installArg` begins with `-`, cobra will interpret it as a flag rather than the positional skill-name argument. `gh skill install` defines flags including `--dir` (arbitrary install directory, overriding agent/scope), `--pin`, `--force`, and `--from-local` [4](#0-3) . In particular, `--dir` lets the attacker redirect where the attacker-supplied `SKILL.md`/skill files are written on the victim's filesystem, and the code contains an explicit `//nolint:gosec` comment asserting the arguments are safe because they come from "user-selected search results, not arbitrary input" — but the content of those results (repo path names) is fully attacker-controlled, not vetted.

There is no allowlist/validation rejecting skill names or paths starting with `-` before they are placed into `installArg` in `promptInstall`.

### Impact Explanation
This allows a remote, unprivileged attacker who merely publishes a public repository to cause the victim's own `gh` process to invoke `gh skill install` with attacker-chosen flags instead of the intended positional skill name. Concretely this can redirect the install target directory (`--dir`) to write attacker-supplied skill file content to a location outside the intended skills directory, matching the "file write or overwrite outside the intended path" impact class. It requires the victim to interactively select the crafted result from `gh skill search` and confirm installation, so it is not silent, but no other guardrail in the codebase blocks the flag injection itself.

### Likelihood Explanation
Requires: (1) the victim runs `gh skill search <query>` on a TTY, which triggers `promptInstall`; (2) the attacker's crafted repository/skill surfaces among the search/relevance-ranked results; (3) the victim selects that specific result from the multi-select picker. This is plausible for a targeted attack (attacker can boost relevance via exact name matches per `relevanceScore` and can advertise the skill) but requires user interaction, lowering likelihood versus a fully automatic path.

### Recommendation
In `promptInstall` (and anywhere else `s.Repo`/`installArg` values are passed to `exec.Command`), reject or sanitize any value that begins with `-` before using it as a positional CLI argument — e.g. prefix the argument list with `--` to stop flag parsing in the invoked `gh skill install` command, or explicitly validate `s.SkillName`/`installArg` against an allowed character set (alphanumeric, `-`, `_`, `/`) that cannot start with `-`.

### Proof of Concept
Go test outline using `httpmock` (extending existing `TestSearchRun_TelemetryRecordsInstallFromResults` in `pkg/cmd/skills/search/search_test.go`):
1. Stub the `search/code` API response so the returned item has `"path": "skills/--dir=/tmp/pwned-poc/SKILL.md"` and `"repository": {"full_name": "attacker/repo"}`.
2. Set up `SearchOptions` with a `PrompterMock` that selects this single result and picks an agent/scope, as in the existing test.
3. Replace `opts.ExecutablePath` with a path to a small test binary/wrapper (or intercept via a custom `runF`) that records the exact `os.Args` it receives.
4. Assert that the recorded arguments contain a literal `--dir=/tmp/pwned-poc` token that would be parsed as a flag by `gh skill install`'s cobra command, rather than the skill positional argument that was intended, demonstrating flag/argument injection.
