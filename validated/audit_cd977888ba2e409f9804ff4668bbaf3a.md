### Title
Webhook signature verification org is decoupled from the org used to resolve the target `Stack`/`Repository`, allowing cross-tenant forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to check the HMAC signature against using `repository.owner.login` (or `organization.login`) from the raw, unauthenticated JSON body, while every webhook handler (`Handler#stacks`, `PushHandler`, `OpenedHandler`, etc.) resolves the target `Repository`/`Stack` using a completely independent field from the same body, `repository.full_name`. Because these two attacker-controlled fields are never cross-checked, an attacker can pick a value for `repository.owner.login` that maps to a Shipit-configured org with no `webhook_secret` (satisfying signature verification trivially) while setting `repository.full_name` to point at a victim org/repo that does have a secret configured, driving `GithubSyncJob`/stack mutation against a repository the attacker never authenticated for.

### Finding Description
The claimed binding, stated as an equality, is:
`org used to verify webhook signature (repository.owner.login)` == `org whose Stack/Repository is mutated (repository.full_name's owner)`

This equality is **not enforced anywhere** in the code, so it is false in general.

- `WebhooksController#verify_signature` resolves the signing org purely from payload data: [1](#0-0) [2](#0-1) 

- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that specific org has no `webhook_secret` configured, without even inspecting the `X-Hub-Signature` header content: [3](#0-2) 

- Once signature verification passes, `params = JSON.parse(request.raw_post)` (the same attacker-controlled body) is handed to the matching handler(s): [4](#0-3) 

- Every handler (base `Handler#stacks`, `PushHandler#process`, `PullRequest::OpenedHandler#repository`, etc.) resolves the target repository/stack from `repository.full_name`, a field that is never checked against `repository.owner.login`: [5](#0-4) [6](#0-5) [7](#0-6) 

- `Repository.from_github_repo_name` does a straightforward case-insensitive lookup with no ownership/authenticity check tying it back to the verified org: [8](#0-7) 

- For `push` events, this reaches `Stack#sync_github` → `GithubSyncJob.perform_later(stack_id:, expected_head_sha:)`, and `GithubSyncJob#perform` unconditionally loads and mutates the resolved `Stack`'s commits: [9](#0-8) [10](#0-9) 

**Exploit flow:** In a multi-org Shipit deployment (explicitly supported per `docs/setup.md`, config keyed by organization), suppose org `attacker-org` is configured in Shipit but has no `webhook_secret` set, while org `victim-org` (tracking a stack) has a secret configured. The attacker sends an HTTP `POST /webhooks` directly (no GitHub relay required, no session/token needed) with:
- `X-Github-Event: push`
- Body: `{"ref": "refs/heads/<victim-tracked-branch>", "after": "<attacker-chosen sha>", "repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}}`

`verify_signature` calls `Shipit.github(organization: 'attacker-org')`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (even absent/garbage) `X-Hub-Signature` header. `PushHandler` then resolves `stacks` via `repository.full_name` = `"victim-org/victim-repo"`, matching the real victim `Stack`, and enqueues `GithubSyncJob` against it.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type exists; `ExplicitParameters` schemas only validate presence/type of `repository.full_name`, not its consistency with `repository.owner.login`; there is no `Repository#owner` vs `verify_signature`'s org cross-check anywhere in the call path.

### Impact Explanation
An attacker who controls (or can point to) any Shipit-known org with no `webhook_secret` configured can forge `push`, `pull_request`, `status`, `check_suite`, etc. webhook payloads for **any other org's repository** tracked by the same Shipit instance, without possessing that org's webhook secret. This directly causes `GithubSyncJob` to run against, and mutate, the victim's `Stack`/`Commit` records, and can trigger stack creation/archival/unarchival via the PR handlers for `review_stacks`. This is a cross-tenant authentication bypass matching the "payload for one repository mutating another's stack, commit" Critical category. The attack is repeatable against any tracked repository/stack simply by changing `repository.full_name` in the forged body, and generalizes across every webhook event type routed through `Handler#stacks`/`repository`.

### Likelihood Explanation
Requires: (1) the Shipit instance uses the multi-org `github:` config format (explicitly documented/supported), and (2) at least one configured org has no `webhook_secret` set. Both are realistic — the shipped config templates (`config/secrets.development.example.yml`, `template.rb`) default `webhook_secret` to blank/nil, and operators managing several orgs may easily leave one unconfigured or newly added org without a secret while others are secured. No GitHub credentials, Shipit session, or API token are needed; the attacker only needs to know/guess a configured-but-secret-less org name and the victim's `owner/repo` full name (both are public/discoverable information). The attack is a single unauthenticated HTTP POST and is trivially repeatable.

### Recommendation
Derive the org used for signature verification from the same field(s) used for repository/stack resolution (i.e., verify the signature using the org parsed from `repository.full_name`, not a separate `repository.owner.login`/`organization.login` field), or explicitly assert `repository.full_name.split('/').first.casecmp(repository_owner) == 0` before proceeding. Additionally, consider making `webhook_secret` mandatory (fail closed) rather than defaulting to `verified = true` when unset.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test ":push with mismatched owner/full_name bypasses signature and syncs victim stack" do
  # Setup: 'attacker-org' configured with no webhook_secret, 'shopify' (victim) stack exists
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(
    Shipit::GitHubApp.new('attacker-org', { webhook_secret: nil })
  )

  request.headers['X-Github-Event'] = 'push'
  forged_payload = {
    ref: "refs/heads/#{@stack.branch}",
    after: 'deadbeef' * 5,
    repository: {
      owner: { login: 'attacker-org' },       # used for signature check -> no secret -> passes
      full_name: @stack.repository.github_repo_name # victim repo -> used for target resolution
    }
  }.to_json

  # No/garbage X-Hub-Signature header
  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: @stack.id, expected_head_sha: 'deadbeef' * 5]) do
    post :create, body: forged_payload, as: :json
  end
  assert_response :ok
end
```
This asserts the binding fails: `repository_owner` ("attacker-org", secret-less) is decoupled from the stack actually mutated (`@stack`, belonging to `shopify`/victim), with `GithubSyncJob` enqueued against the victim's stack despite the forged signing org.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
