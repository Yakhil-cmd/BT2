### Title
Webhook signature is verified against `repository.owner.login`/`organization.login` while stack mutation uses independently-attacker-controlled `repository.full_name`, allowing cross-repo stack archive/unarchive - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to verify the HMAC signature using `repository_owner`, which is read from the raw JSON body's `repository.owner.login` (or `organization.login`) field. `LabeledHandler`/`UnlabeledHandler#repository` separately reads `params.repository.full_name` to resolve the `Shipit::Repository` whose review stack gets archived/unarchived. Nothing in the code cross-validates that `repository.owner.login` and the org segment of `repository.full_name` refer to the same repository, so an attacker who controls the entire raw POST body can make these two fields diverge.

### Finding Description
The claimed binding is: `org_verified_via(repository_owner) == org_owning(repository.full_name)`. Tracing the code shows this is **not enforced**:

- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` (line 59-62) and calls `Shipit.github(organization: repository_owner)` to fetch the app/secret used to verify `X-Hub-Signature` against `request.raw_post`.
- `LabeledHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:65-68) independently resolves the target repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`.
- `repository.owner.login` and `repository.full_name` are two distinct JSON fields inside the same attacker-supplied raw POST body. Since the attacker is POSTing directly to `/webhooks` (not going through GitHub), they fully control both fields and can set them inconsistently, e.g. `repository.owner.login = "attacker-org"` (so `Shipit.github(organization: "attacker-org")` uses the attacker's own known/legitimate webhook secret for that org) while `repository.full_name = "victim-org/victim-repo"` (so the handler resolves and mutates the victim's `Shipit::Repository`/`ReviewStack`).
- `verify_signature` only checks that the raw body's HMAC matches the secret for `attacker-org` — it says nothing about whether the *content* of that body should be allowed to reference `victim-org`'s repository. Once signature verification passes, `LabeledHandler#process` → `respond_to_label_change?` → `handle` → `stack.archive!`/`unarchive!` proceeds entirely against the victim repository/stack looked up from `params.repository.full_name`, using the attacker's own chosen label name and PR number to satisfy `provisioning_behavior_prevent_with_label?`/`archive?`/`unarchive?` logic on the victim's `Repository` config.
- No other guard (drop_unhandled_event, ExplicitParameters schema requiring only `String` for `full_name`, `Repository` model validations) checks consistency between the authenticating org and the repository being acted upon.

### Impact Explanation
An attacker with a legitimate webhook secret for their own org/repo (something any GitHub user who owns a repo already possesses, since GitHub issues it to them) can forge a raw POST to `/webhooks` that passes signature verification under their own org, but names an arbitrary victim repository and PR number in the payload. This lets them archive or unarchive a victim's review stack (deprovisioning/reprovisioning it), a payload for one repository mutating another's stack — matching the Critical impact category explicitly listed in the rules ("a payload for one repository mutating another's stack ... or an unauthorized deploy, rollback"). The attack is repeatable against any victim repo with label-based provisioning behavior and any existing review-stack PR number, since nothing binds the authenticated org to the acted-upon repository.

### Likelihood Explanation
Preconditions: the victim repository must have `review_stacks_enabled` and `provisioning_behavior_allow_with_label?`/`prevent_with_label?` configured, and an existing review stack for the targeted PR number. The attacker needs only their own org's legitimate webhook secret (which they already hold, since GitHub gives repo owners this secret) — no victim secret, no Shipit session, and no privileged role. Constructing the divergent payload (mismatched `repository.owner.login` vs `repository.full_name`) is straightforward with any HTTP client, and repeatable against arbitrary target repos/PRs simply by editing the JSON body and PR number.

### Recommendation
In `WebhooksController#verify_signature`, or in each handler's `repository`/`stack` resolution, enforce that the organization used to verify the signature matches the organization implied by `params.repository.full_name` (and ideally `params.repository.owner.login` should be validated as consistent with `full_name` before use). Reject the webhook (422) if these diverge, rather than trusting `full_name` independently for repository lookup after verifying signature against a different, attacker-chosen owner field.

### Proof of Concept
```ruby
# test/controllers/shipit/webhooks_controller_test.rb (conceptual addition)
test "labeled webhook verified under attacker org cannot mutate victim repo's stack" do
  attacker_org = "attacker-org"
  victim_repo = shipit_repositories(:shipit) # owned by a different org, review_stacks_enabled,
                                              # provisioning_behavior_prevent_with_label? = true,
                                              # provisioning_label_name = "shipit-ignore"
  victim_stack = create_review_stack_for(victim_repo, pr_number: 42, archived: false)

  body = {
    action: "labeled",
    number: 42,
    pull_request: {
      id: 1, number: 42, url: "http://x", title: "t", state: "open",
      additions: 1, deletions: 1,
      head: { sha: "a" * 40, ref: "attacker-branch" },
      user: { login: "attacker" },
      assignees: [],
      labels: [{ name: victim_repo.provisioning_label_name }] # "shipit-ignore"
    },
    repository: {
      full_name: "#{victim_repo.owner}/#{victim_repo.name}", # victim repo
      owner: { login: attacker_org }                          # attacker org, used for signature check
    },
    sender: { login: "attacker" }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", webhook_secret_for(attacker_org), body)

  post shipit.webhooks_path, params: body,
       headers: { "X-Hub-Signature" => signature, "X-Github-Event" => "pull_request" },
       as: :json

  assert_response :ok
  # Broken binding demonstrated: signature verified for attacker_org,
  # but victim_stack (belonging to a different org) is mutated.
  assert victim_stack.reload.archived?, "victim stack should not be archived by a payload verified under a foreign org's secret"
end
```
