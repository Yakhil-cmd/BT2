### Title
`ProxyType::NonTransfer` proxies can escalate to `ProxyType::Auction` and dispatch `Registrar::swap`, a call explicitly excluded from the `NonTransfer` filter - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
In `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, `ProxyType::is_superset` declares `NonTransfer` a superset of every other `ProxyType`, including `Auction`, while `ProxyType::filter` for `NonTransfer` explicitly excludes `paras_registrar::Call::swap` (the comment literally says "Specifically omitting Registrar `swap`"), yet `ProxyType::Auction`'s filter admits the entire `Registrar { .. }` wildcard, which includes `swap`. Because `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` purely on `is_superset` (not on `filter`), a delegate holding only a `NonTransfer` proxy can add itself an `Auction` proxy for the same delegator and then dispatch `Registrar::swap`, a call its own `NonTransfer` grant was designed to deny. This is the exact same bug class that was already found and fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend (see `prdoc/pr_12769.prdoc`), but the fix was not applied to the relay-chain runtimes or the `NonTransfer`/`Auction` pair.

### Finding Description
`pallet_proxy`'s authorization model relies on two independent decisions on the `ProxyType`:
- `filter(call)` — whether the granted proxy type may execute a given call at all.
- `is_superset(other)` — whether a proxy holder may itself grant/revoke a proxy of `other` type for the same delegator, used only in `add_proxy`/`remove_proxy` authorization. [1](#0-0) 

`do_proxy` checks `is_superset` when the dispatched call is `add_proxy`/`remove_proxy`, and otherwise defers to `filter`. The invariant this relies on (documented explicitly in the already-fixed Asset-Hub-Westend commit) is: if type `A.is_superset(B) == true`, then every call `B.filter` admits must also be admitted by `A.filter`. Otherwise a proxy of type `A` can grant itself a proxy of type `B` and use it to reach calls `A.filter` itself denies — a direct authorization-scope escalation.

In `polkadot/runtime/rococo/src/lib.rs`, `is_superset` collapses to: [2](#0-1) 

i.e. `NonTransfer` is unconditionally a superset of every `ProxyType`, including `Auction`.

`NonTransfer`'s filter admits only specific `Registrar` calls and explicitly documents the omission of `swap`: [3](#0-2) 

But `Auction`'s filter admits the full `Registrar { .. }` wildcard: [4](#0-3) 

Since `Registrar { .. }` matches every variant of the `paras_registrar` call enum, it includes `Call::swap`: [5](#0-4) 

The exact same broken lattice (`(ProxyType::NonTransfer, _) => true` plus an `Auction` filter with the `Registrar { .. }` wildcard while `NonTransfer` explicitly omits `swap`) is present in the Westend relay-chain runtime and in the `staking-async` RC runtime as well: [6](#0-5) [7](#0-6) 

This is the identical bug class already identified and fixed for Asset Hub Westend's `NonTransfer`/`Governance` pair: [8](#0-7) 

That fix removed `Governance` from the set `NonTransfer.is_superset` returns true for, but it did not touch the relay-chain runtimes, and it did not address the analogous `Auction` gap that still exists via the blanket `(ProxyType::NonTransfer, _) => true` rule.

`Registrar::swap` itself only requires `ensure_root_para_or_owner`, i.e. Root, the para's owner, or the para's own signed origin — no privileged role is needed: [9](#0-8) 

so a delegate acting as the delegator via the proxy mechanism satisfies this check whenever the delegator is a para owner.

### Impact Explanation
An account that was only ever granted a `NonTransfer` proxy — intended to exclude value-moving and sensitive operations, with `Registrar::swap` specifically called out in the source comments as excluded — can unilaterally widen its own authority for the delegator by self-granting an `Auction` proxy (permitted purely because `is_superset` says so, with no `filter` check applied to `add_proxy`/`remove_proxy`). It can then dispatch `Registrar::swap` as the delegator. `swap` exchanges lease/parachain status, associated deposits, crowdloan fund ownership, and (per `prdoc/1.10.0/pr_3714.prdoc`) triggers coretime broker lease updates via XCM between the delegator's para and another para. This lets a `NonTransfer` delegate perform an operation the delegator explicitly withheld from it, breaking the proxy authorization boundary (CWE-863: Incorrect Authorization) and potentially manipulating the delegator's parachain slot/lease and crowdloan state without ever being granted that permission.

### Likelihood Explanation
The attacker needs only a normal, unprivileged `NonTransfer` proxy grant from a delegator who owns/controls a registered para — a routine, intentionally-limited delegation (e.g. an operations bot or exchange custodian trusted only for non-transfer maintenance calls). No governance, validator, collator, or key compromise is required; the escalation path (`add_proxy(Auction)` → `Registrar::swap`) is two ordinary signed extrinsics through the standard `pallet_proxy::proxy` dispatch, and the vulnerable `is_superset`/`filter` mismatch is a static configuration fact of the affected runtimes (rococo, westend relay chain, staking-async RC), not a race condition.

### Recommendation
Apply the same remediation already used for Asset Hub Westend (`prdoc/pr_12769.prdoc`, `prdoc/pr_12771.prdoc`) to `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`: replace the blanket `(ProxyType::NonTransfer, _) => true` in `is_superset` with an explicit, verified list of subsets whose `filter` is provably contained in `NonTransfer`'s filter (as done for `Collator`/`Staking`/`NominationPools`/`StakingOperator` on Asset Hub). `Auction` must be excluded from that list until `NonTransfer`'s filter is changed to also admit `Registrar::swap` (which would defeat the intended exclusion) — the correct fix is to keep `swap` excluded from `NonTransfer` and stop `NonTransfer.is_superset(Auction)` from returning `true`. Add a lattice-consistency test analogous to `proxy_type_superset_relation_matches_call_filters` (already present for asset-hub-westend) to each affected runtime to prevent regression.

### Proof of Concept
Static evidence (file:line) supporting the escalation path:
1. `pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` solely via `is_superset`, never via `filter`: `substrate/frame/proxy/src/lib.rs:1005-1021`.
2. Rococo `is_superset` returns `true` for `(NonTransfer, Auction)`: `polkadot/runtime/rococo/src/lib.rs:1000-1008`.
3. Rococo `NonTransfer.filter` explicitly does *not* admit `Registrar::swap` (comment "Specifically omitting Registrar `swap`"): `polkadot/runtime/rococo/src/lib.rs:960-966`.
4. Rococo `Auction.filter` admits the whole `Registrar { .. }` wildcard, i.e. including `swap`: `polkadot/runtime/rococo/src/lib.rs:988-995`.
5. `Registrar::swap` only requires Root/owner/para origin, not any governance/privileged role: `polkadot/runtime/common/src/paras_registrar/mod.rs:328-331`.
6. The identical bug class (superset/filter mismatch) was already confirmed and fixed for a different pair on a different runtime, validating that this is a real, previously-recognized vulnerability class in this codebase: `prdoc/pr_12769.prdoc:1-16`.

Reproduction sketch (not executed — this requires a runtime integration test harness for `polkadot/runtime/rococo` analogous to the one that exists for `asset-hub-westend`, which is not present in this repo for the relay-chain runtimes):
```rust
// 1. Delegator (owner of para P) grants a NonTransfer proxy to Attacker.
Proxy::add_proxy(RuntimeOrigin::signed(Delegator), Attacker, ProxyType::NonTransfer, 0)?;

// 2. Attacker escalates: adds itself an Auction proxy for Delegator.
// Allowed only because NonTransfer.is_superset(Auction) == true (no filter check applied here).
Proxy::proxy(
    RuntimeOrigin::signed(Attacker), Delegator, Some(ProxyType::NonTransfer),
    Box::new(RuntimeCall::Proxy(pallet_proxy::Call::add_proxy {
        delegate: Attacker, proxy_type: ProxyType::Auction, delay: 0,
    })),
)?;

// 3. Attacker now dispatches Registrar::swap as Delegator via the Auction proxy,
// a call NonTransfer.filter explicitly denies.
Proxy::proxy(
    RuntimeOrigin::signed(Attacker), Delegator, Some(ProxyType::Auction),
    Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap { id: P, other: Q })),
)?;
// Expected (per documented intent): rejected, NonTransfer excludes `swap`.
// Actual: succeeds, because step 2 legally granted Auction, whose filter admits `swap`.
```

    `Referenda` and `Whitelist` calls that `Governance` admits.

    `NonTransfer` proxy could add a `Governance` proxy for its delegator and thereby reach calls
    that its own filter denies. `NonTransfer` no longer declares `Governance` as a subset, so this
    is rejected.

    Existing `Governance` proxies are unaffected; only the ability of a `NonTransfer` proxy to
    create or remove one changes. The `Collator`, `Staking`, `NominationPools` and
    `StakingOperator` subsets of `NonTransfer` are unchanged.
