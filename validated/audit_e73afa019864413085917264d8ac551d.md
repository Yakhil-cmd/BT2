Confirmed. This is a real, reachable divergence between the org used for HMAC authentication and the org whose repository/record actually gets mutated.

### Title
Forged `pull_request` "assigned" webhook using a no-secret org's login field mutates a different org's `PullRequest` - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used for HMAC verification solely from `params.dig('repository','owner','login')`, while `AssignedHandler` (and other webhook handlers) resolve the target `Repository`/`PullRequest` from the independent `params.repository.full_name` field. Because these two attacker-controlled fields are never required to be consistent, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org's `webhook_secret` is blank, an attacker can pick an org with no configured secret for authentication while pointing `repository.full_name` at any other tracked repository to mutate its `PullRequest` record.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:

`organization_used_for_signature (params.dig('repository','owner','login'))` **should equal** `organization_owning_the_mutated_record (Repository.from_github_repo_name(params.repository.full_name).owner)`

Trace:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)`, then `github_app.verify_webhook_signature(signature, raw_post)`. [1](#0-0) 
- `Shipit.github` in multi-org mode (`github_default_organization` present, i.e. more than one org key configured under `github:`) looks the org up via `github_app_config(organization)` using the attacker-controlled `organization` string directly, case-insensitively. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` returns `true` immediately, bypassing HMAC entirely, whenever that org's `webhook_secret` is blank. [3](#0-2) 
- Once `verify_signature` passes, `WebhooksController#create` parses `request.raw_post` and dispatches the *entire* attacker body to the registered `pull_request` handlers, including `Shipit::Webhooks::Handlers::PullRequest::AssignedHandler`. [4](#0-3) 
- `AssignedHandler#repository` resolves the target repository from `params.repository.full_name` — a field completely separate from `repository.owner.login` used above — via `Shipit::Repository.from_github_repo_name`, which just splits the string on `/` and does a DB lookup, with no reference back to the authenticated org. [5](#0-4) [6](#0-5) 
- `AssignedHandler#process` then finds the matching `PullRequest` via that repository's `id` and updates it with attacker-supplied `pull_request` fields (assignees, labels, etc.) when `action` is `assigned`/`unassigned`. [7](#0-6) 

Exploit request: a JSON body with `X-Github-Event: pull_request`, `action: "assigned"`, `repository.owner.login: "org-with-no-secret"` (an org configured in Shipit's multi-org `github:` block whose `webhook_secret` is blank), but `repository.full_name: "victim-org/victim-repo"` — the full name of a real, unrelated repository/stack tracked by Shipit (which may belong to an org that *does* have a `webhook_secret` configured). Any `X-Hub-Signature` value (or none) works since the no-secret org's `verify_webhook_signature` short-circuits to `true`.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event name is registered; the `ExplicitParameters` schema (`AssignedHandler.params`) validates types/presence but not cross-consistency between `repository.owner.login` and `repository.full_name` (that field isn't even part of the schema); `GithubOrganizationUnknown` only fires if the org string doesn't match any configured org at all — a real, valid but secret-less org bypasses it entirely.

### Impact Explanation
An unauthenticated attacker can mutate a `Shipit::PullRequest` record (assignees, via `pull_request.update(github_pull_request: params.pull_request)`) belonging to a repository/stack/org that never validated the request — the org used for the trivial "authentication" is unrelated to the org whose data is written. This is a cross-tenant state manipulation: one (attacker-chosen, secret-less) org's webhook credentials are used to write another org's `PullRequest` record. The blast radius is repeatable against any repository whose `full_name` the attacker knows and which is already tracked in Shipit, as long as at least one configured org in the multi-org setup lacks a `webhook_secret`. This matches "a payload for one repository mutating another's stack, commit, task or team" (Critical).

### Likelihood Explanation
Requires: Shipit configured in multi-org mode (`github:` top-level keyed by org names) with at least one org lacking `webhook_secret` — a state explicitly supported and documented as valid configuration (`docs/setup.md`'s "Using Multiple GitHub Applications" section shows `webhook_secret:` left blank as an accepted example), and the target repository already tracked with an existing `PullRequest`/`Stack`. No GitHub, Shipit or victim-org secret is needed by the attacker; cost is a single crafted HTTP POST, fully repeatable.

### Recommendation
Bind the signature-verifying organization to the record-mutating organization: require the org derived from `repository.full_name` (i.e., `Repository.from_github_repo_name(...).owner`) to match the org used in `verify_signature`, or better, have every handler re-verify that the payload's `repository.owner.login` matches the actual `Repository#owner` it is about to touch before mutating any record. Additionally, treat a blank `webhook_secret` for an org as a misconfiguration to reject/warn on rather than silently trusting unsigned payloads.

### Proof of Concept
Minitest (`ActionDispatch::IntegrationTest` or the existing `WebhooksControllerTest` style), using `test/dummy/config/secrets_double_github_app.yml`-like multi-org config with one org (`OrgOne`) having `webhook_secret: nil` and a real tracked repository owned by `victim-org` (a different, secured org):

```ruby
test "assigned webhook authenticated via no-secret org mutates a different org's PullRequest" do
  pull_request = shipit_pull_requests(:review_stack_review) # belongs to victim-org's stack/repository
  pull_request.assignees.clear
  assert_equal [], pull_request.reload.assignees

  payload = JSON.parse(payload(:pull_request_assigned))
  payload["repository"]["owner"]["login"] = "OrgOne"          # no webhook_secret configured
  payload["repository"]["full_name"] = pull_request.stack.repository.github_repo_name # victim-org/victim-repo
  payload["number"] = pull_request.number
  payload["pull_request"]["number"] = pull_request.number

  @request.headers["X-Github-Event"] = "pull_request"
  @request.headers["X-Hub-Signature"] = "sha1=deadbeef" # bogus, irrelevant

  post :create, body: payload.to_json, as: :json
  assert_response :ok

  # Equality check: org that authenticated (OrgOne, no secret) != org that owns mutated record (victim-org)
  refute_equal "OrgOne", pull_request.stack.repository.owner
  assert_equal [shipit_users(:codertocat)], pull_request.reload.assignees # mutated despite mismatch
end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
