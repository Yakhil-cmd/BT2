### Title
Arbitrary/unvalidated `creator` account in `initialize_with_permission` lets pool-creator fees be permanently locked to an attacker-chosen (e.g. zero) address - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`initialize_with_permission` accepts the pool's `creator` field as an `UncheckedAccount` with no `address`, `signer`, or non-default constraint, then stores whatever key is passed as `pool_state.pool_creator`. Since `collect_creator_fee_permissionless` sends all accumulated creator fees to an ATA derived from `pool_creator` with no zero-check, any pool created through this path with a maliciously chosen `creator` (e.g., `Pubkey::default()`) will have its swap-generated creator fees permanently unrecoverable — the same root-cause class as the referenced report (funds routed to an unchecked/attacker-controllable destination).

### Finding Description
`InitializeWithPermission` declares:
```
/// CHECK: creator of pool
pub creator: UncheckedAccount<'info>,
``` [1](#0-0) 
with no signer requirement and no `address =` constraint anywhere in the account struct, unlike the plain `initialize` instruction where `creator` must be a `Signer<'info>` [2](#0-1) . The unchecked value is written directly into pool state:
```
pool_state.initialize(
    ...
    ctx.accounts.creator.key(),
    ...
    creator_fee_on,
    true,
);
``` [3](#0-2)  — note `enable_creator_fee` is hardcoded `true`, so creator-fee accrual is active for every pool created this way.

Later, anyone can call `collect_creator_fee_permissionless`, which validates `creator` only against the stored `pool_creator` (no non-zero check) and creates/uses an ATA owned by that address to receive the funds:
```
#[account(address = pool_state.load()?.pool_creator)]
pub creator: UncheckedAccount<'info>,
...
pub creator_token_0: Box<InterfaceAccount<'info, TokenAccount>>, // associated_token::authority = creator
``` [4](#0-3) [5](#0-4) 
then transfers the full `creator_fees_token_0`/`creator_fees_token_1` balance to it: [6](#0-5) 

If `pool_creator == Pubkey::default()` (or any address with no known private key), the derived ATA is deterministic and constructible, but no one can ever sign for that owner outside the token account itself — the tokens sitting in that ATA become permanently unusable/frozen, exactly mirroring the H-01 pattern of funds routed to an unchecked `0x0`-equivalent destination.

### Impact Explanation
Every swap through a pool created via `initialize_with_permission` accrues `creator_fees_token_0`/`creator_fees_token_1` in `PoolState` (via the swap fee-split logic feeding `pool_state`), and `collect_creator_fee_permissionless` is explicitly designed to be callable by anyone since "the fee is always sent to the pool creator" — but that invariant is broken because `pool_creator` itself was never validated at pool-creation time. This causes permanent freezing of the portion of trading fees earmarked for the pool creator, for the lifetime of the pool. This is a Medium/High severity fund-freezing issue matching the "concrete... permanent freezing of user or LP funds" acceptance criterion.

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a `Permission` PDA (a whitelisted market-maker/partner, not the program admin) in a single transaction; the caller fully controls the `creator` account argument with no on-chain validation, so they can trivially set it to `Pubkey::default()` or any other address whose private key is unavailable. No collusion with governance/admin is required beyond having been granted a `Permission` account, which is the expected way pools are created through this instruction.

### Recommendation
Add validation on `creator` in `InitializeWithPermission` (e.g., `require_keys_neq!(creator.key(), Pubkey::default())`), and additionally add a defensive zero-address check on `pool_state.pool_creator` inside `collect_creator_fee` / `collect_creator_fee_permissionless` before transferring funds, mirroring the confirmed mitigation in the referenced report (check the destination before transfer).

### Proof of Concept
1. A whitelisted payer holding a valid `Permission` PDA calls `initialize_with_permission`, supplying `creator = Pubkey::default()` (or any address they don't intend to ever use) while providing their own `payer_token_0/1` for the initial deposit.
2. `pool_state.initialize(...)` stores `pool_creator = Pubkey::default()` and `enable_creator_fee = true`. [3](#0-2) 
3. Regular swaps against this pool accumulate `creator_fees_token_0`/`creator_fees_token_1` in `PoolState`. [7](#0-6) 
4. Anyone calls `collect_creator_fee_permissionless`, which passes the `address = pool_state.load()?.pool_creator` check (matches the stored zero address) and creates an ATA owned by `Pubkey::default()` to receive the transferred fees. [8](#0-7) 
5. The fees are now held in a token account with no controllable authority — permanently frozen.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```
