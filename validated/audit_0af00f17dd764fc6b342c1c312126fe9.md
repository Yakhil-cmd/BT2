The BentoML report describes an unbounded per-character loop while parsing an HTTP multipart boundary string in a Python web service, with no length cap on the malicious input before the server begins expensive processing (CWE-400/770, generic resource exhaustion). This bug class does not transfer to the Polkadot SDK's Rust/FRAME/XCM architecture, because:

- Extrinsic and XCM decoding paths already enforce strict, checked bounds before processing: extrinsics are decoded through `decode_with_len`/`MAX_CALL_SIZE` limits with `DecodeWithMemLimit` [1](#0-0) , and XCM messages are decoded with explicit instruction-count limits via `decode_xcm_instructions` / `MAX_INSTRUCTIONS_TO_DECODE` [2](#0-1)  and depth limits via `MAX_XCM_DECODE_DEPTH` in `NestedInput::descend_ref` [3](#0-2) .
- Asset collections cap the number of distinct items decoded (`MAX_ITEMS_IN_ASSETS`), rejecting oversized inputs outright rather than looping unboundedly [4](#0-3) .
- Contract host functions bound-check pointer/length before decoding untrusted WASM-supplied buffers, with an explicit nesting limit (`MAX_DECODE_NESTING`) [5](#0-4) .
- Weight metering charges gas/weight proportional to input size *before* full decode/processing for user-supplied XCM blobs, unlike the unmetered BentoML parser (`weigh_message` benchmark charges weight ahead of decode) [6](#0-5) .

Since the review method explicitly excludes "unbounded-loop or memory/storage-growth scenarios" and "generic resource-exhaustion claims," and since the SDK's core decode paths for all real user entry points (extrinsics, XCM messages, contract inputs) already enforce length/depth/instruction caps with weight metering ahead of processing, there is no demonstrable, reachable analog to the BentoML unbounded-boundary-parsing DoS in this codebase.

/// Decode a `vec` of XCM instructions.
///
/// This function keeps track of nested XCM instructions and enforces a total limit of
/// `MAX_INSTRUCTIONS_TO_DECODE`.
pub fn decode_xcm_instructions<I: codec::Input, T: Decode>(
	input: &mut I,
) -> Result<Vec<T>, codec::Error> {
	instructions_count::using_once(&mut 0, || {
		let vec_len: u32 = <Compact<u32>>::decode(input)?.into();
		instructions_count::with(|count| {
			*count = count.saturating_add(vec_len);
			if *count > MAX_INSTRUCTIONS_TO_DECODE as u32 {
				return Err(codec::Error::from("Max instructions exceeded"));
			}
			Ok(())
		})
		.unwrap_or(Err(codec::Error::from("Error calling `instructions_count::with()`")))?;
		let decoded_instructions = decode_vec_with_len(input, vec_len as usize)?;
		Ok(decoded_instructions)
	})
