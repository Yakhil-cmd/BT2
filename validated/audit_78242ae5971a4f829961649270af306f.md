Based on my investigation, I found a genuine analog to the Go `path/filepath.Glob` stack-exhaustion bug class in `ocore`, but it is narrower than a fully proven, unbounded exploit — most recursive evaluators in this codebase (`definition.js`'s `evaluate()`, `formula/validation.js`'s `evaluate()`, `aa_validation.js`'s `validate()`) explicitly cap recursion via `MAX_COMPLEXITY`/`MAX_OPS`/`MAX_DEPTH` counters or periodic `setImmediate` stack breaks. One recursive helper, however, has **no such guard at all**.

### Title
Uncontrolled recursion in `replaceInTemplate`/`replaceInVar` allows stack exhaustion via deeply-nested definition templates - (File: definition.js)

### Summary
`replaceInTemplate` (definition.js) walks an arbitrary JSON structure recursively with no depth limit, unlike every other recursive validator/evaluator in the same file and in `formula/validation.js` and `aa_validation.js`, which all impose an explicit depth cap (`MAX_DEPTH`, `depth > 100`) or interrupt the call stack every 100 iterations via `setImmediate`.

### Finding Description
`replaceInTemplate` is invoked whenever an address/asset spending condition or authentifier evaluation contains a `'definition template'` operator: [1](#0-0) [2](#0-1) 

It fetches a previously stored `definition_template` unit's payload and recursively substitutes parameters: [3](#0-2) 

`replaceInVar` recurses into every array element and object key of `x` with **no depth counter, no complexity increment, and no call-stack-breaking `setImmediate`** — in stark contrast to the `evaluate()` function in the very same file, which increments `complexity`/`count_ops` and aborts once `constants.MAX_COMPLEXITY`/`constants.MAX_OPS` is exceeded: [4](#0-3) 

and to `aa_validation.js`'s recursive `validate()`, which explicitly checks `depth > MAX_DEPTH` and periodically defers via `setImmediate` to avoid deep synchronous call stacks: [5](#0-4) 

and `formula/validation.js`'s `evaluate()`, which does the same (`depth > 100` check plus `setImmediate` every 100 calls): [6](#0-5) 

Because `replaceInVar` lacks any of these mitigations, a `definition_template` payload with deeply nested arrays/objects (analogous to a path with a huge number of separators in the Go bug) will cause `replaceInVar` to recurse once per nesting level with no ceiling, purely bounded by V8's native call-stack size.

### Impact Explanation
Any unit author can (1) post an `app='definition_template'` unit whose payload is a deeply nested array/object structure, wait for it to stabilize, then (2) post/reference an address or asset spending condition using `['definition template', [unit, params]]` in any unit's author definition or asset issue/transfer condition. When any node validates a unit that triggers evaluation of that condition (`Definition.validateDefinition` / `Definition.validateAuthentifiers`), `replaceInTemplate` is invoked and can throw `RangeError: Maximum call stack size exceeded`, crashing or hanging validation on every node that processes that unit — a network-wide denial of the ability to validate/confirm new units built on top of it.

### Likelihood Explanation
Likelihood is Medium-High for reachability (any unit poster can craft and reference such a template with only standard JSON message construction), but I could not fully confirm within tool-call limits whether a node/depth cap is separately enforced when the `definition_template` app payload itself is originally validated at submission time (I did not locate such a check in the reachable validation code for this message type). If such an independent nesting-depth cap exists elsewhere (e.g., a generic message-size/depth sanitizer applied to all unit payloads), the practical impact would be reduced to whatever depth that cap allows. This is the one caveat I was unable to fully verify given remaining budget.

### Recommendation
Add an explicit depth counter (mirroring `MAX_DEPTH`/`depth > 100` used elsewhere in `definition.js`, `aa_validation.js`, and `formula/validation.js`) to `replaceInVar`, aborting with an error once exceeded, and/or replace the recursive walk with an iterative (stack-based) traversal that does not consume native call-stack frames.

### Proof of Concept
1. Attacker posts a `definition_template` unit whose payload is `arrTemplate = [ [ [ [ ... "$x" ... ] ] ] ]` nested tens of thousands of levels deep (or programmatically generated to exceed V8's default stack depth, e.g. ~10,000+ levels).
2. Attacker waits for the unit to stabilize.
3. Attacker posts a unit whose address/asset condition (or `assocAuthentifiers`) includes `['definition template', [template_unit_hash, {x: 'val'}]]`.
4. Any node validating this second unit calls `Definition.validateDefinition`/`validateAuthentifiers` → the `'definition template'` case → `replaceInTemplate(arrTemplate, params)` → unbounded recursive `replaceInVar`, crashing the validating node's process with a stack overflow. [3](#0-2)

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
