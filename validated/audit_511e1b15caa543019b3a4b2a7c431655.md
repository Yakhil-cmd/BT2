### Title
Unverified `github-repo` frontmatter metadata drives silent skill-install redirect to an attacker-chosen repository - (File: pkg/cmd/skills/install/install.go)

### Summary
This finding is the closest reachable analog in `hirayap/cli--008` (the `gh` CLI) to the reported `token_uri` issue: an arbitrary, attacker-supplied string embedded in user-controlled content is trusted by the tool to make a security-relevant decision (here, which repository to fetch and install skill files from), without any independent verification that the claim is genuine.

### Finding Description
`gh skill install` supports a "republisher" detection flow implemented in `checkUpstreamProvenance` [1](#0-0) . It fetches the target skill's `SKILL.md` from the repository the user explicitly asked to install from, parses its YAML frontmatter, and reads the `metadata.github-repo` field verbatim from that file: [2](#0-1) 

This `github-repo` value is entirely attacker-controlled — any publisher of a `SKILL.md` file can set it to any string, since it is normal, user-editable frontmatter (the same field is also written by `InjectGitHubMetadata`/legitimate installs, but nothing prevents a malicious author from hand-authoring it) [3](#0-2) . The only "validation" performed is that the string parses as an `owner/repo` shape via `source.ParseRepoURL` → `ghrepo.FromFullName`, and that it differs from the currently-targeted repo [4](#0-3) [5](#0-4) . There is no cryptographic proof, ownership check, or cross-verification that the claimed "upstream" repository actually published this skill.

When the `--upstream` flag is passed, the CLI acts on this unverified claim automatically and without any prompt: [6](#0-5) 

This return value flows back into `installRun`, which re-targets the entire installation to the attacker-specified repository and restarts the install flow against it: [7](#0-6) 

Even in interactive mode without `--upstream`, the user is shown only the bare `owner/repo` string extracted from the forged field and asked to pick between "re-publisher" and "upstream" — both labels being attacker-influenced text with no way for the user to verify authenticity [8](#0-7) . In non-interactive mode without `--upstream`, the CLI still surfaces this attacker-controlled claim to the user as a warning message [9](#0-8) .

This is structurally identical to the reported bug class: a piece of metadata that is nominally "provenance"/identity information (like `token_uri` claiming to represent a specific rental) is actually fully arbitrary and attacker-suppliable, and downstream logic (here, an install/fetch decision instead of a rendering decision) trusts it to represent a legitimate, different source of truth.

### Impact Explanation
If an attacker publishes (or compromises) a repository containing a `SKILL.md` with a forged `metadata.github-repo` field, a user who runs `gh skill install <attacker-repo> <skill> --upstream` will have their installation silently redirected to and fetched from whatever repository the attacker names in that field — an authenticated GitHub API request/download flow driven entirely by attacker-controlled content, matching the "authenticated request sent to an attacker host" and "downloads to disk" criteria. Because installed skill files are subsequently read/executed as instructions by AI coding agents, this creates a plausible path for smuggling attacker-chosen content into a user's skill directory under a false provenance label, which the user may trust more because it is labeled as "the upstream/canonical source."

### Likelihood Explanation
Requires the user to install from a repository the attacker controls or has compromised, and (for automatic/no-prompt redirection) requires the `--upstream` flag or accepting the interactive prompt. This is a real, unprivileged remote-attacker path reachable through normal `gh skill install` usage (an attacker just needs to get a user to install once from their crafted repo), but it depends on user behavior (using `--upstream` or answering "yes" to the prompt), which lowers the practical likelihood relative to a fully automatic exploit.

### Recommendation
Do not treat the `github-repo` frontmatter field as authoritative provenance. At minimum:
- Never auto-redirect (even with `--upstream`) without an explicit, clearly-worded confirmation that names both the originally requested repo and the claimed upstream, making clear the claim is unverified and self-reported by the source repository.
- Consider verifying the claimed upstream actually contains an equivalent/matching `SKILL.md` (e.g., compare blob content or hash) before treating it as a legitimate republish rather than trusting the label alone.
- Sanitize/validate the `github-repo` string for display (as is already done for other frontmatter fields via `sanitizeForTerminal` in `pkg/cmd/skills/list/list.go`) to prevent terminal/prompt injection via this same attacker-controlled field.

### Proof of Concept
1. Attacker creates `attacker/gh-popular-skill` with a `skills/foo/SKILL.md` containing:
   ```yaml
   ---
   name: foo
   metadata:
     github-repo: https://github.com/attacker/malicious-payload-repo
     github-ref: main
   ---
   ```
2. Victim runs: `gh skill install attacker/gh-popular-skill foo --upstream`.
3. `checkUpstreamProvenance` reads the forged `github-repo` value, and because `opts.Upstream` is true, immediately redirects (`installRun` is re-invoked with `opts.repo = upstreamRepo`) to fetch and install skill files from `attacker/malicious-payload-repo` without any further confirmation [10](#0-9) .

// InjectGitHubMetadata adds GitHub tracking metadata to the spec-defined
// "metadata" map in frontmatter. Keys are prefixed with "github-" to avoid
// collisions with other tools' metadata.
// pinnedRef is the user's explicit --pin value; empty string means unpinned.
// skillPath is the skill's source path in the repo (e.g. "skills/author/my-skill").
func InjectGitHubMetadata(content string, host, owner, repo, ref, treeSHA, pinnedRef, skillPath string) (string, error) {
	result, err := Parse(content)
	if err != nil {
		return "", err
	}

	if result.RawYAML == nil {
		result.RawYAML = make(map[string]interface{})
	}

	meta, _ := result.RawYAML["metadata"].(map[string]interface{})
	if meta == nil {
		meta = make(map[string]interface{})
	}
	delete(meta, "github-owner")
	meta["github-repo"] = source.BuildRepoURL(host, owner, repo)
	meta["github-ref"] = ref
	delete(meta, "github-sha")
	meta["github-tree-sha"] = treeSHA
	meta["github-path"] = skillPath
	if pinnedRef != "" {
		meta["github-pinned"] = pinnedRef
	} else {
		delete(meta, "github-pinned")
	}
	result.RawYAML["metadata"] = meta

	return Serialize(result.RawYAML, result.Body)
}

// ParseRepoURL parses a repository URL stored in skill metadata.
func ParseRepoURL(raw string) (ghrepo.Interface, error) {
	raw = strings.TrimSpace(raw)
	if raw == "" {
		return nil, fmt.Errorf("repository URL is empty")
	}

	repo, err := ghrepo.FromFullName(raw)
	if err != nil {
		return nil, fmt.Errorf("invalid repository URL %q: %w", raw, err)
	}

	return repo, nil
}
