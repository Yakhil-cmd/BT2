### Title
Cross-organization webhook confusion allows unauthorized `Stack#sync_github` invocation with attacker-chosen SHA - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb], [File: app/models/shipit/webhooks/handlers/push_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App config used to check the HMAC signature by reading `repository.owner.login` (or `organization.login`) from the untrusted, unsigned JSON body, while `Webhooks::Handlers::Handler#stacks` selects the target `Repository`/`Stack` using a different field from the same body, `repository.full_name`. Because these two fields are never cross-checked for consistency, an attacker who controls a GitHub org configured in Shipit with no `webhook_secret` can forge a push payload whose `owner.login` is their own org (bypassing signature verification) but whose `full_name` names a victim org/repo, causing `PushHandler#process` to run `stack.sync_github(expected_head_sha: params.after)` on the victim's stack with an attacker-chosen SHA.

### Finding Description
The broken binding is: **`organization used for signature verification` == `owner implied by `repository.full_name` used for the data operation`**.

- `WebhooksController#repository_owner` reads `params.dig('repository', 'owner', 'login')` and `verify_signature` calls `Shipit.github(organization: repository_owner)` to pick the `GitHubApp` config used to verify `X-Hub-Signature`: [1](#0-0) [2](#0-1) 
- `Shipit.github` in multi-org mode (`github_default_organization` non-nil, i.e. per-org config keys as documented) looks up config strictly by the `organization` argument, i.e., by `owner.login`: [3](#0-2) 
- `GitHubApp#verify_webhook_signature` **unconditionally returns `true` when the resolved org's `webhook_secret` is blank**: [4](#0-3) 
- Meanwhile, `Webhooks::Handlers::Handler#stacks` resolves the target repository using a *different* field, `repository.full_name`, via `Repository.from_github_repo_name`: [5](#0-4) 
- `Repository.from_github_repo_name` simply splits the string on `/` and does a DB lookup — no comparison against `owner.login`: [6](#0-5) 
- `PushHandler#process` then unconditionally calls `sync_github` with the attacker-supplied `after` value for every matching, non-archived stack on that branch: [7](#0-6) 

**Attacker request**: a raw `POST /webhooks` with `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "full_name": "victim-org/victim-repo", "owner": { "login": "attacker-org" } }
}
```
No valid `X-Hub-Signature` is needed at all, because `Shipit.github(organization: "attacker-org")` resolves to the attacker's own org config, and if that org's `webhook_secret` is unset/blank, `verify_webhook_signature` short-circuits to `true` regardless of the header value.

**Why guards fail**: `verify_signature` and `drop_unhandled_event` only gate on the event type and on a signature check whose *key selection* is itself attacker-influenced via `owner.login`; there is no assertion anywhere in the controller or `Handler` base class that the org used to authenticate the payload matches the owner encoded in `repository.full_name` used to select the mutated record. `ExplicitParameters` only validates presence/type of `ref`/`after`, not cross-field consistency with the outer, unvalidated `repository` hash (`payload` is the raw, unsigned-at-this-point hash; the `params` object built by `ExplicitParameters::Parameters.define(&block)` also does not re-verify signatures) [8](#0-7) .

### Impact Explanation
An unprivileged attacker who merely controls a GitHub organization that has been installed/configured in this Shipit instance (with no `webhook_secret` set for that org) can force `Stack#sync_github` to run on **any other tenant's** stack tracked by the same Shipit install, with an `expected_head_sha` of the attacker's choosing. `sync_github` triggers `GithubSyncJob`, which fetches commits and can enqueue further pipeline actions (cache deploy spec, retries against arbitrary/nonexistent SHAs) for the victim's deploy pipeline — a cross-repository write against an org that never authenticated this specific payload. This matches "a payload for one repository mutating another's stack" under Critical impact.

### Likelihood Explanation
Preconditions: (1) Shipit configured in the documented multi-org schema (`config/secrets.development.example.yml` shows this is a supported, documented configuration) with at least two orgs, (2) the attacker's own org is one of the configured orgs and has `webhook_secret` unset/blank — a state fully within the attacker's control if they can request/influence their own org's app registration, or that simply exists because an admin left it blank for convenience, (3) a victim org/repo with a tracked stack exists in the same install. Attacker cost is a single unauthenticated HTTP POST with no header requirements. Fully repeatable against any repository/branch known to the attacker in the same Shipit instance.

### Recommendation
Bind signature verification and record selection to the same trusted value: after selecting the `GitHubApp` and verifying the signature for organization `X`, require that `repository.full_name` (or `repository.owner.login`) used by handlers also equals `X`; reject the request otherwise. Alternatively, resolve `Repository`/`Stack` scoping using the same `repository_owner` value validated in `verify_signature`, not an independently-read field. Also consider treating a blank `webhook_secret` for a configured org as "signature verification impossible" (fail closed) rather than "verification bypassed" (fail open) in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`), no live GitHub:
1. Configure two orgs in `Shipit.stubs(:github)`/secrets fixture: `attacker-org` (no `webhook_secret`) and `victim-org` (with `webhook_secret`).
2. Create `shipit_repositories(:victim)` with `owner: "victim-org", name: "victim-repo"` and an associated `Stack` fixture with `branch: "main"`, not archived.
3. POST to `/webhooks` with header `X-Github-Event: push`, no/garbage `X-Hub-Signature`, and body:
```json
{"ref":"refs/heads/main","after":"deadbeefattackersha","repository":{"full_name":"victim-org/victim-repo","owner":{"login":"attacker-org"}}}
```
4. Assert response is `:ok` (signature check passed because org resolved was `attacker-org`).
5. Assert `Stack#sync_github` was invoked (e.g. via `Stack.any_instance.expects(:sync_github).with(expected_head_sha: "deadbeefattackersha")`, or `assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: "deadbeefattackersha"])`) on the victim's stack fixture, proving both sides of the binding (`organization used to verify` = `attacker-org` vs. `owner of repository actually mutated` = `victim-org`) diverge.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
