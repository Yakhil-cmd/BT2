### Title
Missing receipt status check in `writeServiceChainTxReceipts` allows a malicious parent-chain P2P peer to corrupt `WriteAnchoredBlockNumber` with a failed anchoring receipt — (`node/sc/sub_bridge_handler.go`)

### Summary
`writeServiceChainTxReceipts` advances the child chain's persisted anchored block number and removes the anchoring tx from `bridgeTxPool` for **any** receipt matching a pooled tx hash, regardless of `receipt.Status`. A malicious parent-chain P2P peer can craft a `ServiceChainReceiptResponseMsg` carrying a `ReceiptForStorage` with `Status = ReceiptStatusFailed` (0) and a `TxHash` matching a live anchoring tx, causing the child chain to permanently record a block as anchored when it was never committed to the parent chain.

### Finding Description
In `writeServiceChainTxReceipts` (`node/sc/sub_bridge_handler.go`, lines 436–461), for each receipt in the P2P response the code:

1. Looks up the tx in `bridgeTxPool` by `receipt.TxHash`.
2. If the tx is a `ChainDataAnchoring` type, decodes its anchoring data and calls `WriteAnchoredBlockNumber(blockNum)` and `WriteReceiptFromParentChain(...)`.
3. Unconditionally calls `RemoveTx(tx)` to drop the tx from the pool.

At no point is `receipt.Status` inspected. The invariant — that `WriteAnchoredBlockNumber` must only advance for `ReceiptStatusSuccessful` receipts — is entirely absent from the code.

The attacker's tx hash is obtained for free: `broadcastServiceChainReceiptRequest` sends all pending anchoring tx hashes to every connected peer before any receipt is returned.

### Impact Explanation
- `subbridge.chainDB.WriteAnchoredBlockNumber` is permanently advanced for a block whose data was **never** anchored on the parent chain.
- The anchoring tx is removed from `bridgeTxPool`, so no automatic retry occurs.
- The child chain's anchoring integrity is broken: it will never re-anchor that block's data, creating a permanent gap in the cross-chain data commitment record.
- This satisfies the "persistent corruption of … data that breaks … settlement" impact gate.

### Likelihood Explanation
Any node that can establish a bridge P2P connection to the SubBridge (i.e., any node that passes the chain-ID handshake) can execute this attack. The attacker does not need validator keys, governance access, or any privileged role — only a P2P connection to the bridge port and knowledge of a pending anchoring tx hash (which is broadcast to all peers automatically).

### Recommendation
Add a status guard before calling `WriteAnchoredBlockNumber` and `WriteReceiptFromParentChain`:

```go
if tx.Type().IsChainDataAnchoring() {
    // ... decode anchoring data ...
    if receipt.Status == types.ReceiptStatusSuccessful {
        sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
        sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
    } else {
        logger.Warn("anchoring tx failed on parent chain, skipping WriteAnchoredBlockNumber",
            "txHash", txHash, "status", receipt.Status)
        // Do NOT remove from pool; allow retry logic to handle it.
        continue
    }
}
```

Additionally, consider whether a failed anchoring tx should be retried rather than silently dropped.

### Proof of Concept
1. SubBridge has a pending `TxTypeChainDataAnchoring` tx in `bridgeTxPool` with hash `H`, anchoring child block `N`.
2. Attacker connects as a parent-chain P2P peer (passes chain-ID handshake).
3. Attacker receives `H` via the `SendServiceChainReceiptRequest` broadcast.
4. Attacker sends a `ServiceChainReceiptResponseMsg` containing one `ReceiptForStorage{TxHash: H, Status: ReceiptStatusFailed}`.
5. `handleParentChainReceiptResponseMsg` → `writeServiceChainTxReceipts` finds `H` in the pool, calls `WriteAnchoredBlockNumber(N)`, removes `H` from the pool.
6. Assert: `subbridge.chainDB.ReadAnchoredBlockNumber() == N` even though the anchoring tx never succeeded — **invariant violated**.

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}
