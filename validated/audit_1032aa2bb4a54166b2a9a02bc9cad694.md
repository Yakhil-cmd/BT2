### Title
Release asset `Name` field path traversal allows arbitrary file write outside `--dir` - (File: pkg/cmd/release/download/download.go)

### Summary
`gh release download` uses the GitHub API-provided asset `Name` field verbatim as the file name to write, joining it with the destination directory via `filepath.Join` with no path-confinement check. A malicious or compromised release (e.g., in a fork, or via a spoofed API response from a GHES-like host) can set an asset name containing `../` sequences to write files outside the intended download directory.

### Finding Description
In `downloadRun`, each release asset's `Name` (`a.Name`, sourced from `shared.ReleaseAsset.Name`, which is populated directly from the GitHub API response) is passed unmodified into `downloadTarget.name` [1](#0-0) . This flows to `downloadAsset(dest, httpClient, a.url, a.name, isArchive)` and then `dest.Copy(fileName, resp.Body)` [2](#0-1) .

`Copy` calls `w.makePath(name)`, which does `filepath.Join(w.dir, name)` [3](#0-2) . `filepath.Join` cleans `..` segments arithmetically but does not prevent the resulting path from resolving outside `w.dir` — e.g. `filepath.Join("/tmp/out", "../../evil.sh")` yields a path outside `/tmp/out`. `Copy` then calls `os.MkdirAll(dir, 0755)` and `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` on this unchecked path with no containment validation whatsoever [4](#0-3) .

This is in stark contrast to the codebase's own established pattern for handling untrusted archive entry names: both `ExtractZip` in `internal/zip/zip.go` and `extractTarGz`/`extractZip` in `pkg/cmd/copilot/copilot.go` route every entry name through `safepaths.Absolute.Join()`, which returns a `safepaths.PathTraversalError` for any entry that would escape the destination directory [5](#0-4) [6](#0-5) . The release-asset download code path was never updated to use `safepaths`, leaving `name` (the asset's `Name` metadata) as the sole unsanitized traversal vector in this file.

The only filtering applied to `a.Name` before use is `matchAny` against user-supplied `--pattern` globs (optional, and does not restrict `../`) and a Windows-reserved-filename check `isWindowsReservedFilename` [7](#0-6) ; neither blocks path traversal characters.

### Impact Explanation
An attacker who controls a release's asset metadata (e.g., a malicious fork's release that the victim is instructed/tricked into downloading from via `-R owner/fork`, or a spoofed GHES-like API response) can cause `gh release download` to write or overwrite arbitrary files outside the `-D/--dir` target, anywhere the victim's OS user has write permission relative to the resolved traversal path (e.g., overwriting shell startup files, git hooks, or other files in the CWD tree). This matches the GitHub bounty "arbitrary file write" impact class.

### Likelihood Explanation
The precondition — an attacker-controlled release with attacker-chosen asset `Name` — is directly achievable by any GitHub user who can create a release (their own repo, or a fork) since asset filenames are attacker-supplied at upload time. The victim only needs to run `gh release download` against that repo. There is no additional bypass required beyond controlling the release itself.

### Recommendation
Route `name` in `destinationWriter.makePath` through a `safepaths.Absolute.Join`-style check (as already done for zip/tar extraction in `internal/zip/zip.go` and `pkg/cmd/copilot/copilot.go`), rejecting or erroring on any asset name that would escape `w.dir`, instead of using a bare `filepath.Join`.

### Proof of Concept
Add a test in `pkg/cmd/release/download/download_test.go` analogous to the existing `TestExtractTarGz`/`TestExtractZip` "rejects path traversal" subtests:

```go
func TestDownloadAsset_PathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    dest := destinationWriter{dir: tmpDir}

    reg := &httpmock.Registry{}
    defer reg.Verify(t)
    reg.Register(
        httpmock.REST("GET", "assets/1"),
        httpmock.StringResponse("evil content"),
    )
    httpClient := &http.Client{Transport: reg}

    err := downloadAsset(&dest, httpClient, safeurl.NewImmutableSafeURL("https://api.github.com/assets/1"), "../../evil.sh", false)

    // Expect an error (traversal rejected) instead of silent write outside tmpDir
    require.Error(t, err)

    // Confirm no file was written outside tmpDir
    _, statErr := os.Stat(filepath.Join(filepath.Dir(filepath.Dir(tmpDir)), "evil.sh"))
    require.True(t, os.IsNotExist(statErr))
}
```

Currently this test would fail: `downloadAsset` succeeds and writes `evil.sh` two directories above `tmpDir`, confirming the traversal is not blocked.
