## Confirmed: `here_come_the_walrus` fixture is stack-scoped (`stack: shipit`, permissions `read:stack` only), matching exactly what `CCMenuController#stack` bypasses.

### Title
Stack-scoped API client authorization bypass via `CCMenuController#stack` override - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` accessor to load stacks directly by `Stack.from_param!(params[:stack_id])`, bypassing the stack-scoping enforced by `BaseController#stacks`/`#stack`. Any `ApiClient` token that is scoped to a single stack (`stack_id` set) and holds the `read:stack` permission can be used to read CCMenu build-status data for **any** stack in the Shipit instance, not just the one the token was authorized for.

### Finding Description
`BaseController` (the parent of all API controllers) enforces per-token stack scoping through two cooperating methods: [1](#0-0) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

This is the binding the whole API authorization model relies on: **the set of stacks a token authorizes (`current_api_client.stack_id`) must equal the set of stacks a request can touch (`stack`/`stacks`)**. `require_permission :read, :stack` (used throughout, including in `CCMenuController`) only checks the permission bitmask (`read:stack`, `write:stack`, etc.) via `ApiClient#check_permissions!`; it never checks which specific stack the request targets — that check is solely the job of `#stacks`/`#stack`.

`CCMenuController` re-implements `#stack` and, in doing so, drops the scoping call entirely: [2](#0-1) 

```ruby
class CCMenuController < BaseController
  require_permission :read, :stack
  ...
  def show
    latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
    render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
  end

  private

  def stack
    @stack ||= Stack.from_param!(params[:stack_id])
  end
  ...
```

`Stack.from_param!` resolves against **all** stacks (`Stack.all`), with no reference to `current_api_client.stack_id`. Consequently, a token created with a specific `stack_id` (e.g. the `here_come_the_walrus` fixture, which has `stack: shipit` and only `read:stack`) — intended to only ever see one stack — can be replayed with any other `stack_id` param and successfully retrieve that other stack's CCMenu status, defeating the entire purpose of the scoped-token model. Note `CCMenuUrlController` (`app/controllers/shipit/ccmenu_url_controller.rb`) creates such stack-agnostic-looking, but conceptually per-stack, tokens for embedding in third-party CI dashboards — this is precisely the workflow the scoping mechanism exists to protect, and it's exactly the token type broken here.

Before/after equality of the broken binding:
- Before (intended invariant): `stack_touched ∈ {current_api_client.stack_id}` when `current_api_client.stack_id?`.
- After (actual behavior in `CCMenuController`): `stack_touched ∈ Stack.all`, independent of `current_api_client.stack_id`.

### Impact Explanation
This is an unauthenticated-scope escalation: possession of a narrowly-scoped, low-privilege (`read:stack` only) CCMenu token for one stack grants read access to build/deploy status (`lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`, lock state, etc.) for **every** stack in the Shipit instance — including stacks belonging to other teams/repositories the token holder should have no visibility into. This matches the "unauthenticated read of stack state" High-impact category: the credential legitimately held (a single-stack CCMenu token, often embedded in a build-monitor URL that is not treated as highly sensitive) is escalated into a read on the full stack directory.

### Likelihood Explanation
Likelihood is high for any deployment that uses per-stack CCMenu URLs/tokens (a documented, first-class feature — `CCMenuUrlController#fetch` mints such tokens on demand). The attack requires only the token string (which is designed to be embeddable in third-party CCTray/CI dashboard tools, i.e., lower operational sensitivity than a general API credential) and a different `stack_id` in the request path — no additional privilege, signature, or session is needed.

### Recommendation
In `CCMenuController`, remove the `stack` override and use the inherited, scope-enforcing `BaseController#stack` (i.e., `stacks.from_param!(params[:stack_id])`) so that stack-scoped tokens cannot address stacks outside their `stack_id`. If unscoped tokens should remain supported for CCMenu, explicitly reintroduce the `current_api_client.stack_id?` check rather than bypassing it unconditionally.

### Proof of Concept
1. As an authorized operator, create (or use) a stack-scoped API client with only `read:stack`, e.g. fixture `here_come_the_walrus` (`stack_id` = stack "shipit", `permissions: [read:stack]`), or mint one via `GET /stacks/:stack_id/ccmenu_url` for `stack_id=stack-A`.
2. Using that token's Basic-Auth credentials (or `?token=` query param, both supported by `CCMenuController#authenticate_api_client`), issue:
   `GET /api/stacks/stack-B/ccmenu.xml`
   where `stack-B` is any other stack in the instance that the token was never scoped to.
3. Observe the response returns a valid CCMenu XML project payload for `stack-B` (build status, last build label/time, web URL) with `200 OK`, rather than a `404`/`403` — confirming the scoping bypass. Contrast with `Api::StacksController#show`, which correctly rejects cross-stack access for the same scoped token (per existing coverage in [3](#0-2) ), proving the divergence in `CCMenuController`.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
