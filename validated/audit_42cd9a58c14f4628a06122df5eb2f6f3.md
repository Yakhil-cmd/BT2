### Title
Webhook signature check authenticates a claimed `repository.owner.login`, but every event handler acts on the unverified `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App configuration (and thus which `webhook_secret`) to verify the HMAC signature against using `repository_owner`, computed from `params.dig('repository', 'owner', 'login')` [1](#0-0) . That authenticated field is never cross-checked against the field every handler actually uses to select the affected `Repository`/`Stack`: `payload.dig('repository', 'full_name')`, defined in the shared `Handler#repository_name` [2](#0-1)  and consumed identically by `PushHandler#process` via `stacks` [3](#0-2) . This is the exact class of bug the report flags in `TokenState.getLockedCount` (data acted upon is not the data actually validated) applied to a deployment-trust binding: `repository.owner.login` used to authenticate ≠ `repository.full_name` used to execute.

### Finding Description
`verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
``` [4](#0-3) 

`GitHubApp#verify_webhook_signature` explicitly bypasses the check when the selected organization has no `webhook_secret` configured:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [5](#0-4) 

`webhook_secret` is documented as optional (`webhook_secret: # nil`) in every sample config [6](#0-5) [7](#0-6) , and multiple GitHub Apps/organizations can be configured simultaneously [8](#0-7) .

The body of the webhook request is entirely attacker-controlled JSON POSTed to a public `/webhooks` endpoint before any authentication occurs. Nothing forces `repository.owner.login` to equal the owner segment of `repository.full_name` inside that same JSON object — they are two independently attacker-settable strings. An attacker can therefore submit:
```json
{
  "repository": {
    "owner": { "login": "org-without-secret" },
    "full_name": "victim-org/protected-repo"
  },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
`repository_owner` resolves to `"org-without-secret"`, so `Shipit.github(organization: "org-without-secret")` is fetched and `verify_webhook_signature` returns `true` unconditionally (no secret to check against) — the signature check is fully bypassed regardless of what `X-Hub-Signature` header is sent. The request then reaches `PushHandler#process`, which resolves the target purely from `payload.dig('repository', 'full_name')` == `"victim-org/protected-repo"` [9](#0-8) , an org that may well have a properly configured `webhook_secret`. The trust decision (which org's secret authenticates the request) and the trust action (which repository/stack is mutated) are bound to two different, independently attacker-controlled fields of the same unauthenticated payload — breaking the invariant "the organization that authenticated == the repository that is written."

### Impact Explanation
A successful forgery lets an unauthenticated attacker enqueue `GithubSyncJob` for any stack tracking `victim-org/protected-repo`, forcing `Stack#sync_github(expected_head_sha:)` with an attacker-chosen SHA [3](#0-2) , and other handlers (`StatusHandler`, `CheckSuiteHandler`, `PullRequest::*Handler`) that use the same `repository.full_name`-based resolution are equally reachable, letting an attacker inject fabricated CI/commit status or check-suite state, or manipulate review-stack provisioning/archival, for a repository they do not control — as long as any other, unrelated organization in the same Shipit deployment has left `webhook_secret` unset. This can result in unauthorized syncs against arbitrary tracked repositories and corruption of merge/deploy gating signals (commit statuses, check suites) used to decide whether a deploy or merge is safe, meeting the "unauthorized deploy" / cross-repository-write bar.

### Likelihood Explanation
Requires only that at least one configured GitHub organization/App in the Shipit instance has `webhook_secret` blank (explicitly supported, and shown as the default/example value everywhere) — no repository write access, no session, no `ApiClient` token, and no knowledge of any real secret is needed. The attack payload is trivial to craft (a JSON body with divergent `owner.login` vs `full_name`) and is sent to the public, unauthenticated `/webhooks` endpoint.

### Recommendation
Verify the webhook signature using the same field that is used to resolve the acted-upon repository. Derive `repository_owner` from `repository.full_name` (splitting on `/`) rather than from the independent `repository.owner.login` field, or, better, resolve the target `Shipit::Repository` first and then look up the GitHub App/secret bound to that repository's known organization rather than trusting any attacker-supplied field for secret selection.

### Proof of Concept
1. Configure two GitHub orgs in `secrets.yml`, e.g. `attacker-org` (no `webhook_secret`) and `victim-org` (with `webhook_secret` set), matching supported multi-org config [10](#0-9) .
2. `victim-org/protected-repo` has an existing `Stack` tracked in Shipit.
3. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/protected-repo"
  }
}
```
No valid `X-Hub-Signature` header is required.
4. `verify_signature` resolves `Shipit.github(organization: "attacker-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` and the request proceeds [4](#0-3) [5](#0-4) .
5. `PushHandler` resolves stacks via `repository.full_name == "victim-org/protected-repo"` [9](#0-8)  and enqueues `GithubSyncJob` with the attacker-chosen `expected_head_sha` for the victim's stack, despite the request never having been signed by `victim-org`'s app.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
