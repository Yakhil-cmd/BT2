### Title
Webhook signature verification authenticates the payload's `repository.owner` organization but handlers act on the unauthenticated `repository.full_name` field, enabling cross-organization forged webhooks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App secret to validate the HMAC signature against based on `repository.owner.login` (or `organization.login`) taken directly from the untrusted JSON body, while every event handler (`PushHandler`, the `pull_request` handlers, `ReviewStackAdapter`, etc.) subsequently looks up the `Stack`/`Repository` to act on using a *different* field of the same body, `repository.full_name`. Because these two fields are independently attacker-controlled inside one JSON document, an attacker who legitimately controls one configured GitHub organization (and thus knows that organization's `webhook_secret` from their own GitHub App settings) can sign an arbitrary payload with their own secret while setting `repository.full_name` to any other repository/stack already tracked by the Shipit instance.

### Finding Description
Shipit supports hosting multiple GitHub organizations behind a single Rails app and a single shared `/webhooks` endpoint [1](#0-0) . Each organization has its own `webhook_secret`, selected at runtime via `Shipit.github(organization: ...)` / `Shipit.github_app_config(organization)` [2](#0-1) .

`WebhooksController#verify_signature` determines which organization's secret to use for signature verification purely from payload content:
```
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where
```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 

The HMAC check (`verify_webhook_signature`) only proves that the raw body was signed with *some* organization's secret — the organization it was signed with is itself chosen from the same unauthenticated body that produced the signature to validate against [4](#0-3) . It never checks that `repository.owner.login` matches `repository.full_name`'s owner segment, nor does any handler re-derive the acted-upon repository from the authenticated organization.

Every handler instead resolves the actual `Repository`/`Stack` to mutate from `repository.full_name`:
```
def repository_name
  payload.dig('repository', 'full_name')
end

def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end
``` [5](#0-4) 
and the same pattern is used by `PushHandler` [6](#0-5) , and every `pull_request` handler (`ClosedHandler`, `OpenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `LabelCapturingHandler`) via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [7](#0-6) [8](#0-7) .

This is exactly analogous to the reported bug class: two independently-supplied fields inside one signed payload are checked/authenticated by one field while the sensitive action is driven by the other, breaking the binding `organization authenticated == repository written`. In the report, the trade fee/royalty/protocol-fee amounts are computed and transferred out of proportion because the code trusts one derived value while acting on another that isn't bounded relative to it; here, the code verifies trust ("this body was signed by organization X's secret") but acts on a value ("full_name") that is never checked to belong to organization X.

### Impact Explanation
An attacker who is a legitimate admin/owner of one GitHub organization configured in Shipit's multi-org `github:` secrets block (and therefore knows that org's own `webhook_secret`, which they configured themselves when installing their GitHub App) can POST directly to the shared `/webhooks` endpoint with:
- `repository.owner.login` = their own org (so `verify_signature` picks their own secret and the HMAC passes)
- `repository.full_name` = `"victim-org/victim-repo"` (any repository already tracked by the shared Shipit instance)

This lets them trigger, on a repository outside their authorization boundary:
- `PushHandler`, causing `stack.sync_github(expected_head_sha: ...)` to run for the victim stack/branch, forging a push/sync event and influencing which commit is considered "head" for deploys [9](#0-8) .
- Pull-request handlers that archive/unarchive/create review stacks and deprovision environments for the victim repository [10](#0-9) .

This crosses the repository/organization authorization boundary that the shared webhook endpoint is supposed to enforce via signature verification, meeting the "cross-repository writes" / "unauthorized deploy, rollback" bar for Critical impact, since state changes (sync, provisioning, archiving) on a repository the caller does not control are triggered using only the caller's own, unrelated organization credentials.

### Likelihood Explanation
This is only exploitable when Shipit is deployed in the documented multi-organization configuration (multiple `github:` sub-keys in `config/secrets.yml`), which is an explicitly supported and documented setup [1](#0-0) . In that mode, any org owner among the configured organizations can exploit this without needing GitHub to relay a real webhook — a direct HTTP POST with a self-computed HMAC using their own known secret suffices, since the verification code never binds the authenticated organization to the acted-upon repository. This requires no repository write access to the victim repo, no leaked secrets, and no privileged Shipit account.

### Recommendation
After successfully verifying the signature, derive the organization to trust strictly from the *same* value used for verification and reject/require that `repository.full_name`'s owner segment (or `repository.owner.login`) matches the organization whose secret validated the signature, before any handler is allowed to resolve `Repository.from_github_repo_name`. Concretely, pass the authenticated `repository_owner` into `Webhooks.for_event(event).each { |handler| handler.call(params) }` and have `Handler#stacks`/`#repository_name` assert that the resolved repository's `owner` equals the authenticated organization, rejecting (422) on mismatch.

### Proof of Concept
Assume Shipit is configured per the multi-org example in `docs/setup.md` with organizations `somegithuborg` (attacker-controlled) and `victim-org` (has a tracked `Stack` for `victim-org/victim-repo`, branch `main`).

1. Attacker knows `webhook_secret` for `somegithuborg` (it's their own GitHub App configuration).
2. Attacker builds a push payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "owner": { "login": "somegithuborg" }, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC_SHA1(somegithuborg_secret, raw_body)` and POSTs to `/webhooks` with header `X-Github-Event: push`.
4. `WebhooksController#repository_owner` returns `"somegithuborg"`; `Shipit.github(organization: "somegithuborg")` resolves the attacker's own app, and `verify_webhook_signature` succeeds because the attacker signed it correctly with their own secret [11](#0-10) .
5. `PushHandler#process` resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and runs `stack.sync_github(expected_head_sha: params.after)` against the victim's stack [5](#0-4) [9](#0-8) , despite the attacker never having been authenticated for `victim-org`.

Note: I was unable to fully trace `Stack#sync_github`/`GithubSyncJob` implementation within this session due to tool limitations, so the precise downstream consequences (e.g., whether this can force an actual deploy versus merely updating cached head-sha state) could not be fully confirmed and should be verified directly in `app/models/shipit/stack.rb` and `app/jobs/shipit/github_sync_job.rb` before finalizing severity.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
