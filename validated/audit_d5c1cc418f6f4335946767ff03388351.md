### Title
Malicious Bridge Operator Can Front-Run User's KLAY Transfer to Inflate Fee and Drain Value — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

### Summary

The `Bridge` contract's fallback function reads `feeOfKLAY` at execution time, not at submission time. A bridge operator (a semi-trusted role that can call `setKLAYFee` unilaterally when the configuration threshold is 1) can front-run a user's pending bridge transfer, raise the fee to any value below `msg.value`, and cause the user to pay excess KAIA fees while transferring less KAIA than intended.

### Finding Description

The `BridgeTransferKLAY` fallback function passes the **current** `feeOfKLAY` as `_feeLimit` at the moment of execution:

```solidity
// BridgeTransferKLAY.sol line 127-129
function () external payable {
    _requestKLAYTransfer(msg.sender, feeOfKLAY, new bytes(0));
}
``` [1](#0-0) 

Inside `_requestKLAYTransfer`, `_payKLAYFeeAndRefundChange(_feeLimit)` is called, which reads `feeOfKLAY` again and deducts it from the user's `msg.value`:

```solidity
// BridgeFee.sol line 43-66
function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
    uint256 fee = feeOfKLAY;
    if (feeReceiver != address(0) && fee > 0) {
        require(_feeLimit >= fee, "insufficient feeLimit");
        (bool ok, ) = feeReceiver.call.value(fee)("");
        ...
    }
}
``` [2](#0-1) 

The fee is mutable by any bridge operator via `setKLAYFee`, which requires only that `configurationNonce` matches and that enough operators vote. The bridge is deployed with a **default threshold of 1**, meaning a single operator can change the fee in one transaction:

```solidity
// BridgeOperator.sol line 54-57
constructor() internal {
    for (uint8 i = 0; i < uint8(VoteType.Max); i++) {
        operatorThresholds[uint8(i)] = 1;
    }
``` [3](#0-2) 

```solidity
// BridgeTransferKLAY.sol line 144-152
function setKLAYFee(uint256 _fee, uint64 _requestNonce)
    external
    onlyOperators
{
    if (!_voteConfiguration(_requestNonce)) { return; }
    _setKLAYFee(_fee);
}
``` [4](#0-3) 

The `_voteConfiguration` function immediately ratifies the change when the vote count reaches the threshold:

```solidity
// BridgeOperator.sol line 119-132
function _voteConfiguration(uint64 _requestNonce) internal returns(bool) {
    require(configurationNonce == _requestNonce, "nonce mismatch");
    bytes32 voteKey = keccak256(msg.data);
    if (_voteCommon(VoteType.Configuration, _requestNonce, voteKey)) {
        configurationNonce++;
        return true;
    }
    return false;
}
``` [5](#0-4) 

### Impact Explanation

A user submitting a fallback transaction with `msg.value = old_fee + transfer_amount` expects to pay `old_fee` and bridge `transfer_amount` KAIA. If a malicious operator front-runs with `setKLAYFee(new_fee)` where `old_fee < new_fee < msg.value`:

- `_feeLimit` is set to `new_fee` (the inflated fee) at execution time
- `require(msg.value > _feeLimit)` passes since `msg.value > new_fee`
- The user pays `new_fee` to `feeReceiver` instead of `old_fee`
- The bridged transfer amount becomes `msg.value − new_fee`, which is less than `transfer_amount`
- The user loses `new_fee − old_fee` KAIA in excess fees, with no recourse

This is an unauthorized fee charge affecting KAIA on the bridge path.

### Likelihood Explanation

- The bridge is deployed with a default configuration threshold of 1, so a single operator can execute the attack in one transaction with no coordination.
- `configurationNonce` is a public state variable, so the attacker always knows the correct nonce to pass.
- The fallback function is the natural entry point for users sending KLAY to the bridge, making it a high-traffic target.
- The attack is mempool-observable and requires only standard transaction ordering (front-running), which is feasible on any chain where the operator controls a node or monitors the mempool.

### Recommendation

1. **Snapshot the fee at submission time**: Change the fallback and `requestKLAYTransfer` functions to accept an explicit `_feeLimit` parameter from the caller, so the user commits to a maximum fee they are willing to pay and the transaction reverts if the actual fee exceeds it.
2. **Enforce a minimum threshold**: Require `operatorThresholds[Configuration] >= 2` at deployment, or enforce it in the constructor, so no single operator can unilaterally change fees.
3. **Add a time-lock or fee-change delay**: Require that fee changes only take effect after a delay (e.g., N blocks), giving users time to observe the change before their pending transactions execute.

### Proof of Concept

```
State: feeOfKLAY = 0.1 KAIA, feeReceiver = operator_wallet, threshold = 1

1. User submits fallback tx: msg.value = 1.1 KAIA
   (intends to bridge 1.0 KAIA, pay 0.1 KAIA fee)

2. Operator sees tx in mempool, front-runs with:
   setKLAYFee(0.9 KAIA, configurationNonce)
   → feeOfKLAY updated to 0.9 KAIA immediately (threshold=1)

3. User's fallback tx executes:
   _feeLimit = feeOfKLAY = 0.9 KAIA
   require(1.1 > 0.9) → passes
   _payKLAYFeeAndRefundChange(0.9):
     fee = 0.9 KAIA → paid to feeReceiver
     refund = 0.9 - 0.9 = 0
   transfer_amount = 1.1 - 0.9 = 0.2 KAIA bridged

4. Result: User paid 0.9 KAIA in fees (expected 0.1 KAIA),
   bridged only 0.2 KAIA (expected 1.0 KAIA).
   Excess extracted: 0.8 KAIA → feeReceiver (operator-controlled).
```

    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }
