### Title
Webhook signature verification org is decoupled from the repository owner used to resolve stacks, allowing cross-tenant `GithubSyncJob` enqueue - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks the GitHub App/organization used to validate the HMAC via `repository_owner`, which falls back to the top-level `organization.login` field when `repository.owner.login` is absent. `Webhooks::Handlers::PushHandler` (via `Handler#repository_name`) independently resolves the target repository/stack from `repository.full_name`. Because these two fields are never cross-checked, an attacker who controls a legitimate Shipit-configured GitHub App/org can forge a payload that is HMAC-verified under their own org while pointing `repository.full_name` at a victim tenant's repository, causing a `GithubSyncJob` to be enqueued for that victim's stack.

### Finding Description
The broken binding is the equality: `organization whose webhook_secret verified the request bytes` (`repository_owner` = `params.dig('repository','owner','login') || params.dig('organization','login')`, `app/controllers/shipit/webhooks_controller.rb:59-62`) must equal `organization owning repository.full_name` (used later in `app/models/shipit/webhooks/handlers/handler.rb:33-38` and `app/models/shipit/repository.rb:53-56`). These two values are computed from disjoint fields of the same JSON body with no reconciliation.

Path:
1. `before_action :verify_signature` runs before `create`. It computes `repository_owner` and calls `Shipit.github(organization: repository_owner)`, then `github_app.verify_webhook_signature(signature, request.raw_post)` (`app/controllers/shipit/webhooks_controller.rb:24-30`), which internally does `OpenSSL::HMAC.hexdigest` against that org's own `webhook_secret` (`lib/shipit/github_app.rb:76-83`).
2. `create` re-parses the same raw body and dispatches to `Shipit::Webhooks.for_event(event)` handlers (`app/controllers/shipit/webhooks_controller.rb:10-15`).
3. `PushHandler#process` calls `stacks`, which resolves via `Repository.from_github_repo_name(repository_name)` where `repository_name = payload.dig('repository', 'full_name')` (`app/models/shipit/webhooks/handlers/handler.rb:33-38`), completely independent of the org used in step 1.
4. Matching stacks are pulled via `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }` (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`), enqueuing `GithubSyncJob` for whatever stack belongs to the repo named in `repository.full_name`.

Attacker request: POST `/webhooks` with `X-Github-Event: push`, body containing no `repository.owner.login`, `organization.login: "attacker-org"`, `repository.full_name: "shopify/shipit-engine"`, `ref`/`after` set to the target branch/sha, and `X-Hub-Signature` computed with `attacker-org`'s own `webhook_secret` (which they legitimately know because they registered that GitHub App tenant in Shipit). `verify_signature` resolves `repository_owner` to `attacker-org`, fetches `attacker-org`'s `GithubApp`, and successfully verifies the signature against bytes the attacker crafted themselves. `create` then dispatches to `PushHandler`, which resolves the real `shopify/shipit-engine` repository/stack from `repository.full_name` and enqueues `GithubSyncJob` for it.

No existing guard closes this gap: `drop_unhandled_event` only checks the event type exists a handler; the `ExplicitParameters` schema for `PushHandler` only requires `:ref` and `:after`, not repository/owner consistency; there is no code anywhere that compares `repository_owner` (used for HMAC selection) against the owner segment of `repository.full_name` (used for stack resolution). The `repository_owner` fallback to `organization.login` exists to support events like `membership` that lack a `repository` key entirely, not `push`, but nothing in the code restricts the fallback to such events.

### Impact Explanation
This is a cross-tenant write: a payload validated under `attacker-org`'s webhook secret triggers `GithubSyncJob.perform_later` for a stack belonging to `shopify` (or any other Shipit tenant repo), which will resync the stack's commit list/state from GitHub using Shipit's real GitHub App credentials for `shopify`. This matches the "payload for one repository mutating another's stack" Critical criterion. It is trivially repeatable against any repository/stack known to the attacker by name, as long as the attacker controls one legitimately-configured GitHub App/org within the same Shipit instance (multi-tenant Shipit installs are the realistic target). Blast radius covers every stack in the Shipit instance reachable through `PushHandler`, and potentially any other handler that resolves repository/stack from body fields distinct from `repository_owner` (e.g. `status`, `check_suite` handlers likely share the same `Handler#repository_name` pattern).

### Likelihood Explanation
Preconditions: a multi-tenant Shipit deployment where the attacker has legitimately registered/owns a GitHub App organization configured in Shipit (so they know that org's `webhook_secret`), and the target tenant/stack exists. No Shipit session, API token, or victim secret is needed. Attacker cost is minimal (craft one JSON body, compute one HMAC with a secret they already possess, send one HTTP POST). It is fully repeatable and requires no timing or race conditions — a single POST per attempt.

### Recommendation
Do not select the verifying `GithubApp` from an untrusted, attacker-influenced fallback field that is decoupled from the entity the handlers actually act upon. Concretely:
- In `repository_owner`, only fall back to `organization.login` when `repository` is entirely absent from the payload (not merely when `owner.login` is missing under an otherwise-present `repository`), and require that this fallback only apply to event types that are documented to lack a `repository` key.
- Additionally, add an explicit check when both `repository.full_name` and `organization.login` are present: verify that `repository.full_name.split('/').first.casecmp?(organization.login)` (or equivalent) before proceeding, rejecting with 422 on mismatch.
- More robust: after determining the actual target repository per-handler, re-verify (or verify only once) using the `GithubApp` for the *repository's* owner rather than a value taken from a different top-level payload key.

### Proof of Concept
Add to `test/controllers/webhooks_controller_test.rb`:
```ruby
test ":push with mismatched organization vs repository.full_name syncs the wrong tenant's stack" do
  request.headers['X-Github-Event'] = 'push'

  parsed_body = JSON.parse(payload(:push_master))
  parsed_body.delete('repository')['owner'] rescue nil
  parsed_body['repository'].delete('owner')          # no repository.owner.login
  parsed_body['organization'] = { 'login' => 'attacker-org' }
  parsed_body['repository']['full_name'] = @stack.repository.github_repo_name # e.g. "shopify/shipit-engine"
  expected_head_sha = parsed_body['after']

  # Attacker's own org verifies successfully with their own secret
  Shipit.github(organization: 'attacker-org').stubs(:verify_webhook_signature).returns(true)

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: @stack.id, expected_head_sha:]) do
    post :create, body: parsed_body.to_json, as: :json
  end
end
```
Both sides of the claimed binding — `repository_owner` resolved to `'attacker-org'` (verifying org) vs. `parsed_body['repository']['full_name'].split('/').first` resolved to `'shopify'`/the real tenant owner (the org whose stack is mutated) — are asserted to diverge while the job still gets enqueued for the real stack, proving the vulnerability.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
