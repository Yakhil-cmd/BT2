### Title
RAY value overflow permanently freezes an oversized high-utilization market - (File: common/src/rates/simulate.rs)

### Summary
An unprivileged user can open a sufficiently large, high-utilization borrow position and eventually push the market into a state where every interest-accrual call panics with `MathOverflow`. The panic occurs before `MAX_BORROW_INDEX_RAY` can cap index growth, permanently blocking repayments, withdrawals, liquidations, and other operations that touch the market. [1](#0-0) 

### Finding Description
Every pool mutation loads the market through `synced_market`, which calls `interest::global_sync` before applying the requested operation. [2](#0-1)  `global_sync` feeds each elapsed chunk into `accrue_step`, which first computes the current debt value with `scaled_to_original(borrowed, borrow_index)` and supply value with `scaled_to_original(supplied, supply_index)`. [3](#0-2) [4](#0-3)  `scaled_to_original` performs a checked RAY multiplication and traps when the scaled-share amount times the index exceeds `i128`. [5](#0-4) 

The existing harness demonstrates this reachable cliff with an 18-decimal market containing one billion whole tokens and 98% utilization: after sustained accrual, `update_indexes` returns `MathOverflow`, while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`. [6](#0-5)  Because `last_timestamp` is only advanced after all accrual chunks complete, a failing chunk leaves the stale timestamp in place and every later market operation repeats the same overflowing calculation. [7](#0-6) 

### Impact Explanation
Once the product of scaled debt or supply shares and its index exceeds the RAY value ceiling, the affected market is permanently frozen rather than merely rejecting one oversized input. [8](#0-7)  Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce risk, and revenue or debt-management paths that accrue the same market cannot execute. [9](#0-8)  This constitutes permanent freezing of user funds and leaves the market unable to operate despite holding token balances.

### Likelihood Explanation
The attacker only needs ordinary `supply` and `borrow` calls to establish an extremely large position, then calls the permissionless `update_indexes(caller, Vec<HubAssetKey>)` entrypoint as time passes until accrual reaches the overflow boundary. [10](#0-9)  The trigger requires whale-scale liquidity, high utilization, and substantial accrued interest, so it is not economically trivial. [11](#0-10)  Nevertheless, market size and utilization are normal protocol variables, and the demonstrated state uses supported token decimals rather than corrupt storage or privileged runtime manipulation. [12](#0-11) 

### Recommendation
Cap or saturate index growth before converting scaled shares back to RAY value, and use widened arithmetic for the boundary comparison. In particular, detect `scaled > MAX_RAY_VALUE / index` before calling `scaled_to_original`, apply `MAX_BORROW_INDEX_RAY` or `MAX_SUPPLY_INDEX_RAY` in a way that preserves liveness, and commit a recoverable final accrual state instead of trapping. Add a regression test proving that a market at the tested boundary can still execute at least `repay`, `withdraw`, `liquidate`, and `clean_bad_debt`.

### Proof of Concept
The repository’s `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` test establishes the sequence end to end. [13](#0-12) 

1. Create an 18-decimal market and a collateral market, then disable the test market utilization ceiling and raise caps as the harness does. [14](#0-13) 
2. Through controller `supply(caller, account_id, spoke_id, assets)`, deposit `1_000_000_000 * 10^18` base units of `BIG18` for `BOB`. [15](#0-14) 
3. Supply collateral to `ALICE` and call `borrow(caller, account_id, borrows, to)` for 98% of the `BIG18` principal. [16](#0-15) 
4. Advance ledger time and repeatedly call `update_indexes(caller, [BIG18])`; eventually the call returns `MathOverflow` while the stored borrow index remains below its cap. [17](#0-16) 
5. Call `withdraw(caller, BOB_account, [(BIG18, 1)], to)` or `repay(caller, ALICE_account, [(BIG18, amount)])`; both panic with `MathOverflow` before reaching their operation-specific logic. [8](#0-7)

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
