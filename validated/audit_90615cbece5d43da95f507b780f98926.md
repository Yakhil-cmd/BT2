### Title
Forged `pull_request` webhook signed under a no-secret org's identity mutates a different org's review stack - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate the HMAC using `params.dig('repository','owner','login')`, while every `pull_request` handler resolves and mutates the target `Repository`/review stack using `params.repository.full_name`. Because these two fields are never checked for consistency, and because `GitHubApp#verify_webhook_signature` trivially returns `true` when the resolved organization has no `webhook_secret` configured, an attacker can pick a no-secret org for `repository.owner.login` and any victim org/repo for `repository.full_name`, producing a request that passes verification but drives handler side effects (archive/unarchive review stacks, provision stacks on `opened`) against a repository the attacker never authenticated for.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:

`repository_owner_used_for_signature == Repository.from_github_repo_name(params.repository.full_name).owner`

In `app/controllers/shipit/webhooks_controller.rb`:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end

def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
  ...
end
``` [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` looks up the GitHub App config keyed by `repository_owner`, and `GitHubApp#verify_webhook_signature` is:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

So if the organization named in `repository.owner.login` is configured in Shipit but has no `webhook_secret` set (a "no-secret org"), signature verification is bypassed entirely — any payload, any signature, passes.

Meanwhile, every `pull_request` handler (`OpenedHandler`, `ClosedHandler`, `ReopenedHandler`, `LabeledHandler`, `UnlabeledHandler`, `LabelCapturingHandler`, `AssignedHandler`) derives the repository it mutates purely from `params.repository.full_name`, completely independent of `repository.owner.login`:
```ruby
def repository
  @repository ||= Shipit::Repository.from_github_repo_name(params.repository.full_name) ||
                  Shipit::NullRepository.new
end
``` [4](#0-3) [5](#0-4) 

`Repository.from_github_repo_name` splits `full_name` on `/` and does a plain DB lookup with no ownership check against the signature-verifying org:
```ruby
def self.from_github_repo_name(github_repo_name)
  repo_owner, repo_name = github_repo_name.downcase.split('/')
  find_by(owner: repo_owner, name: repo_name)
end
``` [6](#0-5) 

Exploit flow: attacker crafts a `pull_request` / `action: opened` JSON body where `repository.owner.login = "no-secret-org"` (an org present in Shipit's GitHub app config but without a `webhook_secret`) and `repository.full_name = "victim-org/victim-repo"`. `Webhooks.for_event('pull_request')` fans this payload out to all registered `Handlers::PullRequest::*` handlers unconditionally [7](#0-6) [8](#0-7) . `verify_signature` passes (secret-less org, `return true unless webhook_secret`), and `OpenedHandler#process` resolves `victim-org/victim-repo`'s `Repository` and calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!`, provisioning/mutating a review stack the attacker does not own [9](#0-8) .

No existing guard closes this gap: `verify_signature` never cross-checks `repository_owner` against `repository.full_name`'s owner segment; `drop_unhandled_event` only checks that a handler exists for the event type, not payload consistency [10](#0-9) ; the `ExplicitParameters` schemas only validate types/presence of `repository.full_name`, not that it matches the org whose secret validated the request [11](#0-10) ; and `Repository#validates` only constrains character format, not cross-org consistency [12](#0-11) .

### Impact Explanation
An attacker who can send an unauthenticated `POST /webhooks` request can drive `pull_request` lifecycle handlers (`opened`, `closed`, `reopened`, `labeled`, `unlabeled`, assignment/label capture) against any repository tracked by Shipit, as long as they can name a configured-but-secretless organization in `repository.owner.login`. This lets them provision, archive, or unarchive review stacks belonging to a victim repository/organization — a payload for one repository mutating another's stack, matching the Critical "cross-tenant/cross-repository state manipulation" category. The blast radius is every repository/stack across all organizations onboarded to the same Shipit instance, and the attack is fully repeatable per request with no rate limiting mentioned in this path.

### Likelihood Explanation
Preconditions: the Shipit instance must have at least one organization configured in `Shipit.github_apps` without a `webhook_secret` (a plausible/likely misconfiguration or intentionally lax setup for a low-risk org), and at least one other org/repo (the victim) with review stacks enabled. The attacker needs no Shipit session, API token, or GitHub permissions on the victim repo — only knowledge of the secretless org's login name and the victim's `owner/name`, both of which are typically public information (GitHub org/repo names). This is a single crafted HTTP POST, trivially repeatable and scriptable.

### Recommendation
Enforce that the organization used to verify the webhook signature matches the owner of the repository referenced by `full_name` before dispatching to handlers — e.g., derive `repository_owner` strictly from `full_name.split('/').first` (or explicitly compare `repository.owner.login` against the `full_name` owner segment and reject mismatches with 422). Additionally, do not treat a missing `webhook_secret` as an implicit signature bypass (`return true unless webhook_secret`); require all onboarded organizations to have a configured secret, or reject webhooks from secretless orgs outright.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` style, hypothetical — not committed since `test/**` is out of scope for remediation but valid for validation):
```ruby
test "cross-org pull_request opened forges review stack for a different repo" do
  victim_repo = shipit_repositories(:some_review_stack_repo) # owner: 'victim-org', review_stacks_enabled: true, provisioning_behavior_allow_all
  no_secret_org = 'no-secret-org' # configured in Shipit.github_apps with no webhook_secret

  before_count = victim_repo.review_stacks.count

  body = {
    action: 'opened',
    number: 999,
    pull_request: {
      id: 1, number: 999, url: 'https://x', title: 't', state: 'open',
      additions: 1, deletions: 1,
      head: { sha: 'a'*40, ref: 'feature' },
      user: { login: 'attacker' }, assignees: [], labels: []
    },
    repository: { owner: { login: no_secret_org }, full_name: "#{victim_repo.owner}/#{victim_repo.name}" },
    sender: { login: 'attacker' }
  }.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary/invalid signature

  assert_difference -> { victim_repo.review_stacks.count }, 1 do
    post :create, body:, as: :json
  end
  assert_response :ok
end
```
Assertions on both sides of the broken binding: before the request, `repository_owner` (`no-secret-org`) != owner of `Repository.from_github_repo_name(params.repository.full_name)` (`victim-org`) — the invariant "the org that verified the signature owns the mutated repo" is false, yet `verified` is `true` because `webhook_secret` is `nil` for `no-secret-org`, and `victim_repo.review_stacks.count` still increases by 1, proving the divergence is exploitable.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
