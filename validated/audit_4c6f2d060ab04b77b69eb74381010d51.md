### Title
Unprivileged collateral top-up straddles the bad-debt dust cap, permanently blocking permissionless `clean_bad_debt` — ([File: contracts/controller/src/positions/supply.rs](contracts/controller/src/positions/supply.rs))

### Summary
`clean_bad_debt` admits an insolvent account only while its remaining collateral is at or below the fixed $5 `BAD_DEBT_USD_THRESHOLD`. The permissionless third-party `supply` path lets any address top up a supply leg the account already holds. An attacker can keep any insolvent account's `total_collateral` strictly above the dust cap, so the permissionless cleanup always reverts and the only remaining path is the owner-gated, timelocked `force_socialize_bad_debt`. This maps the CVE-2017-6266 class — improper access control enabling unprivileged denial of service — onto the lending protocol's own bad-debt gate.

### Finding Description
The dust gate lives in `is_socializable_bad_debt`, used by `socialize_bad_debt` under `BadDebtGate::DustCapped`:

- `process_clean_bad_debt` is callable by anyone: only `caller.require_auth()` and `require_not_flash_loaning` are checked — `contracts/controller/src/positions/liquidation/mod.rs:196-200`.
- Admission requires `is_socializable_bad_debt(total_debt, total_collateral)`, i.e., `D > C` **and** `C <= BAD_DEBT_USD_THRESHOLD` — `mod.rs:229-235`.
- Third-party supply is restricted only by asset-slot ownership, not by value: `require_third_party_existing_supply` asserts only that the account already holds a `supply_positions` entry for each supplied `HubAssetKey` — `contracts/controller/src/positions/supply.rs:86-96`. There is no insolvency, HF, or dust-aware check on this path, and `supply`/`repay` skip the final risk gate per INV-STRAT-02/endpoints.
- The Certora rule `bad_debt_straddle_blocks_dust_gate` confirms the exploit primitive exactly: any `collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1` with `debt_wad > collateral_wad` is insolvent yet rejected by the dust gate (`certora/controller/spec/boundary_rules.rs:44-67`). Only the owner-only `force_socialize_bad_debt` (`BadDebtGate::InsolventOnly`, `mod.rs:246-249`) admits that straddled state, and it requires a governance Sensitive-tier timelock (`docs/reference/runbooks/force-socialize-bad-debt.md`).

Attack path for one unprivileged address:
1. Wait for (or create via own positions + price move) an account that is insolvent with `C <= $5` — the state `clean_bad_debt` exists to clear.
2. Call `controller.supply(attacker, victim_account_id, victim_spoke_id, [(held_hub_asset, amount)])` where `held_hub_asset` is a supply leg the victim already has, with just enough to push `total_collateral` above $5.
3. Every subsequent `clean_bad_debt` reverts `CannotCleanBadDebt` (`mod.rs:235`).
4. If liquidators seize the donated collateral back under the cap, repeat step 2 in the same or next ledger — each `supply` is atomic and permissionless, so the straddle can be re-established cheaper than a timelocked governance intervention.

Note the attacker loses the donated collateral to liquidation seizure, but the check is *value-based, not slot-based*: top-ups into the existing leg suffice, and the attacker can interleave with liquidations indefinitely for the cost of ~$5 plus gas per round.

### Impact Explanation
Bad debt that should be socialized stays live on the books: the unbacked borrow positions are never written down through `bad_debt::execute_bad_debt_cleanup`, so the supply-index write-down and account/NFT removal are deferred until governance executes `force_socialize_bad_debt` after its Sensitive delay. During that window the market's cash shortfall persists — suppliers' `withdraw` continues to hit the liquidity gap, and the account's phantom collateral keeps absorbing liquidation repayment that would otherwise be finalized. This is a temporary freezing of funds / sustained DoS of a permissionless protocol function reachable by a single unprivileged address.

### Likelihood Explanation
Requires an insolvent account near the dust cap (common tail state after liquidations on a sub-3-decimal asset, per the whole-unit leg rounding in `formulas.md`), plus the account holding at least one supply leg (always true for it to have collateral at all). Cost per blocking round is roughly `BAD_DEBT_USD_THRESHOLD + ε` (~$5), partially recoverable only through liquidation bonus to *other* parties. No timing race, privileged access, or oracle manipulation needed. Medium.

### Recommendation
Gate third-party top-ups on insolvent accounts: in `require_third_party_existing_supply` (or `process_deposit`), when `account_id != 0` and the caller is not owner/delegate, compute risk totals and reject if the account is insolvent (`total_debt > total_collateral`) — owners/delegates may still rescue their own accounts. Alternatively, make `clean_bad_debt`'s dust gate compare collateral excluding third-party-supplied legs, or add a permissionless path that caps seizure of freshly-donated collateral.

### Proof of Concept
1. Setup: `t.supply(BOB, "ETH", 100); t.supply(ALICE, "USDC", 30); t.borrow(ALICE, "ETH", 0.011); t.set_price("USDC", usd_cents(10))` → Alice insolvent with ~$3 collateral ≤ $5 cap (shape of `test_bad_debt_socialization_triggers_under_threshold`, `tests/test-harness/tests/controller/liquidation_boundary.rs:214-240`).
2. Attacker: `t.try_supply_to_account(EVIL, ALICE, "USDC", 5.0)` — succeeds because Alice already holds a USDC supply leg (`supply.rs:86-96`); collateral is now ~$8 > $5 while debt ~$22.
3. `t.try_clean_bad_debt_by_id(alice_id)` → reverts `CannotCleanBadDebt` (`mod.rs:230-235`).
4. A liquidator seizing the straddle collateral is paid for it at the insolvency base-bonus quote (`formulas.md:245`), so the attacker must re-top-up after each seizure, but each attempt is a single cheap permissionless call — the dust gate never stays open.
5. Only `force_socialize_bad_debt` (owner-gated, timelocked) clears the account, exactly the straddle admitted by `bad_debt_straddle_admitted_by_force_gate` (`boundary_rules.rs:74-104`).
