### Title
NonTransfer proxy can escalate to Any-type proxy via unrestricted `RuntimeCall::Proxy(..)` in `TransparentProxyType::filter` - (File: relay/kusama/src/lib.rs)

### Summary
The `InstanceFilter<RuntimeCall>::filter` implementation for `TransparentProxyType` permits the entire `pallet_proxy` call surface (including `add_proxy`) for `ProxyType::NonTransfer`, instead of restricting it to safe sub-calls. A delegate holding only a `NonTransfer` proxy can therefore call `Proxy::add_proxy` on behalf of the real account to grant itself (or any account) an `Any`-type proxy, then use that `Any` proxy to transfer the victim's funds — completely defeating the "NonTransfer" restriction.

### Finding Description
In the `NonTransfer` arm of the filter, the match includes: [1](#0-0) 
`RuntimeCall::Scheduler(..) | RuntimeCall::Proxy(..) | RuntimeCall::Multisig(..)` — the entire `Proxy` pallet is allowed unrestricted, unlike the careful per-call restriction used elsewhere in the same match arm (e.g., `Indices` only allows `claim`/`free`/`freeze`, `Vesting` only allows `vest`/`vest_other`) and unlike `ProxyType::CancelProxy`, which explicitly restricts `Proxy` calls to just `reject_announcement`: [2](#0-1) 

Because `RuntimeCall::Proxy(..)` matches with no sub-call restriction, a `NonTransfer` delegate can submit `RuntimeCall::Proxy(pallet_proxy::Call::add_proxy { delegate: attacker, proxy_type: ProxyType::Any, delay: 0 })` as the wrapped `call` argument of `Proxy::proxy(real = victim, force_proxy_type = Some(NonTransfer), call = ...)`. `pallet_proxy`'s dispatch logic only calls `def.proxy_type.filter(&call)` on the exact call being proxied — it performs no independent check that the resulting proxy addition doesn't exceed the calling delegate's own permission level (there is no comparison against `is_superset` at dispatch time for `add_proxy`). Once the filter returns `true`, `pallet_proxy` dispatches the inner `add_proxy` call with origin `Signed(victim)`, adding `attacker` as an `Any` proxy for `victim`.

The `Utility::batch`/`batch_all`/`force_batch` wrapping mentioned in the question is not even necessary for the exploit (since `RuntimeCall::Utility(..)` is also unconditionally allowed at line 1391), but if used, it reaches the same outcome because `pallet_utility` dispatches nested calls with the same already-authorized origin and does not re-invoke the proxy filter.

Once `attacker` holds an `Any` proxy over `victim`, `attacker` can call `Proxy::proxy(real = victim, force_proxy_type = Some(Any), call = Balances::transfer_allow_death(dest = attacker, value = ALL))`, which is permitted since `ProxyType::Any` filter unconditionally returns `true`: [3](#0-2) 

### Impact Explanation
An attacker who is only granted a restricted `NonTransfer` proxy relationship can escalate to full (`Any`) control of the victim's account and drain funds via `Balances::transfer_allow_death`, entirely bypassing the transfer restriction that `NonTransfer` is supposed to enforce. This breaks the core invariant that "user-controlled assets must remain fully backed and cannot be stolen" and that filters must not be bypassable by normal (proxy) users.

### Likelihood Explanation
Preconditions are minimal and fully attacker/user-controlled: any account owner who grants someone a `NonTransfer` proxy (a common, intentionally-restricted delegation, e.g. for staking/governance helpers) is exposed. No privileged origin, governance action, or extra vulnerability is required — a single extrinsic (`Proxy::proxy` with an `add_proxy` payload) executes the escalation, followed by a second `Proxy::proxy` call to drain funds. This is fully reproducible on any deployment of this runtime code.

### Recommendation
Restrict the `Proxy` pallet calls allowed under `ProxyType::NonTransfer` (and any other restrictive proxy type) to non-escalating sub-calls only, e.g. `pallet_proxy::Call::create_pure`, `announce`, `remove_announcement`, `reject_announcement`, and `remove_proxy`/`remove_proxies` when removing a strictly-equal-or-lower type — and explicitly exclude `add_proxy`/`add_proxy_delayed` (or require the target `proxy_type` being added to be a strict, non-escalating subset via `is_superset`-style enforcement at the call-filter level, mirroring the narrow style already used for `CancelProxy`, `Indices`, and `Vesting` in the same match block).

### Proof of Concept
Rust integration test (pallet-level, using relay runtime `Runtime`):
```rust
#[test]
fn nontransfer_proxy_cannot_escalate_to_any_via_add_proxy() {
    new_test_ext().execute_with(|| {
        let victim = AccountId::from(ALICE);
        let attacker = AccountId::from(BOB);

        // victim grants attacker a NonTransfer proxy
        assert_ok!(Proxy::add_proxy(
            RuntimeOrigin::signed(victim.clone()),
            attacker.clone(),
            ProxyType::NonTransfer,
            0,
        ));

        // attacker attempts to escalate: add itself as Any proxy via the NonTransfer delegation
        let escalate_call = Box::new(RuntimeCall::Proxy(pallet_proxy::Call::add_proxy {
            delegate: attacker.clone(),
            proxy_type: ProxyType::Any,
            delay: 0,
        }));

        let result = Proxy::proxy(
            RuntimeOrigin::signed(attacker.clone()),
            victim.clone(),
            Some(ProxyType::NonTransfer),
            escalate_call,
        );

        // Expected (fixed) behavior: this should fail or not add an Any proxy.
        // Currently: call succeeds and Any proxy entry is added -> bug.
        let proxies = Proxy::proxies(&victim).0;
        assert!(
            !proxies.iter().any(|p| p.delegate == attacker && p.proxy_type == ProxyType::Any),
            "NonTransfer proxy escalated to Any proxy"
        );

        // Confirm attacker cannot then drain funds via the escalated Any proxy
        let transfer_call = Box::new(RuntimeCall::Balances(pallet_balances::Call::transfer_allow_death {
            dest: attacker.clone(),
            value: Balances::free_balance(&victim),
        }));
        let transfer_result = Proxy::proxy(
            RuntimeOrigin::signed(attacker.clone()),
            victim.clone(),
            Some(ProxyType::Any),
            transfer_call,
        );
        assert!(transfer_result.is_err() || Balances::free_balance(&victim) > 0);
    });
}
```
Expected assertions: `Proxies` storage for `victim` never contains an `Any`-type entry added transitively through a `NonTransfer` delegate, and the subsequent `Balances::transfer_allow_death` proxied call must fail.
