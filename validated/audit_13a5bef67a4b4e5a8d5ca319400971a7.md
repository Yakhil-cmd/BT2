### Title
`gh release verify-asset` verifies the wrong digest — cryptographic policy binds to the release-ref SHA, not the user-supplied asset file — ([File: pkg/cmd/release/verify-asset/verify_asset.go])

### Summary
This is a strong analog to the ERC4626 "wrong variable" bug class: the code computes the *correct* value needed for a security-critical check (`fileDigest`, the SHA-256 of the local asset file), but then passes a *different* value (`releaseRefDigest`, the digest of the release-tag's git ref) into the actual cryptographic verification call. Just as the ERC4626 `mint` function computed `shares` correctly but minted `amount` instead — breaking the invariant it was supposed to enforce — `verifyAssetRun` computes `fileDigest` correctly but verifies `releaseRefDigest` instead, breaking the invariant that "the Sigstore policy's artifact-digest predicate binds to the exact file being verified."

### Finding Description
In `verifyAssetRun` [1](#0-0) , two independent digests are computed:
- `fileDigest` — the SHA-256 digest of the actual local file at `opts.AssetFilePath` [2](#0-1) 
- `releaseRefDigest` — a digest derived from the resolved git ref/tag SHA of the release [3](#0-2) 

`fileDigest` is used only to *filter* candidate attestations by matching subject digest [4](#0-3) , via `FilterAttestationsByFileDigest`, which compares the attestation subject's `sha256` digest against `fileDigest.Digest()` [5](#0-4) .

However, the actual Sigstore cryptographic verification — the step that builds and enforces the artifact-digest policy via `verify.WithArtifactDigest` — is called with `releaseRefDigest`, not `fileDigest`:
```go
verified, err := config.AttVerifier.VerifyAttestation(releaseRefDigest, filteredAttestations[0])
``` [6](#0-5) 

`VerifyAttestation` builds the enforcement policy directly from the `art` argument it receives: `policy := buildVerificationPolicy(*art, td)`, and `buildVerificationPolicy` derives `artifactDigestPolicyOption` from that same `art` via `verification.BuildDigestPolicyOption(a)` [7](#0-6) [8](#0-7) . Because `art` here is `releaseRefDigest` and not `fileDigest`, the Sigstore/DSSE-level policy that is cryptographically enforced binds to the release ref SHA, **not to the actual bytes of the file the user asked to verify**.

The only place `fileDigest` participates is the pre-filtering step (`FilterAttestationsByFileDigest`), which is a plain string comparison against unauthenticated JSON parsed from the attestation payload before verification occurs — not itself a cryptographic check. The cryptographic binding that actually matters (the Sigstore digest policy passed to `sigstore-go`) never touches `fileDigest`.

### Impact Explanation
If an attacker can produce (or tamper with) release attestations/artifacts such that any attestation subject entry's `sha256` matches `fileDigest.Digest()` (satisfying the string-based prefilter) while an accepted/valid attestation with a subject digest equal to `releaseRefDigest` also exists and passes Sigstore verification, `gh release verify-asset` will report `"Verification succeeded!"` for a file whose actual bytes were never the value bound by the cryptographic policy. This undermines the entire point of the command, which explicitly promises: *"It ensures the asset's integrity by validating that the asset's digest matches the subject in the attestation and that the attestation is associated with the release"* [9](#0-8) . A user or CI pipeline that gates on this command's success/failure to decide whether to trust/execute a downloaded release asset could be misled into trusting a substituted or corrupted file — directly analogous to how the ERC4626 bug let a caller receive value that was never actually validated against the correct accounting variable.

### Likelihood Explanation
This is reachable through the normal, unprivileged `gh release verify-asset <tag> <file>` command flow with only remote/attacker-influenced inputs (a release's attestations, tag ref, and asset), requiring no special privileges beyond what any user of the command already has. The bug is a straightforward argument-mixup (passing `releaseRefDigest` where `fileDigest` was clearly intended, per the surrounding filter logic and the doc string), which is exactly the same class of defect as the reference report's `_mint(to, amount)` vs `_mint(to, shares)` mixup — a locally obvious, structurally simple variable swap with outsized security consequences.

### Recommendation
Pass `fileDigest`, not `releaseRefDigest`, into the Sigstore verification call so that the enforced artifact-digest policy is bound to the actual file being verified:
```diff
- verified, err := config.AttVerifier.VerifyAttestation(releaseRefDigest, filteredAttestations[0])
+ verified, err := config.AttVerifier.VerifyAttestation(fileDigest, filteredAttestations[0])
```
If `releaseRefDigest` is also needed (e.g., to correlate the release ref with the attestation, as implied by the tag-filtering step), it should be validated as an *additional* constraint, not as a substitute for the file's own digest in the artifact-digest policy option.

### Proof of Concept
1. Craft or obtain a legitimate release attestation whose DSSE subject digest equals `releaseRefDigest` (i.e., matches the resolved tag's ref SHA digest) — this passes Sigstore verification because `VerifyAttestation` is invoked with `releaseRefDigest`.
2. Ensure that same attestation (or another attestation for the same release) also contains a subject entry whose `sha256` equals the digest of an attacker-supplied/tampered local file — this satisfies `FilterAttestationsByFileDigest` at [4](#0-3) .
3. Run `gh release verify-asset <tag> <tampered-file>`.
4. Observe that the command outputs `"✓ Verification succeeded!"` even though the Sigstore artifact-digest policy actually enforced was never bound to the tampered file's bytes, only to the release-ref digest — because `VerifyAttestation` at line 190 receives `releaseRefDigest` instead of `fileDigest`.

*(Note: full exploitation requires attestation/subject-digest arrangement details of the sigstore-go bundle format that were not independently constructed/tested here; the root-cause code path — the digest-argument mixup at line 190 — is directly verified from source.)*

func (v *AttestationVerifier) VerifyAttestation(art *artifact.DigestedArtifact, att *api.Attestation) (*verification.AttestationProcessingResult, error) {
	td, err := v.AttClient.GetTrustDomain()
	if err != nil {
		return nil, err
	}

	verifier, err := verification.NewLiveSigstoreVerifier(verification.SigstoreConfig{
		ExternalHttpClient: v.ExternalHttpClient,
		Logger:             att_io.NewHandler(v.IO),
		NoPublicGood:       true,
		TrustDomain:        td,
		TrustedRoot:        v.TrustedRoot,
	})
	if err != nil {
		return nil, err
	}

	policy := buildVerificationPolicy(*art, td)
	sigstoreVerified, err := verifier.Verify([]*api.Attestation{att}, policy)
	if err != nil {
		return nil, err
	}

	return sigstoreVerified[0], nil
}

func FilterAttestationsByFileDigest(attestations []*api.Attestation, fileDigest string) ([]*api.Attestation, error) {
	var filtered []*api.Attestation
	for _, att := range attestations {
		statement := att.Bundle.Bundle.GetDsseEnvelope().Payload
		var statementData v1.Statement
		err := protojson.Unmarshal([]byte(statement), &statementData)

		if err != nil {
			return nil, fmt.Errorf("failed to unmarshal statement: %w", err)
		}
		subjects := statementData.Subject
		for _, subject := range subjects {
			digestMap := subject.GetDigest()
			alg := "sha256"

			digest := digestMap[alg]
			if digest == fileDigest {
				filtered = append(filtered, att)
			}
		}

	}
	return filtered, nil
}

// buildVerificationPolicy constructs a verification policy for GitHub releases
func buildVerificationPolicy(a artifact.DigestedArtifact, trustDomain string) verify.PolicyBuilder {
	// If no trust domain is specified, default to "dotcom"
	if trustDomain == "" {
		trustDomain = "dotcom"
	}
	// SAN must match the GitHub releases domain. No issuer extension (match anything)
	sanMatcher, _ := verify.NewSANMatcher("", fmt.Sprintf("^https://%s\\.releases\\.github\\.com$", trustDomain))
	issuerMatcher, _ := verify.NewIssuerMatcher("", ".*")
	certId, _ := verify.NewCertificateIdentity(sanMatcher, issuerMatcher, certificate.Extensions{})

	artifactDigestPolicyOption, _ := verification.BuildDigestPolicyOption(a)
	return verify.NewPolicy(artifactDigestPolicyOption, verify.WithCertificateIdentity(certId))
}
