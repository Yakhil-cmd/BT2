### Title
Raw issue/PR text (title, body) is written unsanitized to stdout, allowing OSC 52 clipboard-hijack payloads from `gh issue view` output - ([File: pkg/cmd/issue/view/view.go])

### Summary
`printRawIssuePreview` in `pkg/cmd/issue/view/view.go` writes `issue.Title` and `issue.Body` (fields sourced verbatim from the GitHub API) directly via `fmt.Fprintf`/`fmt.Fprintln` to the plain `out io.Writer` parameter, which is `opts.IO.Out` — not the sanitizing `opts.IO.ContentOut` writer, and not wrapped in the `iostreams.Untrusted` type. Neither the asciisanitizer transform nor any escape-sequence check is applied anywhere in the `pkg/cmd/issue/view` package.

### Finding Description
The codebase has a well-established sanitization pattern for untrusted remote content: `iostreams.Untrusted` (in `pkg/iostreams/untrusted.go`) sanitizes ANSI/OSC escape sequences via its `String()` method through the `asciisanitizer` transform, and `opts.IO.ContentOut` (in `pkg/iostreams/iostreams.go`) wraps output in the same sanitizer when `sanitizeContent` is enabled. Other commands that print raw remote/untrusted content — e.g. `pkg/cmd/gist/view/view.go`, `pkg/cmd/pr/diff/diff.go`, `pkg/cmd/repo/read-file/read_file.go` — explicitly route through `iostreams.Untrusted`, `ContentOut`, or `iostreams.ContainsEscapeSequence` checks before writing raw attacker content to the terminal.

`printRawIssuePreview` (`pkg/cmd/issue/view/view.go:197`) does none of this: [1](#0-0) . It writes `issue.Title`, `issue.State`, `issue.Author.DisplayName()`, and finally `issue.Body` straight into `fmt.Fprintf(out, ...)`/`fmt.Fprintln(out, issue.Body)`, where `out` is `opts.IO.Out` passed from the caller at line 194: [2](#0-1) . `opts.IO.Out` is the raw stdout writer (not `ContentOut`), so the asciisanitizer transform (`newContentWriter` in `pkg/iostreams/iostreams.go:503`) is never applied to this path, and grep confirms zero references to `asciisanitizer`, `ContentOut`, or `sanitizeContent` anywhere in `pkg/cmd/issue/**`.

Since `issue.Title` and `issue.Body` are plain Go `string` fields populated directly from the GraphQL API response (not `iostreams.Untrusted`), an attacker who authors an issue/PR title or body containing an OSC 52 escape sequence (e.g. `\x1b]52;c;<base64-of-malicious-command>\x07`) will have that sequence pass through unmodified when a victim runs `gh issue view <number>` in non-TTY/piped mode (the `printRawIssuePreview` path is only reached when `!opts.IO.IsStdoutTTY()`, per the guard at line 185: `if opts.IO.IsStdoutTTY() { return printHumanIssuePreview(...) }`). Terminal emulators that honor OSC 52 (many do, including for piped/redirected output in some configurations) will write the attacker-supplied payload to the system clipboard, staging it for the victim's next paste — a classic clipboard-injection-to-RCE chain if the victim later pastes into a shell.

### Impact Explanation
If exploitable, this allows an unauthenticated remote attacker (any GitHub user who can open an issue or PR) to stage arbitrary clipboard content on a victim's machine merely by having them run `gh issue view` on the attacker's issue. Combined with victim pasting into a terminal, this is a path to remote code execution, matching the "Critical - RCE on developer machine" impact class described in the question.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only to publish a public issue/PR with a crafted title or body containing OSC 52 bytes, and the victim needs to run `gh issue view` with stdout not connected to a TTY (e.g., piped, redirected, or in scripts/CI) — a common usage pattern for scripting against `gh`. The lack of any sanitization call in the `pkg/cmd/issue/view` package (confirmed by grep) means this is not conditionally mitigated; it is unconditionally reachable whenever the raw-preview code path executes.

### Recommendation
Route `issue.Title`, `issue.Body`, and other remote-authored fields (labels, milestone title, issue-type name, parent/sub-issue refs) through `iostreams.Untrusted` before printing, or write `printRawIssuePreview`'s output through `opts.IO.ContentOut` instead of `opts.IO.Out` so the asciisanitizer strips OSC/ANSI sequences consistently with the pattern used in `pr/diff`, `gist/view`, and `repo/read-file`.

### Proof of Concept
```go
// pkg/cmd/issue/view/view_test.go (new test)
func TestPrintRawIssuePreview_StripsOSC52(t *testing.T) {
    payload := "\x1b]52;c;bWFsaWNpb3VzIHBheWxvYWQ=\x07"
    issue := &api.Issue{
        Title: "innocuous title" + payload,
        Body:  "issue body" + payload,
    }
    var buf bytes.Buffer
    err := printRawIssuePreview(&buf, issue)
    require.NoError(t, err)
    assert.NotContains(t, buf.String(), "\x1b]52", "OSC 52 clipboard payload must not reach output")
}
```
Running this test against the current implementation is expected to **fail** (the OSC 52 bytes appear verbatim in `buf.String()`), demonstrating the gap. I was unable to execute this test in this environment (read-only analysis), so this should be verified by running `go test ./pkg/cmd/issue/view/...` in a Devin session with repo access.

```go
func printRawIssuePreview(out io.Writer, issue *api.Issue) error {
	assignees := issueAssigneeList(*issue)
	labels := issueLabelList(issue, nil)
	projects := issueProjectList(*issue)

	// Print empty strings for empty values so the number of metadata lines is consistent when
	// processing many issues with head and grep.
	fmt.Fprintf(out, "title:\t%s\n", issue.Title)
	fmt.Fprintf(out, "state:\t%s\n", issue.State)
	fmt.Fprintf(out, "author:\t%s\n", issue.Author.DisplayName())
	fmt.Fprintf(out, "labels:\t%s\n", labels)
	fmt.Fprintf(out, "comments:\t%d\n", issue.Comments.TotalCount)
	fmt.Fprintf(out, "assignees:\t%s\n", assignees)
	fmt.Fprintf(out, "projects:\t%s\n", projects)
	var milestoneTitle string
	if issue.Milestone != nil {
		milestoneTitle = issue.Milestone.Title
	}
	fmt.Fprintf(out, "milestone:\t%s\n", milestoneTitle)
	var issueTypeName string
	if issue.IssueType != nil {
		issueTypeName = issue.IssueType.Name
	}
	fmt.Fprintf(out, "issue-type:\t%s\n", issueTypeName)
	var parentRef string
	if issue.Parent != nil {
		parentRef = formatLinkedIssueRef(issue.Parent)
	}
	fmt.Fprintf(out, "parent:\t%s\n", parentRef)
	fmt.Fprintf(out, "sub-issues:\t%s\n", formatLinkedIssueRefs(issue.SubIssues.Nodes))
	var subIssuesCompleted string
	if issue.SubIssuesSummary.Total > 0 {
		subIssuesCompleted = fmt.Sprintf("%d/%d", issue.SubIssuesSummary.Completed, issue.SubIssuesSummary.Total)
	}
	fmt.Fprintf(out, "sub-issues-completed:\t%s\n", subIssuesCompleted)
	fmt.Fprintf(out, "blocked-by:\t%s\n", formatLinkedIssueRefs(issue.BlockedBy.Nodes))
	fmt.Fprintf(out, "blocking:\t%s\n", formatLinkedIssueRefs(issue.Blocking.Nodes))
	fmt.Fprintf(out, "number:\t%d\n", issue.Number)
	fmt.Fprintln(out, "--")
	fmt.Fprintln(out, issue.Body)
	return nil
```
