### Title
Unchecked `creator` account in `initialize_with_permission` permanently freezes creator fees - ([File: programs/cp-swap/src/instructions/initialize_with_permission.rs])

### Summary
`InitializeWithPermission::creator` is an `UncheckedAccount` with no non-default/zero-address validation. Its key is written directly into `PoolState.pool_creator` and can never be changed afterward, so a permissioned payer can create a pool whose creator fees become permanently unclaimable by setting `creator` to `Pubkey::default()` (or any other address nobody controls).

### Finding Description
In `initialize_with_permission.rs`, the `creator` account is declared only as: [1](#0-0) 
with no `require_keys_neq!(creator.key(), Pubkey::default())` or similar check, unlike `set_new_protocol_owner`/`set_new_fund_owner` in `update_config.rs` which explicitly guard against the zero pubkey: [2](#0-1) 

The unchecked key is then persisted permanently into `PoolState.pool_creator` via `pool_state.initialize(...)`: [3](#0-2) 
and `PoolState::initialize` stores it verbatim with no validation: [4](#0-3) 

There is no instruction in the program that can later update `pool_creator`, so whatever value is set here is final for the life of the pool.

`collect_creator_fee` requires the `creator` account to be a `Signer` whose address equals `pool_state.pool_creator`: [5](#0-4) 
If `pool_creator == Pubkey::default()` (the System Program ID, which has no corresponding private key), this instruction can never succeed because nobody can produce a valid signature for the default pubkey.

`collect_creator_fee_permissionless` avoids the signer requirement but still sends the accrued creator fees to an ATA owned by `pool_state.pool_creator`: [6](#0-5) [7](#0-6) 
If `pool_creator` is the default pubkey (or any other unowned/attacker-uncontrolled address), the ATA created for it is an account nobody can ever withdraw from, since no private key exists for that authority.

### Impact Explanation
Every swap that accrues a nonzero `creator_fee_rate` adds to `PoolState.creator_fees_token_0`/`creator_fees_token_1` for the life of the pool. If `pool_creator` is set to `Pubkey::default()` at pool creation, these fees accumulate but can never be collected by anyone — `collect_creator_fee` is permanently unusable (no valid signer) and `collect_creator_fee_permissionless` only ever sends funds into an ATA controlled by nobody. This is a permanent freezing of LP/creator funds inside the pool's vaults, satisfying the "permanent freezing of user or LP funds" impact bar.

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a valid `Permission` PDA (a pool-creator-tier permission, not an admin-signer privilege), and the `creator` field is fully attacker-controlled input with zero validation. Setting it to the system-program/default pubkey is trivial and requires no special privilege beyond calling the instruction itself, making this reliably triggerable in a single transaction.

### Recommendation
Add an explicit check in `InitializeWithPermission` (or in `initialize_with_permission`) rejecting `Pubkey::default()` for `creator`, e.g. `require_keys_neq!(ctx.accounts.creator.key(), Pubkey::default())`, mirroring the guard already present in `set_new_protocol_owner`/`set_new_fund_owner` in `update_config.rs`.

### Proof of Concept
1. Obtain (or be granted) a valid `Permission` PDA for `payer`.
2. Call `initialize_with_permission` supplying `creator = Pubkey::default()` (or any account with no reachable private key) along with valid mint/vault/config accounts.
3. `pool_state.pool_creator` is now permanently set to the default pubkey; the pool functions normally for swaps/deposits/withdrawals.
4. Perform swaps that accrue `creator_fees_token_0`/`creator_fees_token_1` in `PoolState`.
5. Attempt `collect_creator_fee`: fails because no signer can match `pool_state.pool_creator == Pubkey::default()`.
6. Attempt `collect_creator_fee_permissionless`: succeeds in moving vault tokens into an ATA owned by the default pubkey, but this ATA's authority has no private key, so the tokens are permanently unrecoverable.
