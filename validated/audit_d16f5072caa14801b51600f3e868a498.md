### Title
Unchecked `getFormula()` NULL/undefined result leads to crash in remote AA getter evaluation - (File: formula/evaluation.js)

### Summary
`callGetter()` in `formula/evaluation.js` derives a getters formula from a remote AA's definition with `getFormula(arrBaseDefinition[1].getters)` and passes the result directly into `exports.evaluate()` without checking whether it is `null`, unlike the sibling code path in `aa_composer.js`'s `evaluateAA()` which explicitly checks `if (f === null)` before using it. This mirrors the CVE-2022-49532 bug class: a helper function that can return a "nothing found" sentinel is used by the caller without validating it, leading to unsafe dereference/parsing further down the call chain.

### Finding Description
`getFormula()` [1](#0-0)  returns `null` whenever its input is not a string (e.g. `undefined`, which is exactly what `arrDefinition[1].getters` is for any AA that does not define a `getters` block).

In `aa_composer.js`, the call site correctly guards against this: [2](#0-1) 

However, in `callGetter()` (the function used to evaluate a *remote* AA's getter, i.e. `$remote_aa.$getter()`/`map`/`filter`/`reduce` formula ops that call into another AA), the same `getFormula()` result is used unconditionally: [3](#0-2) 

If the remote AA (`arrBaseDefinition`) has no `getters` field defined (the common case — most AAs don't define getters), `getFormula(arrBaseDefinition[1].getters)` returns `null`, and `opts.formula = null` is handed straight to `exports.evaluate(opts, astTrace, '/getters', cb)` instead of being special-cased to skip straight to locals lookup, as `evaluateAA` does. This is the same "helper may return a null/empty value and the caller assumes a valid value" defect pattern as the kernel's `drm_cvt_mode()` returning `NULL` and `virtio_gpu_conn_get_modes` dereferencing it without a check.

### Impact Explanation
`callGetter()` is reachable from unprivileged input: any AA trigger sender (or an AA's own oscript logic acting on attacker-influenced trigger data) can cause a formula to invoke `map`/`filter`/`reduce`/remote getter calls that route through `callGetter()` against an arbitrary target AA address [4](#0-3) . Because AA validation and response computation run identically and deterministically on every full node, a crash or divergent/undefined behavior triggered here during formula evaluation of a bad-unit/trigger has consensus-wide effect: it can either throw an uncaught exception (crashing the validating/AA-executing process — denial of service for all nodes processing that trigger) or, if the parser silently tolerates a `null` formula, produce output-inconsistent results between differently-patched nodes, which is a node-disagreement-on-validity/stability risk. Both outcomes fall within the accepted impact categories (node unable to confirm new units, or node disagreement on validity).

### Likelihood Explanation
Likelihood is high in terms of reachability — essentially any AA without an explicit `getters:` field is a valid remote target, and calling a remote getter from another AA/formula is a normal, permitted oscript feature. The exact triggering condition (does `exports.evaluate` actually crash on `formula: null`, or degrade gracefully) could not be fully confirmed within available tool budget — the formula parser/lexer implementation that consumes `opts.formula` was not directly inspected in this session, so behavior when `formula` is `null` is inferred from the analogous explicit-`null`-check present in `evaluateAA` (which implies the author intentionally treats `null` as an unsafe/special value requiring separate handling), but not conclusively proven to throw.

### Recommendation
Add the same `f === null` guard used in `aa_composer.js`'s `evaluateAA()` to `callGetter()` in `formula/evaluation.js`: when `getFormula(arrBaseDefinition[1].getters)` returns `null`, skip evaluating a `/getters` formula and proceed directly to locating `getter` in `locals` (which will simply be empty, correctly yielding "no such getter" rather than attempting to evaluate a `null` formula).

### Proof of Concept
Not independently reproduced in this session (no execution environment available); the code-path proof is based on static analysis:
1. Deploy AA `B` with a `messages` definition and no `getters` field.
2. Deploy AA `A` whose oscript formula calls `$B.$someGetter()` (or uses `map`/`filter`/`reduce` against `B`).
3. Trigger `A`. Formula evaluation calls `callGetter(conn, 'B', 'someGetter', ...)`, which computes `f = getFormula(undefined) = null` and calls `exports.evaluate({..., formula: null, ...}, ...)` without validation, unlike the checked path in `evaluateAA`.

Because the actual runtime effect of `exports.evaluate` receiving `formula: null` was not traced to completion within the available investigation, this should be verified in a full Devin session with codebase execution access before being treated as confirmed-exploitable, but the missing-null-check pattern itself is confirmed by direct code comparison between `aa_composer.js:589-594` and `formula/evaluation.js:3312-3331`.

function getFormula(str, bOptionalBraces) {
	if (bOptionalBraces)
		throw Error("braces cannot be optional");
	if (typeof str !== 'string')
		return null;
	if (str[0] === '{' && str[str.length - 1] === '}')
		return str.slice(1, -1);
	else if (bOptionalBraces)
		return str;
	else
		return null;
}
