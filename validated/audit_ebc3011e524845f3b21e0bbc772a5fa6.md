### Title
RAY index accumulation overflows `i128` before the borrow-index cap engages, permanently freezing a market — ([File: common/src/rates.rs](common/src/rates.rs) via [contracts/pool/src/interest.rs](contracts/pool/src/interest.rs))

### Summary
The CVE-2017-12797 bug class is an integer overflow during a bounded accumulation that turns into a denial of service. The lending analog lives in interest accrual: the RAY borrow index grows monotonically with compounding, and the panic-based checked math in `scaled_to_original`/`accrue_step` overflows `i128` on the index *value* before `MAX_BORROW_INDEX_RAY` can clamp it. Because every market verb accrues first via `global_sync`, a single overflow permanently bricks the market for every user.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs:20-33` splits elapsed time into `MAX_COMPOUND_DELTA_MS` chunks and calls `accrue_chunk`, which invokes `accrue_step` (`common::rates`) and writes the result back with `cache.set_borrow_index` / `cache.set_supply_index` (`interest.rs:39-53`). Unscaling (`scaled_to_original`, wrapped by `Cache::calculate_utilization` in `contracts/pool/src/cache/scale.rs:23-26`) multiplies scaled shares by the index in RAY; on a whale market the product `scaled * index` exceeds `i128::MAX` and panics with `GenericError::MathOverflow` — while `borrow_index < MAX_BORROW_INDEX_RAY`, so the index cap never triggers.

This is demonstrated by the protocol's own test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`, which asserts:

- `try_update_indexes` eventually fails with `MATH_OVERFLOW` while `last.borrow_index < MAX_BORROW_INDEX_RAY`;
- afterwards `try_withdraw_raw` and `try_repay` both fail with `MATH_OVERFLOW`, i.e., no exit, no repayment, no liquidation is possible on that market.

Any unprivileged address can set up the precondition: call `supply` with a large deposit (e.g., a billion-unit 18-decimal market, as in the test), `borrow` to high utilization (~98%), then let time pass; `update_indexes` is permissionless and the overflow then propagates to `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, flash paths — all of which run `global_sync` first.

### Impact Explanation
Permanent freezing of funds: once the RAY value overflows, every entrypoint on that market panics at accrual. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and revenue cannot be claimed — the physical pool balance for that market is irrecoverable. This is not a transient/fail-closed DoS; there is no code path to un-wind the index or bypass accrual.

### Likelihood Explanation
Requires a large-total-supply market sustained at high utilization on a steep rate curve — the test needed ~billions of base units and multi-year accrual at ~98% utilization on the XLM curve. That is expensive but reachable by a single whale using only `supply`/`borrow`/`update_indexes`, and it also arises organically over a market's lifetime. Medium likelihood.

### Recommendation
Clamp the index itself before unscaling: in `accrue_step`, cap `borrow_index`/`supply_index` growth at `MAX_BORROW_INDEX_RAY` (or a value-derived bound `i128::MAX / max(scaled,1)`), and make `scaled_to_original`/`unscale_*` saturate or operate on the capped index so post-cap accrual is a no-op instead of a panic. Alternatively, add a `global_sync` fast-path that freezes accrual once the index reaches the cap while still permitting repay/withdraw.

### Proof of Concept
The harness test at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360` is a complete PoC:

1. Register market `BIG18` (18 decimals, XLM rate curve) plus a collateral market; lift caps.
2. `supply_raw(BOB, "BIG18", 1e9 * 1e18)`; `borrow_raw(ALICE, "BIG18", 0.98 * principal)` after supplying collateral.
3. Loop `advance_time(YEAR_SECS)` + `update_indexes` until it returns `MATH_OVERFLOW` — occurring while `borrow_index < MAX_BORROW_INDEX_RAY`.
4. `withdraw(BOB, "BIG18", 1)` and `repay(ALICE, "BIG18", …)` both revert with `MATH_OVERFLOW`: the market is permanently frozen.
