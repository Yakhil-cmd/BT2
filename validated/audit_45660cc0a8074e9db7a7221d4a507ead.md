### Title
No Owner-Controlled Withdrawal for KLAY Liquidity Permanently Locks Bridge Funds — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

The `Bridge` contract (Kaia service-chain bridge) accepts KLAY deposits via the unrestricted `chargeWithoutEvent()` function and its `payable` constructor, but neither `BridgeTransferKLAY` nor any parent contract in the inheritance chain exposes an owner-controlled function to withdraw or recover that KLAY. Any KLAY deposited as bridge liquidity that is not consumed by legitimate cross-chain `handleKLAYTransfer()` calls is permanently locked with no recovery path.

---

### Finding Description

`BridgeTransferKLAY.chargeWithoutEvent()` is declared `external payable` with **no access control**:

```solidity
// chargeWithoutEvent sends KLAY to this contract without event for increasing
// the withdrawal limit.
function chargeWithoutEvent() external payable {}
``` [1](#0-0) 

The `Bridge` constructor is also `payable`, allowing KLAY to be deposited at deployment time:

```solidity
constructor(bool _modeMintBurn) BridgeTransfer(_modeMintBurn) public payable {
}
``` [2](#0-1) 

The full inheritance chain — `Bridge` → `BridgeTransferKLAY` → `BridgeTransfer` → `BridgeFee` / `BridgeOperator` / `BridgeHandledRequests` — contains **no function** that allows the owner to withdraw KLAY from the contract balance. [3](#0-2) 

The only paths by which KLAY can leave the contract are:

1. **`handleKLAYTransfer()`** — requires operator-quorum votes and a valid cross-chain request nonce; cannot be used to drain arbitrary liquidity.
2. **`_payKLAYFeeAndRefundChange()`** — only executes during an active `_requestKLAYTransfer()` call; sends the fee portion to `feeReceiver` and refunds excess to `msg.sender`. [4](#0-3) 

When the bridge is stopped via `setRunningStatus(false)`, no new KLAY enters through the fallback or `requestKLAYTransfer`. The existing balance deposited via `chargeWithoutEvent()` or the constructor has no exit path controlled by the owner. [5](#0-4) 

---

### Impact Explanation

KAIA deposited as bridge liquidity is permanently locked in the `Bridge` contract whenever the bridge is stopped, decommissioned, or migrated. The bridge operator has no on-chain mechanism to recover this KAIA. Because `chargeWithoutEvent()` has no access control, any address — including the operator — can deposit KLAY, but no address can withdraw it outside of legitimate cross-chain transfer flows. This constitutes an unauthorized permanent lock of KAIA (a system-managed bridged asset), matching the "breaks withdrawals" criterion of the Allowed Impact Gate.

---

### Likelihood Explanation

Every service-chain bridge deployment that pre-funds KLAY liquidity (the standard operational pattern, as shown in tests using `chargeWithoutEvent`) is affected. The condition is triggered simply by stopping or decommissioning the bridge — a routine operational event. No adversarial action is required; the loss is structural. [6](#0-5) 

---

### Recommendation

Add an owner-controlled KLAY withdrawal function to `BridgeTransferKLAY` (or `BridgeTransfer`):

```solidity
function withdrawKLAY(address payable _to, uint256 _amount) external onlyOwner {
    (bool ok, ) = _to.call.value(_amount)("");
    require(ok, "withdrawKLAY: transfer failed");
}
```

This mirrors the pattern already used in `_payKLAYFeeAndRefundChange` for fee transfers and gives the owner a safe, auditable recovery path. [7](#0-6) 

---

### Proof of Concept

1. Deploy `Bridge(false)` (lock mode) — constructor is `payable`.
2. Call `chargeWithoutEvent{value: 1000 ether}()` to pre-fund KLAY liquidity. No access control prevents this.
3. Call `setRunningStatus(false)` (owner) to stop the bridge.
4. Attempt to recover the 1000 KLAY — no function exists in `Bridge`, `BridgeTransferKLAY`, `BridgeTransfer`, `BridgeFee`, or `BridgeOperator` to do so.
5. The only remaining exit is `handleKLAYTransfer()`, which requires a valid cross-chain request nonce and operator quorum — it cannot be used to drain arbitrary liquidity.
6. Result: 1000 KLAY is permanently locked in the contract. [1](#0-0) [8](#0-7)

    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }
