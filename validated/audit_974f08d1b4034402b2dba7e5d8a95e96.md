### Title
Unsigned `DelegateStxOp` sender field allows attacker to register a delegation for a victim's STX, then lock it via `delegate-stack-stx` into an attacker-chosen PoX address - (File: stackslib/src/chainstate/burn/operations/delegate_stx.rs)

### Summary
`DelegateStxOp::parse_from_tx` sets `op.sender` to the `sender` argument passed in from `Burnchain::apply_blockstack_transactions_safety_checks`, which is taken verbatim from `pre_stx.output` — the address encoded in an *arbitrary output* of the linked `PreStxOp` Bitcoin transaction [1](#0-0) [2](#0-1) . Neither `sender` nor `delegate_to` requires a signature from the corresponding Stacks private key; `delegate_to` is likewise read off an output address of the DelegateStxOp transaction with no ownership proof [3](#0-2) . This lets an attacker impersonate any victim as `sender` and name themselves as `delegate_to`, then complete the lock through the legitimate `delegate-stack-stx` Clarity entry point.

### Finding Description
The broken equality: "STX locked in a PoX address == STX whose owner authorized that specific lock and pox-addr." `DelegateStxOp` establishes the `delegated-to`/`amount-ustx`/`pox-addr` fields consumed later by `pox-4.clar`'s `delegate-stack-stx`, and `pox_4.rs`'s `synthesize_events`/`handle_stack_lockup_pox_v4` path logs this as if it were a signed `delegate-stx` call from `sender` [4](#0-3) .

Root cause: `sender` in `DelegateStxOp` comes only from `pre_stx.output` — an address the attacker writes into their own `PreStxOp` Bitcoin transaction — and is never checked against a Bitcoin-input-derived public key (unlike, e.g., `VoteForAggregateKeyOp::get_sender_pubkey`, which does recover a real signing key from the spending input for `signer_key`) [5](#0-4) . No equivalent `get_sender_pubkey` check exists for `DelegateStxOp::sender`. Likewise `delegate_to` is simply output 0 of the DelegateStxOp transaction [3](#0-2) .

Exploit flow:
1. Attacker crafts a `PreStxOp` Bitcoin transaction whose designated output (the field later read as `pre_stx.output`) encodes the victim's Stacks address hash160 — no victim key material or cooperation required, since writing an address into a Bitcoin output requires no proof of ownership.
2. Attacker crafts the follow-up `DelegateStxOp` transaction spending vout 1 of that `PreStxOp` (which the attacker funds/signs themselves), with output 0 set to the attacker's own address (`delegate_to`) and `delegated_ustx` set to (up to) the victim's real balance.
3. This burn op is parsed into `DelegateStxOp{ sender: victim, delegate_to: attacker, delegated_ustx, ... }` and processed into `pox-4`'s delegation bookkeeping.
4. Attacker then submits a normal, self-signed `delegate-stack-stx` transaction (`tx-sender = attacker`), which checks `delegated-to == tx-sender` (satisfied by the forged delegation), `stx-get-balance stacker >= amount-ustx` (victim's real balance), and `is-none (get-stacker-info stacker)` [6](#0-5) . All of these checks pass, and the node locks the victim's actual STX into a PoX address of the attacker's choosing.

Existing guards (`check-caller-allowed`, `ERR_DELEGATION_POX_ADDR_REQUIRED`, `ERR_DELEGATION_TOO_MUCH_LOCKED`, `ERR_STACKING_ALREADY_STACKED`) only validate consistency between the (already-forged) delegation record and the stack-stx call arguments — none of them verify that the delegation record itself was authorized by a signature from the named `stacker`/`sender`, because on the burnchain-op path there is no Stacks transaction signature to check in the first place.

### Impact Explanation
Complete unauthorized locking of a victim's unlocked STX balance, with lock rewards routed to a PoX address chosen entirely by the attacker and delegation rights (`delegated-to`) assigned to the attacker — matching the Critical category ("theft ... of locked STX ... rewards"). This is repeatable against any Stacks account holding unlocked STX, at the cost of only Bitcoin transaction fees for two Bitcoin-anchored transactions (`PreStxOp` + `DelegateStxOp`) plus one Stacks transaction fee for `delegate-stack-stx`.

### Likelihood Explanation
Preconditions: victim must hold unlocked STX and not already be stacking/delegated at the time the forged `DelegateStxOp` and the follow-up `delegate-stack-stx` are mined; no privileged role or pause-admin/bond-admin/signer access is needed. Attacker cost is limited to Bitcoin miner fees for two low-value BTC transactions and one Stacks transaction fee — well within reach of an "unprivileged attacker with their own STX/BTC" as defined. This is fully feasible and repeatable per target victim/cycle, subject only to ordinary reward-cycle scheduling (`start-burn-ht` must match the next reward cycle).

### Recommendation
Require cryptographic proof that the party naming `sender` in `DelegateStxOp` (and analogously `StackStxOp`) actually controls the corresponding Stacks/Bitcoin private key — e.g., recover the signing public key from the input that funds the `PreStxOp`/`DelegateStxOp` chain (as already done for `VoteForAggregateKeyOp::get_sender_pubkey`) and require it to hash to the claimed `sender` address before accepting the op, or require an explicit in-band signature from `sender` authorizing the specific `delegate_to`/`pox-addr`/`amount-ustx` tuple.

### Proof of Concept
Rust integration test (mirroring `stackslib/src/burnchains/tests/mod.rs` / `stackslib/src/chainstate/coordinator/tests.rs` burnchain-op harnesses):
1. Build a `PreStxOp` Bitcoin transaction where output 0 encodes the victim's Stacks address hash160 (victim's real, funded Stacks account created independently with unlocked STX).
2. Build a `DelegateStxOp` Bitcoin transaction spending vout 1 of the `PreStxOp`, with output 0 = attacker's address, `delegated_ustx` = victim's full unlocked balance, no `until_burn_height` restriction, `reward_addr` = attacker's PoX address.
3. Mine both, run `Burnchain::apply_blockstack_transactions_safety_checks` / coordinator processing to confirm `BlockstackOperationType::DelegateStx{ sender: victim, delegate_to: attacker, .. }` is registered.
4. Submit a signed Stacks transaction from attacker calling `.pox-4.delegate-stack-stx(victim, amount, attacker_pox_addr, start_burn_ht, lock_period)`.
5. Assert equality before: victim `STXBalance` unlocked == full balance, `stacking-state` map has no entry for victim.
   Assert equality after: victim `STXBalance` is now locked for `attacker_pox_addr`, `reward-cycle-pox-address-list`/`reward-cycle-total-stacked` include the attacker's PoX address indexed with the victim's locked amount, and the victim never signed any transaction authorizing this — demonstrating LOCK CONSERVATION is broken (STX locked ≠ STX whose owner authorized the lock).

    pub fn parse_from_tx(
        block_height: u64,
        block_hash: &BurnchainHeaderHash,
        tx: &BurnchainTransaction,
        sender: &StacksAddress,
    ) -> Result<DelegateStxOp, op_error> {
        let outputs = tx.get_recipients();

        if tx.num_signers() == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                outputs.len()
            );
            return Err(op_error::InvalidInput);
        }

        if outputs.is_empty() {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                outputs.len()
            );
            return Err(op_error::InvalidInput);
        }

        if tx.opcode() != Opcodes::DelegateStx as u8 {
            warn!("Invalid tx: invalid opcode {}", tx.opcode());
            return Err(op_error::InvalidInput);
        };

        let data = DelegateStxOp::parse_data(&tx.data()).ok_or_else(|| {
            warn!("Invalid tx data");
            op_error::ParseError
        })?;

        let delegate_to = outputs
            .get(0)
            .ok_or(op_error::InvalidInput)?
            .as_ref()
            .ok_or(op_error::InvalidInput)?
            .clone()
            .address
            .coerce_hash_mode()
            .try_into_stacks_address()
            .ok_or_else(|| {
                warn!("Invalid tx: output 1 must be representable as a StacksAddress");
                op_error::InvalidInput
            })?;

        // coerce a hash mode for this address if need be, since we'll need it when we feed this
        // address into the .pox contract
        let reward_addr = if let Some(index) = data.reward_addr_index {
            if outputs.len() > index as usize {
                Some((
                    index,
                    outputs
                        .get(index as usize)
                        .expect("Index should be in bounds.")
                        .as_ref()
                        .ok_or(op_error::InvalidInput)?
                        .clone()
                        .address
                        .coerce_hash_mode(),
                ))
            } else {
                None
            }
        } else {
            None
        };

        Ok(DelegateStxOp {
            sender: sender.clone(),
            reward_addr,
            delegate_to,
            delegated_ustx: data.delegated_ustx,
            until_burn_height: data.until_burn_height,
            txid: tx.txid(),
            vtxindex: tx.vtxindex(),
            block_height,
            burn_header_hash: block_hash.clone(),
        })
    }

    pub fn get_sender_pubkey(tx: &BurnchainTransaction) -> Result<Secp256k1PublicKey, op_error> {
        match tx {
            BurnchainTransaction::Bitcoin(ref btc) => match btc.inputs.first() {
                Some(BitcoinTxInput::Raw(input)) => {
                    let script_sig = Builder::from(input.scriptSig.clone()).into_script();
                    let structured_input = BitcoinTxInputStructured::from_bitcoin_p2pkh_script_sig(
                        &parse_script(&script_sig),
                        input.tx_ref.clone(),
                    )
                    .ok_or(op_error::InvalidInput)?;
                    structured_input
                        .keys
                        .first()
                        .cloned()
                        .ok_or(op_error::InvalidInput)
                }
                Some(BitcoinTxInput::Structured(input)) => {
                    input.keys.first().cloned().ok_or(op_error::InvalidInput)
                }
                _ => Err(op_error::InvalidInput),
            },
        }
    }
