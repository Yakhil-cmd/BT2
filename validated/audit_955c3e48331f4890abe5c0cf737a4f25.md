### Title
PSM `mint`/`redeem` credit debt/collateral using the requested transfer amount instead of the amount actually received, unlike the codebase's own `PartialTransfer` guard pattern - ([File: substrate/frame/psm/src/lib.rs])

### Summary
`pallet-psm`'s `mint()` and `redeem()` extrinsics move external collateral in and out of the PSM's reserve account via `T::Fungibles::transfer(...)`, but discard the returned (actually-transferred) amount and instead update `PsmDebt` using the amount that was *requested* to be transferred. Elsewhere in the same codebase (`substrate/frame/asset-conversion/ops`), an identical `T::Assets::transfer` call is explicitly checked against the amount that was supposed to move, failing the extrinsic with `Error::PartialTransfer` if the actual and requested amounts diverge. `pallet-psm` has no equivalent check for its "secondary"/external collateral assets, mirroring the Notional finding where a vault checked `hasTransferFee` for the primary currency but not for `secondaryBorrowCurrencies`.

### Finding Description
`Pallet::mint` (`substrate/frame/psm/src/lib.rs:703-768`) computes an `internal_equivalent`, records it in `PsmDebt` at line 757, and separately performs the external-asset transfer: [1](#0-0) 

The return value of `T::Fungibles::transfer(...)` — which represents the amount actually credited to the PSM reserve account — is discarded with `?` (error-only), not compared to `effective_external`. `PsmDebt` is then incremented by the full `internal_equivalent`, which was derived from the *requested* `effective_external`, not from what the reserve account actually received.

`Pallet::redeem` (`substrate/frame/psm/src/lib.rs:812-903`) has the symmetric gap: it transfers `external_out` from the reserve to the caller and discards the returned amount: [2](#0-1) 

By contrast, the codebase already contains the correct defensive pattern for exactly this class of risk in `substrate/frame/asset-conversion/ops/src/lib.rs`, where a fungibles `transfer` is explicitly checked against the expected amount and the call fails with `Error::PartialTransfer` on any shortfall: [3](#0-2) 

`pallet-psm`'s own `do_try_state` invariant even asserts that the reserve must cover tracked debt (`reserve >= debt_as_external`), demonstrating that maintainers are aware this invariant must hold but do not enforce it defensively inside `mint`/`redeem`: [4](#0-3) 

`T::Fungibles` is a generic associated type (`FungiblesMutate + FungiblesMetadataInspect + FungiblesRolesInspect`) at `substrate/frame/psm/src/lib.rs:335-337`, and `add_external_asset` only validates that the external asset exists and that its decimals are within `MAX_DECIMALS_DIFF` of the internal asset — it performs no check that the asset's `transfer` implementation delivers the full requested amount: [5](#0-4) 

This is the direct structural analog of the Notional report: the "internal"/primary path (well-understood, `pallet-assets`-style) is assumed safe, but nothing in the PSM prevents an approved "external"/secondary asset backend from returning a `transfer` amount smaller than requested (e.g. a `Fungibles` implementation with hooks that burn/redirect a portion on transfer, or ED/dust-driven partial delivery in some non-`pallet-assets` backend). If that happens, `mint` credits internal-asset debt for collateral the reserve never actually received, and `redeem` under-drains the reserve relative to what it records as repaid.

### Impact Explanation
If an approved external asset's `Fungibles::transfer` implementation can deliver less than the requested amount, `mint` results in unbacked internal-asset issuance (debt tracked in `PsmDebt` exceeds actual reserve balance), which directly violates the PSM's core 1:1-backing invariant and can lead to insolvency of the PSM reserve — later redeemers would be unable to be paid out even though on-chain debt bookkeeping says they should be. This is a collateral/backing integrity break, which would normally be rated Medium/High depending on whether such a `Fungibles` backend is realistically reachable in a given runtime's configuration.

### Likelihood Explanation
Likelihood depends entirely on the concrete `T::Fungibles` implementation wired into a given runtime's `pallet-psm::Config`. For the standard `pallet-assets`/`pallet-balances` fungibles adapters, `transfer` under `Preservation::Expendable` delivers the full requested amount to the recipient (dust-reaping only affects the sender's leftover balance, not the transferred amount), so the issue would not manifest with stock FRAME asset pallets. The gap becomes exploitable only if a runtime approves an external asset whose `Fungibles` implementation can legitimately return a transferred amount smaller than requested (e.g., a custom hook-based token, a wrapped/bridged asset representation, or a matcher/adapter with rounding or fee logic). No PoC using the repository's own mocks (`substrate/frame/psm/src/mock.rs`, backed by `pallet-assets`) was executable, since the mock's fungibles backend does not exhibit partial-transfer behavior — I did not find or execute a concrete mock demonstrating the shortfall, so this should be treated as a defense-in-depth/Low-Medium finding rather than a demonstrated exploit against the current mock/test configuration.

### Recommendation
In `mint`, capture the actual amount transferred into the reserve (`let actual = T::Fungibles::transfer(...)?;`) and either derate `internal_equivalent`/`internal_to_user` accordingly or fail the extrinsic (mirroring `Error::PartialTransfer` in `asset-conversion/ops`) if `actual != effective_external`. Symmetrically, in `redeem`, verify the amount actually delivered to the caller from the reserve equals `external_out` before decrementing `PsmDebt`. Consider also documenting/enforcing (via a trait bound or a runtime-benchmark-style assertion) that `Config::Fungibles` must not silently truncate transfers, since PSM's core invariant (`reserve >= debt_as_external`, already checked in `do_try_state`) currently relies on that assumption without any runtime enforcement in `mint`/`redeem`.

### Proof of Concept
No executable PoC was produced. Attempting to construct one against the existing `substrate/frame/psm/src/mock.rs`/`tests.rs` harness would exercise `pallet-assets`, whose `transfer` does not truncate amounts under `Preservation::Expendable`, so the discrepancy path cannot be triggered with the repo's current mock runtime. A concrete reproduction would require substituting a custom `T::Fungibles` implementation whose `transfer` intentionally returns less than requested (analogous to an ERC20 fee-on-transfer token) and then calling `Psm::mint` to show `PsmDebt` exceeds the PSM reserve's actual balance, i.e. failing the pallet's own `do_try_state` invariant at `substrate/frame/psm/src/lib.rs:1703-1706`. This gap is flagged as an unverified/unresolved point requiring further investigation with a suitable `Fungibles` backend before being escalated beyond a defense-in-depth recommendation.

		pub fn add_external_asset(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
		) -> DispatchResult {
			Self::ensure_psm_admin(origin, &internal_asset, |l| l.can_manage_assets())?;
			let mut info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;
			ensure!(
				!ExternalAssets::<T>::contains_key(&internal_asset, &external_asset),
				Error::<T>::AssetAlreadyApproved
			);
			ensure!(info.external_count < T::MaxExternals::get(), Error::<T>::TooManyAssets);
			ensure!(
				T::Fungibles::asset_exists(external_asset.clone()),
				Error::<T>::AssetDoesNotExist
			);

			let asset_decimals = T::Fungibles::decimals(external_asset.clone());
			ensure!(
				(asset_decimals.abs_diff(info.internal_decimals) as u32) <= MAX_DECIMALS_DIFF,
				Error::<T>::DecimalsRangeExceeded
			);

			ExternalAssets::<T>::insert(
				&internal_asset,
				&external_asset,
				ExternalAssetInfo {
					status: CircuitBreakerLevel::AllEnabled,
					decimals: asset_decimals,
				},
			);
			info.external_count = info.external_count.saturating_add(1);
			Psm::<T>::insert(&internal_asset, info);

			Self::deposit_event(Event::ExternalAssetAdded { internal_asset, external_asset });
			Ok(())
		}
