### Title
Webhook signature verified against organization-specific secret chosen from an unverified payload field, while the acted-upon repository comes from a different, unverified field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App/webhook secret to validate the HMAC signature against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted JSON body, before the signature has been checked. [2](#0-1) [3](#0-2)  The handlers that actually act on the payload (e.g. `PushHandler`) look up the target `Stack`/`Repository` using a *different* field, `repository.full_name`. [4](#0-3) [5](#0-4) 

### Finding Description
In the multi-org GitHub App configuration schema (used when `secrets.github` has multiple organization keys), each organization has its own `webhook_secret`. [6](#0-5)  `verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` using `repository_owner`, which is read from the JSON payload before any cryptographic check has occurred. [2](#0-1)  The signature is then verified as valid HMAC-SHA1 of the *entire* raw body against *that organization's* secret. [7](#0-6) 

Because the HMAC only proves "this body was signed with organization X's secret," and the binding the engine relies on is "the organization that authenticated == the repository the payload writes to," an attacker who controls their own GitHub organization/App installation (and therefore legitimately knows that org's `webhook_secret`) can craft a JSON body where `repository.owner.login` is their own org (so their own known secret is selected and the signature check passes) while `repository.full_name` names a completely different repository/stack tracked by this Shipit instance. `Handler#repository_name` uses `repository.full_name` verbatim to resolve the `Stack`, with no re-check that it matches the organization whose secret authenticated the request. [4](#0-3) 

For the equality check the rules ask for: the binding "organization that authenticated == repository that is written" is broken because `verify_signature` authenticates using `repository.owner.login`/`organization.login`, whereas the actual mutation (`PushHandler#process`, and other handlers relying on `stacks`) acts on `repository.full_name`, an unrelated, unverified field within the same signed body.

### Impact Explanation
This affects handlers such as `PushHandler`, which enqueues `stack.sync_github(expected_head_sha: params.after)` for any stack matching the attacker-chosen `repository.full_name` and `ref`, and other event handlers (`status`, `check_suite`, `pull_request`, `membership`, etc.) that likewise trust `repository.full_name` to select which stack/data record to write. This could let an attacker with a legitimately-configured GitHub App/org (a valid, low-privilege Shipit customer in a multi-tenant deployment) forge webhook events (e.g., fake `push`, `status`, or `check_suite` payloads) attributed to a repository/stack they do not own, potentially triggering unwanted `sync_github` calls, fabricated commit statuses, or spoofed check-run states that influence deploy-eligibility checks (`deployable?`) for repositories they have no legitimate access to. This lines up with the "unauthorized deploy" / cross-repository-write-adjacent impact class.

### Likelihood Explanation
This requires the deployment to be running the **multi-organization** GitHub App config (multiple orgs each with distinct `app_id`/`webhook_secret` under `secrets.github`), which is an explicitly documented, supported configuration (`github_app_config`, `github_default_organization`). [8](#0-7)  No privileged Shipit account, API token, or repository write access is needed — only that the attacker legitimately controls one organization/App installation registered with the same Shipit instance, which is the expected multi-tenant threat model.

### Recommendation
After successful signature verification, cross-check that the organization whose secret validated the payload matches the owner/organization of `repository.full_name` used by the handlers (i.e., derive the acted-upon repository/org strictly from the same field used for authentication, or explicitly validate `repository.full_name`'s owner equals `repository_owner`/`organization.login` before dispatching to handlers).

### Proof of Concept
1. Attacker legitimately registers/operates GitHub App "AttackerOrg" on this Shipit instance, with `webhook_secret` `S_attacker` known to them.
2. Attacker POSTs to `/github/webhooks` with `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "AttackerOrg" }, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker signs the raw body with `S_attacker` and sets `X-Hub-Signature` accordingly.
4. `verify_signature` calls `Shipit.github(organization: "AttackerOrg")`, which loads `S_attacker`, and `verify_webhook_signature` succeeds since the attacker validly signed with their own known secret. [2](#0-1) 
5. `PushHandler#stacks` resolves via `Repository.from_github_repo_name("victim-org/victim-repo")`, and `stack.sync_github` is enqueued for the victim's stack despite the request only being authenticated for "AttackerOrg". [4](#0-3) [5](#0-4)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
