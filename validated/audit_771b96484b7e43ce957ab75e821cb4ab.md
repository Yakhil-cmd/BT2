### Title
Unchecked RAY debt-value multiplication can permanently freeze a large market - (File: common/src/rates/index.rs)

### Summary
Interest accrual converts scaled debt to a RAY-denominated value using `borrowed.mul(env, new_borrow_index)` before the borrow-index ceiling is enforced for that step. Although the resulting index is capped at `10^36`, the intermediate debt value is still required to fit in `i128`; an out-of-range result raises `MathOverflow` and aborts accrual. Once a sufficiently large market reaches this boundary, `update_indexes`, withdrawals, repayments, liquidations, and other paths that sync the market revert, permanently trapping funds in that market.

### Finding Description
The pool’s accrual loop invokes `accrue_step` for each bounded time chunk. That function first computes the market’s original borrowed value, calculates a new borrow index, and then calls `calculate_supplier_rewards`. The latter multiplies the unchanged scaled debt by both the old and new indexes:

```rust
let old_total_debt = borrowed.mul(env, old_borrow_index);
let new_total_debt = borrowed.mul(env, new_borrow_index);
``` [1](#0-0) 

`update_borrow_index` clamps only the index returned by the multiplication, not the separate debt-value multiplication that follows it. [2](#0-1)  The shared multiply-divide implementation widens the intermediate product to `I256`, but deliberately panics when the final quotient cannot fit into `i128`. [3](#0-2) 

Consequently, the index ceiling does not bound the actual precondition that matters: `borrowed * new_borrow_index / RAY <= i128::MAX`. A market whose scaled debt approaches approximately `1.70e38` RAY can therefore fail accrual while its configured index remains below `MAX_BORROW_INDEX_RAY`. [4](#0-3) 

The unprivileged controller entrypoint `update_indexes(caller, assets)` only requires caller authorization and forwards the selected markets to the pool. [5](#0-4)  The pool then loads each market and executes `interest::global_sync`, which calls `accrue_chunk` and the shared `accrue_step` implementation. [6](#0-5) [7](#0-6) 

### Impact Explanation
This is a permanent market freeze, not a transient fail-closed condition. The panic occurs while mutating interest indexes, so every operation that must first accrue the affected market fails with `MathOverflow`. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot clear the position, and revenue cannot be claimed for that market. The existing regression test explicitly demonstrates the cliff: after `update_indexes` fails, both `withdraw` and `repay` fail with the same error. [8](#0-7) 

Severity: **High**. A single unprivileged account can maintain a large borrowed position and periodically call `update_indexes`; once the arithmetic cliff is reached, the market cannot recover through any normal entrypoint.

### Likelihood Explanation
Likelihood: **Medium**. Exploitation requires a very large supplied and borrowed market—on the order of hundreds of billions of whole-token units depending on decimals and index—but it does not require privileged access, invalid parameters, oracle manipulation, leaked keys, or a third-party failure. The protocol supports caps up to the token-to-RAY domain, and its own test constructs a one-billion-token, high-utilization market that reaches the failure before the nominal index cap. [9](#0-8) 

### Recommendation
Do not compute the full debt value when only the delta is needed. Calculate interest as a bounded `mul_div` delta directly, or precompute the largest representable `new_borrow_index` for the current scaled debt and clamp `new_borrow_index` to that value before calling `calculate_supplier_rewards`. Apply equivalent handling to supplied-value calculations in `update_supply_index` and add boundary tests proving that accrual reaches the configured index cap without panicking and that repayment, withdrawal, liquidation, and bad-debt cleanup remain callable at the cap.

### Proof of Concept
1. In an active market with permissive caps, an unprivileged whale supplies a large amount and borrows near the market’s utilization limit.
2. Keep utilization high so `calculate_borrow_rate` produces sustained interest.
3. Repeatedly call controller `update_indexes(caller, vec![hub_asset])` as ledger time advances.
4. Eventually `borrowed * new_borrow_index / RAY` exceeds `i128::MAX` even though `new_borrow_index` is below `10^36`.
5. `calculate_supplier_rewards` panics with `MathOverflow`, aborting accrual.
6. The same overflow occurs on subsequent `update_indexes` calls and on market operations that accrue first. The repository’s long-horizon test reaches this state and confirms both `withdraw` and `repay` revert with `MATH_OVERFLOW`. [10](#0-9)

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);

    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
