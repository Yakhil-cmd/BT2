### Title
Denial of Service via Unbounded Iteration Over Unstable Units in Data-Feed Formula Evaluation - (File: data_feeds.js)

### Summary
`data_feed` / `in_data_feed` oscript operations, used both in AA formulas and in `in data feed` address-definition authentifiers, are charged a fixed, constant "complexity" cost during validation regardless of the actual amount of work the corresponding runtime lookup performs. At runtime, when the AA-aware path is used, `dataFeedExists()` and `readDataFeedValue()` in `data_feeds.js` iterate over the entire in-memory `storage.assocUnstableMessages` map (`for (var unit in storage.assocUnstableMessages)`) on every single evaluation, performing an array-intersection check (`_.intersection`) for every unstable unit. An attacker who inflates the number of currently-unstable units/messages on the network (e.g., by flooding many small AA trigger units before they stabilize) can make this loop arbitrarily expensive, while the formula/complexity budget charged for the `data_feed`/`in_data_feed` op stays flat (complexity = 1, or a couple of small increments) as validated in `formula/validation.js`.

### Finding Description
The complexity/`count_ops` accounting for data-feed formula operators is fixed and does not scale with the real cost of the runtime lookup: [1](#0-0) [2](#0-1) 

Both `data_feed` and `in_data_feed` at runtime call into `data_feeds.js`, passing `bAA` (true when evaluating inside an AA trigger/response): [3](#0-2) [4](#0-3) 

When `bAA` is true, both `dataFeedExists()` and `readDataFeedValue()` walk the *entire* in-memory table of currently-unstable messages/units, doing a filter/intersection per entry, before falling back to the indexed KV-store lookup: [5](#0-4) [6](#0-5) 

`storage.assocUnstableMessages` holds all messages of all units that have not yet stabilized, and it is populated for every unit as soon as it is written and only cleared per-unit when that unit's MCI becomes stable: [7](#0-6) 

The size of this table is proportional to the number of units posted onto the DAG that have not yet stabilized. Any unprivileged unit poster can post a large number of cheap units in rapid succession (analogous to flooding an order book with many small orders in the reported bug), inflating the unstable set. Because the `for...in` scan and `_.intersection` calls are O(n) in the size of this map with no cap, and because the AA/definition author only pays a fixed, size-independent complexity fee for using `data_feed`/`in_data_feed`/`in data feed`, the actual computational cost paid by every node evaluating *any* AA trigger or address authentifier that uses these operators can be made far larger than the fixed budget implies — exactly the same "cheap flood → expensive O(n) scan on legitimate operation" pattern described in the external report (`process_maker_fill`/`vec_set::remove` vs. `max_computation_budget`).

### Impact Explanation
Every AA trigger (sent by any user, since AAs are permissionless and any account can trigger them) or address-definition evaluation (via `in data feed`) that references a `data_feed`/`in_data_feed` operator forces the processing node to perform this unbounded scan synchronously as part of validating/executing the unit. Since Node.js is single-threaded, an attacker who keeps the unstable-unit table large can make this scan take substantially longer than the flat complexity fee suggests, delaying or effectively stalling the processing of legitimate units and AA responses on the node performing validation — i.e., degrading the node's ability to confirm/execute new units and AA triggers in a timely manner, which can cause bounces (from AA execution taking too long) or general processing delays network-wide since every full node performs the same validation.

### Likelihood Explanation
Likelihood is medium-to-high: posting many low-cost units to inflate the unstable set is inexpensive and does not require any special privilege, and any AA composer or definition author routinely uses `data_feed`/`in_data_feed`/`in data feed` — a very common oscript primitive for oracles. No coordination with other network participants is needed; the attacker only needs to be an "unprivileged unit poster."

### Recommendation
- Charge complexity/`count_ops` for `data_feed`/`in_data_feed` proportional to (or bounded by) the size of `storage.assocUnstableMessages` actually scanned, or cap the number of unstable-AA candidates considered.
- Avoid scanning the full unstable-message table on every lookup; maintain a per-address (or per-feed) index of pending/unstable data-feed messages instead of a global `for...in` scan.
- Add an explicit upper bound on the number of unstable units/messages considered for the in-memory (unstabilized) branch of `dataFeedExists`/`readDataFeedValue`, falling back to the DB-indexed path once the bound is exceeded.

### Proof of Concept
1. Attacker rapidly posts a large number of low-fee units to the network so that `storage.assocUnstableMessages` grows to contain many thousands of pending unit entries before they stabilize (achievable since unit posting is permissionless and cheap).
2. A legitimate user sends an AA trigger, or posts a unit whose author address definition uses `in data feed`, to an AA/address that evaluates `data_feed`/`in_data_feed`/`in data feed`.
3. During validation, `dataFeedExists`/`readDataFeedValue` execute `for (var unit in storage.assocUnstableMessages) { ... _.intersection(...) ... }` over the entire inflated map, even though the formula validator charged only a fixed complexity of 1 for this operator (`formula/validation.js` lines 26-49, 381-395).
4. As the unstable set grows, this scan's real cost grows unboundedly while the "gas"/complexity budget enforced by `constants.MAX_COMPLEXITY`/`MAX_OPS` remains unaffected, allowing the attacker to make legitimate AA trigger processing arbitrarily slow on validating nodes without ever exceeding the nominal complexity limit — analogous to flooding the order book to force expensive `vec_set::remove` operations under a fixed `max_computation_budget`.

function dataFeedExists(arrAddresses, feed_name, relation, value, min_mci, max_mci, bAA, handleResult){
	var start_time = Date.now();
	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	if (bAA) {
		var bFound = false;
		function relationSatisfied(v1, v2) {
			switch (relation) {
				case '<': return (v1 < v2);
				case '<=': return (v1 <= v2);
				case '>': return (v1 > v2);
				case '>=': return (v1 >= v2);
				default: throw Error("unknown relation: " + relation);
			}
		}
		function valueIsNumber() {
			if (typeof value === 'string') {
				const float = string_utils.toNumber(value, bLimitedPrecision);
				return float !== null;
			}
			return true;
		}
		for (var unit in storage.assocUnstableMessages) {
			var objUnit = storage.assocUnstableUnits[unit] || storage.assocStableUnits[unit];
			if (!objUnit)
				throw Error("unstable unit " + unit + " not in assoc");
			if (!objUnit.bAA)
				continue;
			if (objUnit.latest_included_mc_index < min_mci || objUnit.latest_included_mc_index > max_mci)
				continue;
			if (_.intersection(arrAddresses, objUnit.author_addresses).length === 0)
				continue;
			storage.assocUnstableMessages[unit].forEach(function (message) {
				if (message.app !== 'data_feed')
					return;
				var payload = message.payload;
				if (!ValidationUtils.hasOwnProperty(payload, feed_name))
					return;
				var feed_value = payload[feed_name];
				if (relation === '=') {
					if (value === feed_value || value.toString() === feed_value.toString())
						bFound = true;
					return;
				}
				if (relation === '!=') {
					// search only within the same type, otherwise 'abc' != 123 but we don't want to say that they are not equal, because they are incomparable
					if (valueIsNumber()) {
						if (value.toString() !== feed_value.toString())
							bFound = true;
					}
					else {
						if (value !== feed_value)
							bFound = true;
					}
					return;
				}
				if (typeof value === 'number' && typeof feed_value === 'number') {
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				var f_value = (typeof value === 'string') ? string_utils.toNumber(value, bLimitedPrecision) : value;
				var f_feed_value = (typeof feed_value === 'string') ? string_utils.toNumber(feed_value, bLimitedPrecision) : feed_value;
				if (f_value === null && f_feed_value === null) { // both are strings that don't look like numbers
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				if (f_value !== null && f_feed_value !== null) { // both are either numbers or strings that look like numbers
					if (relationSatisfied(f_feed_value, f_value))
						bFound = true;
					return;
				}
				if (typeof value === 'string' && typeof feed_value === 'string') { // only one string looks like a number
					if (relationSatisfied(feed_value, value))
						bFound = true;
					return;
				}
				// else they are incomparable e.g. 'abc' > 123
			});
			if (bFound)
				break;
		}
		if (bFound)
			return handleResult(true);
	}

function readDataFeedValue(arrAddresses, feed_name, value, min_mci, max_mci, unstable_opts, ifseveral, timestamp, handleResult){

	var start_time = Date.now();
	var objResult = { bAbortedBecauseOfSeveral: false, value: undefined, unit: undefined, mci: undefined };
	var bIncludeUnstableAAs = !!unstable_opts;
	var bIncludeAllUnstable = (unstable_opts === 'all_unstable');
	if (bIncludeUnstableAAs) {
		var arrCandidates = [];
		for (var unit in storage.assocUnstableMessages) {
			var objUnit = storage.assocUnstableUnits[unit] || storage.assocStableUnits[unit];
			if (!objUnit)
				throw Error("unstable unit " + unit + " not in assoc");
			if (!objUnit.bAA && !bIncludeAllUnstable)
				continue;
			if (objUnit.sequence !== 'good')
				continue;
			if (objUnit.latest_included_mc_index < min_mci || objUnit.latest_included_mc_index > max_mci)
				continue;

				continue;
			storage.assocUnstableMessages[unit].forEach(function (message) {
				if (message.app !== 'data_feed')
					return;
				var payload = message.payload;
				if (!ValidationUtils.hasOwnProperty(payload, feed_name))
					return;
				var feed_value = payload[feed_name];
				if (value === null || value === feed_value || value.toString() === feed_value.toString())
					arrCandidates.push({
						value: string_utils.getFeedValue(feed_value, bLimitedPrecision),
						latest_included_mc_index: objUnit.latest_included_mc_index,
						level: objUnit.level,
						unit: objUnit.unit,
						mci: max_mci // it doesn't matter
					});
			});
		}

			var feed = arrCandidates[0];
			objResult.value = feed.value;
			objResult.unit = feed.unit;
			objResult.mci = feed.mci;
			if (ifseveral === 'last')

			objResult.unit = feed.unit;
			objResult.mci = feed.mci;
			return handleResult(objResult);
		}
	}
