### Title
`GitHubApp#verify_webhook_signature` bypasses HMAC verification when `webhook_secret` is unset - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::GitHubApp#verify_webhook_signature` returns `true` without any cryptographic check when the resolved organization's config has no `webhook_secret`, and the org used is selected purely from the attacker-supplied `repository.owner.login` (or `organization.login`) field in the webhook JSON body. If any configured org in `Shipit.github_config`/`secrets.github` lacks a `webhook_secret`, an unauthenticated attacker can post arbitrary webhook payloads for that org and have them processed as genuine.

### Finding Description
The intended binding is: `verify_webhook_signature(signature, body) == true` should imply `body` was produced by GitHub using that org's `webhook_secret` HMAC. This is broken by the early return at [1](#0-0) , specifically `return true unless webhook_secret` on line 77 — if `@webhook_secret` (set from `@config[:webhook_secret].presence` at [2](#0-1) ) is blank, the method short-circuits to `true` before ever computing or comparing an HMAC.

The reachable path is `POST /webhooks` → `WebhooksController#verify_signature`, which selects the `GitHubApp` instance via `Shipit.github(organization: repository_owner)`, and `repository_owner` is read directly from the untrusted JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [3](#0-2) . This org name is then used to look up config via `Shipit.github_app_config` in `lib/shipit.rb` (`github_config[organization.downcase.to_sym]`) [4](#0-3) , and `verify_signature` calls `github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)` [5](#0-4) . Nothing between the attacker-controlled `repository_owner` and the `GitHubApp` construction validates that the org actually owns the repository being referenced in the payload — the org is only used to pick which secret/config to check against.

Existing guards do not prevent this divergence: `drop_unhandled_event` and `check_if_ping` only filter event types [6](#0-5) ; `GithubOrganizationUnknown` is only raised when the org name doesn't match any configured key at all, not when the matched org's secret is blank [4](#0-3) .

### Impact Explanation
For any configured GitHub org whose config entry has `webhook_secret` omitted or blank, an attacker can send `POST /webhooks` with a fabricated payload (`repository.owner.login` = that org, any event handled by `Shipit::Webhooks.for_event`) and an arbitrary/absent `X-Hub-Signature`; `verify_webhook_signature` returns `true`, and the payload is dispatched to the real webhook handlers as if GitHub had sent it. Depending on which handler is registered for the chosen event, this can drive real state changes (e.g., synthetic status/check-run updates, PR/merge-request state changes) attributed to that org's repositories without any authentic GitHub signature — a full authentication bypass for that org's webhook ingestion, matching the Critical "authentication bypass (forged webhook ... accepted)" category. It is fully repeatable against every request for that org as long as the misconfiguration persists, though the blast radius is scoped to organizations actually missing `webhook_secret` in `Shipit.github_config`/`secrets.github`.

### Likelihood Explanation
The precondition is operator misconfiguration: at least one org entry in `secrets.github` must have no `webhook_secret` set. `docs/setup.md`/`template.rb` document `webhook_secret` as part of expected GitHub app config, but the code does not enforce its presence at boot or reject configs missing it — it silently treats a missing secret as "skip verification." Given this precondition, attacker cost is trivial (a single unauthenticated HTTP POST, no secrets or session needed), and the exploit is deterministic and repeatable.

### Recommendation
Do not treat a missing `webhook_secret` as "verification not required." Either (a) fail closed — treat missing `webhook_secret` as verification failure (`return false unless webhook_secret`) — or (b) validate at application boot / config-load time that every configured GitHub org has a non-blank `webhook_secret`, raising a startup error otherwise, so this state can never be reached in a running instance.

### Proof of Concept
```ruby
# test/unit/github_app_test.rb (conceptual addition)
test "#verify_webhook_signature does not verify when webhook_secret is blank" do
  app_without_secret = GitHubApp.new('acme', { app_id: 1, installation_id: 1, private_key: 'x' }) # no webhook_secret
  # Binding under test: verified == true  vs  body authenticated == false
  assert_equal true, app_without_secret.verify_webhook_signature(nil, 'arbitrary attacker payload')
  assert_equal true, app_without_secret.verify_webhook_signature('sha1=deadbeef', 'arbitrary attacker payload')
end
```
This demonstrates that `verify_webhook_signature` returns `true` for arbitrary/absent signatures when `webhook_secret` is blank, i.e. the "verified" result no longer implies "authentic body for that org," confirming the broken binding described above.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
