### Title
Aquarius LP collateral incentives accrue to the pool but cannot be claimed or distributed - (File: `contracts/pool/src/lib.rs`)

### Summary
XOXNO Lending accepts Aquarius LP tokens as collateral, but custody is held by the shared `LiquidityPool` contract rather than by each supplier’s account. Venue rewards therefore accrue to the pool address, while the pool exposes only owner-gated lending/revenue entrypoints and no external reward-claim or reward-forwarding path. Rewards pushed into the pool are treated as unbooked donations rather than supplier yield.

### Finding Description
An unprivileged user can call `controller::supply` with an Aquarius LP hub asset such as `AQUAUSDC_LP`; the controller transfers the LP token from the caller to the pool and only then credits measured supply shares through `pool::supply`. [1](#0-0)  The pool mints supply shares and credits market `cash`, but records no entitlement to external venue incentives. [2](#0-1)  The pool ABI contains market, lending, flash-loan, strategy, recapitalization, revenue, and upgrade functions, but no function that claims rewards from an external venue or forwards an arbitrary reward token. [3](#0-2)  Mainnet configuration makes Aquarius LP tokens collateral-only assets. [4](#0-3)  The project’s own threat model states that venue rewards accrue to the pool holder, permissionless venue claims can push rewards into the pool as an unbooked donation, and gauge rewards requiring pool authorization cannot be claimed. [5](#0-4) 

### Impact Explanation
Suppliers of Aquarius LP collateral permanently lose the external liquidity-incentive yield attributable to their collateral. Permissionlessly claimed rewards sent to the pool are not booked as market cash and cannot be attributed to suppliers; gauge rewards remain unclaimable because the pool has no authorized claim/forward path. This is freezing or loss of unclaimed yield, while the LP principal remains represented by supply shares. [5](#0-4) 

### Likelihood Explanation
Any user can reach the state through `controller::supply` on a listed Aquarius LP market, and any third party can trigger a venue reward claim that pays the pool address. No privileged role, oracle manipulation, or upgrade is required. The loss occurs whenever the underlying Aquarius position has an incentive or gauge program.

### Recommendation
Add an explicit reward-accounting path for incentivized LP collateral: let the pool or controller claim venue/gauge rewards, measure the actual receipt, and either distribute it pro rata to LP-collateral suppliers or book it as protocol revenue through an intentional governance-controlled path. If rewards are pushed to the pool by third parties, reconcile them into a separate reward ledger instead of leaving them as unbooked token balance.

### Proof of Concept
1. Governance lists `AQUAUSDC_LP` as collateral-only in hub 3, as in the mainnet configuration. [6](#0-5) 
2. Alice calls `controller::supply(caller=Alice, account_id=0, spoke_id=<Aquarius spoke>, assets=[AQUAUSDC_LP payment])`; the controller transfers the LP token to the pool and mints supply shares. [1](#0-0) 
3. The Aquarius position accrues incentives to the pool address. A permissionless venue claim transfers reward tokens to the pool, but `cash` and Alice’s supply shares do not change. A gauge reward requiring pool authorization cannot be claimed because neither the pool nor controller exposes an authorized reward-claim call. [5](#0-4)

**File:** docs/explanation/threat-model.md (L134-140)
```markdown
Aquarius LP collateral earns venue rewards for its holder, which is the pool.
The pool has no entrypoint to claim or forward them. The venue's reward claim
did not require the holder's authorization when reviewed (mainnet simulation,
2026-09), so any caller can push accrued rewards into the pool address as an
unbooked donation. Gauge rewards need the pool's authorization and therefore
cannot be claimed at all. Suppliers of LP collateral should expect no venue
rewards; this is forgone yield, not a loss of principal.
```
