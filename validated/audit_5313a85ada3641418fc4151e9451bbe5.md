### Title
Webhook signature scope (`repository.owner.login`) is decoupled from the repository actually mutated (`repository.full_name`) - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's webhook secret to validate a GitHub delivery against using `repository_owner`, which is read straight out of the attacker-controllable JSON body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). All the actual event handlers (`PushHandler`, `Handler#stacks`, the `PullRequest::*Handler` classes, etc.) instead resolve the target `Repository`/`Stack` using a *different* field from the same body: `payload.dig('repository', 'full_name')`. Nothing ties the two together, so the field that is "authenticated" (the org used to pick the HMAC secret) is not the field that is acted upon (the repository whose stack gets synced/mutated). ### Finding Description
`verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` and then calls `github_app.verify_webhook_signature(...)`, using the per-organization `webhook_secret` from `lib/shipit/github_app.rb`:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 
`webhook_secret` is optional configuration (`@webhook_secret = @config[:webhook_secret].presence`), so for any organization configured on a multi-tenant Shipit instance without a `webhook_secret`, signature verification unconditionally returns `true` regardless of the `X-Hub-Signature` header sent. [5](#0-4) 

Crucially, `repository_owner` is derived purely from the request body, not from any verified GitHub metadata:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [6](#0-5) 

Once `verify_signature` passes, `WebhooksController#create` dispatches the *same raw body* to `Shipit::Webhooks.for_event(event)` handlers. Every handler resolves the target repository via `Handler#repository_name`, which reads a completely separate JSON key:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [7](#0-6) 

`PushHandler#process` then walks every non-archived stack matching that repository/branch and calls `stack.sync_github(expected_head_sha: params.after)`: [8](#0-7) 

The equality this breaks: `repository_owner` used to select the HMAC-verifying organization ("who authenticated this request") should equal the organization that owns `repository.full_name` ("whose repository/stack gets acted upon"). Nothing in the controller or the handler chain enforces this. Both fields are attacker-supplied in the same unauthenticated JSON POST.

### Impact Explanation
Because `repository.owner.login`/`organization.login` (used for signature routing) and `repository.full_name` (used for target resolution) are independent, unbound fields in the same payload, an unauthenticated caller can:
1. Craft a JSON body where `repository.owner.login` (or `organization.login`) is set to any organization configured in the Shipit instance that has no `webhook_secret` set (an entirely plausible, valid, non-malicious configuration state — the field is `presence`-optional), which forces `verify_webhook_signature` to return `true` unconditionally.
2. Set `repository.full_name` in the very same body to point at a completely unrelated victim repository/stack managed by the same Shipit instance under a different, secret-protected organization.
3. POST this to the public `/github_webhooks` endpoint (no session, no `ApiClient` token required — `WebhooksController` skips CSRF and has no `Authentication` concern).

The `push` event handler will then invoke `stack.sync_github(expected_head_sha: ...)` on the victim's stack, and other handlers (`status`, `pull_request` variants, `check_suite`, `membership`) will similarly act on the victim repository/stack — all despite the signature check having validated nothing about that victim organization's secret. This can force out-of-band syncs/deploys and CI-status/state mutations on repositories the attacker has no legitimate relationship to, an unauthorized action against a stack the attacker never authenticated against.

### Likelihood Explanation
Exploitability is fully gated on at least one organization in the multi-tenant Shipit deployment lacking a `webhook_secret`, since `verify_webhook_signature` short-circuits to `true` in that case. This is a supported, documented configuration path (`webhook_secret` is optional in `lib/shipit/github_app.rb`), not a hypothetical misconfiguration outside the engine's control, and no session, API token, or GitHub credentials are needed to send the forged request — only knowledge that the target Shipit instance hosts multiple orgs and that at least one lacks a secret.

### Recommendation
Bind repository resolution to the same verified organization used for signature checking: after `verify_signature` succeeds, re-derive and enforce that `payload.dig('repository', 'full_name')`'s owner segment matches `repository_owner` (the value actually used to pick the HMAC secret), rejecting the webhook otherwise. Alternatively, require `webhook_secret` to be present for every configured organization (fail closed rather than `return true unless webhook_secret`), and have handlers resolve `Repository` scoped to `repository_owner` rather than trusting `repository.full_name` alone.

### Proof of Concept
1. Configure Shipit with two organizations: `attacker-org` (no `webhook_secret` set) and `victim-org` (protected, `webhook_secret` set), each with at least one repository/stack registered.
2. POST to `/github_webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
No valid `X-Hub-Signature` header is required, since `Shipit.github(organization: "attacker-org").verify_webhook_signature` returns `true` unconditionally (`webhook_secret` blank).
3. `WebhooksController#create` dispatches to `PushHandler`, which resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on the victim's stack, despite the request never being validated against `victim-org`'s secret.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',

        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
