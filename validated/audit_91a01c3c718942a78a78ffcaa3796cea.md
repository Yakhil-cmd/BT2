### Title
Denial of service via unhandled exception in `getHeadersSize` on non-finite numbers in unit headers - (File: `object_length.js` / `validation.js`)

### Summary
`validation.js`'s `validate()` computes the header size of every incoming unit via `objectLength.getHeadersSize(objUnit)` (validation.js:257) without a `try/catch`, while the very next check for payload size (`objectLength.getTotalPayloadSize`, validation.js:259‑266) *is* wrapped in a `try/catch`. `getHeadersSize` walks the full unit header (including `authors`, i.e. the raw, not-yet-validated address definitions) via `getLength()`/`_getLength()` in `object_length.js`, which explicitly `throw`s an `Error` when it encounters any JavaScript number that is not finite (`object_length.js:17-19`). Because `JSON.parse()` will happily convert an over-scaled numeric literal such as `1e400` into `Infinity`, an attacker can embed such a literal inside `authors[].definition` (a field that is not schema/range-validated until later, in `validateAuthors`/`validateDefinition`, which run only after this size check). This throws an uncaught `Error` out of `validate()`.

### Finding Description [1](#0-0) 
shows the asymmetry: `getHeadersSize` is called unguarded, whereas `getTotalPayloadSize` right below it is wrapped in `try/catch`. [2](#0-1) 
shows `_getLength()` recursively walking every field of the object and throwing `Error("invalid number: " + value)` for any `!isFinite(value)` number. [3](#0-2) 
shows `getHeadersSize` cloning `objUnit`, stripping only `messages` and a handful of top-level fields, but retaining `authors` (with the full, attacker-supplied address definition tree) before it is validated by `validateAuthors`/`validateDefinition`, which occur later in the `async.series` pipeline (see `validateAuthors` call at `validation.js:437`, well after the size checks at line 257).

Because `objUnit` originates directly from `JSON.parse()` of network-received data, a numeric literal like `1e400` in the JSON payload parses to the JavaScript value `Infinity` (this is valid JSON syntax; the JSON spec does not bound exponent size and standard parsers do not reject it). Placing such a value anywhere inside `authors[].definition` (e.g., as an `amount`, `mci`, or any numeric literal accepted by the oscript-style definition grammar) means it survives:
- the unit-hash check (`objectHash.getUnitHash(objUnit) !== objUnit.unit`, validation.js:133) — the hash simply covers the literal value, so a self-consistent unit can be crafted,
- `isObjectWellFormed`/`isTooDeeplyNestedOrHasTooManyNodes` checks, which only guard against lone surrogates/null bytes and excessive nesting — not numeric finiteness,

and reaches `getHeadersSize(objUnit)` at validation.js:257, which recurses into `authors` and throws when it meets the `Infinity` value.

Since this throw is not caught anywhere in `validate()`'s synchronous entry path, it propagates as an uncaught exception. `network.js` installs a deliberate `process.on('uncaughtException', ...)` handler that logs diagnostics and then re-`throw`s to crash the process "to avoid ending up in an inconsistent state" ( [4](#0-3) ). Thus a single malformed-but-hash-consistent unit posted by any unprivileged peer/unit poster can crash the full node process.

### Impact Explanation
This is a direct process-crash Denial of Service reachable from an untrusted, unprivileged unit poster: any peer that can send/broadcast a joint to a node (or any AA/trigger flow that eventually causes `validation.validate()` to run on attacker-influenced unit content) can trigger the crash, since the vulnerable code path executes very early in `validate()`, before author/definition-specific validation occurs. Repeated crash triggers on core/witness/hub nodes constitute a network-wide DoS: nodes are forced to restart, in the interim they cannot process/confirm new units, i.e., "a network unable to confirm new units," matching the required impact class exactly.

### Likelihood Explanation
High. No signature/authentication bypass is required to reach the flaw — the crash happens during the very first, cheap structural checks (`getHeadersSize`) that run before signature/definition/authentifier verification. Any actor able to submit a unit (even one that ultimately would fail definition validation) can trigger it, because the object-length computation runs unconditionally before that later validation. Building a unit whose `objectHash.getUnitHash()` matches its own `unit` id while containing an `Infinity`-producing numeric literal is straightforward, since the hash function simply hashes the JSON‑serializable structure that includes the numeric literal as-is.

### Recommendation
- Wrap the `objectLength.getHeadersSize(objUnit)` call in `validation.js` (around line 257) in a `try/catch`, mirroring the handling already applied to `getTotalPayloadSize`, and convert any thrown error into a normal `ifJointError`/`ifUnitError` callback instead of letting it escape.
- Additionally, make `getLength`/`_getLength` in `object_length.js` fail closed for non-finite numbers by returning a validation error rather than throwing, or perform an early guard so that a non-finite number anywhere in the unit is turned into a joint/unit validation rejection.
- More generally, reject non-finite numeric values as early as possible in the unit-ingestion pipeline (e.g., right after `JSON.parse`), before any size/hash computations run.

### Proof of Concept
1. Construct a unit object where a numeric field deep inside `authors[0].definition` is the literal `1e400` (or any exponent large enough to overflow to `Infinity`), e.g.:
```json
{
  "unit": "<hash of the below>",
  "version": "4.0",
  "authors": [{
     "address": "SOME32CHARADDRESS...",
     "definition": ["and", [
        ["address", "SOME32CHARADDRESS..."],
        ["age", [">", 1e400]]
     ]],
     "authentifiers": {"r": "<sig>"}
  }],
  "parent_units": [...],
  "last_ball": "...",
  "last_ball_unit": "...",
  "headers_commission": 0,
  "payload_commission": 0,
  "messages": [ ... ]
}
```
2. Compute `objectHash.getUnitHash()` over this structure and set `unit` accordingly so the hash check at `validation.js:133` passes.
3. Broadcast/post this joint to a node (via `network.js`'s `handleJoint`, or via `light.js`/wallet posting paths).
4. `validate()` reaches `objectLength.getHeadersSize(objUnit)` (`validation.js:257`), which recurses into `authors[0].definition`, hits the `1e400`→`Infinity` value, and `_getLength` throws `Error("invalid number: Infinity")` (`object_length.js:18-19`) — uncaught, crashing the node process via `network.js`'s `uncaughtException` handler.

Note: I was unable to fully trace whether every network-facing ingestion point strictly requires `objUnit.unit`'s hash to already match before invoking `validate()` versus some code paths calling `validate()` on not-yet-hash-verified data (which would make the PoC even easier), due to index/tool limitations on tracing every caller. The core root cause — the missing `try/catch` around `getHeadersSize` combined with `_getLength`'s unconditional throw on non-finite numbers — is confirmed directly from the cited source.

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
}
