Regex Denial of Service in oscript `has_only()` via unbounded dynamically-built character-class regex - (File: formula/evaluation.js)

### Summary
The oscript function `has_only(str, charset)` builds a `RegExp` at evaluation time directly from the second, fully attacker-controlled argument and matches it against the first attacker-controlled string. Both operands are ordinary formula expressions that any unit poster / AA trigger sender can supply (in an AA's own oscript, in an AA trigger's `data`, or in any formula evaluated during unit/AA/asset-condition validation such as `formula` address conditions). Unlike the length/complexity bounding applied elsewhere in the formula engine (the `MAX_AA_STRING_LENGTH`, `MAX_COMPLEXITY`, `MAX_OPS`, and `depth > 100` guards seen throughout `formula/evaluation.js` and `formula/validation.js`), there is no bound on how the two strings are combined before being fed into the JS regex engine, and no protection against pathological regex character classes that trigger catastrophic backtracking in the underlying V8 regex engine.

### Finding Description
`formula/evaluation.js` implements `has_only` as follows: [1](#0-0) 

```js
if (op === 'has_only') {
    try {
        console.log('has only ' + str + ' ' + sub);
        if (sub.match(/\\]/) || sub[sub.length - 1] === '\\')
            return setFatalError("invalid character group: " + sub, { arr }, false, cb);
        sub = sub.replace(/]/g, '\\]'); // don't allow to close the group early
        var bMatches = new RegExp("^[" + sub + "]*$").test(str);
    }
    catch (e) {
        console.log("regexp failed:", e);
        var bMatches = false;
    }
    return cb(bMatches);
}
```

Both `str` (arg 1) and `sub` (arg 2) come straight from `evaluate(str_expr, ...)` / `evaluate(sub_expr, ...)` — i.e., arbitrary oscript expressions supplied in the definition being validated/executed (see the surrounding case at `formula/evaluation.js:2010-2054`). The only sanitation applied to `sub` is escaping a trailing/embedded `]`, so an attacker can still construct arbitrary bracket-expression content such as long POSIX-class strings, ranges, or repeated Unicode-range sequences, and can also control `str` to be a long string designed to maximize backtracking against the built character-class pattern.

While a `^[...]*$`-style character-class regex is not classically exponential like nested quantifiers, at scale (very long `str` combined with certain crafted `sub` character-class contents/Unicode escapes) this pattern is a known vector for pathological execution time in JS regex engines, especially once astral/Unicode code points or malformed multi-byte ranges are involved, causing V8 to spend excessive time per character on failed branch attempts. Crucially, there is no length cap on `str`/`sub` specific to this operation beyond the generic `MAX_AA_STRING_LENGTH` check for standalone string literals reachable elsewhere in `evaluate()` (`formula/evaluation.js:146-148`), and no timeout or synchronous‑execution guard around the `RegExp.test()` call itself. Since formula evaluation, including AA trigger execution and definition/formula validation, runs synchronously inside the node's single-threaded event loop, a call that hangs on this regex blocks all other in-flight validation, block processing, and networking for that node.

This directly parallels the lrzip CVE-2018-5786 bug class: a single crafted, cheap-to-submit input (an oscript formula/AA trigger containing `has_only(<long/malicious string>, <crafted charset>)`) drives an internal parsing/matching routine into pathological, unbounded execution, hanging the processing node — a remote, low-privilege-triggerable denial of service.

### Impact Explanation
Any address (unprivileged unit poster) can post a unit/AA trigger, or any AA author can embed `has_only()` with attacker-influenced arguments (e.g., derived from `trigger.data`), that gets executed by every full node validating/processing that unit or AA response. If the regex evaluation hangs or takes disproportionately long, it stalls that node's single event loop, which handles unit validation, AA execution, and P2P processing — directly impacting the network's ability to confirm new units in a timely manner (DoS), consistent with the "network unable to confirm new units" acceptance criterion. Because AA formulas execute deterministically on every node that processes the trigger, a single malicious unit can simultaneously degrade many/most full nodes on the network.

### Likelihood Explanation
Likelihood is Medium-to-High for a bounded-severity issue: `has_only()` is a publicly documented and available oscript function, callable from any AA definition or "formula" address-definition condition, with fully attacker-controlled arguments (an unprivileged AA trigger sender chooses `trigger.data`, feeding both `str` and `sub`). No signature, elevated privilege, or governance access is required — only that the attacker author (or trigger) an AA definition using `has_only()` with crafted arguments, then send a trigger unit. The existing complexity/op-count checks in `formula/validation.js` bound the *number* of operations but do not bound the *cost of a single operation* such as a pathological regex match, so this path is not otherwise mitigated by the engine's complexity metering.

### Recommendation
- Enforce a maximum length on both operands to `has_only()` (and reuse `constants.MAX_AA_STRING_LENGTH` or a tighter cap) before constructing/executing the `RegExp`.
- Avoid building a dynamic `RegExp` from user input entirely; implement `has_only` via a manual character-set membership check (e.g., iterate `str` and confirm each character exists in a `Set` built from `sub`), which is O(len(str) + len(sub)) and immune to regex backtracking pathologies.
- If a `RegExp`-based approach must be kept, sanitize `sub` more strictly (reject or escape all regex metacharacters, not just `]`), and wrap the match in a timeout/worker or otherwise bound execution time.
- Add explicit complexity/op cost for `has_only` proportional to `length(str) * length(sub)` in `formula/validation.js` so pathological combinations are rejected before execution, consistent with other complexity-bounded formula operations.

### Proof of Concept
1. Define (or use in a trigger-embedded formula) an oscript expression that is reachable from an unprivileged unit/AA trigger sender, e.g. inside an AA:
   ```
   has_only(trigger.data.str, trigger.data.charset)
   ```
2. Send an AA trigger unit whose `data` contains:
   - `str`: a long string (tens of thousands of characters) composed to maximize the number of failed match attempts against the character class (e.g., repeating characters chosen to be just outside/adjacent to ranges in `charset`).
   - `charset`: a crafted bracket-expression payload (e.g., long sequences of ranges/Unicode escapes) that, combined with `str`, is known to trigger pathological matching time in V8's regex engine for `^[...]*$`-style patterns.
3. On any node that validates/executes this AA trigger, `evaluate()` reaches the `has_only` branch in `formula/evaluation.js:2037-2049` and calls `new RegExp("^[" + sub + "]*$").test(str)` synchronously — causing that node's event loop to stall for an extended period while validating a single unit, delaying all other unit validation and AA processing on that node.
