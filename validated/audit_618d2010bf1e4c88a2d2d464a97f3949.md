### Title
ERC721 Bridge Transfers Are Free of Any Fees While ERC20 and KLAY Transfers Correctly Charge Fees — (`contracts/service_chain/bridge/BridgeTransferERC721.sol`)

---

### Summary

The service-chain bridge implements a fee mechanism for KLAY and ERC20 value transfers but entirely omits it for ERC721 transfers. The fee is hardcoded to `0` in `_requestERC721Transfer`, meaning the bridge fee receiver collects nothing from ERC721 cross-chain transfers while collecting fees from every KLAY and ERC20 transfer.

---

### Finding Description

`BridgeFee.sol` defines two fee storage slots and two fee-payment helpers:

- `feeOfKLAY` / `_payKLAYFeeAndRefundChange`
- `feeOfERC20[token]` / `_payERC20FeeAndRefundChange`

**KLAY path** — fee is collected before the transfer is recorded:

```solidity
// BridgeTransferKLAY._requestKLAYTransfer
uint256 fee = _payKLAYFeeAndRefundChange(_feeLimit);
emit RequestValueTransfer(..., fee, ...);
``` [1](#0-0) 

**ERC20 path** — fee is collected before the transfer is recorded:

```solidity
// BridgeTransferERC20._requestERC20Transfer
uint256 fee = _payERC20FeeAndRefundChange(_from, _tokenAddress, _feeLimit);
emit RequestValueTransfer(..., fee, ...);
``` [2](#0-1) 

**ERC721 path** — no fee helper is called; fee is hardcoded to `0`:

```solidity
// BridgeTransferERC721._requestERC721Transfer
emit RequestValueTransferEncoded(
    TokenType.ERC721,
    _from, _to, _tokenAddress, _tokenId,
    requestNonce,
    0,          // ← fee hardcoded to zero, no _payFee* call
    _extraData, 2, abi.encode(string(uri))
);
``` [3](#0-2) 

There is no `feeOfERC721` storage variable, no `setERC721Fee` function, and no `_payERC721FeeAndRefundChange` helper anywhere in `BridgeFee.sol`. [4](#0-3) 

---

### Impact Explanation

The bridge fee receiver (`feeReceiver`) receives zero KAIA/tokens from every ERC721 cross-chain transfer, regardless of how high the operator has configured fees for KLAY and ERC20 transfers. Any user initiating an ERC721 bridge transfer bypasses the fee mechanism entirely. This is a direct loss of fee revenue from bridged assets — the same class of impact as M-04 ("protocol leaked value").

---

### Likelihood Explanation

Every ERC721 bridge transfer — whether via `onERC721Received` (1-step) or `requestERC721Transfer` (2-step) — routes through `_requestERC721Transfer`, which unconditionally emits `fee = 0`. No special conditions are required; any unprivileged user initiating an ERC721 transfer triggers this path. [5](#0-4) 

---

### Recommendation

Implement an ERC721 fee mechanism parallel to the existing KLAY and ERC20 mechanisms:

1. Add `mapping(address => uint256) public feeOfERC721` to `BridgeFee.sol`.
2. Add `_payERC721FeeAndRefundChange(address from, address token, uint256 feeLimit)` that mirrors `_payERC20FeeAndRefundChange`.
3. Call it inside `_requestERC721Transfer` and pass the returned fee to the event.
4. Add a `setERC721Fee(address token, uint256 fee, uint64 requestNonce)` operator function.

---

### Proof of Concept

Compare the three request paths side-by-side:

| Token type | Fee helper called | Fee emitted in event |
|---|---|---|
| KLAY | `_payKLAYFeeAndRefundChange` | dynamic | 
| ERC20 | `_payERC20FeeAndRefundChange` | dynamic |
| **ERC721** | **none** | **hardcoded `0`** |

A bridge operator who sets `feeOfKLAY = 1e18` and `feeOfERC20[token] = 1e18` will collect fees from every KLAY and ERC20 transfer but collect nothing from ERC721 transfers, even though the same `feeReceiver` address is shared across all three paths. [6](#0-5)

    mapping (address => uint256) public feeOfERC20;

    event KLAYFeeChanged(uint256 indexed fee);
    event ERC20FeeChanged(address indexed token, uint256 indexed fee);
    event FeeReceiverChanged(address indexed feeReceiver);

    constructor(address payable _feeReceiver) internal {
        feeReceiver = _feeReceiver;
    }

    // Caller of this function must be nonReentrant.
    // - BridgeTransferKLAY._requestKLAYTransfer() is nonReentrant
    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }

    function _payERC20FeeAndRefundChange(address from, address _token, uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfERC20[_token];

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            IERC20(_token).safeTransfer(feeReceiver, fee);

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                IERC20(_token).safeTransfer(from, feeRefund);
            }

            return fee;
        }

        if (_feeLimit > 0) {
            IERC20(_token).safeTransfer(from, _feeLimit);
        }
        return 0;
    }

    function _setKLAYFee(uint256 _fee) internal {
        feeOfKLAY = _fee;
        emit KLAYFeeChanged(_fee);
    }

    function _setERC20Fee(address _token, uint256 _fee) internal {
        feeOfERC20[_token] = _fee;
        emit ERC20FeeChanged(_token, _fee);
    }

    function _setFeeReceiver(address payable _to) internal {
        feeReceiver = _to;
        emit FeeReceiverChanged(_to);
    }
}
