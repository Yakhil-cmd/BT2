### Title
Webhook signature verification binds to `repository.owner.login` while the payload processed for state changes is scoped by the independent `repository.full_name` field, allowing signature bypass via an unconfigured-secret organization to forge events against any tracked repository - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/handler.rb, lib/shipit/github_app.rb)

### Summary
The webhook signature check and the actual state-mutating repository lookup use two independent fields from the same attacker-supplied JSON payload without cross-validating them. `WebhooksController#verify_signature` selects which GitHub App/secret to verify against using `repository.owner.login` (or `organization.login`), while every `Shipit::Webhooks::Handlers::Handler` subclass resolves the repository/stack to act upon using the unrelated `repository.full_name` field. Combined with `GithubApp#verify_webhook_signature` trivially returning `true` when no `webhook_secret` is configured for the authenticated organization, an attacker can select an org with no configured secret to pass verification, then point `repository.full_name` at a different, secret-protected organization's tracked repository to trigger real state changes on it.

### Finding Description
`WebhooksController#verify_signature` computes the authenticating organization purely from the payload: [1](#0-0) [2](#0-1) 

The actual GitHub App instance for that org is fetched via `Shipit.github(organization: repository_owner)`, and its `verify_webhook_signature` short-circuits to `true` whenever no `webhook_secret` is configured for that org: [3](#0-2) 

Once the request passes this org-scoped check, `create` dispatches the *entire* raw payload to handlers: [4](#0-3) 

Every handler independently resolves the repository to act on via a different, unrelated field of the same payload — `repository.full_name` — with no check that it belongs to the organization that was actually verified: [5](#0-4) 

This is used, for example, by `PushHandler` to trigger a sync of a stack to an attacker-chosen SHA: [6](#0-5) 

and by the pull-request handlers to archive/unarchive/create review stacks for whatever repository `full_name` resolves to: [7](#0-6) [8](#0-7) 

**The broken equality:** the organization whose signature was checked (`payload['repository']['owner']['login']`, used only to select the `GithubApp`/secret) is treated as equivalent to the organization/repository the handler actually mutates (`payload['repository']['full_name']`, used by `Repository.from_github_repo_name`). Nothing in the request pipeline enforces `full_name.start_with?("#{owner_login}/")`. Because these are two independently attacker-controlled JSON keys in a single payload, and because `verify_webhook_signature` degrades to an unconditional pass when the *authenticating* org has a blank `webhook_secret` (a documented, supported configuration — see `docs/setup.md`, `webhook_secret` is optional), any org onboarded to a multi-org Shipit deployment without a configured secret becomes a skeleton key: an attacker sets `repository.owner.login` to that unsecured org (satisfying `verify_signature`) and `repository.full_name` to any other tracked, secret-protected repository (satisfying the handler's lookup), fully bypassing the HMAC check for that repository.

### Impact Explanation
This breaks the deployment-trust binding "an organization that authenticated versus the repository that is written," matching the analog class explicitly permitted by the rules. Concrete consequences depend on which handler is invoked with the forged event:
- `PushHandler` calls `stack.sync_github(expected_head_sha:)` for a victim stack the attacker never had signature-verified access to, forcing an unscheduled/forced resync and, on stacks with `continuous_deployment` enabled, an unauthorized deploy trigger for whatever commit is at the head of the tracked branch.
- Pull-request handlers can archive, unarchive, or deprovision `ReviewStack`s belonging to a fully secret-protected repository, purely by forging the `repository.owner.login`/`repository.full_name` mismatch.

This maps to the "unauthorized deploy, rollback" and repository-authorization escalation impact tiers defined in scope.

### Likelihood Explanation
Requires only that the Shipit deployment be configured to track more than one GitHub organization and that at least one of those organizations has no `webhook_secret` set (an explicitly supported, non-default configuration per `docs/setup.md`). No credentials, tokens, or repository write access are needed — the attacker only needs to know the `full_name` of the target repository, which is public information for public repos. This is a config-dependent but code-level design flaw, not a misuse of the engine's documented mounting.

### Recommendation
Cross-validate that `repository.full_name`'s owner segment matches the `repository.owner.login`/`organization.login` used to select and verify the webhook signature before any handler resolves or mutates state from the payload. Additionally, treat a blank `webhook_secret` for a registered organization as a configuration error rather than an implicit "always verified" pass-through, and require at minimum that `full_name` be scoped/pinned to the org whose secret matched.

### Proof of Concept
1. Configure (as an operator) Shipit to track two orgs: `org-unsecured` (no `webhook_secret`) and `org-victim` (has `webhook_secret` and an active continuous-deployment stack tracking `main`).
2. As an unauthenticated external attacker, POST to `/webhooks`:
```
X-Github-Event: push
{
  "ref": "refs/heads/main",
  "after": "<any known head sha of org-victim/repo>",
  "repository": {
    "owner": { "login": "org-unsecured" },
    "full_name": "org-victim/repo"
  }
}
```
3. `verify_signature` resolves `repository_owner` = `org-unsecured`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally (no `X-Hub-Signature` header even required). [3](#0-2) 
4. `PushHandler#process` then resolves `stacks` via `repository_name` = `payload.dig('repository','full_name')` = `"org-victim/repo"`, finding and syncing the real, secret-protected `org-victim` stack. [5](#0-4) [6](#0-5)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
