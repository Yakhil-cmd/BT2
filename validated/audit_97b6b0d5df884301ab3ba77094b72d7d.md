### Title
Signature verifier selected by `repository_owner` fallback is decoupled from the repository/stack actually mutated via `params.repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` picks the `GitHubApp` (and thus the secret) used to authenticate a webhook using `repository_owner`, which falls back to `params.dig('organization', 'login')` when `repository.owner.login` is absent. Every downstream handler, however, resolves the actual repository/stack from an independent field, `params.repository.full_name` (e.g. `LabelCapturingHandler#repository`). In a multi-organization Shipit deployment, these two fields are never checked for consistency, so a webhook can be "authenticated" against one (weakly-configured) organization while mutating a stack that belongs to a completely different one.

### Finding Description
The broken binding: the code implicitly assumes
`repository_owner (used to pick the verifying secret) == owner_of(params.repository.full_name) (the repo/stack actually mutated)`,
but nothing in the code enforces this equality.

- `repository_owner` is computed purely from attacker-supplied JSON: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) , and is used to select the app: `github_app = Shipit.github(organization: repository_owner)` [2](#0-1) .
- In multi-org configs, `Shipit.github_app_config(organization)` looks up the org (case-insensitively) in `secrets.github`, and if that org's `webhook_secret` is blank, `GitHubApp#verify_webhook_signature` returns `true` unconditionally: `return true unless webhook_secret` [3](#0-2) . The example/dummy multi-org configs in this repo explicitly leave `webhook_secret` unset for each org (`webhook_secret: # nil`) [4](#0-3) , so this is not a hypothetical misconfiguration — it is the documented default shape for multi-org setups.
- After signature "verification" passes (trivially, because the selected org has no secret), `LabelCapturingHandler` resolves the target repository purely from `params.repository.full_name`, completely independent of `repository_owner`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .
- For a `pull_request`/`labeled` event, the handler persists attacker-controlled label names onto the review stack's `PullRequest`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [6](#0-5) .
- `ReviewStack#env` later uppercases every stored label and injects it as an environment variable merged into the deploy/task environment: `labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` [7](#0-6) .

Exploit flow: the attacker crafts a raw JSON body (no valid GitHub signature required) with:
- `organization.login` = the name of some org configured in the target Shipit's `secrets.github` that has no `webhook_secret` set (and no `repository.owner.login` field, so the controller falls back to `organization.login`),
- `repository.full_name` = `"victim-org/victim-repo"` (the actual review-stacks-enabled, allow_all stack the attacker wants to hit),
- `pull_request.labels` containing attacker-chosen names that will become environment variable keys, and `action: "labeled"`.

`verify_signature` looks up the `GitHubApp` for `organization.login`, finds no `webhook_secret`, and accepts the request unconditionally regardless of the `X-Hub-Signature` header content [3](#0-2) . `LabelCapturingHandler` then locates and mutates the stack belonging to `victim-org/victim-repo` — an organization completely unrelated to the one whose (non-existent) secret "authenticated" the request.

Existing guards do not close this gap: `drop_unhandled_event` and `check_if_ping` only filter by event type [8](#0-7) ; `verify_signature` never cross-checks `repository_owner` against `repository.full_name`'s owner; `GithubOrganizationUnknown` only fires if the org name isn't configured at all, not if it lacks a secret [9](#0-8) ; the `ExplicitParameters` schema for `LabelCapturingHandler` only requires `repository.full_name` to be a `String`, with no validation tying it to the authenticating org [10](#0-9) .

### Impact Explanation
This is a cross-tenant payload-for-one-repository-mutates-another's-stack vulnerability: an attacker who controls (or merely knows the name of) any organization configured in a shared, multi-org Shipit instance that lacks a `webhook_secret` can forge webhooks that mutate arbitrary *other* organizations' stacks. Chained through `LabelCapturingHandler` and `ReviewStack#env`, attacker-chosen label strings become arbitrary-named environment variables merged into `shipit.yml` task/deploy execution for auto-provisioned review stacks (`review_stacks_enabled: true`, `allow_all`), which is a path toward command/environment injection during deploy execution on the deploy host. This matches "a payload for one repository mutating another's stack" and, depending on downstream `shipit.yml` usage of injected env vars, can escalate to command execution — Critical severity.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured with **multiple** GitHub organizations (`secrets.github` keyed by org name) and at least one configured org must have a blank/unset `webhook_secret` — a configuration shown as the default/example shape in this repo's own multi-org config templates. The attacker needs no credentials, session, or API token — only knowledge of one configured-but-secretless org name and the victim's `owner/repo` full name, both of which are typically public. This is repeatable per request against any repository/stack reachable via `Shipit::Repository.from_github_repo_name`, with no rate limiting on this path noted. Likelihood is high in any multi-org deployment following the documented example config, and zero in single-org deployments (where `config = secrets.github` is used regardless of the `organization` parameter, per `Shipit.github`) [9](#0-8) .

### Recommendation
Enforce that the organization used to select the signing secret matches the owner of `repository.full_name` (or `organization.login`) actually being mutated — e.g., derive `repository_owner` strictly from `repository.full_name`'s owner segment (not from the separate `organization.login` fallback), and reject requests where `repository.owner.login` disagrees with the owner parsed from `repository.full_name`. Additionally, treat a configured org with a blank `webhook_secret` as a hard misconfiguration (refuse to boot / reject webhooks) in multi-org mode rather than silently returning `true` from `verify_webhook_signature`.

```ruby
# test/controllers/webhooks_controller_test.rb (conceptual, minitest, no live GitHub)
test "labeled event authenticated via a secretless org mutates a different org's review stack" do
  # Multi-org secrets: OrgAttacker has no webhook_secret; OrgVictim owns the target stack.
  Shipit.stubs(:secrets).returns(OpenStruct.new(github: {
    "orgattacker" => { app_id: 1, installation_id: 1, webhook_secret: nil, private_key: TEST_KEY },
    "orgvictim"   => { app_id: 2, installation_id: 2, webhook_secret: "real-secret", private_key: TEST_KEY }
  }))

  victim_repo = shipit_repositories(:shipit) # full_name "orgvictim/victim-repo", review_stacks_enabled: true, allow_all
  review_stack = Shipit::ReviewStack.create!(repository: victim_repo, environment: "pr99", branch: "feature")
  pr = review_stack.create_pull_request!(github_pull_request: { ... })

  body = {
    action: "labeled",
    number: 99,
    pull_request: { id: 1, number: 99, url: "u", title: "t", state: "open",
                     additions: 1, deletions: 1,
                     head: { sha: "abc", ref: "feature" },
                     user: { login: "attacker" },
                     assignees: [],
                     labels: [{ name: "INJECTED_ENV_VAR" }] },
    repository: { full_name: "orgvictim/victim-repo" }, # NOTE: no "owner" key
    organization: { login: "orgattacker" },              # forces repository_owner fallback
    sender: { login: "attacker" }
  }.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary/invalid, irrelevant

  post :create, body:, as: :json
  assert_response :ok

  # Equality check: repository_owner (verifier) != owner of repository.full_name (mutated stack)
  assert_equal "orgattacker", JSON.parse(body).dig("organization", "login")
  assert_equal "orgvictim", review_stack.repository.owner # mismatched

  # Yet the victim's stack was mutated:
  assert_equal ["INJECTED_ENV_VAR"], pr.reload.labels
  assert_equal "true", review_stack.reload.env["INJECTED_ENV_VAR"]
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
