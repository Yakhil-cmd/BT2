### Title
Caller-supplied swap route places attacker code inside the user's signed authorization tree, enabling wallet-wide token theft - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply` accept an opaque `swap: Bytes` route from the caller and pass it to the configured router. The router invokes whatever pool/token addresses the payload names with no allowlist, so a crafted route can run attacker-deployed code underneath the victim's `require_auth` entry. Any `token.transfer(victim, attacker, amount)` that code makes is recorded as a child of the victim's authorization and executes once the victim signs the simulated tree — the Soroban equivalent of the CVE's "crafted file that runs attacker code under the user's privilege."

### Finding Description
In `swap_tokens` the controller authorizes only its own exact input transfer (`authorize_transfer_as_current`) and then calls `router.execute_strategy(&controller, &amount_in, swap)` where `swap` is fully caller-controlled bytes [1](#0-0) . The account owner's `require_auth` happens at the strategy entrypoint (e.g. `require_authorized_caller` + `require_owner_or_delegate` in `process_swap_collateral`) [2](#0-1) , so everything the route does rides under that single signed entry.

The router executes payload-named addresses as venues; the threat model explicitly confirms there is no pool/token allowlist and that a transfer the rogue hop makes "from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree" [3](#0-2) . The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves it end-to-end: a `RogueHopPool` named by the route transfers `WALLET_BALANCE` of an unrelated token from Alice to the attacker, and the recorded auth tree shows the stolen transfer nested under Alice's `swap_collateral` entry [4](#0-3) . The swap still returns a fair output and the position stays solvent, so no protocol check fires [5](#0-4) .

### Impact Explanation
Theft of user funds: the entire wallet balance of any token the victim holds (not just the swapped amount) can be drained through a signed auth tree, bounded by nothing the controller or router enforces.

### Likelihood Explanation
Medium. Requires social-engineering a victim into signing a transaction whose simulated auth tree contains the extra child — exactly the CVE's user-interaction prerequisite — and a client that does not decode and reject unexpected children. An unprivileged attacker needs only to deploy a contract and craft route bytes; no privileged role, oracle manipulation, or MEV is involved. The documentation itself prescribes client-side auth-tree inspection as the only mitigation, meaning the protocol relies on every client enforcing a policy the contracts do not.

### Recommendation
Enforce policy on-chain rather than in the client: give the router a governance-managed venue/pool allowlist (or restrict hop `pool`/`token` addresses to known DEX contracts) so arbitrary code cannot be scheduled under the caller's auth. Short of that, the controller could at minimum document/enforce that strategy callers use a wallet that decodes `swap` bytes and refuses auth trees with children other than the single input transfer.

### Proof of Concept
See `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`: `Scene::route_through_pool_stealing` builds a `RoutedSwap` naming an attacker `RogueHopPool` whose `swap()` calls `token.transfer(alice, attacker, WALLET_BALANCE)`; calling `controller.swap_collateral(alice, account_id, USDC, 5000e7, ETH, route)` under recording-mode auth produces a poisoned tree containing the stolen transfer and moves `77_770_000_000` units from Alice's wallet to the attacker while the position ends solvent [6](#0-5) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
