### Title
Accrual panic on RAY value overflow permanently freezes a whole market — no repay, withdraw, or liquidation possible - (File: contracts/pool/src/cache/scale.rs)

### Summary
CVE-2019-2780 is a "repeatable crash → complete denial of service" class. The in-scope analog is the pool's share↔asset unscaling path: when `scaled_to_original` overflows the finite `i128`/`RAY` value capacity during interest accrual, the pool panics with `MATH_OVERFLOW`. Because every controller verb accrues the market first, one oversize book at sustained high utilization freezes all repayments, withdrawals, liquidations, and `update_indexes` permanently — the borrow-index cap (`MAX_BORROW_INDEX_RAY`) never engages because the value overflow trips first.

### Finding Description
`Cache` holds market totals as `Ray` scaled shares (`supplied`, `borrowed`, `revenue`, `borrow_index`, `supply_index`) in `contracts/pool/src/cache/mod.rs:36-40`. [1](#0-0)  Accrual and every utilization/valuation read unscales these by the live index via `scaled_to_original` and `unscale_borrow_ceil`/`unscale_supply` in `contracts/pool/src/cache/scale.rs:23-26,69-92`. [2](#0-1)  Those helpers multiply a scaled share count by a RAY index; when the product of share count × index exceeds `i128` capacity, the multiply panics (`MATH_OVERFLOW`). The repo's own threat model acknowledges that "finite RAY value capacity can be exhausted before the index ceiling" and that "synchronizing an overlarge book can then fail before an otherwise risk-reducing operation". [3](#0-2)  The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates reachability through only unprivileged entrypoints: `supply`, `borrow`, then repeated `update_indexes` until accrual panics, after which `withdraw` and `repay` both revert with `MATH_OVERFLOW` — "the market is frozen: no repay, no withdraw, no liquidation". [4](#0-3) 

An attacker with sufficient capital accelerates this: supply a very large principal into a high-decimals market, borrow most of it back (driving utilization onto the steep part of the rate curve), and let (or periodically nudge via `update_indexes`) the borrow index compound until the next unscaling overflows. Neither an upgrade-free recourse nor a partial-exit path exists, since cleanup (`clean_bad_debt`) and `recapitalize` also touch the same market accrual path.

### Impact Explanation
Permanent freezing of funds for every participant of that market: supplier principal and accrued yield are unwithdrawable, borrower debt cannot be repaid, liquidations cannot execute, and `update_indexes` itself reverts — the market is bricked at the contract level, matching "permanent freezing of funds" / "complete DOS" of the vulnerability class.

### Likelihood Explanation
Reachable by a single unprivileged address via `supply`/`borrow`/`update_indexes`, but requires a very large token position (the test uses ~10⁹ × 10¹⁸ units) and sustained high utilization over a long accrual horizon, or a token/curve combination where RAY share count × index hits `i128` capacity sooner. Caps and utilization limits can be lifted only for the attacker's own leg, so the barrier is capital and accrual time, not privilege — consistent with a Medium rating.

### Recommendation
- Make accrual and unscaling saturating rather than panicking: cap `borrowed`/`supplied` value growth at the representable bound and clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` *before* the `scaled_to_original` multiply that can overflow, so the index cap (which exists but currently engages too late) actually fires.
- Alternatively, unwind accrual to a checkpoint on overflow (commit `last_timestamp` progress up to the last safe chunk) so verbs remain usable.
- Add a supply-side guard: reject `supply`/`borrow` amounts that would push `scaled × index` beyond a documented fraction of `i128::MAX`, enforcing the bound in `docs/reference/formulas.md#numeric-limits` at write time rather than discovering it at accrual time.

### Proof of Concept
Reproduced by the existing harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: create a market with an 18-decimal asset on the XLM rate curve and `with_max_utilization_disabled_all_markets`, `supply` ~`1e9 × 1e18` units from one account, `borrow` ~98% of it from a second account with collateral, advance ledger time in yearly steps calling `update_indexes` until it errors with `MATH_OVERFLOW`; afterwards `try_withdraw` and `try_repay` both fail with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, confirming the market is frozen before the index cap could engage. /// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
```rust
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
