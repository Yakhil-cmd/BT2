### Title
Webhook signature verification fails open when `webhook_secret` is unset, allowing unsigned webhooks to forge `membership` events and grant team authorization - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` with no HMAC check whenever `webhook_secret` is blank, and this is the default value shipped in every scaffolded config (`template.rb`, `config/secrets.development.example.yml`). Any attacker can then POST an unsigned `membership` webhook to `/webhooks` and cause `MembershipHandler#process` to add an arbitrary login to a `Shipit.github_teams` team, escalating that account to `User#authorized?`.

### Finding Description
The broken binding: `verified == true` in `WebhooksController#verify_signature` should require `HMAC(webhook_secret, raw_post) == X-Hub-Signature`, but when `webhook_secret` is nil/blank, `verify_webhook_signature` short-circuits with `return true unless webhook_secret`, making `verified` unconditionally `true`. [1](#0-0) 

`WebhooksController#verify_signature` passes whatever `X-Hub-Signature` header is present (or absent) straight through, without ever checking that `webhook_secret` itself is configured: [2](#0-1) 

With `verified == true`, `create` dispatches the raw JSON body directly to `MembershipHandler#process`: [3](#0-2) 

The handler finds/creates the team by the attacker-supplied `team.id`, finds/creates the attacker-controlled `member.login`, and adds the member on `action: 'added'`: [4](#0-3) 

This directly feeds `User#authorized?`, which grants access based purely on team membership: [5](#0-4) 

Crucially, `webhook_secret` is not a rare misconfiguration — it is the **generated default** in the official scaffold produced by `template.rb` (used when bootstrapping a new Shipit install) and in the documented example config: [6](#0-5) [7](#0-6) 

The setup docs describe the webhook secret itself as "(optional)" during GitHub App creation and never warn that omitting it disables webhook authentication entirely: [8](#0-7) 

No other guard intervenes: `drop_unhandled_event` only screens by event name (membership has a registered handler), and `ExplicitParameters` (`MembershipHandler.params`) only validates the JSON shape, not its authenticity.

### Impact Explanation
An attacker who sends a single unsigned HTTP POST to `/webhooks` with `X-Github-Event: membership` can add any GitHub login (including one they control) as a member of any `Team` already referenced in `Shipit.github_teams` (identified purely by numeric `team.id`, which is guessable/enumerable or discoverable via other org exposure). This flips `User#authorized?` to `true` for that login, unlocking session-based access to the entire Shipit host — stacks, deploys, rollbacks, and merges — for every organization configured without a `webhook_secret`. This is repeatable per attacker-chosen login and is not scoped to a single repository; it compromises the whole tenant's authorization boundary. This matches "escalation into `Shipit.github_teams` authorization" (High) and, once the attacker subsequently authenticates as that login via OAuth and passes `force_github_authentication`, effectively becomes a full authentication/authorization bypass (Critical) for the deploy host.

### Likelihood Explanation
The only precondition is that the target organization's `webhook_secret` is blank — which is the out-of-the-box state generated by `template.rb` and shown in the official example secrets file. An operator must explicitly set a webhook secret to be protected; nothing in the code enforces or defaults to a secret. The attacker needs no credentials, tokens, or GitHub App access — just the ability to send an HTTP POST to the public `/webhooks` endpoint with a crafted JSON body and correct `X-Github-Event` header. This is trivially repeatable and requires no interaction with GitHub itself.

### Recommendation
Fail closed instead of open: reject webhook requests (`head(422)`) whenever `webhook_secret` is not configured for the target organization, or require operators to configure a webhook secret as mandatory (raise at boot / `Shipit.github` initialization) rather than silently treating it as optional. Additionally, update `template.rb` and documentation to generate/require a random `webhook_secret` by default, and add a startup check that warns/fails if any configured GitHub org lacks one.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`), targeting the existing `verify_signature` and `MembershipHandler` path, using the dummy app's default config which has `webhook_secret: # nil` (`test/dummy/config/secrets.yml`):

```ruby
test "membership webhook is accepted without any signature when webhook_secret is blank" do
  refute Shipit.github(organization: 'shopify').send(:webhook_secret) # left-hand side: webhook_secret is blank

  request.headers['X-Github-Event'] = 'membership'
  request.headers.delete('X-Hub-Signature') # no HMAC at all

  attacker_login = 'attacker'
  team = shipit_teams(:shopify_developers)
  Shipit.stubs(:github_teams).returns([team])

  body = {
    action: 'added',
    team: { id: team.github_id, name: team.name, slug: team.slug, url: team.api_url },
    organization: { login: 'shopify' },
    member: { login: attacker_login }
  }.merge(repository: { owner: { login: 'shopify' } }).to_json

  Shipit.github.api.expects(:user).with(attacker_login).returns(
    stub(id: 999, name: 'Attacker', login: attacker_login, email: 'a@example.com',
         avatar_url: 'https://example.com/a.png', url: 'https://api.github.com/user/attacker')
  )

  assert_difference -> { Membership.count }, 1 do
    post :create, body:, as: :json
    assert_response :ok # right-hand side: request accepted despite verified == true with no real HMAC check
  end

  user = User.find_by(login: attacker_login)
  assert_predicate user, :authorized? # equality broken: attacker gains Shipit.github_teams authorization
end
```

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
