### Title
Skill `Description` frontmatter is rendered to the terminal picker/listing without ANSI/control-sequence sanitization, enabling terminal-spoofing during `gh skill install` - (File: pkg/cmd/skills/install/install.go)

### Summary
`skillSearchFunc` and `listAvailableSkills` in `pkg/cmd/skills/install/install.go` print `discovery.Skill.Description` (and `DisplayName()`) directly into the interactive `MultiSelectWithSearch` labels and the `tableprinter` output, without ever routing the value through the repo's `iostreams.Untrusted` sanitization pipeline. Since `Description` comes straight from attacker-authored `SKILL.md` frontmatter with no character-class restriction (unlike `Skill.Name`, which is constrained by `safeNamePattern`/`specNamePattern`), a malicious skill author can embed ANSI/terminal control sequences to visually manipulate what the victim sees in the picker.

### Finding Description
`discovery.Skill` is defined with `Name`, `Namespace`, and `Description` as plain `string` fields [1](#0-0) . `Name` is constrained by `safeNamePattern`/`specNamePattern` regexes that only allow `[a-zA-Z0-9._- ]` [2](#0-1) , so `DisplayName()` cannot itself carry raw escape bytes. However, `Description` is populated from the SKILL.md frontmatter body (fetched via `FetchDescriptionsConcurrent`) with no equivalent character-class validation.

Both consumer paths in `install.go` print `Description` unsanitized:
- `skillSearchFunc`, used to build the labels shown by `opts.Prompter.MultiSelectWithSearch` in the interactive picker, formats `label = fmt.Sprintf("%s - %s", label, text.RemoveExcessiveWhitespace(s.Description))` and only truncates by width — `text.RemoveExcessiveWhitespace`/`text.Truncate` do not strip ANSI escape sequences [3](#0-2) .
- `listAvailableSkills`, used for the non-interactive `--all`/no-TTY table output, writes `s.Description` (optionally truncated) straight into `table.AddField(desc)` [4](#0-3) .

The codebase has an established mitigation for exactly this class of issue: `iostreams.Untrusted`, whose `String()` method runs content through `asciisanitizer.Sanitizer` to neutralize ANSI escape sequences before any `fmt` print path renders it, specifically because it is meant for "HTTP response bodies, file contents fetched from a remote, anything the CLI did not author" [5](#0-4) . Neither `discovery.Skill.Description` nor `DisplayName()` are wrapped in `Untrusted`, and no call site in `pkg/cmd/skills/install/install.go` applies `asciisanitizer`/`stripControl` before printing. This is confirmed by the absence of any `Untrusted`/sanitizer usage anywhere in `pkg/cmd/skills/**` in the search results, even though the sanitizer machinery exists and is used elsewhere in the CLI (e.g., `pkg/cmd/run/view/logs.go`, `pkg/cmd/gist/view/view.go`).

Exploit flow: an unprivileged attacker publishes a repo/skill whose `SKILL.md` frontmatter `description` contains control sequences (e.g. `\x1b[8m` conceal, or cursor-repositioning/overwrite sequences). A victim runs `gh skill install <attacker-repo>` without specifying an exact skill name, triggering `discoverSkills` → `selectSkillsWithSelector` → `opts.Prompter.MultiSelectWithSearch` (interactive) or `listAvailableSkills` (non-interactive/no-TTY) [6](#0-5) . The malicious escape sequence can conceal/rewrite adjacent text in the same terminal line/row (e.g., hiding a suffix, overwriting a sibling skill's label, or making a benign-looking entry appear selected/highlighted), causing the victim to pick a different skill entry than what visually appears intended.

### Impact Explanation
This is an output-safety / terminal-injection issue that produces social confusion in the skill picker — the victim can be misled into selecting and installing an attacker-favored skill (arbitrary file write to the install directory of attacker-chosen skill content) rather than the one they believe they are choosing. This matches GitHub's "terminal escape sequence / spoofing" bounty class rather than direct RCE; actual code execution would still require the victim to separately execute or load the installed skill content, but the entry point of "trick the user's selection in the CLI UI" is a real, reachable defect distinct from the existing pre-install disclaimer (`printPreInstallDisclaimer`) that only warns about content, not about UI-spoofed selection.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: publish any public GitHub repo containing a `SKILL.md` with a description field containing escape sequences, and have the victim run `gh skill install <owner/repo>` without an exact skill name (a common, documented usage pattern shown in the codebase's own tests, e.g. `Test_selectSkillsWithSelector_noDisclaimer`) [7](#0-6) . No auth, no MITM, no social engineering beyond publishing content is required, and the bug is deterministically reproducible.

### Recommendation
Wrap `discovery.Skill.Description` (and any other frontmatter-derived free-text field, e.g. future long-form skill metadata) in `iostreams.Untrusted` at the point it is parsed/fetched, and use `.String()` (which runs `asciisanitizer.Sanitizer`) wherever it is rendered to a terminal — specifically in `skillSearchFunc`'s label construction and `listAvailableSkills`'s `table.AddField(desc)` in `pkg/cmd/skills/install/install.go`, mirroring the pattern already used for other untrusted external content in the CLI (and, per file name matches, apparently already partially applied in `pkg/cmd/skills/list/list.go`).

```go
func Test_skillSearchFunc_sanitizesDescription(t *testing.T) {
    skills := []discovery.Skill{
        {Name: "safe-skill", Description: "A useful skill"},
        {Name: "evil-skill", Description: "Helpful\x1b[8m HIDDEN-PAYLOAD\x1b[0m"},
    }
    search := skillSearchFunc(skills, 80)
    result := search("")
    for _, label := range result.Labels {
        assert.NotContains(t, label, "\x1b[8m", "label must not contain raw ANSI escape sequences")
    }
}

func Test_listAvailableSkills_sanitizesDescription(t *testing.T) {
    ios, _, stdout, _ := iostreams.Test()
    ios.SetStdoutTTY(false)
    opts := &InstallOptions{IO: ios}
    skills := []discovery.Skill{
        {Name: "evil-skill", Description: "Legit\x1b[8mHIDDEN\x1b[0m"},
    }
    err := listAvailableSkills(opts, skills, skillSelector{sourceHint: "owner/repo"})
    require.NoError(t, err)
    assert.NotContains(t, stdout.String(), "\x1b[8m")
}
```
Expected (current, failing) behavior: both assertions fail because the raw `\x1b[8m` sequence passes through unmodified, confirming the lack of sanitization in the rendered picker/list output.

```go
// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```
