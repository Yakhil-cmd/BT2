### Title
Unbounded `reward.mintingamount` Governance Parameter Enables Unlimited KAIA Minting Per Block - (`File: kaiax/gov/param.go`)

### Summary

The `reward.mintingamount` governance parameter has no upper-bound validation anywhere in the vote acceptance, header verification, or consistency-check pipeline. A governing node (in `"single"` mode) or a GovParam contract owner (post-Kore) can vote to set `MintingAmount` to an arbitrarily large `*big.Int` value. Once the epoch boundary passes and the parameter takes effect, every subsequent block's `FinalizeState` mints that unbounded amount of KAIA into validator and fund addresses via `state.AddBalance`, permanently corrupting the total supply and all account balances.

### Finding Description

**Root cause — `noopFormatChecker` on `RewardMintingAmount`:**

The `Params` registry in `kaiax/gov/param.go` defines every governance parameter's canonicalizer and format-checker. For `RewardMintingAmount`, the format-checker is the literal no-op:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // ← always returns true
    ...
},
``` [1](#0-0) 

`noopFormatChecker` is defined as:
```go
func noopFormatChecker(cv any) bool {
    return true
}
``` [2](#0-1) 

Any `*big.Int` value — including `new(big.Int).Lsh(big.NewInt(1), 255)` — passes this check.

**No consistency check either:**

`checkConsistency` in the header-governance verifier explicitly lists `RewardMintingAmount` in the "no additional checks" branch:

```go
case gov.GovernanceDeriveShaImpl, gov.GovernanceGovParamContract, gov.GovernanceGovernanceMode, gov.GovernanceUnitPrice,
    gov.IstanbulCommitteeSize, gov.IstanbulEpoch, gov.IstanbulPolicy,
    gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    gov.RewardDeferredTxFee, gov.RewardKip82Ratio, gov.RewardMintingAmount, ...
    return nil
``` [3](#0-2) 

**State-write path — `FinalizeState` mints the full amount every block:**

`RewardModule.FinalizeState` calls `GetDeferredReward`, which reads `MintingAmount` directly from the governance parameter set, then calls `state.AddBalance` for every reward recipient:

```go
spec, err := r.GetDeferredReward(header, txs, receipts)
...
for addr, amount := range spec.Rewards {
    state.AddBalance(addr, amount)
}
``` [4](#0-3) 

`NewRewardConfig` copies the raw `MintingAmount` from the param set without any cap:

```go
rc.MintingAmount = new(big.Int).Set(paramset.MintingAmount)
``` [5](#0-4) 

**Contrast with parameters that do have bounds:**

`IstanbulCommitteeSize` rejects zero (`v > 0`), `GovernanceDeriveShaImpl` rejects values above 2, `IstanbulPolicy` rejects values above 2, and `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` have a cross-parameter consistency check. `RewardMintingAmount` has none of these protections. [6](#0-5) 

### Impact Explanation

Setting `reward.mintingamount` to `2^255` causes every block's `FinalizeState` to call `state.AddBalance(proposerAddr, 2^255 * ratio)` and similarly for fund addresses. This:

1. **Mints an unbounded amount of KAIA** into validator and fund addresses every block — a direct unauthorized token creation affecting system-managed funds.
2. **Corrupts the state root** — the resulting `header.Root` diverges from what honest nodes that have not applied the parameter would compute, causing a consensus split.
3. **Is irreversible for already-finalized blocks** — even if a subsequent governance vote corrects the parameter, all blocks minted under the bad value have already altered the canonical state.

### Likelihood Explanation

The trigger requires a governance vote to succeed. In `"single"` governance mode (used on Kaia Mainnet), the governing node alone can cast the decisive vote. In `"none"` mode (post-Kore, via GovParam contract), the contract owner can call `setParam` directly. The likelihood is low because acting against economic self-interest is irrational, but the code provides zero protection against accidental misconfiguration (e.g., off-by-one in units: setting `9600000000000000000000000000` instead of `9600000000000000000`) or a compromised key. The external report's judge accepted exactly this reasoning at Medium severity. [7](#0-6) 

### Recommendation

Add a reasonable upper-bound check to the `FormatChecker` for `RewardMintingAmount`. For example, cap it at `1e27` wei (1 billion KAIA per block, far above any realistic inflation):

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok {
            return false
        }
        // Must be non-negative and below a sane maximum (e.g., 1e27 wei = 1e9 KAIA)
        maxMinting, _ := new(big.Int).SetString("1000000000000000000000000000", 10)
        return v.Sign() >= 0 && v.Cmp(maxMinting) <= 0
    },
    ...
},
```

Apply the same check in the `GovParam` contract's byte-decoding path (`ParseContractCall` → `PartialParamSet.Add`) so that contract governance cannot bypass the limit either. [8](#0-7) 

### Proof of Concept

1. Chain is running in `"single"` governance mode with governing node `GN`.
2. `GN` submits a header vote: `("reward.mintingamount", "57896044618658097711785492504343953926634992332820282019728792003956564819968")` (i.e., `2^255`).
3. `NewVoteData` canonicalizes the string to `*big.Int` via `bigIntCanonicalizer` and calls `noopFormatChecker` → passes.
4. `VerifyVote` calls `checkConsistency` → hits the `RewardMintingAmount` case → `return nil`.
5. At the next epoch boundary, the vote is tallied and `header.Governance` encodes the new parameter.
6. `GetParamSet` for all subsequent blocks returns `MintingAmount = 2^255`.
7. `FinalizeState` → `GetDeferredReward` → computes `spec.Rewards` with `MintingAmount = 2^255` → `state.AddBalance(proposerAddr, ~2^255 * 0.34)` (at 34% GC ratio).
8. Every block permanently mints ~`1.95 × 10^76` KAIA into the proposer address, corrupting the total supply and state root. [1](#0-0) [3](#0-2) [4](#0-3)

func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
	case gov.Kip71LowerBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) > params.UpperBoundBaseFee {
			return ErrLowerBoundBaseFee
		} else {
			return nil
		}
	case gov.Kip71UpperBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) < params.LowerBoundBaseFee {
			return ErrUpperBoundBaseFee

			return nil
		}

			return ErrGovNodeInValSetVoteValue
