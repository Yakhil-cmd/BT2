### Title
Cross-organization webhook secret confusion lets an unprivileged sender forge push/status events for repositories outside the organization whose secret validated the request - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to validate a request against using one payload field (`repository.owner.login`), while every event handler afterwards resolves the repository/stack to act on using a *different* payload field (`repository.full_name`). Because both fields live in the same attacker-suppliable JSON body, an attacker who can get a signature to validate for *any* configured organization (most simply, one that has no `webhook_secret` configured at all, which is explicitly documented as optional) can point `repository.full_name` at a completely different organization's repository and have Shipit process the event as if it legitimately came from GitHub for that other repository.

### Finding Description
The equality this endpoint should preserve is:

`organization whose secret validated the signature == organization that owns the repository the handlers act on`

`verify_signature` computes the signing organization from the payload itself, before any cryptographic guarantee exists about the payload's authenticity:

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

`Shipit.github(organization:)` looks up a per-organization config block (multi-org support is a documented, supported deployment mode) and instantiates a `GitHubApp` scoped to that org's `webhook_secret`: [2](#0-1) 

`verify_webhook_signature` explicitly no-ops when that organization has no secret configured:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

`docs/setup.md` documents the webhook secret as **optional** per app/organization, and documents the multi-org configuration format where each organization has its own independent `webhook_secret`: [4](#0-3) 

Once `verify_signature` passes (either because it validated against a real but wrong org's secret, or trivially because that org has no secret set), the raw JSON body is dispatched to handlers unmodified. Every handler resolves the target repository/stack from an entirely different field, `repository.full_name`, not from `repository.owner.login`:

```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [5](#0-4) 

`PushHandler`, for example, uses this to enqueue a real `GithubSyncJob` for whatever stack matches `repository.full_name`: [6](#0-5) 

Nothing in the controller or in `Handler` cross-checks that `repository.owner.login` (used to pick the signing secret) matches the owner embedded in `repository.full_name` (used to pick the acted-upon repository). An attacker only needs the request to validate against *some* configured organization's app (trivial if that organization simply never set a `webhook_secret`, which the docs treat as an optional field) and can then freely set `repository.full_name` to `victim-org/victim-repo` in the same JSON body.

### Impact Explanation
This breaks the "organization authenticated versus repository written" binding explicitly called out as a valid analog class: the app performs authenticated-looking, real actions (queuing `GithubSyncJob`, updating `Commit`/`Status` records, driving merge-queue/CI-status handlers) against a stack belonging to an organization that never authenticated the request. If the targeted stack has `continuous_deployment` enabled, a forged push/status event can drive `Stack.schedule_continuous_delivery` into deploying newly-synced (real, but attacker-timed) commits, i.e. an unauthorized deploy triggered without any credential belonging to the victim organization. This matches the "Critical: an unauthorized deploy" impact bucket.

### Likelihood Explanation
The only precondition is that the Shipit deployment (a documented, supported configuration) manages multiple GitHub organizations and at least one of them has not set a `webhook_secret` (documented as optional). No repository write access, no `ApiClient` token, no `webhook_secret`, and no privileged account are required by the attacker — they only need to know the name of one such lightly-configured organization and POST a crafted JSON body directly to `/webhooks`, which is a public, unauthenticated endpoint by design.

### Recommendation
After signature verification succeeds, re-derive the organization implied by the field(s) the handler will actually use (`repository.full_name`, or `organization.login` for org-level events) and reject the request (422) unless it matches the organization whose secret validated the signature. Alternatively, verify the signature using the secret of the organization that owns the *acted-upon* repository (resolved the same way handlers resolve it), not a separately-parsed `repository.owner.login` field, and disallow silent bypass (`return true unless webhook_secret`) for multi-org configurations where any inconsistency between "authenticating org" and "acted-upon org" could occur.

### Proof of Concept
1. Configure Shipit (as documented) with multiple GitHub organizations, e.g. `victim-org` (has a `webhook_secret`) and `empty-org` (installed but left `webhook_secret` blank, per the "optional" docs).
2. An unauthenticated attacker POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<any sha>",
  "repository": {
    "owner": { "login": "empty-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. `verify_signature` looks up `Shipit.github(organization: "empty-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally, regardless of the (even absent) `X-Hub-Signature` header.
4. `PushHandler#process` resolves `stacks` via `repository.full_name` = `victim-org/victim-repo`, and enqueues a real `GithubSyncJob` for `victim-org`'s stack, potentially triggering continuous deployment — despite the attacker never having presented any credential associated with `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
