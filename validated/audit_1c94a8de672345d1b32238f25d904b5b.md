### Title
Forged membership webhook lets an attacker fabricate the `Team` row later returned by `Shipit.github_teams` (organization/slug trust, no GitHub cross-check) - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`MembershipHandler#find_or_create_team!` trusts the attacker-controlled `team.id`, `team.slug`, and `organization.login` fields from the webhook payload with no verification against GitHub, and `Team.find_or_create_by_handle` (used to build `Shipit.github_teams`) resolves a team purely by matching `organization`+`slug` string columns rather than the authoritative GitHub team id. If a forged `membership` webhook is accepted (only possible when the targeted organization's GitHub App has no `webhook_secret` configured, per `GitHubApp#verify_webhook_signature`) and it wins the race to be the *first* row ever created for that `(organization, slug)` pair, that fabricated `Team` becomes the entry `Shipit.github_teams` returns for that handle for the process's lifetime, and the attacker's own forged membership on it satisfies `User#authorized?`.

### Finding Description
The broken binding: `Team.find_or_create_by_handle('real-org/eng').github_id == <the github_id GitHub actually assigned to real-org's "eng" team>`. This equality is not enforced anywhere in the lookup path.

- `MembershipHandler#find_or_create_team!` (`app/models/shipit/webhooks/handlers/membership_handler.rb:38-43`) does `Team.find_or_create_by!(github_id: params.team.id) { |team| team.github_team = params.team; team.organization = params.organization.login }`. Nothing checks that `params.team.id` really belongs to `params.organization.login` on GitHub - both come straight from the JSON body.
- `Team.find_or_create_by_handle` (`app/models/shipit/team.rb:18-21`) does `find_by(organization:, slug:) || fetch_and_create_from_github(...)`. Once *any* row exists with the matching `organization`+`slug`, that row is returned forever (until process restart clears the `Shipit.github_teams` memoization at `lib/shipit.rb:256-258`), regardless of whether it was created via a real membership event or a forged one.
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) is the only gate; `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) explicitly returns `true` whenever `webhook_secret` is blank for that organization's app config, which the setup docs mark as "optional" (`docs/setup.md:30`). The `membership` payload schema (`MembershipHandler.params`) does not include a `repository` key, so `repository_owner` falls back to `params.dig('organization','login')` - fully attacker-controlled, letting the attacker pick which per-org `GitHubApp` (and therefore which webhook-secret policy) is used for verification.
- The `teams` table has a unique index on `(organization, slug)` (`db/migrate/20140226233935_create_baseline.rb:158`), so this only works as a *first-writer-wins* race: if a legitimate `Team` row for `real-org/eng` already exists in the DB, the attacker's forge attempt with the same `organization`+`slug` raises a uniqueness violation instead of hijacking anything. The exploit is therefore not a general override of an already-resolved team; it only succeeds if the attacker's forged webhook is processed before any legitimate resolution (e.g., before `bin/rake teams:fetch` runs or before any real membership event for that team has ever been received).

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: membership` and body `{action: 'added', team: {id: <arbitrary>, slug: 'eng', name:.., url:..}, organization: {login: 'real-org'}, member: {login: '<attacker>'}}` against an org whose `GitHubApp` has `webhook_secret` unset. If no `real-org`/`eng` `Team` row exists yet, this creates one owned by the attacker and adds them as a member in the same request (`process` at `membership_handler.rb:22-34`). When `Shipit.github_teams` is later computed and `Shipit.github.oauth_teams` includes `'real-org/eng'`, it resolves to this fabricated row, and the attacker's membership makes `User#authorized?` (`app/models/shipit/user.rb:80-82`) true.

### Impact Explanation
Impact matches "High - escalation into `Shipit.github_teams` authorization": the attacker gains membership in a team Shipit treats as authorized, without ever being a real member of the configured org/team, and can add further self-controlled members via the same forged event type. This is not Critical RCE/secret exfiltration; it is authorization-list poisoning for a single deployment's configured team, scoped to whichever `(organization, slug)` handle wasn't yet resolved.

### Likelihood Explanation
Requires two independent, non-attacker-controlled preconditions: (1) the targeted org's GitHub App has no `webhook_secret` configured (an operator misconfiguration, though documented as "optional"); (2) the attacker's forged create must be the first row ever inserted for that exact `organization`+`slug` pair, which in practice means winning a narrow bootstrap window before `bin/rake teams:fetch` or any legitimate membership event resolves it - a unique DB index blocks the attack once a legitimate row exists. This materially reduces feasibility from "repeatable against arbitrary orgs at will" to "exploitable only during a specific setup/race window on a misconfigured org."

### Recommendation
In `MembershipHandler#find_or_create_team!`, verify `params.team.id` against the GitHub API for `params.organization.login` (e.g., via `Team.find_team_on_github`) instead of trusting payload fields verbatim, and never persist `organization`/`slug` from an unverified webhook. Additionally, require a non-blank `webhook_secret` for every configured `GitHubApp` (fail closed rather than open when unset) so unsigned webhooks are always rejected.

### Proof of Concept
```ruby
test "forged membership webhook can win the (organization, slug) race before a legit team resolves" do
  Shipit.stubs(:github).returns(github_app_without_secret) # webhook_secret nil for org
  Shipit.instance_variable_set(:@github_teams, nil)
  Shipit.github.stubs(:oauth_teams).returns(['real-org/eng'])

  assert_nil Shipit::Team.find_by(organization: 'real-org', slug: 'eng')

  post :create, as: :json, body: {
    action: 'added',
    team: { id: 999_999, name: 'Eng', slug: 'eng', url: 'https://example.com' },
    organization: { login: 'real-org' },
    member: { login: 'attacker' }
  }.to_json
  assert_response :ok

  forged = Shipit::Team.find_by(organization: 'real-org', slug: 'eng')
  refute_nil forged
  assert_equal 999_999, forged.github_id

  Shipit.instance_variable_set(:@github_teams, nil)
  resolved = Shipit.github_teams.find { |t| t.handle == 'real-org/eng' }
  assert_equal forged.id, resolved.id # binding violated: not GitHub's real team

  attacker = Shipit::User.find_by!(login: 'attacker')
  assert attacker.authorized?
end

    class << self
      def find_or_create_by_handle(handle)
        organization, slug = handle.split('/').map(&:downcase)
        find_by(organization:, slug:) || fetch_and_create_from_github(organization, slug)
      end

      def fetch_and_create_from_github(organization, slug)
        return unless github_team = find_team_on_github(organization, slug)

        create!(github_team:, organization:)
      end

      def find_team_on_github(organization, slug)
        gh_api = Shipit.github(organization:).api
        teams = Shipit::OctokitIterator.new(github_api: gh_api) { gh_api.org_teams(organization, per_page: 100) }
        teams.find { |t| t.slug == slug }
      rescue Octokit::NotFound
      end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
