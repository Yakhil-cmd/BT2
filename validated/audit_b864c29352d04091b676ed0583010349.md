### Title
Forged `pull_request` "edited" webhook: org selected via `repository.owner.login` verifies signature while `repository.full_name` drives cross-org `PullRequest` mutation - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects which org's `webhook_secret` to check against using `repository.owner.login` from the attacker-controlled JSON body, but `EditedHandler` resolves and mutates the target `Repository`/`PullRequest` using the independent `repository.full_name` field from the same body. If the multi-org config includes an org configured with a blank/absent `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally (`return true unless webhook_secret`), letting an attacker forge a payload naming that no-secret org as `repository.owner.login` while pointing `repository.full_name` at a completely different (and legitimately secret-protected) org's repository whose `PullRequest` gets overwritten.

### Finding Description
The broken binding: the org that `verify_signature` uses to authenticate the request (`repository_owner` = `params.dig('repository','owner','login')`) must equal the org that owns the repository the handler actually mutates (derived from `params.repository.full_name` in `EditedHandler#repository`). Nothing in the code enforces this equality.

Trace:
- `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(signature, raw_post)` [1](#0-0)  where `repository_owner` is taken straight from the JSON body's `repository.owner.login` (or `organization.login`) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` immediately returns `true` if that org's `webhook_secret` is blank: `return true unless webhook_secret` [3](#0-2) . So naming an org that exists in `Shipit.github_app_config` but has no `webhook_secret` configured makes signature verification a no-op, regardless of the `X-Hub-Signature` header content.
- Once verification passes, `WebhooksController#create` dispatches the *entire raw body* to handlers for the event type, unrelated to which org "verified" it: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `EditedHandler#process` looks up the target `PullRequest` by `params.number` joined through `stacks.repository` filtered by a `repository` resolved from `params.repository.full_name`, not from `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) , then calls `pull_request.update(github_pull_request: params.pull_request)` [6](#0-5) .

Exploit: attacker sends `POST /webhooks` with `X-Github-Event: pull_request`, a body with `action: "edited"`, `repository.owner.login: "no-secret-org"` (a configured org lacking `webhook_secret`), and `repository.full_name: "victim-org/victim-repo"` matching a real Shipit-tracked stack belonging to a *different*, secret-protected org. `verify_signature` resolves `Shipit.github(organization: "no-secret-org")`, whose `verify_webhook_signature` trivially returns `true` because that org's `webhook_secret` is unset — no valid signature is needed at all. The handler then updates the real `PullRequest` row owned by `victim-org` using attacker-supplied `pull_request` fields (title, state, additions/deletions, head sha/ref, assignees, labels).

Existing guards don't catch this because: `verify_signature` never cross-checks that the verifying org matches the org implied by `repository.full_name`; `drop_unhandled_event` only checks the event type is registered, not payload consistency; the `ExplicitParameters` schema on `EditedHandler` only validates types/presence, not that `repository.full_name`'s org matches `repository.owner.login`; and `GithubOrganizationUnknown` is only raised if the org name is entirely absent from config — a *configured-but-secretless* org passes straight through.

### Impact Explanation
An unauthenticated internet attacker can overwrite the `github_pull_request` state (title, additions/deletions, head sha/ref, assignees, labels, state) of any `PullRequest` record tracked by Shipit for any repository/stack, as long as at least one configured GitHub org in the multi-org config has no `webhook_secret` set. This is cross-tenant state manipulation — one org's (no-secret) identity is used to forge writes into a completely different org's persisted records, matching the "payload for one repository mutating another's stack/commit/task" Critical impact category. It's repeatable per request against any stack/PR number combination the attacker can guess or enumerate, with no rate limiting on `/webhooks`.

### Likelihood Explanation
Preconditions: the Shipit instance must be running the multi-org GitHub config (`github_default_organization` non-nil) and must have at least one configured org with no `webhook_secret` (e.g., a newly added org whose secret hasn't been set yet, or one deliberately left open for a low-risk repo). Given that precondition, the attack costs the attacker nothing — no valid signature, no session, no API token, just a crafted HTTP POST with attacker-chosen JSON body and headers. The main uncertainty is deployment-specific: does the target's `secrets.github` config include a no-secret org? If every configured org has a `webhook_secret` set, this specific bypass path does not fire (the signature would need to be valid for whichever org is named in `repository.owner.login`), and only same-org cross-repo confusion (still possible if two repos share the same org secret) is exploitable rather than fully unauthenticated forgery. This dependency should be verified against the target's actual `secrets.github` configuration.

### Recommendation
In `EditedHandler` (and all other `PullRequest`/repository-based handlers using `from_github_repo_name`), verify that the resolved repository's owner matches the org used to authenticate the webhook (e.g., pass the verified `repository_owner` into the handler context and assert `repository.full_name.split('/').first.casecmp?(verified_organization)`), or better, have `WebhooksController#verify_signature` re-derive the org strictly from `repository.full_name` (splitting on `/`) rather than trusting `repository.owner.login`/`organization.login` as a separate, independently-forgeable field, and reject any org configured without a `webhook_secret` in production rather than treating a blank secret as "always verified."

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`-style, no live GitHub):
1. Configure two orgs in `Shipit.stubs(:secrets).returns(...)` (or override `Rails.application.credentials`): `victim-org` with a real `webhook_secret`, `noSecretOrg` with no `webhook_secret` key.
2. Create a `Shipit::Stack`/`Shipit::Repository` owned by `victim-org/victim-repo`, and a `Shipit::PullRequest` with `number: 42` and some baseline `github_pull_request` title `"original"`.
3. Build a JSON body: `{"action":"edited","number":42,"pull_request":{...,"title":"HACKED",...},"repository":{"owner":{"login":"noSecretOrg"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker"}}`.
4. `post shipit_webhooks_path, params: body, headers: {'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=deadbeef', 'Content-Type' => 'application/json'}` — no valid HMAC computed.
5. Assert response is `200 OK` (not `422`).
6. Reload the `PullRequest` record and assert `pull_request.github_pull_request['title'] == "HACKED"`, proving the attacker mutated `victim-org`'s record despite authenticating (trivially) as `noSecretOrg`.
7. Equality check performed: assert `verified_organization ("noSecretOrg") != repository_full_name.split('/').first ("victim-org")` while the write still succeeded — demonstrating the broken binding.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
