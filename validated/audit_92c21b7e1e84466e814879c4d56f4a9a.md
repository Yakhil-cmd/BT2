## Title
Threshold crossing in `remove-staker-from-signer-for-cycle` zeroes ALL co-stakers' reward-earning shares under a signer, freezing their rewards mid-cycle - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
The Reserve Protocol bug (H-02) showed that a threshold-crossing check that triggers a wholesale wipe (`beginEra()`) can destroy a large pool of value that happens to sit just above a threshold, because the "wipe" logic assumes little value remains once the threshold is crossed. `pox-5.clar`'s signer-set membership logic contains the same failure mode: when a single staker unstakes and that unstake pushes total delegation to a signer below `SIGNER_SET_MIN_USTX`, the contract zeroes out the *entire* signer's reward-earning shares for the current cycle - wiping the reward accrual for every other staker still delegated to that signer, not just the one who left.

### Finding Description
In `remove-staker-from-signer-for-cycle`, when a staker leaves and `new-delegated` (total delegated to the signer minus this staker's amount) drops below `SIGNER_SET_MIN_USTX`, the code takes the "crossed back below threshold" branch: [1](#0-0) 

This branch calls `remove-staker-from-set-for-cycle` and then sets the signer's `signer-shares-staked-for-cycle` to `u0` and subtracts the signer's *entire* `cur-staked-for-signer` from `total-shares-staked-for-cycle` - not just the departing staker's `amount`: [2](#0-1) 

Crucially, only the *acting* staker's own `staker-signer-cycle-memberships` and `staker-shares-staked-for-cycle` entries are deleted at the end of the function: [3](#0-2) 

All *other* stakers who remain delegated to that same signer keep their individual `staker-shares-staked-for-cycle` records untouched (their STX stays locked), but the signer's aggregate `signer-shares-staked-for-cycle` is now `0`. Since reward accrual is driven by `settle-rewards`/`settle-staker-rewards`, which compute `rewards-per-token` from the signer's aggregate staked shares, once that aggregate is zeroed, the signer accrues no further rewards for the remainder of the cycle - meaning every co-staker under that signer stops earning rewards for the rest of the cycle, purely because one unrelated staker's departure happened to cross the delegation threshold.

This mirrors the Reserve Protocol root cause exactly: the code assumes "if we're below the threshold, there's not much value left," and wipes the whole pool's reward-eligibility instead of proportionally adjusting only the departing staker's contribution. A large remaining pool of co-stakers (who took no action and have no way to prevent this) can have their in-progress rewards frozen for the remainder of the cycle by an action they never authorized.

### Impact Explanation
Other stakers delegated to the same signer lose expected reward accrual for the remainder of the reward cycle without having taken any action themselves - their STX remains locked (no permanent principal loss), but their signer's reward-per-token stops advancing, so they are permanently frozen out of rewards for the rest of that cycle. This is a stacking-state mutation triggered by another user's unrelated unstake action, which they never authorized, matching the "temporary freezing of staked funds" / "a stacking action the staker/signer never authorised" criteria (High impact).

### Likelihood Explanation
This requires no privileged role - any staker delegated to a signer near the `SIGNER_SET_MIN_USTX` threshold can unstake (a completely normal, permitted action via `unstake`) and trigger this for all other co-stakers of that signer. It is easily reachable whenever a signer's aggregate delegation hovers near the threshold, which is a realistic/common operating condition (analogous to the Reserve rate hovering near the era-reset threshold).

### Recommendation
When a signer crosses below `SIGNER_SET_MIN_USTX` mid-cycle, only subtract the departing staker's own `stake-amount`/`amount` from `signer-shares-staked-for-cycle` and `total-shares-staked-for-cycle` (as is already done in the "still above threshold" branch), rather than zeroing the signer's entire aggregate. Removing the signer from the *signer set* (voting/reward-slot participation) can still happen, but the underlying STX-staker reward-accrual bookkeeping for co-stakers should not be wiped in a single step tied to one staker's exit.

### Proof of Concept
1. Signer `S` has `SIGNER_SET_MIN_USTX = T`. Stakers A, B, C each delegate `T/2` to `S` in cycle `N`, giving `S` a total delegation of `1.5T` (comfortably above threshold, in the signer set, accruing rewards for A, B, C).
2. Mid-cycle, staker A calls `unstake`, which for future cycles calls `remove-staker-from-cycles` → `remove-staker-from-signer-for-cycle` for cycle `N` (`stackslib/src/chainstate/stacks/boot/pox-5.clar:1504-1618`).
3. `new-delegated = 1.5T - T/2 = T` ... if A's departure alone (or combined with a small extra delegation decrease) brings `new-delegated` below `T`, the "crossed back below threshold" branch fires.
4. `signer-shares-staked-for-cycle` for `S` is set to `u0` and `total-shares-staked-for-cycle` is reduced by `cur-staked-for-signer` (the full aggregate, i.e., B and C's shares included), even though B and C never unstaked and still hold `T` worth of locked, staked STX under `S`.
5. For the remainder of cycle `N`, `settle-rewards`/`settle-staker-rewards` compute B and C's earned rewards using `S`'s now-zeroed shares, so B and C accrue no further reward for cycle `N` despite holding significant locked value and taking no action.
