## Title
Non-network-aware signed packages accepted by `is_valid_signed_package` lack a domain separator, enabling cross-network replay of AA authorizations - (File: signed_message.js)

### Summary
Regular unit signatures include an `alt` field (network identifier, checked against `constants.alt` in `validation.js`), which distinguishes testnet from mainnet units. `signed_message` packages built via `signMessage()`/`getSignedPackageHashToSign()`, however, omit `alt` entirely and, when built without `last_ball_unit` (`bNetworkAware=false`), omit any chain/network-binding data at all, breaking the same guarantee the external report flags for the KEM hooks: a signature intended for one context can be validly replayed in a different one.

### Finding Description
`signMessage()` in [1](#0-0)  builds `objUnit = {version, signed_message, authors}` with no `alt` field, unlike real units which carry `alt` and are checked against `constants.alt` (network-specific) during validation. The digest that gets signed is produced by `getSignedPackageHashToSign()`, which simply hashes `{version, signed_message, authors}` after stripping authentifiers [2](#0-1) .

`validateSignedMessage()` in [3](#0-2)  determines `bNetworkAware = ("last_ball_unit" in objSignedMessage)`. When `last_ball_unit` is absent (non-network-aware path), the definition/address check is performed with no reference to any chain-specific state at all: [4](#0-3) . Because address derivation in Obyte is `chash(definition)` and is completely independent of network/genesis (see `object_hash.getChash160`), the *same* address/definition/private key can validly exist on two different networks (e.g., testnet and mainnet, or two independently-run ocore-based networks with different genesis units). Since the signed digest contains no genesis unit, no `alt`, and no chain-specific `last_ball_unit`, a signature produced for a signed_message on network A is byte-for-byte reproducible/verifiable as valid on network B.

This construct is directly reachable by an unprivileged AA trigger sender: the `is_valid_signed_package` oscript operator accepts a `signed_package` object from trigger data with an optional `last_ball_unit` field and forwards it to `validateSignedMessage()` [5](#0-4) . Nothing in the AA-facing oscript surface forces `last_ball_unit` to be present, and even the AA's own address/definition/asset identity is not folded into the signed digest.

### Impact Explanation
An AA that authorizes fund transfers, withdrawals, or other state changes based on `is_valid_signed_package(signed_package, address)` (a documented, user-facing oscript pattern for authenticating off-chain-style approvals) can be tricked by an attacker who captures a validly-signed, non-network-aware `signed_message` produced for a different network/context and replays it as trigger data against the AA. Because the digest carries no network/chain identifier, the AA cannot distinguish "this authorization was intended for this exact deployment" from "this authorization was captured elsewhere." This maps to the report's core failure mode — a signed authorization payload lacking a domain separator — and can result in unauthorized AA fund movement (AA fund loss), matching the "Medium" bug class in the original report.

### Likelihood Explanation
Exploitation requires: (1) an AA author using `is_valid_signed_package` to gate value-moving logic based on address only, without embedding their own domain data (AA address, purpose string, chain identifier) inside the `signed_message` payload itself, and (2) the same signer address existing/being reachable on more than one ocore-based network or context (testnet/mainnet dual usage, or a signed_message crafted for one purpose being fed to an unrelated AA that checks the same address). This is a realistic but not universal AA authoring pattern, since ocore itself provides the primitive without enforcing any domain separation, mirroring exactly the "acknowledged, mitigate via short expiry / different signer keys" resolution given for the original finding — i.e., the protocol primitive is unsafe by default and pushes domain separation entirely onto callers.

### Recommendation
Bind the signed-package digest to a domain separator at the protocol level: always include `alt` (or an explicit `network` identifier) in the object hashed by `getSignedPackageHashToSign()`, and require (rather than merely support) `last_ball_unit`/genesis-unit binding for any `signed_message` verified through `is_valid_signed_package`. At minimum, document and enforce that AA authors must include their own AA address and a unique context string inside `signed_message` when using `is_valid_signed_package`, and consider rejecting non-network-aware signed packages in that oscript operator entirely.

### Proof of Concept
1. On network A (e.g. ocore testnet, `constants.bTestnet=true`), a user calls `signed_message.signMessage(message, from_address, signer, false, cb)` (non-network-aware) to produce `objUnit = {version, signed_message: message, authors:[{address, definition, authentifiers}]}` and signs `getSignedPackageHashToSign(objUnit)`.
2. An AA on network A defines: `is_valid_signed_package(trigger.data.signed_package, params.expected_address)` to authorize a payout when the message content matches an expected instruction.
3. An attacker deploys an address with the identical definition (derivable deterministically from the same key material) on network B (mainnet, or another independently-run ocore chain), where an analogous AA also checks `is_valid_signed_package` against the same address.
4. The attacker submits the *same* `signed_package` object (same `version`, `signed_message`, `authors`) as trigger data on network B. `validateSignedMessage()` takes the non-network-aware path [4](#0-3) , verifies the chash of `author.definition` against `author.address` (network-independent), and the ECDSA signature check in `ecdsaSig.verify` succeeds because the digest never referenced network A vs B. The AA on network B executes the authorized action using a signature that was never intended for it.

function getSignedPackageHashToSign(signedPackage) {
	var unsignedPackage = _.cloneDeep(signedPackage);
	for (var i=0; i<unsignedPackage.authors.length; i++)
		delete unsignedPackage.authors[i].authentifiers;
	var sourceString = (typeof signedPackage.version === 'undefined' || signedPackage.version === constants.versionWithoutTimestamp) ? getSourceString(unsignedPackage) : getJsonSourceString(unsignedPackage);
	return crypto.createHash("sha256").update(sourceString, "utf8").digest();
}
