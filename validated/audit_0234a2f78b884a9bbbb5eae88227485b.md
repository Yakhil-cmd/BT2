The premise doesn't hold: the public `borrow` function does not accept an `account` parameter that lets a caller act on behalf of another principal. In both `local-testing/contracts/market/market.clar` and `mainnet/contracts/market/v0-4-market.clar`, `account` is hardcoded to `contract-caller`: [1](#0-0) 

This means only B, acting as `contract-caller`, can ever cause `debt-add-scaled` to be invoked with `account = B`, which is what stamps `last-borrow-block: stacks-block-height` on B's position entry in `market-vault.clar`: [2](#0-1) 

There is no `borrow(account=B, ...)` call surface reachable by an unrelated attacker A — A cannot make B's `borrow` transaction happen, and A cannot call `debt-add-scaled` directly on `market-vault` for B either, since it is gated by `check-impl-auth`, which restricts callers to the authorized market implementation contract (a privileged party, not an ordinary principal): [3](#0-2) 

Since `last-borrow-block` can only be set by B's own borrow transaction (whether the borrowed asset is enabled or disabled as collateral is irrelevant — it's still B's own action), this fails the required two-unprivileged-principal model: the only party who can write this shared state for B is B. There is no attacker A distinct from B able to cause the same-block guard to trip on B's behalf. This is not a non-interference violation — it is B's own single-transaction protection mechanism operating as designed (and intentionally global to the position, protecting all of B's collateral/debt pairs simultaneously from same-block flash-loan-style borrow-then-liquidate attacks).
