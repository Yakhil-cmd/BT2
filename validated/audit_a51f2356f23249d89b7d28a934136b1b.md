### Title
Attacker-controlled submodule URL causes leakage of cached git credentials to an untrusted host - (File: `main.go`)

### Summary
`git-sync`'s credential model can be abused by anyone who can push content to the tracked repository (or a repository it depends on transitively): by adding/altering a `.gitmodules` entry that points a submodule at an attacker-chosen URL sharing the same host/protocol as the legitimate `--repo`, the attacker can cause git to present the operator's previously-cached HTTP(S) username/password to that attacker-controlled endpoint during `git submodule update --init`. This mirrors the "pre-approved resource gets consumed by attacker-chosen parameters" pattern from the reference finding: the operator's credential (analogous to the victim's ERC20 approval) is set up for one intended target (the real `--repo`), but git's default credential-matching lets it be silently reused against a different target chosen by an untrusted party (the malicious submodule URL, analogous to the attacker's malicious market parameters).

### Finding Description
`git-sync` configures the global git credential helper to a host-scoped cache: [1](#0-0) 

`credential.helper = "cache --timeout 3600"` is set with no `credential.useHttpPath` override, so git's credential matching defaults to `protocol://host[:port]` — the path/repo component is *not* part of the match key. Any username/password git-sync stores via `StoreCredentials`/`git credential approve` (used for `--username`/`--password`, `--credential`, `--askpass-url`, and the GitHub App token flow) is therefore available to *any* URL sharing that protocol+host: [2](#0-1) [3](#0-2) 

Separately, on every sync `configureWorktree` runs `git submodule update --init [--recursive]` against whatever `.gitmodules`/submodule URLs are present in the freshly-fetched commit — content that is entirely attacker-controlled if the attacker can push to (or influence) the synced repository or any of its submodules: [4](#0-3) 

Because `SyncRepo`/`fetch` blindly follows the remote ref and then immediately configures/checks out submodules from that untrusted tree, an attacker who can add a commit to the tracked repo (e.g., a contributor with push access to a branch that is later merged, or a compromise of an upstream dependency repo used as a submodule) can add a submodule entry such as `https://github.com/<same-org-or-host>/attacker-repo`. When `configureWorktree` runs `submodule update --init`, git will look up cached credentials for that host and send them (as an HTTP `Authorization: Basic` header) to the attacker's endpoint, disclosing the username/password (or, worse, a short-lived GitHub App installation token minted via `RefreshGitHubAppToken`) to a server the attacker controls. [5](#0-4) 

This is the closest reachable analog to the referenced bug: a resource that the legitimate operator "approved" for use against a specific, intended target (the real `--repo`) is instead consumed against a different target chosen by an unprivileged, attacker-controlled input (a submodule URL embedded in synced repo content) — exactly the "approve for X, attacker substitutes Y" pattern.

### Impact Explanation
If exploited, this results in disclosure of git credentials (username/password, or a GitHub App installation token with read access to the repo) to an attacker-controlled server. Depending on the credential's scope, this can grant the attacker read (or, if the same credential is reused elsewhere, write) access to private repositories, effectively a confidentiality compromise of the sync credentials — one of the accepted impact classes (credential/token disclosure).

### Likelihood Explanation
Requires: (1) HTTP(S) username/password, `--credential`, `--askpass-url`, or GitHub App auth in use (SSH is not affected the same way since host-key/known_hosts scoping differs); (2) submodules enabled (not `--submodules=off`); (3) the attacker being able to introduce a submodule entry pointing to a same-host URL into content that git-sync will fetch and check out (this can be the top-level repo itself if the attacker has any push/PR-merge capability, or a nested submodule under attacker influence). This is a realistic scenario for CI/multi-tenant git hosts (GitHub, GitLab, self-hosted) where many repos/paths share one host and where git-sync's submodule support is a documented, default-available feature. It is not a "malicious operator" scenario — the attacker is an unprivileged contributor to tracked content, consistent with the allowed threat model.

### Recommendation
- Set `credential.useHttpPath = true` (or otherwise scope credentials by full URL/path, not just protocol+host) so cached credentials are never silently replayed to a different repository path on the same host.
- Consider disabling automatic submodule following for untrusted repos by default, or provide an explicit allow-list of submodule URLs/hosts before `submodule update --init` is invoked in `configureWorktree`.
- Avoid the shared `git credential cache` helper for GitHub App tokens and other short-lived secrets when submodules are enabled; scope those credentials as tightly as possible (e.g., `credential.<url>.helper` per exact repo URL).

### Proof of Concept
1. Configure git-sync with `--repo=https://git.example.com/org/legit-repo --username=svc --password=<secret>` (or `--askpass-url`/GitHub App auth), default submodules mode.
2. As a contributor able to push a commit/PR that gets synced, add `.gitmodules` with a submodule URL `https://git.example.com/attacker/evil-repo` (same host as the legitimate repo).
3. On the next sync, `configureWorktree` runs `git submodule update --init`, and git's credential cache (matched by `https://git.example.com`) supplies the operator's `svc`/`<secret>` credential to `attacker/evil-repo`; the attacker, who controls that repo/server logging, observes the `Authorization` header and recovers the credential.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

func (git *repoSync) CallAskPassURL(ctx context.Context) error {
	git.log.V(3).Info("calling auth URL to get credentials")

	var netClient = &http.Client{
		Timeout: time.Second * 1,
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	httpReq, err := http.NewRequestWithContext(ctx, http.MethodGet, git.authURL, nil)
	if err != nil {
		return fmt.Errorf("can't create auth request: %w", err)
	}
	resp, err := netClient.Do(httpReq)
	if err != nil {
		return fmt.Errorf("can't access auth URL: %w", err)
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusOK {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("auth URL returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("auth URL returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}
	authData, err := io.ReadAll(resp.Body)
	if err != nil {
		return fmt.Errorf("can't read auth response: %w", err)
	}

	username := ""
	password := ""
	for line := range strings.SplitSeq(string(authData), "\n") {
		keyValues := strings.SplitN(line, "=", 2)
		if len(keyValues) != 2 {
			continue
		}
		switch keyValues[0] {
		case "username":
			username = keyValues[1]
		case "password":
			password = keyValues[1]
		}
	}

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil

// RefreshGitHubAppToken generates a new installation token for a GitHub app
// and stores it as a credential.
func (git *repoSync) RefreshGitHubAppToken(ctx context.Context, githubBaseURL, privateKey, privateKeyFile, clientID string, appID, installationID int) error {
	git.log.V(3).Info("refreshing GitHub app token")

	privateKeyBytes := []byte(privateKey)
	if privateKey == "" {
		b, err := os.ReadFile(privateKeyFile)
		if err != nil {
			git.log.Error(err, "can't read private key file", "file", privateKeyFile)
			os.Exit(1)
		}

		privateKeyBytes = b
	}

	pkey, err := jwt.ParseRSAPrivateKeyFromPEM(privateKeyBytes)
	if err != nil {
		return err
	}

	now := time.Now()

	// either client ID or app ID can be used when minting JWTs
	issuer := clientID
	if issuer == "" {
		issuer = strconv.Itoa(appID)
	}

	claims := jwt.RegisteredClaims{
		Issuer:    issuer,
		IssuedAt:  jwt.NewNumericDate(now),
		ExpiresAt: jwt.NewNumericDate(now.Add(10 * time.Minute)),
	}

	jwt, err := jwt.NewWithClaims(jwt.SigningMethodRS256, claims).SignedString(pkey)
	if err != nil {
		return err
	}

	url, err := url.JoinPath(githubBaseURL, fmt.Sprintf("app/installations/%d/access_tokens", installationID))
	if err != nil {
		return err
	}

	req, err := http.NewRequestWithContext(ctx, http.MethodPost, url, nil)
	if err != nil {
		return err
	}

	req.Header.Set("Authorization", "Bearer "+jwt)
	req.Header.Set("Accept", "application/vnd.github+json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusCreated {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("GitHub app installation endpoint returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("GitHub app installation endpoint returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}

	tokenResponse := struct {
		Token     string    `json:"token"`
		ExpiresAt time.Time `json:"expires_at"`
	}{}
	if err := json.NewDecoder(resp.Body).Decode(&tokenResponse); err != nil {
		return err
	}

	git.appTokenExpiry = tokenResponse.ExpiresAt

	// username must be non-empty
	username := "-"
	password := tokenResponse.Token

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil
}

		}
	}
	return nil
}
