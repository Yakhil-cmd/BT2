### Title
Baseline shift via `git commit --amend` hides dangerous changes from the security review window - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` in `diffstate.py` intersects `dirty_now` (git-status-derived dirty set, extended only when `head_at_capture` is an ancestor of current `HEAD`) with `changed_since` (tree diff against `baseline_sha`). A normal `git commit --amend` breaks the ancestor relationship between `head_at_capture` and the amended `HEAD`, causing `dirty_now` to go empty once the working tree is clean, which zeroes the intersection and drops an already-changed dangerous file from the review set even though `changed_since` correctly still contains it.

### Finding Description
`compute_v2_review_set` computes the review set as:
```
review_set = dirty_now & changed_since   (if changed_since is not None else dirty_now)
``` [1](#0-0) 

`dirty_now` starts as `tracked_dirty | new_untracked` from `git status --porcelain`, and is only widened to include commit-range diffs when `head_at_capture` is an ancestor of the current `HEAD`:
```
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
``` [2](#0-1) 

`changed_since` is a pure tree-content diff against `baseline_sha` (`git diff --name-only baseline_sha`), independent of commit ancestry — it will correctly show the dangerous file as changed regardless of how the working tree got there.

Attack sequence (achievable through ordinary git operations Claude/the user runs in a session, no special privilege needed):
1. Turn N: baseline is captured at commit `C` (clean tree, `head_at_capture = C`), reviewed and clean.
2. Turn N+1: a commit is made containing a benign version of a file, then `git commit --amend` rewrites that commit to inject the dangerous payload. The amended commit `C'` shares `C`'s parent but is **not** a descendant of the pre-amend commit that `head_at_capture` might reference from an aborted/partial prior turn, or more directly: if `head_at_capture` itself was the just-created pre-amend commit, amending replaces it with a sibling `C'`, so `head_at_capture` is no longer an ancestor of `HEAD`.
3. Because `_is_ancestor(head_at_capture, current_head)` is now `False`, the `head_at_capture..HEAD` name-only diff is skipped, so `dirty_now` stays as just `tracked_dirty | new_untracked` — both empty because the working tree is clean and matches the freshly amended commit.
4. `changed_since = git diff --name-only baseline_sha` still reports the dangerous file (its content differs from the baseline tree), but `review_set = dirty_now(∅) & changed_since({dangerous_file}) = ∅`.
5. The Stop hook's LLM review therefore receives an empty (or file-missing) diff and the dangerous change is silently skipped — exactly the "shift baseline state so the dangerous change is treated as old" scenario, achieved purely through normal git commands (`commit`, `commit --amend`).

No existing guard catches this: the UPS "preserve baseline" logic in `handle_user_prompt_submit` only protects against baselines being overwritten across turns when `touched_paths` is non-empty and Stop hasn't consumed it [3](#0-2) ; it does not address the intra-turn ancestry break caused by amend. No test in the repository exercises the amend path against `compute_v2_review_set` (a targeted search for `amend`/`compute_v2_review_set` in test files returned no matches), so this gap appears unvalidated.

### Impact Explanation
This directly breaks the stated invariant ("an attacker must not hide a dangerous change by shifting it outside the computed review window"): a dangerous code change that was actually introduced during the reviewed turn can be excluded from the Stop-hook's git-diff-based LLM security review. Since the Stop hook is Claude Code's last line of automated defense for reviewing agent-authored changes before they're considered final, a bypass here allows a dangerous change (e.g., an injected command-execution payload) to reach the repository without triggering the exit(2) rewake/review path — i.e., unauthorized local code changes escaping the review/approval-adjacent control, matching "Unauthorized local command execution that bypasses Claude Code approval or deny controls" in scope/severity terms, since the review is the mechanism intended to catch and force remediation of such changes.

### Likelihood Explanation
The only precondition is that a `git commit --amend` (or an equivalent history-rewriting operation such as `rebase`, `reset --hard` + recommit, or `filter-branch`) occurs within the reviewed turn on a commit that was itself the `head_at_capture` reference or otherwise breaks the linear-ancestry assumption, while the resulting working tree is clean. This is an entirely ordinary git workflow (commit, then amend to fix a typo/message, or squash), not privileged or exotic, so it is realistically triggerable in normal agent usage or by a repository/task that nudges Claude toward amending commits. The bug is deterministic given the sequence, not probabilistic.

### Recommendation
Do not gate the `dirty_now` widening solely on strict ancestry of `head_at_capture` in `HEAD`. When ancestry breaks (rewrite detected), fall back to comparing tree content directly (e.g., treat `changed_since` alone as the review set, or compute `dirty_now` from a direct tree diff of `HEAD` vs `head_at_capture` regardless of ancestor status, using `git diff --name-only head_at_capture HEAD` rather than only the ancestor-gated `_git_name_only(head_at_capture..HEAD)` range syntax) so that amended/rewritten commits still surface content differences relative to the last reviewed baseline.

### Proof of Concept
Integration test plan (pytest, using a real temp git repo as most of the suite likely does):
1. Init repo, initial commit `base.txt`.
2. Capture baseline: call `capture_git_baseline(cwd)` → `baseline_sha0`; `head_at_capture0 = HEAD`.
3. Write and commit a benign file `payload.py` with safe content → `HEAD = C`.
4. Set `head_at_capture = C` (simulating a mid-turn baseline referencing this commit, or simply set `head_at_capture` to the pre-amend `C`).
5. Modify `payload.py` to contain a dangerous pattern (e.g., `os.system(user_input)`), then run `git commit --amend --no-edit` → `HEAD = C'`.
6. Call `compute_v2_review_set(cwd, baseline_sha0, head_at_capture=C, untracked_at_baseline={})`.
7. **Expected (fixed) assertion**: `payload.py` (absolute path) is present in the returned `review_paths`.
8. **Current (vulnerable) behavior**: assert reproduction — `review_paths` is empty / does not contain `payload.py`, `metrics["review_set_count"] == 0` despite `metrics["changed_since_count"] >= 1`, demonstrating the dangerous change is dropped from the computed review window. [4](#0-3)

def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
    if not isinstance(untracked_at_baseline, dict):
        untracked_at_baseline = {}

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now

    review_paths = [os.path.join(repo, p) for p in sorted(review_set)]
    untracked_in_review = sorted(new_untracked & review_set)
    metrics = {
        "dirty_now_count": len(dirty_now),
        "changed_since_count": len(changed_since) if changed_since is not None else -1,
        "review_set_count": len(review_set),
    }
    # Only emit when nonzero to stay under the 10-key telemetry cap.
    if preexisting_unchanged:
        metrics["preexisting_untracked_excluded"] = len(preexisting_unchanged)
    return review_paths, diff_base, repo, untracked_in_review, metrics
```
