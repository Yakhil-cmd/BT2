### Title
Denial-of-Bridge-Transfer via Reverting Receiver in `handleKLAYTransfer` — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

`handleKLAYTransfer` in the Kaia service-chain bridge contract sends native KAIA to the recipient via a low-level call and then unconditionally `require`s success. If the recipient `_to` is a contract whose `receive()` function reverts, every attempt to settle that bridge request reverts, the nonce is never marked handled, `lowerHandleNonce` never advances past that slot, and the Go-side relay loop re-queues the same event forever. The attacker's KAIA is permanently locked in the parent-chain bridge and the bridge operator burns gas on every retry cycle.

---

### Finding Description

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` performs all state mutations **before** the native-token transfer, then hard-reverts if the transfer fails:

```solidity
// contracts/service_chain/bridge/BridgeTransferKLAY.sol  lines 81-99
_setHandledRequestTxHash(_requestTxHash);
handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber;
_updateHandleNonce(_requestedNonce);

emit HandleValueTransfer(...);

(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");   // ← hard revert
``` [1](#0-0) 

Because Solidity reverts roll back **all** state changes in the same transaction, the `require` on line 99 undoes every mutation above it: `handleNoncesToBlockNums[_requestedNonce]` is never written, `_updateHandleNonce` is rolled back, and `lowerHandleNonce` stays at the stuck nonce.

`_updateHandleNonce` advances `lowerHandleNonce` only while consecutive entries in `handleNoncesToBlockNums` are non-zero:

```solidity
// BridgeTransfer.sol  lines 149-155
for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
    recoveryBlockNumber = handleNoncesToBlockNums[i];
    ...
}
lowerHandleNonce = i;
``` [2](#0-1) 

With nonce N permanently unhandled, `lowerHandleNonce` is frozen at N and `recoveryBlockNumber` never advances past N's block.

On the Go relay side, `processingPendingRequestEvents` re-queues the failing event on every error and returns immediately, so the bridge loop retries the same nonce on every tick (every second) and on every new event:

```go
// node/sc/bridge_manager.go  lines 254-258
if err := bi.handleRequestValueTransferEvent(ev); err != nil {
    bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
    logger.Error("Failed handle request value transfer event", ...)
    return
}
``` [3](#0-2) 

The VT-recovery goroutine (`vtr.recoverPendingEvents`) independently re-injects the same stuck event into the queue on every recovery cycle, compounding the retry storm. [4](#0-3) 

---

### Impact Explanation

| Asset / State | Effect |
|---|---|
| User's KAIA on parent chain | Permanently locked in the parent-chain bridge contract; no refund path exists |
| Bridge operator's KAIA | Continuously drained by gas costs of endlessly failing `handleKLAYTransfer` transactions |
| `lowerHandleNonce` / `recoveryBlockNumber` | Frozen at the stuck nonce; the VT-recovery scanner never moves past that block |

The KAIA locked in the parent-chain bridge is the direct asset loss. There is no on-chain mechanism to cancel a `requestKLAYTransfer` or to skip a stuck nonce.

---

### Likelihood Explanation

The trigger requires only a standard, unprivileged call to `requestKLAYTransfer` on the parent-chain bridge with `_to` set to any contract address on the child chain whose `receive()` reverts. The attacker can deploy such a contract themselves in one transaction before initiating the bridge request. No operator privilege, majority-validator collusion, or key compromise is needed.

---

### Recommendation

Replace the hard `require` with a graceful-failure path. Two complementary fixes:

1. **Skip-and-record**: If the low-level call fails, emit a `HandleValueTransferFailed` event, still write `handleNoncesToBlockNums[_requestedNonce]` and call `_updateHandleNonce`, so `lowerHandleNonce` advances and the bridge is not frozen. The KAIA can be held in a claimable mapping for the original `_from` address.

2. **Bounded gas forwarding**: Forward only a fixed gas stipend (e.g. 2300 gas) to `_to` so that a malicious `receive()` cannot consume unbounded gas and the call result is treated as advisory rather than fatal.

---

### Proof of Concept

1. On the child chain, deploy a contract `RevertReceiver` with `receive() external payable { revert(); }`.
2. On the parent chain, call `bridge.requestKLAYTransfer{value: 1 ether}(revertReceiverAddress, 1 ether, "")`. This emits `RequestValueTransfer` with nonce N and locks 1 KAIA in the parent bridge.
3. The bridge relay picks up the event and calls `handleKLAYTransfer(..., revertReceiverAddress, 1e18, N, ...)` on the child-chain bridge.
4. `_to.call.value(1e18)("")` returns `(false, ...)`. `require(ok, ...)` reverts the transaction. All state mutations are rolled back; `handleNoncesToBlockNums[N]` remains 0.
5. `processingPendingRequestEvents` logs the error, re-adds the event, and returns. The bridge loop retries every second indefinitely.
6. `lowerHandleNonce` stays at N. `recoveryBlockNumber` stays at the block of nonce N-1. The VT-recovery goroutine re-injects the event on every recovery interval.
7. The user's 1 KAIA is permanently locked. The bridge operator's account is drained by gas on every retry. [5](#0-4) [6](#0-5) [7](#0-6)

// processingPendingRequestEvents handles pending request value transfer events of the bridge.
func (bi *BridgeInfo) processingPendingRequestEvents() {
	ReadyEvent := bi.GetReadyRequestValueTransferEvents()
	if ReadyEvent == nil {
		return
	}

	logger.Trace("Get ready request value transfer event", "len(readyEvent)", len(ReadyEvent), "len(pendingEvent)", bi.pendingRequestEvent.Len())

	for idx, ev := range ReadyEvent {
		if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
			logger.Trace("handled requests can be ignored", "RequestNonce", ev.GetRequestNonce(), "lowerHandleNonce", bi.lowerHandleNonce)
			continue
		}

		if err := bi.handleRequestValueTransferEvent(ev); err != nil {
			bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
			logger.Error("Failed handle request value transfer event", "err", err, "len(RePutEvent)", len(ReadyEvent[idx:]))
			return
		}
	}
}

func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))

		events[i] = event
