### Title
Unsanitized rendering of attacker-controlled comment/issue/PR body content allows bidi/zero-width character spoofing - (File: pkg/cmd/pr/shared/comments.go)

### Finding Description
`formatRawComment` writes `comment.Content()` directly into the output buffer with `fmt.Fprintln(&b, comment.Content())` with no filtering of Unicode control characters. [1](#0-0)  `RawCommentList` (used for `--comments --raw`-style output in `pr view` and `issue view`) simply concatenates the result of `formatRawComment` for every comment/review, and the caller writes the resulting string straight to the terminal. [2](#0-1) 

The comment body originates from `Comment.Content()`, which is populated from the GraphQL API response for an issue/PR comment, review, or review body — fields that are fully attacker-controlled since any unprivileged GitHub user can post a comment or review on a public issue/PR. Unlike the codebase's `Untrusted` type in `pkg/iostreams/untrusted.go`, which wraps untrusted external content (e.g. HTTP bodies, run logs, workflow files) and applies `asciisanitizer` on every `String()`/print path, `Comment.Content()` used by `formatRawComment` is a plain `string` and is never passed through `Untrusted` or any sanitizer before being written. [3](#0-2) 

Additionally, even the `asciisanitizer` package (from `go-gh`) that is used elsewhere in this codebase is documented/scoped to neutralize ANSI escape sequences and a small set of dangerous C0/ASCII control bytes — it is not a general Unicode bidi/zero-width character stripper for characters like U+202E (RIGHT-TO-LEFT OVERRIDE), U+200B (ZERO WIDTH SPACE), or combining marks. So even where `Untrusted`/`asciisanitizer` is applied elsewhere in the codebase, it would not reliably strip bidi-override or zero-width characters. In `formatRawComment`'s path, there is no sanitization at all, so an attacker can embed U+202E or zero-width characters in a comment/PR/issue body to visually reverse or hide substrings of a displayed path, filename, host, or command when the raw comment text is rendered in a terminal (e.g., faking a file extension, or hiding a malicious command inside seemingly benign text) that the victim might copy/paste or act on.

### Impact Explanation
This is a terminal/output spoofing issue: it can mislead a victim who runs `gh pr view --comments`/`gh issue view --comments` (or similar raw-comment surfaces) into misreading a filename, host, or command embedded in an attacker's comment, potentially leading to copy-pasting a malicious command or misidentifying a file. This matches the "Terminal output/prompt spoofing" impact class described in the question, though the severity is bounded by the fact that this affects *display only* — it does not itself execute code, exfiltrate credentials, or write files; a downstream unsafe action (e.g., a victim manually copying and running spoofed text) is required to realize a credential-capture or destructive scenario.

### Likelihood Explanation
High feasibility and repeatability: any unprivileged GitHub user can post a comment, PR body, or review on a public issue/PR containing these Unicode control characters, and any victim who runs `gh pr view`/`gh issue view` with the raw comment flag against that issue/PR will render the spoofed text verbatim. No special permissions or victim misconfiguration are needed beyond viewing the attacker's comment.

### Recommendation
Sanitize comment/body/title content before writing it to the terminal in `formatRawComment` (and the corresponding non-raw `formatComment`/markdown path). Wrap `comment.Content()` (and other attacker-authored fields such as `AuthorLogin`, `Association`, `Link`) in the existing `iostreams.Untrusted` type, or add an explicit Unicode-normalization/stripping step that removes bidi control characters (U+202A–U+202E, U+2066–U+2069) and zero-width characters (U+200B, U+200C, U+200D, U+FEFF) prior to display, consistent with the "Trojan Source" mitigation pattern.

```go
// pkg/cmd/pr/shared/comments_test.go
func TestFormatRawComment_StripsBidiControls(t *testing.T) {
    evil := "safe\u202Etxt.exe" // renders as "safe" + RTL override, spoofing extension
    c := &fakeComment{content: evil}
    out := formatRawComment(c)
    if strings.ContainsRune(out, '\u202E') {
        t.Fatalf("expected bidi override character to be stripped, got: %q", out)
    }
}
```
Expected (currently failing) assertion: `formatRawComment` output should not contain U+202E/zero-width characters; today it passes them through unchanged because `comment.Content()` is written with no sanitization.

```go
func formatRawComment(comment Comment) string {
	if comment.IsHidden() {
		return ""
	}
	var b strings.Builder
	fmt.Fprintf(&b, "author:\t%s\n", comment.AuthorLogin())
	fmt.Fprintf(&b, "association:\t%s\n", strings.ToLower(comment.Association()))
	fmt.Fprintf(&b, "edited:\t%t\n", comment.IsEdited())
	fmt.Fprintf(&b, "status:\t%s\n", formatRawCommentStatus(comment.Status()))
	fmt.Fprintln(&b, "--")
	fmt.Fprintln(&b, comment.Content())
	fmt.Fprintln(&b, "--")
	return b.String()
}
```

```go
// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is

func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```
