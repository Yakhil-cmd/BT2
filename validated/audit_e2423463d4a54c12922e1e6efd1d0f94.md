### Title
Deregistered Bridge Operator's Votes Persist and Can Execute Unauthorized Asset Transfers — (File: `contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`deregisterOperator` removes an operator from the `operators` mapping and `operatorList` but leaves their outstanding votes intact in the `votes` mapping. A deregistered (potentially compromised) operator's prior vote can still count toward the threshold, allowing a single remaining active operator to trigger execution of a bridge value transfer (KLAY, ERC20, ERC721) that the owner intended to block by removing the bad operator.

---

### Finding Description

`deregisterOperator` performs only two cleanup steps:

```solidity
delete operators[_operator];
// ... remove from operatorList array
``` [1](#0-0) 

It does **not** touch the `votes` mapping, which stores per-nonce `VotesData` structs containing `voted[operator]` and `voteCounts[voteKey]` for every pending nonce. [2](#0-1) 

The threshold check in `_voteCommon` reads directly from `voteCounts`:

```solidity
if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
    return true;
}
``` [3](#0-2) 

Because the deregistered operator's `voteCounts` entry is never decremented, a single subsequent vote from any remaining active operator can push the count to the threshold and execute the transfer. The code itself documents this exact scenario:

> *"Operator A votes on nonce N → Owner deregisters A → Operator B votes on nonce N, thereby executing the request N. In this case the request was executed with A's vote after A is deregistered."* [4](#0-3) 

The execution path that transfers assets is `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer`, each of which calls `_voteValueTransfer` → `_voteCommon` and, on threshold, immediately transfers the asset:

```solidity
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [5](#0-4) [6](#0-5) 

---

### Impact Explanation

**High.** The invariant broken is: *a deregistered operator must not influence bridge operations*. When the owner deregisters a compromised operator to abort a pending malicious transfer, the deregistration is ineffective for any nonce on which the operator has already voted. One additional vote from any remaining active operator is sufficient to execute the transfer, draining KLAY or bridged tokens from the contract to an attacker-controlled address.

---

### Likelihood Explanation

**High.** The code explicitly acknowledges this happens *every time* an operator is deregistered while holding outstanding votes. The only mitigation mentioned is that "the owner shall recognize this issue," which is an operational assumption rather than a code-level guard. In practice, operators vote as soon as they observe a cross-chain request event, so pending votes will almost always exist at the moment of deregistration.

---

### Recommendation

In `deregisterOperator`, iterate over all open nonces and decrement `voteCounts` for any `voteKey` the deregistered operator has voted on, using the `voted[_operator]` entry already stored in `VotesData`. Alternatively, record the deregistration block and reject votes cast by operators who were deregistered before the vote was submitted.

---

### Proof of Concept

Setup: operators A, B, C; `operatorThresholds[ValueTransfer] = 2`.

1. Operator A (compromised) calls `handleKLAYTransfer(…, nonce=7, …)` → `_voteCommon` stores `voted[A] = voteKey`, `voteCounts[voteKey] = 1`. Threshold not yet met; no transfer.
2. Owner calls `deregisterOperator(A)` → `operators[A]` deleted, `operatorList` shrunk. `votes[0][7].voteCounts[voteKey]` remains **1**.
3. Operator B (honest, unaware of compromise) calls `handleKLAYTransfer(…, nonce=7, same args…)` → `_voteCommon` increments `voteCounts[voteKey]` to **2** ≥ threshold → returns `true` → `closedValueTransferVotes[7] = true` → `_to.call.value(_value)("")` executes, transferring KLAY to the attacker's address.

The owner's deregistration of A had zero effect on the pending vote, and the bridge transfer completes with A's compromised vote still counted. [7](#0-6)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // _voteValueTransfer votes value transfer transaction with the operator.
    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
