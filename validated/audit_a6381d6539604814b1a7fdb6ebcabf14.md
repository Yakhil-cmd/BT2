### Title
Release asset `name` field is joined into `--dir` without path sanitization, enabling path traversal - ([File: pkg/cmd/release/download/download.go])

### Summary
The archive-download path (Content-Disposition `filename`) is safe because `downloadAsset` calls `filepath.Base(serverFileName)` before using it. However, the asset-name-driven path is not: `a.Name` from the GitHub API flows unmodified through `downloadAsset` into `dest.Check`/`dest.Copy`, which build the write path with `filepath.Join(w.dir, name)` with no `filepath.Base`/`filepath.Clean`-based confinement.

### Finding Description
In `downloadRun` (`pkg/cmd/release/download/download.go:195-208`), for the non-archive (asset pattern/plain) code path, each `shared.ReleaseAsset.Name` (attacker-controlled if the attacker owns the release, e.g. via a self-authored repo/release) is placed directly into `downloadTarget.name` [1](#0-0) , then passed as `fileName` to `downloadAsset` [2](#0-1) .

Because `fileName` is non-empty for named assets, the `mime.ParseMediaType`/`filepath.Base` sanitization branch is skipped entirely — that branch only triggers `if len(fileName) == 0` [3](#0-2) . The raw asset name is passed straight into `dest.Check(fileName)` and `dest.Copy(fileName, resp.Body)`.

`destinationWriter.makePath` then does `filepath.Join(w.dir, name)` with no basename extraction or `..`-segment rejection: [4](#0-3) . `filepath.Join` calls `Clean`, so a name like `../../evil.sh` combined with `dir="."` resolves to a path outside the destination directory, and `Copy` will `os.MkdirAll` any needed parent directories and write the file there [5](#0-4) .

By contrast, the archive/zipball-tarball path (`isArchive=true`, pseudo-asset with `Name` empty) is protected: `fileName` is empty, so the Content-Disposition branch runs and applies `filepath.Base(serverFileName)`, which strips any path separators or `..` segments [6](#0-5) . That specific vector (Content-Disposition injection for `--archive=zip`/`tar.gz`) is therefore neutralized.

### Impact Explanation
For `gh release download` invoked without `--archive` (i.e., matching by `--pattern` or downloading all assets), a malicious release asset `name` containing path-traversal segments (`../../…`) could cause `dest.Copy` to write the downloaded content to a path outside `--dir`, i.e., arbitrary file write/overwrite on the victim's filesystem constrained by the process's OS permissions. This matches the "file write or overwrite outside the intended path" impact class. Whether this is actually reachable end-to-end depends on GitHub's server-side release-asset-upload validation (a component outside this repository) permitting `/`, `\`, or `..` characters in an asset's `name` metadata; I was not able to verify that server-side constraint from this codebase, and no test in `download_test.go` currently covers this asset-name traversal case.

### Likelihood Explanation
The precondition is narrower than the archive case: the attacker must be able to set the release asset's `name` field to contain path-traversal characters via the GitHub REST/GraphQL API (self-authored release) or via a malicious/enterprise host the victim points `gh` at (bypassing github.com's own upload validation). If github.com's real asset-upload endpoint rejects slashes/`..` in asset names (a common practice), the practical exploitability on github.com is blocked upstream; the code-level lack of defense-in-depth remains, and it is fully exploitable against any GHE/custom host that does not enforce equivalent restrictions.

### Recommendation
Apply the same sanitization used for the Content-Disposition path to asset names too: sanitize every `name` passed to `dest.Check`/`dest.Copy` with `filepath.Base` (and ideally an additional check rejecting resulting `..`/empty results) regardless of whether it came from an asset's `name` field or a Content-Disposition header, so `destinationWriter.makePath` never joins an untrusted path component that can escape `w.dir`.

### Proof of Concept
```go
// pkg/cmd/release/download/download_test.go (new test)
func TestDownloadAsset_AssetNamePathTraversal(t *testing.T) {
    tmpDir := t.TempDir()
    dest := destinationWriter{dir: tmpDir}

    // simulate a release asset whose Name (as returned by the API) contains
    // a path traversal segment
    maliciousName := "../../evil.sh"

    // Check/Copy should refuse to write outside tmpDir; currently they don't.
    err := dest.Check(maliciousName)
    require.NoError(t, err) // demonstrates no confinement check exists

    err = dest.Copy(maliciousName, strings.NewReader("PWNED"))
    require.NoError(t, err)

    // Assert the file was NOT created outside tmpDir (this assertion currently fails)
    outside := filepath.Join(filepath.Dir(filepath.Dir(tmpDir)), "evil.sh")
    _, statErr := os.Stat(outside)
    require.True(t, os.IsNotExist(statErr), "file must not be written outside destination")
}
```
Expected (post-fix) behavior: `dest.Check`/`dest.Copy` sanitize `name` via `filepath.Base` (mirroring the Content-Disposition branch), so the resulting write path always stays confined under `w.dir`, and the assertion in the PoC passes.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
