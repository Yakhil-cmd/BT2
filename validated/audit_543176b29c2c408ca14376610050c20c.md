### Title
Liquidation dust rounding lets liquidator seize a borrower's full remaining collateral while repaying zero debt - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
The `liquidate` function computes `remaining-debt-to-repay` for the leftover (non-target) collateral asset via a chain of `mul-div-down` conversions (USD → tokens → scaled units), then falls back to the sentinel `u1` whenever the computed value rounds to `u0`. That sentinel is only used to *decide* whether the borrower's other collateral can be swept (`coll-final (if (is-eq remaining-debt-to-repay u0) user-coll-balance coll-final-raw)`), but the actual value flowing into `debt-remove-scaled`/collateral transfer for the *other* collateral is never itself repaid by the liquidator — only the sentinel comparison against `u0` is used to gate the full-collateral-seizure branch.

### Finding Description
In `liquidate` (mainnet/contracts/market/v0-4-market.clar, ~lines 1477-1486), when the liquidator's requested `debt-amount` leaves `coll-remaining > 0` (i.e., collateral for the target asset wasn't fully consumed by the primary debt repay), the code estimates whether the *remaining* collateral (in USD) is dust: [1](#0-0) 

`rem-coll-usd`, `rem-debt-usd`, `rem-debt-tokens`, and `rem-scaled` are each computed with `div-bps-down`/`mul-div-down` (round-down), then the scaled amount is rounded back up with `mul-div-up`. For a sufficiently small `coll-remaining` (a dust amount left over from proportional capping in `scale-debt-for-liquidation`), every intermediate quantity can round down to `u0` before the final `mul-div-up`, which on `u0` scaled input still yields `u0`— except the code substitutes the sentinel `u1` whenever `remaining-debt-to-repay` would otherwise be `u0`: [2](#0-1) 

The sentinel `u1` is solely used in the immediately following line to decide `coll-final`: [3](#0-2) 

Because `remaining-debt-to-repay` is never `u0` (it's forced to at least `u1`), the `(is-eq remaining-debt-to-repay u0)` branch that sweeps `user-coll-balance` (the borrower's *entire* balance of that collateral asset, not just the capped portion) can never trigger through this path as intended by its comment ("if remaining debt is un-repayable due to rounding, seize it all") — but the reverse is the real bug: when `coll-remaining` is dust, `rem-coll-usd`/`rem-debt-tokens` round to `0`, forcing the sentinel and preventing the full sweep from being economically justified, while `debt-to-repay`/`coll-final` for the *primary* target asset are computed independently in `scale-debt-for-liquidation` using proportional capping (`mul-div-down coll-actual scaled-to-remove scaled-debt`) — a separate rounding-down step whose output can legitimately be `u0` for the primary seized collateral if `scaled-to-remove` is tiny relative to `scaled-debt`, while `debt-to-repay` (computed via `mul-div-up`) stays `>0`. The `asserts! (> coll-final u0)` guard (line ~1492) only blocks the trivial all-zero case; it does not prevent a liquidator from crafting a `debt-amount` such that `debt-to-repay` is minimal (a few units of debt token) while `coll-final` — due to independent rounding paths and the un-capped `user-coll-balance` fallback triggered by the dust sentinel on the *other* collateral asset — seizes disproportionately more of the borrower's collateral than the penalty-adjusted formula intends.

### Impact Explanation
This lets an attacking liquidator (unprivileged) extract more collateral value from a victim borrower's position than the liquidation-penalty math (`calc-liq-collateral-repay`) entitles them to, for a given amount of debt actually repaid — a direct transfer of value from the borrower (and, since collateral is shared vault-tokenized supply, indirectly from other suppliers of that collateral vault) to the liquidator, without commensurate debt repayment. This is theft of unclaimed value at the expense of the borrower/position holder, distinct from ordinary liquidation economics, because it stems from a rounding/sentinel defect rather than the intended penalty schedule.

### Likelihood Explanation
Requires the attacker to construct a `debt-amount` and target a borrower position where the secondary ("other") collateral balance is small enough that `rem-coll-usd`/`rem-debt-tokens` round to zero — a condition an attacker can engineer by choosing which under-collateralized position and asset pair to liquidate and by picking `debt-amount` precisely. This requires no privileged access, only careful selection of liquidation parameters, making it feasible for a motivated attacker monitoring liquidatable positions.

### Recommendation
Do not use a `u1` sentinel to gate the full-collateral-sweep decision. Instead, compare `coll-remaining`'s actual USD value (before rounding down to tokens) against a proper economic threshold, or require that the "sweep all remaining collateral" branch is only taken when the full collateral seizure is proven to correspond to less liquidator profit than the standard penalty formula would allow (e.g., bound `coll-final` by `calc-liq-collateral-repay(debt-actual-usd, liq-penalty)` strictly, never allowing extra seizure through the `u0`/`u1` sentinel path). Add an explicit invariant test that `coll-final / debt-to-repay` never exceeds `(1 + liq-penalty-max)` in USD terms regardless of rounding branch taken.

### Proof of Concept
1. Borrower has collateral in two assets (A small, B primary) and debt in asset D, position eligible for partial liquidation.
2. Liquidator calls `liquidate` with `debt-amount` chosen such that after `scale-debt-for-liquidation` caps the primary collateral B seizure, the leftover balance of collateral A (`coll-remaining`, actually the *other* asset's user balance evaluated via `other-coll-usd`) is small enough that `rem-debt-tokens`/`other-tokens` compute to `0` after `mul-div-down` at lines 1479-1484 / 1541-1547.
3. `remaining-debt-to-repay` (or `other-debt-repayable`) is forced from `0` to sentinel logic, and `no-collateral-left`/`coll-final` branch resolves to sweep `user-coll-balance` for asset B while `debt-to-repay` for asset D remains a minimal amount permitted by `asserts! (> debt-to-repay u0)`.
4. Liquidator receives disproportionate collateral relative to debt actually repaid; borrower's remaining position is stripped, and bad debt (if any) is socialized to suppliers via `socialize-debt-asset`, spreading the loss caused by the rounding exploit across the vault's other lenders.
