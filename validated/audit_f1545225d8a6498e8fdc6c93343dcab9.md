### Title
Bad-debt socialization eligibility miscalculated with `liq-penalty-max` instead of the position's actual liquidation penalty, causing premature loss-socialization to all suppliers - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
In `liquidate`, the decision of whether to socialize a borrower's remaining debt as bad debt (`no-collateral-left`) depends on `other-debt-repayable`, which converts a borrower's *other* collateral (assets not being seized in this call) into a debt-repayable amount using the fixed `liq-penalty-max` rather than the position's actual graduated `liq-penalty` computed earlier in the same function. This mirrors the reported bug class of "a fee/percentage that should reflect the real, computed rate but instead uses an unrelated fixed value in a funds-sufficiency check" — except here the miscalculation doesn't just affect the caller, it decides whether **all lenders/suppliers** absorb a borrower's shortfall via `socialize-debt`.

### Finding Description
Inside `liquidate` [1](#0-0) , the function computes the position's actual graduated penalty:
```
(liq-params (calc-liquidation-params current-ltv ltv-liq-partial ltv-liq-full liq-penalty-min liq-penalty-max curve-exponent total-debt-usd))
(liq-penalty (get liq-penalty liq-params))
```
This `liq-penalty` is the correct, LTV-dependent bonus used to size the current seizure [2](#0-1) .

Later, when deciding whether the borrower has any other usable collateral to cover remaining debt (used to gate bad-debt socialization), the code recomputes a debt-repayable estimate for the *other* collateral assets, but hardcodes `liq-penalty-max` instead of reusing `liq-penalty`:
```
(other-debt-repayable
  (if (> other-coll-usd u0)
    (let ((other-adj (div-bps-down other-coll-usd (+ BPS liq-penalty-max)))
          ...)
      (mul-div-up other-scaled other-borrow-idx INDEX-PRECISION))
    u0))
``` [3](#0-2) 

Because `liq-penalty-max` is the maximum possible bonus (e.g. 10%), dividing collateral USD value by `(BPS + liq-penalty-max)` systematically *underestimates* how much debt that collateral can actually cover relative to the position's real, lower `liq-penalty` for positions not yet at the full-liquidation LTV threshold. This underestimate feeds directly into `no-collateral-left`:
```
(no-collateral-left (and
                      (is-eq coll-removed u0)
                      (or
                        (is-eq (len (get collateral pos-full)) u1)
                        (and
                          (is-eq (len (get collateral pos-full)) (len (get collateral position)))
                          (is-eq other-debt-repayable u0)))))
``` [4](#0-3) 

If `no-collateral-left` evaluates true, the borrower's remaining debt across all assets is force-socialized to the vault's suppliers via `socialize-debt-asset`/`socialize-debt` [5](#0-4) , which reduces `assets`/`lindex` in the underlying vault (`vault-usdc.clar`, etc.) — i.e. it writes down the exchange-rate index shared by every depositor [6](#0-5) .

**Root cause**: `other-debt-repayable` should use the same `liq-penalty` value computed for this liquidation (or the position's true applicable rate) instead of the constant `liq-penalty-max`, exactly as the external report calls out substituting an incorrect fee/rate in a funds-sufficiency style check.

### Impact Explanation
When `other-debt-repayable` is computed using `liq-penalty-max`, positions holding multiple collateral assets can be judged to have "no collateral left" to cover remaining debt even though, at the position's actual (lower) applicable penalty rate, the other collateral is worth enough to cover the residual debt. This triggers `socialize-debt-asset`, which strips the borrower's debt and forces the loss onto the vault's `assets` (LP-share-backed pool), diluting the returns of **every unrelated supplier** in that vault — a socialization of the loss to all suppliers that should not have happened, i.e. temporary/permanent freezing (loss) of unclaimed yield for depositors who had nothing to do with this borrower's position. This lands in the in-scope Impact category: theft/permanent-freezing of unclaimed yield socialized across suppliers.

### Likelihood Explanation
This triggers automatically any time a liquidator (an ordinary unprivileged actor) calls `liquidate` on a multi-collateral position that is only partially underwater (LTV between `ltv-liq-partial` and `ltv-liq-full`, where the real `liq-penalty` is well below `liq-penalty-max`) and the seized asset happens to consume the full balance of one collateral type while other collateral types remain. No special privileges or oracle manipulation are required — only a normal liquidation call on a position with more than one collateral asset type in the graduated liquidation range, which is an expected and common state for the protocol's liquidation curve.

### Recommendation
Use the position's actual computed `liq-penalty` (the same value used to size the current seizure) instead of the fixed `liq-penalty-max` when computing `other-debt-repayable`, so the socialization-eligibility check reflects the true value of the borrower's remaining collateral rather than a worst-case constant that systematically undercounts it.

### Proof of Concept
1. Borrower opens a position with two collateral assets, e.g. sBTC and stSTX, and debt in USDC, with LTV positioned inside the graduated liquidation band such that `calc-liquidation-params` yields `liq-penalty` significantly below `liq-penalty-max` (e.g. `liq-penalty` = 5% vs `liq-penalty-max` = 10%).
2. A liquidator calls `liquidate` targeting the sBTC collateral for partial/near-full debt repay such that all of the sBTC balance is consumed (`coll-removed` for sBTC becomes the full balance, i.e., `coll-final == user-coll-balance`), while the borrower still holds a non-trivial stSTX balance.
3. In computing `other-debt-repayable` for the remaining stSTX, the contract divides `other-coll-usd` by `(BPS + liq-penalty-max)` instead of `(BPS + liq-penalty)`, understating how much debt the stSTX can cover.
4. If this understated value rounds to `u0` (or is simply less than the actual remaining debt, satisfying the `is-eq other-debt-repayable u0` branch), `no-collateral-left` is set `true` even though, using the real `liq-penalty`, the stSTX collateral would in fact be valued high enough to not warrant socialization.
5. `socialize-debt-asset`/`socialize-debt` is invoked, writing down the vault's `lindex`/`assets`, socializing the shortfall across all USDC suppliers — even though the borrower's stSTX collateral (correctly valued) should have covered the debt without any protocol-wide loss.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
