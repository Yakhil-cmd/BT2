## Confirmed Vulnerability

**Broken binding (equality claimed):** `Shipit.github(organization: repository_owner).webhook_secret` (used to authenticate the request in `WebhooksController#verify_signature`) should equal the org actually owning the `Repository`/`ReviewStack` that gets mutated via `params.repository.full_name` in `ClosedHandler`/`ReviewStackAdapter#archive!`. **These are two independently attacker-controlled/looked-up values and nothing in the code enforces they match.**

### Trace

- `WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret` used for HMAC verification) purely from `repository_owner`, i.e. `params.dig('repository','owner','login')`: [1](#0-0) [2](#0-1) 

- `Shipit.github(organization:)` looks up per-org GitHub App config by name only — this is the documented "Multiple GitHub Applications" feature, letting a single Shipit instance host distinct orgs each with their own `webhook_secret`: [3](#0-2) [4](#0-3) 

- Once signature verification passes, `ClosedHandler#repository` resolves the actual repository being mutated using **only** `params.repository.full_name`, with no cross-check against `repository_owner`/the org whose secret authenticated the request: [5](#0-4) [6](#0-5) 

- `ReviewStackAdapter#archive!` then performs the destructive mutation (`remove_from_provisioning_queue`, `deprovision`, `archive!`) on whatever stack matches `environment` under that resolved repository's scope — again with no owner check: [7](#0-6) 

- The base `Handler` class exhibits the identical pattern generally (`stacks` is scoped by `payload.dig('repository','full_name')` with no owner binding), confirming this is systemic, not a one-off bug in `ClosedHandler`: [8](#0-7) 

### Why existing guards don't help

- `verify_signature`'s only failure mode (`GithubOrganizationUnknown` → 422) triggers when `repository_owner` isn't a configured org at all — it does **not** check that `repository_owner` matches the org that owns `params.repository.full_name`.
- `Repository` model validations (`owner`/`name` format/length) only constrain string shape, not tenant ownership relative to the authenticating org.
- `respond_to_pull_request_closed?` only checks `action == "closed"`, irrelevant to this binding.
- `ExplicitParameters` schema in `ClosedHandler` only requires `repository.full_name` to be a `String` — it enforces no relationship to `owner.login`.

### Precondition caveat (this materially limits exploitability)

This attack is only possible on a Shipit instance that uses the **multi-org GitHub App config** (i.e., `secrets.github` has multiple top-level org keys, each attacker- and victim-controlled orgs both onboarded to the same Shipit instance, each with distinct `webhook_secret`s). In the default single-org configuration, `github_default_organization` returns `nil` and `Shipit.github` uses the single top-level `secrets.github` config regardless of payload content, so `repository_owner` doesn't select between secrets at all — there is only one secret, and an attacker without it cannot forge a valid signature. The attack requires: (1) multi-org config is enabled, (2) attacker owns/administers one of the configured orgs (has its legitimate webhook_secret because their own GitHub App fires webhooks to Shipit signed with it), (3) victim-org repo has `review_stacks_enabled` and a live `ReviewStack` at `pr#{number}`.

### Impact

Given multi-org config, an attacker who legitimately controls Org A (onboarded to the shared Shipit instance) can send a `pull_request` `closed` webhook signed with Org A's own secret but with `repository.full_name` set to `victim-org/victim-repo` and a `number` matching a live victim `ReviewStack`. This forces `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!` on the victim's stack — an unauthorized, destructive state mutation of another tenant's `ReviewStack` triggered purely with the attacker's own credentials. This matches "a payload for one repository mutating another's stack" (Critical).

### Recommendation
In `WebhooksController#verify_signature` (or in each `Handler`), after resolving the org from `owner.login`/`organization.login`, verify that `params.dig('repository','full_name')` (or `payload.dig('repository','full_name')`) actually starts with `"#{repository_owner}/"` before dispatching to handlers, rejecting mismatches with 422.

### Proof of Concept (test plan, no live GitHub)
In `test/controllers/webhooks_controller_test.rb` under a multi-org secrets fixture (e.g. reuse `test/dummy/config/secrets_double_github_app.yml` with `OrgOne`/`OrgTwo`):
1. Configure `Repository` `owner: "orgtwo"` (victim) with `review_stacks_enabled` and create a live `ReviewStack` with `environment: "pr7"`.
2. Stub `Shipit.github(organization: "orgone").verify_webhook_signature` to return `true` (simulating attacker's own valid Org-One signature).
3. POST a `pull_request` `closed` webhook with `X-Github-Event: pull_request`, body `{"action":"closed","number":7,"repository":{"owner":{"login":"orgone"},"full_name":"orgtwo/victim-repo"}, "pull_request": {...}, "sender": {...}}`.
4. Assert `Shipit::ReviewStack.any_instance.expects(:deprovision)` (and `:archive!`) is invoked on the victim's stack — i.e., `stack.reload.archived?` becomes true — despite the signature only having been checked against `orgone`'s secret, not `orgtwo`'s.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
