### Title
Webhook signature verification is keyed on `repository.owner.login` while payload effects are keyed on `repository.full_name`, letting an unsigned/wrongly-signed payload act on an unrelated stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to verify a webhook against using `repository_owner`, which reads `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`). [1](#0-0) [2](#0-1)  Once that check passes, the very same raw payload is dispatched to handlers that instead resolve the target `Repository`/`Stack` using the sibling field `repository.full_name`. [3](#0-2)  `GithubApp#verify_webhook_signature` additionally short-circuits to `true` whenever the resolved organization has no `webhook_secret` configured at all, which the shipped multi-org secrets template treats as a normal/valid setup. [4](#0-3) [5](#0-4) 

### Finding Description
The equality the engine relies on is: `organization that authenticated == repository that is written`. In `verify_signature`, the app resolves `Shipit.github(organization: repository_owner)` purely from the JSON field `repository.owner.login`, and uses that org's secret (if any) to HMAC-verify the whole raw body. [1](#0-0)  But every handler that actually mutates state (`Handler#stacks`/`#repository_name`, and the `PullRequest::OpenedHandler#repository` lookup) resolves the target repository from the *different* field `repository.full_name`. [3](#0-2) [6](#0-5)  Nothing enforces that `repository.owner.login` matches the owner encoded in `repository.full_name`; they are independent, attacker-controlled JSON leaves under the same top-level `repository` object.

Compounding this, `verify_webhook_signature` is a no-op (`return true unless webhook_secret`) for any configured organization that has no `webhook_secret` set — a state the project's own secrets template presents as acceptable (`webhook_secret: # nil`). [4](#0-3) [7](#0-6)  On any Shipit deployment that manages more than one GitHub organization and leaves at least one of them without a webhook secret (a documented configuration, not a misconfiguration), an unauthenticated internet client can POST directly to the public webhooks endpoint with `repository.owner.login` set to the secret-less org (so `verify_signature` trivially passes with no real signature check) while setting `repository.full_name` to a *different*, secured organization's repository. The dispatched handler then acts on that unrelated repository/stack using payload fields never covered by any real signature.

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" trust binding called out for this bug class. Depending on event type, the effect ranges from unauthenticated writes into a real repository's tracked state (e.g. `push`/`status`/`check_suite` handlers touching commits and statuses of a repository the requester never controlled) up to PR-driven state changes such as review-stack provisioning via `PullRequest::OpenedHandler` → `ReviewStackAdapter.find_or_create!`, which can result in an unauthorized stack/task being created and executed against a victim repository. [8](#0-7)  This lands in the High-impact tier: unauthenticated read/write of stack state via a forged webhook, effectively acting on a repository outside the credential boundary that was actually checked.

### Likelihood Explanation
Exploitation requires only an unauthenticated HTTP POST to the engine's public `/webhooks` endpoint (no session, no API token, no GitHub App key needed) and relies solely on a supported, plausible multi-org configuration where one configured organization lacks a `webhook_secret` — exactly the shape shown in the project's own multi-org secrets example. No social engineering, TLS interception, or privileged credentials are required, making this readily reachable wherever multiple GitHub orgs are configured and not all of them enforce a webhook secret.

### Recommendation
Derive the signing/verification organization and the write-target repository from the same authenticated source rather than two independent payload fields: after signature verification succeeds, re-derive `repository.owner.login` from `repository.full_name` (or vice versa) and reject the request if they disagree. Additionally, stop treating a missing `webhook_secret` as "verification passes" for organizations that also have any repository under management — either require a secret whenever an organization has a linked `Repository`/`Stack`, or fail closed instead of `return true unless webhook_secret` in `GithubApp#verify_webhook_signature`. [4](#0-3) 

### Proof of Concept
1. Operator configures Shipit with two GitHub orgs in `secrets.yml`: `victim-org` (has `webhook_secret` set, owns a tracked `Stack` for `victim-org/victim-repo`) and `test-org` (no `webhook_secret`, as shown acceptable in `config/secrets.development.shopify.yml`). [5](#0-4) 
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a JSON body where `repository.owner.login = "test-org"` (drives secret lookup) but `repository.full_name = "victim-org/victim-repo"` (drives the handler's repository lookup), and no/garbage `X-Hub-Signature`.
3. `verify_signature` computes `Shipit.github(organization: "test-org")`; since `test-org` has no `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally regardless of the header value. [1](#0-0) [4](#0-3) 
4. `Shipit::Webhooks.for_event('pull_request')` dispatches to `PullRequest::OpenedHandler`, which resolves `Shipit::Repository.from_github_repo_name(params.repository.full_name)` → `victim-org/victim-repo`, and if provisioning is enabled for that repo, creates/looks up a review stack for it — all triggered by a request that was never actually signed for that repository. [9](#0-8)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
