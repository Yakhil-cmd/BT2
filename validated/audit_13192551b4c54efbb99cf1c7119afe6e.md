## Analysis Result

This is a valid analog. The binding broken is: **the organization whose webhook secret is used to authenticate the request (`repository_owner` derived from the unverified payload) ≠ the organization/repository whose records are actually written by the handler (`payload.dig('repository', 'full_name')`)**.

### Title
Webhook signature verification keys off an attacker-controlled field, and a blank/misconfigured org secret allows forged events for a different repository - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Finding Description
In a multi-org configuration, `WebhooksController#verify_signature` selects which GitHub App (and therefore which `webhook_secret`) to verify the request against by reading `repository_owner`/`organization.login` straight out of the **unverified** JSON body: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` then looks up that organization's config and builds a `GitHubApp` keyed by the attacker-chosen org name: [3](#0-2) .

Signature verification itself is `return true unless webhook_secret` — if the selected organization has no `webhook_secret` configured (a supported, documented state — see `webhook_secret: # nil` in every secrets example, including the multi-org fixture `test/dummy/config/secrets_double_github_app.yml`), verification trivially passes for **any** payload: [4](#0-3) .

Once past `verify_signature`, the handler layer never re-checks the organization; it dispatches purely on `payload.dig('repository', 'full_name')` to find the `Stack`/`Repository` to act on: [5](#0-4) , and `PushHandler#process` calls `stack.sync_github(expected_head_sha: params.after)` on whatever stacks match that name: [6](#0-5) .

So the equality that should hold — `organization used to select/verify the webhook secret == organization that owns the repository being mutated` — is never enforced. An attacker only needs `organization.login` (or `repository.owner.login`) in the payload to equal a **misconfigured/secret-less** org entry, while `repository.full_name` in the same payload can reference a stack belonging to a **different, properly-secured** org/repo tracked by the same Shipit instance. Verification succeeds (because the picked org has no secret), but the mutation targets a repository that was never meant to trust that unauthenticated path.

### Impact Explanation
This allows an unauthenticated attacker to forge GitHub webhooks (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) that get applied to any tracked stack whose full_name is guessed/known, as long as any other configured org in the same Shipit deployment lacks (or the operator forgot to set) a `webhook_secret`. This can trigger `GithubSyncJob`, fabricate commit statuses that gate `ci.require`, or manipulate `Membership`/`Team` records used for `Shipit.github_teams` authorization — i.e., escalation into the app's authorization model, matching the High-severity bucket ("escalation into `Shipit.github_teams` authorization").

### Likelihood Explanation
Requires: (1) a multi-org Shipit deployment (explicitly supported and documented), and (2) at least one configured organization with a blank `webhook_secret` — which is the literal default/example value shown in every secrets template in this repo (`config/secrets.development.example.yml`, `template.rb`, `test/dummy/config/secrets_double_github_app.yml`). Given the docs explicitly mark `webhook_secret` as "(optional)" in `docs/setup.md`, this misconfiguration is realistic and encouraged by the defaults, making likelihood moderate-to-high in real deployments that mix orgs with/without a secret.

### Recommendation
Bind the verified secret to the repository actually being mutated, not to an unauthenticated field chosen by the attacker: derive/validate the acting organization only after establishing trust (e.g., verify against every configured org's secret and require a match, or require a non-blank `webhook_secret` for all configured organizations before accepting events), and reject events whose `repository.full_name` organization differs from the organization whose secret validated the signature.

### Proof of Concept
1. Deploy Shipit with two orgs configured: `OrgTrusted` (has `webhook_secret` set) and `OrgOpen` (no `webhook_secret`, i.e., `nil`), both is documented as valid/example configuration.
2. Attacker crafts a POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "organization": { "login": "OrgOpen" },
  "repository": { "full_name": "OrgTrusted/secret-repo", "owner": { "login": "OrgOpen" } },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>"
}
```
3. `repository_owner` resolves to `OrgOpen`; `Shipit.github(organization: "OrgOpen")` returns a `GitHubApp` with `webhook_secret` blank, so `verify_webhook_signature` returns `true` unconditionally regardless of the (missing/garbage) `X-Hub-Signature` header.
4. `PushHandler` then looks up stacks by `payload.dig('repository', 'full_name')` == `OrgTrusted/secret-repo` and calls `sync_github(expected_head_sha: "<attacker-chosen-sha>")` on it, causing Shipit to sync/consider a forged head SHA for a repository outside the attacker's control, unauthenticated with respect to `OrgTrusted`.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
