### Title
Unauthenticated P2P Staking Info Injection Bypasses Content Validation, Corrupting Pre-Kaia Reward Distribution — (`datasync/downloader/queue.go`)

### Summary

During fast sync, staking information received from a remote peer is written directly to the local database without any content validation. The `validate` callback in `queue.DeliverStakingInfos` is an explicit no-op (marked `TODO`). Any connected peer can supply fabricated `P2PStakingInfo` payloads — with wrong staking amounts, wrong reward addresses, or wrong fund addresses — that are persisted and later consumed verbatim by `GetStakingInfo` for pre-Kaia blocks, causing incorrect KAIA reward distribution.

### Finding Description

`queue.DeliverStakingInfos` is the delivery endpoint for staking info received over the P2P wire during fast sync:

```go

It also feeds `getDemotedValidatorsIstanbul` / `collectStakingAmounts`, which determines which validators are qualified for block production: [7](#0-6) 

The same DB-backed path is exposed through the `SyncStakingInfo` admin API, where the only check is that `stakingInfo.BlockNum` matches the requested sequence — content is never verified: [8](#0-7) 

### Impact Explanation

A malicious peer connected during fast sync can supply `P2PStakingInfo` records with:

- **Inflated staking amounts** for its own node → receives a disproportionately large share of KAIA block rewards (unauthorized reward transfer).
- **Substituted `RewardAddrs`** → KAIA staking rewards are redirected to attacker-controlled addresses.
- **Substituted `KEFAddr` / `KIFAddr`** → ecosystem/infrastructure fund allocations are redirected.
- **Deflated staking amounts** for a target validator → that validator is demoted from the qualified set, disrupting consensus participation.

All of these constitute unauthorized transfer or misdirection of KAIA rewards and system-managed funds, matching the allowed impact gate.

### Likelihood Explanation

Any peer that successfully completes the Kaia P2P handshake can send a `StakingInfoMsg` (message code handled at `kaia65+`). The handler `handleStakingInfoMsg` decodes the message and calls `DeliverStakingInfos` with no caller authentication beyond peer connection: [9](#0-8) 

The attack window is any node performing fast sync over pre-Kaia blocks. New nodes syncing from genesis traverse this range. The TODO comment in the validate callback confirms the gap is known but unimplemented.

### Recommendation

Replace the no-op `validate` callback in `queue.DeliverStakingInfos` with a check that re-derives the staking info from the canonical block state (via `getFromState`) and compares it against the peer-supplied data. At minimum, validate that `StakingAmounts`, `NodeIds`, `RewardAddrs`, and fund addresses match what the local node would compute from the block's state root. If re-derivation is too expensive inline, reject any staking info whose `BlockNum` does not correspond to a locally-known canonical block hash, and schedule async verification before committing to DB.

### Proof of Concept

1. Attacker connects to a victim node that is fast-syncing pre-Kaia blocks (e.g., a new node syncing from genesis on Kairos testnet).
2. Attacker responds to `StakingInfoRequestMsg` with a crafted `StakingInfoMsg` containing a `P2PStakingInfo` for source block `S` with:
   - `StakingAmounts[attacker_node] = 999_000_000` (inflated)
   - `RewardAddrs[attacker_node] = attacker_wallet`
3. `handleStakingInfoMsg` → `DeliverStakingInfos` → `queue.DeliverStakingInfos` accepts the payload; `validate` returns `nil`.
4. `commitFastSyncData` calls `PutStakingInfoToDB(S, fabricated_info)`.
5. When the victim node later processes blocks in the epoch `[S, S+StakingInterval)` via full sync, `GetStakingInfo` reads the fabricated record from DB (cache miss falls through to `ReadStakingInfo`).
6. `FinalizeState` → `assignStakingRewards` distributes KAIA staking rewards proportional to the fabricated amounts, sending the attacker's share to `attacker_wallet` instead of the legitimate reward address.

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
```

func collectStakingAmounts(nodes []common.Address, si *staking.StakingInfo) map[common.Address]float64 {
	cns := si.ConsolidatedNodes()
	stakingAmounts := make(map[common.Address]float64, len(nodes))
	for _, node := range nodes {
		stakingAmounts[node] = 0
	}
	for _, cn := range cns {
		for _, node := range cn.NodeIds {
			if _, ok := stakingAmounts[node]; ok {
				stakingAmounts[node] = float64(cn.StakingAmount)
			}
		}
	}
	return stakingAmounts

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
