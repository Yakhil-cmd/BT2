### Title
CCMenu client token authorizes reading every stack, not just the stack it was generated for - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`CCMenuUrlController#fetch` mints a `read:stack` `ApiClient` token to embed in a CCMenu/CCTray polling URL for one specific stack, but the created `ApiClient` is never bound (`stack:`) to that stack. Because `ApiClient#stack` is optional and `check_permissions!` only checks the `permissions` array (not the stack scope), the resulting token grants `read:stack` on **every** stack in the Shipit instance, not just the one the URL was generated for.

### Finding Description
`CCMenuUrlController#fetch` builds a stack-specific CCMenu URL and appends a bearer token: [1](#0-0) 

The client is looked up/created purely by `creator` and `name`, with `permissions: %w[read:stack]` and **no `stack:` attribute set**:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```

On the `ApiClient` model, `stack` is optional and permission enforcement is purely list-membership based, with no reference to the `stack_id` at all: [2](#0-1) 

`Api::BaseController` does correctly restrict the visible stack set when a client *is* scoped:
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
``` [3](#0-2) 

But `Api::CCMenuController` overrides `stack` to resolve directly by URL param, bypassing the `stacks` scoping helper entirely, and overrides `authenticate_api_client` to accept the token straight from a query-string `params[:token]`: [4](#0-3) 

Because the "CCMenu Client" is created with `stack_id = nil` (global read:stack), and `stacks_controller`/`ccmenu_controller` treat `stack_id.nil?` as "no restriction" (see `stacks` helper above), any token minted by `CCMenuUrlController#fetch` for stack A is equally valid to call `GET /api/stacks/<B>/ccmenu` for any other stack B in the installation.

This is the same class of bug as the Sherlock M-14 report: a value that *should* scope/limit a computed authorization (`reserves` limiting usable `liquidity`; here, `stack_id` limiting the token's `read:stack` grant) is silently dropped/ignored when the object granting the permission is constructed, so the effective authorization ends up broader ("all balance"/"all stacks") than what the caller intended and the UI implies ("this stack's CCMenu link"/"available liquidity minus reserves").

The binding broken: *the stack a token is generated (and named) for* ≠ *the stack(s) the token actually authorizes reading*.

### Impact Explanation
Any holder of a single CCMenu URL — which is explicitly designed to be pasted into third-party desktop/CI widgets, dashboards, or shared build-status tools, i.e. handled and often logged/cached by systems with weaker security expectations than the main Shipit session — can use the embedded `token` query parameter to read the build/deploy/lock status (`GET /api/stacks/*/ccmenu`) of **every stack configured in the Shipit instance**, including stacks belonging to entirely different repositories/teams that the token holder was never meant to see. This matches the in-scope "unauthenticated read of stack state" High-impact category, since the attacker needs neither a Shipit session, GitHub credentials, nor knowledge of which stacks exist — only one leaked CCMenu link.

### Likelihood Explanation
Likelihood is moderate-to-high: CCMenu/CCTray URLs are a documented, user-facing feature meant to be copied out of the Shipit UI and pasted into external tools; such links (with embedded tokens as query strings) are routinely logged by proxies/CDNs, stored in browser history, or shared over chat, making leakage plausible. No privileged access, GitHub identity, or session is required to exploit the leaked token — it "just works" against any stack path.

### Recommendation
Bind the CCMenu `ApiClient` to the specific stack it is generated for, and enforce that scope consistently:
1. In `CCMenuUrlController#client`, include `stack:` in the `find_or_create_by!`/`create_with` call (e.g., scope the client per `(creator, stack)` pair rather than a single global "CCMenu Client" per user).
2. In `Api::CCMenuController#stack`, resolve the stack through the same `stacks` (client-scoped) helper used by `BaseController`, instead of `Stack.from_param!(params[:stack_id])` directly, so a stack-scoped token cannot be replayed against other stacks.

### Proof of Concept
1. As an authenticated Shipit user, visit a stack's settings page and request its CCMenu URL, e.g. `GET /ccmenu/myorg/repoA/production` → response includes `ccmenu_url: ".../api/stacks/myorg/repoA/production/ccmenu?token=<TOKEN>"`.
2. Save `<TOKEN>` (e.g., as it would appear leaked from a widget's config file or proxy log).
3. Without any session or additional credentials, call:
   `GET /api/stacks/otherorg/repoB/staging/ccmenu?token=<TOKEN>`
4. The request succeeds and returns build/deploy status for `otherorg/repoB/staging`, a stack unrelated to the one for which the token/URL was originally generated — confirming the token is not actually scoped to the intended stack.

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end
end

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
