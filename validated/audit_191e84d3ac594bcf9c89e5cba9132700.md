### Title
Silent CL Reward Exclusion When Multiple NodeIds Sharing the Same RewardAddr Each Register a CLStakingInfo — (`kaiax/staking/staking_info.go`)

### Summary

`consolidateNodes()` in `kaiax/staking/staking_info.go` silently overwrites the first `CLStakingInfo` with the last one when two NodeIds that share the same `RewardAddr` both have registered consensus-liquidity (CL) pools. The overwritten CL pool address is never added to the reward allocation map, so its liquidity providers receive zero KAIA per block. The reward denominator is also wrong because the dropped CL's staking amount is excluded from `totalExcessInt`, causing every other recipient's share to be inflated.

### Finding Description

The AddressBook explicitly supports multiple NodeIds sharing one `RewardAddr` (the "consolidation" feature). The CLRegistry independently guarantees at most one CL per NodeId. These two invariants are compatible: two NodeIds `N1` and `N3` can share `RewardAddr R1` while each independently registering a CL pool (`CL1`, `CL2`).

`consolidateNodes()` builds a `cmap` keyed by `RewardAddr`. When it processes the `CLStakingInfos` slice it does:

```go
// kaiax/staking/staking_info.go  lines 151-159
for _, clsi := range si.CLStakingInfos {
    if r, ok := nToR[clsi.CLNodeId]; ok {
        // One CLStakingInfo per validator is guaranteed by CLRegistry.
        cmap[r].CLStakingInfo = clsi   // ← plain assignment, not accumulation
    }
}
``` [1](#0-0) 

When `N1 → R1` and `N3 → R1` both appear in `nToR`, the loop first writes `CL1` into `cmap[R1].CLStakingInfo`, then immediately overwrites it with `CL2`. `CL1` is permanently lost from the consolidated node.

The comment "One CLStakingInfo per validator is guaranteed by CLRegistry" is correct at the NodeId level but does not prevent two NodeIds under the same `RewardAddr` from each having a CL. The test suite acknowledges the overwrite in the case labelled `"4 nodes consolidated to 2 nodes and one node has two CLs"` and dismisses it as `"not feasible in real"`, but no on-chain constraint enforces this. [2](#0-1) 

Downstream, `assignStakingRewards` and `assignStakingRewardsFlex` both call `cn.Split(reward)` which uses only the surviving `CLStakingInfo`:

```go
// kaiax/reward/impl/getter.go  lines 521-525
if isPrague && cn.CLStakingInfo != nil {
    cnAmount, clAmount := cn.Split(reward)
    alloc[cn.RewardAddr] = cnAmount
    alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount   // only CL2's pool
}
``` [3](#0-2) 

`Split()` divides the reward using `c.StakingAmount` (correct: sum of all CNStaking) and `c.CLStakingInfo.CLStakingAmount` (wrong: only CL2's amount, CL1's amount is missing):

```go
// kaiax/staking/staking_info.go  lines 169-186
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    cnAmountBig = big.NewInt(int64(c.StakingAmount))
    clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))  // CL1 excluded
    totalAmount = cnAmountBig + clAmountBig
    ...
}
``` [4](#0-3) 

The same missing amount propagates into `totalExcessInt` in both `assignStakingRewards` and `assignStakingRewardsFlex`, skewing every staker's proportional share. [5](#0-4) 

The final `FinalizeState` distributes the corrupted `spec.Rewards` map directly to state balances:

```go
// kaiax/reward/impl/blockstate.go  lines 53-55
for addr, amount := range spec.Rewards {
    state.AddBalance(addr, amount)
}
``` [6](#0-5) 

### Impact Explanation

**Concrete example** (Prague hardfork, `assignStakingRewards`):

| Entity | Staking | Correct reward share | Actual reward share |
|--------|---------|---------------------|---------------------|
| CN (R1) | 20 M KAIA | 20/28 | 20/23 (+inflated) |
| CL1 pool | 5 M KAIA | 5/28 | **0** (silently dropped) |
| CL2 pool | 3 M KAIA | 3/28 | 3/23 (+inflated) |

Every block after Prague hardfork, CL1's pool address receives zero KAIA instead of its proportional share. The KAIA that should have gone to CL1 is instead split between the CN reward address and CL2's pool. This is an unauthorized redistribution of KAIA block rewards affecting system-managed funds.

### Likelihood Explanation

The trigger requires:
1. A GC member registers two or more NodeIds in the AddressBook under the same `RewardAddr` (explicitly supported and documented).
2. Two or more of those NodeIds independently register CL pools in the CLRegistry (no contract prevents this).

Both conditions are valid, permissioned-but-not-privileged operations. No majority-validator collusion is needed; a single GC member who legitimately uses both features simultaneously triggers the bug. The code itself acknowledges the scenario exists (test case present) but incorrectly assumes it cannot occur in production.

### Recommendation

Replace the plain assignment with accumulation in `consolidateNodes()`. The consolidated node should carry a slice of `CLStakingInfo` entries (one per NodeId that has a CL), and `Split()` should sum all CL amounts when computing the denominator and distribute to each CL pool proportionally:

```go
// Instead of:
cmap[r].CLStakingInfo = clsi

// Accumulate:
cmap[r].CLStakingInfos = append(cmap[r].CLStakingInfos, clsi)
```

`Split()` and all callers in `assignStakingRewards` / `assignStakingRewardsFlex` / `specWithProposerAndFunds` must be updated to iterate over the slice and emit one `alloc` entry per CL pool.

### Proof of Concept

Setup (Prague hardfork active, `assignStakingRewards`):

```
AddressBook:
  NodeId=N1, StakingContract=S1, RewardAddr=R1, StakingAmount=10_000_000 KAIA
  NodeId=N3, StakingContract=S3, RewardAddr=R1, StakingAmount=10_000_000 KAIA

CLRegistry:
  N1 → CLPool1, CLStakingAmount=5_000_000 KAIA
  N3 → CLPool2, CLStakingAmount=3_000_000 KAIA

MinimumStake = 5_000_000 KAIA
stakersReward = 1e18 kei
```

After `consolidateNodes()`:
- `cmap[R1].CLStakingInfo` = `{N3, CLPool2, 3_000_000}` (CL1 overwritten)

`assignStakingRewards` computes:
- `cnTotalStakingAmount` = 20_000_000 + 3_000_000 = 23_000_000 (CL1's 5M missing)
- `totalExcessInt` = 23_000_000 − 5_000_000 = 18_000_000
- `reward` = 1e18 × 18/18 = 1e18 kei
- `Split(1e18)` → CN gets 1e18 × 20/23, CLPool2 gets 1e18 × 3/23
- **CLPool1 receives 0 kei** (should receive 1e18 × 5/28 ≈ 1.786e17 kei per block)

The `FinalizeState` call writes these values directly to the EVM state, permanently denying CLPool1's liquidity providers their KAIA block rewards. [7](#0-6) [8](#0-7)

func (si *StakingInfo) consolidateNodes() *[]consolidatedNode {
	// because Go map is not ordered, rList keeps track of the occurrence order of RewardAddrs.
	// to later arrange the consolidatedNodes.
	cmap := make(map[common.Address]*consolidatedNode)
	rList := make([]common.Address, 0, len(si.RewardAddrs))
	nToR := make(map[common.Address]common.Address)

	for i, n := range si.NodeIds {
		r := si.RewardAddrs[i]
		// Unique nodeId is guaranteed by AddressBook.
		nToR[n] = r
		if cn, ok := cmap[r]; ok {
			cn.NodeIds = append(cn.NodeIds, n)
			cn.StakingContracts = append(cn.StakingContracts, si.StakingContracts[i])
			cn.StakingAmount += si.StakingAmounts[i]
		} else {
			cmap[r] = &consolidatedNode{
				NodeIds:          []common.Address{n},
				StakingContracts: []common.Address{si.StakingContracts[i]},
				RewardAddr:       r,
				StakingAmount:    si.StakingAmounts[i],
			}
			rList = append(rList, r)
		}
	}

	// CLStakingInfo can only exist after Prague HF.
	if len(si.CLStakingInfos) > 0 {
		for _, clsi := range si.CLStakingInfos {
			// If the nodeId of CLStakingInfo is not found in nToR, it means the validator is not in the AddressBook.
			// So we skip it.
			if r, ok := nToR[clsi.CLNodeId]; ok {
				// One CLStakingInfo per validator is guaranteed by CLRegistry.
				cmap[r].CLStakingInfo = clsi
			}
		}
	}

	carr := make([]consolidatedNode, 0, len(cmap))
	for _, r := range rList {
		carr = append(carr, *cmap[r])
	}
	return &carr

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
```

```go
// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
