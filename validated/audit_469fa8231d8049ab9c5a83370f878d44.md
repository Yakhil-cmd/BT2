### Title
Permanent market freeze: interest accrual panics in `scaled_to_original` before the borrow-index cap can engage - (File: contracts/pool/src/interest.rs)

### Summary
Like CVE-2021-25218, where a specially crafted query drives `named` into a failed assertion that kills the whole process, XOXNO Lending's pool has a reachable `MathOverflow` panic inside the accrual step that precedes every market mutation. Because `global_sync` runs before `withdraw`, `repay`, `liquidate`, and every other verb, once the panic condition exists the market is bricked permanently — no exit or repayment can ever execute again.

### Finding Description
Every pool entrypoint calls `Cache::load` then `interest::global_sync`, which loops `accrue_chunk` over `accrue_step` to compound indexes [1](#0-0) . `accrue_step` (in `common::rates`) unscaled debt via `scaled_to_original` — `scaled_shares * borrow_index` in fixed point — to compute utilization and the next rate. Both `borrowed` scaled shares and `borrow_index` grow with whale-sized positions and sustained high utilization; their product overflows `i128` and the checked arithmetic panics with `MathOverflow`.

A cap `MAX_BORROW_INDEX_RAY` exists to bound the index, but the value overflow fires *inside* the step's unscaling *before* the cap check ever runs — the panic aborts the transaction, the new (capped) index is never committed, and the next call re-runs the same accrual and panics identically. The project's own test proves this end-to-end: after a whale market sits at 98% utilization for a number of years, `update_indexes` fails with `MATH_OVERFLOW`, `last.borrow_index < MAX_BORROW_INDEX_RAY` ("the index cap did not engage before the value overflow"), and both `withdraw` and `repay` then fail with the same error — the market is frozen [2](#0-1) .

### Impact Explanation
Permanent freezing of funds. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate — every path accrues first and hits the panic. All cash held by that market's pool is locked forever, and underwater positions can never be cleaned up, turning a soft insolvency into total loss of the market's cash.

### Likelihood Explanation
Reachable by an unprivileged address: `supply` and `borrow` are permissionless, and pushing a market to near-max utilization is normal protocol use (a whale or coordinated attacker supplies and borrows a very large position on a high-decimal asset with a steep rate curve). The trigger is then passive — time itself compounds the index — and any later call to `update_indexes` or any mutation locks it in. The requirement is large capital and high sustained utilization on a steep curve, which is plausible for real-money markets but not trivially cheap, keeping it Medium/High rather than critical.

### Recommendation
In `accrue_step` (common::rates) or `accrue_chunk` (contracts/pool/src/interest.rs), apply the borrow-index cap *before* unscaling debt for rate computation, and clamp the unscaled values with saturating/capped math instead of panicking on `scaled * index`. Alternatively, detect when the step would exceed `MAX_BORROW_INDEX_RAY`, commit the capped index, and skip rate recomputation, so accrual degrades gracefully instead of bricking every downstream entrypoint.

### Proof of Concept
See `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs` [3](#0-2) : supply `10^9` units of an 18-decimal asset, borrow 98% of it, advance time until `try_update_indexes` returns `MATH_OVERFLOW`; afterwards `try_withdraw_raw` and `try_repay` both fail with `MATH_OVERFLOW`, confirming permanent freeze with the index cap never engaged.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
