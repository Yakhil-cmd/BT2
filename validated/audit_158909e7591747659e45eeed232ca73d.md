## Title
Unvalidated `payload` dereference in `handleOnlinePrivatePayment` allows a peer-sent `private_payment` message to crash the node - (File: network.js)

### Summary
`network.js`'s `handleOnlinePrivatePayment` dereferences `arrPrivateElements[0].payload.denomination` before ever checking that `.payload` exists, mirroring the CVE-2025-40240 root cause where a buffer pointer (`chunk->skb`) is dereferenced based on the wrong precondition (only the outer container was checked, not the field actually being accessed).

### Finding Description
`handleOnlinePrivatePayment` is the entry point for the `private_payment` network message that any connected peer can send directly (single-element head chain path) or that is queued through `unhandled_private_payments`/`handleSavedPrivatePayments` (multi-element chain path): [1](#0-0) 

The only structural checks performed before dereferencing are:
- `arrPrivateElements` is a non-empty array (`ValidationUtils.isNonemptyArray`)
- Later, `unit` and `message_index` are checked

But `output_index` is computed as `arrPrivateElements[0].payload.denomination ? arrPrivateElements[0].output_index : -1` — this reads `.payload.denomination` without first confirming that `arrPrivateElements[0].payload` is even an object. Because `arrPrivateElements` is parsed straight from attacker-controlled JSON (`JSON.parse` of the incoming network `body.content`, ultimately passed here), an attacker can send `[{"unit": "<64-char b64>", "message_index": 0}]` with no `payload` key at all (or `payload: null`), causing `arrPrivateElements[0].payload.denomination` to throw a `TypeError: Cannot read properties of undefined`.

This is structurally identical to the SCTP bug class: the code validates one condition (`isNonemptyArray`) but dereferences a nested field (`payload.denomination`) that was never independently validated for existence, exactly as `chunk->skb` was dereferenced under a check that only verified `chunk->head_skb`, not `chunk->skb`/`frag_list` itself.

By contrast, the higher-level hub-relay path `handlePrivatePaymentChains` in `wallet.js` *does* validate `isNonemptyObject(e.payload)` for every chain element before calling `handleOnlinePrivatePayment`: [2](#0-1) 

...but `handleOnlinePrivatePayment` is also reachable directly as the network-level `private_payment` message handler (not solely through the hub-validated wallet.js path), so a peer can hit the unguarded code path directly with a malformed message.

### Impact Explanation
An unhandled `TypeError` thrown synchronously inside the WebSocket message-handling callback stack will propagate up and, depending on Node's/ocore's top-level error handling, can crash the node process (uncaught exception) or leave the connection/queue in an inconsistent state. This falls under "a network unable to confirm new units" if repeated/broadcastable crashes affect multiple full or light nodes reachable by any peer that can open a connection and send a `private_payment` message — no special privileges are required, matching the "network-wide DoS via malformed data" pattern of the reference CVE, but reachable here through the ocore private-payment message path rather than SCTP.

### Likelihood Explanation
Likelihood is high for any node that accepts inbound peer connections and processes `private_payment` messages, since the malformed payload requires no valid signatures, no stable units, and no prior state — just a syntactically-arrayed JSON object with a missing `payload` field. The check ordering bug is a straightforward oversight (missing `isNonemptyObject(payload)`/`"payload" in element` check before the ternary that reads `payload.denomination`).

### Recommendation
Add an explicit non-empty-object check on `arrPrivateElements[0].payload` before evaluating `arrPrivateElements[0].payload.denomination` in `handleOnlinePrivatePayment` (and ideally validate the shape of every element in `arrPrivateElements`, similar to the checks already used in `wallet.js`'s `handlePrivatePaymentChains`), returning `callbacks.ifError(...)` on failure instead of allowing the property access to throw.

### Proof of Concept
Send a WebSocket message to a listening ocore node with subject `private_payment` and content:
```json
[{"unit": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=", "message_index": 0}]
```
(a syntactically valid 44-char base64 `unit`, with no `payload` field). This reaches `handleOnlinePrivatePayment`, passes the `isNonemptyArray` check, and throws when evaluating `arrPrivateElements[0].payload.denomination` because `payload` is `undefined`.

*Note: I could not fully trace within the remaining budget the exact top-level `case 'private_payment':` dispatch code in `network.js` that calls `handleOnlinePrivatePayment` (the search found the case label but I did not retrieve its full body to confirm whether any additional payload-shape validation occurs immediately before the call). This should be verified directly in `network.js` around the `case 'private_payment'` handler before treating this as fully confirmed.*

```javascript
function handleOnlinePrivatePayment(ws, arrPrivateElements, bViaHub, callbacks){
	if (!ValidationUtils.isNonemptyArray(arrPrivateElements))
		return callbacks.ifError("private_payment content must be non-empty array");
	
	var unit = arrPrivateElements[0].unit;
	var message_index = arrPrivateElements[0].message_index;
	var output_index = arrPrivateElements[0].payload.denomination ? arrPrivateElements[0].output_index : -1;
	if (!ValidationUtils.isValidBase64(unit, constants.HASH_LENGTH))
		return callbacks.ifError("invalid unit");
	if (!ValidationUtils.isNonnegativeInteger(message_index))
		return callbacks.ifError("invalid message_index");
	if (!(ValidationUtils.isNonnegativeInteger(output_index) || output_index === -1))
		return callbacks.ifError("invalid output_index");

```

**File:** wallet.js (L955-972)
```javascript
function handlePrivatePaymentChains(ws, body, from_address, callbacks){
	var arrChains = body.chains;
	if (!ValidationUtils.isNonemptyArray(arrChains))
		return callbacks.ifError("no chains found");
	if (!arrChains.every(c =>
		isNonemptyArray(c) &&
		c.every(e =>
			isNonemptyObject(e) &&
			isNonemptyString(e.unit) &&
			isNonemptyObject(e.payload) &&
			isNonemptyString(e.payload.asset) &&
			isNonemptyArray(e.payload.inputs) &&
			isNonemptyArray(e.payload.outputs) &&
			e.payload.inputs.every(isNonemptyObject) &&
			e.payload.outputs.every(isNonemptyObject)
		)
	))
		return callbacks.ifError("malformed private chain");
```
