### Title
`pool_creator` is set to an arbitrary, unvalidated address in `initialize_with_permission` and can never be changed, permanently misdirecting creator fees - ([File: programs/cp-swap/src/instructions/initialize_with_permission.rs])

### Summary
`InitializeWithPermission` accepts `creator` as a plain `UncheckedAccount` with no signer requirement and no constraint tying it to the `payer` who actually supplies the initial liquidity. This value is written once into `PoolState.pool_creator` in `PoolState::initialize` and there is no instruction anywhere in the program to update `pool_creator` afterward. This mirrors the reported bug class: a fee-receiving address is fixed at creation time with no mechanism to rotate it if it later becomes compromised, wrong, or otherwise unable to be used, permanently misdirecting/losing all future creator fees for that pool.

### Finding Description
In `InitializeWithPermission`, `creator` is declared only as `pub creator: UncheckedAccount<'info>` with no `constraint`, no signature check, and no relationship enforced to `payer` (who signs and funds the pool): [1](#0-0) 

At the end of the handler, this attacker/caller-supplied `creator` account key is passed straight into `pool_state.initialize(...)`, which stores it permanently as `pool_creator`: [2](#0-1) [3](#0-2) 

`pool_creator` is a plain field with no update path in the codebase (`grep` for `pool_creator` shows it is only read in `collect_creator_fee.rs` / `collect_creator_fee_permissionless.rs`, and written once in `pool.rs`'s `initialize`): [4](#0-3) [5](#0-4) 

All future creator fees accrued by swaps on this pool (`creator_fees_token_0` / `creator_fees_token_1`, accumulated in `update_fees`) can only ever be paid out to this fixed `pool_creator` address: [6](#0-5) 

Crucially, `collect_creator_fee_permissionless` requires no signature from `creator` at all — it only requires the recipient token accounts' `associated_token::authority = creator` constraint, meaning anyone can trigger the payout to whatever `pool_creator` was recorded at pool creation: [7](#0-6) 

Since `creator` in `InitializeWithPermission` is never validated to be the `payer`, a signer, or even an on-curve address capable of owning token accounts, the `payer` (or anyone constructing the instruction with `permission` set up) can set `pool_creator` to any arbitrary value — including an address they do not control, an already-compromised address, or an unusable off-curve/PDA address that can never receive or claim SPL token accounts. Because there is no setter for `pool_creator`, this choice is irrevocable for the lifetime of the pool.

### Impact Explanation
If `pool_creator` is set to an address that is compromised, lost, or otherwise not controlled/usable by the legitimate liquidity provider, 100% of the pool's ongoing creator-fee stream (`creator_fees_token_0`/`creator_fees_token_1`) is permanently misdirected or frozen for the entire life of the pool, with no recovery mechanism. This is a permanent loss/freezing of protocol-designated fee funds tied to the pool, matching the report's bug class (hardcoded/immutable receiver with no rotation path).

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a valid `permission` PDA (an approved pool-creation path in scope per the task rules). No signature or ownership check ties `creator` to `payer`, so a single crafted `initialize_with_permission` transaction is sufficient to set an arbitrary, unrecoverable `pool_creator`. The condition depends on the caller supplying a bad/compromised/unusable `creator` address (either accidentally or maliciously), but nothing in the program prevents or detects this at initialization time, and there is no later remediation instruction.

### Recommendation
- Require `creator` to sign `InitializeWithPermission` (or otherwise cryptographically prove control), or default `pool_creator` to `payer` unless a validated delegation is presented.
- Add an authorized instruction allowing the current `pool_creator` (via signature) to rotate `pool_creator` to a new address, analogous to a two-step ownership transfer, so a compromised or unusable receiver can be replaced.
- Validate that `creator` is on-curve/capable of being an ATA authority before accepting it during initialization.

### Proof of Concept
1. Attacker or a careless integrator obtains a valid `permission` PDA for `payer`.
2. Attacker calls `initialize_with_permission` supplying `creator` = an address they don't control (e.g., a burn/black-hole address, or an address whose key is already known to be compromised), while `payer` funds the pool's initial liquidity normally.
3. `pool_state.initialize(...)` stores this `creator` as `pool_creator` permanently: [2](#0-1) 
4. As swaps occur on the pool, `creator_fees_token_0`/`creator_fees_token_1` accrue in `PoolState` via `update_fees`: [6](#0-5) 
5. Anyone can call `collect_creator_fee_permissionless`, which pays out these fees to `pool_creator`'s associated token accounts, with no way to redirect them since `pool_creator` cannot be changed: [8](#0-7) 
6. The legitimate liquidity provider (`payer`) has no way to recover or redirect the creator-fee stream for the life of the pool.

```rust
    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
```

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

    Ok(())
}
```
