The reported CVE describes a symlink-following vulnerability in a web application's file upload handler (`Components/Pages/Home.razor` in pwnlift), which requires local filesystem semantics (attacker-controlled path -> server follows symlink -> writes/reads outside intended directory) reachable through a privileged web upload endpoint.

I searched the polkadot-sdk--004 codebase for the closest structural analog: any FRAME extrinsic, contract call, or XCM instruction that accepts an attacker-controlled path/identifier and performs a filesystem write/read without validating that the target isn't a symlink or outside a sandboxed directory. All filesystem write/read operations I found are confined to:

- Node/client-side CLI tooling operating on locally-trusted paths supplied by the node operator, not by network peers or signed extrinsics — e.g. `substrate/client/cli/src/commands/export_blocks_cmd.rs`, `substrate/client/cli/src/commands/generate_node_key.rs`, `substrate/client/keystore/src/local.rs`. [1](#0-0) [2](#0-1) 
- PVF worker cache handling, which uses a hard link to a fixed, host-controlled artifact path inside a per-worker chroot-like directory rather than any attacker-supplied path, explicitly designed to prevent exactly this class of issue. [3](#0-2) [4](#0-3) 
- Benchmarking/weight-generation tooling and authority-discovery address cache persistence, all operating on local, non-network-attacker-controlled paths. [5](#0-4) [6](#0-5) 

None of these are reachable through a signed extrinsic, permissioned contract call, or XCM message from an unprivileged, keyless attacker — the prompt's required entry-point condition. FRAME/runtime dispatch logic (pallets, XCM executor, contracts/revive) does not perform filesystem writes based on user-supplied data at all; filesystem interaction is strictly a node-operator/CLI-side concern, isolated from the on-chain state-transition function that untrusted extrinsics can influence. Therefore there is no demonstrable analog of a symlink-following vulnerability reachable by an external, unprivileged user through the runtime's real entry points.
