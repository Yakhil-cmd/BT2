### Title
Governing Node Can Set `reward.mintingamount` to Arbitrary Value, Minting Unlimited KAIA — (`kaiax/gov/param.go`)

---

### Summary

The `reward.mintingamount` governance parameter has no upper-bound validation. In `single` governance mode (the immutable Mainnet configuration), the sole governing node can unilaterally vote to set this parameter to any arbitrarily large `*big.Int` value. After one epoch the new value takes effect, and every subsequent block mints that amount of KAIA to reward recipients through `FinalizeState → state.AddBalance`, causing unbounded inflation and unauthorized KAIA distribution.

---

### Finding Description

`reward.mintingamount` is registered in `kaiax/gov/param.go` with `FormatChecker: noopFormatChecker`, which unconditionally returns `true` for any canonical value: [1](#0-0) 

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // ← no upper-bound check
    ...
    DefaultValue: big.NewInt(0),
},
```

The `noopFormatChecker` is defined as: [2](#0-1) 

```go
func noopFormatChecker(cv any) bool {
    return true
}
```

The consistency check in `checkConsistency` also performs no validation for `RewardMintingAmount`, simply returning `nil`: [3](#0-2) 

```go
case gov.GovernanceDeriveShaImpl, ..., gov.RewardMintingAmount, ...:
    return nil
```

On Mainnet, `governance.governancemode` is `single` (immutable), meaning the single governing node's vote is automatically ratified at the next epoch boundary. The ratified value is then consumed by `NewRewardConfig`: [4](#0-3) 

```go
paramset := govModule.GetParamSet(header.Number.Uint64())
rc.MintingAmount = new(big.Int).Set(paramset.MintingAmount)
```

And applied unconditionally in `FinalizeState`: [5](#0-4) 

```go
spec, err := r.GetDeferredReward(header, txs, receipts)
...
for addr, amount := range spec.Rewards {
    state.AddBalance(addr, amount)
}
```

The minting amount flows directly from the governance parameter into `state.AddBalance` with no cap or sanity check at any layer.

By contrast, `reward.minimumstake` at least checks `v.Sign() >= 0`, and the KIP-71 base-fee bounds check each other. `reward.mintingamount` has no analogous guard.

---

### Impact Explanation

A malicious or compromised governing node can call:

```
governance_vote("reward.mintingamount", "115792089237316195423570985008687907853269984665640564039457584007913129639935")
```

After one epoch (≈ 1 week on Mainnet, 604,800 blocks), every block mints `2^256 − 1` kei to the proposer, stakers, KIF, and KEF addresses. This constitutes:

- **Unauthorized mint of KAIA** at every block, inflating total supply to effectively infinity.
- **Unauthorized reward distribution** — the governing node controls its own reward address and can direct the bulk of the minted tokens to itself by also setting `reward.ratio` to `100/0/0` and `reward.kip82ratio` to `100/0`.
- **Permanent state corruption** — every block's state root reflects the inflated balances; the canonical chain is poisoned.

This satisfies the allowed impact: *"Unauthorized mint … affecting KAIA … or system-managed funds."*

---

### Likelihood Explanation

- **Trigger**: The governing node is a single address with unilateral authority in `single` mode. No multi-sig or quorum is required.
- **Barrier**: The governing node must be malicious or its key compromised. On Mainnet this is a high-trust role, but the protocol itself provides no technical guard against this action.
- **No timelock beyond epoch delay**: The 1-epoch delay gives users advance notice but no ability to prevent the change. There is no protocol-enforced minimum delay or cancellation mechanism.
- **Analogous to H-2**: The external report's coordinator can set margin ratios to 1000% with no upside limit; here the governing node can set `reward.mintingamount` to `2^256 − 1` with no upside limit.

---

### Recommendation

1. **Add an upper-bound `FormatChecker` for `reward.mintingamount`**. A reasonable cap (e.g., `1e27` kei = 1 billion KAIA per block) should be enforced in `kaiax/gov/param.go`:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok { return false }
        maxMint, _ := new(big.Int).SetString("1000000000000000000000000000", 10) // 1e9 KAIA
        return v.Sign() >= 0 && v.Cmp(maxMint) <= 0
    },
    ...
},
```

2. **Apply the same treatment to `reward.stakingrewardthreshold`**, which also uses `noopFormatChecker` after a non-negative sign check.

3. **Consider a protocol-level timelock** (beyond the epoch delay) for parameters that directly affect token issuance, so that token holders have time to react before a malicious change takes effect.

---

### Proof of Concept

1. Governing node calls `governance_vote("reward.mintingamount", "115792089237316195423570985008687907853269984665640564039457584007913129639935")` via the `governance_vote` RPC.
2. `NewVoteData` in `kaiax/gov/headergov/vote.go` canonicalizes the value via `bigIntCanonicalizer` and passes `noopFormatChecker` — vote is accepted.
3. `VerifyVote` in `kaiax/gov/headergov/impl/header.go` calls `checkConsistency`, which returns `nil` for `RewardMintingAmount`.
4. At the next epoch block, the vote is ratified and written to `header.Governance`.
5. From epoch `k+1` onward, `GetParamSet` returns `MintingAmount = 2^256 − 1`.
6. `NewRewardConfig` sets `rc.MintingAmount = 2^256 − 1`.
7. `FinalizeState` calls `state.AddBalance(proposerAddr, 2^256 − 1)` every block, minting unlimited KAIA.
