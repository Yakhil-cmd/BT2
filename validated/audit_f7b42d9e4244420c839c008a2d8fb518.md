## Title
AA and wallet funds in a `spender_attested` asset become permanently frozen if the attestor stops attesting the holder address, with no bypass mechanism - (File: `validation.js`)

### Summary
Ocore supports "permissioned" assets whose `spender_attested` flag requires that every address that spends (is the owner/input of) a unit of the asset be currently attested by one of the asset's designated attestors. This check is enforced unconditionally at validation time with no fallback, exactly mirroring the reported pattern: a single external gatekeeper (the attestor, analogous to a blocklist/pausable token) can make previously-received funds permanently unspendable.

### Finding Description
For divisible/base payments, `validatePaymentInputsAndOutputs` requires that the address that owns the spent output be present in `objAsset.arrAttestedAddresses`, which is computed by `storage.filterAttestedAddresses`/`loadAssetWithListOfAttestedAuthors` from the *current* (most recent, before-last-ball) attestor list: [1](#0-0) 

The same requirement is applied to output addresses receiving change/transfers of the asset (`arrAttestedOutputAddresses.length !== arrOutputAddresses.length` → `"some output addresses are not attested"`): [2](#0-1) 

`storage.readAsset`/`loadAssetWithListOfAttestedAuthors` always fetches only the *latest* stable attestor-list unit for the asset and filters attestations against it: [3](#0-2) [4](#0-3) 

The attestor list itself is entirely controlled by the asset definer and can be replaced at any time via an `asset_attestors` message, requiring only that it be non-empty and sorted — nothing prevents the definer from replacing the list with attestors who will never attest a given address, or an attestor from simply ceasing to publish new attestations for that address: [5](#0-4) [6](#0-5) 

Autonomous Agents are subject to the identical restriction: when an AA composes an outgoing payment of such an asset, it goes through the normal validation path (`aa_composer.js` `sendUnit` → `validateAndSaveUnit`), so if the AA's own address (as spender/owner) is not attested, or the destination address is not attested, unit validation fails and the response bounces — there is no code path in `aa_composer.js` that special-cases or bypasses the attestation requirement, nor any way for the AA (or the coin holder) to force re-attestation or route around a non-cooperating/discontinued attestor.

### Impact Explanation
Once an address (wallet or AA) holds a balance of a `spender_attested` asset and is not (or is no longer) on the current attestor's attested list, every future attempt to spend that balance — for any amount, to any destination — will fail validation with "owner address is not attested"/"none of the authors is attested". Because the check is re-evaluated against the *current* attestor list at spend time (not the list valid when the coins were received), an attestor can retroactively "blocklist" any prior recipient by simply not attesting them going forward, or by rotating the attestor set. This permanently and unconditionally locks the funds with no on-chain recourse, matching the reported bug class: a single external authorization gate with no override/bypass causes indefinite fund freezing.

### Likelihood Explanation
Reaching this state requires no privileged access: any unit poster can receive/hold a `spender_attested` asset (this is the intended design of such assets, used e.g. for KYC/AML-gated tokens), and the only prerequisite for the freeze is that the definer/attestor (who fully controls the attestor list per-asset) fails to attest the holder — whether by policy, oversight, or discontinuing service. This is a realistic and directly reachable scenario for any AA or wallet address holding such an asset.

### Recommendation
Provide an escape hatch for `spender_attested` assets, e.g.: allow spending to be validated against the attestor list that was current when the coins were received (so retroactive de-attestation cannot freeze already-held funds), and/or allow the definer to explicitly revoke `spender_attested` or force-migrate frozen balances, and/or document this as an accepted risk specific to permissioned-asset design so integrators (including AA authors) do not treat AA-held balances of such assets as guaranteed-recoverable.

### Proof of Concept
1. Definer issues asset `A` with `spender_attested: true` and an initial attestor list `[X]`.
2. Attestor `X` attests address `H` (holder/AA).
3. Holder `H` receives a payment of asset `A` (accepted, since `H` was attested at receipt time).
4. Definer publishes an `asset_attestors` message that changes the attestor list to `[Y]` (a different, non-cooperating attestor), or attestor `X` simply stops issuing new attestations for `H`.
5. `H` attempts to spend asset `A` (e.g., an AA tries to send it out in a response, or the wallet tries to transfer it). `loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses` recompute attested status against the *new* current attestor list, find `H` not attested, and `validatePaymentInputsAndOutputs` rejects the unit with `"owner address is not attested"` (line 2506) — for every subsequent attempt, forever, since `H` can never obtain attestation from `Y` (or `X` never resumes). function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}
