### Title
Webhook Signature Bound to Attacker-Controlled Organization ≠ Repository Acted On — Cross-Tenant Forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In a multi-tenant Shipit deployment, the webhook endpoint selects which organization's HMAC secret to verify a request against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted JSON body, then hands that *same* body to event handlers which independently derive the target repository/stack from `repository.full_name` in that body. Nothing enforces that the organization whose secret validated the signature is the same organization embedded in `full_name`. A tenant that legitimately knows its own `webhook_secret` can therefore forge a validly-signed webhook whose `repository.full_name` points at a *different* tenant's repository, causing Shipit to act (archive review stacks, trigger syncs, create teams/users, etc.) on that other tenant's resources.

### Finding Description
`Shipit.github` supports multiple organizations, each configured with its own `webhook_secret`, looked up via `github_app_config(organization)`: [1](#0-0) 

The webhook controller verifies the request's HMAC signature using the secret belonging to whatever organization is named in the payload itself: [2](#0-1) [3](#0-2) 

Once `head(422)` is not raised, the raw JSON is dispatched unchanged to handlers: [4](#0-3) 

Every handler resolves its target `Repository`/`Stack` from a *different* field of the same attacker-supplied JSON — `repository.full_name` — with no re-validation against the organization that satisfied the signature check: [5](#0-4) [6](#0-5) 

Concretely, a state-changing handler such as `PullRequest::ClosedHandler` will archive whatever review stack it resolves from `full_name`: [7](#0-6) 

The broken equality: **`organization derived for signature verification (params.dig('repository','owner','login'))` must equal `organization embedded in the repository the handler mutates (params.dig('repository','full_name'))`**, but this is never checked. Both values are read from the same fully attacker-controlled, unauthenticated POST body — only the HMAC prevents *arbitrary* forgery, and the HMAC is keyed per-organization, not per-repository. Any tenant with a legitimate installation (and therefore knowledge of its own `webhook_secret`) can therefore produce a validly-signed payload that names a different tenant's repository in `full_name`.

This is structurally analogous to the reported bug class: the code assumes one field (order amount / signing organization) is authoritative for another related but distinct quantity (custody balance / target repository) without verifying they actually match.

### Impact Explanation
This breaks the deployment-trust binding between "which organization authenticated the webhook" and "which repository/stack is written to," enabling cross-tenant writes: an attacker-controlled tenant can archive another tenant's review stacks (`PullRequest::ClosedHandler`), force Team/User creation events under another tenant context (`membership` handler), or trigger sync/refresh jobs against repositories they don't own — all without ever needing that other tenant's credentials, `ApiClient` token, or GitHub access. This matches the "cross-repository writes" Critical category, since Shipit-side state belonging to Org B is mutated as a direct result of a forgery only Org A's secret was needed to produce.

### Likelihood Explanation
Requires only that the attacker be a legitimate, onboarded tenant organization on a shared/multi-org Shipit instance (a configuration explicitly supported by `Shipit.github_organizations`/`github_app_config`) — no privileged host access, no other tenant's secret, and no session is needed, since `WebhooksController` is unauthenticated by design (`skip_before_action :verify_authenticity_token`). The attacker only needs to craft a raw HTTP POST with a self-computed HMAC using their own known secret.

### Recommendation
After signature verification, cross-check that the organization used to select the `webhook_secret` (`repository_owner`) matches the owner segment of every repository-identifying field the handlers subsequently use (e.g., `repository.full_name`, `organization.login`) before dispatching to `Shipit::Webhooks.for_event`. Reject the request if they diverge, similar to how the settlement fix now verifies the actual custody balance instead of trusting a separately-sourced field.

### Proof of Concept
1. Operate (or be granted) a legitimate tenant organization "org-attacker" on a shared Shipit instance, with its own configured `webhook_secret` (known to the org admin who installed the GitHub App).
2. Craft a `pull_request` webhook JSON body where `repository.owner.login = "org-attacker"` (so `WebhooksController#repository_owner` resolves the attacker's own secret) but `repository.full_name = "org-victim/target-repo"` and a real PR number belonging to `org-victim`'s review stack, `action: "closed"`.
3. Compute `X-Hub-Signature` as `sha1=HMAC-SHA1(org-attacker's webhook_secret, raw_body)`.
4. POST to `/webhooks`. `verify_signature` passes because it only checks the org-attacker secret against `repository_owner="org-attacker"`.
5. `PullRequest::ClosedHandler` resolves `repository` via `Repository.from_github_repo_name("org-victim/target-repo")` and calls `review_stack.archive!`, archiving `org-victim`'s review stack despite the attacker never authenticating against `org-victim`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
