## Analysis

The Fenix report's root cause is generic: **integer division in a shared reward/ratio calculation rounds to zero for small values, and that rounding decides an all-or-nothing outcome that benefits one party at the expense of another's balance.** Searching Zest for the same rounding-to-zero-triggers-boundary-jump pattern surfaces the "dust sweep" branch inside `liquidate` in [1](#0-0) , which is the strongest analog.

### Title
Rounding error in leftover-collateral debt conversion lets liquidators seize a borrower's entire collateral balance instead of the proportional amount - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
In `liquidate`, once the primary proportional collateral/debt amounts are computed, the contract checks whether the *remaining* collateral (`coll-remaining`) is worth liquidating by converting it to a debt-token amount (`remaining-debt-to-repay`). This conversion chains several `mul-div-down`/`div-bps-down` steps. If that chained division rounds down to `0`, the code silently switches `coll-final` from the correctly proportioned `coll-final-raw` to the borrower's **full** `user-coll-balance`, letting the liquidator take all of the borrower's collateral for a partial debt repayment.

### Finding Description
The relevant computation is: [1](#0-0) 

```
(coll-remaining (- user-coll-balance coll-final-raw))
(remaining-debt-to-repay
  (if (> coll-remaining u0)
    (let ((rem-coll-usd (normalize (* coll-remaining coll-price) coll-decimals false))
          (rem-debt-usd (div-bps-down rem-coll-usd (+ BPS liq-penalty-max)))
          (rem-debt-tokens (mul-div-down rem-debt-usd (pow u10 debt-decimals) debt-price))
          (rem-borrow-index (get index (unwrap-panic (get-cached-indexes debt-aid))))
          (rem-scaled (mul-div-down rem-debt-tokens INDEX-PRECISION rem-borrow-index)))
      (mul-div-up rem-scaled rem-borrow-index INDEX-PRECISION))
    u1))
(coll-final (if (is-eq remaining-debt-to-repay u0) user-coll-balance coll-final-raw)))
```

`coll-final-raw` (the intended, proportionally correct collateral amount to seize) is computed earlier in `scale-debt-for-liquidation`: [2](#0-1) 

The chain `normalize → div-bps-down → mul-div-down → mul-div-down → mul-div-up` applies at least three floor-divisions before one ceiling-division. Whenever `coll-remaining`'s USD value, once converted through the debt asset's decimals/price/borrow-index, floors to `0` (which routinely happens for assets with few decimals relative to price, e.g. an 8-decimal BTC-pegged debt asset with a large price, or simply a modest, non-trivial `coll-remaining`), `remaining-debt-to-repay` becomes `0`. That triggers the `is-eq remaining-debt-to-repay u0` branch, which discards the proportional `coll-final-raw` and reassigns `coll-final` to the **entire** `user-coll-balance` — while `debt-to-repay` used to actually repay the vault is still only the smaller, proportional amount computed earlier from `scale-debt-for-liquidation`.

This is not a symmetric "dust sweep" safeguard: it does not check that `coll-remaining` itself is tiny/dust — it only checks that its *debt-token-equivalent* rounds to zero after several successive floor divisions, which can occur for material collateral amounts, not just dust.

- **Attacker**: any liquidator calling `liquidate`.
- **Victim**: the borrower being liquidated.
- **Shared state**: the borrower's `coll-final` collateral amount removed via `collateral-remove`, and `debt-to-repay`/`scaled-to-remove` passed to `vault-system-repay` / `debt-remove-scaled`.

### Impact Explanation
Without the rounding artifact, the borrower would only lose collateral proportional to the debt actually repaid (`coll-final-raw`), leaving `coll-remaining` in their position. With the rounding artifact, the borrower loses their **entire** remaining collateral balance for that asset while only the smaller, previously computed `debt-to-repay` is actually repaid to the vault — i.e., the liquidator seizes more collateral than the executed repayment entitles them to. This is direct theft of the borrower's funds at rest (collateral), matching the in-scope Critical impact class ("direct theft of user funds at rest ... other than unclaimed yield").

### Likelihood Explanation
This path triggers automatically any time `coll-remaining`'s USD-equivalent, once divided down through `div-bps-down` and two chained `mul-div-down` conversions, floors to zero in debt-token terms — a condition entirely determined by asset decimals/price ratios and position sizes rather than by any privileged action. A liquidator does not need to engineer anything special; they can select borrowers/asset pairs where this rounding condition is naturally satisfied (e.g., low remaining collateral value relative to debt-asset decimals/price), making this readily reachable through ordinary liquidation calls.

### Recommendation
Replace the all-or-nothing zero-check with a genuine dust threshold expressed in absolute terms (e.g., compare `coll-remaining` or its USD value against a small, explicit minimum before sweeping), and/or use consistent rounding direction (ceiling) throughout the `remaining-debt-to-repay` computation so the "dust" decision reflects the true remaining value rather than an artifact of chained floor divisions. Alternatively, cap the sweep amount so it can never exceed `coll-final-raw` plus a bounded, provably-dust delta.

### Proof of Concept
1. Borrower has a position with debt in an asset `debt-aid` with small `debt-decimals` and a high `debt-price` (e.g., a wrapped BTC asset), and collateral in another asset.
2. Liquidator calls `liquidate` with a `debt-amount` sized so that after `scale-debt-for-liquidation`, `coll-final-raw` leaves a `coll-remaining > 0` whose USD value, once run through `div-bps-down` and the two `mul-div-down` conversions into `debt-aid` scaled units, floors to `0` (`rem-debt-tokens = 0` ⇒ `rem-scaled = 0` ⇒ `remaining-debt-to-repay = 0`).
3. `coll-final` is reassigned to `user-coll-balance` (full balance) at [3](#0-2) , while `debt-to-repay`/`scaled-to-remove` used for the actual vault repayment at [4](#0-3)  remain the smaller proportional values.
4. The liquidator receives the borrower's entire collateral balance for that asset while only repaying the smaller proportional debt amount — collateral seizure exceeds its intended proportional bound.

```text
(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))
```
