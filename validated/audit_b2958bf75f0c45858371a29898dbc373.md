### Title
`repay_debt_with_collateral` applies borrow-side risk gates to risk-reducing repayments, so a deleveraging call reverts precisely when the account is near liquidation — ([File: contracts/controller/src/risk/validation.rs](contracts/controller/src/risk/validation.rs))

### Summary
Analogous to the Morpho bug where a `unutilizedLeveragePercentage` haircut on the borrow limit made every repay underflow and revert just as the position approached liquidation, XOXNO Lending's `repay_debt_with_collateral` routes every partial deleverage through `require_post_pool_risk_gates`. Those gates require the *post-action* account to satisfy borrow-admission conditions (`ltv_collateral >= total_debt`, `HF >= 1`, `ltv_collateral >= min_borrow_collateral_usd`). A collateral price drop can put an account into the band `ltv_collateral < total_debt <= weighted_collateral` (LTV < liquidation threshold, so this band is non-empty and wide: e.g. XLM LTV 7500 vs LT 7800). Inside that band — and a fortiori whenever `HF < 1` — any partial repay-with-collateral reverts even though it strictly improves health, and a full close via collateral is impossible when the collateral's swap output can't cover the whole debt. The account's only self-service deleverage path is disabled exactly when it is needed, and the position is pushed to `liquidate` where the HF-based bonus curve and fees take value from the borrower.

### Finding Description
`process_repay_debt_with_collateral` (contracts/controller/src/strategies/repay_debt_with_collateral.rs:30-92) ends every execution with `strategy_finalize`, which runs `require_post_pool_risk_gates` (contracts/controller/src/risk/validation.rs:29-61). The gate only skips when `account.debt_free()`:

```text
ltv_collateral   >= total_debt        // else InsufficientCollateral
health_factor    >= 1e18              // else InsufficientCollateral
ltv_collateral   >= min_borrow_collateral_usd (default 5 WAD)
```

These are *admission* criteria for opening risk, applied unconditionally to a transaction whose only effect is burning supply and repaying debt. Because `ltv_collateral` is weighted by `min(LTV, LT)` while `health_factor` is weighted by `LT` (skills/xoxno-lending/math.md:271-286), the region `ltv_collateral < total_debt <= weighted_collateral` is reachable purely from a price move — no user error. In that region a partial `repay_debt_with_collateral` reverts with `InsufficientCollateral` even though it reduces debt and raises HF. Below `HF = 1` the second assert guarantees every partial call reverts, so the owner cannot preempt a pending liquidation by selling collateral into the debt. The same gate also makes `swap_collateral` into a weaker collateral impossible in that band. The same-token path (`net_settle_collateral_against_debt`, repay_debt_with_collateral.rs:57-67) is affected identically since it shares `strategy_finalize`. Only a *complete* debt close skips the gate — which the user often cannot fund from collateral, mirroring the report's `borrowBalance > adjustedLimit` condition that made every `ripcord` call revert.

### Impact Explanation
A borrower whose collateral crashes into the LTV-HF band cannot partially repay with collateral at all: each attempt reverts. If the collateral is insufficient for a full close, the account is locked into its position until a third-party liquidator acts. The borrower then loses the liquidation bonus (up to the `max_bonus_for_threshold`-bounded cap, on a multi-leg pro-rata seizure) plus `liquidation_fees`, and at `HF < 1` any residual may become bad debt socialized via `clean_bad_debt`. This is theft-equivalent loss of user funds (forced bonus + fee transfer) plus temporary freezing of the user's collateral while the revert window lasts — both accepted impacts.

### Likelihood Explanation
The trigger is an ordinary collateral price decline, identical to the external report's precondition. The vulnerable band is structurally guaranteed: every listed asset has `ltv < lt`, and mainnet stamps (XLM `7500/7800`, USDC `7600/8000` per skills/xoxno-lending-sdk/positions.md:105-115) make the band ~3-4% of collateral value wide, plus the `HF < 1` region below it. Any unprivileged owner or delegate hits the revert via a single `repay_debt_with_collateral(caller, account_id, collateral, amount, debt, swap, close_position=false)` call; no privileged state, leaked keys, or oracle manipulation is needed. Note residual uncertainty: I confirmed `strategy_finalize` is invoked at repay_debt_with_collateral.rs:91 and that `require_post_pool_risk_gates` exists at validation.rs:29, and documentation (skills/xoxno-lending/math.md:306-314) states the gate runs after "every strategy that leaves debt"; I did not read `strategies/mod.rs` line-by-line to confirm there is no risk-decreasing exemption inside `strategy_finalize` — the cited docs and the `debt_free()` early-return structure both indicate there is none.

### Recommendation
Skip or relax the post-gates for risk-reducing paths: in `require_post_pool_risk_gates` (or `strategy_finalize`), exempt `repay_debt_with_collateral`/`swap_collateral` calls when the post-action `total_debt` and `health_factor` are strictly better than pre-action (compute pre-totals before the swap and compare), or only apply `ltv_collateral >= total_debt` / `HF >= 1` / the min-collateral floor when the action increases debt or reduces collateral value in USD. At minimum, never gate a repay on `ltv_collateral < total_debt` when HF improved.

### Proof of Concept
1. Alice supplies 1,000 XLM at $1.00 (LTV 7500, LT 7800) and borrows $760 USDC: `ltv_collateral = $750`, wait — use borrow $740: `ltv_collateral=750 ≥ 740`, `HF = 780/740 ≈ 1.054`. Admitted.
2. XLM price falls to $0.98. Now `total_debt ≈ 740` (plus interest), `ltv_collateral = 735`, `weighted = 764.4`, `HF ≈ 1.033`. `ltv_collateral (735) < total_debt (740)`.
3. Alice calls `repay_debt_with_collateral` to sell $50 of XLM into USDC debt. Post-state `ltv_collateral` still < `total_debt` → `InsufficientCollateral` at validation.rs:43. Reverts. Every partial amount reverts; only a full ~$740+interest close is permitted, which her remaining collateral cannot fund after slippage.
4. Price slides further to `HF < 1`: the validation.rs:51 assert now blocks all partial repayments regardless of improvement, and any liquidator seizes her collateral at bonus + fee — the exact forced-liquidation outcome of the Morpho report.
