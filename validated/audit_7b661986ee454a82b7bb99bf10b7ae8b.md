Confirmed: this repo supports multi-organization GitHub App configuration keyed by org name, each with its own `webhook_secret` [1](#0-0) , and `WebhooksController#verify_signature` selects which org's secret to verify against based on `repository_owner`, which reads `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`) [2](#0-1) . Meanwhile every downstream `Handler` resolves the actual `Repository`/`Stack` to act on using a *different* field, `payload.dig('repository', 'full_name')` [3](#0-2) , and PR/push handlers likewise key off `params.repository.full_name` [4](#0-3) .

### Title
Webhook signature verified against `repository.owner.login`/`organization.login` but the acted-upon repository is `repository.full_name`, enabling cross-organization writes - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
### Finding Description
The reported fatBERA.sol bug is a class of "field acted on but not covered/consistent with the verification step" — `isWhitelistedVault` was toggled without first reconciling accrued state tied to a different tracked field (effective balance), letting the two diverge to the attacker's/victim's detriment. The structural analog in this engine is the binding: *"an organization that authenticated versus the repository that is written."*

In `WebhooksController`, `verify_signature` chooses which GitHub App config (and thus which `webhook_secret`) to validate the HMAC signature against using:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [5](#0-4) 

This engine explicitly supports multiple GitHub App organizations each with independently configured `webhook_secret`s, resolved via `Shipit.github(organization:)` / `github_app_config` [1](#0-0) .

However, once the signature check passes, every event handler (`Handler#stacks`/`#repository_name`, `PushHandler`, `PullRequest::OpenedHandler`, `ClosedHandler`, etc.) determines *which* `Repository`/`Stack` record to mutate using an entirely different JSON key, `repository.full_name`:
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
``` [6](#0-5) 
```ruby
def repository
  @repository ||= Shipit::Repository.from_github_repo_name(params.repository.full_name) || Shipit::NullRepository.new
end
``` [7](#0-6) 

The HMAC covers the raw POST body as a whole (`verify_webhook_signature(signature, request.raw_post)` [8](#0-7) ), so it cannot be "split" after the fact — but it also does not enforce any relationship between `repository.owner.login` (used to pick the secret) and `repository.full_name` (used to pick the target). Since the endpoint is a plain public POST route reachable by anyone who knows a valid `webhook_secret` for *any* configured organization (this is not GitHub-signed traffic verified against source IP or a GitHub-issued delivery ID — it's whoever can compute the correct HMAC), an actor who legitimately possesses OrgA's `webhook_secret` (e.g., because they administer OrgA's GitHub App installation and its webhook config) can self-craft and self-sign an arbitrary JSON body where `repository.owner.login = "OrgA"` but `repository.full_name = "OrgB/target-repo"`. `verify_signature` will pick OrgA's secret, the HMAC will validate, and the handlers will then act on `Repository.from_github_repo_name("OrgB/target-repo")` — a repository whose real webhook secret was never used or known to the attacker.

### Impact Explanation
This breaks the equality *"organization that authenticated == repository that is written"*. For `push` events this triggers `GithubSyncJob`/`sync_github` on an unauthorized stack; for `pull_request` events (`opened`, `closed`, `labeled`, etc.) it can create/archive/unarchive review stacks or update pull request state belonging to a repository outside the attacker's own organization. This is a cross-repository write across organizational trust boundaries not gated by the org the attacker actually controls, matching the Critical "cross-repository writes" / "unauthorized deploy" impact bar, since a forged `push` payload with a crafted `after` SHA can drive `Stack#sync_github` and downstream deploy queuing for a repository the attacker does not own.

### Likelihood Explanation
Requires the attacker to legitimately control (or have been granted) one organization's GitHub App webhook configuration/secret within the same Shipit instance — i.e., to be a "member" of the multi-tenant Shipit deployment for at least one org, but not for the target org/repository. This is exactly the "unprivileged-attacker" scenario contemplated by the rules: no `ApiClient` token, no Shipit session, no GitHub push access to the target repository is needed — only knowledge of a *different*, already-configured organization's webhook secret.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler`), assert that `repository.owner.login` (the field used to select the signing organization) matches the owner segment of `repository.full_name` (the field the handlers actually act on) before dispatching to handlers; reject with `422` on mismatch.

### Proof of Concept
1. Deploy Shipit configured with two GitHub App organizations, `OrgA` and `OrgB`, each with its own `webhook_secret`, both tracked as `Shipit::Repository` records with active stacks.
2. As an administrator of `OrgA`'s GitHub App (who thus knows `OrgA`'s `webhook_secret`), craft a `push` webhook JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/target-repo" }
}
```
3. Compute `X-Hub-Signature: sha1=<hmac-sha1(OrgA_webhook_secret, body)>` and POST to `/webhooks` with `X-Github-Event: push`.
4. `WebhooksController#verify_signature` resolves `repository_owner => "OrgA"`, fetches OrgA's `GitHubApp`, and `verify_webhook_signature` succeeds.
5. `PushHandler#stacks` resolves `Repository.from_github_repo_name("OrgB/target-repo")` and queues `GithubSyncJob`/triggers deploy sync for `OrgB`'s stack, despite the signature never having been produced with `OrgB`'s secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",

    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)

        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
