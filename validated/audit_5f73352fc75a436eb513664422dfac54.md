### Title
Unauthenticated SSE stream exposure via `mount Pubsubstub::StreamAction.new, at: "/events"` bypassing all Shipit authentication - ([File: config/routes.rb])

### Summary
`config/routes.rb` mounts `Pubsubstub::StreamAction.new` directly at `/events` as a raw Rack endpoint, not as a Shipit engine controller, so it never includes the `Shipit::Authentication` concern that provides `force_github_authentication`. The only documented protection is a comment in `GithubAuthenticationController#callback` referencing a `UserRequiredMiddleware`, which does not exist anywhere in `lib/` or `app/` of this engine, leaving the endpoint open to any unauthenticated caller.

### Finding Description
The broken binding: the codebase's authentication guarantee is `every request reaching stack/task/deploy data requires current_user.authorized? == true`, enforced via `before_action :force_github_authentication` in `app/controllers/concerns/shipit/authentication.rb`. That guard is wired only into `ActionController` subclasses that `include Shipit::Authentication` (e.g. `Shipit::StacksController`, etc.). `Pubsubstub::StreamAction` is a plain Rack endpoint mounted via `mount Pubsubstub::StreamAction.new, at: "/events", as: :events` in `config/routes.rb` — it is not a Shipit controller and does not include this concern, so `force_github_authentication` is never invoked for requests to `/events`.

The comment in `app/controllers/shipit/github_authentication_controller.rb`:
```
# We need to set this so that the /events and /sidekiq endpoint
# which leverage `UserRequiredMiddleware` will recognize the user
# is authenticated.
session[:authenticated] = true
```
implies protection is expected to come from a Rack middleware called `UserRequiredMiddleware`. Searching `lib/` and `app/` of this engine (`lib/shipit/engine.rb`'s `initializer 'shipit.config'`, which only conditionally inserts `Shipit::SameSiteCookieMiddleware` and `OmniAuth::Builder`) confirms no such middleware is registered or defined by this engine. Thus the engine itself never installs the guard its own comment claims exists.

Attacker request: `GET /events?channels[]=stack.1` with no cookie, no `Authorization` header, against any deployment mounting this engine per `config/routes.rb`. Because no before_action runs for a Rack-mounted endpoint, and no middleware exists in-engine to check `session[:authenticated]`, the request reaches `Pubsubstub::StreamAction#call` directly and the caller receives a live SSE stream of whatever channel(s) it subscribes to.

### Impact Explanation
An unauthenticated attacker can read real-time stack/task/deploy state broadcast over Pubsubstub channels (e.g. `stack.<id>`, `task.<id>`) for any stack, across any repository/tenant configured on the instance, simply by guessing or enumerating small integer IDs. This is repeatable indefinitely and requires no credentials, matching the "High: unauthenticated read of stack state, task streams or deploy output" category.

### Likelihood Explanation
Preconditions are trivial: the engine mounted per the documented `config/routes.rb` (which is exactly what "host app mounts this engine as documented" assumes), and any stack existing with a guessable id. Attacker cost is a single unauthenticated HTTP GET; no GitHub account, webhook secret, or API token is required. This is fully feasible from the internet and repeatable against arbitrary stack channels.

### Recommendation
Wrap the `/events` mount with an authentication guard before hitting `Pubsubstub::StreamAction`, e.g. mount it behind a controller/concern that includes `Shipit::Authentication` (or a real Rack middleware checking `session[:user_id]`/`current_user.authorized?`) so unauthenticated requests are rejected with 401/403/redirect before reaching the SSE stream. Remove or implement the referenced `UserRequiredMiddleware` so the comment in `GithubAuthenticationController#callback` reflects actual enforced behavior.

### Proof of Concept
```ruby
# test/controllers/events_authentication_test.rb (would be added under test/, not included here per repo layout)
class EventsAuthenticationTest < ActionDispatch::IntegrationTest
  test "unauthenticated GET /events is not authenticated or rejected" do
    stack = shipit_stacks(:shipit)
    get "/events", params: { "channels[]" => "stack.#{stack.id}" }
    # Binding under test: response should require force_github_authentication to have run
    assert_not_equal 401, response.status
    assert_not_equal 403, response.status
    assert_no_match(/github/, response.headers["Location"].to_s)
    # No Shipit::Authentication before_action fires for this Rack-mounted endpoint
  end
end
```
