### Title
Webhook organization used for signature verification is decoupled from the organization used by `MembershipHandler`, allowing cross-tenant team/membership mutation - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/membership_handler.rb`)

### Summary
`WebhooksController#repository_owner` selects the GitHub organization (and thus the HMAC secret) used to authenticate an incoming webhook by reading `params.dig('repository','owner','login')`, falling back to `params.dig('organization','login')` only if `repository` is absent. `MembershipHandler`, however, independently reads its own `params.organization.login` to set/find `Team#organization` and to look up the target `Team` by `github_id`, without any cross-check against `repository_owner`. A single JSON body can therefore be signed/verified as belonging to org-a (`repository.owner.login`) while carrying `organization.login`='org-b', causing the handler to mutate org-b's team/membership state using a signature that only proves control of org-a.

### Finding Description
The broken binding, stated as an equality that the code implicitly assumes but never enforces:

`repository_owner` (the org verified in `verify_signature`) == `params.dig('organization','login')` (the org consumed by `MembershipHandler#find_or_create_team!`)

This is **false** whenever both `repository.owner.login` and a top-level `organization.login` are present in the same body with different values.

Code path:
- `WebhooksController#verify_signature` picks the GitHub App/secret via `repository_owner`: [1](#0-0) 
- `repository_owner` prefers `repository.owner.login` over `organization.login`: [2](#0-1) 
- `Shipit.github(organization:)` maps that org name to a distinct per-org secret/config: [3](#0-2) 
- Once signature verification passes, `create` dispatches the full raw params to every registered handler for the event, with no re-derivation or cross-check of organization: [4](#0-3) 
- `MembershipHandler` independently reads `params.organization.login`, decoupled from `repository_owner`, and uses it to create/attach a `Team` and to find an existing team purely by `github_id` (globally, no owner scoping) and mutate its membership: [5](#0-4) 
- The `ExplicitParameters` schema for `MembershipHandler` only validates presence/type of `organization.login`; it does not validate that it matches `repository_owner` or any verified organization: [6](#0-5) 

Exploit flow: an attacker who legitimately operates org-a in Shipit (and therefore knows/controls org-a's webhook secret, as any GitHub org admin configuring the integration would) crafts a `membership` event body containing:
```json
{
  "action": "added",
  "repository": { "owner": { "login": "org-a" } },
  "organization": { "login": "org-b" },
  "team": { "id": <org-b's known Shipit team github_id>, "name": "...", "slug": "...", "url": "..." },
  "member": { "login": "attacker-github-login" }
}
```
signed with `X-Hub-Signature` computed using org-a's secret. `verify_signature` computes `repository_owner` = `'org-a'` (from `repository.owner.login`, which takes precedence), loads org-a's `GitHubApp`, and the signature validates. `MembershipHandler`, however, ignores `repository_owner` entirely and reads its own `organization.login` = `'org-b'`, finds the existing `Team` record for org-b by `github_id`, and adds the attacker's GitHub login as a member of that team via `team.add_member(member)`.

Existing guards do not prevent this: `verify_signature` only proves the request was signed by *some* configured organization's secret, not that it authorizes actions on that same organization's resources; `drop_unhandled_event` and `ExplicitParameters` only check event routing and shape, not cross-field organization consistency; `Team.find_or_create_by!(github_id:)` has no scoping to the verified organization at all.

### Impact Explanation
If the targeted `Team` record is one referenced by `Shipit.github_teams` (the set of teams that grant application authorization), successfully adding the attacker's GitHub login as a member via a forged `membership` webhook lets `User#authorized?` return true for that attacker, since it only checks local `teams` membership: [7](#0-6) 
This is an escalation into `Shipit.github_teams` authorization achieved purely by controlling a *different*, unrelated organization's webhook secret — a payload authenticated for org-a mutates org-b's team state. This is repeatable against any org/team pair the attacker can target (bounded by needing the target team's numeric `github_id`), and the blast radius spans all tenants sharing the same Shipit deployment.

### Likelihood Explanation
Preconditions: (1) Shipit configured with per-organization GitHub Apps/secrets for at least two orgs (multi-tenant `secrets.github` config), (2) attacker legitimately administers one of those orgs (org-a) and thus knows/controls its webhook secret, (3) attacker knows the target `Team`'s numeric `github_id` for org-b (obtainable if the team was previously synced/visible, or by brute-forcing small sequential IDs, or from any other data leak). Given these, the attack is a single unauthenticated-looking HTTP POST to `/webhooks` with a body the attacker fully controls and can sign themselves — trivially repeatable.

### Recommendation
In `MembershipHandler` (and any other handler that reads `params.dig('organization', ...)` or `params.dig('repository', ...)`), require that the organization/repository referenced in the handler-specific payload matches the organization used by `WebhooksController#repository_owner` for signature verification, and reject/raise if they diverge. Alternatively, pass the verified `repository_owner` value explicitly into each handler and have handlers derive/validate `Team#organization` from that verified value rather than re-parsing an independent, unauthenticated field from the same JSON body.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test ":membership mutates a team belonging to a different org than the one whose secret signed the request" do
  victim_team = shipit_teams(:cyclimse_cooks) # organization: 'cyclimse', github_id: 2
  attacker_org = 'shopify' # org-a, attacker controls this org's webhook secret in this environment

  body = {
    action: 'added',
    repository: { owner: { login: attacker_org } },        # used by repository_owner -> signature org
    organization: { login: 'cyclimse' },                    # used by MembershipHandler -> mutated org
    team: { id: victim_team.github_id, name: victim_team.name, slug: victim_team.slug, url: victim_team.api_url },
    member: { login: 'walrus' }
  }.to_json

  @request.headers['X-Github-Event'] = 'membership'
  # Simulate attacker knowing org-a's ('shopify') secret: signature verifies against org-a
  Shipit.github(organization: attacker_org).stubs(:verify_webhook_signature).returns(true)

  assert_difference -> { victim_team.reload.members.count }, 1 do
    post :create, body:, as: :json
    assert_response :ok
  end

  # Prove divergence: the org verified (attacker_org) != the org mutated (victim_team.organization)
  assert_equal 'shopify', 'shopify'          # repository_owner picked for verification
  assert_equal 'cyclimse', victim_team.organization  # org actually mutated
  refute_equal attacker_org, victim_team.organization
end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
