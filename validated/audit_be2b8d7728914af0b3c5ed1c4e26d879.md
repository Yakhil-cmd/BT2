### Title
Sub-3-decimal sole collateral leg in the liquidation dead band makes every liquidation revert, freezing the debt — (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
An unprivileged borrower can construct an account whose only collateral is a whole-unit leg in an asset with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS`, such that when the account crosses `HF < 1`, the liquidation quote falls into a band where every `liquidate` offer reverts. The debt stays unliquidatable until interest accrual or a price move lifts it out of the band, temporarily freezing debt repayment and letting bad debt accrue. This mirrors CVE-2019-2529's bug class: a low-privilege actor crafts a state that the processing path (liquidation plan normalization, analogous to MySQL's optimizer) cannot handle, turning the operation into a repeatable failure.

### Finding Description
`build_liquidation_plan` requires `HF < 1` and then calls `normalize_repayment_plan` (contracts/controller/src/positions/liquidation/plan.rs:40-71). For a solvent partial plan, the ideal repayment passes through `whole_unit_repayment` (math.rs:235-291). When the account has exactly one supply position, its asset has `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS`, and it holds ≥ 1 whole unit, the function returns the unraised `quote_usd` only in a narrow window:

- `quote_usd * (1 + bonus) < unit_with_margin` (math.rs:266) — the quote backs less than one whole unit, and
- `unit_at_bonus < total_debt + one_unit_per_debt_leg_usd` (math.rs:275-280) — the full-close escape does not apply, and
- `unit_repayment >= snap.total_debt` (math.rs:287-289) — the raise-to-one-unit escape also does not apply.

In that window the plan stays at the quote. `calculate_seized_collateral` then floors the sub-unit seizure to zero whole units (math.rs:408-416), the leg is dropped, `unbacked_usd > 0` with an empty seizure list triggers `release_unbacked_repayment` on the whole `repay_usd` (plan.rs:76-79), and the emptied `repaid` vector fails `require_non_empty_payments(&result.repaid)` in `liquidate` (mod.rs:66). Every offer reverts identically: offers are capped at ceiling debt and trimmed to `ideal_repayment_usd`, so no input amount escapes the band. INV-LIQ-02 acknowledges this: "if the curve quote backs less than one unit, every offer reverts until accrual or a price move ends that state." INV-RISK-04 guarantees the shape is reachable — a sub-3-decimal supply leg must be the account's only supply position, so an attacker supplies exactly one such asset and borrows against it.

### Impact Explanation
Temporary freezing of funds: the unhealthy account's debt cannot be repaid by any liquidator while it sits in the band, and the same revert blocks the self-cure path. Protocol insolvency exposure grows during the freeze because borrow interest keeps accruing against collateral that cannot be seized; if the collateral price keeps falling while debt accrual stays below the `unit_repayment >= total_debt` boundary, the account drifts deeper underwater before becoming liquidatable. `clean_bad_debt` does not cover it while collateral exceeds the $5 dust threshold.

### Likelihood Explanation
Reachable by a single unprivileged address through `supply` + `borrow` on any listed hub asset configured with `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS`. The attacker does not choose when the band is hit (that depends on the HF curve quote and prices), but once an account enters it, the DoS is unconditional — every `liquidate` call reverts with no workaround available to liquidators. The freeze ends when accrual pushes `total_debt` past `unit_repayment`, so impact duration is bounded; that keeps it Medium rather than High. Whether a listed <3-decimal collateral asset exists is deployment-dependent; the code path itself is the defect.

### Recommendation
When `quote_usd` backs less than one whole unit and `unit_repayment >= total_debt`, clamp the plan to a full close at `snap.total_debt` (which already forces the leg to round up to `actual_ray` via `repays_all_debt`/`seize_all` handling) instead of keeping an unseizable quote. Alternatively, in `calculate_seized_collateral`, treat a sole sub-3-decimal leg whose floored seizure is zero as a forced one-unit seizure capped at `actual_ray`, so the plan never produces an empty seizure set with positive debt.

### Proof of Concept
1. Attacker calls `controller.supply` with a single payment in listed asset `A` where `asset_decimals < MIN_BORROWABLE_ASSET_DECIMALS` (e.g. 2 decimals), amount exactly 1 unit (per INV-RISK-04 this must be the account's only supply position).
2. Attacker calls `controller.borrow` to draw debt `D` on another asset.
3. Price of `A` (or the debt asset) moves so `HF < 1` and the curve quote satisfies `quote * (1 + bonus) < unit_usd + margin`, `unit_usd/(1+bonus) < D + Σleg units`, and `ceil((unit_usd+margin)/(1+bonus)) >= D`.
4. Any liquidator calls `controller.liquidate(account_id, debt_payments, SeizeMode::Transfer)`. For any offer: the plan normalizes to `quote_usd`, the sole leg's seizure floors to 0 units and is dropped at math.rs:419-421, `unbacked_usd > 0` with empty `seized_collaterals` releases all repayment at plan.rs:76-79, and `require_non_empty_payments(&result.repaid)` at mod.rs:66 reverts.
5. Repeat with any offered amount — every call reverts until accrued interest moves `D` out of the band.
