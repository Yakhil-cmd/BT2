### Title
Case-insensitive filesystem collision bypasses `existingSkillPrompt`, causing silent overwrite of skill files - (File: pkg/cmd/skills/install/install.go)

### Summary
A repository can publish two skills whose `Name` values differ only by case (e.g. `config` and `Config`) or Unicode form. `discovery.FindNameCollisions` and `checkOverwrite` compare names with plain, byte-exact Go string equality, so these are treated as distinct, non-colliding skills. When both are selected together (e.g. via `--all` or multi-select) and installed in a single `installer.Install` call, they are written concurrently to what resolves to the *same physical directory* on case-insensitive filesystems (default APFS on macOS, NTFS on Windows), completely bypassing `existingSkillPrompt` and the `--force` confirmation flow.

### Finding Description
- `collisionError` → `discovery.FindNameCollisions` groups skills with `byName[s.Name]` using exact string equality, with no case-folding or Unicode normalization: [1](#0-0) . Two skills named `config` and `Config` (or NFC/NFD variants of a name containing non-ASCII characters) are never reported as a collision.
- `checkOverwrite` in `pkg/cmd/skills/install/install.go` determines which of the selected skills already exist by calling `os.Stat(filepath.Join(targetDir, s.Name))` for every skill in the batch *before any of them are written*: [2](#0-1) . If neither `config` nor `Config` exists yet on disk at the time of this pre-check, both are classified as "fresh" and `existingSkillPrompt` (line 1089) is never invoked for either: [3](#0-2) .
- `installer.Install` then writes each skill's files by calling `installSkill`, using up to 5 concurrent goroutines, with each writing to `filepath.Join(baseDir, skill.Name)`: [4](#0-3)  and [5](#0-4) . On a case-insensitive filesystem, `baseDir/config` and `baseDir/Config` are the same physical directory, so the two skills' `SKILL.md` and other files (via `os.MkdirAll`/`os.WriteFile`) race and interleave/overwrite each other in that directory with zero user confirmation.
- Note: for a *sequential* second install of a differently-cased name against an *already-installed* skill, `os.Stat` correctly finds the existing directory on a case-insensitive FS and `existingSkillPrompt` is triggered as expected (reading the real `SKILL.md` at the resolved path). The gap is specifically the same-batch, concurrent-install path, where the pre-write existence check happens once for the whole batch before any file is written.

### Impact Explanation
An attacker who publishes a skills repository containing two (or more) skill directories whose names differ only by case (`skills/config/SKILL.md` and `skills/Config/SKILL.md`) can cause `gh skill install <repo> --all` (or a multi-select install of both names) to silently overwrite files on the victim's disk with attacker content, with no `existingSkillPrompt` confirmation, on macOS (APFS default) or Windows (NTFS). This is a scoped file-write/overwrite issue confined to the skills install target directory (host config directories like `.claude/skills`, `.agents/skills`, etc.) — matching a "file write/overwrite" impact class, though the write is confined to a directory the user already asked to install into, which limits it below full arbitrary-path traversal (no path-traversal was found; `safepaths.ParseAbsolute`/`Join` still guard against directory traversal within a skill's own files).

### Likelihood Explanation
Requires only that the attacker publish a GitHub repository/skills registry entry with two same-name-but-different-case (or Unicode-normalization-different) directories, and that the victim selects both (e.g., `--all`) on a case-insensitive filesystem (the common default for macOS and Windows). No privileged access is needed. It is deterministic given concurrent writes to the same directory, though which file "wins" is a race and non-deterministic per file.

### Recommendation
Normalize skill names (NFC Unicode normalization + case folding) before using them as map keys in `discovery.FindNameCollisions`, and apply the same normalized comparison in `checkOverwrite`'s existing-skill detection so batch-install collisions are always caught and routed through `existingSkillPrompt`/`--force`, instead of relying solely on `os.Stat`, which is filesystem-case-behavior dependent.

### Proof of Concept
Go test plan (in `internal/skills/discovery/collisions_test.go` style, extended into `pkg/cmd/skills/install/install_test.go`):
1. Stub a repo tree with `skills/config/SKILL.md` and `skills/Config/SKILL.md` (two `discovery.Skill{Name: "config", ...}` and `discovery.Skill{Name: "Config", ...}`).
2. Call `discovery.FindNameCollisions` on both — assert it currently returns `nil` (no collision detected), demonstrating the gap versus the expected case-folded/NFC-normalized invariant.
3. Run `installRun` with `--all` on a temp `Dir` on a case-insensitive filesystem (or simulate by pre-creating `Config` and asserting `os.Stat("config")` succeeds to confirm the FS is case-insensitive); assert that after install, the resulting `SKILL.md` content matches only one of the two source blobs and that `existingSkillPrompt`/`Prompter.Confirm` was never invoked for either skill despite both targeting the same physical directory.

func checkOverwrite(opts *InstallOptions, skills []discovery.Skill, targetDir string, canPrompt bool) ([]discovery.Skill, error) {
	var existing, fresh []discovery.Skill
	for _, s := range skills {
		dir := filepath.Join(targetDir, s.Name)
		if _, err := os.Stat(dir); err == nil {
			existing = append(existing, s)
		} else {
			fresh = append(fresh, s)
		}
	}

	if len(existing) == 0 {
		return skills, nil
	}

func existingSkillPrompt(targetDir string, incoming discovery.Skill) string {
	skillFile := filepath.Join(targetDir, incoming.Name, "SKILL.md")
	data, err := os.ReadFile(skillFile)
	if err != nil {
		return fmt.Sprintf("Skill %q already exists. Overwrite?", incoming.DisplayName())
	}

	result, err := frontmatter.Parse(string(data))
	if err != nil || result.Metadata.Meta == nil {
		return fmt.Sprintf("Skill %q already exists. Overwrite?", incoming.DisplayName())
	}

	repoInfo, _, err := source.ParseMetadataRepo(result.Metadata.Meta)
	ref, _ := result.Metadata.Meta["github-ref"].(string)
	if err != nil {
		return fmt.Sprintf("Skill %q already exists. Overwrite?", incoming.DisplayName())
	}

	if repoInfo != nil {
		sourceName := ghrepo.FullName(repoInfo)
		if ref != "" {
			sourceName += "@" + ref
		}
		return fmt.Sprintf("Skill %q already installed from %s. Overwrite?", incoming.DisplayName(), sourceName)
	}

	return fmt.Sprintf("Skill %q already exists. Overwrite?", incoming.DisplayName())
}
