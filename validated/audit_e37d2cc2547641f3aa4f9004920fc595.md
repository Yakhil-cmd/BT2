### Title
`SyncRepo` deletes the actively-published worktree before a replacement is ready, causing a dangling `--link` symlink on any subsequent failure - (File: `main.go`)

### Summary
`repoSync.SyncRepo` in `main.go` re-verifies the currently published worktree with `sanityCheckWorktree` and, if that check fails, immediately deletes the worktree directory that the `--link` symlink is *currently* pointing at via `removeWorktree`, before a new worktree has been created or the symlink has been repointed. If any of the subsequent steps (`createWorktree`, `configureWorktree`, `publishSymlink`) fail, the function returns an error and the on-disk symlink is left dangling, pointing at a directory that no longer exists.

### Finding Description
The relevant flow is in `repoSync.SyncRepo`: [1](#0-0) 

`currentWorktree` is derived directly from reading the published symlink target via `currentWorktree()`: [2](#0-1) 

When `currentHash == remoteHash` (i.e., git-sync believes nothing changed upstream), it calls `sanityCheckWorktree`, which can fail for several reasons including a `git fsck --connectivity-only` failure or a HEAD mismatch — checks whose outcome depends on the state of the objects fetched from the (potentially untrusted) remote repository: [3](#0-2) 

If the check fails, the code unconditionally calls `removeWorktree(ctx, currentWorktree)`, which does `os.RemoveAll` on the exact directory the `--link` symlink currently resolves to — the one path guaranteed by git-sync's documented "contract" to always be valid for consumers: [4](#0-3) 

Only after this destructive step does the code attempt to build and publish a replacement (`createWorktree` → `configureWorktree` → `publishSymlink`), each of which can return an error and cause `SyncRepo` to bail out immediately without ever calling `publishSymlink`: [5](#0-4) 

There is no re-check that the symlink still resolves to a valid target before the function returns on error, and no rollback that would repoint the symlink to a still-good location. This is the same root-cause pattern as the referenced M-37 report: a destructive/irreversible action (deleting funds / deleting the published directory) is taken before verifying that the post-condition invariant (`reservedFunds` covered / "`--link` always resolves to valid synced data") can still be satisfied.

### Impact Explanation
Per the README, the published symlink's validity is explicitly part of git-sync's "contract" with downstream consumers ("this is how the data is expected to be consumed"): [6](#0-5) 

If the symlink is left dangling after a failed re-publish attempt, every consumer container in the pod reading through `--link` gets ENOENT until a future sync loop iteration happens to succeed — this is a "publishing wrong/partial content" / transient denial-of-service condition on the git-sync contract, not merely benign log noise.

### Likelihood Explanation
`sanityCheckWorktree` failing while `currentHash == remoteHash` is an edge case (self-healing e2e tests such as `e2e::worktree_unexpected_removal` and `e2e::sync_recover_wrong_worktree_hash` show git-sync usually repairs itself in one loop iteration because the individual repair steps succeed). The bug only manifests as a real availability problem when one of `createWorktree`/`configureWorktree`/`publishSymlink` also fails on that same iteration (e.g., transient disk pressure, permission error, or a git error triggered by corrupted/partial objects from the remote). This makes the likelihood moderate rather than trivially reproducible, and it requires no special flags beyond default operation.

### Recommendation
Do not delete the actively-published worktree until a replacement worktree has been fully created, configured, and is ready to publish. Build the new worktree at a new path first, call `publishSymlink` to atomically flip the link, and only then remove the old (now-unreferenced) worktree — mirroring the existing "stale worktree" cleanup pattern that already defers deletion until after a hash change is safely published.

### Proof of Concept
Conceptual reproduction path (not exploit code, since this requires local fault injection, matching the pattern used by the existing `e2e::worktree_cleanup` / `e2e::worktree_unexpected_removal` tests):
1. Start git-sync normally so `--link` points at worktree `A` (hash currently == remote hash).
2. On a subsequent sync loop iteration (remote hash unchanged), induce `sanityCheckWorktree(A)` to fail (e.g. corrupt an object so `git fsck --connectivity-only` fails, as already simulated in `e2e::sync_recover_wrong_worktree_hash`) at [7](#0-6) .
3. `SyncRepo` calls `removeWorktree(ctx, A)`, deleting the directory the symlink still points to, at [8](#0-7) .
4. Simultaneously inject a failure in `createWorktree` or `configureWorktree` (e.g., make `--root/.worktrees` temporarily read-only, or interrupt via `--sync-timeout`) so that `SyncRepo` returns an error before reaching `publishSymlink` at [9](#0-8) .
5. Observe that `readlink $ROOT/link` now points at a non-existent path, and any consumer reading through `$ROOT/link` gets ENOENT until a future sync succeeds.

// sanityCheckWorktree tries to make sure that the dir is a valid git
// repository.  Note that this does not guarantee that the worktree has all the
// files checked out - git could have died halfway through and the repo will
// still pass this check.
func (git *repoSync) sanityCheckWorktree(ctx context.Context, worktree worktree) bool {
	git.log.V(3).Info("sanity-checking worktree", "repo", git.root, "worktree", worktree)

	// If it is empty, we are done.
	if empty, err := dirIsEmpty(worktree.Path()); err != nil {
		git.log.Error(err, "can't list worktree directory", "path", worktree.Path())
		return false
	} else if empty {
		git.log.V(0).Info("worktree is empty", "path", worktree.Path())
		return false
	}

	// Make sure it is synced to the right commmit.
	stdout, _, err := git.Run(ctx, worktree.Path(), "rev-parse", "HEAD")
	if err != nil {
		git.log.Error(err, "can't get worktree HEAD", "path", worktree.Path())
		return false
	}
	if stdout != worktree.Hash() {
		git.log.V(0).Info("worktree HEAD does not match worktree", "path", worktree.Path(), "head", stdout)
		return false
	}

	// Consistency-check the worktree.  Don't use --verbose because it can be
	// REALLY verbose.
	if _, _, err := git.Run(ctx, worktree.Path(), "fsck", "--no-progress", "--connectivity-only"); err != nil {
		git.log.Error(err, "worktree fsck failed", "path", worktree.Path())
		return false
	}

	return true
}

// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}

// currentWorktree reads the repo's link and returns a worktree value for it.
func (git *repoSync) currentWorktree() (worktree, error) {
	target, err := os.Readlink(git.link.String())
	if err != nil && !os.IsNotExist(err) {
		return "", err
	}
	if target == "" {
		return "", nil
	}
	if filepath.IsAbs(target) {
		return worktree(target), nil
	}
	linkDir, _ := git.link.Split()
	return worktree(linkDir.Join(target)), nil
}
