### Title
Unvalidated `redirect_to(return_url)` in `GithubAuthenticationController#callback` allows open redirect via the OmniAuth `origin` value - ([File: app/controllers/shipit/github_authentication_controller.rb])

### Summary
`GithubAuthenticationController#callback` redirects the just-authenticated user to `request.env['omniauth.origin']` without any same-host/path validation. Because the OmniAuth request-phase endpoint (`/github/auth/github`) is mounted as raw Rack middleware by this engine (`lib/shipit/engine.rb`) and stores whatever `origin` query parameter is supplied into the session/env for playback at callback time, an attacker can craft a link such as `/github/auth/github?origin=https://evil.example.com` that, once the victim completes GitHub OAuth, causes Shipit to redirect them off-host immediately after establishing their authenticated session.

### Finding Description
The intended binding is: `return_url == a same-host Shipit path`, since the engine's own code always constructs the origin as `request.original_url` (e.g. `app/controllers/concerns/shipit/authentication.rb#force_github_authentication`, lines 24 and 32) whenever it drives users into the OAuth flow itself: `redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))` [1](#0-0) .

However, the `origin` parameter accepted at the OmniAuth request-phase entrypoint (`/github/auth/github`, wired up via `OmniAuth::Builder`/`OmniAuth::Strategies::GitHub` in the engine initializer) is not restricted to values produced by `force_github_authentication` — it is simply read from the incoming request's query string by the OmniAuth gem and later replayed into `request.env['omniauth.origin']` at callback time. `GithubAuthenticationController#callback` then does:

```ruby
return_url = request.env['omniauth.origin'] || root_path
...
redirect_to(return_url)
``` [2](#0-1) 

There is no `only_path` enforcement, no host allowlist check (e.g. against `Shipit.host`), and no scheme restriction before calling `redirect_to`. An attacker who is not authenticated and holds no Shipit or GitHub secrets can send a victim (or their own browser, for PoC purposes) a link of the form:

```
https://shipit.example.com/github/auth/github?origin=https://evil.example.com
```

After GitHub OAuth completes normally (the victim authenticates with their own real GitHub account — no secrets of Shipit's are needed), `GithubAuthenticationController#callback` sets `session[:user_id]` and `session[:authenticated] = true`, then redirects the freshly-authenticated browser to `https://evil.example.com`, i.e., immediately off the trusted host right after session establishment. None of the guard mechanisms listed in the audit rules apply here: `verify_signature` / `GitHubApp#verify_webhook_signature` / `drop_unhandled_event` guard the webhook pipeline, not this OAuth callback; `force_github_authentication` and `User#authorized?` only gate access to already-mounted app controllers and are not invoked in `GithubAuthenticationController`; there is no `ExplicitParameters` schema, model validation, or `EnvironmentVariables#permit` anywhere on this code path since `return_url` never becomes an ActiveRecord attribute.

### Impact Explanation
This does not grant the attacker any Shipit privilege, does not leak `GITHUB_TOKEN`/`github_access_token`/`api_clients_secret`, does not cause a forged webhook or deploy, and does not escalate anyone into `Shipit.github_teams`. What it does allow is redirecting a legitimately-authenticating user's browser to an attacker-controlled destination immediately after their Shipit session cookie is set on the real host — a classic "forced OAuth completion" / phishing continuation. This matches the High-severity category "session fixation / forced OAuth completion" defined in the rules, but only in that narrow sense: the session itself is fixed to the real Shipit host (cookies are still scoped to `shipit.example.com`), only the post-auth redirect target is attacker-controlled. It is repeatable against any victim who clicks the crafted link and does not depend on which repository/stack is targeted — it's a single-tenant, per-victim browser redirect, not a cross-tenant data or credential compromise.

### Likelihood Explanation
Preconditions are minimal: GitHub OAuth must be enabled (`Shipit.github.oauth?`), which is the documented normal configuration for this engine. The attacker needs no Shipit account, API token, or GitHub App/webhook secret — only the ability to send a link to a victim. The main friction is that the victim must click the crafted link and manually complete the GitHub OAuth consent screen with their own credentials; the attacker cannot force this without user interaction, so this is a lure/phishing-dependent primitive rather than a fully attacker-triggerable one-shot exploit.

### Recommendation
Validate `return_url` before using it: allow only relative/local paths (e.g. via `URI.parse(return_url).host.nil?` or Rails' own local-redirect helpers) or explicitly check the host against `Shipit.host`/the app's configured domain before calling `redirect_to`; fall back to `root_path` for anything else. Also consider restricting the `origin` parameter accepted by the OmniAuth request-phase route to local paths.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback does not redirect off-host via omniauth.origin" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(
      raw_info: OmniAuth::AuthHash.new(
        id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
        login: 'shipit-user', avatar_url: 'https://example.com',
        api_url: 'https://github.com/api/v3/users/shipit-user'
      )
    )
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example.com'

  get :callback

  # Binding under test: return_url == a same-host Shipit path
  redirect_host = URI.parse(response.location).host
  assert_not_equal 'evil.example.com', redirect_host
  assert_equal 'test.host', redirect_host # or Shipit.host
end
```
Running this against the current code fails: `response.location` is `https://evil.example.com`, demonstrating the unvalidated redirect.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end
