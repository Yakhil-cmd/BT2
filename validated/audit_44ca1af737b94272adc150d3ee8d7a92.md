### Title
Cross-organization webhook signature confusion allows forged GitHub events for any repository in a multi-org deployment - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp`/`webhook_secret` to validate an incoming webhook against using the attacker-controlled, *unverified* JSON body field `repository.owner.login` (or `organization.login`), while the event handlers that actually act on the payload resolve the target `Repository`/`Stack` from a different field in the same unverified body: `repository.full_name`. Nothing ties these two fields together, so a signature that is valid for organization A can be replayed to act on organization B's repository/stack.

### Finding Description
In a multi-tenant Shipit deployment, `Shipit.github(organization:)` selects a distinct `GitHubApp` config (and thus a distinct `webhook_secret`) per GitHub organization: [1](#0-0) 

The controller picks which organization's secret to validate against from the *unauthenticated* payload before the signature has been checked: [2](#0-1) 

`repository_owner` is read straight out of `params.dig('repository', 'owner', 'login')` — a field inside the JSON body that has no cryptographic binding to the actual signature check that is about to happen. `verify_signature` never verifies that `repository.full_name`'s owner segment matches `repository.owner.login`.

Once the signature check passes, `WebhooksController#create` dispatches the *same raw payload* to event handlers: [3](#0-2) 

Handlers resolve the actual `Repository`/`Stack` to mutate using `repository.full_name`, completely independent of `repository.owner.login`: [4](#0-3) [5](#0-4) 

The `status` event handler in particular takes attacker-supplied `state`/`context`/`sha` and creates a `Status` record for any commit matching the sha, across the whole install (not scoped by which org's secret was used): [6](#0-5) 

That status insertion drives deploy-relevant state transitions: it can flip a commit to `success`, schedule merges, and fire `deployable_status`/`commit_status` hooks: [7](#0-6) 

**Trust binding broken:** the organization whose `webhook_secret` authenticated the request (`repository.owner.login` at [8](#0-7) ) ≠ the repository/organization whose `Stack`/`Commit` state is actually written (`repository.full_name` at [9](#0-8) ).

### Impact Explanation
An attacker who controls (or knows the `webhook_secret` for) any single low-value organization configured in the same Shipit instance can forge webhooks that are accepted as authentic for a completely different, higher-value organization's repositories. Concretely this enables:
- Injecting fabricated `status` events that flip a victim-org commit's CI state to `success`, unblocking deploy/merge gating logic (`stack.schedule_merges`, `deployable_status`) — an unauthorized-deploy/merge-relevant impact.
- Forging `push`/`pull_request` events that enqueue sync jobs or archive/unarchive review stacks belonging to a repository the attacker does not own.

This matches the "organization that authenticated versus the repository that is written" trust-binding category and can lead to an unauthorized deploy/merge decision on a repository the attacker does not control, without ever needing a Shipit session, API token, or the victim org's real webhook secret.

### Likelihood Explanation
Requires the target Shipit instance to be configured for more than one GitHub organization (the multi-org schema in `lib/shipit.rb`'s `github_app_config`/`TOP_LEVEL_GH_KEYS`) and requires the attacker to know the `webhook_secret` of at least one of those configured organizations (e.g., an org they administer or one whose secret is otherwise available to them). This is a realistic but non-trivial precondition, so likelihood is medium rather than trivial-and-universal.

### Recommendation
Bind the signature-verification organization to the same identity used by the handlers to resolve the target repository: after computing `github_app` from `repository_owner`, re-derive the owner from `repository.full_name` and reject the request (422) if the two disagree, or better, resolve the `GitHubApp`/secret to use based on the already-persisted `Shipit::Repository#owner` (looked up from `full_name`) rather than trusting the unauthenticated `repository.owner.login`/`organization.login` field.

### Proof of Concept
1. Configure Shipit with two organizations, `attacker-org` and `victim-org`, each with its own `webhook_secret` (multi-org schema per `lib/shipit.rb`).
2. Attacker knows `attacker-org`'s `webhook_secret` (e.g. they are a legitimate but low-privileged member who can configure webhooks for a repo under `attacker-org`).
3. Attacker crafts a `status` webhook JSON body:
   ```json
   {
     "sha": "<victim commit sha>",
     "state": "success",
     "context": "ci/required-check",
     "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
   }
   ```
4. Attacker computes `X-Hub-Signature: sha1=HMAC(attacker-org secret, raw_body)` and POSTs to `/webhooks` with `X-Github-Event: status`.
5. `verify_signature` calls `Shipit.github(organization: "attacker-org")` (from `repository.owner.login`) and the HMAC checks out, so the request passes. [10](#0-9) 
6. `StatusHandler#process` then creates a `Status` for the matching commit in `victim-org/victim-repo`, using only `payload['sha']`, with no re-check of which org's secret was used: [11](#0-10)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
