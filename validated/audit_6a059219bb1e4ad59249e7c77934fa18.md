## Analysis

The external report's bug class is: **a fee meant only for a specific "assisted" code path is unconditionally applied even on the "self-service" path where the documentation says no fee should be charged**, which silently reduces the funds the rightful party receives.

The closest reachable analog in `ocore` is in `arbiter_contract.js`, in the arbiter‑contract escrow flow (a wallet/contract-message handling path reachable by any private‑payment counterparty who enters into an arbiter contract with a peer — no external/hub/node privilege required).

### Root cause

`deriveSharedAddress()` builds an `["or", […]]` shared‑address definition with several alternative unlock branches:

- Branch `[1][0]`: `["and", [["address", offeror_address], ["address", acceptor_address]]]` — a **pure mutual‑signature branch**, requiring *only* both parties' signatures, with **no output restriction and no arbstore cut**. This is the "self-service" branch — the two counterparties settle directly without ever invoking the arbiter/arbstore.
- Branches `[1][1]` / `[1][2]`: the **dispute-resolution branches**, gated by an `"in data feed"` condition from `contract.arbiter_address`, which additionally force a `"has output"` condition sending `contract.amount - Math.floor(contract.amount * (1 - cut))` to the arbstore address: [1](#0-0) 

So on-chain, branch `[1][0]` (mutual agreement) is fee-free by design — exactly like the documented "self-liquidation" no-fee guarantee in the report.

However, `complete()` — the function wallets call to release/refund escrowed funds after a contract is `"paid"` — does **not** distinguish which unlock branch will actually be used. It unconditionally reads the *dispute-branch* definition (`arrDefinition[1][index]`, where `index` is `1` or `2`, never `0`) to compute `peer_amount`/`arbstore_amount`, and — whenever `hasArbStoreCut` was true at address-derivation time — always builds the payment with the arbstore cut carved out as a separate output to `objContract.arbstore_address`: [2](#0-1) 

This means that even when both counterparties are simply completing the contract by mutual agreement (the `"and"` branch `[1][0]`, which needs only both parties' signatures and has no output restriction, and never invokes the arbiter or arbstore at all), the wallet code still forces a payment split that pays the arbstore its cut — a fee that, per the address definition's own fee-free mutual branch, should not apply to this path.

### Impact

Funds that should go entirely to the peer on a normal, dispute-free, mutually-agreed contract completion are instead partially diverted to the arbstore address, permanently reducing the amount the peer receives — an unconditional, undocumented fee deduction on a self-service settlement path, analogous to the reported `SelfLiquidate.sol` bug where a fee designed only for externally-assisted flows is charged on the party-only flow.

### Recommendation

`complete()` should only apply the arbstore-cut split when the completion is actually settled via the arbiter/data-feed branch (i.e., a real dispute resolution occurred). For a normal mutual completion via branch `[1][0]`, the full `contract.amount` should go to the peer, with no output to `arbstore_address`. [3](#0-2)

								];
							}

						cb(null, objContract, unit);
					});
				});
			}).catch(err => {
