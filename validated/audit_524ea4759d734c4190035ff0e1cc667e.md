### Title
Webhook Organization Used for Signature Verification is Decoupled from the Repository Used for Event Processing - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/organization config (and thus the HMAC secret) to validate the request against based on `repository.owner.login` (or `organization.login`), while the event handlers that actually act on the payload (create stacks, sync commits, add team memberships, etc.) key off the unrelated field `repository.full_name`. These two fields are never cross-checked against each other, and per-organization `webhook_secret` is optional, so a payload can be "authenticated" for one organization while its effects are applied to a repository/stack belonging to a completely different organization.

### Finding Description
`WebhooksController#verify_signature` resolves the org for signature checking purely from attacker-controlled JSON: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` explicitly short-circuits to `true` when the resolved organization has no `webhook_secret` configured: [3](#0-2) 

The `test/dummy` fixtures show that per-org `webhook_secret` is expected to be optional in multi-tenant configs (`OrgTwo: webhook_secret: # nil`): [4](#0-3) 

After signature "verification" passes, every event handler resolves the target repository/stack from a completely different, unverified field, `repository.full_name`, with no linkage back to the `repository.owner.login`/`organization.login` value used for authentication: [5](#0-4) 

The `push` handler then uses this org-agnostic lookup to enqueue a sync against arbitrary stacks using an attacker-controlled `after` SHA: [6](#0-5) 

The binding that should hold is: `organization used to authenticate the webhook == organization owning the repository the handler acts on`. Because `verify_signature` only ever inspects `repository.owner.login`/`organization.login`, and `Handler#repository_name` only ever inspects `repository.full_name`, an attacker who can get one webhook through (either against an organization with no configured `webhook_secret`, or with a stolen/leaked secret for org A) can set `repository.owner.login`/`organization.login` = "OrgA" to satisfy signature verification, while setting `repository.full_name` = "OrgB/victim-repo" to make the handler operate against org B's stack, even though the request was never authenticated for org B at all.

### Impact Explanation
Concretely, if any organization configured in `Shipit.secrets.github` has a blank `webhook_secret` (an explicitly supported, documented configuration per the fixtures), then:
- `Shipit.github(organization: 'OrgWithNoSecret')` succeeds without raising `GithubOrganizationUnknown`.
- `verify_webhook_signature` returns `true` unconditionally for that request, regardless of the actual `X-Hub-Signature` header.
- The attacker can then set `repository.full_name` to any other organization's repository tracked by Shipit, causing `Handler#stacks` to resolve real stacks belonging to that unrelated, actually-secured organization.
- For the `push` event this enqueues `GithubSyncJob` with an attacker-chosen `after` SHA against that organization's stack, and for `membership` events this can create/delete `Team`/`Membership`/`User` records tied to that organization — all without ever presenting a valid signature for the organization being acted upon.

This breaks the "organization authenticated versus repository being written" binding described in scope, and results in unauthorized, unauthenticated manipulation of stack sync state, membership/team data for organizations the attacker was never authorized to touch.

### Likelihood Explanation
This is reachable by any unauthenticated, unprivileged network attacker able to POST to the public `/webhooks` endpoint — no `ApiClient` token, GitHub App private key, or session is required. The only precondition is that at least one organization configured in the Shipit instance has no `webhook_secret` set (a state the codebase and test fixtures explicitly support as valid, rather than a misconfiguration the app disallows).

### Recommendation
Bind the two identities together instead of trusting them independently: derive the repository/stack to act on from the same organization value that was used to select the signing secret (e.g., verify that `repository.full_name.split('/').first.casecmp(repository_owner) == 0` before dispatching to handlers), or reject any webhook where `repository.owner.login` (used for auth) doesn't match the owner segment of `repository.full_name` (used for effects). Separately, consider requiring `webhook_secret` to be present for every configured organization rather than treating it as optional.

### Proof of Concept
1. Configure Shipit with two orgs, e.g. `OrgA` (`webhook_secret: nil`) and `OrgB` (`webhook_secret: <real-secret>`), each with tracked repositories/stacks — this mirrors the supported multi-org config shown in `test/dummy/config/secrets_double_github_app.yml`.
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: push` and no valid `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" }
}
```
3. `verify_signature` resolves `repository_owner` = `"OrgA"`, looks up `Shipit.github(organization: "OrgA")`, and since `OrgA` has no `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally — the request passes with no valid signature at all.
4. `PushHandler` resolves `repository_name` from `repository.full_name` = `"OrgB/victim-repo"`, unrelated to `OrgA`, and enqueues `GithubSyncJob` against `OrgB`'s real, secured stack with the attacker-supplied `after` SHA. [7](#0-6) [1](#0-0)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
