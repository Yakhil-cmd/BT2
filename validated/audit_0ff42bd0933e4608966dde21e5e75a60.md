## Finding

### Title
Stack-scoped API client tokens can read CI/build status of any stack via CCMenu endpoint - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` accessor to resolve the target stack from **all** stacks instead of the caller's authorized stack set, breaking the binding between the stack(s) an `ApiClient` token is scoped to and the stack whose data is actually returned.

### Finding Description
`Shipit::Api::BaseController` establishes the binding "stack a token authorizes == stack a token touches" through its `stacks`/`stack` helpers: [1](#0-0) 

`current_api_client.stack_id?` restricts the visible `Stack` collection to the single stack the token was scoped to when it was created (`belongs_to :stack, optional: true` on `ApiClient`, exercised by fixture `here_come_the_walrus` which is scoped to the `shipit` stack, and tested in `test/controllers/api/stacks_controller_test.rb:217-223` — "an api client scoped to a stack will only see that one stack").

`CCMenuController`, however, defines its own private `stack` method that bypasses this scoping entirely: [2](#0-1) 

Instead of calling `stacks.from_param!(params[:stack_id])` (which would respect `current_api_client.stack_id`), it calls `Stack.from_param!(params[:stack_id])` directly against the full `Stack` table. The controller still enforces `require_permission :read, :stack` (a permission check), but that check only verifies the *permission name* `read:stack`, not which specific stack the token is bound to. The equality that should hold — **stack(s) authorized for this token == stack acted upon in this request** — is broken: any token with `read:stack` permission, no matter which single stack it was scoped to at creation, can pass an arbitrary `stack_id` param and read a different stack's build/deploy status.

### Impact Explanation
An attacker who possesses (or a partner integration that was issued) a stack-scoped `ApiClient` token intended to expose only one stack's CI status through the CCMenu (CCTray) protocol can instead enumerate and read the deploy/build status (`lastBuildStatus`, `lastBuildLabel`, `activity`, lock reason, etc., per `app/views/shipit/ccmenu/project` template) of **every** stack in the Shipit instance, including stacks it has no legitimate visibility into. This is an authorization-scope escalation resulting in unauthorized read of stack state across repositories/stacks, matching the "unauthenticated/unauthorized read of stack state" High-impact category — the token's read is not properly bound to the stack it was authorized for.

### Likelihood Explanation
Exploitation only requires possession of any valid API token with `read:stack` permission (regardless of its intended `stack_id` scope) and knowledge or guessing of another stack's slug/param — both are low-effort for anyone already holding a legitimately-scoped token (e.g., a partner CI dashboard integration). No additional privilege or session is required beyond what the reporter already has as a token holder, matching the "unprivileged-attacker" analog criteria (the token's normal purpose is a single stack; crossing to other stacks is the escalation).

### Recommendation
Change `CCMenuController#stack` to reuse the scoped resolution from `BaseController`, e.g. `stacks.from_param!(params[:stack_id])`, instead of querying `Stack` directly, so stack-scoped tokens cannot read data for stacks outside their authorized scope.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to `stack_id: shipit` with permission `read:stack` (e.g. fixture `here_come_the_walrus`).
2. As documented/tested, this token is restricted to the `shipit` stack for `Api::StacksController#index` (`test/controllers/api/stacks_controller_test.rb:217-223`).
3. Using the same token against the CCMenu endpoint with a different stack's slug:
   `GET /api/stacks/<other_stack_owner>/<other_stack_repo>/<other_env>/ccmenu.xml?token=<here_come_the_walrus_token>`
4. Because `CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` rather than `stacks.from_param!(...)`, the request succeeds (200 OK) and returns the CI/build status of the unauthorized stack, even though the token is only supposed to see the `shipit` stack. module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end
