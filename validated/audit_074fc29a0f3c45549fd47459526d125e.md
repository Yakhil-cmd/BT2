### Title
Bridge Peer Handshake Accepts Any ChainID — Missing Validation in `baseBridgePeer.readStatus` Allows Cross-Chain Peer Registration with Silently-Ignored Rejection — (File: `node/sc/bridgepeer.go`)

---

### Summary

The service-chain bridge peer handshake (`baseBridgePeer.readStatus`) omits the `ChainID` equality check that the main-chain peer handshake (`basePeer.readStatus`) enforces. A peer advertising a different chain ID passes the handshake, is registered in the peer set, and the subsequent `RegisterNewPeer` guard that would reject it has its error return silently discarded by `SubBridge.handle`. The connected rogue peer can then inject `ServiceChainParentChainInfoResponseMsg` messages that overwrite the SubBridge's `mainChainAccountNonce` and `remoteGasPrice`, corrupting the nonce used to sign every subsequent anchoring and value-transfer transaction submitted to the parent chain.

---

### Finding Description

**Main-chain peer handshake** (`node/cn/peer.go`, `basePeer.readStatus`) validates four fields:

```
GenesisBlock  ✓
NetworkId     ✓
ChainID       ✓   ← present
ProtocolVersion ✓
``` [1](#0-0) 

**Bridge peer handshake** (`node/sc/bridgepeer.go`, `baseBridgePeer.readStatus`) validates only two:

```
NetworkId       ✓
ProtocolVersion ✓
ChainID         ✗   ← absent
GenesisBlock    ✗   ← absent
``` [2](#0-1) 

After the handshake succeeds, `p.chainID` is set to whatever the remote peer claimed: [3](#0-2) 

`SubBridge.handle` then calls `RegisterNewPeer`, which does check ChainID and returns an error on mismatch — but the caller **discards the return value**: [4](#0-3) 

`RegisterNewPeer` itself: [5](#0-4) 

Because the error is ignored, the peer remains in `sb.peers` and the message loop continues. The peer can now send `ServiceChainParentChainInfoResponseMsg`, which the SubBridge handler processes unconditionally, overwriting `mainChainAccountNonce` and `remoteGasPrice`.

---

### Impact Explanation

`mainChainAccountNonce` is the nonce the SubBridge uses to sign every transaction it submits to the parent chain (anchoring transactions, value-transfer handle transactions). A rogue peer that injects a stale or future nonce causes:

- **Nonce-too-low**: all pending bridge transactions are rejected by the parent chain mempool, halting value-transfer settlement.
- **Nonce-too-high**: the SubBridge queues transactions with a gap nonce, blocking execution until the gap is filled, effectively freezing cross-chain asset movement.

`remoteGasPrice` controls the gas price of those same transactions; setting it to zero or an extreme value can make them unmineable or wasteful.

The `broadcastServiceChainTx` guard that skips peers with wrong ChainID does not protect against inbound messages from those peers: [6](#0-5) 

---

### Likelihood Explanation

Any node that can reach the bridge's listening port (`MainBridgePort`) and speak the service-chain P2P protocol can trigger this. The bridge server is configured with `NoDial: true` and `NoDiscovery: true` but still accepts inbound connections. A node running a different service chain (different ChainID, same network topology) or a purpose-built attacker node can connect, pass the handshake (NetworkId and ProtocolVersion are the only checks), and immediately send a crafted `ServiceChainParentChainInfoResponseMsg`.

---

### Recommendation

1. **Add ChainID validation in `baseBridgePeer.readStatus`**, mirroring `basePeer.readStatus`:

```go
if status.ChainID.Cmp(chainID) != 0 {
    return errResp(ErrChainIDMismatch, "%v (!= %v)", status.ChainID, chainID)
}
``` [2](#0-1) 

2. **Check and propagate the error from `RegisterNewPeer`** in `SubBridge.handle`:

```go
if err := sb.handler.RegisterNewPeer(p); err != nil {
    p.GetP2PPeer().Log().Error("RegisterNewPeer failed", "err", err)
    return err
}
``` [4](#0-3) 

3. Apply the same fix to `MainBridge.handle` for symmetry.

---

### Proof of Concept

1. Start a Kaia node with `--mainbridge` on chain A (ChainID=1001).
2. Start a second node with `--subbridge` on chain B (ChainID=9999), pointing its bridge endpoint at chain A's bridge port.
3. The SubBridge node completes the handshake (NetworkId and ProtocolVersion match; ChainID is not checked).
4. `SubBridge.handle` calls `RegisterNewPeer`; it returns `"attempt to add a peer with different chainID"` but the error is discarded.
5. The chain-B node sends a `ServiceChainParentChainInfoResponseMsg` with `Nonce = 0xFFFFFFFFFFFFFFFF`.
6. The SubBridge sets `mainChainAccountNonce = 0xFFFFFFFFFFFFFFFF`.
7. All subsequent anchoring and value-transfer transactions signed by the SubBridge carry nonce `0xFFFFFFFFFFFFFFFF`, are rejected by the parent chain mempool, and cross-chain asset settlement halts. [7](#0-6) [8](#0-7) [5](#0-4)

func (p *baseBridgePeer) Handshake(network uint64, chainID, td *big.Int, head common.Hash) error {
	// Send out own handshake in a new thread
	errc := make(chan error, 2)
	var status statusData // safe to read after two values have been received from errc

	go func() {
		errc <- p2p.Send(p.rw, StatusMsg, &statusData{
			ProtocolVersion: uint32(p.version),
			NetworkId:       network,
			TD:              td,
			CurrentBlock:    head,
			ChainID:         chainID,
		})
	}()
	go func() {
		e := p.readStatus(network, &status)
		if e != nil {
			errc <- e
			return
		}
		errc <- e
	}()
	timeout := time.NewTimer(handshakeTimeout)
	defer timeout.Stop()
	for range 2 {
		select {
		case err := <-errc:
			if err != nil {
				return err
			}
		case <-timeout.C:
			return p2p.DiscReadTimeout
		}
	}
	p.td, p.head, p.chainID = status.TD, status.CurrentBlock, status.ChainID
	return nil
}

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}
