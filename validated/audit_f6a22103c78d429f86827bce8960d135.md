### Title
Repository used for signature verification is decoupled from repository used for record mutation, allowing `EditedHandler` to write into an arbitrary victim stack's `PullRequest`/`Commit` records via a no-secret organization - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus whether HMAC verification is enforced) using `params.dig('repository','owner','login')`, while `EditedHandler` locates the `PullRequest`/`Stack`/`Repository` to mutate using the completely separate `params.repository.full_name` field. Nothing binds these two fields together, so an attacker can set `repository.owner.login` to a Shipit-configured organization whose `webhook_secret` is blank (bypassing verification unconditionally) while setting `repository.full_name` to an unrelated victim's `owner/repo`, causing the `EditedHandler` to update that victim's persisted `PullRequest` and, via the `github_pull_request=` setter, create a new `Commit` on the victim stack.

### Finding Description
The broken binding, stated as an equality that the code implicitly assumes but never enforces:

`verification_org = params.dig('repository','owner','login')` **should equal** `target_repository = Shipit::Repository.from_github_repo_name(params.repository.full_name).owner`

Trace:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner` purely from `params.dig('repository','owner','login')` and uses it to fetch a `GitHubApp` via `Shipit.github(organization: repository_owner)`. [1](#0-0) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever `@webhook_secret` is blank for that organization's config. [2](#0-1) 
- `EditedHandler#repository` and `EditedHandler#pull_request` instead derive the target repository/stack/pull-request purely from `params.repository.full_name`, an entirely separate JSON field with no cross-check against `params.repository.owner.login`. [3](#0-2) 
- `EditedHandler#process` then writes `pull_request.update(github_pull_request: params.pull_request)` for whatever record that lookup returns. [4](#0-3) 
- `PullRequest#github_pull_request=` mutates `github_id`, `number`, `api_url`, `title`, `state`, `additions`, `deletions`, `user`, `assignees`, `labels`, and critically calls `find_or_create_commit_from_github_by_sha!`, which can create a brand-new `Commit` row on the victim stack via `stack.commits.create_from_github!(github_commit)`. [5](#0-4) 

Exploit flow: attacker (no Shipit credentials) sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `action: "edited"`, `repository.owner.login: "no-secret-org"` (an org configured in Shipit with a blank `webhook_secret`), but `repository.full_name: "victim-org/victim-repo"` (the actual victim stack, unrelated to `no-secret-org`). `verify_signature` looks up the `no-secret-org` `GitHubApp`, finds no `webhook_secret`, and accepts the request unconditionally regardless of signature. `EditedHandler` then resolves the target repository/stack purely from `full_name`, finds the existing `PullRequest` for `victim-org/victim-repo`, and persists attacker-controlled `title`, `state`, `labels`, `assignees`, and (via the SHA-driven commit-creation path) potentially adds a new `Commit` to the victim's continuous_deployment-enabled stack.

None of the existing guards prevent this: `drop_unhandled_event` only checks event type, `verify_signature` only checks the org from `owner.login` (not `full_name`), the `ExplicitParameters` schema in `EditedHandler` validates types/presence but not that `repository.full_name`'s owner matches `repository.owner.login`, and no model validation cross-checks a webhook's authenticated organization against the resolved `Repository`.

### Impact Explanation
This is a payload for one repository/organization mutating another repository's stack/commit/pull-request records — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." Concretely: the attacker can silently rewrite the state/title/labels/assignees of any victim `PullRequest`, and inject a new `Commit` record into the victim's `Stack.commits` association by referencing any real SHA that exists in the victim's actual GitHub repository via `stack.github_api.commit(stack.github_repo_name, sha)`. On a `continuous_deployment`-enabled stack, `Stack.schedule_continuous_delivery` periodically enqueues `ContinuousDeliveryJob` for every such stack regardless of trigger, and that job deploys `next_commit_to_deploy` if it passes `deployable?`/status checks — so an injected commit that already has passing CI status on GitHub becomes eligible for automatic deployment sooner or via reachable-commit changes that the attacker did not otherwise control. This is repeatable against any victim repository/stack in the Shipit instance, as long as one org anywhere in the Shipit config lacks a `webhook_secret` — the blast radius spans the whole multi-tenant install, not just the misconfigured org's own repos.

### Likelihood Explanation
Preconditions: (1) at least one organization configured in Shipit (`Shipit.github(organization: ...)` config) with a blank `webhook_secret` — an existing, pre-established misconfiguration gap (the "no-secret organization" case from the referenced prior question); (2) a victim stack with an existing `Shipit::PullRequest` record (created earlier through a legitimate `opened` event) so `EditedHandler#pull_request` finds a match. Attacker cost is a single unauthenticated HTTP POST with a crafted JSON body and `X-Github-Event: pull_request` header — no signature, no session, no API token required. This is fully repeatable against arbitrary target stacks by simply changing `repository.full_name` in the forged payload.

### Recommendation
Bind webhook signature verification to the same repository identity used for record resolution: derive the verifying organization from `params.repository.full_name`'s owner segment (or verify that `params.repository.owner.login` matches the owner of the repository resolved from `full_name`) before any handler runs, and reject (422) whenever they diverge. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when `webhook_secret` is blank — a missing secret should either be treated as a hard misconfiguration (reject all webhooks) or the organization should be prevented from being registered without a webhook secret at all.

### Proof of Concept
Minitest plan (`test/controllers/shipit/webhooks_controller_test.rb`-style, no live GitHub):
1. Configure two orgs in `Shipit.github_config`-equivalent test setup: `"no-secret-org"` with no `webhook_secret`, and `"victim-org"` with a real one.
2. Create `victim_repo = shipit_repositories(:shipit)` (or equivalent) owned by `"victim-org"`, a `stack` with `continuous_deployment: true`, and a `Shipit::PullRequest` fixture with `number: 42`, `stack: victim_stack`.
3. POST to `/webhooks` with `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and body:
   ```json
   {
     "action": "edited",
     "number": 42,
     "pull_request": { "id": 1, "number": 42, "url": "...", "title": "attacker title", "state": "open",
       "additions": 1, "deletions": 1, "head": {"sha": "<victim real sha>", "ref": "attacker-branch"},
       "user": {"login": "attacker"}, "assignees": [], "labels": [] },
     "repository": {"full_name": "victim-org/victim-repo", "owner": {"login": "no-secret-org"}},
     "sender": {"login": "attacker"}
   }
   ```
4. Assert response is `200`/`204` (not `422`), i.e., `verify_signature` accepted it via `no-secret-org`'s blank `webhook_secret`.
5. Reload the fixture `PullRequest` and assert `pull_request.title == "attacker title"` and `pull_request.state == "open"`, proving `params.repository.owner.login` ("no-secret-org") ≠ the org that actually owns the mutated record ("victim-org") — the binding `verification_org == target_repository.owner` is violated.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def github_pull_request=(github_pull_request)
      self.github_id = github_pull_request.id
      self.number = github_pull_request.number
      self.api_url = github_pull_request.url
      self.title = github_pull_request.title
      self.state = github_pull_request.state
      self.additions = github_pull_request.additions
      self.deletions = github_pull_request.deletions
      self.user = User.find_or_create_by_login!(github_pull_request.user.login)
      self.assignees = github_pull_request.assignees.map do |github_user|
        User.find_or_create_by_login!(github_user.login)
      end
      self.labels = github_pull_request.labels.map(&:name)
      self.head = find_or_create_commit_from_github_by_sha!(github_pull_request.head.sha)
    end

    def find_or_create_commit_from_github_by_sha!(sha)
      if commit = stack.commits.by_sha(sha)
        commit
      else
        github_commit = stack.github_api.commit(stack.github_repo_name, sha)
        stack.commits.create_from_github!(github_commit)
      end
    rescue ActiveRecord::RecordNotUnique
      retry
    end
