This code path is confined to BlockSTM's internal parallel-execution bookkeeping and is not part of the transaction admission boundary (mempool, vm-validator, authenticator, or API input validation) required by the review scope.

`TxnLastInputOutput::for_each_resource_group_key_and_tags` simply iterates over the resource-group write set that the VM already produced for a given `txn_idx` during execution, and invokes a callback with the group key and its tags [1](#0-0) . The underlying write set itself comes from `BeforeMaterializationOutput::resource_group_write_set`/`for_each_resource_group_key_and_tags` as populated by `aptos-vm`'s Move execution output [2](#0-1) . Whether a given account is authorized to write to a particular resource-group key is decided by Move's global storage access-control rules during bytecode execution (i.e., before this write set even exists), not by this iteration helper.

The only consumers of this method are internal scheduler/estimation logic in `aptos-move/block-executor/src/executor.rs` (`process_resource_group_output_v2`) and `aptos-move/block-executor/src/executor_utilities.rs` (`update_transaction_on_abort`), both of which use it purely to mark MVHashMap entries as estimates or to merge/clear speculative writes across incarnations of the same `txn_idx` [3](#0-2) [4](#0-3) . None of these consumers perform sender/signer validation, replay/expiry/chain-id checks, or authenticator/multisig approval logic — they operate strictly after a transaction has already been admitted and is being speculatively executed within a single block. There is no code path from mempool, vm-validator, or the authenticator that lets unprivileged input inject a group key into another account's write set through this function; the write set contents are fully determined by prior Move execution, which independently enforces per-account resource ownership. Since this doesn't touch the admission boundary described in the review scope, it doesn't meet the required impact criteria.

    fn for_each_resource_group_key_and_tags(
        &self,
        callback: &mut dyn FnMut(&StateKey, HashSet<&StructTag>) -> Result<(), PanicError>,
    ) -> Result<(), PanicError> {
        for (key, tags) in self
            .guard
            .resource_write_set()
            .iter()
            .flat_map(|(key, write)| {
                if let AbstractResourceWriteOp::WriteResourceGroup(group_write) = write {
                    Some((key, group_write.inner_ops().keys().collect()))
                } else {
                    None
                }
            })
        {
            callback(key, tags)?;
        }

        Ok(())
    }
