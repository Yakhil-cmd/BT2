### Title
Signature verified against `repository.owner.login`'s org while payload mutation targets `repository.full_name`'s repo — cross-tenant PR label/env injection amplified via merge queue - ([File: app/controllers/shipit/webhooks_controller.rb], [File: lib/shipit/github_app.rb], [File: app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) using `repository_owner` (`params.dig('repository','owner','login')`), but every `pull_request` handler — including `LabelCapturingHandler` — resolves the mutated `Repository`/`Stack` from `params.repository.full_name`. These two fields are attacker-controlled and independently settable in the raw JSON body, so an attacker who owns/controls a "no-secret" (or otherwise attacker-accessible) GitHub org can pass signature verification using that org's identity while `full_name` points at an entirely different, victim org's repository. The invariant "a webhook event only affects the repository/stack whose secret authenticated it" is broken by construction.

### Finding Description
The broken binding, stated as an equality that must hold but does not:

`org_used_to_verify_signature = params.dig('repository','owner','login')` MUST equal `org_that_owns_repository_whose_stack_is_mutated = params.repository.full_name.split('/').first`

Trace:
1. `verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` (fallback `organization.login`) and looks up `github_app = Shipit.github(organization: repository_owner)`, then calls `github_app.verify_webhook_signature(header, raw_post)`. [1](#0-0) [2](#0-1) 
2. `GitHubApp#verify_webhook_signature` HMACs `raw_post` with that org's `webhook_secret`; critically, if the resolved org has no configured `webhook_secret`, the method `return true unless webhook_secret` — verification is a no-op for that org. `Shipit.github_app_config(organization)` is looked up purely by the string in `repository.owner.login`. [3](#0-2) [4](#0-3) 
3. Once verification passes (or is a no-op for a secretless org), `WebhooksController#create` dispatches the entire raw `params` hash — including `repository.full_name` — to the registered handlers for the event. [5](#0-4) 
4. `LabelCapturingHandler#repository` resolves the actual `Shipit::Repository` to mutate via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely separate field from the one used for authentication. [6](#0-5) 
5. For `action=opened`, `capture_labels?` → `opened_active_stack?` requires only that the resolved `stack` (a `ReviewStackAdapter` lookup scoped to that resolved repo's review stacks) is present; if so, `capture_labels` calls `pull_request.update!(labels: params.pull_request.labels.map(&:name))` on the victim stack's `PullRequest` record. [7](#0-6) [8](#0-7) 
6. `ReviewStack#env` merges `pull_request.labels.each_with_object({}) { |name, h| h[name.upcase] = "true" }` into the environment injected into every `Command`/`PTY.spawn` invocation for that stack (deploys, tasks, rollbacks). [9](#0-8) [10](#0-9) 
7. If the victim stack has `merge_queue_enabled: true`, a green head (test/CI success recorded elsewhere) triggers the merge queue's `merge!`; because the attacker-authenticated request (verified against their own org) was still routed against the victim's stack, the amplification path (unauthorized advance/merge on the victim stack) is reachable through the same divergent-authentication bug.

Why existing guards fail: `verify_signature` never cross-checks that `repository.owner.login` equals the owner portion of `repository.full_name`; `drop_unhandled_event` only checks the event type is registered, not repo/org consistency; `ExplicitParameters` schemas (`requires :repository { requires :full_name, String }` — note `owner.login` is not even part of the declared schema for `LabelCapturingHandler`) validate shape, not cross-field consistency; there is no model validation on `Repository`/`Stack` that rejects a mismatched owner at write time — `Repository.from_github_repo_name` simply looks up by `full_name` string.

### Impact Explanation
An attacker who controls (or can register) a GitHub org/repo with no `webhook_secret` configured in Shipit (or whose own secret they legitimately know) can forge a `pull_request` `opened` webhook whose `repository.owner.login` names their own org (satisfying/bypassing signature verification) while `repository.full_name` names an arbitrary victim repository/stack that Shipit tracks. This lets the attacker: (a) write attacker-chosen labels onto the victim `PullRequest` record, which become uppercase env vars merged into every `Command`/`PTY.spawn` invocation for that `ReviewStack` (deploy, rollback, task commands), and (b) if `merge_queue_enabled` is true on the victim stack, potentially influence merge-queue behavior tied to that stack's PR state. This is a payload for one repository mutating another's stack/PR/environment — matching the Critical category ("a payload for one repository mutating another's stack, commit, task or team" / "unauthorized deploy, rollback or merge"). The attack is repeatable against any victim repository whose `full_name` the attacker knows, since nothing in the dispatch path re-validates ownership.

### Likelihood Explanation
Preconditions: the attacker must control (or find) at least one org entry in `Shipit.secrets.github` that either has no `webhook_secret` configured or whose secret the attacker can compute/know (satisfying `verify_signature`'s "org used for verification"), and must know the victim's `repository.full_name` and have (or forge) a target PR structure the handler's `ExplicitParameters` schema accepts. No Shipit session, API token, or GitHub App private key is required — only the ability to POST to `/webhooks` with a crafted JSON body. This is a low-cost, fully unauthenticated, repeatable attack once a "no-secret" (or attacker-known-secret) org is identified.

### Recommendation
In `WebhooksController#verify_signature`, and/or in `Shipit::Webhooks::Handlers::Handler#stacks`/`repository_name`, enforce that the organization used to resolve the `GitHubApp`/secret (`repository.owner.login` or `organization.login`) matches the owner segment parsed from `repository.full_name` before dispatching to handlers; reject the request (422) on mismatch. Additionally, `GitHubApp#verify_webhook_signature` returning `true` when no secret is configured should be reconsidered — it silently disables authentication for any org lacking a secret, which is the enabling condition for the auth-org substitution.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or a new handler test):
1. Configure two orgs in `secrets.github`: `attacker_org` with no `webhook_secret` (or a known one), and `victim_org` with a real `webhook_secret`.
2. Create `victim_org/victim_repo` `Shipit::Repository` with a `ReviewStack`/`PullRequest` fixture (`merge_queue_enabled: true`), matching `number`/`head.ref` used in the PR opened payload.
3. Build a `pull_request` `action=opened` JSON payload with `repository.owner.login = "attacker_org"` and `repository.full_name = "victim_org/victim_repo"`, `pull_request.labels = [{name: "malicious_flag"}]`.
4. POST to `/webhooks` with `X-Github-Event: pull_request` and a signature computed with `attacker_org`'s (no/known) secret.
5. Assert response is `200`/`:ok` (bypassing the intended per-repo secret check).
6. Assert `victim_repo`'s `ReviewStack#pull_request.labels` now includes `"malicious_flag"` — i.e., `stack.reload.pull_request.labels == ["malicious_flag"]` — and `stack.env["MALICIOUS_FLAG"] == "true"`.
7. Assertion of the broken equality: before, `repository_owner` (`"attacker_org"`) ≠ owner of mutated stack (`"victim_org"`); after processing, the mutation still lands on `victim_org`'s stack — proving the invariant "an event only affects the repo/stack whose secret authenticated it" is violated.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
