### Title
`gh api --paginate` follows attacker-controlled `Link: rel="next"` URL to any host/scheme with no allowlist (SSRF via pagination) - ([File: pkg/cmd/api/pagination.go], [File: pkg/cmd/api/http.go])

### Summary
`findNextPage` extracts the raw URL from the `Link` response header via a regex and returns it verbatim to `apiRun`'s pagination loop, which feeds it straight back into `httpRequest`. Because `httpRequest` treats any string containing `"://"` as a fully-qualified absolute URL and issues the request through the authenticated `http.Client` with no host allowlist, a malicious/compromised GitHub-Enterprise host (or any host the victim points `gh` at) can redirect subsequent pagination requests to an arbitrary internal or external URL.

### Finding Description
- `linkRE` in `pkg/cmd/api/pagination.go` (line 15) parses the `Link` header and `findNextPage` (lines 17-24) returns the raw `<...>` URL for `rel="next"` unmodified. [1](#0-0) 
- `apiRun` in `pkg/cmd/api/api.go` uses this value directly as `requestPath` for the next loop iteration: [2](#0-1) 
- `httpRequest` in `pkg/cmd/api/http.go` explicitly bypasses `safeurl`/host validation whenever the path contains `"://"`, using it as the literal request URL: [3](#0-2) 
- The only mitigating control is `AddAuthTokenHeader` in `api/http_client.go` (lines 152-171), which looks up the bearer token by the *current request's* host (`getHost(req)`), not the originally-configured host, and only skips attaching a token when a client-side redirect changed hosts. Because the pagination loop issues a brand-new `client.Do` call each iteration (not an HTTP redirect), `req.Response` is nil, so `redirectHostnameChange` is always `false`, and the token lookup is keyed purely off whatever host the attacker put in the `Link` header. If that host has no configured token, no `Authorization` header leaks — but the request itself is still made unconditionally to whatever host/URL the attacker specifies, with no allowlist restricting it to the originally requested host. [4](#0-3) 

Attacker input: the `Link` response header of any API/HTTP response served by a host the victim points `gh api --paginate` at (e.g., a malicious or attacker-influenced GHES/`--hostname` endpoint, or any endpoint whose responses the attacker controls per the threat model). Existing repo-wide protections such as `internal/safeurl` are deliberately **not** applied here — the code comment in `http.go` even states this is intentional for user-supplied endpoints, but the same bypass unconditionally also applies to server-supplied pagination URLs, which are not user input and should be constrained to the same host/scheme as the original request.

### Impact Explanation
This allows a malicious/attacker-controlled host to force the victim's `gh` process to issue further authenticated-transport HTTP requests to attacker-chosen destinations (different host, scheme, or port) and have the response content processed and printed by `gh` (matches the "wrong-host or wrong-account request routing" / SSRF impact class). In environments where `gh` runs with implicit network privileges (e.g., CI/cloud runners with metadata endpoints reachable only from that host), this could be used to fetch and reflect back internal-network responses via the CLI's stdout. Credential exfiltration is limited because `AddAuthTokenHeader` only attaches a bearer token for hosts that have a locally configured token, so blind token theft to an arbitrary attacker domain is not directly demonstrated here.

### Likelihood Explanation
Requires the victim to run `gh api ... --paginate` (or GraphQL pagination, though GraphQL path uses `endCursor`, not the `Link` header) against a host under attacker control or whose responses the attacker can influence, consistent with the stated threat model ("controls responses from a host the victim points gh at"). No other special conditions are needed — a single malicious `Link` header is sufficient to redirect subsequent pagination requests.

### Recommendation
In `findNextPage`/`apiRun`, validate that the `next` URL's scheme and host match the original request's host (and scheme) before using it, or re-route it through the same `ghinstance`/`safeurl`-style host validation used for other outbound requests, rejecting or warning on cross-host redirects instead of following them silently.

```go
    evil := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {

    }))

        w.Header().Set("Link", fmt.Sprintf(`<%s/next>; rel="next"`, evil.URL))
        w.Header().Set("Content-Type", "application/json")
        fmt.Fprint(w, "[]")
    }))
    defer malicious.Close()

    // Run `gh api --paginate` (via apiRun) against `malicious`, e.g. with --hostname pointing at it,
    // and assert that a request lands on `evil` server — proving no host allowlist constrains the
    // pagination "next" URL to the originally targeted host.
}
```
Expected assertion: the `evil` server's handler is invoked, proving the "next" link was followed cross-host with no validation, matching `findNextPage`/`httpRequest` behavior described above.

```go
var linkRE = regexp.MustCompile(`<([^>]+)>;\s*rel="([^"]+)"`)

func findNextPage(resp *http.Response) (string, bool) {
	for _, m := range linkRE.FindAllStringSubmatch(resp.Header.Get("Link"), -1) {
		if len(m) > 2 && m[2] == "next" {
			return m[1], true
		}
	}
	return "", false
}
```

```go
func httpRequest(client *http.Client, hostname string, method string, p string, params interface{}, headers []string) (*http.Response, error) {
	isGraphQL := p == "graphql"
	var requestURL string
	if strings.Contains(p, "://") {
		requestURL = p
	} else if isGraphQL {
		requestURL = ghinstance.GraphQLEndpoint(hostname)
	} else {
		// Note that the gh api command takes the path verbatim from the user, so we
		// intentionally do not route it through safeurl and do not escape it here.
		requestURL = ghinstance.RESTPrefix(hostname) + strings.TrimPrefix(p, "/")
	}
```

```go
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```
