### Title
Stale oracle price survives a receiver callback and validates undercollateralized flash debt - (File: contracts/controller/src/context.rs)

### Summary
`flash_position` prefetches debt and collateral prices before forwarding the borrowed tokens and invoking the receiver. [1](#0-0)  `Context::fetch_prices` retains previously cached feeds, and `cached_price` later returns the retained snapshot without rereading the oracle. [2](#0-1)  A receiver can therefore unwind an attacker-controlled price move after the snapshot while the post-callback solvency check still uses the inflated collateral price. [3](#0-2) 

### Finding Description
`process_flash_position` collects the debt asset and every declared collateral token, then calls `prefetch_strategy_prices` before `mint_and_forward` and `invoke_receiver`. [4](#0-3)  The callback runs only after those prices have been cached. [5](#0-4) 

`Context::load_markets` documents that already cached values are retained, `fetch_prices` only fetches keys absent from `token_prices`, and `cached_price` returns that stored `PriceFeedRaw`. [6](#0-5) [2](#0-1)  Consequently, a price invalidated by the receiver callback remains authoritative for the subsequent collateral deposit and final solvency calculation. [3](#0-2) 

This is the smart-contract analogue of retaining a pointer after invalidating its referent: the collateral valuation is retained for further processing after the receiver has changed the market state on which it was based. [7](#0-6) 

### Impact Explanation
An attacker can receive real borrowed assets while leaving behind collateral whose live value is insufficient to secure them. [8](#0-7)  Once the manipulated price is restored during the callback, the account is economically undercollateralized even though the final check evaluates the stale pre-callback collateral price. [7](#0-6) 

The attacker can default on the flash-minted debt, leaving the loss to be absorbed through liquidation shortfalls and bad-debt socialization. [9](#0-8)  This can cause theft of supplier funds and protocol insolvency. [10](#0-9) 

### Likelihood Explanation
Any unprivileged caller can open `account_id = 0`, choose the flash debt market and amount, provide its own Wasm `receiver`, and declare a positive collateral minimum. [11](#0-10)  The receiver is invoked with attacker-controlled `data`, giving it a deterministic point at which to unwind the pre-call manipulation and deliver the declared collateral. [5](#0-4) 

The attack is available when the collateral's configured valuation can be moved through attacker-controlled trading or reserve changes, including a listed market using a manipulable Aquarius or Soroswap price source.  It does not require oracle dishonesty, privileged access, leaked keys, or control of protocol configuration; the flaw is the stale invocation-local price retained across an attacker-controlled callback. [2](#0-1) 

### Recommendation
Do not retain oracle prices across receiver-controlled execution. [2](#0-1)  After `invoke_receiver` returns, clear the affected `token_prices` entries or construct the final solvency calculation with a fresh `Context` so collateral and debt are valued after the callback. [12](#0-11) 

Apply the same rule to every strategy path that performs an external router or receiver call before final valuation. [6](#0-5) 

### Proof of Concept
1. An attacker manipulates a listed collateral asset's configured DEX-based price upward using their own trades. 
2. The attacker calls `flash_position` with `account_id = 0`, a borrowable `debt` market, a large positive `amount`, an attacker-controlled `receiver`, `collaterals = [(manipulated_collateral, minimum)]`, and empty `refund_assets`. [11](#0-10) 
3. `prefetch_strategy_prices` caches the manipulated collateral price before any debt is minted or the callback runs. [4](#0-3) 
4. The controller mints the debt position, receives the underlying into the controller, and forwards the measured tokens to the attacker receiver. [8](#0-7) 
5. Inside `execute_flash_position`, the receiver reverses the price manipulation, recovering its trading capital, and transfers at least `minimum` units of the now-lower-valued collateral to the controller. [13](#0-12) 
6. The controller deposits the measured collateral but evaluates the final account using `cached_price`, which still returns the inflated pre-callback feed. [7](#0-6) 
7. The transaction succeeds with a solvent-looking but economically undercollateralized account; the attacker retains the borrowed asset proceeds and leaves the protocol with the resulting bad debt. [3](#0-2)

/// Mints fee-free debt, verifies the controller receipt against the pool result,
/// then forwards it and returns the receiver's measured receipt.
fn mint_and_forward(
    env: &Env,
    account: &mut Account,
    debt: &HubAssetKey,
    amount: i128,
    receiver: &Address,
    cache: &mut Context,
) -> i128 {
    let controller = env.current_contract_address();
    let before = token::Client::new(env, &debt.asset).balance(&controller);

    let reported = borrow_into_controller(
        env,
        account,
        debt,
        amount,
        false,
        PositionAction::FlashPos,
        cache,
    );

    let measured = balance_delta_since(env, &debt.asset, &controller, before);
    assert_with_error!(env, measured == reported, GenericError::InternalError);
    assert_with_error!(env, measured > 0, GenericError::AmountMustBePositive);

    let forwarded = transfer_amount_measured(
        env,
        &debt.asset,
        &controller,
        receiver,
        measured,
        GenericError::AmountMustBePositive,
    );
    assert_with_error!(env, forwarded > 0, GenericError::AmountMustBePositive);
    forwarded

    /// Fetches missing prices in one aggregator call; retains cached prices.
    pub(crate) fn fetch_prices(&mut self, assets: &Vec<Address>) {
        let missing = collect_uncached_keys(&self.env, assets, &self.token_prices);
        if missing.is_empty() {
            return;
        }
        let fetched = external::price_aggregator::fetch_prices(&self.env, &missing);
        for (asset, feed) in fetched.iter() {
            self.token_prices.set(asset, feed);
        }
    }

    /// Returns a previously loaded price; fails if the cache has no entry.
    pub(crate) fn cached_price(&mut self, asset: &Address) -> PriceFeed {
        let raw = self
            .token_prices
            .get(asset.clone())
            .unwrap_or_else(|| panic_with_error!(&self.env, OracleError::OracleNotConfigured));
        (&raw).into()
    }

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Panics with `PoolInsolvent` if the market has a positive backing shortfall.
///
/// Backing = cash + ceiled debt value; claims = floored supply value.
pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(
        env,
        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
