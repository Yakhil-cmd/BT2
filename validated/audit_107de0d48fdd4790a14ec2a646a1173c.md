### Title
Unescaped filenames passed as git pathspecs let repo-controlled filenames abuse pathspec magic/glob syntax to expand or exclude the security-review diff scope - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`_diff_pathspec` and `get_git_diff` build the `git diff -- <path1> <path2> ...` argument list directly from repo-relative filenames without forcing literal pathspec matching. Because git's default (non-literal) pathspec parser treats a leading `:` as "magic" syntax (e.g. `:(exclude)`, `:(glob)`, `:(icase)`) and treats `*`, `?`, `[` as glob wildcards, a repo-controlled filename containing these characters is reinterpreted by git rather than matched literally, letting the effective diffed file set diverge from the file set `compute_v2_review_set` computed as the intended review scope.

### Finding Description
`_diff_pathspec` in [1](#0-0)  converts each touched/review path to a repo-relative string via `os.path.relpath(os.path.realpath(p), cwd_abs)` and only guards against paths resolving *outside* the repo root (`r.startswith("..")`); it performs no escaping or literal-pathspec wrapping of the resulting strings. `get_git_diff` then splices this list directly after `--` into the `git diff` argv: [2](#0-1) . The invoked `GIT_CMD` never sets `core.literalPathspecs=true` or `--literal-pathspecs`: [3](#0-2) .

Per git's documented pathspec semantics, a pathspec string that starts with `:` is parsed as "magic pathspec" (e.g. `:(exclude)foo`, `:(glob)pattern`, `:!pattern`), and outside of `--literal-pathspecs` mode, bare `*`, `?`, `[` inside a pathspec are treated as glob wildcards rather than literal characters. Filenames are attacker-controlled repo content (the prompt's stated attacker capability), and git itself imposes almost no restriction on filename bytes besides `NUL` and `/`, so a file named e.g. `:(exclude)src/real_target.py` or containing `*`/`?` is a perfectly legal, committable/creatable path on Linux/macOS.

The affected paths reach `get_git_diff` from `compute_v2_review_set` in [4](#0-3)  (repo-relative review paths derived from `git status --porcelain`/`git diff --name-only`) via the Stop-hook flow at [5](#0-4) , where `review_paths` (the security-critical file set the LLM is meant to review) is forwarded unmodified as `paths=review_paths` into `get_git_diff`. If any of these repo-relative paths carries pathspec magic or glob metacharacters, git's actual match set for the `diff --name-only`/`diff` invocation silently diverges from the intended `review_set`:
- A crafted `:(exclude)<other-file>` entry can suppress that other, genuinely-changed file's diff from the output entirely (exclude pathspecs take precedence over positive matches in the same pathspec list), letting a security-relevant change bypass the LLM security reviewer undetected.
- A filename containing `*`/`?`/`[` is treated as a glob rather than a literal name, so it may fail to match its own (literal) file — dropping that file from the diff — while incidentally matching unrelated files, pulling in diff content the caller never intended to include.

No existing check in `_diff_pathspec` neutralizes this: the only defense implemented is the realpath/`..`-prefix filter, which addresses symlink/outside-repo escapes but not pathspec-magic reinterpretation of otherwise in-scope, legitimate repo-relative names.

### Impact Explanation
This breaks the stated invariant that git path scoping must never diverge from the intended target set. The concrete exploitable outcome is a trust-boundary/review bypass: a maliciously named file committed into the repo can suppress the diff of another (real) file from ever reaching the Stop-hook / commit-review LLM security reviewer, allowing genuinely security-relevant, malicious code changes to pass through the security-guidance plugin's automated review undetected. This is a real approval-bypass condition on the plugin whose entire purpose is to gate risky diffs through review.

### Likelihood Explanation
The precondition is only that the attacker can get a maliciously-named file into the repository working tree (as untracked/dirty content, e.g. as part of ordinary repo content or a file created during a Claude Code turn) — no maintainer/admin/credential assumptions are needed, matching the stated unprivileged-attacker model. Git filenames containing `:`, `*`, `?`, `[` are valid and commonly creatable via normal file-write operations, so this is straightforward and repeatable: the pathspec-magic interpretation happens deterministically every time `get_git_diff` is invoked with such a name in `paths`.

### Recommendation
Force literal pathspec interpretation everywhere filenames are spliced into `git` pathspec argument lists: either add `-c core.literalPathspecs=true` to `GIT_CMD` (or set `GIT_LITERAL_PATHSPECS=1` in the subprocess env for the diff/name-only calls) or prefix each converted path in `_diff_pathspec`/other pathspec-builders with `:(literal)` (e.g. `f":(literal){r}"`), guaranteeing the argument matches only the exact repo-relative filename it was derived from.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Init a temp git repo; commit an initial file `a.py`.
2. Create two untracked/dirty files in the same turn: `":(exclude)a.py"` — actually demonstrate with a real secondary target: modify `a.py` (adds a clearly-flagged insecure line, e.g. `eval(input())`) and create a new file literally named `:(exclude)a.py`.
3. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture)` to get `review_paths` containing both `a.py` and `:(exclude)a.py`.
4. Call `get_git_diff(repo, baseline_sha, paths=review_paths, untracked_paths=untracked)`.
5. Assert: the returned diff text does NOT contain the expected `+eval(input())` hunk for `a.py`, even though `a.py` is genuinely dirty and present in `review_paths` — demonstrating the malicious co-located filename suppressed the legitimate file's diff from the reviewer's input.
6. As a control, rerun the same scenario without the `:(exclude)a.py` file present and assert the `a.py` diff IS present, proving the divergence is caused specifically by the unescaped pathspec magic.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

```python
def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
    if not isinstance(untracked_at_baseline, dict):
        untracked_at_baseline = {}

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now

    review_paths = [os.path.join(repo, p) for p in sorted(review_set)]
    untracked_in_review = sorted(new_untracked & review_set)
    metrics = {
        "dirty_now_count": len(dirty_now),
        "changed_since_count": len(changed_since) if changed_since is not None else -1,
        "review_set_count": len(review_set),
    }
    # Only emit when nonzero to stay under the 10-key telemetry cap.
    if preexisting_unchanged:
        metrics["preexisting_untracked_excluded"] = len(preexisting_unchanged)
    return review_paths, diff_base, repo, untracked_in_review, metrics
```
