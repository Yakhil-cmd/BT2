### Title
Unchecked `i128` overflow in scaled-debt × index multiplication permanently freezes a market (accrual panics before the index cap engages) - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
Like CVE-2022-43035 (an attacker-reachable arithmetic overflow that crashes the process → DoS), the pool's interest accrual multiplies the scaled debt `Ray` by the borrow index using a panicking `mul`. When the product exceeds `i128::MAX`, accrual traps with `MathOverflow`. Because every user-facing verb (supply, borrow, withdraw, repay, liquidate, flash paths) accrues first via `ops::renewed_market`, and the stored `borrow_index`/`borrowed` only grow over time, the trap is permanent: all cash, supplier claims, and borrower collateral in that market are frozen forever. The intended `MAX_BORROW_INDEX_RAY` clamp in `update_borrow_index` never protects this path — the overflow occurs in `borrowed.mul(env, new_borrow_index)` inside `calculate_supplier_rewards`, i.e., on the *value* (`scaled × index`), not on the index itself. [1](#0-0) 

### Finding Description
- `update_borrow_index` computes `new_index = old_index.mul(env, interest_factor)` and then clamps to `MAX_BORROW_INDEX_RAY`. The index is bounded, but the *scaled value* is not. [2](#0-1) 
- Immediately after, `calculate_supplier_rewards` computes `new_total_debt = borrowed.mul(env, new_borrow_index)` where `borrowed` is the RAY-scaled debt. `Ray::mul` panics on `i128` overflow (`scaled_to_original` → `mul`, common/src/rates/scaling.rs:14-16). The product `borrowed_raw × index_raw / RAY` overflows when `borrowed_raw × index_raw > i128::MAX`, which happens for a large but plausible market long before `index` reaches `MAX_BORROW_INDEX_RAY = 1e36`. [3](#0-2) [4](#0-3) 
- The panic is sticky: `borrowed` and `borrow_index` are monotone non-decreasing, so once `borrowed × index` overflows, every subsequent accrual overflows too. Since `renewed_market` accrues at the head of every op, withdraw/repay/liquidate all revert permanently — a crash-based DoS that becomes permanent freezing of funds, not a transient fail-closed revert.
- The repository's own harness demonstrates this end-to-end: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows `update_indexes`, `withdraw`, and `repay` all failing with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, explicitly noting "the index cap did not engage before the value overflow" and "the market is frozen." [5](#0-4) 

### Impact Explanation
Permanent freezing of all funds held in the affected (hub, token) market: supplier cash claims cannot be withdrawn (`withdraw` accrues first), borrower collateral cannot be recovered (`repay`/`liquidate` accrue first), and governance cannot unstick it because index/borrowed never decrease. This is the "permanent freezing of funds" impact class — the value-overflow panic is unrecoverable state, not a one-call revert.

### Likelihood Explanation
Reachable by unprivileged `controller::supply`/`borrow`/`update_indexes` calls: an attacker (or organic whale flow) seeds a large-debt market on a high-decimal asset and sustains high utilization so the borrow index compounds. No admin action is required; the trap triggers purely from stored state growth plus time. The harness shows it occurring on a billion-unit 18-decimal market at ~98% utilization on the XLM rate curve — requiring substantial capital and sustained high utilization, which lowers likelihood relative to a small-scale trigger but keeps it well within attacker-reachable parameters on Soroban where flash liquidity and multi-year index growth are realistic.

### Recommendation
Bound the *product*, not just the index. Either (a) clamp `new_borrow_index` to `min(cap, i128::MAX_safe / borrowed_raw)` so `borrowed.mul(new_index)` cannot overflow, (b) compute `accrued_interest` via a saturating/`mul_div`-style primitive that cannot trap, or (c) cap total scaled debt (`borrowed`) at listing/borrow time to `i128::MAX / MAX_BORROW_INDEX_RAY` so the multiplication is provably safe for all reachable states. A regression test asserting `update_indexes`/`withdraw`/`repay` still succeed when `borrowed × MAX_BORROW_INDEX_RAY` approaches `i128::MAX` should accompany the fix.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`: supply `1e9 × 10^18` of an 18-decimal asset, borrow ~98% of it, advance ledger time in yearly steps calling `update_indexes`; accrual eventually panics with `MATH_OVERFLOW` inside `calculate_supplier_rewards` while `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, and afterwards `try_withdraw_raw` and `try_repay` revert with the same error — the market is permanently frozen. pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
```rust
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
