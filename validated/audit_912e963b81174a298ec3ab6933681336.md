### Title
Webhook signature verification is keyed on `repository.owner.login`, but every handler acts on `repository.full_name` — allowing cross-organization write with an attacker's own valid webhook secret - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit supports multi-tenant GitHub App configuration, where each organization has its own `webhook_secret` used to verify inbound webhook payloads. [1](#0-0)  The controller that verifies the HMAC signature selects *which* organization's secret to check against by reading an unauthenticated field of the JSON body itself (`repository.owner.login`), while every webhook handler that actually performs writes (creating teams/users, syncing stacks, updating pull requests, posting commit statuses) resolves the target `Repository`/`Stack` using a *different* unauthenticated field of the same body (`repository.full_name`). [2](#0-1) [3](#0-2)  Because the signature only proves the payload was signed with *some* organization's secret — not that the `full_name` used for the actual write belongs to that organization — an attacker who legitimately controls the webhook secret for their own onboarded organization ("OrgAttacker") can forge a payload that authenticates as OrgAttacker but whose `repository.full_name` (and other repo-scoped fields) point at a completely different, victim organization's repository.

### Finding Description
`WebhooksController#verify_signature` derives `repository_owner` purely from the untrusted JSON body:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```
and uses that value to pick the `GitHubApp` instance (and thus the `webhook_secret`) to verify the signature against:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
``` [4](#0-3) 

`Shipit.github(organization:)` looks up per-organization secrets from the multi-tenant config (`Shipit.github_app_config`), confirming that different organizations have distinct, independently-known `webhook_secret` values in this deployment mode. [1](#0-0)  The `secrets_double_github_app.yml` fixture demonstrates exactly this multi-org layout (`OrgOne`, `OrgTwo`, each with its own `webhook_secret`). [5](#0-4) 

Once the signature is accepted, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches to handlers, and every handler resolves the repository to act on from `repository.full_name`, a field the controller never checked for consistency with `repository.owner.login`:
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
``` [6](#0-5) 

This binding is used throughout handlers, e.g. pull-request handlers resolve the acted-upon repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [7](#0-6)  `PushHandler` similarly operates on `stacks` (i.e. `Repository.from_github_repo_name(repository_name).stacks`) filtered only by branch name from the same unverified payload, then calls `stack.sync_github(expected_head_sha: params.after)`. [8](#0-7) 

**Equality that breaks:** the organization whose secret authenticated the request (`repository.owner.login`) ≠ the repository whose `Stack`/`PullRequest`/`Team`/`Commit` state is written (`repository.full_name`). The controller verifies the former; every handler trusts the latter without re-checking it belongs to the authenticated organization.

### Impact Explanation
An attacker who is a legitimate admin of their own GitHub organization ("OrgAttacker") that has been onboarded to this Shipit instance (and therefore knows/controls the `webhook_secret` configured for OrgAttacker) can:
1. Compute a valid `X-Hub-Signature` over an arbitrary JSON body using OrgAttacker's known `webhook_secret`.
2. Set `repository.owner.login = "OrgAttacker"` (so `verify_signature` selects and validates against OrgAttacker's secret, which succeeds).
3. Set `repository.full_name = "victim-org/victim-repo"` in the same body, so downstream handlers resolve and mutate the victim organization's `Repository`/`Stack`/`PullRequest`/`Commit` records.

This lets the attacker trigger, for a repository they have no legitimate relationship with: `PushHandler`-driven `sync_github` (potential unauthorized deploy triggers via ref/HEAD manipulation), `StatusHandler`-driven fake commit statuses (`create_status_from_github!`) that gate deploy safety checks, and pull-request-handler-driven archive/unarchive of review stacks — a cross-repository write via a spoofed organizational binding. This satisfies the Critical bar of "cross-repository writes" / "an unauthorized deploy" without requiring a Shipit session, API token, or the victim's own webhook secret.

### Likelihood Explanation
The prerequisite (control of one legitimately onboarded organization's webhook secret) is explicitly the normal, unprivileged state of any organization admin using this multi-tenant Shipit deployment mode — it is not an out-of-scope privileged secret belonging to the app or another tenant. No repository write access, no Shipit session, and no knowledge of the victim's secret is required; only the ability to send an HTTP POST to `/webhooks` with a crafted body and a correctly computed signature for the attacker's own org.

### Recommendation
In `WebhooksController#verify_signature` (or in `Shipit::Webhooks::Handlers::Handler`), enforce that the organization used to select/verify the webhook secret matches the organization portion of `repository.full_name` (and/or any other org-scoped fields consumed by handlers) before dispatching. Reject the payload if `repository.owner.login` does not match the owner segment of `repository.full_name`.

### Proof of Concept
1. Onboard/attack as an admin of organization `OrgAttacker`, which has its own configured `webhook_secret` (`WHA`) per `Shipit.github_app_config`.
2. Craft body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "OrgAttacker" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(WHA, body)>`.
4. `POST /webhooks` with header `X-Github-Event: push` and the body above.
5. `WebhooksController#verify_signature` calls `Shipit.github(organization: "OrgAttacker")` and verifies successfully against `WHA`. [4](#0-3) 
6. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef")` on the victim's stack — a write triggered on a repository the attacker never had permission over. [8](#0-7) [3](#0-2)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
