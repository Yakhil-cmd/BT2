### Title
Pool creation permits mints with an active freeze authority, allowing permanent freezing of pool vaults and all LP/swap funds - ([File: programs/cp-swap/src/utils/token.rs])

### Summary
`is_supported_mint`, called from `initialize` and `initialize_with_permission`, only whitelists Token-2022 *extension types* (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) and unconditionally accepts any legacy SPL `Token::id()` mint. [1](#0-0)  Neither this function nor the `Initialize`/`InitializeWithPermission` account contexts ever inspect or reject a mint's base-level `freeze_authority` field. [2](#0-1) [3](#0-2)  `freeze_authority` is a standard base field on both `Token` and `Token-2022` mints (not an extension), so it is completely unchecked by this whitelist logic, and no other part of the codebase references `freeze_authority`.

### Finding Description
An unprivileged pool creator can call `initialize` (or `initialize_with_permission`) supplying `token_0_mint`/`token_1_mint` with an active `freeze_authority` set to any address the creator controls. Because `is_supported_mint` never checks `freeze_authority`, the pool is created successfully and the program derives and initializes `token_0_vault`/`token_1_vault` for these mints via `create_token_account`. [4](#0-3) 

Once the pool is live, the mint's freeze authority can freeze the pool's vault token account directly (a normal `FreezeAccount` instruction sent to the token program, independent of this program). Every core fund-moving path in the program - `swap_base_input`/`swap_base_output`, `deposit`, `withdraw`, and `collect_creator_fee`/`collect_creator_fee_permissionless` - relies on `transfer_from_user_to_pool_vault`/`transfer_from_pool_vault_to_user`, which perform `token_2022::transfer_checked` CPIs directly against the vault accounts. [5](#0-4)  The `Swap` account context only constrains `input_vault`/`output_vault` to match `pool_state.token_0_vault`/`token_1_vault`; it has no ability to route around a frozen vault. [6](#0-5)  Likewise `withdraw.rs` and `deposit.rs` transfer directly to/from these same vaults with no fallback. [7](#0-6) [8](#0-7) 

If either vault is frozen by the mint's freeze authority, every `transfer_checked` CPI touching that vault will revert (frozen accounts cannot send or receive tokens in SPL Token/Token-2022), causing `swap_base_input`, `swap_base_output`, `deposit`, `withdraw`, and fee-collection instructions to permanently fail for that pool. Unlike a per-user blacklist (which only blocks the affected user's own transaction), freezing the *vault* blocks the entire pool for *all* depositors/LPs/swappers simultaneously, and there is no mechanism in the program to exclude the frozen vault or migrate funds out, since `authority` is a PDA and can never "unfreeze" (only the external freeze authority key can, and by hypothesis it is malicious/uncooperative).

### Impact Explanation
This permanently locks 100% of LP funds already deposited in a pool created with such a mint, and permanently disables all swaps for that pool - not merely reverting a single user's transaction like the analog USDC pause/blacklist scenario, but freezing every participant's principal (deposits) with no recovery path from within the program. This satisfies "permanent freezing of user or LP funds."

### Likelihood Explanation
`initialize`/`initialize_with_permission` are permissionless (`creator`/`payer` is any signer), and setting a `freeze_authority` on a mint is a completely standard, unflagged configuration for both legacy SPL Token and Token-2022 mints - it requires no unusual extension and passes `is_supported_mint`'s extension whitelist trivially for legacy `Token::id()` mints (immediately returns `Ok(true)`) and is simply never examined for Token-2022 mints either. Any user seeking to attract LPs to a pool and later hold funds hostage, or a "rug" pool creator, can trivially create such a mint and pool. Likelihood is high because no privileged action or special build feature is required.

### Recommendation
In `is_supported_mint` (`programs/cp-swap/src/utils/token.rs`), explicitly reject mints whose `freeze_authority` is `Some(_)` (for both legacy and Token-2022 mints), unless the pool has been explicitly registered via `SupportMintAssociated` by the protocol admin (as is already done for otherwise-unsupported extensions). This closes the gap where a base-level, non-extension field allows an attacker to retain unilateral freeze control over vault accounts after pool creation.

### Proof of Concept
1. Attacker creates a Token-2022 (or legacy SPL Token) mint `M` with `freeze_authority = attacker_key` and no extensions requiring the `SupportMintAssociated` bypass.
2. Attacker calls `initialize` (or `initialize_with_permission`) with `token_0_mint = M`; `is_supported_mint` returns `true` since `freeze_authority` is never inspected, and `create_pool`/`create_token_account` succeed, creating `token_0_vault` owned by `M`. [9](#0-8) 
3. Other LPs deposit token `M` liquidity via `deposit`; swappers trade against the pool via `swap_base_input`/`swap_base_output`.
4. Attacker sends a `FreezeAccount` instruction (via `attacker_key`) against `token_0_vault`.
5. All subsequent `deposit`, `withdraw`, `swap_base_input`, `swap_base_output`, and `collect_creator_fee(_permissionless)` calls touching `token_0_vault` revert at the `transfer_checked` CPI, permanently locking all LP principal and disabling the pool.

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount
        {
            return Ok(false);
        }
    }
    Ok(true)
}

pub fn create_token_account<'a>(
    authority: &AccountInfo<'a>,
    payer: &AccountInfo<'a>,
    token_account: &AccountInfo<'a>,
    mint_account: &AccountInfo<'a>,
    system_program: &AccountInfo<'a>,
    token_program: &AccountInfo<'a>,
    signer_seeds: &[&[u8]],
) -> Result<()> {
    let space = {
        let mint_info = mint_account.to_account_info();
        if *mint_info.owner == token_2022::Token2022::id() {
            let mint_data = mint_info.try_borrow_data()?;
            let mint_state =
                StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
            let mint_extensions = mint_state.get_extension_types()?;
            let required_extensions =
                ExtensionType::get_required_init_account_extensions(&mint_extensions);
            ExtensionType::try_calculate_account_len::<spl_token_2022::state::Account>(
                &required_extensions,
            )?
        } else {
            TokenAccount::LEN
        }
    };
    create_or_allocate_account(
        token_program.key,
        payer.to_account_info(),
        system_program.to_account_info(),
        token_account.to_account_info(),
        signer_seeds,
        space,
    )?;
    initialize_account3(CpiContext::new(
        *token_program.key,
        InitializeAccount3 {
            account: token_account.to_account_info(),
            mint: mint_account.to_account_info(),
            authority: authority.to_account_info(),
        },
    ))
}

pub fn initialize(
    ctx: Context<Initialize>,
    init_amount_0: u64,
    init_amount_1: u64,
    mut open_time: u64,
) -> Result<()> {
    let mint0_associated_is_initialized = support_mint_associated_is_initialized(
        &ctx.remaining_accounts,
        &ctx.accounts.token_0_mint,
    )?;
    let mint1_associated_is_initialized = support_mint_associated_is_initialized(
        &ctx.remaining_accounts,
        &ctx.accounts.token_1_mint,
    )?;
    if !(is_supported_mint(&ctx.accounts.token_0_mint, mint0_associated_is_initialized).unwrap()
        && is_supported_mint(&ctx.accounts.token_1_mint, mint1_associated_is_initialized).unwrap())
    {
        return err!(ErrorCode::NotSupportMint);
    }

    if ctx.accounts.amm_config.disable_create_pool {
        return err!(ErrorCode::NotApproved);
    }
    let block_timestamp = clock::Clock::get()?.unix_timestamp as u64;
    if open_time <= block_timestamp {
        open_time = block_timestamp + 1;
    }
    // due to stack/heap limitations, we have to create redundant new accounts ourselves.
    create_token_account(
        &ctx.accounts.authority.to_account_info(),
        &ctx.accounts.creator.to_account_info(),
        &ctx.accounts.token_0_vault.to_account_info(),
        &ctx.accounts.token_0_mint.to_account_info(),
        &ctx.accounts.system_program.to_account_info(),
        &ctx.accounts.token_0_program.to_account_info(),
        &[
            POOL_VAULT_SEED.as_bytes(),
            ctx.accounts.pool_state.key().as_ref(),
            ctx.accounts.token_0_mint.key().as_ref(),
            &[ctx.bumps.token_0_vault][..],
        ],
    )?;

    create_token_account(
        &ctx.accounts.authority.to_account_info(),
        &ctx.accounts.creator.to_account_info(),
        &ctx.accounts.token_1_vault.to_account_info(),
        &ctx.accounts.token_1_mint.to_account_info(),
        &ctx.accounts.system_program.to_account_info(),
        &ctx.accounts.token_1_program.to_account_info(),
        &[
            POOL_VAULT_SEED.as_bytes(),

            ctx.accounts.token_1_mint.key().as_ref(),
            &[ctx.bumps.token_1_vault][..],
        ],
    )?;
