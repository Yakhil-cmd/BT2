### Title
`ProxyType::NonTransfer` deny-list fails open on Asset Hub Rococo, letting a `NonTransfer` proxy move the delegator's assets, swap liquidity, teleport funds via XCM and make value-carrying contract calls - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`pallet-proxy`'s `proxy` extrinsic lets an account registered as a delegate execute arbitrary `RuntimeCall`s "on behalf of" the delegator, gated only by `ProxyType::filter` (`InstanceFilter::filter`) at `substrate/frame/proxy/src/lib.rs:1021`. On Asset Hub Rococo, `ProxyType::NonTransfer::filter` is implemented as a **deny-list** (`cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:608-615`), which "fails open": every pallet call not explicitly named is permitted. The list only denies `Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques`, but the runtime also contains `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` (all confirmed present in the runtime's pallet set), none of which are denied. A `NonTransfer` delegate can therefore transfer `ForeignAssets`/`PoolAssets`, drain liquidity via `AssetConversion`, teleport/reserve-transfer the delegator's assets off-chain via `PolkadotXcm`, or make value-carrying `Revive` contract calls - despite the type's documented purpose being "any call that does not transfer funds or assets." This is the exact same bug class already identified and fixed for Asset Hub Westend (see `prdoc/pr_12771.prdoc`, `prdoc/pr_12922.prdoc`) and covered by regression tests in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2642-2668`, but the fix was never ported to Asset Hub Rococo.

### Finding Description
The Convex `VoterProxy.vote()` report's violated invariant is: a delegate authorized for a narrow, specific action (voting) can instead invoke arbitrary contract calls on the proxy's behalf because no whitelist/filter restricts the destination of the call. The Polkadot SDK analog is structurally identical: `pallet-proxy`'s `Pallet::proxy` (`substrate/frame/proxy/src/lib.rs:248-262`) dispatches an arbitrary boxed `RuntimeCall` from the real (delegator) account origin, restricted only by `def.proxy_type.filter(c)` inside `do_proxy` (`substrate/frame/proxy/src/lib.rs:1021`). The "whitelist" is precisely `InstanceFilter<RuntimeCall>::filter`.

Asset Hub Rococo's `NonTransfer` filter implements this whitelist as an *inverted* deny-list:
```
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::NftFractionalization { .. } |
        RuntimeCall::Nfts { .. } |
        RuntimeCall::Uniques { .. }
),
```
(`cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:608-615`)

Because this is a deny-list, any pallet call variant not explicitly enumerated is admitted by default - the same "fails open, no whitelist" defect the Convex report flags. Confirmed via `grep_search`, the runtime instantiates `ForeignAssets: pallet_assets`, `PoolAssets: pallet_assets`, `AssetConversion: pallet_asset_conversion`, `PolkadotXcm: pallet_xcm`, and `Revive: pallet_revive` (4 matching lines found in the runtime construction), none of which appear in the `NonTransfer` deny-list. All of these call families let a caller move value:
- `ForeignAssets`/`PoolAssets` transfers move the delegator's fungible balances exactly as `Assets::transfer` does.
- `AssetConversion` swaps/liquidity calls move the delegator's assets into/out of pools.
- `PolkadotXcm::transfer_assets`/`teleport_assets`/`send`/`execute` can move assets off-chain or express arbitrary XCM.
- `Revive::call`/`instantiate` variants carry a `value` field that transfers balance to the callee.

This is precisely the bug class Parity itself already fixed for asset-hub-westend (`prdoc/pr_12771.prdoc`) and for the staking-async parachain runtime (`prdoc/pr_12922.prdoc`), with regression tests added (`non_transfer_proxy_rejects_value_moving_calls`, `tests.rs:2642-2668`) specifically to prevent this exact class from reappearing. Asset Hub Rococo was not included in that remediation and still carries the old, narrower deny-list.

### Impact Explanation
Any account that has registered a `NonTransfer` proxy delegate (a legitimate, common operational pattern: e.g. a hot-wallet delegate intended only for non-financial administrative actions) is exposed to having that delegate move its `ForeignAssets`, `PoolAssets`, swap/drain liquidity via `AssetConversion`, siphon funds off-chain via XCM, or trigger value-carrying contract calls via `Revive` - actions the account owner explicitly did not authorize when scoping the proxy to `NonTransfer`. Given `VoterProxy`-style reports treat "delegate can perform unrestricted calls instead of the intended narrow action" as High severity due to direct fund-theft potential, the same reasoning applies here: this is an unauthorized-dispatch / asset-theft vector reachable by any account that already holds a `NonTransfer` proxy grant (no additional privilege needed beyond the proxy relationship the delegator itself created).

### Likelihood Explanation
Likelihood is bounded by the prerequisite that the victim has already granted a `NonTransfer` proxy to the attacker - a normal, encouraged usage pattern (hot-wallet/cold-wallet separation) rather than a privileged or rare configuration. Given that prerequisite, exploitation requires only a single signed `Proxy::proxy` extrinsic with the wanted call (e.g., `ForeignAssets::transfer`), with normal transaction fees - no governance, no validator collusion, no race condition. This mirrors exactly the already-fixed asset-hub-westend case, indicating the runtime maintainers consider this pattern realistically reachable and worth patching.

### Recommendation
Port `prdoc/pr_12771.prdoc`'s fix to `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`: extend the `ProxyType::NonTransfer` filter to also deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive` (and any other value-moving pallet present in the runtime, e.g. `Scheduler`/`Vesting::vested_transfer`/`Indices::transfer`/`force_transfer` per the westend fix), or convert the filter to an explicit allow-list so newly added pallets fail closed by default rather than open. Add the same regression test pattern used in `asset-hub-westend`'s `tests.rs` (`non_transfer_proxy_rejects_value_moving_calls`) to Asset Hub Rococo's test suite to prevent regressions.

### Proof of Concept
Guard/check that fails: `ProxyType::NonTransfer::filter` at `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:608-615` returns `true` (admits the call) for `RuntimeCall::ForeignAssets(pallet_assets::Call::transfer { .. })`, `RuntimeCall::PoolAssets(..)`, `RuntimeCall::AssetConversion(..)`, `RuntimeCall::PolkadotXcm(..)`, and `RuntimeCall::Revive(..)`, because none of these variants are named in the `matches!` deny-list, unlike the corrected westend runtime (`asset-hub-westend/src/lib.rs:829-860`).

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});
		let e = call.dispatch(origin);
		Self::deposit_event(Event::ProxyExecuted { result: e.map(|_| ()).map_err(|e| e.error) });
	}

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
