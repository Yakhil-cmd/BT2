### Title
Private textcoin payload (mnemonic + private chains) written to disk with default/shared permissions in `storePrivateAssetPayload` - (File: wallet.js)

### Summary
`wallet.js`'s `storePrivateAssetPayload` persists the mnemonic and private-payment chains of a private-asset textcoin to a file on disk before it is shared with the recipient. On Node.js it uses `fs.writeFile(fullPath, zipFile, cb)` with no explicit mode, and on Cordova it writes into `LocalFileSystem.TEMPORARY`, a shared temporary storage area on the device. [1](#0-0) 

### Finding Description
`storePrivateAssetPayload` zips up `{ mnemonic, chains }` — the mnemonic used to derive the textcoin's private key (`expandMnemonic`) and the private payment chains for a private asset — and writes the zip to `fullPath` via `fs.writeFile(fullPath, zipFile, cb)`, exactly mirroring the CVE-2021-29429 pattern where sensitive downloaded content is written to disk with the process's default (often world-readable) umask instead of a restrictive mode. [2](#0-1) 
On the Cordova code path, the same secret payload is written into `LocalFileSystem.TEMPORARY`, which is a shared temp storage area on the device rather than an app-private, access-restricted location. [3](#0-2) 
This mnemonic is the private key material of a live, unclaimed textcoin: `expandMnemonic` derives an HD private key and address directly from it, and that address can hold live private-asset funds until claimed. [4](#0-3) 
Because the file is created with default filesystem permissions (no `{mode: 0o600}` passed to `fs.writeFile`) rather than in a per-user restricted directory, any other local user or, on mobile, any other app with access to shared temporary storage could read the file and extract the mnemonic before the intended recipient claims the textcoin.

### Impact Explanation
Exposure of the mnemonic/private chains is equivalent to exposure of a private key controlling an unclaimed private-asset textcoin. An attacker who reads the file from the temp/shared location can call the reachable claim path (`receiveTextCoin`/`handlePrivatePaymentFile`) themselves, sign a spend from `addrInfo.address`, and race the legitimate recipient — resulting in unauthorized spending / theft of the private-asset funds represented by the textcoin. [5](#0-4) 

### Likelihood Explanation
Exploitation requires local co-residency (another process/user on the same machine, or another app on the same mobile device with access to shared temporary storage) at the moment the textcoin sender or receiver stores/loads the payload file — the same threat model as the original Gradle CVE. This is a realistic but not trivially remote scenario, consistent with Medium severity.

### Recommendation
When writing the private textcoin payload, explicitly restrict file permissions (e.g., `fs.writeFile(fullPath, zipFile, { mode: 0o600 }, cb)`), and avoid Cordova's shared `LocalFileSystem.TEMPORARY` for this content — prefer app-private, sandboxed storage (`LocalFileSystem.PERSISTENT` app-private directories or platform secure storage) so other apps/processes cannot read the mnemonic.

### Proof of Concept
1. Sender creates a private-asset textcoin and calls `storePrivateAssetPayload(fullPath, cordovaPathObj, mnemonic, chains, cb)` to save it for sharing (e.g., before emailing/AirDropping it). [6](#0-5) 
2. On Node/desktop, the resulting file at `fullPath` is created with the process's default umask (commonly world- or group-readable); on mobile, it lands in the device's shared `TEMPORARY` filesystem area. [7](#0-6) 
3. A co-located local user or another installed app reads the file, unzips it, and extracts `mnemonic`/`chains` from the JSON payload the same way `handlePrivatePaymentFile` does. [8](#0-7) 
4. The attacker calls `expandMnemonic(mnemonic)` to derive the private key/address and races the legitimate recipient via `receiveTextCoin`, spending the funds before the intended party claims them. [9](#0-8)

function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
}

function storePrivateAssetPayload(fullPath, cordovaPathObj, mnemonic, chains, cb) {
	var storedObj = {
		mnemonic: mnemonic,
		chains: chains
	};
	var bCordova = (typeof window === 'object' && window.cordova);
	var JSZip = require("jszip");
	var zip = new JSZip();
	zip.file('private_textcoin', JSON.stringify(storedObj));
	var zipParams = {type: "nodebuffer", compression: 'DEFLATE', compressionOptions: {level: 9}};
	zip.generateAsync(zipParams).then(function(zipFile) {
		if (!bCordova) {
			var fs = require('fs');
			fs.writeFile(fullPath, zipFile, cb);
		} else {
			window.requestFileSystem(LocalFileSystem.TEMPORARY, 0, function(fs) {
				window.resolveLocalFileSystemURL(cordovaPathObj.root, function(dirEntry) {
					dirEntry.getDirectory(cordovaPathObj.path, {create: true, exclusive: false}, function(dirEntry1) {
						dirEntry1.getFile(cordovaPathObj.fileName, {create: true, exclusive: false}, function(file) {
							file.createWriter(function(writer) {
								writer.onwriteend = function() {
									cb(null); 
								};
								writer.write(zipFile.buffer);
							}, cb);
						}, cb);
					}, cb);
				}, cb);
			}, cb);
		}
	}, cb);
}
