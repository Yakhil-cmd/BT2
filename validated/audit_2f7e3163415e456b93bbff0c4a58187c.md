### Title
Borrow/supply index accrual overflows i128 before the index cap engages, permanently freezing the market - (common/src/rates/index.rs)

### Summary
`update_borrow_index` multiplies `old_index * interest_factor` before clamping to `MAX_BORROW_INDEX_RAY`, and `calculate_supplier_rewards` / `update_supply_index` multiply scaled totals by indexes in i128 (`borrowed.mul(env, new_borrow_index)`, `supplied.mul(env, old_index)`). At whale-scale positions, the RAY-denominated total value reaches `i128::MAX` roughly 170x before `MAX_BORROW_INDEX_RAY` can ever be hit, so accrual panics with `MathOverflow` instead of clamping. Every pool verb accrues first via `global_sync`, so the market is bricked forever — the index cap is dead code.

### Finding Description
The bug class in the report (memory corruption via unchecked buffer bounds on attacker-shaped input) maps here to unchecked arithmetic bounds on attacker-shaped input: fixed-point multiplies in the accrual path that panic instead of saturating when the operand domain is exceeded.

- `update_borrow_index` computes `old_index.mul(env, interest_factor)` and only afterwards compares to `MAX_BORROW_INDEX_RAY`, so an overflowing product traps before the clamp can engage (`common/src/rates/index.rs:13-19`).
- `calculate_supplier_rewards` computes `borrowed.mul(env, new_borrow_index)` and `borrowed.mul(env, old_borrow_index)` in panicking i128 (`common/src/rates/index.rs:80-81`). With `borrowed` scaled debt near `i128::MAX / index`, this overflows regardless of the index cap.
- `update_supply_index` computes `supplied.mul(env, old_index)` with the same exposure (`common/src/rates/index.rs:34`).
- All of this runs inside `accrue_chunk`, which is called from `global_sync` before any state-changing operation (`contracts/pool/src/interest.rs:20-33`, `39-53`).

The protocol's own harness proves the freeze: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` shows `update_indexes`, `withdraw`, and `repay` all reverting with `MATH_OVERFLOW` once the cliff is reached, with `borrow_index < MAX_BORROW_INDEX_RAY` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-360`).

### Impact Explanation
Permanent freezing of funds: once `borrowed * borrow_index` exceeds `i128::MAX`, every subsequent call — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `update_indexes` — panics in `global_sync` before touching state. Suppliers can never withdraw, borrowers can never repay, liquidators can never liquidate. All tokens held by the pool for that book are permanently locked.

### Likelihood Explanation
Reachable by a single unprivileged address (or one whale + one borrower): supply a large amount of a high-decimals asset, borrow near max utilization, and let interest accrue at a steep curve segment (the test uses ~98% utilization on the XLM curve). No privileged role, oracle manipulation, or third-party cooperation is needed — only capital and time. The caps that would normally bound position size can be sidestepped across multiple hub books, and `update_indexes` is permissionless.

### Recommendation
Reorder the clamp in `update_borrow_index`: detect when `old_index` is already at/near `MAX_BORROW_INDEX_RAY` and return the cap without multiplying, or use a saturating multiply for the pre-clamp product. Similarly, make `calculate_supplier_rewards` and `update_supply_index` use `mul_div_floor_saturating`-style computations (or widen to I256 without a `to_i128` panic) so accrual degrades gracefully instead of trapping. The RAY-value ceiling, not the index cap, is the real bound and must be enforced before the multiply.

### Proof of Concept
See `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`: supply `1e9 * 10^18` units of an 18-decimal asset, borrow 98% of it, advance time in yearly steps; `try_update_indexes_for` fails with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `try_withdraw_raw` / `try_repay` fail identically — market permanently frozen.
