### Title
GitHubApp#verify_webhook_signature returns true (bypasses signature verification) when `webhook_secret` is not configured for an organization - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` unconditionally treats a missing `webhook_secret` as "signature verified," so any org configured with `webhook_secret: nil` (documented as "optional" in `docs/setup.md` and shown as blank in `config/secrets.development.shopify.yml`) accepts unsigned/arbitrarily-signed webhook payloads. This lets an unauthenticated internet requester forge webhook events (e.g. `push`) for that organization's repositories and trigger real side effects such as `GithubSyncJob` enqueuing.

### Finding Description
The broken binding is: presence of `webhook_secret` for an org == that org's webhooks must be authenticated. The code instead implements: absence of `webhook_secret` == auto-pass authentication, via [1](#0-0) 
`return true unless webhook_secret` short-circuits HMAC verification entirely.

Request path: `POST /webhooks` is routed to `Shipit::WebhooksController#create`, gated by `before_action :verify_signature`, which resolves the app config via `Shipit.github(organization: repository_owner)` where `repository_owner` is read straight from the attacker-controlled JSON body (`params.dig('repository','owner','login')`): [2](#0-1) [3](#0-2) 

`Shipit.github(organization:)` builds a `GitHubApp` from that org's config in `secrets.github` [4](#0-3) , and `GitHubApp#initialize` sets `@webhook_secret = @config[:webhook_secret].presence` [5](#0-4) . If that org's config has `webhook_secret` blank/nil - a configuration pattern explicitly present in `config/secrets.development.shopify.yml` and documented as "optional" for webhook secret in `docs/setup.md` line 30/119 - `verify_webhook_signature` returns `true` regardless of the `X-Hub-Signature` header content or absence.

Exploit: attacker sends `POST /webhooks` with `X-Github-Event: push` and a JSON body whose `repository.owner.login` names the no-secret org, no (or garbage) `X-Hub-Signature`. `verify_signature` passes, `create` runs `Shipit::Webhooks.for_event('push')` handlers against the attacker-supplied payload, which (per the existing `":push with the target branch queues a GithubSyncJob"` test pattern in `test/controllers/webhooks_controller_test.rb` lines 23-32) enqueues `GithubSyncJob` for the matching stack using attacker-controlled `after` (head sha) — a write triggered by a request that never authenticated as GitHub.

Existing guards do not prevent this: `drop_unhandled_event` only filters unregistered event types, not authentication [6](#0-5) ; there is no other signature or auth check on this path.

### Impact Explanation
For any organization configured without a `webhook_secret`, an unauthenticated caller can forge arbitrary webhook events (`push`, `status`, `check_suite`, `membership`, custom handlers) for repositories under that org, causing Shipit to enqueue sync jobs, create commit statuses, or manipulate team memberships without ever proving the request came from GitHub. This is an authentication bypass on the entire webhook surface for that org — repeatable per request, scoped to organizations that have this configuration (not a cross-tenant issue for orgs that do set a secret).

### Likelihood Explanation
The precondition is entirely an operator configuration choice: an org entry in `Shipit.github` with `webhook_secret` unset. This is not a hypothetical edge case — the shipped example config `config/secrets.development.shopify.yml` demonstrates exactly this pattern (`webhook_secret: # nil`), and `docs/setup.md` labels the webhook secret as "optional." Given that, the attack requires no privileges, no secrets, and no bypass of GitHub's own systems - just a raw HTTP POST to `/webhooks` naming the vulnerable org.

### Recommendation
Do not allow authentication to silently no-op. Either (a) require `webhook_secret` to be present at config-load/boot time and refuse to start / raise if missing, or (b) change `verify_webhook_signature` so that a missing secret causes verification to fail closed (`return false unless webhook_secret`), forcing operators to explicitly configure signature checking rather than defaulting to open.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "org without webhook_secret accepts unsigned push and enqueues GithubSyncJob" do
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(
    Shipit::GitHubApp.new('no-secret-org', { app_id: 1, installation_id: 1, webhook_secret: nil, private_key: nil })
  )
  stack = shipit_stacks(:shipit) # or a stack under repository owned by 'no-secret-org'

  request.headers['X-Github-Event'] = 'push'
  # deliberately omit X-Hub-Signature entirely
  payload_body = JSON.parse(payload(:push_master))
  payload_body["repository"]["owner"]["login"] = "no-secret-org"
  expected_head_sha = payload_body["after"]

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: stack.id, expected_head_sha:]) do
    post :create, body: payload_body.to_json, as: :json
  end
  # Binding check: webhook_secret.nil? == true  vs  verified == true  -> should be verified == false, but is true
  assert_equal true, Shipit.github(organization: 'no-secret-org').verify_webhook_signature(nil, payload_body.to_json)
end
```
This demonstrates the equality `webhook_secret.present? == authentication_required` is violated: `webhook_secret` is `nil` yet `verify_webhook_signature` returns `true` and the job is enqueued, confirming an authentication bypass reachable by an unprivileged attacker.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",

      ].join(' '))
    end
