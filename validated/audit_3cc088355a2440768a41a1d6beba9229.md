### Title
Webhook signature verified against attacker-chosen `repository.owner.login` while handlers act on unchecked `repository.full_name`, enabling cross-organization webhook forgery - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
In Shipit's multi-tenant GitHub App mode, each onboarded GitHub organization can have its own `webhook_secret` [1](#0-0) . `WebhooksController#verify_signature` selects *which* organization's secret to validate the HMAC against by reading `repository.owner.login` (or `organization.login`) straight out of the attacker-supplied JSON body, before the signature has been checked [2](#0-1) . Once the HMAC passes for that chosen organization, every event handler instead resolves the *target* repository from a different field of the same body, `repository.full_name`, with no cross-check that it belongs to the organization that produced the valid signature [3](#0-2) .

### Finding Description
`verify_signature` computes `repository_owner` from the untrusted body and uses it purely to pick the HMAC secret:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [4](#0-3) 

`github_app = Shipit.github(organization: repository_owner)` then loads that specific organization's `webhook_secret` from `secrets.github` and verifies the signature against the raw POST body [5](#0-4) . Since anyone who administers a webhook for *any* organization onboarded to this Shipit instance legitimately knows that organization's `webhook_secret` (it is configured by that org's own admin when wiring up the webhook, not a Shipit-internal secret), that person can compute a valid HMAC for an arbitrary JSON body of their own construction — as long as `repository.owner.login` in that body equals their own organization.

However, all downstream `Webhooks::Handlers::Handler` subclasses (push, pull_request, membership, etc.) resolve the actual repository/stack to mutate via a *different* JSON path:
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
``` [6](#0-5) 
which is then used to look up `Repository.from_github_repo_name(repository_name)` and iterate its stacks, e.g. in `PushHandler#process`:
```ruby
stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
``` [7](#0-6) 

Nothing enforces `repository.owner.login == repository.full_name.split('/').first`. This breaks the binding: `organization that authenticated == organization/repository that is written`. An attacker who controls organization `eve-org` (and therefore its `webhook_secret`) can submit a body where `repository.owner.login = "eve-org"` (so the signature check passes against eve-org's secret) but `repository.full_name = "victim-org/victim-repo"` (so the actual handler logic operates on the victim's stacks).

### Impact Explanation
This allows cross-organization forgery of GitHub events against any repository/stack tracked by the Shipit instance, without the attacker needing any credential belonging to the victim organization. Concretely, a forged `push` event can force `stack.sync_github(expected_head_sha: ...)` on a victim's stack [7](#0-6) , and forged `pull_request` events can create/archive/unarchive review stacks for a repository the attacker does not own [8](#0-7) . Where continuous deployment is enabled, driving the sync/commit state of a victim stack can trigger unauthorized deploys/rollbacks — a cross-organization/cross-repository write satisfying the "Critical" bar in scope (cross-repository writes / unauthorized deploy).

### Likelihood Explanation
Exploitability requires only that the Shipit deployment is configured with more than one GitHub organization (multi-tenant `secrets.github` schema, supported natively per `Shipit.github_app_config` [9](#0-8) ) and that the attacker legitimately administers a webhook for at least one of those organizations. No Shipit session, `ApiClient` token, or victim-org credential is needed — only knowledge of the attacker's own organization's `webhook_secret`, which is not privileged with respect to the victim organization.

### Recommendation
- Bind the organization used to select/verify the webhook secret to the same repository object that handlers act on: after verifying the signature, re-derive `repository.owner.login` from the *same* `repository` object whose `full_name` handlers use, and reject the request if the two don't match the organization inferred from `repository.full_name`.
- Alternatively, verify against every configured organization's secret and only accept the payload if the organization that validated the signature exactly matches the owner segment of `repository.full_name` (and `organization.login` when present), rejecting otherwise.
- Avoid trusting any organization-identifying field from the unauthenticated JSON body to select cryptographic material before the signature over that same body has been validated against the *expected* organization for the target repository.

### Proof of Concept
1. Shipit is configured multi-tenant with `secrets.github` containing both `eve-org` (attacker-controlled, webhook_secret known to attacker) and `victim-org` (contains a tracked repo/stack), per `Shipit.github_app_config` [9](#0-8) .
2. Attacker crafts a `push` JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": {"login": "eve-org"}, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(eve-org_webhook_secret, body)` and POSTs to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` resolves `repository_owner` = `"eve-org"`, loads eve-org's `webhook_secret`, and the HMAC validates successfully [5](#0-4) .
5. `PushHandler` resolves the target via `payload.dig('repository','full_name')` = `"victim-org/victim-repo"` [6](#0-5) , and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on the victim's stack [7](#0-6) , despite the attacker having no access to `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
