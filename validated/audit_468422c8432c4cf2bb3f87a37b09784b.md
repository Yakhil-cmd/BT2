### Title
Cross-tenant repository confusion in webhook signature verification vs. handler dispatch - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which `Shipit.github_apps` entry (and thus which `webhook_secret`) to validate a webhook against using `repository_owner` (`params.dig('repository','owner','login')`), while every handler that acts on the payload (`PushHandler`, `StatusHandler` via `Commit.where(sha:)`, `CheckSuiteHandler`, all `PullRequest::*Handler`s) resolves the target repository/stacks independently from `payload.dig('repository','full_name')` via `Repository.from_github_repo_name`. Nothing in the request pipeline asserts these two fields are consistent, so a party who legitimately controls org A's `webhook_secret` can forge a single POST whose signature validates as org A but whose `repository.full_name` names a repo owned by sibling org C on the same Shipit instance.

### Finding Description
The broken binding is: **`repository_owner == repository.full_name.split('/').first`** is assumed true everywhere but never enforced.

- `verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository','owner','login')` (or `organization.login`) and picks `github_app = Shipit.github(organization: repository_owner)` to validate `X-Hub-Signature` against `github_app.webhook_secret` via `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83), which is a pure HMAC-SHA1 comparison over the raw body — it never inspects `repository.full_name`.
- `create` then dispatches the *entire raw payload* to `Shipit::Webhooks.for_event(event)` handlers (app/controllers/shipit/webhooks_controller.rb:10-15).
- `Handlers::Handler#stacks`/`#repository_name` (app/models/shipit/webhooks/handlers/handler.rb:32-38) and every pull_request handler (`OpenedHandler`, `ClosedHandler`, `EditedHandler`, `AssignedHandler`, `LabeledHandler`, `UnlabeledHandler`, `ReopenedHandler`, `LabelCapturingHandler`) resolve the affected `Repository`/`Stack` purely from `params.repository.full_name`, via `Repository.from_github_repo_name` (app/models/shipit/repository.rb:53-56), which does a plain `find_by(owner:, name:)` lookup with **no relation whatsoever to `repository_owner`** used in signature verification.
- `CheckSuiteHandler` uses the same `stacks` helper (repository-scoped by `full_name`), and `StatusHandler` scopes even more loosely — by `Commit.where(sha:)` globally, with no repository/owner check at all.

Attack: the attacker legitimately owns org A's real GitHub App installation and its `webhook_secret`. They craft one JSON body where `repository.owner.login = "A"` (or `organization.login = "A"` for membership events) but `repository.full_name = "C/some-repo"` (a repo belonging to sibling org C hosted on the same Shipit instance), sign the raw body with A's real `webhook_secret`, and POST it to `/webhooks`. `verify_signature` selects A's `GitHubApp`, the HMAC matches (since the attacker holds A's secret), so the request passes with a 200. The handler then reads `repository.full_name` = `"C/some-repo"` and mutates C's `Stack`/`Commit`/`PullRequest`/`Team` rows — e.g., `PushHandler` triggers `sync_github` for C's stack, `CheckSuiteHandler`/`StatusHandler` write commit statuses/check-run refreshes against C's commits, and `PullRequest::ClosedHandler`/`ReopenedHandler` can archive/unarchive C's review stacks.

No existing guard prevents this: `verify_signature` only authenticates *that the sender knows some configured `webhook_secret`*, not *which repository the payload is entitled to affect*. `drop_unhandled_event` and `ExplicitParameters` schemas validate shape/types only, not the owner-vs-full_name binding. `force_github_authentication`/`User#authorized?`/`require_permission!` are unrelated to this unauthenticated webhook endpoint.

### Impact Explanation
An attacker who controls one tenant's GitHub App webhook secret (a normal condition for any org admin/GitHub App installer on that tenant — not a Shipit operator) can mutate state belonging to any other tenant sharing the same Shipit deployment: trigger a GithubSyncJob (push), fabricate commit statuses, trigger check-run refreshes, or archive/unarchive/relabel review stacks and pull requests for a foreign repository. This is a cross-tenant authentication-bypass class issue — the webhook signature only proves the sender knows *a* valid secret, not that they are entitled to act on the specific `repository.full_name` in the payload — matching "a payload for one repository mutating another's stack/commit/task" in the Critical impact category. It is fully repeatable against any repository configured on the shared Shipit instance and is not limited to a specific handler; it reaches push, status, check_suite, and all pull_request handlers identically.

### Likelihood Explanation
Preconditions: Shipit must be configured multi-tenant with `Shipit.github_apps` containing ≥2 orgs (documented, supported feature — see `test/dummy/config/secrets_double_github_app.yml`), and the attacker must legitimately control at least one tenant's real GitHub App `webhook_secret` (trivial for any org that installs its own GitHub App integration pointing at the shared Shipit instance). No Shipit session, API token, or other secret is required. Cost is one crafted HTTP POST with a correctly computed HMAC using a secret the attacker already legitimately possesses. This is fully repeatable and requires no timing race or social engineering.

### Recommendation
In `Shipit::WebhooksController#verify_signature` (or in `Handlers::Handler`), enforce that the repository/organization used for signature verification matches the repository actually acted upon: reject the request (422) unless `repository_owner == payload.dig('repository','full_name')&.split('/')&.first` (and similarly cross-check `organization.login` for membership events). Alternatively, have handlers resolve the target `Repository`/`Stack` scoped by the verified `repository_owner` rather than trusting `full_name` independently.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_cross_tenant_test.rb
require 'test_helper'

module Shipit
  class WebhooksCrossTenantTest < ActionController::TestCase
    tests Shipit::WebhooksController

    setup do
      # Configure two tenants A and C sharing one Shipit instance, each with a real webhook_secret and stack
      Shipit.github_apps = {
        'orga' => Shipit::GitHubApp.new('orga', webhook_secret: 'secret-a'),
        'orgc' => Shipit::GitHubApp.new('orgc', webhook_secret: 'secret-c')
      }
      @stack_c = shipit_stacks(:orgc_repo) # stack owned by orgc/some-repo
    end

    %w[push status check_suite].each do |event|
      test "##{event} verified as org A cannot mutate org C's stack" do
        payload = base_payload_for(event)
        payload['repository'] = { 'owner' => { 'login' => 'orga' }, 'full_name' => 'orgc/some-repo' }
        body = payload.to_json
        signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', 'secret-a', body)}"

        request.headers['X-Github-Event'] = event
        request.headers['X-Hub-Signature'] = signature

        before = @stack_c.reload.attributes

        post :create, body: body, as: :json
        assert_response :ok # verification succeeds as org A

        # Equality check: repository_owner ("orga") must equal
        # payload['repository']['full_name'].split('/').first ("orgc") -- it does NOT.
        assert_equal before, @stack_c.reload.attributes,
          "Payload verified as org A mutated org C's stack via full_name confusion"
      end
    end
  end
end
```
This demonstrates that `repository_owner` (used to select the verifying `webhook_secret`) and `repository.full_name`'s owner segment (used by every handler to select the mutated `Stack`) are never asserted equal, allowing an org-A-secret holder to forge a request that both verifies and mutates org C's records.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
