### Title
Bridge Operator Keystore Password Written to World-Readable Plaintext File — (`node/sc/bridge_accounts.go`)

---

### Summary

`InitializeBridgeAccountKeystore` in `node/sc/bridge_accounts.go` auto-generates a bridge operator account and persists its keystore password to disk via `setup.WriteFile`. The `setup.WriteFile` helper (from `cmd/homi/setup/cmd.go`) writes files with `0o644` / `os.ModePerm` permissions — world-readable on any multi-user host. Any local OS user can read the password file, decrypt the keystore, and obtain the bridge operator's private key, enabling them to sign fraudulent cross-chain value-transfer requests.

---

### Finding Description

When the service-chain bridge starts with no pre-existing keystore, `InitializeBridgeAccountKeystore` is called for both the parent and child bridge operator accounts:

```go
// node/sc/bridge_accounts.go  (lines 207-213)
if len(ks.Accounts()) == 0 {
    password := setup.RandStringRunes(params.PasswordLength)
    acc, err := ks.NewAccount(password)
    ...
    setup.WriteFile([]byte(password), keystorePath, acc.Address.String())
``` [1](#0-0) 

The password is then stored at the predictable path `<keystorePath>/<hex-address>` using `setup.WriteFile` from `cmd/homi/setup/cmd.go`. That helper creates the directory with `os.ModePerm` (0o777) and writes the file with `0o644` permissions — readable by every user on the system:

```go
// cmd/utils/files.go  (the analogous WriteFile used by the setup package)
err := os.MkdirAll(filePath, os.ModePerm)          // 0o777 directory
err  = os.WriteFile(..., []byte(content), 0o644)    // world-readable file
``` [2](#0-1) 

On subsequent starts the same file is read back unconditionally to auto-unlock the account:

```go
// node/sc/bridge_accounts.go  (lines 226-234)
pwdStr, err := os.ReadFile(pwdFilePath)
if err == nil {
    if err := ks.Unlock(acc, string(pwdStr)); err != nil { ... }
    return ks, acc.Address, false, nil
}
``` [3](#0-2)

### Impact Explanation

The bridge operator account is the signing key for cross-chain value-transfer votes. The on-chain `BridgeOperator` contract executes a transfer once `vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]`: [5](#0-4) 

In the default single-operator or low-threshold configuration, an attacker who reads the world-readable password file can:

1. Decrypt the keystore JSON with the stolen password.
2. Obtain the bridge operator ECDSA private key.
3. Sign and submit fraudulent `handleValueTransfer` votes, causing the bridge contract to release bridged KAIA or ERC-20/ERC-721 tokens to an attacker-controlled address.

Impact: **unauthorized transfer of bridged assets** — matching the allowed-impact gate.

---

### Likelihood Explanation

- The password file is written automatically on first start with no operator action required.
- The file path is deterministic and publicly derivable: `<dataDir>/<parent_bridge_account|child_bridge_account>/<hex-address>`.
- Any OS-level user sharing the host (e.g., a compromised co-tenant process, a misconfigured web service, a CI runner) can `cat` the file without elevated privileges.
- The `setup.WriteFile` helper is a general-purpose utility not designed for secret storage; it intentionally uses `0o644` so generated config files are readable.

---

### Recommendation

1. Replace `setup.WriteFile` with a secret-safe write that uses `0o600` permissions (owner-read-only), analogous to how `crypto.SaveECDSA` and the newer `cmd/kcn/genkeys.go` `writeV3` helper handle key material:

```go
// cmd/kcn/genkeys.go — correct pattern already used elsewhere
writeFile(filepath.Join(opDir, name+".pass"), pw, 0o600)
``` [6](#0-5) 

2. Ensure the parent directory is also created with `0o700` (not `os.ModePerm`).
3. Implement the noted `TODO`: gate the auto-generation path behind an explicit opt-in flag so production deployments must supply a pre-provisioned, properly-permissioned keystore.

---

### Proof of Concept

```
# On a multi-user host running a service-chain bridge node:

# 1. Discover the bridge account directory (default datadir layout)
ls /var/kscnd/data/parent_bridge_account/
# Output: UTC--2024-...--<hex-addr>   <hex-addr>
#                  ^keystore JSON      ^plaintext password (0644)

# 2. Read the world-readable password file
cat /var/kscnd/data/parent_bridge_account/<hex-addr>
# Output: <plaintext password>

# 3. Decrypt the keystore to recover the private key
kaia account import --keystore /var/kscnd/data/parent_bridge_account/UTC--...
# Enter the stolen password → private key recovered

# 4. Use the private key to sign a fraudulent handleValueTransfer vote
# targeting an attacker-controlled recipient address, draining bridged assets.
```

		os.Exit(-1)
	}
