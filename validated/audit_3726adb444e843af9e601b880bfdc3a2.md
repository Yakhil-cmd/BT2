### Title
Cross-organization webhook forgery via `repository.owner.login`/`repository.full_name` split lets an unprivileged attacker inject labels into an arbitrary review stack's env - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/secret to verify against using `repository_owner`, derived from `params.dig('repository','owner','login')` [1](#0-0)  and then calls `Shipit.github(organization: repository_owner).verify_webhook_signature`, which returns `true` unconditionally when that org has no `webhook_secret` configured [2](#0-1) . The downstream handler, however, resolves the actual `Repository`/`Stack` to mutate using the completely independent `params.repository.full_name` field via `Repository.from_github_repo_name` [3](#0-2) [4](#0-3) . Since these two fields are never checked against each other, an attacker can name a secret-less org in `repository.owner.login` while pointing `repository.full_name` at any other org's repo the handler resolves, bypassing signature verification entirely for that target repo/stack.

### Finding Description
The broken invariant is the implicit equality Shipit assumes but never enforces: `repository_owner (used to pick the verifying secret) == owner(repository.full_name) (used to pick the mutated record)`. In `WebhooksController`, `before_action :verify_signature` runs before `create`, computing `repository_owner` from `params.dig('repository', 'owner', 'login')` and using it solely to select which `GitHubApp`/secret verifies the signature [5](#0-4) . Once verification passes (or is a no-op because `webhook_secret` is blank, per `GitHubApp#verify_webhook_signature` [2](#0-1) ), `create` parses the whole raw JSON body and dispatches it to handlers, without re-checking which org actually owns the resolved repository [6](#0-5) .

`LabelCapturingHandler` independently resolves the target `Repository` from `params.repository.full_name`, not from `repository.owner.login` [7](#0-6) . `Repository.from_github_repo_name` simply splits the `owner/name` string from `full_name` with no cross-check against a separate owner field [4](#0-3) .

Exploit flow: attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request`, body `action: "labeled"`, `repository.owner.login: "attacker-org"` (an org configured in Shipit's `github` secrets with `webhook_secret: nil`/blank — a normal, legitimate multi-org Shipit configuration, as shown in `config/secrets.development.example.yml` and `test/dummy/config/secrets_double_github_app.yml`), but `repository.full_name: "victim-org/victim-repo"` pointing at a repository that actually has an active `ReviewStack`/`PullRequest`. `verify_signature` calls `Shipit.github(organization: 'attacker-org')`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (attacker-supplied, unchecked) signature header. The request proceeds to `create`, and `LabelCapturingHandler#process` resolves `victim-org/victim-repo`'s `ReviewStack`, finds its `pull_request`, and persists `params.pull_request.labels.map(&:name)` — fully attacker-controlled strings — onto that `PullRequest#labels` [8](#0-7) . `ReviewStack#env` later upcases each label and injects it as `"true"`-valued env var into the stack's deploy/task environment [9](#0-8) .

Existing guards do not stop this: `verify_signature` never compares `repository_owner` against the org that owns `params.repository.full_name`; `ExplicitParameters` schema only validates types/presence, not cross-field consistency [10](#0-9) ; and `Repository#owner=`/format validators only constrain characters in the stored `owner` column, not the relationship between the webhook's verifying org and the payload's target repo.

### Impact Explanation
An unprivileged attacker who can only push/open PRs/label PRs on their own repository under an org they control (or simply craft raw HTTP requests) can inject arbitrary attacker-chosen strings into any other tenant's `ReviewStack`'s deploy/task environment via the `LABEL_NAME=true` mechanism in `ReviewStack#env`, as long as: (a) any org in the Shipit installation is configured without a `webhook_secret`, and (b) the target repository has an active review stack with a pull request. This is a payload for one repository (or no real repository at all) mutating another organization's stack state (`PullRequest#labels`, and transitively the deploy-time environment), matching the "Critical: a payload for one repository mutating another's stack" impact category. It is fully repeatable against any repository with a resolvable `ReviewStack`, is not scoped to a single stack, and requires no privileged Shipit role, GitHub App credentials, or webhook secret from the attacker.

### Likelihood Explanation
Preconditions: the Shipit installation must be configured with more than one GitHub org (a documented, supported configuration per `docs/setup.md` "Using Multiple Github Applications"), and at least one configured org must have a blank `webhook_secret` (also a documented default in `secrets.example.yml`/`secrets.development.example.yml`, where `webhook_secret:` is commonly left blank in examples). Given that, the attack costs the attacker nothing beyond crafting one HTTP POST with a `pull_request`/`labeled` JSON body — no signature computation, no authentication, no GitHub org membership on the victim's side. It is trivially repeatable and scriptable against any target repository name known to the attacker.

### Recommendation
Enforce that the org used to select the verifying webhook secret is the same org that owns the resolved repository before dispatching to handlers: derive `repository_owner` strictly from `Repository.from_github_repo_name(params.dig('repository','full_name'))&.owner`, or explicitly assert `params.dig('repository','owner','login') == full_name.split('/').first` before calling `verify_webhook_signature`, rejecting the request (422) on mismatch. Additionally, treat a missing/blank `webhook_secret` as a misconfiguration to be logged/alerted rather than silently allowing unsigned webhooks (`GitHubApp#verify_webhook_signature`'s `return true unless webhook_secret` should require signature verification to be intentionally disabled per org, not implicit).

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "pull_request labeled event with mismatched repository.owner.login (no-secret org) and repository.full_name (victim org/repo) mutates the victim's review stack" do
  # Setup: two orgs configured; "attacker-org" has webhook_secret: nil, "victim-org" (or whichever
  # org owns the resolved Repository) is the actual target with an active ReviewStack + PullRequest.
  victim_repository = shipit_repositories(:shipit) # or a repository under a distinct owner
  victim_stack = shipit_review_stacks(:review_stack) # has an associated PullRequest
  pull_request = victim_stack.pull_request

  payload = {
    action: "labeled",
    number: pull_request.number,
    pull_request: {
      id: pull_request.github_id, number: pull_request.number, url: "http://example.com",
      title: "t", state: "open", additions: 1, deletions: 1,
      head: { sha: "a" * 40, ref: "some-branch" },
      user: { login: "attacker" },
      assignees: [],
      labels: [{ name: "INJECTED_ENV_VAR" }]
    },
    repository: {
      full_name: victim_repository.github_repo_name, # attacker points at victim's repo
      owner: { login: "attacker-org" }                # but claims a different, secret-less org
    },
    sender: { login: "attacker" }
  }.to_json

  # attacker-org configured with webhook_secret: nil => verify_webhook_signature returns true unconditionally
  post shipit.hooks_url, params: payload,
       headers: { "X-Github-Event" => "pull_request", "X-Hub-Signature" => "sha1=bogus",
                   "Content-Type" => "application/json" }

  assert_response :ok
  pull_request.reload
  # Binding under test: repository_owner (attacker-org, unauthenticated) != owner of full_name (victim org)
  # yet the write succeeded against the victim's PullRequest.
  assert_includes pull_request.labels, "INJECTED_ENV_VAR"
  assert_equal "true", victim_stack.env["INJECTED_ENV_VAR"]
end
```

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post

      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
