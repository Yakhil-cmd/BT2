### Title
Creator fees become permanently unclaimable if the pool creator's token account is frozen or blocked - (File: programs/cp-swap/src/instructions/collect_creator_fee.rs, programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs)

### Summary
The pool creator address (`pool_creator`) is fixed permanently at pool initialization and cannot be updated afterward. All accumulated creator fees can only ever be paid out to a token account owned by that fixed `pool_creator`. If that account becomes frozen (e.g., via Token-2022 freeze authority) or the creator's associated token account otherwise cannot receive tokens, the creator fees accrue in the vault but can never be collected by anyone, with no mechanism to redirect them to an alternate address.

### Finding Description
`PoolState::initialize` sets `pool_creator` once when the pool is created and there is no admin or creator-facing instruction anywhere in the program (`update_config.rs`, `update_pool_status.rs`, or elsewhere) that allows this field to be modified afterward. [1](#0-0) 

Both fee-collection entry points hard-code the destination token accounts to associated token accounts owned by this immutable `pool_creator`/`creator` account:
- `CollectCreatorFee` constrains `creator` to `pool_state.load()?.pool_creator` and creates/uses `creator_token_0`/`creator_token_1` ATAs with `associated_token::authority = creator`. [2](#0-1) 
- `CollectCreatorFeePermissionless` is permissionless (anyone can pay to trigger it), but again the payout ATAs are always owned by the fixed `pool_creator`. [3](#0-2) 

Both instructions transfer the entire accumulated `creator_fees_token_0`/`creator_fees_token_1` to these creator-owned accounts and then zero the counters: [4](#0-3) 

Because the pool supports Token-2022 mints (`TokenInterface`/`token_0_program`/`token_1_program`), and Token-2022 mints can carry a freeze authority that can freeze a specific token account, if the pool creator's token account for `token_0`/`token_1` is frozen, or the mint otherwise rejects transfers to that address, the CPI transfer performed by `transfer_from_pool_vault_to_user` in both collection instructions will fail. Since there is no way to change `pool_creator` or to specify an alternate destination account, the accumulated creator fees remain stuck in the vault indefinitely — permanently unclaimable by anyone.

### Impact Explanation
The creator fees represent real value segregated in the pool vault (subtracted out of swappable liquidity via `vault_amount_without_fee`), so this is a permanent freezing of the pool creator's earned funds rather than a merely cosmetic issue. There is no code path to recover or redirect these fees once the creator's account is blocked, matching the "recipient's address is blocked by token → can't receive funds" bug class from the reference report, since `pool_creator` — unlike a typical swap/deposit/withdraw counterparty which self-selects its own destination accounts per transaction — is fixed once at pool creation and never updatable.

### Likelihood Explanation
This requires the pool's underlying token to be a Token-2022 mint with an active freeze authority (or another mechanism to block a specific account from receiving), and for that authority to freeze the pool creator's specific token account. This is a realistic scenario given the program explicitly supports Token-2022 mints via `TokenInterface`, and freeze authorities are a first-class, commonly-used Token-2022 feature.

### Recommendation
Allow the pool creator to specify/update the destination account for creator fee collection (e.g., an additional field in `PoolState` settable by the current `pool_creator` via a signed instruction, or allow passing an arbitrary destination token account in `CollectCreatorFee`/`CollectCreatorFeePermissionless` instead of hard-coding an ATA derived from the possibly-frozen `pool_creator` key).

### Proof of Concept
1. Initialize a pool with `token_0` or `token_1` as a Token-2022 mint that has a freeze authority; the pool creator's own token account or the ATA to be created for them.
2. Perform swaps so that `creator_fees_token_0`/`creator_fees_token_1` accrue in `PoolState` per `vault_amount_without_fee` accounting. [5](#0-4) 
3. The mint's freeze authority freezes the pool creator's associated token account for the relevant mint.
4. Any call to `collect_creator_fee` or `collect_creator_fee_permissionless` now fails at the `transfer_from_pool_vault_to_user` CPI because the destination account is frozen, and since `pool_creator` cannot be changed and no alternate destination can be supplied, the accrued creator fees are permanently stuck in the vault. [6](#0-5)

    pub fn vault_amount_without_fee(&self, vault_0: u64, vault_1: u64) -> Result<(u64, u64)> {
        let fees_token_0 = self
            .protocol_fees_token_0
            .checked_add(self.fund_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_0)
            .ok_or(ErrorCode::MathOverflow)?;
        let fees_token_1 = self
            .protocol_fees_token_1
            .checked_add(self.fund_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?
            .checked_add(self.creator_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?;
        Ok((
            vault_0
                .checked_sub(fees_token_0)
                .ok_or(ErrorCode::InsufficientVault)?,
            vault_1
                .checked_sub(fees_token_1)
                .ok_or(ErrorCode::InsufficientVault)?,
        ))

pub struct CollectCreatorFee<'info> {
    /// Only pool creator can collect fee
    #[account(mut, address = pool_state.load()?.pool_creator)]

    /// CHECK: pool vault and lp mint authority
    #[account(
        seeds = [
            crate::AUTH_SEED.as_bytes(),

        bump,

    /// Pool state stores accumulated protocol fee amount
    #[account(mut)]
    pub pool_state: AccountLoader<'info, PoolState>,

    /// Amm config account stores fund_owner
    #[account(address = pool_state.load()?.amm_config)]
    pub amm_config: Account<'info, AmmConfig>,

    /// The address that holds pool tokens for token_0
    #[account(
        mut,

    pub token_0_vault: Box<InterfaceAccount<'info, TokenAccount>>,

    /// The address that holds pool tokens for token_1
    #[account(
        mut,
        constraint = token_1_vault.key() == pool_state.load()?.token_1_vault

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
