## Title
CCMenu API token created without stack scope grants read access to all stacks, not just the intended one - ([File: app/controllers/shipit/ccmenu_url_controller.rb])

### Summary
`CCMenuUrlController#fetch` mints a per-stack "CCMenu Client" `ApiClient` token that is meant to authorize read access to a single stack, but the client is created without ever setting the `stack` association. Because `Api::BaseController#stacks` treats an absent `stack_id` as "unscoped" and falls back to `Stack.all`, the resulting token silently authorizes read access to every stack in the Shipit installation instead of the one the URL was generated for.

### Finding Description
`CCMenuUrlController#client` builds the token: [1](#0-0) 

`ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` never passes `stack:` — so the created `ApiClient` record has `stack_id = nil`, even though the surrounding controller only ever intends this token to authorize the specific `stack.to_param` embedded in the generated CCMenu URL: [2](#0-1) 

The API authorization layer uses `stack_id?` (an ActiveRecord boolean predicate on the `stack_id` column) to decide the token's scope: [3](#0-2) 

Since `stack_id` is `nil`, `stack_id?` is `false`, and `stacks` resolves to `Stack.all` — the code path meant for global, unscoped API clients. The `ApiClient` model itself supports per-stack scoping (`belongs_to :stack, optional: true`) precisely to prevent this: [4](#0-3) 

This is the exact analog of the M-22 pattern: a field that is supposed to bound/limit what an authorized action can touch (here, `stack_id` bounding what stacks a token may read) is never actually populated, so the check that is supposed to fail closed instead fails open and the "authorized scope" silently becomes "everything." The binding broken is: *the stack a token is intended to authorize (the single stack shown in the CCMenu widget URL) ≠ the stack(s) it actually can touch (all stacks, via the unscoped API client path)*.

### Impact Explanation
Any authenticated, non-privileged Shipit user (team member with access to at least one stack's CCMenu widget) can fetch `GET /stacks/:stack_id/ccmenu_url`, obtain a `read:stack` bearer token that they believe/are told is scoped to `stack_id`, and then use that same token against `Api::StacksController#index`/`#show` (and any other `read:stack`-gated endpoint) to read the status, lock state, and other metadata of every stack in the installation — including stacks/repositories the user has no legitimate reason to access. This is an authorization-scope escalation (a token meant to be scoped to one repository/stack ends up reading cross-repository stack state), matching the "escalation into authorization … unauthorized read of stack state" High-impact category.

### Likelihood Explanation
High. No special privileges are needed beyond being a logged-in Shipit user who can view at least one stack (baseline access granted to any `Shipit.github_teams` member). Triggering the bug requires only visiting the CCMenu URL endpoint for any stack once and reusing the returned token against the JSON API — no attacker-supplied signature manipulation, no race condition, and no reliance on host-application misconfiguration.

### Recommendation
Pass the stack when creating/looking up the CCMenu API client, e.g. `ApiClient.create_with(permissions: %w[read:stack], stack:).find_or_create_by!(creator: current_user, name: 'CCMenu Client')`, and make `find_or_create_by!` also key off `stack:` (otherwise a client already created for one stack, before this fix, would be reused unscoped for a different stack lookup). Add a regression test asserting that a CCMenu token for stack A returns 403/empty results when used against stack B or `Api::StacksController#index`.

### Proof of Concept
1. As a normal authenticated Shipit user with access to `stack_a`, call `GET /stacks/stack_a/ccmenu_url`.
2. `CCMenuUrlController#client` creates an `ApiClient` named "CCMenu Client" with `permissions: ['read:stack']` and no `stack` set (`stack_id` is `NULL`).
3. Extract the returned `token` query parameter (the client's `authentication_token`).
4. Issue `GET /api/stacks` (or `GET /api/stacks/:any_other_stack_id`) using HTTP Basic auth with that token.
5. `Api::BaseController#authenticate_api_client` succeeds; `Api::BaseController#stacks` evaluates `current_api_client.stack_id?` as `false` and returns `Stack.all`, so the response includes every stack in the installation — not just `stack_a`. [5](#0-4) [6](#0-5)

# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
