### Title
`flash_position` mints leveraged debt with `charge_fee=false`, letting any user bypass the strategy origination fee that `multiply` enforces - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The pool supports an origination fee on strategy debt: `create_strategy` computes `flashloan_fee` bps on the principal when `charge_fee` is true, books it as protocol revenue, and withholds it from the payout (`contracts/pool/src/ops/strategy.rs:94-101`). The controller chooses that flag per entrypoint. `multiply` opens leveraged debt through `borrow_into_controller` with the fee charged, while `flash_position` — a permissionless entrypoint that creates the same kind of leveraged, debt-bearing position via a user-supplied receiver callback — hardcodes `charge_fee=false` and emits `fee: 0` (`flash_position.rs:37-39`, `flash_position.rs:271-279`, `flash_position.rs:164`). A user can therefore obtain the same economic exposure as `multiply` while paying zero origination fee.

### Finding Description
`process_flash_position` is callable by any authorized (unprivileged) caller (`require_authorized_caller`, `flash_position.rs:45`) with a caller-selected WASM `receiver`. It validates that the debt market is flashloanable and that collateral minimums are met, then calls `mint_and_forward`, which invokes `borrow_into_controller(env, account, debt, amount, false, PositionAction::FlashPos, cache)` — the literal `false` is the `charge_fee` argument (`flash_position.rs:271-279`). `borrow_into_controller` forwards it to `pool_create_strategy_call` (`contracts/controller/src/positions/debt.rs:285-287`), and the pool's `compute_fee` returns `0` whenever `charge_fee` is false (`strategy.rs:95-97`).

The result: the pool mints full debt shares against the account but sends the gross `amount` to the receiver, no revenue shares are minted (`add_protocol_revenue` is still called but with a zero-valued `protocol_fee`), and the `FlashPositionEvent` records `fee: 0` (`flash_position.rs:164`). The only gates distinguishing this path from `multiply` are `is_flashloanable` on the market and a receiver contract that deposits the required collateral — both satisfiable by the attacker with their own receiver contract.

### Impact Explanation
The protocol permanently loses the `flashloan_fee`-bps origination fee on every leveraged position opened through `flash_position` instead of `multiply`. Since the borrowed notional is unbounded up to liquidity and collateral constraints, the foregone revenue scales with position size — a direct loss of protocol yield of the same class as the reference finding (fees effectively set to zero by the user's choice of path). Fee revenue that would have been minted as protocol supply shares simply never accrues.

### Likelihood Explanation
High. `flash_position` is permissionless: any account can deploy or reuse a trivial `execute_flash_position` receiver that routes the borrowed funds into the listed collateral assets (e.g., via its own swap), exactly mirroring what `multiply` does internally. No privileged role, leaked key, or off-chain coordination is needed — the user merely selects the fee-free entrypoint. There is no economic disincentive; the flash_position flow is strictly cheaper than `multiply` whenever `flashloan_fee > 0` and the market is flashloanable.

### Recommendation
Charge the origination fee on `flash_position` debt exactly as `multiply` does: pass `charge_fee=true` to `borrow_into_controller` in `mint_and_forward`, or derive the flag from market/hub configuration rather than hardcoding it. The borrowed amount forwarded to the receiver should then be `amount - fee`, and `execute_flash_position` callers should size collateral deposits accordingly. Alternatively, if flash positions are intentionally fee-free, remove or restructure the fee on `multiply` so both leverage entrypoints enforce a single, consistent fee policy that the user cannot select around.

### Proof of Concept
1. Admin creates a market with `flashloan_fee = 100` bps and `is_flashloanable = true`.
2. Attacker deploys a receiver contract implementing `execute_flash_position` that swaps the received debt-asset into a listed collateral asset and transfers it to the controller.
3. Attacker calls controller `flash_position` with `mode = Multiply`, `debt = (hub, USDC)`, `amount = 1_000_000`, `receiver = attacker_receiver`, `collaterals = [(hub, XLM), min]`.
4. `mint_and_forward` calls `pool.create_strategy(..., charge_fee=false)`; the pool mints debt for `1_000_000` and transfers the full `1_000_000` (fee = 0, vs. `10_000` that `multiply` would withhold).
5. The receiver deposits the swapped collateral; `collect_collateral_deposits` accepts it, `strategy_finalize` passes solvency, and the event records `fee: 0`.
6. Repeat with the same notional through `multiply` and compare `get_revenue`: the `flash_position` path minted zero revenue shares on identical leveraged exposure — the protocol collected no origination fee, at the attacker's option.
