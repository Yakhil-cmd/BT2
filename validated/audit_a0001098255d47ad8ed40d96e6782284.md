### Title
Cross-tenant `PullRequest` overwrite via decoupled `repository.owner.login` (used for signature auth) and `repository.full_name` (used for target lookup) - ([File: app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the webhook signature against using `params.dig('repository', 'owner', 'login')`, while `AssignedHandler#process` (and the sibling `EditedHandler`) selects *which tenant's data to mutate* using an entirely separate field, `params.repository.full_name`. These two fields come from the same attacker-controlled JSON body and are never cross-validated, so a request that authenticates as one organization can still target and overwrite another organization's `Shipit::PullRequest` row.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:
`org_from(params.dig('repository','owner','login'))` (used to pick the webhook secret in [1](#0-0)  and [2](#0-1) ) **should equal** `org_from(params.repository.full_name)` (used by the handler to find the target repository via [3](#0-2) ). Nothing in `AssignedHandler`'s `ExplicitParameters` schema requires `repository.owner.login` at all — only `repository.full_name` is required [4](#0-3)  — so these two independently attacker-supplied strings are never compared.

`AssignedHandler#process` then unconditionally overwrites the located `PullRequest`'s cached GitHub data with fully attacker-controlled `params.pull_request` (including `head.sha`, `head.ref`, `title`, `labels`) as long as a row exists for that repository/number: [5](#0-4) 

`Shipit::Repository.from_github_repo_name` performs a plain lookup by owner/name parsed out of `full_name`, with no relationship enforced back to the org that authenticated the request: [6](#0-5) 

The only gate standing between an unauthenticated payload and this write is `verify_webhook_signature`, which is **fail-open** when the resolved organization has no `webhook_secret` configured: [7](#0-6) 

In a multi-org deployment (`github_default_organization` non-nil), `Shipit.github(organization: repository_owner)` resolves per-org config strictly from `params.repository.owner.login`, raising only if the *named org itself* is unknown; it never validates that this org matches the org implied by `repository.full_name`: [8](#0-7) 

Exploit flow: an attacker with no session, no API token, and no secrets sends `POST /webhooks` (`X-Github-Event: pull_request`, `action: assigned`) directly to the Shipit host with:
- `repository.owner.login` = an org configured in this Shipit instance that has **no `webhook_secret` set** (a legitimate, supported configuration state per the `return true unless webhook_secret` fallback), so `verify_signature` passes for any/no `X-Hub-Signature`;
- `repository.full_name` = `"org_b/victim-repo"` — a completely different, victim tenant's tracked repository;
- `number` = a real PR number belonging to a tracked `Shipit::PullRequest` under `org_b`;
- `pull_request.head.sha`, `head.ref`, `title`, `labels`, etc. — arbitrary attacker-chosen values.

`verify_signature` authenticates the request against the (secret-less) org named in `repository.owner.login`, but `AssignedHandler#repository`/`#pull_request` resolve and mutate the row belonging to `org_b`, which never participated in producing or validating this request. This is a genuine tenant-authentication/tenant-authorization mismatch: the code checks "is this org allowed to send us a webhook" but never checks "is this org allowed to touch *this* row."

### Impact Explanation
A successful request lets an attacker overwrite `Shipit::PullRequest#github_pull_request` (and derived columns: `head` commit sha/ref, `title`, `labels`, `state`, `additions`/`deletions`) for any tracked PR belonging to any other tenant repository in the installation, with fully attacker-chosen `head.sha`/`ref`. Since downstream review-stack/merge-queue logic reads this cached data (e.g. `find_or_create_commit_from_github_by_sha!` in [9](#0-8) ) treating it as GitHub-verified truth, this is cross-tenant data poisoning that can influence which commit/branch a victim stack considers current for its PR, satisfying the Critical bar ("a payload for one repository mutating another's stack/commit/task/team"). It is repeatable against any tracked PR number in any tenant repository, limited only by needing to guess/enumerate PR numbers.

### Likelihood Explanation
Requires: (1) a multi-org Shipit configuration where at least one configured organization lacks a `webhook_secret` (a supported, not-unusual state given `webhook_secret` is optional per the fallback code path), and (2) knowledge of a target tenant's `owner/repo` full name and an existing PR number (both are public/guessable GitHub information, not secret). No Shipit credentials, GitHub tokens, or webhook secrets of any kind are needed by the attacker. Given these preconditions, exploitation is a single unauthenticated HTTP POST, fully repeatable and scriptable.

### Recommendation
Cross-validate that the organization used to authenticate the webhook (`repository.owner.login` / `organization` field) matches the owner encoded in `repository.full_name` before dispatching to handlers — reject the request (422) on mismatch. Additionally/alternatively, require `webhook_secret` to be present for every configured organization (fail closed instead of fail open when unset), and have `AssignedHandler`/`EditedHandler` scope their `PullRequest` lookup through the authenticated organization rather than trusting `params.repository.full_name` alone.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "pull_request assigned event cannot cross-tenant overwrite another org's PullRequest" do
  # Setup: two orgs in multi-org config; org_a has no webhook_secret configured
  # org_b is a separate tenant with a real, tracked PullRequest
  victim_repo = Shipit::Repository.create!(owner: 'org_b', name: 'victim-repo')
  victim_stack = create_stack(repository: victim_repo)
  victim_pr = Shipit::PullRequest.create!(stack: victim_stack, number: 42, head: shipit_commits(:first), ...)
  original_sha = victim_pr.github_pull_request['head']['sha']

  request.headers['X-Github-Event'] = 'pull_request'
  # No valid X-Hub-Signature is supplied / org_a has no webhook_secret => verify_signature passes
  payload = payload_parsed(:pull_request_assigned)
  payload['repository'] = { 'full_name' => 'org_b/victim-repo', 'owner' => { 'login' => 'org_a' } }
  payload['number'] = 42
  payload['pull_request']['number'] = 42
  payload['pull_request']['head']['sha'] = 'deadbeef' * 5

  post :create, body: payload.to_json, as: :json

  assert_equal 'deadbeef' * 5, victim_pr.reload.github_pull_request['head']['sha']
  refute_equal original_sha, victim_pr.github_pull_request['head']['sha']
end
```
This demonstrates the binding `authenticated_org (repository.owner.login) == owning_org (repository.full_name)` does **not** hold and is never enforced, allowing `org_a`'s (unsigned) request to overwrite `org_b`'s `PullRequest` row.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
