### Title
Webhook signature is verified against `repository.owner.login`'s GitHub App secret while the affected stack is selected from the unverified `repository.full_name` field — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In the multi-tenant configuration of the engine, `Shipit.github(organization:)` selects a distinct `GitHubApp` (and thus a distinct `webhook_secret`) per GitHub organization [1](#0-0) . `WebhooksController#verify_signature` derives *which* organization's secret to use for HMAC verification exclusively from `repository.owner.login` (or `organization.login`) inside the untrusted JSON body [2](#0-1) . Once the signature is accepted, every webhook `Handler` (the base class used by `PushHandler`, `StatusHandler`, `CheckSuiteHandler`, etc.) determines the **repository/stack to act on** from a *different* field of the same body: `repository.full_name` [3](#0-2) . These two fields are never cross-validated against each other.

### Finding Description
This is the direct analog of the Cooler bug class: a payload field (`repository.full_name`, the resource actually acted upon) is never checked against the value that was used to establish trust (`repository.owner.login`, used to select the verifying secret), even though both are covered by the same signature.

The binding that should hold is:
```
organization_that_authenticated(repository.owner.login) == organization_of(repository_that_is_written(repository.full_name))
```

Before any attacker action, this equality holds for legitimate GitHub-originated webhooks because GitHub itself sets both fields consistently and only signs with the secret of the org that owns that repository.

After the attack: an attacker who administers **any** organization that has a legitimate Shipit GitHub App installation on this instance (org `"attacker-org"`, entry present in `github_app_config`) knows `webhook_secret_attacker-org`. Because HMAC covers the *entire* raw request body, the attacker can freely choose every field of the JSON payload, including making `repository.owner.login = "attacker-org"` (used only for signature-secret selection) while setting `repository.full_name = "victim-org/victim-repo"` (used by `Handler#stacks`/`#repository_name` to find the real `Stack`). `verify_signature` passes because it re-computes HMAC-SHA1 over the same raw body with `webhook_secret_attacker-org`, which the attacker legitimately possesses [4](#0-3) . The handler then resolves `stacks` for `victim-org/victim-repo` [3](#0-2)  and acts on it — e.g. `PushHandler#process` calls `stack.sync_github(expected_head_sha:)` on the victim's stack [5](#0-4) , and `StatusHandler`/`CheckSuiteHandler` write forged CI/check state for victim commits, none of which the attacker's org has any GitHub-side permission to send.

Root cause: `repository_owner` used purely to pick the verification key [6](#0-5)  is never required to be the same organization as the one owning `repository.full_name` that `Handler#repository_name`/`#stacks` subsequently trusts [7](#0-6) .

### Impact Explanation
This crosses a genuine credential/repository trust boundary defined in scope: "an organization that authenticated versus the repository that is written." Concretely, an attacker controlling one onboarded GitHub organization can forge webhook events (push/status/check_suite/membership) that are processed against a completely different organization's stacks:
- `StatusHandler` can inject forged commit statuses for a victim repository's commits, which — combined with `continuous_deployment` — can cause required CI checks to appear to pass and lead to an **unauthorized deploy** of the victim stack.
- `MembershipHandler` similarly trusts `organization.login` from the payload without cross-checking it against the signing org, allowing forged team membership changes tied to `Shipit.github_teams` authorization [8](#0-7) [9](#0-8) , which can escalate into authorization bypass for the Shipit UI.

Both outcomes match the "High/Critical" impact bar defined in scope (unauthorized deploy; escalation into `Shipit.github_teams` authorization).

### Likelihood Explanation
This requires the deployment to be configured in the multi-organization mode (`github_app_config` keyed by org, i.e. more than one org onboarded to a single Shipit instance) and the attacker to legitimately administer/install the Shipit GitHub App on at least one of those organizations — which is a normal, low-privilege, unprivileged-relative-to-the-victim action (installing a GitHub App on your own org requires no access to the victim). No `ApiClient` token, session, or GitHub write access to the victim repo is required, satisfying the "unprivileged attacker" constraint.

### Recommendation
Cross-validate that the field used to select the verification secret (`repository.owner.login` / `organization.login`) matches the owner encoded in `repository.full_name` before dispatching to handlers, or better, derive both the verification key and the acted-upon repository from the same trusted source (e.g. only trust `repository.full_name` after confirming its owner segment equals `repository_owner`), rejecting the webhook (422) on mismatch.

### Proof of Concept
1. Shipit is configured with `github_app_config` entries for both `attacker-org` and `victim-org` (multi-tenant install), attacker administers `attacker-org`'s GitHub App and thus knows `webhook_secret_attacker-org`.
2. Attacker crafts a `push` webhook body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha already known to exist on victim repo>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(webhook_secret_attacker-org, raw_body)` and POSTs to `/github/webhooks`.
4. `verify_signature` resolves `Shipit.github(organization: "attacker-org")` and successfully verifies the signature [10](#0-9) .
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` [3](#0-2)  and calls `stack.sync_github(expected_head_sha: params.after)` on the victim's stack [5](#0-4)  — an action the attacker's org has no GitHub permission to trigger.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
