### Title
Update-check `ReleaseInfo.Version`/`URL` from GitHub API response printed without Unicode bidi/zero-width sanitization - ([File: internal/update/update.go])

### Finding Description
`getLatestReleaseInfo` decodes the `releases/latest` JSON response directly into a `ReleaseInfo` struct whose `Version` and `URL` fields are plain `string` types (`json:"tag_name"` / `json:"html_url"`), with no post-decode sanitization: [1](#0-0) [2](#0-1) 

An attacker who controls the `releases/latest` response for the checked repo (a supported precondition since `gh` can be pointed at attacker-controlled hosts/orgs, and `tag_name`/`html_url` are attacker-authored fields on any release the attacker publishes) can set `tag_name` or `html_url` to a string containing Unicode bidi control characters (e.g. U+202E RIGHT-TO-LEFT OVERRIDE) or zero-width characters mixed with homoglyphs, so the rendered text visually reorders/spoofs a domain (e.g. making a malicious URL appear to end in `github.com`).

The codebase does have a dedicated defense for exactly this class of untrusted-external-content problem: `pkg/iostreams.Untrusted`, which wraps HTTP-response-derived strings and sanitizes them via `asciisanitizer` on every `fmt` print path: [3](#0-2) [4](#0-3) 

However, `ReleaseInfo.Version`/`URL` are declared as raw `string`, not `iostreams.Untrusted`, so this protection is never applied to update-check output before it flows to `ghcmd`'s print path. Additionally, even the existing `Untrusted`/`asciisanitizer` sanitizer is documented and designed to neutralize ANSI escape sequences, not general Unicode bidi-override or zero-width characters — so this specific class of Unicode-based visual spoofing is not covered by any sanitizer in the codebase.

### Impact Explanation
This allows an attacker-controlled release's `tag_name`/`html_url` to be rendered in the user's terminal with reordered/hidden characters, potentially making a malicious URL visually resemble a trusted one (e.g. `github.com`). This maps to a terminal output-spoofing / social-engineering-enabling primitive rather than direct code execution, credential exfiltration, or file-write, but is a real gap in an otherwise-present output-sanitization invariant (`iostreams.Untrusted`) that the codebase applies elsewhere to untrusted HTTP-derived content.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only to control (or publish) a release whose `tag_name` or `html_url` field contains bidi/zero-width Unicode characters, and have `CheckForUpdate` invoked against that repo. This is fully attacker-controlled, repeatable, and requires no victim interaction beyond running an ordinary `gh` command that triggers the update check.

### Recommendation
Wrap `ReleaseInfo.Version` and `ReleaseInfo.URL` (or sanitize them immediately after decode in `getLatestReleaseInfo`) using `iostreams.Untrusted`, and extend the sanitizer (or add a dedicated one) to strip/escape Unicode bidi control characters (U+202A–U+202E, U+2066–U+2069) and zero-width characters (U+200B, U+200D, U+FEFF) in addition to ANSI escapes, before any untrusted string derived from HTTP responses is rendered to the terminal.

### Proof of Concept
```go
func TestGetLatestReleaseInfo_BidiSpoof(t *testing.T) {
    payload := `{"tag_name":"v1.0.0","html_url":"https://evil.example/\u202Emoc.buhtig"}`
    // httpmock returns 200 with `payload` for GET /repos/OWNER/REPO/releases/latest
    info, err := getLatestReleaseInfo(context.Background(), client, "OWNER/REPO")
    require.NoError(t, err)
    // Assert the returned URL still contains the raw U+202E control char,
    // proving no sanitization occurred before it would be printed by ghcmd.Main.
    require.Contains(t, info.URL, "\u202E")
}
```
Expected result today: the assertion passes (raw bidi char preserved, unsanitized) — confirming the gap. After remediation, the fix should either strip/flag the bidi character or route `info.URL` through an `Untrusted`-style sanitizer before it reaches any print path.

// bodies, file contents fetched from a remote, anything that originates outside

// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path

// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
