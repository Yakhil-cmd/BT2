### Title
Cross-repository webhook forgery via secret-less organization bypasses HMAC verification, letting an attacker unarchive a victim's ReviewStack - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's HMAC secret to check against using `params.dig('repository','owner','login')`, while `PullRequest::LabeledHandler` resolves the actual repository/stack to mutate using the independent field `params.repository.full_name`. Because both fields are attacker-controlled inside the same raw JSON body, an attacker can pin the signature check to any Shipit-configured organization that has no `webhook_secret` set (which makes `verify_webhook_signature` return `true` unconditionally) while pointing `repository.full_name` at a victim's repository, causing `stack.unarchive!` to run against a stack the attacker never touched on GitHub.

### Finding Description
The claimed binding — "organization verifying HMAC == organization owning the repository whose provisioning_behavior gates the archive/unarchive decision" — is **not enforced** in code; the two values are derived from two different, independently-attacker-controlled JSON fields:

- Verification org: `repository_owner` in `app/controllers/shipit/webhooks_controller.rb:59-62` reads `params.dig('repository','owner','login')` (or `organization.login`).
- Target repository: `LabeledHandler#repository` in `app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:65-68` reads `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`.

`verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. In `lib/shipit/github_app.rb:76-83`, `verify_webhook_signature` short-circuits: `return true unless webhook_secret` — i.e., if the organization resolved from `repository.owner.login` has no `webhook_secret` configured, the signature is accepted regardless of the `X-Hub-Signature` header content.

Exploit flow:
1. Attacker POSTs directly to `/webhooks` with header `X-Github-Event: pull_request` and a crafted JSON body satisfying `LabeledHandler`'s `ExplicitParameters` schema (`app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:8-39`).
2. In that body, set `repository.owner.login` to any organization the Shipit instance has configured (multi-tenant) but for which no `webhook_secret` is set — this can be the attacker's own onboarded org.
3. Set `repository.full_name` to `"victim-org/victim-repo"` (the victim's actual GitHub repo, unrelated to the org used in step 2), and set `pull_request.labels` such that `unarchive?` (`labeled_handler.rb:90-93`) evaluates true given the victim repo's `provisioning_behavior_prevent_with_label` setting.
4. `verify_signature` resolves the org from `repository.owner.login` (attacker's secret-less org), returns `true` unconditionally, passes.
5. `LabeledHandler#process` → `handle` resolves `repository` from `repository.full_name` (victim repo), builds `stack` scoped to `repository.review_stacks`, and calls `stack.unarchive!` (`labeled_handler.rb:41-57`), mutating a victim stack the attacker never labeled through GitHub.

None of the listed guards close this gap: `drop_unhandled_event` only checks the event type exists a handler; the `ExplicitParameters` schema only validates JSON shape, not cross-field consistency; `verify_signature`'s only real check is HMAC, which is bypassed entirely when the *verification* org (from `repository.owner.login`) has no secret, independent of the *target* org/repo (from `repository.full_name`).

### Impact Explanation
A successful request causes the engine to execute `stack.unarchive!` on a victim's `ReviewStack` — a "payload for one repository mutating another's stack," matching the Critical impact category. Unarchiving re-enables deploy/redeploy eligibility for a stack the victim organization had deliberately archived, an unauthorized stack lifecycle mutation. The attack is repeatable against any repository whose `full_name` the attacker can guess/know, as long as at least one Shipit-configured organization lacks a `webhook_secret`. Blast radius spans all repositories/orgs hosted on the same Shipit instance, since the vulnerable field (`repository.full_name`) is decoupled from tenant identity entirely.

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one GitHub organization configured (`Shipit.github`) without a `webhook_secret` — plausible in real multi-tenant setups where an operator forgets to set a secret for an org, or where a GitHub App is used for API auth but the operator didn't separately configure webhook secret verification. Attacker cost is minimal: no GitHub interaction is required at all, just a single crafted HTTP POST to `/webhooks`; no session, token, or secret is needed. This is directly repeatable per request against arbitrary repositories.

### Recommendation
Enforce that the organization used for signature verification is the same organization that owns the repository being mutated: derive the target repository from the same `repository.owner.login`/`organization.login` used in `verify_signature`, and reject (422) if `repository.full_name`'s owner does not match `repository_owner`. Additionally, treat a missing `webhook_secret` for a configured organization as a configuration error rather than an implicit bypass — either require all onboarded organizations to have a webhook secret, or fail closed instead of `return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`.

      github_app = Shipit.github(organization: repository_owner)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def respond_to_label_change?
            params.action == "labeled" &&
              pull_request_state == "open" &&
              repository.review_stacks_enabled &&
              (archive? || unarchive?)
          end

          def archive?
            (repository.provisioning_behavior_allow_with_label? && !pull_request_has_provisioning_label?) ||
              (repository.provisioning_behavior_prevent_with_label? && pull_request_has_provisioning_label?)
          end

          def unarchive?

              (repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?)
