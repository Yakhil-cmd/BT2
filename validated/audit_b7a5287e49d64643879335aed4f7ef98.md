### Title
Single Bridge Operator Can Drain Bridge Funds Without On-Chain Proof — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeOperator.sol`)

### Summary

The Kaia service-chain bridge's `handleKLAYTransfer`, `handleERC20Transfer`, and `handleERC721Transfer` functions accept operator-supplied parameters — including `_requestTxHash`, `_from`, `_to`, and `_value` — without any on-chain proof that a corresponding `RequestValueTransfer` event actually occurred on the source chain. Combined with a default operator threshold of **1**, a single registered bridge operator can fabricate all transfer parameters and drain the bridge contract's entire KAIA/ERC20/ERC721 balance.

### Finding Description

`BridgeOperator.sol` initialises `operatorThresholds` to `1` for every vote type in its constructor: [1](#0-0) 

With threshold = 1, the `_voteValueTransfer` check in `BridgeTransferKLAY.sol::handleKLAYTransfer` passes on the very first operator call: [2](#0-1) 

The function accepts `_requestTxHash`, `_from`, `_to`, `_value`, `_requestedNonce`, and `_requestedBlockNumber` as plain calldata. The only guards are:

1. `onlyOperators` — caller must be a registered operator.
2. `_lowerHandleNonceCheck` — nonce must be ≥ `lowerHandleNonce`.
3. `_voteValueTransfer` — vote count must reach `operatorThresholds[ValueTransfer]` (default: 1). [3](#0-2) 

`_setHandledRequestTxHash` only records the hash to prevent double-spend; it does **not** verify the hash exists on the source chain or that `_value`/`_to` match any real request. There is no Merkle proof, receipt proof, or any cross-chain verification step.

The Go-side bridge manager in `node/sc/bridge_manager.go` calls these handle functions directly with event data taken from the source chain's event log — but the on-chain contract itself imposes no such constraint: [4](#0-3) 

### Impact Explanation

A single registered bridge operator can call `handleKLAYTransfer(fakeHash, anyFrom, attackerAddr, bridgeBalance, unusedNonce, anyBlock, "")`. Because threshold = 1, `_voteValueTransfer` returns `true` immediately, `closedValueTransferVotes[unusedNonce]` is set, and the contract executes:

```solidity
(bool ok, ) = _to.call.value(_value)("");
```

transferring the full bridge balance to the attacker. The same applies to `handleERC20Transfer` (minting or releasing ERC20 tokens) and `handleERC721Transfer` (transferring NFT ownership). The corrupted protected value is the bridge contract's KAIA balance and all registered token balances.

### Likelihood Explanation

The default threshold is 1 and is never automatically raised. Any deployment that does not explicitly call `setOperatorThreshold` after adding additional operators retains this default. The bridge owner registers operators, but once registered, a single operator needs no collusion and no compromised key — only the ability to submit a transaction to the bridge contract. This is a semi-trusted but reachable role, directly analogous to the ZetaChain observer role.

### Recommendation

1. **Require Merkle / receipt proof**: `handleKLAYTransfer` and sibling functions should accept and verify a Merkle proof that `_requestTxHash` with the claimed parameters was included in a finalised block on the source chain.
2. **Raise the default threshold**: The constructor should default `operatorThresholds` to a value greater than 1 (e.g., majority of registered operators), or enforce a minimum threshold relative to the operator count.
3. **Bind handle parameters to the request hash**: Store a commitment of `(from, to, value, nonce)` at request time and verify it on the handle side, so operators cannot substitute different parameters for a real hash.

### Proof of Concept

```
1. Deploy bridge with default config (threshold = 1, deployer is sole operator).
2. Fund the bridge with 100 KAIA via chargeWithoutEvent().
3. As the operator, call:
     bridge.handleKLAYTransfer(
         bytes32(0xdeadbeef...),   // fabricated hash — never existed on source chain
         address(0),               // arbitrary _from
         attackerAddress,          // _to = attacker
         100 ether,                // _value = full bridge balance
         0,                        // _requestedNonce (>= lowerHandleNonce = 0)
         1,                        // _requestedBlockNumber
         ""
     )
4. _voteValueTransfer(0) returns true (voteCounts[voteKey] = 1 >= threshold 1).
5. Bridge transfers 100 KAIA to attackerAddress.
6. Bridge balance = 0; attacker balance += 100 KAIA.
``` [5](#0-4) [6](#0-5) [7](#0-6)

        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
