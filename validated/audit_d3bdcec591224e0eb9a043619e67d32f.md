### Title
Issuer of a `PreSignedMint`/`PreSignedAttributes` authorization cannot revoke it before consumption or before its `deadline` - ([File: substrate/frame/nfts/src/lib.rs])

### Summary
`pallet-nfts` lets a collection `Issuer`/`Admin` create an off-chain signed authorization (`PreSignedMint` or `PreSignedAttributes`) that any holder of the signed message can later redeem on-chain via the signed extrinsics `mint_pre_signed` / `set_attributes_pre_signed`. Exactly like the Kairos `Offer` struct that a lender signs off-chain and cannot cancel, these Substrate structures are pure data + signature with no on-chain "commitment" record and no cancellation call — the only constraint that limits how long a stale/undesired authorization stays valid is the `deadline` field chosen by the signer itself when the message was created.

### Finding Description
`PreSignedMint` [1](#0-0)  and `PreSignedAttributes` [2](#0-1)  are encoded off-chain, signed by the collection's `Issuer`/`Admin`, and handed to a counterparty (analogous to the lender handing a signed `Offer` to a borrower in the report). The dispatchables that consume them only check the signature and a `deadline` against the current block number — there is no on-chain "commit" step and no `cancel_*` extrinsic that lets the signer void the authorization early:

```rust
pub fn mint_pre_signed(
    origin: OriginFor<T>,
    mint_data: Box<PreSignedMintOf<T, I>>,
    signature: T::OffchainSignature,
    signer: T::AccountId,
) -> DispatchResult {
    let origin = ensure_signed(origin)?;
    Self::validate_signature(&Encode::encode(&mint_data), &signature, &signer)?;
    Self::do_mint_pre_signed(origin, *mint_data, signer)
}
``` [3](#0-2) 

`do_mint_pre_signed` only verifies the deadline hasn't passed and that the signer holds the `Issuer` role — it never checks a "not-revoked" flag:
```rust
let now = T::BlockNumberProvider::current_block_number();
ensure!(deadline >= now, Error::<T, I>::DeadlineExpired);

ensure!(
    Self::has_role(&collection, &signer, CollectionRole::Issuer),
    Error::<T, I>::NoPermission
);
``` [4](#0-3) 

`do_set_attributes_pre_signed` follows the same pattern, checking only `deadline >= now` before applying the signer's pre-authorized attribute changes: [5](#0-4) .

Unlike `pallet-atomic-swap`'s `create_swap`/`cancel_swap` pair [6](#0-5)  or `pallet-nfts`' own item-swap `create_swap`/`cancel_swap` pair [7](#0-6)  (both of which record the intent on-chain and expose an explicit cancellation extrinsic), there is no on-chain record of a `PreSignedMint`/`PreSignedAttributes` authorization and thus no way for the `Issuer` to invalidate one they already signed — no nonce, no revocation list, no "burn the pending approval" call. This exactly mirrors the report's root cause: "once an offer is checked out [signed], it cannot be canceled" because the authorization is proven purely by an off-chain signature with no on-chain state that a cancellation transaction could mutate.

By contrast, the newer `pallet-assets-precompiles` EIP-2612 `permit` implementation added in this repo does solve this correctly by keeping a monotonically-increasing on-chain `Nonces` map, so a signer can always invalidate a stale signed approval by simply signing (and submitting) a new one with the current nonce [8](#0-7) , and there is an explicit `permit_set_and_revoke` test proving revocation works [9](#0-8) . `pallet-nfts`' pre-signed mint/attribute flows have no equivalent nonce or revocation primitive.

### Impact Explanation
If collection state changes after the `Issuer` signs a `PreSignedMint` (e.g. they no longer want to distribute the item, discovered a pricing/attribute mistake, or the collection's economics changed), any holder of the leaked/shared signed message can still call `mint_pre_signed` up until the pre-set `deadline` and force the mint (and, if `mint_price` was set, force a currency transfer from the claimer to the collection owner at the old price) or force attribute changes via `set_attributes_pre_signed`. The `Issuer` has no way to stop this short of waiting out the deadline, which is bounded only by whatever value they originally chose — this is the same "cannot void the unlented/unconsumed offer" class of bug as the Kairos report, just instantiated for FRAME's `pallet-nfts` pre-signed authorizations instead of an EVM lending offer.

### Likelihood Explanation
Likelihood is Low-to-Medium: it requires the `Issuer` to have already signed and shared a `PreSignedMint`/`PreSignedAttributes` message off-chain (standard usage pattern for this feature, e.g. gasless/delegated minting services) and later want to retract it before the deadline or before someone submits it. No privileged role or attacker capability beyond "possessing the previously-shared signed message" is needed to exploit the gap — the caller of `mint_pre_signed`/`set_attributes_pre_signed` need only be `ensure_signed`, i.e. any account.

### Recommendation
Add a nonce (per `(collection, signer)` or per specific `PreSignedMint`/`PreSignedAttributes` payload hash) similar to the `permit` pallet's `Nonces` storage, and/or an explicit `cancel_pre_signed_mint` / `cancel_pre_signed_attributes` extrinsic that lets the `Issuer`/`Admin` invalidate a specific outstanding signed authorization before its `deadline`, mirroring the cancellation pattern already used by `pallet-atomic-swap::cancel_swap` and `pallet-nfts::cancel_swap`.

### Proof of Concept
No dynamic PoC was executed. The finding is a static-code analog derived by tracing `mint_pre_signed`/`set_attributes_pre_signed` in `substrate/frame/nfts/src/lib.rs` down through `do_mint_pre_signed`/`do_set_attributes_pre_signed` and confirming (via `grep_search` across `substrate/frame/nfts/**` for `cancel|Revoke|invalidate`) that no cancellation/revocation path exists for these two pre-signed structures, in contrast to the on-chain-recorded, explicitly cancellable `create_swap`/`cancel_swap` flow in the same pallet and the nonce-based revocable `permit` flow in `pallet-assets-precompiles`. Existing unit tests `pre_signed_mints_should_work` and `pre_signed_attributes_should_work` in `substrate/frame/nfts/src/tests.rs` exercise the deadline-expiry guard but do not (and cannot) exercise a cancellation path, since none exists.

		/// Cancel an atomic swap. Only possible after the originally set duration has passed.
		///
		/// The dispatch origin for this call must be _Signed_.
		///
		/// - `target`: Target of the original atomic swap.
		/// - `hashed_proof`: Hashed proof of the original atomic swap.
		#[pallet::call_index(2)]
		#[pallet::weight(T::DbWeight::get().reads_writes(1, 1).ref_time().saturating_add(40_000_000))]
		pub fn cancel_swap(
			origin: OriginFor<T>,
			target: T::AccountId,
			hashed_proof: HashedProof,
		) -> DispatchResult {
			let source = ensure_signed(origin)?;

			let swap = PendingSwaps::<T>::get(&target, hashed_proof).ok_or(Error::<T>::NotExist)?;
			ensure!(swap.source == source, Error::<T>::SourceMismatch);
			ensure!(
				frame_system::Pallet::<T>::block_number() >= swap.end_block,
				Error::<T>::DurationNotPassed,
			);

			swap.action.cancel(&swap.source);
			PendingSwaps::<T>::remove(&target, hashed_proof);

			Self::deposit_event(Event::SwapCancelled { account: target, proof: hashed_proof });

			Ok(())
		}

		///
		/// This is the recommended function for production use. It:

			v: u8,

				v,
				r,
				s,
