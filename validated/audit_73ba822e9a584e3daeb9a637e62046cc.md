### Title
Signature verification key selection (`repository.owner.login`) is decoupled from repository lookup key (`repository.full_name`), allowing cross-tenant stack mutation - ([File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's `webhook_secret` to validate the HMAC signature against using `payload.dig('repository','owner','login')`, while `Handler#repository_name`/`Handler#stacks` look up the target `Stack` records using `payload.dig('repository','full_name')` from the very same attacker-supplied JSON body. Nothing checks that `full_name` is namespaced under the same owner login used to select the secret, so a payload signed with `OrgA`'s secret can name `OrgB`'s repository as the target of the webhook, causing `PushHandler#process` to call `stack.sync_github(expected_head_sha: params.after)` on `OrgB`'s real stacks.

### Finding Description
The broken binding: `payload.dig('repository','owner','login')` (used in `WebhooksController#verify_signature`/`repository_owner`) == `payload.dig('repository','full_name').split('/').first` (used in `Handler#repository_name`) is assumed but never enforced.

Code path:
- `WebhooksController#verify_signature` picks the `GitHubApp` (and thus the `webhook_secret`) via `Shipit.github(organization: repository_owner)`, where `repository_owner` comes straight from the untrusted request body: [1](#0-0) [2](#0-1) 
- Signature validation is a pure HMAC of the raw body against that secret, with no binding to any other field of the payload: [3](#0-2) 
- Once verification passes, `PushHandler#process` resolves target stacks via `Handler#stacks`/`Handler#repository_name`, which reads `payload.dig('repository','full_name')` independently, with no cross-check against `repository.owner.login`: [4](#0-3) [5](#0-4) 
- In multi-org config mode, each organization has its own distinct `webhook_secret` (`github_app_config`); in single-app mode, all organizations share one secret regardless of the `organization:` argument passed in: [6](#0-5) 

Exploit flow: an attacker who controls (or is the tenant admin for) `OrgA`'s GitHub App/webhook integration crafts a raw JSON body with `repository.owner.login = "OrgA"` (so `verify_signature` selects `OrgA`'s secret and the HMAC validates) but `repository.full_name = "OrgB/private-victim-repo"` and an attacker-chosen `after` SHA, then POSTs it (with a correctly computed `X-Hub-Signature` for `OrgA`'s secret) directly to `/webhooks`. `drop_unhandled_event`/`check_if_ping` do not inspect this field, `verify_signature` only authenticates the raw bytes against `OrgA`'s key, and `Handler#repository_name` blindly trusts `full_name` to resolve `Repository.from_github_repo_name`, returning `OrgB`'s real `Stack` records to `PushHandler#process`, which then calls `stack.sync_github(expected_head_sha: params.after)` on `OrgB`'s stacks.

None of the existing guards catch this: `verify_signature` only proves "this body was signed with the secret selected by `owner.login`", not "this body's `full_name` belongs to that owner"; `ExplicitParameters` schema for `PushHandler` only requires `:ref` and `:after`, not repository consistency; there is no model validation in `Repository`/`Stack` that checks the requesting owner against the stack's actual owner.

### Impact Explanation
A tenant/org boundary is broken: a payload authenticated for `OrgA` can trigger `stack.sync_github` (mutating HEAD sync state) on `OrgB`'s stacks, which the requester never authenticated for and does not own. This matches the explicitly listed Critical category "a payload for one repository mutating another's stack, commit, task or team." The attack is repeatable against any organization whose full name the attacker can guess/enumerate, and is not limited to `push` — every subclass of `Handler` (status, check_suite, pull_request handlers, etc.) inherits the same `repository_name`/`stacks` resolution and is equally exposed, widening the blast radius to any tenant on a shared Shipit instance.

### Likelihood Explanation
Exploitability strictly requires the attacker to possess (or be able to produce) a valid signature computable from `OrgA`'s `webhook_secret` — i.e., they must control or know the secret registered for `OrgA`'s GitHub App/webhook integration in Shipit's config. In a single-tenant deployment this is a Shipit operator-only secret and out of reach for an ordinary unprivileged GitHub user (repo pusher/PR opener), consistent with the audit's attacker model excluding possession of `webhook_secret`. The scenario becomes realistic specifically in multi-tenant Shipit deployments where distinct customer organizations each configure and therefore know their own organization's `webhook_secret` (self-service SaaS style) — there, an org owner of `OrgA` is "unprivileged" with respect to `OrgB` but does legitimately hold `OrgA`'s own secret, which is exactly the premise given in the question. Given that secret, forging the cross-owner payload costs nothing more than one crafted HTTP POST with a correct HMAC, and is fully repeatable against arbitrary target repositories/stacks.

### Recommendation
Bind the signature-selection identity to the resource being mutated: after signature verification succeeds using the secret selected by `repository.owner.login`, require that `Handler#repository_name`'s owner segment (`full_name.split('/').first`) case-insensitively equals the `repository.owner.login`/`organization` used to select that secret, and reject (422) on mismatch. This check should live either in `WebhooksController` before dispatching to handlers, or centrally in `Handler#initialize`/`Handler#stacks`, so every current and future handler subclass is protected.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "push payload signed for OrgA cannot mutate OrgB's stack via mismatched full_name" do
  org_a_secret = "org-a-secret"
  org_b_stack  = shipit_stacks(:shipit) # belongs to real org "OrgB" repo, e.g. "OrgB/private-victim-repo"

  Shipit.stubs(:github).with(organization: "OrgA").returns(
    Shipit::GitHubApp.new("OrgA", webhook_secret: org_a_secret)
  )

  forged_payload = JSON.parse(payload(:push_master))
  forged_payload["repository"]["owner"]["login"] = "OrgA"          # selects OrgA's secret
  forged_payload["repository"]["full_name"]      = "OrgB/private-victim-repo" # targets OrgB's real stack
  forged_payload["after"] = "attacker_chosen_sha"
  body = forged_payload.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", org_a_secret, body)

  @request.headers['X-Github-Event']   = 'push'
  @request.headers['X-Hub-Signature']  = signature

  # Binding check BEFORE fix: verify_signature succeeds (signed with OrgA's secret)
  # but Handler#repository_name resolves OrgB's real stack.
  assert_equal "OrgA", forged_payload.dig("repository", "owner", "login")
  assert_equal "OrgB/private-victim-repo", forged_payload.dig("repository", "full_name")

  org_b_stack.expects(:sync_github).with(expected_head_sha: "attacker_chosen_sha")

  post :create, body:, as: :json
  assert_response :ok # demonstrates OrgB's stack was mutated by an OrgA-signed payload
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
