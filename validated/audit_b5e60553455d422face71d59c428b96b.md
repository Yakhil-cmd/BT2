### Title
Unauthorized creation of shared addresses via unsolicited `new_shared_address` device messages - (File: wallet_defined_by_addresses.js)

### Summary
The Mattermost CVE describes a failure to restrict channel creation, letting an unprivileged remote party create arbitrary channels once shared channels are enabled. The analogous ocore flow is the wallet-messaging handler for `new_shared_address`, which lets any already-paired device unilaterally register a "shared address" (multisig-like resource) in the local wallet database, bypassing the deliberate user-confirmation workflow that exists for locally-initiated shared address creation.

### Finding Description
When the wallet receives a `new_shared_address` message from a paired device, it is routed straight to `walletDefinedByAddresses.handleNewSharedAddress` without any user confirmation step: [1](#0-0) 

`handleNewSharedAddress` only checks that the definition hashes to the given address, that the signer list is structurally consistent with the definition, and that the definition is *syntactically* valid via `Definition.validateDefinition` — it never verifies that the victim's own address only appears behind a conjunction (`and`/`r of set`) that actually requires the victim's cooperation to spend: [2](#0-1) 

The only "membership" check performed is `determineIfIncludesMeAndRewriteDeviceAddress`, which merely confirms that one of the signer addresses in the attacker-supplied definition matches one of the victim's own known addresses (`my_addresses` or `shared_addresses`) — it does not validate the *logical role* that address plays in the definition: [3](#0-2) 

Once these checks pass, `addNewSharedAddress` immediately inserts the row into `shared_addresses`/`shared_address_signing_paths`, fires `new_address` events, and (in light mode) starts watching the address — with no dialog, confirmation, or opt-in from the user, unlike the legitimate `create_new_shared_address` path which explicitly emits an event "to trigger a confirmation dialog" before any address is created: [4](#0-3) [5](#0-4) 

Because `validateAddressDefinition` only checks structural validity (with `bAllowUnresolvedInnerDefinitions: true`) and not the semantic relationship between branches, an attacker can submit a definition such as `["or", [["address", VICTIM_ADDR], ["address", ATTACKER_ADDR]]]`. This passes every check — the victim's real address is present, so `determineIfIncludesMeAndRewriteDeviceAddress` succeeds — yet the `or` operator lets the attacker's branch spend unilaterally, without any cooperation from the victim: [6](#0-5) 

The wallet then silently registers and watches this address as a legitimate "shared address" involving the user, exactly mirroring the Mattermost pattern of unauthorized/unrestricted creation of a shared collaborative resource by a remote peer.

### Impact Explanation
A malicious paired device (correspondent) can push forged `new_shared_address` definitions that make the victim's wallet track and display an address that *appears* to be a joint/multisig address involving the victim, while actually allowing the attacker to spend funds sent there unilaterally (via an `or`/weighted-`or` branch). If the victim or any third party is induced to send funds to this address believing it to be a legitimately co-signed/secured address, the attacker can independently drain those funds — a concrete unauthorized-spending / fund-loss scenario, matching the required "unauthorized spending" impact bar.

### Likelihood Explanation
Exploitation requires only that the attacker be paired with the victim's device (a normal, low-barrier action available to any correspondent, including one paired via a leaked/shared pairing code or lured through a legitimate pairing flow) and knowledge of one of the victim's real addresses (routinely exposed during normal wallet interactions/payment requests). No hub, node, or protocol-level compromise is needed — a single crafted device message is sufficient, making this readily reachable by an attacker who is already a correspondent.

### Recommendation
- Require explicit user confirmation (mirroring the `create_new_shared_address` UI dialog flow) before persisting any incoming `new_shared_address` message to the `shared_addresses` table.
- In `determineIfIncludesMeAndRewriteDeviceAddress`/`validateAddressDefinition`, additionally verify that the victim's own address(es) cannot be bypassed by an alternate `or`/`r of set` branch that does not require the victim's signature, or otherwise surface the full spending conditions to the user before acceptance.
- Track the provenance of unsolicited `new_shared_address` offers and rate-limit/flag ones not preceded by a corresponding `create_new_shared_address` handshake.

### Proof of Concept
1. Pair with the victim's device (or use an existing pairing).
2. Learn one of the victim's real wallet addresses, `VICTIM_ADDR` (e.g., from a payment request).
3. Craft `arrDefinition = ["or", [["address", "VICTIM_ADDR"], ["address", "ATTACKER_ADDR"]]]`, compute `address = objectHash.getChash160(arrDefinition)`.
4. Send a `new_shared_address` device message: `{address, definition: arrDefinition, signers: {"r.0": {address: "VICTIM_ADDR"}, "r.1": {address: "ATTACKER_ADDR", device_address: ATTACKER_DEVICE}}}` per the handler in [2](#0-1) .
5. The victim's wallet accepts and stores this as a shared address (`addNewSharedAddress`), begins watching it, and may display it in the UI as an address involving the user.
6. Any funds later sent to this address can be unilaterally spent by the attacker via the `ATTACKER_ADDR` branch of the `or` definition, without the victim's cooperation.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
