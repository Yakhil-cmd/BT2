### Title
Stack-scoped API token can read CI/deploy status of any stack via CCMenu endpoint - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::BaseController` enforces per-token stack scoping through `stacks`/`stack`, but `Shipit::Api::CCMenuController` overrides `#stack` to bypass that scoping entirely, letting any authenticated `ApiClient` — even one explicitly restricted to a single stack — read deploy/CI status for every stack in the installation.

### Finding Description
`BaseController` defines the trust binding between an `ApiClient` token and the stacks it is allowed to touch: [1](#0-0) 

`stacks` is restricted to `Stack.where(id: current_api_client.stack_id)` whenever `current_api_client.stack_id?` is true, and every other API controller (`DeploysController`, `StacksController`, etc.) resolves the target stack through this scoped `stacks.from_param!`.

`CCMenuController`, however, redefines `#stack` to bypass the scope completely: [2](#0-1) 

`require_permission :read, :stack` only checks that the token's generic `permissions` array contains `"read:stack"` — `ApiClient#check_permissions!` never considers `stack_id` at all: [3](#0-2) 

The equality that should hold for every API endpoint is:
`stack a token authorises (current_api_client.stack_id) == stack the request actually touches (stack)`

For `CCMenuController#show`, this becomes `Stack.from_param!(params[:stack_id])` — an attacker-controlled `stack_id` route parameter — completely decoupled from `current_api_client.stack_id`. This mirrors the GNARK `reduceWithMaxBits` bug class: the equation the code is *supposed* to check (`stack_id == token.stack_id`) is simply never evaluated, even though the analogous check exists and is exercised elsewhere in the same controller family (`app/controllers/shipit/api/base_controller.rb:74-80`, covered by the test `"an api client scoped to a stack will only see that one stack"`).

### Impact Explanation
Any valid `ApiClient` token — regardless of whether it is scoped to a single stack — can be used to fetch the CCMenu XML for an arbitrary stack (`GET /api/stacks/:stack_id/ccmenu`), exposing:
- last deploy status/label/time (`lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`)
- lock state
- deploy/rollback history (`stack.deploys_and_rollbacks.last`)

for stacks the token was never authorized to see. This is an unauthenticated (relative to that stack) read of stack state and deploy output belonging to other repositories/environments, matching the "High" impact bucket of unauthenticated read of stack state/task streams/deploy output. Because the scope check is bypassed rather than merely weak, this also breaks multi-tenant isolation between teams that each hold a stack-scoped token.

### Likelihood Explanation
Any party in possession of a valid, even narrowly-scoped, `ApiClient` authentication token can immediately query any other stack's CCMenu endpoint just by changing the `stack_id` path segment — no special privileges, race conditions, or additional secrets are required. The bypass is unconditional and deterministic.

### Recommendation
Remove the `#stack` override in `CCMenuController` (or reimplement it via the inherited `stacks.from_param!`) so that stack resolution is always scoped by `current_api_client.stack_id` when the token is scope-restricted, consistent with every other `Api::BaseController` subclass.

### Proof of Concept
1. Obtain (or be issued) a token for `ApiClient` A scoped to `stack_id = 1` (`read:stack` permission only).
2. Call `GET /api/stacks/*stack_id/ccmenu?token=<A's token>` with `stack_id` pointing to `stack 2` (a stack A is not authorized for).
3. `CCMenuController#stack` resolves via `Stack.from_param!(params[:stack_id])` (app/controllers/shipit/api/ccmenu_controller.rb:29-31), ignoring `current_api_client.stack_id`; `require_permission!` only checks the generic `read:stack` string (app/models/shipit/api_client.rb:38-45), which A possesses.
4. The response renders `stack 2`'s deploy/rollback status and lock state, even though token A is scoped only to `stack 1` — confirming the token-to-stack binding is broken.
