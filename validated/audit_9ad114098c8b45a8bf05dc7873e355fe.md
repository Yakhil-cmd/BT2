### Title
`pr view` writes attacker-controlled PR body/comments directly to `IOStreams.Out` (which feeds the pager), bypassing the `ContentOut` ANSI sanitizer - (File: pkg/iostreams/iostreams.go)

### Summary
`System()` wires up two separate output paths on `IOStreams`: the raw `Out` writer (stdout, or the pager's stdin once `StartPager` swaps it in) and a sanitizing `ContentOut` writer that wraps `Out` with `asciisanitizer.Sanitizer` when `sanitizeContent` is true. The sanitization is opt-in per call site rather than enforced globally, and `pkg/cmd/pr/view/view.go` calls `StartPager()` but never routes the remote PR title/body/comments through `ContentOut`, so attacker-authored escape sequences reach the pager (or terminal) unsanitized.

### Finding Description
`System()` builds `io.Out` as the raw stdout writer and separately constructs `io.ContentOut` via `newContentWriter(io.Out, io.sanitizeContent)` [1](#0-0) . The sanitizer is only applied to whatever is written to `ContentOut`; anything written directly to `Out` — including after `StartPager` has repointed `Out` at the pager's stdin pipe — passes through completely unmodified [2](#0-1) .

Grepping for `ContentOut` usage across command packages shows that most `view`/`list` commands under `pkg/cmd/*` reference it (issue/view, gist/view, discussion/view, release/view, etc.), but `pkg/cmd/pr/view/view.go` has zero references to `ContentOut` despite calling `StartPager()`. This means the PR title, body, and comment text — all attacker-controlled fields from the GitHub API — are printed through the unsanitized `Out` writer instead of the sanitized `ContentOut` writer that exists specifically to strip dangerous ANSI/control sequences from untrusted remote content before they reach a terminal or external pager.

Because sanitization in this design is applied only when a command explicitly writes to `ContentOut` (an opt-in per-call-site mechanism, not enforced at the `System()`/pager boundary), any command that forgets to route external content through `ContentOut` — as `pr view` appears to — leaks raw escape sequences into whatever consumes `Out`, including a user-configured `$PAGER` (e.g., `less`, `most`) whose own escape/keystroke handling can differ from gh's assumptions (e.g., enabling `less`'s `-r`/raw mode acting on OSC/DCS sequences that gh's sanitizer would otherwise strip).

### Impact Explanation
An attacker who controls a PR title, body, or comment can embed terminal escape sequences (e.g., OSC 8 hyperlink spoofing, cursor movement to overwrite prior trusted output, or terminal title/clipboard manipulation sequences) that are inert if sanitized but active once handed raw to the pager. This can spoof terminal output or a confirmation prompt shown after `gh pr view` output, aligning with the "High - Terminal output/prompt spoofing" impact class referenced in the question.

### Likelihood Explanation
Fully unprivileged and remotely triggerable: any GitHub user can open a PR or leave a comment with crafted content, and the victim only needs to run `gh pr view <PR>` in a TTY with a pager configured (default on most systems, e.g., `less`). No special permissions, MITM, or social engineering beyond authoring public content is required, making this easily repeatable.

### Recommendation
Route all attacker-controlled/remote text rendered by `pr view` (title, body, comments, review bodies, check output) through `IOStreams.ContentOut` instead of `IOStreams.Out`, consistent with the pattern already used by `issue/view`, `gist/view`, `discussion/view`, etc. Alternatively, make sanitization structural rather than opt-in: have `StartPager()` (or `System()`) wrap the pager's stdin pipe itself with the `asciisanitizer` transform so all bytes destined for the pager are sanitized regardless of which writer a command author chooses, removing the per-call-site foot-gun.

### Proof of Concept

```go
func TestPRView_PagerReceivesUnsanitizedBytes(t *testing.T) {
    ios, _, stdout, _ := iostreams.Test()
    ios.SetStdoutTTY(true)
    // stub pager: capture what's written instead of Out

    body := "safe text\x1b]8;;http://evil\x07CLICK\x1b]8;;\x07" // OSC 8 escape
    // mock PR with Body: body, run pr view command
    // ...

    got := pagerBuf.String() // or stdout.String() if pager stubbed to passthrough
    if strings.Contains(got, "\x1b]8;;") {
        t.Fatalf("expected OSC 8 escape sequence to be stripped before reaching pager, got: %q", got)
    }
}
```
Expected (failing) assertion: the raw OSC 8 escape survives in the bytes sent to the pager because `pr view` writes via `opts.IO.Out` (pager-bound) rather than `opts.IO.ContentOut` (sanitized), demonstrating the bypass described above.

```go
// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}
```
