### Title
Bad-debt cleanup leaves residual supply shares that can drain future deposits - (File: contracts/pool/src/interest.rs)

### Summary
The pool’s bad-debt socialization writes down the supply index, but clamps the result upward to `SUPPLY_INDEX_FLOOR_RAW` after a complete wipeout. Because the old supply shares are not burned, they retain a positive withdrawal claim that can consume tokens deposited later. An unprivileged caller can trigger this through the controller’s bad-debt cleanup flow, causing a solvent-looking market to become under-collateralized and allowing the holder of the residual shares to steal a later supplier’s deposit.

### Finding Description
Bad-debt cleanup invokes the pool’s seize operation, which computes the debt value and passes it to `apply_bad_debt_to_supply_index` before burning the debt shares. [1](#0-0) 

The write-down caps the socialized amount at the total supplied value, computes the remaining backing ratio, and applies that ratio to the old supply index. [2](#0-1) 

When the write-down exhausts all supplied value, `reduction_factor` is zero and the mathematically correct resulting index is zero. The code then applies `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))`, restoring a positive index and therefore resurrecting claims represented by the old shares. [3](#0-2) 

The stranded position’s floored value remains positive after the wipeout, while pool cash is initially zero. [4](#0-3) 

After another user deposits, withdrawal resolution still pays the old shares from the new cash because the withdrawal path checks only available reserves before burning and debiting them. [5](#0-4) 

The repository’s own test demonstrates the full sequence: residual shares survive the wipeout, a fresh deposit makes the market owe more than its cash, and the old position withdraws exactly the new deposit. [6](#0-5) 

### Impact Explanation
The holder of shares surviving a complete bad-debt write-down can withdraw newly deposited tokens even though the socialization was intended to erase the old claim. This is theft of user funds and creates a permanent protocol insolvency: supplier claims exceed `cash + outstanding debt` once the residual claim consumes the new deposit. [7](#0-6) 

The issue is not merely a failed transaction or temporary denial of service. The accounting state remains inconsistent, and the first withdrawal from a residual position can remove real token funds contributed by a later depositor. [8](#0-7) 

### Likelihood Explanation
The vulnerable sequence only requires normal market activity: an existing supplier, debt that becomes bad debt, an unprivileged `clean_bad_debt(account)` call that submits the borrow-side seize entry, a later supply deposit, and a withdrawal by the holder of the residual shares. 

Any sufficiently large bad-debt event that exhausts the supplied value reaches the index floor. The floor is unconditional, so the survivor does not need privileged access, oracle manipulation, token-specific behavior, or a malformed parameter to retain the residual claim. [9](#0-8) 

A full wipeout is less common than a partial write-down, but the code explicitly handles and tests that boundary condition. [10](#0-9) 

### Recommendation
Do not clamp the post-write-down supply index above a value that recreates claims after complete socialization. If `remaining` is zero, either set the supply index to zero and permanently treat the preexisting shares as unclaimable, or burn/otherwise mark the preexisting supply shares before admitting new deposits. Add a solvency invariant that `supplied * supply_index` does not exceed cash plus outstanding debt after bad-debt cleanup, and add an end-to-end regression covering cleanup followed by a fresh deposit and residual-share withdrawal. [9](#0-8) 

### Proof of Concept
The repository’s raw-cache regression sequence demonstrates the exploit mechanics:

```rust
let alice_scaled_raw = 1_000 * RAY;
let borrowed_scaled_raw = 1_000 * RAY;

let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
apply_bad_debt_to_supply_index(&mut cache, bad_debt);
cache.burn_debt(borrow_scaled);

assert_eq!(cache.supply_index().raw(), SUPPLY_INDEX_FLOOR_RAW);
let alice_stranded = cache.unscale_supply_floor(alice_scaled);
assert!(alice_stranded > 0);

let deposit = alice_stranded;
let bob_scaled = cache.calculate_scaled_supply(deposit);
cache.mint_supply(bob_scaled);
cache.credit_cash(deposit);

let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
cache.require_reserves(gross);
cache.burn_supply(burn);
cache.debit_cash(gross);

assert_eq!(gross, deposit);
assert!(cache.cash() < cache.unscale_supply_floor(bob_scaled));
```

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

#[test]
fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );
```

/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
