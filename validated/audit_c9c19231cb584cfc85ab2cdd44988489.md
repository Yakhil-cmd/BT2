### Title
Unsanitized comment author name and body allow terminal escape/bidi injection in `gh pr view --comments` / `gh issue view --comments` - ([File: pkg/cmd/pr/shared/comments.go])

### Summary
`formatComment` in `pkg/cmd/pr/shared/comments.go` writes `comment.AuthorLogin()`, `comment.Association()`, and the markdown-rendered `comment.Content()` directly to the terminal buffer without passing them through any of the ANSI/control-character sanitization mechanisms that this codebase otherwise applies to attacker-controlled content (`pkg/iostreams/untrusted.go`'s `Untrusted` type, `iostreams.ContainsEscapeSequence`/`CopyGuardedContent`, and the asciisanitizer-based writers used by `gh api`, `gh gist view`, `gh run view --log`, `gh pr diff`, and `gh repo read-file`/`gh skills list`). Both fields originate from GitHub API data an unprivileged user fully controls (comment body, and GitHub profile display name).

### Finding Description
`CommentList` calls `formatComment` for every comment/review on a PR/issue [1](#0-0) . `formatComment` builds the header by directly interpolating `comment.AuthorLogin()` and `comment.Association()` into the color-scheme-wrapped string, then renders `comment.Content()` through `markdown.Render` and writes the result with `fmt.Fprint`: [2](#0-1) 

`AuthorLogin()` returns `c.Author.DisplayName()` [3](#0-2) , and the underlying GraphQL query fetches both `login` and the free-form profile `name` field for the author [4](#0-3) . Unlike a GitHub `login` (which is restricted to a safe character set), a user's profile display `name` is essentially free-form text and can contain Unicode bidi-override characters (e.g. U+202E) or other unusual code points. `Content()` returns `comment.Body` verbatim [5](#0-4) , and an issue/PR comment body can contain any bytes a user submits via the API, including literal ESC (0x1B) control sequences embedded in text/code spans that `markdown.Render` (a thin wrapper around glamour's markdown-to-ANSI renderer) does not scrub [6](#0-5) .

This project has an established pattern for exactly this risk class — see `pkg/iostreams/untrusted.go`'s `Untrusted` wrapper that auto-sanitizes any `fmt` print path [7](#0-6) , and the escape-sequence guards used in `gh api`, `gh gist view`, `gh run view --log`, and `gh pr diff` [8](#0-7) [9](#0-8) . None of this sanitization is applied in `formatComment`/`formatRawComment`/`formatHiddenComment`, so raw comment author/body text flows straight to the terminal.

### Impact Explanation
An attacker who can post a PR or issue comment (or set their own GitHub profile display name) can inject raw ANSI/CSI/OSC sequences or Unicode bidi-control characters into text rendered by `gh pr view --comments` / `gh issue view --comments`. This enables terminal-output spoofing: faking a different author name/association label, overwriting prior terminal lines, setting the terminal title, or visually reordering text via bidi overrides to disguise malicious content as benign (or vice versa) — a terminal/UI-spoofing impact consistent with GitHub's "spoofing/UI misrepresentation via terminal output" bounty class, not remote code execution.

### Likelihood Explanation
Fully attacker-reachable with no privileges: any GitHub user can leave a comment on a public PR/issue or set an arbitrary profile display name, then get the victim to run the routine `gh pr view --comments` / `gh issue view --comments` command on that PR. No preconditions besides the victim viewing the attacker's comment thread.

### Recommendation
Sanitize `AuthorLogin()`, `Association()`, and `Content()` before composing terminal output in `formatComment`/`formatRawComment`/`formatHiddenComment` — e.g., wrap them in `iostreams.Untrusted` (or run them through the `asciisanitizer.Sanitizer` transform already used elsewhere) before writing to `strings.Builder`/terminal, and strip/escape bidi-control code points as well.

### Proof of Concept
```go
// pkg/cmd/pr/shared/comments_test.go
func TestFormatComment_SanitizesHostileAuthorAndBody(t *testing.T) {
    io, _, out, _ := iostreams.Test()
    io.SetStdoutTTY(true)
    c := fakeComment{
        author:  "evil\u202Eattacker", // U+202E right-to-left override
        content: "hello\x1b[31mHIJACKED\x1b[0m",
    }
    _, err := formatComment(io, c, false)
    require.NoError(t, err)
    assert.NotContains(t, out.String(), "\x1b")
    assert.NotContains(t, out.String(), "\u202E")
}
```
Expected (current) result: assertions fail — raw ESC bytes and the bidi override character appear verbatim in `out.String()`, confirming the injection is not sanitized.

```go
// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```

```go
// ContainsEscapeSequence reports whether b contains an ANSI escape byte (0x1B),
```
