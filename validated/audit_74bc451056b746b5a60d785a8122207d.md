### Title
Below-threshold signer manager can corrupt the global STX-only reward accumulator via bond co-claim, causing stakers to earn sBTC rewards for cycles their signer never participated in - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`claim-rewards` in `pox-5.clar` settles both a signer's bond rewards and its STX-only reward state in the same call. When a signer manager that is *not* a member of the signer set for a given reward cycle (its staked shares for that cycle are `u0`) still has a bond to claim, the shared `settle-rewards` path advances that signer's `signer-rewards-per-token-for-cycle` snapshot even though it earned nothing that cycle. Because per-staker earned amounts are computed as the *difference* between the global/staker-settled snapshot and the signer's snapshot, advancing the signer's snapshot past the window it never contributed to falsely credits its STX-only stakers with sBTC rewards they never earned, breaking the equality between sBTC actually deposited/earned and sBTC claimable.

### Finding Description
`claim-rewards` computes `total-rewards` as the sum of the signer's STX-only earned rewards plus any bond rewards, and pays the total sBTC to the caller in one `as-contract?`/`transfer` step: [1](#0-0) 

The bond-claim path shares the same `settle-rewards` accounting routine used for STX-only rewards. The repository's own property/unit test demonstrates that when a signer manager is below the STX-only participation threshold for a cycle (its `signer-shares-staked-for-cycle` is `u0`, i.e. it was never a set member for that cycle) but still holds a bond that pays out in that cycle, calling `claim-rewards` for the bond causes `settle-rewards` to run on the signer's STX-only cycle-1 state with `shares = 0`. This corrupts `signer-rewards-per-token-for-cycle`, advancing it as though the signer had earned rewards: [2](#0-1) 

The test setup explicitly arranges: signer1 is below `SIGNER_SET_MIN_USTX` for cycle 1 (`isSignerInCycle({signer: signer1, cycle: 1n})` is `false`), yet has a bond (bob's) that resolves in that cycle, and a STX-only staker (alice) delegated to signer1: [3](#0-2) 

Before the bond claim, alice's earned STX-only rewards for cycle 1 are correctly `0`. After `testSigner.claimRewards([0n], 1n)` (the bond-only claim) runs, the test asserts alice's earned rewards should *still* be `0`, but the comment states this assertion "Fails on the unfixed code because the snapshot was advanced past a window signer1 didn't earn in": [4](#0-3) 

This means the shared `settle-rewards` routine invoked from `claim-rewards` does not gate the signer's STX-only rewards-per-token snapshot update on the signer actually being a participating member of the reward set for that cycle — it advances the snapshot as a side effect of any claim call (even a pure bond claim) for that signer/cycle pair.

### Impact Explanation
This breaks the equality between sBTC actually earned/deposited into the reward pool and sBTC claimable by stakers: a staker (alice) becomes entitled to withdraw sBTC for a reward cycle in which her signer manager was never a set member and therefore never earned or was allocated any STX-only rewards. This is a double-counting/unbacked-payout defect in the reward-accounting core of `pox-5.clar`'s `claim-rewards`/`settle-rewards` path, allowing sBTC to be paid out that was never earned by that signer-staker pairing, directly draining the shared reward pool at the expense of legitimately-earning participants.

### Likelihood Explanation
Triggering the bug requires no special privilege — any signer manager below the STX-only participation threshold that also has an active bond paying out in the same cycle can trigger it merely by calling the normal, permissionless `claim-rewards` entry point with its bond index. The scenario (a signer under threshold via STX-only stake but crossing the minimum only through a bond's uSTX) is a plausible, easily-constructible configuration, not a contrived edge case, as evidenced by the repository authors having written a dedicated regression test for it.

### Recommendation
In `settle-rewards` (and the `claim-rewards` path that invokes it for the STX-only leg), only advance/settle a signer's `signer-rewards-per-token-for-cycle` snapshot when the signer's `signer-shares-staked-for-cycle` for that reward cycle is greater than zero (i.e., the signer was actually a participating set member for that cycle). Bond-only claims for a signer that was not a set member in a given cycle must not touch that signer's STX-only reward snapshot for that cycle.

### Proof of Concept
The repository's existing test `below-threshold signer leaks phantom stx-only rewards via bond co-claim` in `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts` (lines 6064-6157) is a concrete, runnable PoC: it sets up signer1 below the STX-only threshold with a bond and a delegated STX-only staker (alice), funds rewards, calls `calculateRewards`, then calls `claimRewards([0n], 1n)` for the bond only, and asserts `alice`'s STX-only earned rewards for cycle 1 remain `0` — an assertion the test comments state fails on the unfixed contract because the bond claim corrupts the STX-only snapshot. [5](#0-4)

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
