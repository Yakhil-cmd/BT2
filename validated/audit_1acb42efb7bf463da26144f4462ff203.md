### Title
Open Redirect via Unvalidated `omniauth.origin` in OAuth Callback Enables Forced-OAuth-Completion to Attacker-Controlled Destination - ([File: app/controllers/shipit/github_authentication_controller.rb])

### Summary
`GithubAuthenticationController#callback` sets `return_url = request.env['omniauth.origin'] || root_path` and then calls `redirect_to(return_url)` with no host/path allowlist check [1](#0-0) . Because the OAuth flow's `origin` param is attacker-controllable (it is set on the initial `/github/auth/github?origin=...` request and echoed back verbatim through `omniauth.origin`), an attacker can craft a link to Shipit's own OAuth entry point that, after the victim completes a legitimate GitHub login, causes the victim's browser to be redirected to an arbitrary external URL immediately after `session[:user_id]`/`session[:authenticated]` are set.

### Finding Description
The claimed binding is: `redirect destination after callback == a Shipit-controlled origin`. Tracing the code: `force_github_authentication` in `app/controllers/concerns/shipit/authentication.rb` redirects unauthenticated users to `github_authentication_path(origin: request.original_url)` [2](#0-1) , which is normally same-host, but nothing stops an attacker from directly sending the victim to `/github/auth/github?origin=https://attacker.example/`. OmniAuth stores this raw `origin` param and replays it as `request.env['omniauth.origin']` on callback. `GithubAuthenticationController#callback` reads that value with no validation, sets the session for whichever GitHub account completes the OAuth handshake (the victim's real identity, via `sign_in_github`), and then performs `redirect_to(return_url)` unfiltered [3](#0-2) . No allowlist, `request.base_url` comparison, or `local_redirect?`-style check exists anywhere in this controller. The only test covering this action never sets `omniauth.origin` and only asserts on `session[:authenticated]` [4](#0-3) , so the divergence is untested and unguarded.

Exploit flow: attacker sends victim a link to the Shipit host itself (e.g., `https://shipit.example.com/github/auth/github?origin=https://attacker.example/`). Victim, trusting the Shipit domain, clicks it, is routed through the real GitHub OAuth consent/redirect (or auto-approved if already authorized), and lands back on `/github/auth/github/callback`. Shipit sets `session[:user_id]`/`session[:authenticated]` for the victim's true identity and then issues `redirect_to('https://attacker.example/')`, sending the now-authenticated victim's browser off Shipit's origin under attacker control.

### Impact Explanation
This is an open redirect chained onto a legitimate authentication completion: the attacker does not gain the victim's session cookie, `github_access_token`, or any token in the URL (none is appended by this code), but they do control the exact moment and destination the victim's browser is sent to immediately after login, matching the "forced OAuth completion" pattern explicitly called out as a High-impact category in this engine's authentication flow. It is repeatable against any victim who clicks such a crafted link and does not require any Shipit or GitHub secret, team membership, or elevated privilege from the attacker.

### Likelihood Explanation
Preconditions are low: GitHub OAuth (`Shipit.github.oauth?`) must be enabled, which is the default expectation for a Shipit deployment, and the attacker only needs the victim to click a link pointing at the Shipit host's own `/github/auth/github` path with a crafted `origin` query parameter. No secrets, team membership, or prior session are required from the attacker.

### Recommendation
Validate `return_url` before redirecting: only allow same-host relative paths (e.g., require `return_url.start_with?('/')` and not `//`, or explicitly compare `URI.parse(return_url).host` against `Shipit.host`/`request.host`) and fall back to `root_path` otherwise, in `GithubAuthenticationController#callback`.

### Proof of Concept
In `test/controllers/github_authentication_controller_test.rb` add:
```ruby
test ":callback does not redirect to an external origin" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(
      raw_info: OmniAuth::AuthHash.new(
        id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
        login: 'shipit-user', avatar_url: 'https://example.com',
        api_url: 'https://github.com/api/v3/users/shipit-user'
      )
    )
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://attacker.example/'

  get :callback

  assert session[:authenticated], "victim session should be authenticated"
  # Binding under test: redirect destination must remain a Shipit-controlled origin
  refute_equal 'https://attacker.example/', @response.location
  assert_redirected_to root_path
end
```
Running this against the current code shows `@response.location == 'https://attacker.example/'`, proving the destination diverges from a Shipit-controlled origin after a real authenticated callback.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end
```

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
