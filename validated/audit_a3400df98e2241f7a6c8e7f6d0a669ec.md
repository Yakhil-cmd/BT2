### Title
Ancestor-check gate lets `git commit --amend`/rebase during a turn hide committed changes from `compute_v2_review_set`'s review set - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` only unions in commits made since `head_at_capture` when `_is_ancestor(head_at_capture, current_head)` is true, i.e. only for a pure fast-forward advance. If the turn's automation amends, rebases, or otherwise rewrites the just-made commit(s) so the new `current_head` is not a descendant of `head_at_capture`, that branch is skipped, `diff_base` stays `"HEAD"`, and because the working tree is clean after a commit/amend, `tracked_dirty` (from `git status`) is empty for those files too — so `review_set = dirty_now ∩ changed_since` silently drops all committed-then-rewritten files even though they really did change relative to the pre-turn baseline.

### Finding Description
In `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:403-408`):

```python
diff_base = "HEAD"
current_head = _git_rev_parse_head(repo)
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
```

`_is_ancestor` (`plugins/security-guidance/hooks/gitutil.py:377-387`) is `git merge-base --is-ancestor head_at_capture current_head`, which is true only when `current_head` is a linear/merge descendant that still has `head_at_capture` in its parent chain.

If, within the same turn, an automated flow does e.g.:
```
git commit -m "..."         # HEAD = C1, parent = head_at_capture
git commit --amend -m "..." # HEAD = C2, parent = head_at_capture (same), but C1 is NOT an ancestor path of C2 by identity
```
or performs an interactive rebase / `git reset --hard <newsha>` that discards `head_at_capture` from the ancestry chain of the final `current_head`, then `_is_ancestor(head_at_capture, current_head)` returns `False` even though the file content of `current_head` differs from `head_at_capture` (and from the true pre-turn tree). Because:
- `diff_base` stays `"HEAD"`, so the `head_at_capture..HEAD` name-only diff (which would have surfaced the changed files) is never computed/unioned into `dirty_now`.
- The working tree is clean after a commit/amend, so `_git_status_porcelain` (`gitutil.py:330-373`) reports no `tracked_dirty` entries for those files either.
- `changed_since = _git_name_only(repo, baseline_sha)` (`diffstate.py:417-420`) *does* correctly detect that the files differ from the pre-turn stash baseline, but `review_set = dirty_now & changed_since` (`diffstate.py:426`) intersects with an empty `dirty_now` for those paths, so they are excluded.

The net effect: files modified by a commit that is created and then rewritten (amend/rebase/hard-reset to a new commit) before Stop fires are excluded from `review_paths`, even though `get_git_diff`/the LLM review is supposed to see everything different from the pre-turn baseline. This defeats the review-set invariant described in the module's own docstring ("`diff_base` is `HEAD` unless HEAD advanced linearly this turn").

### Impact Explanation
This allows malicious or vulnerability-introducing code changes made via Bash-tool git operations during a Claude Code turn to escape the security-guidance Stop-hook review entirely, since the changed files never enter `review_paths` and thus `get_git_diff`'s pathspec-restricted diff (built from `review_paths`, see `get_git_diff` in `gitutil.py:391-427` and its caller in `security_reminder_hook.py`) never surfaces them to the LLM reviewer. This is a security-control bypass: dangerous edits (e.g., adding a backdoor, injecting a command, weakening auth) committed and then amended/rebased are committed to the repository without ever being flagged, undermining the plugin's core guarantee that all code changed during a turn gets reviewed.

### Likelihood Explanation
Requires only ordinary git operations reachable from the agent's own Bash tool within one turn (no privilege escalation, no external input beyond normal automation/agent behavior): commit, then amend/rebase/reset before the turn ends and Stop fires. This is a common and unremarkable sequence (e.g., "oops, fix commit message" or "squash my last two commits") that an attacker-influenced or prompt-injected agent could easily be steered into performing, making this readily repeatable and not reliant on any race condition or timing trick beyond doing it before Stop's `consume_stop_state`/`compute_v2_review_set` runs.

### Recommendation
Do not gate the committed-changes union on `_is_ancestor`. Instead, always union in `_git_name_only(repo, f"{head_at_capture}...HEAD")` (or a plain two-dot diff against `head_at_capture` when it still resolves) regardless of ancestry, since the goal is "what changed since the captured baseline SHA," not "did HEAD move forward linearly." If `head_at_capture` no longer resolves (e.g., pruned by GC), fall back to using the full-tree `baseline_sha` diff (`changed_since`) directly as part of `dirty_now` rather than requiring the ancestor check to pass. At minimum, when `_is_ancestor` is false but `head_at_capture != current_head` and `head_at_capture` still resolves, compute `_git_name_only(repo, head_at_capture)` (diff against that commit's tree, not a range) and union it into `dirty_now` unconditionally.

### Proof of Concept
Integration/fuzz test in the existing test suite (e.g. alongside `compute_v2_review_set` tests):
1. Create a temp git repo with one initial commit.
2. Capture baseline: `baseline_sha = capture_git_baseline(cwd)`, `head_at_capture = _git_rev_parse_head(cwd)`.
3. Write malicious content to `evil.py`, `git add`, `git commit -m "c1"`.
4. `git commit --amend -m "c2"` (new SHA, same parent as `head_at_capture`, so `_is_ancestor(head_at_capture, new_head)` is False).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. Assert: `evil.py` (relative/absolute path) IS present in the returned `review_paths`.
   - Expected today: assertion FAILS — `evil.py` is absent because `diff_base` stayed `"HEAD"` and `dirty_now` is empty for it.
7. As an invariant/fuzz harness, generate random sequences of `{commit, amend, rebase -i (reorder/squash), reset --hard <ref>}` between baseline capture and Stop, and assert for every sequence that `review_paths` (converted to repo-relative) equals the symmetric set difference between the pre-turn tree (`baseline_sha`) and the post-turn worktree (`git diff --name-only baseline_sha` truth), i.e. `set(review_paths) ⊇ files_differing_from(baseline_sha)`. The fuzz should find counterexamples whenever an amend/rebase/reset breaks the `head_at_capture → current_head` ancestor chain.
