### Title
Webhook signature verification is bound to `repository.owner.login`, but handlers act on the independently-attacker-controlled `repository.full_name` — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which organization's `webhook_secret` to check the HMAC signature against using `repository_owner`, derived from the JSON body itself (`repository.owner.login`, falling back to `organization.login`). [1](#0-0) [2](#0-1)  Every default event handler, however, determines which repository/stack to mutate using a *different* field of the same untrusted body — `repository.full_name` — via `Handlers::Handler#repository_name`/`#stacks`. [3](#0-2)  Nothing enforces that these two fields agree. The signature only proves "this body was produced by whoever holds organization X's `webhook_secret`" — it does not prove "organization X owns the repository this body claims to act on."

### Finding Description
`Shipit.github(organization: repository_owner)` returns the `GitHubApp`/secret configured for the organization named in the payload's `repository.owner.login` (or `organization.login`), and `verify_webhook_signature` HMACs the raw body against that org's secret only. [1](#0-0) [4](#0-3)  This is a per-organization secret in a multi-tenant Shipit deployment (`Shipit.github(organization:)` looks up an app config per GitHub org).

Once the signature check passes, `WebhooksController#create` dispatches the *entire raw JSON body* to the registered handlers for the event. [5](#0-4)  Handlers such as `PushHandler` resolve the target `Stack`(s) purely from `repository.full_name`:
```
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [3](#0-2) 

`PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every stack matching that (attacker-supplied) full name and branch. [6](#0-5) 

**Broken binding (equality that should hold but doesn't):**
`organization authenticated by signature (repository.owner.login)` ≠ `repository actually written (repository.full_name)`.

Because both fields live inside the same attacker-controlled JSON body, an attacker who legitimately knows *their own* organization's `webhook_secret` (normal for any org admin who configured their own org's webhook/App integration on a shared Shipit instance) can craft a payload where:
- `repository.owner.login` = `"attacker-org"` (so `verify_signature` picks and successfully validates against attacker-org's own known secret)
- `repository.full_name` = `"victim-org/victim-repo"` (so the handler acts on a stack belonging to an organization the attacker has no relationship with)

The attacker computes `sha1=HMAC(attacker_secret, raw_body)` themselves and POSTs directly to the webhooks endpoint with `X-Github-Event: push` (or `status`, `check_suite`, `pull_request`). The signature check succeeds (it never inspects `full_name`), and the handler silently operates on the victim's stack.

### Impact Explanation
This breaks the trust boundary between tenants/organizations in a shared Shipit install and yields cross-repository writes with no legitimate access to the victim organization or repository:
- `push` → forces `GithubSyncJob`/`sync_github(expected_head_sha:)` on a victim stack with an attacker-chosen SHA, which can drive continuous-deployment stacks to deploy an attacker-chosen commit — an unauthorized deploy.
- `status` → `StatusHandler` writes fabricated commit statuses onto victim commits (spoofing CI results used to gate deploys/merges).
- `check_suite` → triggers `RefreshCheckRunsJob` against victim stacks.

All of these are actions on a repository the attacker never authenticated for, satisfying the "cross-repository writes / unauthorized deploy" Critical-impact bar.

### Likelihood Explanation
Requires only knowledge of one's own organization's configured `webhook_secret` (routine, expected knowledge for any org onboarded into a shared Shipit instance) and the ability to send a direct HTTP POST with a crafted JSON body and matching `X-Hub-Signature` header — no Shipit session, GitHub App private key, or repository write access to the victim is needed. This is a low-effort, unprivileged-attacker path.

### Recommendation
Bind the verified identity to the acted-upon resource: after signature verification succeeds for `repository_owner`, re-derive the repository/organization used by handlers (`repository.full_name`) and reject (422) the webhook if its owner segment does not match `repository_owner`/`organization.login` used for verification. Alternatively, have `Handlers::Handler` receive and enforce the already-verified organization instead of independently trusting `payload.dig('repository', 'full_name')`.

### Proof of Concept
1. Attacker administers `attacker-org`, which is configured in Shipit's `secrets.yml` with its own `webhook_secret` (known to the attacker, as is normal when self-configuring a GitHub App/webhook).
2. Attacker builds a raw JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker computes `sig = "sha1=" + HMAC_SHA1(attacker_org_webhook_secret, raw_body)`.
4. Attacker POSTs to `/webhooks` with headers `X-Github-Event: push` and `X-Hub-Signature: <sig>`.
5. `verify_signature` resolves `repository_owner == "attacker-org"`, fetches attacker-org's `GitHubApp`, and the HMAC check passes (app/controllers/shipit/webhooks_controller.rb:24-30).
6. `PushHandler` resolves stacks via `repository.full_name == "victim-org/victim-repo"` (app/models/shipit/webhooks/handlers/handler.rb:32-38) and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on the victim's stack (app/models/shipit/webhooks/handlers/push_handler.rb:12-17) — despite the request only ever being authenticated as belonging to `attacker-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
