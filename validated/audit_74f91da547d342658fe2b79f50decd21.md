### Title
Accrued debt valuation overflows `i128` and permanently freezes a large high-utilization market - (File: common/src/rates/index.rs)

### Summary
A large borrower can leave enough scaled debt that a later interest accrual makes `borrowed * new_borrow_index / RAY` unrepresentable in `i128`, causing every subsequently synced operation on that market to revert with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description
`Controller::supply` and `Controller::borrow` are reachable by ordinary authenticated users, with borrow additionally requiring account ownership or delegation and post-borrow solvency. [3](#0-2) [4](#0-3) 

Deposits and borrows are converted into RAY-scaled share balances and accumulated in the pool’s `supplied` and `borrowed` totals. [5](#0-4) [6](#0-5) 

Every pool leg loads the market through `load_leg`, which calls `synced_market`; `synced_market` always runs `global_sync` before the requested mutation. [7](#0-6) 

`global_sync` delegates each elapsed-time chunk to `accrue_step`, which computes the new borrow index and then calls `calculate_supplier_rewards`. [8](#0-7) [9](#0-8) 

`calculate_supplier_rewards` separately multiplies the stored scaled debt by both the old and new borrow indexes; although intermediate multiplication is widened to `I256`, conversion of the final RAY value back to `i128` fails when the result exceeds `i128::MAX`. [10](#0-9) [11](#0-10) 

The borrow-index ceiling does not prevent this condition because the debt-value product can overflow before `update_borrow_index` reaches or applies its ceiling. [12](#0-11) 

After the boundary is crossed, each new accrual attempt starts from the still-valid stored index and panics again while valuing debt at the projected index, so there is no catch-up path that skips the overflowing calculation. [13](#0-12) [14](#0-13) 

### Impact Explanation
All suppliers’ underlying in the affected market becomes unavailable through the contract because withdrawals load the market through `synced_market`, which performs the failing accrual before burning shares or paying cash. [15](#0-14) [16](#0-15) 

Borrowers also cannot repay through the normal `repay` path because repayment transfers are followed by a pool `load_leg` that triggers the same accrual panic. [17](#0-16) [18](#0-17) 

Liquidation and debt-management paths that rely on pool legs inherit the same failure because their pool operations are routed through the synchronized cache rather than bypassing accrual. [7](#0-6) [19](#0-18) 

Even changing the market’s rate model cannot recover the market through the intended administrative flow because `upgrade_liquidity_pool_params` first calls the pool’s `update_indexes`, which performs the same failing accrual. [20](#0-19) [21](#0-20) 

This is permanent freezing of user funds absent a contract upgrade or other privileged recovery outside the affected accounting path.

### Likelihood Explanation
The attack requires a market whose configured caps and liquidity permit a scaled debt balance close to the RAY-domain boundary and enough collateral for the borrower to pass the controller’s post-borrow solvency check. [6](#0-5) [22](#0-21) 

For example, an 18-decimal deposit of 1 billion whole tokens produces `1e36` scaled shares; at roughly 98% utilization, debt valuation overflows once the borrow index exceeds approximately `i128::MAX / 0.98e36`, or about 173 times the initial `RAY` index. [5](#0-4) [23](#0-22) 

The attacker does not need a privileged action after opening the positions: any authorized caller can invoke `Controller::update_indexes`, which forwards the assets to the pool’s accrual entrypoint. [24](#0-23) [25](#0-24) 

The capital requirement and sustained-utilization precondition make this Medium rather than Critical or High, but the resulting loss of every normal exit and repayment path is permanent from the contract’s exposed operations. [7](#0-6) 

### Recommendation
Bound admitted market exposure so `borrowed * MAX_BORROW_INDEX_RAY / RAY` and `supplied * MAX_SUPPLY_INDEX_RAY / RAY` remain representable in `i128`, or store/accrue debt and supply values in a wider representation. [12](#0-11) [10](#0-9) 

At minimum, make `accrue_step` cap index growth before evaluating `borrowed * new_index`, while preserving any accrued amount that remains representable and allowing repayment or withdrawal paths to proceed without requiring another unbounded debt valuation. [9](#0-8) 

### Proof of Concept
1. On an 18-decimal market, call `Controller::supply(attacker, 0, spoke_id, [(hub_asset, 1_000_000_000 * 10^18)])`, creating a position with approximately `1e36` supply shares. [26](#0-25) [5](#0-4) 
2. Provide sufficient separate collateral and call `Controller::borrow(attacker, account_id, [(hub_asset, debt_amount)], Some(attacker))`, where `debt_amount` produces approximately `0.98e36` scaled debt and remains within the configured utilization and solvency gates. [27](#0-26) [6](#0-5) 
3. Leave utilization high until the projected borrow index exceeds about `173 * RAY`; at that point `0.98e36 * borrow_index / RAY` exceeds `i128::MAX`. [23](#0-22) 
4. Call `Controller::update_indexes(any_caller, [hub_asset])`; the pool accrues first, `calculate_supplier_rewards` evaluates the new total debt, and the `I256` result cannot convert back to `i128`, so the call panics with `MathOverflow`. [25](#0-24) [11](#0-10) 
5. Subsequent `withdraw` and `repay` calls fail before their mutation logic because both use `load_leg` → `synced_market` → `global_sync`, leaving suppliers unable to exit and borrowers unable to clear the frozen debt. [7](#0-6) [28](#0-27)

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}

/// Funds the pool with measured transfers and repays the corresponding debts.
fn settle_repay(
    env: &Env,
    account: &mut Account,
    payer: &Address,
    aggregated: &AggregatedPayments,
    cache: &mut Context,
) {
    let pool_addr = cache.cached_pool_address();
    let mut actions: Vec<PoolAction> = Vec::new(env);
    for (hub_asset, amount) in aggregated.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &hub_asset,
            FreezePolicy::AllowOnExit,
        );
        let position = get_debt_position_or_panic(env, account, &hub_asset);
        let amount_in = payments::transfer_amount_measured(
            env,
            &hub_asset.asset,
            payer,
            &pool_addr,
            amount,
            GenericError::AmountMustBePositive,
        );
        actions.push_back(make_pool_action(&position, amount_in, hub_asset.clone()));
    }
    apply_repay_batch(
        env,
        account,
        payer,
        events::PositionAction::Repay,
        &actions,
        cache,
    );

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
