### Title
Security-Guidance Stop-hook review permanently skips Claude-authored untracked files after an interrupted turn - (File: plugins/security-guidance/hooks/security_reminder_hook.py / plugins/security-guidance/hooks/diffstate.py)

### Summary
This is the same bug class as the staking report's H-03: a "checkpoint" value (`cheque.lastPrintedAt`) is unconditionally overwritten on a repeated action without first accounting for the not-yet-processed accumulation from the prior period, so that accumulation is permanently lost. In the `security-guidance` plugin, `handle_user_prompt_submit` unconditionally overwrites the `untracked_at_baseline` checkpoint on every `UserPromptSubmit`, even in the code path that deliberately *preserves* `baseline_sha` to make sure a previous turn's unreviewed edits are diffed and reviewed later. This mismatch causes untracked files written by Claude in an aborted/interrupted turn to become permanently invisible to the Stop-hook's LLM security review.

### Finding Description
`handle_user_prompt_submit` in [1](#0-0)  captures a git baseline SHA and an "untracked files" snapshot (`untracked_at_baseline`) on every user prompt so the Stop hook can later diff only Claude's own changes.

The handler contains explicit logic to *preserve* `baseline_sha` when the previous turn's Stop hook never consumed `touched_paths` (user interrupt, tool-reject, crash, maxTurns, etc.), because overwriting the baseline would "re-baseline past those unreviewed edits, making them permanently invisible to the next Stop": [2](#0-1) 

However, the `untracked_at_baseline` field is written unconditionally, regardless of whether `baseline_sha` was preserved:
```python
state["untracked_at_baseline"] = untracked_now
```
(line 502)

`untracked_at_baseline` is consumed by `compute_v2_review_set` in [3](#0-2)  to decide which untracked files are "pre-existing and unchanged" and should be *excluded* from review:
```python
def _unchanged_since_baseline(p):
    base_mtime = untracked_at_baseline.get(p)
    ...
preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
new_untracked = untracked - preexisting_unchanged
dirty_now = tracked_dirty | new_untracked
```

If Claude writes a new (untracked) file during a turn that is then interrupted before Stop fires, that file's mtime is captured into `untracked_now` at the very next `UserPromptSubmit` — i.e., *after* the file already exists on disk. Because `untracked_at_baseline` is refreshed to this new snapshot even in the "preserved baseline" branch, the file's mtime in the new checkpoint matches the file's current mtime. On the subsequent Stop-hook run (which is meant to catch up on the preserved, older baseline's unreviewed diff), `_unchanged_since_baseline` now returns `True` for that file, so it is classified as `preexisting_unchanged` and excluded from `new_untracked`/`dirty_now`/`review_set` — permanently, since nothing will "un-exclude" it unless the file's mtime changes again.

`restore_unreviewed_stop_state` — the other safety net that re-arms `touched_paths` when Stop exits early for a transient reason — only restores `touched_paths` and `baseline_sha`, not `untracked_at_baseline`: [4](#0-3) . So neither preservation path protects the untracked-file checkpoint.

This is structurally identical to the reported staking bug: `deligateStake()` unconditionally sets `cheque.lastPrintedAt = block.timestamp` (a checkpoint used to compute "what's owed since last checkpoint") without first reconciling the pending amount, permanently losing it. Here, `untracked_at_baseline` (a checkpoint used to compute "what's new since last checkpoint") is unconditionally refreshed without regard to whether the pending, not-yet-reviewed file set has actually been reviewed, permanently excluding it from the diff that feeds the LLM security scan.

### Impact Explanation
The Stop hook is the plugin's core security control — an LLM-based diff review that inspects every Claude-authored change for vulnerabilities (secrets, injection, path traversal, etc.) and forces Claude to continue and fix findings via `exit(2)`. A file that silently drops out of the review set defeats this control for that file's entire lifetime in the session (and across sessions, since `untracked_at_baseline` persists in session state). Any newly created (not-yet-`git add`ed) file that Claude writes during a turn that is interrupted before Stop consumes state — which the code's own comments acknowledge happens routinely ("user interrupt, follow-up during work, tool-reject, model crash, maxTurns") — can end up permanently unreviewed. In an adversarial setting (e.g. a prompt-injection payload steering Claude to write a backdoored script to a new untracked file, timed to coincide with an interruption), this is a concrete hook/security-review bypass without any privilege escalation required — an ordinary interrupted turn is enough to trigger it.

### Likelihood Explanation
Interrupted/aborted turns (user hits ESC/Ctrl-C, hits `maxTurns`, a PostToolUse hook blocks, or the model crashes mid-turn) are common, and the code's own comments show the authors are already aware this scenario recurs and specifically engineered the `baseline_sha` preservation path for it — but missed applying the same preservation to `untracked_at_baseline`. No attacker privilege beyond normal usage/prompt content is needed; the race is purely timing-based (turn ends before Stop finishes, next prompt fires UPS). This makes the likelihood of naturally triggering the gap moderate-to-high, and an adversary who controls prompt content (prompt injection) can intentionally increase the odds by causing Claude to write a file and then trigger conditions likely to interrupt the turn.

### Recommendation
In `handle_user_prompt_submit`'s `_save` closure, only overwrite `untracked_at_baseline` when the baseline itself is also being advanced (i.e., in the same branch that writes `state["baseline_sha"] = sha`). When preserving the old baseline because unreviewed `touched_paths` still exist, keep the old `untracked_at_baseline` (or merge the new untracked snapshot into the old one without ever removing entries that were already pending review), so files that haven't yet been diffed against the preserved baseline can't be mtime-matched into `preexisting_unchanged`. Correspondingly, extend `restore_unreviewed_stop_state` to also restore/merge `untracked_at_baseline` for the same transient-Stop-failure case it already handles for `touched_paths`/`baseline_sha`.

### Proof of Concept
1. Start a session; Claude writes a new untracked file `evil.py` containing intentionally malicious code (e.g., simulate via a crafted prompt or manual instruction), but the turn is interrupted (Ctrl-C / ESC, or the turn exceeds `maxTurns`) before the Stop hook fires — `touched_paths=["evil.py"]` remains in state and is never consumed.
2. Submit a new prompt. `handle_user_prompt_submit` fires: since `touched_paths` and `baseline_sha` are both truthy, the `_save` closure takes the "preserve" branch and does **not** overwrite `baseline_sha`/`head_at_capture` — but it unconditionally sets `state["untracked_at_baseline"] = untracked_now`, and `untracked_now` now includes `evil.py` with its current (already-written) mtime.
3. Complete this second turn normally (make no further edits to `evil.py`) and let Stop fire. `compute_v2_review_set` computes `_unchanged_since_baseline("evil.py")` → `True` (mtime unchanged since the just-captured `untracked_at_baseline`), so `evil.py` lands in `preexisting_unchanged`, is excluded from `new_untracked`/`dirty_now`, and never enters `review_set`.
4. `evil.py` is never sent to the Stop-hook's LLM security reviewer in this or any subsequent turn (as long as its mtime doesn't change again), even though it was never actually reviewed — the Stop-hook security control has been permanently bypassed for that file.

```python
def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
    with_locked_state(session_id, _save)

    if preserved["value"]:
        debug_log(
            "UPS: preserving prior baseline — previous Stop hook never "
            "consumed touched_paths (likely user interrupt / aborted turn)"
        )
    elif sha:
        debug_log(f"Captured git baseline: {sha[:12]}")
    else:
        debug_log("Failed to capture git baseline (not a git repo?)")

    sys.exit(0)

```

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
