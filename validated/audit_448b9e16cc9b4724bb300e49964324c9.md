### Title
Webhook signature is verified against the organization named in `repository.owner.login`, but the Stack/Repository actually written is resolved independently from `repository.full_name` — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to validate the inbound webhook signature against by reading `repository.owner.login` (or `organization.login`) out of the **same untrusted JSON body** it is trying to authenticate. Every event handler, however, resolves the repository/stack it actually mutates from a *different* field in that same body: `repository.full_name`. Because these two fields are read and trusted independently, in a multi-organization Shipit deployment an attacker who can produce a valid signature for *any one* configured organization (including one with no `webhook_secret` set, which is explicitly allowed and unconditionally passes verification) can forge a webhook whose `repository.full_name` points at a stack belonging to a completely different, properly-secured organization.

### Finding Description
`repository_owner` is computed purely from attacker-supplied JSON: [1](#0-0) 

That value is fed into `Shipit.github(organization: repository_owner)` to pick which org's secret is used for HMAC verification of the raw body: [2](#0-1) 

`Shipit.github` supports (and the docs recommend) configuring multiple independent GitHub organizations, each with its own `webhook_secret`, looked up by the same attacker-controlled `organization` string: [3](#0-2) 

Critically, `GitHubApp#verify_webhook_signature` unconditionally returns `true` when that organization's `webhook_secret` is blank/unset: [4](#0-3) 

Once the signature check passes for organization *A* (the one named in `repository.owner.login`), the raw JSON is dispatched to handlers unchanged: [5](#0-4) 

But every handler resolves the actual Repository/Stack to act on from `repository.full_name`, a completely separate field never checked against `repository_owner`: [6](#0-5) 

For example, `PushHandler` will look up stacks for whatever `full_name` says and trigger a GitHub sync with an attacker-chosen `after` SHA: [7](#0-6) 

The same pattern (`params.repository.full_name` driving `Repository.from_github_repo_name` independent of signature-selection org) repeats across the pull-request handlers: [8](#0-7) [9](#0-8) 

This is precisely the "authenticated organization ≠ written repository" binding break: the equality that must hold is
`organization_whose_secret_signed(request) == organization_owning(stack_being_mutated)`,
but the code enforces `organization_whose_secret_signed(request) == repository.owner.login (attacker-controlled)` while mutating based on `repository.full_name (attacker-controlled, independently)`.

### Impact Explanation
In a multi-org Shipit instance (a documented, supported configuration — see `docs/setup.md` "Using Multiple Github Applications"), if organization A is configured with no `webhook_secret` (also documented as a valid/default config: `webhook_secret: # nil`), or if the attacker otherwise knows/leaks A's secret, they can:
1. Send a POST to `/github/webhooks` with `X-Github-Event: push`, no/any signature, and a body where `repository.owner.login = "A"` (or absent, causing `verify_signature`'s fallback to `organization.login`) but `repository.full_name = "OrgB/victim-repo"`.
2. `verify_signature` authenticates the request as organization A (trivially, since A has no secret or its secret is known).
3. `PushHandler` (or a PR handler) resolves `OrgB/victim-repo`'s real Stack via `Repository.from_github_repo_name` and triggers `stack.sync_github(expected_head_sha: params.after)`, or archives/unarchives a review stack, or updates pull request state — all cross-organization actions the attacker has no legitimate access to.

This constitutes an unauthorized cross-repository write against a Stack belonging to an organization the attacker never authenticated against, matching the Critical impact bucket ("cross-repository writes, or an unauthorized deploy, rollback or merge") — `sync_github` can advance the tracked head SHA and unarchive/archive review stacks for a repository outside the attacker's control.

### Likelihood Explanation
Requires a Shipit deployment configured for multiple GitHub organizations (an explicitly documented, supported setup) where at least one configured organization has no `webhook_secret` set (also an explicitly supported/default configuration shown in `config/secrets.development.example.yml` and `test/dummy/config/secrets_double_github_app.yml`) — or where the attacker otherwise obtains a valid HMAC for any one configured org. No privileged Shipit account, `ApiClient` token, or GitHub write access to the victim repo is needed; the attacker only needs to be able to authenticate a webhook signature for any org present in the same Shipit configuration.

### Recommendation
- In `WebhooksController#verify_signature`, after establishing which organization's secret validated the signature, cross-check that the `repository.full_name`'s owner segment matches the authenticated organization (or otherwise pin verification to the org that owns `repository.full_name`, not a value read independently).
- Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is blank in a multi-organization configuration; require every configured organization to have a webhook secret, or explicitly scope which organizations may vouch for which repositories.
- In `Handler#repository_name`/`#stacks`, verify that the resolved repository's registered `owner` is consistent with the organization used for signature verification before dispatching mutating actions.

### Proof of Concept
Given a Shipit instance configured (per `docs/setup.md`) with two organizations, `OrgOne` (no `webhook_secret` configured) and `OrgB` (properly secured, hosts a tracked Stack `OrgB/victim-repo`):

```
POST /github/webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # irrelevant, OrgOne has no webhook_secret

{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "OrgOne" },
    "full_name": "OrgB/victim-repo"
  }
}
```

`repository_owner` resolves to `"OrgOne"`; `Shipit.github(organization: "OrgOne").verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`) because `OrgOne` has no `webhook_secret`. The request is accepted and dispatched. `PushHandler#process` then resolves stacks via `repository.full_name = "OrgB/victim-repo"` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on the victim organization's stack — a write the attacker never authenticated to perform.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
