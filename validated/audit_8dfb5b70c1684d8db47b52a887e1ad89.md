### Title
`liquidate` gives liquidators no bound on the dynamically computed collateral seizure - (File: contracts/controller/src/positions/liquidation/plan.rs)

### Summary
`liquidate(liquidator, account_id, debt_payments, seize_mode)` lets a caller commit exact debt-token payments while the collateral it receives is fully computed at execution time from oracle prices, market indexes, the account's health factor, and the bonus curve. There is no `min_seized`/`min_out` parameter anywhere in the signature or the plan, so prices or indexes moving between transaction creation and execution — or a seizure leg rounding to zero — can leave the liquidator paying its full offer and receiving little or no collateral.

### Finding Description
The liquidator controls only the inputs (`debt_payments`, `seize_mode`). `build_liquidation_plan` derives everything else at execution: `repay_usd`, the bonus from `LiquidationCurve`, and per-asset seizures via `calculate_seized_collateral`, which prices each supply leg off `cache.cached_price` and `cached_market_index` [1](#0-0) . Legs whose seizure rounds to zero are silently dropped (`if seizure_ray <= Ray::ZERO { continue; }` / `capped_ray <= Ray::ZERO { continue; }`) [2](#0-1) .

The only zero-seizure guard is the insolvency special case in `build_liquidation_plan`: when `unbacked_usd > 0 && seized_collaterals.is_empty()` the repayment itself is released (so nothing is paid). If `unbacked_usd == 0` and the whole seizure plan collapses — e.g. a sub-3-decimal leg rounding down, or prices moving so all legs round to zero — the plan still validates and the liquidator's offered debt payment is pulled while nothing is seized. The project's own liquidation skill documents this reachable state: "The contract accepts a liquidation that repays debt and seizes nothing, so the liquidator would pay and receive no collateral" [3](#0-2) .

Compare with the sibling strategy verbs: `swap_collateral`, `swap_debt`, `multiply`, and `repay_debt_with_collateral` route through the swap aggregator where a `min_out` floor is enforced (`total_out < total_min_out → SlippageExceeded`) — but only because the user embeds it in `routeXdr`; the controller "never checks a minimum output" itself [4](#0-3) . `liquidate` has no equivalent user-supplied bound at all — unlike `flash_position`, which requires caller-declared minimum collateral receipts [5](#0-4) .

### Impact Explanation
A liquidator's payment is transferred (via per-asset `transfer(liquidator, pool, amount)` authorizations) while the seizure is computed from state that shifts between simulation and execution: oracle price ticks (which also shift HF and thus the bonus via the curve), supply/borrow index accrual, and competing liquidations shrinking or dropping legs. The result ranges from paying debt for collateral below break-even to paying the full offer and receiving zero collateral — a direct, unbounded loss of the liquidator's funds on a permissionless entrypoint, matching the reported bug class (unbounded dynamically-computed output) but on the payout side.

### Likelihood Explanation
`liquidate` is permissionless and races are inherent: any third party can liquidate the same account first, indexes accrue every millisecond, and prices refresh per transaction. The catastrophic empty-seizure case additionally requires the seizure plan to collapse to zero (rounding or a competing liquidation); the partial-severe-slippage case requires only ordinary price/HF drift. Medium likelihood overall — an adversary cannot force the drift, but the liquidator has no protocol-level defense when it occurs.

### Recommendation
Add a `min_seized: Vec<(HubAssetKey, i128)>` (or aggregate `min_seized_usd: Wad`) parameter to `liquidate`, in the same units the seize mode delivers (token units for `Transfer`, RAY shares for `Credit`), and revert after `calculate_seized_collateral` if the resulting `seized` legs fall below it. Also revert when the plan repays a nonzero amount while `seized` is empty, regardless of `unbacked_usd`. This mirrors the documented best practice already enforced for `flash_position` collateral minimums.

### Proof of Concept
1. Account A is liquidatable (HF < 1) with a single supply leg in a low-decimal asset and a USDC debt.
2. Liquidator calls `get_liquidation_estimate(account_a, [(USDC, offer)], Transfer)`, sees a profitable seizure, signs `transfer(liquidator, pool, offer)` auth, and submits `liquidate`.
3. Before execution, a competing liquidation partially closes A (or a price tick re-prices the legs). At execution, `calculate_seized_collateral` rounds each remaining leg's seizure to zero and drops it; `unbacked_usd == 0`, so the empty-seizure release in `plan.rs:76-79` does not trigger.
4. `liquidate` pulls the full offered USDC, credits A's debt repayment, and the liquidator receives no collateral. No parameter existed to bound the outcome; the loss is realized and irreversible.

Caveat: I confirmed the plan-building and zero-seizure-drop logic and the documented empty-seizure acceptance, but did not trace the final `liquidate` entrypoint body end-to-end in `lib.rs`/executor code; the empty-seizure-with-payment acceptance is corroborated by the repo's own liquidation documentation rather than a single reverted-guard line.
