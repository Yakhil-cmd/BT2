### Title
Suppliers can front-run a known bad-debt write-down and concentrate the loss on remaining suppliers - ([File: contracts/pool/src/ops/withdraw.rs](contracts/pool/src/ops/withdraw.rs))

### Summary
XOXNO Lending applies bad-debt losses by reducing a market’s `supply_index` only when a later liquidation or cleanup executes `seize_positions`. Until that happens, ordinary `withdraw` burns supply shares at the pre-write-down index and only enforces cash, utilization, and nonzero-supply guards. An unprivileged supplier who observes an insolvent account can therefore withdraw before the write-down, recover the pre-loss value, and leave the same bad debt to be absorbed by fewer remaining suppliers.

### Finding Description
The controller exposes permissionless `withdraw` and `liquidate`/`clean_bad_debt` entrypoints. `withdraw` processes the caller’s supply position through `positions::process_withdraw` [1](#0-0) , while `liquidate` and `clean_bad_debt` trigger later position seizure and debt cleanup [2](#0-1) .

The pool withdrawal path resolves the withdrawal against the current `supply_index`, burns shares, and then checks only `require_reserves`, `require_utilization_below_max`, and `require_supply_for_debt` [3](#0-2) . It does not check whether outstanding debt is already unrecoverable or whether a bad-debt write-down is pending.

`require_backed_market`, which computes `backing_shortfall`, is not part of withdrawal; backing still treats outstanding debt at its ceiled face value as backing [4](#0-3) . The actual socialization occurs only when `seize_positions` handles a `Borrow` entry by calling `apply_bad_debt_to_supply_index` and burning the debt [5](#0-4) . That function reduces the current suppliers’ index pro-rata [6](#0-5) .

The repository’s own regression test demonstrates the exploit ordering: after a public collateral crash makes Alice liquidatable, Bob withdraws before liquidation, exits whole, and Carol’s loss grows by approximately 4x because Bob’s 75% supply share no longer participates in the write-down [7](#0-6) .

### Impact Explanation
This is theft/loss-shifting of user funds. A faster supplier exits at an index that has not yet recognized publicly observable bad debt. When a permissionless `liquidate` or `clean_bad_debt` later socializes the residual debt, the loss is divided over a smaller remaining supply base, forcing passive suppliers to absorb more than their economic share.

A withdrawal race can also drain tracked `cash` before settlement. Subsequent withdrawals become limited by `require_reserves`, and once the write-down creates a positive backing shortfall, `require_backed_market` blocks new `supply` until recapitalization or repayment restores backing. This can temporarily freeze exits or prevent fresh supply into the affected market, matching the report’s loss-anticipation and liquidity-drain pattern.

### Likelihood Explanation
Likelihood is high when insolvency can be observed before cleanup. Price updates, health-factor views, and permissionless liquidation/cleanup are public. No privileged role or MEV assumption is required: any supplier can call `Controller::withdraw` with its `account_id`, the affected `HubAssetKey`, and a full withdrawal amount such as `0`, subject to its account remaining solvent.

The exploit does not require controlling the insolvent account. It requires only that cash remains available and that Bob’s exit does not leave `supplied == 0` with nonzero `borrowed`, which `require_supply_for_debt` prevents [8](#0-7) . If multiple suppliers race, earlier transactions obtain cash at the old index while later suppliers bear the concentrated index loss or face a cash shortage.

### Recommendation
Do not allow ordinary withdrawals to value supply at an index that ignores already-insolvent, eligible debt. Possible mitigations include:

- Detect pending socializable debt during withdrawal and apply the bad-debt index adjustment before allowing the withdrawal.
- Add a short withdrawal delay/cooling period so pending liquidation or cleanup losses land before shares can exit.
- Add a withdrawal gate when required collateral prices make an account eligible for `clean_bad_debt` or when liquidation would leave residual debt.
- Make cleanup atomic with the price/risk transition where feasible, or reserve/mark eligible bad debt before allowing exits.

The least disruptive fix is likely to run an explicit pre-withdrawal bad-debt check for every debt market touched by the account’s risk context and force eligible cleanup/socialization before processing the withdrawal.

### Proof of Concept
The existing test `supplier_can_exit_ahead_of_bad_debt_writedown` is a direct executable proof:

1. Bob supplies 75 ETH and Carol supplies 25 ETH.
2. Alice supplies USDC collateral and borrows ETH.
3. The USDC price is reduced to `usd_cents(10)`, making Alice liquidatable.
4. Before any liquidation applies the write-down, Bob calls the ordinary withdrawal path and exits whole.
5. Liquidation then socializes Alice’s residual ETH debt.
6. Carol’s measured loss is greater than in the identical scenario where Bob did not withdraw; the test asserts greater than 3x amplification [9](#0-8) .

A user-facing transaction sequence is:

```text
Controller::withdraw(
  caller = BOB,
  account_id = bob_account,
  withdrawals = [(eth_hub_asset, 0)],
  to = Some(BOB)
)

Controller::liquidate(
  liquidator = ANYONE,
  account_id = alice_account,
  debt_payments = [(eth_hub_asset, repay_amount)],
  seize_mode = ...
)
```

or `Controller::clean_bad_debt(ANYONE, alice_account)` when the account is eligible for cleanup.

/// Panics with `PoolInsolvent` if the market has a positive backing shortfall.
///
/// Backing = cash + ceiled debt value; claims = floored supply value.
pub(crate) fn require_backed_market(env: &Env, cache: &Cache) {
    assert_with_error!(
        env,
        backing_shortfall(cache) == 0,
        CollateralError::PoolInsolvent
    );
}

/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}

/// Socializes `bad_debt` by reducing the supply index (capped at total supply value).
///
/// Used when seizing unpaid debt: remaining supplier claims shrink pro-rata.
/// No-op when total supplied value is zero. Floors the resulting index at
/// [`SUPPLY_INDEX_FLOOR_RAW`] to avoid a zero index.
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Bad debt is written down only when a liquidation or cleanup call runs, and
/// `backing_shortfall` counts the unrecoverable debt at face value until then.
/// A supplier can exit at the pre-write-down index and leave the loss on the
/// suppliers who stay. Runs the same crash with Bob passive and with Bob
/// exiting first, and compares Carol's loss.
#[test]
fn supplier_can_exit_ahead_of_bad_debt_writedown() {
    // Scenario A: nobody dodges. Bob 75%, Carol 25% of the ETH supply.
    let mut a = setup();
    a.supply(BOB, "ETH", 75.0);
    a.supply(CAROL, "ETH", 25.0);
    a.supply(ALICE, "USDC", 10.0);
    a.borrow(ALICE, "ETH", 0.003);

    let carol_before_a = a.supply_balance(CAROL, "ETH");
    a.set_price("USDC", usd_cents(10));
    a.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_a = carol_before_a - a.supply_balance(CAROL, "ETH");

    // Scenario B: identical state, but Bob withdraws before the write-down.
    let mut b = setup();
    b.supply(BOB, "ETH", 75.0);
    b.supply(CAROL, "ETH", 25.0);
    b.supply(ALICE, "USDC", 10.0);
    b.borrow(ALICE, "ETH", 0.003);

    let carol_before_b = b.supply_balance(CAROL, "ETH");
    let bob_before_b = b.supply_balance(BOB, "ETH");
    let bob_wallet_before = b.token_balance(BOB, "ETH");

    // The crash is public state. Alice is insolvent from here on, but no
    // write-down has been applied yet.
    b.set_price("USDC", usd_cents(10));
    b.assert_liquidatable(ALICE);

    // Bob exits at the un-written-down index. No gate stops him: the
    // liquidation buffer only guards borrow draws, and `backing_shortfall`
    // still values Alice's uncollateralised debt at face.
    b.withdraw_all(BOB, "ETH");
    let bob_recovered = b.token_balance(BOB, "ETH") - bob_wallet_before;

    b.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);
    let carol_loss_b = carol_before_b - b.supply_balance(CAROL, "ETH");

    assert!(
        bob_recovered >= bob_before_b,
        "Bob exits whole: supplied={:.9} recovered={:.9}",
        bob_before_b,
        bob_recovered
    );
    assert!(
        carol_loss_b > carol_loss_a,
        "dodging must push loss onto Carol: A={:.9} B={:.9}",
        carol_loss_a,
        carol_loss_b
    );

    // Carol holds 25% of supply, so passing the whole loss to her is ~4x.
    let amplification = carol_loss_b / carol_loss_a;
    assert!(
        amplification > 3.0,
        "expected ~4x concentration onto the remaining supplier, got {:.3}x \
         (A={:.9} B={:.9})",
        amplification,
        carol_loss_a,
        carol_loss_b
    );

    std::println!(
        "A4-econ dodge: bob_supplied={:.9} bob_recovered={:.9} \
         carol_loss_passive={:.9} carol_loss_after_dodge={:.9} amplification={:.3}x",
        bob_before_b,
        bob_recovered,
        carol_loss_a,
        carol_loss_b,
        amplification
    );
