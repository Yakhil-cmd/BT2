### Title
Unsanitized `base_branch` from `merge-upstream` API response enables terminal escape injection in `gh repo sync` output - ([File: pkg/cmd/repo/sync/sync.go])

### Summary
`triggerUpstreamMerge` returns the API-controlled `response.BaseBranch` string unmodified, which `executeRemoteRepoSync` passes through as `baseBranchLabel` and `syncRemoteRepo` writes directly to `opts.IO.Out` via `fmt.Fprintf` with no escape-sequence sanitization. Any host that `gh repo sync` talks to (attacker-controlled API endpoint, GHE instance, or a compromised/malicious response) can inject ANSI/OSC-8 escape sequences that land in the victim's terminal.

### Finding Description
`triggerUpstreamMerge` decodes the `merge-upstream` JSON response into a struct and returns `response.BaseBranch` as-is with no validation or sanitization: [1](#0-0) 

This value flows through `executeRemoteRepoSync`, which returns it as `baseBranch` on success: [2](#0-1) 

`syncRemoteRepo` then prints it directly to `opts.IO.Out`: [3](#0-2) 

Critically, `opts.IO.Out` is the raw, unsanitized stdout writer. The codebase has an established, deliberate distinction between `Out` (application-authored text, not sanitized) and `ContentOut` (external/untrusted content, sanitized by default via `asciisanitizer`), and further has an `iostreams.Untrusted` wrapper type specifically designed so that any `fmt` print path of externally-sourced data is automatically neutralized: [4](#0-3) [5](#0-4) 

Other commands that consume server/API-controlled text route it through `ContentOut`, `iostreams.Untrusted`, or explicit `ContainsEscapeSequence` checks before writing to the terminal (e.g. gist view, pr diff, release download, repo read-file): [6](#0-5) [7](#0-6) 

`pkg/cmd/repo/sync/sync.go` does none of this: `baseBranchLabel` is treated as trusted, application-authored text and printed straight to `opts.IO.Out` (not `ContentOut`), even though its ultimate source is the `base_branch` field of an HTTP JSON response from the destination repo's host — attacker-controlled when the victim points `gh` at a malicious/compromised API endpoint or GHE host, or when the response is otherwise influenced by the destination repo owner. `client.REST` does standard JSON decoding, so a `\u001b`-escaped byte in the JSON string decodes to a literal ESC (0x1B) byte with no filtering at the transport layer.

### Impact Explanation
When `gh repo sync <dest>` is run against an attacker-influenced host/response and stdout is a TTY, the printed `%s` (baseBranchLabel) can carry ANSI CSI/OSC sequences (e.g., OSC 8 hyperlink or OSC 0/2 title-set payloads), enabling terminal title/hyperlink spoofing and potentially misleading the victim into executing commands via hidden or fake link text — classic terminal escape injection / prompt spoofing. This matches the CLI's own worked threat model, already tested elsewhere in the codebase (workflow log escape injection, gist/diff/read-file escape guarding).

### Likelihood Explanation
Requires the victim to run `gh repo sync` against a host under attacker influence (custom `GH_HOST`/enterprise config, a malicious mock/test host, or a compromised legitimate host response). Given that precondition, the exploit is fully reliable and repeatable — no race conditions, no additional user interaction beyond running the sync command with a TTY stdout.

### Recommendation
Treat `response.BaseBranch` (and any other server-controlled label used in `syncRemoteRepo`'s success message) as untrusted content: wrap it with `iostreams.NewUntrusted(...)` before formatting, or sanitize with `iostreams.ContainsEscapeSequence`/`asciisanitizer` before writing to `opts.IO.Out`, consistent with the pattern already used in `pkg/cmd/gist/view/view.go` and `pkg/cmd/repo/read-file/read_file.go`.

### Proof of Concept
```go
// pkg/cmd/repo/sync/sync_test.go (new case)
func TestSyncRun_BaseBranchEscapeInjection(t *testing.T) {
    reg := &httpmock.Registry{}
    defer reg.Verify(t)
    reg.Register(
        httpmock.REST("POST", "repos/OWNER/REPO/merge-upstream"),
        httpmock.StatusStringResponse(200, `{"base_branch":"parent:main\u001b]8;;file:///etc/passwd\u0007CLICK\u001b]8;;\u0007","merge_type":"fast-forward"}`),
    )

    io, _, stdout, _ := iostreams.Test()
    io.SetStdoutTTY(true)

    opts := &SyncOptions{
        HttpClient: func() (*http.Client, error) { return &http.Client{Transport: reg}, nil },
        IO:         io,
        DestArg:    "OWNER/REPO",
    }

    err := syncRun(opts)
    require.NoError(t, err)

    // Expected (fixed) behavior: no raw ESC byte reaches the terminal buffer.
    assert.NotContains(t, stdout.String(), "\x1b",
        "base_branch from API response must be sanitized before writing to IO.Out")
}
```
Currently this assertion fails because `baseBranchLabel` is written unsanitized via `fmt.Fprintf(opts.IO.Out, ...)` in `syncRemoteRepo`.
