### Title
Unsigned webhook injection across GitHub organizations forges CI status and repository sync for any stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GithubApp`/secret to validate a webhook against using the attacker-controlled `repository.owner.login` (or `organization.login`) field from the *unverified* JSON body, and `Shipit::GithubApp#verify_webhook_signature` unconditionally returns `true` when that particular org's `webhook_secret` is blank. Handlers (`PushHandler`, `StatusHandler`) then act on a *different*, independently attacker-chosen field, `repository.full_name`/`sha`, to decide which `Stack`/`Commit` to mutate. This breaks the intended binding "organization whose signature authenticated the request" == "repository/stack actually written to."

### Finding Description
`verify_signature` picks the app config purely from payload content: [1](#0-0) [2](#0-1) 

`GithubApp#verify_webhook_signature` bypasses HMAC verification entirely whenever the selected org has no `webhook_secret` configured: [3](#0-2) 

The application explicitly supports multi-organization configuration, and the shipped test/dummy fixtures show `webhook_secret: # nil` as a normal, valid per-organization setting (`OrgTwo`): [4](#0-3) 

Once signature verification is satisfied (trivially, by naming `repository.owner.login` after the weakly-configured org), the request body is handed to handlers that resolve the target purely from other payload fields, independent of the org used for verification:
- `PushHandler#process` triggers `Stack#sync_github` for any stack whose repository matches `payload.dig('repository','full_name')`: [5](#0-4) [6](#0-5) 
- `StatusHandler#process` writes a GitHub commit status for any `Commit` matching the attacker-supplied `sha`, with attacker-controlled `state`/`context`/`description`: [7](#0-6) 

That injected status is consumed directly by the merge queue's mergeability logic, which gates automatic PR merging (`MergeRequest#all_status_checks_passed?` / `any_status_checks_failed?` / `merge!`): [8](#0-7) [9](#0-8) 
and by continuous-deployment triggering.

### Impact Explanation
The bug allows a request that is not authenticated by GitHub's real HMAC signature for the target org/repo to be treated as trusted for a *different* repository:
- An attacker who can name (or discover) any configured GitHub organization/app entry that lacks a `webhook_secret` can send a completely unsigned "status" webhook naming an arbitrary `sha` belonging to *any other* stack in the installation, forcing a fake "success" CI status that the merge queue relies on to auto-merge pull requests — an unauthorized merge/cross-repository write.
- The same technique lets an attacker force a "push" event for an arbitrary stack, causing `GithubSyncJob`/`CacheDeploySpecJob` to run, and combined with continuous deployment, can trigger an unauthorized deploy.
This satisfies the High/Critical impact bar (unauthorized merge, cross-repository write, unauthorized deploy) defined in scope.

### Likelihood Explanation
Exploitability depends entirely on the deployment having at least one configured GitHub organization/app entry with `webhook_secret` left blank while other organizations/stacks exist in the same Shipit instance. This is a supported, documented configuration shape (multi-org `github:` block in `secrets.yml`, and the shipped fixture explicitly demonstrates a nil `webhook_secret` for one org), so it is not a purely theoretical or "host misconfiguration outside the documented setup" scenario — it is a configuration the engine itself accepts and ships as an example. However, real-world exploitability requires the operator to actually have an org without a secret in a multi-org setup; in a strict single-org deployment with a secret configured, this specific cross-org vector does not apply (though the "return true unless webhook_secret" bypass is still a self-inflicted risk for that org alone).

### Recommendation
- Require `webhook_secret` to be present for every configured GitHub organization/app in production; fail closed (reject with 422/500) rather than skip verification when it's blank, or at minimum log/alert loudly and disable such orgs from participating in webhook processing.
- Bind webhook handler target resolution to the *same* verified organization used for signature verification: after verifying the signature for `repository_owner`, assert that `repository.full_name`'s owner matches `repository_owner` (or that the resolved `Repository`/`Stack` belongs to the verified organization) before acting on it.
- Consider requiring signature verification per-repository/installation rather than per-organization string parsed from the untrusted payload.

### Proof of Concept
1. Configure Shipit with two GitHub organizations, e.g. `OrgA` (has `webhook_secret: S`) and `OrgB` (no `webhook_secret`, i.e., blank/nil) — a supported configuration shown in `test/dummy/config/secrets_double_github_app.yml`.
2. Send an unsigned POST to `/github/auth/github` webhook endpoint (`WebhooksController#create`) with header `X-Github-Event: status` and body:
```json
{
  "repository": {"owner": {"login": "OrgB"}, "full_name": "OrgB/anything"},
  "sha": "<sha of a real commit belonging to a stack under OrgA>",
  "state": "success",
  "context": "ci/required-check"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "OrgB")`, whose `verify_webhook_signature` returns `true` unconditionally because `OrgB`'s `webhook_secret` is blank (no `X-Hub-Signature` header check occurs).
4. `StatusHandler#process` looks up `Commit.where(sha: params.sha)` — matching the OrgA-owned commit regardless of the `repository` field used for verification — and creates a forged "success" status via `create_status_from_github!`, which can unblock the merge queue for an OrgA stack.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
