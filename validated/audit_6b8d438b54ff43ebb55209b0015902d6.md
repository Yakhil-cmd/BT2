### Title
Spender-attested assets: definer can revoke attestation of an address that already holds a balance, permanently freezing those funds - (File: `validation.js`)

### Summary
Obyte assets can be created with `spender_attested: true`, which restricts who may hold/spend the asset to addresses on an `attestors`-approved list. The definer can update this list at any time via an `asset_attestors` message. Spend validation checks the *current* (latest stable) attestor list rather than the list that was valid when the holder received the funds. This is the exact same bug class as the reported wLP issue: an authorization/whitelist check is enforced at receive-time but re-checked (against a value that can be revoked later) at spend-time, so revoking authorization for an address that already holds a balance permanently locks that balance with no escape hatch — analogous to a user being unable to withdraw wLP collateral once it is blacklisted.

### Finding Description
When an asset has `spender_attested: true`, the definer publishes an initial `attestors` list at asset-definition time [1](#0-0) . The definer may later replace this list at will via an `asset_attestors` message; the only requirement is that the message is authored by the asset's `definer_address` — there is no restriction preventing removal of an address that currently owns unspent outputs of the asset: [2](#0-1) 

Whenever a payment in this asset is validated (whether it is an issue or a transfer), the current attestor list is loaded fresh and used to determine which addresses are "attested" at validation time: [3](#0-2) [4](#0-3) 

The transfer/spend path then requires the **owner address of the input being spent** to be in this current list, and requires **every output address** to be in it as well: [5](#0-4) [6](#0-5) 

Crucially, this check is not scoped to "was attested when the output was created" — it re-evaluates attestation against the attestor list valid at the moment of the *new* spending unit, using `objValidationState.last_ball_mci` at spend time [7](#0-6) . If the definer removes an address from the attestor list after that address already received/holds asset outputs, all of that address's existing balance becomes permanently unspendable: any attempt to use it as an input fails with `"owner address is not attested"`, and there is no code path that allows disposal/withdrawal of already-held balances despite the health/ownership of the output itself being otherwise perfectly valid.

This mirrors the wLP report precisely: the whitelist/attestation check is enforced going forward when the definer changes state, but pre-existing holders who already have legitimate custody of the asset get trapped with no way to move their funds, even to send them back to the definer or burn them (unless the definer happens to still accept them, i.e. is itself attested).

### Impact Explanation
Any spender-attested asset's definer (a single-signature action, no consensus/multi-party review) can unilaterally and permanently freeze funds belonging to any address, including an Autonomous Agent, simply by publishing a new `asset_attestors` list that omits that address. Both regular users and AAs that hold or manage this asset as part of an escrow/vault/DeFi logic can have their balances frozen with no recovery path in the protocol layer, since the transfer/issue validation always rejects operations by non-attested addresses regardless of whether the funds were legitimately acquired earlier. This is a fund-freezing risk reachable by any private-payment/asset counterparty of a spender-attested asset, matching the accepted "AA fund loss or freezing" impact category.

### Likelihood Explanation
This does not require any protocol bug beyond ordinary use of a documented asset feature (`spender_attested` + `asset_attestors`). Any asset definer who legitimately wants to revoke a compromised or non-compliant address's authorization (the exact "blacklisting" scenario acknowledged by the InitCapital sponsor) will trigger this freezing side effect on any balance that address already holds — there is no code path or documented workaround that lets the holder cash out or the definer transfer out the balance without becoming attested again.

### Recommendation
When validating a spend of a spender-attested asset's existing outputs, allow the input's owner address to be considered attested if it was attested at the time the output was created (i.e., pin/record attestation status at output-creation time rather than re-checking against the live attestor list), or explicitly allow a "withdraw-only" transfer path (e.g., always allow sending back to the definer/burning) for holders removed from the attestor list, mirroring the InitCapital recommendation to allow withdrawal of positions collateralized by de-whitelisted collateral as long as the underlying accounting invariant (balance conservation) is respected.

### Proof of Concept
1. Definer issues asset X with `spender_attested: true` and `attestors: [A]`.
2. Address H is attested by A and receives a transfer of asset X (valid, since H is currently attested) — validated per `validation.js:2115-2121` for issue/transfer author check and `2504-2507` for the actual owner check.
3. Definer publishes an `asset_attestors` message removing attestor A's endorsement of H (or replaces the attestors entirely so H is no longer attested), validated solely against `objUnit.authors[0].address === objAsset.definer_address` in `validateAttestorListUpdate` (`validation.js:2829-2848`).
4. H attempts to spend its previously-received (and still legitimately owned) output of asset X. `loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses` now returns H as not attested, and validation rejects the input with `"owner address is not attested"` (`validation.js:2506`) — H's balance is permanently stuck, with no way to transfer, burn, or return it.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

// filter only those addresses that are attested (doesn't work for light clients)
function filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAddresses, handleAttestedAddresses){
	conn.query(
		"SELECT DISTINCT address FROM attestations CROSS JOIN units USING(unit) \n\
		WHERE attestor_address IN(?) AND address IN(?) AND main_chain_index<=? AND is_stable=1 AND sequence='good' \n\
			AND main_chain_index>IFNULL( \n\
				(SELECT main_chain_index FROM address_definition_changes JOIN units USING(unit) \n\
				WHERE address_definition_changes.address=attestations.address AND main_chain_index<=? AND is_stable=1 AND sequence='good' ORDER BY main_chain_index DESC LIMIT 1), \n\
			0)",
		[objAsset.arrAttestorAddresses, arrAddresses, last_ball_mci, last_ball_mci],
		function(addr_rows){
			var arrAttestedAddresses = addr_rows.map(function(addr_row){ return addr_row.address; });
			handleAttestedAddresses(arrAttestedAddresses);
		}
	);
}

function loadAssetWithListOfAttestedAuthors(conn, asset, last_ball_mci, arrAuthorAddresses, bAcceptUnconfirmedAA, handleAsset){
	if (arguments.length === 5) {
		handleAsset = bAcceptUnconfirmedAA;
		bAcceptUnconfirmedAA = false;
	}
	readAsset(conn, asset, last_ball_mci, bAcceptUnconfirmedAA, function(err, objAsset){
		if (err)
			return handleAsset(err);
		if (!objAsset.spender_attested)
			return handleAsset(null, objAsset);
		filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAuthorAddresses, function(arrAttestedAddresses){
			objAsset.arrAttestedAddresses = arrAttestedAddresses;
			handleAsset(null, objAsset);
		});
	});
}
