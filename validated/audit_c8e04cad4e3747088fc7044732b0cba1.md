### Title
Division-by-Zero Panic in `consolidatedNode.Split()` When Both CN and CL Staking Amounts Truncate to Zero — (`kaiax/staking/staking_info.go`)

### Summary

The `consolidatedNode.Split()` function, introduced for the Prague hardfork's consensus-liquidity (CL) reward split, divides a block reward between a validator's CN staking address and its CL pool address proportionally to their staking amounts. Both amounts are stored as `uint64` values in KAIA units (truncated from kei by dividing by `1e18`). If both `cn.StakingAmount` and `cn.CLStakingInfo.CLStakingAmount` truncate to zero (i.e., both raw balances are < 1 KAIA), the denominator `totalAmount` is zero and Go's `big.Int.Div` panics unconditionally. This panic fires inside `FinalizeState()` during block reward distribution, halting every honest node that attempts to process the block.

### Finding Description

`consolidatedNode.Split()` computes the CL share of a reward as:

```go
clAmount := new(big.Int).Mul(clAmountBig, amount)
clAmount  = clAmount.Div(clAmount, totalAmount)   // panics when totalAmount == 0
``` [1](#0-0) 

`totalAmount` is the sum of two `uint64` fields that are populated by dividing raw kei values by `params.KAIA` (1 × 10¹⁸) and truncating:

```go
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
// and for CL:
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64(),
``` [2](#0-1) 

Any raw balance strictly less than 1 KAIA (< 1 × 10¹⁸ kei) truncates to 0. If both the CN staking balance and the CL pool balance are below 1 KAIA, `totalAmount = 0` and the division panics.

`Split()` is invoked unconditionally for the block proposer in both `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` whenever `cn.CLStakingInfo != nil`, with no guard on `totalAmount`:

```go
if cn.CLStakingInfo == nil {
    break
}
cnAmount, clAmount := cn.Split(proposer)   // no totalAmount > 0 check
``` [3](#0-2) 

The same unguarded call appears in the Flex variant: [4](#0-3) 

These functions are called from `getDeferredRewardFullKore` and `getDeferredRewardFullFlex`, which are the terminal reward-distribution paths executed during `FinalizeState()` for every block after the Prague hardfork. [5](#0-4) 

Note that the staking-reward allocation helpers (`assignStakingRewards`, `assignStakingRewardsFlex`) are safe because they only call `Split()` after confirming `cnTotalStakingAmount > minStake`, which guarantees a non-zero denominator. The proposer-reward path has no equivalent guard. [6](#0-5) 

### Impact Explanation

Go's `(*big.Int).Div` panics with a run-time "division by zero" when the divisor is zero. A panic inside `FinalizeState()` that is not caught by a `recover()` terminates the node process. Even if a recovery wrapper exists, the block cannot be finalized and the node stalls at that height. Because every honest node must execute the same `FinalizeState()` logic for the same block, all nodes stall or crash simultaneously — a complete chain halt. No KAIA rewards are distributed for that block or any subsequent block until the software is patched and nodes are restarted.

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}

func getDeferredRewardFullKore(config *reward.RewardConfig, execFee, burntFee, blobFee *big.Int, si *staking.StakingInfo) (*reward.RewardSpec, error) {
	var (
		spec             = reward.NewRewardSpec()
		minted           = new(big.Int).Set(config.MintingAmount)
		distributableFee = new(big.Int).Sub(execFee, burntFee)
	)

	// Distribute using RewardRatio first. Unlike Legacy, fees are not distributed here
	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.
	validators, kif, kef := config.RewardRatio.Split(minted)
	proposer, stakers := config.Kip82Ratio.Split(validators)
	ratioRemainder := calcRemainder(minted, proposer, stakers, kif, kef)
	kif.Add(kif, ratioRemainder)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.
	// After Prague, if the CLStaking is not nil, the proposer and staking rewards are proportionally distributed to both CN and CL.
	// For proposer rewards, see `specWithProposerAndFunds`.
	stakersAlloc, kip82Remainder := assignStakingRewards(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)
	stakers.Sub(stakers, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}
	spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
	return spec, nil
}
