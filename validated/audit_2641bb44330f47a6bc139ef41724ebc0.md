### Title
Unhandled synchronous `throw Error` in address-definition evaluation crashes the full node on a single crafted unit - (File: definition.js)

### Summary
The Coraza bug class is: attacker-controlled input reaches a code path that terminates the whole process instead of returning a handled error (`log.Fatalf`→`os.Exit`). ocore has an analogous pattern: several `throw Error(...)` statements are placed **inside asynchronous DB-query callbacks** in the address-definition/authentifier evaluators (`definition.js`), rather than being routed through the `cb`/`cb2` error-callback protocol that the rest of `validateDefinition`/`validateAuthentifiers` uses. Because these throws happen inside a `conn.query(...)`/`storage.readDefinitionByAddress(...)` callback, they are **not** caught by the `try{...}catch(e){...}` blocks that wrap the synchronous parts of `validate()` in `validation.js`, so they surface as a Node.js "uncaught exception". `network.js` installs a global handler that **deliberately re-throws** on `uncaughtException` to crash the process: [1](#0-0) 

### Finding Description
`definition.js` evaluates address-definition/spend-condition trees. For the `'address'` operator, when the referenced address's definition is not yet found in storage, the code falls back to looking for a matching definition supplied by one of the *current unit's own authors*: [2](#0-1) 

The same pattern (unauthenticated `throw Error("more than 1 address definition")`) is duplicated in the authentifier-evaluation path: [3](#0-2) 

If `arrDefiningAuthors.length > 1` — i.e., the posted unit contains more than one author entry whose `address` equals the referenced `other_address` and each supplies a `definition` that hashes to the required chash — the code executes an unconditional `throw Error(...)` instead of calling `cb`/`cb2` with an error string as every other branch in this function does. `objUnit.authors` is attacker-supplied array content (`arrAuthorAddresses = objUnit.authors.map(a => a.address)` in `validation.js`), and no earlier stage rejects duplicate author addresses within a single unit: [4](#0-3) 

Because this `throw` occurs inside the `ifDefinitionNotFound` callback of `storage.readDefinitionByAddress`, which itself runs inside a `conn.query` callback, it executes on a different tick of the event loop than the `try/catch` in `validate()`'s `async.series` step, so the exception is not caught locally and propagates as an uncaught exception, triggering the crash-on-purpose handler in `network.js`.

A very similar unguarded `throw Error(...)` also exists for `definition template` handling and for `storage.js` helper reads (`readAADefinition`, `readAAGetters`, `readBaseAADefinitionAndParams`), all of which execute inside async DB callbacks reached during ordinary unit/AA validation: [5](#0-4) [6](#0-5) 

### Impact Explanation
An uncaught exception thrown from validation logic reachable by any unprivileged peer posting a single crafted unit crashes the entire node process (the handler in `network.js` re-throws intentionally "to avoid ending up in an inconsistent state"). This is a full denial of service of the node — matching the accepted impact category "a network unable to confirm new units" if triggered broadly across nodes that process the same malicious unit (light vendors, hubs, and full nodes all run `validation.validate`).

### Likelihood Explanation
The trigger requires posting one unit with:
1. Two or more authors sharing the same `address` value (not rejected elsewhere in the reviewed code), and
2. An address-definition/spend condition (author `definition` field, asset condition, or referenced address condition) containing an `['address', X]` sub-expression pointing at that duplicated address, where `X`'s definition is not yet known to storage, and
3. At least two of the duplicate-address authors each supply a `definition` field that hashes (via `objectHash.getChash160`) to the chash required at that point in the tree.

This requires careful unit construction but no special privileges, keys of other parties, or network position — an ordinary unit poster can build and broadcast it. I was not able to fully confirm (within available search budget) that no other earlier validation step explicitly forbids duplicate author addresses in a single unit; this is the main remaining uncertainty and should be checked directly against `validateAuthors`/`validateAuthor` in `validation.js` before treating this as confirmed-exploitable.

### Recommendation
Replace every unconditional `throw Error(...)` inside async DB-callback branches of `definition.js` (and the analogous ones in `storage.js`) with the standard error-callback pattern already used elsewhere in the same functions (`return cb("more than 1 address definition")` / `return cb2(false)` / `return handleDefinition(null)` etc.), so malformed/adversarial unit content always results in a normal `ifUnitError`/validation failure rather than an uncaught exception. Additionally, consider explicitly rejecting units where two authors share the same address as an early, synchronous validation check.

### Proof of Concept
Conceptual construction (exact byte-level unit crafting would need to be built with the wallet/composer libraries):
1. Compose a unit with two authors, both with `address = X` (same base32 address).
2. Have both authors include an `authors[i].definition` array that hashes (via `object_hash.getChash160`) to the same `definition_chash` that is required by an `['address', X]` clause used either as one author's own top-level address definition, or referenced from a spend condition/asset condition evaluated during `validateDefinition`/`validateAuthentifiers`.
3. Ensure address `X`'s definition is not already stored (fresh/never-used address), so `storage.readDefinitionByAddress` calls `ifDefinitionNotFound`.
4. Broadcast the unit to a node. `evaluate()`'s `'address'` case will find `arrDefiningAuthors.length === 2 > 1` and execute `throw Error("more than 1 address definition")` inside the async DB callback, escaping all try/catch blocks and reaching the global `uncaughtException` handler, which re-throws and crashes the node process.

function readAADefinition(conn, address, to_mci, handleDefinition) {
	if (!handleDefinition)
		return new Promise(resolve => readAADefinition(conn, address, to_mci, (arrDefinition, unit, storage_size) => resolve({ arrDefinition, unit, storage_size })));
	if (to_mci === null || to_mci === Infinity)
		to_mci = MAX_INT32;
	conn.query("SELECT definition, unit, storage_size, mci FROM aa_addresses WHERE address=? AND mci<=?", [address, to_mci], function (rows) {
		if (rows.length !== 1)
			return handleDefinition(null);
		var arrDefinition = JSON.parse(rows[0].definition);
		if (arrDefinition[0] !== 'autonomous agent')
			throw Error("non-AA definition in AA unit");
		handleDefinition(arrDefinition, rows[0].unit, rows[0].storage_size);
	});
}

function readBaseAADefinitionAndParams(conn, address, to_mci, handleDefinitionAndParams) {
	if (!handleDefinitionAndParams)
		return new Promise(resolve => readBaseAADefinitionAndParams(conn, address, to_mci, (arrBaseDefinition, params, storage_size) => resolve({ arrBaseDefinition, params, storage_size })));

	});
}
