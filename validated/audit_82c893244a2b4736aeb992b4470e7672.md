### Title
Denial of Service via unvalidated `xpubkey` in multi-device wallet creation causes unhandled exception in address derivation - (File: wallet_defined_by_keys.js)

### Summary
`handleOfferToCreateNewWallet` and `addDeviceXPubKey` in `wallet_defined_by_keys.js` accept an attacker/peer-controlled `my_xpubkey` string from a paired device and store it in the `extended_pubkeys` table with only a length check (`body.my_xpubkey.length > 112`), never validating that it is a well-formed BIP32 extended public key. The value is later fed unmodified into `Bitcore.HDPublicKey(xPubKey)` / `.derive(path)` in `derivePubkey()` when addresses are derived for the shared wallet, with no surrounding `try/catch`.

### Finding Description
- `wallet.js` routes the `my_xpubkey` device message to `walletDefinedByKeys.addDeviceXPubKey`, only checking it is a non-empty string ≤112 characters: [1](#0-0) 
- `addDeviceXPubKey` stores the raw string directly into `extended_pubkeys.extended_pubkey` with no format validation: [2](#0-1) 
- `handleOfferToCreateNewWallet` similarly never validates `xpubkey`-shaped fields beyond generic string/array checks before it reaches `validateWalletDefinitionTemplate` and eventually `addWallet`, which persists the caller-controlled `xPubKey`: [3](#0-2) [4](#0-3) 
- The unvalidated value is later parsed as a BIP32 extended key with no exception handling: [5](#0-4) 

`Bitcore.HDPublicKey(xPubKey)` performs base58check decoding and structural parsing of the extended-key payload (version bytes, depth, fingerprint, chain code, public key) — exactly the class of length/structure-prefixed binary parsing implicated in the reported `dhowden/tag` CVE (`readPICFrame` indexing without bounds checks). If the string is not valid base58, has a bad checksum, or is truncated/malformed length, `bitcore-lib`'s internal buffer slicing/parsing throws (e.g. `TypeError`/`RangeError`/"Invalid checksum"/out-of-range slice errors). Because none of `derivePubkey`, `deriveAddress`, or `checkAddress` wrap this call in `try/catch`, the exception propagates out of the `db.query` callback, escaping as an unhandled exception on the node's event loop.

### Impact Explanation
An unhandled exception thrown from inside an asynchronous DB callback in Node.js is not caught by any surrounding `try/catch` (since the call stack for that tick starts fresh); it becomes an uncaught exception at the process level, crashing the ocore/hub/wallet process (`process.on('uncaughtException')` is not shown to be a safety net here). Because `deriveAddress`/`checkAddress` run automatically whenever the wallet needs to hand out new addresses (e.g., processing incoming payments, generating change addresses, or a paired device polling `checkAddress`), a single malformed `my_xpubkey` device message from any paired device (which is explicitly in scope as a reachable attacker per the rules) can crash the victim's node whenever wallet address derivation is triggered — a persistent denial of service against a wallet/hub node, requiring the corrupted DB record to be manually cleaned up to recover.

### Likelihood Explanation
The `my_xpubkey` message is explicitly documented as "allowed from non-correspondents" (`wallet.js:162`), meaning any paired or even loosely-verified device can send it directly with no signature/PoW cost. The check `body.my_xpubkey.length > 112` only bounds length; it does nothing to validate base58/checksum/structure, so an attacker can trivially craft a 112-character string that is accepted, stored, and later triggers a parser exception in `bitcore-lib`. No special conditions are needed beyond pairing with the target device (a normal, low-friction protocol interaction), making this readily reachable.

### Recommendation
- Validate `my_xpubkey` (and any xpubkey passed via `create_new_wallet`) strictly as a well-formed BIP32/BIP44 extended public key before persisting it, e.g., by attempting `new Bitcore.HDPublicKey(xPubKey)` inside a `try/catch` at ingestion time in `addDeviceXPubKey`/`handleOfferToCreateNewWallet`, rejecting malformed keys with `callbacks.ifError(...)`.
- Wrap all later uses of stored extended pubkeys (`derivePubkey`, `deriveAddress`, `checkAddress`) in `try/catch` so a corrupted/malicious stored value degrades gracefully (skip/mark wallet as broken) instead of crashing the process.
- Add a global safety net (or confirm one exists) so that async exceptions from library calls on peer-supplied data cannot terminate the whole node process.

### Proof of Concept
1. Pair device B with device A (victim), forming or joining a multi-signature wallet (`create_new_wallet` handshake).
2. From device B, send device A a `my_xpubkey` message: `{ wallet: "<valid wallet id>", my_xpubkey: "<111-character malformed but syntactically-string value, e.g. "A".repeat(111)>" }`.
3. `addDeviceXPubKey` stores this string in `extended_pubkeys.extended_pubkey` unchecked.
4. Once the wallet is (or appears) fully approved and device A needs to derive a new address (e.g., `deriveAddress`/`checkAddress`, triggered by normal wallet operation such as issuing a receiving address or verifying a payment), `derivePubkey(row.extended_pubkey, path)` calls `new Bitcore.HDPublicKey("AAAA...A")`.
5. `bitcore-lib` throws while base58check-decoding/parsing the malformed key; the exception is unhandled inside the `db.query` callback and crashes device A's ocore process.

*Note: I was unable to execute `bitcore-lib` directly in this environment to confirm the exact exception type/message it throws for malformed input, and could not verify whether a top-level `process.on('uncaughtException')` handler exists elsewhere in the deployment to catch and restart the process; if such a handler silently recovers, impact would be reduced to a caught error/log rather than a crash, though repeated triggering would still degrade the affected wallet functionality.*

function handleOfferToCreateNewWallet(body, from_address, callbacks){
	if (!ValidationUtils.isNonemptyString(body.wallet))
		return callbacks.ifError("no wallet");
	if (!ValidationUtils.isNonemptyString(body.wallet_name))
		return callbacks.ifError("no wallet_name");
	if (body.wallet.length > constants.HASH_LENGTH)
		return callbacks.ifError("wallet too long");
	if (body.wallet_name.length > 200)
		return callbacks.ifError("wallet_name too long");
	body.wallet_name = body.wallet_name.replace(/[<>]/g, '');
	if (!ValidationUtils.isArrayOfLength(body.wallet_definition_template, 2))
		return callbacks.ifError("no definition template");
	if (!ValidationUtils.isNonemptyArray(body.other_cosigners))
		return callbacks.ifError("no other_cosigners");
	for (var i=0; i<body.other_cosigners.length; i++){
		var cosigner = body.other_cosigners[i];
		if (!ValidationUtils.isNonemptyObject(cosigner))
			return callbacks.ifError("bad cosigner");
		if (!ValidationUtils.isStringOfLength(cosigner.pubkey, constants.PUBKEY_LENGTH))
			return callbacks.ifError("bad pubkey");
		if (cosigner.device_address !== objectHash.getDeviceAddress(cosigner.pubkey))
			return callbacks.ifError("bad cosigner device address");
		if (!ValidationUtils.isNonemptyString(cosigner.name))
			return callbacks.ifError("no cosigner name");
		if (cosigner.name.length > 100)
			return callbacks.ifError("cosigner name too long");
		cosigner.name = cosigner.name.replace(/[<>]/g, '');
		if (!ValidationUtils.isNonemptyString(cosigner.hub))
			return callbacks.ifError("no cosigner hub");
		if (cosigner.hub.length > 100)
			return callbacks.ifError("cosigner hub too long");
	}
	// the wallet should have an event handler that requests user confirmation, derives (or generates) a new key, records it, 
	// and sends the newly derived xpubkey to other members
	validateWalletDefinitionTemplate(body.wallet_definition_template, from_address, function(err, arrDeviceAddresses){
		if (err)
			return callbacks.ifError(err);
		if (body.other_cosigners.length !== arrDeviceAddresses.length - 1)
			return callbacks.ifError("wrong length of other_cosigners");
		var arrOtherDeviceAddresses = _.uniq(body.other_cosigners.map(function(cosigner){ return cosigner.device_address; }));
		arrOtherDeviceAddresses.push(from_address);
		if (!_.isEqual(arrDeviceAddresses.sort(), arrOtherDeviceAddresses.sort()))
			return callbacks.ifError("wrong other_cosigners");
		eventBus.emit("create_new_wallet", body.wallet, body.wallet_definition_template, arrDeviceAddresses, body.wallet_name, body.other_cosigners, body.is_single_address);
		callbacks.ifOk();
	});
}

		"INSERT "+db.getIgnore()+" INTO extended_pubkeys (wallet, device_address) VALUES(?,?)",

				"UPDATE extended_pubkeys SET extended_pubkey=?, approval_date="+db.getNow()+" WHERE wallet=? AND device_address=?",

					eventBus.emit('wallet_approved', wallet, device_address);

	);
}

function derivePubkey(xPubKey, path){
	var hdPubKey = new Bitcore.HDPublicKey(xPubKey);
	return hdPubKey.derive(path).publicKey.toBuffer().toString("base64");
}

function deriveAddress(wallet, is_change, address_index, handleNewAddress){
	db.query("SELECT definition_template, full_approval_date FROM wallets WHERE wallet=?", [wallet], function(wallet_rows){
		if (wallet_rows.length === 0)
			throw Error("wallet not found: "+wallet+", is_change="+is_change+", index="+address_index);
		if (!wallet_rows[0].full_approval_date)
			throw Error("wallet not fully approved yet: "+wallet);
		var arrDefinitionTemplate = JSON.parse(wallet_rows[0].definition_template);
		db.query(
			"SELECT device_address, extended_pubkey FROM extended_pubkeys WHERE wallet=?", 
			[wallet], 
			function(rows){
				if (rows.length === 0)
					throw Error("no extended pubkeys in wallet "+wallet);
				var path = "m/"+is_change+"/"+address_index;
				var params = {};
				rows.forEach(function(row){
					if (!row.extended_pubkey)
						throw Error("no extended_pubkey for wallet "+wallet);
					params['pubkey@'+row.device_address] = derivePubkey(row.extended_pubkey, path);
					console.log('pubkey for wallet '+wallet+' path '+path+' device '+row.device_address+' xpub '+row.extended_pubkey+': '+params['pubkey@'+row.device_address]);
				});
				var arrDefinition = Definition.replaceInTemplate(arrDefinitionTemplate, params);
				var address = objectHash.getChash160(arrDefinition);
				handleNewAddress(address, arrDefinition);
			}
		);
	});
}
