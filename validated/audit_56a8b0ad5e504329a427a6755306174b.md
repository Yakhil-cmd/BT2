### Title
Webhook signature verified against one organization's secret while handlers act on an unvalidated `repository.full_name` from the same payload, allowing cross-organization/repository writes - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate an inbound webhook using `repository_owner`, computed as `params.dig('repository', 'owner', 'login')` (or `organization.login`). All the actual `Shipit::Webhooks` handlers, however, resolve the target repository/stack independently from `payload.dig('repository', 'full_name')`. These are two separate, attacker-controlled JSON fields inside the same webhook body that are never cross-checked against each other.

### Finding Description
The controller flow is: [1](#0-0) [2](#0-1) 

`repository_owner` is used only to pick which `GitHubApp` (and thus which `webhook_secret`) verifies the HMAC signature, via `Shipit.github(organization: repository_owner)`: [3](#0-2) 

Shipit supports a multi-tenant configuration where each organization key under `secrets.github` has its own independent `webhook_secret`: [4](#0-3) [5](#0-4) 

Once `verify_signature` passes, the exact same raw `params` (including the untouched `repository.full_name`) is forwarded unchanged to every handler for the event: [6](#0-5) 

Every handler determines the repository/stack it operates on solely from `payload.dig('repository', 'full_name')`, never from `repository.owner.login`: [7](#0-6) 

This pattern repeats across handlers, e.g. `PushHandler#process` triggers `stack.sync_github` for any stack matching `full_name` + branch: [8](#0-7) 

and `StatusHandler#process` writes GitHub commit statuses for any commit matching `params.sha`, independent of which repository/org authenticated the request: [9](#0-8) 

The root cause is the equality that should hold but is never enforced: `organization that authenticated (repository.owner.login used for secret selection) == organization of the repository that is written (repository.full_name used by handlers)`. Because both values live in the same JSON body and are attacker-supplied, an entity that controls only the webhook secret for Organization A (e.g., an admin of a repository under Org A that is itself onboarded to this Shipit instance) can forge a payload where `repository.owner.login = "org-a"` (verified successfully with Org A's secret) but `repository.full_name = "org-b/victim-repo"`. The signature check passes, and the handler layer then acts on `org-b/victim-repo`, a stack the attacker never authenticated for.

### Impact Explanation
This breaks the trust boundary between organizations configured in the same Shipit instance: possession of one organization's webhook secret is sufficient to inject spoofed `push`, `status`, `check_suite`, `pull_request`, or `membership` events against any other organization/repository/stack tracked by the same Shipit deployment. Concretely this can be used to:
- Trigger `sync_github` / SHA updates for a victim stack via `PushHandler`, or
- Forge `commit_status`/`check_suite` events via `StatusHandler`/`CheckSuiteHandler` for arbitrary victim commits, which can flip `deployable_status` gating and enable an **unauthorized deploy** of a stack the attacker does not control.

This matches the High/Critical impact bucket "cross-repository writes" / "unauthorized deploy" defined in scope.

### Likelihood Explanation
Requires the attacker to already control (or have leaked) the webhook secret of at least one organization onboarded to the target Shipit instance — a lower bar than compromising the victim organization directly, and plausible in any multi-tenant Shipit deployment where multiple, differently-trusted GitHub orgs share one Shipit install. The request itself is a single crafted HTTP POST with mismatched `repository.owner.login` and `repository.full_name`; no other authentication artifact (session, `ApiClient` token, GitHub App private key) is needed.

### Recommendation
After `verify_signature` succeeds, re-derive and enforce that the organization used to select the webhook secret equals the owner segment of `repository.full_name` (and of `organization.login`, if present) before dispatching to handlers; reject the request otherwise. Alternatively, have `Shipit::Webhooks::Handlers::Handler#repository_name` validate that its owner matches the organization that was used to authenticate the specific delivery, and have `WebhooksController` pass that authenticated organization identity down to handlers instead of relying purely on payload content.

### Proof of Concept
1. Configure/compromise webhook secret for organization `org-a` on the shared Shipit instance (attacker has legitimate admin access to a repo in `org-a` that is registered as a Shipit stack, so they know the secret they configured on GitHub's webhook settings for that repo).
2. Craft a `push` (or `status`) webhook JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<victim-sha>",
  "repository": {
    "owner": { "login": "org-a" },
    "full_name": "org-b/victim-repo"
  }
}
```
3. Compute `X-Hub-Signature: sha1=<hmac using org-a's webhook_secret>` over the raw body.
4. POST to `/webhooks` with `X-Github-Event: push`. `verify_signature` resolves `repository_owner = "org-a"`, fetches `org-a`'s `GitHubApp`, and the HMAC verifies successfully.
5. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, which resolves `stacks` from `payload.dig('repository', 'full_name') == "org-b/victim-repo"` and calls `stack.sync_github(expected_head_sha: "<victim-sha>")` on the victim stack in `org-b`, an organization the attacker never authenticated against.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
