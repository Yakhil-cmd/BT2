### Title
NType Cross-Contamination in NEIGHBORS Response Allows Attacker-Controlled Nodes to Corrupt CN Discovery Storage — (`networks/p2p/discover/udp.go`, `table_data.go`, `table_bond.go`)

---

### Summary

A bonded remote attacker can respond to a FINDNODE(TargetType=EN) request with a NEIGHBORS packet whose packet-level `TargetType` is `NodeTypeEN` (passing the only type-level guard) but whose individual `rpcNode.NType` fields are set to `NodeTypeCN`. Because `nodeFromRPC` never validates `rn.NType` against the pending request's `targetType`, the returned nodes carry `NType=CN`. They survive `bondall`, and `addNode` routes them into `storages[NodeTypeCN]` — the CN flatStorage — corrupting it with attacker-controlled entries that were discovered via an EN lookup.

---

### Finding Description

**The only packet-level guard** is in `loop()`: [1](#0-0) 

```go
if r.data.(*neighbors).TargetType != p.targetType {
    continue
}
```

This checks the `neighbors.TargetType` field of the outer packet — not the per-node `rpcNode.NType` fields inside it. An attacker sets `neighbors.TargetType = NodeTypeEN` to pass this check, while setting each `rpcNode.NType = NodeTypeCN`.

**`nodeFromRPC` performs no NType validation against targetType:** [2](#0-1) 

```go
func (t *udp) nodeFromRPC(sender *net.UDPAddr, rn rpcNode) (*Node, error) {
    if rn.UDP <= 1024 { ... }
    if err := netutil.CheckRelayIP(...); err != nil { ... }
    ...
    n := NewNode(rn.ID, rn.IP, rn.UDP, rn.TCP, nil, rn.NType)  // rn.NType is attacker-controlled
    err := n.validateComplete()
    return n, err
}
```

`validateComplete` checks structural completeness, not type consistency with the lookup context.

**The `findnode()` callback** collects these nodes and returns them: [3](#0-2) 

**`findNodesOnce` only filters BN nodes, not NType mismatches:** [4](#0-3) 

```go
if targetType != NodeTypeBN {
    r = removeBn(r)
}
return tab.bondall(r)   // CN-typed nodes pass through
```

**`bondall` → `Bond` → `addNode` routes by `n.NType`:** [5](#0-4) [6](#0-5) 

```go
func (tab *Table2) addNode(n *Node) {
    ...
    if s := tab.storages[n.NType]; s != nil {
        s.add(n)   // n.NType=CN → storages[NodeTypeCN].add(n)
    }
}
```

**The CN storage is a `flatStorage` with no eviction limit:** [7](#0-6) [8](#0-7) 

`pushNode` is called with `math.MaxInt64` as the cap, so attacker nodes accumulate without bound and legitimate CNs are never evicted — but the attacker can dilute the storage arbitrarily.

---

### Impact Explanation

`RandomNodes(buf, NodeTypeCN)` draws from `storages[NodeTypeCN]`: [9](#0-8) 

As the attacker floods the CN flatStorage, the probability that `RandomNodes` returns attacker-controlled nodes increases proportionally. The `p2p.DialSched` uses these nodes to establish outbound CN connections. A victim CN node that dials attacker-controlled peers as CNs is progressively eclipsed from the legitimate consensus peer set, which can cause it to fail to participate in consensus — a durable loss of core chain functionality and potential consensus divergence.

---

### Likelihood Explanation

- The attacker must be **bonded** with the victim (requires a completed PING/PONG exchange — a public, permissionless P2P flow).
- The attacker must be reachable so that `bondall` succeeds for the injected nodes (the attacker controls those nodes and can respond to PING).
- The victim's `doRefresh` → `simpleRefresh(NodeTypeCN)` and `kademliaRefresh(NodeTypeEN)` run on a timer, so the victim will naturally send FINDNODE to any bonded seed node, including the attacker.
- No privileged access, governance keys, or cryptographic breaks are required. [10](#0-9) 

---

### Recommendation

In `nodeFromRPC` (or in the `findnode()` pending callback), reject any `rpcNode` whose `NType` does not match the `targetType` of the pending request:

```go
// In nodeFromRPC, add a targetType parameter and validate:
if rn.NType != targetType && rn.NType != NodeTypeBN {
    return nil, errors.New("node type mismatch with lookup target type")
}
```

Alternatively, enforce the check inside the `findnode()` callback before appending to `nodes`.

---

### Proof of Concept

1. Attacker node A completes PING/PONG with victim V → A is bonded.
2. V's `doRefresh` calls `kademliaRefresh(NodeTypeEN)` → `lookup(selfID, NodeTypeEN, ...)` → `findNodesOnce(A, selfID, NodeTypeEN, ...)` → `udp.findnode(A.ID, A.addr, selfID, NodeTypeEN, max)`.
3. A receives FINDNODE(TargetType=EN). A responds with NEIGHBORS(TargetType=EN, Nodes=[{ID=X, IP=X.IP, NType=NodeTypeCN}]) where X is an attacker-controlled node that responds to PING.
4. V's `loop()` matches the pending (TargetType=EN matches), calls the callback, which calls `nodeFromRPC` → returns Node{NType=CN}.
5. `findNodesOnce` calls `bondall([Node{NType=CN}])` → `Bond(false, Node{NType=CN})` → pingpong succeeds (X responds) → `addNode(Node{NType=CN})` → `storages[NodeTypeCN].add(Node{NType=CN})`.
6. Assert: `tab.storages[NodeTypeCN]` now contains X. `RandomNodes(buf, NodeTypeCN)` returns X. V dials X as a CN.

		return nil
	}

		r = removeBn(r)
	}
	// Out of the find results, return only reachable (bonded) nodes.
