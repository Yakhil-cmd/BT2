### Title
Unbounded RAY debt valuation overflows during accrual and permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
The protocol bounds the borrow index at `MAX_BORROW_INDEX_RAY`, but it does not bound the market’s scaled debt against the value produced by multiplying that debt by the new index. `accrue_step` computes `borrowed * new_borrow_index / RAY` after index growth, and unrepresentable results raise `MathOverflow` instead of being clamped or prevented. Since every market operation accrues before mutating state, reaching this numerical boundary can freeze repayment, withdrawal, liquidation, and forced index updates for the affected market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Controller.update_indexes(caller, assets)` is reachable by an unprivileged caller and forwards each `HubAssetKey` to pool accrual. [4](#0-3) [3](#0-2)  Pool accrual calls `global_sync`, which invokes `accrue_step` for each elapsed-time chunk. [5](#0-4) [6](#0-5) 

`accrue_step` first computes utilization from the scaled totals and then grows the borrow index. [7](#0-6)  `update_borrow_index` clamps only the index itself to `MAX_BORROW_INDEX_RAY`; it does not account for the magnitude of `borrowed`. [1](#0-0)  `calculate_supplier_rewards` subsequently reconstructs total debt with `borrowed.mul(old_borrow_index)` and `borrowed.mul(new_borrow_index)`. [8](#0-7) 

`Ray::mul` delegates to `mul_div_half_up`, whose result must fit `i128`; otherwise the function panics with `GenericError::MathOverflow`. [9](#0-8) [10](#0-9)  Thus an index value can remain below its explicit cap while the corresponding total debt value exceeds the representable RAY domain. The protocol documentation confirms that valid caps and bounded indexes do not guarantee future accrual values fit, and that the overflow blocks repayment and withdrawal because those operations accrue first. [11](#0-10) 

### Impact Explanation
This can permanently freeze all supplier principal, borrower collateral backing the market, unclaimed supplier yield, and protocol revenue in the affected market. [3](#0-2) [11](#0-10) 

`supply`, `borrow`, `withdraw`, `repay`, and `liquidate` are exposed through the controller, while `update_indexes` provides a permissionless accrual trigger. [12](#0-11) [13](#0-12) [14](#0-13)  Once `borrowed * borrow_index / RAY` can no longer be represented, every path that loads and accrues the market panics before it can reduce debt, release collateral, socialize bad debt, or withdraw supply. The repository’s regression test demonstrates that `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW` after the boundary is reached. [15](#0-14) 

### Likelihood Explanation
The condition requires an extremely large market and enough elapsed high-rate accrual for the scaled debt value to approach `i128::MAX`, so ordinary deployments are unlikely to reach it quickly. [16](#0-15)  However, token amounts up to roughly 170 billion whole tokens are within the protocol’s admitted numeric domain, and a sufficiently large capped or effectively uncapped market can enter the vulnerable region through ordinary `supply` and `borrow` calls. [17](#0-16) [18](#0-17) 

The in-repository test uses a one-billion-token, 18-decimal market with 98% utilization and demonstrates the cliff before `MAX_BORROW_INDEX_RAY` is reached. [19](#0-18)  No privileged action is needed at trigger time because any caller can invoke `update_indexes` once time has advanced. [14](#0-13) [3](#0-2) 

### Recommendation
Bound the scaled-share and index product, not merely the index. At minimum, derive an effective per-market index ceiling such as `min(MAX_BORROW_INDEX_RAY, maximum_index_for(borrowed))` where `maximum_index_for` guarantees that both old and new `borrowed * index / RAY` values fit `i128`. The analogous bound should be applied to `supplied * supply_index / RAY`, since utilization and supplier reward distribution also multiply total supply by its index. [20](#0-19) [21](#0-20) 

Prefer a bounded-index design that stops interest accrual at the representable-value ceiling while preserving repayment and withdrawal, rather than reverting after the state is reached. Entry-side share caps should also account for the configured index ceiling so a newly admitted position cannot already sit outside the future representable domain. Add regression coverage that forces `update_indexes`, `repay`, `withdraw`, `liquidate`, and `clean_bad_debt` at the boundary and asserts exits remain possible. [22](#0-21) [23](#0-22) 

### Proof of Concept
The repository already contains a matching regression test in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`. It creates an 18-decimal market, supplies `1_000_000_000 * 10^18` units through `supply`, supplies collateral through a second account, borrows 98% of the market through `borrow`, advances ledger time, and repeatedly calls `update_indexes` for `BIG18`. [24](#0-23) 

The failing sequence is:

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);

let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}
```

The observed error is `MATH_OVERFLOW`, and the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. Subsequent `withdraw` and `repay` calls fail with the same error because both operations perform accrual before their mutation. [25](#0-24)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
