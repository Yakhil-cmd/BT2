### Title
Webhook organization-to-secret binding is decoupled from the repository the payload actually writes to - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp`/`webhook_secret` to validate the HMAC signature against using the `repository.owner.login` (or `organization.login`) field taken from the *unverified* JSON body itself [1](#0-0) [2](#0-1) . Downstream, `Handler#stacks` resolves the target `Repository`/`Stack` using a *different* field of the same payload, `repository.full_name` [3](#0-2) . Nothing enforces that these two fields refer to the same organization, so the "organization that authenticated" is not bound to the "repository that is written."

### Finding Description
`Shipit.github(organization:)` looks up a per-organization webhook secret from `github_app_config(organization)` when Shipit is configured with multiple organizations [4](#0-3) . The webhook controller picks the organization to verify against purely from attacker-supplied JSON:
```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`verify_webhook_signature` then HMACs the *entire raw body* against that org's secret [5](#0-4) . Since the HMAC covers the whole body and the attacker fully controls the body's contents (they only need to know their own org's genuine webhook secret, obtained legitimately by installing the Shipit integration on their own GitHub org/repo), they can freely set `repository.owner.login` to their own org (so the correct/known secret is selected and the signature validates) while independently setting `repository.full_name` to any other org/repo string, e.g. a victim stack's repository. `Handler#stacks` (used by `push_handler.rb`, `status_handler.rb`, `check_suite_handler.rb`, and the `pull_request/*` handlers) resolves the affected `Stack` purely via `Repository.from_github_repo_name(payload.dig('repository', 'full_name'))` [3](#0-2) [6](#0-5) , with no cross-check against `repository_owner`/the organization whose secret validated the signature.

### Impact Explanation
This breaks the equality that should hold: `organization authenticated by signature == organization/repository the event is applied to`. An attacker who legitimately owns/administers their own GitHub organization (and therefore legitimately possesses that organization's webhook secret through the normal Shipit GitHub App installation flow — not a Shipit credential, not a privileged Shipit account) can forge webhook deliveries that are accepted as authentic for a completely different, victim-owned stack. Depending on which handler is targeted, this can drive `push`/`status`/`check_suite` driven pipeline reactions (commit status/CI state updates that gate `autodeploy` on other stacks) and `pull_request` handlers (auto-provisioning, labeling, merge/close flows) against a stack the attacker does not control, without any legitimate GitHub event from the real repository ever having occurred. This crosses a repository/organization trust boundary using only credentials the attacker legitimately owns for an unrelated repository — i.e., an unauthorized cross-repository state change.

### Likelihood Explanation
Requires only: (1) the target Shipit deployment to be configured with per-organization GitHub App/webhook secrets (the multi-org schema explicitly supported by `github_app_config`), and (2) the attacker to control/own any one of those configured organizations (which they can do without any interaction with the victim, victim credentials, or Shipit accounts) to obtain a legitimate webhook secret for that org, and (3) knowledge of the victim's exact `owner/name` repository string, which is not secret. No Shipit login, ApiClient token, or GitHub App private key is needed.

### Recommendation
Bind the signature-selected organization to the repository actually mutated: after selecting the `GitHubApp`/secret via `repository_owner`, require that the resolved `Repository`/`Stack`'s owner matches `repository_owner` (or the org used for verification) before dispatching to handlers, and reject the webhook otherwise. Alternatively, resolve the target `Stack` first from `repository.full_name`, derive the owner from that same field, and always verify the signature against that owner's secret rather than a separately-read field.

### Proof of Concept
1. Attacker installs the Shipit GitHub App / configures a webhook integration on their own GitHub organization `attacker-org`, legitimately obtaining `webhook_secret_attacker`.
2. Attacker crafts a raw JSON body for, e.g., a `push` event where `repository.owner.login = "attacker-org"` and `repository.full_name = "victim-org/victim-repo"` (a real Shipit-managed stack they do not own).
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(webhook_secret_attacker, raw_body)>` and POSTs to `/webhooks` with header `X-Github-Event: push`.
4. `verify_signature` calls `repository_owner` → `"attacker-org"`, fetches `Shipit.github(organization: "attacker-org")`, and validates the signature successfully because the attacker used their own genuine secret over their own chosen body.
5. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, whose `stacks` method (inherited from `Handler`) resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and applies the push-event logic (e.g., updating latest commit / triggering autodeploy checks) to `victim-org`'s stack — despite the signature never having been validated against `victim-org`'s own webhook secret.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
