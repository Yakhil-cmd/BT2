### Title
Unauthenticated `ServiceChainResponse` Injection via P2P Allows Malicious Peer to Control All Parent-Chain RPC Answers — (`node/sc/sub_bridge_handler.go`, `node/sc/remote_backend.go`)

---

### Summary

`HandleMainMsg` in `sub_bridge_handler.go` writes the raw bytes of any `ServiceChainResponse` P2P message directly into the in-process `net.Pipe` that backs the `rpc.Client` used by `RemoteBackend`, with no authentication, no MAC, and no request-response correlation. Because the bridge P2P handshake only checks public parameters (`networkId`, `chainID`), any node that can reach the SubBridge P2P port can register as a peer and inject arbitrary JSON-RPC responses, making `BalanceAt`, `TransactionReceipt`, `FilterLogs`, and every other `RemoteBackend` call return attacker-controlled values.

---

### Finding Description

**Step 1 — The in-process pipe**

`NewRpcClientP2P` creates a `net.Pipe()` pair `(p1, p2)`. `p1` is stored as `sb.rpcConn` via `SetRPCConn`; `p2` is wrapped as the `rpc.Client`'s codec. [1](#0-0) 

**Step 2 — Outbound path (request)**

A goroutine in `SetRPCConn` reads JSON-RPC request bytes from `p1` and forwards them to `rpcSendCh`. The `loop()` goroutine drains `rpcSendCh` and calls `SendRPCData`, which calls `peer.SendRequestRPC(data)` — sending the request over P2P as a `ServiceChainCall` message. [2](#0-1) [3](#0-2) 

**Step 3 — Inbound path (response) — the vulnerable sink**

When a `ServiceChainResponse` P2P message arrives from any registered peer, `HandleMainMsg` decodes the raw bytes and writes them unconditionally to `sbh.subbridge.rpcConn.Write(data)` — i.e., directly into `p1`, which feeds the `rpc.Client` on `p2`. There is no HMAC, no sequence number, no request-ID correlation, and no signature check. [4](#0-3) 

**Step 4 — Permissive peer admission**

`SubBridge.handle()` admits any peer that completes the handshake. The handshake only verifies `networkId` and `chainID` — both public, static values — and does not require any cryptographic proof of identity. [5](#0-4) [6](#0-5) 

**Step 5 — Affected `RemoteBackend` methods**

Every method that calls `rb.rpcClient.CallContext(...)` is affected: `BalanceAt`, `TransactionReceipt`, `TransactionReceiptRpcOutput`, `FilterLogs`, `SubscribeFilterLogs`, `CallContract`, `PendingNonceAt`, `SuggestGasPrice`, `EstimateGas`, `CurrentBlockNumber`, and `CodeAt`. [7](#0-6) 

---

### Impact Explanation

`RemoteBackend` is the sole source of truth the bridge manager uses to observe parent-chain bridge contract state. A malicious peer that injects a crafted `kaia_getLogs` response containing fabricated `RequestValueTransfer` log entries causes the bridge manager to treat those events as real deposits on the parent chain and call `HandleValueTransfer` on the child-chain bridge contract, minting bridged tokens on the child chain with no corresponding parent-chain deposit. Similarly, injecting a fake `kaia_getTransactionReceipt` response can make the bridge believe a deposit transaction was confirmed when it was not. The result is unauthorized minting/unlocking of bridged assets and corruption of the bridge's canonical view of parent-chain state.

---

### Likelihood Explanation

The attacker must reach the SubBridge's P2P port (TCP, typically 50505) and supply the correct `networkId` and `chainID` — both public values. No private key, no operator credential, and no majority-validator collusion is required. The Kaia code itself contains no peer-identity whitelist and no authentication of `ServiceChainResponse` payloads, satisfying the "Kaia code fails to authenticate it" exception in the scope rules.

---

### Recommendation

1. **Authenticate responses**: Derive a shared secret during the P2P handshake (e.g., ECDH on the peer's node key) and use it to HMAC-sign every `ServiceChainResponse` payload; verify the MAC in `HandleMainMsg` before writing to `rpcConn`.
2. **Correlate request/response**: Embed the JSON-RPC `id` field in the P2P envelope and reject any response whose `id` does not match an outstanding request.
3. **Peer allowlist**: Enforce a configurable allowlist of parent-chain node IDs in `SubBridge.handle()` so that only operator-designated nodes can register as bridge peers.

---

### Proof of Concept

```
1. Start a SubBridge node with a known networkId and chainID.
2. Dial its P2P port with a custom node; complete the bridge StatusMsg handshake
   (send networkId + chainID — no secret required).
3. Wait for a ServiceChainCall P2P message (the SubBridge forwarding a
   kaia_getLogs or kaia_getTransactionReceipt request).
4. Reply with a ServiceChainResponse whose payload is a crafted JSON-RPC
   response, e.g.:
     {"jsonrpc":"2.0","id":1,"result":[<fake RequestValueTransfer log>]}
5. Observe that RemoteBackend.FilterLogs() returns the attacker-controlled log.
6. The bridge manager processes the fake log as a real deposit event and
   calls HandleValueTransfer on the child-chain bridge contract, minting
   tokens with no parent-chain deposit.
```

func (sb *SubBridge) SetRPCConn(conn net.Conn) {
	sb.rpcConn = conn

	go func() {
		for {
			data := make([]byte, rpcBufferSize)
			rlen, err := sb.rpcConn.Read(data)
			if err != nil {
				if err == io.EOF {
					logger.Trace("EOF from the rpc pipe")
					time.Sleep(100 * time.Millisecond)
					continue
				} else {
					// If no one closes the pipe, this situation should not happen.
					logger.Error("failed to read from the rpc pipe", "err", err, "rlen", rlen)
					return
				}
			}
			sb.rpcSendCh <- data[:rlen]
		}
	}()
}

func (sb *SubBridge) SendRPCData(data []byte) error {
	peers := sb.BridgePeerSet().peers
	logger.Trace("send rpc message from the subbridge", "len", len(data), "peers", len(peers))
	for _, peer := range peers {
		err := peer.SendRequestRPC(data)
		if err != nil {
			logger.Error("SendRPCData Error", "err", err)
		}
		return err
	}
	logger.Trace("send rpc message from the subbridge, done")

	return nil
}

		number = head.Number.Uint64()

	if err != nil {
		p.GetP2PPeer().Log().Debug("Kaia peer handshake failed", "err", err)
		fmt.Println(err)
		return err
	}

func (p *baseBridgePeer) Handshake(network uint64, chainID, td *big.Int, head common.Hash) error {
	// Send out own handshake in a new thread
	errc := make(chan error, 2)
	var status statusData // safe to read after two values have been received from errc

	go func() {
		errc <- p2p.Send(p.rw, StatusMsg, &statusData{
			ProtocolVersion: uint32(p.version),
			NetworkId:       network,
			TD:              td,
			CurrentBlock:    head,
			ChainID:         chainID,
		})
	}()
	go func() {
		e := p.readStatus(network, &status)
		if e != nil {
			errc <- e
			return
		}
		errc <- e
	}()
	timeout := time.NewTimer(handshakeTimeout)
	defer timeout.Stop()
	for range 2 {
		select {
		case err := <-errc:
			if err != nil {
				return err
			}
		case <-timeout.C:
			return p2p.DiscReadTimeout
		}
	}
	p.td, p.head, p.chainID = status.TD, status.CurrentBlock, status.ChainID
	return nil
