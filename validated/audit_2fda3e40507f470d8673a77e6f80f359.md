### Title
`flash_position` lets any caller weaponize the controller's `execute_flash_position` callback against third-party receivers that gate only on the `controller` address argument — (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The controller's `flash_position` entrypoint lets any unprivileged caller name an arbitrary WASM contract as `receiver` and supply arbitrary `data`. The controller then invokes `execute_flash_position` on that contract, passing the *genuine* controller address as the `controller` argument and the caller as `initiator`. Because the controller performs the callback with a plain `env.invoke_contract` and never registers an `authorize_as_current_contract` entry, a callee can never satisfy `controller.require_auth()` — so the only viable integration check is comparing the `controller` argument, which is authentic for *any* caller. A third-party receiver that trusts that argument (the documented check) and executes the plan embedded in `data` will transfer its tokens to the controller, where they are measured and deposited as collateral on the **attacker's** account — the exact analog of the FloodPlain `sourceConsideration` spoofing bug, where a hook's arbitrary call impersonates the protocol contract to a victim fulfiller.

### Finding Description
`process_flash_position` accepts `receiver` and `data` from the caller with only a WASM-contract check on `receiver` (`require_wasm_receiver`, same gate used in `contracts/controller/src/strategies/flash_loan.rs:26`). Debt is minted and the minted tokens are forwarded to `receiver`, then `invoke_receiver` performs an arbitrary cross-contract call with a fixed function name and attacker-controlled payload: [1](#0-0) [2](#0-1) 

Key facts:
- `invoke_receiver` hardcodes the function name `execute_flash_position` and passes `initiator = caller`, the real `controller` address, and verbatim attacker `data`.
- `env.invoke_contract` carries no invoker-contract authorization; the controller never calls `env.authorize_as_current_contract` for this call. Therefore `cfg.controller.require_auth()` inside a receiver can never succeed, and the only discriminator available to integrators is the `controller` argument — which is always the true controller, regardless of who initiated `flash_position`.
- After the callback, the controller measures positive balance deltas of declared `collaterals`, requires only a caller-set `min_amount`, and deposits them on the caller's account (`collect_collateral_deposits`). [3](#0-2) 

This mirrors the report: in FloodPlain, the `SELECTOR_EXTENSION` check failed to prevent a hook from calling `IFulfiller::sourceConsideration` with `msg.sender == FloodPlain`; here, nothing prevents `flash_position` from delivering a controller-originated `execute_flash_position` call to *any* contract the attacker names. The integration docs themselves acknowledge receivers can only compare the `controller` argument and must additionally bind `initiator`/account to avoid unintended plans — i.e., the protocol deliberately emits a spoofable trusted-caller callback. [4](#0-3) 

### Impact Explanation
Theft of user funds held by third-party `execute_flash_position` receivers (rebalancers, leverage bots, treasury contracts). An attacker crafts `data` as the victim's own plan format instructing it to transfer its token inventory to `controller`. The controller credits those tokens as collateral on the attacker's account; the victim holds only the forwarded debt tokens, which do not repay the minted debt (`INV-STRAT-04`: returned debt is never auto-repaid). The attacker keeps a solvent leveraged position collateralized by stolen funds — economically equivalent to draining the victim, net of the LTV haircut. Any existing receiver that validates `controller` but not `initiator`/`account_id`/`data` is fully drained of whatever tokens it pushes per the crafted plan. [5](#0-4) 

### Likelihood Explanation
Reachable by a single unprivileged address via `controller.flash_position(caller, account_id, spoke_id, mode, debt, amount, receiver, data, collaterals, refund_assets)` — no roles, allowlists, or signatures beyond the caller's own auth. Requirements: the debt market is `is_flashloanable`, the victim contract exports a function named `execute_flash_position`, and the victim gates on the `controller` argument while executing instructions from `data` without binding `initiator`. This is the same preconditions class as the external report (a fulfiller checking `msg.sender`/magic arg but not the caller) and is the default integration shape, since `require_auth` on the controller is unusable (no invoker auth is registered).

### Recommendation
Bind the callback to the caller cryptographically instead of relying on callee-side argument checks:
- Register an `authorize_as_current_contract` entry covering the `execute_flash_position` invocation (receiver, args including `initiator`, `account_id`, `data` hash) immediately before `invoke_contract`, so receivers can enforce `controller.require_auth()` and get a host-verified caller proof.
- Alternatively/additionally, pass a caller-supplied `expected_initiator` that the controller asserts equals `caller`, and document that `controller` argument equality alone conveys no authorization.
- At minimum, document prominently that the controller will invoke `execute_flash_position` on *any* contract any user names, so receivers must pin `initiator` and decode `data` strictly.

### Proof of Concept
Conceptual trace (no code changes needed):
1. Victim `Rebalancer` contract stores `cfg.controller = <controller>`; its `execute_flash_position` does `if controller != cfg.controller { panic }`, decodes `data` into `(collateral, amount)` and calls `token.transfer(self, controller, amount)`. It holds 1M USDC inventory.
2. Attacker calls `controller.flash_position(attacker, 0, spoke, Multiply, debt=(USDC), amount=small, receiver=Rebalancer, data=<victim plan XDR: collateral=XLM, amount=1M>, collaterals=[(XLM, 1)], refund_assets=[USDC])`.
3. Controller mints debt, forwards to `Rebalancer`, calls `Rebalancer.execute_flash_position(initiator=attacker, ..., controller=<real controller>, data)`. Victim's check `controller == cfg.controller` passes; it transfers 1M XLM to the controller.
4. Controller measures the XLM delta ≥ min, deposits it as collateral on attacker's new account, refunds leftover USDC to attacker; solvency gates pass since the stolen collateral covers the minted debt.
5. Result: attacker's account holds 1M XLM collateral against `small` debt; victim lost its inventory. Host re-entry rules and `FlashLoanOngoing` do not apply — the victim is a distinct contract and the callback is the intended code path. [6](#0-5) [7](#0-6)

```rust
fn collect_collateral_deposits(
    env: &Env,
    controller: &Address,
    collaterals: &Vec<(HubAssetKey, i128)>,
    before: &Map<Address, i128>,
) -> Vec<(HubAssetKey, i128)> {
    let mut deposits: Vec<(HubAssetKey, i128)> = Vec::new(env);
    for (hub_asset, min_amount) in collaterals.iter() {
        let baseline = before
            .get(hub_asset.asset.clone())
            .unwrap_or_else(|| panic_with_error!(env, GenericError::InternalError));
        let delta = balance_delta_since(env, &hub_asset.asset, controller, baseline);
        assert_with_error!(
            env,
            delta >= min_amount,
            StrategyError::CollateralMinimumNotMet
        );
        if delta > 0 {
            deposits.push_back((hub_asset, delta));
        }
    }
    assert_with_error!(
        env,
        !deposits.is_empty(),
        StrategyError::CollateralMinimumNotMet
    );
    deposits
}
```

```markdown
### INV-STRAT-04 — Flash position retains debt and supply

Flash position mints debt without an origination fee and never automatically
repays returned debt tokens. Every declared collateral minimum must be
non-negative, with at least one positive minimum. The controller measures
callback receipts against those minima, deposits positive receipts and
remeasures the pool's receipt.

Before and after account finalization, the borrowed market must retain positive
scaled debt and the account must retain supply. Returned debt becomes
collateral if declared, returns to the caller if refund-listed, or remains
uncredited if in neither list. Refunds cover only positive callback balance
changes.
```

```rust
/// Returns the temporary flash-loan flag, defaulting to false.
pub(crate) fn is_flash_loan_ongoing(env: &Env) -> bool {
    env.storage()
        .temporary()
        .get(&SessionKey::FlashLoanOngoing)
        .unwrap_or(false)
}

/// Sets the temporary flash-loan flag, or removes it when clearing.
pub(crate) fn set_flash_loan_ongoing(env: &Env, ongoing: bool) {
    if ongoing {
        env.storage()
            .temporary()
            .set(&SessionKey::FlashLoanOngoing, &true);
    } else {
        env.storage()
            .temporary()
            .remove(&SessionKey::FlashLoanOngoing);
    }
}

/// Runs `f` with the flash-loan flag set; preserves an already-active outer guard.
pub(crate) fn with_flash_guard<T>(env: &Env, f: impl FnOnce() -> T) -> T {
    let prev = is_flash_loan_ongoing(env);
    set_flash_loan_ongoing(env, true);
    let out = f();
    if !prev {
        set_flash_loan_ongoing(env, false);
    }
    out
```
