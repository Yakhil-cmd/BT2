### Title
`repository.owner.login`/`repository.full_name` split lets an unauthenticated webhook write another repository's `PullRequest` record - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the HMAC secret to check by looking at `repository.owner.login` (via `repository_owner`), but every handler — including `AssignedHandler` — resolves the repository/stack it actually mutates from `repository.full_name`. An attacker who names an organization with no `webhook_secret` configured in `repository.owner.login` gets `verify_webhook_signature` to unconditionally return `true`, while pointing `repository.full_name` at any other tracked repository, causing the handler to write to that unrelated repository's data.

### Finding Description
The broken binding is:
`repository_owner (used to pick the verifying secret) == owner(repository.full_name) (used to select the mutated repo/stack)`
This is never enforced.

- `verify_signature` in [1](#0-0)  computes `github_app = Shipit.github(organization: repository_owner)` from `params.dig('repository','owner','login')` and calls `github_app.verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` at [2](#0-1)  does `return true unless webhook_secret` — i.e., if the org resolved from `repository.owner.login` has no configured secret, **any** signature (or none) is accepted.
- `AssignedHandler#repository` at [3](#0-2)  resolves the repository from `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, entirely independent of `repository_owner`.
- `AssignedHandler#process`/`#pull_request` at [4](#0-3)  looks up and updates the persisted `Shipit::PullRequest` for that (different) repository's stacks: `pull_request.update(github_pull_request: params.pull_request)`.

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `action: "assigned"`, `repository.owner.login = "org-with-no-secret"`, `repository.full_name = "victim-org/victim-repo"`. Because `org-with-no-secret` has no `webhook_secret` in Shipit's GitHub app config, `verify_webhook_signature` returns `true` without checking anything, so the request passes `before_action :verify_signature` regardless of signature/HMAC. `AssignedHandler` then finds and updates the real `PullRequest` record belonging to `victim-org/victim-repo`'s stack.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type is handled; `verify_signature` explicitly derives the app/secret from the owner field but never cross-checks it against `full_name`'s owner; `ExplicitParameters` (the `params do ... end` schema) validates structure/types only, not that `repository.owner.login` matches `repository.full_name`'s owner segment.

### Impact Explanation
This lets a payload nominally "authenticated" (or unauthenticated, if the selected org has no secret) for one repository/organization mutate a `PullRequest` record belonging to a completely different, unrelated repository/stack — matching the "payload for one repository mutating another's stack, commit, task or team" Critical category. The write itself is limited to the cached `github_pull_request` JSON blob on `Shipit::PullRequest` for `AssignedHandler`; I could not confirm within the explored code that `AssignedHandler#process` itself triggers any deploy, merge, or `ContinuousDeliveryJob` side effect — it only calls `pull_request.update(...)`, with no visible callback chain to deploy logic in the files inspected. The continuous_deployment/`ContinuousDeliveryJob` amplification claimed in the question is therefore not substantiated by what was reviewed; the confirmed, demonstrable impact is the cross-repository data write itself.

### Likelihood Explanation
Preconditions: Shipit must have at least one configured GitHub organization/app entry with no `webhook_secret` set (a plausible, common misconfiguration, e.g. for a test/staging org or an org added without secret rotation), and a victim stack/repository with an existing tracked `PullRequest`. The attacker needs no credentials, no Shipit account, and no knowledge of any real webhook secret — only the ability to send an HTTP POST to `/webhooks` with a crafted JSON body. This is fully repeatable against any repository whose owner/name is known, for every organization lacking a secret.

### Recommendation
Enforce that the organization used to verify the webhook signature is the same organization that owns the repository/stack the handler will mutate — i.e., derive/validate both from the same field (`repository.full_name`'s owner segment), and reject the request if `repository.owner.login` doesn't match the owner parsed from `repository.full_name`. Additionally, do not treat a missing `webhook_secret` as "verified": either require a secret for all configured organizations, or fail closed (`return false`) when no secret is configured for production organizations to prevent an attacker from choosing an unsecured org to bypass verification while targeting another org's data.

```ruby
test "assigned event with owner/full_name split writes to unrelated stack's pull request" do
  victim_stack = shipit_stacks(:shipit) # repo e.g. "victim-org/victim-repo"
  pr = shipit_pull_requests(:one)       # belongs to victim_stack, number: N
  assert_not_equal 'unrelated_login', victim_stack.repository.owner

  request.headers['X-Github-Event'] = 'pull_request'
  body = {
    action: 'assigned',
    number: pr.number,
    pull_request: { id: 1, number: pr.number, url: 'x', title: 'x', state: 'open',
                     additions: 1, deletions: 1,
                     head: { sha: 'a'*40, ref: 'feature' },
                     user: { login: 'attacker' },
                     assignees: [{ login: 'attacker' }],
                     labels: [] },
    repository: { owner: { login: 'unrelated-org-with-no-secret' },
                   full_name: victim_stack.repository.github_repo_name },
    sender: { login: 'attacker' }
  }.to_json

  # Simulate Shipit.github(organization: 'unrelated-org-with-no-secret') having no webhook_secret configured
  # so verify_webhook_signature returns true regardless of X-Hub-Signature.

  post :create, body:, as: :json

  pr.reload
  assert_equal 'attacker', pr.github_pull_request['assignees'].first['login']
  # Assert this happened despite the signature having been verified against
  # an org unrelated to victim_stack.repository.owner, proving
  # repository_owner != owner(repository.full_name) was never checked.
end
```

```ruby
      github_app = Shipit.github(organization: repository_owner)
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
