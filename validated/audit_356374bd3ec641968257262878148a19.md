### Title
Cross-AA information leak through unisolated error/trace formatting in `remote_func_call` bounces - (File: `formula/error/errorFormatter.js`, `formula/evaluation.js`)

### Summary
When an AA (or a trigger author invoking `dryRunPrimaryAATrigger`) calls a remote AA's getter via `remote_func_call` and that getter fails (`bounce`/`require`/comparison failure/etc.), the resulting `fatal_error` is passed through `formatError()` which reconstructs and returns the **remote AA's own formula source lines** (`codeLines`), the **comparison operands' actual values** (`formatComparisonContext`), and a full cross-AA call `trace` (caller AA, getter AA, xpath, line numbers) back to the caller/trigger context. This information crosses the AA-to-AA trust/ownership boundary the same way the Firefox bug allowed script-execution error handling to leak information across origins.

### Finding Description
`formula/evaluation.js` evaluates `remote_func_call` by invoking `callGetter()` on a different AA address and propagating any error straight back to the calling AA's evaluation context [1](#0-0) . Errors raised anywhere in oscript evaluation (including inside the *remote* AA's getter) are captured by `setFatalError()`, which builds an `errorData` object containing the raw AST context and the full `astTrace` accumulated across AA/getter boundaries, then runs it through `formatError()` and stores the result as `fatal_error.formattedError` [2](#0-1) .

`formatError()` (in `formula/error/errorFormatter.js`) reconstructs the **source formula lines of whichever AA/getter is on the trace** via `buildCodeLines()`/`getFormulaByLine()`, and if the failure was a comparison, it renders the actual left/right operand values via `formatComparisonContext()` [3](#0-2) [4](#0-3) . It also emits a `trace` array naming every AA address and getter function traversed, with `line`/`xpath` details [5](#0-4) [6](#0-5) .

This formatted error is attached directly to the bounced response returned by the AA composer to whoever posted the trigger, as shown in the existing test where a remote getter's `bounce("==5")` produces a response containing the **remote AA's line/formula and its address**, fully visible to the trigger's poster [7](#0-6) .

Unlike a same-context oscript error (where the failing formula belongs to the AA that is itself processing the trigger and whose logic is already public), a `remote_func_call` crosses an AA ownership boundary: the caller AA (and, transitively, whoever triggers the caller) can force evaluation of arbitrary code paths inside a target AA's getters (bounded only by `checkMaxRemoteComplexity`) and, on failure, receive back verbatim source lines and evaluated operand values from that AA's logic — including comparison operands that may embed values read from the target AA's own state vars/balances via `readVar`/`readBalance` (`case 'var': case 'balance':`) evaluated earlier in the same getter execution [8](#0-7) . If getter code compares a private/sensitive internal state value against a caller-supplied argument (a common oscript pattern, e.g. `if ($secret_var == $guess) bounce(...)`), an attacker can brute-force or binary-search the target AA's private state by repeatedly calling the getter with different arguments and reading the `formatComparisonContext` values or bounce message returned in the trace — a cross-AA state disclosure that the getter author did not intend to expose, mirroring the "error handling incorrectly isolated" root cause of CVE-2025-5263.

### Impact Explanation
This does not directly cause double-spend or fund loss, but it constitutes an unintended data-disclosure channel between AAs that violates the isolation getters are supposed to provide (getters are meant to expose only their designed return value, not raw comparison operands or full source with all local values). An attacker-controlled trigger unit can be crafted to intentionally trigger failures in a victim AA's getter logic through a caller AA, and the failure diagnostics returned in the bounced response can disclose sensitive internal values (private state vars, balances, or values derived from private-payment reveal messages processed earlier in the same DAG) that the AA logic never intended to return via its public getter interface.

### Likelihood Explanation
Reachable by any unprivileged unit poster: compose a trigger to an AA whose oscript calls `remote_func_call` against a target getter (or directly craft an AA with a `remote_func_call` chain), choosing arguments designed to make the target getter's comparison/require/bounce fail on a value derived from the target's private state. No special privilege, and no primary-vs-secondary AA trigger restriction, is required — this is exercised by ordinary `dryRunPrimaryAATrigger`/live trigger flows shown in the existing test suite.

### Recommendation
Do not propagate the target/remote AA's `formattedError` (source lines, comparison operand values, or full cross-AA `trace`) back through `remote_func_call` failures to the calling context. When an error originates inside a different AA's getter than the one that is finally responding to the trigger, the composer should replace the detailed formatted error with a generic, address-scoped failure (e.g., `"remote getter <aa> failed"`) and strip `codeLines`/`formattedContext`/operand values before it is included in `arrResponses[].response.error`. Only the top-level AA actually being invoked by the trigger poster should have its own logic/errors surfaced in full detail.

### Proof of Concept
Based on the existing regression test pattern (`test/aa_composer.test.js:1625-1712`): define a remote AA whose getter compares a private state variable to the caller-supplied argument and bounces with the comparison result, then define a caller AA that does `remote_aa.$f(trigger.data.x)`. Trigger the caller AA with varying `trigger.data.x` values and observe that the returned `response.error` (via `formattedContext`/`codeLines`/`trace`) discloses the remote AA's formula text, comparison operands, and call trace — allowing an external unprivileged user to infer internal state of the remote AA it should not otherwise be able to read via its getter interface. function formatComparisonContext(context) {
	const { left = {}, right = {}, op = '' } = context;

	const leftCode = renderOp(unwrapAstNode(left.var_name));
	const rightCode = renderOp(unwrapAstNode(right.var_name));

	const leftVal = `${left.val}(${left.type})`;
	const rightVal = `${right.val}(${right.type})`;

	return `${leftCode} ${op} ${rightCode}\n${leftVal} ${op} ${rightVal}`;
}

function buildAAFrame(frame, nextFrame, traceLine, defaultXpath) {
	const aaFrame = { type: FRAME_TYPES.AA, aa: frame.aa };

	aaFrame.xpath = frame.xpath ?? defaultXpath;
	aaFrame.line = nextFrame?.call_line ?? traceLine;

	if (aaFrame.xpath === undefined) delete aaFrame.xpath;
	if (aaFrame.line === undefined) delete aaFrame.line;

	return aaFrame;
}

function buildGetterFrame(frame, getterFuncName, functionsAfterGetter, traceLine) {
	const getterFrame = {
		type: FRAME_TYPES.GETTER,
		aa: frame.aa,
		xpath: '/getters',
		name: getterFuncName ?? frame.name,
	};

	if (functionsAfterGetter.length > 1) {
		getterFrame.line = functionsAfterGetter[1]?.call_line ?? traceLine;
	} else {
		getterFrame.line = traceLine ?? frame.call_line;
	}

	if (getterFrame.name === undefined) delete getterFrame.name;
	if (getterFrame.line === undefined) delete getterFrame.line;

	return getterFrame;
}

function buildCodeLines(ctx) {
	const { allLinesFromArr, line, lastFormula, snapshotsByLine, aaPath, gettersAA, aaFormulas } = ctx;

	const formulaState = {
		snapshotsByLine,
		aaPath,
		gettersAA,
		aaFormulas,
		lastFormula,
	};
	const effectiveFormula = resolveTargetFormula(line, formulaState);

	const hasLines = allLinesFromArr.length > 0;
	const hasLine = line !== undefined;
	const linesToExtract = hasLines ? allLinesFromArr : (hasLine ? [line] : []);

	return linesToExtract.map(lineNum => {
		const formula = getFormulaByLine(effectiveFormula, lineNum);
		return { lineNumber: lineNum, formula };
	});
}
