### Title
Webhook signature is verified against the organization derived from `repository.owner.login`/`organization.login`, while the sync job it authorizes acts on the unrelated `repository.full_name` field - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
In a multi-organization Shipit deployment (`Shipit.github_organizations` / per-org `secrets.github` blocks), the webhook endpoint selects which GitHub App/`webhook_secret` to validate a delivery against using one payload field, but the handler that actually mutates state (triggers a git sync of a stack) trusts a *different* payload field that is never tied to the verified organization. This breaks the binding "organization that authenticated the payload" == "repository that gets written to."

### Finding Description
`WebhooksController#verify_signature` picks the `GitHubApp` (and therefore the `webhook_secret` used for HMAC verification) using: [1](#0-0) 
i.e. `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, then calls: [2](#0-1) 

`Shipit.github(organization:)` looks up a config block per organization, and each organization can have its own (or no) `webhook_secret`: [3](#0-2) 
Critically, if an organization's `webhook_secret` is not configured, verification is a no-op: `verify_webhook_signature` returns `true` unless a `webhook_secret` is present: [4](#0-3) 

After passing (or trivially bypassing) this check, `WebhooksController#create` dispatches the **entire raw JSON body** to handlers: [5](#0-4) 

`PushHandler`/`Handler` resolve the target `Stack` using a *different* field of the same payload — `repository.full_name` — with no cross-check against the `repository.owner.login`/`organization.login` value used for signature selection: [6](#0-5) [7](#0-6) 

This mirrors the EIP-4337 report's structural bug class: the entrypoint validates one facet of the operation (aggregator/sender) but never binds it to the facet that is actually executed. Here, the entrypoint (`WebhooksController`) validates trust against `repository.owner.login`, but the executed action (`stack.sync_github`) is bound to `repository.full_name` — two independently attacker-controlled JSON fields with no equality enforced between them.

### Impact Explanation
In any Shipit deployment configured with the documented multi-organization schema (`github: { orgA: {...}, orgB: {...} }`, see `docs/setup.md` and `config/secrets.development.example.yml`), if even one configured organization omits `webhook_secret` (which the docs mark as *optional*), an unauthenticated internet client can:
1. POST to `/webhooks` with `X-Github-Event: push`, `repository.owner.login` (or `organization.login`) set to the org that has *no* `webhook_secret` (verification auto-passes),
2. but `repository.full_name` set to a **different, secret-protected organization's** stack repository.

This forces `Repository.from_github_repo_name` to resolve a real, protected stack and triggers `stack.sync_github(expected_head_sha: params.after)` — an unauthenticated, cross-organization write trigger against a repository the attacker has no GitHub credentials for, causing Shipit to sync/track an arbitrary attacker-chosen commit SHA as the stack's head. Depending on downstream consumers of sync (deploy eligibility, commit tracking), this can influence what gets deployed, satisfying the "unauthorized deploy"-adjacent / cross-repository-write class of impact.

### Likelihood Explanation
Requires the operator to have configured multiple GitHub organizations with at least one lacking a `webhook_secret` — a configuration explicitly presented as valid/optional in `docs/setup.md` and the example secrets files. No attacker credentials, session, or GitHub App key are required; the `/webhooks` endpoint is unauthenticated by design (it's the entrypoint for GitHub itself), so the only bar is the operator's own configuration choice, which the engine does nothing to prevent or warn about.

### Recommendation
Bind the two facets together: derive the target repository/stack strictly from the same organization identity that was cryptographically verified (i.e., after selecting the `GitHubApp`/secret via `repository_owner`, require that `repository.full_name`'s owner segment matches `repository_owner` before dispatching to handlers), and/or require `webhook_secret` to be mandatory (fail closed) for every configured organization rather than treating it as optional.

### Proof of Concept
1. Operator configures two orgs in `secrets.github`: `orgA` (no `webhook_secret`) and `orgB` (has `webhook_secret`, and owns the real, tracked stack `orgB/prod-app`).
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": { "full_name": "orgB/prod-app", "owner": { "login": "orgA" } }
}
```
No `X-Hub-Signature` header, or an arbitrary garbage value, is needed.
3. `verify_signature` computes `repository_owner` = `"orgA"` → `Shipit.github(organization: "orgA")` → `webhook_secret` is blank → `verify_webhook_signature` returns `true` unconditionally [8](#0-7) .
4. `create` proceeds and dispatches to `PushHandler`, which resolves the stack via `repository.full_name` = `"orgB/prod-app"` [6](#0-5) , and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on `orgB`'s protected stack — despite the attacker never possessing `orgB`'s `webhook_secret`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
