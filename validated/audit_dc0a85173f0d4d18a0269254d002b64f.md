### Title
Webhook signature verification key is selected from an unauthenticated payload field, allowing cross-organization webhook forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks *which* organization's webhook secret to validate against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted, not-yet-verified request body, then calls `GitHubApp#verify_webhook_signature`, which unconditionally returns `true` when that organization's `webhook_secret` is blank. [1](#0-0) [2](#0-1)  Because the "organization that authenticated" (the `login` used solely for secret lookup) is never bound to the "repository that is actually written" (`repository.full_name`, `sha`, `ref`, etc. consumed later by the event handlers), an attacker can forge a webhook by claiming to be an organization that has no `webhook_secret` configured while pointing the rest of the payload's repository/commit data at a completely different, secret-protected stack.

### Finding Description
`verify_signature` resolves the signing secret like this:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 

`Shipit.github(organization:)` looks up the per-organization config (in the documented multi-app setup) and instantiates a `GitHubApp` scoped to whatever organization name was found in the body: [4](#0-3) 

`GitHubApp#verify_webhook_signature` then does:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [2](#0-1) 

The setup docs explicitly document `webhook_secret` as **optional** per organization: [5](#0-4)  and the multi-org example config shows each org getting its own independent `webhook_secret` entry: [6](#0-5) 

The root cause: the field used to choose the verification key (`repository.owner.login`) is not cryptographically bound to the fields the downstream handlers use to decide *what to mutate* (`repository.full_name`, `sha`, `ref`, etc., consumed by handlers such as `PushHandler`, which matches stacks purely by `branch`/`repository` name parsed from the same untrusted body) [7](#0-6) . Nothing enforces that the organization whose secret validated the signature is the same organization that owns the repository being acted on. If any one configured organization in a multi-app deployment has an empty `webhook_secret` (a documented, valid configuration), `verify_webhook_signature` returns `true` for **any** payload, so an attacker only needs to set `repository.owner.login`/`organization.login` to that no-secret org's name while supplying a forged `repository.full_name`, `sha`, `state`, `ref`, etc. targeting a stack that actually belongs to a different, secret-protected organization.

### Impact Explanation
This breaks the trust binding "organization authenticated == repository written." A completely unauthenticated attacker (no session, no `ApiClient` token, no GitHub write access) can:
- Forge `status` events to mark arbitrary commits on a victim stack as `success`, which (combined with continuous deployment) can trigger an unauthorized deploy of attacker-chosen commits. [8](#0-7) 
- Forge `push` events to trigger `GithubSyncJob` against arbitrary tracked stacks. [7](#0-6) 
- Forge `membership` events to add/remove arbitrary GitHub-team members from Shipit's authorization model. [9](#0-8) 

This maps to the Critical/High impact bar: unauthorized deploy via spoofed commit status, or escalation into `Shipit.github_teams` authorization via forged membership events.

### Likelihood Explanation
Requires a deployment that configures multiple GitHub organizations (`github_app_config`) where at least one configured org has intentionally left `webhook_secret` blank — a state explicitly documented as acceptable. [6](#0-5)  Given that this is a supported, documented configuration path (not a misconfiguration outside the engine's control), and organization names are typically public, the likelihood of a real-world multi-org deployment having one such org is realistic, though it does depend on that specific configuration existing.

### Recommendation
Do not select the verification secret from an unauthenticated field of the same message being verified. Either (a) require `webhook_secret` to be present for every configured organization and refuse to boot/verify otherwise, or (b) verify the signature against every configured organization's secret (or a global secret) rather than the one named inside the untrusted payload, and only after verification succeeds use the payload to determine which organization/repository is affected. Additionally, cross-check that the resolved GitHub App organization actually owns the `repository.full_name` referenced in the payload before dispatching to handlers.

### Proof of Concept
1. Deploy Shipit with two configured organizations, `OrgA` (no `webhook_secret` set) and `OrgB` (has `webhook_secret`, hosts the real target stack/repo).
2. POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<victim-stack-commit-sha>",
  "state": "success",
  "context": "ci/travis",
  "repository": { "full_name": "OrgB/victim-repo", "owner": { "login": "OrgA" } }
}
```
No `X-Hub-Signature` header (or any garbage value) is required.
3. `verify_signature` resolves `repository_owner` = `"OrgA"`, fetches `Shipit.github(organization: "OrgA")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally — request passes verification.
4. `Shipit::Webhooks.for_event('status')` handlers then process the payload using `repository.full_name` = `"OrgB/victim-repo"`, creating/marking a `Status` on `OrgB`'s commit as `success`, potentially triggering continuous deployment for `OrgB`'s stack — despite the request never being signed by `OrgB`'s (or any) real secret.

Note: full confirmation that handler repo-matching (`Shipit::Webhooks::Handlers::Handler#stacks`) resolves purely from `repository.full_name` independent of the GitHub App organization used for signature selection could not be fully traced to source in this session (only referenced via grep matches in `app/models/shipit/webhooks/handlers/handler.rb`); this should be verified directly in a follow-up review, though `PushHandler`'s use of `stacks.where(branch:)` without any organization/owner cross-check strongly supports the described exploit path.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
