### Title
`GasTarget == 0` Unguarded Division in `NextMagmaBlockBaseFee` Causes Node-Wide Panic via Governance Vote — (`params/kip71_config.go`)

---

### Summary

`NextMagmaBlockBaseFee` in `params/kip71_config.go` explicitly guards against `BaseFeeDenominator == 0` to prevent a divide-by-zero panic, but contains no equivalent guard for `GasTarget == 0`. The `Kip71GasTarget` governance parameter is registered with `noopFormatChecker`, meaning any `uint64` value — including `0` — passes format validation and can be committed to chain state via a governance vote. Once `GasTarget == 0` is active, every block that carries non-zero gas usage triggers an integer divide-by-zero panic inside `NextMagmaBlockBaseFee`, halting all honest nodes simultaneously and causing permanent consensus divergence.

---

### Finding Description

**Root cause 1 — `noopFormatChecker` for `Kip71GasTarget`**

`kaiax/gov/param.go` registers the `kip71.gastarget` parameter with `noopFormatChecker`, which unconditionally returns `true` for any value:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // accepts 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` also uses `noopFormatChecker`, but the runtime code in `NextMagmaBlockBaseFee` explicitly handles the `BaseFeeDenominator == 0` case:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64) // fallback to avoid panic
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
``` [2](#0-1) 

No analogous guard exists for `GasTarget`.

**Root cause 2 — Unguarded division by `gasTarget` in `NextMagmaBlockBaseFee`**

When `parentGasUsed > gasTarget` (which is always true when `gasTarget == 0` and any gas is used), execution reaches:

```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← panic: divide by zero
``` [3](#0-2) 

The symmetric branch (gas below target) has the same unguarded division:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← panic: divide by zero
``` [4](#0-3) 

**Root cause 3 — `ValidateGenesisConfig` does not validate KIP71 parameters**

`ValidateGenesisConfig` checks only `ChainID`, `Istanbul`, `Governance/Reward` presence, and interval non-zero values. It performs no validation of any `KIP71Config` field, so a genesis file with `kip71.gastarget = 0` is accepted without error:

```go
func ValidateGenesisConfig(g *blockchain.Genesis) error {
    // checks ChainID, Istanbul, Governance/Reward, intervals
    // NO check of KIP71 fields at all
    return nil
}
``` [5](#0-4) 

**Call sites that trigger the panic on every block**

`NextMagmaBlockBaseFee` is called on every block after the Magma fork in at least three production paths:

- `blockchain/chain_makers.go` `makeHeader` (block generation)
- `work/worker.go` `commitNewWork` (mining)
- `blockchain/tx_pool.go` `reset` (tx pool update after each head) [6](#0-5) [7](#0-6) [8](#0-7) 

---

### Impact Explanation

Once `kip71.gastarget = 0` is committed to chain state (either via genesis or governance vote), every subsequent block that includes at least one transaction causes `NextMagmaBlockBaseFee` to panic with an integer divide-by-zero. Because this function is called synchronously during block processing and tx-pool reset, **all honest nodes crash simultaneously** on the same block, producing permanent consensus divergence. No block can ever be finalized again on that chain.

This satisfies the allowed impact: *"Invalid state transition … or consensus divergence on honest nodes."*

---

### Likelihood Explanation

**Governance vote path (semi-trusted trigger):** In `single` governance mode the governing node submits `governance.vote("kip71.gastarget", 0)`. The `noopFormatChecker` accepts the value; it is stored and applied after the next epoch boundary. No other actor needs to be involved.

**Genesis path:** A chain operator who supplies a genesis file with `"gastarget": 0` will initialize a chain that panics on the first non-empty block after the Magma fork. `ValidateGenesisConfig` does not catch this.

The governing node is a semi-trusted actor — trusted to govern, but not to halt the chain. The missing guard is the repository's own defect that enables this abuse.

---

### Recommendation

1. **Add a runtime guard in `NextMagmaBlockBaseFee`** analogous to the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    gasTarget = 1 // or return lowerBoundBaseFee; document the fallback
}
```

2. **Replace `noopFormatChecker` for `Kip71GasTarget`** with a checker that rejects zero:

```go
Kip71GasTarget: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v > 0
    },
    ...
},
``` [1](#0-0) 

3. **Extend `ValidateGenesisConfig`** to reject `KIP71.GasTarget == 0` when the Magma fork is enabled at genesis. [5](#0-4) 

---

### Proof of Concept

```
1. Governing node submits:
       governance.vote("kip71.gastarget", 0)

2. Vote is accepted (noopFormatChecker returns true for 0).

3. After the epoch boundary the new ParamSet has GasTarget = 0.

4. The next block arrives with parentGasUsed > 0 (any non-empty block).

5. NextMagmaBlockBaseFee is called:
       gasTarget := kc.GasTarget  // == 0
       parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)  // > 0
       // parentGasUsed > gasTarget branch taken
       gasUsedDelta := parentGasUsed - 0  // > 0
       x := parentBaseFee * gasUsedDelta
       y := x.Div(x, big.NewInt(0))  // ← runtime panic: integer divide by zero

6. All nodes processing this block crash simultaneously.
   Chain halts permanently; no further blocks can be finalized.
```

The exact corrupted value is the `baseFee` field of every subsequent block header — it is never computed, and the chain state root is never advanced past the panic block.
