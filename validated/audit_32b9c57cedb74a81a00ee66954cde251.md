### Title
Cross-tenant stack archive/unarchive via `repository.full_name`/`repository.owner.login` mismatch in webhook payload - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb)

### Summary
`WebhooksController#verify_signature` authenticates a webhook using the GitHub App config for the organization found at `params.dig('repository','owner','login')`, but `LabeledHandler` (and the other PR handlers) resolve the target `Repository`/`ReviewStack` using `params.repository.full_name`. Since GitHub always keeps these two fields consistent but Shipit never cross-validates them, an attacker who owns an org configured in Shipit (org‑A) can sign a payload with org‑A's `webhook_secret` while setting `repository.full_name` to a victim repository under org‑B, causing `LabeledHandler#handle` to call `stack.archive!`/`stack.unarchive!` on org‑B's `ReviewStack`.

### Finding Description
Broken binding: the code assumes `params.repository.owner.login`'s org == `params.repository.full_name`'s owning org, but nothing enforces `params.repository.owner.login == params.repository.full_name.split('/').first`.

Code path:
1. `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository','owner','login')` (or `organization.login`) and fetches `Shipit.github(organization: repository_owner)`, verifying the HMAC signature of the raw body with **that org's** `webhook_secret`. [2](#0-1) 
2. On success, `create` parses the *entire* raw JSON body (unfiltered) and dispatches it unchanged to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [3](#0-2) 
3. `LabeledHandler#repository` resolves the target repo via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which splits `full_name` on `/` and does a plain `find_by(owner:, name:)` — no relation to which org's secret authenticated the request. [4](#0-3) [1](#0-0) 
4. `LabeledHandler#handle` then invokes `stack.archive!`/`stack.unarchive!` through `ReviewStackAdapter`, built with `scope: repository.review_stacks` — i.e., org‑B's `ReviewStack`. [5](#0-4) [6](#0-5) 

Attacker's exact request: attacker owns org‑A, which is a configured GitHub App organization in Shipit's `github:` multi-org config (a documented, supported setup per `docs/setup.md`'s "Using Multiple Github Applications" section, and covered by `test/dummy/config/secrets_double_github_app.yml`). [7](#0-6)  Attacker sends `POST /webhooks` with `X-Github-Event: pull_request`, a body where `repository.owner.login = "org-A"` and `repository.full_name = "org-B/victim-repo"`, a `labels` array containing org‑B's configured `provisioning_label_name`, and signs the raw body with org‑A's `webhook_secret` (which the attacker legitimately possesses, e.g. by configuring a webhook on their own org-A repo, or directly crafting the `X-Hub-Signature` header themselves since they know their own secret).

Why existing guards fail: `verify_signature` only proves the request was signed by *some* org's secret whose name matches `repository.owner.login` in the payload — it never checks that this org matches the org actually referenced by `repository.full_name`, which is the field every downstream PR handler (`LabeledHandler`, `ReopenedHandler`, etc.) actually uses to resolve the target `Repository`/`Stack`. The `ExplicitParameters` schema in `LabeledHandler` only validates presence/types of `repository.full_name`, `pull_request`, `sender`, etc.; it does not require or validate `repository.owner.login` at all, so there is no schema-level linkage either. [8](#0-7) 

### Impact Explanation
A payload authenticated under org‑A's `webhook_secret` can trigger `stack.archive!`/`stack.unarchive!` (deprovisioning/reprovisioning, removing from provisioning queue, enqueuing `GithubSyncJob`, etc.) on a `ReviewStack` that belongs to an entirely different, unrelated tenant (org‑B), which never authenticated or authorized this mutation. This matches the Critical category "a payload for one repository mutating another's stack." The attack is repeatable against any repository already registered in Shipit as long as the attacker can guess/enumerate its `full_name` and its `provisioning_label_name`, and is not limited to a single victim stack — every PR-labeled/reopened event can be forged this way to archive/unarchive any org's review stacks, moving the blast radius across all tenants sharing the same Shipit instance.

### Likelihood Explanation
Requires: (1) the Shipit instance to be configured for multiple GitHub organizations (a supported, documented configuration), (2) the attacker to control at least one org registered in that Shipit instance (any GitHub org they can create an app for satisfies "attacker verified under their own org's webhook_secret"), (3) the victim org/repo to exist in Shipit's `Repository` table with review stacks enabled, and (4) knowledge of the victim's `provisioning_label_name` and target PR number/branch — all guessable/discoverable defaults or public repo metadata. No GitHub-side secrets of the victim are needed. This is fully reproducible without live GitHub access, using only local test fixtures/HMAC signing with the attacker's own secret.

### Recommendation
Cross-validate that `repository.owner.login` (or `organization.login`) matches the owner parsed from `repository.full_name` before authenticating/dispatching the webhook — reject the event (422) if they diverge. Additionally, `Repository.from_github_repo_name` (or the handlers) should verify that the resolved `Repository#owner` corresponds to the org that authenticated the request (e.g., pass the verified organization through to handlers and scope lookups by it) rather than trusting `full_name` alone.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (added test)
test "labeled event cannot archive a review stack belonging to a different org than the one that signed the request" do
  # org-A is the attacker's own configured org, org-B is the victim's
  victim_repo = shipit_repositories(:shipit) # owner distinct from "org-A"
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :prevent_with_label,
                       provisioning_label_name: "pull-requests-label")
  stack = create_review_stack_for(victim_repo) # not archived

  payload = JSON.parse(payload(:pull_request_labeled))
  payload["repository"]["full_name"] = victim_repo.github_repo_name # org-B/repo
  payload["repository"]["owner"]["login"] = "org-A"                # attacker's own org
  payload["pull_request"]["labels"] = [{ "name" => "pull-requests-label" }]
  body = payload.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  Shipit.github(organization: "org-A").stubs(:verify_webhook_signature).returns(true) # attacker signs with own secret

  assert_changes -> { stack.reload.archived? }, from: false, to: true do
    post :create, body:, as: :json
  end
end
```
Binding assertions: before request, `victim_repo.owner != "org-A"` and `stack.archived? == false`; after the request, `stack.reload.archived? == true` even though the signature was verified only against org‑A's `webhook_secret`, proving `repository.full_name`'s owning org != the authenticating org yet the mutation still occurred on the victim's stack.

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
