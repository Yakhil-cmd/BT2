### Title
Webhook organization used for signature verification is not bound to the repository the payload writes to, allowing cross-organization stack manipulation - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/`webhook_secret` to check based on `repository_owner`, which is read directly from the *unverified* JSON payload (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). Once the HMAC check passes, the entire raw payload — including its `repository.full_name` field — is handed unmodified to the event handlers, which locate the target `Repository`/`Stack` purely from that same payload field. Because Shipit supports multiple organizations each with an independent `webhook_secret` [2](#0-1) , the field used to pick the *authenticating* secret and the field used to pick the *acted-upon* repository are the same untrusted value but are never cross-checked against each other, nor against which organization actually owns the target repository/stack.

### Finding Description
`verify_signature` computes `repository_owner` from the payload and calls `Shipit.github(organization: repository_owner)` to fetch that organization's `webhook_secret`, then verifies the signature against that secret [4](#0-3) . If verification succeeds, `create` dispatches `handler.call(params)` with the full, unmodified payload [5](#0-4) .

Handlers such as `PushHandler` resolve the affected repository/stacks strictly via `Handler#repository_name`, i.e., `payload.dig('repository', 'full_name')` [6](#0-5) [7](#0-6) . `Repository.from_github_repo_name` simply splits that string on `/` and does a case-insensitive DB lookup with no relation at all to `repository_owner`/the organization whose secret validated the request [3](#0-2) .

The binding that should hold is: `organization used to select webhook_secret for signature verification == organization owning the repository/stack the payload mutates`. Nothing in the code enforces this. An attacker who legitimately possesses (or brute-forces/leaks) the `webhook_secret` for **any one** organization configured in `secrets.github` can craft a payload where:
- `repository.owner.login` (or `organization.login`) = the organization whose secret they hold, so `verify_signature` picks the correct secret and the HMAC passes, and
- `repository.full_name` = `"other-org/other-repo"`, an entirely different organization/repository hosted on the same Shipit instance.

Since `PushHandler`, pull-request handlers, `Repository.from_github_repo_name`, etc. all key exclusively off `repository.full_name` with no re-validation against the authenticating organization, the forged payload can trigger a `sync_github`/deploy-relevant sync (`stack.sync_github(expected_head_sha:)`) or archive/unarchive/label mutation on a stack that belongs to a completely different, unrelated organization's repository [7](#0-6) .

### Impact Explanation
This breaks the deployment-trust binding "an organization that authenticated versus the repository that is written" explicitly called out in scope. An attacker who is a legitimate (if perhaps compromised/lower-privilege) organization owner on the same multi-tenant Shipit instance can forge webhook events that mutate stack state (sync github refs, archive/unarchive review stacks, capture PR labels) for repositories belonging to a different organization they have no authorization over — an unauthorized cross-repository state change reachable purely by crafting an HTTP request, without any Shipit session, `ApiClient` token, or GitHub write access to the victim repository.

### Likelihood Explanation
Requires the attacker to know one organization's `webhook_secret` in a multi-org deployment (a plausible scenario since each org's GitHub App admin configures/rotates this secret and it is routinely embedded in webhook configuration UIs) but does not require any credential for the victim organization or repository. This is a real cross-tenant boundary violation rather than a theoretical one for any deployment using the multi-organization `secrets.github` schema described in `Shipit.github_app_config`.

### Recommendation
After signature verification, re-derive/validate that `repository.full_name`'s owner matches the `repository_owner` (or `organization.login`) used to select the verifying `webhook_secret`, and reject the webhook (422) if they differ. This binds the authenticating organization to the repository actually being written, closing the gap.

### Proof of Concept
1. Deploy Shipit with multi-org config: `secrets.github` containing both `orgA` (attacker-controlled webhook secret known) and `orgB` (victim, unrelated) organizations, each with distinct stacks/repositories tracked.
2. Attacker crafts a `push` webhook JSON body: `{"repository": {"owner": {"login": "orgA"}, "full_name": "orgB/victim-repo"}, "ref": "refs/heads/main", "after": "<attacker-chosen sha>"}`.
3. Attacker computes `X-Hub-Signature` using `orgA`'s `webhook_secret` over the raw body and POSTs to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` computes `repository_owner = "orgA"`, fetches `orgA`'s secret, and the signature check passes [4](#0-3) .
5. `PushHandler#process` resolves stacks via `Repository.from_github_repo_name("orgB/victim-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on `orgB`'s stack — mutating state for a repository the attacker has no authorization over [7](#0-6) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

  end
