### Title
Liquidating one debt asset forces bad-debt socialization on other debt assets even if they are under active liquidation grace period - ([File: local-testing/contracts/market/market.clar])

### Summary
Attacker A (a borrower) holds a mixed-asset debt position: most debt in asset X (currently under an active DAO-set liquidation grace period / pause) and a small slice in asset Z (not paused), collateralized entirely by asset Y. Victim B is a liquidity supplier of vault X. Any unprivileged liquidator (including A themselves) liquidates the small Z slice via `liquidate`; because that call only checks pause state for `debt-aid = Z`, once Y's collateral is exhausted the bad-debt socialization fold sweeps in X's still-outstanding scaled debt from `fresh-debt-list` and calls `vault-socialize-debt` on vault X, forcing B (and other X suppliers) to eat a write-down during the exact window the DAO's grace period was meant to shield them from.

### Finding Description
`liquidate` gates only the asset actually being repaid: `(asserts! (not (is-liquidation-paused debt-aid)) ERR-LIQUIDATION-PAUSED)` [1](#0-0) , where `is-liquidation-paused` checks the manual pause flag plus the global and per-asset entries of `liquidation-grace-periods` for that one `asset-id` [5](#0-4) . When the position's collateral is fully exhausted (`no-collateral-left`), the code builds `stripped-debt-list` by removing only the just-liquidated `debt-aid` from `(get debt pos-full)`, leaving every other debt asset (including X) untouched, then folds `socialize-debt-asset` over that combined `fresh-debt-list` [2](#0-1) . `socialize-debt-asset` unconditionally calls `vault-socialize-debt asset-id scaled-debt` for each entry regardless of that asset's own grace-period/pause state [3](#0-2) , and the vault-level `socialize-debt` function performs no pause/grace check at all, only `check-caller-auth` [4](#0-3) . Thus a DAO-issued grace period on asset X (via `set-liquidation-grace-period` or the global pause/unpause grace mechanism) protects X only from being the *target* of a `liquidate` call, not from being force-written-down as collateral-of-last-resort bad debt triggered by liquidating a different, non-graced asset in the same position.

### Impact Explanation
Suppliers of vault X (victim B) suffer an involuntary write-down of their deposited principal/interest (via `socialize-debt` reducing `lindex`/`assets`/`total-borrowed` in the X vault) exactly during the period the DAO intentionally paused X liquidations/socialization to protect them (e.g., pending an oracle fix or de-listing decision). This is a permanent loss of principal for B with no recourse, and represents protocol insolvency exposure for vault X - Critical impact.

### Likelihood Explanation
The precondition is a borrower position with debt spread across a graced asset X and a non-graced asset Z, collateralized by an asset Y that can be driven to zero value (or already crashed). This is feasible for any user constructing a multi-asset position within existing group/mask rules, no privileged access needed; the liquidator role can be filled by any address, including the attacker's own alt account, and costs only the (small) debt-repay amount for the Z slice plus gas. The attack is repeatable for every position sharing this structure while X's grace period is active.

### Recommendation
When building `fresh-debt-list` for bad-debt socialization, filter out (or fail/skip) any entries whose `aid` is currently under an active `is-liquidation-paused`/grace-period state before folding `socialize-debt-asset`, or block the entire liquidation (return `ERR-LIQUIDATION-PAUSED`) if `no-collateral-left` would force socialization of any asset with an active grace period.

### Proof of Concept
1. Deploy market with three assets: X (debt-enabled, DAO sets `set-liquidation-grace-period` for X's asset id to a future timestamp), Z (debt-enabled, no grace period), Y (collateral-enabled).
2. Account A (borrower): `collateral-add` Y, `borrow` X (90% of debt) and `borrow` Z (10% of debt).
3. Crash Y's price via oracle feed update so the position becomes liquidatable and Y collateral is fully consumable.
4. Account B (any unprivileged liquidator, distinct from A) calls `market.liquidate(A, Y-ft, Z-ft, debt-amount, 0, none, none)` - Z is not paused so the pause assertion passes.
5. Assert in the same transaction/print event that `bad-debt-socialized: true` and that vault X's `socialize-debt` was invoked (check X vault's `lindex`/`total-borrowed` decreased) even though `get-liquidation-grace-period-asset(X-id)` still returns a timestamp greater than current `stacks-block-time`.
6. Compare X vault supplier B's redeemable balance before and after step 4/5 to show the loss, confirming the grace period on X provided no protection.

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)

            (map-set index-cache

            (unwrap! (contract-call? .market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
