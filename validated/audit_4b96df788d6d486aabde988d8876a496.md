### Title
Unvalidated `omniauth.origin` used as post-login redirect target enables forced OAuth completion / open redirect - (File: app/controllers/shipit/github_authentication_controller.rb)

### Summary
`GithubAuthenticationController#callback` takes `request.env['omniauth.origin']` and passes it directly to `redirect_to` with no host/path validation, so any value an attacker plants in that OmniAuth env key is followed verbatim after a real, successful GitHub login. Because OmniAuth's request phase seeds `omniauth.origin` from the unauthenticated `origin` query parameter, an attacker-supplied external URL survives all the way through the login flow to the final redirect.

### Finding Description
The broken binding: `request.env['omniauth.origin']` (attacker-influenced, arbitrary string) is treated as equivalent to "a URL under the Shipit host the operator intended to return to," but nothing in this engine enforces that equivalence.

Code path in this engine: [1](#0-0) 
`callback` reads `request.env['omniauth.origin']` as `return_url` and, once `sign_in_github(auth)` succeeds and `session[:user_id]`/`session[:authenticated]` are set, calls `redirect_to(return_url)` with no scheme/host check, no `url_for(only_path: true)` normalization, and no allow-list comparison against `Shipit.host` or `root_path`.

The only place this engine itself constructs the `origin` value is in the pre-auth redirect helper: [2](#0-1) 
which passes `request.original_url` (a same-host URL) into `github_authentication_path(origin: ...)`. That is the intended, legitimate flow. However, the attacker does not need to go through this helper: the request phase route `get '/', action: :request` under `/github/auth/github` is intercepted by the `OmniAuth::Builder` middleware configured in the engine's initializer: [3](#0-2) 
and OmniAuth's own request-phase behavior copies whatever `origin` query parameter is present into `omniauth.origin` unconditionally — there is no code anywhere in this repository (app/, lib/) that re-validates or restricts that value before `callback` consumes it.

Exploit flow:
1. Attacker sends the victim a link: `https://shipit.example.com/github/auth/github?origin=https://evil.example.com`.
2. Victim clicks it; OmniAuth's request phase stores `omniauth.origin = "https://evil.example.com"` and redirects the victim into the real GitHub OAuth authorization flow.
3. Victim completes GitHub OAuth honestly (this is a legitimate GitHub login, not a fake one — the attacker isn't stealing credentials here).
4. GitHub redirects back to `/github/auth/github/callback`; `callback` signs the victim in for real (`session[:user_id]`, `session[:authenticated] = true` are correctly set on the real Shipit session), then executes `redirect_to("https://evil.example.com")`.
5. The victim's browser, now holding a valid authenticated Shipit session, is sent to the attacker's page.

No existing guard intercepts this: `force_github_authentication` only runs on protected engine controllers and never executes before `callback` completes; `callback` itself performs no `origin`/host check; there is no `verify_signature`, `ExplicitParameters` schema, or model validation on this path, since it's a redirect string, not a persisted record.

### Impact Explanation
This is a client-side redirect to an attacker-controlled origin immediately after a legitimate authentication completes on the real Shipit session — i.e., forced completion of the OAuth flow followed by delivery of the authenticated browser to an attacker-chosen destination. It matches the High-severity category "session fixation / forced OAuth completion" from the rubric. It does not by itself leak the session cookie (cookies are typically host-scoped and not sent cross-origin), and it does not grant the attacker any GitHub credential, API token, or write access to any repository/stack — so it stops short of the Critical bucket (no `github_access_token`, `api_clients_secret`, or deploy secret leaves the host through this path alone). The primary value to the attacker is a convincing phishing/redirect chain (e.g., landing the just-authenticated victim on a look-alike page) rather than direct account or data compromise, since the session itself remains bound to the Shipit host's cookie jar.

### Likelihood Explanation
Attacker cost is trivial: crafting and sending one URL requires no Shipit session, API token, or GitHub team membership — fully consistent with the "unprivileged internet user" attacker model. The only precondition is that the victim (a real Shipit operator with GitHub access) clicks the link and completes a real GitHub login, which is a normal, expected action. This is repeatable against any victim and does not depend on any particular repository or stack configuration.

### Recommendation
Validate `return_url` in `GithubAuthenticationController#callback` before redirecting: restrict it to a path-only value (e.g., parse with `URI.parse` and reject anything with a `host` set, or explicitly compare `URI(return_url).host` against `Shipit.host`/`request.host`), falling back to `root_path` otherwise. Equivalently, only accept origins that were generated via `github_authentication_path(origin: request.original_url)` by storing a signed/opaque token instead of the raw URL.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback does not redirect to an attacker-controlled external origin" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(
      raw_info: OmniAuth::AuthHash.new(
        id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
        login: 'shipit-user', avatar_url: 'https://example.com',
        api_url: 'https://github.com/api/v3/users/shipit-user'
      )
    )
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example.com'

  get :callback

  assert_equal true, session[:authenticated] # binding LHS: real authentication happened
  refute_redirected_to 'https://evil.example.com' # binding RHS: must not equal attacker host
end
```
Current code fails this assertion: `redirect_to(return_url)` at [4](#0-3)  sends the response to `https://evil.example.com` verbatim.

      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']
