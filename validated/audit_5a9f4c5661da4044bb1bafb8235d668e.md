### Title
Strategy fee is withheld after debt is minted, so borrowers pay interest on the fee — ([File: contracts/pool/src/ops/strategy.rs])

### Summary
`ops::strategy::accounting` mints debt shares for the **gross** `action.amount` and only then withholds the flash-style fee from the cash transfer, sending `amount - fee` to the receiver. The borrower therefore accrues interest on tokens they never received — the exact bug class of the Astaria finding (lien/debt created before the protocol fee is taken).

### Finding Description
In `accounting` (`contracts/pool/src/ops/strategy.rs:58-87`):

```rust
let fee = compute_fee(env, &cache, amount, charge_fee);

let mut position = Ray::from(position.scaled_amount);
borrow::mint_debt(env, &mut cache, &mut position, amount);   // debt on gross amount

let protocol_fee = Ray::from_asset(env, fee, cache.params().asset_decimals);
interest::add_protocol_revenue(&mut cache, protocol_fee);

let amount_to_send = amount.checked_sub(fee)...;              // payout net of fee
cache.debit_cash(amount_to_send);
```

`borrow::mint_debt` (`contracts/pool/src/ops/borrow.rs:63-78`) scales `amount` — the full principal including the fee — by `borrow_index` with `div_ceil` and adds it to the user's debt position and to `borrowed`. All subsequent compounding (`interest::global_sync` raising `borrow_index`) applies to that full scaled amount. Meanwhile the receiver only ever gets `amount_to_send = amount - fee` (`apply` transfers `mutation.amount_received`, `strategy.rs:37-39`).

`create_strategy` is reachable by any unprivileged account through `Controller::multiply` and `Controller::swap_debt`, which set `charge_fee = true` (per `skills/xoxno-lending/math.md`: strategies charge the fee "only when `charge_fee` is set (`multiply`, `swap_debt`)"). The fee is `half_up(amount × flashloan_fee / BPS)` with `flashloan_fee ≤ MAX_FLASHLOAN_FEE_BPS = 500` (5%).

Concrete example matching the report's arithmetic: `flashloan_fee = 500` bps, user calls `multiply` drawing 100 tokens of debt. Debt is minted for 100 tokens; only 95 reach the swap. If the borrow index grows 20% before repayment, the user owes ~120 on a position where 95 were ever usable — an effective ~26.3% cost on funds received, versus the quoted 20%.

### Impact Explanation
Every fee-charged strategy opening (`multiply`, `swap_debt`) permanently overstates the borrower's scaled debt by the fee amount relative to the funds received. The excess grows with `borrow_index` compounding, so the user overpays interest proportional to the fee for the life of the position, and repays fee-inclusive principal. This is an ongoing, quantifiable overcharge of user funds, not a rounding artifact.

### Likelihood Explanation
Deterministic — it fires on every `multiply`/`swap_debt` call whenever a market has `flashloan_fee > 0`. No timing, oracle, or adversary requirement; the over-minted debt is embedded in the position at creation. Magnitude is bounded by the 5% fee cap, so this is Medium rather than High.

### Recommendation
Mint debt only for the amount actually advanced. In `ops::strategy::accounting`, compute `fee` first, call `borrow::mint_debt` with `amount - fee` (or equivalently scale `amount_to_send`), and keep booking `fee` via `add_protocol_revenue`. Guards that must see the gross draw (`require_liquidation_buffer`) can still be evaluated against the gross figure separately if that is the intent.

### Proof of Concept
1. Governance lists a market with `flashloan_fee = 500` bps (5%); suppliers deposit so the market has cash.
2. Alice supplies collateral, then calls `Controller::multiply` with `debt_to_flash_loan = 100` units.
3. Controller calls `pool_create_strategy_call` with `charge_fee = true`.
4. `strategy::accounting`: `fee = 5`, `mint_debt(.., 100)` → Alice's scaled debt corresponds to 100 units; `transfer_out` sends 95.
5. After one accrual period raising `borrow_index` by factor `k`, `repay` requires `ceil(100·k)` while Alice only ever received 95 — she owes interest on the 5-unit fee she never touched.
