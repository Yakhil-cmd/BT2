### Title
Credential Cache Scoped by Host Only (Not Path) Enables Cross-Repo Credential Disclosure via Attacker-Controlled Submodule URL - ([File: main.go])

### Summary
git-sync configures a single, process-wide git credential cache (`credential.helper cache --timeout 3600`) without enabling `credential.useHttpPath`, and stores multiple per-URL credentials via `git credential approve` to support submodules on different hosts/paths [1](#0-0) . Because `git-credential-cache` matches cached entries by protocol+host only when `useHttpPath` is unset, a repository that references a submodule at an attacker-controlled path on the *same host* as another configured credential can cause git to hand that cached credential to the attacker's endpoint during `git submodule update`.

### Finding Description
git-sync merges all `--credential` entries (and `--username`/`--password`) into the shared global gitconfig it creates for the process, and stores each with `git credential approve` [2](#0-1) . The default global config only sets `credential.helper` to `cache --timeout 3600`, with no `credential.useHttpPath` setting [3](#0-2) . Git's `credential-cache` helper, absent `useHttpPath`, keys its cache purely on `protocol://host[:port]`, ignoring the URL path. git-sync explicitly supports the multi-credential pattern "for specific URLs, for example when using submodules" [4](#0-3) , and this is exercised by e2e tests where distinct credentials are configured per submodule endpoint [5](#0-4) . During `configureWorktree`, git-sync unconditionally runs `git submodule update --init` (optionally `--recursive`) against whatever `.gitmodules` content is present in the fetched commit, with no allow-list of hosts/paths [6](#0-5) . Since submodule URLs come from `.gitmodules`, which is attacker-controlled content pushed to the synced repo (or a submodule the operator does not fully trust), an attacker who can add/modify `.gitmodules` to point a new submodule at `https://<same-host-as-a-configured-credential>/attacker/path` can cause git to present the cached credential for that host to the attacker's path, disclosing the operator's token/password (e.g., a GitHub PAT configured for `https://github.com/org/private-repo` could be replayed against `https://github.com/attacker/anything` if both resolve to the same host).

### Impact Explanation
This can result in credential/token disclosure to an attacker-controlled endpoint — one of the accepted high-impact outcomes for this scan, and it maps to the DxSale bug class of a hidden, indirect privilege path (here, a hidden trust boundary in credential scoping) being reachable through content that appears legitimate (`.gitmodules`) rather than an explicit administrative action.

### Likelihood Explanation
Requires: (1) the operator using `--credential`/`--username`+`--password` for HTTP(S) auth (a documented, common configuration for submodules), (2) submodules enabled (`--submodules` not `off`, which is not the default-safe posture — default is recursive-capable), and (3) the synced repo or a nested submodule's `.gitmodules` being attacker-influenced (e.g., the synced repo accepts PRs/branches that add submodules, or a transitively-included submodule is untrusted). This is a realistic but non-trivial precondition — it does not require a leaked key or a malicious operator, only an attacker capable of pushing a ref/commit that git-sync will fetch and check out (in scope per the rules). I was not able to fully verify in the available code whether `credential.useHttpPath` is set anywhere else in the codebase (index search only covered `main.go`), so it is possible this is mitigated elsewhere; this should be confirmed against the full source.

### Recommendation
- Set `credential.useHttpPath=true` globally (or per-credential via `-c`) so cached credentials are scoped to the full URL path, not just host.
- Consider isolating credential caches per configured `--credential` URL (e.g., separate `credential.helper` config sections scoped with `[credential "https://host/path"]`) instead of one shared cache.
- Optionally validate/restrict submodule URLs discovered in `.gitmodules` against an operator-supplied allow-list before running `git submodule update`, especially when `--credential` is used, to prevent an attacker-controlled `.gitmodules` from silently reusing configured credentials against arbitrary paths on the same host.

### Proof of Concept
1. Operator runs git-sync with two credentials for the same host but different paths, e.g.:
   `--credential='{"url":"https://github.com/org/private-repo","username":"x","password-file":"/creds/token"}'`
   for the main sync target, with submodules enabled.
2. Attacker gains push access to a branch/ref that git-sync tracks (or to a nested submodule repo already in the tree) and adds to `.gitmodules`:
   `[submodule "evil"] path = evil url = https://github.com/attacker-controlled/collector`
3. On next sync, `configureWorktree` runs `git submodule update --init` [6](#0-5) ; because `credential-cache` matches on host only (no `useHttpPath`), git presents the cached `org/private-repo` token to `https://github.com/attacker-controlled/collector`, which the attacker's server logs — disclosing the operator's `/creds/token` value without ever compromising git-sync's own secrets store.

Note: I could not fully confirm the absence of `credential.useHttpPath` anywhere else in the repository (index coverage limitation); a Devin session with full repository access should verify there is no compensating configuration before treating this as fully confirmed.

```go
// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}
```

```go
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
```
