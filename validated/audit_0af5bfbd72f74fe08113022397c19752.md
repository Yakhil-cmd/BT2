### Title
Unauthenticated Bridge Peer Can Inject Arbitrary RPC Calls Into Main Chain Node and Corrupt Bridge Operator Nonce — (`node/sc/main_bridge_handler.go`, `node/sc/sub_bridge_handler.go`)

---

### Summary

The Kaia service-chain bridge protocol (`servicechain/2`) performs no counterpart-identity authentication beyond a self-reported `NetworkId` and `ProtocolVersion` check during the P2P handshake. Any peer that can reach the main bridge's listening port and present those two trivially-discoverable values is accepted as a legitimate child-chain peer. Two message handlers then act on the unauthenticated peer's data with protected-state impact:

1. `handleCallMsg` (`main_bridge_handler.go`) writes the peer's raw bytes directly into the main bridge's internal RPC server pipe, giving the attacker arbitrary RPC execution against the `klay`/`kaia` namespace registered on the main-chain node.
2. `handleParentChainInfoResponseMsg` (`sub_bridge_handler.go`) unconditionally overwrites the bridge operator's on-chain nonce with a value supplied by the peer, corrupting the nonce used to sign and submit all subsequent bridge value-transfer transactions.

---

### Finding Description

**Handshake — no identity gate**

`baseBridgePeer.readStatus` accepts a peer's `StatusMsg` and only validates two fields:

```go
// node/sc/bridgepeer.go  lines 305-327
if status.NetworkId != network {
    return errResp(ErrNetworkIdMismatch, ...)
}
if int(status.ProtocolVersion) != p.version {
    return errResp(ErrProtocolVersionMismatch, ...)
}
``` [1](#0-0) 

`NetworkId` is the public chain ID (e.g. `8217` for Kaia mainnet). `ProtocolVersion` is the fixed constant `2` (`SCProtocolVersion`). Neither is a secret. The peer's ECDSA node-ID is authenticated at the RLPx layer, but the bridge handler never checks it against any whitelist of authorised child-chain nodes. The `ChainID` field in `statusData` is also self-reported and accepted without verification. [2](#0-1) 

**Issue 1 — `handleCallMsg`: arbitrary RPC injection into the main-chain node**

`HandleSubMsg` dispatches `ServiceChainCall` (opcode `0x06`) to `handleCallMsg`:

```go
// node/sc/main_bridge_handler.go  lines 86-101
func (mbh *MainBridgeHandler) handleCallMsg(p BridgePeer, msg p2p.Msg) error {
    data := make([]byte, msg.Size)
    err := msg.Decode(&data)
    ...
    _, err = mbh.mainbridge.rpcConn.Write(data)   // ← no sender check
    ...
}
``` [3](#0-2) 

`rpcConn` is one end of an `net.Pipe()` whose other end is served by an `rpc.Server` that has the full `klay`/`kaia` public API namespace registered:

```go
// node/sc/mainbridge.go  lines 240-255
if api.Public && (api.Namespace == "klay" || api.Namespace == "kaia") {
    mb.rpcServer.RegisterName(api.Namespace, api.Service)
    ...
}
``` [4](#0-3) 

The RPC server's response is read back and forwarded to **all** connected bridge peers:

```go
// node/sc/mainbridge.go  lines 401-413
func (mb *MainBridge) SendRPCResponseData(data []byte) error {
    for _, peer := range peers {
        err := peer.SendResponseRPC(data)
        ...
    }
}
``` [5](#0-4) 

An attacker therefore gains a private, unauthenticated RPC channel into the main-chain node, bypassing any IP-based ACL or rate-limiting on the public RPC endpoint.

**Issue 2 — `handleParentChainInfoResponseMsg`: bridge operator nonce overwrite**

`HandleMainMsg` on the sub-bridge dispatches `ServiceChainParentChainInfoResponseMsg` (opcode `0x04`) to:

```go
// node/sc/sub_bridge_handler.go  lines 273-308
func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
    var pcInfo parentChainInfo
    msg.Decode(&pcInfo)
    ...
    sbh.setParentOperatorNonce(pcInfo.Nonce)   // ← attacker-controlled value
    sbh.setParentOperatorNonceSynced(true)
    sbh.setRemoteChainValues(pcInfo)           // also overwrites gas price
    ...
}
``` [6](#0-5) 

`setParentOperatorNonce` writes directly into `bridgeAccounts.pAccount.nonce`, the nonce used to sign every bridge value-transfer transaction submitted to the parent chain. [7](#0-6) 

`setRemoteChainValues` also overwrites `remoteGasPrice` and the KIP-71 fee parameters used for all subsequent bridge transactions. [8](#0-7) 

---

### Impact Explanation

**Issue 1 (RPC injection):** An unauthenticated peer obtains a private RPC channel to the main-chain node's `klay`/`kaia` namespace. This bypasses any public-RPC access controls and allows the attacker to call `klay_sendRawTransaction` (submitting pre-signed transactions to the tx pool), enumerate account state, and probe internal node state — all without appearing in public RPC logs. This is a bridge privilege escalation affecting the main-chain node's protected RPC surface.

**Issue 2 (nonce corruption):** Setting `parentOperatorNonce` to an attacker-chosen value (e.g. `uint64` max − 1) causes every subsequent bridge transaction to be signed with a nonce that the parent chain will reject as too high. The bridge tx pool accumulates unexecutable transactions; `nonceSynced` is set to `true` so the sub-bridge stops re-requesting the real nonce. All pending and future bridge value-transfer requests stall permanently until the operator manually intervenes. This is an unauthorized nonce consumption affecting bridged assets.

---

### Likelihood Explanation

The main bridge P2P server listens on a configurable port (`MainBridgePort`, default `50505`) with `NoDiscovery = true` but `NoDial = false` for incoming connections. The port is reachable by any network peer. The only barrier is knowing `NetworkId` and `ProtocolVersion = 2`, both of which are public constants. No cryptographic proof of being an authorised child-chain node is required. The attack requires only a TCP connection and knowledge of two public values.

---

### Recommendation

1. **Whitelist authorised counterpart node IDs.** After the RLPx handshake the peer's ECDSA node-ID is available via `p.GetP2PPeerID()`. The bridge configuration should accept an explicit list of authorised child-chain node IDs; any peer not on the list should be disconnected before message handling begins.

2. **Reject `ServiceChainCall` from unregistered peers.** `handleCallMsg` should verify that the sending peer's node-ID matches the configured child-chain operator before writing to `rpcConn`.

3. **Validate nonce responses against on-chain state.** `handleParentChainInfoResponseMsg` should cross-check the received nonce against the value returned by a direct on-chain query (already available via `remoteBackend`) before overwriting the local nonce. At minimum, reject any nonce that is lower than the current local value or higher than `currentNonce + maxAllowedDrift`.

---

### Proof of Concept

```
# Attacker machine — connect to main bridge port
# NetworkId = 8217 (Kaia mainnet), ProtocolVersion = 2

1. Establish RLPx connection to <main-bridge-host>:50505
2. Send StatusMsg{ProtocolVersion:2, NetworkId:8217, ChainID:<any>}
   → readStatus() passes; peer is registered in bridgePeerSet

# Issue 1: RPC injection
3. Send ServiceChainCall (0x06) with payload:
   {"jsonrpc":"2.0","method":"kaia_getBalance",
    "params":["0x<target>","latest"],"id":1}
   → handleCallMsg writes bytes to rpcConn
   → main-chain rpcServer processes call
   → SendRPCResponseData forwards result back to attacker

# Issue 2: nonce corruption (sub-bridge side)
1. Connect to sub-bridge P2P port; complete handshake with parent chainID
2. Send ServiceChainParentChainInfoResponseMsg (0x04) with:
   parentChainInfo{Nonce: 0xFFFFFFFFFFFFFFFE, GasPrice: 1}
   → handleParentChainInfoResponseMsg sets parentOperatorNonce = 2^64-2
   → nonceSynced = true
   → all bridge value-transfer txs signed with nonce 2^64-2 are rejected
     by parent chain; bridge halts
```

	}
	if int(status.ProtocolVersion) != p.version {

func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
}
