### Title
Newly-created worktrees are published via the symlink without any emptiness/content sanity check - ([File: main.go])

### Summary
`repoSync.SyncRepo` only validates worktree content (via `sanityCheckWorktree`, which explicitly rejects empty directories) on the *reuse* path, when the locally cached hash already matches the remote hash. The path that creates a **new** worktree for a newly-fetched hash and then flips the publish symlink to it never calls this same validation. An attacker who controls the upstream repository content (a ref/commit that git-sync is configured to track) can push a commit that checks out to an effectively empty worktree, and git-sync will publish it as if it were valid, exactly mirroring the reported bug class where a degenerate/zero-content initialization is accepted as "done" with no way to detect or reject it.

### Finding Description
`SyncRepo` has two branches for handling a hash:

1. **Reuse branch** — `currentHash == remoteHash`: before trusting the existing worktree, it calls `git.sanityCheckWorktree(ctx, currentWorktree)`, which explicitly fails if `dirIsEmpty(worktree.Path())` is true. [1](#0-0) [2](#0-1) 

2. **New-hash branch** — `changed` is true: it calls `createWorktree` then `configureWorktree` (which writes the `.git` gitlink file and does `git reset --hard <hash> --`) and immediately proceeds to `syncHooks.beforePublish`, `publishSymlink`, and `syncHooks.afterPublish` — with **no call to `sanityCheckWorktree`** anywhere in this branch. [3](#0-2) [4](#0-3) [5](#0-4) 

Because `configureWorktree` always writes a `.git` regular file into the worktree directory before checkout, `dirIsEmpty` would never even trigger for a freshly created worktree in this branch anyway — the check simply isn't wired into this code path at all. [6](#0-5) 

If the remote ref/commit that git-sync tracks resolves to a tree with no files (e.g. an empty-tree commit, or a commit whose paths are all removed), `git reset --hard <hash> --` succeeds with zero real files checked out, no error is raised, and the code proceeds straight to publishing the symlink and firing the `afterPublish` webhook/exec hooks as a "successful" sync. [7](#0-6) 

### Impact Explanation
This directly parallels the reported bug class: a state that should represent "real" content (a funded pool / a validly synced checkout) can be finalized in a degenerate, empty condition because a validation guard that exists in the codebase (`sanityCheckWorktree`'s emptiness check) is not applied on the path that actually creates and publishes new content. Consumers reading through the `--link` symlink — the documented atomic-publish "contract" — can observe an empty/wrong directory as if it were a genuine successful sync, and `--exechook-command`/`--webhook-url` are invoked believing the sync succeeded, potentially triggering downstream actions (e.g. application reload) against empty configuration/code. This falls into the accepted impact bucket of "publishing wrong or partial content."

### Likelihood Explanation
Unlike the AMM bug, this is not a permanent one-time lock — the next commit that restores real content will self-heal on the following sync loop iteration, since `changed` becomes true again. That reduces severity relative to the original "persistent sync denial" framing. Triggering it requires that the tracked ref/branch/tag actually resolve to an empty-tree (or otherwise degenerate) commit, which is fully within the control of whoever can push to the tracked repository/ref — no special git-sync flags are required beyond normal operation (`--repo`, `--ref`/branch, `--root`, `--link`).

### Recommendation
Call `sanityCheckWorktree` (or an equivalent emptiness/content check) on the newly created worktree in the `changed` branch of `SyncRepo`, before invoking `beforePublish`/`publishSymlink`/`afterPublish`, and treat an empty or otherwise invalid checkout as a fetch error (retry via `failCount`) rather than a successful sync.

### Proof of Concept
1. Configure git-sync with `--repo=<attacker-controlled-repo>` `--ref=main` `--root=/tmp/root` `--link=current`.
2. In the upstream repo, push a commit with `git commit --allow-empty -m empty` to `main` (tree has zero files).
3. Run one sync cycle: `SyncRepo` detects `changed=true`, calls `createWorktree`/`configureWorktree` (checkout succeeds trivially since the tree is empty), then `publishSymlink` flips `current` to point at this empty worktree, and `afterPublish` fires configured webhook/exec hooks — with no rejection anywhere in the path. [8](#0-7)

// createWorktree creates a new worktree and checks out the given hash.  This
// returns the path to the new worktree.
func (git *repoSync) createWorktree(ctx context.Context, hash string) (worktree, error) {
	// Make a worktree for this exact git hash.
	worktree := git.worktreeFor(hash)

	// Avoid wedge cases where the worktree was created but this function
	// error'd without cleaning up.  The next time thru the sync loop fails to
	// create the worktree and bails out. This manifests as:
	//     "fatal: '/repo/root/nnnn' already exists"
	if err := git.removeWorktree(ctx, worktree); err != nil {
		return "", err
	}

	git.log.V(1).Info("adding worktree", "path", worktree.Path(), "hash", hash)
	_, _, err := git.Run(ctx, git.root, "worktree", "add", "--force", "--detach", worktree.Path().String(), hash, "--no-checkout")
	if err != nil {
		return "", err
	}

	return worktree, nil
}

func (git *repoSync) configureWorktree(ctx context.Context, worktree worktree) error {
	hash := worktree.Hash()

	// The .git file in the worktree directory holds a reference to
	// /git/.git/worktrees/<worktree-dir-name>. Replace it with a reference
	// using relative paths, so that other containers can use a different volume
	// mount name.
	var rootDotGit string
	if rel, err := filepath.Rel(worktree.Path().String(), git.root.String()); err != nil {
		return err
	} else {
		rootDotGit = filepath.Join(rel, ".git")
	}
	gitDirRef := []byte("gitdir: " + filepath.Join(rootDotGit, "worktrees", hash) + "\n")
	if err := os.WriteFile(worktree.Path().Join(".git").String(), gitDirRef, 0644); err != nil {
		return err
	}

	// If sparse checkout is requested, configure git for it, otherwise
	// unconfigure it.
	gitInfoPath := filepath.Join(git.root.String(), ".git/worktrees", hash, "info")
	gitSparseConfigPath := filepath.Join(gitInfoPath, "sparse-checkout")
	if git.sparseFile == "" {
		os.RemoveAll(gitSparseConfigPath)
	} else {
		// This is required due to the undocumented behavior outlined here:
		// https://public-inbox.org/git/CAPig+cSP0UiEBXSCi7Ua099eOdpMk8R=JtAjPuUavRF4z0R0Vg@mail.gmail.com/t/
		git.log.V(1).Info("configuring worktree sparse checkout")
		checkoutFile := git.sparseFile

		source, err := os.Open(checkoutFile)
		if err != nil {
			return err
		}
		defer source.Close()

		if _, err := os.Stat(gitInfoPath); os.IsNotExist(err) {
			err := os.Mkdir(gitInfoPath, defaultDirMode)
			if err != nil {
				return err
			}
		}

		destination, err := os.Create(gitSparseConfigPath)
		if err != nil {
			return err
		}
		defer destination.Close()

		_, err = io.Copy(destination, source)
		if err != nil {
			return err
		}

		args := []string{"sparse-checkout", "init"}
		if _, _, err = git.Run(ctx, worktree.Path(), args...); err != nil {
			return err
		}
	}

	// Reset the worktree's working copy to the specific ref.
	git.log.V(1).Info("setting worktree HEAD", "hash", hash)
	if _, _, err := git.Run(ctx, worktree.Path(), "reset", "--hard", hash, "--"); err != nil {
		return err
	}
