### Title
Skill updates trust `owner/repo` name alone with no source-identity or content-digest pinning, enabling repo-transfer/rename hijack - (File: pkg/cmd/skills/update/update.go, internal/skills/discovery/discovery.go)

### Summary
`gh skill update` re-resolves a skill's remote source using only the `owner/repo` string parsed from the installed `SKILL.md` frontmatter, then calls `DiscoverSkillsWithOptions`/`DiscoverSkills` against that string via the GitHub API. Neither the update flow nor `discovery.go` verifies that the resolved repository is the same underlying repository the skill was originally installed from (e.g. via a stable node ID), so if the original `owner/repo` name is freed up (account deletion, org transfer, repo rename) and reclaimed by an attacker, the next `gh skill update` silently installs attacker content over the trusted skill.

### Finding Description
`updateRun` in [1](#0-0)  parses `s.owner`/`s.repo` straight from the locally-installed `SKILL.md` frontmatter (`github-repo` metadata field, see `parseInstalledSkill` at [2](#0-1) ) and passes those strings to `discovery.ResolveRef` and `discovery.DiscoverSkills`, which forwards to `DiscoverSkillsWithOptions` at [3](#0-2) . That function does nothing more than fetch `repos/{owner}/{repo}/git/trees/{commitSHA}` from whatever repository currently answers to that owner/repo path — there is no check against a stable repository identifier (GitHub's numeric repo `id`/node ID), nor against any recorded content digest from install time.

The only "pin" state tracked is `github-tree-sha`/`github-pinned` in the SKILL.md frontmatter (mirrored in the separate `.skill-lock.json` lockfile in [4](#0-3) , which records `Source`, `SourceURL`, and `SkillFolderHash`). Critically, `update.go` never reads this lockfile or cross-checks these fields against the freshly resolved repository — it only compares `remote.TreeSHA != s.treeSHA` to decide whether an update is "available" ( [5](#0-4) ). A different tree SHA is expected and desired on every legitimate update, so this check cannot distinguish "new commit from the same maintainer" from "entirely different repository now squatting the same name."

GitHub repository names are attacker-claimable after: (a) the owner deletes their account, (b) the owner renames/transfers the repo away from that name (freeing the old owner/name pair), or (c) an org membership change frees a name. None of these require any privilege beyond publishing content as an ordinary GitHub user. Once an attacker recreates `owner/repo` (or a renamed-away name), `gh skill update` for any victim who previously installed that skill will resolve refs/trees/blobs against the attacker's repository and overwrite the local skill content — including `SKILL.md` instructions/scripts that AI agent tooling executes.

### Impact Explanation
This allows a remote, unprivileged GitHub user to substitute the entire content of a previously-trusted, installed skill on a victim's machine simply by reclaiming a vacated `owner/repo` name — no compromise of the original maintainer's account or any elevated privilege is required. Because installed skills are consumed by AI-agent tooling (Copilot, Claude, etc.) that execute or heavily trust `SKILL.md` instructions, this is a supply-chain substitution vector with a realistic path to arbitrary code execution on the victim's developer machine, matching a Critical "Websites and Apps: arbitrary code execution" / RCE-in-gh impact class.

### Likelihood Explanation
Preconditions are entirely attacker-feasible without any special access: publish or reclaim a GitHub repository under the exact `owner/repo` name a victim already has installed (via account deletion, rename, or org departure), then wait for the victim to run `gh skill update` (or `--all`) — a routine, expected workflow action. The bug is deterministic and repeatable for every skill whose original repo name becomes reclaimable, and requires no interaction beyond the victim's normal update command.

### Recommendation
Record a stable source identity at install time (GitHub repository node ID/`id`, not just owner/repo strings) in both the `SKILL.md` frontmatter and `.skill-lock.json`, and have `DiscoverSkillsWithOptions`/`updateRun` fetch and compare that ID before treating a resolved repository as the same source. Optionally also record and verify a content digest (e.g. root tree SHA lineage or signed release digest) so that even a compromised-but-same-ID repository requires an explicit user acknowledgment of a discontinuous history before overwriting local files.

func DiscoverSkillsWithOptions(client *api.Client, host, owner, repo, commitSHA string, opts DiscoverOptions) ([]Skill, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "trees", commitSHA)
	if err != nil {
		return nil, err
	}
	apiPath.SetQuery("recursive", "true")
	var tree treeResponse
	if err := client.REST(host, "GET", apiPath.String(), nil, &tree); err != nil {
		return nil, fmt.Errorf("could not fetch repository tree: %w", err)
	}

	if tree.Truncated {
		return nil, &TreeTooLargeError{Owner: owner, Repo: repo}
	}

	treeSHAs := make(map[string]string)
	for _, entry := range tree.Tree {
		if entry.Type == "tree" {
			treeSHAs[entry.Path] = entry.SHA
		}
	}

	seen := make(map[string]bool)
	var matches []skillMatch
	for _, entry := range tree.Tree {
		if entry.Type != "blob" {
			continue
		}
		m := matchSkillConventions(entry)
		if m == nil {
			m = matchHiddenDirConventions(entry)
		}
		if m == nil {
			continue
		}
		if seen[m.skillDir] {
			continue
		}
		seen[m.skillDir] = true
		matches = append(matches, *m)
	}

	if len(matches) == 0 {
		return nil, fmt.Errorf(
			"no skills found in %s/%s\n"+
				"  Expected skills in skills/*/SKILL.md, skills/{scope}/*/SKILL.md,\n"+
				"  {prefix}/skills/*/SKILL.md, {prefix}/skills/{scope}/*/SKILL.md,\n"+
				"  */SKILL.md, or plugins/*/skills/*/SKILL.md\n"+
				"  This repository may be a curated list rather than a skills publisher",
			owner, repo,
		)
	}

	var skills []Skill
	for _, m := range matches {
		skills = append(skills, Skill{
			Name:       m.name,
			Namespace:  m.namespace,
			Path:       m.skillDir,
			BlobSHA:    m.entry.SHA,
			TreeSHA:    treeSHAs[m.skillDir],
			Convention: m.convention,
		})
	}

	sort.SliceStable(skills, func(i, j int) bool {
		return skills[i].DisplayName() < skills[j].DisplayName()
	})

	return skills, nil
}

// RecordInstall adds or updates a skill entry in the lock file.
// It uses a file-based lock to prevent concurrent read-modify-write races
// when multiple install processes run simultaneously.
func RecordInstall(host, skillName, owner, repo, skillPath, treeSHA, pinnedRef string) error {
	lockPath, err := lockfilePath()
	if err != nil {
		return err
	}
	if err := os.MkdirAll(filepath.Dir(lockPath), 0o755); err != nil {
		return fmt.Errorf("could not create lock directory: %w", err)
	}

	lockedFile, unlock, err := acquireFLock()
	if err != nil {
		return err
	}
	defer unlock()

	f, err := readFrom(lockedFile)
	if err != nil {
		return err
	}

	now := time.Now().UTC().Format(time.RFC3339)

	existing, exists := f.Skills[skillName]
	installedAt := now
	if exists {
		installedAt = existing.InstalledAt
	}

	f.Skills[skillName] = entry{
		Source:          owner + "/" + repo,
		SourceType:      "github",
		SourceURL:       ghinstance.HostPrefix(host) + owner + "/" + repo + ".git",
		SkillPath:       skillPath,
		SkillFolderHash: treeSHA,
		InstalledAt:     installedAt,
		UpdatedAt:       now,
		PinnedRef:       pinnedRef,
	}

	return writeTo(lockedFile, f)
}
