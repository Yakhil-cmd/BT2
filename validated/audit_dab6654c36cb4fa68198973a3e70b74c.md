### Title
Path traversal in `gh release download` allows arbitrary file write via attacker-controlled asset name - ([File: pkg/cmd/release/download/download.go])

### Summary
`gh release download` writes each release asset to a local path built by joining the user-supplied destination directory with the asset's `Name` field taken directly from the GitHub API response, using plain `filepath.Join` with no path-traversal validation. A release asset name containing `../` sequences (or an absolute-like path) is not rejected, so downloading a release from an attacker-controlled or attacker-influenced repository can write/overwrite files outside the intended download directory.

### Finding Description
In `destinationWriter.makePath`, the destination file path is computed as: [1](#0-0) 
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
```
`name` comes from `shared.ReleaseAsset.Name`, which is populated from the GitHub Releases API response and iterated over in `downloadRun`: [2](#0-1) 
The only checks applied to `a.Name` before download are the `--pattern` glob filter and a Windows-reserved-filename check; there is no check for path separators or `..` segments. `Copy` then opens/writes to that computed path unconditionally: [3](#0-2) 

This is the same bug class as the WordPress report: an externally/attacker-supplied string (`$_POST['thumb']` there, the release asset `Name` here) flows unsanitized into a filesystem path used for a write/delete operation, allowing traversal outside the intended directory.

Notably, this codebase already has the correct pattern implemented elsewhere and simply isn't applied here: `gh run download` uses `internal/safepaths.Absolute.Join`, which explicitly detects and rejects any join that would escape the destination directory: [4](#0-3) 
and `gh run download` has a passing regression test proving traversal is blocked there: [5](#0-4) 
The `gh release download` code path (`pkg/cmd/release/download/download.go`) does not use `safepaths` at all — it relies on raw `filepath.Join` and `os.OpenFile`, and I found no corresponding traversal test or check in `pkg/cmd/release/download/download_test.go`.

### Impact Explanation
An attacker who controls (or can influence assets of) a repository that a victim runs `gh release download` against can supply an asset named e.g. `../../../../.ssh/authorized_keys` or `../../.bashrc`. Because `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` is used, this results in arbitrary file creation/overwrite on the victim's machine outside the requested `--dir`, with attacker-controlled content. Depending on the target path this can lead to persistence/code execution (e.g., overwriting shell rc files, SSH authorized_keys, cron entries) — a direct file-write analog to the WordPress arbitrary file deletion primitive, and arguably worse since it's a write rather than a delete.

### Likelihood Explanation
Reachable via a normal, unprivileged `gh release download <tag>` invocation against any repository the attacker controls or has push/release access to (including public open-source repos where an attacker can create a release, or a compromised/malicious fork a victim is instructed to run the command against). No special privileges, MITM, or leaked tokens are required — this matches the "unrelated download/extraction to disk" category explicitly in scope.

### Recommendation
Use the existing `internal/safepaths.Absolute` abstraction (as already done in `pkg/cmd/run/download` and `pkg/cmd/copilot`) to join the destination directory with the asset name, rejecting or erroring out on any path that would escape the destination directory, before calling `destinationWriter.Copy`/`makePath` in `pkg/cmd/release/download/download.go`.

### Proof of Concept
1. Attacker creates/controls a GitHub repository and publishes a release with an asset whose `name` field (as returned by the Releases API) is `../../../../tmp/pwned` (or any traversal sequence reachable through the API/GHES instance).
2. Victim runs `gh release download <tag> -R attacker/repo -D ./safe-dir`.
3. `downloadRun` iterates `release.Assets`, passes `a.Name` unchanged to `downloadAsset` → `dest.Copy(fileName, resp.Body)` → `makePath` computes `filepath.Join("./safe-dir", "../../../../tmp/pwned")`, resolving outside `./safe-dir`.
4. `os.OpenFile` creates/overwrites the file at the resolved path with attacker-controlled asset content, outside the directory the victim intended to write into.

Note: I was unable to fully verify at the API/GHES layer whether GitHub.com's release-asset-name validation currently blocks slashes in asset names (this would need to be tested against a live/mocked API, which is outside what the index can confirm) — the vulnerability is confirmed at the `gh` client code level in that no defensive check exists, unlike the equivalent `run download` and `extension` code paths.

```go
func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
```

```go
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
```
