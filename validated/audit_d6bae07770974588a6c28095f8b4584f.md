### Title
Unauthenticated Receipt Injection via Bridge Peer Corrupts Anchoring State — (`node/sc/sub_bridge_handler.go`)

### Summary

`writeServiceChainTxReceipts` accepts receipt content from any connected bridge peer at face value. The only guard is a `bridgeTxPool` lookup by `TxHash`. Because the child chain broadcasts all pending anchoring tx hashes to every bridge peer, a malicious peer can craft a `ServiceChainReceiptResponseMsg` whose `TxHash` matches a live pending anchoring tx, inject arbitrary receipt content, permanently remove the real tx from the pool, and corrupt both the stored receipt and the anchored-block-number counter.

---

### Finding Description

**Entry point — `handleParentChainReceiptResponseMsg`:** [1](#0-0) 

The message is decoded and forwarded directly to `writeServiceChainTxReceipts` with no peer-identity or receipt-authenticity check.

**The only guard in `writeServiceChainTxReceipts`:** [2](#0-1) 

The code checks `sbh.subbridge.GetBridgeTxPool().Get(txHash)` — i.e., "does a tx with this hash exist in our pool?" — and nothing else. If the lookup succeeds and the tx is a chain-data-anchoring type, it:

1. Decodes the anchoring payload from the **child chain's own tx** (legitimate data).
2. Calls `WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))` — storing **whatever receipt content the peer sent** under the child chain block hash.
3. Calls `WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())` — advancing the anchored-block counter.
4. Calls `RemoveTx(tx)` — permanently evicting the real anchoring tx from the pool.

There is no signature, Merkle proof, status check, or any other verification that the receipt reflects actual parent-chain execution.

**How the attacker learns the pending tx hashes:** [3](#0-2) 

`broadcastServiceChainReceiptRequest` sends all pending anchoring tx hashes to **every** connected bridge peer. The attacker receives these hashes as a normal part of the protocol.

**Peer registration has no whitelist:** [4](#0-3) 

`RegisterNewPeer` only checks that the peer's `chainID` matches the configured parent chain ID — a public value. Any node that can reach the bridge P2P port and presents the correct chain ID is admitted.

---

### Impact Explanation

| Corrupted artifact | Effect |
|---|---|
| `WriteReceiptFromParentChain(childBlockHash, fakeReceipt)` | `GetReceiptFromParentChain` returns a fabricated receipt to every external verifier querying anchoring proofs for that child block |
| `WriteAnchoredBlockNumber(blockNum)` | Child chain permanently believes that block is anchored; no re-anchoring is ever attempted |
| `RemoveTx(tx)` | The real anchoring tx is evicted; the parent chain may never confirm it, and the child chain will not retry |

The anchoring proof is the primary trust mechanism of the service chain. Corrupting it means external verifiers (light clients, bridges, auditors) receive fabricated evidence of parent-chain confirmation for child-chain blocks that were never actually anchored.

---

### Likelihood Explanation

- The bridge P2P port is reachable by any node that knows the parent chain ID (public).
- The pending tx hashes are broadcast to all bridge peers by the child chain itself.
- The attack requires only one crafted P2P message; no cryptographic material is needed.
- The window is open for as long as an anchoring tx remains pending in the pool.

---

### Recommendation

Before calling `WriteReceiptFromParentChain`, verify the receipt against the parent chain:

1. **Require a Merkle receipt proof** (receipt trie root from the parent chain block header) and validate it before accepting any receipt content.
2. Alternatively, **fetch the receipt directly** from a trusted parent-chain RPC endpoint rather than accepting it from a bridge peer message.
3. At minimum, **do not remove the tx from the pool** until the receipt has been independently confirmed; keep it for retry if verification fails.
4. Consider restricting bridge peer connections to a configured allowlist of node IDs rather than relying solely on chain ID matching.

---

### Proof of Concept

```
1. Attacker node connects to the child chain's bridge P2P port, presenting the correct parent chain ID during handshake.

2. Child chain calls broadcastServiceChainReceiptRequest(), sending the attacker the list of pending anchoring tx hashes (e.g., txHash = 0xABC...).

3. Attacker constructs a ReceiptForStorage:
     TxHash: 0xABC...          // matches a real pending anchoring tx
     Status: 1                 // fake "success"
     Logs:   [fabricated logs]
     ...

4. Attacker sends ServiceChainReceiptResponseMsg containing this receipt.

5. handleParentChainReceiptResponseMsg decodes it and calls writeServiceChainTxReceipts.

6. writeServiceChainTxReceipts:
   a. Finds tx 0xABC... in bridgeTxPool — check passes.
   b. Decodes anchoring data from the tx → childBlockHash, childBlockNumber.
   c. Calls WriteReceiptFromParentChain(childBlockHash, fakeReceipt) — fake receipt persisted.
   d. Calls WriteAnchoredBlockNumber(childBlockNumber) — anchoring counter advanced.
   e. Calls RemoveTx(tx) — real anchoring tx evicted, no retry possible.

7. GetReceiptFromParentChain(childBlockHash) now returns the fabricated receipt.
   External verifiers believe the child block was anchored with the attacker's fake data.
```

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}
