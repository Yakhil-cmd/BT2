### Title
`initialize_with_permission` accepts an unverified, non-signing `creator` account that becomes the sole authority over accumulated creator fees, enabling permanent freezing of swapper fee funds - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
The Mattermost CVE-2023-4478 bug class is "the program blindly trusts a request-controlled parameter to set privileged/consent-gated account state, without validating that the affected party actually authorized it." In `raydium-cp-swap`, `initialize_with_permission` accepts a `creator` account that is declared `UncheckedAccount` and never required to sign the transaction, yet its key is written directly into `PoolState.pool_creator`, the field that later gates exclusive control of `collect_creator_fee` and the fee-destination address for `collect_creator_fee_permissionless`.

### Finding Description
In `initialize_with_permission.rs`, the account list defines: [1](#0-0) 
`creator` has no `Signer` constraint and no relationship check to `payer` (the only signer). Only a `payer`-scoped `permission` PDA is validated: [2](#0-1) 

The unchecked `creator` key is then persisted as the pool's permanent authority field via `pool_state.initialize(...)`: [3](#0-2) 

`PoolState.pool_creator` subsequently becomes the sole address authorized to reclaim accumulated creator fees. `collect_creator_fee` requires the caller to *be* that exact address and sign: [4](#0-3) 

`collect_creator_fee_permissionless` is more forgiving (no signature required from `creator`), but it still unconditionally routes every accumulated creator fee to an ATA owned by whatever pubkey was frozen into `pool_creator`: [5](#0-4) [6](#0-5) 

Because the pool's fee-accrual loop (swap → `creator_fees_token_0/1` bump in `PoolState`, per `states/pool.rs`) runs for the lifetime of the pool and is fed by every subsequent swapper's trade fee, any permissioned pool creator can supply a `creator` pubkey that corresponds to no reachable private key (e.g., a burn/incinerator address, `Pubkey::default()`, or an arbitrary PDA belonging to an unrelated program). Once set, that value is immutable — there is no `update_pool_creator`-type instruction in the program — so:
1. `collect_creator_fee` becomes permanently unusable (nobody can produce the required signature).
2. `collect_creator_fee_permissionless` will keep depositing real swapper-paid fees into an ATA owned by an address nobody controls, with no way to ever move them out.

### Impact Explanation
Every trade against the pool contributes to `creator_fees_token_0/1`, funds that originate from unprivileged swappers via the constant-product fee split (`AmmConfig.creator_fee_rate`). By supplying an unspendable `creator` value at pool creation, the accrued creator-fee share of every future swapper's trade fee is permanently and irrecoverably locked out of anyone's reach — a direct freezing of user (swapper) funds routed through the fee ledger, matching the accepted impact category "permanent freezing of user funds."

### Likelihood Explanation
Any account that has been granted a `Permission` PDA (the only prerequisite for calling `initialize_with_permission`) can trigger this in a single transaction by simply choosing an unspendable pubkey for the `creator` account — no special timing, race, or additional privilege is needed beyond the normal ability to create a permissioned pool, which is the exact "pool creator" persona explicitly in scope.

### Recommendation
Require `creator` in `InitializeWithPermission` to either be a `Signer` (proving consent/control, matching the permissionless `Initialize` instruction where `creator: Signer<'info>`) or add an explicit constraint tying it to `payer`/a previously-verified identity. Alternatively, provide a governed instruction to rotate `pool_creator` when the original designated address is unreachable, and/or validate that `creator` is not a known-unspendable address (system program default, zero pubkey, etc.) at initialization time.

### Proof of Concept
1. Obtain a `Permission` PDA for `payer` via `create_permission_pda` (admin-gated but that only restricts *who* can create pools, not what `creator` value they may set).
2. Call `initialize_with_permission` with `creator = Pubkey::default()` (or any PDA of an unrelated program with no signer authority) while `payer` funds/signs everything else normally.
3. `pool_state.pool_creator` is now permanently set to this unspendable address (`programs/cp-swap/src/instructions/initialize_with_permission.rs:357-372`).
4. Any user swaps against the pool; each swap accrues `creator_fees_token_0/1` on `PoolState` per the fee-split logic.
5. Attempt `collect_creator_fee`: fails permanently — no keypair exists for `pool_creator` to sign (`collect_creator_fee.rs:12-13`).
6. Attempt `collect_creator_fee_permissionless`: succeeds in moving tokens out of the pool vaults, but they land in an ATA owned by the unspendable `creator` address (`collect_creator_fee_permissionless.rs:61-79`) — funds are now permanently unrecoverable by anyone.
