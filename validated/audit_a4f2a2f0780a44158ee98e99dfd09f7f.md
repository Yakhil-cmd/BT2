### Title
A stale non-market oracle anchor is blended into fresh market prices, letting borrowers overvalue collateral and create bad debt - (File: `contracts/price-aggregator/src/engine.rs`)

### Summary

Dual-source oracles always return the midpoint of the primary and anchor readings when both resolve successfully. The two-leg timestamp-spread check is applied only when both feeds are declared `FeedNature::Market`; a `Fundamental` anchor can therefore remain “fresh” under its own much larger `max_stale_seconds` while it is substantially older than the live market leg. [1](#0-0) 

An unprivileged borrower can use `supply` followed by `borrow` while the market leg has moved but the fundamental anchor still contains an older, higher price. Because the accepted aggregate is the midpoint, collateral is valued above the current market price even though both configured legs pass their individual freshness checks and tolerance band. [2](#0-1) 

### Finding Description

`engine::blend` sets `spread_bounded` only if `primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market`. For a `Market` primary and `Fundamental` anchor, this condition is false, so `age_spread` is calculated but never gates the result. [3](#0-2) 

The only remaining freshness condition is each leg’s own `Reading::stale` flag. A source-specific `max_stale_seconds` can therefore make a very old fundamental quote count as non-stale even though its timestamp is far behind the market quote. [4](#0-3) 

When both readings resolve, `blend` takes `midpoint_price_or_zero(anchor.price_wad, primary.price_wad)` rather than rejecting or weighting toward the fresher market leg. The midpoint is emitted as `Outcome::price_wad` whenever the configured tolerance accepts the leg ratio. [5](#0-4) 

The deployment validator explicitly applies the leg-age-spread restriction only to two `Market` legs, allowing a non-market partner to declare a wider staleness budget. [6](#0-5) 

For example, an operation can configure a `Market` primary and `Fundamental` RedStone anchor with source-specific windows; this is not merely hypothetical because deployed oracle operations use that shape. [7](#0-6) 

### Impact Explanation

The attacker supplies collateral whose market price has fallen while the configured fundamental anchor still carries an older higher value. The aggregate becomes approximately the midpoint of the stale and fresh prices, increasing the collateral’s valuation by roughly half the accepted leg gap. [8](#0-7) 

That inflated valuation flows into the controller’s ordinary collateral and health-factor checks, so `borrow` can withdraw more debt assets than the fresh market leg would support. The attacker needs only a normal account and standard `supply` and `borrow` calls; no privilege, leaked key, malicious token, or governance action is required. [9](#0-8) 

The borrowed assets are immediately spendable, while the account is undercollateralized relative to the fresh market quote. If the stale anchor later updates or liquidation is performed using fresher prices, the residual loss can become supplier bad debt rather than a recoverable borrower obligation. [1](#0-0) 

The repository’s focused audit test demonstrates the exact boundary: a 23-hour-old `$1.00` fundamental anchor and a fresh `$0.91` market leg produce more than 4% collateral inflation, and a `$70,000` borrow succeeds where the fresh-anchor control fails with `INSUFFICIENT_COLLATERAL`. [10](#0-9) 

### Likelihood Explanation

The exploit requires a dual-source market combining a `Market` leg with a non-`Market` leg whose configured source staleness window is materially longer than the market leg’s effective freshness. The validator intentionally permits that topology because its spread-cap check is conditional on both legs being `Market`. [6](#0-5) 

A moderate market move within the configured reciprocal tolerance is enough to create the skew; the attacker does not need to manipulate either oracle report. They can wait until a slow fundamental publication lags a normal market move, then submit the public controller calls. [11](#0-10) 

The likelihood is therefore bounded by oracle publication cadence and ordinary market volatility, but it does not rely on oracle dishonesty, privileged access, route quality, or an off-chain service. [12](#0-11) 

### Recommendation

Apply the timestamp-spread bound to every dual-source blend, not only `Market`-`Market` pairs, or reject any pair whose timestamps differ by more than the tighter configured freshness window. [3](#0-2) 

If fundamental anchors are intended to smooth market volatility, use an explicit bounded smoothing formula with a hard maximum correction relative to the fresh market leg, and fail closed when the age or ratio bound is exceeded. [13](#0-12) 

Configuration validation should also reject dual-source oracles whose effective timestamp divergence can exceed a protocol-wide bound, regardless of declared `FeedNature`. [6](#0-5) 

### Proof of Concept

The existing repository test constructs a dual-source XLM oracle with a fresh Reflector market leg and a RedStone fundamental anchor. It then freezes the anchor at `$1.00` with a timestamp `82_800` seconds old, moves the market price to `$0.91`, supplies `100,000 XLM`, and calls `borrow` for `70,000 USDC`. [14](#0-13) 

The test’s control uses the same configuration with a fresh `$0.91` anchor. The stale-anchor run reports more than 4% additional collateral value and accepts the borrow, while the fresh-anchor control rejects the identical borrow with `INSUFFICIENT_COLLATERAL`. [10](#0-9)

/// Converts composed `Legs` into an `Outcome`. For two readings, marks the
/// outcome stale when either leg is individually stale, or when both legs
/// are market-nature feeds whose timestamps differ by more than
/// `MAX_LEG_AGE_SPREAD_SECONDS`. Takes the earlier of the two timestamps,
/// flags a deviation when the legs fall outside the oracle's tolerance band, and
/// sets the blended price to the midpoint of the two legs (zero if the
/// midpoint computation fails).
fn blend(env: &Env, oracle: &AssetOracle, legs: Legs) -> Outcome {
    match legs {
        Legs::Empty => Outcome::unreadable(),
        Legs::One(r) => Outcome::one(r),
        Legs::Partial { reading, slot } => Outcome::partial(reading, slot),
        Legs::Two { primary, anchor } => {
            let spread_bounded =
                primary.nature == FeedNature::Market && anchor.nature == FeedNature::Market;
            let age_spread = primary.timestamp.abs_diff(anchor.timestamp);
            let stale = primary.stale
                || anchor.stale
                || (spread_bounded && age_spread > MAX_LEG_AGE_SPREAD_SECONDS);
            let ts = primary.timestamp.min(anchor.timestamp);
            let deviation =
                !within_tolerance_band(env, anchor.price_wad, primary.price_wad, &oracle.tolerance);

            let price_wad = midpoint_price_or_zero(anchor.price_wad, primary.price_wad);
            Outcome {
                price_wad,
                timestamp: ts,
                first_wad: primary.price_wad,
                second_wad: anchor.price_wad,
                stale,
                deviation,
                err: None,

pub(crate) fn within_tolerance_band(
    env: &Env,
    anchor: i128,
    primary: i128,
    tolerance: &OracleTolerance,
) -> bool {
    let high = anchor.max(primary);
    let low = anchor.min(primary);
    let Some(upper_ratio_bps) = fp_core::try_mul_div_half_up(env, high, BPS, low) else {
        return false;
    };

    upper_ratio_bps <= i128::from(tolerance.upper_ratio_bps)
}

/// Returns the average of `anchor_price` and `primary_price`, truncated
/// toward zero. Returns `0` if the sum overflows `i128`.
pub(crate) fn midpoint_price_or_zero(anchor_price: i128, primary_price: i128) -> i128 {
    anchor_price
        .checked_add(primary_price)
        .map(|sum| sum / 2)
        .unwrap_or(0)
}
