### Title
Webhook Signature Verification Uses `repository.owner.login`/`organization.login` While Handlers Trust `repository.full_name` — Cross-Organization Forged-Event Write - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate a webhook against using one field of the JSON body (`repository.owner.login`, falling back to `organization.login`), while every event handler resolves the actual `Stack`/`Repository` to mutate using a different field of the same body (`repository.full_name`). Nothing enforces that these two fields agree, and per the documented setup, the webhook secret is optional per organization. If any configured organization has no `webhook_secret` (or an attacker otherwise obtains/knows it), `GithubApp#verify_webhook_signature` unconditionally returns `true` for that organization, letting an unauthenticated party submit an arbitrary payload that is "authenticated" as that unsecured organization but whose `repository.full_name` — and therefore the stacks/repositories actually written to — can name any other organization/repository tracked by the Shipit instance. This is exactly the "organization that authenticated versus the repository that is written" trust binding called out in scope.

### Finding Description
`WebhooksController#verify_signature` computes the organization to authenticate against from the payload itself, then verifies against that organization's secret: [1](#0-0) 

The organization used for verification comes from: [2](#0-1) 

`GithubApp#verify_webhook_signature` short-circuits to `true` whenever the resolved organization has no configured `webhook_secret`: [3](#0-2) 

Per the setup docs, the webhook secret is explicitly documented as optional per app/organization: [4](#0-3) 

Meanwhile, every `Handler` subclass resolves the target `Repository`/`Stack` set from an entirely different payload field — `repository.full_name` — with no cross-check against the field used for signature verification: [5](#0-4) 

This is used, e.g., by `PushHandler`, which invokes `stack.sync_github(expected_head_sha: params.after)` for every non-archived stack matching the branch on whatever repository `full_name` names: [6](#0-5) 

and by the PR-related handlers (`labeled_handler.rb`, `unlabeled_handler.rb`, `opened_handler.rb`, `reopened_handler.rb`, `assigned_handler.rb`) which archive/unarchive review stacks or mutate `PullRequest` records for the repository named by `params.repository.full_name`: [7](#0-6) 

The binding that should hold is:
`organization authenticated by verify_signature (repository.owner.login / organization.login) == organization owning the repository actually mutated by the handler (repository.full_name)`

Nothing in `WebhooksController` or `Handler` enforces this equality — the signature only proves the raw body was signed by *some* configured organization's secret (or, if that organization has no secret at all, proves nothing), while the write target is taken from a sibling field of the same untrusted body.

### Impact Explanation
In a Shipit deployment tracking multiple GitHub organizations (the multi-org `github:` config block shown in `config/secrets.development.shopify.yml` is exactly this topology), if even one configured organization omits `webhook_secret` (explicitly documented as optional), any unauthenticated network client can:
1. Craft a JSON body with `repository.owner.login` (or `organization.login`) set to the unsecured organization, so `verify_signature` passes unconditionally.
2. Set `repository.full_name` to any *other* tracked organization/repository.
3. Trigger cross-repository writes on stacks belonging to a completely different, secured organization — e.g. forcing `GithubSyncJob`/`stack.sync_github` with an attacker-chosen `expected_head_sha`, archiving/unarchiving review stacks, or mutating `PullRequest` records for repositories the attacker has no legitimate relationship to.

This satisfies the Critical "cross-repository writes" impact criterion: writes are performed against a repository the attacker never authenticated for, using authentication that was only ever valid for an unrelated (unsecured) organization.

### Likelihood Explanation
Requires an unprivileged network attacker only — no Shipit session, API token, or GitHub credentials of any kind. The only precondition is that at least one organization configured in the Shipit instance's `github:` secrets has no `webhook_secret` set, which the project's own setup documentation calls out as an optional field, making this a realistic operational configuration rather than a contrived edge case.

### Recommendation
Bind signature verification to the same repository identity used for the write path: resolve the target `Repository`/`Stack` first (from `repository.full_name`), verify the signature using the secret configured for *that* repository's actual owning organization, and reject/require a non-empty `webhook_secret` for every organization (removing the "optional secret" bypass), rather than deriving the verification organization from a separate, unrelated payload field.

### Proof of Concept
Given a Shipit `github:` config with two organizations, `unsecured-org` (no `webhook_secret`) and `secured-org` (target victim, tracked stacks exist), send:

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored, see below
Content-Type: application/json

{
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "owner": { "login": "unsecured-org" },
    "full_name": "secured-org/victim-repo"
  }
}
```

`verify_signature` resolves `repository_owner` to `unsecured-org`, calls `GithubApp#verify_webhook_signature`, which returns `true` immediately because `unsecured-org` has no `webhook_secret`. `PushHandler#process` then resolves stacks via `Repository.from_github_repo_name("secured-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on stacks the attacker never authenticated against.

```ruby
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
```
