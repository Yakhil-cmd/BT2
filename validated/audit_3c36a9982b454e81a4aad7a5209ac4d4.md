## Finding

### Title
Commit-review security hook can be forced to fully skip review by padding a commit/diff past the pathological-file-count threshold - (File: `plugins/security-guidance/hooks/security_reminder_hook.py`)

### Summary
The reported Tempus bug is a griefing pattern: an attacker perturbs shared, attacker-observable/attacker-influenceable state (contract token balance) that a downstream invariant check (`assert balance == 0`) relies on, causing the check to fail and the entire legitimate operation to become unusable. The `security-guidance` plugin's commit-review and Stop hooks contain a structurally analogous invariant check on attacker-influenceable state — the number of files in a diff — where crossing a fixed threshold causes the entire security review to be skipped outright rather than degraded gracefully, and the threshold is trivially forced by anyone who can add files to the commit/diff being reviewed.

### Finding Description
`handle_commit_review_posttooluse` computes `diff_files` from the commit's `git show`/`git diff` output and then unconditionally bails out of the whole review when the file count crosses a hard multiple of `MAX_DIFF_FILES`: [1](#0-0) 

The same "pathological diff → skip everything" gate exists on the Stop-hook path for uncommitted edits: [2](#0-1) 

`MAX_DIFF_FILES` is a fixed constant (default 30), so the bail-out threshold is `10 * MAX_DIFF_FILES` = 300 files: [3](#0-2) 

The `diff_files` count is derived purely from `parse_diff_into_files`/`extract_file_paths_from_diff` walking the raw `git diff`/`git show` output — i.e., it is fully determined by whatever files are present in the reviewed commit or working-tree diff: [4](#0-3) 

Just like the Tempus bug — where an unprivileged party sends a trivial amount of yield shares to perturb a contract-level invariant (`balanceOf == 0`) that a legitimate `depositAndFix` transaction depends on — an unprivileged contributor to a repository under active Claude Code review can perturb the diff-file-count invariant that the security-review hooks depend on. By bundling their malicious change together with >300 trivial/generated files in the same commit (or the same uncommitted change-set for the Stop hook), the file count crosses the hard threshold and the entire review is skipped via `sys.exit(0)` — no LLM review, no findings, no guidance is ever produced for that commit's actual content.

### Impact Explanation
Where the Tempus bug denies a legitimate financial operation (DoS), this analog denies the legitimate security function itself (fail-open bypass): a security control that is supposed to review every commit/diff can be reliably and deterministically defeated by any party able to influence the size/shape of the reviewed diff (e.g., a malicious PR author, a compromised dependency-update bot, or a co-contributor bundling generated/vendored files). This is a "hook bypass" of the security-guidance control — the exact category explicitly in scope — and it hides the malicious diff content from both the commit-review and Stop-hook review surfaces simultaneously, since both share the same threshold logic.

### Likelihood Explanation
The trigger condition is a fixed, publicly-knowable constant (`300` files) with no rate-limiting or anomaly detection around it, and is reachable via completely ordinary, unprivileged git operations (adding files to a commit or working tree). No special access to Claude Code, hooks configuration, or credentials is required — only the ability to get a large-file-count change reviewed by the hook, which is the same trust boundary the hook is meant to defend (arbitrary/malicious commit content).

### Recommendation
Replace the hard skip with graduated degradation consistent with the file-prioritization logic already used below the threshold (`_prioritize_diff_files`): always review the top-N highest-risk files by path/heuristic regardless of total file count, rather than emitting zero findings once a size threshold is crossed. If a hard ceiling is still desired for cost control, it should never fully disable review — cap what is *sent* to the LLM (as `_cap_files_for_prompt`/`cap_diff_for_prompt` already do for bytes) instead of skipping the review call entirely.

### Proof of Concept
1. In a repository with the `security-guidance` commit-review hook enabled, create a commit that touches 1 genuinely malicious file (e.g., adds a command-injection sink) plus 300+ trivial/generated files (e.g., copies of a large vendored directory, a regenerated lockfile split into many files, or auto-generated boilerplate).
2. Run `git commit -a -m "vendor update"` (or push it, hitting the analogous push-sweep bail-out).
3. `handle_commit_review_posttooluse` computes `diff_files` with `len(diff_files) > 300`, hits the `skip_reason=31` branch, and `sys.exit(0)`s before `analyze_code_security`/`agentic_review` ever runs — the malicious file receives no security review, and no finding is ever surfaced to the user or recorded in `previous_findings`.

def parse_diff_into_files(diff_output):
    """
    Parse unified diff output into a list of (file_path, diff_content) tuples.
    Only includes files with source code extensions.
    """
    if not diff_output or not diff_output.strip():
        return []

    files = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue

        # Extract filename from first line: "a/path/to/file b/path/to/file"
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue

        file_path = header_match.group(2) or header_match.group(1) or ''

        # Filter to source code files only
        if not _is_reviewable_source(file_path):
            continue

        # Extract the diff content (from first @@ onwards)
        diff_lines = []
        in_hunks = False
        for line in lines[1:]:
            if line.startswith('@@'):
                in_hunks = True
            if in_hunks:
                diff_lines.append(line)

        if diff_lines:
            files.append((file_path, '\n'.join(diff_lines)))

    return files
