### Title
Tokens sent directly to the pool or controller are permanently unrecoverable — no sweep or surplus-withdrawal path exists - (File: contracts/pool/src/cache/cash.rs)

### Summary
The Nouns Stream bug class — "surplus tokens sent to the contract can only be recovered by tearing down the whole position" — maps onto XOXNO Lending as a stronger variant: tokens transferred directly to the pool or controller are unbooked and there is no unprivileged (or even privileged in-pool) entrypoint that can return them. The excess can only leave the pool if it is consumed to pay out *other* users' claims, i.e. it is absorbed by the protocol rather than returned.

### Finding Description
The pool tracks a `cash` accounting book that is deliberately decoupled from its physical token balance. `credit_cash`/`debit_cash` are the only ways the book moves, and `transfer_out` is only invoked on paths where the caller's entitlement was first booked (withdraw, borrow, revenue claim, refund legs) [1](#0-0) .

Every token-funded credit path uses measured receipt (`balance_delta_since`) and refunds are bounded to the delta measured *within that call* — `refund_controller_balance_delta` explicitly "preserv[es] the pre-existing balance" [2](#0-1) . Liquidation excess refunds are likewise computed only against the caller's own declared payment legs [3](#0-2) .

The documentation confirms donations are unbooked by design: "Direct donations do not rewrite those books" [4](#0-3)  and "Tracked cash is a separate reserve balance that incidental token donations do not increase" [5](#0-4) . Unlike the out-of-scope swap-aggregator, which has an owner-only `sweep_balance` that pays the balance above reserved fees [6](#0-5) , neither `contracts/pool` nor `contracts/controller` contains any sweep/rescue/skim function — a grep for `sweep|rescue|stray|skim` across all in-scope contracts returns only unrelated matches.

So an unprivileged user who transfers tokens straight to the pool (or has leftovers stranded at the controller, which also has no sweep) has no call — `supply`, `repay`, `recapitalize`, `flash_loan`, any liquidation leg, or governance operation — that will return the surplus. All outbound transfers are gated by `require_reserves` against the cash book, which never credited the donation [7](#0-6) .

### Impact Explanation
Permanent freezing of funds for the sender, and an effective windfall donation to the market: the stranded balance is excess custody above the `cash` book that will eventually be drawn down to satisfy supplier withdrawals and borrows it was never booked against — the original sender cannot reclaim it through any entrypoint. This is worse than the reference finding, where `cancel` at least returned the surplus to the payer; here no equivalent exists at any privilege level within the pool/controller.

### Likelihood Explanation
Requires a user error (direct transfer to a contract address) or stranded leftovers — e.g. a measured-delta path that intentionally preserves pre-existing controller balances, confirmed reachable in `test_swap_debt_refund_only_uses_strategy_excess` and `test_migrate_refund_ignores_preexisting_controller_balance` where stray controller balances demonstrably persist [8](#0-7) . Individual events are infrequent but the recovery probability is zero, which is the Medium-severity shape of the source report.

### Recommendation
Add a governance-executed surplus sweep on the pool (and optionally the controller) that pays out `token.balance(pool) - sum_over_markets(cash)` for a given asset — the analogue of the report's "rescue surplus in excess of `tokenAmount`" — without touching any market's booked cash. The hub/spoke shared-custody layout requires the sweep amount to be computed across all markets of the same asset, not per-market.

### Proof of Concept
1. `token.transfer(user -> pool, X)` directly (Soroban SAC transfer, unprivileged).
2. `cash` book is unchanged (donations do not credit cash — INV-ACCT-02); `token.balance(pool) == sum(cash) + X`, exactly as pinned by `pool_all_money_paths_preserve_books_and_shared_token_custody` which asserts `balance == cash_a + cash_b + donation` [9](#0-8) .
3. Enumerate every outbound path: `withdraw`/`borrow`/`claim_revenue` are capped by `require_reserves(cash)`; `repay`/`recapitalize` refunds are capped by the intra-call measured delta; controller refunds preserve pre-existing balance. No call can pay `X` to the donor.
4. Result: `X` is permanently unrecoverable by its sender and is progressively absorbed into other users' payouts — analogous to the Nouns Stream locked-surplus, with no `cancel`-equivalent escape.

    /// Increases accounting cash by `amount`. Rejects negative amounts and overflow.
    pub(crate) fn credit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.cash = self
            .cash
            .checked_add(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Decreases accounting cash by `amount`. Rejects negative amounts or
    /// insufficient reserves.
    pub(crate) fn debit_cash(&mut self, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        self.require_reserves(amount);
        self.cash = self
            .cash
            .checked_sub(amount)
            .unwrap_or_else(|| panic_with_error!(&self.env, GenericError::MathOverflow));
    }

    /// Transfers `amount` of the market asset from the pool to `recipient`.
    ///
    /// Rejects negative amounts; zero is a no-op. Does not adjust accounting cash.
    pub(crate) fn transfer_out(&self, recipient: &Address, amount: i128) {
        require_nonneg_amount(&self.env, amount);
        if amount == 0 {
            return;
        }
        let tok = token::Client::new(&self.env, &self.params.asset_id);
        tok.transfer(&self.env.current_contract_address(), recipient, &amount);
    }

fn process_excess_payment(
    env: &Env,
    repaid_tokens: &mut Vec<RepayEntry>,
    refunds: &mut Vec<PaymentTuple>,
    excess_usd: Wad,
    keep_within_quote: bool,
) {
    let mut remaining_excess_usd = excess_usd;
    let mut current_index = repaid_tokens.len();
    while remaining_excess_usd > Wad::ZERO && current_index > 0 {
        current_index -= 1;
        let entry = expect_invariant(env, repaid_tokens.get(current_index));
        if entry.amount <= 0 {
            continue;
        }
        let usd = Wad::from(entry.usd_wad);
        if usd == Wad::ZERO {
            continue;
        }
        if usd > remaining_excess_usd {
            let decimals = entry.feed.asset_decimals;
            let price = Wad::from(entry.feed.price_wad);
            let new_amount = if keep_within_quote {
                usd.checked_sub(env, remaining_excess_usd)
                    .div_floor(env, price)
                    .to_token_floor(env, decimals)
                    .min(entry.amount)
            } else {
                let ratio = remaining_excess_usd.div_floor(env, usd);
                entry.amount
                    - Wad::from_token(env, entry.amount, decimals)
                        .mul_floor(env, ratio)
                        .to_token_floor(env, decimals)
            };
            let new_usd = Wad::from_token(env, new_amount, decimals).mul(env, price);
            refunds.push_back(PaymentTuple {
                asset: entry.hub_asset.asset.clone(),
                amount: entry.amount - new_amount,
            });

    #[only_owner]
    fn sweep_balance(env: Env, recipient: Address, tokens: Vec<Address>) {
        renew_instance(&env);
        let router = env.current_contract_address();
        let n = tokens.len();
        for i in 0..n {
            // `i < n == tokens.len()`, so the index is in range by construction.
            let token = tokens.get_unchecked(i);
            let client = token::Client::new(&env, &token);
            let balance = client.balance(&router);
            let reserved = storage::reserved_fee_balance(&env, &token);
            if balance > reserved {
                client.transfer(&router, &recipient, &(balance - reserved));
            }
        }
    }
