### Title
Pool creator permanently loses access to accrued creator fees if either token is blacklisted/frozen for their fee-recipient account - (File: programs/cp-swap/src/instructions/collect_creator_fee.rs, programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs)

### Summary
`collect_creator_fee` and `collect_creator_fee_permissionless` transfer both `creator_fees_token_0` and `creator_fees_token_1` to the pool creator atomically, with no pull-based or per-token fallback. If the creator's fixed, deterministically-derived associated token account for either mint is frozen/blacklisted (e.g. a legacy USDT/USDC-style freeze), the whole instruction reverts and the creator can never collect the accrued fees for the other, unaffected token either.

### Finding Description
Both instructions load `pool_state.creator_fees_token_0`/`creator_fees_token_1` and then issue two sequential `transfer_from_pool_vault_to_user` CPIs before zeroing the counters: [1](#0-0) 

The recipient accounts are not attacker/user-selectable — they are `init_if_needed` ATAs pinned to `associated_token::authority = creator`: [2](#0-1) 

The identical pattern exists in the permissionless variant, whose recipient ATAs are likewise pinned to the `creator` authority (only the payer differs): [3](#0-2) [4](#0-3) 

`is_supported_mint` (enforced only at `initialize`/`initialize_with_permission`) unconditionally allows any plain SPL Token-program mint regardless of whether it has a `freeze_authority` set — it only inspects Token-2022 extension types and does not check the base `freeze_authority` field at all: [5](#0-4) [6](#0-5) 

This means a pool pairing a normal SPL token with a real blacklist-capable stablecoin (USDT/USDC-style, freeze authority held by the issuer) passes the mint check unconditionally (`Token::id()` branch returns `Ok(true)`), so such pools are fully permitted. Because the creator's fee-recipient token account address is fixed by the `associated_token::authority = creator` constraint (unlike `withdraw`, where `token_0_account`/`token_1_account` carry no ownership constraint and the caller may freely supply any valid token account of the right mint, allowing them to route around a frozen ATA), the creator has no way to substitute an alternate, unfrozen account to receive the fees. If the creator's ATA for either mint is frozen at the SPL Token-program level, both `transfer_from_pool_vault_to_user` calls must succeed atomically or the whole instruction reverts (`creator_fees_token_0`/`creator_fees_token_1` are only zeroed after both transfers), so accrued fees for the *unaffected* token also become permanently unclaimable through this path — mirroring the ClaimManager "all-or-nothing" bug class.

### Impact Explanation
The pool creator's economically-owned, already-accrued creator fees for token_0 and/or token_1 become permanently locked in the vault with no pull mechanism, alternate recipient, or partial-collection path in either `collect_creator_fee` or `collect_creator_fee_permissionless`. This is a permanent freezing of legitimately-earned funds triggered purely by the atomic bundling design, not by any error on the creator's part.

### Likelihood Explanation
Requires only that one of the pool's two mints is a real blacklist-capable token (common for stablecoins) and that the specific creator ATA becomes frozen/blacklisted by that token's issuer — a realistic, externally-triggerable precondition that `is_supported_mint` does nothing to prevent since it never inspects `freeze_authority` for legacy SPL Token mints.

### Recommendation
Decouple token_0 and token_1 fee collection into independently claimable instructions (or wrap each transfer in a manner that lets one succeed/fail independently), and/or allow the creator to designate an alternate, non-frozen recipient token account instead of a fixed ATA, consistent with the flexibility already present in `withdraw`.

### Proof of Concept
1. Attacker (or any user) permissionlessly creates a pool via `initialize` pairing a benign token with a real blacklist-capable stablecoin such as USDT/USDC as `token_1_mint`; `is_supported_mint` accepts it unconditionally since it is a plain Token-program mint.
2. Pool operates normally; swaps accrue `creator_fees_token_0` and `creator_fees_token_1` in `pool_state`.
3. The stablecoin issuer freezes the creator's associated token account for `token_1_mint` (a real-world, externally-controlled event, independent of cp-swap).
4. Creator calls `collect_creator_fee` (or anyone calls `collect_creator_fee_permissionless`); the second `transfer_from_pool_vault_to_user` for token_1 fails inside the Token program due to the frozen destination account, reverting the whole instruction.
5. Because `creator_token_0`/`creator_token_1` are pinned ATAs with no alternate-recipient option, the creator can never collect `creator_fees_token_0` either — both fee balances remain permanently stuck in the vaults.

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount
        {
            return Ok(false);
        }
    }
    Ok(true)
}
