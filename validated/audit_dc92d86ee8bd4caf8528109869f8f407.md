### Title
Unsanitized skill file paths injected into interactive file-picker prompt enable terminal/menu spoofing - ([File: pkg/cmd/skills/preview/preview.go])

### Finding Description
`renderInteractive` builds the `choices` slice directly from `extraFiles[i].Path` with no validation or escaping: [1](#0-0) 

These `Path` values originate from the Git tree API response for the skill's directory and are fully attacker-controlled — any repository owner, forker, or PR-branch author can name a file inside a skill directory using arbitrary bytes (Git tree entry names only disallow `/` and NUL within a path component; embedded newlines, control characters, and ANSI/OSC escape sequences are permitted): [2](#0-1) 

The raw strings are passed straight to `opts.Prompter.Select(...)`: [3](#0-2) 

Both prompter backends (`huhPrompter.Select` / `accessiblePrompter.Select` / `surveyPrompter.Select`) simply hand the option string to the underlying `huh`/`survey` option renderer without stripping control sequences: [4](#0-3) [5](#0-4) 

Notably, other parts of the skills feature (e.g. `pkg/cmd/skills/list/list.go`) apply output sanitization to untrusted skill metadata before printing, indicating the project is aware sanitization is needed for attacker-controlled skill strings — but `renderInteractive`'s file-picker path was not brought in line with that pattern.

### Impact Explanation
An attacker who publishes a repository/skill (or a PR branch/fork that the victim previews) can embed newline characters or ANSI/OSC-8 escape sequences in a file name so that, when rendered inside the terminal UI list widget, the option text visually fragments or overlays adjacent list rows. This can be used to fabricate the appearance of an extra menu entry, hide/mask the real file name behind fake "safe-looking" text (e.g., render `README.md` while the underlying path is actually a script), or otherwise visually mislead the user about what item they are selecting in `gh skill preview`'s file browser. This is a terminal output/UI spoofing issue (deceptive prompt rendering) rather than remote code execution or credential exfiltration — the underlying `idx` returned by `Select` still indexes correctly into `extraFiles`, so the attacker cannot force selection of a different file than what is highlighted, but they can deceive the victim about what is highlighted/what will be viewed next.

### Likelihood Explanation
Requires only that the victim run `gh skill preview <attacker-repo>` (or preview a skill from a fork/PR branch) interactively with a TTY, and that the skill directory contain more than one file — both are ordinary, expected usage patterns for this command, and repository/skill content is entirely attacker-controlled. No special privileges are needed beyond publishing the repository content.

### Recommendation
Sanitize `SkillFile.Path` (and any other attacker-controlled display strings, including the file tree renderer in `renderFileTree`/`printTree`) before using them as prompt/choice labels — strip or escape control characters (`\n`, `\r`, `\t`, ESC/`\x1b`) and non-printable Unicode, consistent with the sanitization already applied in `pkg/cmd/skills/list/list.go`. Apply this sanitization once in `discovery.ListSkillFiles`/`DiscoverSkillFiles` or immediately when building `choices` in `renderInteractive`.

### Proof of Concept
```go
func TestRenderInteractive_SanitizesMenuChoices(t *testing.T) {
    var captured []string
    mockPrompter := &prompter.PrompterMock{
        SelectFunc: func(prompt, defaultValue string, options []string) (int, error) {
            captured = options
            return 0, errors.New("esc") // exit after capturing
        },
    }
    opts := &PreviewOptions{
        IO:       iostreams.Test(),
        Prompter: mockPrompter,
    }
    extraFiles := []discovery.SkillFile{
        {Path: "legit.sh\n\x1b[2Ahidden-fake-entry.sh", SHA: "sha1"},
    }
    renderInteractive(opts, opts.IO.ColorScheme(), discovery.Skill{}, nil, "", extraFiles, nil, "github.com", "o", "r")

    for _, c := range captured {
        assert.NotContains(t, c, "\n")
        assert.NotContains(t, c, "\x1b")
    }
}
```
Expected (current) result: the assertion fails because `captured[1]` equals the raw `"legit.sh\n\x1b[2Ahidden-fake-entry.sh"` string, demonstrating the unsanitized escape/newline sequence reaches the prompter's choice list.
