### Title
Missing Cross-Epoch Validation Between `LowerBoundBaseFee` and `UpperBoundBaseFee` Allows Inverted Fee Bounds — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` validates each KIP-71 base-fee governance vote in isolation against the **current** parameter set. Because two votes (`Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee`) can be cast in the same epoch and are each checked only against the pre-epoch state, a validator (in `none` governance mode) or the governing node (in `single` mode) can submit two individually-valid votes that, when applied together at epoch boundary, produce `LowerBoundBaseFee > UpperBoundBaseFee`. Once inverted, `NextMagmaBlockBaseFee()` pins the base fee to `UpperBoundBaseFee` (the lower value), causing every subsequent block to carry a base fee below the intended minimum. `VerifyMagmaHeader()` enforces this wrong value, so all honest nodes accept blocks with the incorrect base fee.

---

### Finding Description

**Root cause — per-vote isolation in `checkConsistency`:** [1](#0-0) 

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)          // reads CURRENT state
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)          // reads CURRENT state
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    }
```

Each vote is validated against `GetParamSet(blockNum)`, which returns the parameters **before** any pending epoch votes are applied. There is no check that combines the effect of both votes.

**Attack sequence (governance mode = `none`, any validator can vote):**

| Step | Action | Check performed | Result |
|------|--------|----------------|--------|
| Current state | Lower=25 Gkei, Upper=750 Gkei | — | valid |
| Block N (epoch E) | Vote `Kip71UpperBoundBaseFee = 30 Gkei` | `30G < 25G`? → No | **passes** |
| Block N+k (epoch E) | Vote `Kip71LowerBoundBaseFee = 35 Gkei` | `35G > 750G`? → No | **passes** |
| Epoch boundary | Both applied | — | **Lower=35G, Upper=30G — INVERTED** |

**Consequence in `NextMagmaBlockBaseFee()`:** [2](#0-1) 

With `LowerBound=35G > UpperBound=30G`, after `makeEvenByCeil`/`makeEvenByFloor`:

```
parentBaseFee.Cmp(upperBoundBaseFee) >= 0  // always true (any fee ≥ 35G > 30G)
→ parentBaseFee = upperBoundBaseFee         // pinned to 30G
→ returns 30G as the next base fee
```

The base fee is permanently pinned to `UpperBoundBaseFee` (30 Gkei), which is **below** the intended minimum of 35 Gkei.

**`VerifyMagmaHeader()` enforces the wrong value:** [3](#0-2) 

All honest nodes call `VerifyMagmaHeader()` → `NextMagmaBlockBaseFee()` → compute the same wrong base fee → accept blocks carrying it. The chain reaches consensus on an invalid base fee.

**No genesis-level guard exists either:** [4](#0-3) 

`ValidateGenesisConfig()` checks `ProposerUpdateInterval != 0` and `StakingUpdateInterval != 0` but has no `LowerBoundBaseFee <= UpperBoundBaseFee` check. The `genKIP71Config()` genesis tool also applies no such check: [5](#0-4) 

The individual `FormatChecker` entries for both parameters are `noopFormatChecker`: [6](#0-5) 

---

### Impact Explanation

Once `LowerBoundBaseFee > UpperBoundBaseFee` is committed to chain state:

1. **Invalid base fee on every subsequent block** — `NextMagmaBlockBaseFee()` returns `UpperBoundBaseFee` (the smaller value) regardless of gas usage, breaking the EIP-1559-style fee market.
2. **All honest nodes accept the wrong base fee** — `VerifyMagmaHeader()` enforces the computed (wrong) value, so the invalid state propagates canonically.
3. **Fee revenue below intended minimum** — transactions pay fees at `UpperBoundBaseFee` (e.g., 30 Gkei) instead of the intended floor (e.g., 35 Gkei). This is a direct, measurable reduction in fee-based KAIA collection per block.
4. **Persistent corruption** — the inverted bounds remain in the governance parameter set until a corrective vote is passed, which itself requires another epoch cycle.

---

### Likelihood Explanation

- In **`none` governance mode** (any validator can vote), two validators (or one validator casting two votes in the same epoch) can trigger this without any special privilege.
- In **`single` governance mode** (mainnet), the governing node must cast both votes — this is a privileged actor, but the missing invariant still represents a latent misconfiguration risk (e.g., via genesis JSON or contract governance).
- The `FormatChecker` for both parameters is `noopFormatChecker`, so no individual-value check catches the inversion.
- The contract governance path (`ContractGov`) also reads parameters without the `checkConsistency` cross-check, providing an additional route.

---

### Recommendation

Add a cross-parameter check at epoch application time (not just per-vote), and add a genesis-level guard:

1. **In `checkConsistency`** — when validating a `Kip71LowerBoundBaseFee` vote, also check it against any pending `Kip71UpperBoundBaseFee` vote in the same epoch (and vice versa).
2. **In `ValidateGenesisConfig()`** — add:
   ```go
   if kip71 := g.Config.Governance.KIP71; kip71 != nil {
       if kip71.LowerBoundBaseFee > kip71.UpperBoundBaseFee {
           return errors.New("LowerBoundBaseFee must not exceed UpperBoundBaseFee")
       }
   }
   ```
3. **In `NextMagmaBlockBaseFee()`** — add a defensive guard:
   ```go
   if lowerBoundBaseFee.Cmp(upperBoundBaseFee) > 0 {
       // inverted bounds: clamp to upper (or return error)
       lowerBoundBaseFee = upperBoundBaseFee
   }
   ```

### Proof of Concept

**Setup:** Private network, governance mode = `none`, Magma fork enabled, current params: `Lower=25G, Upper=750G`.

**Step 1:** Validator A casts vote in block N (epoch E):
```
governance.vote("kip71.upperboundbasefee", 30_000_000_000)  // 30 Gkei
```
`checkConsistency`: `30G < 25G`? → No → **accepted**.

**Step 2:** Validator A (or B) casts vote in block N+1 (same epoch E):
```
governance.vote("kip71.lowerboundbasefee", 35_000_000_000)  // 35 Gkei
```
`checkConsistency`: `35G > 750G`? → No → **accepted**.

**Step 3:** At epoch boundary, both votes are applied:
- `LowerBoundBaseFee = 35_000_000_000`
- `UpperBoundBaseFee = 30_000_000_000`
- **Invariant broken: Lower > Upper**

**Step 4:** Next block's base fee computation via `NextMagmaBlockBaseFee()`:
- `lowerBound = 35G`, `upperBound = 30G`
- Any `parentBaseFee >= 30G` → `parentBaseFee = upperBound = 30G`
- Returns `30G` as the canonical next base fee

**Step 5:** `VerifyMagmaHeader()` enforces `baseFee == 30G` on all honest nodes. Blocks with `baseFee = 30G` (below the intended 35G minimum) are accepted by the entire network. [7](#0-6) [2](#0-1) [3](#0-2)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
	case gov.Kip71LowerBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) > params.UpperBoundBaseFee {
			return ErrLowerBoundBaseFee
		} else {
			return nil
		}
	case gov.Kip71UpperBoundBaseFee:
		params := h.GetParamSet(blockNum)
		if vote.Value().(uint64) < params.LowerBoundBaseFee {
			return ErrUpperBoundBaseFee
		} else {
			return nil
		}

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}
