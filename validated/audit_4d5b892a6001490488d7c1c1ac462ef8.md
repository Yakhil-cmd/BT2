### Title
Wallet leaks its permanent device‑pairing secret to an attacker‑chosen arbstore URL during arbiter‑contract dispute/appeal flow - (File: `arbiter_contract.js`)

### Summary
The arbiter‑contract dispute (`openDispute`) and appeal (`appeal`) flows build a JSON payload that includes the caller's own permanent pairing code (`device_pubkey@hub#pairing_secret`) and the counterparty's pairing code, then POST it via `httpRequest()` to a URL that is resolved from the attacker‑influenceable `arbiter_address` field of the contract. Because the `arbiter_address` (and therefore the destination host of the outbound request) is supplied by the untrusted counterparty when the contract offer is created/stored, a malicious counterparty (or colluding "arbiter") can steer this request to a server they control and receive the victim's permanent pairing secret — the credential that allows anyone to pair with (impersonate a correspondent to) the victim's wallet device.

### Finding Description
`createAndSend()` generates the wallet's permanent pairing info and stores it as `my_pairing_code` on the contract row: [1](#0-0) 

Contracts (including the `arbiter_address` field) are received from a peer device and persisted via `store()` without any validation that `arbiter_address` designates a trustworthy, vetted arbiter — it is accepted as supplied by the counterparty: [2](#0-1) 

When a dispute is opened, the wallet resolves the arbstore URL purely from this counterparty‑supplied `arbiter_address` via the hub, then POSTs a payload containing both parties' permanent pairing codes to that URL: [3](#0-2) 

The same pattern (resolve URL from `arbiter_address`/`arbstore_address`, then POST identifying/secret data) repeats for `appeal()`: [4](#0-3) 

The `httpRequest()` helper simply performs a POST to whatever host `url.parse(host)` yields, with no allow‑listing of the destination host: [5](#0-4) 

`arbiters.getArbstoreInfo`/`arbiters.getInfo` similarly resolve and trust a URL for any `arbiter_address` string via `device.requestFromHub("hub/get_arbstore_url", ...)`, with no cryptographic binding proving the address is a legitimate, community‑vetted arbiter versus any address an attacker registers as an "arbiter" with a hub: [6](#0-5) 

Because `arbiter_address` originates from the contract offer sent by the counterparty (an unprivileged peer who can pick any address, including one they themselves control and register an arbstore URL for), the destination host of the dispute/appeal HTTP request is effectively attacker‑controlled. The payload sent to that host includes `my_pairing_code` — `device_pubkey + "@" + hub + "#" + pairing_secret` — which is the credential required to pair with the victim's device. This mirrors the reported bug class: an outbound request whose target host is user/peer‑controlled carries along a secret credential, defeating the intended trust boundary (only a genuine arbiter should ever see it).

### Impact Explanation
Leaking the permanent pairing secret lets an attacker pair with the victim's wallet device as a "correspondent." Paired devices in ocore are trusted for chat, shared/multisig address negotiation, private‑payment chain exchange, and various wallet message flows (`device.js` `handlePairingMessage` and related handlers). An attacker who obtains this secret can impersonate a trusted correspondent to the victim, phish for signatures on malicious multisig/shared-address definitions, intercept or manipulate private‑payment chain exchanges, or otherwise leverage device‑level trust to move toward fund loss — a high‑severity confidentiality breach with a credible path to unauthorized spending.

### Likelihood Explanation
Exploitation requires only that the attacker (or a colluding party acting as "arbiter") propose an arbiter contract to the victim naming an address they control as `arbiter_address`, and register an arbstore URL for that address with a hub — both are ordinary, unprivileged actions available to any wallet user in the arbiter‑contract feature. The victim then triggers the leak simply by using the normal dispute/appeal flow of the contract they accepted.

### Recommendation
- Do not include `my_pairing_code` (or the counterparty's pairing_secret) in payloads sent to arbstore URLs resolved from a peer‑supplied `arbiter_address`; use a one‑time, dispute‑scoped token instead of the permanent pairing secret.
- Validate/pin arbiter addresses against a vetted, signed registry rather than trusting whatever URL the hub returns for an arbitrary address.
- Restrict `httpRequest()` destinations (e.g., verify TLS identity matches a registered arbiter public key) before sending any secret material.

### Proof of Concept
1. Attacker generates address `A` and registers it with a hub as an arbiter, pointing `hub/get_arbstore_url(A)` to `https://attacker.example`.
2. Attacker (as counterparty) sends victim an `arbiter_contract_offer` with `arbiter_address = A` via `device.sendMessageToDevice` (see `createAndSend`, `arbiter_contract.js:21-27`); victim's wallet stores it via `store()` (`arbiter_contract.js:91-116`).
3. Victim later disputes the contract; wallet calls `openDispute()`, which resolves the URL for `A` from the hub and POSTs `{ my_pairing_code, peer_pairing_code, ... }` to `https://attacker.example/api/dispute/new` (`arbiter_contract.js:262-318`).
4. Attacker's server logs the victim's `my_pairing_code`, then uses it to pair with the victim's device as a trusted correspondent.

function appeal(hash, cb) {
	getByHash(hash, function(objContract){
		if (objContract.status !== "dispute_resolved")
			return cb("contract can't be appealed");
		var command = "hub/get_arbstore_url";
		var address = objContract.arbiter_address;
		if (objContract.arbstore_address) {
			command = "hub/get_arbstore_url_by_address";
			address = objContract.arbstore_address;
		}
		device.requestFromHub(command, address, async function(err, url){
			if (err)
				return cb("can't get arbstore url:", err);
			err = await fillArbstoreAddresses(objContract);
			if (err)
				return cb(err);
			device.getOrGeneratePermanentPairingInfo(function(pairingInfo){
				var my_pairing_code = pairingInfo.device_pubkey + "@" + pairingInfo.hub + "#" + pairingInfo.pairing_secret;
				var data = JSON.stringify({
					contract_hash: hash,
					my_pairing_code: objContract.my_pairing_code,
					my_address: objContract.my_address,
					contract: {title: objContract.title, text: objContract.text, creation_date: objContract.creation_date, me_is_payer: objContract.me_is_payer, my_address: objContract.my_address, peer_address: objContract.peer_address, my_party_name: objContract.my_party_name, peer_party_name: objContract.peer_party_name, arbiter_address: objContract.arbiter_address, amount: objContract.amount, asset: objContract.asset},
				});
				httpRequest(url, "/api/appeal/new", data, function(err, resp) {
					if (err)
						return cb(err);
					setField(hash, "status", "in_appeal", function(objContract) {
						cb(null, resp, objContract);
					});
				});
			});
		});
	});
}

function httpRequest(host, path, data, cb) {
	var reqParams = Object.assign(url.parse(host),
		{
			path: path,
			method: "POST",
			headers: {
				"Content-Type": "application/json",
				"Content-Length": (new TextEncoder().encode(data)).length
			}
		}
	);
	var req = http.request(
		reqParams,
		function(resp){
			var data = "";
			resp.on("data", function(chunk){
				data += chunk;
			});
			resp.on("end", function(){
				try {
					data = JSON.parse(data);
					if (data.error) {
						return cb(data.error);
					}
					cb(null, data);
				} catch (e) {
					cb(e);
				}
			});
		}).on("error", cb);
	req.write(data);
	req.end();
}

function getInfo(address, cb) {
	cb = cb || function() {};
	db.query("SELECT device_pub_key, real_name FROM wallet_arbiters WHERE arbiter_address=?", [address], function(rows){
		if (rows.length && rows[0].real_name) { // request again if no real name
			cb(null, rows[0]);
		} else {
			device.requestFromHub("hub/get_arbstore_url", address, function(err, url){
				if (err) {
					return cb(err);
				}
				if (!validationUtils.isNonemptyString(url))
					return cb("invalid url received from hub");
				requestInfoFromArbStore(url+'/api/arbiter/'+address, function(err, info){
					if (err) {
						return cb(err);
					}
					if (!validationUtils.isNonemptyObject(info))
						return cb("invalid arbiter info received from arbstore");
					db.query("REPLACE INTO wallet_arbiters (arbiter_address, device_pub_key, real_name) VALUES (?, ?, ?)", [address, info.device_pub_key, info.real_name], function() {cb(null, info);});
				});
			});
		}
	});
}

function requestInfoFromArbStore(url, cb){

			try {
				cb(null, JSON.parse(data));

				cb(ex);
			}
		});
	}).on("error", cb);
}
