### Title
Unbounded Gas Forwarding in `handleKLAYTransfer` Allows Malicious Recipient to Permanently Lock Bridged KAIA — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

### Summary

`BridgeTransferKLAY.handleKLAYTransfer` delivers KAIA to the recipient using `_to.call.value(_value)("")`, which in Solidity 0.5.x forwards **all available gas** to the callee. A user who specifies a malicious contract as `_to` can cause every bridge-operator handle transaction for that nonce to revert. Because the bridge contract has no mechanism to skip or override a permanently failing nonce, the corresponding KAIA is locked in the source bridge indefinitely and the bridge nonce accounting is corrupted.

### Finding Description

`handleKLAYTransfer` performs all nonce-state mutations (marking the request tx hash, recording the block number, advancing `lowerHandleNonce`) and then makes an unbounded external call:

```solidity
// BridgeTransferKLAY.sol L98-99
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [1](#0-0) 

Because the entire function is one atomic transaction, a revert at the `require` rolls back every state change made earlier in the same call (the `_setHandledRequestTxHash`, `handleNoncesToBlockNums`, `_updateHandleNonce`, and the `HandleValueTransfer` event). The nonce is therefore never recorded as handled.

The off-chain relay loop in `processingPendingRequestEvents` re-queues and retries any event whose handle call fails:

```go
// node/sc/bridge_manager.go L254-258
if err := bi.handleRequestValueTransferEvent(ev); err != nil {
    bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
    logger.Error("Failed handle request value transfer event", ...)
    return
}
``` [2](#0-1) 

There is no on-chain escape hatch to skip a nonce that permanently reverts. `_lowerHandleNonceCheck` only enforces a lower bound; it never advances past a gap:

```solidity
// BridgeTransfer.sol – _updateHandleNonce advances only while handleNoncesToBlockNums[i] > 0
for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) { ... }
lowerHandleNonce = i;
``` [3](#0-2) 

### Impact Explanation

| Asset | Effect |
|---|---|
| User's KAIA on source chain | Permanently locked in source bridge — transfer can never complete |
| Bridge `lowerHandleNonce` | Stuck at the poisoned nonce; after 200 subsequent nonces are handled the sliding window stops advancing, eventually preventing any new nonce from being accepted |
| Bridge operator | Forced to retry a transaction that always reverts, burning gas indefinitely |

The KAIA locked in the source bridge is a bridged asset that becomes unrecoverable: there is no `cancelTransfer` or `reclaimKLAY` function in the bridge contract.

### Likelihood Explanation

Any user who initiates a `requestKLAYTransfer` controls the `_to` field. Deploying a contract whose `fallback` executes `assert(false)` (consuming all forwarded gas) or simply `revert()` costs only a small amount of gas. The attacker sacrifices the KAIA they lock, but the cost is bounded and predictable, while the damage to the bridge operator (repeated failed transactions) and to the bridge nonce state is unbounded.

### Recommendation

1. **Cap the gas forwarded** to `_to` to the 2300-gas stipend sufficient for a simple EOA receive, or to an explicit operator-configurable limit:
   ```solidity
   (bool ok, ) = _to.call.value(_value).gas(2300)("");
   ```
2. **Add a pull-payment pattern**: record the owed amount in a mapping and let `_to` claim it, removing the bridge's dependency on `_to`'s fallback behaviour.
3. **Add an operator-only `skipNonce` function** that marks a nonce as handled without transferring value, allowing recovery from permanently stuck nonces.

### Proof of Concept

```solidity
// Deploy on destination chain
contract PoisonRecipient {
    fallback() external payable {
        // Consume all forwarded gas — handleKLAYTransfer always reverts
        assembly { invalid() }
    }
}
```

1. Attacker deploys `PoisonRecipient` on the destination chain.
2. Attacker calls `requestKLAYTransfer(PoisonRecipient, 1 ether, "")` on the source bridge — KAIA is locked in the source bridge at nonce `N`.
3. Bridge operator calls `handleKLAYTransfer(..., PoisonRecipient, 1 ether, N, ...)` on the destination bridge.
4. `PoisonRecipient.fallback` consumes all gas; `ok == false`; `require` reverts the entire transaction — all nonce state is rolled back.
5. `processingPendingRequestEvents` re-queues nonce `N` and retries indefinitely.
6. `lowerHandleNonce` is stuck at `N`; after 200 further nonces are handled the window `[N, N+200]` is exhausted and `_updateHandleNonce` can no longer advance `lowerHandleNonce`, blocking all future bridge transfers.
7. The 1 KAIA remains permanently locked in the source bridge with no recovery path.
