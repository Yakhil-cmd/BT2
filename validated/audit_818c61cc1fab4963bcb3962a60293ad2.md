The reward-duplication bug class in the reference report requires a per-user staking accumulator pattern — a global `rewardPerTokenStored` checkpoint combined with per-user balance and a per-user `userRewardPerTokenPaid` snapshot, where depositing more tokens *before* claiming lets a user retroactively capture rewards accrued during a period when their balance was smaller.

Raydium CP-swap has no analogous mechanism reachable by an unprivileged swapper, LP, or pool creator:

- Protocol/fund/creator fees are tracked as simple pool-level aggregate counters (`protocol_fees_token_0/1`, `fund_fees_token_0/1`, `creator_fees_token_0/1`) that are incremented on every swap via `PoolState::update_fees` and later withdrawn in full (zeroed out) by the privileged fund/protocol owner or the pool creator — there is no per-account "balance × (accumulator delta)" reward formula and no per-user checkpoint that could be gamed by timing deposits/withdrawals. [1](#0-0) [2](#0-1) 

- LP earnings from swap fees accrue directly into the pool reserves (constant-product curve), so LP token value is instantaneous and proportional to current holdings at withdrawal time — there is no separate accumulator/checkpoint state that a depositor could exploit by depositing right before a fee distribution to claim fees earned before their deposit. [3](#0-2) 

Since the underlying mechanism (accumulator-based reward checkpointing with per-user balance snapshots) simply doesn't exist in this AMM's fee/LP accounting, there is no reachable path for the described "duplicated reward calculation" bug class.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();

                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();

        };
