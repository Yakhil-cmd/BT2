### Title
RAY value overflow during accrual permanently freezes a market before index caps engage - (contracts/pool/src/interest.rs)

### Summary
An integer-overflow analog exists in the accrual path: `global_sync` always runs before market mutations and computes RAY-denominated totals with `scaled * index`; once a market’s scaled totals are near the RAY domain limit, further accrual panics with `MathOverflow` before `MAX_BORROW_INDEX_RAY` can clamp growth. Because `update_indexes`, `withdraw`, `repay`, `borrow`, and liquidation all load/accrue the market first, the overflow bricks that hub-asset market rather than corrupting memory. [1](#0-0) [2](#0-1) 

### Finding Description
The GLib issue is a size-calculation overflow that makes later code believe an allocation is safe. Here, the analogous pattern is fixed-point value growth: supply/debt shares are stored as RAY-scaled values, while interest accrual multiplies them by indexes to recover token-denominated RAY values. `Cache::calculate_utilization` computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`, and `accrue_chunk` applies `accrue_step` to the same cached totals. [3](#0-2) [4](#0-3) 

The market documentation explicitly warns that accrued position values and market totals must fit the RAY domain and that value overflow can occur before the index ceiling, blocking repayment/withdrawal because those operations accrue first. [5](#0-4)  The harness test proves the cliff: at 98% utilization on the XLM curve, `try_update_indexes` eventually returns `MATH_OVERFLOW`, after which `try_withdraw_raw` and `try_repay` also fail with `MATH_OVERFLOW`. [6](#0-5) 

### Impact Explanation
Permanent freezing of funds for the affected market: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot force resolution because every verb re-enters the same accrual overflow. This is not a fail-closed pause; it is an arithmetic dead end reached from normal permissionless entries. Admin remediation is also constrained because `upgrade_liquidity_pool_params` accrues indexes before replacing params. [7](#0-6) 

### Likelihood Explanation
Likelihood is low but nonzero: it requires whale-scale RAY exposure near the documented `i128::MAX / 10^(27-d)` token-to-RAY ceiling and sustained high utilization until value growth crosses the safe domain before index caps. An unprivileged actor can reach it by controlling multiple accounts: supply the target asset to build `supplied`, supply a separate collateral asset and borrow the target to keep utilization high, then permissionlessly call `update_indexes` over time. No privileged parameter, leaked key, oracle manipulation, or upgrade is required once the market admits sufficiently large caps. [8](#0-7) [9](#0-8) 

### Recommendation
Make accrual saturate or degrade gracefully before any `scaled * index` overflow becomes a mandatory revert: clamp index/total-value growth at the documented RAY value ceiling, or split accrual so repay/withdraw/liquidate can proceed using the last committed index when the next projection overflows. At minimum, add an emergency non-accruing path that permits exits and liquidations once `scaled_to_original` would overflow, instead of letting `global_sync` gate every verb.

### Proof of Concept
1. Same unprivileged caller creates account A and supplies `BIG18` (18 decimals) up to the admitted cap via `supply(caller, account_id_A, spoke, [(BIG18, principal)])`.
2. Same caller creates account B, supplies collateral `COL`, then calls `borrow(caller, account_id_B, [(BIG18, debt)], to)` at ~98% utilization of `BIG18`.
3. Advance ledger time and repeatedly call `update_indexes(caller, [BIG18])`; each call reaches `pool_update_indexes` → `global_sync` → `accrue_chunk`. After enough high-utilization accrual, `scaled * index` overflows in RAY space and returns `MathOverflow` before `MAX_BORROW_INDEX_RAY` engages.
4. Subsequent `withdraw`, `repay`, and `liquidate` on `BIG18` re-enter the same accrual and revert, matching the harness assertion that the market is frozen even though the borrow index remains below its cap.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
