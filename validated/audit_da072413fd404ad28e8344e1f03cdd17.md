The CVE describes a desktop client application (Cyberduck/Mountain Duck) improperly installing untrusted TLS certificates into the OS certificate store without restriction — a GUI/client-side certificate-trust issue triggered through user-initiated file-transfer connections. This has no meaningful analog within Polkadot SDK's runtime/consensus attack surface (signed extrinsics, XCM, contracts, bridges, FRAME pallets).

The only certificate-handling logic I found in the codebase is `substrate/client/network/src/webrtc.rs`, which deterministically derives a self-signed WebRTC DTLS certificate from the node's Ed25519 secret key [1](#0-0) , and validates/completes `webrtc-direct` multiaddresses by appending the certificate's `certhash` [2](#0-1) . This certificate is never written to any OS/user certificate store; it is a peer-to-peer transport-layer certificate pinned by content hash (`/certhash/...`) in the multiaddress itself, verified by the connecting peer against that hash rather than any trust store [3](#0-2) . There is no attacker-controlled entry point (extrinsic, XCM message, contract call) that installs or elevates trust of a certificate on a user's machine, and no runtime state, asset, or governance logic is implicated. The `BadCertificate` TLS-alert warning removal noted in `prdoc/1.12.0/pr_4426.prdoc` and `prdoc/1.13.0/pr_4541.prdoc` is a cosmetic logging change, not a certificate-store trust issue [4](#0-3) .

Since the underlying bug class (unrestricted installation of untrusted certificates into a persistent OS trust store, exploitable via user-driven client interaction) has no structural counterpart in Polkadot SDK's runtime, node-network, or FRAME code, there is no demonstrable analog to report.

/// Check the shape of every `webrtc-direct` address, then append `certhash` to the public ones.
pub(crate) fn validate_and_complete_addresses(
	listen_addresses: &[Multiaddr],
	public_addresses: &mut [Multiaddr],
	certhash: Multihash,
) -> Result<(), Error> {
	// Listen addresses are validated but never completed, unlike the public ones below.
	//
	// A listen address names a socket to bind, and `/certhash` is no part of binding one.
	// litep2p appends it itself when it reports the address it actually bound.
	//
	// A public address is the opposite: it is handed to peers to dial, and a `webrtc-direct` dialer
	// verifies the DTLS handshake against that hash, so it has to be there before anything reads
	// `--public-addr`.
	for address in listen_addresses {
		if is_webrtc_address(address) {
			validate_listen_address(address)?;
		}
	}

	for address in public_addresses.iter_mut() {
		if is_webrtc_address(address) {
			complete_public_address(address, certhash)?;
		}
	}

	Ok(())
}
