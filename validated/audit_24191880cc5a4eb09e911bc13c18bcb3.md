### Title
Unfiltered `machine.environment` from a fork's `shipit.yml` reaches `PTY.spawn` for `ruby`/`bundle` dependency steps, enabling RCE on review stacks - ([File: lib/shipit/task_commands.rb])

### Summary
`TaskCommands#env` merges `deploy_spec.machine_env` directly into the process environment used by `Command#start`/`PTY.spawn`, with no allowlist filtering, unlike deploy/task/rollback variables which are passed through `EnvironmentVariables#permit`. For a `ReviewStack`, `deploy_spec` is built from the checked-out PR branch (`DeploySpec::FileSystem.new(@task.working_directory, @stack)`), and that branch is exactly the fork's head ref (`stack_attributes` sets `branch: params.pull_request.head.ref`). A fork author can therefore set `machine.environment.RUBYLIB` (or `RUBYOPT`, etc.) in their branch's `shipit.yml`, which flows unfiltered into the environment for the `bundle install` / `ruby` dependency step run via `Command#unbundled_env` → `PTY.spawn`, causing `require` in that step to load attacker-controlled code.

### Finding Description
The broken binding: it is assumed that `TaskCommands#env`'s final environment passed to `PTY.spawn` is restricted to a known-safe set of keys, i.e. `env_reaching_PTY.spawn == allowlisted_keys`. In reality, `env_reaching_PTY.spawn ⊇ deploy_spec.machine_env` verbatim, and `machine_env` is fully attacker-controlled on review stacks.

Trace:
1. `DeploySpec#machine_env` returns `config('machine','environment') || {}` verbatim [1](#0-0)  — no key/value validation, no allowlist.
2. `TaskCommands#env` merges this directly: `.merge(deploy_spec.machine_env)` right before `.merge(@task.env)` [2](#0-1) . Contrast this with `DeploySpec#filter_deploy_envs`/`#filter_task_envs`/`#filter_rollback_envs`, which explicitly call `EnvironmentVariables.with(env).permit(...)` against a declared variable whitelist [3](#0-2) . `machine_env` has no equivalent filtering — confirmed by the test asserting raw pass-through: `assert_equal({ 'GLOBAL' => '1' }, @spec.machine_env)` [4](#0-3)  and `"#perform merges shipit.yml machine_env in ENVIRONMENT"` [5](#0-4) .
3. `TaskCommands#install_dependencies` builds `Command.new(command_line, env:, chdir: steps_directory)` for each dependency step (e.g. `bundle install ...` produced by `BundlerDiscovery#bundle_install`) [6](#0-5) , using the same unfiltered `env`.
4. `Command#unbundled_env` merges `@env.stringify_keys` directly into the base spawn env with no key restriction: `BASE_ENV.merge('PATH' => ...).merge(@env.stringify_keys)` [7](#0-6) , and `#start` passes that straight to `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` [8](#0-7) .
5. On a `ReviewStack`, `deploy_spec` is instantiated from `@task.working_directory` — the checked-out fork branch — via `DeploySpec::FileSystem.new(@task.working_directory, @stack)` in `TaskCommands#deploy_spec` [9](#0-8) . That branch is set from the attacker-controlled PR head ref at stack creation time: `branch: params.pull_request.head.ref` in `ReviewStackAdapter#stack_attributes` [10](#0-9) , reachable under `allow_with_label` once the attacker labels their own PR (per the `OpenedHandler#provision?` / `LabeledHandler` logic gating provisioning on `provisioning_behavior_allow_with_label?` plus the label) [11](#0-10) .

Why existing guards don't help: `EnvironmentVariables#permit` (used for deploy/task/rollback envs and API-supplied envs, e.g. rejecting `DANGEROUS_VARIABLE`) is never invoked on `machine_env`. There is no repository/stack model validation restricting `machine.environment` keys, and `Command` performs no environment key sanitization beyond string coercion (`@env.transform_values { |v| v&.to_s }`) [12](#0-11) .

Attacker request: open (or already have) a PR from a fork with a `shipit.yml` containing:
```yaml
machine:
  environment:
    RUBYLIB: "/tmp/attacker_payload"
```
and place a malicious library at that path (also delivered within the fork branch, checked out into the working directory) that gets `require`d by the `bundle install`/`ruby` toolchain during `install_dependencies`. Add the repository's provisioning label to their own PR (the rules explicitly allow this as part of the unprivileged attacker capability set for `allow_with_label`).

### Impact Explanation
This results in arbitrary code execution on the Shipit deploy host, in the context of whatever user/permissions the Shipit worker process runs as. Because the dependency step runs during `install_dependencies` before any human review of the deploy output, RCE is achieved automatically once the review stack is provisioned/updated. Blast radius: full compromise of the deploy host, including access to `GITHUB_TOKEN`, other stacks' git checkouts, and any secrets available to the Shipit process — matching the "Critical — RCE on the deploy host via `Command`/`PTY.spawn`" category. Repeatable against any repository that has review stacks enabled with `allow_with_label` (or `allow_all`, which removes even the labeling step).

### Likelihood Explanation
Preconditions: the target repository must have Review Stacks enabled with `provisioning_behavior` set to `allow_with_label` (or `allow_all`), and the review stack's dependency-installation step must be an auto-discovered `ruby`/`bundle` step (i.e. a `Gemfile` present) or any dependency step at all, since `machine_env` applies broadly to all commands, not just ruby ones. Attacker cost is low: fork the repo, add a `shipit.yml` with a `machine.environment` entry, add the drop-in payload file, open a PR, and (if required) self-label it. No secrets or elevated GitHub permissions are needed. This is fully repeatable per PR/push.

### Recommendation
Filter `machine_env` (and any other `shipit.yml`-derived environment injected for review stacks) through an explicit allowlist analogous to `EnvironmentVariables#permit`, or strip/deny known loader-sensitive variable names (`RUBYLIB`, `RUBYOPT`, `BUNDLE_GEMFILE`, `LD_PRELOAD`, `GEM_HOME`, `GEM_PATH`, `PYTHONPATH`, `NODE_OPTIONS`, etc.) before merging into `TaskCommands#env`. Alternatively, for review stacks specifically, do not honor `machine.environment` from the untrusted PR branch's `shipit.yml` at all (require it to come from a repo-owner-controlled source, e.g. the base/default branch), and always launch dependency-installation commands via `Bundler.clean_env`/`unbundled_env` semantics that explicitly exclude ruby/bundler loader variables regardless of `@env` contents.

### Proof of Concept
Minitest plan (unit-level, no live GitHub required):
```ruby
test "machine_env RUBYLIB from a fork's shipit.yml reaches the install_dependencies command env" do
  stack = shipit_stacks(:review_stack) # allow_with_label repo, branch set from fork's PR head ref
  task  = shipit_tasks(:shipit_restart)
  task.stack = stack

  commands = Shipit::TaskCommands.new(task)
  commands.deploy_spec.stubs(:load_config).returns(
    'machine' => { 'environment' => { 'RUBYLIB' => '/tmp/attacker_payload' } },
    'dependencies' => { 'override' => ['bundle install'] }
  )

  install_cmds = commands.install_dependencies
  assert_equal 1, install_cmds.length
  # Binding under test: machine_env value must NOT reach the ruby/bundle dependency step's env
  assert_nil install_cmds.first.env['RUBYLIB'],
    "Expected RUBYLIB to be filtered out of the ruby/bundle dependency step environment, " \
    "but attacker-controlled machine.environment reached the process env unfiltered"
end
```
Expected today: the assertion fails because `install_cmds.first.env['RUBYLIB']` equals `'/tmp/attacker_payload'`, proving the fork-controlled `machine.environment` entry propagates unfiltered into the `Command` passed to `PTY.spawn` for the dependency-installation step.

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end
