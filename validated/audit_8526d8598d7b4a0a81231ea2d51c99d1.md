### Title
Bridge `handleKLAYTransfer` and `handleERC20Transfer` Bypass `isRunning`/`isLockedKLAY` Emergency-Stop Controls, Allowing Operators to Drain Assets from a Stopped Bridge — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `contracts/service_chain/bridge/BridgeTransferERC20.sol`)

---

### Summary

The Kaia service-chain bridge exposes two protective state flags — `isRunning` (stops all transfers) and `isLockedKLAY` / `lockedTokens` (stops specific asset transfers) — that the owner can set in an emergency. However, these flags are only enforced on the **request (inflow) side** of the bridge. The **handle (outflow) side** — `handleKLAYTransfer` and `handleERC20Transfer` — does not check either flag. Operators can therefore drain KLAY and ERC-20 tokens from a bridge the owner believes is fully stopped, defeating the emergency-stop invariant.

---

### Finding Description

`BridgeTransfer.sol` declares `isRunning = true` and `setRunningStatus`/`start` as owner-only controls to halt all value movement. [1](#0-0) 

`BridgeTransferKLAY.sol` adds `isLockedKLAY` and the `unlockedKLAY` modifier for the same purpose. [2](#0-1) 

The **request path** (`_requestKLAYTransfer`) correctly enforces both guards:

```solidity
function _requestKLAYTransfer(...) internal unlockedKLAY nonReentrant {
    require(isRunning, "stopped bridge");
    ...
}
``` [3](#0-2) 

The **handle path** (`handleKLAYTransfer`) enforces **neither**:

```solidity
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
    _lowerHandleNonceCheck(_requestedNonce);
    if (!_voteValueTransfer(_requestedNonce)) { return; }
    ...
    (bool ok, ) = _to.call.value(_value)("");
    require(ok, "handleKLAYTransfer: transfer failed");
}
``` [4](#0-3) 

The same asymmetry exists in `BridgeTransferERC20.sol`: `_requestERC20Transfer` checks `onlyUnlockedToken` and `require(isRunning, ...)`, but `handleERC20Transfer` checks neither. [5](#0-4) [6](#0-5) 

The Go-layer `BridgeInfo.handleRequestValueTransferEvent` calls these handle functions unconditionally, with no pre-check of the bridge's running or lock state. [7](#0-6) 

---

### Impact Explanation

When the bridge owner calls `lockKLAY()` or `start(false)` to halt the bridge in an emergency (e.g., a security incident on the counterpart chain), the KLAY and ERC-20 balances held inside the bridge contract remain fully accessible to operators via `handleKLAYTransfer` / `handleERC20Transfer`. Operators (who reach the configured threshold) can call these functions with arbitrary `_value` and `_to` parameters, transferring the bridge's entire KLAY or token balance to any address. The owner's emergency stop is silently ineffective for the outflow direction.

Corrupted/protected value: the KLAY balance of the bridge contract (`address(this).balance`) and any ERC-20 token balances held by the bridge.

---

### Likelihood Explanation

- The default `operatorThresholds[ValueTransfer]` is **1**, meaning a single operator can execute a handle transfer unilaterally.
- Operators are registered by the owner but are otherwise semi-trusted external accounts; a compromised or malicious operator key is a realistic threat model for a bridge.
- The owner's expectation that `lockKLAY()` or `start(false)` stops all asset movement is reasonable and documented by the existence of the `isRunning`/`isLockedKLAY` flags and the `"stopped bridge"` / `"locked"` revert strings on the request side.
- No existing guard in the handle functions prevents exploitation after the owner has set the stop flags. [8](#0-7) 

---

### Recommendation

Add the same protective checks to the handle functions that already exist on the request functions:

**`handleKLAYTransfer`** — add `unlockedKLAY` modifier and `require(isRunning, "stopped bridge")`:

```solidity
function handleKLAYTransfer(...) public onlyOperators nonReentrant unlockedKLAY {
    require(isRunning, "stopped bridge");
    ...
}
```

**`handleERC20Transfer`** — add `onlyUnlockedToken(_tokenAddress)` and `require(isRunning, "stopped bridge")`:

```solidity
function handleERC20Transfer(...) public onlyOperators onlyUnlockedToken(_tokenAddress) {
    require(isRunning, "stopped bridge");
    ...
}
```

This ensures the owner's emergency-stop controls are symmetrically enforced on both the inflow and outflow paths.

---

### Proof of Concept

1. Deploy `Bridge` (which inherits `BridgeTransferKLAY`). Fund it with 1000 KLAY via `chargeWithoutEvent`.
2. Owner calls `lockKLAY()` — `isLockedKLAY` is now `true`.
3. Verify: `bridge.fallback({value: 1 ether})` reverts with `"locked"` ✓ (request side blocked).
4. Operator calls `handleKLAYTransfer(txHash, from, attacker, 1000 ether, nonce, blockNum, "0x")`.
5. With threshold = 1 (default), the call succeeds and transfers 1000 KLAY to `attacker`.
6. `isLockedKLAY` is still `true`; the bridge is "locked" yet fully drained.

The same steps apply with `start(false)` and `handleERC20Transfer` for ERC-20 tokens. [9](#0-8) [10](#0-9)

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
