### Title
Unvalidated P2P StakingInfo Delivery Allows Malicious Peer to Corrupt Reward-Distribution State — (`File: datasync/downloader/queue.go`)

### Summary

During fast-sync, a malicious peer can serve arbitrary `P2PStakingInfo` payloads that are accepted and written to the node's persistent staking database without any content validation. The corrupted staking records are subsequently used by the reward module to distribute KAIA block rewards, allowing an attacker to redirect or inflate validator rewards.

### Finding Description

The external bug's invariant class is: **unprotected state that is critical to financial calculations can be freely manipulated by an unprivileged actor**. The Kaia analog is the staking-info sync path.

**Root cause — missing validation in `queue.DeliverStakingInfos`:** [1](#0-0) 

```go

Compare this to `DeliverBodies`, which verifies `DeriveTransactionsRoot(...) == header.TxHash`, and `DeliverReceipts`, which verifies `DeriveReceiptsRoot(...) == header.ReceiptHash`: [2](#0-1) [3](#0-2) 

No equivalent cryptographic binding exists for staking info. The `P2PStakingInfo` struct carries `NodeIds`, `StakingContracts`, `RewardAddrs`, `StakingAmounts`, `KEFAddr`, and `KIFAddr` — every field that drives reward distribution — yet none of them are checked against the block header or any on-chain commitment.

**Write path — corrupted data reaches persistent storage:**

During fast-sync, `commitFastSyncData` unconditionally persists whatever the peer sent: [4](#0-3) 

```go

    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
```

`PutStakingInfoToDB` calls `WriteStakingInfo`, which writes directly to the key-value database: [5](#0-4) 

**Read path — corrupted DB entry is used for reward distribution:**

`GetStakingInfo` prefers the database over re-reading from state for pre-Kaia blocks: [6](#0-5) 

```go

    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)

```

This staking info is then consumed by `assignStakingRewards` / `assignStakingRewardsFlex` to compute per-validator KAIA allocations: [7](#0-6) 

And by `FinalizeState` to call `state.AddBalance` for each recipient: [8](#0-7) 

**P2P entry point — reachable by any connected peer:**

`handleStakingInfoMsg` accepts the message from any peer that speaks `kaia/65+` and forwards it directly to `DeliverStakingInfos` with no additional checks: [9](#0-8) 

The `SyncStakingInfo` recovery path has an additional `BlockNum` sequence check but still performs no content validation before calling `PutStakingInfoToDB`: [10](#0-9) 

### Impact Explanation

A malicious peer can inject `P2PStakingInfo` records with:
- **Inflated `StakingAmounts`** for its own validator address → receives a disproportionately large share of KAIA staking rewards.
- **Substituted `RewardAddrs`** → redirects another validator's reward stream to an attacker-controlled address.
- **Substituted `KEFAddr` / `KIFAddr`** → redirects treasury fund allocations.

The corrupted value is the exact `StakingAmounts[]` and `RewardAddrs[]` arrays that `assignStakingRewards` uses to compute `reward = excess * stakersReward / totalExcess` and call `state.AddBalance`. This constitutes an **unauthorized reward distribution** affecting KAIA.

### Likelihood Explanation

- **Attacker precondition:** establish a P2P connection to a victim node that is performing fast-sync (standard node bootstrap). No privileged keys required.
- **Trigger:** serve a `StakingInfoMsg` (message code `StakingInfoMsg`, protocol `kaia/65+`) with crafted `P2PStakingInfo` payloads during the sync window.
- **Scope:** affects pre-Kaia-hardfork staking intervals on any chain (private chains, testnets, or mainnet nodes syncing historical pre-Kaia blocks). The `TODO-Kaia-Snapsync update validation logic` comment confirms the gap is known and unresolved.

### Recommendation

1. **Bind staking info to the block header** by committing a hash of the canonical staking info into the block header (or a Merkle root), and verify the delivered data against that commitment in `queue.DeliverStakingInfos`, analogous to how `DeliverBodies` checks `header.TxHash` and `DeliverReceipts` checks `header.ReceiptHash`.
2. **Alternatively**, re-derive staking info from the authenticated state trie at `sourceNum` instead of trusting the peer-supplied payload, and use the P2P data only as a cache hint that is always re-verified before persistence.
3. Remove the `// TODO-Kaia-Snapsync update validation logic` placeholder and replace it with a real validation function.

### Proof of Concept

```
1. Victim node starts fast-sync (e.g., fresh node joining the network).
2. Attacker connects as a peer (standard P2P handshake, kaia/65).
3. When victim requests staking info for block hash H (interval block),
   attacker responds with a StakingInfoMsg containing a P2PStakingInfo where:
     BlockNum      = <legitimate interval block number>
     StakingAmounts = [<inflated value for attacker's validator>]
     RewardAddrs    = [<attacker-controlled address>]
4. queue.DeliverStakingInfos validate() returns nil unconditionally.
5. commitFastSyncData calls PutStakingInfoToDB, writing the fake record.
6. On subsequent block processing, GetStakingInfo reads the DB record
   (cache miss → DB hit → returns attacker data).
7. assignStakingRewards computes reward proportional to the inflated
   StakingAmount and calls state.AddBalance(attackerRewardAddr, inflatedReward).
8. FinalizeState commits the state, permanently crediting the attacker.
``` [11](#0-10) [12](#0-11) [13](#0-12) [14](#0-13)

func (s *StakingModule) GetStakingInfo(num uint64) (*staking.StakingInfo, error) {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(new(big.Int).SetUint64(num))
	sourceNum := sourceBlockNum(num, isKaia, s.stakingInterval)

	// Try cache first
	if si, ok := s.stakingInfoCache.Get(sourceNum); ok {
		return si.(*staking.StakingInfo), nil
	}

	// Only before Kaia, try the database
	if !isKaia {
		if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
			s.stakingInfoCache.Add(sourceNum, si)
			return si, nil
		}
	}

	// Read from the state
	si, err := s.getFromStateByNumber(sourceNum)
	if err != nil {
		return nil, err
	}

	// Only before Kaia, write to database
	if !isKaia {
		WriteStakingInfo(s.ChainKv, sourceNum, si)
	}

	// Cache it
	s.stakingInfoCache.Add(sourceNum, si)
	return si, nil
}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
}
