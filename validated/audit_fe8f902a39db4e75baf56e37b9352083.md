## Title
Webhook signature verification uses an attacker-controlled organization field that is decoupled from the repository actually acted upon, allowing forged GitHub events for any tracked stack - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to use for HMAC verification based on `repository_owner`, a value read directly out of the *unauthenticated* JSON body (`params.dig('repository', 'owner', 'login')`), before the signature has been checked. [1](#0-0) [2](#0-1) 

Downstream, the actual event handlers resolve the repository/stack to act on using a *different* field of the same body, `repository.full_name`, with no cross-check that it belongs to the organization that was used to select/verify the signature. [3](#0-2) 

### Finding Description
In multi-organization Shipit setups, `Shipit.github(organization:)` looks up a per-organization config (`app_id`, `installation_id`, `webhook_secret`, …) keyed by an organization name. [4](#0-3) 

`GitHubApp#verify_webhook_signature` explicitly treats a missing/blank `webhook_secret` as automatic success:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [5](#0-4) 

The `webhook_secret` is explicitly documented as optional, and the shipped example configs leave it blank/nil for one or more organizations: [6](#0-5) [7](#0-6) 

The organization used to pick this (possibly secret-less) `GitHubApp` is taken from the *unverified* request body itself:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
end
...
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [8](#0-7) 

Once `verify_signature` passes (trivially, for the secret-less org), `create` parses the whole raw body and dispatches it to handlers keyed only by the `X-Github-Event` header: [9](#0-8) 

Handlers such as `PushHandler` resolve the target `Repository`/`Stack` from a *different* JSON field, `repository.full_name`, never revalidating it against `repository.owner.login` (the field that determined which secret gated the request): [10](#0-9) [3](#0-2) 

This breaks the intended binding: **organization authenticated (`repository.owner.login`, used to pick/validate the HMAC key) must equal the repository actually written (`repository.full_name`, used by the handler)**. Because both fields live in the same unauthenticated JSON body and only the org-selection field feeds into the (bypassable) HMAC check, an attacker can set `repository.owner.login` to any organization configured without a `webhook_secret` (bypassing verification entirely per line 77 of `github_app.rb`), while setting `repository.full_name` to the full name of a *different*, fully protected, tracked repository/stack. The handler will act on the spoofed `full_name` regardless of which org "authenticated" the request.

### Impact Explanation
An unauthenticated attacker who knows (or can guess/enumerate) that any one configured GitHub organization in a multi-org Shipit deployment has no `webhook_secret` set can forge a `push` webhook naming an arbitrary tracked repository owned by a *different*, secured organization. This enqueues `GithubSyncJob` for that stack, which pulls real commits from GitHub using the stack's legitimate credentials and can advance the stack's HEAD, unlock reverted commits, and — if continuous deployment is enabled for that stack — trigger an automatic, unauthorized deploy. This matches the "unauthorized deploy" impact class and, depending on CD configuration, can also be leveraged against `membership`/`check_suite` handlers similarly gated by the same decoupled binding.

### Likelihood Explanation
Requires: (1) a multi-organization Shipit configuration (explicitly documented and shipped as an example, `docs/setup.md`), and (2) at least one configured organization left without a `webhook_secret` (also explicitly documented as "optional"). Given the docs steer operators toward leaving it blank as acceptable, and no credentials, session, or prior access is required, likelihood is non-trivial for real deployments using multiple GitHub orgs.

### Recommendation
- Require `webhook_secret` to be present for every configured organization in multi-org mode; refuse to boot or reject webhooks otherwise instead of returning `true` from `verify_webhook_signature` when `webhook_secret` is blank.
- After selecting the organization for signature verification, re-derive/validate that `repository.full_name`'s owner segment matches the `repository_owner` used to select the verifying `GitHubApp`, rejecting mismatches with `422`.
- Consider verifying the signature against every configured organization's secret (or against the specific org's app the target repository is actually registered under, looked up from Shipit's own `Repository` table) rather than trusting an org name taken from the unauthenticated payload.

### Proof of Concept
1. Configure Shipit with two GitHub orgs: `OrgA` (no `webhook_secret` set) and `OrgB` (secret configured, hosting tracked repo `OrgB/critical-app` with continuous deployment enabled).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-or-real-sha>",
  "repository": {
    "full_name": "OrgB/critical-app",
    "owner": { "login": "OrgA" }
  }
}
```
No `X-Hub-Signature` header (or any garbage value) is required.
3. `verify_signature` calls `Shipit.github(organization: "OrgA")`, whose `webhook_secret` is nil, so `verify_webhook_signature` returns `true` unconditionally. [5](#0-4) 
4. `PushHandler` resolves the stack via `repository.full_name` = `"OrgB/critical-app"`, and enqueues `GithubSyncJob` for that stack, unrelated to `OrgA`. [11](#0-10)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
