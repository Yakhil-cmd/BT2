### Title
Cross-tenant repository/stack mutation via decoupled webhook signature verification and repository lookup - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/repository.rb)

### Finding Description
The broken binding is: `verifying_org(repository_owner)` (the org whose `GitHubApp#verify_webhook_signature` accepted the HMAC) is claimed to equal `owning_org(repository.full_name.split('/').first)` (the org that actually owns the `Repository` row loaded and mutated by the handler). This equality is never enforced.

`WebhooksController#verify_signature` selects the verifying `GitHubApp` using only the payload-supplied `repository.owner.login` (or `organization.login`) field: [1](#0-0) [2](#0-1) . `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever that org's `webhook_secret` is blank/unconfigured: [3](#0-2) .

Separately, every pull_request handler (e.g. `UnlabeledHandler#repository`) resolves the `Repository` used for stack mutation purely from the independent `params.repository.full_name` field, via `Shipit::Repository.from_github_repo_name`, which only queries `owner`/`name` derived from that string with zero reference to which org's secret verified the request: [4](#0-3) [5](#0-4) .

Because `repository.owner.login` and `repository.full_name` are two independent, attacker-controlled fields inside the same JSON body, and the controller never cross-checks them, an attacker who controls (or targets) an org configured in Shipit with no `webhook_secret` set can craft a POST to `/webhooks` where:
- `repository.owner.login` = `unsecured-org` (satisfies `verify_signature`, since that org's `verify_webhook_signature` returns `true` for any signature/body once `webhook_secret` is blank),
- `repository.full_name` = `victim/repo` (any known, unrelated tenant's repository),
- and valid `pull_request`/`labels`/`action=unlabeled` fields.

`drop_unhandled_event` and the `ExplicitParameters` schema only validate structural shape, not cross-field consistency, and do nothing to bind `repository_owner` to `repository.full_name`. Once past `verify_signature`, `UnlabeledHandler#repository` loads the real, persisted `victim/repo` `Repository` and its `review_stacks`, and `handle` calls `stack.archive!`/`stack.unarchive!` on the victim's `ReviewStack` — a real cross-tenant mutation triggered entirely by an attacker-controlled webhook body authenticated only against the attacker's own org's (unsecured) signature.

### Impact Explanation
An attacker who can get any org into an "unsecured" state within a multi-tenant Shipit install (no `webhook_secret` configured for that org — a documented/possible but insecure configuration) can forge webhook deliveries that pass signature verification for their own org, yet name and mutate any other tenant's `Repository`/`ReviewStack`/`Stack` by `full_name`. This yields unauthorized `archive!`/`unarchive!` of another org's review stacks (and via the sibling handlers — `opened_handler.rb`, `closed_handler.rb`, `labeled_handler.rb`, `reopened_handler.rb` — provisioning/deprovisioning of review stacks) for repositories the attacker does not own. This matches "a payload for one repository mutating another's stack" — Critical severity, and is repeatable against any known `owner/repo` string.

### Likelihood Explanation
The attack requires: (1) the attacker to be able to name the org used for `repository_owner` in the forged payload such that its `GitHubApp#verify_webhook_signature` degenerates to `true` — this occurs only when that org's `webhook_secret` is unset in Shipit's config, an operator misconfiguration, not the attacker's fault or credential. If every configured org has a `webhook_secret` set, `verify_webhook_signature` performs a real `secure_compare` and the attacker cannot forge a valid signature without the secret, blocking this path entirely. Thus exploitability is entirely conditional on the "unsecured org" precondition explicitly named in the question, not a universal bypass — but the underlying code defect (no cross-check between the verified org and the mutated repository's owner) is present regardless and is the root cause once that precondition is met.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler#initialize`/`stacks`/`repository`), after verifying the signature, assert that `repository_owner` from the payload matches the owner segment of `params.dig('repository', 'full_name')` before dispatching to handlers; reject the request (422) on mismatch. Additionally, `Repository.from_github_repo_name` (or its callers) should not be trusted to gate cross-tenant access — the controller should be the single point that binds "verified org" to "repository being acted upon."

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "signature verified for unsecured org does not authorize mutating another org's repository" do
  victim_repo = shipit_repositories(:shipit) # owner: 'shopify' (or similar), name: 'shipit-engine'
  # Configure an org "unsecured-org" in Shipit.github_config with no webhook_secret

  payload = {
    action: "unlabeled",
    number: 1,
    pull_request: { id: 1, number: 1, url: "u", title: "t", state: "open",
                     additions: 0, deletions: 0,
                     head: { sha: "sha", ref: "ref" },
                     user: { login: "attacker" },
                     assignees: [], labels: [] },
    repository: { full_name: "#{victim_repo.owner}/#{victim_repo.name}",
                   owner: { login: "unsecured-org" } },
    sender: { login: "attacker" }
  }.to_json

  post shipit.webhooks_path,
    params: payload,
    headers: { 'X-Github-Event' => 'pull_request',
               'X-Hub-Signature' => 'sha1=anything', # accepted since unsecured-org has no webhook_secret
               'Content-Type' => 'application/json' }

  assert_response :ok
  # Assert the victim repo's review stack was actually archived/unarchived, proving
  # a payload verified under "unsecured-org" mutated "victim"'s repository.
end
```
Combined with the direct unit check requested: `Shipit::Repository.from_github_repo_name(victim_repo.full_name)` returns the live persisted `victim_repo` record with no argument or check tying it to `repository_owner`/`unsecured-org`, confirming the binding is absent at the model layer as well: [5](#0-4) .

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
