### Title
Stale delegate grants reactivate when a lending NFT returns to its previous owner - (File: contracts/controller/src/storage/account.rs)

### Summary
The controller invalidates a delegate grant while a different address owns the position NFT, but leaves the grant stored and keyed only by `granted_by`. If the NFT later returns to that owner without overwriting or deleting the grant, the former delegate automatically regains authority to call owner-gated account operations such as `borrow`, `withdraw`, `multiply`, and `swap_collateral`. This is analogous to reusing a stale authenticated channel after its authorization context changed. [1](#0-0) 

### Finding Description
`DelegateGrant` persists under `ControllerKey::Delegates(account_id)` and stores only the granting owner's address plus the delegate list. [2](#0-1) 

`get_delegates` filters that stored grant by equality with the *current* NFT owner rather than deleting it or tying it to an ownership epoch. [1](#0-0) 

Consequently, a grant is inactive after `position-nft::transfer` moves the account to Bob, but becomes valid again if Bob transfers the NFT back to Alice. [1](#0-0) 

`is_owner_or_delegate` then accepts that caller whenever it is an active position manager and appears in the revived list. [3](#0-2) 

`borrow` explicitly allows the resulting authorized caller to choose an arbitrary `to` recipient, defaulting to the delegate itself when `to` is absent. [4](#0-3) 

Withdrawals likewise accept a separate `recipient` and send the measured pool payout to that address. [5](#0-4) 

### Impact Explanation
A previously approved manager can extract the account's withdrawable collateral or borrow up to the account's post-operation solvency limit and direct the proceeds to itself after the NFT returns to the original owner. [6](#0-5) 

This produces theft of user funds or economically equivalent extraction of pool liquidity against debt attached to the victim's account. [7](#0-6) 

The stale delegate can also use other owner-or-delegate strategy paths because `require_owner_or_delegate` is the shared authority check. [8](#0-7) 

### Likelihood Explanation
The exploit requires three conditions: the owner previously granted an active position manager, the NFT is transferred to another holder, and it is later transferred back without the intermediate holder calling `add_delegate` or `remove_delegate`. [9](#0-8) 

Both NFT transfers are ordinary holder-authorized operations, and no governance action or contract upgrade is required once the manager remains active. [10](#0-9) 

The likelihood is constrained because the attacker cannot unilaterally force the NFT to return, but wallet, custody, escrow, marketplace, or operational transfer flows can create that sequence. [1](#0-0) 

### Recommendation
Bind each delegate grant to an ownership epoch or NFT ownership generation, or delete `ControllerKey::Delegates(account_id)` whenever the controller observes that the NFT owner changed. [1](#0-0) 

A practical alternative is to store the current owner alongside an owner-controlled nonce and have `get_delegates` require both the grant's `granted_by` and nonce to match the live account state. [11](#0-10) 

The controller should also provide and exercise a hook or explicit cleanup path on every owner transition so returning an NFT cannot resurrect a dormant delegate. [12](#0-11) 

### Proof of Concept
1. Alice owns lending account `account_id`, supplies collateral through `controller::supply`, and grants an active manager `manager` with `controller::add_delegate(caller=alice, account_id=account_id, delegate=manager)`. [13](#0-12) 
2. Alice calls `position-nft::transfer(from=alice, to=bob, token_id=account_id)`. The stored grant remains, but `get_delegates(account_id, bob)` returns empty because `grant.granted_by != bob`. [1](#0-0) 
3. Bob calls `position-nft::transfer(from=bob, to=alice, token_id=account_id)` without performing a delegate update. [10](#0-9) 
4. `get_delegates(account_id, alice)` returns the stored `manager`, so `is_owner_or_delegate` accepts `manager` again. [3](#0-2) 
5. `manager` calls `controller::withdraw(caller=manager, account_id=account_id, withdrawals=[(hub_asset, 0)], to=Some(manager))` to remove all withdrawable collateral to itself. [14](#0-13) 
6. Alternatively, `manager` calls `controller::borrow(caller=manager, account_id=account_id, borrows=[(debt_hub_asset, amount)], to=Some(manager))`; the pool pays `manager`, while `account_id` retains the debt subject to the final solvency check. [15](#0-14)

/// Adds a delegate, enforcing `MAX_DELEGATES`; returns false for duplicates.
/// Overwrites stale grants with a list stamped by the current owner.
pub(crate) fn add_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let mut delegates = get_delegates(env, account_id, owner);
    if delegates.contains(delegate) {
        return false;
    }
    assert_with_error!(
        env,
        delegates.len() < MAX_DELEGATES,
        GenericError::RegistryCapReached
    );
    delegates.push_back(delegate.clone());
    set_delegates(env, account_id, owner, &delegates);
    true
}

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}

            LegDirection::Entry {
                asset_decimals: result.asset_decimals,

            &LegOutcome::from(&result),
            cache,
        );

/// Withdraws in normal or liquidation mode and merges the pool mutations.
pub(crate) fn apply_withdraw_batch(
    env: &Env,
    account: &mut Account,
    recipient: &Address,
    kind: WithdrawKind,
    action: events::PositionAction,
    entries: &Vec<PoolWithdrawEntry>,
    cache: &mut Context,
) -> Vec<PoolPositionMutation> {
    let is_liquidation = kind == WithdrawKind::Liquidation;
    let pool_addr = cache.cached_pool_address();
    let results = pool_withdraw_call(env, &pool_addr, recipient, is_liquidation, entries);
    for_each_leg(env, entries, &results, |entry, result| {
        let hub_asset = entry.action.hub_asset;
        let outcome = LegOutcome::from(&result);
        merge_withdraw_leg(env, account, action, &hub_asset, kind, &outcome, cache);
    });
