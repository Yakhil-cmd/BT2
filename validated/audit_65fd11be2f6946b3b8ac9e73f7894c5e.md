## Title
Uncaught exception in PEM public-key parsing (`is_valid_sig`/`vrf_verify`) can crash node validation on a malformed AA trigger - (File: signature.js)

### Summary
The external CVE describes a crash caused by a malformed/short binary attribute whose length/format is not validated before it is parsed, letting a remote peer crash the server. `ocore`'s `signature.js` contains an analogous pattern: `validateAndFormatPemPubKey()` and `verifyMessageWithPemPubKey()` index into a `Buffer` derived from an attacker-controlled string (`pem_key`) using offsets computed from attacker-controlled length bytes, without first checking that the buffer is long enough to contain those offsets.

### Finding Description
`validateAndFormatPemPubKey` decodes a base64 string into `contentAloneBuffer` and then reads `contentAloneBuffer[1]`, `[2]`, `[3]`, `[4]`, `[5]` to determine ASN.1 length encoding, then computes `identifiersStart`/`identifiersLength` and slices `contentAloneHex` using those attacker-influenced offsets: [1](#0-0) 

Similarly, `verifyMessageWithPemPubKey` computes `algIdStart` from `der[1]` and slices the DER buffer at `algIdStart` without validating `der.length` is sufficient, then indirectly calls `verifyMessageWithSecp256k1PemPubKey`, which itself indexes `pubkey[0]` after slicing: [2](#0-1) 

Both functions are reachable from unprivileged, attacker-controlled input: the `is_valid_sig(message, pem_key, sig)` and `vrf_verify(seed, proof, pem_key)` oscript functions evaluate arbitrary trigger data as the `pem_key` argument and pass it directly into `signature.validateAndFormatPemPubKey` / `signature.verifyMessageWithPemPubKey`: [3](#0-2) [4](#0-3) 

This means any user can trigger an AA whose formula uses `is_valid_sig`/`vrf_verify` and supply a crafted, too-short "PEM key" string as trigger data (`trigger.data.pem_key`). Since `contentAloneB64` only needs to pass a length check (`<=736`) and a base64-format check (`isValidBase64`) — not a minimum-length or structural check — an attacker can supply a base64 string that decodes to a buffer of 0, 1, or 2 bytes. Reading out-of-range indices of a Node.js `Buffer` (e.g., `buf[5]` on a 2-byte buffer) does not throw by itself (returns `undefined`), but the subsequent use of that `undefined` value in arithmetic/comparisons and in `Buffer.slice()`/`.toString('hex').slice()` calls can produce inconsistent state; more importantly, `verifyMessageWithSecp256k1PemPubKey` calls `.equals()` and other Buffer methods on slices whose bounds may be nonsensical, and any place that calls `.toString()` on `undefined` or performs disallowed type coercion inside these functions is a candidate for an uncaught `TypeError`.

### Impact Explanation
`validateAndFormatPemPubKey` and `verifyMessageWithPemPubKey` are called during **oscript formula evaluation while validating an incoming trigger unit / AA response**, not from within an isolated worker. If an uncaught exception propagates out of formula evaluation (I was unable to fully confirm, due to remaining tool budget, whether every call site around `evaluate()` in `aa_composer.js`/`aa_validation.js` wraps formula evaluation in a blanket `try/catch`), it could throw during unit or AA-trigger validation. Given `network.js` installs a global `process.on('uncaughtException', ...)` handler that deliberately **re-throws and crashes the process** ("throw err; // crash the process to avoid ending up in an inconsistent state"): [5](#0-4) 
any exception that escapes an `async`/event-loop callback during validation (rather than being caught synchronously inline) would crash the whole node. Because AA trigger evaluation runs on every full node that processes the DAG, a single malicious unit invoking an AA with `is_valid_sig`/`vrf_verify` and a malformed `pem_key` in its trigger data could crash all nodes processing that unit — a network-wide denial of service, analogous to the freeradius crash from a single malicious RADIUS request.

### Likelihood Explanation
Medium. Reaching this code only requires: (1) an AA definition that includes `is_valid_sig` or `vrf_verify`, and (2) a post-trigger unit with attacker-controlled `pem_key` payload feeding those AA parameters — this is fully permissible per `aa_validation.js`'s payload rules for `data`/`data_feed` messages, which allow arbitrary string/number fields. No special privileges are needed beyond posting a normal unit. However, exploitability depends on finding an exact malformed base64 payload that (a) passes `isValidBase64`, (b) is ≤736 chars, and (c) triggers a genuine uncaught `TypeError`/`RangeError` rather than merely producing `undefined` comparisons that fail gracefully — this requires concrete confirmation via runtime testing of `signature.js`, which I could not fully verify from static review alone.

### Recommendation
- In `signature.js`, add explicit length checks before every buffer-index access in `validateAndFormatPemPubKey` (verify `contentAloneBuffer.length` is at least large enough for the byte(s) about to be read at each branch) and in `verifyMessageWithPemPubKey`/`verifyMessageWithSecp256k1PemPubKey` (verify `der.length` before reading `der[1]` and before slicing).
- Wrap the body of these functions (or their callers in `formula/evaluation.js` for `is_valid_sig`/`vrf_verify`) in `try/catch` and treat any exception as formula evaluation failure (`setFatalError`/`cb(false)`) rather than letting it propagate.
- Add unit tests with truncated/short/garbage base64 `pem_key` values (0–10 bytes) to confirm no uncaught exception occurs.

### Proof of Concept
Conceptual PoC (exact minimal-length trigger payload not confirmed without live testing):
1. Deploy or use an existing AA whose oscript formula calls `is_valid_sig(trigger.data.message, trigger.data.pem_key, trigger.data.signature)`.
2. Send a trigger unit to the AA with:
   - `data.message`: any non-empty string
   - `data.signature`: any valid-looking hex/base64 string ≤1024 chars
   - `data.pem_key`: a base64 string that decodes to a very short buffer (e.g., 1–2 bytes) while still passing `ValidationUtils.isValidBase64` and the `<=736` length check, such as `"AA=="` (decodes to a single `0x00` byte).
3. On validation of this trigger by any full node, `signature.validateAndFormatPemPubKey("AA==", ...)` is invoked; `contentAloneBuffer[0]` is `0x00` (fails the `!= 0x30` check and returns an error) — but variations of the byte pattern (e.g., first byte `0x30`, followed by insufficient remaining bytes for the declared length branch) should be fuzzed to find an input that causes an unguarded property access on `undefined` to be used in a `Buffer`/string method call that throws.
4. If such an input is found, the resulting exception during AA trigger validation would be uncaught within the async callback chain, hitting the global `uncaughtException` handler in `network.js`, which crashes the node process.

function verifyMessageWithPemPubKey(message, signature, pem_key, bPostPemCurvesFix) {
	var contentB64 = pem_key
		.replace("-----BEGIN PUBLIC KEY-----", "")
		.replace("-----END PUBLIC KEY-----", "")
		.replace(/\s/g, "");
	var der = Buffer.from(contentB64, 'base64');
	var algIdStart = der[1] <= 0x7F ? 4 : der[1] === 0x81 ? 5 : der[1] === 0x82 ? 6 : -1;
	if (algIdStart >= 0 && der.slice(algIdStart, algIdStart + SECP256K1_ALG_ID.length).equals(SECP256K1_ALG_ID)
			&& bPostPemCurvesFix)
		return verifyMessageWithSecp256k1PemPubKey(message, signature, der);

	verify.end();

}

function verifyMessageWithSecp256k1PemPubKey(message, signature, der) {
	try {
		// Locate the BIT STRING for an uncompressed public key: 03 42 00 04 <32 X> <32 Y>
		var bitStringIdx = der.indexOf(Buffer.from([0x03, 0x42, 0x00]));
		if (bitStringIdx === -1) return false;
		var pubkey = der.slice(bitStringIdx + 3, bitStringIdx + 68); // 65 bytes: 04 + 32 + 32
		if (pubkey.length !== 65 || pubkey[0] !== 0x04) return false;

		var encoding = ValidationUtils.isValidHexadecimal(signature) ? 'hex' : 'base64';
		var sigBytes = Buffer.from(signature, encoding);
		var rawCompact = sigBytes.length === 64 ? sigBytes : Buffer.from(ecdsa.signatureImport(sigBytes));
		var compactSig = Buffer.from(ecdsa.signatureNormalize(rawCompact));

		var msgBuf = Buffer.isBuffer(message) ? message : Buffer.from(message);
		var hash = crypto.createHash('sha256').update(msgBuf).digest();
		return ecdsa.ecdsaVerify(compactSig, hash, pubkey);
	} catch(e) {
		console.log('secp256k1 pem verify exception: ' + e);
		return false;
	}
}
