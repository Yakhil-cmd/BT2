The GeoTools advisory concerns a PostGIS/JDBC SQL-injection in a GIS filter function (`jsonArrayContains`) that concatenates unescaped input into generated SQL. Polkadot SDK has no PostGIS/JDBC dependency, and the codebase's only SQL usage is in the eth-rpc indexer (`substrate/frame/revive/rpc`), which is an off-chain, non-consensus component that persists Ethereum-compatible receipts/logs in a local SQLite database — not reachable via any signed extrinsic, XCM message, or proof submission.

All SQL statements there use compile-time-checked `sqlx::query!` macros or `QueryBuilder` with `push_bind`, which parameterize every user-influenced value (block hashes, addresses, topics, block numbers) rather than string-concatenating them into the query text. There is no runtime pallet, filter DSL, or query-construction analog matching the "unescaped value written into generated SQL" root cause, and no reachable attacker entry point (signed extrinsic, XCM, or proof submission) into this off-chain indexer's query paths.
