### Title
Ghost Votes Persist After Operator Deregistration, Enabling Unauthorized Bridge Asset Transfers — (File: `contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`deregisterOperator()` removes an operator from the active set but does not clear that operator's existing votes from the `votes` storage mapping. A deregistered operator's vote count remains live and can combine with a subsequent honest operator's vote to reach the threshold, causing unauthorized KLAY or ERC20 transfers to execute from the bridge.

---

### Finding Description

In `BridgeOperator.sol`, `deregisterOperator` removes the operator from `operators[_operator]` and `operatorList`, but leaves the operator's recorded votes untouched in `votes[voteType][nonce].voted[operator]` and `votes[voteType][nonce].voteCounts[voteKey]`. [1](#0-0) 

The contract itself acknowledges this in a comment: [2](#0-1) 

The `_voteCommon` function, called by `_voteValueTransfer` and `_voteConfiguration`, only checks `operators[msg.sender]` at the **entry point** via the `onlyOperators` modifier. Once a vote is recorded in storage, it is never invalidated by deregistration: [3](#0-2) 

The threshold check at line 96 compares `voteCounts[voteKey]` against `operatorThresholds`, and the deregistered operator's count contribution is never subtracted: [4](#0-3) 

`handleKLAYTransfer` and `handleERC20Transfer` both call `_voteValueTransfer`, which triggers the transfer when the threshold is met: [5](#0-4) [6](#0-5) 

---

### Impact Explanation

A compromised operator votes on a fraudulent value-transfer nonce (e.g., directing KLAY to an attacker address). The bridge owner deregisters the operator, believing the threat is neutralized. However, the ghost vote persists in `votes` storage. When any remaining honest operator subsequently votes on the same nonce — believing it to be a legitimate cross-chain request — the threshold is reached and the fraudulent KLAY or ERC20 transfer executes, draining bridge funds to the attacker.

The corrupted protected value is the bridge contract's KLAY/ERC20 balance: an unauthorized `_to.call.value(_value)("")` or `IERC20.safeTransfer` is executed.

---

### Likelihood Explanation

Medium. The scenario requires a compromised operator to vote before deregistration and a second honest operator to vote on the same nonce afterward. In a live multi-operator bridge with asynchronous off-chain relayers, this ordering is realistic: the honest relayer may process the same cross-chain event independently without knowing the first vote came from a now-deregistered operator.

---

### Recommendation

In `deregisterOperator`, iterate over all open vote nonces and subtract the deregistered operator's vote contribution, or delete their `voted` entry and decrement `voteCounts`. Alternatively, add a `revokeVote(voteType, nonce)` function callable by the owner that clears a specific operator's vote for a given nonce before deregistration takes effect.

```solidity
// In deregisterOperator, before emitting OperatorDeregistered:
// For each open nonce, clear the operator's vote:
// votes[voteType][nonce].voteCounts[votes[voteType][nonce].voted[_operator]]--;
// delete votes[voteType][nonce].voted[_operator];
```

### Proof of Concept

Setup: Bridge with operators A, B; threshold = 2 for `ValueTransfer`.

1. Operator A (compromised) calls `handleKLAYTransfer(fraudTxHash, attacker, victim, 100 ether, nonce=5, ...)`. `_voteCommon` records `votes[0][5].voted[A] = voteKey` and `votes[0][5].voteCounts[voteKey] = 1`. Threshold not yet met; function returns without transfer.

2. Owner discovers A is compromised and calls `deregisterOperator(A)`. `operators[A]` is deleted, `operatorList` shrinks — but `votes[0][5].voted[A]` and `votes[0][5].voteCounts[voteKey] = 1` remain in storage.

3. Operator B (honest relayer) independently processes the same cross-chain event and calls `handleKLAYTransfer(fraudTxHash, attacker, victim, 100 ether, nonce=5, ...)`. `_voteCommon` records B's vote: `voteCounts[voteKey]` becomes 2, which equals the threshold.

4. `_voteValueTransfer` returns `true`, `closedValueTransferVotes[5] = true`, and `_to.call.value(100 ether)("")` executes — sending 100 KLAY to the attacker's address. [7](#0-6)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
