### Title
Amending the HEAD commit captured as `head_at_capture` desyncs `dirty_now` from `changed_since`, silently dropping a committed dangerous file from the Stop-hook review set - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` intersects `dirty_now` (git-status-derived) with `changed_since` (content-diff-derived) to build the file set the Stop hook reviews. The `dirty_now` side only picks up committed-this-turn files when `head_at_capture` is a strict git ancestor of the current `HEAD`. A completely ordinary git operation — `git commit --amend` on the exact commit that was `HEAD` when `UserPromptSubmit`'s `capture_git_baseline`/`_git_rev_parse_head` snapshot ran — replaces that commit with a sibling, breaking the ancestor relationship. The resulting file is then present in `changed_since` (raw content diff) but absent from `dirty_now` (clean, committed), so the intersection silently drops it from `review_paths`, and the file is never sent to the LLM security reviewer.

### Finding Description
At `UserPromptSubmit`, `handle_user_prompt_submit` (`security_reminder_hook.py:446-515`) captures two independent values: `baseline_sha` via `capture_git_baseline` (`diffstate.py:163-204`, a `git stash create` snapshot of the working tree) and `head_at_capture` via `_git_rev_parse_head(cwd)` (`security_reminder_hook.py:477`). These are stored in session state and later consumed by the Stop hook.

`compute_v2_review_set` (`diffstate.py:353-438`) computes:
- `dirty_now` = currently-dirty tracked files ∪ new untracked files, **plus** (only if `head_at_capture` is a strict ancestor of current `HEAD` via `_is_ancestor`, `gitutil.py:377-387`) the files touched by `head_at_capture..HEAD`.
- `changed_since` = `git diff --name-only baseline_sha` (`_git_name_only`, `gitutil.py:303-327`) — a raw tree-vs-worktree content diff that is agnostic to commit history/ancestry.
- `review_set = dirty_now & changed_since` (`diffstate.py:426`).

The bug: if the commit that equals `head_at_capture` itself is amended (`git commit --amend`), the amended commit is a **sibling** of `head_at_capture` (same parent), not a descendant, so `_is_ancestor(head_at_capture, HEAD)` returns `False`. The amended file is now fully committed (clean), so `git status --porcelain` no longer reports it, and it is absent from `dirty_now`. Meanwhile `changed_since` (content diff against the `git stash create` baseline) still correctly shows the file as changed, since it diffs tree content directly, independent of commit ancestry. The intersection at line 426 then drops the file entirely: `review_set` no longer contains it, `review_paths` is empty or missing that entry, and `handle_stop_hook` either skips via `_skip(9, ...)` (`security_reminder_hook.py:1795-1797`) or proceeds without that file in the diff sent to the LLM reviewer.

This is reachable purely through "normal git operations in a cloned repo": committing (or having a pre-existing commit as the turn-start HEAD) and then amending that exact commit is an everyday workflow (`git commit --amend`, interactive rebase with `reword`/`fixup` on the tip commit, etc.), requiring no special privilege — an attacker only needs to get such a command sequence executed (e.g., via repo-embedded instructions that influence how Claude/user manages commits) in a session where a dangerous edit lands in that amended commit.

No existing guard catches this: `_is_ancestor` is documented as detecting "HEAD moved forward via commit/merge, not sideways via checkout" (`gitutil.py:377-379`), but amend is neither forward-only advance nor a checkout — it's a same-parent replacement that the code treats identically to a sideways move, and the `changed_since` fallback that would otherwise catch content changes is defeated by the `&` intersection rather than an `|` union or an amend-aware detection.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a dangerous file that is genuinely new since the UPS-captured baseline is excluded from `review_paths`, so the Stop hook's LLM vulnerability scan (`analyze_code_security` at `security_reminder_hook.py:1857`) never inspects it and no `exit(2)` remediation loop is triggered. This is a logic-level bypass of the security-guidance plugin's core enforcement mechanism — a required security guard is silently skipped due to baseline/ancestry misbinding, matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state."

### Likelihood Explanation
Preconditions are trivial and require no privilege beyond normal repository/commit access: (1) a turn starts with `HEAD` at some commit `H0` (this is simply whatever the repo's HEAD already is, not necessarily authored by Claude), (2) during the turn a dangerous change is folded into an `--amend` of `H0` rather than a fresh commit. Amending the previous commit is an exceedingly common and unremarkable git habit (fixing a typo, adding a forgotten file, "clean history" workflows), so this is easily and repeatably triggered without any anomalous or suspicious command sequence.

### Recommendation
Do not gate the committed-file contribution to `dirty_now` on strict ancestry alone. Either:
1. Union `changed_since` content-diff results directly into `review_set` when `baseline_sha` is available (drop the `dirty_now &` requirement for the baseline-diff term), while still separately excluding pre-existing untracked files as today, or
2. When `_is_ancestor` returns `False`, fall back to treating `head_at_capture..HEAD`'s reflog-based commit set (or a full diff of `baseline_sha` vs `HEAD`) as authoritative for `dirty_now` instead of silently omitting committed files, so `review_set` is never narrower than what `changed_since` reports for tracked files that differ from the stash baseline.

### Proof of Concept
Integration test in the existing Stop-hook test harness:
1. Init a repo with commit `H0` containing `safe.py`.
2. Simulate UPS: call `capture_git_baseline(cwd)` → `baseline_sha`; call `_git_rev_parse_head(cwd)` → `head_at_capture` (== `H0`).
3. Simulate Claude's turn: edit `dangerous.py` (e.g., add `os.system(user_input)`), `git add -A && git commit -m "fix"` → `H1`.
4. Simulate an amend of the tip: `git commit --amend --no-edit` after also staging an additional tweak to `dangerous.py` → new commit `H1'` (still descendant of `H0`, so this step alone is fine — included as a control).
5. Now amend `H0` itself instead: reset scenario where the dangerous edit is committed as an amend of `head_at_capture` directly (e.g., `git commit --fixup=H0` + `git rebase --autosquash -i H0~1`, or simpler: `git reset --soft H0~1 && git commit --amend` chain) producing `H0'` where `H0` is not an ancestor of `H0'`.
6. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture)`.
7. Assert (expected to fail pre-fix): `dangerous.py` is present in `changed_since` (verify via direct `_git_name_only(repo, baseline_sha)` call) but **absent** from the returned `review_paths` — demonstrating the intersection silently drops a genuinely changed, dangerous file from the reviewed set. def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
