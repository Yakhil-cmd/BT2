### Title
Webhook signature check binds trust to `repository.owner.login`, but event handlers act on the unrelated `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to verify the HMAC signature against using `repository_owner`, extracted from the attacker-controlled JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). Every downstream `Shipit::Webhooks::Handlers::Handler` subclass, however, resolves the actual `Repository`/`Stack` to act on using a *different* attacker-controlled field from the same body: `payload.dig('repository', 'full_name')`. Nothing ties these two fields together, so the organization whose secret is "authenticated" is not the repository that ends up being written to.

### Finding Description
`verify_signature` in [1](#0-0)  does:

```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```

where `repository_owner` comes straight from the JSON payload [2](#0-1) .

`GitHubApp#verify_webhook_signature` has an unconditional bypass when no `webhook_secret` is configured for that organization:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [3](#0-2) 

`webhook_secret` is documented as optional per organization (`webhook_secret: # nil`) in both the single-org and multi-org setup docs [4](#0-3)  and in the shipped example secrets files [5](#0-4) .

Meanwhile, every handler that decides *which* `Repository`/`Stack` an event applies to uses the unrelated `repository.full_name` field, e.g. the base `Handler#repository_name` [6](#0-5) , `PushHandler#process` [7](#0-6) , and the pull-request handlers that call `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [8](#0-7) .

Because `Shipit.github(organization:)` is keyed per-organization for multi-org installs [9](#0-8) , an installation that manages several GitHub organizations, where at least one organization has no `webhook_secret` configured (an explicitly supported, documented configuration), lets an unauthenticated party set `repository.owner.login`/`organization.login` to that unsecured org to skip signature verification entirely, while independently setting `repository.full_name` to point at a stack/repository belonging to a *different*, secured organization tracked by the same Shipit instance. The equality that should hold - "the organization whose signature was authenticated == the repository being written by the handler" - is broken.

### Impact Explanation
This lets an unauthenticated attacker forge GitHub webhook events (`push`, `pull_request`, `status`, `check_suite`, `membership`) against stacks/repositories that belong to an organization other than the one used to pass the (missing) signature check. Concretely this can be used to:
- Trigger `Stack#sync_github` on an unrelated org's stacks via forged `push` events.
- Forge `status` events to inject/mark commit statuses on an unrelated org's commits, which Shipit's CI gate (`ci.require`) consults before allowing deploys - a path toward an unauthorized deploy.
- Create/close/unarchive review stacks or manipulate PR labels tracked for provisioning behavior on a different org's repositories.
- Fabricate `membership` events that create/delete `Team`/`Membership`/`User` records used for authorization (`Shipit.github_teams`).

This maps to the High-severity category ("unauthenticated ... escalation into `Shipit.github_teams` authorization" / manipulation of deploy-gating state) and, depending on downstream CI-gate consumption, can chain toward an unauthorized deploy.

### Likelihood Explanation
Requires only that the Shipit deployment manages more than one GitHub organization and that at least one of them is configured without a `webhook_secret` - a state the project's own documentation and shipped example configs present as a normal, supported, "optional" configuration. No credentials, tokens, or GitHub App secrets are needed by the attacker; a single unauthenticated HTTP POST to `/webhooks` suffices. This makes the likelihood non-trivial in any multi-org deployment that doesn't uniformly enforce webhook secrets.

### Recommendation
- Require `webhook_secret` to be mandatory for every configured organization (fail closed) rather than treating it as optional/bypassable when absent.
- Verify the signature using the organization actually resolved from `repository.full_name` (i.e., the org that owns the target repository), not a separate, independently-attacker-controlled field (`repository.owner.login` / `organization.login`).
- Cross-check that `repository.owner.login` matches the owner portion of `repository.full_name` before dispatching to handlers, and reject the webhook if they diverge.

### Proof of Concept
1. Configure Shipit for two GitHub organizations: `OrgA` (no `webhook_secret` set) and `OrgB` (has a `webhook_secret`, hosts a real tracked repo `OrgB/prod-app`).
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/prod-app" },
  "sha": "<target commit sha>",
  "state": "success",
  "context": "required-ci-check",
  "branches": [{ "name": "main" }]
}
```
No `X-Hub-Signature` header is required, since `verify_signature` resolves `Shipit.github(organization: "OrgA")`, whose `verify_webhook_signature` returns `true` unconditionally because `OrgA` has no `webhook_secret`.
3. `StatusHandler` resolves the target repository/stack via `repository.full_name` ("OrgB/prod-app") and writes the forged `success` status onto `OrgB`'s commit, even though the request was never authenticated against `OrgB`'s secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
