### Title
Cross-Party IDOR: `handleNewSharedAddress` Accepts Attacker-Supplied Shared-Address Definitions Naming the Victim's Own Address Without Verifying the Sender Is a Legitimate Co-Signer — ([File: wallet_defined_by_addresses.js])

### Summary
`wallet.js`'s `handleMessageFromHub` routes the `"new_shared_address"` device message directly to `walletDefinedByAddresses.handleNewSharedAddress(body, callbacks)` with no check that `from_address` (the sending paired device) is actually one of the parties named in `body.signers`, and no check that the resulting definition enforces genuine multi-party control. This mirrors the Coolify bug class: a handler trusts caller-supplied identifiers (here, `address`/`definition`/`signers`) that reference a resource (the victim's own address) belonging to someone else, without validating that the caller is authorized to bind that resource into the new object.

### Finding Description
The message handler for `"new_shared_address"` is registered here: [1](#0-0) 

It forwards straight into `handleNewSharedAddress`: [2](#0-1) 

The only checks performed are:
- `body.address` matches the c-hash of `body.definition` (`objectHash.getChash160`) — line 384-390.
- Each `signerInfo.address` in `body.signers` is a syntactically valid address — line 391-395.
- The signer addresses line up with the `['address', ...]` leaves extracted from the definition — line 396-405.
- `determineIfIncludesMeAndRewriteDeviceAddress` merely checks that *some* address referenced in `body.signers` is either one of my own (`my_addresses`) or an already-known `shared_addresses` entry — it does **not** verify that `from_address` (the actual sender of the message) corresponds to any of the `device_address` values claimed in `body.signers`: [3](#0-2) 
- `validateAddressDefinition` only checks generic oscript definition validity (each branch has a signature, complexity limits) — it does not restrict the boolean structure to `and`-only (multi-sig) definitions: [4](#0-3) 

Because `from_address` is never cross-checked against the `signers` map, **any paired device correspondent** of the victim can send a `"new_shared_address"` message naming the victim's own real address as one signer and an attacker-controlled address as another, combined with `['or', [...]]` instead of `['and', [...]]`. Since `determineIfIncludesMeAndRewriteDeviceAddress` finds the victim's real address among `my_addresses`, the message is accepted and `addNewSharedAddress` silently persists the shared address and its `shared_address_signing_paths` into the victim's wallet database — with no user confirmation event required for this path (unlike `create_new_shared_address`/`approve_new_shared_address`, which are meant to require interactive confirmation before storage). This is analogous to the Coolify defect where Livewire components accepted `server_id`/`destination_uuid` from an untrusted source without validating team/ownership scope, in contrast to the API layer that did check `Server::whereTeamId`.

### Impact Explanation
An attacker who is merely paired with the victim (device correspondent — one of the reachable actor classes) can inject a shared-address record into the victim's wallet whose oscript definition is `['or', [victim_address, attacker_address]]` rather than a true multisig `['and', ...]`. If the victim (or an application built on the wallet) is subsequently led to fund this "shared" address — believing it requires joint authorization because it is displayed/tracked as a shared/multisig address — the attacker can unilaterally spend the funds via the `or` branch, with no cooperation or additional signature from the victim required. This is a concrete unauthorized-spending / fund-loss vector rooted in a missing authorization check on data received from an untrusted paired device, matching the "unauthorized spending" and "AA/contract fund loss" impact classes required by the validation rules.

### Likelihood Explanation
Any device that has completed pairing with the victim (a normal, low-privilege relationship — pairing does not imply trust for asset custody) can trigger this at will by sending a single `"new_shared_address"` message with attacker-chosen `definition`/`signers` naming the victim's genuine address. No race condition, no special timing, and no cooperation from the victim's UI is needed to get the malicious record persisted — only subsequent social engineering (or a wallet feature that automatically suggests funding known shared addresses) is needed to realize the fund-loss impact. The persistence step itself is fully attacker-triggerable and requires no victim confirmation.

### Recommendation
In `handleNewSharedAddress`, before persisting the shared address:
1. Verify that `from_address` matches the `device_address` claimed for at least one signer entry that is *not* controlled by "me" (i.e., that the sender is legitimately a party being introduced into the shared address), rather than only checking that one of the referenced addresses happens to be mine.
2. Restrict/flag definitions where an address I own participates in an `or` branch alongside a foreign address, since this defeats the "shared" (multi-party) security property implied by a shared address; at minimum, require explicit user confirmation via `eventBus.emit` before calling `addNewSharedAddress`, mirroring the confirmation flow used for `create_new_shared_address`/`approve_new_shared_address`.
3. Re-validate that the definition topology matches what the sending party is entitled to propose (e.g., disallow unauthenticated third parties from constructing arbitrary boolean combinations that include the recipient's own addresses).

### Proof of Concept
1. Attacker device `D_a` is paired with victim device `D_v` (ordinary pairing, e.g. via a public pairing link).
2. Attacker crafts `arrDefinition = ['or', [['address', V], ['address', A]]]` where `V` is the victim's known real address (learned e.g. from a prior payment/text message) and `A` is an address fully controlled by the attacker.
3. Attacker computes `address = objectHash.getChash160(arrDefinition)`.
4. Attacker sends device message:
```
subject: "new_shared_address"
body: {
  address: address,
  definition: arrDefinition,
  signers: {
    "r.0": { address: V, device_address: D_v },
    "r.1": { address: A, device_address: D_a }
  }
}
```
5. On `D_v`, `handleNewSharedAddress` validates the c-hash, signer format, and definition validity — all pass trivially since `V` and `A` are pre-existing real addresses with valid `sig` definitions. `determineIfIncludesMeAndRewriteDeviceAddress` finds `V` in `my_addresses` and succeeds.
6. `addNewSharedAddress` persists `shared_addresses`/`shared_address_signing_paths` for `address` into `D_v`'s wallet database with no confirmation dialog.
7. If `D_v`'s user is subsequently induced to send funds to `address` (e.g., attacker claims "let's use this shared address for escrow"), the attacker alone can immediately spend those funds via the `['address', A]` branch of the `or` definition, without any signature or cooperation from the victim.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
