### Title
Unsocialized bad debt lets early withdrawers exit at full supply-index value, concentrating the entire loss on late suppliers - (File: contracts/pool/src/ops/withdraw.rs)

### Summary
XOXNO Lending tracks supplier claims as RAY supply shares valued at `supply_index`, and only writes the index down when bad debt is explicitly socialized inside `ops::seize::apply` via `interest::apply_bad_debt_to_supply_index`. A `withdraw` only gates on tracked `cash` (`require_reserves`) and the `require_supply_for_debt` shape check — it never accounts for existing-but-unsocialized bad debt. Between the moment an account becomes insolvent and the moment someone calls `clean_bad_debt`/`force_socialize_bad_debt` (or a liquidation seizes the debt leg), every supplier can still withdraw 100% of their index-valued claim while cash lasts. The loss is therefore borne entirely by whoever withdraws last, not pro-rata — the same distortion class as the `EthAnchor` report.

### Finding Description
Withdrawal resolves shares at the live `supply_index` and pays the request verbatim; the only liquidity gates are `cache.require_reserves(net_transfer)` and `guards::require_supply_for_debt` [1](#0-0) . `require_reserves` compares only against tracked `cash`, which still includes the cash backing of uncollectible debt [2](#0-1) .

The loss is only recognized when a seize entry with `AccountPositionType::Borrow` runs `apply_bad_debt_to_supply_index`, which scales the index down by `bad_debt / total_supplied_value` [3](#0-2) [4](#0-3) . That happens inside liquidation or explicit `clean_bad_debt`/`force_socialize_bad_debt` [5](#0-4)  — none of which is atomic with the price move that creates the insolvency.

So a supplier who calls `withdraw` (or exits via `repay_debt_with_collateral`/`swap_collateral`-adjacent flows that end in a withdraw leg) in the gap between insolvency and socialization receives `floor(shares × index)` at the pre-loss index. Once cleanup runs, the index write-down lands on everyone still holding shares — including users who had no chance to exit — amplifying their loss beyond pro-rata.

### Impact Explanation
Permanent, asymmetric loss of user funds: early withdrawers recover 100% of indexed value from an already-insolvent market, while remaining suppliers absorb the early exits plus the full bad-debt write-down. In the worst ordering, last suppliers lose everything (write-down clamps at `SUPPLY_INDEX_FLOOR_RAW = RAY/1000`, a 99.9% loss) even though their fair pro-rata share was far smaller. This is theft-by-ordering of supplier principal.

### Likelihood Explanation
Requires an external trigger (a price crash making an account insolvent before any liquidation/cleanup transaction lands), matching the Medium profile: value leakage along a stated path with external requirements. Cleanup is permissionless, but nothing forces it to execute before withdrawals — an attentive supplier can front-run `clean_bad_debt`, and ordinary users simply withdraw first. No privileged role is needed on the exploiting side; the victim class is all remaining suppliers.

### Recommendation
Make withdrawal itself recognize the shortfall instead of deferring it to cleanup: before paying out, compute the market backing shortfall (`max(0, supply_value − (cash + debt_value))`, the same check `recapitalize` uses) and reduce the payout proportionally, or apply `apply_bad_debt_to_supply_index` lazily for any insolvent-debt amount already identified. At minimum, gate `withdraw` with the same solvency condition used for `clean_bad_debt` eligibility so no exit can precede the required write-down.

### Proof of Concept
1. BOB supplies 1,000 ETH to hub asset `(hub, ETH)`; ALICE supplies USDC collateral and borrows 500 ETH. `state.cash` ≈ 500 ETH (rest lent out), `supplied` shares value = 1,000 ETH at `supply_index ≈ 1`.
2. USDC price crashes so ALICE's `D > C` (insolvent, e.g. collateral ≤ dust or forced path). No one has called `clean_bad_debt` yet.
3. CAROL, another supplier with 400 ETH of indexed claim, calls `controller::withdraw` → pool `ops::withdraw::apply`. `resolve_withdrawal` pays `floor(shares × index)` = 400 ETH; `require_reserves` passes because `cash` still counts uncollectible-backing; she exits whole.
4. Anyone now calls `clean_bad_debt(ALICE)`: `apply_bad_debt_to_supply_index` writes the index down by `bad_debt / total_supplied_value` computed against the *remaining* smaller supply base. BOB's 600 ETH claim shrinks to cover both ALICE's bad debt and CAROL's full-value exit — BOB's loss exceeds his pro-rata `bad_debt × his_share / total_supply`, and if bad debt ≥ remaining cash-backed value the index clamps at `RAY/1000`, wiping him out.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```
