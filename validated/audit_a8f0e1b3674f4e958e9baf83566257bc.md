Found it: the `StatusHandler` (and similarly `check_suite`/`push` for cross-org cases) resolves the target purely from unauthenticated payload fields, while the webhook signature is verified against a *different* claimed field. This is a genuine binding break in the multi-org configuration case.

### Title
Webhook signature verified against attacker-claimed `repository.owner.login`, not the record actually mutated - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the HMAC signature against using `repository_owner`, a value read directly out of the *unauthenticated* JSON body, before any signature has been confirmed. The event handlers (e.g. `StatusHandler`, `PushHandler`) then act on data (`sha`, `repository.full_name`, `branches`) that is not required to be internally consistent with that same `repository.owner.login` field. This mirrors the `updateOwnerSplit()` pattern: a value read from the payload (`ownerSplit`/`repository_owner`) is used to authorize an action, but the actually-affected record (the loan's revenue split / the Shipit stack whose commit status gets written) is not bound to what was actually verified.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-30` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
`repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`) is taken straight from the unverified request body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. In a multi-organization Shipit configuration (`config/secrets.yml` supports per-org `github:` blocks per `docs/setup.md`), each organization can have its own `webhook_secret`, and `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) explicitly **returns `true` when no secret is configured for that org** (`return true unless webhook_secret`).

Once `verify_signature` passes, `WebhooksController#create` dispatches to handlers such as `StatusHandler` (`app/models/shipit/webhooks/handlers/status_handler.rb`) which looks up commits purely `by sha` — with no repository/org scoping at all — and `PushHandler`/`Handler#stacks` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) which resolve the target `Repository`/`Stack` from `payload.dig('repository', 'full_name')`, a field independent from the `owner.login` sub-field that gated the signature check.

This creates the exact equality break the rules describe — "an organization that authenticated versus the repository that is written": the org whose secret was used to authenticate the payload is not cryptographically bound to the `repository.full_name`/`sha` fields that the handlers subsequently write to. An attacker with no Shipit credentials who can guess or observe that some configured GitHub org in the multi-tenant setup has `webhook_secret` unset (the docs explicitly call the secret "optional") can forge a payload with `repository.owner.login` set to that no-secret org while setting `repository.full_name`/`sha`/`ref` to point at a target stack under a *different, secured* organization, bypassing signature verification entirely for writes to that target stack's commit statuses/deploy triggers.

### Impact Explanation
This allows an unauthenticated, unprivileged network attacker to inject/forge GitHub `status` or `push` events for a repository whose real webhook secret they don't know, as long as any other configured organization lacks a webhook secret. Forged `status` events can flip a commit to `success`, satisfying CI gates and enabling an unauthorized deploy through the merge queue / deploy trigger machinery (`Commit#create_status_from_github!`, `MergeRequest#all_status_checks_passed?`). This matches the "unauthorized deploy" Critical-impact bucket in scope.

### Likelihood Explanation
Requires the operator to run a multi-org Shipit configuration where at least one configured organization has no `webhook_secret` set (explicitly documented as optional/`nil` in `config/secrets.development.example.yml`), and the attacker must know the target `repository.full_name` and a commit `sha`. This is a realistic-but-conditional configuration state, not a hard requirement of code paths — likelihood is moderate, not universal, since single-org / secret-everywhere deployments are unaffected.

### Recommendation
Bind the verified organization to the record actually mutated: after computing `repository_owner`, require the resolved handler's target repository (`repository.full_name`) to belong to that same organization before dispatching, and reject payloads where `repository.owner.login` doesn't match the owner segment of `repository.full_name`. Additionally, do not silently treat a missing `webhook_secret` as "verified"; only allow secret-less bypass for organizations that have no stacks in a shared/multi-org install, or require a secret to be configured for every organization.

### Proof of Concept
1. Configure Shipit with two orgs: `victim-org` (has `webhook_secret: "s3cret"`, owns a monitored `Stack`) and `test-org` (no `webhook_secret` configured).
2. Attacker POSTs to `/webhooks` with header `X-Github-Event: status`, no valid `X-Hub-Signature` for `victim-org`, and body:
```json
{
  "repository": {"owner": {"login": "test-org"}, "full_name": "victim-org/victim-repo"},
  "sha": "<known undeployed commit sha of victim-org/victim-repo>",
  "state": "success",
  "context": "ci/required"
}
```
3. `verify_signature` calls `Shipit.github(organization: "test-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally.
4. `StatusHandler#process` looks up `Commit.where(sha: params.sha)` with no org check and marks the victim commit's status as `success`, potentially unblocking a deploy/merge for `victim-org` without ever presenting a valid signature for that organization.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
