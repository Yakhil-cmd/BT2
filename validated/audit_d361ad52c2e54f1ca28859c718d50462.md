## Analysis

`Api::CCMenuController` overrides `#stack` to bypass the token→stack scoping that `Api::BaseController` enforces everywhere else. In `BaseController`, `stacks` restricts the visible set to the token's bound stack (`current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all`), and `#stack` (used by `TasksController`, `DeploysController`, `MergeRequestsController`, `StacksController`) resolves through that scoped relation via `stacks.from_param!(params[:stack_id])`. [1](#0-0) 

`CCMenuController`, however, redefines `#stack` to call `Stack.from_param!(params[:stack_id])` directly, never going through the `stacks` scoping helper: [2](#0-1) 

`require_permission :read, :stack` only calls `ApiClient#check_permissions!`, which checks that the token *has* the `read:stack` permission string in its `permissions` array — it never checks *which* stack the permission applies to: [3](#0-2) 

So for a token created with `stack_id` set (i.e., intentionally scoped to a single stack, e.g. via `CCMenuUrlController#client` which creates such a scoped `ApiClient` with only `read:stack`), the authorization check only verifies the permission name, while the actual stack object acted upon is resolved without any ownership filter. This breaks the binding: **stack a token authorizes == stack it touches**. Before: token scoped to stack A is only supposed to see stack A's CI status. After: passing any other `stack_id` in the URL, the same token can read `deploys_and_rollbacks` (deploy history / status / last build info) for *any* stack in the instance, because `Stack.from_param!` is unscoped. [4](#0-3) [5](#0-4) 

This matches the "High" impact category: "unauthenticated read of stack state, task streams or deploy output" — here it's a token that is authenticated but scoped, reading state of a stack it was never authorized for, an escalation of read-access across the authorization boundary that every other API controller enforces.

### Title
Stack-scoped API tokens can read CI/deploy state of any stack via `CCMenuController` (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Api::CCMenuController#stack` resolves the target stack with `Stack.from_param!(params[:stack_id])` instead of the `stacks.from_param!(...)` helper used by all other API controllers. This means a token that is deliberately scoped to a single stack (via `ApiClient#stack_id`) is not restricted to that stack when calling this endpoint, breaking the "stack authorized by token == stack touched" binding.

### Finding Description
Every other `Api::BaseController` subclass resolves the target stack through `#stack`, which is defined in the base as `stacks.from_param!(params[:stack_id])`, and `stacks` filters to `Stack.where(id: current_api_client.stack_id)` when the token is stack-scoped. [1](#0-0) 

`CCMenuController` overrides `#stack` and drops this scoping entirely: [2](#0-1) 

The only authorization gate left is `require_permission :read, :stack`, which delegates to `ApiClient#check_permissions!`, a check that only inspects the `permissions` array of strings — it has no knowledge of, or dependency on, which stack ID is in the request: [3](#0-2) 

Stack-scoped tokens with `read:stack` are a real, intentionally-created artifact: `CCMenuUrlController#client` creates exactly this kind of token (`permissions: %w[read:stack]`, implicitly bound to a stack via `find_or_create_by!` scoping usage elsewhere in the app), meant to let a CI dashboard read one project's status. [5](#0-4) 

Because `CCMenuController` also supports authenticating purely via a `token` query-string parameter (`ApiClient.authenticate(params[:token])`), and this token is embedded directly in a plain URL meant to be pasted into third-party CI-dashboard tools: [6](#0-5) 

anyone holding that URL (arguably a lower-trust, cross-tool integration secret than a general API credential) can swap the `stack_id` parameter and read `deploys_and_rollbacks` — deploy status, timestamps, and lock state — for any stack in the Shipit instance, not just the one the token was issued for.

### Impact Explanation
This is an unauthenticated-relative-to-scope read of stack state: a credential explicitly minted and distributed for reading exactly one stack's CI status can be repurposed to read every stack's deploy/lock state in the instance. This matches the "High" category ("unauthenticated read of stack state, task streams or deploy output") since the effective authorization for stacks outside the token's intended scope is bypassed.

### Likelihood Explanation
Likelihood is elevated because: (1) the vulnerable code path is reachable with only a `token` query parameter, no session or privileged credential; (2) CCMenu tokens are specifically designed to be embedded in bookmarkable/shareable URLs for third-party CI dashboard tools, increasing the chance of the token leaking into logs, browser history, or being shared outside its intended scope; and (3) the only required action is changing `stack_id` in the URL — no other guessing or brute forcing needed if the attacker holds any valid stack-scoped token.

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the scoped `stacks` helper from `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!(params[:stack_id])`, so stack-scoped tokens cannot read data for stacks outside their `stack_id`.

### Proof of Concept
1. Create (or obtain, e.g. from a leaked CCMenu URL) an `ApiClient` scoped to Stack A with `permissions: ['read:stack']` (as produced by `CCMenuUrlController#client`). [5](#0-4) 
2. Send `GET /api/stacks/:stack_id_of_stack_B/ccmenu.xml?token=<token_for_stack_A>`.
3. `authenticate_api_client` succeeds via `ApiClient.authenticate(params[:token])`. [6](#0-5) 
4. `require_permission :read, :stack` passes because the token has `read:stack` in its permission list — it never checks whether Stack B equals the token's bound stack. [3](#0-2) 
5. `#show` calls `stack.deploys_and_rollbacks.last`, where `#stack` resolves unscoped to Stack B via `Stack.from_param!`, returning Stack B's deploy state to a token that was only ever authorized for Stack A. [7](#0-6)
