### Title
Path traversal via unsanitized release asset name allows arbitrary file write outside destination directory - ([File: pkg/cmd/release/download/download.go])

### Summary
`gh release download` builds the destination file path by joining the user-supplied `--dir` with the release asset's `Name` field taken verbatim from the GitHub API, with no `filepath.Base` or traversal confinement. An attacker who controls a repository/release (e.g. via a fork or any repo the victim points `gh` at) can publish an asset whose `name` contains `../` segments, causing the write to land outside the intended destination directory when the victim runs `gh release download`.

### Finding Description
In `downloadRun`, asset names come straight from `release.Assets` (`a.Name`, parsed from the GitHub API JSON) and are passed unmodified into `downloadTarget.name` [1](#0-0) . This flows into `downloadAsset` -> `dest.Copy(fileName, resp.Body)` [2](#0-1) [3](#0-2) , which calls `makePath`:

```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [4](#0-3) 

`filepath.Join` performs `Clean` on the concatenated path, so a `name` like `../../.ssh/authorized_keys` will resolve to a path outside `w.dir` when it contains enough `..` segments. `Copy` then does `os.MkdirAll(dir, 0755)` on the resulting (potentially escaped) parent directory and `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` on it [5](#0-4) , truncating/overwriting whatever file exists at that resolved path (subject only to the pre-existing `check`/`--clobber` logic, which does not stop cross-directory writes — it only blocks overwriting *within* the resolved path unless `--clobber` is passed, and does nothing to prevent the path itself from escaping `w.dir`).

Notably, the sibling command `pkg/cmd/run/download/download.go` uses the `internal/safepaths` package (`safepaths.Absolute.Join`, which explicitly rejects any join that would traverse outside the base directory via `PathTraversalError`, see `internal/safepaths/absolute.go`) to confine artifact-derived file names to the destination directory. `pkg/cmd/release/download/download.go`'s `makePath` has no equivalent confinement, and the codebase's own `isWindowsReservedFilename` check demonstrates that reserved/malicious filenames from `a.Name` are already recognized as an "exploit vector" worth guarding against on Windows, but path traversal is not guarded against on any OS [6](#0-5) .

### Impact Explanation
An attacker publishing a release (in their own repo or a fork) with an asset named e.g. `../../../../.ssh/authorized_keys` or `../../.git/hooks/pre-commit` can, when the victim runs an ordinary `gh release download` (or `gh release download <tag>` without `--pattern`) against that repository, cause `gh` to write attacker-controlled content to a file outside `opts.Destination`. This is an arbitrary file write outside the intended download directory, which can lead to further compromise (e.g. SSH key injection, git hook execution, or overwriting startup/config files), matching the "file write outside intended path" impact class.

### Likelihood Explanation
The precondition is simply that the victim runs `gh release download` against an attacker-controlled or attacker-forked repository — no special flags, no `--pattern`, and no `--output` are required, since the default flow iterates `release.Assets` directly. Publishing a release with an arbitrarily-named asset is trivial for any GitHub user (unprivileged attacker). This makes the issue readily reachable and repeatable.

### Recommendation
Sanitize/confine asset names in `makePath`/`Copy` before joining with `w.dir`, e.g. reuse `internal/safepaths.Absolute.Join` (as `pkg/cmd/run/download` already does) or at minimum reject any asset name containing path separators or `..` components (or apply `filepath.Base` and validate the result stays within `w.dir` via `filepath.Rel`/prefix check) before calling `os.MkdirAll`/`os.OpenFile`.

### Proof of Concept
```go
func TestDownloadRun_AssetNamePathTraversal(t *testing.T) {
	tmpDownloadDir := t.TempDir()          // simulate opts.Destination
	tmpVictimDir := t.TempDir()            // simulate a directory above/outside destination
	traversalName := filepath.Join("..", filepath.Base(tmpVictimDir), "pwned")

	reg := &httpmock.Registry{}
	reg.Register(
		httpmock.REST("GET", "repos/OWNER/REPO/releases/latest"),
		httpmock.JSONResponse(shared.Release{
			TagName: "v1.0.0",
			Assets: []shared.ReleaseAsset{
				{Name: traversalName, APIURL: "https://api.github.com/assets/1"},
			},
		}),
	)
	reg.Register(
		httpmock.REST("GET", "assets/1"),
		httpmock.StringResponse("attacker controlled content"),
	)

	httpClient := &http.Client{Transport: reg}
	opts := &DownloadOptions{
		HttpClient:  func() (*http.Client, error) { return httpClient, nil },
		IO:          iostreams.Test(),
		BaseRepo:    func() (ghrepo.Interface, error) { return ghrepo.New("OWNER", "REPO"), nil },
		Destination: tmpDownloadDir,
		Concurrency: 1,
	}

	err := downloadRun(opts)
	require.NoError(t, err)

	// Expected (fix): file should stay confined to tmpDownloadDir
	// Actual (bug): file is written into tmpVictimDir, outside the destination
	escapedPath := filepath.Join(filepath.Dir(tmpDownloadDir), filepath.Base(tmpVictimDir), "pwned")
	_, statErr := os.Stat(escapedPath)
	require.NoError(t, statErr, "expected file to have escaped destination directory, confirming path traversal")
}
```
Assertion for the fix: `downloadRun` should return an error (or otherwise refuse) when an asset name resolves outside `opts.Destination`, instead of writing `escapedPath`.
