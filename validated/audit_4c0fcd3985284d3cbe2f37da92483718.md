### Title
Gasless Swap Deadline Validated Against Stale `CurrentBlock().Time()` Instead of Next Block's Expected Timestamp, Causing Proposer to Lose Lent KAIA — (`kaiax/gasless/impl/tx_pool.go`)

---

### Summary

`checkBalanceForSwap` in the gasless module validates `swapArgs.Deadline` against `g.Chain.CurrentBlock().Time()` — the **last committed block's** timestamp. However, the transaction will be executed in the **next** block, whose timestamp is guaranteed to be at least `CurrentBlock().Time() + params.BlockGenerationInterval`. Any swap transaction with a deadline in the half-open interval `[CurrentBlock().Time(), CurrentBlock().Time() + params.BlockGenerationInterval)` passes the txpool admission check but will revert on-chain when `GaslessSwapRouter.swapForGas()` enforces `require(deadline >= block.timestamp)`. Because the proposer's LendTx (which transfers KAIA to the user) is committed before the SwapTx, a revert leaves the proposer without repayment — a direct, unrecoverable loss of KAIA.

---

### Finding Description

In `checkBalanceForSwap`, the deadline guard is:

```go
// tx.deadline >= currentTimestamp
deadline := swapArgs.Deadline
if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
    return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", ...)
}
``` [1](#0-0) 

`g.Chain.CurrentBlock().Time()` returns the timestamp of the **already-finalized** head block. The next block's timestamp is set during `PrepareHeader` as:

```go
header.Time = new(big.Int).Add(parent.Time, new(big.Int).SetUint64(blockPeriod))
``` [2](#0-1) 

and is validated to be strictly greater than the parent's timestamp:

```go
if parent.Time.Uint64()+uint64(params.BlockGenerationInterval) > header.Time.Uint64() {
    return ErrInvalidTimestamp
}
``` [3](#0-2) 

Therefore, the next block's `block.timestamp` is always `≥ CurrentBlock().Time() + params.BlockGenerationInterval`. A swap transaction with `deadline = CurrentBlock().Time()` satisfies the txpool guard (`deadline >= CurrentBlock().Time()` is true) but will fail the on-chain check (`deadline >= block.timestamp` is false, since `block.timestamp ≥ CurrentBlock().Time() + 1`).

The gasless bundle execution order is:

1. **LendTx** — proposer transfers KAIA to the user (irreversible within the block)
2. **ApproveTx** — user approves the router
3. **SwapTx** — calls `GaslessSwapRouter.swapForGas(...)` which enforces the deadline on-chain [4](#0-3) 

When SwapTx reverts, the EVM rolls back the swap state but **not** the LendTx (it is a separate, already-committed transaction in the same block). The proposer's lent KAIA is gone.

The lend amount equals the total gas fee for all three transactions:

```go
// From tests/gasless_test.go
R1 = 21000  * gasPrice  // LendTx
R2 = 100000 * gasPrice  // ApproveTx
R3 = 500000 * gasPrice  // SwapTx
ammontRepay = R1 + R2 + R3
``` [5](#0-4) 

---

### Impact Explanation

A user (who holds ERC-20 tokens but zero KAIA) can deliberately set `deadline = CurrentBlock().Time()`. The txpool accepts the transaction. The proposer builds the bundle, lends KAIA, and the swap reverts on-chain. The proposer loses the lent KAIA (gas fees for the full bundle). The attack is repeatable across blocks and across multiple proposers.

This is an unauthorized loss of KAIA from the proposer — matching the allowed impact gate: *"Unauthorized transfer … affecting KAIA … or system-managed funds."*

---

### Likelihood Explanation

- The attacker needs only ERC-20 tokens (no KAIA), which is exactly the gasless use-case target population.
- Setting `deadline = CurrentBlock().Time()` is trivially observable from any RPC call (`kaia_blockNumber` + `kaia_getBlockByNumber`).
- No privileged access, no validator collusion, and no external service is required.
- The attack can be repeated every block.

---

### Recommendation

Replace the stale `CurrentBlock().Time()` reference with the **next block's expected timestamp**:

```go
// Use next block's minimum expected timestamp
nextBlockTime := new(big.Int).Add(
    g.Chain.CurrentBlock().Time(),
    new(big.Int).SetUint64(params.BlockGenerationInterval),
)
if deadline.Cmp(nextBlockTime) < 0 {
    return fmt.Errorf("insufficient deadline: deadline=%s, want>=%s",
        deadline.String(), nextBlockTime.String())
}
```

This mirrors the pattern used in the integration test, where the deadline is set as `CurrentBlock().Time() + 300`: [6](#0-5) 

---

### Proof of Concept

1. Observe `currentTime = chain.CurrentBlock().Time()` via RPC.
2. Construct a `GaslessSwapTx` with `deadline = currentTime` (all other fields valid: sufficient balance, allowance, `minAmountOut >= amountRepay`).
3. Submit to the txpool. `checkBalanceForSwap` passes: `currentTime >= currentTime`.
4. The proposer builds the bundle: `[LendTx, SwapTx]`. LendTx sends KAIA to the attacker.
5. The next block's `block.timestamp = currentTime + params.BlockGenerationInterval`.
6. `GaslessSwapRouter.swapForGas()` checks `deadline >= block.timestamp` → `currentTime >= currentTime + 1` → **reverts**.
7. SwapTx state is rolled back; LendTx KAIA transfer is **not** rolled back.
8. Proposer has lost the lent KAIA (≈ `(21000 + 100000 + 500000) × gasPrice` per attack). [1](#0-0) [7](#0-6)
