### Title
Burning the position NFT makes an underwater account permanently unliquidatable and uncleanable — every controller path fails on the vanished owner read - (File: contracts/controller/src/storage/account.rs)

### Summary
The kernel bug is a missing NULL check between a `detach()` that clears a shared field and a concurrent `update()` that still dereferences it. The analog on this codebase is the detach between the position-NFT `Owner` entry and the controller's account state. The controller treats NFT ownership as the account's owner pointer: `try_get_account` resolves `try_account_owner` (the NFT `owner_of` read) and returns `None` — i.e., `get_account` panics `AccountNotFound` — whenever the token no longer exists. An unprivileged user who owns the NFT can `burn` it while the account still holds debt and collateral. That is the "set `link->map = NULL`" step. Every later permissionless keeper path — `liquidate`, `clean_bad_debt`, `force_socialize_bad_debt`, `update_account_threshold` — then dereferences the cleared owner and reverts (or skips), exactly the update-on-released-link shape. Because the account entry itself is still live and never expires on the controller's own TTL, no path can ever write down or seize the debt again.

### Finding Description
`storage::get_account` → `try_get_account` returns `None` when `try_account_owner` cannot resolve an owner, and all position flows call `get_account` up front. `storage::account_owner`/`try_account_owner` read the position-NFT `owner_of`, so once the NFT is burned every such read fails. [1](#0-0) 

Liquidation enters through `storage::get_account(env, account_id)` at the top of `liquidate` in `positions/liquidation/mod.rs:46`, and `socialize_bad_debt` (behind permissionless `clean_bad_debt`) does the same. The harness tests encode this: after `position_nft::PositionNftClient::burn(&token_id)`, `try_liquidate`, `try_clean_bad_debt`, and `try_force_socialize_bad_debt` all revert with `AccountNotFound` while `account_exists(id)` still returns true. [2](#0-1) 

`update_account_threshold` handles the same NULL by silently skipping (`let Some(owner) = ... else { return }`), so it cannot restamp or otherwise touch the account either. [3](#0-2) 

Account deletion is only ever performed by `remove_account_and_burn_nft`, which requires empty position maps, so the controller will never clean this account up on its own — collateral and debt stay booked on a spoke whose usage rows permanently include them, and the dust-threshold `clean_bad_debt` exit that normally retires insolvent positions is unreachable. [4](#0-3) 

### Impact Explanation
Permanent freezing of user funds and protocol insolvency. A borrower who is liquidatable (or about to become liquidatable through interest accrual) burns their NFT. From that ledger on, the debt can never be repaid off, seized, or socialized: `liquidate` reverts, `clean_bad_debt` reverts even when the remaining collateral is dust, and `repay`/`withdraw` also fail on `get_account` if called with the stale id. The borrowed tokens are gone but the debt stays on the books; the collateral is stranded inside an account nobody can own or operate. Suppliers of that hub bear the hole with no cleanup path — the exact loss class the bad-debt machinery exists to prevent.

### Likelihood Explanation
Reachable by a single unprivileged address: open a borrow position (`supply` + `borrow`), wait for interest or a price move to make it marginal, then call `burn` on the position NFT (owner-authorized). No admin, no timing race, no third-party dependency. It can also be done speculatively on any borrow account at trivial cost, converting the entire protocol's liquidation pipeline into a permanently reverting path for that account. The main uncertainty I could not fully resolve within the tool budget: the exact auth gate on position-NFT `burn` (it is invoked with mock auths in tests and via `nft_burn_call` from the controller). Standard token burn is owner-authed, which is sufficient for the self-burn attack above; I did not verify whether burn is additionally restricted to the controller, which would reduce the finding to the NFT-expiry variant (partially mitigated by host auto-restore in simulation, per the existing tests, but still unguarded for callers that build a footprint without simulation).

### Recommendation
Add the missing "NULL check" the kernel patch represents, but on the correct side: treat a burned/missing `Owner` entry as a detached account that must still be wound down, not as a nonexistent account.

- In `try_get_account`/`get_account`, do not conflate missing metadata with unresolvable ownership. When `AccountMeta` exists but `try_account_owner` returns `None`, reconstruct the account with a sentinel owner (or carry `Option<Address>`) so that permissionless read-only legs — `repay`, `liquidate`, `clean_bad_debt`, `update_account_threshold`, `get_health_factor` — can proceed.
- Alternatively, block the detach: have the position-NFT `burn` consult the controller (or have the controller gate burns on empty position maps) so an NFT with live supply or debt cannot be burned directly, mirroring `remove_account_and_burn_nft` being the only sanctioned deletion path.
- As defense in depth, allow `clean_bad_debt`/`force_socialize_bad_debt` to operate on `AccountMeta` + position maps alone, since bad-debt write-down does not need an owner.

### Proof of Concept
Conceptual transaction sequence (mirrors the existing harness tests `partial_liquidation_resolves_nft_ownership` and `bad_debt_winddown_resolves_nft_ownership`):

1. Attacker calls `supply(caller, 0, spoke_id, [(USDC, 10_000)])` then `borrow(caller, id, [(ETH, 3.0)])` — account id `id`, NFT minted to attacker.
2. Price or interest pushes HF below 1 (or attacker simply wants to lock collateral): attacker calls `position_nft.burn(token_id)` with their own auth.
3. Any keeper calls `liquidate(liquidator, id, debt_payments, SeizeMode::Transfer)` → `storage::get_account` → `try_account_owner` returns `None` → panic `AccountNotFound`. Same for `clean_bad_debt(keeper, id)` and `force_socialize_bad_debt(id)` — verified by the existing tests at `tests/test-harness/tests/controller/position_nft_ttl_and_ownership_reads.rs:286-334`.
4. `update_account_threshold(caller, true, [id])` succeeds but silently skips the account, so it cannot be used to repair state either.
5. End state: `account_exists(id)` is true, debt and collateral remain booked forever, and no entrypoint can move them — the link was released while the map still pointed at it, permanently.

/// Loads both position maps and current NFT ownership. Missing metadata or
/// unresolved ownership fails with `AccountNotFound`.
pub(crate) fn get_account(env: &Env, account_id: u64) -> Account {
    try_get_account(env, account_id)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::AccountNotFound))
}

/// Loads both position maps and current NFT ownership; returns `None` when
/// metadata is absent or ownership cannot be resolved.
pub(crate) fn try_get_account(env: &Env, account_id: u64) -> Option<Account> {
    let meta = try_get_account_meta(env, account_id)?;
    let owner = try_account_owner(env, account_id)?;
    Some(account_from_parts(
        owner,
        meta,
        get_supply_positions(env, account_id),
        get_debt_positions(env, account_id),
    ))
}

fn partial_liquidation_resolves_nft_ownership() {
    let mut t = LendingTest::new().standard_two_asset().build();
    t.supply(ALICE, "USDC", 10_000.0);
    t.borrow(ALICE, "ETH", 3.0);
    let id = t.account_id(ALICE);
    let token_id = u32::try_from(id).expect("test ids fit u32");

    t.set_price("USDC", usd_cents(50));

/// Deletes all account entries and burns its NFT atomically. Account deletion
/// must use this path to preserve the NFT/account existence invariant.
pub(crate) fn remove_account_and_burn_nft(env: &Env, account_id: u64) {
    storage::remove_account_entry(env, account_id);
    let nft = storage::get_position_nft(env);
    nft_burn_call(env, &nft, account_id);
}

/// Deletes the account and burns its NFT when both position maps are empty.
pub(crate) fn cleanup_account_if_empty(env: &Env, account: &Account, account_id: u64) {
    if account.is_empty() {
        remove_account_and_burn_nft(env, account_id);
    }
}
