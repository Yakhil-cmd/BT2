### Title
ReDoS in hookify rule regex causes PreToolUse hook timeout, which fails open and allows the blocked operation - ([File: plugins/hookify/core/rule_engine.py])

### Finding Description
`_regex_match` in `plugins/hookify/core/rule_engine.py` compiles a user-supplied `pattern` string via `compile_regex()` (an `lru_cache`d `re.compile(pattern, re.IGNORECASE)`) and directly calls `regex.search(text)` with no timeout, length cap, or ReDoS-safety check. [1](#0-0)  Python's `re` engine is backtracking-based, so a pattern such as `(a+)+$` (or similar nested-quantifier patterns) matched against an adversarial string (e.g. many `a`s followed by a non-matching character) triggers catastrophic backtracking and can hang for an effectively unbounded time. The only exception handling present catches `re.error` (compilation syntax errors), not runtime hangs, so a pathological match is not "caught" by anything in this function. [2](#0-1) 

Rules (including the `pattern`/`conditions[].pattern` fields) are loaded from `.claude/hookify.*.local.md` files by `load_rules()`/`load_rule_file()` in `plugins/hookify/core/config_loader.py`. [3](#0-2)  These are ordinary repository files under `.claude/` — if a malicious repository ships such a file, it is picked up automatically the next time any Bash/Edit/Write/MultiEdit tool call fires, per the plugin's own documentation that "Rules take effect on the very next tool use" with no restart needed. [4](#0-3)  The field being matched (`command`, `new_text`, `content`, `file_path`, etc., extracted in `_extract_field`) is attacker-influenceable content: e.g. a Bash command string or file content that Claude is asked to act on, itself often derived from repository content. [5](#0-4) 

`pretooluse.py` wraps the whole evaluation in a broad `try/except Exception` with a `finally: sys.exit(0)`, but this only protects against Python exceptions — it does not, and cannot, interrupt a regex call that never returns. [6](#0-5)  The hookify plugin's own `hooks.json` declares a hard 10-second timeout for the `PreToolUse` command hook. [7](#0-6)  When a hook process exceeds its declared timeout, Claude Code's hook runner (outside this repo) kills/abandons the process; because the hook never printed a `"permissionDecision": "deny"` response before being killed, the host treats the timeout as "no hook output" and defaults to allowing the tool call to proceed — i.e., the enforcement mechanism fails open rather than fail closed.

### Impact Explanation
An attacker who can plant a `.claude/hookify.*.local.md` file in a repository (e.g. via a malicious repo, PR, or shared plugin configuration) can define a rule with a catastrophic-backtracking regex pattern and `action: block`. Any subsequent Bash command or file edit whose content is attacker-influenced (e.g. containing a crafted string in the file/command that triggers the backtracking) causes the PreToolUse hook to hang past its 10s timeout. Because the host defaults to allow-on-timeout, this converts an intended `block` rule into a silent bypass — the exact opposite of the rule's purpose — while also degrading availability (every matching tool call takes ~10s longer). This matches an approval/enforcement-bypass class of impact: a security control (hookify block rule) is nullified by an attacker-controlled regex, allowing dangerous commands/file writes to proceed without the intended block.

### Likelihood Explanation
Feasible and repeatable: no special privilege is required beyond the ability to have a `.claude/hookify.*.local.md` rule file present in the working repository (a normal, documented, user-facing configuration mechanism), and ReDoS patterns like `(a+)+$` or `(a|aa)+$` are well-known, trivial to construct, and Python's backtracking `re` engine is confirmed vulnerable to them. The attacker only needs the victim's Bash/Edit/Write flow to process a string that triggers the backtracking against the malicious pattern — this can be baked into repository content the attacker controls (e.g. a filename, file content, or a command argument the AI is likely to reproduce/execute).

### Recommendation
- Enforce a bounded execution budget on `_regex_match`/`compile_regex`, e.g. via `signal.alarm` (POSIX) or running the match in a worker process/thread with a hard timeout, and treat a timeout as an explicit `deny`/warn rather than silent pass-through.
- Validate/sanitize rule patterns at load time (e.g. reject nested quantifiers like `(x+)+`, `(x*)*`, or use a ReDoS-detection heuristic/library) before caching them in `compile_regex`.
- Cap the length of the text being matched (`field_value`) for regex operations.
- Make the hook fail closed on timeout: if the hook process is killed/times out, the host-side PreToolUse decision should default to `deny` (or at least surface a warning) rather than implicit allow, and this plugin should document/mitigate that its own internal exception handling cannot protect against non-exception hangs.

### Proof of Concept

```python
import time
import pytest
from hookify.core.rule_engine import RuleEngine
from hookify.core.config_loader import Rule, Condition

def test_redos_pattern_bounded_or_fails_closed():
    rule = Rule(
        name="redos",
        enabled=True,
        event="bash",
        action="block",
        conditions=[Condition(field="command", operator="regex_match",
                               pattern=r"(a+)+$")],
        message="blocked"
    )
    engine = RuleEngine()
    payload = {
        "hook_event_name": "PreToolUse",
        "tool_name": "Bash",
        "tool_input": {"command": "a" * 40 + "!"}  # triggers catastrophic backtracking, never matches
    }

    start = time.monotonic()
    result = engine.evaluate_rules([rule], payload)
    elapsed = time.monotonic() - start

    # Expect bounded execution (e.g. < 1s) ...
    assert elapsed < 1.0, f"regex evaluation took {elapsed}s — ReDoS not mitigated"
    # ... and if evaluation could not complete safely, the result must fail CLOSED (deny),
    # not silently allow (empty dict / no permissionDecision).
    if elapsed >= 1.0:
        assert result.get("hookSpecificOutput", {}).get("permissionDecision") == "deny"
```
Expected current behavior: the test fails because `elapsed` grows exponentially with payload length (demonstrating unbounded hang), and there is no fail-closed fallback anywhere in `_regex_match` or `pretooluse.py` — confirming the ReDoS/fail-open path.

**Note on scope/uncertainty:** the actual host-side behavior when a Claude Code hook process times out (whether it truly defaults to "allow") is enforced outside this repository (in Claude Code core, not present in the indexed files), so that specific fail-open mechanism could not be directly verified in-repo — it is inferred from the documented 10s `timeout` in `hooks.json` combined with the complete absence of any in-process timeout/deny fallback in `rule_engine.py`/`pretooluse.py`.

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None

    def _regex_match(self, pattern: str, text: str) -> bool:
        """Check if pattern matches text using regex.

        Args:
            pattern: Regex pattern
            text: Text to match against

        Returns:
            True if pattern matches
        """
        try:
            # Use cached compiled regex (LRU cache with max 128 patterns)
            regex = compile_regex(pattern)
            return bool(regex.search(text))

        except re.error as e:
            print(f"Invalid regex pattern '{pattern}': {e}", file=sys.stderr)
            return False

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules

```

def main():
    """Main entry point for PreToolUse hook."""
    try:
        # Read input from stdin
        input_data = json.load(sys.stdin)

        # Determine event type for filtering
        # For PreToolUse, we use tool_name to determine "bash" vs "file" event
        tool_name = input_data.get('tool_name', '')

        event = None
        if tool_name == 'Bash':
            event = 'bash'
        elif tool_name in ['Edit', 'Write', 'MultiEdit']:
            event = 'file'

        # Load rules
        rules = load_rules(event=event)

        # Evaluate rules
        engine = RuleEngine()
        result = engine.evaluate_rules(rules, input_data)

        # Always output JSON (even if empty)
        print(json.dumps(result), file=sys.stdout)

    except Exception as e:
        # On any error, allow the operation and log
        error_output = {
            "systemMessage": f"Hookify error: {str(e)}"
        }
        print(json.dumps(error_output), file=sys.stdout)

    finally:
        # ALWAYS exit 0 - never block operations due to hook errors
        sys.exit(0)
```
