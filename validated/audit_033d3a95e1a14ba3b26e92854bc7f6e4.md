### Title
Pool refunds declared excess from custody regardless of measured receipt, letting `repay`/`recapitalize` drain supplier funds - (File: contracts/pool/src/ops/repay.rs)

### Summary
The Kyber report's bug class — a contract holding user tokens and paying them out to whoever calls a function — maps onto XOXNO's measured-receipt settlement: `ops::repay::apply` and `ops::recapitalize::apply` refund a "declared excess" (amount over debt / amount over shortfall) out of the pool's real token custody without verifying that the inbound payment ever arrived, and without debiting the `cash` book. An unprivileged caller can therefore withdraw pooled supplier funds by triggering a refund for a payment that never happened.

### Finding Description
`Controller::repay` / `Controller::recapitalize` pull tokens from the payer to the pool and pass a declared amount to the pool ops. Both ops compute an excess (`resolve_repay` takes the full-close branch when `current_debt_ceil` is zero; `recapitalize` refunds the excess over the shortfall) and pay it back via `transfer_out` from pool custody. The refund path does not debit `cash` and does not pass `require_reserves`, so it is funded by whatever custody the pool happens to hold — i.e., other suppliers' deposits. The in-repo test suite demonstrates the primitive directly: `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` repays `custody_before` against a market with zero debt, receives a full refund, and leaves the pool's token balance at 0 while `cash` still reports the funds as present (`assert_unfunded_refund_drained_custody` in contracts/pool/tests/flows.rs). The same gap is documented for `ops::recapitalize::apply`. This is the exact analog of Kyber's `transferAllTokens`: tokens belonging to users sit in the contract and are disbursed to an arbitrary caller with no per-caller entitlement check.

### Impact Explanation
Theft of user funds / protocol insolvency. Any unprivileged address can call `repay` (or `recapitalize`) with a declared amount and receive a refund paid out of supplier custody. Secondarily, since `cash` is not debited, `Cache::require_reserves` keeps admitting exits the pool can no longer fund — the market reports itself solvent and later withdrawals revert inside the SAC transfer (permanent freeze of the residual book until recapitalized).

### Likelihood Explanation
Fully permissionless: `repay` and `recapitalize` are public entrypoints; the only requirement is payer auth, which the attacker controls. No privileged role, oracle manipulation, or timing condition is needed — just declare an amount exceeding the debt/shortfall on a market holding custody.

### Recommendation
Measure the actual inbound receipt (balance delta) before computing any refund, and pay refunds only out of that measured inflow — never out of standing custody. Debit `cash` (or route through `require_reserves`) for any refund funded by the book. The controller already uses `transfer_amount_measured` in `markets::recapitalize`; the same measured amount, not the declared amount, must bound the pool's refund inside `ops::repay::apply` and `ops::recapitalize::apply`.

### Proof of Concept
```rust
// contracts/pool/tests/flows.rs — existing test demonstrating the drain
let t = TestSetup::new();                      // pool holds supplier custody, zero debt
let payer = Address::generate(&t.env);
let custody_before = token.balance(&t.pool);   // e.g. funded by prior supply

let credited = t.client()
    .repay(&payer, &t.ract(0, custody_before)) // declare amount == whole custody
    .get_unchecked(0).actual_amount;

assert_eq!(credited, 0);                        // no debt retired
// assert_unfunded_refund_drained_custody:
assert_eq!(token.balance(&payer), custody_before); // attacker paid in full
assert_eq!(token.balance(&t.pool), 0);             // pool custody emptied
// after.cash == before.cash — book untouched, reserves overstated
```

Note: I verified this behavior via the pool's own test suite (`assert_unfunded_refund_drained_custody`, `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` in contracts/pool/tests/flows.rs) rather than by reading the full bodies of `ops::repay::apply` / `ops::recapitalize::apply`; the exact refund computation lines were not read, so the precise expression that sources the refund from custody is inferred from the documented test comments and assertions.
