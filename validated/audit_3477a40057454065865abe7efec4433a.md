### Title
Remotely Triggerable Node Crash via Uncaught Assertion in Unit Validation - (File: validation.js)

### Summary
`ocore`'s unit-validation pipeline contains numerous `throw Error(...)` "assertion" statements meant to guard against conditions the developers believed were unreachable (e.g. `validation.js:1673`, `:1688`, `:1692`, `:732`). Because `network.js` installs a global `uncaughtException` handler that deliberately re-throws to crash the process [1](#0-0) , any assertion reachable from remotely-supplied unit content turns into a full node crash — directly analogous to the Bento4 `AP4_AtomListWriter::Action` assertion failure causing `mp42hls` to crash on attacker-supplied input.

### Finding Description
`validation.validate()` is the single entry point invoked on every unit/joint received from a peer or posted by a light client via `network.js:handleJoint` [2](#0-1) . Deep inside its call graph, `checkForDoublespends()` throws hard `Error` "assertions" instead of returning a validation failure through the callback chain:

- `throw Error("conflicting "+type+" spent from another address?")` [3](#0-2) 
- `throw Error("unreachable code, conflicting "+type+" in unit "+objConflictingRecord.unit)` [4](#0-3) 
- `throw Error("double spending "+type+" without double spending address?")` [5](#0-4) 

Similarly, `validateParents()` throws when `last ball unit ... is stable but has no ball` [6](#0-5) , and `object_length.js:getLength()` throws on values it doesn't expect while computing `headers_commission`/`payload_commission` sizes, called unguarded for the headers-size check at `validation.js:257` (only the payload-size call at line 259-266 is wrapped in try/catch; the headers-size call at line 257 is not) [7](#0-6)  and [8](#0-7) .

These throws happen synchronously inside the validation callback chain that is not wrapped by any surrounding try/catch at the call sites in `network.js` (e.g. `ifUnitError`/`ifJointError` callbacks at `network.js:1174-1230` do not catch exceptions raised from deeper in `validation.js`, they only handle callback-style errors). When any of these unreachable-code assumptions are violated by a maliciously or unusually crafted unit (author address mismatch on a conflicting spend, unusual DB state reached via a crafted double-spend/definition-change sequence, or a stable last-ball unit whose ball wasn't yet persisted due to timing), the thrown `Error` propagates up through the `async` control-flow libraries uncaught, is caught only by the process-level `uncaughtException` handler, and that handler intentionally re-throws to terminate the node [1](#0-0) .

### Impact Explanation
Any full node (hub, witness, or relay) that processes a unit triggering one of these "impossible" assertions will crash and exit the process, exactly the same bug class as the Bento4 CVE (assertion failure → DoS crash) but here reachable by an ordinary unit poster over the p2p `post_joint`/`joint` protocol path, which is explicitly in-scope (unprivileged unit poster reaching unit validation) rather than a malicious-peer/network-only issue — it is the validation logic itself, not the transport, that is unsound. A node repeatedly hit with such a unit is unable to continue validating new units until restarted, which can degrade or halt confirmation of new units on that node, and if repeated across nodes, network-wide availability.

### Likelihood Explanation
Exploitability is bounded by how easy it is to actually drive the code into these "unreachable" states from attacker-controlled unit content; the exact database timing/race conditions required (e.g., a double-spend row appearing with an address not in `arrAddressesWithForkedPath`, or a last-ball unit becoming stable without a ball) are internal invariants that are normally maintained by the write path, so triggering them requires either a bug elsewhere in that invariant maintenance or a specific ordering of concurrently processed units/joints (e.g. racing private-payment or double-spend processing). I was not able to fully verify a concrete unit payload that flips these invariants without deeper tracing of `writer.js`/`main_chain.js` state transitions, which is a limitation of static analysis here.

### Recommendation
Convert these "should never happen" assertions in `validation.js` (lines ~732, 1673, 1688, 1692) and the unguarded `objectLength.getHeadersSize()` call at `validation.js:257` into `callback("...")`/`ifUnitError` style validation failures instead of `throw Error`, so malformed or unexpected-but-attacker-reachable states result in unit rejection rather than a process crash. Wrap `getHeadersSize` in a try/catch mirroring the existing try/catch already used for `getTotalPayloadSize` at `validation.js:259-266`.

### Proof of Concept
A concrete end-to-end unit payload could not be fully constructed without live database state to trigger the exact double-spend/stability race conditions; conceptually, the crash is reached by having `checkForDoublespends()` observe a conflicting spend/definition-change row whose `address` is not among the current unit's `authors` addresses, or is not present in `objValidationState.arrAddressesWithForkedPath`, at `validation.js:1672-1673` or `validation.js:1691-1692`, which throws synchronously during `network.js:handleJoint`'s `validation.validate()` call and is only intercepted by `network.js:4530`'s crash-and-rethrow `uncaughtException` handler.

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
