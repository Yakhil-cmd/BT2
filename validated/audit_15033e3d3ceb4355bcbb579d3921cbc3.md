### Title
Aquarius LP dust collateral can make an insolvent account unliquidatable by exhausting the LP oracle's minimum-liquidity check - ([File: contracts/controller/src/positions/supply.rs](contracts/controller/src/positions/supply.rs))

### Summary
An unprivileged borrower can add a dust Aquarius LP collateral leg through `supply`, then withdraw enough underlying liquidity from that same Aquarius pool to push its fair pool value below `min_pool_value_wad`. Every later liquidation or bad-debt cleanup prices **all** collateral legs, so the poisoned leg makes `read` return `InsufficientAquariusLiquidity`, causing the whole risk calculation to revert before any debt leg is repaid.

### Finding Description
`process_supply` accepts positive measured deposits and creates a supply position without requiring the collateral's oracle price to be usable at deposit time. It validates entry gates, transfers the tokens to the pool, creates/updates the position, and persists it; the caller can open the leg with an arbitrarily small positive amount. [1](#0-0) 

Once present, `calculate_account_risk_totals` loads every supply and borrow market and evaluates each supply position with `cache.cached_price(&hub_asset.asset)`. A price failure on any collateral leg aborts the entire computation. [2](#0-1) 

For Aquarius LP collateral, `providers::aquarius::read` recomputes the LP fair value from live reserves and total shares, then rejects the quote when `pool_value_wad < lp.min_pool_value_wad`. An LP can reach that condition through an ordinary withdrawal from the venue; the oracle treats it as unavailable rather than assigning a fallback value. [3](#0-2) 

`liquidate` calls `build_liquidation_plan`, which computes account totals before enforcing `health_factor < 1` or planning repayments/seizures. Therefore the unavailable LP price prevents even proof that the account is liquidatable and prevents every repayment path through this entrypoint. [4](#0-3) 

The same whole-portfolio pricing occurs before `execute_bad_debt_cleanup`, so cleanup cannot bypass the poisoned collateral leg and socialization is blocked while the Aquarius price remains unavailable. [5](#0-4) 

The repository already demonstrates the same fail-closed pattern with a stale non-LP feed: a dust supply leg is accepted while its feed is stale, subsequent `liquidate` and `clean_bad_debt` both revert with `PRICE_FEED_STALE`, and withdrawal of that leg is also blocked by the price refresh. [6](#0-5) 

### Impact Explanation
A borrower can delay liquidation after collateral values move against the account, allowing debt to continue accruing and increasing the eventual bad-debt loss to suppliers. If the attacker keeps the Aquarius pool below the configured liquidity threshold, normal liquidation, bad-debt cleanup, and exits requiring full account valuation remain unavailable. This is temporary freezing of liquidation/cleanup and can contribute to protocol insolvency.

### Likelihood Explanation
The sequence is reachable by a single unprivileged address that is both a lending borrower and an LP in the relevant Aquarius pool:

1. Supply ordinary collateral and borrow against it.
2. Supply a dust amount of the Aquarius LP token as an additional collateral leg.
3. Withdraw enough of their LP position, or coordinate value out of the pool through normal venue operations, until `pool_value_wad < min_pool_value_wad`.
4. Remain insolvent or become insolvent; every liquidation attempt aborts while pricing the dust LP leg.

The dust position need not be economically meaningful because the controller does not skip zero-value or tiny collateral when calculating risk.

### Recommendation
Treat unavailable prices for economically immaterial collateral as zero during liquidation planning, or let liquidation exclude/drop collateral legs below a conservative dust threshold before fetching their prices. At minimum, require a fresh valid price for every newly supplied collateral leg and reject deposits whose post-deposit collateral value is below the governance dust threshold. Bad-debt cleanup should likewise isolate an unpriceable dust leg instead of letting it prevent seizure of the remaining positions.

### Proof of Concept
1. Attacker calls `supply(caller=attacker, account_id=0, spoke_id=S, assets=[(hub_asset(H1, USDC), collateral_amount)])` to create an account, then calls `borrow` for `ETH`.
2. Attacker calls `supply(caller=attacker, account_id=A, spoke_id=S, assets=[(hub_asset(H_AMM, AQUARIUS_LP), 1)])`. The contract transfers one LP base unit to the pool and records a nonzero supply position; no successful LP price quote is required for this deposit.
3. The attacker withdraws its underlying liquidity from the Aquarius pool referenced by the configured `AquariusLpSource`, leaving `price_wad * total_shares / 10^share_decimals < min_pool_value_wad`.
4. The attacker manipulates or waits for ordinary market movement so the account is insolvent.
5. Any liquidator calls `liquidate(liquidator, account_id=A, debt_payments=[(hub_asset(H1, ETH), repayment)], seize_mode=Transfer)`. The plan calls `calculate_account_risk_totals`, requests the LP price, receives `InsufficientAquariusLiquidity`, and the transaction reverts.
6. `clean_bad_debt` follows the same account-totals path and also reverts, so the dust LP leg blocks both ordinary liquidation and cleanup until liquidity is restored or governance changes remove the market's usability.

/// Supplies collateral, creating an account when `account_id` is zero.
/// Third parties may only add to existing supply positions. Returns the account id.
pub(crate) fn process_supply(
    env: &Env,
    caller: &Address,
    account_id: u64,
    spoke_id: u32,
    assets: &Vec<HubPayment>,
) -> u64 {
    validation::require_authorized_caller(env, caller);
    let aggregated = payments::aggregate_positive_payments(env, assets);
    let mut cache = Context::new(env);

    let (acct_id, mut account) = account::load_or_create_account(
        env,
        caller,
        account_id,
        spoke_id,
        PositionMode::Normal,
        account::AccountGuard::Supply,
        &mut cache,
    );

    require_third_party_existing_supply(env, account_id, acct_id, caller, &account, &aggregated);

    process_deposit(env, caller, &mut account, &aggregated, &mut cache);

    finalize_position_flow(
        env,
        acct_id,
        &account,
        &mut cache,
        PositionSides::Supply,
        false,
    );
    acct_id
}
