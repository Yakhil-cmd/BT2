### Title
Webhook signature verified against `repository.owner.login`'s org secret while stack mutation uses `repository.full_name`'s org, allowing cross-org forged writes - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` authenticates the raw webhook body against the GitHub App keyed by `params.dig('repository','owner','login')`, but `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler#repository` (and the base `Handler#stacks`) independently resolve the mutated `Repository`/`Stack` from `params.repository.full_name` read from the same attacker-controlled JSON body. Because these two fields are never checked for consistency, an attacker who owns a GitHub org/app registered in `Shipit.github_organizations` can sign a payload with their own `webhook_secret` while setting `repository.full_name` to a victim org's repository, causing a `ReviewStack` to be created/mutated under the victim's repository without ever possessing the victim's secret.

### Finding Description
The broken binding is: `organization_that_verified_signature == organization_owning_mutated_repository`, i.e. `Shipit.github(organization: params.dig('repository','owner','login'))` must equal the org derived from `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. This does not hold.

Code path:
1. `before_action :check_if_ping, :drop_unhandled_event, :verify_signature` runs before `create` [4](#0-3) .
2. `verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)` to obtain the app, then verifies the raw body signature against that app's secret [1](#0-0) .
3. On success, `create` re-parses the same raw body and dispatches to handlers for the event, e.g. `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` for `pull_request` events, invoking `OpenedHandler` [5](#0-4) .
4. `OpenedHandler#repository` resolves the target repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, entirely independent of `repository.owner.login` used for signature selection [3](#0-2) .
5. `process` then creates/updates a `ReviewStack` scoped to that resolved repository via `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` [6](#0-5) .

Attacker request: register/control a GitHub App organization `evil-org` in `Shipit.github_organizations` (this is attacker's own org — no victim secret needed), then `POST /webhooks` with `X-Github-Event: pull_request`, `X-Hub-Signature` computed with `evil-org`'s `webhook_secret` over a body where `repository.owner.login = "evil-org"` but `repository.full_name = "shopify/shipit-engine"`. `verify_signature` picks `evil-org`'s app and validates successfully because the signature was computed with that same secret over that same body — HMAC validity is independent of the JSON *content* of `repository.full_name`. The `OpenedHandler` then mutates the `shopify/shipit-engine` repository's review stacks.

Existing guards do not catch this: `drop_unhandled_event` only checks the event type is handled [7](#0-6) ; `GithubOrganizationUnknown` only fires if `repository_owner` itself isn't a configured org, which is not the case here since `evil-org` is configured [8](#0-7) ; `ExplicitParameters` schema only validates types/presence, not cross-field consistency [9](#0-8) .

### Impact Explanation
An attacker who registers as a legitimate (but unprivileged w.r.t. the victim) GitHub App organization in `Shipit.github_organizations` can forge pull_request (and other) webhook events that create, update, or close `ReviewStack`s under any *other* configured organization's repository, without ever holding that other organization's `webhook_secret`. This is a cross-repository/cross-tenant write matching the "payload for one repository mutating another's stack" Critical category. It's repeatable against any repository name resolvable by `Shipit::Repository.from_github_repo_name`, for any handler that derives its target repository from `params.repository.full_name`/`payload.dig('repository','full_name')` rather than from the org used for signature verification (this affects the base `Handler#stacks` helper too, used broadly).

### Likelihood Explanation
Requires: (a) at least two organizations configured in `Shipit.github_organizations` with distinct `webhook_secret`s — a normal multi-tenant Shipit deployment; (b) attacker controls or registers one such org's GitHub App (feasible if Shipit allows self-service org registration, or if attacker is a legitimate but low-trust org member elsewhere in the same Shipit instance). Attacker cost is a single crafted HTTP POST with a correctly computed HMAC over their own secret — no need to know the victim's secret or credentials. This is fully repeatable and scriptable.

### Recommendation
After resolving the target `Repository`/`Stack` in each handler (or centrally in `Handler#initialize`/`stacks`), verify that the repository's owning organization matches the organization whose secret validated the signature (i.e., compare `repository.owner`/organization derived from `full_name` against `repository_owner` used in `verify_signature`), rejecting the webhook if they differ. Alternatively, pass the verified `repository_owner` into the handler and require handlers to resolve repositories scoped to that owner only.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb`-style, no live GitHub):
1. Configure two orgs in `Shipit.github_organizations`/`Shipit.github_organizations=` fixture: `evil-org` with `webhook_secret: 'evilsecret'`, and `shopify` with `webhook_secret: 'shopifysecret'` (matching existing fixture repo `shopify/shipit-engine`).
2. Build `payload = { action: 'opened', number: 1, pull_request: {...valid pull_request fields..., head: {...}, user: {login: 'attacker'}, assignees: [], labels: []}, repository: { full_name: 'shopify/shipit-engine', owner: { login: 'evil-org' } }, sender: { login: 'attacker' } }.to_json`.
3. Compute `signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', 'evilsecret', payload)`.
4. `assert_difference -> { Shipit::ReviewStack.where(repository: shipify_repo).count }, 1 do post :create, body: payload, as: :json, headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => signature } end` — asserting equality `verified_org ('evil-org') != mutated_repository_org ('shopify')` while the write still succeeds, and `assert_response :ok`.
5. Contrast with a control test where `repository.full_name` belongs to `evil-org`'s own repository, confirming intended behavior only for same-org payloads.
