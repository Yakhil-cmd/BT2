### Title
Stack-scoped API token can read CI/build status of any stack via CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Api::CCMenuController#stack` resolves the target stack from the global `Stack` table via `Stack.from_param!(params[:stack_id])` instead of the `stacks` helper that every other API controller uses to enforce `ApiClient#stack_id` scoping, breaking the binding "stack a token authorizes == stack a controller touches".

### Finding Description
`Api::BaseController` establishes the authorization invariant that a stack-scoped `ApiClient` can only touch its own stack, via `stacks`/`stack` in `app/controllers/shipit/api/base_controller.rb:74-80`. `CCMenuController` overrides `stack` (`app/controllers/shipit/api/ccmenu_controller.rb:29-31`) to bypass this scoping and look up any stack by param, relying solely on `require_permission :read, :stack`, which `ApiClient#check_permissions!` (`app/models/shipit/api_client.rb:38-45`) implements purely as a string-membership check on `permissions`, with no `stack_id` comparison.

### Impact Explanation
An attacker holding a legitimately-issued, stack-scoped `read:stack` token (e.g., a CCMenu URL token generated for one stack, per `app/controllers/shipit/ccmenu_url_controller.rb:15-18`) can query `/api/1/stacks/<other_stack_id>/ccmenu.xml?token=<their_token>` and read another stack's build/deploy status metadata, an authorization-scope escalation across stacks.

### Likelihood Explanation
Any holder of a CCMenu URL (which are often shared/embedded in CI dashboards, IRC bots, etc.) can trivially enumerate/guess other `stack_id`/`repo_name` params, since no server-side check compares the token's `stack_id` to the requested stack.

### Recommendation
Change `CCMenuController#stack` to resolve through the scoped `stacks` collection (`stacks.from_param!(params[:stack_id])`) as `StacksController` and other API controllers do, so a stack-scoped token cannot address stacks outside its `stack_id`.

### Proof of Concept
1. Create/obtain a CCMenu token scoped to Stack A via `GET /stack_a/ccmenu_url` (or any stack-scoped `read:stack` `ApiClient`).
2. Call `GET /api/1/stacks/<stack_b_id>/ccmenu.xml?token=<token_scoped_to_stack_a>`.
3. Observe the response renders Stack B's project/build status even though the token was only ever authorized for Stack A, because `CCMenuController#stack` does not filter through `current_api_client.stack_id`.
