### Title
Amend-delta review marks unreviewed pre-amend content as reviewed, letting push-sweep skip it - (File: plugins/security-guidance/hooks/security_reminder_hook.py)

### Summary
`_resolve_amend_pre_sha` enables a delta-only review (`pre_amend_sha..post_amend_sha`) for `git commit --amend`, based on the undocumented/unenforced assumption that the pre-amend commit was already reviewed. The code never verifies this against `.git/sg-reviewed-shas`, and the amend's resulting SHA is unconditionally recorded as "reviewed," letting `push-sweep` skip re-diffing the original, never-reviewed content forever.

### Finding Description
`handle_commit_review_posttooluse` decides to take the amend-delta path purely from reflog shape checks in `_resolve_amend_pre_sha` (HEAD@{0} is `commit (amend)`, HEAD@{1} isn't) [1](#0-0) , then diffs only `pre_amend_sha..sha` instead of the full commit [2](#0-1) . Regardless of whether that delta review ran, is empty, or whether the original pre-amend commit `C0` was ever actually reviewed, the resulting post-amend SHA is unconditionally recorded into the persistent `.git/sg-reviewed-shas` store used by push-sweep dedup [3](#0-2) .

If `C0` was never reviewed — e.g. it hit the hourly rate limit (`skip_reason=23`, which exits *before* any `_append_reviewed_shas` call) [4](#0-3) , or `commit_succeeded` detection/reflog fallback missed it, or the LLM review was transiently disabled/unreachable — then amending it (even with a trivial, message-only or single-line change) causes the *entire* pre-amend content to be silently marked "reviewed" via the post-amend SHA. `push-sweep`'s `_compute_push_sweep_base` treats any SHA present in the reviewed set as a fully-covered prefix and advances the diff base past it [5](#0-4) , so `git push` never re-diffs or re-reviews `C0`'s dangerous content [6](#0-5) . No maintainer/admin privilege or leaked credentials are needed — an ordinary Claude Code session that hits the rate limit or a transient review-skip condition and then amends is sufficient.

### Impact Explanation
This breaks the stated invariant that dangerous edits/commands must remain reviewable and blockable across retries, amends, and pushes. A commit containing a dangerous change (e.g., a backdoor, secret exfiltration, or destructive command introduced through prompt-injected repo content) can permanently escape both the per-commit LLM review and the push-sweep net-diff review, with zero warning/rewake ever surfaced to the user — a logic-level bypass of the plugin's security-guidance guard rather than a crash or credential leak.

### Likelihood Explanation
The precondition (an unreviewed original commit followed by a trivial amend) is reachable through normal, unprivileged operation: the hourly commit-review rate limit (`MAX_COMMIT_REVIEWS_PER_HOUR=20`, default) is easily hit in longer sessions, and transient `ensure_anthropic_reachable()` failures or output-suppressed commits (`-q`, piped) that also miss the 120s reflog fallback window are realistic in automation-heavy workflows. Once the precondition occurs, the trigger (`git commit --amend`) is a completely ordinary follow-up action, so the bypass is repeatable and not reliant on rare timing races.

### Recommendation
Before taking the amend-delta path (or before calling `_append_reviewed_shas` with the post-amend SHA), verify that `pre_amend_sha` is itself present in `.git/sg-reviewed-shas` (or the equivalent per-session review record). If it is not, fall back to a full `git show` review of the entire post-amend commit instead of the delta, and only then record the resulting SHA as reviewed.

```python
def _resolve_amend_pre_sha(repo_root, expected_post_sha=None):
    """For a `git commit --amend` we just ran, return the pre-amend SHA via
    reflog, or None if it can't be safely determined.

    expected_post_sha: the post-amend SHA the caller parsed from bash stdout
    (or reflog). If provided, HEAD@{0} of `repo_root` must match it (prefix
    compare — bash stdout SHAs are abbreviated, reflog %H is 40 chars) before
    we trust the reflog-derived pre-amend SHA. This guards against the
    cross-repo case (`cd ../other && git commit --amend && cd -`) where
    `repo_root` happens to have its own recent amend that's unrelated to
    the bash command we're reviewing.

    We require HEAD@{0}'s reflog subject to start with `commit (amend)` —
    otherwise our `--amend` regex matched something that didn't actually
    perform an amend (e.g., `git commit --amend --dry-run`, aliased commands,
    aborted amends), and HEAD@{1} would be the wrong commit. Also requires
    HEAD@{1} to NOT itself be an amend, since back-to-back amends would have
    HEAD@{1} as the previous-amend's post state — the original commit we
    want to compare against is then HEAD@{2}, but at that point we're
    reaching and fall back to a full review.

    Bytes + decode('utf-8', errors='replace'): reflog subjects embed commit
    subjects, which git stores as raw bytes (commit messages may be latin-1
    / cp1252 / etc.). text=True would raise UnicodeDecodeError (a
    ValueError, not OSError) on non-UTF8 bytes and crash the hook.
    """
    if not repo_root:
        return None
    try:
        r = subprocess.run(
            [*GIT_CMD, "log", "-g", "-2", "--format=%H|%gs", "HEAD"],
            cwd=repo_root, capture_output=True, timeout=5,
        )
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
    if r.returncode != 0:
        return None
    stdout_text = r.stdout.decode("utf-8", errors="replace")
    lines = [ln for ln in stdout_text.splitlines() if "|" in ln]
    if len(lines) < 2:
        return None
    head0_sha, _, head0_subj = lines[0].partition("|")
    head1_sha, _, head1_subj = lines[1].partition("|")
    if not head0_subj.startswith("commit (amend)"):
        return None
    if head1_subj.startswith("commit (amend)"):
        return None
    # Cross-repo guard: the post-amend SHA the caller is about to review must
    # match HEAD@{0} of repo_root. Otherwise the bash command was likely run
    # in a different repo than repo_root, and the reflog we just read is
    # unrelated. Prefix-compare: expected_post_sha is typically the 7-char
    # abbreviated SHA captured from bash stdout by _COMMIT_SHA_RE (git's
    # default core.abbrev floor), while head0_sha is the full 40-char %H —
    # strict equality would always fail and silently disable the delta path.
    if expected_post_sha and not head0_sha.startswith(expected_post_sha):
        return None
    return head1_sha or None
```

```python
def _compute_push_sweep_base(prev_upstream, push_range, reviewed):
    """Advance the diff base past the contiguous reviewed prefix.

    Spec: review `git diff B..HEAD` where `B` is the newest commit such that
    `prev_upstream..B` is entirely in `reviewed`. Returns (B, unreviewed_tail).
    `B == None` means the whole range is reviewed (caller should skip).
    `push_range` must be oldest→newest.

    Examples (✓=reviewed, ✗=not):
      [✓1, ✗2, ✓3]  → B=1, tail=[2,3]   (cannot trim suffix; Read is at HEAD)
      [✓1, ✓2, ✓3]  → B=None            (all reviewed → skip)
      [✗1, ✓2, ✗3]  → B=prev_upstream, tail=[1,2,3]
      []            → B=None
    """
    i = 0
    while i < len(push_range) and push_range[i] in reviewed:
        i += 1
    if i == len(push_range):
        return None, []
    base = push_range[i - 1] if i > 0 else prev_upstream
    return base, push_range[i:]
```
