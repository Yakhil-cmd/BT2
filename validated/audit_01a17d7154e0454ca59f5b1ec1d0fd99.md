### Title
API token scoped to a single stack can read CCMenu status of any stack - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::CCMenuController` overrides the stack-lookup helper inherited from `BaseController` with an unscoped lookup, so an `ApiClient` token that is authorized (scoped) for exactly one stack can be used to read the CI/deploy status of *any* stack in the installation.

### Finding Description
`Shipit::Api::BaseController` restricts which stacks an `ApiClient` may act on via the `stacks`/`stack` helpers: if the client has a `stack_id`, only that stack is in scope. [1](#0-0) 

`ApiClient#check_permissions!` only checks that the *permission name* (e.g. `read:stack`) is present in the client's permission list; it never checks which specific stack is being accessed. [2](#0-1) 

So the only place that enforces "this token may only touch its own stack" is the scoped `stacks`/`stack` method in `BaseController`. `CCMenuController`, however, redefines `stack` to bypass that scoping entirely, resolving the stack directly from the URL param against the full `Stack` table: [3](#0-2) 

The controller still declares `require_permission :read, :stack`, which only proves the token *has* the `read:stack` permission somewhere — it does not prove the token is scoped to the stack referenced in `params[:stack_id]`. As a result the equality the system is supposed to maintain, "the stack a token authorizes == the stack the action touches," is broken specifically for this controller: the token authorizes only one stack (per `ApiClient#stack_id`) but the action can touch any stack (via `Stack.from_param!(params[:stack_id])`).

The test fixture `here_come_the_walrus` demonstrates the intended scoping (an `ApiClient` bound to a single stack via `stack: shipit`): [4](#0-3) 
and other controllers correctly honor that scoping, e.g. the stacks-index test confirms a scoped client only sees its one stack: [5](#0-4) 
but no equivalent test exists for `CCMenuController`, and its own `stack` override makes such scoping impossible.

### Impact Explanation
Using a token that was deliberately scoped to a single, presumably less-sensitive stack, an attacker can enumerate/read the deploy/build status (`lastBuildStatus`, `lastBuildLabel`, lock state, activity) of every other stack managed by the Shipit instance, including production stacks it was never granted access to. This is an unauthenticated-for-that-resource read of stack state, matching the High-severity bucket "escalation into `Shipit.github_teams` authorization ... unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
Any holder of a legitimately-issued, stack-scoped `ApiClient` token (e.g., a CI/CD integration or CCMenu client meant to monitor a single stack, as created by `CCMenuUrlController`) can trivially exploit this by changing the `stack_id` path segment on the existing CCMenu endpoint — no additional privileges, secrets, or social engineering required.

### Recommendation
Have `CCMenuController#stack` use the scoped `stacks.from_param!(params[:stack_id])` helper (as `BaseController#stack` does) instead of the unscoped `Stack.from_param!`, so `check_permissions!`'s implicit assumption of stack scoping actually holds for this controller.

### Proof of Concept
1. Obtain (or be issued) a stack-scoped `ApiClient` token analogous to fixture `here_come_the_walrus` (`stack: shipit`, `permissions: [read:stack]`), e.g. via `CCMenuUrlController#fetch`, which itself mints a `read:stack` client for one specific stack: [6](#0-5) 
2. Call `GET /api/stacks/:other_owner/:other_repo/:other_env/ccmenu.xml?token=<that_token>` where `other_owner/other_repo/other_env` is a *different* stack than the one the token is scoped to.
3. `CCMenuController#stack` resolves it via `Stack.from_param!(params[:stack_id])` — unscoped — so `require_permission :read, :stack` passes (the token has `read:stack`) and the response returns that other stack's CCMenu status, even though `current_api_client.stack_id` never matches it.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
