**Rationale:** The leader schedule code already fully addresses the described concern. `stake_weighted_slot_leaders` calls `sort_stakes` before doing any weighted sampling, and `sort_stakes` sorts by `(stake, vote_address)` with an explicit total order — ties in stake are broken deterministically by `vote_address` pubkey comparison, not by HashMap iteration order. [1](#0-0) 

Because `sort_unstable_by` is given a comparator that forms a strict total order over `(stake, vote_address)` pairs, and vote account pubkeys (the map keys) are unique, the sorted result is invariant to the initial iteration order of the input `Vec`/`HashMap`. `LeaderSchedule::new` collects `vote_accounts_map.iter()` into a `Vec` and immediately passes it through this deterministic sort before any randomized sampling (`WeightedU64Index` + `ChaChaRng` seeded only by `epoch`), so the resulting schedule is fully deterministic across nodes regardless of `VoteAccountsHashMap` insertion/iteration order. [2](#0-1) 

This is explicitly tested: `test_sort_stakes_with_equal_stakes` confirms tie-break behavior for equal-stake entries, and `test_leader_schedule_basic` confirms two independent `LeaderSchedule::new` calls over the same map produce an identical schedule. [3](#0-2) [4](#0-3) 

Additionally, the VAT (Vote Account Truncation) filtering logic explicitly handles stake ties at the truncation boundary by removing all accounts sharing the cutoff stake value (to prevent "grinding" via pubkey selection), rather than relying on arbitrary map ordering. [5](#0-4) 

Since the tie-break is a pure function of `(stake, vote_address)` — both of which are identical on every honest node computing the same epoch's schedule — an attacker crafting many equal-stake accounts cannot induce divergent leader schedules across nodes. There is no non-deterministic HashMap iteration path feeding into the final ordering used for sampling.

fn sort_stakes(stakes: &mut Vec<(SlotLeader, u64)>) {
    // Sort first by stake. If stakes are the same, sort by vote address pubkey
    // to ensure a deterministic result.
    // Note: Use unstable sort, because we dedup right after to remove the equal
    // elements.
    stakes.sort_unstable_by(|(l_leader, l_stake), (r_leader, r_stake)| {
        if r_stake == l_stake {
            r_leader.vote_address.cmp(&l_leader.vote_address)
        } else {
            r_stake.cmp(l_stake)
        }
    });

    // Now that it's sorted, we can do an O(n) dedup.
    stakes.dedup_by(|(l_leader, l_stake), (r_leader, r_stake)| {
        r_stake == l_stake && r_leader.vote_address == l_leader.vote_address
    });
}

    // 1. Filter out any vote accounts without BLS pubkey
    // 2. Given minimum_vote_account_balance, filter out any vote account
    //    without required balance
    // 3. If we have more than max_vote_accounts vote accounts after above
    //    filtering, sort by stake and truncate
    // 4. If any vote account in the resulting list has the same stake as any
    //    truncated vote account, just remove this vote account as well (A and
    //    B have the same stake amount, it's unfair to keep A in and kick B out
    //    just because of Pubkey difference, because that can be grinded)
    // 5. If we end up with an empty list (can happen if everyone in the world
    //    has the same stake, happens in tests, doesn't happen in real world),
    //    log a warning
    pub fn clone_and_filter_for_vat(
        &self,
        max_vote_accounts: usize,
        minimum_vote_account_balance: u64,
    ) -> VoteAccounts {
        assert!(max_vote_accounts > 0, "max_vote_accounts must be > 0");
        let capacity = max_vote_accounts.min(self.vote_accounts.len());
        let mut entries_to_sort: Vec<(&Pubkey, &VoteAccount, u64)> = Vec::with_capacity(capacity);
        for (pubkey, (stake, vote_account)) in self.vote_accounts.iter() {
            let has_bls = vote_account
                .vote_state_view()
                .bls_pubkey_compressed()
                .is_some();
            let has_stake = *stake != 0u64;
            let has_balance = vote_account.lamports() >= minimum_vote_account_balance;

            if !has_bls || !has_stake || !has_balance {
                continue;
            }
            entries_to_sort.push((pubkey, vote_account, *stake));
        }

        let valid_len = entries_to_sort.len();
        if entries_to_sort.len() > max_vote_accounts {
            // Find the cutoff stake using partial sort (more efficient than full sort).
            let (_, cutoff_entry, _) =
                entries_to_sort.select_nth_unstable_by(max_vote_accounts, |a, b| b.2.cmp(&a.2));
            let floor_stake = cutoff_entry.2;

            // the first truncated one.
            entries_to_sort.retain(|(_, _, stake)| *stake > floor_stake);
