### Title
`AccountKeyFail` in `RoleTransaction` Slot Bypassed via Cross-Type `CheckReplacable` — (`blockchain/types/accountkey/account_key.go`)

---

### Summary

`CheckReplacable` only invokes `oldKey.CheckUpdatable()` when the old and new key share the same type. When types differ, it falls through to `newKey.CheckInstallable()` alone. This means `AccountKeyFail.CheckUpdatable()` — which unconditionally returns `ErrAccountKeyFailNotUpdatable` — is never consulted when the replacement key is a different type (e.g., `AccountKeyPublic`). A holder of the `RoleAccountUpdate` key can therefore replace an `AccountKeyFail` in the `RoleTransaction` slot with a functional signing key, permanently unlocking an account that was intended to be transaction-locked.

---

### Finding Description

The invariant is that `AccountKeyFail` in any slot is permanently non-updatable. `AccountKeyFail.CheckUpdatable` enforces this: [1](#0-0) 

`CheckReplacable` is the gating function for slot-level replacement inside `AccountKeyRoleBased.CheckUpdatable`: [2](#0-1) 

The flaw: when `oldKey.Type() != newKey.Type()`, `CheckReplacable` skips `oldKey.CheckUpdatable()` entirely and only calls `newKey.CheckInstallable()`. For `AccountKeyPublic` with a valid curve point, `CheckInstallable` returns `nil`: [3](#0-2) 

This is reached from `AccountKeyRoleBased.CheckUpdatable` in the `default` branch for each slot: [4](#0-3) 

The full call chain for a `TxTypeAccountUpdate` transaction:

1. `TxInternalDataAccountUpdate.Validate` calls `CheckReplacable(oldRoleBasedKey, newRoleBasedKey, blockNum)` — same type, so calls `oldRoleBasedKey.CheckUpdatable(newRoleBasedKey, blockNum)`. [5](#0-4) 

2. `AccountKeyRoleBased.CheckUpdatable` iterates slots; for slot 0 (`RoleTransaction`), old=`AccountKeyFail`, new=`AccountKeyPublic` → calls `CheckReplacable(AccountKeyFail, AccountKeyPublic, blockNum)`. [6](#0-5) 

3. `CheckReplacable` sees different types → calls `AccountKeyPublic.CheckInstallable()` → returns `nil` → slot replacement is approved. [7](#0-6) 

4. `Execute` writes the new key to state, overwriting `AccountKeyFail` with `AccountKeyPublic`. [8](#0-7) 

---

### Impact Explanation

An account configured as `AccountKeyRoleBased[AccountKeyFail, AccountKeyPublic(update), AccountKeyPublic(fee)]` is intended to be permanently unable to sign value-transfer transactions. After exploitation, the `RoleTransaction` slot holds a live `AccountKeyPublic`, and the attacker can sign and submit `TxTypeValueTransfer` transactions to drain KAIA from the account. This constitutes unauthorized KAIA withdrawal — a direct match to the required impact gate.

---

### Likelihood Explanation

The precondition requires an account to have `AccountKeyFail` in the `RoleTransaction` slot of a role-based key, with a separate `RoleAccountUpdate` key held by a different party. This is a deliberate security configuration (e.g., a smart-contract-like EOA where transaction signing is intentionally disabled). The attacker only needs to hold the `RoleAccountUpdate` key and submit a single standard `TxTypeAccountUpdate` via public RPC — no privileged access, no validator collusion, no cryptographic break.

---

### Recommendation

`CheckReplacable` must consult the old key's replaceability regardless of type mismatch. The fix is to add an explicit guard for `AccountKeyFail` (or more generally, introduce a `IsReplacable() bool` method on `AccountKey` that `AccountKeyFail` returns `false` for), and check it before falling through to `newKey.CheckInstallable()`:

```go
func CheckReplacable(oldKey AccountKey, newKey AccountKey, currentBlockNumber uint64) error {
    if oldKey.Type() == newKey.Type() {
        return oldKey.CheckUpdatable(newKey, currentBlockNumber)
    }
    // Must still verify the old key permits replacement, even across types.
    if oldKey.Type() == AccountKeyTypeFail {
        return kerrors.ErrAccountKeyFailNotUpdatable
    }
    return newKey.CheckInstallable(currentBlockNumber)
}
```

	if oldKey.Type() == newKey.Type() {

	}
	return newKey.CheckInstallable(currentBlockNumber)
}
