### Title
Security review bypass via `git commit --amend` shifting the Stop-hook baseline — dangerous change dropped from review set - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the Stop-hook review set as the intersection of `dirty_now` (git-status-derived) and `changed_since` (content diff vs the turn's stash baseline). `dirty_now` only re-includes committed-this-turn files when `head_at_capture` is a linear ancestor of the current `HEAD`. A normal `git commit --amend` on the commit that was `HEAD` at `head_at_capture` breaks that ancestor relationship even though the file content still differs from `baseline_sha`, so the intersection silently drops the file from review while `consume_stop_state`/`compute_v2_review_set` report a "clean" or reduced review set.

### Finding Description
`handle_stop_hook` calls `consume_stop_state(session_id)` to snapshot `baseline_sha`/`head_at_capture`/`touched_paths` and then `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)` [1](#0-0) [2](#0-1) .

Inside `compute_v2_review_set`, `dirty_now` starts from `git status --porcelain` (uncommitted files) and is unioned with commit-range changes **only if** `head_at_capture` is an ancestor of the current `HEAD`: [3](#0-2) 

`review_set` is then the intersection of `dirty_now` and `changed_since` (content diff of the working tree against `baseline_sha`, the stash-created snapshot from turn start): [4](#0-3) 

`_is_ancestor` uses `git merge-base --is-ancestor` [5](#0-4) , which returns `False` for a commit that was **amended** — `git commit --amend` produces a new commit object with the *same parent* as the original but is not itself a descendant of the original commit. If the commit amended is the exact commit captured as `head_at_capture` (i.e., the pre-existing HEAD at turn start, not a commit made during this turn), then:
- The working tree is clean after the amend, so `dirty_now` from `git status` is empty for the touched file.
- `_is_ancestor(head_at_capture, current_head)` is `False`, so the commit-range union that would normally re-add the changed file to `dirty_now` never executes.
- `changed_since` (diff against `baseline_sha`, computed independently via `_git_name_only`) still correctly reports the file as changed, since it's a pure content diff.
- `review_set = dirty_now ∩ changed_since` therefore excludes the file even though its content genuinely differs from the turn's baseline.

`handle_stop_hook` treats an empty/reduced `review_paths` as "no changes since baseline" and skips the LLM security review entirely [6](#0-5) , or reviews a set missing the dangerous file. No other check (allowlist, workspace guard, session binding) validates that `dirty_now` and `changed_since` agree before intersecting; the code comment even flags the intersection as risky for the "changed_since is None" case but not for this "dirty_now missing an entry" case.

### Impact Explanation
This breaks the stated invariant that the review set must stay bound to the repo's actual touched paths: a file whose content was modified during the turn (via amend of the pre-turn HEAD commit) is silently excluded from the LLM security review pipeline. Any vulnerability, backdoor, or malicious file write introduced this way is committed to the repo without ever being surfaced to the user via the Stop-hook's `exit(2)` guidance, defeating the plugin's entire purpose of catching unauthorized/dangerous file writes before they land unreviewed.

### Likelihood Explanation
Requires only ordinary git usage already available to any session driving Claude Code in a cloned repo: (1) a pre-existing commit exists before the turn (near-universal in real repos), (2) during the turn the dangerous change is introduced via `git commit --amend --no-edit` on that exact commit rather than a fresh commit, and (3) no other uncommitted changes remain in the working tree. `--amend` is an extremely common, ordinary git operation (fixing a forgotten file/message), making this easy to trigger unintentionally or deliberately via prompt injection steering Claude's git usage.

### Recommendation
Do not gate the commit-range union on strict linear ancestry alone. Either (a) always union `dirty_now` with `_git_name_only(repo, baseline_sha)`-derived changed files regardless of ancestry (effectively making `review_set = changed_since` when `dirty_now` computation via status/ancestry is inconclusive), or (b) detect history rewrites (amend/rebase) by comparing `head_at_capture` against the merge-base of itself and current `HEAD`, and when they diverge, fall back to treating `changed_since` (content-vs-baseline diff) as authoritative rather than intersecting with the ancestry-gated `dirty_now`.

### Proof of Concept
Integration test in the Stop-hook test suite:
1. Init a git repo, create `danger.py` with benign content, commit (`H0`).
2. Simulate UPS: call `capture_git_baseline(cwd)` → `baseline_sha`; record `head_at_capture = H0`.
3. Modify `danger.py` to add a dangerous pattern (e.g., `os.system(user_input)`), `git add -A`, then `git commit --amend --no-edit` (amending `H0`, producing `H0'`).
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture=H0, untracked_at_baseline={})`.
5. Assert `review_paths` **should** contain `danger.py` (per the security invariant) — the PoC demonstrates it does **not**, because `_is_ancestor(H0, H0')` is `False` while `changed_since` correctly contains `danger.py`, so the intersection drops it.
6. Confirm via `handle_stop_hook` end-to-end that `_skip(9, ...)` ("empty review set") fires and no `sys.exit(2)` guidance is emitted despite the dangerous diff being present in the repo.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
