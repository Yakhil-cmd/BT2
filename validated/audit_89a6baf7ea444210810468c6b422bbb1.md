### Title
Cross-organization webhook confusion allows unauthorized `ReviewStack#archive!` on a victim repository - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb)

### Summary
`WebhooksController#verify_signature` authenticates a webhook payload against the GitHub App configured for `params.dig('repository','owner','login')`, but `ClosedHandler` resolves the repository/stack to mutate using the independent field `params.repository.full_name`. Because these two JSON fields are attacker-controlled and never cross-validated, an attacker can verify a payload under an organization they control (one with no `webhook_secret` configured) while naming a victim org/repo in `full_name`, causing the victim's `ReviewStack` to be archived.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`organization_that_verified_signature (params.repository.owner.login)` == `organization_owning_the_mutated_stack (owner segment of params.repository.full_name)`.

Code path:
- `WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) computes `repository_owner` via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` (line 59-62) and looks up `Shipit.github(organization: repository_owner)`. `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) returns `true` unconditionally when that organization's `webhook_secret` is blank/nil — a documented, supported configuration state (see `test/dummy/config/secrets.yml:13`, `config/secrets.development.shopify.yml:9,18`).
- Once verification passes, `WebhooksController#create` (app/controllers/shipit/webhooks_controller.rb:10-15) dispatches the *entire raw JSON body* to `ClosedHandler#process`.
- `ClosedHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb:49-53) resolves the target repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely separate JSON field from `repository.owner.login` used in step 1.
- `ClosedHandler#review_stack` (lines 55-59) then scopes to `repository.review_stacks`, and `#process` (lines 41-45) calls `review_stack.archive!` unconditionally once `action == "closed"`.

Nothing in the `params do ... end` ExplicitParameters schema (lines 8-39) requires or validates `repository.owner.login`, nor cross-checks it against `repository.full_name`. The two fields are simply independent, attacker-supplied strings in the same POST body.

Exploit: attacker crafts `POST /webhooks` with header `X-Github-Event: pull_request`, body:
```json
{
  "action": "closed",
  "number": <victim_pr_number>,
  "pull_request": { ...attacker-fillable fields... },
  "repository": { "owner": {"login": "attacker-controlled-org-with-no-secret"}, "full_name": "victim-org/victim-repo" },
  "sender": {"login": "attacker"}
}
```
`repository_owner` resolves to `attacker-controlled-org-with-no-secret`, whose `Shipit.github(...)` app has no `webhook_secret`, so `verify_webhook_signature` returns `true` trivially — no signature or secret is ever needed. `ClosedHandler` then resolves `victim-org/victim-repo`'s `Repository`, finds the review stack for `number`, and calls `.archive!`, mutating a victim's state without any credential tied to that victim org.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type is handled; `verify_signature` authenticates the *organization named in a different field* than the one acted upon; the `ExplicitParameters` schema never requires or compares `repository.owner.login`; there is no model validation or controller check tying `repository_owner` to `params.repository.full_name`.

### Impact Explanation
An unauthenticated (with respect to the victim org) attacker can force archival of any victim organization's active `ReviewStack` for a known PR number, using only credentials/configuration of an unrelated (possibly attacker-owned or misconfigured) GitHub org registered in the Shipit instance with no webhook secret. This is a state-mutating write on a repository/review-stack that never validated the attacker's payload — matching "a payload for one repository mutating another's stack" (Critical). It is repeatable against any repository/PR combination the attacker can guess or observe (PR numbers are low-entropy and often public), and the blast radius spans every tenant/org hosted on the same Shipit instance that has any org configured without a webhook secret.

### Likelihood Explanation
Requires: (1) the Shipit instance hosts multiple GitHub orgs (`Shipit.github` supports multi-org config, per docs/setup.md:182-209), (2) at least one configured org has no `webhook_secret` set (a state explicitly present in this repo's own dev/test configs, e.g. `test/dummy/config/secrets.yml:13`, `config/secrets.development.shopify.yml`), and (3) the victim repo has an active review stack for a PR number the attacker knows. No GitHub App private key, session, or API token is required. Attacker cost is a single crafted HTTP POST with no auth headers besides an (unchecked) `X-Hub-Signature`. Fully repeatable and scriptable.

### Recommendation
Bind signature verification to the same repository the handler will act on: derive `repository_owner` and the acted-upon repository from a single, verified source, and reject requests where `params.dig('repository','full_name')`'s owner segment does not match `params.dig('repository','owner','login')`/`params.dig('organization','login')` used for signature verification. Alternatively, require `webhook_secret` to be present for every configured org (fail closed instead of `return true unless webhook_secret`), and additionally verify that the resolved `Repository#owner` matches the organization that authenticated the request before calling `review_stack.archive!` (or any other mutating action) in every PullRequest handler.

### Proof of Concept
Minitest under `test/controllers/webhooks_controller_test.rb` or `test/models/shipit/webhooks/handlers/pull_request/closed_handler_test.rb`:

1. Seed: `attacker_org` configured in `Shipit.github` config with `webhook_secret: nil`; `victim_repo` (owner `"victim-org"`, name `"victim-repo"`) with an active, non-archived `ReviewStack` fixture for PR number `N`.
2. Assert precondition: `victim_repo.review_stacks.find_by(pull_request_number: N).archived? == false`.
3. POST to `/webhooks` with `X-Github-Event: pull_request`, no `X-Hub-Signature` (or any garbage value), and body JSON where `repository.owner.login == "attacker-org"` and `repository.full_name == "victim-org/victim-repo"`, `action == "closed"`, `number == N`.
4. Assert response is `200 OK` (verification passed via attacker-org's nil secret).
5. Assert `victim_repo.review_stacks.find_by(pull_request_number: N).reload.archived? == true`, proving the binding `organization_verified != organization_mutated` and demonstrating unauthorized cross-tenant mutation.
