### Title
Path traversal via unsanitized `file.Name` in `writeToOutput` allows directory creation and file write outside intended `--output` tree - ([File: pkg/cmd/repo/read-file/read_file.go])

### Summary
When `gh repo read-file --output <dir>/` is used, `writeToOutput` builds the destination path with `filepath.Join(dest, file.Name)` where `file.Name` comes directly from the unsanitized `name` field of the Contents API JSON response. A malicious or attacker-controlled API host can return a `name` value containing `../` traversal segments, causing both `mkdirAllF` and the subsequent `writeFileF` to operate outside the directory the user intended.

### Finding Description
In `writeToOutput` (`pkg/cmd/repo/read-file/read_file.go`), when the `--output` target is a directory (either because it ends in a path separator or already exists as a directory), the code does: [1](#0-0) 

`file.Name` is populated straight from the JSON `name` field of the Contents API response with no validation that it is a bare basename: [2](#0-1) 

`filepath.Join` cleans `../` sequences, so a `name` value such as `"../../../../tmp/evil"` collapses the joined path to a location outside the intended output directory. The code then computes `dir := filepath.Dir(dest)` and calls `mkdirAllF(dir, 0755)`, followed by `writeFileF(dest, file.Content, 0644)`: [3](#0-2) 

There is no path-confinement check (no `filepath.Rel`/prefix check against the original `output` base directory) anywhere in `writeToOutput`, `fetchFile`, or `fetchContent`. The only existing protections are for symlinks at the *final* resolved `dest` (`lstatF` checks) and for `--clobber` semantics — neither of which restrict the resolved path to stay inside the requested output directory. Against a real, unmodified github.com the `name` field always reflects the true file basename, so this is only reachable when the victim points `gh` at an attacker-controlled or attacker-influenced API host (e.g., a malicious GHES-compatible endpoint or `GH_HOST`/enterprise config an attacker convinces the user to use), which is within the accepted threat model of "controls responses from a host the victim points gh at."

### Impact Explanation
This is a full arbitrary file write (not just directory creation) outside the intended output path: both the parent-directory creation (`mkdirAllF`) and the actual content write (`writeFileF`) use the traversed `dest`. This corresponds to the "file write outside the intended path" impact class, potentially allowing the attacker to place files (with attacker-controlled content) at arbitrary filesystem locations writable by the victim's user, including creating new directories that did not exist before.

### Likelihood Explanation
Requires the victim to run `gh repo read-file <path> --output <dir>/` (or an output path that already exists as a directory) against a host/repo under attacker control or influence, and for that host to return a crafted `name` field in the Contents API JSON response. This is deterministic and fully repeatable once the attacker controls the HTTP response — no other conditions (races, timing, etc.) are needed.

### Recommendation
Sanitize `file.Name` before use: reject any value containing path separators or `..` segments (e.g., require `filepath.Base(content.Name) == content.Name` and disallow `..`), or explicitly verify with `filepath.Rel` that the final `dest` is contained within the original `output` directory before creating directories or writing the file.

### Proof of Concept
```go
func TestWriteToOutput_PathTraversalInName(t *testing.T) {
    tmp := t.TempDir()
    outDir := filepath.Join(tmp, "downloads") + string(os.PathSeparator)
    require.NoError(t, os.MkdirAll(filepath.Join(tmp, "downloads"), 0755))

    file := &repoFile{
        Name:    "../../evil-outside",
        Content: []byte("pwned"),
    }

    dest, err := writeToOutput(file, outDir, false)
    require.NoError(t, err)

    // dest should be forced to remain under tmp/downloads, but Join+Dir/MkdirAll
    // will escape it instead.
    require.True(t, strings.HasPrefix(dest, filepath.Join(tmp, "downloads")),
        "dest escaped intended output directory: %s", dest)
}
```
Expected (buggy) result: `dest` resolves to `tmp/evil-outside`, outside `tmp/downloads`, and the file/directory is created there — the assertion fails, demonstrating the traversal.
