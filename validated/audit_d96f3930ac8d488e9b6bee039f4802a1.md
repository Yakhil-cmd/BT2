## Title
Missing freeze-authority validation on pool token mints allows permanent freezing of pool vaults and LP/swap funds - (File: `programs/cp-swap/src/utils/token.rs`)

## Summary
`initialize` and `initialize_with_permission` accept arbitrary `token_0_mint` / `token_1_mint` accounts and create program-owned vault token accounts for them without ever checking whether the mint has an active `freeze_authority`. A malicious or later-compromised mint authority can freeze the pool's vault ATA at any time, permanently disabling swaps, deposits, and withdrawals for that pool and trapping LP and swapper funds.

## Finding Description
Pool creation only validates mint "shape" via `is_supported_mint`, which whitelists a small set of Token-2022 extensions and, for legacy SPL Token mints, returns `true` unconditionally with no inspection of the mint's authorities: [1](#0-0) 

Neither this check nor the Anchor account constraints on `token_0_mint`/`token_1_mint` in `Initialize`/`InitializeWithPermission` verify `freeze_authority == None`: [2](#0-1) 

The vault token accounts that will hold pool funds are then created for these unchecked mints, owned by the pool `authority` PDA: [3](#0-2) [4](#0-3) 

Because `token_0_vault`/`token_1_vault` are ordinary SPL/Token-2022 accounts, they remain subject to `FreezeAccount` by whoever holds the mint's `freeze_authority`. The program never verifies this authority is `None`, so any creator (or the mint's authority, at any later time) can render a pool's vault permanently frozen.

## Impact Explanation
Once a vault ATA is frozen, `swap_base_input`/`swap_base_output`, `deposit`, and `withdraw` all fail because the underlying token CPIs (`transfer_checked`) will be rejected by the token program for a frozen account. This is a permanent, protocol-level DoS/fund-lock on genuine LP deposits and any swapper funds already routed to that vault — matching the reported bug class of "lack of freeze authority check leading to permanently unusable/frozen funds." Given this is an AMM pool (not a lending position), the practical severity is high for the affected pool: LPs cannot withdraw liquidity and swappers cannot trade once frozen.

## Likelihood Explanation
Pool creation via `initialize`/`initialize_with_permission` is permissionless (`creator`/`payer` can be anyone), and the mint accounts are fully attacker-chosen. An attacker only needs to create (or use) a mint with a non-null `freeze_authority`, spin up a pool, attract liquidity/swaps, and later freeze the vault. This requires no privileged access to the cp-swap program itself, matching the required unprivileged/single-transaction reachability.

## Recommendation
In `is_supported_mint` (or as an explicit constraint in `Initialize`/`InitializeWithPermission`), read the mint's `freeze_authority` (via `StateWithExtensions::<Mint>` for Token-2022, and `spl_token::state::Mint` unpack for legacy SPL Token) and reject pool creation (`return Ok(false)` / `err!(ErrorCode::NotSupportMint)`) if `freeze_authority.is_some()`.

## Proof of Concept
1. Create an SPL Token (legacy) or Token-2022 mint with a non-null `freeze_authority`.
2. Call `initialize` (or `initialize_with_permission`) with this mint as `token_0_mint`/`token_1_mint`; `is_supported_mint` returns `true` immediately for legacy `Token::id()` owner without checking `freeze_authority`, so pool creation succeeds and vaults are created.
3. Liquidity providers `deposit` into the pool; swappers `swap_base_input`/`swap_base_output` through it.
4. The freeze authority calls `FreezeAccount` on the pool's `token_0_vault` (or `token_1_vault`) ATA.
5. All subsequent `deposit`, `withdraw`, and `swap_*` calls touching that vault fail, permanently locking LP and swapper funds in the frozen vault.

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
