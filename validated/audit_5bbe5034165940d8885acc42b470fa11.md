### Title
Copilot bearer token unconditionally re-attached to redirected requests, bypassing Go's cross-host credential stripping - (File: pkg/cmd/agent-task/capi/client.go)

### Summary
`capiTransport.RoundTrip` in `pkg/cmd/agent-task/capi/client.go` unconditionally sets the `Authorization: Bearer <token>` header on every outgoing request made through the shared `http.Client`, without checking whether the request's destination host matches the intended CAPI host. This is the same bug class as the reported `AuctionDemo` issue: a payload (funds / a credential) that should only go to the intended, verified recipient (the token owner / the original request host) instead gets sent to whichever party the code currently happens to be talking to — here, whichever host the request is ultimately sent to after a redirect.

### Finding Description
`NewCAPIClient` wraps a shared `*http.Client` (also used elsewhere, e.g. for GraphQL calls to `github.com`/GHES) with `capiTransport`: [1](#0-0) 

The transport's `RoundTrip` method sets the Authorization header on **every** request it handles, with only the `Copilot-Integration-Id`/API-version headers gated on a host check — the token itself is not: [2](#0-1) 

Contrast this with the codebase's own correct pattern in `api/http_client.go`, where `AddAuthTokenHeader` explicitly detects a hostname change across a redirect and refuses to attach the token if the redirect target differs from the original request host: [3](#0-2) 

`capiTransport.RoundTrip` has no equivalent guard. Because Go's `net/http.Client` invokes the transport's `RoundTrip` again for every hop of a redirect chain, and because Go only strips *pre-existing* sensitive headers (`Authorization`, `Cookie`, `WWW-Authenticate`) when constructing the redirected request — it does not prevent a `RoundTripper` from re-adding them — this transport actively defeats that built-in protection by re-setting `Authorization` on the redirected request regardless of the new host. If any response received by this client (whether from the CAPI endpoint or from a GitHub GraphQL request funneled through the same client, e.g. `GetPullRequestDatabaseID` / `hydrateSessionPullRequestsAndUsers`) issues an HTTP redirect (3xx with `Location`) to an attacker-controlled host, the Copilot bearer token will be sent to that host. [4](#0-3) 

### Impact Explanation
The Copilot API bearer token is a live, usable credential for the user's Copilot/agent-task session. Leaking it to an attacker-controlled host allows the attacker to impersonate the user against the Copilot API (e.g., create/read agent jobs, session logs, or other authenticated resources), similar in spirit to the report's core defect: a value intended exclusively for one specific, verified destination is instead delivered to whatever destination the flow currently resolves to. Because the same `httpClient` instance is shared for GitHub GraphQL calls to a hostname (`hostname` parameter in `GetPullRequestDatabaseID`, which can be a GHE host), any redirect response encountered while talking to that host also results in the same over-broad credential attachment.

### Likelihood Explanation
Exploitation requires a redirect response to be produced by a host this shared client interacts with (the resolved CAPI base URL, or a GraphQL host) pointing to an attacker-controlled origin. The `capiBaseURL` is fetched via a GraphQL query (`resolveCapiURL`) whose response `Viewer.CopilotEndpoints.Api` is server-supplied, and `hostname` in `GetPullRequestDatabaseID` can be any GHE host derived from a local repository remote — not, by itself, obviously attacker-controlled without a compromised/malicious server response in the chain. This limits it to attacker-published/attacker-hosted content or a compromised/attacker-controlled host in the request chain, which fits the "attacker-controlled host during a normal gh command" category, though the exact trigger (a redirect from the CAPI backend or a GHE-hosted GraphQL endpoint) could not be fully traced end-to-end within the available index — I was unable to confirm whether `http.Client.CheckRedirect` is overridden anywhere upstream to block redirects for this client, which would mitigate the issue.

### Recommendation
Mirror the existing `AddAuthTokenHeader` pattern: in `capiTransport.RoundTrip`, only set the `Authorization` header when `req.Header.Get("Authorization") == ""` and when the request host matches the original/intended host (`ct.capiHost` for CAPI-bound requests, or the initial request host otherwise), analogous to the `redirectHostnameChange` check in `api/http_client.go`: [5](#0-4) 

### Proof of Concept
Not independently executed against the live `gh` binary (no filesystem/terminal access in this session); the following illustrates the code path that would need to be exercised:
1. Configure `capiClient := capi.NewCAPIClient(httpClient, "SECRET_TOKEN", "github.com", "https://api.githubcopilot.com")` as done in `CapiClientFunc`. [6](#0-5) 
2. Have the mocked/attacker-controlled server behind `api.githubcopilot.com` (or the resolved `capiBaseURL`) respond to a request (e.g. `GetJob`/`GetSessionLogs`) with a 3xx redirect to `https://attacker.example.com/collect`.
3. Because `capiTransport.RoundTrip` sets `Authorization: Bearer SECRET_TOKEN` unconditionally on the redirected request (which Go's `http.Client` would otherwise have stripped for a cross-host redirect), the bearer token is transmitted to `attacker.example.com`.

I was not able to find an existing unit test in `pkg/cmd/agent-task/capi/*_test.go` that specifically exercises the redirect scenario, so this needs to be validated with a live/mocked redirecting server to confirm actual header leakage in the outgoing request to the attacker host.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}

// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}

	// TODO: better int handling so we don't need to do bounds checks

			PullRequest struct {
				FullDatabaseID string `graphql:"fullDatabaseId"`

			} `graphql:"pullRequest(number: $number)"`
		} `graphql:"repository(owner: $owner, name: $repo)"`
	}

	variables := map[string]interface{}{
		"owner":  githubv4.String(owner),
		"repo":   githubv4.String(repo),
		"number": githubv4.Int(number),
	}

	apiClient := api.NewClientFromHTTP(c.httpClient)
	if err := apiClient.Query(hostname, "GetPullRequestFullDatabaseID", &resp, variables); err != nil {
		return 0, "", err
	}

func CapiClientFunc(f *cmdutil.Factory) func() (capi.CapiClient, error) {
	return func() (capi.CapiClient, error) {
		cfg, err := f.Config()
		if err != nil {
			return nil, err
		}

		httpClient, err := f.HttpClient()
		if err != nil {
			return nil, err
		}

		authCfg := cfg.Authentication()
		host, _ := authCfg.DefaultHost()
		token, _ := authCfg.ActiveToken(host)

		cachedClient := api.NewCachedHTTPClient(httpClient, time.Minute*10)
		capiBaseURL, err := resolveCapiURL(cachedClient, host)
		if err != nil {
			return nil, fmt.Errorf("failed to resolve Copilot API URL: %w", err)
		}

		return capi.NewCAPIClient(httpClient, token, host, capiBaseURL), nil
	}
}
