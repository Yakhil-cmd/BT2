### Title
Unverified `temp_data.data_length` bypasses size accounting, corrupting payload-commission and fee balance checks - ([File: validation.js])

### Summary
The Linux CVE fixes an accelerator command-stream validator that computed a buffer's required size using the wrong bit-field/format assumptions, so the calculated element size could be smaller than the real one, letting downstream code operate past the real buffer bounds. The ocore analog is the `temp_data` message handler in `validate`/`validateInlinePayload`: the size value that is later trusted for unit-fee accounting (`data_length`) is verified against the real data only on the code path where `data` is actually attached; on the code path where `data` is omitted, no length verification against real content ever happens, so a fabricated `data_length` silently propagates into the unit's payload-commission/fee arithmetic.

### Finding Description
`temp_data` messages carry `data_length`, `data_hash`, and (optionally) `data`. When `data` is present, the validator recomputes the real length and compares it to the declared one: [1](#0-0) 

But when `data` is **absent** from the payload, the only gate is a timestamp/age check (and it is skipped entirely for AA-generated messages): [2](#0-1) 

Because unit timestamps are attacker-controlled (units only reject timestamps *too far in the future*, not old ones) and AA units are unconditionally exempt (`!objValidationState.bAA`), an author can submit a `temp_data` message with a `data_length`/`data_hash` pair and no `data` at all, while setting the unit `timestamp` more than `TEMP_DATA_PURGE_TIMEOUT` (24h) in the past: [3](#0-2) 

This bypasses the only length check that exists for this field, exactly analogous to the kernel bug where element size wasn't accounted for one of the two code paths (OFM vs IFM/IFM2, or NHWC vs other layouts).

The unverified `data_length` then feeds directly into the size-accounting functions used for unit fee/commission validation: [4](#0-3) [5](#0-4) 

`getTotalPayloadSize()` is enforced as the mandatory `payload_commission` for every unit: [6](#0-5) 

and `payload_commission` (together with `headers_commission`, `oversize_fee`, `tps_fee`, `burn_fee`) must balance exactly against the unit's base-asset inputs/outputs: [7](#0-6) 

So the declared, unverified `data_length` becomes an authoritative input to the byte-balance equation that determines how many bytes the poster must actually pay, and to `getOversizeFee`: [8](#0-7) 

### Impact Explanation
Any single unit poster (not just AAs, though AAs are unconditionally exempt from even the timing check) can declare an arbitrary `data_length` for a `temp_data` message and never supply matching `data`, while making the message pass validation by back-dating the unit's `timestamp`. Since `data_length` (not the real, absent data) is what drives `payload_commission`/`oversize_fee`/byte-balance accounting, an attacker can under-price the unit relative to what a genuinely-sized temp-data payload would cost, or later (out of band, via gossip of the pre-image matching `data_hash`) attach real data whose actual size was never checked against the committed `data_length`, since the length-verification branch only runs at initial "data present" validation and is never re-run against this already-accepted unit. This is a size/fee accounting divergence directly reachable from a single posted unit that undermines the byte-fee mechanism ocore uses to prevent free storage/propagation cost externalization, which can produce disagreement between nodes about correct commission (if the check is later re-triggered on the same unit via a different path expecting the real length) and can be leveraged to under-pay the antispam fee for data storage.

### Likelihood Explanation
The condition is trivially reachable: any wallet or AA can compose a `temp_data` message, choose `data_length`/`data_hash` freely, omit `data`, and set an old `timestamp` (units place no lower bound on `timestamp`, only an upper bound relative to "now"). No privileged network position, hub, or peer collusion is required — a single ordinary unit author triggers the code path.

### Recommendation
- Require that `data_length`/`data_hash` in a `temp_data` message can only be accepted once, at the time `data` is actually present and verified (i.e., disallow accepting a brand-new `temp_data` message without `data` regardless of the unit's declared `timestamp`), or bind the "no data" bypass strictly to already-stable/already-validated units being replayed, not first-time validation of new units.
- Do not exempt AA-generated `temp_data` messages from the length/hash verification when `data` is omitted.
- Ensure any place that later attaches/serves the real `data` for a "dataless" `temp_data` message re-validates `getLength(data, true) === data_length` and `hash(data) === data_hash` before trusting it, and treat a mismatch as making the unit invalid (not just an isolated data-serving error), so that fee accounting can never diverge from the real element size committed to the network.

### Proof of Concept
1. Compose a unit with a single `temp_data` message: `payload = { data_length: 1, data_hash: <hash of a large, e.g. 5MB, JSON blob> }` (no `data` field).
2. Set `objUnit.timestamp = now - constants.TEMP_DATA_PURGE_TIMEOUT - 3600` (i.e., more than 24h+1h in the past); this is not rejected by the future-timestamp check in `validate()`.
3. Compute `headers_commission`/`payload_commission` using `object_length.getHeadersSize`/`getTotalPayloadSize` — because `extractTempData()` only adds `data_length + 4 = 5` bytes (not the real 5MB), the unit's required byte-fee is trivially small.
4. Submit the unit; `validateInlinePayload` case `"temp_data"` takes the `else` branch (`"data" in payload` is false) and, because the age condition is satisfied, skips the "data not found in temp_data" transient error and accepts the message with no real length verification.
5. Separately propagate the actual 5MB pre-image (matching `data_hash`) to peers/light clients through any out-of-band data-serving mechanism; nothing in the accepted unit's payload/fee accounting is ever recalculated against the real size, leaving the byte-fee paid inconsistent with the real committed data size.

function getTotalPayloadSize(objUnit) {
	if (objUnit.content_hash)
		throw Error("trying to get payload size of stripped unit");
	var bWithKeys = (objUnit.version !== constants.versionWithoutTimestamp && objUnit.version !== constants.versionWithoutKeySizes);
	const { temp_data_length, messages_without_temp_data } = extractTempData(objUnit.messages);
	return Math.ceil(temp_data_length * constants.TEMP_DATA_PRICE) + getLength({ messages: messages_without_temp_data }, bWithKeys);
}

function extractTempData(messages) {
	let temp_data_length = 0;
	let messages_without_temp_data = messages;
	for (let i = 0; i < messages.length; i++) {
		const m = messages[i];
		if (m.app === "temp_data") {
			if (!m.payload || typeof m.payload.data_length !== "number") // invalid message, but we don't want to throw exceptions here, so just ignore, and validation will fail later
				continue;
			temp_data_length += m.payload.data_length + 4; // "data".length is 4
			if (m.payload.data) {
				if (messages_without_temp_data === messages) // not copied yet
					messages_without_temp_data = _.cloneDeep(messages);
				delete messages_without_temp_data[i].payload.data;
			}
		}
	}
	return { temp_data_length, messages_without_temp_data };
}

function getOversizeFee(objUnitOrSize, mci, bAA) {
	let size;
	if (typeof objUnitOrSize === "number")
		size = objUnitOrSize; // must be already without temp data fee
	else if (typeof objUnitOrSize === "object") {
		if (!objUnitOrSize.headers_commission || !objUnitOrSize.payload_commission)
			throw Error("no headers or payload commission in unit");
		// AA-generated units pay the oversize fee based on the unit size excluding its payment messages to avoid swelling the fee while spending dust outputs
		const payload_commission = (bAA && mci >= constants.pemCurvesFixMci)
			? objectLength.getTotalPayloadSize({ ...objUnitOrSize, messages: objUnitOrSize.messages.filter(message => message.app !== 'payment') })
			: objUnitOrSize.payload_commission;
		size = objUnitOrSize.headers_commission + payload_commission - objectLength.getPaidTempDataFee(objUnitOrSize);
	}
	else
		throw Error("unrecognized 1st arg in getOversizeFee");
	const threshold_size = getSystemVar('threshold_size', mci);
	if (size <= threshold_size)
		return 0;
	return Math.ceil(size * (exp(size / threshold_size - 1) - 1));
}
