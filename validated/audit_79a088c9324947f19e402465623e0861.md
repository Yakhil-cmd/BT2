The confirmed binding to check: **`repository_owner`** (the value `WebhooksController#verify_signature` uses to select the `GitHubApp`/secret used to authenticate the request) must equal the owner of the `Shipit::Repository` record that `OpenedHandler#repository` resolves and mutates via `params.repository.full_name`. These are two independently-attacker-controlled JSON fields that are never cross-checked.### Title
Webhook-verification/repository-resolution mismatch lets a payload verified against one org's (no-)secret provision a ReviewStack on any other repository - ([File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates an inbound webhook using the org derived from `payload['repository']['owner']['login']`, but `OpenedHandler#repository` (and its sibling PR handlers) resolves the `Shipit::Repository` to mutate using the independent field `params.repository.full_name`. These two fields are never cross-checked, and `GitHubApp#verify_webhook_signature` unconditionally returns `true` when no `webhook_secret` is configured for the resolved org, so a payload "verified" under one (secret-less) org can target and provision a `Stack` on a completely different org's repository.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't: `organization_used_to_verify_signature (params.dig('repository','owner','login'))` **must equal** `owner_of_repository_actually_mutated (Repository.from_github_repo_name(params.repository.full_name).owner)`.

Code path:
- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`) and fetches `Shipit.github(organization: repository_owner)` to validate `X-Hub-Signature` [1](#0-0) , [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the org's config has no `webhook_secret` set (`return true unless webhook_secret`) [3](#0-2) . This is a documented, supported configuration (`webhook_secret: # nil` appears in the example configs) [4](#0-3) , [5](#0-4) .
- Once `verify_signature` passes (or is bypassed this way), `WebhooksController#create` hands the **entire attacker-controlled JSON body** to `Shipit::Webhooks.for_event(event)` handlers [6](#0-5) .
- `OpenedHandler#repository` resolves the `Repository` record using `params.repository.full_name` — a completely different field from the one used for signature verification, with no check that its owner matches `repository_owner` [7](#0-6) .
- `#provision?` then reads `review_stacks_enabled`/`provisioning_behavior_*` off whichever `Repository` that resolves to, and if `allow_all`/label conditions are met, calls `ReviewStackAdapter#find_or_create!` scoped to `repository.review_stacks` [8](#0-7) .

Exploit: an unprivileged internet user (no session, no secret) sends `POST /webhooks` with header `X-Github-Event: pull_request` and a JSON body where `repository.owner.login = "OrgOne"` (an org configured in Shipit with no `webhook_secret`) but `repository.full_name = "victim-org/victim-repo"` (a real tracked repository belonging to a different, properly-secured org). `verify_signature` resolves `Shipit.github(organization: "OrgOne")`, finds no `webhook_secret`, and accepts the request regardless of the `X-Hub-Signature` header content. The handler then looks up and mutates `victim-org/victim-repo`'s `Repository` record via `Repository.from_github_repo_name("victim-org/victim-repo")`, and if that repo has `review_stacks_enabled` and `provisioning_behavior_allow_all?`, a `Stack`/review-stack is auto-provisioned for it — a deploy-adjacent action triggered without any authentication tied to that repository's own org/secret.

None of the existing guards stop this: `drop_unhandled_event` only checks the event type; `ExplicitParameters` schema only validates presence/types of `repository.full_name`, not consistency with `repository.owner.login`; there is no `force_github_authentication`/`User#authorized?`/`require_permission!` check in the webhook path (webhooks are inherently unauthenticated except via signature); model validations on `Repository` only constrain character format, not provenance.

### Impact Explanation
An attacker can trigger creation (`find_or_create!`) of a `ReviewStack`/`Stack` record for an arbitrary tracked repository that has `provisioning_behavior_allow_all?` and `review_stacks_enabled`, without having any relationship to that repository's org, session, API token, or its real `webhook_secret`. This matches the "payload for one repository mutating another's stack" Critical category. The blast radius is every repository tracked by the same Shipit instance whose provisioning settings allow it, cross-tenant, as long as any single org configured in the instance lacks a `webhook_secret` (or the attacker can otherwise get a payload verified). Repeatable per matching victim repository/PR-number combination (idempotency limits duplicate stacks per PR number, but distinct PR numbers/repos can be targeted repeatedly).

### Likelihood Explanation
Requires: (1) the Shipit instance to have at least one org configured without a `webhook_secret` (a documented, real-world configuration pattern shown in this repo's own example secrets files), and (2) a victim repository tracked by Shipit with `review_stacks_enabled` and a permissive `provisioning_behavior`. No GitHub App installation, session, or secret is required by the attacker — only knowledge of the org name lacking a secret and a target repo's `full_name`, both of which are visible/guessable (org names and repo names are public). This is a low-cost, direct HTTP POST exploit with no live GitHub interaction needed.

### Recommendation
Cross-validate that the `owner` segment of `params.repository.full_name` matches `repository_owner` (`params.dig('repository','owner','login')`) before resolving/mutating any `Repository` in every PR/webhook handler (`OpenedHandler`, `ClosedHandler`, `UnlabeledHandler`, `LabeledHandler`, etc.), rejecting the payload otherwise. Additionally, treat a missing `webhook_secret` as a hard misconfiguration (refuse to accept webhooks, or require an explicit "unsafe" opt-in) rather than silently allowing all payloads through `GitHubApp#verify_webhook_signature`.

### Proof of Concept
Minitest plan (webhook controller integration test, no live GitHub):
```ruby
test "payload verified under org with no webhook_secret cannot provision a stack for another org's repository" do
  # Org "OrgOne" configured with webhook_secret: nil (as in test/dummy/config/secrets_double_github_app.yml)
  victim_repo = shipit_repositories(:shipit) # belongs to org "shopify", not "OrgOne"
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)

  body = payload_parsed(:pull_request_opened)
  body["repository"]["owner"]["login"] = "OrgOne"           # used for verify_signature
  body["repository"]["full_name"] = victim_repo.github_repo_name # used by OpenedHandler#repository
  body["action"] = "opened"

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary/invalid, irrelevant when OrgOne has no secret

  assert_no_difference -> { Shipit::Stack.where(repository: victim_repo).count } do
    post :create, body: body.to_json, as: :json
  end
  # ^ Assert this equality holds: repository_owner ("OrgOne") == owner-of-mutated-repo ("shopify")
  # Currently FAILS (stack IS created), proving the binding is broken.
end
```
Assertions on both sides of the equality: (a) `repository_owner` resolved by `WebhooksController#repository_owner` == `"OrgOne"`; (b) owner of the `Repository` actually mutated by `OpenedHandler#repository` == `victim_repo.owner` (`"shopify"`). The test demonstrates these differ yet the write still occurs.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
