### Title
Unhandled hashing exception causes double-callback and node crash on malformed private payment payload - (File: network.js)

### Summary
`handleSavedPrivatePayments()` in `network.js` processes previously-queued private payment chains sent by a payment counterparty. When hashing the head element's payload throws, the `catch` block does not `return`, so execution falls through and the same async iteration item is finalized twice, ultimately double-invoking the `unlock` callback from `mutex.js`, which explicitly throws `Error("double unlock?")`. That uncaught exception reaches the global `process.on('uncaughtException', …)` handler in `network.js`, which re-throws to crash the whole node process — directly analogous to CVE-2016-10363, where malformed Netflow packets triggered unhandled parser errors that killed the Logstash process.

### Finding Description
`handleSavedPrivatePayments` reads rows from `unhandled_private_payments` (populated earlier from a private-payment counterparty's `payment_notification`/private-chain message in `wallet.js`/`network.js`) and, for each row, hashes the head private element's payload: [1](#0-0) 

If `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` throws, the code logs the error, optionally sends an error to the peer, and calls `deleteHandledPrivateChain(..., cb)` — but the function does **not** `return` after the `catch` block. Execution continues to compute `key` (using the now-`undefined` `json_payload_hash`) and calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, …)`, whose `ifOk`/`ifError`/`ifWaitingForChain` handlers each separately call `deleteHandledPrivateChain(..., cb)` or `cb()` again: [2](#0-1) 

`getBase64Hash` calls `getJsonSourceString`, which throws `Error` for several attacker-controlled payload shapes, e.g. an empty object/array, a non-finite number, or a value of unsupported type: [3](#0-2) 

Because `cb` here is the `async.each` iterator callback, invoking it twice for the same item is invalid and results in the outer `async.each` final callback (`unlock`) firing twice: [4](#0-3) [5](#0-4) 

`mutex.js`'s `exec()` wraps `unlock` such that a second call throws synchronously: [6](#0-5) 

This uncaught throw is not caught anywhere in this call chain and reaches the global handler, which deliberately re-throws to terminate the process: [7](#0-6) 

### Impact Explanation
Any private-payment counterparty (or paired device forwarding a private chain) can craft a payload for the head element of a private payment chain that fails `getJsonSourceString`/`getBase64Hash` (e.g., an empty object, `NaN`/`Infinity` field, or unsupported type nested in the payload). Once this malformed chain lands in `unhandled_private_payments` and is later reprocessed by `handleSavedPrivatePayments`, it deterministically crashes the victim's ocore node process. This is a remote, unauthenticated-by-network-topology denial of service against any wallet node that accepts private payments — matching the "network unable to confirm new units" / node-crash impact class of the CVE analog, since a crashed node stops validating/relaying/confirming units until manually restarted.

### Likelihood Explanation
High. No special privileges are required beyond being a private-payment counterparty (a normal wallet interaction), and payload shapes that throw in `getJsonSourceString` (empty `{}`/`[]`, `NaN`, `Infinity`, or an `undefined`-holding key) are trivial to construct. The `try/catch` exists specifically to catch this exception but was written without a `return`, making the crash a certainty once the exception path is hit — it is not a probabilistic race, just missing control flow.

### Recommendation
Add a `return` immediately after the `deleteHandledPrivateChain(...)` call inside the `catch (e)` block in `handleSavedPrivatePayments` (`network.js`) so that the callback `cb` is invoked exactly once per iterated row and the fallthrough into `validateAndSavePrivatePaymentChain` with an already-failed hash is prevented. Additionally, wrap `validateAndSavePrivatePaymentChain`'s use and any downstream `unlock()`/`cb()` calls with guards against double invocation, and consider hardening `mutex.js`'s `exec()` to log-and-ignore rather than throw on a double unlock, to avoid single-bug-crashes process-wide.

### Proof of Concept
1. As a paired device / private-payment counterparty, send a private payment chain (via the private-chain message flow handled in `wallet.js` → `handlePrivatePaymentChains` → `network.js`'s private-chain handler) whose head element's `payload` is an object that fails hashing, e.g. `payload: {}` (empty object) or `payload: { amount: NaN }`.
2. The chain is queued into `unhandled_private_payments` because the referenced unit is not yet known/stable (`ifWaitingForChain`/`ifKnownUnverified` path): [8](#0-7) 
3. When `handleSavedPrivatePayments` later reprocesses the queue (triggered periodically or upon receiving the referenced unit), `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` throws inside the `try` block at `network.js:2469-2470`.
4. The `catch` block runs but does not `return`; `cb` is invoked once there and again via `validateAndSavePrivatePaymentChain`'s callback, causing `mutex.js`'s `unlock` to be called twice, throwing `Error("double unlock?")`.
5. This uncaught exception propagates to `process.on('uncaughtException', …)` in `network.js`, which re-throws and terminates the node process.

function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
