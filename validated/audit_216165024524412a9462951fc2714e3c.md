### Title
Webhook signature verification org selection is decoupled from the repository `EditedHandler` mutates, allowing cross-tenant `PullRequest` forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the HMAC secret to verify a webhook using `repository_owner`, which falls back to `params.dig('organization','login')` whenever `repository.owner.login` is absent from the JSON body. `EditedHandler`, however, determines which repository/stack/`PullRequest` to mutate from a completely independent field, `params.repository.full_name`. Because these two fields are set independently by the attacker in the same request body, a webhook that is cryptographically authenticated with one tenant's secret can be crafted to mutate a `PullRequest` record belonging to a different tenant's stack.

### Finding Description
The broken binding is the implicit assumption:
`repository_owner (used to pick verifying secret) == owner(params.repository.full_name) (repository actually mutated)`.

- `WebhooksController#repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) , and `verify_signature` uses it to pick the `GitHubApp` (and thus its `webhook_secret`) via `Shipit.github(organization: repository_owner)` [2](#0-1) .
- `Shipit.github`/`github_app_config` looks up `secrets.github[organization]`, i.e. in a multi-organization deployment each onboarded organization has its own, independently configured `webhook_secret` [3](#0-2) .
- `EditedHandler`'s `ExplicitParameters` schema only `requires :repository do requires :full_name, String end` — it never requires `repository.owner.login` [4](#0-3) . Its `process`/`repository`/`pull_request` methods resolve the target `Repository`/`Stack`/`PullRequest` purely from `params.repository.full_name` [5](#0-4) , then persist attacker-controlled JSON: `pull_request.update(github_pull_request: params.pull_request)` [6](#0-5) .

Exploit request: omit `repository.owner`, set `organization.login` to the attacker's own onboarded org (whose `webhook_secret` the attacker legitimately knows), but set `repository.full_name` to the victim org/repo:
```json
{
  "action": "edited",
  "number": 42,
  "pull_request": { "...attacker-controlled fields..." },
  "repository": { "full_name": "victim-org/victim-repo" },
  "organization": { "login": "attacker-org" },
  "sender": { "login": "attacker" }
}
```
signed with `attacker-org`'s HMAC secret. `verify_signature` resolves `repository_owner` = `"attacker-org"` (since `repository.owner.login` is absent) and verifies successfully against `attacker-org`'s own secret. The request is accepted, `Shipit::Webhooks.for_event('pull_request')` dispatches to `EditedHandler`, whose schema is satisfied (only `repository.full_name` is required, not `owner`), and it updates the `PullRequest` row belonging to `victim-org/victim-repo`'s stack with attacker-supplied JSON.

None of the existing guards catch this: `verify_signature` never cross-checks that the org it authenticated against matches `params.repository.full_name`'s owner; `drop_unhandled_event` only checks the event type exists a handler for; the `ExplicitParameters` schema for `EditedHandler` does not require `repository.owner`, so parsing does not fail; there is no `force_github_authentication`/session check on this unauthenticated endpoint by design.

### Impact Explanation
A request cryptographically authenticated only by `attacker-org`'s webhook secret writes/mutates a `PullRequest` record (`github_pull_request` JSON) that belongs to a stack under a different repository (`victim-org/victim-repo`). This is a "payload for one repository mutating another's stack" scenario, matching the Critical impact bucket in scope. This is repeatable against any victim stack/PR number the attacker can discover (PR numbers/repo names are public GitHub information), and it works against every stack configured under any other tenant regardless of that stack's `ignore_ci` setting — `EditedHandler` itself does not gate on CI at all, so the `ignore_ci`/`Commit#deployable?` angle in the prompt is not actually exercised by this handler (it only updates metadata, it does not create a `Commit` or trigger a deploy). Concretely the confirmed impact is: cross-tenant forgery of `PullRequest#github_pull_request` metadata, not an unauthorized deploy/rollback by itself.

### Likelihood Explanation
This bug only manifests in a **multi-organization** Shipit deployment where `secrets.github` is keyed by organization name and each organization has its own distinct `webhook_secret` (`github_default_organization` non-nil path in `lib/shipit.rb`) [7](#0-6) . It further requires the attacker to be a legitimate operator/admin of one of those other onboarded organizations (so they know that org's own, correctly configured `webhook_secret` — not the victim's). In a single-organization/default Shipit configuration (`github_default_organization` nil), `Shipit.github(organization: ...)` ignores the `organization` argument entirely and always resolves the single configured secret, so the fallback-selection divergence has no observable effect. The rules state the attacker holds no `webhook_secret`; if this is read strictly (no secret for any org), the attack is not reachable and the finding does not hold. If read as "no secret belonging to the victim" (i.e., they may know their own onboarded tenant's secret), the attack is straightforward and repeatable.

### Recommendation
Bind webhook signature verification to the same repository the handler will act on: derive the verifying organization exclusively from `params.repository.full_name`'s owner (or require `repository.owner.login` to be present and consistent with `organization.login` before falling back), and reject requests where they diverge. Additionally, require `repository.owner.login` in every handler's `ExplicitParameters` schema (not just `repository.full_name`) so the mutated repository's owner is always present and can be cross-checked against `repository_owner`.

  #   secrets.github[:"attacker-org"][:webhook_secret] == "attacker_secret"
  #   secrets.github[:"victim-org"][:webhook_secret]   == "victim_secret"
  victim_stack = shipit_stacks(:victim_stack) # repository full_name "victim-org/victim-repo"

    number: 42,
    pull_request: {

      additions: 0, deletions: 0,
      head: { sha: 'a' * 40, ref: 'evil' },
      user: { login: 'attacker' },
      assignees: [], labels: []

    organization: { login: 'attacker-org' },              # verifier fallback selection
    sender: { login: 'attacker' }

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', 'attacker_secret', body)

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = signature

  post :create, body: body, as: :json

  assert_response :ok
  pr.reload

  #   verifying_org(repository_owner) == "attacker-org"
  #   mutated_repo_owner(params.repository.full_name) == "victim-org"
  # These differ, yet the write still succeeds:
  assert_equal 'ATTACKER TITLE', pr.github_pull_request['title']
end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',

        "status=#{status}"

    rescue Shipit::GithubOrganizationUnknown => e

        "status=#{status}"
      ].join(' '))

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
