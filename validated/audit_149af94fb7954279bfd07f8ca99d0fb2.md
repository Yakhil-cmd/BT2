### Title
Webhook signature verification is keyed to an attacker-controlled `repository_owner` field, letting requests targeting any repository bypass HMAC verification via an unrelated, secret-less GitHub App config - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` chooses **which** `GitHubApp`/`webhook_secret` to validate a webhook against based on `repository_owner`, a value read straight out of the untrusted JSON body [1](#0-0) . The actual repository/stack that gets mutated by the event handler is looked up separately, from `payload.dig('repository', 'full_name')` [2](#0-1) . Because these two fields are never required to be consistent, and because `GitHubApp#verify_webhook_signature` unconditionally returns `true` when the selected org has no `webhook_secret` configured [3](#0-2) , an attacker can pick any configured-but-secretless organization name for the "owner" field used for auth, while pointing `repository.full_name` (or `organization.login` for membership events) at a completely different, protected target - fully bypassing signature verification for that target.

### Finding Description
`verify_signature` runs as a `before_action` and does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
head(422) unless verified
```
with
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [4](#0-3) 

`repository_owner` is entirely attacker-controlled JSON content, not something cryptographically bound to the request. `Shipit::GitHubApp` supports multiple independently configured organizations, each with its own optional `webhook_secret` [5](#0-4) , and the setup docs/templates explicitly show `webhook_secret` as an optional/nil field per org [6](#0-5) [7](#0-6) . When the selected org's `webhook_secret` is blank, verification is skipped entirely:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [3](#0-2) 

Meanwhile, the event handlers resolve the actual mutated repository independently via `full_name`:
```ruby
def repository_name
  payload.dig('repository', 'full_name')
end
``` [8](#0-7) 
and, for events like `membership`, bind team/organization directly from `params.organization.login` supplied in the same unauthenticated payload [9](#0-8) .

This breaks the equality: `organization used to select the verifying secret == organization/repository actually acted upon`. Nothing enforces that `repository.owner.login` (used only to pick the verification key) matches `repository.full_name`'s owner or `organization.login` used by the handler. An attacker who knows the name of **any** org configured in the deployment with a blank `webhook_secret` (a common misconfiguration explicitly supported/documented as valid) can put that org's name in the "owner"/`organization.login` field to force `verify_webhook_signature` to return `true` unconditionally, then supply arbitrary `repository.full_name` or team/member data targeting a different, fully protected repository/organization.

### Impact Explanation
This is a Critical/High-impact authentication bypass on an unauthenticated public endpoint:
- For `push`/`status`/`check_suite` events, the attacker can forge signature-free events for any repository already registered in Shipit, driving `PushHandler#process` to call `stack.sync_github(expected_head_sha:)` [10](#0-9)  with attacker-chosen data for repositories under organizations that *do* have signatures properly configured - an unauthorized cross-repository write into deploy state.
- For `membership` events, the attacker can forge team membership changes (`team.add_member(member)` / removal) [11](#0-10) , directly escalating into `Shipit.github_teams`/OAuth-team-based authorization used elsewhere in the app, without ever supplying a valid HMAC signature for the real target.

### Likelihood Explanation
Exploitability only requires: (1) knowledge that some organization configured on the instance has no `webhook_secret` set (a documented, common default state for new/incompletely-configured orgs), and (2) the ability to send an unauthenticated POST to the public GitHub webhooks endpoint. No GitHub App private key, `ApiClient` token, or session is required, satisfying the unprivileged-attacker requirement.

### Recommendation
Bind signature verification to the same identity the handler actually acts on: derive the verifying organization from `repository.full_name`'s owner segment (or a value cross-checked against it), require `webhook_secret` to be present for every configured organization (fail closed instead of `return true unless webhook_secret`), and reject events where `repository.owner.login`/`organization.login` doesn't match the owner encoded in `repository.full_name`.

### Proof of Concept
1. Operator configures `Shipit.github` with two orgs: `secure-org` (has `webhook_secret`) and `legacy-org` (left `webhook_secret: nil`, as shown as a valid default in the shipped config templates).
2. Attacker sends, without any `X-Hub-Signature` value (or an arbitrary one):
```
POST /github/webhooks
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "legacy-org" },
    "full_name": "secure-org/production-app"
  }
}
```
3. `verify_signature` computes `repository_owner == "legacy-org"`, loads `Shipit.github(organization: "legacy-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of signature.
4. `PushHandler` looks up the stack via `repository.full_name == "secure-org/production-app"` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")`, mutating deploy-relevant state for a repository whose organization is fully secured - all without ever presenting a valid signature for `secure-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
