### Title
Shared-address definition accepted without verifying it actually requires the local co-signer's key - ([File: wallet_defined_by_addresses.js])

### Summary
`handleNewSharedAddress()` accepts an unsolicited `new_shared_address` device message and stores it as a trusted co-signing (multi-party) address after only checking (1) hash integrity of the definition, (2) that `signers` addresses are syntactically valid, and (3) that the leaf `["address", ...]` paths match the `signers` map. It never verifies that the *combinator structure* of the definition (`and`/`or`/`r of set`) actually requires the local device's key to authorize spending. This is analogous to the Keycloak flaw where a party could register an additional authentication factor alongside an existing one that alone satisfies "step-up" checks — here, a paired device/counterparty can register a spending-authorization structure that looks like a joint (AND) address but is actually satisfiable by the attacker alone (via `or`), letting them unilaterally spend funds the victim believes are jointly controlled.

### Finding Description
`handleNewSharedAddress` in `wallet_defined_by_addresses.js` performs the following checks before persisting the address as a trusted shared/multisig address: [1](#0-0) 

- It confirms `objectHash.getChash160(body.definition) === body.address` (hash integrity only — proves the definition wasn't tampered with, not that it is a safe joint condition).
- It confirms `signers[path].address` matches the actual `["address", ...]` leaf found by `extractAddressPathsFromDefinition` at that path.
- It calls `determineIfIncludesMeAndRewriteDeviceAddress`, which only checks that *some* of the local wallet's own addresses appear somewhere as a leaf in the definition: [2](#0-1) 
- It then calls `validateAddressDefinition`, which only runs `Definition.validateDefinition` — a purely *syntactic* validity check of the spending-condition grammar, not a semantic check that all listed members are jointly required: [3](#0-2) 

Nowhere in this flow is there a check that the top-level combinator is `and` (or `r of set` with `required_count === set.length`) whenever the local device's address is included. A counterparty (or any device that pairs with the victim, since this message can arrive from any paired device) can send:

```
["or", [["address", "VICTIM_ADDR"], ["address", "ATTACKER_ADDR"]]]
```

This passes every check: it hashes correctly to its own `address`, both leaves match the `signers` map, the victim's own address is "included" (satisfying `determineIfIncludesMeAndRewriteDeviceAddress`), and it is a syntactically valid definition. The wallet then silently stores it via `addNewSharedAddress` as a "shared address" and may treat it (and display it, and accept incoming funds sent to it as `outputs`/watched address) as if it were a cooperatively controlled address, while in fact the attacker's single signature alone satisfies the `or` and can move any funds sent there.

The developer's own code comment acknowledges the incompleteness of this check: [4](#0-3) 

### Impact Explanation
If the victim (or an application built on ocore, e.g. an escrow/arbiter/multisig wallet feature) is led to believe the shared address requires joint approval and deposits or forwards funds to it as a "protected" or "co-signed" address, the attacker who sent the crafted `or`-based definition can spend the entire balance unilaterally with only their own signature, since `["address", "ATTACKER_ADDR"]` alone satisfies the definition. This is concrete unauthorized spending / fund loss for the counterparty who trusted the shared-address abstraction, reachable purely from an unprivileged paired device sending a device message — no privileged network/hub/node role is required.

### Likelihood Explanation
The `new_shared_address` handler is reachable directly from any correspondent device via `handleMessageFromHub` → `case "new_shared_address"` with no additional authorization gate beyond the definition's own internal (attacker-controlled) content: [5](#0-4) 
Crafting a definition whose top-level operator is `or` (or a `r of set` with `required=1`) including the victim's real address as a decoy leaf is straightforward and requires no cryptographic breaking — it exploits a missing semantic-structure check, similar to how the Keycloak flaw let an authenticated-but-unprivileged actor register an additional factor that bypassed the intended step-up requirement.

### Recommendation
In `handleNewSharedAddress` / `validateAddressDefinition`, after confirming the local address(es) are referenced, walk the definition tree from the root and verify that the local member address's leaf lies under `and`/`r of set`-with-full-threshold nodes only (i.e., that removing/forging the other listed co-signers cannot satisfy the condition without the local key). Reject or flag (with an explicit, unavoidable user warning) any shared-address definition whose overall condition can be satisfied without the local device's signing path, e.g. by evaluating the definition twice — once with the local leaf forced false — and rejecting if it can still evaluate true through other listed members alone.

### Proof of Concept
1. Attacker device pairs with victim device (`device.handlePairingMessage` – standard, low-privilege pairing flow). [6](#0-5) 
2. Attacker computes `arrDefinition = ["or", [["address", VICTIM_ADDR], ["address", ATTACKER_ADDR]]]` and `address = objectHash.getChash160(arrDefinition)`.
3. Attacker sends a `new_shared_address` device message:
```json
{
  "subject": "new_shared_address",
  "body": {
    "address": "<computed address>",
    "definition": ["or", [["address", "VICTIM_ADDR"], ["address", "ATTACKER_ADDR"]]],
    "signers": {
      "r.0": {"address": "VICTIM_ADDR", "device_address": "<victim device>"},
      "r.1": {"address": "ATTACKER_ADDR", "device_address": "<attacker device>"}
    }
  }
}
```
4. `handleNewSharedAddress` accepts it: hash matches, signer addresses match leaves, victim's own address is found among the leaves so `determineIfIncludesMeAndRewriteDeviceAddress` succeeds, `validateAddressDefinition` succeeds (syntactically valid `or`), and `addNewSharedAddress` persists it as a trusted shared address, watched for incoming funds. [7](#0-6) 
5. If funds are sent to this address believing it requires both parties, the attacker alone signs with `ATTACKER_ADDR`'s key satisfying the `or` and spends the funds without the victim's cooperation or knowledge.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

// {pairing_secret: "random string", device_name: "Bob's MacBook Pro", reverse_pairing_secret: "random string"}
function handlePairingMessage(json, device_pubkey, callbacks){
	var body = json.body;
	var from_address = objectHash.getDeviceAddress(device_pubkey);
	if (!ValidationUtils.isNonemptyString(body.pairing_secret))
		return callbacks.ifError("correspondent not known and no pairing secret");
	if (!ValidationUtils.isNonemptyString(json.device_hub)) // home hub of the sender
		return callbacks.ifError("no device_hub when pairing");
	if (json.device_hub.length > 200)
		return callbacks.ifError("device_hub too long");
	if (!network.isValidWsUrl(conf.WS_PROTOCOL + json.device_hub))
		return callbacks.ifError("invalid device_hub URL");
	if (!ValidationUtils.isNonemptyString(body.device_name))
		return callbacks.ifError("no device_name when pairing");
	if (body.device_name.length > 100)
		return callbacks.ifError("device_name too long");
	if ("reverse_pairing_secret" in body && !ValidationUtils.isNonemptyString(body.reverse_pairing_secret))
		return callbacks.ifError("bad reverse pairing secret");
	eventBus.emit("pairing_attempt", from_address, body.pairing_secret);
	db.query(
		"SELECT is_permanent FROM pairing_secrets WHERE pairing_secret IN(?,'*') AND expiry_date>"+db.getNow()+" ORDER BY (pairing_secret=?) DESC LIMIT 1", 
		[body.pairing_secret, body.pairing_secret], 
		function(pairing_rows){
			if (pairing_rows.length === 0)
				return callbacks.ifError("pairing secret not found or expired");
			// add new correspondent and delete pending pairing
			var safe_device_name = body.device_name.replace(/<[^>]*>?/g, '');
			db.query(
				"INSERT "+db.getIgnore()+" INTO correspondent_devices (device_address, pubkey, hub, name, is_confirmed) VALUES (?,?,?,?,1)", 
				[from_address, device_pubkey, json.device_hub, safe_device_name],
				function(){
					db.query( // don't update name if already confirmed
						"UPDATE correspondent_devices SET is_confirmed=1, name=? WHERE device_address=? AND is_confirmed=0", 
						[safe_device_name, from_address],
						function(){
							db.query("UPDATE correspondent_devices SET is_blackhole=0 WHERE device_address=?", [from_address], function(){
								eventBus.emit("paired", from_address, body.pairing_secret);
								if (pairing_rows[0].is_permanent === 0){ // multiple peers can pair through permanent secret
									db.query("DELETE FROM pairing_secrets WHERE pairing_secret=?", [body.pairing_secret], function(){});
									eventBus.emit('paired_by_secret-'+body.pairing_secret, from_address);
								}
								if (body.reverse_pairing_secret)
									sendPairingMessage(json.device_hub, device_pubkey, body.reverse_pairing_secret, null);
								callbacks.ifOk();
							});
						}
					);
				}
			);
		}
	);
}
