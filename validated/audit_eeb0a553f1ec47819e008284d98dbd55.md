### Title
Unbounded `reward.stakingrewardthreshold` Governance Vote Redirects Entire Staking-Reward Budget to Proposer — (`kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`, `kaiax/reward/impl/getter.go`)

---

### Summary

The `reward.stakingrewardthreshold` governance parameter (introduced for the Flex reward rule at Osaka hardfork) has no upper-bound validation and no cross-validation against `reward.minimumstake`. A governing node (or any council member in `none`-mode governance) can vote to set the threshold above every validator's actual staking amount. When `assignStakingRewardsFlex` runs, no validator clears the threshold, `totalExcessInt` stays zero, the entire staking-reward budget is returned as `kip82Remainder`, and that remainder is added directly to the proposer's balance. All stakers receive zero KAIA for that block.

---

### Finding Description

**Unvalidated parameter stored and used in reward distribution**

`reward.stakingrewardthreshold` is a mutable governance parameter. Its `FormatChecker` in `kaiax/gov/param.go` only requires the value to be non-negative:

```go
RewardStakingRewardThreshold: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok { return false }
        return v.Sign() >= 0   // only non-negative check; no upper bound
    },
    ...
}
```

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` explicitly lists `RewardStakingRewardThreshold` in the "no further checks" branch:

```go
case gov.GovernanceDeriveShaImpl, ...,
    gov.RewardStakingRewardThreshold, ...:
    return nil
```

There is no check that `threshold ≤ minimumstake` or that `threshold` is bounded by any realistic staking amount.

**How the value flows into reward distribution**

In `kaiax/reward/impl/getter.go`, `assignStakingRewardsFlex` reads the threshold and uses it to compute each validator's "excess" stake:

```go
threshold = config.StakingRewardThreshold.Uint64()
...
if amount > threshold {
    excessInt[cn.RewardAddr] = amount - threshold
    totalExcessInt += excessInt[cn.RewardAddr]
}
```

If `threshold` exceeds every validator's `amount`, `totalExcessInt` remains 0, `alloc` is empty, and the full `budget` is returned as `remaining`.

Back in `getDeferredRewardFullFlex`:

```go
stakersAlloc, kip82Remainder := assignStakingRewardsFlex(config, stakers, si)
proposer.Add(proposer, kip82Remainder)   // entire staking budget goes to proposer
stakers.Sub(stakers, kip82Remainder)     // stakers = 0
```

The proposer's balance is inflated by the entire staking-reward allocation; every other validator receives zero staking rewards for that block.

**The test suite already documents this exact behavior:**

```go
{"flex, all below threshold, no staking reward", true, big.NewInt(9_000_000), kpfAddr, &reward.RewardSpec{
    Proposer: big.NewInt(3.84e18 + 3.5e16), // fee/2 + stakers
    Stakers:  big.NewInt(0),                // no stakers were eligible
    ...
}}
```

---

### Impact Explanation

**Unauthorized redistribution of KAIA staking rewards.** Every block processed under the manipulated threshold transfers the staking-reward portion (e.g., 80 % of the validator share under the default `20/80` KIP-82 ratio) from all stakers to the proposer. On mainnet with a 6.4 KAIA minting amount and a `50/20/30` reward ratio and `20/80` KIP-82 ratio, the staking budget is approximately 2.56 KAIA per block. Redirecting this to the proposer constitutes an unauthorized KAIA transfer affecting system-managed funds every block until governance corrects the parameter.

---

### Likelihood Explanation

**Trigger requires governance privilege.** On Kaia mainnet (`single` mode), only the governing node can cast a ratified vote. On chains running `none`-mode governance, any council member (validator) can cast the last vote in an epoch and have it ratified. The attacker must be a council member and must become the block proposer in the same epoch to inscribe the vote. This is a semi-trusted role reachable without external key compromise. The attack is a single governance vote, not majority collusion.

---

### Recommendation

Add a cross-validation in `checkConsistency` (or in the `FormatChecker`) that rejects any `reward.stakingrewardthreshold` vote whose value exceeds the current `reward.minimumstake`:

```go
case gov.RewardStakingRewardThreshold:
    params := h.GetParamSet(blockNum)
    if vote.Value().(*big.Int).Cmp(params.MinimumStake) > 0 {
        return ErrStakingRewardThresholdExceedsMinStake
    }
    return nil
```

Alternatively, add an upper-bound `FormatChecker` that rejects values above a protocol-defined maximum (e.g., the genesis `minimumstake`). The analogous fix in GoGoPool was to validate `duration` against `[14 days, 365 days]`; the equivalent here is to validate `threshold ∈ [0, minimumstake]`.

---

### Proof of Concept

1. Chain is post-Osaka with `reward.useflexreward = true`, `reward.minimumstake = 5_000_000`, validators staking ~5–6 million KAIA.
2. Governing node (or any council member in `none` mode) calls `governance_vote("reward.stakingrewardthreshold", "9000000")`.
3. Vote passes format check (`9000000 >= 0`), passes `checkConsistency` (`return nil`), and is inscribed in `header.Vote`.
4. At the next epoch block, the vote is ratified and `StakingRewardThreshold` becomes 9,000,000.
5. For every subsequent block, `assignStakingRewardsFlex` finds `amount (≤ 6M) ≤ threshold (9M)` for all validators → `totalExcessInt = 0` → `alloc = {}` → entire `stakers` budget returned as `kip82Remainder`.
6. `proposer.Add(proposer, kip82Remainder)` credits the full staking budget to the proposer.
7. `spec.Stakers = 0`; all other validators receive zero staking rewards.

The test case `"flex, all below threshold, no staking reward"` in `kaiax/reward/impl/getter_test.go` at line 1082 already confirms this exact outcome with `threshold = big.NewInt(9_000_000)`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

```go
// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}
```
