### Title
Verifier-organization/mutation-target confusion in `/webhooks` lets a `pull_request.closed` payload archive a review Stack belonging to an org whose GitHub App has a different (or missing) webhook secret than the org used for signature verification - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate a webhook against based on `params.dig('repository','owner','login')` (or `organization.login`), while `ClosedHandler#repository` resolves the actual mutation target from a completely independent field, `params.repository.full_name`. Nothing binds these two fields together, so a raw POST to `/webhooks` can be "verified" under one organization's GitHub App config while its `repository.full_name` points at a different organization's tracked repository/Stack, causing `ClosedHandler#process` to call `review_stack.archive!` on a Stack the verifying organization does not own.

### Finding Description
The broken binding is: **verifying_org (used to select the HMAC secret) == owning_org (whose Stack/repo is mutated by the handler)**.

Trace:
- `WebhooksController#repository_owner` reads `params.dig('repository','owner','login')` and falls back to `params.dig('organization','login')` [1](#0-0) .
- `verify_signature` uses that value to fetch a per-organization `GitHubApp` config and validate `X-Hub-Signature` against `request.raw_post` using that org's `webhook_secret` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally if that org's `webhook_secret` is blank/absent — a state explicitly documented as "optional" during App setup [3](#0-2) .
- `Shipit.github(organization:)` only actually uses the `organization` argument to pick a config when the instance is running in multi-org mode (`github_default_organization` non-nil); in single-app mode the `organization` argument is ignored entirely, so this specific confusion is only org-boundary-crossing in the documented "Using Multiple Github Applications" topology [4](#0-3) .
- Once the request passes the `before_action` chain, `Shipit::Webhooks.for_event('pull_request')` dispatches to `ClosedHandler`, which does **not** re-derive the repository from the same `repository.owner.login`/`organization.login` field used for verification. It instead resolves the target repository from `params.repository.full_name` via `Repository.from_github_repo_name`, which simply splits on `/` and does a DB lookup with no relation to the verifying org [5](#0-4) , [6](#0-5) .
- `ClosedHandler#process` then calls `review_stack.archive!` unconditionally for any tracked repo matching that `full_name`, with no comparison back to `repository_owner` [7](#0-6) .

Exploit flow: attacker (any internet user, no GitHub/Shipit credentials) sends `POST /webhooks` with header `X-Github-Event: pull_request`, `X-Hub-Signature: sha1=anything`, and a JSON body where `repository.owner.login` = `organization.login` = some org configured in this Shipit instance's multi-org `secrets.github` map that has **no `webhook_secret` set** (an explicitly optional, supported configuration per `docs/setup.md`), but `repository.full_name` = `"victim-org/victim-repo"` (a different, actually secured org tracked by the same Shipit instance), `action: "closed"`, and a syntactically valid `pull_request` object. `verify_signature` looks up the no-secret org's `GitHubApp`, and `verify_webhook_signature` returns `true` unconditionally regardless of the (garbage) signature. The request proceeds to `ClosedHandler#process`, which resolves `victim-org/victim-repo` via `full_name` and calls `review_stack.archive!`, mutating the victim's Stack state — with zero involvement of the victim's own webhook secret.

Existing guards fail to catch this because: `verify_signature` and `drop_unhandled_event` operate purely on headers/one payload field to choose a verifier and never cross-check it against the field the handler later uses to select the mutation target; the `ExplicitParameters` schema in `ClosedHandler` only validates types/presence of `repository.full_name`, not that it is consistent with `repository.owner.login`; `Repository.from_github_repo_name` performs no ownership/authorization check tied to the verifying organization.

### Impact Explanation
An attacker can archive (effectively close) any tracked review Stack in a multi-org Shipit deployment — including a Stack belonging to an organization whose secret they never had — as long as some other organization configured on that same Shipit instance has no `webhook_secret` set. This is a cross-tenant integrity violation: "a payload for one repository mutating another's stack" (matches the Critical bucket explicitly). The attack is fully repeatable against any tracked repo/Stack full_name the attacker can guess or enumerate, and can be probed via response codes (200 OK vs 422) to discover which configured orgs lack a secret, without needing any Shipit session, API token, or GitHub credential.

### Likelihood Explanation
Preconditions: the Shipit instance must be configured with the documented "Using Multiple Github Applications" topology, and at least one of the configured organizations must have left `webhook_secret` unset (documented as optional in `docs/setup.md`). Given that precondition, the attacker cost is trivial — a single unauthenticated HTTP POST, no secrets, no GitHub account, no repository access required at all. This is entirely feasible and repeatable; the only variable is whether the specific deployment has a no-secret org configured, which the attacker can discover via the 200/422 response oracle described above.

### Recommendation
Bind webhook signature verification to the exact same repository/organization identity used for mutation: derive `repository_owner` and the repository lookup key from a single canonicalized source, and after selecting the verifying `GitHubApp`, assert that `params.repository.full_name`'s owner segment equals the verified `repository_owner` before dispatching to any handler (reject with 422 otherwise). Additionally, stop treating `webhook_secret` as silently optional in multi-org configurations — require it for every configured organization, or fail startup/verification loudly when unset in multi-org mode, since a missing secret in any one organization becomes a global authentication bypass usable against every other organization on the same instance.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (illustrative)
test "cross-org repository confusion allows unauthorized stack mutation" do
  # Setup: multi-org secrets config where 'attacker-org' has no webhook_secret,
  # 'victim-org' has a real webhook_secret (see test/dummy/config/secrets_double_github_app.yml pattern).
  victim_repository = Shipit::Repository.create!(owner: 'victim-org', name: 'victim-repo')
  victim_stack = victim_repository.stacks.create!(environment: 'production', branch: 'master')
  merge_request = victim_stack.merge_requests.create!(number: 42, state: 'pending')

  body = payload_parsed(:pull_request_closed)
  body["repository"]["owner"]["login"] = "attacker-org" # no secret configured -> verify_webhook_signature always true
  body["organization"] = { "login" => "attacker-org" }
  body["repository"]["full_name"] = "victim-org/victim-repo" # actually mutated

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # garbage, never checked because attacker-org has no secret

  post :create, body: body.to_json, as: :json

  assert_response :ok
  # Binding under test: verifying_org == owning_org
  assert_not_equal "attacker-org", victim_repository.owner
  refute victim_stack.reload.archived?, "Victim stack must remain untouched without victim-org's own secret"
  # Absent the fix, this assertion fails: victim_stack.archived? is true
end
```
Note: exact fixture/model names (`merge_requests`, `state` column) could not be fully confirmed from the index within the available tool budget; `ClosedHandler` mutates via `Stack#archive!`/`ReviewStackAdapter`, so the assertion should target `victim_stack.reload.archived?` as the authoritative binding check.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
