### Title
Deregistered Bridge Operator's Votes Persist and Can Still Execute Value Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`deregisterOperator()` in `BridgeOperator.sol` removes an operator from the `operators` mapping and `operatorList`, but does **not** revoke or clear that operator's outstanding votes from the `votes` storage mapping. A remaining registered operator voting on the same nonce can combine with the deregistered operator's stale vote to meet the threshold, causing `handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`, `setKLAYFee`, or `setERC20Fee` to execute — even though the owner intended to stop the deregistered operator's influence.

---

### Finding Description

`BridgeOperator.deregisterOperator()` sets `operators[_operator] = false` and removes the address from `operatorList`, but leaves all entries in the private `votes` mapping untouched: [1](#0-0) 

The code itself documents the problem: [2](#0-1) 

When `_voteCommon` evaluates whether the threshold is reached, it reads `vote.voteCounts[_voteKey]` — a counter that was incremented by the deregistered operator and was never decremented on deregistration: [3](#0-2) 

The `onlyOperators` modifier only blocks **new** votes from deregistered operators; it does not retroactively invalidate votes already cast: [4](#0-3) 

All three handle functions (`handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`) and both fee-setting functions (`setKLAYFee`, `setERC20Fee`) route through `_voteValueTransfer` or `_voteConfiguration`, which call `_voteCommon`: [5](#0-4) [6](#0-5) [7](#0-6) 

---

### Impact Explanation

A deregistered operator's vote count persists in `votes[VoteType.ValueTransfer][nonce].voteCounts[voteKey]`. When a remaining registered operator votes on the same `(nonce, calldata)`, the combined count can reach `operatorThresholds`, causing the bridge to:

- Transfer KLAY to the `_to` address (`handleKLAYTransfer`)
- Mint or transfer ERC20 tokens (`handleERC20Transfer`)
- Mint or transfer ERC721 tokens (`handleERC721Transfer`)
- Change bridge fee configuration (`setKLAYFee`, `setERC20Fee`)

The owner's security action — deregistering an operator to stop their influence — is not fully effective for any nonce on which the deregistered operator had already voted.

---

### Likelihood Explanation

The scenario is reachable whenever:
1. An operator votes on a nonce (normal bridge operation).
2. The owner deregisters that operator (e.g., key compromise, upgrade, or policy change).
3. A remaining operator votes on the same nonce with the same parameters.

Step 3 is a normal bridge operation. The window between steps 1 and 2 is the ordinary latency of bridge operation. This is not a low-probability edge case — it is the normal deregistration flow.

---

### Recommendation

In `deregisterOperator()`, iterate over all open (non-closed) nonces for which the deregistered operator has a recorded vote and decrement the corresponding `voteCounts` entry:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    delete operators[_operator];
    // Revoke outstanding votes for all open nonces
    // (requires tracking open nonces or iterating known pending nonces)
    for (uint8 vt = 0; vt < uint8(VoteType.Max); vt++) {
        // For each pending nonce, if votes[vt][nonce].voted[_operator] != 0:
        //   votes[vt][nonce].voteCounts[oldKey]--;
        //   delete votes[vt][nonce].voted[_operator];
    }
    // ... remove from operatorList ...
    emit OperatorDeregistered(_operator);
}
```

Because the `votes` mapping is keyed by nonce and the set of open nonces is unbounded, the practical fix is to track a list of pending nonces per operator, or to add a per-operator "deregistered-at-block" timestamp and reject stale votes in `_voteCommon` when `msg.sender` was deregistered before the vote was cast.

---

### Proof of Concept

Setup: operators A, B, C; `operatorThresholds[ValueTransfer] = 2`.

1. Operator A calls `handleKLAYTransfer(txHash, from, to, value, nonce=5, blockNum, data)`. `votes[ValueTransfer][5].voteCounts[keccak256(calldata)] = 1`. `closedValueTransferVotes[5] = false`.
2. Owner calls `deregisterOperator(A)`. `operators[A] = false`. Vote count for nonce 5 is **not cleared**.
3. Operator B calls `handleKLAYTransfer` with identical parameters. `_voteCommon` increments `voteCounts` to 2, which equals threshold 2 → returns `true` → `closedValueTransferVotes[5] = true` → KLAY transferred.

A's vote contributed to the execution despite A being deregistered. The owner's intent to stop A's influence on nonce 5 was not honored. [3](#0-2) [8](#0-7)

```text
    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
```

```text
    // deregisterOperator deregisters the operator.
    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
```
