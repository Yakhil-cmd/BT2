### Title
`repository.owner.login` vs `repository.full_name` divergence lets an attacker who owns a no-secret org's webhook forge `pull_request` events that mutate a different org's stack via `LabelCapturingHandler` - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the webhook secret) used to authenticate an inbound webhook using `params.dig('repository','owner','login')`, while every `pull_request` handler (e.g. `LabelCapturingHandler#repository`) resolves the *actual* repository/stack it mutates from the independent, unchecked `params.repository.full_name` field. Because `GitHubApp#verify_webhook_signature` unconditionally returns `true` when no `webhook_secret` is configured for the selected org, an attacker who controls (or names) any org configured in Shipit without a secret can forge a payload whose `owner.login` is that no-secret org while `full_name` points at an arbitrary other org/repo tracked by the same Shipit instance, causing `LabelCapturingHandler` to write attacker-controlled labels onto a victim `PullRequest`/`ReviewStack` it never authenticated for.

### Finding Description
The broken binding: the code assumes `repository_owner (used to pick the verifying secret) == owner_of(repository.full_name) (used to resolve the mutated repo/stack)`. Nothing enforces this equality.

- `WebhooksController#verify_signature` picks the GitHub App config solely from `repository_owner`, i.e. `params.dig('repository','owner','login')` [1](#0-0) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever no `webhook_secret` is configured for that org, i.e. attacker payloads are accepted unconditionally for any configured-but-secretless org [3](#0-2) .
- `Shipit.github(organization:)`/`github_app_config` resolve per-org config from `secrets.github` in multi-tenant mode, meaning different orgs can legitimately have different (or absent) webhook secrets [4](#0-3) .
- Once verification passes, `LabelCapturingHandler#repository` resolves the concrete `Shipit::Repository` from `params.repository.full_name` — a completely separate field from `owner.login`, with no cross-validation between the two [5](#0-4) .
- `capture_labels` then persists `params.pull_request.labels.map(&:name)` onto `stack.pull_request` for whatever stack was resolved from `full_name` [6](#0-5) .
- The ExplicitParameters schema only `requires :repository { requires :full_name, String }` — it does not require or validate `owner.login` at all in this handler, so nothing in the schema catches the mismatch [7](#0-6) .

Attacker request: `X-Github-Event: pull_request`, body `{"action":"unlabeled","number":<n>,"pull_request":{...,"labels":[{"name":"ATTACKER_ENV=malicious"}]},"repository":{"owner":{"login":"attacker-no-secret-org"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker"}}`, with any (even garbage) `X-Hub-Signature`. Because `attacker-no-secret-org` has no configured `webhook_secret`, `verify_webhook_signature` returns `true` regardless of the signature supplied, so `verify_signature` passes and the handler runs against `victim-org/victim-repo`'s review stack.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type exists a handler [8](#0-7) ; `verify_signature` never compares `owner.login` against `full_name`'s owner segment; the `ExplicitParameters` schema validates types/presence, not cross-field org consistency.

### Impact Explanation
A payload authenticated as belonging to one (no-secret) org is used to write to another org/repo's `PullRequest` record via `LabelCapturingHandler`, matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." [6](#0-5)  If the victim review stack has `continuous_deployment` enabled, and if `ReviewStack#env` surfaces label names as environment variables consumed by deploy tasks, attacker-controlled label strings become attacker-controlled deploy-time environment content for a stack the attacker never authenticated against — amplifying to unauthorized/altered deploy behavior on each new green commit shipped by `ContinuousDeliveryJob`. This is repeatable against any repository/stack tracked by the Shipit instance as long as at least one org in the multi-org config lacks a `webhook_secret`.

### Likelihood Explanation
Preconditions: Shipit must be configured in multi-org mode (`secrets.github` keyed by org) — required for `repository_owner`-based per-org secret selection to matter at all; single-org legacy mode uses one global secret regardless of the value in `repository_owner`, so the split is not exploitable there. At least one configured org must have no `webhook_secret` set (an operator misconfiguration/gap, but explicitly listed by the question as an accepted precondition — "no-secret org"). Given that precondition, attacker cost is trivial: a single unauthenticated HTTP POST to `/webhooks` with a crafted JSON body; no valid signature, GitHub token, or Shipit session is needed. The attack is fully repeatable against any repository/stack whose `full_name` the attacker knows.

### Recommendation
In `WebhooksController#verify_signature`, and in every `pull_request`/`push`/etc. handler that resolves a repository via `params.repository.full_name`, enforce that the resolved repository's actual owner (e.g., `Repository#owner`/GitHub org derived from `full_name`) matches the `repository_owner` (or `organization.login`) that was used to select and verify the webhook secret. Reject the request (422) if they diverge. Additionally, treat a missing `webhook_secret` for a configured org as a hard misconfiguration to be flagged/blocked rather than silently trusting all unsigned traffic for that org (`GitHubApp#verify_webhook_signature`'s `return true unless webhook_secret` should not silently authenticate arbitrary payloads for other orgs' full_name targets).

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Seed two orgs in `secrets.github`: `"victim-org"` (with a `webhook_secret`) and `"attacker-org"` (no `webhook_secret`).
2. Create `shipit_repository` for `victim-org/victim-repo`, a `Shipit::Stack` with `continuous_deployment: true`, and an active `ReviewStack`/`PullRequest` for PR number `N` belonging to that repo.
3. POST `/webhooks` with `X-Github-Event: pull_request`, body: `action: "unlabeled"`, `number: N`, `pull_request.labels: [{name: "INJECTED_ENV=evil"}]`, `repository: {owner: {login: "attacker-org"}, full_name: "victim-org/victim-repo"}`, `sender: {login: "attacker"}`, and an arbitrary/garbage `X-Hub-Signature` header.
4. Assert response is `:ok` (not `422`), proving `verify_signature` passed using `attacker-org`'s (absent) secret — i.e., assert `repository_owner == "attacker-org"` while the mutated repo's actual owner `== "victim-org"`, demonstrating the equality claimed by the invariant ("the org that authenticated the request equals the org whose stack is mutated") is false.
5. Reload the victim `PullRequest` and assert `pull_request.labels == ["INJECTED_ENV=evil"]`, proving the victim's record was mutated by a payload authenticated under a different, attacker-controlled org.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
