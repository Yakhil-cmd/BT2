### Title
Unbounded recursive expansion of `definition_template` payloads causes stack-overflow DoS - (File: definition.js)

### Summary
`replaceInTemplate()` in `definition.js` recursively walks an entire nested-array/object structure with no depth limit before an address definition referencing a `definition template` op is evaluated. The template content itself (an app=`definition_template` message payload) is accepted into the DAG with only a shallow, two-element-array check, no depth/size/complexity bound. This mirrors the react-router GHSA-8x6r-g9mw-2r78 bug class (unbounded expansion of an attacker-controlled nested structure driving disproportionate server-side resource consumption/crash), applied to `ocore`'s address-definition evaluation path instead of route matching.

### Finding Description
An unprivileged unit poster can post a message with `app: 'definition_template'`. Its payload is validated only for shape, not depth or complexity: [1](#0-0) 

The same shallow check exists on the AA-side validator: [2](#0-1) 

Later, when any address definition (an ordinary wallet's spending condition, or a nested/shared address, or an AA-triggering author's definition) contains a `['definition template', [unit, params]]` operator, `definition.js` fetches the stored raw JSON payload and calls `replaceInTemplate` on it *before* any complexity/op accounting is applied: [3](#0-2) [4](#0-3) 

`replaceInTemplate` recurses into every array/object level of the attacker-supplied JSON with no depth cap: [5](#0-4) 

By contrast, every other recursive validator in the codebase that walks attacker-supplied nested structures enforces an explicit `MAX_DEPTH`/depth counter (e.g. AA definition validation and oscript formula validation): [6](#0-5) [7](#0-6) 

`definition.js`'s own `evaluate()` function that walks address-definition expression trees *does* enforce `MAX_COMPLEXITY`/`MAX_OPS` limits per node: [8](#0-7) 
—but this accounting only starts once `evaluate()` is invoked on the *already expanded* template (`evaluate(arrFilledTemplate, path, bInNegation, cb)`), i.e. only after `replaceInTemplate`'s unbounded recursive walk has already completed (or crashed the stack). A deeply nested array (e.g. thousands of levels of single-element arrays) is cheap to store (`object_length.js`'s `getLength` sums lengths without any depth limit either) but expensive/unsafe to traverse recursively in V8, leading to `RangeError: Maximum call stack size exceeded`.

Critically, this `RangeError` is not a `NoVarException`, so it falls through the `catch` block and is re-thrown: [9](#0-8) 
This throw happens inside a `conn.query` callback (async context), which in Node.js is an uncaught exception that crashes the process rather than propagating to a `try/catch` around unit validation — turning a single crafted unit/message pair into a full node crash.

### Impact Explanation
Any node (full node, hub, or wallet) that validates a unit whose spending/definition path references a poisoned `definition_template` unit will attempt the unbounded recursive expansion and can crash with a stack overflow, an uncaught exception in an async callback. Because unit/definition validation is mandatory consensus-critical work performed by every node that receives the unit, this can be used to crash multiple/all validating nodes that process the same DAG data — a network-wide denial of service preventing confirmation of new units (CWE-400), matching the required "network unable to confirm new units" impact bar.

### Likelihood Explanation
Reachable by an ordinary unprivileged unit poster with two ordinary messages: (1) post a `definition_template` message with a deeply/pathologically nested JSON array payload (cheap in byte size, since a chain of single-element arrays is small), and (2) have (or later post) an address definition/authentifier chain that includes `['definition template', [unit_of_1, params]]`, then trigger validation of that address's spending or definition. No special privileges, hub/peer trust, or protocol version bypass is required — this is an ordinary oscript address-definition feature (`definition template`) available to any address owner.

### Recommendation
- Add a depth/size limit to `replaceInTemplate` (mirror the `MAX_DEPTH` pattern used elsewhere, e.g. in `aa_validation.js`'s `validate()`), rejecting templates whose nesting exceeds a small bound.
- Enforce a depth and node-count limit at the point `definition_template` messages are first validated/stored (`validation.js` case `"definition_template"`), not only when they are later expanded.
- Wrap the `replaceInTemplate`/expansion call in `definition.js` in explicit error handling that converts stack-overflow/RangeError into a normal validation failure (`cb(err)`), rather than allowing it to propagate as an uncaught exception out of an async callback.

### Proof of Concept
1. Attacker posts unit A containing a message `{app: 'definition_template', payload: ['x', T]}` where `T` is a deeply nested array such as `[[[[...(N thousand levels)...]]]]` (or a `params`-substitutable large nested `templates`), satisfying only the `isArrayOfLength(payload, 2)` check in `validation.js`.
2. Attacker (or any address owner) defines/uses an address whose spending definition includes `['definition template', [unit_of_A, {...}]]`.
3. When any node validates a unit spending from (or referencing the definition of) that address, `definition.js`'s `evaluate()` for op `'definition template'` fetches A's payload and calls `replaceInTemplate(arrTemplate, params)`, which recurses to depth N and overflows the call stack, throwing an uncaught `RangeError` inside the `conn.query` callback and crashing the node process.

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
