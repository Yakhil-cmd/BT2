This confirms the design intentionally supports **multiple GitHub App configurations keyed by organization name**, each with its own independent `webhook_secret` [1](#0-0) , and `verify_webhook_signature` short-circuits to `true` whenever a given organization's `webhook_secret` is blank [2](#0-1) .

### Title
Webhook signature is verified against the organization named in an attacker-controlled field, not the repository the payload actually mutates - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects *which* configured GitHub App/secret to validate the delivery against using `repository_owner`, a value read straight out of the unauthenticated JSON body (`repository.owner.login`, or `organization.login` as a fallback) [3](#0-2) . Every webhook handler, however, resolves the target `Stack`/`Repository` from a *different* field of the same attacker-controlled body: `payload.dig('repository', 'full_name')` [4](#0-3) . Nothing in the engine enforces that `repository.owner.login` and `repository.full_name`'s owner segment refer to the same GitHub organization. Because Shipit supports multiple independently-configured GitHub Apps/organizations, each with its own optional `webhook_secret` [5](#0-4) , and validation is skipped entirely (`return true unless webhook_secret`) when a given org has none configured [2](#0-1) , an attacker can pick the organization used for signature *selection* while a completely different field is used for signature *action*.

### Finding Description
The binding that should hold is: **organization whose signature authenticated the request == repository/organization that is written by handling that request**. The webhooks controller breaks this equality:

1. `repository_owner` picks the verifying `github_app` from `params.dig('repository','owner','login')` [6](#0-5) .
2. `verify_signature` calls `Shipit.github(organization: repository_owner)` to fetch that org's app config and verifies the HMAC using **that org's** `webhook_secret` [7](#0-6) .
3. If that org is configured but has no `webhook_secret` set (a supported, documented configuration — see `webhook_secret (optional)` in `docs/setup.md`, and the `test/dummy/config/secrets_double_github_app.yml` fixture showing two orgs each with `webhook_secret: # nil`), `verify_webhook_signature` returns `true` unconditionally regardless of the actual `X-Hub-Signature` header [8](#0-7) .
4. Once "verified," the *same* JSON body is dispatched to handlers (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`) [9](#0-8) , which locate the stack to mutate using `repository.full_name`, a value never checked against `repository.owner.login` [4](#0-3) .

An attacker crafts one JSON payload:
```json
{
  "repository": {
    "owner": { "login": "org-with-no-webhook-secret" },
    "full_name": "victim-org/victim-repo"
  },
  ...
}
```
`repository_owner` resolves to `org-with-no-webhook-secret`, the signature check trivially passes, and the handler acts on `victim-org/victim-repo`. Every event whose handler trusts `repository.full_name` (push → `GithubSyncJob`, status → new commit `Status`, check_suite → `RefreshCheckRunsJob`, pull_request edited → updating a tracked `PullRequest`, etc.) is affected [10](#0-9) [11](#0-10) .

### Impact Explanation
This lets an unauthenticated network attacker inject forged, unsigned GitHub events (push/status/check_suite/pull_request/membership) that are attributed to and acted upon *any* repository/organization already registered in the Shipit instance, as long as **any other** configured organization in the same instance has no `webhook_secret`. Consequences include forging commit statuses that feed CI-gating logic (`ci.require`), triggering `GithubSyncJob` refresh/rollback bookkeeping, or manipulating tracked pull-request state for a repository the attacker does not control — none of which required possession of the real webhook secret for the targeted org. This falls in the "cross-repository writes" / unauthorized-deploy-adjacent High-Critical category the ruleset calls out, since it defeats the very purpose of per-organization webhook signing.

### Likelihood Explanation
Requires: (a) the Shipit deployment to have at least two GitHub App/organization configs, and (b) at least one of them lacking a `webhook_secret` — both explicitly supported, undocumented-as-dangerous configurations shown in the engine's own test fixtures (`test/dummy/config/secrets_double_github_app.yml`) and README ("Webhook secret (optional)"). No credentials, session, or repository access are needed; only a raw HTTP POST to `/webhooks` with a crafted body and an `X-Github-Event` header.

### Recommendation
Bind the signature-selection field and the payload-action field together: require that `repository.owner.login` (used to pick the verifying app) equal the owner segment of `repository.full_name` (used to select the target stack), and reject the request otherwise. Alternatively, verify against every configured organization's secret (or a single well-known one) rather than trusting an unauthenticated field to choose which secret protects the request.

### Proof of Concept
```ruby
# Assume org "OrgOne" is configured with webhook_secret: nil (as in
# test/dummy/config/secrets_double_github_app.yml), and "victim-org/victim-repo"
# is a real tracked Stack signed with a *different* org's secret.

payload = {
  "repository" => { "owner" => { "login" => "OrgOne" }, "full_name" => "victim-org/victim-repo", "id" => 1 },
  "after" => "deadbeef" * 5,
  "ref" => "refs/heads/master"
}.to_json

post "/webhooks", body: payload, headers: {
  "X-Github-Event" => "push"
  # No valid X-Hub-Signature needed: OrgOne has no webhook_secret
}
# => WebhooksController#verify_signature passes trivially,
#    GithubSyncJob is enqueued against victim-org/victim-repo's stack.
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end
