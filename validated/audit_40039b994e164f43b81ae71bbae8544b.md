### Title
Webhook signature verification and repository lookup key off two independent, attacker-controlled fields of the same unsigned JSON body, allowing cross-tenant PullRequest mutation - (File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb, app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to check against using `params.dig('repository','owner','login')`, and `EditedHandler#repository` independently resolves the target `Repository` using `params.repository.full_name` — both fields come from the same unsigned, attacker-supplied JSON body. Nothing binds these two values together, so a payload can be signed with an org the attacker legitimately controls in Shipit while pointing `repository.full_name` at a completely different, victim organization/repository.

### Finding Description
The broken binding is the implicit assumption that:
`repository_owner` (used to pick the `webhook_secret` in `Shipit.github(organization: repository_owner)`, [1](#0-0) , `repository_owner` defined at [2](#0-1) )
==
owner of `repository.full_name` used by `EditedHandler#repository` to build the ActiveRecord scope ( [3](#0-2) , consumed in the join at [4](#0-3) ).

Both values are read from the *same* untrusted JSON body (`params.dig('repository','owner','login')` vs `params.repository.full_name`), and the engine never asserts they refer to the same organization. The `verify_signature` before_action only proves that *some* configured GitHub org's secret was used to sign the raw body; it says nothing about which repository the handler will actually touch, because the handler re-parses `repository.full_name` independently from the same body ( [5](#0-4) ).

Exploit flow: an attacker who owns/administers any GitHub organization/App installation that is configured in this Shipit instance (i.e., has a legitimate `webhook_secret` configured for their own org — which they can obtain simply by being a legitimate, unprivileged tenant of a multi-org Shipit install, or in the single-tenant case knows nothing extra) can:
1. Construct a JSON body where `repository.owner.login` = `attacker-org` (their own org) but `repository.full_name` = `victim-org/victim-repo`.
2. Compute `X-Hub-Signature` HMAC-SHA1 using `attacker-org`'s webhook secret (which GitHub itself provides to them via their own webhook delivery, or they can trigger a real delivery from their own repo and only rewrite `repository.full_name`/`pull_request.number` in transit if they can also intercept — however since this is a direct POST to `/webhooks` with attacker-controlled raw body signed with their own known secret, no interception is needed: the attacker signs the body themselves offline with the secret associated with their own org, which was disclosed to them by GitHub when they configured their own org's webhook against this Shipit instance).
3. POST to `/webhooks` with `X-Github-Event: pull_request`.
4. `verify_signature` resolves `github_app` for `attacker-org`, verifies HMAC against attacker's own secret → passes.
5. `EditedHandler#repository` resolves `Shipit::Repository.from_github_repo_name("victim-org/victim-repo")` → returns the real victim `Repository` record and its `id`.
6. `pull_request` query joins `stacks: :repository` filtered on `repositories.id == victim_repo.id` and `number == params.number`, and if `action == "edited"`, calls `pull_request.update(github_pull_request: params.pull_request)` — mutating the victim's `PullRequest` record with attacker-supplied `title`, `state`, `head.sha`, `head.ref`, `labels`, `assignees`, etc. ( [6](#0-5) ).

None of the listed guards prevent this: `verify_signature` validates the signature against the org named in the payload itself, not against the org actually being mutated ( [7](#0-6) ); `drop_unhandled_event` and the `ExplicitParameters` schema only check event/param shape, not cross-field consistency ( [8](#0-7) ); `Repository.from_github_repo_name` and validators only constrain format, not provenance ( [9](#0-8) ).

### Impact Explanation
An attacker who legitimately controls one org's webhook secret in a multi-tenant Shipit deployment can forge `pull_request` webhook events (edited, and by the same pattern labeled/unlabeled/assigned/closed/reopened/opened, since they all derive `repository` from `params.repository.full_name` independently of the signing org) targeting **any other tenant's repository/stack** known by `owner/name`, mutating that victim's `PullRequest` record (title, labels, assignees, head sha/ref, state) without ever authenticating as that org. This is a payload for one repository (the signer's) mutating another repository's (the victim's) record — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." The blast radius spans every stack/repository configured in the same Shipit instance, repeatable at will and for every PR-related handler that follows this same pattern.

### Likelihood Explanation
This only applies to deployments where multiple GitHub organizations/App installations are configured in the same Shipit instance (`Shipit.github_apps`/config keyed by org), which is a documented, supported multi-tenant configuration. The attacker needs no special privilege beyond being an authorized (even low-trust) tenant/org owner able to configure a webhook against this Shipit instance for their own org — a capability explicitly allowed to "any internet user" per the threat model once they have any org integrated, and does not require any Shipit secret, session, or API token. Cost is a single crafted HTTP POST with a self-computed HMAC using a secret they legitimately possess for their own org. Fully repeatable against arbitrary target repositories/stacks known to exist by name.

### Recommendation
Verify that the organization used to select the signing secret is the same organization referenced by `repository.full_name` (and `organization.login` fallback) in the payload before any handler runs — e.g., derive `repository_owner` from `full_name.split('/').first` and require it to equal `params.dig('repository','owner','login')`, and reject the request if they diverge. More robustly, bind the resolved `Repository`/`Stack` scope to the same organization value that was cryptographically verified, rather than re-deriving it from a second, independently-read field of the same unsigned body.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_cross_org_test.rb (conceptual)
test "signature verified for attacker org does not bind to victim repo used by handler" do
  attacker_org = "attacker-org"
  victim_repo  = shipit_repositories(:shipit) # owner/name belongs to a different org
  stack = shipit_stacks(:shipit)
  pr = shipit_pull_requests(:shipit_pending) # belongs to victim_repo's stack

  payload = {
    action: "edited",
    number: pr.number,
    pull_request: { id: 1, number: pr.number, url: "u", title: "PWNED",
                     state: "open", additions: 0, deletions: 0,
                     head: { sha: "a" * 40, ref: "attacker-branch" },
                     user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { full_name: victim_repo.full_name, owner: { login: attacker_org } },
    sender: { login: "attacker" }
  }.to_json

  secret = Shipit.github(organization: attacker_org).send(:webhook_secret)
  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", secret, payload)

  post :create, body: payload, params: {}, headers: {
    "X-Github-Event" => "pull_request",
    "X-Hub-Signature" => signature,
    "Content-Type" => "application/json"
  }

  # signature check passed against attacker_org's secret (authenticated org)
  authenticated_org = attacker_org

  # but the record actually mutated belongs to victim_repo's org
  pr.reload
  mutated_org = victim_repo.owner

  assert_equal 200, response.status
  assert_equal "PWNED", pr.github_pull_request["title"]
  refute_equal authenticated_org, mutated_org # proves no shared binding ties auth org to mutated org
end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
