### Title
Bad-debt wipeout resurrects supplier claims through the supply-index floor - (File: contracts/pool/src/interest.rs)

### Summary
**High.** A complete bad-debt write-down clamps `supply_index` upward to `SUPPLY_INDEX_FLOOR_RAW` instead of reducing existing supply claims to zero. Stale supply shares therefore retain a claim equal to roughly 0.1% of their pre-wipe value. When a later supplier deposits cash into the empty market, an old supplier can withdraw this phantom claim and receive the new depositor’s tokens.

### Finding Description
`apply_bad_debt_to_supply_index` computes `remaining = total_supplied_value - capped_bad_debt`, derives a reduction factor, and then applies `.max(SUPPLY_INDEX_FLOOR_RAW)` to the result. [1](#0-0) 

When `bad_debt >= total_supplied_value`, `remaining` is zero and the mathematically correct new index is zero, but the floor raises it to `RAY / 1000`. All historical supply shares then continue to unscale to a positive amount. The production seize path reaches this through `PoolSeizeEntry { side: Borrow }`, which unscales the debt, calls `apply_bad_debt_to_supply_index`, and burns the debt shares. [2](#0-1) 

The controller builds cleanup entries from the account’s supply and debt maps and submits them to `pool_seize_positions_call`; liquidation automatically invokes cleanup when the remaining debt is socializable. [3](#0-2) [4](#0-3) 

The repository’s own pool test demonstrates the resulting state transition: a wiped position retains a positive claim after the floor clamp, a fresh deposit supplies real cash, and withdrawal of the old scaled position drains exactly that fresh deposit. [5](#0-4) 

### Impact Explanation
A wiped supplier can steal a subsequent depositor’s funds up to the phantom floor-rounded claim. The old supplier calls `withdraw` after a victim supplies the drained asset; pool accounting recognizes the stale shares, `require_reserves` sees the newly credited cash, and `transfer_out` pays real tokens. [6](#0-5) [7](#0-6) 

This also leaves the market’s books insolvent: the fresh supplier’s scaled claim remains on the books after their cash has been paid to the wiped position. The regression test explicitly asserts that the drained position pays out real tokens and that remaining pool cash cannot cover the fresh supplier’s claim. [8](#0-7) 

### Likelihood Explanation
The path is permissionless once an account reaches the socializable-bad-debt state. An attacker can be both an existing supplier and the owner of a separate borrowing account, borrow the market’s cash against initially sufficient collateral, wait for adverse pricing or interest to make the account insolvent, liquidate it to the dust threshold, and call `liquidate` or `clean_bad_debt` to trigger the borrow-side seize. The attacker’s unrelated supplier position is not burned by that cleanup, so its floor-clamped claim remains withdrawable after the next deposit.

The main precondition is a residual debt write-down at least equal to the market’s total supplied value. This is naturally reachable in a market whose available cash was fully borrowed and whose remaining debt equals or exceeds the aggregate supplier claim, particularly after reserve-factor divergence and interest accrual.

### Recommendation
Do not clamp the post-write-down index upward. If the capped loss consumes all supplied value, write an explicit zero-value state and prevent that market’s historical shares from unscaling to a positive claim; for a partial write-down, use the exact computed index rather than `max(index, SUPPLY_INDEX_FLOOR_RAW)`.

If a zero index must be avoided for arithmetic reasons, mark the market wiped or closed before accepting new `supply`, and ensure cleanup burns or permanently disables every residual scaled supply claim. Add an integration regression covering: full liquidation → `clean_bad_debt` → new `supply` → old supplier `withdraw`, asserting that the old supplier receives zero.

### Proof of Concept
Assumptions use distinct attacker accounts so the supplier position survives the borrower’s cleanup.

1. Attacker supplier account `A` calls:
   ```text
   supply(
     caller = attacker,
     account_id = 0,
     spoke_id = S,
     assets = [({ hub_id = H, asset = TOKEN }, 1_000_000)]
   )
   ```
   This creates a normal supplier position holding scaled shares worth 1,000,000 token units.

2. Attacker borrower account `B` supplies sufficient collateral in another listed asset and calls:
   ```text
   borrow(
     caller = attacker,
     account_id = B,
     borrows = [({ hub_id = H, asset = TOKEN }, 1_000_000)],
     to = attacker
   )
   ```
   The pool’s accounting cash for `TOKEN` is now zero while `A` retains the supplier shares.

3. Price movement or accrued interest makes `B` unhealthy. The attacker or any third party liquidates collateral until the residual position is socializable, then calls:
   ```text
   clean_bad_debt(caller = attacker, account_id = B)
   ```
   The controller submits `B`’s deposit and borrow entries to `Pool::seize_positions`; the borrow entry invokes `apply_bad_debt_to_supply_index`. [3](#0-2) [9](#0-8) 

4. Because the residual debt consumes the entire supplied value, `remaining` is zero, but `new_supply_index` is raised to `SUPPLY_INDEX_FLOOR_RAW`. `A`’s old shares now retain a positive claim instead of being worth zero. [10](#0-9) 

5. Victim `V` supplies `Y <= A_residual_claim`:
   ```text
   supply(
     caller = victim,
     account_id = 0,
     spoke_id = S,
     assets = [({ hub_id = H, asset = TOKEN }, Y)]
   )
   ```

6. Attacker supplier `A` calls a full withdrawal:
   ```text
   withdraw(
     caller = attacker,
     account_id = A,
     withdrawals = [({ hub_id = H, asset = TOKEN }, 0)],
     to = attacker
   )
   ```
   The floor-clamped index converts `A`’s wiped shares into a positive gross withdrawal, `cash >= Y` satisfies the reserve check, and the pool transfers the victim’s real `TOKEN` deposit to the attacker. [11](#0-10)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

            cache.absorb_supply_as_revenue(position);
        }

    cache.commit()
