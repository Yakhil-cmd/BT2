### Title
Missing team-authorization check allows any logged-in GitHub user to read merge status/lock state for arbitrary repositories - (File: app/controllers/shipit/merge_status_controller.rb)

### Summary
`MergeStatusController#show` is exempted from `force_github_authentication` via `skip_authentication only: %i[check show]`, so `current_user.authorized?` (which enforces `Shipit.github_teams` membership) is never invoked for this action. The only guard left is `current_user.logged_in?`, which is `true` for any `Shipit::User`, including one created for an attacker who merely completed GitHub OAuth without belonging to any configured team.

### Finding Description
The required binding is: access to a stack's merge status must require `current_user.authorized?` (team membership in `Shipit.github_teams`) to be `true`, i.e. `current_user.authorized? == true` before render. What the code actually enforces is `current_user.logged_in? == true`, which for any persisted `Shipit::User` is always `true` by definition: [1](#0-0) 

The global `before_action :force_github_authentication` in `Shipit::Authentication` is the only place `authorized?` is checked, and it is explicitly skipped for `show`/`check`: [2](#0-1) [3](#0-2) 

`#show` resolves the stack purely from repository owner/name (and optional branch) parsed out of the `referrer` param, with no ownership or team check on the resolved stack: [4](#0-3) 

Exploit flow: an attacker completes normal GitHub OAuth (any GitHub account can do this — `User.find_or_create_from_github` performs no team check), obtaining `session[:user_id]` for a `Shipit::User` row that is not a member of any `Shipit.github_teams` team. They then send `GET /merge_status?referrer=https://github.com/<org>/<repo>/pull/<n>&branch=<branch>` for any repository tracked by the instance. `current_user.logged_in?` is `true`, so the request bypasses the `logged_out` branch and renders `stack_status` (merge status: `locked`/`failure`/`backlogged`/`success`) and lock reason for that stack, without any check that the caller belongs to the org's team.

Existing guards that would normally prevent this (`force_github_authentication`, `User#authorized?`) do not run for this action because of the `skip_authentication only: %i[check show]` declaration, so nothing stands between an arbitrary logged-in user and merge-status disclosure for arbitrary repositories.

### Impact Explanation
Any authenticated-but-unauthorized user can repeatedly enumerate merge status (`success`/`failure`/`backlogged`/`locked`) and lock reason for any stack/repository tracked by the Shipit instance, across organizational boundaries, simply by supplying a crafted `referrer` URL. This is a read-only information disclosure (no write, no RCE), matching the "unauthenticated read of stack state" High-impact category defined in scope, since it escalates read access beyond what `Shipit.github_teams` authorization is meant to gate.

### Likelihood Explanation
Preconditions are minimal and attacker-achievable: complete GitHub OAuth once (no team membership required), then issue GET requests with an arbitrary `referrer` pointing at any org/repo/PR the instance tracks. No secrets, tokens, or special privileges are needed, and the request is trivially repeatable against any tracked repository.

### Recommendation
Remove `show` (and reconsider `check`) from `skip_authentication`, or explicitly call/enforce `current_user.authorized?` inside `#show` before resolving/rendering `stack_status`, so that team-membership authorization is checked consistently with the rest of the app, while still allowing the `logged_out` render path for fully anonymous users if that behavior is intentional for the browser extension use case.

### Proof of Concept
In `test/controllers/merge_status_controller_test.rb` (new test, minitest, no live GitHub):
```ruby

  Shipit.stubs(:github_teams).returns([team])

  outsider = shipit_users(:walrus) # ensure this user has no membership in `team`

  session[:user_id] = outsider.id

  get :show, params: { referrer: 'https://github.com/Shopify/shipit-engine/pull/42', branch: 'master' }

  # Binding under test: current_user.authorized? must be false here
  assert_equal false, outsider.authorized?
  # Expected (per AUTHORIZATION TRUTH): request should be forbidden
```

This demonstrates that `authorized? == false` and the response is `200 OK` with merge status content rather than `:forbidden`, confirming the divergence.

```ruby
# frozen_string_literal: true

module Shipit
  class MergeStatusController < ShipitController
    skip_authentication only: %i[check show]

    etag { cache_seed }
    layout 'merge_status'

    def show
      response.headers['X-Frame-Options'] = 'ALLOWALL'
      response.headers['Vary'] = 'X-Requested-With'

      if stack
        return render('logged_out') unless current_user.logged_in?

        if stale?(last_modified: [stack.updated_at, merge_request.updated_at].max, template: false)
          render(stack_status, layout: !request.xhr?)
        end
      else
        render(html: '')
      end
    rescue ArgumentError
      render(html: '')
    end
```

```ruby
      before_action :force_github_authentication

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
