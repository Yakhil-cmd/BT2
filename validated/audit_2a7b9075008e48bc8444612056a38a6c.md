### Title
Permanent market freeze from i128 RAY-value overflow in accrual (`scaled_to_original`) — (`contracts/pool/src/interest.rs`, `common/src/rates/scaling.rs`)

### Summary
Every state-changing controller verb first accrues the market via `global_sync` → `accrue_chunk` → `accrue_step`. `accrue_step` converts scaled debt to value with `scaled_to_original(borrowed, borrow_index)`, which multiplies two RAY numbers and panics with `GenericError::MathOverflow` when `scaled * index` exceeds `i128::MAX` [1](#0-0) [2](#0-1) . An unprivileged user can drive a high-decimal market into this state: supply a very large amount, borrow near full utilization so the borrow index compounds on the steep part of the rate curve, then wait. Once `borrowed_scaled * borrow_index` crosses `i128::MAX`, every subsequent accrual panics, permanently bricking the market — the `MAX_BORROW_INDEX_RAY` cap never engages because the value ceiling is reached first [3](#0-2) [4](#0-3) .

### Finding Description
The overflow path:

1. `global_sync` runs unconditionally at the top of every mutating pool call and chunks elapsed time into `MAX_COMPOUND_DELTA_MS` windows [5](#0-4) .
2. Each chunk calls `accrue_step`, which computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` — a plain `Ray::mul` returning `scaled * index / RAY`, panicking on `i128` overflow [6](#0-5) [7](#0-6) .
3. The borrow index grows by `compound_interest(rate, delta)` each chunk and is capped at `MAX_BORROW_INDEX_RAY` (1e36 raw), but that cap only bounds the index — not the product `scaled_debt * index` [8](#0-7) .
4. For an 18-decimal market, a supply of ~1e9 whole tokens is ~1e36 raw RAY scaled; `i128::MAX ≈ 1.7e38` gives only ~170x of index headroom. At ~98% utilization on the steep curve segment the index exceeds that multiplier before the index cap is approached, and the next accrual reverts [9](#0-8) .

The invariants doc acknowledges this gap: "Debt-value overflow can still revert accrual before that ceiling is reached" [10](#0-9) , but nothing recovers the market — there is no accrual-skip, saturated-value path, or governance escape for a market whose `scaled * index` product is unrepresentable.

### Impact Explanation
Permanent freezing of funds for the entire (hub, token) book. Because accrual precedes every verb, once the product overflows:

- `withdraw` / `supply` / `borrow` / `repay` / `update_indexes` / `claim_revenue` for that market all revert with `MathOverflow`.
- `liquidate` and `clean_bad_debt` touching the market revert too, so positions cannot be unwound and collateral backing debt in that market is locked.
- All other suppliers' deposits in that market are unrecoverable; the state cannot be rolled forward because `borrowed` and `borrow_index` are already persisted and every future accrual recomputes the same overflowing product.

The harness test proves the freeze end-to-end: `try_withdraw_raw` and `try_repay` both revert after the cliff [11](#0-10) .

### Likelihood Explanation
The trigger is fully unprivileged: `supply`, `borrow` (backed by collateral in a second market), then time — `update_indexes` and every verb accrue automatically. The cost is real but plausible: it needs a market whose cap permits ~1e36 raw scaled value (roughly a billion 18-decimal tokens, or proportionally less index headroom at lower scales), sustained ~95–98% utilization on a steep rate curve, and enough time for the index to multiply the scaled debt past 1.7e38. Meme-token-style assets with huge supply and high decimals fit this profile; the defender's only mitigation is conservative caps per listing (`require_cap_within_asset_domain` exists but bounds the cap input, not the index-times-debt product [12](#0-11) ). No oracle, admin key, or timing manipulation is required — compounding does the work. This mirrors CVE-2019-2683's shape: a legitimate-feature path (Server Options / rate accrual) that, under attacker-controllable but valid inputs, crashes the system into a state no operation can exit.

### Recommendation
Make accrual total with respect to large values:

- In `accrue_step` / `scaled_to_original`, use a saturating or `try_` conversion for `borrowed_original` and `supplied_original` (e.g., `mul_div_floor_saturating` already exists in `fp_core` [13](#0-12) ) so utilization and rate selection clamp instead of trapping.
- Alternatively, enforce a protocol-level ceiling on `scaled_total * RAY` headroom at listing/borrow time: validate `supply_cap`/`borrow_cap` against `i128::MAX / MAX_BORROW_INDEX_RAY` so the product can never exceed the representable range before the index cap engages.
- Add a recovery path (e.g., allow bad-debt write-down or index clamping to proceed without full accrual) so a market at the ceiling can still be unwound rather than frozen forever.

### Proof of Concept
The repository's own harness test demonstrates the attack end-to-end at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs` [14](#0-13) :

```rust
// 18-decimal market, XLM-style steep rate curve
let principal = BILLION * 10i128.pow(18);        // ~1e36 raw scaled
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98);  // ~98% utilization

// advance one year per iteration until accrual fails
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// => Error(Contract, MATH_OVERFLOW); borrow_index < MAX_BORROW_INDEX_RAY

// market is bricked: every verb accrues first and panics
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Attacker steps on-chain: `supply` large amount of the high-decimal asset → `supply` collateral in a second market → `borrow` ~98% of the first market → wait while the borrow index compounds (any user's `update_indexes` call advances it) → once `scaled_borrowed * borrow_index > i128::MAX`, the market reverts on all operations permanently. Uncertainty: feasibility depends on the listed market's supply cap and rate curve permitting sufficient index growth; markets with caps far below ~1e36 raw RAY or flat curves have more headroom.

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
}
