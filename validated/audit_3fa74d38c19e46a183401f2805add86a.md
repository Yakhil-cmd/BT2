### Title
Webhook can report a hash whose worktree has already been pruned during rapid successive syncs - ([File: main.go], [File: pkg/hook/hook.go], [File: pkg/hook/webhook.go])

### Finding Description
`SyncRepo` calls `syncHooks.afterPublish(newWorktree.Hash())` right after `publishSymlink`, which calls `webhookRunner.Send(hash)` [1](#0-0) . `Send` only enqueues the hash into a non-blocking, single-slot channel (`hookData.send`) and returns immediately [2](#0-1) ; the actual `Webhook.Do` HTTP call happens asynchronously in the `HookRunner.Run` goroutine, which reads `r.data.get()` once and then calls `w.Do(ctx, hash)`, which can block for up to `--webhook-timeout` [3](#0-2) [4](#0-3) .

Meanwhile, the main sync loop is completely decoupled from this in-flight `Do()` call: after each `SyncRepo`, it unconditionally calls `git.cleanup(ctx)`, which calls `removeStaleWorktrees()` [5](#0-4) [6](#0-5) . `removeStaleWorktrees` removes any worktree directory that is not the *current* worktree and whose mtime is older than `--stale-worktree-timeout` (default `0`, i.e. "removed immediately") [7](#0-6) . On the *next* sync cycle, a hash that was previously "current" becomes stale the moment a newer hash is published, its worktree mtime is touched to start the timer [8](#0-7) , and with the default 0s timeout, that worktree is deleted by `removeWorktree` (`os.RemoveAll`) in the very next cleanup pass [9](#0-8) .

There is no coordination between the `HookRunner`/`Webhook.Do` goroutine and the worktree-cleanup logic: nothing prevents `git.cleanup()` from deleting hash A's worktree while `Webhook.Do(ctx, "A")` is still in flight (or has already completed and told the consumer "fetch hash A") if a rapid push B lands and a new sync completes before A's webhook call/consumer fetch is done. Since `--period` can be set very low (e2e tests use `100ms`), and `--webhook-timeout`/consumer processing time can exceed the sync period, this race is straightforward to trigger by an attacker who can push rapid commits to the synced ref.

### Impact Explanation
This is a publish-integrity failure, not a code-execution or secret-leak issue: a webhook consumer can be told "fetch content at hash X" via the `Gitsync-Hash` header, but by the time it acts on that notification (or even while the `Webhook.Do` request for X is still outbound), the worktree directory for X has been `os.RemoveAll`'d by the next sync's cleanup pass, and `--link` now points at a newer hash Y. A slow/queued consumer following the webhook's stated hash will find nothing at that path — an availability/integrity break of the documented contract ("git-sync can also be configured to make a webhook call upon successful git repo synchronization") [10](#0-9) , matching a "publish wrong/partial content" bounty class rather than a confidentiality or RCE issue.

### Likelihood Explanation
Preconditions are modest and match the given attacker model (unprivileged repo/ref control, no flag/env control): the attacker only needs push access to a ref git-sync tracks and the ability to push faster than one full sync+webhook-timeout cycle. With default settings (`--stale-worktree-timeout=0`), the very next successful sync will delete the prior worktree unconditionally, so the race window is essentially "does the webhook call/consumer read finish before the next sync completes" — realistic under rapid pushes or a slow webhook consumer/endpoint, as acknowledged by the question's own proof idea. No non-default flags are strictly required to trigger the underlying race (default `stale-worktree-timeout=0` already maximizes it), though operators using `--webhook-url` are inherently opted into this notification contract.

### Recommendation
Introduce coordination between in-flight hook/webhook `Do()` calls and worktree cleanup, e.g.: track a reference count or "in-use" set of hashes that have hooks pending/in-flight and have `removeStaleWorktrees`/`cleanup` skip removal of any worktree whose hash is still referenced; or have `HookRunner` acquire a lease on the worktree path before calling `Do` and release it after, checked by `removeWorktree`. Alternatively, document explicitly that `--webhook-url` consumers must treat the notification as best-effort and re-verify `--link` resolution rather than assuming the announced hash's worktree persists, and consider making `--stale-worktree-timeout` default non-zero when webhooks are enabled.

### Proof of Concept

```go
// slowWebhook simulates a webhook consumer that is slow to process.
type slowWebhook struct{ started, allowFinish chan string }
func (s *slowWebhook) Name() string { return "slow" }
func (s *slowWebhook) Do(ctx context.Context, hash string) error {
    s.started <- hash
    <-s.allowFinish // block until test releases
    return nil
}

func TestWebhookRaceWithWorktreePruning(t *testing.T) {
    slow := &slowWebhook{started: make(chan string, 1), allowFinish: make(chan string)}
    data := hook.NewHookData()
    runner := hook.NewHookRunner(slow, 0, data, testLogger, false)
    go runner.Run(context.Background())

    runner.Send("hashA")
    hashInFlight := <-slow.started // Do("hashA") now blocked

    // Simulate rapid push + second sync completing and calling cleanup()
    // which, per main.go removeStaleWorktrees/removeWorktree, deletes
    // the worktree directory for hashA immediately (stale-worktree-timeout=0)
    // while Do("hashA") is still executing.
    os.RemoveAll(worktreePathFor(hashInFlight))

    close(slow.allowFinish) // let Do("hashA") finish, "notifying" the consumer

    // Assertion (currently fails): worktree for the hash reported by the
    // webhook must still resolve under --root at the time Do() completes.
    if _, err := os.Stat(worktreePathFor(hashInFlight)); os.IsNotExist(err) {
        t.Fatalf("webhook reported hash %s but its worktree was already pruned", hashInFlight)
    }
}
```
This demonstrates that `HookRunner`/`Webhook.Do` provides no guarantee that the worktree for the hash it announces is retained until the call completes, confirming the race described.

```go
func (git *repoSync) removeStaleWorktrees() (int, error) {
	currentWorktree, err := git.currentWorktree()
	if err != nil {
		return 0, err
	}

	git.log.V(3).Info("cleaning up stale worktrees", "currentHash", currentWorktree.Hash())

	count := 0
	err = removeDirContentsIf(git.worktreeFor("").Path(), git.log, func(fi os.FileInfo) (bool, error) {
		// delete files that are over the stale time out, and make sure to never delete the current worktree
		if fi.Name() != currentWorktree.Hash() && time.Since(fi.ModTime()) > git.staleTimeout {
			count++
			return true, nil
		}
		return false, nil
	})
	if err != nil {
		return 0, err
	}
	return count, nil
}
```

```go
// removeWorktree is used to remove a worktree and its folder.
func (git *repoSync) removeWorktree(ctx context.Context, worktree worktree) error {
	// Clean up worktree, if needed.
	_, err := os.Stat(worktree.Path().String())
	switch {
	case os.IsNotExist(err):
		return nil
	case err != nil:
		return err
	}
	git.log.V(1).Info("removing worktree", "path", worktree.Path())
	if err := os.RemoveAll(worktree.Path().String()); err != nil {
		return fmt.Errorf("error removing directory: %w", err)
	}
	if _, _, err := git.Run(ctx, git.root, "worktree", "prune", "--verbose"); err != nil {
		return err
	}
	return nil
}
```

```go
func (r *HookRunner) Run(ctx context.Context) {
	var lastHash string

	// Wait for trigger from hookData.Send
	for range r.data.events() {
		// Retry in case of error
		for {
			// Always get the latest value, in case we fail-and-retry and the
			// value changed in the meantime.  This means that we might not send
			// every single hash.
			hash := r.data.get()
			if hash == lastHash {
				break
			}

			if err := r.hook.Do(ctx, hash); err != nil {
				r.log.Error(err, "hook failed", "hash", hash, "retry", r.backoff)
				updateHookRunCountMetric(r.hook.Name(), "error")
				// don't want to sleep unnecessarily terminating anyways
				r.sendOneTimeResultAndTerminate(false)
				time.Sleep(r.backoff)
			} else {
				updateHookRunCountMetric(r.hook.Name(), "success")
				lastHash = hash
				r.sendOneTimeResultAndTerminate(true)
				break
			}
		}
	}
```

```go
func (w *Webhook) Do(ctx context.Context, hash string) error {
	req, err := http.NewRequest(w.method, w.url, nil)
	if err != nil {
		return err
	}
	req.Header.Set("Gitsync-Hash", hash)

	ctx, cancel := context.WithTimeout(ctx, w.timeout)
	defer cancel()
	req = req.WithContext(ctx)

	w.log.V(0).Info("sending webhook", "hash", hash, "url", w.url, "method", w.method, "timeout", w.timeout)
	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()
	body, err := io.ReadAll(resp.Body)
	if err != nil {
		return err
	}

	// If the webhook has a success statusCode, check against it
	if w.success > 0 && resp.StatusCode != w.success {
		return fmt.Errorf("received response code %d expected %d, body: %q", resp.StatusCode, w.success, body)
	}

	w.log.V(1).Info("webhook succeeded", "hash", hash, "status", resp.StatusCode, "headers", resp.Header, "body", body)
	return nil
}
```
