### Title
Missing Minimum-Debt-Amount Validation Enables Unliquidatable Dust Debt That Is Later Socialized to All Suppliers - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
The mobile report's root bug class is "insufficient minimum-value validation on user-supplied input, with no safeguard for the resulting weak/degenerate state." The `borrow` function in `mainnet/contracts/market/v0-4-market.clar` has the analogous defect on-chain: it only asserts `amount > u0` and never enforces a minimum notional debt size, so any borrower can open a dust debt position (as low as `1n` base units, confirmed by the test at `local-testing/tests/security/edge-cases.test.ts:212-223`, "should reject borrow that results in dust debt" — which in fact passes with no rejection). Such dust positions cannot be liquidated profitably (the debt/collateral is too small for `liquidate` to compute a non-zero repay/seize amount), and once a position degrades below the point where `coll-final`/`debt-to-repay` round to zero, the position becomes practically unliquidatable, accrues interest indefinitely, and is ultimately resolved via bad-debt socialization that is charged against all suppliers of that asset — harming lenders who had nothing to do with the dust borrower's position.

### Finding Description
`borrow` at [1](#0-0)  validates only:
```
(asserts! (> amount u0) ERR-AMOUNT-ZERO)
(asserts! (get debt asset) ERR-BORROW-DISABLED)
(asserts! (is-healthy collateral-value debt-value current-ltvb) ERR-UNHEALTHY)
```
There is no lower bound on the resulting debt notional (no "minimum debt" / "minimum health-relevant size" check), so a caller can create a position with debt so small that it is economically unliquidatable. This is confirmed by the project's own edge-case test, which borrows `1n` (a single base unit) against a full BTC collateral position and expects (and gets) success rather than a minimum-debt rejection: [2](#0-1) .

Downstream, `liquidate` computes `debt-to-repay` and `coll-final` from rounding/scaling math (`process-debt-asset`, `scale-debt-for-liquidation`, `calc-final-liquidation-amounts`) and then requires both to be strictly positive: `(asserts! (> debt-to-repay u0) ERR-ZERO-LIQUIDATION-AMOUNTS)` and `(asserts! (> coll-final u0) ERR-ZERO-LIQUIDATION-AMOUNTS)` at [3](#0-2) . For a position whose debt/collateral values are dust, this math can round these amounts to zero, making the position rejected by every liquidator attempt (`ERR-ZERO-LIQUIDATION-AMOUNTS`), i.e. it becomes stuck: unhealthy but not liquidatable by anyone.

If/when such a stuck position eventually has all its collateral removed by other means (or its collateral is fully consumed in a partial liquidation of another asset in the position) the code path for full write-off triggers: `no-collateral-left` and the bad-debt socialization fold `socialize-debt-asset` over `fresh-debt-list`, emitting `bad-debt-socialized` and mutating shared vault/index state that is paid for by all suppliers of that debt asset, as seen at [4](#0-3) .

The shared state harmed is the debt asset's supplier-side index/liquidity in `market-vault` — an unprivileged borrower (attacker or simply a careless user, mirroring the "weak password" user) creates a dust/degenerate position, and unprivileged liquidators/suppliers (victims) bear the consequence: liquidators cannot earn the bonus reward on it (their capital/gas is wasted attempting), and suppliers absorb the eventual bad-debt write-off.

### Impact Explanation
This lands in **High** — temporary freezing of funds / theft of unclaimed yield: the dust debt continues to accrue interest that suppliers are owed but that principal is never collectible (frozen/unclaimed yield), and if/when write-off triggers, the loss is socialized directly onto suppliers' shared pool balance, which is a loss they did not cause and cannot avoid. It is not Critical because the position sizes reachable this way are inherently dust-sized (bounded by rounding thresholds), limiting aggregate loss per position, but it is systemic since any number of dust positions can be opened at negligible cost.

### Likelihood Explanation
Likelihood is Medium: opening a dust-debt position costs only gas and a marginal amount of collateral, requires no special privilege, and the existing test suite already demonstrates the codebase accepts `amount = 1n` as a valid borrow with no minimum-debt guard ( [2](#0-1) ). An attacker (or many uncoordinated ordinary users) could repeatedly open such positions, and liquidators naturally have no incentive to attempt liquidating them since `ERR-ZERO-LIQUIDATION-AMOUNTS` blocks profitless liquidations.

### Recommendation
Enforce a protocol-level minimum debt notional (in USD terms, analogous to enforcing a minimum password length) in `borrow`, alongside the existing `ERR-AMOUNT-ZERO`/health checks in `mainnet/contracts/market/v0-4-market.clar`, e.g. reject `debt-increase`/`debt-post-increased` below a `MIN-DEBT-USD` threshold sized so that `process-debt-asset`/`calc-final-liquidation-amounts` in `liquidate` can never legitimately round `debt-to-repay` or `coll-final` to zero for a liquidatable position. This prevents dust positions from ever reaching the unliquidatable/write-off path that ultimately socializes losses to suppliers.

### Proof of Concept
1. Alice deposits substantial sBTC collateral via `collateral-add`.
2. Alice calls `borrow` on USDC with `amount = 1` (or another dust value below any meaningful minimum) — this succeeds today since only `(> amount u0)` is checked, per [5](#0-4)  and the passing test [2](#0-1) .
3. BTC price drops so Alice's dust position crosses into the liquidation zone.
4. A liquidator calls `liquidate`; because `debt-actual`/`coll-actual` are computed from dust-sized `debt-amount`, `process-debt-asset` and `calc-final-liquidation-amounts` can yield `debt-to-repay = 0` or `coll-final = 0`, tripping `ERR-ZERO-LIQUIDATION-AMOUNTS` at [3](#0-2)  and reverting every liquidation attempt.
5. The unhealthy dust position remains open, continuing to accrue debt interest that suppliers are entitled to but can never collect; if collateral is eventually fully exhausted by other flows, the `bad-debt-socialized` path at lines 1534-1560 writes the loss onto the shared supplier pool for that asset — a cost borne entirely by uninvolved suppliers, not the position's own owner.
