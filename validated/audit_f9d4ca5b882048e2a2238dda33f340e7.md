### Title
Webhook signature verification keys off `repository.owner.login`, but handlers act on the unrelated `repository.full_name` field — cross-repository sync/write via a spoofed payload - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/org config (and thus which webhook secret) to HMAC-verify a delivery against using `repository_owner`, taken straight from the unverified JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). Every handler, however, resolves the actual `Stack`/`Repository` to act on using a *different* field of the same unverified body: `Handler#repository_name` = `payload.dig('repository','full_name')`. Because the HMAC only proves the payload was signed with the secret configured for whichever org name the attacker put in `repository.owner.login`, nothing ties that verified org to the `repository.full_name` that handlers subsequently trust to pick a target repo/stack.

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb` does: [1](#0-0) [2](#0-1) 

`repository_owner` is read from the same request body that is being verified, before verification succeeds, and is used only to pick *which* GitHub App config (`Shipit.github(organization: repository_owner)`) — and hence which `webhook_secret` — the HMAC in `X-Hub-Signature` must match: [3](#0-2) 

Once the signature check passes, `create` dispatches the *entire* raw payload to handlers: [4](#0-3) 

Every default handler (`PushHandler`, `PullRequest::*Handler`, `StatusHandler`, `CheckSuiteHandler`, etc.) resolves the target `Repository`/`Stack` via `Handler#repository_name`/`#stacks`, which reads `repository.full_name`, a field completely independent from `repository.owner.login`: [5](#0-4) 

`PushHandler#process` uses that repository/stack lookup to trigger a GitHub sync against arbitrary matching stacks: [6](#0-5) 

`PullRequest::OpenedHandler` similarly re-derives the repository from `params.repository.full_name` and provisions/updates review stacks for it: [7](#0-6) 

**Binding broken (equality that should hold but doesn't):**
`organization authenticated by HMAC (repository.owner.login used to select the secret)` == `repository/organization whose stack state handlers mutate (repository.full_name)`.

Before the attacker's request: the code implicitly assumes these two fields always agree because legitimate GitHub deliveries populate both consistently from the real repository object. After a crafted request: an attacker who legitimately owns/administers *any* GitHub organization/repository that has a Shipit webhook configured (i.e., they know that org's `webhook_secret`, which is a normal, unprivileged capability of being an org admin for their own org) can POST directly to `/webhooks` (mounted unauthenticated for any origin, see `resources :webhooks, only: :create` in `config/routes.rb`) with a hand-crafted JSON body where `repository.owner.login` = their own org (so the correct/known secret is used for the HMAC) but `repository.full_name` = a victim org/repo tracked by the same Shipit instance. The signature check passes because it only validates against the secret for the attacker's own org; nothing checks that `full_name` is actually owned by that same org.

### Impact Explanation
This lets an attacker with no access to the victim's GitHub repository or Shipit credentials trigger repository-scoped actions against a victim `Stack` they don't control, satisfying "cross-repository writes":
- Force `GithubSyncJob`/`stack.sync_github` runs on arbitrary branches of a victim stack via `PushHandler` (state pollution of an unrelated repo's tracked commits).
- Trigger `ReviewStackAdapter#find_or_create!` provisioning flows for a victim repository via the PR handlers, creating/mutating review stacks that don't belong to the attacker.
- Any other handler keyed off `repository.full_name` is similarly reachable.

This is a genuine authentication/authorization binding failure: the HMAC signature is supposed to bind the payload to a specific trusted GitHub organization, but the code trusts an unrelated, unverified field from the same payload to decide what is acted on.

### Likelihood Explanation
Requires only that the attacker administers some GitHub org/repo already configured as a webhook source for the same Shipit instance (a common multi-tenant Shipit deployment scenario), which is not a privileged Shipit credential, ApiClient token, or GITHUB_TOKEN — it is ordinary control over one's own GitHub webhook settings. Crafting the JSON body and computing a valid HMAC with a secret they legitimately know is straightforward with any HTTP client; GitHub's normal UI is not required since the endpoint accepts any POST matching the signature.

### Recommendation
After signature verification succeeds, re-derive/require that `repository.full_name`'s owner matches the `repository_owner`/organization whose secret verified the request (or, better, resolve the target repository strictly from a trusted, out-of-band mapping — e.g. the GitHub App installation ID — rather than from attacker-suppliable JSON fields). Reject the webhook if the owner encoded in `full_name` doesn't match the organization used for signature verification.

### Proof of Concept
1. Attacker controls `github-org-attacker`, which has a Shipit webhook configured with secret `S` (known to the attacker as the org admin).
2. Attacker builds a payload:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef...",
  "repository": {
    "owner": { "login": "github-org-attacker" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC(S, body)` — valid because `verify_signature` looks up the secret using `repository.owner.login = "github-org-attacker"`. [1](#0-0) 
4. POST to `/webhooks` with `X-Github-Event: push`. Signature check passes.
5. `PushHandler` resolves `stacks` via `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on stacks the attacker never authenticated for. [6](#0-5) [5](#0-4)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
