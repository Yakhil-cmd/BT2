### Title
Stack-scoped API token can read CCMenu build status of any stack, bypassing its `stack_id` authorization scope - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::ApiClient` tokens can be scoped to a single stack via `stack_id` [1](#0-0) . Every other API controller resolves the target stack through the `stacks` helper in `BaseController`, which restricts lookups to `Stack.where(id: current_api_client.stack_id)` when the token is stack-scoped [2](#0-1) . `Api::CCMenuController`, however, overrides `stack` to resolve directly via the unscoped `Stack.from_param!(params[:stack_id])`, and overrides `authenticate_api_client` to authenticate by a bare token parameter instead of Basic Auth [3](#0-2) . This is the equivalent binding break called out in the rules: "a stack a token authorises versus a stack it touches" — the token's `read:stack` permission is checked, but the specific stack it is bound to (`current_api_client.stack_id`) is never checked against the requested `stack_id`.

### Finding Description
- `ApiClient#check_permissions!` only validates that the required permission string (e.g. `read:stack`) is present in `permissions`; it never validates which stack the permission applies to [4](#0-3) .
- Scope-to-stack enforcement happens exclusively in `BaseController#stacks`/`#stack`, which every other controller (`StacksController`, `DeploysController`, `TasksController`, etc.) relies on to filter the queryable `Stack` relation by `current_api_client.stack_id` [2](#0-1) .
- `Api::CCMenuController` does not call `stacks.from_param!`; it calls `Stack.from_param!(params[:stack_id])` directly, an unscoped class-level lookup, so any `stack_id` in the URL is resolved without regard to `current_api_client.stack_id` [5](#0-4) .
- The controller still declares `require_permission :read, :stack`, which only checks that the permission bit exists on the token — a stack-scoped token created with just `read:stack` (e.g. via `CCMenuUrlController`, which mints such tokens: `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` bound implicitly to a specific stack context) will pass this check for a request naming a completely different `stack_id` [6](#0-5) .
- Authentication for this controller also bypasses HTTP Basic Auth used elsewhere; it authenticates purely from `params[:token]` [7](#0-6) , matching the "GitHub identity vs. `User` bound to session"-style credential/consumer mismatch called out by the rules, applied here to stack-scoped API clients.

Before the attacker's request: a `stack_id`-scoped `ApiClient` token with only `read:stack` is expected to be usable solely to fetch CCMenu XML for its own bound stack (equality: `token.stack_id == requested.stack_id`).
After: because `Api::CCMenuController#stack` performs an unscoped `Stack.from_param!`, that equality is never enforced, so `token.stack_id != requested.stack_id` is accepted, breaking the binding.

### Impact Explanation
This grants unauthenticated (from the target-stack's perspective) read access to another stack's build/deploy state — specifically last build status, last build label, last build time, activity, and web URL — for any stack in the Shipit instance, using only a token that was authorized for one specific, unrelated stack. This matches the "High" impact category explicitly listed in scope: "unauthenticated read of stack state." It discloses deployment status/activity across repositories the token holder was never granted access to, which is an authorization boundary violation of the deployment-trust model (token scope vs. stack accessed).

### Likelihood Explanation
Likelihood is high: `CCMenuUrlController#fetch` is a normal authenticated user-facing feature that mints exactly this kind of stack-scoped, `read:stack`-only token and exposes its `token` value as a URL query parameter meant to be embedded in third-party CI dashboard tools [8](#0-7) . Any holder of such a token (which is designed to be shared/embedded in external tooling, unlike Basic Auth secrets) can trivially enumerate other `stack_id` params in the `?token=...` query string against the CCMenu API endpoint and read cross-stack build state, with no code change or privilege required beyond possessing one legitimately-issued CCMenu token.

### Recommendation
Have `Api::CCMenuController#stack` resolve through the scoped `stacks` helper (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!`, so that stack-scoped tokens are restricted to their bound stack exactly as in every other API controller. If unscoped lookups are intentionally desired for unscoped tokens, explicitly check `current_api_client.stack_id.nil? || current_api_client.stack_id == stack.id` before rendering.

### Proof of Concept
1. As an authenticated Shipit user with access to `stack_a`, visit the CCMenu URL feature to mint a token: `GET /stacks/stack_a/ccmenu_url` → creates (or reuses) an `ApiClient` with `permissions: ['read:stack']`, effectively bound to `stack_a`, and returns `token=<T>` [9](#0-8) .
2. Using `<T>`, issue: `GET /api/stacks/<stack_b_owner>/<stack_b_repo>/<stack_b_env>/ccmenu.xml?token=<T>` for an unrelated `stack_b` that the token was never scoped to.
3. `authenticate_api_client` succeeds via `ApiClient.authenticate(params[:token])` [7](#0-6) , `require_permission :read, :stack` passes because the token has `read:stack` [10](#0-9) , and `stack` resolves `stack_b` via the unscoped `Stack.from_param!` [11](#0-10) , returning `stack_b`'s CCMenu XML (build status, label, timestamp) despite the token only being authorized for `stack_a`.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
