### Title
Unfiltered pull request label names injected as environment variables allow fork PR authors to set `RUBYLIB` (or other sensitive env vars) on deploy-host command execution - (File: `app/models/shipit/review_stack.rb`)

### Summary
`ReviewStack#env` merges every PR label name (uppercased) directly into the stack's environment hash with no key allowlist, and that hash is merged unfiltered into `Command#unbundled_env`, which is passed straight to `PTY.spawn`. Because the fork PR author fully controls both the label names and the checked-out working directory content, they can set `RUBYLIB=true` (or `RUBYOPT`, `BUNDLE_GEMFILE`, `LD_PRELOAD`, etc.) and combine it with a matching file placed at a relative path in their own branch to hijack `require` resolution during any ruby-invoking step (including `deploy.variables`-adjacent deploy/dependency steps).

### Finding Description
The broken binding: the set of environment variable **keys** reaching `PTY.spawn` for a review-stack task should equal `Shipit.env ∪ {fixed Shipit-defined keys} ∪ deploy_spec.machine_env ∪ (task.env filtered by EnvironmentVariables#permit against deploy.variables whitelist)`. In fact it equals that set **∪ {label_name.upcase for every PR label}**, with no filtering at all.

Code path:
- `ReviewStack#env` (`app/models/shipit/review_stack.rb:84-93`) does:
```ruby
super.merge(pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" })
```
No allowlist, no denylist, no validation of `label_name`.
- `LabelCapturingHandler#capture_labels` (`app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb:98-102`) persists label names taken verbatim from the incoming webhook body (`params.pull_request.labels.map(&:name)`) for `opened`/`labeled`/`unlabeled`/`reopened` events on active (non-archived) stacks — this fires regardless of `provisioning_behavior` (`allow_all`, `allow_with_label`, or `prevent_with_label`), since `capture_labels?` only checks stack presence/archived state, not the provisioning label check performed by `OpenedHandler`/`LabeledHandler`.
- `TaskCommands#env` (`lib/shipit/task_commands.rb:33-48`) merges `@stack.env` (line 35) directly — this is a separate merge path from `@task.env` (line 47), which is the only path subject to `EnvironmentVariables#permit`/the `deploy.variables` whitelist (`lib/shipit/environment_variables.rb:13-44`). The whitelist mechanism therefore never sees or filters label-derived keys.
- `Command#unbundled_env` (`lib/shipit/command.rb:103-105`) does `BASE_ENV.merge(...).merge(@env.stringify_keys)` with no key filtering, and `Command#start` (`lib/shipit/command.rb:85-101`) passes this directly to `PTY.spawn`.

Attacker request: an unprivileged fork owner opens a PR (or labels their own open PR) against a repo with `provisioning_behavior = prevent_with_label`, applying a label named `rubylib` (any case) to their own PR, and places a file such as `true/openssl.rb` (or any library name expected to be `require`d by a deploy/dependency step) in their fork branch content.

Why guards fail: `prevent_with_label`'s label check (`pull_request_has_provisioning_label?` in `labeled_handler.rb`/`opened_handler.rb`) only gates *provisioning* (archive/unarchive), not label capture or env exposure — `LabelCapturingHandler` runs independently and unconditionally records all label names for active stacks. `EnvironmentVariables#permit` — the only sanitization primitive in the codebase — is wired to `@task.env`, not `@stack.env`, so it never inspects label-derived keys.

### Impact Explanation
The attacker (unprivileged fork PR author) can set arbitrary env-variable **names** (value fixed to the string `"true"`) on the Shipit deploy host process for their own review stack's tasks/deploys. Combined with full control over the checked-out working directory (their fork branch), setting `RUBYLIB=true` causes Ruby's `$LOAD_PATH` to include the relative directory `true` under the command's `chdir`; any `require` of a library name that collides with a file the attacker placed at `<workdir>/true/<name>.rb` during a deploy/dependency/task step executes attacker-controlled Ruby code in the deploy host process — Remote Code Execution on the Shipit deploy host. This is scoped to the attacker's own review stack (their own fork/PR), but is fully repeatable per-PR/per-label-edit and requires no privileges, session, or Shipit secret. It matches the Critical RCE class via `Command`/`PTY.spawn`.

### Likelihood Explanation
Preconditions: a repository with review stacks enabled (any `provisioning_behavior`, since label capture isn't gated by the provisioning label check) and at least one deploy/dependency/task step in the review stack's `shipit.yml` that invokes ruby with a `require` reachable by a relative-path collision. Attacker cost is trivial: open a PR from a fork, add a label, and include a crafted file in the branch — no secrets, no maintainer approval, no Shipit session needed. The exact RCE trigger (a require collision) depends on the deploy scripts in use, but the core defect — arbitrary env-variable key injection into the spawned process with no allowlist — is unconditionally reproducible and independently dangerous (also allows setting `BUNDLE_GEMFILE`, `RUBYOPT`, `GEM_HOME`, etc.).

### Recommendation
Do not merge raw pull-request label names into the process environment. Either:
1. Remove label-derived keys from `ReviewStack#env` entirely, or
2. Apply a strict allowlist/prefix (e.g., require label names to match `SHIPIT_LABEL_*` and reject/ignore any label colliding with security-sensitive variable names such as `RUBYLIB`, `RUBYOPT`, `LD_PRELOAD`, `BUNDLE_GEMFILE`, `PATH`, `GEM_HOME`, `GEM_PATH`), and
3. Route the resulting hash through `EnvironmentVariables#permit` (or an equivalent explicit whitelist) before merging into `TaskCommands#env`, closing the gap where `@stack.env` bypasses the `deploy.variables` sanitization applied to `@task.env`.

      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)

        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)

      rescue Errno::EACCES

      end
      @started = true
      self
    end

```ruby
    def permit(variable_definitions)
      return {} unless @env
      raise "A whitelist is required to sanitize environment variables" unless variable_definitions

      sanitize_env_vars(variable_definitions)
    end

    def interpolate(argument)
      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
    end

    private

    def initialize(env)
      @env = env
    end

    def sanitize_env_vars(variable_definitions)
      allowed_variables = variable_definitions.map(&:name)

      allowed, disallowed = @env.partition { |k, _| allowed_variables.include?(k) }.map(&:to_h)

      error_message = "Variables #{disallowed.keys.to_sentence} have not been whitelisted"
      raise NotPermitted, error_message unless disallowed.empty?

      allowed
    end
```
