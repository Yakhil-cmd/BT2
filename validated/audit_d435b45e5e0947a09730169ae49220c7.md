### Title
Unvalidated swap routes can execute malicious contracts under the caller’s authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The controller accepts an opaque caller-supplied `StrategySwap` byte payload and forwards it to the configured swap router without constraining which venue or pool contracts the route may invoke. [1](#0-0) [2](#0-1)  A route-named malicious contract can request authorization from the account that signed the lending operation, causing simulation to attach an unrelated token transfer as a child of the caller’s signed authorization tree. [3](#0-2) 

### Finding Description
`swap_collateral` authenticates `caller`, authorizes the caller as the account owner or delegate, withdraws collateral, and passes the user-controlled `swap` payload into the router path. [4](#0-3)  `swap_tokens` grants the router only the controller’s exact input transfer, but it places no restriction on which contracts the route subsequently invokes and validates only controller input/output balances. [5](#0-4)  Because `caller.require_auth()` establishes authorization for the whole controller invocation, a malicious venue invoked below the router can make `token.transfer(caller, attacker, amount)`; transaction simulation records that call as a child of the caller’s controller authorization. [6](#0-5) [3](#0-2)  The same poisoned authorization tree then permits that unrelated wallet-token transfer while the swap itself still returns a valid measured output. [7](#0-6) 

### Impact Explanation
A victim who submits an attacker-supplied or otherwise poisoned route can lose arbitrary token balances held by the caller address, including assets that are unrelated to the lending market and never deposited in the protocol. [8](#0-7)  The loss is not limited to the swapped collateral: the harness demonstrates theft of the caller’s full unrelated wallet-token balance while preserving the fair swap output and final position. [8](#0-7) 

### Likelihood Explanation
Any unprivileged user can reach this path through `swap_collateral`; equivalent route-bearing entrypoints include `multiply`, `swap_debt`, and `repay_debt_with_collateral`. [9](#0-8) [10](#0-9)  Exploitation requires the victim to authorize a route whose simulated authorization tree contains the malicious child call, so wallet/client validation and user behavior affect likelihood, but neither the controller nor the measured-output checks prevent the poisoning. [3](#0-2) 

### Recommendation
Restrict route execution to protocol-registered, audited venue contracts rather than accepting arbitrary route-address registries. The route format should bind each hop to an allowlisted venue/pool identity, reject unknown addresses before external dispatch, and ensure strategy clients display and verify the complete authorization tree before signing. Until venue identities are constrained on-chain, clients must treat any unexpected child authorization as fatal rather than relying on swap output validation.

### Proof of Concept
1. Deploy `RogueHopPool` configured with `(victim, wallet_token, attacker, amount)` so its `swap` function calls `wallet_token.transfer(victim, attacker, amount)`. [11](#0-10) 
2. Construct a route that names the rogue contract as its hop pool while still returning a fair output token amount. [12](#0-11) 
3. Have the victim invoke `swap_collateral(caller=victim, account_id, current=USDC, amount, new=ETH, swap=route)`. [13](#0-12) 
4. During simulation, the rogue pool’s token transfer is recorded under the victim’s `swap_collateral` authorization root. [14](#0-13) 
5. If that simulated tree is signed, the transaction succeeds, pays the expected swap output, and moves the victim’s unrelated wallet tokens to the attacker. [7](#0-6)

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
