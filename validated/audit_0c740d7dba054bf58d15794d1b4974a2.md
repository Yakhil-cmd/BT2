### Title
Webhook signature verification authenticates the payload's `repository.owner.login` but event handlers act on the independently-attacker-controlled `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to verify the HMAC signature against using `repository_owner`, derived from `params.dig('repository', 'owner', 'login')` (falling back to `params.dig('organization', 'login')`). However, once the signature check passes, event handlers (e.g. `PushHandler`) resolve which `Stack`/`Repository` to act on using a *different* field of the same JSON payload: `payload.dig('repository', 'full_name')`, via `Handler#repository_name` / `Repository.from_github_repo_name`. In a multi-organization Shipit deployment (`Shipit.github_organizations`, per-org `webhook_secret` in `config/secrets.yml`), these two fields are never checked for consistency.

### Finding Description
The equality the engine implicitly relies on is:
`organization authenticated by webhook_secret == organization of the repository the handler writes to`

This equality is not enforced. The relevant code: [1](#0-0) [2](#0-1) 

`verify_signature` fetches `github_app = Shipit.github(organization: repository_owner)` and verifies the raw body's HMAC against that organization's specific `webhook_secret`: [3](#0-2) 

Per-organization secrets are configured independently in `secrets.github` (`Shipit.github_app_config`): [4](#0-3) 

Once `verify_signature` succeeds, `WebhooksController#create` dispatches the *entire, unmodified* raw JSON payload to handlers: [5](#0-4) 

Handlers determine the target `Stack` using `repository.full_name`, not `repository.owner.login`: [6](#0-5) 

`Repository.from_github_repo_name` splits `full_name` on `/` and looks up by `owner`/`name` independently of which organization's secret verified the request: [7](#0-6) 

Because a legitimate webhook subscriber for organization A (an attacker who controls their own GitHub organization/App configured as a valid Shipit `github` entry) knows their own organization's `webhook_secret`, they can craft an arbitrary payload with `repository.owner.login` = `"org-a"` (so `verify_signature` selects and successfully verifies against `org-a`'s known secret) while setting `repository.full_name` = `"org-b/victim-repo"` (a repository belonging to a different, victim organization tracked by the same Shipit instance). The signature only covers "did I sign this raw body with a secret I know" — it never binds the signing organization to the `repository.full_name` field the handlers actually trust.

### Impact Explanation
This breaks the deployment-trust binding between "which organization authenticated the webhook" and "which repository/stack is written to." For `push` events, `PushHandler` (via `Handler#stacks`) enqueues `GithubSyncJob` against any stack matching the forged `full_name`, which resyncs commits and can advance the deploy queue for a repository the requester's organization does not actually own. Other events (`status`, `check_suite`, `membership`, `pull_request`, etc.) similarly key off attacker-controlled payload fields once past `verify_signature`, potentially triggering state changes (commit statuses, check-run refreshes, team/membership synchronization) scoped to a stack belonging to an organization the attacker does not control. This is an authentication-binding bypass: the org that "signed" is not the org whose data is mutated, letting an attacker with only their own legitimate (but lower-privileged) org webhook credentials affect another tracked organization's repository/stack state.

### Likelihood Explanation
Requires the Shipit instance to be configured with the multi-organization schema (`secrets.github` keyed by organization, each with its own `webhook_secret`), which the engine explicitly supports (`Shipit.github_organizations`, `TOP_LEVEL_GH_KEYS`), and requires the attacker to control (or have compromised) a GitHub App/organization already integrated as one of the configured `github` entries — a realistic scenario for platforms hosting multiple orgs. No `ApiClient` token, `github_access_token`, or repository write access on the target org's GitHub side is required; only a valid webhook secret for *any one* configured organization.

### Recommendation
When verifying the webhook signature, bind the resolved organization to the repository actually being acted upon: after `Shipit.github(organization: repository_owner)` verifies the signature, re-derive the owner from `repository.full_name` as well and reject the request (422) if `repository.full_name`'s owner segment does not case-insensitively match `repository_owner` (or `organization.login`) used for secret selection. Enforce this in `WebhooksController#verify_signature` before dispatching to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`.

### Proof of Concept
1. Shipit is configured with two organizations in `secrets.github`: `org-a` (attacker-controlled GitHub App, known `webhook_secret_a`) and `org-b` (victim, tracked stacks for `org-b/victim-repo`).
2. Attacker crafts a payload:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker chosen sha>",
  "repository": {
    "full_name": "org-b/victim-repo",
    "owner": { "login": "org-a" }
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(webhook_secret_a, raw_body)>` since they legitimately know `webhook_secret_a`.
4. POST to `/webhooks` with `X-Github-Event: push`.
5. `WebhooksController#verify_signature` computes `repository_owner` = `"org-a"`, calls `Shipit.github(organization: "org-a")`, and the signature verifies successfully against `webhook_secret_a`.
6. `create` dispatches the full payload to `PushHandler`, which calls `Handler#stacks` → `Repository.from_github_repo_name("org-b/victim-repo")`, resolving org-b's actual `Stack`, and enqueues `GithubSyncJob` for it with attacker-supplied `expected_head_sha`, even though the request was never signed by org-b's secret.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
