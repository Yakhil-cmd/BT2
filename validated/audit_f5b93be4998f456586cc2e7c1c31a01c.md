### Title
`compute_v2_review_set` drops non-linear (amended/rebased) commits from the Stop-hook review set, letting an attacker's git operations hide a dangerous change permanently - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only folds commits made during a turn into the reviewable `dirty_now` set when `head_at_capture` is a strict ancestor of the current `HEAD` [1](#0-0) . Any normal git operation that produces a non-linear history from the captured baseline (e.g. `git commit --amend`, `git rebase`, `git reset --hard` + recommit) causes this ancestry check to fail, the working tree to be clean, and `dirty_now` to end up empty — silently excluding the dangerous file from `review_set` even though `changed_since` (diff vs `baseline_sha`) still contains it, because `review_set = dirty_now & changed_since` [2](#0-1) .

### Finding Description
The Stop hook calls `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)` to determine which files to send to the LLM security reviewer [3](#0-2) .

Inside `compute_v2_review_set`:
- `tracked_dirty`/`untracked` come from `git status` vs the *current* `HEAD` (working-tree dirtiness only) [4](#0-3) .
- Commits made during the turn are only added to `dirty_now` via `_git_name_only(repo, f"{head_at_capture}..HEAD")` **when `_is_ancestor(repo, head_at_capture, current_head)` is true** [5](#0-4) .
- `review_set = dirty_now & changed_since` — an **intersection**, not a union, so anything missing from `dirty_now` is dropped regardless of what `changed_since` (diff against the stash baseline SHA) contains [6](#0-5) .

If, after committing a dangerous change, the agent (driven by attacker-controlled repository content, e.g. a prompt-injection payload in a README/issue/PR that Claude reads and acts on, or simply ordinary developer git usage that an attacker can induce) performs `git commit --amend`, a rebase, or a reset+recommit, the new `HEAD` is a sibling of `head_at_capture`, not a descendant. `_is_ancestor` then returns `False`, the amended commit's file changes never enter `dirty_now`, and since the working tree is clean post-commit, `dirty_now` is empty. The intersection with `changed_since` is therefore empty, `review_paths` is `[]`, and the Stop hook exits at `_skip(9)` ("empty review set") [7](#0-6)  — the LLM review never runs on the dangerous file.

Because `_skip(9)` returns without updating `baseline_sha` [8](#0-7)  but `consume_stop_state` has already cleared `touched_paths` for this turn [9](#0-8) , the next `UserPromptSubmit` sees `touched_paths` empty and unconditionally re-captures a fresh baseline SHA that already includes the amended/rebased commit [10](#0-9) . From that point on the dangerous change is baked into the baseline and will never again appear as "changed since baseline" — it is permanently treated as old, pre-existing code and is never reviewed by the LLM security analysis, regardless of how many future turns occur.

### Impact Explanation
The security-guidance Stop hook is the mechanism that inspects Claude's session-generated diff for dangerous patterns (secrets, command injection, SQLi, etc.) and forces Claude to continue/fix via exit code 2 before completing the turn [11](#0-10) . By exploiting the non-linear-history gap in `compute_v2_review_set`, a dangerous file change introduced via a normal commit followed by `amend`/`rebase`/`reset+recommit` is never sent for review and is folded into the "safe" baseline for all subsequent turns. This defeats the plugin's core invariant — that all code changed during a session must eventually pass through the review window — allowing a dangerous command/code change to persist undetected, which is consistent with an unauthorized local command execution bypassing the plugin's review/deny guidance.

### Likelihood Explanation
The precondition is only "normal git operations in a cloned repo" (commit + amend/rebase/reset), which requires no elevated privilege, no secrets, and no social engineering — any turn in which Claude (potentially steered by attacker-supplied repository content) performs a history-rewriting git operation after making the dangerous edit will trigger this. This is a common and unremarkable sequence of git commands, making the condition easily and repeatably reachable.

### Recommendation
Do not gate commit-diff inclusion on strict ancestry. Compute the set of files changed between `baseline_sha` (the pre-turn stash/HEAD snapshot) and the current `HEAD`/worktree directly (e.g. via `_git_name_only(repo, baseline_sha)` already computed as `changed_since`) and use that as (or union it into) `dirty_now`, rather than intersecting a possibly-empty `dirty_now` with `changed_since`. At minimum, when `_is_ancestor` is `False` (history diverged), fall back to including `_git_name_only(repo, baseline_sha)` directly in the review set instead of silently dropping the turn's commits.

### Proof of Concept
Integration/unit test plan (extends the existing `compute_v2_review_set` test suite):
1. Init a git repo, create initial commit (`HEAD0`).
2. Capture baseline via `capture_git_baseline` → `baseline_sha`, `head_at_capture = HEAD0`.
3. Write a dangerous file (e.g. `os.system(user_input)`), `git add` + `git commit` → `HEAD1`.
4. Amend the commit: `git commit --amend -m "amended"` → `HEAD2` (sibling of `HEAD1`, not descendant of `HEAD0`... note `HEAD0` is still ancestor of `HEAD2` if amend keeps same parent — use `git rebase`/`git reset --hard HEAD0 && git commit` to force true non-ancestor case, or amend twice to diverge further via `--no-edit` + interactive rebase changing parent).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture)`.
6. Assert (currently failing) that the dangerous file path IS in the returned `review_paths` list — expected: `review_paths` should be non-empty and include the dangerous file, but current code returns `[]` because `dirty_now` is empty and intersecting with `changed_since` yields `∅`.
7. Follow-up assertion: run `handle_user_prompt_submit` for the next turn and confirm `baseline_sha` now equals a SHA that already contains the dangerous commit, proving the change is permanently absorbed into "reviewed/old" state without ever having been analyzed.

def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap
```

    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface

    if baseline_sha:

## How the git baseline works

On each UserPromptSubmit, the plugin runs `git stash create` to get a SHA representing
the current working tree state (HEAD + any uncommitted changes). This SHA is saved to
the session state file. When the Stop hook fires, it runs `git diff <baseline_sha>` to
get only the changes made since that snapshot. After analysis, the baseline is updated
so the next Stop hook iteration only sees new changes.
```
