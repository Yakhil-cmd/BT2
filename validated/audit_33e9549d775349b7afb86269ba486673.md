### Title
Asset Hub Kusama nomination-pools `TotalUnbondingPools` bound can shrink and corrupt existing sub-pool storage on `AreNominatorsSlashable` flip - (File: system-parachains/asset-hubs/asset-hub-kusama/src/staking/nom_pools.rs)

### Summary
Asset Hub Kusama's nomination-pools config still hardcodes `PostUnbondingPoolsWindow = ConstU32<4>`, unlike Asset Hub Polkadot which was patched to compute this value dynamically after the same bug was reported (bugbounty report #90, fixed in PR #1201). If Kusama governance ever sets `AreNominatorsSlashable` from `true` to `false`, `nominator_bonding_duration()` drops from 28 to `NominatorFastUnbondDuration` (2) [3](#0-2) , shrinking the pallet's derived `TotalUnbondingPools` bound (`bonding_duration() + PostUnbondingPoolsWindow`) from 32 to 6.

### Finding Description
`pallet_nomination_pools::SubPools::with_era` is a bounded map sized by `TotalUnbondingPools = StakeAdapter::bonding_duration() + PostUnbondingPoolsWindow`. On Kusama Asset Hub, `PostUnbondingPoolsWindow` is fixed at 4 [1](#0-0) , while `bonding_duration()` resolves through `StakingInterface::nominator_bonding_duration()`, which depends on the runtime storage flag `AreNominatorsSlashable` and can drop from `BondingDuration` (28) to `NominatorFastUnbondDuration` (2) [4](#0-3) . Existing `with_era` maps created while the bond was 32 slots would exceed the new bound (6) the moment the flag flips, making the historical sub-pool storage undecodable — the same root cause as the LOAN_TERM bug: liquidation/unbonding logic uses the *current* value of a mutable config parameter instead of the value in effect when the position (unbonding chunk / sub-pool) was created. The comment in the Polkadot fix even documents this pattern is Kusama-relevant ("Unlike Polkadot, Kusama nominators are expected to be slashable... `AreNominatorSlashable` is intended to remain set to true and should not be modified via governance" [3](#0-2) ), but this is only a governance convention, not an enforced runtime invariant — the storage item is settable via `set_staking_configs`/`AreNominatorsSlashable` extrinsic and nothing in the runtime prevents flipping it.

### Impact Explanation
If `AreNominatorsSlashable` is flipped on KAH, the next `unbond` extrinsic on an oversized historical `SubPools::with_era` entry would fail to decode and the pallet would overwrite it with `Default` (empty), destroying per-era unbonding accounting for that pool — the exact same failure mode already fixed on Polkadot Asset Hub (PR #1201). This can lead to loss of user funds/accounting corruption for pool members.

### Likelihood Explanation
This requires a governance-approved change (setting `AreNominatorsSlashable` to `false`), which is described in code comments as not intended for Kusama. This makes it a lower-likelihood, governance-triggered issue rather than an unprivileged-user-triggerable exploit — similar to the original LOAN_TERM finding, which also required an admin/governance action to trigger. Given the identical pattern was already treated as a valid, fixable finding on the Polkadot sibling runtime (bugbounty report #90), the missing parity fix on Kusama Asset Hub represents a real, reachable inconsistency rather than a purely theoretical issue.

### Recommendation
Apply the same fix used on Asset Hub Polkadot: replace `type PostUnbondingPoolsWindow = ConstU32<4>` with a dynamic `Get<u32>` implementation (mirroring `system-parachains/asset-hubs/asset-hub-polkadot/src/staking/nom_pools.rs::PostUnbondingPoolsWindow`) that computes `BondingDuration::get().saturating_add(4).saturating_sub(nominator_bonding_duration())`, keeping `TotalUnbondingPools` pinned at its historical maximum regardless of `AreNominatorsSlashable`'s value.

### Proof of Concept
1. On Kusama Asset Hub, a nomination pool accumulates unbonding requests across many eras while `AreNominatorsSlashable = true` (bond duration 28), causing some `SubPools::with_era` maps to grow toward the current bound of 32.
2. Governance calls `Staking::set_staking_configs` (or equivalent) to set `AreNominatorsSlashable = false`.
3. `nominator_bonding_duration()` now returns `NominatorFastUnbondDuration` (2), so `TotalUnbondingPools` recomputes to `2 + 4 = 6` instead of 32.
4. The next `unbond` call on an affected pool attempts to decode the oversized `with_era` map against the new bound of 6, fails, and the pallet substitutes an empty default map, silently erasing existing unbonding-era accounting for that pool. [2](#0-1)

```rust
/// Bound for `pallet_nomination_pools::SubPools::with_era`, frozen at its historical maximum so it
/// does not shrink when the nominator bonding duration drops.
///
/// The pallet derives its `TotalUnbondingPools` bound as `StakeAdapter::bonding_duration() +
/// PostUnbondingPoolsWindow`, and `StakeAdapter::bonding_duration()` resolves to
/// `StakingInterface::nominator_bonding_duration()`, which drops from `BondingDuration` (28) to
/// `NominatorFastUnbondDuration` (2) the moment `AreNominatorsSlashable` is set from `true` to
/// `false`. With a fixed window the bound would shrink 32 -> 6, making any oversized historical
/// `with_era` map undecodable; the next `unbond` then overwrites it with an empty `Default`,
/// destroying per-era unbonding accounting (bugbounty report #90).
///
/// We pin the bound at `BondingDuration + 4 = 32` by computing the window as `MAX -
/// nominator_bonding_duration()`. Subtracting the same value the pallet adds keeps
/// `TotalUnbondingPools == MAX` by construction, regardless of the flag. Post-flip this also widens
/// the effective merge window to `32 - 2 = 30` eras, keeping each per-era pool on its correct
/// points-to-balance ratio long enough for deferred pre-flip slashes (`SlashDeferDuration = 27`) to
/// still be applied.
///
/// TODO: this is an interim runtime fix, meant to be superseded by the in-pallet decoupling in
/// polkadot-sdk.
pub struct PostUnbondingPoolsWindow;
impl Get<u32> for PostUnbondingPoolsWindow {
	fn get() -> u32 {
		// Historical maximum number of unbonding sub-pools: the validator bonding duration plus the
		// legacy 4-era post-unbonding window. `BondingDuration` is the upper bound of
		// `nominator_bonding_duration()`, so the subtraction below never saturates.
		let max_unbonding_pools = BondingDuration::get().saturating_add(4);
		max_unbonding_pools
			.saturating_sub(<Staking as sp_staking::StakingInterface>::nominator_bonding_duration())
	}
```
