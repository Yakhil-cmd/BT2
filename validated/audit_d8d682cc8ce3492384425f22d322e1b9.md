### Title
Market-wide RAY-value overflow permanently freezes borrower repayments and supplier withdrawals - ([File: common/src/rates/scaling.rs](common/src/rates/scaling.rs))

### Summary
Every pool accrual unscales the market’s total borrowed and supplied RAY shares with `scaled_to_original`, which panics on `i128` overflow before the borrow-index cap can take effect. An unprivileged user can place a sufficiently large, highly utilized market into this state through ordinary `supply` and `borrow`; afterward, permissionless `update_indexes`, repayments, withdrawals, borrows, liquidations, and other market operations all fail while synchronizing the same market. This permanently freezes funds in that market because the failing accrual runs before both debt-reducing and collateral-recovery paths.

### Finding Description
`accrue_step` first computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` and `supplied_original = scaled_to_original(supplied, supply_index)` to calculate utilization [1](#0-0) . `scaled_to_original` is only `scaled.mul(index)` [2](#0-1) , and the underlying `mul_div_half_up` widens to `I256` but panics with `GenericError::MathOverflow` if the resulting value does not fit `i128` [3](#0-2) .

The overflow occurs before `update_borrow_index` computes or clamps the next index [4](#0-3) . Thus the configured `MAX_BORROW_INDEX_RAY` cap does not prevent a stored `(scaled shares * index)` value from exceeding `i128::MAX` [5](#0-4) . Supply-index math repeats the same `supplied * supply_index` multiplication [6](#0-5) .

Every market mutation loads a synced cache and calls `interest::global_sync` before processing a leg [7](#0-6) . `global_sync` calls `accrue_step` for every elapsed chunk before committing updated indexes [8](#0-7) . Controller `update_indexes` is permissionless except for caller authentication and forwards the requested `HubAssetKey` list to the pool [9](#0-8) [10](#0-9) .

### Impact Explanation
The market becomes permanently unusable once either scaled total times its index exceeds `i128::MAX`. Suppliers cannot withdraw, borrowers cannot repay, new borrowers cannot borrow, and liquidators cannot repay or seize through that market because each operation synchronizes before executing its state transition [11](#0-10) [12](#0-11) . The repository’s regression test demonstrates that after the cliff, both `withdraw` and `repay` fail with `MATH_OVERFLOW` [13](#0-12) .

This is not merely transaction-local denial of service: the stored scaled balances and indexes remain unchanged after the revert, so the same panic recurs on every subsequent operation. The affected market retains pool tokens that accounting can no longer safely unscale or move, resulting in permanent freezing of user funds and potentially uncollateralized/unresolvable protocol debt.

### Likelihood Explanation
Reaching the condition requires an exceptionally large market and enough time for indexes to grow, but it is reachable through normal unprivileged actions and permitted market parameters. The documented test constructs a one-billion-whole-token, 18-decimal market, supplies it, borrows 98% of it, advances time at a valid 175% stress rate, and observes the panic before the borrow-index cap engages [14](#0-13) . A 175% annual rate is below the protocol’s configured maximum borrow-rate bound of `2 * RAY` [15](#0-14) .

The attacker does not need privileged access or malformed calldata: they use controller `supply`, `borrow`, and later permissionless `update_indexes`. Capital cost is substantial and the freeze is time-dependent, so likelihood is lower than a direct arithmetic exploit, but the condition is deterministic once the market’s scaled-value capacity is exceeded.

### Recommendation
Accrue interest without ever forming an `i128` product that can exceed the representable range:

- Compute utilization from saturating or `I256` total values, or compare scaled totals against explicit precomputed index bounds before unscaling.
- Clamp `borrow_index` and `supply_index` below the point where `supplied * supply_index` or `borrowed * borrow_index` can exceed `i128::MAX`.
- Add a debt-reduction escape path that can burn stored scaled debt for a measured token receipt without requiring full interest accrual, while ensuring the skipped-interest accounting is explicit.
- Enforce market supply/debt caps with headroom for worst-case index growth, not only the initial raw-token amount.
- Keep the existing long-horizon regression as a permanent test and add boundary tests for both supply- and borrow-side totals.

### Proof of Concept
The repository already contains a deterministic reproduction:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}
```

At the point where `borrowed * borrow_index` exceeds `i128::MAX`, `update_indexes` fails inside `scaled_to_original`. The stored `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, proving that the value multiplication overflows before index clamping. Subsequent calls to `withdraw` and `repay` fail with `MATH_OVERFLOW` because both operations first call `global_sync` [16](#0-15) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }

    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
