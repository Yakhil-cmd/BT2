### Title
Per-partition epoch-reward distribution work (`store_stake_accounts_in_partition`) is unbounded because `num_partitions` is clamped to a fixed max regardless of total stake-delegation count - ([File: runtime/src/bank/partitioned_epoch_rewards/mod.rs] / [File: runtime/src/bank/partitioned_epoch_rewards/distribution.rs])

### Summary
`Bank::get_reward_distribution_num_blocks` derives `num_partitions` as `total_stake_accounts.div_ceil(stake_account_stores_per_block)`, then clamps this value to a hard cap of `slots_per_epoch / 10` (`MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH`). Because the cap bounds the number of *partitions*, not the per-partition size, once the number of network-wide stake delegations `N` exceeds `stake_account_stores_per_block * (slots_per_epoch/10)`, the per-block work in `distribute_epoch_rewards_in_partition` / `store_stake_accounts_in_partition` grows linearly with `N` instead of staying bounded near `stake_account_stores_per_block`. An attacker who creates many low-balance stake accounts delegated to their own vote account increases the global delegation count `N`, thereby inflating the per-block reward-distribution work for every validator during every affected epoch boundary going forward.

### Finding Description
`get_reward_distribution_num_blocks` computes:
```
num_chunks = total_stake_accounts.div_ceil(stake_account_stores_per_block)
num_chunks.clamp(1, (slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1))
``` [1](#0-0) 

This value becomes `epoch_rewards_sysvar.num_partitions`, which is subsequently used both to size `hash_rewards_into_partitions`'s partition vector [2](#0-1)  and to drive `distribute_partitioned_epoch_rewards` → `distribute_epoch_rewards_in_partition` → `store_stake_accounts_in_partition`, which iterates over every index assigned to that block's partition and performs a stake-account load, deserialize, reward application, and store for each entry [3](#0-2) .

The intended invariant (implicit in the design, and validated by `test_get_reward_distribution_num_blocks_cap`, which asserts partitions cap out at `slots_per_epoch/10`) is that partition size stays close to `stake_account_stores_per_block` (default `MAX_PARTITIONED_REWARDS_PER_BLOCK = 4096`, see `accounts-db/src/partitioned_rewards.rs`) [4](#0-3) . But the clamp only limits the *count* of partitions/blocks, not the average partition size. Once `N` (total stake delegations network-wide) exceeds `stake_account_stores_per_block * slots_per_epoch / 10`, `num_partitions` stays fixed at the cap while `N/num_partitions` (i.e., the average number of accounts to process per block) keeps growing linearly with `N`. `hash_rewards_into_partitions` distributes `stake_rewards` uniformly at random across the fixed `num_partitions` buckets via hashing on `stake_pubkey` [2](#0-1) , so partition sizes scale with total N, not with the configured per-block budget.

An unprivileged attacker can increase `N` by funding and creating many stake accounts at (or near) the minimum delegation (1 SOL post-feature-activation, see `stake_utils::get_minimum_delegation`) [5](#0-4)  and delegating them (even to their own vote account) via ordinary `CreateAccount` + `DelegateStake` instructions before the epoch boundary. This is standard `StakeAccount` creation and delegation logic that requires no special privileges, only funding, e.g. as shown in `test_bank_cloned_stake_delegations`'s use of `create_account_and_delegate_stake` [6](#0-5) . `total_stake_accounts` reflects the total count of `PartitionedStakeReward`s for the *entire network* (the value comes from `rewards.num_rewards()` over all stake delegations, not per-attacker), so this affects every validator's processing time at every subsequent epoch boundary, not just the attacker's own view.

Existing guards (signer checks, rent-exempt checks, minimum-delegation checks) prevent unauthorized account mutation or theft but do nothing to bound aggregate epoch-boundary CPU/IO cost, because none of those checks constrain the total count of delegations network-wide.

### Impact Explanation
This is a scoped, degraded/DoS-adjacent impact on epoch-boundary processing: the number of reward-distribution blocks is capped, but the work done per block is not, so validators can be forced to do unboundedly (proportional to attacker-funded delegation count) larger per-block work at epoch boundaries, which can slow down or destabilize epoch-boundary block production across the whole cluster — matching the "degraded network/consensus performance" / DoS-adjacent bounty category for epoch-boundary processing. It does not directly mint or steal lamports.

### Likelihood Explanation
Feasible and repeatable: an attacker only needs enough capital to fund `N` stake accounts each holding at least (rent-exempt reserve + minimum delegation, currently 1 SOL) and issue ordinary `CreateAccount`/`DelegateStake` transactions before an epoch boundary — no special permissions or validator control required. The financial cost scales linearly with `N`, but for adversaries willing to invest capital, the exploit reliably increases per-block distribution work at every future epoch boundary until the accounts are removed, since `num_partitions` recomputation happens fresh at each epoch calculation phase based on then-current delegation count.

### Recommendation
Change `get_reward_distribution_num_blocks` to prioritize bounding per-block work over bounding block count: instead of (or in addition to) capping `num_chunks` at `slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH`, ensure the actual per-partition size used by `store_stake_accounts_in_partition` stays within `stake_account_stores_per_block`, e.g., by processing multiple partitions per block when `num_chunks` exceeds the cap, or by decoupling "block schedule length" from "per-partition size" so the per-block store operation count is always bounded near the configured `stake_account_stores_per_block`, independent of total network stake-delegation count.

### Proof of Concept
Invariant/integration test plan (Rust, in `runtime/src/bank/partitioned_epoch_rewards/mod.rs` test module):
```rust
#[test]
fn test_partition_work_bounded_regardless_of_total_delegations() {
    // Use a short epoch and small stake_account_stores_per_block so the cap
    // (slots_per_epoch/10) is reached quickly.
    let slots_per_epoch = 32;
    let stake_account_stores_per_block = 10;
    let (bank, _bank_forks) = /* build bank as in test_get_reward_distribution_num_blocks_cap */;

    // Case 1: N accounts just at cap boundary
    let n_at_cap = stake_account_stores_per_block * (slots_per_epoch / 10);
    let rewards_at_cap = build_random_partitioned_stake_rewards(n_at_cap);
    let num_partitions_at_cap = bank.get_reward_distribution_num_blocks(&rewards_at_cap);
    let avg_partition_size_at_cap = n_at_cap / num_partitions_at_cap;

    // Case 2: N accounts far beyond cap boundary (simulating attacker-inflated
    // delegation count via many low-balance stake accounts)
    let n_inflated = n_at_cap * 100;
    let rewards_inflated = build_random_partitioned_stake_rewards(n_inflated);
    let num_partitions_inflated = bank.get_reward_distribution_num_blocks(&rewards_inflated);
    let avg_partition_size_inflated = n_inflated / num_partitions_inflated;

    // EXPECTED (bug): num_partitions_inflated == num_partitions_at_cap (both capped),
    // but avg_partition_size_inflated >> avg_partition_size_at_cap,
    // violating the invariant that per-block work stays bounded near
    // stake_account_stores_per_block.
    assert_eq!(num_partitions_inflated, num_partitions_at_cap);
    assert!(avg_partition_size_inflated > stake_account_stores_per_block * 10,
        "per-partition work is unbounded: {} vs configured budget {}",
        avg_partition_size_inflated, stake_account_stores_per_block);
}
```
This test demonstrates that `num_partitions` (hence block count) stays fixed at the cap while the average number of stake accounts processed per `store_stake_accounts_in_partition` call grows unboundedly with the attacker-inflatable total delegation count, violating the "epoch-boundary work must be bounded" invariant.

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );

/// Baseline number of stake accounts to store in one 400ms block during the
/// partitioned reward interval.

    /// partitioned reward interval.
    ///
    /// This value is stored as the 400ms-slot baseline. Runtime `Bank` state
    /// derives the effective per-bank value from the active slot-time target.
    pub stake_account_stores_per_block: u64,
