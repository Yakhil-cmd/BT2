### Title
Terminal escape sequence injection via unsanitized PR title/author/ref names in `printHumanPrPreview` - (pkg/cmd/pr/view/view.go)

### Finding Description
`printHumanPrPreview` in `pkg/cmd/pr/view/view.go` writes several attacker-influenced fields directly to the terminal via `fmt.Fprintf` without any escape-sequence sanitization: `pr.Title`, `pr.Author.DisplayName()`, `pr.BaseRefName`, and `pr.HeadRefName` are interpolated as `%s` arguments in the header lines [1](#0-0) . Note that the format strings themselves (`"%s %s#%d\n"`, `"%s • %s wants to merge %s into %s from %s • %s\n"`) are static literals, so this is not classic format-string injection — the risk is terminal control-sequence injection through the *argument values*, since PR titles, author logins/display names, and git ref names (which GitHub allows to contain a wide range of characters) are attacker-controlled and can embed ANSI/VT100 escape sequences (e.g., cursor movement, line clear, or OSC sequences) that rewrite or hide previously rendered trusted output such as the auth banner or the footer at line 290 [2](#0-1) .

The codebase has a purpose-built defense for exactly this problem: `iostreams.Untrusted`, a wrapper type whose `String()` method runs content through `asciisanitizer` to neutralize ANSI escape sequences before any `fmt` print path renders it [3](#0-2) . Its doc comment explicitly says it exists for "HTTP response bodies... anything that originates outside the CLI" [4](#0-3) . However, `printHumanPrPreview` does not route `pr.Title`, `pr.Author.DisplayName()`, `pr.BaseRefName`, or `pr.HeadRefName` through `Untrusted` — they are printed as plain Go strings.

I was unable to fully verify from the indexed code whether `api.PullRequest.Title`, `HeadRefName`, `BaseRefName`, or the author's `DisplayName()` are declared as `iostreams.Untrusted` typed fields elsewhere in `api/queries_pr.go` (that file's contents were not available in the index), which would change the analysis if `Untrusted.String()` is implicitly invoked by `%s`. Based on the code I could inspect (`pkg/cmd/pr/view/view.go`, `pkg/cmd/pr/shared/display.go`), these values are used as ordinary strings without any visible sanitization call, and `printRawPrPreview` similarly prints `pr.Title` and `pr.Author.DisplayName()` unsanitized to non-terminal output [5](#0-4) .

### Impact Explanation
If these fields are not backed by the `Untrusted` type, a malicious PR author could craft a PR title, use a crafted account display name, or create a branch name containing ANSI escape sequences to manipulate the victim's terminal display when they run `gh pr view <n>` — e.g., clearing lines, repositioning the cursor, or overwriting the trusted CLI footer with fake text (such as a spoofed "Authentication required" prompt), which could be used for terminal-based phishing/social engineering against a human operator. This does not achieve code execution, credential theft, or file write on its own; the impact is limited to terminal UI spoofing.

### Likelihood Explanation
Preconditions are low-effort for an unprivileged attacker: fork a public repo, open a PR with a crafted title, or use a branch name / account display name containing control characters, since GitHub permits many characters in these fields. The victim only needs to run `gh pr view` on that PR while connected to a TTY, which triggers `printHumanPrPreview` directly [6](#0-5) . This is easily repeatable.

### Recommendation
Wrap `pr.Title`, `pr.Author.DisplayName()`, `pr.BaseRefName`, `pr.HeadRefName`, and other externally-sourced PR metadata (labels, reviewer/assignee names, milestone titles, project names) in `iostreams.Untrusted` (or otherwise pass them through the existing `asciisanitizer`-based sanitizer) before they reach any `fmt.Fprintf`/`fmt.Fprint` call that writes to the terminal, consistent with the pattern already established in `pkg/iostreams/untrusted.go`.

### Proof of Concept
Because I could not confirm the exact type of `api.PullRequest.Title`/`HeadRefName`/`BaseRefName` in this index (file not available), a concrete PoC should be validated with a background Devin session: construct an `api.PullRequest` fixture with `Title` set to a string containing `\x1b[2K\x1b[1A` (clear-line/cursor-up) sequences plus fake "Authentication required" text, call `printHumanPrPreview` with a buffer `IOStreams`, and assert whether the raw escape bytes appear unmodified in the captured output (vulnerable) or are stripped/neutralized (safe), comparing against how `Untrusted.String()` handles the same input in `pkg/iostreams/untrusted_test.go`.

```go
// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
```
