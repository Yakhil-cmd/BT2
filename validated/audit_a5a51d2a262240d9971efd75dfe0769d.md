### Title
Reuse of the same L1 Bitcoin lockup outpoint across successive `register-for-bond` calls double-counts sBTC collateral - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond`'s L1 lockup path (`verify-l1-lockups` / `validate-l1-lockup`) only deduplicates Bitcoin outpoints *within a single call's fold* via `seen-outpoints`. There is no persistent, contract-wide map recording which (txid, output-index) outpoints have already been credited to a bond. A staker whose rollover/registration sequencing allows re-invoking `register-for-bond` (non-overlapping bond terms, or after a prior bond ends) can present the *same* physical BTC lockup proof again to a different `bond-index`, crediting `sats-total` for that outpoint a second time without any additional BTC ever being locked.

### Finding Description
`verify-l1-lockups` ( [1](#0-0) ) folds over the caller-supplied `outputs` list via `validate-l1-lockup`, which tracks `seen-outpoints` only inside the `accumulator` of that single fold call: [2](#0-1) 

The dedup check `(asserts! (is-none (index-of? seen-outpoints outpoint)) ERR_DUPLICATE_LOCKUP_OUTPOINT)` at line 2086 only prevents the same outpoint appearing twice *inside one transaction's `outputs` list*. It is never persisted to a map, so nothing prevents the exact same outpoint (same real Bitcoin UTXO, same merkle proof, same header) from being submitted again in a *later* call to `register-for-bond` for a different `bond-index`.

`register-for-bond` gates re-registration only on whether the staker's *existing membership overlaps* the new bond's term (`bond-overlaps-new-position?` at line 767-770) and on `verify-bond-rollover-window` for non-overlapping rollovers [3](#0-2) . Neither of these checks inspects the specific Bitcoin outpoints used to compute `sats-total`; they only look at STX-stake term overlap. Because the lockup script `construct-lockup-output-script` is a function of `(staker, unlock-burn-height, staker-unlock-bytes, early-unlock-bytes)`, and `early-unlock-bytes`/`minimum-unlock-height` are chosen by the bond admin at `setup-bond` time (and can be identical or trivially satisfied across multiple bonds), an attacker who is the allowlisted staker for two or more bonds can:

1. Lock BTC once into a P2WSH script that satisfies bond 0's `early-unlock-bytes`/unlock-height requirement.
2. Call `register-for-bond(bond-index=0, ..., proof)` → credited `sats-total = X` sats for bond 0, consuming their allowlist `max-sats` and STX for bond 0.
3. Once bond 0's non-overlapping window permits (or after it ends, per `verify-bond-rollover-window`), call `register-for-bond(bond-index=1, ..., same proof)` → `validate-l1-lockup` re-verifies the *same* Bitcoin header/merkle-proof/output and succeeds again (nothing rejects a previously-used outpoint), crediting `sats-total = X` sats again for bond 1.

This breaks the intended equality that on-chain `sats` credit toward reward shares/allowlist consumption must correspond 1:1 to sats actually locked on Bitcoin. The staker ends up with reward-earning "shares" backed by BTC collateral they only locked once, i.e., a double-counted commitment.

### Impact Explanation
This maps to the "double-counting a commitment or reward" / "sats credited by an L1 proof that were never locked on Bitcoin" categories described as Critical/High impact. The staker obtains reward-share weight in a second bond period without any incremental BTC ever moving into a timelocked UTXO for that period, diluting genuine bond participants' pro-rata sBTC-denominated rewards and/or allowing the attacker to exceed their allowlisted `max-sats` cap across bond periods using a single BTC deposit.

### Likelihood Explanation
Exploitation requires only an allowlisted (unprivileged) staker account, control over their own timelock script parameters at BTC-lockup creation time, and being allowlisted for two bond periods that (by admin's typical reuse of `early-unlock-bytes` and choosing an unlock height satisfying both bonds' minimums) accept the same physical output. Because bond parameters (`early-unlock-bytes`, min unlock height) are commonly reused/standardized by the bond admin across bond periods (per the contract's design intent for the reference signer-manager), this is a realistic, staker-triggerable path with no admin/miner cooperation needed.

### Recommendation
Persist a global (or at least per-outpoint, cross-call) map of consumed L1 lockup outpoints (e.g., `(map-set used-l1-lockup-outpoints { txid: ..., output-index: ... } true)`) and check/consume it inside `validate-l1-lockup` (or immediately after `verify-l1-lockups` returns) so that any given Bitcoin outpoint can only ever be credited toward one bond registration for the lifetime of the contract, not merely deduplicated within a single call.

### Proof of Concept
1. Bond admin calls `setup-bond` for `bond-index=0` and `bond-index=1` with identical `early-unlock-bytes` and both with a `minimum-unlock-height` satisfied by a single chosen `unlock-burn-height`.
2. Attacker (allowlisted for both bonds) constructs one Bitcoin lockup output using `construct-lockup-output-script(staker, unlock-burn-height, staker-unlock-bytes, early-unlock-bytes)` and broadcasts/confirms it on Bitcoin, locking `X` sats once.
3. Attacker calls `register-for-bond(bond-index=0, signer-manager, amount-ustx, (ok {outputs: [proof], staker-unlock-bytes}), none)`. `verify-l1-lockups` succeeds, `sats-total = X`, bond-0 membership created with `amount-sats: X`.
4. After bond 0's rollover window opens (`verify-bond-rollover-window`), attacker calls `register-for-bond(bond-index=1, signer-manager, amount-ustx, (ok {outputs: [SAME proof], staker-unlock-bytes}), none)`. Because `validate-l1-lockup`'s outpoint check is scoped to the current call's `seen-outpoints` list only, the identical header/merkle-proof/output validates again, yielding `sats-total = X` a second time for bond 1 — crediting `2X` sats of reward-share weight from a single `X`-sat BTC lockup.

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
