## Analysis

The reported bug class in the DODO GSP report (hardcoded `MAINTAINER` fee-recipient that can be blacklisted, permanently freezing `mtFee`) has a direct analog in this codebase around the pool-creator fee mechanism.

### Title
Permanent freezing of accrued creator fees due to an immutable `pool_creator` recipient that can be frozen/blacklisted by the token mint - (File: `programs/cp-swap/src/instructions/collect_creator_fee.rs`, `programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs`, `programs/cp-swap/src/states/pool.rs`)

### Summary
`pool_creator` is written once at pool initialization into `PoolState` [1](#0-0)  and is never updatable afterward. Both fee-collection paths for creator fees hardcode this address as the sole destination: `CollectCreatorFee` requires `creator` to equal `pool_state.pool_creator` and pays into an associated token account owned by that same address [2](#0-1) , and the permissionless variant does the same, only allowing anyone to pay for account creation while still routing tokens to the fixed `creator` [3](#0-2) . Unlike `amm_config.protocol_owner` / `amm_config.fund_owner`, which the admin can rotate via `update_amm_config` (params 3 and 4) [4](#0-3) [5](#0-4) , there is no instruction anywhere in the program that can change `pool_state.pool_creator`.

### Finding Description
Every swap accrues `creator_fees_token_0` / `creator_fees_token_1` into `PoolState`, physically held in `token_0_vault` / `token_1_vault` [6](#0-5) . The only way to withdraw these funds is `collect_creator_fee` or `collect_creator_fee_permissionless`, both of which unconditionally transfer to a token account owned by the pool's immutable `pool_creator` [7](#0-6) . If either token in the pool is a token whose issuer/freeze authority can freeze a specific holder's account (a legitimate and explicitly supported feature of Token/Token-2022, which this program natively supports via `token_0_program`/`token_1_program` on `PoolState`), and the `pool_creator` address gets frozen/blacklisted by that mint's freeze authority, both the permissioned and permissionless collection paths become permanently unusable for that pool: the destination account is forced to be an account owned by the frozen address, and no alternate recipient or owner-rotation mechanism exists.

### Impact Explanation
Once `pool_creator`'s account is frozen by the mint's freeze authority, `creator_fees_token_0`/`creator_fees_token_1` are locked in the pool's vaults forever — no admin, owner, or the creator themselves can redirect fee collection to a different account, since the recipient authority is derived directly from the immutable on-chain `pool_state.pool_creator` field with no update path. This is a permanent freezing of LP/creator funds tracked in the fee ledger.

### Likelihood Explanation
Likelihood is moderate: it requires the pool to include a token whose issuer has and exercises freeze authority against the specific `pool_creator` address (e.g., a regulated stablecoin or a Token-2022 mint with freeze extension). Given the program explicitly supports Token-2022 mints (`token_0_program`/`token_1_program`, `vault_0_mint`/`vault_1_mint` typed as `InterfaceAccount<Mint>`), this is a realistic and reachable condition without any privileged action from the protocol side — it only requires an external token-issuer action against an address the protocol cannot change.

### Recommendation
Add an admin- or creator-controlled instruction to update `pool_state.pool_creator` (analogous to `set_new_protocol_owner`/`set_new_fund_owner` in `update_amm_config`), so a new, unfrozen recipient can be designated if the original creator address becomes blacklisted/frozen.

### Proof of Concept
1. Pool is created with `token_0` = a Token-2022 mint with freeze authority (or a Token mint with freeze authority) and `pool_creator` = address `C`.
2. Swaps occur, accruing `creator_fees_token_0`/`creator_fees_token_1` in `PoolState`.
3. The mint's freeze authority freezes the token account owned by `C` for `token_0`.
4. `collect_creator_fee` (signed by `C`) and `collect_creator_fee_permissionless` (callable by anyone) both attempt to transfer into an ATA owned by `C`; the transfer CPI fails because the destination/authority is frozen.
5. Since `pool_state.pool_creator` cannot be changed by any instruction in the program, the accrued creator fees for that pool remain permanently locked in `token_0_vault`.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,

        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();

                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }

                self.protocol_fees_token_1 = self

                    .checked_add(protocol_fee)

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

fn set_new_protocol_owner(amm_config: &mut Account<AmmConfig>, new_owner: Pubkey) -> Result<()> {
    require_keys_neq!(new_owner, Pubkey::default());
    #[cfg(feature = "enable-log")]
    msg!(
        "amm_config, old_protocol_owner:{}, new_owner:{}",
        amm_config.protocol_owner.to_string(),
        new_owner.key().to_string()
    );
    amm_config.protocol_owner = new_owner;
    Ok(())
}

fn set_new_fund_owner(amm_config: &mut Account<AmmConfig>, new_fund_owner: Pubkey) -> Result<()> {
    require_keys_neq!(new_fund_owner, Pubkey::default());
    #[cfg(feature = "enable-log")]
    msg!(
        "amm_config, old_fund_owner:{}, new_fund_owner:{}",
        amm_config.fund_owner.to_string(),
        new_fund_owner.key().to_string()
    );
    amm_config.fund_owner = new_fund_owner;
    Ok(())
}
