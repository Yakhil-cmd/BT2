### Title
Stop-hook review set silently drops dangerous commits after non-ancestor HEAD moves (`reset`/checkout to sibling commit) - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` in `diffstate.py` computes the Stop-hook's review set as an intersection of "currently dirty or newly-committed-this-turn" files with "files that differ from the baseline SHA." When HEAD is moved by a non-linear git operation (e.g. `git reset --hard` to a commit/branch not descended from `head_at_capture`) and the working tree ends up clean, the "dirty" term becomes empty while the baseline-diff term still contains the dangerous file, so the intersection silently yields an empty review set even though the file's content differs from `baseline_sha`.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) builds `review_set = dirty_now & changed_since` [1](#0-0) .

- `dirty_now` comes from `_git_status_porcelain` (tracked-dirty + new-untracked paths) and, only when `head_at_capture` is an *ancestor* of the current HEAD, the paths touched by `head_at_capture..HEAD` [2](#0-1) .
- `changed_since` comes from `_git_name_only(repo, baseline_sha)`, i.e. `git diff --name-only <baseline_sha>` against the current working tree/HEAD, independent of ancestry [3](#0-2) .

If the working directory is put into a state where `git reset --hard` (or any operation that lands HEAD on a commit that is not a descendant of `head_at_capture`, e.g. checkout of another branch/tag that already contains the dangerous file, or a rewritten history) makes the working tree byte-for-byte clean:
- `_git_status_porcelain` reports no tracked-dirty and no untracked files → `dirty_now = ∅`.
- `_is_ancestor(repo, head_at_capture, current_head)` returns `False` (non-linear move) → `diff_base` stays `"HEAD"` and the `head_at_capture..HEAD` term is never unioned in [2](#0-1) .
- `changed_since` from `baseline_sha` still legitimately contains the dangerous file, since its tree content differs from `baseline_sha`.
- `review_set = ∅ ∩ changed_since = ∅` — the file is excluded from the entire review pipeline even though it is genuinely different from the review-set baseline [4](#0-3) .

`load_baseline_sha` (`plugins/security-guidance/hooks/diffstate.py:50-54`) simply returns whatever `baseline_sha` was captured at the last `UserPromptSubmit` via `capture_git_baseline` (`git stash create`/`HEAD`) [5](#0-4) ; it performs no re-validation that the current git state still corresponds to a linear descendant of that baseline, so it happily feeds a stale/mismatched baseline into `compute_v2_review_set` without detecting the non-ancestor jump. This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths" — the touched-paths bookkeeping (`record_touched_path`/`consume_stop_state`) is not consulted by `compute_v2_review_set` at all, so it provides no backstop once the git-derived intersection goes empty.

Because the trigger is ordinary git commands (`commit`, `reset --hard`, `checkout <ref> -- <path>`) that an instructed/compromised Claude Code agent (driven by injected instructions in repository content) can run with no special privileges, this is reachable purely through "normal git operations in a cloned repo," matching the question's attacker model.

### Impact Explanation
A dangerous code change (e.g., a backdoor, credential exfiltration, or command-injection payload) that is committed and then made "invisible" to the diff-intersection logic via a non-ancestor HEAD move is never sent to the LLM security reviewer, never triggers the `exit(2)` re-wake/guidance flow, and is never flagged to the user. This defeats the entire purpose of the security-guidance Stop hook — a local safety net intended to catch unauthorized/dangerous commands and code before they are treated as reviewed — allowing local command execution / dangerous code paths to slip past the plugin's approval-adjacent review gate silently.

### Likelihood Explanation
No special privileges are required — only the ability to run ordinary git commands inside the working session (which is the plugin's entire operating assumption: Claude executing Bash/git tool calls, potentially steered by prompt injection from repository content, issue text, or automation). The sequence (commit dangerous change → `git reset --hard` to a commit already containing it, or checkout of an existing ref with the payload → clean working tree) is simple, deterministic, and reproducible in any git repo with more than one branch/commit reachable outside the linear `head_at_capture..HEAD` chain.

### Recommendation
Do not gate `changed_since` behind `dirty_now` when HEAD has moved non-linearly. Detect the non-ancestor HEAD-move case explicitly (compare `head_at_capture` vs current HEAD regardless of ancestry) and, when HEAD changed at all since `head_at_capture` in a way `_is_ancestor` doesn't recognize as a simple forward commit, either (a) union in `_git_name_only(head_at_capture, "HEAD")` unconditionally (not gated by ancestry) so any file differing from the pre-turn snapshot is captured, or (b) fall back to reviewing the full `changed_since` set (drop the intersection) whenever HEAD is not a linear descendant of `head_at_capture`. Also treat `_is_ancestor` returning `False` as a signal to log/telemetry-flag a "baseline shifted non-linearly" event so operators can detect the class of git operation.

### Proof of Concept
Integration test plan (pytest style, using a temp git repo):
1. Init repo, create `safe.py` with benign content, commit as `A`. Capture `baseline_sha = capture_git_baseline(repo)` and `head_at_capture = A` (simulating UPS).
2. Create branch `evil` from `A`, add dangerous content to `danger.py` (e.g. `os.system(user_input)`), commit as `B` on `evil`.
3. Back on original branch (still at `A`, matching `baseline_sha`/`head_at_capture`), simulate Claude's turn: `git reset --hard evil` (or `git checkout evil -- danger.py && git commit` then `git reset --hard` an unrelated sibling that already carries the file) — end state: working tree clean, `HEAD == B`, `_is_ancestor(repo, A, B)` is `False` only if `B`'s branch history is engineered to not descend from `A` in the observed check (e.g., by rebasing/filter-branching `evil` after divergence, or by having originally created `evil` from an unrelated root and cherry-picking); alternatively directly reproduce via `git commit --amend` history rewriting so `merge-base --is-ancestor A HEAD` fails while `danger.py` differs from `A`.
4. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture)`.
5. Assert (currently failing) that `danger.py` is in the returned `review_paths` — expected: it is present because content differs from baseline; actual (bug): `review_set` is empty because `dirty_now` is empty and the ancestor-gated union never fires.

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None

def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}
