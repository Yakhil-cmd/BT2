### Title
Non-Qualified Council Members Satisfy Pre-Permissionless Quorum in `verifySeals`, Enabling Unauthorized Block Acceptance — (`blockchain/block_validator.go`)

### Summary

In the pre-permissionless branch of `verifySeals`, committed seals are validated against the full **council** set (which includes demoted, non-qualified validators), but the quorum threshold is computed over the **qualified** validator count. A qualified proposer colluding with demoted council members can produce a block whose committed seals come entirely from non-qualified validators yet pass the quorum check.

### Finding Description

`verifySeals` in `blockchain/block_validator.go` contains a structural mismatch in its pre-permissionless path. [1](#0-0) 

The line `signerSet := qualifiedSet.Copy()` is immediately overwritten because the `if !rules.IsPermissionless` branch is always entered in the pre-permissionless path. The effective `signerSet` is always `council`. [2](#0-1) 

The quorum threshold `2*F(qualifiedLen, committeeSize)+1` is computed over `qualifiedLen` — the number of qualified validators — but `countValidCommittedSeals` accepts any council member's seal as valid. For `qualifiedLen=2`, `F` returns 0 and the threshold is 1, meaning a single demoted validator's seal satisfies quorum. [3](#0-2) 

### Impact Explanation

A qualified proposer can craft a block whose `CommittedSeal` entries are signed by demoted (non-qualified) council validators. The block passes `verifySeals` and is inserted into the canonical chain. This constitutes:

- **Invalid block acceptance**: blocks lacking genuine qualified-validator quorum are accepted as canonical.
- **Invalid reward distribution**: block rewards are distributed based on an illegitimate block.
- **Consensus invariant violation**: the BFT safety property (2f+1 over qualified validators) is broken without requiring a majority of qualified validators to collude.

### Likelihood Explanation

Requires one qualified validator acting as proposer and cooperation from demoted council validators. Demoted validators are still running nodes in the pre-permissionless era and retain their signing keys. This is a realistic collusion scenario that does not require majority-validator compromise or cryptographic breaks.

### Recommendation

Replace `signerSet = valset.NewAddressSet(council).Copy()` with `signerSet = qualifiedSet.Copy()` (removing the overwrite entirely, since `qualifiedSet` is already computed). Committed seals should only be counted from qualified validators, and the quorum threshold is already computed over `qualifiedLen`. Alternatively, if council-wide signing is intentional for historical compatibility, the quorum denominator must be `len(council)`, not `len(qualified)`.
