The CometBFT report concerns panic recovery in a P2P reactor within Tendermint/CometBFT's networking stack — a node-level availability concern, not a consensus/runtime state-transition bug. Searching the Polkadot SDK for analogous constructs shows that panic isolation in the networking and execution layers is already deliberately handled in multiple places:

- `substrate/client/network/src/protocol/notifications/handler.rs` poll loops treat substream errors as ordinary state transitions (closing/reopening substreams) rather than propagating panics [1](#0-0) .
- `substrate/primitives/panic-handler/src/lib.rs` provides a dedicated `AbortGuard`/`OnPanic` mechanism used throughout the node to control whether a panic aborts the process or unwinds safely [2](#0-1) .
- `substrate/client/executor/src/executor.rs`'s `with_externalities_safe` explicitly wraps runtime calls in `catch_unwind` and converts panics into `Error::RuntimePanicked` [3](#0-2) .
- Host functions called from Wasm are also wrapped in `catch_unwind` via the runtime-interface macro, converting panics into `anyhow::Error` results instead of crashing [4](#0-3) .
- Malformed/oversized network payloads (e.g., in `substrate/client/network/statement/src/lib.rs`) are explicitly tested to ensure they are rejected with a reputation penalty rather than causing a panic [5](#0-4) .

There is no unsigned extrinsic, XCM message, or contract call path through which an unprivileged attacker can trigger an unguarded panic that escapes these existing recovery boundaries and causes a measurable state-transition impact (theft, unbacked issuance, unauthorized dispatch, irreversible freezing, or deterministic chain failure). A node-process crash/DoS in the networking layer, even if it existed, falls into the explicitly excluded category of generic resource-exhaustion/availability claims rather than a runtime/consensus integrity violation, so no qualifying analog is supported.

	F: UnwindSafe + FnOnce() -> U,

	sp_externalities::set_and_run_with_externalities(ext, move || {
		// Substrate uses custom panic hook that terminates process on panic. Disable
		// termination for the native call.
		let _guard = sp_panic_handler::AbortGuard::force_unwind();
		std::panic::catch_unwind(f).map_err(|e| {
			if let Some(err) = e.downcast_ref::<String>() {
				Error::RuntimePanicked(err.clone())
			} else if let Some(err) = e.downcast_ref::<&'static str>() {
				Error::RuntimePanicked(err.to_string())
			} else {
