### Title
Unsanitized attacker-controlled file paths in skill file tree rendering enable terminal escape-sequence injection - ([File: pkg/cmd/skills/preview/preview.go])

### Summary
`buildTree`/`printTree` in `pkg/cmd/skills/preview/preview.go` render `discovery.SkillFile.Path` segments directly to the terminal via `fmt.Fprintf` without any ANSI/OSC sanitization. Since `SkillFile.Path` is populated verbatim from the `path` field of a GitHub git-tree API response (attacker-controlled repo content), a malicious skill repo can embed raw escape sequences in a file or directory name that get written straight to `opts.IO.Out`/`opts.IO.ErrOut`.

### Finding Description
`ListSkillFiles` builds `SkillFile{Path: entry.Path, ...}` directly from the `treeResponse.Tree[].Path` JSON field returned by the GitHub git-trees REST endpoint, with no validation or sanitization: [1](#0-0) 

`previewRun` calls `discovery.ListSkillFiles` and passes the resulting `files` (and the `extraFiles` subset) into `renderAllFiles`/`renderInteractive`: [2](#0-1) 

Both rendering paths call `renderFileTree(out, cs, files)`, which calls `buildTree` then `printTree`: [3](#0-2) 

`buildTree` splits `f.Path` on `/` and stores each raw path segment as `node.name` with no sanitization: [4](#0-3) 

`printTree` then writes `node.name` verbatim via `fmt.Fprintf`: [5](#0-4) 

This output goes to `opts.IO.Out` (non-interactive/pager path, `renderAllFiles` line 281) or `opts.IO.ErrOut` (interactive path, `renderInteractive` line 324) — plain `io.Writer`s from `IOStreams` that are **not** ANSI-sanitized by default. The codebase's own sanitization design (`iostreams.ContentOut`, `iostreams.Untrusted`, `asciisanitizer.Sanitizer`) is applied only when a command explicitly routes external/untrusted content through `ContentOut` or wraps it in `Untrusted`, as done in `pkg/cmd/gist/view/view.go` and `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal`: [6](#0-5) [7](#0-6) 

`preview.go`'s tree rendering does none of this — `node.name` (and similarly `f.Path` used directly at lines 303/309 in `renderAllFiles`, and as `choices` fed to the prompter at line 331) is untrusted attacker data reaching the terminal unsanitized. An attacker who publishes a skill repo with a file whose path (e.g., under `scripts/` or `references/`) contains raw `\x1b]0;...\x07` or `\x1b[8m` bytes can inject terminal control sequences the moment the victim runs `gh skill preview <attacker-repo>`, even without selecting or fetching that file's content.

### Impact Explanation
This allows terminal control-sequence injection (title-bar spoofing, hidden/invisible text via SGR conceal, cursor manipulation, or terminal-emulator-specific escape abuse) purely from listing a repo's skill file tree — the victim need not install or view the malicious file's contents. This matches GitHub's "terminal escape sequence injection" bounty class (client-side output-neutralization bypass), scoped to `gh skill preview`.

### Likelihood Explanation
High feasibility: the attacker only needs to publish a public repo with a skill directory containing an extra file whose name/path embeds control bytes (valid in git tree entries). The victim simply runs `gh skill preview <attacker-repo>` (interactive or non-interactive) on a skill with more than just `SKILL.md`, which is a documented, ordinary use case (multi-file skills with `scripts/`, `references/`, etc.).

### Recommendation
Sanitize all attacker-controlled path segments before they reach `IO.Out`/`IO.ErrOut` in `preview.go`:
- Wrap `SkillFile.Path` (and derived `node.name` values) as `iostreams.Untrusted` before formatting, or pass them through the same `asciisanitizer.Sanitizer`/`sanitizeForTerminal`-style helper already used in `pkg/cmd/skills/list/list.go`.
- Apply this in `buildTree`/`printTree` (for the tree display) and in `renderAllFiles`'s per-file header (`"── "+f.Path+" ──"`) and `renderInteractive`'s picker `choices`, since all of these render attacker-controlled path strings.

### Proof of Concept
```go
func TestRenderFileTree_SanitizesEscapeSequences(t *testing.T) {
    files := []discovery.SkillFile{
        {Path: "SKILL.md", SHA: "s1", Size: 10},
        {Path: "scripts/\x1b]0;pwned\x07evil.sh", SHA: "s2", Size: 20},
    }
    var buf bytes.Buffer
    ios, _, _, _ := iostreams.Test()
    cs := ios.ColorScheme()

    renderFileTree(&buf, cs, files)

    require.NotContains(t, buf.String(), "\x1b",
        "tree output must not contain raw ESC bytes from attacker-controlled file paths")
}
```
This can be extended into a full `previewRun` test using `httpmock` to stub `repos/{owner}/{repo}/git/trees/{treeSHA}?recursive=true` with a tree entry `{"path": "scripts/\u001b]0;pwned\u0007evil.sh", "type": "blob", "sha": "x"}`, then asserting `stdout`/`stderr` from `TestPreviewRun`-style harness does not contain byte `0x1B`.

// buildTree constructs a tree structure from flat file paths.
func buildTree(files []discovery.SkillFile) *treeNode {
	root := &treeNode{isDir: true}
	for _, f := range files {
		parts := strings.Split(f.Path, "/")
		current := root
		for i, part := range parts {
			isLast := i == len(parts)-1
			found := false
			for _, child := range current.children {
				if child.name == part {
					current = child
					found = true
					break
				}
			}
			if !found {
				node := &treeNode{name: part, isDir: !isLast}
				current.children = append(current.children, node)
				current = node
			}
		}
	}
	sortTree(root)
	return root
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
