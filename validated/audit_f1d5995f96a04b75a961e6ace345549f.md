### Title
Bad-debt write-down clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW`, resurrecting wiped suppliers' claims that drain later deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` socializes unpaid debt by scaling the debt market's `supply_index` down. When the bad debt meets or exceeds the total supplied value, the proportional index would be 0, but the code clamps it **up** to `SUPPLY_INDEX_FLOOR_RAW` (RAY/1000). The burned debt is gone, yet every pre-seizure supply share retains a claim valued at the floor index — a phantom, unbacked claim. The first fresh deposit into the wiped market then becomes withdrawable by those wiped-out holders, i.e. theft of the new depositor's funds.

### Finding Description
In `contracts/pool/src/interest.rs:73-89`, when `bad_debt >= total_supplied_value`, `capped = total_supplied_value`, `remaining = 0`, `reduction_factor = 0`, so `new_supply_index = 0`, and `new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))` sets the index to RAY/1000. The supply shares themselves are never burned or zeroed, so `unscale_supply_floor(old_shares)` still returns `old_shares_raw * RAY/1000 / RAY > 0`.

The reachable path is fully permissionless:

1. `controller::process_clean_bad_debt(caller, account_id)` — requires only `caller.require_auth()` plus the dust gate (`BadDebtGate::DustCapped`: debt > collateral and collateral ≤ $5), `contracts/controller/src/positions/liquidation/mod.rs:195-235`.
2. `execute_bad_debt_cleanup` builds `PoolSeizeEntry` items and calls `pool_seize_positions_call`, `contracts/controller/src/positions/liquidation/bad_debt.rs:21-49`.
3. Pool `seize::apply` on a `Borrow` side computes `bad_debt = unscale_borrow_ceil_ray(position)` then calls `interest::apply_bad_debt_to_supply_index` and `burn_debt`, `contracts/pool/src/ops/seize.rs:24-28`.

The wipeout condition (debt value ≥ total supplied value in the debt market) is reachable because `global_sync` accrual is not bounded by the utilization gate — `INV-ACCT-08` explicitly notes "accrual and bad-debt writeoff can exceed the ceiling" — and a small/dormant market with maxed utilization accrues debt faster than supplier value accrues. The production unit test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (`contracts/pool/tests/interest.rs:372-427`) demonstrates exactly this exploit shape at cache level: after the clamp, a wiped position withdraws `gross == fresh_cash`, leaving `cash < fresh_claim` for the new depositor.

### Impact Explanation
Theft of user funds / permanent loss: fresh depositors into a previously wiped market fund phantom withdrawals by the wiped suppliers (or by anyone holding the stranded shares — an attacker who held dust supply in that market). Each deposit up to the stranded claim size can be fully extracted. There is no recovery path: `recapitalize` fills the backing shortfall with real tokens but "without restoring the lost index" (`docs/reference/invariants.md:478-479`), so the phantom claims keep priority on any recapitalized cash too.

### Likelihood Explanation
Medium. It requires driving a market's debt value to ≥ its total supplied value before cleanup. Permissionless cleanup only needs collateral ≤ $5, and debt-over-supply states arise organically through interest accrual in high-utilization markets (the utilization gate blocks only new mints, not accrual). No privileged action is needed at trigger time: any EOA can call `clean_bad_debt`. An attacker can also deliberately hold dust supply in the target market to capture the stranded claims.

### Recommendation
When `bad_debt >= total_supplied_value`, zero out the claims properly instead of clamping the index: e.g. treat `remaining == 0` as a full wipeout by burning all tracked `supplied`/`revenue` shares (or track a per-market "wiped" flag that makes `resolve_withdrawal`/`calculate_scaled_supply` revert until recapitalization resets `supplied` to zero). At minimum, add a `require_reserves`-independent guard so a market whose supply index sits at `SUPPLY_INDEX_FLOOR_RAW` due to a clamp rejects withdrawals of claims created before the wipeout until `supplied` is re-initialized.

### Proof of Concept
1. Attacker supplies a dust amount into market M (becoming a supply shareholder), and an insolvent account is created with debt in M.
2. Let market M accrue (or leave it long enough at high utilization) until `borrowed * borrow_index >= supplied * supply_index`.
3. Once the borrower's collateral is ≤ $5 and debt > collateral, any address calls `controller.clean_bad_debt(account_id)`. In `seize::apply` (Borrow leg), `apply_bad_debt_to_supply_index` computes `reduction_factor = 0` and clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW`; `burn_debt` removes the debt. Attacker's dust supply shares survive with claim `shares * RAY/1000`.
4. Victim calls `supply` into market M; `mint_supply`/`credit_cash` book real tokens.
5. Attacker calls `withdraw` for the full stranded claim; `resolve_withdrawal` values it at the floor index and `require_reserves`/`debit_cash` pay out the victim's deposit.

The cache-level mechanics are pinned by `contracts/pool/tests/interest.rs:372-427`, which asserts `gross == fresh_cash` and `cache.cash() < fresh_claim` — i.e., the stranded claim pays out exactly the fresh deposit and the new supplier is left unbacked.
