### Title
Cross-organization webhook forgery via mismatched authentication org vs. written repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub organization's `webhook_secret` to use for HMAC verification based on the untrusted, unverified request body (`repository.owner.login` / `organization.login`), while the downstream event handlers act on a different field of that same untrusted body (`repository.full_name`) to decide which `Stack`/`Repository` to mutate. Nothing binds these two reads together, so a party who legitimately controls one organization's webhook secret can forge a signed request whose "authenticating organization" and "written repository" diverge.

### Finding Description
The controller resolves the signing organization purely from the JSON body, before any cryptographic check has occurred: [1](#0-0) 
That value is passed into `Shipit.github(organization: repository_owner)`, which looks up per-organization credentials from `secrets.github[organization]`: [2](#0-1) 
`verify_signature` then HMACs the raw body against that organization's `webhook_secret`: [3](#0-2) [4](#0-3) 

Once the signature is accepted, the event handler base class reads the *repository to act on* from a different JSON path (`repository.full_name`), independent of the field used to pick the signing org: [5](#0-4) 
`PushHandler` uses this to look up stacks and immediately triggers a GitHub sync with an attacker-supplied `after` SHA: [6](#0-5) 

Because the multi-org codepath (`github_organizations`, `github_app_config`) exists specifically so one Shipit deployment can host several independently-configured GitHub orgs/apps, an actor who legitimately administers/holds credentials for *one* configured organization ("Org A") knows Org A's `webhook_secret`. That actor can construct a raw JSON payload where `organization.login` / `repository.owner.login` = `"org-a"` (so the controller selects Org A's secret to verify the HMAC) but `repository.full_name` = `"org-b/victim-repo"` (so the handler acts on Org B's tracked repository). Since the attacker can correctly HMAC-sign this body with Org A's secret, `verify_signature` passes, and the handler then operates on Org B's stack using data the attacker fully controls.

This is the exact class of "authenticated identity vs. acted-upon target" mismatch called out in the review guidance: an organization that authenticated (Org A, via `repository_owner`/`webhook_secret`) diverges from the repository that is written (Org B, via `repository.full_name`).

### Impact Explanation
`PushHandler#process` calls `stack.sync_github(expected_head_sha: params.after)` for every non-archived stack matching the forged branch — an attacker-controlled cross-organization action forced onto a repository/stack the attacker has no legitimate relationship to, using only a webhook secret for an unrelated org they do control. Other handlers (`status`, `check_suite`, `pull_request/*`, `membership`) key off similarly untrusted fields once the wrong org's secret has been accepted, so the blast radius extends to check-run refreshes, commit status writes, membership/team mutations, and merge-request state changes for repositories outside the attacker's authorized scope — i.e., cross-repository writes not verifiable by the intended party.

### Likelihood Explanation
Requires the deployment to host multiple GitHub organizations under one Shipit instance (a supported, documented configuration via `secrets.github.<org>.webhook_secret`) and requires the attacker to control at least one such organization's webhook secret (e.g. as a legitimate org admin who configured their own org's app in this shared instance) — not `GITHUB_TOKEN`, `api_clients_secret`, or a Shipit session. Given multi-tenant Shipit deployments are an intended use case of this exact code path, this is a realistic misuse of a supported feature rather than a purely theoretical scenario.

### Recommendation
Bind the organization used for signature verification to the same field (and same trust boundary) used by handlers to select the write target — i.e., derive both from `repository.full_name`'s owner segment consistently, or verify that `repository.owner.login`/`organization.login` matches the owner segment of `repository.full_name` before dispatching to handlers. Additionally, reject requests where the resolved organization's configuration does not deterministically match the tracked `Repository`'s recorded owner in the Shipit database, rather than trusting an unauthenticated field to select the verification secret.

### Proof of Concept
1. Configure Shipit with two orgs, `org-a` and `org-b`, each with distinct `webhook_secret`s (multi-tenant setup, as in `lib/shipit.rb`'s `github_organizations`).
2. As an actor who knows `org-a`'s `webhook_secret` (e.g. its GitHub App owner), craft:
```json
{
  "organization": { "login": "org-a" },
  "repository": { "owner": { "login": "org-a" }, "full_name": "org-b/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>"
}
```
3. Compute `X-Hub-Signature` using `org-a`'s `webhook_secret` over the raw body and send it with `X-Github-Event: push` to `/webhooks`.
4. `WebhooksController#verify_signature` resolves `repository_owner` = `"org-a"`, verifies successfully against `org-a`'s secret, and dispatches to `PushHandler`, which resolves the target stack from `repository.full_name` = `"org-b/victim-repo"` and calls `sync_github(expected_head_sha: "<attacker-chosen-sha>")` on Org B's stack — an action the attacker was never authorized to trigger for Org B.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
