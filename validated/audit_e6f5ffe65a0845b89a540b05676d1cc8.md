### Title
Contract-text hash malleability from delimiter-less/weak-delimiter string concatenation enables dispute forgery in arbiter escrow contracts - (File: arbiter_contract.js)

### Summary
`arbiter_contract.js` computes the on-chain-anchored `contract.hash` (referenced as `contract_text_hash` in the escrow's `data` message and used as the dispute identifier `"CONTRACT_" + contract.hash` in the escrow's oscript definition) by naively concatenating variable-length, attacker-controlled string fields with either no delimiter at all, or a fixed, guessable delimiter. This is directly analogous to the reported `abi.encodePacked()` hash-malleability bug class: distinct sets of contract terms can be crafted to produce an identical hash, allowing a counterparty to later present different terms that still validate against the previously agreed hash.

### Finding Description
`getHashSrc()` builds the source string for `getHash()` as follows: [1](#0-0) 

For any contract created before `exports.NEW_HASH_DATE = '2026-11-01'` (today is 2026-09-15, so this branch is the one currently in production use), the fields `title`, `text`, `payer_name`, `arbiter_address`, `payee_name`, `amount`, and `asset` are joined with `.join("")` — i.e., plain concatenation with **no delimiter whatsoever**. Even after `NEW_HASH_DATE`, the "fixed" branch still only uses a fixed literal string `exports.DELIMITER = "[|#|]"` as a separator, which is not escaped or checked against occurring inside the free-form `title`/`text`/party-name fields.

This is the same weakness the external report flags for `abi.encodePacked()`: because the encoding carries no explicit type tags or length prefixes (unlike ocore's own `getSourceString()` in `string_utils.js`, which prefixes every value with a type tag and a NUL-byte join character and explicitly rejects embedded NUL bytes — see [2](#0-1) ), two different tuples of `(title, text, party_names, amount, asset, ...)` can concatenate to the exact same byte string, and therefore hash to the exact same SHA-256 digest. `getContactsHash()` has the identical flaw, using a fixed `"|"` separator over free-form contact-info/pairing-code strings: [3](#0-2) .

This `contract.hash` is not a cosmetic identifier — it is embedded directly into the on-chain escrow logic: `deriveSharedAddress()` builds the shared-address oscript definition using `"CONTRACT_" + contract.hash` and `"CONTRACT_DONE_" + contract.hash` as the data-feed keys the arbiter posts to release funds, and the same hash is posted on-chain as `contract_text_hash` in the funding data message: [4](#0-3) [5](#0-4) . The dispute record persisted for arbitration (`insertDispute`) stores the free-form `contract_content` (title/text/amount/etc.) alongside the `contract_hash`, which is precisely the data a plaintiff/disputant supplies to the arbiter/arbstore for adjudication: [6](#0-5) .

### Impact Explanation
Because the hash of the contract's textual terms is malleable, a dishonest party to a private arbiter contract can construct an alternate set of terms (e.g., shifting characters between `title` and `text`, or padding `amount`/`asset` boundaries) that hashes to the identical `contract.hash`/`contract_text_hash` already anchored on-chain and known to the counterparty and arbiter. During dispute resolution, the malicious party can submit this alternate `contract_content` to the arbstore while it still passes a naive "hash matches" verification, misrepresenting the agreed terms to the arbiter. Since the arbiter's ruling (posted as a data feed keyed by `CONTRACT_<hash>`) directly controls release of the escrowed funds encoded in the shared address, this can lead to the arbiter releasing funds under a false understanding of the agreement — a fund-loss/fund-misdirection outcome for the honest counterparty, the analog of the AP-offer-fulfilled-without-incentives scenario in the source report.

### Likelihood Explanation
The vulnerable code path (`join("")` with zero delimiter) is the one currently active in production, since `NEW_HASH_DATE` is set to a future date (2026-11-01) relative to the present. Any user who creates or accepts an arbiter contract is exposed, and the attacker needs only control over the free-form `title`/`text`/party-name fields of a contract they propose — no special privileges, network position, or race condition are required, making this reachable by a normal, single private-payment counterparty.

### Recommendation
Replace the manual `.join("")`/`.join(DELIMITER)` concatenation in `getHashSrc()` and `getContactsHash()` with the existing type-tagged, NUL-delimited `getSourceString()`/`getJsonSourceString()` utilities from `string_utils.js` (as already used for unit hashing in `object_hash.js`), which reject embedded join-characters and unambiguously encode field boundaries and lengths. Additionally, remove or retire the legacy pre-`NEW_HASH_DATE` hashing branch, and have the arbstore recompute the hash from the full `contract_content` object (using the same collision-resistant encoding) rather than trusting a caller-supplied hash string as proof of unaltered terms.

### Proof of Concept
1. Build two contract term sets that concatenate identically under the pre-`NEW_HASH_DATE` scheme, e.g.:
   - Contract A: `title="Pay"`, `text="ment for goods"`
   - Contract B: `title="Payment for"`, `text=" goods"`
   Both produce the identical string `"Payment for goods"` prior to `creation_date`/other fields being appended, and (holding `creation_date`, `payer_name`, `arbiter_address`, `payee_name`, `amount`, `asset` constant) yield the same SHA-256 digest via `getHash()` (`arbiter_contract.js:205-207`).
2. Have the malicious party send contract A to the counterparty via `createAndSend()` (`arbiter_contract.js:21-36`), which is accepted and funded — anchoring `contract.hash` on-chain via `createSharedAddressAndPostUnit()` (`arbiter_contract.js:578-630`).
3. During a later dispute, the malicious party submits contract B's `contract_content` to the arbstore (`insertDispute`, `arbiter_contract.js:421-431`). Since `getHash(contractB) === getHash(contractA)`, any verification that merely checks the recomputed hash against the on-chain `contract_text_hash` will accept contract B's differing terms as authentic, letting the arbiter rule on fabricated terms and misdirect the escrowed funds.

function getHashSrc(contract) {
	const payer_name = contract.me_is_payer ? contract.my_party_name : contract.peer_party_name;
	const payee_name = contract.me_is_payer ? contract.peer_party_name : contract.my_party_name;
	const payer_address = contract.me_is_payer ? contract.my_address : contract.peer_address;
	const payee_address = contract.me_is_payer ? contract.peer_address : contract.my_address;
	const src = contract.creation_date > exports.NEW_HASH_DATE
		 ? [contract.title, contract.text, contract.creation_date, payer_address, payer_name || '', contract.arbiter_address, payee_address, payee_name || '', contract.amount, contract.asset || 'null'].join(exports.DELIMITER)
		 : [contract.title, contract.text, contract.creation_date, payer_name || '', contract.arbiter_address, payee_name || '', contract.amount, contract.asset || 'null'].join("");
	return src;
}

function getHash(contract) {
	return crypto.createHash("sha256").update(getHashSrc(contract), "utf8").digest("base64");
}

function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);
