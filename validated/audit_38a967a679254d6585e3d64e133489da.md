### Title
Webhook signature is verified against an organization derived from `repository.owner.login`, but every event handler acts on the unrelated `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit supports multi-organization GitHub App configuration, where each configured organization has its own, independently-set `webhook_secret` [1](#0-0) . `WebhooksController#verify_signature` selects *which* organization's secret to check the HMAC signature against using `repository_owner`, which reads `params.dig('repository', 'owner', 'login')` with a fallback to `params.dig('organization', 'login')` [2](#0-1) . However, none of the actual event handlers use that same field to decide which repository/stack to mutate — they instead resolve the target repository from `payload.dig('repository', 'full_name')` [3](#0-2) , and this same field is reused directly by `PushHandler`, `PullRequest::*Handler`, etc. [4](#0-3) [5](#0-4) .

### Finding Description
The binding that should hold is: **organization whose secret authenticated the request == organization that owns the repository being written to**. Instead the code implements: **organization selected by `repository.owner.login` (used only to pick a secret) ⟂ organization implied by `repository.full_name` (used to pick the actual `Repository`/`Stack` to mutate)**.

Compounding this, `GitHubApp#verify_webhook_signature` is lenient when a webhook secret is not configured for the selected organization:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [6](#0-5) 

Because `repository_owner` is attacker-controlled JSON body content (not itself covered by any prior verification step — it's read *before* the signature check even runs, purely to select which secret to check against) [7](#0-6) , and because none of the handlers cross-check that `repository.owner.login` matches the owner portion of `repository.full_name`, an attacker who can get **any** configured organization to have a blank/unset `webhook_secret` (a valid, supported configuration state per `TOP_LEVEL_GH_KEYS`/`github_app_config`) can send a request with:
- `repository.owner.login` (or `organization.login`) = the organization with no configured secret,
- `repository.full_name` = `victim-org/victim-repo` (any other configured, secret-protected organization's repository).

`verify_signature` will resolve `Shipit.github(organization: "org-with-no-secret")`, call `verify_webhook_signature` which unconditionally returns `true` because `webhook_secret` is blank, and the request passes with **no valid signature at all**. The subsequent handler dispatch (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` in `WebhooksController#create` [8](#0-7) ) then acts on `repository.full_name`, which points at the victim organization's repository — completely bypassing that organization's `webhook_secret` protection.

### Impact Explanation
This allows an unauthenticated attacker to forge webhook events (push, pull_request, membership, status, check_suite) against any repository configured in the Shipit instance, as long as at least one configured GitHub organization lacks a `webhook_secret`. Concretely: a forged `push` event can invoke `stack.sync_github(expected_head_sha: params.after)` on a victim's stack [9](#0-8) , and forged `membership` events can add arbitrary GitHub logins into `Shipit.github_teams`-backing `Team`/`Membership` records (visible in tests exercising `:membership` handling) [10](#0-9) , which — combined with `User#authorized?`'s team-membership check [11](#0-10)  — can escalate an attacker's own GitHub account into `Shipit.github_teams` authorization, enabling deploy/merge actions on the web UI. This matches the "escalation into `Shipit.github_teams` authorization" and "unauthorized deploy" impact tiers.

### Likelihood Explanation
Exploitation requires no privileged credential from the attacker — only that a Shipit deployment has multiple GitHub organizations configured (a documented, supported feature) and that at least one of them was configured without a `webhook_secret` (also an explicitly supported/optional config value per `TOP_LEVEL_GH_KEYS`). This is a plausible misconfiguration rather than a certainty for every deployment, which somewhat lowers likelihood, but the underlying code defect — selecting the verification key from a field disjoint from the field the write path trusts, combined with signature verification being optional — is present unconditionally in the engine's own code.

### Recommendation
- In `Handler#repository_name`/`stacks`, and in every webhook handler, verify that `payload.dig('repository', 'full_name')`'s owner segment matches the `repository_owner` used to select the signing organization in `WebhooksController#verify_signature`, rejecting mismatches.
- Do not allow `GitHubApp#verify_webhook_signature` to return `true` when `webhook_secret` is blank for organizations that are part of a multi-org configuration; require a secret to be present for every configured organization, or reject requests whose selected org has no secret.

### Proof of Concept
1. Configure Shipit with two GitHub organizations in `secrets.github`: `orgA` (no `webhook_secret` set) and `orgB` (has a `webhook_secret`, owns the target stack/repo).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "owner": { "login": "orgA" }, "full_name": "orgB/victim-repo" }
}
```
No `X-Hub-Signature` header value needs to be valid.
3. `WebhooksController#verify_signature` computes `repository_owner == "orgA"`, calls `Shipit.github(organization: "orgA").verify_webhook_signature(...)`, which returns `true` unconditionally because `orgA` has no `webhook_secret` [6](#0-5) .
4. `PushHandler#process` resolves `stacks` from `payload.dig('repository', 'full_name')` = `orgB/victim-repo` [3](#0-2)  and triggers `sync_github(expected_head_sha: ...)` on `orgB`'s protected stack, despite `orgB`'s webhook secret never being checked.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks

        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
