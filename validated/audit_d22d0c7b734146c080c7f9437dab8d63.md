### Title
`repository.owner.login` (used for signature verification) diverges from `repository.full_name` (used to resolve the mutated stack) in `pull_request` webhooks - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` authenticates a webhook using the GitHub App/organization keyed by `params.dig('repository','owner','login')`, but `ClosedHandler#repository` resolves the target `Repository`/`ReviewStack` using the independent field `params.repository.full_name`. Because the two fields are never cross-checked for consistency, a request signed with org A's webhook secret (or org A's secret) can carry a `full_name` pointing at a different repository/org B, letting the handler archive `ReviewStack`s belonging to a repository the signing organization does not own.

### Finding Description
The broken binding is the implicit assumption: `repository_owner == owner(params.repository.full_name)`. This is never enforced.

- `verify_signature` in `app/controllers/shipit/webhooks_controller.rb:24-49` picks `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` (line 59-62) reads only `params.dig('repository','owner','login')`. It then calls `github_app.verify_webhook_signature(header, raw_post)` on the **raw, unparsed** JSON body — it validates that *some* org's secret produced a valid HMAC for the whole payload, but does not look at, or validate, `repository.full_name` at all.
- `ClosedHandler#repository` (`app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb:49-53`) resolves `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely separate field from the one used for signature verification — and then archives the `ReviewStack` scoped to that repository (`review_stack.archive!` -> `ReviewStackAdapter#archive!` in `app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb:23-35`, which calls `stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!(user)`).

For this to be exploitable, the attacker must control a GitHub organization/repo (org A) configured in Shipit with its own webhook secret (or the "no organization" legacy secret path — `Shipit.github_default_organization`/`Shipit.github(organization: ...)` in `lib/shipit.rb:170-200`), sign a payload with that legitimate secret, but set `repository.full_name` to `victim-org/victim-repo`. Since `verify_signature` never inspects `full_name`, and `ClosedHandler` never checks that `repository.owner.login` (used to select the signing secret) matches the owner segment of `repository.full_name`, the HMAC check passes while the payload mutates a repository the attacker does not control.

None of the existing guards catch this: `verify_signature` only checks HMAC validity against whatever org name attacker chooses in `repository.owner.login`; `drop_unhandled_event` only checks the event name is registered; the `ExplicitParameters` schema (`requires :repository { requires :full_name, String }`) only validates presence/type, not cross-consistency with `repository.owner.login`; there is no `force_github_authentication`/`User#authorized?`/`require_permission!` involved since this is an unauthenticated webhook path.

### Impact Explanation
A successful forged request lets an attacker (who controls any org/repo with its own configured Shipit webhook secret) archive a `ReviewStack` belonging to an unrelated, victim-owned repository purely by number-matching `pr#<number>` environments. Since archiving deprovisions/tears down the review stack (`stack.deprovision`), and the broader class of bug (org/full_name split) generalizes to other `pull_request`/`status`/`push` handlers reachable through the same `verify_signature` gap, the blast radius is cross-tenant: a payload authenticated by one repository's secret can mutate records (`ReviewStack`, its `Task`s/`Deploy`s, blocked/deploy gating state through `blocking_statuses`) owned by a different repository. This matches "a payload for one repository mutating another's stack" — Critical severity.

### Likelihood Explanation
Exploitability requires the attacker to control at least one GitHub organization/repository that is itself configured in Shipit's `secrets.github` map (multi-org GitHub App mode) so they possess a valid webhook secret to sign with, and knowledge of the victim's target PR number/environment naming (`pr#{params.number}`) which is guessable/enumerable. This is a real but non-trivial precondition — it requires Shipit to be configured for multiple organizations and the attacker to be one of them, which is a plausible tenant model for Shipit's GitHub App multi-org support. Given that precondition, the attack is fully repeatable against any PR number/environment in the victim repository.

### Recommendation
In `Shipit::WebhooksController`, after JSON-parsing the body, verify that `params.dig('repository','full_name').split('/').first == params.dig('repository','owner','login')` (or, more robustly, derive `repository_owner` strictly from `full_name`'s owner segment and use that single source of truth both for selecting the signing GitHub App/secret and for resolving the target repository in every handler). Reject the request (422) on mismatch.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`-style, using existing fixtures):
1. Configure two orgs in test secrets (`org-a`, `org-b`) each with distinct `webhook_secret`s (or reuse fixture pattern from "unknown github organization" test).
2. Create a `ReviewStack` for `org-b/victim-repo` PR #42 (environment `pr42`), asserting `stack.archived?` is `false`.
3. Build a `pull_request` `closed` payload: `repository.owner.login = "org-a"`, `repository.full_name = "org-b/victim-repo"`, `number: 42`, valid `pull_request`/`sender` subfields per `ClosedHandler` schema.
4. Sign the raw JSON with `org-a`'s webhook secret; set `X-Hub-Signature` and `X-Github-Event: pull_request` headers.
5. POST to `/webhooks`, assert `response.status == 200`.
6. Reload the `org-b` stack and assert `stack.archived? == true` (or `assert_difference` on `ReviewStack.archived.count`), proving org-a's signature caused a write against org-b's stack — i.e., assert `repository_owner_used_for_signature ("org-a") != owner_of(full_name) ("org-b")` while the mutation still succeeded.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
