### Title
Webhook signature verification uses an org selected from the unverified payload, allowing cross-repository forged events - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
In multi-organization GitHub App configurations, `WebhooksController` selects which organization's `webhook_secret` to use for HMAC verification from a field inside the *untrusted* request body (`repository.owner.login`), rather than from any value tied to the actual target repository being acted upon (`repository.full_name`). Because these two fields are never cross-checked, an attacker who legitimately controls one onboarded GitHub organization (and therefore knows *that org's* webhook secret) can forge a signed payload whose `owner.login` names their own org (to pass signature verification) while `full_name` names a victim repository belonging to a different organization. The event handlers act on `full_name`, not on the verified `owner.login`, so the forged event is applied to a stack the attacker does not control.

### Finding Description
`Shipit.github` supports per-organization configuration (`lib/shipit.rb`, `github_app_config`), each with its own `webhook_secret`: [1](#0-0) 

`WebhooksController#verify_signature` picks the org (and therefore the secret) used to validate `X-Hub-Signature` purely from a field inside the JSON body being verified: [2](#0-1) 

Once the signature check passes (using the secret for whatever org the attacker put in `repository.owner.login`), `create` dispatches the *entire* payload to the registered handlers: [3](#0-2) 

The handlers, however, resolve the target repository/stack from a *different* field of the same payload — `repository.full_name` — with no relation back to `repository.owner.login`: [4](#0-3) 

`PushHandler` (and similarly `StatusHandler`, `CheckSuiteHandler`, `PullRequest::*Handler`) then act on whatever stacks match that `full_name`: [5](#0-4) 

This breaks the trust binding: **the organization whose secret authenticated the request** (`repository.owner.login`, used in `verify_signature`) is never required to equal **the repository that is actually written to** (`repository.full_name`, used by `Handler#stacks`/`#repository_name`). Any org admin who has legitimately set up their own GitHub App + webhook secret in Shipit's multi-org config (a documented, supported configuration per `docs/setup.md`) can therefore sign a payload with their own secret while pointing `full_name` at any other repository tracked by the same Shipit instance.

### Impact Explanation
An attacker in control of one onboarded organization's webhook secret can forge webhooks (`push`, `status`, `check_suite`, `pull_request`, etc.) that are applied to *any other organization's* stacks hosted on the same Shipit instance:
- A forged `push` event calls `stack.sync_github(expected_head_sha: ...)` on a victim stack, forcing sync/refresh behavior outside the attacker's authorization.
- A forged `status` event directly creates a `Status` record for an arbitrary commit on the victim's stack from attacker-supplied `state`/`context`/`description` fields (see `test/controllers/webhooks_controller_test.rb` `:state create a Status...`), which can satisfy `ci.require`/merge-queue checks and enable an unauthorized deploy or merge.

This is a cross-repository/cross-organization write and a path to an unauthorized deploy, matching the Critical impact bucket.

### Likelihood Explanation
Requires the deployment to use the documented multi-organization GitHub App configuration (`github.<org>.webhook_secret`) and requires the attacker to be a legitimate admin of at least one onboarded organization (able to create their GitHub App and choose/know its webhook secret) — this is the normal onboarding path described in `docs/setup.md`, not a privileged Shipit account or leaked internal secret. No access to the victim org, to `GITHUB_TOKEN`, or to Shipit sessions/API tokens is needed.

### Recommendation
Do not select the verification secret from a field inside the unverified body. Instead:
- Verify the signature against every configured org's secret (or the specific org's secret expected for that installation route/webhook endpoint), and
- After verification, cross-check that `repository.owner.login` (or `organization.login`) used to select/validate the secret matches the owner embedded in `repository.full_name` before dispatching to handlers, rejecting the event otherwise.

### Proof of Concept
1. Shipit is configured with multi-org GitHub Apps, e.g. `attacker-org` (secret `S_attacker`, known to the attacker as the org's own GitHub App creator) and `victim-org` (secret `S_victim`, unknown to attacker), both tracked in the same Shipit instance.
2. Attacker crafts a raw JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "attacker-org" }
  }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(S_attacker, raw_body)>` and sends:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=...
```
4. `verify_signature` calls `Shipit.github(organization: "attacker-org")` (from `repository.owner.login`), which validates successfully because the attacker signed with `S_attacker`.
5. `create` dispatches the payload to `PushHandler`, which resolves `repository_name` as `"victim-org/victim-repo"` (from `full_name`) and calls `stack.sync_github(...)` on the victim's stack — an action the attacker was never authorized to trigger on `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
