### Title
Unpriceable dust collateral blocks liquidation and bad-debt cleanup - ([File: contracts/controller/src/risk/totals.rs](contracts/controller/src/risk/totals.rs))

### Summary
An account can add a very small supply position in a listed asset whose price feed is already stale. Thereafter, both `liquidate` and `clean_bad_debt` value every supply position and revert with `PriceFeedStale`, even if the stale leg is economically insignificant. Because Soroban reverts the complete transaction, earlier repayment and seizure legs do not commit. [1](#0-0) 

### Finding Description
`supply` authenticates only `caller`; an owner can add another listed collateral leg to their own account through `supply(caller, account_id, spoke_id, assets)`. The third-party restriction only prevents other callers from creating new supply legs and does not restrict the account owner. [2](#0-1) [3](#0-2) 

The liquidation planner calls `calculate_account_risk_totals` before checking that the account is unhealthy. [4](#0-3)  That function loads markets for every supply and borrow key and then requests `cached_price` for every supply asset, without filtering dust, zero-risk-weight, or economically insignificant positions. [1](#0-0) 

Seizure is also computed pro rata across every supply position, so the liquidation API provides no argument that lets a liquidator exclude the unpriceable collateral leg. [5](#0-4)  `SeizeMode::Credit` does not bypass the problem because the strict account valuation and seizure plan run before share crediting. [6](#0-5) 

The existing regression proof demonstrates the reachable sequence: a borrower supplies WBTC while its Reflector price is stale, USDC later crashes, `liquidate` reverts with `PriceFeedStale`, and `clean_bad_debt` reverts for the same reason. [7](#0-6) 

### Impact Explanation
A borrower can place a low-cost stale-priced collateral leg in their account before becoming liquidatable. If the feed remains stale, liquidators cannot reduce the debt and permissionless cleanup cannot socialize it, so interest can continue accruing into protocol bad debt. This is a Medium-severity temporary freezing of liquidation funds and can become protocol insolvency if the oracle outage is permanent or persists until collateral value is exhausted. [8](#0-7) 

### Likelihood Explanation
The attack requires only a normal borrower, a listed collateral market, and enough of the collateral token to create a dust position. The existing test proves that `supply` accepts the WBTC leg while its feed is stale. [9](#0-8)  The borrower does not need privileged access, leaked keys, malformed parameters, or control of the oracle beyond selecting an asset whose configured feed is unavailable.

### Recommendation
Require a valid strict price when creating a new supply position, not merely when a later risk-parameter refresh needs the account health factor. For existing accounts, add a bounded recovery path that can remove or quarantine an unpriceable dust position after proving an upper bound on its value, or provide a liquidation/cleanup variant that isolates such a leg without letting borrowers evade valuable collateral seizure. Merely letting `SeizeMode::Credit` bypass cash settlement is insufficient because planning fails before delivery mode is applied. [10](#0-9) [4](#0-3) 

### Proof of Concept
From `tests/test-harness/tests/controller/audit_liquidate_and_clean_stale_leg.rs`:

```rust
#[test]
fn unpriceable_dust_leg_blocks_liquidation_and_cleanup() {
    let mut t = LendingTest::new()
        .three_asset_usdc_eth_wbtc()
        .with_dust_disabled_all_markets()
        .build();

    t.set_oracle_single_spot("WBTC");

    t.supply(LIQUIDATOR, "USDC", 50_000.0);
    let borrower = test_harness::ALICE;
    t.supply(borrower, "USDC", 10_000.0);
    t.borrow(borrower, "ETH", 3.0);

    // Make the WBTC feed stale before the borrower plants a dust leg.
    t.advance_time(5_000);
    let now = t.env.ledger().timestamp();
    let wbtc = t.resolve_asset("WBTC");
    t.mock_reflector_client()
        .set_price_at(&wbtc, &usd(60_000), &(now - 3_600));

    // The borrower's own supply call accepts the unpriceable dust position.
    let plant = t.try_supply(borrower, "WBTC", 0.001);
    assert!(plant.is_ok());

    // Make the account liquidatable.
    t.set_price("USDC", usd_cents(50));
    let borrower_id = t.resolve_account_id(borrower);

    // Neither liquidation nor bad-debt cleanup can skip the stale leg.
    assert_contract_error(
        t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0),
        errors::PRICE_FEED_STALE,
    );
    assert_contract_error(
        t.try_clean_bad_debt_by_id(borrower_id),
        errors::PRICE_FEED_STALE,
    );

    // Restoring the feed proves the stale leg is the blocker.
    t.set_price("WBTC", usd(60_000));
    assert!(t.try_liquidate(LIQUIDATOR, borrower, "ETH", 1.0).is_ok());
}
```
