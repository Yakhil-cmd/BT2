### Title
`ProxyType::NonTransfer` fails open and permits value-moving calls (AssetConversion, ForeignAssets, PoolAssets, PolkadotXcm, Revive) - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
`asset-hub-rococo`'s `ProxyType::NonTransfer::filter` implements a deny-list (`!matches!(c, ...)`) instead of an allow-list, so it fails open: any pallet call not explicitly named is treated as permitted. The deny-list only lists `Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques`, while the runtime also includes `AssetConversion`, `ForeignAssets`, `PoolAssets`, `PolkadotXcm`, and `Revive` — all of which can move the delegator's funds/assets — none of which are denied. [1](#0-0) 

### Finding Description
This mirrors exactly the bug class in the external report: an access-control check enumerates only a subset of operation kinds and implicitly treats every other kind as valid/allowed, rather than defaulting to deny. In the Algorand report, the approval program checked only `OptIn`/`CloseOut` and let `UpdateApplication`/`DeleteApplication` fall through as accepted. Here, `ProxyType::NonTransfer::filter` checks only 5 pallets and lets every other `RuntimeCall` variant — including several that move value — fall through as accepted:

```rust
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::NftFractionalization { .. } |
        RuntimeCall::Nfts { .. } |
        RuntimeCall::Uniques { .. }
),
``` [2](#0-1) 

This runtime's `construct_runtime!` includes `AssetConversion`, `ForeignAssets`, `PoolAssets`, `PolkadotXcm`, and `Revive` as live pallets/`RuntimeCall` variants (confirmed present in the file), all of which are absent from the deny-list.

Notably, the identical bug was already found and fixed in the sibling runtime `asset-hub-westend` via a documented regression fix: [3](#0-2) 
and the corresponding westend `ProxyType::NonTransfer` filter now explicitly denies `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, `Vesting::vested_transfer`, and `Indices::transfer`/`force_transfer`: [4](#0-3) 
There is also a dedicated regression test enforcing this on westend: [5](#0-4) 

The `asset-hub-rococo` implementation, however, still has the vulnerable/pre-fix deny-list and has not received the equivalent patch, leaving the fail-open access-control gap live in that runtime's `pallet-proxy` configuration.

### Impact Explanation
`pallet-proxy`'s `do_proxy` dispatches the wrapped call through `origin.add_filter(... def.proxy_type.filter(c) ...)` — i.e., `ProxyType::filter` is the actual gate deciding what a delegate can execute on behalf of the delegator: [6](#0-5) 

A delegate holding only a `NonTransfer` proxy — which is documented/intended to disallow moving the delegator's funds or assets — can, on asset-hub-rococo, still: swap/withdraw liquidity via `AssetConversion`, transfer `ForeignAssets`/`PoolAssets`, execute raw XCM `send`/`execute` or `transfer_assets`/`teleport_assets` via `PolkadotXcm`, and make value-carrying contract calls/instantiations via `Revive`. This lets an attacker holding a limited, non-transfer delegation move or drain the delegator's assets, matching the exploit scenario in the source report (an attacker abusing an under-checked permission gate to steal funds it should not be able to touch).

### Likelihood Explanation
No privileged role is required beyond being granted (or otherwise obtaining) any `NonTransfer` proxy relationship — this is the normal, documented "safe" delegation type users are expected to grant to less-trusted delegates. The bypass requires only a signed `Proxy::proxy` extrinsic wrapping one of the unlisted calls (`AssetConversion`, `ForeignAssets`, `PoolAssets`, `PolkadotXcm`, `Revive`), all of which are ordinary permissionless user-facing extrinsics. The exact analogous bug (asset-hub-westend) was previously confirmed exploitable and fixed, confirming the reachability and severity of this pattern; the same fix was simply never back-ported to asset-hub-rococo.

### Recommendation
Apply the same fix as PR referenced in `prdoc/pr_12771.prdoc` to `asset-hub-rococo`: extend `ProxyType::NonTransfer::filter`'s deny-list to explicitly include `AssetConversion`, `ForeignAssets`, `PoolAssets`, `PolkadotXcm`, and `Revive` (and any other value-moving pallet enabled in that runtime), or better, convert the filter to an allow-list so newly added pallets fail closed by default instead of fail open. Add a regression test mirroring `non_transfer_proxy_rejects_value_moving_calls` for asset-hub-rococo to prevent recurrence.

### Proof of Concept
- Confirmed by direct code inspection that `asset-hub-rococo`'s `ProxyType::NonTransfer::filter` (lines 604–621) omits `AssetConversion`, `ForeignAssets`, `PoolAssets`, `PolkadotXcm`, `Revive` from its deny-list.
- Confirmed via grep that these pallet identifiers occur in `asset-hub-rococo/src/lib.rs` (4 matches for the pallet-name-with-colon pattern used in `construct_runtime!`), indicating they are live pallets/`RuntimeCall` variants in this runtime.
- Confirmed the identical bug was previously found and fixed for `asset-hub-westend` (`prdoc/pr_12771.prdoc`, `prdoc/pr_12922.prdoc`) with dedicated regression tests, establishing this bug class as real and previously bounty-worthy in this codebase family; the rococo runtime was not patched.
- I was not able to execute a live integration test against a running rococo node/runtime instance in this session (no execution environment available); the finding is based on static code comparison between the vulnerable pre-fix pattern (still present in rococo) and the fixed pattern (now in westend), plus confirmation that the omitted pallets are present in the rococo `RuntimeCall` enum. A follow-up session with a Rust/FRAME test harness should add a `non_transfer_proxy_rejects_value_moving_calls`-style test for `asset-hub-rococo` to produce a concrete failing/passing assertion.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});
