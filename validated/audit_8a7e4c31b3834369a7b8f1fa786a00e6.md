## Title
Webhook signature verification authenticates the organization named in `repository.owner.login`, while every event handler resolves and mutates the repository named in the separate, unverified `repository.full_name` field - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

## Summary
`WebhooksController#verify_signature` derives the organization used to check the HMAC signature from `repository.owner.login` (falling back to `organization.login`), a plain field inside the attacker-supplied JSON body. Every default event handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, the `PullRequest::*` handlers) instead resolves the *actual* repository/stack to act on from a different field in the same untrusted payload: `repository.full_name`. Nothing binds these two fields together, and `GithubApp#verify_webhook_signature` returns `true` unconditionally whenever the resolved organization has no `webhook_secret` configured. This breaks the equality `verified_organization(webhook) == owner_of(repository_acted_upon)`.

## Finding Description
`verify_signature` computes the org used for authentication purely from the payload: [1](#0-0) 

That org is passed to `Shipit.github(organization: repository_owner)`, and its signature is checked with: [2](#0-1) 

Note line 77: `return true unless webhook_secret` - if the resolved organization is configured but has no secret (a documented, supported configuration, e.g. `webhook_secret: # nil` in `config/secrets.development.shopify.yml` and `docs/setup.md`), signature verification is bypassed entirely regardless of the actual `X-Hub-Signature` header.

Meanwhile, every handler determines the repository actually mutated using a *different* field of the same payload: [3](#0-2) 

`PushHandler`, `StatusHandler`, and `CheckSuiteHandler` all consume this `stacks`/`repository_name` helper to find the `Stack`/`Commit` to act on: [4](#0-3) [5](#0-4) [6](#0-5) 

For a legitimate GitHub-originated webhook, `repository.owner.login` and the owner segment of `repository.full_name` always agree because GitHub populates both from the same repository object. For a forged request sent directly to the unauthenticated `/webhooks` endpoint, an attacker fully controls the JSON body and can set these two fields independently - e.g. `repository.owner.login = "org-with-no-secret"` (satisfying `verify_signature`) while `repository.full_name = "victim-org/victim-repo"` (the repository actually mutated by the handler).

This is precisely the binding class the report demonstrates for `savedTotalUnderlying`: a security-relevant state mutation is keyed off a *requested*/asserted quantity (`repository.owner.login`, checked) that diverges from the *actual* quantity the operation is performed against (`repository.full_name`, unchecked) - "an organization that authenticated versus the repository that is written."

## Impact Explanation
Once verification is satisfied for the attacker-chosen, secret-less organization, the attacker can drive handler-level effects against any repository/stack actually tracked by the Shipit instance:
- `StatusHandler` writes arbitrary commit CI statuses via `commit.create_status_from_github!(params)` for any `sha` matching a tracked `Commit`, which can be used to fake a passing CI/status context that gates deploy eligibility (`release_status_context`).
- `PushHandler` and `CheckSuiteHandler` trigger `stack.sync_github` and check-run refresh scheduling for the victim stack.
- The `pull_request` handlers act on the same mismatched-repository resolution path and can affect review-stack lifecycle state for a repository the "authenticating" organization has no relation to.

Faking a green CI/status check for a victim's commit is a direct step toward an unauthorized deploy of an unreviewed or unsafe revision, which falls under the Critical impact bucket ("an unauthorized deploy, rollback or merge").

## Likelihood Explanation
The webhook endpoint is intentionally unauthenticated at the HTTP layer (protected only by the HMAC check), so any external attacker can POST to it. The only precondition is that the Shipit instance has at least one configured GitHub organization without a `webhook_secret` — a state explicitly supported and shown in the shipped example configs (`config/secrets.development.shopify.yml`, `docs/setup.md`). Multi-tenant Shipit deployments tracking several organizations, where not every org owner has set up a webhook secret, are the realistic trigger condition for this analog.

## Recommendation
Bind the field used for signature verification to the field used for the actual mutation: derive `repository_owner` from the same `repository.full_name` (or require they match) before dispatching to handlers, and reject the request if `repository.owner.login`/`organization.login` disagrees with the owner segment of `repository.full_name`. Additionally, consider treating a missing `webhook_secret` as "reject unsigned/unverifiable requests" rather than "always verified," or restrict handler dispatch to only the repositories owned by the exact organization that was cryptographically verified.

## Proof of Concept
1. Identify (from deployment docs/behavior) that organization `empty-secret-org` is configured on the target Shipit instance with no `webhook_secret`.
2. POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "repository": { "owner": { "login": "empty-secret-org" }, "full_name": "victim-org/victim-repo" },
  "sha": "<victim commit sha tracked by Shipit>",
  "state": "success",
  "context": "ci/required-check"
}
```
3. `verify_signature` resolves `repository_owner = "empty-secret-org"`, and `verify_webhook_signature` returns `true` unconditionally because that org has no secret — no valid `X-Hub-Signature` is required.
4. `StatusHandler` processes the payload using `repository.full_name = "victim-org/victim-repo"`'s commit, creating a forged passing status for a commit in a repository the attacker never authenticated against.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
