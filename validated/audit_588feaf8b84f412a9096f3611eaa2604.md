### Title
Missing CheckRedirect policy allows Authorization Bearer token to follow cross-host redirects from the Copilot API - (File: pkg/cmd/agent-task/capi/client.go)

### Summary
`NewCAPIClient` only wraps `httpClient.Transport` with `capiTransport` and never sets `httpClient.CheckRedirect`, so the default `net/http` behavior (follow up to 10 redirects) applies. `capiTransport.RoundTrip` unconditionally sets the `Authorization: Bearer <token>` header on every request it processes, including the synthetic follow-up request `net/http` builds for a redirect `Location`, regardless of destination host.

### Finding Description
`NewCAPIClient` constructs a `capiTransport` and assigns it to `httpClient.Transport`, but does not touch `httpClient.CheckRedirect`: [1](#0-0) 

`capiTransport.RoundTrip` sets the Authorization header unconditionally on every call, and only conditionally adds `Copilot-Integration-Id`/`X-GitHub-Api-Version` based on host match — the Authorization header itself has no host check: [2](#0-1) 

`ListLatestSessionsForViewer` and `GetSession` (and the other CAPI methods) issue requests via `c.httpClient.Do(req)`: [3](#0-2) [4](#0-3) 

Because no `CheckRedirect` is set, `net/http.Client` uses its default policy: follow up to 10 redirects, and for each hop it builds a new `*http.Request` and invokes `Transport.RoundTrip` again — which re-adds the Authorization header unconditionally, including to a different host than `capiBaseURL`. `net/http`'s default client does sanitize `Authorization`/cookie headers that were present on the *original* request when redirecting cross-host, but that protection does not apply here: the header isn't carried over from the original request, it is freshly injected by `RoundTrip` on the redirected request itself, bypassing that safeguard entirely.

### Impact Explanation
If an attacker can get the client to receive an HTTP redirect from the resolved `capiBaseURL` host (e.g., via a compromised/malicious proxy, a misresolved/attacker-influenced CAPI host, or any response the client trusts as coming from `capiBaseURL`), the attacker-controlled `Location` can point anywhere, and the CLI will send its Copilot bearer token to that URL. This is a credential-exfiltration primitive (matches "credential/token disclosure").

### Likelihood Explanation
Exploitability strictly depends on the attacker's ability to control the response returned from the resolved `capiBaseURL` host (e.g., a host-confusion bug in URL resolution, a malicious/compromised proxy, or a misdirected DNS/host value) — which is an external precondition not established within this file. Under the stated unprivileged, no-MITM, no-local-access threat model, an attacker who cannot already influence responses from the trusted CAPI host has no way to trigger this. This finding is a defense-in-depth gap (no redirect-based token-stripping safeguard) rather than an independently attacker-reachable vulnerability absent that other precondition.

### Recommendation
Set an explicit `httpClient.CheckRedirect` function on the client used by `NewCAPIClient` that either disallows redirects entirely for CAPI requests, or strips the `Authorization` header (and refuses to re-add it in `RoundTrip`) whenever the redirect target host differs from `capiHost`. Additionally, `capiTransport.RoundTrip` should only set `Authorization` when `req.URL.Host == ct.capiHost` (or otherwise validate destination) rather than unconditionally.

### Proof of Concept
```go
func TestCAPITokenNotSentOnCrossHostRedirect(t *testing.T) {
    var secondHostAuthHeader string
    second := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        secondHostAuthHeader = r.Header.Get("Authorization")
        w.WriteHeader(http.StatusOK)
    }))
    defer second.Close()

    first := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        http.Redirect(w, r, second.URL+"/agents/sessions", http.StatusFound)
    }))
    defer first.Close()

    client := capi.NewCAPIClient(&http.Client{}, "secret-token", "github.com", first.URL)
    _, _ = client.GetSession(context.Background(), "abc")

    if secondHostAuthHeader != "" {
        t.Fatalf("expected no Authorization header sent to redirect target, got %q", secondHostAuthHeader)
    }
}
```
Expected (current) result: the test fails because `secondHostAuthHeader` contains `Bearer secret-token`, proving the token followed the cross-host redirect. After adding a `CheckRedirect`/host check, the test should pass.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
