### Title
Webhook signature verification is fully bypassed for any organization missing `webhook_secret`, allowing unauthenticated PR mutation - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#verify_webhook_signature` short-circuits to `true` whenever the organization's config has no `webhook_secret`, before any HMAC comparison happens. Since the organization used for verification (`repository_owner` from the payload) is attacker-controlled and is the same value used later by `EditedHandler` to resolve the real `Repository`/`PullRequest`, an attacker can post an unsigned webhook naming a secretless-but-tracked org and mutate a real `PullRequest` row.

### Finding Description
The broken binding, stated as an equality that must hold but does not:
`organization_that_cryptographically_verified(request_bytes) == organization_that_owns(repository written by handler)`.

Trace:
1. `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` is read straight from the attacker-controlled payload: `params.dig('repository', 'owner', 'login')` [1](#0-0) , [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` is invoked with the raw signature header and raw body, but returns `true` immediately if `webhook_secret` is blank for that org's config — no HMAC comparison, no signature-presence check — `return true unless webhook_secret` [3](#0-2) .
3. `#create` then dispatches the raw JSON body to `EditedHandler.call(params)` [4](#0-3) .
4. `EditedHandler#repository` resolves the real, tracked `Shipit::Repository` from `params.repository.full_name` (also attacker-supplied) [5](#0-4) , and `#pull_request` looks up the real `PullRequest` by `number` scoped to that repository [6](#0-5) .
5. `#process` calls `pull_request.update(github_pull_request: params.pull_request)`, persisting attacker-chosen fields (including `title`) onto the real row [7](#0-6) .

Because step 2 never actually authenticates anything when `webhook_secret` is absent, no organization "verified" the bytes at all, yet the write in step 5 still targets a genuinely tracked repository/PR owned by that org. The equality fails: the left side is "nobody" (no verification occurred) while the right side is a real, existing organization's repository. Neither `drop_unhandled_event` (the `pull_request`/`edited` event is a handled event) nor the `ExplicitParameters` schema (which only validates shape, not authenticity) nor any user/session/permission check intervenes, because this entire path is unauthenticated by design (webhook endpoint, no `current_user`).

### Impact Explanation
An unauthenticated internet attacker can forge a `pull_request`/`edited` webhook for any organization whose Shipit configuration omits `webhook_secret`, and — provided that org has at least one repository/stack/PR tracked in Shipit — overwrite the `title` (and other `github_pull_request` fields) of a real `PullRequest` record without ever knowing a secret or presenting `X-Hub-Signature`. This is a webhook-authentication bypass (Critical): a request that must be attributable to a specific GitHub organization is accepted as authentic with zero verification, and it mutates persistent state for a real repository. The blast radius is scoped to organizations that lack a configured `webhook_secret`; every such org is fully open to this bypass for any handled webhook event, not just `edited`.

### Likelihood Explanation
Precondition: at least one organization configured in `Shipit.github_apps` without a `webhook_secret`, while owning a repository that is actually tracked (has a `Repository`/`Stack`/`PullRequest`) in Shipit. This is exactly the kind of misconfiguration the shipped `secrets.development` template can lead operators to leave in place (per the audit context), and organization names/repo names are public GitHub information, so the attacker cost is negligible: craft one JSON POST to `/webhooks` with `X-Github-Event: pull_request`, no signature header, and correct `repository.owner.login`/`repository.full_name`/`pull_request.number`. It is fully repeatable against any PR number in that org's tracked repos.

### Recommendation
Do not treat a missing `webhook_secret` as "skip verification." Either require every configured organization to have a non-blank `webhook_secret` and fail closed (reject/`422`) when it's absent, or explicitly and loudly opt an organization out only in non-production/test environments, never based on the mere absence of a config key. At minimum, change `verify_webhook_signature` so that `webhook_secret.blank?` results in rejecting all requests (return `false`) rather than accepting them (return `true`), and audit `config/secrets.yml` deployments for orgs missing `webhook_secret`.

### Proof of Concept
```ruby
# test/lib/shipit/github_app_test.rb (unit proof of the broken binding)
class GithubAppVerifyWebhookSignatureTest < ActiveSupport::TestCase
  test "verify_webhook_signature returns true with no secret and no signature" do
    app = Shipit::GitHubApp.new('secretless-org', {}) # no webhook_secret key
    # LHS of the binding: "organization that verified the bytes" -- none, since no HMAC check ran.
    assert_equal true, app.verify_webhook_signature(nil, "anything-attacker-controlled")
  end
end

# test/controllers/webhooks_controller_test.rb (integration proof of impact)
test "unsigned pull_request/edited webhook mutates a real PullRequest for a secretless org" do
  repository = shipit_repositories(:shipit) # tracked repo owned by an org with no webhook_secret in test secrets
  pr = shipit_pull_requests(:shipit_pending) # existing tracked PR under that repo/stack
  original_title = pr.title

  payload = {
    action: 'edited',
    number: pr.number,
    pull_request: {
      id: pr.github_id, number: pr.number, url: 'https://…', title: 'PWNED TITLE',
      state: 'open', additions: 1, deletions: 1,
      head: { sha: 'a' * 40, ref: 'main' },
      user: { login: 'attacker' }, assignees: [], labels: []
    },
    repository: { full_name: repository.full_name, owner: { login: repository.owner } },
    sender: { login: 'attacker' }
  }.to_json

  post shipit.webhooks_path,
    params: payload,
    headers: { 'X-Github-Event' => 'pull_request', 'Content-Type' => 'application/json' }
    # deliberately NO X-Hub-Signature header

  assert_response :ok
  pr.reload
  refute_equal original_title, pr.title
  assert_equal 'PWNED TITLE', pr.title
end
```
Both sides of the binding: before the request, `verified_by(bytes) = nil` (no HMAC ever computed) while `owner_of(pull_request.stack.repository) = repository.owner`; after the request, the PR title still changed — proving state mutation occurred without any organization ever verifying the request bytes.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
