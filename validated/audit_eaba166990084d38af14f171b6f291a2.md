### Title
Unchecked i128 overflow in accrual (`scaled_to_original`) permanently freezes a market — every entry point accrues first and reverts - (File: common/src/rates/simulate.rs)

### Summary
The analog of CVE-2019-6445 (a crash primitive reachable by an authenticated party that permanently disables the daemon) is a reachable arithmetic panic in the interest-accrual step. `accrue_step` multiplies the scaled totals by the indexes via `scaled_to_original` → `Ray::mul` → `mul_div_half_up`, which panics (`MathOverflow`, error 33) when `scaled * index` exceeds the `i128` domain. Once a market's `borrowed * borrow_index` crosses the representable ceiling, accrual panics, `global_sync` runs before every state-changing pool verb, and the market is frozen permanently: no `withdraw`, `repay`, `borrow`, `seize`, or `update_indexes` can succeed. Unlike the borrow-index cap (`MAX_BORROW_INDEX_RAY = 10^36`), which bounds the *index*, nothing bounds `borrowed_scaled * index`, so the value ceiling is hit first and the cap never engages. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
`accrue_step` computes `borrowed_original = scaled_to_original(env, borrowed, borrow_index)` and `supplied_original = scaled_to_original(env, supplied, supply_index)` before anything else. `scaled_to_original` is a `Ray::mul` (`mul_div_half_up(scaled, index, RAY)`) which uses `I256`-widened multiplication only to detect overflow and then panics with `GenericError::MathOverflow` when the result exceeds `i128::MAX`. [5](#0-4) [2](#0-1) 

`update_borrow_index` caps the *index* at `MAX_BORROW_INDEX_RAY`, but the overflow lives in the product `borrowed_scaled * borrow_index`, which is reached at index ≈ 170× on a market holding ~10^28 scaled debt — well below the 10^36 cap. The panic is not transient: `global_sync` (which every pool mutation and the controller's `update_indexes` invoke) loops `accrue_chunk` until `remaining == 0`, so the very first instruction of every subsequent interaction re-executes the same overflowing multiply and reverts. [6](#0-5) [4](#0-3) 

The repo's own regression test demonstrates this end-to-end: at ~98% utilization on a whale market, `try_update_indexes_for` reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and afterwards both `withdraw` and `repay` revert with the same error — "no repay, no withdraw, no liquidation". [7](#0-6) 

### Impact Explanation
Permanent freezing of funds. All supplier principal and accrued yield in the affected market become permanently unrecoverable — `withdraw` accrues first and panics; `repay`, `liquidate`, `clean_bad_debt`, and `recapitalize` hit the same accrual path, so there is no recovery verb. This matches the accepted impact classes (permanent freezing of funds / contract unable to operate) rather than a fail-closed check: the panic is an unguarded internal arithmetic trap, not an intentional rejection. [6](#0-5) [8](#0-7) 

### Likelihood Explanation
An unprivileged borrower reaches this through ordinary `borrow`/`supply` plus `update_indexes` — no privileged call is needed. The trigger requires an extremely large market (the test uses ~10^9 × 10^18 units) and sustained high utilization for a multi-year horizon at the 200% APR curve ceiling, so exploitation is capital- and time-intensive rather than instant; hence Medium rather than High. The failure mode is confirmed by an existing harness test, not speculation. [9](#0-8) [10](#0-9) 

### Recommendation
Saturate rather than panic in the accrual path. Concretely: in `accrue_step`, compute `borrowed_original`/`supplied_original` with a saturating multiply-divide (`mul_div_floor_saturating`/`mul_div_half_up_saturating` style helper) or clamp the accrual to a representable domain — e.g., when `scaled * index` would overflow, cap the effective accrued value at `i128::MAX` and/or force `borrow_index` to `MAX_BORROW_INDEX_RAY` and stop interest accrual (debt keeps its last representable value) instead of trapping. A freeze-safe fallback such as "if the chunk panics, accrue nothing and stamp `last_timestamp = now`" would also unstick the market. Additionally, add a governance or per-market guard that halts new borrows when `borrowed * borrow_index` approaches the `i128` ceiling, mirroring the existing `MAX_BORROW_INDEX_RAY` index cap. [11](#0-10) [4](#0-3) 

### Proof of Concept
The repository already contains a working demonstration in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`:

1. Build a market with an 18-decimal asset on the XLM rate curve (`with_max_utilization_disabled_all_markets`, `lift_caps`).
2. `BOB` supplies `BILLION * 10^18` units; `ALICE` supplies collateral and borrows ~98% (`debt = principal/100*98`).
3. Advance time year-by-year, calling `update_indexes` each year. After index growth of ~170×, `try_update_indexes_for` returns `Error(Contract, #33)` (`MATH_OVERFLOW`) with `borrow_index` still below `MAX_BORROW_INDEX_RAY`.
4. Thereafter `t.try_withdraw_raw(BOB, "BIG18", 1)` and `t.try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW` — the market is permanently frozen. [12](#0-11)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
