No matches for `jackson` in the repository, and the CBOR/Jackson advisory concerns a Java Maven dependency (`com.fasterxml.jackson.dataformat:jackson-dataformat-cbor`) with unchecked byte-buffer allocation causing `OutOfMemoryError`. This is a Rust codebase (`polkadot-sdk`) with no Jackson/Maven dependency chain whatsoever, so the vulnerable library is not present at all.

Looking for an actual analog within the codebase's own decoding paths (SCALE/XCM), the relevant decode routines already enforce explicit size/depth/memory limits rather than doing unchecked allocation based on attacker-supplied length fields:
- `VersionedXcm::decode_all_with_mem_and_depth_limit` wraps input in a `MemTrackingInput` bounded by `MAX_XCM_SIZE`, and enforces `MAX_XCM_DECODE_DEPTH` before any allocation is permitted. [1](#0-0) 
- The nested `DoubleEncoded` decoder propagates `on_before_alloc_mem` notifications to the downstream input and enforces `RECURSION_LIMIT`/`MAX_XCM_DECODE_DEPTH` checks before decoding untrusted nested calls. [2](#0-1)
