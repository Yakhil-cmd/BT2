### Title
`ProxyType::NonTransfer` proxy escalates to `paras_registrar::Call::swap` via mis-declared `is_superset` over `ProxyType::Auction` - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
The `InstanceFilter` implementation for `ProxyType` on the Westend relay-chain runtime declares `NonTransfer` a superset of *every* other proxy type (`(ProxyType::NonTransfer, _) => true`), including `Auction`, while `NonTransfer`'s own call filter explicitly and intentionally excludes `paras_registrar::Call::swap` ("Specifically omitting Registrar `swap`"). Because `pallet_proxy` authorizes `add_proxy`/`remove_proxy` purely on `is_superset` (not on the target type's actual filter), a `NonTransfer` delegate can add itself an `Auction` proxy for the real account and then invoke `Registrar::swap` through that new proxy — a call the delegator deliberately withheld from the `NonTransfer` grant. This is the exact bug class already found and fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend (PR #12769/`pr_12769.prdoc`), but it remains present for the `NonTransfer`/`Auction` pair on the Westend (and Rococo, and `staking-async` `rc`) relay-chain runtimes.

### Finding Description
`ProxyType::filter` for `NonTransfer` on Westend admits `RuntimeCall::Proxy(..)` unconditionally and admits only `Registrar::register`/`deregister`/`reserve`, explicitly omitting `Registrar::swap`: [1](#0-0) 

`ProxyType::Auction`'s filter admits the entire, unrestricted `Registrar(..)` call family (including `swap`): [2](#0-1) 

`is_superset` uses a blanket rule that makes `NonTransfer` a declared superset of *all* other types, including `Auction`, without checking that `NonTransfer`'s filter actually covers everything `Auction` admits: [3](#0-2) 

`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` purely on `is_superset`, not on the target type's filter: [4](#0-3) 

Consequence: a delegate holding only a `NonTransfer` proxy for `real`
1. Dispatches `proxy(real, None, Proxy::add_proxy{ delegate: <self>, proxy_type: Auction, delay: 0 })`. The add-proxy escalation guard checks `!NonTransfer.is_superset(Auction)`, which is `false` (since `is_superset` unconditionally returns `true` for `NonTransfer`), so the call falls through to `NonTransfer.filter(Proxy::add_proxy{..})`, which is `true` because `NonTransfer` admits the whole `Proxy` pallet. `add_proxy` succeeds.
2. Dispatches `proxy(real, Some(Auction), Registrar::swap{ id, other })`. `find_proxy` locates the freshly added `Auction` definition; the filter check is `Auction.filter(Registrar::swap{..})`, which is `true` because `Auction` admits unrestricted `Registrar(..)`.

The end result: `Registrar::swap` executes with `origin = Signed(real)`, exactly the call that `NonTransfer`'s own filter was written to deny. This is a proxy-type call-filter lattice violation identical in root cause to the one already patched via `pr_12769.prdoc` and its regression tests `proxy_type_superset_relation_matches_call_filters` / `non_transfer_proxy_is_not_a_superset_of_governance`, which prove the maintainers recognize and treat this specific class as a genuine authorization bug — just not remediated here for the `Auction` edge on the relay-chain runtime(s). [5](#0-4) [6](#0-5) 

The same unfixed pattern (`(ProxyType::NonTransfer, _) => true` combined with `Auction` admitting unrestricted `Registrar(..)`) also exists on Rococo and the `staking-async` `rc` runtime: [7](#0-6) [8](#0-7) 

`Registrar::swap` requires the caller to be Root, the para's owner, or the para itself, and swaps parachain/parathread lifecycle and scheduling data (and, per `pr_3714.prdoc`, now also notifies the Coretime broker chain of the swap via XCM): [9](#0-8) 

### Impact Explanation
This is an authorization/dispatch-filter integrity break: an account that was granted only a `NonTransfer` proxy — specifically to be denied `Registrar::swap` — can nonetheless self-escalate and invoke it against paras owned by the delegator (`real`), because `ensure_root_para_or_owner` still passes for `Signed(real)`. The delegate cannot reach paras not owned by `real`, so this is not a cross-account theft, but it is an unauthorized dispatch relative to the explicit intent encoded in the `NonTransfer` filter, and it can be used to unexpectedly swap `real`'s parachain/parathread slot assignment, associated deposits/lease bookkeeping and now Coretime broker-chain state, without the delegator's consent for that specific action. Given the maintainers already classified and fixed the sibling case (`NonTransfer`/`Governance`) as worth a runtime patch, this is a real but bounded (Medium) authorization defect, not a Critical unbacked-issuance or theft bug.

### Likelihood Explanation
Reachable by any account that a `real` user has granted a plain `NonTransfer` proxy to — a routine, publicly documented delegation pattern (`pallet_proxy::add_proxy`), with no privileged role, governance action, or stolen keys required. The only prerequisite is that `real` owns at least one registered para (the normal target audience for this proxy). No node/collator/validator compromise, forged inherent, or external chain trust is needed — purely two signed extrinsics from the delegate account.

### Recommendation
Apply the same fix pattern used in `pr_12769.prdoc` for `Governance`: remove the blanket `(ProxyType::NonTransfer, _) => true` catch-all and enumerate exactly the subset relationships that `NonTransfer`'s filter actually covers, explicitly excluding `Auction` (and any other type whose filter admits calls `NonTransfer` deliberately omits, e.g. unrestricted `Registrar(..)`/`swap`). Extend the existing `proxy_type_superset_relation_matches_call_filters`-style regression test (currently only run for `asset-hub-westend`) to the Westend relay-chain runtime, the Rococo runtime, and the `staking-async` `rc`/`parachain` runtimes so this class of lattice violation cannot silently reappear elsewhere.

### Proof of Concept
Not executed against a live network. Root cause and reachability were verified statically by tracing:
- `polkadot/runtime/westend/src/lib.rs:973-1030` (`NonTransfer` filter omitting `swap`; `Auction` filter admitting unrestricted `Registrar(..)`; `is_superset` blanket rule),
- `substrate/frame/proxy/src/lib.rs:994-1026` (`do_proxy` gating `add_proxy` purely on `is_superset`),
- `polkadot/runtime/common/src/paras_registrar/mod.rs:316-338` (`swap` dispatchable and its `ensure_root_para_or_owner` check).

A minimal integration reproduction (not run here) would use `polkadot/runtime/common/src/paras_registrar/tests.rs` or a Westend runtime test harness to: (1) register a para owned by account `A`; (2) `A` calls `Proxy::add_proxy(B, ProxyType::NonTransfer, 0)`; (3) `B` calls `Proxy::proxy(A, None, Proxy::add_proxy{ delegate: B, proxy_type: Auction, delay: 0 })` and assert it succeeds; (4) `B` calls `Proxy::proxy(A, Some(Auction), Registrar::swap{ id, other })` and assert it succeeds — demonstrating that `B`, holding only `NonTransfer`, achieved `swap`, which `NonTransfer`'s filter explicitly denies. This mirrors the already-existing `non_transfer_proxy_is_not_a_superset_of_governance` regression test methodology, applied to the unfixed `Auction`/`swap` edge. Existing deployment evidence: the sibling bug for `Governance` was confirmed live enough on Asset Hub Westend to warrant `prdoc/pr_12769.prdoc`; the `Auction`/`swap` edge shown here uses the identical `is_superset` blanket-rule pattern and remains unpatched in `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

		/// The swap will happen only if there is already an opposite swap pending. If there is not,

		///
		/// The `ParaId`s remain mapped to the same head data and code so external code can rely on
		/// `ParaId` to be a long-term identifier of a notional "parachain". However, their

			Self::ensure_root_para_or_owner(origin, id)?;

			// If `id` and `other` is the same id, we treat this as a "clear" function, and exit
