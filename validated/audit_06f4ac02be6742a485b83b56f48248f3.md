Based on my research, I found a structurally analogous "invariant enforced in one code path but silently skipped in a sibling path" bug class in ocore, involving the well-formedness/lone-surrogate check that plays the same role as mistune's `escape=True` contract.

### Title
AA-generated response/state content can bypass the "well-formed string" integrity check enforced on ordinary units - (File: formula/evaluation.js, aa_composer.js)

### Summary
ocore treats "well-formedness" of every string reaching a unit (no lone UTF‑16 surrogates, no NUL bytes) as a hard validity invariant, exactly like Mistune's `escape=True` contract for HTML output. The invariant is enforced centrally for every externally-received unit via `isObjectWellFormed()` [1](#0-0) , and it is re-implemented ad-hoc, deliberately, for one specific internally-generated value: AA state-variable assignments explicitly call `.isWellFormed()` on both the var name and the value before persisting them [2](#0-1) . This shows the authors recognize that formula-generated strings (built via `concat`, substring-style manipulation, string.js `chr()`, unicode escapes, etc.) are not automatically well-formed even though the *original* trigger unit passed the top-level check, and therefore need re-validation before being written/hashed again.

However, this same re-validation is not visibly applied to other AA/oscript-generated string outputs that end up embedded in newly composed response units — `response[...]` variables (used in `data`/`attestation`/`text` messages of the composed response, see usages in `formula/evaluation.js` and sample oscripts such as `test/samples/order_book_exchange.oscript` and `test/samples/a_bank_without_percent.oscript`) and the message-composition logic in `aa_composer.js`, which contains no occurrence of `isWellFormed`/`isObjectWellFormed` at all. This mirrors the mistune bug precisely: one render/output path (`HTMLRenderer` main methods / `state_var_assignment`) honors the security contract, while a sibling path that produces equally attacker-influenced content (`math` plugin / `response[...]`, formula-composed `data`/`attestation`/`text` payloads) silently ignores it.

### Finding Description
- The well-formedness contract exists specifically to prevent ill-formed UTF‑16 strings (lone surrogates) from entering units, because such strings can serialize inconsistently across JS engines/JSON implementations and break the deterministic hashing that the whole DAG-consensus and stability model depends on. This is explicitly called out in the code: `"unit contains invalid string (lone surrogate or null byte)"` [3](#0-2) , and there is even an offline auditing tool for scanning stored joints for violations of this invariant [4](#0-3) .
- `String.prototype.isWellFormed` / `isObjectWellFormed` are the canonical enforcement primitives [5](#0-4) [6](#0-5) .
- For externally-submitted units, the check is applied once, centrally, at the very top of `validate()`, covering the entire joint recursively [1](#0-0) .
- For AA formula execution, the authors recognized that the general check does not automatically re-run on values *derived* from formula operations (concatenation, substrings, etc.), so they added an explicit, narrow re-check only for `state_var_assignment` (`var[...] =`) [2](#0-1)  and for `var[...]` name reads used as the getter's oracle path [7](#0-6) .
- The same formula engine can build strings via `concat` for many other outputs besides state vars — `response[...]` assignments, `data`/`attestation`/`text` message payload fields, and dynamically generated message objects (`{$getMessage(...)}` patterns seen throughout the AA test suite, e.g. `test/aa_composer.test.js:873-920`) — that all end up as part of a brand-new response unit built by `aa_composer.js`. I was unable to find any call to `isWellFormed`/`isObjectWellFormed` inside `aa_composer.js`, and the grep for these tokens against that file returned zero matches, while the response-var assignment logic in `formula/evaluation.js` (distinct from `state_var_assignment`) did not show the same explicit `.isWellFormed()` guard that state vars have.

### Impact Explanation
If a formula can construct an ill-formed string (lone surrogate) via `concat`/`chr`/substring tricks and place it into a `data`, `attestation`, or `text` message of the AA's own response unit without the well-formedness re-check, the resulting response unit's JSON/hash serialization could diverge between different Node.js/V8 versions or between full and light nodes performing hash/ball computations, exactly the failure mode the codebase's own comment warns about ("lone surrogate ... unit contains invalid string"). Since AA response units are part of the DAG and their content and hashes are used for stability determination, commissions, and dependent AA triggers, this can lead to node disagreement on unit validity/hash or on stability, which matches the required "node disagreement on validity or stability" impact category.

### Likelihood Explanation
Any unprivileged AA trigger sender who can cause an AA to execute arbitrary formula code (all AAs are triggerable by anyone posting a payment/trigger unit) can attempt to drive formula-controlled strings (via `concat`, JSON-decoded trigger data, `chr`-like sequences) into `response[...]` or message-payload fields. This requires only crafting an oscript-based AA (or triggering an existing one) whose logic funnels attacker-supplied substrings into these fields — a low-privilege, externally reachable path, similar in spirit to the "unprivileged unit poster / AA trigger sender" reach specified in scope.

### Recommendation
Apply the same `.isWellFormed()`/`isObjectWellFormed()` re-validation uniformly to every string produced by formula evaluation before it is placed into any AA-composed message (response vars, `data`, `attestation`, `text`, dynamically generated message objects), not just `state_var_assignment`, mirroring the centralized enforcement used for externally submitted units in `validation.js`. Ideally, run `isObjectWellFormed()` once over the fully composed response `objUnit` in `aa_composer.js` immediately before it is passed to `writer`/`validation.validate`, so the invariant cannot be bypassed by any current or future code path that builds message content from formula results.

### Proof of Concept
I could not fully trace, within the available tool budget, the exact call path aa_composer.js uses to finalize and hash a composed response unit (whether it re-invokes the full `validate()` — which would recheck well-formedness — before calling `writer.saveJoint`). This is the key open question that determines whether the gap is actually exploitable end-to-end or merely a defense-in-depth omission caught by a later check. **This should be verified by a Devin session with full repository access** by tracing `aa_composer.js`'s `handleTrigger`/response-composition flow to confirm whether `isObjectWellFormed` (or an equivalent check) is invoked on the fully composed response unit before it is persisted, and by writing a targeted oscript AA that uses `concat`/substring tricks to inject a lone surrogate into a `response[...]`, `data`, or `attestation.profile` field to confirm whether such a unit is accepted and hashed/stored without rejection.

// https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/isWellFormed
// Added in Node.js v20 / V8 v11.2. For older runtimes, a fast charCodeAt loop is used
// (avoids regex engine overhead and exits at the first lone surrogate found).
if (!String.prototype.isWellFormed) {
	Object.defineProperty(String.prototype, 'isWellFormed', {
		value: function isWellFormed() {
			for (let i = 0; i < this.length; i++) {
				const code = this.charCodeAt(i);
				if (code >= 0xD800 && code <= 0xDBFF) {          // high surrogate
					const next = this.charCodeAt(i + 1); // NaN if out of bounds
					if (next >= 0xDC00 && next <= 0xDFFF)
						i++;                                       // valid pair — skip low surrogate
					else
						return false;                              // lone high surrogate
				}
				else if (code >= 0xDC00 && code <= 0xDFFF)   // lone low surrogate
					return false;
			}
			return true;
		},
		writable: true,
		configurable: true,
		enumerable: false,
	});
}

function isObjectWellFormed(obj) {
	if (typeof obj !== 'object' || obj === null)
		return typeof obj === 'string' ? obj.isWellFormed() && obj.indexOf('\0') === -1 : true;

	if (Array.isArray(obj)) {
		// for-loop is faster than .every
		for (let i = 0; i < obj.length; i++) {
			if (!isObjectWellFormed(obj[i])) return false;
		}
		return true;
	}

	for (const key in obj) {
		if (Object.hasOwn(obj, key)) {
			if (!key.isWellFormed() || key.indexOf('\0') >= 0) return false;
			if (!isObjectWellFormed(obj[key])) return false;
		}
	}

	return true;
}
