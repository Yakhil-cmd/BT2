### Title
Pool creator-fee collection ignores the `Withdraw` outflow gate, letting funds leave the vault while admin has paused withdrawals - (File: `programs/cp-swap/src/instructions/collect_creator_fee.rs`, `programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs`)

### Summary
`PoolState::status` implements an outflow gate via `PoolStatusBitIndex::Withdraw`, which `withdraw()` explicitly checks before returning any tokens to LPs. However, `collect_creator_fee()` and the fully permissionless `collect_creator_fee_permissionless()` transfer accumulated `creator_fees_token_0`/`creator_fees_token_1` out of the pool's vaults without ever checking `pool_state.get_status_by_bit(PoolStatusBitIndex::Withdraw)`. This mirrors the `rolloverEth()` bug pattern: a designated "outflow" gate is enforced in the primary withdrawal path but silently skipped in a secondary path that also moves real vault funds to an external account.

### Finding Description
`update_pool_status()` lets the admin flip a bitmask (`Deposit`/`Withdraw`/`Swap`) that is meant to be the single authoritative switch controlling whether funds can move into/out of a pool [1](#0-0) . `withdraw()` honors this gate before returning LP-owned tokens [2](#0-1) , and `deposit()`/`swap_base_input()`/`swap_base_output()` similarly check their respective bits [3](#0-2) [4](#0-3) .

`creator_fees_token_0`/`creator_fees_token_1` are real balances physically held inside `token_0_vault`/`token_1_vault` — they are explicitly subtracted out of the vault's "spendable" total in `vault_amount_without_fee()` [5](#0-4) , confirming they represent funds sitting in — and leaving from — the same vaults that `withdraw()` protects.

Despite this, `collect_creator_fee()` transfers these balances straight out of the vaults with zero pool-status check [6](#0-5) , and `collect_creator_fee_permissionless()` — callable by *any* signer, not even the creator — does the exact same unconditional transfer [7](#0-6) . Neither function loads `PoolStatusBitIndex::Withdraw` (or any status bit) at all, unlike `deposit`/`withdraw`/`swap_*`.

The `status` field only exposes three bits (`Deposit`, `Withdraw`, `Swap`) [8](#0-7) ; there is no dedicated bit to gate creator-fee collection, so an admin who disables `Withdraw` — presumably intending to halt *all* outflows from the pool (e.g. during an incident, migration, or detected accounting anomaly) — cannot actually stop creator-fee extraction.

### Impact Explanation
When the admin disables the `Withdraw` bit expecting to freeze all outbound token movement from the pool's vaults, an unprivileged actor can still call `collect_creator_fee_permissionless` (no signer authorization beyond paying for ATA creation) to drain the accrued `creator_fees_token_0`/`creator_fees_token_1` out of the vaults to the recorded `pool_creator`. This breaks the intended security guarantee of the outflow gate and can be used to move real vault funds out of the pool during a period the admin explicitly intended to be outflow-frozen, undermining the incident-response mechanism the status bit exists to provide.

### Likelihood Explanation
Reachable in a single transaction with attacker-chosen accounts: any signer can invoke `collect_creator_fee_permissionless` for any pool that has nonzero accrued creator fees, with no dependency on privileged accounts. The only precondition is that `creator_fees_token_0` or `creator_fees_token_1` is nonzero, which is a normal, common state for any actively-traded pool with `enable_creator_fee = true`. This makes the bypass trivially and repeatedly triggerable whenever the admin pauses withdrawals.

### Recommendation
Add the same `PoolStatusBitIndex::Withdraw` check (or introduce a dedicated status bit for fee outflows) at the start of `collect_creator_fee()` and `collect_creator_fee_permissionless()`, mirroring the check already present in `withdraw()`:
```rust
let pool_state = ctx.accounts.pool_state.load()?;
if !pool_state.get_status_by_bit(PoolStatusBitIndex::Withdraw) {
    return err!(ErrorCode::NotApproved);
}
```
so that disabling the outflow gate reliably halts every path that moves tokens out of the pool vaults, not just LP withdrawals.

### Proof of Concept
1. Admin calls `update_pool_status` to disable the `Withdraw` bit (e.g., `status = 2`), intending to freeze all outbound transfers from the pool [1](#0-0) .
2. Users continue swapping (unaffected, since `Swap` bit is separate), causing `creator_fees_token_0`/`creator_fees_token_1` to accrue in the vault.
3. Any account (not even the pool creator) submits `collect_creator_fee_permissionless` with the pool's `pool_state`, `token_0_vault`, `token_1_vault`, and `creator` (`pool_creator`) accounts.
4. `transfer_from_pool_vault_to_user` executes twice, moving `creator_fees_token_0`/`creator_fees_token_1` out of the vaults to the creator's ATA [9](#0-8) , succeeding despite `Withdraw` being disabled — demonstrating the outflow gate bypass.

```rust
pub fn update_pool_status(ctx: Context<UpdatePoolStatus>, status: u8) -> Result<()> {
    require_gte!(255, status);
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    pool_state.set_status(status);
    pool_state.recent_epoch = Clock::get()?.epoch;
    Ok(())
}
```

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```
