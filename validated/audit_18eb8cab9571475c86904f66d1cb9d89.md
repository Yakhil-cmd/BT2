### Title
Newly created worktree is published via symlink without a content/sanity check, potentially publishing empty or partial data - (File: main.go)

### Summary
The external report concerns `Community.sol` publishing a project without validating that it has at least one task with a non-zero cost, i.e., an unprivileged "publish" action succeeds without a required content/sanity check. The reachable analog in this repo is `git-sync`'s `SyncRepo` publish path, where a *newly created* worktree (`changed == true` branch) is checked out and its symlink flipped via `publishSymlink` without ever calling the existing `sanityCheckWorktree` validation on it.

### Finding Description
`git-sync` defines `sanityCheckWorktree` specifically to guard against publishing corrupt or empty state — it verifies the worktree directory isn't empty, that `HEAD` matches the expected hash, and runs `git fsck` [1](#0-0) . However, this check is only invoked in the "hash unchanged" branch of `SyncRepo`, to re-validate an *existing* worktree before deciding whether to reuse it [2](#0-1) .

In the "hash changed" branch — the actual new-content publish path — `createWorktree` is called, followed by `configureWorktree` (which resets `--hard` and updates submodules), and then directly `publishSymlink(newWorktree)` with **no call to `sanityCheckWorktree` on the new worktree** before the symlink flip [3](#0-2) . `publishSymlink` itself performs no content validation — it purely does path/rename bookkeeping [4](#0-3) .

This means if `createWorktree`'s `git worktree add --no-checkout` succeeds but the subsequent `reset --hard` in `configureWorktree` is interrupted, races with `--stale-worktree-timeout` cleanup, or a `--sparse-checkout-file`/`submodule update` step leaves the directory sparse/empty (e.g., an upstream commit that legitimately has an empty tree, or a filter/sparse config that excludes everything), the symlink can be atomically flipped to point at content that is empty or inconsistent with what the "contract" promises consumers [5](#0-4) .

### Impact Explanation
Consumers rely on the `--link` symlink as an atomic, always-valid contract [6](#0-5) . Publishing an empty/partial worktree without the existing sanity check being applied is analogous to publishing a project with a zero budget in the original finding: a "successful" publish event that should have been rejected proceeds, downstream `--exechook`/`--webhook` consumers fire on this state [7](#0-6) , and applications may consume wrong/partial content, which matches the required impact class ("publishing wrong or partial content").

### Likelihood Explanation
This requires no privileged access — it is reachable purely from the state of the upstream repo/ref that `--repo`/`--ref` point to (attacker-controlled content or a legitimately problematic commit/sparse config), combined with normal operational conditions (interrupted process, filesystem race, or an upstream commit with an effectively empty tree for the configured sparse-checkout/filter). It is not a mocked-only or malicious-operator scenario; it's a gap in defense-in-depth that exists in the standard sync loop for every "hash changed" sync, which is the common case.

### Recommendation
Call `git.sanityCheckWorktree(ctx, newWorktree)` immediately after `configureWorktree` and before `syncHooks.beforePublish`/`publishSymlink` in the `changed` branch of `SyncRepo`, and abort/retry the sync (without publishing) if the check fails, mirroring the existing safeguard already used for the "unchanged" path [2](#0-1) .

### Proof of Concept
Not independently executed (index/tool access does not allow running the binary or e2e harness); reasoning is based on static code-path analysis of `SyncRepo`, `createWorktree`, `configureWorktree`, `publishSymlink`, and `sanityCheckWorktree` as cited above. Conceptually: point `--repo`/`--ref` at a commit whose tree is empty for the active `--sparse-checkout-file`/`--filter` configuration (or induce a `reset --hard`/`submodule update` failure mid-`configureWorktree` that doesn't return an error but leaves the worktree incomplete); `SyncRepo` will still proceed to `publishSymlink` since no post-checkout sanity check gates that path.

// sanityCheckWorktree tries to make sure that the dir is a valid git
// repository.  Note that this does not guarantee that the worktree has all the
// files checked out - git could have died halfway through and the repo will
// still pass this check.
func (git *repoSync) sanityCheckWorktree(ctx context.Context, worktree worktree) bool {
	git.log.V(3).Info("sanity-checking worktree", "repo", git.root, "worktree", worktree)

	// If it is empty, we are done.
	if empty, err := dirIsEmpty(worktree.Path()); err != nil {
		git.log.Error(err, "can't list worktree directory", "path", worktree.Path())
		return false
	} else if empty {
		git.log.V(0).Info("worktree is empty", "path", worktree.Path())
		return false
	}

// publishSymlink atomically sets link to point at the specified target.  If the
// link existed, this returns the previous target.
func (git *repoSync) publishSymlink(worktree worktree) error {
	targetPath := worktree.Path()
	linkDir, linkFile := git.link.Split()

	// Make sure the link directory exists.
	if err := os.MkdirAll(linkDir.String(), defaultDirMode); err != nil {
		return fmt.Errorf("error making symlink dir: %w", err)
	}

	// linkDir is absolute, so we need to change it to a relative path.  This is
	// so it can be volume-mounted at another path and the symlink still works.
	targetRelative, err := filepath.Rel(linkDir.String(), targetPath.String())
	if err != nil {
		return fmt.Errorf("error converting to relative path: %w", err)
	}

	const tmplink = "tmp-link"
	git.log.V(2).Info("creating tmp symlink", "dir", linkDir, "link", tmplink, "target", targetRelative)
	if err := os.Symlink(targetRelative, filepath.Join(linkDir.String(), tmplink)); err != nil {
		return fmt.Errorf("error creating symlink: %w", err)
	}

	git.log.V(2).Info("renaming symlink", "root", linkDir, "oldName", tmplink, "newName", linkFile)
	if err := os.Rename(filepath.Join(linkDir.String(), tmplink), git.link.String()); err != nil {
		return fmt.Errorf("error replacing symlink: %w", err)
	}

	return nil
}
