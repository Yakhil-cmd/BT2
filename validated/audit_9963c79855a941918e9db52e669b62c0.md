### Title
`initialize_with_permission` accepts an unauthenticated, non-signing `creator` account whose pubkey is later trusted as the authoritative fee-recipient identity - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`InitializeWithPermission` declares `creator` as a bare `UncheckedAccount<'info>` with no `Signer` requirement and no constraint tying it to `payer` or to the admin-issued `permission` PDA's `authority` field [1](#0-0) . The instruction later writes `ctx.accounts.creator.key()` straight into `pool_state.pool_creator` via `pool_state.initialize(...)` [2](#0-1) . This is exactly the ZeptoClaw pattern: a caller-supplied identity field (`creator`, analogous to `sender`/`chat_id`) is accepted without proof of authenticity/consent and then becomes the authoritative identity used by all downstream authorization checks.

### Finding Description
Contrast this with the permissionless `Initialize` accounts struct, where `creator` is required to be a `Signer<'info>` [3](#0-2)  — enforcing that whoever becomes the pool's fee-recipient identity has actually authorized it by signing the transaction.

`InitializeWithPermission` drops that requirement. The only gate is that `payer` must hold an admin-issued `Permission` PDA seeded on `payer.key()` [4](#0-3) , created out-of-band via the admin-only `create_permission_pda` instruction [5](#0-4) . That PDA authenticates `payer`, not `creator`. Nothing in `InitializeWithPermission` requires `creator.key()` to equal `payer.key()`, `permission.authority`, or any signer in the transaction — `creator` is fully attacker/caller-chosen data, just like the untrusted `sender`/`chat_id` fields in the webhook payload.

This unauthenticated `pool_creator` value is subsequently trusted as the sole authorization anchor in two downstream instructions:
- `CollectCreatorFee` gates fee withdrawal purely by `#[account(mut, address = pool_state.load()?.pool_creator)] pub creator: Signer<'info>` [6](#0-5) .
- `CollectCreatorFeePermissionless` routes accumulated fees to an ATA whose authority is `creator`, again constrained only by `address = pool_state.load()?.pool_creator` [7](#0-6) .

Because `pool_creator` was set from unverified caller data at pool-creation time (no signature, no equality check to any authenticated party), the permission-holding `payer` can silently assign the entire future creator-fee revenue stream of the pool to any pubkey of their choosing — including addresses they alone control — regardless of who the pool is actually created "for," and with zero cryptographic proof that the named `creator` consented to or is even aware of this designation.

### Impact Explanation
Creator fees are a real, continuously-accruing share of swap fees (`pool_state.creator_fees_token_0/1`, drained via `transfer_from_pool_vault_to_user` in both collection paths). Because `pool_creator` identity is established from unauthenticated data instead of a verified signer (unlike the sibling `Initialize` path), the fee-ledger's notion of "who owns the creator-fee stream" for any pool created through `initialize_with_permission` can be set arbitrarily by the transaction's `payer`, diverting fee revenue away from the intended/expected creator without their consent. This is a fee-ledger accounting/authorization integrity defect stemming directly from trusting a caller-supplied, non-signed identity field for a later authorization decision — the same root cause as the ZeptoClaw advisory.

### Likelihood Explanation
Exploitation requires only a single `initialize_with_permission` call with an attacker-chosen `creator` account (no signature required for that account) from a `payer` that already holds a valid `Permission` PDA. No other privileged action, off-chain component, or race condition is needed; the missing constraint is unconditionally reachable on every pool created via this instruction.

### Recommendation
Require `creator` to be a `Signer<'info>` in `InitializeWithPermission` (matching `Initialize`), or add an explicit constraint binding `creator.key()` to an already-authenticated identity (e.g., `constraint = creator.key() == payer.key()` or `== permission.authority`) so that `pool_state.pool_creator` can never be set from unverified, non-signing caller data.

### Proof of Concept
1. Attacker (or any actor) obtains/holds a `Permission` PDA as `payer` (admin-granted, one-time).
2. Attacker calls `initialize_with_permission` supplying:
   - `payer` = their own signing keypair (holds the `Permission` PDA)
   - `creator` = any arbitrary pubkey they choose (not required to sign, e.g. their own second wallet, or even a victim's public key without consent)
3. `pool_state.initialize(...)` records `ctx.accounts.creator.key()` as `pool_state.pool_creator` with no verification that this account authorized the assignment [2](#0-1) .
4. As swaps occur on the pool, creator fees accumulate under `pool_state.creator_fees_token_0/1`.
5. Whoever controls the arbitrarily-named `creator` pubkey can later call `collect_creator_fee` (signing as `creator`) or anyone can trigger `collect_creator_fee_permissionless` to route the accumulated fees to that unverified identity [8](#0-7) , confirming that the unauthenticated identity set at pool-creation time is fully honored downstream.

```rust
#[derive(Accounts)]
pub struct CreatePermissionPda<'info> {
    #[account(
        mut,
        constraint = (owner.key() == crate::admin::ID || owner.key() == crate::create_permission_pda_owner::ID) @ ErrorCode::InvalidOwner
    )]
    pub owner: Signer<'info>,

    /// CHECK: permission account authority
    pub permission_authority: UncheckedAccount<'info>,

    /// Initialize config state account to store protocol owner address and fee rates.
    #[account(
        init,
        seeds = [
            PERMISSION_SEED.as_bytes(),
            permission_authority.key().as_ref()
        ],
        bump,
        payer = owner,
        space = Permission::LEN
    )]
    pub permission: Account<'info, Permission>,

    pub system_program: Program<'info, System>,
}

pub fn create_permission_pda(ctx: Context<CreatePermissionPda>) -> Result<()> {
    let permission = ctx.accounts.permission.deref_mut();
    permission.authority = ctx.accounts.permission_authority.key();
    Ok(())
}
```

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
