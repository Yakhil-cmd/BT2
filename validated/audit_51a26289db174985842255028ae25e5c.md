### Title
Webhook Signature Verified Against One GitHub Organization While the Handled Payload Writes to a Different Organization's Repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / `webhook_secret` to validate the inbound webhook against by reading an **unauthenticated** field of the JSON body (`repository.owner.login` or `organization.login`), and only then checks the HMAC signature against that org's secret. The event handlers that subsequently mutate application state (e.g. `PushHandler`, `StatusHandler`) resolve the target `Repository`/`Commit` from a **different, independently-controlled field of the same unauthenticated body** (`repository.full_name`, or a bare `sha` lookup with no repository scoping at all). Nothing binds "the organization whose secret was used to accept the payload" to "the repository/stack the payload is allowed to write to."

### Finding Description
`verify_signature` in `app/controllers/shipit/webhooks_controller.rb` does: [1](#0-0) [1](#0-0) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
```
with `repository_owner` derived purely from the request body: [2](#0-1) 

The signature check itself, in `Shipit::GithubApp#verify_webhook_signature`, unconditionally passes when the selected organization has no `webhook_secret` configured: [3](#0-2) 

Shipit explicitly supports multi-organization deployments where each org has its own (optional) `webhook_secret` in `config/secrets.yml`, and the shipped example templates default `webhook_secret` to `nil`: [4](#0-3) [5](#0-4) 

Once `create` proceeds, the actual mutation is dispatched to handlers that resolve the target repository from a completely different payload field than the one used for org/secret selection: [6](#0-5) 

For `status` events, resolution is even weaker — there is no repository scoping at all, only a global `sha` lookup across every `Commit` in the Shipit instance: [7](#0-6) 

**Root cause / broken equality:** the engine implicitly assumes
`organization used to select webhook_secret (repository_owner)` == `organization/repository actually written to by the handler (repository.full_name / sha lookup)`
but both values come from the same untrusted JSON body and are read independently, so an attacker fully controls whether they match.

### Impact Explanation
In a multi-org Shipit deployment where at least one configured organization has `webhook_secret` unset (shown as the documented default in `config/secrets.development.shopify.yml` and the double-app fixture), an unauthenticated network attacker can:
1. Send a POST to `/webhooks` with `X-Github-Event: push` (or `status`), `repository.owner.login` (or `organization.login`) set to the secret-less org — causing `verify_signature` to short-circuit to `verified = true` regardless of the `X-Hub-Signature` header.
2. Set `repository.full_name` in the same body to point at a *different*, real, secret-protected repository/stack tracked by Shipit.
3. `PushHandler` will then call `stack.sync_github(expected_head_sha: ...)` against that unrelated stack, or `StatusHandler` will forge a commit status (`state`, `target_url`, `description`, `context`) on any commit in the system by `sha` alone, with no relation to the org that "authenticated" the request.

This is a cross-repository write triggered by a forged/unauthenticated webhook that would let an attacker forge CI status or trigger `sync_github` state changes on stacks belonging to organizations they have no relationship with — an authentication-bypass-driven unauthorized write on repositories the attacker does not control, consistent with the engine's own Critical impact bar ("cross-repository writes" / "an unauthorized deploy").

### Likelihood Explanation
This requires only that one organization among several configured in the deployment leaves `webhook_secret` blank — the exact configuration shown as the default/example in this repository's own shipped config templates — and requires no session, `ApiClient` token, or GitHub credentials. Any attacker who can reach the public `/webhooks` endpoint (which must be internet-reachable to receive real GitHub webhooks) can exploit it with a single crafted HTTP request; no privileged access is needed.

### Recommendation
Bind the two fields together instead of trusting them independently:
- Derive the repository/stack the handler is allowed to act on strictly from the same organization whose secret verified the request (reject/ignore events where `repository.full_name`'s owner does not match the verified `repository_owner`).
- Require `webhook_secret` to be present for every configured organization (fail closed instead of `return true unless webhook_secret`), or at minimum warn loudly and refuse silent unconditional pass-through in `GithubApp#verify_webhook_signature`.
- In `StatusHandler`, scope the `Commit.where(sha: ...)` lookup to commits belonging to the verified organization's repositories rather than matching by `sha` globally.

### Proof of Concept
1. Configure Shipit with two organizations in `config/secrets.yml`: `OrgA` (no `webhook_secret`) and `OrgB` (real repo tracked by Shipit, with `webhook_secret` set).
2. POST to `/webhooks` with header `X-Github-Event: push`, arbitrary/absent `X-Hub-Signature`, and body:
```json
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/tracked-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "OrgA")`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured) — request passes with HTTP 200.
4. `PushHandler` resolves `Repository.from_github_repo_name("OrgB/tracked-repo")` and calls `sync_github(expected_head_sha: "<attacker-chosen sha>")` on `OrgB`'s stacks, despite the request never being authenticated for `OrgB`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
