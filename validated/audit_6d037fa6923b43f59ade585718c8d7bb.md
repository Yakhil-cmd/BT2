### Title
CCMenu API token scope bypass allows reading arbitrary stacks' deploy status - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
The reported bug is a condition mismatch that breaks the intended binding between "money that should reach the pool" and "money the code actually routes there." The same class of bug — a security-relevant binding silently broken by a controller that skips the check the rest of the system relies on — exists in Shipit's CCMenu API. `Api::BaseController` binds every `ApiClient` token to the single stack it was scoped for (`ApiClient#stack_id`), and every other API controller enforces that binding through `#stacks`/`#stack`. `Api::CCMenuController` overrides `#stack` and completely skips that scoping, so a token that is supposed to authorize reading exactly one stack can be used to read any stack.

### Finding Description
`Api::BaseController` establishes the trust binding "the stack a token authorizes == the stack it can touch": [1](#0-0) 

`Api::StacksController`, `DeploysController`, etc. all resolve `stack`/`stacks` through this scoped helper, so a token created with `stack_id` set can only ever touch that one stack.

`Api::CCMenuController`, however, overrides `#stack` to bypass this scoping entirely and load whatever `stack_id` is supplied in the request, ignoring `current_api_client.stack_id`: [2](#0-1) 

`require_permission :read, :stack` (line 6) only checks the string permission `"read:stack"` via `ApiClient#check_permissions!`: [3](#0-2) 

It never checks whether the requested `stack_id` matches the token's own `stack_id`. That check is only performed by `BaseController#stacks`, which `CCMenuController#stack` deliberately does not use.

Making things worse, the token minted for this exact endpoint is not even scoped to a stack in the first place. `CCMenuUrlController#client` creates (or reuses) an `ApiClient` with only the `read:stack` permission and no `stack:` association, keyed solely by `creator` + a fixed name: [4](#0-3) 

So the equality that should hold — `token.authorized_stack == stack_being_touched` — is broken on both sides: the token is unscoped (`stack_id == nil`, so `BaseController#stacks` would return `Stack.all` even if it were consulted), and the one controller that serves this token additionally ignores scoping altogether.

### Impact Explanation
A `ccmenu_url` token is explicitly designed to be embedded in a plain, unauthenticated query string and handed to third-party CI/CD dashboard tools (CCMenu clients), i.e. it is meant to be a narrowly-scoped, low-trust credential for one stack's build status. Because of the missing binding, anyone who obtains one such URL/token (which is routinely embedded in dashboards, browser history, logs, or shared links) can swap the `stack_id` query parameter and use the same token to read the deploy/build status of **every** stack managed by that Shipit instance — an unauthenticated read of stack state that the token was never meant to grant. This matches the "High" impact category: unauthenticated read of stack state via a scope authorized for a different resource.

### Likelihood Explanation
No credentials beyond a single, low-privilege, intentionally-shareable CCMenu token are required. Any user who can request one CCMenu URL for one stack (any authenticated Shipit user, or anyone who is handed the link/token) can trivially exploit this by changing a URL parameter; no signature, secret, or GitHub access is needed.

### Recommendation
Make `Api::CCMenuController#stack` honor the same scoping as the rest of the API by resolving the stack through `stacks.from_param!(params[:stack_id])` (or explicitly checking `current_api_client.stack_id == stack.id`) instead of `Stack.from_param!(params[:stack_id])`. Additionally, `CCMenuUrlController#client` should set `stack: stack` when creating/finding the `ApiClient`, and `find_or_create_by!` should be scoped per-stack (not just per-creator+fixed-name), so each CCMenu token is bound to exactly the stack it was requested for.

### Proof of Concept
1. As any Shipit user, visit `GET /*stack_id/ccmenu_url` for Stack A (`stack_id: "owner/repoA/production"`). Note the response `ccmenu_url`, which embeds `token=<T>`.
2. Reuse the returned `T` and call `GET /api/stacks/owner-repoB-staging.xml?token=<T>` (substituting any other stack's `to_param`).
3. Observe that `Api::CCMenuController#show` renders Stack B's deploy status even though the token was only ever requested/authorized for Stack A, because `#stack` loads `Stack.from_param!(params[:stack_id])` without checking `current_api_client.stack_id`.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
