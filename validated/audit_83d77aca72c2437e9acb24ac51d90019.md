## Analog Found: Uncaught Synchronous `throw` in Definition-Template Authentifier Evaluation Crashes the Node Process

### Title
Crafted unit definition triggers an uncaught exception in `Definition.validateAuthentifiers`, crashing the validating node - (File: `definition.js`)

### Summary
CVE-2020-20813 describes OpenVPN's control channel crashing on a malformed reset packet — a single crafted network message causes a process-wide denial of service. `ocore` has an analogous class of bug: a single, attacker-crafted unit definition can drive the authentifier-evaluation code path into a `throw Error(...)` that is executed inside an asynchronous `conn.query` callback with no enclosing `try/catch`. Because ocore's top-level `process.on('uncaughtException', ...)` handler deliberately re-throws to crash the process (`throw err; // crash the process to avoid ending up in an inconsistent state`), this uncaught exception brings down the entire validating node — a network-wide unavailability, not merely a rejected unit.

### Finding Description
`Definition.validateAuthentifiers()` performs two passes over a definition:
1. `validateDefinition(...)` — a structural pass that validates every op, including `'definition template'`, and returns errors gracefully via callback: [1](#0-0) 
which explicitly guards against the template not being found or being duplicated:
```
if (rows.length !== 1)
    return cb("template not found or too many");
```

2. `evaluate(...)` — the real authentifier/signature evaluation pass, used to actually verify signatures for `sig`, `hash`, `address`, `definition template`, etc. Its `'definition template'` handler does **not** have the same safety check and instead throws synchronously inside the DB callback: [2](#0-1) 
```
case 'definition template':
    ...
    conn.query(
        "SELECT payload FROM messages JOIN units USING(unit) \n\
        WHERE unit=? AND app='definition_template' AND main_chain_index<=? AND +sequence='good' AND is_stable=1",
        [unit, objValidationState.last_ball_mci],
        function(rows){
            if (rows.length !== 1)
                throw Error("not 1 template");
            ...
        }
    );
    break;
```

This `evaluate()` function is invoked by `validateAuthentifiers` right after `validateDefinition` succeeds: [3](#0-2) 

`validateAuthentifiers` is called directly from `validateAuthor()` during normal unit validation for every posted unit that carries an explicit `definition` or references an existing address definition: [4](#0-3) 

None of these call sites wrap the call in a `try/catch` that can intercept an exception thrown from inside an asynchronous DB callback — a synchronous `throw` inside a `conn.query` callback cannot be caught by a `try/catch` around the original (already-returned) synchronous call. The exception therefore propagates to the event loop and reaches the global handler: [5](#0-4) 
which logs the error and then re-throws, terminating the Node.js process.

The same unguarded `'definition template'` throw is also reachable from the `evaluateAssetCondition()` path (asset spending conditions) and from `signed_message.js`'s call into `Definition.validateAuthentifiers` for signed messages, both of which are also externally reachable (asset issuance/spend conditions from any unit; signed messages from any paired device/counterparty). [6](#0-5) [7](#0-6) 

### Impact Explanation
An unprivileged unit poster who can get an address definition containing a `'definition template'` operator into the authentifier-evaluation path (e.g., by defining/using an address whose spending condition references a `definition_template` unit, timed or crafted so that the template row set differs between the structural check and the authentifier-evaluation check) causes a synchronous, uncaught `throw` inside `conn.query`'s callback. Because ocore's `uncaughtException` handler is configured to re-throw and crash the process, a single malicious unit can crash any full node (hub, witness, or explorer) that attempts to validate it — halting confirmation of new units on that node until manually restarted. This matches the "network unable to confirm new units" / node-disagreement class of impact called for in the validation rules, and is the direct structural analog of the OpenVPN control-channel crash from a single malformed packet.

### Likelihood Explanation
The vulnerable code path (`evaluate()`'s `'definition template'` case) executes on every unit whose address definition or asset condition uses the `definition template` operator once it passes structural validation, and is one of only a handful of the officially supported operators — no special privileges are required, only knowledge of the definition-template feature. The trigger condition is a mismatch between the row count seen during the structural `validateDefinition` pass and the row count seen during the later `evaluate` pass for the same `(unit, last_ball_mci)` lookup — plausible whenever a `definition_template` unit's stability/sequence state can change between look-ups, or whenever `evaluate()` is exercised without a preceding, fully-covering `validateDefinition()` pass (e.g., via `evaluateAssetCondition` / `signed_message.js`, which have narrower or differently-scoped structural checks).

### Recommendation
Change the `'definition template'` handler inside `Definition.validateAuthentifiers`'s `evaluate()` (definition.js, `case 'definition template'`) to call `cb2(false)` or propagate a normal validation error through `fatal_error`/`cb2` instead of `throw Error("not 1 template")`, mirroring the graceful handling already implemented in `validateDefinition`'s corresponding case. More generally, audit all `throw Error(...)` statements reachable from asynchronous `conn.query` callbacks inside unit/AA/signed-message validation code paths and convert them to callback-based errors, since none of them can be intercepted by surrounding `try/catch` and all of them will crash the process via the global `uncaughtException` handler.

### Proof of Concept
1. Create (and get stabilized) a `definition_template` unit `T`.
2. Construct address `A` whose definition uses `['definition template', [T, {...}]]` such that `validateDefinition`'s structural check (definition.js:321-339) sees exactly one matching, stable `definition_template` row for `T` at validation time (e.g., because it is evaluated slightly earlier, or via a different query context such as `evaluateAssetCondition`/`signed_message.js` that does not perform the same structural pre-check).
3. Post a unit authored by `A` (or a signed message using `A`'s definition) so that `Definition.validateAuthentifiers`'s `evaluate()` (definition.js:802-819) re-queries the same `definition_template` row and finds `rows.length !== 1` (0 or >1) — e.g., by having a second author in the same unit also declare an app `definition_template` message for the same unit `T`, or by racing the stabilization of `T` between the two checks.
4. `evaluate()`'s callback executes `throw Error("not 1 template")` inside `conn.query`'s callback, which is not caught anywhere, propagates to `process.on('uncaughtException')` in `network.js`, and crashes the full node process.
