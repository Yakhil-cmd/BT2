### Title
Webhook org used for signature verification is decoupled from the repository the handler mutates, allowing unsigned forged `pull_request`/`unlabeled` events to archive/unarchive an arbitrary stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/org config using `repository.owner.login` from the raw JSON body, but `UnlabeledHandler` (like all `pull_request` handlers) resolves the repository/stack to mutate from a completely separate field, `repository.full_name`. If the org named by `repository.owner.login` has no `webhook_secret` configured, `GitHubApp#verify_webhook_signature` trivially returns `true`, so the request is accepted without any real signature check while still being routed to whatever repo/stack `repository.full_name` names.

### Finding Description
The broken binding is the implicit equality the code assumes but never enforces:
`org_used_for_signature_verification (params.repository.owner.login) == org_owning_the_mutated_stack (derived from params.repository.full_name)`.

Path:
1. `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository','owner','login')` [1](#0-0) , and uses it to fetch the org-specific `GitHubApp` instance and verify the signature against that org's secret [2](#0-1) .
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` when the resolved org has no configured `webhook_secret`: `return true unless webhook_secret` [3](#0-2) .
3. Once past `verify_signature`, `WebhooksController#create` dispatches to `Shipit::Webhooks.for_event(event)` handlers using the raw, unauthenticated params [4](#0-3) .
4. `UnlabeledHandler#repository` resolves the actual target repository from `params.repository.full_name`, independent of `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .
5. `handle` then calls `stack.archive!` or `stack.unarchive!` on the review stack derived from that repository [6](#0-5) .

Exploit: an attacker crafts a `pull_request` webhook body with `action: "unlabeled"`, sets `repository.owner.login` to any org configured in Shipit without a `webhook_secret` (verification always passes for that org, no valid signature needed), but sets `repository.full_name` to `"victim-org/victim-repo"` where `victim-org` is a fully-secured org with review stacks enabled. Because the two fields are never checked for consistency, the forged, unsigned request is accepted and then mutates the victim repository's review stack via `archive!`/`unarchive!`.

Existing guards do not catch this: `drop_unhandled_event` only checks the event type is handled [7](#0-6) ; `verify_signature` never cross-checks `repository.full_name`'s owner against `repository_owner` [8](#0-7) ; the `ExplicitParameters` schema in `UnlabeledHandler` only validates types/presence, not owner consistency [9](#0-8) .

### Impact Explanation
An unprivileged attacker can trigger `stack.archive!` or `stack.unarchive!` on any review stack belonging to any repository configured in the Shipit instance, as long as at least one other unrelated org in the same Shipit deployment has no `webhook_secret` set. This is a payload for one repository (the no-secret org) mutating another org's stack — matching the Critical "payload for one repository mutating another's stack" category. The attack is fully repeatable against arbitrary stacks/repos in the same Shipit deployment, and requires no credentials at all.

### Likelihood Explanation
Preconditions: at least one org configured in `Shipit.github_apps`/config without a `webhook_secret` (a real, not-uncommon multi-tenant misconfiguration, e.g. sandbox/demo orgs), and the target victim org's repository must have `review_stacks_enabled`. Attacker cost is a single unauthenticated HTTP POST to `/webhooks` with a crafted JSON body and `X-Github-Event: pull_request` header — no valid HMAC signature is required for the chosen no-secret org. This is trivially repeatable.

### Recommendation
Enforce that the org used to select/verify the webhook signature is the same org that owns the resolved repository. Concretely: after resolving the target repository/stack in each handler (or centrally before dispatch), assert that `repository.full_name`'s owner matches `params.dig('repository','owner','login')`/`repository_owner` used in `verify_signature`, and reject (422) on mismatch. Additionally, do not allow signature verification to silently pass (`return true unless webhook_secret`) for any org that is not explicitly and intentionally marked as "webhook signature disabled"; require an explicit opt-in flag instead of "secret absent = unauthenticated open door" in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
minitest under `test/controllers/webhooks_controller_test.rb` (existing file, extend with):
```ruby
test "unlabeled event with mismatched owner/full_name and no-secret org bypasses signature verification and mutates victim stack" do
  # Setup: org "no-secret-org" configured with no webhook_secret
  # Setup: org "victim-org" configured with webhook_secret = "realsecret"
  # Setup: victim_repository = repositories(:shipit) owned by "victim-org", review_stacks_enabled = true
  # Setup: victim review stack currently NOT archived

  payload = {
    action: "unlabeled",
    number: 1,
    pull_request: {
      id: 1, number: 1, url: "url", title: "t", state: "open",
      additions: 1, deletions: 1,
      head: { sha: "sha", ref: "ref" },
      user: { login: "attacker" },
      assignees: [],
      labels: [] # no provisioning label -> triggers archive! per provisioning_behavior config
    },
    repository: {
      full_name: "victim-org/victim-repo",       # points at victim stack
      owner: { login: "no-secret-org" }           # used only for signature org selection
    },
    sender: { login: "attacker" }
  }.to_json

  # No X-Hub-Signature header needed/valid, since no-secret-org has no webhook_secret
  post shipit.webhooks_path, params: payload,
       headers: { 'X-Github-Event' => 'pull_request', 'Content-Type' => 'application/json' }

  assert_response :ok
  # Equality check BEFORE: victim_stack.archived? == false
  # Equality check AFTER: victim_stack.reload.archived? == true, despite
  #   no valid signature ever computed against victim-org's webhook_secret.
  assert victim_stack.reload.archived?
end
```
This demonstrates the archive/unarchive of a repository's stack that never authenticated the request with its own secret, confirming the authentication-bypass / cross-tenant mutation.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
