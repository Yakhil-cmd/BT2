### Title
Missing global outpoint registry allows a single Bitcoin L1 lockup output to be replayed across multiple `register-for-bond` calls, double-crediting sats stake - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`pox-5.clar`'s `register-for-bond` accepts a Bitcoin L1 lockup proof (`btc-lockup` argument, `ok` branch) and calls `verify-l1-lockups` → `validate-l1-lockup` to credit `sats-total` toward a staker's bond allowance and stake weight. The duplicate-output protection (`seen-outpoints`) is only tracked *within a single call's fold* over the `outputs` list, not persisted in contract storage across transactions. [1](#0-0) [2](#0-1) 

### Finding Description
`validate-l1-lockup` verifies that a given BTC output (identified by `txid`/`output-index`) pays into the correct P2WSH script for the staker/bond and is confirmed by a valid block header/merkle proof, then adds it to a running `seen-outpoints` accumulator to reject duplicates *within the same call*: [3](#0-2) 

However, this `seen-outpoints` list is a local fold parameter created fresh on each call to `verify-l1-lockups`/`register-for-bond`: [4](#0-3) 

There is no persistent map (e.g. `l1-lockup-used-outpoints` keyed by `{txid, output-index}`) checked/inserted in contract storage, unlike the `used-signer-key-authorizations` pattern used elsewhere in the boot contracts to prevent authorization replay (`pox-4.clar`, lines 747, 785-787). This is structurally identical to the reported bug class: a signed/proved artifact (there, an EIP-712 signature; here, a Bitcoin-inclusion proof for a specific UTXO) is verified for correctness but not bound to "has this exact artifact already been consumed," so it can be replayed.

Consequently, a staker can call `register-for-bond` multiple times (for different `bond-index` values, or after `announce-l1-early-exit`/exit of a prior bond frees up their membership) while presenting the *same* BTC output/lockup transaction each time. Each call independently re-validates the same on-chain BTC output and credits `sats-total` again, since nothing in `register-for-bond` records "this outpoint has already been used to back a bond."

This breaks the equality that pox-5's sat-backed weighting is supposed to enforce: `sum of sats credited across all live bonds for a lockup ≤ sats actually locked in that one Bitcoin output`. It becomes possible to double- (or N-times-) count a single real BTC lock as backing multiple simultaneous stakes/allowances, producing stake credit, reward eligibility, and reward-share weight in `pox-5` that is not actually backed 1:1 by locked sats.

### Impact Explanation
This is a double-counting/unbacked-credit bug against the core invariant of `pox-5`'s L1 lockup path: STX-stake authorization and reward weighting for a staker is supposed to be capped by real BTC value locked (`sats-total`, checked against `allowance` at line 744 and used to size `min-ustx-for-sats-amount`). If the same UTXO can be reused across bonds, an attacker can obtain oversized stake weight/signing weight and reward-cycle rewards ("sBTC rewards paid that were not earned" / "sats credited by an L1 proof that were never locked on Bitcoin" for the second and further uses) without locking additional BTC. This matches the Critical/High bucket: double-counting a commitment, and reward/signing weight exceeding the value actually locked.

### Likelihood Explanation
Reachable by any allow-listed unprivileged staker simply by calling `register-for-bond` more than once with the same lockup proof for different `bond-index` values (or after their earlier bond ends/rolls over), which is a standard user-level transaction — no admin, signer, or other-party key required. The check that exists (`ERR_DUPLICATE_LOCKUP_OUTPOINT`) only defends against duplicate entries in a single call's `outputs` list, giving false confidence that replay is handled, while cross-call/cross-bond reuse is unguarded.

### Recommendation
Persist consumed L1 lockup outpoints in a durable Clarity map, e.g. `(define-map used-l1-lockup-outpoints { txid: (buff 32), output-index: uint } bool)`, and in `validate-l1-lockup` (or `verify-l1-lockups`) both check that the outpoint is not already present in that map and insert it there (via `map-insert`, failing the transaction with a dedicated error such as `ERR_LOCKUP_OUTPOINT_ALREADY_USED` if already present), analogous to how `pox-4.clar`'s `consume-signer-key-authorization` uses `used-signer-key-authorizations` to prevent signature/authorization replay. This binds each BTC lockup output to at most one bond registration for its entire lifetime, not just within a single transaction's output list.

### Proof of Concept
1. Staker locks `X` sats on Bitcoin into the P2WSH address produced by `construct-lockup-output-script(staker, unlock_burn_height, staker_unlock_bytes, early_unlock_bytes)`, confirmed on-chain (one real UTXO, `txid:vout`).
2. Staker is allow-listed for `bond-index = 0` and `bond-index = 1` (two separate protocol bonds, or the same bond re-entered after a roll-over window).
3. Staker calls `register-for-bond(bond-index=0, ..., btc-lockup=ok({outputs: [<proof of txid:vout>], staker-unlock-bytes}), ...)`. `verify-l1-lockups`/`validate-l1-lockup` verifies the merkle/header proof and credits `sats-total = X` toward bond 0's allowance and stake weight — passes, since `seen-outpoints` is empty at call start. [5](#0-4) 
4. Staker calls `register-for-bond(bond-index=1, ..., btc-lockup=ok({outputs: [<same proof of txid:vout>], staker-unlock-bytes}), ...)` for the second bond (or after the first bond's membership permits a new registration). This is a fresh top-level call, so `seen-outpoints` is again initialized empty; the same outpoint is re-verified and `sats-total = X` is credited a second time. [6](#0-5) 
5. Net effect: `X` sats of real BTC collateral now back `2 * X` sats worth of stake/reward-weight credit across bond 0 and bond 1, with no mechanism in the contract preventing this because the only duplicate check (`ERR_DUPLICATE_LOCKUP_OUTPOINT`) is scoped to the single fold call in step 3 (or 4), not persisted across transactions.

Note: I was not able to fully trace whether external node-side validation (Rust) enforces any additional global outpoint bookkeeping outside the Clarity contract, since that would require deeper inspection of the L1-lockup handling code path outside `pox-5.clar`; this uncertainty should be checked before treating the finding as fully confirmed.

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
