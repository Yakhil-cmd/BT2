## Valid Analog Found

### Title
Pool creator fees become permanently unrecoverable if `pool_creator`'s USDC associated token account is frozen/blacklisted - ([File: programs/cp-swap/src/instructions/collect_creator_fee.rs] / [File: programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs])

### Summary
`PoolState.pool_creator` is a fixed address recorded once at pool `initialize` time and never updatable afterward. [1](#0-0)  Every code path that pays out accumulated creator fees (`collect_creator_fee` and `collect_creator_fee_permissionless`) hard-constrains the destination token account to be the associated token account owned by that exact `pool_creator` address, with no alternative destination or reassignment mechanism. [2](#0-1)  This mirrors the reported bug class: a permanently fixed "user" address whose only fund-exit path is gated to that same address, so if the token issuer (e.g., USDC) freezes that specific associated token account, the accumulated fees become permanently stuck.

### Finding Description
`pool_creator` is written into `PoolState` during `initialize`/`initialize_with_permission` and there is no instruction anywhere in the program that lets it be changed. [3](#0-2)  In `CollectCreatorFee`, the `creator` account must equal `pool_state.pool_creator` (`address = pool_state.load()?.pool_creator`), and the `creator_token_0`/`creator_token_1` destination accounts are forced via `associated_token::authority = creator` to be exactly that creator's ATA for the vault mint. [4](#0-3) [2](#0-1) 

The permissionless variant does not fix this: it also derives the fee destination strictly as `associated_token::authority = creator` where `creator` is constrained to `pool_state.pool_creator`, and merely allows any `payer` to fund the (once) creation of that same ATA — it does not allow redirecting funds to a different, non-frozen account. [5](#0-4) [6](#0-5) 

Since pools can be created for any SPL/Token-2022 mint pair (including USDC) as `token_0_mint`/`token_1_mint`, and swap fees continually accrue into `creator_fees_token_0`/`creator_fees_token_1` on every swap via `update_fees`, USDC amounts owed to the creator accumulate in the pool's token vault over time regardless of whether the creator can currently receive them. [7](#0-6)  If Circle blacklists/freezes the creator's USDC associated token account (the standard USDC blacklist mechanism freezes a specific token account), both `collect_creator_fee` and `collect_creator_fee_permissionless` will always attempt to transfer into that exact frozen ATA and will fail on every call, indefinitely, because the destination account is not user-selectable and `pool_creator` cannot be updated.

### Impact Explanation
This causes a permanent freezing of pool creator fee funds (`creator_fees_token_0`/`creator_fees_token_1`) that have already been carved out of the vault's spendable balance via `vault_amount_without_fee`. [8](#0-7)  These funds are unrecoverable through any code path in-scope (no owner/admin override, no ability to change `pool_creator`, no alternate destination account parameter), matching the "permanent freezing of user funds" acceptance criterion.

### Likelihood Explanation
Reaching this state requires no privileged action beyond USDC's normal blacklist/freeze operation on the specific creator's ATA — a real-world event outside program control but foreseeable when USDC is used as a pool token. Any unprivileged user can create a pool with USDC as `token_0_mint`/`token_1_mint` via `initialize`/`initialize_with_permission`, and normal swap activity from any unprivileged swapper accrues creator fees automatically.

### Recommendation
Allow the current `pool_creator` (or a designated authority) to reassign the creator-fee-receiving address, or allow `collect_creator_fee`/`collect_creator_fee_permissionless` to accept a caller-specified, mint-matching destination token account instead of hard-deriving the ATA from the immutable `pool_creator` field, so a blacklisted creator can still route accrued fees to a different account they control.

### Proof of Concept
1. An unprivileged user calls `initialize` (or `initialize_with_permission`) creating a pool where `token_0_mint` = USDC, becoming `pool_creator`. [9](#0-8) 
2. Normal swaps occur, accruing `creator_fees_token_0` in USDC via `update_fees` on each `swap_base_input`/`swap_base_output` call. [10](#0-9) 
3. Circle freezes the pool creator's USDC associated token account (their standard blacklist ATA for that mint).
4. Any call to `collect_creator_fee` or `collect_creator_fee_permissionless` derives/uses that same frozen ATA as `creator_token_0` (`associated_token::authority = creator`) and the underlying token transfer CPI fails permanently, since `pool_creator` cannot be changed and no alternate destination exists. [11](#0-10) 
5. `creator_fees_token_0` remains stuck in the vault indefinitely, unreachable by any instruction in the program.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
