### Title
Arbiter/ArbStore re-registration permanently strands funds locked in already-created arbiter-contract shared addresses - ([File: arbiter_contract.js])

### Summary
The `SecondSwap` bug is a generic instance of a broader class: a contract bakes in a pointer to a mutable, externally-managed "manager" entity at deposit/listing time, and once that manager's registration changes, previously locked funds that depend on interacting with the manager become permanently unreachable, because the definition/oscript condition governing the funds cannot be satisfied any other way. In `ocore--015`, the closest reachable analog is the arbiter-contract flow in `arbiter_contract.js`, where the "arbstore" address for an arbiter is resolved via the hub at contract-creation time and is baked into the on-chain multisig ("shared address") definition, while dispute/appeal/settlement code paths re-resolve the arbstore's registration from the hub at a later time.

### Finding Description
When two parties fund an arbiter contract, `deriveSharedAddress()` builds the payment-locking oscript definition for the shared address that will hold the deposit. It calls `arbiters.getArbstoreInfo(contract.arbiter_address, ...)` to fetch the arbstore's payout address and fee-cut, then hardcodes that address into the `"has"` output condition of the shared-address definition (the arbstore's cut branch): [1](#0-0) 

This `arbstoreInfo` is obtained from a mutable, hub-mediated registration (`hub/get_arbstore_url` → `arbiter_locations` table), not from anything anchored immutably to the arbiter's ocore address: [2](#0-1) [3](#0-2) 

Once the shared address is derived and funded, the funds are locked into an oscript condition that is fixed forever (only the union of the `"or"` branches can ever unlock them: mutual cooperation of both parties, or the arbiter's `data_feed` decision routed through the specific arbstore-cut output amount/address baked in at creation). Subsequent lifecycle operations — `openDispute()`, `appeal()`, `getAppealFee()`, and `complete()` — all depend on re-resolving the arbiter's currently-registered arbstore via `hub/get_arbstore_url` / `hub/get_arbstore_url_by_address`: [4](#0-3) [5](#0-4) 

If the arbiter's hub registration in `arbiter_locations` is later changed or removed (the arbstore re-registers under a different `arbstore_address`, migrates hubs, or is deregistered), `hub/get_arbstore_url` returns "arbiter is not known" and every one of these functions fails outright: [6](#0-5) 

This mirrors the reported issue precisely: the "manager" pointer (arbstore registration) used to gate access to already-locked funds can be changed independently of the already-created lock (the shared address definition and its baked-in "has output to `arbstoreInfo.address`" condition), and the recovery/administrative paths (dispute open, appeal, cut-computation in `complete()`) are gated by the very same broken pointer, just as `unlistVesting`/`spotPurchase` in the SecondSwap report were gated by the changed `marketplace` pointer.

### Impact Explanation
If the arbiter's arbstore registration changes or disappears after a contract has been funded (`status` = `paid` or `in_dispute`), any counterparty who is not cooperating cannot obtain a unilateral resolution: `openDispute()` fails to reach the (now-unregistered) arbstore, and the only remaining unlock path — mutual "and" cooperation of both offeror and acceptor — is exactly the path that a hostile counterparty (the reason a dispute is needed in the first place) will refuse to sign. The deposited funds (private-payment or public-asset amounts, potentially large) are then permanently frozen inside the shared address with no way for the honest party to recover them, which is a concrete freezing-of-funds impact analogous to the SecondSwap report's "loss of previous listing."

### Likelihood Explanation
This requires the arbiter (or the arbstore operating on their behalf) to change/remove its hub registration (`arbiter_locations`) while contracts funded under the old registration are still outstanding — a routine operational event (arbstore migration, re-registration under a new payout address, hub change) rather than an attack, making it moderately likely to occur in practice for any long-lived contract, and it affects any user (unprivileged private-payment counterparty) who has funded an arbiter contract.

### Recommendation
- Anchor arbstore identity/payout information to something immutable per-contract (e.g., record and pin the exact `arbstore_address`/cut used at deposit time as an authoritative, contract-scoped value that all later flows — dispute, appeal, completion — must use, never re-resolving from the mutable hub registration for existing contracts).
- Provide a unilateral fallback unlock branch in the shared-address definition (e.g., a timeout-based "either party can withdraw after N days if arbiter/arbstore is unreachable") so fund recovery does not depend solely on mutual cooperation or a specific, mutable external registration.
- Add a monitoring/validation step so that `openDispute`, `appeal`, and `complete` fail with a clear, actionable error identifying the unreachable arbstore and, ideally, fall back to previously cached/pinned arbstore info rather than only the live hub lookup.

### Proof of Concept
1. Alice and Bob create and fund an arbiter contract via `createSharedAddressAndPostUnit()`; `deriveSharedAddress()` bakes `arbstoreInfo.address` (fetched via `arbiters.getArbstoreInfo`) into the shared address definition's arbstore-cut branch. [7](#0-6) 
2. Bob pays into the shared address (`pay()`), moving contract status to `paid`. [8](#0-7) 
3. The arbstore operator re-registers under a different `arbstore_address` (or is deregistered) in the hub's `arbiter_locations` table.
4. Alice disputes non-delivery and calls `openDispute()`; `device.requestFromHub("hub/get_arbstore_url", objContract.arbiter_address, ...)` now fails because the hub's `arbiter_locations` lookup returns "arbiter is not known" or a stale/incorrect URL. [6](#0-5) [9](#0-8) 
5. Bob refuses to cooperate on the mutual "and" branch of the shared-address definition (the only alternative unlock path), leaving the deposited funds permanently stuck in the shared address with no functioning dispute, appeal, or completion path.

function pay(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, function(objContract) {
		if (!objContract.shared_address || objContract.status !== "signed" || !objContract.me_is_payer)
			return cb("contract can't be paid");
		var opts = {
			asset: objContract.asset,
			to_address: objContract.shared_address,
			amount: objContract.amount,
			spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own'
		};
		if (arrSigningDeviceAddresses.length)
			opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
		walletInstance.sendMultiPayment(opts, function(err, unit){								
			if (err)
				return cb(err);
			setField(objContract.hash, "status", "paid", function(objContract){
				cb(null, objContract, unit);
			});
			// listen for peer announce to withdraw funds
			storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
				if (assetInfo && assetInfo.is_private)
					db.query("INSERT "+db.getIgnore()+" INTO my_watched_addresses (address) VALUES (?)", [objContract.peer_address]);
			});
		});
	});
}

function getArbstoreInfo(arbiter_address, cb) {
	if (!cb)
		return new Promise(function(resolve, reject){
			getArbstoreInfo(arbiter_address, function(err, info){
				if (err) return reject(err);
				resolve(info);
			});
		});
	if (arbStoreInfos[arbiter_address]) return cb(null, arbStoreInfos[arbiter_address]);
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err) {
			return cb(err);
		}
		if (!validationUtils.isNonemptyString(url))
			return cb("invalid url received from hub");
		requestInfoFromArbStore(url+'/api/get_info', function(err, info){
			if (err)
				return cb(err);
			if (!validationUtils.isNonemptyObject(info))
				return cb("invalid info received from arbstore");
			const cut = parseFloat(info.cut);
			if (!info.address || !validationUtils.isValidAddress(info.address) || isNaN(cut) || cut < 0 || cut >= 1) {
				return cb("malformed info received from ArbStore");
			}
			info.url = url;
			arbStoreInfos[arbiter_address] = info;
			cb(null, info);
		});
	});
}
