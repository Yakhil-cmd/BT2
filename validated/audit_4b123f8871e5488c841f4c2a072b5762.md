## Analog Found [1](#0-0) 

### Title
Wallet accepts and registers an attacker-crafted "shared address" without verifying the local user actually authorized or co-created it - (File: wallet_defined_by_addresses.js)

### Summary
A paired correspondent device can push a `new_shared_address` message that references one of the victim's own (public) payment addresses inside an arbitrary, attacker-authored address definition (e.g., an `or` condition where the attacker's key alone is sufficient). `handleNewSharedAddress` accepts and persists this definition into `shared_addresses`/`shared_address_signing_paths` purely because the victim's address happens to appear somewhere in the definition — with no check that the victim ever requested, approved, or co-signed the creation of this "shared" address. This mirrors the Nextcloud Notes bug class: a resource received/pre-existing from an untrusted party is silently adopted as if it were legitimately the user's own, without validating provenance or consent.

### Finding Description
`handleNewSharedAddress` (invoked from `wallet.js` on the `"new_shared_address"` message subject) performs only structural checks:
- that `body.definition` hashes to `body.address` [2](#0-1) 
- that each `signers` entry's address matches the definition path [3](#0-2) 
- that the definition itself is a syntactically valid oscript definition via `validateAddressDefinition` [4](#0-3) 

It never verifies that the local user was the one who initiated the shared-address flow (e.g., via `createNewSharedAddressByTemplate` / `pending_shared_addresses`), nor that the local user consented to being included as a cosigner. `determineIfIncludesMeAndRewriteDeviceAddress` merely checks whether any address inside the sent definition matches one of the victim's own `my_addresses`, and if so treats the victim as a legitimate member: [5](#0-4) 

Because the definition is attacker-supplied, nothing prevents an `or`-style definition (`["or", [["address","ATTACKER_ADDR"], ["address","VICTIM_ADDR"]]]`) where the attacker's key alone is sufficient to spend, while the victim's own address is merely referenced as a decoy to pass the "am I a member" check. The subject `"new_shared_address"` is not restricted to only-just-paired flows — it is dispatched to any known correspondent device, and `device.js` only requires the sender to already be a known correspondent (or whitelists a few subjects for unknown ones); it performs no authorization check tying the `new_shared_address` message to a specific consented shared-address-creation session: [6](#0-5) 

Once accepted, `addNewSharedAddress` stores the address and emits `new_address` events that the wallet UI/UX surfaces to the user as one of "their" (shared) addresses: [7](#0-6) 

### Impact Explanation
A victim's wallet silently registers a bogus "shared address" that appears to include the victim as a cosigner, but is actually fully controlled by the attacker (via an `or` branch). If the victim (or anything automated, e.g. a payment/notification flow that lists "my shared addresses") is induced to send funds to this address believing it requires joint control, the attacker can unilaterally withdraw the full balance — concrete unauthorized loss of funds. This is analogous to the Nextcloud Notes bug, where a resource created/planted by an attacker before proper user validation/consent is trusted and adopted as the user's own.

### Likelihood Explanation
Requires the attacker to already be a paired correspondent device of the victim (a state reachable through normal pairing flows, e.g. QR/pairing-code sharing for contracts, marketplaces, or bots) — squarely within the "paired device" reachable-attacker class. No privileged network position or hub compromise is needed; a single crafted `new_shared_address` justsaying message suffices.

### Recommendation
`handleNewSharedAddress` should only accept a `new_shared_address` message when it corresponds to a shared-address creation the local device actually initiated or approved (i.e., cross-check against a `pending_shared_addresses`/`pending_shared_address_signing_paths` record that the local user approved), rather than inferring membership solely by scanning for the victim's address inside an arbitrary attacker-supplied definition. Additionally, the UI should clearly indicate/verify the actual signing structure (which branches require the local user's key) before treating an address as "shared" with the user.

### Proof of Concept
1. Attacker pairs with victim's device (or is already an existing correspondent).
2. Attacker learns one of the victim's payment addresses `VICTIM_ADDR` (addresses are not secret; visible in payment requests, chat, etc.).
3. Attacker sends a `new_shared_address` device message: `{address: hash(["or",[["address","ATTACKER_ADDR"],["address","VICTIM_ADDR"]]]), definition: ["or",[["address","ATTACKER_ADDR"],["address","VICTIM_ADDR"]]], signers: {"r.0": {address:"ATTACKER_ADDR"}, "r.1": {address:"VICTIM_ADDR"}}}`.
4. `handleNewSharedAddress` validates structural consistency, `determineIfIncludesMeAndRewriteDeviceAddress` finds `VICTIM_ADDR` in `my_addresses` and accepts membership, `validateAddressDefinition` accepts the syntactically valid `or` definition.
5. `addNewSharedAddress` stores the address in `shared_addresses`, exposing it to the victim's wallet as a "shared address" they are part of.
6. Any funds sent to this address can be withdrawn unilaterally by the attacker via the `ATTACKER_ADDR` branch, regardless of victim's cooperation.

// Checks if any of my payment addresses is mentioned.
// It is possible that my device address is not mentioned in the definition if I'm a member of multisig address, one of my cosigners is mentioned instead
function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
