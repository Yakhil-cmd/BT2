### Title
Unauthenticated `sender` field in `TransferStxOp`/`PreStxOp` linkage allows theft of any Stacks address's unlocked STX - ([File: stackslib/src/chainstate/burn/operations/transfer_stx.rs])

### Summary
`TransferStxOp::parse_from_tx` takes `sender` as an externally-supplied parameter that is populated from the linked `PreStxOp.output` field, which is itself parsed purely from output[0] of a Bitcoin transaction with no cryptographic proof that the transaction's author controls the private key behind that Stacks address. `TransferStxOp::check` only rejects a zero amount or `sender == recipient`, so a spoofed sender passes validation and `process_transfer_ops` moves real STX out of the victim's account.

### Finding Description
The broken equality: *"STX transferred by the applied op == STX owned by the Stacks address that cryptographically authorised the op."* Here the transferred STX belongs to an address that never signed anything.

`PreStxOp::parse_from_tx` derives `output` solely from the address encoded in output[0] of the Bitcoin transaction: [1](#0-0) 
Nothing here checks that the hash160/address in output[0] corresponds to a key that signed any input of the transaction — in Bitcoin, anyone can construct an output paying to an arbitrary address they do not control.

That `PreStxOp.output` value later becomes the `sender` field passed into `TransferStxOp::parse_from_tx`, which trusts it unconditionally: [2](#0-1) 
The only linkage enforced between the `PreStxOp` and the follow-up `TransferStxOp` is that the latter's input must spend output[1] (the "funding" output) of the former: [3](#0-2) 
There is no requirement that whoever spends output[1] (attacker-controlled) also controls the address encoded in output[0] (which can be set to the victim's Stacks address hash160/version).

`TransferStxOp::check` performs no sender-authorization check at all — only that the amount is non-zero and sender != recipient: [4](#0-3) 

Exploit flow: attacker crafts a `PreStxOp` Bitcoin transaction whose output[0] address decodes to the victim's Stacks address (costing only the dust amount sent to that address, which attacker does not need to control the key for) and output[1] paid to an address the attacker controls. Attacker then submits a `TransferStxOp` transaction spending output[1] of the `PreStxOp`, with its own output[0] set to the attacker's Stacks address. The parsed op has `sender = victim`, `recipient = attacker`, `transfered_ustx > 0`. `check()` passes since `sender != recipient` and amount is non-zero. Downstream, `process_transfer_ops` invokes `tx.run_stx_transfer(&sender, &recipient, transfered_ustx, ...)`, debiting the victim's real unlocked STX balance and crediting the attacker — with zero Stacks-signed authorization from the victim.

No existing guard (`check()`, the `get_sender_txid` vout==1 linkage, or the PoX-sunset height check) validates that the address encoded in `PreStxOp.output` is actually controlled by the entity that funds/spends the corresponding UTXO chain.

### Impact Explanation
Any unprivileged attacker who can broadcast two ordinary Bitcoin transactions can drain the entire unlocked STX balance of any known Stacks address to an address of their choosing, with no signature or consent from the victim. This is repeatable against any address and any amount up to the victim's balance, and is a direct theft of STX belonging to a party that never authorized the transaction — matching the Critical severity bar for theft of funds not authorized by their true owner.

### Likelihood Explanation
Preconditions are minimal: the attacker needs a small amount of BTC to pay transaction fees and dust for the `PreStxOp` outputs, knowledge of the victim's Stacks address (public information), and the target address must hold a positive unlocked STX balance. No special chain state, cycle phase, or membership status is required, and the attack requires only the two chained Bitcoin transactions already used for legitimate `StackStxOp`/`TransferStxOp` flows.

### Recommendation
Bind the `sender`/`PreStxOp.output` address cryptographically to the entity actually authorizing the operation: e.g., require that the address in `PreStxOp.output[0]` matches the address recoverable from the public key(s) that signed input 0 of the `PreStxOp` transaction (as Stacks addresses are derived from Bitcoin-compatible public keys), and reject the op otherwise. Alternatively, require that `TransferStxOp`/`StackStxOp` funding inputs also be signed by the same key that would authorize spending from `sender`.

### Proof of Concept
1. Boot a test chainstate and fund a victim Stacks address (`Sv`) with STX via a normal Stacks transaction.
2. Construct a `PreStxOp` Bitcoin transaction with output[0] address decoding to `Sv` and output[1] paid to an attacker-controlled key (`Ka`), without using `Sv`'s private key anywhere.
3. Construct a `TransferStxOp` Bitcoin transaction whose sole input spends output[1] of the `PreStxOp` (signed by `Ka`), with its own output[0] set to the attacker's Stacks address `Sa`, and payload amount `X <= Sv`'s balance.
4. Feed both burnchain transactions through `PreStxOp::parse_from_tx` / `TransferStxOp::parse_from_tx`, apply them in a burn block, and process the corresponding Stacks block via `process_transfer_ops`.
5. Assert: `Sv`'s post-op STX balance decreased by `X` and `Sa`'s balance increased by `X`, with the assertion that no Stacks transaction signed by `Sv`'s key ever appeared in the mempool or chain — demonstrating the equality "STX moved == STX whose owner authorized the move" is broken.

*Note: I was unable to fully trace, within the available iterations, the exact call site in `stackslib/src/burnchains/burnchain.rs` that resolves the `sender` parameter passed into `TransferStxOp::parse_from_tx` from the corresponding `PreStxOp`; this conclusion is based on the directly-analogous, fully-traced `StackStxOp`/`PreStxOp` pairing in `stack_stx.rs`, which shares the identical `PreStxOp.output` → `sender` data flow and linkage-by-vout mechanism.*

    pub fn parse_from_tx(
        block_height: u64,
        block_hash: &BurnchainHeaderHash,
        tx: &BurnchainTransaction,
        sender: &StacksAddress,
    ) -> Result<TransferStxOp, op_error> {
        // can't be too careful...
        let num_outputs = tx.num_recipients();

        if tx.num_signers() == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                num_outputs,
            );
            return Err(op_error::InvalidInput);
        }

        if num_outputs == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                num_outputs,
            );
            return Err(op_error::InvalidInput);
        }

        if tx.opcode() != Opcodes::TransferStx as u8 {
            warn!("Invalid tx: invalid opcode {}", tx.opcode());
            return Err(op_error::InvalidInput);
        };

        let data = TransferStxOp::parse_data(&tx.data()).ok_or_else(|| {
            warn!("Invalid tx data");
            op_error::ParseError
        })?;

        let outputs = tx.get_recipients();
        assert!(!outputs.is_empty());

        let output = outputs
            .get(0)
            .ok_or_else(|| {
                warn!("Invalid tx: No first output");
                op_error::InvalidInput
            })?
            .as_ref()
            .ok_or_else(|| {
                warn!("Invalid tx: could not decode the first output");
                op_error::InvalidInput
            })?
            .address
            .clone()
            .try_into_stacks_address()
            .ok_or_else(|| {
                warn!("Invalid tx: output must be representable as a StacksAddress");
                op_error::InvalidInput
            })?;

        Ok(TransferStxOp {
            sender: sender.clone(),
            recipient: output,
            transfered_ustx: data.transfered_ustx,
            memo: data.memo,
            txid: tx.txid(),
            vtxindex: tx.vtxindex(),
            block_height,
            burn_header_hash: block_hash.clone(),
        })
    }

    pub fn check(&self) -> Result<(), op_error> {
        if self.transfered_ustx == 0 {
            warn!("Invalid TransferStxOp, must have positive ustx");
            return Err(op_error::TransferStxMustBePositive);
        }
        if self.sender == self.recipient {
            warn!("Invalid TransferStxOp, sender is recipient");
            return Err(op_error::TransferStxSelfSend);
        }
        Ok(())
    }
