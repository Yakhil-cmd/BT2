### Title
Webhook signature verified against attacker's own org while the payload's `repository.full_name` targets a different org's stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and therefore the `webhook_secret` used for HMAC verification) from the payload's `repository.owner.login` field, but every event `Handler` (e.g. `PushHandler`, `StatusHandler`) resolves the `Repository`/`Stack` to act on from the independent `repository.full_name` field. Because these are two separate, attacker-controlled fields inside the same JSON body, a party that legitimately administers a GitHub App/webhook for one organization configured on the Shipit instance can sign a payload with their own org's secret while pointing `full_name` at a different org's repository, causing Shipit to act on a stack it was never authorized to touch for that signature.

### Finding Description
`verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`), fetches that org's `GitHubApp` via `Shipit.github(organization: repository_owner)`, and calls `verify_webhook_signature(signature, raw_post)`, which HMACs the *entire raw body* with that org's `webhook_secret`: [1](#0-0) [2](#0-1) 

Shipit supports hosting multiple GitHub organizations in a single instance, each with its own `app_id`/`webhook_secret`: [3](#0-2) 

Once the signature passes, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` runs the handler with the raw, attacker-supplied `params` — the same hash that was just used for owner lookup: [4](#0-3) 

But `Handler#repository_name`, used by all handlers (via `#stacks`) to find the target `Repository`, reads `full_name`, not `owner.login`: [5](#0-4) 

`PushHandler#process` then triggers `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack of that repository/branch: [6](#0-5) 

Nothing in the request pipeline enforces `repository.owner.login == repository.full_name.split('/').first`. An attacker who legitimately controls the GitHub App/webhook secret for organization `A` (e.g. they are the admin of their own org's GitHub App configured on this shared Shipit instance) can send:
```json
{"repository": {"owner": {"login": "A"}, "full_name": "B/target-repo"}, "ref": "refs/heads/master", "after": "<attacker-chosen-sha>"}
```
signed with `A`'s `webhook_secret`. `verify_signature` resolves and validates against `A`, succeeds, and the `PushHandler` then looks up `Repository.from_github_repo_name("b/target-repo")` — an org (`B`) the attacker never authenticated for — and calls `sync_github` on its stacks with an attacker-chosen `expected_head_sha`.

This is the same class of bug as the HMX report: a value used to satisfy the trust/verification check (`repository.owner.login`, bound to the signing secret) is a *different* field from the one that determines which resource is actually acted upon (`repository.full_name`), and the code never asserts equality between them.

### Impact Explanation
`sync_github` drives which commit becomes the stack's `HEAD`/deployable commit; for stacks with continuous deployment/continuous delivery enabled, this can trigger an unauthorized deploy of an attacker-influenced SHA on a different organization's repository than the one whose credentials were used to authenticate the webhook — a cross-tenant write that breaks the org-to-repository trust boundary. Other handlers (`StatusHandler`, `CheckSuiteHandler`, `MembershipHandler`) are similarly reachable cross-org because they too resolve their target purely from attacker-controlled payload fields once the org-scoped signature check passes for a different org than the one being mutated.

### Likelihood Explanation
Requires the attacker to legitimately possess a valid `webhook_secret` for at least one organization configured in the same multi-tenant Shipit deployment (i.e., they are an authorized webhook sender for org `A`, which is plausible for organization admins in a shared/hosted Shipit instance serving multiple orgs) and knowledge of another org/repo `B` also hosted on the instance. This is realistic in shared/hosted Shipit deployments where different teams/orgs each configure their own GitHub App but share one Shipit host.

### Recommendation
In `WebhooksController#verify_signature`, after verifying the signature, assert that the same `repository_owner`/`organization` value used to select the `webhook_secret` also matches the owner implied by `repository.full_name` (and by `organization.login` when both are present) before dispatching to handlers. Reject the request (422) on mismatch, similar to the existing `GithubOrganizationUnknown` handling.

### Proof of Concept
1. Configure Shipit with two orgs, `orga` and `orgb`, each with distinct `webhook_secret`s (per `config/secrets.development.shopify.yml` format).
2. As an entity that controls `orga`'s GitHub App webhook secret, POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": {"owner": {"login": "orga"}, "full_name": "orgb/target-repo"},
  "ref": "refs/heads/master",
  "after": "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"
}
```
3. Compute `X-Hub-Signature: sha1=<hmac_sha1(orga_webhook_secret, raw_body)>` per `Hook::DeliverySigner`/`GitHubApp#verify_webhook_signature`.
4. `verify_signature` resolves `Shipit.github(organization: "orga")` and successfully verifies the signature.
5. `PushHandler.call(params)` resolves `Repository.from_github_repo_name("orgb/target-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` on org `B`'s stacks, despite the request never being authenticated for org `B`.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
