### Title
Unbounded index accrual can permanently freeze an over-sized market - (File: common/src/rates/simulate.rs)

### Summary
High: a sufficiently large, highly utilized market can make `borrowed * borrow_index` or `supplied * supply_index` exceed the `i128` accounting domain during `accrue_step`, causing every subsequent market operation to revert because accrual runs before mutations.

### Finding Description
Each accrual first converts the stored scaled debt and supply back to RAY asset values through `scaled_to_original`, which computes `scaled.mul(index)` and panics on `MathOverflow` when the result cannot fit `i128`. [1](#0-0) [2](#0-1) 

The borrow index is allowed to grow as high as `MAX_BORROW_INDEX_RAY`, but the multiplication needed to determine utilization happens before that cap can protect the accumulated market value. [3](#0-2) [4](#0-3) 

Consequently, a market whose scaled balances and index product approach the RAY-value ceiling can enter a state where computing utilization always panics before the index is updated or capped. [5](#0-4) 

Every pool mutation uses `global_sync`, which invokes `accrue_step`; therefore the same overflow blocks `supply`, `borrow`, `withdraw`, `repay`, liquidation-driven withdrawals, flash-loan accounting, revenue claims, and parameter updates that first synchronize the market. [6](#0-5) [7](#0-6) 

The repository already contains a regression demonstrating this exact failure: a billion-unit, 18-decimal market at 98% utilization reaches `MathOverflow`, after which both withdrawal and repayment fail with the same error. [8](#0-7) 

### Impact Explanation
Once the market crosses this arithmetic boundary, suppliers cannot withdraw, borrowers cannot repay or be liquidated, and any unclaimed protocol revenue in that market cannot be synchronized or claimed through the normal paths. [9](#0-8) [10](#0-9) 

Because the stale stored values remain unchanged and every later accrual repeats the overflowing multiplication, this is a permanent freezing of market funds rather than an isolated failed transaction. [5](#0-4) [11](#0-10) 

### Likelihood Explanation
An unprivileged account can create the precondition through ordinary `supply`, `borrow`, and later `update_indexes` calls; `update_indexes` only requires caller authorization and forwards the selected assets to the pool. [12](#0-11) [13](#0-12) 

The attack requires an unusually large position and sustained high utilization, so it is capital-intensive and depends on the market cap admitting balances near the protocol’s arithmetic limits. [14](#0-13) [15](#0-14) 

Nevertheless, the vulnerable state can also arise organically in a large market: index growth is cumulative, and admitted caps do not guarantee that future scaled-value accrual remains inside `i128`. [16](#0-15) 

### Recommendation
Before accrual, compare scaled balances and indexes against a conservative market-value ceiling and reject growth, borrowing, or supply that would make the next `scaled * index` calculation unrepresentable. [2](#0-1) 

`accrue_step` should use saturating or checked utilization inputs that preserve a recoverable state, for example clamping the index before recomputing `borrowed_original` and `supplied_original`, while allowing repayments and withdrawals to proceed without requiring a full utilization calculation. [5](#0-4) 

At a minimum, enforce market caps low enough that `scaled_balance * MAX_*_INDEX / RAY` always fits `i128`, and add an emergency non-accruing exit path for debt repayment and collateral settlement. [4](#0-3) 

### Proof of Concept
The existing integration test reproduces the failure:

1. Create an 18-decimal market using the XLM rate curve and a collateral market.
2. Supply `1_000_000_000 * 10^18` units of the borrow asset.
3. Supply enough collateral and borrow 98% of the market.
4. Advance ledger time while repeatedly calling `update_indexes` for the borrow market.
5. The first overflowing accrual returns `MathOverflow` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`.
6. A subsequent 1-unit withdrawal and a repayment both fail with `MathOverflow` because they perform accrual first. [17](#0-16) 

The failing call chain is `Controller.update_indexes` → `pool_update_indexes_call` → `LiquidityPool.update_indexes` → `global_sync` → `accrue_step` → `scaled_to_original`. [12](#0-11) [13](#0-12) [1](#0-0)

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```markdown
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
```
