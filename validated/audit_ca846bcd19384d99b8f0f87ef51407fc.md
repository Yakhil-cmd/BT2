Based on the code inspection, this vulnerability is confirmed and reproducible in the codebase.

### Title
Commit author identity forgery via attacker-controlled `Merge-Requested-By:` commit-message field - (File: app/models/shipit/user.rb)

### Summary
`Shipit::User.find_or_create_author_from_github_commit` blindly trusts a `Merge-Requested-By: <login>` line embedded in *any* synced commit's message, not just genuine merge commits generated by Shipit's own merge queue, and uses it to look up/create a `User` and assign it as `commit.author`. An attacker who can get any commit synced (e.g., by pushing to a branch tracked by a `Stack` or `ReviewStack`) can forge the attributed author to any existing GitHub login.

### Finding Description
The broken binding: `commit.author == identity of the GitHub actor who authored/pushed that commit` is expected, but the code allows `commit.author == User.find_or_create_by_login!(<attacker-chosen string from commit message>)`.

Code path:
- `Commit.from_github` calls `User.find_or_create_author_from_github_commit(commit)` for every synced commit: [1](#0-0) 
- That method matches the raw commit message against `MergeRequest::MERGE_REQUEST_FIELD` (`"Merge-Requested-By"`) with no check that the commit is an actual Shipit-generated merge commit, and if matched, calls `find_or_create_by_login!(match_info[1])`, setting the returned/created `User` as the commit author: [2](#0-1) 
- `find_or_create_by_login!` will create a brand-new global `User` row (fetching from GitHub API) if the login doesn't exist yet, or reuse the existing row for `victim-login`: [3](#0-2) 
- This field format is intentionally emitted by Shipit itself when it merges a PR via the merge queue (`MergeRequest#merge_message`), embedding the actual merge-requester's login into the merge commit it asks GitHub to create: [4](#0-3) . However, `find_or_create_author_from_github_commit` has no way to distinguish "a merge commit that Shipit itself produced via `merge!`" from "any arbitrary commit an attacker pushed containing that exact text". Any commit synced through `Commit.create_from_github!`/`Commit.from_github` — including regular pushes to a `Stack`'s or `ReviewStack`'s tracked branch synced via `GithubSyncJob#append_commit` — is subject to this check: [5](#0-4) .
- `Commit#identify_merge_request` further propagates this forged attribution into `merge_request.merge_requested_by` bookkeeping when the commit's message also matches a PR number pattern: [6](#0-5) .

Attacker request: push a commit to a branch of their own fork whose commit message body contains a line `Merge-Requested-By: victim-login`. If that branch is tracked by any `Stack`/`ReviewStack` in the target Shipit instance (e.g., the attacker's own PR/ReviewStack, which they control by definition), the webhook-driven sync (`GithubSyncJob`) fetches the new commit and calls `create_from_github!`, which resolves `commit.author` to `victim-login`'s `User` record (creating it if necessary) purely from the attacker-supplied string — no GitHub authentication of the pusher is checked at this step.

No existing guard prevents this: `find_or_create_by_login!` only rescues `Octokit::NotFound` (i.e., only if the login doesn't exist on GitHub); it does not verify the pusher's identity, the commit's actual author, or that the commit came from Shipit's own `merge!` call.

### Impact Explanation
The attacker forges the `author`/`merge_requested_by` attribution of a commit they push to their own tracked branch to any existing GitHub login. `Shipit::User` is a global table (not scoped per-repository), so this corrupts deploy provenance/audit trail (`commit.author`, `stacks_contributed_to`, `MergeRequest#merge_requested_by`) engine-wide, potentially implicating an unrelated maintainer or victim in deploys/merges they never performed. This matches "a payload for one repository mutating another's ... commit" / provenance corruption, and is repeatable against any repository the attacker can push a branch to and get synced (their own fork/PR).

### Likelihood Explanation
Preconditions are minimal and entirely within attacker control: they need a branch tracked by a `Stack` or `ReviewStack` (trivially satisfied by opening a PR from their own fork, which is standard unprivileged GitHub behavior), and they simply craft a commit message containing the exact `Merge-Requested-By: <login>` line. No Shipit secrets, session, or team membership needed. This is cheap and fully repeatable on every commit they push.

### Recommendation
Restrict the `Merge-Requested-By` trust boundary: only apply this override when the commit is verified to be a genuine Shipit-generated merge commit (e.g., match by `sha`/`merge_request.head` relationship established by `MergeRequest#merge!`, or store `merge_requested_by` at merge-time on the `MergeRequest`/`Commit` row directly rather than re-parsing attacker-controlled commit message text during sync). At minimum, do not let arbitrary synced commits' free-text messages override the GitHub-authenticated `commit.author`/`commit.committer` identity.

```ruby
# test/models/shipit/user_test.rb (conceptual)
test "find_or_create_author_from_github_commit trusts forged Merge-Requested-By field from attacker commit" do
  victim = shipit_users(:walrus) # or any existing fixture user with a known login
  forged_commit = stub(
    sha: "deadbeef",
    commit: stub(
      message: "Some innocuous commit\n\nMerge-Requested-By: #{victim.login}\n",
      author: stub(id: 999_999, login: "attacker"),
      committer: stub(id: 999_999, login: "attacker"),
    ),
    author: stub(id: 999_999, login: "attacker"),
    committer: stub(id: 999_999, login: "attacker"),
  )

  resolved_author = Shipit::User.find_or_create_author_from_github_commit(forged_commit)

  assert_equal victim.login, resolved_author.login
  refute_equal forged_commit.author.id, resolved_author.github_id
end
```
This demonstrates the equality break: `commit.author.login == "attacker"` (expected, from GitHub commit author) is violated because the code produces `commit.author.login == victim.login` solely from attacker-supplied commit-message text.

```ruby
    def self.find_or_create_author_from_github_commit(github_commit)
      if (match_info = github_commit.commit.message.match(/^#{MergeRequest::MERGE_REQUEST_FIELD}: ([\w\-.]+)$/))
        begin
          return find_or_create_by_login!(match_info[1])
        rescue Octokit::NotFound
          # Corner case where the merge-requested-by user cannot be found (renamed/deleted).
          # In this case we carry on and search for the commit author
        end
      end
      find_or_create_from_github(github_commit.author.presence || github_commit.commit.author.presence)
    end
```
