### Title
Unsigned webhook accepted for any org missing `webhook_secret` allows cross-org forgery of `membership` events into `Shipit.github_teams` - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when that specific GitHub App configuration's `webhook_secret` is blank. Because `Shipit.github(organization: repository_owner)` selects the app config purely from the attacker-supplied `organization.login` (or `repository.owner.login`) field of the webhook payload, an attacker can pick any org configured with a nil `webhook_secret` to make `verify_signature` pass unconditionally, then supply a completely unrelated, pre-existing `team.id` (belonging to any other org) in the `membership` event body to have `MembershipHandler` add themselves to that team.

### Finding Description
The broken binding: the code implicitly assumes `organization.login` in the payload (used to select the signing secret) `==` the organization that actually owns `team.id` (used to authorize a membership change). These are two independent, attacker-controlled/attacker-exploitable values that are never cross-checked.

Path:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner` straight from `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0)  and calls `Shipit.github(organization: repository_owner)` [2](#0-1) .
- `Shipit.github` resolves per-organization config via `github_app_config(organization)`, instantiating an independent `GitHubApp` per org with its own `webhook_secret` [3](#0-2) .
- `GitHubApp#verify_webhook_signature` short-circuits `return true unless webhook_secret` [4](#0-3) , meaning for the org whose config has no secret, ANY signature/body combination "verifies."
- `MembershipHandler#process` and `#find_or_create_team!` locate/create the `Team` purely by `params.team.id` (`Team.find_or_create_by!(github_id: params.team.id)`), never checking that `params.organization.login` matches the team's actual `organization` [5](#0-4) . If the team already exists (e.g., because it's a real, admin-configured team fetched via `bin/rake teams:fetch`, see `Shipit.github_teams`, which builds authorized teams from `github.oauth_teams` config via `Team.find_or_create_by_handle` [6](#0-5) ), the organization field on the payload is simply ignored — only used when creating a brand-new team.
- The handler then calls `team.add_member(member)` for `action: 'added'`, creating a `Membership` record for the attacker-supplied `member.login` [7](#0-6) .

Attacker request: POST `/webhooks` with header `X-Github-Event: membership`, no `X-Hub-Signature` header (or a garbage one), and body:
```json
{"action":"added","team":{"id":<github_id of ANY configured Shipit::Team, e.g. one referenced by Shipit.github_teams>,"name":"x","slug":"x","url":"https://example.com"},"organization":{"login":"<org-with-nil-webhook_secret>"},"member":{"login":"attacker"}}
```
`verify_signature` looks up the GithubApp for `"<org-with-nil-webhook_secret>"`, which has `webhook_secret` nil, so `verify_webhook_signature` returns `true` without inspecting the signature at all. `MembershipHandler` then finds the pre-existing team by `github_id` (belonging to a completely different, properly-secured org) and adds the attacker as a member, regardless of the org named in the payload.

Existing guards that fail to stop this: `drop_unhandled_event` only checks event type is handled, not authenticity; `ExplicitParameters` schema in `MembershipHandler.params` validates shape/types only, not org/team binding; there is no `force_github_authentication`, `User#authorized?`, or `require_permission!` gate on the webhooks controller at all, since webhooks are meant to be authenticated purely by HMAC signature — which is exactly what's bypassed here.

### Impact Explanation
This is an escalation into `Shipit.github_teams` authorization (High per the stated severity taxonomy): `User#authorized?` grants access whenever `teams.where(id: Shipit.github_teams.map(&:id)).exists?` is true [8](#0-7) . By forging a `Membership` for an authorized team, an attacker who names an arbitrary GitHub login gains that login membership in an authorized team, which (combined with GitHub OAuth login using that same GitHub login) can grant them logged-in, authorized access to the Shipit instance — bypassing the team-membership gate entirely without ever possessing the real webhook secret for the org that actually owns the team. The blast radius spans every org configured in the multi-org `secrets.github` map: a single misconfigured (secretless) org anywhere in the deployment undermines the membership-authorization model for teams belonging to all other orgs.

### Likelihood Explanation
Preconditions: the deployment must use the multi-org `secrets.github` schema (keyed by org) with at least one org's `webhook_secret` left blank/nil — a state explicitly documented as valid/optional in `docs/setup.md` ("If it's missing... webhook_secret is optional") and reflected in `template.rb`'s generated secrets template, which leaves `webhook_secret` blank by default. The attacker needs zero credentials: no session, no signature, no knowledge of any secret — just the numeric `github_id` of a target team, which is often discoverable (e.g., via GitHub's public team API for public orgs/teams, or by observing a legitimate past webhook). The attack is a single unauthenticated HTTP POST and fully repeatable.

### Recommendation
Bind the two independent values before trusting either: reject the request if the payload's `organization.login` does not match the `organization` already recorded on the existing `Team` for `params.team.id` and require a valid signature specifically for that team's owning org (`Shipit.github(organization: team.organization)`), not merely for whichever org name the payload happens to carry. Additionally, do not treat `verify_webhook_signature`'s "no secret configured" case as globally trusted — either mandate a `webhook_secret` for every configured org, or scope trust decisions strictly per-org and never let one org's lack of a secret "verify" webhooks purporting to act on data belonging to a different org.

### Proof of Concept
```ruby
test ":membership from an org with nil webhook_secret can forge membership for a DIFFERENT org's team" do
  no_secret_org_app = Shipit::GitHubApp.new('no-secret-org', webhook_secret: nil)
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(no_secret_org_app)

  target_team = shipit_teams(:shopify_developers) # belongs to org "shopify", already exists
  @request.headers['X-Github-Event'] = 'membership'
  # deliberately no X-Hub-Signature header

  assert_difference -> { Shipit::Membership.count }, 1 do
    post :create, as: :json, body: {
      action: 'added',
      team: { id: target_team.github_id, name: target_team.name, slug: target_team.slug, url: target_team.api_url },
      organization: { login: 'no-secret-org' },
      member: { login: 'attacker' }
    }.to_json
    assert_response :ok
  end

  attacker = Shipit::User.find_by(login: 'attacker')
  assert target_team.members.include?(attacker)
end
```
Binding asserted before/after: `organization.login` in the payload (`"no-secret-org"`) is proven `!=` `target_team.organization` (`"shopify"`), yet the `Membership` is still created, demonstrating the divergence is never checked.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
