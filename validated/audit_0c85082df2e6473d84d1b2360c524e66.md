The reported issue is specific to Aave's `LendingPoolLiquidationManager.sol`: combining "add accrued interest" and "subtract repayment" into a single Solidity subtraction that reverts on underflow (Solidity's default checked-arithmetic revert semantics), which borrowers can exploit to block liquidation entirely.

I searched the Polkadot SDK for structurally analogous patterns — slashing/liquidation-style reductions where a repayment/principal or debt-like value is decremented in a single combined operation that could unexpectedly revert and block a punitive state transition (e.g., `pallet-staking` slashing via `do_slash`, `pallet-nomination-pools` slash application via `do_apply_slash`/`withdraw_unbonded`, `pallet-delegated-staking`, `pallet-assets` withdrawal consequence checks, and `pallet-balances` reserved-balance slashing).

None of these match the bug class:
- FRAME code consistently uses `saturating_sub`/`saturating_reduce` or explicit `checked_sub` with graceful `None`-handling (e.g. `WithdrawConsequence::Underflow`), rather than an implicit reverting subtraction as in Solidity's default arithmetic. [1](#0-0) 
- Slashing paths in `pallet-nomination-pools` and `pallet-delegated-staking` are "lazy"/pending and applied via `do_apply_slash`/`apply_slash`, deliberately decoupled from other repayment-like operations, precisely to avoid the kind of combined-operation revert described in the report. [2](#0-1) 
- `Balances::slash_reserved` and similar imbalance-based slashing use `saturating_reduce`/`saturating_sub` explicitly, so an insufficient balance never causes a revert — it just under-slashes with a returned remainder. [3](#0-2) 

There is no on-chain lending/borrowing/liquidation pallet in this repository (the Polkadot SDK is a blockchain framework, not a lending protocol), so there is no "principal minus accrued interest minus repayment" computation to analyze, and no equivalent "close factor"/collateral-based liquidation-size restriction exists in-tree that a user-supplied extrinsic could exploit to block a punitive state transition. Since FRAME's idiomatic arithmetic (saturating/checked with explicit branching) structurally avoids the specific "combined subtraction reverts on underflow" failure mode described in the report, no demonstrable analog exists.
