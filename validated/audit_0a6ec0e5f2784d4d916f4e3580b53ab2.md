### Title
Path traversal via malicious release asset filename allows arbitrary file write outside destination directory - ([File: pkg/cmd/release/download/download.go])

### Summary
`gh release download` builds the destination file path by directly joining the user-chosen destination directory with the attacker-controlled asset `Name` field from the GitHub Releases API, with no containment check. An attacker who owns a public repository can publish a release asset named e.g. `../../.ssh/authorized_keys`, causing the victim's `gh release download` to write the downloaded content outside the intended directory.

### Finding Description
In `downloadRun`, asset names are taken verbatim from the API (`a.Name`) and placed into `downloadTarget.name` [1](#0-0)  with no sanitization for path traversal sequences (the only per-name checks are file-pattern matching and a Windows-reserved-filename check) [2](#0-1) .

That name flows into `downloadAsset` → `dest.Check(fileName)` / `dest.Copy(fileName, ...)`, both of which call `destinationWriter.makePath`:
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [3](#0-2) 

`filepath.Join` lexically cleans the path but does **not** prevent `..` segments from escaping `w.dir` — it simply concatenates and normalizes, so `filepath.Join("dest", "../../.ssh/authorized_keys")` resolves outside `dest`. There is no subsequent check (e.g., `filepath.Rel` + `strings.HasPrefix` guard, or use of the repo's own `internal/safepaths` package) verifying the resulting path is still contained within `w.dir` before `os.MkdirAll`/`os.OpenFile` are called in `Copy`:
```go
if dir := filepath.Dir(fp); dir != "." {
    if copyErr = os.MkdirAll(dir, 0755); copyErr != nil { ... }
}
var f *os.File
if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil { ... }
``` [4](#0-3) 

Notably, the repository already contains a purpose-built defense for exactly this class of bug — `internal/safepaths.Absolute.Join`, which returns a `PathTraversalError` if a joined path would escape the base directory [5](#0-4)  — and this is used by the sibling `pkg/cmd/run/download` package for artifact downloads, but it is **not** used by `pkg/cmd/release/download`, leaving this code path unprotected.

### Impact Explanation
An attacker who can publish a public release (no special privileges beyond owning/controlling the repo) can name an asset with path-traversal sequences. When a victim runs `gh release download <tag> -R attacker/repo`, the tool will write attacker-controlled bytes to an arbitrary file path relative to the destination directory (limited by the victim's OS file permissions), enabling overwrite of files such as `~/.ssh/authorized_keys`, shell rc files, or other files reachable via directory traversal from the download destination. This maps to GitHub's bounty impact class of arbitrary file write outside the intended directory.

### Likelihood Explanation
Feasible and repeatable: publishing a release with a crafted asset filename requires only that the attacker control a public repository, which matches the stated unprivileged attacker model. The victim needs to run an ordinary `gh release download` command against that repo — no other special conditions are required, and the vulnerable code path (`makePath`/`Copy`) is always exercised for named assets.

### Recommendation
Sanitize/validate asset filenames before constructing the destination path — reject or strip path separators and `..` components (e.g., use `filepath.Base(name)` before joining), and/or adopt the existing `internal/safepaths.Absolute.Join` mechanism (as already used in `pkg/cmd/run/download`) to guarantee the resolved path stays within the destination directory, returning an error otherwise.

### Proof of Concept
Add an httpmock-based test similar to existing tests in `pkg/cmd/release/download/download_test.go`:
1. Mock the release API response so one asset has `"name": "../../evil.txt"` (or a deeper traversal like `"../../../../tmp/pwned"`).
2. Mock the asset download URL to return arbitrary bytes.
3. Run `downloadRun` with `Destination` set to a `t.TempDir()` subdirectory.
4. Assert that no file was created outside the temp destination directory (e.g., check the parent of the temp dir for `evil.txt`), and/or assert that `downloadRun` returns an error instead of writing the file.

Expected current behavior (proving the bug): the file is written outside the destination directory without error. Expected behavior after fix: `downloadRun` returns an error (e.g., a `PathTraversalError`) and no file is created outside the destination directory.

// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
```
