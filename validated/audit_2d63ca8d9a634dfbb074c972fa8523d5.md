### Title
Missing Receipt Status Check in `writeServiceChainTxReceipts` Allows Any Bridge Peer to Corrupt Anchored Block Number — (`node/sc/sub_bridge_handler.go`)

### Summary

`writeServiceChainTxReceipts` processes `ServiceChainReceiptResponseMsg` messages from bridge peers without checking `receipt.Status`. A peer that connects to the sub-bridge's P2P port can send a crafted receipt with `Status = ReceiptStatusFailed` for a pending anchoring tx hash, causing the child chain to permanently record that block as anchored and remove the tx from the pool with no retry.

### Finding Description

In `writeServiceChainTxReceipts`, for every receipt whose `TxHash` matches a pending `BridgeTxPool` entry of type `IsChainDataAnchoring()`, the code unconditionally calls:

```go
sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
```

and then removes the tx from the pool — **with no check on `receipt.Status`**. [1](#0-0) 

The entry point is `handleParentChainReceiptResponseMsg`, which is invoked directly from `HandleMainMsg` for any connected bridge peer that sends `ServiceChainReceiptResponseMsg` (message code `0x02`): [2](#0-1) [3](#0-2) 

The bridge P2P handshake only checks network ID and chain ID — there is no allowlist or cryptographic proof that the responding peer is the legitimate parent chain operator: [4](#0-3) 

### Impact Explanation

1. **Corrupted anchored block number**: `WriteAnchoredBlockNumber` persists the block number from the anchoring tx's embedded data to the `bridgeServiceDB`. The child chain now permanently believes that block is anchored on the parent chain when it is not.
2. **Anchoring tx silently dropped**: `RemoveTx` removes the tx from `BridgeTxPool` with no retry mechanism for anchoring txs (unlike value-transfer txs which have VT Recovery). The anchoring is permanently lost.
3. **False receipt stored**: `WriteReceiptFromParentChain` stores the failed receipt keyed by the child chain block hash, poisoning future `GetReceiptFromParentChain` lookups. [5](#0-4) [6](#0-5) 

### Likelihood Explanation

Any peer that can reach the sub-bridge's P2P port and pass the chain-ID handshake can exploit this. The sub-bridge broadcasts receipt requests to **all** connected bridge peers: [7](#0-6) 

The attacker only needs to know the parent chain ID (public) and the sub-bridge's P2P address to connect and respond before the legitimate main bridge does.

### Recommendation

Add a status check before writing anchoring state:

```go
if receipt.Status != types.ReceiptStatusSuccessful {
    logger.Warn("anchoring tx failed on parent chain, skipping", "txHash", txHash)
    // optionally keep in pool for retry or handle separately
    continue
}
```

### Proof of Concept

1. Sub-bridge has a pending anchoring tx `T` in `BridgeTxPool` with hash `H`, anchoring child block `N`.
2. Attacker connects to sub-bridge P2P port, passes handshake with matching chain ID.
3. Sub-bridge broadcasts `ServiceChainReceiptRequestMsg` containing `H`.
4. Attacker sends `ServiceChainReceiptResponseMsg` with a `ReceiptForStorage{TxHash: H, Status: ReceiptStatusFailed}`.
5. `handleParentChainReceiptResponseMsg` → `writeServiceChainTxReceipts` finds `T` in pool, calls `WriteAnchoredBlockNumber(N)` and `WriteReceiptFromParentChain(blockHash, failedReceipt)`, then `RemoveTx(T)`.
6. Child chain DB now records block `N` as anchored; tx `T` is gone from pool with no retry.

---

**Verdict: Valid vulnerability.** The missing `receipt.Status` guard is confirmed in the code. The attacker path is a semi-trusted P2P bridge peer (no privileged access required), and the impact is persistent corruption of the child chain's anchored block number — a bridge state integrity violation within the allowed impact gate.

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}

func (p *baseBridgePeer) Handshake(network uint64, chainID, td *big.Int, head common.Hash) error {
	// Send out own handshake in a new thread
	errc := make(chan error, 2)
	var status statusData // safe to read after two values have been received from errc

	go func() {
		errc <- p2p.Send(p.rw, StatusMsg, &statusData{
			ProtocolVersion: uint32(p.version),
			NetworkId:       network,
			TD:              td,
			CurrentBlock:    head,
			ChainID:         chainID,
		})
	}()
	go func() {
		e := p.readStatus(network, &status)
		if e != nil {
			errc <- e
			return
		}
		errc <- e
	}()
	timeout := time.NewTimer(handshakeTimeout)
	defer timeout.Stop()
	for range 2 {
		select {
		case err := <-errc:
			if err != nil {
				return err
			}
		case <-timeout.C:
			return p2p.DiscReadTimeout
		}
	}
	p.td, p.head, p.chainID = status.TD, status.CurrentBlock, status.ChainID
	return nil
}
