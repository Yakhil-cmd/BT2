### Title
Webhook signature verification is skipped entirely for orgs without a configured `webhook_secret`, allowing forged webhooks - (File: lib/shipit/github_app.rb)

### Summary
`Shipit::GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever `@webhook_secret` is blank, meaning any organization that has not configured `github.webhook_secret` accepts arbitrary, unsigned webhook payloads. `WebhooksController#verify_signature` relies on this return value as its sole authentication check, so a forged `POST /webhooks` request with any `X-Hub-Signature` (or none at all) is dispatched to `Shipit::Webhooks.for_event(event)` handlers.

### Finding Description
The binding the code should uphold is: `verify_webhook_signature(signature, message) == true` implies `signature` is a valid HMAC-SHA1 of `message` under a secret only Shipit and GitHub know. The actual code is: [1](#0-0) 

`return true unless webhook_secret` breaks that binding: when `@webhook_secret` is `nil` (i.e., the org's config never set `github.webhook_secret`, per `@webhook_secret = @config[:webhook_secret].presence` in the initializer [2](#0-1) ), the method returns `true` for any `signature`/`message` pair, with zero cryptographic check.

`WebhooksController#verify_signature` treats this `true` as proof of authenticity and lets the request through to `create`, which parses `request.raw_post` and dispatches it to registered handlers: [3](#0-2) 

Attacker request: `POST /webhooks` with header `X-Github-Event: <handled event, e.g. push>`, header `X-Hub-Signature: anything` (or a malformed value), and a JSON body naming any `repository.owner.login`/`repository.full_name` the attacker wants to target — as long as that org's `GitHubApp` has no `webhook_secret` configured, the request bypasses `verify_signature` and reaches the event handlers under `app/models/shipit/webhooks/handlers/`, which act on the (attacker-controlled) payload as if GitHub had sent it.

No other guard catches this: `check_if_ping` and `drop_unhandled_event` only filter by event type/presence of a handler, not authenticity [4](#0-3) ; `verify_signature`'s only defense is the broken `verify_webhook_signature` call itself.

### Impact Explanation
For any organization whose Shipit deployment omits `github.webhook_secret` in its GitHub app config, an unauthenticated internet attacker can submit fully forged webhook payloads (push, pull_request, status, etc.) that are dispatched to real handlers, letting them drive stack/commit/task state (e.g., triggering merges, status updates, or other side effects the specific handler performs) for that org's repositories without ever proving they control GitHub. This is a critical authentication bypass — the impact is scoped to organizations that have not set `webhook_secret`, but for those orgs the blast radius covers every repository/stack under that org since `repository_owner` (and thus which `GitHubApp`/secret is checked) is taken directly from the attacker-supplied payload.

### Likelihood Explanation
Exploitability requires only that the target org's Shipit configuration leaves `github.webhook_secret` unset — no secrets, sessions, or privileged roles are needed by the attacker, and the request is a single unauthenticated HTTP POST. This is a plausible real-world misconfiguration (setup docs show it as an optional-looking config key [5](#0-4) ), and the check is entirely inside this engine's own code path, not a third-party dependency issue.

### Recommendation
Change the default behavior so that a missing `webhook_secret` fails closed rather than open: `verify_webhook_signature` should return `false` (or the controller should reject the request) when `webhook_secret` is blank, and/or the application should refuse to boot/register a `GitHubApp` for webhook-receiving orgs without a configured secret.

# test/unit/github_app_test.rb (or similar)
test "#verify_webhook_signature returns true with no cryptographic check when webhook_secret is blank" do
  github_app = Shipit::GitHubApp.new('acme-corp', {}) # no webhook_secret configured

  # Binding claimed to hold: verified == true implies signature is a valid HMAC.
  # Here we show verified == true even for a completely arbitrary, invalid signature.
  assert_equal true, github_app.verify_webhook_signature(nil, 'anything')

end

# test/controllers/webhooks_controller_test.rb
test "forged webhook is accepted when org has no webhook_secret configured" do
  Shipit.stubs(:github).with(organization: 'acme-corp').returns(Shipit::GitHubApp.new('acme-corp', {}))
  Shipit::Webhooks.stubs(:for_event).with('push').returns([mock_handler = Minitest::Mock.new])

       headers: { 'X-Github-Event' => 'push', 'X-Hub-Signature' => 'sha1=totally-forged' }

  assert_response :ok
  mock_handler.verify
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
