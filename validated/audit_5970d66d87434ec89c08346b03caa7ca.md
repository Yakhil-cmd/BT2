Confirmed: there is **no persistent, cross-call outpoint registry** in `pox-5.clar`. The only duplicate-detection is `seen-outpoints`, an accumulator threaded through the `fold validate-l1-lockup` call that lives only for the duration of a single `verify-l1-lockups` invocation.

### Title
Reusable Bitcoin L1 lockup proof lets a staker credit the same UTXO's sats to multiple protocol bonds - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`register-for-bond`'s L1 path (`verify-l1-lockups` → `validate-l1-lockup`) verifies that a supplied Bitcoin output is real, unspent-looking, and matches the expected timelock script for the staker, then adds its `amount` to `sats-total`, which becomes the staker's `amount-sats` share in that bond. Nothing records that a given `(txid, output-index)` outpoint has already been consumed by an *earlier, separate* `register-for-bond` call. The only anti-replay check, `seen-outpoints`, is a local accumulator built and discarded within one `fold` call [1](#0-0) , so it only prevents duplicates *within the same transaction's outputs list*.

### Finding Description
`validate-l1-lockup` checks the Bitcoin header, merkle proof, script hash, and declared amount for each output, and accumulates `sum` across the outputs supplied in one call [2](#0-1) . `verify-l1-lockups` returns that sum as `sats-total`, and `register-for-bond` uses it to set the new membership's `amount-sats`, add it to `protocol-bonds-total-staked`, and add the staker's per-cycle sBTC-equivalent shares via `add-staker-to-bond-cycles` [3](#0-2) . Because the outpoint is never written to durable contract state (no `define-map` entry keyed by `(txid, output-index)` exists anywhere in the contract — confirmed by grep across the repo), the exact same L1 lockup proof (same Bitcoin transaction, same output, same header/merkle proof) can be resubmitted as the `btc-lockup` argument to `register-for-bond` again after the staker's bond ends (or from a rolled-over position), crediting the identical sats a second time toward a new bond's `amount-sats`, `protocol-bonds-total-staked`, and signer/bond reward-share accounting — without any additional BTC ever being locked.

### Impact Explanation
This breaks the equality between "sats actually locked on Bitcoin" and "sats credited inside pox-5's bond accounting." A staker can inflate `amount-sats` for one or more bonds using a single real BTC lockup, thereby claiming a larger share of `sBTC` rewards distributed via `claim-rewards`/`settle-rewards` than their real collateral warrants, and inflating `protocol-bonds-total-staked`, diluting or double-counting reward shares versus genuinely-collateralized stakers. This is a double-counting of a locked commitment as described in the rules ("sats credited by an L1 proof that were never locked on Bitcoin" / "double-counting a commitment or reward"), which maps to Critical impact per the rules' severity table.

### Likelihood Explanation
Reachable by any unprivileged account already on a bond's allowlist (`protocol-bond-allowances`) with a legitimate, single BTC lockup transaction. It requires the L1 lockup's `unlock-burn-height` to still satisfy `get-bond-l1-unlock-height` for the new target bond and the corresponding header still queryable via `get-burn-block-info?`, both realistic for any bond whose L1 unlock window is still open, and is straightforward to repeat once per new `register-for-bond` call — no signer or admin cooperation required.

### Recommendation
Persist consumed L1 outpoints across calls (e.g., a `define-map used-l1-outpoints { txid: (buff 32), output-index: uint } bool`) and check/insert against it inside `validate-l1-lockup` (or `verify-l1-lockups`) before accepting the amount, in addition to the existing intra-call `seen-outpoints` dedup.

### Proof of Concept
1. Staker locks `X` sats on L1 in a valid timelock output for `bond-index=0`, calls `register-for-bond(0, signer, amount-ustx, ok({outputs: [output], staker-unlock-bytes}), none)`. `sats-total = X` is credited; membership recorded with `amount-sats: X`.
2. Bond 0's term ends (or the staker becomes eligible for another allowlisted bond, `bond-index=1`) while the same BTC UTXO remains intact on L1 (the staker never actually needs to move/re-lock the BTC because pox-5 never marks the outpoint used).
3. Staker calls `register-for-bond(1, signer, amount-ustx, ok({outputs: [same output, same header/merkle-proof/amount]}), none)`. `validate-l1-lockup` re-verifies the same real Bitcoin proof (still valid, since nothing about it changed) and re-credits `X` sats to bond 1's `protocol-bonds-total-staked` and the staker's new `amount-sats`.
4. The staker now holds simultaneous credited `amount-sats: X` positions in two bonds from one BTC lockup, doubling their claimable share of sBTC rewards relative to actual locked BTC.
