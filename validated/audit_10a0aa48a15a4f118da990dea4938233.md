### Title
Pre-Permissionless-Fork Single-Mode Governance Authority Bypass: Any Council Member Can Add Arbitrary Validators — (`kaiax/gov/headergov/impl/header.go`, `kaiax/valset/impl/getter_council.go`)

### Summary

In single-governance mode (`governance.governancemode == "single"`), only the designated governing node is supposed to be able to cast governance votes. However, the authority check enforcing this restriction in `VerifyVote` is **gated behind `IsPermissionlessForkEnabled`**. Before the Permissionless hardfork, any council member who becomes a block proposer can embed a `governance.addvalidator` vote in their block header, pass all verification checks, and have `applyVote` unconditionally add an arbitrary address to the council — without ever being the governing node.

### Finding Description

**Step 1 — `VerifyVote` skips the single-mode authority check pre-fork.** [1](#0-0) 

The comment itself says "after Permissionless." Before that fork, the only checks are:
- voter is in council ✓ (attacker is a council member)
- voter is the block proposer ✓ (attacker is the current proposer)
- `checkConsistency` — see below

**Step 2 — `checkConsistency` for `AddValidator` does not check the voter's identity.** [2](#0-1) 

In single mode, `checkConsistency` only rejects votes whose *value* contains the governing node's address. It never verifies that the *voter* is the governing node. A non-governing-node proposer embedding `addvalidator` for any other address passes this check cleanly.

**Step 3 — `applyVote` has no authority check.** [3](#0-2) 

`applyVote` parses the vote from the header and unconditionally calls `council.Add(address)` for any `AddValidator` vote. It does not inspect who cast the vote.

**Step 4 — `postInsertBlockPermissioned` calls `applyVote` without re-checking authority.** [4](#0-3) 

After a block is inserted, `postInsertBlockPermissioned` fetches the governing node from `GovModule.GetParamSet` and passes it to `applyVote` only to protect the governing node's own address from being removed — not to verify that the voter had authority to cast the vote.

**Step 5 — `VerifyHeader` calls `VerifyVote`, so the flawed check is the canonical gate.** [5](#0-4) 

All honest nodes run `VerifyHeader` → `VerifyVote` during block import. Because `VerifyVote` passes for a non-governing-node proposer pre-fork, all honest nodes accept the block and subsequently execute `postInsertBlockPermissioned` → `applyVote`, persistently writing the corrupted council to the DB.

### Impact Explanation

A single malicious council member (not the governing node) who becomes a block proposer can:
1. Add an attacker-controlled address to the validator council.
2. That address then participates in future block production and reward distribution.
3. The corruption is durable — written to `ChainKv` and replayed on every subsequent `getCouncilPermissioned` call.

This is a **validator/governance privilege escalation** that changes protected chain state (the council) and affects asset ownership (block rewards). It violates the core invariant of single-governance mode.

### Likelihood Explanation

- Requires being a council member — not fully permissionless, but council members are not all trusted to have governance authority.
- Requires becoming a block proposer — this happens in normal rotation (round-robin, sticky, or weighted-random), so any council member will eventually propose a block.
- No cryptographic break, no key compromise, no majority collusion required.
- Applies to any network running pre-Permissionless fork with `governance.governancemode == "single"` (Mainnet and Kairos both operate in single mode).

### Recommendation

Move the single-mode authority check out of the `IsPermissionlessForkEnabled` gate so it applies pre-fork as well:

```go
params := h.GetParamSet(blockNum)
if params.GovernanceMode == "single" && vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
```

Additionally, `applyVote` should independently verify the voter's authority rather than relying solely on `VerifyVote` having been called upstream.

### Proof of Concept

1. Configure a chain with `governance.governancemode = "single"`, `governance.governingnode = A`, and council `[A, B]`. Do **not** activate the Permissionless fork.
2. Wait for node `B` (non-governing) to become the block proposer.
3. Node `B` crafts `header.Vote = NewVoteData(B, "governance.addvalidator", attackerAddr).ToVoteBytes()`.
4. Node `B` proposes the block. All honest nodes call `VerifyVote`:
   - `B` is in council ✓
   - `B` is the proposer ✓
   - Permissionless fork not active → single-mode check skipped ✓
   - `checkConsistency`: `attackerAddr != A` → passes ✓
5. Block is accepted. `postInsertBlockPermissioned` → `applyVote` → `council.Add(attackerAddr)`.
6. `GetCouncil(blockNum+1)` now includes `attackerAddr`, which participates in future consensus and reward distribution.

```go
func applyVote(header *types.Header, council *valset.AddressSet, governingNode common.Address) bool {
	voteKey, addresses, ok := parseValidatorVote(header)
	if !ok {
		return false
	}

	originalSize := council.Len()
	for _, address := range addresses {
		if address == governingNode {
			continue
		}
		switch voteKey {
		case gov.AddValidator:
			if !council.Contains(address) {
				council.Add(address)
			}
		case gov.RemoveValidator:
			if council.Contains(address) {
				council.Remove(address)
			}
		}
	}
	return originalSize != council.Len()
}
```

```go
func (v *ValsetModule) postInsertBlockPermissioned(block *types.Block) error {
	header := block.Header()
	num := header.Number.Uint64()
	council, err := v.getCouncilPermissioned(num)
	if err != nil {
		return err
	}
	governingNode := v.GovModule.GetParamSet(num).GoverningNode
	if applyVote(header, council, governingNode) {
		insertValidatorVoteBlockNums(v.ChainKv, num)
		writeCouncil(v.ChainKv, num, council.List())
		v.validatorVoteBlockNumsCache = nil
	}
	return nil
}
```
