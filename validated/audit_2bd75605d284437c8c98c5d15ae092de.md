### Title
Unchecked RAY value multiplication permanently freezes an overgrown market - ([File: `common/src/rates/index.rs`])

### Summary

Scaled debt multiplied by the updated borrow index can overflow `i128` before the configured borrow-index ceiling is reached. Because every market operation first runs interest accrual, this one arithmetic failure permanently blocks repayments, withdrawals, liquidations, and index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description

`global_sync` applies each accrual step before a pool operation mutates state. [3](#0-2)  Each step calls `calculate_supplier_rewards`, which computes `borrowed.mul(new_borrow_index)` using checked fixed-point multiplication. [4](#0-3) [5](#0-4)  `update_borrow_index` caps only the index itself at `MAX_BORROW_INDEX_RAY`; it does not ensure that `borrowed * new_borrow_index` remains representable. [6](#0-5) 

A sufficiently large debt position can therefore make the debt-value product overflow while `new_borrow_index` is still below its cap. [7](#0-6)  `repay` loads the leg through `synced_market`, and `withdraw` does the same before resolving the user's scaled position, so neither exit path can bypass the failing accrual. [8](#0-7) [9](#0-8) [10](#0-9)  The public controller paths expose this state transition to an unprivileged account through `supply`, `borrow`, `repay`, `withdraw`, `liquidate`, and `update_indexes`. [11](#0-10) [12](#0-11) 

### Impact Explanation

Once the product overflows, the transaction reverts before new state is committed, so the market cannot accrue past the failing timestamp. [3](#0-2) [7](#0-6)  Because repayment and withdrawal also accrue first, borrower funds cannot be recovered and supplier principal plus yield cannot be withdrawn through the normal permissionless interface. [13](#0-12) [14](#0-13)  The repository's stress test demonstrates the concrete consequence: a market crossing the RAY-value cliff rejects `update_indexes`, `withdraw`, and `repay` with `MathOverflow`. [15](#0-14) 

### Likelihood Explanation

Triggering the condition requires an unusually large token-denominated book and sustained borrowing long enough for the borrow index to make the debt product exceed `i128::MAX`. [16](#0-15)  An unprivileged attacker can establish the required supply and debt positions through ordinary controller calls, but only with substantial capital and a market whose configured collateral limits, utilization ceiling, and interest curve permit the position to persist. [17](#0-16) [18](#0-17) [19](#0-18) 

### Recommendation

Bound the scaled debt or its projected value before calculating accrued interest, and make index growth stop safely when the debt-value representation limit is reached. [2](#0-1)  At minimum, check `borrowed * new_borrow_index` before committing an index increase, clamp accrual to the largest representable product, and provide a recovery path that can burn debt or wind down the market without requiring the overflowing accrual. [1](#0-0) 

### Proof of Concept

1. Deploy or select a high-decimal market whose configured caps permit approximately `1_000_000_000 * 10^18` supplied units and whose rate curve can sustain high utilization. [16](#0-15) 
2. As one unprivileged caller, call `controller.supply(caller, 0, spoke_id, [(hub_asset, principal), (collateral_asset, collateral)])` and use the created account for both liquidity and collateral. [20](#0-19) 
3. Call `controller.borrow(caller, account_id, [(hub_asset, principal * 98 / 100)], Some(caller))` to create the oversized scaled-debt position. [21](#0-20) 
4. Keep utilization high and periodically call `controller.update_indexes` until `borrowed * new_borrow_index` exceeds `i128::MAX` while `new_borrow_index < MAX_BORROW_INDEX_RAY`. [22](#0-21) [2](#0-1) 
5. Subsequent `controller.repay(caller, account_id, [(hub_asset, 1)])`, `controller.withdraw(caller, supplier_account, [(hub_asset, 1)], None)`, liquidation attempts, and further `update_indexes` calls all revert in accrual before reaching their exits. [1](#0-0) [23](#0-22)

    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

    let (mut cache, position) = ops::load_leg(env, action);

    let (burned, overpayment) = cache.resolve_repay(amount, position);

    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
