### Title
Terminal escape sequence injection via unsanitized tool-call `Path` argument in agent-task log rendering - ([File: pkg/cmd/agent-task/shared/log.go])

### Summary
`renderLogEntry` renders `view`, `create`, and `str_replace` tool-call titles by passing the raw JSON-decoded `args.Path` string through `relativeFilePath` and `cs.Bold`, then writing the result directly to `io.Out` with `fmt.Fprintf`. Unlike the `Content`/`ReasoningText` fields, which are explicitly typed `iostreams.Untrusted` and sanitized of ANSI escapes via `Untrusted.String()`, the `Path` field of `viewToolArgs`, `createToolArgs`, and `strReplaceToolArgs` is a plain `string`, so no ANSI/control-sequence sanitization is ever applied to it before it reaches the terminal.

### Finding Description
In `pkg/cmd/agent-task/shared/log.go`, `renderLogEntry` handles `view`, `create`, and `str_replace` tool calls at lines 134-147, 230-241, and 242-253. For each, `args.Path` is unmarshaled directly from `tc.Function.Arguments` JSON (attacker/agent-controlled tool call arguments streamed from the chat-completion log) into a plain `string` field: [1](#0-0) [2](#0-1) 

That path is then passed to `relativeFilePath`, which performs only prefix-trimming and `/`-splitting with no character filtering: [3](#0-2) 

The result is wrapped in `cs.Bold(...)` and printed via `renderToolCallTitle`, which does a plain `fmt.Fprintf(w, "%s: %s\n", toolName, title)` with no escaping: [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

This is inconsistent with the codebase's own established mitigation for exactly this problem: `iostreams.Untrusted`, used for `Delta.Content` and `Delta.ReasoningText` in the same struct, sanitizes ANSI escape sequences automatically via its `String()` method before any `fmt` print path renders it: [8](#0-7) [9](#0-8) 

Because `Path` is a bare `string` rather than `iostreams.Untrusted`, and `relativeFilePath`/`cs.Bold`/`renderToolCallTitle` do not strip control bytes, any embedded ANSI escape sequence (e.g. `\x1b[`) or other terminal control code in `args.Path` reaches `io.Out` unescaped.

The attack requires attacker-controlled tool-call arguments to appear in the streamed agent-task log. This is plausible via prompt injection: if a malicious repository contains a file (or triggers agent behavior) whose path is derived from attacker-influenced content, the coding agent could invoke `view`/`create`/`str_replace` with a `path` value containing a crafted string (this can be influenced indirectly, e.g. by naming conventions, symlink targets, or agent reasoning steered by repo content) that is then echoed back into the streamed tool-call JSON and rendered by `gh agent-task view` or similar log-following commands on the victim's terminal.

### Impact Explanation
Successful injection of raw ANSI/terminal escape sequences into `io.Out` can be used to manipulate the victim's terminal display (e.g., hide/spoof text, move the cursor, clear the screen, or — depending on terminal emulator — trigger more dangerous escape-sequence behaviors such as title-bar manipulation or, in vulnerable terminal emulators, further control-sequence abuse). This matches a terminal/output-injection impact class: it is a lower-severity issue since it does not directly grant code execution or credential exfiltration within `gh` itself, but it does violate the intended output-safety invariant that untrusted content should not reach the terminal unsanitized — an invariant the codebase already treats as security-relevant, as evidenced by the dedicated `iostreams.Untrusted` sanitization type used for adjacent fields in the exact same struct.

### Likelihood Explanation
Preconditions require the victim to run `gh agent-task view`/follow-log style commands against a session whose tool-call log contains a `path` argument with embedded control sequences. Because `Path` values originate from the coding agent's own tool invocations (which can, in turn, be influenced by content in the target repository through prompt injection), an unprivileged attacker who can get their crafted repository content processed by the agent has a plausible, repeatable path to injecting values into `args.Path`. This is a real but conditional path (it depends on the agent actually acting on attacker-supplied path names), so likelihood is moderate rather than trivial.

### Recommendation
Wrap `Path` fields (`viewToolArgs.Path`, `createToolArgs.Path`, `strReplaceToolArgs.Path`) in `iostreams.Untrusted` (or otherwise sanitize with the same `asciisanitizer`/`stripControl` logic) before passing them through `relativeFilePath`/`cs.Bold` and printing them, consistent with how `Delta.Content` and `Delta.ReasoningText` are already handled in the same struct.

### Proof of Concept
```go
func TestRenderToolCallTitle_PathANSIInjection(t *testing.T) {
    io, _, out, _ := iostreams.Test()
    cs := io.ColorScheme()

    maliciousPath := "/home/runner/work/owner/repo/\x1b[31mFAKE\x1b[0m/evil.go"
    renderToolCallTitle(io.Out, cs, fmt.Sprintf("View %s", cs.Bold(relativeFilePath(maliciousPath))), "")

    if strings.Contains(out.String(), "\x1b[") {
        t.Fatalf("raw ANSI escape sequence reached terminal output: %q", out.String())
    }
}
```
Expected (current, vulnerable) result: the assertion fails because `out.String()` contains the raw `\x1b[31m`/`\x1b[0m` sequences, since neither `relativeFilePath` nor `renderToolCallTitle` strip or sanitize them. A fuzz target over `relativeFilePath`/`renderToolCallTitle` seeded with `\x1b[` sequences and long strings would confirm the same for `create`/`str_replace` code paths.

// relativeFilePath converts an absolute file path to a relative one.
// We expect paths to be of the form: /home/runner/work/<repo-owner>/<repo-name>/path/to/file
// The expected output of that example is: path/to/file
func relativeFilePath(absPath string) string {
	relPath := strings.TrimPrefix(absPath, "/home/runner/work/")

	parts := strings.Split(relPath, "/")

	// The last two parts of the path are the
	// repo name and the repo owner.
	// If that's all we have (or less),
	// we return a friendly name "repository".
	if len(parts) > 2 {
		// Drop the repo owner and name, returning the remaining path.
		return strings.Join(parts[2:], "/")
	}
	return "repository"
}

func renderToolCallTitle(w io.Writer, cs *iostreams.ColorScheme, toolName, title string) {
	// Should not happen, but if it does we still want to print a heading
	// with the information we do have.
	if toolName == "" {
		toolName = "Generic tool call"
	}

	if title != "" {
		title = cs.Bold(title)
	}

	if title != "" {
		fmt.Fprintf(w, "%s: %s\n", toolName, title)
	} else {
		fmt.Fprintf(w, "%s\n", toolName)
	}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
