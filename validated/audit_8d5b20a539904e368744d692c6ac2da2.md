### Title
Governance Permanently Locked by Zero-Address Vote for `governance.governingnode` in Single Mode — (`File: kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `FormatChecker` for the `GovernanceGoverningNode` parameter accepts the zero address (`0x0000000000000000000000000000000000000000`) as a valid vote value. The consistency check in `checkConsistency` validates only that the *current* governing node is in the council — it never inspects the *new* value being voted on. A governing node operating in `"single"` mode can therefore ratify a vote that sets `governance.governingnode` to the zero address, after which no further governance votes can ever be accepted, permanently locking all on-chain governance parameters.

---

### Finding Description

**Root cause — missing zero-address guard in `FormatChecker`**

In `kaiax/gov/param.go`, the `GovernanceGoverningNode` parameter definition is:

```go
GovernanceGoverningNode: {
    Canonicalizer: addressCanonicalizer,
    FormatChecker: func(cv any) bool {
        _, ok := cv.(common.Address)
        return ok          // only type-checks; zero address passes
    },
    DefaultValue: common.HexToAddress("0x0000000000000000000000000000000000000000"),
},
```

The `FormatChecker` accepts any value that canonicalizes to a `common.Address`, including `0x0000…0000`. The existing test suite in `kaiax/gov/headergov/vote_test.go` explicitly lists the zero address as a *good* vote value:

```go
{name: gov.GovernanceGoverningNode, value: "0x0000000000000000000000000000000000000000"},
```

**Root cause — `checkConsistency` validates the wrong address**

In `kaiax/gov/headergov/impl/header.go`, the consistency check for a `GovernanceGoverningNode` vote inspects `params.GoverningNode` (the *current* governing node) rather than `vote.Value()` (the *proposed* new value):

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    ...
    if slices.Contains(council, params.GoverningNode) { // current node, not new value
        return nil
    }
    return ErrGovNodeNotInValSetList
```

The new value (zero address) is never checked against the council or for zero-ness.

**Lock mechanism after ratification**

Once the zero address is ratified as `governance.governingnode`, two independent enforcement points reject every subsequent vote:

1. **API layer** (`kaiax/gov/headergov/impl/api.go`):
   ```go
   if gMode == "single" && voter != gp.GoverningNode {
       return "", ErrVotePermissionDenied
   }
   ```
   No real node has the zero address, so every caller fails this check.

2. **Consensus layer** (`kaiax/gov/headergov/impl/header.go`), post-Permissionless fork:
   ```go
   if h.ChainConfig.IsPermissionlessForkEnabled(...) &&
       params.GovernanceMode == "single" &&
       vote.Voter() != params.GoverningNode {
       return ErrVotePermissionDenied
   }
   ```
   Any block carrying a `header.Vote` is rejected by every honest node.

`GovernanceGoverningNode` is absent from both `AlwaysDeprecated` and `PermissionlessDeprecated`, so the vote is accepted at all fork levels.

---

### Impact Explanation

After the zero address is ratified as the governing node:

- **All header-governance parameter changes are permanently blocked.** No node can ever cast a valid vote for `governance.unitprice`, `reward.mintingamount`, `reward.ratio`, `kip71.*`, `governance.govparamcontract`, or any other mutable parameter.
- **The `getDemotedValidatorsIstanbul` protection becomes a no-op.** The zero address is not in the council, so the "governing node cannot be demoted" guard (`kaiax/valset/impl/getter_demote.go` line 100) never fires, and the zero address never becomes a qualified proposer.
- The chain continues to produce blocks, but governance is irrecoverably frozen. This constitutes permanent destruction of the governance privilege — a protected chain-state invariant.

---

### Likelihood Explanation

The trigger requires the current governing node (a semi-trusted operator) to submit a vote with the zero address as the new governing node. This can occur through:

- **Operator error**: submitting an empty or uninitialized address string via the `governance_vote` RPC.
- **Scripting bug**: an automation script that constructs the vote value from an unset variable.
- **Intentional griefing**: a compromised or malicious governing-node operator.

The fact that the existing test suite explicitly marks the zero address as a *valid* vote value (with no corresponding rejection test) confirms that no protection exists at any layer of the stack.

---

### Recommendation

1. **Add a zero-address guard to the `FormatChecker`** for `GovernanceGoverningNode` in `kaiax/gov/param.go`:

   ```go
   FormatChecker: func(cv any) bool {
       addr, ok := cv.(common.Address)
       return ok && addr != (common.Address{})
   },
   ```

2. **Validate the *new* value in `checkConsistency`** (`kaiax/gov/headergov/impl/header.go`): confirm that `vote.Value().(common.Address)` is a member of the current council before accepting the vote, not just that the current governing node is in the council.

3. **Remove the zero address from the `goodVotes` list** in `kaiax/gov/headergov/vote_test.go` and add a corresponding `badVotes` entry.

```bash
curl http://localhost:8551 -X POST -H 'Content-Type: application/json' --data '{
  "jsonrpc":"2.0","id":1,"method":"governance_vote",
  "params":["governance.governingnode","0x0000000000000000000000000000000000000000"]
}'
```

The call succeeds because:
- `NewVoteData` passes `FormatChecker` (zero address is a valid `common.Address`). [1](#0-0)

- The API-level single-mode guard passes because the caller *is* the current governing node. [3](#0-2) 

**Step 2 — Vote is ratified at the next epoch block**

`VerifyVote` accepts the block because the voter is the current governing node and the new value passes `FormatChecker`. At the epoch boundary, `header.Governance` is written with `{"governance.governingnode": "0x0000…0000"}`. [4](#0-3) 

**Step 3 — Governance is permanently locked from the following epoch**

Any subsequent `governance_vote` call returns `ErrVotePermissionDenied` because `voter != gp.GoverningNode` (zero address). [3](#0-2)
