### Title
Unbounded per-block reward distribution work via mass stake-account creation defeats `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` clamp - (File: runtime/src/bank/partitioned_epoch_rewards/mod.rs)

### Summary
`Bank::get_reward_distribution_num_blocks` clamps the number of reward-distribution blocks to at most `slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH`, but this clamp only limits the *number of blocks*, not the *work per block*. When the number of stake accounts (`rewards.num_rewards()`) exceeds `stake_account_stores_per_block * (slots_per_epoch / 10)`, the average number of stake accounts processed per distribution block grows linearly with the attacker-controlled stake-account count instead of staying bounded by `partitioned_rewards_stake_account_stores_per_block`.

### Finding Description
`get_reward_distribution_num_blocks` computes: [1](#0-0) 
`num_chunks = total_stake_accounts.div_ceil(stake_account_stores_per_block)` is clamped to `[1, slots_per_epoch/10]`. The clamped value becomes `epoch_rewards_sysvar.num_partitions`, which is then passed as `num_partitions` into `hash_rewards_into_partitions`, which hashes every reward index into one of exactly `num_partitions` buckets: [2](#0-1) 
Because the number of buckets is capped independently of `total_stake_accounts`, once `total_stake_accounts` exceeds `stake_account_stores_per_block * max_blocks`, each bucket's average size becomes `total_stake_accounts / max_blocks`, which is unbounded in `total_stake_accounts`. `store_stake_accounts_in_partition` then loops over every index in the assigned partition for the block, doing full stake-account reconstruction, rent adjustment, and account store work per index, with no additional per-block cap: [3](#0-2) 

An unprivileged attacker can inflate `total_stake_accounts` simply by creating a very large number of stake accounts, each delegated at (or just above) the minimum stake delegation, to any validator's vote account (delegation requires no permission over the target vote account). Every such delegation that earns any inflation reward (even the minimum non-zero reward) becomes a `Some(PartitionedStakeReward)` entry contributing to `num_rewards()` in the following epoch's calculation phase. This causes the per-block partition size in `store_stake_accounts_in_partition` to scale with attacker-controlled input while the number of blocks stays fixed at the clamp, violating the intended invariant that `partitioned_rewards_stake_account_stores_per_block` bounds per-block work.

No existing signer/authority/rent/overflow check prevents this: `store_stake_accounts_in_partition`'s loop bound is `indices.len()` for the given partition, not `stake_account_stores_per_block`, and there is no secondary check enforcing that partition size stays under this configured cap once `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` is hit.

### Impact Explanation
This is an epoch-boundary DoS: once enough delegations exist, every honest validator replaying the reward-distribution blocks does proportionally more work per block (account reconstruction, rent adjustment math, `store_accounts` calls) than `stake_account_stores_per_block` was designed to bound, which can materially slow down or stall replay for the whole cluster at every epoch boundary — a cluster-wide liveness/halt risk rather than a direct minting bug, matching the "epoch-boundary work must be bounded" invariant class in scope.

### Likelihood Explanation
Feasibility depends purely on economic cost to the attacker: each malicious stake account requires rent-exempt reserve for a `StakeStateV2`-sized account plus the minimum stake delegation amount, both attacker-funded and non-recoverable until deactivated/withdrawn. Because delegation targets an arbitrary vote account with no cooperation required from its owner, and the number of accounts a single attacker can create scales only with their own capital (not with any per-validator or per-cluster limit found in this code path), this is repeatable every epoch and does not require validator/operator collusion — it is limited only by how much SOL the attacker is willing to lock up temporarily.

### Recommendation
Bound `store_stake_accounts_in_partition`'s per-block work directly by `partitioned_rewards_stake_account_stores_per_block`, independent of the number of distribution blocks — e.g., allow `num_partitions` (and thus the number of distribution blocks) to grow past the current `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` clamp when `total_stake_accounts` is large, or split any partition whose size exceeds `stake_account_stores_per_block` across additional sub-partitions processed in the same or subsequent blocks, so per-block work never exceeds the configured store-per-block limit regardless of total delegation count.

### Proof of Concept
Add a test in `runtime/src/bank/partitioned_epoch_rewards/mod.rs` alongside `test_get_reward_distribution_num_blocks_cap`:
```rust
#[test]
fn test_reward_distribution_partition_size_unbounded_by_stores_per_block() {
    // Use small epoch + small stake_account_stores_per_block, as in
    // test_get_reward_distribution_num_blocks_cap.
    let stake_account_stores_per_block = 10;
    let slots_per_epoch = 32; // max_blocks = 32/10 = 3

    // Simulate an attacker-inflated reward set far exceeding
    // stake_account_stores_per_block * max_blocks (10 * 3 = 30).
    let num_stakes: u64 = 1_000_000; // attacker-controlled, unbounded
    let stake_rewards = (0..num_stakes)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect::<PartitionedStakeRewards>();

    let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);
    assert_eq!(num_blocks, 3); // clamped, as designed

    let partition_indices = hash_rewards_into_partitions(
        &stake_rewards, &Hash::new_from_array([1; 32]), num_blocks as usize,
    );

    // Assert (and expect this to FAIL) that no partition exceeds the
    // configured per-block store limit.
    for partition in &partition_indices {
        assert!(
            partition.len() as u64 <= stake_account_stores_per_block,
            "partition size {} exceeds stake_account_stores_per_block {}",
            partition.len(),
            stake_account_stores_per_block
        );
    }
}
```
Expected result on current code: the assertion fails because each partition holds roughly `num_stakes / num_blocks` ≈ 333,333 entries, far exceeding `stake_account_stores_per_block = 10`, demonstrating that per-block distribution work is not bounded by the configured limit once the attacker inflates `total_stake_accounts` beyond the clamp threshold.

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
        DistributionResults {
            stake_reward_lamports_minted,
            stake_reward_lamports_burned,
            block_reward_lamports_distributed,
            block_reward_lamports_burned,
            updated_stake_rewards,
        }
    }
