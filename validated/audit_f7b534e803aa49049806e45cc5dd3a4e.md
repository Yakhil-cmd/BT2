### Title
Cross-tenant `pull_request` `closed` webhook forgery via decoupled `repository.owner.login` / `repository.full_name` fields lets an attacker archive/deprovision any tracked repository's `ReviewStack` - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb)

### Summary
`WebhooksController#verify_signature` authenticates a webhook using `params.dig('repository','owner','login')` only, while `ClosedHandler#repository` looks up the mutated `Repository` using the independent `params.repository.full_name` field. Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org's `webhook_secret` is blank, an attacker can authenticate as a "no-secret" org while pointing `repository.full_name` at a completely different, victim-tracked repository, causing `ClosedHandler` to archive and deprovision that victim's `ReviewStack`.

### Finding Description
The broken binding: the code implicitly assumes `params.dig('repository','owner','login') == owner-of(params.repository.full_name)`, but nothing enforces this equality.

- `verify_signature` resolves the app/secret via `repository_owner`, defined as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) , then calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when `webhook_secret` is blank, with no HMAC check at all: `return true unless webhook_secret` [3](#0-2) .
- `ClosedHandler#repository` (and thus the `ReviewStack` scope that gets archived) is derived from a completely different payload field, `params.repository.full_name`, via `Shipit::Repository.from_github_repo_name` [4](#0-3) .
- `ClosedHandler#process` unconditionally calls `review_stack.archive!` once `params.action == "closed"`, with no re-check of `review_stacks_enabled`, provisioning behavior, or organization ownership [5](#0-4) .
- `ReviewStackAdapter#archive!` looks up the stack by `environment` ("pr#{number}") within the scope passed in, and if found, calls `stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!` [6](#0-5) .

Exploit flow: attacker crafts a `pull_request` `action=closed` JSON body where `repository.owner.login` = some GitHub org configured in Shipit with no `webhook_secret` (passes `verify_signature` trivially), but `repository.full_name` = `"victim-org/victim-repo"` (a different, secret-protected org that is actually tracked by Shipit) and `number` = the PR number of an existing `ReviewStack` on that victim repo. Because the two fields are never checked against each other, the request is accepted, and `ClosedHandler` finds and archives/deprovisions the victim's `ReviewStack` for that PR — a payload authenticated as one repository mutating another repository's stack.

The `review_stacks_enabled false` / "provision precedence bug" angle raised in the question affects `OpenedHandler`/`ReopenedHandler`'s `provision?`/`unarchive?` predicates, where Ruby operator precedence makes `review_stacks_enabled` gate only the `allow_all` disjunct and not the `allow_with_label`/`prevent_with_label` disjuncts [7](#0-6) [8](#0-7) . That bug can leave a `ReviewStack` row present even when `review_stacks_enabled` is later set to `false`. However, `ClosedHandler` itself performs **no** `review_stacks_enabled` or `provision?` check whatsoever — it archives any pre-existing `ReviewStack` unconditionally once `action == "closed"` [9](#0-8) . If no `ReviewStack` row exists for that PR number, `archive!` is a no-op (logs and returns `true`) [10](#0-9) . So the `review_stacks_enabled false` precondition only matters insofar as it determines whether a `ReviewStack` row still exists (e.g., left over from before the flag was disabled, or created earlier via the precedence bug); it does not gate `ClosedHandler`'s behavior directly.

Existing guards that fail to prevent this: `drop_unhandled_event` only checks the event type, not payload consistency; `ExplicitParameters` schema for `ClosedHandler` validates types/presence of `repository.full_name`, `number`, etc., but never cross-validates against `repository.owner.login` [11](#0-10) ; `verify_signature` never re-derives or compares the org against `params.repository.full_name`.

### Impact Explanation
An attacker who owns/controls (or merely names) an unrelated GitHub org that happens to be configured in Shipit without a `webhook_secret` can forge a `pull_request` `closed` event that archives and deprovisions any other tracked repository's `ReviewStack`, as long as that `ReviewStack` row exists (`Shipit::Repository.from_github_repo_name` + `environment: "pr#{number}"` match). This is a payload for one repository mutating another repository's stack — matching the Critical impact category ("a payload for one repository mutating another's stack"), since `deprovision`/`archive!` triggers unauthorized stack teardown for a victim tenant. The attack is repeatable against any PR number/environment on any tracked repository, for as long as at least one Shipit-configured org lacks a `webhook_secret`.

### Likelihood Explanation
Preconditions: (1) at least one GitHub organization is configured in Shipit (`Shipit.github(organization: ...)`) without a `webhook_secret` — an operator misconfiguration, not attacker-controlled; (2) a `ReviewStack` row already exists for the targeted victim repo/PR number. Given those, the attacker needs no Shipit session, API token, or any secret — just the ability to POST an arbitrary JSON body to `/webhooks` with a crafted `X-Github-Event: pull_request` header and mismatched `repository.owner.login` / `repository.full_name` fields. This is a single unauthenticated HTTP request, fully repeatable and scriptable across arbitrary repositories/PR numbers.

### Recommendation
In `WebhooksController#verify_signature`, derive the authenticating organization strictly from the same field used for repository resolution downstream (`params.repository.full_name`'s owner segment), and reject the request if `repository.owner.login` doesn't match that owner. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when `webhook_secret` is blank in production — either require a secret for every configured org or fail closed. Also add an explicit ownership check in each handler (`ClosedHandler`, `OpenedHandler`, `ReopenedHandler`) that the resolved `Repository#owner` equals the org that authenticated the request. Fix the `provision?`/`unarchive?` operator-precedence bug by explicitly parenthesizing `review_stacks_enabled && (...)` across all three provisioning-behavior disjuncts.

### Proof of Concept
minitest plan (`test/controllers/shipit/webhooks_controller_test.rb` or `test/models/shipit/webhooks/handlers/pull_request/closed_handler_test.rb`):
1. Configure two orgs in `Shipit.app_configuration`/`Shipit.github`: `"no-secret-org"` with `webhook_secret: nil`, and `"victim-org"` with a real `webhook_secret`.
2. Create `Repository.create!(owner: "victim-org", name: "victim-repo")` and a `ReviewStack` for it at `environment: "pr123"` (via `OpenedHandler` while `review_stacks_enabled: true`, or directly via fixture).
3. Assert binding before: `stack = ReviewStack.find_by(environment: "pr123"); assert_not stack.archived?`.
4. POST to `/webhooks` with header `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and JSON body `{"action":"closed","number":123,"repository":{"owner":{"login":"no-secret-org"},"full_name":"victim-org/victim-repo"}, "pull_request": {...}, "sender": {"login":"attacker"}}`.
5. Assert response is `200`/`:ok` (signature check passed because `no-secret-org` has blank secret) — confirming `repository_owner == "no-secret-org"` authenticated the request while the mutated repository is `"victim-org/victim-repo"`.
6. Assert binding after: `assert stack.reload.archived?` — the victim's stack was archived/deprovisioned by a request authenticated under an unrelated org's (absent) secret, proving the divergence.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
