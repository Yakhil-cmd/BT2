### Title
Unfiltered pull-request label names in `ReviewStack#env` inject fork-controlled `LD_LIBRARY_PATH` into `tasks.<name>.steps`/deploy processes - ([File: app/models/shipit/review_stack.rb])

### Summary
`ReviewStack#env` merges every pull-request label name (uppercased) directly into the environment hash with no allowlist, and that hash flows unfiltered through `TaskCommands#env`/`DeployCommands#env` into `Command#unbundled_env`, which is passed straight to `PTY.spawn`. A fork PR author who can label their own PR (per this audit's attacker model) can set a label named `ld_library_path`, and the value `"true"` for that key will be present in the environment of every spawned process for that stack's `tasks.<name>.steps`, `deploy` and `rollback` steps.

### Finding Description
The broken binding: `TaskCommands#env` and `DeployCommands#env` assume `@stack.env` is a safe, fixed set of stack metadata keys (`ENVIRONMENT`, `BRANCH`, etc. — see the base `Stack#env` at [1](#0-0)  ), i.e. the claimed invariant is `keys(@stack.env) == keys(Stack#env base hash)`. For a `ReviewStack`, this is false: `ReviewStack#env` overrides the base and merges in one entry per pull-request label, uppercased, with no key filtering: [2](#0-1) 

Labels are persisted verbatim from the webhook body by `LabelCapturingHandler#capture_labels`, with only a String-type parameter constraint, no content/format allowlist: [3](#0-2) [4](#0-3) 

`TaskCommands#env` merges `@stack.env` unfiltered (unlike task-triggered user variables, which go through `TaskDefinition#filter_envs`/`EnvironmentVariables#permit`): [5](#0-4) 

That merged env is passed straight into `Command.new(command_line, env:, chdir: steps_directory)` for both `perform` (custom `tasks.<name>.steps`) and `install_dependencies`: [6](#0-5) 

`DeployCommands#env` (used for `tasks.deploy.steps`) similarly calls `super` (which includes `@stack.env`) without any filtering: [7](#0-6) 

Finally, `Command#unbundled_env` merges `@env` (stringified) directly on top of `BASE_ENV`/`PATH`, and this exact hash is handed to `PTY.spawn`: [8](#0-7) 

Exploit flow: an unprivileged fork PR author (per this audit's attacker model, capable of "labeling their own PR") adds/has a label literally named `ld_library_path` to their PR on a repository configured with `provisioning_behavior=allow_with_label`. On the next `labeled`/`opened`/`reopened` webhook, `LabelCapturingHandler#capture_labels` stores `["ld_library_path", ...]` on the `PullRequest#labels` column with no sanitization. Any subsequent stack action for that review stack — a custom task under `tasks.<name>.steps`, `install_dependencies`, or a deploy — calls `TaskCommands#env`/`DeployCommands#env`, which merges `ReviewStack#env`'s `{"LD_LIBRARY_PATH" => "true"}` into the spawned command's environment via `Command#unbundled_env` and `PTY.spawn`.

Existing guards do not intercept this: `filter_deploy_envs`/`TaskDefinition#filter_envs`/`EnvironmentVariables#permit` are only applied to explicitly user-supplied env parameters at trigger time (e.g. `Stack#trigger_task`, `Stack#build_deploy`), not to `@stack.env` itself, so the label-derived keys bypass the variable-definition allowlist entirely. The `provisioning_behavior_allow_with_label` gate only controls whether the review stack is provisioned/unarchived — it does not filter the environment merged into spawned processes.

### Impact Explanation
Every process spawned for that review stack's tasks, deploys, rollbacks, and dependency installation inherits an attacker-chosen environment-variable name (value fixed to `"true"` by the code). Because tasks run with `chdir` set inside the checked-out fork's working directory, and `LD_LIBRARY_PATH` is a relative-or-absolute colon-separated search path for the dynamic linker, an attacker who also controls the repository content (which they do, since it's their own fork) can additionally place a directory/library at a path resolvable via this variable to redirect dynamic linking of any dynamically-linked binary invoked during the pipeline. This matches the Critical RCE class (`Command`/`PTY.spawn`) since the attacker fully controls both the injected environment key and the working directory content backing it, without holding any privileged Shipit role, GitHub write/triage permission emulation aside (per the stated attacker capabilities), or secret.

### Likelihood Explanation
Preconditions: the repository must have `review_stacks_enabled` and `provisioning_behavior` set to `allow_with_label` (or `allow_all`) so a review stack exists and runs task/deploy steps for the fork's PR; the attacker needs only to open a PR from their fork and set the label on it, both explicitly enumerated as within-scope attacker capabilities for this audit. No Shipit credentials, GitHub App keys, or maintainer approval are required. This is fully repeatable against any repository with review stacks enabled under this provisioning mode, and against every task/deploy run for that stack.

### Recommendation
Filter `ReviewStack#env`'s label-derived hash through an explicit allowlist (or a distinct namespaced prefix such as `SHIPIT_LABEL_*`) before merging, and additionally strip/deny well-known security-sensitive variable names (`LD_LIBRARY_PATH`, `LD_PRELOAD`, `DYLD_*`, `PATH`, etc.) anywhere untrusted, per-PR-controlled data is merged into `Command`'s environment, mirroring the `EnvironmentVariables#permit` allowlist already used for explicit task/deploy variables.

### Proof of Concept
```ruby
test "[allow_with_label] LD_LIBRARY_PATH via PR label reaches tasks.<name>.steps spawned env" do
  stack = shipit_stacks(:review_stack)
  stack.pull_request.update!(labels: ["ld_library_path"])
  task = shipit_tasks(:shipit_restart)
  task.stack = stack

  env = Shipit::TaskCommands.new(task).env
  assert_equal "true", env["LD_LIBRARY_PATH"]

  command = Shipit::Command.new("true", env: env, chdir: task.working_directory)
  assert_equal "true", command.unbundled_env["LD_LIBRARY_PATH"]
end
```

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end

    def unbundled_env
      BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)
    end
