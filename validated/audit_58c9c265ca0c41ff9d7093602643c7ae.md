### Title
Webhook signature verification uses an attacker-supplied organization field that is never cross-checked against the repository the event actually mutates - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects *which* GitHub App/webhook secret to validate the HMAC against using `repository_owner`, a value read straight out of the unauthenticated JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). [1](#0-0) [2](#0-1)  Once the signature is accepted, the actual event handlers resolve the target `Stack`/`Repository` using a *different* field from the same payload, `repository.full_name`, via `Handler#repository_name` / `#stacks`. [3](#0-2)  Nothing ties the `repository_owner` value that selected the verifying secret to the `repository.full_name` value that is actually acted upon.

### Finding Description
The equality that should hold is:

`organization whose webhook_secret verified the HMAC == owner of the repository.full_name that the handler mutates`

Before the attacker's request: for a legitimate GitHub-originated push/PR/status webhook, `repository.owner.login` and `repository.full_name`'s owner segment are always the same value, produced by GitHub itself, so the binding trivially holds.

After the attacker's request: an attacker who operates their own GitHub organization/App configured in the same multi-org Shipit deployment (see the documented multi-org config shape in `config/secrets.development.shopify.yml`, where several `github:` entries each carry an independent `webhook_secret`) [4](#0-3)  can craft an arbitrary JSON body where:
- `repository.owner.login` (or `organization.login`) = their own org (`attacker-org`), so `Shipit.github(organization: repository_owner)` resolves to *their own* configured `GithubApp`, and they sign the raw body with their own legitimately-known `webhook_secret` for `attacker-org`. `verify_signature` passes. [5](#0-4) 
- `repository.full_name` = `victim-org/victim-repo`, which is what `PushHandler`/`Handler#stacks` actually uses to look up the `Repository` and its `Stack`s: `Repository.from_github_repo_name(repository_name)&.stacks`. [3](#0-2)  `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the target branch, with `after` also fully attacker-controlled. [6](#0-5) 

Because the signature only proves "signed by `attacker-org`'s secret," and the handler never re-checks that `victim-org/victim-repo` is actually owned by `attacker-org`, the attacker forges a push event for a repository/stack they do not own, causing Shipit to sync/deploy against a fabricated `after` SHA for a stack that belongs to a different, unrelated GitHub organization. The same architecture affects other handlers keyed off `repository.full_name` (PR opened/closed/labeled handlers, status handler, check_suite handler), and the membership handler which is keyed off the org login used purely for team bookkeeping — but the push path is the most impactful because it drives `sync_github`/deploy machinery.

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" binding explicitly called out as in-scope. A party that legitimately controls only their own org's GitHub App/webhook secret gains the ability to inject synthetic GitHub events (push, PR, status, check_suite) against a completely different organization's repositories/stacks on the same Shipit instance, since only the org identity is verified and the repository identity used for mutation is not cross-checked. On a single-org deployment this is not exploitable (there is only one secret and only one org's repos exist), but the code path and documented multi-org configuration schema make this a real cross-tenant boundary violation in shared/multi-org installs, which the engine explicitly supports (`Shipit.github(organization:)` and the documented multi-org `secrets.yml` shape).

### Likelihood Explanation
Requires the instance to be configured for multiple GitHub organizations (a documented, supported configuration) and requires the attacker to control (as an org admin) one of the onboarded orgs' GitHub Apps/webhook secrets — a credential they legitimately hold for their own org, not a stolen victim secret. Given that, forging the request is trivial (a single signed HTTP POST to `/webhooks` with crafted JSON).

### Recommendation
In `WebhooksController#verify_signature`/`create`, after verifying the signature, assert that the resolved `repository_owner` organization actually matches the owning organization of `repository.full_name` (and of `organization.login` for org-scoped events) before dispatching to handlers. Equivalently, resolve the target `Repository`/`Stack` first and verify the signature using the secret configured for that repository's actual owner, rejecting any event whose declared `repository_owner` does not match the owner segment of `repository.full_name`.

### Proof of Concept
1. Configure Shipit with two orgs, `attacker-org` and `victim-org`, each with distinct `webhook_secret`s (as supported by `config/secrets.development.shopify.yml` schema).
2. Victim-org has a Shipit `Stack` tracking `victim-org/victim-repo` on branch `main`.
3. Attacker crafts payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": { "full_name": "victim-org/victim-repo", "owner": { "login": "attacker-org" } }
}
```
4. Attacker computes `X-Hub-Signature` using `attacker-org`'s own `webhook_secret` over the raw body, and sends `POST /webhooks` with `X-Github-Event: push`.
5. `verify_signature` resolves `Shipit.github(organization: "attacker-org")` and validates the signature successfully. [5](#0-4) 
6. `PushHandler` resolves stacks via `repository.full_name` = `victim-org/victim-repo` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` for the victim's stack. [7](#0-6)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"

    rescue Shipit::GithubOrganizationUnknown => e

    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
