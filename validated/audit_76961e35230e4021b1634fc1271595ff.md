### Title
Alpenglow per-epoch stake reward permanently truncated to zero for small stake accounts due to integer division precision loss - (File: `runtime/src/inflation_rewards/points.rs`, `runtime/src/inflation_rewards/mod.rs`)

### Summary
In Alpenglow epochs, `calculate_alpenglow_points` computes a delegator's earned reward via truncating integer division `earned_credits * stake_amount / total_stake`. When an individual delegation's stake is small relative to the vote account's total delegated stake for the reward epoch, this division rounds down to zero. Unlike the Tower path, which defers (does not advance `credits_observed`) when a computed value rounds to zero so the delegator can accumulate and be paid later, the Alpenglow path unconditionally advances `credits_observed` even when the reward is zero, permanently forfeiting that epoch's reward for the delegator.

### Finding Description
`calculate_alpenglow_points` in [1](#0-0)  computes:
```
earned_points = earned_credits * stake_amount / total_stake
```
This is a single truncating division over `u128` values with no minimum/scaling safeguard, directly analogous to the reported `long_utilization = base_interest / (base_reserve / 100)` truncation that produces a zero utilization (and thus zero funding fee) whenever the numerator is small relative to the denominator.

In `calculate_stake_rewards`, the Alpenglow branch treats `ag_points` (in Alpenglow, points *are* the actual lamport reward — see the comment at [2](#0-1) ) and if it is zero, calls `skip_reward(SkippedReason::ZeroPoints)`: [3](#0-2) 

The critical distinction is in `advance_credits_for_skipped_reward`:
```
let advance_credits_for_skipped_reward =
    !is_tower_epoch && new_credits_observed != stake.credits_observed;
```
For Tower epochs (`is_tower_epoch == true`), this is always `false`, so `skip_reward` returns `None`, meaning `credits_observed` is *not* advanced and the un-rewarded credits remain available to be counted (and potentially cross the rounding threshold) in a future epoch. For Alpenglow epochs (`is_tower_epoch == false`), whenever new credits were earned (`new_credits_observed != stake.credits_observed`, which is normally true every epoch a validator votes), `advance_credits_for_skipped_reward` is `true`, so `skip_reward` calls `skipped_reward()`: [4](#0-3) 
which returns `CalculatedStakeRewards { staker_rewards: 0, voter_rewards: 0, new_credits_observed }` — i.e., `credits_observed` is moved forward to the latest value even though zero reward was paid. This permanently discards the fractional reward the delegator earned for that epoch's credits window, rather than deferring it for accumulation as Tower does.

This precision-loss condition is systematically reachable: any delegator whose `stake` is small relative to the vote account's total `RewardEpochDelegatedStakes` for that epoch (e.g., a large validator with many small delegators, or a newly-activated small delegation) will compute `earned_credits * stake_amount / total_stake == 0` and lose that epoch's reward outright, every epoch, indefinitely — mirroring the "long_utilization is zero until base_reserve/100 >= base_interest" condition in the report.

### Impact Explanation
Small unprivileged stake-account holders permanently and repeatedly lose inflation rewards they are legitimately entitled to under Alpenglow, since the truncation happens every epoch and credits are advanced regardless, with no mechanism to recover or accumulate the lost fractional reward (in contrast to Tower's deferral behavior). Over many epochs this compounds into a durable, systemic underpayment for a class of legitimate stakers — a reward-distribution correctness bug causing permanently forfeited lamports for affected delegators, analogous to the "1% loss" quantified in the referenced report.

### Likelihood Explanation
This requires no attacker action or privileged role — any legitimate small delegation relative to its vote account's total active stake in a reward epoch triggers it deterministically. Because vote-account total stakes for large validators are commonly orders of magnitude larger than individual small delegations, this is a realistic and recurring condition, not a contrived edge case.

### Recommendation
Scale up the numerator (e.g., use higher fixed-point precision, or scale `earned_credits`/`stake_amount` before dividing) in `calculate_alpenglow_points`, and/or apply the same "defer rather than permanently advance credits" semantics used by Tower to the Alpenglow zero-points case so that small delegators' fractional rewards can accumulate across epochs instead of being irrecoverably dropped when `advance_credits_for_skipped_reward` is true.

### Proof of Concept
Given (matching the escalated report's proportions):
- `stake_amount = 1` (small delegation)
- `total_stake = 1_000_000` (large vote account total stake for the epoch)
- `earned_credits = 500_000` (half of max per-epoch credits)

`earned_points = 500_000 * 1 / 1_000_000 = 0` (rounds down from 0.5).

In `calculate_stake_rewards`, `ag_points == 0` triggers `skip_reward(SkippedReason::ZeroPoints)`; since this is an Alpenglow (non-Tower) epoch and `new_credits_observed != stake.credits_observed` (credits did advance because the validator voted), `advance_credits_for_skipped_reward` is `true`, so the function returns `Some(CalculatedStakeRewards { staker_rewards: 0, voter_rewards: 0, new_credits_observed })`. The delegator's `credits_observed` is bumped forward with zero payout, permanently losing that epoch's reward, exactly analogous to the referenced `funding_paid = 0` result from truncated `long_utilization`.
