### Title
Unbounded stake-account count inflates per-block epoch-reward distribution work despite `MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH` partition cap - ([File: runtime/src/bank/partitioned_epoch_rewards/mod.rs])

### Summary
`get_reward_distribution_num_blocks` caps the *number* of reward-distribution blocks/partitions to at most 10% of `slots_per_epoch`, but does not cap the *number of stake accounts per partition*. Once the attacker-controlled delegation count exceeds `partitioned_rewards_stake_account_stores_per_block * (slots_per_epoch/10)`, additional stake accounts are folded into the same fixed number of partitions, so the per-block store work in `store_stake_accounts_in_partition` grows linearly with the attacker-controlled delegation count instead of staying bounded.

### Finding Description
`Bank::get_reward_distribution_num_blocks` computes: [1](#0-0) 
`num_chunks = total_stake_accounts.div_ceil(stake_account_stores_per_block)`, then clamps it to `[1, slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH]`. This clamp bounds the *number of partitions/blocks* used for distribution, which is the safety property the "10%-of-slots" comment is trying to guarantee. However, it does not bound how many stake accounts land in each partition. `hash_rewards_into_partitions` distributes all `N` stake-reward entries into exactly `num_partitions` buckets by pubkey hash: [2](#0-1) 
Once `N` (total stake delegations with a payable reward) grows past the point where `num_chunks` hits the upper clamp bound (`slots_per_epoch/10`), the number of partitions stops growing, but `N` keeps growing — so the average (and worst-case) number of stake accounts processed per partition/block in `store_stake_accounts_in_partition` (called from `distribute_epoch_rewards_in_partition`) increases roughly linearly with attacker-controlled `N`: [3](#0-2) 
This breaks the implicit invariant that per-block distribution work is bounded independent of attacker-controlled account/delegation count, once `N` exceeds the clamp threshold.

The only economic control on this is the minimum delegation amount, enforced in `get_minimum_delegation` (1 SOL once the relevant feature is active, or as low as 1 lamport pre-feature) plus the stake account's rent-exempt reserve: [4](#0-3) 
This is a capital cost, not a protocol-level bound on `N` — a sufficiently funded attacker can still create an arbitrarily large number of minimum-delegation stake accounts before the reward-calculation-epoch snapshot, each contributing one entry to `hash_rewards_into_partitions`, inflating per-block distribution work above the fixed `stake_account_stores_per_block` baseline that the per-block budget is designed around.

### Impact Explanation
This is an epoch-boundary processing-time blow-up risking degraded liveness (each distribution block does proportionally more work storing stake accounts than the `MAX_PARTITIONED_REWARDS_PER_BLOCK` baseline assumes), adjacent to reward-accounting correctness rather than being classified as RPC/gossip DoS, since it's triggered purely through normal stake-delegation instructions processed as part of consensus-critical epoch-boundary bank processing.

### Likelihood Explanation
Feasibility is gated by capital cost: each stake account requires at least the minimum delegation (1 SOL, post-feature-activation) plus rent-exempt reserve, so inflating `N` to values large enough to exceed the `slots_per_epoch/10` partition-count clamp requires proportionally large SOL outlay (this stake is not lost, merely locked/delegated), making the attack economically bounded but not protocol-bounded — a well-capitalized actor can still realize the effect, and the attack is fully repeatable every epoch by maintaining or re-delegating the stake accounts.

### Recommendation
Cap the number of stake accounts processed per distribution block independent of total delegation count — e.g., derive `num_partitions` so that `total_stake_accounts / num_partitions` never exceeds `stake_account_stores_per_block`, and instead allow `num_partitions` (and thus the distribution period, bounded elsewhere) to grow, or explicitly reject/queue excess entries into additional distribution blocks beyond the `slots_per_epoch/10` clamp with a documented, tested worst-case per-block account limit that is enforced regardless of total delegation count.

```rust
#[test]
fn test_reward_distribution_partition_size_unbounded_with_delegation_count() {
    let (mut genesis_config, _mint_keypair) = create_genesis_config(1_000_000 * LAMPORTS_PER_SOL);
    genesis_config.epoch_schedule = EpochSchedule::custom(432_000, 432_000, false);

    let mut accounts_db_config: AccountsDbConfig = ACCOUNTS_DB_CONFIG_FOR_TESTING;
    // baseline per-block store budget
    accounts_db_config.partitioned_epoch_rewards_config =
        PartitionedEpochRewardsConfig::new_for_test(4096);

    let bank = Bank::new_from_genesis(
        &genesis_config,
        Arc::new(RuntimeConfig::default()),
        Vec::new(),
        None,
        accounts_db_config,
        None,
        Some(SlotLeader::new_unique()),
        Arc::default(),
        None,
        None,
    );

    let stake_account_stores_per_block =
        bank.partitioned_rewards_stake_account_stores_per_block();
    let max_partitions = genesis_config.epoch_schedule.slots_per_epoch / 10;
    // threshold at which num_partitions saturates
    let threshold = stake_account_stores_per_block * max_partitions;

    // Simulate an attacker-controlled delegation count far beyond threshold,
    // e.g. 10x over.
    let attacker_n = threshold * 10;

    let stake_rewards = (0..attacker_n)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect::<PartitionedStakeRewards>();

    let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);

    // Invariant under test: num_blocks stays capped ...
    assert_eq!(num_blocks, max_partitions);

    // ... but per-partition size (average) now vastly exceeds the
    // configured per-block store budget, violating the assumption that
    // per-block work is bounded independent of attacker-controlled N.
    let avg_accounts_per_block = attacker_n / num_blocks as usize;
    assert!(
        avg_accounts_per_block > stake_account_stores_per_block as usize,
        "expected per-block work ({avg_accounts_per_block}) to exceed the configured \
         per-block budget ({stake_account_stores_per_block}), demonstrating unbounded \
         growth with attacker-controlled delegation count"
    );
}
```
Expected result: the assertion on `avg_accounts_per_block` passes, demonstrating that `num_blocks`/`num_partitions` saturates at the `slots_per_epoch/10` cap while the per-block/per-partition stake-account processing load keeps growing proportionally to the attacker-controlled delegation count `N`, contradicting the intended fixed per-block budget (`MAX_PARTITIONED_REWARDS_PER_BLOCK` / `stake_account_stores_per_block`).

```rust
    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }
```

```rust
pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}
```
