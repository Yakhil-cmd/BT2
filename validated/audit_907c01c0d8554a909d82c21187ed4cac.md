### Title
Cross-tenant webhook forgery via decoupled organization selection between `WebhooksController#verify_signature` and `Repository.from_github_repo_name` full_name owner - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the GitHub App / `webhook_secret` to validate the HMAC signature using `params.dig('repository','owner','login')`, while `LabeledHandler#repository` (and the other PR handlers) resolve the mutated `Repository`/`Stack` using `params.dig('repository','full_name')`. These two fields are never checked for consistency, so an attacker who controls both fields in the JSON body can pick which organization's secret authenticates the request while a *different* organization's repository/stack is the one actually mutated.

### Finding Description
The required binding for safety is:
`org_used_for_signature = params.dig('repository','owner','login')` must equal `org_embedded_in_repo = params.dig('repository','full_name').split('/').first`.

Tracing the code:
- `verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and calls `Shipit.github(organization: repository_owner)` to fetch the `GitHubApp` (and thus the `webhook_secret`) used to validate `X-Hub-Signature` against the raw body. [1](#0-0) 
- `GitHubApp#verify_webhook_signature` explicitly returns `true` when no `webhook_secret` is configured for that organization: `return true unless webhook_secret`. [2](#0-1) 
- Once the request passes `verify_signature`, `WebhooksController#create` dispatches the *entire raw payload* (unchanged) to the handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [3](#0-2) 
- `LabeledHandler#repository` (and `OpenedHandler`, `UnlabeledHandler`, `ClosedHandler`) resolve the actual `Repository`/`Stack` to mutate using `params.repository.full_name`, completely independent of `params.repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [4](#0-3) 
- `Repository.from_github_repo_name` simply splits the string on `/` and looks up by `owner`/`name` columns with no cross-check to the webhook's authenticated organization. [5](#0-4) 

Root cause: the controller authenticates the request against the organization named in `repository.owner.login`, but the handler layer mutates state for the organization named in `repository.full_name`. Nothing forces these two attacker-supplied strings to agree. If any organization configured on the Shipit instance has no `webhook_secret` set (a state explicitly supported by `verify_webhook_signature`'s `return true unless webhook_secret` fallback, documented as backward compatibility), an attacker can set `repository.owner.login` to that organization (satisfying `verify_signature` trivially) while setting `repository.full_name` to `victim-org/target-repo` (a fully-secured, unrelated organization). The signature check passes because it only validated against the secret-less organization; the mutation then proceeds against the victim organization's `Stack`/`Repository`.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type is registered; `ExplicitParameters` schemas in the handlers (`requires :repository do requires :full_name, String end`) only validate types/presence, never cross-reference `owner.login`; `Repository` validations only constrain the owner/name character format, not correspondence to the authenticated organization; there is no `force_github_authentication`/session check involved since this is the unauthenticated `/webhooks` endpoint by design.

### Impact Explanation
A successful forged request against `POST /webhooks` with event `pull_request` and action `labeled`/`unlabeled` causes `Stack#archive!` or `Stack#unarchive!` to run for a review stack belonging to a target organization the attacker never authenticated against, and via `OpenedHandler`/`ClosedHandler` the same decoupling allows creating or archiving review stacks for arbitrary repositories. This is a payload for one tenant/organization mutating another tenant's stack state without possessing that tenant's credentials — matching the Critical category "a payload for one repository mutating another's stack." The attack is repeatable against any victim repository whose `owner/name` is known, as long as one organization on the instance has an unset `webhook_secret`.

### Likelihood Explanation
Exploitation requires: (1) the Shipit instance hosts multiple GitHub organizations via the multi-org `secrets.github.<org>` config, and (2) at least one configured organization has no `webhook_secret` set — a state the code explicitly tolerates rather than rejects. Given that state, the attacker needs no session, no API token, and no actual secret; they only need to know the login of the secret-less organization (which may be discoverable, e.g., a demo/staging org, or an org onboarded before a secret was set) and the `owner/name` of the victim repository. The attack costs a single crafted HTTP POST, is fully repeatable, and requires no interaction with GitHub at all (no PR is even needed — the payload is synthetic). This preconditions on a specific operational misconfiguration (an org without a secret), so likelihood depends on deployment configuration, but the code path itself provides no defense-in-depth against it.

### Recommendation
Bind the authenticated organization to the organization actually used for mutation before dispatching to handlers: after `verify_signature` succeeds, derive `repository_owner` and independently derive the owner segment of `params.dig('repository','full_name')`, and reject the request (`head 422`) if they differ. Alternatively, do not allow any organization to be configured without a `webhook_secret` (remove or make opt-in-only-for-non-production the `return true unless webhook_secret` fallback in `GitHubApp#verify_webhook_signature`), and additionally verify in `verify_signature` that `repository.owner.login` matches `repository.full_name`'s owner segment.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_cross_tenant_test.rb
require 'test_helper'

module Shipit
  class WebhooksControllerCrossTenantTest < ActionController::TestCase
    tests WebhooksController

    test "forged pull_request payload with mismatched owner.login vs full_name mutates the wrong org's stack" do
      victim_stack = shipit_stacks(:shipit) # repository full_name e.g. "shopify/shipit-engine"
      victim_repo = victim_stack.repository
      assert_equal 'shopify', victim_repo.owner

      # Simulate an organization ("attacker-org") configured with NO webhook_secret,
      # per GitHubApp#verify_webhook_signature's `return true unless webhook_secret`.
      attacker_org_app = Shipit.github(organization: 'attacker-org')
      attacker_org_app.stubs(:webhook_secret).returns(nil)

      payload = {
        action: 'labeled',
        number: 1,
        pull_request: {
          id: 1, number: 1, url: 'https://api.github.com/x', title: 't', state: 'open',
          additions: 1, deletions: 1,
          head: { sha: 'abc', ref: 'feature-branch' },
          user: { login: 'attacker' },
          assignees: [],
          labels: [{ name: 'shipit:provision' }]
        },
        repository: {
          owner: { login: 'attacker-org' },      # value A: used by verify_signature
          full_name: victim_repo.full_name        # value B: used by LabeledHandler#repository
        },
        sender: { login: 'attacker' }
      }.to_json

      @request.headers['X-Github-Event'] = 'pull_request'
      @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary, never validated for attacker-org

      assert_changes -> { victim_stack.reload.archived? } do
        post :create, body: payload, as: :json
      end

      assert_response :ok
    end
  end
end
```

Both sides of the equality diverge in this PoC (`owner.login == "attacker-org"` vs `full_name owner == "shopify"`), `verify_signature` passes solely because `attacker-org`'s `webhook_secret` is nil, and `LabeledHandler#repository` mutates the `shopify`-owned `victim_stack` — confirming the broken binding.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',

        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",

    rescue Shipit::GithubOrganizationUnknown => e

        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
