### Title
`GitHubApp#verify_webhook_signature` unconditionally accepts unsigned/forged webhooks when an org's `webhook_secret` is unset - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#verify_webhook_signature` returns `true` immediately whenever the org-specific `webhook_secret` is blank, before ever inspecting the `X-Hub-Signature` header or payload. In a multi-org Shipit deployment where at least one configured GitHub organization has no `webhook_secret`, any internet user can POST arbitrary, unsigned JSON to `/webhooks` naming that organization via `repository.owner.login` and have it processed as authentic.

### Finding Description
The binding this should enforce is: `verify_webhook_signature(signature, message) == true` **iff** `signature` is a valid HMAC-SHA1 of `message` under that organization's `webhook_secret`. Instead, the actual code is: [1](#0-0) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

`webhook_secret` is set from `@config[:webhook_secret].presence` at construction time, so a config entry with `webhook_secret: nil` (a documented option) makes `webhook_secret` `nil` for that `GitHubApp` instance, and the method short-circuits to `true` for **any** `signature`/`message` pair, including `nil` and an empty body.

The call path from the controller is: [2](#0-1) 

`WebhooksController#verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` is read straight from the untrusted JSON body (`params.dig('repository', 'owner', 'login')`), then calls `github_app.verify_webhook_signature(...)` and only halts the request with `422` if that returns `false`. Since it returns `true` for the no-secret org regardless of the signature, `create` proceeds and dispatches the forged payload to every registered handler for that event type: [3](#0-2) 

None of the other guards mentioned in the audit rules (`drop_unhandled_event`, `ExplicitParameters`, `force_github_authentication`, `User#authorized?`, model validators) check the webhook's authenticity — they only validate shape/format of an already-accepted payload. `drop_unhandled_event` merely filters by event type, not by authenticity, and runs *before* `verify_signature` in the `before_action` chain, so it does not block this path for handled events (push, pull_request, check_suite, membership, status).

### Impact Explanation
For the affected organization, an attacker who knows (or guesses) its login can send a completely forged webhook body naming any repository under that org, with no valid `X-Hub-Signature`, and have it dispatched to the real handlers: [4](#0-3) [5](#0-4) [6](#0-5) . Depending on the handler, this can drive stack/commit state changes, team membership sync, or CI-status-driven merge/deploy gating for that org's repositories — an authentication bypass matching the Critical category ("a payload for one repository mutating another's stack, commit, task or team" / forged webhook accepted). This is repeatable indefinitely and applies to every repository under the misconfigured organization, though it is scoped to that specific organization only (orgs with a real `webhook_secret` still verify correctly).

### Likelihood Explanation
The precondition is a legitimate, documented configuration: a multi-org `Shipit.github` setup where one org entry has `webhook_secret: nil`. Given that precondition, exploitation requires no secrets, no session, and no GitHub credentials — just an HTTP POST to `/webhooks` with a fabricated JSON body and a fabricated `repository.owner.login`. Attacker cost is negligible and the action is trivially repeatable.

### Recommendation
Do not treat a missing `webhook_secret` as "trust unconditionally." Instead, either (a) require `webhook_secret` to be present for every configured organization at boot/config-load time and fail fast if absent, or (b) change `verify_webhook_signature` to return `false` (reject) when `webhook_secret` is blank, so an org without a secret cannot receive webhooks at all rather than accepting everything unauthenticated.

### Proof of Concept
```ruby
# test/lib/shipit/github_app_test.rb (illustrative, not to be placed under out-of-scope paths per repo conventions)
test "#verify_webhook_signature returns true for unsigned/forged payloads when webhook_secret is not configured" do
  app = Shipit::GitHubApp.new('some-org', webhook_secret: nil)

  # binding under test: result should equal
  # HMAC-SHA1('anything', webhook_secret) match, but webhook_secret is nil so no comparison happens
  assert_equal true, app.verify_webhook_signature(nil, 'anything')
  assert_equal true, app.verify_webhook_signature('sha1=deadbeef', '{"forged":"payload"}')
end
```
This demonstrates that for an org configured without `webhook_secret`, the equality `verify_webhook_signature(signature, message) == valid_hmac?(signature, message, webhook_secret)` does not hold — the method returns `true` unconditionally, confirming the authentication bypass for that organization's `/webhooks` traffic.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
