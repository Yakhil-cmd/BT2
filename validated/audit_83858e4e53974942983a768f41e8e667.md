### Title
Borrow-index accrual overflows the RAY value ceiling before `MAX_BORROW_INDEX_RAY` engages, permanently freezing a whale market - (File: common/src/rates/scaling.rs)

### Summary
Analog of the CVE-2018-4119 "memory corruption → uncontrolled state" class mapped onto XOXNO Lending's RAY share/index math: interest accrual computes the borrowed value as `scaled_to_original(borrowed, borrow_index)`, an `i128` `mul` in `Ray::mul`. On a large market at sustained high utilization, `borrowed * borrow_index` overflows `i128` while `borrow_index` is still below the `MAX_BORROW_INDEX_RAY` cap. The cap therefore never engages, and because every state-changing verb calls `global_sync` first, the market can never accrue again — permanently freezing all supplier and borrower funds in that book.

### Finding Description
`accrue_step` (shared by `simulate_update_indexes` and `accrue_chunk` in `contracts/pool/src/interest.rs`) multiplies the scaled borrow position by the grown index via `scaled_to_original`, which is `scaled.mul(env, index)` (`common/src/rates/scaling.rs:14-16`). `Ray::mul` panics with `MathOverflow` when the product does not fit `i128`. The protocol's own guard — the `MAX_BORROW_INDEX_RAY` index cap — is applied to the *index*, not to `scaled * index`. A scaled borrow position can be up to ~170× the index ceiling's value domain, so for sufficiently large `borrowed`, `scaled * index` overflows at an index far below the cap. The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-362`) demonstrates exactly this: accrual panics with `MATH_OVERFLOW` while `last.borrow_index < MAX_BORROW_INDEX_RAY`, and `withdraw`/`repay` fail identically because `global_sync` runs first (`contracts/pool/src/interest.rs:20-33`). The doc comment at line 340 also notes the bound stated in `docs/reference/formulas.md` is wrong — the overflow arrives earlier than documented.

### Impact Explanation
Permanent freezing of funds. Once `borrowed * borrow_index` exceeds `i128::MAX`, every `update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `claim_revenue` call on that (hub, token) book reverts inside `global_sync` → `accrue_chunk` → `scaled_to_original`. Suppliers cannot exit and borrowers cannot repay; the book's tokens are locked forever. This is a fail-*bricked* condition, not a fail-closed revert of a single bad input — the panic poisons the entire market state with no recovery path, since the only writes that could shrink `borrowed` (repay, liquidation, bad-debt cleanup) all accrue first.

### Likelihood Explanation
Reachable by unprivileged addresses: any user can `supply`, `borrow`, and call `update_indexes`/`global_sync`. The attack requires a whale-scale market (the test uses ~1e18-decimal token supply of a billion units at 98% utilization on the steep segment of the XLM curve) and many years of compounding, or a configured curve with extreme rates. It does not require privilege, oracle manipulation, or special parameters beyond what the existing cap-lifted market config permits — the test disables the max-utilization guard, but the arithmetic cliff is independent of it. That keeps this out of "bad parameter" territory: the overflow is a missing invariant in the accrual math itself, acknowledged in-repo by the test asserting the documented bound is incorrect. Medium likelihood → Medium severity.

### Recommendation
Cap or saturate the *value* product, not just the index. In `accrue_step`/`scaled_to_original`, either (a) clamp `borrow_index` so that `borrowed * index` stays within `i128` for the current scaled position (dynamic per-book index ceiling), or (b) use a saturating multiply for the accrual path and short-circuit further index growth once saturated, while still allowing `repay`/`liquidate`/`withdraw` to proceed against the saturated value. Additionally, `clean_bad_debt`/`recapitalize` should be able to run without full accrual so a stuck book can be wound down.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
