The ksmbd CVE is a C-language memory-safety defect: a kernel object (`opinfo`) is linked into a shared list (`ci->m_op_list`) and a global lease list before all of its fields (`o_fp`) are initialized and before a fallible allocation (`add_lease_global_list`) has succeeded, so concurrent readers can dereference a freed or partially-initialized pointer. This bug class depends on manual memory management (kmalloc/RCU-deferred free) and raw pointer publication ordering that simply doesn't exist in the Polkadot SDK's Rust codebase — Rust's ownership/borrow-checker model prevents a struct from being referenced by another thread/reader before it is fully constructed, and there is no manual `free()`/RCU-deferred free path for FRAME storage or in-memory subsystem state.

I looked for a logic-level analog of "publish a partially-initialized record into a shared structure before an operation that can fail, then improperly unwind it while it's still visible to concurrent readers" reachable through a real user entrypoint (signed extrinsic, XCM, contract call). The closest structural candidate found was `HopDataPool::insert` in `substrate/client/hop/src/pool.rs`, which builds a complete `HopEntryMeta` (with all recipients/signer/signature fields) and only exposes it to readers (`get`, `claim`, `get_with_auth`, `fetch_meta`) via `commit_meta` under `rmw_lock` after the record is fully constructed [1](#0-0) . The on-disk blob is written before the metadata is committed, but since metadata is the documented "source of truth" for entry existence, a reader that doesn't find metadata simply treats the hash as not-found — there is no window where a reader can observe a metadata record with unset/default fields, unlike the ksmbd `opinfo->o_fp` NULL-deref case [2](#0-1) . No allocation-fails-after-partial-publish sequence exists here or elsewhere I could locate in FRAME/XCM/bridges reachable through an unprivileged extrinsic/XCM/contract entrypoint.

No unbacked issuance, unauthorized dispatch, freezing, or a reproducible UAF/NULL-deref analog was found; therefore no report is filed.
