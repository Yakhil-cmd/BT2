### Title
Forged GitHub webhook accepted when an organization's `webhook_secret` is blank/nil - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever the configured `webhook_secret` for the target organization is blank, regardless of the actual `X-Hub-Signature` header content. Since `WebhooksController#verify_signature` selects the `GitHubApp` instance based on attacker-controlled `repository_owner` (derived from `params.dig('organization', 'login')`), an attacker can pick any organization configured with a blank `webhook_secret` and submit a completely unsigned/forged webhook, which will be processed as if it originated from GitHub.

### Finding Description
The broken binding: `verified == true` is claimed to hold only when `request` genuinely originated from GitHub (i.e., HMAC-SHA1 of `request.raw_post` using the organization's `webhook_secret` matches `X-Hub-Signature`). In code: [1](#0-0) 

`return true unless webhook_secret` breaks this binding: if `@webhook_secret = @config[:webhook_secret].presence` is `nil` (blank secret in config), `verify_webhook_signature` returns `true` without inspecting `signature` or `message` at all. [2](#0-1) 

The controller resolves which `GitHubApp` (and therefore which `webhook_secret`) to use from attacker-controlled payload data, not from any trusted context: [3](#0-2) [4](#0-3) 

`Shipit.github(organization:)` looks up the app config by that organization name from `secrets.github`, which is exactly the map that can contain an org with `webhook_secret: nil`, as shown in the shipped example configuration pattern: [5](#0-4) [6](#0-5) 

If `verify_signature` passes, `create` dispatches the parsed body to the matching handler(s): [7](#0-6) 

For `X-Github-Event: membership`, `MembershipHandler#process` creates/finds a `Team` by `params.team.id` (an id the attacker can set to any `Shipit.github_teams` team) and, for `action: 'added'`, calls `team.add_member(member)` where `member` is created directly from attacker-supplied `params.member.login`: [8](#0-7) 

No other guard intercepts this: `drop_unhandled_event` only screens for events with no registered handler, `check_if_ping` only special-cases the `ping` event, and there is no signature-independent authentication of the caller. The divergence is real: an attacker with zero secrets can make `verified` `true` for any org they choose whose config has a blank `webhook_secret`, which the repo's own example/config pattern shows is a supported real-world configuration state, not just a hypothetical.

### Impact Explanation
This is an authentication bypass: a forged/unsigned HTTP POST to `/webhooks` results in Shipit accepting attacker-supplied membership data as authentic GitHub data, creating a `Membership` row that adds the attacker's account to any `Shipit.github_teams` team associated with the misconfigured organization. Membership in `Shipit.github_teams` is used elsewhere in the app for authorization decisions (`User#authorized?`, `require_permission!` paths), so this can escalate the attacker into privileged Shipit roles — matching both "authentication bypass (forged webhook accepted)" (Critical) and "escalation into `Shipit.github_teams` authorization" (High). The attack is repeatable at will against every organization configured this way, and is not limited to a single request.

### Likelihood Explanation
The only precondition is operator misconfiguration: at least one organization entry under `secrets.github` with a blank/nil `webhook_secret`. This is not a theoretical edge case — the repository's own shipped configuration template (`config/secrets.development.shopify.yml`) shows exactly this pattern (`webhook_secret: # nil`) for organizations, and `docs/setup.md` walks through GitHub App configuration where a webhook_secret must be explicitly filled in; if left blank, this exact bypass activates. Given no other input validation blocks this state, and the attacker needs no session, token, or secret, the practical likelihood depends entirely on whether any configured org in a given deployment has an empty `webhook_secret`, which is a plausible operational mistake rather than a contrived one.

### Recommendation
`GitHubApp#verify_webhook_signature` should never silently return `true` when `webhook_secret` is blank. Instead, either raise/fail closed (return `false`, or raise a configuration error) when `webhook_secret` is not configured, and/or add a startup/boot-time validation that refuses to run (or refuses to register that organization's webhook endpoint) if any configured organization lacks a webhook secret. At minimum, change line 77 in `lib/shipit/github_app.rb` from `return true unless webhook_secret` to `return false unless webhook_secret`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test 'membership webhook is rejected when webhook_secret is blank' do
  org = 'blank-secret-org'
  Shipit.stubs(:secrets).returns(
    ActiveSupport::InheritableOptions.new(
      github: { org => { app_id: 1, installation_id: 1, private_key: nil, webhook_secret: nil } }
    )
  )

  payload = {
    action: 'added',
    team: { id: shipit_teams(:some_team).github_id, name: 'x', slug: 'x', url: 'https://x' },
    organization: { login: org },
    member: { login: 'attacker' }
  }.to_json

  assert_no_difference -> { Shipit::Membership.count } do
    post shipit.webhooks_path, params: payload,
      headers: { 'X-Github-Event' => 'membership', 'X-Hub-Signature' => 'sha1=deadbeef', 'CONTENT_TYPE' => 'application/json' }
  end
  assert_response :unprocessable_entity # currently fails: response is 200 and Membership.count increases
end
```
This test would currently fail (asserting the vulnerable behavior: response `200` and a new `Membership`/`Team` row created) rather than the expected `422`, demonstrating the equality `verified == true` holds even though the request did not originate from GitHub.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",

    rescue Shipit::GithubOrganizationUnknown => e

        "unknown_organization=#{e.message}",

      ].join(' '))
    end
