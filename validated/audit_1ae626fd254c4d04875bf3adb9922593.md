### Title
Git-sync configures a 1-hour plaintext credential cache, keeping secrets resident in memory far longer than necessary - (File: main.go, function `SetupDefaultGitConfigs`)

### Summary
`git-sync` mirrors the "mnemonic stays in memory too long" bug class in its handling of git credentials (passwords, askpass-URL secrets, and GitHub App installation tokens). Instead of only holding credentials in memory for as long as a sync operation needs them, git-sync globally configures git's `credential.helper` to `cache --timeout 3600`, which spawns a long-lived `git-credential-cache--daemon` process that retains every credential it is given — in plaintext, over a Unix domain socket — for up to one hour after each use.

### Finding Description
During startup, `SetupDefaultGitConfigs` sets: [1](#0-0) 
```
key: "credential.helper", val: "cache --timeout 3600"
```
This configuration is applied globally (`git config --global`) before any credentials are ever stored, and it is not adjustable via any git-sync flag.

Every time git-sync obtains credentials — from `--credential`/`--password-file` (used for token rotation), from `--askpass-url` (dynamic, per-sync secrets), or from a freshly minted short-lived GitHub App installation token — it calls `StoreCredentials`, which pipes the secret straight into `git credential approve`: [2](#0-1) 

Because `credential.helper` is `cache`, `git credential approve` hands the plaintext `url=/username=/password=` triple to `git-credential-cache--daemon`, which keeps it resident in its own process memory (accessible to any process on the same host/user that can reach the daemon's Unix socket) for the full `--timeout 3600` window, regardless of how quickly git-sync itself is done using it. This applies to all three credential-refresh code paths:

- Static `--credential`/password-file rotation: [3](#0-2) 
- `--askpass-url` dynamic per-sync secrets: [4](#0-3) 
- GitHub App short-lived tokens, whose own server-side lifetime is only 10 minutes: [5](#0-4)  yet the local cache still exposes the same token in cleartext for up to an hour: [6](#0-5) 

This exactly parallels the audited report's root cause: sensitive secret material (there, a mnemonic; here, a password/token) is kept resident in an unprotected, in-memory form for far longer than the operation that needed it, widening the window in which a crash dump, `ptrace`/core-dump inspection, or any local process capable of talking to the cache daemon's socket can recover the plaintext credential — even for the GitHub App case where the origin token itself was designed to be short-lived precisely to limit this exposure.

### Impact Explanation
If an attacker obtains local access to the git-sync container/pod during the cache lifetime (e.g., via a shared debug sidecar, a crash/core-dump collector, or any process capable of reaching the `git-credential-cache--daemon` socket), they can retrieve the plaintext repository credentials or the GitHub App installation token well after git-sync itself finished using them — up to 3600 seconds later — even though the underlying token may have already been intentionally scoped/rotated to expire in 10 minutes. This is a credential/token disclosure risk that undermines the short-lived-token security model documented for GitHub App auth.

### Likelihood Explanation
No attacker-controlled repo content or ref manipulation is required to trigger this; it is a permanent, default-on behavior of every git-sync invocation that uses username/password, askpass-url, or GitHub App authentication. Any operator running git-sync with these auth modes is affected, and the only additional requirement for exploitation is any form of local access to the process's environment during the 1-hour cache window (e.g., crash reporting, shared debugging tooling, or another local process/user sharing the credential-cache socket) — a materially lower bar than compromising git-sync itself.

### Recommendation
Do not cache credentials for a full hour by default. Use `credential.helper` with `cache --timeout` set to the minimum value needed to complete a single fetch/clone (or use a one-shot, non-caching helper such as feeding credentials via `git credential approve` immediately before use and `git credential reject`/erasing them immediately after each sync). Where GitHub App tokens or askpass-url secrets are refreshed, explicitly purge the previous cached entry (`git credential reject`) as soon as the new one is stored, and align the cache TTL with the actual token lifetime rather than a fixed 3600-second default.

### Proof of Concept
1. Run git-sync with `--github-app-*` flags (or `--askpass-url`) so `RefreshGitHubAppToken`/`CallAskPassURL` calls `StoreCredentials`, which pipes the secret into `git credential approve` under the globally configured `credential.helper = cache --timeout 3600` set by `SetupDefaultGitConfigs`.
2. Observe that a `git-credential-cache--daemon` process is spawned and remains running, holding the plaintext username/password (or GitHub App token) in memory.
3. From any local process/user able to reach the daemon's Unix socket (default `~/.cache/git/credential/socket`), run `echo "url=<repo-url>" | git credential fill` at any point within the 3600-second window — including well after the GitHub App token's own 10-minute server-side expiry — and observe the plaintext credential/token is returned, demonstrating retention far beyond the window in which git-sync itself needed it.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

// CallAskPassURL consults the specified URL looking for git credentials in the
// response.
//
// The expected URL callback output is below,
// see https://git-scm.com/docs/gitcredentials for more examples:
//
//	username=xxx@example.com
//	password=xxxyyyzzz
func (git *repoSync) CallAskPassURL(ctx context.Context) error {
	git.log.V(3).Info("calling auth URL to get credentials")

	var netClient = &http.Client{
		Timeout: time.Second * 1,
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	httpReq, err := http.NewRequestWithContext(ctx, http.MethodGet, git.authURL, nil)
	if err != nil {
		return fmt.Errorf("can't create auth request: %w", err)
	}
	resp, err := netClient.Do(httpReq)
	if err != nil {
		return fmt.Errorf("can't access auth URL: %w", err)
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusOK {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("auth URL returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("auth URL returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}
	authData, err := io.ReadAll(resp.Body)
	if err != nil {
		return fmt.Errorf("can't read auth response: %w", err)
	}

	username := ""
	password := ""
	for line := range strings.SplitSeq(string(authData), "\n") {
		keyValues := strings.SplitN(line, "=", 2)
		if len(keyValues) != 2 {
			continue
		}
		switch keyValues[0] {
		case "username":
			username = keyValues[1]
		case "password":
			password = keyValues[1]
		}
	}

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil
}

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
