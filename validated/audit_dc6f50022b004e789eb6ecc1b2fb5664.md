### Title
`GitHubApp#verify_webhook_signature` fails open when `webhook_secret` is unset, letting unsigned payloads bypass `WebhooksController#verify_signature` - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` immediately whenever the resolved organization's config has no `webhook_secret`, and `WebhooksController#verify_signature` treats that `true` as proof of authenticity. Because the organization used for verification is derived directly from attacker-controlled JSON (`repository.owner.login` / `organization.login`), any org entry in `secrets.github` that lacks a `webhook_secret` becomes a fully open, unauthenticated event-injection point for every repository nominally under that org name.

### Finding Description
The broken binding is: for the webhook to be treated as authentic, `webhook_secret.present?` for the resolving org must be `true`. In the code, `verify_signature` calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [1](#0-0)  and `repository_owner` is read straight out of the untrusted JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [2](#0-1) .

Inside `GitHubApp#verify_webhook_signature`, the guard `return true unless webhook_secret` makes verification vacuously pass for any org config where `webhook_secret` is blank [3](#0-2) , with `webhook_secret` itself set from `@config[:webhook_secret].presence` at construction time [4](#0-3) .

`Shipit.github` resolves the org config from `secrets.github` by downcased key lookup, raising `GithubOrganizationUnknown` only if the org name is entirely absent from the secrets file [5](#0-4) . If that org key exists but was configured without `webhook_secret`, no exception is raised and `verify_webhook_signature` returns `true` unconditionally, regardless of the actual `X-Hub-Signature` header or body content.

Once `verified` is `true`, `create` parses the raw body and dispatches it to every registered handler for the event type: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [6](#0-5) . Handlers (push, pull_request, status, check_suite, membership, etc.) then act on the attacker-supplied `repository.full_name`, branch, labels, commit SHAs, etc., as if they came from GitHub itself — none of them re-verify the HMAC signature or the sender's identity.

Existing guards do not prevent this divergence: `drop_unhandled_event` only checks that a handler exists for the event type, not the payload's authenticity; the `GithubOrganizationUnknown` rescue only fires when the org name doesn't exist in `secrets.github` at all, not when it exists without a secret; there is no model-level or `ExplicitParameters` check that ties an inbound webhook to a signature-verified identity independent of `verify_webhook_signature`.

### Impact Explanation
For any organization entry in `secrets.github` missing `webhook_secret`, an attacker can POST arbitrary JSON to `/webhooks` with any `X-Github-Event` header and any `repository.full_name` under that org's name, and every matching handler will execute against that fabricated payload — e.g. spoofed `push`, `pull_request`, or `status` events that can move a stack's `deployed_revision`, add/remove PR labels tracked for review-stack provisioning, or trigger stack/task state changes for a repository the attacker does not own. This is repeatable against every repository nominally under that org and is not scoped to a single tenant — it is a full authentication bypass of the webhook ingestion pipeline for that org, matching the "Critical - authentication bypass (forged webhook ... accepted) / a payload for one repository mutating another's stack, commit, task or team" category.

### Likelihood Explanation
The precondition is that the Shipit operator has configured at least one entry in `secrets.github` without a `webhook_secret` (a real, documented but easy-to-miss misconfiguration, since `webhook_secret` is not enforced as mandatory anywhere in `lib/shipit.rb` or `GitHubApp`). Given that precondition, the attacker needs zero Shipit credentials, no GitHub App keys, and no session — only the ability to send an unauthenticated HTTP POST to the public `/webhooks` endpoint, which is explicitly in scope for this audit. The attack is trivially repeatable and requires no timing or race conditions.

### Recommendation
Change `GitHubApp#verify_webhook_signature` to fail closed rather than fail open: if `webhook_secret` is blank, reject the signature (return `false`) unless a deliberate, explicitly-flagged "insecure/legacy" mode is configured and logged loudly. At minimum, add a startup-time validation that every org registered in `secrets.github` (and the legacy single-org config) must define a non-blank `webhook_secret`, raising a configuration error otherwise, so this state can never exist in a running instance.

```ruby
test "#verify_webhook_signature returns true with no signature when webhook_secret is blank" do
  app = Shipit::GitHubApp.new('org-without-secret', {})
  assert_equal true, app.verify_webhook_signature(nil, 'anything')
  assert_equal true, app.verify_webhook_signature('sha1=deadbeef', 'anything-else')
end

# test/controllers/webhooks_controller_test.rb (integration proof)
test "#create processes an unsigned payload for an org missing webhook_secret" do
  Shipit.stubs(:github).with(organization: 'org-without-secret').returns(
    Shipit::GitHubApp.new('org-without-secret', {}) # no webhook_secret key
  )
  handler = mock('handler')
  handler.expects(:call).once
  Shipit::Webhooks.stubs(:for_event).returns([handler])

  post :create,
    body: { repository: { full_name: 'org-without-secret/victim-repo', owner: { login: 'org-without-secret' } } }.to_json,
    headers: { 'X-Github-Event' => 'push' } # no X-Hub-Signature header at all

  assert_response :ok # handler.call was invoked despite zero signature
end
```
Both sides of the binding diverge: `webhook_secret.present?` is `false` for `org-without-secret`, yet `verified` is `true` and the handler pipeline runs on an entirely unsigned, attacker-controlled body.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
