### Title
Hard 8 KB truncation in `build_refute_prompt` lets an attacker-sized diff push the flagged vulnerability out of the self-refute window, causing legitimate false-negative suppression - (File: `plugins/security-guidance/hooks/review_api.py`)

### Summary
`build_refute_prompt` truncates the diff text to `diff_text[:8000]` with no per-file anchoring or guarantee that the flagged candidate's actual diff hunk is included in that window, while stage 1 (`build_investigate_prompt`/`cap_diff_for_prompt`) allows up to `DIFF_TOTAL_BYTES=400000` bytes of diff to reach the same candidates. An attacker who controls diff content (extra files, verbose additions, or ordering) can push their dangerous `+` line past the 8000-character cutoff, causing the adversarial refute model to correctly-but-wrongly apply its own "PRE-EXISTING: the cited vulnerableCode does NOT appear on any + line in the DIFF block above" rule and drop a true finding.

### Finding Description
Stage 1 investigation builds its prompt via `cap_diff_for_prompt`, allowing each file up to `DIFF_PER_FILE_BYTES` (80 KB) and the whole diff up to `DIFF_TOTAL_BYTES` (400 KB) [1](#0-0) , so a large but plausible diff comfortably produces candidate findings from files/hunks anywhere within that 400 KB budget.

Stage 2, `build_refute_prompt`, re-embeds only the first 8000 characters of the same `diff_text` when asking the model to adversarially disprove each candidate: [2](#0-1) 

The refute instructions explicitly tell the model to REFUTE a candidate when its `vulnerableCode` "does NOT appear on any + line in the DIFF block above — it is unchanged context in a touched file. The diff did not introduce it": [3](#0-2) 

Because the 8000-char slice is a raw substring cut with no per-file boundary awareness (unlike `cap_diff_for_prompt`, which truncates per file and inserts explicit truncation markers [4](#0-3) ), a diff whose vulnerable hunk sits after byte 8000 (e.g., because earlier files in the diff are large, or because there are many other touched files/hunks preceding it) will have that hunk silently absent from the refute prompt's `DIFF:` block. The refute model, following its own explicit rule, will then legitimately conclude "PRE-EXISTING" and refute a true, freshly-introduced vulnerability. The identical unguarded `diff_text[:8000]` pattern is duplicated in the inline `agentic_review` implementation in `llm.py`: [5](#0-4) .

No existing check re-verifies that a refuted "PRE-EXISTING" candidate's cited code was actually present in the (uncapped) diff before honoring the refutation; `_intersects_diff`'s anchoring runs before self-refute and only tags `in_diff`/`off_diff`, it does not protect the refute prompt's own truncated view from mismatching stage 1's fuller view [6](#0-5) .

### Impact Explanation
Because `filter_mode` defaults to `self_refute` [7](#0-6) , and the self-refute result (`survived`) is precisely what gets surfaced/blocked on for the agentic commit/Stop-hook review, an attacker who can shape the reviewed diff (e.g., a coding agent working on a large task, or a crafted PR) can cause a genuinely dangerous newly-introduced sink to be dropped from the findings list solely due to prompt truncation ordering, not due to any actual absence of risk. This directly undermines the "truncation must not consistently drop the high-risk lines the user expects to be reviewed" invariant, and can let a real vulnerability (SSRF, injected shell/eval sink, auth bypass, etc.) pass the security-guidance gate undetected, matching a "wrong-target mutation with real security impact" class of bounty impact — the review model is deceived into skipping enforcement it was designed to perform.

### Likelihood Explanation
This requires no privilege beyond normal ability to produce a diff that the agentic reviewer processes (i.e., ordinary repository/session content that Claude Code or an agent is already reviewing) — well within the "unprivileged attacker" scope. It is deterministic and reproducible: any diff whose stage-1-flagged hunk lies beyond the 8000-character offset of `diff_text` will hit this behavior every time the pipeline runs `self_refute`, since the substring cut is unconditional and independent of which file/line the candidate cites.

### Recommendation
Make the stage-2 refute prompt file-anchored rather than a blind byte-offset cut: for each candidate, ensure the diff hunk for its `filePath` is included (even if other unrelated files are truncated first), analogous to `cap_diff_for_prompt`'s per-file truncation with explicit markers. At minimum, prioritize/never-truncate-away hunks belonging to files referenced by any stage-1 candidate before applying the total-byte cap, and/or raise the refute-stage budget to match `DIFF_TOTAL_BYTES` so stage 1 and stage 2 see a consistent diff view.

### Proof of Concept
Unit test plan for `build_refute_prompt`:
1. Construct `diff_files` with a large decoy file (e.g., 9000 bytes of benign `+` lines) followed by a small file containing one dangerous `+` line (e.g., `+os.system(user_input)`).
2. Run stage 1 (`build_investigate_prompt`/investigate) to obtain a candidate citing the dangerous line as `vulnerableCode` (or construct the candidate dict directly to isolate `build_refute_prompt`).
3. Call `build_refute_prompt(candidates, diff_text)` where `diff_text` is the joined diff exceeding 8000 characters before the dangerous line appears.
4. Assert that the dangerous `+` line does NOT appear in the returned prompt string (i.e., `"os.system(user_input)" not in build_refute_prompt(...)`), proving the candidate's anchoring evidence is unavailable to the refute model even though it was legitimately introduced in the diff — demonstrating the truncation will force a PRE-EXISTING refutation of a true positive.
5. (Integration variant) Run the full `agentic_review` self-refute path with a mocked `_run` that inspects the prompt it receives and asserts the dangerous file's diff block is present/absent to confirm end-to-end behavior.

    # Mechanical pre-existing filter: drop findings whose cited vulnerableCode
    # does NOT intersect any +-line in the diff. Investigate reads full files
    # and often flags pre-existing patterns in unchanged context; this is the
    # single largest false-positive source. String match on
    # normalized whitespace; keep if any non-trivial token from the cited code
    # appears on a +-line (lenient — only drops obvious unchanged-context hits).
    if os.environ.get("SG_AGENTIC_DIFF_INTERSECT") != "0":
        added = [ln[1:] for ln in diff_text.splitlines()
                 if ln.startswith("+") and not ln.startswith("+++")]
        removed = [ln[1:] for ln in diff_text.splitlines()
                   if ln.startswith("-") and not ln.startswith("---")]

        def _norm(s: str) -> str:
            return " ".join(t for t in " ".join(s.split()).split() if len(t) > 2)

        added_norm = _norm("\n".join(added))
        removed_norm = _norm("\n".join(removed))

        def _intersects_diff(cand: Dict[str, Any]) -> bool:
            vc_raw = " ".join(str(cand.get("vulnerableCode") or "").split())
            vc = _norm(vc_raw)
            if len(vc) < 8:
                return True
            # 1) vc 3-gram appears in + lines (original check, now symmetric norm)
            toks = vc.split()
            for i in range(max(1, len(toks) - 2)):
                if " ".join(toks[i:i + 3]) in added_norm:
                    return True
            # 2) any individual + line (≥8 chars) is contained in vc — handles
            #    "investigate cites whole block, diff added one list item"
            for ln in added:
                ln_n = _norm(ln)
                if len(ln_n) >= 8 and ln_n in vc:
                    return True
            # 3) deletion-aware: vc tokens match REMOVED lines and there are
            #    fewer + than - lines in the diff — vuln introduced by removing
            #    a guard. Keep so self-refute can adjudicate.
            if len(added) < len(removed):
                for i in range(max(1, len(toks) - 2)):
                    if " ".join(toks[i:i + 3]) in removed_norm:
                        return True
            return False

        # SOFT intersect: tag instead of drop. Non-intersecting candidates
        # reach self-refute with a `_diff_anchor` flag so the refute pass
        # can apply higher scrutiny without hard-dropping correct findings
        # that cite off-diff sinks.
        for c in candidates:
            c["_diff_anchor"] = "in_diff" if _intersects_diff(c) else "off_diff"
        metrics["pre_existing_dropped"] = sum(
            1 for c in candidates if c.get("_diff_anchor") == "off_diff"
        )
        # Sort in_diff first so self-refute processes anchored findings
        # before noise; off_diff candidates are evaluated only after
        # in_diff ones, with stricter survival criteria below.
        candidates.sort(key=lambda c: c.get("_diff_anchor") != "in_diff")
