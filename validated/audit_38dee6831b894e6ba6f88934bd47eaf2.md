### Title
Oracle `data_feed()` value has no exposed freshness/timestamp guarantee, allowing AAs to unknowingly act on stale oracle data - (File: `formula/evaluation.js`, `data_feeds.js`)

### Summary
The oscript `data_feed()` primitive that Autonomous Agents (AAs) use to read oracle-posted values (e.g. price feeds) returns only the `value` or `unit` of the most recent matching data-feed post within a `[min_mci, mci]` window, but never exposes the actual mci/timestamp of that post to the calling formula. This is analogous to relying on Chainlink's `latestRoundData` without checking `updatedAt`/`answeredInRound`: the caller has no protocol-level way to detect that the returned figure is stale.

### Finding Description
`getDataFeed()` in `formula/evaluation.js` resolves `data_feed({...})` calls by invoking `dataFeeds.readDataFeedValue(...)`, which walks stored `df/dfv` records and returns the newest value up to `max_mci` (the trigger's mci), constrained only by an optional `min_mci` supplied by the AA author. [1](#0-0) 
The only fields ever surfaced back to the oscript caller are the feed `value` or the `unit` hash — controlled by the `what` parameter, which `formula/validation.js` restricts to just `'value'` or `'unit'`. [2](#0-1) 
`readDataFeedValue`/`readDataFeedByAddress` in `data_feeds.js` do track an internal `mci` for the matched record, but this is never returned in `objResult` beyond internal bookkeeping — it is not forwarded to the AA as an accessible value (no "age" or "timestamp of feed" is exposed). [3](#0-2) [4](#0-3) 
An AA author can only bound freshness indirectly by passing a `min_mci` computed off-chain, but has no oscript-level construct to compare "now" against "when this specific value was posted," unlike Chainlink's `updatedAt`/`answeredInRound`, which explicitly let callers reject stale rounds.

### Impact Explanation
Any AA that uses `data_feed()` for economically sensitive decisions (asset pricing, collateral valuation, conversion rates, payout triggers) cannot algorithmically guard against the referenced oracle having stopped posting fresh data or being delayed. If the oracle address goes silent, is compromised, or lags behind real market conditions, the AA will keep consuming the last known (now stale) value indefinitely and indistinguishably from a fresh one. An attacker can then send a trigger unit at a moment when the stale price diverges from the true market price to extract value from the AA's balance (e.g., buying/selling against a mispriced feed), causing fund loss to the AA and its other users.

### Likelihood Explanation
Any unprivileged sender can post a trigger unit to the AA at will and immediately benefit once the underlying oracle feed becomes stale relative to market conditions; no special privilege is required beyond normal unit posting, and the condition (oracle silence/lag) is common in production oracle deployments.

### Recommendation
Extend `data_feed()`/`readDataFeedValue` to optionally return the mci (and/or unit timestamp) at which the matched value was posted, so AA authors can implement explicit freshness checks (e.g., `data_feed(what='mci', ...)` or a combined `{value, mci}` object), analogous to exposing Chainlink's `updatedAt`/`answeredInRound`. Document this pattern in AA-development guidance so DeFi-style AAs are encouraged to reject stale data explicitly rather than relying solely on `min_mci`, which requires the author to already know the current mci in advance.

### Proof of Concept
1. Oracle `O` posts price feed `data_feed({ PRICE: 100 })` at mci `M0` for a DeFi AA that reads it via `data_feed({ oracles: O, feed_name: 'PRICE' })` in `formula/evaluation.js` (case `'data_feed'`). [5](#0-4) 
2. Oracle `O` stops posting (goes offline / is compromised) while the real market price of the underlying asset drifts far from `100`.
3. At a later mci `M1 >> M0`, an attacker posts a trigger unit to the AA. The AA's formula calls `data_feed(...)` again; `readDataFeedByAddress` finds the same stale record from `M0` (still the latest within `[0, M1]`) and returns `value = 100` with no way for the AA logic to know it is `M1 - M0` mci old. [6](#0-5) 
4. The AA executes economic logic (e.g., swap, collateral valuation, payout) using the stale `100` price, letting the attacker profit from the mismatch versus current market price at the AA's expense.

	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	var bAbortIfSeveral = (ifseveral === 'abort');
	var key_prefix;
	if (value === null){
		key_prefix = 'dfv\n'+address+'\n'+feed_name;
	}
	else{
		var prefixed_value;
		if (typeof value === 'string'){
			var float = string_utils.toNumber(value, bLimitedPrecision);
			if (float !== null)
				prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(float);
			else
				prefixed_value = 's\n'+value;
		}
		else
			prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(value);
		key_prefix = 'df\n'+address+'\n'+feed_name+'\n'+prefixed_value;
	}
	var options = {
		gte: key_prefix+'\n'+string_utils.encodeMci(max_mci),
