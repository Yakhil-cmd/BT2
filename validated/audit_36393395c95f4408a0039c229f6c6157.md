### Title
`StatusHandler#process` creates `Status` rows for any commit sha without verifying the webhook's `repository.full_name` matches the target `Stack`'s repository - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`MergeRequest#all_status_checks_passed?` trusts `Status` rows attached to `head`/`merge_commit` via `StatusChecker`, but those rows are created by `StatusHandler#process`, which looks up commits purely by `sha` across the entire database with no repository binding check. An attacker who owns any GitHub repository already onboarded to Shipit under an organization they know the webhook secret for can forge a `status` webhook naming an arbitrary `sha` (e.g. a target stack's PR head commit sha, which is public) and the resulting `Status` row will be attached to that unrelated commit/stack regardless of what repository the payload claims.

### Finding Description
The binding the question asks about, expressed as an equality, is: `MergeRequest.stack.repository.full_name == payload.dig('repository', 'full_name')`. Tracing the code shows this equality is **never checked**:

1. `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) authenticates the request only against `Shipit.github(organization: repository_owner)`, where `repository_owner` (line 59-62) is read straight from the attacker-controlled JSON body (`repository.owner.login`, falling back to `organization.login`). This only proves the request was signed with the secret configured for *some* organization the attacker names in the payload — it says nothing about which repository or stack the `sha` belongs to.
2. `StatusHandler#process` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`):
   ```ruby
   def process
     Commit.where(sha: params.sha).each do |commit|
       commit.create_status_from_github!(params)
     end
   end
   ```
   This queries `Commit` by `sha` alone, across **every stack and every repository** tracked by the Shipit instance. There is no comparison against `payload.dig('repository','full_name')` or the commit's own `stack.repository`.
3. `Commit#create_status_from_github!` → `Status.replicate_from_github!` (`app/models/shipit/status.rb:23-33`) persists the state using the commit's own `stack_id` (not anything derived from the payload's repository field), and `MergeRequest#all_status_checks_passed?` (`app/models/shipit/merge_request.rb:193-197`) later reads exactly these `Status` rows via `head.statuses_and_check_runs`.

**Attacker's exact request:** the attacker owns Repo A which is legitimately onboarded to Shipit under GitHub org `attacker-org` (so they know or can obtain the correctly-signed webhook, since they configured that webhook themselves during onboarding). They send (or cause GitHub to send, by pushing a commit-status through their own CI on Repo A) a `status` event whose JSON body is:
```json
{
  "sha": "<sha of victim stack's open PR head commit, publicly visible on GitHub>",
  "state": "success",
  "context": "ci/attacker-forge",
  "repository": {"full_name": "victim-org/victim-repo", "owner": {"login": "attacker-org"}}
}
```
Because `repository_owner` used for `verify_signature` is `attacker-org` (whatever the attacker puts there), the signature check passes using the attacker's own known secret. `StatusHandler` then finds `Commit.where(sha: ...)` matching the victim's real commit row (looked up globally, not scoped to `attacker-org`/Repo A) and writes a `success` `Status` onto it.

**Why existing guards fail:** `verify_signature` binds the request to an *organization's secret*, not to the specific *repository* named in the payload, and the repository field used for that check is fully attacker-controlled and independent from the `repository.full_name` value read (or not read at all) later by `StatusHandler`. No model validation, controller filter, or `ExplicitParameters` schema (`StatusHandler.params` only requires `sha`/`state`, not `repository`) ties the processed commit back to the repository asserted in the payload.

### Impact Explanation
A forged `success` status on a target stack's pull-request head commit flips `MergeRequest#all_status_checks_passed?` to `true` for that PR, which drives `reject_unless_mergeable!`/`ProcessMergeRequestsJob` to treat the PR as CI-green and proceed to auto-merge it via `MergeRequest#merge!` (`app/models/shipit/merge_request.rb:164-191`), which calls `stack.github_api.merge_pull_request`. This is a cross-repository/cross-tenant forgery: any commit sha in any Shipit-tracked repository/stack can be targeted as long as the attacker knows that sha (commit shas on open PRs are public GitHub information) and holds a valid webhook secret for *any* organization tracked by the same Shipit instance. This matches "Critical: a payload for one repository mutating another's stack/commit ... or an unauthorized merge."

### Likelihood Explanation
Preconditions: multi-tenant Shipit deployment tracking more than one GitHub org/repo, and the target repo's PR having CI checks that can be short-circuited to `success` by a single forged context (or all required contexts forged). The attacker needs no privilege on the victim's repo/org — only ownership of any repo already integrated with Shipit (to legitimately know/possess a valid webhook signature). The commit sha of an open PR's head is public. This is repeatable per request/PR and requires no timing race or secret theft.

### Recommendation
In `StatusHandler#process` (and similarly `CheckSuiteHandler`/other handlers keyed only by sha), scope the `Commit` lookup by the reporting repository: resolve `params.dig('repository','full_name')` to the associated `Stack`(s) first (e.g. `Stack.where(repository_owner:, repository_name:)`), and only update `Status` rows for commits belonging to those stacks — i.e., enforce `commit.stack.repository.full_name == payload.dig('repository','full_name')` before calling `create_status_from_github!`. Additionally, `verify_signature` should not let the payload alone determine which organization secret is used to authorize writes to a specific stack.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (illustrative, no live GitHub)
test "cross-repository status forgery can flip an unrelated MergeRequest's all_status_checks_passed?" do
  victim_stack = shipit_stacks(:shipit)          # repository.full_name == "shopify/shipit-engine"
  pr = shipit_merge_requests(:mergeable)         # belongs to victim_stack
  head_sha = pr.head.sha

  refute pr.all_status_checks_passed?

  GithubHook.any_instance.stubs(:verify_signature).returns(true) # simulate attacker's known secret for their own org
  request.headers['X-Github-Event'] = 'status'

  forged_payload = {
    'sha' => head_sha,
    'state' => 'success',
    'context' => 'ci/attacker-forge',
    'repository' => {
      'full_name' => 'attacker-org/unrelated-repo', # does NOT equal victim_stack.repository.full_name
      'owner' => { 'login' => 'attacker-org' }
    }
  }.to_json

  post :create, body: forged_payload, as: :json

  assert_equal 'success', pr.head.reload.statuses.last.state
  assert pr.reload.all_status_checks_passed?, "forged status from an unrelated repository incorrectly satisfied the victim stack's check"
end
```
Assertions on both sides of the binding: before the request, `victim_stack.repository.full_name` ("shopify/shipit-engine") != forged `payload['repository']['full_name']` ("attacker-org/unrelated-repo"), yet after the request `pr.all_status_checks_passed?` becomes `true`, proving the code never enforces `MergeRequest.stack.repository.full_name == payload.dig('repository','full_name')`.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end
