### Title
Cross-organization signature/target divergence lets an attacker-controlled webhook mutate another org's `PullRequest` record - (File: app/controllers/shipit/webhooks_controller.rb, lib/shipit/github_app.rb, app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to verify a webhook against using `repository.owner.login`, while `EditedHandler` resolves and mutates the target repository/stack using the unrelated `repository.full_name` field. Because these two fields are never checked for consistency, and `GitHubApp#verify_webhook_signature` trivially returns `true` for any org that has no `webhook_secret` configured, an attacker can pick a no-secret org for `repository.owner.login` to sail through signature verification while pointing `repository.full_name` at a victim repository that the `EditedHandler` will actually update.

### Finding Description
The broken binding, stated as an equality that the code fails to enforce:
`org_used_to_verify_signature (params.repository.owner.login) == org_owning_repository_actually_mutated (params.repository.full_name.split('/').first)`

Trace:
- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` and fetches `github_app = Shipit.github(organization: repository_owner)`, then checks `github_app.verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org has no `webhook_secret` configured: `return true unless webhook_secret`. [3](#0-2) 
- `Shipit.github(organization:)` raises `GithubOrganizationUnknown` only if the organization name is *not present at all* in `secrets.github`; a *known but secret-less* org configuration passes through and reaches the no-op verification above. [4](#0-3) 
- `EditedHandler` never reads `repository.owner.login`. It resolves the repository to mutate purely from `params.repository.full_name`, and looks up the `PullRequest` to update by `number` + that repository's id, then persists attacker-supplied `params.pull_request` into `github_pull_request`. [5](#0-4) 

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `action: "edited"`, `repository.owner.login` set to an org configured in Shipit's multi-org GitHub App settings but with no `webhook_secret` set, and `repository.full_name` set to `"victim-org/victim-repo"` (a real repository onboarded to Shipit with `review_stacks_enabled: true, allow_all: true`). Signature verification trivially passes (no secret configured for the named owner org), and `EditedHandler` then updates the matching `PullRequest` row for `victim-org/victim-repo` with entirely attacker-supplied data (`title`, `head.sha`, `head.ref`, `additions`, `deletions`, `assignees`, `labels`), without the victim org's own secret ever being checked.

This bypasses the intended guard that "a `pull_request` event only affects the repository/stack whose secret authenticated it." `drop_unhandled_event`, `ExplicitParameters` schema validation, and `check_if_ping` do not enforce any owner/full_name consistency; they only validate shape and presence, not cross-field consistency.

### Impact Explanation
This allows a payload verified under one (attacker-chosen, secret-less) organization to mutate a `PullRequest` record belonging to a completely different, victim organization's repository/stack - directly matching the rules' Critical impact category "a payload for one repository mutating another's stack, commit, task or team." The mutated fields include `head.sha`/`head.ref`, which are subsequently used by review-stack machinery for that PR; combined with `review_stacks_enabled: true, allow_all: true` (external PRs auto-provision review stacks that execute `shipit.yml`), attacker-influenced PR head/ref/sha data reaching that pipeline materially increases risk, though the `EditedHandler` itself does not directly invoke `Command`/`PTY.spawn`. This is repeatable against any victim repository/stack once one no-secret org name is known, is not rate-limited by any additional authentication, and scales across all repositories/orgs mounted on the same Shipit instance.

### Likelihood Explanation
Exploitability is conditioned on a specific but realistic deployment configuration: Shipit configured with **multiple GitHub App organizations** (`secrets.github` keyed by org) where at least one configured org lacks a `webhook_secret`. If Shipit is running in single-org/legacy mode (`github_default_organization` is `nil`), `secrets.github` supplies one global `webhook_secret` used for every request regardless of `repository.owner.login`, so this divergence would not bypass verification in that mode. If every configured org has a `webhook_secret` set, `verify_webhook_signature` performs the real HMAC comparison and this attack fails. Given the precondition holds, attacker cost is trivial: no GitHub credentials, no Shipit session, just a single crafted HTTP POST with a known repository name and a known secret-less org name, which is themselves visible to anyone able to inspect a public multi-tenant Shipit deployment's onboarded orgs.

### Recommendation
Enforce that the organization used to select/verify the webhook secret matches the organization that owns the repository actually being mutated: derive `repository_owner` for verification the same way `EditedHandler`/other handlers derive the target repository (i.e., from `repository.full_name.split('/').first`, not `repository.owner.login`), or explicitly compare `repository.owner.login` against `repository.full_name.split('/').first` and reject on mismatch before verifying the signature. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when `webhook_secret` is blank for a per-org multi-tenant configuration — require a webhook secret to be configured per org, or fail closed.

### Proof of Concept
Under `test/controllers/webhooks_controller_test.rb` (or a new test alongside `test/models/shipit/webhooks/handlers/pull_request/edited_handler_test.rb`):
1. Configure `secrets.github` with two orgs: `org-a` (no `webhook_secret`) and `org-b` (`webhook_secret: "s3cr3t"`).
2. Create `stack_b` belonging to repository `org-b/repo`, with `review_stacks_enabled: true`, `allow_all: true`.
3. Create an existing `Shipit::PullRequest` for `stack_b` with `number: 42` and some baseline `github_pull_request` state (e.g., `title: "original"`).
4. Forge a `pull_request` `edited` webhook body with `repository.owner.login = "org-a"`, `repository.full_name = "org-b/repo"`, `number: 42`, and attacker-controlled `pull_request.title = "PWNED"`, `pull_request.head.sha = "<attacker sha>"`.
5. POST to `/webhooks` with `X-Github-Event: pull_request` and any/garbage `X-Hub-Signature` (since `org-a` has no secret, verification short-circuits to `true`).
6. Assert response is `200 OK` (not `422`).
7. Assert `pull_request.reload.github_pull_request['title'] == "PWNED"` and `github_pull_request['head']['sha'] == "<attacker sha>"`, proving the record for `org-b`'s stack was mutated by a request that never authenticated against `org-b`'s secret.

Both sides of the equality (`repository_owner` used at verification-time vs. `repository.full_name`'s owner used at mutation-time) diverge (`"org-a" != "org-b"`), and the mutation still succeeds — confirming the invariant is violated.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
