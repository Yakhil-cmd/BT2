### Title
`min-ustx-for-sats-amount` double-truncation lets a staker register a protocol bond with zero uSTX collateral - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond` in `pox-5.clar` gates the amount of uSTX a staker must lock against the sats they bond by calling `min-ustx-for-sats-amount`, which performs two sequential floor divisions. For sufficiently small `sats-total` relative to `stx-value-ratio`, the intermediate and/or final result truncates to `0`, so the `asserts! (>= amount-ustx (min-ustx-for-sats-amount ...))` check can be satisfied with `amount-ustx = 0`. This is structurally identical to the referenced report's rounding-to-zero fee bug, but here the value that rounds away is the mandatory STX collateral backing a bonded sats position rather than an owner fee.

### Finding Description
`min-ustx-for-sats-amount` is defined as: [1](#0-0) 

```
(define-read-only (min-ustx-for-sats-amount
        (sats-amount uint)
        (stx-value-ratio uint)
        (min-ustx-ratio uint)
    )
    (/ (* (/ (* stx-value-ratio sats-amount) u100) min-ustx-ratio) u10000)
)
```

This performs `floor(floor(stx-value-ratio * sats-amount / 100) * min-ustx-ratio / 10000)`. Whenever `stx-value-ratio * sats-amount < 100`, the inner division already floors to `0`, forcing the whole expression to `0` regardless of `min-ustx-ratio`. Even when the inner term is non-zero, the outer `/ u10000` can floor a small nonzero product back to `0`.

`register-for-bond` uses this value as the sole floor for the STX a staker must commit: [2](#0-1) 

```
;; Verify that they're sending enough STX
(asserts!
    (>= amount-ustx
        (min-ustx-for-sats-amount sats-total (get stx-value-ratio bond)
            (get min-ustx-ratio bond)
        ))
    ERR_INSUFFICIENT_STX
)
```

When the floor computes to `0`, `amount-ustx = 0` passes this check. The subsequent balance check `(>= total-balance amount-ustx)` is then trivially satisfied (`total-balance >= 0` always holds), so a staker can proceed to lock **zero** uSTX while still custodying real sats (`new-sbtc = sats-total`, moved via `roll-sbtc`) and being recorded with real `amount-sats` in `protocol-bond-memberships`: [3](#0-2) 

The staker is then credited into `add-staker-to-bond-cycles` with the full `sats-total`, meaning bond reward accrual (which is driven by `total-sats`, see `calculate-bond-rewards`'s `target-yield`) proceeds unaffected by the missing STX collateral — the `min-ustx-ratio` invariant that is supposed to back every unit of bonded sats with a proportional amount of locked STX is silently bypassed.

### Impact Explanation
`min-ustx-ratio` exists to ensure that sats bonded into a protocol bond carry a minimum proportional STX backing (skin-in-the-game / collateral requirement) tied to the bond's `stx-value-ratio`. By fragmenting registrations (or simply choosing a small enough `sats-total` relative to `stx-value-ratio`), a staker can obtain full bond membership — and the associated bond reward share driven purely by `amount-sats` — while contributing `amount-ustx = 0`. This breaks the equality the protocol relies on: reward-earning bonded sats should never exceed the value actually backed by locked STX. This matches the High-impact category of "signing weight or reward slots exceeding locked value" — the staker's bond share (and thus reward slot within the bond) is not backed by the locked STX the protocol design requires.

### Likelihood Explanation
Likelihood is high for any bond whose `stx-value-ratio` is small (or where a staker deliberately picks a small `sats-total`), since `stx-value-ratio * sats-amount < 100` is trivial to satisfy — this requires no special privilege, only choosing input parameters, exactly mirroring the "buy in chunks" pattern from the reference report. Any unprivileged staker already on a bond's allowlist can trigger this on a normal `register-for-bond` call.

### Recommendation
Change `min-ustx-for-sats-amount` (and the `register-for-bond` check) to round up (ceiling) instead of flooring, or add an explicit guard rejecting registrations where the computed floor is `0` but `sats-total > 0`, e.g.:
```
(asserts! (or (is-eq sats-total u0) (> (min-ustx-for-sats-amount sats-total ...) u0)) ERR_INSUFFICIENT_STX)
```
combined with ceiling-style division so that any nonzero `sats-total` always requires a nonzero, proportionally rounded-up `amount-ustx`.

### Proof of Concept
1. Deployer sets up a bond via `setup-bond` with `stx-value-ratio = 10` and `min-ustx-ratio = 100` (or any ratios such that `stx-value-ratio * sats-amount < 100`).
2. An allow-listed staker picks `sats-total = 9` sats (so `stx-value-ratio * sats-amount = 90 < 100`).
3. Staker calls `register-for-bond` with `btc-lockup = (err 9)` (custody 9 sats) and `amount-ustx = 0`.
4. `min-ustx-for-sats-amount(9, 10, 100)` evaluates to `(/ (* (/ (* 10 9) 100) 100) 10000) = (/ (* 0 100) 10000) = 0`, so `(>= 0 0)` passes; `(>= total-balance 0)` trivially passes.
5. The call succeeds: `protocol-bond-memberships` records `amount-ustx: 0, amount-sats: 9`, and the staker's 9 sats are added into `protocol-bonds-total-staked` and `add-staker-to-bond-cycles`, entitling them to bond-reward accrual proportional to sats with zero STX collateral locked.
