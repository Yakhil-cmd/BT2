### Title
RAY-value overflow in accrual permanently bricks a market — every user-facing verb panics in `scaled_to_original` before the borrow-index cap can engage - (File: contracts/pool/src/cache/scale.rs)

### Summary
Analog of CVE-2021-42528 (fatal null-deref DoS on a crafted input): the pool computes accrued totals as `scaled_shares * index` in RAY inside `scaled_to_original`, guarded only by a checked-multiply that panics with `MathOverflow`. A separate borrow-index ceiling (`MAX_BORROW_INDEX_RAY`) exists, but the value product saturates `i128` *before* the index reaches its cap, so the cap never engages. Since every market operation accrues interest first, once the product overflows the market is permanently frozen — no supply, borrow, repay, withdraw, liquidation, or `update_indexes` ever succeeds again.

### Finding Description
- `Cache::calculate_utilization` (and every accrual/unscale path) calls `scaled_to_original(&self.env, self.borrowed, self.borrow_index)` and `scaled_to_original(&self.env, self.supplied, self.supply_index)`, which multiply RAY-scaled share counts by RAY indexes in `i128` and panic on overflow [1](#0-0) 
- `scaled_to_original` backs every verb: `unscale_supply`, `unscale_borrow`, `resolve_withdrawal`, `resolve_repay`, and `resolve_net_settle` all funnel through the same checked RAY multiplication [2](#0-1) 
- The checked multiply returns `GenericError::MathOverflow`/`DivisionByZero`-style protocol errors rather than an untyped trap, but that only converts the crash into a contract panic — the state itself is never clamped [3](#0-2) 
- The in-repo harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` proves the failure end-to-end: on an 18-decimal market with ~10^9 × 1e18 principal at ~98% utilization on the XLM rate curve, the borrow index grows past ~170×, the next accrual panics inside `scaled_to_original`, `borrow_index < MAX_BORROW_INDEX_RAY` (cap never engaged), and subsequent `try_withdraw_raw` and `try_repay` both fail with `MATH_OVERFLOW` [4](#0-3) 

### Impact Explanation
Permanent freezing of funds / contract unable to operate: once `scaled * index ≥ i128::MAX`, every entrypoint that touches the market accrues first and panics. All supplied principal in that market is locked forever, borrowers can never repay or be liquidated (a solvency risk on top of the freeze), and there is no admin escape because the panic is inside state reads, not a guardable flag.

### Likelihood Explanation
No privileged action is required — the state is built only by `supply`, `borrow`, and elapsed time, all reachable by unprivileged addresses via the controller. However, triggering it needs a whale-scale position (≈10^27 raw units on an 18-decimal asset) held at ~98% utilization on a steep rate curve for many years of accrual, so practical likelihood is low: it requires either an enormous-token-supply asset or an extreme sustained-utilization regime. Real but expensive and slow — consistent with Medium.

### Recommendation
Order the index cap before the value multiplication: accrue against `borrowed * min(new_index, MAX_BORROW_INDEX_RAY)`, or compute accrued value with saturating/`I256` math in `scaled_to_original` and clamp the stored index at the cap in the same step. At minimum, when the product would overflow, clamp the index to the largest value keeping `scaled * index` within `i128` and emit an event, so the market degrades (interest stops accruing) instead of bricking.

### Proof of Concept
Reproduced by the existing test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321`:
1. Create an 18-decimal market with the XLM curve; lift supply/borrow caps and disable max-utilization.
2. `supply(BOB, BIG18, 1e9 * 1e18)`, `supply(ALICE, COL, large)`, `borrow(ALICE, BIG18, 98% of principal)`.
3. Advance ledger time in 1-year steps calling `update_indexes` (permissionless — `test_permissionless_keeper_ops` shows any signer may call it).
4. Within ~40 simulated years, `update_indexes` reverts with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`; thereafter `withdraw` and `repay` for that market revert identically — funds are permanently frozen.

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
