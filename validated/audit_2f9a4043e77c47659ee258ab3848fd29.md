## #VulnerabilityFound

### Title
Unbounded recursive deep-clone of attacker-controlled unit object before depth validation causes stack-overflow crash - (File: `validation.js`, `object_hash.js`)

### Summary
`validate()` in `validation.js` computes the unit hash via `objectHash.getUnitHash(objUnit)` **before** the unit is checked for excessive nesting depth (`isTooDeeplyNestedOrHasTooManyNodes`). When the attacker-supplied unit contains a `content_hash` field, `getUnitHash()` calls `getNakedUnit()`, which performs `_.cloneDeep(objUnit)` — a fully recursive deep-clone with no depth limit — over the raw, unvalidated unit object. An attacker can submit a unit containing an arbitrarily deep nested structure and crash the node with a stack overflow, exactly analogous to the pupnp `ixmlNode_free()` unbounded-recursion DoS in CVE-2021-28302.

### Finding Description
In `validation.js`, `validate()` performs the hash check and field-shape validation in this order: [1](#0-0) 

`objectHash.getUnitHash(objUnit)` is invoked at line 133, while `isTooDeeplyNestedOrHasTooManyNodes(objUnit)` — the only depth-bounding check in the whole validation pipeline — is not applied until line 154, and `hasFieldsExcept()` (which would reject unknown/extra fields such as an unexpected `content_hash` on a "serial" unit, or reject unexpected keys) is not applied until even later (lines 181-191). There is nothing before line 133 that restricts the shape or depth of `objUnit`, other than requiring `objUnit.unit` to be a non-empty string of the correct hash length.

`getUnitHash()` branches on the presence of `content_hash`: [2](#0-1) 

When `objUnit.content_hash` is truthy, it calls `getNakedUnit(objUnit)`, which performs an unbounded recursive deep clone of the **entire** unit object via lodash `_.cloneDeep`, before deleting a handful of fields: [3](#0-2) 

`_.cloneDeep` recurses into every nested array/object with no depth limit and no mechanism (such as `setImmediate`) to interrupt the call stack — unlike the AA-formula validators and `validateDefinition`/`validateAuthentifiers` recursors in `aa_validation.js` and `definition.js`, which explicitly track `depth`/`MAX_DEPTH` and periodically yield with `setImmediate` to avoid deep call stacks, e.g.: [4](#0-3) 

No such protection exists in `getNakedUnit`/`_.cloneDeep`, and it is reached before `isTooDeeplyNestedOrHasTooManyNodes` can reject overly nested input.

### Impact Explanation
An attacker who can submit a unit/joint to a full node (an ordinary, unprivileged action any unit poster performs) can craft a unit object containing:
- a syntactically valid `unit` field (correct length string) to pass the first check,
- a truthy `content_hash` field,
- an arbitrarily deeply nested value under any additional key (e.g., thousands of nested arrays),

and have the node's `validate()` call `objectHash.getUnitHash()` → `getNakedUnit()` → `_.cloneDeep()` before any depth or field-shape check runs. This recursion, running thousands of levels deep, will overflow the V8 call stack and crash (or hang) the node process handling unit validation. Since `validate()` is the central gate used for all incoming units (light and full nodes, hub-and non-hub), this can be used to repeatedly crash nodes attempting to process posted units, preventing the network from confirming new units — a direct denial-of-service against unit/joint validation, matching the accepted "network unable to confirm new units" impact category.

### Likelihood Explanation
Likelihood is high: the attack requires only crafting and submitting a single joint/unit with a `content_hash` field plus one deeply-nested field; it does not require any special key material, address ownership, mining, or privileged network role, and it fires deterministically before any of the existing shape/size defenses (`hasFieldsExcept`, `isTooDeeplyNestedOrHasTooManyNodes`) can reject it.

### Recommendation
Move the `isTooDeeplyNestedOrHasTooManyNodes(objUnit)` (and `isObjectWellFormed`) checks to occur **before** `objectHash.getUnitHash(objUnit)` is invoked in `validate()`, so malformed/over-nested units are rejected prior to any recursive hashing/cloning. Additionally, harden `getNakedUnit`/`getUnitHash`/`getSourceString`/`getJsonSourceString` (and any other place using `_.cloneDeep` or manual recursion over untrusted unit content) with an explicit depth limit that throws rather than recursing unboundedly, independent of call order in `validate()`.

### Proof of Concept
Construct and submit a joint whose `unit` object is:
```js
{
  unit: "<44-char base64 string of correct HASH_LENGTH>",
  content_hash: "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=", // any string, checked only later
  version: constants.versionWithoutTimestamp,
  authors: [{ address: "SOME_VALID_LOOKING_ADDRESS" }],
  bomb: (() => { let a = 1; for (let i = 0; i < 200000; i++) a = [a]; return a; })() // deeply nested array
}
```
Send this as `{unit: ...}` to a node's joint intake (e.g., via the same path used for `bundle`/network `joint` messages, or `light/postJoint`). `validation.validate()` will call `objectHash.getUnitHash(objUnit)` at line 133 of `validation.js`, which — because `content_hash` is truthy — calls `getNakedUnit(objUnit)` and thus `_.cloneDeep(objUnit)` over the 200,000-deep `bomb` array before any depth check runs, causing `RangeError: Maximum call stack size exceeded` and crashing/hanging the validating process.
