This codebase has a deliberate, extensive sanitization framework for untrusted content (`iostreams.Untrusted`, `iostreams.ContainsEscapeSequence`, `SetContentSanitization`, `asciisanitizer`) applied consistently across commands that render remote text (e.g. `pkg/cmd/repo/read-file`, `pkg/cmd/gist/view`, `pkg/cmd/skills/list` via `sanitizeForTerminal`, `pkg/cmd/run/view`'s `copyLogWithLinePrefix`). This shows the project explicitly treats ANSI/control-sequence injection as an in-scope vulnerability class and has fixed it repeatedly elsewhere, but `printVerifiedSubjects` in `pkg/cmd/release/verify/verify.go` was not updated to use any of these mechanisms. [1](#0-0) 

`printVerifiedSubjects` parses the DSSE envelope payload with `protojson.Unmarshal` into `statementData`, then for each `Subject`, takes `s.Name` directly and passes it unmodified to `table.AddField(name)` before `table.Render()` writes it to `io.Out`. [2](#0-1) 

No call to `iostreams.NewUntrusted`, `ContainsEscapeSequence`, `asciisanitizer`, or any stripping function is applied to `name` or `digestStr` before they reach `tableprinter`. `internal/tableprinter/table_printer.go` (the wrapper used here) performs no ANSI/control-character stripping in `AddField`/`AddTimeField`/`Render`; it only handles color, padding, and truncation. [3](#0-2) 

The subject `Name` field originates from the release asset filename embedded in a GitHub-issued build-provenance-style attestation for the release tag; GitHub does not restrict asset filenames to printable-ASCII-only, so a repository owner (an unprivileged attacker per the threat model, since they can create their own public repo and releases) can upload a release asset whose filename contains raw ANSI/CSI/OSC escape bytes (e.g. `\x1b[2K`, `\x1b]0;...\x07`). This name is embedded verbatim by GitHub into the attestation subject and is not sanitized anywhere in the `gh release verify` output path.

### Title
Terminal escape sequence injection via unsanitized attestation subject name - (File: pkg/cmd/release/verify/verify.go)

### Summary
`printVerifiedSubjects` writes the `Subject.Name` field from a DSSE-attested statement directly into a rendered table without any ANSI/control-character sanitization, unlike other commands in this codebase (`gist view`, `repo read-file`, `skills list`, `run view`) that explicitly sanitize untrusted external text before writing to the terminal. An attacker who names a release asset with embedded terminal escape sequences can have that name propagated unsanitized into the attestation and rendered raw to the victim's terminal when they run `gh release verify`.

### Finding Description
`verifyRun` fetches and verifies a release attestation, then calls `printVerifiedSubjects(io, verified)` [4](#0-3) . That function unmarshals the DSSE envelope payload into `v1.Statement` and iterates `statementData.Subject`, taking `s.Name` and `s.Digest` and feeding them straight into `table.AddField(name)` / `table.AddField(digestStr)` followed by `table.Render()` [5](#0-4) . Neither `internal/tableprinter.TablePrinter.AddField` (inherited from `go-gh/v2/pkg/tableprinter`) nor any code in this function strips or escapes control bytes such as `ESC` (0x1B), meaning any CSI/OSC sequence embedded in the asset filename is written byte-for-byte to the victim's terminal. This is in contrast to the sanitization pattern used elsewhere in the same repo (`iostreams.Untrusted.String()`, `sanitizeForTerminal` in `pkg/cmd/skills/list/list.go`), confirming the project recognizes and patches this exact class of bug but missed this call site.

### Impact Explanation
An attacker-controlled release asset filename can inject terminal escape sequences into `gh release verify` output, enabling terminal spoofing (fake success/status text, clearing/rewriting prior trusted output such as the "Release verified!" banner), OSC title-bar manipulation, or (on vulnerable/legacy terminal emulators) more dangerous sequences. This matches GitHub's "terminal injection / output spoofing" impact class — it undermines trust in `gh`'s own verification output, which is precisely the security-sensitive text this command is meant to produce reliably.

### Likelihood Explanation
Fully feasible and repeatable: any unprivileged GitHub user can create a public repository, publish a release with an asset filename containing raw escape bytes, and have GitHub generate the build-provenance attestation used by `gh release verify` from that filename. No privileged access, token leakage, or MITM is required — simply asking a victim to run `gh release verify` against the attacker's own repo/tag triggers the unsanitized render.

### Recommendation
Sanitize `s.Name` (and any other untrusted attestation-derived strings such as digest values) before passing them to `table.AddField`, e.g., wrap them with `iostreams.NewUntrusted(name).String()` or apply the same `asciisanitizer`-based control-character stripping used in `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal`, prior to rendering.

```go
func printVerifiedSubjects(io *iostreams.IOStreams, att *verification.AttestationProcessingResult) error {
	cs := io.ColorScheme()
	w := io.Out

	statement := att.Attestation.Bundle.GetDsseEnvelope().Payload
	var statementData v1.Statement

	err := protojson.Unmarshal([]byte(statement), &statementData)
	if err != nil {
		return err
	}

	// If there aren't at least two subjects, there are no assets to display
	if len(statementData.Subject) < 2 {
		return nil
	}

	fmt.Fprintln(w, cs.Bold("Assets"))
	table := tableprinter.New(io, tableprinter.WithHeader("Name", "Digest"))

	for _, s := range statementData.Subject {
		name := s.Name
		digest := s.Digest

		if name != "" {
			digestStr := ""
			for key, value := range digest {
				digestStr = key + ":" + value
			}

			table.AddField(name)
			table.AddField(digestStr)
			table.EndRow()
		}
	}
	err = table.Render()
	if err != nil {
		return err
	}
```

```go
type TablePrinter struct {
	tableprinter.TablePrinter
	isTTY bool
	cs    *iostreams.ColorScheme
}

// IsTTY gets whether the TablePrinter will render to a terminal.
func (t *TablePrinter) IsTTY() bool {
	return t.isTTY
}

// AddTimeField in TTY mode displays the fuzzy time difference between now and t.
// In non-TTY mode it just displays t with the time.RFC3339 format.
func (tp *TablePrinter) AddTimeField(now, t time.Time, c func(string) string) {
	var tf string
	if tp.isTTY {
		tf = text.FuzzyAgo(now, t)
	} else {
		tf = t.Format(time.RFC3339)
	}
	tp.AddField(tf, WithColor(c))
}

var (
	WithColor    = tableprinter.WithColor
	WithPadding  = tableprinter.WithPadding
	WithTruncate = tableprinter.WithTruncate
)
```
