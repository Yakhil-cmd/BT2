### Title
`repository.owner.login`/`repository.full_name` split lets an attacker forge `pull_request` `labeled` webhooks that mutate an unrelated org's review stack via `LabelCapturingHandler` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/HMAC secret to check using `repository_owner`, which is read from `params.dig('repository','owner','login')` (falling back to `organization.login`), while every `pull_request` handler — including `LabelCapturingHandler` — resolves the repository/stack to mutate using `params.repository.full_name` via `Repository.from_github_repo_name`. Nothing enforces that the owner segment of `full_name` matches `repository.owner.login`, so an attacker who owns/controls a GitHub org with no `webhook_secret` configured (or whose signature check trivially passes because `verify_webhook_signature` returns `true` "unless webhook_secret") can forge a payload whose `repository.owner.login` names that org while `repository.full_name` points at `victim-org/victim-repo`.

### Finding Description
The broken binding, stated as an equality that the code assumes but never checks: `repository_owner_used_for_signature == Repository.from_github_repo_name(params.repository.full_name).owner`.

- `Shipit::WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(header, raw_post)`. `repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`) is `params.dig('repository','owner','login') || params.dig('organization','login')`. [1](#0-0) [2](#0-1) 
- `Shipit::GitHubApp#verify_webhook_signature` returns `true` unconditionally if the org's `webhook_secret` is blank/unset (`return true unless webhook_secret`), and otherwise validates the HMAC using that org's own configured secret. [3](#0-2) 
- After the signature step passes, `WebhooksController#create` dispatches the same raw `params` (including `repository.full_name`) to every handler registered for the event, with no re-derivation from an authenticated identity. [4](#0-3) 
- `LabelCapturingHandler#repository` resolves the target repository purely from `params.repository.full_name` via `Repository.from_github_repo_name`, which just splits the string on `/` and does a DB lookup — no relation to `repository_owner` used above. [5](#0-4) [6](#0-5) 
- On `action == "labeled"` and an active, non-archived stack, `capture_labels` persists `params.pull_request.labels.map(&:name)` onto `stack.pull_request`. [7](#0-6) [8](#0-7) 
- `ReviewStack#env` merges each persisted label, upcased, into the environment as `"true"`, so attacker-chosen label names become arbitrary uppercase env var keys/values injected into the review stack's deploy/task environment. [9](#0-8) 
- `Commit#deployable?` is `!locked? && (stack.ignore_ci? || (success? && !blocked?))` — with `ignore_ci: true` on the victim stack, any commit is deployable, so the attacker-poisoned environment is guaranteed to actually reach a deploy/task execution without needing a passing CI status. [10](#0-9) 

Exploit flow: attacker crafts a raw JSON body with `repository.owner.login` set to an org the attacker controls that has no `webhook_secret` in Shipit's config (or one where the attacker knows the secret), and `repository.full_name` set to `"victim-org/victim-repo"` matching an existing `Shipit::Repository` with an `ignore_ci: true` review stack. `X-Github-Event: pull_request`, body `action: "labeled"`. `verify_signature` picks the attacker-org's `GitHubApp` (no secret ⇒ `verify_webhook_signature` returns `true` regardless of the actual header), so the request passes. `LabelCapturingHandler` then resolves the *victim* repository from `full_name` and calls `pull_request.update!(labels: [...attacker-chosen strings...])`, which get merged as uppercase env vars into that review stack's `env`, reaching any deploy/task's `PTY.spawn` environment because `ignore_ci` bypasses the CI gate.

Existing guards do not close this: `drop_unhandled_event` only checks the event is handled; `verify_signature` never cross-checks `repository.owner.login` against `repository.full_name`'s owner; the `ExplicitParameters` schema on `LabelCapturingHandler` only requires `repository.full_name` to be a `String`, not that it match the signature-verifying owner; `Repository.from_github_repo_name` performs no ownership check either.

### Impact Explanation
A single unauthenticated POST to `/webhooks` lets an attacker (who need only own or name any org, including one with no secret configured in Shipit) inject arbitrary attacker-chosen environment variable keys/values into a completely different organization's review stack. This is a payload for one repository mutating another's stack/record without the mutated repository's secret ever being checked — the Critical-severity category explicitly called out in the rules ("a payload for one repository mutating another's stack, commit, task or team"). Because `ignore_ci: true` makes `Commit#deployable?` bypass CI status entirely, the poisoned environment is guaranteed to reach a real deploy or task execution (`PTY.spawn` environment) rather than being blocked pending CI. This is repeatable against any victim repository/stack for which the attacker can guess or observe the `full_name`, and against any number of tenants sharing the Shipit instance, as long as one org with no configured `webhook_secret` (or an org whose secret the attacker knows) exists in the deployment's `github` config.

### Likelihood Explanation
Preconditions: (1) the Shipit deployment uses the multi-org `github:` config format with at least one org lacking a `webhook_secret`, or the attacker otherwise knows a valid org's secret; (2) a victim `Shipit::Repository`/`ReviewStack` exists with `ignore_ci: true` and an open, non-archived PR-backed review stack. Both are realistic and not privileged: no Shipit session, API token, or GitHub App key is needed — only knowledge of a repository's `full_name` and the ability to craft an HTTP POST with a fabricated JSON body. Attacker cost is a single HTTP request; the attack is trivially repeatable for label injection.

### Recommendation
Verify that the resolved target repository's owner matches the org whose secret authenticated the signature. Concretely, in `WebhooksController#verify_signature` (or in each handler's `process`), derive `repository_owner` from the same field used to select the target repository (`params.repository.full_name`'s owner segment) rather than the independent `repository.owner.login`/`organization.login` field, or explicitly assert `params.repository.full_name.split('/').first.casecmp(repository_owner).zero?` before dispatching to handlers, rejecting the request with 422 otherwise.

### Proof of Concept
minitest plan (no live GitHub):
1. In `test/controllers/webhooks_controller_test.rb`, configure `Shipit.secrets.github` with two orgs: `"attacker-org"` (no `webhook_secret`) and `"victim-org"` (with a `webhook_secret`).
2. Create `victim_repo = shipit_repositories(:some_fixture)` with `owner: "victim-org", name: "victim-repo"`, and a `ReviewStack` with `ignore_ci: true` and an associated `PullRequest`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and body: `{"action":"labeled","number":<n>,"pull_request": {..., "labels":[{"name":"malicious_env_key"}]}, "repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}, "sender": {...}}`.
4. Assert response is `200`/`:ok` (signature check passed via `attacker-org`'s empty secret) — establishing `verify_signature`'s org != mutated repo's org.
5. Reload `victim_repo`'s review stack's `pull_request` and assert `pull_request.labels == ["malicious_env_key"]`.
6. Assert `review_stack.env["MALICIOUS_ENV_KEY"] == "true"`, proving attacker-controlled data reached the environment of a stack belonging to `"victim-org"`, which never authenticated the request — before/after equality check: `repository_owner_used_for_signature ("attacker-org") != mutated_repository.owner ("victim-org")`, yet the mutation succeeded.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
