### Title
Aggregate RAY-value overflow permanently freezes an overgrown market - (File: common/src/rates/simulate.rs)

### Summary
An unprivileged caller can trigger accrual through `Controller::update_indexes(caller, assets)`, which forwards the selected `(hub_id, asset)` markets to the owner-only pool entrypoint. [1](#0-0) [2](#0-1)  Accrual converts aggregate scaled debt and supply into original RAY values before applying the configured borrow-index ceiling, so a sufficiently large book can make that conversion overflow while the index is still far below `MAX_BORROW_INDEX_RAY`. [3](#0-2) [4](#0-3) 

### Finding Description
`global_sync` chunks elapsed time and calls `accrue_step` for each chunk. [5](#0-4)  `accrue_step` first computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`; `scaled_to_original` performs checked multiplication and reverts when the represented aggregate value exceeds `i128`. [6](#0-5) [4](#0-3)  The borrow-index cap is applied only later in `update_borrow_index`, so it cannot protect the earlier aggregate-value multiplication. [7](#0-6) 

Because `Cache::mark_accrued` runs only after every chunk succeeds, the failed accrual does not advance `last_timestamp`; every later invocation starts from the same stale timestamp and reaches the same overflow. [8](#0-7) [9](#0-8)  All ordinary pool operations load the market through `synced_market`, which runs `global_sync` before the operation-specific mutation. [10](#0-9) 

### Impact Explanation
Once the aggregate scaled balance multiplied by its stored index no longer fits in `i128`, the market becomes permanently unable to accrue. [4](#0-3)  Withdrawals, repayments, liquidations, bad-debt cleanup, revenue claims, recapitalization, and any other path that syncs that market revert before reaching their operation-specific logic. [11](#0-10)  The harness reproduces this state and confirms that even a one-unit withdrawal and a repayment fail with `MathOverflow` after accrual fails. [12](#0-11) 

This is permanent freezing of user funds and can leave protocol debt unrecoverable, not merely temporary transaction failure. [10](#0-9) 

### Likelihood Explanation
The trigger path is permissionless: `update_indexes` accepts any authorized caller address and forwards the supplied market keys to the pool. [1](#0-0) [2](#0-1)  The condition requires an extremely large scaled book and enough elapsed interest for the aggregate represented value to exceed `i128`; an attacker cannot directly set the index or ledger time. [3](#0-2)  Nevertheless, the state can arise through normal high-utilization market operation, after which one routine index update irreversibly freezes the market. [13](#0-12) 

### Recommendation
Explicitly bound or saturate aggregate `scaled * index` value calculations before the panicking conversion in `accrue_step`, and ensure the chosen bound lets `last_timestamp` advance and the configured index caps engage. [14](#0-13) [8](#0-7)  Enforce market-size ceilings derived from the maximum representable aggregate value at entry, so future accrual cannot create a market state whose own accounting routine cannot evaluate. [15](#0-14) 

### Proof of Concept
1. Create a high-decimal market capable of admitting approximately `1e27` base units of supply and sustain utilization near its maximum. [16](#0-15) 
2. Supply the large amount and establish debt at approximately 98% utilization. [17](#0-16) 
3. Advance ledger time and call `Controller::update_indexes(caller, vec![HubAssetKey { hub_id, asset }])`; any address can provide the required caller authorization. [1](#0-0) 
4. During accrual, `accrue_step` multiplies the stored scaled aggregate by the stored index and reverts before the borrow-index ceiling is applied. [14](#0-13) [7](#0-6) 
5. Repeat the call or attempt a withdrawal or repayment; each path syncs first and reverts on the same stale interval, leaving the market frozen. [10](#0-9) [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
