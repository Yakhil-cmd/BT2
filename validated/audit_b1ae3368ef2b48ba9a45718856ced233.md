### Title
Bad-debt cleanup leaves residual supply claims that can drain dust collateral and recapitalization - ([File: contracts/pool/src/interest.rs])

### Summary

When bad debt exceeds the market’s total supplied value, `apply_bad_debt_to_supply_index` caps the write-down but then clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW` instead of fully extinguishing supplier claims. Those residual shares remain withdrawable against any cash subsequently present in the market, including seized dust collateral or recapitalization funds. [1](#0-0) 

### Finding Description

`clean_bad_debt` is permissionless once the account has debt and its collateral is insolvent and at or below the dust threshold. [2](#0-1)  The controller iterates the account’s supply and debt positions, sends them to the pool as `PoolSeizeEntry` values, removes the account, and burns its NFT. [3](#0-2)  For each debt leg, the pool converts the position to a ceiling-rounded RAY amount, writes it down through `apply_bad_debt_to_supply_index`, and burns the debt. [4](#0-3) 

The write-down computes `remaining = total_supplied_value - min(bad_debt, total_supplied_value)`, so a complete wipeout produces a zero reduction factor. [5](#0-4)  Nevertheless, the implementation sets the index to `SUPPLY_INDEX_FLOOR_RAW`, leaving every surviving supply share with a positive claim rather than zero. [6](#0-5)  Withdrawals unscale those shares at the floored index, enforce only available `cash` reserves, burn the shares, debit cash, and transfer the resulting amount. [7](#0-6) [8](#0-7) 

The repository already contains a regression-style test demonstrating this precise accounting shape: after a wipeout clamps the index to the floor, an old supplier retains a positive stranded claim and can withdraw newly credited cash. [9](#0-8)  The ordinary supply path does reject a presently unbacked market before minting new shares, so arbitrary new deposits are not credited while the residual shortfall remains. [10](#0-9)  However, cash can already remain from seized dust collateral, or can be added through `recapitalize`, which measures an inbound transfer and credits it up to the backing shortfall. [11](#0-10) 

### Impact Explanation

Residual suppliers can extract cash that should back seized dust collateral, protocol revenue, or a recapitalization payment. This can transfer value from the protocol or a recapitalizer to holders of shares that should have been completely written off, and can leave the market undercollateralized again after the withdrawal. [4](#0-3) [12](#0-11) 

The loss is bounded in the pure dust-cleanup case by the residual floor value and available cash, but repeated markets or recapitalization can make the loss material. This is theft of user or protocol funds and can also cause continued market insolvency. [13](#0-12) 

### Likelihood Explanation

Exploitation requires a borrow position to become insolvent and then reach the permissionless dust-collateral cleanup gate. [14](#0-13)  An attacker can control both the supplier account and the bad-debt account, but still needs adverse market movement or another legitimate path that creates bad debt; the vulnerability does not let an attacker create arbitrary debt without collateral or authorization. [15](#0-14) 

Once a full write-down occurs, exploitation is mechanical: the residual supplier calls `withdraw` with a zero amount, which the controller treats as a full withdrawal. [16](#0-15)  The withdrawal succeeds whenever the pool’s `cash` covers the floored residual claim. [17](#0-16) 

### Recommendation

Handle a complete bad-debt wipeout explicitly instead of preserving claims at `SUPPLY_INDEX_FLOOR_RAW`. [18](#0-17)  When `bad_debt >= total_supplied_value`, the pool should extinguish the outstanding supply/revenue claims or record a separate residual-loss state that prevents those claims from withdrawing later cash. [19](#0-18) 

If the index floor is retained for arithmetic safety, add an explicit wiped-market flag that causes withdrawals and revenue claims to receive zero until governance resets or fully recapitalizes the market. Add an integration test covering `clean_bad_debt` followed by seized-dust cash, `recapitalize`, and a residual supplier’s full withdrawal. [3](#0-2) [20](#0-19) 

### Proof of Concept

1. Supplier account `S` supplies asset `A` and receives nonzero scaled supply shares through `supply(caller=S, account_id=0, spoke_id, assets=[(A, amount)])`. [21](#0-20) 
2. Borrower account `B` obtains debt in `A` and later becomes insolvent, leaving only collateral value at or below the configured dust threshold. [22](#0-21) 
3. Any caller invokes `clean_bad_debt(caller, B_id)`; the controller emits pool seize entries for `B`’s supply and debt positions and then deletes the account. [23](#0-22) [3](#0-2) 
4. For `B`’s debt leg, `bad_debt` is at least `total_supplied_value`, causing `remaining` to be zero and `new_supply_index` to be clamped upward to `SUPPLY_INDEX_FLOOR_RAW`. [24](#0-23) 
5. `S`’s scaled shares are not burned and therefore still unscale to a positive asset amount at the floored index. [19](#0-18) 
6. If seized dust collateral or a `recapitalize` call leaves `cash > 0`, `S` calls `withdraw(caller=S, account_id=S_id, withdrawals=[(A, 0)], to=Some(S))`; zero selects a full withdrawal. [16](#0-15) [20](#0-19) 
7. The pool enforces `cash >= net_transfer`, debits that cash, and transfers it to `S`, allowing a claim that should have been eliminated by the full write-down to consume funds belonging to the protocol or recapitalizer. [25](#0-24) [8](#0-7)

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Enforces reserve, utilization, and solvency guards, then debits cash for
/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
}

#[test]
fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );

    env: &Env,

        &pool_addr,
        amount,
        GenericError::AmountMustBePositive,
    );

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}
