### Title
`EnvironmentVariables#interpolate` falls back to Shipit's process `ENV` for unresolved `$VAR` names, letting `deploy.override` steps leak host secrets - (File: lib/shipit/environment_variables.rb)

### Summary
`EnvironmentVariables#interpolate` resolves a `$VAR` token by first checking the task's env hash and, if absent, falling back to `ENV[variable]`, the Shipit host process environment. `DeploySpec#deploy_steps` reads step strings directly from `deploy.override` in `shipit.yml`, and `Command#interpolated_arguments` interpolates every argument through this same method before `PTY.spawn`, so a fork-authored step referencing an unregistered variable name is filled in with whatever value happens to be set in the host process's environment.

### Finding Description
The broken binding is: for any token `$SOMEVAR` in a step argument, the value substituted into `argv` should be constrained to `∈ task.env ∪ {""}` (i.e., either the whitelisted per-task/deploy env or nothing), but the actual binding is `value ∈ task.env ∪ ENV` because of: [1](#0-0) 

`argument.gsub(/(\$\w+)/) { ... @env.fetch(variable) { ENV[variable] } }` — when `variable` is not a key of `@env`, it silently reads `ENV[variable]` (Shipit's own process environment, which can hold `GITHUB_TOKEN`, `webhook_secret`, DB credentials, etc. depending on deployment) and `Shellwords.escape`s it into the interpolated argument string.

This method is invoked from `Command#interpolate_environment_variables`/`#interpolated_arguments`, which is called right before spawning the process: [2](#0-1) [3](#0-2) 

Step content itself is sourced from `deploy.override` in the repository's `shipit.yml`, which for a ReviewStack under `allow_with_label`/`provision_pr_stacks` comes from the fork branch: [4](#0-3) 

So the attacker's exploit path is: open a PR from a fork, edit `shipit.yml`'s `deploy.override` to include a step like `echo $GITHUB_TOKEN` (or any other name they guess is set as a host env var, e.g. `DATABASE_URL`, `SECRET_KEY_BASE`, `REDIS_URL`), get a maintainer to label the PR to trigger provisioning under `allow_with_label`, and the resulting task's output (visible to the PR author via the ReviewStack task page) will contain the escaped value of that host environment variable, because `GITHUB_TOKEN` is not defined in the deploy task's own `@env` (which is built from `filter_deploy_envs`/whitelisted `deploy.variables`), triggering the `ENV[variable]` fallback.

None of the existing guards catch this: `filter_deploy_envs`/`EnvironmentVariables#permit` only restricts what keys are allowed *into* the task's env hash (`sanitize_env_vars` in `lib/shipit/environment_variables.rb`), it does not prevent `interpolate`'s independent fallback to `ENV` for names absent from that hash. The whitelist and the interpolation fallback are two different, disconnected code paths in the same class, and the fallback branch has no whitelist check at all.

### Impact Explanation
Any name in the Shipit host process's `ENV` (this can include `GITHUB_TOKEN`, `webhook_secret`, `secret_key_base`, database/redis URLs, or any other secret exported as a process env var in the deployment configuration) can be exfiltrated into task output that the PR-owning (unprivileged) attacker can read, purely by naming a `$VARNAME` in their fork's `shipit.yml`. This matches the Critical impact category "exfiltration of GITHUB_TOKEN / deploy-time secrets." The attack is repeatable per task run and is scoped to whatever repository has PR-provisioned ReviewStacks with `allow_with_label` enabled; the leaked ENV is the same across all stacks/tenants sharing the same Shipit process, so it is not limited to the attacker's own repository's secrets — it is the *host's* environment.

### Likelihood Explanation
Preconditions: the target repository must have `provision_behavior` set to `allow_with_label` (or otherwise provision ReviewStacks for fork PRs) — a documented, opt-in Shipit feature. The attacker needs no privileged role: they only need to open a PR from a fork with a crafted `shipit.yml`, and a maintainer's routine act of labeling the PR (the normal workflow for this feature) triggers provisioning and task execution. The attacker's cost is trivial (edit YAML, guess/know common host env var names such as `GITHUB_TOKEN`, `DATABASE_URL`, `RAILS_MASTER_KEY`), and the exploit is fully repeatable across any number of PRs/tasks.

### Recommendation
Remove the `ENV[variable]` fallback entirely in `EnvironmentVariables#interpolate` (`lib/shipit/environment_variables.rb:25`); unresolved variables should raise or resolve to an empty string, never read from Shipit's own process environment. If some legitimate use case requires access to specific host-level variables, that should be an explicit, maintainer-controlled allowlist merged into the task's env before interpolation, not an implicit fallback to the full process environment.

### Proof of Concept
```ruby
# test/unit/environment_variables_test.rb (illustrative)
test "#interpolate does not fall back to Shipit's process ENV" do
  ENV['SHIPIT_SECRET_FOR_TEST'] = 'super-secret-value'
  env = Shipit::EnvironmentVariables.with({}) # deploy task env has no SHIPIT_SECRET_FOR_TEST
  result = env.interpolate('echo $SHIPIT_SECRET_FOR_TEST')

  # Broken binding under test: result should equal 'echo ' (empty/absent), not leak host ENV
  assert_equal 'echo ', result # FAILS today: actual result is 'echo super-secret-value'
ensure
  ENV.delete('SHIPIT_SECRET_FOR_TEST')
end

test "deploy.override step referencing unregistered var leaks host ENV into Command argv" do
  ENV['SHIPIT_SECRET_FOR_TEST'] = 'super-secret-value'
  spec = Shipit::DeploySpec.new(
    'deploy' => { 'override' => ['echo $SHIPIT_SECRET_FOR_TEST'] }
  )
  command = Shipit::Command.new(*spec.deploy_steps, chdir: Dir.tmpdir, env: {})
  assert_includes command.interpolated_arguments.join(' '), 'super-secret-value'
ensure
  ENV.delete('SHIPIT_SECRET_FOR_TEST')
end
```
Both assertions demonstrate the equality `interpolated_value == ENV[VAR]` (attacker-controlled name) instead of the expected `interpolated_value ∈ task.env ∪ {""}`.

    def interpolate(argument)
      return argument unless @env

      argument.gsub(/(\$\w+)/) do |variable|
        variable.sub!('$', '')
        Shellwords.escape(@env.fetch(variable) { ENV[variable] })
      end
    end
