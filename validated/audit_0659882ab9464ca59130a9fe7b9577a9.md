### Title
Webhook signature is verified against `repository.owner.login`'s secret while handlers act on `repository.full_name`, allowing cross-tenant Stack/Repository mutation - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate the HMAC against using `repository_owner`, which is read straight out of the untrusted JSON body (`params.dig('repository','owner','login')`). All the actual event handlers, however, resolve the target `Repository`/`Stack` using a completely different field of the same body, `repository.full_name`. Nothing binds these two fields together, so an attacker who owns/controls a repository under organization X (and therefore knows X's `webhook_secret`) can compute a valid `sha1=` HMAC over a body whose `repository.owner.login` is `X` but whose `repository.full_name` names a repository owned by victim organization Y, and the request passes verification while mutating Y's data.

### Finding Description
Broken binding: the code implicitly assumes
`organization_whose_secret_signed_body (repository.owner.login)` == `organization_owning_the_mutated_repository (repository.full_name's owner segment)`,
but no code enforces this equality.

Code path:
- `verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository','owner','login') || params.dig('organization','login')` (line 61) and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(header, request.raw_post)`.
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) simply HMAC-sha1's `request.raw_post` with the `webhook_secret` configured for that organization and compares to the header — this is correct *in isolation*, but it authenticates "this body was signed by whoever holds X's secret," not "this body's target repository belongs to X."
- On success, `create` (webhooks_controller.rb:10-15) parses the same raw body and dispatches to handlers, e.g. `Handlers::PullRequest::LabeledHandler`, `ClosedHandler`, `OpenedHandler`, `AssignedHandler`, `EditedHandler`, `ReopenedHandler`, `UnlabeledHandler`, `LabelCapturingHandler`, and the base `Handler#stacks`.
- All of these resolve the acted-upon repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` (e.g. app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:66, opened_handler.rb:52, closed_handler.rb:51, assigned_handler.rb:68, edited_handler.rb:64, reopened_handler.rb:51, and the shared `Handler#stacks`/`#repository_name` at app/models/shipit/webhooks/handlers/handler.rb:33-38), which splits `full_name` on `/` and does `find_by(owner:, name:)` (app/models/shipit/repository.rb:53-56) — completely independent of `repository.owner.login`.

Exploit: attacker owns org `X` with a legitimate `webhook_secret` in Shipit's config (their own tracked repo, so `X` is a real configured organization). They craft a raw JSON body where `repository.owner.login = "X"` and `repository.full_name = "Y/victim-repo"` (Y being any other tracked org/repo, e.g. from a `pull_request.labeled` or `pull_request.closed` event), compute `HMAC-SHA1(X_webhook_secret, raw_body)`, and POST it to `/webhooks` with header `X-Hub-Signature: sha1=<hmac>` and `X-Github-Event: pull_request`. `verify_signature` looks up `X`'s `GitHubApp`, validates the signature against `X`'s real secret, and succeeds. The handler then loads `Y/victim-repo`'s `Repository`/`Stack`/`ReviewStack` and archives/unarchives it, updates its `PullRequest` record, or (via `LabeledHandler`) triggers `stack.archive!`/`stack.unarchive!` on the victim's stack — a write attributable to and targeting a different tenant than the one whose secret authenticated the request.

No existing guard prevents this: `verify_signature` never cross-checks `repository_owner` against `repository.full_name`; `drop_unhandled_event` only checks event type presence; the `ExplicitParameters` schemas only validate types/presence of fields, not cross-field consistency; `Repository.from_github_repo_name` performs no ownership check tying it back to the authenticated organization.

### Impact Explanation
An attacker with a webhook secret for their own (possibly attacker-registered/onboarded) organization can forge writes against any other tracked repository's `Stack`/`ReviewStack`/`PullRequest` records — archiving/unarchiving review stacks, mutating stored PR metadata (`github_pull_request`, `labels`) for a victim repo they do not control. This is a cross-tenant integrity breach matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." It is fully repeatable against any tracked repository/org combination as long as the attacker has any org with a configured `webhook_secret`.

### Likelihood Explanation
Preconditions: Shipit must be configured with more than one GitHub organization's `webhook_secret` (typical for a multi-tenant Shipit deployment), and the attacker must control/own at least one such organization (e.g., they onboarded their own small org/repo into the same Shipit instance) — this is the "unprivileged attacker who can own a repo and emit its webhooks" scenario explicitly allowed by the rules. No secret guessing, leakage, or privileged Shipit access is required; attacker cost is a single crafted HTTP POST with a correctly computed HMAC over a body they fully control.

### Recommendation
In `verify_signature`, derive the organization used to select the webhook secret from the same field the handlers use to resolve the target repository (`repository.full_name`'s owner segment), and reject the request if `repository.owner.login` (when present) does not match that owner. Alternatively, after verification, have `Handler`/`Repository` resolution re-validate that the resolved `Repository#owner` matches the organization whose secret validated the signature, rejecting the event otherwise.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test 'a valid signature from org X cannot mutate a repository owned by org Y' do
  # Org X: attacker-controlled org, real webhook_secret configured in test/dummy secrets
  # Org Y: victim org/repo already tracked with its own stack
  victim_repo = shipit_repositories(:shipit) # owner: "shipit-engine" e.g., Y
  victim_stack = victim_repo.stacks.first
  victim_stack.update!(review_stacks_enabled: true) if victim_stack.respond_to?(:review_stacks_enabled)

  body = {
    action: 'closed',
    number: 1,
    pull_request: { id: 1, number: 1, url: 'x', title: 'x', state: 'closed',
                     additions: 0, deletions: 0,
                     head: { sha: 'a'*40, ref: 'x' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { owner: { login: 'attacker-org' }, full_name: victim_repo.github_repo_name },
    sender: { login: 'attacker' }
  }.to_json

  attacker_org_secret = Shipit.github(organization: 'attacker-org').send(:webhook_secret)
  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', attacker_org_secret, body)

  assert_no_difference -> { victim_stack.reload.archived_since } do
    post shipit.github_webhooks_path,
      params: body,
      headers: {
        'X-Github-Event' => 'pull_request',
        'X-Hub-Signature' => signature,
        'Content-Type' => 'application/json'
      }
  end
  # Assert response is accepted (200) even though repository.owner.login ("attacker-org")
  # != victim_repo.owner ("shipit-engine"), proving binding is broken:
  assert_response :ok
  # Then assert the victim stack WAS mutated (e.g. archived), proving cross-tenant write:
  assert victim_stack.reload.archived?
end
```
This demonstrates: signature valid under `attacker-org`'s secret (equality LHS = `attacker-org`), but the mutated record belongs to `victim-org` (equality RHS = `shipit-engine`/victim owner) — the two sides diverge, confirming the vulnerability.     def verify_webhook_signature(signature, message)
```ruby
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
