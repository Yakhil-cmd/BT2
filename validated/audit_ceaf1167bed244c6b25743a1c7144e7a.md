### Answer

No vulnerability found for this question.

**Reasoning:** Worktree retention is time-window bounded, not merely "purely time-based and unbounded." `removeStaleWorktrees` deletes any non-current worktree whose mtime is older than `git.staleTimeout` [1](#0-0) , and its timer starts only when a worktree stops being current, via `touch(currentWorktree.Path())` at the moment a new hash is published [2](#0-1) . Crucially, `cleanup()` — which calls `removeStaleWorktrees` — runs on **every** iteration of the main sync loop (governed by `--period`), independent of whether a new commit was actually fetched [3](#0-2) , not only when new commits land.

Given a fixed `--stale-worktree-timeout`, the steady-state number of retained worktrees is bounded by roughly `staleTimeout / commit-interval + O(1)` — a fixed constant determined entirely by the (attacker-uncontrolled) flag value, not something that grows over the lifetime of the deployment. The attack scenario in the question (pushing at `timeout - epsilon` cadence) actually produces the *smallest* possible steady-state count (~1-2 stale worktrees), since each old worktree is evicted almost as fast as a new one is created — it does not cause unbounded accumulation.

Additionally, the default value of `--stale-worktree-timeout` is `0`, meaning stale worktrees are removed immediately on the next cleanup cycle [4](#0-3) , and per the rules the attacker does not control flags, so they cannot force a larger timeout to widen this bound. There is no code path here that allows an unprivileged repo-content attacker to defeat the periodic `cleanup()` call or cause monotonic, unbounded worktree growth; the mechanism is self-correcting by design and matches documented behavior, not an exploitable resource-exhaustion bug.

```go
func (git *repoSync) removeStaleWorktrees() (int, error) {
	currentWorktree, err := git.currentWorktree()
	if err != nil {
		return 0, err
	}

	git.log.V(3).Info("cleaning up stale worktrees", "currentHash", currentWorktree.Hash())

	count := 0
	err = removeDirContentsIf(git.worktreeFor("").Path(), git.log, func(fi os.FileInfo) (bool, error) {
		// delete files that are over the stale time out, and make sure to never delete the current worktree
		if fi.Name() != currentWorktree.Hash() && time.Since(fi.ModTime()) > git.staleTimeout {
			count++
			return true, nil
		}
		return false, nil
	})
	if err != nil {
		return 0, err
	}
	return count, nil
}
```
