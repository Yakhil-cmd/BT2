### Title
Arbiter contract dispute/appeal flow leaks permanent pairing secrets to an attacker-chosen "arbiter" URL - (File: arbiter_contract.js)

### Summary
`arbiter_contract.js`'s `openDispute()` and `appeal()` functions send the wallet's permanent device-pairing secret (and the counterparty's) to a URL resolved from `objContract.arbiter_address`/`arbstore_address` [1](#0-0) [2](#0-1) . The `arbiter_address` field of a contract is chosen by whichever party creates/offers the contract via `createAndSend()` [3](#0-2) , and the corresponding ArbStore URL is fetched generically through `device.requestFromHub("hub/get_arbstore_url", address, ...)` with no verification that the address belongs to a trusted, vetted arbiter [4](#0-3) [5](#0-4) . A malicious counterparty can name an address they control (or collude with) as `arbiter_address`, causing the victim's own client to POST both parties' `my_pairing_code`/`peer_pairing_code` — derived from the long-lived `device.getOrGeneratePermanentPairingInfo()` secret — to that attacker-controlled server whenever the victim opens a dispute or files an appeal.

### Finding Description
When a contract is created, the offeror freely sets `arbiter_address` in the object that is sent as `arbiter_contract_offer` to the peer [6](#0-5) . There is no check anywhere in `arbiter_contract.js`, `arbiters.js`, or `getArbstoreAddresses()`/`fillArbstoreAddresses()` [7](#0-6)  that validates the arbiter address against a trusted/whitelisted arbiter registry — any address that the hub can resolve to *some* ArbStore URL via `hub/get_arbstore_url` is accepted.

Later, when the victim (as plaintiff, respondent, or during appeal) triggers `openDispute()` or `appeal()`, the code:
1. Resolves the URL for `objContract.arbiter_address` (or `arbstore_address`) via the hub [8](#0-7) [9](#0-8) .
2. Generates/fetches the wallet's *permanent* pairing secret via `device.getOrGeneratePermanentPairingInfo()` [10](#0-9) [11](#0-10) .
3. Sends this secret (`my_pairing_code`), and in `openDispute()` also the peer's previously-received `peer_pairing_code`, in the JSON body POSTed to the resolved URL [12](#0-11) [13](#0-12) .

Because the URL and the identity behind it (`arbiter_address`) are attacker-influenced at contract-creation time, and no code path ever confirms that this address is a legitimately-operated arbiter/arbstore (e.g., against a known list or on-chain attestation), this is structurally the same bug class as the Jenkins report: an unprivileged party (here, a private-payment/contract counterparty) can steer a victim's client into sending stored long-lived credentials — the permanent pairing secret used to re-establish device pairing without further confirmation — to a URL of the attacker's choosing.

### Impact Explanation
The permanent pairing secret (`pairing_secret` returned by `getOrGeneratePermanentPairingInfo`) combined with the device pubkey/hub forms a `my_pairing_code`, which functions as a durable credential: possessing it lets the holder pair with the victim's device (or with the peer's device, since `peer_pairing_code` is also leaked) as though it were a legitimately-established relationship, going forward via the paired device channel used for chat, wallet requests, and other trusted interactions. Leaking it to an attacker's server allows the attacker to impersonate a paired contact for further device-message based attacks against the victim's wallet, undermining the confidentiality/integrity guarantees relied on by other message handling code in the wallet. This is a credential-capture issue directly reachable from a private, two-party interaction (arbiter contract creation) with no privileged access required.

### Likelihood Explanation
Likelihood is moderate-to-high: any user can propose an arbiter contract via `createAndSend()` and simply set `arbiter_address` to an address they control, provided they (or a colluder) can get the hub to answer `hub/get_arbstore_url` for that address with a URL they operate. The victim does not need to do anything unusual — normal usage of the dispute/appeal feature (`openDispute`/`appeal`) triggers the leak automatically once the contract reaches "paid"/"in_dispute"/"dispute_resolved" status, without any additional confirmation prompt shown to the user about the arbiter's trustworthiness before the pairing secret is transmitted.

### Recommendation
Before sending `my_pairing_code`/`peer_pairing_code` (or any pairing credential) to an ArbStore URL, validate that `arbiter_address` corresponds to a genuinely trusted/registered arbiter (e.g., cross-check against a canonical, hub-independent arbiter registry, or require explicit user confirmation displaying the resolved ArbStore URL and arbiter identity before transmitting any pairing secret). Consider avoiding transmission of the *permanent* pairing secret altogether in favor of a short-lived, single-use pairing token scoped to the specific dispute/appeal interaction, so a malicious arbiter cannot reuse a captured secret to re-pair with the victim's device indefinitely.

### Proof of Concept
1. Attacker (Mallory) creates or controls an address `A` and stands up a malicious ArbStore server, and gets the hub to resolve `hub/get_arbstore_url` for `A` to `https://mallory-evil.example`.
2. Mallory proposes an arbiter contract to Victim via `createAndSend()`, setting `arbiter_address = A` [3](#0-2) .
3. Victim accepts and later, after a dispute arises, calls `openDispute()` (or, after a dispute is resolved and appealed, `appeal()`).
4. Victim's client resolves `A`'s URL to `https://mallory-evil.example` and POSTs `my_pairing_code` (and `peer_pairing_code`) to it [12](#0-11) [13](#0-12) .
5. Mallory's server now has Victim's permanent pairing secret and can use it to establish a persistent paired-device relationship with Victim's wallet.

function getArbstoreAddresses(arbiter_address, cb) {
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err)
			return cb(err);
		device.requestFromHub("hub/get_arbstore_address", arbiter_address, function(err, arbstore_address){
			if (err) {
				return cb(err);
			}
			httpRequest(url, "/api/get_device_address", "", function(err, arbstore_device_address) {
				if (err) {
					console.warn("no arbstore_device_address", err);
					return cb(err);
				}
				cb(null, { arbstore_address, arbstore_device_address });
			});
		});
	});

function getInfo(address, cb) {
	cb = cb || function() {};
	db.query("SELECT device_pub_key, real_name FROM wallet_arbiters WHERE arbiter_address=?", [address], function(rows){
		if (rows.length && rows[0].real_name) { // request again if no real name
			cb(null, rows[0]);
		} else {
			device.requestFromHub("hub/get_arbstore_url", address, function(err, url){
				if (err) {
					return cb(err);
				}
				if (!validationUtils.isNonemptyString(url))
					return cb("invalid url received from hub");
				requestInfoFromArbStore(url+'/api/arbiter/'+address, function(err, info){
					if (err) {
						return cb(err);
					}
					if (!validationUtils.isNonemptyObject(info))
						return cb("invalid arbiter info received from arbstore");
					db.query("REPLACE INTO wallet_arbiters (arbiter_address, device_pub_key, real_name) VALUES (?, ?, ?)", [address, info.device_pub_key, info.real_name], function() {cb(null, info);});
				});
			});
		}
	});
}

function getArbstoreInfo(arbiter_address, cb) {
	if (!cb)
		return new Promise(function(resolve, reject){
			getArbstoreInfo(arbiter_address, function(err, info){
				if (err) return reject(err);
				resolve(info);
			});
		});
	if (arbStoreInfos[arbiter_address]) return cb(null, arbStoreInfos[arbiter_address]);
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err) {
			return cb(err);
		}
		if (!validationUtils.isNonemptyString(url))
			return cb("invalid url received from hub");
		requestInfoFromArbStore(url+'/api/get_info', function(err, info){
			if (err)
				return cb(err);
			if (!validationUtils.isNonemptyObject(info))
				return cb("invalid info received from arbstore");
			const cut = parseFloat(info.cut);
			if (!info.address || !validationUtils.isValidAddress(info.address) || isNaN(cut) || cut < 0 || cut >= 1) {
				return cb("malformed info received from ArbStore");
			}
			info.url = url;
			arbStoreInfos[arbiter_address] = info;
			cb(null, info);
		});
	});
}
