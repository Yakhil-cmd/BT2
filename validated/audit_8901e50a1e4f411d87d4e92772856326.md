### Title
Webhook signature is verified against an attacker-chosen `repository.owner.login`/`organization.login`, while the actual write targets a completely unrelated repository/commit resolved from a separate, unverified payload field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` binds HMAC verification to a GitHub organization identity picked directly out of the untrusted JSON body, while the handlers that perform the actual database writes resolve their target repository/commit from a different, independent field of that same body. The two lookups are never cross-checked, so the "organization that authenticated" and the "repository/commit that is written" are decoupled - the exact binding-break pattern from the report (address salted/derived from one set of inputs vs. funds that end up bound to a different, uncommitted set of inputs).

### Finding Description
`verify_signature` derives the organization used for HMAC verification purely from payload fields: [1](#0-0) [2](#0-1) 

```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```

`GitHubApp#verify_webhook_signature` treats an organization with no configured `webhook_secret` as automatically verified: [3](#0-2) 

```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```

`webhook_secret` is explicitly documented as optional and shipped blank by default in every example configuration (`config/secrets.development.example.yml` line 11, `docs/setup.md` line 30, `template.rb`), so a Shipit host that has not filled it in for one (or all) configured organizations has effectively no signature protection for that organization.

Meanwhile, the code path that actually mutates state resolves the target repository from a *different* field, `repository.full_name`, and never re-checks it against the organization used above: [4](#0-3) 

And `StatusHandler`, which writes commit statuses, doesn't even use the repository field at all - it looks up commits globally by `sha`, across every stack in the installation: [5](#0-4) 

```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
```

So the equality that should hold - "organization whose signature was verified" == "organization/repository whose data gets written" - is never enforced. If any configured organization lacks a `webhook_secret` (a documented, common setup state), an unauthenticated caller can:
1. Send a `status` event to `POST /webhooks`.
2. Set `repository.owner.login` (or `organization.login`) to that unsecured organization, so `verify_signature` trivially passes (`return true unless webhook_secret`).
3. Set `sha` to the sha of a commit belonging to *any other* stack/repository in the installation (secured or not - `StatusHandler` never checks which repo the commit belongs to).
4. Set `state: "success"` and `context` to match a required blocking status.

This forges a passing CI status on an arbitrary commit belonging to a repository/organization that is otherwise properly secured.

### Impact Explanation
A forged, unsigned commit status can satisfy `ci.require` / blocking-status checks documented in `README.md` (`ci.require`), which Shipit's merge-queue and deploy-safety logic rely on to decide whether a commit is safe to merge/deploy. Forging a success status on a commit that never actually passed CI can unblock an unauthorized deploy or merge - this matches the Critical impact bucket "unauthorized deploy, rollback or merge."

### Likelihood Explanation
Likelihood is moderate-to-high in realistic deployments: `webhook_secret` is explicitly marked optional in the setup docs and defaults to blank/nil in every shipped example config, so many real installations (single-org or multi-org) will have at least one organization with no secret configured. No credentials, sessions, or tokens are required - only knowledge of a target commit `sha`, which is public information on GitHub.

### Recommendation
- Reject webhooks outright (do not `return true`) when `webhook_secret` is blank for a strict "fail closed" default, or require an explicit opt-in flag to disable signature verification.
- Bind the verified organization to the actual write path: after verifying the signature, re-derive the target repository strictly from the same `repository.owner.login`/`full_name` that was verified, and reject/ignore events whose target repository does not belong to the organization that was authenticated.
- In `StatusHandler`, scope `Commit.where(sha: params.sha)` to commits whose stack's repository matches the verified `repository.full_name`, rather than searching globally across all stacks.

### Proof of Concept
Assume the Shipit instance has organization `unsecured-org` configured with no `webhook_secret` (a documented/default state), and a separate, properly secured stack `victim-org/victim-repo` with a commit `abc123...` gating a deploy behind `ci.require: [ci/tests]`.

```
POST /webhooks HTTP/1.1
X-Github-Event: status
Content-Type: application/json

{
  "sha": "abc123deadbeefabc123deadbeefabc123deadbeef",
  "state": "success",
  "context": "ci/tests",
  "target_url": "https://ci.example.com/fake",
  "created_at": "2026-09-01T00:00:00Z",
  "branches": [{"name": "main"}],
  "repository": {
    "full_name": "unsecured-org/anything",
    "owner": {"login": "unsecured-org"}
  }
}
```

`verify_signature` resolves `repository_owner` = `unsecured-org`, whose `webhook_secret` is blank, so verification trivially passes with no `X-Hub-Signature` header at all. `StatusHandler#process` then runs `Commit.where(sha: "abc123...")`, finds the commit in `victim-org/victim-repo` (regardless of the payload's `repository` field), and calls `create_status_from_github!`, injecting a forged passing status that can unblock a deploy gated by that status context.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
