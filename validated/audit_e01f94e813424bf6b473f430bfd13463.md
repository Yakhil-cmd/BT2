## Finding [1](#0-0) , together with [2](#0-1)  and the process-wide crash handler at [3](#0-2) , expose an analog of the reported bug class: a crafted/malformed input value that is used without validation and later triggers an unhandled fatal error, crashing the whole process (the JS analog of a C NULL‑pointer dereference causing an unrecoverable crash on a malformed input file).

### Title
Uncaught exception crash via malformed `amount` in a private-payment chain link - (File: indivisible_asset.js)

### Summary
`validatePrivatePayment()` copies the previous private-chain element's unrevealed output `amount` straight into `objValidationState.src_coin.amount` without checking that it is a positive integer. `validatePaymentInputsAndOutputs()` in `validation.js` later asserts this invariant with `throw Error("no src coin amount")` instead of returning a normal validation error. Because this deep assertion runs inside nested asynchronous DB-callback chains with no enclosing `try/catch`, the `throw` becomes an unhandled exception. `network.js` installs a global `uncaughtException` handler that deliberately re-throws to kill the Node process ("crash the process to avoid ending up in an inconsistent state").

### Finding Description
A private-payment counterparty (i.e. the sender of a private asset payment, delivered device-to-device or via a hub) fully controls every element of the private-payment chain they send to a recipient's wallet. In the `transfer` branch of `validatePrivatePayment`:
```
var prev_hidden_output = objPrevPrivateElement.payload.outputs[input.output_index];
if (!prev_hidden_output)
    return callbacks.ifError("no prev hidden output");
...
objValidationState.src_coin = {
    src_output: src_output,
    denomination: payload.denomination,
    amount: prev_hidden_output.amount   // <-- never type/positivity checked
};
``` [4](#0-3) 

This `src_coin` is handed to `validation.validatePayment` → `validatePaymentInputsAndOutputs`, which enforces the invariant with hard `throw`s instead of callback errors:
```
if (!objValidationState.src_coin)
    throw Error("no src_coin");
var src_coin = objValidationState.src_coin;
if (!src_coin.src_output)
    throw Error("no src_output");
if (!isPositiveInteger(src_coin.denomination))
    throw Error("no denomination in src coin");
if (!isPositiveInteger(src_coin.amount))
    throw Error("no src coin amount");
``` [2](#0-1) 

The call path from an attacker-controlled message to this throw is:
`wallet.js handlePrivatePaymentChains` (device message `private_payment_chains`) or `network.js handleOnlinePrivatePayment` → `private_payment.js validateAndSavePrivatePaymentChain` → `indivisible_asset.js validateAndSavePrivatePaymentChain` → `parsePrivatePaymentChain` → `validatePrivatePayment` → `validation.js validatePayment` → `validatePaymentInputsAndOutputs`. [5](#0-4) [6](#0-5) 

Because `validatePaymentInputsAndOutputs` is entered from a `db.query` callback (an asynchronous re-entry point with a fresh call stack), the `throw` cannot be caught by any surrounding synchronous `try/catch` in the caller chain, so it surfaces as `process.on('uncaughtException', …)`, which explicitly re-throws to terminate the process:
```
process.on('uncaughtException', (err) => {
    ...
    throw err; // crash the process to avoid ending up in an inconsistent state
});
``` [3](#0-2) 

### Impact Explanation
Any wallet acting as a recipient/cosigner of a private asset can be crashed on demand by the sending counterparty simply by omitting or corrupting the `amount` field of an intermediate hidden output in the private-payment chain it sends. This is a full denial-of-service of the victim's ocore process (wallet, hub, or full node acting as a private-asset participant), matching the CVSS profile of the source report (availability-only impact, local/adjacent vector requiring the victim to receive and process the attacker's message).

### Likelihood Explanation
High for the specific actor class: the private-payment counterparty already has a private-payment relationship with the victim (a prerequisite that is trivial to establish, e.g. by initiating any private-asset transfer), fully controls the JSON content of every chain element it sends, and no field-level type/positivity validation exists on `amount` before it is consumed by the strict `throw`-based assertions in `validatePaymentInputsAndOutputs`.

### Recommendation
- In `indivisible_asset.js validatePrivatePayment`, validate `prev_hidden_output.amount` (and other externally supplied numeric fields reused as `src_coin.*`) with `ValidationUtils.isPositiveInteger` before assigning `objValidationState.src_coin`, and call `callbacks.ifError(...)` on failure instead of relying on a later `throw` inside `validation.js`.
- Convert the `throw Error("no src_coin")/"no src_output"/"no denomination in src coin"/"no src coin amount"` assertions in `validatePaymentInputsAndOutputs` (`validation.js`, lines ~2415-2424) into normal `callback(...)` validation errors, since their inputs originate (transitively) from attacker-supplied private-payment payloads, not from trusted internal state only.
- More generally, audit other `throw Error(...)` sites reachable from message/payload handling paths that assume "should never happen" invariants about attacker-influenced data, and convert them to graceful validation-error returns.

### Proof of Concept
1. Attacker Alice and victim Bob have (or Alice initiates) a private indivisible-asset relationship.
2. Alice sends Bob a private-payment chain (`private_payment_chains` device message, handled by `wallet.js handlePrivatePaymentChains`, or a direct `private_payment` justsaying handled by `network.js handleOnlinePrivatePayment`) containing at least two chain elements, where an intermediate element's `payload.outputs[output_index].amount` is set to a non-positive value (e.g. `0`, a negative number, or omitted) while all hash/spend-proof checks are otherwise kept consistent for that crafted amount.
3. Bob's node parses the chain via `parsePrivatePaymentChain` → `validatePrivatePayment`, copies the tampered `amount` into `objValidationState.src_coin.amount` uncontested, and later `validatePaymentInputsAndOutputs` throws `Error("no src coin amount")` from inside a `db.query` callback.
4. The exception is unhandled, reaches `process.on('uncaughtException', …)` in `network.js`, and the handler re-throws, terminating Bob's ocore process.

function validateAndSavePrivatePaymentChain(arrPrivateElements, callbacks){
	if (!ValidationUtils.isNonemptyArray(arrPrivateElements))
		return callbacks.ifError("no priv elements array");
	var headElement = arrPrivateElements[0];
	if (!headElement.payload)
		return callbacks.ifError("no payload in head element");
	var asset = headElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in head element");
	if (!ValidationUtils.isNonnegativeInteger(headElement.message_index))
		return callbacks.ifError("no message index in head private element");
	
	var validateAndSave = function(){
		storage.readAsset(db, asset, null, function(err, objAsset){
			if (err)
				return callbacks.ifError(err);
			if (objAsset.is_private !== 1)
				return callbacks.ifError("asset is not private");
			if (!!objAsset.fixed_denominations !== !!headElement.payload.denomination)
				return callbacks.ifError("presence of denomination field doesn't match the asset type");
			if (!!objAsset.fixed_denominations !== ("output" in headElement))
				return callbacks.ifError("divisible asset must not have output field, indivisible must");
			db.takeConnectionFromPool(function(conn){
				conn.query("BEGIN", function(){
					var transaction_callbacks = {
						ifError: function(err){
							conn.query("ROLLBACK", function(){
								conn.release();
								callbacks.ifError(err);
							});
						},
						ifOk: function(){
							conn.query("COMMIT", function(){
								conn.release();
								callbacks.ifOk();
							});
						}
					};
					// check if duplicate
					var sql = "SELECT address, denomination, amount, blinding FROM outputs WHERE unit=? AND asset=? AND message_index=?";
					var params = [headElement.unit, asset, headElement.message_index];
					if (objAsset.fixed_denominations){
						if (!ValidationUtils.isNonnegativeInteger(headElement.output_index))
							return transaction_callbacks.ifError("no output index in head private element");
						sql += " AND output_index=?";
						params.push(headElement.output_index);
					}
					conn.query(
						sql, 
						params, 
						function(rows){
							if (rows.length > 1)
								throw Error("more than one output "+sql+' '+params.join(', '));
							if (rows.length > 0 && rows[0].address){ // we could have this output already but the address is still hidden
								const stored = rows[0];
								const payload = headElement.payload;
								let bDuplicate = false;
								if (objAsset.fixed_denominations){ // the row we selected is exactly headElement.output_index, filtered in sql above
									const claimed_output = payload.outputs?.[headElement.output_index];
									const revealed_output = headElement?.output;
									bDuplicate =
										ValidationUtils.isNonemptyObject(claimed_output)
										&& ValidationUtils.isNonemptyObject(revealed_output)
										&& stored.denomination === payload.denomination
										&& stored.amount === claimed_output.amount
										&& stored.address === revealed_output.address
										&& stored.blinding === revealed_output.blinding;
								}
								else // divisible outputs are never hidden individually and sql has no output_index filter, so match against any of them
									bDuplicate = (payload.outputs || []).some(output => {
										return ValidationUtils.isNonemptyObject(output)
											&& stored.denomination === 1
											&& stored.amount === output.amount
											&& stored.address === output.address
											&& stored.blinding === output.blinding;
									});
								if (bDuplicate) {
									console.log("duplicate private payment "+params.join(', '));
									return transaction_callbacks.ifOk();
								}
							}
							var assetModule = objAsset.fixed_denominations ? indivisibleAsset : divisibleAsset;
							assetModule.validateAndSavePrivatePaymentChain(conn, arrPrivateElements, transaction_callbacks);
						}
					);
				});
			});
		});
	};
	
	if (conf.bLight)
