The protobuf.js issue is a JavaScript-specific code-injection bug: attacker-controlled schema defaults get spliced as literal source text into a dynamically generated `toObject` function body, which is then evaluated as executable JS. This vulnerability class has no meaningful analog in the Polkadot SDK's Rust/FRAME code, because:

- Rust code generation (proc-macros like `substrate/frame/support/procedural/src/pallet/expand/type_value.rs` and `substrate/frame/election-provider-support/solution-type/src/single_page.rs`) happens entirely at compile time over trusted, developer-authored source code — never over runtime/attacker-supplied data, and there is no `eval`-style mechanism that would execute dynamically assembled strings as code at runtime [1](#0-0) [2](#0-1) .
- Runtime handling of untrusted binary payloads (contracts/PVF code) goes through strict validators/instruction scanners rather than any form of source-text templating or `eval`, e.g. the syscall/opcode validation in `substrate/frame/revive/src/limits.rs` and the PVF `prevalidate`/`prepare` pipeline in `polkadot/node/core/pvf/src/testing.rs` [3](#0-2) [4](#0-3) .
- There is no `protobufjs` dependency or protobuf-descriptor-driven dynamic code generation anywhere in this repository (search for `protobufjs` returned no matches), so the specific attack surface (schema-controlled `bytes` field default value injected into generated JS) does not exist here at all.

Given the underlying invariant violated by the advisory — untrusted schema data being embedded as executable source in dynamically generated code — has no structural counterpart in this Rust/FRAME/WASM codebase, no valid analog finding can be reported.

pub fn validate_candidate(
	code: &[u8],
	params: &[u8],
) -> Result<Vec<u8>, Box<dyn std::error::Error>> {
	use polkadot_node_core_pvf_common::executor_interface::{prepare, prevalidate};
	use polkadot_node_core_pvf_execute_worker::execute_artifact;

	let code = sp_maybe_compressed_blob::decompress(code, 10 * 1024 * 1024)
		.expect("Decompressing code failed");

	let blob = prevalidate(&code)?;
	let executor_params = ExecutorParams::default();
	let compiled_artifact_blob = prepare(blob, &executor_params)?;

	let result = unsafe {
		// SAFETY: This is trivially safe since the artifact is obtained by calling `prepare`
		//         and is written into a temporary directory in an unmodified state.
		execute_artifact(&compiled_artifact_blob, &executor_params, params)?
	};

	Ok(result)
}
