### Title
Webhook signature is validated against an organization taken from the unauthenticated payload, while the event is actioned against a different repository field from the same payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to use for HMAC validation from an attacker-controlled field of the *unauthenticated* request body, but the downstream handler that actually mutates state (`PushHandler`) resolves the target `Repository`/`Stack` from a *different* field of that same body. In a multi-org Shipit deployment, an attacker can pick whichever configured organization has a blank/known `webhook_secret` to satisfy signature verification, while pointing the actual event at a completely different organization's repository.

### Finding Description
`verify_signature` derives the org used to pick the verifying secret from the payload itself, before any authentication has occurred: [1](#0-0) [2](#0-1) 

`repository_owner` (used only to pick which `GitHubApp` instance/secret to check against) is `params.dig('repository', 'owner', 'login')`. `Shipit.github(organization:)` looks up per-org config by that same attacker-supplied string: [3](#0-2) 

`GitHubApp#verify_webhook_signature` trivially returns `true` when the resolved org has no configured `webhook_secret`: [4](#0-3) 

Once signature verification passes, `Handler#stacks`/`repository_name` resolve the *actual* target repository from an entirely separate field of the same JSON body — `repository.full_name` — with no re-check that it belongs to the org that was authenticated: [5](#0-4) [6](#0-5) 

The binding broken is: **organization authenticated (`repository.owner.login`, used to select the verifying secret) ≠ repository written (`repository.full_name`, used to select the `Stack` acted upon)**. Nothing enforces that these two attacker-controlled strings, both read from the same unauthenticated body, refer to the same tenant. In the documented multi-org configuration schema (`config/secrets.development.shopify.yml`, `docs/setup.md`), each org can have its own (or no) `webhook_secret`: [7](#0-6) 

If any configured org has `webhook_secret: nil` (the documented default in `config/secrets.development.example.yml`), or if an attacker otherwise knows one org's secret, they can forge a signature "valid" for that org while `repository.full_name` names a stack belonging to a different, protected org/repo.

### Impact Explanation
A successful forgery lets an unauthenticated attacker drive `PushHandler#process`, which calls `stack.sync_github(expected_head_sha: params.after)` for any `Stack` resolvable via `Repository.from_github_repo_name(repository_name)` — i.e., any stack configured in the Shipit instance, regardless of which org's secret was used to pass the signature check. This forces the sync job to treat an attacker-chosen commit SHA as the expected head for a repository the attacker does not control, which can trigger unwanted deploy-eligibility state changes or "unauthorized deploy" preconditions for a repository outside the attacker's authenticated scope, satisfying the "unauthorized deploy" / cross-repository-write criteria in a multi-tenant Shipit instance.

### Likelihood Explanation
Requires a multi-org Shipit configuration (`github: <org>: ...` schema) where at least one configured org has no `webhook_secret` set (the example/documented default) or a secret known to the attacker. The webhook endpoint itself requires no authentication (`skip_before_action :verify_authenticity_token`), so any internet client can reach it once such a config exists.

### Recommendation
- Derive the organization used for signature verification from the same field(s) used by the handler to select the target repository/stack (or validate that both fields agree before acting).
- Do not allow `verify_webhook_signature` to return `true` when `webhook_secret` is blank in production/multi-org configurations; require an explicit secret per configured organization.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
