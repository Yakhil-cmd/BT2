### Title
Stack-Scoped API Token Bypasses `stack_id` Authorization in `CCMenuController` - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` resolution method inherited from `Shipit::Api::BaseController` and, in doing so, drops the enforcement that binds an `ApiClient`'s token to the single stack it was scoped to. Any token created with a `stack_id` restriction can be replayed against any other stack in the installation via this endpoint.

### Finding Description
`Shipit::Api::BaseController` establishes the trust binding: `token.authorized_stack == requested stack`. This is implemented by scoping the `stack` lookup through `stacks`, which filters by `current_api_client.stack_id` when the client is stack-scoped: [1](#0-0) 

`ApiClient` records can be created scoped to a single stack (`belongs_to :stack, optional: true`), and its permission check only verifies the operation/scope string (e.g. `read:stack`), never that the target stack matches the token's `stack_id`: [2](#0-1) 

The scoping to the *correct* stack is therefore enforced entirely inside `BaseController#stack`/`#stacks`, not inside `ApiClient#check_permissions!`. `CCMenuController` re-implements `stack` and bypasses that scoping entirely, resolving directly against the global `Stack` relation instead of the token-scoped `stacks` relation: [3](#0-2) 

So the equality that should hold — `requested_stack ∈ { current_api_client.stack_id }` when the client is stack-scoped — is broken specifically for this controller: `requested_stack ∈ Stack.all`, regardless of `current_api_client.stack_id`. The `require_permission :read, :stack` before_action only checks that `"read:stack"` is present in the token's `permissions` array; it says nothing about *which* stack, so a stack-scoped, read-only token still passes that check for a foreign stack.

`before ApiClient.creator's PR / configuration` vs `after`: before this endpoint existed/was used, an operator handing out a token scoped to `stack: shipit-app-production` (e.g. through the `ApiClientsController` UI) reasonably assumes it can only read/act on that one stack. After hitting `CCMenuController#show` with a different `stack_id` in the URL, the same token discloses build/deploy status for every other stack, because the controller-specific `stack` method never consults `current_api_client.stack_id`.

### Impact Explanation
This is an authorization-scope escape: a token deliberately restricted to one stack can be used to read another stack's state (last build status/label/time, stack name, web URL) via the CCMenu XML feed, matching the "unauthenticated/unauthorized read of stack state" High-impact category — the token authenticates but is not authorized for the touched stack, i.e. the binding `stack the token authorises` vs `stack it touches` is broken.

### Likelihood Explanation
Any holder of a legitimately-issued, stack-scoped `ApiClient` token (a common integration pattern per `ApiClientsController`/`ApiClient.stack` fixtures such as `here_come_the_walrus`) can trivially exploit this by changing the `stack_id` route/query parameter — no additional privileges, secrets, or session access are required beyond the token itself, which the attacker already legitimately possesses for one stack.

### Recommendation
Have `CCMenuController#stack` reuse the inherited, scope-aware `stacks` method (`stacks.from_param!(params[:stack_id])`) instead of querying `Stack.from_param!` directly, so that stack-scoped tokens can never resolve a stack outside `current_api_client.stack_id`.

### Proof of Concept
1. Admin creates an `ApiClient` scoped to `stack: stack_A` with permission `read:stack` (as supported by `ApiClient` and demonstrated by fixture `here_come_the_walrus`): [4](#0-3) 
2. Token holder requests `GET /api/<stack_B_owner>/<stack_B_name>/<stack_B_env>/ccmenu.xml?token=<token_scoped_to_stack_A>` where `stack_B` is any other stack in the installation.
3. `CCMenuController#authenticate_api_client` authenticates the token successfully (it is valid), then `CCMenuController#show` calls the overridden `stack` method, which resolves `stack_B` via unscoped `Stack.from_param!`, bypassing the `current_api_client.stack_id` check that `BaseController#stacks` would have enforced.
4. The response renders `stack_B`'s name, last build status/label/time, and web URL — data the token was never authorized to see.

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
