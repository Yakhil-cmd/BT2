### Title
Cross-stack CCMenu disclosure via un-scoped `stack` lookup - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::CCMenuController#stack` resolves the requested stack directly from `Stack.from_param!(params[:stack_id])` instead of `BaseController#stack`'s scoped `stacks.from_param!(params[:stack_id])`, and `#authenticate_api_client` bypasses the `stacks` scoping helper entirely. Combined with `ApiClient#check_permissions!` only checking permission *names* (`read:stack`) with no `stack_id` comparison, a token scoped to stack A can read deploy status for any stack B.

### Finding Description
The binding that must hold is: `params[:stack_id]` resolves to a stack S such that `S.id == current_api_client.stack_id` (when `stack_id` is set on the `ApiClient`). In `BaseController`, this is implemented as `stacks.from_param!(params[:stack_id])` where `stacks` is `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all` (`app/controllers/shipit/api/base_controller.rb:74-80`). `CCMenuController` overrides `stack` to call `Stack.from_param!(params[:stack_id])` directly (`app/controllers/shipit/api/ccmenu_controller.rb:29-31`), never touching `stacks`, so the scoping to `current_api_client.stack_id` is dropped entirely.

`require_permission :read, :stack` only triggers `require_permission!` → `current_api_client.check_permissions!(:read, :stack)` (`app/controllers/shipit/api/base_controller.rb:82-84`, `app/models/shipit/api_client.rb:38-45`), which checks `permissions.include?("read:stack")` — a pure string/name check with no reference to `stack_id` at all.

Attack: attacker obtains (e.g. pasted by an operator) a CCMenu URL like `GET /api/stacks/org/stack-a/ccmenu.xml?token=<token for ApiClient scoped to stack A>`. Attacker then requests `GET /api/stacks/org/stack-b/ccmenu.xml?token=<same token>`. `authenticate_api_client` verifies the token signature and loads the `ApiClient` row (valid, scoped to stack A) (`app/controllers/shipit/api/ccmenu_controller.rb:33-36`). `require_permission!` passes because the client does have `read:stack` permission (just for stack A). `#stack` then loads stack B unconditionally via `Stack.from_param!`, and `#show` renders stack B's latest deploy/rollback status in the CCMenu XML response — disclosed to an attacker who was never granted access to stack B.

No existing guard prevents this: `check_permissions!` doesn't know about `stack_id`; the `stacks` scoping that would enforce it is simply not used by this controller.

### Impact Explanation
Any holder of a stack-scoped CCMenu token can read deploy/build status (latest deploy, running state, timestamps) for *any other stack* in the Shipit instance, not just the one the token was issued for. This is an unauthenticated-scope-escalation read of stack state — matches the High severity category "unauthenticated read of stack state, task streams or deploy output." It's fully repeatable against arbitrary stacks by simply changing `params[:stack_id]` in the URL, with no additional cost per request.

### Likelihood Explanation
Preconditions are realistic and low-cost: any `ApiClient` scoped to a single stack with `read:stack` permission (a normal, non-privileged configuration used to hand out CCMenu URLs to CI dashboards), `Shipit.disable_api_authentication` false (default), and knowledge of one legitimate CCMenu URL/token (which is routinely shared/pasted since CCMenu URLs are meant to be embedded in tools like CCTray). The attacker needs no session, no secret, and no elevated role — just the token string and the target stack's slug (stack slugs are typically public/discoverable). This is trivial and repeatable.

### Recommendation
Make `CCMenuController#stack` reuse the scoped `stacks` collection from `BaseController` instead of querying `Stack` directly, e.g. `def stack; @stack ||= stacks.from_param!(params[:stack_id]); end`, and ensure `authenticate_api_client` still results in `current_api_client` being used consistently with the `stacks` scoping (remove the ad-hoc override or align it with `BaseController`'s scoped lookup logic).

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb (new test)
test "token scoped to stack A cannot read stack B's CCMenu status" do
  stack_a = shipit_stacks(:shipit)
  stack_b = shipit_stacks(:cyclid)

  api_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: 'scoped-client',
    stack: stack_a,
    permissions: ['read:stack'],
  )

  get :show, params: {
    stack_id: stack_b.to_param,
    token: api_client.authentication_token,
  }, format: :xml

  # Binding under test: params[:stack_id] resolved stack must equal
  # current_api_client.stack_id-authorized stack (stack_a), not stack_b.
  assert_response :forbidden # or :not_found — currently fails, returns :ok with stack_b's data
  refute_includes response.body, stack_b.deploys_and_rollbacks.last&.id.to_s
end
```
Currently this request returns `200 OK` and renders stack B's deploy/rollback data, confirming the cross-stack disclosure via `CCMenuController#stack` (`app/controllers/shipit/api/ccmenu_controller.rb:29-31`) bypassing the `stacks` scope enforced elsewhere (`app/controllers/shipit/api/base_controller.rb:74-80`).
