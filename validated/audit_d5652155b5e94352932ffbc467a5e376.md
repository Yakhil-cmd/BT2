### Title
Bridge `requestNonce` Re-org Causes Permanent KAIA/Token Lock in Service-Chain Bridge — (`contracts/service_chain/bridge/BridgeTransfer.sol`, `node/sc/bridge_manager.go`)

---

### Summary

The Kaia service-chain bridge assigns a sequential, content-independent `requestNonce` to every cross-chain value-transfer request. If a re-org on the source chain replaces a mined `RequestValueTransfer` transaction with a different one that receives the same nonce, the destination bridge permanently refuses to process the new canonical transfer because it already closed that nonce for the pre-reorg (now non-canonical) transaction. The result is a permanent lock of the user's deposited KAIA or tokens in the source bridge contract, with no recovery path.

---

### Finding Description

**Nonce assignment (source bridge)**

`BridgeTransferKLAY._requestKLAYTransfer` emits `RequestValueTransfer` with the current value of the contract-level counter `requestNonce`, then increments it:

```solidity
emit RequestValueTransfer(
    TokenType.KLAY, msg.sender, _to, address(0),
    msg.value.sub(_feeLimit), requestNonce, fee, _extraData
);
requestNonce++;
``` [1](#0-0) 

The same pattern exists in `BridgeTransferERC20._requestERC20Transfer` and `BridgeTransferERC721._requestERC721Transfer`. The nonce encodes no information about the transfer's content (`from`, `to`, `value`, `tokenType`). [2](#0-1) 

**Nonce-based deduplication (destination bridge)**

`handleKLAYTransfer` (and its ERC-20/ERC-721 siblings) uses `_requestedNonce` as the primary deduplication key:

```solidity
_lowerHandleNonceCheck(_requestedNonce);   // reverts if nonce < lowerHandleNonce
if (!_voteValueTransfer(_requestedNonce)) { // returns false if nonce already closed
    return;
}
_setHandledRequestTxHash(_requestTxHash);
handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber;
_updateHandleNonce(_requestedNonce);
``` [3](#0-2) 

Once a nonce is handled, `_updateHandleNonce` either advances `lowerHandleNonce` past it (making `_lowerHandleNonceCheck` revert for that nonce forever) or leaves `closedValueTransferVotes[nonce]` set (making `_voteValueTransfer` return false). Either path permanently blocks any future `handleXxxTransfer` call for that nonce. [4](#0-3) 

**Bridge operator does not filter removed logs**

The bridge manager's event loop receives `RequestValueTransfer` events from `WatchRequestValueTransfer` and forwards them unconditionally, without checking `ev.Raw.Removed`:

```go
case ev := <-chanReqVT:
    bm.reqVTevFeeder.Send(RequestValueTransferEvent{ev})
``` [5](#0-4) 

The filter system does deliver removed logs (re-org events) to `LogsSubscription` subscribers: [6](#0-5) 

**Recovery system also skips re-org'd nonces**

`retrievePendingEventsFrom` in `vt_recovery.go` calls `isHandledEvent`, which checks `HandleNoncesToBlockNums[nonce] > 0`. Because the destination bridge already recorded the pre-reorg nonce, the recovery system silently skips the new canonical event with the same nonce:

```go
if isHandledEvent(to, RequestValueTransferEvent{reqVTevIt.Event}) {
    continue
}
``` [7](#0-6) [8](#0-7) 

---

### Impact Explanation

**Permanent fund lock / unauthorized transfer of bridge reserves**

Concrete scenario (threshold = 1 operator, KLAY bridge):

| Step | Source chain | Destination bridge |
|---|---|---|
| 1 | Block B: tx H1 → `RequestValueTransfer(nonce=5, 100 KAIA → Alice)` | — |
| 2 | Bridge operator processes H1 | `HandleKLAYTransfer(H1, Alice, 100, nonce=5)` succeeds; `closedValueTransferVotes[5]` set; 100 KAIA sent to Alice |
| 3 | **Re-org**: Block B replaced by B′; tx H2 → `RequestValueTransfer(nonce=5, 200 KAIA → Bob)` | — |
| 4 | Bridge operator receives removed log for H1 (no `Removed` check) and new event H2 | Both trigger `HandleKLAYTransfer` calls for nonce=5 |
| 5 | — | `_voteValueTransfer(5)` returns false for H2 (nonce already closed); **Bob's 200 KAIA locked forever** |

Two simultaneous impacts:
1. **Unauthorized transfer**: 100 KAIA was sent from destination bridge reserves to Alice for a transfer that no longer exists on the canonical source chain.
2. **Permanent lock**: Bob's 200 KAIA deposited in the source bridge can never be released because the destination bridge permanently refuses nonce=5.

Both fall squarely within the allowed impact gate: unauthorized transfer of KAIA from bridge-managed funds, and permanent lock of bridged assets.

---

### Likelihood Explanation

Kaia uses IBFT consensus which provides single-block finality under normal operation, making re-orgs rare. However:

- The codebase explicitly implements and tests re-org handling (`blockchain.go:reorg`, `TestLogReorgs`, `TestChainTxReorgs`).
- The `isReorganizationRequired` function shows re-orgs are triggered by total block-score comparisons, which can occur during network partitions or sync.
- The service-chain bridge is designed to connect to external parent chains that may have weaker finality guarantees.
- The bridge manager's failure to check `ev.Raw.Removed` means any re-org that touches a `RequestValueTransfer` block triggers the vulnerability without any attacker action required — it is a passive, environmental trigger. [9](#0-8) 

---

### Recommendation

1. **Check `Removed` flag in the bridge event loop**: Before forwarding a `RequestValueTransfer` event, check `ev.Raw.Removed`. If true, remove the corresponding nonce from `pendingRequestEvent` rather than adding it.

2. **Bind nonce to content hash on-chain**: Include a `keccak256` hash of `(from, to, value, tokenType, extraData)` in the `RequestValueTransfer` event and require the bridge operator to pass it to `handleXxxTransfer`. The destination bridge should verify the hash matches before closing the nonce.

3. **Recovery system must re-validate canonical state**: `isHandledEvent` should cross-check that `handleNoncesToBlockNums[nonce]` refers to a block that is still canonical on the source chain before skipping an event.

---

### Proof of Concept

```
Source bridge (child chain):
  Block 100: Alice calls requestKLAYTransfer(Bob, 100 KAIA)
    → RequestValueTransfer(nonce=7, value=100, to=Bob, txHash=H1)

Bridge operator observes H1, calls:
  destination.HandleKLAYTransfer(H1, Alice, Bob, 100, nonce=7, blk=100)
  → closedValueTransferVotes[7] = set; Bob receives 100 KAIA on parent chain

Re-org on child chain:
  Block 100 replaced: Carol calls requestKLAYTransfer(Dave, 200 KAIA)
    → RequestValueTransfer(nonce=7, value=200, to=Dave, txHash=H2)
    (same nonce=7 because requestNonce counter was reset by re-org)

Bridge operator receives H1 with Removed=true (not checked) and H2:
  destination.HandleKLAYTransfer(H2, Carol, Dave, 200, nonce=7, blk=100)
  → _voteValueTransfer(7) returns false (nonce=7 already closed)
  → Carol's 200 KAIA permanently locked in source bridge
  → vt_recovery also skips nonce=7 (HandleNoncesToBlockNums[7] > 0)
``` [10](#0-9) [11](#0-10) [12](#0-11)

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil

// isReorganizationRequired returns if reorganization is required or not based on total blockscore.
func isReorganizationRequired(localTd, externTd *big.Int, currentBlock, block *types.Block) bool {
	reorg := externTd.Cmp(localTd) > 0
	if !reorg && externTd.Cmp(localTd) == 0 {
		// Split same-blockscore blocks by number, then at random
		reorg = block.NumberU64() < currentBlock.NumberU64() || (block.NumberU64() == currentBlock.NumberU64() && mrand.Float64() < 0.5)
	}
	return reorg
