### Title
Copilot API bearer token is attached to every outbound request regardless of destination host - ([File: pkg/cmd/agent-task/capi/client.go])

### Summary
`capiTransport.RoundTrip` unconditionally sets the `Authorization: Bearer <token>` header on every request it round-trips, instead of scoping the header to the intended Copilot API host. This mirrors the analog bug class from the reference report: a value that should be validated/scoped to a specific destination (`refundChain` → `wormholeTargetChainId`) is instead applied unconditionally/incorrectly, causing sensitive data to be sent to the wrong destination.

### Finding Description
`NewCAPIClient` mutates the caller-supplied `*http.Client` (obtained from `f.HttpClient()`, the CLI's general-purpose, GitHub-authenticated client) by wrapping its existing `Transport` with `capiTransport`: [1](#0-0) 

Inside `RoundTrip`, the Copilot bearer token is set on the request headers before checking anything about the destination host, and the code comment explicitly acknowledges the transport is shared between two different backends (Copilot API and GitHub API): [2](#0-1) 

Only the *additional* Copilot-specific headers (`Copilot-Integration-Id`, `X-GitHub-Api-Version`) are gated by `req.URL.Host == ct.capiHost`. The `Authorization` header carrying the actual credential is not gated at all — it is set for the request to whatever host it is destined for, including subsequent hops if the underlying transport chain follows a redirect to a different host.

This is architecturally inconsistent with the rest of the codebase, which treats cross-host header/credential leakage as a real threat. `AddAuthTokenHeader` in `api/http_client.go` explicitly detects a hostname change across a redirect and deliberately withholds the `Authorization` header when the host differs: [3](#0-2) 

`capiTransport` bypasses this protection for the specific client instance it wraps, because it sits in the transport chain and unconditionally injects its own `Authorization` header regardless of `req.URL.Host`, for every request (including redirected ones, since `net/http` invokes `RoundTrip` again for each redirect hop).

### Impact Explanation
If the wrapped `http.Client` is ever used to fetch a resource whose response redirects to (or whose target URL is derived from) an untrusted/attacker-influenced host — e.g., a session log URL or any other value returned by session/job data that this CAPI client methods might dereference — the Copilot bearer token would be sent to that host. This is a credential-exfiltration analog to the Wormhole refund-chain bug: a value/header that should only be scoped to the intended trusted destination is instead broadcast without a destination check, risking loss/leakage to the wrong target.

### Likelihood Explanation
I could not fully verify, within the scope of this investigation, whether any `CapiClient` method (e.g., `GetSessionLogs`) uses this shared `httpClient` to fetch a URL that is attacker-influenced or subject to redirect to a non-Copilot host — this would be required to make the path concretely reachable by an unprivileged remote attacker. The code confirms the missing host-check in `capiTransport.RoundTrip` as the root-cause pattern, but the full exploitation chain (an attacker-controlled redirect target reachable via this specific client) was not conclusively traced in the time available. This should be verified by inspecting `pkg/cmd/agent-task/capi/sessions.go`/`job.go` (`GetSessionLogs`, etc.) for any URL fetched via the same `httpClient` that originates from session data rather than a fixed, trusted API endpoint.

### Recommendation
Gate the `Authorization: Bearer` header the same way the `Copilot-Integration-Id` and `X-GitHub-Api-Version` headers are gated — only attach it when `req.URL.Host == ct.capiHost` — mirroring the host-check pattern already used in `AddAuthTokenHeader`. Additionally, avoid mutating a shared/passed-in `*http.Client` in place; construct a dedicated client/transport for CAPI-only traffic to prevent the credential from ever being applied to non-CAPI destinations.

### Proof of Concept
Not independently reproduced end-to-end (would require confirming a caller path that fetches an attacker-influenced or redirecting URL through the CAPI-wrapped `httpClient`). The root-cause code path is directly demonstrable:
1. `CapiClientFunc` passes the shared `f.HttpClient()` into `capi.NewCAPIClient`. [4](#0-3) 
2. `NewCAPIClient` mutates that client's `Transport` to `capiTransport`.
3. Any subsequent `RoundTrip` call through this client — for any host, including a redirect target — has `Authorization: Bearer <copilot-token>` set unconditionally, per lines 64–65 of `client.go`, with no host check comparable to the one used for the other Copilot-only headers.

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
```

```go
// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```
