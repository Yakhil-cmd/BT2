### Title
`GitHubApp#verify_webhook_signature` returns `true` when `webhook_secret` is blank, allowing unsigned/forged webhooks to bypass authentication - (File: lib/shipit/github_app.rb)

### Summary
`WebhooksController#verify_signature` delegates signature validation entirely to `GitHubApp#verify_webhook_signature`, which explicitly short-circuits to `true` whenever the app's `webhook_secret` is absent, regardless of the `X-Hub-Signature` header content. For any organization whose GitHub app config lacks a configured `webhook_secret`, any unauthenticated internet client can POST arbitrary, unsigned webhook payloads to `/webhooks` and have them processed as if they came from GitHub.

### Finding Description
The binding the audit is testing is: `github_app.webhook_secret == a non-nil, operator-configured secret` must imply `verified == false` whenever that binding fails (i.e., whenever `webhook_secret` is absent). Tracing the code shows this binding is explicitly violated by design: [1](#0-0) 

`verify_webhook_signature` starts with `return true unless webhook_secret`, meaning when `@webhook_secret = @config[:webhook_secret].presence` is `nil` (unset/blank in the org's config), the method returns `true` unconditionally — before ever inspecting the `X-Hub-Signature` header or the request body. [2](#0-1) 

`WebhooksController#verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` from the attacker-controlled `params.dig('repository','owner','login')` and calls `github_app.verify_webhook_signature(...)`. If that organization's app config in `Rails.application.credentials` (`secrets.github`) has no `webhook_secret` entry, `verified` is `true` for a request with no `X-Hub-Signature` header at all, and `head(422)` is never triggered — the request falls through to `create`, which parses `params` and dispatches to `Shipit::Webhooks.for_event(event)` handlers (push, status, membership, check_suite, pull_request, etc.), each of which writes application state (commits, statuses, team memberships, sync jobs) attributed to that organization.

None of the other guards intercept this: `GithubOrganizationUnknown` is only raised when the organization key is entirely missing from config, not when it exists with a blank secret; `drop_unhandled_event` only filters unrecognized event types; there is no `ExplicitParameters` schema or `force_github_authentication` check on this controller since it is intentionally unauthenticated (webhooks come from GitHub, not a logged-in user).

### Impact Explanation
For any organization configured in `secrets.github` without a `webhook_secret` value, an unauthenticated attacker can forge arbitrary GitHub webhook events (`push`, `status`, `check_suite`, `membership`, `pull_request`, etc.) for that organization's repositories. This can enqueue `GithubSyncJob`s, create/modify commit `Status` records, and add/remove `Team`/`Membership` records — writes attributed to a repository/organization the attacker never authenticated against. This matches the Critical category: authentication bypass on `/webhooks` leading to unauthorized writes of commit/task/team state for that organization. The attack is fully repeatable against any organization sharing this misconfiguration, and each request is independent (no rate limiting relevant here per scope).

### Likelihood Explanation
The precondition is that a Shipit operator has configured an organization app in `secrets.github` with the `webhook_secret` key absent or blank — this is a real config state the code explicitly tolerates (`@webhook_secret = @config[:webhook_secret].presence`), not merely hypothetical; nothing in the codebase enforces `webhook_secret` presence at config-load time (`app_id`/`installation_id`/`private_key` use `@config.fetch(...)`, which raises if missing, but `webhook_secret` uses `@config[:webhook_secret]`, tolerating absence). Given that, the attacker's cost is zero: no signature, no secret, no session, just an HTTP POST to `/webhooks` with a JSON body naming the target organization's login.

### Recommendation
In `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83), do not treat a missing `webhook_secret` as an automatic pass. Instead, either (a) fail closed — return `false` (or raise) when `webhook_secret` is blank, forcing operators to configure a secret before webhooks are accepted, or (b) fail fast at boot/config-load time by requiring `webhook_secret` similarly to how `app_id`/`installation_id`/`private_key` are required via `@config.fetch`, so a misconfigured organization cannot be onboarded at all.

test "unsigned webhook is rejected when organization has no configured webhook_secret" do
  # Arrange: organization "shopify" GitHubApp config built with webhook_secret: nil
  github_app = Shipit::GitHubApp.new('shopify', { app_id: 1, installation_id: 1, private_key: 'x', webhook_secret: nil })

  # Binding under test: webhook_secret absent => verified must be false => response must be 422
  assert_equal false, github_app.verify_webhook_signature(nil, payload)

end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
