### Title
Unbounded per-block stake-reward store work despite reward-distribution-block clamp - (File: `runtime/src/bank/partitioned_epoch_rewards/mod.rs`)

### Summary
`Bank::get_reward_distribution_num_blocks` clamps only the *number of distribution blocks* to `slots_per_epoch / 10`, not the amount of work done per block. Once the number of stake-reward recipients `M` exceeds `partitioned_rewards_stake_account_stores_per_block * (slots_per_epoch/10)`, the number of partitions used by `hash_rewards_into_partitions` is capped at `slots_per_epoch/10`, so each partition's average size grows linearly with `M`, and `store_stake_accounts_in_partition`/`store_accounts` must process a correspondingly unbounded slice within a single block.

### Finding Description
`get_reward_distribution_num_blocks` computes: [1](#0-0) 
```
let num_chunks = total_stake_accounts.div_ceil(stores_per_block) as u64;
num_chunks.clamp(1, (slots_per_epoch / 10).max(1))
```
The result, `num_partitions`, is the *only* input into `hash_rewards_into_partitions`: [2](#0-1) 
which hashes every stake reward's pubkey into one of `num_partitions` buckets. When `total_stake_accounts` is small enough that `num_chunks <= slots_per_epoch/10`, `num_partitions == num_chunks`, so average bucket size ≈ `stores_per_block` (the intended per-block bound). But once `total_stake_accounts` (`M`) grows large enough that `num_chunks` would exceed `slots_per_epoch/10`, the clamp forces `num_partitions = slots_per_epoch/10` — a constant independent of `M`. The average (and near-uniform, due to hashing) bucket size becomes `M / (slots_per_epoch/10)`, which scales linearly with `M` with no further ceiling.

Each block during the distribution phase calls `distribute_partitioned_epoch_rewards` → `store_stake_accounts_in_partition`, which iterates over exactly one bucket (`partition_rewards.partition_indices[partition_index]`) and calls `self.store_accounts` on the entire resulting slice in that single block: [3](#0-2) 
There is no secondary bound re-checked here against `partitioned_rewards_stake_account_stores_per_block`; the clamp in `get_reward_distribution_num_blocks` was the only mechanism intended to keep this work small, and it fails to do so for large `M`.

The existing tests (`test_get_reward_distribution_num_blocks_cap`) only assert that the *block count* saturates at the cap; they never check that per-partition (per-block) work stays bounded, so this gap is untested. [4](#0-3) 

An unprivileged attacker can grow `M` (the number of network-wide stake delegations that receive nonzero rewards) by creating many stake accounts and delegating them (to any existing validator's vote account — no control of that validator is required) using ordinary `system_instruction::create_account` + `stake_instruction::delegate_stake`. The minimum cost per account is the rent-exempt reserve for a `StakeStateV2` plus the minimum delegation amount, both of which are recoverable capital, not spent: [5](#0-4) 

### Impact Explanation
Once `M` grows well past `stores_per_block * (slots_per_epoch/10)`, every leader during the epoch-boundary reward-distribution window must execute `store_accounts` over a slice whose size scales with `M`, unboundedly, in a single block. This directly threatens the "bounded epoch-boundary work" invariant: CPU/IO cost per block during reward distribution is no longer capped by a fixed constant, and can be driven arbitrarily high by an attacker willing to fund enough stake accounts, risking leader block-production stalls / epoch-boundary halt across the whole cluster (every validator processes the same partitions on the same schedule).

### Likelihood Explanation
Requires no privileged access — only capital to create and delegate `M` stake accounts (rent-exempt reserve, recoverable) before an epoch boundary. Feasibility scales with available capital and the currently active `get_minimum_delegation` value (as low as 1 lamport pre-feature-activation, 1 SOL post-activation, both economically retrievable, not burned). The exploit is deterministic and repeatable every epoch as long as the attacker maintains the delegations.

### Recommendation
Bound the *size* of each partition directly (e.g., by capping `stake_account_stores_per_block` work per block via sub-chunking each hashed partition further, or by making `num_partitions` scale purely with `M / stores_per_block` without an upper clamp, instead bounding block count differently — e.g. spreading extra partitions across more blocks within the epoch, or processing a fixed number of accounts per block regardless of partition boundaries) so that per-block work is truly capped by a constant regardless of `M`.

### Proof of Concept
```rust
#[test]
fn test_partition_size_unbounded_by_num_blocks_clamp() {
    // Small epoch to make the 10% cap bite quickly.
    let slots_per_epoch = 432_000u64;
    let stores_per_block = 100u64;
    let cap = slots_per_epoch / 10; // 43_200

    // Choose M far larger than stores_per_block * cap so num_chunks would
    // exceed cap and get clamped.
    let m: u64 = stores_per_block * cap * 5; // 5x over the clamp threshold

    let stake_rewards = (0..m)
        .map(|_| Some(PartitionedStakeReward::new_random()))
        .collect::<PartitionedStakeRewards>();

    // num_blocks should be clamped to `cap`.
    let num_blocks = bank.get_reward_distribution_num_blocks(&stake_rewards);
    assert_eq!(num_blocks, cap);

    // But partition_indices sizes are NOT bounded by stores_per_block.
    let partition_indices =
        hash_rewards_into_partitions(&stake_rewards, &Hash::default(), num_blocks as usize);
    let max_partition_len = partition_indices.iter().map(|p| p.len()).max().unwrap();

    // Expected (bug): max_partition_len grows with M, e.g. ~M/cap = 5*stores_per_block,
    // violating the intended fixed per-block ceiling of ~stores_per_block.
    assert!(
        max_partition_len > (stores_per_block as usize) * 2,
        "per-block store work is not bounded by a fixed constant: got {max_partition_len}"
    );
}
```
Expected assertion result: `max_partition_len` scales proportionally to `M`, demonstrating that `store_stake_accounts_in_partition` (called once per block with exactly this slice) performs unbounded per-block work despite the block-count clamp.

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
