The reported bug class — a Solidity function lacking the `payable` modifier and therefore rejecting `msg.value` (ETH) when a trading module needs to receive the sell token — has no structural analog in this codebase's FRAME/`pallet-revive` model:

- Substrate/FRAME does not use Solidity's `payable` modifier concept at all. Native balance movement for extrinsics and precompile calls is driven by an explicit `value_transferred` field processed uniformly in `Contract::transfer_from_origin` regardless of any "payable" annotation on the target. [1](#0-0) 
- The one Solidity-interfaced module in this repo that performs DEX-style swaps involving the native token, `pallet_asset_conversion` precompiles' `IAssetConversion` interface, exposes `swapExactTokensForTokens`/`swapTokensForExactTokens`/`addLiquidity`/`removeLiquidity` as ordinary non-payable Solidity functions. [2](#0-1) 
- These functions never rely on `msg.value`/native call-value to move the native token; instead, the native leg of a swap is withdrawn/deposited from the caller's on-chain account balance via `pallet_asset_conversion::Pallet::swap`, keyed by `AccountId`, entirely independent of whether the precompile call itself carried any transferred value. [3](#0-2) 
- This is confirmed by the precompile's own tests, which call `bare_call` with value `0u64.into()` for native-token swaps and still observe correct balance debits/credits of the native asset, proving no `payable`-gated value path is involved. [4](#0-3) [5](#0-4) 

Because native-token accounting in FRAME is balance-based (via the `Currency`/`fungible` traits keyed by `AccountId`) rather than call-value-based (via `msg.value` requiring a `payable` modifier), there is no reachable code path where a missing "payable-equivalent" annotation would cause a revert or fund-lock when the native token is the traded asset. No genuine cross-boundary reachability, attacker-controlled input, or violated invariant analogous to the reported issue could be established.

	fn swap_exact_tokens_for_tokens(
		call: &IAssetConversion::swapExactTokensForTokensCall,
		env: &mut impl Ext<T = Runtime>,
	) -> Result<Vec<u8>, Error> {
		let path_len = Self::validated_path_len(&call.path)?;
		env.charge(
			<Runtime as pallet_asset_conversion::Config>::WeightInfo::swap_exact_tokens_for_tokens(
				path_len,
			),
		)?;
		let path: Vec<_> =
			call.path.iter().map(|e| Self::decode_asset_kind(e)).collect::<Result<_, _>>()?;

		let sender = Self::caller_account_id(env)?;
		let send_to = env.to_account_id(&H160(call.sendTo.0 .0));

		let amount_out = <pallet_asset_conversion::Pallet<Runtime> as Swap<
			<Runtime as frame_system::Config>::AccountId,
		>>::swap_exact_tokens_for_tokens(
			sender,
			path,
			Self::to_balance(call.amountIn)?,
			Some(Self::to_balance(call.amountOutMin)?),
			send_to,
			call.keepAlive,
		)?;

		Ok(IAssetConversion::swapExactTokensForTokensCall::abi_encode_returns(&Self::to_u256(
			amount_out,
		)?))
	}
