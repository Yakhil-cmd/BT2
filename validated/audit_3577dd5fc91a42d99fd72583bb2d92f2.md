### Title
`BridgeTransferERC20.handleERC20Transfer` Permanently DoS'd for Tokens Whose `mint` Returns No Value — (`contracts/service_chain/bridge/BridgeTransferERC20.sol`)

---

### Summary

`handleERC20Transfer` in `modeMintBurn` mode hard-casts the registered token address to `ERC20Mintable` and calls `mint` inside a `require`. The `ERC20Mintable` ABI declares `mint` as `returns (bool)`. The Solidity 0.5.x compiler therefore emits a return-data-size check: if the actual token's `mint` emits 0 bytes of return data (i.e., is declared `void`), the ABI decoder reverts before the `require` condition is even evaluated. Because the source-chain burn already succeeded in a prior transaction, the user's tokens are permanently destroyed with no corresponding mint on the destination chain.

---

### Finding Description

In `BridgeTransferERC20.sol` line 69:

```solidity
require(ERC20Mintable(_tokenAddress).mint(_to, _value), "handleERC20Transfer: mint failed");
```

`ERC20Mintable` is the OpenZeppelin v2 contract whose `mint` signature is:

```solidity
function mint(address account, uint256 amount) public onlyMinter returns (bool)
``` [1](#0-0) 

The Solidity compiler generates a return-data-size check for every high-level call to a function that declares a return type. If the actual token at `_tokenAddress` implements `mint` without a return value — e.g., `function mint(address to, uint256 amount) external` — the EVM returns 0 bytes. The compiler-generated check expects exactly 1 byte (`bool`), so it reverts unconditionally, regardless of whether the mint itself succeeded.

The call site is:

```solidity
if (modeMintBurn) {
    require(ERC20Mintable(_tokenAddress).mint(_to, _value), "handleERC20Transfer: mint failed");
}
``` [2](#0-1) 

The source-chain burn that precedes this is a separate, already-committed transaction triggered by `_requestERC20Transfer`:

```solidity
if (modeMintBurn) {
    ERC20Burnable(_tokenAddress).burn(_value);
}
``` [3](#0-2) 

`ERC20Burnable.burn` declares no return value, so it is immune to this class of bug. The asymmetry — burn succeeds, mint always reverts — is the root cause of asset loss.

---

### Impact Explanation

When `modeMintBurn` is active and the registered token's `mint` function does not return a `bool`:

1. The user calls `requestERC20Transfer` (or `onERC20Received`) on the source-chain bridge. The token is burned. This transaction succeeds and is irreversible.
2. Bridge operators call `handleERC20Transfer` on the destination-chain bridge. The `ERC20Mintable(_tokenAddress).mint(...)` call reverts due to the return-data-size mismatch. The entire transaction reverts, so no tokens are minted and no nonce is consumed.
3. Every subsequent operator attempt to handle the same nonce also reverts for the same reason.
4. The user's tokens are permanently destroyed on the source chain with no corresponding credit on the destination chain — a complete, unrecoverable loss of bridged assets.

The corrupted value is the recipient's token balance on the destination chain: it remains at zero instead of being credited with `_value`.

---

### Likelihood Explanation

The bridge owner registers tokens via `registerToken`. Many real-world mintable tokens (e.g., custom service-chain tokens, wrapped assets) define `mint` as `void` rather than `returns (bool)`. The OpenZeppelin v2 `ERC20Mintable` interface is not universally adopted. Any such token registered on a `modeMintBurn` bridge triggers this condition for every cross-chain transfer, making the DoS persistent and total for that token pair. [4](#0-3) 

---

### Recommendation

Replace the typed cast with a low-level call that tolerates both `returns (bool)` and `returns ()` mint signatures, analogous to how `SafeERC20.callOptionalReturn` works:

```solidity
// Instead of:
require(ERC20Mintable(_tokenAddress).mint(_to, _value), "handleERC20Transfer: mint failed");

// Use a safe wrapper:
(bool success, bytes memory data) = _tokenAddress.call(
    abi.encodeWithSignature("mint(address,uint256)", _to, _value)
);
require(success && (data.length == 0 || abi.decode(data, (bool))),
    "handleERC20Transfer: mint failed");
```

This mirrors the `callOptionalReturn` pattern already present in `SafeERC20`: [5](#0-4) 

---

### Proof of Concept

Deploy a token with a void `mint`:

```solidity
pragma solidity 0.5.6;
contract VoidMintToken {
    mapping(address => uint256) public balanceOf;
    // mint returns nothing — non-standard but common
    function mint(address to, uint256 amount) public {
        balanceOf[to] += amount;
    }
    function burn(uint256 amount) public {
        balanceOf[msg.sender] -= amount;
    }
    // ... minimal ERC20 stubs
}
```

1. Register `VoidMintToken` on both sides of a `modeMintBurn` bridge.
2. User calls `requestERC20Transfer` on the source bridge → tokens are burned → `RequestValueTransfer` event emitted.
3. Operator calls `handleERC20Transfer` on the destination bridge with the same parameters.
4. The call reverts with `EvmError: Revert` at the `ERC20Mintable(_tokenAddress).mint(...)` line because `VoidMintToken.mint` returns 0 bytes while the ABI decoder expects 1 byte.
5. User's tokens are gone from the source chain; destination balance is zero. [2](#0-1)

    function callOptionalReturn(IERC20 token, bytes memory data) private {
        // We need to perform a low level call here, to bypass Solidity's return data size checking mechanism, since
        // we're implementing it ourselves.

        // A Solidity high level call has three parts:
        //  1. The target address is checked to verify it contains contract code
        //  2. The call itself is made, and success asserted
        //  3. The return value is decoded, which in turn checks the size of the returned data.
        // solhint-disable-next-line max-line-length
        require(address(token).isContract(), "SafeERC20: call to non-contract");

        // solhint-disable-next-line avoid-low-level-calls
        (bool success, bytes memory returndata) = address(token).call(data);
        require(success, "SafeERC20: low-level call failed");

        if (returndata.length > 0) { // Return data is optional
            // solhint-disable-next-line max-line-length
            require(abi.decode(returndata, (bool)), "SafeERC20: ERC20 operation did not succeed");
        }
    }
