### Title
`collect_creator_fee` / `collect_creator_fee_permissionless` permanently locks creator fees if `pool_creator`'s token account is frozen by the mint's freeze authority - (File: `programs/cp-swap/src/instructions/collect_creator_fee.rs`, `programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs`)

### Summary
`collect_creator_fee` and `collect_creator_fee_permissionless` always send the accumulated `creator_fees_token_0`/`creator_fees_token_1` to an ATA owned by the fixed `pool_creator` address that was recorded at pool creation. If the token mint has a freeze authority (which `is_supported_mint` never checks or restricts) and that authority freezes the creator's token account, every attempt to collect the fee will revert, permanently trapping those fees inside the vault, exactly mirroring the reported bug class where a transfer to a fixed, potentially-restricted recipient causes a permanent revert.

### Finding Description
`is_supported_mint` in `programs/cp-swap/src/utils/token.rs` only inspects the Token-2022 *extension list* (`TransferFeeConfig`, `MetadataPointer`, `TokenMetadata`, `InterestBearingConfig`, `ScaledUiAmount`) to decide whether a mint can be used to create a pool. [1](#0-0) 
Freeze authority is a base mint field (present on both legacy SPL Token and Token-2022 mints), not an extension, so it is completely unchecked by this whitelist — pools are freely created for mints that have an active freeze authority.

`pool_creator` is fixed permanently at pool initialization: [2](#0-1) 

Both fee-collection instructions derive/require the destination token accounts as the ATA owned by that immutable `pool_creator`: [3](#0-2) [4](#0-3) 

The transfer to that destination account is a `transfer_checked` CPI via `transfer_from_pool_vault_to_user`, which will revert if the destination token account is frozen, exactly like the `IERC20.safeTransfer` revert in the original report when the recipient is blacklisted: [5](#0-4) 

Crucially, `creator_fees_token_0`/`creator_fees_token_1` are zeroed only *after* the transfer succeeds: [6](#0-5) 

and these amounts are subtracted from the pool's withdrawable balance in `vault_amount_without_fee`, meaning they are already segregated from LP-withdrawable liquidity and can only leave the vault via a successful collect call: [7](#0-6) 

If the freeze authority freezes `creator_token_0`/`creator_token_1` (the account is owned/controlled by `pool_creator`, but the freeze authority is a separate, unprivileged-with-respect-to-this-program third party — the mint's freeze authority, not a protocol admin or pool creator signer for this instruction), every future call to `collect_creator_fee` or the permissionless variant will revert forever with `AccountFrozen`, and the accrued creator fees become permanently unrecoverable.

### Impact Explanation
Funds equal to the accrued `creator_fees_token_0`/`creator_fees_token_1` become permanently locked inside the pool vault: they cannot be withdrawn by LPs (already excluded from LP-redeemable balance) and cannot be collected by the creator (transfer always reverts). This is a permanent freezing of protocol/creator funds triggered entirely by a third-party mint-level action reachable through the normal, unprivileged `collect_creator_fee_permissionless` path, matching the report's root cause (recipient-side transfer restriction blocking a stored, immutable transfer target) and the validation bar (permanent freezing of funds).

### Likelihood Explanation
Requires: (1) a Token-2022 mint with an active freeze authority to pass `is_supported_mint` and be used to create a pool — trivially possible since freeze authority isn't checked at all; (2) the freeze authority freezing the creator's ATA. Both are realistic since anyone can create a pool with an arbitrary Token-2022 mint (subject only to the extension whitelist, which does not cover freeze authority), and freeze authorities are a standard, documented feature of Token-2022/SPL Token that many token issuers retain.

### Recommendation
Extend `is_supported_mint` (or add an explicit check in `initialize`/`initialize_with_permission`) to reject mints that have a non-null freeze authority, unless explicitly allow-listed via `SupportMintAssociated`. Additionally, consider allowing an alternate/rescue recipient path for `collect_creator_fee`/`collect_creator_fee_permissionless` so accrued fees are not unconditionally tied to a single, potentially-frozen ATA.

### Proof of Concept
1. Create a Token-2022 mint with `freeze_authority = attacker` and no disqualifying extensions (e.g. only `TransferFeeConfig`), so `is_supported_mint` returns `true`.
2. Call `initialize` (or `initialize_with_permission`) to create a pool with this mint as `token_0_mint`/`token_1_mint`; `pool_creator` is set to `creator.key()`.
3. Perform swaps so `creator_fees_token_0`/`creator_fees_token_1` accrue in `pool_state`.
4. `attacker` (freeze authority) calls `FreezeAccount` on the creator's ATA for that mint (creating it first if necessary, or freezing after `init_if_needed` creates it on a prior legitimate collect attempt).
5. Call `collect_creator_fee_permissionless`; the `transfer_checked` CPI reverts with `AccountFrozen`, and the accrued creator fees remain permanently stuck in the vault with no code path to recover them.

pub fn transfer_from_pool_vault_to_user<'a>(
    authority: AccountInfo<'a>,
    from_vault: AccountInfo<'a>,
    to: AccountInfo<'a>,
    mint: AccountInfo<'a>,
    token_program: AccountInfo<'a>,
    amount: u64,
    mint_decimals: u8,
    signer_seeds: &[&[&[u8]]],
) -> Result<()> {
    if amount == 0 {
        return Ok(());
    }
    token_2022::transfer_checked(
        CpiContext::new_with_signer(
            *token_program.key,
            token_2022::TransferChecked {
                from: from_vault,
                to,
                authority,
                mint,
            },
            signer_seeds,
        ),
        amount,
        mint_decimals,
    )
}

pub fn is_supported_mint(
    mint_account: &InterfaceAccount<Mint>,
    mint_associated_is_initialized: bool,
) -> Result<bool> {
    let mint_info = mint_account.to_account_info();
    if *mint_info.owner == Token::id() {
        return Ok(true);
    }
    if mint_associated_is_initialized {
        return Ok(true);
    }
    let mint_data = mint_info.try_borrow_data()?;
    let mint = StateWithExtensions::<spl_token_2022::state::Mint>::unpack(&mint_data)?;
    let extensions = mint.get_extension_types()?;
    for e in extensions {
        if e != ExtensionType::TransferFeeConfig
            && e != ExtensionType::MetadataPointer
            && e != ExtensionType::TokenMetadata
            && e != ExtensionType::InterestBearingConfig
            && e != ExtensionType::ScaledUiAmount
        {
            return Ok(false);
        }
    }
    Ok(true)
}

            .checked_add(self.creator_fees_token_1)
            .ok_or(ErrorCode::MathOverflow)?;
        Ok((
            vault_0
                .checked_sub(fees_token_0)
                .ok_or(ErrorCode::InsufficientVault)?,
            vault_1
                .checked_sub(fees_token_1)
                .ok_or(ErrorCode::InsufficientVault)?,
        ))

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

    Ok(())
