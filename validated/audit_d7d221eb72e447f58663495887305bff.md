### Title
`GitHubApp#verify_webhook_signature` fails open when `webhook_secret` is unset for an organization - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the configured organization has no `webhook_secret`, and `WebhooksController#verify_signature` selects the `GitHubApp` instance purely from the attacker-controlled `repository.owner.login` / `organization.login` field in the JSON body. If any configured organization in `secrets.github` lacks a `webhook_secret`, an unauthenticated attacker can send arbitrary unsigned webhook bodies claiming that organization and have them processed as verified.

### Finding Description
The broken binding: the code implicitly assumes `webhook_secret.present? == true` for every configured organization, but nothing in the engine enforces that. The equality that should hold - "a request is treated as verified only if it was signed with that organization's secret" - collapses to "a request is treated as verified if that organization simply configured no secret," i.e. `verified == true` even when no HMAC check ever occurred.

Code path:
- `Shipit::WebhooksController#verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)`, where `repository_owner` is read straight from the untrusted JSON payload (`params.dig('repository','owner','login') || params.dig('organization','login')`) — [1](#0-0)  and [2](#0-1) .
- `Shipit.github(organization:)` builds/caches a `GitHubApp` from `secrets.github` config keyed by that organization name — [3](#0-2) .
- `GitHubApp#initialize` sets `@webhook_secret = @config[:webhook_secret].presence`, so a missing or blank value becomes `nil` — [4](#0-3) .
- `verify_webhook_signature` then does `return true unless webhook_secret`, bypassing the HMAC/`SecureCompare` check entirely when the secret is `nil` — [5](#0-4) .

Attacker request: `POST /webhooks` with header `X-Github-Event: <supported event>`, no valid `X-Hub-Signature` (or any arbitrary garbage value), and a JSON body whose `repository.owner.login` (or `organization.login`) matches the name of a configured organization whose `secrets.github[<org>][:webhook_secret]` is blank/unset. `verify_signature` calls `verify_webhook_signature` on that org's `GitHubApp`, which returns `true` without inspecting the signature or body at all, so `head(422)` is never triggered and `create` proceeds to dispatch `Shipit::Webhooks.for_event(event)` handlers on the attacker-supplied `params` — [6](#0-5) .

Why existing guards don't help: `drop_unhandled_event` only filters by event *type*, not by authenticity — [7](#0-6) ; `GithubOrganizationUnknown` is only raised when the organization name isn't configured at all, not when it's configured without a secret — [8](#0-7) ; there is no code path anywhere in the engine that requires `webhook_secret` to be present for a configured organization.

### Impact Explanation
For any organization configured with a blank `webhook_secret`, an unauthenticated remote attacker can submit fabricated webhook payloads (push, pull_request, status, etc.) that are treated as fully verified GitHub events for that organization's repositories, driving writes to `Stack`, `Commit`, `PullRequest`/`Task`, or `Team` records without ever having controlled the real GitHub repository or organization. This is a genuine authentication-bypass (Critical) for the affected tenant/organization; it does not, however, let an attacker forge events for a *different*, properly-configured organization (the `webhook_secret` for other orgs still gates their own `GitHubApp` instance), nor does it expose secrets or enable RCE by itself — the blast radius is scoped to whichever specific organization is misconfigured.

### Likelihood Explanation
This requires a precondition outside the attacker's control: a Shipit operator must have configured a per-organization multi-org `secrets.github` block for at least one organization while leaving that organization's `webhook_secret` blank/unset. This is a plausible operational mistake (webhook_secret being one of several optional-looking keys per org), and once it exists, the attacker doesn't need to discover it out-of-band — they can simply probe: submit a webhook claiming a target organization with a bogus signature and observe whether the controller responds `422` (rejected) or the event handler proceeds (indicating the secret is unset). This turns a config error into a directly, remotely, and repeatably discoverable and exploitable bypass, and each subsequent request against that organization is free and repeatable with no rate limiting on `POST /webhooks`.

### Recommendation
Change `GitHubApp#verify_webhook_signature` to fail closed: if `webhook_secret` is blank for a configured organization, reject the request (return `false`) rather than returning `true`, and/or add a boot-time/config validation in `Shipit.github_app_config` (or engine initialization) that raises if any entry under `secrets.github` (in multi-org mode) omits `webhook_secret`. At minimum, log loudly and refuse to process the organization's webhooks until it is fixed.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
