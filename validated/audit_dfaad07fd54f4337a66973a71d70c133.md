Now I have the crucial evidence: `process_stacking_ops` in `stackslib/src/chainstate/stacks/db/blocks.rs` executes the `stack-stx` Clarity contract call using `&sender.clone().into()` as the `tx-sender` principal for the contract call, with no separate cryptographic signature check tying that principal to a private key.### Title
Unauthenticated `PreStxOp.output` lets any Bitcoin-broadcaster impersonate an arbitrary Stacks account as `sender` for `StackStxOp`/`TransferStxOp`/`DelegateStxOp`, causing an unsigned stacking-lock (and for transfers, outright theft) - (File: stackslib/src/chainstate/burn/db/processing.rs)

### Summary
`check_transaction` explicitly skips validation for `BlockstackOperationType::PreStx` (`"no check() required for PreStx"`), so `PreStxOp.output` is accepted verbatim as the future `sender` for any chained `StackStxOp`/`TransferStxOp`/`DelegateStxOp`. Because `sender` is later used *directly* as the Stacks principal in `stack-stx`/`stx-transfer`-equivalent operations with no Stacks-transaction signature involved, an attacker can make any Stacks address (including a victim's) act as the authorizing principal for a lock or transfer, purely by choosing that address as the Bitcoin output of their own `PreStxOp`.

### Finding Description
The claimed equality is: `burnchain op's sender == the Stacks address whose private key authorized the spend`.

Trace:
1. `PreStxOp::parse_from_tx` (`stackslib/src/chainstate/burn/operations/stack_stx.rs:74-144`) sets `output` to whatever the first Bitcoin output of the transaction decodes to as a `StacksAddress` — this is attacker-chosen and never checked against any Stacks-layer proof of ownership.
2. `check_transaction` (`stackslib/src/chainstate/burn/db/processing.rs:82-85`) explicitly performs **no** `check()` for `PreStx`, unlike `StackStx`/`TransferStx`/`DelegateStx`, which do call `.check()`.
3. `Burnchain::from_burnchain_block_ops` (`stackslib/src/burnchains/burnchain.rs:900-992`) resolves `sender` for `TransferStxOp`, `StackStxOp`, and `DelegateStxOp` purely from `pre_stx.output` / `pre_stack_stx.output` — i.e., directly and unconditionally from the unchecked `PreStxOp.output` (lines 907, 936, 971).
4. When these ops are actually applied, `StacksChainState::process_stacking_ops` (`stackslib/src/chainstate/stacks/db/blocks.rs:4077-4185`) invokes the Clarity `stack-stx` entry point using `&sender.clone().into()` as the contract-call principal (`tx.run_contract_call(&sender.clone().into(), ...)`, line ~4122) — this bypasses the normal Stacks transaction signature-verification path entirely, since burnchain ops are not signed Stacks transactions.
5. `pox_4.rs`/`pox_5.rs` (`pox-locking/src/pox_4.rs:178-242`, `pox-locking/src/pox_5.rs:360-441`) then lock whatever amount the contract call reports for that `stacker` principal via `pox_lock_v4`/`pox_lock_v5`, requiring only that the named principal's account has sufficient *unlocked* balance — not that the principal cryptographically authorized the call.

Because `PreStxOp.output` is never checked, and it is the *sole* source of `sender` for all three downstream ops, an attacker can:
- craft a `PreStxOp` (real Bitcoin transaction, low cost) with `output` = victim's Stacks address,
- immediately submit a `StackStxOp` referencing that `pre_stx_txid` (or a `TransferStxOp`/`DelegateStxOp`), 
- and have the victim's account treated as the authorizing `sender`/`stacker` for a PoX lock (or, for `TransferStxOp`, a debit) — with no Stacks signature from the victim ever produced or checked.

None of the listed guards (`verify-not-prepare-phase`, `validate-no-reentrancy`/`signer-manager-call-active`, `check-pox-lock-period`, `verify-signer-key-grant`, `<=` guards, `parse_pox_stake_result`, coordinator cycle-start handlers) intervene at this layer — they all operate inside the Clarity contract-call boundary, which by this point has already been handed an attacker-chosen `tx-sender` equivalent with no signature check.

### Impact Explanation
- For `StackStxOp`/`DelegateStxOp`: the victim's unlocked STX gets force-locked for `num_cycles`/`until_burn_height` without their consent — an unsigned stacking action causing temporary freezing of the victim's STX (High).
- For `TransferStxOp`: the same unauthenticated `sender` is debited and an attacker-controlled `recipient` credited — this is a direct theft path (Critical), since no proof of the victim's private-key control of the `output`/`sender` address is ever required at the burnchain-op layer.
- Repeatable per victim/target address at the cost of one low-fee Bitcoin transaction pair (`PreStx` + chained op) per attempt.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to be able to broadcast ordinary Bitcoin transactions (already assumed capability) and know a target Stacks address with a nonzero unlocked STX balance. No privileged role, no signer key, no pox-5 membership is required — the burnchain op path is open to anyone who can fund a Bitcoin UTXO. This is highly feasible and repeatable.

### Recommendation
Require `check_transaction` to validate `PreStxOp` (e.g., verifying that the Bitcoin input(s) funding the `PreStxOp` are provably controlled by the Stacks address claimed in `output`, or otherwise cryptographically binding `output` to the entity broadcasting the op) before allowing it to be referenced as `sender` by `StackStxOp`/`TransferStxOp`/`DelegateStxOp`. At minimum, `process_stacking_ops`/`process_transfer_ops`/`process_delegate_ops` should not treat burnchain-op `sender` as equivalent to a signed `tx-sender` without an explicit ownership proof.

    pub fn parse_from_tx(
        block_height: u64,
        block_hash: &BurnchainHeaderHash,
        epoch_id: StacksEpochId,
        tx: &BurnchainTransaction,
        pox_sunset_ht: u64,
    ) -> Result<PreStxOp, op_error> {
        // can't be too careful...
        let num_inputs = tx.num_signers();
        let num_outputs = tx.num_recipients();

        if num_inputs == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                num_inputs, num_outputs,
            );
            return Err(op_error::InvalidInput);
        }

        if num_outputs == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                num_inputs, num_outputs,
            );
            return Err(op_error::InvalidInput);
        }

        if tx.opcode() != Opcodes::PreStx as u8 {
            warn!("Invalid tx: invalid opcode {}", tx.opcode());
            return Err(op_error::InvalidInput);
        };

        let outputs = tx.get_recipients();
        assert!(!outputs.is_empty());

        let output = outputs
            .get(0)
            .ok_or_else(|| {
                warn!("Invalid tx: first output not found");
                op_error::InvalidInput
            })?
            .as_ref()
            .ok_or_else(|| {
                warn!("Invalid tx: first output cannot be decoded");
                op_error::InvalidInput
            })?
            .address
            .clone()
            .try_into_stacks_address()
            .ok_or_else(|| {
                warn!("Invalid tx: first output must be representable as a StacksAddress");
                op_error::InvalidInput
            })?;

        // check if we've reached PoX disable
        if PoxConstants::has_pox_sunset(epoch_id) && block_height >= pox_sunset_ht {
            debug!(
                "PreStxOp broadcasted after sunset. Ignoring. txid={}",
                tx.txid()
            );
            return Err(op_error::InvalidInput);
        }

        Ok(PreStxOp {
            output,
            txid: tx.txid(),
            vtxindex: tx.vtxindex(),
            block_height,
            burn_header_hash: block_hash.clone(),
        })
    }

        clarity_tx: &mut ClarityTx,
        operations: Vec<StackStxOp>,
        active_pox_contract: &str,

        let mut all_receipts = vec![];
        let mainnet = clarity_tx.config.mainnet;
        let cost_so_far = clarity_tx.cost_so_far();
        for stack_stx_op in operations.into_iter() {
            let StackStxOp {
                sender,
                reward_addr,
                stacked_ustx,
                num_cycles,
                block_height,
                txid,
                burn_header_hash,
                ..
            } = &stack_stx_op;

                // this .expect() should be unreachable since we coerce the hash mode when
                // we parse the StackStxOp from a burnchain transaction

                    .as_clarity_tuple()
                    .expect("FATAL: stack-stx operation has no hash mode")

                        warn!("Skipping StackStx operation for txid: {}, burn_block: {} because of failure in collecting pox-4 stacking args: {}", txid, burn_header_hash, e);

                    }
                }
            }
            let result = clarity_tx.connection().as_transaction(|tx| {
                tx.run_contract_call(
                    &sender.clone().into(),
                    None,
                    &boot_code_id(active_pox_contract, mainnet),
                    "stack-stx",
                    &args,
                    |_, _| None,
                    &ResourceBudget::unlimited(),
                )
            });

/// Handle responses from stack-stx and delegate-stack-stx in pox-4 -- functions that *lock up* STX
fn handle_stack_lockup_pox_v4(
    global_context: &mut GlobalContext,
    function_name: &str,
    value: &Value,
) -> Result<Option<StacksTransactionEvent>, VmExecutionError> {
    debug!(
        "Handle special-case contract-call to {:?} {function_name} (which returned {value:?})",
        boot_code_id(POX_4_NAME, global_context.mainnet)
    );
    // applying a pox lock at this point is equivalent to evaluating a transfer
    runtime_cost(
        ClarityCostFunction::StxTransfer,
        &mut global_context.cost_track,
        1,
    )?;

    let (stacker, locked_amount, unlock_height) = match parse_pox_stacking_result(value) {
        Ok(x) => x,
        Err(_) => {
            // nothing to do -- the function failed
            return Ok(None);
        }
    };

    match pox_lock_v4(
        &mut global_context.database,
        &stacker,
        locked_amount,
        unlock_height,
    ) {
        Ok(_) => {
            // For direct stacking, we log the locked amount in the asset map.
            if function_name == "stack-stx" {
                global_context.log_stacking(&stacker, locked_amount)?;
            }

            let event =
                StacksTransactionEvent::STXEvent(STXEventType::STXLockEvent(STXLockEventData {
                    locked_amount,
                    unlock_height,
                    locked_address: stacker,
                    contract_identifier: boot_code_id(POX_4_NAME, global_context.mainnet),
                }));
            Ok(Some(event))
        }
        Err(LockingError::DefunctPoxContract) => Err(VmExecutionError::Runtime(
            RuntimeError::DefunctPoxContract,
            None,
        )),
        Err(LockingError::PoxAlreadyLocked) => {
            // the caller tried to lock tokens into multiple pox contracts
            Err(VmExecutionError::Runtime(
                RuntimeError::PoxAlreadyLocked,
                None,
            ))
        }
        Err(e) => {
            panic!(
                "FATAL: failed to lock {locked_amount} from {stacker} until {unlock_height}: '{e:?}'"
            );
        }
    }
}

/// Handle responses from pox-5 entry points that lock STX for a staker:
/// `stake` (STX-only) and `register-for-bond` (protocol bond). A first-time
/// call (no existing pox-5 lock) acquires a fresh lock via
/// [`pox_lock_v5`]; a roll-over (the account is already locked from an
/// ending bond or stake) carries the lock forward via
/// [`pox_rollover_v5`] -- the amount may go up or down and the
/// unlock height is rescheduled, so the lock never releases. The contract
/// is responsible for gating the roll-over (non-overlap + L1 unlock window
/// for bond sources); if the contract returns ok, this handler trusts the
/// call is legitimate.
fn handle_lockup_pox_v5(
    global_context: &mut GlobalContext,
    function_name: &str,
    value: &Value,
) -> Result<Option<StacksTransactionEvent>, VmExecutionError> {
    debug!(
        "Handle special-case contract-call to {:?} {function_name} (which returned {value:?})",
        boot_code_id(POX_5_NAME, global_context.mainnet)
    );
    runtime_cost(
        ClarityCostFunction::StxTransfer,
        &mut global_context.cost_track,
        1,
    )?;

    let parsed = parse_pox_stake_result(value).map_err(|e| {
        locking_error_to_vm_error(e, &format!("pox-5 {function_name}: bad response"))
    })?;
    let (staker, locked_amount, unlock_height) = match parsed {
        ParsedStakeResult::Ok {
            staker,
            amount_ustx,
            unlock_burn_height,
        } => (staker, amount_ustx, unlock_burn_height),
        ParsedStakeResult::ContractErr => return Ok(None),
    };

    // A staker rolling from one bond/stake position into another is already
    // locked; carry the lock forward instead of acquiring a fresh one (which
    // would fail with `PoxAlreadyLocked`). A first-time call locks fresh.
    let already_locked = {
        let mut snapshot = global_context.database.get_stx_balance_snapshot(&staker)?;
        snapshot.has_locked_tokens()?
    };

    let lock_result = if already_locked {
        pox_rollover_v5(
            &mut global_context.database,
            &staker,
            unlock_height,
            locked_amount,
        )
        .map(|_| ())
    } else {
        pox_lock_v5(
            &mut global_context.database,
            &staker,
            locked_amount,
            unlock_height,
        )
    };

    match lock_result {
        Ok(()) => {
            // Log the staking in the asset map
            global_context.log_stacking(&staker, locked_amount)?;

            let event =
                StacksTransactionEvent::STXEvent(STXEventType::STXLockEvent(STXLockEventData {
                    locked_amount,
                    unlock_height,
                    locked_address: staker,
                    contract_identifier: boot_code_id(POX_5_NAME, global_context.mainnet),
                }));
            Ok(Some(event))
        }
        Err(e) => Err(locking_error_to_vm_error(
            e,
            &format!("pox-5 {function_name}: failed to lock {locked_amount} from {staker} until {unlock_height}"),
        )),
    }
}
