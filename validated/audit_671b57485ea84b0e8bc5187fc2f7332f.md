### Title
`compute_v2_review_set` drops dangerous committed changes from review after `git commit --amend` due to `_is_ancestor` ancestry check failing on amended commits - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` only folds committed changes into `dirty_now` when `head_at_capture` is a git ancestor of the current `HEAD`. `git commit --amend` replaces the tip commit with a new, sibling commit object that is *not* a descendant of the pre-amend commit, so `_is_ancestor` returns `False` and the committed diff is never added to `dirty_now`. Because `review_set = dirty_now ∩ changed_since`, a dangerous change that was folded into the working tree via `--amend` is excluded from the review set even though `changed_since` (a raw content diff against the pre-turn baseline) correctly still contains it.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is invoked from `handle_user_prompt_submit` on every `UserPromptSubmit`, recording `baseline_sha` (via `git stash create`, falling back to `HEAD`) and `head_at_capture` (`security_reminder_hook.py:468-498`). At `Stop`, `compute_v2_review_set` (`diffstate.py:353-438`) derives the file set to send to the LLM reviewer as:

```
review_set = dirty_now ∩ changed_since   (diffstate.py:401-426)
```

- `dirty_now` starts from `git status --porcelain` (content differs from current `HEAD`) plus new untracked files.
- If `head_at_capture` is an ancestor of the current `HEAD` (`_is_ancestor`, `gitutil.py:377-387`, backed by `git merge-base --is-ancestor`), committed files from `head_at_capture..HEAD` are unioned into `dirty_now` and `diff_base` becomes `head_at_capture` (`diffstate.py:403-408`).
- `changed_since` is a raw tree-content diff between `baseline_sha` and the current worktree (`_git_name_only`, `gitutil.py:303-327`), independent of commit history/ancestry.

Exploit flow: at turn start, `head_at_capture = C0` (clean repo). Claude edits a dangerous file and runs `git commit --amend` on `C0` (rather than a normal `git commit`, which would create a proper child commit). `git commit --amend` produces a new commit `C0'` that shares `C0`'s parent — it is a sibling, not a descendant, of `C0`. Consequently `_is_ancestor(C0, C0')` returns `False`, so the `head_at_capture..HEAD` term is skipped and `dirty_now` no longer contains the dangerous file (the working tree is clean relative to the new `HEAD=C0'`). However, `changed_since = git diff --name-only baseline_sha(C0)` (content diff against the worktree at `C0'`) still correctly reports the file as changed. The intersection `dirty_now ∩ changed_since` therefore silently drops the dangerous file from `review_set`, even though the file content genuinely diverges from the session baseline and was authored during the session.

This breaks the stated invariant ("the review set must stay bound to the right repo, baseline, and touched paths") because a real, in-scope, baseline-diverging change is excluded purely due to how the commit was made (amend vs. plain commit), not due to any legitimate pre-existing/off-scope reasoning.

### Impact Explanation
This causes the Stop-hook's security review (`analyze_code_security` / agentic review pipeline gated on the review set) to silently skip a dangerous, session-authored change, defeating the entire purpose of the plugin: catching vulnerabilities introduced during a Claude Code turn before the turn ends. This is a "wrong-target/skip" class bug matching the stated Immunefi impact of "Cross-repo, cross-session, or wrong-target mutation with real security impact" — here it manifests as within-session content that should be reviewed and blocked (exit code 2 forcing remediation) instead passing through unreviewed, allowing a dangerous change to ship silently. The trigger requires only normal, unprivileged git usage (`git commit --amend`) that Claude Code or a user-directed agent routinely performs, no elevated privileges or exploitation of parsing/injection needed.

### Likelihood Explanation
High feasibility: `git commit --amend` is an extremely common, ordinary git operation, not adversarial tooling. Any workflow where Claude amends a commit it just made in the same turn (a very common pattern — "let me fix that commit message" or "let me fold this into that commit") triggers the gap deterministically, without any awareness that it disables review. No special repo state, permissions, or timing races are required beyond a single amend of the turn's own commit.

### Recommendation
Do not rely solely on ancestry (`_is_ancestor`) to decide whether to add commit-range diffs to `dirty_now`. Instead, always include committed-but-baseline-differing files by relying primarily on `changed_since` (content diff against `baseline_sha`) as the driving set, using `dirty_now`/ancestry only to prioritize or double-check, not to gate inclusion. Concretely, when `changed_since` is available (`baseline_sha` valid), the review set should default to `changed_since` (optionally still capped/filtered by `dirty_now` for untracked exclusion logic) rather than intersecting with an ancestry-dependent `dirty_now`. Alternatively, detect amend/rebase (`HEAD` moved but `head_at_capture` isn't an ancestor) and fall back to reviewing `changed_since` directly instead of intersecting to `dirty_now`.

### Proof of Concept
Unit/integration test in the existing `compute_v2_review_set` test suite:
1. Init a repo, commit `C0` containing a benign file `f.py`.
2. Simulate UPS: `baseline_sha, head_at_capture = capture_git_baseline(repo)` and `_git_rev_parse_head(repo)` → both equal `C0` (clean tree).
3. Simulate Claude editing `f.py` to add a dangerous pattern (e.g. `os.system(user_input)`), then run `git commit --amend --no-edit` (not a plain `git commit`).
4. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
5. Assert `review_paths` (the review set) **contains** the absolute path to `f.py`.
6. Expected current (buggy) behavior: `review_paths == []` because `_is_ancestor(C0, C0')` is `False`, so `dirty_now` is empty and the intersection with `changed_since` (which does contain `f.py`) yields nothing — demonstrating the dangerous change is skipped.
7. As a control, repeat with a plain `git commit` (not `--amend`) instead of amend, and assert the file IS included — confirming the divergence is specifically caused by the amend/ancestry interaction.
