### Title

Unbounded RAY accrual can permanently freeze a large market through `update_indexes` - (contracts/pool/src/interest.rs)

### Summary

`Controller::update_indexes` is permissionless for any authorized caller and accepts attacker-selected `HubAssetKey` values. [1](#0-0)  Every pool mutation loads the market through `synced_market`, which runs `interest::global_sync` before executing the requested operation. [2](#0-1)  If scaled debt multiplied by the accrued borrow index exceeds `i128::MAX`, accrual panics before the market timestamp is committed; the existing regression test demonstrates that repayments and withdrawals then fail permanently with `MathOverflow`. [3](#0-2) [4](#0-3) 

### Finding Description

`global_sync` advances every elapsed interval and calls `accrue_chunk` for each chunk, but commits the accrued timestamp only after all chunks complete. [5](#0-4)  Each chunk calls `accrue_step` with the market’s scaled borrowed balance, scaled supplied balance, borrow index, and supply index. [6](#0-5)  Pool accounting repeatedly converts scaled balances back to original value using `scaled_to_original`; for the borrow side this evaluates the scaled debt against `borrow_index`. [7](#0-6) 

For a sufficiently large scaled debt, index growth can make the exact debt value exceed the `i128` range before `MAX_BORROW_INDEX_RAY` is reached. The regression test uses a billion-unit, 18-decimal market at 98% utilization and observes `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [8](#0-7) 

The panic happens before `mark_accrued`, so transaction rollback leaves the stale market timestamp unchanged. [9](#0-8)  The next operation repeats accrual from the same timestamp and reaches the same overflow, making the condition self-reinforcing rather than a one-call failure. [2](#0-1) 

### Impact Explanation

Once the boundary is crossed, no operation that touches that market can complete accrual. [10](#0-9)  The in-repository proof shows both a supplier withdrawal and a borrower repayment failing with `MathOverflow` after the first failed index update. [11](#0-10)  Because liquidation, bad-debt processing, and recapitalization also must operate through synchronized pool-market accounting, an affected debt market can leave borrower collateral and supplier principal locked and prevent normal loss containment. [12](#0-11)  This satisfies the permanent-freezing impact class; absent a code upgrade or separate recovery path, the stored accounting state remains unusable.

### Likelihood Explanation

The triggering call itself is permissionless: any caller can submit `update_indexes(caller, [hub_asset])`. [1](#0-0)  The expensive precondition is a very large scaled debt balance and enough accrued index growth to make the debt value exceed `i128`; the demonstrated setup uses an 18-decimal market holding `BILLION * 10^18` units with 98% borrowed. [13](#0-12)  An attacker does not need oracle manipulation, privileged access, malformed calldata, or a victim signature; once either attacker-created or naturally accumulated market state approaches the bound, the attacker only invokes normal supply, borrow, and index-maintenance entrypoints. [14](#0-13)  The severity is best treated as Medium because the impact is permanent market freezing, but reaching the arithmetic bound requires an exceptionally large market and sustained interest accrual.

### Recommendation

Enforce the borrow-index and debt-value bounds before converting scaled debt back to an `i128` value. In particular, `accrue_step` should compute the post-accrual debt/index product in widened arithmetic and clamp `borrow_index` at `MAX_BORROW_INDEX_RAY` before `scaled_to_original` can overflow. The accrual should commit a capped index and current timestamp rather than revert, so repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization remain available. Add a regression assertion that the index cap engages before the value conversion and that exit paths still succeed at the boundary.

### Proof of Concept

1. Create or use a listed 18-decimal market with enough collateral and liquidity, supply `BILLION * 10^18` raw units from an unprivileged account, and borrow 98% of that principal through `Controller::borrow`; the existing regression performs this setup. [13](#0-12) 
2. Allow interest to accrue until the scaled debt multiplied by the next borrow index exceeds `i128::MAX`, while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [15](#0-14) 
3. Call `Controller::update_indexes(attacker, vec![HubAssetKey { hub_id, asset }])`; the call reaches `Cache::load → global_sync → accrue_step` and returns `MathOverflow`. [1](#0-0) [2](#0-1) 
4. Retry `withdraw` or `repay` for the same market; both repeat accrual and fail with `MathOverflow`, leaving the supplier’s funds and the borrower’s repayment path frozen. [11](#0-10)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
