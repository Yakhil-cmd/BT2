### Title
Webhook Signature Verification Silently Bypassed When `webhook_secret` Is Unset, Enabling Unauthenticated Forgery of `membership` Events and Escalation into `Shipit.github_teams` Authorization - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` whenever the configured `webhook_secret` is blank, which is the documented default for a Shipit installation. Combined with `WebhooksController` picking the GitHub App/secret to verify against using an attacker-controlled field of the same JSON body, and with `MembershipHandler` trusting the payload's `team`/`organization`/`member` fields to mutate `Team` membership, an unauthenticated actor can forge a `membership` webhook that inserts themselves into any `Team` matching `Shipit.github_teams`, directly bypassing the authorization gate enforced by `User#authorized?`.

### Finding Description
`WebhooksController#verify_signature` resolves the GitHub App configuration to check the signature against using data taken straight from the untrusted payload: [1](#0-0) [2](#0-1) 

The actual signature check is: [3](#0-2) 

`return true unless webhook_secret` means that for any organization configured without a `webhook_secret`, **every** request is treated as verified regardless of the `X-Hub-Signature` header or body content. Leaving `webhook_secret` unset/nil is the documented default configuration shipped in the setup examples and generator template: [4](#0-3) [5](#0-4) 

Once past `verify_signature`, the raw JSON is dispatched to registered handlers with no further authentication: [6](#0-5) 

`MembershipHandler` takes the `team`, `organization`, and `member` objects directly from the payload and mutates `Team` membership without any secondary confirmation against GitHub's API: [7](#0-6) 

`Team#add_member` simply appends the resolved `User`: [8](#0-7) 

This membership is exactly what gates application access: [9](#0-8) [10](#0-9) 

**The broken binding, expressed as an equality that fails:**
`organization that authenticated the webhook request` (derived from `repository_owner`/`organization.login` in the attacker-supplied JSON, and only checked at all when a `webhook_secret` happens to be configured) ≠ `identity actually granted Team membership` (`params.member.login`, `params.team`, `params.organization.login`, taken from the same untrusted body with no cryptographic guarantee when `webhook_secret` is blank). This mirrors the analog rule of "an organization that authenticated versus the repository that is written" — here the mutated resource is `Team`/`Membership` rather than a repository row, and the authentication step that should bind the claim to the real GitHub organization is a no-op by default.

### Impact Explanation
An attacker who has no Shipit session, no `ApiClient` token, no `webhook_secret`, and no GitHub App private key can add an arbitrary GitHub login (their own account) to any `Team` whose handle appears in `Shipit.github_teams`. Since `User#authorized?` checks only `teams.where(id: Shipit.github_teams...)`, once the attacker subsequently completes normal OAuth login with that GitHub account, `force_github_authentication` will treat them as authorized, granting them full access to stacks, deploys, and rollback/merge actions gated behind team membership. This satisfies the "escalation into `Shipit.github_teams` authorization" High-impact category.

### Likelihood Explanation
The precondition — an organization entry with `webhook_secret` left blank — is not a misconfiguration outside the documented setup; it is the value shown in the shipped example/development secrets files and the install `template.rb`. Any installation that has not explicitly generated and set a webhook secret for every configured GitHub organization is exploitable by a purely network-reachable, credential-less attacker who can reach the mounted `WebhooksController` endpoint.

### Recommendation
- Make `webhook_secret` presence mandatory: fail closed (reject the request) when `webhook_secret` is blank instead of `return true unless webhook_secret` in `lib/shipit/github_app.rb`.
- For `MembershipHandler` (and other handlers that mutate authorization-relevant state), do not trust payload-declared team/organization/member relationships blindly; re-verify against the GitHub API (e.g., re-fetch team membership via `Team#refresh_members!`) before persisting `added` actions.
- Add a startup/config validation (similar to `Shipit.all_settings_present?`) that raises if any configured GitHub organization is missing a `webhook_secret`.

### Proof of Concept
1. Target a Shipit deployment where at least one configured GitHub organization has no `webhook_secret` set (the documented default).
2. POST to the mounted webhooks endpoint with header `X-Github-Event: membership` and a JSON body:
```json
{
  "action": "added",
  "team": { "id": 999, "name": "Shopify Developers", "slug": "developers", "url": "https://api.github.com/teams/999" },
  "organization": { "login": "shopify" },
  "member": { "login": "attacker-github-login" }
}
```
3. `WebhooksController#verify_signature` resolves `Shipit.github(organization: "shopify")`; because that org's `webhook_secret` is blank, `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-83`), no valid `X-Hub-Signature` is required.
4. `MembershipHandler#process` runs, calling `find_or_create_team!` and `team.add_member(member)` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-43`), inserting `attacker-github-login` into the `Team` matching `shopify/developers`.
5. If `shopify/developers` is part of `Shipit.github_teams`, the attacker logs in via GitHub OAuth with `attacker-github-login`; `User#authorized?` (`app/models/shipit/user.rb:80-82`) now returns `true`, and `force_github_authentication` (`app/controllers/concerns/shipit/authentication.rb:20-34`) grants full application access.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
