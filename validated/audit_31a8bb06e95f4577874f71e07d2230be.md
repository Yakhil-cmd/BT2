### Title
Webhook signature is verified against `repository.owner.login`'s secret while the handler acts on the unrelated `repository.full_name` field, allowing cross-organization stack teardown - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization config (and therefore which `webhook_secret`) to verify the HMAC against using `params.dig('repository', 'owner', 'login')`, a field taken from the raw, attacker-controlled JSON body. `ClosedHandler#repository`, however, resolves the actual target repository using a *different* field of the same body, `params.repository.full_name`. Nothing ties these two fields together, so an attacker can sign (or exploit a secret-less) organization A while pointing the payload's `repository.full_name` at organization B's repository, causing `ReviewStackAdapter#archive!` to deprovision and archive B's review stack.

### Finding Description
The intended binding is: **the organization whose `webhook_secret` authenticates the request == the organization that owns the repository being mutated**. In code this should mean `params.repository.owner.login == owner_of(params.repository.full_name)`, but the two are read from independent, attacker-suppliable JSON fields with no cross-check.

Trace:
- `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and fetches `Shipit.github(organization: repository_owner)`, then calls `github_app.verify_webhook_signature(signature, raw_post)`. [1](#0-0) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally "unless webhook_secret" is configured for that organization — i.e., if org A has no `webhook_secret` set (an optional config field, `@webhook_secret = @config[:webhook_secret].presence`), *any* payload naming `repository.owner.login = "orgA"` passes verification with zero cryptographic knowledge. [2](#0-1) [3](#0-2) 
- After passing this check, `WebhooksController#create` dispatches to `Shipit::Webhooks.for_event(event)` handlers with the full, unmodified `params` (the same JSON body). [4](#0-3) 
- `ClosedHandler#repository` resolves the target repo from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`, a field entirely separate from `repository.owner.login` used above. [5](#0-4) 
- `ClosedHandler#process` then calls `review_stack.archive!`, which is `ReviewStackAdapter#archive!`, performing `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!(user, ...)` — a real, destructive, deploy-affecting action — scoped to `repository.review_stacks` for whatever repository `full_name` named. [6](#0-5) [7](#0-6) 

Attacker's exact request: an unauthenticated `POST /webhooks` with header `X-Github-Event: pull_request`, `X-Hub-Signature` computed (or omitted/anything, if org A has no secret) for organization A, and a JSON body where `repository.owner.login = "orgA"` but `repository.full_name = "orgB/victim-repo"`, `action = "closed"`, `number = <PR number of B's active review stack>`. Since `Shipit.github(organization: 'orgA')` must resolve to a *configured* organization (raising `GithubOrganizationUnknown` → 422 otherwise), the attacker needs org A to be one of the Shipit-configured GitHub organizations lacking a `webhook_secret` (this field is optional per the config schema seen in `test/dummy/config/secrets.yml`, `webhook_secret: # nil`), or one whose secret has otherwise leaked. Neither `drop_unhandled_event`, `ExplicitParameters` schema validation, nor any model validator checks that `repository.owner.login` matches the owner segment of `repository.full_name`; both are simple string fields validated independently and never cross-referenced.

### Impact Explanation
A successful forged event causes `ReviewStack#deprovision` and `ReviewStack#archive!` to run against organization B's stack without B's owner authenticating anything — this is a payload for one organization/repository mutating another's stack, matching the Critical category explicitly listed in scope ("a payload for one repository mutating another's stack, commit, task or team, or an unauthorized deploy, rollback or merge"). The attack is repeatable against any organization B that has review stacks enabled, as long as any configured organization A (not necessarily B) lacks a `webhook_secret` or has one known to the attacker. Blast radius spans all tenants sharing the Shipit instance, since the vulnerable binding is in the shared controller, not per-tenant.

### Likelihood Explanation
Preconditions: (1) B has an active review stack for the claimed PR number (given), (2) some Shipit-configured organization A must exist for which either no `webhook_secret` is set, or its secret is otherwise known/leaked to the attacker. Given `webhook_secret` is an optional configuration key (confirmed present as `nil` in the test config), it is plausible in real deployments that at least one onboarded organization omits it, especially early in setup or for low-risk repos. No GitHub credentials, Shipit session, or API token is required — a single unauthenticated HTTP POST suffices, and the exploit is fully repeatable/scriptable against any repository name known to the attacker.

### Recommendation
In `WebhooksController#verify_signature`, additionally verify that the organization used to select the signing secret matches the owner embedded in `repository.full_name` (and any other repository-identifying field used downstream), rejecting the request (422) on mismatch. More robustly, every handler resolving `Shipit::Repository.from_github_repo_name(params.repository.full_name)` should independently confirm that the resolved repository's `owner` equals the `repository_owner` value that was actually used to verify the HMAC signature for this request, rather than trusting an unrelated field of the same JSON body.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "cross-organization pull_request closed forgery tears down victim's review stack" do
  # Org B ("victim-org") has an active review stack for PR #42
  victim_repo = shipit_repositories(:victim_org_repo) # owner: 'victim-org'
  victim_stack = create_review_stack(repository: victim_repo, environment: 'pr42') # active, not archived

  # Org A ("attacker-org") is configured in Shipit.github but has no webhook_secret
  # (verify_webhook_signature returns true unconditionally per lib/shipit/github_app.rb:76-77)

  body = {
    action: "closed",
    number: 42,
    pull_request: { id: 1, number: 42, url: "u", title: "t", state: "closed",
                     additions: 1, deletions: 1,
                     head: { sha: "sha", ref: "some-branch" },
                     user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { owner: { login: "attacker-org" }, full_name: "victim-org/victim-repo" },
    sender: { login: "attacker" }
  }.to_json

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=irrelevant' # attacker-org has no secret configured

  assert_not victim_stack.reload.archived?
  post :create, body: body, as: :json
  assert_response :ok
  assert victim_stack.reload.archived?, "victim-org's stack was archived by a request authenticated for attacker-org"
end
```
This test demonstrates: signature check passes using `attacker-org`'s (absent) secret while the destructive `archive!`/`deprovision` executes against `victim-org`'s stack, proving the binding `repository.owner.login (verified) == owner(repository.full_name) (acted upon)` is not enforced.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
