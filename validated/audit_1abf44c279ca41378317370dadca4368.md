### Title
Webhook signature is verified against the payload's `repository.owner.login` while the record that is actually written is selected by the independent `repository.full_name` / `sha` fields, allowing cross-organization forged webhooks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App / `webhook_secret` used to validate the inbound webhook HMAC based on `repository_owner`, which is read from the payload itself (`params.dig('repository', 'owner', 'login')` or `organization.login`) [1](#0-0) . Once the signature check passes, the handlers that mutate state select the target `Repository`/`Stack`/`Commit` using a *different* field of the same attacker-controlled JSON body: `payload.dig('repository', 'full_name')` in `Handler#repository_name` [2](#0-1) , or, in the case of `StatusHandler`, no repository scoping at all — just `Commit.where(sha: params.sha)` [3](#0-2) .

### Finding Description
The engine's trust model assumes that if an HMAC signature verifies for organization X (derived from `repository.owner.login`), then every other field in that same payload also legitimately pertains to organization X's own repository. That assumption is false: since Shipit supports "Using Multiple GitHub Applications," each organization onboarded gets its own `webhook_secret` in `config/secrets.yml` [4](#0-3) . Anyone who administers their own GitHub App installation on their own organization (a completely unprivileged actor with respect to any *other* org/repo on the same Shipit instance) legitimately knows their own org's `webhook_secret` and can compute a valid `X-Hub-Signature` for **any payload content they want**, because `verify_webhook_signature` just HMACs the raw body with that org's secret [5](#0-4) .

The break is the equality: `repository_owner` (the field used to select/authenticate the webhook_secret) ≠ `repository.full_name` / commit `sha` (the fields used to select what gets written). An attacker sets:
- `repository.owner.login` = their own org (to pass signature verification with their known secret)
- `repository.full_name` = a victim org/repo tracked on the same Shipit instance (to control what `Handler#stacks` resolves to for `PushHandler`/`CheckSuiteHandler`)
- or, for `StatusHandler`, simply any victim commit `sha` regardless of repository, since that handler never checks repository ownership at all [3](#0-2) , `push_handler.rb` similarly resolves `stacks` purely from `payload.dig('repository','full_name')` [6](#0-5) .

### Impact Explanation
This breaks the "organization authenticated vs. repository written" binding and yields cross-repository/cross-organization writes on a multi-tenant Shipit instance:
- Via `StatusHandler`, the attacker can forge a `success` CI status on any commit belonging to any other tracked stack/repository, via `commit.create_status_from_github!` [3](#0-2) , which can satisfy `required_statuses` gating used elsewhere in the deploy pipeline (`deploy_spec.rb`'s `required_statuses`/`blocking_statuses`) [7](#0-6) , potentially leading to an unauthorized deploy of unvetted code.
- Via `PushHandler`, the attacker can force `stack.sync_github(expected_head_sha: ...)` for a victim's stack to an arbitrary SHA of their choosing [8](#0-7) .

This matches the "Critical - unauthorized deploy" / "cross-repository writes" impact bar defined in scope.

### Likelihood Explanation
Requires only that the attacker control (or be an admin of) one legitimate, independent GitHub organization/App configured on the same multi-tenant Shipit deployment — no privileged Shipit credentials, `ApiClient` token, or GitHub write access to the victim repository are needed. Multi-org configuration is a documented, supported deployment mode [4](#0-3) , making this reachable on any Shipit instance serving more than one GitHub organization.

### Recommendation
After signature verification succeeds for organization X, `Handler#repository_name` (and `StatusHandler`'s commit lookup) must additionally verify that the resolved `Repository`/`Commit`'s owning organization equals the authenticated `repository_owner`/organization X, rejecting the webhook otherwise — mirroring the Solidity fix pattern of clamping/validating a value against the actually-authorized bound rather than trusting an independent, attacker-supplied field.

### Proof of Concept
1. Attacker administers `attacker-org`, which has its own GitHub App installed with `webhook_secret = S` configured in this Shipit instance's `config/secrets.yml`.
2. Attacker crafts a `status` event body:
```json
{
  "repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"},
  "sha": "<victim commit sha to be marked green>",
  "state": "success",
  "context": "ci/required-check"
}
```
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(S, body)>` themselves (they legitimately know `S`).
4. `WebhooksController#verify_signature` resolves `repository_owner = "attacker-org"`, looks up `Shipit.github(organization: 'attacker-org')`, and the signature verifies successfully [9](#0-8) .
5. `StatusHandler#process` runs unscoped: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }`, injecting a forged "success" status onto the victim's commit [3](#0-2) , independent of `attacker-org` having any relationship to `victim-org/victim-repo`.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
