### Title
Path traversal via crafted file name in Contents API response allows directory creation outside the `--output` directory on Windows - ([File: pkg/cmd/repo/read-file/read_file.go])

### Finding Description
`writeToOutput` builds the destination path with `dest = filepath.Join(dest, file.Name)` when `--output` points at (or resolves to) a directory [1](#0-0) , then derives the parent directory with `filepath.Dir(dest)` and unconditionally creates it via `mkdirAllF(dir, 0755)` before ever checking whether `dest` still resides inside the requested output directory [2](#0-1) . There is no confinement check (e.g., verifying `dest` has the output directory as a prefix after `filepath.Clean`/`filepath.Abs`).

`file.Name` originates from the `name` field of the GitHub REST Contents API response and is used verbatim [3](#0-2) . This field reflects the raw tree-entry name of the blob in the attacker's repository. Git's tree format forbids `/` and NUL bytes and the literal names `.`/`..` as entry names, but it does **not** forbid a literal backslash character in an entry name. On Windows, Go's `path/filepath` package treats `\` as the path separator, so a malicious repository containing a file whose tree-entry name is something like `..\..\..\evil\marker` (a single git tree entry with no forward slashes, so it passes git's own name checks) will be reported by the Contents API with that exact string as `name`. When the victim runs `gh repo read-file <path-to-that-blob> --repo attacker/repo --output C:\safe\dir\` on Windows, `filepath.Join(dest, file.Name)` resolves the embedded `..\` backslash segments and escapes the intended output directory; `filepath.Dir(dest)` then yields a directory outside the output root, and `mkdirAllF` creates it.

The final `writeFileF` may still fail (e.g., due to a subsequent overwrite/clobber check on an unrelated path) or succeed, but the directory-creation side effect itself already occurs outside the intended tree, matching the audited invariant (path confinement) and scoped impact (directory creation outside intended path).

### Impact Explanation
An attacker-controlled repository can cause `gh repo read-file --output <dir>` to create arbitrary directories outside the user-specified output tree on Windows hosts, which is a file-system side effect outside the intended path (matches "file write or overwrite outside the intended path" bounty class, scoped here to directory creation as staging for further writes, e.g. combined with a subsequent `--clobber` write or other tool that trusts pre-existing directories).

### Likelihood Explanation
Exploitability is limited to Windows, since on POSIX systems git tree-entry names cannot contain `/` (git's only forbidden separator), so `filepath.Join`/`filepath.Dir` cannot be redirected by `file.Name` alone. On Windows, however, the git object format still permits raw backslash bytes in a tree entry name, and the GitHub API returns that raw byte sequence in `name` without sanitization on the client side. Preconditions required: (1) attacker publishes a repository containing such a specially-named blob, (2) victim runs `gh repo read-file` against that exact path with `--output` pointing at (or resolving to) a directory. This requires the victim to explicitly target the attacker's crafted path, which is a realistic scenario if the attacker documents/links the "interesting" path (e.g., in a README) to lure a victim into running the read-file command against it.

### Recommendation
After computing `dest` in `writeToOutput`, canonicalize both the output directory and `dest` (e.g., `filepath.Clean` plus `filepath.Abs`) and verify `dest` remains a descendant of the resolved output directory before calling `mkdirAllF`/`writeFileF`; reject (return an error) if `file.Name` contains a path separator for either OS (`/` or `\`) or resolves outside the target directory, regardless of host OS.

### Proof of Concept
```go
func TestWriteToOutput_RejectsBackslashTraversalInName(t *testing.T) {
    origMkdirAll := mkdirAllF
    defer func() { mkdirAllF = origMkdirAll }()

    var mkdirDirs []string
    mkdirAllF = func(dir string, perm os.FileMode) error {
        mkdirDirs = append(mkdirDirs, dir)
        return nil // spy: don't actually touch disk
    }
    origWriteFile := writeFileF
    defer func() { writeFileF = origWriteFile }()
    writeFileF = func(name string, data []byte, perm os.FileMode) error { return nil }

    origLstat := lstatF
    defer func() { lstatF = origLstat }()
    lstatF = func(path string) (*lstatResult, error) {
        if path == "output" { // pretend output dir exists as a directory
            return &lstatResult{isDir: true}, nil
        }
        return nil, os.ErrNotExist
    }

    file := &repoFile{Name: `..\..\..\evil\marker`, Content: []byte("x")}
    _, err := writeToOutput(file, "output", false)

    // Expect an error (traversal rejected) instead of silent success.
    if err == nil {
        t.Fatalf("expected traversal rejection, got nil error")
    }
    for _, dir := range mkdirDirs {
        if !strings.HasPrefix(filepath.Clean(dir), filepath.Clean("output")) {
            t.Fatalf("mkdirAllF called with directory outside output root: %q", dir)
        }
    }
}
```
Run on `GOOS=windows` (or force backslash handling by testing `filepath.Join`/`filepath.Dir` semantics directly), asserting that `mkdirAllF` is never invoked with a path outside `output`, and that `writeToOutput` returns an error for such crafted `file.Name` values instead of proceeding.
