### Title
Flash-position callback receipts in undeclared assets are permanently locked in controller custody with no recovery path - ([File: contracts/controller/src/strategies/flash_position.rs])

### Summary
`flash_position` mints debt, forwards the measured proceeds to a caller-selected receiver contract, and then settles only the assets the caller explicitly declared in `collaterals` or `refund_assets`. Any tokens the receiver transfers to the controller during the callback that appear in neither list stay in controller custody forever: they are not deposited, not refunded, and no other entrypoint can move them. This is the same bug class as the reference report — funds are moved into contract custody as part of a settlement and the missing/undeclared leg has no recovery path.

### Finding Description
`process_flash_position` forwards `amount_received` of the debt asset to `receiver` via `transfer_amount_measured` inside `mint_and_forward` (lines 285–294) and then invokes `execute_flash_position` on the receiver (lines 131–141). After the callback, the controller settles custody by balance deltas:

- `collect_collateral_deposits` (lines 325–352) measures the balance increase only for assets in `collaterals` and deposits the delta via `process_deposit` (line 146).
- `refund_listed_assets` (lines 372–384) refunds the balance increase only for assets in `refund_assets` to `caller` (line 148).

`validate_collaterals` requires non-empty collaterals but each `min_amount` may be zero (lines 192–206), and `validate_refund_assets` merely requires each refund asset be a listed hub asset distinct from the collateral assets (lines 233–255). There is no check that the controller's token balances return to their pre-callback baseline for any other asset. The documented invariant INV-STRAT-04 confirms the behavior: "Returned debt becomes collateral if declared, returns to the caller if refund-listed, or remains uncredited if in neither list" (`docs/reference/invariants.md`, INV-STRAT-04). Crucially, even the debt asset itself is not automatically refunded: a receiver that returns the borrowed tokens while the caller forgets to include the debt asset in `refund_assets` (or declare it as collateral) leaves the entire `amount_received` in controller custody. No sweep, cancel, or admin-recovery function exists in the controller for uncredited balances; `claim_revenue` only forwards pool-claimed revenue for the market asset, not arbitrary callback residue (`contracts/controller/src/markets.rs:168-208`).

### Impact Explanation
Tokens sent to the controller during the callback and not declared in either list are permanently frozen in the contract. Because the protocol measures custody by balance and never reconciles undeclared receipts, a user (or a third-party receiver contract the user integrates with) that returns funds in an undeclared asset loses them irrevocably. This is permanent freezing of user funds, matching the reference report's impact of tokens stuck in admin/contract custody with no recovery mechanism.

### Likelihood Explanation
The path is reachable by any unprivileged caller through `flash_position` with its own receiver contract (`require_wasm_receiver`, line 69). The realistic trigger is integration error rather than exotic conditions: the receiver is responsible for returning/forwarding arbitrary tokens during the callback, the API gives no signal that undeclared assets are silently forfeited, and the caller must correctly enumerate every possible incoming asset across `collaterals` and `refund_assets`. Any receiver that returns an extra asset (e.g., a swap's dust output or the debt token itself when repayment was not needed) produces locked funds. Medium likelihood: it requires a caller mistake, but the API makes that mistake easy and irreversible.

### Recommendation
After the callback, enforce custody neutrality: for every token the receiver could plausibly return, require it to be declared, or refund any positive balance delta of the debt asset (and any other market asset touched) to `caller` automatically. At minimum, refund positive deltas of the forwarded debt asset unconditionally, and document/emit an event for residual undeclared custody. Alternatively add a recovery entrypoint that lets a caller reclaim controller balance deltas attributable to their callback.

### Proof of Concept
1. Attacker/user deploys a receiver contract implementing `execute_flash_position` that, instead of repaying nothing, transfers the received debt tokens back to the controller plus an extra listed token it acquired.
2. User calls `controller.flash_position` with `collaterals = [(hub_asset_B, min>0)]` and `refund_assets = []`, omitting the debt asset and the extra token.
3. The receiver returns the debt tokens to the controller and sends the extra token to the controller.
4. `collect_collateral_deposits` deposits only asset B's delta; `refund_listed_assets` iterates an empty list. The returned debt tokens and extra tokens remain as a controller balance increase that is never credited, deposited, or refunded — permanently locked, since no entrypoint allows withdrawing undeclared controller custody.
