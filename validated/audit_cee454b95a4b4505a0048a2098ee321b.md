### Title
Delimiter injection in `arbiter_contract.getHashSrc` allows contract-content hash collisions - ([File: arbiter_contract.js])

### Summary
`arbiter_contract.js` builds the arbiter-contract integrity hash by naively joining free-text fields with a fixed delimiter string and hashing the result, exactly the class of bug described in the Tomcat report: an untrusted-controlled value is allowed to contain the character sequence that is also used as a field delimiter, so the delimiter loses its meaning as a boundary marker and different logical inputs can produce the same serialized/hashed representation.

### Finding Description
`exports.DELIMITER = "[|#|]"` is a fixed, publicly-known separator used to concatenate contract fields before hashing: [1](#0-0) 

```
var status_PENDING = "pending";
exports.CHARGE_AMOUNT = 4000;
exports.NEW_HASH_DATE = '2026-11-01';
exports.DELIMITER = "[|#|]";
```

`getHashSrc()` joins user-supplied free-text fields (`contract.title`, `contract.text`, `contract.my_party_name` / `peer_party_name`) together with structured fields (addresses, amount, asset) using this delimiter, and `getHash()` hashes the resulting string: [2](#0-1) 

None of `title`, `text`, `my_party_name`, or `peer_party_name` are restricted from containing the literal `[|#|]` sequence before this join happens — there is no escaping, length-prefixing, or rejection of the delimiter inside these fields. Because string concatenation with an unescaped separator is not injective, a party constructing the contract (the "AA author"/private-payment counterparty equivalent here — the contract creator, who calls `createAndSend`) can choose `title`/`text`/party-name values that embed the delimiter itself, producing a joined byte string identical to that of a *different* set of field values split at a different boundary. For example:

- Set A: `title = "foo"`, `text = "[|#|]bar"`
- Set B: `title = "foo[|#|]"`, `text = "bar"`

Both produce the identical string after `.join(exports.DELIMITER)` (`"foo[|#|][|#|]bar..."`), and therefore the identical SHA-256 hash from `getHash()`. This is the direct analog of Tomcat treating `'` as an unescapable delimiter inside cookie data: the separator has no protection against appearing inside the data it separates, breaking the assumption that the hash/parse uniquely identifies the underlying content.

### Impact Explanation
The contract hash returned by `getHash()`/`getHashSrc()` is used as the canonical identifier and integrity check for the contract (`getByHash`, `store`, dispute/appeal flows, and message exchange with the peer device and the arbstore/arbiter via `openDispute`/`appeal`), which govern funds held in a shared address between the two contracting parties. Because the join is not injective, a dishonest party can craft a contract whose title/text can be represented two different ways that hash identically, letting them present one rendering of the terms to the counterparty (e.g., for signing/payment) while a different rendering exists that hashes the same and could be substituted or referenced during arbitration/appeal (`openDispute`, `appeal`), muddying the record that the hash is meant to guarantee. This can translate into a counterparty being defrauded about the actual contract terms backing an escrowed payment, i.e., fund loss/disagreement in a private-payment/arbiter flow reachable by an ordinary paired-device counterparty.

### Likelihood Explanation
Any user of the arbiter-contract wallet feature — a normal paired-device counterparty, not a privileged operator — can call `createAndSend` with attacker-chosen `title`/`text`/party-name strings, since these are plain free-text fields with no validation against containing the delimiter sequence `[|#|]`. Crafting a colliding pair of field values is a mechanical string-boundary manipulation with no cryptographic effort required, only pre-image control of adjacent free-text fields.

### Recommendation
Do not build hash input by naively joining variable-length untrusted strings with a delimiter that can appear inside the data. Instead, either:
- Reject/escape occurrences of `exports.DELIMITER` inside `title`, `text`, `my_party_name`, `peer_party_name` before hashing, or
- Use a length-prefixed or otherwise unambiguous encoding (e.g., hash each field separately and hash the concatenation of fixed-length digests, or JSON-canonicalize with strict escaping) so that no two distinct field-value tuples can serialize to the same byte string.

### Proof of Concept
```js
const crypto = require('crypto');
const DELIMITER = "[|#|]";

function hashOf(fields) {
  return crypto.createHash('sha256').update(fields.join(DELIMITER), 'utf8').digest('base64');
}

// Two different logical (title, text) pairs...
const A = ["foo", "[|#|]bar", "2026-09-15", "ADDR1", "Alice", "ARBITER", "ADDR2", "Bob", "100", "base"];
const B = ["foo[|#|]", "bar", "2026-09-15", "ADDR1", "Alice", "ARBITER", "ADDR2", "Bob", "100", "base"];

console.log(hashOf(A) === hashOf(B)); // true — same hash for different contract content
```
This mirrors `getHashSrc`'s join order in `arbiter_contract.js` (line 200) and shows that attacker-controlled `title`/`text` content containing the delimiter produces identical contract hashes for different underlying contract terms. [3](#0-2)

```javascript
function getHashSrc(contract) {
	const payer_name = contract.me_is_payer ? contract.my_party_name : contract.peer_party_name;
	const payee_name = contract.me_is_payer ? contract.peer_party_name : contract.my_party_name;
	const payer_address = contract.me_is_payer ? contract.my_address : contract.peer_address;
	const payee_address = contract.me_is_payer ? contract.peer_address : contract.my_address;
	const src = contract.creation_date > exports.NEW_HASH_DATE
		 ? [contract.title, contract.text, contract.creation_date, payer_address, payer_name || '', contract.arbiter_address, payee_address, payee_name || '', contract.amount, contract.asset || 'null'].join(exports.DELIMITER)
		 : [contract.title, contract.text, contract.creation_date, payer_name || '', contract.arbiter_address, payee_name || '', contract.amount, contract.asset || 'null'].join("");
	return src;
}

function getHash(contract) {
	return crypto.createHash("sha256").update(getHashSrc(contract), "utf8").digest("base64");
}
```
