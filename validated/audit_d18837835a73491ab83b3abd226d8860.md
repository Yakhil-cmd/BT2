### Title
Cross-organization webhook forgery: signature verified against attacker's GitHub org config, but `StatusHandler`/handlers act on any commit or repository by unauthenticated payload fields - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
Shipit supports multi-tenant GitHub configuration, where each organization has its own `webhook_secret` under `secrets.github` [1](#0-0) . `WebhooksController#verify_signature` selects *which* organization's secret to verify the HMAC signature against using `repository_owner`, a value read straight out of the untrusted JSON body (`repository.owner.login` or `organization.login`) rather than any pre-established, authenticated context [2](#0-1) [3](#0-2) . Once the signature is accepted, the event handler is dispatched and reads *other* fields from the very same attacker-controlled body — e.g. `params.sha` in `StatusHandler`, or `repository.full_name` in `Handler#stacks`/other handlers — to decide what to mutate [4](#0-3) [5](#0-4) . Nothing ties the organization whose secret validated the signature to the organization/repository the handler subsequently acts on.

### Finding Description
The binding that should hold is:
`organization whose webhook_secret verified the signature == organization owning the repository/commit the handler mutates`

Before the attack: an organization "O" only ever receives webhooks for its own repositories, since GitHub always signs the payload it produces for repository "O/repo" with "O"'s configured secret, and `repository.owner.login`/`repository.full_name` are self-consistent because GitHub generated them.

After the attack: an attacker who controls (or is an authorized user of) their *own* onboarded GitHub organization "attacker-org" in a multi-tenant Shipit deployment knows their own `webhook_secret` (they set it up themselves when installing the App, per `docs/setup.md`) [6](#0-5) . They can POST an arbitrary JSON body to `/webhooks` with:
- `repository.owner.login = "attacker-org"` (or `organization.login`), which `WebhooksController#repository_owner` extracts to select the verification key [3](#0-2) ,
- a signature computed with the attacker's own `webhook_secret` over the full raw body,
- but any other content in the body, including `sha` (for the `status` event) pointing at a commit belonging to a completely different, victim stack.

`StatusHandler#process` does not scope the lookup to any repository at all — it looks up `Commit.where(sha: params.sha)` globally across the whole Shipit installation and calls `commit.create_status_from_github!(params)` [7](#0-6) . The signature check only proved the request was made under "attacker-org"'s valid secret; it proves nothing about which repository's commit the `sha` actually belongs to. The verified-organization ↔ mutated-commit binding is broken.

### Impact Explanation
By injecting a forged `status` event with an arbitrary `state` (e.g. `success`) for a real commit SHA belonging to a victim's stack that the attacker doesn't have write access to, the attacker can create fabricated commit statuses on that commit via `Commit#create_status_from_github!`. Shipit's deploy/merge gating logic (`Shipit::CommitChecks`, `DeploySpec` required statuses, `Status::Group`) consumes these stored statuses to decide whether a commit is safe to deploy or merge [8](#0-7) . Forging a passing status on a commit that actually failed CI can defeat these safety gates and lead to an unauthorized deploy — matching the report's root cause (a value that should be constrained to a verified scope is instead accepted from an unauthenticated part of the same payload) and the Critical impact bar of "an unauthorized deploy."

### Likelihood Explanation
Any party legitimately onboarded as one organization in a Shipit multi-tenant install (a normal, unprivileged setup step, not a compromise of Shipit's own secrets) can exploit this without any Shipit session, `ApiClient` token, or GitHub App private key belonging to the victim — they only need their own org's `webhook_secret`, which they control by design. The `sha` value needed to target a specific commit is public (visible on GitHub), making the attack straightforward to mount once two organizations share the same Shipit instance.

### Recommendation
When resolving the organization/repository for a webhook, derive it once (e.g., during signature verification) and pass that resolved, trusted identity into the handlers; reject or scope any operation whose target repository/commit does not belong to the same organization that supplied a valid signature. Concretely, `StatusHandler` (and any handler using a global lookup such as `Commit.where(sha:)`) should scope the query through `stacks`/`repository_name` derived from the verified organization, and `WebhooksController` should confirm that `repository.full_name`'s owner matches the organization used for signature verification before dispatching.

### Proof of Concept
1. Shipit is configured with two GitHub orgs, `victim-org` and `attacker-org`, each with its own `webhook_secret` under `secrets.github` [1](#0-0) .
2. Attacker installs their own GitHub App on `attacker-org` and knows `attacker-org`'s `webhook_secret`.
3. Attacker crafts a `status` event JSON body:
```json
{
  "sha": "<victim-commit-sha>",
  "state": "success",
  "context": "ci/tests",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "attacker-org/whatever" }
}
```
4. Attacker computes `X-Hub-Signature` with `attacker-org`'s `webhook_secret` over this exact body and POSTs it to `/webhooks` with `X-Github-Event: status`.
5. `WebhooksController#repository_owner` resolves to `attacker-org`; `Shipit.github(organization: 'attacker-org').verify_webhook_signature` succeeds [9](#0-8) .
6. `StatusHandler#process` runs `Commit.where(sha: params.sha)` and stores a fabricated `success` status on the victim's commit [7](#0-6) , even though the request was never signed by `victim-org`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
