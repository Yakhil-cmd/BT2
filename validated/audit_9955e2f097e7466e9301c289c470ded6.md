Let me look at the tx pool integration to understand if `GetCheckBalance` is re-run during promotion.

### Title
Allowance Check Bypass via Stale State Nonce Allows Lender Fund Loss — (`kaiax/gasless/impl/tx_pool.go`)

### Summary

The `checkBalanceForSwap` function skips the ERC-20 allowance check when `swapNonce > senderNonce` (committed state), assuming an ApproveTx will precede the SwapTx. However, this check is only run once at admission time via `validateTx`. When a non-gasless tx at nonce N is mined, the SwapTx at nonce N+1 is re-promoted as a standalone swap (no ApproveTx) without re-running the allowance check. The resulting bundle `[LendTx, SwapTx]` causes the lender to send KAIA to the attacker, then the SwapTx reverts due to zero allowance, and the lender loses the lend amount.

---

**Note on the claimed mechanism:** The claim states that `isSwapTxReady` accepts the swap while the non-gasless tx is still in pending (treating it as approveTx). This is **incorrect** — `isSwapTxReady` explicitly calls `g.IsApproveTx(prevTx)`, which returns false for any non-gasless tx, so the swap is NOT promoted at that stage. [1](#0-0) 

The real exploit path is through the **post-mining promotion**, described below.

---

### Finding Description

**Step 1 — Admission (`validateTx` → `GetCheckBalance` → `checkBalanceForSwap`):**

At admission time, `senderNonce = getCurrentStateNonce(addr) = N` (committed state). The SwapTx has `swapNonce = N+1`. The condition `noApproveTxPreceeds = (swapNonce == senderNonce)` evaluates to `false`, so the allowance check is skipped entirely. [2](#0-1) 

`GetCheckBalance` is called only inside `validateTx` during tx admission: [3](#0-2) 

It is **never called again** during `promoteExecutables`: [4](#0-3) 

**Step 2 — Non-gasless tx at nonce N is mined:**

`PostInsertBlock` updates `g.currentState` to the new block's state, so `getCurrentStateNonce` now returns N+1. [5](#0-4) 

**Step 3 — Promotion (`promoteExecutables` → `IsReady` → `isSwapTxReady`):**

Now `nonce = N+1` and `swapTx.Nonce() = N+1 = nonce`, so the branch `approveTx = nil` is taken. `IsExecutable(nil, swapTx)` passes the nonce check (`N+1 == N+1`). The SwapTx is promoted as a standalone swap with no ApproveTx. [6](#0-5) 

**Step 4 — Block building (`ExtractTxBundles`):**

`approveTxs[addr]` is nil. `IsExecutable(nil, swapTx)` passes. The bundle `[LendTx, SwapTx]` is built. [7](#0-6) 

**Step 5 — Execution:**

- LendTx executes: lender sends `lendAmount = SwapTx.Fee()` KAIA to the attacker.
- SwapTx executes: router calls `transferFrom(attacker, router, amountIn)` — no allowance was ever set → **REVERT**.
- LendTx is already committed; the KAIA is not returned. Lender loses `SwapTx.Fee()` KAIA. [8](#0-7) 

### Impact Explanation

The lender (block proposer) loses `SwapTx.Fee()` KAIA per exploit iteration. The attacker retains the lend amount. Since the token balance check still passes at admission (attacker holds tokens, which are never consumed because the swap reverts), the attacker can repeat this with the same token balance across multiple blocks, draining the lender's KAIA balance.

### Likelihood Explanation

Requires only a public RPC submission of two transactions (a normal tx at nonce N, then a SwapTx at nonce N+1 with no prior `approve` call). No privileged access, validator collusion, or key compromise is needed. The attacker must hold a non-zero token balance of a whitelisted token to pass the balance check at admission.

### Recommendation

Re-run the allowance check at promotion time, or re-run `GetCheckBalance` when a queued gasless tx transitions from queue to pending. Specifically, in `isSwapTxReady` (or `IsExecutable`), when `approveTx == nil`, verify that `token.allowance(sender, router) >= amountIn` against the current committed state before promoting the SwapTx as a standalone swap.

### Proof of Concept

1. Attacker holds token balance ≥ `amountIn` but has **not** called `approve(router, MaxUint256)`.
2. Attacker submits a plain ETH transfer (non-gasless) at nonce N → admitted to pending.
3. Attacker submits SwapTx at nonce N+1 → `checkBalanceForSwap` skips allowance check (`swapNonce N+1 != senderNonce N`), token balance check passes → admitted to queue.
4. Plain tx at nonce N is mined. `PostInsertBlock` updates state nonce to N+1.
5. `promoteExecutables` runs: `isSwapTxReady` sees `swapTx.Nonce() == nonce` (N+1 == N+1), promotes SwapTx as standalone swap.
6. `ExtractTxBundles` builds `[LendTx, SwapTx]`.
7. LendTx sends `SwapTx.Fee()` KAIA to attacker. SwapTx reverts (no allowance). Lender loses `SwapTx.Fee()` KAIA.
8. Attacker repeats from step 2 (tokens are not consumed since swap reverted).

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
