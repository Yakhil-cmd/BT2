### Title
Cross-tenant PR-label webhook forgery via no-secret organization mismatch between `repository.owner.login` (signature scope) and `repository.full_name` (mutation scope) - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` used to validate the HMAC signature solely from `params.dig('repository','owner','login')` [1](#0-0) , while the `pull_request` handlers resolve the repository/stack they mutate from the completely independent, attacker-supplied `params.repository.full_name` field [2](#0-1) . Because `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever `webhook_secret` is blank [3](#0-2) , an attacker who knows (or configures) any Shipit-registered GitHub org with no `webhook_secret` can forge a `pull_request`/`labeled` payload whose `repository.owner.login` is that no-secret org, but whose `repository.full_name` names a totally different, victim-owned repository, and the `LabeledHandler` will archive/unarchive that victim's review stack.

### Finding Description
The broken invariant should be: **the organization that authenticated the webhook (`repository_owner` used in `verify_signature`) equals the organization owning the repository the handler mutates (`params.repository.full_name`'s owner)**. Nothing in the code enforces this equality.

- `WebhooksController#create` parses the raw JSON body once, then dispatches it, unmodified, to every handler registered for the event: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `verify_signature` looks up the GitHub App config via `repository_owner`, which reads `params.dig('repository','owner','login')` (falling back to `organization.login`) [5](#0-4) .
- `GitHubApp.new` sets `@webhook_secret = @config[:webhook_secret].presence` [6](#0-5) , and `verify_webhook_signature` returns `true` unconditionally when that secret is blank [7](#0-6) . The test fixtures (`test/dummy/config/secrets_double_github_app.yml`, `test/dummy/config/secrets.test.json`) show `webhook_secret: nil` is an explicitly supported configuration shape for one or more orgs, confirming this is not a hypothetical edge case [8](#0-7) .
- `Shipit::Webhooks::Handlers::PullRequest::LabeledHandler#repository` resolves the repository purely from `params.repository.full_name` — a string fully controlled by the attacker's JSON body and never cross-checked against `repository_owner` used for signing [2](#0-1) . It then calls `stack.archive!`/`stack.unarchive!` via `ReviewStackAdapter` on that repository's `review_stacks` scope [9](#0-8) .
- `respond_to_label_change?` only checks `params.action`, `pull_request.state`, `repository.review_stacks_enabled`, and label state — no ownership/authenticity binding at all [10](#0-9) .

**Attacker request:** POST `/webhooks` with header `X-Github-Event: pull_request`, `X-Hub-Signature: sha1=anything` (or omitted algorithm handling aside, irrelevant since it's never checked when secret is blank), and JSON body:
```json
{
  "action": "labeled",
  "number": 1,
  "pull_request": { ...state: "open", "labels": [...], "head": {...}, "user": {...}, "assignees": [] },
  "repository": { "owner": { "login": "no-secret-org" }, "full_name": "victim-org/victim-repo" },
  "sender": { "login": "attacker" }
}
```
`verify_signature` resolves `Shipit.github(organization: 'no-secret-org')`, which has a blank `webhook_secret`, so `verify_webhook_signature` returns `true` and the request proceeds regardless of the actual (forged/garbage) signature header. `LabeledHandler` then resolves `Shipit::Repository.from_github_repo_name('victim-org/victim-repo')` and, if the label state matches the repo's `provisioning_behavior`, calls `stack.archive!` or `stack.unarchive!` on the victim's real review stack.

Existing guards do not close this gap: `drop_unhandled_event` only checks the event type is registered, not payload content [11](#0-10) ; the `ExplicitParameters` schema in the handler validates types/shape only, not cross-field consistency between `repository.owner.login` and `repository.full_name` [12](#0-11) ; `GithubOrganizationUnknown` only fires when the org name isn't configured at all, not when it's configured with no secret [13](#0-12) .

### Impact Explanation
An attacker who controls (or knows) any Shipit-registered organization lacking a `webhook_secret` can archive or unarchive the review stack of an arbitrary victim repository/organization also configured in the same Shipit instance, without any legitimate signature, push access, or membership in the victim repo. This is a cross-repository/cross-tenant state manipulation: a payload attributed to one (unrelated, low-trust) org mutates another org's stack records, matching the Critical impact category "a payload for one repository mutating another's stack". The action is repeatable against any victim repository with `review_stacks_enabled`, for every PR number/branch an attacker chooses to name in the forged `full_name`+`pull_request.head.ref` fields, and other PR handlers (`OpenedHandler`, `ClosedHandler`, `ReopenedHandler`, `UnlabeledHandler`) sharing the identical `repository.full_name`-based lookup are equally exploitable, widening blast radius to provisioning/deprovisioning of arbitrary review stacks.

### Likelihood Explanation
Preconditions: Shipit must be configured with the multi-organization github config schema and at least one organization must have a blank/absent `webhook_secret` (documented as a supported, valid configuration in `docs/setup.md` and shipped in fixture files) [14](#0-13) ; the victim repository must exist in Shipit with `review_stacks_enabled` and a matching provisioning-label configuration. No attacker secrets, sessions, or GitHub write access to the victim repo are required — only knowledge of the victim's `full_name` and the existence of any no-secret org, both discoverable/public information. Attacker cost is a single unauthenticated HTTP POST, fully repeatable and scriptable.

### Recommendation
Bind the resolved repository owner to the organization whose secret verified the request: after determining the `GitHubApp` used for signature verification, require that `params.repository.full_name.split('/').first` (case-insensitively) equals the verified `repository_owner`/organization key, and reject (422) on mismatch, before invoking any handler. Alternatively, pass the verified organization into `Webhooks.for_event(event).each { |handler| handler.call(params, verified_organization: repository_owner) }` and have each PR handler assert `repository.owner == verified_organization` before mutating any stack.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure `Shipit.stubs(:secrets)` (or use `test/dummy/config/secrets_double_github_app.yml`) with two orgs: `NoSecretOrg` (blank `webhook_secret`) and `VictimOrg` (any secret).
2. Create `victim_repo = Shipit::Repository.create!(owner: 'victimorg', name: 'victim-repo', review_stacks_enabled: true, provisioning_behavior: <allow_with_label>)` and a pre-existing `ReviewStack`/PR fixture on it, currently un-archived.
3. POST `/webhooks` with `X-Github-Event: pull_request`, an arbitrary/garbage `X-Hub-Signature`, and body:
   `{"action":"labeled","number":<pr_number>,"pull_request":{...,"state":"open","labels":[{"name":"<provisioning_label>"}]},"repository":{"owner":{"login":"NoSecretOrg"},"full_name":"victimorg/victim-repo"},"sender":{"login":"attacker"}}`.
4. Assert response is `:ok` (not `:unprocessable_entity`), i.e., `verify_signature` passed purely because `NoSecretOrg` has no secret — establishing the equality-before check: `repository_owner == 'NoSecretOrg'` while the mutated repo's owner is `'victimorg'` (mismatch, unenforced).
5. Assert the side effect landed on the victim stack: `assert stack.reload.archived?` (or `unarchived?` depending on scenario), proving a payload verified under `NoSecretOrg`'s (non-)secret mutated `VictimOrg`'s review stack — the divergence the invariant was meant to prevent.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
