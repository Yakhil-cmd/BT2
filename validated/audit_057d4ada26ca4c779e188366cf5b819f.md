Found: `CCMenuController` authenticates via a token in the query string rather than the `ApiClient` binding used everywhere else, and it does not scope the `stack` lookup to the token's authorized stack.

### Title
Stack-scoped API token can read any stack's build status via CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Api::CCMenuController` overrides `authenticate_api_client` to authenticate solely from a `token` query-string parameter, bypassing the `stacks` scoping helper defined in `BaseController`. It then resolves the target stack directly from `params[:stack_id]` via `Stack.from_param!`, instead of scoping through `current_api_client`'s authorized stack list.

### Finding Description
`BaseController#stacks` enforces the binding "stack a token authorizes == stack it touches" by scoping to `Stack.where(id: current_api_client.stack_id)` when the client is stack-scoped: [1](#0-0) 

Every other controller (`Api::TasksController`, `Api::DeploysController`, `Api::MergeRequestsController`, `Api::CommitsController`, `Api::ReleaseStatusesController`) resolves `stack` via this scoped `stacks` method, so a client whose `ApiClient#stack_id` is set (e.g. the `here_come_the_walrus` fixture, scoped to `stack: shipit`) can only ever touch that one stack: [2](#0-1) 

`Api::CCMenuController`, however, defines its own `stack` method that bypasses the scoped `stacks` helper entirely and resolves any stack by id from the URL, with no ownership check against `current_api_client`: [3](#0-2) 

The `require_permission :read, :stack` before_action only checks that the token carries the `read:stack` permission string on `ApiClient#permissions` — it never checks `current_api_client.stack_id` against the requested `stack_id`: [4](#0-3) 

This is the direct analog of the `closeLoan()` finding: an authorization check exists in the codebase pattern (the `stacks` scoping used by sibling controllers) but this specific action's implementation swaps in a weaker/local resolution of the target resource, breaking the equality `token.stack_id == requested_stack_id`.

### Impact Explanation
Per the engine's own `docs/setup.md`, CCMenu tokens are meant to be embedded in URLs and shared for CI-dashboard integrations, i.e., treated as loosely held, per-stack credentials `client.authentication_token` created scoped to a single stack via `CCMenuUrlController`: [5](#0-4) 

Because the CCMenu controller does not enforce the stack scope on the token, holding any valid `read:stack`-permissioned CCMenu token (intended for one specific stack) grants unauthenticated-read access to the deploy/build status (`lastBuildStatus`, `lastBuildLabel`, `activity`, lock reason, etc.) of every stack in the installation by simply substituting a different `stack_id` in the URL, per the required-impact category "unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
High. This requires only possession of one legitimately-issued, low-privilege CCMenu URL/token (these are designed to be shared in CI dashboards, README badges, etc., and carry only `read:stack`) and knowledge or guessing of another stack's `to_param`/slug, which is derivable from repository name and environment and is not secret.

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the scoped `stacks` helper (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!(params[:stack_id])`, so the token's `stack_id` binding is enforced the same way it is in every sibling API controller.

### Proof of Concept
1. Create/obtain a stack-scoped CCMenu token for `stack_a` (e.g. via `CCMenuUrlController#fetch`, which creates an `ApiClient` with only `permissions: %w[read:stack]` and no `stack_id` restriction is verified downstream).
2. Send `GET /api/{other_stack_b_id}/ccmenu.xml?token=<token_for_stack_a>`.
3. Observe the request passes `require_permission :read, :stack` (token has that permission) and `stack` resolves `stack_b` directly via `Stack.from_param!`, returning `stack_b`'s build status/XML — data the token was never authorized to access.

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
