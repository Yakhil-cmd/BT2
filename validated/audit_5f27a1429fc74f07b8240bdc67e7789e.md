### Title
Interest-accrual `i128` overflow permanently freezes an oversized lending market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
Accrual computes total debt and supplied value as `i128` RAY products before enforcing a value ceiling. Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, every operation that synchronizes the market reverts, permanently freezing supplier and borrower funds.

### Finding Description
`update_borrow_index` caps the index only after calculating it, but `calculate_supplier_rewards` still multiplies total scaled debt by both the old and new index as `Ray` values [1](#0-0) [2](#0-1) .

The configured borrow-index ceiling is `1e36` raw RAY, while an `i128` result overflows near `1.70e38`; therefore, scaled market totals around `1e36` overflow after roughly a 170× index increase, long before the 1-billion-times index cap is reached [3](#0-2) .

Every pool mutation loads a synced market, and syncing calls `global_sync`, which applies `accrue_step` before the requested action [4](#0-3) [5](#0-4) .

The permissionless controller `update_indexes` path forwards a caller-selected `Vec<HubAssetKey>` to pool accrual, so any user can trigger the overflow once the market state crosses the boundary [6](#0-5) [7](#0-6) .

### Impact Explanation
All users with positions in the affected `(hub_id, asset)` market lose access to funds because repayments, withdrawals, liquidations, and other pool mutations perform accrual before operating on positions [8](#0-7) .

The repository's existing boundary test demonstrates the resulting market freeze: a large 18-decimal market at 98% utilization reaches `MathOverflow`, while `withdraw` and `repay` continue to fail with the same error [9](#0-8) .

### Likelihood Explanation
The condition requires an exceptionally large market and sustained high interest, so exploitation is capital- and time-dependent rather than immediate [10](#0-9) .

However, the triggering state is reachable through ordinary `supply`, `borrow`, and permissionless `update_indexes` calls, and no privileged input is needed once the market configuration permits the required caps and utilization [11](#0-10) [6](#0-5) .

### Recommendation
Represent total supplied/debt valuations and accrued interest in `I256` throughout accrual, or clamp the indexes before any product whose value cannot fit `i128`.

Add a market recovery path that bounds accrued-value calculations instead of panicking, and enforce a market-total cap that guarantees `scaled_total * MAX_*_INDEX_RAY` remains representable.

### Proof of Concept
1. Create or use an 18-decimal market with an aggressive rate curve and raise its caps enough to admit approximately `1e18` base units.
2. Call `supply(caller, account_id, spoke_id, vec![(hub_asset, 1_000_000_000 * 10^18)])`.
3. Supply sufficient collateral in another market and call `borrow(caller, account_id, vec![(hub_asset, 980_000_000 * 10^18)], None)`.
4. Let interest accrue at high utilization until the scaled debt multiplied by the next borrow index exceeds `i128::MAX`.
5. Call `update_indexes(caller, vec![hub_asset])`; accrual panics with `MathOverflow`.
6. Subsequent `withdraw`, `repay`, `liquidate`, or `clean_bad_debt` calls for that market fail before state changes because they all synchronize interest first.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
