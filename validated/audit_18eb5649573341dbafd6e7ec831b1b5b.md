### Title
Unrate-limited JSON-RPC `query` method allows unbounded, unauthenticated trie/state reads to exhaust shared node resources - (File: `chain/jsonrpc/src/lib.rs`)

### Summary
The nearcore JSON-RPC server exposes read-only state access (`query` with `ViewState`, `CallFunction`, `ViewAccount`, etc.) to any unauthenticated caller via `rpc_handler()` / `process_request_internal()`, with no per-request or per-caller rate limiting analogous to the disperser `RetrieveBlob` bug class: each call performs trie reads, thread-pool work, and (for `CallFunction`) wasm execution, and can be issued at unbounded frequency by any client.

### Finding Description
The JSON-RPC HTTP layer wires the `/` route to `rpc_handler()`, which forwards every request to `JsonRpcHandler::process()` → `process_request_internal()` [1](#0-0) . The only middleware applied to the router is CORS and a request-body size cap; there is no rate-limiting or concurrency-limiting layer [2](#0-1) .

The `query` method is routed to `ViewClientActor` via `query_sharded`/`query`, which performs trie/state reads (`ClientQuery`) against the runtime for `ViewAccount`, `ViewCode`, `ViewState`, `ViewAccessKey(List)`, `ViewGasKeyNonces`, and `CallFunction` [3](#0-2) [4](#0-3) . Each `CallFunction` query triggers a full wasm invocation with runtime gas metering (`call_function` in `runtime/runtime/src/runtime/mod.rs`/state_viewer), and `ViewState` performs a paginated trie disk iteration [5](#0-4) .

By contrast, nearcore *does* apply explicit rate limiting to the analogous state-sync request path (`StateRequestActor`), which tracks request timestamps and rejects requests exceeding `state_requests_per_throttle_period` within `state_request_throttle_period` [6](#0-5) [7](#0-6) . That throttle, however, only protects the P2P state-sync message handlers (`StateRequestHeader`/`StateRequestPart`, node-to-node), not the user-facing JSON-RPC `query`/`EXPERIMENTAL_*` endpoints reachable from any external caller. No equivalent throttle exists on `ViewClientActor`'s `ClientQuery` handler or on the JSON-RPC HTTP layer itself — the only bounding factor is the fixed `view_client_threads` thread-pool size [8](#0-7) , which limits *concurrency* but not *rate*, and imposes no cost or backoff on the calling IP/account.

Existing mitigations documented in `client_config.rs` (`trie_viewer_state_size_limit`, `max_gas_burnt_view`, `receipt_to_tx_max_outcomes_per_request`) cap the cost of a *single* request but do nothing to cap the *number* of requests per unit time from an unauthenticated caller [9](#0-8) . Per-request lock contention on the trie has been independently observed in profiling: futex traces show contention originating from `Trie::get`/`get_optimized_ref` paths reachable from account/verifier lookups, confirming shared-resource contention under load [10](#0-9) .

### Impact Explanation
An unprivileged remote caller can flood the public JSON-RPC endpoint with `query` (`ViewState`, `CallFunction`, `ViewAccessKeyList`, etc.) requests at unbounded rate. Because there is no throttle comparable to `StateRequestActor`'s, this can saturate the `ViewClientActor` thread pool, cause RocksDB/trie lock contention, and degrade or stall service for legitimate RPC/light-client callers on that node — an availability/DoS impact ("unbounded resource use") rather than a consensus-breaking bug, consistent with the medium-risk classification of the original disperser report.

### Likelihood Explanation
High: `query` and its `EXPERIMENTAL_*` siblings are default-enabled, unauthenticated, publicly reachable RPC methods on any node exposing the JSON-RPC HTTP port (default 3030), requiring no special privileges, staking, or account setup to trigger repeatedly.

### Recommendation
Add a configurable per-IP/per-caller rate limiter (e.g., a token-bucket similar to `chain/network/src/concurrency/rate.rs`'s `Limit`, or a `tower` rate-limiting layer) to the JSON-RPC router in `create_jsonrpc_app()`, at minimum for the expensive `query` sub-types (`ViewState`, `CallFunction`) and `EXPERIMENTAL_*` methods, mirroring the throttle already applied to `StateRequestActor` for P2P state-sync requests.

### Proof of Concept
Not applicable/unverified with executable PoC — this is a design-level absence-of-rate-limiting finding derived from static review of `chain/jsonrpc/src/lib.rs` (router/middleware construction) and comparison with the throttled `StateRequestActor` path; no rate-limiting or concurrency-limiting middleware was found anywhere under `chain/jsonrpc/`. Confirming real-world exploitability (thread starvation / RocksDB latency spikes under sustained `query` flood) would require running a live node and load-testing the `/` RPC endpoint, which is outside the scope of static code search.

    pub fn view_state(
        &self,
        state_update: &TrieUpdate,
        account_id: &AccountId,
        prefix: &[u8],
        after_key: Option<&[u8]>,
        limit: Option<NonZeroU32>,
        include_proof: bool,
    ) -> Result<ViewStateResult, errors::ViewStateError> {
        let paginated = limit.is_some() || after_key.is_some();
        if paginated && include_proof {
            return Err(errors::ViewStateError::ProofUnsupportedWithPagination);
        }
        if let Some(after_key) = after_key {
            if !after_key.starts_with(prefix) {
                return Err(errors::ViewStateError::AfterKeyOutsidePrefix);
            }
        }

        let Some(account) = get_account(state_update, account_id)? else {
            return Err(errors::ViewStateError::AccountDoesNotExist {
                requested_account_id: account_id.clone(),
            });
        };

        // Legacy per-account gate — paginated callers opt out of it.
        if !paginated {
            let code_len = state_update
                .get_code_len(
                    account_id.clone(),
                    account.local_contract_hash().unwrap_or_default(),
                )?
                .unwrap_or_default() as u64;
            if let Some(limit) = self.state_size_limit {
                if account.storage_usage().saturating_sub(code_len) > limit {
                    return Err(errors::ViewStateError::AccountStateTooLarge {
                        requested_account_id: account_id.clone(),
                    });
                }
            }
        }

        let query = trie_key_parsers::get_raw_prefix_for_contract_data(account_id, prefix);
        let acc_sep_len = query.len() - prefix.len();
        let mut iter = state_update.trie().disk_iter()?;
        iter.remember_visited_nodes(include_proof);

        match after_key {
            None => iter.seek_prefix(&query)?,
            Some(after_key) => {
                let mut full = query[..acc_sep_len].to_vec();
                full.extend_from_slice(after_key);
                iter.seek(Bound::Excluded(full))?;
            }
        }

        // Per-page caps, separate from the `trie_viewer_state_size_limit` that pagination skips.
        // The byte cap is soft: it's checked before each append, so a page can run one item over.
        const MAX_VIEW_STATE_PAGE_ITEMS: u32 = 10_000;
        const MAX_VIEW_STATE_PAGE_BYTES: u64 = 50_000;

        let (item_cap, byte_cap) = if paginated {
            let items = limit
                .map_or(MAX_VIEW_STATE_PAGE_ITEMS, NonZeroU32::get)
                .min(MAX_VIEW_STATE_PAGE_ITEMS);
            (Some(items), Some(MAX_VIEW_STATE_PAGE_BYTES))
        } else {
            (None, None)
        };

        // Pre-allocate only for an explicit `limit`; the default page size is too big to assume.
        let mut values = match (limit, item_cap) {
            (Some(_), Some(cap)) => Vec::with_capacity(cap as usize),
            _ => Vec::new(),
        };
        let mut used_bytes: u64 = 0;
        let mut last_key = None;

        for item in &mut iter {
            let (key, value) = item?;
            // `seek` (resumed pages) is not prefix-bounded — stop at the account edge.
            if !key.starts_with(&query) {
                break;
            }
            let hit_items = item_cap.is_some_and(|cap| values.len() as u64 >= u64::from(cap));
            let hit_bytes = byte_cap.is_some_and(|cap| used_bytes >= cap);
            if hit_items || hit_bytes {
                // At least one more item exists; resume after the last we kept.
                last_key = values.last().map(|it: &StateItem| it.key.clone());
                break;
            }
            used_bytes += (key.len() + value.len()) as u64;
            values.push(StateItem { key: key[acc_sep_len..].to_vec().into(), value: value.into() });
        }
        let proof = iter.into_visited_nodes();
        Ok(ViewStateResult { values, proof, last_key })
    }

    /// Returns true if this request needs to be **dropped** due to exceeding a
    /// rate limit of state sync requests.
    fn throttle_state_sync_request(&self) -> bool {
        let mut timestamps = self.state_request_timestamps.lock();
        let now = self.clock.now();
        while let Some(&instant) = timestamps.front() {
            // Assume that time is linear. While in different threads there might be some small differences,
            // it should not matter in practice.
            if now - instant > self.throttle_period {
                timestamps.pop_front();
            } else {
                break;
            }
        }
        if timestamps.len() >= self.num_state_requests_per_throttle_period {
            return true;
        }
        timestamps.push_back(now);
        false
    }
