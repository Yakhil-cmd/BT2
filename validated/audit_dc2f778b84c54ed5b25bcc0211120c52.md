### Title
Committing then amending a dangerous change causes `compute_v2_review_set` to silently drop it from the Stop-hook review set - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` only folds committed changes into `dirty_now` when the pre-turn `head_at_capture` is a strict git ancestor of the current `HEAD` (a linear fast-forward). Any normal, unprivileged git operation that replaces rather than extends the commit chain during the same turn — most simply `git commit --amend`, but also interactive rebase, `git commit --amend` after `git reset --soft`, or a squash — breaks that ancestry relationship, so the dangerous file is excluded from the review set even though it genuinely differs from the turn-start baseline.

### Finding Description
`compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) computes:

```
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
``` [1](#0-0) 

`dirty_now` starts from `git status --porcelain` (tracked/untracked changes vs current `HEAD`), then conditionally adds committed-this-turn files only via:

```python
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
``` [2](#0-1) 

`_is_ancestor` is implemented as `git merge-base --is-ancestor head_at_capture current_head` [3](#0-2) , which is true only for a genuine fast-forward. `git commit --amend` (or an equivalent history-rewrite: interactive rebase, `reset --soft` + recommit, squash) creates a brand-new commit object whose parent equals the *original* pre-turn parent — i.e., `head_at_capture` becomes a sibling of the new HEAD, not an ancestor. Consequently:

- `_is_ancestor(head_at_capture, current_head)` returns `False`.
- The `f"{head_at_capture}..HEAD"` diff is never unioned into `dirty_now`.
- After the commit/amend, the working tree is clean, so `git status --porcelain` also does not report the file — `dirty_now` ends up empty for that file.
- Meanwhile `changed_since = _git_name_only(repo, baseline_sha)` (diff against the turn-start stash `baseline_sha`, computed independently of `HEAD`/`head_at_capture` at `diffstate.py:417-420`) *does* still contain the file, because the tree content genuinely differs from the pre-turn stash.
- Since `review_set = dirty_now ∩ changed_since`, the file drops out of the intersection entirely and is never reviewed by the Stop hook.

This is reachable purely through "normal git operations in a cloned repo" as stipulated: the agent (or any process running in the same session) commits a dangerous change, then amends/rebases it before Stop fires. No admin privilege, no `.git` tampering beyond standard porcelain commands, and no bypass of any explicit allowlist is required — the hook's own linear-ancestry assumption is the flaw. `handle_stop_hook` consumes `compute_v2_review_set`'s output directly and skips review entirely when `review_paths` is empty (`_skip(9, ...)`) [4](#0-3) , so the dangerous file is never diffed, never sent to the LLM reviewer, and the baseline subsequently advances past it on the next turn, permanently hiding the change.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths." A file containing a dangerous/vulnerable change, introduced and then amended within a single agent turn, is silently excluded from the security-guidance Stop-hook LLM review — the plugin's sole final backstop for reviewing agent-authored code changes. This is a wrong-target/incomplete-review condition: session security enforcement is bypassed by an entirely ordinary git workflow (commit + amend), letting insecure code slip past the review gate that the plugin exists to enforce.

### Likelihood Explanation
Highly feasible and repeatable. `git commit --amend` (or equivalent rebase/squash flows) is an extremely common, unprivileged operation that agents or users routinely perform mid-session (e.g., fixing a commit message or adding a forgotten file to the last commit). No special timing, race, or repo corruption is needed — the bug triggers deterministically any time `head_at_capture` stops being an ancestor of `HEAD` while `changed_since` still reflects the change.

### Recommendation
Do not gate the committed-changes contribution to `dirty_now` on strict linear ancestry. Instead, always union `_git_name_only(repo, head_at_capture)` (diff between `head_at_capture` and current `HEAD`, regardless of ancestry) into `dirty_now` whenever `head_at_capture != current_head`, since `git diff` between two arbitrary commits is well-defined and doesn't require ancestry. Alternatively, since `changed_since` (diff vs the stash `baseline_sha`) is already ancestry-independent and correctly captures amended/rebased content, consider using `changed_since` alone as the review set when `head_at_capture` is not an ancestor of `HEAD` (i.e., drop the intersection with `dirty_now` in that branch, falling back to `changed_since` directly, mirroring the existing `changed_since is None` fallback).

### Proof of Concept
Unit/integration test plan (extends existing test patterns exercising `compute_v2_review_set`):
1. Init a repo, make an initial commit (`file_a.py` with benign content); capture `baseline_sha = capture_git_baseline(cwd)` and `head_at_capture = _git_rev_parse_head(cwd)` (simulating UPS).
2. Write a dangerous change into `danger.py` (e.g., `os.system(user_input)`), `git add`, `git commit -m "add danger"`.
3. Run `git commit --amend -m "add danger (amended)"` — this is the attacker's normal git operation that shifts `HEAD` off the linear path from `head_at_capture`.
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. **Expected (secure) assertion**: `danger.py` is present in the returned `review_paths`.
6. **Actual (vulnerable) result**: `review_paths` is empty (or omits `danger.py`), because `_is_ancestor(head_at_capture, HEAD)` is `False` after amend, so `dirty_now` never gains the committed file and the working tree is clean, causing the intersection with `changed_since` to be empty for that file.

This directly demonstrates that `Stop-hook reviewed file selection` (`handle_stop_hook` → `compute_v2_review_set`) will call `_skip(9, ...)` and skip the dangerous change, confirming the baseline-state shift bypass.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
