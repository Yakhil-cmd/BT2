### Title
`repository_owner` fallback to `organization.login` lets an attacker-controlled org's webhook secret authenticate a `pull_request` payload whose `repository.full_name` targets a victim's production stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the webhook secret) used to authenticate a payload via `repository_owner`, which falls back to `params.dig('organization','login')` when `repository.owner.login` is absent. `LabelCapturingHandler` (and its siblings) instead resolve the affected `Repository`/`Stack` from the independently-controlled `params.repository.full_name` field, so the field that authenticates the request and the field that determines which stack is mutated can point to different organizations/repositories.

### Finding Description
The broken binding, stated as an equality that the code assumes but does not enforce: `repository_owner == organization_owning(params.repository.full_name)`.

- `WebhooksController#repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) .
- `verify_signature` uses that value to pick the `GitHubApp`: `github_app = Shipit.github(organization: repository_owner)` then calls `github_app.verify_webhook_signature(signature, raw_post)` [2](#0-1) .
- `Shipit.github` only does per-organization config lookup ("multi-org" mode) when `github_default_organization` is non-nil (i.e., when `secrets.github` is keyed by org names rather than top-level GH keys); in "single-app" mode it ignores the `organization:` argument entirely and always returns the one configured `GitHubApp` [3](#0-2) . In multi-org mode (`test/dummy/config/secrets_double_github_app.yml`), each org has its own (possibly nil) `webhook_secret` [4](#0-3) .
- `GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for that org: `return true unless webhook_secret` [5](#0-4) .
- Meanwhile `LabelCapturingHandler` (and `OpenedHandler`, `ClosedHandler`, `LabeledHandler`, `UnlabeledHandler`, `ReopenedHandler`) resolve the target `Repository` purely from `params.repository.full_name`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) , then derives `stack` from that repository's `review_stacks` [7](#0-6) , and on `unlabeled`/`labeled`/etc. persists `params.pull_request.labels.map(&:name)` onto that stack's `PullRequest` [8](#0-7) .
- Nothing cross-checks that `repository.full_name`'s owner equals `repository_owner` (i.e., equals `organization.login`). The `ExplicitParameters` schema for this handler only requires `repository.full_name` to be a `String`, with no format/owner constraint [9](#0-8) .

Exploit flow: attacker's own GitHub organization/repo is configured in Shipit (or configured with no `webhook_secret`, which is a legitimate and common config as shown in the dummy multi-org fixture). Attacker crafts a `pull_request` webhook body where `organization.login` = their own org (so `repository_owner` resolves to their org, whose secret they know, or is nil and trivially verified) while `repository.owner.login` is omitted and `repository.full_name` is set to `victim-org/victim-repo`. The signature is computed correctly against the attacker's own (weak/absent/known) secret for their org, so `verify_signature` passes. The event then dispatches to `LabelCapturingHandler`, which loads the victim's `Repository`/`Stack` via `repository.full_name` and, for `action=unlabeled`, overwrites `PullRequest#labels` for the victim's PR/review stack — labels which `ReviewStack#env` subsequently uppercases into environment variable keys, potentially injecting into deploy/rollback commands for whatever stack is affected, including a production-environment stack.

Existing guards fail: `verify_signature` authenticates *a* secret, but not "the secret belonging to the repository the payload claims to mutate" — it authenticates against `organization.login`/`repository.owner.login`, a field disjoint from `repository.full_name` used everywhere downstream. `drop_unhandled_event` and the `ExplicitParameters` schema do not perform any repository/owner consistency check.

### Impact Explanation
This is a payload that authenticates as one organization/repository but mutates state (`PullRequest#labels`, and consequently `ReviewStack#env` values fed into deploy/rollback `Command`/`PTY.spawn` invocations) belonging to a completely different repository's stack, matching the Critical category "a payload for one repository mutating another's stack" and potentially "unauthorized deploy/rollback" if the injected label-derived environment variables are consumed by deploy scripts. Repeatable against any stack whose full repository name is known to the attacker, as long as the attacker controls (or Shipit is configured with) at least one organization that either has no `webhook_secret` or whose secret the attacker knows. The blast radius spans every tenant/stack configured in the same Shipit instance, since the handler-side lookup keys purely off attacker-supplied `repository.full_name` with no relation to the authenticated organization.

### Likelihood Explanation
Requires Shipit to be running in the multi-org GitHub App configuration (`secrets.github` keyed by org names) with at least one organization onboarded that has no `webhook_secret` configured, or one whose secret the attacker otherwise knows (e.g., their own onboarded org). This is a plausible/documented configuration (see `test/dummy/config/secrets_double_github_app.yml`, which sets `webhook_secret: # nil` for both orgs) rather than a contrived edge case. Attacker cost is a single crafted HTTP POST with no signature secret needed for a nil-secret org, fully repeatable and automatable against multiple victim stacks.

### Recommendation
Verify the webhook signature using the same field that handlers use to resolve the affected repository/stack — derive the app/organization for signature verification from `params.repository.full_name`'s owner (or require `repository.owner.login` to be present and matching), rather than falling back to the independent `organization.login` field. Additionally, add a consistency check in `WebhooksController#verify_signature` (or in each handler) asserting that the authenticated organization equals the owner segment of `repository.full_name` before dispatching to handlers.

### Proof of Concept
Minitest plan under `test/controllers/webhooks_controller_test.rb` (multi-org fixtures from `test/dummy/config/secrets_double_github_app.yml`):
1. Configure test app with two orgs, `OrgOne` (attacker, `webhook_secret: nil`) and `OrgTwo`/victim org owning a production-environment stack with an existing `PullRequest`.
2. Build a `pull_request` webhook body: `action: 'unlabeled'`, `organization: { login: 'OrgOne' }`, no `repository.owner.login`, `repository: { full_name: 'OrgTwo/victim-repo' }`, `pull_request.labels: [{ name: 'malicious-env-key' }]`.
3. POST to `/webhooks` with `X-Github-Event: pull_request` and no/garbage `X-Hub-Signature` (since `OrgOne` has nil `webhook_secret`, `verify_webhook_signature` returns `true` unconditionally).
4. Assert response is `:ok` (not `:unprocessable_entity`), i.e. `verify_signature` passed using `OrgOne`'s (nil) secret while `repository_owner` resolved to `'OrgOne'` — establishing the equality `repository_owner ('OrgOne') != owner_of(repository.full_name) ('OrgTwo')` still passed verification.
5. Assert the victim's `PullRequest#labels` in `OrgTwo/victim-repo`'s stack was updated to `['malicious-env-key']`, demonstrating that a payload authenticated under `OrgOne` mutated `OrgTwo`'s production stack state.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
