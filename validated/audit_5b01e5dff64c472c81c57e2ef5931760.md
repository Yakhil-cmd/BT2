### Title
Unprivileged front-running of `coin_registry::new_currency<T>` permanently blocks legitimate `Currency<T>` registration and grants the squatter a live `TreasuryCap<T>` - (File: `crates/sui-framework/packages/sui-framework/sources/registries/coin_registry.move`)

### Summary
`sui::coin_registry::new_currency<T: key>` is a fully public, unprivileged entry point into the system `CoinRegistry` (object `0xc`). It is gated only by `assert!(!registry.exists<T>(), ECurrencyAlreadyExists)` and then immediately calls `derived_object::claim(&mut registry.id, CurrencyKey<T>())`, which permanently reserves the `(registry, T)` slot via a dynamic field marker that can never be un-set. Because Move generic type parameters only need to satisfy the ability bound (`key`) and not any capability proving ownership of `T`, *any* caller can invoke this function using *any* existing `key`-ability struct as `T` - including a struct they don't control - racing ahead of the type's legitimate owner. This is the exact same root cause as the Alchemix `Bribe.swapOutRewardToken` bug: a permissionless "enable/register" path that an attacker can call first to make the legitimate, gated caller's later "doesn't exist yet" check fail forever.

### Finding Description [1](#0-0) 

`new_currency<T: key>` has no OTW/witness requirement (unlike `new_currency_with_otw<T: drop>`, which requires `sui::types::is_one_time_witness(&otw)`), so it does not require the caller to actually possess a value of `T` or be the module that defines `T`. The only guard against duplicate registration is: [2](#0-1) 

and the underlying claim primitive: [3](#0-2) 

`derived_object::claim` aborts with `EObjectAlreadyExists` on any subsequent attempt to claim the same `(parent, key)` pair, and the note in the module explicitly documents this as a race: "The parent only maintains a record of which derived addresses have been claimed to prevent duplicates" - once claimed, it is claimed forever, regardless of who claimed it.

Critically, `new_currency` also unconditionally mints a working `TreasuryCap<T>` for the caller via `coin::new_treasury_cap`: [4](#0-3) 

`new_treasury_cap` creates a brand-new `Supply<T>` with **no witness/uniqueness check at all** (`balance::create_supply_internal()`), relying entirely on the caller-side gate in `coin_registry::new_currency` to prevent abuse. That gate checks only "is this type already registered in the CoinRegistry," not "is the caller authorized to mint this type."

This mirrors the Alchemix pattern precisely:
- Alchemix: `Bribe.notifyRewardAmount(token, amount)` lets anyone permissionlessly "enable" a whitelisted token, so an attacker front-runs `Voter.swapReward`'s "new token must not already exist" check.
- Sui: `coin_registry::new_currency<T>()` lets anyone permissionlessly claim the `CurrencyKey<T>` derived-object slot for any `key`-ability type `T`, so an attacker front-runs the legitimate project's later `new_currency<T>()` (or, for OTW-based coins, the analogous `finalize_registration` -> `derived_object::claim` step), which then aborts forever with `EObjectAlreadyExists`/`ECurrencyAlreadyExists`.

### Impact Explanation
An attacker who observes (via mempool/consensus) that a project is about to launch an object-typed ("dynamic") coin - the pattern shown in the framework's own test package: [5](#0-4) 

can call `coin_registry::new_currency<Dynamic>()` first, with arbitrary attacker-chosen `decimals`/`symbol`/`name`/`description`/`icon_url`. This:
1. **Permanently and irreversibly prevents the legitimate project from ever registering the canonical `Currency<T>` entry** for their coin type in the system-wide `CoinRegistry` (object `0xc`), since the derived-object slot is claimed for good - a harmful, permanent smart-contract-level DoS on the project's ability to publish authoritative metadata that wallets, explorers, and DeFi protocols are meant to trust.
2. **Grants the attacker a fully functional `TreasuryCap<T>`** for a type they do not own, backed by its own independent `Supply<T>`. Since `Coin<T>`/`Balance<T>` carry no reference back to which `Supply<T>` minted them (fungibility is enforced purely by the phantom type `T`), this is a genuine unauthorized-mint capability for the squatted type, not merely a griefing annoyance.

This satisfies the "harmful smart-contract behavior" / permanent-DoS class of High-severity impacts, and edges toward Critical if the squatted type is later used to mint tokens that circulate as if legitimate (since nothing in the `Coin`/`Balance` model can distinguish the attacker's `Supply<T>` from a "real" one for the same `T`).

### Likelihood Explanation
High. The attack requires no special privilege - only knowledge of the target type name `T` (which is public on-chain/off-chain, e.g. visible via a pending transaction in the mempool or a published-but-not-yet-registered package) and a plain transaction calling `coin_registry::new_currency<T>()`. No signatures, capabilities, or coordination with validators/admins are needed, matching the "unauthenticated/ordinary caller" threat model in scope.

### Recommendation
- Require `T` to carry proof of authorization to register a currency (e.g., require an OTW/witness value of `T`, or require a capability object created only by the module that defines `T`, analogous to how `new_currency_with_otw` enforces `is_one_time_witness`).
- Alternatively, restrict `new_currency<T: key>` to be callable only from the module that defines `T` (e.g., via a `public(package)`-style boundary enforced by a witness struct minted in that module's `init`), so the derived-object slot for `CurrencyKey<T>` cannot be claimed by unrelated code.
- Do not mint a real `TreasuryCap<T>`/`Supply<T>` until the caller's authority over `T` has been established.

/// Creates a new currency.
///
/// Note: This constructor has no long term difference from `new_currency_with_otw`.
/// This can be called from the module that defines `T` any time after it has been published.
public fun new_currency<T: /* internal */ key>(
    registry: &mut CoinRegistry,
    decimals: u8,
    symbol: String,
    name: String,
    description: String,
    icon_url: String,
    ctx: &mut TxContext,
): (CurrencyInitializer<T>, TreasuryCap<T>) {
    assert!(!registry.exists<T>(), ECurrencyAlreadyExists);
    assert!(is_ascii_printable!(&symbol), EInvalidSymbol);

    let treasury_cap = coin::new_treasury_cap(ctx);
    let currency = Currency<T> {
        id: derived_object::claim(&mut registry.id, CurrencyKey<T>()),
        decimals,
        name,
        symbol,
        description,
        icon_url,
        supply: option::some(SupplyState::Unknown),
        regulated: RegulatedState::Unregulated,
        treasury_cap_id: option::some(object::id(&treasury_cap)),
        metadata_cap_id: MetadataCapState::Unclaimed,
        extra_fields: vec_map::empty(),
    };

    (CurrencyInitializer { currency, is_otw: false, extra_fields: bag::new(ctx) }, treasury_cap)
}

public fun claim<K: copy + drop + store>(parent: &mut UID, key: K): UID {
