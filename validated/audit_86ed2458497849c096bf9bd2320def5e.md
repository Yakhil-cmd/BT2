### Title
Bad-debt floor clamp resurrects wiped-out supply claims that drain future depositors - (File: contracts/pool/src/interest.rs)

### Summary
When socialized bad debt equals or exceeds total supplied value, `apply_bad_debt_to_supply_index` clamps the supply index *up* to `SUPPLY_INDEX_FLOOR_RAW` (RAY/1000) instead of zeroing supplier shares. Positions that were economically wiped out retain a positive scaled balance whose floor-unscaled claim is still payable. Because `require_reserves` only checks current cash, the next depositor's tokens fund the phantom claim — direct theft of user funds and protocol insolvency. This is the XOXNO analog of CVE-2019-5855's class: an integer-bound handling defect (saturating/clamping arithmetic) that corrupts accounting state into an exploitable condition.

### Finding Description
`contracts/pool/src/interest.rs` `apply_bad_debt_to_supply_index` (lines 73-89):

```rust
let capped = bad_debt.min(total_supplied_value);
let remaining = total_supplied_value.checked_sub(cache.env(), capped);
let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
let new_supply_index = cache.supply_index().mul_floor(cache.env(), reduction_factor);
cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

When `bad_debt >= total_supplied_value`, `capped == total_supplied_value`, `remaining == 0`, `reduction_factor == 0`, and `new_supply_index == 0`. The `.max(SUPPLY_INDEX_FLOOR_RAW)` then sets the index to `RAY/1000` — a *positive* index — while every supplier's scaled shares are unchanged. Each wiped supplier keeps claim value `floor(scaled * RAY/1000 / RAY / 10^(27-d)) > 0` tokens against a pool with zero backing.

Bad debt reaches this path through `clean_bad_debt` and the liquidation seize path (`contracts/pool/src/ops/seize.rs`, `contracts/controller/src/positions/liquidation/mod.rs`), both reachable by unprivileged callers. A severe price move or self-liquidation on an undercollateralized position can push unpaid debt past total supplied value in a thin market.

The pool's own test proves the end-to-end drain: `contracts/pool/tests/interest.rs` `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (lines 372-427) shows that after the clamp, `unscale_supply_floor(old_scaled) > 0`, a fresh deposit of that size makes `require_reserves` pass, and `resolve_withdrawal` + `burn_supply` + `debit_cash` pays the wiped position exactly the fresh deposit, leaving `cash < fresh_claim` — the new supplier's funds are gone. The withdrawal path uses the identical call sequence as `ops/withdraw.rs`, so the stranded claim is spendable through the normal `withdraw` entrypoint.

### Impact Explanation
Theft of user funds and protocol insolvency. Once the floor clamp fires, holders of legacy supply shares hold a token-denominated claim with no backing. Any subsequent `supply` deposit adds real cash that `require_reserves` counts toward those phantom claims; the wiped position withdraws first and the honest depositor's claim exceeds remaining cash permanently. Repeatable on every fresh deposit until the stranded shares are burned.

### Likelihood Explanation
Requires bad debt ≥ total supplied value in a single market, i.e., a wipeout event — achievable via `clean_bad_debt` on dust-threshold positions or a liquidation that cannot cover debt (price gap, illiquid collateral, or a deliberately constructed underwater account). Likelihood is gated on an insolvency event occurring, but no privileged action is needed to trigger the clamp or to later withdraw the phantom claim; the arithmetic defect converts what should be a bounded write-down into a standing theft vector.

### Recommendation
When `remaining == 0` (full wipeout), burn or zero all supply shares rather than clamping the index to `SUPPLY_INDEX_FLOOR_RAW` — e.g., set the index to zero and gate further supply minting until shares are reset, or track a wiped flag that forces `resolve_withdrawal`/`unscale_supply_floor` to return zero for pre-wipe positions. The floor exists to avoid a zero index, but a positive index on wiped shares is strictly worse: it manufactures unbacked claims. At minimum, block withdrawals of shares minted before a full-wipe event.

### Proof of Concept
The in-repo test `contracts/pool/tests/interest.rs:372-427` is a working PoC at the cache layer:

1. Market with `supplied = 1000 RAY` scaled shares, `supply_index = RAY`, `cash = 0`.
2. `apply_bad_debt_to_supply_index(cache, 5000 RAY)` (bad debt 5× supply value) → index clamps to `SUPPLY_INDEX_FLOOR_RAW`, shares unchanged.
3. `unscale_supply_floor(old_scaled) > 0` — wiped supplier retains a token claim `stranded`.
4. Victim supplies `fresh_cash = stranded`; `mint_supply` + `credit_cash`.
5. Wiped supplier calls `resolve_withdrawal(i128::MAX, old_scaled)` → `require_reserves(gross)` passes against fresh cash → `burn_supply` + `debit_cash(gross)` transfers out `gross == fresh_cash`.
6. Assert `cache.cash() < fresh_claim` — victim's deposit is unrecoverable.

Controller-level invocation: unprivileged `clean_bad_debt` (or `liquidate` producing unpaid debt) on a market where outstanding debt exceeds supplied value, then `withdraw` by the wiped position after any new `supply` lands.
