### Title
Unsanitized `args.Path` extension in `renderFileContentAsMarkdown` allows markdown/terminal-escape injection into agent-task log output - (File: pkg/cmd/agent-task/shared/log.go)

### Summary
`renderFileContentAsMarkdown` builds a markdown code fence with `fmt.Sprintf("```%s\n%s\n```", lang, content)` where `lang` is `filepath.Ext(path)` and `path` comes directly from LLM tool-call JSON arguments (`viewToolArgs.Path`, `createToolArgs.Path`, `strReplaceToolArgs.Path`) as a plain `string`, never routed through the codebase's `iostreams.Untrusted` sanitization path that is deliberately used for other externally-sourced log content. An attacker who controls file names in a repository that a GitHub Copilot coding agent later operates on can cause the agent's tool-call `path` argument to reflect a crafted filename (containing backticks/newlines or raw ANSI escape bytes as the "extension"), which is then spliced unsanitized into the rendered markdown fence shown by `gh agent-task ... --log`.

### Finding Description
`renderLogEntry` dispatches on tool-call names and, for `view`, `create`, and `str_replace`, decodes tool arguments with plain `json.Unmarshal` into structs whose `Path` field is a bare `string`: [1](#0-0) 

This contrasts with `choice.Delta.Content` and `choice.Delta.ReasoningText`, which are typed `iostreams.Untrusted` and therefore automatically ANSI-sanitized whenever printed via `fmt`: [2](#0-1) [3](#0-2) 

`args.Path` is passed straight into `renderFileContentAsMarkdown`, which derives `lang` via `filepath.Ext` and interpolates it unsanitized into the fence: [4](#0-3) 

Because `lang` never passes through `Untrusted.String()`'s `asciisanitizer` transform, a crafted "extension" segment of a file path (i.e., everything after the last `.`) — for example one containing a closing fence sequence (`` ` ``/newline) followed by attacker markdown, or raw ANSI escape bytes — is emitted verbatim into the rendered output at `fmt.Fprint(w, rendered)` in `renderMarkdownWithFormat`: [5](#0-4) 

Since git/GitHub tree entries permit arbitrary non-`/`/non-NUL bytes in file names, an attacker can commit a file whose name's extension segment is composed of such characters. If the Copilot coding agent later issues a `view`/`create`/`str_replace` tool call referencing that path (which reflects real repository content, so this is plausible), the raw path text flows into the log stream and is rendered by `gh agent-task view --log`/`Follow` on the victim's terminal without going through the same sanitization boundary applied to tool-call `content`.

### Impact Explanation
This is an output/terminal injection issue: the attacker can break out of the intended code-fence boundary to inject arbitrary markdown into the rendered log (spoofing headings, bold text, fake tool-call results) and/or inject raw ANSI/control sequences that reach the terminal emulator, matching the "output sanitization bypass" class referenced in the audit rules. It does not achieve code execution, credential exfiltration, or file write outside the intended path — the impact is limited to what the victim sees on their own terminal while viewing Copilot agent-task logs (potential terminal spoofing/hiding of content, not remote compromise).

### Likelihood Explanation
Exploitation requires: (1) the attacker controls a public repo/issue that a GitHub Copilot coding agent session operates against, and (2) the coding agent's tool-call `path` argument echoes the attacker-chosen file path as-is (plausible, since these tool arguments typically mirror real repository paths), and (3) a victim runs `gh agent-task view --log`/`--follow` against that session. This is feasible but indirect — the attacker does not directly control the JSON tool-call stream, only influences it via file naming that the LLM agent is likely, but not guaranteed, to echo verbatim.

### Recommendation
Wrap `viewToolArgs.Path`, `createToolArgs.Path`, and `strReplaceToolArgs.Path` (and any other tool-call-derived string later fed into `renderFileContentAsMarkdown`/used to build fenced/rendered output) in `iostreams.Untrusted`, or otherwise sanitize `filepath.Ext(path)` before interpolating it into the fence — e.g., strip/escape backticks, newlines, and control characters, and fall back to a safe default language string if the extension contains any of those characters.

### Proof of Concept
Go unit test sketch for `pkg/cmd/agent-task/shared`:
```go
func TestRenderFileContentAsMarkdown_ExtensionInjection(t *testing.T) {
    var buf bytes.Buffer
    ios, _, out, _ := iostreams.Test()
    maliciousPath := "file.`\n**INJECTED**\n```\nfakecontent\n```" // extension segment breaks fence
    err := renderFileContentAsMarkdown(maliciousPath, "real content", &buf, ios)
    require.NoError(t, err)
    rendered := out.String()
    // Assert the injected markdown is rendered outside/breaking the intended fence,
    // i.e. "INJECTED" appears formatted (bold) rather than as literal fenced text.
    require.Contains(t, rendered, "INJECTED")
}
```
Extend by driving it through `Render`/`Follow` with a fabricated SSE `data:` line whose `tool_calls[0].function.arguments` JSON contains `{"path": "<malicious>"}` for the `create`/`view`/`str_replace` tool name, and assert the terminal output contains the raw injected bytes/formatting rather than literal fenced text — while an equivalent payload placed in `choice.delta.content` (typed `Untrusted`) is confirmed to be sanitized, demonstrating the inconsistency.

func renderMarkdownWithFormat(md string, w io.Writer, io *iostreams.IOStreams, formatFunc func(string) string) error {
	rendered, err := markdown.Render(md,
		markdown.WithTheme(io.TerminalTheme()),
		markdown.WithWrap(io.TerminalWidth()),
	)

	if err != nil {
		return fmt.Errorf("failed to render markdown: %w", err)
	}

	rendered = strings.TrimSpace(rendered)
	if formatFunc != nil {
		rendered = formatFunc(rendered)
	}

	fmt.Fprint(w, rendered)

	return nil
}

func renderFileContentAsMarkdown(path, content string, w io.Writer, io *iostreams.IOStreams) error {
	lang := filepath.Ext(filepath.ToSlash(path))

	if lang == ".md" {
		return renderRawMarkdown(content, w, io)
	}

	md := fmt.Sprintf("```%s\n%s\n```", lang, content)
	// Glamour adds leading newlines when content is only a code block,
	// so we only want to add a trailing newline.
	formatFunc := func(s string) string {
		return fmt.Sprintf("%s\n\n", s)
	}

	return renderMarkdownWithFormat(md, w, io, formatFunc)
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
