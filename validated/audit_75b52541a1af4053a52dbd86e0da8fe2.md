### Title
Cross-Organization Commit Status Forgery via Unscoped SHA Lookup in Multi-Org Webhook Handling - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to validate a request against using an organization name taken from the *same untrusted request body* it is trying to authenticate. Once that per-organization signature check passes, the `status` event handler applies the resulting write globally by commit SHA, with no check that the SHA actually belongs to a stack owned by the organization that signed the request. This breaks the intended binding "organization that authenticated the webhook" == "repository/stack that gets written."

### Finding Description
Shipit supports hosting multiple GitHub organizations from a single instance, each with its own GitHub App and its own `webhook_secret` [1](#0-0) , as shown in the multi-org fixture [2](#0-1) .

The webhook signature check determines *which* organization's secret to verify against using data taken from the very payload being verified:
```
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 

So `Shipit.github(organization: repository_owner)` picks the `GitHubApp` (and its `webhook_secret`) that corresponds to whatever organization the attacker put in the payload. If that organization is one for which the attacker legitimately controls a webhook delivery (e.g. their own small/unrelated org that also happens to be onboarded to the same Shipit instance), `verify_webhook_signature` will succeed using that org's secret [4](#0-3) .

Once the signature passes, the `status` event is dispatched to `StatusHandler`, which resolves the target purely by commit SHA, with no scoping to the stack/repository/organization that was actually authenticated:
```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [5](#0-4) 

`Commit.where(sha: ...)` is a global, unscoped ActiveRecord query across every stack tracked by the Shipit instance — it is not filtered by the `repository`/`organization` fields that were used to select the signing secret. This is exactly the class of bug in the reference report: a value trusted to select the authorization context (the IP for the node DB, here the organization for the webhook secret) is not the same value enforced on the operation actually performed (arbitrary DB writes, here a write against an unrelated repository's commit).

### Impact Explanation
An attacker who legitimately controls (or can trigger) a signed webhook for *any* GitHub organization configured in the same multi-tenant Shipit instance can forge a `status` event payload claiming any commit SHA that belongs to a *different* organization's stack, and have Shipit record an attacker-chosen CI status (`state`, `context`, `target_url`, `description`) against that unrelated commit. Commit status is used by Shipit's deployability/required-status logic (`required_statuses`, `blocking_statuses`, `soft_failing_statuses` referenced via `Stack` delegation to `deploy_spec`) [6](#0-5) . Forging a passing status on another organization's commit can unblock deploy gating and continuous deployment for that unrelated stack, resulting in an unauthorized deploy/rollback of code the attacker does not control — meeting the "unauthorized deploy" bar for Critical impact.

### Likelihood Explanation
Requires: (1) the target Shipit instance is configured for multiple GitHub organizations (documented, supported feature), and (2) the attacker legitimately administers a webhook delivery for at least one of the onboarded organizations (their own weakly-trusted org), and (3) the target commit SHA in the victim organization's repo, which is typically discoverable (public repos, PR pages, or Shipit's own UI). No `ApiClient` token, no `webhook_secret` of the victim org, and no privileged Shipit account are needed — only a valid signature from the attacker's own, unrelated organization.

### Recommendation
Scope the effect of every webhook handler to the organization/repository that was actually verified, not just to fields taken from the unauthenticated JSON body. Concretely: pass the verified `repository_owner`/organization through to `StatusHandler` (and other handlers) and constrain `Commit.where(sha: ...)` to `Commit.joins(stack: :repository).where(sha: params.sha, repositories: { owner: verified_organization })`, so a status can only be attached to commits belonging to the organization whose secret actually validated the request.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgOne` (victim, tracks a stack with commit SHA `abc123...`) and `OrgTwo` (attacker's own org, tracked by the same instance), each with distinct `webhook_secret`s, per `lib/shipit.rb#github_app_config` and the documented multi-org schema.
2. Attacker, who owns/administers `OrgTwo`'s GitHub App, crafts a `status` webhook payload:
```json
{
  "sha": "abc123...",  // commit belonging to OrgOne's stack
  "state": "success",
  "context": "ci/required-check",
  "repository": { "owner": { "login": "OrgTwo" } }
}
```
3. Sign it with `OrgTwo`'s legitimate `webhook_secret` and POST to `/webhooks` with header `X-Github-Event: status`.
4. `verify_signature` computes `repository_owner == "OrgTwo"`, fetches `OrgTwo`'s app, and successfully verifies the signature (`app/controllers/shipit/webhooks_controller.rb`).
5. `StatusHandler#process` executes `Commit.where(sha: "abc123...")`, which matches the commit under `OrgOne`'s stack (no org check), and calls `create_status_from_github!`, recording an attacker-forged "success" status on `OrgOne`'s commit — potentially unblocking continuous deployment for a stack the attacker has no access to.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
