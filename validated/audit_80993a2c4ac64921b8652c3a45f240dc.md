## Title
Webhook signature verification is keyed to `repository.owner.login` while the handler mutates the Stack found via the independent `repository.full_name` field, allowing a payload verified under one (secret-less) organization to alter another organization's Stack — ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/unlabeled_handler.rb], [File: app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb])

### Summary
`WebhooksController#verify_signature` resolves which GitHub App/secret to validate against solely from `params.dig('repository','owner','login')`, then the pull-request handlers (`UnlabeledHandler`, `LabeledHandler`, `LabelCapturingHandler`) locate the `Repository`/`Stack` to mutate using the *independent* `params.repository.full_name` field from the same attacker-controlled JSON body. Because GitHub's per-organization webhook secret is documented as optional and multi-org configuration is supported, if any onboarded organization has no `webhook_secret` configured, `verify_webhook_signature` trivially returns `true`, letting a forged payload whose `repository.owner.login` names that secret-less org carry a `repository.full_name` pointing at a totally different (properly secured) org's repository, and drive that victim's Stack's label-gated archive/unarchive logic.

### Finding Description
The binding the code is supposed to enforce is:
`organization used to verify the webhook signature == owner of the Repository/Stack that gets mutated`
i.e. `repository_owner (params.dig('repository','owner','login')) == owner(Repository.from_github_repo_name(params.repository.full_name))`.

Tracing the path:
1. `WebhooksController#verify_signature` computes `repository_owner` purely from the JSON body: [1](#0-0)  and uses it to select the GitHub App config: [2](#0-1) .
2. `Shipit.github(organization:)`/`github_app_config` looks up that organization's config in `secrets.github` (multi-tenant mode, distinguished from single-app mode by `TOP_LEVEL_GH_KEYS`): [3](#0-2) .
3. `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that resolved organization has no `webhook_secret` configured: [4](#0-3) . The webhook secret is explicitly documented as optional per-app config.
4. Once verification passes, the actual event handlers never re-check `repository.owner.login`. They instead resolve the target `Repository`/`Stack` from `params.repository.full_name` alone: `UnlabeledHandler#repository` [5](#0-4) , and `LabelCapturingHandler#repository` [6](#0-5) . `Repository.from_github_repo_name` parses `owner/name` straight out of that string with no cross-check against the `repository.owner.login` used for signature verification: [7](#0-6) .

**Attacker request:** POST `/webhooks` with `X-Github-Event: pull_request`, a body where `repository.owner.login = "attacker-org"` (an org onboarded into Shipit's multi-tenant config with no `webhook_secret` set) but `repository.full_name = "victim-org/victim-repo"`, `action: "unlabeled"`/`"labeled"`, and a `pull_request.head.ref` matching an existing review stack's branch on the victim repo. No `X-Hub-Signature` needs to be correct because verification for `attacker-org` is unconditionally `true`.

**Why existing guards don't catch it:** `drop_unhandled_event` only checks the event name is registered; `verify_signature` only checks the organization named in the payload, not the organization actually being mutated; the `ExplicitParameters` schema for these handlers requires `repository.full_name` to be a `String` but performs no consistency validation against `repository.owner.login`; and the handler's `stack`/`repository` resolution trusts `full_name` unconditionally. Thus the two fields that should be bound together (verifying org vs. mutated org) are read and used completely independently from the same attacker-supplied JSON.

### Impact Explanation
An attacker can flip `Stack#archived?`/`unarchived?` state (which gates review-stack provisioning/deployment eligibility) for a victim repository's review stack, without possessing that victim org's `webhook_secret`, `api_clients_secret`, or any Shipit session — this is exactly the "payload for one repository mutating another's stack" Critical category. It is repeatable against any repository already synced into Shipit's DB, for as many stacks/branches as the attacker can enumerate, as long as at least one onboarded organization in the Shipit instance has no webhook secret configured. Blast radius spans all tenants sharing that Shipit instance.

### Likelihood Explanation
Exploitation requires: (1) the Shipit instance runs multi-organization GitHub App configuration (`secrets.github` keyed by org, per `github_default_organization`/`TOP_LEVEL_GH_KEYS`), and (2) at least one onboarded organization has left `webhook_secret` blank — an explicitly supported, "optional" configuration per `docs/setup.md`. Given that, the attacker's cost is a single unauthenticated HTTP POST with a crafted JSON body; no GitHub credentials, sessions, or secrets are needed. This is a realistic misconfiguration in any hosted/shared multi-tenant Shipit deployment, though it does not apply to single-organization deployments (where the `organization` argument is ignored and only the one global secret is checked).

### Recommendation
In `WebhooksController#verify_signature` and in every `PullRequest` handler, require that the organization resolved for signature verification (`repository.owner.login`) matches the owner segment parsed from `repository.full_name` before any handler runs; reject the request (422) on mismatch. Additionally, do not allow `verify_webhook_signature` to silently return `true` for organizations with a blank secret when operating in multi-org mode — require every onboarded org to have a non-blank secret, or explicitly disallow onboarding without one.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`-style, no live GitHub):
1. Configure multi-org secrets: `attacker-org` with `webhook_secret: nil`, `victim-org` with `webhook_secret: "victimsecret"`.
2. Seed `victim-org/victim-repo` as a `Shipit::Repository` with `provisioning_behavior: allow_with_label`, label `"deploy-ok"`, and create an active, non-archived review `Stack` for a PR branch `feature-x` (`stack.archived?` == `false`, asserting label-gated flag before request).
3. POST `/webhooks` with header `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and body: `{"action":"unlabeled","repository":{"owner":{"login":"attacker-org"},"full_name":"victim-org/victim-repo"},"pull_request":{"head":{"ref":"feature-x"},"labels":[],"state":"open",...},...}`.
4. Assert response is `200 OK` (not `422`) — proving verification passed under `attacker-org`'s blank secret.
5. Assert `stack.reload.archived?` changed (e.g., became `true`), i.e., `owner(verifying org) = "attacker-org" != owner(mutated stack's repo) = "victim-org"`, demonstrating the binding is broken.
6. Negative control: repeat with `repository.full_name` unchanged but posting under `victim-org`'s (correct) secret-required path with an invalid signature — assert `422` and no state change, confirming the bypass is specific to the secret-less org confusion, not a general signature-check absence.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
