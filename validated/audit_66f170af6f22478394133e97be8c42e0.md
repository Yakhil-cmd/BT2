### Title
Missing webhook secret causes `verify_webhook_signature` to accept unsigned/forged payloads - (File: lib/shipit/github_app.rb)

### Summary
`Shipit::GitHubApp#verify_webhook_signature` unconditionally returns `true` when `@webhook_secret` is blank, so `WebhooksController#verify_signature` accepts any POST to `/webhooks` for that org with an arbitrary or absent `X-Hub-Signature`. Since `repository_owner` (and thus the `GitHubApp` instance selected) is derived from attacker-controlled JSON in the request body, any internet user can forge webhook events for such an org's stacks.

### Finding Description
The broken binding is: `verified == true` should imply `HMAC-SHA1(webhook_secret, raw_body) == signature`, but the code enforces `verified == true` whenever `webhook_secret.nil?`, with zero cryptographic check: [1](#0-0) 

`WebhooksController#verify_signature` selects the `GitHubApp` for the org purely from the untrusted payload (`repository_owner` reads `params.dig('repository','owner','login')` or `params.dig('organization','login')`), then calls `verify_webhook_signature` and only rejects with 422 if it returns `false`: [2](#0-1) [3](#0-2) 

There is no other guard between the controller entry point and `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` — `check_if_ping` and `drop_unhandled_event` only filter by event type, not authenticity: [4](#0-3) 

Root cause: `@webhook_secret` is set straight from config with no enforcement that it be present, and the example/documented configuration ships with it commented out/nil by default: [5](#0-4) [6](#0-5) 

Attack: attacker sends `POST /webhooks` with header `X-Github-Event: push` (or `status`, `check_suite`, `membership`, etc.) and a JSON body whose `repository.owner.login` matches an org configured in Shipit whose `github.webhook_secret` is unset (this is the documented default when no secret is entered during setup, and is realistic for multi-org configs where only some orgs have a secret configured). No `X-Hub-Signature` header, or any garbage value, is required. `verify_webhook_signature` short-circuits to `true`, and the handlers registered for that event (e.g. `GithubSyncJob` enqueue on `push`, commit `Status` creation on `status`, `Team`/`User` creation on `membership`) run against real data as if GitHub had sent them, per the existing test evidencing the intended flow when signature verification fails/succeeds: [7](#0-6) [8](#0-7) 

Existing guards do not prevent this: `drop_unhandled_event` only screens by event name, not authenticity; `verify_signature` itself is the (bypassed) guard; there is no `ExplicitParameters` schema or session/token check on this unauthenticated endpoint (`WebhooksController` inherits `ActionController::Base`, not the authenticated base controller, and skips CSRF).

### Impact Explanation
For any org whose `GitHubApp` has no `webhook_secret` configured, an unauthenticated internet attacker can submit arbitrary webhook payloads that are treated as verified GitHub events, driving `Shipit::Webhooks.for_event(event)` handlers (e.g., queuing `GithubSyncJob`, writing commit `Status` records, creating `Team`/`User` records via `membership` events, triggering `RefreshCheckRunsJob` via `check_suite`) for that org's repositories. This is a record being written/mutated for a repository that never cryptographically authenticated the payload — matching the Critical category "authentication bypass (forged webhook … accepted)". The blast radius is scoped to orgs without a configured `webhook_secret`; it is fully repeatable per request and does not require any secret, session, or privileged role.

### Likelihood Explanation
Preconditions: an org entry in `Shipit.github_apps`/config whose `webhook_secret` is blank. This is the documented, out-of-the-box default in `config/secrets.development.example.yml` (`webhook_secret: # nil`) and plausible in real multi-org deployments where an operator forgets or has not yet set the secret for one org. Attacker cost is trivial: a single unauthenticated HTTP POST with a crafted JSON body, no credentials needed. Fully repeatable against any repository under that unconfigured org.

### Recommendation
Fail closed instead of open: require `webhook_secret` to be present for every configured GitHub org and reject (422/500) requests when it is missing, rather than treating a missing secret as "signature verified". At minimum, log/alert loudly and refuse to process webhooks for orgs lacking a configured secret, and update `verify_webhook_signature` so `return true unless webhook_secret` becomes `return false unless webhook_secret`.

### Proof of Concept
Minitest plan:
1. Unit test in `test/lib/shipit/github_app_test.rb` style:
   - `app = Shipit::GitHubApp.new('org', {})`
   - `assert_equal true, app.verify_webhook_signature(nil, 'anything')` — demonstrates the broken binding (`verified == true` while no HMAC check happened).
   - Contrast: `app_with_secret = Shipit::GitHubApp.new('org', { webhook_secret: 's3cr3t' })`; `assert_equal false, app_with_secret.verify_webhook_signature(nil, 'anything')`.
2. Integration test in `test/controllers/webhooks_controller_test.rb`:
   - Stub `Shipit.github(organization: 'no-secret-org')` to return a `Shipit::GitHubApp.new('no-secret-org', {})` (no `webhook_secret`).
   - `post :create` with `X-Github-Event: push`, no/garbage `X-Hub-Signature`, and a push payload for `no-secret-org/some-repo`.
   - Assert `assert_response :ok` (not `:unprocessable_entity`) and `assert_enqueued_with(job: GithubSyncJob, ...)`, proving the forged, unsigned webhook was accepted and processed.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
