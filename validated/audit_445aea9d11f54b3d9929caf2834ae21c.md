### Title
Attacker-supplied swap route executes arbitrary contract code inside the victim's authorized `swap_collateral`/`swap_debt`/`multiply`/`repay_debt_with_collateral` call tree, enabling wallet drain via a poisoned signed auth tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_tokens` forwards user-controlled `swap: Bytes` to the configured router and executes it inside the same invocation that carries the account owner's `require_auth`. Because the route payload names executable contract addresses (unallowlisted hop pools/venues), a malicious route can invoke an attacker-deployed contract that calls `token.transfer(victim -> attacker)` on *any* token the victim holds. Soroban recording mode attaches that sub-invocation to the victim's `swap_collateral` auth entry during `simulateTransaction`; if the victim signs the returned tree, the host enforces it and the wallet token is stolen — the direct analog of mtr executing a program named by attacker-controlled input in a privileged context.

### Finding Description
The strategy verbs take an opaque route byte string from the caller and execute it under the caller's root authorization:

- `Controller::swap_collateral` / `swap_debt` / `multiply` / `repay_debt_with_collateral` accept `swap: Bytes` and require `caller` to be owner/delegate via `require_authorized_caller` / `require_owner_or_delegate` → `caller.require_auth()` at the root frame [1](#0-0) [2](#0-1) .
- `swap_tokens` passes the bytes verbatim to the router: `router.execute_strategy(&controller, &amount_in, swap)`. The only on-chain protections are the exact-amount input authorization (`authorize_transfer_as_current` authorizes *the controller's* tokens, not the caller's), the flash guard, and post-hoc balance-delta checks (`RouterOverspend`, `NoSwapOutput`) — none of which restrict which contracts the route invokes or which extra `require_auth` calls those contracts make [3](#0-2) .
- The route is untrusted and venues are not allowlisted: "DEX swap router… executes multi-hop, multi-venue routes built off-chain and passed as XDR" [4](#0-3) .

The harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves the mechanism end-to-end: a route naming `RogueHopPool` causes `token.transfer(alice → attacker, WALLET_BALANCE)` on an arbitrary unrelated token to be recorded as a child of Alice's `swap_collateral` auth entry during simulation, and the transfer executes once the tree is signed [5](#0-4) [6](#0-5) .

### Impact Explanation
Theft of user funds. A victim who submits `swap_collateral` (or `swap_debt`, `multiply` with payment, `repay_debt_with_collateral`) using a route byte string supplied by a malicious quote/frontend can lose every token in their wallet, not merely the swap input — the rogue hop contracts can issue `require_auth`-gated calls for any asset and any amount attributable to the victim's address, all bundled invisibly inside the single auth tree returned by simulation. The controller's measured-output accounting still "succeeds" (the router can even pay a fair `token_out`), so the victim's collateral swap looks normal while unrelated wallet funds are drained.

### Likelihood Explanation
The attack is reachable by any unprivileged route author against any user who signs a simulated auth tree without inspecting its sub-invocations — the standard composition flow explicitly directs users to build the transaction from off-chain `routeXdr` and sign the simulation output [7](#0-6) . It requires the victim to sign the poisoned tree (the auth is not forged), which bounds likelihood below the severities of unconditional exploits, but no on-chain check distinguishes the theft leg from the swap, and wallets display auth trees poorly. Rated Medium–High; reported as High given direct theft of arbitrary user funds.

### Recommendation
Constrain what route-executed code can do under the caller's authority:

- Prefer `require_auth_for_args` / scoped auth for the strategy verbs, or execute the swap leg in a frame where only the controller's own `authorize_as_current_contract` entries (already correctly used for the input pull) exist — e.g., have the router be invoked by the controller with controller-auth only and never let the route reach the caller's address.
- Enforce a venue/pool allowlist in the router (or verify pool addresses against a registry) so route bytes cannot name attacker-deployed contracts.
- Document/emit the expected sub-invocation shape so clients can reject simulated trees containing unexpected children.

### Proof of Concept
See `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`:

1. Attacker deploys `RogueHopPool` with plan `(victim=alice, wallet_token, to=attacker, amount=WALLET_BALANCE)` [8](#0-7) .
2. Route bytes name the rogue pool; `swap_collateral` executes it inside Alice's call [9](#0-8) .
3. Simulation records `transfer(alice → attacker)` as a child of Alice's `swap_collateral` entry; her wallet balance goes to 0 while she still receives the fair 2.5 ETH swap output [10](#0-9) .
4. In enforcing mode the same theft succeeds iff the signed tree lists the rogue transfer — i.e., iff the victim signs the simulation-produced tree [6](#0-5) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
