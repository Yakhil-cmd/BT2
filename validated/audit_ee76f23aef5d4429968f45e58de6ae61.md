### Title
Shared `handleAATriggers` serial queue can be stalled by a single crafted AA trigger, freezing execution for every other user's queued triggers - (File: aa_composer.js)

### Summary
`handleAATriggers` in `aa_composer.js` pulls **every pending AA trigger from every unit and every address** into one ordered array and processes them with `async.eachSeries`, exactly the "loop over independent user-submitted entries" pattern that broke `mintRollovers` in the Y2K report. In that report, one attacker-controlled ERC1155 receiver reverted inside `_mintShares`, and because minting happened inside a `for` loop, the revert aborted the whole batch, blocking every other legitimate user queued in the same call. The Obyte analog is the global `aa_triggers` queue: any address (unprivileged) can post a payment unit to any AA and get inserted into this queue, and the queue is drained strictly in series for the whole node, not per-address.

### Finding Description
`handleAATriggers` builds the full set of pending triggers with one query and iterates them serially: [1](#0-0) 

Each row's callback (`handlePrimaryAATrigger`) must call `cb()` for `async.eachSeries` to move on to the next, unrelated trigger: [2](#0-1) 

`handlePrimaryAATrigger` chains through `handleTrigger`, `evaluateAA`, `sendUnit`, `executeStateUpdateFormula`, DB writes, and a batch write, calling `onDone()`/`cb()` only along the success/`bounce` paths: [3](#0-2) 

Deep inside this chain, exceptions are thrown directly rather than routed through `cb`/`bounce` in several places I could confirm, e.g. `handleSecondaryTriggers` throws `Error("secondary triggers while bouncing")`, and `handlePrimaryAATrigger` itself throws on `!objUnitProps`: [4](#0-3) [5](#0-4) 

If any of these (or an equivalent unhandled exception reachable through AA formula evaluation for a specially-crafted `trigger.data`/definition combination) throws instead of invoking `cb`, the surrounding `async.eachSeries` in `handleAATriggers` never advances: the callback for the current row is never invoked, so no subsequent row — i.e., no other address's queued AA trigger anywhere in the network — is ever processed. Because the `mutex.lock(['aa_triggers'], …)` is only released inside the final callback of `async.eachSeries`, the lock itself is also never released, permanently blocking `handleAATriggers` from running again even on retry/restart-independent event triggers.

This is structurally identical to `mintRollovers`: a loop draining a shared, multi-tenant queue where a single malformed/malicious entry aborts processing for every other, unrelated entry in the same batch.

### Impact Explanation
If reachable, this freezes AA-trigger execution network-wide: no AA anywhere can produce a response for any user until the node is manually restarted (and the poisoned trigger would be re-queried and would stall it again on restart, since the `aa_triggers` row is only deleted after successful processing). This matches "AA fund loss or freezing" and "a network unable to confirm/execute new units" from the validation criteria — funds sent to any AA by any user become stuck (no response, no bounce, no refund) until node operators can intervene, which is an availability/consensus-relevant impact well above informational.

### Likelihood Explanation
Likelihood is uncertain without being able to fully trace the formula evaluator (`formula/evaluation.js`) and every catch site along `handleTrigger`'s many nested callbacks, so I cannot construct a concrete unhandled-throw case from the available index. The pattern (unhandled `throw` mixed with an `async.eachSeries`/`cb`-based control flow across ~1800 lines of deeply nested callbacks) is inherently fragile: any single spot where an exception is thrown instead of being funneled to `bounce`/`cb` turns a per-trigger failure into a global processing halt. Given the code explicitly throws in multiple places already found (`handlePrimaryAATrigger`, `handleSecondaryTriggers`), it is plausible that at least one is reachable by adversarial trigger content (e.g., malformed AA state, edge-case in `executeStateUpdateFormula`, or a race causing `storage.assocStableUnits[unit]` to be missing).

### Recommendation
- Wrap the per-row body of `handleAATriggers`'s `async.eachSeries` iterator in a `try/catch` (and ensure every async continuation reachable from `handlePrimaryAATrigger` also catches synchronous throws) so an exception for one trigger results in `cb(err)`/skip-and-log rather than aborting the whole series.
- Ensure `mutex.lock(['aa_triggers'], …)`'s `unlock()` is called from a `finally`-equivalent path so a stuck trigger cannot also permanently withhold the lock.
- Convert the internal `throw Error(...)` calls in `aa_composer.js` (e.g. `handlePrimaryAATrigger`'s missing-`objUnitProps` check, `handleSecondaryTriggers`'s "secondary triggers while bouncing") into controlled `bounce`/`cb(err)` paths, or at minimum isolate each trigger's processing so a defect in one AA cannot block others.

### Proof of Concept
Not fully constructible from the available index: I was unable to confirm a concrete, externally-triggerable path inside `formula/evaluation.js` or the deeper `handleTrigger` callbacks that produces an uncaught synchronous throw. This is a structural/DoS-pattern analog based on confirmed code — `handleAATriggers`'s single serial loop over ALL pending triggers [1](#0-0)  combined with confirmed unhandled `throw` statements inside the per-trigger call chain [4](#0-3) [5](#0-4)  — rather than a demonstrated end-to-end exploit. A background Devin session with full repo/test access (including `formula/evaluation.js` and all nested callbacks) would be needed to confirm whether user-controlled trigger content can actually reach one of these unhandled throws.

function handleAATriggers(onDone) {
	if (!onDone)
		return new Promise(resolve => handleAATriggers(resolve));
	mutex.lock(['aa_triggers'], function (unlock) {
		db.query(
			"SELECT aa_triggers.mci, aa_triggers.unit, address, definition \n\
			FROM aa_triggers \n\
			CROSS JOIN units USING(unit) \n\
			CROSS JOIN aa_addresses USING(address) \n\
			ORDER BY aa_triggers.mci, level, aa_triggers.unit, address",
			function (rows) {
				var arrPostedUnits = [];
				async.eachSeries(
					rows,
					function (row, cb) {
						console.log('handleAATriggers', row.unit, row.mci, row.address);
						var arrDefinition = JSON.parse(row.definition);
						handlePrimaryAATrigger(row.mci, row.unit, row.address, arrDefinition, arrPostedUnits, cb);
					},
					function () {
						arrPostedUnits.forEach(function (objUnit) {
							eventBus.emit('new_aa_unit', objUnit);
						});
						unlock();
						onDone();
					}
				);
			}
		);
	});

function handlePrimaryAATrigger(mci, unit, address, arrDefinition, arrPostedUnits, onDone) {
	db.takeConnectionFromPool(function (conn) {
		conn.query("BEGIN", function () {
			var batch = kvstore.batch();
			readMcUnit(conn, mci, function (objMcUnit) {
				readUnit(conn, unit, function (objUnit) {
					var arrResponses = [];
					var trigger = getTrigger(objUnit, address);
					trigger.initial_address = trigger.address;
					trigger.initial_unit = trigger.unit;
					handleTrigger(conn, batch, trigger, {}, {}, arrDefinition, address, mci, objMcUnit, false, arrResponses, function(){
						conn.query("DELETE FROM aa_triggers WHERE mci=? AND unit=? AND address=?", [mci, unit, address], async function(){
							await conn.query("UPDATE units SET count_aa_responses=IFNULL(count_aa_responses, 0)+? WHERE unit=?", [arrResponses.length, unit]);
							let objUnitProps = storage.assocStableUnits[unit];
							if (!objUnitProps)
								throw Error(`handlePrimaryAATrigger: unit ${unit} not found in cache`);
							if (!objUnitProps.count_aa_responses)
								objUnitProps.count_aa_responses = 0;
							objUnitProps.count_aa_responses += arrResponses.length;
							var batch_start_time = Date.now();
							batch.write({ sync: true }, function(err){
								console.log("AA batch write took "+(Date.now()-batch_start_time)+'ms');
								if (err)
									throw Error("AA composer: batch write failed: "+err);
								conn.query("COMMIT", function () {
									conn.release();
									if (arrResponses.length > 1) {
										// copy updatedStateVars to all responses
										if (arrResponses[0].updatedStateVars)
											for (var i = 1; i < arrResponses.length; i++)
												arrResponses[i].updatedStateVars = arrResponses[0].updatedStateVars;
										// merge all changes of balances if the same AA was called more than once
										let assocBalances = {};
										for (let { aa_address, balances } of arrResponses)
											assocBalances[aa_address] = balances; // overwrite if repeated
										for (let r of arrResponses) {
											r.balances = assocBalances[r.aa_address];
											r.allBalances = assocBalances;
										}
									}
									else
										arrResponses[0].allBalances = { [address]: arrResponses[0].balances };
									arrResponses.forEach(function (objAAResponse) {
										if (objAAResponse.objResponseUnit)
											arrPostedUnits.push(objAAResponse.objResponseUnit);
										eventBus.emit('aa_response', objAAResponse);
										eventBus.emit('aa_response_to_unit-'+objAAResponse.trigger_unit, objAAResponse);
										eventBus.emit('aa_response_to_address-'+objAAResponse.trigger_address, objAAResponse);
										eventBus.emit('aa_response_from_aa-'+objAAResponse.aa_address, objAAResponse);
									});
									onDone();
								});
							});
						});
					});
				});
			});
		});
	});
}
