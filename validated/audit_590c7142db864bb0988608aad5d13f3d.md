### Title
Unauthenticated disclosure of private stack merge/build status via `MergeStatusController#check` - (File: `app/controllers/shipit/merge_status_controller.rb`)

### Summary
`MergeStatusController` skips the engine's mandatory GitHub-team authentication for the `check` and `show` actions [1](#0-0) . The `show` action compensates for this by manually re-checking `current_user.logged_in?` before rendering any stack data [2](#0-1) , but the `check` action has no equivalent guard and unconditionally renders the resolved stack's merge/build status to anyone, authenticated or not [3](#0-2) .

### Finding Description
The binding this breaks is: "authentication required by the engine's `Authentication` concern" versus "the actual gate enforced before returning stack state." `Shipit::Authentication#force_github_authentication` is the engine-wide guard requiring a logged-in, team-authorized user for every controller action [4](#0-3) . `MergeStatusController` explicitly opts both `check` and `show` out of this guard via `skip_authentication only: %i[check show]` [1](#0-0) .

`show` re-establishes the equality by manually checking `current_user.logged_in?` and rendering a `logged_out` template instead of any stack data when it's false [5](#0-4) . `check`, however, calls `stack_status` (which resolves `stack.merge_status(...)`) and renders it directly to the response, with no `current_user` check at all [3](#0-2) [6](#0-5) .

The `stack` resolution method accepts a direct `stack_id` param (in `owner/repo/environment` form, matched by the route's `stack_id_format` regex) and, when absent, resolves the stack from a `referrer` URL against **all** stacks in the database, not scoped to any authorization [7](#0-6) . This route is publicly mounted with no engine-level access control at `/merge_status` [8](#0-7) .

### Impact Explanation
This matches the accepted High-impact category of "unauthenticated read of stack state, task streams or deploy output." An unauthenticated network attacker who can guess or discover a stack's `owner/repo/environment` identifier (or supply a `referrer` matching a tracked repository's public pull request URL) can query `check` and learn whether that stack's build/merge status is passing or failing, without being a member of any `Shipit.github_teams` and without any session, API token, or GitHub credential.

### Likelihood Explanation
No credentials, tokens, or privileged access are required — only a GET request to `/merge_status/check` with a `stack_id` or `referrer`/`branch` param. This is directly reachable by any unauthenticated party who can reach the Shipit host.

### Recommendation
Add the same `current_user.logged_in?` (and ideally `current_user.authorized?`) gate to `check` that `show` already enforces, so that skipping `force_github_authentication` for this action does not silently remove all access control on the underlying stack-status data.

### Proof of Concept
1. Identify or guess a stack id in the `owner/repo/environment` form used elsewhere in Shipit (e.g., `myorg/myrepo/production`), or use a `referrer` param pointing to a known GitHub PR of a tracked repository.
2. As an anonymous, unauthenticated client, request:
   `GET /merge_status/check?stack_id=myorg/myrepo/production`
   or
   `GET /merge_status/check?referrer=https://github.com/myorg/myrepo/pull/1&branch=main`
3. Observe the plain-text (`ok` / failure reason) or JSON (`{"stack_status": ...}`) response returned without any authentication, revealing the private stack's build/merge state — contrast this with `GET /merge_status?stack_id=...`, which correctly returns the `logged_out` view for the same anonymous request.

    included do
      before_action :force_github_authentication
      helper_method :current_user
    end

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
