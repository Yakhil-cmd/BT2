### Title
Route-nested third-party contracts can execute arbitrary token transfers from the caller's wallet under the user's signed authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The XOXNO Lending controller's swap entrypoints (`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`) invoke the configured router's `execute_strategy` under the caller's `require_auth` tree. Neither the controller nor the router enforces an allowlist on the pool/venue addresses embedded in the swap payload, so a route can place attacker-controlled contract code on the call stack. That code can invoke `token.transfer(caller, attacker, amount)` on any token; Soroban records it as a child invocation of the caller's auth entry, and once simulation returns that poisoned tree and the caller signs it, the host executes the transfer — draining wallet balances far beyond the routed amount. This is the on-chain analog of CVE-2020-14449: authorization (the user's signed auth subtree) is effectively disclosed to third-party servers (unvetted route venues).

### Finding Description
`swap_tokens` in `contracts/controller/src/strategies/swap.rs` grants exactly one authorization — `authorize_transfer_as_current(env, token_in, controller → router, amount_in)` — and measures only the controller's own input spend and output receipt (`RouterOverspend`, `NoSwapOutput` checks) [1](#0-0) . These checks bound the controller's grant only. The router resolves venue/pool addresses from the user-supplied `swap` payload and calls them with no venue allowlist; venue pulls are self-authorized by the router via `authorize_as_current_contract`, so they never appear as extra constraints in the sender's tree.

The harness test `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` proves the mechanism end-to-end: a `RogueHopPool` named in the route calls `token.transfer(alice, attacker, WALLET_BALANCE)` on an unrelated wallet token; simulation records that transfer as a child of Alice's `swap_collateral` auth entry [2](#0-1) , and in enforcing mode the signed "poisoned" tree executes the theft while an honest tree is rejected [3](#0-2) . The threat model acknowledges the exposure: "the loss is then the caller's wallet, not the routed amount, and neither the payload minimum nor the final risk gate bounds it" [4](#0-3) .

### Impact Explanation
Theft of user funds. Any token (including unlisted tokens the protocol never touches) held in the calling user's wallet can be transferred to an attacker address inside a single `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply` call, once the user signs the simulated auth tree. The loss is unbounded by `amount_in`, the payload min-out, or the controller's risk gates — it is limited only by the victim's wallet balance.

### Likelihood Explanation
Exploitation requires a victim to sign a route crafted by an attacker (e.g., distributed via a malicious or compromised route-quoting frontend), which is the standard delivery mechanism for this bug class — the user believes they are authorizing a swap while the simulated tree silently includes the rogue child transfer. The reachable-code prerequisite is fully satisfied on-chain: unprivileged callers may supply arbitrary `StrategySwap` payloads and arbitrary venue addresses. Residual factors (user inspecting the auth tree, honest simulators flagging non-root children) reduce but do not eliminate likelihood.

### Recommendation
Enforce a venue allowlist at the router for pool/pair addresses reachable from lending-strategy calls, or have the controller restrict `swap` payloads to a governance-curated venue registry so third-party code cannot sit beneath the user's auth. Independently, clients should decode and refuse any simulated auth tree containing child invocations beyond the single expected input transfer — but protocol-side venue allowlisting is the robust fix since it removes the attack surface entirely.

### Proof of Concept
1. Attacker deploys `RogueHopPool` configured with `(victim=Alice, wallet_token, to=attacker, amount=Alice's full balance)` — see `RogueHopPool::swap` [5](#0-4) .
2. Attacker serves Alice a `swap_collateral` route whose hop pool is the rogue contract but which otherwise pays a fair output, so the swap itself looks legitimate.
3. `simulateTransaction` runs recording mode and returns an auth tree where `token.transfer(Alice, attacker, WALLET_BALANCE)` is a child of Alice's `swap_collateral` entry; Alice signs it.
4. Enforcement accepts the tree: Alice's wallet token balance goes to 0, the attacker receives `WALLET_BALANCE`, and the swap still settles normally (`assert_eq!(s.wallet(&s.alice), 0)` at line 267-268).

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
}

That bound covers the controller's own grant only. The router calls the pool
and token addresses its payload names and keeps no allowlist of them, so a
route can put third-party code on the call stack below the caller's
authorization. A token transfer that such code makes from the caller is
recorded by an honest simulation as a child of the caller's authorization
entry, and it executes if the caller signs that tree. The loss is then the
caller's wallet, not the routed amount, and neither the payload minimum nor the
final risk gate bounds it. An honest swap strategy gives the caller no child
entry, and a direct router swap gives exactly one input transfer. A client must
decode the route it signs and refuse an authorization tree with any other
child. The direct `execute_strategy` path has the same exposure for every swap
user.
