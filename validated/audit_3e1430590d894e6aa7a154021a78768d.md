## Analog Found

### Title
Stop-Hook Security Review Bypass via mtime Equality Grief on Untracked Files - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
The Stop hook decides whether to review an untracked file by comparing its **current mtime** to the mtime captured at `UserPromptSubmit` using strict equality (`==`). Just as the DebtorNFT report showed a strict `balanceOf() == debtAmount` check can be griefed by an attacker who controls the compared value, this codebase relies on a strict `st_mtime_ns == base_mtime` check on a value the same actor (the agent/model) fully controls via the Bash tool. An attacker profile explicitly recognized by this repo's own threat model — "the model is the attacker, the user is the victim" for LLM-agent capability gates — can modify a pre-existing untracked file's content and then reset its mtime to the exact baseline value, causing the equality check to hold and the file to be silently excluded from the Stop hook's LLM security review.

### Finding Description
`_list_untracked` snapshots untracked files as `{path: mtime_ns}` at `UserPromptSubmit` time: [1](#0-0) 

`compute_v2_review_set` later decides which untracked files to exclude from review using a strict equality comparison against that snapshot: [2](#0-1) 

If `_unchanged_since_baseline(p)` returns `True`, the file is placed in `preexisting_unchanged` and removed from `new_untracked`, so it never enters `dirty_now` / `review_set`. This mirrors the `_validateLoan` pattern in the external report — a downstream security gate keyed off a strict equality on a value that the same principal exploiting the check can also write.

The comparison operand, `os.stat(...).st_mtime_ns`, is trivially attacker-writable: any Bash tool invocation such as `touch -d`/`os.utime()` lets the agent restore a file's mtime to an arbitrary prior value after editing its contents. This is the exact same class of bug as sending "the minimum amount of debt token directly to the vault" to defeat a strict equality check — here the attacker (the model/agent) engineers the compared quantity so the equality *succeeds* instead of fails, but the root cause is identical: a security decision keyed on a mutable, attacker-controllable value compared with exact equality instead of a robust invariant (e.g., content hash).

### Impact Explanation
This allows a compromised or prompt-injected agent turn to modify the content of any pre-existing untracked file and evade the Stop hook's `analyze_code_security` LLM review entirely for that file, by appending a trailing `touch -d`/mtime-reset command to its Bash sequence. Since the Stop hook (and its `sys.exit(2)`-forced continue-and-fix loop) is the plugin's last line of defense for surfacing vulnerabilities introduced during a session, this lets injected vulnerable/malicious code slip past the security-guidance plugin undetected and be presented to the user as reviewed/clean, per the repo's own threat model in `plugins/security-guidance/hooks/llm.py` which explicitly treats hook/hook-bypass scenarios where "the model is the attacker, the user is the victim" as in-scope and never subject to the no-privilege-boundary exclusion. [3](#0-2) 

### Likelihood Explanation
Requires only Bash tool access already available to any Claude Code session and a pre-existing untracked file in the working tree (a common state for scratch files, generated artifacts, or files created earlier in the conversation) — no privileged access, and the operation (`touch`/`os.utime`) is an ordinary filesystem primitive, not flagged by any command classifier in this plugin.

### Recommendation
Do not rely on mtime equality to detect "unchanged" untracked files. Replace with a content hash (e.g., `git hash-object`) comparison, or simply always include untracked files that are dirty at Stop-hook time, deduping by content hash against the baseline hash instead of mtime.

### Proof of Concept
1. Turn starts; `UserPromptSubmit` captures `untracked_at_baseline = {"scratch.py": T0}` via `_list_untracked` (`diffstate.py:319-348`).
2. Agent edits `scratch.py`, injecting a command-injection/eval sink.
3. Agent runs `touch -d @<T0_in_seconds> scratch.py` (or `os.utime(path, ns=(T0, T0))`) via the Bash tool to restore the original mtime.
4. Stop hook calls `compute_v2_review_set`; `_unchanged_since_baseline("scratch.py")` reads the new stat, finds `st_mtime_ns == T0`, returns `True` (`diffstate.py:390-397`).
5. `scratch.py` is added to `preexisting_unchanged` and excluded from `new_untracked`/`dirty_now`/`review_set` (`diffstate.py:399-401`), so `analyze_code_security` never sees the injected vulnerability, and no `sys.exit(2)` guidance is emitted for it.

def _list_untracked(cwd):
    """Repo-root-relative untracked (and not-ignored) path → mtime_ns, or {}
    on error. Used at UPS to snapshot the pre-turn untracked set so the Stop
    hook can exclude unchanged pre-existing untracked files from review.
    mtime is captured so an in-place edit during the turn is still reviewed.

    Uses ls-files (not status) for the UPS path: the index diff isn't needed,
    and ls-files --others only walks the worktree against .gitignore."""
    try:
        repo = _git_toplevel(cwd) or cwd
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "ls-files",
             "--others", "--exclude-standard", "-z"],
            cwd=repo, capture_output=True, text=True, timeout=15,
        )
        if r.returncode != 0:
            debug_log(f"_list_untracked rc={r.returncode}: {r.stderr[:200]}")
            return {}
        out = {}
        for p in r.stdout.split("\0"):
            if not p:
                continue
            try:
                out[p] = os.stat(os.path.join(repo, p)).st_mtime_ns
            except OSError:
                out[p] = 0
            if len(out) >= UNTRACKED_BASELINE_CAP:
                debug_log(f"_list_untracked: capped at {UNTRACKED_BASELINE_CAP}")
                break
        return out
