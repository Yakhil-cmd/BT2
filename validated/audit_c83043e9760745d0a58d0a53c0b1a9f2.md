## Title
CCMenu API token stack-scope bypass allows reading arbitrary stacks' build status - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Api::CCMenuController` re-implements stack lookup with an unscoped query, breaking the binding between "the stack an `ApiClient` token is authorized for" and "the stack the endpoint actually operates on." Any valid CCMenu token — including one an admin deliberately scoped to a single stack — can be replayed with a different `stack_id` to read another stack's build/deploy status.

### Finding Description
`Shipit::Api::BaseController` implements token-scoping via `stacks`/`stack`: [1](#0-0) 

`stacks` restricts the visible set to `current_api_client.stack_id` when the token was created scoped to a specific stack, and `stack` resolves the requested record through that scoped relation (`stacks.from_param!`). This is the mechanism that is supposed to guarantee: `token.authorized_stack == stack_touched_by_request`.

`Api::CCMenuController`, however, overrides `stack` to bypass this relation entirely: [2](#0-1) 

`Stack.from_param!(params[:stack_id])` queries the unscoped `Stack` model directly, ignoring `current_api_client.stack_id`. `require_permission :read, :stack` only checks that the token carries the `read:stack` permission string via `ApiClient#check_permissions!`: [3](#0-2) 

— it never checks *which* stack the permission applies to. As a result the equality the system relies on breaks:
`token authorizes stack A` ≠ `stack actually touched by the request (any stack B chosen by the caller)`.

Tokens minted specifically for this narrow use case are stack-scoped by design, e.g. the fixture used by the very tests for this controller: [4](#0-3) 

and the production helper that mints CCMenu tokens embeds a `stack_id` in the generated URL expecting the token to be tied to that stack: [5](#0-4) 

Because `CCMenuController#stack` does not consult `current_api_client.stack_id`, a caller holding any such token can substitute an arbitrary `stack_id` and receive that other stack's `name`, `activity`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, and `webUrl`: [6](#0-5) 

### Impact Explanation
This crosses the "stack a token authorizes versus stack it touches" trust boundary called out for this bug class. A token that was distributed for CCMenu integration with one stack (frequently embedded in a widget URL, CI dashboard, or third-party badge and therefore exposed with lower operational secrecy than an admin `ApiClient` token) can be reused to disclose build/deploy status of every other stack in the Shipit instance — an unauthorized cross-stack read of stack state.

### Likelihood Explanation
Exploitation only requires possession of any valid, unrevoked CCMenu token (`?token=...` query string, as demonstrated by the "can authenticate with query string token" test) plus knowledge/guessing of another stack's `to_param` (its repo/environment slug, which is often predictable or discoverable). No additional secrets, sessions, or GitHub access are required beyond the token itself, which the feature is designed to hand out to lower-trust consumers (CI badges).

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the scoped `stacks` relation like the rest of `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!`, so a stack-scoped token can only ever resolve the stack it was authorized for.

### Proof of Concept
1. Admin generates a CCMenu URL for `stack-A` via `CCMenuUrlController#fetch`, producing a token whose `ApiClient#stack_id == stack-A.id` and permission `read:stack` only.
2. Attacker (or the widget consumer who now holds that token) sends:
   `GET /api/stacks/stack-B/ccmenu.xml?token=<stack-A-token>`
3. `CCMenuController#stack` calls `Stack.from_param!('stack-B')` unscoped, `require_permission :read, :stack` passes because the token has `read:stack`, and the response renders `stack-B`'s `lastBuildStatus`, `lastBuildLabel`, `webUrl`, etc. — data the token was never authorized to see.

```ruby
require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
```
