### Title
`fillAllocated()` silently swallows `GetAllocatedCount` error, causing all zeroed KAIA to be burnt without allocation — (File: `blockchain/system/rebalance.go`)

---

### Summary

In `blockchain/system/rebalance.go`, the `fillAllocated` function returns `nil` instead of propagating the error when `GetAllocatedCount` fails. This leaves `result.After.Allocated` empty, and `RebalanceTreasury` proceeds to zero all treasury addresses while distributing nothing — permanently burning all zeroed KAIA with no allocation to recipients.

---

### Finding Description

`fillAllocated` is responsible for populating the allocation map (`result.After.Allocated`) before the treasury rebalance executes. Its counterpart `fillZeroed` correctly propagates errors:

```go
// fillZeroed — correct
if err != nil {
    logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
    return err   // ← propagates error
}
```

But `fillAllocated` silently swallows the error on the very first call:

```go
// fillAllocated — BUG
numNewbieBigInt, err := contract.GetAllocatedCount(nil)
if err != nil {
    logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
    return nil   // ← returns nil instead of err
}
``` [1](#0-0) 

When `GetAllocatedCount` fails, `result.After.Allocated` remains an empty map. `RebalanceTreasury` receives `nil` from `fillAllocated` and continues: [2](#0-1) 

**Validation 4** does not catch this because `totalAllocatedAmount` = 0 and the guard is `totalZeroedAmount < totalAllocatedAmount` (i.e., `X < 0`), which is always false: [3](#0-2) 

Execution then proceeds in two steps:

1. **Execution 1** — all zeroed addresses are set to balance 0 (KAIA removed from state): [4](#0-3) 

2. **Execution 2** — iterates over the empty `result.After.Allocated` map, distributing nothing: [5](#0-4) 

`RebalanceTreasury` returns `(result, nil)` — success — so the caller in `kaiax/system/impl/blockstate.go` commits the state: [6](#0-5) 

The comment "State not changed" in the error branch is misleading — there is no state revert even in the error path, but in this bug the function returns success, so all zeroed balances are permanently wiped with zero allocation.

---

### Impact Explanation

All KAIA held by the registered zeroed addresses is permanently burnt. No KAIA is distributed to the allocated (recipient) addresses. The total supply is reduced by the full zeroed amount with no corresponding allocation. This is an unauthorized, irreversible burn of system-managed KAIA funds at the KIP-103 or KIP-160 hard-fork block.

---

### Likelihood Explanation

The trigger requires `GetAllocatedCount` to fail during block processing at the exact fork block. This can occur if the contract at `Kip160ContractAddress` / `Kip103ContractAddress` is not deployed, is misconfigured, or reverts on `getAllocatedCount`. While this requires a configuration-level precondition, the code defect itself is unconditional — the asymmetry between `fillZeroed` (returns `err`) and `fillAllocated` (returns `nil`) is a latent bug that fires silently whenever the contract call fails, with no safety net.

---

### Recommendation

Change line 219 from `return nil` to `return err`:

```go
func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {
    numNewbieBigInt, err := contract.GetAllocatedCount(nil)
    if err != nil {
        logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
        return err  // ← fix: propagate error, matching fillZeroed behavior
    }
    ...
}
``` [7](#0-6)

### Proof of Concept

1. Configure a chain with `Kip160CompatibleBlock = N` and `Kip160ContractAddress = addr`.
2. At block `N`, deploy a `TreasuryRebalanceV2`-compatible contract at `addr` where `getAllocatedCount()` reverts (or point `addr` to an undeployed address).
3. Register zeroed addresses with non-zero KAIA balances in the contract; set status to `Approved`.
4. At block `N`, `FinalizeState` calls `RebalanceTreasury`.
5. `fillAllocated` calls `GetAllocatedCount`, which fails; returns `nil`.
6. `result.After.Allocated` is empty; `totalAllocatedAmount` = 0.
7. Validation 4 passes (`totalZeroedAmount < 0` is false).
8. All zeroed addresses are set to balance 0.
9. No allocations are made.
10. `RebalanceTreasury` returns success; state is committed.
11. All KAIA from zeroed addresses is permanently burnt with no recipients. [8](#0-7) [9](#0-8)

func (result *rebalanceResult) fillZeroed(contract RebalanceCaller, state *state.StateDB) error {
	numRetiredBigInt, err := contract.GetZeroedCount(nil)
	if err != nil {
		logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
		return err
	}

	for i := 0; i < int(numRetiredBigInt.Int64()); i++ {
		ret, err := contract.Zeroeds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Zeroeds from TreasuryRebalance contract", "err", err)
			return err
		}
		result.Before.Zeroed[ret] = state.GetBalance(ret)
		result.After.Zeroed[ret] = state.GetBalance(ret) // will be set as zero if rebalance succeeds
	}
	return nil
}

func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {
	numNewbieBigInt, err := contract.GetAllocatedCount(nil)
	if err != nil {
		logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
		return nil
	}

	for i := 0; i < int(numNewbieBigInt.Int64()); i++ {
		ret, err := contract.Allocateds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Allocateds from TreasuryRebalance contract", "err", err)
			return err
		}

		result.Before.Allocated[ret.Addr] = state.GetBalance(ret.Addr)
		result.After.Allocated[ret.Addr] = ret.Amount
	}
	return nil
}
