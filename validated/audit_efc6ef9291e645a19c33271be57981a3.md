### Title
Symlink-following arbitrary file read via `load_rules()`/`load_rule_file()` in hookify config loader - ([File: plugins/hookify/core/config_loader.py])

### Summary
`load_rules()` globs `.claude/hookify.*.local.md` and passes any matched path directly to `load_rule_file()`, which calls `open(file_path, 'r').read()` with no symlink check or workspace-boundary validation. A repository-checked-in symlink named to match this glob (e.g. `.claude/hookify.evil.local.md -> ~/.aws/credentials`) will be transparently dereferenced by Python's `open()`, causing the hook to read a file outside the repository on every Bash/Edit/Write tool invocation.

### Finding Description
`load_rules()` builds the glob pattern with `os.path.join('.claude', 'hookify.*.local.md')` and calls `glob.glob(pattern)` [1](#0-0) . `glob.glob` matches filenames without regard to whether they are symlinks, and neither `load_rules()` nor `load_rule_file()` calls `os.path.islink()`, `os.path.realpath()`, or performs any check that the resolved path stays under the `.claude` directory / repo root before opening it [2](#0-1) . `open(file_path, 'r')` in CPython follows symlinks by default (no `O_NOFOLLOW`), so a symlink checked into the repo pointing to an absolute path outside the workspace (e.g. `~/.aws/credentials`, a sibling project's `.env`) is fully read into `content` regardless of the target's location. This code path is invoked automatically and unconditionally on every tool call, since `pretooluse.py` (and the equivalent posttooluse/stop/userpromptsubmit hooks) call `load_rules()` on every `PreToolUse` event without any user confirmation [3](#0-2) . If the target's content happens to start with `---` and parses as YAML frontmatter (as required by `extract_frontmatter`), the parsed message body is stored as `rule.message` and, if the rule is enabled and matches, is emitted verbatim in the `systemMessage` field returned to the user by `RuleEngine.evaluate_rules()` [4](#0-3) . Even when the target does not parse as frontmatter, the file has still been opened and read into process memory, and partial content/paths can surface via the exception-driven warning/error branches (`Warning: {file_path} missing YAML frontmatter...`, `Error: Malformed rule file...`) printed by `load_rule_file()` [5](#0-4) . No allowlist, workspace guard, or symlink check exists anywhere in this module to prevent this.

### Impact Explanation
This is an unauthorized file read outside the intended workspace boundary, triggered purely by repository content (a checked-in symlink) with no user interaction beyond normal tool usage that Claude Code performs automatically before/after every Bash/Edit/Write call. In the worst case (target file happens to have frontmatter-like content), the content is reflected directly to the user via `systemMessage`, constituting secret disclosure. Even without frontmatter, this establishes an exploitable workspace-escape primitive: arbitrary local file read gated only by matching a filename glob, which violates the stated invariant that repo-triggered reads must not escape the approved workspace.

### Likelihood Explanation
Precondition matches the stated threat model: an attacker can check in a plugin/rule file (or, here, a symlink shaped like one) into a repository that a victim later clones and opens with Claude Code/hookify enabled. No special privileges are required beyond normal repo contribution/cloning, and the vulnerable path executes automatically and repeatedly (every tool call triggers `load_rules()`), making it highly reliable and repeatable once the victim opens the malicious repo.

### Recommendation
In `load_rule_file()` (and/or `load_rules()`), reject any `file_path` that is a symlink via `os.path.islink(file_path)`, or resolve with `os.path.realpath(file_path)` and verify the resolved path is still contained within the repository's `.claude` directory before calling `open()`. Alternatively, open with `os.open(file_path, os.O_RDONLY | os.O_NOFOLLOW)` to refuse to follow symlinks at the OS level, treating any symlink match as an invalid/ignored rule file with a clear warning logged.

### Proof of Concept
Unit test in `plugins/hookify/core/` test suite:
1. Create a temp workspace directory with `.claude/` subdirectory.
2. Create a sensitive "external" file outside the workspace, e.g. `/tmp/outside/secret.md`, containing `---\nname: leak\nenabled: true\nevent: all\npattern: ".*"\n---\nSECRET-DATA-1234`.
3. Inside `.claude/`, create a symlink `hookify.evil.local.md` pointing to `/tmp/outside/secret.md`.
4. `chdir` into the temp workspace and call `load_rules()`.
5. Assert that either: (a) `load_rules()` returns no rule derived from the symlinked file (i.e., the symlink is skipped/rejected), or (b) if a rule is returned, its `message` does not equal/contain `"SECRET-DATA-1234"`.
6. Additionally assert, via `os.open`/mock on `open`, that `open()` was never called with the resolved path `/tmp/outside/secret.md`.
Currently, this test fails: `load_rules()` returns a `Rule` with `message == "SECRET-DATA-1234"`, and running `RuleEngine.evaluate_rules()` on hook input causes `"SECRET-DATA-1234"` to appear in the returned `systemMessage`.

```python
def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
```
