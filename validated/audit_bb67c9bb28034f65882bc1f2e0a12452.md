### Title
Path traversal via unsanitized release asset name in `destinationWriter.makePath` allows arbitrary file write/overwrite outside `--dir` - ([File: pkg/cmd/release/download/download.go])

### Summary
`downloadRun` builds download targets directly from `release.Assets[].Name` (attacker-controlled, returned verbatim from the GitHub API's asset JSON for a release the attacker publishes) without any path sanitization, and passes that name through `downloadAsset` to `destinationWriter.Copy` → `makePath`, which does `filepath.Join(w.dir, name)` with no `filepath.Base` or containment check. An asset named e.g. `../../.git/hooks/pre-commit` will resolve outside `opts.Destination`.

### Finding Description
In `downloadRun` (pkg/cmd/release/download/download.go:196-207), asset names are taken directly from `a.Name` and stored as `downloadTarget.name`, with only reserved-filename checks on Windows (`isWindowsReservedFilename`) — no `..`/absolute-path filtering. [1](#0-0) 

This flows to `downloadAsset(dest, httpClient, a.url, a.name, isArchive)` and then `dest.Copy(fileName, resp.Body)`. [2](#0-1) [3](#0-2) 

`destinationWriter.makePath` joins `w.dir` (i.e., `opts.Destination`, from `--dir`) with the untrusted `name` via `filepath.Join`, without ever calling `filepath.Base` or otherwise confining the result to `w.dir`: [4](#0-3) 

Note that for the archive/Content-Disposition path, the code does apply `filepath.Base(serverFileName)` before use, showing sanitization is understood to be necessary there, but this same treatment is not applied to `a.Name` from the regular asset-list path: [5](#0-4) 

`Copy` then calls `os.MkdirAll(filepath.Dir(fp), 0755)` and `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` on the joined path with no re-validation against `w.dir`: [6](#0-5) 

`Check`/`check` (existence/overwrite guard) similarly operate on the already-joined, unconfined path and provide no traversal protection. [7](#0-6) 

Attack flow: victim runs `gh release download` (optionally with `-p`/`--pattern`, or no pattern against latest release) targeting an attacker-controlled repository/release. The attacker crafts a release asset whose `name` field is `../../.git/hooks/pre-commit` (or any relative traversal, since `filepath.Join` cleans `..` segments against `w.dir` but does not prevent escaping it — e.g. `../../../etc/passwd`-style paths, though absolute paths are neutralized by `Join` unlike `filepath.Base`, which fully strips traversal). GitHub's release API does not itself restrict asset `name` to a basename, so the JSON field is attacker-controlled at publish time.

### Impact Explanation
This is an arbitrary file write/overwrite primitive scoped to files reachable via a relative path traversal from `--dir`. Concrete scoped impact matches the described scenario: writing/overwriting a file such as `.git/hooks/pre-commit` in a repository directory used as the download destination, which upon the next `git commit` (or other hook-triggering git operation) in that directory would achieve code execution on the victim's machine. This corresponds to GitHub's bounty impact class for file write/overwrite outside intended path leading to potential code execution.

### Likelihood Explanation
Feasible and fully attacker-controlled: any GitHub user can create a public repository and publish a release with an asset whose `name` metadata contains `../` sequences (the asset filename shown via the GitHub UI/API is not required to be a bare filename). The victim only needs to run the ordinary command `gh release download` (with `--dir` pointing at, or defaulting to, a git working directory) against that attacker's repo/tag — a normal, expected usage pattern (e.g., downloading a release inside a cloned project directory). No additional privileges, tokens, or MITM needed.

### Recommendation
In `destinationWriter.makePath` (and/or immediately when constructing `downloadTarget.name` from `a.Name` in `downloadRun`), sanitize the asset name the same way the Content-Disposition path already does: apply `filepath.Base(name)` (or equivalently reject/strip any path separators and `..` components) before joining with `w.dir`. Additionally, after `filepath.Join(w.dir, name)`, verify the resulting cleaned path still has `w.dir` as a prefix (e.g., using `filepath.Abs` + `strings.HasPrefix` or an existing safepath-style helper) and reject the download if not, to defend against any bypasses of the basename normalization.

```go
func TestDownloadAsset_PathTraversalInAssetName(t *testing.T) {
    tempDir := t.TempDir()
    // pretend tempDir is a "repo" with a hooks dir
    hooksDir := filepath.Join(tempDir, ".git", "hooks")
    require.NoError(t, os.MkdirAll(hooksDir, 0755))

    reg := &httpmock.Registry{}
    reg.Register(
        httpmock.REST("GET", "attacker/release/asset-url"),
        httpmock.StringResponse("malicious content"),
    )
    httpClient := &http.Client{Transport: reg}

    dest := destinationWriter{dir: tempDir}
    target := downloadTarget{
        url:  safeurl.NewImmutableSafeURL("https://api.github.com/attacker/release/asset-url"),
        name: "../../.git/hooks/pre-commit", // attacker-controlled a.Name
    }

    err := downloadAsset(&dest, httpClient, target.url, target.name, false)
    require.NoError(t, err)

    // Expected (secure) behavior: file should NOT exist outside tempDir/... in hooks dir
    // unless it was requested; assert that writing landed inside `tempDir`, not escaping it.
    escaped := filepath.Join(hooksDir, "pre-commit")
    _, statErr := os.Stat(escaped)
    require.Error(t, statErr, "asset name traversal must not allow writing into .git/hooks outside destination confinement")
}
```
Expected result on the current code: the test fails (file is written to `hooksDir/pre-commit`), demonstrating the path confinement violation. After applying the recommended fix (basename + prefix check), the write should be rejected or redirected to `filepath.Join(tempDir, "pre-commit")`, and the assertion should pass.

```go
// Check returns an error if a file already exists at destination
func (w destinationWriter) Check(name string) error {
	if name == "" {
		// skip check as file name will only be known after the API request
		return nil
	}
	fp := w.makePath(name)
	if fp == "-" {
		// writing to stdout should always proceed
		return nil
	}
	return w.check(fp)
}

func (w destinationWriter) check(fp string) error {
	if _, err := os.Stat(fp); err == nil {
		if w.skipExisting {
			return errSkipped
		}
		if !w.overwrite {
			return fmt.Errorf(
				"%s already exists (use `--clobber` to overwrite file or `--skip-existing` to skip file)",
				fp,
			)
		}
	}
	return nil
}
```

```go
func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
```
