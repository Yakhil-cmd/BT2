### Title
Cross-tenant Team membership write via unauthenticated organization mismatch in `MembershipHandler#process` - (File: `app/models/shipit/webhooks/handlers/membership_handler.rb`)

### Summary
`MembershipHandler#process` looks up a `Team` solely by `github_id` and never re-validates that the organization which authenticated the webhook (`repository_owner`, resolved from `params.organization.login`) matches the `organization` column already stored on that `Team`. If an attacker controls (or is granted) a GitHub App installation for an organization that has no `webhook_secret` configured, they can forge a `membership` webhook naming any existing `github_id` and mutate a `Team` belonging to a completely different, secured organization.

### Finding Description
The binding that should hold is: `organization_that_verified_signature == Team#organization_being_mutated`, i.e. `Shipit.github(organization: repository_owner)`'s org (the one whose `webhook_secret` validated the request in `WebhooksController#verify_signature`, [1](#0-0)  and `repository_owner` [2](#0-1) ) must equal `team.organization` for the `Team` row that `add_member`/`members.delete` mutates.

In `MembershipHandler#process`, the team is resolved with `Team.find_or_create_by!(github_id: params.team.id)`, and the block that sets `team.organization = params.organization.login` only runs when the record does **not** already exist: [3](#0-2) . For a pre-existing `Team` (e.g. one created earlier via a legitimate `shopify` webhook, fixture `shopify_developers` team belonging to org `shopify`), the incoming `params.organization.login` is never compared to the stored `team.organization`; it is simply discarded. The handler then does `team.add_member(member)` for action `'added'`, appending an arbitrary attacker-chosen GitHub login (`params.member.login`, resolved via `User.find_or_create_by_login!`) as a member of that team [4](#0-3) .

`verify_signature` only proves that the request was signed (or, if `webhook_secret` is blank, does not require a signature at all — `verify_webhook_signature` returns `true` unless a secret is configured: [5](#0-4) ) for the GitHub App configured for `repository_owner`, i.e. `params.organization.login` in this membership payload. It never checks that this organization is the same one that owns the `Team.github_id` being targeted. Because `Team` lookup key is `github_id` (a GitHub-assigned integer, not org-scoped in the query), any org's webhook — including one with no `webhook_secret` set — can target and mutate a `Team` row tagged with a different `organization`.

Attacker request: a `POST /webhooks` with header `X-Github-Event: membership`, body `{"action":"added","team":{"id":<victim_team_github_id>,"name":...,"slug":...,"url":...},"organization":{"login":"attacker-org"},"member":{"login":"attacker-controlled-login"}}`, sent with a signature (or none) that only needs to satisfy `attacker-org`'s app config (which has no `webhook_secret`).

None of the existing guards prevent this: `drop_unhandled_event` only checks the event is registered; the `ExplicitParameters` schema in `MembershipHandler.params` only validates presence/type, not cross-field/tenant equality; `verify_signature` validates against the wrong scope (the attacker's own configured, secret-less org, not the victim team's org); no model validation on `Team`/`Membership` enforces organization consistency between `find_or_create_by!` lookups and payload origin.

### Impact Explanation
An attacker who registers/controls a GitHub organization configured in Shipit with no `webhook_secret` (a permitted, documented multi-org configuration state, see "Using Multiple Github Applications" in `docs/setup.md`) can add an arbitrary GitHub login as a member of any `Team` whose numeric `github_id` they know or guess, even though that team belongs to a fully secured organization such as `shopify`. This is a cross-tenant record write (`Membership` row created) not authenticated by the org that owns the target `Team`, matching the "Critical" impact category ("a payload for one repository/org mutating another's ... team"). Team membership in Shipit can gate deploy/stack authorization depending on how the host app uses `Team`/`github_teams`, so this can plausibly escalate into unauthorized authorization grants. It is fully repeatable against any team whose `github_id` is known, across arbitrary organizations.

### Likelihood Explanation
Preconditions: (1) the Shipit instance uses the multi-organization `github:` config schema (`github_default_organization` non-nil) with at least one org (`attacker-org`) that has `webhook_secret` unset — a state permitted by Shipit's own documented setup instructions, not a hypothetical misconfiguration outside the app's control surface; (2) the attacker needs to know the target `Team`'s GitHub numeric team ID, discoverable via GitHub's team API for teams the attacker can view, or via prior legitimate webhooks/log leakage. No Shipit session, API token or secret is required. Attacker cost is a single unauthenticated HTTP POST. This is fully repeatable and scriptable.

### Recommendation
In `MembershipHandler#find_or_create_team!` (and generally in `process`), always compare `params.organization.login` (downcased) against the persisted `team.organization` before performing any mutation, and reject (raise/ignore) the webhook if they differ — even for freshly-created teams, the org used to create/look up the team must equal the org that authenticated the request. Additionally, scope the `Team.find_or_create_by!` lookup by both `github_id` and `organization` (`find_or_create_by!(github_id: params.team.id, organization: params.organization.login)`), so a webhook from one organization can never resolve to a `Team` tagged with a different organization.

    team: { id: team.github_id, name: team.name, slug: team.slug, url: team.api_url },
    organization: { login: 'attacker-org' },
    member: { login: 'attacker-controlled-login' }

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

module Shipit
  class Team < Record
    REQUIRED_HOOKS = %i[membership].freeze

    has_many :memberships
    has_many :members, class_name: :User, through: :memberships, source: :user

    has_many :github_hooks,
             -> { where(event: REQUIRED_HOOKS) },
             foreign_key: :organization,
             primary_key: :organization,
             class_name: 'GithubHook::Organization',
             inverse_of: false

    class << self
      def find_or_create_by_handle(handle)
        organization, slug = handle.split('/').map(&:downcase)
        find_by(organization:, slug:) || fetch_and_create_from_github(organization, slug)
      end

      def fetch_and_create_from_github(organization, slug)
        return unless github_team = find_team_on_github(organization, slug)

        create!(github_team:, organization:)
      end

      def find_team_on_github(organization, slug)
        gh_api = Shipit.github(organization:).api
        teams = Shipit::OctokitIterator.new(github_api: gh_api) { gh_api.org_teams(organization, per_page: 100) }
        teams.find { |t| t.slug == slug }
      rescue Octokit::NotFound
      end
    end

    def handle
      "#{organization}/#{slug}"
    end

    def add_member(member)
      members.append(member) unless members.include?(member)
    end

    def refresh_members!
      github_api = Shipit.github(organization:).api
      github_members = Shipit::OctokitIterator.new(github_api.get(api_url).rels[:members])
      members = github_members.map { |u| User.find_or_create_from_github(u) }
      self.members = members
      save!
    end

    def github_team=(github_team)
      self.name = github_team.name
      self.slug = github_team.slug
      self.api_url = github_team.url
      self.github_id = github_team.id
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
