### Title
Webhook signature verification fails open (unauthenticated webhook accepted) when an organization has no `webhook_secret` configured - ([File: lib/shipit/github_app.rb], [File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever `webhook_secret` is blank/nil for the resolved organization, and `WebhooksController#verify_signature` selects that organization purely from attacker-controlled JSON (`repository.owner.login`). This lets anyone send an arbitrary, unsigned POST to `/webhooks` and have it processed as a legitimate GitHub event for any repository belonging to that organization.

### Finding Description
The broken invariant is: **"a webhook body was cryptographically verified with a secret belonging to the organization that owns the target repository"** should imply **"the request truly originated from GitHub for that organization/repository"**. In this codebase that equality collapses to a tautology when the org's config omits `webhook_secret`.

Path:
1. `WebhooksController#verify_signature` reads `repository_owner` straight from the untrusted JSON body (`params.dig('repository','owner','login')`) and calls `Shipit.github(organization: repository_owner)` [1](#0-0) [2](#0-1) .
2. `Shipit.github` builds a `GitHubApp` from `github_app_config(organization)`, which is whatever the operator configured for that org key — including possibly no `webhook_secret` at all [3](#0-2) .
3. `GitHubApp#verify_webhook_signature` short-circuits to `true` when `webhook_secret` is blank, before ever comparing the `X-Hub-Signature` header to anything [4](#0-3) .
4. `verify_signature` treats `verified == true` as pass and proceeds to `create`, which re-parses `request.raw_post` and dispatches to handlers such as `PushHandler`, which resolves the target `Stack` from `payload.dig('repository','full_name')` and can enqueue `GithubSyncJob`/trigger stack sync [5](#0-4) .

No other guard intervenes: `drop_unhandled_event` only filters by event type, not authenticity [6](#0-5) ; `GithubOrganizationUnknown` is only raised when the org key is entirely absent from config, not when it's present without a secret [7](#0-6) .

Attacker request: `POST /webhooks` with `X-Github-Event: push`, no `X-Hub-Signature` header (or a bogus one), and body `{"repository":{"owner":{"login":"X"},"full_name":"X/target-repo"}, "ref": "refs/heads/master", "after": "<sha>"}` where `X` is any organization present in `Shipit.github_apps`/credentials config but lacking `webhook_secret`.

### Impact Explanation
An unauthenticated attacker can forge any webhook event (push, status, check_suite, pull_request, membership, etc.) for every repository under an organization whose config entry lacks `webhook_secret`. For `push`, this causes `stack.sync_github`/`GithubSyncJob` to run for arbitrary attacker-chosen ref/sha, and other handlers (status, membership, pull_request labeling) can mutate commit statuses, team membership, or PR-driven records — all without any credential. This matches the Critical category: authentication bypass (forged webhook accepted) enabling unauthorized stack actions for a repository that never authenticated the request.

### Likelihood Explanation
Exploitability strictly depends on operator configuration: it requires at least one organization entry in the Shipit GitHub apps configuration that omits `webhook_secret` (fail-open by design in `GitHubApp#verify_webhook_signature`). Given that precondition, the attack costs nothing — no secret, no session, a single unauthenticated HTTP POST, fully repeatable against every repository under that org.

### Recommendation
Make `webhook_secret` mandatory: raise/reject (e.g., `head(422)` or raise a configuration error) when `webhook_secret` is blank instead of returning `true` in `GitHubApp#verify_webhook_signature`, or fail closed in `WebhooksController#verify_signature` when the resolved app has no secret configured.

### Proof of Concept
```ruby
test "webhook is accepted without any signature when org has no webhook_secret configured" do
  Shipit.stubs(:github_app_config).with('no-secret-org').returns({ app_id: 1, installation_id: 1 })
  # organization config present, but webhook_secret key absent -> verify_webhook_signature short-circuits true
  stack = shipit_stacks(:shipit) # repurpose fixture, full_name matches payload below

  request.headers['X-Github-Event'] = 'push'
  # no X-Hub-Signature header set at all
  payload = JSON.parse(payload(:push_master))
  payload['repository']['owner']['login'] = 'no-secret-org'
  payload['repository']['full_name'] = stack.repository.full_name

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: stack.id, expected_head_sha: payload['after']]) do
    post :create, body: payload.to_json, as: :json
  end
  assert_response :ok
end
```
This demonstrates the equality `verified == true` holds even though no `X-Hub-Signature` bytes were checked against any secret, confirming the bypass at [8](#0-7) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
