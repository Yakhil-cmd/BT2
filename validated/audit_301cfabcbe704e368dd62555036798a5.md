### Title
Path traversal in release asset `Name` allows directory creation and file writes outside `--dir` - (File: pkg/cmd/release/download/download.go)

### Summary
`destinationWriter.makePath` builds the destination path with `filepath.Join(w.dir, name)` using the attacker-controlled release asset `Name` field with no confinement check, so a crafted name containing `../` segments resolves (via `filepath.Join`'s implicit `Clean`) to a path outside `w.dir`. `Copy` then calls `os.MkdirAll(filepath.Dir(fp), 0755)` and writes the file at that escaped path, allowing an attacker who controls a release's asset metadata (or a malicious host `gh` is pointed at) to create directories and write files anywhere the victim's OS user has permission to write.

### Finding Description
In `downloadRun`, each `shared.ReleaseAsset.Name` from the fetched release JSON is used directly as `downloadTarget.name` [1](#0-0) . This flows into `downloadAsset` → `dest.Copy(fileName, resp.Body)` [2](#0-1) .

`destinationWriter.makePath` joins the attacker-supplied `name` with `w.dir` without any sanitization, `filepath.Base`, or containment check: [3](#0-2) 

`Copy` then derives the parent directory of the resulting (already-cleaned) path and unconditionally creates it with `os.MkdirAll`, followed by `os.OpenFile` with `O_CREATE|O_TRUNC`: [4](#0-3) 

Because `filepath.Join` internally calls `filepath.Clean`, a name like `"../../evil/pwned"` combined with `w.dir="."` collapses to `"../evil/pwned"` at the `makePath` call itself — there is no subsequent independent "final Join/Clean" step, and critically no check anywhere that the resulting `fp` still has `w.dir` as a prefix. The only validation performed on `name` prior to this point is the Windows-reserved-filename check [5](#0-4)  and a pre-existing-file check in `check(fp)` (used only to warn about overwrite, not confinement) [6](#0-5) . Neither prevents the join result from resolving outside `w.dir`.

Grepping the `release` package confirms there is no `filepath.Base`/containment sanitization applied to asset names anywhere in `download.go` or `shared/fetch.go` before use.

### Impact Explanation
An attacker who controls a release's asset name (e.g., a public/forked repo release, or a malicious GHES/host `gh` is configured against) can cause `gh release download` to create arbitrary directories and write/overwrite arbitrary files outside the user-specified `--dir`, up to the OS permissions of the victim's user. This matches "file write or overwrite outside the intended path" impact class.

### Likelihood Explanation
- Preconditions: victim runs `gh release download` (or defaults with no `--pattern`/`--archive` and default `--dir .`) against a release whose assets include a crafted `Name` containing traversal segments (e.g. `subdir/../../escape/payload.sh`).
- No special privileges needed beyond being able to publish a release/asset with that name (or controlling the API response if `gh` is pointed at an attacker-controlled host).
- Deterministic and repeatable: each invocation with the same crafted name reproduces the same out-of-tree path.

### Recommendation
In `destinationWriter.makePath` (or `Copy`), after computing `fp`, verify containment: compute `absDir, _ := filepath.Abs(w.dir)` and `absFp, _ := filepath.Abs(fp)`, then reject (return an error) if `absFp` is not equal to or a descendant of `absDir` (e.g., using `filepath.Rel` and checking it doesn't start with `..` or isn't absolute), or simply reduce `name` to `filepath.Base(name)` before joining, disallowing any embedded path separators.

### Proof of Concept
Go test (add to `pkg/cmd/release/download/download_test.go`):
```go
func TestDestinationWriter_PathTraversal(t *testing.T) {
    tmp := t.TempDir()
    dw := destinationWriter{dir: tmp}
    name := "sub/../../escape/payload.txt"
    err := dw.Copy(name, strings.NewReader("pwned"))
    require.NoError(t, err)

    fp := dw.makePath(name)
    absDir, _ := filepath.Abs(tmp)
    absFp, _ := filepath.Abs(fp)
    rel, relErr := filepath.Rel(absDir, absFp)
    // Assert fp escapes tmp: rel starts with ".." meaning it's outside absDir
    require.NoError(t, relErr)
    require.True(t, strings.HasPrefix(rel, ".."), "expected path escape, got fp=%s rel=%s", absFp, rel)

    // Confirm file actually created outside tmp
    _, statErr := os.Stat(absFp)
    require.NoError(t, statErr)
}
```
Fuzz plan: `func FuzzDestinationWriterCopy(f *testing.F)` seeding names like `"../x"`, `"a/../../b"`, `"/etc/passwd"`, `"a\\..\\..\\b"`; for each generated `name`, call `dest.Copy(name, bytes.NewReader(nil))` against a `t.TempDir()` root and assert `filepath.Rel(root, dest.makePath(name))` never begins with `..` and is never absolute — currently this assertion fails for traversal payloads.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}
