### Title
Stack-scoped `ApiClient` tokens can read the CCMenu build status/commit info of arbitrary stacks - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`CCMenuController#stack` overrides `Api::BaseController#stack`/`#stacks` and calls `Stack.from_param!(params[:stack_id])` directly on the unscoped `Stack` model instead of going through the `stacks` helper that restricts lookups to `current_api_client.stack_id`. Any valid `ApiClient` token that has the `read:stack` permission and is provisioned as scoped to one specific stack can therefore fetch the CCMenu XML (status, lock state, `lastBuildLabel` commit sha, `webUrl`) of any other stack in the installation, not just the one it was granted access to.

### Finding Description
The intended binding enforced elsewhere in the API is:
`current_api_client.stack_id == stack.id` (when `current_api_client.stack_id?` is true), implemented in `Api::BaseController`: [1](#0-0) 

Every other controller that inherits `stack` from `BaseController` (e.g. `Api::StacksController`) performs the lookup through `stacks.from_param!`, so a token scoped to stack A can never resolve stack B.

`Api::CCMenuController` breaks this binding by redefining `stack` to bypass the scope entirely: [2](#0-1) 

`require_permission :read, :stack` only checks that the permission string `"read:stack"` is present in `current_api_client.permissions`; it never checks `current_api_client.stack_id` against the requested `params[:stack_id]`: [3](#0-2) 

**Exploit flow:** An attacker holding a valid `ApiClient` token created for/scoped to stack A (`stack_id = A.id`, `permissions: ["read:stack"]`) sends `GET /stack_a_owner/stack_a_repo/master/ccmenu.xml?token=<token>` with `stack_id` replaced by any other stack's identifier (e.g. `victim_owner/victim_repo/master`). Because `CCMenuController#stack` calls `Stack.from_param!` on the whole `Stack` table rather than `stacks.from_param!`, the lookup succeeds and returns stack B's record, and the controller renders that stack's build/commit data.

No existing guard prevents this: `require_permission!` only checks the permission string, not stack identity; `authenticate_api_client` only verifies the token signature; there is no `stack_id` equality check anywhere in this controller.

### Impact Explanation
A holder of any `read:stack`-permissioned `ApiClient` token — even one deliberately restricted by an operator to a single stack via `stack_id` — can enumerate and read the CCMenu status (build success/failure, lock state, `lastBuildLabel` containing the latest deployed commit sha, `webUrl`) of every other stack managed by the Shipit instance, across repositories/tenants the token was never authorized for. This is repeatable for any stack whose owner/repo/branch (environment) string is known or guessable, with no rate limiting on this endpoint. This matches "High - unauthenticated read of stack state" in effect, since the disclosed information (deploy/build status and current commit) is exposed outside the token's intended authorization boundary across tenants sharing one Shipit instance.

### Likelihood Explanation
Requires possession of a legitimate, restricted `ApiClient` token with `read:stack` permission (an insider/lower-privileged integration credential, not a Shipit operator secret) — this is a plausible real-world scenario since Shipit is commonly deployed multi-tenant with narrowly scoped tokens issued per team/repo. Given such a token, the attack costs a single HTTP GET with a different `stack_id` path segment; it is trivially repeatable against any stack.

### Recommendation
Remove the `stack` override in `Api::CCMenuController` (or reimplement it using the inherited `stacks.from_param!` scope) so lookups are always constrained by `current_api_client.stack_id` when set, consistent with `Api::BaseController#stack`.

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb
test "a token scoped to stack A cannot read stack B's ccmenu" do
  stack_a = shipit_stacks(:shipit)
  stack_b = Stack.create!(repository: Repository.new(owner: "victim", name: "repo"), branch: "master")

  scoped_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: "scoped",
    stack_id: stack_a.id,
    permissions: ["read:stack"]
  )

  get :show, params: { stack_id: stack_b.to_param, token: scoped_client.authentication_token }

  # Binding under test: scoped_client.stack_id (== stack_a.id) must equal the id of the
  # stack whose data is rendered. It does not:
  assert_response :not_found # or :forbidden, expected
  # Currently fails: assert_response :ok; project data belongs to stack_b, not stack_a.
end
```
