## Title
Webhook signature verification binds to `repository.owner.login`/`organization.login` while all processing binds to the independent `repository.full_name` field, allowing cross-organization webhook forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App (and therefore which `webhook_secret`) to validate the inbound HMAC signature against using only `repository.owner.login` (falling back to `organization.login`) from the attacker-controlled JSON body. Every downstream `Shipit::Webhooks::Handlers::Handler` subclass instead resolves the actual target `Repository`/`Stack` using a completely different, unverified field: `repository.full_name`. Because these two fields are never cross-checked, a party who knows the webhook secret for *one* organization configured on a shared Shipit instance can forge a signed payload whose `repository.full_name` points at a repository belonging to a *different* organization also hosted on that instance.

### Finding Description
Signature verification: [1](#0-0) 

Specifically: [2](#0-1) [3](#0-2) 

`Shipit.github(organization: repository_owner)` looks up a per-organization `GitHubApp` configuration/secret via `github_app_config`, which is keyed strictly by organization name: [4](#0-3) 

However, every handler resolves the repository/stack to act on from a separate field, `repository.full_name`, which is not covered by `repository_owner`: [5](#0-4) 

This pattern repeats in the pull-request handlers, which archive/unarchive/deprovision review stacks based solely on `params.repository.full_name`: [6](#0-5) [7](#0-6) 

Nothing in `create` re-checks that `repository.owner.login`/`organization.login` (used to pick the secret) matches `repository.full_name` (used to pick the write target): [8](#0-7) 

The equality that is silently assumed but never enforced is:
`organization authenticated by verify_signature (repository.owner.login / organization.login)` == `repository actually written by the handler (repository.full_name)`.
An attacker who controls the webhook secret for Organization A (e.g., an admin of a GitHub App/org that shares this single Shipit deployment with other orgs) can compute a valid HMAC over a crafted body where `organization.login` (or `repository.owner.login`) is `"OrgA"` but `repository.full_name` is `"OrgB/some-configured-repo"`. `verify_signature` passes because it only checks OrgA's secret against the raw body; the handler then acts on OrgB's repository/stack.

### Impact Explanation
This breaks the deployment-trust binding between "organization that authenticated" and "repository that is written," enabling cross-repository/cross-tenant writes: an attacker holding only one organization's webhook secret can archive, unarchive, deprovision, or force-resync review stacks belonging to a repository under an unrelated organization hosted on the same Shipit instance, and create/mutate `PullRequest`/team-membership records tied to that foreign repository. This matches the "cross-repository writes" / "unauthorized deploy or rollback" class of Critical impact, since `unarchive!`/`archive!` on a `ReviewStack` triggers provisioning/deprovisioning task execution: [9](#0-8) 

### Likelihood Explanation
This is only reachable on Shipit instances configured with multiple GitHub Apps/organizations sharing one webhook endpoint (the per-organization `github` config keying is a supported, documented setup): [10](#0-9) 
An attacker needs the webhook secret of any one configured organization (which they may legitimately possess for their own org's GitHub App) but not for the target org — no Shipit session, `ApiClient` token, or repository write access is required. The request itself is a plain unauthenticated POST to `/github/webhooks` with a computable HMAC.

### Recommendation
In `WebhooksController#verify_signature`/`Handler`, require that `repository.owner.login` (or `organization.login`) used to select the webhook secret is identical to the owner segment of `repository.full_name` before dispatching to any handler; reject the request otherwise.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgA` and `OrgB`, each with its own `github.webhook_secret` (as in `docs/setup.md`).
2. As someone who only knows `OrgA`'s webhook secret, craft a `pull_request` "closed" payload:
```json
{
  "action": "closed",
  "number": 1,
  "pull_request": { ... "head": {"sha": "...", "ref": "..."} ... },
  "repository": { "full_name": "OrgB/target-repo" },
  "organization": { "login": "OrgA" },
  "sender": { "login": "attacker" }
}
```
(omit `repository.owner.login` so `repository_owner` falls back to `organization.login` = `"OrgA"`).
3. Compute `X-Hub-Signature` using `OrgA`'s `webhook_secret` over the raw JSON body.
4. POST to `/github/webhooks` with `X-Github-Event: pull_request`. `verify_signature` validates successfully against `OrgA`'s secret; `ClosedHandler` then resolves `Shipit::Repository.from_github_repo_name("OrgB/target-repo")` and calls `review_stack.archive!`, deprovisioning a review stack that belongs to `OrgB`.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

**File:** lib/shipit.rb (L170-200)
```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
