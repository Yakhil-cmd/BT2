### Title
Untrusted swap-route venue can add unauthorized wallet-token transfers to the victim's signed authorization tree - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
Controller strategy routes are user-supplied and can invoke attacker-controlled venue contracts. During simulation, a transfer initiated by that venue from the victim's wallet is recorded as a child of the victim's `swap_collateral` authorization; if the victim signs the returned tree, the host executes the otherwise unauthorized transfer. This is analogous to CVE-2024-7525 because a low-privilege request path causes a trusted caller-authorized operation to carry an unexpected state-changing side effect.

### Finding Description
`swap_collateral` authenticates the caller and requires account-owner or delegate authority before routing a withdrawal through `swap_tokens_or_passthrough`. [1](#0-0)  The strategy withdraws collateral into controller custody and passes the measured amount and caller-supplied swap payload into the router. [2](#0-1)  `swap_tokens` authorizes only the intended controller-to-router input transfer and then calls `execute_strategy` with the unvalidated route payload. [3](#0-2) 

The route payload is an address registry plus packed instructions whose `idx_a` field selects the pool contract to call. [4](#0-3)  The router decodes this caller-controlled program, pulls the declared input under `sender.require_auth`, and executes each selected instruction. [5](#0-4)  Swap hops dispatch to the payload-selected pool address, with no venue/pool allowlist in the dispatch path. [6](#0-5) 

A malicious pool called during the route can invoke an unrelated token's `transfer(victim, attacker, amount)` while the victim's authorization context is still active. The test demonstrates that simulation records this wallet transfer as a child of the victim's `swap_collateral` authorization, and that signing that poisoned tree makes the transfer execute. [7](#0-6)  A benign route succeeds with no children, while the rogue transfer is rejected if it is not included in the signed tree. [8](#0-7) 

### Impact Explanation
An attacker can steal arbitrary token balances from a user who signs a poisoned strategy transaction, including assets unrelated to the lending markets and not listed by the protocol. [9](#0-8)  The strategy can still return a valid measured output and leave the lending position solvent, so the route's min-out and final account checks do not bound the separate wallet theft. [10](#0-9) 

### Likelihood Explanation
Exploitation requires user interaction: the victim must obtain or be induced to sign the poisoned authorization tree produced by simulation. An unprivileged attacker can deploy the malicious venue and supply the route bytes; no protocol privileges, leaked keys, upgrades, or oracle manipulation are required. All strategy entrypoints that accept route bytes share the same exposure, including `multiply`, `swap_collateral`, `swap_debt`, and `repay_debt_with_collateral`.

### Recommendation
Constrain strategy routes to governance-approved venue/pool addresses, or route through a fixed registry keyed by immutable venue identifiers rather than arbitrary payload-selected addresses. Additionally, clients should decode the complete simulated authorization tree and reject any child invocation other than the expected token pulls, but contract-level route allowlisting is the robust mitigation because signature UX cannot be relied upon to detect malicious children.

### Proof of Concept
1. Victim owns a lending account and holds `WALLET_BALANCE` of an unrelated token.
2. Attacker deploys a contract implementing the selected venue's pool interface and configures it to call `token.transfer(victim, attacker, WALLET_BALANCE)` during its swap invocation.
3. Attacker supplies a `swap_collateral` route that selects the malicious pool.
4. During simulation, the malicious transfer is recorded under the victim's root `swap_collateral` invocation. [11](#0-10) 
5. Victim signs the simulated authorization tree.
6. At enforcement time, the host accepts the included child transfer; the test asserts the victim wallet reaches zero and the attacker receives the full wallet balance. [12](#0-11)

pub(crate) fn run(env: Env, sender: Address, total_in: i128, payload: StrategyPayload) -> i128 {
    sender.require_auth();

    if total_in <= 0 {
        panic_with_error!(&env, Error::InvalidAmount);
    }

    let StrategyPayload {
        amounts,
        assets,
        ops,
    } = payload;
    let program = Program::decode(&env, &ops, assets.len(), amounts.len());

    let input_token = assets.get_unchecked(program.token_in);
    let output_token = assets.get_unchecked(program.token_out);
    let total_min_out = amounts.get_unchecked(program.min_out);
    if total_min_out <= 0 {
        panic_with_error!(&env, Error::SlippageExceeded);
    }

    let router = env.current_contract_address();
    let mut vault = Vault::new(&env);
    let mut tokens_cache: Map<Address, Vec<Address>> = Map::new(&env);

    // Credit the measured delta, not declared `total_in`: a fee-on-transfer
    // input would otherwise draw the shortfall from the fee reserve.
    let credited_in = transfer_amount_measured(
        &env,
        &input_token,
        &sender,
        &router,
        total_in,
        GenericError::AmountMustBePositive,
    );

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
