The analog scan requires a genuine deserialization‑gadget class of bug: a Java-style scenario where deserializing attacker-controlled bytes into a runtime-selected polymorphic type lets the attacker construct arbitrary "gadget" objects that execute code via callbacks (finalize/readObject/etc.) during deserialization itself, without any application-level validation of the decoded value.

Polkadot SDK's SCALE `Decode`/`Encode` codec is fundamentally different from Java serialization: types are statically known at the call site (`T::decode(&mut input)`), decoding never invokes attacker-influenced virtual dispatch or executes code as a side effect of decoding, and there's no class-loading/gadget-chain concept in Rust's type system. I reviewed the entry points that decode attacker-supplied bytes into typed values across the codebase:

- Extrinsic decoding enforces depth/size limits and static typing: [1](#0-0) 
- Contracts sandbox memory decoding uses `decode_with_depth_limit`/`decode_all_with_depth_limit` against a compile-time-known type `D`, with explicit bounds checks: [2](#0-1) 
- XCM double-encoded/nested decoding tracks depth and memory explicitly to avoid unbounded recursion, not polymorphic gadget construction: [3](#0-2) 
- `WrapperOpaque<T>` decoding is bounded by `MAX_EXTRINSIC_DEPTH` and statically typed to `T`: [4](#0-3) 

None of these constructs allow an attacker to choose or influence *which concrete type* gets instantiated from serialized bytes (the essential precondition for a Java deserialization gadget-chain attack), nor does decoding itself trigger arbitrary method execution as a side effect. This is a structural property of Rust's static typing and the SCALE codec design, not an incidental safeguard, so there is no demonstrable analog to CVE-2022-1415 in this codebase.

where
	T: Decode,
{
	fn decode<I: codec::Input>(input: &mut I) -> Result<Self, codec::Error> {
		let mut obj = Self { encoded: Vec::<u8>::decode(input)?, decoded: None };

		// If it's a local call, we also decode the inner double encoded object,
		// in order to make sure that its heap memory is accounted for.
		nesting_count::using_once(&mut 0, || {
			nesting_count::with(|count| {
				descend_ref_and_check_depth(
					count,
					RECURSION_LIMIT as u32,
					DECODE_RECURSION_LIMIT_MSG,
				)
			})
			.unwrap_or(Err("Could not access nesting_count env variable".into()))?;

			let mut nested_input =
				NestedInput { downstream_input: input, encoded: &obj.encoded[..], depth: 0 };
			let decoded = T::decode(&mut nested_input)?;
			// If we didn't manage to consume any byte, this is a remote call, and it can't
			// be decoded locally.
			if nested_input.encoded.len() == obj.encoded.len() {
				let _ = nesting_count::with(|count| {
					count.saturating_dec();
				});

				return Ok(obj);
			}
			obj.decoded = Some(decoded);

			// We need to also make sure that we consumed all the input data, but we can't use
			// `decode_all()`, because it only accepts a byte slice as input.
			if !nested_input.encoded.is_empty() {
				return Err(DECODE_ALL_ERR_MSG.into());
			}

			let _ = nesting_count::with(|count| {
				count.saturating_dec();
			});

			Ok(obj)
		})
	}
}
