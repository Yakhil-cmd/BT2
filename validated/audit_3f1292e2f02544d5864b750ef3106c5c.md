### Title
`ProxyType::NonTransfer::is_superset` incorrectly claims containment of `Auction`/`SudoBalances`, allowing proxy privilege escalation - ([File: substrate/frame/staking-async/runtimes/rc/src/lib.rs])

### Summary
The `pallet-staking-async-rc-runtime` (a Relay Chain runtime built on `pallet_proxy`) defines `ProxyType::is_superset` as `(ProxyType::NonTransfer, _) => true`, meaning `NonTransfer` is declared a superset of *every* other proxy type, including `Auction` and `SudoBalances`. [1](#0-0) 

However, `NonTransfer`'s own `filter` explicitly documents and enforces exclusions that `Auction` and `SudoBalances` admit: it only allows `Registrar::register`, `Registrar::deregister`, and `Registrar::reserve` while the comment says `// Specifically omitting Registrar 'swap'`, and it fully omits the `Sudo` pallet and `Balances` pallet (`// Specifically omitting Sudo pallet`, `// Specifically omitting the entire Balances pallet`). [2](#0-1) 

`Auction`'s filter admits the *entire* `Registrar` pallet (`RuntimeCall::Registrar(..)`), including `swap`, and `SudoBalances`'s filter admits `Sudo(sudo{ call: Balances(..) })`. [3](#0-2) 

This is the exact same bug class that was already found and fixed in this same repository for the Asset Hub Westend runtime: `NonTransfer` falsely claiming to be a superset of `Governance` (see `prdoc/pr_12769.prdoc` and the regression tests in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs`). That fix was never mirrored into `pallet-staking-async-rc-runtime`. [4](#0-3) [5](#0-4) 

### Finding Description
`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` performed *through* a proxy solely on `def.proxy_type.is_superset(proxy_type)` — if that returns `true`, the guard that would otherwise block the call is bypassed, and `filter` for the delegate's own type is consulted only as a fallback (and `NonTransfer`'s filter admits `RuntimeCall::Proxy(..)` wholesale, so it also passes there): [6](#0-5) 

Because `pallet-staking-async-rc-runtime`'s `ProxyType::is_superset` declares `NonTransfer` a superset of `Auction` (and `SudoBalances`) without the corresponding call-filter containment holding, any account that has been granted an ordinary `NonTransfer` proxy over a delegator can:
1. Call `Proxy::proxy(real, None, Proxy::add_proxy{ delegate: attacker, proxy_type: Auction, delay: 0 })` on behalf of `real` — this succeeds because `NonTransfer.is_superset(Auction) == true` bypasses the escalation guard, and `NonTransfer.filter` also admits `Proxy(..)` calls generically.
2. Now hold an `Auction` proxy over `real`, and call `Proxy::proxy(real, None, Registrar::swap{..})` — `Auction.filter` admits all `Registrar` calls, including `swap`, which `NonTransfer.filter` intentionally denies.

The attacker thereby reaches a call (`paras_registrar::Call::swap`) that the delegator explicitly did *not* authorize when granting a `NonTransfer` proxy — a straightforward escalation of privileges through a permission-lattice mismatch, analogous to CVE-2021-41325 where an unprivileged, low-permission actor (there: a "standard user" creation profile; here: a `NonTransfer` proxy) is able to grant itself elevated permissions (there: admin `Roles`; here: `Auction`/`SudoBalances` proxy types) because the server/runtime fails to validate that the claimed containment/permission set is actually a subset.

The same broken invariant also lets a `NonTransfer` proxy grant itself a `SudoBalances` proxy, which (if the delegator account happens to be the chain's `Sudo` key) would allow the delegate to reach `Sudo::sudo(Balances::...)` — a call `NonTransfer`'s own filter explicitly excludes ("Specifically omitting Sudo pallet", "Specifically omitting the entire Balances pallet").

### Impact Explanation
This breaks the core access-control invariant of `pallet_proxy`: a delegate with a restricted proxy type must never be able to obtain calls beyond what its own filter allows. Concretely, a `NonTransfer` delegate — which a user grants specifically to *withhold* fund-moving/critical calls — can silently escalate to `Registrar::swap` (parachain slot/ID manipulation) via the `Auction` type, and, given a sudo-holding delegator, to arbitrary `Balances` calls via `SudoBalances`. This is an unauthorized-dispatch / broken-access-control class issue on a live relay-chain-style runtime, matching Medium/High severity criteria for authorization bypass.

### Likelihood Explanation
Likelihood is high for the mechanism itself: it requires only that some account has previously granted an unprivileged delegate a standard `NonTransfer` proxy (a very common configuration recommended precisely because it is supposed to be safe/non-custodial), and that the delegate then issues two ordinary signed extrinsics (`add_proxy` then the proxied call) — no privileged role, governance, or stolen keys are needed. The `Registrar::swap` escalation path requires no special precondition on the delegator. The `SudoBalances` path additionally requires the delegator to be the runtime's Sudo key holder, which reduces its practical likelihood but does not change that the authorization check itself is broken.

### Recommendation
Correct `ProxyType::is_superset` in `substrate/frame/staking-async/runtimes/rc/src/lib.rs` so that `NonTransfer` is not blanket-declared a superset of every other type. Either:
- Enumerate only the proxy types whose `filter` is provably a subset of `NonTransfer`'s `filter` (mirroring the fix applied to `asset-hub-westend-runtime` in `prdoc/pr_12769.prdoc`), excluding at minimum `Auction` and `SudoBalances`; or
- Add an automated lattice-consistency test analogous to `proxy_type_superset_relation_matches_call_filters` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs` for this runtime, asserting for every `(superset, subset)` pair that `subset.filter(call) ⇒ superset.filter(call)` across representative calls, so this class of regression cannot reappear silently.

### Proof of Concept
No executable PoC was run against a live network or test harness (out of scope/not permitted). The reachability was traced statically through real, non-mocked production code:
- Guard bypass point: `pallet_proxy::Pallet::do_proxy`'s `is_superset` check [6](#0-5) .
- Vulnerable declaration: `(ProxyType::NonTransfer, _) => true` [1](#0-0) .
- Mismatched filters: `NonTransfer` (partial `Registrar`, no `Sudo`/`Balances`) vs. `Auction`/`SudoBalances` (full `Registrar`, `Sudo(Balances)`) [7](#0-6) .

A minimal reproduction (not executed) would mirror the existing asset-hub-westend regression test pattern: build the `pallet-staking-async-rc-runtime` test/mock, have account A `add_proxy(B, ProxyType::NonTransfer, 0)`, then from B call `Proxy::proxy(A, None, Proxy::add_proxy{delegate: B, proxy_type: Auction, delay: 0})` and assert it succeeds (`ProxyExecuted{result: Ok(())}`), followed by `Proxy::proxy(A, None, Registrar::swap{..})` from B succeeding despite `NonTransfer` explicitly excluding `Registrar::swap`. I could not execute this due to lacking a runnable environment in this ask-only session; this should be verified with an integration test before filing, consistent with the existing sibling test for asset-hub-westend.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
