### Title
Status webhooks resolve target commits by bare SHA with no repository/organization scoping, letting a webhook accepted for one (unsecured) GitHub org forge commit status on any stack - ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates an inbound webhook by looking up the GitHub App configured for `repository_owner` (derived from the payload's `repository.owner.login`, or `organization.login` as fallback) and checking the signature against **that org's** `webhook_secret`. [1](#0-0) . Crucially, `GithubApp#verify_webhook_signature` **unconditionally returns `true` when no `webhook_secret` is configured** for that org: [2](#0-1) . A `webhook_secret: nil` org is a documented, supported configuration, shown as the example value in both `config/secrets.development.example.yml` and `config/secrets.development.shopify.yml`.

Once a request is "verified" this way, `StatusHandler#process` — unlike every sibling handler (`PushHandler`, `CheckSuiteHandler`, the `PullRequest::*` handlers) — never scopes its lookup to the authenticated repository. It resolves the target purely by the attacker-supplied `sha` field, across the **entire** `Commit` table: [3](#0-2) . Compare this to `CheckSuiteHandler`, which correctly restricts to `stacks.where(branch: ...)` derived from `repository.full_name` before touching any commit: [4](#0-3) , and to the base `Handler#stacks`/`#repository_name` helper that all properly-scoped handlers use: [5](#0-4) .

### Finding Description
The broken binding is: **organization that authenticated (`repository_owner` used in `verify_signature`) ≠ repository/stack whose data is mutated (any `Commit` matching `params.sha`, resolved with zero ownership check in `StatusHandler`)**.

- Before the attack: signature verification is meant to guarantee that a webhook claiming to originate from org `X` was actually sent by GitHub for a repository owned by `X`, and any handler mutating state should only touch resources that belong to that same repository/org.
- After the attack: an attacker who can get a `status` event accepted for **any** org configured in Shipit with a blank `webhook_secret` (a documented, valid configuration) can set `sha` to an arbitrary value and `state` to `success`, and `StatusHandler` will locate and update the status of a `Commit` belonging to a **completely different** stack/organization, because the handler never checks `payload.dig('repository','full_name')` or joins through `stacks` at all.

This is the same root-cause class as the referenced report ("a check exists but its result isn't actually applied to the thing being changed"): here, the check ("is this webhook from an authorized org?") is disconnected from the thing being changed (an arbitrary commit's CI status, chosen only by unchecked SHA).

### Impact Explanation
Commit statuses (`success`/`failure`/`pending`) reported via GitHub `status` webhooks feed Shipit's deployable-status logic (`commit.create_status_from_github!`, and the `deployable_status` concept referenced in `Hook::EVENTS`). Forging a `success` status on a commit belonging to a stack the attacker has no access to lets that commit appear deployable/mergeable through Shipit's normal UI/API workflow without any real CI having run, directly enabling an **unauthorized deploy** decision on a target stack the attacker was never authorized to touch — meeting the High/Critical bar defined for this analysis (escalation of trust leading to an unauthorized deploy).

### Likelihood Explanation
Requires only: (1) one org in the multi-org GitHub config to have no `webhook_secret` set — a supported, documented configuration, not a privileged secret the attacker must obtain; and (2) knowledge of a target commit SHA in another tracked stack (commit SHAs are not secrets — visible via GitHub's public API, PR pages, or the target repo itself). No `ApiClient` token, GitHub App private key, or webhook secret of the *target* org is required, so this does not fall under the excluded "requires webhook_secret" cases (the exploited org's secret is unset, not compromised).

### Recommendation
Scope `StatusHandler` (and any other handler that reads `params.sha`/similar identifiers) to the authenticated repository, e.g. `stacks.flat_map(&:commits).where(sha: params.sha)` or `Commit.joins(stack: :repository).where(sha: params.sha, repositories: { id: repository.id })`, matching the pattern already used by `CheckSuiteHandler`/`PushHandler`. Additionally, require `webhook_secret` to be present for every configured org (reject boot/config if blank) so `verify_webhook_signature` can never silently degrade to "always true."

### Proof of Concept
1. Shipit is configured with two GitHub orgs: `org-a` (no `webhook_secret` set) and `org-b` (secret set, hosts a real tracked stack with commit `abc123...`).
2. Attacker POSTs to the webhooks endpoint:
   - `X-Github-Event: status`
   - Body: `{"repository": {"owner": {"login": "org-a"}, "full_name": "org-a/whatever"}, "sha": "abc123...", "state": "success", "context": "ci/forged"}`
   - No valid `X-Hub-Signature` needed.
3. `verify_signature` resolves `repository_owner = "org-a"`, calls `Shipit.github(organization: "org-a").verify_webhook_signature(...)`, which returns `true` immediately because `org-a`'s `webhook_secret` is blank. [2](#0-1) 
4. `Shipit::Webhooks.for_event('status')` dispatches to `StatusHandler`, which runs `Commit.where(sha: 'abc123...').each { |c| c.create_status_from_github!(params) }` — updating the status of the `org-b` commit despite the request never being authenticated for `org-b`. [6](#0-5)

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"

      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
