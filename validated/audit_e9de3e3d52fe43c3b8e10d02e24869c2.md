### Title
Bad-debt socialization writes down the liquidity index before accruing pending interest, causing suppliers to absorb an inflated loss - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
When a liquidation leaves a borrower with uncoverable debt, `liquidate` in `mainnet/contracts/market/v0-4-market.clar` folds `socialize-debt-asset` over the borrower's remaining debt to write off the bad debt against the vault's suppliers. `socialize-debt-asset` calls `vault-socialize-debt` (which mutates the vault's `lindex`) *before* calling `vault-accrue` to bring the vault's `index`/`lindex` up to the current timestamp: [1](#0-0) 

The vault-side `socialize-debt` function itself never calls `accrue` — unlike every other state-mutating vault entrypoint (`deposit`, `redeem`, `borrow`, `system-repay`, etc.), which all begin with `(u (try! (accrue)))`: [2](#0-1) 

### Finding Description
`socialize-debt` computes the write-down ratio from `old-total-assets`, which is derived from the vault's *stored* (unaccrued) `index`, not the up-to-date `next-index`:
- `old-total-assets = (total-assets)` → `current-assets + (total-debt - borrowed)`, where `total-debt` uses `(var-get index)`.
- `new-lindex = current-lindex * (old-total-assets - debt-reduction) / old-total-assets`.

If any time has elapsed since the vault's `last-update`, real total assets (including interest accrued but not yet posted to `index`/`lindex`) are higher than `old-total-assets`. Using the understated `old-total-assets` as the denominator makes the same absolute `debt-reduction` represent a *larger* fraction of assets than it truly is, so `new-lindex` is slashed more severely than the actual bad debt warrants.

Only *after* this premature write-down does `socialize-debt-asset` call `vault-accrue` to refresh the cache, meaning the subsequent accrual compounds on top of the already-slashed `lindex` rather than crediting suppliers with the interest earned up to the liquidation moment before the loss is applied: [3](#0-2) 

This is structurally the same root cause as the reported issue: a shared, protocol-wide accrual value (`accumulatedETHPerFreeFloatingShare` there, `index`/`lindex` here) must be refreshed immediately before a state transition that locks in a snapshot (knot deregistration there, bad-debt write-down here); skipping that refresh permanently under-credits passive third parties who have no involvement in the triggering transaction.

### Impact Explanation
The victims are all liquidity suppliers of the affected vault (zToken holders), a shared pool of unrelated users who did not cause the borrower's bad debt. Because the write-down denominator omits interest that has already economically accrued to them, their `lindex`-derived share price is reduced by more than the true bad-debt loss, permanently destroying value that should have been theirs (unclaimed yield they had already earned up to that block). This lands in the High-impact category: theft/permanent loss of unclaimed yield for depositors uninvolved in the liquidation.

### Likelihood Explanation
Any liquidation that results in `no-collateral-left` (uncovered debt) triggers `socialize-debt-asset`. The magnitude of the discrepancy scales with the time elapsed since the vault's last `accrue` call for that asset — vaults with lower traffic (fewer transactions touching `accrue-and-cache` for that `aid`) between liquidations will exhibit a larger unaccrued interest gap, amplifying the error. This does not require any privileged action or DAO compromise — it occurs on the standard liquidation code path whenever bad debt must be socialized.

### Recommendation
Call `vault-accrue`/`accrue` on the affected vault *before* computing and applying the write-down in `socialize-debt` (both in `mainnet/contracts/market/v0-4-market.clar`'s `socialize-debt-asset` and in each vault's `socialize-debt` function), so that `old-total-assets` reflects fully accrued interest at the moment of write-down, and only then compute `new-lindex` from the correctly accrued base.

### Proof of Concept
1. Vault has `index`/`lindex` last updated at `t0`; interest continues to accrue implicitly (owed but not yet posted) between `t0` and the liquidation block `t1`.
2. No other transaction touching that vault's `accrue-and-cache` occurs between `t0` and `t1`, so `index`/`lindex` remain stale at `t1`.
3. A borrower becomes fully underwater; a liquidator calls `liquidate`, exhausting the borrower's collateral, triggering `no-collateral-left` and the `socialize-debt-asset` fold.
4. `vault-socialize-debt` computes `old-total-assets` from the stale `index`, understating real total assets, and writes `new-lindex` down by a larger fraction than the true bad debt represents.
5. `vault-accrue` is called afterward, compounding future interest on top of the already over-slashed `lindex`.
6. All existing zToken holders in that vault now redeem at a lower share price than the economically correct write-down would have produced, permanently losing the difference — with no ability to detect or reverse it, since it is baked directly into `lindex`. [4](#0-3) [1](#0-0)

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
