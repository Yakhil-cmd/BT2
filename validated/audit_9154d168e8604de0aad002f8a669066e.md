### Title
Accidental direct token transfer to the pool or controller is stranded forever — ([File: contracts/pool/src/lib.rs](contracts/pool/src/lib.rs))

### Summary
The pool accounts for liquidity through an internal `cash` book per `(hub, asset)` market, not through its live SAC balance. Any tokens pushed directly to the pool or controller contract address via a raw `token.transfer` belong to no market's book, and neither contract exposes a sweep/rescue entrypoint. The result is the same bug class as the referenced NFT finding: assets sent directly to the contract are permanently unrecoverable.

### Finding Description
The pool credits `cash` only inside `supply`, `repay`, and `recapitalize`, on the controller's word; a plain `token.transfer(user, pool, amount)` moves real custody without touching any book. The pool README documents the complete public surface — `create_market`, `update_params`, `update_indexes`, `supply`, `borrow`, `withdraw`, `repay`, `net_settle`, `seize_positions`, `claim_revenue`, `recapitalize`, `flash_loan`, `create_strategy`, `upgrade` — and none of them releases unbooked balance. The protocol itself acknowledges this: `docs/reference/architecture.md` states "direct donations do not automatically increase booked cash," and `docs/explanation/threat-model.md` states "Direct donations do not rewrite those books." The test `tests/test-harness/tests/pool_money_flow_audit.rs` pins that an unsolicited `token.transfer` to the pool leaves `token.balance(pool) = cash + donation` forever, with the donation belonging to no market.

The controller is worse: `tests/test-harness/tests/controller/recipient_is_protocol_contract.rs` documents that the controller "holds funds no balance-delta measurement can ever claim" — all inbound crediting paths (`supply`, `repay`, `recapitalize`, flash callbacks) measure *deltas* during the call, so a pre-existing balance is invisible and unclaimable. The same test shows the protocol already fixed the *internal* version of this bug (GH-17: `borrow`/`withdraw` with `receiver` set to the pool or controller is rejected with `INVALID_FLASHLOAN_RECEIVER`), proving the stranded-funds failure mode is real and recognized — but nothing stops an external `token.transfer`, and no recovery path exists (unlike the swap-aggregator, which has an admin `sweep`, the pool and controller have none). The DeFindex adapter likewise "has no recovery path for arbitrary stranded assets" per `docs/explanation/threat-model.md`.

### Impact Explanation
Permanent freezing of funds. Any user who transfers a listed token directly to the pool or controller address — a common wallet/UX mistake since both are plain SAC transfer recipients — loses those tokens permanently. No unprivileged or even privileged entrypoint can return them; only a Wasm `upgrade` adding a sweep could.

### Likelihood Explanation
Requires user error rather than attacker action, and on Soroban no callback trick forces the transfer — matching the source report's "accidental" framing. Likelihood is moderate: the pool/controller addresses are public constants users interact with. Consistent with the Medium rating of the analog. Note the same stray balance also breaks `flash_loan`'s strict `balance == before + fee` equality check, but that is a fail-closed DoS secondary effect, not the primary impact.

### Recommendation
Add a permissionless or owner-gated sweep on the pool that transfers out `token.balance(pool) - Σ cash across all markets of that asset`, and a controller sweep for tokens it holds outside any measured flow. Alternatively, expose a `recapitalize`-style path that credits stray balances to protocol revenue shares so they are recoverable through `claim_revenue`.

### Proof of Concept
1. User calls `token.transfer(user, pool_address, 100e7)` on any listed asset (or to the controller address).
2. `token.balance(pool)` increases; `pool.get_sync_data(hub_asset).state.cash` is unchanged — the donation belongs to no market book.
3. No subsequent `supply`, `repay`, `recapitalize`, `withdraw`, `claim_revenue`, or `flash_loan` can attribute or release the 100 tokens; controller `recapitalize` only measures the delta of its own inbound transfer, so it cannot claim prior balances.
4. Funds are permanently stranded absent a contract upgrade — the same outcome the protocol prevented for `borrow`/`withdraw` recipients in GH-17, still open for raw transfers.
