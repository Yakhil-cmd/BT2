The Vesper Finance incident exploited a lending protocol (Rari Fuse) that used a manipulable AMM spot price as a collateral oracle, allowing the attacker to inflate collateral value and over-borrow. To find a genuine analog in this codebase I looked for the FRAME equivalent: a pallet that (a) reads AMM-style spot reserves as a price/oracle input and (b) uses that price to mint credit, unlock collateral, or authorize a loan/borrow without safeguards.

What exists in-scope is `pallet_asset_conversion`'s constant-product AMM ( [1](#0-0) ), its `QuotePrice`/`SwapCredit` traits ( [2](#0-1) ), and its only price-quote consumers I could find: the `AssetConversionApi` runtime API exposed for off-chain/UI queries ( [3](#0-2) ), the XCM `SingleAssetExchangeAdapter`/`quote_exchange_price` used to price XCM asset exchanges ( [4](#0-3) ), and `SwapAssetAdapter` in `pallet-asset-conversion-tx-payment`, which quotes and *immediately* executes an atomic swap within the same extrinsic to pay transaction fees ( [5](#0-4) ).

None of these consumers match the Vesper/Rari Fuse pattern:
- The tx-payment adapter quotes a price and consumes it atomically in the same transaction against the pool's real, current reserves — there is no persisted/cached price used later to value collateral or authorize a loan, and any withdrawal is bounded by `reducible_balance` checks ( [6](#0-5) ), so manipulating reserves only makes the payer's own fee swap worse, not a path to extract unbacked value.
- The XCM exchange adapter and runtime API are pure quote/exchange functions operating on the same pool state that a swap would actually execute against — they don't back any lending, borrowing, or credit-issuance logic elsewhere in the reviewed scope.
- I found no pallet in this codebase implementing a lending/borrowing market (Rari Fuse/Compound-style) that treats `pallet_asset_conversion`'s spot price as a trusted collateral oracle. `pallet-oracle` (referenced in `prdoc/stable2512/pr_9815.prdoc`) is an off-chain-data-feed pallet, not an AMM-derived price, and I found no evidence it or any other pallet consumes AMM reserves for collateral valuation.

Without a reachable lending/borrowing (or equivalent unbacked-issuance) consumer that trusts a manipulable spot price the way Rari Fuse's VesperLend pool did, the Vesper Finance oracle-manipulation bug class has no demonstrable analog in this codebase's production paths.

			.ok()?;

			.map_err(|error| {

					target: "xcm::SingleAssetExchangeAdapter::quote_exchange_price",
					?want_asset,
					?error,
					"Could not map XCM asset to FRAME asset"
				);
				()
			})

					give_asset_id,
					want_asset_id,
					want_amount,

				)?;

			Some((give_asset.id.clone(), necessary_give).into())
