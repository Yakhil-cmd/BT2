### Title
Position NFT transferred to a contract that cannot authorize permanently freezes the lending account - ([File: contracts/position-nft/src/contract.rs])

### Summary
The position NFT is the sole ownership record for a lending account — the controller resolves `owner_of(account_id)` on every owner-gated call. The NFT contract uses OpenZeppelin's stock `transfer`/`transfer_from`, which authenticate only `from`/`spender` and perform no receiver-capability check on `to`. A holder can move a position to a contract address that has no `__check_auth` implementation, after which no auth tree can ever satisfy `from.require_auth()` for `transfer`, and no one can call `withdraw`, `repay`, `borrow`, or `liquidate`-as-owner on that account.

### Finding Description
- `PositionNft` inherits `NonFungibleToken` (ContractType = `Enumerable`) unchanged; `transfer` and `transfer_from` call `Base::update`, which requires auth from the sender/owner only. There is no `safeTransfer`-style receiver check, and none exists in Soroban — but the consequence is the same: ownership lands wherever the sender names, whether or not that address can ever act. [1](#0-0) 
- The controller stores no owner for an account; `try_account_owner` calls `owner_of` live on the NFT contract, and `is_owner_or_delegate` gates every position verb (`supply` into owned slots, `borrow`, `withdraw`, `multiply`, `swap_*`, `flash_position`, delegate grants). [2](#0-1) 
- A Stellar contract `Address` can only satisfy `require_auth` by running its own `__check_auth`. A SAC, a DeFi contract, a burned/uninitialized contract id, or any contract that simply does not implement `__check_auth` can never authorize an NFT `transfer`/`transfer_from` and never authorize a controller call as owner/delegate.
- The mint path does not create the problem by itself: `create_account` mints to `caller`, which must already `require_auth` — so a minter that is a contract must already be capable of signing. But `transfer(from, to, token_id)` and `transfer_from` accept an arbitrary `to` with no authorization from it. [3](#0-2) 

### Impact Explanation
Permanent freezing of funds: all collateral held in the account becomes unreachable by anyone. The position cannot be withdrawn, unwound, repaid-and-withdrawn by its "owner," or moved onward. The only remaining interaction is permissionless liquidation if the account goes underwater — which seizes collateral to a liquidator rather than returning it to the user — or `clean_bad_debt` socialization. Either way the value is lost to the user permanently, matching the "minted token might be stuck forever" class of the reference report.

### Likelihood Explanation
Requires a holder error (sending the NFT to an incapable contract, e.g. a marketplace/escrow contract that does not handle this collection, or a mistaken contract address). This is a well-documented user-error pattern — the original finding was accepted as High — but it is a one-party mistake rather than an attacker-reachable exploit, so likelihood is moderate. Severity Medium/High depending on how the program weighs self-inflicted loss; the code offers no guardrail (no receiver check, no two-step transfer, no recovery path).

### Recommendation
There is no `safeTransfer` primitive on Soroban, so mitigate at the interface layer:
- Provide a controller-mediated `transfer_account(account_id, to)` that optionally requires `to.require_auth()` — forcing the recipient to prove it can sign before receiving the position (analogous to `safeMint`/`onERC721Received`).
- Document prominently that `transfer`/`transfer_from` to a contract address without `__check_auth` permanently locks the account.
- Optionally reject `to` being a known contract address unless invoked via the check-auth-enforcing path.

### Proof of Concept
1. Alice supplies USDC via `controller::supply(caller=alice, account_id=0, ...)`, minting NFT `id=1` to alice.
2. Alice calls `position-nft::transfer(from=alice, to=dead_contract, token_id=1)` where `dead_contract` is any contract lacking `__check_auth` (or a never-deployed contract address preimage). The call succeeds — only `from` auth is checked.
3. `owner_of(1) = dead_contract`. Every subsequent owner-gated controller call (`withdraw`, `borrow`, `repay`-and-withdraw, `flash_position`, `add_delegate`) resolves the owner as `dead_contract` and fails `NotAuthorized` / host auth error, because `dead_contract` can never produce an auth entry.
4. Alice's collateral is permanently frozen; only a third-party liquidation can move it, and not to her.

#[contractimpl]
impl PositionNft {
    /// `controller` is the only address allowed to mint, burn and upgrade. Consumes
    /// token id 0 so the first position is id 1 — the controller ABI reserves
    /// account id 0 as the "create new account" sentinel.
    pub fn __constructor(e: &Env, controller: Address, uri: String, name: String, symbol: String) {
        e.storage()
            .instance()
            .set(&DataKey::Controller, &controller);
        Base::set_metadata(e, uri, name, symbol);
        sequential::increment_token_id(e, 1);
    }

    /// Mints the next sequential position token to `to`. Controller-only.
    ///
    /// Renews the instance TTL (controller address, collection metadata and
    /// id counter) on every account creation (INV-STOR-02a).
    pub fn mint(e: &Env, to: Address) -> u32 {
        controller(e).require_auth();
        renew_instance(e);
        let token_id = Enumerable::sequential_mint(e, &to);
        // sequential_mint writes Owner/Balance at the network minimum TTL; lift
        // them to the user window so a new position does not archive early.
        extend_user_persistent_ttl(e, &to, token_id);
        token_id
    }

    /// Burns `token_id` without the holder's authorization. Controller-only.
    ///
    /// Not the OZ `Burnable` extension: `Base::burn` calls
    /// `from.require_auth()`, and the controller must burn when liquidation
    /// empties an account without the owner's signature. This replicates
    /// `Enumerable::burn` (v0.7.1) without that auth: `Base::update` removes the
    /// owner and approval and decrements the holder's balance. The enumeration
    /// helper updates owner enumeration, total supply and global enumeration.
    ///
    /// Renews the instance TTL on every account deletion.
    pub fn burn(e: &Env, token_id: u32) {
        controller(e).require_auth();
        renew_instance(e);
        let owner = Base::owner_of(e, token_id);
        Base::update(e, Some(&owner), None, token_id);
        emit_burn(e, &owner, token_id);
        Enumerable::remove_from_enumerations(e, &owner, token_id);
    }

    /// Extends the TTL of `token_id`'s persistent `Owner` entry and its owner's
    /// `Balance` entry to the protocol's per-user renewal window, plus the
    /// instance TTL.
    /// Permissionless: a TTL extension cannot move, approve or reassign the
    /// token, and it cannot shorten a lifetime.
    ///
    /// OZ `owner_of` extends `Owner` to only 30 days. The controller calls this
    /// from `renew_account`, so account renewal keeps ownership alive for the
    /// same 120-day window as the account entries (INV-STOR-02b).
    ///
    /// Panics with the OZ `NonExistentToken` error when the token was never
    /// minted or was burned.
    pub fn renew(e: &Env, token_id: u32) {
        // Existence check first: extend_ttl on a missing key would trap with
        // a storage error; owner_of gives the standard token error instead.
        let owner = Base::owner_of(e, token_id);
        extend_user_persistent_ttl(e, &owner, token_id);
        renew_instance(e);
    }

    /// Upgrades the contract WASM to `new_wasm_hash`, extending the instance
    /// TTL first. Controller-only: the only path is the controller's owner-only
    /// `upgrade_position_nft`, behind the governance timelock.
    pub fn upgrade(e: &Env, new_wasm_hash: BytesN<32>) {
        controller(e).require_auth();
        renew_instance(e);
        upgradeable::upgrade(e, &new_wasm_hash);
    }
}
