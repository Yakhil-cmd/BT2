### Title
`GitHubApp#verify_webhook_signature` unconditionally accepts webhooks for any org without a configured `webhook_secret` - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` returns `true` without performing any HMAC comparison whenever the resolved organization's `webhook_secret` is nil/blank. Since `Shipit::WebhooksController#verify_signature` selects which `GitHubApp` instance to check against purely from attacker-controlled payload data (`repository.owner.login`), any org configured without a `webhook_secret` becomes fully open to forged webhooks for stacks under that org.

### Finding Description
The broken binding: `verified == HMAC-SHA1(webhook_secret, raw_body) matches X-Hub-Signature` is expected to hold for every accepted webhook, but for orgs with no `webhook_secret` configured, `verified` is set to `true` unconditionally, with no dependency on `raw_body` or `X-Hub-Signature` at all.

Code path:
1. `Shipit::WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner)`, where `repository_owner` is read straight from the untrusted JSON body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [1](#0-0) [2](#0-1) 
2. `Shipit.github(organization:)` resolves the matching `GitHubApp` from `secrets.github` config for that org and instantiates/caches a `GitHubApp` for it. [3](#0-2) 
3. `GitHubApp#initialize` sets `@webhook_secret = @config[:webhook_secret].presence`, which is `nil` when the org's config has no secret (e.g. `webhook_secret:` with no value). [4](#0-3) 
4. `verify_webhook_signature` short-circuits: `return true unless webhook_secret` — no comparison of `signature` or `message` (`request.raw_post`) ever happens. [5](#0-4) 
5. Back in the controller, `verified` is `true`, so the request is processed by `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` — e.g. a forged `push` event triggers `GithubSyncJob` for a real, tracked stack under that org. [6](#0-5) 

Existing guards don't stop this: `drop_unhandled_event` only filters by event type, not authenticity; `check_if_ping` is irrelevant; the `GithubOrganizationUnknown` rescue only fires when the org key doesn't exist in config at all, not when it exists with a blank secret. There is no code path that rejects or warns about an org configured without a `webhook_secret`.

Attack: attacker POSTs to `/webhooks` with `X-Github-Event: push` and a body where `repository.owner.login` is an org configured in `secrets.github` with no `webhook_secret` (this is exactly the sample provided in `config/secrets.development.shopify.yml`, which ships `webhook_secret:` blank for `somegithuborg`/`someothergithuborg`), and `repository.full_name` pointing at a real stack tracked under that org. `X-Hub-Signature` can be any garbage value or omitted; `verify_webhook_signature` never inspects it when `webhook_secret` is blank.

### Impact Explanation
Any org whose config omits `webhook_secret` allows unauthenticated, forged webhook events to be processed as if they came from GitHub. For `push` events this queues `GithubSyncJob` with attacker-chosen `expected_head_sha`/branch data against a real stack; for `status`/`check_suite`/`membership` events it can create commit statuses, trigger check-run refreshes, or manipulate team membership — all for a repository/stack the attacker does not control or own. This is a webhook authentication bypass, repeatable against every stack under any org lacking a secret, and the blast radius spans all repositories/stacks configured under that org (multi-tenant if multiple orgs share the Shipit instance).

### Likelihood Explanation
Precondition: a Shipit deployment must have at least one org entry in `Shipit.github`/`secrets.github` with `webhook_secret` blank or absent, while still having a real, tracked stack under that org. This is an operator configuration state, not a code bug requiring a secret — the shipped example config (`config/secrets.development.shopify.yml`) demonstrates this is a plausible/expected configuration shape (webhook_secret intentionally left blank), and no part of the engine validates that `webhook_secret` is present before trusting an org's webhooks. Attacker cost is a single unauthenticated HTTP POST with no secrets required, fully repeatable.

### Recommendation
Do not treat a missing `webhook_secret` as "verification passes." Either (a) require `webhook_secret` to be present for every configured org at boot/config-validation time and refuse to start / disable webhook processing for orgs without one, or (b) change `verify_webhook_signature` to return `false` (reject) when `webhook_secret` is blank instead of `true`, only allowing an explicit, clearly-named "unsafe/disabled verification" opt-in (e.g. via a distinct config flag) rather than silent bypass on blank secret.

### Proof of Concept
Minitest plan (no live GitHub needed):
```ruby
test "verify_webhook_signature does not bypass verification when webhook_secret is blank" do
  app = Shipit::GitHubApp.new('org', {}) # no webhook_secret configured

  # Binding under test: verified == valid HMAC comparison of signature/message.
  # Expected (secure) side: false, since 'garbage' is not a valid signature over 'garbage'.
  # Actual side observed:
  assert_equal false, app.verify_webhook_signature('garbage', 'garbage')
end

test "controller rejects forged push webhook for org with no webhook_secret" do
  Shipit.stubs(:github).with(organization: 'somegithuborg').returns(
    Shipit::GitHubApp.new('somegithuborg', { webhook_secret: nil })
  )

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=garbage'

  payload = JSON.parse(payload(:push_master))
  payload['repository']['owner']['login'] = 'somegithuborg'
  payload['repository']['full_name'] = shipit_stacks(:shipit).github_repo_name

  assert_no_enqueued_jobs do
    post :create, body: payload.to_json, as: :json
  end
  assert_response :unprocessable_entity
end
```
Currently both assertions fail (first returns `true`, second enqueues the job / returns `:ok`), demonstrating the bypass.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
