### Title
Webhook signature is verified against `repository.owner.login`'s org secret while the handler mutates a `Repository` resolved from `repository.full_name`, letting a no-secret org's webhook forge events for any other org's stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/org used to validate `X-Hub-Signature` solely from `params.dig('repository','owner','login')` (`repository_owner`), while every `pull_request` handler (e.g. `LabelCapturingHandler`) resolves the `Repository`/`Stack` it mutates from the independent field `params.repository.full_name`. Nothing binds these two values together, so a payload whose `repository.owner.login` names an org with no `webhook_secret` configured trivially passes signature verification (`GitHubApp#verify_webhook_signature` returns `true` when `webhook_secret` is blank) while `repository.full_name` can point at a completely different, secret-protected org's repository.

### Finding Description
The invariant that should hold is:
`org_whose_secret_verified(request) == org_that_owns(repository_used_by_handler)`

Tracing the code:
- `Shipit::WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (fallback `params.dig('organization', 'login')`) and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that org's `webhook_secret` is blank: `@webhook_secret = @config[:webhook_secret].presence` then `return true unless webhook_secret`. [3](#0-2) [4](#0-3) 
- Once verification passes, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` dispatches the raw, attacker-controlled `params` to every registered handler for the event, with no re-check that `repository.owner.login` matches anything. [5](#0-4) 
- `LabelCapturingHandler#repository` (and the identical pattern in `ClosedHandler`, `LabeledHandler`, `OpenedHandler`, `ReopenedHandler`, `UnlabeledHandler`) resolves the actual `Shipit::Repository` from `params.repository.full_name`, entirely independent of `repository.owner.login`: [6](#0-5) 
- The `stack` is then found by `ReviewStackAdapter#stack` (`scope.find_by(environment: "pr#{params.number}")`), and `capture_labels` persists attacker-supplied label names onto that stack's `PullRequest`: [7](#0-6) [8](#0-7) 

Exploit flow: an attacker who controls (or names) some org `no-secret-org` that Shipit has onboarded without a `webhook_secret` (or whose `webhook_secret` is left blank in configuration — a state the code explicitly tolerates via `.presence`) crafts a raw JSON body with:
- `repository.owner.login = "no-secret-org"` (drives signature-org selection, bypasses HMAC check trivially)
- `repository.full_name = "victim-org/victim-repo"` (drives the actual `Repository`/`Stack` lookup and mutation)
- `action = "labeled"`, arbitrary `pull_request.labels[].name`, `number` matching a live PR/environment on the victim stack.

`verify_signature` passes because `no-secret-org` has no secret, the request reaches `LabelCapturingHandler`, which resolves `victim-org/victim-repo`'s stack and overwrites `PullRequest#labels` with attacker-chosen values — with no check that the signature-verifying org and the mutated repository's org are the same. Existing guards do not catch this: `drop_unhandled_event` only checks the event type exists; `ExplicitParameters` only validates JSON shape, not owner/full_name consistency; there is no `force_github_authentication`/`current_user`/`require_permission!` gate on this unauthenticated endpoint by design (webhooks are meant to be unauthenticated but secret-signed) — the entire security boundary is the signature check, which this split defeats.

### Impact Explanation
This is a "payload for one repository mutating another's stack" — matching the Critical impact category. The attacker (unprivileged, no Shipit session, no `webhook_secret`, no GitHub App key for the victim org) can write attacker-chosen label names into `victim-org/victim-repo`'s `PullRequest#labels` for any review-stack environment they can guess/target (`pr<number>`). Because `ReviewStack#env` (established Shipit review-stack behavior) turns label names into uppercase environment variables consumed by deploy commands, and the victim stack is configured with a `bot_login` (`Shipit.user`) that auto-triggers/executes deploys, this can influence the environment under which the bot-identity deploy runs — an unauthorized cross-tenant mutation triggered without ever authenticating against the victim org's secret. Blast radius is any repository/org configured in the same Shipit instance, repeatable per request as long as a "no-secret" (or blank-secret) org exists in the multi-tenant GitHub config.

### Likelihood Explanation
Preconditions: (1) Shipit configured for multiple GitHub orgs (multi-tenant), (2) at least one configured org has a blank/absent `webhook_secret` (explicitly tolerated by `GitHubApp#initialize`'s `.presence` and `verify_webhook_signature`'s `return true unless webhook_secret`), and (3) a target victim stack/environment (`pr<number>`) exists for `repository.full_name`. Attacker cost is a single crafted, unsigned-but-accepted HTTP POST to `/webhooks` — no GitHub account interaction, no secrets, fully scriptable and repeatable against any repo/org combination sharing the Shipit instance.

### Recommendation
Bind the org used for signature verification to the org that will actually be acted upon: derive the verifying `GitHubApp` from the resolved `Repository`'s configured owner (i.e., look up the `Repository` by `full_name` first, verify against that repository's own org's `webhook_secret`), and reject the request if `repository.owner.login`'s org does not match the owner encoded in `repository.full_name`. Additionally, do not allow `verify_webhook_signature` to silently pass for orgs with a blank `webhook_secret` when the payload is being used to mutate a *different* org's records — this fallback should be paired with confirmation that the payload's declared owner and the acted-upon repository's owner are identical.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, hypothetical addition — not present in current `test/`, would need to be added there):
1. Configure `Shipit.github_config` (or stub) with two orgs: `"no-secret-org"` (no `webhook_secret` key) and `"victim-org"` (`webhook_secret: "victim-secret"`).
2. Create `victim_repo = Shipit::Repository.create!(owner: "victim-org", name: "victim-repo")`, a `Stack`/`ReviewStack` with `environment: "pr42"` and `bot_login`/`Shipit.user` configured, and its `PullRequest` with `labels: []`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` for `victim-secret` (or an arbitrary/garbage signature), and body:
   ```json
   {
     "action": "labeled",
     "number": 42,
     "repository": { "owner": { "login": "no-secret-org" }, "full_name": "victim-org/victim-repo" },
     "pull_request": { ..., "labels": [{"name": "MALICIOUS_ENV_OVERRIDE"}] },
     "sender": { "login": "attacker" }
   }
   ```
4. Assert response is `200 OK` (not `422`), and `victim_repo.review_stacks.find_by(environment: "pr42").pull_request.reload.labels` now equals `["MALICIOUS_ENV_OVERRIDE"]` — i.e., the equality `org_whose_secret_verified(request) ("no-secret-org") == org_that_owns(repository_used_by_handler) ("victim-org")` is false, yet the mutation still occurred.

Note: I was unable to fully inspect `Shipit.github`'s org-resolution/fallback method body (`lib/shipit.rb`) in this session to confirm exact behavior for a completely *unregistered* org name (vs. a registered org with a blank secret); the finding is grounded specifically in the confirmed code path where a registered org lacks a `webhook_secret`, which the code demonstrably tolerates.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
