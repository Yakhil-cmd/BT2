### Title
Unchecked Negative `reward.mintingamount` Governance Vote Causes Permanent Chain Halt via `FinalizeState` Failure — (`kaiax/gov/param.go`, `kaiax/reward/impl/blockstate.go`)

---

### Summary

The `RewardMintingAmount` governance parameter uses `noopFormatChecker` (always returns `true`) instead of the non-negativity guard applied to every other `*big.Int` governance parameter. A governance vote setting `reward.mintingamount` to a negative value is accepted, ratified, and persisted. Starting from the next epoch, every block's `FinalizeState` computes negative reward amounts, `spec.Validate()` returns `ErrNegativeRewardAmount`, and block finalization fails on all honest nodes — a permanent chain halt.

---

### Finding Description

**Root cause — missing sign check on `RewardMintingAmount`:**

`RewardMinimumStake` and `RewardStakingRewardThreshold` both guard against negative values:

```go
// kaiax/gov/param.go:425-433
RewardMinimumStake: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok { return false }
        return v.Sign() >= 0   // ← sign guard present
    },
```

`RewardMintingAmount` uses `noopFormatChecker` — no sign guard at all:

```go
// kaiax/gov/param.go:414-424
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // ← always returns true
    ...
    DefaultValue: big.NewInt(0),
},
```

`bigIntCanonicalizer` accepts any `*big.Int` or any string parseable by `new(big.Int).SetString(v, 10)`, including `"-9600000000000000000"`. The consistency check in `checkConsistency` explicitly passes `RewardMintingAmount` through with `return nil` and no further validation:

```go
// kaiax/gov/headergov/impl/header.go:205-211
case gov.GovernanceDeriveShaImpl, ..., gov.RewardMintingAmount, ...:
    return nil
```

**Downstream failure path:**

After the negative value is ratified and takes effect, `FinalizeState` calls `GetDeferredReward` → `getDeferredRewardFullKore` (or `Flex`/`Simple`):

```go
// kaiax/reward/impl/getter.go:303
minted = new(big.Int).Set(config.MintingAmount)  // negative
```

`RewardRatio.Split(minted)` and `Kip82Ratio.Split(validators)` produce negative `proposer`, `stakers`, `kif`, `kef` values. These are written into `spec.Rewards`:

```go
// kaiax/reward/impl/getter.go:356-357
proposer.Add(proposer, distributableFee)  // still negative if |minted| >> fees
spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
```

`FinalizeState` then calls `spec.Validate()`:

```go
// kaiax/reward/spec.go:118-124
func (spec *RewardSpec) Validate() error {
    for addr, amount := range spec.Rewards {
        if amount.Sign() < 0 {
            return errNegativeRewardAmount(addr, amount)
        }
    }
    return nil
}
```

This returns `ErrNegativeRewardAmount`, which propagates out of `FinalizeState`:

```go
// kaiax/reward/impl/blockstate.go:50-52
if err := spec.Validate(); err != nil {
    return err
}
```

Block finalization fails on every honest node for every block in the affected epoch.

---

### Impact Explanation

**Invalid state transition / consensus divergence on honest nodes.** Once the negative `MintingAmount` takes effect, no block can be finalized. `FinalizeState` is called during block processing; its error return prevents the block from being committed to the chain. All honest nodes halt at the same block height. This is a permanent chain halt unless a governance vote reverting the parameter is somehow included — which is impossible if no blocks can be finalized.

The corrupted value is the `spec.Rewards` map entry for the proposer/staker/fund addresses, which receives a negative KAIA amount, violating the invariant that reward amounts are non-negative.

---

### Likelihood Explanation

**Trigger requires governance authority:**

- In `single` governance mode (Kaia Mainnet, Kairos): only the `governance.governingnode` can cast the vote. This is a privileged actor.
- In `none` governance mode (the `DefaultValue` for `GovernanceGovernanceMode`): any GC member can cast the vote. The last vote in the epoch wins. This is a semi-trusted actor.

The `none` mode is the default and applies to any chain that does not explicitly configure `single` mode. In that setting, any validator who is a GC member can cast `governance_vote("reward.mintingamount", "-9600000000000000000")`, and it will be ratified at the next epoch block with no further checks.

The attack requires no special tooling: the `governance_vote` RPC API is the standard interface.

---

### Recommendation

Add a non-negativity `FormatChecker` to `RewardMintingAmount`, consistent with `RewardMinimumStake` and `RewardStakingRewardThreshold`:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(*big.Int)
        if !ok {
            return false
        }
        return v.Sign() >= 0  // reject negative minting amounts
    },
    ...
},
```

---

### Proof of Concept

1. On a chain with `governance.governancemode = "none"` (the default), a GC member calls:
   ```
   governance_vote("reward.mintingamount", "-9600000000000000000")
   ```
2. The vote passes `bigIntCanonicalizer` (parses `"-9600000000000000000"` as a valid `*big.Int`) and `noopFormatChecker` (always `true`). It is inscribed in `header.Vote`.
3. At the next epoch block, the vote is ratified and written to `header.Governance`. The negative value is stored in the governance DB.
4. Starting from `(k+1)*epoch`, `GetParamSet` returns `MintingAmount = -9.6e18`.
5. For every block in the new epoch, `FinalizeState` calls `getDeferredRewardFullKore`:
   - `minted = -9.6e18`
   - `validators = minted * 50/100 = -4.8e18`
   - `proposer = validators * 20/100 = -0.96e18`
   - `spec.Rewards[proposer_addr] = -0.96e18`
6. `spec.Validate()` returns `ErrNegativeRewardAmount`.
7. `FinalizeState` returns the error. Block finalization fails on all honest nodes. **Chain halts.** [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7)

// getDeferredRewardFullKore is for non-Simple policy and after Kore.
func getDeferredRewardFullKore(config *reward.RewardConfig, execFee, burntFee, blobFee *big.Int, si *staking.StakingInfo) (*reward.RewardSpec, error) {
	var (
		spec             = reward.NewRewardSpec()
		minted           = new(big.Int).Set(config.MintingAmount)
		distributableFee = new(big.Int).Sub(execFee, burntFee)
	)

	// Distribute using RewardRatio first. Unlike Legacy, fees are not distributed here
	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.
	validators, kif, kef := config.RewardRatio.Split(minted)
	proposer, stakers := config.Kip82Ratio.Split(validators)
	ratioRemainder := calcRemainder(minted, proposer, stakers, kif, kef)
	kif.Add(kif, ratioRemainder)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.
	// After Prague, if the CLStaking is not nil, the proposer and staking rewards are proportionally distributed to both CN and CL.
	// For proposer rewards, see `specWithProposerAndFunds`.
	stakersAlloc, kip82Remainder := assignStakingRewards(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)
	stakers.Sub(stakers, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}
	spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
	return spec, nil
}
