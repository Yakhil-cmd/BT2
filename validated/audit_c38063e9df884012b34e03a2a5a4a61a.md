### Title
Potential residual "NonTransfer" proxy deny-list bypass in `staking-async` parachain runtime — ([File: substrate/frame/staking-async/runtimes/parachain/src/lib.rs])

### Summary
The MinIO CVE-2021-21362 root cause is a policy-enforcement bypass: a readOnly policy was checked on one code path (presigned URLs) but not on an equivalent alternate path (`mc share upload` / multipart form uploads), so the same operation reachable through a different entry point skipped the check. The closest verified analog in this codebase is the `ProxyType::NonTransfer` `InstanceFilter` implementation across multiple runtimes, which is implemented as a **deny-list** rather than an allow-list, so it "fails open": any call family not explicitly named is permitted, even though the type is documented as "any call that does not transfer funds or assets."

### Finding Description
This exact bug class was already found and fixed for `asset-hub-westend-runtime`: `ProxyType::NonTransfer` omitted `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer` from its deny-list, letting a delegate holding a supposedly value-restricted `NonTransfer` proxy move the delegator's funds via these alternate, "equivalent" call paths [1](#0-0) . The fix, tracked in `prdoc/pr_12771.prdoc`, explicitly denies all of these families [2](#0-1) .

A sibling runtime, `pallet-staking-async-parachain-runtime`, has the identical deny-list architecture and received only a partial fix: `prdoc/pr_12922.prdoc` states the fix denies **only** `ForeignAssets` and `PoolAssets` transfers, mirroring just one slice of the asset-hub-westend fix [3](#0-2) . The accompanying regression test in this runtime, `non_transfer_proxy_denies_other_asset_instances`, only asserts against `ForeignAssets::transfer` and `PoolAssets::transfer` [4](#0-3)  — it does not assert anything about `AssetConversion`, `PolkadotXcm`, or `Revive`-style value-moving calls, which is exactly the set of "equivalent alternate paths" that had to be added for asset-hub-westend.

Confirmed from the runtime's own API implementations, this parachain runtime does wire up `pallet_asset_conversion::AssetConversionApi` (backed by an `AssetConversion` pallet with swap/liquidity calls) and `PolkadotXcm` (used for `XcmPaymentApi`/`DryRunApi`, implying the `PolkadotXcm` pallet with `transfer_assets`/`teleport_assets`/`send`/`execute` is present in `construct_runtime!`) [5](#0-4) . If the `ProxyType::NonTransfer` match arms in this file were not updated (beyond the `ForeignAssets`/`PoolAssets` fix) to also deny `AssetConversion` swaps, `PolkadotXcm` asset-moving calls, and any `Revive`-style value-carrying calls, the same class of bypass documented for asset-hub-westend (issue #12466 / PR #12771) would remain live here: a `NonTransfer` delegate could move the delegator's assets by calling `AssetConversion::swap_exact_tokens_for_tokens` (sending proceeds to an attacker-chosen `send_to`) or `PolkadotXcm::transfer_assets`/`teleport_assets` instead of the denied `Balances`/`Assets` transfer calls — an "equivalent wrapped path" exactly analogous to MinIO's alternate multipart-upload route bypassing the same policy check enforced elsewhere.

### Impact Explanation
If unaddressed, this would let a delegate account holding only a `NonTransfer` proxy (or a pure `NonTransfer` proxy explicitly created by a delegator to restrict fund movement) directly steal or redirect the delegator's tokens via asset-conversion swaps or XCM asset transfers — the exact violated invariant the `NonTransfer` documentation promises against. This is a direct theft-of-funds primitive (High severity class), matching the criteria for FRAME proxy/origin-filter bugs called out in the assessment method.

### Likelihood Explanation
Reachability requires only that a delegator has granted a `NonTransfer` proxy to some account (a normal, unprivileged, permitted configuration — no governance or validator access needed) and that the delegate account calls `Proxy::proxy` with the underlying `AssetConversion`/`PolkadotXcm` call. This is a standard signed-extrinsic flow with ordinary transaction fees, no special preconditions.

### Recommendation
Audit `substrate/frame/staking-async/runtimes/parachain/src/lib.rs`'s `impl InstanceFilter<RuntimeCall> for ProxyType` (and the analogous `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, which shares the same proxy-type pattern) and apply the same denial set already merged for `asset-hub-westend-runtime` in `prdoc/pr_12771.prdoc` — explicitly deny `AssetConversion`, any `Psm`-equivalent pallet, `PolkadotXcm` asset-moving calls, `Revive`/contracts calls carrying `value`, and `Indices::transfer`/`force_transfer` — rather than relying on a deny-list that must be manually kept in sync with every pallet added to the runtime. Consider switching to an allow-list architecture for `NonTransfer` to prevent recurrence of this exact bug class.

### Proof of Concept
**Verified evidence:** `prdoc/pr_12922.prdoc` text confirms the `staking-async` parachain fix covered only `ForeignAssets`/`PoolAssets`, unlike the more complete `asset-hub-westend` fix in `prdoc/pr_12771.prdoc`; the runtime's own API impls confirm `AssetConversion` and `PolkadotXcm` pallets are present in this runtime.

**Unverified/uncertain (tool access exhausted):** I was unable to retrieve the exact current `match` arms of `impl InstanceFilter<RuntimeCall> for ProxyType` in `substrate/frame/staking-async/runtimes/parachain/src/lib.rs` (repeated `read_file`/`grep_search` calls on this file returned mismatched/stale content instead of the filter body), so I cannot cite the exact file:line proof that `AssetConversion`/`PolkadotXcm`/`Revive` calls are still admitted by `NonTransfer` in this file today, nor produce a concrete dispatch-level PoC trace. No test was executed; no local reproduction was run.

Given this gap in direct evidence, this should be treated as a **strong, well-supported lead requiring a background agent (or direct file read) to confirm the current filter contents** before filing as a confirmed finding — not as a fully proven vulnerability.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}

#[test]
fn non_transfer_proxy_denies_other_asset_instances() {
	use frame_support::traits::InstanceFilter;

	// `ForeignAssets` (Instance2) and `PoolAssets` (Instance3) move fungibles just like
	// `Assets` (Instance1) does, so a `NonTransfer` proxy must not be able to call them.
	let foreign_assets_transfer = RuntimeCall::ForeignAssets(pallet_assets::Call::<
		Runtime,
		ForeignAssetsInstance,
	>::transfer {
		id: xcm::v5::Location::parent(),
		target: sp_runtime::MultiAddress::Id(AccountId::from([0u8; 32])),
		amount: 1,
	});
	assert!(
		!ProxyType::NonTransfer.filter(&foreign_assets_transfer),
		"NonTransfer must deny ForeignAssets transfers",
	);

	let pool_assets_transfer =
		RuntimeCall::PoolAssets(pallet_assets::Call::<Runtime, PoolAssetsInstance>::transfer {
			id: 1,
			target: sp_runtime::MultiAddress::Id(AccountId::from([0u8; 32])),
			amount: 1,
		});
	assert!(
		!ProxyType::NonTransfer.filter(&pool_assets_transfer),
		"NonTransfer must deny PoolAssets transfers",
	);
}
