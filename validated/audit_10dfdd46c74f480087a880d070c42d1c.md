### Title
Sybil-splitting one staker's locked STX across multiple `signer_key`/`signer-manager` identities wins extra Hare-round leftover slots in `pox_5_make_signer_set` - ([File: stackslib/src/chainstate/nakamoto/signer_set.rs])

### Summary
`pox_5_make_signer_set` aggregates stake purely by `signer_key` (a per-`signer-manager`-contract identity), never by the underlying staking principal, so a single staker who deploys two `signer-manager` contracts and splits one real STX position into two `stake` calls to two different signers gets two independent "tickets" in the largest-remainder Hare round instead of one. For low-competition network states this lets the same locked STX win two leftover slots where an unsplit position could win at most one.

### Finding Description
The claimed equality is: total signing weight granted, for a fixed amount of real locked STX and a fixed set of *other* competing signers, must be independent of whether that STX is represented as one `RawPox5Entry` or split across `k` entries with distinct `signer_key`s. `RawPox5Entry` only carries `(signer_key, amount_ustx)` [1](#0-0) ; it never records which Stacks principal originated the stake, so `pox_5_make_signer_set`'s `HashMap<signer_key, amount_ustx>` aggregation step [2](#0-1)  can never merge two entries backed by the same staker but different `signer_key`s.

The apportionment computes `weight = floor(stacked_amt/threshold)` per key, then hands out `reward_slots - sum(floor)` leftover slots one-per-key in descending-remainder order [3](#0-2) . Because `floor(a/t) + floor(b/t) <= floor((a+b)/t)`, splitting a position can only ever *lose* base weight, never gain it — but the Hare round grants **one bonus slot per surviving entry**, so `k` entries have `k` independent chances at the leftover pool while a merged entry has only 1. When the staker's true total is below `threshold` (so `base=0` either way, no loss from splitting) and the network's other competing remainders leave at least 2 leftover slots reachable, splitting into 2 entries can capture 2 leftover slots (weight=2) in exactly the same global state where the single merged entry would have captured only 1 (weight=1) — the property test's own per-entry bound `weight ∈ {base, base+1}` (`stackslib/src/chainstate/nakamoto/tests/signer_set.rs:141-159`) is respected per-entry but the *sum across the sybil's entries* is not bounded by the merged entry's `base+1` cap.

Attacker path: deploy two `signer-manager` contracts, `grant-signer-key` + `register-self`/`register-signer` for two distinct `signer_key`s [4](#0-3)  (no privileged role required — the attacker is the admin of contracts they themselves deployed), then call `stake` twice from the same or attacker-controlled principals, once per `signer-manager`, splitting the real STX total [5](#0-4) . Nothing in `stake`, `verify-signer-key-grant`, `verify-not-prepare-phase`, or `signer-manager-validate-stake` checks whether the same underlying STX/principal is already represented under another `signer_key` — those guards protect reentrancy and grant-forgery, not cross-identity stake fragmentation. `pox_5_stake_entries` walks the per-cycle linked list purely by `signer` principal (the signer-manager contract), independent of staker identity [6](#0-5) , so the two entries reach `pox_5_make_signer_set` as fully independent signer identities.

### Impact Explanation
The attacker's controlled `signer_key`s receive combined signing weight/reward-slot count exceeding what floor(their real locked STX / threshold) + one Hare bonus would give a single unsplit position, for the identical amount of locked STX and identical competing network state. This is a direct instance of the defined High-severity category "signing weight or reward slots exceeding locked value": the attacker gains disproportionate block-signing weight and (since weight typically drives reward-slot share) a larger cut of block rewards than their real stake entitles them to, at the expense of the honest signers who would otherwise have won those leftover slots. The attack is repeatable every reward cycle and scales with the number of `signer-manager` contracts the attacker is willing to deploy (more splits ⇒ more Hare "tickets"), subject to diminishing returns from lost base weight once individual pieces are large enough to have nonzero floor.

### Likelihood Explanation
Preconditions are cheap and fully within an unprivileged attacker's control: deploy N `signer-manager` contracts (Clarity contract-deploy cost only), self-sign N `grant-signer-key`/`register-self` calls, and issue N `stake` calls splitting one's own already-owned STX. The gain is maximized when the attacker's own stake is small relative to `threshold` (so splitting costs no base weight) and when the network has few enough other high-remainder competitors that multiple leftover slots are reachable by the same actor — a realistic condition in early/low-participation PoX-5 cycles, which is exactly the scenario the Hare round comment says it was added to handle. No cycle-phase or membership-state guard in `pox-5.clar` (`verify-not-prepare-phase`, `validate-no-reentrancy`, `check-pox-lock-period`, `verify-signer-key-grant`) addresses cross-identity aggregation, since none of them are staker-identity-aware.

### Recommendation
Track and aggregate by the underlying staking principal (or require the largest-remainder round to allocate at most one leftover slot per distinct principal, not per distinct `signer_key`), or change `RawPox5Entry`/`pox_5_stake_entries` to also aggregate multiple `signer_key`s controlled by provably the same principal before running the Hare round. At minimum, cap the number of Hare bonus slots any single principal's aggregate positions can win to 1, matching the merged-entry bound already enforced per-entry in the property test.

### Proof of Concept
Extend `check_make_signer_set`/`pox_5_make_signer_set_props` (`stackslib/src/chainstate/nakamoto/tests/signer_set.rs:83-176`) with a dedicated unit test:
1. Fix `pox_constants` so `threshold` is large (e.g. `test_pox_constants` giving `reward_slots=2`, `threshold` derived from total network stake).
2. Construct a network with a few "other" entries whose remainders leave exactly 2 leftover slots reachable.
3. Case A (merged): one `RawPox5Entry{signer_key: K, amount_ustx: T}` with `T < threshold`. Run `pox_5_make_signer_set`; record `weight_A = ` entry's weight (expect ≤ `base+1 = 1`).
4. Case B (split): two `RawPox5Entry`s `{signer_key: K1, amount: T1}`, `{signer_key: K2, amount: T2}` with `T1+T2=T`, `T1,T2 < threshold`, chosen so both remainders are large enough to win the Hare round. Run `pox_5_make_signer_set`; record `weight_B = weight(K1)+weight(K2)` (expect `2`).
5. Assert `weight_B > weight_A` for identical total locked STX `T` and identical "other" competing entries, demonstrating the equality "weight granted == f(real locked STX)" is broken by identity-splitting.

/// `RawPox5Entry` per registered signer for the cycle.
pub struct StakeEntryIteratorPox5<'a, 'b, 'c> {
    current_signer: Option<PrincipalData>,
    pox_contract: QualifiedContractIdentifier,
    clarity: &'a mut ClarityTransactionConnection<'b, 'c>,
    reward_cycle_clar: SymbolicExpression,
}

#[derive(Debug)]
pub enum PoxEntryParsingError {
    /// Errors for which PoX set calculation should continue, but skip
    ///  the offending entry.
    Skip(String),
    /// Errors for which PoX set calculation should abort.
    Abort(String),
}

impl<'a, 'b, 'c> StakeEntryIteratorPox5<'a, 'b, 'c> {
    fn fallible_next(&mut self) -> Result<Option<RawPox5Entry>, PoxEntryParsingError> {
        let Some(cur_signer) = self.current_signer.take() else {
            return Ok(None);
        };

        let lookup_signer = SymbolicExpression::atom_value(Value::Principal(cur_signer.clone()));

        // Advance the linked list before any per-entry lookups: a malformed
        // entry skips this iteration but must not stall the iterator.
        let next_signer = self
            .clarity
            .eval_method_read_only(
                &self.pox_contract,
                "get-signer-set-next-item-for-cycle",
                &[lookup_signer.clone(), self.reward_cycle_clar.clone()],
            )
            .map_err(|e| PoxEntryParsingError::Abort(e.to_string()))?
            .expect_optional()
            .map_err(|_| {
                PoxEntryParsingError::Abort(
                    "get-signer-set-next-item-for-cycle did not return optional".into(),
                )
            })?
            .map(|entry| entry.expect_principal())
            .transpose()
            .map_err(|_| {
                PoxEntryParsingError::Abort(
                    "get-signer-set-next-item-for-cycle did not return principal".into(),
                )
            })?;
        self.current_signer = next_signer;

        // Errors below this point skip the entry but continue iteration.

        // Signer key from `signers` map (written by register-signer).
        let signer_key_buff = self
            .clarity
            .eval_method_read_only(
                &self.pox_contract,
                "get-signer-info",
                &[lookup_signer.clone()],
            )
            .map_err(|e| PoxEntryParsingError::Skip(e.to_string()))?
            .expect_optional()
            .map_err(|_| {
                PoxEntryParsingError::Skip("get-signer-info did not return optional".into())
            })?
            .ok_or_else(|| {
                PoxEntryParsingError::Skip(format!(
                    "get-signer-info did not return Some: {cur_signer}"
                ))
            })?
            .expect_buff(SIGNERS_PK_LEN)
            .map_err(|_| {
                PoxEntryParsingError::Skip(format!(
                    "get-signer-info value should be (buff {SIGNERS_PK_LEN})"
                ))
            })?;

            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {

                stacked_amt,

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
