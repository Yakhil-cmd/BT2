## Finding

### Title
JIT liquidity sandwich attack allows extracting a disproportionate share of swap fees from long-term LPs — ([File: programs/cp-swap/src/instructions/deposit.rs], [File: programs/cp-swap/src/instructions/withdraw.rs], [File: programs/cp-swap/src/states/pool.rs])

### Summary
`deposit()` and `withdraw()` allow instant, penalty-free entry/exit of liquidity, and swap fees that are not routed to the protocol/fund/creator accrue directly into the pool vaults, instantly increasing the value of every outstanding LP share. This lets an attacker mint LP tokens immediately before a large swap and burn them immediately after, capturing a disproportionate share of the LP-side trade fee at the expense of the pool's existing liquidity providers — the same "yield sandwich" bug class described in the referenced report.

### Finding Description
When a swap executes, `CurveCalculator::swap_base_input`/`swap_base_output` compute `trade_fee`, from which `protocol_fee`, `fund_fee`, and `creator_fee` are carved out and tracked separately in `pool_state.protocol_fees_token_*`, `fund_fees_token_*`, and `creator_fees_token_*` via `update_fees()`. [1](#0-0) 

Those tracked fee balances are explicitly excluded from LP share value via `vault_amount_without_fee`, but the *remainder* of `trade_fee` (i.e. `trade_fee - protocol_fee - fund_fee - creator_fee`) is never removed from the vault — it stays in `input_vault`/`output_vault` and increases `total_token_0_amount`/`total_token_1_amount` used for LP share pricing. [2](#0-1) 

This uncollected fee portion is the LP yield: it instantly inflates the value of every LP token outstanding at the moment the swap lands, exactly analogous to `LiquidityReserve.totalLockedValue` increasing from the unstake fee in the referenced report.

`deposit()` mints LP tokens proportional to the *current* vault balances (via `lp_tokens_to_trading_tokens`), with no cooldown, vesting, or additional fee besides optional SPL Token-2022 transfer fees: [3](#0-2) [4](#0-3) 

`withdraw()` symmetrically burns LP tokens and returns the pro-rata share of vault balances, again instantly and without any lock-up or exit penalty: [5](#0-4) 

There is no mechanism (minimum holding period, deposit/withdraw fee, or delayed fee accrual) preventing an attacker from:
1. Depositing a large amount of liquidity right before an anticipated large swap (their own or a victim's), becoming the majority LP share holder.
2. Letting the swap execute — the LP-share-inflating portion of `trade_fee` is added to the vaults, increasing the value of all LP shares including the attacker's freshly minted ones.
3. Immediately withdrawing, capturing a share of that fee proportional to their (large, momentary) ownership percentage, at the expense of the pool's pre-existing LPs who are diluted out of the fee they would otherwise have fully earned.

### Impact Explanation
This directly transfers value away from long-term liquidity providers to a well-capitalized/flash-loan-funded attacker who can time deposit/withdraw around fee-generating swaps, with no cost beyond gas and any optional token transfer fee. Given no lock-up or exit fee exists, this can be repeated for every meaningfully-sized swap, systematically eroding the fee yield that should accrue to genuine LPs — an unbacked reallocation of pool yield, matching the "yield can be stolen" bug class from the source report.

### Likelihood Explanation
The attack is reachable by any unprivileged user through the public `deposit` and `withdraw` instructions with attacker-chosen amounts, requiring only capital (which can be flash-loaned since Solana supports same-transaction, multi-instruction atomic composition) and no privileged accounts or non-default features. Profitability scales with the size of the swap's fee and the attacker's capital relative to the pool's TVL, making it most attractive against larger swaps/pools — a realistic and repeatable MEV strategy rather than a theoretical edge case.

### Recommendation
- Introduce a minimum LP holding period (e.g., disallow `withdraw` for LP tokens minted in the same transaction/slot, or within N slots of the corresponding `deposit`).
- Add a small deposit or withdrawal fee that offsets the JIT extraction incentive.
- Accrue the LP-side fee portion gradually (e.g., via a time-weighted or epoch-based distribution) rather than instantaneously crediting it to the current vault balance used for share pricing.

### Proof of Concept
1. Attacker observes (or triggers) a large pending swap against a pool with `trade_fee_rate` configured in `AmmConfig`.
2. Attacker calls `deposit` with a large `lp_token_amount`, becoming a majority holder of `pool_state.lp_supply`. [6](#0-5) 
3. The swap executes via `swap_base_input`/`swap_base_output`, adding the LP-share portion of `trade_fee` into `input_vault`/`output_vault` balances (net of `update_fees`-tracked protocol/fund/creator cuts). [7](#0-6) 
4. Attacker immediately calls `withdraw` for the same `lp_token_amount`, receiving back their principal plus a pro-rata share of the newly accrued fee, extracted from what would otherwise accrue to pre-existing LPs. [8](#0-7)

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
        Ok(())
    }

pub fn deposit(
    ctx: Context<Deposit>,
    lp_token_amount: u64,
    maximum_token_0_amount: u64,
    maximum_token_1_amount: u64,

    require_gt!(lp_token_amount, 0);
    let pool_id = ctx.accounts.pool_state.key();
    let pool_state = &mut ctx.accounts.pool_state.load_mut()?;
    if !pool_state.get_status_by_bit(PoolStatusBitIndex::Deposit) {
        return err!(ErrorCode::NotApproved);
    }
    let (total_token_0_amount, total_token_1_amount) = pool_state.vault_amount_without_fee(
        ctx.accounts.token_0_vault.amount,
        ctx.accounts.token_1_vault.amount,
    )?;
    let results = CurveCalculator::lp_tokens_to_trading_tokens(
        u128::from(lp_token_amount),
        u128::from(pool_state.lp_supply),
        u128::from(total_token_0_amount),
        u128::from(total_token_1_amount),
        RoundDirection::Ceiling,
    )
    .ok_or(ErrorCode::ZeroTradingTokens)?;

        let transfer_fee =
            get_transfer_inverse_fee(&ctx.accounts.vault_0_mint.to_account_info(), token_0_amount)?;
        (
            token_0_amount.checked_add(transfer_fee).unwrap(),
            transfer_fee,
        )
    };

pub fn withdraw(
    ctx: Context<Withdraw>,
    lp_token_amount: u64,
    minimum_token_0_amount: u64,
    minimum_token_1_amount: u64,
) -> Result<()> {
    require_gt!(lp_token_amount, 0);
    require_gte!(ctx.accounts.owner_lp_token.amount, lp_token_amount);
    let pool_id = ctx.accounts.pool_state.key();
    let pool_state = &mut ctx.accounts.pool_state.load_mut()?;
    if !pool_state.get_status_by_bit(PoolStatusBitIndex::Withdraw) {
        return err!(ErrorCode::NotApproved);
    }
    let (total_token_0_amount, total_token_1_amount) = pool_state.vault_amount_without_fee(
        ctx.accounts.token_0_vault.amount,
        ctx.accounts.token_1_vault.amount,
    )?;
    let results = CurveCalculator::lp_tokens_to_trading_tokens(
        u128::from(lp_token_amount),
        u128::from(pool_state.lp_supply),
        u128::from(total_token_0_amount),
        u128::from(total_token_1_amount),
        RoundDirection::Floor,
    )
    .ok_or(ErrorCode::ZeroTradingTokens)?;
    if results.token_0_amount == 0 || results.token_1_amount == 0 {
        return err!(ErrorCode::ZeroTradingTokens);
    }
    let token_0_amount = u64::try_from(results.token_0_amount).unwrap();
    let token_0_amount = std::cmp::min(total_token_0_amount, token_0_amount);
    let (receive_token_0_amount, token_0_transfer_fee) = {
        let transfer_fee =
            get_transfer_fee(&ctx.accounts.vault_0_mint.to_account_info(), token_0_amount)?;
        (
            token_0_amount.checked_sub(transfer_fee).unwrap(),
            transfer_fee,
        )
    };

    let token_1_amount = u64::try_from(results.token_1_amount).unwrap();
    let token_1_amount = std::cmp::min(total_token_1_amount, token_1_amount);
    let (receive_token_1_amount, token_1_transfer_fee) = {
        let transfer_fee =
            get_transfer_fee(&ctx.accounts.vault_1_mint.to_account_info(), token_1_amount)?;
        (
            token_1_amount.checked_sub(transfer_fee).unwrap(),
            transfer_fee,
        )
    };
