### Title
Rewards accrued while a pool has zero stakers are permanently stranded in `pallet-asset-rewards` - ([File: substrate/frame/asset-rewards/src/lib.rs])

### Summary
`pallet-asset-rewards`'s reward-per-token accounting has the same structural flaw as the Y2K Finance `StakingRewards.sol` report: when a pool's `total_tokens_staked` is zero, the elapsed blocks during that period are silently dropped from the reward-per-token accumulator, and the corresponding reward-asset balance sitting in the pool account is never attributed to any staker, nor rolled forward for future distribution.

### Finding Description
`reward_per_token` returns the stored value unchanged whenever `total_tokens_staked` is zero, without accounting for the blocks that elapsed at that rate: [1](#0-0) 

Every mutating operation (`stake`, `unstake`, rate changes) calls `update_pool_and_staker_rewards` → `update_pool_rewards`, which unconditionally advances `last_update_block` to the current block: [2](#0-1) 

Because `last_update_block` is always fast-forwarded to "now" (regardless of whether `total_tokens_staked` was zero during the gap), any first staker who calls the permissionless, signed `stake` extrinsic after a period of zero stake causes the elapsed "zero-stake" window to be permanently excluded from `reward_per_token` computation: [3](#0-2) 

This mirrors the Y2K Finance bug exactly: `reward_rate_per_block` continues to run from pool creation (`last_update_block: 0` at creation) or from the last update, and the pool admin/creator is expected to keep the pool account "adequately funded with the reward asset" per the module docs: [4](#0-3) [5](#0-4) 

The reward asset that was already deposited/expected to cover the zero-stake window is never returned to the admin (there's no accounting of "unused" rewards), never rolled into the reward-per-token accumulator retroactively, and never redistributed to future stakers — it simply becomes unattributable, stuck balance in the pool's reward account, exactly as in the original finding ("stuck rewards are not considered so these ... rewards will remain in contract with no usage").

### Impact Explanation
This is a fund-attribution/accounting bug: reward-asset value that is economically meant for stakers (and funded by the pool admin under that assumption) becomes permanently unclaimable by anyone, while remaining locked in the pool's sub-account. Depending on `reward_rate_per_block` and pool_creation-to-first-stake latency, this can amount to significant reward-asset loss for the party funding the pool, though it does not represent a privilege escalation, unbacked issuance, or unauthorized dispatch — it is a value-freezing/accounting defect of Medium severity, matching the classification of the original report.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: any pool creator setting `reward_rate_per_block`/funding a pool before the first staker joins (a very common workflow — pools are typically created first, then discovered/staked into later) will trigger exactly this scenario. No privileged role or attacker action is required; a normal, permissionless `stake` call by any signed account after the gap is sufficient to "consume" (permanently skip) the unattributed period.

### Recommendation
When `total_tokens_staked` is zero in `reward_per_token`, either (a) do not advance `last_update_block` past the point where staking resumes so the zero-stake window is excluded from the *rate* accrual entirely and the funds are simply not owed to anyone but also not silently dropped by fast-forwarding, or (b) track and refund/roll over the reward amount corresponding to zero-stake blocks — e.g., accumulate an `unallocated_rewards` counter during zero-supply periods and let the admin withdraw or redirect it via `set_pool_reward_rate_per_block`/an explicit "sweep unused rewards" extrinsic, analogous to the C4 recommendation to mark `(block.timestamp - startTime) * rewardRate` as unused and reusable.

2. Advance the block number by N blocks with `total_tokens_staked == 0`.

		pub fn stake(origin: OriginFor<T>, pool_id: PoolId, amount: T::Balance) -> DispatchResult {
			let staker = ensure_signed(origin)?;

			// Always start by updating staker and pool rewards.
			let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
			let staker_info = PoolStakers::<T>::get(pool_id, &staker).unwrap_or_default();
			let (mut pool_info, mut staker_info) =
				Self::update_pool_and_staker_rewards(&pool_info, &staker_info)?;

			T::AssetsFreezer::increase_frozen(
				pool_info.staked_asset_id.clone(),
				&FreezeReason::Staked.into(),
				&staker,
				amount,
			)?;

			// Update Pools.
			pool_info.total_tokens_staked.ensure_add_assign(amount)?;

			Pools::<T>::insert(pool_id, pool_info);

			// Update PoolStakers.
			staker_info.amount.ensure_add_assign(amount)?;
			PoolStakers::<T>::insert(pool_id, &staker, staker_info);

			// Emit event.
			Self::deposit_event(Event::Staked { staker, pool_id, amount });

			Ok(())
		}

		pub fn update_pool_and_staker_rewards(
			pool_info: &PoolInfoFor<T>,
			staker_info: &PoolStakerInfo<T::Balance>,
		) -> Result<(PoolInfoFor<T>, PoolStakerInfo<T::Balance>), DispatchError> {
			let reward_per_token = Self::reward_per_token(&pool_info)?;
			let pool_info = Self::update_pool_rewards(pool_info, reward_per_token)?;

			let mut new_staker_info = staker_info.clone();
			new_staker_info.rewards = Self::derive_rewards(&staker_info, &reward_per_token)?;
			new_staker_info.reward_per_token_paid = pool_info.reward_per_token_stored;
			return Ok((pool_info, new_staker_info));
		}

		pub(super) fn reward_per_token(
			pool_info: &PoolInfoFor<T>,
		) -> Result<T::Balance, DispatchError> {
			if pool_info.total_tokens_staked.is_zero() {
				return Ok(pool_info.reward_per_token_stored);
			}

			let rewardable_blocks_elapsed: u32 =
				match Self::last_block_reward_applicable(pool_info.expiry_block)
					.ensure_sub(pool_info.last_update_block)?
					.try_into()
				{
					Ok(b) => b,
					Err(_) => return Err(Error::<T>::BlockNumberConversionError.into()),
				};

			Ok(pool_info.reward_per_token_stored.ensure_add(
				pool_info
					.reward_rate_per_block
					.ensure_mul(rewardable_blocks_elapsed.into())?
					.ensure_mul(PRECISION_SCALING_FACTOR.into())?
					.ensure_div(pool_info.total_tokens_staked)?,
			)?)
		}
