### Title
Cross-organization team membership mutation via github_id-only lookup in `MembershipHandler#process` - (File: app/models/shipit/webhooks/handlers/membership_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` only checks that the request's HMAC signature matches the webhook secret of the organization named in the payload (`repository_owner`, derived from `organization.login`), i.e. it authenticates *who sent the request*, not *which records the payload may reference*. `MembershipHandler#find_or_create_team!` then looks up the target `Team` solely by `github_id`, so an attacker who owns their own GitHub org (and thus its correctly-configured `webhook_secret`) can sign an arbitrary `membership`/`removed` payload naming a victim org's `Team#github_id` and a victim member's login, causing `team.members.delete(member)` to strip that user's membership from a team belonging to an organization the attacker never authenticated for.

### Finding Description
The broken binding, stated explicitly: the organization whose `webhook_secret` verified the request (`repository_owner` used in `Shipit.github(organization: repository_owner)` at `app/controllers/shipit/webhooks_controller.rb:25`) is assumed to equal the organization owning the `Team` record mutated by the handler. This equality is never enforced.

Code path:
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-30`) verifies the raw JSON body's HMAC-SHA1 against the secret configured for `repository_owner`, which is read straight from the attacker-controlled payload (`repository.owner.login` or `organization.login`, `app/controllers/shipit/webhooks_controller.rb:59-62`). Since the attacker owns this org in GitHub, they legitimately know/control this webhook secret and can sign **any JSON body** they choose, not just a body GitHub itself would generate.
- `MembershipHandler#process` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-34`) calls `find_or_create_team!`, which does `Team.find_or_create_by!(github_id: params.team.id)` (`app/models/shipit/webhooks/handlers/membership_handler.rb:38-43`) — keyed only on the numeric `github_id`, with no comparison against `params.organization.login` or `repository_owner`.
- For the `'removed'` action, the handler runs `team.members.delete(member)` (`app/models/shipit/webhooks/handlers/membership_handler.rb:30`) using whatever `Team` the id lookup returned, and `member` is resolved via `User.find_or_create_by_login!(params.member.login)` (`app/models/shipit/webhooks/handlers/membership_handler.rb:24`), which is also a global, org-independent lookup.

Attacker request: `POST /webhooks` with `X-Github-Event: membership`, a valid `X-Hub-Signature` computed with the attacker's own org's webhook secret over a body of the form:
```json
{
  "action": "removed",
  "team": { "id": <victim_team_github_id>, "name": "...", "slug": "...", "url": "..." },
  "organization": { "login": "attacker-org" },
  "member": { "login": "victim-user" }
}
```
`repository_owner` resolves to `"attacker-org"` (whose secret correctly signs the body), so `verify_signature` passes. `find_or_create_team!` then finds the pre-existing victim `Team` (matched purely by `github_id`), and `team.members.delete(member)` removes the victim's real membership row.

Existing guards do not stop this: `verify_signature` only validates sender authenticity for the org named in the payload, not consistency between that org and the entity ids referenced inside the payload; `drop_unhandled_event` and the `ExplicitParameters` schema only validate presence/type of fields, not cross-org ownership; there is no `force_github_authentication`, `require_permission!`, or model validation tying `Team#organization` to the caller's authenticated org during lookup by `github_id`.

### Impact Explanation
This lets an attacker who controls any GitHub organization (and thus a valid webhook secret registered in Shipit for that org) delete a real membership row from a completely different, victim organization's `Team`, as long as they can obtain/guess the victim `Team`'s numeric GitHub id (observable via public GitHub API/UI) and the target member's GitHub login (public). If that `Team` is one of `Shipit.github_teams` used for authorization (`User#authorized?`, `app/models/shipit/user.rb:80-82`), this directly deauthorizes a legitimate operator from the victim's Shipit instance — a cross-tenant write ("payload for one repository/org mutating another's team") matching the Critical impact category. The action is repeatable against any victim team/member combination and is not rate-limited by any additional check.

### Likelihood Explanation
Preconditions are modest: the attacker needs their own GitHub organization already onboarded into Shipit (so a `webhook_secret` exists and is verifiable), knowledge of the victim `Team`'s GitHub numeric id (discoverable via GitHub's team API/UI for teams the attacker can see, or by other means), and the victim member's login (public). No Shipit session, API token, or victim secrets are required — only the attacker's own legitimately-configured webhook secret. This is a low-cost, fully repeatable exploit requiring no privileged access to the victim.

### Recommendation
In `find_or_create_team!`, scope the lookup by both `github_id` and the verified organization (e.g. `Team.find_or_create_by!(github_id: params.team.id, organization: repository_owner)`, passing the controller's verified `repository_owner` into the handler), and reject/raise if a `Team` with that `github_id` exists under a different `organization`. More generally, `MembershipHandler#process` should verify `params.organization.login == repository_owner` (the org that passed signature verification) before performing any lookup or mutation, ensuring the payload's `team`/`organization` claims cannot cross organizational boundaries.

### Proof of Concept
Minitest plan (using `test/controllers/webhooks_controller_test.rb` style, no live GitHub calls):
1. Seed two orgs in `Shipit.github` config/secrets fixtures: `"victim-org"` and `"attacker-org"`, each with its own `webhook_secret`.
2. Seed `victim_team = Shipit::Team.create!(github_id: 555, organization: "victim-org", name: "ops", slug: "ops", api_url: "...")`.
3. Seed `victim_member = Shipit::User.find_or_create_by_login!("victim-user")` and `victim_team.add_member(victim_member)`; assert `victim_team.members.include?(victim_member)` is `true` (state before).
4. Build payload:
```ruby
body = {
  action: 'removed',
  team: { id: 555, name: 'ops', slug: 'ops', url: 'https://api.github.com/teams/555' },
  organization: { login: 'attacker-org' },
  member: { login: 'victim-user' }
}.to_json
```
5. Compute `signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', attacker_org_webhook_secret, body)`.
6. `post '/webhooks', params: body, headers: { 'X-Github-Event' => 'membership', 'X-Hub-Signature' => signature, 'Content-Type' => 'application/json' }`.
7. Assert response is `200 OK` (i.e., `verify_signature` accepted it under `attacker-org`'s secret) — showing `repository_owner == "attacker-org"` while `victim_team.organization == "victim-org"` (the two sides of the binding, unequal).
8. Assert `victim_team.reload.members.include?(victim_member)` is now `false` — proving a request authenticated only for `attacker-org` deleted a membership belonging to `victim-org`'s team. [1](#0-0) [2](#0-1) [3](#0-2)

        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
