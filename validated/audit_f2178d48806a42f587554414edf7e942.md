### Title
Position NFT transferred to the controller or pool contract permanently freezes the lending account — no owner-of-recovery or sweep path exists — (contracts/position-nft/src/contract.rs)

### Summary
The OpenQ issue's bug class is "asset transferred to a contract address becomes unrecoverable because no code path can act on its behalf." XOXNO Lending reproduces this exactly, and worse: the position NFT *is* the account. `transfer` accepts any `to` address — including the controller or pool contract — and every controller verb that touches an account resolves the owner via a live `owner_of` call and demands that address's authorization. A contract address can never satisfy `require_auth` from an external caller, so the collateral and debt attached to the token are permanently frozen. There is no sweep, rescue, or forced-transfer endpoint.

### Finding Description
The controller stores no owner; `try_account_owner`/`is_owner_or_delegate` read `owner_of(token_id)` on the position NFT live and require that address to authorize [1](#0-0) . The NFT's `transfer(from, to, token_id)` places no constraint on `to` beyond `from`'s authorization [2](#0-1) . Because "transferring the token transfers the whole position — collateral and debt both move with the token" [3](#0-2) , setting `to = <controller>` or `to = <pool>` makes a contract address the account owner. No controller entrypoint can produce an authorization for the controller's own address, and `burn`/`mint` are controller-gated but the controller never calls them on its own initiative for a live account.

The token-level analog also holds: the docs state "Undeclared callback assets receive neither credit nor refunds. There is no controller sweep endpoint" [4](#0-3) , so a direct token transfer to the controller (explicitly an in-scope action) is unrecoverable; `claim_revenue` only forwards pool revenue to the configured accumulator, not stray controller balances [5](#0-4) .

### Impact Explanation
Permanent freezing of funds. A user who transfers their position NFT to the controller or pool contract address (or to any contract that cannot re-transfer it, e.g. a buggy wallet or a protocol integration) loses all collateral in the account and cannot repay the debt; the account stays live, accrues interest, and is liquidatable, but no principal can ever exit. Likewise, tokens sent directly to the controller have no recovery path. Unlike the OpenQ original where the NFT unlocks at expiration, here there is no expiration — the freeze is permanent.

### Likelihood Explanation
Requires a user mistake (fat-fingered `to` address, integration bug, or wallet auto-filling the contract address), matching the Medium severity of the source report. The position NFT is deliberately designed as a plain transferable ERC-721-style token so that "wallets, indexers, and marketplaces can read and move it with no protocol-specific tooling" [6](#0-5)  — generic marketplace/aggregator flows are precisely where transfers to contract addresses happen.

### Recommendation
- In `transfer`/`transfer_from` (or a controller-side hook invoked on transfer), reject `to` equal to the controller or pool contract addresses.
- Alternatively/additionally, add a governance-timelocked rescue operation (`recover_account_nft`) so a proven-accidental recipient contract address can be bypassed, and a governance sweep for stray token balances held by the controller.
- Document that integrations must never address transfers to protocol contracts.

### Proof of Concept
1. Alice calls `controller.supply(caller=alice, account_id=0, spoke_id=S, assets=[(hub, USDC, 1000e7)])`, minting account id `N` with collateral.
2. Alice calls `position_nft.transfer(from=alice, to=<controller_address>, token_id=N)` — succeeds; `owner_of(N)` returns the controller.
3. Any subsequent `withdraw`/`repay`/`borrow`/`renew_account`/`add_delegate` on account `N` fails `NotAuthorized` (error 44) because the controller contract address cannot sign, and the controller never invokes NFT operations on itself. The same failure occurs for `to=<pool_address>` or any non-transfer-capable contract. The 1000 USDC collateral is frozen permanently; delegation re-arming cannot help since `granted_by` can never equal the contract address [7](#0-6) .
