### Title
Cross-tenant webhook forgery: `WebhooksController#verify_signature` selects the verifying org from attacker-controlled `repository.owner.login`, decoupled from `params.repository.full_name` used by `LabelCapturingHandler#repository` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb`, `lib/shipit/github_app.rb`)

### Summary
`WebhooksController#verify_signature` picks the GitHub App/secret to verify a webhook against using `params.dig('repository','owner','login')`, a field taken directly from the untrusted JSON body, and never checks it against `params.repository.full_name`, which is the field `LabelCapturingHandler#repository` actually uses via `Shipit::Repository.from_github_repo_name` to resolve the target stack. In multi-org Shipit deployments, an attacker can name any org (including one with a misconfigured/blank `webhook_secret`) in `repository.owner.login` to pass `verify_signature` trivially, while pointing `repository.full_name` at a completely different tenant's real repository, causing `capture_labels` to overwrite that foreign stack's `pull_request.labels`.

### Finding Description
The binding the code should enforce is: `organization_that_verified_signature == owner(params.repository.full_name)`. Tracing the code shows this is never checked.

`WebhooksController#verify_signature` computes: [1](#0-0) 
```
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where `repository_owner` is `params.dig('repository','owner','login') || params.dig('organization','login')` — both fields fully controlled by whoever posts the raw body. [2](#0-1) 

`Shipit.github(organization:)` only uses the passed `organization` argument to select a distinct app/secret when the deployment is in genuine multi-org mode (`github_default_organization` non-nil); otherwise it ignores it and always uses the single global secret. [3](#0-2) 

`GitHubApp#verify_webhook_signature` has an explicit bypass: `return true unless webhook_secret`, i.e. if the selected org's `webhook_secret` is blank/unset, ANY signature (or none at all) is accepted. [4](#0-3) 

Downstream, `LabelCapturingHandler#repository` and `#capture_labels` never re-derive or validate against `repository_owner`; they resolve the stack purely from `params.repository.full_name`: [5](#0-4) 
```
def repository
  @repository ||= Shipit::Repository.from_github_repo_name(params.repository.full_name) || NullRepository.new
end
def capture_labels
  return unless pull_request = stack.pull_request
  pull_request.update!(labels: params.pull_request.labels.map(&:name))
end
```
`Shipit::Repository.from_github_repo_name` simply splits the string and does a `find_by(owner:, name:)` lookup — no ownership check against the verifying app. [6](#0-5) 

Exploit: in a multi-org deployment (e.g. matching `test/dummy/config/secrets_double_github_app.yml`, which ships one org, `OrgTwo`, with `webhook_secret: # nil`), an unprivileged attacker POSTs directly to `/webhooks` with `X-Github-Event: pull_request`, body `repository.owner.login = "OrgTwo"` (any signature accepted because that org's secret is blank) and `repository.full_name = "OrgOne/victim-repo"` (a real, unrelated tenant's repository). `verify_signature` passes trivially; `LabelCapturingHandler` resolves `stack` for `OrgOne/victim-repo` and calls `pull_request.update!(labels: attacker_supplied_labels)`, mutating a foreign tenant's stack state with attacker-chosen data — with zero relationship between the "authenticating" org and the "target" org.

None of the existing guards catch this: `drop_unhandled_event` only checks the event type exists; `ExplicitParameters` schema only validates field types/presence, not cross-field consistency; model validations on `Repository`/`Stack` only validate format, not provenance; there is no code anywhere binding the app used for signature verification to the repository named in the payload.

### Impact Explanation
An attacker who can reach `POST /webhooks` (a public, unauthenticated endpoint) can write attacker-chosen `pull_request.labels` onto any other tenant's stack's pull request record, without ever authenticating as that tenant. Labels captured this way are documented (per the question) to later flow into that tenant's own deploy-time environment building (`TaskCommands#env`/`Command#unbundled_env`) on the victim's next deploy — meaning a payload from one repository mutates another repository's stack state, matching the "payload for one repository mutating another's stack" Critical category. This is repeatable against any stack whose owning org's name the attacker can guess/discover, as long as at least one org configured in the Shipit instance has a blank `webhook_secret` (a supported, non-error configuration state per `docs/setup.md` and the shipped test fixtures).

### Likelihood Explanation
Exploitability strictly requires a multi-org Shipit deployment where at least one configured org has `webhook_secret` unset (a state the codebase explicitly supports and the shipped example config demonstrates, not an exotic misconfiguration). Given that, the attacker needs no secrets, tokens, sessions, or privileged roles at all — just knowledge of a target repository's `owner/name` (public information) and the name of any org configured without a secret. In a single-org deployment this specific decoupling is not exploitable, because `Shipit.github(organization:)` ignores the passed org and always uses the one global secret, so the root cause (missing binding check) exists but is latent unless multi-org + blank-secret conditions hold.

### Recommendation
In `WebhooksController#verify_signature`, after successfully verifying, additionally check that `repository_owner` matches the owner segment of `params.dig('repository','full_name')` (and reject/`head(422)` on mismatch) before dispatching to handlers. Also remove or gate the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature` behind a non-production/test-only flag so a blank secret cannot silently disable signature enforcement in a live multi-org deployment.

### Proof of Concept
minitest plan (multi-org fixture, e.g. reuse `test/dummy/config/secrets_double_github_app.yml` pattern):
1. Configure two orgs: `OrgOne` (real secret) owning stack/repo `orgone/victim-repo` with an existing `pull_request` whose `labels` are `["safe-label"]`; `OrgTwo` with blank `webhook_secret`.
2. `post :create` to `WebhooksController#create` with `X-Github-Event: pull_request`, no/garbage `X-Hub-Signature`, and JSON body: `repository.owner.login = "OrgTwo"`, `repository.full_name = "orgone/victim-repo"`, `action = "labeled"`, `pull_request.labels = [{name: "attacker-label"}]`.
3. Assert response is not `:unprocessable_entity` (verification passed).
4. Assert `Shipit::Stack.find_by(...).pull_request.reload.labels` is unchanged (`["safe-label"]`), i.e. still equal to the pre-attack value — the equality `organization_that_verified_signature ("OrgTwo") == owner(full_name) ("orgone")` must be false and enforced by rejecting the request; currently the test would show labels changed to `["attacker-label"]`, proving the vulnerability.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
