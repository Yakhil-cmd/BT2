### Title
Unauthenticated cross-tenant stack-status disclosure via spoofed `referrer` in `MergeStatusController#check` - ([File: app/controllers/shipit/merge_status_controller.rb])

### Summary
`MergeStatusController#check` is exempted from `force_github_authentication` via `skip_authentication only: %i[check show]`, and unlike `#show` it has no `current_user.logged_in?` gate at all. Combined with `ReferrerParser::URL_PATTERN`, which only requires the client-supplied `params[:referrer]` to look like `https://github.com/<owner>/<repo>/pull/<n>`, an attacker with zero Shipit session or credentials can enumerate and read the merge/CI status of any repository's `Stack` configured in the instance.

### Finding Description
The claimed binding is: `authorized_repository_of(current_identity) == repository_owner_from(referrer)`. In reality, `#stack` (`app/controllers/shipit/merge_status_controller.rb:62-81`) resolves the `Stack` purely by matching `Repository#owner`/`#name` against `referrer_parser.repo_owner`/`repo_name`, which come from `ReferrerParser` (`app/controllers/shipit/merge_status_controller.rb:114-128`) parsing the raw client-supplied `params[:referrer]` string — there is no comparison to any webhook signature, session identity, or `current_api_client`.

`#show` (lines 10-25) at least requires `current_user.logged_in?` (line 15) before rendering `stack_status`, which limits exposure to holders of a valid Shipit session. `#check` (lines 39-50) has no such check:
```ruby
def check
  respond_to do |format|
    format.html do
      if stack_status == 'success'
        render(plain: 'ok')
      else
        render(plain: stack_status, status: 503)
      end
    end
    format.json { render(json: { stack_status: }) }
  end
end
```
`stack_status` (line 58-60) calls `stack.merge_status`, and `stack` resolution (lines 62-81) never checks the caller's identity — only the attacker-controlled `referrer` string. Since `#check` is listed in `skip_authentication`, `force_github_authentication` (which is the only place `current_user.authorized?` / team membership is enforced, see `app/controllers/concerns/shipit/authentication.rb:20-34`) never runs for this action. A fully anonymous HTTP client (no cookies, no `ApiClient` token) can therefore send `GET /merge_status/check?referrer=https://github.com/other-org/other-repo/pull/1` and receive `other-org/other-repo`'s stack merge status (`success`/`pending`/`failure`/`backlogged`, reflected in the plain-text/JSON response), as confirmed by the request/response shapes exercised in the existing `#show` tests (`test/controllers/merge_status_controller_test.rb`), which use the identical `stack` resolution path.

### Impact Explanation
This discloses internal CI/merge-queue state (build health, whether a branch is locked and why, whether the merge queue is backlogged) for any repository/stack hosted on the Shipit instance to a fully unauthenticated internet client, purely by supplying a spoofed `referrer` string that need not correspond to any real GitHub PR the attacker has access to. This matches the specified High-severity category "unauthenticated read of stack state." It is trivially repeatable against every repository/stack in the instance since the only input required is a well-known repo owner/name pair; no GitHub webhook, session, or API token is involved anywhere in the path.

### Likelihood Explanation
Preconditions are minimal: the target Shipit instance must host at least one `Stack` for the victim repository (a very common configuration in shared/multi-tenant Shipit deployments), and the attacker only needs the target's `owner/repo` name, which is public information for public GitHub repos and often guessable/enumerable even for private ones. No secrets, tokens, or GitHub interaction are required — a single unauthenticated HTTP GET suffices, and the request can be repeated for arbitrary repositories.

### Recommendation
Apply the same authorization gating to `#check` as intended for the general controller: either remove `check` from `skip_authentication` and require `force_github_authentication` (and hence `current_user.authorized?`), or explicitly verify that the resolved `stack.repository` is one the caller is authorized to view (e.g., check `current_user.authorized?` and/or repository-level ACL) before computing/rendering `stack_status`. At minimum, mirror the `current_user.logged_in?` guard already present in `#show`.

### Proof of Concept
```ruby
# test/controllers/merge_status_controller_test.rb
test "GET check without any session discloses status of a stack the caller is not authorized for" do

  assert_includes %w(success pending failure backlogged), body['stack_status']
```

```ruby
    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
    end
```

```ruby
    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
