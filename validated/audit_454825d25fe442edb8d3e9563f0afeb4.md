### Title
Webhook signature is verified against the org selected from an unauthenticated payload field, while handlers act on a different, independently-controlled repository field of the same payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks *which* GitHub App/organization secret to verify the HMAC signature against by reading `repository.owner.login` (or `organization.login`) straight out of the still-unverified JSON body. Once the signature check passes, the actual event handlers (`Handler#repository_name`, used by `PushHandler`, the pull-request handlers, etc.) resolve the target `Repository`/`Stack` using a *different* field of that same body: `repository.full_name`. In a multi-organization deployment (the documented `github: { orgA: {...}, orgB: {...} }` schema) these two fields are never checked against each other.

### Finding Description
`Shipit.github(organization:)` resolves a distinct `webhook_secret` per GitHub organization from `secrets.github` [1](#0-0) . The controller selects which organization's secret to verify with using the untrusted payload itself, before any authentication has occurred: [2](#0-1) [3](#0-2) 

`verify_webhook_signature` only proves that the *entire raw body* was HMAC-signed by whoever holds the secret for the organization named in `repository.owner.login`/`organization.login` [4](#0-3) . It proves nothing about which repository the body's other fields describe.

Every handler, however, resolves the acted-upon repository/stack from a separate field, `repository.full_name`, with no cross-check against `repository.owner.login`: [5](#0-4) [6](#0-5) [7](#0-6) 

Because both fields live in the same JSON object and can be set independently by whoever crafts the raw body, an organization admin who legitimately owns a webhook secret for Org A (a valid, low-privilege actor with respect to Org B, which is a separate tenant/repository owner registered in the same Shipit instance) can sign a payload whose `repository.owner.login` is `"org-a"` (so it is verified with Org A's secret) but whose `repository.full_name` is `"org-b/some-repo"` (a repository/stack that belongs to Org B and that Org A has no access to). This breaks the binding: `organization authenticated (repository.owner.login → webhook_secret used)` ≠ `repository actually written to (repository.full_name → Repository/Stack acted upon)`.

### Impact Explanation
This lets an attacker who only controls Org A's webhook secret drive actions against Org B's stacks: `PushHandler#process` will call `stack.sync_github(expected_head_sha: params.after)` for any stack whose repository's `full_name` the attacker names, regardless of which org it actually belongs to [8](#0-7) . Other handlers (pull_request opened/closed/labeled/reopened, status, check_suite) are equally reachable this way since they all resolve their target repository via the same `full_name` lookup pattern, independent of `owner.login` [9](#0-8) . This is a cross-repository/cross-tenant write triggered with credentials belonging to a different, unrelated organization.

### Likelihood Explanation
Requires a multi-org Shipit deployment (the documented pattern in `docs/setup.md`/`config/secrets.development.example.yml`) where multiple, mutually-untrusted GitHub organizations are each configured with their own `webhook_secret`. Any actor who is a legitimate admin of one such organization (and therefore knows or can obtain that organization's own webhook secret through normal GitHub App setup) can exploit this without any additional privilege escalation, cracking, or interception — they only need to POST directly to `/webhooks` with a self-crafted, self-signed body.

### Recommendation
After `verify_signature` succeeds, cross-check that the organization used to select the verifying secret matches the owner embedded in `repository.full_name` (and `organization.login` where present) before dispatching to handlers; reject the webhook if they disagree. Alternatively, resolve the target `Repository`/`Stack` and confirm its `owner` equals the authenticated organization prior to invoking any handler logic.

### Proof of Concept
1. Deploy Shipit with the multi-org config schema: `secrets.github.org-a.webhook_secret = S_A`, `secrets.github.org-b.webhook_secret = S_B`, both `org-a/repo` and `org-b/repo` registered as `Repository`/`Stack` records.
2. As an admin who only knows `S_A` (legitimate for Org A), build a JSON body:
   ```json
   {
     "ref": "refs/heads/master",
     "after": "<attacker-chosen-sha>",
     "repository": { "owner": { "login": "org-a" }, "full_name": "org-b/repo" }
   }
   ```
3. Compute `X-Hub-Signature: sha1=<hmac_sha1(S_A, body)>` and POST to `/webhooks` with `X-Github-Event: push`.
4. `WebhooksController#repository_owner` returns `"org-a"`; `Shipit.github(organization: "org-a")` selects `S_A`; `verify_webhook_signature` succeeds because the whole raw body was signed with `S_A`.
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("org-b/repo")`, and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on Org B's stack — an action performed using only Org A's webhook secret against Org B's repository.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
```
