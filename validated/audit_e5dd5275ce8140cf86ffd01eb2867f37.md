### Title
Attacker-controlled `device_address` in `handleNewSharedAddress` lets a peer hijack signer routing for a multi-signature shared address - (File: wallet_defined_by_addresses.js)

### Summary
`handleNewSharedAddress` in `wallet_defined_by_addresses.js` accepts a `signers` map from an untrusted correspondent and only validates that each `signers[path].address` matches the address embedded in the definition; it never validates that `signers[path].device_address` actually belongs to the real owner of that member address. [1](#0-0)  The only place a device's own identity is enforced is in `determineIfIncludesMeAndRewriteDeviceAddress`, and that rewrite only fires for signing paths whose `address` is found in the *local* device's own `my_addresses`/`shared_addresses` — for every other cosigner's path, whatever `device_address` the sender supplied is trusted verbatim and persisted. [2](#0-1)  That untouched map is written straight into `shared_address_signing_paths`, which is exactly the table used later to route co-signing requests. [3](#0-2) 

### Finding Description
A multi-signature ("shared") address in ocore is defined purely by an `["and"/"or"/...]` array of member `["address", ADDR]` leaves; its address is `objectHash.getChash160(definition)`, so the address itself is public and derivable by anyone who knows all member addresses (which are routinely exchanged in plaintext device chat during wallet setup). Any correspondent that is a party to (or is invited to become a party to) the shared-address creation flow can call `handleNewSharedAddress` with a legitimate `definition`/`address` pair but with a `signers` map in which the `device_address` for *another* member's signing path points to an address it controls instead of the real cosigner's device.

The validation performed is:
- `objectHash.getChash160(body.definition) === body.address` (proves the definition is authentic) [4](#0-3) 
- `signerInfo.address` at each path matches the `["address", ...]` leaf extracted from the definition [5](#0-4) 

Nothing ties `signerInfo.device_address` to the actual owner of `signerInfo.address`. `determineIfIncludesMeAndRewriteDeviceAddress` corrects the mapping only for paths whose member address is one of *my own* addresses; paths belonging to *other* cosigners are stored as received. [6](#0-5) 

`addNewSharedAddress` then does `INSERT OR IGNORE` into `shared_addresses` and `shared_address_signing_paths`, so whichever peer's message is processed first wins the primary key `(shared_address, signing_path)`; a legitimate, later-arriving message with the correct `device_address` for that path is silently ignored. [7](#0-6) 

Once `shared_address_signing_paths.device_address` for a given member's path is poisoned, every future attempt to route a co-signing request to that member (to build a transaction spending from the shared address, forwarding, etc.) is a request sent by device address recorded in this table — which now points to the attacker's device instead of the legitimate cosigner's device — so the real cosigner never receives (and can never respond to) signing requests for that shared address.

### Impact Explanation
This is a fund-freezing / denial-of-availability bug on a multi-signature address: once the attacker's poisoned signer mapping wins the race, the shared/multisig address becomes permanently unusable by its legitimate members because the network layer no longer knows how to reach the correct cosigner device for that signing path, mirroring the reported CVE's effect ("prevent a legitimate user from authenticating/participating by acting first for an identity that exists"). It does not directly allow the attacker to forge signatures (it cannot fabricate the actual private-key signatures required by the definition), but it can permanently deny the legitimate cosigner from being able to co-sign spends from a shared address that other members believe is properly configured, effectively freezing any funds sent to it. This satisfies "AA fund loss or freezing" / unauthorized denial-of-use criteria for a High-severity analog.

### Likelihood Explanation
Reachable by any unprivileged correspondent participating in (or invited into) a shared-address setup — no special privileges, hub role, or network position needed; it is a normal `pairing`/wallet-message-level device-to-device interaction (`handle_message_from_hub` → `handleNewSharedAddress`). [8](#0-7)  The only requirement is that the attacker learns the definition/member addresses ahead of time — which happens naturally as part of the shared-address negotiation protocol itself (`sendOfferToCreateNewSharedAddress`/`approvePendingSharedAddress` flow) or from any observed prior message, making this attack realistically reachable by a dishonest party to the multisig setup.

### Recommendation
When persisting `shared_address_signing_paths`, do not trust the sender-supplied `device_address` for cosigner paths that are not the local device's own addresses. Either (a) require independent confirmation/derivation of each member's `device_address` from `correspondent_devices`/an authenticated introduction rather than accepting it inline in `handleNewSharedAddress`'s untrusted `signers` payload, or (b) treat `shared_address_signing_paths` rows as append-only/conflict-detected instead of "INSERT OR IGNORE" so that a legitimate cosigner's own device-address claim for its own signing path always takes precedence over a value supplied by a third party, and surface a conflict/warning to the user instead of silently accepting the first writer.

### Proof of Concept
1. Alice, Bob, and Mallory begin setting up a 2-of-3 (or `and`/`or`) shared address whose `["address", ...]` leaves are Alice's, Bob's, and Mallory's real payment addresses. The resulting `arrDefinition`/`address` are computable/knowable by Mallory as soon as she learns Alice's and Bob's addresses (which are exchanged as plaintext device messages during setup).
2. Before the legitimate `createNewSharedAddress`/`sendNewSharedAddress` completion message from the real initiator arrives at Bob's device, Mallory sends her own `new_shared_address` message to Bob with the same correct `address`/`definition`, but with `signers["r.0"] = {address: Alice_address, device_address: Mallory_device_address}` for Alice's signing path.
3. On Bob's device, `handleNewSharedAddress` validates that `objectHash.getChash160(definition) === address` and that `Alice_address` matches the definition leaf — both pass — then calls `addNewSharedAddress`, inserting `shared_address_signing_paths` with Alice's path mapped to Mallory's `device_address`. [9](#0-8) 
4. When the legitimate message from Alice's actual device (or the real initiator) arrives afterward with the correct `device_address` for Alice's path, `INSERT OR IGNORE` causes it to be silently dropped because the primary key `(shared_address, signing_path)` already exists. [10](#0-9) 
5. From this point forward, any device on Bob's side that needs to request Alice's signature for a transaction spending from the shared address routes the request to Mallory's device address instead of Alice's, so Alice never receives the signing request and can never co-sign — the shared address is now unusable by its intended owners, freezing any funds sent to it.

Note: I was not able to fully trace, within the indexing coverage available, the exact downstream code path in `wallet.js` that consumes `shared_address_signing_paths.device_address` to route a live signing request (only that 17 references to this table exist there); a Devin session with full repository access would be needed to confirm the precise routing call sites and validate the end-to-end PoC against a running node.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
