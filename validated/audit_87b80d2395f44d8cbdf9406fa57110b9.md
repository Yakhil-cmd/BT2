### Title
Signature verification selects GitHub App by `repository.owner.login` while all business logic acts on `repository.full_name`, so a secretless-but-known org's webhook can mutate a different org's stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` resolves the `GithubApp` used to check the HMAC signature solely from `repository_owner` (`repository.owner.login`), and only rejects the request via `head(422)` when `Shipit.github(organization: ...)` raises `Shipit::GithubOrganizationUnknown`. If that organization is known but configured without a `webhook_secret`, `GithubApp#verify_webhook_signature` returns `true` unconditionally, no exception is raised, and the request proceeds to `#create`, which dispatches handlers keyed entirely on the (attacker-controlled, unverified-per-target) `repository.full_name` field.

### Finding Description
The claimed binding — "`GithubOrganizationUnknown` raised == the only rejection path" — is false. In [1](#0-0) , `verify_signature` calls `Shipit.github(organization: repository_owner)` and then `github_app.verify_webhook_signature`. But in [2](#0-1) , `verify_webhook_signature` contains `return true unless webhook_secret` — for any configured-but-secretless organization, signature verification is a no-op that always returns `true`, without ever raising `GithubOrganizationUnknown` and without ever calling `head(422)`.

Meanwhile, the org used to pick the `GithubApp` (`repository.owner.login`) is never cross-checked against the org/repo actually acted upon. `#create` re-parses `request.raw_post` independently in [3](#0-2)  and dispatches to handlers that resolve the target purely from `payload.dig('repository', 'full_name')`, as seen in the base `Handler` class [4](#0-3)  and in `PushHandler#process` [5](#0-4) , as well as in the pull-request handlers (`OpenedHandler`, `ClosedHandler`, `LabeledHandler`, etc.) which all call `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) .

Nothing in the request pipeline enforces `repository.owner.login == repository.full_name.split('/').first`. An attacker who controls the full JSON body of the POST (no session, no secret, no team membership required) can set `repository.owner.login` to a known org that has no `webhook_secret` configured, while setting `repository.full_name` to an entirely different, secret-protected org's repository slug. `verify_signature` will succeed trivially for the secretless org and the handler will then act on the different org's `Stack`/`Repository` record.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type; `ExplicitParameters` schemas validate structure/types, not owner-target consistency; `Shipit::Repository.from_github_repo_name` looks up by string match without any tie back to `repository_owner`.

### Impact Explanation
For a Shipit deployment configured with multiple GitHub Apps (per `docs/setup.md`'s documented multi-org configuration schema, e.g. `test/dummy/config/secrets_double_github_app.yml`), if any one configured organization omits `webhook_secret` (documented as "optional"), that organization becomes an unauthenticated relay: an attacker forges a webhook body naming that org as `repository.owner.login` but naming a secret-protected org/repo as `repository.full_name`. This lets the attacker trigger `stack.sync_github` (push events), pull-request review-stack provisioning/archival, or `PullRequest#update` for a stack belonging to a completely unrelated, secured tenant — a payload for one repository mutating another's stack, matching the Critical "authentication bypass" / "payload for one repository mutating another's stack" category. It is repeatable against any stack whose `Repository#github_repo_name` is known/guessable.

### Likelihood Explanation
Exploitability is contingent on the target deployment running multi-org GitHub App configuration with at least one org lacking a `webhook_secret`. Since the webhook secret is explicitly documented as optional per-org, this is a realistic and low-cost misconfiguration, not a theoretical one. Given that precondition, the attacker's cost is a single unauthenticated HTTP POST with an internet-crafted JSON body — no GitHub session, no Shipit credentials required.

### Recommendation
Enforce that the organization used to select the `GithubApp` for signature verification matches the organization embedded in `repository.full_name` (and `organization.login` fallback) before any handler processes the payload; reject mismatches with `head(422)`. Additionally, consider making `webhook_secret` mandatory (or defaulting `verify_webhook_signature` to `false` instead of `true`) when unset, so a misconfigured/secretless org fails closed rather than open.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "secretless-but-known org bypasses signature check and can target another org's repo" do
  # Precondition: an org configured with webhook_secret: nil (secretless) exists,
  # e.g. via test/dummy secrets fixture with a second, secret-protected org "secret-org".
  request.headers['X-Github-Event'] = 'push'

  payload = JSON.parse(payload_fixture(:push_master))
  payload['repository']['owner']['login'] = 'secretless-org'   # used only for signature app lookup
  payload['repository']['full_name']       = 'secret-org/private-repo' # used by PushHandler to pick target stack

  # No valid X-Hub-Signature header is set / signature is arbitrary.
  assert_nothing_raised do
    post :create, body: payload.to_json, as: :json
  end
  refute_equal 422, response.status  # head(422) never invoked
  # and the handler dispatched against secret-org/private-repo's Stack despite
  # the request never being signed by secret-org's webhook_secret.
end
```
This demonstrates both sides of the claimed equality diverge: `Shipit.github(organization: 'secretless-org')` does not raise `GithubOrganizationUnknown`, `verify_webhook_signature` short-circuits to `true` via the secretless branch, `head(422)` is never called, and `#create` proceeds to act on `secret-org/private-repo`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
