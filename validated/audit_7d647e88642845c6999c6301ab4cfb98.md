### Title
Webhook signature verified against attacker-chosen organization while handlers act on an unrelated `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the `X-Hub-Signature` against using the `repository.owner.login` (or `organization.login`) field of the attacker-supplied JSON body. The actual side effects of the webhook (which `Repository`/`Stack` records get mutated) are instead resolved independently by each `Handler` using `payload.dig('repository', 'full_name')`. Because both fields come from the same attacker-controlled JSON, they can be set to different values, letting an unauthenticated caller pick an organization with no (or a guessable) `webhook_secret` to satisfy verification while pointing the payload's `repository.full_name` at a stack belonging to a different, properly-secured organization.

### Finding Description
`Shipit.github(organization:)` supports multi-tenant configuration, keyed by organization, each with its own optional `webhook_secret`: [1](#0-0) 

`GitHubApp#verify_webhook_signature` explicitly short-circuits to `true` when no `webhook_secret` is configured for that organization: [2](#0-1) 

`WebhooksController#verify_signature` picks the app/secret to check against using `repository_owner`, which is read straight from the untrusted JSON payload (`repository.owner.login`, falling back to `organization.login`): [3](#0-2) 

Meanwhile, the dispatched handlers resolve the actual repository/stack to mutate from a *different* field of the same payload, `repository.full_name`: [4](#0-3) 

Nothing enforces that `repository.owner.login` (used for signature/authentication selection) matches the owner encoded in `repository.full_name` (used for the actual write). An attacker who knows (or guesses) that some configured organization in `secrets.github` has no `webhook_secret` set (a legal, documented configuration - `@webhook_secret = @config[:webhook_secret].presence`) can craft a JSON body where:
- `repository.owner.login` (or `organization.login`) = the org with no secret → `verify_webhook_signature` returns `true` unconditionally.
- `repository.full_name` = `"victim-org/victim-repo"` → the handler resolves and mutates the real, secret-protected stack.

This is the exact "organization that authenticated versus the repository that is written" trust binding called out in the rules.

### Impact Explanation
Depending on the event type dispatched (`X-Github-Event` header, also attacker controlled and unauthenticated), this allows forging arbitrary GitHub events against a victim stack without ever possessing that organization's `webhook_secret`:
- `status` events let the attacker fabricate CI state directly onto real commits via `Commit#create_status_from_github!`, which feeds `deployable?`/safety checks used for continuous deployment: [5](#0-4) 
- `push` events can enqueue `GithubSyncJob` for the victim stack.
- `pull_request` events can archive/mutate `ReviewStack`/`PullRequest` records tied to the victim repository.

Forged green CI statuses on a stack with `continuous_deployment: true` can lead to an unauthorized deploy being triggered, which meets the "Critical - unauthorized deploy" bar. At minimum this is an authentication bypass of the webhook trust boundary and unauthenticated write to stack/commit state, meeting the "High" bar.

### Likelihood Explanation
Exploitability depends entirely on operator configuration: it requires (a) a multi-organization Shipit deployment (`secrets.github` keyed by org) and (b) at least one configured organization lacking a `webhook_secret` (this is a supported, non-default-forbidden configuration, not a bug in itself). Given that, the attack requires no credentials at all - only knowledge of the low-security organization's name and the target's `owner/repo` full name, both of which are typically public information (GitHub org/repo names). This is a plausible, not purely theoretical, misconfiguration given the code explicitly supports secret-less orgs.

### Recommendation
Bind the identity used to authenticate the webhook to the identity used to determine the mutation target:
1. In `Handler#repository_name`, do not trust `full_name` independently; instead derive the repository strictly from the same `repository.owner.login` (or `organization.login`) value that was used in `verify_signature`, and reject/compare the two for consistency.
2. In `verify_signature`, after successfully identifying the organization, assert that `payload.dig('repository', 'owner', 'login')` matches `payload.dig('repository', 'full_name').split('/').first` before allowing processing to continue.
3. Consider disallowing/warn-logging any organization configuration lacking a `webhook_secret` when other organizations in the same deployment do have one configured, since it creates this bypass path.

### Proof of Concept
Assume `secrets.github` is configured with two orgs: `low-security-org` (no `webhook_secret`) and `victim-org` (has a `webhook_secret`), and `victim-org/victim-repo` has a Shipit stack with `continuous_deployment: true`.

```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=anything

{
  "sha": "<real deployed commit sha on victim stack>",
  "state": "success",
  "context": "ci/forged",
  "repository": {
    "owner": { "login": "low-security-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
- `verify_signature` computes `repository_owner` = `"low-security-org"`, loads that org's `GitHubApp` (no `webhook_secret`), and `verify_webhook_signature` returns `true` unconditionally regardless of the bogus `X-Hub-Signature`.
- `StatusHandler.process` resolves `Commit.where(sha: params.sha)` (global lookup, not org-scoped) and calls `create_status_from_github!`, injecting a forged "success" status for the commit belonging to `victim-org/victim-repo`, without ever supplying `victim-org`'s real webhook secret.

Note: I was not able to fully trace whether `Commit.where(sha:)` in `StatusHandler` is additionally scoped by stack/repository elsewhere in the model layer beyond what is shown; this should be verified against the full `Commit` model and `create_status_from_github!` implementation before treating the PoC as fully confirmed end-to-end.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
