## Title
Cross-tenant webhook signature confusion: `repository_owner` (used for signature verification) is not required to match `repository.full_name` (used to look up the mutated repository/stack) - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` derives the signing organization solely from `params.dig('repository', 'owner', 'login')` (or `organization.login`) and looks up that org's `webhook_secret` via `Shipit.github(organization: repository_owner)`. Handlers such as `LabeledHandler` separately resolve the repository to mutate via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. Both fields (`repository.owner.login` and `repository.full_name`) come from the same attacker-controlled, unsigned JSON body, and nothing enforces that the owner embedded in `full_name` matches `repository.owner.login`.

### Finding Description
The binding that should hold is: **organization authenticated by `verify_webhook_signature` == organization owning the repository resolved by `Repository.from_github_repo_name(params.repository.full_name)`**.

Trace:
- `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` (`app/controllers/shipit/webhooks_controller.rb:59-62`), then calls `Shipit.github(organization: repository_owner).verify_webhook_signature(header, raw_post)`.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) returns `true` unconditionally `unless webhook_secret` is configured for that resolved org config.
- If verification passes (or the org has no `webhook_secret` configured), `WebhooksController#create` dispatches the same raw JSON to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` (`app/controllers/shipit/webhooks_controller.rb:10-15`).
- `LabeledHandler#repository` and `#stack` resolve the target repository using a **different field of the same attacker-supplied JSON**: `params.repository.full_name` (`app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb:65-68`), then `respond_to_label_change?` (line 78-83) gates on `repository.review_stacks_enabled` and calls `stack.archive!`/`stack.unarchive!` (line 49-57).

Since the attacker crafts the entire raw JSON body themselves (no signature check blocks unsigned/garbage payloads once the resolved org has no `webhook_secret`), nothing prevents `repository.owner.login` (used only for org lookup) from being a *different* value than the owner encoded inside `repository.full_name` (used for the actual mutation). An attacker who has discovered (e.g., via repeated probing, since a failed signature just yields a 422 with no other signal) that some org `X` has no `webhook_secret` configured can submit:

```json
{
  "action": "labeled",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "X" }
  },
  ...
}
```

`repository_owner` resolves to `X` (unsecured), signature check passes trivially, but the handler operates on `victim-org/victim-repo`'s stack.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type exists as a handler; the `ExplicitParameters` schema (`params do ... end` in `labeled_handler.rb`) only validates types/presence of fields, not cross-field consistency between `repository.owner.login` and `repository.full_name`; there is no `force_github_authentication` or `require_permission!` on this controller at all (it's a webhook endpoint, `ActionController::Base`, no session/user check); `Repository` model validations validate format of a single repo record, not cross-payload consistency.

### Impact Explanation
If org `X` is unauthenticated (no `webhook_secret`), or if signature verification can be satisfied by any means for org `X`, an attacker can flip `archived?`/mutate the review stack of *any other* tenant's repository that has `review_stacks_enabled=true`, entirely without valid credentials for the victim org. This is a payload for one (uncredentialed) org mutating another tenant's stack - matching the Critical category "a payload for one repository mutating another's stack." It is repeatable against any repository with review stacks enabled, for any PR the attacker can reference (label/unlabel triggers `archive!`/`unarchive!`).

### Likelihood Explanation
Preconditions: (1) at least one configured GitHub org in `Shipit.github_configuration`/`config/shipit.yml`-equivalent has no `webhook_secret` set (which the code explicitly tolerates via `return true unless webhook_secret` in `verify_webhook_signature`), and (2) a victim org/repo has `review_stacks_enabled` and an open PR/label matching provisioning behavior. Attacker cost is a single unauthenticated HTTP POST to `/webhooks`; there is no rate limiting concern in scope, but even a single request suffices. This is feasible with no GitHub secrets, no Shipit session, no API client - satisfying the stated attacker model.

### Recommendation
Enforce consistency between the authenticated organization and the mutated repository's organization: after resolving `repository_owner` for signature verification, require that `Repository.from_github_repo_name(payload.dig('repository','full_name'))&.owner` (or the parsed org from `full_name`) equals `repository_owner` before dispatching to handlers. Reject (422) any webhook where `repository.owner.login` does not match the owner segment of `repository.full_name`. Additionally, consider requiring `webhook_secret` to be present for all configured orgs (fail closed instead of `return true unless webhook_secret`), removing the "any org with no secret" bypass entirely.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, illustrative):
```ruby
test "labeled event with mismatched owner/full_name archives a different org's stack" do
  # Org "no-secret-org" configured with webhook_secret: nil
  # Victim stack belongs to repository "victim-org/victim-repo", review_stacks_enabled: true
  victim_repo = shipit_repositories(:review_stacks_enabled_repo) # owner: victim-org
  victim_stack = create_review_stack_for(victim_repo, pull_request_number: 42)
  refute victim_stack.archived?

  payload = pull_request_labeled_payload(
    full_name: "#{victim_repo.owner}/#{victim_repo.name}",
    owner_login: "no-secret-org", # org with no webhook_secret configured
    label: victim_repo.provisioning_label_name
  )

  post shipit.webhooks_path,
       params: payload.to_json,
       headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=garbage', 'Content-Type' => 'application/json' }

  assert_response :ok
  # BEFORE: repository_owner ("no-secret-org") != repository.full_name owner ("victim-org")
  # AFTER: victim_stack mutated despite no valid credential for victim-org
  assert victim_stack.reload.archived?
end
```
Assert on both sides of the binding: `repository_owner` resolved by the controller (`"no-secret-org"`) must equal the owner of the repository actually mutated (`"victim-org"`) - they diverge, and the mutation still occurs, proving the vulnerability. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
