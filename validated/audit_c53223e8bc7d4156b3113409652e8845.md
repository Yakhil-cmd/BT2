### Title
`kip71.gastarget` Governance Parameter Accepts Zero Without Validation, Causing Division-by-Zero Panic in `NextMagmaBlockBaseFee` — (File: `params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter uses `noopFormatChecker`, accepting any `uint64` value including `0`. In contrast, `kip71.basefeedenominator` has both a `FormatChecker` rejecting `0` and a runtime guard in `NextMagmaBlockBaseFee`. `kip71.gastarget` has neither. When `GasTarget = 0` and `parentGasUsed > 0`, `NextMagmaBlockBaseFee` executes an integer division by zero via `x.Div(x, new(big.Int).SetUint64(gasTarget))`, causing a Go runtime panic. Every code path that calls `NextMagmaBlockBaseFee` — block production, header verification, and the gas price oracle — will panic, halting all nodes and causing consensus divergence.

---

### Finding Description

**Root cause — missing `FormatChecker` for `Kip71GasTarget`:**

`kaiax/gov/param.go` defines the format checker for each governance parameter. `Kip71BaseFeeDenominator` explicitly rejects zero:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // zero rejected
    },
```

But `Kip71GasTarget` uses `noopFormatChecker`, which accepts every value including `0`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // no validation at all
``` [1](#0-0) 

**Root cause — no runtime guard in `NextMagmaBlockBaseFee`:**

`NextMagmaBlockBaseFee` guards against `BaseFeeDenominator == 0` at runtime:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64)
}
```

No equivalent guard exists for `GasTarget`. When `parentGasUsed > gasTarget` (i.e., `parentGasUsed > 0` when `gasTarget = 0`), the code reaches:

```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // ← division by zero panic
``` [2](#0-1) 

**`checkConsistency` does not validate `kip71.gastarget`:**

The header governance consistency checker places `gov.Kip71GasTarget` in the "no additional checks" branch, returning `nil` unconditionally:

```go
case gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    ...
    return nil
``` [3](#0-2) 

**All callers of `NextMagmaBlockBaseFee` are affected:**

- Block production (`work/worker.go`): `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` — proposer panics before sealing.
- Header verification (`params/kip71_config.go` `VerifyMagmaHeader`): every validator panics when verifying the next block.
- Gas price oracle (`node/cn/gasprice/gasprice.go`): RPC layer panics. [4](#0-3) [5](#0-4) 

---

### Impact Explanation

When `kip71.gastarget = 0` takes effect and the next block has any gas usage (`parentGasUsed > 0`, which is true for any non-empty block), every node that calls `NextMagmaBlockBaseFee` panics. Go's `big.Int.Div` panics on division by zero. The panic is unrecovered in the call stack, crashing the node process. This halts block production and header verification on all honest nodes simultaneously, constituting **consensus divergence** — the chain stops advancing.

The corrupted value is the `baseFee` field of every subsequent block header: it can never be computed, so no valid block can be produced or accepted.

---

### Likelihood Explanation

The trigger is a governance vote from the governing node (semi-trusted actor in `governance.governancemode = "single"`). The governing node is a mutable, on-chain-designated role. The protocol accepts `kip71.gastarget = 0` through the full governance pipeline — `FormatChecker` passes, `checkConsistency` passes, the vote is embedded in a block header, and the parameter takes effect at the next epoch boundary. No additional privilege beyond holding the governing node key is required.

The inconsistency is notable: `kip71.basefeedenominator` has both a `FormatChecker` rejecting `0` and a runtime guard, demonstrating that the developers were aware of the division-by-zero risk for denominator-type parameters. The same protection was not applied to `kip71.gastarget`.

---

### Recommendation

1. **Add a `FormatChecker` for `Kip71GasTarget`** in `kaiax/gov/param.go` that rejects `0`, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
```

2. **Add a runtime guard in `NextMagmaBlockBaseFee`** in `params/kip71_config.go`, mirroring the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // Avoid division by zero; treat as if gas usage equals target
    return makeEvenByFloor(parentBaseFee)
}
```

### Proof of Concept

1. Governing node submits a header governance vote: `kip71.gastarget = 0`.
2. The vote passes `FormatChecker` (`noopFormatChecker` → always `true`) and `checkConsistency` (falls through to `return nil`).
3. At the next epoch boundary, the vote is applied; `GasTarget = 0` becomes the active parameter.
4. The next block is produced with any transactions (`parentGasUsed > 0`).
5. Every node calls `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)`.
6. `parentGasUsed > gasTarget (0)` → enters the `else if parentGasUsed > gasTarget` branch.
7. `y := x.Div(x, new(big.Int).SetUint64(0))` → Go runtime panic: `integer divide by zero`.
8. All nodes crash. Chain halts. Consensus divergence on all honest nodes. [6](#0-5) [7](#0-6)
