### Title
Webhook signature verification is scoped to `repository.owner.login`, not to the org that owns the mutated `repository.full_name` — authentication bypass via org/repo mismatch when the verifying org has no `webhook_secret` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` used to verify the HMAC signature solely from `repository.owner.login` (or `organization.login`), while the event handlers (e.g. `ReopenedHandler`) resolve and mutate the target `Repository`/`Stack` solely from `repository.full_name`. These two payload fields are never cross-checked against each other, so an attacker can pick any org whose `GitHubApp` has `webhook_secret` unset (which makes `verify_webhook_signature` return `true` unconditionally) and pair it with an arbitrary victim org's `repository.full_name` to unarchive/provision that victim's stack without ever passing a real signature check.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:

`verifying_org = repository_owner` (used to pick `Shipit.github(organization:)` for signature verification) **must equal** `owning_org = Repository#owner` for `params.repository.full_name` (the record actually mutated).

Code path:
- `WebhooksController#repository_owner` reads `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, both fully attacker-controlled JSON fields. [1](#0-0) 
- `#verify_signature` looks up `github_app = Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature`. [2](#0-1) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is not configured: `return true unless webhook_secret`. [3](#0-2) 
- `#create` then dispatches the raw, unsigned/unverified body to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [4](#0-3) 
- `ReopenedHandler#repository` resolves the actual repository from a completely different field, `params.repository.full_name`, not from `repository_owner`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [5](#0-4) 
- `#process` then calls `stack.unarchive!` (via `ReviewStackAdapter#unarchive!`, which can also `create!` a brand-new stack if the repo is provisioned as `allow_all` and no stack exists yet). [6](#0-5) [7](#0-6) 

Attacker's exact request: an unauthenticated POST to `/webhooks` with header `X-Github-Event: pull_request`, body:
```json
{
  "action": "reopened",
  "number": <existing PR number for the victim stack>,
  "repository": {"owner": {"login": "OrgTwo"}, "full_name": "victim-org/victim-repo"},
  "pull_request": {...minimal valid shape...},
  "sender": {"login": "attacker"}
}
```
where `OrgTwo` is any org configured in `Shipit.github` (multi-org config) whose `webhook_secret` is left blank — a configuration state the project's own templates/docs show as a common/default state (e.g. `secrets.development.shopify.yml`, `secrets.development.example.yml`, `docs/setup.md`, and the test fixture `test/dummy/config/secrets_double_github_app.yml` which explicitly has `OrgTwo`'s `webhook_secret: # nil`). [8](#0-7) 

Existing guards that fail to prevent this:
- `drop_unhandled_event` and `check_if_ping` don't check org/repo consistency at all. [9](#0-8) 
- `GithubOrganizationUnknown` only rejects orgs absent from config; it does nothing when the org exists but has no secret. [10](#0-9) 
- No handler cross-validates that `repository.owner.login`/`organization.login` equals the owner parsed out of `repository.full_name`.

Before the trace: it was assumed `verifying_org == owning_org` because in a legitimately-emitted GitHub webhook these fields always agree. After tracing the actual code, no code enforces this — the fields are read independently and can diverge under attacker control, and the divergence is not caught anywhere in the reachable path.

### Impact Explanation
An unauthenticated attacker can trigger `Stack#unarchive!` (and even provisioning of a brand-new review stack, via `ReviewStackAdapter#create!`) on any repository/org configured in Shipit, by simply routing the "signature verification" step to a different, secret-less org entry while naming the real victim repo in `repository.full_name`. This is a payload for one org mutating another org's stack, and it is fully repeatable against any repository with an existing or provisionable review stack, as long as at least one configured `GitHubApp` in the deployment has no `webhook_secret` set. This matches the Critical category: "authentication bypass (forged webhook accepted)... a payload for one repository mutating another's stack."

### Likelihood Explanation
Preconditions: multi-org Shipit deployment (`Shipit.github_organizations` with more than one entry) where at least one configured org's `GitHubApp` has no `webhook_secret` — a state the shipped example/dummy configs explicitly demonstrate as a default/blank value. Attacker cost is a single unauthenticated HTTP POST with a crafted JSON body; no secrets, tokens, or GitHub access required. It is fully repeatable against any victim repository with an active or `allow_all`-provisionable review stack. Given that unset `webhook_secret` appears to be the documented default/placeholder in templates, the precondition is realistic during onboarding of new organizations before their secret is configured.

### Recommendation
Do not select the verifying `GitHubApp` from attacker-controlled `repository.owner.login`/`organization.login` alone without binding it to the actual target of the mutation. At minimum: (1) require `webhook_secret` to be present for every configured org and refuse (422) any org lacking one instead of treating it as implicitly verified; (2) after resolving the handler's target `Repository` from `repository.full_name`, assert its `owner` matches the `repository_owner` used for signature verification before allowing any mutation.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "org with no webhook_secret cannot unarchive a different org's stack via full_name mismatch" do
  victim_stack = create_archived_stack_for("shopify/shipit-repo") # victim org "shopify", existing archived stack
  no_secret_app = Shipit::GitHubApp.new("OrgTwo", { webhook_secret: nil })
  Shipit.stubs(:github).with(organization: "OrgTwo").returns(no_secret_app)

  @request.headers['X-Github-Event'] = 'pull_request'
  body = {
    action: 'reopened',
    number: victim_stack.pull_request.number,
    repository: { owner: { login: 'OrgTwo' }, full_name: 'shopify/shipit-repo' },
    pull_request: { ...minimal valid pull_request shape... },
    sender: { login: 'attacker' }
  }.to_json

  # verifying_org ("OrgTwo") != owning_org ("shopify") -- binding is broken
  post :create, body: body, as: :json

  assert_response :ok
  assert_not victim_stack.reload.archived?, "victim stack was unarchived by an unverified request scoped to a different org"
end
```
Both sides of the equality: `verifying_org = "OrgTwo"` (unset secret, signature trivially accepted) vs `owning_org = "shopify"` (owner of `repository.full_name`) — they diverge, and `stack.unarchive!` still fires, proving the vulnerability.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
