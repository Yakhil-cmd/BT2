### Title
`cleanup_account_if_empty` can delete an account whose supply map was never loaded — debt-side flows using `get_account_borrow_only` wipe live supply positions - (File: contracts/controller/src/account.rs)

### Summary
The account/portfolio state is split into two position maps, `SupplyPositions` and `BorrowPositions`, mirroring the Notional `storedAssets`/`newAssets` split. `get_account_borrow_only` deliberately loads an account with an **empty** `supply_positions` map, and `persist_account_positions`/`cleanup_account_if_empty` then judge emptiness on that partial view. Any debt-side flow (e.g., `clean_bad_debt` / liquidation finalization) that persists with `remove_if_empty = true` will burn the NFT and delete `SupplyPositions` even when the user still holds collateral.

### Finding Description
`get_account_borrow_only` in `contracts/controller/src/storage/account.rs:167-172` builds an `Account` with `Map::new(env)` for supply, and its own doc warns: "The empty supply map does not prove supply is absent." However, the deletion helper `cleanup_account_if_empty` in `contracts/controller/src/account.rs:166-170` calls `account.is_empty()`, which checks both in-memory maps. On a borrow-only-loaded account, `supply_positions` is trivially empty, so once the last debt leg is cleared the account is treated as fully empty and `remove_account_and_burn_nft` executes.

`remove_account_entry` (`contracts/controller/src/storage/account.rs:250-256`) unconditionally removes `AccountMeta`, `SupplyPositions`, `BorrowPositions`, and `Delegates`, and `remove_account_and_burn_nft` then burns the position NFT (`account.rs:159-163`). The gate is reached through `persist_account_positions` (`contracts/controller/src/positions/mod.rs:153-170`), which writes only the side selected by `PositionSides` — with `PositionSides::Debt` the supply map is never re-persisted, so the real stored `SupplyPositions` entry is erased without ever having been read. This is the direct analog of `deleteAsset()` only considering one of the two asset arrays: the emptiness test and the delete operate on a state view that excludes half the portfolio.

### Impact Explanation
Permanent freezing / loss of user funds. If a debt-only flow (bad-debt cleanup, liquidation apply, or any path that loads the account borrow-only and persists `PositionSides::Debt` with `remove_if_empty = true`) runs against an account that still has nonzero scaled supply, the account's `SupplyPositions` entry and NFT are destroyed. The pool still holds the corresponding shares, but the user can no longer reach them — no entrypoint can recover collateral for a burned account ID. This satisfies the "permanent freezing of funds / theft of user funds" impact bar.

### Likelihood Explanation
Reachable by a single unprivileged address: `clean_bad_debt` and `liquidate` are permissionless entrypoints and operate on borrow-side state where a borrow-only load is the natural implementation (`get_account_borrow_only` exists precisely for that). The trigger requires the account to retain supply while its debt is fully removed in one flow — exactly the bad-debt write-down shape, where a victim retains dust collateral. The severity is gated on whether such a flow actually passes `remove_if_empty = true`; the supply/debt split, the partial-load helper, and the unconditional four-key delete are all confirmed in code, but I was unable to fully trace every `persist_account_positions` caller to confirm a `PositionSides::Debt` + `remove_if_empty` combination on a borrow-only-loaded account — that is the remaining verification step.

### Recommendation
Before deleting an account, reload or verify the real `SupplyPositions` entry from storage rather than trusting the in-memory map. Concretely: in `cleanup_account_if_empty`, either (a) require callers to pass a fully loaded account and assert it, or (b) check `get_supply_positions(env, account_id)` directly alongside `account.borrow_positions.is_empty()`. Additionally, have `persist_account_positions` skip `remove_if_empty` when `sides == PositionSides::Debt`, since a debt-only persist implies the supply side was never read.

### Proof of Concept
Conceptual sequence on a victim account `A` holding a nonzero supply position in `(hub, X)` and small residual debt in `(hub, Y)`:

1. Attacker calls `clean_bad_debt` (or completes a `liquidate` that zeroes debt) on `A`.
2. The flow loads `A` via `get_account_borrow_only` → `account.supply_positions` is an empty `Map`, `borrow_positions` holds the `Y` debt.
3. The debt leg is written down to zero; `update_or_remove_debt_position` removes `Y` → `borrow_positions` becomes empty.
4. `persist_account_positions(env, A, account, PositionSides::Debt, true)` → `cleanup_account_if_empty` sees `account.is_empty() == true`.
5. `remove_account_entry` deletes `SupplyPositions(A)` (which still contained the real `X` collateral) and `nft_burn_call` burns the account NFT.
6. Victim's supply shares are orphaned in the pool forever; `account_owner`/position lookups fail because the NFT no longer exists.

pub(crate) fn remove_account_entry(env: &Env, account_id: u64) {
    let persistent = env.storage().persistent();
    persistent.remove(&ControllerKey::AccountMeta(account_id));
    persistent.remove(&ControllerKey::SupplyPositions(account_id));
    persistent.remove(&ControllerKey::BorrowPositions(account_id));
    persistent.remove(&ControllerKey::Delegates(account_id));
}

/// Deletes the account and burns its NFT when both position maps are empty.
pub(crate) fn cleanup_account_if_empty(env: &Env, account: &Account, account_id: u64) {
    if account.is_empty() {
        remove_account_and_burn_nft(env, account_id);
    }
}

pub(crate) fn persist_account_positions(
    env: &Env,
    account_id: u64,
    account: &Account,
    sides: PositionSides,
    remove_if_empty: bool,
) {
    if sides != PositionSides::Debt {
        storage::set_supply_positions(env, account_id, &account.supply_positions);
    }
    if sides != PositionSides::Supply {
        storage::set_debt_positions(env, account_id, &account.borrow_positions);
    }
    storage::renew_user_account(env, account_id);
    if remove_if_empty {
        account::cleanup_account_if_empty(env, account, account_id);
    }
}
