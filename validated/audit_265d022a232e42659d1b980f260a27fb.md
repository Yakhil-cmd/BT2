### Title
Unallowlisted route venues execute attacker code under the caller's authorization tree, draining the victim's wallet - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The Script Security sandbox-bypass class maps onto XOXNO Lending as an *authorization-context bypass*: the controller's strategy swaps hand attacker-chosen route bytes to the configured router, which invokes arbitrary pool/token addresses named in the payload with no venue allowlist. Any third-party contract placed on that call stack executes *below* the caller's `require_auth` tree, so a token `transfer` it makes from the caller is recorded as a child of the caller's own authorization entry and executes once the caller signs the simulated tree. The loss is unbounded by `amount_in`, `min_out`, or the account risk gates — it is the victim's whole wallet.

### Finding Description
`swap_tokens` authorizes exactly one `token_in.transfer(controller, router, amount_in)` invocation via `authorize_transfer_as_current`, then calls `router.execute_strategy(controller, amount_in, swap)` with the caller-supplied `swap` payload under a flash guard [1](#0-0) . All six account strategies (`multiply`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `flash_position` helpers, `execute_strategy`) funnel through this helper.

The router decodes the payload and invokes whatever pool and token addresses the route names; it keeps no allowlist of venues or pools [2](#0-1) . The threat model states the consequence directly: "a route can put third-party code on the call stack below the caller's authorization. A token transfer that such code makes from the caller is recorded by an honest simulation as a child of the caller's authorization entry, and it executes if the caller signs that tree. The loss is then the caller's wallet, not the routed amount" [3](#0-2) .

Post-call checks do not contain this: `swap_tokens` only asserts `actual_spent <= amount_in` and positive measured `token_out` output (`RouterOverspend`/`NoSwapOutput`) — a rogue venue paying a fair `token_out` while simultaneously pulling an unrelated wallet token passes every check [4](#0-3) .

The harness test proves the end-to-end path: a `RogueHopPool` named by the route calls `wallet_token.transfer(alice → attacker, WALLET_BALANCE)`, and simulation records it as a child of Alice's `swap_collateral` root entry; Alice's wallet is drained while her account receives a fair `FAIR_OUT_ETH` output [5](#0-4) , [6](#0-5) .

### Impact Explanation
Theft of user funds. Any token the victim holds can be transferred to the attacker inside the victim's own `swap_collateral`/`swap_debt`/`multiply` authorization, regardless of `amount_in`, `min_out`, or account health. The victim's lending position can even remain healthy — the theft is orthogonal to the swap settlement checks.

### Likelihood Explanation
Reachable by a single unprivileged address: the attacker only needs to supply crafted route bytes (e.g., as a malicious route provider, phishing UI, or poisoned off-chain quote) that a victim executes via `swap_collateral`/`multiply`/`execute_strategy`. Simulation faithfully produces an auth tree that includes the theft as a child entry, and wallet clients that blindly sign simulated trees authorize it. The only mitigation is client-side: the user must decode the route and reject any auth tree with unexpected children — a burden the contracts do not enforce [7](#0-6) .

### Recommendation
Enforce the invariant on-chain rather than in client UX:
- In the router, restrict hop pool/token targets to a governance- or registry-managed allowlist, or to venues derivable from the route's declared `assets` registry only.
- Alternatively, isolate the swap by requiring strategy calls to originate from a dedicated per-user proxy/spender address that holds no other funds and no standing authorization, so a rogue child call cannot reach the caller's wallet.
- At minimum, surface the signed auth tree's sub-invocations in the SDK/quote flow and refuse routes producing more children than the single expected input transfer.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a complete PoC: `UnlistedPoolRouter::execute_strategy` invokes the `swap` function on the `hop_pool` address named in the payload [8](#0-7) ; `RogueHopPool::swap` transfers `WALLET_BALANCE` of an unrelated token from Alice to the attacker [5](#0-4) ; the test asserts the stolen transfer is recorded as a `sub_invocation` of Alice's `swap_collateral` auth entry and that `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE` while `supply_balance_raw(ALICE, "ETH") == FAIR_OUT_ETH` [9](#0-8) .

/// Passes matching assets through only with an empty route; otherwise swaps.
pub(crate) fn swap_tokens_or_passthrough(
    env: &Env,
    refund_to: &Address,
    token_in: &Address,
    amount_in: i128,
    token_out: &Address,
    swap: &StrategySwap,
) -> i128 {
    if token_in == token_out {
        assert_with_error!(env, swap.is_empty(), GenericError::InvalidPayments);
        amount_in
    } else {
        swap_tokens(env, refund_to, token_in, amount_in, token_out, swap)
    }
}

/// Returns the output balance increase; rejects zero or negative receipts.
fn verify_router_output(env: &Env, token_out: &Address, balance_before: i128) -> i128 {
    let received = balance_delta_since(
        env,
        token_out,
        &env.current_contract_address(),
        balance_before,
    );
    assert_with_error!(env, received > 0, StrategyError::NoSwapOutput);
    received
}

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
