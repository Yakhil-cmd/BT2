### Title
Git pathspec-magic injection via attacker-named files causes review scope to escape/exclude intended diff targets - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`get_git_diff` builds its `git diff` command by splicing raw, unescaped repo-relative filenames after `--` via `_diff_pathspec`, without disabling git's pathspec "magic" syntax (`:(exclude)`, `:(glob)`, `:(top)`, etc.) or wrapping entries in `:(literal)`. A repo-controlled filename that happens to start with `:` is passed through untouched, letting an attacker who can introduce arbitrary filenames into the working tree (e.g. via an agent-driven edit, PR checkout, or untracked file) turn one of the diff-scoping pathspec entries into a pathspec-magic directive that excludes/redirects the diff away from the intended target file.

### Finding Description
`_diff_pathspec` in [1](#0-0)  only guards against symlink/`realpath`-based traversal (`r.startswith("..")` after resolving `os.path.realpath`), but performs no escaping or literal-pathspec enforcement on the resulting relative path strings before they are appended to the pathspec list. `get_git_diff` then splices that list directly after `--` in the `git diff` command: [2](#0-1) , and `GIT_CMD` never sets `--literal-pathspecs` or `GIT_LITERAL_PATHSPECS`: [3](#0-2) .

Git treats any pathspec argument beginning with `:` as the start of a "magic signature" (e.g. `:(exclude)`, `:(icase)`, `:(glob)`, `:(top)`) rather than a literal path, unless `--literal-pathspecs`/`:(literal)` is used. Filenames beginning with `:` are legal on POSIX filesystems and are tracked by git normally (`core.quotePath=false`, used by `_git_status_porcelain` and `_git_name_only`, only affects display quoting of special/non-ASCII bytes, not the semantic meaning git assigns to a leading `:`).

The call chain is: `handle_stop_hook` → `compute_v2_review_set` (produces `review_paths`, `untracked_paths` derived from `git status --porcelain`, which is repo-content-controlled) → `get_git_diff(repo_root, content_base, paths=review_paths, untracked_paths=untracked)` [4](#0-3)  → `_diff_pathspec`. If the repo (attacker-controlled content, e.g. code an autonomous coding agent or PR content creates) contains a file whose repo-relative path begins with `:`, that raw string is passed through `_diff_pathspec` unmodified and lands in the pathspec list. Because `r.startswith("..")` cannot detect this (a `:`-prefixed string doesn't start with `..`), the existing guard does not stop it.

Depending on the exact magic used (e.g. `:(exclude)<target-file>` crafted to collide with, or combined alongside, an intended review-set entry), this can cause `git diff -- ... :(exclude)<real-target> ...` to silently drop the actually-modified sensitive file from the diff text that is handed to `parse_diff_into_files`/the LLM security reviewer, even though `review_paths` correctly listed it as dirty. The net effect: the diff-scoping invariant ("git path scoping must never escape the intended repo target") is violated — the pathspec set passed to `git diff` no longer corresponds 1:1 to `review_paths`, and a maliciously introduced change can be excluded from the content actually reviewed for security issues.

### Impact Explanation
This lets attacker-controlled repository content weaken/bypass the security-review guard (the Stop-hook's automated code-security reviewer) that is supposed to inspect every file in the turn's diff. By naming a colon-prefixed decoy/companion file appropriately, a change to a real target file can be excluded from the diff text sent downstream, so the guard's enforcement is effectively bypassed for that file's content — matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state."

### Likelihood Explanation
Feasible without any elevated privilege: the attacker only needs the ability to get a colon-prefixed filename into the working tree that git will report as changed/untracked (e.g. via a crafted PR checked out and edited by an agent, or an agent asked to create such a file). No symlink tricks or unicode normalization needed — a plain leading `:` is legal on Linux/macOS filesystems and git tracks it fine. The bug is deterministic and repeatable given such a file exists in `review_paths`/`untracked_paths` at Stop-hook time.

### Recommendation
In `_diff_pathspec`, force literal interpretation of every pathspec entry, e.g. prefix each relative path with `:(literal)` (or pass `--literal-pathspecs` / set `GIT_LITERAL_PATHSPECS=1` in the environment used for the `git diff`/`git add` subprocess calls in `gitutil.py`). Apply the same treatment to any other pathspec-splicing helper (`_git_name_only`, `_temp_index`'s `git add -- <paths>`) so untracked-file targeting can't be hijacked either.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Create a temp git repo; commit an initial file `real_target.py` with `SECRET = "safe"`.
2. Create baseline SHA (stash/HEAD).
3. Modify `real_target.py` to add a vulnerable pattern (e.g. `eval(user_input)`).
4. Also create an untracked file literally named `:(exclude)real_target.py` (or `:(top)real_target.py` per git version) alongside it.
5. Call `compute_v2_review_set` to obtain `review_paths` (expect it to include `real_target.py`) and pass both `real_target.py` and the colon-prefixed file's realpath into `get_git_diff(repo_root, baseline_sha, paths=review_paths + [colon_file_abs_path], untracked_paths=...)`.
6. Assert (current buggy behavior): the returned diff text does NOT contain the `eval(user_input)` change for `real_target.py`, even though `git status`/`review_paths` show it as dirty — demonstrating the pathspec-magic entry suppressed the intended target from the diff.
7. After applying the `:(literal)` fix, re-run the same test and assert the diff text DOES contain the `real_target.py` change, confirming the pathspec no longer escapes/excludes the intended scope.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
