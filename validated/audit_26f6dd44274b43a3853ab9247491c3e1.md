### Title
Every `liquidate` offer reverts for a solvent-but-underwater account whose only collateral leg is a sub-3-decimal asset while its debt sits in the whole-unit quote band - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
Analogous to CVE-2018-3280 (a reachable input state that hangs/crashes processing), a borrower can leave its account in a state where *every* liquidation attempt reverts with `InvalidPayments`, freezing both the borrower's collateral and the debt positions against the pool until accrual or a price move escapes the band. `whole_unit_repayment` in `contracts/controller/src/positions/liquidation/math.rs:235-290` raises the partial quote for a single-supply, sub-3-decimal leg only under two rules: a full close (`unit_at_bonus >= D + R`) or a raise to `ceil((U + margin) / (1 + b))` when `raised < D`. When `unit_at_bonus - R < D <= raised` neither rule applies; if the curve quote then backs less than one whole unit, seizure rounds to zero units, the leg is dropped, and `build_liquidation_plan` produces a plan with no seizure legs that fails `plan.validate` / settlement with `InvalidPayments` for every offer size.

### Impact Explanation
An unprivileged borrower supplies a low-decimal collateral (< 3 decimals, e.g., a 0-2 decimal token) as its only supply position and borrows so that, after interest accrual, total debt `D` lands in `floor(U/(1+b)) - R < D <= ceil((U+m)/(1+b))` with the curve quote backing less than one unit. Any liquidator calling `liquidate` — regardless of offered payment — reverts, so the position cannot be liquidated and pool funds owed by that account are temporarily frozen (the protocol cannot collect on underwater debt). This is a live transaction-level DoS on `liquidate`, matching the crash/hang class of CVE-2018-3280, and the outcome is temporary freezing of funds rather than mere fail-closed input rejection: the revert depends on attacker-constructed account state, not on the caller's arguments.

### Likelihood Explanation
The band width is `raised - (unit_at_bonus - R) ≈ margin + R` WAD — small, but debt drifts upward deterministically through it via millisecond-chunked interest accrual, so no precise landing is required; any account borrowed near the boundary will pass through the band. The window ends when accrual pushes `D` above `raised` or a price move changes `U`, so the freeze is temporary. Docs (`docs/reference/formulas.md:305-308`, `docs/reference/invariants.md:433-437`) describe the band and state the account "stays liquidatable below HF = 1" with this exception, indicating an acknowledged residual gap rather than an intended safety property — an underwater account that cannot be liquidated is not a designed outcome.

### Recommendation
When `D` falls in the band (`unit_at_bonus - R < D <= raised`) and the curve quote backs less than one unit, promote the quote to `D` (full close taking the whole held units) or to `raised` even though `raised <= D` is false — i.e., allow the raised quote to exceed `D` as a full-close seizure of one unit — so at least one offer size always produces a non-empty seizure leg. Alternatively, treat `raised >= D` in rule 2 as a full close, merging it into rule 1's outcome.
