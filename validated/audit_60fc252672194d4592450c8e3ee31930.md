### Title
Permissionless pool creation lets an attacker front-run and permanently squat the deterministic `pool_state` PDA, hijacking the creator-fee revenue stream - (File: `programs/cp-swap/src/instructions/initialize.rs`)

### Summary
`initialize` in `programs/cp-swap/src/instructions/initialize.rs` is fully permissionless — any signer can call it — and it derives the `pool_state` PDA deterministically solely from `amm_config`, `token_0_mint`, and `token_1_mint`. Because the identifier is entirely predictable and not bound to the caller (unlike a commit/reveal or per-creator seed), an attacker watching the mempool can front-run a legitimate project's pool-creation transaction for the same token pair, exactly analogous to the Audius `ServiceProviderFactory.register` endpoint-squatting bug.

### Finding Description
`create_pool` computes the pool PDA as: [1](#0-0) 

This PDA is independent of `msg.sender`/`creator`, so whoever's `initialize` transaction lands first claims the PDA. The `creator` account is recorded immutably into `PoolState` at creation time via `pool_state.initialize(...)`: [2](#0-1) [3](#0-2) 

That recorded `pool_creator` is the sole beneficiary of the ongoing "creator fee" cut of every swap, and is the only signer authorized to withdraw it via `collect_creator_fee` (or anyone can trigger `collect_creator_fee_permissionless`, but funds always flow to the stored `pool_creator`): [4](#0-3) [5](#0-4) 

Because the token-pair/config PDA can only be initialized once (`create_pool` requires `pool_account_info.owner == system_program::ID`, i.e., not yet initialized), an attacker who front-runs the legitimate project's `initialize` call for the same `(amm_config, token_0_mint, token_1_mint)` permanently occupies that PDA. The legitimate deployer's subsequent `initialize` transaction reverts (`NotApproved`/ownership check fails), and they are forced either to abandon that token pair or use a different `amm_config` index, fragmenting liquidity for the token they are launching. Meanwhile the attacker, having seeded the pool with only the minimum tokens required to pass `CurveCalculator::validate_supply`, becomes the perpetual `pool_creator` and collects the creator-fee share of every trade that flows through that pool going forward via `collect_creator_fee`/`collect_creator_fee_permissionless`.

### Impact Explanation
This is a direct analog of the Audius `register` front-running bug class: a permissionless, first-come-first-served identifier registration (an `_endpoint`/here a `(amm_config, token_0_mint, token_1_mint)` PDA) can be squatted by an attacker who observes the mempool, at low cost (only minimal initial liquidity, no meaningful stake requirement here since there's no slashing mechanism at all). Unlike Audius, there is no lockup/slashing risk mitigating the attacker's position — once the attacker's `initialize` lands, they permanently and unremovably own the `pool_creator` role and its associated fee stream for that pool, which is an unauthorized privileged effect (siphoning fee revenue intended for the legitimate project) and a form of ongoing value extraction from all future traders/LPs of that pool, since creator fees are deducted from swap outputs before LPs and protocol.

### Likelihood Explanation
Likelihood is moderate-to-high: pool creation transactions for a specific, anticipated token launch are easy to identify in the public mempool (`initialize` calls reference the token mints being launched), and front-running only requires submitting a competing `initialize` with the same `token_0_mint`/`token_1_mint`/`amm_config` and higher priority fee/compute budget — a standard, well-understood Solana front-running technique. The attacker's cost is only the minimum token amounts needed to satisfy `CurveCalculator::validate_supply`, which can be trivially small.

### Recommendation
Bind pool ownership/creator identity to the initiating signer at the protocol level in a way that cannot be squatted, e.g.:
- Require the `creator`/`payer` to pre-commit (commit/reveal) to the token pair before allowing `initialize`, or
- Allow governance/the legitimate project to permissionlessly reclaim/transfer `pool_creator` for a pool it did not intend to create if it was created by an unrelated, un-vetted party (e.g., via the existing `Permission`/`create_permission_pda` mechanism used by `initialize_with_permission`), or
- Make the `initialize_with_permission` path (which already gates callers via `Permission` PDA) the default/only route for launches where creator-fee assignment matters, rather than leaving fully-permissionless `initialize` as the mechanism that assigns a permanent fee-earning role.

### Proof of Concept
1. Project A prepares a transaction calling `initialize` for `token_0_mint = X`, `token_1_mint = Y`, under `amm_config` index `0`, intending to become `pool_creator`.
2. Attacker monitors the mempool, observes this transaction referencing mints `X`/`Y`.
3. Attacker submits their own `initialize` transaction with the same `amm_config`, `token_0_mint = X`, `token_1_mint = Y`, minimal `init_amount_0`/`init_amount_1`, and a higher priority fee, so it lands first — see PDA derivation at [1](#0-0) .
4. `create_pool` succeeds for the attacker's transaction (account was still system-owned), and `pool_state.initialize(...)` records the attacker as `pool_creator` — [3](#0-2) .
5. Project A's `initialize` transaction now fails because `pool_account_info.owner != system_program::ID` no longer holds true / PDA already initialized — see the ownership check at [6](#0-5) .
6. Traders unaware of the squat trade against this pool; the attacker permanently collects the accrued `creator_fees_token_0`/`creator_fees_token_1` via `collect_creator_fee`/`collect_creator_fee_permissionless` — [7](#0-6) .

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;
```
