### Title
Signer-level reward-per-token snapshot frozen when signer has zero shares lets a newly-staked staker retroactively claim sBTC rewards accrued before they staked - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`settle-rewards` in `pox-5.clar` only refreshes the per-signer, per-cycle reward-per-token checkpoint (`signer-rewards-per-token-for-cycle`) when the signer currently has non-zero shares staked. When a signer's shares are zero (e.g., all delegated stakers have withdrawn), the checkpoint is left stale even though the global `rewards-per-token-for-cycle` accumulator keeps advancing as `calculate-rewards`/`calculate-bond-rewards` distribute new sBTC. This is the same "cumulative accumulator not updated on the zero branch" bug class described in the Malt `RewardThrottle._sendToDistributor()` report, and it produces double-counted/unearned rewards instead of merely retained capital.

### Finding Description
`settle-rewards` is documented to be called before any change to a signer's staked shares: [1](#0-0) 

Its body reads the signer's *current* (pre-update) shares and the fresh global `rewards-per-token-for-cycle`, then conditionally writes the signer-level snapshot only if shares are non-zero: [2](#0-1) 

Because the shares value inspected is the value *before* the pending stake/unstake action, the very first time a new staker joins a signer that currently has zero staked shares, `shares` is `0`, so `signer-rewards-per-token-for-cycle` is **not** advanced to the current true global rate — it stays at whatever (possibly much older, possibly default `u0`) value it last held. The new staker's own checkpoint is then written via `settle-staker-rewards`/`get-earned-staker-rewards`, both of which read this same stale signer-level value as `rpt-current`: [3](#0-2) 

`compute-earned-rewards` computes `earned = pending + shares * (rpt-current - rpt-paid) / PRECISION`. Once the signer's checkpoint is finally advanced later (the next time shares happen to be non-zero when `settle-rewards` runs), the jump from the old, stale value to the true current global rate is attributed entirely to whoever holds shares at that moment — including a staker who only joined *after* the period during which that delta actually accrued. In effect, the newly-joined staker receives sBTC rewards for a period during which they had zero stake, at the expense of the shared reward pool / other genuine earners.

### Impact Explanation
This breaks the equality that "sBTC rewards paid must equal rewards actually earned by staked capital during the staking period." A staker can receive rewards for a period before their stake existed, which is a form of unearned/double-counted reward payout drawn from the same finite reward pool that legitimate stakers and bonds are also drawing from. This matches the in-scope "sBTC rewards paid that were not earned or counted twice" criterion and rises to at least a High-severity issue (temporary/permanent misallocation of reserve funds via unearned reward credit), potentially Critical if it can be repeated to drain rewards intended for other stakers.

### Likelihood Explanation
No privileged role is needed — any unprivileged staker/signer path that causes a signer's staked shares to go from zero to non-zero (e.g., a signer's last delegated staker exits, then a new staker delegates to that same signer for the same reward cycle/bond index while rewards continue to accrue via `calculate-rewards`) triggers the stale-checkpoint condition. This is a normal, reachable sequence of unprivileged stacking operations, not a contrived edge case, though it requires a specific but realistic sequence (signer's shares hit zero, global rewards accrue further via `calculate-rewards`, then a new staker joins that signer).

### Recommendation
`settle-rewards` should always refresh `signer-rewards-per-token-for-cycle` to the current global `rewards-per-token-for-cycle` regardless of whether `shares` is currently zero (mirroring the Malt fix of always updating the cumulative accumulator even when the incremental amount/shares is zero), so that any staker joining afterward starts their checkpoint from the true current rate rather than a stale lower one.

### Proof of Concept
1. Signer S has one delegated staker A with shares > 0 for `reward-cycle` C, `bond-index` B. `calculate-rewards`/`calculate-bond-rewards` runs, advancing `rewards-per-token-for-cycle` (C, B) to `R1`. Staker A unstakes; prior to the shares update, `settle-rewards` runs with `shares > 0`, correctly syncing `signer-rewards-per-token-for-cycle` (S, C, B) to `R1`. Shares then drop to 0.
2. More sBTC rewards accrue and `calculate-rewards` advances the global `rewards-per-token-for-cycle` (C, B) to `R2 > R1` (e.g., other signers'/bonds' activity, or reserve inflow attributed to this cycle/bond).
3. A new staker D delegates to signer S for the same cycle/bond. Before D's shares are recorded, `settle-rewards` runs with `shares == 0` (signer S currently has none), so per lines 2559-2568 the signer-level snapshot is **not** updated — it remains `R1`, not `R2`.
4. `settle-staker-rewards`/`get-earned-staker-rewards` write D's own checkpoint (`staker-rewards-per-token-settled-for-cycle`) using `rpt-current = R1` (the stale signer snapshot), even though the true current rate is `R2`.
5. Later, once the signer's shares become non-zero again in a future `settle-rewards` call, `signer-rewards-per-token-for-cycle` (S, C, B) jumps directly from `R1` to the then-current global rate (say `R3 ≥ R2`), and D's `compute-earned-rewards` now credits D with `shares_D * (R3 - R1) / PRECISION`, which includes the `R2 - R1` portion of rewards that accrued strictly before D ever staked with signer S — rewards D never earned.

;; Pure math formula for computing rewards earned since the last snapshot
;;
;; `earned = (shares * (rpt - rptPaid)) / PRECISION + pending`
(define-read-only (compute-earned-rewards
        (shares uint)
        (rpt-current uint)
        (rpt-paid uint)
        (pending uint)
    )
    (+ pending (/ (* shares (- rpt-current rpt-paid)) PRECISION))
)

(define-private (settle-rewards
        (signer principal)
        (reward-cycle uint)
        (bond-index (optional uint))
    )
    (let (
            (shares (get-signer-shares-staked-for-cycle signer reward-cycle bond-index))
            (rewards-per-token (get-rewards-per-token-for-cycle reward-cycle bond-index))
            (earned (compute-earned-rewards
                shares
                rewards-per-token
                (get-signer-rewards-per-token-settled-for-cycle signer reward-cycle bond-index)
                (get-signer-unclaimed-rewards-for-cycle signer reward-cycle bond-index)
            ))
        )
        (map-set signer-unclaimed-rewards-for-cycle {
            reward-cycle: reward-cycle,
            bond-index: bond-index,
            signer: signer,
        }
            earned
        )
        (map-set signer-rewards-per-token-settled-for-cycle {
            reward-cycle: reward-cycle,
            bond-index: bond-index,
            signer: signer,
        }
            rewards-per-token
        )
        (if (> shares u0)
            (map-set signer-rewards-per-token-for-cycle {
                signer: signer,
                reward-cycle: reward-cycle,
                bond-index: bond-index,
            }
                rewards-per-token
            )
            true
        )
        {
            earned: earned,
            rewards-per-token: rewards-per-token,
        }
    )
)
