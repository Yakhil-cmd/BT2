The reported CVE describes an SSRF/DNS-rebinding bypass in MindsDB, where user-supplied URLs reach an internal HTTP client without host/IP revalidation after DNS resolution. Looking for an analogous "attacker-controlled URL/host reaches an internal network client without proper validation" pattern in the Polkadot SDK, the only network-fetching client I could find is the offchain worker HTTP API [1](#0-0)  and its runtime-facing wrapper [2](#0-1) .

This does not qualify as an analog under the required threat model for the following reasons:

- There is no real, unprivileged user entry point (signed extrinsic, XCM message, or contract call) that lets an external attacker supply an arbitrary URL for a node to fetch. The `uri` parameter to `http_request_start` originates from the runtime WASM code itself (i.e., logic authored/deployed by the chain's own developers), not from an attacker-supplied extrinsic payload [3](#0-2) .
- Offchain workers only run when explicitly enabled by the node operator, and the HTTP capability itself is opt-in and gated by `enable_http_requests` in the client, meaning the "attacker" would need to already control what code is compiled into the runtime — a privileged-actor scenario explicitly excluded by the review method [4](#0-3) .
- The libp2p/litep2p networking stack (a separate, unrelated subsystem) already defaults to the system DNS resolver rather than a hardcoded public resolver, and multiaddress validation restricts what host/IP forms are accepted for dialing, which is the closest analog to "DNS rebinding protection" in this codebase, but it operates on peer-to-peer connection addresses configured by node operators/bootnodes, not on attacker-supplied extrinsic data [5](#0-4) [6](#0-5) .

Since no reachable path exists where an ordinary signed-extrinsic user, permitted XCM message, or contract call can supply a URL/host that a Polkadot SDK node will dereference on their behalf (the defining element of the SSRF/DNS-rebinding bug class), there is no demonstrable analog meeting the required entry-point and attacker-capability criteria.

	/// Mimics the corresponding method in the offchain API.
	pub fn request_start(&mut self, method: &str, uri: &str) -> Result<HttpRequestId, ()> {
		// Start by building the prototype of the request.
		// We do this first so that we don't touch anything in `self` if building the prototype
		// fails.
		let (body_sender, receiver) = mpsc::channel(0);
		let body = StreamBody::new(receiver);
		let body = BoxBody::new(body);
		let mut request = hyper::Request::new(body);
		*request.method_mut() = hyper::Method::from_bytes(method.as_bytes()).map_err(|_| ())?;
		*request.uri_mut() = hyper::Uri::from_maybe_shared(uri.to_owned()).map_err(|_| ())?;

		let new_id = self.next_id;
		debug_assert!(!self.requests.contains_key(&new_id));
		match self.next_id.0.checked_add(1) {
			Some(new_id) => self.next_id.0 = new_id,
			None => {
				tracing::error!(
					target: LOG_TARGET,
					"Overflow in offchain worker HTTP request ID assignment"
				);
				return Err(());
			},
		};
		self.requests
			.insert(new_id, HttpApiRequest::NotDispatched(request, body_sender));

		tracing::trace!(
			target: LOG_TARGET,
			id = %new_id.0,
			%method,
			%uri,
			"Requested started",
		);

		Ok(new_id)
	}

	/// Send the request and return a handle.
	///
	/// Err is returned in case the deadline is reached
	/// or the request timeouts.
	pub fn send(self) -> Result<PendingRequest, HttpError> {
		let meta = &[];

		// start an http request.
		let id = sp_io::offchain::http_request_start(self.method.as_ref(), self.url, meta)
			.map_err(|_| HttpError::IoError)?;

		// add custom headers
		for header in &self.headers {
			sp_io::offchain::http_request_add_header(id, header.name(), header.value())
				.map_err(|_| HttpError::IoError)?
		}

		// write body
		for chunk in self.body {
			sp_io::offchain::http_request_write_body(id, chunk.as_ref(), self.deadline)?;
		}

		// finalize the request
		sp_io::offchain::http_request_write_body(id, &[], self.deadline)?;

		Ok(PendingRequest { id })
	}
