### Title
Webhook signature verification failure does not stop handler dispatch (missing `throw(:abort)`) - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` calls `head(422)` when `GitHubApp#verify_webhook_signature` returns `false`, but `head` never halts the Rails callback chain — only `throw(:abort)` does since Rails 5. Because the `before_action` chain is not aborted, `WebhooksController#create` still executes and dispatches the event to every registered `Shipit::Webhooks` handler even though the signature check failed, meaning an attacker who can reach `POST /webhooks` with an unsigned or badly signed payload can still trigger real side effects (GitHub syncs, review-stack provisioning, team/membership mutation, etc.).

### Finding Description
The binding the code is supposed to guarantee is: `verify_signature succeeds == handler.call(params) is invoked` for any event that has a registered handler.

```ruby
before_action :check_if_ping, :drop_unhandled_event, :verify_signature

def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end

def verify_signature
  ...
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  head(422) unless verified
  ...
end
``` [1](#0-0) [2](#0-1) 

`head(status)` (from `ActionController::Head`) only overwrites `self.status` / `self.response_body`; it does not set `performed?` in a way that halts the `before_action` chain, and it does not `throw(:abort)`. In Rails ≥ 5 (this app runs `config.load_defaults 8.1`, i.e. Rails 8) [3](#0-2)  a `before_action` only stops the remaining chain (and the action) if it explicitly calls `throw(:abort)`. Simply calling `head`/`render` inside a `before_action` no longer halts execution. `check_if_ping` and `verify_signature` both use bare `head(...)` with no `throw(:abort)` and no `return false`-based halting configured anywhere in this engine [4](#0-3) .

Consequently, when `drop_unhandled_event` has already determined a handler exists for the event (`Shipit::Webhooks.for_event(event).present?`) [5](#0-4) , a subsequent signature failure in `verify_signature` no longer prevents `create` from running: `create` re-parses the body and invokes every handler for that event, then calls `head(:ok)`, overwriting the 422 status set moments earlier. The equality "signature verified == handler dispatch permitted" is broken: dispatch happens unconditionally once a handler exists, independent of the signature outcome.

An attacker who is an unprivileged internet user can `POST /webhooks` with:
- `X-Github-Event: push` (or `pull_request`, `membership`, `status`, `check_suite`, etc. — any event with a registered handler, e.g. `Shipit::Webhooks::Handlers::PushHandler`) [6](#0-5) 
- an arbitrary/garbage `X-Hub-Signature` header (or none at all)
- a JSON body naming `repository.owner.login` as any organization Shipit already knows about (this is public information, not a secret — it's simply the name of the organization the Shipit instance is configured for)

`verify_webhook_signature` will correctly return `false`, `head(422)` is set, but because the chain isn't aborted, `create` still runs `Shipit::Webhooks.for_event('push').each { |handler| handler.call(params) }`, which for `push` calls `stack.sync_github(expected_head_sha: params.after)` for every non-archived stack on the named branch — with attacker-controlled `after` sha — with no valid signature at all.

Existing guards do not stop this: `check_if_ping` and `drop_unhandled_event` also don't halt via `throw(:abort)`, so they can't compensate; `ExplicitParameters` on the handler only validates payload shape, not authenticity; there is no `force_github_authentication`/`require_permission!` gate on this controller since it's explicitly meant to be an unauthenticated webhook receiver secured only by the HMAC signature.

### Impact Explanation
Any handler registered in `Shipit::Webhooks.handlers` can be invoked with attacker-supplied JSON without a valid GitHub HMAC signature, for any repository/organization the attacker names. Concretely this allows an unauthenticated actor to force `GithubSyncJob`-style resyncs, membership/team mutations (`membership` handler creates/deletes `Team`/`Membership`/`User` records) [7](#0-6) , and pull-request driven review-stack provisioning/close actions, all cross-tenant (any repository/org name can be supplied in the payload, not just ones the attacker controls). This is a webhook authentication bypass — a forged webhook is accepted and drives real state changes — matching the Critical category ("authentication bypass (forged webhook ... accepted)").

### Likelihood Explanation
No secrets are required: the attacker only needs network access to the public `/webhooks` endpoint, a valid `X-Github-Event` header naming a handled event, and a JSON body whose `repository.owner.login`/`organization.login` matches an organization the Shipit instance already serves (public knowledge, e.g. visible in Shipit's own UI/URLs). No session, API token, GitHub App key, or `webhook_secret` is needed. This is trivially repeatable and requires only standard `curl`/HTTP tooling.

### Recommendation
In `app/controllers/shipit/webhooks_controller.rb`, make `verify_signature`, `check_if_ping`, and `drop_unhandled_event` actually halt the callback chain by using `throw(:abort)` (or `head(422); throw(:abort)` explicitly, or converting these methods to `render`/`head` followed by `throw(:abort)`), e.g.:
```ruby
def verify_signature
  ...
  unless verified
    head(422)
    throw(:abort)
  end
  ...
end
```
Apply the same fix to `check_if_ping` and `drop_unhandled_event`.

### Proof of Concept
In `test/controllers/webhooks_controller_test.rb`, add:
```ruby
test "handler is NOT invoked when signature verification fails" do
  request.headers['X-Github-Event'] = 'push'
  payload = JSON.parse(payload(:push_master)).to_json

  spy_handler = mock
  spy_handler.expects(:call).never
  Shipit::Webhooks.handlers["push"] = [spy_handler]

  Shipit.github(organization: 'shopify').stubs(:verify_webhook_signature).returns(false)

  post :create, body: payload, as: :json

  assert_response :unprocessable_entity
end
```
Both sides of the binding are asserted: `verified == false` (via the stub) on the left, and `spy_handler.call` must never be invoked on the right (`.never`). Given the current implementation (`head(422) unless verified` with no `throw(:abort)`), this test fails because `create` still runs and calls `spy_handler.call(params)`, proving the divergence.

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

      head(:ok) if event == 'ping'

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
