### Title
Measured-withdrawal input makes the router's absolute `total_min_out` floor unpredictable, so `repay_debt_with_collateral` can revert and leave the borrower unable to repay - (File: contracts/controller/src/strategies/legs.rs)

### Summary
The external report describes a repay path that slippage-checks a token amount the borrower cannot predict (the post-swap `saleToken` remainder), causing frequent reverts. XOXNO Lending has the same shape in `repay_debt_with_collateral`: the controller does not swap the caller-quoted `collateral_amount` — it swaps the *measured* balance delta of the collateral withdrawal and pushes it through the aggregator, which enforces an absolute `total_min_out` floor encoded in the route for the *quoted* amount. Any shortfall between the measured input and the quoted input reverts the entire repayment.

### Finding Description

`repay_via_collateral_swap` calls `withdraw_and_swap_from_supply`, which withdraws `collateral_amount` to the controller, measures the balance delta (`actual_withdrawn`), and hands exactly that measured receipt to `swap_tokens_or_passthrough` / `swap_tokens` as `amount_in` [1](#0-0) . The router then enforces `total_out < total_min_out → SlippageExceeded` where `total_min_out` is an absolute floor indexed from the payload's `amounts` registry [2](#0-1) .

The borrower, however, cannot know `actual_withdrawn` when building the route:

- The withdrawal is paid out of RAY-scaled supply shares with floor/ceil unscaling against a millisecond-accruing supply index, so the measured payout of `collateral_amount` base units can be less than the quoted amount.
- `collateral_amount` may be the withdraw-all sentinel (`i128::MAX` / `WITHDRAW_ALL_SENTINEL`), in which case the input is literally unknowable at quote time — the project's own composition docs acknowledge that "`amountOutMin` stays the absolute floor encoded for the quoted amount. A smaller actual input can give an output below that floor and revert with `SlippageExceeded`" [3](#0-2) .

The same measured-receipt-vs-absolute-floor mismatch exists for `swap_debt` and `multiply`, whose router input is the measured flash-loan receipt net of the pool's flash fee (`swap_amount_in = amount_received + debt_extra`), not the gross `debt_to_flash_loan` the caller supplies [4](#0-3) .

A further wrinkle matching the report's "saleToken becomes 0 → revert" case: `verify_router_output` asserts `received > 0` with `NoSwapOutput` [5](#0-4) , and the router also panics if `total_min_out <= 0`, so a zero/minimal-output leg can never succeed even when the borrower would accept it [6](#0-5) .

### Impact Explanation
An unprivileged borrower calling `repay_debt_with_collateral` — the only path that repays debt out of collateral atomically — sees the transaction revert whenever the measured withdrawal input produces less than the quoted `total_min_out`. The debt stays open and keeps accruing interest toward liquidation; each retry burns fees. For `close_position: true` the revert additionally blocks `execute_withdraw_all`, temporarily freezing the borrower's ability to exit. With `swap_debt`, a borrower trying to refinance a deteriorating debt position is similarly reverted, because the router input (net of the flash fee) is smaller than the gross amount they sized the quote's `min_out` against.

### Likelihood Explanation
Deterministic whenever the quoted `amountOutMin` is calibrated to the nominal `collateral_amount`/`newDebtAmount` rather than the measured receipt: index accrual, floor unscaling on share withdrawal, the flash-loan fee deduction, or a withdraw-all sentinel all shrink the router's actual input. Because Soroban execution is atomic there is no partial fill — a one-unit shortfall reverts the whole repay. The borrower can recover only by re-quoting with a lower (but still strictly positive) `min_out`, which partially defeats the slippage protection the mechanism exists to provide.

### Recommendation
Slippage-check the leg the caller controls, not the measured remainder: enforce the min-out floor inside the router against a *relative* bound (e.g., `min_out` scaled by `credited_in / total_in`, or a PPM-of-input floor analogous to the existing `Mode::Ppm` splits) so a slightly smaller measured input proportionally lowers the floor instead of reverting. Alternatively, the controller could pass the measured `actual_withdrawn` back to the caller's expectation (a `min_debt_repaid`/`min_out` argument on the verb itself) rather than relying on an absolute floor baked into off-chain route bytes that predate the measurement.

### Proof of Concept
1. Borrower supplies XLM, borrows USDC; calls `repay_debt_with_collateral` with `collateral_amount` sized to the full supply position (or the withdraw-all sentinel) and a `routeXdr` whose `total_min_out` was quoted for exactly `collateral_amount`.
2. Between quote and inclusion, the supply index accrues / unscaling floors reduce the payout, so `withdraw_collateral_to_controller` returns `actual_withdrawn < collateral_amount` [7](#0-6) .
3. The router swaps the smaller input and produces `total_out < total_min_out`, panicking with `SlippageExceeded` [2](#0-1) .
4. The entire transaction reverts: no debt is repaid, `close_position` never runs, the borrower pays fees, and accrued interest continues to degrade the position toward liquidation. The same reversion occurs on `swap_debt` whenever the net-of-flash-fee receipt undershoots the quoted input.
