## Analysis: Missing Sender Authorization in `new_shared_address` Handler

The VoltAgent bug class is "trusting a caller-supplied identifier without verifying the caller actually owns/controls the referenced resource." The closest reachable analog in `ocore` is in the wallet device-message dispatcher, specifically the `new_shared_address` handler, which accepts an attacker-controlled `signers` map (device_address ↔ member-address bindings for a shared/multisig address) from *any* paired correspondent device, without verifying that the sender is actually one of the legitimate cosigners of that shared address.

### Root cause

`handleMessageFromHub` dispatches the `new_shared_address` subject straight to `walletDefinedByAddresses.handleNewSharedAddress(body, ...)` — note that `from_address` (the actual sender, already authenticated as *some* known correspondent) is never passed in or checked against the claimed `signers` map: [1](#0-0) 

`handleNewSharedAddress` only validates that (a) the definition structurally hashes to the claimed address, (b) `body.signers` addresses match the leaves of the definition, and (c) *some* address in `signers` belongs to the local wallet (`my_addresses`) or a previously known `shared_addresses` row: [2](#0-1) 

The membership check (`determineIfIncludesMeAndRewriteDeviceAddress`) only proves the local node owns one of the member addresses — it never proves the *sender* (`from_address`) legitimately controls or was ever a party to the specific `device_address` bindings it is asserting for the *other* signing paths in the definition: [3](#0-2) 

Once accepted, `addNewSharedAddress` persists these attacker-chosen bindings into `shared_address_signing_paths` using `INSERT IGNORE`, meaning any signing path not already recorded locally (e.g. after wallet recovery from seed, or before the legitimate cosigner ever pushed the record) gets silently populated with the attacker's claimed `device_address`: [4](#0-3) 

These routing records are exactly what `findAddress()` consults later to decide where to forward `signing_request` messages for that shared address: [5](#0-4) 

### Title
Unauthenticated `new_shared_address` device message allows any correspondent to hijack signing-path routing for a shared (multisig) address - (File: wallet_defined_by_addresses.js)

### Summary
The `new_shared_address` wallet device-message handler never checks that the message's sender (`from_address`) is authorized to assert `device_address` bindings for the other signing paths of a shared address it claims membership in. This mirrors the VoltAgent bug class of trusting caller-supplied identifiers without an ownership check.

### Finding Description
`wallet.js`'s dispatcher forwards `new_shared_address` bodies to `handleNewSharedAddress` without passing/validating `from_address` [1](#0-0) . `handleNewSharedAddress` requires only that one signer address already belongs to the local wallet (`my_addresses`/`shared_addresses`) [3](#0-2) ; it does not verify that `from_address` is the device that legitimately controls the *other* member address/path being asserted. The resulting record is written with `INSERT IGNORE` into `shared_address_signing_paths` [4](#0-3) , so any path not already present (common after wallet restoration from seed, per the code comment about "peer has lost shared address definitions after a wallet recovery") is populated with attacker-chosen `device_address` values. This function is explicitly designed to let the wallet accept resent shared-address info from peers, but does not check that the resender is actually one of the recorded cosigners for that specific shared address.

### Impact Explanation
Because `findAddress()` routes future `signing_request` messages for a member/shared address based on `shared_address_signing_paths.device_address` [5](#0-4) , an attacker who is merely a paired correspondent of the victim (knowing the victim's real payment address, which is often publicly visible on the DAG once used) can cause future co-signing requests for that shared/multisig address to be routed to a device the attacker controls instead of the legitimate cosigner. This can freeze the victim's ability to complete multisig payments (denial of use of funds locked in that shared address) since legitimate cosigners never receive the signing requests needed to complete the transaction.

### Likelihood Explanation
Reachable purely through the normal paired-device message channel (`hub/message` → `handle_message_from_hub` → `new_shared_address`) that any already-paired correspondent can use; no special privileges beyond being a correspondent are required. The main precondition — a missing/empty `shared_address_signing_paths` row for the targeted path — realistically occurs after wallet recovery, which is a common, expected event.

### Recommendation
When handling `new_shared_address` (and its `INSERT IGNORE` routing update in `addNewSharedAddress`), require that `from_address` matches one of the `device_address` values being asserted in `body.signers` for the paths the sender is not the local wallet, or otherwise cryptographically prove authorization (e.g., only accept resent routing info from a device_address that already appears as a known cosigner in a locally-trusted record, or require a signature over the binding). At minimum, do not allow an unrelated correspondent to populate `shared_address_signing_paths.device_address` for paths it does not own.

### Proof of Concept
1. Attacker device D pairs with victim device V (ordinary correspondent pairing).
2. Attacker learns victim's real payment address `A_v` (e.g., from a past payment on the DAG) and knows/obtains the real public definition of an existing 2-of-2 shared address `S` that includes `A_v` as one signer (definitions are publicly known once an address transacts).
3. Attacker crafts and sends a `new_shared_address` device message: `{address: S, definition: <real definition>, signers: {"r.0": {address: A_v, device_address: V}, "r.1": {address: <other real member address>, device_address: D}}}`.
4. If V's local `shared_address_signing_paths` table lacks the row for the second path (e.g., after wallet restore from seed), `handleNewSharedAddress` accepts it (membership check passes via `A_v`), and `addNewSharedAddress` inserts `device_address = D` for that path.
5. Subsequent attempts by V to pay from `S` route the cosigner's `signing_request` to attacker device D instead of the legitimate cosigner, blocking completion of the transaction.

function findAddress(address, signing_path, callbacks, fallbackInfo){
	db.query(
		"SELECT wallet, account, is_change, address_index, full_approval_date, device_address \n\
		FROM my_addresses JOIN wallets USING(wallet) JOIN wallet_signing_paths USING(wallet) \n\
		WHERE address=? AND signing_path=?",
		[address, signing_path],
		async function(rows){
			if (rows.length > 1)
				throw Error("more than 1 address found");
			if (rows.length === 1){
				var row = rows[0];
				if (!row.full_approval_date)
					return callbacks.ifError("wallet of address "+address+" not approved");
				if (row.device_address !== device.getMyDeviceAddress()) {
					const other_rows = await db.query("SELECT DISTINCT device_address FROM wallet_signing_paths WHERE wallet=? AND device_address!=?", [row.wallet, row.device_address]);

					return callbacks.ifRemote(row.device_address, other_device_addresses);
				}
				var objAddress = {
					address: address,
					wallet: row.wallet,
					account: row.account,
					is_change: row.is_change,
					address_index: row.address_index
				};
				callbacks.ifLocal(objAddress);

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
