### Title
Skill update re-resolves `owner/repo` by name only, enabling repository-transfer ("repojacking") substitution of skill content - ([File: internal/skills/discovery/discovery.go])

### Summary
`ListSkillFiles` (and the `DiscoverSkills`/`ResolveRef` calls that feed it during `gh skill update`) address a skill's source purely by the `owner`/`repo` name pair stored in the installed `SKILL.md` frontmatter, never by an immutable repository identity (GitHub's numeric `id`/`node_id`). If the original repository is renamed or transferred and the `owner/repo` name pair becomes available, an unprivileged attacker can register a new repository at that same path; the next `gh skill update` will silently treat the attacker's repo as the legitimate update source.

### Finding Description
`ListSkillFiles` resolves a skill's file list purely from caller-supplied `owner`, `repo`, and `treeSHA` strings and issues a raw `GET /repos/{owner}/{repo}/git/trees/{treeSHA}` request, with no verification that the addressed repository is the same one the skill was originally installed from: [1](#0-0) 

That `owner`/`repo` pair is not derived from any GitHub-issued immutable identifier. It comes straight from the skill's own `SKILL.md` frontmatter metadata (`github-owner`/`github-repo` style fields), parsed in `parseInstalledSkill`: [2](#0-1) 

During `gh skill update`, these name strings are fed directly into `discovery.ResolveRef` and `discovery.DiscoverSkills` to fetch the "current" tree for the repo and match/compare tree SHAs against the locally recorded `treeSHA`: [3](#0-2) 

Similarly, the lock file (`internal/skills/lockfile/lockfile.go`) records only the human-readable `owner/repo` string and a git URL as `Source`/`SourceURL`, never a stable repository ID: [4](#0-3) 

Because GitHub reuses `owner/repo` name paths once a repository is renamed or transferred away from that path, an attacker who creates a new repository at the now-vacated name causes every subsequent GitHub API call using that `owner/repo` string (`ResolveRef`, `DiscoverSkills`, `ListSkillFiles`, `FetchBlob`) to silently operate against the attacker's content instead of the originally-installed source. The only "pin" mechanism present (`github-pinned` frontmatter field / lockfile `PinnedRef`) pins a *ref* (branch/tag) within the named repo — it does not pin or verify the repository's identity, and it is bypassed entirely with `--unpin`, `--force`, or on any skill lacking a pin. There is no digest/identity check comparing the resolved repository against the one recorded at install time; a differing `treeSHA` is treated purely as "an update is available," not as a possible identity mismatch.

### Impact Explanation
If exploited, `gh skill update` (and `--force` re-installs) will download and install attacker-controlled `SKILL.md`/skill files into the victim's local skills directory, from which agent tooling (Copilot, Claude, etc.) may execute skill instructions/scripts. This matches "Remote code execution on the victim's developer machine" — Critical impact under GitHub's bug bounty RCE class.

### Likelihood Explanation
Requires the original skill-repository owner to first rename/transfer/delete the repo (freeing the `owner/repo` path) — an event outside attacker control but not uncommon (repo renames, org migrations, abandoned projects). Once that occurs, any unprivileged GitHub user can immediately claim the freed `owner/repo` name and publish malicious skill content ("repojacking"), a well-documented supply-chain technique requiring no special privileges. The victim's `gh skill update` will then automatically or (with `--all`) silently pull the substituted content on the next run.

### Recommendation
Persist and verify an immutable repository identifier (GitHub `id`/`node_id`, obtained via the Repos API) alongside `owner/repo` in both the `SKILL.md` frontmatter metadata and `.skill-lock.json`. At update time, before calling `ResolveRef`/`DiscoverSkills`/`ListSkillFiles`, fetch the repository's current `id` and abort (or prompt) if it differs from the recorded value, rather than only comparing tree SHAs by name path.

### Proof of Concept
Go test sketch using `httpmock`:
1. Install a skill from `owner/repo` (id `111`), recording `treeSHA=A` and the repo's `id=111` is available via `GET /repos/owner/repo` in the mock.
2. Simulate transfer: mock `GET /repos/owner/repo` to now return `id=999` (attacker's newly created repo at the same path) with a different tree (`treeSHA=B`) containing malicious `SKILL.md` content.
3. Run `updateRun` (or call `discovery.ResolveRef`/`ListSkillFiles` directly) with the stored `owner`, `repo` from the original install.
4. Assert current behavior: update proceeds and overwrites local skill content with `treeSHA=B`'s content, with no error despite `id` mismatch (999 ≠ 111) — demonstrating the missing identity check.
5. Expected (fixed) behavior: update should fail with an identity-mismatch error and not modify the installed skill.

func ListSkillFiles(client *api.Client, host, owner, repo, treeSHA string) ([]SkillFile, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "trees", treeSHA)
	if err != nil {
		return nil, err
	}
	apiPath.SetQuery("recursive", "true")
	var tree treeResponse
	if err := client.REST(host, "GET", apiPath.String(), nil, &tree); err != nil {
		return nil, fmt.Errorf("could not fetch skill tree: %w", err)
	}

	if tree.Truncated {
		// Fall back to non-recursive traversal when the tree is too large.
		return walkTree(client, host, owner, repo, treeSHA, "", 0)
	}

// RecordInstall adds or updates a skill entry in the lock file.
// It uses a file-based lock to prevent concurrent read-modify-write races
// when multiple install processes run simultaneously.
func RecordInstall(host, skillName, owner, repo, skillPath, treeSHA, pinnedRef string) error {
	lockPath, err := lockfilePath()
	if err != nil {
		return err
	}
	if err := os.MkdirAll(filepath.Dir(lockPath), 0o755); err != nil {
		return fmt.Errorf("could not create lock directory: %w", err)
	}

	lockedFile, unlock, err := acquireFLock()
	if err != nil {
		return err
	}
	defer unlock()

	f, err := readFrom(lockedFile)
	if err != nil {
		return err
	}

	now := time.Now().UTC().Format(time.RFC3339)

	existing, exists := f.Skills[skillName]
	installedAt := now
	if exists {
		installedAt = existing.InstalledAt
	}

	f.Skills[skillName] = entry{
		Source:          owner + "/" + repo,
		SourceType:      "github",
		SourceURL:       ghinstance.HostPrefix(host) + owner + "/" + repo + ".git",
		SkillPath:       skillPath,
		SkillFolderHash: treeSHA,
		InstalledAt:     installedAt,
		UpdatedAt:       now,
		PinnedRef:       pinnedRef,
	}

	return writeTo(lockedFile, f)
}
