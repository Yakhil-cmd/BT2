### Title
Suppliers can front-run `clean_bad_debt` socialization to dodge the supply-index write-down, concentrating the loss on remaining suppliers - (File: tests/test-harness/tests/composition/supplier_exit_before_socialization_is_bounded_by_utilization.rs)

### Summary
Bad-debt socialization in XOXNO Lending writes down a market's supply index, so every supplier holding shares at that moment absorbs the loss pro-rata. Because withdrawal stays permissionless and `clean_bad_debt` is callable by anyone, a supplier who monitors for a pending cleanup (or a liquidation that ends in `check_bad_debt_after_liquidation`) can withdraw at the pre-write-down index, let the cleanup execute, and re-supply at the written-down index — shifting the entire loss onto suppliers who did not exit. A composition test pins this exact exit → clean → re-enter sequence succeeding atomically in one transaction.

### Finding Description
`process_clean_bad_debt` only requires `caller.require_auth()` and the dust-gated insolvency check; the caller need not be the account owner [1](#0-0) . The actual loss is applied in the pool by `apply_bad_debt_to_supply_index`, which scales `supply_index` down by `bad_debt / total_supplied_value`, diluting every scaled-share holder [2](#0-1) . A borrow-side seize burns the debt shares after the index write-down [3](#0-2) .

Crucially, withdrawal and supply remain callable while cleanup is pending — global pause explicitly leaves "withdrawal, repayment, liquidation, bad-debt cleanup, recapitalization … callable" [4](#0-3) . The threat model itself concedes the gap: "a supplier who exits before cleanup can avoid that loss" [5](#0-4) .

The harness test `exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows` executes `withdraw → CleanBadDebt → supply` atomically and asserts the runner "kept its whole stake" while "BOB absorbed the entire write-down" [6](#0-5) .

The same front-run applies to `liquidate`, which calls `apply::check_bad_debt_after_liquidation` at the end of the same flow [7](#0-6) , and to the governance `force_socialize_bad_debt` path, whose timelocked delay makes the write-down trivially predictable.

### Impact Explanation
Theft of user funds / yield from passive suppliers. Every exited share withdraws at the pre-write-down index, so the fixed `bad_debt` is spread over a smaller `total_supplied_value`; remaining suppliers' claims fall by strictly more than their pro-rata share. The runner's atomic script even re-enters at the depressed index, later exiting at par value restored by `recapitalize`, converting the dodged write-down into a direct claim on recapitalized funds. Bounded only by `max_utilization` on the exit leg.

### Likelihood Explanation
Medium. Requires (a) an insolvent account approaching the dust gate and (b) pool utilization leaving enough idle cash to withdraw. Both are observable on-chain; `clean_bad_debt` eligibility is computable from public positions and prices, and `force_socialize_bad_debt` is announced by a Sensitive-tier governance delay. Any supplier can run the single-transaction script with no timing race. No privileged access is needed: `withdraw`, `supply`, and `clean_bad_debt` are all reachable by an unprivileged address.

### Recommendation
The cleanest mitigation is economic rather than a commit-reveal scheme: before socializing, net the insolvent account's same-market supply against its debt (currently cleanup "does not net those pairs first"), and/or delay claims — e.g., value withdrawals against the worst-case pending write-down by computing the supply index as if all accounts currently eligible for `clean_bad_debt` were socialized. A practical lower-effort fix is to let `withdraw` optionally accept a `min_supply_index`/slippage bound and to make liquidation-triggered cleanup pull repayment in the same transaction before suppliers can observe the intermediate state — though since write-downs are deterministic once eligibility is public, only reducing the write-down surface (netting, or an insurance fund via `recapitalize` before index reduction) fully closes the dodge.

### Proof of Concept
1. BOB and attacker supply ETH; ALICE supplies a small amount of collateral and borrows ETH, then the collateral price crashes so `D > C` with `C ≤ $5` — `clean_bad_debt` becomes permissionlessly executable.
2. Attacker submits one Soroban transaction: `withdraw` full ETH supply → `clean_bad_debt(account_id)` → `supply` the same ETH (new account id).
3. `apply_bad_debt_to_supply_index` writes down the ETH supply index with the attacker's shares already gone; BOB's scaled shares absorb the entire reduction (`supplier_exit_before_socialization_is_bounded_by_utilization.rs` asserts `BOB`'s balance strictly decreases while the runner's does not).
4. When `recapitalize` later fills the backing shortfall, the attacker's shares — minted at the depressed index — redeem at full value, realizing the extracted difference.

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Socializes insolvent debt when remaining collateral is at or below the dust cap.
pub(crate) fn clean_bad_debt_standalone(env: &Env, account_id: u64) {
    socialize_bad_debt(env, account_id, BadDebtGate::DustCapped);
}

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn exit_then_clean_then_re_enter_dodges_the_write_down_when_utilization_allows() {
    let Seed {
        t,
        runner,
        runner_account,
        victim,
    } = seed(true, 0.0);
    let bob_before = t.supply_balance_raw(BOB, "ETH");
    let ops: Vec<Op> = vec![
        &t.env,
        withdraw_op(&t, runner_account, "ETH", 0, None),
        Op::CleanBadDebt(AccountOp { account_id: victim }),
        supply_op(&t, 0, "ETH", 50 * U),
    ];
    let new_id = t
        .run_script(&runner, &ops)
        .expect("atomic exit, clean, re-enter");
    assert!(new_id > 0 && new_id != runner_account);
    assert!(
        t.supply_balance_raw_for(new_id, "ETH") >= 50 * U - 1,
        "the runner kept its whole stake"
    );
    assert!(
        t.supply_balance_raw(BOB, "ETH") < bob_before,
        "BOB absorbed the entire write-down"
    );
}
