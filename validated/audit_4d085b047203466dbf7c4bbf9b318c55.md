### Title
CCMenu token authorizes read access to *every* stack, not just the stack it was issued for - (File: `app/controllers/shipit/ccmenu_url_controller.rb`)

### Summary
`CCMenuUrlController#fetch` mints an `ApiClient` token intended to authorize CCMenu/CCTray XML polling for **one specific stack**, but the token it creates is never bound to that stack. Any holder of a generated CCMenu URL therefore gets an `ApiClient` with the `read:stack` permission and **no `stack_id`**, which the rest of the API treats as an unscoped, instance-wide read token — capable of reading the state of every stack, task and deploy in the Shipit installation, not just the one the URL was generated for.

### Finding Description
`CCMenuUrlController#fetch` builds the shareable CCMenu URL like this: [1](#0-0) 

```ruby
def fetch
  uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
  uri.query = { 'token' => client.authentication_token }.to_query
  render(json: { ccmenu_url: uri.to_s })
end

private

def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```

The URL path embeds `stack_id` for the intended target stack, but the `ApiClient` record backing the `token` query parameter is looked up/created only by `creator` + `name: 'CCMenu Client'` — it never sets `stack:`. Consequently every user gets exactly **one** reusable "CCMenu Client" token, and that token's `stack_id` column is `nil`.

That matters because the API authorization layer treats a `nil` `stack_id` as "unscoped, applies to all stacks": [2](#0-1) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

`ApiClient#check_permissions!` only checks that the permission string (e.g. `read:stack`) is present in the token's permission list — it never checks which stack the request targets: [3](#0-2) 

Additionally, `CCMenuController#stack` doesn't even go through the `stacks` scoping helper — it fetches the requested stack directly and unconditionally: [4](#0-3) 

```ruby
def show
  latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
  render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
end

private

def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```

The binding that should hold is: *the stack a CCMenu token authorizes* (the one stack the user requested a badge/URL for) *== the stack the token can be used to read*. Because the underlying `ApiClient` is created without `stack:`, that equality is broken: the token authorizes **all** stacks. Worse, because the same token also carries `read:stack`, it is not limited to the CCMenu XML endpoint — it can be used as a normal Basic-Auth API credential (`Authorization: Basic <id>--<token>`) against `Shipit::Api::StacksController#index/show`, `Shipit::Api::CommitsController#index`, and `Shipit::Api::TasksController#index/show`, exposing the full list of stacks, commits, and deploy/task history for the entire Shipit installation.

### Impact Explanation
CCMenu/CCTray URLs are a documented, intentionally-shareable feature (they are meant to be pasted into third-party CI dashboards, build-status widgets, README badges, IDE plugins, etc. — i.e., handed to parties that should only ever see one project's build status). Because the token backing that URL is unscoped, anyone who obtains one user's CCMenu URL/token — through a leaked badge, a public dashboard screenshot, a shared IDE config, etc. — gains standing, reusable read access to the state, commit history, and task/deploy output of **every stack** in the Shipit instance, not just the one it was generated for. This is an unauthenticated (relative to the intended single-stack scope) disclosure of stack state, task streams, and deploy output across the entire deployment, matching the High-severity class of "escalation into stack authorization; unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
High. No special privilege beyond having ever generated (or obtained) one CCMenu URL is required, and the bug is purely a data-modeling omission (`stack:` not passed to `find_or_create_by!`) — it triggers on the very first, normal use of the feature. Any Shipit deployment where at least one user has generated a CCMenu URL and shared it (the feature's designed use case) is affected for every stack in that instance.

### Recommendation
Scope the CCMenu client to the specific stack when creating/looking it up, and enforce stack scoping consistently in `CCMenuController`:

```diff
 def client
-  @client ||= ApiClient.create_with(permissions: %w[read:stack])
-                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
+  @client ||= ApiClient.create_with(permissions: %w[read:stack])
+                       .find_or_create_by!(creator: current_user, name: "CCMenu Client (#{stack.to_param})", stack:)
 end
```

And in `CCMenuController`, reuse the scoped `stacks` helper instead of `Stack.from_param!`:

```diff
 def stack
-  @stack ||= Stack.from_param!(params[:stack_id])
+  @stack ||= stacks.from_param!(params[:stack_id])
 end
```

This restores the invariant that a token's `stack_id` binds exactly the stack it is allowed to read, and ensures a leaked CCMenu URL only discloses the one project it was meant for.

### Proof of Concept
1. As a logged-in Shipit user with access to stack `acme/api` (environment `production`), call `GET /stacks/acme/api/production/ccmenu_url` (the `fetch` action). This creates/reuses `ApiClient` named `"CCMenu Client"` for the current user, with `permissions: ["read:stack"]` and `stack_id: nil`, and returns a URL such as:
   `https://shipit.example.com/api/stacks/acme%2Fapi%2Fproduction/ccmenu.xml?token=<TOKEN>`
2. Embed/share that URL in a public CI-status badge or dashboard, as CCMenu URLs are designed to be used.
3. An external party who only has this URL can strip the `stack_id` and substitute any other stack the instance hosts, e.g.:
   `https://shipit.example.com/api/stacks/acme%2Finternal-secrets-service%2Fproduction/ccmenu.xml?token=<TOKEN>`
   and the server returns that stack's build/deploy status — a stack the token was never intended to expose.
4. The same `<TOKEN>` can also be used as HTTP Basic Auth (`Authorization: Basic base64(<client_id>--<token>)`) directly against `GET /api/stacks`, `GET /api/stacks/:stack_id/commits`, and `GET /api/stacks/:stack_id/tasks`, returning the full list of stacks and their commit/deploy history for the whole Shipit installation — confirmed by `require_permission :read, :stack` on those controllers checking only permission presence [3](#0-2)  and by `stacks` returning `Stack.all` whenever `current_api_client.stack_id?` is false [5](#0-4) .
