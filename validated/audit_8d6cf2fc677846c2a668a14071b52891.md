Confirmed: `here_come_the_walrus` is an `ApiClient` fixture scoped to `stack: shipit` with only `read:stack` permission, proving the engine's intended model is that a `stack_id`-scoped `ApiClient` must be restricted to that one stack via `BaseController#stacks`/`#stack`. `Api::CCMenuController` overrides `#stack` to bypass that scoping entirely.

### Title
Stack-scoped API token can read any stack's CCMenu deploy status - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Api::CCMenuController` authenticates an `ApiClient` and enforces only the coarse `read:stack` permission, but resolves the target `Stack` with an unscoped lookup instead of the client's authorized stack, breaking the binding between the stack a token authorizes and the stack it actually touches.

### Finding Description
`Shipit::Api::BaseController` implements per-token stack scoping: when an `ApiClient` has a `stack_id` set, `#stacks` restricts the visible set to that single stack, and `#stack` resolves `params[:stack_id]` only within that scoped relation [1](#0-0) . This is the mechanism that makes a stack-scoped `ApiClient` (e.g., the fixture `here_come_the_walrus`, which has `stack: shipit` and only `read:stack` permission) safe to hand out, per `test/fixtures/shipit/api_clients.yml`.

`Api::CCMenuController`, however, overrides `#stack` to bypass this scoping: [2](#0-1) 
It calls `Stack.from_param!(params[:stack_id])` directly against all stacks, rather than through the scoped `stacks` relation used by the base controller. The `require_permission :read, :stack` before_action only checks that `"read:stack"` is present in the client's `permissions` array via `ApiClient#check_permissions!`, which never inspects `stack_id` [3](#0-2) . Authentication for this controller also accepts the token from the query string (`params[:token]`), matching how the CCMenu URL is minted and distributed via `CCMenuUrlController` [4](#0-3) .

The equality that should hold is: `stack a token authorizes == stack a token can act on`. Before the request, a stack-scoped token authorizes only `Stack A`. After a request to `/api/stacks/:stack_id/ccmenu.xml?token=...` with `stack_id` pointing at `Stack B`, the controller renders `Stack B`'s latest deploy/rollback status — the equality is broken.

### Impact Explanation
This grants an unauthenticated-by-scope read of another stack's deploy/task state (deploy status, running/failure state, last build label) through `Api::CCMenuController#show`, which is exactly the "unauthenticated read of stack state" class of High-impact issue: a token minted and distributed for one stack (e.g., embedded in a CI status-monitoring tool URL) discloses status of stacks the holder was never granted access to.

### Likelihood Explanation
Exploitation requires possession of a valid CCMenu token, which is routinely generated and embedded in external URLs (CCMenu/CI dashboard tools) by `CCMenuUrlController#fetch`, i.e., not a privileged secret. The only "attack" step is substituting a different `stack_id` in the otherwise-public URL path, requiring no additional privileges, session, or GitHub credentials — an unprivileged holder of one CCMenu link can enumerate other stacks' status.

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the scoped `stacks` method inherited from `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so a stack-scoped `ApiClient` cannot be used to read other stacks' CCMenu status.

### Proof of Concept
1. Obtain a CCMenu token scoped to `Stack A` (e.g., via `GET /ccmenu/*stack_a_id` which creates/returns an `ApiClient` with `stack_id = A` and `read:stack` permission, exposed in the returned `ccmenu_url`).
2. Issue `GET /api/stacks/B/ccmenu.xml?token=<token>` where `B` is any other stack.
3. `authenticate_api_client` succeeds (token is valid), `require_permission :read, :stack` passes (client has `read:stack`), and `#stack` returns `Stack.from_param!('B')` — unscoped — rendering `Stack B`'s deploy status even though the token was only meant to authorize `Stack A`.
