### Title
Webhook authentication is bound to `repository.owner.login`/`organization.login`, but every event handler acts on the independent `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects *which* GitHub App (and therefore which `webhook_secret`) to validate a webhook against using the attacker-influenceable JSON fields `repository.owner.login` / `organization.login`. Every `Webhooks::Handlers::Handler` subclass, however, resolves the `Stack`/`Repository` it actually acts on from a completely different field in the same body: `repository.full_name`. Because signature verification silently succeeds whenever the resolved app has no `webhook_secret` configured, an attacker can pick an org name with no secret for authentication while pointing `repository.full_name` at a *different*, secret-protected org/repo's stack, causing that stack's handlers (push sync, check-suite refresh, membership, etc.) to run.

### Finding Description
`verify_signature` picks the GitHub App config to check against like this: [1](#0-0) [2](#0-1) 

`repository_owner` is read straight from the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`). `Shipit.github(organization: repository_owner)` then looks up per-organization app config: [3](#0-2) 

If that organization's `webhook_secret` is blank — which the setup docs explicitly call "optional" and the shipped example config sets to `nil` — the signature check is a no-op: [4](#0-3) 

Meanwhile, none of the event handlers use `repository.owner.login`/`organization.login` to decide what to act on. They resolve the target `Repository`/`Stack` from `repository.full_name`, a sibling field in the same body: [5](#0-4) [6](#0-5) 

So the binding the code implicitly assumes — `authenticated_org == acted_on_repo_owner` — is never checked as an equality anywhere. `verify_signature` authenticates the request against organization `A` (chosen by the attacker to be one with no `webhook_secret`), while the handler that runs afterwards acts on repository `full_name` belonging to organization `B` (a real, secret-protected Shipit-tracked repository), because `full_name` is under attacker control and is never cross-checked against `repository_owner`.

### Impact Explanation
An unauthenticated caller (no session, no `ApiClient` token, no `webhook_secret`) can drive Shipit's GitHub webhook handlers for *any* stack tracked by the instance, as long as at least one configured GitHub App organization has no `webhook_secret` set (a state the documentation presents as a normal, supported configuration, and the one used in every shipped example/secrets file):
- `PushHandler` will invoke `stack.sync_github(expected_head_sha:)` for arbitrary stacks matching the forged `repository.full_name`, forcing an out-of-band sync that can trigger continuous deployment on stacks that have `continuous_deployment` enabled — an unauthorized deploy trigger the attacker should never have been able to cause, since the real owning organization's app does have a `webhook_secret` and would normally reject forged requests.
- `MembershipHandler`, commit-status handlers, and check-suite handlers are reachable the same way, letting an outsider create/modify `Team` membership records and commit statuses for repositories they have no relationship to.

This crosses the "unauthorized deploy" / "escalation into `Shipit.github_teams` authorization" bar for a valid finding without requiring any credential, session, or secret.

### Likelihood Explanation
Requires only: (1) an unprivileged HTTP request to the public `/webhooks` endpoint, (2) knowledge that the target Shipit instance is running multiple GitHub App configs (documented, discoverable pattern for enterprises tracking several orgs) and that at least one configured organization left `webhook_secret` unset (the documented default/example value). No GitHub credentials, private key, or Shipit session are needed — the attacker only crafts a JSON body with mismatched `repository.owner.login` and `repository.full_name`.

### Recommendation
In `WebhooksController#verify_signature`, after successfully verifying the signature, assert that `repository_owner` equals the owner implied by `repository.full_name` (and by extension the `Repository`/`Stack` the handler will resolve) before dispatching to handlers. Alternatively, stop trusting attacker-controlled fields to select the verification secret: verify against every configured app's secret (or require an explicit installation identifier signed by GitHub) rather than the org name embedded in the unauthenticated body, and reject requests whose selected app has a blank `webhook_secret` if any other app is configured.

### Proof of Concept
1. Configure Shipit (as documented) with two GitHub App orgs: `OrgNoSecret` (webhook_secret unset — the documented "optional" default) and `OrgVictim` (webhook_secret set, tracking a real Stack `OrgVictim/victim-repo` with `continuous_deployment: true`).
2. As an unauthenticated attacker, POST to `/webhooks` with:
   - Header `X-Github-Event: push`
   - Body: `{"repository": {"owner": {"login": "OrgNoSecret"}, "full_name": "OrgVictim/victim-repo"}, "ref": "refs/heads/master", "after": "<any sha>"}`
   - No `X-Hub-Signature` header required.
3. `verify_signature` resolves `Shipit.github(organization: "OrgNoSecret")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally.
4. `PushHandler#process` resolves the target stacks via `repository.full_name` = `"OrgVictim/victim-repo"`, finds the real, secret-protected `Stack`, and calls `stack.sync_github`, potentially triggering an unauthorized deploy for a repository the attacker never authenticated against.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
