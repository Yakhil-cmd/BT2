## Analysis

The python-socketio bug class is: an unauthenticated/unprivileged sender submits a multi-part message and deliberately withholds part of it, causing the server to retain the partial message in memory indefinitely (no timeout/cleanup tied to the sender's connection), leading to unbounded memory growth (CWE-770).

The closest reachable analog in `ocore--017` is in the **private-payment chain** handling path, which is driven by messages from a paired device (an "unprivileged... private-payment counterparty or paired device" per the allowed reach list).

### Title
Unbounded accumulation of incomplete private-payment chains and event listeners causes memory exhaustion - (File: wallet.js, network.js)

### Finding Description
`handlePrivatePaymentChains()` in [1](#0-0)  accepts an arbitrary `body.chains` array of private-payment element chains from any paired device correspondent, with only structural validation (no bound on chain count/size). For each chain it derives a `key` and registers `assocValidatedByKey[key] = false`, then calls `network.handleOnlinePrivatePayment()`.

For light clients (or whenever `ifQueued` is returned), a `eventBus.once(key, ...)` listener is registered [2](#0-1)  that is only ever cleaned up when the corresponding `key` event fires. That event only fires from `handleSavedPrivatePayments()` in [3](#0-2) , which only processes rows whose `unit` already exists in the local `units` table (`CROSS JOIN units USING(unit)` at [4](#0-3) ). If the referenced unit (or its full dependency chain) is never actually delivered by the same malicious counterparty, the row stays in `unhandled_private_payments` and the `eventBus.once(key, ...)` listener is never invoked and never removed.

The corresponding DB row (`unhandled_private_payments`, storing the full attacker-controlled JSON payload) is only purged by `cleanBadSavedPrivatePayments()`, which is full-node only, runs once every 5 minutes after coming online, and only deletes rows older than 1 day [5](#0-4) . For light wallets, cleanup of stale entries depends on `requestUnfinishedPastUnitsOfPrivateChains()` being invoked and succeeding in confirming the units are unresolvable [6](#0-5)  — there is no unconditional periodic purge on the light-wallet side.

This mirrors the python-socketio flaw: state tied to an incomplete, attacker-controlled multi-part submission (`arrPrivateElements`/chain) is retained in memory/DB keyed by content the attacker controls, with no immediate disconnect-based or bounded cleanup, allowing an unprivileged paired device or hub-relayed peer to keep injecting new chains that never complete.

### Impact Explanation
A malicious paired device (or a hub relaying on behalf of a malicious correspondent) can repeatedly send `private_payments` messages with unique, well-formed-but-incomplete chains referencing units it never actually publishes. Each such message:
- inserts a row into `unhandled_private_payments` holding the full JSON payload,
- registers a persistent `eventBus.once(key, ...)` listener in the wallet process that is never released.

Repeated over time this causes continuous memory growth in the node/wallet process (listener accumulation plus DB growth for up to 24 hours per full node's own retention window, indefinitely for light wallets absent successful resolution), degrading or crashing the affected node — a memory/availability DoS (CWE-770), matching the "Attack" impact category (node/wallet unable to continue operating normally).

### Likelihood Explanation
Any device already paired/correspondent with the victim (a normal, low-privilege trust relationship established via pairing, not an operator or hub-admin) can trigger this at will, and the hub-relay path (`bViaHub`) does not require the sender to prove chain completeness before the record is accepted and queued. No exceptional network position or privileged access is required, making this readily reproducible by an unprivileged counterparty.

### Recommendation
- Bound the number of concurrent unresolved chains and/or the age of `unhandled_private_payments` entries per sender, purging them independent of the "already 1 day" full-node-only job, and apply the same policy to light wallets unconditionally (not only when `requestUnfinishedPastUnitsOfPrivateChains` succeeds).
- Track and remove the `eventBus.once(key, ...)` listeners with an explicit timeout, so a chain that never resolves does not hold a listener (and its closure) forever.
- Rate-limit/size-limit incoming `private_payments` messages per device correspondent.

### Proof of Concept
1. Pair a device with the victim wallet (normal, unprivileged pairing).
2. Send a `private_payments` message via `handleMessageFromHub` whose `chains` reference a syntactically valid but never-published unit (or one whose full dependency chain is withheld).
3. Observe: a new `unhandled_private_payments` row is created and an `eventBus.once(key, ...)` listener is registered in `wallet.js`; neither is cleaned up because `handleSavedPrivatePayments()`'s join against `units` never matches.
4. Repeat with new fabricated units to grow memory/DB usage without bound (bounded only by the full-node's 1-day sweep, which does not apply the same way to light wallets).

function requestUnfinishedPastUnitsOfPrivateChains(arrChains, onDone){
	mutex.lock(["private_chains"], function(unlock){
		function finish(){
			unlock();
			if (onDone)
				onDone();
		}
		privatePayment.findUnfinishedPastUnitsOfPrivateChains(arrChains, true, function(arrUnits){
			if (arrUnits.length === 0)
				return finish();
			breadcrumbs.add(arrUnits.length+" unfinished past units of private chains");
			requestHistoryFor(arrUnits, [], err => {
				if (err) {
					console.log(`error getting history for unfinished units of private payments`, err);
					return finish();
				}
				// get units that are still new or unstable after refreshing the history
				storage.filterNewOrUnstableUnits(arrUnits, async arrMissingUnits => {
					if (arrMissingUnits.length === 0) return finish();
					console.log(`will delete unhandled private payments whose units are not known after 1 day`, arrMissingUnits);
					await db.query(`DELETE FROM unhandled_private_payments WHERE unit IN(${arrMissingUnits.map(db.escape).join(', ')}) AND creation_date < ${db.addTime('-1 DAY')}`);
					finish();
				});
			});
		});
	});
}
