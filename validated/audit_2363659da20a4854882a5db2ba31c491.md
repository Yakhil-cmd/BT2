Found it: the binding "organization that authenticated versus the repository that is written" breaks in `WebhooksController`.

### Title
Webhook signature verified against an organization derived from the unverified payload, decoupled from the repository actually mutated - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App / webhook secret used to authenticate the request from `repository_owner`, a value read straight out of the still-unverified JSON body. `StatusHandler#process` (and other handlers), however, act on state (`Commit`, `Stack`) keyed only on `sha` / `repository.full_name`, with no re-check that the commit/stack actually belongs to the organization whose secret validated the HMAC. The `organization` used to authenticate and the `repository` that is ultimately written are two different fields of the same attacker-influenced payload, and only the former is covered by verification while the latter drives the write.

### Finding Description
`verify_signature` picks the signing secret via: [1](#0-0) 
`repository_owner` is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`: [2](#0-1) 

`Shipit.github(organization:)` resolves per-organization config/secret via `github_app_config`, which is a case-insensitive hash lookup keyed by that same attacker-supplied string: [3](#0-2) 

Once `verify_webhook_signature` returns true (HMAC over the raw body using the secret picked from `repository_owner`), the handler dispatch runs the event handlers over the full, already-parsed `params` hash: [4](#0-3) 

For `status` events, `StatusHandler#process` looks up commits purely `Commit.where(sha: params.sha)` — with no scoping back to the organization/repository whose secret was used for verification: [5](#0-4) 

`PushHandler` resolves the stack via `Repository.from_github_repo_name(repository_name)` where `repository_name` is `payload.dig('repository', 'full_name')` — again a payload field, distinct from `repository.owner.login` used for signature selection: [6](#0-5) 

In a single-tenant (single GitHub App) Shipit install this is not exploitable, because `github_default_organization` returns `nil` and the same static `secrets.github` webhook_secret is used regardless of the payload's claimed owner: [7](#0-6) 

The gap only opens in the documented multi-organization configuration (`config/secrets.development.example.yml` shows the `github: <org>: webhook_secret: ...` schema for "multiple Github applications for different Github organizations"). In that mode, each organization the operator configured has its own webhook secret, and any of those secrets is sufficient to authenticate a request whose `repository.owner.login`/`organization.login` matches that secret's org — but the body content that drives the actual write (`repository.full_name`, `sha`, commit `state`) is not required to belong to that same org. An actor who legitimately controls (or compromises) one configured organization's webhook secret (e.g. via that org's own GitHub App webhook delivery, which is not itself privileged access to Shipit) can craft a signed payload where `repository.owner.login` is their own org (so verification passes with their own secret) while `repository.full_name` / `sha` reference a repository/commit belonging to a different organization also hosted on the same Shipit instance, causing Shipit to update commit statuses or trigger `sync_github`/deploy-eligible state for a stack outside the org that supplied the signature.

### Impact Explanation
This does not by itself grant RCE or token exfiltration, but it breaks the intended per-organization trust boundary underpinning the "unauthorized deploy" impact class: a status update forged this way can flip a commit's CI/status green (`create_status_from_github!`), which is exactly the signal the merge queue (`MergeRequest#all_status_checks_passed?`) and deploy eligibility gates rely on, potentially enabling an unauthorized deploy/merge on a stack the attacker's organization was never granted access to.

### Likelihood Explanation
This requires the deployment to be running in the multi-organization webhook configuration and requires the attacker to control (or have compromised) at least one of the configured organizations' webhook secrets — this is a real but narrow precondition, not a fully unprivileged, credential-free attack path, so likelihood is low-to-moderate and confidence in exploitability without a live multi-org test fixture is limited.

### Recommendation
After verifying the HMAC signature, re-derive/require the `repository.owner.login` (or `organization.login`) used for verification to match the owner of `repository.full_name` (and any commit/stack subsequently mutated) before dispatching to handlers, rather than trusting the payload's `repository.full_name` independently of the field used to select the signing secret.

### Proof of Concept
1. Configure Shipit in multi-org mode with two orgs, `org-a` (secret `S_A`) and `org-b` (secret `S_B`), each with stacks hosted.
2. As the operator/holder of `S_A`'s webhook secret (e.g., because you configured `org-a`'s GitHub App webhook to point at your own relay, or the secret otherwise leaked to `org-a`'s side), craft a `status` event body: `{"repository": {"owner": {"login": "org-a"}, "full_name": "org-a/whatever"}, "sha": "<commit sha belonging to org-b/real-repo>", "state": "success", ...}`.
3. Sign the raw body with `S_A` and send `X-Hub-Signature`, `X-Github-Event: status` to `/webhooks`.
4. `verify_signature` resolves `Shipit.github(organization: 'org-a')`, validates the HMAC with `S_A`, succeeds.
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)` and updates the status on the `org-b` commit, even though verification was performed against `org-a`'s secret. [8](#0-7) [3](#0-2) [9](#0-8) [10](#0-9)

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit

      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
