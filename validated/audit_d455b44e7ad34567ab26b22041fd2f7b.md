### Title
No-secret organization bypass + `membership` webhook enables attacker self-insertion into a `Shipit.github_teams` authorization team - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/membership_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` instance to verify a webhook by looking up `Shipit.github(organization: repository_owner)`, where `repository_owner` is entirely attacker-controlled JSON (`params.dig('repository','owner','login')` or, for `membership` events, `params.dig('organization','login')`). `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever that organization's config has no `webhook_secret` configured, so a forged, unsigned `membership` payload naming such an organization is accepted and dispatched to `Shipit::Webhooks::Handlers::MembershipHandler#process`, which calls `team.add_member(member)` with attacker-supplied `member.login` and `team` data, adding the attacker to any team record (keyed only by `team.id`), including one used in `Shipit.github_teams` for `User#authorized?`.

### Finding Description
The broken binding is: **for any webhook processed, `repository_owner-of-verified-org == repository_owner-in-processed-payload`, and that org must actually possess a configured `webhook_secret` used to verify the specific bytes received.** In this code, the second half never holds when the resolved org's config carries no `webhook_secret`.

Trace:
- `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner` from `params.dig('repository','owner','login') || params.dig('organization','login')` (line 61), which is raw, unauthenticated attacker JSON.
- It calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. `Shipit.github` (`lib/shipit.rb:170-181`) looks up `github_app_config(organization)` purely by string key in `secrets.github`, with no cross-check against the actual repository/team ownership recorded in Shipit's DB.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`): `return true unless webhook_secret`. If the resolved org's config in `secrets.github` has no `webhook_secret` entry, any payload — signed or not — is accepted.
- For a `membership` event, there is no `repository` key in the real GitHub payload, so `repository_owner` resolves via the `organization.login` fallback — which is exactly the field `MembershipHandler` also reads (`params.organization.login`, `membership_handler.rb:15-17`, `:39-42`). The attacker fully controls this string.
- Once verified, `Shipit::Webhooks.for_event('membership')` dispatches to `MembershipHandler#process` (`membership_handler.rb:22-34`), which does:
  - `team = find_or_create_team!` — `Team.find_or_create_by!(github_id: params.team.id) { ... }` (lines 38-43). If the attacker supplies a `team.id` matching an **existing** Team record already tracked by Shipit (e.g., one referenced in `Shipit.github_teams`, built from `github.oauth_teams`, see `lib/shipit.rb:256-258` and `Team.find_or_create_by_handle`), `find_or_create_by!` returns that existing record instead of creating a new one, because the lookup key is only `github_id`.
  - `member = User.find_or_create_by_login!(params.member.login)` — creates/looks up a `User` by attacker-chosen login (line 24).
  - `team.add_member(member)` (`team.rb:41-43`) appends the member to `team.members` — an unconditional DB write with no ownership or signature-linkage check between the "no-secret organization" and the specific `team.id`/`member.login` supplied.
- `User#authorized?` (`app/models/shipit/user.rb:80-82`) grants Shipit-wide authorization if `teams.where(id: Shipit.github_teams.map(&:id)).exists?` — i.e., membership in any team whose `id` is in the configured `github_teams` list is sufficient, regardless of which organization's webhook secret nominally "verified" the request.

Existing guards do not block this: `check_if_ping` only intercepts `ping` events; `drop_unhandled_event` only filters unregistered event types (`membership` is registered); `ExplicitParameters` (`params do ... end` block in `MembershipHandler`) only validates JSON shape/types, not authenticity or organization/team ownership; there is no `require_permission!`/`current_user` check on this unauthenticated controller by design (webhooks are meant to be unauthenticated but HMAC-verified) — but the verification is defeated precisely because it degrades to `true` for organizations without a `webhook_secret`.

### Impact Explanation
An unprivileged internet attacker who can identify (from public Shipit configuration/behavior, e.g. via the `GithubOrganizationUnknown` 422 vs. 200/204 status divergence, or from an org they already know is onboarded to Shipit without a webhook secret configured) a Shipit-configured GitHub organization lacking `webhook_secret` can forge a `membership` webhook body naming that organization and an existing team's `id`/`slug` (which may be discoverable, e.g. from the organization if it is public, or from prior Shipit UI/team listings), and insert an arbitrary GitHub login (including one they control) as a member of that `Team` record in Shipit's database. If that `team.id` is one of the teams configured in `Shipit.github_teams` (used for OAuth authorization gating access to the whole app per `User#authorized?`), this directly escalates the attacker into Shipit's authorization group — matching the "High: escalation into `Shipit.github_teams` authorization" impact category. This is repeatable against any organization onboarded without a `webhook_secret` and requires no interaction with the actual owning organization or GitHub API.

### Likelihood Explanation
Preconditions: (1) at least one organization configured in Shipit's `secrets.github` multi-org config without a `webhook_secret` key, and (2) the attacker knowing/guessing that organization's login and an existing team's numeric `github_id`. Condition (1) is a real, plausible operator misconfiguration explicitly enabled by the code (`webhook_secret` is optional/`presence`-checked, not required). Attacker cost is a single unauthenticated `POST /webhooks` request with a crafted JSON body and `X-Github-Event: membership` header — no secrets, sessions, or tokens needed. It is fully repeatable and scriptable.

### Recommendation
- Require `webhook_secret` to be present for every configured GitHub organization (fail closed at boot/config-validation time, or reject webhooks for orgs with a missing secret instead of treating it as "trusted").
- Do not fall back to attacker-supplied `organization.login`/`repository.owner.login` to select the verification key without also validating that the resulting `Team`/`Repository` state changes are scoped to records already associated with that specific, correctly-authenticated organization.
- In `MembershipHandler#find_or_create_team!`, verify that `params.organization.login` matches the `Team#organization` of any existing record found by `github_id` before mutating membership, rejecting mismatches.

### Proof of Concept
minitest plan (in `test/controllers/webhooks_controller_test.rb`, no live GitHub):
1. Configure `Shipit.github` (via stubbed `secrets.github`) with an organization `"no-secret-org"` whose config hash has no `webhook_secret` key.
2. Seed a `Shipit::Team` with `github_id: 555`, `organization: "trusted-org"`, and stub `Shipit.stubs(:github_teams).returns([that_team])` to simulate it being an authorization-gating team.
3. POST to `/webhooks` with header `X-Github-Event: membership`, **no** `X-Hub-Signature` header (or a bogus one), and JSON body:
   ```json
   {
     "action": "added",
     "team": { "id": 555, "name": "Trusted", "slug": "trusted", "url": "https://api.github.com/teams/555" },
     "organization": { "login": "no-secret-org" },
     "member": { "login": "attacker" }
   }
   ```
4. Assert response is `200 OK` (not `422`).
5. Assert the binding equality after: `team = Shipit::Team.find_by(github_id: 555)`; `assert team.members.exists?(login: "attacker")`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end

    @github[organization] ||= GitHubApp.new(organization, config)

          team = find_or_create_team!
