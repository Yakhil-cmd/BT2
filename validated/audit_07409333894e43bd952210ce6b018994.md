### Title
Zero `GasTarget` Governance Parameter Causes Division-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting Block Production — (`params/kip71_config.go`)

---

### Summary

`NextMagmaBlockBaseFee` explicitly guards against `BaseFeeDenominator == 0` to avoid a panic, but applies no equivalent guard for `GasTarget == 0`. A governance vote setting `kip71.gastarget` to zero causes an unrecovered integer division-by-zero panic on every subsequent block that has any non-zero gas usage, permanently halting block production and chain consensus.

---

### Finding Description

`NextMagmaBlockBaseFee` in `params/kip71_config.go` computes the next block's base fee using the KIP-71 formula. The function explicitly handles `BaseFeeDenominator == 0` with a comment "To avoid panic":

```go
// params/kip71_config.go lines 70-76
var baseFeeDenominator *big.Int
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
```

However, `GasTarget` receives no such guard:

```go
// params/kip71_config.go lines 77-78
gasTarget := kc.GasTarget
upperGasLimit := kc.MaxBlockGasUsedForBaseFee
```

When `gasTarget == 0` and `parentGasUsed > 0` (true for any block with transactions), the condition `parentGasUsed > gasTarget` is satisfied and execution reaches:

```go
// params/kip71_config.go lines 100-102
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← division by zero: gasTarget == 0
```

`big.Int.Div` panics on a zero divisor in Go. The only escape hatch is `parentGasUsed == gasTarget`, which requires `parentGasUsed == 0` — an empty block. Any block with even one transaction triggers the panic.

`NextMagmaBlockBaseFee` is called in three critical paths:

1. **Block header validation** — `VerifyMagmaHeader` calls it to check the expected base fee; all nodes reject or panic on every new block.
2. **Block production** — `chain_makers.go` and `tx_pool.go` call it to set the next block's base fee; the proposer node panics and cannot produce blocks.
3. **Gas price oracle** — `gasprice.go` calls it via `isRelaxedNetwork`; RPC nodes panic on fee queries.

The governance system's `FormatChecker` for `Kip71GasTarget` is `noopFormatChecker`, meaning no validation prevents a zero value from being committed on-chain.

---

### Impact Explanation

Once a governance vote setting `kip71.gastarget = 0` is applied, every subsequent block with non-zero gas usage causes an unrecovered panic in `NextMagmaBlockBaseFee`. This crashes all nodes attempting to validate or produce blocks, resulting in a permanent chain halt. No block can be finalized, no transaction can be settled, and no withdrawal or transfer can complete. This is an invalid state transition / consensus divergence on all honest nodes.

---

### Likelihood Explanation

In Kaia's "single" governance mode (the Mainnet configuration), the governing node alone can submit and pass a governance vote. A misconfiguration or a compromised governing node key is sufficient to trigger this. The asymmetry — `BaseFeeDenominator == 0` is explicitly guarded while `GasTarget == 0` is not — suggests the `GasTarget` case was overlooked rather than intentionally excluded.

---

### Recommendation

Add a zero-guard for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // To avoid division-by-zero panic, treat as a no-op (base fee unchanged)
    return makeEvenByFloor(parentBaseFee)
}
```

Additionally, add a non-zero `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` to reject zero at the governance layer before it is committed.

---

### Proof of Concept

1. Governing node submits a governance vote: `kip71.gastarget = 0`.
2. Vote is accepted (no `FormatChecker` rejects it).
3. The parameter takes effect at the next epoch boundary.
4. The next block is produced with any transactions (non-zero `GasUsed`).
5. Every node calls `NextMagmaBlockBaseFee(parentNum, parentBaseFee, parentGasUsed)` where `parentGasUsed > 0`.
6. `parentGasUsed > gasTarget` (0) → enters the increase branch.
7. `x.Div(x, new(big.Int).SetUint64(0))` → Go runtime panic: `division by zero`.
8. All nodes crash. Chain halts permanently until manual intervention and a node software patch. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)
