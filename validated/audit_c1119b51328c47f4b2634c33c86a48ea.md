### Title
`isContractAddr` Uses `extcodesize`, Enabling CREATE2+SELFDESTRUCT to Bypass Zeroed-Address Quorum and Trigger Unauthorized KAIA Mint in KIP-160 Treasury Rebalance — (`contracts/testing/system_contracts/TreasuryRebalanceV2.sol`, `blockchain/system/rebalance.go`)

---

### Summary

Both `TreasuryRebalance` (KIP-103) and `TreasuryRebalanceV2` (KIP-160) classify a registered address as a contract or EOA using `extcodesize`. A zeroed-address contract that self-destructs between `approve()` and `finalizeApproval()` causes the quorum check to silently switch from contract-mode (requiring `req` valid admin approvals) to EOA-mode (requiring exactly 1 approver). Under KIP-160, there is no check that total zeroed balance covers total allocated amounts, so if the zeroed contract's funds were moved out via `SELFDESTRUCT` before the rebalance block, `RebalanceTreasury` mints the full allocated amount to recipients with no corresponding burn.

---

### Finding Description

`isContractAddr` is implemented in both contracts as:

```solidity
function isContractAddr(address _addr) public view returns (bool) {
    uint256 size;
    assembly { size := extcodesize(_addr) }
    return size > 0;
}
``` [1](#0-0) 

This result is not stable. A contract deployed via `CREATE2` can be destroyed with `SELFDESTRUCT`, after which `extcodesize` returns 0 for the same address.

`checkZeroedsApproved()` (called inside `finalizeApproval()` and again by the core via `CheckZeroedsApproved`) branches on this value:

```solidity
bool isContract = isContractAddr(zeroed.addr);
if (isContract) {
    (address[] memory adminList, uint256 req) = _getState(zeroed.addr);
    require(zeroed.approvers.length >= req, "min required admins should approve");
    // ... validate each approver is still in adminList
} else {
    require(zeroed.approvers.length == 1, "EOA should approve");
}
``` [2](#0-1) 

If a zeroed contract with quorum `req = 2` self-destructs after only 1 admin has called `approve()`, the EOA branch fires and `approvers.length == 1` passes, bypassing the quorum entirely.

The core's `RebalanceTreasury` re-runs this check at the rebalance block:

```go
if err = caller.CheckZeroedsApproved(nil); err != nil {
    return result, err
}
``` [3](#0-2) 

For KIP-160, the balance-sufficiency guard that exists for KIP-103 is absent:

```go
if isKIP103 && totalZeroedAmount.Cmp(totalAllocatedAmount) < 0 {
    return result, ErrRebalanceNotEnoughBalance
}
``` [4](#0-3) 

Execution then unconditionally sets each allocated address to its stored amount:

```go
for addr, balance := range result.After.Allocated {
    currentBalance := state.GetBalance(addr)
    result.Burnt.Add(result.Burnt, currentBalance)
    state.SetBalance(addr, balance)
}
``` [5](#0-4) 

If the zeroed contract's balance was already moved out via `SELFDESTRUCT`, `totalZeroedBalance` is 0 while `totalAllocatedBalance` is the full intended distribution — a net KAIA mint.

---

### Impact Explanation

Under KIP-160 (`TreasuryRebalanceV2`):

- **Quorum bypass**: A zeroed contract holder can obtain `finalizeApproval` with fewer admin signatures than the contract's own quorum requires.
- **Unauthorized KAIA mint**: If the zeroed contract's balance is moved out before the rebalance block (via `SELFDESTRUCT` recipient), the core zeros an already-empty address and still credits the full allocated amounts to recipients, creating KAIA from nothing.
- The corrupted value is the KAIA balance of each `allocated` address: it is set to `ret.Amount` regardless of whether any corresponding funds were actually burned. [6](#0-5) 

---

### Likelihood Explanation

The zeroed addresses in a treasury rebalance are existing treasury contracts (e.g., KGF, KIR) whose holders have a direct financial incentive to resist having their balances zeroed. If any such contract was deployed via `CREATE2` (or contains a `SELFDESTRUCT` path), its administrators can execute this attack. The `extcodesize`-based EOA/contract distinction is a well-known fragile pattern; the OrchidLottery report documents the exact same class of failure.

---

### Recommendation

1. **Snapshot the contract/EOA classification at registration time** (`registerZeroed`) and store it immutably, rather than re-evaluating it dynamically via `extcodesize` at approval and finalization time.
2. **Use `extcodehash`** instead of `extcodesize` to detect self-destructed contracts: a self-destructed account returns `bytes32(0)` for `extcodehash`, distinguishing it from a live contract (`hash != 0 && hash != EMPTY_CODE_HASH`) and from a plain EOA (`hash == EMPTY_CODE_HASH`).
3. **Add the balance-sufficiency guard to KIP-160** (`TreasuryRebalanceV2`) analogous to the KIP-103 check, so that `totalAllocatedAmount > totalZeroedAmount` aborts execution.

---

### Proof of Concept

```
1. Deploy MaliciousZeroed via CREATE2 at address A.
   - getState() returns ([attacker], 2)   // quorum = 2
   - selfDestruct() sends balance to attacker

2. Owner calls TreasuryRebalanceV2.registerZeroed(A)
   Owner calls TreasuryRebalanceV2.registerAllocated(recipient, 1_000_000e18)
   Owner calls TreasuryRebalanceV2.finalizeRegistration()

3. Attacker calls TreasuryRebalanceV2.approve(A)
   // extcodesize(A) > 0 → contract branch
   // attacker is in adminList → approval recorded (approvers.length = 1)

4. Attacker calls MaliciousZeroed.selfDestruct(attacker)
   // A's balance moves to attacker; extcodesize(A) = 0 henceforth

5. Owner calls TreasuryRebalanceV2.finalizeApproval()
   // checkZeroedsApproved(): extcodesize(A) = 0 → EOA branch
   // require(approvers.length == 1) → PASSES (quorum=2 bypassed)
   // status → Approved

6. At rebalanceBlockNumber, core calls RebalanceTreasury():
   // fillZeroed: balance(A) = 0
   // fillAllocated: recipient gets 1_000_000e18
   // CheckZeroedsApproved: EOA branch, passes
   // KIP-160: no balance-sufficiency check
   // state.SetBalance(A, 0)                    // no-op
   // state.SetBalance(recipient, 1_000_000e18) // NET MINT

func RebalanceTreasury(state *state.StateDB, chain backends.BlockChainForCaller, header *types.Header) (*rebalanceResult, error) {
	var (
		err    error
		caller RebalanceCaller

		result   = newRebalanceReceipt()
		isKIP160 = chain.Config().IsKIP160ForkBlock(header.Number)
		isKIP103 = chain.Config().IsKIP103ForkBlock(header.Number)
	)

	if isKIP160 {
		caller, err = rebalance.NewTreasuryRebalanceV2Caller(chain.Config().Kip160ContractAddress, backends.NewBlockchainContractBackend(chain, nil, nil))
	} else if isKIP103 {
		caller, err = NewKip103ContractCaller(state, chain, header)
	} else {
		return nil, errors.New("rebalancing shouldn't be executed unless the block number is kip103 or kip160 hard fork")
	}
	if err != nil {
		return nil, err
	}

	// Retrieve 1) Get Zeroed
	if err = result.fillZeroed(caller, state); err != nil {
		return result, err
	}

	// Retrieve 2) Get Allocated
	if err = result.fillAllocated(caller, state); err != nil {
		return result, err
	}

	// Validation 1) Check the target block number
	if blockNum, err := caller.RebalanceBlockNumber(nil); err != nil || blockNum.Cmp(header.Number) != 0 {
		return result, ErrRebalanceIncorrectBlock
	}

	// Validation 2) Check whether status is approved. It should be 2 meaning approved
	if status, err := caller.Status(nil); err != nil || status != 2 {
		return result, ErrRebalanceBadStatus
	}

	// Validation 3) Check approvals from zeroeds
	if err = caller.CheckZeroedsApproved(nil); err != nil {
		return result, err
	}

	// Validation 4) Check the total balance of zeroeds are bigger than the distributing amount
	totalZeroedAmount := result.totalZeroedBalance()
	totalAllocatedAmount := result.totalAllocatedBalance()
	if isKIP103 && totalZeroedAmount.Cmp(totalAllocatedAmount) < 0 {
		return result, ErrRebalanceNotEnoughBalance
	}

	// Execution 1) Clear all balances of zeroeds
	for addr := range result.Before.Zeroed {
		state.SetBalance(addr, big.NewInt(0))
		result.After.Zeroed[addr] = big.NewInt(0)
	}
	// Execution 2) Distribute KAIA to all allocateds
	for addr, balance := range result.After.Allocated {
		// if an allocated has KAIA before the allocation, it will be burnt
		currentBalance := state.GetBalance(addr)
		result.Burnt.Add(result.Burnt, currentBalance)

		state.SetBalance(addr, balance)
	}

	// Fill the remaining fields of the result
	remainder := new(big.Int).Sub(totalZeroedAmount, totalAllocatedAmount)
	result.Burnt.Add(result.Burnt, remainder)
	result.Success = true
	return result, nil
