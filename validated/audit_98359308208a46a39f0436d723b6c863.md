### Title
Webhook signature verified against attacker-chosen `repository.owner.login` while the handler acts on independently attacker-controlled `repository.full_name`, allowing cross-organization forged webhook writes - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp`/`webhook_secret` to verify the raw request bytes against using only `params.dig('repository','owner','login')`, while `Shipit::Webhooks::Handlers::Handler`/`PullRequest::OpenedHandler#repository` resolve and mutate the actual target `Repository` using the separately attacker-controlled `params.dig('repository','full_name')`. In a multi-organization Shipit deployment where any configured organization has no `webhook_secret` set, an attacker can pick that organization as the payload's `repository.owner.login` (making `verify_webhook_signature` return `true` unconditionally) while pointing `repository.full_name` at a victim organization's tracked private repository, causing an unauthenticated cross-tenant `ReviewStack` write.

### Finding Description
The broken binding is: `organization_whose_secret_verified_bytes` (derived from `params['repository']['owner']['login']`) `== organization_owning_written_repository` (derived from `params['repository']['full_name']`). This does not hold and nothing in the code enforces it.

Trace:
1. `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, i.e. fully attacker-supplied JSON. [1](#0-0) [2](#0-1) 
2. `Shipit.github` only consults the passed `organization` argument to select config when the installation is in multi-org mode (`github_default_organization` non-nil); in that mode it calls `github_app_config(organization)`, keyed purely off the attacker-chosen string, with no relation to the actual repository field used later. [3](#0-2) 
3. `GitHubApp#verify_webhook_signature` short-circuits `return true unless webhook_secret`, so if the selected org has no configured `webhook_secret` (an explicitly optional setting per `docs/setup.md` and shown as `webhook_secret: # nil` in example multi-org configs), any signature (or none) is accepted. [4](#0-3) 
4. `WebhooksController#create` re-parses `request.raw_post` and dispatches the full attacker-controlled JSON to the matching handler(s), with no re-check of `repository_owner` against `full_name`. [5](#0-4) 
5. `PullRequest::OpenedHandler#repository` resolves the actual target using `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely different JSON field than the one used for signature selection — and its `ExplicitParameters` schema does not even require `repository.owner.login`. [6](#0-5)  `Repository.from_github_repo_name` performs a simple `owner`/`name` lookup with no cross-validation against the verifying organization. [7](#0-6) 
6. If found, `process` calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!`, writing a `ReviewStack` record scoped to the victim repository. [8](#0-7) 

Exploit flow: attacker POSTs `/webhooks` with `X-Github-Event: pull_request`, `params['repository']['owner']['login'] = 'org-a'` (configured in `Shipit.github_apps`/`secrets.github` with no `webhook_secret`), `params['repository']['full_name'] = 'org-b/private-repo'` (a repository already tracked in Shipit and belonging to a different, properly-secured organization), and any/no `X-Hub-Signature`. `verify_signature` passes trivially via step 3; `create` dispatches to `OpenedHandler`, which resolves and writes to `org-b/private-repo` per steps 4–6.

Existing guards do not catch this: `drop_unhandled_event` only checks the event type exists a handler for it; `ExplicitParameters` schemas validate types/presence but never cross-reference `repository.owner.login` against `repository.full_name`; there is no `force_github_authentication`/`User#authorized?`/`require_permission!` gate on the webhooks endpoint at all (it is intentionally public for GitHub-originated calls); `GithubOrganizationUnknown` only rejects wholly unconfigured organizations, not organizations legitimately configured without a secret.

### Impact Explanation
An unauthenticated internet attacker can create a `Shipit::ReviewStack` row for a repository belonging to an organization other than the one whose (absent) secret validated the request bytes, with attacker-controlled branch name (`pull_request.head.ref`), PR title, and other PR metadata, as long as that repository is already tracked by Shipit with a provisioning behavior that auto-creates review stacks (e.g. `allow_all`, or `allow_with_label`/`prevent_with_label` satisfied via attacker-forged `labels`). This is a cross-repository/cross-tenant write triggered without any valid signature over the org-b bytes, matching "Critical: authentication bypass (forged webhook accepted) ... a payload for one repository mutating another's stack." The attack is repeatable against any tracked repository in any other organization on the same Shipit instance, for every event type handled by the webhooks pipeline (push, status, check_suite, pull_request opened/closed/reopened/labeled, membership), not just `pull_request` — the same organization-confusion applies uniformly since `verify_signature` is shared across all events.

### Likelihood Explanation
Requires: (1) Shipit deployed with the multi-organization `github:` config format (per `docs/setup.md`'s "Using Multiple Github Applications" section), (2) at least one configured organization with no `webhook_secret` set (explicitly documented as optional), and (3) a target repository belonging to a different, tracked organization with a provisioning behavior that would auto-create a review stack. Given these preconditions, attacker cost is a single unauthenticated HTTP POST with a crafted JSON body — no GitHub account interaction, no secrets, no session required. This is a configuration-dependent but realistic and repeatable bug in the engine's own signature-selection logic, not a third-party or infrastructure issue.

### Recommendation
In `WebhooksController#verify_signature`/`#create`, after resolving the acting organization from `repository.owner.login`, validate that the repository actually being mutated (`repository.full_name`'s owner segment, or the resolved `Shipit::Repository#owner`) matches that same organization before dispatching to handlers; alternatively, require every multi-org configuration to mandate a non-blank `webhook_secret` (fail closed instead of `return true unless webhook_secret`), removing the trivial bypass path entirely.

### Proof of Concept
Minitest (`ActionDispatch::IntegrationTest`, configuring a multi-org `secrets.github` fixture like `test/dummy/config/secrets_double_github_app.yml` where one org, e.g. `OrgOne`, has no `webhook_secret`):
```ruby
test "cross-org webhook confusion creates ReviewStack for unrelated org's repo without valid signature" do
  repository = Repository.create!(owner: "org-b", name: "private-repo", provisioning_behavior: :allow_all, review_stacks_enabled: true)

  payload = {
    action: "opened",
    number: 99,
    pull_request: {
      id: 1, number: 99, url: "https://api.github.com/x", title: "attacker pr",
      state: "open", additions: 1, deletions: 0,
      head: { sha: "a" * 40, ref: "attacker-branch" },
      user: { login: "attacker" }, assignees: [], labels: []
    },
    repository: { owner: { login: "org-a" }, full_name: "org-b/private-repo" }, # mismatched owner/full_name
    sender: { login: "attacker" }
  }.to_json

  request.headers["X-Github-Event"] = "pull_request"
  # no X-Hub-Signature, or an invalid one — org-a has no webhook_secret

  assert_difference -> { repository.review_stacks.count }, 1 do
    post webhooks_path, params: payload, headers: { "Content-Type" => "application/json" }
  end
  assert_response :ok # not 422
end
```
Assertions on both sides of the binding: `Shipit.github(organization: 'org-a').verify_webhook_signature(...)` returns `true` despite no valid signature over the sent bytes; `Shipit::Repository.from_github_repo_name('org-b/private-repo')` resolves to `org-b`'s repository and gains a new `review_stacks` row — proving `organization_whose_secret_verified != organization_owning_written_repository`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
