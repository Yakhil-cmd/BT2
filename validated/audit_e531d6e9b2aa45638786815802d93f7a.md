Investigation summary: I searched for a Polkadot SDK analog of the USSD `amountToSellUnits` bug — a compounding double-division pattern (`(a * 1e18 / b) / 1e18`) that truncates a ratio to zero before it's ever multiplied by a balance, combined with a missing decimals adjustment for tokens like WBTC.

The closest structural analog in this repo is `pallet-psm`, which — like USSD's rebalancer — mediates between assets of differing decimal precision [1](#0-0) . Its conversion helpers `external_to_internal`/`internal_to_external` apply the decimal scaling factor in a single `checked_mul`/`checked_div` step against the recorded decimals snapshot, rather than computing an intermediate ratio and dividing by a large fixed-point constant twice [2](#0-1) . Both `mint` and `redeem` explicitly guard against the truncation-to-zero case with `Error::AmountTooSmallAfterConversion` [3](#0-2) [4](#0-3) , and round-trip bounds/exactness are covered by dedicated tests [5](#0-4) [6](#0-5) . This decimals-aware design was introduced specifically to fix an earlier version that rejected assets with mismatched decimals [7](#0-6) .

Other similar-purpose arithmetic in the codebase (`pallet-asset-conversion`'s `mul_div`/`get_amount_in`, `pallet-asset-rate`'s fungible conversion, `Perbill`/`Permill` multiplication) all route through `HigherPrecisionBalance` widening or the `overflow_prune_mul`/`multiply_by_rational_with_rounding` primitives that keep the multiply-then-divide order and apply remainder correction, rather than performing the report's flawed "divide, then divide again by a large constant" sequence [8](#0-7) [9](#0-8) [10](#0-9) .

No FRAME/XCM code path reachable from an unprivileged, signed extrinsic reproduces the report's specific defect (a compounded/self-canceling division that silently zeroes an amount while ignoring per-asset decimals). The invariant the report violates — "value scaled to the wrong or lost precision before being multiplied by a balance" — is not present in an exploitable, unguarded form in this codebase.

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}

  description: |-
    Previously pallet-psm rejected any external stablecoin whose decimals did
    not match pUSD. This change normalizes to pUSD units internally so the PSM
    can approve assets with arbitrary decimal precision within a safe range.

    Core changes:
    - New storage: per-asset `AssetDecimals` snapshot and pallet-wide
      `StableDecimals` snapshot. Storage version bumped to 2.
    - Conversion helpers `external_to_pusd` / `pusd_to_external` with checked

    - `mint` and `redeem` use round-trip rounding. Truncation dust stays in the

      in the reserve and no hidden dust is routed to the fee destination.
    - `PsmDebt` now denominates in pUSD units so aggregate ceilings and issuance
      checks are meaningful across mixed-decimal assets.
    - Runtime drift guard: `mint`/`redeem` return `DecimalsMismatch` if live
      metadata diverges from the registration snapshot; that asset halts until
      governance intervenes.
    - New errors: `DecimalsRangeExceeded`, `ConversionOverflow`,
      `AmountTooSmallAfterConversion`.

/// Returns `a * b / c` (wrapping to 128 bits) or `None` in the case of
/// overflow.
pub const fn multiply_by_rational_with_rounding(
	a: u128,
	b: u128,
	c: u128,
	r: Rounding,
) -> Option<u128> {
	use double128::Double128;
	if c == 0 {
		return None;
	}
	let (result, remainder) = Double128::product_of(a, b).div(c);
	let mut result: u128 = match result.try_into_u128() {
		Ok(v) => v,
		Err(_) => return None,
	};
	if match r {
		Rounding::Up => remainder > 0,
		// cannot be `(c + 1) / 2` since `c` might be `max_value` and overflow.
		Rounding::NearestPrefUp => remainder >= c / 2 + c % 2,
		Rounding::NearestPrefDown => remainder > c / 2,
		Rounding::Down => false,
	} {
		result = match result.checked_add(1) {
			Some(v) => v,
			None => return None,
		};
	}
	Some(result)
}

fn overflow_prune_mul<N, P>(x: N, part: P::Inner, rounding: Rounding) -> N
where
	N: MultiplyArg + UniqueSaturatedInto<P::Inner>,
	P: PerThing,
	P::Inner: Into<N>,
{
	let maximum: N = P::ACCURACY.into();
	let part_n: N = part.into();
	let c = rational_mul_correction::<N, P>(x.clone(), part, P::ACCURACY, rounding);
	(x / maximum) * part_n + c
}
