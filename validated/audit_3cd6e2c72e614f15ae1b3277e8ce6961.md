### Title
Webhook signature verified against `repository.owner.login` but repository writes are keyed off unverified `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
This is an analog of the C4 finding where a value used for a critical calculation (accrued interest) was derived from an unauthenticated/mismatched field. Here, `WebhooksController` selects which GitHub App/organization secret to use for HMAC verification based on `params.dig('repository', 'owner', 'login')`, but every event `Handler` (e.g. `PushHandler`, pull-request handlers) resolves the actual `Stack`/`Repository` to mutate using the completely separate, unverified `payload.dig('repository', 'full_name')` field. The signature only proves the payload was signed with organization A's `webhook_secret`; it proves nothing about which repository's data (`full_name`) is inside that payload.

### Finding Description
`verify_signature` computes the GitHub App/organization to check the signature against from the attacker-controlled JSON body itself: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` looks up the webhook secret keyed by that same `repository_owner` value, taken from the multi-tenant config: [3](#0-2) 

Once the signature check passes, `create` dispatches the parsed JSON body unchanged to every registered handler for the event: [4](#0-3) 

Every handler's base class computes the target `Repository`/`Stack` via a *different* field of the same payload — `repository.full_name` — not `repository.owner.login`: [5](#0-4) 

`PushHandler` uses this to sync every non-archived stack on the matching branch: [6](#0-5) 

`Repository.from_github_repo_name` splits `full_name` on `/` to find owner+name independently of what was used for signature verification: [7](#0-6) 

**Equality that should hold but doesn't:** `organization whose webhook_secret authenticated the request == owner of the repository whose Stack is mutated by the handler`. Because `repository.owner.login` and `repository.full_name` are two independent attacker-controlled keys inside the same signed JSON body, an attacker with a valid webhook secret for organization A (e.g. because they administer their own GitHub App/org configured in Shipit's multi-tenant `secrets.github`, per `docs/setup.md`'s "multiple GitHub applications" schema) can craft a payload where `repository.owner.login = "org-a"` (so `verify_signature` picks org A's secret and the HMAC computed with A's `webhook_secret` validates) while `repository.full_name = "org-b/some-other-repo"` (so the handler acts on org B's stack).

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" trust boundary explicitly called out as in-scope. A `push` event forged this way triggers `GithubSyncJob`/`stack.sync_github` for a stack belonging to a repository the attacker's organization does not own, and other handlers (e.g. `status`, `check_suite`, pull-request-related handlers using `Repository.from_github_repo_name(params.repository.full_name)`) similarly act on/archive/unarchive review stacks, update PR state, or record commit statuses for a foreign repository. This is a cross-repository write triggered purely by owning any one configured organization's webhook secret — matching the Critical "cross-repository writes" impact bucket.

### Likelihood Explanation
Requires knowledge of a valid `webhook_secret` for at least one organization configured in the multi-tenant `github:` secrets schema (each org typically owns/knows its own webhook secret, since it's set when creating that org's GitHub App) plus the ability to send an HTTP POST to `/webhooks` with a forged JSON body — no GitHub-side webhook delivery or repository write access is needed, since the controller does not check that `full_name`'s owner matches `repository.owner.login`. This is realistic in the documented multi-org deployment mode.

### Recommendation
In `WebhooksController#verify_signature`, or in `Shipit::Webhooks::Handlers::Handler#repository_name`, enforce that the owner segment of `repository.full_name` matches `repository.owner.login` (the value used to pick the webhook secret) before any handler runs, and reject (422) mismatches.

### Proof of Concept
1. Configure Shipit with two organizations in `secrets.github` (multi-tenant schema), `org-a` and `org-b`, each with its own `webhook_secret`.
2. Obtain/know `org-a`'s `webhook_secret` (e.g., because the attacker administers `org-a`'s GitHub App).
3. Craft a `push` event body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "org-a" },
    "full_name": "org-b/victim-repo"
  }
}
```
4. Sign it with `org-a`'s `webhook_secret` (`sha1=` HMAC over the raw body) and POST to `/webhooks` with `X-Github-Event: push` and the computed `X-Hub-Signature`.
5. `verify_signature` resolves `repository_owner => "org-a"`, fetches org A's `GitHubApp`, and validates the signature successfully (see `verify_webhook_signature`): [8](#0-7) 
6. `PushHandler#process` then resolves `stacks` via `Repository.from_github_repo_name("org-b/victim-repo")` and calls `stack.sync_github(expected_head_sha: ...)` on `org-b`'s stack — a repository the attacker does not control and whose organization never signed this request.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
