Confirmed: no repo ID/node-ID or any identity anchor is stored or checked anywhere in `internal/skills/*` — identity is tracked purely by `owner`/`repo` strings.

### Title
Update flow re-resolves skills by mutable `owner/repo` name with no identity pinning, allowing repo-jacking to silently substitute attacker content - (File: pkg/cmd/skills/update/update.go)

### Summary
`gh skill update` re-resolves an installed skill's remote source purely by the `owner`/`repo` strings recorded in `SKILL.md` frontmatter, with no persistent identity anchor (e.g., GitHub's immutable repository node/database ID) to confirm the resolved repository is the same one the skill was originally installed from. If the original `owner/repo` name becomes available (account rename/deletion) and is reclaimed by an attacker who publishes a same-named repository, the next `gh skill update` will treat any content there as a legitimate "newer version" and overwrite the local skill.

### Finding Description
`scanInstalledSkills` (`pkg/cmd/skills/update/update.go:554`) and its helper `parseInstalledSkill` (`update.go:601-639`) only read locally-trusted frontmatter fields (`github-repo`, `github-tree-sha`, `github-pinned`, `github-path`) via `source.ParseMetadataRepo`, extracting `owner`/`repo`/`host` strings. No repository identity beyond these mutable strings is captured or persisted at install time — confirmed by `frontmatter.InjectGitHubMetadata` (`internal/skills/frontmatter/frontmatter.go:70-98`), which only ever writes `github-repo` (a URL built from owner/repo), `github-ref`, `github-tree-sha`, `github-path`, and `github-pinned`. Nothing like a repository node ID or database ID is stored anywhere in `internal/skills/*`.

At update time, `updateRun` (`update.go:257-313`) uses these strings directly to call `discovery.ResolveRef(apiClient, s.repoHost, s.owner, s.repo, "")` (`internal/skills/discovery/discovery.go:207`) and `discovery.DiscoverSkills(...)`, both of which hit the GitHub REST API at `repos/{owner}/{repo}/...`. These endpoints resolve to whatever repository currently occupies that `owner/repo` path — GitHub does not guarantee identity continuity for a name once an account is renamed/deleted and reclaimed. The only comparison performed (`update.go:303`) is `remote.TreeSHA != s.treeSHA`, which is purely a "has this repo's tree changed" heuristic, not a source-identity check. If the name is repo-jacked, this comparison trivially evaluates true (new content, new tree SHA) and `updateSkillInPlace` (`update.go:418-462`) installs and atomically swaps the attacker's content into the existing skill directory — with no error, warning, or identity-mismatch prompt.

Root cause: the entire trust model in `pkg/cmd/skills/update/update.go` treats `owner/repo` name as a stable identity, when GitHub only guarantees stability of numeric/node IDs, not names. `--pin` mode (`s.pinned`) mitigates version drift but pins a *ref name* (tag/branch), not the repository identity, so pinned skills remain equally vulnerable to a repo-jacked `owner/repo`.

### Impact Explanation
A victim who has installed a skill from `owner/repo` and later runs `gh skill update` (interactively, with `--all`, or in CI) can have their local `SKILL.md` and any accompanying files (scripts, prompts) silently overwritten with attacker-controlled content once `owner/repo` is reclaimed by an attacker. Skills are typically consumed by AI coding agents (Copilot, Claude, Cursor, etc.) that execute or heavily weight the skill's instructions/scripts, so attacker-controlled content reaching the developer's skill directory can translate into command/code execution on the developer's machine — matching a Critical "arbitrary code execution" / RCE impact class.

### Likelihood Explanation
Requires the original `owner/repo` name to become available (e.g., account deletion/rename, org name change, or repo deletion followed by recreation under the same path) and an attacker to claim it and publish a repository with matching skill content/tree structure — a well-documented "repo-jacking" technique used against numerous package ecosystems that rely on GitHub URLs as identity. This does not require any privileged action, token leak, or MITM; it only requires the attacker to publish content under a reclaimed name, which is squarely within the described attacker capability ("a remote GitHub user who publishes repos ... or controls responses from a host the victim points gh at" via public registry metadata). Likelihood is moderate — bounded by the precondition that the original name must become available — but is entirely realistic over the lifetime of installed skills, and requires no interaction beyond the victim's routine `gh skill update`.

### Recommendation
Persist an immutable repository identity (GitHub repository `id`/`node_id`) in the injected frontmatter/lockfile at install time. At update time, fetch the current repository's `id` via `GET /repos/{owner}/{repo}` and compare it against the recorded value before treating any resolved content as a legitimate update; on mismatch, abort with an explicit warning requiring user confirmation (similar to SSH host-key-change prompts) rather than silently updating.

func updateSkillInPlace(opts *UpdateOptions, u pendingUpdate, apiClient *api.Client, gitRoot, homeDir string) error {
	if u.local.dir == "" {
		return fmt.Errorf("cannot update %s: no install location recorded", u.local.name)
	}

	parent := filepath.Dir(u.local.dir)
	if err := os.MkdirAll(parent, 0o755); err != nil {
		return fmt.Errorf("could not ensure parent directory %s: %w", parent, err)
	}

	// Stage as a sibling of the existing skill directory so the swap stays
	// on the same filesystem and every rename is atomic.
	staging, err := os.MkdirTemp(parent, "."+u.skill.Name+".gh-skill-update-")
	if err != nil {
		return fmt.Errorf("could not create staging directory: %w", err)
	}
	defer os.RemoveAll(staging)

	installOpts := &installer.Options{
		Host:    u.local.repoHost,
		Owner:   u.local.owner,
		Repo:    u.local.repo,
		Ref:     u.resolved.Ref,
		SHA:     u.resolved.SHA,
		Skills:  []discovery.Skill{u.skill},
		Dir:     staging,
		GitRoot: gitRoot,
		HomeDir: homeDir,
		Client:  apiClient,
	}
	if _, err := installer.Install(installOpts); err != nil {
		return err
	}

	stagedSkillDir := filepath.Join(staging, u.skill.Name)
	if _, err := os.Stat(stagedSkillDir); err != nil {
		return fmt.Errorf("installer did not produce %s: %w", stagedSkillDir, err)
	}

	if err := os.MkdirAll(u.local.dir, 0o755); err != nil {
		return fmt.Errorf("could not ensure skill directory %s: %w", u.local.dir, err)
	}

	return swapDirectoryContents(u.local.dir, stagedSkillDir)
}

// parseInstalledSkill parses a SKILL.md file and returns an installedSkill.
func parseInstalledSkill(data []byte, name, dir string, host *registry.AgentHost, scope registry.Scope) (installedSkill, bool) {
	result, err := frontmatter.Parse(string(data))
	if err != nil {
		return installedSkill{
			name:        name,
			dir:         dir,
			host:        host,
			scope:       scope,
			metadataErr: fmt.Errorf("invalid SKILL.md: %w", err),
		}, true
	}

	s := installedSkill{
		name:  name,
		dir:   dir,
		host:  host,
		scope: scope,
	}

	if result.Metadata.Meta != nil {
		repoInfo, ok, repoErr := source.ParseMetadataRepo(result.Metadata.Meta)
		if repoErr != nil {
			s.metadataErr = repoErr
		} else if ok {
			if err := source.ValidateSupportedHost(repoInfo.RepoHost()); err != nil {
				s.metadataErr = err
			} else {
				s.repoHost = repoInfo.RepoHost()
				s.owner = repoInfo.RepoOwner()
				s.repo = repoInfo.RepoName()
			}
		}
		s.treeSHA, _ = result.Metadata.Meta["github-tree-sha"].(string)
		s.pinned, _ = result.Metadata.Meta["github-pinned"].(string)
		s.sourcePath, _ = result.Metadata.Meta["github-path"].(string)
	}

	return s, true
}

// ResolveRef determines the git ref to use for a given owner/repo.
// Priority: explicit version > latest release tag > default branch.
func ResolveRef(client *api.Client, host, owner, repo, version string) (*ResolvedRef, error) {
	if version != "" {
		return resolveExplicitRef(client, host, owner, repo, version)
	}
	ref, err := resolveLatestRelease(client, host, owner, repo)
	if err == nil {
		return ref, nil
	}
	// Only fall back to the default branch when the repository genuinely
	// has no releases (404) or the latest release has no tag. Any other
	// API error (403, 500, network failure, …) is surfaced immediately
	// so it cannot silently mask problems and cause an unexpected ref to
	// be used.
	var nre *noReleasesError
	if !errors.As(err, &nre) {
		return nil, err
	}
	return resolveDefaultBranch(client, host, owner, repo)
}

// InjectGitHubMetadata adds GitHub tracking metadata to the spec-defined
// "metadata" map in frontmatter. Keys are prefixed with "github-" to avoid
// collisions with other tools' metadata.
// pinnedRef is the user's explicit --pin value; empty string means unpinned.
// skillPath is the skill's source path in the repo (e.g. "skills/author/my-skill").
func InjectGitHubMetadata(content string, host, owner, repo, ref, treeSHA, pinnedRef, skillPath string) (string, error) {
	result, err := Parse(content)
	if err != nil {
		return "", err
	}

	if result.RawYAML == nil {
		result.RawYAML = make(map[string]interface{})
	}

	meta, _ := result.RawYAML["metadata"].(map[string]interface{})
	if meta == nil {
		meta = make(map[string]interface{})
	}
	delete(meta, "github-owner")
	meta["github-repo"] = source.BuildRepoURL(host, owner, repo)
	meta["github-ref"] = ref
	delete(meta, "github-sha")
	meta["github-tree-sha"] = treeSHA
	meta["github-path"] = skillPath
	if pinnedRef != "" {
		meta["github-pinned"] = pinnedRef
	} else {
		delete(meta, "github-pinned")
	}
	result.RawYAML["metadata"] = meta

	return Serialize(result.RawYAML, result.Body)
}
