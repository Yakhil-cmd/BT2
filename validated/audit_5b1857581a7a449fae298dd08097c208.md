### Title
EIP-712 domain separator uses a static `Config::ChainId` constant that does not track actual chain identity, enabling permit signature replay across redeployments/forks - ([File: substrate/frame/assets/precompiles/src/permit.rs])

### Summary
The `pallet-assets-precompiles` permit module implements EIP-2612 gasless approvals for ERC20 asset precompiles using an EIP-712 domain separator [1](#0-0) . The domain separator's chain-id component is taken from a fixed `Config::ChainId: Get<u64>` associated constant rather than any value that is provably bound to the actual, currently-running chain's unique identity (such as its genesis hash) [2](#0-1) [3](#0-2) .

### Finding Description
`compute_domain_separator` builds the EIP-712 domain separator as `keccak256(DOMAIN_TYPEHASH || name_hash || version_hash || chain_id || verifying_contract)`, where `chain_id = T::ChainId::get()` is a `#[pallet::constant]` fixed in the runtime's `Config` implementation, not derived from any live/dynamic chain-identity source (e.g. `frame_system::Pallet::<T>::block_hash(0)` / genesis hash) [4](#0-3) . `permit_digest` then feeds this separator into the final EIP-712 digest that is ECDSA-recovered against the claimed `owner` in `use_permit` [5](#0-4) .

This mirrors exactly the reported bug class: a chain-id value baked into the signed domain that is not tied to the chain's true, forkable identity. In FRAME, `frame_system::CheckGenesis` deliberately uses the *runtime-queried* genesis block hash for replay protection between different networks precisely to avoid this kind of hardcoding problem [6](#0-5) . The permit domain separator, in contrast, never consults `frame_system`'s genesis hash or any other chain-specific runtime state — it only uses the static `T::ChainId` constant configured at compile time.

Consequently, if the exact same runtime code/config (and hence the same `ChainId` constant) is used to launch a new network instance that shares the same verifying-contract address and asset/token name — e.g. a chain relaunch/reset (new genesis), a long-lived testnet reset, or a forked deployment of the same runtime under a different network — a permit signature that was valid on the original chain remains bit-for-bit valid on the new one, because the domain separator computation is identical in both cases. The signer never had any way to scope their signature to "this specific chain instance," only to the fixed `ChainId` constant compiled into the runtime.

### Impact Explanation
An attacker who captured a previously-signed, still within-deadline permit signature (via the mempool, an indexer, or any public broadcast of the signed payload) could resubmit it on a new/forked deployment of the identical runtime configuration to obtain the owner's approval there too, without the owner's consent for that specific network instance. This grants the attacker (or their designated spender) an ERC20 allowance they were never authorized on the new chain, which is the classic permit-replay-after-fork impact called out in the original report.

### Likelihood Explanation
Likelihood is Medium: it requires (a) the runtime being redeployed/relaunched with the exact same `Config::ChainId` value, verifying-contract address, and asset name — which is realistic for testnet resets or intentional forks of the same runtime code (e.g., AssetHub Westend genesis resets) — and (b) an unexpired permit signature being available for replay. It does not require any privileged role, governance action, or malicious validator/collator; only ordinary public broadcast of a previously signed permit payload.

### Recommendation
Bind the EIP-712 domain separator to a value that changes whenever the chain's actual identity changes, consistent with how `frame_system::CheckGenesis` already provides replay protection between networks. Concretely, incorporate the genesis block hash (via `frame_system::Pallet::<T>::block_hash(Zero::zero())`) into the domain separator (or into the signed payload independently of the domain separator) instead of, or in addition to, the static `Config::ChainId` constant, so that a `permit` signature valid on one chain instance cannot be replayed on a separately-launched instance of the same runtime configuration.

### Proof of Concept
No dynamic PoC was executed against a live network; this is a static code-level finding derived from reading `substrate/frame/assets/precompiles/src/permit.rs` and confirming (via `substrate/frame/assets/precompiles/src/permit_tests.rs`) that `compute_domain_separator` is deterministic purely as a function of `(verifying_contract, name, T::ChainId)` [7](#0-6) , with no dependency on genesis hash or any other chain-specific runtime state. The prdoc confirms this permit module is shipped into the `asset-hub-westend-runtime` production runtime [8](#0-7) , establishing real-world reachability. A full end-to-end replay-across-relaunch reproduction (deploying two separate chain instances with identical `ChainId`/config and replaying a signed permit between them) was not executed due to the read-only nature of this analysis; the finding is based on direct code inspection showing the missing chain-identity binding, matching the exact violated invariant described in the source report.

		/// Compute the EIP-712 domain separator for a given verifying contract.
		///
		/// DOMAIN_SEPARATOR = keccak256(abi.encode(
		///   keccak256("EIP712Domain(string name,string version,uint256 chainId,address
		/// verifyingContract)"),
		///   keccak256(name),
		///   keccak256("1"),
		///   chainId,
		///   verifyingContract
		/// ))
		///
		/// The `name` parameter should be the token name per EIP-2612 specification.
		pub fn compute_domain_separator(verifying_contract: &H160, name: &[u8]) -> H256 {
			let name_hash = keccak_256(name);
			let version_hash = keccak_256(b"1");
			let chain_id = T::ChainId::get();

			// Encode: typehash || name_hash || version_hash || chainId || verifyingContract
			let mut data = Vec::with_capacity(DOMAIN_SEPARATOR_ENCODED_LEN);
			data.extend_from_slice(&DOMAIN_TYPEHASH);
			data.extend_from_slice(&name_hash);
			data.extend_from_slice(&version_hash);
			// Pad chain_id to 32 bytes (big-endian)
			data.extend_from_slice(&[0u8; 24]);
			data.extend_from_slice(&chain_id.to_be_bytes());
			// Pad address to 32 bytes
			data.extend_from_slice(&[0u8; 12]);
			data.extend_from_slice(verifying_contract.as_bytes());

			H256(keccak_256(&data))
		}

		/// Compute the final EIP-712 digest to be signed.
		///
		/// digest = keccak256("\x19\x01" || domainSeparator || structHash)
		///
		/// The `name` parameter should be the token name per EIP-2612 specification.
		pub fn permit_digest(
			verifying_contract: &H160,
			name: &[u8],
			owner: &H160,
			spender: &H160,
			value: &[u8; 32],
			nonce: &U256,
			deadline: &[u8; 32],
		) -> [u8; 32] {
			let domain_separator = Self::compute_domain_separator(verifying_contract, name);
			let struct_hash = Self::permit_struct_hash(owner, spender, value, nonce, deadline);

			let mut data = Vec::with_capacity(DIGEST_PREFIX_LEN);
			data.extend_from_slice(&[0x19, 0x01]);
			data.extend_from_slice(domain_separator.as_bytes());
			data.extend_from_slice(struct_hash.as_bytes());

			keccak_256(&data)
		}
