### Title
Missing per-organization webhook signature enforcement lets an unprivileged attacker forge GitHub webhook events (team membership, push, pull_request) - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::WebhooksController#verify_signature` derives the GitHub App config to check the signature against from the *attacker-supplied payload itself* (`repository_owner`), then delegates the actual cryptographic check to `GitHubApp#verify_webhook_signature`. That method silently treats "no configured secret" as "verified": `return true unless webhook_secret` [1](#0-0) . `Shipit.github(organization:)` resolves the App config per-organization from `secrets.github`, and each org entry may independently have a blank/absent `webhook_secret` (the multi-org schema documented in `config/secrets.development.shopify.yml` explicitly shows `webhook_secret: # nil` per org) [2](#0-1) . This breaks the binding: **"organization whose secret authenticated the HMAC" == "organization/repository whose state is mutated by the handler."** When any configured org has no webhook secret, the equality degenerates to "any payload claiming that org's name is accepted," even though the same request also drives `Handler#stacks`/`Repository.from_github_repo_name` and, critically, `MembershipHandler`, which uses `params.organization.login` verbatim to create/update `Team` records and add/remove `Membership`s [3](#0-2) .

### Finding Description
`WebhooksController#verify_signature` computes `repository_owner` straight from the untrusted JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`) and passes it into `Shipit.github(organization: repository_owner)` [4](#0-3) . `Shipit.github` looks up that org's `GitHubApp` instance from `secrets.github` [2](#0-1) , and `GitHubApp#verify_webhook_signature` unconditionally passes when that org's `webhook_secret` is blank [1](#0-0) .

Because the handler dispatch (`Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, `app/controllers/shipit/webhooks_controller.rb:12`) trusts the exact same untrusted payload for both the "which org's key verifies this" decision and the "which org/repo do I mutate" decision, an attacker who targets an org entry with no `webhook_secret` set can submit an arbitrary, unsigned `X-Github-Event: membership` payload naming any `organization.login`, `team{id,slug,name,url}` and `member.login` of their choosing. `MembershipHandler#process` will `find_or_create_team!` and then `team.add_member(member)` with zero verification that GitHub actually sent this event [3](#0-2) . Because `Shipit.github_teams` is used as the sole authorization gate for `User#authorized?` (`@authorized ||= Shipit.github_teams.empty? || teams.where(id: Shipit.github_teams.map(&:id)).exists?`, `app/models/shipit/user.rb:80-82`), an attacker who already has (or creates) a Shipit `User`/OAuth session for their own GitHub identity can forge a `membership added` event that inserts their own `User` (via `User.find_or_create_by_login!`) into a `Team` matching `Shipit.github_teams`, thereby escalating from an ordinary/unauthorized GitHub identity into the authorized team gate used by `authorized?`.

### Impact Explanation
This crosses the High-severity bar "escalation into `Shipit.github_teams` authorization" without ever presenting a valid GitHub webhook signature, `ApiClient` token, or session privilege — it only requires an org entry in the Shipit deployment's multi-tenant GitHub config with an unset `webhook_secret`, which the engine's own `GitHubApp#verify_webhook_signature` treats as "always verified" rather than "misconfigured/deny." The same bypass also lets an unprivileged attacker forge `push` (triggering `stack.sync_github`) and `pull_request` events (creating/archiving Review Stacks) for any repository whose owning org shares that unsecured config entry, since `Handler#stacks`/`Repository.from_github_repo_name` also trust `payload.dig('repository','full_name')` unconditionally once `verify_signature` passes [5](#0-4) .

### Likelihood Explanation
Likelihood is contingent on operator configuration: the multi-org GitHub App schema explicitly ships in the repo's own documentation/config samples with `webhook_secret` left blank per organization (`config/secrets.development.shopify.yml`), and the setup docs describe the webhook secret as merely "optional" rather than mandatory. Any Shipit deployment onboarding a second/new GitHub organization without immediately setting its `webhook_secret` — a state the code path explicitly supports and silently accepts rather than rejects — is exposed. Since exploitation requires no credentials, tokens, or session, it is trivially reachable by any unauthenticated network client once that condition holds.

### Recommendation
Treat a missing/blank `webhook_secret` as a hard misconfiguration rather than an implicit "always verified" bypass: `GitHubApp#verify_webhook_signature` should fail closed (return `false`/raise) when `@webhook_secret` is blank, requiring operators to explicitly opt into disabling verification (e.g., via a distinct `Shipit.authentication_disabled?`-style flag) rather than relying on unset config to silently succeed. Additionally, cross-check that the org/repo asserted by the payload for signature selection matches the org/repo actually mutated by the invoked handler, so a verified-org binding cannot be satisfied by an unrelated org/repo claim in the same forged payload.

### Proof of Concept
1. Operator configures two GitHub orgs in `secrets.github`, e.g. `acme` (with `webhook_secret` set) and `acme-staging` (with `webhook_secret` left blank/nil), per the documented multi-org schema in `config/secrets.development.shopify.yml`.
2. Attacker (no Shipit session, no `ApiClient` token, no GitHub App key) sends:
   ```
   POST /webhooks
   X-Github-Event: membership
   (no X-Hub-Signature required)

   {
     "action": "added",
     "team": {"id": 999999, "name": "Attacker Team", "slug": "attacker-team", "url": "https://api.github.com/teams/999999"},
     "organization": {"login": "acme-staging"},
     "member": {"login": "<attacker-github-login>"}
   }
   ```
3. `WebhooksController#verify_signature` resolves `Shipit.github(organization: "acme-staging")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`), and the request proceeds to `MembershitHandler#process`, creating/updating the `Team` record and adding the attacker's `User` as a member (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-34`).
4. If that `Team` handle matches one of `Shipit.github_teams` (`lib/shipit.rb:256-258`), the attacker's `User#authorized?` now evaluates true, escalating an otherwise unauthorized GitHub identity into the app's team-based authorization gate — with no valid webhook signature ever produced.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
