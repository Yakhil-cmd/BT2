### Title
RAY value overflow during interest accrual permanently freezes a whale market - (File: `common/src/rates/scaling.rs`)

### Summary
A sufficiently large borrowed position can make `borrowed_scaled * borrow_index` exceed the `i128` result domain before the borrow index reaches its protocol ceiling. Because pool operations run `global_sync` before accounting, the resulting `MathOverflow` blocks subsequent withdrawals, repayments, liquidations, and index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description
Debt value is calculated by `scaled_to_original`, which calls `Ray::mul` on the stored scaled debt and live borrow index. [2](#0-1)  `Ray::mul` computes `scaled * index / RAY`; when the quotient cannot fit `i128`, the widened `I256` calculation converts back through `to_i128` and raises `GenericError::MathOverflow`. [3](#0-2) [4](#0-3) [5](#0-4) 

Interest is applied through `global_sync`, which iterates accrual chunks and commits updated indexes only after `accrue_step` succeeds. [6](#0-5)  The borrow-index ceiling therefore does not protect the protocol when the intermediate debt valuation overflows first. [7](#0-6) 

### Impact Explanation
All user funds and unclaimed yield in the affected market can become permanently frozen: after the overflow state is reached, calls that must first accrue interest revert before they can reduce debt or shares. [8](#0-7)  The repository's regression test demonstrates that both `withdraw` and `repay` fail with `MathOverflow` after `update_indexes` reaches the overflow condition, while the index remains below `MAX_BORROW_INDEX_RAY`. [9](#0-8) 

### Likelihood Explanation
An unprivileged flow can create the state through ordinary `supply`, `borrow`, and later `update_indexes` calls, provided the market admits a sufficiently large position and sustained high-utilization interest. [10](#0-9)  The practical likelihood is constrained by the required token liquidity, configured caps, collateral, and elapsed accrual, but it does not require privileged parameters, oracle manipulation, or malformed token behavior. [11](#0-10) 

### Recommendation
Bound market totals and configured caps so `scaled_amount * index / RAY` remains representable at the maximum reachable index, not merely at index `RAY`. Alternatively, clamp accrual before evaluating the unrepresentable debt value and provide an emergency path that can burn debt or write it down without first computing the overflowing total. [2](#0-1) [6](#0-5) 

### Proof of Concept
The existing test creates an 18-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows 98% of it, advances time in yearly chunks, and invokes `update_indexes` until `MathOverflow` occurs. [12](#0-11)  It then verifies that the borrow index is still below its ceiling and that `withdraw` and `repay` both revert with `MathOverflow`, confirming that normal exits cannot repair the state. [13](#0-12)

/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```

fn to_i128(env: &Env, val: &I256) -> i128 {

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
