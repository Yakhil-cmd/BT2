### Title
Interest accrual overflows before the borrow-index cap can engage, permanently freezing a large market - (File: common/src/rates/scaling.rs)

### Summary

`accrue_step` reconstructs the borrowed and supplied values with `scaled_to_original` before applying the `MAX_BORROW_INDEX_RAY` cap, so a sufficiently large scaled balance can overflow `i128` while the borrow index is still below its intended ceiling. [1](#0-0)   
Because every pool mutation loads the market through `synced_market`, which always runs `interest::global_sync` first, the resulting `MathOverflow` becomes a persistent gate for that market rather than a one-transaction failure. [2](#0-1)   
The repository’s long-horizon test demonstrates this exact cliff: after sustained high utilization, `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [3](#0-2) 

### Finding Description

`scaled_to_original` is a direct `Ray::mul` of the scaled share amount by the market index. [4](#0-3)   
That multiplication uses exact intermediate arithmetic, but returns `None` when the final value cannot fit in `i128`; the public wrapper converts that condition into `GenericError::MathOverflow`. [5](#0-4) [6](#0-5)   

The unsafe ordering is in `accrue_step`: it first computes `borrowed_original = scaled_to_original(borrowed, borrow_index)` and only afterwards computes `new_borrow_index = update_borrow_index(...)`. [1](#0-0)   
Although `update_borrow_index` clamps the new index to `MAX_BORROW_INDEX_RAY`, that cap is never reached when reconstructing the old borrowed value overflows first. [7](#0-6)   

A single user can create the vulnerable state through ordinary controller operations: supply collateral with `supply`, create the large debt with `borrow`, and later trigger or simply wait for `update_indexes` or any other market action. [8](#0-7)   
The in-repository proof uses a one-billion-token 18-decimal market, borrows 98% of it, advances ledger time, and observes the accrual failure. [9](#0-8) 

### Impact Explanation

Once the product `borrowed * borrow_index / RAY` exceeds `i128::MAX`, every operation that touches the market performs the same failing accrual before its business logic. [2](#0-1)   
Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot complete repayment/seizure, and the pool cannot settle or service that market. [10](#0-9)   
The panic rolls back each transaction without advancing `last_timestamp`, so retrying later reaches the same overflowing product rather than recovering. [11](#0-10)   
This is permanent freezing of user funds and can leave an underwater position unliquidatable, creating protocol-insolvency exposure. [12](#0-11) 

### Likelihood Explanation

The trigger requires a very large market balance, an index large enough that its value reconstruction exceeds `i128`, and sufficient elapsed time at a high-utilization rate. [13](#0-12)   
Those requirements are economically significant, but they arise from valid share/index accounting rather than privileged calls, malformed calldata, token misbehavior, or resource exhaustion. [14](#0-13)   
The checked regression shows the bound is reachable on the configured XLM-style curve within the modeled horizon and that the intended index ceiling does not prevent it. [15](#0-14) 

### Recommendation

Do not derive the current debt or supplied value through an `i128` product before enforcing the index ceiling. [1](#0-0)   
Store or carry unscaled aggregate debt/supply values for accrual, or perform the reconstruction and utilization/reward calculations in `I256` with explicit protocol-defined saturation before converting to `i128`. [16](#0-15)   
At minimum, detect the impending overflow in `accrue_step`, clamp the affected index/value according to a documented rule, and add a regression asserting that `update_indexes`, `repay`, `withdraw`, and `liquidate` remain executable at and beyond the boundary. [17](#0-16) 

### Proof of Concept

1. On an 18-decimal market whose configured caps admit the position, attacker supplies `1_000_000_000 * 10^18` base units through `Controller::supply`. [18](#0-17) 
2. Using separately supplied collateral, the attacker borrows 98% of that market through `Controller::borrow`. [19](#0-18) 
3. Ledger time advances until the borrow index is large enough that `borrowed * borrow_index / RAY > i128::MAX`, while still below `MAX_BORROW_INDEX_RAY`. [20](#0-19) 
4. The attacker or any victim calls `update_indexes`, `repay`, `withdraw`, or `liquidate`; `synced_market` enters `global_sync`, `accrue_step` calls `scaled_to_original`, and the call reverts with `MathOverflow`. [2](#0-1) [21](#0-20) 
5. The existing regression demonstrates both the initial accrual failure and the resulting withdrawal/repayment freeze. [22](#0-21)

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
