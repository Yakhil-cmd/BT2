### Title
CCMenu API endpoint scopes token by permission but not by the stack it was issued for - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Api::CCMenuController` overrides the `stack` accessor used by `Api::BaseController` to bypass the per-`ApiClient` stack scoping, letting any token with `read:stack` permission read the build status of any stack, not just the one it was issued for.

### Finding Description
`Api::BaseController#stack` resolves the requested stack from a scope that is restricted to the token's assigned `stack_id` when one is set: [1](#0-0) 

This is the binding the system is supposed to enforce: `ApiClient#stack_id` (the stack a token authorizes) == the stack a request against that token can touch. `ApiClient` itself models this scoping via `belongs_to :stack, optional: true` and `check_permissions!`, which only validates the coarse `operation:scope` permission string (e.g. `read:stack`), not which specific stack record is targeted: [2](#0-1) 

`Api::CCMenuController`, however, redefines `stack` to look up the record directly from `Stack.from_param!(params[:stack_id])`, completely skipping the `stacks` scoping helper that enforces the token-to-stack binding: [3](#0-2) 

The only authorization check that remains is `require_permission :read, :stack`, which is a class-level `before_action` that just calls `current_api_client.check_permissions!(:read, :stack)` — a permission-string check with no relation to the `stack_id` param: [4](#0-3) [5](#0-4) 

The token itself is looked up purely by the `token` param (no additional scoping): [6](#0-5) 

This exactly matches the analog class called out in the rules: "a stack a token authorises versus a stack it touches." `BaseController` establishes the invariant `stack ∈ stacks (scoped by current_api_client.stack_id)`, but `CCMenuController` breaks it by evaluating `stack = Stack.from_param!(params[:stack_id])` unconditionally.

### Impact Explanation
Any holder of a CCMenu token scoped to one stack (these tokens are created automatically and exposed via `CCMenuUrlController#fetch`, e.g. embedded in a CI-status widget URL shared with third parties) can pivot to reading the build/deploy status (`lastBuildStatus`, `lastBuildLabel`, `webUrl`, lock state, etc.) of *any* stack in the Shipit instance by changing the `stack_id` query param, since the controller's `stack` method never checks `current_api_client.stack_id`. This is an unauthenticated-relative-to-target read of stack state (deploy/build status) which matches the in-scope High-severity impact: "unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
High. Exploitation requires only a single valid `read:stack` token (which the app hands out for every stack via the CCMenu integration, `CCMenuUrlController#fetch` creates one) and modifying a URL query parameter — no privileged account, no webhook secret, no session, and no code execution capability is needed.

### Recommendation
In `Api::CCMenuController`, resolve the stack through the same `stacks` scope used by `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!(params[:stack_id])`, so a stack-scoped token cannot be used to query other stacks.

### Proof of Concept
1. As stack A's owner, visit `CCMenuUrlController#fetch` for stack A (`GET /ccmenu/*stack_id`), which creates/returns an `ApiClient` scoped to `stack: A` with `permissions: ['read:stack']` and its `authentication_token`: [7](#0-6) 
2. Take the returned token (`ccmenu_url` query string `token=...`) and call the CCMenu API endpoint for an unrelated stack B: `GET /api/stacks/<stack_B_id>/ccmenu?token=<token_for_stack_A>`.
3. `authenticate_api_client` succeeds (token is valid), `require_permission :read, :stack` passes (`permissions` includes `read:stack`), and `stack` resolves `Stack.from_param!(params[:stack_id])` to stack B regardless of the token's `stack_id`, returning stack B's build/deploy status in the response.

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end

# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
