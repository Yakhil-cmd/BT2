## Finding: CCMenu endpoint duplicates stack-lookup logic and bypasses per-token stack scoping

The reported Solidity bug pattern — a subclass re-implementing base logic in a way that silently drops security-relevant behavior (duplicate `balances`/`allowed` state that isn't kept in sync with the inherited `_balances`/`_allowances`) — has a direct structural analog in `Shipit::Api::CCMenuController`.

### Root cause

`Shipit::Api::BaseController` scopes stack lookups to the authenticated `ApiClient`'s authorized stack when the client is stack-scoped: [1](#0-0) 

`ApiClient` supports being scoped to a single `stack` (`belongs_to :stack, optional: true`), and `check_permissions!` only validates the operation/scope pair (e.g. `read:stack`), it does not validate *which* stack: [2](#0-1) 

So the only place that enforces "this token may only see the stack it's bound to" is `BaseController#stacks`/`#stack`. `CCMenuController` re-implements `stack` instead of inheriting it, dropping that scoping entirely: [3](#0-2) 

`CCMenuController#stack` calls `Stack.from_param!(params[:stack_id])` directly — unscoped — while `BaseController#stack` calls `stacks.from_param!(params[:stack_id])`, where `stacks` restricts to `Stack.where(id: current_api_client.stack_id)` for stack-scoped clients. `require_permission :read, :stack` (also duplicated as a class-level declaration, mirroring the ERC20 report's duplicated `approve`/`transfer`) only checks the permission string, never the stack binding, exactly like the reported `approve`/`transferFrom` mismatch where one function checks a duplicated mapping and the other reads from the "real" one.

### The broken binding

`stack a token authorises == stack a token touches` should hold for every authenticated API surface. It holds in `StacksController`, `CommitsController`, `LocksController`, `MergeRequestsController`, `OutputsController`, `HooksController`, `TasksController`, `DeploysController` (all of which use the inherited, scoped `stack`/`stacks` helpers) — but it is broken specifically in `CCMenuController`, which duplicates the lookup instead of reusing it.

### Attack

1. Attacker obtains (or is issued) an `ApiClient` token scoped to a single stack, e.g. the `here_come_the_walrus` fixture pattern (`stack: shipit`, `permissions: [read:stack]`): [4](#0-3) 
2. Using that token, the attacker calls `GET /ccmenu/*stack_id?token=<token>` (or via Basic Auth) for a **different** `stack_id` belonging to another team/repository they were never granted `read:stack` on.
3. `authenticate_api_client` in `CCMenuController` authenticates the token successfully (it's a valid token) via `ApiClient.authenticate(params[:token])`: [5](#0-4) 
4. `require_permission :read, :stack` passes because the client does have `read:stack` in its generic permission list.
5. `stack` resolves via unscoped `Stack.from_param!`, returning the arbitrary target stack, and `show` renders that stack's build status, last build label/time, and deploy URL — data outside the token's intended scope.

### Impact

This is an authorization-scope escalation: a token deliberately restricted (via `ApiClient#stack_id`) to read one stack's CI/deploy status can instead read CI/build/deploy status (name, last build status/label, last build time) of **any** stack in the Shipit installation, across repositories/teams the token owner has no legitimate access to. This matches the "unauthenticated read of stack state" class of High-impact findings (here, cross-tenant/cross-stack read despite valid authentication, because the per-stack authorization binding is dropped).

### Recommendation

Remove the duplicated `stack` method and `authenticate_api_client` override logic drift in `CCMenuController`; have it inherit `BaseController#stack`/`#stacks` (or explicitly re-apply the `current_api_client.stack_id?` scoping check) so CCMenu lookups are constrained the same way as every other API controller. [6](#0-5)  is the exact file/lines to fix.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
