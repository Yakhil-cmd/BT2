## Finding: Hard-coded DOT/KSM exchange rate can make bridge delivery-fee estimation stale

### Title
Hard-coded DOT/KSM exchange rate in bridge fee estimation can become stale, causing mispriced Bridge Hub delivery fees - (File: `system-parachains/bridge-hubs/bridge-hub-polkadot/primitives/src/lib.rs`, `system-parachains/bridge-hubs/bridge-hub-kusama/primitives/src/lib.rs`)

### Summary
Similar to the Cooler `maxLTC` issue (a constant standing in for a market exchange rate that can drift), this runtime hard-codes a fixed 5:1 DOT/KSM conversion rate used to compute the base cross-chain message delivery fee for the Polkadot↔Kusama bridge, instead of deriving it from any live price source.

### Finding Description
`convert_from_uksm_to_udot` and `convert_from_udot_to_uksm` both assume `ksm_to_dot_economic_rate = FixedU128::from_rational(1, 5)` ("assuming exchange rate is 5 DOTs for 1 KSM"), a value baked in as source code rather than derived from a market oracle. [1](#0-0) [2](#0-1) 

This conversion feeds `estimate_polkadot_to_kusama_message_fee` / `estimate_kusama_to_polkadot_message_fee`, which are in turn used to initialize `XcmBridgeHubRouterBaseFee`, the base fee an unprivileged user pays (in DOT) when routing an XCM message to Kusama through the sibling Bridge Hub: [3](#0-2) 

This value is a `parameter_types! { pub storage ... }`, i.e. computed once and only mutable later via a governance `set_storage` call, exactly like the audited `maxLTC` constant which the sponsor said was "not intended to be updated in real-time... set via gov." [4](#0-3) 

The same pattern also appears in the Snowbridge (Ethereum) pricing parameters, where `exchange_rate: FixedU128::from_rational(1, 1)` is a placeholder ETH/DOT rate explicitly documented as needing to be set correctly by governance before bridge activation: [5](#0-4) 

### Impact Explanation
If the real DOT/KSM market rate diverges materially from the hard-coded 5:1 ratio (as it does for any pair of freely-traded tokens over time), the resulting `XcmBridgeHubRouterBaseFee` under- or over-prices the actual cost of relaying a message between Polkadot's and Kusama's Bridge Hubs. Underpricing lets any unprivileged user send bridge messages more cheaply than the true delivery/confirmation cost is worth, which can be used to cheaply spam the bridge message queue (a griefing/DoS vector against the bridge and its relayers) since relayer rewards (`BridgeHubKusamaBaseDeliveryFeeInKsms`/`BridgeHubPolkadotBaseDeliveryFeeInDots`) no longer reflect market reality. Overpricing simply overcharges legitimate users. Unlike the Cooler case, this does not directly enable draining of collateral/funds — there is no debt/collateral accounting analog here — so the blast radius is narrower (fee mispricing / relayer incentive degradation / spam potential), not fund loss.

### Likelihood Explanation
The DOT/KSM rate is a live, freely-traded market rate that will predictably drift away from a fixed 5:1 constant over time, and no code path re-derives it automatically — it only changes via an explicit governance `set_storage` extrinsic. Any unprivileged user reaching `PolkadotXcm::send`/reserve-transfer to Kusama pays fees computed from this stale constant, so the entry path is fully reachable without any privileged role. Likelihood of the rate becoming stale is high (it already is, since 5:1 is not the current market rate); likelihood of it being exploited for meaningful spam/DoS is moderate since it primarily affects bridge economics rather than direct value extraction.

### Recommendation
Treat `XcmBridgeHubRouterBaseFee`/`XcmBridgeHubRouterByteFee` (and the Snowbridge `PricingParameters.exchange_rate`) as parameters requiring active governance monitoring and periodic re-calibration against real market rates, or replace the hard-coded 5:1 constant with a governance-updatable/oracle-derived rate feeding `convert_from_uksm_to_udot`/`convert_from_udot_to_uksm`, so bridge fees track actual DOT/KSM economics rather than a fixed assumption baked into source code.

### Proof of Concept
1. Observe that `ksm_to_dot_economic_rate` is fixed at `1/5` in `convert_from_uksm_to_udot`/`convert_from_udot_to_uksm`. [6](#0-5) 
2. This feeds `XcmBridgeHubRouterBaseFee`, the fee an unprivileged user pays via `pallet_xcm::send`/reserve transfer routed through `ToKusamaXcmRouter` to reach Kusama's Bridge Hub. [4](#0-3) 
3. As the real DOT/KSM market price diverges from 5:1, any user sending a message pays a fee that no longer matches the actual relaying cost, until a governance `set_storage` call corrects it — mirroring exactly the "hard-coded exchange rate can become stale" root cause of the referenced M-5 finding, just applied to bridging fees instead of loan collateralization.

```rust
/// Convert from uKSMs to uDOTs.
fn convert_from_uksm_to_udot(price_in_uksm: Balance) -> Balance {
	// assuming exchange rate is 5 DOTs for 1 KSM
	let dot_to_ksm_economic_rate = FixedU128::from_rational(5, 1);
	// tokens have different nominals and we need to take that into account
	let nominal_ratio = FixedU128::from_rational(
		polkadot_runtime_constants::currency::UNITS,
		kusama_runtime_constants::currency::UNITS,
	);

	dot_to_ksm_economic_rate
		.saturating_mul(nominal_ratio)
		.saturating_mul(FixedU128::saturating_from_integer(price_in_uksm))
		.into_inner() /
		FixedU128::DIV
}
```
