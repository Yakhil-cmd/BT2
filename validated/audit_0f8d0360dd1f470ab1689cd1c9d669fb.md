### Title
Governance vote for `kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, halting all nodes — (`params/kip71_config.go`)

### Summary

The `kip71.gastarget` governance parameter has no zero-guard in its `FormatChecker` (`noopFormatChecker`), while the analogous `kip71.basefeedenominator` parameter explicitly rejects zero and also has a runtime fallback in `NextMagmaBlockBaseFee`. A governance vote ratifying `GasTarget = 0` causes `NextMagmaBlockBaseFee` to perform integer division by zero via `big.Int.Div`, panicking every node on the network when processing any block with non-zero gas usage.

### Finding Description

**Inconsistent zero-guard between `BaseFeeDenominator` and `GasTarget`**

In `kaiax/gov/param.go`, `Kip71BaseFeeDenominator` has an explicit non-zero `FormatChecker`:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // ← zero rejected at vote time
    },
``` [1](#0-0) 

`Kip71GasTarget` uses `noopFormatChecker` — always returns `true`, accepting zero:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // ← zero accepted
``` [2](#0-1) 

**Runtime zero-check exists for `BaseFeeDenominator` but not for `GasTarget`**

In `NextMagmaBlockBaseFee`, `BaseFeeDenominator` has a runtime fallback:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64)  // ← protected
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget   // ← no zero-check
``` [3](#0-2) 

`gasTarget` is then used as a divisor at two points with no guard:

```go
// line 102 (parentGasUsed > gasTarget branch):
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // panic if gasTarget == 0

// line 120 (parentGasUsed < gasTarget branch):
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // panic if gasTarget == 0
``` [4](#0-3) [5](#0-4) 

**Vote validation does not reject `GasTarget = 0`**

`VerifyVote` in `kaiax/gov/headergov/impl/header.go` checks: not deprecated, voter in council, voter is proposer, and `checkConsistency`. The `checkConsistency` function lists `gov.Kip71GasTarget` in the `return nil` branch — no value check:

```go
case gov.GovernanceDeriveShaImpl, gov.GovernanceGovParamContract, ...,
    gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee, ...:
    return nil   // ← no value validation for GasTarget
``` [6](#0-5) 

`Kip71GasTarget` is not in `AlwaysDeprecated` or `PermissionlessDeprecated`, so it is a live, voteable parameter. [7](#0-6) 

### Impact Explanation

Once `GasTarget = 0` is ratified and takes effect, every call to `NextMagmaBlockBaseFee` where `parentGasUsed > 0` (any block with transactions) enters the `parentGasUsed > gasTarget` branch and panics with a division-by-zero. `big.Int.Div` panics on a zero divisor in Go.

`NextMagmaBlockBaseFee` is called on every new block in:

- `blockchain/tx_pool.go` line 576 — pool reset on every new head (crashes all nodes)
- `work/worker.go` line 382 — block production
- `node/cn/gasprice/gasprice.go` line 334 — gas price oracle
- `node/cn/gasprice/feehistory.go` line 112 — fee history RPC [8](#0-7) [9](#0-8) 

The tx pool reset path is triggered on every new block, so every node on the network panics and crashes when the first block with non-zero gas usage arrives after `GasTarget = 0` takes effect. This is a **chain halt** affecting all honest nodes.

The only escape is if `MaxBlockGasUsedForBaseFee` is also voted to `0` simultaneously (making `parentGasUsed = min(anything, 0) = 0 = gasTarget`, triggering the early return). But the default `MaxBlockGasUsedForBaseFee` is 60,000,000, so under normal conditions the panic is guaranteed on any block with transactions. [10](#0-9) 

### Likelihood Explanation

In `single` governance mode (Mainnet and Kairos), only the governing node can cast a ratified vote. In `none` mode, any council member can. The trigger is a semi-trusted actor (governing node or council member) casting a vote for `kip71.gastarget` with value `0`. The vote passes all existing validation checks because `noopFormatChecker` accepts zero and `checkConsistency` returns `nil` for `Kip71GasTarget` without inspecting the value.

### Recommendation

Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`, matching the pattern already used for `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v > 0   // reject zero
    },
```

Additionally, add a runtime zero-check in `NextMagmaBlockBaseFee` before dividing by `gasTarget`, analogous to the existing `BaseFeeDenominator` guard:

```go
if gasTarget == 0 {
    return makeEvenByFloor(parentBaseFee)
}
``` [11](#0-10) 

### Proof of Concept

1. In `none` governance mode, any council member calls:
   ```
   governance_vote("kip71.gastarget", 0)
   ```
2. The vote passes `NewVoteData` (uint64 canonicalizer accepts 0, `noopFormatChecker` returns true).
3. The vote is inscribed in `header.Vote` when the voter proposes a block.
4. `VerifyVote` accepts it: not deprecated, voter in council, voter is proposer, `checkConsistency` returns `nil`.
5. At the next epoch boundary, the vote is ratified; `GasTarget = 0` takes effect at `(k+1)*epoch`.
6. The first block after that epoch with any gas used (e.g., a simple ETH transfer using 21,000 gas) triggers:
   - `tx_pool.go:576`: `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` is called
   - `parentGasUsed = min(21000, 60000000) = 21000 > 0 = gasTarget`
   - Enters `else if parentGasUsed > gasTarget` branch
   - `x.Div(x, new(big.Int).SetUint64(0))` → **panic: division by zero**
7. All nodes crash. Chain halts. [2](#0-1) [12](#0-11) [13](#0-12)
