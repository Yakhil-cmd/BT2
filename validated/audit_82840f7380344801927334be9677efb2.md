### Title
`Api::CCMenuController#stack` bypasses `current_api_client.stack_id` scoping - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Api::BaseController#stacks`/`#stack` restrict stack resolution to `Stack.where(id: current_api_client.stack_id)` whenever the authenticated `ApiClient` is scoped to a stack [1](#0-0) . `Api::CCMenuController` overrides `#stack` to call `Stack.from_param!(params[:stack_id])` directly, completely bypassing that scope check [2](#0-1) . This means a stack-scoped `ApiClient` token can be used against `GET /api/stacks/:stack_id/ccmenu` for **any** stack, not just the one it is scoped to, while `require_permission :read, :stack` still passes because `ApiClient#check_permissions!` checks only the string permission list, not the record [3](#0-2) .

### Finding Description
Binding claimed: for every `Api::*Controller`, `stack resolved == a member of Scope(current_api_client.stack_id)`, where `Scope(stack_id) = Stack.where(id: stack_id)` if `stack_id` is present, else `Stack.all`.

Tracing the controllers that do **not** override `#stack`/`#stacks` (`Api::TasksController`, `Api::DeploysController`, `Api::HooksController`, and `Api::StacksController`'s `#index`/`#stacks`) confirms the binding holds: they all resolve through `BaseController#stack` → `stacks.from_param!(params[:stack_id])` → `stacks` → `current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all` [1](#0-0) . `Api::StacksController` overrides `#stack` but still calls `stacks.from_param!`, preserving the scope [4](#0-3) . `Api::TasksController#task` and `#index` call `stack.tasks`/`stack.trigger_task`, inheriting the scoped `stack` [5](#0-4) . Existing regression tests corroborate this scoping is a real, tested feature (`shipit_api_clients(:here_come_the_walrus)` is a stack-scoped client, and `"an api client scoped to a stack will only see that one stack"` passes against `StacksController#index`) [6](#0-5) .

`Api::CCMenuController` is the sole exception: it redefines `#stack` to call `Stack.from_param!(params[:stack_id])` directly on the model class, never consulting `current_api_client.stack_id` [7](#0-6) . It also overrides `authenticate_api_client` to accept the token from `params[:token]` (query string) rather than only via HTTP Basic auth [8](#0-7) , which is by itself benign (still requires a valid signed token) but combined with the missing scoping means: any holder of a valid `ApiClient` token restricted to stack A can query `GET /api/stacks/<owner>/<repo>/<env-of-B>/ccmenu?token=<tokenA>` and receive stack B's CI status (`name`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`) via the rendered `shipit/ccmenu/project` template, and `require_permission :read, :stack` does not stop this because it only checks the permission string, not the specific stack record [3](#0-2) .

### Impact Explanation
This is an unauthenticated-scope read of another stack's build/deploy state (name, latest build status/time, web URL) using a token that was only supposed to grant access to a single stack. It matches the High-severity category "unauthenticated read of stack state" since a client credentialed for stack A reads data for stack B with no additional secret needed. It is repeatable against any stack in the installation, for the attacker, as long as they hold any valid `ApiClient` token (even one that is supposed to be scoped narrowly) — the blast radius is limited to CCMenu-exposed data (build status metadata), not deploy secrets, commands, or write actions.

### Likelihood Explanation
Exploitation requires the attacker to already possess a valid `ApiClient` authentication token (signed via `Shipit.api_clients_secret`) that is scoped to a specific stack via the `stack_id` column on `ApiClient`. This scoping is not currently exposed through the web UI's `ApiClientsController#create_params` (`permit(:name, permissions: [])`, no `stack_id`) [9](#0-8) , nor through `CCMenuUrlController#client`, which creates a client with `permissions: %w[read:stack]` but does not set `stack_id` [10](#0-9) . It is only demonstrated as populated via fixtures/tests and presumably via direct DB/console assignment by an operator. This lowers real-world likelihood: the feature (`stack_id`-scoped API clients) is tested and supported by the model/`BaseController`, but no current in-app admin workflow issues such scoped tokens. If an operator does provision stack-scoped tokens (a legitimate, documented use case), the bypass is trivially and repeatedly exploitable with a single GET request per target stack, at zero additional attacker cost beyond having the token.

### Recommendation
Change `Api::CCMenuController#stack` to resolve through the scoped accessor instead of calling `Stack.from_param!` directly, e.g. `@stack ||= stacks.from_param!(params[:stack_id])`, so it inherits `current_api_client.stack_id` filtering exactly like `BaseController#stack`.

### Proof of Concept
```ruby
# test/controllers/api/ccmenu_controller_test.rb
test "a stack-scoped api client cannot fetch ccmenu status for a different stack" do
  other_stack = shipit_stacks(:shipit) # stack B
  scoped_client = ApiClient.create!(
    creator: shipit_users(:walrus),
    name: 'scoped',
    permissions: %w[read:stack],
    stack: shipit_stacks(:cyclimse) # stack A, distinct from other_stack
  )
  request.headers['Authorization'] = "Basic #{Base64.encode64(scoped_client.authentication_token)}"

  get :show, params: { stack_id: other_stack.to_param } # requesting stack B with A-scoped token

  # Binding under test: stack resolved must be a member of
  # Stack.where(id: scoped_client.stack_id), i.e. only stack A.
  # BaseController-derived controllers enforce this (see StacksController test),
  # CCMenuController does not:
  assert_response :not_found # EXPECTED after fix; currently returns :ok exposing stack B's data
end
```
Companion table-driven assertion (base-controller-derived controllers uphold the binding):
```ruby
test "tasks/deploys/stacks controllers scope to current_api_client.stack_id" do
  scoped_client = shipit_api_clients(:here_come_the_walrus) # stack_id set
  other_stack = shipit_stacks(:shipit) # not scoped_client.stack
  request.headers['Authorization'] = "Basic #{Base64.encode64(scoped_client.authentication_token)}"
  # e.g. against Api::TasksController#index for other_stack.id
  get :index, params: { stack_id: other_stack.to_param }
  assert_response :not_found
end
```
