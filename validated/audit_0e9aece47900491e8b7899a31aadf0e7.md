The reported CVE describes a classic web-application SSRF: a caller-supplied `api_base` string is concatenated into a URL and passed unchecked to an HTTP client (`httpx.Client.request`) inside PraisonAI's Python `passthrough()` fallback path. A structural analog would require: (1) a real user entry point (signed extrinsic, contract call, or XCM instruction) that lets an attacker supply an arbitrary destination URL/host, and (2) production Rust code that takes that attacker string and issues an outbound network request to it without validation, with an on-chain-visible consequence.

I checked the only place in `polkadot-sdk` that performs outbound HTTP calls: the offchain worker HTTP API (`sp_io::offchain::http_request_start` in `substrate/primitives/io/src/lib.rs`, `substrate/client/offchain/src/api/http.rs`, and the high-level wrapper `sp_runtime::offchain::http::Request` in `substrate/primitives/runtime/src/offchain/http.rs`). [1](#0-0) [2](#0-1) 

This mechanism is structurally incompatible with the reported bug class:

- It only runs in the node's offchain worker context, which is explicitly non-deterministic and has no effect on consensus state unless the worker itself submits a signed/unsigned transaction back through normal extrinsic validation. [3](#0-2) 
- It is gated per-node by operator configuration (`enable_http_requests`, `is_validator`), so it is not automatically reachable by an arbitrary unprivileged network caller the way a Flask HTTP passthrough endpoint is. [4](#0-3) 
- Searching all pallets implementing `Hooks::offchain_worker` in the codebase (`im-online`, `election-provider-multi-phase`, `election-provider-multi-block`, `node-authorization`, `statement`, etc.) shows none of them construct an HTTP request URL from attacker-supplied extrinsic input — none of them use `sp_runtime::offchain::http::Request` at all; the only usages of `Request::get`/`http::Request` in the whole repo are in the primitive's own definition/tests and the reference documentation example. [5](#0-4) 

There is no on-chain state-transition code path (extrinsic dispatch, contract call, or XCM execution) in this codebase that takes an attacker-controlled string and uses it as a destination for an outbound network request — doing so would break determinism of the runtime, which is a core design invariant explicitly called out in the offchain-worker documentation. Since the reported vulnerability's root cause (unvalidated attacker-controlled URL passed to an HTTP client sink, reachable via a normal user request) has no demonstrable counterpart in FRAME/XCM/Cumulus production code, no valid analog exists.
