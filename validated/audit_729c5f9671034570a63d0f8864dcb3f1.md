### Title
Deposit function mints zero shares for a depositor's assets, silently transferring their principal to existing shareholders - ([File: mainnet/contracts/vault/v0-vault-usdc.clar], and identically in v0-vault-sbtc.clar, v0-vault-ststx.clar, v0-vault-ststxbtc.clar, v0-vault-stx.clar, v0-vault-usdh.clar)

### Summary
Every Zest vault contract's `deposit()` computes the shares to mint via `convert-to-shares-preview` and only validates that `amount > 0` and `inkind >= min-out`; it never checks that the computed `inkind` (shares) is greater than zero before minting and crediting the deposit. `redeem()` in the same contracts explicitly guards against this by asserting `(> inkind u0)` (`ERR-OUTPUT-ZERO`), but the symmetric check is missing on the deposit path.

### Finding Description
`convert-to-shares-preview` rounds down when total supply (`ts`) is non-zero: [1](#0-0) 

`deposit()` uses this value as `inkind` and mints it directly, with no `inkind > 0` assertion, unlike `redeem()`: [2](#0-1) [3](#0-2) 

The vault's share price (`assets`/`total-supply`) rises over time purely from interest accrual, since only the protocol's fee-reserve cut of interest is minted back as `treasury-lp` shares in `accrue()`; the remainder of accrued interest increases `total-assets-preview` without a matching increase in `total-supply`. Combined with ordinary redemptions shrinking `total-supply` toward a small residual, the ratio `ta/ts` can grow arbitrarily large relative to typical deposit sizes. When a victim then calls `deposit(amount, min-out, recipient)` with `min-out = 0` (the common default) and `amount * ts < ta`, `mul-div-down` rounds `inkind` down to `0`. Because there is no `inkind > 0` guard, `ft-mint? zft 0 recipient` still succeeds, `receive-underlying` still pulls the victim's tokens, and `(var-set assets (+ current-assets amount))` still credits the full deposited amount into the shared asset pool — silently transferring the victim's principal in value to every existing holder of `zft` (the shared state consumed at redemption via `convert-to-assets-preview`), while the victim receives nothing.

This is the same root cause as the referenced report (missing zero-shares revert on the deposit path, asymmetric with the withdraw/redeem path's existing check), applied to Zest's vault deposit/redeem model.

### Impact Explanation
A depositor's full principal can be captured into the vault's accounting with zero shares minted in return, and that value is not recoverable by the depositor — it becomes value backing existing shareholders' positions. This is direct theft of another principal's funds at rest, mediated entirely through the shared `assets`/`total-supply` pricing state, and falls under the Critical/High impact class of direct theft of user funds.

### Likelihood Explanation
The condition (`ts` small relative to `ta`) is not exotic: it is the natural end-state of any long-lived interest-accruing vault after most depositors redeem, since interest compounding continuously grows `ta` relative to a shrinking `ts`. No privileged access or DAO action is required — only ordinary `deposit()`/`redeem()` calls by unprivileged users, plus a victim depositing an amount small enough relative to the prevailing share price. A default `min-out` of `0` (typical for a first-time or naive integrator/UI call) does not protect against this, since `0 >= 0` passes the slippage check.

### Recommendation
Add an explicit zero-shares guard to `deposit()` in every vault contract, mirroring the existing `redeem()` protection, e.g. `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)` before minting, so that a deposit which would produce zero shares reverts instead of silently absorbing the caller's principal into the shared pool.

### Proof of Concept
1. Vault operates normally for a period; `total-borrowed`/interest accrual steadily grows `total-assets-preview` (`ta`) relative to `total-supply` (`ts`) each time `accrue()` runs, since only the fee-reserve share of interest is minted back as `treasury-lp`.
2. Existing holders redeem over time via `redeem()` at `mainnet/contracts/vault/v0-vault-usdc.clar:795`, shrinking `ts` down to a small residual (e.g. a handful of zft units) while `ta` remains large due to un-mint-backed accrued interest.
3. A victim calls `deposit(amount, min-out=0, recipient=victim)` at `mainnet/contracts/vault/v0-vault-usdc.clar:761` with an `amount` such that `amount * ts < ta` in `convert-to-shares-preview` (`mainnet/contracts/vault/v0-vault-usdc.clar:306-313`), yielding `inkind = 0`.
4. The `deposit()` function's checks all pass: `amount > 0` ✓, `0 >= min-out(0)` ✓, cap-supply check ✓ — there is no assertion that `inkind > 0`.
5. `receive-underlying` transfers the victim's tokens into the vault, `ft-mint? zft 0 recipient` succeeds (mint of 0 does not fail), and `(var-set assets (+ current-assets amount))` credits the victim's full deposit amount into `assets`.
6. The victim now holds `0` zft shares while their deposited principal permanently backs the value of the existing (attacker-held) `zft` supply, redeemable only by those pre-existing holders via `convert-to-assets-preview` at redemption.

```text
(define-private (convert-to-shares-preview (amount uint))
  (let ((ta (total-assets-preview))
        (ts (total-supply-preview)))
    (if (is-eq ts u0)
        amount
        (if (is-eq ta u0)
            u0
            (mul-div-down amount ts ta)))))
```

```text
(define-public (redeem (amount uint) (min-out uint) (recipient principal))
  (let (
    (states (var-get pause-states))
    (u (try! (accrue)))
    (account contract-caller)
    (current-assets (var-get assets))
    (balance (get-balance-internal account))
    (balance-check (asserts! (>= balance amount) ERR-INSUFFICIENT-BALANCE))
    (available-assets (get-available-assets))
    (inkind (convert-to-assets-preview amount)))

  (asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)
  (asserts! (not (get redeem states)) ERR-PAUSED)
  (asserts! (> amount u0) ERR-AMOUNT-ZERO)
  (asserts! (> inkind u0) ERR-OUTPUT-ZERO)
  (asserts! (>= inkind min-out) ERR-SLIPPAGE)
  (asserts! (>= available-assets inkind) ERR-INSUFFICIENT-LIQUIDITY)
```
