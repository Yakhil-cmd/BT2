### Title
Webhook signature verification is bound to the payload's `repository.owner.login` (or `organization.login`) while stack routing is bound to `repository.full_name` — organization authenticated ≠ repository written - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App/webhook secret to verify a request against using `repository_owner`, a value taken straight from the attacker-controlled JSON body (`repository.owner.login`, falling back to `organization.login`). Once the signature check passes, the actual work performed by `Shipit::Webhooks::Handlers::Handler` (and its `PushHandler` subclass) is routed using an entirely different field from the same body: `repository.full_name`. Nothing enforces that the organization whose secret validated the signature is the same organization that owns the repository being acted on.

### Finding Description
`verify_signature` resolves the signing key like this: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` resolves per-organization config (`app_id`, `installation_id`, `webhook_secret`) in multi-org deployments: [3](#0-2) 

Signature verification itself is a no-op whenever that organization's `webhook_secret` is blank — a state explicitly documented as supported/optional: [4](#0-3) [5](#0-4) 

Once verification passes (trivially, because no secret was configured for the organization named in `repository.owner.login`), the request body is dispatched to handlers that never re-check the owner used for authentication — they resolve the target `Stack`/`Repository` purely from `repository.full_name`: [6](#0-5) [7](#0-6) 

The binding that should hold is: `organization authenticated (repository.owner.login / organization.login, used to pick the webhook_secret) == owner(repository.full_name) (used to select which Stack is acted upon)`. No code path enforces this equality; `repository_owner` and `repository.full_name` are independent, attacker-supplied fields inside the same unauthenticated JSON body accepted before signature verification succeeds.

### Impact Explanation
In any Shipit deployment using the documented multi-organization GitHub App configuration (`docs/setup.md`, "Using Multiple Github Applications") where at least one configured organization has no `webhook_secret` (explicitly listed as optional at app-creation time), an unauthenticated attacker can:

1. Send a forged `push` webhook to `/webhooks` with `repository.owner.login` (or `organization.login`) set to the organization that has no `webhook_secret configured — passing `verify_webhook_signature` unconditionally.
2. Set `repository.full_name` in the same payload to any other tracked repository/stack in the Shipit instance, including one belonging to a different, properly-secured organization.
3. `PushHandler` resolves the target stack purely from `repository.full_name`, and calls `stack.sync_github(expected_head_sha: params.after)`, enqueuing `GithubSyncJob` against that unrelated stack.

This lets an attacker who never obtained any organization's webhook secret trigger sync/deploy-pipeline machinery (`GithubSyncJob` → `CacheDeploySpecJob`, and potentially continuous-deployment merge/deploy triggers) for a stack whose owning organization's credentials were never actually validated for this request — an authentication/authorization boundary that the multi-org design implies exists but the code does not enforce.

### Likelihood Explanation
Requires only that the operator has configured at least one GitHub organization without a webhook secret (a state the project's own setup documentation calls "optional"), and knowledge of the target repository's `full_name`, which is discoverable (it's just `owner/repo` as tracked by any public Shipit stack page). No credential, GitHub App key, or session is required.

### Recommendation
In `WebhooksController#verify_signature`, require the organization used to select the webhook secret to match the owner segment of `repository.full_name` (or `organization.login` when present) before dispatching to handlers; reject the request (422) on mismatch even when the resolved secret is blank/unconfigured.

### Proof of Concept
Given a multi-org Shipit config where `orgA` has no `webhook_secret` and `orgB/tracked-repo` is a real tracked stack secured by `orgB`'s secret:

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored because orgA has no secret

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-or-real-sha>",
  "repository": { "owner": { "login": "orgA" }, "full_name": "orgB/tracked-repo" }
}
```

`repository_owner` resolves to `orgA`, whose blank `webhook_secret` makes `verify_webhook_signature` return `true` unconditionally (`app/controllers/shipit/webhooks_controller.rb:25-30`, `lib/shipit/github_app.rb:76-83`). The request is then handled by `PushHandler`, which loads the stack via `Repository.from_github_repo_name('orgB/tracked-repo')` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) and enqueues a sync for `orgB`'s stack, even though only `orgA`'s (non-)secret was ever checked.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
