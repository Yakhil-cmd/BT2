## Title
Webhook signature verification is keyed off attacker-controlled `repository.owner.login`, decoupled from the `repository.full_name` handlers actually mutate - allowing cross-tenant stack/commit mutation - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/handler.rb, lib/shipit/github_app.rb)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret using `repository_owner`, derived from `payload.dig('repository','owner','login')` or `payload.dig('organization','login')`, both fully attacker-supplied JSON fields. `Handler#repository_name`/`#stacks` independently read `payload.dig('repository','full_name')` with no cross-check against the org used for signature verification. `GitHubApp#verify_webhook_signature` additionally returns `true` unconditionally when `webhook_secret` is blank. Together, these let an attacker whose org has no `webhook_secret` configured send a single unsigned POST to `/webhooks` naming any real `repository.full_name` and have the corresponding handler mutate that repository's stacks/commits.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`verified_organization (payload.dig('repository','owner','login') used by WebhooksController#repository_owner)` == `owning_organization_of(repository_name)` (payload.dig('repository','full_name') used by `Handler#repository_name`/`#stacks`), for every handler dispatched from `Shipit::Webhooks.for_event`.

Trace:
- `WebhooksController#create` parses the raw JSON body and, before this, `before_action :verify_signature` runs [1](#0-0) , computing `github_app = Shipit.github(organization: repository_owner)` and calling `github_app.verify_webhook_signature(...)` [2](#0-1) .
- `repository_owner` reads directly from the untrusted, unverified JSON payload params: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [3](#0-2) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally if `webhook_secret` is blank/not configured for that organization [4](#0-3) .
- On success, `create` dispatches `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`, passing the raw parsed JSON, not a value scoped to the verified organization [5](#0-4) .
- Each `Handler` resolves the repository to mutate purely from `payload.dig('repository', 'full_name')` via `Repository.from_github_repo_name`, with no reference to the organization the signature check used [6](#0-5) .
- `Repository.from_github_repo_name` simply looks up any `Repository` row matching the owner/name split out of the string, regardless of who verified the request [7](#0-6) .
- `PushHandler#process` then runs `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }` [8](#0-7) ; `StatusHandler#process` updates `Commit` status for any commit matching the attacker-chosen `sha` regardless of repository [9](#0-8) ; `CheckSuiteHandler#process` schedules check-run refresh against the named repo's stacks [10](#0-9) .

Root cause: the two payload fields (`repository.owner.login` used for auth, `repository.full_name` used for the DB mutation) are never cross-validated, and for orgs configured without a `webhook_secret`, `verify_webhook_signature` grants an unconditional pass to any payload shape. An attacker who controls (or who knows an existing) `Shipit.github_apps` entry with a blank `webhook_secret` can set `repository.owner.login` to that org's name while setting `repository.full_name` to any other tenant's real `owner/repo` string, and the handler will still mutate that other tenant's stacks/commits. This bypasses `drop_unhandled_event` (only checks event type) and `ExplicitParameters` schema validation (only validates shape of fields like `ref`/`after`/`sha`, not cross-field organization ownership), and there is no other guard in the codebase that binds the verified organization to the acted-upon repository.

### Impact Explanation
A successful forged request causes DB mutation of a repository/stack/commit belonging to a different tenant than the one whose (possibly nonexistent) signature was checked - exactly the "payload for one repository mutating another's stack/commit" Critical category. Concretely: `PushHandler` can trigger `stack.sync_github` for arbitrary victim stacks, `StatusHandler` can forge commit statuses (`create_status_from_github!`) for any commit by sha across all repositories (this handler doesn't even scope by repository at all, only by `sha`), and `CheckSuiteHandler` can force check-run refresh scheduling on arbitrary stacks. This is repeatable against any repository configured in Shipit as long as at least one org exists (attacker's own, or any misconfigured org) with a blank `webhook_secret`. Blast radius spans all tenants/repos hosted on the same Shipit instance.

### Likelihood Explanation
Preconditions per the question: at least one entry in `Shipit.github_apps` lacking `webhook_secret` (a plausible/common misconfiguration, e.g., during onboarding or for internal/test orgs), or simply two distinct configured orgs where an attacker owns one and targets a repo under the other. Attacker cost is minimal: a single unauthenticated HTTP POST to `/webhooks` with a crafted JSON body and correct `X-Github-Event` header; if the blank-secret path is used, no valid `X-Hub-Signature` is needed at all. This is fully repeatable and requires no privileged access, session, or GitHub secret - consistent with the "unprivileged internet attacker" threat model.

### Recommendation
Bind the verified organization to the mutated repository:
1. In `Handler#stacks`/`#repository_name`, verify that `Repository.from_github_repo_name(repository_name).owner` equals the organization actually verified by `WebhooksController#verify_signature` (thread this value through, e.g., via a verified-organization context passed into `handler.call`), rejecting/no-op'ing on mismatch.
2. In `GitHubApp#verify_webhook_signature`, stop returning `true` when `webhook_secret` is blank; treat a missing secret as unverifiable and reject (fail closed) or refuse to boot with such a config.
3. Ensure `repository_owner` used for HMAC selection is derived from the same field ultimately used for the DB lookup (`repository.full_name`), not independently read.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_forged_org_test.rb (conceptual, not to be placed under test/ scope exclusions if actually added)
class WebhooksForgedOrgTest < ActionDispatch::IntegrationTest
  test "push webhook signed under org with blank webhook_secret mutates unrelated repository's stack" do
    # Precondition: Shipit.github_apps includes an org (e.g. 'attacker-org') with no webhook_secret configured
    victim_repo = shipit_repositories(:rails) # owner: 'shopify', name: 'rails' (real, configured victim org WITH a secret)
    victim_stack = shipit_stacks(:shipit) # belongs to victim_repo, branch 'main'

    payload = {
      ref: "refs/heads/#{victim_stack.branch}",
      after: 'deadbeef' * 5,
      repository: {
        full_name: victim_repo.github_repo_name,   # targets victim
        owner: { login: 'attacker-org' }            # selects attacker's org for signature check
      }
    }.to_json

    Stack.any_instance.expects(:sync_github).with(expected_head_sha: anything) # equality check #2: mutation DID happen

    post shipit.webhooks_url, params: payload,
      headers: { 'X-Github-Event' => 'push', 'X-Hub-Signature' => 'sha1=irrelevant', 'Content-Type' => 'application/json' }

    assert_response :ok
    # Binding check: verified_organization ('attacker-org') != owning_organization_of(victim_repo.full_name) ('shopify')
    # yet the mutation against victim_stack still executed -> binding is broken.
  end
end
```
This can be parameterized across `Shipit::Webhooks.for_event('push')`, `('status')`, `('check_suite')` as the question suggests, asserting in each case that the DB-visible side effect (stack sync, commit status creation, check-run refresh scheduling) occurs against the named repository despite the signature having been verified (or bypassed) under an unrelated organization.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
