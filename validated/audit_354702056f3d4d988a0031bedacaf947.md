### Title
Consensus-time AA-trigger/tps-fee validation can under-count primary triggers that are actually executed at stabilization - ([File: validation.js])

### Summary
`validateAATrigger()` in `validation.js` determines how many AA triggers a unit contains — and therefore how much `tps_fee` must be paid — by looking up which output addresses are registered AAs **as of `last_ball_mci`**. The code itself documents that this count can be wrong: "*There might be actually more triggers due to AAs defined between last_ball_mci and our unit, so our validation of tps fee might require a smaller fee than the fee actually charged when the trigger executes*". `validateTpsFee()` then only requires the sender to pay a `tps_fee` sized for that (possibly too-small) trigger count. When the unit later stabilizes, `handleAATriggers()` picks up AA triggers from the `aa_triggers` table joined against the *current* `aa_addresses` table with no `mci` restriction back to the original `last_ball_mci`, so an output address that became an AA only after the unit's `last_ball_mci` (but before/at stabilization) is executed as a full AA trigger anyway. This is the same "consensus/static-validation vs. execution" split described in the source report: a message is accepted as non-triggering (cheap) at consensus time, but is fully executed (expensive) later, without commensurate fee having been enforced.

### Finding Description
- `validateAATrigger` (`validation.js:986-1039`) counts `count_primary_aa_triggers` using:
```js
const rows = await conn.query("SELECT address FROM aa_addresses WHERE address IN (?) AND mci<=?", [arrOutputAddresses, objValidationState.last_ball_mci]);
``` [1](#0-0) 
This snapshot is fixed at the unit's `last_ball_mci`, and the function's own comment (line 1017) admits the resulting fee estimate can be too low. [2](#0-1) 

- `validateTpsFee` (`validation.js:1050-1097`) computes the minimum required `tps_fee` from `objValidationState.count_primary_aa_triggers` (derived above) via `storage.getCountUnitsPayingTpsFee`/`storage.getLocalTpsFee`, and only rejects the unit if the paid fee is below that (possibly understated) minimum. [3](#0-2) 

- At stabilization, actual AA execution is driven by `handleAATriggers()`, which selects rows from `aa_triggers` joined to the live `aa_addresses` table with no filter tying the match back to the trigger unit's original `last_ball_mci`:
```js
"SELECT aa_triggers.mci, aa_triggers.unit, address, definition \n\
FROM aa_triggers CROSS JOIN units USING(unit) CROSS JOIN aa_addresses USING(address) ..."
``` [4](#0-3) 
`handlePrimaryAATrigger` then fully executes the AA (`handleTrigger`), running the formula engine, updating state vars, and potentially cascading to secondary AAs — real computational and storage work — for a trigger whose fee was validated against a smaller trigger count. [5](#0-4) 

This mirrors the reported bug class exactly: a validity/fee check performed with one view of state at admission time (consensus) diverges from the heavier processing performed with a later, different view of state at execution time, letting the payer avoid paying for the resource they actually consume.

### Impact Explanation
An attacker can pay outputs to an address that is not yet an AA at the time their unit is composed/validated (so `validateAATrigger`/`validateTpsFee` treat it as a plain payment, requiring only the base `tps_fee`), then race to get another unit defining that address as an AA included and stabilized before or alongside the payment unit. When the network stabilizes, the payment unit is picked up by `handleAATriggers` and fully executed as a primary AA trigger — consuming AA execution CPU/DB resources, generating secondary triggers, response units, and state updates — while the sender only paid the tps_fee appropriate for a non-AA payment. Repeating this lets an attacker drive cheap-but-unbounded AA execution load onto every full node, a resource-exhaustion/DoS vector against the network's tps-fee anti-spam mechanism, without nodes disagreeing about validity (all nodes will still deterministically execute the same triggers), but with the network's fee-based resource-pricing guarantee being bypassed.

### Likelihood Explanation
Requires precise timing: the target address must become a registered AA between the payment unit's `last_ball_mci` and its stabilization MCI, and the attacker needs to have that AA registration reliably ordered. This is plausible for an attacker who controls or coordinates both the AA-defining unit and the payment/trigger unit (e.g., pre-registers a "cheap" address as an AA in the background and sends payments to it just after `last_ball` was fixed but before the AA-defining unit is included in `last_ball_mci`). This is achievable without any special network position, purely from unit composition, matching the "unprivileged unit poster" threat model, but the attack surface is narrower than a simple single-unit exploit because it depends on two related units and MCI progression.

### Recommendation
Make the trigger-count/tps-fee validation performed in `validateAATrigger`/`validateTpsFee` consistent with the actual criteria used by `handleAATriggers` at stabilization — either by re-validating/re-charging tps_fee based on the AA-address set effective at the unit's actual stabilization MCI (not just `last_ball_mci`), or by restricting `handleAATriggers`'s trigger-matching query to only treat an address as an AA trigger if it was already a registered AA at the triggering unit's `last_ball_mci` (i.e., add the same `mci<=last_ball_mci` condition used in `validateAATrigger` when joining `aa_addresses` in `aa_composer.js`), so consensus-time fee estimation and execution-time trigger recognition always agree.

### Proof of Concept
1. Attacker prepares unit `U1` that will define address `A` as an AA (`aa_addresses` row with `mci = M1`).
2. Concurrently, attacker composes unit `U2` with `last_ball_mci = M0 < M1`, sending a payment to address `A`. At `M0`, `A` is not yet in `aa_addresses`, so `validateAATrigger` finds `count_primary_aa_triggers = 0` for `U2`, and `validateTpsFee` only requires the minimal single-unit tps_fee — `U2` passes consensus validation cheaply.
3. Attacker arranges for `U1` (defining `A` as AA) to stabilize at or before the MCI at which `U2` stabilizes.
4. When `U2` stabilizes, `main_chain.js`'s `stabilizeMci`/`markMcIndexStable` records an `aa_triggers` row for `U2`→`A` (using current AA-address state, not `U2`'s original `last_ball_mci`), and `handleAATriggers()` (`aa_composer.js:59-89`) executes the full AA logic for `U2`, even though `U2` never paid a tps_fee sized for triggering an AA.
5. Repeat with many such `U2` units against newly-registered AA addresses to impose AA execution load on all full nodes while paying only base-payment tps fees.

Note: I was unable to fully trace the exact code path that inserts rows into the `aa_triggers` table during stabilization (likely in `main_chain.js`/`writer.js`) within the available search budget, so the precise MCI-consistency of that insertion (whether it also checks `last_ball_mci` of the triggering unit) could not be 100% confirmed from the retrieved snippets — this should be verified directly in the repository before treating the PoC as fully proven.

function handleAATriggers(onDone) {
	if (!onDone)
		return new Promise(resolve => handleAATriggers(resolve));
	mutex.lock(['aa_triggers'], function (unlock) {
		db.query(
			"SELECT aa_triggers.mci, aa_triggers.unit, address, definition \n\
			FROM aa_triggers \n\
			CROSS JOIN units USING(unit) \n\
			CROSS JOIN aa_addresses USING(address) \n\
			ORDER BY aa_triggers.mci, level, aa_triggers.unit, address",
			function (rows) {
				var arrPostedUnits = [];
				async.eachSeries(
					rows,
					function (row, cb) {
						console.log('handleAATriggers', row.unit, row.mci, row.address);
						var arrDefinition = JSON.parse(row.definition);
						handlePrimaryAATrigger(row.mci, row.unit, row.address, arrDefinition, arrPostedUnits, cb);
					},
					function () {
						arrPostedUnits.forEach(function (objUnit) {
							eventBus.emit('new_aa_unit', objUnit);
						});
						unlock();
						onDone();
					}
				);
			}
		);
	});
}

function handlePrimaryAATrigger(mci, unit, address, arrDefinition, arrPostedUnits, onDone) {
	db.takeConnectionFromPool(function (conn) {
		conn.query("BEGIN", function () {
			var batch = kvstore.batch();
			readMcUnit(conn, mci, function (objMcUnit) {
				readUnit(conn, unit, function (objUnit) {
					var arrResponses = [];
					var trigger = getTrigger(objUnit, address);
					trigger.initial_address = trigger.address;
					trigger.initial_unit = trigger.unit;
					handleTrigger(conn, batch, trigger, {}, {}, arrDefinition, address, mci, objMcUnit, false, arrResponses, function(){
						conn.query("DELETE FROM aa_triggers WHERE mci=? AND unit=? AND address=?", [mci, unit, address], async function(){
							await conn.query("UPDATE units SET count_aa_responses=IFNULL(count_aa_responses, 0)+? WHERE unit=?", [arrResponses.length, unit]);
							let objUnitProps = storage.assocStableUnits[unit];
							if (!objUnitProps)
								throw Error(`handlePrimaryAATrigger: unit ${unit} not found in cache`);
							if (!objUnitProps.count_aa_responses)
								objUnitProps.count_aa_responses = 0;
							objUnitProps.count_aa_responses += arrResponses.length;
							var batch_start_time = Date.now();
							batch.write({ sync: true }, function(err){
								console.log("AA batch write took "+(Date.now()-batch_start_time)+'ms');
								if (err)
									throw Error("AA composer: batch write failed: "+err);
								conn.query("COMMIT", function () {
									conn.release();
									if (arrResponses.length > 1) {
										// copy updatedStateVars to all responses
										if (arrResponses[0].updatedStateVars)
											for (var i = 1; i < arrResponses.length; i++)
												arrResponses[i].updatedStateVars = arrResponses[0].updatedStateVars;
										// merge all changes of balances if the same AA was called more than once
										let assocBalances = {};
										for (let { aa_address, balances } of arrResponses)
											assocBalances[aa_address] = balances; // overwrite if repeated
										for (let r of arrResponses) {
											r.balances = assocBalances[r.aa_address];
											r.allBalances = assocBalances;
										}
									}
									else
										arrResponses[0].allBalances = { [address]: arrResponses[0].balances };
									arrResponses.forEach(function (objAAResponse) {
										if (objAAResponse.objResponseUnit)
											arrPostedUnits.push(objAAResponse.objResponseUnit);
										eventBus.emit('aa_response', objAAResponse);
										eventBus.emit('aa_response_to_unit-'+objAAResponse.trigger_unit, objAAResponse);
										eventBus.emit('aa_response_to_address-'+objAAResponse.trigger_address, objAAResponse);
										eventBus.emit('aa_response_from_aa-'+objAAResponse.aa_address, objAAResponse);
									});
									onDone();
								});
							});
						});
					});
				});
			});
		});
	});
}
