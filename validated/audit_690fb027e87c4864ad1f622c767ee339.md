Based on my analysis of the code path, here is my assessment.

### Title
Forged `pull_request`/`assigned` webhook via `organization.login` fallback lets an unconfigured/no-secret org's verifier authorize a payload targeting an arbitrary repository's `PullRequest` - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`WebhooksController#repository_owner` selects the GitHub App/org used for signature verification via `params.dig('repository','owner','login') || params.dig('organization','login')`, while `AssignedHandler#repository` independently derives the target repository from `params.repository.full_name`. [1](#0-0) [2](#0-1)  These two fields are attacker-controlled independently, so an attacker can pick a lenient/unconfigured verifying org while pointing `repository.full_name` at any repo Shipit tracks.

### Finding Description
The broken binding, as equality: `organization_that_verifies_the_signature == organization_that_owns(params.repository.full_name)` should always hold, but nothing in the code enforces it.

- `verify_signature` computes `repository_owner` by first trying `repository.owner.login`, and only falling back to `organization.login` when `repository.owner` is absent. [3](#0-2)  It then calls `Shipit.github(organization: repository_owner)` and verifies via `GitHubApp#verify_webhook_signature`. [4](#0-3) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally if that specific org's `webhook_secret` is blank: `return true unless webhook_secret`. [5](#0-4) 
- `AssignedHandler` requires `params.repository.full_name` (not `params.repository.owner.login`) and uses it solely to look up the `Shipit::Repository`/`PullRequest` to mutate: `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. [6](#0-5) [7](#0-6) 

Exploit request: attacker POSTs `X-Github-Event: pull_request` with a body containing `repository: { full_name: "victim-org/victim-repo" }` (deliberately omitting `repository.owner`) and `organization: { login: "attacker-controlled-or-secretless-org" }`. `repository_owner` resolves to `"attacker-controlled-or-secretless-org"` because `dig('repository','owner','login')` is `nil`. If that org exists in Shipit's multi-org config with a blank `webhook_secret`, `verify_webhook_signature` returns `true` for any body/signature. The request passes `verify_signature`, and `AssignedHandler#process` then loads and mutates the `PullRequest` belonging to `victim-org/victim-repo` via `pull_request.update(github_pull_request: params.pull_request)`. [8](#0-7) 

None of the existing guards close this gap: `drop_unhandled_event` only checks the event name is registered; `check_if_ping` only handles `ping`; the `ExplicitParameters` schema on `AssignedHandler` only requires `repository.full_name` to be a `String` and does not require or cross-check `repository.owner.login` against the org used for signature verification. There is no place in the controller or handler that asserts the verifying org equals the org owning `repository.full_name`.

### Impact Explanation
An attacker who controls (or can name) any organization entry configured in Shipit's multi-org GitHub App config with no `webhook_secret` set can forge signature-valid webhooks that are routed to and mutate `PullRequest`/`Stack`/`Commit`/`Team` records belonging to a *different, secret-protected* organization/repository. This is cross-tenant state manipulation reachable repeatedly by any unauthenticated internet client, matching the "payload for one repository mutating another's stack/commit/task/team" Critical impact category.

### Likelihood Explanation
This requires:
1. A multi-org Shipit deployment (i.e., `Shipit.github_default_organization` non-nil, using the per-organization `github_app_config` schema rather than the single flat `secrets.github` schema — in the single-org schema, `Shipit.github` ignores the `organization:` argument entirely, per `lib/shipit.rb` lines 170-181, and the vulnerability does not apply).
2. At least one configured organization in that multi-org config with a blank/absent `webhook_secret`.

Given these two preconditions, the attack is trivial and free: it needs only an HTTP client, no credentials, no valid signature, and works against arbitrary tracked repositories. I could not confirm from the available test/config fixtures (`test/dummy/config/secrets_double_github_app.yml`, `secrets.test.json`) whether any org is actually configured without a `webhook_secret` in this repo's test/default setup — I was unable to read those files' contents before running out of iterations, so I cannot fully confirm this specific misconfiguration precondition is present by default, only that the code permits it if an operator configures it this way.

### Recommendation
Bind signature verification to the same repository ownership the handler will act on: derive `repository_owner` strictly from `params.dig('repository','owner','login')` when `repository` is present, and only accept the `organization.login` fallback for events that have no repository context (e.g., `membership`). Additionally, require that `AssignedHandler` (and other repo-scoped handlers) validate that the resolved `Shipit::Repository`'s owner matches the organization that verified the webhook signature, rejecting the event otherwise. Also treat a missing/blank `webhook_secret` for a configured organization as a hard misconfiguration (fail closed) rather than defaulting `verify_webhook_signature` to `true`.

### Proof of Concept
minitest plan (integration/controller test, no live GitHub):
1. Configure `Shipit.github_app_config` (via stubbing `Shipit.secrets.github`) with two orgs: `"victim-org"` (has `webhook_secret: "s3cr3t"`) and `"attacker-org"` (no `webhook_secret` key, i.e., blank).
2. Create fixtures: a `Shipit::Repository` with `owner: "victim-org"`, a `Shipit::Stack` and `Shipit::PullRequest` (number `N`) belonging to that repository, with an initial `assignees` set.
3. Build payload for `pull_request`/`assigned` event: `{"action" => "assigned", "number" => N, "pull_request" => {... assignees: [different user] ...}, "repository" => {"full_name" => "victim-org/victim-repo"}, "organization" => {"login" => "attacker-org"}, "sender" => {"login" => "attacker"}}` — deliberately omit `repository.owner`.
4. `assert_equal "attacker-org", @controller.send(:repository_owner)` type assertion (or directly compute `params.dig('repository','owner','login') || params.dig('organization','login')` on the JSON body) to establish the equality-violation before tracing: verifying org = `"attacker-org"`, owning org of mutated repo = `"victim-org"`.
5. POST to `/webhooks` with headers `X-Github-Event: pull_request` and an arbitrary/garbage `X-Hub-Signature`.
6. Assert response is `:ok` (200), not `422`, proving the forged/unsigned request was accepted.
7. Reload the `PullRequest` fixture and assert its `assignees` changed to match the forged payload, proving `AssignedHandler` mutated a record owned by `"victim-org"` using a signature verified only by `"attacker-org"`'s (secretless) verifier. [9](#0-8) [10](#0-9) [5](#0-4)

      github_app = Shipit.github(organization: repository_owner)

module Shipit
  module Webhooks
    module Handlers
      module PullRequest
        class AssignedHandler < Shipit::Webhooks::Handlers::Handler
          params do
            requires :action, String
            requires :number, Integer
            requires :pull_request do
              requires :id, Integer
              requires :number, Integer
              requires :url, String
              requires :title, String
              requires :state, String
              requires :additions, Integer
              requires :deletions, Integer
              requires :head do
                requires :sha, String
                requires :ref, String
              end
              requires :user do
                requires :login, String
              end
              requires :assignees, Array do
                requires :login, String
              end
              requires :labels, Array do
                requires :name, String
              end
            end
            requires :repository do
              requires :full_name, String
            end
            requires :sender do
              requires :login, String
            end
          end

          def process
            return unless respond_to_assignee_change?

            pull_request.update(github_pull_request: params.pull_request) if pull_request.present?
          end

          private

          def respond_to_assignee_change?
            %w[assigned unassigned].include?(params.action)
          end

          def pull_request
            @pull_request ||= Shipit::PullRequest
                              .joins(:stack, stack: :repository)
                              .find_by(
                                number: params.number,
                                stacks: {
                                  repositories:
                                    {
                                      id: repository.id
                                    }
                                }
                              )
          end

          def repository
            Shipit::Repository.from_github_repo_name(params.repository.full_name) || Shipit::NullRepository.new
          end
        end
      end
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
