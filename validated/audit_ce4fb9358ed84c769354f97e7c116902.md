### Title
Webhook signature is verified against `repository.owner.login` while record mutation is keyed on the independently attacker-controlled `repository.full_name`, letting a payload authenticated under a secret-less org write labels onto a victim PR - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate the HMAC using `repository_owner`, which is read from `payload.dig('repository','owner','login')`. `LabelCapturingHandler` (via `Handler#repository_name` / its own `repository`/`stacks` methods) instead resolves the target `Repository`/`Stack`/`PullRequest` using `payload.dig('repository','full_name')`. Both fields are attacker-supplied and are never cross-checked against each other, so a request whose bytes are "verified" for one configured org can still cause the handler to mutate a `PullRequest` belonging to a completely different org/repo.

### Finding Description
Broken binding: `organization whose webhook_secret validated request.raw_post` (derived from `params.dig('repository','owner','login')` in `WebhooksController#repository_owner`, `app/controllers/shipit/webhooks_controller.rb:59-62`) `==` `organization owning the PullRequest row mutated by params.pull_request.labels` (derived from `payload.dig('repository','full_name')` via `Handler#repository_name`, `app/models/shipit/webhooks/handlers/handler.rb:36-38`, and `LabelCapturingHandler#repository`/`#stack`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb:110-118`). Root cause: `GitHubApp#verify_webhook_signature` intentionally short-circuits with `return true unless webhook_secret` [5](#0-4)  — for any org configured in `secrets.github` without a `webhook_secret`, *any* payload passes verification with no HMAC required. `Shipit.github(organization:)`/`github_app_config` require the org name to already exist in the app's own configured `secrets.github` map, raising `GithubOrganizationUnknown` (→422) otherwise [6](#0-5) , so the attacker cannot invent an arbitrary org — they must target an org that is already configured on this Shipit instance without a secret (a documented/known misconfiguration case, not attacker-controlled infrastructure).

Exploit flow:
1. Attacker (no Shipit session, no secrets) crafts a raw JSON POST to `/webhooks` with `X-Github-Event: pull_request`, `repository.owner.login` set to some org known to be configured on the target Shipit instance with no `webhook_secret`, and `repository.full_name` set to `"victim-org/victim-repo"` (a real, secret-protected repo with an open, tracked PR and active stack), plus `action: "labeled"`, `pull_request.number` matching a real victim PR, and `pull_request.labels` containing attacker-chosen strings.
2. `verify_signature` computes `repository_owner` from `repository.owner.login` = the secret-less org, looks up that org's `GitHubApp`, and `verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is blank — no forgery of victim org's HMAC needed.
3. `LabelCapturingHandler.call(params)` runs; `capture_labels?`/`stack`/`repository` all resolve using `params.repository.full_name` = `"victim-org/victim-repo"`, completely ignoring which org's secret gated the request.
4. `capture_labels` calls `pull_request.update!(labels: params.pull_request.labels.map(&:name))` on the victim's real `Shipit::PullRequest` row [7](#0-6) .

Existing guards fail because: `drop_unhandled_event`/`ExplicitParameters` schema only validate types/presence, not cross-field consistency; `verify_signature` never re-derives or checks `repository.full_name`'s owner against `repository_owner`; and the handler layer trusts `repository.full_name` unconditionally once the controller sets `head` status (note: `verify_signature` does not `return` after `head(422)`, so `create` still executes handlers regardless — a related defect, but the org-mismatch is the core binding violation here).

### Impact Explanation
A single crafted, unauthenticated HTTP POST lets an attacker overwrite the `labels` column of any victim `PullRequest` known by number and repository full name, on any Shipit instance that has ≥2 GitHub orgs configured where at least one lacks a `webhook_secret`. Labels captured here are documented to gate provisioning/archival behavior for review stacks (`archive?`/`unarchive?` logic used by sibling handlers such as `LabeledHandler`/`UnlabeledHandler`), so forged label state can be used to trigger unintended stack archival/unarchival or downstream deploy/merge-gating decisions on a repository the attacker never authenticated against — a payload for one repository mutating another's PR/stack record, matching the Critical category "a payload for one repository mutating another's stack, commit, task or team."

### Likelihood Explanation
Exploitability is conditioned entirely on Shipit operator configuration: it requires a multi-org `secrets.github` setup where at least one configured org has no `webhook_secret`. If every configured org has a secret (recommended and typical for production), `verify_webhook_signature` never short-circuits and the attack is blocked for all orgs. The engine itself, however, provides no defense-in-depth against this scenario — it never checks that the org used for signature verification matches the org implied by the mutated resource — so any such misconfiguration is fully and repeatably exploitable, requiring only one HTTP POST per victim PR, with no rate limiting concerns relevant here.

### Recommendation
Bind the verified organization to the resource being mutated: derive `repository_owner` from the same `repository.full_name` field the handlers use (e.g., `full_name.split('/').first`) instead of the separate `repository.owner.login`, or explicitly assert `repository.full_name.split('/').first.casecmp?(repository_owner)` before dispatching to handlers, rejecting mismatches with 422. Additionally, ensure `verify_signature` halts the filter chain (`return` after `head(422)`) so `create` cannot run when verification fails.

### Proof of Concept
minitest under `test/controllers/webhooks_controller_test.rb` (or a dedicated handler test):
1. Fixture setup: configure `Rails.application.credentials.github` (via stub) with two orgs: `"secretless-org"` (no `webhook_secret`) and `"victim-org"` (has `webhook_secret`). Create `shipit_repository(:victim_repo, full_name: "victim-org/victim-repo")` with a tracked `Stack` and a `PullRequest` fixture with `labels: ["safe-to-deploy"]`.
2. Build payload: `{"action" => "labeled", "number" => victim_pr.number, "pull_request" => {..., "labels" => [{"name" => "attacker-injected-label"}]}, "repository" => {"full_name" => "victim-org/victim-repo", "owner" => {"login" => "secretless-org"}}, "sender" => {"login" => "attacker"}}`.
3. `request.headers['X-Github-Event'] = 'pull_request'`; send `post :create, body: payload.to_json, as: :json` with **no** `X-Hub-Signature` header.
4. Assert: `assert_response :ok` (signature check passed via secretless org) and `assert_equal ["attacker-injected-label"], victim_pr.reload.labels` — proving `organization verifying bytes ("secretless-org") != organization owning the mutated PullRequest ("victim-org")` while the write still succeeded.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
