## Tracing the Attack Path

**Step 1: `startgRPC` registers all public APIs without module filtering** [1](#0-0) 

`startgRPC` iterates all APIs and registers every one where `api.Public == true`. There is no namespace/module whitelist. Compare this to `startHTTP`, which passes `n.config.HTTPModules` to `rpc.StartHTTPEndpoint` to filter which namespaces are exposed. [2](#0-1) 

**Step 2: `headerGovModule.APIs()` registers `Vote` with `Public: true`** [3](#0-2) 

The `governance` namespace, including the `Vote` method, is marked `Public: true` and therefore gets registered into the gRPC handler unconditionally.

**Step 3: The gRPC server is a general JSON-RPC proxy with no authentication**

The proto defines a generic `Call(RPCRequest)` where `RPCRequest` carries `service`, `method`, and `params`. The server dispatches directly to `kns.handler.ServeSingleRequest`. [4](#0-3) [5](#0-4) 

`grpc.NewServer()` is called with no credentials, no interceptors, and no TLS. Any remote TCP client can call `governance_vote`.

**Step 4: The `Vote` function's auth check** [6](#0-5) 

The voter is hardcoded to `api.h.nodeAddress` — the node's own address. The caller's identity is never checked. The only guard is:

```go
if gMode == "single" && voter != gp.GoverningNode {
    return "", ErrVotePermissionDenied
}
```

This means:
- **Single mode, node is NOT the governing node**: `ErrVotePermissionDenied` is returned. The guard holds.
- **Single mode, node IS the governing node**: The check passes. `PushMyVotes(vote)` is called. The attacker has queued a governance vote as the governing node.
- **Ballot/none mode**: The `gMode == "single"` branch is never taken. Any remote caller can queue a vote as the node's address.

## Verdict

The claim is **partially correct** but overstated in one dimension. The attacker cannot inject a vote *from their own address* — the vote is always cast as the node's address. However, the real vulnerability is that a remote unauthenticated gRPC caller can **trigger the node to cast a governance vote it never intended to cast**, because:

1. The gRPC endpoint has no authentication.
2. The gRPC endpoint has no module whitelist (unlike HTTP/WS), so `governance_vote` is exposed even if the operator never added `governance` to `HTTPModules`.
3. If the target node is the governing node (single mode) or any validator (ballot mode), the attacker can queue arbitrary governance votes — including changing `GoverningNode`, `MintingAmount`, or `Ratio` — which will be included in the next block the node proposes.

This satisfies the required impact gate: **governance privilege escalation that changes protected chain state**.

### Title
Unauthenticated Remote gRPC Caller Can Queue Governance Votes as the Node's Address — (`node/node.go`, `networks/grpc/gServer.go`, `kaiax/gov/headergov/impl/api.go`)

### Summary
`startgRPC` registers all `Public: true` APIs — including `governance_vote` — into an unauthenticated gRPC server with no module whitelist. A remote attacker who can reach the gRPC port can call `governance_vote` and queue governance parameter changes (e.g., `GoverningNode`, `MintingAmount`) that will be committed to the chain when the node next proposes a block.

### Finding Description
`startgRPC` in `node/node.go` registers every API with `api.Public == true` without any namespace filtering. The `headerGovModule.APIs()` returns the `governance` namespace with `Public: true`, so `governance_vote` (the `Vote` method on `headerGovAPI`) is registered in the gRPC handler. The gRPC server is started with `grpc.NewServer()` — no TLS, no auth interceptors. The `Vote` function uses `api.h.nodeAddress` as the voter and never authenticates the caller. The only guard is a governance-mode check against the node's own address, which passes if the node is the governing node or if the mode is not `single`.

### Impact Explanation
An attacker who can reach the gRPC port of the governing node can call `governance_vote` with parameters such as `governance.governingnode` (set to attacker's address) or `reward.mintingamount`. The vote is queued via `PushMyVotes` and will be embedded in the next block header the node proposes, causing a permanent on-chain governance parameter change. This constitutes unauthorized governance privilege escalation affecting protected chain state.

### Likelihood Explanation
The gRPC endpoint is opt-in but has no documented security warning about exposing governance APIs. Operators who enable gRPC for performance reasons (e.g., service-chain relayers) may not realize `governance_vote` is exposed. The attack requires only TCP access to the gRPC port and knowledge of the proto schema (which is in the public repository and has gRPC reflection enabled). [7](#0-6) 

### Recommendation
1. Add a module whitelist to `startgRPC` analogous to the `modules` parameter in `startHTTP`.
2. Alternatively, mark governance write APIs (`Vote`) as `Public: false` so they are only accessible via IPC.
3. Add authentication (mTLS or a token interceptor) to the gRPC server if it must remain open.

### Proof of Concept
1. Start a Kaia node with gRPC enabled (`--grpc` / `--grpcport`) where the node is the governing node in single-mode governance.
2. Connect a gRPC client using the `KlaytnNode` proto.
3. Call `Call` with `params = {"jsonrpc":"2.0","method":"governance_vote","params":["governance.governingnode","0xAttackerAddress"],"id":1}`.
4. Observe the response is a success string (not `ErrVotePermissionDenied`).
5. Wait for the node to propose a block; observe the governance vote embedded in the block header and the subsequent parameter change taking effect at the next epoch boundary.

func (n *Node) startgRPC(apis []rpc.API) error {
	if n.grpcEndpoint == "" {
		return nil
	}

	handler := rpc.NewServer()
	for _, api := range apis {
		if api.Public {
			if err := handler.RegisterName(api.Namespace, api.Service); err != nil {
				return err
			}
			n.logger.Debug("gRPC registered", "namespace", api.Namespace)
		}
	}

	listener := &grpc.Listener{Addr: n.grpcEndpoint}
	n.grpcHandler = handler
	n.grpcListener = listener
	listener.SetRPCServer(handler)

	go listener.Start()
	n.logger.Info("gRPC endpoint opened", "url", n.grpcEndpoint)
	return nil
}

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}
