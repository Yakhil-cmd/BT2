### Title
Webhook signature verified against one organization while `MembershipHandler` mutates a different organization's `Team`/`Membership` due to `params` (Rails auto-parsed body) vs `JSON.parse(request.raw_post)` (handler input) diverging under attacker-controlled `Content-Type` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the signing organization via `repository_owner`, which reads Rails' auto-parsed `params`, while `#create` re-parses the raw body unconditionally with `JSON.parse(request.raw_post)` and hands that hash to `Shipit::Webhooks.for_event(event)` handlers (e.g. `MembershipHandler`). The literal "duplicate JSON key" premise in the question does not hold because both paths ultimately rely on the same underlying `json` gem parser (last-key-wins in both), so `params.dig('organization','login')` and `JSON.parse(request.raw_post)['organization']['login']` will match when the request `Content-Type` is `application/json`. However, a real divergence exists: if the attacker sends a `Content-Type` that Rails does not register as a body parser (e.g. `text/plain` or a missing header), Rails never merges the JSON body into `params` at all, so `repository_owner` falls back to values from the query string, while `#create`'s explicit `JSON.parse(request.raw_post)` still parses the full body regardless of `Content-Type`.

### Finding Description
The intended binding is: `organization used to select webhook_secret in Shipit.github(organization: repository_owner)` == `organization whose fields MembershipHandler reads from the body passed to handler.call`. This binding is broken as follows:

- `repository_owner` (app/controllers/shipit/webhooks_controller.rb:59-62) computes `params.dig('repository','owner','login') || params.dig('organization','login')` using ActionController's `params`, which is populated by Rails' body-parsing middleware only when `Content-Type` matches a registered parser (`application/json`).
- `#create` (app/controllers/shipit/webhooks_controller.rb:10-15) independently calls `JSON.parse(request.raw_post)`, which always parses the raw bytes as JSON irrespective of `Content-Type`, and passes that hash straight to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`.
- `MembershipHandler#process` (app/models/shipit/webhooks/handlers/membership_handler.rb) reads `params.organization.login`, `params.team.id/name/slug`, `params.member.login` directly from that re-parsed hash, with no re-check against the organization used for signature verification.

Exploit: an attacker who legitimately owns/administers a Shipit-onboarded organization "AttackerOrg" (and thus knows or can trigger delivery signed with `AttackerOrg`'s `webhook_secret`, per `Shipit.github(organization:)` in lib/shipit/github_app.rb:76-83) sends:
```
POST /webhooks?organization[login]=AttackerOrg
Content-Type: text/plain
X-Github-Event: membership
X-Hub-Signature: sha1=<HMAC over raw body using AttackerOrg's webhook_secret>
Body: {"action":"added","organization":{"login":"VictimOrg"},"team":{"id":<victim_team_github_id>,"name":"...","slug":"...","url":"..."},"member":{"login":"attacker_github_login"}}
```
Because `Content-Type` is not `application/json`, Rails does not decode the body into `params`; `params` only reflects the query string, so `repository_owner` returns `"AttackerOrg"`. `verify_signature` therefore verifies the raw body's HMAC against `AttackerOrg`'s `webhook_secret` — which the attacker computed correctly — and passes. `#create` then calls `JSON.parse(request.raw_post)` on the same raw body, obtaining `organization.login == "VictimOrg"`, and dispatches it to `MembershipHandler`, which creates/updates a `Team` scoped to `VictimOrg` and adds the attacker as a member (`Team#add_member`).

None of the existing guards catch this: `verify_signature` only checks the HMAC against whichever org `repository_owner` names, `drop_unhandled_event` only checks event presence, and `ExplicitParameters` in `MembershipHandler` validates field *shape*, not provenance/org consistency with the verified signature.

### Impact Explanation
The attacker forges membership/team-management data for an arbitrary victim organization while only proving control of their own organization's webhook secret. This lets an attacker's GitHub account be inserted into a `Team` associated with `VictimOrg`, which can escalate into `Shipit.github_teams` authorization checks used elsewhere (`User#authorized?`), and it constitutes "a payload for one repository/organization mutating another's team" — explicitly listed as Critical. It is repeatable against any organization/team whose numeric `team.id` (GitHub team id) the attacker can guess or observe, and is not limited to a single victim.

### Likelihood Explanation
Requires: (1) attacker controls at least one organization onboarded into Shipit's multi-tenant `github_apps`/webhook_secret configuration (a normal, unprivileged customer capability, not a Shipit operator role), (2) knowledge of a target `team.id` for the victim org (GitHub team IDs are often discoverable via public GitHub API/UI), (3) ability to set an arbitrary `Content-Type` header and query string on the POST to `/webhooks`, which is trivial for any internet client. No GitHub-side webhook delivery is needed — the attacker sends the HTTP request directly. This is low-cost and fully repeatable.

### Recommendation
Compute `repository_owner` from the exact same parsed hash that is passed to handlers (i.e., parse `request.raw_post` once via `JSON.parse` unconditionally and reuse that single hash for both signature-org selection and handler dispatch), rather than relying on Rails' `Content-Type`-dependent `params`. Additionally, verify that the `organization`/`repository` fields actually used by each handler match the organization used for signature verification before processing.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_divergence_test.rb
require 'test_helper'

module Shipit
  class WebhooksControllerDivergenceTest < ActionController::TestCase
    tests WebhooksController

    test "signature org (params) diverges from body org (JSON.parse(raw_post)) used by handler" do
      victim_team = shipit_teams(:shopify_developers) # existing team tied to 'shopify' org
      body = {
        action: 'added',
        organization: { login: 'shopify' }, # victim org read by MembershipHandler
        team: { id: victim_team.github_id, name: victim_team.name, slug: 'developers', url: 'http://example.com' },
        member: { login: 'attacker' }
      }.to_json

      @request.headers['X-Github-Event'] = 'membership'
      @request.headers['Content-Type'] = 'text/plain' # prevents Rails JSON param parsing
      # query string supplies a DIFFERENT org for signature verification path
      signing_secret = Shipit.github(organization: 'attacker-org').send(:webhook_secret)
      sig = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', signing_secret, body)
      @request.headers['X-Hub-Signature'] = sig

      post :create, params: { organization: { login: 'attacker-org' } }, body: body

      # Equality check demonstrating the broken binding:
      assert_equal 'attacker-org', @controller.send(:repository_owner) rescue nil
      parsed_body_org = JSON.parse(body).dig('organization', 'login')
      assert_equal 'shopify', parsed_body_org
      refute_equal @controller.send(:repository_owner), parsed_body_org

      assert_response :ok
      assert victim_team.reload.members.exists?(login: 'attacker')
    end
  end
end
```
