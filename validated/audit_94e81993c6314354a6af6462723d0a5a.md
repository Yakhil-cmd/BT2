**Reasoning:** The claimed attack path relies on `validate_kzg_g1` in `src/common/bytes.c` accepting a 48-byte string with the infinity flag set but a nonzero x-coordinate. Tracing the actual code: [1](#0-0) 

`validate_kzg_g1` calls `blst_p1_uncompress` first, and only proceeds to accept the point-at-infinity short-circuit (`blst_p1_is_inf`) if uncompression succeeded. The BLS12-381 compressed serialization format (as implemented by blst) mandates that when the infinity bit is set, all remaining bits of the 48-byte encoding — including the x-coordinate bits — must be zero. `blst_p1_uncompress` enforces this encoding rule internally and returns `BLST_BAD_ENCODING` (not `BLST_SUCCESS`) for any input where the infinity flag is set but the x-coordinate is nonzero. Since `validate_kzg_g1` checks `blst_p1_uncompress(...) != BLST_SUCCESS` and returns `C_KZG_BADARGS` immediately on failure, a "48-byte string with the infinity flag set but a nonzero x coordinate" never reaches the `blst_p1_from_affine`/`blst_p1_is_inf` acceptance branch at all — it is rejected at the deserialization step, before the point-at-infinity short-circuit is even reached.

This means the two sides of the invariant never diverge: `bytes_to_kzg_commitment`/`bytes_to_kzg_proof` (both thin wrappers around `validate_kzg_g1`) return `C_KZG_BADARGS` for such malformed bytes, so `verify_kzg_proof` in `src/eip4844/eip4844.c` never proceeds to the pairing check with attacker-controlled forged data — `*ok` is never set to `true` for this input; the call fails outright with an error return code, which the JNI/Java binding (`CKZG4844JNI.verifyKzgProof`) surfaces as an exception/negative result rather than a `true` verdict.

This is exactly the case the audit rules flag as out-of-scope: "blst's own subgroup and curve checks already prevent the divergence," and the guard here is blst's mandatory encoding validation (not a defect in blst, but its correct, spec-compliant behavior), which this repo relies on and correctly checks the return value of.

static C_KZG_RET validate_kzg_g1(g1_t *out, const Bytes48 *b) {
    blst_p1_affine p1_affine;

    /* Convert the bytes to a p1 point */
    /* The uncompress routine checks that the point is on the curve */
    if (blst_p1_uncompress(&p1_affine, b->bytes) != BLST_SUCCESS) return C_KZG_BADARGS;
    blst_p1_from_affine(out, &p1_affine);

    /* The point at infinity is accepted! */
    if (blst_p1_is_inf(out)) return C_KZG_OK;
    /* The point must be on the right subgroup */
    if (!blst_p1_in_g1(out)) return C_KZG_BADARGS;

    return C_KZG_OK;
}
