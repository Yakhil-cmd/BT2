### Title
Tokens sent directly to the controller are permanently locked because no rescue or arbitrary withdrawal path exists - (File: contracts/controller/src/lib.rs)

### Summary
The controller is designed to hold token balances transiently during router swaps and strategy execution, but it has no generalized `rescue_token` or sweep function. [1](#0-0)   
Any tokens transferred directly to the controller remain outside position accounting and are deliberately excluded from delta-based refunds, so an unprivileged sender cannot recover them. [2](#0-1) 

### Finding Description
Stellar token transfers can target the controller’s contract address independently of any lending operation. [3](#0-2)   
The controller normally receives tokens only as temporary custody: `swap_tokens` snapshots its input and output balances, authorizes the router for an exact amount, executes the swap, and refunds only unused input from the operation. [4](#0-3)   
`refund_controller_balance_delta` snapshots the controller balance and refunds only the positive increase since that snapshot, explicitly preserving any pre-existing controller balance. [2](#0-1)   
The public `withdraw` entrypoint is not a token rescue path: it requires an `account_id`, validates the caller against the account, and resolves withdrawals through recorded pool supply positions. [5](#0-4) [6](#0-5)   
Those withdrawals load an existing supply position and send the pool a `PoolWithdrawEntry`; a direct token balance on the controller creates no corresponding position or pool shares. [7](#0-6)   
The exposed interface contains account, liquidation, strategy, revenue, and administrative operations, but no callable token sweep to an arbitrary recipient. [8](#0-7) 

### Impact Explanation
A user who transfers a supported or arbitrary token directly to the controller permanently loses access to that amount. [3](#0-2)   
The balance cannot be claimed through `withdraw` because it is not represented by account shares, cannot be obtained through measured refunds because pre-existing balances are preserved, and cannot be swept through any public rescue entrypoint. [7](#0-6) [2](#0-1) 

### Likelihood Explanation
This requires a mistaken direct token transfer or an external strategy/callback sending assets to the controller outside the explicit measured-receipt and refund flow. [9](#0-8)   
The condition is externally reachable by an unprivileged token holder and produces permanent loss, but it depends on user or integration error rather than ordinary lending behavior. [2](#0-1) 

### Recommendation
Add an owner- or governance-authorized `rescue_token(asset: Address, recipient: Address, amount: i128)` entrypoint that invokes `token::Client::transfer(&env.current_contract_address(), &recipient, &amount)`. [10](#0-9)   
For listed market assets, restrict the rescue to the controller’s unaccounted surplus and never allow withdrawal of user custodial balances; alternatively, route listed assets through an explicit reconciliation operation that credits legitimate protocol revenue or returns clearly orphaned funds. [2](#0-1) 

### Proof of Concept
The following test demonstrates that a direct token transfer increases the controller’s token balance without creating a withdrawable position:

```rust
use soroban_sdk::{
    testutils::Address as _, token, vec, Address, Env,
};
use controller::{Controller, ControllerClient};
use common::types::HubAssetKey;

#[test]
fn direct_token_transfer_to_controller_is_locked() {
    let env = Env::default();
    env.mock_all_auths();

    let admin = Address::generate(&env);
    let user = Address::generate(&env);
    let controller_id = env.register(Controller, (admin,));
    let controller = ControllerClient::new(&env, &controller_id);

    let token_admin = Address::generate(&env);
    let asset = env
        .register_stellar_asset_contract_v2(token_admin)
        .address();

    token::StellarAssetClient::new(&env, &asset).mint(&user, &1_000);
    token::Client::new(&env, &asset).transfer(&user, &controller_id, &1_000);

    assert_eq!(token::Client::new(&env, &asset).balance(&controller_id), 1_000);

    // There is no rescue_token/sweep entrypoint. The only `withdraw` entrypoint
    // resolves an account's recorded supply position; this direct balance is
    // not backed by such a position.
    let hub_asset = HubAssetKey {
        hub_id: 0,
        asset: asset.clone(),
    };
    let result = controller.try_withdraw(
        &user,
        &0,
        &vec![&env, (hub_asset, 1_000)],
        &None,
    );
    assert!(result.is_err());
}
```
