### Title
KIP-71 Base Fee Market Permanently Corrupted via Cross-Epoch Pending-Vote Blind Spot in `checkConsistency` — (`kaiax/gov/headergov/impl/header.go`)

### Summary

`checkConsistency` validates a new `kip71.upperboundbasefee` (or `kip71.lowerboundbasefee`) vote only against the **ratified** param set from the previous epoch, completely ignoring pending votes already accumulated in the current epoch's `groupedVotes`. Two independent GC members (in `none` mode) can each cast a single, individually-valid vote in the same epoch that together produce `LowerBoundBaseFee > UpperBoundBaseFee` after ratification. `getExpectedGovernance` performs no cross-validation at the epoch boundary, so the corrupted pair is written to `header.Governance` and persisted. `NextMagmaBlockBaseFee` then enters a chaotic oscillation regime, permanently breaking the KIP-71 base fee market until a corrective governance vote is ratified one full epoch later.

### Finding Description

**Entry point — `governance_vote` RPC / `Vote` API:** [1](#0-0) 

`nextBlock = CurrentBlock().NumberU64() + 1`, then `checkConsistency(nextBlock, vote)` is called.

**`checkConsistency` for `Kip71UpperBoundBaseFee`:** [2](#0-1) 

It calls `GetParamSet(blockNum)` and rejects only if `newUpper < ratified_Lower`. It never inspects `h.groupedVotes` for a pending `kip71.lowerboundbasefee` vote in the same epoch.

**`GetParamSet` only reads ratified history:** [3](#0-2) 

`PrevEpochStart` resolves to the start of the epoch *before* the current one. Pending votes in `h.groupedVotes[currentEpochIdx]` are invisible to this call.

**`getExpectedGovernance` performs no cross-validation at epoch boundary:** [4](#0-3) 

It simply collects all votes from the previous epoch and emits them as `GovData`. There is no check that the resulting `LowerBoundBaseFee ≤ UpperBoundBaseFee`.

**`VerifyVote` on the block proposer side has the same blind spot:** [5](#0-4) 

It also calls `checkConsistency(blockNum, vote)` with the same `GetParamSet` call, so the conflicting block is accepted by all verifying nodes.

**`NextMagmaBlockBaseFee` is undefined when Lower > Upper:** [6](#0-5) 

With `Lower=700 gwei, Upper=200 gwei`, any `parentBaseFee ≥ 200` is clamped to 200, then if `gasUsed < gasTarget` the next fee is floored to 700 — immediately violating the upper bound. The fee oscillates between 200 and 700 gwei with no stable equilibrium, and `VerifyMagmaHeader` will reject any block whose proposer computes a different value, risking consensus stall.

### Impact Explanation

After ratification the effective `ParamSet` has `LowerBoundBaseFee > UpperBoundBaseFee`. Every subsequent call to `NextMagmaBlockBaseFee` produces a chaotically oscillating base fee. `VerifyMagmaHeader` enforces the computed value, so any node that computes a different fee (e.g., due to a race in the clamping branch) will reject the block, causing consensus divergence or a chain halt. The corrupted state persists for a full epoch (604 800 blocks ≈ 1 week on Mainnet) until a corrective vote is ratified. This is a durable loss of core chain functionality (KIP-71 base fee market).

### Likelihood Explanation

In `none` governance mode (the code default per `params/governance_params.go:40`), any two GC members acting independently and in good faith can trigger this: one raises the lower bound, the other lowers the upper bound, each vote individually passing all checks. No collusion, no compromised keys, no majority required — just two honest governance participants exercising their permitted rights in the same epoch. In `single` mode the governing node would have to cast both conflicting votes itself (an operator mistake), which is less likely but still possible.

### Recommendation

1. **In `checkConsistency`**: when validating a `kip71.upperboundbasefee` vote, also scan `h.groupedVotes[currentEpochIdx]` for any pending `kip71.lowerboundbasefee` vote and use `max(ratified_Lower, pending_Lower)` as the effective lower bound for the check (and symmetrically for `kip71.lowerboundbasefee`).
2. **In `getExpectedGovernance`**: after collecting all votes, assert `LowerBoundBaseFee ≤ UpperBoundBaseFee` and drop or reject the conflicting pair if the invariant is violated.
3. **In `NextMagmaBlockBaseFee`**: add a defensive guard that returns `lowerBoundBaseFee` immediately when `lowerBoundBaseFee > upperBoundBaseFee`, preventing chaotic oscillation even if the governance state is corrupted.

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (h *headerGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	h.mu.RLock()
	defer h.mu.RUnlock()

	prevEpochStart := PrevEpochStart(blockNum, h.epoch, h.isKoreHF(blockNum))
	gh := h.history
	gp, err := gh.Search(prevEpochStart)
	if err != nil {
		logger.Warn("No param set", "blockNum", blockNum, "prevEpochStart", prevEpochStart)
		return *gov.GetDefaultGovernanceParamSet()
	}
	return gp
}
