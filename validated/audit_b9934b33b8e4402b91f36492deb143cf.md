Verification: the raydium-cp-swap program's `ObservationState`/TWAP oracle is write-only telemetry — it is updated inside `swap_base_input` and `swap_base_output` after every swap [1](#0-0) [2](#0-1) , and is only otherwise referenced at pool initialization to create the account [3](#0-2) . No instruction in the program (swap, `deposit`, or `withdraw`) reads the TWAP/`ObservationState` back to gate eligibility, compute redeemable amounts, or open/close a minting or redemption window the way `LibUbiquityPool` in the reported bug does. Deposit and withdraw use direct vault-balance/constant-product math rather than any oracle price, so there is no reachable path where manipulating the recorded TWAP unlocks disproportionate redemption or minting of pool funds. The reported bug class (oracle-gated collateral redemption manipulated via TWAP) has no analog in this codebase's unprivileged swap/deposit/withdraw paths.
