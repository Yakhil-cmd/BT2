### Title
Proposer-Controlled `header.VRank` Suppression Bypasses CFS Threshold, Enabling Unqualified Candidate Promotion to `ValActive` — (`File: kaiax/vrank/impl/consensus.go`)

---

### Summary

`VerifyHeader` unconditionally accepts a nil/empty `header.VRank` for any non-epoch-start block. Because the proposer of block N writes `header(N).VRank` unilaterally, a malicious proposer can suppress candidate failure reports (cfReport) for every block they propose. The Candidate Failure Score (CFS) accumulated in the CP matrix is then artificially low. At epoch-end, a `CandTesting` candidate whose true CFS should exceed `CfsThreshold` instead passes the VRank test and is promoted to `ValActive`, gaining block-proposal rights and KAIA block rewards they are not entitled to.

---

### Finding Description

`header(N).VRank` is written by the proposer of block N and is supposed to contain the list of `CandTesting` addresses that failed to respond to `VRankPreprepare` during consensus of block N-1. `VerifyHeader` validates the field as follows:

```go
// kaiax/vrank/impl/consensus.go lines 58-71
// Non-epoch-start block
if len(header.VRank) == 0 {
    return nil          // ← accepted unconditionally; no completeness check
}

report, err := vrank.DecodeReport(header.VRank)
...
candidates, err := v.Valset.GetCandTesting(number - 1)
...
return validateNonEpochVRank(report, candidates)
``` [1](#0-0) 

`validateNonEpochVRank` only checks that reported addresses are valid candidates, are sorted, and are deduplicated. It does **not** verify that the report is complete — i.e., that every candidate who actually failed is included. [2](#0-1) 

A malicious proposer therefore passes `VerifyHeader` by setting `header.VRank = nil`, suppressing all failures for their block. `applyBlocksForCPMatrix` then reads an empty cfReport for that block:

```go
// kaiax/vrank/impl/scoring.go lines 167-190
cfReport, err := v.cfReport(blockNum)   // returns [] when header.VRank == nil
...
cpMatrix.AddProposer(reporter)          // proposer counted in N
for _, candidate := range cfReport {   // loop body never executes
    cpMatrix.Increment(candidate, reporter)
}
``` [3](#0-2) 

The byzantine filter (`generateCFSFromCPMatrix`) removes the **top-F** reporter scores per candidate, where `F = floor(N/3)` and N = distinct proposers seen:

```go
// kaiax/vrank/impl/scoring.go lines 199-201
func generateCFSFromCPMatrix(cpMatrix vrank.CPMatrix) map[common.Address]uint64 {
    F := cpMatrix.ProposerCount() / 3
    return byzantineFilter(cpMatrix, F)
}
``` [4](#0-3) 

The filter is designed to discard **false accusers** (proposers who inflate scores). When malicious proposers instead **suppress** reports (contributing 0 to the matrix), the filter removes the top-F **honest** scores, amplifying the suppression. With F malicious proposers each setting `header.VRank = nil`, the effective CFS is computed from only `N - 2F` honest proposers' reports — well below what the full honest set would produce.

At epoch-end, `applyEpochTransition` uses this deflated CFS to gate candidate promotion:

```go
// kaiax/valset/impl/transition_context.go lines 207-213
case valset.CandTesting:
    if ctx.isPassVrankTest(addr) {
        competeOrDemote(addr, val)   // promoted to ValActive
    } else {
        val.State = valset.Registered // T2: failed vrank test
    }
``` [5](#0-4) 

`isPassVrankTest` returns `true` when `CFS[addr] < CfsThreshold`: [6](#0-5) 

---

### Impact Explanation

A `CandTesting` candidate who was genuinely unresponsive (true CFS ≥ `CfsThreshold`) is incorrectly promoted to `ValActive`. As an active validator they:
- Participate in block proposal and committee selection
- Receive KAIA block rewards they are not entitled to

This is a **validator privilege escalation** that corrupts the protected validator-set state and causes unauthorized KAIA reward distribution.

---

### Likelihood Explanation

Any proposer (a semi-trusted actor) can set `header.VRank = nil` for every block they propose. No special capability beyond being a proposer is required. With F = floor(N/3) colluding proposers — the standard BFT threat model — the suppression is sufficient to keep a candidate's CFS below the threshold even when honest proposers faithfully report failures. The byzantine filter, designed for false-accusation resistance, inadvertently amplifies the suppression by removing honest high scores.

---

### Recommendation

`VerifyHeader` should not accept a nil/empty `header.VRank` when `GetCandTesting(N-1)` returns a non-empty candidate set. The verifier should require the proposer to commit to a complete report (or prove via a signed aggregate that no failures occurred). At minimum, the protocol should require a non-nil VRank whenever candidates exist for the reported block, forcing the proposer to explicitly encode an empty list rather than silently omitting the field.

---

### Proof of Concept

**Setup:** 10 validators, 1 epoch = 86400 blocks, `CfsThreshold = 43200` (50% of blocks), candidate C is unresponsive in every block.

**Honest behavior:** Each of the 7 honest proposers reports C as failed in all their ~8640 blocks → per-proposer score = 8640.

**Attack:** 3 malicious proposers (F = floor(10/3) = 3) set `header.VRank = nil` for all their ~25920 blocks → per-malicious-proposer score = 0.

**CP matrix for C:** `{honest1: 8640, honest2: 8640, ..., honest7: 8640, mal1: 0, mal2: 0, mal3: 0}`

**Filter removes top F=3 scores** (three honest scores of 8640):
`filteredScores = [8640, 8640, 8640, 8640]` (4 remaining honest)

**CFS(C) = 4 × 8640 = 34560 < 43200 = CfsThreshold**

`isPassVrankTest(C)` returns `true`. At epoch-end, `applyEpochTransition` promotes C from `CandTesting` → `ValActive` via T3a, despite C being genuinely unresponsive throughout the epoch. [7](#0-6) [8](#0-7) [5](#0-4)

func (v *VRankModule) applyBlocksForCPMatrix(start, end uint64, seed vrank.CPMatrix) (vrank.CPMatrix, error) {
	cpMatrix := seed.Clone()
	for blockNum := start; blockNum <= end; blockNum++ {
		header := v.Chain.GetHeaderByNumber(blockNum)
		if header == nil {
			return nil, vrank.ErrHeaderNotFound
		}

		cfReport, err := v.cfReport(blockNum)
		if err != nil {
			return nil, err
		}

		roundByte, err := v.RoundReader.Round(header)
		if err != nil {
			return nil, err
		}
		round := uint64(roundByte)
		reporter, err := v.Valset.GetProposer(blockNum, round)
		if err != nil {
			return nil, err
		}
		// Record the proposer in the CP matrix even when this block has no cfReport,
		// so ProposerCount() reflects every proposer seen in the epoch.
		cpMatrix.AddProposer(reporter)

		for _, candidate := range cfReport {
			if _, ok := cpMatrix[candidate]; !ok {
				logger.Warn("cfReport contains address not in candidates list; skipping", "blockNum", blockNum, "candidate", candidate.Hex())
				continue
			}
			cpMatrix.Increment(candidate, reporter)
		}
	}
	return cpMatrix, nil

// generateCFSFromCPMatrix derives F = floor(N/3) from the number of distinct
// proposers seen in the epoch (CPMatrix.ProposerCount()) and applies the
// byzantine filter.
func generateCFSFromCPMatrix(cpMatrix vrank.CPMatrix) map[common.Address]uint64 {
	F := cpMatrix.ProposerCount() / 3
	return byzantineFilter(cpMatrix, F)
}

// byzantineFilter computes CFS scores from pre-aggregated per-candidate failure data.
//
// cpMatrix[candidate][reporter] is the number of times reporter included candidate
// in cfReport over the epoch. F is the number of highest reporter totals to discard
// per candidate, defending against up to F byzantine reporters that may inflate scores.
func byzantineFilter(cpMatrix vrank.CPMatrix, F int) map[common.Address]uint64 {
	cfs := make(map[common.Address]uint64)
	for cand, reporterToScore := range cpMatrix {
		scores := slices.Collect(maps.Values(reporterToScore))
		slices.Sort(scores)
		if F >= len(scores) {
			// since `scores` contain non-zero scores only, F >= len(scores) can happen, in which case all scores are discarded.
			scores = nil
		} else {
			scores = scores[:len(scores)-F]
		}
		var sum uint64
		for _, t := range scores {
			sum += t
		}
		cfs[cand] = sum
	}
	return cfs
}
