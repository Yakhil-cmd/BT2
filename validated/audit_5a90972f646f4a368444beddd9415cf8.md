## Finding

Multi-tenant Shipit installations (see `docs/setup.md` "Using Multiple Github Applications", showing several orgs each with their own `webhook_secret`) select the HMAC secret to verify a webhook against the *organization* claimed in the payload, but the `status` event handler writes to a commit selected purely by SHA with **no repository/organization scoping at all**. This lets an attacker who legitimately administers their own org's GitHub App (and therefore knows their own `webhook_secret`) forge CI status results on commits belonging to a completely different, victim organization/stack.

### Root cause

`WebhooksController#verify_signature` picks the app/secret to validate against based on the org named inside the attacker-controlled JSON body: [1](#0-0) [2](#0-1) 

`repository_owner` reads `params.dig('repository', 'owner', 'login')` (or the `organization.login` fallback). Since the attacker composes the entire raw POST body themselves and signs it with their own org's real secret, they can freely set this field to their own org (so `Shipit.github(organization: repository_owner)` resolves to their own app and the HMAC check succeeds) while independently controlling every other field in the same JSON body — including `sha`.

Most webhook handlers scope their effect through `Handler#stacks`, which looks up `Repository.from_github_repo_name(repository_name)`: [3](#0-2) 

But `StatusHandler` does not use this scoping at all — it looks up commits globally by SHA across the entire installation: [4](#0-3) 

`Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` has no `stack_id`/`repository` filter, so any commit sha known to the attacker (git SHAs are not secret — they're visible in any public GitHub UI, PR diff link, `git log`, etc.) in *any* stack on the Shipit instance can have an arbitrary `state`/`context`/`description` status attached.

### Impact

That forged `Status` record is exactly what gates auto-merge/auto-deploy: [5](#0-4) 

`all_status_checks_passed?` / `any_status_checks_failed?` feed `reject_unless_mergeable!`, and `ProcessMergeRequestsJob` uses exactly this to decide whether to call `merge_request.merge!` (which invokes `stack.github_api.merge_pull_request`): [6](#0-5) [7](#0-6) 

`Status#after_commit` also directly schedules continuous delivery: [8](#0-7) 

So an attacker with their own (legitimately configured) org in a shared/multi-org Shipit instance can forge a `success` status for a required CI context on a victim commit they never touched, causing Shipit to merge a pull request and/or trigger continuous deployment for that victim's repo — a cross-repository, unauthorized merge/deploy that bypasses the real CI gate. The equality broken is exactly "an organization that authenticated versus the repository that is written": `Shipit.github(organization: repository_owner)` (attacker's own org secret) authenticates the request, but `StatusHandler#process`'s `Commit.where(sha:)` write target has no binding to that organization or its repositories at all.

### What is unverified

I could not directly inspect `Shipit.github`'s org-resolution/`GithubOrganizationUnknown` raising code beyond what `lib/shipit/github_app.rb` shows (token/signature-only), nor confirm whether any additional org allow-list gate exists elsewhere in `config/`/initializer code that might restrict this further — the index did not surface such a file. This scenario also assumes a multi-org Shipit deployment (as documented) where at least two independently-secreted orgs exist; a single-org instance would not expose this cross-tenant angle, though the missing repository scoping in `StatusHandler` itself remains present regardless.

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
