### Title
CCMenu API token created without a stack scope grants read access to every stack, not just the one requested - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`Shipit::CCMenuUrlController#client` mints an `ApiClient` with `permissions: %w[read:stack]` but never sets `stack_id`, then embeds that client's token in a URL that is scoped, in appearance, to a single stack (`api_stack_ccmenu_url(stack_id: stack.to_param)`). Because the API layer treats an absent `stack_id` on the `ApiClient` as "authorized for all stacks," the resulting token silently authorizes read access to every stack in the Shipit instance, not just the one the user requested the CCMenu URL for.

### Finding Description
`CCMenuUrlController#fetch` builds a per-user, unscoped `ApiClient` and generates a URL that looks like it is bound to one stack: [1](#0-0) 

The `client` method finds-or-creates this API client with only `permissions: %w[read:stack]` — no `stack:` attribute is ever assigned: [2](#0-1) 

Downstream, the API base controller decides which stacks an `ApiClient` may see purely based on whether `stack_id` is present on the client record: [3](#0-2) 

Since the CCMenu client's `stack_id` is `nil`, `current_api_client.stack_id?` is false, so `stacks` resolves to `Stack.all` for that token — the exact same authorization surface as a totally unscoped API client. The one place this token is actually meant to be consumed, `Api::CCMenuController#show`, does not use the `stacks`-scoped lookup at all; it resolves the target stack directly from the URL param and only checks `require_permission :read, :stack` (a permission-string check, not a per-stack ownership check): [4](#0-3) 

`require_permission :read, :stack` only calls `ApiClient#check_permissions!`, which checks the `permissions` array, never the `stack_id`: [5](#0-4) 

The binding that is broken: the URL/UI presents the token as authorizing **stack A** ("Fetch CCMenu URL for stack A"), but the token that is actually minted and embedded authorizes **all stacks** the user can see none of that is enforced at all in `Api::CCMenuController`, which never checks `current_api_client.stack_id`. The test suite even documents the intended behavior with a *different*, explicitly stack-scoped fixture client (`here_come_the_walrus`, `stack: shipit`) elsewhere in the API test suite, and `Api::StacksControllerTest` explicitly asserts "an api client scoped to a stack will only see that one stack" — confirming stack-scoping is a deliberate, expected security boundary that the CCMenu flow fails to apply: [6](#0-5) [7](#0-6) 

### Impact Explanation
CCMenu URLs are designed to be handed out to third-party, unauthenticated CI-status-monitoring tools (CCMenu/CCTray clients) per stack, precisely because they carry a bearer token in the query string instead of requiring a logged-in Shipit session. Because the token is not stack-scoped, anyone who obtains one stack's CCMenu URL (which is explicitly meant to be shared with external tooling, embedded in configs, dashboards, etc.) can reuse the same `token` value against `Api::CCMenuController#show` with an arbitrary `stack_id`, and against any other `read:stack` endpoint (`Api::StacksController#show/index`, `Api::DeploysController#index`, `Api::TasksController#index/show`, etc., since `stacks` resolves to `Stack.all`). This yields unauthenticated read access to stack state, deploy history, and task output for every stack in the deployment — matching the High-impact category "unauthenticated read of stack state, task streams or deploy output."

### Likelihood Explanation
No privileged credentials are required to trigger the flaw. Any authenticated Shipit user requesting a CCMenu URL for a single, low-sensitivity stack unintentionally receives a token with global read scope; the vulnerability is baked into the default code path (`CCMenuUrlController#client`) and is exercised every time this feature is used, with no additional attacker action needed beyond obtaining a URL that a legitimate user was encouraged to share externally.

### Recommendation
Scope the `ApiClient` created by `CCMenuUrlController#client` to the specific stack being requested (`stack: stack`), and key the `find_or_create_by!` lookup on `(creator, stack)` rather than a single global "CCMenu Client" per user, so each stack gets its own appropriately scoped token. Additionally, `Api::CCMenuController#show` should validate that `current_api_client.stack_id` (if present) matches the requested stack, consistent with the scoping already enforced by `Api::BaseController#stacks`.

### Proof of Concept
1. As a logged-in Shipit user with access to stack `low-sensitivity-stack`, visit its settings page and click "Fetch CCMenu URL" (`GET /stacks/low-sensitivity-stack/.../ccmenu_url`, routed to `CCMenuUrlController#fetch`).
2. Observe the response contains `ccmenu_url=".../api/stacks/low-sensitivity-stack/ccmenu.xml?token=<TOKEN>"`; note that `ApiClient.last.stack_id` is `nil` and `permissions == ["read:stack"]`.
3. Share/leak this URL externally (its whole purpose is external, unauthenticated consumption by CI dashboard tools).
4. An attacker in possession of `<TOKEN>` requests `GET /api/stacks/secret-production-stack/ccmenu.xml?token=<TOKEN>` (a stack the URL was never meant to expose).
5. `Api::BaseController#authenticate_api_client` (overridden in `Api::CCMenuController`) successfully authenticates via `ApiClient.authenticate(params[:token])`; `require_permission :read, :stack` passes because `permissions` includes `read:stack`; `stack` is resolved directly from `params[:stack_id]` with no ownership check — the attacker receives full CCMenu XML status data for `secret-production-stack`.
6. The same `<TOKEN>` also works against other `read:stack`-gated endpoints such as `GET /api/stacks/secret-production-stack.json`, since `Api::BaseController#stacks` treats the token as unscoped (`Stack.all`).

```ruby
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end
```
