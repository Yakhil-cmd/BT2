## Analog Found: Centralization risk in asset `spender_attested` attestor list control

### Title
Asset definer has unilateral, unbounded control over the trusted attestor list for `spender_attested` assets, enabling freezing or griefing of holders' funds - (File: validation.js)

### Summary
The ArtGobblers report flags a centralization risk where an `onlyOwner` function (`upgradeRandProvider`) lets a single privileged address swap out a critical, trust-anchored dependency (the randomness provider) with no on-chain constraints, which can brick reveals or let the owner manipulate outcomes in its favor. The closest reachable analog in ocore is the `asset_attestors` message, which lets an asset's **definer** (the ordinary, unprivileged address that issued the asset — one of the explicitly allowed actors) unilaterally and repeatedly replace the entire list of "trusted attestors" that gate spending of a `spender_attested` asset, with essentially no restriction other than address-format validity.

### Finding Description
When an asset is created with `spender_attested: true`, spending is conditioned on the sender being attested by one of the addresses in the asset's attestor list [1](#0-0) . This attestor list is not fixed at issuance — it can be arbitrarily replaced at any later time via an `asset_attestors` message, validated by `validateAttestorListUpdate`:

```
function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	...
	if (objUnit.authors[0].address !== objAsset.definer_address)
		return callback("attestor list can be edited only by definer");
	err = checkAttestorList(payload.attestors);
	...
}
``` [2](#0-1) 

The only checks performed by `checkAttestorList` are that addresses are syntactically valid, sorted, deduplicated, and under a length cap [3](#0-2) . There is no restriction preventing the definer from:
- Replacing the entire attestor set with addresses under its own control (analogous to the RandProvider being swappable to a malicious/controlled contract), or
- Replacing it with attestors that will never attest any current holder, effectively cutting off previously-attested addresses from spending.

Because `readAsset` always resolves to the **latest** attestor list as of `last_ball_mci` (not the list active when a holder received/was attested for the asset) [4](#0-3) , spend validation re-checks attestation against whatever list is current at the time of the payment [1](#0-0) . This means a definer can, at any later main chain index, swap the attestor set and immediately change who is capable of spending an asset that others already hold, with no cooldown, timelock, or governance check on this "provider" mechanism — mirroring the report's core complaint that an owner can arbitrarily update a critical, trust-relied-upon address list.

### Impact Explanation
Any holder of a `spender_attested` asset is exposed to unilateral action by the definer: the definer can revoke attestation eligibility for existing holders (freezing their ability to spend already-received asset units) or install self-controlled attestors to grant/deny spending rights at will. This is a concrete "AA/asset fund loss or freezing" scenario reachable purely by an unprivileged asset issuer posting a single `asset_attestors` unit — no network, node, or key-compromise assumption is needed. Severity is Medium, matching the source report, since it requires the definer to act (a defined, semi-trusted role) but the design gives that role unusually broad, un-timelocked power over already-issued, held funds.

### Likelihood Explanation
Likelihood is moderate to high: any asset definer choosing `spender_attested: true` can trigger this at will by composing and posting a single `asset_attestors` message referencing their asset; validation only checks that the sender is `objAsset.definer_address` [5](#0-4) , with no additional protections such as requiring holder consent, a delay, or immutability once set. The composer function to build such a message is a standard exposed helper (`composeAssetAttestorsJoint`) [6](#0-5) .

### Recommendation
Consider adding safeguards analogous to those recommended in the report (avoiding fully unilateral control of a critical trust anchor), for example:
- Allow attestor list updates to only add attestors, not remove ones that have already attested holders of unspent outputs, or
- Introduce a delay/timelock between an attestor list change and its effect on already-issued outputs, or
- Document/require that `spender_attested` assets be considered explicitly definer-trusted and clearly warn wallets/holders that the attestor set (and thus spendability) can change at any time without notice.

### Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true` and an initial attestor list `[X]` (as part of the `asset` message) [7](#0-6) .
2. Attestor `X` attests holder `H`; `H` receives units of asset `A` and can spend them because `H` is attested by `X`, which is in the current list.
3. At any later point, `D` posts an `asset_attestors` message with a brand-new list `[Y]` where `Y` is controlled by `D` and has not attested `H` [2](#0-1) , [8](#0-7) .
4. From that point on, `readAsset` returns the new list `[Y]` as the current attestor set [4](#0-3) , and `H`'s previously-spendable holdings of asset `A` become unspendable (`"none of the authors is attested"` / `"issuer is not attested"`) [1](#0-0) , effectively freezing `H`'s funds without `H`'s consent.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}
