### Title
Insolvent account's remaining collateral is booked as protocol revenue while its bad debt is fully socialized onto suppliers - (File: contracts/pool/src/ops/seize.rs)

### Summary
When `clean_bad_debt` / post-liquidation cleanup seizes an insolvent account, the account's leftover supply positions are reclassified as **protocol revenue** (`absorb_supply_as_revenue`), while the account's leftover debt is **written down against the debt market's supply index**, i.e. socialized onto ordinary suppliers. The seized collateral value is never applied to offset the debt being socialized. This is the XOXNO analog of the Symmetrical bug: value belonging to the liquidated/cleaned account is distributed *to the protocol* instead of being applied *before* the loss distribution, leaving suppliers (the analog of partyB/liquidator) worse off by exactly the collateral amount.

### Finding Description
Bad-debt cleanup runs `execute_bad_debt_cleanup` (contracts/controller/src/positions/liquidation/bad_debt.rs:14-60), which builds `PoolSeizeEntry` items for both sides and calls `pool_seize_positions_call`. In the pool, `ops::seize::apply` (contracts/pool/src/ops/seize.rs:23-31) treats the two sides asymmetrically:

- `AccountPositionType::Deposit` → `cache.absorb_supply_as_revenue(position)` — the borrower's supply shares become **revenue shares the protocol owns**, claimable later via `claim_revenue` (pool README explicitly states this path "books a seized deposit as revenue").
- `AccountPositionType::Borrow` → `interest::apply_bad_debt_to_supply_index` then `burn_debt` — the unpaid debt is socialized by lowering the debt market's supply index, hurting every supplier in that market.

So the cleaned account's residual collateral accrues to the protocol owner, while its residual debt is dumped on suppliers in full. The collateral's value is not routed (via recapitalization, revenue-for-debt offset, or sale) to the market absorbing the loss. In the Symmetrical report, partyA's reimbursement was credited only after deficit distribution; here the account's residual collateral is credited to protocol revenue while the deficit is distributed to suppliers — same economic defect, opposite beneficiary.

This is reachable by any unprivileged address: `clean_bad_debt` (permissionless, dust-capped) and `liquidate` (which calls `check_bad_debt_after_liquidation` → `execute_bad_debt_cleanup` when residual collateral is ≤ the dust cap) both trigger this path.

### Impact Explanation
For every cleaned insolvent account with non-zero residual collateral, suppliers in the debt market absorb the *entire* bad debt, while the protocol captures the residual collateral as claimable revenue. Concretely: if an insolvent account has $4 of collateral dust and $100 of bad debt, suppliers lose the full $100 of purchasing power via the supply-index write-down and the protocol gains $4 — value that should have reduced the socialized loss to ~$96. Repeated across accounts this is a systematic transfer from suppliers to the protocol during insolvencies, i.e. loss of user funds (suppliers' yield/principal) and unjust enrichment of revenue.

### Likelihood Explanation
The permissionless `clean_bad_debt` path requires the account to be insolvent with residual collateral at or below the ~$5 dust cap, which caps per-call theft at a few dollars — bounding severity to Medium. However, the post-liquidation cleanup inside `liquidate` uses the same admission (`is_socializable_bad_debt`), and the owner-only `process_force_socialize_bad_debt` removes the dust cap entirely; the mechanism itself is deterministic and fires every time an insolvent account still holds collateral — which is common, since seizure floors to whole token units and rounding dust is routinely left behind.

### Recommendation
Offset the socialized debt with the seized collateral's value before writing down the supply index. Options: (a) have the controller `recapitalize` the debt market using proceeds from selling/withdrawing the seized deposit shares before socializing the remainder; (b) absorb the deposit as revenue but simultaneously reduce the bad-debt amount written down by the collateral's value so net socialization reflects only the true shortfall; or (c) claim the seized shares as revenue in a way that funds the shortfall rather than accruing them as free profit. At minimum, apply the account's residual collateral to the deficit *before* `apply_bad_debt_to_supply_index`, mirroring the "reimburse before distribution" fix from the source report.

### Proof of Concept
1. Supplier S supplies token D into hub market `(hub, D)`. Borrower A supplies token C as collateral and borrows D to near-max LTV.
2. Price moves make A insolvent: `total_debt > total_collateral`, with residual collateral value small (≤ dust cap) — e.g., achieved by a prior `liquidate` that floors seizure and leaves dust, or directly via `clean_bad_debt` once eligible.
3. Attacker (or the same liquidator) calls `controller.clean_bad_debt(account_id)`. `execute_bad_debt_cleanup` emits two seize entries: `Deposit` on market C and `Borrow` on market D.
4. In `pool::seize`: market C's shares become protocol `revenue` (later extractable via `claim_revenue` for cash); market D's `supply_index` is scaled down by the full `bad_debt`, reducing every D-supplier's claim.
5. Result: supplier S bears 100% of the bad debt; the protocol pockets the residual C collateral. No mechanism returns that collateral's value to market D to offset the write-down.

Note: the "absorb deposit as revenue" behavior is explicitly documented in the pool README and `ops/seize.rs` comments as the intended mechanism for share reclassification (avoiding share minting). The vulnerability is not the reclassification itself but that the absorbed value is captured as profit rather than applied against the concurrently socialized debt; the documentation describes the mechanism, not a fairness decision, so I assessed it as in-scope rather than a documented ADR choice.
