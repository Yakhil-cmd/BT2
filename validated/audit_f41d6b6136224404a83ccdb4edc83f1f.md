### Title
Uncaught exception from `objectLength.getHeadersSize()` on attacker-controlled numeric overflow crashes validating nodes - (File: [validation.js](), [object_length.js]())

### Summary
`validation.js`'s main `validate()` function computes the expected headers size via `objectLength.getHeadersSize(objUnit)` at line 257 **without a try/catch**, while the very next computation, `objectLength.getTotalPayloadSize(objUnit)`, is explicitly wrapped in `try { ... } catch (e) { return callbacks.ifJointError(...) }` (lines 259-266). `getHeadersSize()` internally calls `object_length.js`'s `getLength()`, which `throw`s a raw `Error("invalid number: " + value)` whenever it encounters a non-finite JS number (`Infinity`/`-Infinity`/`NaN`) anywhere in the unit header (e.g. inside `earned_headers_commission_recipients`, `witnesses`, `authors`, etc.). Because JS's `JSON.parse` silently converts out-of-range numeric literals (e.g. `1e400`) to `Infinity` instead of throwing, a single unprivileged unit poster can smuggle such a value into a unit header field and trigger an uncaught exception deep inside core validation logic that every receiving node executes on every new/relayed unit.

### Finding Description
`getLength()` in [1](#0-0)  explicitly throws for any non-finite number:
```
case "number":
    if (!isFinite(value))
        throw Error("invalid number: " + value);
```
`getHeadersSize()` calls this function on a stripped-down clone of the unit header [2](#0-1) , with no exception handling of its own.

In `validation.js`, the call to `getHeadersSize()` at line 257 is unguarded, whereas the structurally identical call to `getTotalPayloadSize()` right below it is wrapped in try/catch: [3](#0-2) 

Any attacker who can post a unit (an "unprivileged unit poster", per scope) can include a numeric field in the unit header that becomes `Infinity` after JSON parsing — JSON syntax permits arbitrarily large exponents (e.g. `1e400`), and `JSON.parse` in JavaScript silently coerces such overflowing literals to `Infinity` rather than raising a parse error. Fields eligible for this attack are those copied into `objHeader` by `getHeadersSize` (i.e. everything except `unit`, `headers_commission`, `payload_commission`, `oversize_fee`, `actual_tps_fee`, `main_chain_index`, `timestamp` (conditionally), `messages`, `parent_units`) — this includes `authors`, `witnesses`, `witness_list_unit`, `last_ball`/`last_ball_unit`, `alt`, `earned_headers_commission_recipients` (an array of `{address, earned_headers_commission_share}` objects where `earned_headers_commission_share` is a plain number), `tps_fee`, `burn_fee`, and `max_aa_responses`.

Because none of these fields are constrained by earlier validation checks to be finite/bounded numbers before `getHeadersSize` runs (the checks at lines 197-209 validate `oversize_fee`, `tps_fee`, `burn_fee`, `max_aa_responses`, but `earned_headers_commission_recipients.*.earned_headers_commission_share` is not checked for finiteness before this point), a unit containing `Infinity` in one of these numeric sub-fields reaches `getHeadersSize()` unguarded and throws.

### Impact Explanation
Since `validate()` is the entry point invoked by every node (via `network.js`, `composer.js`, `divisible_asset.js`, `indivisible_asset.js`, `aa_composer.js`) whenever it receives or composes a joint, an uncaught `Error` thrown from deep inside synchronous validation logic propagates up the call stack. `network.js` installs a deliberate `process.on('uncaughtException', ...)` handler that logs diagnostics and then explicitly re-throws to crash the process: [4](#0-3) 
If the exception from `getHeadersSize()` is not caught by an intermediate handler on the call path, this results in the node process crashing — a remote, unauthenticated, single-unit denial-of-service that can be broadcast to and crash every full node in the network that attempts to validate the poisoned unit, matching the CVE-2006-4574 pattern of "unexpected length/numeric values" triggering an unhandled assertion/crash from a single crafted input. This aligns with the "network unable to confirm new units" impact category, since a network-wide crash-inducing unit would prevent nodes from processing/confirming subsequent units until restarted, and could be repeated indefinitely by relaying the same poisoned unit.

### Likelihood Explanation
Likelihood is High for reachability (any peer/unit-poster can submit units for validation) but the actual severity depends on whether the exception is caught somewhere between `validate()`'s caller and the top-level event loop — this could not be fully confirmed within the available search budget (call sites in `composer.js`, `divisible_asset.js`, `indivisible_asset.js`, `aa_composer.js` were located but their surrounding try/catch context and network.js's specific joint-handling call path were not fully traced). The asymmetry between the guarded `getTotalPayloadSize()` call and the unguarded `getHeadersSize()` call strongly suggests this is an unintentional gap rather than a deliberate design choice, since the two functions have essentially the same failure mode (an object containing a non-finite number) and only one is defensively wrapped.

### Recommendation
Wrap the `objectLength.getHeadersSize(objUnit)` call at `validation.js:257` in the same kind of try/catch used for `getTotalPayloadSize()`, converting any thrown error into a `callbacks.ifJointError(...)` (or `ifUnitError`) response instead of letting it propagate as an uncaught exception. Additionally, consider validating that all numeric fields copied into the header (in particular `earned_headers_commission_recipients[].earned_headers_commission_share`, and any other author/witness-related numeric sub-fields) are finite integers before they reach `getHeadersSize()`/`getLength()`, to close off this class of bug at the source rather than only at the call site.

### Proof of Concept
1. Craft a unit whose `earned_headers_commission_recipients` array (or any other header field copied by `getHeadersSize`) contains a numeric sub-value using a JSON literal that overflows to `Infinity`, e.g.:
```json
{
  "unit": { ... valid unit fields ...,
    "earned_headers_commission_recipients": [
      { "address": "SOME32CHARADDRESS...", "earned_headers_commission_share": 1e400 }
    ],
    ...
  }
}
```
2. `JSON.parse` on the receiving node converts `1e400` to `Infinity` for the `earned_headers_commission_share` field.
3. Post/broadcast this joint to a node. `validation.js`'s `validate()` reaches line 257: `objectLength.getHeadersSize(objUnit)`.
4. `getHeadersSize` → `getLength` encounters the `Infinity` value and executes `throw Error("invalid number: Infinity")`, unguarded by any try/catch at the call site.
5. The exception propagates out of `validate()`; if uncaught up the stack, `network.js`'s `process.on('uncaughtException', ...)` handler logs the error and then `throw err;`, crashing the node process.

Note: Full confirmation that no intermediate try/catch exists between `validate()`'s various call sites (`network.js`, `composer.js`, `divisible_asset.js`, `indivisible_asset.js`, `aa_composer.js`) and the top-level event loop was not completed due to tool-call limits; a Devin session with full repo access should trace these call paths to verify the exception indeed reaches the top-level `uncaughtException` handler unhandled.
