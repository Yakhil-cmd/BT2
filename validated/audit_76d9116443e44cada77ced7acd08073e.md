Missing Zero-Check on `kip71.gastarget` Governance Parameter Causes Node-Wide Panic During Base Fee Calculation — (`params/kip71_config.go`, `kaiax/gov/param.go`)

---

### Summary

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, accepting any `uint64` value including zero. When `kip71.gastarget` is ratified as `0` via header or contract governance, every subsequent call to `NextMagmaBlockBaseFee` with non-zero `parentGasUsed` performs an integer division by zero (`big.Int.Div(x, 0)`), causing a Go runtime panic. Because this function is invoked during block header verification, tx-pool reset, and the gas price oracle, the panic crashes every honest node that attempts to process or validate any block containing transactions — producing a permanent chain halt.

---

### Finding Description

**Root cause — missing `FormatChecker` for `kip71.gastarget`:**

`kaiax/gov/param.go` defines the governance parameter registry. `Kip71BaseFeeDenominator` explicitly rejects zero:

```go
// kaiax/gov/param.go  lines 310-323
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0          // ← zero explicitly rejected
    },
    ...
},
```

`Kip71GasTarget`, which is used as a **divisor** in the same formula, has no such guard:

```go
// kaiax/gov/param.go  lines 324-334
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker, // ← always returns true; 0 accepted
    ...
    DefaultValue: uint64(30000000),
},
```

`noopFormatChecker` is defined as:

```go
// kaiax/gov/param.go  lines 160-162
func noopFormatChecker(cv any) bool {
    return true
}
```

**Trigger path — governance vote:**

In `none` governance mode any GC member, or in `single` mode the governing node, casts a vote `(kip71.gastarget, 0)`. The vote passes `NewVoteData` format validation (calls `FormatChecker` → `noopFormatChecker` → `true`) and `checkConsistency` (which explicitly returns `nil` for `Kip71GasTarget` without additional checks). At the next epoch boundary the ratified value `GasTarget = 0` is written into the effective `ParamSet`.

**Panic site — `NextMagmaBlockBaseFee`:**

```go
// params/kip71_config.go  lines 88-128
parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
if parentGasUsed == gasTarget {          // only safe exit: both zero
    return makeEvenByFloor(parentBaseFee)
} else if parentGasUsed > gasTarget {    // true whenever any gas is used
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // ← PANIC: Div by 0
    ...
} else {
    gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // ← PANIC: Div by 0
    ...
}
```

Go's `math/big.(*Int).Div` panics unconditionally when the divisor is zero. The only escape is `parentGasUsed == 0` (completely empty block). Any block containing at least one transaction reaches the division.

**Call sites that propagate the panic:**

- `blockchain/block_validator.go` → `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`: every validator crashes while verifying any non-empty block.
- `blockchain/tx_pool.go` line 576 → `TxPool.reset` → `NextMagmaBlockBaseFee`: the tx pool crashes on every chain head update.
- `node/cn/gasprice/gasprice.go` line 334 → `isRelaxedNetwork` → `NextMagmaBlockBaseFee`: the gas price oracle crashes.

None of these call sites recover the panic.

---

### Impact Explanation

Once `kip71.gastarget = 0` is ratified and takes effect at the next epoch:

1. Every honest node panics (process crash) the moment it tries to validate or import any block that consumed gas.
2. The chain halts permanently: no block with transactions can be verified, finalized, or imported.
3. All pending and future transactions — including KAIA transfers, staking withdrawals, bridge settlements, and reward distributions — are frozen indefinitely.
4. The corrupted governance parameter persists in the canonical chain state; there is no automatic rollback.

This satisfies the allowed impact gate: **persistent corruption of state that breaks canonical execution, withdrawals, transfers, and settlement**, and **consensus divergence on honest nodes**.

---

### Likelihood Explanation

- In `none` governance mode any GC member can trigger this with a single vote per epoch.
- In `single` governance mode the governing node (one key) can trigger it.
- The vote value `0` is a valid `uint64`; no on-chain or off-chain guard rejects it before it is ratified.
- The analogous parameter `kip71.basefeedenominator` already has the correct `v != 0` guard, demonstrating that the developers are aware of the pattern — the guard was simply omitted for `kip71.gastarget`.
- No recovery path exists once the parameter is active.

---

### Recommendation

Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`, mirroring the existing guard on `Kip71BaseFeeDenominator`:

```go
// kaiax/gov/param.go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // reject zero; it is used as a divisor
    },
    ...
},
```

Optionally, add a defensive guard inside `NextMagmaBlockBaseFee` itself:

```go
// params/kip71_config.go
if kc.GasTarget == 0 {
    // governance misconfiguration; fall back to lower bound
    return makeEvenByFloor(lowerBoundBaseFee)
}
```
