The SVGO advisory concerns XML entity expansion ("Billion Laughs") in a JavaScript SVG-optimization tool that pattern-matches `DOCTYPE` custom entities from untrusted SVG input and recursively expands them without depth limits. This bug class requires: (1) an XML/entity parser that (2) recursively substitutes user-defined entities without bounding recursion depth or output size.

The Polkadot SDK is a Rust codebase with no XML/DOCTYPE/entity parsing surface exposed to untrusted extrinsic, XCM, or contract input — a search for `DOCTYPE`/entity-expansion patterns only turned up unrelated static HTML documentation files [1](#0-0) , not production parsing logic.

The closest structural analog — recursive decoding of nested/self-referential structures from attacker-supplied bytes — is exactly the class of bug the codebase already guards against. For example, `DoubleEncoded::decode` in XCM enforces both a per-structure depth limit (`MAX_XCM_DECODE_DEPTH`) and a global nesting recursion limit (`RECURSION_LIMIT`) via `descend_ref_and_check_depth`, explicitly rejecting inputs that exceed these bounds before any unbounded expansion can occur [2](#0-1) . Similarly, `NestedInput::descend_ref` enforces the depth check on every recursive decode step [3](#0-2) .

Other candidate "recursive expansion" code paths found (`construct_runtime!` macro expansion, `frame-support` procedural macros, transient storage meters) are either compile-time-only constructs with no runtime attacker input, or already have accounting/limits in place (e.g., `StorageMeter::charge` in contracts enforces limits per nested call) [4](#0-3) . None of these constitute a reachable, unauthenticated user entry point analogous to feeding attacker-controlled entity-recursive input into an unguarded expansion routine.

No demonstrable analog to the SVGO Billion-Laughs vulnerability exists in this codebase's production Rust/FRAME/XCM code.

impl<T> Decode for DoubleEncoded<T>
where
	T: Decode,
{
	fn decode<I: codec::Input>(input: &mut I) -> Result<Self, codec::Error> {
		let mut obj = Self { encoded: Vec::<u8>::decode(input)?, decoded: None };

		// If it's a local call, we also decode the inner double encoded object,
		// in order to make sure that its heap memory is accounted for.
		nesting_count::using_once(&mut 0, || {
			nesting_count::with(|count| {
				descend_ref_and_check_depth(
					count,
					RECURSION_LIMIT as u32,
					DECODE_RECURSION_LIMIT_MSG,
				)
			})
			.unwrap_or(Err("Could not access nesting_count env variable".into()))?;

			let mut nested_input =
				NestedInput { downstream_input: input, encoded: &obj.encoded[..], depth: 0 };
			let decoded = T::decode(&mut nested_input)?;
			// If we didn't manage to consume any byte, this is a remote call, and it can't
			// be decoded locally.
			if nested_input.encoded.len() == obj.encoded.len() {
				let _ = nesting_count::with(|count| {
					count.saturating_dec();
				});

				return Ok(obj);
			}
			obj.decoded = Some(decoded);

			// We need to also make sure that we consumed all the input data, but we can't use
			// `decode_all()`, because it only accepts a byte slice as input.
			if !nested_input.encoded.is_empty() {
				return Err(DECODE_ALL_ERR_MSG.into());
			}

			let _ = nesting_count::with(|count| {
				count.saturating_dec();
			});

			Ok(obj)
		})
	}
