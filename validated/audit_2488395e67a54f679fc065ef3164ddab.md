### Title
Inconsistent Cross-Epoch Validation of `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` Governance Votes Allows Inverted Fee Bounds, Breaking the KIP-71 Fee Market — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` validates each KIP-71 bound vote independently against the **current** (pre-epoch) parameter state. Because header-governance votes take effect only at the next epoch boundary, the governing node can cast two votes within the same epoch that each individually pass validation but together produce `LowerBoundBaseFee > UpperBoundBaseFee`. When that inverted state takes effect, `NextMagmaBlockBaseFee` in `params/kip71_config.go` computes fees in the opposite direction of the intended EIP-1559-style mechanism: fees fall under high load and rise under low load. Every honest node computes the same wrong value, so `VerifyMagmaHeader` accepts the broken fee as canonical, permanently corrupting the fee market until a corrective governance vote is applied.

---

### Finding Description

`checkConsistency` contains two cross-parameter guards:

```go
// kaiax/gov/headergov/impl/header.go  lines 179-192
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)          // reads current (pre-epoch) state
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)          // reads current (pre-epoch) state
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    }
```

Each guard reads `h.GetParamSet(blockNum)`, which returns the **currently effective** parameter set — it does not include votes that were cast earlier in the same epoch but have not yet taken effect. Because an epoch spans many blocks (default 604800), the governing node can propose:

- **Block N (epoch E):** vote `kip71.upperboundbasefee = 30 gwei`
  - Check: `30 < currentLower (25 gwei)`? → **No → accepted**
- **Block N+k (epoch E):** vote `kip71.lowerboundbasefee = 100 gwei`
  - Check: `100 > currentUpper (750 gwei)`? → **No → accepted** (pending vote 1 is invisible)

At the epoch-E/E+1 boundary both votes are applied simultaneously, yielding `LowerBound = 100 gwei`, `UpperBound = 30 gwei`.

The individual `FormatChecker` for both parameters is `noopFormatChecker` — no single-parameter range check exists either:

```go
// kaiax/gov/param.go  lines 335-366
Kip71LowerBoundBaseFee: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // no range check
    ...
},
Kip71UpperBoundBaseFee: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // no range check
    ...
},
```

Once the inverted state is live, `NextMagmaBlockBaseFee` in `params/kip71_config.go` misbehaves:

```go
// params/kip71_config.go  lines 60-86
lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)  // 100 gwei
upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)  // 30 gwei

parentBaseFee := parentHeaderBaseFee  // e.g. 50 gwei
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {   // 50 >= 30 → TRUE
    parentBaseFee = upperBoundBaseFee             // clamped to 30 gwei
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee
}
```

After clamping, `parentBaseFee = 30 gwei` regardless of actual network load:

| Gas usage vs target | Shortcut condition | Returned fee |
|---|---|---|
| `> gasTarget` (high load) | `parentBaseFee == upperBound` (30 == 30) → shortcut | **30 gwei** (fee falls) |
| `< gasTarget` (low load) | `nextBaseFee < lowerBound` (< 100) → floor | **100 gwei** (fee rises) |
| `== gasTarget` | returns `parentBaseFee` | **30 gwei** |

The fee market is inverted: congestion lowers the fee and idle periods raise it.

`VerifyMagmaHeader` in `blockchain/block_validator.go` (line 199) calls `govParamSet.ToKip71Config().VerifyMagmaHeader(...)`, which calls `NextMagmaBlockBaseFee` with the same inverted bounds. Every honest node computes the same wrong expected fee, so blocks are accepted — the broken state is canonical and persistent.

---

### Impact Explanation

- **Incorrect fee charges on KAIA**: Under high load the base fee collapses to `UpperBound` (30 gwei), far below the intended floor of 100 gwei; under low load it rises to `LowerBound` (100 gwei), above the intended ceiling of 30 gwei.
- **Fee market permanently broken**: `VerifyMagmaHeader` enforces the inverted fee as the only valid value, so no block can carry a "correct" fee. The state persists until a corrective governance vote takes effect at the next epoch.
- **Transaction filtering corrupted**: `FilterTransactionWithBaseFee` in `work/worker.go` (line 383) uses the inverted `nextBaseFee`, so the txpool accepts/rejects transactions against the wrong floor.
- **`isRelaxedNetwork` in `node/cn/gasprice/gasprice.go` (line 335)** compares `nextBaseFee` against `pset.LowerBoundBaseFee` (100 gwei); under high load the fee is 30 gwei, so `isRelaxedNetwork` always returns `true`, suppressing tip suggestions even during congestion.

---

### Likelihood Explanation

In Kaia's "single" governance mode the governing node is a validator and therefore a block proposer. An epoch of 604800 blocks gives the governing node hundreds of proposal slots per epoch. The two votes need only appear in any two of those slots within the same epoch — a straightforward operation requiring no external coordination. The attack can also occur accidentally when an operator lowers `UpperBound` and raises `LowerBound` in separate transactions without realising the combined effect.

---

### Recommendation

Add a cross-parameter check inside `checkConsistency` that also reads any **pending** (same-epoch, not-yet-effective) vote for the counterpart parameter before accepting the current vote. Alternatively, enforce the invariant at the point where epoch-boundary votes are merged:

```go
// kaiax/gov/headergov/impl/header.go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    // also check against any pending UpperBound vote in this epoch
    if vote.Value().(uint64) >= params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    // also check against any pending LowerBound vote in this epoch
    if vote.Value().(uint64) <= params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    }
```

Using `>=` / `<=` (rather than `>` / `<`) also closes the equal-bounds edge case that `NextMagmaBlockBaseFee` does not handle gracefully.

### Proof of Concept

**Setup**: Mainnet-like chain, Magma fork active, "single" governance mode.  
Initial state: `LowerBoundBaseFee = 25 gwei`, `UpperBoundBaseFee = 750 gwei`.

**Step 1 — Block N (epoch E), governing node is proposer:**
```
governance.Vote("kip71.upperboundbasefee", 30_000_000_000)  // 30 gwei
```
`checkConsistency`: `30e9 < currentLower (25e9)`? → **No** → vote accepted and embedded in header.

**Step 2 — Block N+k (epoch E), governing node is proposer again:**
```
governance.Vote("kip71.lowerboundbasefee", 100_000_000_000)  // 100 gwei
```
`checkConsistency`: `100e9 > currentUpper (750e9)`? → **No** (vote 1 not yet effective) → vote accepted.

**Step 3 — Epoch boundary (E→E+1):**  
Both votes are applied. Effective state: `LowerBound = 100 gwei`, `UpperBound = 30 gwei`.

**Step 4 — Next block, `parentBaseFee = 50 gwei`, `parentGasUsed > gasTarget`:**
```go
// params/kip71_config.go NextMagmaBlockBaseFee
lowerBound = 100 gwei, upperBound = 30 gwei
parentBaseFee (50) >= upperBound (30) → clamp to 30 gwei
parentGasUsed > gasTarget → shortcut: parentBaseFee == upperBound → return 30 gwei
```
`VerifyMagmaHeader` expects 30 gwei; block producer sets 30 gwei; block is accepted.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}
