### Title
Uncaught exception in `getHeadersSize`/`getLength` during unit validation causes denial of service - (File: `object_length.js`, `validation.js`)

### Summary
`object_length.js`'s recursive `getLength()` helper throws bare `Error` objects whenever it encounters a non-finite number, a non-own property, an `undefined` value, or any type it doesn't recognize inside the object it is asked to measure [1](#0-0) . `validation.js` calls `objectLength.getHeadersSize(objUnit)` directly, with no `try/catch`, while the parallel call to `objectLength.getTotalPayloadSize(objUnit)` a few lines below it is explicitly wrapped in `try/catch` [2](#0-1) . This asymmetry mirrors the CVE-2017-12801 bug class: a crafted, attacker-controlled input reaches a low-level size/length computation routine that enforces internal invariants via unconditional `throw`/`assert`-style checks instead of returning a graceful validation error, and the calling code fails to catch it.

### Finding Description
`validate()` in `validation.js` is the single entry point through which every unit posted by any (unprivileged) network participant is checked before acceptance [3](#0-2) . Part of that check computes the header size by cloning the unit object and calling `objectLength.getHeadersSize(objHeader...)`: [4](#0-3) 

`getHeadersSize` in turn calls the shared recursive `getLength()` walker [5](#0-4) . That walker throws unconditionally in several cases while traversing arbitrary values from the (still only shallowly-validated) unit header/messages structure:
- `throw Error("invalid number: " + value)` for non-finite numbers [6](#0-5) 
- `throw Error("object has non-own property " ...)` [7](#0-6) 
- `throw Error("undefined at " + key ...)` [8](#0-7) 
- `throw Error("unknown type=" ...)` for the `default` switch branch [9](#0-8) 

At the point `getHeadersSize` is invoked (line 257), field-level JSON well-formedness has been checked, but the code has not yet excluded every pathological value shape (e.g., `NaN`/`Infinity`-producing numeric fields that survive earlier structural checks, or fields whose values are functions/symbols after being reconstructed from certain deserialization paths) before this size computation runs. Because this specific call site has no surrounding `try/catch` — unlike the very next call to `getTotalPayloadSize` which is deliberately wrapped — any exception thrown deep inside `getLength()` during this call propagates out of `validate()` uncaught.

This is structurally the same defect class as the libebml2 issue: a size/length-accounting routine (`UpdateDataSize` in the CVE vs. `getLength`/`getHeadersSize` here) enforces its own internal correctness assumptions with hard failures (`assert()` vs. `throw Error()`), and a single crafted, remotely supplied unit can drive execution into that failure path, converting what should be a rejected/invalid-input case into an unhandled crash.

### Impact Explanation
If reached without being caught by any outer handler, an uncaught exception thrown synchronously during unit validation can crash or destabilize the node process handling that unit (Node.js processes terminate on unhandled exceptions unless a global handler is present), which is a denial-of-service against the ability of that node to continue validating and confirming new units — directly matching the "network unable to confirm new units" impact class called for in the validation criteria.

### Likelihood Explanation
This requires only crafting an object that: (a) passes the earlier field-presence/type checks in `validate()` up to line 257, and (b) contains, in a header-only field (i.e., not deleted by `getHeadersSize`'s `_.cloneDeep`/`delete` steps — e.g. `alt`, `version`, `authors`, `witness_list_unit`, `earned_headers_commission_recipients`, `last_ball`, etc.), a value shape that trips one of `getLength`'s `throw` branches (a non-finite number is the easiest: `NaN`/`Infinity` cannot be represented in canonical JSON, so this specific vector likely requires the unit to arrive via a non-JSON-serializing internal path, which lowers confidence). Because I could not fully trace whether an actual remote JSON-received unit can carry a non-JSON-representable value (e.g. `NaN`) through the deserialization layer before reaching `validate()`, and could not confirm whether `network.js`'s call site wraps `validation.validate()` in a try/catch that would swallow this particular synchronous throw, I cannot assert with full certainty that this is remotely triggerable end-to-end without a top-level safety net.

### Recommendation
Wrap the `objectLength.getHeadersSize(objUnit)` call in `validation.js` in the same `try/catch` pattern already used for `getTotalPayloadSize`, converting any exception into a proper `ifJointError`/`ifUnitError` callback instead of letting it propagate. More generally, harden `getLength()` in `object_length.js` to return a sentinel/error value (or be called only from callers that already catch) rather than relying on `throw` for input-shape assertions that can be reached by attacker-supplied unit data.

### Proof of Concept
Not conclusively demonstrable from static review alone: I was unable to verify (a) whether a value that triggers `getLength`'s `throw` branches (non-finite number, non-own property, `undefined` value, or unsupported type) can actually survive JSON transport and the preceding `hasFieldsExcept`/type checks in `validate()` before reaching the unguarded `getHeadersSize` call at `validation.js:257`, and (b) whether `network.js`'s invocation of `validation.validate(...)` has an outer `try/catch` that would catch such an exception before it destabilizes the process. Confirming this requires tracing the exact deserialization path for incoming units in `network.js` and constructing a concrete unit payload — I recommend a Devin session with full repo/runtime access to build and test such a payload before treating this as confirmed-exploitable.

function getLength(value, bWithKeys) {
	let cache = new WeakMap();  // object to length
	function _getLength(value) {
		if (value === null)
			return 0;
		switch (typeof value) {
			case "string":
				return value.length;
			case "number":
				if (!isFinite(value))
					throw Error("invalid number: " + value);
				return 8;
				//return value.toString().length;
			case "object":
				// return cached result if already processed
				if (cache.has(value))
					return cache.get(value);
				var len = 0;
				if (Array.isArray(value))
					value.forEach(function (element) {
						len += _getLength(element);
					});
				else
					for (var key in value) {
						if (!Object.prototype.hasOwnProperty.call(value, key))
							throw Error("object has non-own property " + key + " in " + JSON.stringify(value));
						if (typeof value[key] === "undefined")
							throw Error("undefined at " + key + " of " + JSON.stringify(value));
						if (bWithKeys)
							len += key.length;
						len += _getLength(value[key]);
					}
				cache.set(value, len);  // memoize for future references
				return len;
			case "boolean":
				return 1;
			default:
				throw Error("unknown type=" + (typeof value) + " of " + value);
		}
	}
	return _getLength(value);
