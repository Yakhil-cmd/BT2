### Title
`net_settle` rejects valid settlements when directed rounding floors the debt burn to zero — `(contracts/pool/src/ops/net_settle.rs)`

### Summary
Analogous to the Superposition `swap_2_internal` `interim_usdc_out == interim_usdc_in` check, `pool::net_settle` enforces a strict post-condition — a positive settled amount must burn nonzero shares on *both* legs (`GenericError::NetSettleRoundsToZeroShares`). Because the debt burn is deliberately `floor`-rounded, any settlement whose settled token amount corresponds to less than one RAY debt share produces `burned_debt == 0` and reverts, even though the caller requested a legitimate settle and supply shares were ready to burn. This propagates into the controller's `repay_debt_with_collateral` (and any multi-leg path using `net_settle_collateral_against_debt`), causing valid user operations to revert.

### Finding Description
`resolve_net_settle` in `common/src/rates/scaling.rs:133-161` computes `settle = min(amount, floor(supply), ceil(debt))` and then `burned_debt = floor(settle → scaled debt)`. Whenever `settle` is small relative to `borrow_index / 10^(27-decimals)` — i.e., the settle covers less than one debt share — `burned_debt` is `0` while `gross_amount > 0`.

`contracts/pool/src/ops/net_settle.rs:38-42` then does:

```rust
assert_with_error!(
    env,
    gross_amount == 0 || (burned_supply.raw() > 0 && burned_debt.raw() > 0),
    GenericError::NetSettleRoundsToZeroShares
);
```

The in-repo test `test_net_settle_uses_directed_rounding_and_rejects_zero_debt_burn` at `contracts/pool/tests/flows.rs:776-820` proves the revert: with `borrow_index = 3*RAY`, `amount = 1`, and a `10*RAY` position, `net_settle` reverts with `NetSettleRoundsToZeroShares` even though a positive `settle` of 1 token was available.

The controller calls this via `net_settle_collateral_against_debt` (`contracts/controller/src/strategies/legs.rs:165-229`), which is invoked from `repay_debt_with_collateral` (`contracts/controller/src/strategies/repay_debt_with_collateral.rs`). Note the asymmetry that makes this strictly worse than a symmetric guard: `burned_supply` is `ceil`-rounded, so for the same `settle` it is possible to get `burned_supply > 0 && burned_debt == 0` — the check fires precisely on the smallest legitimate settles.

### Impact Explanation
A user attempting `repay_debt_with_collateral` on a market where the conservative overlap `min(amount, floor(supply), ceil(debt))` is smaller than one debt share (dust debt, high `borrow_index`, low-decimal assets, or a near-closed position) has every such call revert. Increasing `amount` does not help when `debt_ceil` itself is sub-share — the whole settle is capped by `ceil(debt)`, so the leg is unclosable through `net_settle` permanently. This is a Denial-of-Service on a subset of valid repayments/liquidation-adjacent flows, matching the medium-severity "valid transaction reverts with no further harm" shape of the source report. It does not steal funds; the user retains alternative repay paths (`repay` with tokens), which bounds severity.

### Likelihood Explanation
Reachable by any unprivileged account via `repay_debt_with_collateral` whenever a position's residual debt or requested settle is dust relative to one RAY debt share — a routine end-state after repeated partial repays under a high borrow index, or on low-decimal (0–2 decimal) hub assets where one native unit already maps to less than a share. The directed-rounding boundary is hit deterministically, not randomly, once a position decays into the sub-share band.

### Recommendation
Relax the strict both-legs-nonzero check the same way the source report recommends relaxing the equality: permit `burned_debt == 0` settles by treating them as a no-op (skip the burn, return `settled_amount = 0` or the actual settled amount with only the supply burn applied only when the debt burn is nonzero), or round the debt burn *up* to a minimum of one share when `gross_amount > 0` so the caller pays for the dust rather than reverting. At minimum, the controller path in `legs.rs` should treat a zero-overlap/zero-burn result as "nothing to settle" instead of propagating the revert.

### Proof of Concept
`contracts/pool/tests/flows.rs:776-820` already demonstrates it: configure a market with `borrow_index = 3*RAY`, positions of `10*RAY` supply/debt, call `net_settle` with `amount = 1` — `resolve_net_settle` returns `settle = 1`, `burned_supply = 1`, `burned_debt = floor(1 / 3) = 0`, and `apply` reverts with `NetSettleRoundsToZeroShares`. The same state reached through `controller.repay_debt_with_collateral` makes the whole user-facing entrypoint revert on the `net_settle_collateral_against_debt` leg.
