### Title
Webhook signature verification keys on `repository.owner.login` while handlers trust `repository.full_name`, allowing cross-tenant stack mutation - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to verify against using `params.dig('repository','owner','login')`, and `Shipit::Repository.from_github_repo_name` later trusts `params.repository.full_name` to resolve the target repository/stack. These are two independently attacker-controlled JSON fields in the same payload with no cross-check that the owner segment of `full_name` matches `repository.owner.login`.

### Finding Description
The broken binding: `repository_owner` (`params.dig('repository','owner','login')`) is asserted to equal the owner segment of `params.dig('repository','full_name')`, but nothing in the code enforces this.

- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner` via `repository_owner` (`app/controllers/shipit/webhooks_controller.rb:59-62`), which reads `params.dig('repository', 'owner', 'login')`, then calls `Shipit.github(organization: repository_owner)` (`lib/shipit.rb:170-181`, `lib/shipit.rb:196-200`) to look up the `GitHubApp`/`webhook_secret` config for that organization and verifies the HMAC signature against it.
- Once verified, `WebhooksController#create` (`app/controllers/shipit/webhooks_controller.rb:10-15`) dispatches to all registered `pull_request` handlers, including `OpenedHandler` (`app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb`), which resolves the target `repository` via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` (`app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:50-53`, `app/models/shipit/repository.rb:53-56`), splitting `full_name` on `/` to get `owner/name` and doing a DB lookup — completely independent of `repository_owner`.

Because the JSON payload is fully attacker-crafted (no live GitHub relay validates internal consistency of the fields), an attacker who legitimately administers an org/repo tracked by Shipit (and therefore knows that org's configured `webhook_secret`) can send a POST to `/webhooks` with:
```json
{
  "action": "opened",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/repo" },
  "pull_request": { ... },
  "sender": { "login": "attacker" }
}
```
signed with `attacker-org`'s real webhook secret. `verify_signature` resolves `Shipit.github(organization: 'attacker-org')`, finds attacker-org's own valid config, and the HMAC check passes because it's computed with attacker-org's real secret over the exact raw body sent. The event then reaches `OpenedHandler#process`, which resolves `repository` using `full_name = "victim-org/repo"` — the victim's real tracked repository — and calls `ReviewStackAdapter#find_or_create!` (`app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:41-46`) against the victim repo's `review_stacks`, potentially creating/mutating a review stack for a repository the attacker never controls or authenticated for.

No existing guard catches this: `verify_signature` only checks the HMAC against attacker-org's own secret (not tied to `full_name`); `drop_unhandled_event` only checks the event type is registered; the `ExplicitParameters` schema in `OpenedHandler` only requires `repository.full_name` be a `String`, with no format/consistency validation against `repository.owner.login`; `Repository.from_github_repo_name` performs a plain DB lookup with no provenance check.

### Impact Explanation
An attacker who legitimately owns one Shipit-tracked org (and thus its webhook secret) can forge `pull_request` (and similarly `closed`, `reopened`, `labeled`, `unlabeled`, `edited`, `assigned` — all handlers under `app/models/shipit/webhooks/handlers/pull_request/` that resolve `repository` via `from_github_repo_name(params.repository.full_name)`) events for ANY other tenant's tracked repository, by simply changing `full_name` in a payload they sign themselves. This is a cross-tenant webhook forgery: a payload authenticated for org A mutates stack/review-stack state for org B (create review stacks, archive them, apply/remove provisioning labels affecting deploy behavior). This matches the "Critical" impact category: a payload for one repository mutating another's stack. It's fully repeatable against any tracked repository whose `owner/name` string the attacker knows (repository names are typically public/guessable).

### Likelihood Explanation
Preconditions: the attacker must control at least one org/repo that is itself legitimately configured in Shipit's multi-org `secrets.github` config (with its own `webhook_secret`) — a normal, low-cost bar in self-service multi-tenant Shipit deployments where teams onboard their own repos. No Shipit session, API token, or victim secrets are needed. The attacker only needs to know the victim's `owner/name` string (public information) and craft a raw HTTP POST with a valid HMAC-SHA1 signature computed from their own known secret. This is trivially repeatable and requires no timing race or privileged access.

### Recommendation
In `WebhooksController#verify_signature`, after signature verification succeeds, assert that `repository_owner` equals the owner segment of `params.dig('repository', 'full_name')` (case-insensitively) before dispatching to handlers; reject (422) on mismatch. Alternatively, have handlers derive the target repository owner exclusively from the same field used for signature verification (`repository.owner.login`) rather than re-parsing `full_name`, or validate that `full_name.split('/').first == repository_owner` inside `Shipit::Repository.from_github_repo_name` callers.

### Proof of Concept
Minitest plan (in `test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure two orgs in test secrets: `attacker-org` (with a known `webhook_secret`, e.g., `"attackersecret"`) and `victim-org` (with a real tracked `Repository` `victim-org/repo` and an associated `review_stacks`-enabled config).
2. Build payload:
```ruby
payload = {
  action: 'opened',
  number: 2,
  pull_request: { id: 1, number: 2, url: 'x', title: 't', state: 'open', additions: 1, deletions: 0,
                   head: { sha: 'abc', ref: 'branch' }, user: { login: 'attacker' }, assignees: [], labels: [] },
  repository: { owner: { login: 'attacker-org' }, full_name: 'victim-org/repo' },
  sender: { login: 'attacker' }
}.to_json
signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', 'attackersecret', payload)}"
```
3. `assert_no_difference -> { Shipit::ReviewStack.count }` (or assert on victim repo's `review_stacks`) while POSTing:
```ruby
@request.headers['X-Github-Event'] = 'pull_request'
@request.headers['X-Hub-Signature'] = signature
post :create, body: payload, as: :json
```
4. Assertion demonstrating the bug (expected to FAIL against current code, proving the vulnerability): assert that `Shipit::Repository.from_github_repo_name('victim-org/repo')` was NOT touched / no review stack was created for `victim-org/repo`, i.e. `repository_owner` (`'attacker-org'`) must equal `full_name.split('/').first` (`'victim-org'`) before any handler runs — currently no such equality check exists, so the request returns `200 OK` and a review stack gets created/mutated for `victim-org/repo` despite being signed only by `attacker-org`'s secret.       github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
