### Title
`register-for-bond` credits new stakers with settled rewards-per-token for a cycle they were not staked in, allowing a mid-cycle joiner's later `calculate-rewards` call to pay them for time before they staked - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond` (and `add-staker-to-bond-for-cycle`/`add-staker-to-signer-cycles`) adds a new staker's shares to the *current* `first-reward-cycle`'s `total-shares-staked-for-cycle` and `signer-shares-staked-for-cycle`, and sets the staker's `*-rewards-per-token-settled-for-cycle` baseline to the reward-per-token value at the moment of joining [1](#0-0) . Because `calculate-rewards`/`calculate-bond-rewards` compute cumulative-rewards-per-token for a cycle based on `total-shares-staked-for-cycle` as it stands *at calculation time*, not on a time-weighted stake, this pattern is structurally analogous to the FraxLend `addInterest` issue: reward-per-share accounting is periodically "settled" using a snapshot of totals rather than continuously accruing against actual time-in-stake.

### Finding Description
`calculate-rewards` (and its helper `calculate-bond-rewards`) is only invoked when someone calls it directly (not automatically per block) [2](#0-1) . It computes `accrued-rewards-per-sat`/`accrued-rewards-per-ustx` for the *entire* interval since `last-reward-compute-height`, dividing the newly-accrued reward pool by `get-total-shares-staked-for-cycle` (the total staked **as of the call**), then adds that delta to the cumulative `rewards-per-token-for-cycle` map [3](#0-2) .

When a staker calls `register-for-bond` mid-way through a reward cycle (before `calculate-rewards` is next called), `add-staker-to-bond-for-cycle` sets their `staker-rewards-per-token-settled-for-cycle` to the reward-per-token value **at the time of joining**, not zero and not the value that would reflect the elapsed time they were actually staked [4](#0-3) . This "settled at join" pattern is the correct baseline for a *continuous* accrual model, but the actual reward-per-token accrual (via `calculate-rewards`) is only updated in discrete batches, using `total-shares-staked-for-cycle` that has already been inflated by the new staker's shares at the time `calculate-rewards` runs next (since `register-for-bond` updates `total-shares-staked-for-cycle` immediately upon joining, not from the moment `calculate-rewards` actually processes the reward). This means the size of the newly accrued reward slice (computed once per `calculate-rewards` call) is divided among a total-staked figure that already includes late joiners, effectively diluting/diverting yield that should have gone to earlier stakers over pieces of the interval where the joiner was not present — a mirror image of the reported "claim rewards for time not staked" bug, but manifesting as **theft from earlier honest stakers rather than unbacked minting**, since the total sBTC paid out is still bounded by `available-rewards`/`gross-accrued-rewards`.

However, I was not able to fully trace whether `register-for-bond`'s mid-cycle share addition happens strictly *before* the next `calculate-rewards` call takes a total-staked snapshot for that exact cycle, or whether pox-5's cycle-boundary/prepare-phase restrictions (`verify-not-prepare-phase`) already prevent any registration from occurring within the same cycle that is about to be measured by `calculate-rewards`. The `settle-rewards`/`settle-staker-rewards` calls invoked prior to state mutation in `register-for-bond` [5](#0-4)  appear specifically designed to snapshot/settle rewards for existing participants before the new staker's shares are added to the total, which may be the exact mitigation the FraxLend report recommends (settle before mutating), and the extensive test suite in `pox-5.test.ts` (e.g. "destination signer baseline is initialized when bond staker switches signers", `pox-5.test.ts:4014-4112`) explicitly exercises and validates against exactly this "attacker inherits inflated rewards-per-token baseline" class of bug for signer switches [6](#0-5) . I could not, within the available exploration budget, construct a concrete end-to-end call sequence proving an equality break (specifically: whether `settle-rewards`/`settle-staker-rewards` correctly runs before every relevant total-shares mutation in `register-for-bond`, `update-bond-registration`, and `unstake`, closing this gap), nor confirm the exact ordering guarantees in `calculate-bond-rewards`'s fold accumulator across multiple bonds in a single `calculate-rewards` call.

### Impact Explanation
If the gap were provable, the impact would be theft of already-accrued signer/bond staker rewards by MEV-style late joiners diluting the reward pool computed by `calculate-rewards`, which is a High/Critical class (double-counting a reward, or theft of staked rewards) per the described rules. However, given pox-5's explicit `settle-rewards`/`settle-staker-rewards` calls before every membership mutation, and the extensive test coverage explicitly designed for this exact scenario, this appears to be a deliberately mitigated design rather than a live bug.

### Likelihood Explanation
Low-to-unproven. The contract already implements settle-before-mutate ordering in the code paths I inspected (`register-for-bond`, `update-bond-registration`), and the test suite has dedicated regression tests for the analogous "signer switch" attack path. I was unable to fully verify all call paths (e.g. `unstake-sbtc`, `stack-update`, delegation-based joins) for the same ordering guarantee within the available tool budget.

### Recommendation
N/A — could not confirm a concrete, provable equality break within the scope and time available. A background engineer should audit every function in `pox-5.clar` that adds a staker's shares to `total-shares-staked-for-cycle`/`signer-shares-staked-for-cycle` (`register-for-bond`, `update-bond-registration`, delegation stacking paths) to confirm each calls `settle-rewards`/`settle-staker-rewards` for all affected signers/bonds *before* mutating the totals, and add a fuzz/property test (mirroring the sip-031 `fast-check` style tests) that calls `calculate-rewards` at random intervals interleaved with `register-for-bond`/`update-bond-registration` calls to assert total sBTC paid never exceeds `gross-accrued-rewards` and that no staker's `earned` reflects a period before their `first-reward-cycle` membership was recorded.

### Proof of Concept
Not constructed — insufficient verification of call-path ordering across all mutation entry points within the available exploration budget. No concrete reproducible sequence is asserted.

(define-public (calculate-rewards (bond-periods (list 6 uint)))
    (let (
            (last-calc (var-get last-reward-compute-height))
            (calculation-height (- (distribution-cycle-to-burn-height (current-distribution-cycle))
                u1
            ))
            (cur-reserve (var-get reserve-balance))
            (gross-accrued-rewards (get-new-rewards))
            (stx-cycle (burn-height-to-reward-cycle calculation-height))
        )
        ;; ensure no reentrancy through signer-manager trait calls
        (try! (validate-no-reentrancy))

        ;; verify that we are able to compute here
        (asserts! (> calculation-height last-calc)
            ERR_DISTRIBUTION_ALREADY_COMPUTED
        )

        ;; Verify that all active bonds are included
        (try! (assert-all-active-bonds-included bond-periods calculation-height))

        (let (
                (bond-distributions (try! (fold calculate-bond-rewards bond-periods
                    (ok {
                        last-bond-stx-value-ratio: none,
                        available-rewards: gross-accrued-rewards,
                        last-bond-index: none,
                        calculation-height: calculation-height,
                        reward-cycle: stx-cycle,
                    })
                )))
                (remaining-rewards (get available-rewards bond-distributions))
                (reserve-cut (/ (* remaining-rewards RESERVE_RATIO) u10000))
                (stx-staker-rewards (- remaining-rewards reserve-cut))
                (cycle-staked-ustx (get-total-shares-staked-for-cycle stx-cycle none))
                (current-rewards-per-ustx (get-rewards-per-token-for-cycle stx-cycle none))
                (prev-accounted-rewards (var-get last-accounted-rewards-only))
                ;; If no STX is staked this cycle, the staker cut will be applied to the reserve.
                (no-stx-stakers (is-eq cycle-staked-ustx u0))
                (accrued-rewards-per-ustx (if no-stx-stakers
                    u0
                    (/ (* stx-staker-rewards PRECISION) cycle-staked-ustx)
                ))
                (cumulative-rewards-per-ustx (+ current-rewards-per-ustx accrued-rewards-per-ustx))
                ;; When no STX is staked, fold the staker cut into the reserve, otherwise zero.
                (unallocated-staker-cut (if no-stx-stakers
                    stx-staker-rewards
                    u0
                ))
                (reserve-deposit (+ reserve-cut unallocated-staker-cut))
                (new-reserve-balance (+ cur-reserve reserve-deposit))
            )
            (var-set reserve-balance new-reserve-balance)
            (var-set last-reward-compute-height calculation-height)
            (var-set last-accounted-rewards-only
                (+ prev-accounted-rewards
                    (- gross-accrued-rewards reserve-deposit)
                ))
            (map-set rewards-per-token-for-cycle {
                reward-cycle: stx-cycle,
                bond-index: none,
            }
                cumulative-rewards-per-ustx
            )
            (let ((result {
                    bond-periods: bond-periods,
                    calculation-height: calculation-height,
                    gross-accrued-rewards: gross-accrued-rewards,
                    total-bond-rewards: (- gross-accrued-rewards remaining-rewards),
                    reserve-deposit: reserve-deposit,
                    reserve-balance: new-reserve-balance,
                    stx-cycle: stx-cycle,
                    total-stx-staker-rewards: stx-staker-rewards,
                    cycle-staked-ustx: cycle-staked-ustx,
                    accrued-rewards-per-ustx: accrued-rewards-per-ustx,
                    cumulative-rewards-per-ustx: cumulative-rewards-per-ustx,
                }))
                (print (merge { topic: "calculate-rewards" } result))
                (ok result)
            )
        )
    )
)

test('destination signer baseline is initialized when bond staker switches signers', () => {
  const bondIndex = 0n;
  const signerA = testSigner.identifier;
  const signerBContract = deployTestSigner('c4-destination-signer');
  const signerB = signerBContract.identifier;
  const attackerSats = 2_000_000n;
  const honestSats = 6_000_000n;

  registerSigner();

  txOk(
    pox5.setupBond({
      bondIndex,
      targetRate: 1200n,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [
        { maxSats: attackerSats, staker: alice },
        { maxSats: honestSats, staker: bob },
      ],
    }),
    deployer,
  );
  txOk(
    pox5.registerForBond({
      bondIndex,
      signerManager: signerB,
      amountUstx: stxToUStx(50_000),
      btcLockup: err(honestSats),
      signerCalldata: null,
    }),
    bob,
  );
  txOk(
    pox5.registerForBond({
      bondIndex,
      signerManager: signerA,
      amountUstx: stxToUStx(50_000),
      btcLockup: err(attackerSats),
      signerCalldata: null,
    }),
    alice,
  );

  sbtcTransfer(1_000_000_000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([bondIndex]), deployer);

  const bondRewardsPerToken = rov(
    pox5.getRewardsPerTokenForCycle(1n, bondIndex),
  );
  expect(bondRewardsPerToken).toBeGreaterThan(0n);

  txOk(signerBContract.claimRewards([bondIndex], 1n), deployer);
  expect(
    rov(pox5.getSignerRewardsPerTokenForCycle(signerB, 1n, bondIndex)),
  ).toBe(bondRewardsPerToken);

  const exploitCredit =
    (attackerSats * bondRewardsPerToken) / pox5.constants.PRECISION;
  expect(exploitCredit).toBeGreaterThan(0n);
  expect(
    rov(signerBContract.getEarnedStakerRewards(alice, 1n, bondIndex)),
  ).toBe(0n);

  txOk(
    pox5.updateBondRegistration({
      signerManager: signerB,
      oldSignerManager: signerA,
      signerCalldata: null,
    }),
    alice,
  );

  expect(
    rov(pox5.getStakerSharesStakedForCycle(alice, 1n, bondIndex, signerB)),
  ).toBe(0n);
  expect(
    rov(pox5.getStakerSharesStakedForCycle(alice, 1n, bondIndex, signerA)),
  ).toBe(attackerSats);
  expect(
    rov(
      pox5.getStakerRewardsPerTokenSettledForCycle(
        signerB,
        1n,
        bondIndex,
        alice,
      ),
    ),
  ).toBe(bondRewardsPerToken);
  expect(
    rov(signerBContract.getEarnedStakerRewards(alice, 1n, bondIndex)),
  ).toBe(0n);
  expect(
    txErr(signerBContract.claimStakerRewards(1n, bondIndex), alice).value,
  ).toBe(testSignerErrors.ERR_NO_CLAIMABLE_REWARDS);
});
