### Title
Unbounded index-scaled market value can permanently freeze a pool market - (File: common/src/rates/simulate.rs)

### Summary
A market whose scaled debt or supply value exceeds `i128::MAX` makes every subsequent market operation revert during mandatory interest accrual. An unprivileged attacker can create the prerequisite position through ordinary `supply` and `borrow` flows when asset supply and configured caps are sufficiently large; once the index grows enough, permissionless `update_indexes` triggers the irrecoverable overflow.

### Finding Description
Every pool mutation loads the market and calls `interest::global_sync` before applying the operation. [1](#0-0)  `global_sync` invokes `accrue_step`, which computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` before updating either index. [2](#0-1) [3](#0-2)  `scaled_to_original` performs a checked fixed-point multiplication and raises `MathOverflow` when the represented market value no longer fits `i128`. [4](#0-3) [5](#0-4) 

The borrow-index cap does not prevent this condition because the panic occurs while calculating current debt value, before the new capped index is committed. [6](#0-5)  The repository’s production harness demonstrates that a one-billion-whole-token, 18-decimal market at 98% utilization reaches the value ceiling before `MAX_BORROW_INDEX_RAY`, after which `update_indexes`, `withdraw`, and `repay` all return `MathOverflow`. [7](#0-6) 

### Impact Explanation
This permanently freezes all funds associated with the affected `(hub_id, asset)` market. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, revenue cannot be claimed, and maintenance accrual cannot complete because each path performs accrual before its state mutation. [2](#0-1) [8](#0-7)  The failed call does not advance `last_timestamp`, so subsequent calls repeat the same overflowing accrual rather than skipping or repairing it. [9](#0-8) 

### Likelihood Explanation
The attack is permissionless but capital-intensive and conditional on a listed asset having enough circulating supply and configured caps to approach the `i128` RAY-value domain. An attacker can fund supplier and borrower accounts under their control, build a high-utilization position through the normal `supply` and `borrow` entrypoints, and later call `update_indexes(caller, vec![hub_asset])`; `update_indexes` requires only caller authorization. [10](#0-9)  The required scale makes exploitation impractical for ordinary capped markets, but the accepted asset-decimal domain and market caps allow the state where an extremely high-decimal or high-supply asset is listed. [11](#0-10) 

### Recommendation
Prevent accrual from evaluating an unrepresentable aggregate value. In `common/src/rates/simulate.rs::accrue_step`, calculate utilization using a widened `I256` ratio or a saturating debt/supply-value representation, and cap the resulting rate or index before converting back to `i128`. Market caps should also enforce the stricter bound `scaled_shares * max_index <= i128::MAX`, rather than only the initial asset-unit domain. Add a regression test that demonstrates `update_indexes`, repayment, withdrawal, and liquidation remain callable after the market reaches the configured index ceiling.

### Proof of Concept
1. Using one unprivileged address controlling two accounts, call controller `supply` to fund one account with `hub_asset = {hub_id: H, asset: A}` and a large amount near the configured cap, then supply sufficient collateral in another listed asset to a second account.
2. Call controller `borrow` for `{hub_id: H, asset: A}` with an amount that leaves utilization near the market’s maximum.
3. Allow interest to accrue until either `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY` exceeds `i128::MAX`.
4. Submit `controller.update_indexes(caller, vec![HubAssetKey { hub_id: H, asset: A }])`. The controller forwards the market to pool `update_indexes`, whose accrual calls `accrue_step`; the `scaled_to_original` multiplication overflows and returns `MathOverflow`. [12](#0-11) [13](#0-12) [14](#0-13) 
5. Subsequent `withdraw`, `repay`, `liquidate`, `claim_revenue`, and `recapitalize` attempts against the same market all re-enter the same accrual and revert before changing state. [1](#0-0)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
