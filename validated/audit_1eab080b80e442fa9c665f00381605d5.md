### Title
`ProxyType::NonTransfer` falsely declares itself a superset of `ProxyType::Auction`, letting a NonTransfer proxy self-grant the `Auction` proxy type and reach `Registrar::swap`, which `NonTransfer` deliberately excludes - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
The Westend relay-chain runtime's `InstanceFilter<RuntimeCall> for ProxyType::is_superset` unconditionally treats `NonTransfer` as a superset of every other `ProxyType`, including `Auction`. However `NonTransfer`'s `filter()` explicitly and intentionally omits `Registrar::swap` (per the inline comment `// Specifically omitting Registrar \`swap\``), while `Auction`'s `filter()` admits the entire `Registrar(..)` call family, including `swap`. Because `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` solely on `is_superset` and not on the actual `filter`, a delegate holding only a `NonTransfer` proxy can add itself (or another controlled account) as an `Auction` proxy for the delegator, then invoke `Registrar::swap` on the delegator's behalf — a call the delegator's `NonTransfer` grant was specifically designed to forbid. [1](#0-0) [2](#0-1) [3](#0-2) 

This is structurally identical to a bug class already found and fixed in this same codebase for Asset Hub Westend: `NonTransfer` falsely claimed to be a superset of `Governance`, letting a `NonTransfer` proxy add itself as a `Governance` proxy and reach `Treasury`/`ConvictionVoting`/`Referenda`/`Whitelist` calls that `NonTransfer` denied (fixed in `prdoc/pr_12769.prdoc`, with regression tests `non_transfer_proxy_is_not_a_superset_of_governance` and the general lattice test `proxy_type_superset_relation_matches_call_filters` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs`). [4](#0-3) [5](#0-4) 

No equivalent fix or lattice-consistency test exists for the relay-chain runtimes (`polkadot/runtime/westend/src/lib.rs`, and the same pattern appears with the identical comment `// Specifically omitting Registrar \`swap\`` in `polkadot/runtime/rococo/src/lib.rs` and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`). [6](#0-5) 

### Finding Description
`pallet_proxy::Pallet::do_proxy` installs a call filter on the inner dispatch that specifically blocks `add_proxy`/`remove_proxy` unless the acting proxy's `ProxyType` `is_superset` of the target `proxy_type` being granted/removed — it does **not** re-check the target type's `filter()` against the acting type's `filter()`: [7](#0-6) 

For Westend, `ProxyType::is_superset` is defined generically as: any type equals itself, `Any` is superset of everything, and `NonTransfer` is superset of everything else (the `_ => false` catch-all), with no per-pair validation: [8](#0-7) 

But `NonTransfer`'s actual `filter()` explicitly permits only `Registrar::register`, `Registrar::deregister`, and `Registrar::reserve`, with an inline comment noting `swap` is intentionally omitted: [9](#0-8) 

Meanwhile `ProxyType::Auction`'s `filter()` matches `RuntimeCall::Registrar(..)` unconditionally — i.e. it admits every Registrar call including `swap`: [10](#0-9) 

The invariant that is violated is the same one that governs `pallet_proxy`'s lattice: "if type A declares itself a superset of type B, A's filter must admit every call B's filter admits." Because `NonTransfer.is_superset(Auction) == true` while `NonTransfer.filter` denies `Registrar::swap` and `Auction.filter` admits it, a `NonTransfer`-restricted delegate can escalate: it uses its existing `NonTransfer` proxy right to call `Proxy::add_proxy { delegate: <itself or another account>, proxy_type: Auction, delay: 0 }` on behalf of the real account (this passes the `do_proxy` filter check because `is_superset` returns `true`), then separately calls `Proxy::proxy` using the newly-granted `Auction` type to dispatch `Registrar::swap` on behalf of the real account — a capability its original `NonTransfer` grant was designed to withhold.

I was unable to fully verify within the available tool budget whether `Registrar::swap`'s own dispatch-time origin check (e.g. requiring the caller to be a specific para manager) would independently prevent misuse beyond what the real account could already do itself; the pallet source (`polkadot/runtime/common/src/paras_registrar/mod.rs`) was not fully inspected for this call's internal authorization logic in this pass. This uncertainty affects how severe the practical impact is, but the authorization-model violation itself (mismatched `is_superset`/`filter` on a live proxy type in a shipped runtime) is concretely demonstrated and matches the exact bug class already confirmed and remediated elsewhere in this repository.

### Impact Explanation
If `Registrar::swap` relies only on the dispatching account being a para manager (checked against the "real" account identity, which is preserved through `pallet_proxy`'s origin substitution), then this bug lets a proxy holder that was only ever trusted with "non-transfer, non-swap" permissions perform a parachain-ID/deregistration-adjacent `swap` operation on behalf of the delegator without that delegator's explicit consent for that specific action — exactly the kind of unintended-permission escalation the already-merged `prdoc/pr_12769.prdoc` fix for Asset Hub Westend was designed to close for the `Governance` pair. Given the analogous fix was rated worth a runtime patch bump for a similarly narrow call surface, this would likely be assessed as Medium under the same rationale (unauthorized-but-bounded dispatch of a specific, deliberately-excluded call family through the proxy escalation path), matching the CVE's "developer role able to reach a protected resource via an indirect/misconfigured permission path" pattern.

### Likelihood Explanation
Likelihood is Medium: it requires only a legitimate `NonTransfer` proxy relationship (no privileged role, no governance, no stolen keys) and two ordinary signed extrinsics (`Proxy::add_proxy` via the existing `NonTransfer` proxy, then `Proxy::proxy` with `force_proxy_type: Auction`). No unbounded loops, no economic/front-running elements, and no dependency-only or mock-only artifacts are involved — it is a pure runtime-configuration logic gap identical in shape to the confirmed and fixed `prdoc/pr_12769` case, just on an un-patched pair (`NonTransfer`/`Auction`) and un-patched runtime (Westend/Rococo relay chain and the staking-async rc runtime), each still containing the tell-tale "Specifically omitting Registrar `swap`" comment with no matching `is_superset` restriction.

### Recommendation
Change `ProxyType::is_superset` for these runtimes to stop treating `NonTransfer` as an unconditional superset of every other type, or explicitly special-case `Auction` (and any other type whose filter is a strict superset of what `NonTransfer` allows for the same call families) to return `false`, mirroring the fix applied in `prdoc/pr_12769.prdoc`. Add the same kind of lattice-consistency regression test used in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs` (`proxy_type_superset_relation_matches_call_filters`) to the relay-chain runtimes (`polkadot/runtime/westend`, `polkadot/runtime/rococo`) and to `substrate/frame/staking-async/runtimes/rc` to prevent this bug class from recurring on any other `ProxyType` pair.

### Proof of Concept
Reproduction sketch using the existing `pallet_proxy` test harness pattern (as used in `substrate/frame/proxy/src/tests.rs`), adapted to the Westend runtime's `ProxyType`:
1. Delegator `real` calls `Proxy::add_proxy(origin: signed(real), delegate: attacker, proxy_type: ProxyType::NonTransfer, delay: 0)`. This is a normal, unprivileged setup step.
2. Attacker calls `Proxy::proxy(origin: signed(attacker), real, force_proxy_type: Some(ProxyType::NonTransfer), call: Proxy::add_proxy { delegate: attacker, proxy_type: ProxyType::Auction, delay: 0 })`. Expected (if the bug is present): this succeeds, because `do_proxy`'s inner filter only checks `NonTransfer.is_superset(Auction)`, which evaluates to `true` per `polkadot/runtime/westend/src/lib.rs:1027`, even though `NonTransfer.filter(&Registrar::swap{..})` is `false`.
3. Attacker now calls `Proxy::proxy(origin: signed(attacker), real, force_proxy_type: Some(ProxyType::Auction), call: Registrar::swap { .. })`. Expected: this succeeds because `Auction.filter` admits all `Registrar(..)` calls, dispatching `Registrar::swap` as `real`, despite `real` never having granted the attacker the `Auction`-level trust nor the `swap` capability directly.
4. Assert: `real`'s stored `Proxies` now contains an `Auction`-type entry for `attacker` that `real` never explicitly authorized, and `Registrar::swap` executed under `real`'s identity via a `NonTransfer`-only delegate.

I did not execute this against a live network or a local test harness in this pass (no code-execution tool was invoked here); the failed-guard evidence is derived directly from reading the `is_superset`/`filter` implementations and the `do_proxy` gating logic cited above, following the same reasoning already validated and merged as a fix for the equivalent Asset Hub Westend case (`prdoc/pr_12769.prdoc`). A background Devin session with Rust/cargo access would be needed to run the exact `#[test]` reproduction against `polkadot/runtime/westend` (or an equivalent mock) and confirm the `assert_ok!` sequence above.

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
