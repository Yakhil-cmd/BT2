### Title
Cross-organization webhook forgery via decoupled signature-org lookup and payload repository binding - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
### Finding Description
`WebhooksController#verify_signature` selects which GitHub App configuration (and thus which `webhook_secret`) to verify the HMAC signature against using `repository_owner`, computed as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) . This value comes straight out of the attacker-controlled JSON body, with no cryptographic binding yet at that point (the signature hasn't been checked). Once verification passes, `WebhooksController#create` dispatches the *entire raw payload* to handlers such as `PushHandler`, which look up the target repository/stack using a **different** field of the same payload: `payload.dig('repository', 'full_name')` in `Handler#repository_name` (and directly in each `PullRequest::*Handler`) [2](#0-1) .

`Shipit.github(organization:)` supports multiple independently configured GitHub Apps/organizations, each with its own optional `webhook_secret` [3](#0-2) . Critically, `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that organization's `webhook_secret` is blank: `return true unless webhook_secret` [4](#0-3) . The setup docs explicitly describe the webhook secret as "(optional)" [5](#0-4) , so a real, supported multi-org Shipit deployment can have one organization configured without a webhook secret while other organizations it also serves are configured with one (see the double-app config fixture using per-org `webhook_secret` keys) [6](#0-5) .

This breaks the intended binding: `organization authenticated by verify_signature == organization whose repository/stack is written by the handler`. An attacker can craft a webhook body where `repository.owner.login` (and/or top-level `organization.login`) names the no-secret organization — causing `verify_signature` to pass unconditionally — while `repository.full_name` names a *different*, secret-protected organization's repository that Shipit actually tracks. Because handlers resolve the target purely from `repository.full_name` via `Repository.from_github_repo_name` [7](#0-6) , the forged event is accepted and acted upon against the victim organization's stack.

### Impact Explanation
Via `PushHandler`, this lets an attacker trigger `stack.sync_github(expected_head_sha:)` on an arbitrary tracked stack belonging to the secret-protected org, without ever possessing that org's real webhook secret [8](#0-7) . Depending on which handlers are registered (`push`, `pull_request`, `membership`, `status`, `check_suite`), this can desynchronize commit state, spuriously archive/unarchive review stacks, or otherwise manipulate deploy-relevant metadata for a repository the attacker does not control — i.e., cross-repository/cross-organization state manipulation driven by a forged, effectively unauthenticated request. This lands in the "cross-repository writes" / unauthorized-action impact tier since the write target is decoupled from the entity whose credential was checked.

### Likelihood Explanation
This requires a Shipit deployment configured for multiple GitHub organizations where at least one has no `webhook_secret` set (an explicitly documented, supported, "optional" configuration) while also tracking repositories from at least one other, secret-protected organization. Given webhook secrets are optional and the setup guide does not force them, this is a realistic operational configuration, and exploitation needs only crafting one HTTP POST with attacker-chosen JSON fields — no privileged credentials required.

### Recommendation
Bind the signature-verification identity to the same field the handlers act on: verify using the organization/owner parsed from `repository.full_name` (or reject payloads where `repository.owner.login` and the owner segment of `repository.full_name` disagree). Additionally, consider requiring `webhook_secret` to be present for all configured organizations (fail closed) rather than allowing silent bypass when it is blank.

### Proof of Concept
1. Deploy Shipit configured with two orgs: `OrgA` (no `webhook_secret`) and `OrgB` (`webhook_secret: s3cr3t`), each with tracked repositories, matching the supported multi-org schema shown in `test/dummy/config/secrets_double_github_app.yml`.
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" }
}
```
No valid `X-Hub-Signature` for `OrgB`'s secret is supplied/needed.
3. `verify_signature` resolves `repository_owner` = `"OrgA"`, looks up `Shipit.github(organization: "OrgA")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` and the request proceeds.
4. `PushHandler` resolves the target via `repository.full_name` = `"OrgB/victim-repo"`, finds `OrgB`'s tracked stack, and calls `stack.sync_github(expected_head_sha: "deadbeef")` — a forged event accepted and acted on for `OrgB`'s repository despite never validating against `OrgB`'s webhook secret.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

        def process
          stacks

            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end
