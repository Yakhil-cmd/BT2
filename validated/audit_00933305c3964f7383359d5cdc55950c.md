### Title
Deregistered Bridge Operator's Votes Persist and Can Execute Unauthorized Value Transfers — (`contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`BridgeOperator.deregisterOperator` removes an operator from the active set but does not clear that operator's outstanding votes from the `votes` mapping. A deregistered operator's prior vote can still be counted toward the threshold in a subsequent `_voteValueTransfer` call, allowing a bridge value transfer (KAIA, ERC20, or ERC721) to execute with authority that has already been revoked.

---

### Finding Description

`deregisterOperator` removes the operator from `operators[_operator]` and `operatorList`, but leaves their entries in `votes[VoteType.ValueTransfer][nonce].voted` and `votes[VoteType.ValueTransfer][nonce].voteCounts` completely intact. [1](#0-0) 

`_voteCommon` tallies votes purely from the stored `voteCounts` map, with no check that each counted voter is still a registered operator at the time the threshold is evaluated. [2](#0-1) 

`_voteValueTransfer` calls `_voteCommon` and, when the threshold is met, marks the nonce closed and returns `true`, triggering the actual asset transfer in callers such as `handleKLAYTransfer`. [3](#0-2) [4](#0-3) 

The code itself documents the scenario in a comment but treats it as an operator-education issue rather than fixing it: [5](#0-4) 

---

### Impact Explanation

The corrupted value is the execution of a bridge value transfer (KAIA, ERC20, or ERC721) that is authorized in part by a vote from an operator whose authority has already been revoked. This is an **unauthorized transfer of bridged assets**: the owner's explicit act of deregistering an operator to stop or prevent a transfer has no effect on votes already cast. Assets locked in the bridge contract can be drained to an attacker-controlled address on the counterpart chain.

---

### Likelihood Explanation

The sequence is reachable without majority-validator collusion and without any privileged action by the attacker:

1. Operator A (attacker or compromised key) calls `handleKLAYTransfer` / `handleERC20Transfer` with a fraudulent `_to` address, casting a vote on nonce N.
2. The bridge owner discovers the fraud and calls `deregisterOperator(A)` to revoke A's authority.
3. Any remaining registered operator B calls the same handle function for nonce N (e.g., during normal recovery or because B is also compromised). A's vote count is still present; the threshold is met; the fraudulent transfer executes.

The attacker's only required action (step 1) is a normal operator call, which is a valid semi-trusted trigger. The owner's remediation action (step 2) is ineffective.

---

### Recommendation

In `deregisterOperator`, iterate over all open nonces and delete the deregistered operator's vote entry, decrementing the corresponding `voteCounts`:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    delete operators[_operator];

    // Revoke outstanding ValueTransfer votes by the deregistered operator.
    // Iterate over all open (non-closed) nonces tracked in the pending pool,
    // or maintain a per-operator list of voted nonces for O(1) cleanup.
    for (uint64 n = lowerHandleNonce; n <= upperHandleNonce; n++) {
        if (closedValueTransferVotes[n]) continue;
        VotesData storage vd = votes[uint8(VoteType.ValueTransfer)][n];
        bytes32 key = vd.voted[_operator];
        if (key != bytes32(0)) {
            vd.voteCounts[key]--;
            delete vd.voted[_operator];
        }
    }

    // Remove from operatorList (existing logic) ...
    emit OperatorDeregistered(_operator);
}
```

Alternatively, store a per-operator list of voted nonces to avoid the loop cost.

### Proof of Concept

```
Setup: threshold = 2, operators = [owner, A, B]

1. Operator A calls handleKLAYTransfer(txhash, victim, attacker, value, nonce=5, ...)
   → votes[ValueTransfer][5].voteCounts[key] = 1
   → closedValueTransferVotes[5] = false

2. Owner calls deregisterOperator(A)
   → operators[A] = false
   → votes[ValueTransfer][5] is UNCHANGED; voteCounts[key] still = 1

3. Operator B calls handleKLAYTransfer(txhash, victim, attacker, value, nonce=5, ...)
   → _voteCommon: voteCounts[key] becomes 2 >= threshold(2) → returns true
   → closedValueTransferVotes[5] = true
   → _to.call.value(value)("") executes → attacker receives bridged KAIA

Result: bridge transfer executed with A's deregistered vote counting,
        owner's deregistration had zero effect on the in-flight vote.
``` [6](#0-5) [4](#0-3)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // _voteValueTransfer votes value transfer transaction with the operator.
    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }
