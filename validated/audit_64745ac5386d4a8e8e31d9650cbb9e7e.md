### Title
`flash_position` mints the same strategy debt as `multiply`/`swap_debt` but skips the strategy origination fee, letting any user bypass protocol revenue - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
XOXNO Lending charges a `flashloan_fee`-denominated origination fee when strategy debt is opened via `multiply` or `swap_debt` (`charge_fee = true`), but the `flash_position` entrypoint opens an economically identical leveraged position through `pool_create_strategy_call` with `charge_fee = false`. Any unprivileged caller with a self-deployed `execute_flash_position` receiver can route every leveraged open through `flash_position`, permanently avoiding the fee. The loss accrues to protocol revenue on every strategy open. The codebase itself demonstrates parity: `tests/test-harness/tests/strategy_origination_fee_parity.rs` shows `flash_position` produces more collateral for the same debt precisely because no fee is withheld.

### Finding Description
`contracts/pool/src/ops/strategy.rs` gates fee collection entirely on a `charge_fee` flag:

- `compute_fee` returns `Bps::from(flashloan_fee).flash_loan_fee_on(amount)` only when `charge_fee` is true; otherwise it returns 0 (`contracts/pool/src/ops/strategy.rs:94-101`).
- `accounting` mints full debt for `action.amount` but only withholds `fee` from the payout, booking it via `interest::add_protocol_revenue` (`contracts/pool/src/ops/strategy.rs:58-88`).

On the controller side:

- `multiply` and `swap_debt` call `pool_create_strategy_call(..., charge_fee = true)`, so the protocol collects the origination fee.
- `process_flash_position` (`contracts/controller/src/strategies/flash_position.rs:40-169`) mints debt via the same `create_strategy` pool path but passes `charge_fee = false` (confirmed by the hardcoded `fee: 0` in `FlashPositionEvent` at line 164) and by the doc comment "Mints `amount` of `debt` without a flash fee" in `contracts/controller/src/lib.rs:182`.

Both paths end at the same `strategy_finalize` solvency checks and produce the same final state (new debt + new measured collateral on a Multiply/Long/Short account). The only difference a user observes is that `flash_position` requires deploying a Wasm receiver that pushes collateral to the controller, whereas `multiply` routes through the aggregator — no privilege, approval, or allowlist gates the fee-free path (`require_authorized_caller` + `require_wasm_receiver` only, flash_position.rs:45-69).

The internal parity test quantifies this: for 1.0 ETH of strategy debt, `multiply` books `flashloan_fee` bps of revenue while `flash_position` books 0, and the fee-free route ends with strictly more collateral for identical debt (`tests/test-harness/tests/strategy_origination_fee_parity.rs:96-131`).

### Impact Explanation
Every leveraged position opened via `flash_position` instead of `multiply`/`swap_debt` deprives the protocol of `flashloan_fee` bps on the full debt notional — revenue that is booked into `revenue` shares and ultimately claimable via `claim_revenue`. At the configured cap (`MAX_FLASHLOAN_FEE_BPS = 500`, 5%) this is a material, repeatable loss of unclaimed protocol yield on the primary leveraged-flow entrypoint. Since the bypassed fee is the protocol's revenue stream, this maps to "theft of unclaimed yield" — the yield is simply never created.

### Likelihood Explanation
Any user can trigger it on every position open: deploy a trivial receiver implementing `execute_flash_position` that swaps the minted debt token (on their own Aquarius/Soroswap route, which is in scope as "own flash receiver or swap route") and transfers the proceeds to the controller, then call `flash_position` with `account_id = 0`. There is no per-use cost beyond the receiver deployment, so rational users always prefer it over `multiply` whenever the debt market is `is_flashloanable`. Whether the fee-free minting is intentional mirrors the audited precedent exactly (clubs "intended" not to charge royalties was still ruled a valid medium because EIP-2981-consistent marketplaces lose the protocol yield); here `multiply`'s fee is the analog of the player royalty and `flash_position` is the club sale — an equivalent transfer of economic exposure that skips it. Note the docs do state `flash_position` borrows fee-free (`skills/xoxno-lending/math.md:464`), so sponsors may argue design intent — but the same argument was rejected for Footium since the inconsistency loses protocol revenue either way.

### Recommendation
Charge `charge_fee = true` in `flash_position`'s `pool_create_strategy_call` path so strategy origination fees are consistent across `multiply`, `swap_debt`, and `flash_position`, or withhold the fee from `amount_received` inside `mint_and_forward` so the receiver still gets the fee-adjusted amount and `fee` is reported nonzero in `FlashPositionEvent`.

### Proof of Concept
1. Alice deploys a Wasm contract `R` implementing `execute_flash_position(env, initiator, account_id, asset, amount, fee, amount_received, controller, data)`. In the callback, `R` swaps `amount_received` of the debt asset to the collateral asset on Aquarius and calls `token::Client::transfer(R, controller, swapped)` for the collateral token.
2. Alice calls `controller.flash_position(caller=alice, account_id=0, spoke_id=S, mode=Multiply, debt=(hub, USDC), amount=X, receiver=R, data=..., collaterals=[(hub, XLM) with min>0], refund_assets=[USDC])`. Requires only the USDC market's `is_flashloanable` flag.
3. Pool mints `X` USDC debt to the account with `charge_fee=false`: `compute_fee` returns 0, `debit_cash(X)` (not `X - fee`), and `interest::add_protocol_revenue` receives a zero-valued fee.
4. Account ends with X debt + deposited collateral, passing `strategy_finalize`. Compare against `multiply` with identical debt: `multiply` books `X * flashloan_fee / 10_000` into protocol revenue; `flash_position` books 0. Repeat for every open → systematic fee loss, matching the parity assertion `fp_revenue == 0` vs `mul_revenue == expected_fee` in `strategy_origination_fee_parity.rs:114-122`.
