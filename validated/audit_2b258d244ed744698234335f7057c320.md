### Title
Webhook signature check authenticates the JSON's `repository.owner.login`/`organization.login` while the event handlers act on the independent `repository.full_name` field, allowing cross-repository forged pushes when an org has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GithubApp` (and thus which HMAC secret) to validate the raw POST body against using `repository_owner`, which is read from `params.dig('repository','owner','login')` with a fallback to `params.dig('organization','login')` [1](#0-0) . However, `GithubApp#verify_webhook_signature` returns `true` unconditionally whenever that organization has no `webhook_secret` configured: `return true unless webhook_secret` [2](#0-1) . `webhook_secret` is documented and shipped as optional/nilable per-organization [3](#0-2) , and multiple example/test configs set it to `null`/`nil` [4](#0-3) [5](#0-4) .

Once the (possibly vacuous) signature check passes, the actual event handlers never re-check `repository.owner.login`; instead they resolve the target Stack/Repository from a *different*, independently-controlled field, `repository.full_name`: `Handler#repository_name` reads `payload.dig('repository','full_name')` and `stacks` looks it up via `Repository.from_github_repo_name(repository_name)` [6](#0-5) . `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` on whatever stack matches that `full_name` [7](#0-6) .

### Finding Description
The engine binds authentication to the field `repository.owner.login`/`organization.login` (used to pick the `GithubApp`/secret) but binds the mutating action to the field `repository.full_name` (used to pick the `Stack`/`Repository` acted on). Both fields live in the same attacker-supplied JSON body of an unauthenticated `POST /webhooks` request, and are never cross-checked against each other. When at least one configured GitHub organization in `Shipit.github` has no `webhook_secret` (an explicitly supported, documented configuration), `verify_webhook_signature` short-circuits to `true` for any payload whose `repository.owner.login` (or `organization.login`) names that organization — with no cryptographic proof of origin at all.

This breaks the intended equality:
`organization that authenticated == organization owning the repository that is written`

An attacker can set `repository.owner.login` to the no-secret organization (satisfying authentication) while setting `repository.full_name` to any other tracked `owner/repo` in the Shipit installation (satisfying the write target lookup), even one belonging to a completely different, fully-secured GitHub organization.

### Impact Explanation
This allows an unauthenticated, unprivileged internet client (no Shipit session, no `ApiClient` token, no `webhook_secret`, no GitHub App private key, no repository write access) to forge a `push` webhook for a stack it has no relationship to, supplying an attacker-chosen `after` SHA. `PushHandler` queues `GithubSyncJob` with that SHA for the targeted stack [8](#0-7) , which on continuous-deployment-enabled stacks can trigger an unauthorized deploy/rollback of an attacker-chosen commit on a repository/organization the attacker was never authenticated for — an "unauthorized deploy," which is an explicitly in-scope Critical-class impact.

### Likelihood Explanation
Likelihood is High: no secrets, sessions, or tokens are required — only knowledge that some organization configured in the target Shipit instance omits `webhook_secret` (an officially "optional" setting per `docs/setup.md`), plus the target's `owner/full_name` naming, both of which are either guessable/public GitHub metadata or discoverable via the Shipit UI/API for tracked stacks.

### Recommendation
Bind webhook authentication and target-resolution to the same value. Concretely, after selecting `github_app` via `repository_owner` and verifying the signature, re-validate that `repository.full_name`'s owner segment matches the same `repository_owner`/organization used for signature verification, rejecting the request otherwise. Alternatively, require `webhook_secret` to always be present in production configurations and refuse to boot/verify when absent, removing the `return true unless webhook_secret` bypass entirely, or route repository resolution through the same GithubApp object used for authentication (i.e., only allow handlers to act on repositories confirmed to belong to the authenticated organization/installation).

### Proof of Concept
1. Configure (or target a Shipit instance configured with) a GitHub organization in `secrets.yml` that has `webhook_secret: nil` (the documented default/optional value), e.g. organization `no-secret-org`.
2. Ensure Shipit already tracks a victim stack for repository `victim-org/victim-repo` with continuous deployment enabled.
3. Send, with no signature header required:
```
POST /webhooks
X-Github-Event: push
Content-Type: application/json

{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "no-secret-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
4. `verify_signature` resolves `repository_owner` = `"no-secret-org"`, fetches its `GithubApp`, and `verify_webhook_signature` returns `true` unconditionally because that org has no `webhook_secret` [2](#0-1) .
5. `PushHandler` ignores `repository.owner.login` entirely and looks up the target stack via `repository.full_name = "victim-org/victim-repo"` [6](#0-5) , then queues a sync/deploy for that unrelated victim stack with the attacker's chosen `after` SHA [8](#0-7) .

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
