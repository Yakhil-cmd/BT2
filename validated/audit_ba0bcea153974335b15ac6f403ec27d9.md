### Title
Path traversal in `gh release download` via unsanitized release asset name allows writing files outside the destination directory - (File: `pkg/cmd/release/download/download.go`)

### Summary
`gh release download` builds the on-disk file path for each release asset directly from the asset's `name` field returned by the GitHub API, without sanitizing it with `filepath.Base()` or otherwise rejecting path-traversal sequences. Any user who can create a release/asset on a repository (e.g. via the REST API's `name` upload parameter, which is not restricted to a bare filename) can name an asset `../../../../some/path/evil`, and when a victim runs `gh release download` against that release, the file is written outside the requested `--dir`/current directory.

### Finding Description
In `downloadRun`, each asset's `Name` is copied verbatim into a `downloadTarget.name`: [1](#0-0) 

That `name` is then passed to `downloadAsset`, which calls `dest.Check(fileName)` and ultimately `dest.Copy(fileName, resp.Body)`: [2](#0-1) [3](#0-2) 

Both `Check` and `Copy` resolve the destination path via `makePath`, which simply does `filepath.Join(w.dir, name)` with no traversal protection: [4](#0-3) [5](#0-4) 

`filepath.Join` performs `Clean`, which resolves `..` segments rather than rejecting them, so a name such as `../../../../tmp/evil` (or an absolute path) will happily escape the intended download directory. Contrast this with the archive-filename path a few lines above, which explicitly hardens the *same* code path by taking `filepath.Base(serverFileName)` of the `Content-Disposition` filename before use: [6](#0-5) 

That defensive `filepath.Base()` call is conspicuously absent for the normal (non-archive) per-asset `Name` field, which is attacker-influenceable: GitHub's release-asset upload API accepts a `name` parameter that is not required to be a bare filename, so any user able to publish a release/asset (which is a much lower privilege bar than the `RECOVERY_ROLE` in the reference report, but analogous in spirit — a party with limited/legitimate publish rights abuses an unchecked "destination" value to affect a different, unintended target) can set a traversal payload as the asset name.

This mirrors the reference bug class: a caller supplies a value that is trusted to determine *where output lands* (`to` address in the Sherlock finding vs. destination file path here) without adequate restriction, letting the caller redirect the operation's effect outside the intended scope.

### Impact Explanation
A victim running `gh release download <tag>` (or without pattern/archive flags, whichever downloads all assets) against a release containing a maliciously-named asset can have arbitrary files written outside the specified `--dir`/current working directory, up to overwriting files the running user has write access to (e.g. dotfiles, shell profiles, cron files, `authorized_keys`), which can lead to code execution or persistence on the victim's machine — a concrete "file write outside the intended path" outcome.

### Likelihood Explanation
Any GitHub user capable of creating a release (in their own repo, or a repo where they have push/release privileges) can set an arbitrary asset `name` via the REST API, then simply advertise/link that release for others to download with `gh release download`. This requires no special access to the victim's machine or account — only that the victim run the download command against the attacker's repository/release, which is the CLI's documented ordinary use case.

### Recommendation
Sanitize every user/API-supplied filename before joining it into a destination path, consistently with the treatment already given to `Content-Disposition` filenames:
- Apply `filepath.Base(name)` (or the `safepaths`/`internal/zip` traversal-safe join helpers already present elsewhere in this codebase, e.g. `internal/safepaths.Absolute.Join`) to the asset `Name` in `downloadAsset`/`destinationWriter.makePath` before building the destination path.
- Reject or strip path separators and `..` segments, and reject absolute paths, from asset names prior to writing. [7](#0-6) 

### Proof of Concept
1. Attacker creates (or has push access to) a public repository and a release, uploading an asset with the API `name` parameter set to `../../../../tmp/pwned` (or a Windows-style traversal on Windows), e.g.:
   `POST /repos/OWNER/REPO/releases/{id}/assets?name=..%2F..%2F..%2F..%2Ftmp%2Fpwned`
2. Victim runs:
   `gh release download v1.0.0 -R OWNER/REPO`
3. `downloadRun` enumerates `release.Assets`, builds `downloadTarget{name: "../../../../tmp/pwned"}` [1](#0-0) 
4. `downloadAsset` → `dest.Copy(fileName, resp.Body)` → `makePath` computes `filepath.Join(".", "../../../../tmp/pwned")`, resolving to `/tmp/pwned` (or further outside), and the attacker-controlled asset content is written there instead of inside the victim's chosen download directory. [5](#0-4)

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

// Join an absolute path with elements to create a new Absolute path, or error.
// A PathTraversalError will be returned if the joined path would traverse outside of
// the base Absolute path. Note that this does not handle symlinks.
func (a Absolute) Join(elem ...string) (Absolute, error) {
	joinedAbsolutePath, err := ParseAbsolute(filepath.Join(append([]string{a.path}, elem...)...))
	if err != nil {
		return Absolute{}, fmt.Errorf("failed to parse joined path: %w", err)
	}

	isSubpath, err := joinedAbsolutePath.isSubpathOf(a)
	if err != nil {
		return Absolute{}, err
	}

	if !isSubpath {
		return Absolute{}, PathTraversalError{
			Base:  a,
			Elems: elem,
		}
	}

	return joinedAbsolutePath, nil
}
