### Title
Splitting a single stake across multiple signer-key grants lets an attacker win multiple leftover-round bonuses, inflating combined weight above `ceil(total_stacked/threshold)` - ([File: stackslib/src/chainstate/nakamoto/signer_set.rs])

### Summary
`pox_5_make_signer_set` computes weight per signer-key via `floor(stacked_amt/threshold)` plus a largest-remainder ("Hare") leftover-slot bonus of `+1` per signer key that has one of the largest remainders [1](#0-0) . Because the bonus is granted per distinct `signing_key` entry rather than per underlying STX principal, a single staker can split the same total STX across two (or more) `signer-manager`/`signer-key` registrations to collect more than one leftover bonus for one economic stake, so the attacker's combined weight can exceed `ceil(total_ustx/threshold)`.

### Finding Description
The claimed equality is: **assigned signing weight for a principal's total locked STX == a single rounding of `stacked_amt/threshold`** (i.e., for one economic position, weight should be bounded by `ceil(stacked_amt/threshold)`, matching what a single, unsplit registration would receive).

`pox_5_make_signer_set` aggregates entries by `signer_key` (not by underlying staker principal) at `signer_set.entry(entry.signer_key).and_modify(...)` [2](#0-1) . It then computes a global `threshold = ceil(total_ustx_locked / reward_slots)` [3](#0-2) , assigns base weight `stacked_amt / threshold` per key, and distributes the leftover slots (`reward_slots - sum(base weights)`) one at a time to the entries with the largest remainder, sorted descending by remainder with ties broken by key [4](#0-3) .

For one un-split position with amount `S`, worst-case weight = `floor(S/threshold) + 1 = ceil(S/threshold)` (at most one leftover bonus, since it's one entry). If the same `S` is split into `S1 + S2` registered under two different `signer_key`s (two different `signer-manager` contracts the attacker deploys and controls), the entries are aggregated independently:
- `weight_total_split = floor(S1/t) + floor(S2/t) + b1 + b2`, where `b1,b2 ∈ {0,1}` are independent leftover bonuses.
- Using the standard inequality `floor(S1/t)+floor(S2/t) ≤ floor(S/t)`, and choosing `S1, S2` so both remainders (`S1 mod t`, `S2 mod t`) are large enough to each win a leftover slot (feasible whenever `leftover ≥ 2` and the attacker's crafted remainders outrank other real signers, e.g. by making each remainder close to `t-1`), the attacker can obtain `b1=b2=1` while `floor(S1/t)+floor(S2/t) = floor(S/t)` (no carry case), yielding `weight_total_split = floor(S/t) + 2 = ceil(S/t) + 1` when `S mod t > 0`.

This is strictly greater than the single-position bound `ceil(S/t)`, i.e., the attacker's post-round weight exceeds what their locked STX would earn if not split — a real reward-slot (signing weight) inflation of at least one extra slot, taken from the shared `leftover` pool that would otherwise have gone to another honest signer. The same technique generalizes: splitting into `k` pieces with small, similarly-sized remainders can win up to `k` bonuses (bounded by `leftover` and the number of pieces the attacker can register), further increasing the gap beyond one slot.

**Attacker's exact call path:** deploy two `signer-manager` contracts, obtain a `grant-signer-key` for two distinct `signer-key`s via `grant-signer-key` (an unprivileged, permissionless entry point requiring only a valid `secp256k1-recover?` signature over an attacker-chosen `auth-id`) [5](#0-4) , register both via `register-signer`/`register-self` [6](#0-5) , then call `stack` twice with `amount-ustx = S1` and `S2` respectively so that `S1 mod threshold` and `S2 mod threshold` are both large [7](#0-6) .

**Why existing guards don't stop this:** `verify-not-prepare-phase`, `validate-no-reentrancy`/`signer-manager-call-active`, and `verify-signer-key-grant` only guard against timing/reentrancy/unauthorized-key issues, not against a single principal registering multiple independent signer keys — this is an explicitly supported pattern (multiple signer-managers per staker is a normal use case) [8](#0-7) . Nothing in `pox_5_make_signer_set` deduplicates or caps leftover bonuses by underlying staker principal — the aggregation key is `signer_key`, and the code comment even documents the leftover round as being distributed "one-per-signer" without any per-principal cap [9](#0-8) .

### Impact Explanation
The attacker gains extra reward-slot **weight** (signing power in the Nakamoto signer set) beyond what their locked STX proportionally warrants, at the expense of the "leftover" bonus slots that would otherwise go to genuinely under-served honest signers with large remainders. This matches the "High" category: "signing weight or reward slots exceeding locked value." It is repeatable every reward cycle in which the attacker re-stakes with a favorably split remainder, though the magnitude of the gain per cycle is bounded (at most a small number of extra weight units bounded by the network's `leftover` count and how many distinct remainder-crafted splits the attacker can register and still outrank other signers' remainders).

### Likelihood Explanation
Preconditions: attacker must be an unprivileged staker able to deploy `signer-manager` contracts and call `grant-signer-key`/`register-signer`/`stack` — all permissionless entry points confirmed above. The attacker must know or estimate `threshold` for the upcoming cycle (computable from total network stacked STX at the time of staking, a public quantity) to craft `S1 mod threshold` and `S2 mod threshold` close to `threshold - 1`. Success also depends on `leftover ≥ 2` in that cycle and the attacker's crafted remainders outranking other signers' remainders (feasible since remainders are chosen deliberately while other signers' amounts are typically round numbers, less likely to have near-maximal remainders). This is feasible but probabilistic/cycle-dependent, and the achievable gain is small and bounded per cycle — not an unbounded value-extraction bug, but a real rounding-fairness violation.

### Recommendation
Aggregate remainder/leftover apportionment by underlying staker principal(s) contributing to each signer key, or cap the leftover-round bonus so that the sum of `floor` + bonus weight assigned to any given amount contributed by a single principal (traceable across all its `signer-key`/`signer-manager` registrations) cannot exceed `ceil(sum_of_that_principal's_amounts / threshold)`. Alternatively, restrict leftover-bonus eligibility to at most one bonus per staker principal by tracking contributor identity in `RawPox5Entry` and de-duplicating before the leftover sort, rather than only de-duplicating by `signer_key`.

### Proof of Concept
Rust property test extending `pox_5_make_signer_set_props` in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs`:
1. Pick `reward_slots` and a set of "other" signers whose total stacked amount and remainders are controlled so that `leftover ≥ 2` after their base-weight allocation and their individual remainders are smaller than the attacker's crafted remainders.
2. Compute `threshold = ceil(total/reward_slots)` for the full set (including the attacker's contribution).
3. Build one `RawPox5Entry` with `amount_ustx = S = S1 + S2` under a single `signing_key` A (baseline, unsplit), run `pox_5_make_signer_set`, record `weight_unsplit = entry.weight` for A.
4. Build two `RawPox5Entry`s with `amount_ustx = S1` and `S2` (chosen so `S1 mod threshold` and `S2 mod threshold` are each just under `threshold`, and `S1 mod threshold + S2 mod threshold < threshold` to force the "no-carry" case) under two distinct `signing_key`s B and C, run `pox_5_make_signer_set` again, and record `weight_split = weight_B + weight_C`.
5. Assert `weight_split <= weight_unsplit` (expected to fail, demonstrating `weight_split == weight_unsplit + 1` or more), and separately assert `weight_split <= (S1+S2).div_ceil(threshold)` (expected to fail as well), proving the combined attacker weight exceeds the single-position ceiling bound.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }
