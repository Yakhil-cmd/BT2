### Title
Reuse of the same L1 Bitcoin lockup outpoint across multiple `register-for-bond` calls double-counts sats collateral - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`register-for-bond` accepts an L1 BTC lockup proof (`btc-lockup` as `err`) or a set of Bitcoin-tx output proofs (`btc-lockup` as `ok`) via `verify-l1-lockups`/`validate-l1-lockup`. Duplicate-output protection (`seen-outpoints`) is only tracked *within a single call's fold* — there is no persistent, contract-wide map recording which Bitcoin outpoints have already been credited toward a bond. A staker can therefore submit the same valid Bitcoin lockup transaction/output as proof for multiple different bonds (or, after a bond ends, for a rolled-over/duplicate bond position pattern relying on the same UTXO), crediting the identical locked sats to more than one `protocol-bond-memberships`/`protocol-bonds-total-staked` entry, analogous to the reported ERC-4626 vault accounting bug where a claimed deposit is not reconciled against what was actually taken/locked.

### Finding Description
`validate-l1-lockup` (`stackslib/src/chainstate/stacks/boot/pox-5.clar:2031-2113`) validates that a supplied Bitcoin transaction output:
- pays the expected timelock script for `staker`/`unlock-burn-height` (`construct-lockup-output-script`),
- has the claimed `amount`,
- has not already appeared earlier **in the same `outputs` list** (`seen-outpoints`, `index-of?`),
- is included in a valid, proven block (header + merkle proof).

`seen-outpoints` is seeded fresh as `(list)` at the start of every `verify-l1-lockups` call (`stackslib/src/chainstate/stacks/boot/pox-5.clar:1984-2019`) and is discarded once the fold completes — it is *not* persisted in any Clarity map (`define-map`) that tracks previously-consumed outpoints across separate transactions. Nothing in `register-for-bond` (`stackslib/src/chainstate/stacks/boot/pox-5.clar:642-841`) or in the rest of the contract cross-checks a newly-submitted lockup's `(txid, output-index)` against outpoints used by prior successful `register-for-bond` calls (by this staker or any other staker).

Because a single Bitcoin UTXO satisfying the timelock script continues to exist as valid, provable on-chain data indefinitely (its block header/merkle proof do not change), the same lockup proof can be replayed:
- Across different `bond-index` values (e.g. register for bond 0 with lockup X, then register for bond 1 with the same lockup X), or
- Potentially by colluding/multiple accounts submitting the same underlying transaction, if the timelock script binds only to the intended `staker`, but the sats amount credited toward `sats-total`/`protocol-bonds-total-staked` is not decremented anywhere when the corresponding BTC has already been counted for another active bond.

This breaks the equality that `sum(sats credited across all active bond memberships derived from L1 proofs) == sum(sats actually locked on distinct Bitcoin UTXOs)`. sBTC-denominated rewards (`calculate-bond-rewards`, `get-rewards`) and STX-lock minimums (`min-ustx-for-sats-amount`) are computed directly from `sats-total`/`amount-sats`, so double-counted sats inflate reward shares (`get-total-shares-staked-for-cycle`) and `protocol-bonds-total-staked` without any corresponding additional sBTC or STX ever entering the protocol.

### Impact Explanation
This falls into the "double-counting a commitment or reward" category described as Critical impact: the same physically-locked BTC collateral can be credited toward reward-share calculations and bond weight more than once, letting a staker (or colluding stakers) receive an outsized share of sBTC rewards relative to real locked value, and inflating `protocol-bonds-total-staked`, which other accounting (e.g., `get-rewards`, waterfall distribution across bonds) relies on being an accurate sum of genuinely-locked sats.

### Likelihood Explanation
Likelihood depends on whether any out-of-scope, off-chain/node-side check (not visible in the reviewed Clarity/pox-locking code) rejects reuse of the same outpoint across separate transactions — this could not be confirmed from the available contract and locking code, since `seen-outpoints` and all dedup logic found is scoped to a single `verify-l1-lockups` call. Absent such an external check, the exploit requires only a normal, unprivileged staker submitting an already-used, otherwise-valid BTC lockup proof to `register-for-bond` for a second bond, which the contract does not appear to reject.

### Recommendation
Persist consumed L1 lockup outpoints in a durable Clarity map (e.g. `used-lockup-outpoints: (txid, output-index) -> bool`) that is checked and updated in `validate-l1-lockup`/`verify-l1-lockups`, independent of any single call's local fold accumulator, so the same Bitcoin lockup output can never be credited toward more than one bond membership over the life of the contract.

### Proof of Concept
1. Staker Alice builds a valid Bitcoin lockup transaction/output `X` (as done in `buildL1Lockup` test helper) satisfying the timelock script for bond 0 and calls `register-for-bond(bond-index=0, ..., btc-lockup=ok([X]))`. This succeeds; `X`'s sats are credited to bond 0's `protocol-bonds-total-staked` and Alice's membership.
2. Once bond 0's registration window is open for another bond (or immediately for a second, concurrently-open bond, since the only gate is `verify-not-prepare-phase` and `bond-start-height`), Alice (or a colluding second staker whose allowlisted address happens to match the script's staker binding via a rollover flow) calls `register-for-bond(bond-index=1, ..., btc-lockup=ok([X]))` reusing the identical proof `X`.
3. `validate-l1-lockup` re-verifies the same header/merkle proof/script/amount for `X` — all checks pass again because `seen-outpoints` was re-initialized to `(list)` for this new call; there is no persistent map rejecting the already-consumed outpoint.
4. `sats-total` for bond 1 is credited with the same sats as bond 0, and `protocol-bonds-total-staked` for both bonds now jointly reflect BTC that was locked only once, inflating aggregate locked-sats accounting and reward-share calculations across bonds. [1](#0-0) [2](#0-1) [3](#0-2)

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)

(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
