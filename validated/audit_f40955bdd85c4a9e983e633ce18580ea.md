### Title
Rosetta RPC reports fabricated NEP-141 balance-changing operations from logs of *failed* receipts as "Success" - (File: chain/rosetta-rpc/src/adapters/nep141.rs, chain/rosetta-rpc/src/adapters/transactions.rs)

### Summary
`near-rosetta-rpc`'s NEP-141 event collector extracts `EVENT_JSON:` logs from every execution outcome in a block without checking whether that outcome's execution actually succeeded, and the code that converts these events into Rosetta `Operation`s hardcodes the operation status to `Success`. Because NEAR runtime does **not** discard logs emitted before a receipt later fails, any contract can emit a spoofed `EVENT_JSON` NEP-141 transfer/mint log and then deliberately fail the receipt, causing Rosetta consumers (e.g., exchanges) to observe a "successful" balance-changing transfer that never actually happened on-chain.

### Finding Description
`extract_events` iterates over `execution_outcome.outcome.logs` and tries to parse any log starting with `EVENT_JSON:` into a `Nep141Event`, with no check of `execution_outcome.outcome.status`: [1](#0-0) 

`collect_nep141_events` calls `extract_events` for every outcome in the block, again without any status filter: [2](#0-1) 

Although `get_base`/`get_status` do capture the real outcome status into a `status` field on the resulting `FungibleTokenEvent`: [3](#0-2) 

that field is never used to gate operation emission — `convert_fungible_token_balance_change_to_operations` unconditionally hardcodes the Rosetta `Operation.status` to `OperationStatusKind::Success`: [4](#0-3) 

and this function is invoked for every collected event in `for_block`, without checking `fungible_token_event.status`: [5](#0-4) 

Crucially, logs emitted before a receipt fails are **not** discarded by the runtime. `ActionReceiptResult::set_error` explicitly keeps `logs` (only receipts, validator proposals, and burnt/subsidized balances are cleared): [6](#0-5) 

and `merge()` appends `next_result.logs` unconditionally regardless of the action's `Ok`/`Err` result: [7](#0-6) 

Finally, the constructed `ExecutionOutcome` retains `result.logs` even when `status` is `ExecutionStatus::Failure`: [8](#0-7) 

This is the exact analog of the reported Phoenix SDK bug class: event/log parsing that fails to check whether the surrounding execution (`is_err`/`ExecutionStatusView::Failure`) succeeded, leading to spoofed/inaccurate events being processed as if they represented real state changes.

### Impact Explanation
Any account can submit a transaction that calls a contract which:
1. Calls `env::log_str("EVENT_JSON:{\"standard\":\"nep141\",\"event\":\"ft_transfer\",...}")` with arbitrary `old_owner_id`, `new_owner_id`, and `amount` fields, then
2. Deliberately fails the receipt (e.g., panics, exceeds gas, or performs an invalid action later in the same receipt).

Because the log is retained despite the failure, and Rosetta ignores execution status when building fungible-token `Operation`s, the Rosetta `/block` and `/block/transaction` endpoints will report a "SUCCESS" `TRANSFER` operation crediting/debiting a currency of the attacker's choosing (as long as the contract account is present in the configured `currencies` list) for arbitrary accounts and amounts — despite no real balance change occurring on-chain. Since the Rosetta Data API exists specifically to let exchanges and custodians track deposits/withdrawals and reconcile balances, this allows spoofing of fake fungible-token deposits, which is a realistic vector for tricking an exchange into crediting funds that were never transferred (fraudulent balance crediting via a trusted indexing API).

### Likelihood Explanation
The bug is trivially reachable by any unprivileged account submitting an ordinary function call transaction to any contract (including a contract deployed by the attacker) — no validator or node privileges are required. It only requires that the Rosetta operator has configured the abused contract account as a tracked `Currency`, which is a normal deployment scenario for exchanges monitoring specific NEP-141 tokens.

### Recommendation
In `extract_events`/`collect_nep141_events` (`chain/rosetta-rpc/src/adapters/nep141.rs`), skip logs belonging to outcomes whose `outcome.status` is `ExecutionStatusView::Failure` (and arguably `Unknown`) before parsing `EVENT_JSON` events. Additionally, in `convert_fungible_token_balance_change_to_operations` (`chain/rosetta-rpc/src/adapters/transactions.rs`), use the real `fungible_token_event.status` (already computed via `get_status`) to set the Rosetta `Operation.status` instead of hardcoding `OperationStatusKind::Success`, and consider excluding failed-execution events from the operations list entirely, consistent with Rosetta's own guidance that `Operation.status` must reflect whether the operation actually affected the account.

### Proof of Concept
1. Deploy a contract with a method that does:
```rust
env::log_str("EVENT_JSON:{\"standard\":\"nep141\",\"version\":\"1.0.0\",\"event\":\"ft_transfer\",\"data\":[{\"old_owner_id\":\"victim.near\",\"new_owner_id\":\"attacker.near\",\"amount\":\"1000000000000000000000000\"}]}");
env::panic_str("forced failure");
```
2. Call this method in a transaction from any account.
3. The resulting `ExecutionOutcome` for the receipt has `status: ExecutionStatus::Failure(...)` but still contains the `EVENT_JSON` log (per `lib.rs:1107-1140` and `set_error` at `lib.rs:482-493`).
4. Query the Rosetta `/block` (or `/block/transaction`) endpoint for the block containing this receipt, with the contract configured as a tracked `Currency`.
5. Observe a `TRANSFER` operation with `status: "SUCCESS"` moving the fabricated amount between `victim.near` and `attacker.near`, even though no such transfer occurred on-chain.

pub(crate) fn extract_events(
    execution_outcome: &ExecutionOutcomeWithIdView,
) -> Vec<crate::models::Nep141Event> {
    let prefix = "EVENT_JSON:";
    execution_outcome
        .outcome
        .logs
        .iter()
        .filter_map(|untrimmed_log| {
            let log = untrimmed_log.trim();
            if !log.starts_with(prefix) {
                return None;
            }

            match serde_json::from_str::<'_, crate::models::Nep141Event>(log[prefix.len()..].trim())
            {
                Ok(result) => Some(result),
                Err(_err) => None,
            }
        })
        .collect()
}

    pub fn merge(&mut self, mut next_result: ActionResult) -> Result<(), RuntimeError> {
        assert!(next_result.gas_burnt_for_function_call <= next_result.gas_burnt);
        assert!(
            next_result.gas_burnt <= next_result.gas_used,
            "Gas burnt {} <= Gas used {}",
            next_result.gas_burnt,
            next_result.gas_used
        );
        self.gas_burnt = self.gas_burnt.checked_add_result(next_result.gas_burnt)?;
        self.gas_burnt_for_function_call = self
            .gas_burnt_for_function_call
            .checked_add(next_result.gas_burnt_for_function_call)
            .ok_or(IntegerOverflowError)?;
        self.gas_used = self.gas_used.checked_add_result(next_result.gas_used)?;
        self.compute_usage = safe_add_compute(self.compute_usage, next_result.compute_usage)?;
        // Profile aggregates by summing; each per-action `ActionResult`
        // contributes exactly one entry to the receipt-level contract list.
        self.profile.merge(&next_result.profile);
        self.current_contracts.push(next_result.current_contract);
        self.logs.append(&mut next_result.logs);
        match next_result.result {
            Ok(mut ret_data) => {
                if let ReturnData::ReceiptIndex(ref mut receipt_index) = ret_data {
                    // Shifting local receipt index to be global receipt index.
                    *receipt_index += self.new_receipts.len() as u64;
                }
                self.result = Ok(ret_data);
                self.new_receipts.append(&mut next_result.new_receipts);
                self.validator_proposals.append(&mut next_result.validator_proposals);
                self.tokens_burnt = self
                    .tokens_burnt
                    .checked_add(next_result.tokens_burnt)
                    .ok_or(IntegerOverflowError)?;
                self.subsidized_amount = self
                    .subsidized_amount
                    .checked_add(next_result.subsidized_amount)
                    .ok_or(IntegerOverflowError)?;
            }
            Err(err) => self.set_error(err),
        }
        Ok(())
    }

    /// Marks the receipt as failed: records the error and discards any
    /// receipt-scoped state that would otherwise leak across the failure
    /// boundary (queued receipts, proposed validators, burnt/subsidized
    /// balances). Profile, gas counters, logs and `current_contracts` are
    /// kept — they reflect work already done.
    pub fn set_error(&mut self, err: ActionError) {
        self.result = Err(err);
        self.new_receipts.clear();
        self.validator_proposals.clear();
        self.tokens_burnt = Balance::ZERO;
        self.subsidized_amount = Balance::ZERO;
    }
