### Title
Interest accrual arithmetic overflow permanently freezes a high-utilization market - (File: common/src/rates/simulate.rs)

### Summary
A heavily utilized market can drive the borrow index high enough that the next accrual overflows while converting scaled debt to its original value in `accrue_step`. Because every state-changing market operation accrues interest before proceeding, the resulting contract panic permanently prevents repayment, withdrawal, liquidation, and further index updates for that market. [1](#0-0) 

### Finding Description
`accrue_step` calls `scaled_to_original` with the market's total scaled debt and current borrow index before calculating utilization, the borrow rate, and the next index. [2](#0-1)  Pool mutations invoke this accrual through `interest::global_sync`, which loops over elapsed time and calls `accrue_chunk`; `accrue_chunk` delegates directly to `accrue_step`. [3](#0-2) [4](#0-3)  The regression test documents that an 18-decimal whale market held at approximately 98% utilization reaches the `i128` RAY-value ceiling before the configured borrow-index ceiling can engage, after which `update_indexes`, `withdraw`, and `repay` all fail with `MATH_OVERFLOW`. [5](#0-4) 

### Impact Explanation
This is permanent freezing of user funds in the affected market: suppliers cannot withdraw and borrowers cannot repay because both paths attempt accrual and hit the same overflow before their position mutation executes. [6](#0-5)  Liquidation and bad-debt cleanup are likewise blocked when they load or mutate the affected market through the same accrual path. [3](#0-2) 

### Likelihood Explanation
An unprivileged borrower can create the trigger by maintaining extremely high utilization in a large listed market and allowing interest to compound until the valuation overflow is reached. [7](#0-6)  The required conditions are demanding—an 18-decimal market, very large supplied principal, sustained approximately 98% utilization, and enough elapsed accrual—so the issue is less likely than an ordinary transaction DoS, but the test demonstrates that the state transition is reachable and that the intended index cap does not prevent it. [8](#0-7) 

### Recommendation
Bound or saturate the debt-value calculation before `borrowed * borrow_index / RAY` can exceed `i128`, and cap the borrow index at `MAX_BORROW_INDEX_RAY` before calculating scaled-to-original value. Accrual should also validate that revenue-share accumulation and subsequent index updates remain inside the representable RAY domain so one market cannot enter a state where all recovery paths panic.

### Proof of Concept
The existing reproduction uses an 18-decimal `BIG18` market, supplies `1_000_000_000 * 10^18` units, borrows 98% of that principal, advances ledger time yearly, and invokes `update_indexes` until `MATH_OVERFLOW` occurs. [9](#0-8)  The test then verifies that the stored index remains below `MAX_BORROW_INDEX_RAY` and that subsequent `withdraw` and `repay` calls both fail with the same overflow. [10](#0-9)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
