### Title
PR title and other metadata printed unsanitized to the terminal in `gh pr view` - (File: pkg/cmd/pr/view/view.go)

### Summary
`printHumanPrPreview` in `pkg/cmd/pr/view/view.go` writes `pr.Title`, `pr.Milestone.Title`, reviewer/assignee/author display names, and the auto-merge enabler login directly to `opts.IO.Out` via `fmt.Fprintf`/`fmt.Fprintln`, bypassing the sanitization mechanisms (`iostreams.Untrusted`, `asciisanitizer`-wrapped `ContentOut`) that the codebase otherwise consistently applies to third-party content. An attacker who opens a pull request with a title containing ANSI/OSC/CSI escape sequences can therefore inject raw terminal control codes into the maintainer's terminal when they run `gh pr view`.

### Finding Description
`NewCmdView` wires up `viewRun` → `printHumanPrPreview` when connected to a TTY: [1](#0-0) 

Inside `printHumanPrPreview`, the header line prints the PR title with `fmt.Fprintf(out, "%s %s#%d\n", cs.Bold(pr.Title), ...)` where `out := opts.IO.Out`: [2](#0-1) 

`pr.Title` is a plain `string` field populated from the GitHub API response — fully attacker-controlled (any user who can open a PR against the repo sets the title). Unlike `pr.Body`, which is passed through `markdown.Render` before being written (a rendering path the codebase treats as neutralizing content, per the analogous comment in `pkg/cmd/gist/view/view.go`), the title, milestone title, reviewer/assignee names, and auto-merge login are written straight to `opts.IO.Out` with no call to `iostreams.NewUntrusted(...).String()` and no use of `opts.IO.ContentOut` (which wraps writes with the `asciisanitizer` transform): [3](#0-2) [4](#0-3) 

Other similarly-shaped commands in this codebase (`pr diff`, `gist view`, `release download`, `run view --log`, `api`) explicitly guard against exactly this class of injection using `iostreams.ContainsEscapeSequence`, `CopyGuardedContent`, or `Untrusted.String()` before writing untrusted external bytes to a terminal: [5](#0-4) [6](#0-5) 

`pkg/cmd/pr/view/view.go`'s `printHumanPrPreview` has no equivalent check for `pr.Title`, `pr.Milestone.Title`, `prReviewerList`/`prAssigneeList` names, or `autoMerge.EnabledBy.Login` — these are all values sourced from the API that a low-privilege actor (an issue/PR author, reviewer, or milestone creator with only "open PR" rights) can influence, and they land in the terminal unsanitized when `out := opts.IO.Out` is used instead of `opts.IO.ContentOut` or `iostreams.NewUntrusted(...)`.

### Impact Explanation
An attacker opens a pull request whose title contains OSC/CSI escape payloads (e.g., terminal title spoofing, "clear screen and print fake prompt", or in vulnerable terminal emulators, more dangerous sequences). When the repo maintainer runs `gh pr view <number>` in an interactive terminal, `printHumanPrPreview` prints the raw title directly, executing/rendering the escape sequences in the victim's terminal. This matches the "Terminal output/prompt spoofing" impact class noted in the question — potential for prompt/title spoofing that could mislead a maintainer into taking a destructive action (e.g., approving/merging, or being tricked by a spoofed confirmation prompt).

### Likelihood Explanation
Highly feasible: opening a PR with an arbitrary title requires no special privilege beyond fork/PR access to the target repo, which is the exact "unprivileged" threat model in scope. Any maintainer running `gh pr view` interactively (the default, common workflow) is affected. No dependency on other misconfiguration.

### Recommendation
Wrap all externally-sourced display strings printed by `printHumanPrPreview` (and `printRawPrPreview`) — `pr.Title`, `pr.Milestone.Title`, reviewer/assignee display names, `autoMerge.EnabledBy.Login` — in `iostreams.NewUntrusted(...)` before formatting, or route these writes through `opts.IO.ContentOut` so the `asciisanitizer` transform strips escape sequences consistently with the rest of the codebase's untrusted-content handling.

### Proof of Concept
Add a test analogous to existing escape-sequence regression tests (e.g. `pkg/cmd/pr/diff/diff_test.go`, `pkg/iostreams/untrusted_test.go`):
```go
func TestPrintHumanPrPreview_TitleEscapeSequence(t *testing.T) {
    io, _, stdout, _ := iostreams.Test()
    io.SetStdoutTTY(true)
    pr := &api.PullRequest{
        Title: "hello\x1b]0;HIJACKED\x07world",
        // ... minimal required fields
    }
    err := printHumanPrPreview(&ViewOptions{IO: io, Now: time.Now}, ghrepo.New("OWNER","REPO"), pr)
    require.NoError(t, err)
    assert.NotContains(t, stdout.String(), "\x1b",
        "PR title must not leak raw ESC bytes to the terminal")
}
```
Current behavior: the assertion fails because `pr.Title` is written to `opts.IO.Out` unsanitized.

// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}
