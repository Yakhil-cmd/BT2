## Title
`Api::CCMenuController` bypasses the API token's stack scope, allowing a stack-scoped `ApiClient` to read the build/deploy status of any stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
The Connext bug allowed an unprivileged input (`_local`) to reach a code path whose result was blindly trusted to update `routerBalances`, breaking the invariant that a caller can only affect its own balance. The analogous binding in shipit-engine is: **the set of stacks an `ApiClient` token is scoped to authorize (`ApiClient#stack_id`) must equal the set of stacks the controller code actually touches**. `Api::CCMenuController` breaks this equality by resolving the target stack directly from client-supplied `params[:stack_id]` without applying the scoping filter that every other API controller uses.

### Finding Description
`Api::BaseController` defines the canonical, scope-respecting accessor: [1](#0-0) 

`stacks` restricts the queryable set to `Stack.where(id: current_api_client.stack_id)` whenever the authenticated `ApiClient` is scoped to a single stack, and `stack` resolves `params[:stack_id]` against that restricted relation. `Api::StacksController` and other API controllers rely on this scoped `stack`/`stacks` method (confirmed by the passing test `"an api client scoped to a stack will only see that one stack"` in `test/controllers/api/stacks_controller_test.rb`).

`Api::CCMenuController`, however, overrides `stack` to bypass the scope entirely: [2](#0-1) 

`stack` here calls `Stack.from_param!(params[:stack_id])` directly on the unscoped `Stack` model, not the scoped `stacks` relation from `BaseController`. The only guard is `require_permission :read, :stack`, which only checks that the token *has* the `read:stack` permission string — it never checks *which* stack the token is bound to (`ApiClient#stack_id`, `ApiClient#check_permissions!` in `app/models/shipit/api_client.rb`).

So for an `ApiClient` created with a `stack_id` (a token deliberately scoped to a single stack, e.g. fixture `here_come_the_walrus` in `test/fixtures/shipit/api_clients.yml`), `#show` on `CCMenuController` will happily render build status, last build label/time, and web URL for *any* stack in the installation, not just the one the token was issued for.

### Impact Explanation
This breaks the binding "a stack a token authorizes versus a stack it touches." A token deliberately scoped to a single stack (least-privilege deployment) can be used to read the CI/deploy status (`lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`, lock state) of every other stack managed by the Shipit instance, including stacks belonging to other teams/repositories the token holder was never meant to see. This matches the specified High-impact class: "unauthenticated read of stack state" in the sense that the specific *stack*'s state is read without being authorized for that particular stack — the token authenticates the caller but the code fails to authorize the requested resource.

### Likelihood Explanation
Trivial to trigger by any holder of a legitimately-issued, stack-scoped `ApiClient` token (a normal, unprivileged deployment integration credential, not requiring special access) — they simply pass a different `stack_id` in the request to the `ccmenu` endpoint.

### Recommendation
Change `Api::CCMenuController#stack` to reuse the scoped accessor from `BaseController` instead of hitting `Stack` directly:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

### Proof of Concept
1. Create an `ApiClient` scoped to `stack_a` only (`stack_id` set, permissions `['read:stack']`) — analogous to fixture `here_come_the_walrus`.
2. Authenticate as that client and request:
   `GET /api/stacks/:stack_b_id/ccmenu.xml?token=<client_token>` where `stack_b` is a different stack the token was never scoped to.
3. Observe that `Api::CCMenuController#show` renders `stack_b`'s deploy/rollback status successfully (HTTP 200), whereas the equivalent request to `Api::StacksController#show` for `stack_b` with the same token would 404 due to the `stacks` scoping in `Api::BaseController#stacks`. # frozen_string_literal: true

```ruby
module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
