### Title
Wrong Address in `GovernanceGoverningNode` Consistency Check Allows Setting Governing Node to Non-Council Address, Permanently Breaking Single-Mode Governance — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

In `checkConsistency`, the `GovernanceGoverningNode` vote case checks whether the **current** governing node (`params.GoverningNode`) is in the council, instead of checking whether the **proposed new** governing node (`vote.Value().(common.Address)`) is in the council. Because the current governing node is always protected from removal by `applyVote`, this check is a permanent no-op that always passes. A vote to change the governing node to any address — including one not in the council — is accepted. After ratification, the new governing node cannot propose blocks or cast votes, permanently locking governance in "single" mode with no recovery path.

---

### Finding Description

In `kaiax/gov/headergov/impl/header.go`, `checkConsistency` handles the `GovernanceGoverningNode` vote:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {  // ← BUG: checks current node, not proposed new node
        return nil
    }
    return ErrGovNodeNotInValSetList
``` [1](#0-0) 

The check `slices.Contains(council, params.GoverningNode)` tests whether the **current** governing node is in the council. The vote value — the **proposed new** governing node — is `vote.Value().(common.Address)`, which is never consulted here.

The current governing node is structurally guaranteed to always be in the council. In `applyVote`, any `RemoveValidator` vote targeting the governing node is silently skipped:

```go
for _, address := range addresses {
    if address == governingNode {
        continue  // governing node cannot be removed
    }
    ...
}
``` [2](#0-1) 

Therefore `slices.Contains(council, params.GoverningNode)` is always `true`, and `checkConsistency` unconditionally returns `nil` for any `GovernanceGoverningNode` vote, regardless of whether the proposed new governing node is in the council.

Compare with the `AddValidator`/`RemoveValidator` case in the same function, which correctly uses `vote.Value().([]common.Address)` (the proposed addresses) rather than `params.GoverningNode`:

```go
case gov.AddValidator, gov.RemoveValidator:
    ...
    if slices.Contains(vote.Value().([]common.Address), params.GoverningNode) {
        return ErrGovNodeInValSetVoteValue
    }
``` [3](#0-2) 

The `GovernanceGoverningNode` param is canonicalized to `common.Address`:

```go
GovernanceGoverningNode: {
    Canonicalizer: addressCanonicalizer,
    FormatChecker: func(cv any) bool {
        _, ok := cv.(common.Address)
        return ok
    },
``` [4](#0-3) 

So `vote.Value().(common.Address)` is the correct expression for the proposed new governing node, and it is what the check should use.

`checkConsistency` is called from both the `Vote()` API path and the `VerifyVote()` block-verification path, making this reachable in production:

```go
// API path
err := api.h.checkConsistency(nextBlock, vote)

// Block verification path
return h.checkConsistency(blockNum, vote)
``` [5](#0-4) [6](#0-5) 

---

### Impact Explanation

Kaia Mainnet and Kairos testnet operate in `"single"` governance mode, where only the governing node can cast votes. If the governing node is changed to an address that is not in the council:

1. The new governing node cannot be selected as block proposer (proposers are drawn from the council/committee).
2. Because it cannot propose blocks, it cannot embed a `header.Vote` and therefore cannot cast any governance vote.
3. No other node can vote in `"single"` mode.
4. There is no recovery path: the governing node cannot vote to add itself to the council, cannot vote to change the governing node back, and cannot vote on any other parameter.

The result is **permanent, irrecoverable governance lock** — all mutable parameters (`reward.mintingamount`, `reward.ratio`, `governance.unitprice`, `istanbul.committeesize`, etc.) are frozen forever. This constitutes a governance privilege escalation that changes protected chain state (the governing authority) in a way that breaks all future governance settlement.

---

### Likelihood Explanation

The governing node is a semi-trusted party. The bug removes the only on-chain guard that should prevent the governing node from accidentally or intentionally setting itself to a non-council address. Scenarios include:

- **Operator error**: the governing node operator votes to transfer governance to a new address before adding that address to the council via `AddValidator`.
- **Key rotation**: the operator rotates the governing node key, votes the new key as governing node, but the `AddValidator` vote for the new key has not yet been ratified.
- **Malicious insider**: a compromised governing node key deliberately locks governance.

In all cases the missing check (`vote.Value().(common.Address)` not in council) is the only thing that would have prevented the outcome.

---

### Recommendation

Replace `params.GoverningNode` with `vote.Value().(common.Address)` in the `GovernanceGoverningNode` consistency check:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    // Check the PROPOSED new governing node, not the current one.
    newGoverningNode := vote.Value().(common.Address)
    if slices.Contains(council, newGoverningNode) {
        return nil
    }
    return ErrGovNodeNotInValSetList
```

This mirrors the pattern already used in the `AddValidator`/`RemoveValidator` case, which correctly inspects `vote.Value()`.

### Proof of Concept

**Setup**: Kaia chain in `"single"` governance mode. Council = `{A, B, C}`. Current governing node = `A`. Address `X` is not in the council.

1. Node `A` calls `governance_vote("governance.governingnode", X)`.
2. `Vote()` calls `checkConsistency(nextBlock, vote)`.
3. `checkConsistency` evaluates `slices.Contains(council, params.GoverningNode)` = `slices.Contains({A,B,C}, A)` = **true** → returns `nil` (no error).
4. The vote is queued and embedded in a block header when `A` next proposes a block.
5. `VerifyVote` on peer nodes calls `checkConsistency` again — same result, block accepted.
6. At the next epoch boundary, `getExpectedGovernance` collects the vote and the proposer writes `header.Governance = {"governance.governingnode": X}`.
7. `VerifyGov` accepts this governance data (it matches the locally derived expected governance).
8. `GetParamSet` for all subsequent blocks returns `GoverningNode = X`.
9. `X` is not in the council. `X` is never selected as proposer. `X` cannot embed `header.Vote`. No governance vote can ever be cast again.
10. **Governance is permanently locked.**
