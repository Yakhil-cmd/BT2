### Title
`has_only()` character-class injection allows negating an oscript allowlist check via a leading `^` — ([File: formula/evaluation.js])

### Summary
The `has_only(str, chars)` oscript builtin builds a dynamic JavaScript `RegExp` character class from the caller-supplied `chars` argument with insufficient sanitization, mirroring the reported bug class of an allowlist-validation routine that fails to account for meta-characters that change the semantics of the underlying interpreter (there: shell `$()`/backticks inside quotes; here: regex character-class negation/escape sequences inside `[...]`).

### Finding Description
`has_only` is implemented in the formula evaluator: [1](#0-0) 

```
if (sub.match(/\\]/) || sub[sub.length - 1] === '\\')
    return setFatalError("invalid character group: " + sub, { arr }, false, cb);
sub = sub.replace(/]/g, '\\]'); // don't allow to close the group early
var bMatches = new RegExp("^[" + sub + "]*$").test(str);
```

The only sanitization performed is: (1) reject if `sub` contains a literal `\]` sequence, (2) reject if `sub` ends with a bare `\`, and (3) escape any unescaped `]` in `sub`. No other regex meta-characters are neutralized before `sub` is concatenated directly into a `RegExp` literal as the *content* of a character class.

This is the same class of bug as the advisory's root cause: a validator/allowlist implementation that inspects a string for a narrow, hard-coded set of "dangerous" tokens (there: raw `` ` `` / `$(` inside double quotes; here: raw `]` / trailing `\`) while missing other syntax that is equally capable of changing the meaning of the string once it reaches the real interpreter (there: the shell; here: the JS regex engine).

Concretely, if `sub` begins with `^`, the resulting regex becomes `^[^...]*$`. In JavaScript, `[^]` (a negated class with an empty body, or effectively any negated class matching only excluded chars) matches virtually any character not in the excluded set — and if the excluded set is empty or trivial, `[^]` matches *every* character including newlines. This means `has_only(str, "^")` (or `sub` starting with `^`) does not enforce "string must contain only these characters" as an oscript author would expect; instead it can be turned into a match-everything (or the semantic opposite of the intended allowlist), silently returning `true` for arbitrary/malicious `str` content that the AA logic assumed had been constrained to a safe character set.

Other regex-affecting tokens are also unescaped/unvalidated, e.g. ranges (`-`) and backslash-class shortcuts (`\d`, `\w`, `\s`, `\D`, etc. are intentionally allowed per the existing test suite), so the escaping logic is deliberately narrow and only defends against prematurely closing the class with `]` — not against negation via `^`. [2](#0-1) 

The existing tests only cover the "invalid escaped `]`" and "trailing backslash" cases, confirming the fix scope was narrowly targeted and did not consider `^`-based negation.

### Impact Explanation
`has_only()` is a general-purpose oscript primitive available to any AA author to sanity-check untrusted `trigger.data` fields (e.g., restrict a user-supplied string to alphanumerics before using it in further logic, storage keys, or output construction). If an AA's `chars` argument to `has_only` is influenced by attacker-controlled data (directly, or built up from constants concatenated with data), an attacker can supply a value that flips the check from "allow-only-these-chars" to "match anything," bypassing an intended input-sanitization gate inside the AA. Depending on how the AA subsequently uses the "validated" string (e.g., feeding it into `data_feed` keys, response messages, or further business logic gating fund transfers), this can lead to unintended AA behavior, including incorrect fund routing/spending decisions the AA developer believed were protected by the character allowlist. This is a logic/validation-bypass primitive rather than a guaranteed direct fund-loss bug on its own; actual impact depends on how a specific AA uses the return value, but it defeats a documented security primitive of the language in the same way the advisory's allowlist bypass defeated the exec allowlist.

### Likelihood Explanation
Reachable by any unprivileged AA trigger sender able to supply `trigger.data`, provided the AA passes attacker-influenced content into the `chars` (second) argument of `has_only`. This is a less common usage pattern than passing attacker data as the first argument (`str`), which somewhat limits real-world reachability compared to the original advisory (where the allowlisted string was always attacker-controlled). Still, it is a genuine gap in the sanitization logic of a documented, permissionless oscript builtin, and any AA that builds the `chars` argument dynamically (e.g., unioning a base charset with data-derived characters, or misusing `has_only` for negation logic) is exposed.

### Recommendation
Harden `has_only`'s handling of the `chars` argument in `formula/evaluation.js`:
- Reject (or escape) a leading `^` when it is not intended to be a literal character, or require it to be escaped like `]` is.
- More robust: escape all regex meta-characters in `sub` except the ones explicitly intended to retain special meaning (e.g., `\d`, `\w`, `\s`, ranges via `-`), rather than only guarding against `]`.
- Add explicit test coverage for `has_only(str, "^...")` and other meta-character combinations to ensure the check cannot be turned into a match-all or into unintended negation.

### Proof of Concept
Within an oscript formula/AA (evaluated via `evalFormulaWithVars`, mirroring `test/formula.test.js`):
```
has_only("any$arbitrary#string!!", "^")
```
This evaluates `new RegExp("^[^]*$")`, which matches the entire input string, causing `has_only` to return `true` even though the string contains characters an AA author intended to disallow (only `]` and trailing `\` are currently rejected by the sanitizer in `formula/evaluation.js:2040-2042`). An AA relying on `has_only(trigger.data.value, someCharsIncludingLeadingCaret)` to gate logic would treat arbitrary attacker-controlled `trigger.data.value` as validated.
