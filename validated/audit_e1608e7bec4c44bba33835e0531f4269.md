### Title
Malicious swap routes can poison Soroban authorization trees to steal unrelated wallet tokens - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary

The controller forwards caller-supplied `swap` bytes to the configured router while validating only the controller's input spend and measured output. A route-selected contract can therefore execute an additional token transfer from the caller inside the same authorization subtree; if the victim signs the simulation-generated tree, the attacker can drain an unrelated wallet token while the protocol receives a fair-looking swap output. This is the contract-side analogue of poisoning a password-reset link: the attacker supplies a malicious destination that causes the victim's authenticated action to authorize an attacker-chosen transfer. [1](#0-0) [2](#0-1) 

### Finding Description

`swap_tokens` snapshots the controller's input and output balances, authorizes one exact input-token transfer to the configured router, and invokes `router.execute_strategy(controller, amount_in, swap)` with the caller-controlled route payload. [3](#0-2) 

After the router returns, the controller only rejects controller input-balance growth, spending above `amount_in`, and zero measured output; it does not constrain contracts reached through the route or additional caller-authorized token movements beneath the caller's root authorization. [4](#0-3) 

The regression proof registers an attacker-controlled hop pool in the route and has that pool call `wallet_token.transfer(victim, attacker, amount)` during `swap_collateral`. [5](#0-4) [6](#0-5) 

Simulation records that rogue transfer as a child invocation under the victim's `swap_collateral` root, and the transaction can deliver a normal output balance to the victim while transferring the unrelated wallet token to the attacker. [7](#0-6) 

Enforcing auth rejects the same route under an honest tree with no child transfer, but succeeds when the victim signs the poisoned tree returned by simulation, leaving the victim wallet balance at zero and the attacker balance equal to the stolen amount. [8](#0-7) 

### Impact Explanation

An unprivileged attacker can cause theft of user funds beyond the declared swap input by supplying or inducing use of a malicious route whose hop executes an extra victim-token transfer. [7](#0-6) 

The loss is not bounded by `amount_in`, the route minimum, or the controller's measured-output check because the stolen asset need not be either routed token and is authorized only as a child invocation in the victim's signed tree. [4](#0-3) [9](#0-8) 

### Likelihood Explanation

The attacker can reach this path through ordinary strategy inputs such as `swap_collateral(caller, account_id, collateral, collateral_amount, debt, swap)`, where `swap` is opaque route bytes supplied to the operation. [10](#0-9) 

Exploitation requires the victim to sign the poisoned authorization tree rather than merely submit an honest route, so wallet or quote-interface verification can prevent it; however, the contract provides no venue allowlist or authorization-tree shape check that stops the malicious child transfer once signed. [1](#0-0) [8](#0-7) 

### Recommendation

Restrict strategy routes to a governance-maintained allowlist of venue contracts and token addresses, and reject any route containing addresses outside that allowlist. [1](#0-0) 

If venue allowlisting is intentionally delegated to the router, the trusted router boundary must cryptographically constrain executable route hops and provide clients a canonical signed-route/authorization-tree preview that rejects any child invocation other than the expected exact input transfer. [11](#0-10) 

Clients should additionally simulate, decode, and display every authorization sub-invocation and refuse a strategy authorization containing any transfer other than the intended routed input. [12](#0-11) 

### Proof of Concept

```rust
// Route bytes selected by the attacker for victim.swap_collateral(...).
let route = RoutedSwap {
    hop_pool: env.register(RogueHopPool, (
        victim.clone(),
        unrelated_wallet_token.clone(),
        attacker.clone(),
        wallet_balance,
    )),
    min_out: fair_output,
    token_in: usdc,
    token_out: eth,
}.to_xdr(&env);

// During router execution, the route-selected hop pool executes:
token::Client::new(&env, &unrelated_wallet_token).transfer(
    &victim,
    &attacker,
    &wallet_balance,
);
```

The harness demonstrates that simulation places this `transfer` as a child of the victim's `swap_collateral` authorization and that the same call records the victim's expected swap output. [2](#0-1) 

```rust
let stolen_transfer = MockAuthInvoke {

// Victim signs the poisoned tree returned by simulation.

assert_eq!(wallet_balance(attacker), wallet_balance);
```

The enforcing-auth test confirms that an honest tree without that child transfer fails, while the poisoned signed tree succeeds and drains the wallet token. [8](#0-7)

```rust
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
```
