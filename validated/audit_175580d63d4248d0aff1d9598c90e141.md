The key evidence is now clear. Let me confirm the critical no-op validation in `DeliverStakingInfos`:

### Title
Unvalidated P2P StakingInfo Written to DB During Fast Sync Enables Permanent Reward Redirection — (`datasync/downloader/queue.go`, `datasync/downloader/downloader.go`)

---

### Summary

During fast sync, `P2PStakingInfo` objects received from a remote peer are written unconditionally to the local database with no cryptographic or state-root-based validation. A malicious peer can serve forged `RewardAddrs`, `KEFAddr`, and `KIFAddr` values. After sync completes, `GetStakingInfo` for pre-Kaia blocks reads the DB entry first and returns it without ever consulting the canonical state, causing all subsequent block reward distributions for the affected staking epochs to use attacker-controlled addresses.

---

### Finding Description

**Step 1 — No-op validation in `DeliverStakingInfos`**

`queue.DeliverStakingInfos` uses the shared `deliver` helper, which calls a per-type `validate` callback before accepting data. For bodies, this callback verifies `TxHash`; for receipts, it verifies `ReceiptHash`. For staking infos, the callback is explicitly a no-op:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [1](#0-0) 

There is no check that the delivered `P2PStakingInfo` corresponds to the AddressBook state committed under the block's `Header.Root`.

**Step 2 — Unconditional DB write in `commitFastSyncData`**

After the forged staking info passes the no-op validation and lands in a `fetchResult`, `commitFastSyncData` writes it directly to the persistent key-value store:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
``` [2](#0-1) 

`PutStakingInfoToDB` calls `WriteStakingInfo` which does a plain `db.Put` with no further checks. [3](#0-2) 

**Step 3 — DB entry takes priority over state in `GetStakingInfo`**

For any block number before the Kaia hardfork, `GetStakingInfo` checks the DB first and returns immediately if an entry exists, never falling through to the state-based path:

```go
if !isKaia {
    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)
        return si, nil   // forged data returned here
    }
}
// Read from the state  ← never reached if DB has an entry
``` [4](#0-3) 

**Step 4 — Forged data used for reward finalization**

`FinalizeState` calls `GetDeferredReward`, which calls `GetStakingInfo`. The returned `RewardAddrs` determine where per-validator staking rewards are sent, and `KEFAddr`/`KIFAddr` determine where KEF/KIF treasury funds are sent: [5](#0-4) [6](#0-5) 

---

### Impact Explanation

An attacker who serves as a fast-sync peer can permanently redirect:
- **Staking rewards** (`RewardAddrs`) — per-validator block rewards for every staking epoch whose source block was fast-synced
- **KEF/KIF treasury distributions** (`KEFAddr`/`KIFAddr`) — protocol-level treasury fund flows

The corruption is durable: the forged DB entry is never overwritten because `GetStakingInfo` returns the DB value before reaching the state-read path. The effect persists across node restarts and affects every block processed after sync whose `sourceNum` maps to a forged epoch.

---

### Likelihood Explanation

The attacker only needs to be a reachable P2P peer during fast sync. They serve valid, validator-signed headers (downloaded from the canonical network) but substitute forged `P2PStakingInfo` payloads in response to `GetStakingInfo` P2P requests. No cryptographic break, no key compromise, and no majority-validator collusion is required. The attack is limited to pre-Kaia-hardfork staking epochs (after the Kaia fork, `GetStakingInfo` bypasses the DB entirely), but those epochs cover the entire pre-fork history of the chain.

---

### Recommendation

1. **Implement the missing validation** in `queue.DeliverStakingInfos` (the `// TODO-Kaia-Snapsync` comment acknowledges this is unfinished). After fast sync downloads the state trie for the pivot block, re-derive the `StakingInfo` for each staking epoch by calling `getFromState` against the committed state root and compare it to the peer-supplied value before writing to DB.
2. **Alternatively**, remove the DB write during fast sync entirely and derive staking info lazily from state on first access, consistent with how post-Kaia blocks work.
3. **At minimum**, add a post-sync integrity pass that re-reads each stored staking epoch from the canonical state and overwrites any DB entry that does not match.

---

### Proof of Concept

```
1. Attacker runs a modified Kaia node that serves canonical headers/receipts/bodies
   but overrides GetStakingInfo responses to return P2PStakingInfo with
   CouncilRewardAddrs = [attacker_addr, ...] and KEFAddr/KIFAddr = attacker_addr.

2. Victim node initiates fast sync; attacker's node is selected as sync peer
   (highest advertised TD, or simply the first available peer).

3. fetchStakingInfos() requests staking info for every staking-interval block.
   DeliverStakingInfos() accepts all of them (validate() returns nil unconditionally).
   commitFastSyncData() calls PutStakingInfoToDB() for each forged entry.

4. Fast sync completes. Victim node begins processing new blocks.
   For each new block N (pre-Kaia), GetStakingInfo(N) computes sourceNum,
   finds the forged entry in DB, returns it, and caches it.

5. FinalizeState distributes block rewards to attacker_addr instead of
   legitimate validator reward addresses and treasury contracts.

Assert: ReadStakingInfo(db, sourceNum).RewardAddrs == [attacker_addr]
Assert: block reward state delta credits attacker_addr, not legitimate validators
```

func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
