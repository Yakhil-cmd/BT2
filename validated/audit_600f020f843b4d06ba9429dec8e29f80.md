### Title
Webhook signature check is keyed to attacker-controlled `repository.owner.login`, letting a payload for one (secretless) org forge CI status / sync for any tracked stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate the HMAC signature against using `repository_owner`, a value read straight out of the untrusted JSON body, *before* the signature has been verified. The equality the app relies on — "the organization whose secret authenticated this request" == "the organization whose repository the payload writes to" — is never enforced, because `verify_webhook_signature` treats a blank `webhook_secret` as automatic success, and the handlers (`StatusHandler`, `PushHandler`, PR handlers) resolve the target stack from a *different* field (`sha` / `repository.full_name`) in the same attacker-controlled body.

```ruby

  ...

``` [2](#0-1) 

If the organization named in the payload has no `webhook_secret` configured — a state the shipped templates actively encourage (`webhook_secret: # nil` in `config/secrets.development.example.yml`, `config/secrets.development.shopify.yml`, and `test/dummy/config/secrets_double_github_app.yml`) — verification is unconditionally `true`, and the request proceeds with **no cryptographic check at all**.

The handlers that then act on the body never re-check that this "authenticating" organization matches the resource being mutated:
- `StatusHandler#process` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`) does `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` — a global, cross-stack lookup keyed only by commit SHA, with zero repository/organization scoping. [3](#0-2) 
- `Handler#stacks`/`#repository_name` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) and `PushHandler#process` resolve the acted-upon stack from `payload.dig('repository', 'full_name')`, a field independent from `repository_owner`. [4](#0-3) 
- `Status#replicate_from_github!`/`create_status_from_github!` feed directly into `MergeRequest#reject_unless_mergeable!`, `#any_status_checks_failed?`, `#all_status_checks_passed?` (`app/models/shipit/merge_request.rb:155-206`) which gate `merge!`. [5](#0-4) [6](#0-5) 

The binding that breaks: **organization whose secret validated this request (attacker-chosen, possibly secretless) ≠ repository/commit actually written by the handler (arbitrary, chosen independently in the same payload)**. Both fields live in the same JSON body under the attacker's control, so signature coverage of the raw body does not prevent this — signature verification is skipped entirely by choosing an org with no configured secret, and once inside `create`, nothing re-derives the target repository from the org that was actually authenticated.

### Impact Explanation
By POSTing a crafted `status` (or `push`) event where `repository.owner.login` names any GitHub org configured in `Shipit.github` without a `webhook_secret`, an unauthenticated attacker bypasses HMAC verification entirely, then supplies a `sha` matching a commit belonging to any other, unrelated, secret-protected tracked stack. This lets the attacker inject a fabricated `success` `Status` for that commit, satisfying `ci.require`/`merge.require` checks in `MergeRequest#reject_unless_mergeable!`, and enabling an **unauthorized merge/deploy** of a commit that never actually passed CI — matching the "unauthorized deploy, rollback or merge" High-impact criterion. It can equally be used to spuriously trigger `PushHandler`'s `stack.sync_github` on arbitrary tracked stacks.

### Likelihood Explanation
Exploitation requires only an unauthenticated HTTP POST to the public `/webhooks` endpoint (`before_action :check_if_ping, :drop_unhandled_event, :verify_signature`), no credentials, tokens or repository access. The only precondition is that at least one configured GitHub organization lacks a `webhook_secret` — the setup docs and shipped example templates set this as the default value, so this is a realistic multi-org configuration state, not an edge case.

### Recommendation
Do not select the verification org from unauthenticated payload fields. Instead: (1) require every configured organization to have a non-blank `webhook_secret` in production and fail closed rather than returning `true` when absent; (2) after signature verification succeeds, re-derive `repository_owner`/`repository.full_name` strictly from the authenticated org's known repositories and reject/ignore any handler action whose target repository owner does not match the org whose secret validated the request; (3) scope `StatusHandler`'s `Commit.where(sha:)` lookup to commits belonging to the verified organization only.

### Proof of Concept
1. Configure Shipit with two orgs: `victim-org` (has `webhook_secret` set, tracks `victim-org/app`) and `attacker-org` (left with default `webhook_secret: # nil`, per template).
2. Obtain (public) the SHA of a commit on a `victim-org/app` branch awaiting CI/merge.
3. POST to `/webhooks` with header `X-Github-Event: status`, no valid `X-Hub-Signature` (or any garbage value), and body:
```json
{
  "sha": "<victim-commit-sha>",
  "state": "success",
  "context": "ci/required-check",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "attacker-org/whatever" }
}
```
4. `verify_signature` calls `Shipit.github(organization: 'attacker-org')`; since that org's `webhook_secret` is blank, `verify_webhook_signature` returns `true` and the request is processed.
5. `StatusHandler#process` runs `Commit.where(sha: params.sha)`, finds the victim commit (owned by a different, secret-protected org/stack), and creates a fabricated `success` `Status` on it, which `MergeRequest#reject_unless_mergeable!` will treat as passing CI, enabling an unauthorized merge/deploy.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
