### Title
Cross-Organization Webhook Signature Confusion Allows Forged GitHub Events Against Any Configured Stack - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
Shipit supports hosting multiple GitHub organizations in a single instance, each with its own `webhook_secret` under `secrets.github[<org>]` [1](#0-0) . `WebhooksController#verify_signature` selects *which* organization's secret to validate the incoming HMAC signature against by reading the untrusted, unsigned request body itself (`repository.owner.login` or `organization.login`), then hands the entire raw payload to event handlers that resolve the *target* repository/stack using a *different* field of that same payload (`repository.full_name`). These two fields are never cross-checked, so a request can be validated against one organization's (weak or absent) secret while acting on a stack that belongs to a completely different, properly-secured organization.

### Finding Description
`verify_signature` picks the GitHub App/secret to verify against purely from attacker-supplied JSON: [2](#0-1) 

Note `repository_owner` is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` — both come straight from the unauthenticated POST body, before any signature has been checked.

Separately, `GitHubApp#verify_webhook_signature` treats a missing `webhook_secret` as automatically valid: [3](#0-2) 

Per the setup docs, `webhook_secret` is optional per organization (“If you've set a webhook secret … you should copy it here”), so a multi-org Shipit deployment can easily have one org configured without a secret while other, "real" orgs have one configured [4](#0-3) .

Once `verify_signature` passes (either by matching the weak org's secret or by that org having no secret at all), the raw body is dispatched to handlers that resolve the actual repository/stack to mutate from an entirely different, unrelated JSON field: [5](#0-4) 

For example `PushHandler` calls `GithubSyncJob`/`stack.sync_github` using attacker-supplied `after` (expected head SHA) for whatever stack matches `repository.full_name`: [6](#0-5) 

Pull-request handlers similarly resolve `repository` via `params.repository.full_name`, independent of the field used for signature scoping: [7](#0-6) 

**Binding broken:** `repository_owner used to select the verifying secret == repository.full_name used to select the acted-upon stack` — the code assumes these are always the same GitHub-authored repository, but nothing enforces it once the payload is attacker-controlled input to an unauthenticated public endpoint.

### Impact Explanation
An attacker only needs to know (a) the login of any organization configured on this Shipit instance that either has no `webhook_secret` set, or whose secret has leaked/is guessable, and (b) the `full_name` of a stack's repository belonging to *any other* organization hosted on the same instance (repository names are typically public). They can then POST an arbitrary crafted JSON body directly to the public webhooks endpoint with `repository.owner.login` set to the weak org and `repository.full_name` set to the target victim repo. This forges `push`, `pull_request`, `status`/`commit_status`, `membership`, `merge`, `deployable_status`, etc. events for stacks the attacker has no GitHub access to, without possessing any Shipit session, API token, or repository permission. This can drive `GithubSyncJob` with an attacker-chosen `expected_head_sha`, forge commit statuses used as deploy gating checks, or manipulate review-stack lifecycle (archive/unarchive/create) — enabling an unauthorized deploy pathway, satisfying the Critical/High impact bar.

### Likelihood Explanation
The webhooks endpoint is intentionally public and unauthenticated by design (protected only by signature verification), so no session, token, or GitHub access is required — only knowledge of one weakly-configured org on the shared instance, which is a realistic and low-effort precondition for any Shipit deployment that hosts more than one organization.

### Recommendation
Bind signature verification to the same identity used to route the event: after verifying the signature against the org resolved from the payload, re-derive and cross-check that `repository.full_name`'s owner matches the same organization/secret that validated the signature (or reject payloads where they diverge) before dispatching to any handler. Do not allow `verify_webhook_signature` to silently return `true` when `webhook_secret` is unset in a multi-organization configuration; require secrets for all configured organizations.

### Proof of Concept
1. Shipit instance configures two orgs, `weak-org` (no `webhook_secret`) and `victim-org` (secured, hosting a real stack for `victim-org/prod-repo`).
2. Attacker POSTs to `/github/webhooks` (or wherever `WebhooksController` is mounted) with header `X-Github-Event: push` and body:
```json
{
  "repository": {
    "owner": { "login": "weak-org" },
    "full_name": "victim-org/prod-repo"
  },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "weak-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (even absent) `X-Hub-Signature` header [8](#0-7) .
4. `PushHandler#stacks` resolves via `Repository.from_github_repo_name("victim-org/prod-repo")` and triggers `sync_github(expected_head_sha: "<attacker-chosen-sha>")` on the victim's stack, with no signature ever validated by `victim-org`'s actual secret [9](#0-8) .

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          requires :ref
          requires :after
