Investigation confirms a live, exploitable analog of the reported bug class — a missing-guard privilege-escalation via the `ProxyType::is_superset` relation in `pallet-proxy`, essentially the same pattern that phpMyFAQ exhibited (a lower-privileged delegated role able to self-grant a role with capabilities its own scope explicitly excludes). Parity itself already fixed one instance of exactly this bug class in Asset Hub Westend (`NonTransfer`/`Governance`, [1](#0-0) ), but a sibling instance (`NonTransfer`/`Auction`) remains unpatched in the relay-chain runtimes.

### Title
Privilege escalation via unguarded `ProxyType::is_superset(NonTransfer, Auction)` lets a `NonTransfer` proxy self-grant an `Auction` proxy and call `Registrar::swap` - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
`pallet_proxy` authorizes `add_proxy`/`remove_proxy` purely through `ProxyType::is_superset` (checked before `filter`) [2](#0-1) . In `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, `is_superset` uses a blanket rule `(ProxyType::NonTransfer, _) => true`, declaring `NonTransfer` a superset of every other proxy type [3](#0-2) . However, `NonTransfer`'s call filter explicitly *excludes* `paras_registrar::Call::swap` while `Auction`'s filter admits the *entire* `Registrar` pallet (`RuntimeCall::Registrar { .. }`) [4](#0-3) . This is exactly the same inconsistency class that was already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend [1](#0-0) , but the equivalent `NonTransfer`/`Auction` pair on the relay-chain runtimes was never audited or fixed.

### Finding Description
`pallet_proxy::do_proxy` intercepts `add_proxy`/`remove_proxy` calls made through a proxy and rejects them only `if !def.proxy_type.is_superset(proxy_type)`; otherwise it falls through to `def.proxy_type.filter(c)` [5](#0-4) .

In Rococo/Westend/staking-async-rc runtimes:
- `ProxyType::NonTransfer` filter admits `RuntimeCall::Proxy(..)` and `RuntimeCall::Registrar(register{..}) | Registrar(deregister{..}) | Registrar(reserve{..})`, with an explicit code comment "Specifically omitting Registrar `swap`" [6](#0-5) .
- `ProxyType::Auction` filter admits `RuntimeCall::Registrar { .. }` unconditionally — i.e., every Registrar call including `swap` [7](#0-6) .
- `is_superset` nonetheless declares `(ProxyType::NonTransfer, _) => true`, so `NonTransfer.is_superset(Auction) == true` [3](#0-2) .

Because `Proxy(..)` calls (including `add_proxy`) are themselves admitted by `NonTransfer`'s filter, and the superset guard on `add_proxy`/`remove_proxy` is satisfied for the `Auction` target type, a `NonTransfer` delegate can call `Proxy::proxy(real, None, Proxy::add_proxy{delegate: <self>, proxy_type: Auction, delay: 0})` to grant itself an `Auction` proxy over `real`. It can then call `Proxy::proxy(real, Some(Auction), Registrar::swap{...})`, reaching a call that `NonTransfer`'s own filter explicitly denies.

The identical bug class was already found and fixed for the `Governance` proxy type on Asset Hub Westend, with a regression test added specifically to prevent the class from reappearing on another edge of the lattice [8](#0-7) . However, that lattice-consistency test only covers Asset Hub Westend's `ProxyType`; it was never applied to `polkadot/runtime/rococo`, `polkadot/runtime/westend`, or `substrate/frame/staking-async/runtimes/rc`, where the same `NonTransfer`/`Auction` inconsistency exists uncaught.

### Impact Explanation
An account holding only a `NonTransfer` proxy delegation (a routine, lower-trust operational delegation intended to exclude fund/asset-moving and slot-management actions) can escalate to invoke `paras_registrar::swap` on behalf of the delegator. `swap` lets two parachain managers exchange registered para IDs; a delegator that is a parachain manager could have its para ID swapped with an attacker-controlled ID via this path, corrupting parachain-slot bookkeeping — a call the `NonTransfer` proxy was deliberately designed to exclude (per the "Specifically omitting Registrar `swap`" comment). This is an unauthorized-dispatch / privilege-escalation issue in production relay-chain runtime code.

### Likelihood Explanation
Requires only a routinely-granted `NonTransfer` proxy (no privileged role, no governance, no stolen keys) and a `real` account that is registered as a manager of a parachain in `paras_registrar`. `NonTransfer` proxies are the most commonly delegated proxy type. Given Parity's own prior fix and regression test for the sibling `Governance` case, this is a demonstrably real bug class in the same codebase, just on a different runtime and lattice edge that lacks the corresponding safety test.

### Recommendation
Remove `(ProxyType::NonTransfer, _) => true` as a blanket rule in `polkadot/runtime/rococo/src/lib.rs`, `polkadot/runtime/westend/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`; enumerate only the subsets whose filters are fully contained in `NonTransfer`'s filter (i.e., exclude `Auction`, or add `Registrar::swap` handling consistently). Port the `proxy_type_superset_relation_matches_call_filters` lattice-consistency test from `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs` (lines 2486-2516) to these runtimes to prevent regressions on other lattice edges.

### Proof of Concept
Not executed against a live network. Reproduction path (traced via source, not run):
1. `real` grants `attacker` a `NonTransfer` proxy via `Proxy::add_proxy`.
2. `attacker` calls `Proxy::proxy(real, None, Box::new(RuntimeCall::Proxy(add_proxy{delegate: attacker, proxy_type: Auction, delay: 0})))`. This passes both `is_superset(NonTransfer, Auction) == true` and `NonTransfer.filter(Proxy(..)) == true`, registering `attacker` as an `Auction` proxy of `real`.
3. `attacker` calls `Proxy::proxy(real, Some(Auction), Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap{ id: real_para_id, other: attacker_para_id, ... })))`. `Auction.filter` admits `Registrar { .. }` unconditionally, so the call dispatches as `real`, despite `NonTransfer.filter` explicitly denying `Registrar::swap`.

A minimal FRAME integration test analogous to `non_transfer_proxy_is_not_a_superset_of_governance` (`cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2523-2559`) would need to be written against the Rococo/Westend/staking-async-rc `ProxyType` to assert `!ProxyType::NonTransfer.is_superset(&ProxyType::Auction)`; this assertion currently fails (returns `true`) confirming the guard is missing. No such test currently exists in these runtimes, and none was executed as part of this analysis — this is a static-analysis-derived finding, not a confirmed dynamic PoC run.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
