### Title
Stop-hook review-set intersection drops dangerous changes when HEAD diverges from `baseline_sha` without ancestry (branch switch / hard reset / rebase) - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` (which consumes the value returned by `load_baseline_sha`/`consume_stop_state`) computes the Stop-hook review set as `dirty_now ∩ changed_since`, where `dirty_now` is widened with committed-range diffs only when `_is_ancestor(head_at_capture, current_head)` holds. Any normal git operation that advances HEAD without preserving ancestry to the captured baseline (branch checkout to an unrelated branch + commit, `git reset --hard` to a diverged ref, or a rebase onto a different base) makes `dirty_now` empty for the newly-committed file while `baseline_sha` and `head_at_capture` still point at the old, now-unrelated state — collapsing the intersection to the empty set and causing the Stop hook to skip review entirely (`_skip(9)`), even though `changed_since` (diff against `baseline_sha`) would show the dangerous file as changed.

### Finding Description
`load_baseline_sha`/`consume_stop_state` retrieve `baseline_sha` and `head_at_capture` captured at the previous `UserPromptSubmit` [1](#0-0) [2](#0-1) . `handle_stop_hook` feeds these straight into `compute_v2_review_set` [3](#0-2) .

Inside `compute_v2_review_set`, the review set is built as an **intersection** of two sets:
- `dirty_now`: files dirty vs. current HEAD/index, plus (only when `head_at_capture` is an ancestor of the current HEAD) files changed by commits made this turn.
- `changed_since`: files that differ from `baseline_sha` in the *current* working tree. [4](#0-3) 

The ancestry gate is:
```
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
``` [5](#0-4) 

If Claude (potentially steered by attacker/repo-controlled content such as an injected instruction in a README, issue, or code comment) performs a normal git action that moves HEAD to a commit that is **not** reachable from `head_at_capture` — e.g. `git checkout <other-branch>` followed by a commit there, or `git reset --hard <divergent-ref>` — then:
1. `_is_ancestor(head_at_capture, current_head)` returns `False`, so the commit-range diff is never merged into `dirty_now`.
2. After the commit, the working tree is clean relative to the new HEAD, so `tracked_dirty` (from `git status`) is also empty for that file.
3. `dirty_now` therefore does not contain the dangerous file at all.
4. `changed_since` (a plain `git diff --name-only <baseline_sha>` against the *working tree*) does still include the file, since content genuinely differs from the old baseline, but the intersection `dirty_now ∩ changed_since` yields nothing for that file.
5. If no other files are dirty, `review_paths` is empty, and `handle_stop_hook` exits at `_skip(9)` ("empty review set") without ever calling the LLM reviewer or emitting a warning [6](#0-5) .

No existing check compensates: there is no fallback that widens `dirty_now` to `changed_since` when ancestry is broken, and `_is_ancestor` is purely graph-based (branch identity is irrelevant), so a commit on an unrelated branch built on top of `head_at_capture`'s sibling history reliably defeats the review-window computation.

### Impact Explanation
This breaks the stated invariant that a dangerous change introduced during a Claude session cannot be hidden by shifting it outside the computed review window. Because the Stop hook is the last line of defense that forces Claude to continue/fix via `exit(2)` after an LLM security scan [7](#0-6) , silently emptying the review set means a dangerous command/code change committed via a normal branch-switch-and-commit sequence is never scanned, never flagged, and never forces remediation — i.e., a path to unauthorized local command execution or malicious code landing without triggering Claude Code's security-guidance approval/deny controls.

### Likelihood Explanation
The precondition — Claude switching to a different existing branch (or otherwise moving HEAD off the ancestry chain of the captured baseline) and committing there — is an ordinary, unprivileged, and highly plausible action inducible purely through repository content (e.g., a prompt-injected instruction telling Claude to "apply the fix on the `hotfix` branch" or "sync with `origin/main` via `git reset --hard`"). It requires no special privileges, no leaked credentials, and no direct state mutation — only standard git commands run inside the cloned repo, matching the attacker model in the question. The bug is deterministic given the git graph state, so it is fully repeatable.

### Recommendation
When `_is_ancestor(head_at_capture, current_head)` is `False` but `current_head != head_at_capture`, don't rely solely on the ancestor-gated `dirty_now` widening. Instead, fall back to unioning `dirty_now` with `changed_since` (or directly with `_git_name_only(repo, baseline_sha)` against `HEAD`, not just the working tree) whenever HEAD has moved in a non-ancestor way, so committed-but-clean files that differ from the baseline are still included in the review set. At minimum, treat a broken-ancestry HEAD move as a signal to review the full `changed_since` set rather than intersecting it away.

### Proof of Concept
Integration test plan (pytest-style, using a real temp git repo as most existing tests in this suite do):

1. Init repo, create `app.py` with benign content, commit → `H0`. Capture `baseline_sha = capture_git_baseline(cwd)` (≈`H0`) and `head_at_capture = H0`.
2. Create a second branch `git branch other H0; git checkout other`.
3. Edit `app.py` to add a dangerous line (e.g. `os.system(user_input)`), `git add -A && git commit -m "feature"` → `H1` (parent `H0`, but test forces the divergence case, or use `git checkout --orphan other2` before commit / `git reset --hard` to a ref that shares no ancestry to `H0` to simulate real divergence).
4. Call `compute_v2_review_set(cwd, baseline_sha=H0_stash_sha, head_at_capture=H0, untracked_at_baseline={})`.
5. Assert: `review_paths` is expected (by the invariant) to contain the absolute path to `app.py`.
6. Observed failure: when step 2/3 breaks ancestry (`_is_ancestor` returns `False`), `review_paths == []`, demonstrating the dangerous file is dropped from the review set — reproducing `_skip(9)` in `handle_stop_hook`. [8](#0-7)
