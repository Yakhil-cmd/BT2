### Title
Stale spoke listing cached in `Context` is reused for seizure flags and risk params after an in-transaction listing mutation - (File: contracts/controller/src/context.rs)

### Summary
The TLS bug class is "resumed session skips re-validation against a mutated trust store." The controller analog is `Context::cached_spoke_asset`: it loads the spoke asset listing once per invocation and never re-reads it. A liquidation (or supply/borrow/withdraw) validates listing flags and risk params from that cached snapshot, then performs token transfers (`transfer_amount_measured` in `apply_liquidation_repayments`) during which a token transfer hook can execute a *ready* governance operation (`edit_asset_in_spoke` / `set_spoke_asset_flags` / `remove_asset_from_spoke`). The post-mutation seizure path re-calls `enforce_spoke_asset_flags`, but it consults the same stale cache, so a newly activated `no_seize`/`paused` flag or a tightened liquidation tuple is never enforced.

### Finding Description
- `Context::cached_spoke_asset` memoizes the listing in `self.spoke_assets` and returns the cached value on every later read; there is no invalidation hook. [1](#0-0) 
- `build_liquidation_plan` enforces flags on repayment legs (`AllowOnExit`) and seizure legs (`SeizureLeg`, i.e. `no_seize`) using that cache. [2](#0-1) 
- Between planning and seizure, `apply_liquidation_repayments` executes `transfer_amount_measured`, an external token transfer that can invoke a hook on the liquidator/token side. The code itself acknowledges this: "token hooks can reenter first." [3](#0-2) [4](#0-3) 
- The flash guard blocks *controller* reentry but does not block `governance.execute` — a separate contract — and executing a ready operation is permissionless. A hook can therefore flip `no_seize = true` or lower `liquidation_threshold` mid-transaction.
- After the pull returns, `apply_liquidation_seizures`/`apply_liquidation_share_credit` re-invoke `enforce_spoke_asset_flags`, but `cached_spoke_asset` serves the pre-mutation tuple, so the seizure proceeds under the revoked configuration. [5](#0-4) 
- The same stale read feeds `restamp_listed_supply_ltv`/`apply_gated_liquidation_params` in borrow/withdraw flows, so a mid-flow listing edit is also invisible to the LTV/LT restamp and to the HF gate. [6](#0-5) 

This is structurally identical to the advisory: a security decision made against config version *N* is honored after the config is replaced by version *N+1*, because the "session" (the `Context` cache) is resumed without re-checking.

### Impact Explanation
A liquidator (or any unprivileged caller) can seize collateral that governance has just marked `no_seize`, or liquidate under liquidation params that were just tightened — theft of user funds that the flag/param change was specifically intended to protect. The `no_seize` flag exists to make a collateral non-seizable; bypassing the re-check defeats that protection for every account in the spoke for the duration of one transaction.

### Likelihood Explanation
Requires (a) a listed debt token whose `transfer` executes a controllable hook during the repay pull, and (b) a governance operation that is already past its timelock and executable at the moment of the liquidation. Both are attainable by an unprivileged actor: governance execute of a ready operation is permissionless, and the attacker controls the timing by initiating the liquidation themselves. The main mitigations are that the ready-op window must coincide with a liquidatable account, and the exploit needs a token with transfer hooks — for pure SAC markets this vector does not exist, so the practical exposure is limited to hook-capable listed tokens.

### Recommendation
Re-validate the security-relevant listing fields at the point of use rather than serving them from the invocation cache: in `enforce_spoke_asset_flags` (and in `apply_gated_liquidation_params`), read `storage::get_spoke_asset` fresh for seizure/repayment legs, or explicitly invalidate `cache.spoke_assets` after any external token transfer (`transfer_amount_measured`) returns. At minimum, drop the cached entry for each `hub_asset` between the repay pull and the seizure flag check in `process_liquidation`.

### Proof of Concept
1. Governance queues `set_spoke_asset_flags(spoke_id, X, no_seize=true)`; timelock elapses (operation ready).
2. Victim's HF drops below 1; attacker calls `liquidate(liquidator, account_id, debt_payments, SeizeMode::Transfer)` where `debt_payments` uses a hook-capable debt token.
3. `build_liquidation_plan` caches the spoke listing with `no_seize=false` and validates the plan.
4. `apply_liquidation_repayments` calls `transfer_amount_measured`; the token hook executes the ready governance op, writing `no_seize=true` to storage.
5. `apply_liquidation_seizures` calls `enforce_spoke_asset_flags`, which hits `cache.spoke_assets` and sees the stale `no_seize=false`.
6. Seizure succeeds despite the flag — the resumed context never re-checked the mutated config.

    pub(crate) fn cached_spoke_asset(
        &mut self,
        spoke_id: u32,
        hub_asset: &HubAssetKey,
    ) -> Option<SpokeAssetConfig> {
        self.ensure_spoke_context(spoke_id);
        if let Some(cfg) = self.spoke_assets.get(hub_asset.clone()) {
            return Some(cfg);
        }
        let loaded = storage::get_spoke_asset(&self.env, spoke_id, hub_asset)?;
        self.spoke_assets.set(hub_asset.clone(), loaded.clone());
        Some(loaded)
    }

pub(crate) fn restamp_listed_supply_ltv(cache: &mut Context, account: &mut Account) -> bool {
    let mut changed = false;
    let keys = account.supply_positions.keys();
    for hub_asset in keys.iter() {
        let Some(listed) = cache.cached_spoke_asset(account.spoke_id, &hub_asset) else {
            continue;
        };
        let config: AssetConfig = (&listed).into();
        let Some(raw) = account.supply_positions.get(hub_asset.clone()) else {
            continue;
        };
        let mut position = AccountPosition::from(&raw);
        if position.loan_to_value.raw() == config.loan_to_value.raw() {
            continue;
        }
        position.loan_to_value = config.loan_to_value;
        update_or_remove_supply_position(account, &hub_asset, &position);
        changed = true;
    }
    changed
