## Title
CCMenu API endpoint bypasses ApiClient stack scoping, allowing a stack-scoped token to read the CI status of any stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController` authenticates a request using a bearer token (`ApiClient.authenticate`) and, per `Shipit::Api::BaseController`, tokens can be created scoped to a single stack via `ApiClient#stack_id`. Every other API controller resolves the target stack through the scoped `stacks` helper, which restricts lookups to `current_api_client.stack_id` when the client is scoped. `CCMenuController`, however, overrides `stack` to call `Stack.from_param!(params[:stack_id])` directly, bypassing that scope entirely.

### Finding Description
`BaseController#stacks` and `#stack` enforce the "stack a token authorizes" binding: [1](#0-0) 

```
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

`CCMenuController` overrides `stack` and only checks `require_permission :read, :stack` (the operation/scope permission bit, not the stack-id restriction): [2](#0-1) 

Because `stack` is redefined to `Stack.from_param!(params[:stack_id])` (unscoped), the `current_api_client.stack_id` restriction that every other API endpoint honors (`StacksController`, `TasksController`, `HooksController`, etc. via `BaseController#stack`) is never applied here. This breaks the binding: `stack a token authorizes == stack it touches`. Before the fix this binding held for all other API endpoints; on this endpoint it does not — a stack-scoped token is treated as if it were unscoped.

Tokens are explicitly designed to be stack-scoped for exactly this endpoint: `CCMenuUrlController#client` mints a token restricted to `read:stack` and hands the resulting URL (containing the raw bearer token as a query string parameter) to users/CI tools for a specific stack: [3](#0-2) 

The existing test suite for this controller never exercises a stack-scoped `ApiClient` (fixture `here_come_the_walrus`, scoped to stack `:shipit`) against a *different* stack, so the missing scope check is untested: [4](#0-3) 

Compare with `Api::StacksController`, `Api::TasksController`, `Api::HooksController` (all inherit `BaseController#stack`/`#stacks`) which correctly scope lookups, and the tests explicitly validating that scoping: [5](#0-4) 

### Impact Explanation
Any holder of a stack-scoped `read:stack` API token (e.g., a CI dashboard/CCMenu client URL that was leaked, embedded in a public CI config, or shared with a partially-trusted third party for one stack) can use that same token to fetch the CCMenu status (`name`, `activity`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`) of **any** stack in the Shipit instance by simply changing the `stack_id` in the URL — not just the stack it was originally issued for. This is an unauthenticated (relative to that stack) read of stack build/deploy state, matching the "High" impact category of unauthenticated read of stack state.

### Likelihood Explanation
Exploitation requires only possession of a valid `ApiClient` token with `read:stack` permission scoped to some stack (a routine, low-privilege credential intentionally distributed for CCMenu integrations) and knowledge/guessing of another stack's `owner/name/environment` identifier, which is often predictable or discoverable. No additional secrets, GitHub credentials, or webhook signatures are needed.

### Recommendation
Change `Shipit::Api::CCMenuController#stack` to use the scoped lookup consistent with the rest of the API surface:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
removing the `Stack.from_param!` override so that `current_api_client.stack_id` scoping (inherited from `BaseController`) is enforced.

### Proof of Concept
1. As an authorized user, generate a CCMenu URL for Stack A via `GET /ccmenu/*stack_id` (`CCMenuUrlController#fetch`), which creates/returns an `ApiClient` with `permissions: ['read:stack']` and no explicit `stack_id` restriction in this particular helper — but the same vulnerability applies to any deliberately stack-scoped token, e.g. the `here_come_the_walrus` fixture (`permissions: ['read:stack']`, `stack: shipit`).
2. Using that token (`?token=<token>` or Basic auth), issue `GET /api/stacks/<owner>/<name>/<other-environment-or-repo>/ccmenu` for **Stack B**, a stack the token was never scoped to.
3. Because `Api::CCMenuController#stack` calls `Stack.from_param!` directly (bypassing `stacks.from_param!`), the request succeeds and returns Stack B's CCMenu XML (build status, activity, etc.), even though `current_api_client.stack_id` (if set) does not match Stack B.
4. Compare with the equivalent request to `Api::StacksController#show` using the same scoped token and Stack B's id — that request correctly 404s because `BaseController#stack` uses `stacks.from_param!`, confirming the discrepancy is specific to `CCMenuController`.

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
