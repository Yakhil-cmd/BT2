### Title
Cross-organization webhook forgery via decoupled `repository.owner.login` (used for signature selection) and `repository.full_name` (used to locate the target Stack) - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
In multi-organization Shipit deployments, `WebhooksController#verify_signature` picks the HMAC secret to validate an inbound GitHub webhook based on `repository.owner.login` (or `organization.login`) read out of the **unauthenticated** request body, while every event handler locates the actual `Repository`/`Stack` to act on using a *different* field in that same body, `repository.full_name` [3](#0-2) . Because the HMAC only proves "whoever holds Org A's webhook secret produced this exact byte string," and never proves that Org A's secret has any relationship to the repository the body claims to target, a holder of one organization's webhook secret can forge events that mutate a completely different organization's stacks.

### Finding Description
`WebhooksController#verify_signature` computes `repository_owner` from the raw payload (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`) and uses it to select which configured `GitHubApp`/`webhook_secret` to check the `X-Hub-Signature` against [4](#0-3) . Shipit explicitly supports configuring one distinct app/secret per GitHub organization [5](#0-4) [6](#0-5) .

After signature verification passes, `create` dispatches the parsed JSON to handlers keyed only by the `X-Github-Event` header [7](#0-6) . Every handler then independently resolves the target `Repository`/`Stack` using `payload.dig('repository', 'full_name')` — a field that is never cross-checked against `repository.owner.login` [3](#0-2) , e.g. `PushHandler#process` triggers `stack.sync_github` for whatever stacks match that `full_name` and branch [8](#0-7) .

Because HMAC verification is computed over the entire raw body with a secret chosen from a field *inside* that same body, and the field used for authorization-of-secret (`owner.login`) is disjoint from the field used for target-resolution (`full_name`), the signature check only proves the sender knows *some* configured organization's secret — not that this organization is entitled to act on the named repository. This is the binding break: **the organization whose secret authenticated the request ≠ the repository the handlers actually write to.**

### Impact Explanation
A party who legitimately administers (or has otherwise obtained) the webhook secret for Organization A — who is not privileged with respect to Organization B in any way — can set `repository.owner.login` (or `organization.login`) to `"OrgA"` while setting `repository.full_name` to `"OrgB/some-repo"`, sign the whole body with OrgA's secret, and send it to the shared `WebhooksController#create` endpoint. Verification succeeds because it only checks OrgA's secret against the body, then the `push`, `status`, `check_suite`, or `pull_request` handlers act on OrgB's stacks (e.g. triggering `stack.sync_github`, updating commit statuses, archiving/unarchiving review stacks, or updating check-run state) despite the request never being authenticated by anyone associated with OrgB. This crosses a repository/organization trust boundary and enables cross-repository writes on stacks belonging to organizations the attacker has no relationship with.

### Likelihood Explanation
Any tenant of a multi-org Shipit installation who is issued (or leaks) their own organization's webhook secret can construct this payload with no further privilege; the two payload fields are independent JSON keys and neither the controller nor any handler ties `owner.login` to `full_name`.

### Recommendation
After selecting the `GitHubApp` via `repository_owner` and verifying the signature, re-validate that `repository.full_name`'s owner segment matches the same organization used for signature selection (or resolve the `Repository` before dispatch and confirm it belongs to the verified organization) before invoking any handler.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgA` and `OrgB`, each with a distinct `webhook_secret`, and create a Stack for `OrgB/target-repo`.
2. As an entity that only knows `OrgA`'s webhook secret, craft a `push` webhook payload: `{"repository": {"owner": {"login": "OrgA"}, "full_name": "OrgB/target-repo"}, "ref": "refs/heads/main", "after": "<attacker-controlled-sha>"}`.
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(OrgA_webhook_secret, raw_body)>` and POST to `/webhooks` with header `X-Github-Event: push`.
4. `verify_signature` resolves `Shipit.github(organization: "OrgA")` and successfully verifies the signature against OrgA's secret [2](#0-1) ; `PushHandler` then resolves the stack via `full_name = "OrgB/target-repo"` [8](#0-7)  and enqueues `stack.sync_github(expected_head_sha: ...)` for OrgB's stack, despite OrgB never having authorized this request.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
