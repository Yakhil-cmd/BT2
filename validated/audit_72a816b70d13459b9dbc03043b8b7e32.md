### Title
`ProxyType::NonTransfer` on Asset Hub Rococo is an incomplete deny-list that lets a non-transfer proxy move the delegator's funds and assets - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
The reported CVE's root cause is a privacy/permission filter implemented as an incomplete deny-list: it enumerated specific attack surfaces (`<img>` tags) but missed an equivalent one (`background-image` CSS), letting a value it was supposed to block slip through. The Polkadot SDK analog is `ProxyType::NonTransfer::filter` on `asset-hub-rococo`, which is documented as allowing "any call that does not transfer funds or assets" but is implemented as a deny-list that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques` [1](#0-0) . It fails to deny other pallets and calls that move the same delegator's value: `ForeignAssets`, `PoolAssets` (other `pallet-assets` instances), `AssetConversion` swaps/liquidity, `PolkadotXcm` (`transfer_assets`/`teleport_assets`/`send`/`execute`), `Revive` contract calls/instantiations carrying `value`, and `Indices::transfer`/`force_transfer`.

### Finding Description
`pallet_proxy::do_proxy` dispatches the wrapped call under a filtered origin gated by `def.proxy_type.filter(c)` [2](#0-1) . For `ProxyType::NonTransfer` on Asset Hub Rococo, that filter only excludes five pallets by name [3](#0-2) ; any other call, including one added later or already present that moves value, is admitted by default because a deny-list "fails open."

This is exactly the same bug class Parity itself identified and fixed on the sibling `asset-hub-westend` runtime: PR titled *"asset-hub-westend: deny value-moving calls to the `NonTransfer` proxy"* explicitly documents that "the `ProxyType::NonTransfer` call filter is a deny-list and so fails open," and lists `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer` as calls that had been silently reachable [4](#0-3) . The companion PR also fixed a related `is_superset` lattice violation that let `NonTransfer` escalate to `Governance` on that runtime [5](#0-4) . Both fixes were applied only to `asset-hub-westend-runtime` (per the `crates:` section of each prdoc) [6](#0-5) ; the parallel `asset-hub-rococo` runtime, which has the same pallet set (`ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`) and the byte-for-byte same `NonTransfer` deny-list, was not updated and still carries the identical unpatched filter [1](#0-0) .

### Impact Explanation
A delegator who grants a proxy only `ProxyType::NonTransfer` (via `pallet_proxy::add_proxy`) does so under the documented invariant that the delegate cannot move funds or assets. Because the deny-list omits `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive`, that delegate can dispatch, e.g., `RuntimeCall::PolkadotXcm(transfer_assets {...})` or `RuntimeCall::ForeignAssets(Call::transfer {...})` through `Proxy::proxy`, and `def.proxy_type.filter(c)` returns `true`, permitting the transfer. This breaks the confidentiality/authorization invariant of the proxy in the same way the CVE broke the "don't leak read state" invariant: the filter's positive claim ("no value movement") is falsified by an unlisted equivalent path.

### Likelihood Explanation
No privileged role or governance action is required. Any account can create a `NonTransfer` proxy relationship (a normal, permitted `pallet_proxy::add_proxy` extrinsic), and the delegate (who by design is meant to be restricted) can immediately use the unlisted calls. This is directly reachable by any signed account already holding a `NonTransfer` proxy grant on Asset Hub Rococo.

### Recommendation
Port the same fix applied to `asset-hub-westend` (PRs `pr_12769`/`pr_12771`) to `asset-hub-rococo`: extend `ProxyType::NonTransfer::filter` to also deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm` (or at minimum its value-moving calls), `Revive` calls carrying `value`, and `Indices::transfer`/`force_transfer`, matching the documented "cannot transfer funds or assets" policy. Also audit `is_superset` for the same lattice-violation class fixed in `pr_12769`.

### Proof of Concept
Not executed against a live network. Evidence is a static file:line comparison: `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:606-615` shows the vulnerable deny-list [1](#0-0) , contrasted with `prdoc/pr_12771.prdoc` documenting the identical bug being fixed only on `asset-hub-westend-runtime` [7](#0-6) . A local repro would extend the existing westend regression test `non_transfer_proxy_rejects_value_moving_calls` [8](#0-7)  to `asset-hub-rococo-runtime`, asserting `ProxyType::NonTransfer.filter(&value_moving_call)` for `ForeignAssets`/`PoolAssets`/`AssetConversion`/`PolkadotXcm`/`Revive`/`Indices` calls; this was not run in this session, so pass/fail is unverified but the source diff between the two runtimes is confirmed by direct file inspection.

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});

    The following are now denied to a `NonTransfer` proxy:

    - `ForeignAssets` and `PoolAssets` (the other `pallet-assets` instances), which transfer
      value exactly as `Assets` does
    - `AssetConversion`, whose swaps and liquidity operations move the caller's assets
    - `Psm`, whose mint and redeem swap the caller's stablecoins
    - `PolkadotXcm`, whose `transfer_assets`/`teleport_assets` move assets to another chain and
      whose `send`/`execute` can express the same as raw XCM
    - `Revive`, whose contract calls and instantiations carry a `value` to transfer
    - `Indices::transfer` and `Indices::force_transfer`, which repatriate the index's reserved
      deposit to the new owner

    Calls that do not move value are unaffected, including `Indices::claim`/`free`/`freeze` and
    `Vesting::vest`, as are the call families backing the proxy types that `NonTransfer` declares
    as its subsets.

fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
