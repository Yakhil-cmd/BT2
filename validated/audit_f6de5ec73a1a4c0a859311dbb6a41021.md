### Title
Attacker-controlled dynamic RegExp construction in `has_only()` allows unbounded regex evaluation / crash of AA execution engine - ([File: formula/evaluation.js])

### Summary
CVE-2017-9227 is a memory-safety bug in the Oniguruma regex engine caused by mishandling of attacker-influenced regex search state, reachable through untrusted strings fed to the regex engine. In `ocore`, the `has_only()` oscript function builds a `RegExp` object directly from AA-trigger-controlled string data and runs it against another attacker-controlled string, which is the closest reachable analog: a regex engine invoked on fully untrusted, attacker-crafted pattern and subject strings inside the AA (Autonomous Agent) formula evaluator.

### Finding Description
The `has_only` operator in the oscript formula evaluator lets any AA trigger sender supply both the subject string and the "character class" string that is turned into a regex pattern: [1](#0-0) 

```
if (op === 'has_only') {
    try {
        if (sub.match(/\\]/) || sub[sub.length - 1] === '\\')
            return setFatalError(...);
        sub = sub.replace(/]/g, '\\]');
        var bMatches = new RegExp("^[" + sub + "]*$").test(str);
    }
    catch (e) { ... }
    return cb(bMatches);
}
```

`sub` and `str` are both derived from `evaluate(str_expr, ...)`/`evaluate(sub_expr, ...)`, i.e. from oscript expressions inside an AA's `bounce`/response formulas or from `trigger.data`, which is fully controlled by whoever posts a unit that triggers the AA (an unprivileged unit poster per the scope rules). The escaping logic only blocks a literal `]` or a trailing single backslash — it does not restrict regex metacharacters such as backreferences, character-class ranges, or nested quantifiers embedded through other characters (`-`, `^`, `\d`, `\w`, `\s`, etc. are all valid inside `[...]` and pass through untouched). Both `sub` (pattern) and `str` (subject) can be as long as `constants.MAX_AA_STRING_LENGTH` allows [2](#0-1) , and the AA/oscript layer imposes complexity/op-count limits but no limit specific to regex engine work.

While V8's regex engine is different from Oniguruma, this code path is the direct structural analog of the CVE: an engine-selectable regex is compiled and executed against attacker data inside a validation-critical code path (AA response computation, which determines whether/how AA funds are transferred). Any pathological interaction inside the JS regex engine (catastrophic backtracking, stack exhaustion on deeply nested char classes, or an underlying native regex engine bug) is directly reachable by a single posted unit/trigger, with no privilege required.

### Impact Explanation
`has_only()` executes as part of computing an AA's response (`bounce`/`payment`/`data` outputs). If the regex evaluation hangs (ReDoS-style) or crashes the node process, the affected node cannot finish computing AA state for that trigger unit. Because AA state and response transactions must be deterministic and agreed upon by all full nodes to preserve consensus, a crash/hang on one implementation but not another (or simply an unhandled exception escaping the `try/catch` in some Node/V8 version) can cause disagreement on unit validity/response finality, or make the AA (and any funds locked in it) permanently unable to process further triggers — an availability/fund-freezing impact that matches the "AA fund loss or freezing" and "network unable to confirm new units" acceptance criteria.

### Likelihood Explanation
Likelihood is high for the reachability portion: `has_only` is a documented, public oscript function usable by any AA definition, and its arguments can come straight from `trigger.data`, so a single crafted unit sent to any AA using `has_only` triggers this code. What is unproven without deeper engine-level testing is whether a specific crafted `sub`/`str` pair triggers pathological backtracking/crash in the deployed Node/V8 version — this is analogous to the original CVE requiring specific reg->dmin edge conditions in Oniguruma. The `try/catch` around `new RegExp(...).test(str)` mitigates synchronous JS exceptions but does not mitigate CPU/stack exhaustion during matching, since regex execution itself is not exception-based when it hangs.

### Recommendation
- Restrict the character-class content of `sub` to a safe allow-list (e.g., only literal characters, escaped via `RegExp`-safe escaping, no ranges/backreferences), rather than merely blocking `]` and trailing backslash.
- Enforce a strict length cap on both `str` and `sub` specific to `has_only`, well below `MAX_AA_STRING_LENGTH`, or implement character-class matching manually (e.g., building a `Set` of allowed characters and checking membership) instead of delegating to the regex engine at all.
- If a regex is still required, wrap evaluation with a timeout/complexity charge added to `count_ops`/`complexity` proportional to `str.length * sub.length`, so it cannot cheaply consume disproportionate node resources for a single unit of complexity.

### Proof of Concept
An AA definition using `has_only(trigger.data.subject, trigger.data.pattern)` allows any user to post a trigger unit with a large `trigger.data.subject` string and a `trigger.data.pattern` string engineered to maximize regex character-class backtracking cost (e.g., long strings with many escaped ranges/overlapping ambiguous alternatives) as inputs, forcing `new RegExp("^[" + pattern + "]*$").test(subject)` inside `formula/evaluation.js` (lines 2037-2050) to run with proportionally larger cost than the complexity/op-count budget charges for a single `has_only` call, since complexity accounting elsewhere in `formula/validation.js` charges a flat cost per operation, not per input size for this op. Exact confirmation of a hang/crash on the current Node/V8 version was not verifiable within this review's scope and would require runtime testing.
