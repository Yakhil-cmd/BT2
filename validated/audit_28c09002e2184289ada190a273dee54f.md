### Title
Cross-tenant webhook forgery: signature verified against org A's `webhook_secret` but repository resolved from unchecked `repository.full_name`, allowing `LabelCapturingHandler` to mutate org B's `pull_request.labels` - ([File: app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret`) to verify against using `params.dig('repository', 'owner', 'login')`, while `LabelCapturingHandler#repository` resolves the target Shipit `Repository`/stack using the independent `params.repository.full_name` field. Both fields come from the same attacker-suppliable JSON body with no cross-check, so in a multi-organization Shipit deployment an attacker who knows organization A's `webhook_secret` can forge a payload whose `repository.owner.login` is A (to pass signature verification) but whose `repository.full_name` names a repository under organization B, causing `capture_labels` to overwrite B's PR labels.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`org_that_signed(request) == owning_org(params.repository.full_name)`

Trace:
- `WebhooksController#verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)`, which in multi-org mode (`github_default_organization` present) looks up a distinct `GitHubApp` per organization key, each with its own `@webhook_secret` [1](#0-0) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` only confirms that the raw body's HMAC matches the secret belonging to the organization named in `repository.owner.login`; it says nothing about `repository.full_name` [3](#0-2) .
- After signature verification passes, the same parsed `params` (containing the untouched `repository.full_name`) is dispatched to all registered `pull_request` handlers, including `LabelCapturingHandler` [4](#0-3) [5](#0-4) .
- `LabelCapturingHandler#repository` resolves the Shipit repository purely from `params.repository.full_name`, independent of `repository.owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) .
- `capture_labels` then writes `params.pull_request.labels.map(&:name)` directly into `stack.pull_request.labels` [7](#0-6) .

Attack: attacker administers organization A's GitHub App/webhook installation (and thus knows A's `webhook_secret`, per the question's stipulated capability). They POST directly to `/webhooks` with `X-Github-Event: pull_request`, `X-Hub-Signature: sha1=HMAC(webhook_secret_A, raw_body)`, and a JSON body where `repository.owner.login = "orgA"` but `repository.full_name = "orgB/victim-repo"`. `verify_signature` resolves and validates against A's secret successfully (the HMAC is computed over the *entire* raw body regardless of what `full_name` says), while `LabelCapturingHandler` acts on `orgB/victim-repo`, overwriting the labels on B's real, existing PR/stack if one matches the given PR number.

This only diverges from the intended binding in multi-organization Shipit configurations (`secrets.github` keyed per-org, each with its own `webhook_secret`); the divergence exists because no code anywhere compares `repository.owner.login` (or the org implied by the verified secret) against the owner segment of `repository.full_name` before handlers act on it.

### Impact Explanation
A successfully forged request lets an attacker who only controls organization A's webhook configuration overwrite `pull_request.labels` on an entirely different tenant's (organization B's) stack, without ever authenticating against B's secret. Since `ReviewStack#env`/deploy environment derives from PR labels (per the question's stated downstream use), this is a cross-tenant data-integrity break: a payload verified for one repository mutates another repository's stack state, matching the "Critical" category ("a payload for one repository mutating another's stack, commit, task or team"). The attack is repeatable against any repository name the attacker can guess/know (`org/repo` strings are public), for every `pull_request` event action handled (`opened`, `labeled`, `unlabeled`, `reopened`), and does not require any Shipit session, API token, or B's secret.

### Likelihood Explanation
Exploitability requires: (1) Shipit is configured in multi-organization mode with separate `webhook_secret` values per organization (`github_default_organization` set, distinct `secrets.github` entries) — this is a supported, documented configuration in `lib/shipit.rb`, not a single-tenant edge case; (2) the attacker legitimately administers/knows organization A's registered `webhook_secret` (explicitly granted in the threat model); (3) a matching `Repository`/`Stack`/`ReviewStack`/`PullRequest` exists for the target `full_name` and PR number in organization B. Given those preconditions — realistic for any shared, multi-tenant Shipit install — the attacker's cost is a single crafted HTTP POST with a correctly computed HMAC using their own known secret; no interaction with GitHub itself is required. This is directly repeatable at will.

### Recommendation
Enforce the missing binding: after signature verification, validate that `repository.owner.login` (or the organization used to select the verifying `GitHubApp`) matches the owner segment of `repository.full_name` before dispatching to handlers, rejecting (422) any mismatch in `WebhooksController#verify_signature` or in a shared handler pre-check. Alternatively, have `LabelCapturingHandler#repository` (and all other PR handlers using `full_name`) re-derive the repository strictly from `repository.owner.login` + `repository.name`, refusing to trust `full_name` independently, and add an explicit consistency assertion between the two fields at the controller level.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (proof plan, no live GitHub)
test "pull_request payload signed with org A's webhook_secret cannot mutate org B's stack via full_name mismatch" do
  # Precondition: multi-org secrets.github configured with org A and org B, each own webhook_secret
  org_a_secret = Shipit.github(organization: 'orga').send(:webhook_secret) # known to attacker per threat model
  victim_repo = shipit_repositories(:orgb_repo) # full_name "orgb/victim-repo"
  victim_stack = victim_repo.stacks.first
  victim_pr = victim_stack.pull_request # existing PR, labels: []

  payload = {
    action: "labeled",
    number: victim_pr.number,
    pull_request: {
      id: 1, number: victim_pr.number, url: "...", title: "x", state: "open",
      additions: 0, deletions: 0,
      head: { sha: "a" * 40, ref: "feature" },
      user: { login: "attacker" },
      assignees: [],
      labels: [{ name: "malicious-env-injected" }]
    },
    repository: { owner: { login: "orga" }, full_name: "orgb/victim-repo" }, # mismatch: signed by orgA, targets orgB
    sender: { login: "attacker" }
  }.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", org_a_secret, payload)

  post "/webhooks", params: payload, headers: {
    "X-Github-Event" => "pull_request",
    "X-Hub-Signature" => signature,
    "Content-Type" => "application/json"
  }

  assert_response :ok  # signature check passes (binding: signer org == "orga")
  victim_pr.reload
  # Assert the broken binding: full_name's owner ("orgb") != signing org ("orga"), yet the write succeeded
  assert_equal ["malicious-env-injected"], victim_pr.labels,
    "org B's PR was mutated by a payload authenticated only against org A's webhook_secret"
end
```
Both sides of the equality (`repository_owner used to verify signature == owner implied by repository.full_name used to select the mutated stack`) diverge (`"orga" != "orgb"`) yet the request succeeds and the write occurs, confirming the missing webhook-provenance check.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
