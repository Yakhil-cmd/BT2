### Title
Unvalidated swap routes can execute attacker code under the caller’s authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary

Route bytes supplied to `swap_collateral`, `swap_debt`, `multiply`, or `repay_debt_with_collateral` can direct execution to venue and token addresses embedded in the payload. Because the router does not allowlist those addresses, a malicious venue can invoke unrelated token transfers from the caller during the swap; Soroban simulation records that transfer as a child of the caller’s authorization, and enforcement permits it when the caller signs the returned tree. [1](#0-0) 

### Finding Description

`swap_collateral` authorizes the caller and account owner or delegate, then passes attacker-influenced `swap` bytes through `withdraw_and_swap_from_supply` to the generic router path. [2](#0-1) 

`swap_tokens` grants only a bounded transfer authorization for the routed input, but then invokes `SwapAggregatorClient::execute_strategy(controller, amount_in, swap)`. [3](#0-2) 

The post-swap checks verify only the controller’s input balance and positive output receipt; they do not constrain what payload-selected contracts do elsewhere in the invocation. [4](#0-3) 

The authorization helper also bounds only the controller’s input transfer; it does not prevent a malicious nested venue from making an additional call that the user’s root authorization covers. [5](#0-4) 

The harness demonstrates the concrete behavior: a route-selected rogue pool calls `token.transfer(victim, attacker, amount)`, simulation places that transfer beneath the user’s `swap_collateral` authorization, and signing that simulated tree allows the theft while the swap otherwise succeeds. [6](#0-5) 

### Impact Explanation

A victim can lose wallet assets unrelated to the lending collateral, debt markets, or routed amount. The loss is not bounded by `min_out`, the measured router output, or the final health-factor check; in the demonstrated route, the caller’s entire unrelated wallet balance is transferred to the attacker while the expected collateral output is still deposited. [1](#0-0) 

This is theft of user funds and can drain any token whose contract enforces `from.require_auth()` against the signed caller authorization tree. [7](#0-6) 

### Likelihood Explanation

An unprivileged attacker needs to supply a malicious route to a user who executes it and signs the authorization tree generated by simulation. The exploit does not require compromised keys, privileged roles, leaked allowances, or control of a listed market, but it does depend on the victim using a malicious route source or failing to inspect unexpected authorization children. [1](#0-0) 

The reachable production entrypoints include at least `swap_collateral(caller, account_id, current, from_amount, new, swap)` and `swap_debt(caller, account_id, existing_debt, new_debt_amount, new_debt, swap)`; the analogous route-processing path also serves `multiply` and `repay_debt_with_collateral`. [8](#0-7) 

### Recommendation

Do not rely on transaction-level simulation to disclose malicious venue behavior to end users. Restrict executable route destinations to governance-registered venue contracts or immutable venue adapters whose calls are structurally constrained, and reject routes containing unknown token, pool, or venue addresses. [9](#0-8) 

At the client boundary, require the signed controller authorization tree to contain only the expected exact input-transfer children and no other nested invocation. An honest controller strategy should produce no additional caller-authorized child beyond the documented transfer authorization. [10](#0-9) 

### Proof of Concept

1. The attacker deploys a contract with a `swap`-compatible function that calls `wallet_token.transfer(victim, attacker, victim_balance)` when invoked. [11](#0-10) 
2. The attacker constructs route bytes naming that contract as a hop pool and configures a fair `token_out` payment so the swap still satisfies the controller’s measured-output check. [12](#0-11) 
3. The victim calls `controller.swap_collateral(victim, account_id, usdc_key, amount, eth_key, malicious_route)`; the controller authorizes and invokes the configured router with that route. [13](#0-12) 
4. During router execution, the rogue hop transfers the victim’s unrelated wallet token to the attacker. Simulation records that unauthorized-looking transfer as a child of the victim’s root `swap_collateral` invocation. [14](#0-13) 
5. If the victim submits the simulated authorization tree, enforcement accepts the child transfer; the test leaves the victim at zero, credits the attacker with the full wallet balance, and still records the expected `ETH` collateral output. [7](#0-6)

/// Authorizes, on behalf of the current contract, one `transfer(from, to, amount)`
/// call on `token_addr` made deeper in the next contract call (for example by
/// the pool). The entry allows no further sub-invocations.
pub fn authorize_transfer_as_current(
    env: &Env,
    token_addr: &Address,
    from: &Address,
    to: &Address,
    amount: i128,
) {
    let entry = InvokerContractAuthEntry::Contract(SubContractInvocation {
        context: ContractContext {
            contract: token_addr.clone(),
            fn_name: symbol_short!("transfer"),
            args: (from.clone(), to.clone(), amount).into_val(env),
        },
        sub_invocations: Vec::new(env),
    });
    env.authorize_as_current_contract(vec![env, entry]);

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
