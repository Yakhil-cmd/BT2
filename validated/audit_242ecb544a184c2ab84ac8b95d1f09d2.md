### Title
Unsanitized `viewer.login` from attacker-controlled GraphQL host injects extra lines into `git credential approve` stdin, allowing credential/token confinement bypass - ([File: pkg/cmd/auth/shared/git_credential.go])

### Summary
`GetCurrentLogin` in `pkg/cmd/auth/shared/login_flow.go` returns `result.Data.Viewer.Login` verbatim from an unauthenticated-trust GraphQL response, without stripping newlines or validating the username format. This value is passed through `Login` -> `GitCredentialFlow.Setup` -> `gitcredentials.Updater.Update`, where it is interpolated unsanitized into a `heredoc.Docf` block used as stdin for `git credential approve`/`reject`, a line-oriented key=value protocol.

### Finding Description
`GetCurrentLogin` sends the `UserCurrent{viewer{login}}` query to the hostname the victim is authenticating against and decodes the JSON response directly into `result.Data.Viewer.Login` with no validation: [1](#0-0) 

Because the victim explicitly runs `gh auth login --hostname <attacker-host>` (an Enterprise/Garage-style host under attacker control), the attacker fully controls the JSON response body for this request, including the `login` field, and can set it to a multi-line string such as `"monalisa\nhost=evil.example.com"`.

This value flows into `Login()` as `username` when the token-paste auth mode is used or when `authflow.AuthFlow` doesn't already provide one: [2](#0-1) 

then into `opts.CredentialFlow.Setup(hostname, username, authToken)`: [3](#0-2) 

`GitCredentialFlow.Setup` forwards it unmodified to `Updater.Update` when a non-`gh` credential helper (store/cache/etc.) is configured: [4](#0-3) 

`Updater.Update` builds the `git credential approve` stdin via `heredoc.Docf` with straight `%s` substitution of `hostname` and `username`, with no escaping or line-based validation: [5](#0-4) 

Git's credential protocol (used by `git credential approve`) parses stdin as newline-separated `key=value` pairs. Since `username` here is inserted with no newline filtering, a malicious `login` value containing `\nhost=evil.example.com` (or `\nprotocol=...`) will inject additional `host=`/`protocol=` lines into the record that the invoked credential helper (e.g. `git-credential-store`, `git-credential-cache`) parses and persists — potentially binding the freshly-issued `authToken` to an attacker-chosen host/protocol key rather than only the intended `hostname`. No allowlist, safeurl-style validation, or line-sanitization exists anywhere in this path to prevent embedding control characters from the API response into the credential-store protocol stream.

### Impact Explanation
This breaks credential confinement (CREDENTIAL_CONFINEMENT): the OAuth/PAT token that `gh auth login` just obtained for the intended host can be caused to be additionally stored by the system git credential helper under an attacker-chosen host entry. Depending on the exact injected fields and how the specific helper parses overlapping/duplicate keys, this could result in the token being retrievable by git operations against an attacker-specified host, i.e., token disclosure/misrouting to an unintended host. This matches a "credential or token exfiltration / wrong-host credential routing" bounty impact class.

### Likelihood Explanation
Requires: (1) the victim runs `gh auth login --hostname <attacker-host>` against a host the attacker controls (an Enterprise/GHES-style instance, plausible for internal or public "Garage"/self-hosted GHE deployments), (2) victim selects "yes" to configure git credentials interactively, and (3) a non-`gh` git credential helper (store/cache) is configured — the default `ConfigureOurs` path is skipped only if a helper is already configured. These are realistic conditions for many enterprise git configurations. The attacker only needs to control the HTTP response of a GraphQL endpoint on a host the victim intentionally points `gh` at — no MITM, no elevated privileges required beyond controlling that host's responses. This is deterministic and repeatable once conditions are met.

### Recommendation
Sanitize/validate `viewer.login` immediately after decoding in `GetCurrentLogin` (and `api.CurrentLoginName`/`CurrentLoginNameAndOrgs`) — reject or strip any value containing `\n`, `\r`, or other control characters, since GitHub usernames are constrained to a well-known safe character set (alphanumeric and hyphens). Additionally, harden `gitcredentials.Updater.Update` to reject/escape any `hostname`/`username`/`password` value containing newlines before constructing the `git credential` stdin block, defensively preventing protocol injection regardless of the value's origin.

### Proof of Concept
Go test sketch:
1. Use `httpmock` (or a fake `httpClient`) to respond to the `UserCurrent` GraphQL query with `{"data":{"viewer":{"login":"monalisa\nhost=evil.example.com"}}}`.
2. Call `GetCurrentLogin(httpClient, "attacker-host.example", "token123")` and assert it returns the raw multi-line string unchanged (demonstrating no sanitization).
3. Construct a `gitcredentials.Updater{GitClient: fakeGitClient}` backed by `run.Stub()` capturing the `approveCmd.Stdin` passed to `git credential approve`.
4. Call `Updater.Update("attacker-host.example", "monalisa\nhost=evil.example.com", "token123")`.
5. Read the captured stdin buffer and assert it contains an injected `host=evil.example.com` line distinct from the intended `host=attacker-host.example` line — proving the credential record can be steered to an unintended host key, violating CREDENTIAL_CONFINEMENT.

```go
func GetCurrentLogin(httpClient httpClient, hostname, authToken string) (string, error) {
	query := `query UserCurrent{viewer{login}}`
	reqBody, err := json.Marshal(map[string]interface{}{"query": query})
	if err != nil {
		return "", err
	}
	result := struct {
		Data struct{ Viewer struct{ Login string } }
	}{}
	apiEndpoint, err := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "token "+authToken)
	res, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}
	defer res.Body.Close()
	if res.StatusCode > 299 {
		return "", api.HandleHTTPError(res)
	}
	decoder := json.NewDecoder(res.Body)
	err = decoder.Decode(&result)
	if err != nil {
		return "", err
	}
	return result.Data.Viewer.Login, nil
```

```go
func (flow *GitCredentialFlow) Setup(hostname, username, authToken string) error {
	// If there is no credential helper configured then we will set ourselves up as
	// the credential helper for this host.
	if !flow.helper.IsConfigured() {
		return flow.HelperConfig.ConfigureOurs(hostname)
	}

	// Otherwise, we'll tell git to inform the existing credential helper of the new credentials.
	return flow.Updater.Update(hostname, username, authToken)
}
```
