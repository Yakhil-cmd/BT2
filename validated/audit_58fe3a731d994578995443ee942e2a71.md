**Rationale:** CVE-2019-1551 is a defect in OpenSSL's x86_64 assembly implementation of Montgomery squaring (`BN_mod_exp`) affecting 512-bit DH/1024-bit RSA/DSA operations. This is a dependency-only vulnerability in a specific C/assembly cryptographic library implementation, explicitly excluded by the scan rules ("Reject ... dependency-only findings").

The Polkadot SDK does not link against or use OpenSSL for its consensus-critical cryptography; its signature/crypto primitives are implemented in pure Rust (e.g., `sp-core`, ed25519/sr25519/ecdsa crates), and the only `openssl` references found in the codebase are in unrelated tooling scripts, documentation, and a WebRTC networking dependency comment [1](#0-0) , none of which touch runtime-reachable big-number modular exponentiation.

The closest conceptual analog — modular exponentiation exposed to a real user entry point — is the EVM `Modexp` precompile in `pallet-revive`, reachable via a permitted contract call [2](#0-1) . However, this implementation uses the pure-Rust `num_bigint::BigUint::modpow` [3](#0-2)  — a completely different algorithm/codebase from OpenSSL's hand-optimized assembly Montgomery squaring routine that CVE-2019-1551 patched. There is no shared root cause (no analogous carry/overflow bug in the specific squaring optimization path), no re-used private-key scenario, and gas/weight accounting is charged before computation based on bounded input sizes (≤1024 bytes) [4](#0-3) , which is unrelated to the OpenSSL defect's attack surface (DH512 private key reuse).

No demonstrable, reachable analog of the violated invariant (Montgomery squaring overflow enabling private-key recovery) exists in Polkadot SDK production code.
