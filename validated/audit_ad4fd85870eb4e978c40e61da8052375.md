### Title
Credit-mode liquidation rewards are diluted by the same-transaction bad-debt write-down - ([File: contracts/controller/src/positions/liquidation/mod.rs])

### Summary
Analogous to `_rewardBucketTake` minting LP into a bucket that is bankrupt in the same block, `apply_liquidation` in Credit mode mints/credits supply shares to the liquidator's receiver *before* `check_bad_debt_after_liquidation` socializes the residual bad debt. When the seized collateral asset is the same market as the written-down debt (or any market whose supply index is reduced by the cleanup), the shares just credited to the receiver immediately bear their pro-rata slice of the loss in the very same transaction, so the liquidator repays real tokens for collateral whose quoted value is never actually received.

### Finding Description
In `contracts/controller/src/positions/liquidation/mod.rs`, Credit-mode seizure credits shares to the receiver account via `apply_liquidation_share_credit` (lines 86-92), and only afterwards `check_bad_debt_after_liquidation` (line 135) runs `execute_bad_debt_cleanup` when the account still qualifies as insolvent-and-dusty (`apply.rs:301-316`). The cleanup path builds seize entries and calls `pool_seize_positions_call` (`bad_debt.rs:21-49`); for each `Borrow` entry the pool applies `interest::apply_bad_debt_to_supply_index`, which lowers the market's supply index pro-rata across *all* outstanding supply shares (`seize.rs:24-28`), clamped only by the `RAY/1000` floor.

Because the receiver's credited shares are ordinary supply shares added before the write-down runs, the `supplied` total used in `reduction_ray = floor((total_supply - bad_debt) / total_supply)` includes them, and the index reduction devalues them just like any pre-existing supplier. The liquidation plan/bonus (`build_liquidation_plan`, `result.bonus_bps`) is computed on pre-cleanup state and the emitted `LiquidationEvent` reports a bonus that the liquidator never realizes: they transferred real debt tokens (Transfer repayment legs execute before seizure) and received shares that are written down in the same call. The test `bad_debt_promotion_still_fires_after_a_credit_mode_liquidation` confirms cleanup fires in the same transaction after a Credit seizure; nothing orders the write-down before the credit or excludes the just-credited reward.

This is reachable by an unprivileged liquidator (`liquidate` with `SeizeMode::Credit`) on any account where the residual post-liquidation position passes `is_socializable_bad_debt` (debt > collateral, collateral ≤ $5), which is common precisely for dust insolvent accounts that cannot be fully liquidated.

### Impact Explanation
Theft/unfair loss of liquidation payment: the liquidator's repayment tokens are taken, but the collateral reward is devalued by a loss-socialization step the plan never priced in. If residual bad debt approaches the market's remaining supplied value, the index is driven toward the 10^24 floor and the just-credited shares become nearly worthless — the effective outcome approaches the Ajna case where rewards minted at bankruptcy time were entirely voided. At minimum the liquidator receives strictly less than the quoted `bonus_bps`, potentially below break-even.

### Likelihood Explanation
Any Credit-mode liquidation that leaves a socializable residual triggers it; the receiver need do nothing unusual — the loss is imposed on them. It requires same-market overlap between the credited collateral and a written-down debt leg (or multiple debt legs including that market), which is a natural configuration (e.g., user supplies and borrows the same asset).

### Recommendation
Apply the bad-debt write-down to the debt market's supply index before crediting seized shares to the receiver (i.e., run `check_bad_debt_after_liquidation` before `apply_liquidation_share_credit`), or compute the credit against the post-write-down index so the receiver is compensated in fairly-valued shares. Alternatively, exclude same-market credit rewards when cleanup will fire, or revert Credit-mode liquidations that would trigger a same-market write-down so the liquidator can choose Transfer mode.

### Proof of Concept
1. Supplier BOB supplies 100 ETH into the hub/ETH market.
2. ALICE supplies dust USDC collateral and also holds an ETH supply position; she borrows ETH such that a small liquidation leaves residual ETH debt above remaining collateral ≤ $5 (dust gate).
3. USDC price drops; LIQUIDATOR calls `liquidate(ALICE, [ETH payment], SeizeMode::Credit(0))`.
4. `apply_liquidation_repayments` takes LIQUIDATOR's ETH; `apply_liquidation_share_credit` mints ETH supply shares (at pre-write-down index) to the receiver.
5. `check_bad_debt_after_liquidation` → `execute_bad_debt_cleanup` → pool `apply` on the ETH Borrow entry calls `apply_bad_debt_to_supply_index`, lowering the ETH supply index; the receiver's freshly credited shares lose the same pro-rata fraction as BOB.
6. The receiver's redeemable ETH is strictly below `payment * (1 + bonus)`, while the emitted `LiquidationEvent.bonus_bps` still reports the unimpaired bonus — the reward was voided in the same transaction it was granted.
