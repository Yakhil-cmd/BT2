## Title
Stack-scoped API tokens can read the build/deploy status of arbitrary stacks via the CCMenu endpoint - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController` overrides `BaseController#stack` in a way that drops the enforcement of `ApiClient#stack_id` scoping, allowing a token that was only supposed to read one specific stack to read the CCMenu status of any stack in the installation.

### Finding Description
`ApiClient` supports being scoped to a single stack (`belongs_to :stack, optional: true`) [1](#0-0) . `Api::BaseController` enforces this binding for every regular API controller: it restricts the queryable set of stacks to `current_api_client.stack_id` before resolving `params[:stack_id]`: [2](#0-1) 

This is exactly the pattern used to generate scoped CCMenu tokens in the first place — `CCMenuUrlController` mints (or reuses) a `read:stack`-permissioned `ApiClient` and hands the caller a URL containing that token plus a `stack_id` [3](#0-2) . The `here_come_the_walrus` fixture demonstrates a token that is deliberately scoped to a single stack with only `read:stack` permission [4](#0-3) .

However, `Api::CCMenuController` does not use `BaseController#stacks`/`#stack`. It defines its own `#stack` that resolves directly against the global `Stack` relation, ignoring `current_api_client.stack_id` entirely: [5](#0-4) 

`require_permission :read, :stack` only checks that the token has the string permission `"read:stack"` — it never checks *which* stack the token is bound to [6](#0-5) . So the only binding meant to prevent cross-stack reads (`token.stack_id == requested stack`) is skipped for this controller.

### Impact Explanation
This breaks the equality "stack a token authorizes == stack it touches." Any holder of a valid, stack-scoped `read:stack` CCMenu token (which is routinely embedded in a plain URL, e.g. for CI dashboard widgets, and can be authenticated via a `token` query-string parameter rather than a privileged session [7](#0-6) ) can supply an arbitrary `stack_id` and obtain that other stack's name, activity, last build status/label/time — i.e., unauthorized cross-stack read of stack state, matching the in-scope "High" impact category (unauthenticated/under-privileged read of stack state).

### Likelihood Explanation
Likelihood is high once a single low-privilege CCMenu token is known: the caller already has a legitimate, low-scope credential (obtainable by anyone with read access to just one stack via `CCMenuUrlController#fetch`), and only needs to change the `stack_id` request parameter — no additional secret, session, or team membership is required.

### Recommendation
Have `Api::CCMenuController#stack` reuse the scoped `stacks` helper from `BaseController` (i.e. `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so the `ApiClient#stack_id` binding is enforced consistently with every other API controller.

### Proof of Concept
1. As a legitimate user with read access to `stack-A` only, call `CCMenuUrlController#fetch` for `stack-A` to obtain a `read:stack`-scoped `ApiClient` token bound to `stack-A` (`ccmenu_url` response containing `token=<T>`).
2. Send `GET /api/stacks/stack-B/ccmenu.xml?token=<T>` (or any other `stack_id`) using the token minted for `stack-A`.
3. `authenticate_api_client` in `CCMenuController` accepts `<T>` (it is a valid token with `read:stack` permission) [7](#0-6) .
4. `#stack` resolves `stack-B` directly via `Stack.from_param!`, bypassing the `current_api_client.stack_id` check that `BaseController#stacks` would have applied [8](#0-7) .
5. The response renders `stack-B`'s build/deploy status XML even though the token was only authorized for `stack-A`.

```ruby
# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
```
