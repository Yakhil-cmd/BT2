## Title
Unvalidated `status` field in `arbiter_contract_shared` device message allows privilege escalation of arbiter-contract state - (File: wallet.js)

### Summary
The `arbiter_contract_shared` handler in `handleMessageFromHub()` accepts a peer/cosigner-supplied contract object and passes it straight to `arbiter_contract.store()` with `bFromCosigner = true`, which trusts the caller-supplied `status` field. Unlike the sibling `arbiter_contract_offer` handler, which explicitly rejects any attacker-supplied `status`, the `arbiter_contract_shared` handler performs no such check, letting a device that only proves it is *a* cosigner of the receiver's address inject an arbitrary contract lifecycle state (e.g. `"signed"`, `"paid"`, `"accepted"`) for a brand-new, self-fabricated contract record. This mirrors the CVE-2025-66385 pattern of an edit endpoint blindly trusting extra caller-controlled privileged fields (`role_id`) instead of deriving them server-side.

### Finding Description
`store()` in [1](#0-0)  computes the status as `bFromCosigner ? (objContract.status || status_PENDING) : status_PENDING` — i.e. whenever the insert is invoked with `bFromCosigner=true`, the row's `status` (and, since `objContract.shared_address` and `objContract.unit` are also conditionally added, those fields too) come directly from the untrusted payload rather than being computed from the actual contract lifecycle.

The only call site that sets `bFromCosigner=true` is the `arbiter_contract_shared` case in `wallet.js`: [2](#0-1) 

Compare this to the `arbiter_contract_offer` handler a few lines above, which explicitly guards against a caller supplying `status`: [3](#0-2) 

Note line 621-622: `if (body.status) return callbacks.ifError("status must not be submitted in contract offer");` — this defensive check is conspicuously absent from the `arbiter_contract_shared` branch, even though both messages ultimately reach the same `store()` function that trusts `objContract.status`/`shared_address`/`unit` when `bFromCosigner` is true.

The only authorization performed for `arbiter_contract_shared` is that `from_address` (the device that signed the encrypted device message, verified in `device.js` at [4](#0-3) ) must be *some* device listed in `wallet_signing_paths` for `body.my_address` — i.e. any cosigner of a shared/multisig address, not necessarily the wallet owner or the peer who actually negotiated the contract. The `hash` integrity check (`arbiter_contract.getHash(body)`, computed in [5](#0-4) ) only binds `title, text, creation_date, addresses, party names, amount, asset` — it never covers `status`, `shared_address`, or `unit`, so a self-consistent, attacker-fabricated contract (any hash the attacker wants, since they control all hashed fields) can be inserted with an arbitrary status/shared_address/unit combination.

### Impact Explanation
A cosigner of a shared/multisig wallet address — a "paired device" in the trust model, but not necessarily entitled to control that wallet's contract state machine — can inject fabricated `wallet_arbiter_contracts` rows claiming a contract is already `"signed"` or `"paid"` and pointing `shared_address`/`unit` at addresses/units of the attacker's choosing. Because `pay()` at [6](#0-5)  and `complete()` at [7](#0-6)  gate fund movement purely on the locally stored `status`/`shared_address`/`me_is_payer` fields (all attacker-influenced here), the wallet UI can be tricked into directing a real payment to an address controlled by the attacker under the guise of a legitimate arbitrated contract, i.e. concrete unauthorized/misdirected spending. It also lets an unprivileged cosigner desynchronize contract state across devices (bypassing the intended state machine enforced elsewhere, e.g. in `arbiter_contract_update` at [8](#0-7) ), producing disagreement between honest parties about contract/payment status.

### Likelihood Explanation
Exploitation requires the attacker to already be registered as a cosigner device for the victim's wallet address (a "paired device" reachable from a single device message, as scoped by the rules), which is a realistic configuration for multi-party shared/multisig wallets used with arbiter contracts. No additional privilege (e.g. control of the counterparty's device or the arbiter) is required — only a normal `hub/message` device message needs to be crafted with matching hash and status/shared_address/unit set arbitrarily.

### Recommendation
In the `arbiter_contract_shared` handler, reject or ignore attacker-supplied `status`, `shared_address`, and `unit` fields exactly as `arbiter_contract_offer` already rejects `status`; derive these fields server-side from the actual verified state (e.g. always insert with `status_PENDING`/no `shared_address`/`unit` for a freshly-shared contract, and only allow transitions via the already-guarded `arbiter_contract_update` state machine). Also include `status` (and any other privileged field trusted only when `bFromCosigner`) in the `getHash`/signed payload so it cannot be forged without invalidating the hash.

### Proof of Concept
1. Attacker device D2 is a legitimate cosigner (`wallet_signing_paths`) of victim's shared address `my_address`.
2. D2 crafts a fresh contract object with consistent `title/text/creation_date/addresses/amount/asset`, computes `hash = arbiter_contract.getHash(body)`, but sets `status: "paid"`, `shared_address: "<attacker-controlled address>"`, `unit: "<arbitrary/self-chosen unit>"`.
3. D2 sends this as an `arbiter_contract_shared` device message to victim.
4. `wallet.js` `arbiter_contract_shared` handler (lines 658-678) validates only the whitelisted required fields and hash, then calls `arbiter_contract.store(body, true)`.
5. `store()` (lines 91-116) inserts the row using the attacker-supplied `status`, `shared_address`, and `unit` verbatim because `bFromCosigner=true`.
6. Victim's wallet now shows a fabricated "paid"/"signed" contract pointing at the attacker's `shared_address`, potentially leading the victim (or automated `complete()`/`pay()` UI flow) to send further funds to the attacker-controlled address.

function getHashSrc(contract) {
	const payer_name = contract.me_is_payer ? contract.my_party_name : contract.peer_party_name;
	const payee_name = contract.me_is_payer ? contract.peer_party_name : contract.my_party_name;
	const payer_address = contract.me_is_payer ? contract.my_address : contract.peer_address;
	const payee_address = contract.me_is_payer ? contract.peer_address : contract.my_address;
	const src = contract.creation_date > exports.NEW_HASH_DATE
		 ? [contract.title, contract.text, contract.creation_date, payer_address, payer_name || '', contract.arbiter_address, payee_address, payee_name || '', contract.amount, contract.asset || 'null'].join(exports.DELIMITER)
		 : [contract.title, contract.text, contract.creation_date, payer_name || '', contract.arbiter_address, payee_name || '', contract.amount, contract.asset || 'null'].join("");
	return src;
}

function getHash(contract) {
	return crypto.createHash("sha256").update(getHashSrc(contract), "utf8").digest("base64");
}

function pay(hash, walletInstance, arrSigningDeviceAddresses, cb) {
	getByHash(hash, function(objContract) {
		if (!objContract.shared_address || objContract.status !== "signed" || !objContract.me_is_payer)
			return cb("contract can't be paid");
		var opts = {
			asset: objContract.asset,
			to_address: objContract.shared_address,
			amount: objContract.amount,
			spend_unconfirmed: walletInstance.spendUnconfirmed ? 'all' : 'own'
		};
		if (arrSigningDeviceAddresses.length)
			opts.arrSigningDeviceAddresses = arrSigningDeviceAddresses;
		walletInstance.sendMultiPayment(opts, function(err, unit){								
			if (err)
				return cb(err);
			setField(objContract.hash, "status", "paid", function(objContract){
				cb(null, objContract, unit);
			});
			// listen for peer announce to withdraw funds
			storage.readAssetInfo(db, objContract.asset, function(assetInfo) {
				if (assetInfo && assetInfo.is_private)
					db.query("INSERT "+db.getIgnore()+" INTO my_watched_addresses (address) VALUES (?)", [objContract.peer_address]);
			});
		});
	});
}

					});
				});

			});
