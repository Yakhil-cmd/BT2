### Title
Unfunded overpayment refund drains pool custody — repay and recapitalize refund tokens never received - (File: contracts/pool/src/ops/repay.rs)

### Summary
The net-snmp double free frees a resource a second time that the code no longer owns. The analog here is a *release without ownership*: `repay::apply` and `recapitalize::apply` transfer tokens out of pool custody as a "refund" computed purely from the caller-declared `amount`, never from the amount actually received by the pool. An unprivileged caller can declare a large repay against a market with no debt (or a recapitalize above the shortfall), transfer nothing in, and walk away with real pooled tokens.

### Finding Description
`repay::accounting` resolves `overpayment = amount - current_debt_ceil` from the *declared* `action.amount`, credits `net_repay` to cash, and `repay::apply` then executes `outcome.cache.transfer_out(payer, outcome.overpayment)`. The refund path never debits `cash` and never checks `require_reserves` — the doc comment and the regression test both state that neither refund is backed by the cash book.

- `repay::apply` → `transfer_out(payer, overpayment)` at `contracts/pool/src/ops/repay.rs:25-34`, where `overpayment` comes from `resolve_repay(amount, position)` on the declared amount (lines 42-47).
- `recapitalize::apply` → `transfer_out(&payer, outcome.refund)` at `contracts/pool/src/ops/recapitalize.rs:26-38`, where `refund = amount - applied` and `applied = min(amount, backing_shortfall)` (lines 52-55).
- The test at `contracts/pool/tests/flows.rs:3589-3611` demonstrates the primitive directly: `client.repay(&payer, &t.ract(0, custody_before))` on a market with zero debt, with "nothing transferred in", returns `actual_amount == 0` and still drains `custody_before` tokens out of the pool to `payer` via the overpayment refund.

The pool's repay/recapitalize entrypoints perform no inbound measurement on this path — the comment "The controller transfers the repay amount into the pool before this call" is a convention, not an enforced invariant, and `transfer_out` pays the refund out of existing custody regardless of what arrived. The result is exactly the double-free shape: the same custodied tokens are "returned" to a caller who never deposited them, i.e., the resource is released twice — once to the attacker as a refund, while still owed to real suppliers.

### Impact Explanation
Theft of user funds / contract unable to operate from lack of token funds. A single unprivileged address can call `pool.repay` (or `pool.recapitalize` on a market with a small or zero shortfall) with a declared amount up to the pool's token balance, send nothing, and receive the entire declared amount back as a refund. Repeatable until the pool is empty; all suppliers' underlying is drained.

### Likelihood Explanation
High: it requires no special state, no price movement, no flash loan — only a direct call to a permissionless pool entrypoint with a fabricated `PoolAction`/`amount`. The only prerequisite is that the pool holds custody (which is its normal state), and for the pure-drain variant, a `(hub, asset)` book with no outstanding debt or with debt smaller than the declared amount.

### Recommendation
Measure inbound tokens (balance delta of the pool before/after pull, or pull via `transfer_from` inside the op) and compute `overpayment`/`refund` against the *received* amount, not the declared `action.amount`. Additionally, route refunds through `require_reserves`/`debit_cash` semantics so a refund can never exceed what this call deposited.

### Proof of Concept
```rust
// Mirror of contracts/pool/tests/flows.rs::test_unfunded_repay_overpayment_refund_also_pays_out_of_custody
let t = TestSetup::new();
let token = token::Client::new(&t.env, &t.asset);
let attacker = Address::generate(&t.env);      // holds zero tokens

let custody_before = token.balance(&t.pool);   // e.g. suppliers' deposits
assert_eq!(t.state_snapshot().borrowed, 0);    // market with no debt

// Declare a repay equal to entire custody; transfer nothing in.
let credited = t.client()
    .repay(&attacker, &t.ract(0, custody_before))
    .get_unchecked(0)
    .actual_amount;

assert_eq!(credited, 0);                                // no debt retired
assert_eq!(token.balance(&attacker), custody_before);   // full custody refunded
assert_eq!(token.balance(&t.pool), 0);                  // pool drained
```
The same shape applies to `recapitalize(hub_asset, payer, amount)`: declare `amount` far above `backing_shortfall`, and `refund = amount - applied` is paid from custody.

Note: whether `pool.repay` enforces any caller check beyond the arguments shown could not be fully confirmed within available iterations (`lib.rs` entrypoint signature was not read); the existing test's ability to drain custody with an arbitrary `payer` address and zero inbound transfer strongly indicates no such gate exists on this path.
