### Title
Hookify PreToolUse security rules fail open for any tool outside a hardcoded Bash/Edit/Write/MultiEdit set - (File: `plugins/hookify/hooks/pretooluse.py`)

### Summary
`hookify`'s `PreToolUse` hook is supposed to enforce user-authored blocking/warning rules (e.g. "block edits to `.env`", "block `rm -rf`") on every tool call, matching the report's pattern of a permission-check gate whose scope doesn't match what the guarded action actually needs. The gate is keyed off a hardcoded `tool_name` → `event` mapping that only recognizes `Bash`, `Edit`, `Write`, and `MultiEdit`; for every other tool the enforced "event" is `None`, and the field extractor that determines whether a rule matches also only knows the field names used by those four tools. Just like `reassignGlobalAdmin` silently fails to enforce its intended access control when the checked role (`TIMELOCK_ROLE`) doesn't line up with what the downstream calls actually require (`ADMIN_ROLE`), hookify's blocking rules silently fail to fire when the tool actually invoked doesn't line up with the hardcoded set the hook was written for.

### Finding Description
`pretooluse.py` derives the rule-matching `event` purely from a fixed tool-name check: [1](#0-0) 

For any tool not in `{Bash, Edit, Write, MultiEdit}` — e.g. `NotebookEdit`, `WebFetch`, `Task` (subagent), or an MCP-provided write/exec tool — `event` stays `None`. `load_rules(event=None)` does not filter by event when `event` is falsy, so it loads (unfiltered) every rule, of every configured `event` type: [2](#0-1) 

Whether a rule then actually blocks the call depends on `_check_condition` → `_extract_field`, which only knows how to pull field values (`command`, `file_path`, `new_text`, etc.) for `Bash`, `Write`/`Edit`, and `MultiEdit` tool-input shapes: [3](#0-2) 

Because a rule like a "block edits to `.env`" (`event: file`, `field: file_path`) or "block dangerous shell command" (`event: bash`, `field: command`) can never resolve its condition field for tools outside the hardcoded set, `_extract_field` returns `None`, `_check_condition` returns `False`, and the rule silently never matches — the operation is allowed with `{}` (empty decision), exactly as if no rule existed: [4](#0-3) 

The gate that the user configured (a hookify `block` rule intended to be a hard security control on file writes or command execution) is checked against the wrong scope of the actual attack surface (all tools that can write files or execute commands), mirroring the report's root cause: an authorization check whose enforced condition does not match the actual set of paths the protected action can be reached through.

### Impact Explanation
Any project relying on hookify `action: block` rules for security enforcement (e.g. `.env`/credential-file protection, dangerous-command blocking as documented in `plugins/hookify/README.md` and `plugins/hookify/commands/help.md`) gets a false sense of protection: the block silently does not apply to file-modifying or command-executing tools outside `Bash`/`Edit`/`Write`/`MultiEdit` — such as `NotebookEdit` writing into a notebook file, an MCP filesystem/write tool, or a `Task` subagent invoking one of these. An unprivileged agent turn (model-driven tool selection, or a crafted prompt that steers the model toward an unlisted tool) can perform the exact operation the user's rule was written to block, with no warning and no `deny` decision emitted — a hook-bypass leading to unauthorized file write/command execution relative to user intent.

### Likelihood Explanation
This triggers automatically, with no special privilege, whenever the model (or an attacker who can influence its tool choice, e.g. via prompt injection in project content) uses any tool other than the four hardcoded ones to perform the sensitive action a hookify rule was meant to block. Since hookify's blocking rule set is explicitly marketed as a way to "prevent unwanted behaviors" (`plugins/hookify/commands/help.md` lines 12, 38-41), the mismatch is easy to trigger and not defense-in-depth — it is often the only configured control.

### Recommendation
Do not special-case `event` inference and field extraction by a hardcoded tool-name list. Either (a) always pass the tool's `tool_input` dict generically to a field extractor that looks up by declared `field` name directly (falling back to `None` only when truly absent), and treat every `PreToolUse` call as candidate for rules of `event: all` and any event whose declared field is present in `tool_input`, or (b) explicitly enumerate every registered tool (including MCP/plugin tools) that can write files or run commands and route them to the correct `event`/field mapping. Additionally, `load_rules(event=None)` should not implicitly mean "load rules of every event" — an unresolved event should either use `event='all'`-only rules or raise/log so a mismatch is visible rather than silently applying (or skipping) rules the author didn't intend.

### Proof of Concept
1. Add `.claude/hookify.block-env.local.md`:
```markdown
---
name: block-env-writes
enabled: true
event: file
action: block
conditions:
  - field: file_path
    operator: contains
    pattern: .env
---
Blocked: do not write .env files.
```
2. Ask Claude Code to write secrets into a `.env`-named file using the `Write` tool → the hook correctly emits `permissionDecision: deny` (rule matches, `tool_name == 'Write'`, `event == 'file'`).
3. Ask Claude Code to perform the equivalent write using a tool not in `{Bash, Edit, Write, MultiEdit}` (e.g. `NotebookEdit` targeting a path containing `.env`, or any MCP filesystem-write tool with a different `tool_input` schema). `pretooluse.py` computes `event = None` for that `tool_name`; `load_rules(None)` returns the rule anyway, but `_extract_field('file_path', 'NotebookEdit', tool_input, ...)` finds no direct `file_path` key match for `NotebookEdit`'s actual input shape and returns `None`, so `_check_condition` returns `False` and `evaluate_rules` returns `{}` — the write proceeds with no block and no warning, despite the user's explicit blocking rule.

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)
