### Title
Membership webhook lets a client-asserted `team.slug`/`member.login` forge `Shipit.github_teams` authorization - (File: app/models/shipit/webhooks/handlers/membership_handler.rb)

### Summary
`Shipit.github_teams` is resolved once via `Team.find_or_create_by_handle` against real GitHub team data [1](#0-0) , and `User#authorized?` trusts local `Membership` rows to decide if a user belongs to one of those teams [2](#0-1) . The `MembershipHandler` writes those `Membership` rows purely from webhook body fields (`team.id`, `organization.login`, `member.login`) with no cross-check against GitHub, and is reachable once `verify_signature` is bypassed by an org with `webhook_secret: nil` (the Q1 finding) [3](#0-2) [4](#0-3) .

### Finding Description
Broken binding: `Membership(user_id, team_id) exists in DB` should equal `GitHub org team membership fact retrieved/verified from GitHub`. Instead, the handler establishes the equality purely from attacker-controlled webhook JSON.

Path:
1. `WebhooksController#verify_signature` calls `Shipit.github(organization: repository_owner).verify_webhook_signature(sig, raw_post)` [5](#0-4) . `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `@webhook_secret` is blank [4](#0-3) , and `head(422)` is not followed by a `return`, so processing continues into `create` regardless of the verification outcome for a nil-secret org (Q1 bypass).
2. `Shipit::Webhooks.for_event('membership')` dispatches to `MembershipHandler` [6](#0-5) .
3. `MembershipHandler#process` calls `find_or_create_team!`, which does `Team.find_or_create_by!(github_id: params.team.id) { |team| team.github_team = params.team; team.organization = params.organization.login }` — every field (`id`, `name`, `slug`, `url`) comes straight from the request body [7](#0-6) . If `params.team.id` matches the `github_id` of a `Team` already materialized into `Shipit.github_teams` (e.g. via `lib/tasks/teams.rake` or prior legitimate sync) [8](#0-7) , the existing row is reused directly — the attacker doesn't even need to guess a fresh id, just the id of a privileged team, which is discoverable (team ids are not secret, e.g. visible via GitHub's public team API or the `handle` used in config).
4. `User.find_or_create_by_login!(params.member.login)` creates/looks up a `User` purely by the attacker-supplied login string [9](#0-8) ; the attacker asserts their own GitHub login here.
5. `case params.action; when 'added'; team.add_member(member)` appends the `Membership` row unconditionally [10](#0-9)  and `Team#add_member` just appends without any GitHub round-trip [11](#0-10) .
6. `User#authorized?` subsequently returns `true` because `teams.where(id: Shipit.github_teams.map(&:id)).exists?` matches the forged `Membership` [2](#0-1) .

No guard revalidates team membership against GitHub at authorization time — `authorized?` is a pure DB lookup, and nothing in `MembershipHandler` calls GitHub's API to confirm the asserted `added`/`removed` event actually happened. `drop_unhandled_event` and `ExplicitParameters` schema only validate shape, not provenance — `membership` is a registered handled event and the schema happily accepts any attacker-chosen `team.id`/`slug`/`name`/`url`, `organization.login`, and `member.login` [12](#0-11) .

This is a direct combination of the Q1 signature-bypass with an unauthenticated write into the authorization table.

### Impact Explanation
An attacker for any org configured with `webhook_secret: nil` (this is explicitly the documented default in `config/secrets.development.example.yml` and `test/dummy/config/secrets.test.json`, i.e. a supported, not-hardened configuration) can POST a forged `membership` `added` event naming their own GitHub login and a `team.id` matching an org team included in `Shipit.github_teams`. This flips `User#authorized?` to `true` for that attacker, granting them everything gated by `authorized?` (repositories/stacks management pages, deploy authorization checks, etc., per usages in `app/controllers/concerns/shipit/authentication.rb` and `stacks_controller_test.rb`). This matches the "escalation into `Shipit.github_teams` authorization" High-severity category. The attack is repeatable at will and works per-organization wherever `webhook_secret` is unset; it is not limited to a single request.

### Likelihood Explanation
Preconditions: the target organization's GitHub App config in Shipit has no `webhook_secret` set (a real, documented possibility, not a hypothetical misconfiguration — see the example/dummy secrets files), and `Shipit.github_teams` is non-empty (i.e., the deployment actually restricts access by team, which is precisely when this matters). The attacker needs only the numeric GitHub team `id` of one of the configured teams, which is not a secret (visible to any member via GitHub UI/API, or inferable from public org team listings). No Shipit credentials, session, or GitHub token are required. Cost is a single unauthenticated HTTP POST.

### Recommendation
`MembershipHandler` must verify team membership by calling back to the GitHub API (e.g. `Team#refresh_members!`, which already exists and re-derives membership from `github_api.get(api_url).rels[:members]`) rather than trusting the webhook body to create `Team`/`Membership` rows directly. At minimum, on `membership` events, re-fetch team membership from GitHub instead of blindly calling `team.add_member(member)`/`team.members.delete(member)` off client-supplied fields. This is independent of, but compounded by, fixing the Q1 nil-`webhook_secret` bypass in `verify_signature`.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "forged :membership event escalates an unauthenticated attacker into Shipit.github_teams authorization" do
  # Precondition: org configured with webhook_secret: nil (as in test/dummy secrets.test.json)
  # and Shipit.github_teams includes shipit_teams(:shopify_developers)
  Shipit.stubs(:github_teams).returns([shipit_teams(:shopify_developers)])

  @request.headers['X-Github-Event'] = 'membership'
  # No X-Hub-Signature header sent at all (Q1 bypass path)

  attacker_login = 'attacker'
  Shipit.github.api.expects(:user).with(attacker_login).returns(stub(
    id: 999, name: 'Attacker', login: attacker_login, email: 'a@a.com',
    avatar_url: 'https://example.com/a.png', url: 'https://api.github.com/users/attacker'
  ))

  post :create, as: :json, body: {
    action: 'added',
    team: {
      id: shipit_teams(:shopify_developers).github_id, # publicly known team id
      name: 'Developers', slug: 'developers', url: 'http://example.com'
    },
    organization: { login: 'shopify' },
    member: { login: attacker_login }
  }.to_json
  assert_response :ok

  attacker = User.find_by(login: attacker_login)
  refute_nil attacker
  assert attacker.authorized?, "unauthenticated webhook body granted github_teams authorization"
end
```
Before the fix, `attacker.authorized?` is `true` after a single unsigned POST; after adding GitHub-side re-verification of team membership, the assertion fails because no real GitHub membership backs the forged event.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    class << self
      def find_or_create_by_handle(handle)
        organization, slug = handle.split('/').map(&:downcase)
        find_by(organization:, slug:) || fetch_and_create_from_github(organization, slug)
      end

      def fetch_and_create_from_github(organization, slug)
        return unless github_team = find_team_on_github(organization, slug)

        create!(github_team:, organization:)
      end

      def find_team_on_github(organization, slug)
        gh_api = Shipit.github(organization:).api
        teams = Shipit::OctokitIterator.new(github_api: gh_api) { gh_api.org_teams(organization, per_page: 100) }
        teams.find { |t| t.slug == slug }
      rescue Octokit::NotFound
      end
    end
```
