Confirmed: `parent_units` can contain 1 to `constants.MAX_PARENTS_PER_UNIT` units [1](#0-0) , yet `object_length.js` charges a fixed size for the field regardless of the actual count, using a hardcoded constant sized for exactly 2 parent units [2](#0-1) . This is the same bug class as the CVE: a fixed-size allocation/accounting constant that does not track the actual variable-length structure it represents, so once the structure legitimately grows beyond the assumed size, the accounting becomes wrong for everyone using it.

### Title
Fixed 2-parent size constant in `getHeadersSize()` undercounts real header size for units with 3+ parents - ([File: object_length.js])

### Summary
`object_length.js` hardcodes `PARENT_UNITS_SIZE = 2*44` bytes and `PARENT_UNITS_KEY_SIZE = "parent_units".length`, and `getHeadersSize()` always adds exactly this constant instead of computing the size from the actual `parent_units` array length [3](#0-2) . However, a valid unit is permitted to declare between 1 and `constants.MAX_PARENTS_PER_UNIT` parent units — `validateParentsExistAndOrdered` only rejects units whose `parent_units.length` exceeds `MAX_PARENTS_PER_UNIT`, allowing e.g. 3, 4, or more parents (only AA-generated units are capped at 2) [1](#0-0) [4](#0-3) .

`getHeadersSize()` deletes the real `parent_units` field from the header object before computing length and substitutes the fixed 2-parent-sized constant unconditionally: `delete objHeader.parent_units; ... return getLength(objHeader, bWithKeys) + PARENT_UNITS_SIZE + (bWithKeys ? PARENT_UNITS_KEY_SIZE : 0);` [5](#0-4) . This is directly analogous to the r8169 bug: a structure/array that can legitimately have more elements than the size constant assumes, with the size constant never updated to reflect the true content length.

### Finding Description
The declared `headers_commission` for a unit must exactly equal `objectLength.getHeadersSize(objUnit)` per `validate()` [6](#0-5) , so `getHeadersSize` is the network-wide, deterministic authority on how much a poster is charged for header bytes. Because `PARENT_UNITS_SIZE` is a compile-time constant for exactly 2 parents (`2*44`) rather than `objUnit.parent_units.length * 44`, any unit that legitimately posts 3 or more parent units (which is allowed up to `MAX_PARENTS_PER_UNIT`) is charged the same headers_commission as a 2-parent unit — the actual byte content of the extra parent unit hashes (44 bytes each) is not billed. Conversely, if a unit had only 1 parent, it would still be charged for 2, overcharging that unit, but the more consequential case is undercharging.

Since every full node runs the identical `getHeadersSize` function, all nodes agree on this (wrong) size, so this does not create validation disagreement or a fork; however, it produces a fee-metering flaw at the protocol level: unit posters can obtain "free" bytes for the extra parent hashes by using additional parents beyond the assumed 2, since the deterministic commission formula never bills for them.

### Impact Explanation
This does not cause memory corruption in JS the way it did in the kernel driver, since the function under study returns a JS Number, not a fixed native buffer. The consequence in ocore is a fee/spam-accounting defect: units with more than 2 parents get a discount on `headers_commission` for the un-billed extra parent hash bytes, which is a form of fee evasion / storage-cost externalization — network storage grows (extra parent-unit hash references) without proportional payment, which over time could be leveraged by any unprivileged unit poster to reduce their storage fees while consuming more DAG storage than paid for. It does not enable double-spend, supply inflation, or AA fund loss, and it does not cause node disagreement (deterministic function, same result everywhere), so it does not meet the "network unable to confirm new units" or "node disagreement" bar required by the validation rules.

### Likelihood Explanation
Trivially reachable by any ordinary unit poster: parent selection with more than 2 parents is a normal, permitted DAG operation (only bounded by `MAX_PARENTS_PER_UNIT`), requiring no special privilege, hub cooperation, or malicious peer behavior.

### Recommendation
Compute `PARENT_UNITS_SIZE` dynamically as `objUnit.parent_units.length * 44` (and the key-size contribution as `objUnit.parent_units.length * "parent_units".length` or equivalent) inside `getHeadersSize()` instead of using a fixed 2-parent constant, mirroring the correct accounting done elsewhere in the codebase for variable-length arrays (e.g., message and input arrays in `getLength`).

### Proof of Concept
1. Compose and broadcast a normal unit `A` with exactly 2 parent units; note its `headers_commission` as computed/validated by `getHeadersSize`.
2. Compose a second unit `B` that is otherwise structurally identical but selects 4 valid, unrelated free-hanging parent units (permitted since `MAX_PARENTS_PER_UNIT` typically allows more than 2, and `validateParentsExistAndOrdered` only checks the upper bound) [1](#0-0) .
3. Observe that `getHeadersSize(B)` returns the same header size contribution for parent_units as `getHeadersSize(A)` (both add the fixed `PARENT_UNITS_SIZE = 2*44` plus one `PARENT_UNITS_KEY_SIZE`), even though `B.parent_units` contains 88 more raw bytes (2 extra 44-byte hashes) that are never included in the header size or the `headers_commission` charged [5](#0-4) .
4. Confirm both units pass `validate()`'s headers_commission equality check despite `B` storing more DAG-parent data per byte paid than `A`.

function getHeadersSize(objUnit) {

		throw Error("trying to get headers size of stripped unit");

	delete objHeader.unit;
	delete objHeader.headers_commission;
	delete objHeader.payload_commission;
	delete objHeader.oversize_fee;
//	delete objHeader.tps_fee;
	delete objHeader.actual_tps_fee;
	delete objHeader.main_chain_index;
	if (objUnit.version === constants.versionWithoutTimestamp)
		delete objHeader.timestamp;
	delete objHeader.messages;
	delete objHeader.parent_units; // replaced with PARENT_UNITS_SIZE
	var bWithKeys = (objUnit.version !== constants.versionWithoutTimestamp && objUnit.version !== constants.versionWithoutKeySizes);
	return getLength(objHeader, bWithKeys) + PARENT_UNITS_SIZE + (bWithKeys ? PARENT_UNITS_KEY_SIZE : 0);
