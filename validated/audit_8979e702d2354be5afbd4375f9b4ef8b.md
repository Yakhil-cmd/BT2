### Title
Cross-repository `PullRequest` record poisoning via `repository.owner.login`/`repository.full_name` mismatch on no-secret organization - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) using `params.dig('repository','owner','login')`, while `AssignedHandler` resolves the target repository/stack using the independent field `params.repository.full_name`. Because these two attacker-controlled fields are never required to be consistent, an attacker who owns/controls a GitHub organization configured in Shipit with no `webhook_secret` can forge a `pull_request`/`unassigned` payload whose `repository.owner.login` is that no-secret org (bypassing signature verification entirely) while setting `repository.full_name` to the victim's real repository, causing `AssignedHandler` to update the victim's persisted `Shipit::PullRequest` record.

### Finding Description
The broken binding the code should enforce is:
`authenticated_org(webhook_secret_used) == target_repository_owner(record_mutated)`

i.e., the organization whose secret validated the HMAC signature must be the same organization that owns the repository/stack being mutated.

Trace:
1. `verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-49) computes `repository_owner` from `params.dig('repository','owner','login')` (or `organization.login`) and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`.
2. `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83) returns `true` unconditionally `unless webhook_secret` — i.e. if the org resolved in step 1 has no `webhook_secret` configured, **any** raw body/signature is accepted.
3. Once accepted, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` runs with the fully attacker-controlled JSON body, including `params.repository.full_name` — a field completely separate from `repository.owner.login` and never cross-checked against it.
4. `AssignedHandler#pull_request` (app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb:53-65) resolves the repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, then looks up `Shipit::PullRequest.joins(:stack, stack: :repository).find_by(number: params.number, stacks: { repositories: { id: repository.id } })` — scoped entirely by `full_name`, not by the `owner.login` used for authentication.
5. `process` then calls `pull_request.update(github_pull_request: params.pull_request)` (line 44), overwriting the victim's persisted `PullRequest` record's cached GitHub metadata (title, state, assignees, labels, head sha/ref, additions/deletions) with attacker-supplied data.

The exploit request: an unprivileged attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or an arbitrary one), and a JSON body where `repository.owner.login` = `<no-secret-org>` (some org configured in Shipit's `github_teams`/organizations list but lacking `webhook_secret`), `repository.full_name` = `<victim-org>/<victim-repo>` (the real target), `action` = `unassigned`, and `number` = an existing victim PR number. Because step 2 short-circuits to `true`, the forged payload is processed against the victim's actual `Repository`/`Stack`/`PullRequest` records.

Existing guards fail because: `drop_unhandled_event` only checks the event type is registered, not authenticity; `verify_signature` authenticates using a field (`owner.login`) that is disjoint from the field used to select the mutated record (`full_name`); there is no invariant anywhere in `WebhooksController` or `Handler` that ties the authenticated organization to the resolved `Repository`/`Stack`. The "commit SHA" lookup mechanism hypothesized in the question does not actually exist in `AssignedHandler` — it resolves purely by PR `number` + `full_name` join, not by SHA — so the SHA-collision amplifier described is not the actual mechanism, but it is unnecessary: the `owner.login`/`full_name` divergence alone is sufficient to achieve full cross-repository state mutation.

### Impact Explanation
An unprivileged attacker who registers/controls any GitHub organization present in Shipit's configuration without a `webhook_secret` can forge webhook events that mutate `PullRequest` records belonging to any other configured repository/stack, entirely bypassing signature authentication. This is a cross-tenant record-mutation primitive: "a payload for one repository mutating another's stack, commit, task" — matching the Critical impact category. The blast radius extends to every handler in `Shipit::Webhooks` that resolves its target via `repository.full_name` rather than the authenticated `owner.login` (e.g. `ClosedHandler`, `LabeledHandler`, `OpenedHandler`, `ReopenedHandler`, `UnlabeledHandler`, `EditedHandler` all call `from_github_repo_name` the same way), not just `AssignedHandler`. Repeatable per request, against arbitrary target repositories, as long as the attacker knows/guesses a victim PR number and full_name.

### Likelihood Explanation
Requires: (a) at least one GitHub organization configured in Shipit without a `webhook_secret` (a real-world misconfiguration explicitly acknowledged by the "no-secret organization" scenario name), and (b) the attacker knowing the victim's `repository.full_name` and an existing PR `number` in that stack (both are public/guessable GitHub information, not secret). No Shipit session, API token, or GitHub secret is required. Attacker cost is a single unauthenticated HTTP POST. Fully repeatable and scriptable against any victim stack.

### Recommendation
In `Shipit::WebhooksController#verify_signature`, do not allow signature verification to trivially pass for organizations without a configured secret (fail closed, not open, when `webhook_secret` is blank) or, at minimum, require the resolved `Repository`'s actual owner (looked up server-side via `Repository.from_github_repo_name(payload.dig('repository','full_name'))`) to match the organization used for signature verification before dispatching to handlers. Enforce this equality check once in `Handler#call`/`WebhooksController#create`, not per-handler.

### Proof of Concept
minitest plan (test/controllers/webhooks_controller_test.rb or test/models/shipit/webhooks/handlers/pull_request/assigned_handler_test.rb style):

```ruby
test "pull_request unassigned event with owner.login pointing to a no-secret org still mutates a victim repo's PullRequest when full_name differs" do
  # Setup: victim stack/repo/PR
  victim_repo = shipit_repositories(:shipit) # full_name e.g. "shopify/shipit-engine"
  victim_stack = victim_repo.stacks.first
  victim_pr = create_pull_request(stack: victim_stack, number: 42, title: "legit title")

  # Configure a "no-secret-org" GitHubApp: Shipit.github(organization: "attacker-org") returns config with no webhook_secret
  Shipit.stubs(:github).with(organization: "attacker-org").returns(
    Shipit::GitHubApp.new("attacker-org", { app_id: 1, installation_id: 1 }) # no webhook_secret key
  )

  forged_payload = {
    action: "unassigned",
    number: 42,
    pull_request: {
      id: 1, number: 42, url: "http://example.com", title: "PWNED",
      state: "open", additions: 0, deletions: 0,
      head: { sha: "deadbeef", ref: "attacker-branch" },
      user: { login: "attacker" },
      assignees: [], labels: []
    },
    repository: { full_name: victim_repo.full_name, owner: { login: "attacker-org" } },
    sender: { login: "attacker" }
  }.to_json

  post shipit.webhooks_path, params: forged_payload,
       headers: { "X-Github-Event" => "pull_request", "X-Hub-Signature" => "sha1=bogus",
                   "CONTENT_TYPE" => "application/json" }

  assert_response :ok
  victim_pr.reload
  # Assert the binding is broken: attacker (unauthenticated for victim org) mutated victim's record
  assert_equal "PWNED", victim_pr.title
end
```

Assertions on both sides of the equality:
- Before: `authenticated_org = "attacker-org"` (no secret, signature auto-passes) while `target_repository.owner = victim_repo.full_name.split('/').first` — these differ, and the request should be rejected (422).
- After (current buggy behavior): request returns `200 OK` and `victim_pr.title == "PWNED"`, proving the mismatch was never checked and the victim's record was mutated by a payload that never authenticated against the victim's organization.
