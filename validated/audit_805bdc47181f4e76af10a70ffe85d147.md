### Title
Webhook signature verification is keyed by an attacker-controlled `repository.owner.login` field, decoupling "organization authenticated" from "repository written" - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App / webhook secret to verify against using `repository_owner`, a value read directly out of the unauthenticated JSON body, *before* the signature has been checked. The handlers that actually mutate state (e.g. enqueue `GithubSyncJob`) key off a different field in that same unauthenticated body — `repository.full_name`. Because these two fields are never cross-checked, an attacker can pick an organization whose webhook secret is unset (or otherwise weak) to make `verify_webhook_signature` trivially pass, while pointing `repository.full_name` at a stack belonging to a completely different, properly-secured organization. This breaks the binding: `organization that authenticated == repository that is written`.

### Finding Description
`verify_signature` derives the org used to fetch the `GitHubApp` purely from request JSON, prior to any cryptographic check: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` unconditionally accepts the payload if that org's `webhook_secret` is blank (a state explicitly documented as an allowed/optional configuration): [3](#0-2) 

Multi-org config resolves the app purely by the (attacker-supplied) org name from the payload, with no relation enforced back to the target repository being acted upon: [4](#0-3) 

Once `verify_signature` passes (because the chosen decoy organization has no secret configured), `WebhooksController#create` dispatches the full, attacker-controlled body to event handlers: [5](#0-4) 

Those handlers locate the affected `Stack`/`Repository` using `repository.full_name` from the same body — a field completely independent of `repository.owner.login` used for the signature-secret lookup — as evidenced by existing tests that enqueue `GithubSyncJob` keyed to whatever stack matches the payload's repository, and only no-op when no matching repository exists in the datastore: [6](#0-5) 

So the equality the engine implicitly (and incorrectly) assumes is:
`org used to select webhook_secret (repository.owner.login)` == `org/repo actually written to (repository.full_name)`

These are two independent, attacker-controlled fields inside the same unsigned-at-selection-time JSON body, so the equality does not hold.

### Impact Explanation
This crosses the "cross-repository writes / unauthorized deploy" boundary called out as Critical/High: an attacker with no Shipit session, no `ApiClient` token, and no GitHub push access can forge a `push`, `status`, or `check_suite` webhook naming an org with no configured `webhook_secret` for verification, while setting `repository.full_name` to a real, tracked stack belonging to a different, fully-secured organization. This can force `GithubSyncJob` to sync an attacker-chosen `expected_head_sha` into that stack, or forge `status`/`check_suite` results, potentially green-lighting merges or deploys of attacker-chosen revisions on a repository the attacker does not control.

### Likelihood Explanation
Requires: (1) a deployment using the multi-org config schema in `secrets.github` with at least one org that has `webhook_secret` unset — a state the docs present as legitimate/optional — and (2) knowledge of the target repository's `full_name`, which is typically visible on the Shipit stack list itself. No credentials, tokens, or GitHub repository access are needed, so this is reachable by any external, unauthenticated attacker able to POST to `/webhooks`.

### Recommendation
After resolving `repository_owner` and verifying the signature, re-derive and enforce that the repository/organization named in `repository.full_name` (or `organization.login`) actually belongs to the same organization whose secret was used to authenticate the request, rejecting the webhook otherwise. Additionally, treat a missing/blank `webhook_secret` as a hard misconfiguration to warn about rather than silently authorizing all requests for that org (`return true unless webhook_secret` in `lib/shipit/github_app.rb`).

### Proof of Concept
1. Shipit is configured with two orgs in `secrets.github`: `open-org` (no `webhook_secret` set) and `secure-org` (proper `webhook_secret`), each with tracked stacks.
2. Attacker sends `POST /webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": {
    "owner": { "login": "open-org" },
    "full_name": "secure-org/victim-repo"
  },
  "after": "<attacker-chosen-sha>"
}
```
3. `repository_owner` resolves to `open-org`; `Shipit.github(organization: "open-org")` returns a `GitHubApp` with blank `webhook_secret`; `verify_webhook_signature` returns `true` regardless of the (missing/garbage) `X-Hub-Signature` header.
4. `create` dispatches the parsed body to push handlers, which look up the `Stack`/`Repository` via `repository.full_name` = `secure-org/victim-repo` and enqueue `GithubSyncJob` with `expected_head_sha` = attacker-chosen sha, affecting `secure-org`'s stack despite the request never being authenticated against `secure-org`'s secret.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

**File:** lib/shipit.rb (L170-200)
```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
