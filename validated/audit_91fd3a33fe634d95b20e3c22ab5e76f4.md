### Title
Cross-organization team lookup by `github_id` allows an unrelated org's webhook to delete a victim operator's team `Membership` - (File: app/models/shipit/webhooks/handlers/membership_handler.rb)

### Summary
`MembershipHandler#find_or_create_team!` resolves `Team` records solely by `params.team.id` (GitHub's global numeric team ID), with no check that the payload's `organization.login` (used for signature verification) actually owns that team. Because Shipit explicitly supports multi-tenant configurations where several independent GitHub orgs each hold their own `webhook_secret` (`Shipit.github_app_config`, `github_organizations`), an attacker who legitimately controls one onboarded org can sign a `membership` webhook with `action: 'removed'` and an arbitrary `team.id`/`member.login`, causing Shipit to delete an unrelated victim's `Membership` row and deauthorize them.

### Finding Description
The broken binding: `Membership(team_id, user_id)` should only be mutated by a webhook whose verified signing organization equals `team.organization` (the org that actually owns that GitHub team). Instead, the code enforces only `github_id == params.team.id`: [1](#0-0) 

`WebhooksController#verify_signature` verifies the HMAC signature using `Shipit.github(organization: repository_owner)`, where `repository_owner` is taken directly from the attacker-controlled payload (`organization.login` for membership events): [2](#0-1) 

Each org in a multi-tenant deployment has its own independent `webhook_secret`, resolved via `Shipit.github_app_config`: [3](#0-2) 

An attacker who owns/administers their own onboarded GitHub org (a supported, documented configuration — "Using Multiple Github Applications") knows their own org's `webhook_secret` and can produce a valid signature for a payload where `organization.login` is their own org, while `team.id` is set to the victim's real, already-existing `Team.github_id`. `verify_signature` passes (it only checks the signature against the attacker's own org's secret — it never checks that this org owns the referenced team). `find_or_create_team!` then does `Team.find_or_create_by!(github_id: params.team.id)`, which finds the pre-existing victim `Team` row (since `github_id` already exists in the DB), regardless of the fact that the signing organization has nothing to do with it. `User.find_or_create_by_login!(params.member.login)` resolves the real victim operator by login. `team.members.delete(member)` then deletes the legitimate `Membership` row for a team/org the attacker never belonged to.

No existing guard closes this gap: `verify_signature` only proves the payload's claimed org signed it, not that the claimed org is authoritative for the referenced `team.id`; the `ExplicitParameters` schema only validates types/presence, not cross-object ownership; `Team.find_or_create_by!` intentionally ignores `organization` in its lookup key.

### Impact Explanation
A successful request flips `User#authorized?` from `true` to `false` for a legitimate operator, because `authorized?` depends on `teams.where(id: Shipit.github_teams.map(&:id)).exists?`: [4](#0-3) 
This is a cross-tenant write — an attacker's own org's webhook mutates state (`Membership`) belonging to a completely different org/team — matching the "payload for one repository mutating another's stack/commit/task/team" Critical category. It is repeatable against any team whose numeric `github_id` the attacker can determine, and against any operator's login (which is generally public), for as long as the attacker's own org remains configured with Shipit.

### Likelihood Explanation
Requires: (1) a multi-tenant Shipit deployment where the attacker's own GitHub org is a legitimately onboarded tenant (a documented, supported configuration), giving the attacker a real `webhook_secret` they control; (2) knowledge of the victim team's numeric `github_id` and the victim operator's GitHub `login`, both of which are frequently discoverable (public org/team pages, prior webhook deliveries, GitHub API for public teams). No Shipit or victim-org secrets are needed. Cost is a single signed HTTP POST to `/webhooks`.

### Recommendation
In `find_or_create_team!`, scope the lookup by both `github_id` AND `organization` (matching `params.organization.login`), rejecting/dropping the event if an existing `Team` with that `github_id` belongs to a different organization than the one that signed the webhook. More generally, `verify_signature` should validate that the signing organization matches every organization-scoped entity referenced in the payload before handlers mutate it.

### Proof of Concept
```ruby
test "cross-org membership webhook cannot delete another org's membership" do
  victim_team = shipit_teams(:shopify_developers) # organization: 'shopify', github_id: 1
  victim_user = shipit_users(:walrus)
  Membership.create!(team: victim_team, user: victim_user) unless victim_team.members.include?(victim_user)

  # Attacker's own org, separately configured with its own webhook_secret
  Shipit.stubs(:github).with(organization: 'attacker-org').returns(
    Shipit::GitHubApp.new('attacker-org', webhook_secret: 'attacker-secret')
  )

  payload = {
    action: 'removed',
    team: { id: victim_team.github_id, name: victim_team.name, slug: victim_team.slug, url: victim_team.api_url },
    organization: { login: 'attacker-org' },
    member: { login: victim_user.login }
  }.to_json

  signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', 'attacker-secret', payload)}"
  @request.headers['X-Github-Event'] = 'membership'
  @request.headers['X-Hub-Signature'] = signature

  assert_difference -> { Membership.count }, -1 do
    post :create, body: payload, as: :json
    assert_response :ok
  end

  assert_not victim_user.reload.authorized?
end
```
Both sides of the binding diverge: signature verifies `organization.login == 'attacker-org'`, but the mutated `Membership` belongs to `team.organization == 'shopify'` — the equality `signing_org == team.organization` is never checked before the write.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([

    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
