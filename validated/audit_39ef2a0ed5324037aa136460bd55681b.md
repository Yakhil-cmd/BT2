### Title
Liquidation's "remaining collateral repayable" check uses the maximum liquidation penalty instead of the borrower's actual graduated penalty, enabling premature bad-debt socialization onto all vault suppliers - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
In `liquidate()`, the decision to trigger bad-debt socialization (`no-collateral-left`) depends on `other-debt-repayable`, a value meant to estimate whether the borrower's *other* (not-yet-seized) collateral could still cover the remaining debt. That estimate is computed using the hardcoded `liq-penalty-max` group parameter instead of the position's actual graduated `liq-penalty` that was computed moments earlier for the same liquidation via `calc-liquidation-params`. This mirrors the H-11 bug class: a wrong/mismatched fee-like parameter fed into a formula that gates a shared accounting operation (`socialize-debt-asset` → `vault-socialize-debt`, which writes down the vault's `lindex` for every depositor), rather than the correct, already-derived value.

### Finding Description
During liquidation, the graduated penalty is computed once for the whole call: [1](#0-0) 

and used correctly to size the expected collateral for the asset actually being liquidated: [2](#0-1) 

However, when the same function evaluates whether the borrower's *remaining* collateral in other assets could still repay the leftover debt (used purely to decide if the position is "fully drained" and bad debt should be socialized), it substitutes `liq-penalty-max` for the graduated `liq-penalty`: [3](#0-2) 

Because `liq-penalty-max >= liq-penalty` by construction of `calc-liq-factor-bound`, using the max penalty in the denominator (`BPS + liq-penalty-max`) systematically understates `other-debt-repayable` relative to what the borrower's remaining collateral could actually cover at the position's true (lower) graduated penalty. In the borderline/dust cases this check exists for, this understatement can round `other-debt-repayable` down to `u0` when it should be strictly positive, flipping `no-collateral-left` to `true` prematurely.

When `no-collateral-left` is true, the code immediately folds the borrower's remaining debt entries into `socialize-debt-asset`, which calls `vault-socialize-debt` and writes down the vault's `lindex` (liquidity index) shared by all depositors of that vault: [4](#0-3) [5](#0-4) 

`lindex` is the shared state consumed by every zToken/vault-share holder's exchange rate: writing it down early — while the borrower still had recoverable collateral in another asset — permanently transfers a real, avoidable loss onto every supplier of that vault, none of whom took any action to cause it.

- Attacker: the liquidator calling `liquidate()` on a partially-liquidated position (unprivileged, permissionless).
- Victim: all depositors/suppliers of the debt vault whose `lindex` gets written down.
- Shared state: `lindex` (vault liquidity index), primed/consumed identically for every supplier.

### Impact Explanation
Without the bug, `other-debt-repayable` correctly reflects the graduated-penalty-adjusted repayable value of the borrower's remaining collateral; if positive, the market waits for a follow-up liquidation of the other asset instead of socializing debt. With the bug, a liquidator can force `other-debt-repayable` to round to zero (using the harsher max-penalty denominator) even though real recoverable value remains, triggering `socialize-debt-asset` immediately. That call reduces `lindex` for the entire vault, permanently diluting the redeemable value of every zToken/share holder in that vault — a loss they did not need to bear, since the borrower's residual collateral could have covered it. This lands in the "socialization charged to all suppliers" category and constitutes a permanent, unwarranted freezing/loss of supplier value (Critical/High class: protocol insolvency-adjacent socialization / permanent loss of yield for suppliers).

### Likelihood Explanation
The check is only reachable in the exact edge case it was written for — the last sliver of a position's collateral being liquidated — which is precisely where rounding to zero is most likely (small USD residuals divided by an artificially inflated `BPS + liq-penalty-max` denominator through `mul-div-down`/`mul-div-up`). Any liquidator can trigger this by choosing to liquidate the smaller/majority collateral asset first, leaving a small "other" balance that this flawed check evaluates. No special privileges or governance action are required.

### Recommendation
Use the position's actual graduated `liq-penalty` (already computed via `calc-liquidation-params` earlier in the same function) instead of `liq-penalty-max` when computing `other-adj`/`other-debt-repayable` at: [6](#0-5) 

so the "is there still recoverable value" estimate is consistent with the penalty that would actually apply to that collateral if liquidated, preventing premature socialization of debt that a borrower's remaining collateral could still cover.

### Proof of Concept
1. Borrower has two collateral assets, A and B, and one debt asset D. `ltv-liq-partial`/`ltv-liq-full`/`liq-penalty-min`/`liq-penalty-max` are set such that at the borrower's current LTV the graduated penalty `liq-penalty` = 500 bps, while `liq-penalty-max` = 1000 bps.
2. Liquidator calls `liquidate(borrower, A, D, ...)`, fully seizing asset A (`coll-removed` equals `user-coll-balance`, `coll-final` computed from `scale-debt-for-liquidation`).
3. Asset B remains with a small residual USD value, e.g. `other-coll-usd` = a dust amount X such that:
   - `X / (BPS + liq-penalty) ` (using the correct 500 bps) rounds, after token conversion, to a nonzero `other-debt-repayable`.
   - `X / (BPS + liq-penalty-max)` (using the buggy 1000 bps) rounds down to `u0` after the `mul-div-down`/`mul-div-up` chain in [7](#0-6) .
4. `other-debt-repayable` evaluates to `u0`, so `no-collateral-left` is `true` even though asset B still had recoverable value under the correct graduated penalty.
5. `socialize-debt-asset` is invoked on the borrower's remaining debt [8](#0-7) , which calls `vault-socialize-debt`, writing down `lindex` for asset D's vault [9](#0-8) , permanently reducing the redemption value for every unrelated depositor of that vault — even though the correct penalty calculation shows the debt was not actually unrecoverable.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
