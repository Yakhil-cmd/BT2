### Title
Unvalidated Peer-Supplied Staking Info Written to Persistent DB During Fast Sync Corrupts Reward Distribution — (`datasync/downloader/queue.go`)

---

### Summary

During fast sync, `DeliverStakingInfos` in `datasync/downloader/queue.go` accepts `P2PStakingInfo` payloads from any connected peer with a completely no-op validation function (marked `TODO`). Every other data type — bodies, receipts — is validated against a cryptographic commitment in the block header before being accepted. Staking info is not. The unvalidated data is then written unconditionally to the node's persistent `MiscDB` and is later read back as the authoritative source for reward distribution on pre-Kaia blocks, allowing a malicious peer to redirect KAIA block rewards to attacker-controlled addresses.

---

### Finding Description

**Step 1 — No-op validation in `DeliverStakingInfos`**

`DeliverBodies` validates transaction data against `header.TxHash`; `DeliverReceipts` validates against `header.ReceiptHash`. `DeliverStakingInfos` has a stub that unconditionally returns `nil`:

```go
// datasync/downloader/queue.go:956-958
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
```

There is no check that the received `NodeIds`, `RewardAddrs`, or `StakingAmounts` match the on-chain AddressBook state at the corresponding block root.

**Step 2 — Unvalidated data written to persistent DB**

`commitFastSyncData` and `commitPivotBlock` write whatever arrived from the peer directly to the node's key-value store:

```go
// datasync/downloader/downloader.go:1881-1884
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
```

`PutStakingInfoToDB` calls `WriteStakingInfo` which does a raw `db.Put` with no further checks.

**Step 3 — DB is the authoritative source for pre-Kaia reward distribution**

`GetStakingInfo` reads the DB first for any block before the Kaia hardfork, and returns without falling back to on-chain state if a DB entry exists:

```go
// kaiax/staking/impl/getter.go:58-63
if !isKaia {
    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)
        return si, nil
    }
}
```

**Step 4 — Staking info drives KAIA reward distribution**

`FinalizeState` calls `GetDeferredReward`, which calls `GetStakingInfo`, and then calls `state.AddBalance` for every address in the returned `RewardAddrs` / `StakingAmounts`:

```go
// kaiax/reward/impl/blockstate.go:46-55
spec, err := r.GetDeferredReward(header, txs, receipts)
...
for addr, amount := range spec.Rewards {
    state.AddBalance(addr, amount)
}
```

**Step 5 — Second unvalidated write path: `SyncStakingInfo`**

The admin-triggered `SyncStakingInfo` recovery path also writes peer-supplied staking info to the DB with only a `BlockNum` equality check — no validation of addresses or amounts:

```go
// datasync/downloader/downloader.go:672-679
for _, stakingInfo := range stakingInfos {
    if d.stakingInfoRecoveryBlocks[0] != stakingInfo.BlockNum {
        // error
    }
    d.stakingModule.PutStakingInfoToDB(stakingInfo.BlockNum, staking.ToStakingInfo(stakingInfo))
}
```

---

### Impact Explanation

A malicious peer serving a fast-syncing node can supply `P2PStakingInfo` with:
- **Inflated `StakingAmounts`** for a validator it controls → that validator receives a disproportionately large share of staking rewards.
- **Substituted `RewardAddrs`** → block rewards for legitimate validators are redirected to attacker-controlled addresses.
- **Removed validators** → their staking reward share is redistributed to the proposer or other validators.

The corrupted DB entry is then used by `GetStakingInfo` → `GetDeferredReward` → `state.AddBalance` during `FinalizeState` for every pre-Kaia block the node subsequently processes, resulting in **unauthorized minting/transfer of KAIA to attacker-controlled addresses** and **denial of legitimate validator rewards**.

---

### Likelihood Explanation

- **Trigger**: Any peer that connects to a node performing fast sync can supply fabricated staking info. No special privilege is required beyond being a registered P2P peer.
- **Scope**: Affects nodes fast-syncing to a chain height before the Kaia hardfork. After the Kaia hardfork, `GetStakingInfo` bypasses the DB and reads directly from state, so the corrupted entries have no effect on post-Kaia blocks.
- **Persistence**: The corrupted entry is written to the persistent `MiscDB` and cached in the LRU, so it survives node restarts and affects all subsequent pre-Kaia block processing on that node.

---

### Recommendation

1. **Validate staking info content against the block header's state root.** Re-execute the AddressBook multicall against the state at `header.Root` and compare the result to the peer-supplied data before accepting it. This mirrors how `DeliverReceipts` validates against `header.ReceiptHash`.

2. **Remove the no-op stub.** Replace the `// TODO-Kaia-Snapsync update validation logic` placeholder with a real check, or reject staking info delivery entirely until validation is implemented.

3. **In `SyncStakingInfo`, validate content against on-chain state** before calling `PutStakingInfoToDB`, not just the block number.

---

### Proof of Concept

```
1. Attacker runs a Kaia node and registers as a peer with a victim node
   that is performing fast sync (FullSync or FastSync mode).

2. Victim node calls handleStakingInfoRequestMsg → peer.RequestStakingInfo(hashes).

3. Attacker intercepts the request and responds with a crafted P2PStakingInfo:
     BlockNum:       <legitimate block number, e.g. 86400>
     NodeIds:        [<legitimate validator address>]
     RewardAddrs:    [<attacker-controlled address>]   // ← substituted
     StakingAmounts: [999_999_999]                     // ← inflated

4. handleStakingInfoMsg → pm.downloader.DeliverStakingInfos(peerId, fabricated)
   → queue.DeliverStakingInfos → validate() returns nil (no-op)
   → result.StakingInfo = fabricated

5. commitFastSyncData:
     d.stakingModule.PutStakingInfoToDB(86400, fabricated)
   Fabricated entry now persists in MiscDB.

6. Node completes fast sync and begins processing new pre-Kaia blocks.
   FinalizeState → GetDeferredReward → GetStakingInfo(num):
     isKaia = false
     sourceNum = 86400
     ReadStakingInfo(db, 86400) → returns fabricated entry (cache hit)
   assignStakingRewards uses fabricated StakingAmounts and RewardAddrs.
   state.AddBalance(attacker_address, large_reward_amount)

Result: KAIA block rewards are transferred to the attacker's address
        instead of the legitimate validator's reward address.

func (s *StakingModule) GetStakingInfo(num uint64) (*staking.StakingInfo, error) {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(new(big.Int).SetUint64(num))
	sourceNum := sourceBlockNum(num, isKaia, s.stakingInterval)

	// Try cache first
	if si, ok := s.stakingInfoCache.Get(sourceNum); ok {
		return si.(*staking.StakingInfo), nil
	}

	// Only before Kaia, try the database
	if !isKaia {
		if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
			s.stakingInfoCache.Add(sourceNum, si)
			return si, nil
		}
	}

	// Read from the state
	si, err := s.getFromStateByNumber(sourceNum)
	if err != nil {
		return nil, err
	}

	// Only before Kaia, write to database
	if !isKaia {
		WriteStakingInfo(s.ChainKv, sourceNum, si)
	}

	// Cache it
	s.stakingInfoCache.Add(sourceNum, si)
	return si, nil
}

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
