### Title
Retroactive attestor list changes freeze already-held outputs of a `spender_attested` asset - (File: [validation.js](validation.js))

### Summary
`ThunderNFT` bug: a strategy operator can de-list a strategy at any time, and `ThunderExchange.cancel_order()` hard-requires `is_strategy_whitelisted()`, so any seller whose order used the de-listed strategy can no longer withdraw an NFT they already own — a mutable, definer-controlled whitelist that gates spending of already-held property. ocore has a directly analogous mechanism for `spender_attested` assets: the asset definer can freely change the `attestors` whitelist at any time via an `asset_attestors` message, and payment validation re-checks attestation membership at spend time (not at receipt time), so coins already held by a previously-attested address become permanently unspendable the moment the definer edits the list.

### Finding Description
An asset can be created with `spender_attested: true` plus an `attestors` list [1](#0-0) . Spending (transferring) that asset requires the *spender* (and, for divisible/public assets, every output address) to currently appear in the attested-address list computed from the *latest* attestor list at validation time:
- Payment validation loads `arrAttestedAddresses` fresh for the current unit and rejects if the payer isn't attested: [2](#0-1) 
- The transfer-side, input-owner check re-verifies attestation for every spent input, both for public/divisible assets and for private fixed-denomination assets: [3](#0-2) [4](#0-3) 
- Output addresses receiving the asset are likewise required to be currently attested: [5](#0-4) 

The attestor list itself is not immutable — the asset *definer* (the entity analogous to the "protocol team" in the report) can post a new `asset_attestors` message at any time to replace it, the only requirements being single-authorship and being the definer: [6](#0-5) . Attestation membership is resolved dynamically by joining current on-chain `attestations` against whichever attestor(s) are named in the *most recent* `asset_attestors` unit for the asset, not the list in effect when the coin was received: [7](#0-6) [8](#0-7) .

This is the same bug class as the ThunderNFT report: a mutable, issuer/operator-controlled allow-list gates the ability to move an asset a user already legitimately possesses, and the check is enforced retroactively/continuously rather than only at issuance/acquisition time.

### Impact Explanation
If the definer of a `spender_attested` asset removes an attestor (or replaces the attestor set) such that a holder's address is no longer attested, every subsequent attempt by that holder to spend their existing output — a normal transfer, not an attack — will be rejected by `validatePaymentInputsAndOutputs`/`validatePayment` with "none of the authors is attested" / "owner address is not attested" / "some output addresses are not attested". The holder's coins become frozen in place with no way to move them until (and unless) the definer re-adds the relevant attestor/attestation, which may never happen (e.g., if the attestor was de-listed because it was compromised or discontinued). This is a fund-freezing condition equivalent in kind to the ThunderNFT "strategy de-listing locks seller's NFT," reachable by an ordinary token holder who did nothing wrong, triggered purely by an ordinary, permitted definer action.

### Likelihood Explanation
`spender_attested` and `asset_attestors` are first-class, documented asset features (present in schema, `divisible_asset.js`, `indivisible_asset.js`, and AA asset-issuance support), so any asset issuer can create such an asset and later rotate attestors for entirely legitimate reasons (attestor key compromise, provider discontinuation, policy change). No special privilege beyond being the asset's own definer is required, and the check re-evaluates attestation at every spend using the latest stable attestor-list unit, so the freeze triggers automatically as soon as the update unit becomes stable — no additional attacker action needed.

### Recommendation
Decouple spend-eligibility from the *current* attestor list: either (a) snapshot/grandfather attestation status at the time an output is created so already-received coins remain spendable regardless of later attestor list changes, or (b) allow a two-state transition (e.g., a "paused" attestor list) where holders whose attestation was revoked retain a limited ability to withdraw/transfer back to the definer or to themselves, rather than being unconditionally blocked by `arrAttestedAddresses.indexOf(owner_address) === -1` in `validation.js`.

### Proof of Concept
1. Definer creates asset `A` with `spender_attested: true`, `attestors: [X]`.
2. Attestor `X` attests holder `H`; `H` receives an output of asset `A` (validated per `validatePayment`, `validation.js:2115-2122`).
3. Definer later posts `asset_attestors` naming a new list that no longer includes `X` (or the definer changes `X`'s attestation policy so `H` is no longer attested) — permitted per `validateAttestorListUpdate`, `validation.js:2829-2847`.
4. `H` attempts to spend the previously received output. `loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses` (`storage.js:1959-1992`) now returns `H` as not attested using the newest attestor list, so `validatePaymentInputsAndOutputs` rejects the transfer at `validation.js:2506-2507` ("owner address is not attested"), leaving `H`'s coins permanently stuck.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
