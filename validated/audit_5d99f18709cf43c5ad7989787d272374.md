### Title
Cached HTTP credentials are keyed only by protocol+host (not path), causing token/password disclosure to attacker-controlled submodules on the same host - ([File: main.go])

### Summary
`git-sync` stores all HTTP(S) credentials (from `--username`/`--password`, `--askpass-url`, GitHub App tokens, and per-URL `--credential` entries) via `git credential approve`, cached by git's built-in `cache` credential helper with a 3600s timeout, and never sets `credential.useHttpPath`. Because git's credential cache defaults to keying entries by `protocol://host` only (ignoring the URL path), any credential approved for one repo URL on a host is transparently reused by git for *any other path on that same host* — including an attacker-controlled submodule added to the synced repository. This mirrors the referenced bug class: a routing/lookup table keyed too coarsely (Edition instead of Edition+tokenId in the Solidity report; protocol+host instead of full URL here) silently redirects a sensitive resource (referral fee there, an auth credential here) to the wrong, attacker-influenced party.

### Finding Description
`SetupDefaultGitConfigs` sets `credential.helper` to `cache --timeout 3600` globally, and never sets `credential.useHttpPath` to `true`: [1](#0-0) 

Credentials are stored via `StoreCredentials`, which calls `git credential approve` with the *full URL* (`git.repo` or a `--credential`-specified URL), username, and password/token: [2](#0-1) 

This is used by the askpass-URL flow and GitHub App token refresh, both of which approve a credential scoped to `git.repo` (the top-level repository URL) on every refresh cycle: [3](#0-2) [4](#0-3) 

Later, during a sync, `configureWorktree` runs `git submodule update --init [--recursive]`, which will fetch whatever submodule URLs are present in `.gitmodules` at the currently-synced commit — content that is fully attacker-controlled if the attacker can push a commit/PR that is later merged and synced, or if the mirrored repo is otherwise attacker-influenced: [5](#0-4) 

Because git's `cache` credential helper (absent `credential.useHttpPath=true`) matches stored credentials by `protocol://host` alone, a submodule URL under the *same host* as the main repo (or as any `--credential`-approved URL) but a *different path* — e.g., a different, attacker-owned repository on the same git hosting service — will receive the previously cached username/password or GitHub App installation token when git performs HTTP Basic Auth against it. The e2e test suite even demonstrates the multi-credential, multi-host pattern this feature is meant to support, but never exercises (and the production code never defends against) the same-host/different-path collision case: [6](#0-5) 

### Impact Explanation
An attacker who can introduce a submodule reference (via a PR, a compromised branch, or any content merged into the synced ref) pointing to a repository under the *same HTTP(S) host* as the legitimately configured repo/credential can cause `git-sync` to send the cached password, personal access token, or short-lived GitHub App installation token to that attacker-controlled path via the HTTP Basic Auth header on the submodule fetch request. This is a credential/token disclosure impact, and depending on the token's scope, may allow further compromise (e.g., a GitHub App installation token scoped to the whole installation could grant the attacker access to other repositories the token can read).

### Likelihood Explanation
Requires: (1) an HTTP(S)-based `--repo` or `--credential`, (2) submodules enabled (`--submodules=shallow|recursive`, the default), and (3) the attacker being able to introduce a `.gitmodules` change on the synced ref (or, if using multiple `--credential` entries for known submodules, an attacker adding an additional submodule on the same host as one of those). This is a realistic misconfiguration risk rather than a default-on vulnerability, since it depends on the operator's host topology (multiple repos under one shared host with differing trust/credential scopes) and on git's undocumented-to-most-users default of ignoring path in credential caching, but no special git-sync flags beyond normal submodule + HTTP auth use are required.

### Recommendation
Set `credential.useHttpPath` to `true` in `SetupDefaultGitConfigs` (or per approved credential) so the cache/lookup is scoped to the full URL including path, not just protocol+host. Additionally, consider validating/allow-listing submodule URLs against the configured `--repo`/`--credential` URL prefixes before running `git submodule update`, to prevent credential reuse across unrelated repositories that merely share a hostname.

### Proof of Concept
1. Configure `git-sync` with `--repo=https://git.example.com/org/private-repo` and a GitHub-App-style token refresh (or `--username`/`--password-file`), which is approved via `StoreCredentials` for `https://git.example.com/org/private-repo`. [2](#0-1) 
2. An attacker with push/PR access to `private-repo` adds a submodule entry pointing to `https://git.example.com/attacker/evil-repo` (same host `git.example.com`, different path) and merges it (or it lands on the synced ref through normal review-bypass scenarios).
3. On the next sync, `configureWorktree` runs `git submodule update --init --recursive`, and git requests credentials for `https://git.example.com/attacker/evil-repo`. [5](#0-4) 
4. Because `credential.useHttpPath` was never set to `true`, git's `cache` helper matches the cached entry keyed by `https://git.example.com` and returns the previously approved username/password (or GitHub App token) for that host, sending it as an HTTP Basic Auth header in the request to `attacker/evil-repo`, disclosing the credential to the attacker-controlled server's request logs.

// StoreCredentials stores a username and password for later use.
func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
