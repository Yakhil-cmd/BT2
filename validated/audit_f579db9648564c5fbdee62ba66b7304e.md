### Title
Forged `pull_request` "opened" webhook accepted via organization-fallback signature bypass mutates unrelated repository's `ReviewStack` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret`) used to authenticate an inbound webhook based on `repository_owner`, which falls back from `repository.owner.login` to the independent, attacker-controlled `organization.login` field. `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler`, however, resolves the repository to mutate strictly from `params.repository.full_name`. Because these two fields are set independently by the attacker, a payload can be signed/verified against an organization with no `webhook_secret` configured while causing the handler to provision a `ReviewStack` for a completely different, victim organization's repository.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:

`organization_that_verified_signature (Shipit.github(organization: repository_owner)) == organization_that_owns_repository.full_name (used by OpenedHandler#repository)`

Code path:
- `Shipit::WebhooksController#repository_owner` (app/controllers/shipit/webhooks_controller.rb:59-62): `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. If the payload omits `repository.owner.login`, the value falls back to the independently-attacker-set top-level `organization.login`.
- `#verify_signature` (lines 24-49) calls `Shipit.github(organization: repository_owner)` and then `github_app.verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` (lib/shipit/github_app.rb:76-83): `return true unless webhook_secret` — if the selected organization has no configured `webhook_secret`, **any** signature (even garbage) is accepted.
- If verification passes, `#create` (lines 10-15) dispatches to `Shipit::Webhooks::Handlers::PullRequest::OpenedHandler.call(params)`.
- `OpenedHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:50-54) resolves via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely separate field from the one used for `repository_owner`.
- The handler's `ExplicitParameters` schema (lines 8-39) only `requires :repository do requires :full_name, String end` — it does **not** require `repository.owner.login`, so the attacker is free to omit `owner` under `repository` while still satisfying schema validation.
- If `respond_to_pull_request_opened?` passes (repo has `review_stacks_enabled` and an allow-all/label-based provisioning policy), `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!` provisions a `ReviewStack` for the victim repository using attacker-supplied `pull_request.head.ref`/`sha`/labels.

Attacker's request: a JSON body with `action: "opened"`, a fully attacker-controlled `pull_request` object (their own PR, branch, labels), `repository: { full_name: "victim-org/victim-repo" }` (no `owner` sub-key), and `organization: { login: "attacker-controlled-org" }` where `attacker-controlled-org` is a real organization known to `Shipit.github_apps` config but configured with no `webhook_secret`. The `X-Hub-Signature` header can be arbitrary/garbage.

Why existing guards fail: `verify_signature` only ever checks the signature against the org selected by `repository_owner`; it never cross-checks that org against the repository the handler will actually act upon (`repository.full_name`). `GithubOrganizationUnknown` only protects against completely unconfigured organizations, not against a configured-but-secretless one. The `ExplicitParameters` schema in `OpenedHandler` validates presence/type of fields but has no cross-field consistency check tying `repository.owner.login` to `repository.full_name`'s namespace.

### Impact Explanation
An attacker who controls (or names) an organization in Shipit's configuration that lacks a `webhook_secret` can forge a fully-authenticated-looking `pull_request` "opened" event for **any other** repository tracked by this Shipit instance, causing creation of a `ReviewStack` (and any downstream automation tied to review-stack provisioning, e.g. deploy/build triggering) for that victim repository using entirely attacker-chosen branch ref/sha/PR metadata. This is a cross-repository/cross-tenant state-mutation matching the "Critical" category: a payload for one repository (attacker/no-secret org) mutating another repository's (victim org) stack state. It is repeatable against any repository whose `full_name` the attacker knows and that has review-stack provisioning enabled with an allow-all or label-based policy that the attacker can satisfy (labels are attacker-controlled in the payload).

### Likelihood Explanation
Preconditions: (1) Shipit must be configured with at least one organization that has no `webhook_secret` set (or the attacker must otherwise be able to point at such an org); (2) the target repository must have `review_stacks_enabled` with a provisioning policy the forged payload satisfies (allow-all, or label-based where the attacker sets the matching label in the payload). Both are realistic operational configurations — `webhook_secret` is optional per-org, and review-stack provisioning is a documented Shipit feature meant to trigger from PR events. The attacker needs zero credentials: no session, no API token, no GitHub App key, no target org's `webhook_secret`. Cost per request is a single unauthenticated HTTP POST, and it is trivially repeatable against many repositories.

### Recommendation
Verify the webhook against the same organization that owns the `repository.full_name` used by the handler — i.e., derive `repository_owner` and the "owning organization" from a single authoritative source, or explicitly reject payloads where `repository.owner.login` is absent instead of silently falling back to `organization.login`. Additionally, do not treat a missing `webhook_secret` as automatic verification success (`return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`); require an explicit secret for every configured organization or fail closed. Finally, add a schema check in `OpenedHandler`/`ReviewStackAdapter` (or upstream in the controller) asserting `repository.owner.login` matches the org actually verified.

### Proof of Concept
minitest (`test/controllers/webhooks_controller_test.rb` style) plan:
1. Configure two orgs in `Shipit.github_apps` test config: `"victim-org"` with a real `webhook_secret`, and `"attacker-org"` with no `webhook_secret`.
2. Create `Shipit::Repository` for `"victim-org/victim-repo"` with `review_stacks_enabled: true` and `provisioning_behavior: "allow_all"`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, an arbitrary/garbage `X-Hub-Signature`, and a JSON body:
   ```json
   {
     "action": "opened",
     "number": 1,
     "pull_request": { "id": 1, "number": 1, "url": "...", "title": "x", "state": "open",
       "additions": 1, "deletions": 0,
       "head": { "sha": "deadbeef", "ref": "attacker-branch" },
       "user": { "login": "attacker" }, "assignees": [], "labels": [] },
     "repository": { "full_name": "victim-org/victim-repo" },
     "organization": { "login": "attacker-org" },
     "sender": { "login": "attacker" }
   }
   ```
4. Assert response is `200 OK` (signature check passed despite garbage signature, because `attacker-org` has no `webhook_secret`).
5. Assert `Shipit::Repository.find_by(full_name: "victim-org/victim-repo").review_stacks.count` increased by 1, i.e. a `ReviewStack` was created for `victim-org/victim-repo` from a request that was only ever verified against `attacker-org`.
6. Equality check before: `repository_owner` (= `"attacker-org"`, the verifying org) != owning org of the mutated repo (`"victim-org"`), proving the divergence; after the request, the mutation still targets `"victim-org/victim-repo"`, confirming the bypass. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
