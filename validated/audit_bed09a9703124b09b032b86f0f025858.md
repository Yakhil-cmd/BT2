### Title
Insolvent liquidation can seize collateral beyond the value backed by the liquidator’s repayment - (File: contracts/controller/src/positions/liquidation/math.rs)

### Summary
`liquidate` can mark an insolvent liquidation as `seize_all` when the executed repayment is merely within one native unit per debt leg of the collateral-backed quote. Seizure then uses each collateral position’s full balance instead of the repayment-derived amount. This lets a liquidator receive collateral value exceeding `repayment × (1 + bonus)`, while the borrower loses the unbacked remainder.

### Finding Description
`process_liquidation` is callable by any authenticated liquidator for an account whose health factor is below one. [1](#0-0) [2](#0-1) 

For an insolvent account, excess offered repayment is trimmed and kept amounts are rounded down to whole debt-token units, so the actual repayment may be below the calculated collateral-backed quote. [3](#0-2) [4](#0-3) 

The plan nevertheless sets `seize_all` when the repaid value plus one native unit of each repayment leg reaches the ideal quote. [5](#0-4) 

When `seize_all` is set, `calculate_seized_collateral` ignores the repayment-derived `seizure_ray` bound and uses `actual_ray`, the entire collateral balance. [6](#0-5) 

The resulting `SeizeEntry` is then paid as underlying or credited as supply shares. [7](#0-6) [8](#0-7) 

### Impact Explanation
The borrower permanently loses collateral whose value is not covered by the configured liquidation bonus. The unbacked amount is bounded by approximately one native unit per repayment leg multiplied by `1 + bonus`; for a three-decimal debt asset with a high underlying token price, that unit can represent substantial USD value. The loss is direct theft of collateral value by an unprivileged liquidator rather than a user self-inflicted routing loss.

### Likelihood Explanation
The attacker needs an insolvent account whose collateral-backed repayment falls between two native debt-token units. Because the insolvent repayment path rounds the kept amount down, the attacker can choose offered `debt_payments` so the executed amount lands just below the quote while still satisfying `seize_all`. Calling `liquidate` with `SeizeMode::Transfer` then withdraws the entire planned collateral balance from the pool.

### Recommendation
Do not use `seize_all` to expand seizure to `actual_ray` when measured repayment is below the collateral-backed quote. Instead:

- cap seizure at the exact value backed by the kept repayment and selected bonus;
- transfer only the rational collateral amount;
- if a collateral asset cannot be subdivided, either require the repayment that fully backs the next whole unit or revert rather than awarding the unbacked remainder;
- preserve the existing refund behavior for any repayment not backed by seized collateral.

### Proof of Concept
Consider an insolvent borrower with collateral valued at `C = $3,150`, debt valued at `D = $3,151`, and a 5% liquidation bonus. The collateral-backed repayment is approximately `$3,000`.

Let the debt token have three decimals and a whole-token price of `$1,000,000`, so one native debt unit is worth `$1,000`. If whole-unit trimming leaves the liquidator paying two native units (`$2,000`) while the ideal quote is `$2,999.999`, `seize_all` is true because `$2,000 + $1,000 >= $2,999.999`. Execution then seizes the full `$3,150` collateral balance even though the repayment plus bonus economically backs only `$2,100`.

The liquidator submits `debt_payments` for the debt legs and calls:

```rust
liquidate(
    liquidator,
    account_id,
    debt_payments,
    SeizeMode::Transfer,
)
```

The call is authorized, plans the liquidation, pulls the rounded repayment, and awards every collateral share because `capped_ray` is set to `actual_ray`. [9](#0-8) [6](#0-5)

/// Executes transfer-mode seizure: burns shares, debits pool cash, and pays
/// underlying to the liquidator after withholding the protocol fee.
pub(crate) fn apply_liquidation_seizures(
    env: &Env,
    liquidator: &Address,
    account: &mut Account,
    seized: &Vec<SeizeEntry>,
    cache: &mut Context,
) {
    let mut entries: Vec<PoolWithdrawEntry> = Vec::new(env);
    for entry in seized.iter() {
        enforce_spoke_asset_flags(
            env,
            cache,
            account.spoke_id,
            &entry.hub_asset,
            FreezePolicy::SeizureLeg,
        );

        let position: AccountPosition =
            (&expect_invariant(env, account.supply_positions.get(entry.hub_asset.clone()))).into();
        entries.push_back(PoolWithdrawEntry {
            action: make_pool_action(&position, entry.amount, entry.hub_asset),
            protocol_fee: entry.protocol_fee,
        });
    }
    apply_withdraw_batch(
        env,
        account,
        liquidator,
        WithdrawKind::Liquidation,
        events::PositionAction::LiqSeize,
        &entries,
        cache,
    );
