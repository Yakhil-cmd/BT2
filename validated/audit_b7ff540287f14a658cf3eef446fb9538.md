### Title
Byzantine Proposer Can Corrupt Candidate CFS Score via Fake-Hash VRankPreprepare — (`kaiax/vrank/impl/handler.go`)

---

### Summary

A byzantine proposer (a single validator acting maliciously) can send a `VRankPreprepare` message containing an arbitrary, attacker-chosen block hash to a candidate node. Because `HandleVRankPreprepare` only verifies that the sender is the legitimate proposer — not that the block hash matches the one used in Istanbul consensus — the candidate signs and broadcasts a `VRankCandidate` response carrying the fake hash. Honest committee members, whose `expectedBlockHash` is set from the real Istanbul PREPREPARE, then mark the candidate as failed. The resulting false `cfReport` is written into `header.VRank` and accepted by all honest nodes (since `VerifyHeader` performs only structural, not semantic, validation), permanently corrupting the candidate's CFS score on-chain.

---

### Finding Description

**Step 1 — Proposer signature verification does not bind the block hash to Istanbul consensus.**

`HandleVRankPreprepare` calls `recoverVRankPreprepareSender` and `verifyVRankPreprepareSender`: [1](#0-0) 

`verifyVRankPreprepareSender` only checks that the recovered address equals `GetProposer(blockNum, round)`: [2](#0-1) 

The signature covers `vrankPreprepareSigHash(blockNum, round, blockHash)`: [3](#0-2) 

A byzantine proposer holds their own private key and can produce a valid signature over any `blockHash` they choose. There is no check that `msg.Block.Hash()` matches the block hash broadcast in the Istanbul PREPREPARE.

**Step 2 — `markSeenPreprepare` locks in the first (fake) hash and silences the second.**

On the first message (fake hash), `markSeenPreprepare` records it and returns `(false, false)`: [4](#0-3) 

The candidate then broadcasts `VRankCandidate` with the fake hash: [5](#0-4) 

On the second message (real hash), `markSeenPreprepare` returns `(false, true)` — conflicting view — and the handler silently returns `nil`: [6](#0-5) 

The candidate has no opportunity to correct its response.

**Step 3 — Committee members hold the real hash; the candidate's response fails the check.**

`HandleIstanbulPreprepare` records the real block hash from Istanbul consensus into the collector, but only for committee members (validators), not candidates: [7](#0-6) 

`EvaluateCandidates` compares each stored `VRankCandidate.BlockHash` against `expectedBlockHash`: [8](#0-7) 

Because the candidate responded with `hash_fake` and `expectedBlockHash = hash_real`, the candidate is appended to `cfReport`.

**Step 4 — `VerifyHeader` accepts the false cfReport without semantic validation.**

`VerifyHeader` only checks that reported addresses are sorted, deduplicated, and present in `GetCandTesting(N-1)`: [9](#0-8) 

It does not verify that the reported candidates actually failed to respond. All honest nodes accept the block containing the false `cfReport`.

**Step 5 — The byzantine filter does not help.**

`byzantineFilter` discards the top-F reporter scores per candidate to tolerate up to F byzantine *reporters*: [10](#0-9) 

In this attack, the false report originates from honest committee members (who genuinely observed the wrong hash). The filter is designed to discard dishonest reporters, not to correct honest reporters who were deceived by a byzantine proposer.

---

### Impact Explanation

The candidate's CFS score is persistently inflated on-chain via `header.VRank`. A high CFS score signals repeated candidate failure and directly affects whether the candidate is promoted to active validator status and how rewards are distributed. Because `VerifyHeader` accepts the false report, the corruption is canonical across all honest nodes — it is not a local or transient state.

---

### Likelihood Explanation

The attacker must be the elected proposer for a specific `(blockNum, round)`. In a permissionless validator set, any single byzantine validator will eventually be selected as proposer. No majority collusion, key compromise, or external service access is required. The attack is repeatable every time the byzantine validator is proposer, allowing sustained CFS score inflation against targeted candidates.

---

### Recommendation

In `HandleVRankPreprepare`, after signature and proposer verification, cross-check `msg.Block.Hash()` against the locally known Istanbul PREPREPARE block hash for the same view. Candidates that are also committee members already have this hash via `HandleIstanbulPreprepare`; for pure candidates, the real block hash should be delivered through an authenticated side-channel or embedded in the Istanbul PREPREPARE flow. Alternatively, `VerifyHeader` should validate the semantic correctness of `cfReport` entries by requiring a quorum of signed `VRankCandidate` messages with matching block hashes to be included in the block, making false reports provably invalid.

---

### Proof of Concept

```
Setup:
  - Candidate node C (not a committee member for block N)
  - Byzantine proposer P (legitimate proposer for block N, round 0)
  - Honest committee member V (evaluates candidates for block N)

Attack:
  1. P constructs VRankPreprepare{Block: blockN_with_fake_hash, View: {N, 0}}
     and signs it with their real node key.
     → recoverVRankPreprepareSender returns P's address ✓
     → verifyVRankPreprepareSender confirms P == GetProposer(N, 0) ✓
     → markSeenPreprepare(ViewKey{N,0}, hash_fake) → (false, false) → new entry
     → C broadcasts VRankCandidate{BlockNumber:N, Round:0, BlockHash:hash_fake}

  2. P constructs VRankPreprepare{Block: blockN_with_real_hash, View: {N, 0}}
     and signs it with their real node key.
     → markSeenPreprepare(ViewKey{N,0}, hash_real) → (false, true) → silently ignored

  3. V receives VRankCandidate from C with BlockHash=hash_fake.
     V's collector has expectedBlockHash=hash_real (from Istanbul PREPREPARE).

  4. Proposer of block N+1 calls EvaluateCandidates(N, 0):
     → C's msg.BlockHash (hash_fake) != expectedBlockHash (hash_real)
     → C is appended to cfReport

  5. header(N+1).VRank = RLPEncode([C])
     VerifyHeader passes (C is a valid candidate, list is sorted and deduplicated).
     All honest nodes accept the block. C's CFS score increments.

Assert: C is in header(N+1).VRank despite having responded correctly to the
        legitimate VRankPreprepare (which it never received first).
```

func (v *VRankModule) markSeenPreprepare(vk vrank.ViewKey, blockHash common.Hash) (bool, bool) {
	v.seenPreprepareMu.Lock()
	defer v.seenPreprepareMu.Unlock()

	if seenHash, ok := v.seenPreprepare[vk]; ok {
		if seenHash == blockHash {
			return true, false
		}
		return false, true
	}
	v.seenPreprepare[vk] = blockHash
	return false, false
}

func (v *VRankModule) vrankPreprepareSigHash(blockNum uint64, round uint8, blockHash common.Hash) common.Hash {
	chainID := v.ChainConfig.ChainID.Uint64()

	// Canonical encoding:
	// domain separator || chain_id(uint64 BE) || block_number(uint64 BE) || round(uint8) || block_hash(32 bytes)
	payload := make([]byte, 0, len(vrankPreprepareSigDomain)+8+8+1+len(blockHash))
	payload = append(payload, []byte(vrankPreprepareSigDomain)...)
	payload = binary.BigEndian.AppendUint64(payload, chainID)
	payload = binary.BigEndian.AppendUint64(payload, blockNum)
	payload = append(payload, round)
	payload = append(payload, blockHash[:]...)
	return crypto.Keccak256Hash(payload)
}

func (v *VRankModule) verifyVRankPreprepareSender(msg *vrank.VRankPreprepare, sender common.Address) error {
	blockNum := msg.Block.NumberU64()
	round := msg.View.Round.Uint64()
	proposer, err := v.Valset.GetProposer(blockNum, round)
	if err != nil {
		logger.Debug("GetProposer failed", "err", err, "blockNum", blockNum)
		return err
	}
	if sender != proposer {
		logger.Debug("VRankPreprepare from non-proposer", "sender", sender.Hex(), "proposer", proposer.Hex(), "blockNum", blockNum)
		return vrank.ErrMsgFromNonProposer
	}
	return nil
}

func byzantineFilter(cpMatrix vrank.CPMatrix, F int) map[common.Address]uint64 {
	cfs := make(map[common.Address]uint64)
	for cand, reporterToScore := range cpMatrix {
		scores := slices.Collect(maps.Values(reporterToScore))
		slices.Sort(scores)
		if F >= len(scores) {
			// since `scores` contain non-zero scores only, F >= len(scores) can happen, in which case all scores are discarded.
			scores = nil
		} else {
			scores = scores[:len(scores)-F]
		}
		var sum uint64
		for _, t := range scores {
			sum += t
		}
		cfs[cand] = sum
	}
	return cfs
}
