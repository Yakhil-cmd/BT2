Webhook signature is verified against the organization derived from an unverified payload field while the acted-upon repository comes from a different unverified field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to use for HMAC verification based on `repository_owner`, a value read directly out of the *unauthenticated* request body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). The event handlers that subsequently act on the payload (e.g. `PushHandler`) resolve the target `Repository`/`Stack` from a *different* field of the same unauthenticated body: `payload.dig('repository', 'full_name')`. Nothing binds these two fields together, so the identity that is cryptographically "authenticated" (the organization used to pick the secret) is not the identity that is actually written to (the repository whose stacks get synced).

### Finding Description
`Shipit.github(organization:)` supports a multi-org configuration schema where each org has its own, independently optional, `webhook_secret` [1](#0-0) . `GitHubApp#verify_webhook_signature` explicitly trusts any payload when the organization's configured secret is blank: `return true unless webhook_secret` [2](#0-1) . The setup docs and secret templates confirm `webhook_secret` is optional and commonly `nil` for some orgs in multi-org setups [3](#0-2) .

`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the secret) using `repository_owner`, itself taken straight from the unauthenticated JSON body: [4](#0-3) 

After (trivially) passing this check, `#create` dispatches the raw, still only field-validated `params` to every registered handler for the event [5](#0-4) . `Handler#stacks`/`#repository_name` resolve the repository to act on from a *different* JSON field — `repository.full_name` — with no cross-check against `repository.owner.login`: [6](#0-5) 

`PushHandler#process` then finds all matching, non-archived `Stack`s for that resolved repository/branch and triggers a GitHub sync on them: [7](#0-6) 

This reproduces the audit's bug class exactly: a value/setting selected for one purpose ("does this signature, for organization X, look valid?") is silently repurposed to gate a decision about a completely different binding ("which repository's stacks should I act on?") without the two ever being checked against each other. The equality that should hold — *the organization whose secret authenticated this request == the owner of the repository the handler is about to act on* — is never enforced.

### Impact Explanation
If any organization configured in this Shipit instance has no `webhook_secret` (an explicitly supported, documented configuration — "Webhook secret (optional)" [8](#0-7) ), an unprivileged external attacker can POST a forged `push` (or `check_suite`/`status`/`membership`) webhook where:
- `repository.owner.login` (or `organization.login`) = the no-secret organization → `verify_webhook_signature` returns `true` unconditionally, regardless of the (even absent/garbage) `X-Hub-Signature` header.
- `repository.full_name` = `victim-org/victim-repo`, a completely different, secret-protected organization's repository that has real Shipit stacks configured.

The forged payload is then processed by `PushHandler`, which resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha:)` on every matching stack/branch — forcing Shipit to fetch and ingest attacker-chosen commit metadata into a stack belonging to an org the attacker never authenticated against. Because deploy eligibility, undeployed-commit counts, and CI/status gating all key off synced commit state, this is a cross-organization / cross-repository write achieved without ever possessing the victim org's webhook secret, matching the "cross-repository writes" / "unauthorized deploy" impact tier.

### Likelihood Explanation
Likelihood depends on the deployment having at least one organization configured with a blank `webhook_secret` in a multi-org `github:` config — a state the app's own documentation calls out as optional and which the test fixtures (`OrgTwo` in `test/dummy/config/secrets_double_github_app.yml`) explicitly exercise. Single-org deployments using the legacy top-level `github:` schema are less exposed (there is one secret and `repository_owner` doesn't select between apps), but any multi-tenant Shipit instance following the documented setup is directly exposed with no extra prerequisites beyond an HTTP POST to `/webhooks`.

### Recommendation
Enforce equality between the identity used to select/verify the webhook secret and the identity of the repository the handler subsequently acts on: after verifying (or determining verification is not required for) an organization, require that `repository.owner.login`/`organization.login` and `repository.full_name`'s owner segment match, and reject (422) otherwise. Additionally, treat a blank `webhook_secret` for one organization as authorizing only payloads whose repository owner is that same organization — never as a blanket bypass usable to inject events referencing other organizations' repositories. Consider requiring a non-blank `webhook_secret` per organization in multi-org configurations, or performing signature verification against the org that actually owns `repository.full_name` rather than the org named in `repository.owner.login`.

### Proof of Concept
1. Configure Shipit with the multi-org schema, e.g. `github: { attacker-org: { ... webhook_secret: nil ... }, victim-org: { ... webhook_secret: "s3cr3t" ... } }`, and create a Shipit `Stack` for `victim-org/victim-repo`.
2. As an unauthenticated attacker, POST to `/webhooks` with headers `X-Github-Event: push` and no (or any) `X-Hub-Signature`, and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef...",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
}
```
3. `WebhooksController#verify_signature` calls `Shipit.github(organization: "attacker-org")` → `GitHubApp#verify_webhook_signature` returns `true` immediately because `attacker-org`'s `webhook_secret` is blank [9](#0-8) .
4. `PushHandler#process` resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "deadbeef...")` [7](#0-6)  — a sync on `victim-org`'s stack triggered without ever possessing `victim-org`'s `webhook_secret`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    def event

    end
