### Title
Accrual mints unbacked protocol revenue shares while a market has outstanding debt but zero supply — (File: common/src/rates/simulate.rs)

### Summary
This is the XOXNO Lending analog of the Synthetix "rewards lost / mis-credited while `totalSupply == 0`" bug class. In `accrue_step`, when `supplied == 0` but `borrowed > 0`, the market still compounds its borrow index at `base_borrow_rate`, the entire accrued interest is reclassified as protocol reward via `supply_index_reward_shortfall`, and `protocol_fee_shares` mints scaled supply shares into `revenue`/`supplied` with no backing cash and no supplier base. Instead of the rewards simply sitting idle (Lybra), here they are converted into unbacked claims that later dilute real suppliers.

### Finding Description
In `common/src/rates/curve.rs:100-105`, `utilization` returns `Ray::ZERO` whenever supplied value is zero, so `calculate_borrow_rate` falls back to `params.base_borrow_rate` (`curve.rs:28-32`) — a nonzero rate. In `accrue_step` (`common/src/rates/simulate.rs:60-87`):

1. `borrow_index` compounds at the base rate (`update_borrow_index`, line 66).
2. `calculate_supplier_rewards` computes accrued interest vs. the old index (line 68).
3. `update_supply_index` returns `old_index` unchanged because `supplied`/`total_supplied_value` is zero (`common/src/rates/index.rs:30-38`), so `supply_index_reward_shortfall` returns the *entire* `supplier_rewards` (index.rs:53-63).
4. `protocol_reward = protocol_fee + supplier_shortfall` is converted by `protocol_fee_shares` into scaled shares minted into `revenue` and `supplied` (`contracts/pool/src/interest.rs:50-53`, `accrue_revenue`). With `supplied == 0`, the cap `i128::MAX - supplied` is effectively unbounded, so the protocol mints itself a large share position backed by zero cash.

This mirrors the reported bug structurally: interest/reward is generated over a window with no reward base (`totalSupply == 0` in Synthetix; `supplied == 0` here), and instead of accruing to nobody (lost), it is silently converted into unbacked protocol claims.

### Impact Explanation
The minted revenue shares become part of `supplied` and participate in the supply index like real supplier shares (documented in `skills/xoxno-lending/math.md:247` and `docs/reference/invariants.md` INV-IDX sections). They represent claims on the pool's cash that were never funded — an unbacked balance-sheet liability. When `claim_revenue` is later executed, these shares redeem real tokens paid for by subsequent depositors, draining legitimate supplier funds (theft of user funds / insolvency). Additionally, once nonzero `supplied` exists again purely from these phantom shares, utilization becomes nonzero and the borrow rate jumps off the base rate, distorting subsequent accrual.

### Likelihood Explanation
The state `borrowed > 0 && supplied == 0` is reachable by unprivileged paths listed in scope: `recapitalize` injects cash without minting shares, after which suppliers can fully `withdraw` while bad/outstanding debt remains (`borrowed > 0` persisted as scaled shares). Every subsequent `update_indexes` / any controller op that triggers `global_sync` (`contracts/pool/src/interest.rs:20-33`) then mints unbacked revenue shares at base-rate-compounding speed. No privileged reward call is needed — unlike the Lybra original, the accrual is permissionless and continuous.

### Recommendation
In `accrue_step`, gate supplier-reward conversion when there is no supply base: if `supplied == Ray::ZERO` (or total supplied value is zero), skip minting `revenue_shares` — either skip accrual of `borrow_index` entirely for that chunk (debt with no suppliers cannot be serviced anyway) or book the accrued amount only as a pending accounting entry backed by actual repayment, not as shares. Equivalently, `protocol_fee_shares` should return zero when `supplied == Ray::ZERO`, matching the `update_supply_index` early return, so the no-participant window produces no unbacked claims.

### Proof of Concept
1. Market has `borrowed > 0`, `supplied == 0` (reached via `recapitalize` injecting cash + full supplier `withdraw`, leaving bad debt shares outstanding).
2. Anyone calls `update_indexes` (or any accrual-triggering op) after `delta_ms` elapses.
3. `accrue_step`: `utilization = 0` → `borrow_rate = base_borrow_rate` → `borrow_index' > borrow_index` → `supplier_rewards = accrued - fee > 0`.
4. `update_supply_index` early-returns `old_index`; `shortfall = supplier_rewards`; `protocol_reward = fee + supplier_rewards` (≈ all accrued interest).
5. `protocol_fee_shares(protocol_reward, new_supply_index, 0)` mints `floor(protocol_reward * RAY / supply_index)` shares; `accrue_revenue` adds them to `revenue` and `supplied`.
6. Later, a new supplier deposits; the phantom revenue shares dilute them, and `claim_revenue` withdraws real cash against shares that were never funded. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}
