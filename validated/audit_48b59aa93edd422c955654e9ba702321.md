### Title
L1 lockup outpoint replay allows double-counting BTC collateral across bond registrations - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`validate-l1-lockup` only prevents duplicate outpoints *within a single* `register-for-bond` call (via the `seen-outpoints` accumulator passed through the fold), but there is no persistent, contract-level map recording which Bitcoin lockup outpoints have already been credited in prior calls. A staker can therefore submit proof of the *same* on-chain BTC lockup output in more than one `register-for-bond` transaction (e.g., registering for two different bonds, or re-registering after being removed) and have the same locked sats counted as collateral each time.

### Finding Description
`validate-l1-lockup` in `stackslib/src/chainstate/stacks/boot/pox-5.clar` (around lines 2031-2113) validates each L1 lockup entry by checking the BTC header, merkle proof, script, and amount, and rejects duplicates only via an in-call accumulator: [1](#0-0) 
This `seen-outpoints` list is built and consumed entirely within the fold of a single call (see the accumulator type and its initialization/finalization around `get-l1-lockup-summary`), i.e. it is not backed by a `define-map` that persists between transactions: [2](#0-1) 

I searched the contract for any persistent outpoint tracking (`used-outpoints`, `consumed-outpoint`, or any `define-map` keyed on `{txid, output-index}`) and found none — the only outpoint bookkeeping in the file is the ephemeral `seen-outpoints` list scoped to a single `validate-l1-lockup`/`register-for-bond` invocation. This means nothing stops the exact same Bitcoin outpoint (a specific locked-sats output) from being presented again in a later, independent `register-for-bond` call — for a different `bond-index`, or after the staker's registration for a given bond/cycle window is cleared and re-submitted — and being credited again toward that call's `sum` of committed sats.

This is the structural analog of the reported "fee on transfer" class of bug: in the original finding, the contract trusts a *stated* amount (`bProposal.weights[i]`) and grants downstream rights (`safeApprove`) without verifying that the same underlying value hasn't already been consumed/altered elsewhere. Here, pox-5 trusts a *presented proof* of a real BTC lockup and grants downstream rights (counting it toward `sum`, and thus toward allowlist limits, stx-value ratios, and reward/signing weight) without checking whether that specific BTC lockup was already consumed by an earlier registration.

### Impact Explanation
Because the sats sum derived from L1 lockup proofs feeds directly into stacking/bond accounting (allowlist caps, `stxValueRatio`/`minUstxRatio` checks, and reward-cycle sats staked used for reward calculation and signer weight), replaying the same outpoint across separate `register-for-bond` calls lets a staker be credited with more locked-BTC collateral than actually exists on Bitcoin. This directly breaks the equality that staked/committed sats in pox-5 must equal sats actually and currently locked on the Bitcoin chain, and can inflate a staker's/signer's effective stake, signing weight, or reward eligibility beyond what is backed — matching the "High: signing weight or reward slots exceeding locked value" / "sats credited by an L1 proof that were never locked on Bitcoin" criteria in scope.

### Likelihood Explanation
Likelihood is contingent on operational constraints I could not fully verify (e.g., whether `register-for-bond`'s allowlist/one-bond-at-a-time gating and the "must not already be registered" checks incidentally prevent reuse across bonds, or whether the merkle-proof’s `unlock-burn-height` gating limits which cycles a given proof is valid for). I was not able to inspect the complete `register-for-bond` function body (only grep hits, not full source) before running out of tool calls, so I cannot confirm with full certainty that no other check (e.g. a global "lockup already claimed" gate elsewhere in the contract) blocks this replay path. This uncertainty should be resolved by a direct code review of `register-for-bond` and any allowlist/removal logic in `pox-5.clar`.

### Recommendation
Add a persistent `define-map` keyed by `{txid, output-index}` (or the full outpoint) that records once an L1 lockup output has been credited to any staker/bond, and have `validate-l1-lockup` (or its caller `register-for-bond`) check and set this map, rejecting any proof whose outpoint has already been consumed contract-wide — not just within the current call's fold.

### Proof of Concept
Conceptual PoC (pending confirmation against the full `register-for-bond` implementation, which I could not fully retrieve):
1. Staker locks `X` sats on Bitcoin to a valid lockup script for pox-5's `staker-unlock-bytes`/`early-unlock-bytes`.
2. Staker calls `register-for-bond` for bond A, submitting the merkle proof for this lockup output; `validate-l1-lockup` accepts it and credits `X` sats toward bond A's `sum`.
3. Staker calls `register-for-bond` again for bond B (a different `bond-index`/allowlist), submitting the exact same lockup proof (same outpoint). Because `seen-outpoints` is scoped only to the current call's fold and there is no persistent map rejecting previously-used outpoints, the proof is accepted again, crediting the same `X` sats toward bond B's `sum`.
4. The staker now has `X` sats counted as collateral in both bond A and bond B, despite only `X` sats being locked on Bitcoin in total — double-counting the same L1 commitment. [3](#0-2)

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
