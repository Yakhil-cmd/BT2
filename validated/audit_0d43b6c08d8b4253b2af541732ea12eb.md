### Title
Unvalidated Gas Price from Parent Chain P2P Response Drains SubBridge Operator's KAIA Balance — (`node/sc/sub_bridge_handler.go`, `node/sc/bridge_accounts.go`)

---

### Summary

The Kaia service-chain bridge (`SubBridge`) blindly trusts the `GasPrice` and `KIP71Config.UpperBoundBaseFee` values received from a parent-chain peer over P2P. No upper-bound validation is applied before these values are stored and used as the gas price for every subsequent bridge transaction submitted to the parent chain. A malicious or compromised parent-chain peer can send an arbitrarily large gas price, causing the SubBridge operator's KAIA balance to be drained through excessive fee payments.

---

### Finding Description

When the SubBridge needs to synchronize its nonce and gas price, it calls `SyncNonceAndGasPrice()`, which broadcasts a `ServiceChainParentChainInfoRequestMsg` to all connected parent-chain peers. [1](#0-0) 

Any peer that responds with a `ServiceChainParentChainInfoResponseMsg` triggers `handleParentChainInfoResponseMsg`, which unconditionally calls `setRemoteChainValues(pcInfo)` with the peer-supplied data: [2](#0-1) 

`setRemoteChainValues` stores the peer-supplied `GasPrice` and `KIP71Config.UpperBoundBaseFee` without any range check or cap: [3](#0-2) 

These values are then used in two places to set the gas price of outgoing bridge transactions:

1. **Anchoring transactions** — `genUnsignedChainDataAnchoringTx` uses `sbh.remoteGasPrice` directly: [4](#0-3) 

2. **Value-transfer handle transactions** — `GenerateTransactOpts` uses `acc.kip71Config.UpperBoundBaseFee` (set from the peer response) as the gas price: [5](#0-4) 

The MainBridge side constructs the response from its own `txPool.GasPrice()` and genesis `KIP71Config`, but the SubBridge performs no validation on the received values before applying them: [6](#0-5) 

---

### Impact Explanation

Every bridge transaction (anchoring and value-transfer handle) submitted by the SubBridge operator to the parent chain is signed with the attacker-controlled gas price. Because the parent chain deducts `gasUsed × gasPrice` from the operator's account, an inflated gas price directly drains the SubBridge operator's KAIA balance on the parent chain. If the balance is exhausted, the bridge stops functioning: anchoring halts and cross-chain value transfers cannot be completed, effectively freezing user assets in transit.

This is an **unauthorized fee charge affecting KAIA** held by the bridge operator — a system-managed fund that enables bridge liveness.

---

### Likelihood Explanation

The SubBridge connects to parent-chain peers whose chain ID matches the configured `ParentChainID`. Chain IDs are public. Any node running the parent chain software with the correct chain ID can establish a P2P connection to the SubBridge. The SubBridge sends `ServiceChainParentChainInfoRequestMsg` to **all** connected peers and accepts the first valid response. A malicious peer that connects before or alongside the legitimate MainBridge node can win the race and inject an inflated gas price. Additionally, a compromised MainBridge node achieves the same effect with certainty. The sync is triggered on every new peer connection and periodically every `SyncRequestInterval` (10) blocks when nonce is not yet synced. [7](#0-6) 

---

### Recommendation

1. **Cap the received gas price** against a locally configured maximum (e.g., `params.KIP71Config.UpperBoundBaseFee` from the local genesis config, not the peer-supplied one) before storing it in `setRemoteChainValues`.
2. **Validate `KIP71Config` fields** against locally known governance parameters rather than accepting them verbatim from a peer.
3. **Prefer a local gas price oracle** (analogous to the SKALE recommendation) over peer-supplied values; use the peer value only as a fallback with a hard cap.

---

### Proof of Concept

1. Attacker runs a node with the correct parent chain ID and connects to the SubBridge as a parent-chain peer.
2. SubBridge sends `ServiceChainParentChainInfoRequestMsg`.
3. Attacker responds with a crafted `parentChainInfo` where `KIP71Config.UpperBoundBaseFee = math.MaxUint64` and `IsMagmaEnabled = true`.
4. `handleParentChainInfoResponseMsg` → `setRemoteChainValues` stores `remoteGasPrice = math.MaxUint64` and `kip71Config.UpperBoundBaseFee = math.MaxUint64`.
5. Next anchoring period: `genUnsignedChainDataAnchoringTx` builds a tx with `gasPrice = math.MaxUint64`; `GenerateTransactOpts` does the same for handle-value-transfer txs.
6. These transactions are signed and submitted to the parent chain. The parent chain deducts `gasUsed × math.MaxUint64` from the operator's account, draining it in a single transaction.
7. Bridge operator's KAIA balance on the parent chain reaches zero; all subsequent bridge transactions fail; cross-chain transfers are frozen.

func (sbh *SubBridgeHandler) setRemoteChainValues(pcInfo parentChainInfo) {
	sbh.setRemoteGasPrice(pcInfo.GasPrice)
	if pcInfo.IsMagmaEnabled {
		// Set parent chain's gasprice with upperboundbasefee
		sbh.remoteGasPrice = pcInfo.KIP71Config.UpperBoundBaseFee

	} else {
		logger.Info("Updated parent chain's gas price", "gasPrice", sbh.subbridge.bridgeAccounts.GetParentGasPrice())
	}
}

// handleParentChainInfoResponseMsg handles parent chain info response message from parent chain.
// It will update the ParentOperatorNonce and remoteGasPrice of ServiceChainProtocolManager.
func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil

// SyncNonceAndGasPrice requests the nonce of address used for service chain tx to parent chain peers.
func (scpm *SubBridgeHandler) SyncNonceAndGasPrice() {
	addr := scpm.GetParentOperatorAddr()
	for _, peer := range scpm.subbridge.BridgePeerSet().peers {
		peer.SendServiceChainInfoRequest(addr)
	}
}
