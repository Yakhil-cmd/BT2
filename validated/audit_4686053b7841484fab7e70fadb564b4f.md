### Title
Permanently Blocking Bridge Value Transfer Queue via Malicious `_to` Address — (`node/sc/bridge_manager.go`)

### Summary

`processingPendingRequestEvents()` in `node/sc/bridge_manager.go` processes bridge value-transfer events in strict nonce order. When `handleRequestValueTransferEvent()` returns an error for event at index `idx`, the function re-queues `ReadyEvent[idx:]` — the failing event **and every subsequent event** — and returns immediately. Because there is no mechanism to skip or discard a permanently failing event, any unprivileged user who can initiate a value-transfer request can craft one that will always fail at the Go-binding level, permanently blocking all subsequent cross-chain transfers.

### Finding Description

**Blocking loop in `processingPendingRequestEvents`** [1](#0-0) 

When `handleRequestValueTransferEvent(ev)` returns an error, the code calls `bi.AddRequestValueTransferEvents(ReadyEvent[idx:])`, which re-inserts the failing event (and every event after it) back into the `pendingRequestEvent` sorted map, then returns. On the next tick (every 1 second via the ticker) or on the next `newEvent` signal, `processingPendingRequestEvents` is called again, encounters the same failing event at the front of the queue, fails again, and re-queues again — indefinitely. [2](#0-1) 

**Root cause in `handleRequestValueTransferEvent`**

For a KAIA transfer, the Go binding calls `bi.bridge.HandleKLAYTransfer(auth, ...)`. The go-ethereum binding first calls `EstimateGas`; if the simulated transaction would revert on-chain, `EstimateGas` fails and the binding returns an error, which propagates back as the blocking error. [3](#0-2) 

**On-chain revert trigger**

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` sends KLAY to `_to` using a low-level call and requires success: [4](#0-3) 

If `_to` is a contract whose fallback always reverts, the `require(ok, ...)` reverts the entire `handleKLAYTransfer` transaction. Gas estimation therefore fails, the Go binding returns an error, and the event is re-queued forever.

**No skip / drain mechanism**

The `valueTransferRecovery` subsystem only re-adds the same stuck events via `AddRequestValueTransferEvents`; it does not skip or remove permanently failing ones. [5](#0-4) 

There is no operator API to remove a specific nonce from `pendingRequestEvent` or to advance `lowerHandleNonce` past a stuck event.

### Impact Explanation

All cross-chain value transfers (KAIA, ERC-20, ERC-721) queued after the stuck nonce are permanently frozen. The bridge operator's node loops on the failing event every second, consuming resources, while legitimate users' funds remain locked on the source chain with no path to settlement. This is a persistent DoS on the bridge's asset-transfer channel with direct impact on bridged assets.

### Likelihood Explanation

The attack requires only:
1. Deploying a contract whose fallback reverts (trivial, costs minimal gas).
2. Calling the public `requestKLAYTransfer(maliciousContract, value, extraData)` on the source bridge with any non-zero value above the fee. [6](#0-5) 

No special privilege is required. The `requestKLAYTransfer` function is fully public. The attacker only needs to pay the bridge fee plus a small KLAY amount.

### Recommendation

1. **Non-blocking event processing**: Catch the error from `handleRequestValueTransferEvent`, log it, and `continue` to the next event rather than re-queuing and returning. Maintain a separate "failed nonce" set so the VTR can retry only those specific nonces.
2. **Operator skip API**: Add an admin function to advance `lowerHandleNonce` past a permanently stuck nonce (analogous to LayerZero's `forceResumeReceive`).
3. **On-chain guard**: In `handleKLAYTransfer`, use a try/catch pattern (or check the destination balance/code) before the low-level call, and emit a failure event rather than reverting, so the bridge operator can detect and skip undeliverable transfers without the Go-level gas estimation failing.

### Proof of Concept

```
1. Attacker deploys MaliciousReceiver:
   contract MaliciousReceiver { fallback() external payable { revert(); } }

2. Attacker calls on source bridge (child chain):
   bridge.requestKLAYTransfer{value: fee + 1 wei}(address(maliciousReceiver), 1 wei, "")
   → emits RequestValueTransfer(nonce=N, to=maliciousReceiver, value=1 wei)

3. Bridge operator node picks up the event, calls:
   bi.bridge.HandleKLAYTransfer(auth, txHash, from, maliciousReceiver, 1, N, blkNum, extraData)
   → EstimateGas simulates: maliciousReceiver.call{value:1}("") reverts
   → EstimateGas returns error → Go binding returns error

4. processingPendingRequestEvents (bridge_manager.go:254-257):
   err != nil → AddRequestValueTransferEvents(ReadyEvent[N:]) → return
   (All events with nonce ≥ N are re-queued)

5. Next ticker fires (1 second later) → same failure → infinite loop.
   All legitimate transfers with nonce > N are permanently blocked.
``` [7](#0-6) [8](#0-7)

// processingPendingRequestEvents handles pending request value transfer events of the bridge.
func (bi *BridgeInfo) processingPendingRequestEvents() {
	ReadyEvent := bi.GetReadyRequestValueTransferEvents()
	if ReadyEvent == nil {
		return
	}

	logger.Trace("Get ready request value transfer event", "len(readyEvent)", len(ReadyEvent), "len(pendingEvent)", bi.pendingRequestEvent.Len())

	for idx, ev := range ReadyEvent {
		if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
			logger.Trace("handled requests can be ignored", "RequestNonce", ev.GetRequestNonce(), "lowerHandleNonce", bi.lowerHandleNonce)
			continue
		}

		if err := bi.handleRequestValueTransferEvent(ev); err != nil {
			bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
			logger.Error("Failed handle request value transfer event", "err", err, "len(RePutEvent)", len(ReadyEvent[idx:]))
			return
		}
	}
}

// recoverPendingEvents recovers all pending events by resending them.
func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))
	}

	vtHandleEventMeter.Mark(int64(len(vtr.parentEvents)))
	events = make([]IRequestValueTransferEvent, len(vtr.parentEvents))
	for i, event := range vtr.parentEvents {
		events[i] = event
	}
	vtr.cBridgeInfo.AddRequestValueTransferEvents(events)

	return nil
}
