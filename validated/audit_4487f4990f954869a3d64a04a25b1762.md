### Title
Webhook signature is verified against a GitHub organization inferred from an unverified payload field, decoupled from the repository actually mutated - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks which GitHub App configuration (and therefore which `webhook_secret`) to check the `X-Hub-Signature` against based on `repository_owner`, a value read straight out of the still-unauthenticated JSON body [1](#0-0) [2](#0-1) . The repository that is actually mutated by the event handlers, however, is resolved independently from `payload.dig('repository', 'full_name')` [3](#0-2) . These two payload fields are never cross-checked against each other, so the "organization that authenticated" and the "repository that is written" are not bound together.

### Finding Description
Shipit supports multiple GitHub Apps/organizations, each with its own config block (including an optional `webhook_secret`) [4](#0-3) . `GitHubApp#verify_webhook_signature` is written to be permissive when a given organization has no secret configured:

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [5](#0-4) 

The organization used to look up this `GitHubApp` instance (and thus its `webhook_secret`) comes from `repository_owner`, which is read from the attacker-controlled JSON body *before* any signature is checked:

```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

Meanwhile, `create` dispatches the same raw payload to handlers such as `PushHandler`, which resolve the target stack using a *different* field, `repository.full_name`, via `Repository.from_github_repo_name` [3](#0-2) [6](#0-5) .

Because signature verification is scoped to whatever organization the attacker *claims* to be (`repository.owner.login`), and the actually-affected stack is scoped to whichever repository the attacker *claims* to write to (`repository.full_name`), these two attacker-controlled values are never required to agree. If any single organization configured in the multi-org secrets is missing a `webhook_secret` (`@webhook_secret = @config[:webhook_secret].presence`, `nil` when absent) [7](#0-6) , an attacker can:

1. Set `repository.owner.login` (or `organization.login`) to that unprotected organization's name so `verify_signature` resolves a `GitHubApp` whose `verify_webhook_signature` unconditionally returns `true`.
2. Set `repository.full_name` to `victim-org/victim-repo`, a fully-protected stack, so the handler processes the forged event against it.

This is directly analogous to the reported Vault bug: the value used to authorize/gate the action (`totalCash` derived from a spoofable `balanceOf`) is different from, and not properly bound to, the value that determines the economic outcome (share price). Here, the value used to authorize the request (the organization inferred for signature checking) is different from, and not bound to, the value that determines which repository's state is mutated.

### Impact Explanation
An unprivileged, unauthenticated network attacker with no Shipit session, API token, or GitHub credentials can forge webhook events (`push`, `commit_status`, `deployable_status`, `merge_status`, `pull_request`, `membership`, etc., per `Hook::EVENTS`/`Shipit::Webhooks`) against any stack, as long as one configured organization lacks a `webhook_secret`. Forged `push` events trigger `stack.sync_github` for a targeted stack [8](#0-7) ; forged commit/deployable status events can manipulate deploy-gating signals used to determine whether a commit is deployable. This crosses the credential/repository boundary the engine is designed to enforce (per-organization webhook authentication), enabling unauthorized cross-repository state changes without any privileged access — matching the Critical criteria of cross-repository writes / unauthorized deploy triggers.

### Likelihood Explanation
The precondition — a multi-organization Shipit deployment where at least one configured GitHub App entry omits `webhook_secret` — is an operator misconfiguration, not a code-enforced invariant; nothing in `github_app_config`/`TOP_LEVEL_GH_KEYS` requires `webhook_secret` to be present for every organization [9](#0-8) [10](#0-9) . Given this precondition, exploitation requires only sending a single crafted HTTP POST with mismatched `repository.owner.login` and `repository.full_name` fields — no signing key, no timing, no race condition.

### Recommendation
Bind the organization used for signature verification to the same field used for repository resolution: derive `repository_owner` from `repository.full_name` (or otherwise require `repository.owner.login` and `repository.full_name`'s owner segment to match) before selecting the `GitHubApp`/secret, and reject the request if they diverge. Additionally, do not allow `verify_webhook_signature` to trivially return `true` for organizations without a `webhook_secret`; require an explicit signature-disabled acknowledgment instead of implicit fallback.

### Proof of Concept
1. Configure Shipit with two organizations: `attacker-org` (no `webhook_secret` set) and `victim-org` (protected, unknown secret to attacker).
2. Send:
```http
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything

{
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>"
}
```
3. `repository_owner` resolves to `attacker-org`, whose `GitHubApp#verify_webhook_signature` returns `true` unconditionally (no `webhook_secret`) [11](#0-10) .
4. `PushHandler` resolves the stack from `repository.full_name = "victim-org/victim-repo"` [12](#0-11)  and calls `stack.sync_github(expected_head_sha: params.after)`, forging a push event on a fully-protected repository without ever presenting a valid signature for it.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
