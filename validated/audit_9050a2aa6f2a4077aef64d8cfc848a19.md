### Title
Signature verification keyed by `repository.owner.login` while handlers act on `repository.full_name` allows cross-organization stack archival - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/secret to verify the webhook signature using `params.dig('repository','owner','login')`, but `Shipit::Webhooks::Handlers::PullRequest::ClosedHandler#repository` (and every sibling handler) resolves the target repository/stack using `params.repository.full_name`. Nothing binds these two values together, so an attacker who controls an organization with no `webhook_secret` configured can send a payload where `owner.login` names their own org (bypassing signature checks) while `full_name` names a victim org's repository, causing that victim's review stack to be archived.

### Finding Description
The broken binding, stated as an equality that must hold but does not:
`organization_that_verified_signature (params.repository.owner.login)` == `organization_owning_mutated_repository (params.repository.full_name.split('/').first)`

Trace:
1. `verify_signature` computes `repository_owner` via `params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)` to get the `GitHubApp` for that org [1](#0-0) .
2. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org has no `webhook_secret` configured: `return true unless webhook_secret` [2](#0-1) .
3. On success, `#create` re-parses `request.raw_post` and dispatches to handlers for the event, e.g. `ClosedHandler` [3](#0-2) .
4. `ClosedHandler#repository` resolves the repository purely from `params.repository.full_name`, independent of `owner.login`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [4](#0-3) .
5. `ClosedHandler#process` calls `review_stack.archive!`, and `ReviewStackAdapter#archive!` performs `stack.remove_from_provisioning_queue`, `stack.deprovision`, `stack.archive!(user, ...)` — a real state-mutating write — with no re-check that the stack's owning repository belongs to the org that verified the signature [5](#0-4) .

Root cause: `owner.login` (used for authentication) and `full_name` (used for authorization/target selection) are two independently attacker-controlled fields in the same untrusted JSON body, and the controller never asserts they agree. `Repository.from_github_repo_name` splits `full_name` and looks up by owner/name from that string alone, with no cross-check against `repository_owner` [6](#0-5) .

Attacker request: `POST /webhooks` with `X-Github-Event: pull_request`, `X-Hub-Signature` computed with any bytes (verification is vacuous), body:
```json
{"action":"closed","number":<N>,"pull_request":{...},"repository":{"owner":{"login":"A"},"full_name":"B/target-repo"},"sender":{"login":"..."}}
```
Provided `Shipit.github_apps` config has an entry for `A` with no `webhook_secret`, `verify_webhook_signature` returns `true` regardless of what's in `X-Hub-Signature` or the body, and the request is dispatched. `ClosedHandler` then archives `B/target-repo`'s review stack for PR `<N>` if such a stack exists.

Existing guards checked and found insufficient:
- `drop_unhandled_event` only checks event type is handled, not payload consistency [7](#0-6) .
- `ExplicitParameters` schema in `ClosedHandler` only validates types/presence of `repository.full_name`, not that it matches `owner.login` [8](#0-7) .
- `GithubOrganizationUnknown` rescue only fires if org `A` is not configured at all — it does nothing when `A` is configured but has no secret [9](#0-8) .

### Impact Explanation
An attacker with an org configured in `Shipit.github_apps` without a `webhook_secret` (or any org they can get onboarded with review stacks but no secret) can forge a webhook whose `owner.login` names that org, and whose `repository.full_name` names an arbitrary other tracked repository (`B/target-repo`), causing `B`'s review stack to be deprovisioned/archived — a cross-repository unauthorized write triggered by a payload that never went through `B`'s signing secret. This is repeatable against any repository/organization tracked by the Shipit instance whose review stack environment (`pr<N>`) can be guessed or observed, matching the Critical category: "a payload for one repository mutating another's stack."

### Likelihood Explanation
Preconditions: (1) The Shipit instance must have at least one organization entry in `Shipit.github_apps`/`secrets.github` with no `webhook_secret` set (an operator misconfiguration, but one the codebase explicitly tolerates via `return true unless webhook_secret`), and (2) a live `ReviewStack` must exist for the target repo/PR combination. Given (1), the attack requires no secrets from the attacker — no signing key, no session, no API token — just knowledge of the victim repo's `full_name` and PR number, both of which are typically public. This is a config-dependent but code-enabled vulnerability: the engine's own logic permits total signature bypass for any no-secret org and never re-validates the acting org against the target repo.

### Recommendation
In `Shipit::WebhooksController`, after determining `repository_owner`, validate that it matches the owner segment of `params.dig('repository','full_name')` before proceeding, rejecting mismatches with `head(422)`. Additionally, treat an org configured without a `webhook_secret` as a hard misconfiguration error rather than silently authorizing all payloads (e.g., raise/log loudly and refuse if `webhook_secret` is blank for a configured org), since `verify_webhook_signature`'s `return true unless webhook_secret` effectively disables authentication entirely for such orgs.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "webhook naming org A (no secret) but full_name of org B's repo archives B's stack" do
  # Preconditions
  stack = shipit_stacks(:review_stack_org_b) # lives under repository B/target-repo, environment "pr1"
  refute stack.archived?

  Shipit.stubs(:github_app_config).with('a').returns({}) # org A configured, no webhook_secret
  # verify_webhook_signature('sha1=anything', raw_body) must be true because webhook_secret is blank
  github_app_a = Shipit.github(organization: 'a')
  assert_nil github_app_a.send(:webhook_secret)

  request.headers['X-Github-Event'] = 'pull_request'
  request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # never validated against B's secret

  body = {
    action: 'closed',
    number: 1,
    pull_request: { id: 1, number: 1, url: '...', title: 't', state: 'closed',
                     additions: 0, deletions: 0,
                     head: { sha: 'x', ref: 'feature' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { owner: { login: 'A' }, full_name: 'B/target-repo' },
    sender: { login: 'attacker' }
  }.to_json

  post :create, body: body, as: :json

  assert_response :ok
  assert stack.reload.archived?, "Expected B's stack to be archived despite never being signed by B's webhook_secret"
end
```
Assertion of the binding: before the request, `repository_owner ('A') != full_name.split('/').first ('B')` and `stack.archived? == false`. After the request, the code treats `verify_webhook_signature` result for org `A` (vacuously `true`) as authorization to mutate org `B`'s stack — `stack.archived? == true` — proving the equality the security model requires (verifying org == acted-upon org) does not hold.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
