### Title
Unauthenticated disclosure of arbitrary stack `merge_status` via unvalidated `referrer` param - ([File: app/controllers/shipit/merge_status_controller.rb])

### Summary
`MergeStatusController#check` is exempted from `force_github_authentication` (`skip_authentication only: %i[check show]`) and, unlike `#show`, never checks `current_user.logged_in?` before rendering. The only "selector" used to pick which `Stack` row to expose is `referrer_parser.repo_owner`/`repo_name`, a regex capture parsed straight out of the client-supplied `params[:referrer]` string with no relation to any authenticated identity or webhook-verified organization.

### Finding Description
The claimed binding, stated as an equality that should hold but doesn't:
`current_user.identity_verified_for(repo) == true` is required to disclose `stack.merge_status`, but the actual code only enforces `repository.owner/name (from unauthenticated params[:referrer]) == repository.owner/name (of the Stack row returned by the DB query)`.

Code path: [1](#0-0)  exempts `check` (and `show`) from the `force_github_authentication` before_action defined in [2](#0-1) . Inside `#check`, `stack_status` is computed unconditionally: [3](#0-2) . The `stack` finder resolves purely from parsed `referrer`: [4](#0-3) , and `ReferrerParser` just regex-matches and downcases attacker-controlled input with zero relation to session/identity: [5](#0-4) .

Contrast with `#show`, which explicitly gates rendering on `current_user.logged_in?`: [6](#0-5) . `#check` has no equivalent gate, so it will return `stack_status` (JSON or plain text) for any repository owner/name pair the caller supplies in `referrer`, or any `stack_id`, regardless of session state, `AnonymousUser`, or GitHub org membership.

Attacker request: `GET /merge_status/check.json?referrer=https://github.com/repo-b/owner/pull/1` (no session cookie, no `Authorization` header). This resolves `repositories.owner = 'repo-b-owner'`/`name = 'repo-b'`, looks up the production-environment `Stack` for that repo, and returns its `merge_status` as JSON with no authentication check at all.

Existing guards checked and confirmed absent/insufficient here: `verify_signature`/webhook HMAC checks are irrelevant (this isn't the webhooks endpoint); `force_github_authentication` is explicitly skipped for this action; there is no `require_permission!` or `User#authorized?` call anywhere in `#check`; `ExplicitParameters` schemas aren't used on this controller; DB scoping by `repositories.owner`/`name` only selects *which* stack's status to return — it enforces no authorization, since any caller can supply any owner/name pair.

### Impact Explanation
Any unauthenticated internet client can enumerate/probe `merge_status` (queue position, lock state, pass/fail status) for any repository configured in the Shipit instance, including private/internal repositories the attacker has no access to, by supplying a crafted `referrer` or `stack_id` param. This is a repeatable, zero-cost, unauthenticated read of stack state across arbitrary tenants/repositories on the same Shipit instance — matching the "High: unauthenticated read of stack state" impact category. No secrets, tokens, or write access are obtained; this is a confidentiality-only issue limited to merge/queue status data.

### Likelihood Explanation
Trivial and fully repeatable: no Shipit session, no `ApiClient` token, no GitHub team membership, and no valid webhook secret is required. The only precondition is knowing (or guessing) a target repository's owner/name (or `stack_id`), both of which are frequently public/guessable (e.g., visible on the public GitHub repo itself, or via typical naming conventions), and the endpoint is unauthenticated by explicit `skip_authentication` design for `#check`.

### Recommendation
Add the same authentication/authorization gate to `#check` that `#show` already has (`return head(:forbidden) unless current_user.logged_in? && current_user.authorized_for?(stack.repository)`), or scope stack lookup in `#check` to only repositories the requester is authorized to view before computing/returning `stack_status`.

### Proof of Concept
```ruby
# test/controllers/shipit/merge_status_controller_test.rb (illustrative, minitest)
test "#check discloses stack_status to an unauthenticated/anonymous user" do
  stack = shipit_stacks(:shipit) # fixture stack for a known repo/owner
  assert_equal false, AnonymousUser.new.logged_in?

  # no session[:user_id] set -> current_user resolves to AnonymousUser
  get :check, params: {
    referrer: "https://github.com/#{stack.repository.owner}/#{stack.repository.name}/pull/1"
  }, format: :json

  body = JSON.parse(response.body)
  assert_not_nil body["stack_status"]
  assert_includes %w(success pending failure blocked), body["stack_status"]
end
```
This demonstrates that with `current_user` being `AnonymousUser` (`logged_in? == false`), `#check` still renders non-empty `stack_status` for the targeted stack, confirming disclosure with no identity binding enforced beyond matching the attacker-supplied repo owner/name string to the DB row.

    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
    end

        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?

        end

      end
