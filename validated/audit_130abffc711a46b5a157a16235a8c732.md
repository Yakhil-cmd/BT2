### Title
Unvalidated P2P Staking Info Written Before `InsertReceiptChain` Causes Persistent Staking DB Corruption During Fast Sync — (`datasync/downloader/downloader.go`)

### Summary

During fast sync, both `commitFastSyncData` and `commitPivotBlock` call `PutStakingInfoToDB` with peer-supplied `P2PStakingInfo` **before** `InsertReceiptChain` is called. The staking info delivery path has an explicit no-op validator (`// TODO-Kaia-Snapsync update validation logic`). A single connected P2P peer can inject arbitrary staking data (validator node IDs, reward addresses, staking amounts) that is written unconditionally and immediately to the persistent DB. Because `InsertReceiptChain` does not invoke `PostInsertBlock`, the staking module never re-derives the correct value from chain state for fast-synced blocks. The `SyncStakingInfo` recovery path also skips blocks that already have a DB entry, so the corrupted record survives operator-initiated recovery.

### Finding Description

**Step 1 — No content validation on delivery.**

`queue.DeliverStakingInfos` accepts arbitrary peer-supplied data with a stub validator:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [1](#0-0) 

Receipts, by contrast, are validated against `header.ReceiptHash` before being stored. [2](#0-1) 

**Step 2 — Unconditional DB write precedes `InsertReceiptChain` in both functions.**

In `commitFastSyncData`:
```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(...)   // ← written first
}
// ...
if index, err := d.blockchain.InsertReceiptChain(blocks, receipts); err != nil {
    return fmt.Errorf(...)                    // ← staking write already committed
}
``` [3](#0-2) 

In `commitPivotBlock`:
```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(...)   // ← written first
}
if _, err := d.blockchain.InsertReceiptChain(...); err != nil {
    return err                                // ← staking write already committed
}
``` [4](#0-3) 

`PutStakingInfoToDB` calls `WriteStakingInfo` which issues a direct `db.Put` — not a batch — so the write is immediately durable. [5](#0-4) 

**Step 3 — `InsertReceiptChain` never triggers `PostInsertBlock`.**

`PostInsertBlock` on the staking module re-derives and persists the correct staking info from chain state, but it is only called from `insertChain` (full sync) and the block worker — never from `InsertReceiptChain`. [6](#0-5) [7](#0-6) 

**Step 4 — `SyncStakingInfo` recovery skips blocks that already have a DB entry.**

```go
has := d.stakingModule.GetStakingInfoFromDB(i) != nil
if !has {
    blockNums = append(blockNums, i)
    ...
}
``` [8](#0-7) 

Once the attacker's fabricated record is in the DB, the operator-initiated recovery path silently skips it.

### Impact Explanation

The staking DB record for a given epoch determines:
- `NodeIds` — the validator set eligible to propose/validate blocks (WeightedRandom policy)
- `RewardAddrs` — addresses that receive block rewards
- `StakingAmounts` — weights used for proposer selection

A fabricated record causes the synced node to use a wrong validator set and wrong reward addresses for all blocks in that epoch. This produces consensus divergence (the node rejects or accepts blocks based on a wrong committee) and incorrect reward distribution (rewards credited to attacker-controlled addresses instead of legitimate validators).

The corruption is durable: `InsertReceiptChain` does not re-derive staking info, and the `SyncStakingInfo` recovery path skips already-populated entries.

### Likelihood Explanation

Fast sync is the default mode for new nodes joining the network. Any peer that can complete the P2P handshake (permissionless) can respond to staking info requests with fabricated data. The attacker does not need to forge block headers or receipts — only the staking info payload, which has no cryptographic binding to the header. A single malicious peer connected at the right moment during fast sync is sufficient.

### Recommendation

1. Move `PutStakingInfoToDB` to after a successful `InsertReceiptChain` return in both `commitFastSyncData` and `commitPivotBlock`.
2. Implement content validation in `queue.DeliverStakingInfos` — at minimum, verify that the delivered `BlockNum` matches the requested header number and that the staking amounts are non-negative.
3. After fast sync completes, re-derive staking info from chain state for all staking-update blocks in the synced range (analogous to what `PostInsertBlock` does for full sync).
4. In `SyncStakingInfo`, allow overwriting existing DB entries rather than skipping them, so operator-initiated recovery can correct corrupted records.

### Proof of Concept

1. Stand up a victim node configured for fast sync with WeightedRandom proposer policy (pre-Kaia fork).
2. Connect an attacker peer that responds to `RequestStakingInfo` for the pivot block's hash with a `P2PStakingInfo` containing attacker-controlled `CouncilRewardAddrs` and `CouncilNodeAddrs`.
3. Intercept or mock `InsertReceiptChain` to return an error for the pivot block.
4. Observe that `PutStakingInfoToDB` was called with the fabricated data before the error is returned.
5. Read the staking DB entry for the pivot block's epoch — it contains the attacker's addresses.
6. Restart the sync; `SyncStakingInfo` skips the block because `GetStakingInfoFromDB` returns non-nil.
7. After sync completes, the node uses the attacker's validator set and reward addresses for that epoch.

func (bc *BlockChain) InsertReceiptChain(blockChain types.Blocks, receiptChain []types.Receipts) (int, error) {
	bc.wg.Add(1)
	defer bc.wg.Done()

	// Do a sanity check that the provided chain is actually ordered and linked
	for i := 1; i < len(blockChain); i++ {
		if blockChain[i].NumberU64() != blockChain[i-1].NumberU64()+1 || blockChain[i].ParentHash() != blockChain[i-1].Hash() {
			logger.Error("Non contiguous receipt insert", "number", blockChain[i].Number(), "hash", blockChain[i].Hash(), "parent", blockChain[i].ParentHash(),
				"prevnumber", blockChain[i-1].Number(), "prevhash", blockChain[i-1].Hash())
			return 0, fmt.Errorf("non contiguous insert: item %d is #%d [%x…], item %d is #%d [%x…] (parent [%x…])", i-1, blockChain[i-1].NumberU64(),
				blockChain[i-1].Hash().Bytes()[:4], i, blockChain[i].NumberU64(), blockChain[i].Hash().Bytes()[:4], blockChain[i].ParentHash().Bytes()[:4])
		}
	}

	var (
		stats = struct{ processed, ignored int32 }{}
		start = time.Now()
		bytes = 0

		// TODO-Kaia Needs to roll back if any one of batches fails
		bodyBatch            = bc.db.NewBatch(database.BodyDB)
		receiptsBatch        = bc.db.NewBatch(database.ReceiptsDB)
		txLookupEntriesBatch = bc.db.NewBatch(database.TxLookUpEntryDB)
	)

	defer bodyBatch.Release()
	defer receiptsBatch.Release()
	defer txLookupEntriesBatch.Release()

	for i, block := range blockChain {
		receipts := receiptChain[i]
		// Short circuit insertion if shutting down or processing failed
		if atomic.LoadInt32(&bc.procInterrupt) == 1 {
			return 0, nil
		}
		// Short circuit if the owner header is unknown
		if !bc.HasHeader(block.Hash(), block.NumberU64()) {
			return i, fmt.Errorf("containing header #%d [%x…] unknown", block.Number(), block.Hash().Bytes()[:4])
		}
		// Skip if the entire data is already known
		if bc.HasBlock(block.Hash(), block.NumberU64()) {
			stats.ignored++
			continue
		}
		// Compute all the non-consensus fields of the receipts
		if err := SetReceiptsData(bc.chainConfig, block, receipts); err != nil {
			return i, fmt.Errorf("failed to set receipts data: %v", err)
		}
		// Write all the data out into the database
		bc.db.PutBodyToBatch(bodyBatch, block.Hash(), block.NumberU64(), block.Body())
		bc.db.PutReceiptsToBatch(receiptsBatch, block.Hash(), block.NumberU64(), receipts)
		bc.db.PutTxLookupEntriesToBatch(txLookupEntriesBatch, block)

		stats.processed++

		totalBytes, err := database.WriteBatchesOverThreshold(bodyBatch, receiptsBatch, txLookupEntriesBatch)
		if err != nil {
			return 0, err
		} else {
			bytes += totalBytes
		}
	}

	totalBytes, err := database.WriteBatches(bodyBatch, receiptsBatch, txLookupEntriesBatch)
	if err != nil {
		return 0, err
	} else {
		bytes += totalBytes
	}

	// Update the head fast sync block if better
	bc.mu.Lock()
	head := blockChain[len(blockChain)-1]
	if td := bc.GetTd(head.Hash(), head.NumberU64()); td != nil { // Rewind may have occurred, skip in that case
		currentFastBlock := bc.CurrentFastBlock()
		if bc.GetTd(currentFastBlock.Hash(), currentFastBlock.NumberU64()).Cmp(td) < 0 {
			bc.db.WriteHeadFastBlockHash(head.Hash())
			bc.currentFastBlock.Store(head)
		}
	}
	bc.mu.Unlock()

	logger.Info("Imported new block receipts",
		"count", stats.processed,
		"elapsed", common.PrettyDuration(time.Since(start)),
		"number", head.Number(),
		"hash", head.Hash(),
		"size", common.StorageSize(bytes),
		"ignored", stats.ignored)
	return 0, nil
}
