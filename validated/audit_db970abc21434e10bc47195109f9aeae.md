### Title
Raw comment/PR content written directly to `IO.Out` bypasses ANSI sanitization before reaching pager - (File: pkg/cmd/pr/shared/comments.go)

### Summary
`RawCommentList` (and `printRawPrPreview`) writes attacker-controlled comment/PR body text directly into the buffer returned to callers via `fmt.Fprint`, and callers such as `pkg/cmd/pr/view/view.go` write that buffer straight to `opts.IO.Out` instead of through `IOStreams.ContentOut`, the writer iostreams.go explicitly documents as being for "external content ... where the application is not the author of the bytes" and which by default sanitizes escape sequences via `asciisanitizer`.

### Finding Description
`RawCommentList` at [1](#0-0) builds its output by calling `formatRawComment`, which does `fmt.Fprintln(&b, comment.Content())` directly on the attacker-supplied comment body [2](#0-1) . `comment.Content()` originates from the GitHub API (issue/PR comment or review body) and is fully attacker-controlled — any unprivileged user who can comment on a public issue/PR controls these bytes.

The resulting string is then written straight to `opts.IO.Out` in `pr view`'s non-interactive/plain path: `fmt.Fprint(opts.IO.Out, shared.RawCommentList(pr.Comments, pr.DisplayableReviews()))` [3](#0-2) . This same command also invokes the pager earlier via `opts.IO.StartPager()` [4](#0-3) , meaning these raw, unsanitized bytes are the exact stream that gets forwarded to an external pager process (e.g., `less`, or a user/environment-configured `$PAGER`/`$GH_PAGER`).

Critically, `iostreams.go` defines a separate output stream, `ContentOut`, specifically intended for this class of data: "ContentOut is the writer for external content (HTTP response bodies, gist files, etc.) where the application is not the author of the bytes. By default it sanitizes ANSI escape sequences before they reach..." [5](#0-4) . `RawCommentList`/`printRawPrPreview` do not use `ContentOut`; they use the plain `Out` writer, so this dedicated sanitization mechanism is bypassed for comment bodies and raw PR bodies (`fmt.Fprintln(out, pr.Body)` in `printRawPrPreview` [6](#0-5) ).

Because the escape sequences are inert to gh itself (it just streams bytes) but are interpreted by the pager/terminal, an attacker can embed terminal escape sequences (e.g., OSC 8 hyperlink spoofing, terminal title manipulation, cursor movement to overwrite prior lines, or sequences some terminals interpret as further commands) in a PR/issue comment body. When a victim runs `gh pr view --comments` (or without a TTY where output still flows to a pager if configured) on that PR, the malicious bytes reach the pager unfiltered.

### Impact Explanation
This enables terminal/output spoofing: an attacker-controlled comment can manipulate what the victim sees in their pager (e.g., fake prompts, hidden/obscured text, spoofed links), potentially tricking the victim into revealing credentials or approving destructive actions they believe are something else. This matches the "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" impact class described in the prompt, scoped to the specific code path where the dedicated sanitizing writer (`ContentOut`) exists but is not used for comment content.

### Likelihood Explanation
Preconditions are minimal: any unprivileged GitHub user can post a comment or review on a public issue/PR containing arbitrary bytes including ANSI/terminal escape sequences. The victim only needs to run an ordinary `gh pr view <number> --comments` (or equivalent `gh issue view`, which shares `RawCommentList`) against that PR. This is fully repeatable and requires no special configuration beyond a terminal/pager that interprets the injected escapes.

### Recommendation
Route comment bodies and raw PR/issue body text through `IOStreams.ContentOut` (or apply the same `asciisanitizer`-based sanitization used by `ContentOut`) before writing to `Out`, in `formatRawComment`, `RawCommentList`, and `printRawPrPreview`, so that attacker-authored text is sanitized before it reaches the pager, consistent with the design intent already documented in `iostreams.go`.

### Proof of Concept
```go
// pkg/cmd/pr/shared/comments_test.go
func TestRawCommentList_SanitizesEscapeSequences(t *testing.T) {
    malicious := "\x1b]0;pwned\x07\x1b[2Jfake prompt: enter password:"
    comments := api.Comments{
        Nodes: []*api.Comment{
            {Body: malicious, Author: api.Author{Login: "attacker"}},
        },
    }
    out := RawCommentList(comments, api.PullRequestReviews{})
    // Expect: no raw ESC (\x1b) bytes should be present verbatim in output
    // meant to be forwarded to a pager; sanitized form should be used instead.
    if strings.Contains(out, "\x1b") {
        t.Fatalf("expected escape sequences to be sanitized before reaching pager output, got: %q", out)
    }
}
```
Additional integration-level validation: stub `opts.IO.Out` with a `*bytes.Buffer` acting as the pager's stdin in `pr view --comments` end-to-end test, submit a comment body containing `\x1b]8;;http://evil` (OSC 8 hyperlink injection) via httpmock, and assert the buffer written to the stub pager does not contain the raw escape sequence.

func formatRawComment(comment Comment) string {
	if comment.IsHidden() {
		return ""
	}
	var b strings.Builder
	fmt.Fprintf(&b, "author:\t%s\n", comment.AuthorLogin())
	fmt.Fprintf(&b, "association:\t%s\n", strings.ToLower(comment.Association()))
	fmt.Fprintf(&b, "edited:\t%t\n", comment.IsEdited())
	fmt.Fprintf(&b, "status:\t%s\n", formatRawCommentStatus(comment.Status()))
	fmt.Fprintln(&b, "--")
	fmt.Fprintln(&b, comment.Content())
	fmt.Fprintln(&b, "--")
	return b.String()
}
