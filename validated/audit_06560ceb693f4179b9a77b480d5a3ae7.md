### Title
Missing branch-name validation allows git-branch flag/argument injection via attacker-controlled `opts.Branch` in `gitExecuter.CreateBranch` - ([File: pkg/cmd/repo/sync/git.go])

### Summary
`gitExecuter.CreateBranch` passes `branch` directly as a positional argument to `git branch <branch> <ref>` and `git branch --set-upstream-to=<upstream> <branch>` without any leading-dash/flag validation. `opts.Branch` can originate from the API-resolved `RepoDefaultBranch` of an attacker-controlled `--source` repository, which reaches `CreateBranch` unsanitized when the local branch does not yet exist.

### Finding Description
In `pkg/cmd/repo/sync/sync.go`, `syncLocalRepo` resolves `opts.Branch` from `api.RepoDefaultBranch(apiClient, srcRepo)` when `--branch` is not given [1](#0-0) , where `srcRepo` can be an attacker-chosen repository via `--source`. That branch value later flows into `executeLocalRepoSync` and, when the branch does not exist locally, into `git.CreateBranch(branch, "FETCH_HEAD", fmt.Sprintf("%s/%s", remote, branch))` [2](#0-1) .

`CreateBranch` in `pkg/cmd/repo/sync/git.go` builds git commands using `branch` as a bare positional argument, unlike `UpdateBranch` and `Fetch`, which prefix the value with `refs/heads/` (neutralizing a leading `-`): [3](#0-2) 

Contrast this with `pkg/cmd/pr/checkout/checkout.go`, which explicitly validates and rejects head branch names beginning with `-` (`invalid branch name: "-foo"`), a defense that exists precisely because this codebase's authors have previously treated attacker-influenced branch/ref name strings from the GitHub API as untrusted, non-validated-against-git-ref-rules input [4](#0-3) . No equivalent check exists in the `repo sync` code path.

### Impact Explanation
If a crafted branch/ref-name string (e.g., one beginning with `-`) can reach `CreateBranch`, it would be interpreted as a `git branch` option rather than a branch name, allowing manipulation of local git-branch invocation behavior (e.g., unexpected branch deletion/renaming flags) rather than arbitrary process execution. This falls short of RCE, credential exfiltration, or authenticated cross-host requests — the concrete impact is limited to local git-branch command misbehavior/state corruption in the destination repo.

### Likelihood Explanation
Exploitability hinges entirely on whether an attacker can actually get GitHub to store/return a branch name beginning with `-` as a repository's default branch via `RepoDefaultBranch`. Standard git ref-name rules (`git check-ref-format`) forbid ref components beginning with `-`, and this restriction is normally enforced both locally by git and by GitHub's branch-creation/rename APIs. I could not verify in this codebase or via available tools whether GitHub's API enforces this rule strictly enough to block such a default-branch name (the sibling protection in `checkout.go` suggests the authors believed such values could reach the CLI unsanitized in at least one scenario, but I found no direct evidence in this repo confirming GitHub's server-side validation can be bypassed for default branch names specifically).

### Recommendation
Add the same leading-dash / invalid-branch-name validation used in `pkg/cmd/pr/checkout/checkout.go` to `opts.Branch` before it is used in `pkg/cmd/repo/sync/sync.go`/`git.go`, and prefer using `--` argument separators (e.g., `git branch -- <branch> <ref>`) in `gitExecuter.CreateBranch` and other raw `g.client.Command` calls that accept externally-derived branch/ref strings as bare positional arguments.

### Proof of Concept
Unable to construct a concrete httpmock/git-stub PoC confirming actual exploitability, because it depends on an unverified precondition (whether GitHub's API can return a default branch name beginning with `-`). A test to build once that precondition is confirmed:
1. Mock `api.RepoDefaultBranch` (via httpmock GraphQL/REST stub) to return `"-D"` for the attacker's `srcRepo`.
2. Run `syncLocalRepo` with `--source attacker/repo` and no `--branch`, with a `git-stub` `CommandStubber` capturing the exact argv passed for the `branch` subcommand.
3. Assert whether the stub receives `git branch -D FETCH_HEAD` (flag injection) instead of `git branch -- -D FETCH_HEAD` / rejection with `invalid branch name`.

```go
func (g *gitExecuter) CreateBranch(branch, ref, upstream string) error {
	ctx := context.Background()
	cmd, err := g.client.Command(ctx, "branch", branch, ref)
	if err != nil {
		return err
	}
	if _, err := cmd.Output(); err != nil {
		return err
	}
	cmd, err = g.client.Command(ctx, "branch", "--set-upstream-to", upstream, branch)
	if err != nil {
		return err
	}
	_, err = cmd.Output()
	return err
}
```
