### Title
Unauthenticated `new_shared_address` Device Message Allows Silent Injection of Attacker-Controlled Co-Signer into a Victim's Multisig Address - (File: `wallet_defined_by_addresses.js`)

### Summary
The Nextcloud advisory describes a backend authorization flaw where knowledge of another user's identifier (their principal URL) lets an attacker submit a request that silently changes group/resource membership, granting the attacker full access to a resource that belongs to someone else. The analogous flaw in `ocore` is in the `new_shared_address` device-message handler: any correspondent who knows a victim's wallet address can push a crafted multisig/shared-address definition naming the victim as a member, while embedding the attacker as a co-signer, and the wallet silently persists it as a legitimate local address with no user confirmation — unlike the "official" shared-address creation flow, which requires explicit user approval.

### Finding Description
`wallet.js` routes the `new_shared_address` message straight into `walletDefinedByAddresses.handleNewSharedAddress` with no confirmation dialog: [1](#0-0) 

`handleNewSharedAddress` only checks that the `definition`/`signers` are internally consistent (definition hashes to the claimed `address`, and each signer's declared address matches the corresponding leaf of the definition), and that the *local device* is a member somewhere in the tree: [2](#0-1) 

The membership check is performed by `determineIfIncludesMeAndRewriteDeviceAddress`, which only verifies that one of the addresses referenced in `signers` is a `my_addresses` or `shared_addresses` entry of the receiver — it never checks that the *sender* (`from_address`, i.e. the correspondent device that sent the message) is actually a party to the new shared address, nor does it require any prior handshake/consent step: [3](#0-2) 

Once the check passes, `addNewSharedAddress` unconditionally inserts the address, definition, and every signer (including the attacker-controlled device/address) into `shared_addresses` / `shared_address_signing_paths`, and fires `new_address` events that most GUIs use to display the address as a wallet-owned/shared address: [4](#0-3) 

By contrast, the "official"/reviewed flow for creating a shared address (`create_new_shared_address` → `approve_new_shared_address`) is explicitly designed to trigger a user confirmation dialog before any address is trusted, per the code comment: [5](#0-4) 

but that flow is optional and marked "unused" in the codebase, while the direct `new_shared_address` push path bypasses it entirely and is the one actually reachable and processed automatically by any paired correspondent.

### Impact Explanation
Any device that is (or becomes) a correspondent of the victim — which only requires exchanging a pairing code, an unprivileged action — and that knows or learns the victim's payment address, can silently register a shared/multisig address in the victim's wallet where the attacker is embedded as a co-signer (e.g., via an `or` or weighted `and` branch). Because the wallet displays and treats this address like any other locally known address/shared address without a confirmation step, a victim who is later induced to fund that address (e.g., believing it to be their own multisig with a known partner) exposes those funds to independent spending by the attacker, resulting in unauthorized loss of funds — the same class of harm (unauthorized access/modification of a resource that should require the victim's own membership decision) as the Nextcloud calendar takeover.

### Likelihood Explanation
Exploitation requires only: (1) being a correspondent of the victim (trivial via device pairing), and (2) knowing the victim's wallet address (routinely shared for payments). No cryptographic secret of the victim is needed, and the message handler accepts the crafted definition/signers automatically without any consent UI, making this readily reachable from an "unprivileged" correspondent similarly to how the Nextcloud bug only required an authenticated user who knew the target's principal URL.

### Recommendation
Require an explicit user-approval step (mirroring the `create_new_shared_address`/`approve_new_shared_address` flow) before any address delivered via an unsolicited `new_shared_address` message is written into `shared_addresses`/`shared_address_signing_paths`, and/or verify that the sending device (`from_address`) is itself one of the signer device addresses declared in the message before trusting/persisting the shared address definition.

### Proof of Concept
1. Attacker pairs with victim's wallet as a normal correspondent device.
2. Attacker learns victim's wallet address `V` (routinely shared for receiving payments).
3. Attacker crafts an `or` definition `["or", [["address","V"], ["address","$ATTACKER"]]]`, computes `address = chash160(definition)`, and sends a `new_shared_address` message `{address, definition, signers: {...}}` where `signers` maps the `V` leaf to `V`'s address/attacker-supplied device metadata and the second leaf to the attacker's own address/device.
4. Victim's `handleNewSharedAddress` verifies structural consistency and that `V` is a member (satisfied), and silently calls `addNewSharedAddress`, adding the address to the victim's `shared_addresses` table with no confirmation dialog.
5. If the victim later sends/receives funds to this new address believing it is exclusively theirs, the attacker can independently satisfy the `or` branch and spend the funds.

// Checks if any of my payment addresses is mentioned.
// It is possible that my device address is not mentioned in the definition if I'm a member of multisig address, one of my cosigners is mentioned instead
function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
