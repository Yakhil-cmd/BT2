### Title
Unbounded access-key/gas-key iteration in `remove_account` during `DeleteAccount` can exceed per-receipt gas budget and permanently brick account deletion - (File: core/store/src/utils/mod.rs)

### Summary
`remove_account` iterates over the *entire* set of access keys and gas-key nonces stored for an account in the trie before any of that work is gas-metered, mirroring the audited Solidity bug where a for-loop over an attacker/user-growable array (`allTokens`) could become unexecutable once the array is "significant in size." Here the growable, unbounded collection is the number of access keys (including gas keys and their nonces) an account can accumulate, and the trigger is the `DeleteAccount` action, which any unprivileged account can submit against itself.

### Finding Description
`remove_account` walks the whole access-key prefix range for an account with `locked_iter`, parsing every key and, for gas keys, every nonce index, before returning a count/byte total that is only used afterwards to compute compute-usage/gas: [1](#0-0) 

There is no cap on how many access keys (or gas-key nonces) an account can hold — no `max_number_of_access_keys`-style protocol limit exists in the codebase (confirmed via search returning no matches), so a user can grow this collection to an arbitrarily large size over many cheap, individually-paid `AddKey`/gas-key-creation transactions. The related helper `compute_gas_key_balance_sum`, used along the same `DeleteAccount`/gas-key code path, has the identical unbounded iterate-then-charge pattern: [2](#0-1) 

Tests confirm the removal cost is only known and charged as `compute_usage` *after* the full loop over all keys/nonces has already executed against the trie (I/O + CPU work already spent): [3](#0-2) [4](#0-3) 

This is structurally the same bug class as the reported Solidity issue: a function (`DeleteAccount`, analogous to `withdrawAllIncentives`) contains an internal loop bounded only by an attacker/user-controllable collection size (`access_keys`/`gas_key_nonce`s, analogous to `allTokens`), with no protocol-level cap comparable to the auditors' recommended "<100 items" ceiling. Once the collection is large enough, the single receipt executing `DeleteAccount` performs unbounded trie reads before the runtime's gas accounting can reject it, so the action either burns disproportionate real node resources or exceeds the receipt/block gas limit and can never successfully complete.

### Impact Explanation
If an account accumulates enough access keys/gas-key nonces, its `DeleteAccount` action can never finish within the gas limits of a single receipt: the account (and any locked storage-staked balance) becomes effectively unable to be closed, a denial-of-service on that account's lifecycle. More importantly, because the trie iteration cost is incurred *before* being converted into a gas charge, the node performs unbounded, unmetered read/CPU work per receipt — this is a resource-exhaustion / potential chain-stall vector rather than a benign gas-estimation inconvenience, since block production requires bounded per-receipt execution time.

### Likelihood Explanation
Growing an account's access-key/gas-key set to a large size only requires ordinary `AddKey` or gas-key-creation transactions, each individually affordable and each independently valid; no privileged role is required. Triggering the vulnerable path only requires later submitting a single `DeleteAccount` action against that same account. This is fully reachable by any unprivileged account, matching the required threat model.

### Recommendation
Add an explicit, protocol-enforced maximum on the number of access keys and gas-key nonces per account, and/or make `remove_account` (and `compute_gas_key_balance_sum`) incrementally gas-metered during iteration so the loop can be aborted mid-way once the gas budget is exhausted, rather than only totting up cost after the full trie walk completes.

### Proof of Concept
1. From an unprivileged account, submit repeated `AddKey` transactions (or gas-key creation, per `access_keys.rs::add_gas_key`) to accumulate a very large number of access keys / gas-key nonces on the account, each paid for individually and cheaply. [5](#0-4) 
2. Submit a `DeleteAccount` action for that account. Internally this calls `remove_account`, which iterates the full, now-large, `access_keys` prefix range in the trie in one uninterrupted loop before any gas is deducted for the work performed. [6](#0-5) 
3. Once the key/nonce count is large enough, the resulting compute usage exceeds the receipt's available gas, the action fails or the node spends disproportionate unmetered resources completing the iteration — the account can no longer be deleted, analogous to the reported "functions may become unexecutable due to potentially huge array" issue.

/// Computes the total balance across all gas keys for a given account.
pub fn compute_gas_key_balance_sum(
    state_update: &TrieUpdate,
    account_id: &AccountId,
) -> Result<Balance, StorageError> {
    let mut total = Balance::ZERO;
    let lock = state_update.trie().lock_for_iter();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if nonce_index.is_some() {
            continue;
        }
        if let Some(balance) = get_access_key_by_handle(state_update, account_id, &key_handle)?
            .as_ref()
            .and_then(|access_key| access_key.gas_key_info())
            .map(|gas_key_info| gas_key_info.balance)
        {
            total = total.checked_add(balance).ok_or_else(|| {
                StorageError::StorageInconsistentState("gas key balance overflow".to_string())
            })?;
        }
    }
    Ok(total)
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

fn add_gas_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    // For gas keys, nonce stored on access key is not used and should always be zero
    let mut access_key = access_key.clone();
    access_key.nonce = 0;
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    // Set up nonces for gas key
    let num_nonces = gas_key_info.num_nonces;
    let nonce = initial_nonce_value(block_height);
    for i in 0..num_nonces {
        set_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i, nonce);
    }

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(gas_key_storage_cost(fee_config, public_key, &access_key, num_nonces))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
