### Title
Liquidation silently skips bad-debt socialization when residual collateral exceeds the 5 USD dust cap, permanently stranding unbacked debt on suppliers - ([File: contracts/controller/src/positions/liquidation/apply.rs])

### Summary
The bug class is "a routine claims to perform a security-critical step but silently skips it." In XOXNO Lending, `liquidate` performs repayments and seizures and then calls `check_bad_debt_after_liquidation`, which is expected to socialize insolvent residual debt. It does so only when `is_socializable_bad_debt` returns true — `total_debt > total_collateral && total_collateral <= BAD_DEBT_USD_THRESHOLD` (5 USD WAD) — and otherwise returns silently. An unprivileged liquidator can drive an account into the state where debt exceeds collateral but collateral is above the dust cap; the cleanup is silently skipped, and because the permissionless `clean_bad_debt` enforces the same gate, the unbacked debt can never be socialized by any unprivileged caller.

### Finding Description
`check_bad_debt_after_liquidation` in `contracts/controller/src/positions/liquidation/apply.rs:301-316` removes the account if all borrow positions are empty, otherwise it socializes bad debt only under `is_socializable_bad_debt` (`contracts/controller/src/positions/liquidation/curve.rs:25-27`), which requires collateral at or below `BAD_DEBT_USD_THRESHOLD`. When `total_debt > total_collateral > 5 USD`, the function does nothing: no revert, no event, no socialize.

This state is reachable from the unprivileged `liquidate` path. `estimate_liquidation_amount` in `curve.rs:117-122` deliberately caps the repayment at the collateral-backed amount `floor(C / (1 + base))` when `total_collateral < total_debt`, leaving residual debt after the liquidation. Because the seizure plan is pro-rata over whole-unit, sub-3-decimal legs, the seized collateral need not exhaust the position's collateral; a residual collateral leg above 5 USD can remain alongside the residual unbacked debt. `execute_bad_debt_cleanup` in `contracts/controller/src/positions/liquidation/bad_debt.rs:14-60` — the only code path that seizes remaining positions and burns the account — is never invoked for this state, and `clean_bad_debt` reverts with `CannotCleanBadDebt` for the same gate.

### Impact Explanation
The residual account carries debt with no covering collateral. That debt is never written down via supply-index adjustment (the socialize step that is skipped), and it keeps accruing borrow-index interest. The pool books keep counting phantom debt repayment expectations while suppliers' claims are backed by less cash than `total_supply` shares imply — a protocol-insolvency condition. The only remaining remediation is the owner-only `force_socialize_bad_debt`, i.e., a privileged path; no unprivileged address can trigger the write-down, matching the analog's constraint and severity (Medium).

### Likelihood Explanation
Reachable by any liquidator calling `liquidate` on an account whose `total_collateral < total_debt` but exceeds the 5 USD dust threshold after pro-rata seizure — a normal outcome for moderately undercollateralized positions where whole-unit leg rounding or partial collateral coverage leaves residual collateral above the cap. No privileged role, leaked key, or off-chain component is required.

### Recommendation
Change the post-liquidation check so that any residual state with `total_debt > total_collateral` is socialized regardless of the collateral dust cap, or at minimum route the `collateral > BAD_DEBT_USD_THRESHOLD && debt > collateral` case into a socialize/write-down path (e.g., seize remaining collateral pro-rata to suppliers and write the supply index down). If the design intentionally defers large bad debt to `force_socialize_bad_debt`, revert the liquidation instead of silently committing a state no unprivileged actor can repair.

### Proof of Concept
1. A victim account holds collateral and debt such that after the collateral-backed repayment cap `floor(C/(1+base))` is applied, residual debt `D'` is positive and residual collateral `C'` lies between `BAD_DEBT_USD_THRESHOLD` and `D'` (achievable because pro-rata whole-unit seizure legs need not exhaust all collateral).
2. An unprivileged liquidator calls `controller::liquidate` with a full-close plan (`offered`) covering the capped repayment.
3. `check_bad_debt_after_liquidation` sees non-empty borrow positions, `is_socializable_bad_debt(D', C')` returns false because `C' > 5 USD`, and returns without action.
4. Any unprivileged `clean_bad_debt` call reverts with `CannotCleanBadDebt` (#114) on the same gate; the unbacked debt remains on the books accruing interest, and only the privileged `force_socialize_bad_debt` can resolve it.
