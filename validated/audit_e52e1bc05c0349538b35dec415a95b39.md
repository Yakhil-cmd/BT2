### Title
CCMenu API token scope bypass — `read:stack` token bound to one stack can read any other stack's build status - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::CCMenuController#stack` resolves the target stack directly from the `stack_id` URL parameter via `Stack.from_param!`, instead of going through the scope-restricted `stacks` helper used everywhere else in the API. This breaks the binding "the stack a token authorises == the stack it touches": an `ApiClient` token that is scoped to a single stack can be replayed against any other stack's CCMenu endpoint to read that stack's build/deploy status.

### Finding Description
`Shipit::Api::BaseController` scopes stack lookups to the calling `ApiClient`'s authorized stack: [1](#0-0) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

Every other API controller (`StacksController`, etc.) relies on this scoped `stacks`/`stack` method, so an `ApiClient` whose `stack_id` column is set (e.g. the read-only client created by `CCMenuUrlController#client`) can only resolve `stacks_controller`-style endpoints for its own stack.

`CCMenuController`, however, overrides `stack` and bypasses the scoping entirely: [2](#0-1) 

```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```

`Stack.from_param!` performs a global, unscoped lookup: [3](#0-2) 

The only authorization gate on this controller is `require_permission :read, :stack`, which merely checks that the token's permission list includes the string `read:stack` — it never checks whether the requested `stack_id` matches the token's `stack_id`: [4](#0-3) 

The `ApiClient#stack` association / `stack_id` column exists precisely to scope such single-stack tokens, e.g. the token minted by `CCMenuUrlController`: [5](#0-4) 

```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
```

Because `CCMenuController` never consults `current_api_client.stack_id`, any holder of a valid `read:stack` token — even one legitimately minted for a single, specific stack — can pass an arbitrary `stack_id` param and retrieve build state for a stack it was never authorized to see.

### Impact Explanation
This is an authorization boundary bypass: the binding "stack a token authorises" vs "stack it touches" is broken. Any leaked/observed CCMenu token (these tokens are embedded in plain URLs meant for CI dashboard tools, e.g. `ccmenu_url`, and are not bound in the browser session) can be replayed to read build status (`lastBuildStatus`, `lastBuildLabel`, activity, lock state) of every stack on the Shipit instance, not just the one it was created for. This is an unauthorized read of stack state across stacks the token holder has no right to see, matching the "escalation into authorization... unauthenticated/unauthorized read of stack state" impact category.

### Likelihood Explanation
Any user with legitimate, low-privilege access to one stack (able to mint a CCMenu URL for their own stack) can trivially exploit this by editing the `stack_id` in the request path/params of their own token — no additional secrets, sessions, or privileged access required beyond the token they already legitimately hold for their own stack.

### Recommendation
Change `CCMenuController#stack` to use the scoped resolver consistent with the rest of the API:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
so that a stack-bound `ApiClient` cannot resolve any stack other than the one it was authorized for.

### Proof of Concept
1. As a legitimate user with access only to `stack-A`, visit `stack-A`'s page; the app calls `CCMenuUrlController#fetch`, minting (or reusing) an `ApiClient` with `permissions: ['read:stack']` and `stack_id = stack-A.id`, returning a URL like `.../api/stacks/stack-A/ccmenu.xml?token=<TOKEN>`.
2. Using the same `<TOKEN>`, request `.../api/stacks/stack-B/ccmenu.xml?token=<TOKEN>` where `stack-B` is any other stack on the instance.
3. `CCMenuController#authenticate_api_client` accepts the token (it is a valid, unexpired `ApiClient`), `require_permission :read, :stack` passes because the token has `read:stack` in its permission list, and `stack` resolves `stack-B` via the unscoped `Stack.from_param!`, returning `stack-B`'s build status/deploy info even though the token was only ever authorized for `stack-A`. # frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
