### Title
Unbounded scan of all in-memory unstable AA units in `dataFeedExists()` allows AA trigger senders to cause a network-wide processing DoS - ([File: data_feeds.js])

### Summary
`dataFeeds.dataFeedExists()` is invoked from the `in_data_feed` oscript operator during AA trigger/response evaluation [1](#0-0) . When called in an AA context (`bAA === true`), it iterates over `storage.assocUnstableMessages`, i.e. **every currently unstable unit in the whole node's memory**, not just units related to the specified oracle addresses or feed, and for each one loops over all of that unit's messages [2](#0-1) . This is analogous to the Knox `_previewWithdraw()`/`_redeemMax()` bug class: a loop whose iteration count is driven by an attacker-inflatable, unbounded external collection rather than by a value the formula's complexity/`count_ops` accounting actually charges for.

### Finding Description
`dataFeedExists(arrAddresses, feed_name, relation, value, min_mci, max_mci, bAA, handleResult)` first executes an in-memory pre-check when `bAA` is true:
```
for (var unit in storage.assocUnstableMessages) {
    var objUnit = storage.assocUnstableUnits[unit] || storage.assocStableUnits[unit];
    ...
    if (!objUnit.bAA) continue;
    if (objUnit.latest_included_mc_index < min_mci || objUnit.latest_included_mc_index > max_mci) continue;
    if (_.intersection(arrAddresses, objUnit.author_addresses).length === 0) continue;
    storage.assocUnstableMessages[unit].forEach(function (message) { ... });
    if (bFound) break;
}
``` [2](#0-1) 

The `for...in` loop walks the **entire** `assocUnstableMessages` map — every unstable unit tracked by the node, regardless of oracle/feed — before any filtering by `arrAddresses` happens per-iteration. This map's size is a function of global DAG congestion (number of not-yet-stable units), which any unprivileged party can inflate by flooding the network with units (including AA triggers that create additional unstable AA response units), since AA responses themselves become entries in `assocUnstableMessages`/`assocUnstableUnits` until they stabilize [3](#0-2) .

Reachability: any AA trigger sender can invoke an AA whose oscript uses the `in_data_feed` formula operator [1](#0-0) ; this is a normal, publicly-documented oscript primitive available to any AA author and triggerable by any unprivileged sender who sends a payment to that AA. Unlike other formula loop primitives (`foreach`/`map`/`filter`/`array`/`dictionary`), which are explicitly capped (100/1000 element limits, `count` argument, complexity multipliers) [4](#0-3) [5](#0-4) , the cost of `in_data_feed`/`data_feed` is charged as a fixed complexity unit in `validateDataFeed()` regardless of how many unstable units currently exist in the node's memory [6](#0-5) . The static complexity/`count_ops` accounting therefore does not reflect the true, unbounded cost of this operation at execution time.

### Impact Explanation
Every full node executing the AA (to determine trigger outcome and reach consensus on the resulting state/response) must perform this same O(N) scan, where N is the number of currently unstable units held in that node's memory (which can vary slightly between nodes depending on synchronization timing, unlike deterministic on-chain data). Repeatedly triggering AAs that use `in_data_feed` while an attacker keeps the DAG artificially congested with many outstanding unstable units can:
- Significantly slow AA processing across all full nodes handling the same primary/secondary AA triggers, delaying MC advancement and unit confirmation (network unable to confirm new units in a timely manner).
- Because `assocUnstableMessages` is a live, per-node, timing-sensitive in-memory structure, nodes may not iterate over exactly the same content at the moment of evaluation, creating a path where different nodes could, in edge cases, observe different data-feed-matching results for `bFound`, leading to potential disagreement on AA response correctness/validity between nodes — a stability/consensus concern for the qualifying-impact bar ("node disagreement on validity or stability").

This does not directly cause fund loss but degrades the network's core liveness/consensus guarantees, meeting the Medium-severity bar for this class of finding (loop-based DoS reachable by an unprivileged AA trigger sender).

### Likelihood Explanation
Likelihood is Medium: any address can define an AA using `in_data_feed`, and any unprivileged user can trigger it with a small payment. The magnitude of the impact scales with how large `assocUnstableMessages` can be grown, which itself requires sustained network activity (many outstanding unstable units) — achievable but not trivial for a lone attacker without also paying real fees for many units/AA calls. The bug is deterministic and always executes the full-map scan whenever `in_data_feed` runs inside an AA (`bAA===true`), so the vulnerable code path itself is reliably reachable on every relevant trigger.

### Recommendation
- Index unstable AA units by oracle address (similar to how `readDataFeedValue`'s unstable-AA branch already filters by `_.intersection(arrAddresses, objUnit.author_addresses)`) so that the search does not require scanning the entire `assocUnstableMessages` map, e.g. maintain a `assocUnstableDataFeedsByAddress` index updated incrementally as units become unstable/stable.
- Charge `count_ops`/complexity for `data_feed`/`in_data_feed` proportionally to the current size of `storage.assocUnstableMessages` (or the filtered subset) at validation time rather than a fixed cost, so the AA's complexity budget reflects real work.
- Alternatively, cap the number of unstable units/messages considered in the pre-check (e.g., stop after a fixed number of iterations and fall back to the DB-backed stable lookup), bounding worst-case per-call cost.

### Proof of Concept
1. Deploy an AA whose oscript contains an `in_data_feed` call, e.g. a condition/state update using `in_data_feed(oracles=..., feed_name=..., feed_value>...)`.
2. As an unprivileged actor, flood the network with many independent units (payments, data messages, or additional AA triggers/responses) faster than they can stabilize, growing `storage.assocUnstableMessages` on full nodes to a large size (thousands of entries), consistent with the "over thousands of orders/entries" DoS scaling described in the source report.
3. Send a small trigger payment to the vulnerable AA to invoke `in_data_feed`.
4. Observe that `dataFeedExists()` performs a `for...in` scan over the entire (now large) `assocUnstableMessages` map on every full node processing this trigger before returning, measurably increasing AA-processing latency; repeating this trigger while congestion is sustained multiplies the cumulative CPU cost across the network's nodes performing consensus-critical AA execution.

function validateDataFeed(params) {
	var complexity = 1;
	if (params.oracles && params.feed_name) {
		for (var name in params) {
			var operator = params[name].operator;
			var value = params[name].value;
			if (Decimal.isDecimal(value)){
				if (!isFiniteDecimal(value))
					return {error: 'not finite', complexity};
				value = toDoubleRange(value).toString();
			}
			if (operator !== '=') return {error: 'not =', complexity};
			if (['oracles', 'feed_name', 'min_mci', 'feed_value', 'ifseveral', 'ifnone', 'what', 'type'].indexOf(name) === -1)
				return {error: 'unknown df param: ' + name, complexity};
			if (typeof value !== 'string')
				continue;
			switch (name) {
				case 'oracles':
					if (value.trim() === '') return {error: 'empty oracle', complexity};
					var addresses = value.split(':');
					if (addresses.length === 0) return {error: 'empty oracle list', complexity};
				//	complexity += addresses.length;
					if (!addresses.every(ValidationUtils.isValidAddress)) return {error: 'oracle address not valid', complexity};
					break;

				case 'feed_name':
					if (value.trim() === '') return {error: 'empty feed name', complexity};
					break;

				case 'min_mci':
					if (!(/^\d+$/.test(value) && ValidationUtils.isNonnegativeInteger(parseInt(value)))) return {
						error: 'bad min_mci',
						complexity
					};
					break;

				case 'feed_value':
					break;
				case 'ifseveral':
					if (!(value === 'last' || value === 'abort')) return {error: 'bad ifseveral: ' + value, complexity};
					break;
				case 'ifnone':
					break;
				case 'what':
					if (!(value === 'value' || value === 'unit')) return {error: 'bad what: ' + value, complexity};
					break;
				case 'type':
					if (!(value === 'string' || value === 'auto')) return {error: 'bad df type: ' + value, complexity};
					break;
				default:
					throw Error("unrecognized name after checking: "+name);
			}
		}
		return {error: false, complexity};
	} else {
		return {error: 'no oracles or feed name', complexity};
	}
}
