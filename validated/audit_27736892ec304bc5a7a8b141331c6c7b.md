### Title
Division-by-Zero Panic in `consolidatedNode.Split()` When Both CN and CL Staking Amounts Are Zero — (`kaiax/staking/staking_info.go`)

### Summary

`consolidatedNode.Split()` divides by `totalAmount = cnAmountBig + clAmountBig` without a zero guard. If a validator's CNStaking contract balance rounds down to 0 KAIA **and** its CL pool balance also rounds down to 0 KAIA, `totalAmount` is zero and `big.Int.Div` panics. This function is called unconditionally during block-reward finalization for the block proposer (post-Prague), crashing every honest node that tries to finalize such a block.

### Finding Description

`consolidatedNode.Split()` in `kaiax/staking/staking_info.go` computes the CN/CL reward split:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    ...
}
``` [1](#0-0) 

Both `StakingAmount` and `CLStakingInfo.CLStakingAmount` are stored as `uint64` values in **whole KAIA** (rounded down from wei). They are populated by:

```go
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
// and
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64()
``` [2](#0-1) 

Any balance below 1 KAIA (10^18 wei) rounds to 0. If both the CNStaking contract and the CL pool hold less than 1 KAIA, `totalAmount = 0`.

`Split()` is called for the block proposer in **both** `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` with no guard on `totalAmount`:

```go
// specWithProposerAndFunds (Prague path)
cnAmount, clAmount := cn.Split(proposer)
``` [3](#0-2) 

```go
// specWithProposerAndFundsFlex (Osaka/Flex path)
cnAmount, clAmount := cn.Split(proposer)
``` [3](#0-2) 

The only guard present is `c.CLStakingInfo == nil` — it does **not** check whether the combined staking amount is non-zero.

By contrast, the staking-reward distribution paths (`assignStakingRewards`, `assignStakingRewardsFlex`) are safe because they only call `Split()` after confirming `cnTotalStakingAmount > minStake`, which implies `totalAmount > 0`. [4](#0-3) 

### Impact Explanation

`specWithProposerAndFunds` / `specWithProposerAndFundsFlex` are called from `getDeferredRewardFullKore` / `getDeferredRewardFullFlex`, which are called from `GetDeferredReward`, which is called during `FinalizeState()` at the end of every block. A panic here crashes the node process. Every honest validator node that attempts to import or finalize the affected block will crash, causing a consensus halt / chain split.

The corrupted value is the **proposer's KAIA reward**: instead of being credited, the entire block-finalization step aborts, leaving the state uncommitted and the reward undelivered.

### Likelihood Explanation

After the Prague hardfork, any validator registered in the AddressBook whose CNStaking contract holds < 1 KAIA **and** whose CL pool also holds < 1 KAIA will trigger this panic the moment they are selected as block proposer. A validator can legitimately reach this state by withdrawing nearly all staked KAIA (leaving a dust amount below 1 KAIA in both contracts). The AddressBook does not enforce a minimum balance for remaining registered, and proposer selection is independent of current staking balance.

### Recommendation

Add a zero-check in `Split()` before dividing:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )

    // Guard: if total staking is zero, assign everything to CN.
    if totalAmount.Sign() == 0 {
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0) 

### Proof of Concept

1. After Prague hardfork, register a validator in AddressBook with CNStaking contract holding 0.5 KAIA (500_000_000_000_000_000 wei) and a CL pool also holding 0.5 KAIA.
2. Both amounts round down to 0 in `parseCallResult` / `parsePermissionlessCallResult` (division by `params.KAIA = 1e18`).
3. The consolidated node has `StakingAmount = 0` and `CLStakingInfo.CLStakingAmount = 0`, but `CLStakingInfo != nil`.
4. When this validator is selected as block proposer, `GetDeferredReward` → `getDeferredRewardFullKore` → `specWithProposerAndFunds` → `cn.Split(proposer)` is called.
5. Inside `Split`: `totalAmount = 0 + 0 = 0`; `big.Int.Div(x, 0)` panics.
6. Every node importing this block crashes during `FinalizeState()`. [5](#0-4) [6](#0-5)
