### Title
Webhook signature verification org selected from `repository.owner.login` is never checked against `repository.full_name`, letting a no-secret org's webhook mutate another org's `ReviewStack` via `LabelCapturingHandler` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the HMAC secret) to verify a webhook using only `params.dig('repository','owner','login')`, while every `pull_request` handler (including `LabelCapturingHandler`) resolves the `Shipit::Repository`/`ReviewStack` to mutate using the independent `params.repository.full_name` field. Because a GitHub App organization can be configured with no `webhook_secret` (a documented, supported configuration), any request claiming that no-secret org as `repository.owner.login` passes verification unconditionally, then can point `repository.full_name` at a completely different, secured org's repository whose `review_stacks_enabled=true`/`allow_all` review stack gets mutated.

### Finding Description
The broken binding, stated as an equality that the code assumes but never enforces:
`org_used_to_verify_signature (params.repository.owner.login) == org_that_owns_the_mutated_repository (params.repository.full_name.split('/').first)`

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository','owner','login')` [1](#0-0)  and uses it to select the `GitHubApp` instance: `Shipit.github(organization: repository_owner)` [2](#0-1) .
2. `Shipit::GitHubApp#verify_webhook_signature` short-circuits to `true` when that org has no configured `webhook_secret`: `return true unless webhook_secret` [3](#0-2) . Multi-org deployments with a `webhook_secret: nil` entry are an explicitly documented/example configuration [4](#0-3) .
3. Once `head(422)` is not triggered, `create` parses `params` fresh from the raw body and dispatches to all handlers for the event, with no re-validation tying the payload to the verified org: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [5](#0-4) .
4. `LabelCapturingHandler#repository` resolves the target repository purely from `params.repository.full_name`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) , and `Repository.from_github_repo_name` splits that string on `/` with no relation to the org used in step 1 [7](#0-6) .
5. For `action == "reopened"` against an existing, non-archived review stack (`reopened_active_stack?`), the handler persists attacker-controlled label names onto the victim stack's `PullRequest`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [8](#0-7) .
6. Those labels become uppercased environment variable keys merged into the review stack's deploy/task environment: `ReviewStack#env` merges `pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` [9](#0-8) , which flows into `TaskCommands#env`/`DeployCommands#env` used for command execution [10](#0-9) [11](#0-10) .

No existing guard closes this gap: `verify_signature` only checks the signature against the org named by `repository.owner.login`; it never compares that org to `repository.full_name`'s owner. `drop_unhandled_event` and the `ExplicitParameters` schema in `LabelCapturingHandler` only validate shape/presence, not cross-field consistency. `Repository.from_github_repo_name` and `ReviewStackAdapter` perform no ownership check either.

Note: this exploit path exists only when Shipit is configured with the **multi-org** GitHub App schema (`Shipit.github_default_organization` non-nil) and at least one configured org has no `webhook_secret`. In the single-app schema, `Shipit.github` ignores the `organization:` argument entirely and always uses the one global secret [12](#0-11) , so the bypass does not apply there.

### Impact Explanation
A single unauthenticated `POST /webhooks` request can write to another organization's `ReviewStack`/`PullRequest` records without ever presenting that organization's webhook secret — matching the rules' Critical category "a payload for one repository mutating another's stack." Because the injected values become uppercase environment variables merged into the stack's execution environment for subsequent tasks/deploys (`PTY.spawn`/`Command` invocations), an attacker can inject arbitrary env var names/values (e.g., overriding `PATH`, tool flags, or other build-influential variables) into a victim's `shipit.yml`-driven task execution, which is the RCE class named in the target severity. This is repeatable against every review-stack-enabled, `allow_all` repository owned by any configured org other than the no-secret one, as long as an active non-archived stack for the targeted PR number exists.

### Likelihood Explanation
Preconditions: Shipit must use the multi-org GitHub App config schema, with at least one configured org missing a `webhook_secret` (a supported, documented setup shown in the project's own sample config files), and the victim repository must have `review_stacks_enabled = true` with `provisioning_behavior = allow_all` and an already-provisioned, non-archived review stack for the targeted PR number. Attacker cost is a single crafted HTTP POST with no valid GitHub signature and no Shipit credentials — fully unauthenticated and repeatable at will.

### Recommendation
In `WebhooksController#verify_signature`, derive the verifying GitHub App from the same field used to resolve the target repository (`repository.full_name`'s owner), not from `repository.owner.login`/`organization.login` alone, and reject the request if the two disagree. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when `webhook_secret` is blank for a named multi-org config entry — require an explicit secret for every configured organization when running the multi-org schema, or fail closed instead of bypassing verification.

### Proof of Concept
minitest under `test/controllers/webhooks_controller_test.rb` (or a new test file), no live GitHub:
1. Configure `Shipit.secrets.github` with two orgs: `"no-secret-org"` (webhook_secret: nil) and `"victim-org"` (webhook_secret: "victim-secret"), stubbing `Shipit.stubs(:secrets)` as done in `test/unit/shipit_test.rb`.
2. Create `shipit_repositories(:victim)` with `owner: "victim-org"`, `name: "repo"`, `review_stacks_enabled: true`, `provisioning_behavior: "allow_all"`, and an existing non-archived `ReviewStack` with `environment: "pr1"` and an associated `PullRequest` whose `labels` is `[]`.
3. Build a `pull_request` JSON payload with `action: "reopened"`, `repository.owner.login: "no-secret-org"`, `repository.full_name: "victim-org/repo"`, `number: 1`, and `pull_request.labels: [{ "name" => "injected_env" }]`, and send it via `post :create, body: payload.to_json, as: :json` with `X-Github-Event: pull_request` and any/no `X-Hub-Signature`.
4. Assert `response.status == 200`(request accepted despite no valid signature for `victim-org`), then assert `Shipit::ReviewStack.find_by(environment: "pr1").pull_request.reload.labels == ["injected_env"]` and `stack.env["INJECTED_ENV"] == "true"` — proving that a request authenticated (trivially) as `no-secret-org` mutated `victim-org`'s stack state and injected an environment variable that will reach `Command#args`/`PTY.spawn` on the next task/deploy.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)

    end
