### Title
CCMenu token authorizes reads on every stack instead of the single stack it was minted for - (File: `app/controllers/shipit/ccmenu_url_controller.rb`)

### Summary
`CCMenuUrlController#fetch` mints a per-user `ApiClient` intended to expose the build status of one specific stack (the CCMenu URL is meant to be embedded in third-party CI dashboards/badges, i.e. handed to unauthenticated parties). The `ApiClient` it creates is never bound to that stack, so the `read:stack` token it hands out authorizes reads against **every** stack in the Shipit instance through the normal JSON API, not just the one the URL was generated for.

### Finding Description
The equality that should hold is: `token.stack == the single stack the CCMenu URL names`. Before the fix path exists, this is broken:

```ruby
# app/controllers/shipit/ccmenu_url_controller.rb
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
``` [1](#0-0) 

`find_or_create_by!` only keys on `creator` and `name`; `stack` is never part of the create attributes or lookup key, so the resulting `ApiClient` record has `stack_id == nil`. [2](#0-1) 

Every API controller derives its visible stack set from that flag:
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
``` [3](#0-2) 

Because `stack_id?` is false for the CCMenu client, `stacks` resolves to `Stack.all` for that token. The `authentication_token` generated for this client (`self.class.message_verifier.generate(id)`) is a self-contained bearer credential that can be used as Basic Auth against the whole JSON API (`authenticate_api_client` accepts any valid token via `BasicAuth.authenticate`). [4](#0-3) [5](#0-4) 

The check performed at each endpoint only verifies the client *has* the `read:stack` permission string, not that it is scoped to the requested stack:
```ruby
def check_permissions!(operation, scope)
  required_permission = "#{operation}:#{scope}"
  unless permissions.include?(required_permission)
    raise InsufficientPermission, ...
  end
end
``` [6](#0-5) 

So a CCMenu token — designed to be embedded in a public/unauthenticated CI badge for one stack — grants `read:stack` on `Api::StacksController#index/#show`, `Api::TasksController`, and other `require_permission :read, :stack` endpoints for **all** stacks configured in the Shipit instance, exposing deploy history, task output, and stack metadata for repositories the token was never meant to touch.

### Impact Explanation
This is an unauthorized cross-stack read: an unauthenticated third party who is only supposed to see one stack's public CCMenu XML status instead obtains full `read:stack` access (via Basic Auth on `/api/stacks*`) to every stack managed by that Shipit instance, including private/sensitive deploy pipelines, task logs, and commit/branch data. This matches the "High - unauthenticated read of stack state, task streams or deploy output" impact category.

### Likelihood Explanation
CCMenu URLs are explicitly designed to be shared with external tooling (CI status widgets, dashboards), so the token is expected to leave the trust boundary of the authenticated Shipit user. Any holder of one such URL/token automatically gets the over-broad `Stack.all` scope — no additional privilege or secret is required beyond the token itself, which was legitimately, if unintentionally, exposed.

### Recommendation
Bind the `ApiClient` created in `CCMenuUrlController#client` to the requested `stack` (include `stack:` in both the `find_or_create_by!` lookup key and `create_with` attributes) so `stack_id?` is true and `stacks` correctly narrows to `Stack.where(id: stack.id)`. Additionally, `Api::CCMenuController#stack` should reuse the scoped `stacks` helper instead of `Stack.from_param!`, in case any client is scoped but the controller still bypasses that scope.

### Proof of Concept
1. As an authorized Shipit dashboard user, visit stack A's settings page and copy its CCMenu URL, e.g. `GET /ccmenu/org/repoA/production` → returns `{ ccmenu_url: ".../api/stacks/org/repoA/production/ccmenu?token=<T>" }` generated by `CCMenuUrlController#fetch`. [7](#0-6) 
2. Embed/publish this URL as a public CI badge (its intended use).
3. Anyone in possession of `<T>` can instead call, e.g., `GET /api/stacks` with `Authorization: Basic <base64(":<T>")>` (or any `id--<T>` combo) and receive the full list of all stacks (`Stack.all`), because `ApiClient#stack_id` is `nil` for this token. [8](#0-7) 
4. The same token can be used against `/api/stacks/:owner/:repo/:env/tasks` and other `read:stack`-gated endpoints for repositories unrelated to stack A.
