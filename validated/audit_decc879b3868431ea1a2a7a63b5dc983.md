### Title
Unbounded ZIP extraction allows attacker-controlled Actions artifacts to trigger a decompression (zip-bomb) disk-exhaustion DoS during `gh run download` - (File: pkg/cmd/run/download/http.go)

### Summary
`downloadArtifact` streams an artifact ZIP response fully to a temp file and hands it to `zip.NewReader` with no cap on total size, and `ghzip.ExtractZip` then writes every entry to disk via a raw `io.Copy` with no per-file or cumulative output-size accounting. An attacker who can get a victim to run `gh run download` against an Actions run containing an attacker-crafted, highly compressible artifact can force unbounded disk writes on the victim's machine.

### Finding Description
The full chain is: `runDownload` (pkg/cmd/run/download/download.go) lists artifacts via the GitHub Actions API and calls `opts.Platform.Download(...)`, which is `apiPlatform.Download` → `downloadArtifact` in [1](#0-0) . Inside `downloadArtifact`, the response body is copied to a temp file with no size limit [2](#0-1) , then parsed as a ZIP and handed to `ghzip.ExtractZip` [3](#0-2) . `ExtractZip`/`extractZipFile` in internal/zip/zip.go only guards against path traversal (`destDir.Join`) but performs an unguarded `io.Copy(df, f)` for every entry, with no check on the decompressed size of any individual file or the sum of all files [4](#0-3) .

Unlike other parts of the codebase that do enforce such caps (e.g., `pkg/cmd/skills/preview` enforces a `maxBytes` cap on fetched blob content, seen in its tests asserting "size limit reached"), no analogous protection exists anywhere in the artifact-download/extraction path. This is confirmed by searching for `MaxBytes`/`LimitReader`/size-limit patterns in the repo, which only turn up in `pkg/cmd/attestation` and `pkg/cmd/skills/preview`, not in `pkg/cmd/run/download` or `internal/zip`.

Attacker input reaches this path because a GitHub Actions artifact's *contents* are attacker-controlled: any unprivileged user who can trigger a workflow run in their own repository/fork (a routine, unprivileged action) can `actions/upload-artifact` a file consisting of a large, highly repetitive/compressible pattern (e.g., a multi-gigabyte run of zeros). GitHub packages artifacts into a ZIP for download; such content compresses extremely well (ratios well over 100:1 with standard DEFLATE), so the artifact's stored/compressed size can be modest while its decompressed size is very large. When a victim runs the ordinary command `gh run download <run-id>` against that run (e.g., to inspect CI output from a PR or shared workflow), the CLI will decompress the full attacker-chosen size to disk with no limit.

### Impact Explanation
This is a local resource-exhaustion / disk-space denial-of-service triggered by ordinary use of `gh run download` against an attacker-controlled or attacker-influenced workflow run's artifact. It does not achieve code execution, credential theft, or path traversal (that is separately guarded by `safepaths`), but it can fill the victim's disk during a routine artifact download, which can degrade or crash the local system/CI runner. This corresponds to a resource-exhaustion/DoS class of impact, generally a lower-severity finding relative to code execution or credential leakage classes.

### Likelihood Explanation
Preconditions are minimal and fully within reach of an unprivileged attacker: publish a repo/fork, add a workflow that uploads a large, highly compressible artifact, and get a victim to run `gh run download` against that run (a common workflow-review action, e.g., reviewing a PR's CI artifacts). No token leakage, MITM, or special privilege is required. The attack is fully repeatable and deterministic given the artifact content.

### Recommendation
- Enforce a hard cap on the total downloaded artifact body size in `downloadArtifact` (e.g., wrap `resp.Body` in `io.LimitReader` before the `io.Copy` into the temp file, comparable to the artifact's `Size` field already returned by the Actions API in `shared.Artifact.Size`, plus a sane maximum).
- Enforce a cumulative and per-file decompressed-size limit inside `ghzip.ExtractZip`/`extractZipFile` (track bytes written across all entries, using `io.CopyN` or a limited writer, and abort extraction once a threshold is exceeded), mirroring the `maxBytes` pattern already used in `pkg/cmd/skills/preview`.
- Optionally, use `zip.File.UncompressedSize64` metadata to reject archives whose declared total decompressed size exceeds an acceptable bound before starting extraction.

### Proof of Concept
```go
// pkg/cmd/run/download/http_test.go (new test)
func Test_Download_ZipBomb(t *testing.T) {
    tmpDir := t.TempDir()
    destDir, err := safepaths.ParseAbsolute(filepath.Join(tmpDir, "artifact"))
    require.NoError(t, err)

    // Build a crafted zip in-memory: one entry of highly compressible content
    // (e.g. 2 GiB of zero bytes), which DEFLATE compresses to a few hundred KB.
    var buf bytes.Buffer
    zw := zip.NewWriter(&buf)
    fw, _ := zw.CreateHeader(&zip.FileHeader{Name: "bomb.bin", Method: zip.Deflate})
    zr := io.LimitReader(zeroReader{}, 2<<30) // 2 GiB of zero bytes
    io.Copy(fw, zr)
    zw.Close()

    reg := &httpmock.Registry{}
    defer reg.Verify(t)
    reg.Register(
        httpmock.REST("GET", "repos/OWNER/REPO/actions/artifacts/1/zip"),
        httpmock.BytesResponse(buf.Bytes())) // small compressed body

    api := &apiPlatform{client: &http.Client{Transport: reg}}
    err = api.Download(safeurl.NewImmutableSafeURL("https://api.github.com/repos/OWNER/REPO/actions/artifacts/1/zip"), destDir)
    require.NoError(t, err) // currently succeeds, writing ~2 GiB to disk

    info, _ := os.Stat(filepath.Join(destDir.String(), "bomb.bin"))
    // Demonstrates unattenuated growth: no cap stopped extraction before ~2 GiB was written.
    require.Greater(t, info.Size(), int64(1<<30))
}
```
Expected assertion after a fix: extraction should abort with an error (e.g., "artifact exceeds maximum allowed size") well before reaching gigabyte-scale output, rather than succeeding silently as it does today.

func extractZipFile(zf *zip.File, dest safepaths.Absolute) (extractErr error) {
	zm := zf.Mode()
	if zm.IsDir() {
		extractErr = os.MkdirAll(dest.String(), dirMode)
		return
	}

	var f io.ReadCloser
	f, extractErr = zf.Open()
	if extractErr != nil {
		return
	}
	defer f.Close()

	if extractErr = os.MkdirAll(filepath.Dir(dest.String()), dirMode); extractErr != nil {
		return
	}

	var df *os.File
	if df, extractErr = os.OpenFile(dest.String(), os.O_WRONLY|os.O_CREATE|os.O_EXCL, getPerm(zm)); extractErr != nil {
		return
	}

	defer func() {
		if err := df.Close(); extractErr == nil && err != nil {
			extractErr = err
		}
	}()

	_, extractErr = io.Copy(df, f)
	return
