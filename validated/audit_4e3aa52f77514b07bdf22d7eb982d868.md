### Title
Webhook signature verification org is decoupled from the payload's target repository, allowing a no-secret-org payload to mutate a victim `PullRequest`/`ReviewStack` via `EditedHandler` - ([File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to verify against using `repository.owner.login` from the raw JSON body, while `EditedHandler` resolves the record to mutate using the independent `repository.full_name` field from the same body. Because nothing ties these two fields together, a payload whose `repository.owner.login` names an onboarded org with no `webhook_secret` configured passes verification trivially and can carry an arbitrary `repository.full_name` pointing at a victim repository, causing `EditedHandler` to update that victim's `PullRequest#github_pull_request` (and thus the linked `ReviewStack`'s tracked PR/title/branch data).

### Finding Description
The broken binding, stated as an equality that should hold but doesn't:
`params.dig('repository','owner','login')` (used in `WebhooksController#verify_signature`, [1](#0-0) ) MUST equal the owner segment of `params.repository.full_name` (used in `EditedHandler#repository`, [2](#0-1) ) for the write to be authorized for the org whose secret verified the request. Nothing in the code enforces this.

Path:
1. `WebhooksController#create` parses the raw JSON body and dispatches it to handlers for the event type, with no per-handler re-verification: [3](#0-2) .
2. `verify_signature` computes `repository_owner` strictly from `params.dig('repository','owner','login')` (or `organization.login`) and fetches `Shipit.github(organization: repository_owner)`, then calls `verify_webhook_signature`: [4](#0-3) .
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that specific org's `webhook_secret` is blank: [5](#0-4) .
4. `EditedHandler#process` then looks up the target `PullRequest` using `params.number` and a repository resolved purely from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`: [6](#0-5) . This field is completely independent from the `repository.owner.login` value used in step 2.
5. If found, it calls `pull_request.update(github_pull_request: params.pull_request)`, unconditionally overwriting the cached PR payload (title, `head.ref`, etc.) on whichever repository/stack `full_name` names: [7](#0-6) .

Exploit flow: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `{"action":"edited","number":<victim PR number>,"repository":{"owner":{"login":"attacker-org-with-no-secret"},"full_name":"victim-org/victim-repo"},"pull_request":{...attacker-chosen title/head.ref...},"sender":{"login":"attacker"}}`. If `attacker-org-with-no-secret` is an org known to Shipit's configuration but lacking a configured `webhook_secret`, `verify_signature` passes with no signature required, yet the handler mutates the victim's `PullRequest`/`ReviewStack` record. Existing guards (`drop_unhandled_event`, `ExplicitParameters` schema, model validations) check only structural shape of the payload, not the org/full_name consistency, and thus do not prevent this divergence.

### Impact Explanation
An attacker who can reach the webhook endpoint with no Shipit credentials can overwrite the cached `github_pull_request` (title, `head.ref`/branch tracking, additions/deletions, assignees, labels) on a victim's existing `PullRequest`/`ReviewStack`, for any repository already onboarded to the Shipit instance, as long as one onboarded org lacks a `webhook_secret`. This is a cross-tenant write - a payload verified under one org's identity mutates another org's stack state - matching the "payload for one repository mutating another's stack" pattern. Repeated arbitrarily against any PR number/repository combination present in the DB.

### Likelihood Explanation
Exploitability strictly requires at least one GitHub organization configured in Shipit (`Shipit.github_teams`/GitHub App config) with a missing or blank `webhook_secret` -- this is the "no-secret" precondition baked into `GitHubApp#verify_webhook_signature`'s `return true unless webhook_secret` fallback. Given that precondition, the attack costs a single unauthenticated HTTP POST with a crafted JSON body; no GitHub interaction, tokens, or session is needed. Without that precondition (i.e., all onboarded orgs have a `webhook_secret` set), forging a valid HMAC signature for the victim org is infeasible for an unprivileged attacker, and the attack does not work. This makes the vulnerability real but conditional on a specific operator misconfiguration.

### Recommendation
Bind signature verification to the same repository identity that handlers act on: derive the org used for `Shipit.github(organization: ...)` from `repository.full_name`'s owner segment (or otherwise verify `repository.full_name`'s owner matches `repository.owner.login`) before dispatch, and remove/harden the `return true unless webhook_secret` fallback in `GitHubApp#verify_webhook_signature` so an org without a configured secret rejects webhooks rather than accepting them unauthenticated.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure two orgs in test secrets: `victim-org` with a real `webhook_secret`, `attacker-org` with `webhook_secret` blank/unset.
2. Create `victim-org/victim-repo` `Repository`, a `Stack`, a `ReviewStack`, and a `PullRequest` (number `42`) with known `github_pull_request` containing `title: "Original"`, `head: {ref: "main"}`.
3. POST to `/webhooks` with `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or an arbitrary bogus one), and body:
   `{"action":"edited","number":42,"pull_request":{...,"title":"Hacked","head":{"sha":"...","ref":"attacker-branch"},...},"repository":{"owner":{"login":"attacker-org"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker"}}`.
4. Assert response is `200 OK` (not `422`), proving `verify_signature` passed via the no-secret org path.
5. Reload the `PullRequest` and assert `github_pull_request["title"] == "Hacked"` and `github_pull_request["head"]["ref"] == "attacker-branch"`, i.e., the equality `repository_owner (attacker-org) != full_name owner (victim-org)` yet the victim record changed - demonstrating the binding violation on both sides.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
