## Title
Asset definer can permanently freeze all existing holders' funds of a `spender_attested` asset by replacing the attestor list - ([File: validation.js])

## Summary
For assets created with `spender_attested: true`, ocore requires that at least one author of every payment referencing that asset currently be "attested" by an address contained in the *most recent* attestor list published for the asset. The definer of the asset can unilaterally publish a new `asset_attestors` message that fully replaces the trusted attestor set. Because attestation-validity is always evaluated against only the latest attestor list (`storage.readAsset` → `addAttestorsIfNecessary`), any coin holder who was validly attested under the old (now-superseded) attestor list, but who is not re-attested by the new attestors, becomes permanently unable to spend their existing balance of that asset. This mirrors the reported UXD bug where a privileged party could unilaterally invalidate an existing registration and trap already-held assets, with no recourse for the affected holders.

## Finding Description
When an asset is defined with `spender_attested: true`, `validatePayment` enforces that every payment message referencing the asset must have at least one author currently attested: [1](#0-0) 

The set of "currently attested" authors is computed by `storage.filterAttestedAddresses`/`loadAssetWithListOfAttestedAuthors`, which restricts valid attestor addresses to those in the **single latest** `asset_attestors` list for that asset (ordered by level/rowid, `LIMIT 1`): [2](#0-1) [3](#0-2) 

The attestor list can be replaced at any time via an `asset_attestors` message, which is validated in `validateAttestorListUpdate`. The only requirement to change the list is that the message author equals `objAsset.definer_address` — no check is done regarding whether replacing the attestor set will orphan already-attested balances: [4](#0-3) [5](#0-4) 

Because only the *latest* attestor list is ever consulted (never a union of historical lists), publishing a new list that omits the attestor(s) who attested the current coin holders instantly and permanently strips those holders' ability to satisfy the "must be attested" condition for any future spend of their existing balance — exactly analogous to `unregisterDepository` in the referenced report severing access to already-deposited collateral. In both cases, a single privileged, unilateral state change (unregister a depository vs. swap the attestor list) leaves previously-valid asset holdings permanently stranded, with the base protocol offering no built-in migration or grandfathering path for holders attested under the old configuration.

## Impact Explanation
Any holder of a `spender_attested` asset who is attested only by an attestor removed from the list loses the ability to move, exchange, or redeem their existing balance forever (until/unless a new attestation happens to be issued to them by a currently-trusted attestor, which is out of their control). This is a concrete freezing of user funds caused entirely by an asset-issuer-controlled state transition, matching the Medium-severity impact pattern of the reference report (assets become permanently inaccessible due to unilateral deregistration).

## Likelihood Explanation
This requires only a single `asset_attestors` message from the asset's `definer_address` — an action explicitly reachable by the asset issuer (an in-scope actor per the rules). No cooperation from other parties, no race condition, and no unusual preconditions are needed; simply publishing a new attestor list that drops previously-relied-upon attestors is sufficient to freeze the corresponding balances.

## Recommendation
- Consider validating attestation against the historical list(s) that were in effect when the holder's balance was attested/received, not only the single latest list, or
- Require that attestor-list updates only add attestors (never fully replace/remove without a migration window), or
- Emit a governance/warning mechanism and grace period before an attestor removal becomes effective, allowing existing holders time to obtain new attestations.

## Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true` and initial `attestors: [X]`.
2. Attestor `X` attests holder `H`'s address; `H` receives/holds a balance of `A` and can freely spend it because `H` is in `arrAttestedAddresses` (per `filterAttestedAddresses`, using the current single attestor list `[X]`).
3. Definer `D` publishes an `asset_attestors` message for asset `A` with a new list `attestors: [Y]` (dropping `X`). This passes `validateAttestorListUpdate` because the only check is `objUnit.authors[0].address === objAsset.definer_address` and `checkAttestorList` format validation — no continuity/holder-impact check is performed.
4. `storage.readAsset` now returns `arrAttestorAddresses = [Y]` as "the latest list" for asset `A` (query is `ORDER BY level DESC LIMIT 1`).
5. `H` tries to spend the existing balance of `A`. `validatePayment` calls `loadAssetWithListOfAttestedAuthors`, which calls `filterAttestedAddresses` restricted to `attestor_address IN [Y]`; `H`'s old attestation by `X` no longer counts, so `arrAttestedAddresses` excludes `H`, and the payment is rejected with `"none of the authors is attested"`.
6. `H`'s existing balance of asset `A` is now permanently unspendable unless `Y` happens to attest `H` again — an event outside `H`'s control and possibly never occurring.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}
