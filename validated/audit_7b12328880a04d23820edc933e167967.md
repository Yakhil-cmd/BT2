## Title
Cross-organization webhook signature confusion allows one org's webhook_secret to authorize writes to another org's Repository/ReviewStack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` resolves the GitHub App/webhook_secret used to verify the HMAC signature via `repository_owner`, which reads `params.dig('repository', 'owner', 'login')`. `Handler#repository_name` (used by every `pull_request` handler to load the `Repository`/`ReviewStack` to mutate) reads a *different* field of the same untrusted body, `payload.dig('repository', 'full_name')`. Nothing enforces that these two fields refer to the same repository, so a body signed with org A's secret can direct the mutation at org B's repository.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`organization_that_verified(repository_owner) == organization_that_owns(repository_name.split('/').first)`

Path:
- `WebhooksController#verify_signature` [1](#0-0)  calls `Shipit.github(organization: repository_owner)` and verifies the raw POST body against that organization's `webhook_secret`.
- `repository_owner` reads `params.dig('repository', 'owner', 'login')` [2](#0-1) .
- On success, `create` re-parses the raw body and dispatches it unchanged to handlers [3](#0-2) .
- `Handler#repository_name` reads `payload.dig('repository', 'full_name')` [4](#0-3)  - a sibling key of `repository.owner.login`, not derived from it.
- `OpenedHandler#repository` calls `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) , and `Repository.from_github_repo_name` splits `full_name` on `/` to look up by `owner`/`name` columns directly, independent of `repository.owner.login` [6](#0-5) .
- `ReviewStackAdapter#find_or_create!`/`unarchive!` then create/mutate a `Stack`/`ReviewStack` scoped to that looked-up `Repository` [7](#0-6) .

There is no code anywhere in this chain that cross-checks `repository.owner.login` against `repository.full_name`'s owner segment. `verify_webhook_signature` itself only checks the HMAC over the raw bytes against whichever organization's secret was selected by the caller [8](#0-7) ; it has no notion of "which organization this body is about."

Exploit: attacker owns org A, for which Shipit has a configured `webhook_secret` (per the stated precondition). Attacker POSTs to `/webhooks` with `X-Github-Event: pull_request`, a body with `repository.owner.login = "org-a"`, `repository.full_name = "org-b/repo"`, `action = "opened"`, valid `pull_request`/`sender` fields, and an `X-Hub-Signature` computed with org A's `webhook_secret`. `verify_signature` resolves org A via `repository_owner`, verifies successfully. `OpenedHandler` then loads `Repository` for `org-b/repo` and, if `review_stacks_enabled` and provisioning behavior permit, creates a `ReviewStack`/`Stack` under org B's `Repository`, and enqueues provisioning for it.

Existing guards do not prevent this: `drop_unhandled_event` only checks the event type is handled, not payload consistency; `ExplicitParameters` schema in `OpenedHandler#params` only validates that `repository.full_name` is present/typed as a `String`, not that it matches `repository.owner.login`; there is no `force_github_authentication`/`User#authorized?`/`require_permission!` on this unauthenticated webhook endpoint (it is intentionally unauthenticated, relying solely on signature verification for provenance).

### Impact Explanation
An attacker who legitimately controls only org A's webhook configuration can cause writes (creation/unarchival of `ReviewStack` and its provisioning queue entry) against org B's `Repository`, entirely determined by attacker-chosen JSON fields, with no capability over org B required. This is a cross-repository/cross-tenant write triggered by a signature that authenticates a different organization than the one being mutated - matching the "Critical: a payload for one repository mutating another's stack" category. Repeatable for any `full_name` of any repository configured in the target Shipit instance, as long as review stacks are enabled/permitted by provisioning behavior on that repository, and the write is not confined to org A's own repositories at all.

### Likelihood Explanation
Requires: (1) Shipit hosting both org A's and org B's repositories, (2) attacker has a working `webhook_secret` for org A (per given precondition - they control a GitHub App/webhook config for org A), (3) target repository (org B's) has `review_stacks_enabled` and a `provisioning_behavior` that the crafted PR payload satisfies (e.g., `allow_all`, or label rules the attacker also controls since it's their own payload). Attacker cost is a single crafted HTTP POST with a valid HMAC computed over an arbitrary chosen body - fully within their control since they choose both the body and, using org A's secret, the signature. No GitHub-side action or org B credentials required. This is straightforwardly repeatable against any repository name the attacker can guess/enumerate.

### Recommendation
Bind signature verification to the same repository identity used by handlers: derive the verifying organization from `repository.full_name`'s owner segment (or verify that `repository.owner.login` matches the owner parsed from `repository.full_name`) before dispatching to handlers, e.g., reject the request in `verify_signature`/`drop_unhandled_event` if `params.dig('repository','full_name')&.split('/')&.first != repository_owner`. Alternatively, have `Handler#repository_name`/`#stacks` use `repository_owner`-derived owner rather than `full_name`'s owner segment, so a mismatch cannot occur.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
```ruby
test "a webhook signed for org-a can mutate a repository owned by org-b" do
  repo_b = shipit_repositories(:cyclimse) # or create with owner: 'org-b', name: 'repo'
  # ensure repo_b.owner == 'org-b', review_stacks_enabled true, provisioning_behavior_allow_all

  payload = {
    action: "opened",
    number: 42,
    pull_request: {
      id: 1, number: 42, url: "https://api.github.com/...", title: "t",
      state: "open", additions: 1, deletions: 0,
      head: { sha: "abc123", ref: "feature" },
      user: { login: "attacker" },
      assignees: [], labels: []
    },
    repository: { owner: { login: "org-a" }, full_name: "org-b/repo" },
    sender: { login: "attacker" }
  }.to_json

  github_app_a = stub(verify_webhook_signature: true)
  Shipit.stubs(:github).with(organization: "org-a").returns(github_app_a)

  assert_difference -> { Shipit::ReviewStack.where(environment: "pr42").joins(:repository).where(shipit_repositories: { owner: "org-b" }).count }, 1 do
    post shipit.webhooks_path, params: payload, headers: {
      "X-Github-Event" => "pull_request",
      "X-Hub-Signature" => "sha1=anything", # bypassed via stub above
      "Content-Type" => "application/json"
    }
  end

  assert_response :ok
  # Assert the two sides of the binding diverged:
  assert_equal "org-a", JSON.parse(payload).dig("repository", "owner", "login")
  assert_equal "org-b", JSON.parse(payload).dig("repository", "full_name").split("/").first
end
```
Assertions: `repository_owner` (verifying org) == `"org-a"`; owner segment of `repository_name` (mutated org) == `"org-b"`; these differ, yet a `ReviewStack` row is created under org B's `Repository` despite org A's secret verifying the request - confirming the binding is broken.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
