### Title
Auto-close-duplicates trusts any `user.type === "Bot"` account instead of verifying the specific dedup bot identity - ([File: scripts/auto-close-duplicates.ts])

### Summary
`autoCloseDuplicates` selects the "duplicate detection" comment purely by matching text (`"Found"` + `"possible duplicate"`) and checking `comment.user.type === "Bot"`, without validating `comment.user.login` against an allowlist of the legitimate dedup bot account. Any GitHub App or Actions-authored comment satisfying that text pattern is accepted as the trusted signal driving automatic issue closure.

### Finding Description
The filter that selects the trusted "duplicate detected" comment is: [1](#0-0) 

This checks `comment.user.type === "Bot"` only — a property GitHub sets for *any* bot/App-authored account, not exclusively the project's own dedup bot. There is no check of `comment.user.login` (or app ID) against an allowlist. The selected comment (`lastDupeComment`) then:
1. Has its body regex-parsed for a duplicate issue number via `extractDuplicateIssueNumber`, which just looks for `#(\d+)` or a GitHub issue URL — fully attacker-controlled text: [2](#0-1) 
2. Drives `closeIssueAsDuplicate`, which PATCHes the issue closed with `state_reason: 'duplicate'` and posts a closing comment using the extracted number: [3](#0-2) 

The only other guards are: no comments after the dupe comment, and no `-1` reaction from the issue author on that specific comment (`authorThumbsDown`) — [4](#0-3) . Neither guard validates *who* authored the dupe comment beyond `user.type`. None of these checks constrain identity to the legitimate dedup automation, so any bot-typed comment (e.g., from a different GitHub App installed on the repo, or an Actions bot triggered by unrelated workflow) containing the two substrings and a `#NNN` reference will be treated as authoritative.

### Impact Explanation
An attacker who can cause any bot-typed account to post a comment containing `"Found"` and `"possible duplicate"` plus an issue reference on a target issue can cause the automation to auto-close that issue as a duplicate of an attacker-chosen issue number after 3 days of inactivity — unauthorized automated state change (issue closure) driven by untrusted content, matching an "unauthorized automated action / trust-boundary bypass" class of impact.

### Likelihood Explanation
Exploitability depends entirely on the attacker's ability to get a `type: "Bot"` comment with attacker-influenced text onto the target issue (e.g., via another installed GitHub App that echoes user-supplied text, or a workflow bot triggered by an issue comment/label). This is a real precondition gap, not guaranteed in all deployments, but the code itself provides no defense-in-depth against it — it is a pure text+type match with no login/app allowlist, so once the precondition is met the exploit is deterministic and repeatable every 3-day cron run.

### Recommendation
Restrict the dedup-comment filter to a specific trusted identity, e.g. check `comment.user.login === 'github-actions[bot]'` (or the specific dedup bot's login/app id) in addition to `user.type === 'Bot'`, and/or use a stable marker (e.g., an HTML comment tag or structured footer) embedded only by the legitimate dedup bot rather than free-text substring matching.

### Proof of Concept
Integration test:
1. Mock `githubRequest` for `/issues` to return one open issue older than 3 days with no thumbsdown reaction.
2. Mock `/issues/{n}/comments` to return a single comment: `{ id: 1, body: "Found a possible duplicate: #999", created_at: <old date>, user: { type: "Bot", id: 12345 } }` where `user.login` (if tracked) is NOT the canonical dedup bot's login (e.g. `some-other-app[bot]`).
3. Run `autoCloseDuplicates()`.
4. Assert: expected behavior is that the issue is NOT closed (PATCH to `/issues/{n}` is never called) because the comment's login isn't allowlisted — current code fails this assertion, closing the issue as duplicate of `#999` solely because `user.type === "Bot"`.

function extractDuplicateIssueNumber(commentBody: string): number | null {
  // Try to match #123 format first
  let match = commentBody.match(/#(\d+)/);
  if (match) {
    return parseInt(match[1], 10);
  }
  
  // Try to match GitHub issue URL format: https://github.com/owner/repo/issues/123
  match = commentBody.match(/github\.com\/[^\/]+\/[^\/]+\/issues\/(\d+)/);
  if (match) {
    return parseInt(match[1], 10);
  }
  
  return null;
}

async function closeIssueAsDuplicate(
  owner: string,
  repo: string,
  issueNumber: number,
  duplicateOfNumber: number,
  token: string
): Promise<void> {
  await githubRequest(
    `/repos/${owner}/${repo}/issues/${issueNumber}`,
    token,
    'PATCH',
    {
      state: 'closed',
      state_reason: 'duplicate',
      labels: ['duplicate']
    }
  );

  await githubRequest(
    `/repos/${owner}/${repo}/issues/${issueNumber}/comments`,
    token,
    'POST',
    {
      body: `This issue has been automatically closed as a duplicate of #${duplicateOfNumber}.

If this is incorrect, please re-open this issue or create a new one.

🤖 Generated with [Claude Code](https://claude.ai/code)`
    }
  );

}
