`repository_owner` fallback to `organization.login` lets an attacker pick a lenient (no-`webhook_secret`) org verifier while `UnlabeledHandler` archives/unarchives a stack belonging to a different repository named via `repository.full_name` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/verifier by `repository_owner`, which falls back from `params.dig('repository','owner','login')` to `params.dig('organization','login')` when the nested owner is absent. `Shipit::Webhooks::Handlers::PullRequest::UnlabeledHandler`, however, resolves the acted-upon repository solely from `params.repository.full_name`. Because these two values are independently attacker-controlled fields in the same JSON body, an attacker can set `organization.login` to an org configured with no `webhook_secret` (which makes `GitHubApp#verify_webhook_signature` return `true` unconditionally) while pointing `repository.full_name` at a victim repository belonging to a different, secret-protected org, causing the forged `pull_request`/`unlabeled` event to be accepted and to archive/unarchive the victim's review stack.

### Finding Description
The broken binding: the code implicitly assumes `repository_owner == owner(params.repository.full_name)`. In fact:
- `repository_owner` (used to select the verifying `GitHubApp`) = `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) 
- The repository actually mutated by `UnlabeledHandler` = `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [2](#0-1) 

These are read from different JSON paths (`repository.owner.login` vs `organization.login` vs `repository.full_name`), so an attacker who supplies `repository.full_name` (required by the handler's `ExplicitParameters` schema) but omits the nested `repository.owner.login` key forces `repository_owner` to fall back to whatever `organization.login` they supply.

`verify_signature` then does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
``` [3](#0-2) 

and `GitHubApp#verify_webhook_signature` is:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 

So if the org selected via `organization.login` has no `webhook_secret` configured, **any** signature (or none) is accepted for that request — unconditionally, per `Shipit.github(organization:)`'s per-org `GitHubApp` construction from `github_app_config(organization)` [5](#0-4) .

Exploit flow:
1. Attacker identifies (or is themselves the owner/maintainer of) an org `lenient-org` configured in `Shipit.secrets.github` without a `webhook_secret` — a legitimate, low-cost misconfiguration case that the question specifies as given ("org configured without webhook_secret").
2. Attacker crafts a `pull_request` webhook body:
   - `action: "unlabeled"`
   - `organization: { login: "lenient-org" }`
   - `repository: { full_name: "victim-org/victim-repo" }` (no `repository.owner.login` key)
   - `pull_request: { state: "open", labels: [...], head: {...}, user: {...}, ... }`
   - `sender: { login: "attacker" }`
3. POST to `/webhooks` with header `X-Github-Event: pull_request` and any/garbage `X-Hub-Signature`.
4. `repository_owner` resolves to `"lenient-org"` → `Shipit.github(organization: "lenient-org")` → `verify_webhook_signature` returns `true` because `lenient-org` has no secret.
5. `drop_unhandled_event`/`check_if_ping` pass, `Shipit::Webhooks.for_event('pull_request')` dispatches to `UnlabeledHandler`, which resolves `repository` from `params.repository.full_name = "victim-org/victim-repo"`, independent of the org used for verification.
6. If that repository has `review_stacks_enabled` and a matching open review-stack PR number/label state, `handle` calls `stack.archive!` or `stack.unarchive!` on the victim's stack [6](#0-5) .

Existing guards do not close this gap:
- `verify_signature`'s only failure mode is `GithubOrganizationUnknown` (when the chosen org doesn't exist in config) [7](#0-6)  — this does not check that the verifying org matches the acted-upon repository's actual owner.
- The `ExplicitParameters` schema on `UnlabeledHandler` only requires `repository.full_name` to be present as a string; it does not require or cross-check `repository.owner.login` [8](#0-7) .
- `Repository.from_github_repo_name` performs no ownership/org-verification check, just a DB lookup by owner+name string [9](#0-8) .

### Impact Explanation
An unauthenticated attacker can archive or unarchive any repository's review-stack (a `ReviewStack`/`Stack` record) as long as: (a) at least one org in the Shipit deployment is configured without a `webhook_secret` (used purely as the signature-bypass vehicle via `organization.login`), and (b) the target repository has review stacks enabled with an open PR matching number/labels. This is a cross-tenant authorization bypass: a payload naming one repository (via `repository.full_name`) mutates that repository's stack state despite the webhook being "authenticated" (trivially, due to no secret) against an unrelated organization. This matches the Critical criterion "a payload for one repository mutating another's stack ... an unauthorized deploy/rollback" — archiving a review stack terminates/deprovisions the environment; unarchiving re-provisions it, both without the victim's or GitHub's consent.

### Likelihood Explanation
Preconditions: at least one org configured in `Shipit.secrets.github` without `webhook_secret` (explicitly given by the question as the target scenario), and a target repository with `review_stacks_enabled` plus a known/guessable open PR number and provisioning-label state. No Shipit session, API token, or GitHub secret is required — the attacker only needs to send a raw HTTP POST with an `X-Github-Event: pull_request` header and a crafted JSON body. This is fully repeatable against any repository whose `owner/name` string the attacker can enumerate, and costs nothing beyond one HTTP request.

### Recommendation
Do not let `repository_owner` (verification key) diverge from the repository the handler actually acts upon. Concretely:
- In `Shipit::WebhooksController#repository_owner`, derive the verification org strictly from `params.dig('repository', 'full_name')`'s owner segment (or require `repository.owner.login` to be present whenever `repository.full_name` is present) rather than falling back to the top-level `organization.login` for events that carry a `repository` field.
- Alternatively, after verification, assert that `repository_owner` matches the owner segment of `params.repository.full_name` before dispatching to handlers, rejecting (422) on mismatch.
- Require `webhook_secret` to be configured for every org in production, and fail closed (reject, not accept) when it's missing, instead of `verify_webhook_signature` returning `true`.

      user: { login: "attacker" },
      assignees: [],
      labels: [] # label removed -> triggers archive? if provisioning_behavior_allow_with_label

    organization: { login: "lenient-org" }, # org with no webhook_secret configured
    sender: { login: "attacker" }
  }.to_json

  @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # garbage signature

Binding checked before/after:
- Before: `repository_owner` (verifier selector) = `"lenient-org"`; `owner("victim-org/victim-repo")` = `"victim-org"`. These differ, yet `verify_signature` passes because `lenient-org` has no `webhook_secret`.
- After: `stack.archived?` flips from `false` to `true` for `victim-org/victim-repo`'s review stack, proving a request "verified" for `lenient-org` mutated a different org's repository state — the invariant "a `pull_request` event only affects the repository/stack whose secret authenticated it" is violated.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)

  end
