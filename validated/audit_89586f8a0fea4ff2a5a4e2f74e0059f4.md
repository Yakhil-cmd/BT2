### Title
Single-Step Ownership Transfer in Bridge Contracts Permanently Bricks Operator Management and Asset Controls — (`contracts/service_chain/bridge/BridgeOperator.sol`, `BridgeTokens.sol`, `BridgeCounterPart.sol`)

---

### Summary

All service-chain bridge contracts inherit from OpenZeppelin v2's single-step `Ownable`, which immediately replaces `_owner` on `transferOwnership()` with no confirmation. If the owner accidentally provides a wrong address, every `onlyOwner`-gated function — including operator registration/deregistration, token locking, and bridge halting — becomes permanently inaccessible. Because operators execute live KLAY and ERC20/ERC721 transfers, losing the ability to deregister a compromised operator directly enables unauthorized asset draining with no recovery path. No `Ownable2Step` equivalent exists anywhere in the repository.

---

### Finding Description

`BridgeOperator`, `BridgeTokens`, and `BridgeCounterPart` each directly inherit from `contracts/libs/openzeppelin-contracts-v2/contracts/ownership/Ownable.sol`. The `transferOwnership` function in that contract performs an immediate, unconditional owner replacement:

```solidity
// Ownable.sol line 63-65
function transferOwnership(address newOwner) public onlyOwner {
    _transferOwnership(newOwner);
}

// line 70-74
function _transferOwnership(address newOwner) internal {
    require(newOwner != address(0), "Ownable: new owner is the zero address");
    emit OwnershipTransferred(_owner, newOwner);
    _owner = newOwner;
}
```

The only guard is `newOwner != address(0)`. Any other wrong address (mistyped EOA, uninitialized contract, etc.) is accepted and immediately becomes the permanent owner.

`Bridge.sol` is the concrete deployed contract that inherits the full chain:

```
Bridge
 ├── BridgeCounterPart   (Ownable)
 ├── BridgeTransferKLAY
 │    └── BridgeTransfer
 │         └── BridgeOperator  (Ownable)
 ├── BridgeTransferERC20
 │    └── BridgeTokens    (Ownable)
 └── BridgeTransferERC721
```

Every `onlyOwner` function across this hierarchy becomes permanently inaccessible after a bad transfer:

| Contract | Bricked function | Asset/state consequence |
|---|---|---|
| `BridgeOperator` | `registerOperator`, `deregisterOperator`, `setOperatorThreshold` | Cannot rotate or remove operators |
| `BridgeTokens` | `registerToken`, `deregisterToken`, `lockToken`, `unlockToken` | Cannot halt token transfers |
| `BridgeCounterPart` | `setCounterPartBridge` | Counterpart address permanently frozen |
| `BridgeTransfer` | `setRunningStatus`, `start`, `setFeeReceiver` | Bridge cannot be stopped |
| `BridgeTransferKLAY` | `lockKLAY`, `unlockKLAY` | KLAY transfers cannot be halted |

---

### Impact Explanation

The critical asset-loss path is through operator management. Operators call `handleKLAYTransfer` and `handleERC20Transfer` to release funds from the bridge to recipients. If an operator key is compromised after ownership is bricked:

- `deregisterOperator` (line 159–174, `BridgeOperator.sol`) is permanently inaccessible — the compromised operator cannot be removed.
- `setRunningStatus(false)` (line 51–57, `BridgeTransfer.sol`) is permanently inaccessible — the bridge cannot be halted.
- `lockToken` / `lockKLAY` are permanently inaccessible — individual asset flows cannot be frozen.

The compromised operator can continue calling `handleKLAYTransfer` (line 62–100, `BridgeTransferKLAY.sol`) and `handleERC20Transfer` (line 32–73, `BridgeTransferERC20.sol`) to drain all KLAY and ERC20 tokens held by the bridge, with no on-chain mechanism to stop it.

---

### Likelihood Explanation

Low. It requires the current owner to make a typo or copy-paste error when calling `transferOwnership`. However, bridge ownership transfers are infrequent operational events where human error is plausible, and the zero-address guard provides no protection against any other wrong address.

---

### Recommendation

Replace the OZ v2 `Ownable` import in `BridgeOperator.sol`, `BridgeTokens.sol`, and `BridgeCounterPart.sol` with a two-step ownership pattern. Since the codebase uses Solidity 0.5.6, a custom `Ownable2Step` must be implemented (OZ's `Ownable2Step` requires ^0.8.0). The pattern requires:

1. `transferOwnership(address newOwner)` stores `newOwner` as `_pendingOwner` only.
2. A new `acceptOwnership()` function, callable only by `_pendingOwner`, finalizes the transfer.

This ensures a wrong address can never silently become owner, because only the holder of the correct private key can call `acceptOwnership`.

---

### Proof of Concept

1. Deploy `Bridge` with `modeMintBurn = false`. Deployer is `owner`.
2. Fund the bridge with 100 KLAY via `chargeWithoutEvent()`.
3. Register operator `opA` via `registerOperator(opA)`.
4. Owner calls `transferOwnership(wrongAddress)` — e.g., a mistyped address. This succeeds immediately; `_owner` is now `wrongAddress`.
5. `opA`'s key is later compromised. Owner attempts `deregisterOperator(opA)` — reverts with `"Ownable: caller is not the owner"`.
6. Attacker controlling `opA` calls `handleKLAYTransfer(txHash, from, attacker, 100 ether, nonce, blockNum, "")`.
7. `_voteValueTransfer` passes (threshold = 1, single operator), `closedValueTransferVotes[nonce]` is set, and `_to.call.value(100 ether)("")` sends all KLAY to the attacker.
8. Owner cannot call `setRunningStatus(false)` or `lockKLAY()` to stop further transfers.

All 100 KLAY is drained with no recovery path.

    function registerOperator(address _operator)
    external
    onlyOwner
    {
        require(operatorList.length < MAX_OPERATOR, "max operator limit");
        require(!operators[_operator], "exist operator");
        operators[_operator] = true;
        operatorList.push(_operator);
        emit OperatorRegistered(_operator);
    }

    // deregisterOperator deregisters the operator.
    //
    // Note that outstanding votes by the deregistered operator are not revoked.
    // This enables a subtle counterintuitive scenario.
    //
    // Suppose there are two operators A, B and C with threshold 2.
    // 1. Operator A votes on nonce N
    // 2. Owner deregisters A
    // 3. Operator B votes on nonce N, thereby executing the request N.
    // In this case the request was executed with A's vote after A is deregistered.
    //
    // The Owner shall recognize this issue and expect that operator deregistration
    // takes some time to be fully effective.
    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }

    // setOperatorThreshold sets the operator threshold.
    function setOperatorThreshold(VoteType _voteType, uint8 _threshold)
    external
    onlyOwner
    {
        require(_threshold > 0, "zero threshold");
        require(operatorList.length >= _threshold, "bigger than num of operators");
        operatorThresholds[uint8(_voteType)] = _threshold;
        emit OperatorThresholdChanged(_voteType, _threshold);
    }
