### Title
Stale delegate grants reactivate when a position NFT returns to its original owner - (File: contracts/controller/src/storage/account.rs)

### Summary
Controller delegate authorization is keyed only by the account ID and the granting owner's address, so an NFT transfer temporarily disables the grant without deleting it. [1](#0-0)  If ownership later returns to the granting address, the old delegate becomes authorized again and can invoke owner-only position operations such as `withdraw` or `borrow`. [2](#0-1) 

### Finding Description
The controller resolves account ownership dynamically from the position NFT rather than maintaining an ownership-transfer generation or cached previous owner. [3](#0-2)  `get_delegates` loads the single `ControllerKey::Delegates(account_id)` record and returns it whenever `grant.granted_by` equals the current NFT owner. [1](#0-0) 

An NFT transfer therefore hides the old owner's grant, but the record remains in persistent storage. It is deleted only if the interim owner calls `add_delegate` or `remove_delegate`; `remove_delegate` explicitly recognizes and deletes this stale-grant case. [4](#0-3)  If the interim owner performs neither operation and later transfers the NFT back to the original owner, `is_owner_or_delegate` once again accepts every delegate in the stale `DelegateGrant` because the `granted_by` field matches the restored owner. [2](#0-1) 

The result is an authorization resurrection analogous to deleting or changing an account without permanently removing its dependent membership: transfer appears to revoke the old owner's delegates, but the membership silently returns with the original owner.

### Impact Explanation
A stale active position manager can steal the account's withdrawable collateral after the NFT returns to the grantor. `process_withdraw` accepts that stale manager through `require_owner_or_delegate`, allows `to` to be an arbitrary external recipient, and treats a zero withdrawal amount as a request for the full position. [5](#0-4)  For an account with outstanding debt, the delegate can instead use `borrow` and direct the borrowed assets to itself up to the account's solvency limit, converting user collateral into attacker-controlled proceeds and leaving the owner with the debt. [6](#0-5) 

### Likelihood Explanation
The attack requires an account owner to have delegated to an active position manager, transfer the position NFT to another address, and receive the same NFT back without that interim owner having modified delegates. This can occur through a cancelled marketplace listing, escrow, custody transfer, temporary wallet migration, or sale that is later reversed. Because the stale grant persists automatically and requires no new signature from the returning owner, the prior delegate can act immediately after ownership returns.

### Recommendation
Treat every NFT ownership change as permanent revocation, including a change away from and back to the same address. For example, store the last observed owner or an ownership-generation value in account metadata, and when `storage::get_account` resolves a different NFT owner, delete `ControllerKey::Delegates(account_id)` and update the generation before evaluating authorization. Alternatively, add an ownership-transfer notification from the position NFT to the controller that clears delegate storage atomically.

### Proof of Concept
1. Governance activates `manager` as a position manager.
2. Alice creates and funds account `A` through `supply(caller=alice, account_id=0, ...)`.
3. Alice calls `add_delegate(caller=alice, account_id=A, delegate=manager)`.
4. Alice transfers position NFT `A` to an escrow or buyer `bob`; the stored grant remains but is inactive because `granted_by == alice` while the current owner is `bob`.
5. `bob` transfers NFT `A` back to Alice without calling `add_delegate` or `remove_delegate`.
6. `manager` calls:
   ```text
   withdraw(
       caller=manager,
       account_id=A,
       withdrawals=[(collateral_asset, 0)],
       to=Some(manager)
   )
   ```
   The zero amount withdraws Alice's entire collateral position to `manager`.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }

/// Accepts the owner or a registered, active manager delegated by that owner.
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Withdraws for an authorized owner/delegate and checks post-pool solvency.
/// Zero requests withdraw all; returns the pool's actual payouts per asset.
pub(crate) fn process_withdraw(
    env: &Env,
    caller: &Address,
    account_id: u64,
    withdrawals: &Vec<HubPayment>,
    to: Option<Address>,
) -> Vec<HubPayment> {
    validation::require_authorized_caller(env, caller);

    let mut account = storage::get_account(env, account_id);
    require_owner_or_delegate(env, account_id, caller, &account.owner);

    let recipient = to.unwrap_or_else(|| caller.clone());
    let mut cache = Context::new(env);
    require_external_recipient(env, &mut cache, &recipient);
    let aggregated = payments::aggregate_payments(env, withdrawals, payments::ZeroLeg::MeansAll);

    let paid = settle_withdraw(env, &mut account, &recipient, &aggregated, &mut cache);
    let _ = enforce_post_pool_solvency(env, &mut cache, &mut account);
