### Title
Webhook signature verification is bound to `repository.owner.login`, not to the `repository.full_name` the handlers actually act on - cross-organization/cross-repository forgery when a configured GitHub App has no `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects *which* GitHub App/secret to validate a webhook against using `repository_owner` (`params.dig('repository','owner','login')` or `params.dig('organization','login')`), then calls `GithubApp#verify_webhook_signature`. [1](#0-0) 
That method unconditionally returns `true` whenever the selected app has no `webhook_secret` configured: [2](#0-1) 
Once "verified", every event handler (`PushHandler`, `PullRequest::*Handler`) resolves the target `Repository`/`Stack` using an entirely different, unauthenticated field of the same JSON body: `payload.dig('repository', 'full_name')`. [3](#0-2) [4](#0-3) [5](#0-4) 
No code ever checks that `repository.full_name`'s owner segment matches `repository_owner` / the app whose secret was used for verification. The two fields are never cross-bound even though they live in the same attacker-controlled payload.

### Finding Description
The binding that should hold is: `organization whose secret authenticated the request == organization owning the repository the handler mutates`. In this engine that equality is never enforced.

`Shipit.github(organization:)` looks up a per-organization app config (multi-org deployments are an explicitly documented, supported schema): [6](#0-5) 
The engine's own example configs show `webhook_secret` shipped blank/commented out by default for both single-app and multi-org schemas: [7](#0-6) [8](#0-7) 
When an operator follows this documented pattern for one organization (e.g. leaves `webhook_secret` unset on org `OrgOne` while other tracked repositories belong to `OrgTwo` or any other org that *is* protected), `verify_webhook_signature` for `OrgOne` trivially returns `true` for any request body, regardless of its `X-Hub-Signature` header.

An unauthenticated, unprivileged network client can then POST directly to the public `/github/webhooks` endpoint with:
- `repository.owner.login` (or `organization.login`) = `OrgOne` (the org with no secret) — satisfies `verify_signature`.
- `repository.full_name` = `<any-other-tracked-org>/<victim-repo>` — the field the handler actually uses to resolve `Repository.from_github_repo_name` / stacks / review stacks.

Because `Handler#stacks`/`#repository_name` and every `PullRequest::*Handler#repository` key off `full_name` alone, with no re-check against the organization that "authenticated" the call, the forged event is processed against the victim repository as if it were a legitimate signed GitHub event.

### Impact Explanation
Depending on the event type, this allows cross-repository/cross-organization actions that should require a valid signed GitHub webhook for that specific organization:
- `push` → enqueues `GithubSyncJob` for arbitrary tracked stacks (`stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(...) }`). [9](#0-8) 
- `pull_request` closed/opened/labeled → archives, creates, or unarchives review stacks for a repository the caller never proved they control. [10](#0-9) 

This crosses the "cross-repository writes" / "unauthorized deploy/rollback" impact bar for any Shipit deployment configured with the documented multi-organization schema where at least one configured organization omits `webhook_secret` (the shipped example configs default to blank).

### Likelihood Explanation
Likelihood is conditioned on operator misconfiguration (an org left without `webhook_secret`), but this is exactly the state the engine's own shipped example files (`config/secrets.development.example.yml`, `test/dummy/config/secrets_double_github_app.yml`) leave commented/blank by default, and nothing in `Shipit::GitHubApp` or the setup docs enforces that `webhook_secret` be present. No credential, session, or repository write access is required by the attacker — only knowledge that some configured organization name lacks a secret (discoverable via the `422`/`GithubOrganizationUnknown` behavior contrast, since unknown org names 422 while known-but-secretless orgs return `200`/normal processing).

### Recommendation
- Make `verify_webhook_signature` fail closed when `webhook_secret` is blank instead of returning `true`.
- Independently of that, bind the handler's target lookup to the same organization used for verification: after determining `repository_owner`/`organization`, verify that `payload.dig('repository','full_name')`'s owner segment matches it before dispatching to `Shipit::Webhooks.for_event(event)`.

### Proof of Concept
1. Configure Shipit with the multi-org schema; leave `OrgOne.webhook_secret` blank (as in the shipped example) while `OrgTwo` (owner of the real target repo, e.g. `OrgTwo/victim-repo`) has a real secret configured and a stack for it exists in Shipit.
2. POST to `/github/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "OrgOne" }, "full_name": "OrgTwo/victim-repo" }
}
```
No valid `X-Hub-Signature` is required because `verify_webhook_signature` short-circuits to `true` for `OrgOne`.
3. `WebhooksController#create` dispatches to `PushHandler`, which resolves `Repository.from_github_repo_name("OrgTwo/victim-repo")` and enqueues `GithubSyncJob` for that stack — an action that should have required a signature validated against `OrgTwo`'s secret. [11](#0-10)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

**File:** lib/shipit.rb (L170-200)
```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
