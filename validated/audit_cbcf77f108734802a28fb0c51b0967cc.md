### Title
Accrued-debt value overflows `i128` before the borrow-index cap, permanently freezing a market's funds - (File: contracts/pool/src/interest.rs)

### Summary
The external report describes a heap-buffer-overflow in `libde265` that crashes the decoder — a memory-safety fault turned into a denial of service by crafted input. The analog in XOXNO Lending is an arithmetic-overflow fault turned into a permanent denial of service: when `borrowed * borrow_index` (a RAY-domain product) exceeds `i128::MAX`, every accrual panics with `MathOverflow`, and because every pool and controller verb accrues the market first, the market becomes permanently unspendable — no repay, withdraw, liquidate, or `clean_bad_debt` can ever succeed.

### Finding Description
Interest accrual runs inside `global_sync`, which chunks elapsed time into `MAX_COMPOUND_DELTA_MS` (one year) windows and calls `accrue_chunk` → `accrue_step` [1](#0-0) . Inside `accrue_step`, the new debt value is computed as `half_up(borrowed × borrow_index' / RAY)` and supplier rewards use `calculate_supplier_rewards(borrowed, new_index, old_index)` [2](#0-1) . The multiply-divide widens intermediates to `I256` only for the product; if the *result* does not fit `i128`, `to_i128` panics with `GenericError::MathOverflow` [3](#0-2) .

Crucially, the borrow-index ceiling (`MAX_BORROW_INDEX_RAY = 10^36`, i.e. 10^9× the initial index) does **not** bound the debt *value*: `borrowed` can be up to ~170 billion whole tokens (`i128::MAX / 10^(27-d)`), so `borrowed × index` overflows `i128` while the index is still far below its cap. The docs state this directly: "Value overflow can occur before the index ceiling and block repayment/withdrawal because those operations accrue first" [4](#0-3) . The harness test proves it end-to-end: after supplying 10^27 units and borrowing 98%, repeated `update_indexes` eventually fails with `MATH_OVERFLOW`, and thereafter `withdraw` and `repay` of even 1 unit fail identically [5](#0-4) .

Once the panic point is crossed, `global_sync` reverts on every entry (`Cache::load` → `interest::global_sync` precedes every mutation, per the documented flow [6](#0-5) ), so there is no path — repay, withdraw, liquidate, seize, recapitalize — that can touch the market. `update_borrow_index`'s cap cannot retroactively help because the overflow occurs inside the value computation, not the index write.

### Impact Explanation
Permanent freezing of funds: all supplier cash and borrower collateral value in the affected `(hub, token)` market becomes unrecoverable. Liquidations cannot run, so positions that later go underwater also cannot be resolved — compounding into potential protocol insolvency via unclosable bad debt. This is the accepted impact class "permanent freezing of funds."

### Likelihood Explanation
Medium. Reachable by a single unprivileged address through ordinary `controller.supply` + `controller.borrow` + `update_indexes` calls — no privilege, oracle manipulation, or off-chain help required. However, it demands (a) a market holding on the order of 10^26–10^27 base units of one token (~170 billion whole tokens at 18 decimals, proportionally less for lower-decimal assets, which the admitted-cap maximum permits), and (b) sustained high utilization at high borrow rates for years before the cliff is reached. The capital requirement is astronomical for most tokens but plausible for large-supply/low-unit-price assets, and the borrow itself can be flash-assisted since the attacker only needs to *hold* the debt long-term. The overflow is self-triggering: once state crosses the line, any subsequent caller's transaction finalizes the freeze.

### Recommendation
Bound the debt value, not just the index. Concretely:
- Cap `borrowed` (or `borrowed × borrow_index`) at a protocol constant well inside `i128` — e.g., reject `borrow`/`create_strategy`/`flash_position` when `borrowed` exceeds `i128::MAX / MAX_BORROW_INDEX_RAY`, so the product can never overflow for any reachable index.
- Alternatively, clamp `accrue_step` so that when `borrow_index` reaches `MAX_BORROW_INDEX_RAY`, value computations skip the multiply for already-capped indexes rather than computing `borrowed × index` unconditionally.
- Emit/flag an index-ceiling approach so operators can act before the irreversible cliff.

### Proof of Concept
A single unprivileged attacker:

1. `controller.supply(account_id, [(hub, T, ~10^27 base units)])` — admit the maximum the token-to-RAY bound allows (~170B whole tokens at 18 decimals).
2. From a collateralized account, `controller.borrow(account_id, [(hub, T, 0.98 × supplied)])` — pushed to high utilization so the borrow curve sits at its steep segment (`MAX_BORROW_RATE_RAY` up to 200% APR).
3. Wait (or repeatedly call `controller.update_indexes([hub_asset])` to checkpoint accrual). The index grows ~e^2 per year-chunk; within a few years `borrowed × borrow_index` crosses `i128::MAX`.
4. The next accrual — e.g., anyone's `update_indexes`, `repay`, `withdraw`, `liquidate`, or `clean_bad_debt` on that market — panics inside `accrue_step`'s `mul`/`to_i128` with `MathOverflow`, and does so on every subsequent call forever.

This is exactly what the harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates: `try_update_indexes_for(["BIG18"])` fails with `MATH_OVERFLOW` at `borrow_index < MAX_BORROW_INDEX_RAY`, and `try_withdraw`/`try_repay` of 1 unit fail identically — "The market is frozen: exits and repayments accrue first and hit the same panic" [7](#0-6) .

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

/// Computes `floor(x * y / d)`, rounding toward negative infinity for a negative quotient.
/// Panics with `GenericError::DivisionByZero` if `d == 0`, or with
/// `GenericError::MathOverflow` if the result does not fit in `i128`.
pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
