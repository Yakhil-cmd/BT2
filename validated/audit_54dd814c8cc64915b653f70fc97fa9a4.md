### Title
Market-scale `i128` overflow during accrual permanently freezes all positions - (File: contracts/pool/src/cache/scale.rs)

### Summary

A sufficiently large market can reach an `i128` overflow while converting scaled totals back to asset value during interest accrual, before `MAX_BORROW_INDEX_RAY` can cap index growth. Because every affected market operation accrues before mutating state, the overflow permanently blocks withdrawals, repayments, liquidations, and subsequent index updates. The public `update_indexes` path calls `pool_update_indexes_call`, while the pool routes that call into `ops::market::accrue`. [1](#0-0) [2](#0-1) 

### Finding Description

`Cache::calculate_utilization` derives current utilization by multiplying both scaled borrowed and scaled supplied balances by their live indexes through `scaled_to_original`. [3](#0-2)  Interest accrual processes elapsed time in bounded chunks and calls `accrue_step` for each chunk. [4](#0-3) [5](#0-4) 

The accounting domain therefore has two separate limits: the configured borrow-index ceiling and the much earlier `i128` limit for `scaled_balance * index`. A whale market can cross the latter first. The checked-in reproduction creates a one-billion-whole-token, 18-decimal market, borrows 98% of it, advances time until `update_indexes` fails with `MATH_OVERFLOW`, and verifies that the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [6](#0-5) 

The same test demonstrates that the overflow is not confined to the index-maintenance entrypoint: both `withdraw` and `repay` subsequently fail because they perform the same accrual first. [7](#0-6)  Once this state is reached, liquidations and other position mutations that accrue the market are exposed to the same trap, leaving suppliers and borrowers unable to settle their positions.

### Impact Explanation

This causes permanent freezing of user funds in the affected market: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot restore account health through the ordinary liquidation flow. [8](#0-7)  The failure also prevents `update_indexes` from reaching and persisting the intended borrow-index ceiling, so the protocol cannot recover merely by letting the index hit its configured cap. [9](#0-8) 

### Likelihood Explanation

Likelihood is constrained by the extreme liquidity and duration required: the reproduction uses one billion 18-decimal tokens, 98% utilization, a steep rate curve, and years of elapsed accrual. [10](#0-9)  An unprivileged borrower and supplier can create the utilization state through normal `supply` and `borrow` calls, and `update_indexes` only requires caller authorization rather than a privileged role. [1](#0-0)  Time and market size, rather than a privileged action, are the barrier.

### Recommendation

Make index saturation independent of the finite `i128` market-value calculation. In particular, clamp the borrow index to `MAX_BORROW_INDEX_RAY` before computing utilization from unscaled totals, or compute utilization with widened/saturating arithmetic that cannot trap after the index ceiling has been reached. Accrual should also detect the market-value domain boundary and freeze the indexes at their configured limits rather than leaving the market permanently unable to accrue.

The fix should preserve conservative liquidation accounting by using ceiling-rounded debt and floor-rounded supply where values remain representable, while explicitly treating values above the representable ceiling as saturated rather than reverting.

### Proof of Concept

The existing harness test is a direct proof of concept:

1. Create an 18-decimal `BIG18` market using the steep XLM curve and a separate collateral market.
2. Supply `1_000_000_000 * 10^18` raw `BIG18`.
3. Supply collateral and borrow 98% of the `BIG18` market through the normal controller entrypoints.
4. Advance ledger time in one-year increments while calling `update_indexes` for `BIG18`.
5. `update_indexes` eventually returns `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. Calls to withdraw one unit and repay one token then fail with the same `MATH_OVERFLOW`. [11](#0-10)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {

        env,

    cache.set_supply_index(step.supply_index);
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
