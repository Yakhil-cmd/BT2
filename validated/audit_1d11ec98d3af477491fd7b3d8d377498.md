I searched for the closest structural analog to the webhookd flaw — unauthenticated, attacker-controlled input (HTTP headers) being forwarded without an allowlist into a privileged execution context (shell variables) that a script trusts for identity/authorization. The closest surface candidates in this codebase are:

- `get_proxy_ip` in `substrate/client/rpc-servers/src/utils.rs`, which parses `Forwarded`/`X-Forwarded-For`/`X-Real-Ip` headers — but this is only used to exempt an IP from rate-limiting, is gated behind the explicit opt-in flag `--rpc-rate-limit-trust-proxy-headers` (`substrate/client/cli/src/params/rpc_params.rs:93-101`), and its trust posture is documented and default-off, unlike webhookd's default-allow-all forwarding.
- The PVF worker spawning code in `polkadot/node/core/pvf/src/worker_interface.rs:236-251` explicitly calls `command.env_clear()` before launching child worker processes, which is the opposite of the vulnerable pattern (it actively strips rather than blindly forwards attacker-influenced data into the child's environment).
- The offchain worker HTTP API (`substrate/client/offchain/src/api/http.rs`, `substrate/primitives/runtime/src/offchain/http.rs`) only concerns outgoing HTTP requests initiated by trusted offchain worker code — it isn't attacker-reachable via an unprivileged extrinsic and doesn't involve unfiltered forwarding of incoming request headers into a privileged execution context.

None of these constitute a real user-facing entry point where attacker-controlled headers/input are blindly forwarded, without an allowlist, into a privileged execution context that a downstream component trusts for authentication/identity — which is the core invariant violated in the webhookd advisory. There is no signed-extrinsic, contract-call, or XCM analog here since this bug class is specific to an HTTP-to-shell-env bridge that doesn't exist in the Polkadot SDK's runtime/consensus code paths.

/// Extracts the IP addr from the HTTP request.
///
/// It is extracted in the following order:
/// 1. `Forwarded` header.
/// 2. `X-Forwarded-For` header.
/// 3. `X-Real-Ip`.
pub(crate) fn get_proxy_ip<B>(req: &http::Request<B>) -> Option<IpAddr> {
	if let Some(ip) = req
		.headers()
		.get(&FORWARDED)
		.and_then(|v| v.to_str().ok())
		.and_then(|v| ForwardedHeaderValue::from_forwarded(v).ok())
		.and_then(|v| v.remotest_forwarded_for_ip())
	{
		return Some(ip);
	}

	if let Some(ip) = req
		.headers()
		.get(&X_FORWARDED_FOR)
		.and_then(|v| v.to_str().ok())
		.and_then(|v| ForwardedHeaderValue::from_x_forwarded_for(v).ok())
		.and_then(|v| v.remotest_forwarded_for_ip())
	{
		return Some(ip);
	}

	if let Some(ip) = req
		.headers()
		.get(&X_REAL_IP)
		.and_then(|v| v.to_str().ok())
		.and_then(|v| IpAddr::from_str(v).ok())
	{
		return Some(ip);
	}

	None
}
