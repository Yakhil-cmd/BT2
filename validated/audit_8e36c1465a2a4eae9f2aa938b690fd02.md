### Title
Webhook signature verification is keyed on `repository.owner.login`/`organization.login` but downstream handlers act on the independently-attacker-controlled `repository.full_name` field, allowing cross-organization event forgery - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GithubApp`/`webhook_secret` used to validate the `X-Hub-Signature` HMAC based on `repository_owner`, which is read from the JSON body itself (`params.dig('repository','owner','login')` or `params.dig('organization','login')`). Once verification succeeds, the raw, attacker-supplied `params` are handed unmodified to the event handlers, which independently resolve the *target* repository from a different field of the same body: `payload.dig('repository','full_name')`. Nothing binds these two fields together cryptographically or logically, so a signature that is valid for organization A's webhook secret can be attached to a payload whose `repository.full_name` points at organization B's repository.

### Finding Description
- `verify_signature` picks the app/secret via `Shipit.github(organization: repository_owner)` and checks `X-Hub-Signature` against that secret and the raw body. [1](#0-0) 
- `repository_owner` is taken straight from the JSON payload the attacker controls: `params.dig('repository', 'owner', 'login')` (fallback `params.dig('organization', 'login')`). [2](#0-1) 
- After verification, the same raw `params` (the full JSON body) are dispatched unchanged to every registered handler for the event type: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [3](#0-2) 
- Every handler resolves its target `Stack`/`Repository` from a *different* field of the same body — `payload.dig('repository', 'full_name')` — with no cross-check against `repository.owner.login`: [4](#0-3) 
- `Repository.from_github_repo_name` simply splits `owner/name` out of that string and looks up the record, again with no relationship to whatever value verified the signature: [5](#0-4) 
- Shipit explicitly supports one `webhook_secret`/GitHub App per GitHub organization on a single instance (multi-tenant deployments), each independently administered: [6](#0-5) 

The broken binding is: `verified_organization(repository.owner.login) == owner(repository.full_name)` is assumed but never enforced. An attacker who legitimately administers (or has compromised) the GitHub App/webhook secret for their **own** onboarded organization "attacker-org" can craft a raw webhook body where `repository.owner.login` (and/or `organization.login`) = `"attacker-org"` (so the signature computed with attacker-org's secret verifies), while `repository.full_name` = `"victim-org/victim-repo"`. `verify_signature` passes because it validated against attacker-org's own secret, and then `Handlers::PushHandler`, `StatusHandler`, `CheckSuiteHandler`, or the `PullRequest::*` handlers all act on `victim-org/victim-repo`.

### Impact Explanation
This lets an attacker who controls only their own organization's GitHub App inject forged events against a completely different, unrelated organization's stack that is hosted on the same shared Shipit instance:
- Forged `push` events feed `GithubSyncJob`, causing the victim stack to sync against an attacker-chosen `expected_head_sha`.
- Forged `status`/`check_suite` events (`StatusHandler`/`CheckSuiteHandler`) can fabricate green CI/check results on arbitrary commits of the victim repository, which Shipit uses to gate deploy readiness/merge status — enabling deploy-gating bypass on a repository the attacker has no access to.
- Forged `pull_request` events (`opened`, `closed`, `labeled`, etc.) can manipulate merge-status/review-stack state for PRs in the victim repository.

This is a cross-organization write against another tenant's stack state without holding any credential for that tenant, matching the "cross-repository writes" / "unauthorized deploy" impact class from an unprivileged (relative to the victim org) attacker.

### Likelihood Explanation
Requires the Shipit instance to be configured for multiple GitHub organizations (a documented, supported configuration) and requires the attacker to control the webhook secret for at least one onboarded organization (e.g., they administer their own team's GitHub App installation on the shared instance). Given that scenario, forging the raw HTTP request is trivial — no other authentication artifact is needed.

### Recommendation
After signature verification, re-derive the trusted organization from the same field used to select the secret (`repository_owner`), and require that the repository resolved by handlers (`repository.full_name`'s owner segment) matches that verified organization; reject the webhook otherwise. Concretely, pass the verified `repository_owner`/organization into `Handler.call`/`Repository.from_github_repo_name` lookups and assert equality before acting on the payload, rather than trusting `repository.full_name` in isolation.

### Proof of Concept
1. Attacker administers GitHub App for `attacker-org` on a multi-org Shipit deployment and knows `attacker-org`'s `webhook_secret`.
2. Attacker crafts a `push` event JSON body:
```json
{
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
  "after": "<attacker-chosen sha>"
}
```
3. Attacker computes `X-Hub-Signature: sha1=<hmac-sha1(attacker-org secret, raw_body)>` and POSTs to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` looks up `Shipit.github(organization: "attacker-org")` and successfully verifies the signature against that org's secret. [7](#0-6) 
5. `Handlers::PushHandler` (via `Handler#stacks`/`#repository_name`) resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and enqueues `GithubSyncJob` for the victim's stack, entirely outside attacker-org's authority. [4](#0-3)

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```
