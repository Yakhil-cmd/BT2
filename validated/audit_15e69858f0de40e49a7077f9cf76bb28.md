## Finding

### Title
Front-Running Oracle/VRF Randomness via Unstable Data-Feed Reads in AA Formula Evaluation - (File: `data_feeds.js`, `formula/evaluation.js`)

### Summary
The `data_feed[[...]]`/`in_data_feed[[...]]` oscript selectors, when evaluated inside Autonomous Agent (AA) trigger processing, are allowed to read data-feed values posted by **not-yet-stable** AA response units. This lets any user observe a random/oracle value the instant it is broadcast to the network — before it is finalized (stable) and before dependent AA effects (e.g. state changes that would otherwise "harm" the user) are applied — and then decide, with full knowledge of that outcome, whether to compose and post a competing trigger unit that reacts favorably to it.

### Finding Description
When an oscript formula executes the `data_feed` operator inside AA execution, it calls `dataFeeds.readDataFeedValue(arrAddresses, feed_name, value, min_mci, mci, bAA, ifseveral, ...)`, unconditionally passing `bAA` (which is `true` whenever the formula runs as part of AA processing) as the `unstable_opts` argument: [1](#0-0) 

Inside `readDataFeedValue`, when `unstable_opts` is truthy, the function scans `storage.assocUnstableMessages` — i.e., messages belonging to units that have been broadcast/written but are **not yet marked stable** — for `data_feed` payloads from AA response units, and returns the *latest* one found by `(latest_included_mc_index, level)` ordering, without waiting for the unit to become stable: [2](#0-1) 

The same unstable-read behavior applies to `in_data_feed` boolean checks via `dataFeedExists`, which likewise scans `storage.assocUnstableMessages` for AA-authored data feeds within the requested MCI window: [3](#0-2) 

The oscript language also exposes `number_from_seed` and `vrf_verify`, which are the primitives typically used to build randomness/games on top of a data feed value (an oracle posts a seed/proof, and the consuming AA derives a number from it): [4](#0-3) [5](#0-4) 

Because `data_feed[[...]]` reads are not restricted to the stable state when executed inside an AA, a randomness/oracle-providing AA's response (posted as a normal unit, visible to the whole network as soon as it is broadcast) reveals its outcome to observers *before* that unit is officially stable. AA triggers are processed strictly per stabilized MCI in a deterministic order (`level, unit, address`) once `markMcIndexStable`/`handleAATriggers` runs: [6](#0-5) 

An attacker (or any observer of the peer-to-peer broadcast) who watches for the oracle/VRF-provider's response unit can read its content directly (units are gossiped before stability), compute the outcome, and only then decide whether to compose and submit their own trigger to a dependent AA (e.g., an "escape"/"claim" style AA) so that it lands in an MCI batch that stabilizes with, or shortly after, the revealing unit but before a separate "apply penalty/wound" AA trigger stabilizes. Because the decision of *whether to submit at all* is made with foreknowledge of the random outcome, this is the same class of vulnerability as the reported `rawFulfillRandomWords()`/`escape()` front-run: information that should only affect the state atomically is instead observable and actionable ahead of the atomic effect being finalized.

### Impact Explanation
An attacker with knowledge of a not-yet-stable oracle/VRF data feed value can selectively decide whether to interact with a dependent AA (mint, claim, escape, bet, etc.), guaranteeing a favorable outcome or avoiding an unfavorable one. This breaks the fairness guarantee of any AA-based game or financial mechanism that relies on `data_feed`/`in_data_feed` reads for randomness, potentially causing unauthorized extraction of AA funds (asymmetric payouts favoring informed actors) at the expense of AA reserves or other honest participants.

### Likelihood Explanation
Any full node — not a privileged validator, hub, or malicious infrastructure operator — can observe pending/unconfirmed units broadcast on the Obyte network before they stabilize, because this is normal peer gossip, not a network attack. The `bAA`-driven unstable-read path is unconditionally taken by ocore whenever AA formulas evaluate `data_feed`/`in_data_feed`, so any AA design that uses a data feed for randomness (a well-known and encouraged Obyte pattern via `number_from_seed`/`vrf_verify`) is exposed. No special privileges are required beyond composing and broadcasting an ordinary payment/trigger unit.

### Recommendation
- For randomness-sensitive reads, restrict `data_feed`/`in_data_feed` evaluation to fully stable data only (disallow the `unstable_opts`/`bIncludeUnstableAAs` shortcut for values intended as random seeds), or
- Require AA authors to explicitly commit-then-reveal randomness across two separate, stability-gated steps, ensuring the revealing data feed cannot be read by any trigger until it is stable, closing the observation window that enables selective/conditional submission of competing triggers.

### Proof of Concept
1. Oracle AA `O` posts a `data_feed` message containing a VRF-derived random value as part of its AA response unit (broadcast to network, not yet stable).
2. Dependent AA `G` (e.g., a lottery/escape-style AA) reads `data_feed[[oracles=O, feed_name="rnd"]]` to decide payouts/state transitions.
3. Because `readDataFeedValue` is invoked with `unstable_opts = bAA = true` (`formula/evaluation.js` line 646), any observer who sees `O`'s unstable unit on the network can compute the exact outcome before it is stable.
4. The observer composes and posts a trigger to `G` only if the revealed value is favorable, exploiting the deterministic MCI-ordered processing (`main_chain.js` `handleAATriggers`, lines 1691-1723) to land their trigger advantageously relative to any separate "apply penalty" AA logic that has not yet stabilized.
5. Honest users who submit triggers before the random value is revealed do not have this informational advantage, resulting in unfair extraction of AA funds.

function readDataFeedValue(arrAddresses, feed_name, value, min_mci, max_mci, unstable_opts, ifseveral, timestamp, handleResult){
	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	var start_time = Date.now();
	var objResult = { bAbortedBecauseOfSeveral: false, value: undefined, unit: undefined, mci: undefined };
	var bIncludeUnstableAAs = !!unstable_opts;
	var bIncludeAllUnstable = (unstable_opts === 'all_unstable');
	if (bIncludeUnstableAAs) {
		var arrCandidates = [];
		for (var unit in storage.assocUnstableMessages) {
			var objUnit = storage.assocUnstableUnits[unit] || storage.assocStableUnits[unit];
			if (!objUnit)
				throw Error("unstable unit " + unit + " not in assoc");
			if (!objUnit.bAA && !bIncludeAllUnstable)
				continue;
			if (objUnit.sequence !== 'good')
				continue;
			if (objUnit.latest_included_mc_index < min_mci || objUnit.latest_included_mc_index > max_mci)
				continue;
			if (_.intersection(arrAddresses, objUnit.author_addresses).length === 0)
				continue;
			storage.assocUnstableMessages[unit].forEach(function (message) {
				if (message.app !== 'data_feed')
					return;
				var payload = message.payload;
				if (!ValidationUtils.hasOwnProperty(payload, feed_name))
					return;
				var feed_value = payload[feed_name];
				if (value === null || value === feed_value || value.toString() === feed_value.toString())
					arrCandidates.push({
						value: string_utils.getFeedValue(feed_value, bLimitedPrecision),
						latest_included_mc_index: objUnit.latest_included_mc_index,
						level: objUnit.level,
						unit: objUnit.unit,
						mci: max_mci // it doesn't matter
					});
			});
		}
		if (arrCandidates.length === 1) {
			var feed = arrCandidates[0];
			objResult.value = feed.value;
			objResult.unit = feed.unit;
			objResult.mci = feed.mci;
			if (ifseveral === 'last')
				return handleResult(objResult);
		}
		else if (arrCandidates.length > 1) {
			if (ifseveral === 'abort') {
				objResult.bAbortedBecauseOfSeveral = true;
				return handleResult(objResult);
			}
			arrCandidates.sort(function (a, b) {
				if (a.latest_included_mc_index < b.latest_included_mc_index)
					return -1;
				if (a.latest_included_mc_index > b.latest_included_mc_index)
					return 1;
				if (a.level < b.level)
					return -1;
				if (a.level > b.level)
					return 1;
				if (bIncludeAllUnstable) // still ambiguous, sort randomly (it's OK outside AAs)
					return 1;
				throw Error("can't sort candidates "+a+" and "+b);
			});
			var feed = arrCandidates[arrCandidates.length - 1];
			objResult.value = feed.value;
			objResult.unit = feed.unit;
			objResult.mci = feed.mci;
			return handleResult(objResult);
		}
