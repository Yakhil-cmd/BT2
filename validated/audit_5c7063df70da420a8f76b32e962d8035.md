### Title
Verifier-selector/repository-target divergence lets a webhook authenticated against any secretless org provision a `ReviewStack` for an unrelated, secured repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` picks the `GitHubApp` used to authenticate a webhook from `repository_owner`, which falls back to `params.dig('organization','login')`. `OpenedHandler` and `ReviewStackAdapter`, however, resolve the actual target repository/stack from the independently attacker-controlled `params.repository.full_name`. If any org configured in Shipit lacks a `webhook_secret`, `GitHubApp#verify_webhook_signature` returns `true` unconditionally, so an attacker can authenticate under that secretless org while pointing `repository.full_name` at a completely different, properly-secured repository, causing `OpenedHandler` to create a `ReviewStack` for it.

### Finding Description
The broken binding, stated as an equality that should hold but doesn't:
`repository_owner` (used to select the verifying `GitHubApp`, `app/controllers/shipit/webhooks_controller.rb:25,59-62`) should equal the owner of `params.repository.full_name` (used by the handler/adapter to select the target `Repository`/`ReviewStack`, `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:50-54` and `app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb:64-66,87-98`). Nothing in the code enforces this equality.

Path:
1. `WebhooksController#create` parses the JSON body and runs `before_action :verify_signature` first [1](#0-0) .
2. `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)`, where `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` [2](#0-1) [3](#0-2) .
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank for that org's config: `return true unless webhook_secret` [4](#0-3) .
4. Once verified, `WebhooksController#create` dispatches `params` (the whole raw JSON, unmodified) to `Shipit::Webhooks.for_event(event)` handlers, including `OpenedHandler` for `pull_request`/`opened` [1](#0-0) .
5. `OpenedHandler#repository` resolves the actual `Shipit::Repository` via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, a plain `owner`/`name` DB lookup with no relation whatsoever to the org used in step 2 [5](#0-4) [6](#0-5) .
6. If provisioning is enabled for that resolved repository, `ReviewStackAdapter#find_or_create!` creates a `ReviewStack` using `params.pull_request.head.ref` as branch and `params.number` as environment, with no re-check of the authenticating org [7](#0-6) .

Exploit request: attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a JSON body where `organization.login` (or `repository.owner.login`) = `secretless-org` (an org configured in Shipit's secrets with `webhook_secret` blank/nil, per the documented multi-org config schema), but `repository.full_name` = `secured-org/victim-repo` (a real, provisioning-enabled repository belonging to a different, properly-secured org), `action` = `opened`, and a valid `pull_request` sub-object (`head.ref`, `user.login`, etc.) with no need for a correct `X-Hub-Signature` since verification is skipped for `secretless-org`.

Existing guards fail to close this: `verify_signature` only checks that *some* configured org's secret (or lack thereof) validates the signature — it never checks that the org used for verification matches the repository the payload claims to touch; `drop_unhandled_event` only filters by event type, not payload consistency; the `ExplicitParameters` schema in `OpenedHandler` only validates presence/types of fields, not cross-field consistency between `repository.full_name` and whatever org authenticated the request; `Repository.from_github_repo_name` performs no ownership/organization cross-check against the verifying org.

### Impact Explanation
An attacker who can get any single org registered in Shipit's config without a `webhook_secret` (a documented, supported configuration per `docs/setup.md`'s "Using Multiple Github Applications" section) gains the ability to forge `pull_request`/`opened` (and, by the same mechanism, `closed`/`labeled`/`reopened`/`unlabeled`/`assigned`/`edited` handlers, all of which resolve `repository` the same way) events for **any other repository in the system**, including ones belonging to properly-secured orgs, creating/mutating `ReviewStack` records (a stack, not merely a comment) that the attacker does not own or control. This is a payload for one repository/org mutating another repository's stack — matching the "Critical: a payload for one repository mutating another's stack" impact category. It is repeatable against arbitrary repositories/stacks with provisioning enabled, as long as at least one secretless org config exists in the deployment.

### Likelihood Explanation
Preconditions: (a) the Shipit deployment must use the multi-organization `github:` config schema with at least one org lacking `webhook_secret` — this is an explicit, documented configuration option, not a default, so likelihood depends entirely on operator configuration; (b) a target repository with `review_stacks_enabled` and an `allow_all`/label-based provisioning policy that would accept the forged PR. Attacker cost is a single unauthenticated HTTP POST with no secrets or session required, fully repeatable. The core weakness (selector/target divergence) is present unconditionally in the code — its exploitability is gated purely on the secretless-org precondition, which the question explicitly stipulates as given ("victim stack where org configured without webhook_secret").

### Recommendation
After resolving the target `Repository` in each `pull_request` handler (or centrally, before dispatch), verify that the resolved repository's `owner` matches the `repository_owner`/org that authenticated the webhook (i.e., re-derive `repository_owner` and compare it against `params.repository.owner.login` / the resolved `Repository#owner`, rejecting the request on mismatch). Additionally, consider making `webhook_secret` mandatory for all configured orgs (removing the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature`), since an org without a secret effectively disables authentication for every webhook that can be routed to that org key.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`), no live GitHub calls:
1. Configure test secrets with two orgs: `secretless-org` (no `webhook_secret`) and `secured-org` (with `webhook_secret` set), mirroring `test/dummy/config/secrets_double_github_app.yml` pattern seen in `test/unit/shipit_test.rb`.
2. Create a `Shipit::Repository` for `secured-org/victim-repo` with `review_stacks_enabled: true`, `provisioning_behavior: allow_all`.
3. Build a `pull_request`/`opened` payload: `{"action"=>"opened","number"=>1,"organization"=>{"login"=>"secretless-org"},"repository"=>{"full_name"=>"secured-org/victim-repo"},"pull_request"=>{...valid fields, head: {ref: "attacker-branch", sha: "..."}},"sender"=>{"login"=>"attacker"}}` with no correct `X-Hub-Signature` (or an arbitrary garbage value).
4. `post :create` with `X-Github-Event: pull_request`.
5. Assert response is `:ok` (not `:unprocessable_entity`), and `assert_difference -> { Shipit::ReviewStack.count }, 1` to prove a `ReviewStack` was provisioned for `secured-org/victim-repo` despite the request only being "authenticated" against `secretless-org`'s (non-existent) secret — i.e., assert `Shipit::Repository.find_by(owner: 'secretless-org').nil?` (no repo exists for the verifying org) while `Shipit::ReviewStack.last.pull_request` belongs to `secured-org/victim-repo`, proving `repository_owner` (`"secretless-org"`) ≠ the actual owner mutated (`"secured-org"`).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
