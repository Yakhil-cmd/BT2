### Title
Cross-tenant webhook confusion: `repository_owner` (signature-verification selector) and `repository.full_name` (handler target) are independent fields, letting one organization's webhook secret authenticate a `pull_request`/`reopened` event that mutates another organization's `ReviewStack` — (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit.rb`, `app/models/shipit/webhooks/handlers/pull_request/reopened_handler.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects which organization's webhook secret to verify a payload against using `repository_owner`, which falls back from `repository.owner.login` to `organization.login` when the former is absent. `ReopenedHandler` never inspects `repository.owner.login`/`organization.login` at all — it resolves the target `Repository`/`Stack` purely from `params.repository.full_name`, a separately attacker-controlled field. In a multi-organization Shipit deployment (`Shipit.github_app_config`), an attacker who legitimately controls one onboarded organization's webhook secret can sign a payload as that organization while pointing `repository.full_name` at a victim organization's repository, causing `ReopenedHandler#process` to unarchive/recreate a `ReviewStack` for a repository that never authenticated the request.

### Finding Description
The claimed broken binding, verified explicitly:

- Verification identity: `verifying_org = params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0) , used to pick the `GitHubApp`/secret via `Shipit.github(organization: repository_owner)` and `verify_webhook_signature` [2](#0-1) .
- Processing identity: `target_repo = params.dig('repository','full_name')`, used by `ReopenedHandler#repository` to load the acted-upon `Shipit::Repository`/`ReviewStack` [3](#0-2) .

The invariant the question asks to test — "a `pull_request` event only affects the repository/stack whose secret authenticated it" — requires `verifying_org == owner(target_repo)`. This equality is **not enforced anywhere** in the traced path:

1. `Shipit.github(organization:)` looks up per-organization config independently via `github_app_config(organization)`, each with its own `webhook_secret` [4](#0-3) .
2. `ReopenedHandler`'s `ExplicitParameters` schema requires `repository.full_name` but never requires or cross-checks `repository.owner.login` or `organization.login` [5](#0-4) , so an attacker can freely omit/diverge those fields from `repository.full_name`.
3. `Handler#repository_name` (the shared base-class helper used across handlers) likewise reads only `payload.dig('repository','full_name')` [6](#0-5) .

Exploit flow: attacker legitimately controls organization "attacker-org" onboarded to this shared multi-org Shipit instance (they configured its GitHub App/webhook and thus know `webhook_secret_attacker`). They send `POST /webhooks` with header `X-Github-Event: pull_request`, body `{"action":"reopened", "organization":{"login":"attacker-org"}, "repository":{"full_name":"victim-org/victim-repo"}, "pull_request": {...}, "sender": {...}}` (omitting `repository.owner.login` so the controller's fallback selects `attacker-org`), signed with `webhook_secret_attacker`. `verify_signature` succeeds because it verifies against `attacker-org`'s secret, which matches. `ReopenedHandler` then resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and, if that repository's provisioning policy allows it (`allow_all`, or label-based policy satisfied by attacker-controlled `labels` in the forged payload), calls `stack.unarchive!`, unarchiving/recreating a `ReviewStack` for `victim-org/victim-repo` — a repository that never authenticated this request. `check_if_ping`/`drop_unhandled_event` do not block this event type, and no code path re-derives or checks that the signature-verifying organization matches the repository actually processed.

### Impact Explanation
An attacker who is a legitimate tenant of one organization on a shared multi-org Shipit instance can, using only their own organization's webhook secret, forge state-changing webhook events targeting any other tenant's repository/stack, here causing unarchiving/recreation of a `ReviewStack` (and, by the identical field-divergence pattern, other `pull_request`/`push`/`status` handlers acting on `repository.full_name`) for a repository that did not authenticate the request. This matches the explicitly Critical category "a payload for one repository mutating another's stack, commit, task or team." It is fully repeatable against any victim repository/stack known to the attacker (repo names are public), with no rate limit or additional privilege needed beyond the attacker's own organization's webhook secret.

### Likelihood Explanation
This requires: (1) the Shipit instance to be configured in multi-organization mode (`secrets.github` keyed by org, each with independent `webhook_secret`) rather than single-org mode (in single-org mode `Shipit.github` ignores the `organization:` argument entirely and always uses the one global secret, per `lib/shipit.rb:170-174`, so the divergence is moot there); (2) the attacker to legitimately control/onboard one organization on that shared instance (a realistic SaaS/multi-tenant deployment scenario, and the attacker only needs knowledge of their own org's secret); (3) the victim repository to have review-stack provisioning enabled with a policy the attacker's forged payload satisfies (`allow_all`, or label-based, which the attacker fully controls in the payload). Given multi-org support is a first-class configuration path in this engine (`TOP_LEVEL_GH_KEYS`, `github_app_config`), this is a realistic, low-cost, repeatable attack for any tenant against any other tenant on the same shared instance.

### Recommendation
Enforce that the organization/repository used to select the webhook signature verifier matches the repository the handler will act on. Concretely: after successful signature verification, re-derive the repository owner strictly from `repository.full_name`'s owner segment (never from `organization.login` alone) and reject/422 the request if it does not match the organization whose secret was used to verify the signature; alternatively, require `repository.owner.login` in every handler's `params` schema and assert equality with the verifying organization before invoking `handler.call`.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` or `test/models/shipit/webhooks/handlers/pull_request/reopened_handler_test.rb`), no live GitHub:
1. Configure two orgs in `Shipit.secrets.github`: `attacker_org` (secret `S_A`) and `victim_org` (secret `S_V`), each `Shipit::GitHubApp.new`.
2. Create `victim_repo = shipit_repositories(:victim_org_repo)` with `review_stacks_enabled: true`, `provisioning_behavior: allow_all`, owned by `victim_org`, and its production `Stack`.
3. Build payload: `{ action: "reopened", organization: { login: "attacker_org" }, repository: { full_name: "victim_org/victim_repo" }, pull_request: {...}, sender: { login: "attacker" } }` (no `repository.owner.login`).
4. Sign with `S_A` (`OpenSSL::HMAC.hexdigest('sha1', S_A, body)`), set `X-Hub-Signature`, `X-Github-Event: pull_request`, `POST /webhooks`.
5. Assert: response is `:ok` (signature verified via `attacker_org`'s secret) — i.e. `verifying_org == "attacker_org"`.
6. Assert: `victim_repo.review_stacks.find_by(...)` was unarchived/created — i.e. `acted_on_repo == "victim_org/victim_repo"`.
7. Assert `verifying_org != owner(acted_on_repo)` (`"attacker_org" != "victim_org"`), proving the invariant is violated and the cross-tenant mutation occurred.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
