### Title
RAY-value overflow during mandatory interest accrual permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
**High.** A sufficiently large, highly utilized market can make `borrowed * borrow_index` or `supplied * supply_index` exceed `i128::MAX` during accrual. [1](#0-0)  Once that happens, `Controller::update_indexes`, `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, `supply`, `borrow`, `recapitalize`, and even pool parameter replacement all revert before committing new state. [2](#0-1) [3](#0-2) 

### Finding Description
`Controller::update_indexes` is callable by an ordinary authenticated caller and forwards the selected `HubAssetKey`s to the pool. [4](#0-3) [5](#0-4)  The pool’s `update_indexes` handler runs `ops::market::accrue`, which loads the market and calls `interest::global_sync` before committing. [6](#0-5) [7](#0-6) 

`global_sync` runs `accrue_step` for each elapsed chunk. [8](#0-7)  `accrue_step` first converts scaled debt and supply to RAY-denominated values with `scaled_to_original`. [9](#0-8)  That conversion is `Ray::mul`, which computes `scaled * index / RAY` and returns an `i128`. [10](#0-9) [11](#0-10)  Although the intermediate multiplication uses `I256`, the final `to_i128()` fails when the resulting market value exceeds `i128::MAX`, surfacing `MathOverflow`. [12](#0-11) [13](#0-12) 

The borrow-index ceiling does not prevent this state: it caps the index at `MAX_BORROW_INDEX_RAY`, but the scaled balance can already be large enough that `scaled * index` overflows at an index far below that ceiling. [14](#0-13)  The same overflow can occur when calculating old and new total debt for supplier rewards. [15](#0-14) 

All ordinary market mutations share the same mandatory pre-sync: `load_leg` calls `synced_market`, and `synced_market` calls `global_sync`. [2](#0-1) [16](#0-15)  Repay, withdraw, borrow, liquidation seizure, and recapitalization therefore all hit the same failing accrual before any recovery logic executes. [17](#0-16) [18](#0-17) [19](#0-18) [20](#0-19) [21](#0-20) 

### Impact Explanation
The affected market becomes permanently unusable without a privileged code upgrade or equivalent out-of-band recovery. Suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize collateral or socialize bad debt, and governance cannot replace the rate model because that path also accrues under the old model first. [3](#0-2)  Pool cash and all user claims in that market remain frozen, while an underwater account cannot be liquidated through `Controller::liquidate` or `clean_bad_debt`. [22](#0-21) [23](#0-22) 

### Likelihood Explanation
The trigger requires a very large scaled market balance and enough index growth for its RAY value to exceed `i128::MAX`; it is not reachable through an ordinary small position alone. Markets may nevertheless admit very large balances because the asset-domain cap is approximately `i128::MAX / 10^(27-d)`, while accrued values are documented as independently required to fit `i128`. [24](#0-23)  A single funded address can create separate supplier and borrower accounts, supply the debt asset and collateral, take the largest permitted borrow, and later call the permissionless index-update path once the stored balances cross the representable-value boundary. [25](#0-24) [26](#0-25) [27](#0-26) 

### Recommendation
Enforce a balance-dependent representability bound before minting supply or debt: for each scaled total `S`, require `S * MAX_INDEX / RAY <= i128::MAX`, or calculate the largest safe index dynamically and cap accrual at that value before computing RAY totals. For existing markets, add an explicit overflow-safe accrual path that detects the boundary with `I256`, clamps the index to a value that keeps debt and supply values representable, and commits that state so repayment, withdrawal, liquidation, and recapitalization remain available. Index growth should stop or rate-limit rather than permanently brick the market. [14](#0-13) [28](#0-27) 

### Proof of Concept

```rust
// One unprivileged address owns both accounts.
let debt_asset = HubAssetKey { hub_id, asset: big18_token };
let collateral_asset = HubAssetKey { hub_id, asset: collateral_token };

// P must be within the configured supply cap but large enough that:
// scaled_debt * future_borrow_index / RAY > i128::MAX.
let p: i128 = 1_000_000_000 * 10i128.pow(18);
let d: i128 = p * 98 / 100;

let supplier_id = controller.supply(
    whale.clone(),
    0,
    spoke_id,
    vec![&env, (debt_asset.clone(), p)],
);

let borrower_id = controller.supply(
    whale.clone(),
    0,
    spoke_id,
    vec![&env, (collateral_asset, sufficient_collateral)],
);

controller.borrow(
    whale.clone(),
    borrower_id,
    vec![&env, (debt_asset.clone(), d)],
    Some(whale.clone()),
);

// After enough ledger time for index growth, the permissionless sync reverts.
controller.update_indexes(whale.clone(), vec![&env, debt_asset.clone()]);

// All of these subsequently revert inside the same mandatory accrual.
controller.repay(whale.clone(), borrower_id, vec![&env, (debt_asset.clone(), 1)]);
controller.withdraw(
    whale.clone(),
    supplier_id,
    vec![&env, (debt_asset.clone(), 1)],
    Some(whale.clone()),
);
controller.liquidate(
    liquidator,
    borrower_id,
    vec![&env, (debt_asset, 1)],
    SeizeMode::Transfer,
);
```

```markdown
| Borrow APR maximum 2 RAY | 200% annual rate; not a bound on balance growth alone |
| Token-to-RAY input maximum `i128::MAX / 10^(27-d)` | About 170.14 billion whole tokens, before other limits |
| Deposit conversion at the supply-index floor | About 170.14 million whole tokens before scaled-share overflow |

The token-to-RAY maximum is also the admitted cap maximum. Accrued position
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
no borrower interest. No dedicated ceiling alarm is emitted.
```
