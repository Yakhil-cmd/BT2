### Title
Unauthenticated webhook acceptance for orgs without `webhook_secret` allows forged `pull_request` `unlabeled` events to archive/unarchive arbitrary review stacks - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the organization's GitHub App config has no `webhook_secret` set, meaning `Shipit::WebhooksController#verify_signature` provides zero authentication for such orgs. An attacker who knows a repository's `owner/name` under such an org can forge a `pull_request` `action=unlabeled` JSON body, which `UnlabeledHandler` will process and use to archive or unarchive the matching `ReviewStack`.

### Finding Description
The broken binding: `verify_signature` is claimed to guarantee `authenticated(request) == true` only if `request` truly originated from GitHub for `repository_owner`. In reality, for an org configured without `webhook_secret`, the binding degrades to `authenticated(request) == true` unconditionally, independent of the request's true origin.

Code path: `Shipit::WebhooksController#create` calls `verify_signature` as a `before_action` [1](#0-0) . `verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` from the attacker-controlled `params.dig('repository','owner','login')`, then calls `github_app.verify_webhook_signature(...)` [2](#0-1) [3](#0-2) . `GitHubApp#verify_webhook_signature` is defined as:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 
`@webhook_secret` is set from `@config[:webhook_secret].presence`, so any org entry in `config/secrets.yml` lacking a `webhook_secret` value causes this method to short-circuit to `true` for every request claiming that org, regardless of the `X-Hub-Signature` header's validity [5](#0-4) .

Once `verify_signature` passes, `create` parses the forged JSON body and dispatches it to `Shipit::Webhooks.for_event('pull_request')`, which includes `UnlabeledHandler` [6](#0-5) . `UnlabeledHandler` resolves the target `repository` purely from the attacker-supplied `params.repository.full_name` via `Shipit::Repository.from_github_repo_name` (a DB lookup keyed by owner/name string, no ownership check against the resolved `github_app`) [7](#0-6) , then resolves the `ReviewStack` via `ReviewStackAdapter#stack` matched on `environment` (derived from PR number, also attacker-controlled) within `repository.review_stacks` [8](#0-7) . If `respond_to_label_change?` is true (action `unlabeled`, PR state `open`, `review_stacks_enabled`, and the provisioning-behavior/label logic evaluates to archive or unarchive), `handle` calls `stack.archive!` or `stack.unarchive!` [9](#0-8) . `ReviewStackAdapter#archive!`/`#unarchive!` mutate the stack state, including `deprovision`/re-enqueuing to the provisioning queue, attributed to a `user` created from the attacker-controlled `params.sender.login` [10](#0-9) .

No other guard intervenes: `drop_unhandled_event` only checks the event type is registered, not authenticity [11](#0-10) ; there is no cross-check that the resolved `repository`'s configured GitHub App/org matches the `github_app` used for signature verification. Existing model validations (`Repository` owner/name format) don't prevent this since the attacker only needs to know or guess a valid `owner/name` for a real, no-secret-configured org's repository.

### Impact Explanation
For any organization whose Shipit deployment omits `webhook_secret` in `config/secrets.yml` — an explicitly documented "optional" field in `docs/setup.md` — an unauthenticated internet attacker can forge `pull_request` webhooks that cause Shipit to archive or unarchive review stacks (triggering `deprovision`/provisioning-queue side effects) for any repository under that org, without ever having interacted with GitHub or holding any Shipit credential. This is a full authentication bypass for the webhook ingress on that org's tenant, matching the Critical "authentication bypass (forged webhook ... accepted as trusted)" category. It is repeatable against every repository/review-stack under any org lacking `webhook_secret`, and could similarly be used to trigger other `pull_request`/`push`/`status` handlers gated the same way (e.g. `OpenedHandler`, `ReopenedHandler`, `ClosedHandler`), not just `UnlabeledHandler`.

### Likelihood Explanation
The only precondition is that the target org's `github` config in `secrets.yml` has no `webhook_secret` set — a state the setup docs explicitly present as optional/allowed [12](#0-11) . Given that, attacker cost is a single unauthenticated `POST /webhooks` with a crafted JSON body and correct `X-Github-Event: pull_request` header; no secrets, sessions, or GitHub interaction are required. This is fully feasible and repeatable at will.

### Recommendation
Require `webhook_secret` to be configured for every org and fail closed (reject/`head(422)`) when it is absent instead of returning `true`; alternatively, refuse to boot/register a `GitHubApp` without a configured `webhook_secret`, or emit a startup warning and reject all webhooks for that org until one is set.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` or `test/models/.../unlabeled_handler_test.rb` style, illustrative only per rules):
1. Configure `Shipit.github(organization: 'no-secret-org')` backed by a config hash with no `webhook_secret` key.
2. Create `Repository.create!(owner: 'no-secret-org', name: 'repo', review_stacks_enabled: true, provisioning_behavior: 'allow_with_label')` and a provisioned `ReviewStack` matching `environment` derived from a PR number.
3. Assert binding before: `stack.archived? == false`.
4. `post '/webhooks', params: forged_pull_request_unlabeled_json, headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=garbage' }` — no valid HMAC computed since attacker has no secret.
5. Assert response is `200 OK` (not `422`), proving `verify_webhook_signature` accepted the forged, incorrectly-signed request.
6. Assert binding after: `stack.reload.archived? == true` (or `unarchive!` transition observed), demonstrating state mutation on a stack that never authenticated the request.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end

          def user
            @user ||= Shipit::User.find_or_create_by_login!(params.sender["login"])
