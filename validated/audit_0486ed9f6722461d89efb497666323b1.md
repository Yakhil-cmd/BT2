### Title
Owner/full_name split lets an attacker forge webhook signatures for a foreign org's repository and auto-provision a `ReviewStack` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the HMAC secret to check using `repository.owner.login` [1](#0-0) [2](#0-1) , while `OpenedHandler` (and its sibling `pull_request` handlers) resolve the actual repository/stack to mutate from the independent `repository.full_name` field [3](#0-2) . Because `verify_webhook_signature` returns `true` unconditionally whenever the selected org has no `webhook_secret` configured [4](#0-3) , an attacker can name a no-secret org in `owner.login` (which is used only for signature selection) while pointing `full_name` at a victim org/repo, causing the signature check to "pass" for a payload that mutates a completely different, victim-authenticated repository.

### Finding Description
The broken binding, stated as an equality that the code should enforce but doesn't:

`repository_owner_used_for_signature (params.repository.owner.login) == repository_used_for_mutation (params.repository.full_name).split('/').first`

This equality is never checked anywhere in the request path.

Code path:
1. `Shipit::WebhooksController#verify_signature` computes `repository_owner` strictly from `params.dig('repository', 'owner', 'login')` (or `organization.login`) [2](#0-1) , and uses that value to fetch the corresponding `Shipit::GitHubApp` config: `Shipit.github(organization: repository_owner)` [1](#0-0) .
2. `GitHubApp#verify_webhook_signature` short-circuits and returns `true` whenever that org has no `webhook_secret` configured: `return true unless webhook_secret` [4](#0-3) . Any GitHub org/user account an attacker controls, that is simply not configured with a `webhook_secret` in the host's Shipit config, satisfies this.
3. Once the signature check "passes," `WebhooksController#create` dispatches the parsed JSON body to all handlers for the `pull_request` event unmodified [5](#0-4) .
4. `OpenedHandler#repository` resolves the repository to act on using `params.repository.full_name` via `Shipit::Repository.from_github_repo_name` — a field completely independent from `repository.owner.login` used in step 1 [3](#0-2) . Nothing anywhere cross-checks that `full_name`'s owner segment matches `owner.login`.
5. If that resolved repository has review-stack provisioning enabled, `OpenedHandler#process` calls `ReviewStackAdapter#find_or_create!`, which creates a `ReviewStack` using attacker-controlled `branch: params.pull_request.head.ref` and `environment: "pr#{params.number}"`, then enqueues it for provisioning (`Shipit::ReviewStackProvisioningQueue.add(stack)`) [6](#0-5) .

The attacker's exact request: `POST /webhooks` with header `X-Github-Event: pull_request`, a valid `X-Hub-Signature` value (irrelevant, since it's ignored when the selected org has no secret), and a JSON body where `repository.owner.login` = attacker's own no-secret GitHub org/user, and `repository.full_name` = `"<victim-org>/<victim-repo>"` (a repository configured on the victim Shipit host with review-stack provisioning enabled and `Shipit.user`/bot_login configured). `action` = `"opened"`.

Existing guards fail to prevent this:
- `verify_signature` only ever checks the org named in `owner.login`; it never reads or validates `full_name`'s owner segment against it [7](#0-6) .
- `drop_unhandled_event` and `check_if_ping` only gate on event type, not payload consistency.
- `ExplicitParameters` schema in `OpenedHandler` requires `repository.full_name` to be a `String` but performs no relational check against `repository.owner.login` (which isn't even part of the declared schema) [8](#0-7) .
- `Repository#from_github_repo_name` does a straightforward `owner/name` lookup with no relation back to the org that authenticated the request [9](#0-8) .

### Impact Explanation
An attacker who owns any GitHub org/user account that the victim's Shipit deployment has NOT configured with a `webhook_secret` (a very common state - most hosts only configure secrets for the orgs they actually operate) can forge `pull_request` webhooks that are treated as authenticated for a target victim repository named in `full_name`. This lets the attacker auto-provision `ReviewStack`s for a completely different, secret-protected tenant repository, with attacker-controlled `branch`/`ref` and PR metadata, triggering the review-stack provisioning pipeline (which, per the question's premise, deploys using the stack's configured bot identity, e.g. `Shipit.user`). This is a payload for one repository (an unowned/no-secret org) mutating another repository's/tenant's stack state and triggering deploy actions under the bot identity — matching the Critical category "a payload for one repository mutating another's stack... or an unauthorized deploy". It is repeatable against any repository/tenant on the same Shipit host whose org name the attacker can enumerate or guess, and is not scoped to a single victim.

### Likelihood Explanation
Preconditions: (1) the Shipit host has at least one org configured in `Shipit.github(organization: ...)` without a `webhook_secret` (this is plausible for hosts that mix mandatory-secret production orgs with looser/test orgs, or multi-tenant configs where secret configuration is inconsistent), and (2) the victim repository named in `full_name` has review-stack provisioning enabled (`review_stacks_enabled` + a `provisioning_behavior` that matches, e.g. `allow_all`). Attacker cost is a single unauthenticated HTTP POST with no GitHub credentials, no Shipit session, and no valid HMAC secret required — trivial and fully repeatable/scriptable against many `full_name` targets in one campaign.

### Recommendation
In `Shipit::WebhooksController#verify_signature`, derive the organization used for signature verification from the same field used for repository resolution downstream (`repository.full_name`'s owner segment) rather than `repository.owner.login`/`organization.login`, or explicitly assert that both fields resolve to the same organization before proceeding. Additionally, `GitHubApp#verify_webhook_signature` should not silently return `true` when `webhook_secret` is blank for orgs that own repositories with review-stack provisioning or bot deploy configuration — failing closed (or requiring a mandatory secret for any org with configured repositories) removes the exploitable "no-secret org" bypass entirely.

### Proof of Concept
Minitest plan (`test/controllers/shipit/webhooks_controller_test.rb`, no live GitHub):
1. Configure two orgs in test `Shipit.github_apps`-style config: `"attacker-org"` with no `webhook_secret`, and `"victim-org"` with a `webhook_secret` set.
2. Create `Repository` with `owner: "victim-org"`, `name: "victim-repo"`, `review_stacks_enabled: true`, `provisioning_behavior: "allow_all"`.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, body:
   ```json
   {
     "action": "opened",
     "number": 42,
     "pull_request": { "id":1, "number":42, "url":"...", "title":"x", "state":"open",
       "additions":1, "deletions":0,
       "head": { "sha":"abc", "ref":"attacker-branch" },
       "user": { "login": "attacker" }, "assignees": [], "labels": [] },
     "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
     "sender": { "login": "attacker" }
   }
   ```
   with `X-Hub-Signature` absent/arbitrary.
4. Assert equality violated: `params.dig('repository','owner','login') != params.dig('repository','full_name').split('/').first` ("attacker-org" != "victim-org") — the binding the invariant requires to match.
5. Assert response is `200`/`:ok` (not `422`), proving signature verification "passed" despite the mismatch.
6. Assert `Shipit::ReviewStack.find_by(environment: "pr42")` exists under the `victim-org/victim-repo` repository with `branch: "attacker-branch"` — proving cross-tenant state mutation via an unauthenticated forged request.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
