### Title
Missing sender-authorization check in `handleNewSharedAddress` allows any paired device to register spoofed multisig shared-address bindings - ([File: wallet_defined_by_addresses.js])

### Summary
`wallet_defined_by_addresses.js`'s `handleNewSharedAddress` processes the `new_shared_address` device message and persists a shared (multisig) address definition plus the signer-to-device-address bindings that the wallet UI will later use to route signing requests, without ever verifying that the message's sender (`from_address`) is actually one of the parties named in the definition/signers it is submitting.

### Finding Description
`handleNewSharedAddress(body, callbacks)` [1](#0-0)  validates only internal self-consistency of the attacker-supplied payload:
- that `body.address` equals `getChash160(body.definition)` [2](#0-1) 
- that each entry in `body.signers` is a syntactically valid address [3](#0-2) 
- that the signer addresses match the `["address", ...]` leaves extracted from the definition [4](#0-3) 
- that "my" address is referenced somewhere in the signers [5](#0-4) 

None of these checks bind the message to the actual sending device. Unlike other paired-device handlers in the same codebase (e.g. `arbiter_contract_shared` in `wallet.js`, which explicitly requires `SELECT ... FROM my_addresses JOIN wallet_signing_paths ... WHERE device_address=?` matching `from_address` [6](#0-5) , or `prosaic_contract_update`, which checks `objContract.peer_device_address !== from_address` [7](#0-6) ), `handleNewSharedAddress` never receives or checks `from_address` at all — its signature is `handleNewSharedAddress(body, callbacks)` with no sender identity parameter [8](#0-7) .

Consequently, any correspondent (paired) device can send a fabricated `new_shared_address` message naming a definition whose "signers" map claims arbitrary correspondent addresses (including addresses genuinely belonging to victims or other unrelated correspondents) as cosigners at chosen signing paths, as long as it also lists one of the receiver's own addresses somewhere in the definition to pass `determineIfIncludesMeAndRewriteDeviceAddress`. `addNewSharedAddress` then persists `shared_addresses` and `shared_address_signing_paths` rows binding those cosigner addresses to attacker-chosen `device_address` values [9](#0-8) . This is directly analogous to the RustFS bug class: a state-mutating handler reachable from a semi-trusted peer performs an authorization-relevant write (binding "who can co-sign/route funds for this shared address") while checking only generic message well-formedness, not that the specific party asserted in the payload actually originated it.

### Impact Explanation
Once a spoofed shared-address entry is registered, the victim's wallet software will treat the fabricated definition as a legitimate multisig wallet the victim participates in. Because `shared_address_signing_paths.device_address` controls where signing requests for that path are routed (`getSigner`/`ifRemote` in `wallet.js` sends the unsigned unit to `device_address` for signature [10](#0-9) ), an attacker-controlled device can be substituted as the routing target for a cosigner slot. This can be leveraged for social-engineering/UI-spoofing to trick a user into paying into or signing with a shared address whose cosigner metadata is falsified, and to pollute wallet state (`shared_addresses`, `shared_address_signing_paths`) with unauthorized entries that misrepresent contractual relationships between users, undermining trust assumptions in multisig payment setup — a fund-loss/fund-freezing risk consistent with the wallet/contract message handling category in scope.

### Likelihood Explanation
Any device that is a confirmed correspondent (paired) of the victim can trigger this: no special privilege beyond normal pairing is required, and `new_shared_address` is one of the standard justsaying subjects dispatched to `handleMessageFromHub`/`wallet.js`. The attacker only needs to know or guess a valid address string to insert into the `signers` map (addresses are public identifiers, easily obtained e.g. from prior chat/payment history), making exploitation straightforward once paired.

### Recommendation
Add sender-authorization to `handleNewSharedAddress`: pass `from_address` into the handler and verify that the `signerInfo.device_address` values claimed for third-party addresses in `body.signers` are consistent with what the sending device is authorized to assert (e.g., require that the sender's own address/device pairing already appears in `correspondent_devices`/`my_addresses` for the relevant path, or require the message to be co-signed/consistent with a prior sanctioned quorum initiation flow rather than accepted unilaterally), mirroring the pattern used in `arbiter_contract_shared`/`prosaic_contract_update` where `from_address` is cross-checked against DB-recorded ownership before mutating state.

### Proof of Concept
1. Device A is paired (correspondent) with Device B (victim).
2. Device A crafts a `new_shared_address` message with `body.definition` = an `["and"/"or", ...]` tree containing `["address", B_own_address]` (to pass the "includes me" check) and `["address", C_address]` at another path, where `C_address` is some third victim's real address.
3. Device A sets `body.signers` mapping the `C_address` path to `{address: C_address, device_address: A_device_address}` — i.e., claiming device A is authorized to sign on behalf of `C_address`.
4. Device B receives and processes the message via `handleNewSharedAddress`; all structural checks pass (hash match, signer/definition consistency, "includes me") since nothing verifies that `from_address` (A) is actually related to `C_address`.
5. `addNewSharedAddress` persists the shared address with A bound as the signing device for C's slot, and B's wallet now treats future signing requests for that path as legitimately routable to A — despite A never being authorized by C. [1](#0-0)

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
