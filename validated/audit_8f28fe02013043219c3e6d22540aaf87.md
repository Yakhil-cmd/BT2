### Title
Division-by-Zero Panic in `consolidatedNode.Split()` Crashes Block Finalization When Proposer Has Zero CN and CL Staking — (File: `kaiax/staking/staking_info.go`)

---

### Summary

In the Prague hardfork reward distribution path, `consolidatedNode.Split()` divides by `totalAmount = cnAmountBig + clAmountBig`. If the block proposer has both `StakingAmount = 0` (CN staking < 1 KAIA) and `CLStakingInfo.CLStakingAmount = 0` (CL staking < 1 KAIA) while having a non-nil `CLStakingInfo`, `totalAmount = 0`, causing a `big.Int.Div()` division-by-zero panic inside `FinalizeState()`, crashing every honest node that attempts to process the block.

---

### Finding Description

`consolidatedNode.Split()` in `kaiax/staking/staking_info.go` splits a reward amount between a CN staking contract and its CL (consensus liquidity) pool:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← PANICS when totalAmount == 0
    cnAmount := big.NewInt(0).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0) 

The only guard is `if c.CLStakingInfo == nil`. There is **no guard** for the case where `CLStakingInfo` is non-nil but both staking amounts are zero.

**How both amounts become zero:** Both `StakingAmount` and `CLStakingAmount` are stored in KAIA units, computed by integer-dividing the raw wei balance by `params.KAIA` (1 × 10¹⁸):

```go
stakingAmounts = append(stakingAmounts,
    new(big.Int).Div(amounts[i], big.NewInt(params.KAIA)).Uint64())
// ...
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i],
    big.NewInt(params.KAIA)).Uint64(),
``` [2](#0-1) 

Any balance between 0 and 999 999 999 999 999 999 wei (exclusive of 1 KAIA) rounds down to 0. A validator can legitimately have a CL pool registered in CLRegistry with < 1 KAIA staked and a CN staking contract also holding < 1 KAIA, producing `StakingAmount = 0` and `CLStakingAmount = 0` while `CLStakingInfo != nil`.

**Vulnerable call site — proposer reward split:** `Split()` is called unconditionally (no staking-amount guard) in `specWithProposerAndFunds()` and `specWithProposerAndFundsFlex()`:

```go
// specWithProposerAndFunds (line 628-633)
if cn.CLStakingInfo == nil {
    break
}
cnAmount, clAmount := cn.Split(proposer)   // ← PANICS if totalAmount == 0
``` [3](#0-2) 

The same pattern appears in `specWithProposerAndFundsFlex`: [4](#0-3) 

These functions are reached every block via:

```
FinalizeState()
  → getDeferredRewardFull()
    → getDeferredRewardFullKore() / getDeferredRewardFullFlex()
      → specWithProposerAndFunds() / specWithProposerAndFundsFlex()
        → cn.Split(proposer)   ← panic
``` [5](#0-4) 

The staking-reward helpers (`assignStakingRewards`, `assignStakingRewardsFlex`) also call `Split()`, but only after confirming `cnTotalStakingAmount > minStake`, so they are safe for the zero-staking case. The proposer-split path has no such guard. [6](#0-5) 

**Confirmed reachable state from existing test data:** The test suite already constructs a `consolidatedNode` with `StakingAmount = 0` (`a0`) and a non-nil `CLStakingInfo` with a positive `CLStakingAmount`:

```go
StakingAmounts: []uint64{a2, aM, aL, a0},   // a0 = 0
CLStakingInfos: CLStakingInfos{
    {CLNodeId: n4, CLPoolAddr: clPool2, CLStakingAmount: clStakingAmount2},
},
``` [7](#0-6) 

The test uses `CLStakingAmount = 3 000 000` (non-zero), so it does not trigger the panic. Replacing it with a CL pool holding < 1 KAIA (so `CLStakingAmount = 0`) while the proposer is that node would trigger the panic.

---

### Impact Explanation

`big.Int.Div()` panics at the Go runtime level when the divisor is zero. A panic inside `FinalizeState()` is unrecovered and crashes the node process. Every honest node that attempts to import or finalize the block containing this proposer will crash. The chain halts: no further blocks can be produced or accepted until the software is patched and nodes are restarted. This is an invalid state transition / consensus divergence on honest nodes, matching the allowed impact gate.

The corrupted value is the **proposer's reward distribution**: instead of being credited to the proposer's reward address, the entire block reward is lost to a crash, and the chain state is never updated.

---

### Likelihood Explanation

Preconditions:
1. **Prague hardfork active** — required for CL staking paths.
2. **Validator registers a CL pool in CLRegistry** — permissionless after Prague.
3. **CL pool holds < 1 KAIA** (e.g., 1 wei) → `CLStakingAmount = 0`.
4. **Validator's CN staking contract holds < 1 KAIA** → `StakingAmount = 0`.
5. **Validator becomes proposer** — guaranteed when all council members are below `minstake`, because the valset module then qualifies all council members:

> If no validator meets the minimum staking requirement, all council members are qualified. [8](#0-7) 

A single attacker who controls one validator seat and deliberately stakes < 1 KAIA in both their CN staking contract and CL pool can trigger this panic the moment they are selected as proposer. In a permissionless network this is a low-cost, one-time setup.

---

### Recommendation

Add a zero-total guard inside `Split()`:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount := new(big.Int).Add(cnAmountBig, clAmountBig)
    if totalAmount.Sign() == 0 {
        // Both CN and CL staking round to 0 KAIA; give all reward to CN.
        return amount, big.NewInt(0)
    }
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
```

Additionally, `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` should defensively skip the CL split when the proposer's total staking is zero, consistent with the staking-reward helpers.

---

### Proof of Concept

1. Activate Prague hardfork on a test network.
2. Register validator `V` in AddressBook; fund its CN staking contract with exactly 1 wei (< 1 KAIA → `StakingAmount = 0`).
3. Register `V`'s node ID in CLRegistry with a CL pool holding exactly 1 wei (< 1 KAIA → `CLStakingAmount = 0`).
4. Ensure all other validators also hold < 1 KAIA staked, so all council members are qualified and `V` can be selected as proposer.
5. Wait for `V` to be selected as proposer (deterministic via the weighted-random shuffle).
6. Observe that every node crashes with a Go runtime panic:
   ```
   panic: runtime error: integer divide by zero
   goroutine ... [running]:
   math/big.(*Int).Div(...)
       kaiax/staking/staking_info.go:181
   ```
   during `FinalizeState()`, halting the chain.

	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.

	proposer, stakers := config.Kip82Ratio.Split(validators)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.

	// For proposer rewards, see `specWithProposerAndFunds`.
	stakersAlloc, kip82Remainder := assignStakingRewards(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}
	spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
	return spec, nil
}
