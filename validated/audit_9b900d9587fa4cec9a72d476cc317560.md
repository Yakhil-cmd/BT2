### Title
Webhook Organization Trust Bypass via Unsigned `repository.full_name` Field When `webhook_secret` Is Unset - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which organization's GitHub App configuration (and therefore which `webhook_secret`) is used to authenticate an inbound webhook based on `repository.owner.login` (falling back to `organization.login`), while every event handler that actually determines *which repository/stack gets acted on* uses a completely different, independently-controlled payload field: `repository.full_name`. When the organization resolved for signature verification has no `webhook_secret` configured, verification is a no-op that accepts any payload, letting an attacker freely set `repository.full_name` to point at an unrelated repository/stack.

### Finding Description
`WebhooksController#verify_signature` computes the organization used to authenticate the request from the payload: [1](#0-0) 

That organization is passed into `Shipit.github(organization: repository_owner)`, whose `verify_webhook_signature` method short-circuits to `true` whenever no `webhook_secret` is configured for that organization: [2](#0-1) 

This is not a hypothetical config — the shipped sample configuration explicitly documents `webhook_secret` as an optional/nilable per-organization setting: [3](#0-2) 

Meanwhile, every default event `Handler` (used by `PushHandler`, `CheckSuiteHandler`, `StatusHandler`, etc.) resolves the actual target repository/stack from a **different** payload field, `repository.full_name`, entirely independent of the field used for signature-organization selection: [4](#0-3) 

`PushHandler#process` uses that resolved `stacks` scope to call `stack.sync_github` for any stack matching the (also attacker-controlled) branch name derived from `params.ref`: [5](#0-4) 

The security-relevant equality that should hold is:

`organization used to authenticate the webhook (repository.owner.login) == organization owning the repository that gets synced (repository.full_name)`

Because these are two independent, unauthenticated JSON fields in the same payload, and because verification is skipped entirely for organizations without a configured `webhook_secret`, an attacker only needs to know (or guess) that *any one* configured GitHub organization in the Shipit instance has no `webhook_secret` set. They can then submit a webhook whose `repository.owner.login` matches that unsecured organization (so `verify_signature` passes trivially) while `repository.full_name` names a stack belonging to an entirely different, secured organization. This breaks the trust binding between "the organization that authenticated the request" and "the repository that Shipit acts on."

### Impact Explanation
This crosses an authentication boundary: it lets an unprivileged party (anyone who can send an HTTP POST to the public `/webhooks` endpoint — no GitHub credentials, no Shipit session, no `ApiClient` token required) trigger `Stack#sync_github` for a repository/stack they do not control, as long as some organization in the deployment lacks a `webhook_secret`. `sync_github` drives Shipit's internal notion of the repository's HEAD and can feed into continuous-deployment triggering logic downstream (`trigger_continuous_delivery` / `schedule_continuous_delivery`), potentially causing an unauthorized deploy trigger for a stack that has continuous deployment enabled, using attacker-supplied `ref`/`after` values. This falls under "unauthenticated read of stack state" / "unauthorized deploy" impact categories.

### Likelihood Explanation
Multi-organization Shipit deployments are an explicit, documented use case (`config/secrets.development.shopify.yml` shows two orgs configured side by side). It is plausible for an operator to leave `webhook_secret` unset for a low-risk/internal organization while configuring it properly for a sensitive one — the code does nothing to prevent that weaker organization's identity from being used to author events about the sensitive organization's stacks. No credential, GitHub App private key, or session is required — only knowledge of one organization's handle that lacks a secret, which can often be inferred from public GitHub org membership in the Shipit configuration.

### Recommendation
Bind the field used to select the webhook-verification organization to the same field used by handlers to resolve the acted-upon repository (i.e., verify the signature using the organization derived from `repository.full_name`, or reject events where `repository.owner.login` does not match the owner segment of `repository.full_name`). Additionally, consider requiring `webhook_secret` to be present for all configured organizations in non-development environments, or reject webhooks whose declared organization/repository fields are inconsistent, regardless of whether a secret is configured.

### Proof of Concept
1. Configure two organizations in `secrets.yml`: `weak-org` (no `webhook_secret`) and `victim-org` (has `webhook_secret`), each with a stack — the victim's stack `victim-org/prod-app` has `continuous_deployment: true`.
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha-that-exists-on-victim-org/prod-app>",
  "repository": {
    "owner": { "login": "weak-org" },
    "full_name": "victim-org/prod-app"
  }
}
```
No `X-Hub-Signature` header (or an arbitrary one) is required.
3. `WebhooksController#verify_signature` resolves `repository_owner` = `"weak-org"` and calls `Shipit.github(organization: "weak-org").verify_webhook_signature(...)`, which returns `true` immediately because `weak-org` has no `webhook_secret`.
4. `PushHandler#process` resolves the target repository via `payload.dig('repository', 'full_name')` = `"victim-org/prod-app"`, finds the victim's stack, and calls `stack.sync_github(expected_head_sha: ...)`, all without ever validating a signature tied to `victim-org`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
