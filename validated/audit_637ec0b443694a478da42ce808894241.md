### Title
Debt-value overflow in accrual permanently freezes a market (no repay, withdraw, or liquidation) - (common/src/rates/scaling.rs)

### Summary
The pool accrues indexes on every mutating verb, and accrual recomputes the market's borrowed and supplied values via `scaled_to_original(scaled, index)`, which panics with `MathOverflow` when `scaled * index` no longer fits in `i128`. An unprivileged whale can put a market on this trajectory (large supply + borrow at sustained high utilization); once the RAY debt value crosses the `i128` ceiling, every subsequent accrual reverts, freezing all funds in that market forever. The borrow-index cap at `MAX_BORROW_INDEX_RAY` does not engage first because the value overflow occurs well before the index reaches its cap.

### Finding Description
`accrue_step` in `common/src/rates/simulate.rs:60-61` calls `scaled_to_original` on both `borrowed`/`borrow_index` and `supplied`/`supply_index` before computing utilization and the interest factor. `scaled_to_original` (`common/src/rates/scaling.rs:14-16`) performs `scaled * index / RAY` half-up; the exact `I256` widening only helps the intermediate product — the final `to_i128` still panics with `GenericError::MathOverflow` when the RAY result exceeds `i128::MAX` (`common/src/math/fp_core.rs:300-303`).

`global_sync`/`accrue_chunk` (`contracts/pool/src/interest.rs:20-53`) run this accrual at the head of every pool verb — supply, borrow, withdraw, repay, liquidation, flash paths, `update_indexes`. The borrow index is capped at `MAX_BORROW_INDEX_RAY` (10^36 raw), but a market can hit the value ceiling first: scaled debt shares times the index overflows `i128` when the debt's RAY value reaches ~1.7e38, i.e. index ~170x on a whale-sized position — long before the index cap. From then on, the panic is deterministic on every call that touches the market: `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `update_indexes` all accrue first and revert.

A repository test pins the behavior end-to-end: `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`) supplies ~10^27 units of an 18-decimal asset, borrows at 98% utilization, advances time, and observes `update_indexes`, `withdraw`, and `repay` all failing with `MATH_OVERFLOW`, with `borrow_index < MAX_BORROW_INDEX_RAY` — the index cap never engaged. `docs/reference/invariants.md` INV-IDX-01 acknowledges the gap: "Debt-value overflow can still revert accrual before that ceiling is reached."

### Impact Explanation
Permanent freezing of all supplier funds in the affected market and permanent protocol insolvency mechanics: borrowers can never repay, suppliers can never withdraw, liquidators cannot liquidate underwater accounts, and bad-debt cleanup (`clean_bad_debt`/`recapitalize`) also accrues first and reverts. The market is dead with all cash locked, matching the report's repeatable-crash DoS class but with the on-chain consequence of permanently locked user funds.

### Likelihood Explanation
Likelihood is low but nonzero. Triggering requires only the unprivileged `supply` and `borrow` entrypoints (no privileged action), but it needs (a) a whale-scale position — the RAY debt value must approach `i128::MAX` (~10^38 RAY, i.e. ~10^11 whole 18-decimal tokens of debt, reachable only for very high-supply assets), and (b) sustained high utilization for years so the borrow index compounds ~170x while caps/max-utilization are disabled or lifted. Time cannot be accelerated and caps bound positions in practice, so this is a tail-risk cliff rather than a quick attack; still, once the state exists it is irreversible — no entrypoint can unwind it. Medium severity: high impact, low likelihood, consistent with the 4.9 report class.

### Recommendation
Bound the debt value, not just the index: after computing `new_borrow_index` in `accrue_step`, clamp or saturate the effective index so `scaled_to_original(borrowed, borrow_index)` stays representable — e.g. cap `borrow_index` at `min(MAX_BORROW_INDEX_RAY, i128::MAX / borrowed)` so the product cannot overflow, or make `update_borrow_index` saturate and stop accruing borrower interest (already the documented behavior at the ceiling) instead of panicking. Equivalently, `global_sync` could catch the overflow by capping the index before recomputing utilization. Accrual must never panic on index math, since every exit path depends on it.

### Proof of Concept
The existing harness test demonstrates the freeze (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`):

1. Create an 18-decimal market on the XLM rate curve plus a collateral market; lift caps and disable max utilization.
2. Unprivileged `supply("BIG18", 10^9 * 10^18)` (BOB) and `borrow("BIG18", 98% of supply)` (ALICE, backed by COL collateral).
3. Advance time; call `update_indexes(&["BIG18"])` each year. Within the loop's bound, `scaled_to_original(borrowed, borrow_index)` overflows `i128` and panics with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
