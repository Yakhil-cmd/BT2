The premise doesn't hold up under review of the actual code and admission architecture.

`native_type_of` is a Move VM native function invoked during **transaction execution** (deep inside VM bytecode interpretation), not during the transaction **admission** stack (mempool, vm-validator, authenticator, prologue). It has no access to or influence over sequence number, sender, signer, chain-id, or expiry binding — those are validated in the transaction prologue and by `vm-validator`/mempool *before* any user Move code, let alone this native, is ever reached. [1](#0-0) 

The function's abort behavior is fully deterministic: it computes `type_tag` from `ty_args[0]` via `context.type_to_type_tag(&ty_args[0])?`, and if the resolved `TypeTag` is not a `Struct` variant, it always returns `SafeNativeError::abort_with_message(NFE_EXPECTED_STRUCT_TYPE_TAG, ...)`. [2](#0-1) 

This is a pure function of its generic type argument — given the same `TypeTag`, it aborts identically regardless of which sequence number, sender, or transaction wraps the call. There is no "gating" divergence across generic instantiation paths: any non-struct `TypeTag` (e.g. `u8`, `vector<u8>`, `address`) hits the same `else` branch unconditionally.

Sequence-number replay-resistance is enforced entirely upstream of this native, in the transaction prologue and mempool/vm-validator sequence checks, which are independent of what the Move bytecode/natives do during execution. A native aborting mid-execution does not "leave state permitting sequence-number replay" — Aptos's standard transaction lifecycle already handles execution failures (including aborts) by charging gas and incrementing the sequence number in the prologue/epilogue, which is unaffected by which native aborted or why. Nothing in `native_type_of` touches sender, signer set, fee payer, sequence, expiry, or chain-id binding, so it falls outside the required admission-boundary impact scope.

fn native_type_of(
    context: &mut SafeNativeContext,
    ty_args: &[Type],
    arguments: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(ty_args.len() == 1);
    debug_assert!(arguments.is_empty());

    context.charge(TYPE_INFO_TYPE_OF_BASE)?;

    let type_tag = context.type_to_type_tag(&ty_args[0])?;

    if context.eval_gas(TYPE_INFO_TYPE_OF_PER_BYTE_IN_STR) > 0.into() {
        let type_tag_str = type_tag.to_canonical_string();
        // Ideally, we would charge *before* the `type_to_type_tag()` and `type_tag.to_string()` calls above.
        // But there are other limits in place that prevent this native from being called with too much work.
        context
            .charge(TYPE_INFO_TYPE_OF_PER_BYTE_IN_STR * NumBytes::new(type_tag_str.len() as u64))?;
    }

    if let TypeTag::Struct(struct_tag) = type_tag {
        Ok(type_of_internal(&struct_tag).expect("type_of should never fail."))
    } else {
        Err(SafeNativeError::abort_with_message(
            super::status::NFE_EXPECTED_STRUCT_TYPE_TAG,
            format!(
                "Expected a struct type, found: {}",
                type_tag.to_short_string()
            ),
        ))
    }
}
