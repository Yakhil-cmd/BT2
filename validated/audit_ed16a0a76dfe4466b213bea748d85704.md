### Title
Missing cross-validation between the authenticating organization and the target repository in webhook processing allows cross-organization stack writes - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate a webhook against based on `repository_owner`, a value read out of the *same* untrusted JSON body it is about to authenticate [1](#0-0) . Once the signature is accepted, every webhook handler resolves the target `Stack`/`Repository` using a completely independent field of that body, `repository.full_name`, with no check that it belongs to the same organization that was used to validate the signature [2](#0-1) . This mirrors the Linea `TokenBridge.initialize` bug class: two related identifiers (`sourceChainId`/`targetChainId`, or here "organization that authenticated" vs. "repository that is written") are never checked for consistency, so binding `organization_that_authenticated == repository.full_name.owner` can be broken.

### Finding Description
In a multi-tenant Shipit deployment, `config/secrets.yml`'s `github:` key holds one GitHub App configuration (including `webhook_secret`) per organization [3](#0-2) . The org that owns/configured that GitHub App knows its own `webhook_secret`.

`WebhooksController#verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [4](#0-3) . `verify_webhook_signature` is a plain HMAC-SHA1 comparison over the raw body using the secret associated with `repository_owner` [5](#0-4) .

After signature verification succeeds, `Handler#stacks` resolves the affected stacks purely from `payload.dig('repository', 'full_name')`:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [2](#0-1) 

Nothing ties `repository.owner.login` (used to pick the HMAC secret) to `repository.full_name`'s owner (used to select which `Stack`s get mutated). Because an attacker who legitimately controls organization A's GitHub App knows organization A's `webhook_secret`, they can sign an arbitrary JSON body with that secret while setting:
- `repository.owner.login` = `"orgA"` (so `verify_signature` picks org A's secret and passes),
- `repository.full_name` = `"orgB/victim-repo"` (any other org/repo registered as a Shipit `Stack`).

This forged, validly-signed webhook is then dispatched to handlers such as `PushHandler`, which calls `stack.sync_github(expected_head_sha: params.after)` on every non-archived stack matching the forged branch [6](#0-5) , or `StatusHandler`, which writes commit statuses for any commit matching the forged `sha` regardless of which org it actually belongs to [7](#0-6) . Other handlers (`check_suite_handler.rb`, `pull_request/*`, `membership_handler.rb`) follow the same pattern of trusting `repository.full_name` without validating it against the org that authenticated the request.

### Impact Explanation
This breaks the trust binding "organization that authenticated == repository that is written," allowing an attacker who only controls one tenant organization's GitHub App/webhook secret to trigger unauthorized syncs, deploy-eligibility state changes (commit statuses driving deploy gating), and PR/membership mutations on any other organization's stacks hosted by the same Shipit instance — a cross-repository/cross-organization write, matching the report's "Critical" impact bucket (cross-repository writes / unauthorized operations resulting from unvalidated chain/identity fields).

### Likelihood Explanation
Requires the attacker to control (or have leaked) the `webhook_secret` for at least one organization already onboarded to the shared Shipit instance — a realistic scenario for any multi-tenant deployment where different teams/orgs each manage their own GitHub App credentials but share one Shipit backend. No Shipit session, API token, or repository write access on the *victim* org is needed; only the attacker's own org's webhook secret.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler#initialize`), after establishing which organization's secret validated the signature, assert that `repository.owner.login` (or `organization.login`) equals the owner portion of `repository.full_name` before any handler acts on the payload — analogous to validating `sourceChainId != targetChainId` and both non-zero in the referenced fix. Reject the webhook (422) if the two disagree.

### Proof of Concept
1. Configure two orgs in `secrets.yml`: `orgA` (attacker-controlled, secret known to attacker) and `orgB` (victim, has a `Stack` for `orgB/victim-repo`).
2. Attacker crafts a `push` event JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "deadbeef",
  "repository": { "owner": { "login": "orgA" }, "full_name": "orgB/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(orgA_webhook_secret, body)>` and POSTs to `/github/webhooks`.
4. `verify_signature` looks up `Shipit.github(organization: "orgA")` and successfully verifies the HMAC [1](#0-0) .
5. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("orgB/victim-repo")` and calls `sync_github` on org B's stack [2](#0-1) , [6](#0-5) , despite the signature only proving knowledge of org A's secret.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',

        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
