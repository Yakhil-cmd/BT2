### Title
Unconstrained iteration over unbounded access-key/gas-key collection during account deletion is not gas/compute metered - ([File: core/store/src/utils/mod.rs], [File: runtime/runtime/src/actions.rs])

### Summary
`action_delete_account` calls `compute_gas_key_balance_sum` and `remove_account`, both of which iterate over the full set of access keys (and gas-key nonces) stored under an account's trie prefix. The number of access keys an account can accumulate is not bounded by protocol — it grows with every `AddKeyAction`/gas-key creation the account owner is willing to pay storage for. The enumeration cost of this loop is not charged to gas/compute before or during the scan; only the nonce-removal portion is later billed via `storage_removes_compute`, and the `DeleteAccount` action itself carries a fixed base fee regardless of how many keys exist. This is the same bug class as the reported `unregisterPendingMarketOrder()` issue: a for-loop over a collection whose length is unconstrained, invoked from a single externally triggerable call.

### Finding Description
`compute_gas_key_balance_sum` walks every trie entry under `get_raw_prefix_for_access_keys(account_id)` to sum gas-key balances: [1](#0-0) 

This is invoked unconditionally at the start of `action_delete_account`, before any compute is charged for the traversal: [2](#0-1) 

`remove_account` then performs a second full trie scan over the same access-key prefix (plus a third scan over contract data) to build the list of keys to delete: [3](#0-2) 

Only after these scans complete does the code add compute cost, and even then only proportional to `gas_key_nonce_count` (i.e. gas-key nonces), not to the total number of regular access keys or gas keys enumerated: [4](#0-3) 

Nothing in `action_add_key` limits how many access keys (regular or gas keys) an account may hold — it only rejects re-adding an existing public key: [5](#0-4) 

An account owner who is willing to pay the storage cost for each key (a per-key storage deposit, not a per-key gas fee at delete time) can accumulate an arbitrarily large number of access keys/gas keys over many transactions. A single, fixed-fee `DeleteAccount` action later triggers an O(n) trie walk (three scans total) whose cost scales with that unbounded n but is not priced into the action's gas cost.

### Impact Explanation
Because the `DeleteAccount` action fee is fixed and the enumeration/removal loops over the access-key and contract-data prefixes are unbounded and largely unmetered, a chunk producer/validator processing this single receipt can be forced to spend CPU/trie-read time far exceeding what the charged gas represents. This is underpriced execution: the attacker pays the flat `DeleteAccount` fee but consumes resources proportional to however many keys they previously stored. At sufficient scale this can slow down or stall chunk application for that shard (a resource-exhaustion / chain-liveness risk), which matches the "node panic or unbounded resource use / chain stall" impact category.

### Likelihood Explanation
Reachable purely through unprivileged user transactions: repeatedly submit `AddKeyAction` (or gas-key creation) transactions to inflate the access-key count on one's own account, then submit a single `DeleteAccountAction`. No privileged or validator role is required. The practical limiting factor is the storage cost paid for accumulating keys, but this is a NEAR-denominated cost proportional to storage bytes, not gas proportional to the eventual deletion-time compute cost, so the two are decoupled — an account with enough balance (or many small keys with minimal `AccessKeyPermission::FunctionCall` allowances) can build up a large key count relatively cheaply per key while the single delete-time scan cost is undercharged.

### Recommendation
- Charge compute/gas for the enumeration itself (not just the nonce removal), proportional to the number of trie entries visited under the access-key and contract-data prefixes, before or as the scan proceeds in `remove_account` and `compute_gas_key_balance_sum`.
- Consider capping the number of access keys/gas keys an account may hold (enforced in `action_add_key`), similar to `Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE` which already caps deletable account storage size — extend that same style of bound to access-key count specifically, since currently only aggregate storage usage is checked, not key count.
- Alternatively, disallow `DeleteAccount` in one shot for accounts whose access-key count exceeds a safe threshold, mirroring the existing `DeleteAccountWithLargeState` rejection path.

### Proof of Concept
Conceptual reproduction (requires live-network or test-loop measurement, not verified in this pass):
1. From an unprivileged account, submit many transactions with `AddKeyAction` (or gas-key creation) to accumulate a very large number of access keys/gas keys on the account, paying only the per-key storage deposit.
2. Submit a single `DeleteAccountAction` transaction/receipt for that account.
3. Observe that `action_delete_account` → `compute_gas_key_balance_sum` and `remove_account` perform O(n) trie scans over all keys, while the actual gas/compute charged is the fixed `delete_account` action fee plus only nonce-removal compute — i.e., the bulk of the enumeration is effectively unmetered, and its wall-clock cost grows with attacker-controlled n.

Note: I was not able to execute this against a running node/test-loop to measure actual wall-clock divergence between charged gas and consumed compute; this assessment is based on static code review of the metering logic described above.

pub fn compute_gas_key_balance_sum(
    state_update: &TrieUpdate,
    account_id: &AccountId,
) -> Result<Balance, StorageError> {
    let mut total = Balance::ZERO;
    let lock = state_update.trie().lock_for_iter();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if nonce_index.is_some() {
            continue;
        }
        if let Some(balance) = get_access_key_by_handle(state_update, account_id, &key_handle)?
            .as_ref()
            .and_then(|access_key| access_key.gas_key_info())
            .map(|gas_key_info| gas_key_info.balance)
        {
            total = total.checked_add(balance).ok_or_else(|| {
                StorageError::StorageInconsistentState("gas key balance overflow".to_string())
            })?;
        }
    }
    Ok(total)
}

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }

pub(crate) fn action_add_key(
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    add_key: &AddKeyAction,
) -> Result<(), StorageError> {
    if get_access_key(state_update, account_id, &add_key.public_key)?.is_some() {
        result.result = Err(ActionErrorKind::AddKeyAlreadyExists {
            account_id: account_id.to_owned(),
            public_key: add_key.public_key.clone().into(),
        }
        .into());
        return Ok(());
    }

    let fee_config = &apply_state.config.fees;

    if let Some(gas_key_info) = add_key.access_key.gas_key_info() {
        add_gas_key(
            fee_config,
            state_update,
            account,
            account_id,
            &add_key.public_key,
            &add_key.access_key,
            gas_key_info,
            apply_state.block_height,
        )?;
    } else {
        add_regular_key(
            fee_config,
            state_update,
            account,
            account_id,
            &add_key.public_key,
            &add_key.access_key,
            apply_state.block_height,
        )?;
    }

    Ok(())
}
