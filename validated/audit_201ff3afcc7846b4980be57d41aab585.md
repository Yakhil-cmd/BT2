### Title
Webhook signature verification is keyed to `repository.owner.login` while all event handlers route on the unrelated `repository.full_name` field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate an inbound GitHub webhook using `repository_owner`, computed from `params.dig('repository', 'owner', 'login')` (or `organization.login`). [1](#0-0) [2](#0-1)  Every event handler, however, resolves the target repository/stack via the completely independent `repository.full_name` field. [3](#0-2)  Because Shipit supports multiple configured GitHub organizations, each with its own optional `webhook_secret` (explicitly documented as optional and frequently left `nil` in example configs), any org configured without a secret makes `verify_webhook_signature` return `true` unconditionally. [4](#0-3) [5](#0-4) 

### Finding Description
The binding that should hold is: **the organization whose signature authenticates the request == the organization that owns the repository the handler acts on**. This binding is broken:

- `verify_signature` derives the signing organization solely from `repository.owner.login` (or `organization.login`) and looks up that org's `GitHubApp` to validate `X-Hub-Signature` against the *entire raw body*. [6](#0-5) 
- Handlers (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, all `PullRequest` handlers, `Handler#stacks`) never consult `repository.owner.login` at all — they resolve the repository purely from `repository.full_name` via `Repository.from_github_repo_name`. [3](#0-2) [7](#0-6) [8](#0-7) 
- `GitHubApp#verify_webhook_signature` trivially returns `true` when no `webhook_secret` is configured for the org resolved from `repository.owner.login`. [4](#0-3) 

Because the two fields (`repository.owner.login` and `repository.full_name`) are never cross-checked, an attacker only needs to know (or control) one organization in a multi-org Shipit deployment that has no `webhook_secret` configured. They can then submit an unsigned request to `/webhooks` with `X-Github-Event` set to any handled event, `repository.owner.login` (or top-level `organization.login`) set to the secret-less org (making `verify_signature` pass unconditionally), while setting `repository.full_name` (and any other payload fields the handler consumes, e.g. `sha`, `state`, `ref`, `pull_request`) to point at a *different, secured* organization's tracked repository/stack. The signature check never inspects `repository.full_name`, so it has no bearing on which stack is actually mutated.

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" boundary explicitly called out as in-scope. Concretely reachable, unauthenticated (no Shipit session, API token, or GitHub credentials needed) impacts include:
- `StatusHandler`/`CheckSuiteHandler`: forging a passing CI status/check-suite result for an arbitrary commit on a stack the attacker does not control, which can satisfy `ci.require`/blocking-status gating used to allow deploys/merges — an unauthorized-deploy-class impact.
- `PushHandler`: forcing `stack.sync_github(expected_head_sha:)` on arbitrary tracked stacks, affecting deploy state tracking.
- `PullRequest` handlers: creating/archiving/unarchiving review stacks for repositories unrelated to the attacker-controlled organization.

This satisfies the "unauthorized deploy" / authorization-bypass class of impact defined in scope.

### Likelihood Explanation
Likelihood is high in any deployment using the multi-organization GitHub App config schema (`Shipit.github(organization:)` / `github_app_config`) where at least one configured organization omits `webhook_secret` — a state the project's own example configs (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`) show as normal/expected ("webhook secret (optional)"). No credentials, sessions, or GitHub access are required; the attacker just needs to know that org's login name (often public) and craft a raw HTTP POST.

### Recommendation
Bind signature verification and repository resolution to the same trust boundary:
- Require `webhook_secret` to be present for every configured organization (fail closed instead of `return true unless webhook_secret`).
- After verifying the signature for `repository_owner`, additionally assert that `repository.full_name`'s owner segment matches the verified `repository_owner` (or `organization.login`) before dispatching to handlers, rejecting mismatches with `422`.

### Proof of Concept
Given a `secrets.yml` with two orgs, `SecretlessOrg` (no `webhook_secret`) and `TrustedOrg` (tracked stack `TrustedOrg/app`):

```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=anything-or-omitted

{
  "sha": "<victim commit sha in TrustedOrg/app>",
  "state": "success",
  "target_url": "https://ci.example.com/fake",
  "context": "required-ci-check",
  "repository": {
    "owner": { "login": "SecretlessOrg" },
    "full_name": "TrustedOrg/app"
  }
}
```

- `verify_signature` computes `repository_owner = "SecretlessOrg"`, loads that org's `GitHubApp`, and since `webhook_secret` is blank, `verify_webhook_signature` returns `true` regardless of the (missing/garbage) `X-Hub-Signature`. [1](#0-0) [4](#0-3) 
- `StatusHandler` (subclass of `Handler`) resolves the target stack/commit via `repository.full_name = "TrustedOrg/app"`, unrelated to the verified `SecretlessOrg`, and creates a passing status for the specified commit. [3](#0-2)

```ruby
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
```
