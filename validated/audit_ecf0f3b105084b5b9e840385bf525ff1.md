### Title
Unbounded recursion in `Definition.replaceInTemplate()` allows a paired device to crash a wallet node via a deeply nested shared-address definition template - ([File: definition.js])

### Summary
`Definition.replaceInTemplate()` in `definition.js` recursively walks an attacker-supplied `arrDefinitionTemplate`/`params` structure with no depth limit, exactly mirroring the `JSONTaggedDecoder.decode_obj()` bug class (CWE-674, unbounded recursion on untrusted nested data). This function is invoked on address-definition templates received directly from a paired device, before any of the depth/complexity checks that `Definition.validateDefinition()` normally performs.

### Finding Description
The vulnerable recursive helper is `replaceInVar()` inside `replaceInTemplate()`: [1](#0-0) 

For array/object branches it recurses over every element/key with **no depth counter and no call to `string_utils.isTooDeeplyNestedOrHasTooManyNodes`**, unlike other recursive validators in this codebase that were hardened against this exact issue (e.g. `aa_validation.js`'s `validate()` with `MAX_DEPTH`, or `formula/validation.js`'s `evaluate()` with `depth > 100`): [2](#0-1) [3](#0-2) 

`replaceInTemplate()` is reached via `validateAddressDefinitionTemplate()`, which is called when a paired device sends a `create_new_shared_address` message containing an `address_definition_template`: [4](#0-3) 

Note that `replaceInTemplate()` (line 504) runs **before** `Definition.validateDefinition()` (line 511), so none of `validateDefinition`'s complexity/op-count safeguards apply to this initial pass — the recursion in `replaceInVar` is fully unguarded. The same unguarded call also occurs in `wallet_defined_by_keys.js`'s `validateWalletDefinitionTemplate()` and in the definition-template evaluation path used when accepting an already-approved shared address (`approvePendingSharedAddress()`): [5](#0-4) [6](#0-5) 

A paired device (a peer explicitly reachable in scope per the rules) can send a `create_new_shared_address` (or, for wallets, the equivalent wallet-definition-template) message whose `address_definition_template` is a deeply nested array/object (e.g., thousands of nested arrays). `replaceInVar` will recurse once per nesting level with no bound, exhausting the JS call stack and throwing an unrecoverable `RangeError: Maximum call stack size exceeded`, crashing the receiving wallet/node process — identical impact class to the NLTK `RecursionError` DoS described in the report.

### Impact Explanation
An unhandled stack-overflow exception in Node.js is fatal and terminates the process. A malicious (or compromised) paired device can remotely crash a victim's wallet/full node simply by pairing (or via an existing correspondent relationship) and sending one crafted `create_new_shared_address` message, with no requirement for a stable output, valid signatures, or any prior payment. This is reachable purely through the wallet/device-message handling surface explicitly listed as in-scope, causing denial of service to the victim node (unable to process further payments/units while down or restarting).

### Likelihood Explanation
Likelihood is high for any node that accepts device pairing/correspondent messages from third parties (a normal, expected operating mode for hub-less wallet pairing): the attack requires only sending a single crafted JSON message with deep array nesting; no cryptographic material, fees, or prior on-chain state is needed, and the vulnerable code path executes unconditionally on receipt, prior to any complexity/depth validation.

### Recommendation
Add an explicit recursion-depth (and/or node-count) guard to `replaceInVar()` in `definition.js`, e.g. threading a `depth` parameter and rejecting with `NoVarException`/error once `depth` exceeds a small constant (consistent with `MAX_DEPTH` used elsewhere), or run `string_utils.isTooDeeplyNestedOrHasTooManyNodes(arrTemplate)` on `arrDefinitionTemplate`/`params` before calling `replaceInTemplate()` in `wallet_defined_by_addresses.js` and `wallet_defined_by_keys.js`.

### Proof of Concept
```js
// Simulate a paired device sending a crafted "create_new_shared_address" message
// with a deeply nested address_definition_template.
const Definition = require('./definition.js');

const depth = 50000; // exceeds default V8 stack depth
let arrTemplate = 1;
for (let i = 0; i < depth; i++)
    arrTemplate = [arrTemplate]; // deeply nested array

// This call is reached from wallet_defined_by_addresses.js:
// validateAddressDefinitionTemplate(arrDefinitionTemplate, from_address, handleResult)
// -> Definition.replaceInTemplate(arrDefinitionTemplate, params)
Definition.replaceInTemplate(arrTemplate, {}); 
// Throws: RangeError: Maximum call stack size exceeded
// -> crashes the Node.js process handling the paired-device message
```

function replaceInTemplate(arrTemplate, params){
	function replaceInVar(x){
		switch (typeof x){
			case 'number':
			case 'boolean':
				return x;
			case 'string':
				// searching for pattern "$name"
				if (x.charAt(0) !== '$')
					return x;
				var name = x.substring(1);
				if (!ValidationUtils.hasOwnProperty(params, name))
					throw new NoVarException("variable "+name+" not specified, template "+JSON.stringify(arrTemplate)+", params "+JSON.stringify(params));
				return params[name]; // may change type if params[name] is not a string
			case 'object':
				if (Array.isArray(x))
					for (var i=0; i<x.length; i++)
						x[i] = replaceInVar(x[i]);
				else
					for (var key in x)
						assignField(x, key, replaceInVar(x[key]));
				return x;
			default:
				throw Error("unknown type");
		}
	}
	return replaceInVar(_.cloneDeep(arrTemplate));
}
