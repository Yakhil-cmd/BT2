### Title
Cross-tenant Status forgery via unscoped `sha` lookup in `StatusHandler#process` enables unauthorized merge - (File: `app/models/shipit/webhooks/handlers/status_handler.rb`)

### Summary
`StatusHandler#process` looks up commits by `sha` alone, across the entire `commits` table, with no check that the commit's stack belongs to the organization that authenticated the webhook. On a multi-org Shipit instance, an attacker who owns any configured GitHub organization can post a `status` webhook, correctly signed with their own org's webhook secret, that attaches a forged `success` `Status` to a commit belonging to a victim stack in a different organization, whenever the shas coincide (trivially achievable when a fork shares commit objects with the upstream victim repo). That forged status is then read by `MergeRequest#all_status_checks_passed?` and can cause `ProcessMergeRequestsJob` to merge a PR that should have been rejected.

### Finding Description
The broken binding is: `repository_owner_that_signed_the_webhook == organization_owning(commit.stack)`. The code never enforces this.

- `WebhooksController#verify_signature` only checks that the payload is validly signed by *some* known organization's webhook secret, selected via `repository_owner` from the payload itself: `Shipit.github(organization: repository_owner)` at `app/controllers/shipit/webhooks_controller.rb:24-30`, `59-62`. It does not check that `repository_owner` matches the owner of any commit the handler will subsequently mutate.
- `StatusHandler#process` then does:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [1](#0-0) 
This queries `Commit` globally by `sha`, with no `stack_id`/repository scoping tying it back to the org that was authenticated in `verify_signature`. The `commits` table index is `(stack_id, sha)`, not a unique global index on `sha`, per `db/migrate/20170524104615_index_commits_on_stack_id_and_sha.rb`, confirming the same `sha` can legitimately exist for different stacks (e.g., shared commit objects across a fork and its upstream, both onboarded to the same multi-org Shipit instance).
- `Status.replicate_from_github!` writes the status with `commit.stack_id` (the victim stack's id), not any id derived from the webhook's own `repository`: `app/models/shipit/status.rb:24-33`.
- `Commit#create_status_from_github!` -> `statuses.replicate_from_github!(stack_id, github_status)` at `app/models/shipit/commit.rb:165-169`.
- `MergeRequest#all_status_checks_passed?` reads exactly this data: `StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec).success?` at `app/models/shipit/merge_request.rb:193-197`, where `head.statuses_and_check_runs` is `statuses + check_runs` (`app/models/shipit/commit.rb:144-146`), unfiltered by which org created them.
- `MergeRequest#reject_unless_mergeable!` (`app/models/shipit/merge_request.rb:155-162`) and `#merge!` (`164-191`) consume this forged status, and `#merge!` calls `stack.github_api.merge_pull_request` using the *victim* stack's GitHub App credentials.

Attacker's exact request: a `status` webhook POST to `/webhooks` with `X-Github-Event: status`, `X-Hub-Signature` computed with the attacker's own org's `webhook_secret` (which they legitimately possess if their org is one of the orgs configured on the shared Shipit instance), body `{"sha": "<shared_commit_sha>", "state": "success", "repository": {"owner": {"login": "attacker-org"}}}`. `verify_signature` passes because it only validates against `attacker-org`'s secret, and the handler applies the status to any `Commit` row matching that sha regardless of owning stack/org.

Existing guards fail here because:
- `verify_signature` authenticates "a webhook signed by *an* org," not "the org owning the specific resource being mutated."
- `StatusHandler` has no `params.repository`/stack cross-check (unlike, e.g., a repository-scoped lookup would be `stack.commits.where(sha:)`).
- Model validations on `Status`/`Commit` do not enforce sha uniqueness across stacks.

### Impact Explanation
This allows a payload authenticated for one repository/organization to mutate another organization's stack/commit data (a CI status), directly matching the "Critical" category: "a payload for one repository mutating another's stack, commit, task or team" and ultimately "an unauthorized deploy, rollback or merge." The forged status feeds `MergeRequest#all_status_checks_passed?`, letting `ProcessMergeRequestsJob` merge a PR into `victim/prod` via `stack.github_api.merge_pull_request` using Shipit's own GitHub credentials, even though the PR's real CI state was `pending`/`failing`/`missing`. This is repeatable against any victim stack whose head commit sha is shared with a repo the attacker owns (forks routinely share commit objects), and the blast radius spans every tenant stack hosted on the same multi-org Shipit instance.

### Likelihood Explanation
Requires: (1) the Shipit deployment configured for multiple GitHub organizations (a documented, supported configuration in `docs/setup.md` "Using Multiple Github Applications" and exercised in `test/dummy/config/secrets_double_github_app.yml`), (2) the attacker controlling at least one of those configured orgs/repos (e.g., they were onboarded as a tenant, or fork-based collision), (3) `victim_stack.allows_merges?` true and the merge request `pending`. Attacker cost is a single unauthenticated HTTP POST with a correctly-signed (using their own legitimate secret) payload — no victim secrets needed. This is directly repeatable per matching sha.

### Recommendation
Scope `StatusHandler#process` (and equivalent handlers) to only touch commits belonging to stacks whose repository matches the authenticated `repository_owner`/`repository.full_name` from the webhook payload, e.g. `Commit.joins(:stack).where(sha: params.sha, shipit_stacks: { ... repository matching payload ... })`, rather than a bare `Commit.where(sha: params.sha)`. More generally, `WebhooksController#verify_signature` should pass down the authenticated repository identity so every handler enforces `commit.stack.repository == payload.repository` before mutating state.

### Proof of Concept
Minitest plan (`test/models/webhooks/handlers/status_handler_test.rb` or similar):
1. Set up two stacks in different orgs via `secrets_double_github_app.yml`-style config: `victim_stack` (org `OrgOne`, `merge_queue_enabled: true`), `attacker_stack` (org `OrgTwo`).
2. Create `victim_commit` on `victim_stack` with `sha = "deadbeef..."` and no passing status (so `all_status_checks_passed?` is false, `any_status_checks_missing?` true).
3. Create a pending `MergeRequest` on `victim_stack` whose `head` is `victim_commit`.
4. Post a `status` webhook where `params.sha == victim_commit.sha`, `state: "success"`, and `repository.owner.login == "OrgTwo"`, signed with `OrgTwo`'s webhook secret (valid signature for `OrgTwo`).
5. Assert `Shipit::StatusHandler.new(params).process` (or the full controller `post :create`) creates a `Status` on `victim_commit` with `state: "success"` — i.e. `assert_difference 'victim_commit.statuses.count', 1`.
6. Assert both sides of the binding: `victim_commit.stack.repository.owner` (`"OrgOne"`) `!= "OrgTwo"` (the authenticated org), yet the write succeeded.
7. Assert `merge_request.reload.all_status_checks_passed?` is now `true` despite no CI having run for `OrgOne`.
8. Call `ProcessMergeRequestsJob.perform_now(victim_stack)` and assert `merge_request.merge!` is invoked / `stack.github_api.merge_pull_request` expectation is satisfied, with no live GitHub call, confirming the unauthorized merge path. [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6)

    def reject_unless_mergeable!
      return reject!('merge_conflict') if merge_conflict?
      return reject!('ci_missing') if any_status_checks_missing?
      return reject!('ci_failing') if any_status_checks_failed?
      return reject!('requires_rebase') if stale?

      false
    end

    def merge!
      raise InvalidTransition unless pending?

      raise NotReady if not_mergeable_yet?

      stack.github_api.merge_pull_request(
        stack.github_repo_name,
        number,
        merge_message,
        sha: head.sha,
        commit_message: 'Merged by Shipit',
        merge_method: stack.merge_method
      )
      begin
        if stack.github_api.pull_requests(stack.github_repo_name, base: branch).empty?
          stack.github_api.delete_branch(stack.github_repo_name, branch)
        end
      rescue Octokit::UnprocessableEntity
        # branch was already deleted somehow
      end
      complete!
      true
    rescue Octokit::MethodNotAllowed # merge conflict
      reject!('merge_conflict')
      false
    rescue Octokit::Conflict # shas didn't match, PR was updated.
      raise NotReady
    end

    def all_status_checks_passed?
      return false unless head

      StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec).success?
    end

    def any_status_checks_failed?
      status = StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec)
      status.failure? || status.error?
    end

    def any_status_checks_missing?
      StatusChecker.new(head, head.statuses_and_check_runs, stack.cached_deploy_spec).missing?
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
