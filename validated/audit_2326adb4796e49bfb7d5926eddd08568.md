### Title
Proposer Can Suppress Candidate Failure Reports via Empty VRank, Corrupting CFS-Based Validator Ejection — (`kaiax/vrank/impl/consensus.go`)

### Summary
`VerifyHeader` unconditionally accepts `len(header.VRank) == 0` for any non-epoch-start block. A malicious block proposer can therefore submit an empty VRank even when candidates genuinely failed to respond, suppressing their CFS score increments. The byzantine filter in `generateCFSFromCPMatrix` only discards the highest reporter scores (protecting against inflation), leaving score suppression entirely unguarded.

### Finding Description
In `VerifyHeader` (`consensus.go` lines 59-61), the check for non-epoch-start blocks is:

```go
if len(header.VRank) == 0 {
    return nil
}
```

No validation is performed against the actual candidate failure data. A proposer who observed all candidates time out can simply set `header.VRank = nil` and the block passes verification.

Downstream, `cfReport` (`getter.go` lines 51-53) returns an empty slice when `header.VRank` is empty. `applyBlocksForCPMatrix` (`scoring.go` lines 159-193) iterates over `cfReport` to build the CP matrix; an empty report means no `cpMatrix.Increment` calls are made for that block. The byzantine filter (`scoring.go` lines 209-226) then sorts per-candidate reporter scores and removes the top `F = ProposerCount()/3` entries — it removes the **highest** scores to guard against inflation, but a suppressing proposer contributes 0, which is the **lowest** possible score and is never removed.

### Impact Explanation
A malicious proposer can persistently suppress CFS increments for failing candidates across every block they propose. Because the byzantine filter is one-sided (inflation-only), even a single malicious proposer reduces the effective CFS score below what honest reporting would produce. If the suppressed score stays below the ejection threshold, genuinely failing candidates are never ejected, remain in the active validator set, and continue degrading consensus liveness. This constitutes durable corruption of the CFS-based validator ejection state and validator privilege escalation over protected chain state.

### Likelihood Explanation
Any single validator who is selected as block proposer can execute this attack without any collusion. The proposer simply omits the VRank field. No cryptographic break, key compromise, or majority collusion is required. The attack is silent — honest nodes accept the block because `VerifyHeader` returns `nil`.

### Recommendation
`VerifyHeader` for non-epoch-start blocks should not treat empty VRank as unconditionally valid. Options:
1. **Require non-empty VRank when candidates exist:** If `GetCandTesting(number-1)` returns a non-empty list, reject `header.VRank == nil` (or require the proposer to prove no failures via an explicit empty-report encoding, e.g., `0xc0`).
2. **Distinguish "no candidates" from "no failures":** Use the RLP-encoded empty list (`0xc0`) to mean "candidates exist but none failed," and `nil` to mean "no candidates." `VerifyHeader` can then enforce that `nil` is only valid when `GetCandTesting` returns empty.
3. **Extend the byzantine filter to handle suppression:** Apply a symmetric lower-bound filter (discard the bottom F scores per candidate), though this is a larger protocol change.

### Proof of Concept
1. Set up a consensus test with N candidates registered in `GetCandTesting`.
2. Simulate all candidates timing out (no `VRankCandidate` messages arrive within `candidateMsgTimeoutMs`).
3. Have the proposer build a block with `header.VRank = nil` instead of calling `encodeCandidateFailureVRank`.
4. Call `VerifyHeader` on the block — it returns `nil` (accepted).
5. Insert the block; call `GetCFS(blockNum)`.
6. Assert all candidate CFS scores are 0, even though all candidates failed.
7. Repeat for enough blocks that honest reporting would have triggered ejection; assert no ejection occurs.

func (v *VRankModule) applyBlocksForCPMatrix(start, end uint64, seed vrank.CPMatrix) (vrank.CPMatrix, error) {
	cpMatrix := seed.Clone()
	for blockNum := start; blockNum <= end; blockNum++ {
		header := v.Chain.GetHeaderByNumber(blockNum)
		if header == nil {
			return nil, vrank.ErrHeaderNotFound
		}

		cfReport, err := v.cfReport(blockNum)
		if err != nil {
			return nil, err
		}

		roundByte, err := v.RoundReader.Round(header)
		if err != nil {
			return nil, err
		}
		round := uint64(roundByte)
		reporter, err := v.Valset.GetProposer(blockNum, round)
		if err != nil {
			return nil, err
		}
		// Record the proposer in the CP matrix even when this block has no cfReport,
		// so ProposerCount() reflects every proposer seen in the epoch.
		cpMatrix.AddProposer(reporter)

		for _, candidate := range cfReport {
			if _, ok := cpMatrix[candidate]; !ok {
				logger.Warn("cfReport contains address not in candidates list; skipping", "blockNum", blockNum, "candidate", candidate.Hex())
				continue
			}
			cpMatrix.Increment(candidate, reporter)
		}
	}
	return cpMatrix, nil

// byzantineFilter computes CFS scores from pre-aggregated per-candidate failure data.
//
// cpMatrix[candidate][reporter] is the number of times reporter included candidate
// in cfReport over the epoch. F is the number of highest reporter totals to discard
// per candidate, defending against up to F byzantine reporters that may inflate scores.
func byzantineFilter(cpMatrix vrank.CPMatrix, F int) map[common.Address]uint64 {
	cfs := make(map[common.Address]uint64)
	for cand, reporterToScore := range cpMatrix {
		scores := slices.Collect(maps.Values(reporterToScore))
		slices.Sort(scores)
		if F >= len(scores) {
			// since `scores` contain non-zero scores only, F >= len(scores) can happen, in which case all scores are discarded.
			scores = nil
		} else {
			scores = scores[:len(scores)-F]
		}
		var sum uint64
		for _, t := range scores {
			sum += t
		}
		cfs[cand] = sum
	}
	return cfs
