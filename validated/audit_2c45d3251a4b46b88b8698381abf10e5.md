### Title
Issue comments printed raw to stdout without escape-sequence sanitization in `--comments` non-TTY mode - ([File: pkg/cmd/issue/view/view.go])

### Summary
When `gh issue view <n> --comments` is run with stdout piped (non-TTY), `viewRun` writes `prShared.RawCommentList(issue.Comments, ...)` directly to `opts.IO.Out` via `fmt.Fprint` with no escape-sequence detection or sanitization, unlike the explicit `iostreams.ContainsEscapeSequence`/`SetContentSanitization` guard used in `gist view`'s raw-output path. An attacker who posts a GitHub issue comment containing raw ANSI/OSC escape sequences can have that content passed through unmodified into any script or terminal consuming `gh`'s non-TTY output.

### Finding Description
In `pkg/cmd/issue/view/view.go`, `viewRun` at line 189-192 does: [1](#0-0) 
which calls `prShared.RawCommentList` [2](#0-1)  — this simply concatenates `comment.Content()` (the raw GraphQL `body` field, fully attacker-controlled by anyone who can comment on a public issue) with no filtering, and `formatRawComment` embeds it verbatim via `fmt.Fprintln(&b, comment.Content())` [3](#0-2) .

Contrast this with `pkg/cmd/gist/view/view.go`, where the raw-dump path explicitly treats untrusted content with `iostreams.NewUntrusted`, checks `iostreams.ContainsEscapeSequence(content.RawBytes())` when not a TTY, and refuses to print unless `--allow-escape-sequences` is passed, otherwise calling `opts.IO.SetContentSanitization(false)` before writing to `ContentOut` [4](#0-3) . `pkg/iostreams/content.go` defines this exact primitive (`ContainsEscapeSequence`, checking for the `0x1B` ESC byte) and a broader `CopyGuardedContent` helper used elsewhere in the codebase for untrusted byte streams [5](#0-4) .

`viewRun` in issue view never calls this check for the `--comments` raw path. It also does not go through `ContentOut` (the sanitizing writer used for gist raw content) — it writes to the plain `opts.IO.Out`. This is an inconsistency versus the codebase's own established output-safety pattern for untrusted external text reaching a piped consumer.

### Impact Explanation
When a victim runs `gh issue view <n> --comments` with output piped into a script, log file, or another terminal-rendering tool (a common automation pattern), an attacker-controlled comment body containing raw ANSI/OSC escape sequences is written through unmodified. Depending on the downstream consumer, this can corrupt terminal state, spoof text in logs, or manipulate terminal-rendering tools that don't otherwise sanitize input (e.g., overwriting previous lines, hiding text, or in more advanced OSC-based cases, manipulating clipboard/prompt in vulnerable terminal emulators). This matches an escape-sequence/terminal injection impact class — lower severity than direct code execution, but a genuine consistency gap with the sanitization guarantee `gh` provides elsewhere (gist view raw dumps).

### Likelihood Explanation
Fully attacker-reachable with no privilege beyond posting a public comment on any issue the victim later views with `--comments` in a non-interactive/piped context. Feasible and repeatable: any GitHub user can comment on public issues, and `--comments` combined with output redirection is a common scripting pattern (e.g., `gh issue view 123 --comments > log.txt` or feeding to `less`/other tools via a pipeline that itself isn't a TTY).

### Recommendation
Apply the same guard used in `gist view` to the raw comment output path in `viewRun`: before writing `prShared.RawCommentList(...)` to `opts.IO.Out` in the non-TTY branch, check `iostreams.ContainsEscapeSequence` on the assembled content (or sanitize/strip ESC bytes) and either refuse with an explanatory error (optionally gated behind a `--allow-escape-sequences`-style flag) or write through a sanitizing writer equivalent to `ContentOut`. The same review should be extended to `printRawIssuePreview`'s `issue.Body` output, `pr view --comments`, and any other place `RawCommentList`/raw issue-body text reaches non-TTY stdout, since the same helper is shared across issue/PR view raw paths.

func formatRawComment(comment Comment) string {
	if comment.IsHidden() {
		return ""
	}
	var b strings.Builder
	fmt.Fprintf(&b, "author:\t%s\n", comment.AuthorLogin())
	fmt.Fprintf(&b, "association:\t%s\n", strings.ToLower(comment.Association()))
	fmt.Fprintf(&b, "edited:\t%t\n", comment.IsEdited())
	fmt.Fprintf(&b, "status:\t%s\n", formatRawCommentStatus(comment.Status()))
	fmt.Fprintln(&b, "--")
	fmt.Fprintln(&b, comment.Content())
	fmt.Fprintln(&b, "--")
	return b.String()
}

// ContainsEscapeSequence reports whether b contains an ANSI escape byte (0x1B),
// which can manipulate a terminal when printed.
func ContainsEscapeSequence(b []byte) bool {
	return bytes.IndexByte(b, 0x1B) >= 0
}
