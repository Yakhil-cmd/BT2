### Title
Scaled-debt × borrow-index multiplication overflows `i128` before the index cap engages, permanently freezing a whale market - ([File: common/src/rates/index.rs])

### Summary
Analogous to SA001 (an integer overflow in validation that panics the node), the pool's interest accrual computes `borrowed_scaled * borrow_index` in `i128` and panics with `GenericError::MathOverflow` when the product exceeds `i128::MAX`. The `MAX_BORROW_INDEX_RAY` ceiling is checked on the index itself, not on the resulting value, so on a sufficiently large market (high-decimals token, whale-scale scaled supply/debt) the value overflow is reached while the index is still far below its cap. Because accrual runs first in every state-changing entrypoint, the market then freezes permanently: no repay, withdraw, borrow, or liquidation can ever execute again. A single unprivileged address can create the preconditions via `supply`/`borrow`, and any unprivileged address triggers the freeze via `update_indexes`.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs:20-33` runs on every pool verb and calls `accrue_step`, which internally calls `calculate_supplier_rewards` in `common/src/rates/index.rs:73-89`. That function computes:

- `old_total_debt = borrowed.mul(env, old_borrow_index)` (line 80)
- `new_total_debt = borrowed.mul(env, new_borrow_index)` (line 81)

`Ray::mul` routes to `fp_core::mul_div_half_up`, which widens to `I256` for the intermediate product but panics with `GenericError::MathOverflow` if the quotient does not fit back into `i128` (`common/src/math/fp_core.rs`, per the overflow-panicking contract documented at lines 177-201 and tested in `common/tests/math/fp_core.rs`). The same overflow exists in `scaled_to_original` (`common/src/rates/scaling.rs:14-16`) via `calculate_utilization` (`contracts/pool/src/cache/scale.rs:23`).

The intended guard is `MAX_BORROW_INDEX_RAY` (`common/src/constants/pool.rs:19`, ≈1e36 raw ray), applied in `update_borrow_index` (`common/src/rates/index.rs:13-19`). But it clamps the *index*, not the *debt value*. The value ceiling is `i128::MAX ≈ 1.7e38`, i.e. roughly 170× the raw-ray value of a 1e9-token position at 18 decimals. The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`) demonstrates exactly this: after sustained ~98% utilization on the XLM rate curve, `update_indexes` panics with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and the same panic then hits `withdraw` and `repay` since they accrue first. The test also notes the safe bound documented in `docs/reference/formulas.md` is incorrect, so this is not a documented/ADR-accepted limitation.

### Impact Explanation
Permanent freezing of funds. Once `borrowed_scaled * borrow_index > i128::MAX`, every accrual panics, and every user-facing verb (`supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `recapitalize`, etc.) calls `global_sync` first. No path can skip accrual or reduce the scaled debt before the multiplication, so suppliers' principal and any remaining collateral/borrowed tokens in that pool book are locked forever, and bad debt can never be liquidated. This matches the accepted "permanent freezing of funds" / "contract unable to operate" impact classes.

### Likelihood Explanation
Medium-low. Reaching the cliff requires a very large scaled position (on the order of 1e9 whole units of a high-decimals asset) plus years of compounding at high utilization on the steep segment of the rate curve — all achievable by a single unprivileged whale account through ordinary `supply`/`borrow` calls, with no privileged input. Once the state exists, any unprivileged caller (including the attacker) triggers the freeze by calling `update_indexes`. The capital and time cost is high, but the failure is deterministic, irreversible, and not gated by any admin action.

### Recommendation
Make the value computation overflow-safe instead of relying on the index cap:

- In `calculate_supplier_rewards` and `scaled_to_original`, compute `borrowed * index` via the saturating/`I256` path (as `mul_div_floor_saturating` already does for caps) and clamp the resulting debt value at `i128::MAX` rather than panicking, or
- Clamp the effective index to `min(index, i128::MAX / borrowed_scaled)` inside accrual before unscaling, so `MAX_BORROW_INDEX_RAY`-style bounding actually bounds the value domain the code operates in.

Add a regression test asserting accrual/withdraw/repay still succeed when `borrowed_scaled * index` exceeds `i128::MAX`.

### Proof of Concept
Already encoded in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`: supply ~1e9 units of an 18-decimal asset, borrow ~98% of it on the XLM rate curve with caps lifted, advance time until index growth pushes `borrowed_scaled * borrow_index` past `i128::MAX` (well before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`), then:

- `update_indexes` → `Error(Contract, #33)` (`GenericError::MathOverflow`)
- `withdraw` → same panic
- `repay` → same panic

pub fn calculate_supplier_rewards(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    new_borrow_index: Ray,
    old_borrow_index: Ray,
) -> (Ray, Ray) {
    let old_total_debt = borrowed.mul(env, old_borrow_index);
    let new_total_debt = borrowed.mul(env, new_borrow_index);

    let accrued_interest = new_total_debt.checked_sub(env, old_total_debt);

    let protocol_fee = params.reserve_factor.apply_to_ray(env, accrued_interest);
    let supplier_rewards = accrued_interest.checked_sub(env, protocol_fee);

    (supplier_rewards, protocol_fee)
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub fn mul_div_floor_saturating(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    div_floor_i256(
        env,
        &x256.mul(&y256),
        &d256,
        quotient_is_nonnegative(x, y, d),
    )
    .to_i128()
    .unwrap_or(if quotient_is_negative(x, y, d) {
        i128::MIN
    } else {
        i128::MAX
    })
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
