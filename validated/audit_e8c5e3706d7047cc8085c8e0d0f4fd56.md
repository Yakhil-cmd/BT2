### Title
Missing `return` after malformed-payload error causes uncaught crash in `handleSavedPrivatePayments()` - (File: network.js)

### Summary
`network.js`'s `handleSavedPrivatePayments()` fails to `return` after catching a hashing error on a private-payment element, so execution falls through and still calls `privatePayment.validateAndSavePrivatePaymentChain()` on a payload that was just proven to be malformed. This is analogous to the NFSD bug (CVE-2024-53217): a lookup/parse step signals "not usable" (NULL session / thrown hash error) but the caller doesn't bail out and dereferences/uses the unusable object anyway, leading to an unhandled exception and process crash.

### Finding Description
In `handleSavedPrivatePayments()`, each row from `unhandled_private_payments` (populated by a private-payment counterparty via `network.handleOnlinePrivatePayment` / `wallet.js` `handlePrivatePaymentChains`) is parsed and hashed: [1](#0-0) 

```
var validateAndSave = function(){
    var objHeadPrivateElement = arrPrivateElements[0];
    try {
        var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
    }
    catch (e) {
        console.log("getBase64Hash failed for private element", objHeadPrivateElement.payload, e);
        if (ws)
            sendResult(ws, {private_payment_in_unit: row.unit, result: 'error', error: e.toString()});
        deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
    }
    var key = 'private_payment_validated-'+objHeadPrivateElement.unit+'-'+json_payload_hash+'-'+row.output_index;
    privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, { ... });
```

`getBase64Hash(..., true)` calls `string_utils.getJsonSourceString`, which `throw`s on inputs that are not "well-formed" for hashing purposes (e.g. `NaN`/`Infinity`, empty arrays/objects, `undefined` object values): [2](#0-1) 

The `catch` block only logs, notifies the peer, and deletes the queued row — it does **not** `return`. Execution continues past the `catch` and calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, ...)` on the very payload that was just shown to be structurally invalid enough to blow up serialization. Downstream code in `private_payment.js`, `divisible_asset.js`, and `indivisible_asset.js` assumes the payload has valid shapes (numeric amounts, well-formed arrays/objects, no `undefined` fields) and does not have the same defensive `try/catch`. For example `divisible_asset.js` directly does `parseInt(output.amount)` and array iteration on `payload.outputs`/`payload.inputs` without re-validating for the pathological values that caused the earlier hash failure, and `console.log("saving private chain "+JSON.stringify(arrPrivateElements))` in `indivisible_asset.js` operates on the same tainted structure.

The `arrPrivateElements` array originates from `JSON.parse(row.json)`, which itself was stored from an attacker-supplied `body.chains` sent over a device message (`wallet.js` `handlePrivatePaymentChains`, reachable from any paired/correspondent device or hub-relayed private-payment counterparty) — this is fully attacker controlled, unprivileged content.

### Impact Explanation
Because the fall-through path calls further processing (which is not guarded by a matching try/catch further down the stack) on a value already known to be malformed, this can raise an uncaught `TypeError`/`Error` deep in async database-driven code (e.g., a `throw Error(...)` guard inside `validateAndSavePrivatePaymentChain`/`indivisible_asset.js`/`divisible_asset.js`, or a native error from further hashing/serialization). An uncaught exception in Node.js crashes the process (unless a global handler exists), producing a remote, unauthenticated (from a device/private-payment counterparty perspective) denial-of-service against a wallet/hub node — mirroring the "availability-only" impact profile of CVE-2024-53217 (C:N/I:N/A:H).

### Likelihood Explanation
Any device correspondent or private-payment counterparty can send a `private_payment` message with a `payload` engineered to fail `getJsonSourceString` (e.g., containing an object whose only own-enumerable value is `undefined`, or a numeric field set to `NaN`/`Infinity`, or an empty nested object). This requires no special privilege beyond being a paired device / private payment counterparty, matching the reachability constraints of the task. The trigger condition (an already-malformed payload) is easy to construct deterministically since the validation logic that normally rejects malformed inputs runs only after this faulty short-circuit.

### Recommendation
Add an explicit `return` inside the `catch` block in `handleSavedPrivatePayments()` (`network.js`, around line 2476) immediately after `deleteHandledPrivateChain(...)`, so that a hashing failure aborts processing of that chain instead of falling through to `validateAndSavePrivatePaymentChain`. Additionally, consider wrapping the call to `privatePayment.validateAndSavePrivatePaymentChain` in a `try/catch` (or ensuring all reachable code paths that operate on attacker-supplied JSON payloads validate structure before doing arithmetic/serialization) as defense in depth.

### Proof of Concept
1. As a paired device / private-payment counterparty, send a `private_payment_chains` message to the victim wallet (via `wallet.js` `handlePrivatePaymentChains`) whose head element's `payload` contains a value that makes `getJsonSourceString` throw, e.g.:
```
payload: { asset: "<valid-asset-hash>", denomination: 1, inputs: [{...}], outputs: [{ address: "...", amount: NaN, blinding: "..." }] }
```
2. For a light client (`conf.bLight`), this is queued via `savePrivatePayment` into `unhandled_private_payments` (`network.js`, `handleOnlinePrivatePayment`).
3. When `handleSavedPrivatePayments()` later processes this row, `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` throws inside `getJsonSourceString` (`invalid number: NaN`).
4. The `catch` block logs/deletes the row but does not `return`; execution proceeds to call `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, ...)` on the same malformed `arrPrivateElements`.
5. Depending on exact malformed fields chosen, this second pass can hit an unguarded `throw Error(...)` (e.g., in `indivisible_asset.js`/`divisible_asset.js`/`private_payment.js`) outside of any protecting `try/catch`, propagating as an uncaught exception and crashing the node process.

*(Note: I could not execute this against a live node to confirm the exact crash line reached in every code path — the specific downstream `throw` that gets hit depends on which malformed field is chosen and whether `conf.bLight` branch or full-node branch is taken. The core, confirmed root-cause defect — the missing `return` allowing use of a value proven invalid — is verified directly in the cited source.)*

```javascript
function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
}
```
