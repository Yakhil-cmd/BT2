### Title
Webhook signature verification selects a GitHub organization from an attacker-controlled payload field that is decoupled from the repository field the event handlers actually act on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub organization (and thus which `webhook_secret` to verify the HMAC against) using `repository_owner`, which is read straight from the untrusted JSON body (`params.dig('repository','owner','login')`). The event handlers that subsequently run, however, resolve the target `Stack`/`Repository` using a *different* field of the very same body: `payload.dig('repository','full_name')`. Because these two fields are never cross-checked, the "organization whose secret authenticated the request" and the "repository that the handler actually writes to" are two independent, attacker-controlled bindings.

### Finding Description
`verify_signature` derives the signing organization purely from payload content: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` loads that organization's own config (including its own, independent `webhook_secret`) via `github_app_config`: [3](#0-2) 

Signature verification is a no-op if that particular organization has no `webhook_secret` configured — a case the code explicitly handles as "valid": [4](#0-3) 

If verification passes, the *entire* untrusted payload is handed to the event handlers unmodified: [5](#0-4) 

The base `Handler` class, and concrete handlers such as `PushHandler`, resolve the `Stack` to mutate using `repository.full_name` — a field that was never part of the signature check: [6](#0-5) [7](#0-6) 

`PushHandler#process` then calls `stack.sync_github(expected_head_sha:)`, which enqueues `GithubSyncJob` and appends whatever commits it fetches from GitHub for that stack's repository into Shipit's tracked history: [8](#0-7) 

**The binding that should hold:** `organization used to select webhook_secret for verification == organization that owns the repository the handler resolves and mutates`.
**What actually happens:** the controller derives the verifying organization from `repository.owner.login`, while the handler derives the acted-upon repository from `repository.full_name`. Nothing forces these to refer to the same tenant. In a multi-organization Shipit deployment (`Shipit.github_organizations`, `github_app_config`), if *any* configured organization has a blank/unset `webhook_secret` (a state the code explicitly treats as valid, see `verify_webhook_signature`), an unauthenticated attacker can:
1. Set `repository.owner.login` (and/or `organization.login`) to that unsecured organization, so `verify_signature` fetches its `GitHubApp` and `verify_webhook_signature` returns `true` unconditionally — no signature/secret needed at all.
2. Set `repository.full_name` (and `ref`/`after` for a `push` event) to point at a *different*, secured organization's repository that is tracked by Shipit.

The request passes verification (step 1 needed no secret), and `PushHandler` then syncs/appends attacker-chosen commit SHAs into that other organization's `Stack`, entirely bypassing the intended per-organization HMAC boundary.

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" binding from a webhook whose signature never covered the repository actually mutated. The result is a cross-tenant, cross-repository write into Shipit's commit/stack state (via `GithubSyncJob#append_commit` -> `stack.commits.create_from_github!`) performed by an attacker with no credentials for the targeted organization — matching the Critical "cross-repository writes" / "unauthorized deploy" impact category, since downstream automatic deploy triggers can act on the injected commit history.

### Likelihood Explanation
Exploitability depends entirely on the deployment having at least one GitHub organization configured with a blank `webhook_secret` in a multi-org setup — a state the code (`lib/shipit/github_app.rb#verify_webhook_signature`) explicitly treats as legitimate ("no secret configured means always trust"), rather than an undocumented misuse. Given that state, the exploit requires zero credentials: a plain unauthenticated POST to the public `/webhooks` endpoint. Likelihood is therefore config-dependent but requires no privileged capability from the attacker once that precondition holds.

### Recommendation
Bind organization identity to the same field used for repository resolution: derive the verifying organization strictly from `repository.full_name`'s owner segment (or from an explicit route/subdomain per organization), and reject any payload where `repository.owner.login`/`organization.login` disagrees with the owner segment of `repository.full_name`. Additionally, treat an organization with no `webhook_secret` configured as failing closed rather than as automatically verified, or require `webhook_secret` presence for every organization in a multi-org configuration.

### Proof of Concept
1. Configure Shipit with two GitHub organizations: `secured-org` (has `webhook_secret`) and `open-org` (no `webhook_secret` set) — both valid, documented per-org configs.
2. Attacker (no credentials) sends:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything
{
  "repository": { "owner": { "login": "open-org" }, "full_name": "secured-org/target-repo" },
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>"
}
```
3. `verify_signature` loads `Shipit.github(organization: 'open-org')`, whose `verify_webhook_signature` returns `true` unconditionally (no secret configured) — `app/controllers/shipit/webhooks_controller.rb:24-30`, `lib/shipit/github_app.rb:76-83`.
4. `create` dispatches to `PushHandler`, which resolves `stacks` via `payload.dig('repository','full_name')` = `secured-org/target-repo` — `app/models/shipit/webhooks/handlers/handler.rb:32-38` — and calls `stack.sync_github(expected_head_sha: 'attacker-chosen-sha')`, enqueuing `GithubSyncJob` against `secured-org`'s stack despite the signature having been verified (trivially) against `open-org`'s (absent) secret.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
```
