### Title
Attacker-supplied route pool executes arbitrary code under the caller's signed auth tree, draining wallet tokens unrelated to the swap - (File: contracts/controller/src/strategies/swap.rs)

### Summary
The typosquat advisory's bug class is "a dependency the user did not vet executes attacker code in a trusted context." The on-chain analog is the strategy-route path: `swap_collateral`/`swap_debt`/`repay_debt_with_collateral`/`multiply` forward a caller-supplied `swap_xdr` route to the swap-aggregator, which calls whatever `pool` address the payload names with no allowlist. A malicious pool contract on the call stack sits below the caller's `require_auth` and can invoke `token.transfer(caller, attacker, …)`; Soroban simulation records that call as a child of the caller's own authorization entry, so a wallet that signs the simulated tree authorizes the theft.

### Finding Description
`swap_tokens` authorizes exactly one input `transfer` from the controller to the router, then calls `router.execute_strategy(controller, amount_in, swap)` with the caller-provided route bytes [1](#0-0) . The venue dispatcher invokes `hop.pool` directly — e.g. Sushi calls `token0`/`token1`/`get_oracle_hints`/`swap` on the payload-named address [2](#0-1)  — and the threat model states the router "keeps no allowlist" of pool or token addresses, so "a route can put third-party code on the call stack below the caller's authorization" and "the loss is then the caller's wallet, not the routed amount" [3](#0-2) . The harness test proves both halves: in recording mode a `RogueHopPool.swap` that calls `token.transfer(alice, attacker, WALLET_BALANCE)` is recorded as a child invocation of Alice's `swap_collateral` auth entry, and in enforcing mode signing that poisoned tree transfers her full balance of a token the protocol never listed [4](#0-3) [5](#0-4) .

### Impact Explanation
Theft of user funds beyond the routed amount: any token in the victim's wallet — including assets the lending protocol never touched — can be transferred out inside the same transaction the victim believed was a collateral swap. Neither the route's `min_out` nor the controller's post-swap solvency gate bounds the loss, since the stolen transfer is a sibling auth child, not part of the measured swap [6](#0-5) .

### Likelihood Explanation
Exploitation requires the victim to sign an authorization tree containing the rogue child entry. This is realistic: `simulateTransaction` auto-populates the full tree, and clients that re-sign the simulated envelope without decoding the route (the norm for wallet UX) will sign the poisoned tree. The attacker only needs to get a crafted `swap_xdr` in front of the victim — e.g., via a compromised or malicious quote source, exactly the "unvetted dependency" shape of the advisory. Reachable by any unprivileged address via `controller.swap_collateral(account, …, route)`.

### Recommendation
Enforce a governance-managed allowlist of pool addresses (and route token addresses) in the router's `dispatch_hop`, or constrain hops to venue-registered pools verified on-chain. Absent an allowlist, the protocol should document hard that clients must decode `ops`/`assets` and reject any signed auth tree with children beyond the single input `transfer`, and surface this check in `verifyRouteBytes`.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a working PoC: `RogueHopPool::swap` calls `token::Client::new(&env, &wallet_token).transfer(&victim, &to, &amount)` [7](#0-6) ; `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` asserts the recorded tree nests the theft under Alice's `swap_collateral` entry and that `wallet(alice) == 0`, `wallet(attacker) == WALLET_BALANCE` [8](#0-7) ; `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` confirms the signed poisoned tree executes the drain [9](#0-8) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
