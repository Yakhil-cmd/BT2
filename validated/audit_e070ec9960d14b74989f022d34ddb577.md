### Title
Infinite recursion via cyclic shared-address definitions in `readAllControlAddresses` - ([File: wallet_defined_by_addresses.js])

### Summary
`readAllControlAddresses` in `wallet_defined_by_addresses.js` recursively walks the `shared_address_signing_paths` table to resolve the full set of "control addresses" (signers) of a multi-signature shared address, but performs no cycle detection or recursion-depth limit. [1](#0-0) 
This is analogous to CVE-2019-25040, where Unbound's `dname_pkt_copy` followed compressed-name pointers without loop protection, allowing an attacker-controlled, self-referential structure to drive the function into an infinite loop.

### Finding Description
A shared address is created and persisted via `handleNewSharedAddress`, which is invoked directly on data received from a paired device (the `new_shared_address` device message). [2](#0-1) 
The function validates that `body.address` matches the c-hash of `body.definition`, that signer addresses referenced in the definition are syntactically valid, and that `Definition.validateDefinition` accepts the definition, but it never checks whether the "control" addresses in `assocSignersByPath`/`shared_address_signing_paths` form a cycle back to the shared address itself (or to a chain of other shared addresses that eventually points back). [3](#0-2) 
Because a shared-address definition's leaf "address" nodes can point to *other* shared addresses (which are themselves resolved recursively via `shared_address_signing_paths`), a peer/paired device can register two (or more) shared addresses S1 and S2 such that S1's signing path lists S2 as a control address, and S2's signing path lists S1 back. When `readAllControlAddresses(conn, [S1], ...)` is later called (e.g. to determine which addresses/devices control funds of a shared address, used by `wallet.js` and for forwarding private chains), each recursive call queries `shared_address_signing_paths` for the current address set, discovers the other cyclic address, and recurses again with an ever-growing but ultimately looping working set — the function never terminates because there is no depth counter, no "visited" set, and no cap analogous to `MAX_DEPTH`/`isTooDeeplyNestedOrHasTooManyNodes` used elsewhere in the codebase for similar recursive definition-walking (`aa_validation.js`'s `MAX_DEPTH` guard, `formula/validation.js`'s depth>100 check, `string_utils.js`'s `isTooDeeplyNestedOrHasTooManyNodes`). [4](#0-3) [5](#0-4) 
By contrast, `definition.js`'s own definition evaluators (`validateDefinition`/`validateAuthentifiers`) re-resolve nested "address" references each time and rely on complexity/op counters (`MAX_COMPLEXITY`, `MAX_OPS`) to bound cost, but `readAllControlAddresses` has none of these protections despite performing the same kind of unbounded, attacker-influenced graph traversal driven purely by database rows a remote device can insert. [6](#0-5) 

### Impact Explanation
An unprivileged paired device can cause the victim wallet process to enter an unbounded recursive query loop whenever `readAllControlAddresses` is invoked for the crafted shared addresses (used for determining shared-address control lists, e.g. from `wallet.js`, and for forwarding of private payment chains to cosigners). This blocks the Node.js event loop and the wallet's database connection with repeated queries that never resolve, preventing the wallet from processing further units/messages — a denial-of-service against the wallet/node's ability to confirm or forward payments involving that shared address, consistent with the "network unable to confirm new units" acceptance criterion for this address's transactions.

### Likelihood Explanation
Likelihood is high for any node that accepts `new_shared_address` messages from correspondent/paired devices (a standard multi-sig wallet workflow), since the attacker only needs to be a paired device (not privileged) sending two ordinary-looking shared-address definitions that reference each other as co-signers — no invalid signatures, malformed JSON, or protocol violations are required, and `handleNewSharedAddress`'s existing checks (hash match, valid address format, `Definition.validateDefinition`) do not check for such cross-address cycles.

### Recommendation
Add a visited-address set (or explicit recursion depth cap) to `readAllControlAddresses` so that any address already processed in the current resolution chain is not re-queried/re-expanded, mirroring the depth/complexity guards already used in `aa_validation.js` and `definition.js`. Additionally, consider rejecting shared-address definitions at creation time (`handleNewSharedAddress`/`addNewSharedAddress`) whose "address" signer references form a cycle among shared addresses.

### Proof of Concept
1. Attacker's paired device (Device B) sends a `new_shared_address` message defining shared address S1 = `["r of set", {set:[["address","<S2>"], ["sig", ...]], required:1}]`, listing S2 as one signer/control address.
2. Attacker also sends a `new_shared_address` for S2 whose definition references S1 back as one of its signer/control addresses (`["address","<S1>"]`).
3. Both pass `handleNewSharedAddress`'s validation (hash matches, addresses are syntactically valid, `Definition.validateDefinition` succeeds because each definition alone is valid and unresolved nested addresses are allowed via `bAllowUnresolvedInnerDefinitions`).
4. Once both are stored in `shared_addresses`/`shared_address_signing_paths`, any call such as `readAllControlAddresses(db, ['S1'], cb)` (triggered from `wallet.js` or private-chain forwarding logic) recurses S1→S2→S1→S2… indefinitely, since the function has no cycle/depth guard.

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function readAllControlAddresses(conn, arrAddresses, handleLists){
	conn = conn || db;
	conn.query(
		"SELECT DISTINCT address, shared_address_signing_paths.device_address, (correspondent_devices.device_address IS NOT NULL) AS have_correspondent \n\
		FROM shared_address_signing_paths LEFT JOIN correspondent_devices USING(device_address) WHERE shared_address IN(?)", 
		[arrAddresses], 
		function(rows){
			if (rows.length === 0)
				return handleLists([], []);
			var arrControlAddresses = rows.map(function(row){ return row.address; });
			var arrControlDeviceAddresses = rows.filter(function(row){ return row.have_correspondent; }).map(function(row){ return row.device_address; });
			readAllControlAddresses(conn, arrControlAddresses, function(arrControlAddresses2, arrControlDeviceAddresses2){
				handleLists(_.union(arrControlAddresses, arrControlAddresses2), _.union(arrControlDeviceAddresses, arrControlDeviceAddresses2));
			});
		}
	);
}

function isTooDeeplyNestedOrHasTooManyNodes(obj, depthLimit = 100, nodesLimit = 10000) {
	let nodeCount = 0;

	function check(variable, depth){
		if (depth > depthLimit || nodeCount > nodesLimit)
			return true;
		if (variable === null || typeof variable !== "object")
			return false;
		if (Array.isArray(variable)) {
			nodeCount += variable.length;
			for (let v of variable)
				if (check(v, depth + 1))
					return true;
		}
		else {
			nodeCount += Object.keys(variable).length;
			for (let key in variable)
				if (check(variable[key], depth + 1))
					return true;
		}
		return false;
	}

	return check(obj, 1);
}
