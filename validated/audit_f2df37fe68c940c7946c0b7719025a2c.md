### Title
Non-Payable `_to` Contract Permanently Locks Bridged KLAY and Freezes Bridge Handle-Nonce — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

In `handleKLAYTransfer`, the KLAY delivery is performed via a low-level `call.value()` to the user-supplied `_to` address. If `_to` is a contract that has no `receive` or `fallback` function, the call returns `false`, the subsequent `require` reverts the entire transaction, and every state mutation that preceded the transfer (nonce bookkeeping, handled-request hash, `_updateHandleNonce`) is rolled back. Because there is no mechanism to skip or override a stuck nonce, `lowerHandleNonce` is permanently frozen at that position, the bridged KLAY is permanently locked in the source-chain bridge, and the off-chain recovery daemon enters an infinite retry loop.

---

### Finding Description

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` executes the following sequence:

```
_setHandledRequestTxHash(_requestTxHash);          // line 81
handleNoncesToBlockNums[_requestedNonce] = ...;    // line 83
_updateHandleNonce(_requestedNonce);               // line 84
emit HandleValueTransfer(...);                     // line 86-96
(bool ok, ) = _to.call.value(_value)("");          // line 98
require(ok, "handleKLAYTransfer: transfer failed");// line 99
``` [1](#0-0) 

If `_to` is a contract without a payable `receive`/`fallback`, the `call` at line 98 returns `ok = false`. The `require` at line 99 reverts the transaction, unwinding **all** state changes from lines 81–84. Consequently:

- `handleNoncesToBlockNums[_requestedNonce]` is never written.
- `_updateHandleNonce` is never committed.

`_updateHandleNonce` advances `lowerHandleNonce` by scanning consecutive entries in `handleNoncesToBlockNums`:

```solidity
for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
    recoveryBlockNumber = handleNoncesToBlockNums[i];
    ...
}
lowerHandleNonce = i;
``` [2](#0-1) 

Because `handleNoncesToBlockNums[N]` is never set for the stuck nonce N, the loop halts at N on every future call, and `lowerHandleNonce` is permanently frozen at N. There is no `skipNonce`, `forceHandle`, or admin escape hatch in the contract.

The `_to` address is fully user-controlled: it is supplied on the source chain via `requestKLAYTransfer` / the fallback, relayed verbatim by the off-chain bridge manager, and passed directly into `handleKLAYTransfer` by operators. [3](#0-2) 

The off-chain recovery daemon (`vt_recovery.go`) reads `RecoveryBlockNumber` and `LowerHandleNonce` from the contract to determine which events to replay: [4](#0-3) 

With `lowerHandleNonce` frozen at N and `recoveryBlockNumber` frozen at the block preceding N, the daemon perpetually re-submits the same failing handle transaction, consuming operator gas indefinitely.

---

### Impact Explanation

| Asset / State | Effect |
|---|---|
| Bridged KLAY (source chain) | Permanently locked in the source-chain bridge; no withdrawal path exists |
| `lowerHandleNonce` (destination bridge) | Permanently frozen at nonce N; cannot be advanced without a successful handle |
| `recoveryBlockNumber` | Frozen; recovery daemon replays from the same block forever |
| Subsequent bridge transfers | Operators can still submit nonces > N (the `_lowerHandleNonceCheck` only requires `lowerHandleNonce <= _requestedNonce`), but the nonce window (`lowerHandleNonce + 200`) eventually fills, blocking all new handles | [5](#0-4) [6](#0-5) 

---

### Likelihood Explanation

The attack requires only a single `requestKLAYTransfer` call on the source chain, directing KLAY to any contract address on the destination chain that lacks a payable receive function (e.g., a multisig, a DAO treasury, or a deliberately deployed no-receive contract). The attacker forfeits the bridged KLAY but permanently disrupts the bridge. No special privilege is required; any user with enough KLAY to cover the bridge fee can execute this.

---

### Recommendation

Replace the push-transfer pattern with a pull-payment (withdrawal) pattern: instead of calling `_to.call.value(_value)("")` inside `handleKLAYTransfer`, credit the amount to a per-address balance mapping and let `_to` withdraw it separately. This decouples delivery failure from nonce progression. Alternatively, add an owner-callable `skipNonce(uint64 nonce)` function that writes a sentinel value into `handleNoncesToBlockNums[nonce]` so `_updateHandleNonce` can advance past it, and separately escrow the stuck KLAY for manual recovery.

---

### Proof of Concept

```solidity
// 1. Deploy on destination chain — no receive function
contract NoReceive {}

// 2. On source chain — attacker locks KLAY and poisons nonce N
bridge_A.requestKLAYTransfer{value: 1 ether + fee}(
    address(noReceive_on_B), 1 ether, ""
);
// requestNonce on bridge_A is now N+1; KLAY is locked in bridge_A

// 3. Bridge operators call on destination chain
bridge_B.handleKLAYTransfer(txHash, attacker, noReceive_on_B, 1 ether, N, blockNum, "");
// → noReceive_on_B.call.value(1 ether)("") returns false
// → require(ok) reverts
// → handleNoncesToBlockNums[N] is never written
// → lowerHandleNonce stays at N forever

// 4. Verify freeze
assert(bridge_B.lowerHandleNonce() == N);          // stuck
assert(bridge_B.recoveryBlockNumber() == blockN-1); // stuck

// 5. Recovery daemon loops forever re-submitting the same failing tx,
//    burning operator gas with no progress.

    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }
