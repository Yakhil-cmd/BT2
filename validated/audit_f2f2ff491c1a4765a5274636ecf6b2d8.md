### Title
Unvalidated `omniauth.origin` used as post-authentication redirect target enables open redirect / forced OAuth completion - ([File: app/controllers/shipit/github_authentication_controller.rb])

### Summary
`GithubAuthenticationController#callback` builds `return_url` directly from `request.env['omniauth.origin']` with no host allow‑listing, then calls `redirect_to(return_url)` after setting `session[:user_id]` and `session[:authenticated] = true`. Because OmniAuth persists the `origin` request parameter across the OAuth round trip, an attacker can craft a link to `/github/auth/github?origin=https://evil.example` that, once the target completes GitHub sign-in, redirects the freshly authenticated browser to an attacker-controlled site.

### Finding Description
The binding assumed safe is: `return_url used by redirect_to == a URL scoped to the Shipit host that issued the OAuth request`. In code, `return_url = request.env['omniauth.origin'] || root_path` [1](#0-0)  takes the raw `omniauth.origin` value with no scheme/host validation, and it is immediately used in `redirect_to(return_url)` after `session[:authenticated] = true` [2](#0-1) . The `origin` value is populated from the initiating request's `origin` query parameter (standard OmniAuth behavior for the `omniauth_authorize` phase) and is not constrained to the Shipit host anywhere in this codebase — `Authentication#force_github_authentication` only ever sets it to `request.original_url` for its own internal redirects [3](#0-2) , but nothing prevents a third party from supplying an arbitrary `origin` value on the initial authorize request themselves. No guard such as a host allow-list, `only_path`, or same-origin check exists between the OmniAuth callback and the final `redirect_to`. The existing test suite only checks that sign-in succeeds and `session[:authenticated]` is set, never that the redirect target is constrained [4](#0-3) .

Exploit flow: attacker sends a victim a link `https://shipit.example/github/auth/github?origin=https://evil.example/phish`. Victim, already trusting the Shipit domain, completes GitHub OAuth. `omniauth.auth` populates, `session[:user_id]`/`session[:authenticated]` are set on the legitimate Shipit session, and the browser is then redirected to `https://evil.example/phish`. This is a forced-OAuth-completion / open-redirect chain: the attacker fully controls the post-login navigation, which can be used to phish the now-authenticated victim, chain to further CSRF-style actions on `evil.example`, or capture referrer information from the Shipit callback URL.

### Impact Explanation
No secrets or cookies are placed in the redirect URL itself (session data stays in the cookie, not the URL), so this is not a direct session-token exfiltration. However, it does allow an attacker to force completion of the OAuth login flow and control where the victim's browser lands immediately after authentication, matching the "session fixation / forced OAuth completion" High-severity category explicitly listed in scope. This is exploitable against any user who clicks the crafted authorize link, and is repeatable for any target since the `origin` parameter is fully attacker-supplied with no whitelist.

### Likelihood Explanation
Preconditions are minimal: no Shipit session, no privileged role, and no knowledge of secrets are required — only the ability to get a victim to click a link of the form `/github/auth/github?origin=<attacker-url>` and complete the GitHub OAuth consent screen. This is a standard phishing-link attack, low cost, and fully repeatable.

### Recommendation
Validate/allow-list `return_url` before redirecting: only accept origins that are same-host relative paths (e.g., via `URI.parse` checking `host.blank? || host == request.host`), or drop the externally supplied `origin` and always redirect to `root_path` / a server-side allow-listed set of paths.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback redirects only within the Shipit host, not to attacker-controlled origin" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(raw_info: OmniAuth::AuthHash.new(
      id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
      login: 'shipit-user', avatar_url: 'https://example.com',
      api_url: 'https://github.com/api/v3/users/shipit-user'
    ))
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example/phish'

  get :callback

  assert session[:authenticated], "session must be authenticated"
  redirect_host = URI.parse(response.location).host
  # Binding under test: redirect target host must equal the Shipit host, not attacker's
  assert_equal @request.host, redirect_host,
    "callback redirected authenticated session to attacker-controlled host: #{response.location}"
end
```
Expected today: this assertion fails, because `response.location` is `https://evil.example/phish`, demonstrating the open redirect.

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
