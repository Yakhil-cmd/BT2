### Title
Non-Validator Governance Vote in Block Header Silently Nullifies All RemoveValidator Votes in Interval, Allowing Removed Validator to Receive Unauthorized Block Proposer Rewards — (`kaiax/valset/impl/getter_proposers.go`)

---

### Summary

`getRemoveVotesInInterval` conflates "this block's vote is not a validator vote" with "parse failure" and executes `return nil` instead of `continue`. Any block in the proposer update interval whose `header.Vote` encodes a valid but non-validator governance parameter (e.g., `governance.unitprice`) causes the entire function to return `nil`, silently discarding every `RemoveValidator` vote already collected for that interval. The downstream `filteredProposerList(nil)` call then returns the original proposer list unchanged, so the voted-out validator remains eligible to propose blocks and collect KAIA block rewards for the rest of the interval.

---

### Finding Description

**Step 1 — `parseValidatorVote` returns `false` for any non-validator vote.**

`parseValidatorVote` checks whether the vote key is in `gov.ValidatorParams` (which contains only `governance.addvalidator` and `governance.removevalidator`). For any other valid governance key — `governance.unitprice`, `reward.mintingamount`, `istanbul.committeesize`, etc. — it returns `("", nil, false)`. [1](#0-0) 

**Step 2 — `getRemoveVotesInInterval` treats that `false` as a fatal error and returns `nil`.**

The loop over `scanBlocks` calls `parseValidatorVote` for every block that has a non-empty `header.Vote`. When `ok == false` (which is the normal, expected result for any non-validator governance vote), the code logs an error and immediately returns `nil`, abandoning all `RemoveValidator` votes already accumulated in `removeVotes`. [2](#0-1) 

The correct behavior is `continue` — skip non-validator votes and keep scanning.

**Step 3 — `filteredProposerList` called on a nil receiver returns the original proposer list unchanged.**

`getProposerList` calls `removeVoteLists.filteredProposerList(c.num, pList)` where `removeVoteLists` is the nil `removeVoteList` returned above. [3](#0-2) 

Inside `filteredProposerList`, `isUniquelySorted()` passes trivially (`len(nil) == 0 ≤ 1`), the `for range *r` loop iterates zero times, `removeAddrs.Len() == 0`, and the function returns the original `proposers` slice unmodified. [4](#0-3) 

**Step 4 — This only affects the non-migrated scan path.**

`scanBlocks` falls through to the full-interval scan when `lowestScannedVoteNum` is nil or does not yet cover `pUpdateNum`. In that state every block in `[pUpdateNum, pUpdateNum+pUpdateInterval)` is scanned, so any block with a non-validator vote triggers the bug. [5](#0-4) 

---

### Impact Explanation

A validator that has been voted out via `governance.removevalidator` continues to appear in the proposer list for the remainder of the interval. Because block proposer selection and KAIA block rewards are derived from that list, the removed validator receives block rewards it is no longer entitled to — unauthorized KAIA reward distribution. The invariant "a governance-voted-out validator must not appear in the proposer list for the remainder of the interval" is violated.

---

### Likelihood Explanation

The trigger is a block in the same proposer update interval whose `header.Vote` encodes any valid non-validator governance parameter. This can occur:

- **Accidentally**: a validator routinely casting a `governance.unitprice` or `reward.mintingamount` vote in the same interval as a `RemoveValidator` vote.
- **Intentionally**: the validator being removed (or any colluding validator) proposes a block with a non-validator vote before the `RemoveValidator` vote takes effect, ensuring the removal is silently dropped.

The non-migrated path is the active path on any node that has not yet completed the migration scan, which includes all nodes during initial sync or before the migration index is fully built.

---

### Recommendation

Replace `return nil` with `continue` at line 88 of `getter_proposers.go`. The function should skip blocks whose votes are not validator-related, not abort the entire scan:

```go
voteKey, addresses, ok := parseValidatorVote(header)
if !ok {
    continue // not a validator vote; skip this block
}
``` [2](#0-1)

func (r *removeVoteList) filteredProposerList(currentNum uint64, proposers []common.Address) []common.Address {
	if !(*r).isUniquelySorted() {
		logger.Error("removeVoteList are not sorted. create the list in ascending order.")
		return nil
	}

	removeAddrs := new(valset.AddressSet)
	for _, vote := range *r {
		if currentNum <= vote.voteBlkNum {
			break
		}
		for _, addr := range vote.removeAddrs {
			removeAddrs.Add(addr)
		}
	}

	if removeAddrs.Len() == 0 {
		return proposers
	}

	newProposers := make([]common.Address, 0)
	copy(newProposers, proposers)
	for _, removeAddr := range proposers {
		if !removeAddrs.Contains(removeAddr) {
			newProposers = append(newProposers, removeAddr)
		}
	}
	return newProposers
}
