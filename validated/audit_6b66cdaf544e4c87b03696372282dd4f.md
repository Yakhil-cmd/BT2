File-path terminal injection in skill file tree renders unsanitized attacker-controlled paths - (File: pkg/cmd/skills/preview/preview.go)

### Summary
`buildTree`/`printTree` in `pkg/cmd/skills/preview/preview.go` render skill file names taken directly from `discovery.SkillFile.Path` without any control-sequence sanitization, unlike the blob content elsewhere in the same file which is wrapped in `iostreams.Untrusted` and sanitized via `.String()`. Since git allows almost arbitrary bytes (including ESC) in a tree entry's path/name, an attacker who publishes a skill can embed OSC/CSI payloads in a file name and have them printed raw to the victim's terminal by `gh skill preview`.

### Finding Description
`discovery.ListSkillFiles`/`walkTree` populate `SkillFile.Path` directly from the GitHub git-tree API's `entry.Path` field with no filtering: [1](#0-0) [2](#0-1) 

This is fully attacker-controlled: a git tree entry's path can contain any byte sequence except `/` and NUL, so a published skill repository can have a blob whose name contains raw ESC (`0x1B`) bytes forming an OSC (`\x1b]...\x07`) or CSI (`\x1b[...`) sequence.

`renderFileTree` → `buildTree` (`pkg/cmd/skills/preview/preview.go:501`) splits `f.Path` on `/` and stores each path segment verbatim in `treeNode.name`: [3](#0-2) 

`printTree` then writes `node.name` straight to the output writer with `fmt.Fprintf`, with no escaping: [4](#0-3) 

This is called both in the non-interactive pager path and — critically — in the interactive path where the tree is printed to `opts.IO.ErrOut` *before* the file picker prompt is shown, directly adjacent to the `Select` prompt: [5](#0-4) [6](#0-5) 

By contrast, every other place this file prints attacker-controlled text is sanitized: `FetchBlob` returns `iostreams.Untrusted`, and `.String()` runs it through `asciisanitizer` before printing (`content.String()` for SKILL.md and each extra file): [7](#0-6) [8](#0-7) [9](#0-8) [10](#0-9) 

The codebase's own convention (seen in `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal` helper using the same `asciisanitizer` transform for frontmatter-derived strings) confirms that raw skill-derived strings destined for the terminal are expected to be sanitized before printing: [11](#0-10)  — but `buildTree`/`printTree` in preview.go were never wired through an equivalent sanitizer.

### Impact Explanation
An attacker who publishes a skill with a maliciously-named file (path segment containing OSC/CSI sequences) can inject terminal control sequences into a victim's terminal simply by having them run `gh skill preview owner/repo`. This can be used for terminal title/tab spoofing, hiding/obscuring subsequent output, or (on terminals supporting risky OSC sequences like clipboard write, hyperlink, or answerback queries) more severe spoofing that could mislead a user into pasting credentials or approving a destructive action they didn't intend. This matches the "Terminal output/prompt spoofing" impact class referenced in the question. It is a client-terminal display/spoofing issue rather than remote code execution or credential theft in the traditional sense — the practical severity depends on the victim's terminal emulator capabilities.

### Likelihood Explanation
Fully feasible with no special privileges: any GitHub user can publish a public repository with a skill directory containing a file whose name embeds ESC bytes (git does not filter path bytes other than `/` and NUL, and the GitHub Contents/Trees API will happily return and preserve such a path). The victim only needs to run `gh skill preview <attacker-repo>` (or `gh skill install` flows that reuse the same discovery/list code path) against the attacker's repo — a normal, expected usage pattern for this feature. This is reliably repeatable and requires no timing or race conditions.

### Recommendation
Sanitize `SkillFile.Path` (or each path segment) before it is used to build/print the tree — e.g., wrap paths in `iostreams.NewUntrustedBytes`/`NewUntrusted` and call `.String()` (or reuse `sanitizeForTerminal`/`asciisanitizer` as done in `pkg/cmd/skills/list/list.go`) in `buildTree` or `printTree` before writing `node.name` to the writer. Apply the same treatment to `skill.DisplayName()` and the file-picker `choices` list built from `extraFiles[].Path` in `renderInteractive`, since those are also printed/prompted with unsanitized attacker-controlled path strings.

// FetchBlob retrieves the content of a blob by SHA. The blob is base64-encoded
// inside the JSON response and decoded here, so it is returned as
// iostreams.Untrusted and callers must choose sanitized display or raw
// round-tripping.
func FetchBlob(client *api.Client, host, owner, repo, sha string) (iostreams.Untrusted, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "blobs", sha)
	if err != nil {
		return iostreams.Untrusted{}, err
	}
	var resp struct {
		SHA      string `json:"sha"`
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(host, "GET", apiPath.String(), nil, &resp); err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not fetch blob: %w", err)
	}

	if resp.Encoding != "base64" {
		return iostreams.Untrusted{}, fmt.Errorf("unexpected blob encoding: %s", resp.Encoding)
	}

	// GitHub API returns base64 with embedded newlines; use the StdEncoding
	// decoder via a reader to handle them transparently.
	decoded, err := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(resp.Content)))
	if err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not decode blob content: %w", err)
	}

	return iostreams.NewUntrustedBytes(decoded), nil
}

func buildTree(files []discovery.SkillFile) *treeNode {
	root := &treeNode{isDir: true}
	for _, f := range files {
		parts := strings.Split(f.Path, "/")
		current := root
		for i, part := range parts {
			isLast := i == len(parts)-1
			found := false
			for _, child := range current.children {
				if child.name == part {
					current = child
					found = true
					break
				}
			}
			if !found {
				node := &treeNode{name: part, isDir: !isLast}
				current.children = append(current.children, node)
				current = node
			}
		}
	}
	sortTree(root)
	return root
}

func printTree(w io.Writer, cs *iostreams.ColorScheme, nodes []*treeNode, indent string) {
	for i, node := range nodes {
		isLast := i == len(nodes)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		if node.isDir {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(node.name+"/"))
			printTree(w, cs, node.children, indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), node.name)
		}
	}
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}
