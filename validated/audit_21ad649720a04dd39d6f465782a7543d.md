### Title
Webhook signature verification is keyed on `repository.owner.login` while event handlers act on `repository.full_name`, allowing forged events for any repository if any configured organization lacks a `webhook_secret` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/`webhook_secret` used to validate the inbound webhook based on `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')`. The event handlers that actually mutate state (resolve the `Stack`, create `Status` rows, trigger `GithubSyncJob`, etc.) instead resolve the target repository from a *different* field of the same attacker-supplied JSON body: `payload.dig('repository', 'full_name')`. Because HMAC verification is skipped entirely whenever the selected organization has no `webhook_secret` configured, an attacker can set `repository.owner.login` to an org with no secret (satisfying `verify_signature`) while setting `repository.full_name` to a fully-configured, secured target org/repository (driving the actual side effects).

### Finding Description
`verify_signature` derives the authorization context from one payload field: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` unconditionally passes when no secret is configured for the resolved organization: [3](#0-2) 

`Shipit.github` resolves the `GitHubApp`/config purely by the `organization` argument that was passed in (i.e., by `repository_owner`), independent of which repository the payload actually claims to modify: [4](#0-3) 

Meanwhile every webhook `Handler` base class resolves the actual `Stack`/`Repository` to act on from a *different* field of the very same JSON body — `repository.full_name`, not `repository.owner.login`: [5](#0-4) 

`PushHandler`, for example, uses that repository/stack resolution to trigger `stack.sync_github`: [6](#0-5) 

The `webhook_secret` is explicitly documented as optional per organization in multi-org configurations: [7](#0-6) 

The equality binding that is assumed but never enforced is: **`organization authenticated (repository.owner.login)` = `organization/repository written (repository.full_name)`**. Nothing in `verify_signature` or the handler pipeline checks that `repository.owner.login` is consistent with the org prefix of `repository.full_name`. Since both fields live inside the same attacker-controlled JSON body and are never cross-validated, an attacker can decouple which secret gates the request from which repository the request actually operates against.

### Impact Explanation
In a multi-organization Shipit deployment (`config/secrets.yml` keyed per-org, as documented), if even one configured organization has no `webhook_secret` set (an explicitly supported/optional configuration), an unauthenticated attacker can:
1. Send a POST to `/webhooks` with `X-Github-Event` set to any handled event (`push`, `status`, `check_suite`, `pull_request`, `membership`).
2. Set `repository.owner.login` (or `organization.login`) to the org with no secret — `verify_signature` picks that org's `GitHubApp`, whose `verify_webhook_signature` returns `true` regardless of signature/body content.
3. Set `repository.full_name` (and other event-specific fields) to point at a different, fully-secured organization/repository that has real stacks configured.
4. The `create` action re-parses the same raw body and dispatches it to handlers, which resolve the stack from `repository.full_name` and act on it as if it were a legitimate, signed webhook from the secured org.

Concretely this permits forging `status` events that write attacker-controlled `state`/`context`/`target_url` directly into a target commit's `Status` records (as shown by `verifies webhook signature`/`:state create a Status` tests), which can satisfy `ci.require` checks that gate deploys, and forging `push` events that trigger `GithubSyncJob`/`stack.sync_github` against arbitrary stacks not belonging to the attacker. This crosses the "unauthorized deploy" / cross-repository-write impact bar since it lets an attacker manipulate deploy-gating state for repositories they have no legitimate access to, entirely without any Shipit session, API token, or GitHub credentials.

### Likelihood Explanation
This requires a Shipit instance running the documented multi-organization webhook configuration with at least one organization that has an unset `webhook_secret` — an explicitly supported and documented configuration, not a misconfiguration outside the engine's design. No credentials, sessions, or tokens are required; the request is a single unauthenticated HTTP POST to the public `/webhooks` endpoint with a crafted JSON body.

### Recommendation
Enforce that the organization used to select the signing secret is bound to the same repository the handlers act upon (e.g., re-derive `repository_owner` from `repository.full_name`'s prefix rather than from `repository.owner.login`, or explicitly verify they match before dispatch). Additionally, consider treating a missing `webhook_secret` as "reject all webhooks that don't explicitly target that org" instead of "accept unconditionally," since the current unconditional bypass in `verify_webhook_signature` amplifies the impact of the field mismatch across all configured organizations sharing the same `/webhooks` endpoint.

### Proof of Concept
Preconditions: multi-org `secrets.github` config where org `unsecured-org` has `webhook_secret: nil` and org `target-org` has stacks and a real `webhook_secret`.

```
POST /webhooks HTTP/1.1
X-Github-Event: status
Content-Type: application/json

{
  "sha": "<real-sha-of-target-org-commit>",
  "state": "success",
  "context": "ci/required-check",
  "description": "forged",
  "target_url": "https://attacker.example",
  "repository": {
    "owner": { "login": "unsecured-org" },
    "full_name": "target-org/real-repo"
  }
}
```
`verify_signature` resolves `repository_owner` = `"unsecured-org"`, whose `GitHubApp` has no `webhook_secret`, so `verify_webhook_signature` returns `true` for any/no `X-Hub-Signature`. `create` then dispatches the same body, and the status handler resolves the target commit via `repository.full_name` = `"target-org/real-repo"`, writing the forged status onto `target-org`'s commit. # frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit
  module Webhooks
    module Handlers
      class Handler
        class << self
          attr_reader :param_parser

          def params(&block)
            @param_parser = ExplicitParameters::Parameters.define(&block)
          end
        end

        def self.call(params)
          new(params).process
        end

        attr_reader :params, :payload

        def initialize(payload)
          @payload = payload
          @params = self.class.param_parser.parse!(payload)
        end

        def process
          raise NotImplementedError
        end

        private

        def stacks
          @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
        end

        def repository_name
          payload.dig('repository', 'full_name')
        end
      end
    end
  end

### Using Multiple Github Applications

A Github application can only authenticate to the Github organization it's installed in. If you want to deploy code from multiple Github organizations the `github` section of your `config/secrets.yml` will need to be formatted differently.
