The reported issue is specific to ERC721 NFT permits (EIP-4494), where the nonce should increment on *transfer*, not on `permit()` itself — since the same NFT nonce should allow multiple pending signed approvals to different spenders. This codebase does not contain an ERC721/NFT signature-based permit implementation at all: `pallet-nfts`'s approval mechanism (`do_approve_transfer` in `substrate/frame/nfts/src/features/approvals.rs`) is a direct on-chain, origin-checked approval with no EIP-712/EIP-4494 signature or nonce involved [1](#0-0) , and its dispatchable `approve_transfer` is authorized via `ensure_signed`/`ForceOrigin`, not a recovered signature [2](#0-1) .

The only permit/nonce implementation present is `pallet_permit` for **ERC20Permit (EIP-2612)** in `substrate/frame/assets/precompiles/src/permit.rs`, which is a fungible-token allowance permit, not an NFT permit [3](#0-2) . For EIP-2612 ERC20 permits, incrementing the nonce inside `permit()`/`use_permit()` on every successful call is exactly the correct, spec-mandated behavior (each permit signature must be single-use to prevent replay) — this is the opposite semantics of the reported ERC721/EIP-4494 issue, and is explicitly tested and documented as a security-critical invariant here [4](#0-3) [5](#0-4) .

Since there is no ERC721/NFT permit code path in the codebase that reuses a nonce across multiple pending spender signatures (the bug class described in the report), there is no demonstrable Polkadot SDK analog for this finding.

		/// This is the recommended function for production use. It:

		/// 3. Increments the nonce to prevent replay attacks

		/// The `name` parameter should be the token name per EIP-2612 specification.
		///
		/// After this function returns `Ok(())`, the permit cannot be used again.
		pub fn use_permit(

			name: &[u8],
			owner: &H160,
			spender: &H160,
			value: &[u8; 32],
			deadline: &[u8; 32],
			v: u8,
			r: &[u8; 32],
			s: &[u8; 32],
		) -> Result<(), Error<T>> {
			// Verify the permit first
			Self::do_verify_permit(
				verifying_contract,
				name,
				owner,
				spender,
				value,
				deadline,
				v,
				r,
				s,
			)?;

			// Consume the permit by incrementing the nonce
			// This prevents the same permit from being used again
			Self::increment_nonce(verifying_contract, owner)?;
