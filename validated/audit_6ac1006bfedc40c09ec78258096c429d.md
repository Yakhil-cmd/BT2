### Title
Under-backed supply shares remain priced at the floored supply index as collateral after bad-debt write-down, enabling borrows against unbacked value - (File: contracts/pool/src/interest.rs / contracts/controller/src/risk/totals.rs)

### Summary
Analogous to the MetaMorpho "lost assets not reflected in share price" class: XOXNO Lending prices collateral as `scaled_amount × supply_index × oracle price`. When bad debt is socialized, `apply_bad_debt_to_supply_index` clamps the write-down at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`). If the true loss exceeds what the floor can express, residual supply claims stay unbacked — yet the controller's risk engine still values those shares at the floored index, so holders can borrow against collateral whose redeemable value is lower than its risk value, creating fresh protocol insolvency.

### Finding Description
Bad-debt cleanup (`clean_bad_debt`, `force_socialize_bad_debt`, or liquidation-time cleanup) calls `apply_bad_debt_to_supply_index`, which computes `new_supply_index = max(10^24, floor(old_index × reduction))`. [1](#0-0)  When the loss is large enough to hit the `RAY/1000` floor, `backing_shortfall` remains positive: `floor(supplied × supply_index) > cash + ceil(debt)`. [2](#0-1) 

The only consumer of `backing_shortfall` is `require_backed_market`, which gates **new supply only**. [3](#0-2)  Borrow, withdraw, and liquidation never test whether the *collateral* market is backed. Collateral USD value in `calculate_ltv_collateral_wad` / `calculate_account_risk_totals` is `position_value_floor(scaled_amount, supply_index, price)` — the floored index value, not the actually redeemable pro-rata cash. [4](#0-3) 

So after a floor-clamped write-down, each remaining supply share is priced at `supply_index` for LTV/HF purposes even though the market cannot pay it. A holder of legacy shares (supplied before the loss, or credited shares via `SeizeMode::Credit` liquidation, which reclassifies existing supply and bypasses the supply backing gate entirely [5](#0-4) ) can call `borrow` and pass `require_post_pool_risk_gates` on inflated collateral, drawing real cash from a *different* healthy market.

### Impact Explanation
Protocol insolvency / theft of user funds. The attacker borrows up to `ltv_collateral` computed on claims the collateral market cannot redeem. Their account is immediately under-collateralized in economic terms; subsequent `clean_bad_debt` socializes the loss onto suppliers of the borrowed market. This is the same shape as the report: the share "oracle" (the pool's own index pricing) does not account for lost assets, so lending against those shares overpays the borrower.

### Likelihood Explanation
Requires a bad-debt event severe enough to pin the supply index at `SUPPLY_INDEX_FLOOR_RAW` while a positive `backing_shortfall` remains — i.e., loss per supplied share above ~99.9% of remaining claim, achievable when a near-total wipeout occurs (as in `test_floor_wipeout_blocks_supply_until_recap_then_new_deposit_is_safe`, which leaves `shortfall == claim` at the floor). [6](#0-5)  The attacker needs to already hold shares in the impaired market (or receive them via Credit-mode liquidation of an insolvent account, which is permissionless). `recapitalize` is permissionless and would close the window, but nothing sequences it before borrows; the attacker can borrow in the ledger immediately after cleanup. Severity is bounded by the residual shortfall — typically dust-to-moderate — so Medium rather than High. Note the residual-claims behavior is documented (INV-ACCT-04), but the downstream use of inflated collateral in the borrow risk gate is the unmitigated consequence.

### Recommendation
- In `require_post_pool_risk_gates` (or position valuation used for LTV/HF), discount each collateral leg by its market's backing ratio, e.g. `min(index_value, index_value × backing / supplied_claim)`, or value collateral at `min(supply_index claim, pro-rata redeemable cash + debt)`.
- Alternatively, gate `borrow`/`create_strategy` on `backing_shortfall == 0` for every collateral market touched, mirroring `require_backed_market` on supply.
- Optionally let `apply_bad_debt_to_supply_index` write below the floor (or zero claims entirely) when backing is exhausted, so share price cannot exceed redeemable value.

### Proof of Concept
1. Bob supplies 1000 units of token A; Alice supplies collateral B and borrows nearly all of A; B's price collapses so Alice's debt is unpayable.
2. Keeper calls `clean_bad_debt`; the write-down hits `SUPPLY_INDEX_FLOOR_RAW` and `backing_shortfall(A) > 0` remains (residual claim ≈ 1/1000 of original, unbacked).
3. Attacker already holds supply shares of A from before the event (or liquidates Alice via `SeizeMode::Credit` to be credited A shares — Credit mode moves existing shares and never invokes `require_backed_market`).
4. Attacker calls `borrow` for token C from a healthy market. `calculate_ltv_collateral_wad` values the A shares at the floored index; the post-pool risk gate passes; `require_reserves`/`require_liquidation_buffer` on market C (which is fully backed) pass.
5. Attacker withdraws real C, defaults. A keeper `clean_bad_debt` later writes the C loss down onto C suppliers — the insolvency the inflated share price enabled is now socialized.

```rust
/// Asset units by which supplier claims exceed cash + debt (0 if solvent).
pub(crate) fn backing_shortfall(cache: &Cache) -> i128 {
    let supplied_claim = cache.unscale_supply_floor(cache.supplied());
    let outstanding_debt = cache.unscale_borrow_ceil(cache.borrowed());
    let backing = cache.cash().saturating_add(outstanding_debt);
    supplied_claim.saturating_sub(backing).max(0)
}
```
