### Title
Forged `pull_request action=labeled` webhook bypasses signature verification via `repository.owner.login`/`repository.full_name` decoupling, letting an attacker write labels onto another repo's `PullRequest` — ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate against using `repository.owner.login` (or `organization.login`) from the raw JSON body, while `LabelCapturingHandler` (and the other `pull_request` handlers) resolve the actual `Repository`/`ReviewStack` to mutate using the independent `repository.full_name` field from the same body. Because these two fields are never cross-checked, an attacker who can get a signature-check pass for *any* org configured with no `webhook_secret` can set `repository.full_name` to an arbitrary victim repo and have `LabelCapturingHandler` write `params.pull_request.labels.map(&:name)` onto that victim's `PullRequest`.

### Finding Description
The claimed binding to test is: `repository_owner used to verify signature == owner of the repository whose stack/PullRequest gets mutated`. Tracing the code shows this binding is false.

- `verify_signature` picks the app config purely from the payload: `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')`, then `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [1](#0-0) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved org has no configured `webhook_secret`: `return true unless webhook_secret` [2](#0-1) .
- Once the request passes this org-scoped check, `Shipit::WebhooksController#create` dispatches the raw parsed body to every `pull_request` handler, including `LabelCapturingHandler` [3](#0-2) .
- `LabelCapturingHandler#repository` resolves the target `Repository` from a **different** field of the same payload: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [4](#0-3) , and `stack`/`review_stack` are derived from that repository's `review_stacks` scoped by `environment: "pr#{params.number}"` via `ReviewStackAdapter#stack` [5](#0-4) .
- `capture_labels` then writes attacker-controlled data onto that resolved stack's `PullRequest`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [6](#0-5) .

Because `repository.owner.login` (used to pick the signing org) and `repository.full_name` (used to pick the mutated repo) are independent JSON fields fully controlled by the attacker in the same POST body, an attacker can:
1. Set `repository.owner.login` to an org that Shipit is configured to know about but which has no `webhook_secret` set (an operator misconfiguration precondition, matching the question's "org with no configured webhook_secret").
2. Set `repository.full_name` to `"victim-org/victim-repo"`, an unrelated, properly configured victim repository/stack.
3. Set `action: "labeled"`, `pull_request.number` to a PR number that corresponds to an existing, non-archived `ReviewStack` on the victim repo (`environment == "pr#{number}"`), and `pull_request.labels` to arbitrary label names.

`verify_signature` passes (org has no secret ⇒ `verify_webhook_signature` trivially returns `true`), and `LabelCapturingHandler` writes the forged labels onto the victim's `PullRequest` record — a record belonging to a repository whose signature was never validated for this specific request.

Note on the question's stated amplifier ("status/commit lookup by bare SHA collides with victim's commit"): this mechanism does **not** apply to `LabelCapturingHandler`. That handler and its sibling `pull_request` handlers never look up commits/statuses by bare SHA; they resolve the target stack strictly via `Repository.from_github_repo_name(params.repository.full_name)` and PR-number-derived `environment` [7](#0-6) . So the specific SHA-collision causal chain in the question is not the actual mechanism; the real and sufficient mechanism is the `owner.login`/`full_name` field decoupling described above.

Existing guards do not close this gap: `drop_unhandled_event` only checks the event type exists in `Webhooks.handlers`, not payload consistency [8](#0-7) ; the `ExplicitParameters` schemas in the handlers only enforce presence/type of fields, not that `repository.owner.login` matches `repository.full_name`'s owner segment [9](#0-8) ; and `Repository#from_github_repo_name` performs no ownership/authentication check, just a DB lookup by owner/name strings [10](#0-9) .

### Impact Explanation
An attacker can write to `Shipit::PullRequest#labels` on a review stack belonging to a repository/org they do not control, without knowing that org's `webhook_secret`, as long as any other org configured in the Shipit instance lacks a `webhook_secret`. Since `ReviewStack#env` uppercases label names into environment variables surfaced to deploy/provisioning commands, this is a cross-tenant state write from one repository's payload into another repository's stack, matching the Critical "a payload for one repository mutating another's stack" category. Repeatable per request against any review stack whose PR number and repo full name the attacker can guess or observe on public GitHub.

### Likelihood Explanation
Requires: (a) a multi-org Shipit deployment where at least one configured org has no `webhook_secret` (an operator misconfiguration, but one the docs/templates allow since `webhook_secret` is optional per app config), and (b) knowledge of the victim repo's `owner/name` and an active review stack's PR number, both publicly observable on GitHub. No Shipit credentials, GitHub App keys, or team membership are needed. Cost is a single crafted HTTP POST to `/webhooks`.

### Recommendation
In `Shipit::WebhooksController#verify_signature`, bind the verified organization to the repository actually being mutated: derive `repository_owner` from `repository.full_name`'s owner segment (or explicitly reject payloads where `repository.owner.login` and the owner segment of `repository.full_name` disagree) before dispatching to handlers. Additionally, consider making `webhook_secret` mandatory for all configured orgs, or treat a missing secret as "reject" rather than "always verified" ( `return true unless webhook_secret` in `lib/shipit/github_app.rb` should not be treated as authenticated pass-through).

### Proof of Concept
minitest outline (extends `test/controllers/webhooks_controller_test.rb` style):
```ruby
test "labeled payload with mismatched owner/full_name writes labels to unrelated repo's stack" do
  # Precondition: configure Shipit with two orgs — "attacker-org" (no webhook_secret) and
  # "victim-org" (has its own webhook_secret, but victim's secret is never checked here).
  victim_repo = shipit_repositories(:shipit) # owner/name resolves to victim-org/shipit
  stack = create_stack_for(victim_repo) # active, non-archived ReviewStack with PR number N

  request.headers['X-Github-Event'] = 'pull_request'
  payload = payload_parsed(:pull_request_labeled)
  payload["repository"]["owner"]["login"] = "attacker-org"       # used only for signature org selection
  payload["repository"]["full_name"] = victim_repo.github_repo_name # used to resolve mutated repo/stack
  payload["number"] = stack.pull_request.number
  payload["pull_request"]["number"] = stack.pull_request.number
  payload["pull_request"]["labels"] = [{ "name" => "attacker-injected" }]

  assert_changes -> { stack.reload.pull_request.labels }, to: ["attacker-injected"] do
    post :create, body: payload.to_json, as: :json
  end
  assert_response :ok
end
```
Assert both sides of the binding: before the request, `stack.pull_request.labels` is unrelated to the attacker payload and `repository_owner` (`attacker-org`) ≠ `victim_repo.owner`; after the request, `stack.reload.pull_request.labels == ["attacker-injected"]` despite the request never having authenticated against `victim-org`'s secret — proving the divergence.

```ruby
      verified = github_app.verify_webhook_signature(
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
