### Title
Governance vote of `kip71.gastarget = 0` causes integer division-by-zero panic in `NextMagmaBlockBaseFee`, halting block production and validation — (`params/kip71_config.go`)

---

### Summary

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, which accepts any `uint64` value including `0`. Once a zero value is ratified, every call to `NextMagmaBlockBaseFee` for a block with non-zero gas used performs an integer division by zero (`big.Int.Div(x, 0)`), causing a Go runtime panic. This crashes block producers, block validators, and the transaction pool, halting consensus on all honest nodes.

---

### Finding Description

**Root cause — missing zero guard in the format checker:**

`Kip71GasTarget` is registered with `noopFormatChecker`, which unconditionally returns `true`:

```go
// kaiax/gov/param.go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // accepts ANY uint64, including 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` — the other divisor in the same formula — explicitly rejects zero:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // zero rejected
    },
``` [2](#0-1) 

**No consistency check for `Kip71GasTarget` either:**

`checkConsistency` in `headergov/impl/header.go` lists `gov.Kip71GasTarget` in the "no additional checks" branch, returning `nil` unconditionally:

```go
case gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    ...
    return nil
``` [3](#0-2) 

**Division by zero in `NextMagmaBlockBaseFee`:**

Once `GasTarget = 0` is effective, the function reaches:

```go
// params/kip71_config.go
gasTarget := kc.GasTarget   // == 0
...
} else if parentGasUsed > gasTarget {   // true for any non-empty block
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← Div(x, 0) → PANIC
``` [4](#0-3) 

The developers were aware of this risk for `BaseFeeDenominator` and added a fallback guard:

```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64)
}
``` [5](#0-4) 

No equivalent guard exists for `GasTarget`.

**Call sites that panic:**

`NextMagmaBlockBaseFee` is called in three production paths:

1. **Block production** — `work/worker.go` line 382: `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` [6](#0-5) 
2. **Block validation** — `params/kip71_config.go` line 50 via `VerifyMagmaHeader` [7](#0-6) 
3. **Transaction pool reset** — `blockchain/tx_pool.go` line 576: `pset.ToKip71Config().NextMagmaBlockBaseFee(...)` [8](#0-7) 

All three panic when `GasTarget = 0` and any block contains at least one transaction.

---

### Impact Explanation

After the zero-`GasTarget` vote is ratified:

- **Block producers** panic on every attempt to build a block with transactions → no new blocks.
- **All nodes** panic when importing any block with non-zero `GasUsed` → chain sync halts.
- **Transaction pool** panics on every head-change event → no pending transactions can be managed.

The result is a permanent, network-wide consensus halt: honest nodes cannot produce or accept blocks containing transactions. This matches the allowed impact: *consensus divergence on honest nodes* and *invalid block acceptance breaking canonical execution*.

---

### Likelihood Explanation

**In `none` governance mode** (any council member can vote): any single council member can cast `governance_vote("kip71.gastarget", 0)`. The vote is ratified at the next epoch boundary with no further checks.

**In `single` governance mode** (Mainnet): the governing node must cast the vote. This is a privileged actor, but the missing guard is still a latent defect — a misconfiguration or key compromise would trigger it with no on-chain safety net.

The `noopFormatChecker` is the direct root cause; the inconsistency with `Kip71BaseFeeDenominator`'s explicit zero-rejection confirms this is an oversight rather than intentional design.

---

### Recommendation

1. **Add a non-zero format check for `Kip71GasTarget`** in `kaiax/gov/param.go`, mirroring `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // reject zero to prevent division-by-zero
    },
    ...
},
```

2. **Add a defensive guard in `NextMagmaBlockBaseFee`** analogous to the existing `BaseFeeDenominator` guard:

```go
if kc.GasTarget == 0 {
    return makeEvenByFloor(lowerBoundBaseFee)
}
```

3. **Add a `checkConsistency` case** for `Kip71GasTarget` that rejects zero values.

---

### Proof of Concept

```
1. Deploy a Kaia network in "none" governance mode (any council member can vote).
2. Any council member calls:
       governance_vote("kip71.gastarget", 0)
3. Wait for the next epoch boundary; the vote is ratified (no format check rejects it).
4. From this point, every block with at least one transaction causes:
       panic: runtime error: integer divide by zero
   in NextMagmaBlockBaseFee at params/kip71_config.go:102 (or :120).
5. All nodes crash on block production and block import.
   The chain halts permanently for any block containing transactions.
```

The panic path is deterministic: `parentGasUsed > 0 = gasTarget` → enters the `else if` branch → `x.Div(x, big.NewInt(0))` → Go runtime panic.
