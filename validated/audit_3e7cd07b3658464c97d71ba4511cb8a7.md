### Title
Review-stack PR labels are promoted verbatim into deploy/task environment variables, bypassing the deploy-spec variable whitelist - ([File: app/models/shipit/review_stack.rb])

### Summary
`Shipit::ReviewStack#env` merges every PR label name (uppercased) directly into the environment hash passed to `Command`/`PTY.spawn`, with no whitelist check against the repository's `deploy_spec` variables. Since labels are attacker-controlled PR metadata captured verbatim by `LabelCapturingHandler`, an attacker can set a label such as `RUBYLIB` to inject that environment variable into ruby-based deploy/task steps run via `PTY.spawn`.

### Finding Description
The broken binding: the codebase intends "keys reaching `PTY.spawn`'s env argument == deploy-spec-approved variable set" via `EnvironmentVariables#permit`, enforced by `DeploySpec#filter_deploy_envs`/`filter_rollback_envs` [1](#0-0)  and `TaskDefinition#filter_envs` [2](#0-1) . However `TaskCommands#env` never routes `@stack.env` through any such filter — it merges it directly: `super.merge(@stack.env).merge(...)` [3](#0-2) , and `DeployCommands#env` further merges on top of that unfiltered result [4](#0-3) .

`Shipit::ReviewStack#env` is the source of the unfiltered keys: it takes every label on the associated pull request and injects `LABEL_NAME.upcase => "true"` into the env hash with no whitelist, no name validation, and no exclusion list:
```ruby
def env
  return super unless pull_request.present?
  super.merge(
    pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }
  )
end
``` [5](#0-4) 

Labels are captured verbatim (no format/blacklist validation) by `LabelCapturingHandler#capture_labels`: `pull_request.update!(labels: params.pull_request.labels.map(&:name))` [6](#0-5) , gated only by `reopened_active_stack?` (`reopened? && stack.present? && !stack.archived?`) [7](#0-6) .

Call sequence for the exploit: a `pull_request` `reopened` webhook first runs `ReopenedHandler#process`, which unarchives the stack when the repository is `review_stacks_enabled` with `allow_all` or an appropriate label policy: `stack.unarchive!` [8](#0-7) . Both handlers are registered for the same `pull_request` event in `Shipit::Webhooks.default_handlers` [9](#0-8) , so `LabelCapturingHandler` runs against the now-unarchived stack and persists `RUBYLIB` as a label.

On the next scheduled deploy/task, `TaskCommands#env`/`DeployCommands#env` merge `@stack.env` (now containing `'RUBYLIB' => 'true'`) unfiltered into the `Command` env, which is stringified and passed straight to `PTY.spawn(unbundled_env, ...)` in `Command#start`/`#unbundled_env` [10](#0-9) .

This behavior is already demonstrated (unintentionally, as a "feature") by existing tests showing arbitrary label names becoming env vars: `test/models/shipit/review_stack_test.rb:59-65`, `test/lib/shipit/task_commands_test.rb:6-16`, and `test/lib/shipit/deploy_commands_test.rb:6-15` all assert that labels like `wip`/`bug` become `env["WIP"]`/`env["BUG"]` == `"true"` with no whitelist check [11](#0-10) [12](#0-11) . None of `EnvironmentVariables#permit`, `filter_deploy_envs`, or `filter_rollback_envs` are invoked on this path — those functions guard only the `deploy.variables` submitted through the UI/API, not `Stack#env`/`ReviewStack#env`.

### Impact Explanation
Any environment variable name derivable from an arbitrary GitHub label (case-insensitively, since it's upcased) can be forced into the process environment of every `git`, dependency, deploy, and rollback command run for that review stack, including `PTY.spawn`-executed steps. `RUBYLIB` is a canonical example: Ruby prepends its value to `$LOAD_PATH`, so any `require` in a ruby-based deploy step (`cap`, `rake`, custom scripts checked out from the attacker's own branch) will preferentially load attacker-supplied `.rb` files, yielding **Critical RCE on the deploy host** for the repository that has review stacks enabled. Other dangerous variable names (`LD_PRELOAD`, `BUNDLE_GEMFILE`, `GIT_SSH`, `PYTHONPATH`, etc.) are equally reachable, and the blast radius is per-stack (the attacker's own PR/branch) but runs with the deploy host's full deploy privileges (which include `GITHUB_TOKEN` and repository write/deploy capability), so it can pivot beyond the originating stack.

### Likelihood Explanation
Preconditions: the target repository must have `review_stacks_enabled` and a provisioning policy that lets the attacker's PR create/unarchive a stack (`allow_all`, or `allow_with_label`/`prevent_with_label` satisfied by label state) — this is a repository configuration choice made by the repo owner, not a Shipit-wide default. Given that, the attacker's cost is trivial: open a PR from their own fork, close and reopen it, and have a label named `RUBYLIB` (or another dangerous variable name) applied. No Shipit credentials, sessions, or GitHub App secrets are required — this is a normal, signed GitHub webhook for an action the attacker legitimately performs on their own PR. The attack is fully repeatable against every review-stack-enabled repository and does not depend on flaky timing (unarchive happens synchronously before `LabelCapturingHandler` runs in the same handler chain).

### Recommendation
`ReviewStack#env` should not inject raw label names as environment variable keys/values without passing them through the same `EnvironmentVariables#permit` whitelist enforced for deploy/rollback variables (i.e., derive an explicit, deploy-spec-declared set of "label flags" instead of arbitrary uppercase label names), or at minimum reject/strip labels that collide with reserved/sensitive environment variable names (`RUBYLIB`, `LD_PRELOAD`, `PATH`, `BUNDLE_*`, `GIT_*`, etc.) before merging them into `Command` env. Additionally, `TaskCommands#env`/`DeployCommands#env` should route the final merged environment through `deploy_spec.filter_deploy_envs`/`filter_rollback_envs` (or an equivalent hard denylist) before constructing `Command` objects, so no code path can introduce unapproved keys into `PTY.spawn`.

### Proof of Concept
```ruby
# test/models/shipit/review_stack_env_rubylib_test.rb
require "test_helper"

module Shipit
  class ReviewStackEnvRubylibTest < ActiveSupport::TestCase
    test "PR label RUBYLIB propagates unfiltered into TaskCommands/DeployCommands env reaching Command#unbundled_env" do
      repository = shipit_repositories(:shipit)
      repository.provisioning_behavior = :allow_all
      repository.review_stacks_enabled = true
      repository.save!

      opened_payload = payload_parsed(:pull_request_opened)
      Shipit::Webhooks::Handlers::PullRequest::OpenedHandler.new(opened_payload).process
      stack = repository.stacks.last
      stack.tasks.active.each(&:run)
      stack.tasks.active.reload.each(&:complete)
      stack.archive!(shipit_users(:codertocat))

      reopened_payload = payload_parsed(:pull_request_reopened)
      reopened_payload["pull_request"]["labels"] = [{ "name" => "RUBYLIB" }]

      # Simulate the same-event handler chain: ReopenedHandler then LabelCapturingHandler
      Shipit::Webhooks::Handlers::PullRequest::ReopenedHandler.new(reopened_payload).process
      Shipit::Webhooks::Handlers::PullRequest::LabelCapturingHandler.new(reopened_payload).process

      stack.reload
      assert_not stack.archived?
      assert_includes stack.pull_request.labels, "RUBYLIB"

      # Binding under test: keys reaching PTY.spawn's env must equal deploy-spec-approved set (should NOT include RUBYLIB)
      assert_equal "true", stack.env["RUBYLIB"], "ReviewStack#env unexpectedly (but reproducibly) includes RUBYLIB"

      deploy = stack.trigger_continuous_delivery
      commands_env = Shipit::DeployCommands.new(deploy).env
      assert_equal "true", commands_env["RUBYLIB"], "DeployCommands#env propagates RUBYLIB unfiltered"

      cmd = Shipit::Command.new("true", env: commands_env, chdir: Dir.tmpdir)
      spawned_env = cmd.unbundled_env
      assert_equal "true", spawned_env["RUBYLIB"], "RUBYLIB reaches Command#unbundled_env / PTY.spawn env argument"
    end
  end
end
```
This demonstrates the equality violation: `deploy_spec.deploy_variables` for the fixture stack does not declare `RUBYLIB`, yet `env['RUBYLIB'] == 'true'` survives unchanged through `ReviewStack#env` → `TaskCommands#env`/`DeployCommands#env` → `Command#unbundled_env`, the exact hash passed to `PTY.spawn`.

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end
