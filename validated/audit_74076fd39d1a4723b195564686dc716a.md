Investigation summary: I searched for a Polkadot SDK analog to the Curve-pool "asymmetric primary/secondary deposit → less LP minted than expected" issue. The most direct structural analog is `pallet_asset_conversion::Pallet::do_add_liquidity` [1](#0-0) , which is the FRAME AMM equivalent of Curve's `add_liquidity` (forwarding two asset amounts and minting LP/pool-claim tokens).

Unlike the reported Curve `_joinPoolAndStake` code, which forwards `primaryAmount`/`secondaryAmount` directly to `add_liquidity` without checking them against the pool's existing reserve ratio, `do_add_liquidity` explicitly guards against exactly this class of bug:

- When reserves are non-zero, it computes the "optimal" counter-amount via `Self::quote` [2](#0-1) , clamping whichever side would exceed the pool's current ratio down to the ratio-consistent optimal value (`amount2_optimal`/`amount1_optimal`), and enforces `amount1_min`/`amount2_min` bounds so users can bound acceptable slippage.
- LP tokens for non-empty pools are minted as `side1.min(side2)` where each side is `amount * total_supply / reserve` [3](#0-2) , which is the standard Uniswap-v2-style "min of both sides" mint formula that inherently prevents minting a share disproportionate to either token's contribution and prevents the described arbitrage/dilution attack.
- Only the very first liquidity provision into an empty pool takes the raw `amount1_desired`/`amount2_desired` as-is [4](#0-3) , which is expected AMM behavior (the first depositor sets the initial price/ratio) and not equivalent to the reported bug (which concerns adding liquidity to an *existing* pool with an established ratio).

Since the exact missing check described in the report (ratio validation before minting) is present and enforced in `do_add_liquidity`, and the same logic is reused by the `MutateLiquidity` trait implementation used by the precompile [5](#0-4) , there is no reachable violated invariant here. I found no other user-facing "add liquidity"/"join pool" style extrinsic in the indexed codebase (e.g., nomination-pools `join`/`bond_extra`) that forwards two independently-attacker-controlled asset amounts into a pricing formula without a ratio check — nomination-pools only ever bonds a single balance amount, so the "asymmetric two-asset deposit" root cause does not apply there.

		/// Add liquidity to a pool.
		pub(crate) fn do_add_liquidity(
			who: &T::AccountId,
			asset1: T::AssetKind,
			asset2: T::AssetKind,
			amount1_desired: T::Balance,
			amount2_desired: T::Balance,
			amount1_min: T::Balance,
			amount2_min: T::Balance,
			mint_to: &T::AccountId,
		) -> Result<T::Balance, DispatchError> {
			let pool_id = T::PoolLocator::pool_id(&asset1, &asset2)
				.map_err(|_| Error::<T>::InvalidAssetPair)?;

			ensure!(
				amount1_desired > Zero::zero() && amount2_desired > Zero::zero(),
				Error::<T>::WrongDesiredAmount
			);

			let pool = Pools::<T>::get(&pool_id).ok_or(Error::<T>::PoolNotFound)?;
			let pool_account =
				T::PoolLocator::address(&pool_id).map_err(|_| Error::<T>::InvalidAssetPair)?;

			let reserve1 = Self::get_balance(&pool_account, asset1.clone());
			let reserve2 = Self::get_balance(&pool_account, asset2.clone());

			let amount1: T::Balance;
			let amount2: T::Balance;
			if reserve1.is_zero() || reserve2.is_zero() {
				amount1 = amount1_desired;
				amount2 = amount2_desired;
			} else {
				let amount2_optimal = Self::quote(&amount1_desired, &reserve1, &reserve2)?;

				if amount2_optimal <= amount2_desired {
					ensure!(
						amount2_optimal >= amount2_min,
						Error::<T>::AssetTwoDepositDidNotMeetMinimum
					);
					amount1 = amount1_desired;
					amount2 = amount2_optimal;
				} else {
					let amount1_optimal = Self::quote(&amount2_desired, &reserve2, &reserve1)?;
					ensure!(
						amount1_optimal <= amount1_desired,
						Error::<T>::OptimalAmountLessThanDesired
					);
					ensure!(
						amount1_optimal >= amount1_min,
						Error::<T>::AssetOneDepositDidNotMeetMinimum
					);
					amount1 = amount1_optimal;
					amount2 = amount2_desired;
				}
			}

			ensure!(
				amount1.saturating_add(reserve1) >= T::Assets::minimum_balance(asset1.clone()),
				Error::<T>::AmountOneLessThanMinimal
			);
			ensure!(
				amount2.saturating_add(reserve2) >= T::Assets::minimum_balance(asset2.clone()),
				Error::<T>::AmountTwoLessThanMinimal
			);

			T::Assets::transfer(asset1, who, &pool_account, amount1, Preserve)?;
			T::Assets::transfer(asset2, who, &pool_account, amount2, Preserve)?;

			let total_supply = T::PoolAssets::total_issuance(pool.lp_token.clone());

			let lp_token_amount: T::Balance;
			if total_supply.is_zero() {
				lp_token_amount = Self::calc_lp_amount_for_zero_supply(&amount1, &amount2)?;
				T::PoolAssets::mint_into(
					pool.lp_token.clone(),
					&pool_account,
					T::MintMinLiquidity::get(),
				)?;
			} else {
				let side1 = Self::mul_div(&amount1, &total_supply, &reserve1)?;
				let side2 = Self::mul_div(&amount2, &total_supply, &reserve2)?;
				lp_token_amount = side1.min(side2);
			}

			ensure!(
				lp_token_amount > T::MintMinLiquidity::get(),
				Error::<T>::InsufficientLiquidityMinted
			);

			T::PoolAssets::mint_into(pool.lp_token.clone(), mint_to, lp_token_amount)?;

			Self::deposit_event(Event::LiquidityAdded {
				who: who.clone(),
				mint_to: mint_to.clone(),
				pool_id,
				amount1_provided: amount1,
				amount2_provided: amount2,
				lp_token: pool.lp_token,
				lp_token_minted: lp_token_amount,
			});

			Ok(lp_token_amount)
		}
