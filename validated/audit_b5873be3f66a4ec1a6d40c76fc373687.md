### Title
Unauthenticated Bridge Peer Can Inject Arbitrary RPC Calls into Main Bridge's Internal `kaia`/`klay` RPC Server via `ServiceChainCall` — (`node/sc/main_bridge_handler.go`)

---

### Summary

The `MainBridge` creates an internal RPC server and registers all public `kaia`/`klay` API services on it. Any peer that connects to the main bridge's P2P listen port and passes the bridge protocol handshake — which only validates `NetworkId` and `ProtocolVersion`, not chain ID or any application-level identity — can send a `ServiceChainCall` P2P message whose raw bytes are written verbatim into the internal RPC server pipe. The RPC server processes the call and returns the result to the peer. Because the bridge operator account must be unlocked for bridge operations, a connected attacker can call `kaia_sendTransaction` to submit arbitrary transactions from the bridge operator's account, or call `kaia_sendRawTransaction` to inject pre-signed transactions into the parent chain's tx pool.

---

### Finding Description

**Step 1 — Internal RPC server is populated with all public `kaia`/`klay` APIs.**

In `SetComponents`, every API whose namespace is `"klay"` or `"kaia"` and whose `Public` flag is `true` is registered on `mb.rpcServer`: [1](#0-0) 

This includes the full `kaia`/`klay` public API surface: `kaia_sendTransaction`, `kaia_sendRawTransaction`, `kaia_call`, etc.

**Step 2 — The internal RPC server is wired to a `net.Pipe` connection.** [2](#0-1) 

`mb.rpcConn` (the write end) is the only gate between the P2P network and the RPC server.

**Step 3 — The bridge protocol handshake does not validate chain ID or peer identity.**

`readStatus` only checks `NetworkId` and `ProtocolVersion`: [3](#0-2) 

`ChainID` is stored but never compared against the expected parent chain ID during handshake. Any peer that knows the public network ID and the fixed protocol version `2` passes.

**Step 4 — `handleCallMsg` writes any `ServiceChainCall` payload directly into the RPC pipe.** [4](#0-3) 

There is no allowlist, no method filter, no caller identity check. The raw bytes from the peer become the RPC request.

**Step 5 — The main bridge listens for inbound connections from any peer.** [5](#0-4) 

`NoDial = true` prevents the main bridge from dialing out, but it still accepts inbound connections on `MainBridgePort` (default `50505`). The `handle` function enforces only a peer-count limit and the weak handshake.

---

### Impact Explanation

The bridge operator's parent-chain account (`pAccount`) must be unlocked at runtime so the sub-bridge can sign and submit value-transfer handle transactions. Because `kaia_sendTransaction` is registered on `mb.rpcServer` under the `kaia`/`klay` namespace, an attacker who connects to port 50505 can craft a JSON-RPC call:

```json
{"jsonrpc":"2.0","id":1,"method":"kaia_sendTransaction",
 "params":[{"from":"<bridge_operator_addr>","to":"<attacker>","value":"0x..."}]}
```

and send it as a `ServiceChainCall` P2P message. The RPC server executes it using the unlocked operator account, transferring KAIA from the bridge operator to the attacker. Alternatively, `kaia_sendRawTransaction` can be used to replay any previously signed transaction that has not yet been consumed, causing nonce exhaustion or double-spend of bridge operator funds.

The corrupted value is the bridge operator's KAIA balance and nonce on the parent chain, both of which are protected assets used to authorize and sequence all cross-chain value-transfer handle transactions.

---

### Likelihood Explanation

The main bridge P2P port is reachable by any host that can route to the main bridge node. The only barrier is the RLPx transport handshake (which provides encryption but not application-level authorization for inbound connections) and the bridge status handshake (which checks only public, static values). No secret, certificate, or pre-shared key is required. An attacker on the same network segment or with access to the bridge's public IP can exploit this without any privileged position.

---

### Recommendation

1. **Restrict the internal RPC server's API surface.** Do not register the full `kaia`/`klay` namespace on `mb.rpcServer`. Register only the specific methods the sub-bridge legitimately needs (e.g., `kaia_getTransactionCount`, `kaia_gasPrice`).
2. **Validate peer identity at the application layer.** After the RLPx handshake, verify that the connecting peer's derived address matches the configured sub-bridge operator address before accepting `ServiceChainCall` messages.
3. **Add a method allowlist in `handleCallMsg`.** Parse the JSON-RPC method name before forwarding and reject any method not on an explicit allowlist.

---

### Proof of Concept

```python
# Pseudocode — attacker connects to main bridge port 50505
import rlpx, json

conn = rlpx.connect("mainbridge_host", 50505)  # inbound: no pre-shared key needed
conn.send_status(network_id=8217, protocol_version=2)  # public values

payload = json.dumps({
    "jsonrpc": "2.0", "id": 1,
    "method": "kaia_sendTransaction",
    "params": [{
        "from": "<bridge_operator_address>",
        "to":   "<attacker_address>",
        "value": hex(10**18)   # 1 KAIA
    }]
}).encode()

# Send as ServiceChainCall (msg code 0x06)
conn.send_p2p_msg(code=0x06, data=payload)
response = conn.recv_p2p_msg()   # ServiceChainResponse (0x07) with tx hash
```

The main bridge's `handleCallMsg` writes `payload` to `mb.rpcConn`; the RPC server calls `kaia_sendTransaction` using the unlocked bridge operator account and returns the transaction hash. The operator's KAIA balance is debited and the nonce is consumed, breaking the invariant that only legitimate bridge handle transactions may spend the operator's funds.

	serverConfig.PrivateKey = mb.ctx.NodeKey()

	serverConfig.Logger = logger
	serverConfig.ListenAddr = mb.config.MainBridgePort
	serverConfig.MaxPhysicalConnections = mb.maxPeers
	serverConfig.NoDiscovery = true

	scprotocols := make([]p2p.Protocol, 0, len(mb.SCProtocol().Versions))

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}

func (mbh *MainBridgeHandler) handleCallMsg(p BridgePeer, msg p2p.Msg) error {
	logger.Trace("mainbridge writes the rpc call message to rpc server", "msg.Size", msg.Size, "msg", msg)
	data := make([]byte, msg.Size)
	err := msg.Decode(&data)
	if err != nil {
		logger.Error("error in mainbridge message handler", "err", err)
		return err
	}

	// Write to RPC server pipe
	_, err = mbh.mainbridge.rpcConn.Write(data)
	if err != nil {
		logger.Error("failed to write to the rpc server pipe", "err", err)
		return err
	}
	return nil
}
