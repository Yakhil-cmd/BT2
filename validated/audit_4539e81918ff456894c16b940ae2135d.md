### Title
Webhook signature verified against attacker-selected organization's secret while handlers act on a different, unverified repository - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks the GitHub App/secret to validate the HMAC signature by reading `repository.owner.login` (or `organization.login`) straight out of the *unverified* JSON body, then delegates to event handlers that resolve the target `Stack`/`Repository` using a *different* field of the same unverified body: `repository.full_name`. When Shipit is configured with more than one GitHub organization (each with its own `webhook_secret`), these two lookups are not bound to each other, breaking the trust equality "organization whose secret authenticated the request == repository the handler writes to."

### Finding Description
`verify_signature` selects the signing secret like this: [1](#0-0) [2](#0-1) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
```

`Shipit.github(organization:)` returns a `GithubApp` instance configured with a **per-organization** `webhook_secret` (Shipit supports multiple GitHub App configs, one per organization, as shown by `Shipit.github(organization: 'OrgOne')` in `test/unit/shipit_test.rb`). The secret used for HMAC verification is therefore `Shipit.secrets.github[repository_owner].webhook_secret` [3](#0-2) [4](#0-3) 

After signature verification passes, `WebhooksController#create` dispatches to handlers derived from `Shipit::Webhooks.for_event`, e.g. `PushHandler`, which resolves the target stacks not from `repository.owner.login` but from `repository.full_name`: [5](#0-4) 

```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
```

`repository.owner.login` (used to pick the verifying secret) and `repository.full_name` (used to pick the repository that gets acted on) are two independent fields inside the same attacker-controlled JSON body, and nothing ties them together before the signature is verified. An attacker who legitimately possesses (or can obtain) the `webhook_secret` configured for organization `A` (for example because they operate/administer a repository under org A that is registered with this Shipit instance, and GitHub lets any admin of that org's repo see/rotate that secret) can craft a payload where:

- `repository.owner.login` = `"A"` (so `Shipit.github(organization: "A")`'s secret is used to compute/verify the HMAC — and the attacker signs with that secret, so verification succeeds), and
- `repository.full_name` = `"B/some-repo"` (a repository belonging to a *different* configured organization `B`).

Because `PushHandler`/`CheckSuiteHandler`/`StatusHandler` trust `repository.full_name` unconditionally to select the `Stack`, this payload — verified only with org A's secret — is applied to a stack that belongs to org B. This breaks the intended binding: "the organization whose webhook secret authenticated the request" must equal "the repository/stack the handler is permitted to write to."

### Impact Explanation
This allows unauthorized cross-repository writes: an attacker who only controls (or has obtained) the webhook secret of one configured organization can trigger `sync_github`, check-run refreshes, or commit status writes for a `Stack` belonging to an unrelated organization/repository also configured in the same Shipit instance — an authorization boundary the app is documented and expected to enforce per-organization. This matches the "cross-repository writes" Critical impact class.

### Likelihood Explanation
Exploitability requires: (1) the Shipit instance to be configured with more than one GitHub organization/app (a documented, supported configuration — see `docs/setup.md` and `secrets_double_github_app.yml` used in tests), and (2) the attacker to know one organization's `webhook_secret` (obtainable by any admin of a repo under that org, since webhook secrets are visible/rotatable by repo/org admins in GitHub's webhook settings — this is not the same as compromising the whole Shipit deployment). Given multi-org setups are an intended feature, and per-org admins routinely have access to their own webhook secret, likelihood is realistic in any multi-tenant Shipit deployment.

### Recommendation
Cross-check that the organization used to select/verify the webhook secret matches the organization implied by `repository.full_name` (and any org-scoped fields the individual handlers rely on) before dispatching to handlers — e.g. derive `repository_owner` from `repository.full_name.split('/').first` consistently, or have each handler re-validate that `payload['repository']['owner']['login']` matches the verified organization.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgA` and `OrgB`, each with its own `github.webhook_secret` (as in `test/dummy/config/secrets_double_github_app.yml`).
2. As an attacker with admin access to a repo under `OrgA` (and thus knowledge of `OrgA`'s webhook secret), craft a `push` event JSON body:
   ```json
   {
     "ref": "refs/heads/main",
     "after": "<attacker-chosen sha>",
     "repository": {
       "owner": { "login": "OrgA" },
       "full_name": "OrgB/victim-repo"
     }
   }
   ```
3. Compute `X-Hub-Signature: sha1=HMAC(OrgA_webhook_secret, body)` and POST to `/webhooks`.
4. `WebhooksController#verify_signature` calls `Shipit.github(organization: "OrgA")` and successfully verifies the signature.
5. `Shipit::Webhooks::Handlers::PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("OrgB/victim-repo")`, and triggers `stack.sync_github(expected_head_sha: ...)` on a stack that belongs to `OrgB`, despite the request only being authenticated as `OrgA`. [6](#0-5)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
