### Title
Webhook signature verification is keyed by an attacker-controlled organization field that is decoupled from the repository actually written to - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to verify the HMAC signature against using `repository_owner`, a value read directly from the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`). All downstream handlers, however, resolve the actual `Repository`/`Stack` to act on from a *different* field in the same body: `payload.dig('repository', 'full_name')` [1](#0-0) . Nothing enforces that `repository.owner.login` and the owner portion of `repository.full_name` refer to the same organization. If any configured organization has `webhook_secret: nil` (an explicitly supported configuration, as shown in `test/dummy/config/secrets_double_github_app.yml`), `verify_webhook_signature` short-circuits to `true` for that organization regardless of the request body [2](#0-1) , letting an unauthenticated caller "authenticate" as that organization while pointing `repository.full_name` at a stack belonging to a different, properly-secured organization.

### Finding Description
The binding that should hold is:
`organization whose secret validated the signature == organization owning the repository the handler writes to`

Path of the mismatch:
1. `WebhooksController#verify_signature` computes `repository_owner` purely from the JSON payload: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [3](#0-2) , then fetches `Shipit.github(organization: repository_owner)` and verifies `X-Hub-Signature` against that organization's `webhook_secret` [4](#0-3) .
2. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank/nil: `return true unless webhook_secret` [2](#0-1) . The fixture `test/dummy/config/secrets_double_github_app.yml` shows this is a normal, supported configuration state (`webhook_secret: # nil`) for an org configured alongside others that do have secrets.
3. Once "verified", `WebhooksController#create` dispatches the raw JSON to the registered handler for the event, e.g. `Handlers::PushHandler` [5](#0-4) .
4. `Handler#stacks` resolves the target `Repository` from `payload.dig('repository', 'full_name')` via `Repository.from_github_repo_name` [1](#0-0) , a completely separate field from the one used to pick the verifying secret in step 1.
5. `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` on every matching, non-archived stack for the resolved repository/branch [6](#0-5) , enqueuing `GithubSyncJob`, which fetches commits using that stack's *own* configured GitHub App credentials and can trigger continuous delivery.

Because `repository.owner.login` and `repository.full_name`'s owner segment are two independent, attacker-supplied fields in the same unsigned-for-that-organization payload, an attacker who knows (or discovers) that any tenant organization in a multi-org Shipit deployment has `webhook_secret: nil` can trivially pass signature verification "as" that organization while targeting a stack that belongs to an entirely different, secured organization.

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" trust boundary called out in scope. Concretely, an attacker can force `GithubSyncJob`/resync and related state changes (e.g. via `check_suite`/`status` handlers which similarly key `stacks` off `repository.full_name`) against a victim stack that belongs to an organization whose webhook secret the attacker never possessed, simply by riding on another configured organization's absent secret. In deployments where `continuous_deployment` is enabled, prematurely or repeatedly forcing a resync/check-run refresh cycle can influence when the pipeline decides a commit is deployable and trigger an unauthorized deploy sequence through the normal continuous-delivery path, without the attacker ever holding a valid signature for the targeted organization/repository. This matches the High/Critical bar of "escalation... or an unauthorized deploy" via a credential/authentication boundary that the engine itself fails to bind correctly.

### Likelihood Explanation
Requires: (a) a multi-organization Shipit deployment (explicitly supported, see `secrets_double_github_app.yml`), and (b) at least one configured organization with no `webhook_secret` set — a state the codebase treats as valid/expected (`return true unless webhook_secret`) rather than rejecting. No privileged credentials, no `ApiClient` token, and no GitHub App private key are needed; only knowledge of the target's `full_name` and the low-secret organization's `login`, both discoverable in a typical open-source or multi-tenant Shipit install.

### Recommendation
Do not select the verifying organization's secret from unauthenticated payload fields, or if it must be, cross-validate that the resolved `repository.owner.login`/`organization.login` matches the owner segment of `repository.full_name` (and any other repository identifiers used later by handlers) before dispatching. Additionally, treat a missing/blank `webhook_secret` as "signature required to fail" or restrict such no-secret organizations to only affect their own literal repositories, never resolving handler targets from separate, uncorrelated fields in the same payload.

### Proof of Concept
Given a Shipit instance configured with two organizations, `OrgSecure` (has a `webhook_secret`) and `OrgOpen` (configured with `webhook_secret: nil`, as in `secrets_double_github_app.yml`):

```
POST /webhooks
X-Github-Event: push
(no valid X-Hub-Signature needed)

{
  "ref": "refs/heads/master",
  "after": "<attacker_chosen_sha>",
  "repository": {
    "owner": { "login": "OrgOpen" },
    "full_name": "OrgSecure/victim-repo"
  }
}
```

* `verify_signature` computes `repository_owner = "OrgOpen"`, fetches `Shipit.github(organization: "OrgOpen")`, whose `webhook_secret` is `nil`, so `verify_webhook_signature` returns `true` — no valid signature required.
* `PushHandler#process` resolves `stacks` from `payload.dig('repository','full_name') == "OrgSecure/victim-repo"`, matching real stacks under `OrgSecure`, and calls `stack.sync_github(expected_head_sha: "<attacker_chosen_sha>")`, acting on a repository never covered by any secret the attacker controls.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event

    end

    def repository_owner

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
