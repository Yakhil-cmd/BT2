### Title
Textcoin claim logic only redeems the first private asset held at a claim address, permanently locking any additional private assets sent there - (File: wallet.js)

### Summary
The reported Seaport bug locks non-WETH tokens because `_validateSaleOrder()` never checks that `order.parameters.offer` contains exactly one item, so any extra assets received are stranded with no withdrawal path. The same single-item assumption exists in ocore's textcoin claiming flow: `receiveTextCoin()` in [1](#0-0)  queries all unspent outputs sitting at the deterministic textcoin address, but for private assets it explicitly claims only the first asset (`assets[0]`) and silently ignores the rest, with no mechanism to later retrieve them once the one-time claim address is abandoned.

### Finding Description
`receiveTextCoin()` derives a one-off address from the textcoin mnemonic and queries `outputs` for everything unspent at that address, grouped by `asset`: [2](#0-1) 

If the row set contains a private asset, the code branches into `else { // claim only the 1st asset }`, setting `opts.asset = asset` (i.e. `assets[0]`) and constructing a payment for only that single asset: [3](#0-2) 

Unlike the public-asset branch, which iterates over *all* returned assets and builds an `outputs_by_asset` map to sweep every asset to the recipient: [4](#0-3) 

...the private-asset branch has no equivalent loop. Nothing in the address definition or protocol prevents more than one private asset from being sent to the same textcoin address before it is claimed - the address is a plain `["sig", {pubkey}]` address (`expandMnemonic()`, [5](#0-4) ) reachable by any unprivileged unit poster who learns the address (e.g. it can be observed on-chain once any transaction referencing it appears, or additional assets can be attached by the sender/composer path itself). Once the recipient calls `receiveTextCoin()`, only the first (alphabetically-sorted by the `ORDER BY asset DESC` SQL clause) private asset is redeemed to `addressTo`; the remainder stays parked at the ephemeral address.

Because the wallet's automatic reclaim job `claimBackOldTextcoins()` matches candidates via `sent_mnemonics LEFT JOIN unit_authors ... WHERE unit_authors.address IS NULL` ( [6](#0-5) ), as soon as the address authors one unit (from claiming `assets[0]`), it is excluded from all future automatic reclaim attempts even though it still holds other unclaimed private-asset funds. Since the mnemonic itself is typically single-use/ephemeral in the UI flow (and is erased via `eraseTextcoin()`, [7](#0-6) ), the remaining assets become permanently unspendable.

### Impact Explanation
Any private asset amounts beyond the first one present at a textcoin claim address are permanently locked with no automated or user-facing path to recover them - directly analogous to the AA/marketplace funds-locking bug in the reference report. This is a fund-freezing bug reachable by ordinary wallet users (both the textcoin creator, who may fund the address with more than one private asset, and any external party who deposits an additional private-asset payment to the known address before it is claimed).

### Likelihood Explanation
The single-asset assumption is hard-coded (`// claim only the 1st asset`) and unconditionally applied whenever the address holds a private asset, with no validation that only one asset type is present, unlike the explicit multi-asset handling used for public assets in the same function. Any user or application composing a textcoin with more than one private asset, or any third party sending an additional private-asset payment to a not-yet-claimed textcoin address, triggers the loss without any special conditions or need for a malicious counterparty.

### Recommendation
Mirror the public-asset handling: enumerate all assets returned by the `checkStability()` query and issue claim payments for every private asset present (or explicitly reject/return an error until all attached assets have been redeemed), instead of only processing `assets[0]`. Additionally, ensure `claimBackOldTextcoins()` continues considering an address for reclaim as long as it still holds unclaimed asset balances, not merely until it authors its first unit.

### Proof of Concept
1. Alice creates a textcoin intended to carry private asset A, but composes (or a third party later sends) an additional payment of private asset B to the same generated textcoin address before Bob claims it.
2. Bob calls `receiveTextCoin(mnemonic, addressTo, ...)`. `checkStability()` returns two rows (asset A and asset B); `assets[0]` (say asset A, first alphabetically) is claimed via `opts.asset = asset`, `opts.to_address = addressTo` — [8](#0-7) .
3. The resulting unit is broadcast, and the textcoin address now has authored a unit, so `claimBackOldTextcoins()`'s `WHERE unit_authors.address IS NULL` filter permanently excludes it — [9](#0-8) .
4. Asset B's output at the ephemeral address is never spent; since the mnemonic is treated as single-use and erased from `sent_mnemonics`, no party retains the means to redeem it, permanently freezing asset B.

function expandMnemonic(mnemonic) {
	var addrInfo = {};
	mnemonic = mnemonic.toLowerCase().split('-').join(' ');
	if ((mnemonic.split(' ').length % 3 !== 0) || !Mnemonic.isValid(mnemonic)) {
		throw new Error("invalid mnemonic: "+mnemonic);
	}
	mnemonic = new Mnemonic(mnemonic);
	addrInfo.xPrivKey = mnemonic.toHDPrivateKey().derive("m/44'/0'/0'/0/0");
	addrInfo.pubkey = addrInfo.xPrivKey.publicKey.toBuffer().toString("base64");
	addrInfo.definition = ["sig", {"pubkey": addrInfo.pubkey}];
	addrInfo.address = objectHash.getChash160(addrInfo.definition);
	return addrInfo;
}

function claimBackOldTextcoins(to_address, days){
	if (typeof days !== 'number')
		throw Error("bad days: " + days);
	db.query(
		"SELECT mnemonic FROM sent_mnemonics LEFT JOIN unit_authors USING(address) \n\
		WHERE mnemonic!='' AND unit_authors.address IS NULL AND creation_date<"+db.addTime("-"+days+" DAY"),
		function(rows){
			async.eachSeries(
				rows,
				function(row, cb){
					receiveTextCoin(row.mnemonic, to_address, function(err, unit, asset){
						if (err)
							console.log("failed claiming back old textcoin "+row.mnemonic+": "+err);
						else
							console.log("claimed back mnemonic "+row.mnemonic+", unit "+unit+", asset "+asset);
						cb();
					});
				}
			);
		}
	);
}
