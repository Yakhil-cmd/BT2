### Title
Unsanitized skill file names printed to terminal by `printTreeDir` allow ANSI/OSC escape-sequence injection - (File: pkg/cmd/skills/install/install.go)

### Summary
`printTreeDir` (pkg/cmd/skills/install/install.go:1163) renders the on-disk file tree of a just-installed skill by printing `entry.Name()` values obtained from `os.ReadDir` directly via `fmt.Fprintf`, with no control-character or ANSI escape sequence stripping. Because these file/directory names originate from an attacker-controlled skill archive extracted onto disk, a malicious skill can embed terminal escape sequences (OSC 8 hyperlink spoofing, terminal title changes, cursor movement, etc.) in its file names that get echoed unfiltered to the victim's terminal during `gh skills install`.

### Finding Description
`printFileTree` (install.go:1151) is called after a skill is installed to show the user what was written to disk: [1](#0-0) 

It calls `printTreeDir`, which reads the extracted skill directory and prints each entry's name unmodified: [2](#0-1) 

The entry names come straight from `os.ReadDir(dir)`, i.e., the literal file/directory names that were extracted from the attacker's published skill archive onto the local filesystem. Unix filenames may legally contain arbitrary bytes other than `/` and NUL, including ESC (0x1B) and other C0 control bytes, so an attacker who publishes a skill with a file named e.g. `\x1b]8;;http://evil\x07innocuous.md\x1b]8;;\x07` (OSC 8 hyperlink) or one containing cursor-repositioning/terminal-title CSI/OSC sequences can have that payload rendered verbatim in the tree output.

The codebase has an established mitigation for exactly this class of problem: `iostreams.Untrusted` (pkg/iostreams/untrusted.go) wraps externally-sourced strings and its `String()` method sanitizes ANSI escape sequences via `asciisanitizer.Sanitizer` before any `fmt` print path renders it: [3](#0-2) 

`printTreeDir` does not route `entry.Name()` through `Untrusted` or any equivalent sanitizer — it uses raw `fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)`, so the established sanitization convention used elsewhere in the CLI (e.g., in the skills `list` command) is bypassed here.

Note: this specific function only prints the file/directory listing of the installed skill, not the skill description or instructions text (those are rendered by other code paths not covered by this citation); the question's broader claim about "description, instructions" is not substantiated for `printTreeDir` itself, but the file-list injection is confirmed.

### Impact Explanation
This enables terminal output/prompt spoofing: a malicious skill's file names can inject OSC 8 hyperlinks that visually disguise a link's destination, manipulate the terminal title/status line, or use cursor control to overwrite/obscure previously printed trusted text (e.g., the immediately-following `printPreInstallDisclaimer`/`printReviewHint` warnings about reviewing skill contents). This matches a "Terminal output/prompt spoofing" class impact — moderate to high depending on terminal emulator, since it could be used to hide or spoof the security warnings the CLI itself prints right after the tree, potentially misleading a user into skipping review of a malicious skill.

### Likelihood Explanation
Fully attacker-controlled and requires no special privilege: any unprivileged GitHub user can publish a skill repository whose skill directory contains a file with an embedded escape sequence in its name, and any victim who runs `gh skills install <that skill>` will have the payload echoed to their terminal via `printFileTree`/`printTreeDir`. This is a repeatable, one-shot injection with no timing or race requirements.

### Recommendation
Sanitize `entry.Name()` (and any other skill-derived strings, such as description text used elsewhere) before printing, e.g. by routing it through `iostreams.NewUntrusted(name).String()` or an equivalent ANSI/control-character stripping helper, consistent with the pattern already established in `pkg/iostreams/untrusted.go` and used by `pkg/cmd/skills/list/list.go`.

### Proof of Concept
Go test sketch (golden test over a hostile fixture):
```go
func TestPrintTreeDir_MaliciousFileName(t *testing.T) {
	dir := t.TempDir()
	evilName := "\x1b]8;;http://evil.example\x07innocuous.md\x1b]8;;\x07"
	if err := os.WriteFile(filepath.Join(dir, evilName), []byte("x"), 0644); err != nil {
		t.Fatal(err)
	}
	var buf bytes.Buffer
	cs := iostreams.NewColorScheme(false, false, false)
	printTreeDir(&buf, cs, dir, "  ")
	out := buf.String()
	if strings.Contains(out, "\x1b]8;;") {
		t.Fatalf("expected OSC 8 escape sequence to be stripped, got: %q", out)
	}
}
```
Expected (current, vulnerable) behavior: the raw OSC 8 escape bytes appear unmodified in `out`. Expected (fixed) behavior: escape sequences are stripped/neutralized before being written to the terminal writer.

func printTreeDir(w io.Writer, cs *iostreams.ColorScheme, dir, indent string) {
	entries, err := os.ReadDir(dir)
	if err != nil {
		fmt.Fprintf(w, "%s%s\n", indent, cs.Muted("(could not read directory)"))
		return
	}
	for i, entry := range entries {
		isLast := i == len(entries)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		name := entry.Name()
		if entry.IsDir() {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(name+"/"))
			printTreeDir(w, cs, filepath.Join(dir, name), indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)
		}
	}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
