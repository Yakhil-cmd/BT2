### Title
Missing existence check on `storage.assocStableUnits[trigger.unit]` before property access causes unhandled TypeError / node crash on AA primary trigger handling - (File: aa_composer.js)

### Summary
CVE-2023-32248 describes a ksmbd flaw where SMB2_TREE_CONNECT/SMB2_QUERY_INFO access a pointer without validating it first, letting a remote attacker crash the kernel server (DoS). The analogous bug class — dereferencing/accessing a property of an object that is assumed to exist but is never checked — is present in `aa_composer.js` `handleTrigger()`, where `storage.assocStableUnits[trigger.unit]` is accessed and immediately indexed with `.count_aa_responses` without first checking that the lookup returned a defined object.

### Finding Description
In `handleTrigger()`, when processing a primary AA trigger (a normal unit sending funds to an AA address, something any unprivileged unit poster can construct), the code does: [1](#0-0) 

```js
if (!bSecondary) {
    if ((trigger.outputs.base || 0) < bounce_fees.base) {
        return bounce('received bytes are not enough to cover bounce fees');
    }
    for (var asset in trigger.outputs) { ... }
    // skip this check for dry-run which uses genesis unit as trigger unit
    if (trigger.unit !== constants.GENESIS_UNIT && !trigger_opts.bAir && storage.assocStableUnits[trigger.unit].count_aa_responses && mci >= constants.pemCurvesFixMci)
        return bounce('a second primary trigger from the same unit is not allowed');
}
```

`storage.assocStableUnits` is an in-memory associative cache of stable-unit properties maintained by `storage.js` (populated/evicted as units stabilize and as memory is trimmed — see the many mutation sites in `storage.js`, `main_chain.js`, `headers_commission.js`, `writer.js`, `graph.js`). The code assumes that the trigger unit's props object is present in this cache at the moment the AA trigger executes, but there is no `if (storage.assocStableUnits[trigger.unit])` guard before dereferencing `.count_aa_responses`. If the entry has been evicted, not yet (re)populated after a restart/catch-up, or is otherwise absent for any reason other than being the genesis unit or an "air" (dry-run) trigger, `storage.assocStableUnits[trigger.unit]` evaluates to `undefined`, and `.count_aa_responses` throws `TypeError: Cannot read properties of undefined (reading 'count_aa_responses')`.

This is the same root-cause pattern as the CVE: a pointer/reference obtained from a lookup is used without validating that the lookup succeeded, prior to a live network-driven code path (SMB2 tree connect/query → ksmbd handler; here, unit stabilization → AA trigger handler).

### Impact Explanation
`handleTrigger()` runs deep inside the unit-processing / AA execution pipeline that fires synchronously as part of stabilizing units and writing AA response joints. An uncaught `TypeError` thrown here is not part of any of the defined error paths (`bounce`, `revert`, `callback(err)`); it propagates as an unhandled JS exception out of the trigger-processing call chain. Depending on where this exception surfaces (inside `async`/db-callback chains that are not wrapped in try/catch), it can crash the running Node.js process, taking the node offline (denial of service) exactly as described for the ksmbd bug — every node in the network that processes the same triggering unit and enters this code path would hit the same crash, potentially stalling the network's ability to confirm units through the affected AA (matches the "no impact" exclusion boundary vs. the accepted outcome "a network unable to confirm new units").

### Likelihood Explanation
Any unprivileged party can construct a payment unit whose output funds an AA address, thereby becoming a "primary trigger" — this is completely permissionless. Triggering the vulnerable line additionally requires that, at trigger-processing time, `storage.assocStableUnits[trigger.unit]` be absent. This is plausible in scenarios such as: nodes that recently restarted and are re-processing a backlog of already-stable units before the in-memory cache is fully warmed, or when AA responses to a unit are re-executed via cache-eviction / catch-up paths where the cache was trimmed to save memory. Because the exact cache-eviction timing is internal implementation detail, exploitability confidence is moderate rather than certain — I could not fully trace every population/eviction path for `assocStableUnits` in the time available, so the precise conditions under which the map entry is missing for a real (non-air) trigger unit remain unverified.

### Recommendation
Add an explicit existence check before dereferencing the cached unit-props object:
```js
if (trigger.unit !== constants.GENESIS_UNIT && !trigger_opts.bAir) {
    const objTriggerUnitProps = storage.assocStableUnits[trigger.unit];
    if (!objTriggerUnitProps)
        throw Error("trigger unit props not found in assocStableUnits: " + trigger.unit); // or fetch from DB as fallback
    if (objTriggerUnitProps.count_aa_responses && mci >= constants.pemCurvesFixMci)
        return bounce('a second primary trigger from the same unit is not allowed');
}
```
Alternatively, fall back to a DB read (`storage.readUnitProps`) when the in-memory cache entry is missing, mirroring the defensive patterns already used elsewhere (e.g., `storage.readStaticUnitProps` callers checking `if (!objUnitProps)` in `validation.js`).

### Proof of Concept
Conceptual (not independently executed):
1. An attacker/normal user posts unit U with a payment output to AA address A (a valid, permissionless action).
2. Node processes and stabilizes U, then invokes `handleTrigger()` for the primary trigger from U to A.
3. If, at the moment this code executes, `storage.assocStableUnits[U]` is not populated (e.g., due to cache eviction/restart/catch-up timing), the expression `storage.assocStableUnits[trigger.unit].count_aa_responses` throws `TypeError: Cannot read properties of undefined`.
4. This exception is not caught by any of the `bounce`/`revert`/`callback` error paths in `handleTrigger`, propagating as an unhandled exception in the unit-processing pipeline and potentially crashing the node process — a denial of service triggerable by ordinary unit posting.
