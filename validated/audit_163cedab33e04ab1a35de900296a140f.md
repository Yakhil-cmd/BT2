### Title
Non-linear HEAD advance (commit + rebase/checkout) desyncs `dirty_now` from `changed_since`, silently dropping committed-and-reviewed-worthy files from the Stop-hook review set - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` intersects `dirty_now` (git-status-derived, plus committed diff only when `head_at_capture` is a linear ancestor of current `HEAD`) with `changed_since` (content diff against the UPS-captured stash `baseline_sha`). When ordinary git operations during a turn (a commit followed by a rebase, `checkout`, `reset`, or amend that changes the parent) make `head_at_capture` no longer an ancestor of `HEAD`, the committed diff is never unioned into `dirty_now`, while `tracked_dirty` from `git status` is empty (the file is already committed and matches the index). The intersection collapses to empty for that file even though `changed_since` (which is ancestry-agnostic) still shows it as changed, so the Stop hook treats a genuinely new, Claude-authored dangerous change as if nothing changed and skips review entirely.

### Finding Description
`save_baseline_sha`/`capture_git_baseline` set `state["baseline_sha"]` and `state["head_at_capture"]` at `UserPromptSubmit` [1](#0-0) . On `Stop`, `compute_v2_review_set` derives the review set purely from current git state, not from the `touched_paths` list that `record_touched_path` actually tracks per edited file — `touched_paths` is only ever used for a metrics counter, never merged into `review_paths` [2](#0-1) .

The review set is computed as:
```
dirty_now = tracked_dirty | new_untracked
if head_at_capture is an ancestor of current HEAD:
    dirty_now |= diff(head_at_capture..HEAD)
changed_since = diff(baseline_sha, worktree)
review_set = dirty_now & changed_since
``` [3](#0-2) 

`_is_ancestor` explicitly checks that `HEAD` moved forward linearly ("not sideways via checkout") [4](#0-3) . If, during the same turn, the dangerous file is committed and then the branch is rebased, checked out elsewhere and merged back, or otherwise has its history rewritten so `head_at_capture` is no longer reachable from the new `HEAD`, `_is_ancestor` returns `False`. `tracked_dirty` from `git status --porcelain` is empty because the file is fully committed and matches the index [5](#0-4) . So `dirty_now` never includes the file. Meanwhile `changed_since` is computed via `git diff <baseline_sha>` against the current worktree, which is ancestry-agnostic and still reports the file as changed [6](#0-5) . The set intersection `dirty_now & changed_since` therefore drops the file, `review_paths` comes back empty for it, and if it's the only changed file the Stop hook exits via `_skip(9, ...)` ("empty review set") without ever running the LLM vulnerability scan [2](#0-1) .

This is reachable through entirely ordinary git workflows a repository can direct Claude to perform (e.g., via prompt-injected instructions in README/CLAUDE.md/commit hooks telling the agent to "rebase onto main" or "amend and reorder commits" after making a change) — no admin privilege, no key leakage, and no direct state-file tampering is required; it is a pure git-sequence consequence of the review-set algorithm.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a file Claude actually edited/committed during the turn (tracked in `touched_paths`) is excluded from the diff sent to the Stop-hook's Haiku vulnerability scan, so a dangerous, freshly introduced change is silently treated as pre-existing/old and never flagged. This is a logic-level bypass of the security-guidance plugin's core enforcement mechanism — a required security guard (Stop-hook review) is skipped for content that should be in scope, matching "Logic-level service disruption caused by bypassing a required guard or misbinding security state."

### Likelihood Explanation
The precondition is simply that git history advance non-linearly relative to `head_at_capture` during a turn (rebase, checkout+merge, or history-rewriting amend) while the file in question ends up clean relative to the index. This is a normal, unprivileged git sequence achievable by an agent following ordinary repo instructions (e.g. a common "rebase before commit" workflow, or prompt injection in repo content directing such operations), fully reproducible deterministically given the described sequence, and does not depend on timing races, mocks, or config-only changes.

### Recommendation
Do not gate the committed-diff term on `_is_ancestor`; instead always compute `diff(head_at_capture, HEAD)` (or better, always compute `diff(baseline_sha, HEAD)` unioned with worktree dirty state) regardless of ancestry, since `git diff` between two SHAs is already ancestry-agnostic and safe. Alternatively, fall back to including `touched_paths` (paths PostToolUse actually recorded as edited this turn) directly in the review set as a floor, so a Claude-authored edit is never excluded purely due to a later non-linear git operation.

### Proof of Concept
Integration test in the plugin's git-state test suite:
1. Init a repo with an initial commit `C0`.
2. Simulate `UserPromptSubmit`: call `capture_git_baseline`/`save_baseline_sha` to snapshot `baseline_sha` and `head_at_capture = C0`.
3. Simulate Claude editing `vuln.py` with a dangerous pattern (e.g. `eval(user_input)`), then `git add` + `git commit` → `C1` (parent `C0`).
4. Simulate a non-linear history rewrite: create a branch `B` off `C0`, `git checkout B`, cherry-pick or re-commit an unrelated trivial change to get `C1'` on `B`, then `git checkout main; git reset --hard C1'` (or equivalently `git rebase --onto` to a point where `C0` is not an ancestor of the final `HEAD`) — end state: worktree matches `HEAD`, `head_at_capture (C0)` is not an ancestor of new `HEAD` per `_is_ancestor`.
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. Assert (expected-but-failing): `review_paths` contains `vuln.py`'s absolute path. Under the current implementation, assert this fails — `review_paths` is empty — demonstrating the dangerous file is dropped from review despite `changed_since` (`git diff baseline_sha`) showing it as modified.

def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}

    try:
        if not include_untracked:
            return _run(None)
        with _temp_index(cwd) as env:
            return _run(env)
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_name_only({base!r}) error: {e}")
        return None

def _git_status_porcelain(cwd):
    """One `git status --porcelain=v1 -z` → (tracked_dirty, untracked) sets of
    repo-root-relative paths, or (None, None) on error. Replaces the
    `_temp_index + git diff HEAD --name-only` pair for the v2 dirty_now
    computation: faster in large repos, and yields the
    untracked set separately so the later get_git_diff can do a targeted
    `add -N -- <files>` instead of a whole-tree `add -N .`.

    -uall: list individual files inside untracked directories (default
    collapses to `dir/`). Required so the untracked set subtracts cleanly
    against the UPS-time `_list_untracked` snapshot, which uses ls-files and
    therefore always lists individual files."""
    try:
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "status",
             "--porcelain=v1", "-uall", "-z"],
            cwd=cwd, capture_output=True, text=True, timeout=30,
        )
        if r.returncode != 0:
            debug_log(f"_git_status_porcelain rc={r.returncode}: {r.stderr[:200]}")
            return None, None
        tracked, untracked = set(), set()
        entries = r.stdout.split("\0")
        i = 0
        while i < len(entries):
            e = entries[i]
            if not e:
                i += 1
                continue
            xy, path = e[:2], e[3:]
            if xy == "??":
                untracked.add(path)
            else:
                tracked.add(path)
                # Rename/copy entries are XY old\0new\0 — second NUL field is
                # the origin path; consume it so it isn't misparsed as a new
                # 2-char-status entry.
                if "R" in xy or "C" in xy:
                    i += 1
            i += 1
        return tracked, untracked
```

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
