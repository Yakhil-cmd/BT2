## Analysis

This confirms the exact asymmetric-binding pattern the report describes: the field used to select the verification key (`repository.owner.login`, resolved to a `GitHubApp`/`webhook_secret` in `verify_signature`) is not the same field used by the event handler to determine which repository is actually acted upon (`repository.full_name`, used by `Handler#repository_name` / `Handler#stacks`). Both fields live in the same attacker-controlled JSON body, and are read independently at two different phases — exactly mirroring the DEX bug's "bucket size read at creation vs. re-read at cancellation" mismatch. In a multi-organization deployment (`Shipit.github(organization:)`, documented in `docs/setup.md`), each organization has its own `webhook_secret`, which the setup docs explicitly mark **optional**. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank. If any configured organization has no `webhook_secret`, an unauthenticated attacker can send a webhook payload with `repository.owner.login` set to that unsecured organization (satisfying `verify_signature`) while setting `repository.full_name` to a **different** organization's repository — the field actually used by `PushHandler`/`Handler#stacks` to locate and mutate a `Stack`. This breaks the intended binding: *the organization whose secret authenticated the request* == *the repository whose stack is written to*. That equality does not hold, letting a forged push event trigger `stack.sync_github(expected_head_sha:)` against a stack belonging to a fully-secured organization, without ever presenting a valid signature for it.

### Title
Webhook signature verification is keyed on `repository.owner.login`/`organization.login` but stack mutation is keyed on the unrelated `repository.full_name` field, allowing cross-organization forged push events - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/handler.rb, lib/shipit/github_app.rb)

### Summary
`WebhooksController#verify_signature` derives which `GitHubApp` (and thus which `webhook_secret`) to use for HMAC verification from `params.dig('repository','owner','login')` (or `organization.login`) in the unauthenticated request body. Every event `Handler` (e.g. `PushHandler`) independently re-reads `payload.dig('repository','full_name')` to resolve the `Repository`/`Stack` it will act on. These two payload fields are never cross-checked against each other.

### Finding Description
- `verify_signature` selects the app config via `Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(signature, raw_post)`.
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally `unless webhook_secret` is present — a state explicitly supported since `docs/setup.md` calls the webhook secret "optional" and the shipped `config/secrets.development.shopify.yml` ships it as `nil`.
- Once verification passes (or is skipped), `WebhooksController#create` dispatches the full, attacker-controlled `params` hash to `Shipit::Webhooks.for_event(event)` handlers.
- `Handler#stacks`/`Handler#repository_name` resolve the target `Repository` using `payload.dig('repository','full_name')`, a completely separate JSON field from the one used to pick the verification secret.
- Because the two lookups are decoupled, an attacker only needs one organization in the deployment to be configured without a `webhook_secret` to forge events (e.g. `push`) that claim `repository.owner.login` = the unsecured org (to pass/skip verification) but `repository.full_name` = `secured-org/some-repo` (to target a real, secured stack).

### Impact Explanation
This achieves an unauthenticated cross-organization write: an attacker forges a `push` webhook that is never actually verified against the target organization's secret, yet it causes `Stack#sync_github` to run against that organization's stack, triggering commit ingestion/build-status side effects tied to a repository the attacker was never authorized to touch. This matches the "cross-repository writes" / "unauthorized deploy pipeline mutation" class of High/Critical impact defined in scope, because the binding "signature verified for org X" == "repository mutated belongs to org X" is broken.

### Likelihood Explanation
Requires a multi-org Shipit deployment where at least one configured GitHub App entry has no `webhook_secret` — a configuration explicitly permitted and documented as optional in `docs/setup.md`. No token, session, or repository write access is needed; only knowledge of the target repository's `full_name` and the unsecured organization's login, both of which are typically public information.

### Recommendation
After identifying the `Repository`/`Stack` to act on via `repository.full_name`, verify that its `owner` matches the organization whose `webhook_secret` actually validated the signature (or require every configured organization to have a mandatory, non-optional `webhook_secret`), rejecting any event where these two do not match.

### Proof of Concept
1. Configure `secrets.yml` with two orgs: `orga` (no `webhook_secret`) and `orgb` (`webhook_secret: "s3cret"`), each installed as documented in `docs/setup.md`.
2. `Repository` `orgb/production-app` exists with an active `Stack`.
3. Attacker POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "repository": { "owner": { "login": "orga" }, "full_name": "orgb/production-app" },
  "ref": "refs/heads/master",
  "after": "<attacker chosen sha>"
}
```
   with no valid `X-Hub-Signature` (or any arbitrary value).
4. `verify_signature` calls `Shipit.github(organization: "orga")`; since `orga` has no `webhook_secret`, `verify_webhook_signature` returns `true` regardless of the header value.
5. `PushHandler.process` resolves `Repository.from_github_repo_name("orgb/production-app")` and calls `stack.sync_github(expected_head_sha: "<attacker chosen sha>")`, mutating a stack belonging to the fully-secured `orgb` organization without ever presenting a signature validated by `orgb`'s secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
