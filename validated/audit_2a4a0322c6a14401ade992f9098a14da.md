### Title
Webhook signature verification keys off an attacker-supplied organization field, decoupling the "authenticated organization" from the repository actually acted on - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and thus which `webhook_secret`) to verify a webhook against using `repository_owner`, a value read straight out of the unauthenticated JSON body. `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that selected app has no `webhook_secret` configured. Because the organization used for authentication and the repository whose data is later written (`repository.full_name`, used by `Handler#repository_name`) are two independent fields inside the same attacker-controlled body, an attacker can pick a "no-secret" organization to pass verification while pointing the rest of the payload at a different, protected stack/organization.

### Finding Description
`verify_signature` derives the authenticating organization purely from the payload: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` looks up a per-organization config keyed by that same attacker-supplied string once the app is running in multi-org mode: [3](#0-2) 

`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the selected org's config has no `webhook_secret` — a documented, supported configuration (see the `webhook_secret: # nil` entries in the multi-org fixture): [4](#0-3) [5](#0-4) 

Once the request passes this check, the actual event handlers resolve the target repository/stack from a *different* field of the very same untrusted body, independent of which org was used to authenticate: [6](#0-5) 

This is the same class of bug as the report: two values that are supposed to move together (`DOMAIN_SEPARATOR()`/cached separator built from name vs. the live `token.name`) are instead independently derived, so verifying one does not guarantee the other is trustworthy. Here the equality that should hold is `organization authenticated == organization owning the repository being written`, but nothing enforces it — `repository_owner` (used to pick the verification secret) and `repository.full_name` (used to pick the target `Stack`) are both attacker-supplied and can be set inconsistently.

The `membership` event handler is the most dangerous consequence because it does not re-derive its data from the GitHub API — it trusts the webhook body directly to create `Team` and `Membership` rows: [7](#0-6) 

### Impact Explanation
If any configured GitHub App/organization in a multi-org Shipit deployment has no `webhook_secret` set (an explicitly supported configuration), an unauthenticated attacker can send a forged `membership` webhook claiming that "no-secret" organization as `organization.login`, adding an arbitrary GitHub login (including their own) to any `Team`. If that team's handle is one of `Shipit.github_teams`, the attacker instantly becomes `authorized?` in Shipit and gains full application access — a direct escalation into `Shipit.github_teams` authorization, matching the "High" impact bar. It can also be used to forge `push`/`status`/`check_suite` events for stacks belonging to organizations other than the one whose (missing) secret was used to pass verification.

### Likelihood Explanation
This requires a specific but realistic operator misconfiguration: a multi-organization Shipit deployment (`Shipit.github_default_organization` present) where at least one configured organization omits `webhook_secret`. The engine's own test fixtures model exactly this configuration as valid (`secrets_double_github_app.yml`), and `verify_webhook_signature`'s `return true unless webhook_secret` makes the omission silently permissive rather than failing closed. No repository write access, session, or API token is needed — only knowledge (or discovery) that one configured org lacks a secret.

### Recommendation
Fail closed instead of open when `webhook_secret` is blank for a per-organization config in multi-org mode (only allow the "no secret configured" bypass for legacy single-app deployments, or better, require a secret unconditionally). Additionally, cross-check that the organization used to select/verify the webhook secret matches the owner of `repository.full_name` (or `organization.login`) actually referenced by the payload before invoking handlers, so authentication and the acted-upon resource are bound to the same value.

### Proof of Concept
1. Operate a multi-org Shipit instance where org `NoSecretOrg` is configured without `webhook_secret` (per `lib/shipit/github_app.rb#L76-77`, a supported config).
2. POST to `/webhooks` with header `X-Github-Event: membership` and body:
```json
{
  "action": "added",
  "organization": {"login": "NoSecretOrg"},
  "team": {"id": 123, "name": "Developers", "slug": "shopify-developers", "url": "https://example.com"},
  "member": {"login": "attacker-github-login"}
}
```
No valid `X-Hub-Signature` is required because `repository_owner` resolves to `NoSecretOrg`, whose `verify_webhook_signature` short-circuits to `true` (`lib/shipit/github_app.rb#L76-77`).
3. The `MembershipHandler` (exercised identically in `test/controllers/webhooks_controller_test.rb#L129-149`) creates the `Team` and `Membership` directly from the forged payload.
4. If `Team#slug` matches an entry in `Shipit.github_teams`, `attacker-github-login`'s Shipit `User` now satisfies `authorized?` (`app/models/shipit/user.rb#L80-82`), granting full access to the Shipit instance without ever authenticating through GitHub OAuth.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
