### Title
Missing `return` after caught hashing exception causes duplicate async callback invocation / crash while processing a crafted private-payment chain - ([File: network.js])

### Summary
`getSourceString()` (used by `objectHash.getBase64Hash`) throws for a number of malformed but attacker-reachable values (`null`, `NaN`/`Infinity`, `00`-byte strings, empty arrays/objects, `undefined` fields). A private-payment counterparty can craft such a value inside `payload` of a private-payment chain element. When that malformed payload is later reprocessed from `unhandled_private_payments`, the resulting exception is caught but the enclosing function does not `return`, so execution falls through and performs additional, conflicting work using an uninitialized variable, ultimately double-invoking the `async.each` iteratee callback — an unhandled-error condition that crashes the node process (denial of service), analogous to the CVE-2021-1405 pattern of an improperly initialized variable causing a fault in unauthenticated attacker-supplied content.

### Finding Description
The bug is in `network.js`, function `handleSavedPrivatePayments` → inner `validateAndSave`: [1](#0-0) 

```js
var validateAndSave = function(){
    var objHeadPrivateElement = arrPrivateElements[0];
    try {
        var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
    }
    catch (e) {
        console.log("getBase64Hash failed for private element", objHeadPrivateElement.payload, e);
        if (ws)
            sendResult(ws, {private_payment_in_unit: row.unit, result: 'error', error: e.toString()});
        deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
    }
    var key = 'private_payment_validated-'+objHeadPrivateElement.unit+'-'+json_payload_hash+'-'+row.output_index;
    privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, { ... });
};
```

If `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` throws (which it does for many malformed `payload` shapes, per `getSourceString`'s explicit throw conditions: `null` values, `NaN`/`Infinity` numbers, strings containing the `\x00` join char, empty arrays/objects, or `undefined` object fields — see `string_utils.js` lines 14-54), the `catch` block:
1. Logs the error,
2. Calls `deleteHandledPrivateChain(..., cb)` — which asynchronously calls `cb()` once the DB delete completes.

But there is **no `return`** after the catch block. Execution falls through to:
- `var key = ... + json_payload_hash + ...` — using the now-`undefined` `json_payload_hash` (uninitialized variable read, directly analogous to the CVE's "improper variable initialization"), and
- `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})`, which independently calls `cb()` a second time via one of its `ifOk`/`ifError`/`ifWaitingForChain` handlers.

This means the `async.each` iteratee `cb` for that row gets invoked **twice**. `async`'s `each`/`eachOf` implementations throw ("Callback was already called") or otherwise corrupt control flow when the iteratee callback fires more than once for the same item. Since this occurs inside a `db.query` callback executed outside any request-scoped try/catch, an exception thrown here is unhandled and will crash the Node.js process — a denial of service.

### Impact Explanation
This is reachable by any private-payment counterparty (or paired device forwarding a chain) sending a `private_payments` message with a crafted element whose `payload` fails `getSourceString`'s well-formedness checks (e.g., containing a `null` sub-value, `NaN`, or an object with an `undefined` field slipped through `JSON.stringify`/`JSON.parse` round-tripping is unlikely, but a `null` array element or a `0`-length array/object is a straightforward, JSON-representable trigger). The malformed chain is accepted into `unhandled_private_payments` by `handleOnlinePrivatePayment` with only shallow structural checks (`isNonemptyObject(e.payload)`, `isNonemptyString`, `isNonemptyArray`) — no deep-content validation is performed before storage: [2](#0-1) 

When `handleSavedPrivatePayments` later reprocesses the row, the double-callback bug fires, crashing the node's wallet/network process — a network-facing DoS triggerable by a private-payment counterparty, matching the "node unable to confirm/process" impact class allowed by the validation rules.

### Likelihood Explanation
The crafted payload only needs to pass the shallow checks in `handlePrivatePaymentChains`/`handleOnlinePrivatePayment` (nonempty array/object/string checks) while still containing a value that trips one of `getSourceString`'s explicit throw conditions (e.g., a `null` entry inside `outputs`/`inputs`, or a `0`-length nested array). This is easily achievable by any peer that can send a `private_payments` websocket message, without needing any privileged role, and does not require winning any race — the code path is deterministic once the malformed row is dequeued by `handleSavedPrivatePayments`.

### Recommendation
Add a `return;` immediately after the `catch` block in `validateAndSave` (network.js, after line 2477) so that once `deleteHandledPrivateChain(..., cb)` is invoked on the hashing-failure path, the function does not continue to also call `privatePayment.validateAndSavePrivatePaymentChain`. Additionally, guard against `json_payload_hash` being used while `undefined` by only building `key` and proceeding when the `try` block succeeds.

### Proof of Concept
1. As a correspondent device or peer, send a `private_payments` message whose chain element has a syntactically valid `payload` (passing `isNonemptyObject`/`isNonemptyArray`/`isNonemptyString` checks) but contains a value that fails `getSourceString`, e.g. an `outputs` array containing an element with a nested empty array/object, or an inputs/outputs array containing `null`.
2. The victim's `handleOnlinePrivatePayment`/`savePrivatePayment` stores this chain unvalidated into `unhandled_private_payments`.
3. When `handleSavedPrivatePayments` runs (triggered periodically / on new unit save), it calls `validateAndSave`, which calls `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)`, throwing inside `getSourceString` due to the crafted malformed value.
4. The `catch` block calls `deleteHandledPrivateChain(..., cb)` (async `cb()` eventually), but execution falls through and also calls `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})`, which calls `cb()` again through one of its callbacks.
5. `async.each`'s iteratee callback fires twice for the same item, throwing/erroring in a context with no surrounding try/catch, crashing the process. [3](#0-2) [4](#0-3)

function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);
