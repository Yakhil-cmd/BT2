### Title
Malicious swap route can add unauthorized token transfers to the caller's authorization tree - (File: contracts/controller/src/strategies/swap.rs)

### Summary
An attacker-supplied route can direct the configured swap aggregator to an unallowlisted pool contract. That contract executes inside the victim-authorized `swap_collateral` transaction and can invoke `token.transfer(victim, attacker, amount)` on any unrelated token. Simulation records this as a sub-invocation beneath the victim's controller authorization; if the victim signs the poisoned authorization tree, the rogue pool steals unrelated wallet assets while still delivering valid swap output. The controller bounds only its own input transfer and measured output, not arbitrary caller-authorized sub-invocations reached through route-controlled contracts. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Controller::swap_collateral(caller, account_id, current, amount, new, swap)` accepts opaque route bytes and requires `caller.require_auth()` before calling the configured router. [4](#0-3) [5](#0-4) 

The controller grants the router only an exact transfer of `amount_in` from the controller to the router and verifies the controller's balance deltas afterward. Those checks bound the protocol's routed funds, but they do not prevent route-selected contracts from making additional calls that require the original caller's authority. [6](#0-5) 

The swap payload selects pool contracts by registry index, and no venue allowlist validates those addresses. For a Soroswap hop, the router invokes `get_reserves` and `swap` on the payload-selected `pool`, so attacker-deployed code runs below the caller-authorized controller invocation. [7](#0-6) [8](#0-7) 

Soroban authorization attaches nested calls requiring the caller's authority to the caller's authorization tree. A malicious pool can therefore add a child `token.transfer(victim, attacker, amount)` for an unrelated wallet token. Simulation records that child, and transaction execution succeeds if the submitted authorization tree includes it. The repository's regression test demonstrates this exact behavior through `swap_collateral`: recording mode attaches the rogue transfer under Alice's `swap_collateral` entry, and enforcing mode moves the wallet token when that child is signed. [9](#0-8) [10](#0-9) 

### Impact Explanation
Theft of user funds. The victim can lose tokens unrelated to the lending position and outside the routed `token_in` amount. The malicious pool can still satisfy the route's minimum output—either by returning genuine output or by being funded with the output token—so the swap can appear economically successful while unrelated wallet funds are transferred to the attacker. The test demonstrates an unrelated `WALLET_BALANCE` moving from Alice to the attacker while Alice receives the expected ETH collateral output. [11](#0-10) 

The attacker cannot take wallet tokens without the victim's authorization. Exploitation requires the victim to submit a transaction whose simulated authorization tree includes the rogue child transfer, but the route itself is opaque and the malicious destination is selected by attacker-supplied route data.

### Likelihood Explanation
An unprivileged attacker can deploy the malicious pool and provide a route containing its address. The controller accepts caller-provided `swap` bytes, and the production router's program format treats pool addresses as payload-supplied registry entries rather than trusted configuration. [12](#0-11) [13](#0-12) 

The attack is user-assisted rather than fully permissionless: the victim must sign the authorization tree returned by simulation. The likelihood is nevertheless material where wallets or clients do not clearly decode and display every nested token transfer, particularly because the root request remains an ordinary `swap_collateral` operation. This is analogous to the symlink report: attacker-controlled data redirects execution outside the operation's expected boundary, while the visible operation still completes.

### Recommendation
Do not execute arbitrary, unallowlisted pool contracts under a caller-authorized strategy invocation.

- Maintain governance-approved venue pool registries and reject payload-selected pools not registered for the declared venue.
- If generic pools must remain supported, execute them in an isolated contract that receives no authority beneath the user's invocation, or require a separate explicit authorization step for any non-allowlisted hop.
- At the client/API boundary, reject any `swap_collateral`, `swap_debt`, `multiply`, or `repay_debt_with_collateral` authorization tree containing children other than the expected controller-to-router input transfer.
- Add a regression test for production router execution proving that a payload-selected pool cannot add a caller token transfer beneath the strategy authorization.

### Proof of Concept
1. Alice has a debt-free account with USDC collateral and holds an unrelated token `WALLET`.
2. Attacker deploys `RoguePool` configured with `(victim=alice, wallet_token=WALLET, to=attacker, amount=alice_wallet_balance)`.
3. `RoguePool.get_reserves()` returns reserves sufficient for a positive Soroswap quote.
4. `RoguePool.swap(amount_0_out, amount_1_out, to)` calls `WALLET.transfer(alice, attacker, amount)` and also transfers the requested output token to the router.
5. Attacker gives Alice a `swap_collateral` route whose Soroswap hop uses `RoguePool` as the pool address.
6. Alice calls:

   `swap_collateral(alice, account_id, USDC_hub_asset, 5_000_USDC, ETH_hub_asset, malicious_swap_xdr)`

7. Transaction simulation records an authorization rooted at `Controller.swap_collateral`, with a child `WALLET.transfer(alice, attacker, amount)`.
8. If Alice signs that poisoned tree, `RoguePool.swap` executes, `WALLET` is transferred to the attacker, the router receives positive ETH output, and the controller deposits that output into Alice's position.
9. The repository test `simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry` verifies the recorded child and theft, while `enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer` verifies the signed execution path. pub(crate) fn swap(ctx: &HopContext<'_>) {
    let token_in_is_0 = ctx.hop.token_in < ctx.hop.token_out;

    let no_args: Vec<Val> = vec![ctx.env];
    let (reserve_0, reserve_1): (i128, i128) = ctx.env.invoke_contract(
        &ctx.hop.pool,
        &Symbol::new(ctx.env, "get_reserves"),
        no_args,
    );
    let (reserve_in, reserve_out) = if token_in_is_0 {
        (reserve_0, reserve_1)
    } else {
        (reserve_1, reserve_0)
    };

    let requested_out = soroswap_amount_out(ctx.env, ctx.amount_in, reserve_in, reserve_out);
    if requested_out <= 0 {
        panic_with_error!(ctx.env, Error::ZeroOutput);
    }

    let token_client = token::Client::new(ctx.env, &ctx.hop.token_in);
    token_client.transfer(ctx.router, &ctx.hop.pool, &ctx.amount_in);

    let (amount_0_out, amount_1_out) = if token_in_is_0 {
        (0_i128, requested_out)
    } else {
        (requested_out, 0_i128)
    };
    let args: Vec<Val> = vec![
        ctx.env,
        amount_0_out.into_val(ctx.env),
        amount_1_out.into_val(ctx.env),
        ctx.router.into_val(ctx.env),
    ];
    let _: () = ctx
        .env
        .invoke_contract(&ctx.hop.pool, &symbol_short!("swap"), args);
}

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
