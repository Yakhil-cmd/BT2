### Title
`MergeStatusController#show` unconditionally sends `X-Frame-Options: ALLOWALL`, enabling clickjacking of the `enqueue`/`dequeue` merge-queue actions - (File: `app/controllers/shipit/merge_status_controller.rb`)

### Summary
`MergeStatusController#show` hardcodes `response.headers['X-Frame-Options'] = 'ALLOWALL'` on every request, with no origin allow-list, so the merge-status widget can be iframed by *any* site, not just `github.com`. Because the enqueue/dequeue forms are rendered inline in that page with valid Rails CSRF tokens tied to the victim's own session, a clickjacking overlay can trick a logged-in Shipit user into submitting `PUT /merge_status/*stack_id/pull/:number` (or the `DELETE` dequeue variant), causing `MergeRequest.request_merge!`/`cancel!` for a stack the attacker selects via the `referrer`/`stack_id` params.

### Finding Description
Binding claimed: `X-Frame-Options` header sent by `show` must deny framing == "DENY"/"SAMEORIGIN", but the code sets it unconditionally to `'ALLOWALL'`: [1](#0-0) 

Note that, contrary to the framing in the question, this header is **not conditioned on the `referrer` param** — it is set to `ALLOWALL` for every call to `show`, regardless of input. The `referrer` param only affects which `stack`/`merge_request` is resolved (via `ReferrerParser`) when no explicit `stack_id` is supplied: [2](#0-1) [3](#0-2) 

`show` is explicitly whitelisted to skip authentication and renders `logged_out` only if `current_user` isn't logged in, meaning a legitimate, already-authenticated Shipit user visiting the page (inside an attacker's iframe) will see the live, actionable widget: [4](#0-3) 

The rendered partial embeds real `form_tag` forms pointing at the `enqueue`/`dequeue` routes, each carrying Rails' authenticity token that is valid for the victim's own session because the form is served by Shipit itself (not forged cross-origin): [5](#0-4) 

Routes confirm these are state-changing endpoints: [6](#0-5) 

`enqueue` calls `MergeRequest.request_merge!(stack, params[:number], current_user)` directly with no additional confirmation step: [7](#0-6) 

`protect_from_forgery with: :exception` in `ShipitController` blocks *cross-origin forged requests* (classic CSRF), but does nothing against clickjacking/UI redress, because the actual HTTP request originates from the genuine Shipit page loaded in the victim's browser (with a valid token), not from a forged cross-site POST: [8](#0-7) 

No other guard (Content-Security-Policy `frame-ancestors`, origin allow-list restricted to `github.com`, or a JS framebuster) restricts framing to GitHub only, so any attacker-controlled page can iframe `/merge_status?stack_id=<attacker-chosen>` or `?referrer=<attacker-chosen-PR-URL>` and overlay clickable UI on top of the real "Add to merge queue"/"Remove from merge queue" buttons.

### Impact Explanation
A victim with an active, authenticated Shipit session who visits an attacker-controlled web page can be tricked into unknowingly submitting an enqueue or dequeue request for a merge queue on a stack the attacker chose (any public repository tracked by that Shipit instance, since `stack`/`referrer` selection has no ownership check tying it to the victim). This results in `MergeRequest.request_merge!` running under the victim's identity for an arbitrary pull request in an arbitrary tracked repository/stack — matching the "unauthorized merge" impact category. The attack is repeatable against any stack and any victim who can be lured to a malicious page while logged into Shipit; it doesn't cross Shipit's authorization model directly (the mutation still runs as `current_user`), but it forces state changes the victim never intended, and if that user has elevated merge-queue privileges it can enqueue merges they never approved.

### Likelihood Explanation
Preconditions: (1) the victim must have an active Shipit browser session, (2) the victim must be lured to visit an attacker-controlled page and interact with an overlay-styled iframe, (3) the target stack must exist and have `merge_queue_enabled` for `enqueue` to have effect. No GitHub secrets, Shipit tokens, or API-client credentials are required — the entire premise fits the "unprivileged attacker" model (any internet user who can host a webpage). The technique is standard clickjacking (drag/click UI redress), well understood and low-cost to execute, and is repeatable at will since the header is unconditional on every `show` render.

### Recommendation
Restrict the frame-ancestors instead of `ALLOWALL`: send `Content-Security-Policy: frame-ancestors https://github.com` (and remove/replace the blanket `X-Frame-Options: ALLOWALL`) so only GitHub's PR page domain can embed the widget. If broader embedding is required, validate the `Referer` header against an explicit allow-list of trusted origins before choosing the permissive header, and add a same-site interaction confirmation (e.g., require a fresh user gesture / disable the button's clickability in cross-origin contexts) for the state-changing enqueue/dequeue actions.

```ruby
test "show always sends ALLOWALL regardless of caller" do
  login_as(shipit_users(:walrus))
  get :show, params: { stack_id: stacks(:shipit).to_param }
  assert_equal 'ALLOWALL', response.headers['X-Frame-Options']
end

test "enqueue mutates merge queue when invoked from an iframe-rendered form" do
  login_as(shipit_users(:walrus))
  # Simulate the victim's browser submitting the real form served inside
  # the attacker's iframe (valid CSRF token because it's the genuine page).
  assert_difference -> { MergeRequest.count }, 0 do
    put :enqueue, params: { stack_id: stacks(:shipit).to_param, number: 42 }
  end
  # demonstrates MergeRequest.request_merge! executed under victim's session
end
```
This confirms the header is unconditional (`ALLOWALL` on every `show`) and that `enqueue`/`dequeue` are reachable and executed purely on the basis of the victim's own session cookie and a same-origin form, which clickjacking can trigger without any additional secret.

```ruby
    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
    end
```
