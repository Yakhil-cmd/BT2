### Title
Bridge Operator Can Pass Arbitrary `_value = 0` to `handleKLAYTransfer` / `handleERC20Transfer`, Consuming the Request Nonce While Delivering Zero Assets — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `contracts/service_chain/bridge/BridgeTransferERC20.sol`)

---

### Summary

`handleKLAYTransfer` and `handleERC20Transfer` accept `_value` as a fully operator-controlled parameter. The on-chain vote key is `keccak256(msg.data)`, which binds the vote to the exact calldata including `_value`. With the default operator threshold of **1** (set in the `BridgeOperator` constructor), a single operator can call either function with `_value = 0`, pass the vote unilaterally, permanently consume the request nonce, and send the user zero KAIA or zero ERC-20 tokens — while the user's assets on the source chain are already locked or burned.

---

### Finding Description

**`BridgeOperator` constructor sets threshold = 1 by default:**

```solidity
// BridgeOperator.sol:54-57
constructor() internal {
    for (uint8 i = 0; i < uint8(VoteType.Max); i++) {
        operatorThresholds[uint8(i)] = 1;   // default: single operator suffices
    }
```

**Vote key is `keccak256(msg.data)` — includes `_value`:**

```solidity
// BridgeOperator.sol:109-111
bytes32 voteKey = keccak256(msg.data);
if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
    closedValueTransferVotes[_requestNonce] = true;
```

Because the vote key commits to the full calldata, operators must agree on the **exact** `_value`. With threshold = 1, no agreement is needed — a single operator's call with any `_value` immediately closes the vote.

**`handleKLAYTransfer` sends exactly `_value` to the user:**

```solidity
// BridgeTransferKLAY.sol:77-99
if (!_voteValueTransfer(_requestedNonce)) { return; }
// ... nonce consumed, state updated ...
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
```

**`handleERC20Transfer` mints or transfers exactly `_value`:**

```solidity
// BridgeTransferERC20.sol:47-72
if (!_voteValueTransfer(_requestedNonce)) { return; }
// ...
if (modeMintBurn) {
    require(ERC20Mintable(_tokenAddress).mint(_to, _value), ...);
} else {
    IERC20(_tokenAddress).safeTransfer(_to, _value);
}
```

There is **no on-chain record** of the original `valueOrTokenId` from the source-chain `RequestValueTransfer` event. The destination bridge contract trusts whatever `_value` the operator supplies.

---

### Impact Explanation

A malicious bridge operator calls:

```
handleKLAYTransfer(txHash, from, to, 0 /*_value*/, N, blockNum, extraData)
```

With threshold = 1:
1. `_voteValueTransfer(N)` returns `true` immediately.
2. `closedValueTransferVotes[N] = true` — nonce `N` is **permanently consumed**; no legitimate relay can ever process it again.
3. `_to.call.value(0)("")` — user receives **0 KAIA**.
4. The user's KAIA on the source chain is already locked in (or burned by) the source bridge and is unrecoverable.

The same attack applies to `handleERC20Transfer` with `_value = 0`, resulting in `mint(_to, 0)` or `safeTransfer(_to, 0)` — zero tokens delivered, nonce consumed, source-chain assets lost.

**Corrupted value:** `_value` is set to `0` instead of the legitimate transfer amount `V`. The user loses `V` KAIA (or `V` ERC-20 tokens) permanently.

**Allowed impact match:** Unauthorized burn/lock of bridged KAIA/ERC-20 assets and nonce consumption affecting system-managed bridge funds.

---

### Likelihood Explanation

- The default `operatorThresholds[ValueTransfer] = 1` means **every newly deployed bridge** is vulnerable until the owner explicitly raises the threshold.
- The Go relay daemon (`node/sc/bridge_manager.go:333`) passes `valueOrTokenId` from the observed event, but the Solidity contract imposes no constraint — any operator can deviate.
- The attack is subtle: the operator calls the correct function with the correct nonce and a valid `_requestTxHash`; only `_value` is zeroed. Off-chain monitoring that checks only nonce progression would not detect the manipulation.
- A single compromised or malicious operator key is sufficient; no collusion is required.

---

### Recommendation

1. **Commit the transfer value into the request hash on the source chain** and verify it on the destination chain. Store `keccak256(from, to, value, nonce)` in `handledRequestTxHashes` and require the operator-supplied parameters to reproduce it.
2. **Require threshold ≥ 2** for all production bridge deployments and enforce this in the deployment scripts, so that `_value` manipulation requires collusion of at least two operators.
3. **Emit and cross-check the source-chain event value** in the Go relay (`node/sc/bridge_manager.go`) against the on-chain state before submitting the handle transaction.

---

### Proof of Concept

```
Setup:
  - Bridge deployed with default threshold = 1
  - One operator registered (owner is operator by default)
  - Bridge funded with 1000 KAIA

Step 1 (source chain):
  User calls requestKLAYTransfer(userAddr, 100 KAIA)
  → RequestValueTransfer emitted: value=100, nonce=0
  → 100 KAIA locked in source bridge

Step 2 (destination chain — malicious operator):
  operator.handleKLAYTransfer(
      txHash,   // valid source tx hash
      user,     // from
      user,     // to
      0,        // _value  ← set to 0 instead of 100
      0,        // _requestedNonce
      blockNum,
      ""
  )

Result:
  - _voteValueTransfer(0) returns true (threshold=1, single vote suffices)
  - closedValueTransferVotes[0] = true  ← nonce 0 permanently consumed
  - _to.call.value(0)("") succeeds      ← user receives 0 KAIA
  - User's 100 KAIA on source chain is permanently locked/lost
  - Any subsequent legitimate handleKLAYTransfer for nonce 0 reverts: "closed vote"

    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }
