### Title
`pull_request` webhook signature verification keyed on `repository.owner.login` diverges from `LabelCapturingHandler`'s repository resolution via `repository.full_name`, letting an attacker forge labels onto a victim's `ReviewStack` and inject env vars into bot-triggered deploys - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/`webhook_secret` to verify a webhook against using `repository_owner`, derived from `params.dig('repository','owner','login')`. `LabelCapturingHandler` (and its siblings) independently resolve the target repository/stack from `params.repository.full_name` via `Repository.from_github_repo_name`. These two fields are never cross-checked, so an attacker can pick an org with no `webhook_secret` configured for signature verification while pointing `full_name` at a different, victim org's repository.

### Finding Description
The broken binding: the code implicitly assumes `params.repository.owner.login == params.repository.full_name.split('/').first`, but this is never enforced anywhere in the request path.

- `verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login')` and calls `Shipit.github(organization: repository_owner)` [1](#0-0) [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever `webhook_secret` is blank for that organization's config: `return true unless webhook_secret` [3](#0-2) .
- In the multi-org config schema (`Shipit.github(organization:)` keyed per top-level org, per `docs/setup.md` "Using Multiple Github Applications"), any org without a `webhook_secret` set passes verification for free [4](#0-3) .
- `LabelCapturingHandler#repository` resolves the actual acted-upon repository purely from `params.repository.full_name`, with no relation to `repository_owner`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [5](#0-4) .
- On `action == "opened"` with a pre-existing (non-archived) stack for that PR, `capture_labels` overwrites `stack.pull_request.labels` with attacker-supplied label names from the payload [6](#0-5) .
- Those labels become uppercased env vars merged into `ReviewStack#env`, which flows into `Shipit::TaskCommands#env` and ultimately into `PTY.spawn`'d deploy commands: `labels[label_name.upcase] = "true"` [7](#0-6) [8](#0-7) . This is directly demonstrated by the existing test asserting `WIP`/`BUG` env vars from labels [9](#0-8) .
- Auto-triggered continuous delivery runs deploys as `Shipit.user`, which resolves to the configured `bot_login` when set: `Stack#trigger_continuous_delivery` calls `trigger_deploy(commit, Shipit.user, ...)` [10](#0-9) , and `Shipit.user` returns the bot-login-derived `User` [11](#0-10) .

Exploit flow: attacker creates/controls an org "AttackerOrg" (a real GitHub org, or any org name accepted by the multi-org config that has no `webhook_secret` configured on the Shipit host — this is operator configuration, not attacker-controlled). Attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `{"action":"opened","repository":{"owner":{"login":"AttackerOrg"},"full_name":"VictimOrg/victim-repo"},"pull_request":{...,"labels":[{"name":"SOME_MALICIOUS_ENV=value"}]},...}`. `verify_signature` looks up `Shipit.github(organization: "AttackerOrg")`, whose `webhook_secret` is unset, so verification is skipped (`return true unless webhook_secret`). The handler then resolves `VictimOrg/victim-repo`'s stack and overwrites its `PullRequest#labels`.

Why existing guards fail: there is no `ExplicitParameters` validation, model validation, or controller check that `repository.owner.login` matches the first path segment of `repository.full_name`; `drop_unhandled_event` only checks the event type exists, not payload consistency; `force_github_authentication`/`User#authorized?` are session-based controls irrelevant to unauthenticated webhook delivery.

### Impact Explanation
This is a payload for one repository (attacker's low-value/no-secret org) mutating another organization's stack and, through `ReviewStack#env`, injecting attacker-chosen uppercase-named environment variables into the next auto-triggered (bot-driven, `continuous_deployment: true`) deploy for the victim's review stack. This matches the Critical category "a payload for one repository mutating another's stack" and can lead to unauthorized/altered deploy behavior since deploy scripts read `ENV` for feature flags/behavior toggles named after labels. Repeatable against any org/repository as long as the operator has a permissive-webhook-secret org configured under the multi-org schema, and it is not scoped to a single victim — any review stack with a matching PR number in any org resolvable via `full_name` is affected.

### Likelihood Explanation
Requires the Shipit deployment to be configured with the multi-org `github:` config schema (`docs/setup.md` "Using Multiple Github Applications") and at least one configured org with `webhook_secret` unset/blank — this is a real, documented, supported configuration, not a hypothetical. Requires a victim review stack (PR-based) to exist for the targeted `full_name` repository with a matching PR number, and `bot_login`/continuous delivery configured to amplify impact. Attacker cost is low: no GitHub secrets, tokens, or Shipit session needed — only knowledge of the victim org/repo name and PR number, both public information. Fully repeatable and scriptable.

### Recommendation
Enforce that `repository.owner.login` (used to select the signing secret) matches the owner segment of `repository.full_name` before dispatching to handlers, e.g. reject the webhook if `params.dig('repository','full_name')&.split('/')&.first&.downcase != repository_owner&.downcase`. Additionally, do not treat a missing `webhook_secret` as "verified"; instead, require an explicit secret per configured organization or fail closed.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure `Shipit.secrets.github` with two orgs: `attackerorg` (no `webhook_secret`) and `victimorg` (with `webhook_secret`), via a fixture similar to `test/dummy/config/secrets_double_github_app.yml`.
2. Create a `Shipit::Repository` `victimorg/victim-repo` with an active, non-archived `Shipit::ReviewStack` for PR number `42`, with `continuous_deployment: true` and `bot_login` configured.
3. POST to `/webhooks` with header `X-Github-Event: pull_request`, no valid `X-Hub-Signature` (or one computed for the empty/no secret), and body: `action: "opened"`, `repository.owner.login: "attackerorg"`, `repository.full_name: "victimorg/victim-repo"`, `pull_request.number: 42`, `pull_request.labels: [{name: "INJECTED_ENV"}]`.
4. Assert response is not `422` (i.e., signature check passed).
5. Assert `stack.reload.pull_request.labels` now includes `"INJECTED_ENV"` — proving a request "signed" under `attackerorg`'s (secret-less) identity mutated `victimorg`'s stack.
6. Assert `stack.env["INJECTED_ENV"]` equals `"true"`, and that this value would be merged into `Shipit::TaskCommands#env` for the next deploy, confirming the equality `repository_owner (attackerorg) != full_name_owner (victimorg)` was never checked while the mutation still succeeded.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
