### Title
i128 overflow in share×index multiplication during accrual permanently freezes a large market - (File: common/src/rates/index.rs)

### Summary
The analog of CVE-2025-48175 (integer overflow in a multiplication that converts one representation to another) maps directly onto XOXNO Lending's RAY share/index accounting. Every pool op accrues first via `global_sync`, and accrual multiplies total scaled shares by the live index in plain `i128`. For a sufficiently large market the products `borrowed * borrow_index` and `supplied * supply_index` overflow `i128` and panic with `MathOverflow` **before** the `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY` caps can engage. From that point every state-changing verb on the market reverts forever: no `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, `update_indexes`, or `recapitalize`. This is proven by an existing test, `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`, which asserts `MATH_OVERFLOW` on `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` once the cliff is reached.

### Finding Description
`update_borrow_index` caps the index after growth, but `calculate_supplier_rewards` first computes `borrowed.mul(env, new_borrow_index)` and `borrowed.mul(env, old_borrow_index)`, and `update_supply_index` computes `supplied.mul(env, old_index)` — all `Ray::mul` → `fp_core::mul_div_half_up`, which computes `x * y / RAY` and panics with `GenericError::MathOverflow` when the product or result does not fit `i128` (even the `I256`-widened intermediate path panics if the final quotient exceeds `i128::MAX`). [1](#0-0) [2](#0-1) [3](#0-2) 

`Cache::calculate_utilization` performs the same `scaled_to_original` multiply on `borrowed`/`supplied` before interest math, so the panic fires inside `accrue_step`/`global_sync` on every invocation. [4](#0-3) [5](#0-4) 

The index caps are checked against `new_index` (a value around `MAX_BORROW_INDEX_RAY`), but the overflow happens on `shares * index`, whose ceiling is `i128::MAX / index` — a bound on *total market value*, not the index. Once `borrowed × borrow_index > i128::MAX`, accrual reverts, `last_timestamp` is never updated, and the freeze is permanent and unrecoverable.

### Impact Explanation
Permanent freezing of funds and an effective protocol freeze for that market: suppliers cannot withdraw, borrowers cannot repay or be liquidated, bad debt cannot be cleaned or recapitalized, and flash loans against the market fail — because every entrypoint calls `global_sync` first and hits the same panic. The existing test demonstrates all three of `update_indexes`, `withdraw`, and `repay` reverting with `MATH_OVERFLOW` after the cliff. [6](#0-5) 

### Likelihood Explanation
Reachable by unprivileged addresses using only `supply` and `borrow`, but requires a very large market: the test uses ~10^9 tokens of an 18-decimal asset supplied and ~98% borrowed on a steep rate curve, after which sustained high utilization grows the RAY-denominated debt value past `i128::MAX` (~1.7e38) while `borrow_index` is still ~170× — far below `MAX_BORROW_INDEX_RAY`. Realizability depends on the listed market's supply/borrow caps permitting that scale and on years of high utilization (or an attacker holding utilization high); the caps are governance-set, so the window exists only on markets configured with very high caps on high-decimal assets. Time does the rest — no privileged action is needed once the market exists at scale. This is uncertain to the extent that currently listed caps are not visible in-scope; the test harness had to lift caps to demonstrate it.

### Recommendation
Bound the total value rather than the index: in `accrue_step`/`update_borrow_index`/`update_supply_index`, cap `borrowed` and `supplied` growth (or the new index) such that `scaled × index ≤ i128::MAX`, e.g. clamp `new_index ≤ i128::MAX / scaled` before multiplying, or apply the index cap relative to current shares. Alternatively, make `global_sync` degrade gracefully by freezing accrual (saturation) instead of panicking, so withdrawals and repayments remain possible.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
