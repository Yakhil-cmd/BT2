### Title
Unauthenticated SSE stream exposes live stack/task state via unauthenticated `/events` mount - ([File: config/routes.rb])

### Summary
`config/routes.rb` mounts `Pubsubstub::StreamAction` directly at `/events` as a raw Rack endpoint, bypassing the `Shipit::Authentication` controller concern entirely. The comment in `GithubAuthenticationController#callback` claims a `UserRequiredMiddleware` protects this route, but no such class exists anywhere in the engine, so any unauthenticated internet client can subscribe to arbitrary `stack.ID`/`repository.ID` channels and receive live task/deploy broadcasts.

### Finding Description
The binding claimed by the question is: `GET /events?channels[]=stack.ID` succeeds only if `force_github_authentication` has run AND `current_user.authorized?` is true for the session, matching ownership of the channel's stack/repository.

Tracing the code:
- `config/routes.rb` line 9: `mount Pubsubstub::StreamAction.new, at: "/events", as: :events` [1](#0-0) . This is a `mount` of a plain Rack app, not a Rails controller action, so it never passes through `ActionController::Base#process_action` callbacks.
- `Shipit::Authentication#force_github_authentication` is only invoked via `before_action` when a controller `include`s the `Shipit::Authentication` concern [2](#0-1) . `Pubsubstub::StreamAction` is not a `Shipit` controller and never includes this concern, so `force_github_authentication` and `current_user.authorized?` are never evaluated for `/events` requests.
- `GithubAuthenticationController#callback` sets `session[:authenticated] = true` with a comment claiming `/events` and `/sidekiq` "leverage `UserRequiredMiddleware`" to recognize authentication [3](#0-2) , but a repo-wide search finds no `UserRequiredMiddleware` class definition anywhere — the only occurrence of the string is this comment itself.
- `lib/shipit/engine.rb`'s `shipit.config` initializer only registers `OmniAuth::Builder` and, conditionally, `Shipit::SameSiteCookieMiddleware` — no authentication-enforcing middleware is inserted in front of `/events` [4](#0-3) .

Because both sides of the equality diverge — the route is reachable, but `force_github_authentication`/`current_user.authorized?` never execute — any unauthenticated attacker can `GET /events?channels[]=stack.<id>` (or `repository.<id>`) and receive the live SSE stream that `Stack`/`Task`/`Deploy` models publish for status changes, without ever authenticating.

### Impact Explanation
An unauthenticated internet user can read live deploy/task/merge-queue state (stack status changes, task output progress notifications, merge status updates) for any stack or repository by guessing or enumerating numeric IDs in the channel name, with no session, token, or team membership required. This is a cross-tenant confidentiality breach of live operational state, matching the "unauthenticated read of stack state, task streams, or deploy output" High-severity category. It is fully repeatable against arbitrary stacks/repositories since channel names are simply sequential/enumerable IDs.

### Likelihood Explanation
No preconditions beyond network access to the Shipit host are required — no Shipit session, no GitHub credentials, no repository maintainer status. The attacker only needs to know or guess a stack or repository numeric ID, which is low-cost and easily enumerable (IDs are sequential auto-increment primary keys). This makes the attack trivially and repeatedly executable.

### Recommendation
Do not mount `Pubsubstub::StreamAction` unauthenticated at the routing layer. Wrap it in (or precede it with) a real authentication/authorization check — e.g., implement an actual Rack middleware or a thin controller action that runs `force_github_authentication` and validates that `current_user` is authorized for the specific stack/repository referenced by the requested `channels[]` parameter before delegating to `Pubsubstub::StreamAction`.

### Proof of Concept
```ruby
# test/integration/events_stream_authentication_test.rb
require 'test_helper'

module Shipit
  class EventsStreamAuthenticationTest < ActionDispatch::IntegrationTest
    test "GET /events is not reachable without authentication" do
      stack = shipit_stacks(:shipit)

      # No session cookie, no login, no github auth performed.
      get '/events', params: { channels: "stack.#{stack.id}" }

      # Binding under test: force_github_authentication + current_user.authorized?
      # must gate this request, i.e. response should be 302 to github_authentication_path
      # or 401/403.
      assert_response :redirect
      assert_redirected_to Shipit::Engine.routes.url_helpers.github_authentication_path

      # Actual observed behavior: Pubsubstub::StreamAction serves the SSE
      # response directly (200, text/event-stream), proving the binding is broken.
    end
  end
end
```
