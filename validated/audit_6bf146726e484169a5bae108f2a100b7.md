### Summary
The liquidation planner declares `seize_all` on an insolvent account whenever `repay_usd + one_unit_per_leg_usd(repaid) >= ideal_repayment_usd`, where `ideal_repayment_usd` for an insolvent account is the collateral-backed quote `floor(C / (1 + base))`. The slack term values **one whole base unit of each repaid debt leg in USD**. For any debt asset whose whole unit exceeds the quote — ETH (~$2k+), WBTC, or any mid-price asset against a small insolvent account — a repayment of one stroop satisfies the condition and the liquidator seizes the entire remaining collateral while paying essentially nothing. This mirrors the reported bug class: an operation nominally sized by a USD quote is bypassed by submitting it in arbitrarily small pieces, because the admission check adds a per-leg "one unit" allowance that dwarfs the intended payment. ### Finding Description
In `normalize_repayment_plan`, the plan flags are computed as:

```rust
// contracts/controller/src/positions/liquidation/math.rs
let repay_usd = sum_repaid_usd(env, &final_repayment_tokens);
let seize_all = insolvent
    && repay_usd > Wad::ZERO
    && repay_usd.checked_add(env, one_unit_per_leg_usd(env, &final_repayment_tokens))
        >= ideal_repayment_usd;
```

For an insolvent account, `ideal_repayment_usd` equals `min(D, floor(C × WAD / (WAD + base)))` — the repayment the liquidator is supposed to make to earn the full collateral seizure (`curve quote = (min(D, floor(C/(1+base))), base)` per the bonus-curve spec). The `seize_all` predicate lets the actual payment under-deliver the quote by up to the USD value of one whole unit of each repaid debt leg.

That slack is only safe when one debt unit is small relative to the quote. Nothing in admission constrains this: `MinBorrowCollateralUsd` / `BAD_DEBT_USD_THRESHOLD` is $5, while one unit of a typical debt asset is worth orders of magnitude more (one ETH ≈ $2,000, one BTC ≈ $60k+; even one XLM ≈ $0.25 covers a dust-scale quote). An insolvent account with `ideal` ≈ $476 (C = $500 at 5% base bonus) and an ETH debt leg admits `seize_all` for `repay_usd = 1 wei`, since `1 + $2,000 ≥ $476`. The planner then proceeds as a full-collateral seizure funded by a dust repayment, and the residual debt is socialized to suppliers through `apply_bad_debt_to_supply_index`. [2](#0-1) 

The documented intent is the opposite bound: an insolvent liquidator is capped at "what the collateral backs," paying `floor(C/(1+base))` for the whole collateral. The `seize_all` slack silently converts a bounded rounding tolerance into a near-total payment bypass whenever one debt unit ≥ the backed quote. [3](#0-2) 

### Impact Explanation
Theft of funds / protocol insolvency. The pool pays out the victim's full collateral (real token transfers in `SeizeMode::Transfer`, or share credit in `SeizeMode::Credit`) against a repayment of dust, then the unpaid remainder of the debt is written down against suppliers via the supply-index socialization path (`clean_bad_debt` → `execute_bad_debt_cleanup` → `apply_bad_debt_to_supply_index`). Value that the quote earmarks for the pool — `ideal − actual_paid`, arbitrarily close to the whole collateral — is transferred to the liquidator and socialized onto suppliers. Repeatable on every insolvent account whose debt is denominated in an asset with a unit value above the backed quote, which is the common case for small-to-mid insolvencies.

### Likelihood Explanation
Fully permissionless: `liquidate` requires only `caller.require_auth()` and `HF < 1` on the target; no position ownership or allowlist gates the liquidator. Insolvent accounts arise routinely from price moves, and the exploit needs only a dust payment in the debt asset (flash-loanable for zero effective cost). No privileged state, timing, or oracle manipulation is required — the bypass is deterministic arithmetic in the planner.

### Recommendation
In `normalize_repayment_plan`, bound the `seize_all` slack to a true rounding tolerance rather than a per-leg whole unit — e.g., require `repay_usd` to meet the quote directly, or cap the allowance at the smallest representable fraction of the quote (`ideal_repayment_usd × ε` or one unit only when `one_unit_per_leg_usd ≤ ideal − repay` cannot dominate). At minimum, restrict the whole-unit tolerance to debt markets whose whole-unit USD value is below the dust threshold, and add a regression test where a sub-threshold repayment against an insolvent ETH/BTC-denominated account reverts or seizes only the backed proportion.

### Proof of Concept
1. Market A lists USDC collateral; market B lists ETH borrowable at ~$2,000/unit, 5% `liquidation_fee`/base bonus.
2. Victim supplies ~$500 USDC and borrows ETH; price moves push HF < 1 with C = $500, D = $2,000 (insolvent).
3. Attacker calls `liquidate` with a payment vector containing `amount = 1` (one wei of ETH) on the debt leg.
4. Planning: `ideal = floor(500/1.05) ≈ $476` (WAD); `one_unit_per_leg_usd ≈ $2,000`; `seize_all = (1 wei USD + $2,000) ≥ $476` → true.
5. Execution transfers/wei-pulls dust, seizes the victim's entire $500 USDC collateral position (Transfer mode pays pool cash; Credit mode moves shares).
6. Residual ~$1,524 of ETH debt remains; permissionless `clean_bad_debt` (collateral now zero ≤ $5 dust cap) socializes it via `apply_bad_debt_to_supply_index`, writing it down against USDC suppliers.
7. Net: attacker paid ≈ $0 and received ≈ $500 of collateral; suppliers absorb the remainder.

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```
