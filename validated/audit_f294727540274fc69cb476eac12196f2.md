### Title
Double-Crediting of Bitcoin L1 Lockups Due to Missing Persistent Outpoint Tracking — (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`pox-5.clar`'s `verify-l1-lockups` / `validate-l1-lockup` functions (used to credit a staker's Bitcoin-side lockups toward a bond) deduplicate Bitcoin UTXOs (`outpoint = {txid, output-index}`) only *within a single call's fold*, via a freshly-initialized `seen-outpoints: (list)` accumulator [1](#0-0) . The per-output dedup check is `(asserts! (is-none (index-of? seen-outpoints outpoint)) ERR_DUPLICATE_LOCKUP_OUTPOINT)` [2](#0-1) , which only guards against the *same* outpoint appearing twice in the *same* `lockups.outputs` list passed to one call.

### Finding Description
The comment on `validate-l1-lockup` explicitly states the scope of the protection: *"`seen-outpoints` tracks every (txid, output-index) pair already credited **in this call**"* [3](#0-2) . `verify-l1-lockups` reinitializes `seen-outpoints: (list)` to an empty list every time it is invoked [4](#0-3) . This means the outpoint-dedup state is not persisted in any contract map/var across separate calls.

Within my available search, I confirmed the presence of the `sum`/`seen-outpoints` accumulator logic and its comment-documented "in this call" scope, but I was not able to fully trace every caller (`register-for-bond` and related public entry points had ~46 references I could not fully enumerate before the session ended) to determine with certainty whether a *separate*, persistent map (e.g., a `credited-lockups` or `spent-outpoints` map) is checked/updated elsewhere in the contract before or after `verify-l1-lockups` is invoked. If no such persistent map exists, a staker could submit the exact same Bitcoin lockup transaction/output (the same on-chain BTC UTXO) across two or more separate `register-for-bond`-style calls (each with its own fresh `seen-outpoints` list) and have the same sats credited toward two different bonds/reward-cycle windows — i.e., sats locked once on Bitcoin would be double-counted as backing for stacking commitments in pox-5.

This maps directly to the rule's named analog: *"sats credited by an L1 proof that were never locked on Bitcoin" / double-counting a commitment*, since the same physical BTC lock is being asserted as backing more than once.

### Impact Explanation
If a persistent, contract-wide record of already-consumed outpoints does not exist (unconfirmed from available context), this would allow an unprivileged staker to double-count real BTC lockups as backing for multiple bonds, inflating their effective committed stake/signing weight beyond what is actually locked on Bitcoin — a Critical-class issue under the stated impact criteria ("double-counting a commitment or reward", "signing weight ... exceeding locked value").

### Likelihood Explanation
Likelihood is uncertain without confirming whether a persistent anti-replay map is present elsewhere in `pox-5.clar` (e.g., set by the caller of `verify-l1-lockups`) — the function itself provides no persistence, but the calling function(s) may. This could not be verified within the available tool budget.

### Recommendation
Persist every credited `(txid, output-index)` outpoint in a contract-level map (e.g., `credited-l1-outpoints`) and check/insert into it (failing with `ERR_DUPLICATE_LOCKUP_OUTPOINT` on a hit) inside `validate-l1-lockup`/`verify-l1-lockups`, in addition to the existing intra-call `seen-outpoints` list, so the same Bitcoin lockup cannot be credited across multiple separate transactions/bonds.

### Proof of Concept
Not independently confirmed with a runnable PoC — this is based on static analysis of `verify-l1-lockups`/`validate-l1-lockup` [5](#0-4) . A concrete PoC would require confirming that no persistent outpoint map exists among the ~46 references to `register-for-bond`/outpoint-related identifiers in this file that I was unable to fully review before the session ended; I recommend a follow-up Devin session with full read access to `pox-5.clar` to confirm this before treating the finding as conclusively exploitable.

(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
