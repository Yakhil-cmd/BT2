### Title
Webhook signature verification is scoped to `repository.owner.login`/`organization.login` while event handlers act on the independently-attacker-controlled `repository.full_name` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App (and therefore the HMAC secret) used to authenticate an inbound webhook based on `repository.owner.login` (or `organization.login`) taken from the JSON body, but the actual event handlers that write data (create commits, sync stacks, archive/unarchive review stacks) resolve the target `Repository`/`Stack` from the independent `repository.full_name` field of the same body via `Repository.from_github_repo_name`. Nothing enforces that `repository.owner.login` and the owner encoded in `repository.full_name` refer to the same organization.

### Finding Description
`verify_signature` computes:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) 

This picks the webhook secret to verify with, per organization, from a multi-tenant config keyed by organization (`Shipit.github_app_config`) [2](#0-1)  — a deployment explicitly supported for hosting multiple GitHub organizations on one Shipit instance (`test/dummy/config/secrets_double_github_app.yml`, `docs/setup.md` "Using Multiple Github Applications"). [3](#0-2) 

Once the HMAC check passes, `create` re-parses the same raw body and dispatches it to handlers unmodified:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [4](#0-3) 

Every handler resolves the target repository purely from `repository.full_name`, ignoring `repository.owner.login`:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [5](#0-4) 
and `PushHandler#process` uses that scope to enqueue a `GithubSyncJob` per matching stack: [6](#0-5) 

Because signature validation is keyed off `repository.owner.login` (an attacker-supplied field distinct from `repository.full_name`), an attacker who legitimately controls a GitHub App/organization onboarded to the same Shipit instance (`OrgA`, with a webhook secret they can compute HMACs for) can craft a webhook body where:
- `repository.owner.login = "OrgA"` (so `Shipit.github(organization: "OrgA")`'s secret is used and the signature verifies), but
- `repository.full_name = "VictimOrg/victim-repo"` (so `Handler#stacks` resolves to a completely different, victim-owned `Stack`).

This breaks the binding "organization that authenticated == repository that is written": the org whose secret validated the request is not the org whose repository/stack data gets mutated.

### Impact Explanation
With a forged `push` event, the attacker (who only needs valid credentials for their own onboarded organization, not the victim's) can enqueue `GithubSyncJob` against a victim stack with an attacker-chosen `expected_head_sha` [6](#0-5) , which will pull real GitHub commit history for the victim repo and, on stacks with continuous delivery configured, can trigger deployment ahead of the legitimate schedule. Other events (`pull_request`, `membership`, `status`, `check_suite`) resolved the same way can similarly be spoofed against arbitrary stacks/repositories not owned by the attacker's authenticated organization — e.g. forcing archive/unarchive of review stacks [7](#0-6) , or provisioning/deprovisioning review stacks. This crosses a repository/organization trust boundary using credentials that were only ever meant to authorize webhooks for the attacker's own organization, matching the "unauthorized deploy" / "cross-repository writes" impact classes.

### Likelihood Explanation
Exploitation requires the attacker to control (or be the legitimate owner of) at least one GitHub organization/App already configured in this Shipit instance's multi-org `github` secrets block — a documented, supported deployment topology (`docs/setup.md`, `secrets_double_github_app.yml`). Given that, forging the payload is trivial: it is just a normal webhook POST with the `repository.owner.login` and `repository.full_name` fields set independently, and the attacker can compute the correct HMAC using their own known webhook secret.

### Recommendation
In `WebhooksController#verify_signature`/`create`, derive the organization used both for signature verification and for handler dispatch from a single, consistent source, and reject the request if `repository.owner.login` does not match the owner segment parsed out of `repository.full_name` (or if `Handler#repository_name`/`stacks` lookups aren't scoped to the same verified organization). At minimum, handlers should cross-check that the resolved `Repository`'s `owner` equals the organization whose secret validated the webhook before acting on it.

### Proof of Concept
1. Shipit is configured with two organizations, `OrgA` (attacker-controlled, webhook secret known to attacker) and `VictimOrg` (target), per the documented multi-org config.
2. Attacker crafts a `push` event body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "full_name": "VictimOrg/victim-repo",
    "owner": { "login": "OrgA" }
  }
}
```
3. Attacker computes `X-Hub-Signature` using `OrgA`'s webhook secret and POSTs to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` calls `Shipit.github(organization: "OrgA")` and validates successfully against the attacker-known secret [8](#0-7) .
5. `create` dispatches the same body to `PushHandler`, which resolves `Repository.from_github_repo_name("VictimOrg/victim-repo")` and enqueues `GithubSyncJob` for that victim stack with the attacker-supplied `expected_head_sha` [6](#0-5) , even though the attacker never proved control of `VictimOrg`'s webhook secret.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner

      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
