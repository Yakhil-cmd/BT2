### Title
Unbounded accrued debt value permanently freezes a market on the next accrual - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary
The pool’s accrual path converts the aggregate scaled debt into its RAY-denominated current value before applying the bounded borrow index. Once `borrowed * borrow_index` can no longer fit in `i128`, `scaled_to_original` reverts with `MathOverflow` before the index ceiling can take effect. Because every subsequent mutating pool operation accrues first, a sufficiently large and highly utilized market can reach a state where repayment, withdrawal, liquidation, and settlement all revert permanently.

### Finding Description
`accrue_step` computes `borrowed_original` by multiplying the stored scaled debt by the current borrow index, and computes `supplied_original` similarly before deriving utilization and interest. Both conversions use `Ray::mul`, which panics on `i128` overflow rather than clamping the unscaled value.

The borrow index itself is capped at `MAX_BORROW_INDEX_RAY`, but that cap is applied only after the earlier aggregate-value multiplication succeeds. The same unchecked multiplication is repeated when calculating old and new total debt inside `calculate_supplier_rewards`. [1](#0-0) [2](#0-1) [3](#0-2) 

An unprivileged caller can trigger the transition through `Controller::update_indexes`, which requires only the caller’s authorization and forwards the requested markets to the pool’s accrual entrypoint. The pool then loads each market and runs `interest::global_sync` before committing state. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

### Impact Explanation
Once accrued market totals cross the representable-value boundary, the accrual transaction reverts and leaves `last_timestamp` unchanged. Every later attempt therefore attempts the same overflowing calculation again.

The market cannot be repaired through ordinary user or keeper flows: repayments call the pool repay path after funding, withdrawals call the pool withdrawal path, liquidations and bad-debt cleanup call the pool seizure/withdrawal paths, and all of those paths first perform global accrual. The repository’s long-horizon integration test demonstrates that both `withdraw` and `repay` revert with `MathOverflow` after `update_indexes` hits the cliff. [8](#0-7) 

This permanently freezes the affected market’s supplier funds and prevents debt settlement, including liquidation and bad-debt processing.

### Likelihood Explanation
This is not a single inexpensive state write. Reaching the boundary requires an extremely large scaled debt position and sufficient sustained utilization/time for the borrow index to make `borrowed * borrow_index` exceed `i128::MAX`. The documented scenario uses a billion whole tokens at 18 decimals with 98% borrowed and allows accrual to run until the value crosses the arithmetic ceiling. [9](#0-8) 

Nevertheless, market caps admit token values near the RAY-domain maximum, `update_indexes` is permissionless, and no recovery path bypasses accrual once the threshold is crossed. The protocol documentation also acknowledges that valid caps and bounded indexes do not guarantee future accrued values remain representable. [10](#0-9) 

### Recommendation
Make accrual saturate rather than panic when aggregate debt or supply value exceeds the representable range. At minimum, derive utilization using saturating fixed-point multiplication and avoid computing `new_total_debt` when `update_borrow_index` has already reached `MAX_BORROW_INDEX_RAY`; at the cap, interest should be zero by definition.

A stronger fix is to introduce a checked/saturating `scaled_to_original` variant for aggregate accrual, cap utilization at `RAY` when debt value saturates, and add a regression test proving that `update_indexes`, `repay`, `withdraw`, liquidation, and bad-debt cleanup remain executable at the boundary. The fix should not silently erase debt or supplier value; it should deterministically bound rate inputs while preserving the stored scaled positions.

### Proof of Concept
1. Governance creates an 18-decimal market with a steep but valid rate curve and permits a very large market size.
2. The attacker supplies approximately `1_000_000_000 * 10^18` base units of the debt asset.
3. The attacker supplies sufficient collateral in another market and borrows approximately 98% of the debt asset.
4. Time advances while utilization remains high. Because `update_indexes(caller, [hub_asset])` is permissionless, the attacker or any other unprivileged signed caller invokes it after accrued debt has crossed the `i128` representable-value boundary.
5. `accrue_step` calls `scaled_to_original(borrowed, borrow_index)`; `Ray::mul` reverts with `GenericError::MathOverflow` before the borrow-index cap can commit.
6. Since the failed call rolls back the timestamp update, every later `update_indexes`, `repay`, `withdraw`, `liquidate`, or `clean_bad_debt` attempt repeats the overflowing accrual and reverts. The existing integration test demonstrates the terminal state by asserting `MathOverflow` from `update_indexes`, `withdraw`, and `repay`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
