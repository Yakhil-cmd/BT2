**Rationale:** The premise does not hold up against the actual code.

`NEXT_POOL_ID` in [1](#0-0)  is used exclusively to build a per-caller-thread rayon pool for Move native functions that need to spawn their own rayon work (e.g. `ark_ec` MSM/pairing), isolating them from the block-executor's `par_exec` pool to avoid deadlocks. The comment explicitly states the id is "only used for thread naming," and this is confirmed by the module's own tests, which check that `native-rayon-{id}-*` name prefixes differ across calling threads [2](#0-1) .

This pool has no relationship to transaction admission, authenticator verification, or `vm-validator`. Searching the codebase for any authenticator/signature verification cache keyed by thread name, thread identity, or this pool's naming scheme (`grep` for `check_signature`, `verified_authenticator`, `SIGNATURE_CACHE`, `thread().name()`) turns up nothing that ties authenticator verification results to thread names. The actual `vm-validator` code performs signature verification directly via `transaction.check_signature()` per call [3](#0-2) , with no cache keyed by thread identity, and mempool's concurrent VM validation dispatches independent `validate_transaction` calls per transaction through `par_map_blocking` without any shared authenticator cache [4](#0-3) .

Since there is no downstream code that uses `native-rayon-*` (or any other) thread name as an authenticator-cache key, a relaxed-ordering race on `NEXT_POOL_ID` cannot cause cross-transaction authenticator confusion. The exploit path described (thread-name collision → shared authenticator cache entry → sender confusion) does not exist in this codebase.

/// Monotonic id assigned to each per-caller pool, only used for thread naming.
static NEXT_POOL_ID: AtomicUsize = AtomicUsize::new(0);

thread_local! {
    static PER_CALLER_POOL: OnceCell<Arc<rayon::ThreadPool>> = const { OnceCell::new() };
}

fn build_pool() -> Arc<rayon::ThreadPool> {
    let id = NEXT_POOL_ID.fetch_add(1, Ordering::Relaxed);
    let n = THREADS_PER_POOL
        .get()
        .copied()
        .unwrap_or(DEFAULT_THREADS_PER_POOL);
    Arc::new(
        rayon::ThreadPoolBuilder::new()
            .num_threads(n)
            .thread_name(move |i| format!("native-rayon-{}-{}", id, i))
            .build()
            .expect("failed to build native rayon thread pool"),
    )
}
