### Title
Unbounded, undercharged duplicate-oracle expansion in `data_feed`/`in_data_feed` formulas causes disproportionate DB/KV resource consumption per AA trigger - (File: formula/evaluation.js)

### Summary
The Mattermost CVE-2023-5333 root cause is that a client-controlled list of IDs is not deduplicated/bounded, so an attacker can force the server to do O(n) expensive work for a single cheap request. The oscript `data_feed[[...]]` / `in_data_feed[[...]]` formula functions accept an `oracles` parameter that is a colon-separated string of addresses, split with no deduplication and no per-address complexity charge, then iterated with `async.eachSeries` doing one KV-store stream read per address.

### Finding Description
In `formula/evaluation.js`, the `data_feed` case parses `oracles`: [1](#0-0) 
It then calls `dataFeeds.readDataFeedValue(arrAddresses, ...)`, which walks the (unfiltered, non-deduplicated) address list sequentially: [2](#0-1) 
Each entry triggers a full `kvstore.createReadStream`/key-scan operation: [3](#0-2) 
The same pattern exists for `in_data_feed`, which calls `dataFeeds.dataFeedExists` iterating `arrAddresses` with `async.eachSeries` and one `dataFeedByAddressExists` KV scan per element: [4](#0-3) [5](#0-4) 

Critically, the static-complexity checker for these ops only charges a flat complexity of `1` regardless of the number of oracle addresses supplied — the per-address charge is explicitly commented out: [6](#0-5) [7](#0-6) 

The only constraint on `oracles` is that every colon-separated token parses as `isValidAddress`; there is no uniqueness check and no limit on how many addresses (or duplicate copies of the same address) can be listed: [8](#0-7) [9](#0-8) 

Because the `oracles` value can be built dynamically from formula expressions (string concatenation of a repeated valid address, e.g. `"ADDR:" .. "ADDR:" .. ... ` or via a loop/`foreach`-style formula concatenation), an AA definer (or, indirectly, a trigger sender providing `trigger.data` consumed unchecked by a poorly written AA formula) can construct an arbitrarily long oracle list consisting of the same valid address repeated many times. Since the accounted "complexity" that gates how much work an AA/formula is allowed to do does not scale with the number of oracle entries, the fee charged to the attacker for this operation does not reflect the actual number of KV-store reads performed.

### Impact Explanation
Each duplicate oracle entry causes an additional synchronous KV read via `kvstore.createReadStream`/`createKeyStream` (see `dataFeedByAddressExists`/`readDataFeedByAddress`/`dataFeedExists`), executed on every node that processes the AA response (all full nodes, since AA execution is deterministic and re-run by every node validating the trigger/response). A single crafted trigger unit can therefore force every witnessing/validating node in the network to perform thousands of redundant LevelDB/RocksDB key-range scans while paying for only a single unit of "complexity", i.e., paying a fee disproportionate to the CPU/I/O cost imposed on the network. This is a resource-exhaustion primitive analogous to the Mattermost `/api/v4/users/ids` duplicate-ID bug: unbounded, undeduplicated, attacker-controlled repetition of "IDs" (oracle addresses) drives real backend work with no corresponding cost control, degrading node performance and potentially delaying stabilization/validation of new units network-wide under repeated exploitation.

### Likelihood Explanation
Exploitation requires only posting an ordinary AA-triggering unit (a payment to an AA address with `trigger.data` that an AA formula relates to an `oracles` construction), which is available to any unprivileged unit poster/AA trigger sender in scope. No malicious peer, hub, or node cooperation is needed; the amplification lives purely in formula evaluation and the `data_feeds.js` KV read loop, and the missing complexity charge (explicitly commented out in the code) confirms the gap was known/considered but not enforced.

### Recommendation
- Deduplicate `arrAddresses` derived from the `oracles` parameter before processing in `data_feed`/`in_data_feed` (both in `formula/evaluation.js` and `data_feeds.js`).
- Enforce a maximum number of oracle addresses per `data_feed`/`in_data_feed` call, and re-enable/implement the commented-out per-address complexity charge (`complexity += addresses.length`) in `formula/validation.js` so the fee reflects the number of distinct KV lookups actually performed.
- Cap the total number of KV-store scans triggerable per AA response/trigger evaluation, independent of how the oracle list was constructed (static string vs. dynamic concatenation).

### Proof of Concept
1. Deploy an AA whose formula includes something like:
   `data_feed[[oracles = trigger.data.addr_list, feed_name="x"]]`
   or an AA that builds `oracles` via repeated string concatenation of the same valid address, e.g. `oracles = repeat_string(oracle_address + ":", N)` (any formula construct that yields a colon-joined string of N copies of a valid address).
2. Trigger this AA with a minimal-fee unit; N can be chosen large enough to require thousands of colon-separated address tokens while incurring only the flat complexity cost of `1` per `formula/validation.js`'s `validateDataFeed`/`validateDataFeedExists`.
3. Observe that `dataFeeds.readDataFeedValue`/`dataFeeds.dataFeedExists` performs N sequential `kvstore` stream scans (`data_feeds.js:287-339`, `data_feeds.js:13-107`) during trigger validation/execution on every full node, for a single cheaply-priced trigger unit.

function readDataFeedByAddress(address, feed_name, value, min_mci, max_mci, ifseveral, objResult, handleResult){
	var bLimitedPrecision = (max_mci < constants.aa2UpgradeMci);
	var bAbortIfSeveral = (ifseveral === 'abort');
	var key_prefix;
	if (value === null){
		key_prefix = 'dfv\n'+address+'\n'+feed_name;
	}
	else{
		var prefixed_value;
		if (typeof value === 'string'){
			var float = string_utils.toNumber(value, bLimitedPrecision);
			if (float !== null)
				prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(float);
			else
				prefixed_value = 's\n'+value;
		}
		else
			prefixed_value = 'n\n'+string_utils.encodeDoubleInLexicograpicOrder(value);
		key_prefix = 'df\n'+address+'\n'+feed_name+'\n'+prefixed_value;
	}
	var options = {
		gte: key_prefix+'\n'+string_utils.encodeMci(max_mci),
		lte: key_prefix+'\n'+string_utils.encodeMci(min_mci),
		limit: bAbortIfSeveral ? 2 : 1
	};
	var handleData = function(data){
		if (bAbortIfSeveral && objResult.value !== undefined){
			objResult.bAbortedBecauseOfSeveral = true;
			return;
		}
		var mci = string_utils.getMciFromDataFeedKey(data.key);
		if (objResult.value === undefined || ifseveral === 'last' && mci > objResult.mci){
			if (value !== null){
				objResult.value = string_utils.getValueFromDataFeedKey(data.key);
				objResult.unit = data.value;
			}
			else{
				var arrParts = data.value.split('\n');
				objResult.value = string_utils.getFeedValue(arrParts[0], bLimitedPrecision); // may convert to number
				objResult.unit = arrParts[1];
			}
			objResult.mci = mci;
		}
	};
	kvstore.createReadStream(options)
	.on('data', handleData)
	.on('end', function(){
		handleResult(objResult.bAbortedBecauseOfSeveral);
	})
	.on('error', function(error){
		throw Error('error from data stream: '+error);
	});
}

function validateDataFeedExists(params) {
	var complexity = 1;
	if (!params.oracles || !params.feed_name || !params.feed_value)
		return {error: 'no oracles or feed name or feed value', complexity};
	for (var name in params) {
		var operator = params[name].operator;
		var value = params[name].value;
		if (Decimal.isDecimal(value)){
			if (!isFiniteDecimal(value))
				return {error: 'not finite', complexity};
			value = toDoubleRange(value).toString();
		}
		if (operator === '==') return {error: 'op ==', complexity};
		if (['oracles', 'feed_name', 'min_mci', 'feed_value'].indexOf(name) === -1)
			return {error: 'unknown param: ' + name, complexity};
		if ((name === 'oracles' || name === 'feed_name' || name === 'min_mci') && operator !== '=')
			return {error: 'not =', complexity};
		if (typeof value !== 'string')
			continue;
		switch (name) {
			case 'oracles':
				if (value.trim() === '') return {error: 'empty oracles', complexity};
				var addresses = value.split(':');
				if (addresses.length === 0) return {error: 'empty oracles list', complexity};
			//	complexity += addresses.length;
				if (!addresses.every(ValidationUtils.isValidAddress)) return {error: 'not valid oracle address', complexity};
				break;
