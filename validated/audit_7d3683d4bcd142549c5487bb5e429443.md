### Title
`ProxyType::NonTransfer` on Asset Hub Rococo fails to deny `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, and `Indices::transfer` calls, letting a read/non-transfer proxy move the delegator's funds - ([File: cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs])

### Summary
The Zammad CVE's violated invariant is: a permission tier documented as read-only/non-mutating must not permit state-mutating operations that its own model says it forbids. The direct Polkadot SDK analog is `pallet_proxy`'s `InstanceFilter` for `ProxyType::NonTransfer`, which is documented as allowing "any call that does not transfer funds or assets." On Asset Hub Rococo this filter is implemented as a deny-list that only excludes `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`, while the runtime also configures `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` — all of which move the delegator's assets — plus `Indices::transfer`/`force_transfer`, which repatriate a reserved deposit. [1](#0-0) 

This exact bug class was already found and fixed on the sibling Asset Hub Westend runtime (issue #12466 / PR #12771) and again on the staking-async parachain runtime (PR #12922), each time adding the missing pallet families to the `NonTransfer` deny-list. [2](#0-1) [3](#0-2) 

Asset Hub Rococo, however, still has the pre-fix deny-list and was never patched to include these pallets.

### Finding Description
`pallet_proxy::do_proxy` dispatches the wrapped call under a filter derived from `T::ProxyType::filter`, without any independent enforcement that a "non-transfer" claim actually holds: [4](#0-3) 

On Asset Hub Rococo, `ProxyType::NonTransfer` is documented as "Can execute any call that does not transfer funds or assets," and its `filter` implementation is a **deny-list**:
```rust
ProxyType::NonTransfer => !matches!(
    c,
    RuntimeCall::Balances { .. } |
        RuntimeCall::Assets { .. } |
        RuntimeCall::NftFractionalization { .. } |
        RuntimeCall::Nfts { .. } |
        RuntimeCall::Uniques { .. }
),
``` [5](#0-4) 

Because this is a deny-list, it fails open: any pallet configured in the runtime that is not explicitly named is reachable. The runtime construction includes `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` (confirmed present via 117 references and 31 direct `Pallet:` config matches in the same file), none of which appear in the `NonTransfer` deny-list. Each of these families can move the delegator's value:
- `ForeignAssets`/`PoolAssets` transfer value exactly as `Assets` does — this is the sibling pallet instance already denied on Westend.
- `AssetConversion` swaps/removes liquidity, moving the caller's assets.
- `PolkadotXcm::transfer_assets`/`teleport_assets`/`send`/`execute` can move assets off-chain via raw XCM.
- `Revive` contract calls/instantiations carry a `value` that transfers native balance.
- `Indices::transfer`/`force_transfer` repatriate the index's reserved deposit to a new owner.

This is precisely the same violated-invariant pattern as CVE-2022-40817 (a "read-only"/restricted permission tier that still permits state-changing operations it is documented to forbid) — here the analog boundary is `pallet_proxy`'s call filter rather than Zammad's ticket ACL, and the attacker-controlled input is the proxied `RuntimeCall` itself, submitted by an unprivileged delegate through the ordinary `Proxy::proxy` extrinsic.

The Westend and staking-async fixes (PR #12771, #12922) demonstrate that Parity considers this exact gap security-relevant and remediates it by adding the missing pallet families to the deny-list; Asset Hub Rococo's `NonTransfer` filter was not updated the same way and still has the narrower, pre-fix list. [6](#0-5) 

### Impact Explanation
A delegator who grants a `NonTransfer` proxy — explicitly to protect against fund movement while allowing everyday, non-transfer administration — has that guarantee silently broken. A trusted-but-limited delegate (e.g., an automated bot or lower-trust key) can use the proxy to swap/move the delegator's `ForeignAssets`/`PoolAssets` via `AssetConversion`, teleport/transfer assets off-chain via `PolkadotXcm`, or drive value through `Revive` contract calls — actions the delegator's threat model explicitly excluded when choosing `NonTransfer` over `Any`. This is a permission/authorization-integrity break (unauthorized fund movement by an under-privileged proxy), analogous in class to the Zammad finding but concretely worse because it is a fund-movement bypass rather than a ticket-metadata bypass.

### Likelihood Explanation
`Proxy::add_proxy`/`Proxy::proxy` are ordinary, fee-only signed extrinsics available to any account; no privileged role or governance action is needed to create a `NonTransfer` proxy relationship or to exploit it once created. The bug is deterministic: any of the un-denied pallet calls listed above will pass `ProxyType::NonTransfer::filter` and dispatch normally. The precedent fixes (#12771 for Westend NonTransfer, #12922 for staking-async NonTransfer) confirm this exact configuration mistake is realistic and has occurred multiple times across sibling runtimes in this codebase, increasing confidence that Asset Hub Rococo's un-patched instance is a genuine, live gap rather than a theoretical one.

### Recommendation
Update `ProxyType::NonTransfer::filter` in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` to explicitly deny `RuntimeCall::ForeignAssets`, `RuntimeCall::PoolAssets`, `RuntimeCall::AssetConversion`, `RuntimeCall::PolkadotXcm`, `RuntimeCall::Revive`, and `RuntimeCall::Indices(pallet_indices::Call::transfer{..} | force_transfer{..})`, mirroring the fix already applied to Asset Hub Westend in PR #12771. Additionally, consider converting the filter to an allow-list (or adding a lattice/regression test like `non_transfer_proxy_rejects_value_moving_calls` from Asset Hub Westend's test suite) so that adding a new value-moving pallet to the runtime cannot silently reintroduce this class of bug. [7](#0-6) 

### Proof of Concept
Not executed in this environment (ask-only/no code-execution access). A minimal FRAME integration reproduction would mirror the existing Westend regression test `non_transfer_proxy_rejects_value_moving_calls`, adapted to the Asset Hub Rococo runtime:
1. `Proxy::add_proxy(delegator, delegate, ProxyType::NonTransfer, 0)`.
2. Construct `RuntimeCall::AssetConversion(pallet_asset_conversion::Call::swap_exact_tokens_for_tokens { .. })` (or `PolkadotXcm::transfer_assets{..}`, or `Revive::call{ value: N, .. }`) moving the delegator's assets.
3. Call `Proxy::proxy(delegate, delegator, None, Box::new(call))`.
4. Expected (per documented `NonTransfer` policy): `CallFiltered` / `ProxyExecuted{ result: Err(..) }`.
5. Actual (per current code at lines 608–615): `ProxyType::NonTransfer::filter` returns `true` for these calls since they are absent from the deny-list, so `Proxy::proxy` dispatches them and the assets move.

Failed guard: `ProxyType::NonTransfer::filter` at `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs:608-615` — the deny-list omits `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, `Revive`, and `Indices::transfer`/`force_transfer`, all of which are configured pallets in the same runtime file. This is a config-only asset-hub-rococo runtime bug (same class already fixed elsewhere via PR #12771/#12922), not a hypothetical/EVM-forced analogy, and not privileged-prerequisite: any signed account can create and exploit the proxy relationship at ordinary transaction fees.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
