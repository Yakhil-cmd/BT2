### Title
Webhook signature verification selects the signing organization from the same untrusted payload used to pick the target repository, decoupling "organization authenticated" from "repository written" - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks which GitHub App / `webhook_secret` to verify the HMAC signature against using `repository_owner`, a value read straight out of the unauthenticated JSON body. The downstream `Webhooks::Handlers::Handler` classes, however, resolve the `Stack`/`Repository` to act on using a *different* field from the very same body: `repository.full_name`. Nothing binds these two fields together, and per-organization `webhook_secret` is optional. This is the same "field acted upon vs. field actually covered by validation" class as the `replacePool()`/`curatePool()` binding bypass in the referenced report: the signature only ever certifies "some org's secret matches", not "the org that owns the repository this payload will mutate".

### Finding Description
In a multi-organization deployment (the schema explicitly supported by `config/secrets.development.shopify.yml` and `Shipit.github_app_config`), each organization has its own `GitHubApp` instance with its own, optional `webhook_secret`: [1](#0-0) 

The controller derives which app/secret to check against entirely from attacker-controlled JSON: [2](#0-1) 

Signature verification itself trivially passes for any organization whose `webhook_secret` is blank/unset: [3](#0-2) 

Once `verify_signature` passes, `create` hands the raw JSON straight to the event handlers: [4](#0-3) 

But every handler resolves the target `Stack`/`Repository` using a completely separate JSON field, `repository.full_name`, that is never checked against `repository_owner`: [5](#0-4) [6](#0-5) 

The equality that should hold but doesn't: `organization whose secret validated the signature == organization that owns repository.full_name being acted upon`. Concretely:
- If any configured organization in `secrets.github` has no `webhook_secret` set, an attacker sets `repository.owner.login` (or `organization.login`) to that org's key so `verify_signature` short-circuits to `true` regardless of the `X-Hub-Signature` header, while setting `repository.full_name` to any other organization's/stack's repository. The handler then acts on that unrelated repository with a payload whose signature was never actually checked against anything meaningful.
- Even where every configured org has a secret, whoever knows one org's `webhook_secret` (e.g. from operating a webhook receiver for that org, or via a leaked/shared secret) can sign a payload with `repository.owner.login` set to that org while `repository.full_name` targets a repo belonging to a different, unrelated organization, since the two fields are never cross-checked.

### Impact Explanation
An attacker able to satisfy either condition above can forge `push`, `status`, `check_suite`, `pull_request`, or `membership` events for stacks/repositories outside the organization whose secret was actually validated. This drives cross-repository state changes without genuine authorization from the targeted repository's owner: forged `push` events enqueue `GithubSyncJob`/`stack.sync_github` for arbitrary stacks, forged `status` events fabricate commit statuses that downstream merge/deploy gating may trust, and forged `pull_request`/`membership` events can archive/unarchive review stacks or mutate `Team`/`Membership` records. This is a cross-repository write achieved without the targeted repository's own webhook secret, matching the Critical "cross-repository writes" impact bucket.

### Likelihood Explanation
Exploitability depends on deployment configuration: it requires either a multi-org Shipit deployment with at least one org missing a `webhook_secret`, or an attacker who legitimately knows one org's secret (e.g., they are a webhook-receiving party for that org) and wants to act on a different org's repository. Both are realistic operational states not prevented by any code in this engine, and no session, `ApiClient` token, or repository write access is required to send the forged webhook.

### Recommendation
Bind the field used for signature-key selection to the field used for repository/stack resolution: verify that `repository.owner.login`/`organization.login` matches the owner of the repository resolved via `repository.full_name` before any handler runs, and require `webhook_secret` to be mandatory (not optional) for every configured organization so `verify_webhook_signature` can never short-circuit to `true`.

### Proof of Concept
1. Configure Shipit with two organizations in `secrets.github`, e.g. `orga` (no `webhook_secret` set) and `orgb` (has a stack `orgb/target-repo`).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": { "full_name": "orgb/target-repo", "owner": { "login": "orga" } }
}
```
with any garbage `X-Hub-Signature` header (or none).
3. `verify_signature` resolves `Shipit.github(organization: "orga")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`), bypassing the check entirely.
4. `PushHandler` then resolves stacks via `repository.full_name = "orgb/target-repo"` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`) and enqueues a sync for `orgb`'s stack, even though no valid signature for `orgb` was ever presented.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping

    end

    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
