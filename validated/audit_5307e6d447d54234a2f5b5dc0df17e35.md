### Title
Debt-value overflow during interest accrual permanently freezes a market - ([File: common/src/rates/index.rs])

### Summary
A sufficiently large, highly utilized market can overflow the fixed-point debt calculation before the borrow index reaches its cap. Once this occurs, `update_indexes`, `repay`, `withdraw`, and other operations touching that market revert during mandatory accrual, permanently freezing suppliers’ funds and preventing borrowers or liquidators from reducing the debt.

### Finding Description
`ops::load_leg` synchronizes the market before every debt or supply mutation by calling `interest::global_sync`. [1](#0-0)  Accrual calls `accrue_step` for each bounded elapsed-time chunk and commits the returned indexes. [2](#0-1)  The rewards calculation computes both `borrowed * old_borrow_index` and `borrowed * new_borrow_index`. [3](#0-2) 

Although `update_borrow_index` clamps the resulting index to `MAX_BORROW_INDEX_RAY`, that clamp does not prevent the separate RAY-valued debt multiplication from exceeding `i128::MAX`. [4](#0-3)  The overflow therefore aborts accrual before the index ceiling can engage. A regression test constructs a billion-token, 18-decimal market at 98% utilization and demonstrates `MathOverflow` from `update_indexes`, followed by the same failure for withdrawal and repayment. [5](#0-4) 

### Impact Explanation
All pool operations that load the affected leg synchronize interest before performing their mutation, so the overflow blocks repayment, withdrawal, liquidation-related pool accounting, revenue handling, and further accrual for that market. [6](#0-5)  The tested state leaves suppliers unable to withdraw and the borrower unable to repay. [7](#0-6)  This causes permanent freezing of user funds and leaves protocol debt irrecoverable through the normal entrypoints.

### Likelihood Explanation
An unprivileged account can reach the state through ordinary `supply` and `borrow` calls when the listed market caps permit a sufficiently large position and utilization remains high enough for debt value growth to cross the representable range. The setup uses only ordinary market entrypoints: a billion-unit deposit followed by a borrow equal to 98% of principal. [8](#0-7)  The exploit requires an unusually large market and elapsed accrual, but it does not require privileged access, oracle manipulation, malformed token behavior, or a malformed transaction.

### Recommendation
Bound aggregate scaled debt and supplied-share value before accrual so the multiplication cannot exceed `i128::MAX`. In `calculate_supplier_rewards`, avoid computing unchecked RAY-valued totals directly; use wider intermediate arithmetic or a checked ratio formulation that can clamp at the borrow-index cap before value multiplication overflows. Add a market-level maximum scaled-supply/debt invariant or lower the admitted cap so every configured cap remains safely below the accrual overflow threshold.

### Proof of Concept
The repository contains a deterministic reproduction:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
