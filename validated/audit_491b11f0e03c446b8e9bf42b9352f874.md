I found the analog. The `BridgeOperator.sol` contract has the exact same bug class — votes by a deregistered operator are not revoked, and the stale vote count persists and can be used to reach the execution threshold for bridge value transfers.

### Title
Deregistered Bridge Operator's Outstanding Votes Persist and Can Satisfy the Execution Threshold — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator` removes an operator from the `operators` mapping and `operatorList` array but does not clear that operator's previously cast votes from the `votes[voteType][nonce].voteCounts` storage. A remaining valid operator can subsequently cast a vote that, combined with the stale count from the deregistered operator, reaches `operatorThresholds[voteType]` and executes a bridge value transfer (KAIA, ERC20, or ERC721) with fewer currently-authorized votes than the threshold requires.

### Finding Description

`_voteCommon` accumulates vote counts in a persistent mapping:

```solidity
vote.voteCounts[_voteKey]++;
if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
    return true;
}
``` [1](#0-0) 

`deregisterOperator` only removes the operator from the access-control structures:

```solidity
delete operators[_operator];
// ... removes from operatorList ...
``` [2](#0-1) 

It does not touch any `votes[voteType][nonce].voteCounts` entries. The code itself documents this gap:

> "Note that outstanding votes by the deregistered operator are not revoked." [3](#0-2) 

When `_voteValueTransfer` is called by a remaining valid operator, the stale count from the deregistered operator is already present in storage. The new vote increments the count past the threshold, and `closedValueTransferVotes[_requestNonce]` is set to `true`, triggering the actual asset transfer in `handleKLAYTransfer` or `handleERC20Transfer`. [4](#0-3) [5](#0-4) 

### Impact Explanation

A bridge value transfer — KAIA or bridged ERC20/ERC721 tokens — is executed on-chain with a vote count that includes a contribution from an operator whose authority has been explicitly revoked. The invariant "only currently-authorized operators' votes count toward the threshold" is broken. The concrete corrupted value is `votes[VoteType.ValueTransfer][nonce].voteCounts[voteKey]`, which remains inflated by the deregistered operator's vote, causing the threshold check to pass with fewer valid operator approvals than `operatorThresholds[ValueTransfer]` requires. This is an unauthorized asset transfer affecting bridged KAIA and tokens.

### Likelihood Explanation

The most realistic trigger is operator key compromise: the owner deregisters a compromised operator to stop it from authorizing transfers, but any pending votes that operator already cast remain live. A single remaining valid operator's subsequent vote on the same nonce then executes the transfer. With threshold set to 2 and two operators, deregistering one after it has voted leaves the stale count at 1; the second operator's vote brings it to 2, executing the transfer immediately. The owner has no on-chain mechanism to cancel the stale vote without also canceling the entire nonce (which is not supported).

### Recommendation

In `deregisterOperator`, iterate over all open (non-closed) nonces and decrement `voteCounts` for any `voteKey` the deregistered operator has voted on:

```solidity
function deregisterOperator(address _operator) external onlyOwner {
    require(operators[_operator]);
    // For each open vote nonce, revoke _operator's outstanding vote
    for (uint8 vt = 0; vt < uint8(VoteType.Max); vt++) {
        // Iterate known open nonces and clear _operator's contribution
        // votes[vt][nonce].voted[_operator] and decrement voteCounts accordingly
    }
    delete operators[_operator];
    // ... remove from operatorList ...
}
```

Because iterating all nonces on-chain is expensive, an alternative is to validate at threshold-check time that each voter in `vote.voters` is still a current operator before counting their vote.

### Proof of Concept

Setup: operators = {A, B}, threshold = 2.

1. Operator A calls `handleKLAYTransfer(txHash, from, to, value, nonce=5, ...)`.
   - `_voteValueTransfer(5)` → `_voteCommon` → `voteCounts[voteKey]` becomes 1. Returns false (1 < 2). No transfer yet.
2. Owner calls `deregisterOperator(A)`.
   - `operators[A]` deleted. `operatorList` shrinks. `voteCounts[voteKey]` for nonce 5 is still 1.
3. Operator B calls `handleKLAYTransfer(txHash, from, to, value, nonce=5, ...)`.
   - `_voteValueTransfer(5)` → `_voteCommon` → `voteCounts[voteKey]` becomes 2. Returns true (2 >= 2).
   - `closedValueTransferVotes[5] = true`. KAIA is transferred to `to`.

The transfer executed with A's revoked vote + B's valid vote, bypassing the intended 2-of-current-operators requirement. [6](#0-5)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // _voteValueTransfer votes value transfer transaction with the operator.
    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }
