### Title
Pool creator address is immutable after `initialize`, permanently freezing accrued creator fees if the key is lost or needs rotation - ([File: programs/cp-swap/src/instructions/initialize.rs])

### Summary
`PoolState.pool_creator` is set once during pool creation and there is no instruction anywhere in the program that allows it to be changed, unlike the admin-controlled `protocol_owner`/`fund_owner` fields on `AmmConfig`, which do have an update path. Since all creator-fee withdrawals are strictly gated on this immutable field, loss or compromise of the creator key permanently locks the accumulated creator fees in the pool vaults.

### Finding Description
When a pool is created via `initialize`/`initialize_with_permission`, the creator's public key is written into `PoolState.pool_creator` and never touched again: [1](#0-0) 

The `pool_creator` field is defined once in `PoolState` and set exclusively inside `PoolState::initialize`: [2](#0-1) 

Fees accrued for the creator (`creator_fees_token_0`, `creator_fees_token_1`) can only be withdrawn through `collect_creator_fee` or `collect_creator_fee_permissionless`, both of which hard-constrain the recipient/authority to `pool_state.load()?.pool_creator`: [3](#0-2) [4](#0-3) 

By contrast, the admin-level `AmmConfig.protocol_owner` and `AmmConfig.fund_owner` fields *do* have an explicit update path via `update_amm_config`'s `set_new_protocol_owner`/`set_new_fund_owner` branches: [5](#0-4) 

No equivalent mechanism exists for `pool_creator`. A grep across the codebase confirms `pool_creator` is only referenced in `states/pool.rs` (definition/initialization) and the two `collect_creator_fee*` instructions (read-only constraint) — there is no `set_new_pool_creator` or similar. This mirrors the `TokenTimelock.beneficiary` issue: an address that funds are permanently routed to, with no transfer mechanism, unlike its sibling addresses which are updatable.

### Impact Explanation
If the wallet holding the `pool_creator` key is lost, compromised, or the creator organization needs to rotate signing keys (e.g., moving from a hot wallet to a multisig, or key compromise recovery), the accumulated `creator_fees_token_0`/`creator_fees_token_1` sitting in `token_0_vault`/`token_1_vault` become permanently unclaimable. Since `collect_creator_fee` requires a signature matching the immutable `pool_creator` address and `collect_creator_fee_permissionless` requires the ATA to be owned by that same immutable address, there is no path — permissioned or permissionless — to redirect or recover these funds. This is a permanent freezing of legitimate creator-fee funds accumulated by an ordinary, unprivileged pool creator through normal `swap_base_input`/`swap_base_output` activity.

### Likelihood Explanation
Any user who creates a pool via `initialize`/`initialize_with_permission` (unprivileged, permissionless action) is exposed. Key loss/compromise or the routine business need to rotate a fee-receiving address is a realistic, non-adversarial scenario, and once fees have accrued (which happens automatically as trades occur), there is no recovery option built into the protocol.

### Recommendation
Add a creator-controlled instruction (optionally two-step, à la the referenced `pendingBeneficiary` pattern) that allows the current `pool_creator` to nominate and confirm a new `pool_creator` address in `PoolState`, mirroring the existing `set_new_protocol_owner`/`set_new_fund_owner` pattern already used for `AmmConfig`:
```rust
pub fn transfer_pool_creator(ctx: Context<TransferPoolCreator>, new_creator: Pubkey) -> Result<()> {
    // require signer == pool_state.pool_creator
    pool_state.pending_creator = new_creator;
    Ok(())
}
pub fn accept_pool_creator(ctx: Context<AcceptPoolCreator>) -> Result<()> {
    // require signer == pool_state.pending_creator
    pool_state.pool_creator = pool_state.pending_creator;
    Ok(())
}
```

### Proof of Concept
1. Unprivileged user calls `initialize` (or `initialize_with_permission`), setting `pool_creator = creatorPubkey` in `PoolState`.
2. Normal swap activity accrues `creator_fees_token_0`/`creator_fees_token_1` in the pool's vaults over time.
3. The `creatorPubkey` private key is lost or compromised.
4. Neither `collect_creator_fee` (requires `creator` signer == `pool_creator`) nor `collect_creator_fee_permissionless` (requires ATA owned by `pool_creator`) can be executed by the legitimate creator anymore.
5. No instruction in the program (`update_amm_config` only covers `AmmConfig.protocol_owner`/`fund_owner`) can update `PoolState.pool_creator`.
6. The accrued creator fees remain permanently locked in the vaults, unreachable by anyone.

pub fn update_amm_config(ctx: Context<UpdateAmmConfig>, param: u8, value: u64) -> Result<()> {
    let amm_config = &mut ctx.accounts.amm_config;
    let match_param = Some(param);
    match match_param {
        Some(0) => update_trade_fee_rate(amm_config, value),
        Some(1) => update_protocol_fee_rate(amm_config, value),
        Some(2) => update_fund_fee_rate(amm_config, value),
        Some(3) => {
            let new_procotol_owner = *ctx.remaining_accounts.iter().next().unwrap().key;
            set_new_protocol_owner(amm_config, new_procotol_owner)?;
        }
        Some(4) => {
            let new_fund_owner = *ctx.remaining_accounts.iter().next().unwrap().key;
            set_new_fund_owner(amm_config, new_fund_owner)?;
        }
        Some(5) => amm_config.create_pool_fee = value,
        Some(6) => amm_config.disable_create_pool = if value == 0 { false } else { true },
        Some(7) => update_creator_fee_rate(amm_config, value),
        _ => return err!(ErrorCode::InvalidInput),
    }

    Ok(())
}

fn update_protocol_fee_rate(amm_config: &mut Account<AmmConfig>, protocol_fee_rate: u64) {
    assert!(protocol_fee_rate <= FEE_RATE_DENOMINATOR_VALUE);
    assert!(protocol_fee_rate + amm_config.fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE);
    amm_config.protocol_fee_rate = protocol_fee_rate;
}

fn update_trade_fee_rate(amm_config: &mut Account<AmmConfig>, trade_fee_rate: u64) {
    assert!(trade_fee_rate + amm_config.creator_fee_rate < FEE_RATE_DENOMINATOR_VALUE);
    amm_config.trade_fee_rate = trade_fee_rate;
}

fn update_fund_fee_rate(amm_config: &mut Account<AmmConfig>, fund_fee_rate: u64) {
    assert!(fund_fee_rate <= FEE_RATE_DENOMINATOR_VALUE);
    assert!(fund_fee_rate + amm_config.protocol_fee_rate <= FEE_RATE_DENOMINATOR_VALUE);
    amm_config.fund_fee_rate = fund_fee_rate;
}

fn update_creator_fee_rate(amm_config: &mut Account<AmmConfig>, creator_fee_rate: u64) {
    assert!(creator_fee_rate + amm_config.trade_fee_rate < FEE_RATE_DENOMINATOR_VALUE);
    amm_config.creator_fee_rate = creator_fee_rate;
}

fn set_new_protocol_owner(amm_config: &mut Account<AmmConfig>, new_owner: Pubkey) -> Result<()> {
    require_keys_neq!(new_owner, Pubkey::default());
    #[cfg(feature = "enable-log")]
    msg!(
        "amm_config, old_protocol_owner:{}, new_owner:{}",
        amm_config.protocol_owner.to_string(),
        new_owner.key().to_string()
    );
    amm_config.protocol_owner = new_owner;
    Ok(())
}

fn set_new_fund_owner(amm_config: &mut Account<AmmConfig>, new_fund_owner: Pubkey) -> Result<()> {
    require_keys_neq!(new_fund_owner, Pubkey::default());
    #[cfg(feature = "enable-log")]
    msg!(
        "amm_config, old_fund_owner:{}, new_fund_owner:{}",
        amm_config.fund_owner.to_string(),
        new_fund_owner.key().to_string()
    );
    amm_config.fund_owner = new_fund_owner;
    Ok(())
}
