### Title
Webhook signature verification is scoped to `repository.owner.login`, but event processing acts on the unrelated `repository.full_name` field, letting an attacker forge events for any tracked repository by pointing at an unprotected organization - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the HMAC signature against using `repository_owner`, taken straight from the unauthenticated JSON body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). [1](#0-0) 
However, the actual event handlers resolve which `Repository`/`Stack` to mutate using a *different* payload field, `repository.full_name`, via `Handler#repository_name`. [2](#0-1) 
These two fields are never checked for consistency.

### Finding Description
`verify_webhook_signature` short-circuits and returns `true` whenever the resolved GitHub App has no `webhook_secret` configured: [3](#0-2) 
Multi-organization Shipit deployments are an explicitly documented configuration (see the sample multi-org `config/secrets.development.shopify.yml`, where `webhook_secret` is commented as `# nil`/optional), so it's realistic for one configured organization to have no webhook secret while another (that owns the actually-targeted repository/stack) does. [4](#0-3) 

An attacker can therefore:
1. Craft a webhook body with `repository.owner.login` (or `organization.login`) set to the secret-less organization — this makes `verify_signature` pass unconditionally, without knowing any secret.
2. Set `repository.full_name` in the same body to `protected-org/some-tracked-repo` — the repository actually managed by Shipit under a different, secret-protected organization.
3. POST this forged payload to the public `/github/webhooks` endpoint with an arbitrary `X-Github-Event` header (`push`, `status`, `check_suite`, `deployable_status`, etc.).

Because `verify_signature` never checks that `repository_owner` matches the owner encoded in `repository.full_name`, the signature check is satisfied for the wrong organization while the handler executes against the intended target's data. `PushHandler` will run `stack.sync_github(expected_head_sha: params.after)` with an attacker-chosen SHA for any not-archived stack on the target repo/branch, and `StatusHandler` will create an arbitrary `Status` for any commit SHA it likes: [5](#0-4) [6](#0-5) 

The broken binding, stated as an equality that should hold but doesn't:
`organization whose webhook secret authenticated the request` == `owner of the repository the handler acts on (repository.full_name)`.

### Impact Explanation
Forged `status` events let an unprivileged, unauthenticated attacker inject arbitrary commit statuses (state, context, target_url) for any commit SHA on any stack tracked by the Shipit instance, as long as at least one configured GitHub organization lacks a webhook secret. Commit status is used by Shipit to gate mergeability/deployability decisions, so this can produce an unauthorized merge or deploy signal being fed into the merge queue/stack pipeline. Forged `push`/`check_suite` events similarly let the attacker trigger sync jobs and check-run refreshes for stacks they have no access to. This crosses the "unauthorized deploy, rollback, or merge" bar defined for High/Critical impact.

### Likelihood Explanation
Exploitation requires no credentials, no repository access, and no GitHub App secret — only that the Shipit deployment manages at least two GitHub organizations, one of which has no `webhook_secret` configured (an explicitly supported, documented configuration). Given that, forging the request is a single unauthenticated HTTP POST.

### Recommendation
In `WebhooksController#verify_signature`, derive the organization used for signature verification from the same field the handlers use to resolve the target repository (`repository.full_name`'s owner segment), and reject the request if `repository.owner.login`/`organization.login` doesn't match. Additionally, do not allow `verify_webhook_signature` to silently pass for organizations without a configured secret when a `repository.full_name` in the payload points to a stack owned by a different, secret-protected organization — e.g., require webhook secrets to be mandatory for all configured organizations, or validate the resolved repository's actual owner against the same App's organization before verifying.

### Proof of Concept
Given a Shipit config with two orgs, `unprotected-org` (no `webhook_secret`) and `protected-org` (with a real `webhook_secret`, owning the tracked `protected-org/prod` repo/stack):

```
POST /github/webhooks
X-Github-Event: status
X-Hub-Signature: sha1=anything

{
  "sha": "<victim-commit-sha-on-protected-org/prod>",
  "state": "success",
  "context": "ci/tests",
  "repository": {
    "full_name": "protected-org/prod",
    "owner": { "login": "unprotected-org" }
  }
}
```

`repository_owner` resolves to `unprotected-org`, so `Shipit.github(organization: 'unprotected-org').verify_webhook_signature` returns `true` (no secret configured), bypassing signature verification entirely. [7](#0-6) 
`StatusHandler#process` then runs against `Commit.where(sha: params.sha)` for the commit belonging to `protected-org/prod`, creating a forged "success" status without ever validating against `protected-org`'s secret. [6](#0-5)

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
