## Title
Remote DoS via unhandled `throw Error` on malformed private (indivisible-asset) payment chain — crashes the node ([File: validation.js])

### Summary
CVE-2023-37015 crashes Open5GS MME with an assertion triggered by a malformed S1AP message that omits a required field (`MME_UE_S1AP_ID`). The direct analog in `ocore--017` is in the private-payment validation path for indivisible (fixed-denomination) private assets: `validatePaymentInputsAndOutputs()` in `validation.js` performs `throw Error(...)` — instead of returning a normal validation error through `callback()` — when `objValidationState.src_coin` is missing required sub-fields. Because `src_coin` is populated earlier from attacker-controlled fields of a private payment chain sent by any private-payment counterparty, a peer can omit/corrupt those fields to make the validator `throw`, producing an uncaught exception that crashes the node process — the same "malformed message missing required field → assertion/throw → crash" bug class as the CVE.

The pre-check does not require `denomination` to be a positive integer or `outputs[i].amount` to be valid, so a corrupted chain passes this gate and reaches `validatePaymentInputsAndOutputs`, where the `throw` occurs deep inside asynchronous DB-callback code (`async.eachSeries`/`async.series` chains in `indivisible_asset.js` and `validation.js`), outside any surrounding `try/catch`. An uncaught exception thrown from inside a Node.js callback (not wrapped by domain/try-catch at that call depth) crashes the whole process, exactly like the Open5GS assertion crash triggered by a missing required ASN.1 field.

### Impact Explanation
This is a remotely triggerable denial-of-service: any private-payment counterparty (a peer that a wallet exchanges private payments with, or a hub relaying such payments) can send a specially crafted private payment chain for a private fixed-denomination asset that omits/corrupts `denomination` or output `amount`, causing the receiving node/wallet process to crash via an unhandled `throw`. Repeated delivery can be used to repeatedly crash the target, matching "a network unable to confirm new units" / DoS class explicitly accepted by the validation rules.

### Likelihood Explanation
The reachable path only requires being a private-payment counterparty capable of sending `private_payment_chains` content (over the wallet/hub protocol) — no elevated privilege, no witness/hub-operator status, and no malicious peer/node assumption beyond a normal correspondent. The loose validation in `wallet.js`'s `handlePrivatePaymentChains` (checking only object/array non-emptiness, not field validity) makes it straightforward to construct a payload that slips past pre-checks and reaches the unguarded `throw` in `validation.js`.

### Recommendation
Replace the `throw Error(...)` statements at `validation.js:2416-2424` with calls to `cb(...)`/`callback(...)` that surface a normal validation error instead of throwing, and add explicit shape/type validation for `payload.denomination` and `outputs[i].amount` earlier — both when building `src_coin` in `indivisible_asset.js` (`validatePrivatePayment`) and in the coarse pre-check in `wallet.js`'s `handlePrivatePaymentChains` — so malformed private chains are rejected gracefully rather than crashing the process.

### Proof of Concept
1. Attacker controls (or corrupts) a private payment chain element sent to a victim wallet, e.g., via `handlePrivatePaymentChains`/`handleOnlinePrivatePayment` for a private, `fixed_denominations` asset.
2. Craft `objPrevPrivateElement` such that `payload.denomination` is `0`/`null`/omitted, or the referenced `payload.outputs[output_index]` lacks a valid positive-integer `amount`, while still satisfying the shallow checks in `wallet.js:959-972` and `indivisible_asset.js:102-105` (blinding present, outputs array present).
3. When the victim validates the chain, `indivisible_asset.js` populates `objValidationState.src_coin` with the invalid `denomination`/`amount`.
4. `validatePaymentInputsAndOutputs` in `validation.js` reaches the `transfer` branch for this private asset and executes `throw Error("no denomination in src coin")` or `throw Error("no src coin amount")` inside an async DB callback, producing an uncaught exception that crashes the victim's node/wallet process.
