Asset Hub Kusama nomination-pools `PostUnbondingPoolsWindow` is a fixed constant, unlike Asset Hub Polkadot, leaving the `AreNominatorsSlashable`-driven `TotalUnbondingPools` bound-shrink bug technically reachable - (File: `system-parachains/asset-hubs/asset-hub-kusama/src/staking/nom_pools.rs`)

### Summary
`pallet-nomination-pools` derives its internal bound on the number of historical unbonding sub-pools (`TotalUnbondingPools`) as `StakeAdapter::bonding_duration() + PostUnbondingPoolsWindow`. `StakeAdapter::bonding_duration()` resolves to `StakingInterface::nominator_bonding_duration()`, which is governed by the dynamically-settable `pallet_staking_async::AreNominatorsSlashable` storage item: `true` yields `BondingDuration` (28), `false` yields the much smaller `NominatorFastUnbondDuration` (2). This is directly analogous to `GOVERNANCE_TOKENS_PER_NFT` in the external report: a governance-adjustable multiplier/rate that feeds into an accounting bound used for existing user balances/state.

Asset Hub Polkadot fixed this exact class of bug (documented in-repo as "bugbounty report #90", changelog 2.3.1, PR #1201) by replacing the fixed `PostUnbondingPoolsWindow = ConstU32<4>` with a dynamic implementation that compensates for the flag flip, keeping `TotalUnbondingPools` pinned at its historical maximum (32) regardless of `AreNominatorsSlashable`'s value: [1](#0-0) 

Asset Hub Kusama, however, still uses the plain fixed constant: [2](#0-1) 

### Finding Description
`pallet_staking_async::AreNominatorsSlashable` is a runtime storage flag controlled by `AdminOrigin` (`EitherOf<EnsureRoot<AccountId>, StakingAdmin>` on Asset Hub Kusama): [3](#0-2) 

The Kusama config comment explicitly acknowledges the danger but relies purely on operational policy, not a technical safeguard: [4](#0-3) 

If `AreNominatorsSlashable` were ever set to `false` via governance/`StakingAdmin` on Asset Hub Kusama (there is no runtime-level restriction preventing this — it is the same storage item and same `AdminOrigin` mechanism used on Polkadot, which *does* flip it), `nominator_bonding_duration()` would drop from 28 to `NominatorFastUnbondDuration`, and because `PostUnbondingPoolsWindow` stays fixed at `ConstU32<4>`, the pallet's computed `TotalUnbondingPools` bound would shrink from 32 to 6. Any existing pool's `SubPools::with_era` map that grew beyond the new bound (built up over the prior 28-era window) would become undecodable under the shrunk `BoundedBTreeMap` size, and the pallet's own decode-or-default fallback would silently replace it with an empty map on the next `unbond` call — destroying per-era unbonding accounting and each era's points-to-balance ratio, exactly mirroring the burn/mint accounting inconsistency described in the `ApiologyDAOToken::_burnGovernanceTokens` report where a governance-changed rate parameter corrupts a per-user accounting invariant.

Asset Hub Polkadot's own regression test explicitly demonstrates the exact mechanics of this bug and its fix: [5](#0-4) 

Asset Hub Kusama has no equivalent test and no equivalent compensating `Get<u32>` implementation, so it does not carry forward the fix that Polkadot's own codebase proves is necessary for this exact scenario.

### Impact Explanation
If `AreNominatorsSlashable` is toggled to `false` on Asset Hub Kusama after pools have accumulated more than 6 eras' worth of unbonding sub-pools (a realistic scenario after 28 eras of normal operation, matching the currently configured `BondingDuration`), affected nomination pool members would have their per-era unbonding accounting silently reset to empty/default. This can cause members to lose the ability to correctly withdraw unbonded funds tied to specific eras and corrupts the points-to-balance ratio integrity that the pallet relies on for fair payouts — a High-severity accounting failure impacting all unprivileged pool members, not just an attacker.

### Likelihood Explanation
Likelihood is Medium: it requires a privileged governance/`StakingAdmin` action to flip `AreNominatorsSlashable`, which the Kusama runtime authors currently do not intend to exercise (per the code comment). However, this is not enforced by the runtime — it is the same code path and same admin origin that Polkadot's own runtime uses in production (Polkadot does flip this flag as evidenced by its dedicated fix and regression test). A future policy change, a copy-paste governance proposal mirroring Polkadot's, or simple oversight could trigger it on Kusama, and unlike Polkadot, Kusama has no compensating mechanism to prevent state corruption.

### Recommendation
Apply the same fix used on Asset Hub Polkadot to Asset Hub Kusama: replace the fixed `type PostUnbondingPoolsWindow = frame_support::traits::ConstU32<4>` with a `Get<u32>` implementation that computes the window as `BondingDuration::get() + 4 - nominator_bonding_duration()`, pinning `TotalUnbondingPools` at its historical maximum (32) regardless of the `AreNominatorsSlashable` flag state, and add the equivalent regression test (`nomination_pools_bound_survives_nominator_unslashable_flip`) to Asset Hub Kusama.

### Proof of Concept
1. On Asset Hub Kusama, an account bonds into a nomination pool and repeatedly unbonds across many eras while `AreNominatorsSlashable = true` (default), accumulating a `SubPools::with_era` map sized based on `nominator_bonding_duration() = 28` (i.e., up to `28 + 4 = 32` entries).
2. Governance/`StakingAdmin` (the same `AdminOrigin` used on both Polkadot and Kusama Asset Hubs) sets `pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(false)`.
3. `nominator_bonding_duration()` now returns `NominatorFastUnbondDuration` (2). Because `PostUnbondingPoolsWindow` is the fixed `ConstU32<4>` on Kusama (unlike Polkadot's dynamic compensation), the pallet's `TotalUnbondingPools` bound becomes `2 + 4 = 6`.
4. On the next `unbond` call by any affected pool member, the pallet attempts to decode the existing (larger than 6-entry) `SubPools::with_era` bounded map, fails, and falls back to an empty/default map — as demonstrated by Polkadot's own test at `system-parachains/asset-hubs/asset-hub-polkadot/src/lib.rs:3170-3209`, which proves the mechanics of the bound shrink (32→6) that Kusama's unmodified `nom_pools.rs` remains exposed to. /// Bound for `pallet_nomination_pools::SubPools::with_era`, frozen at its historical maximum so it
/// does not shrink when the nominator bonding duration drops.
///
/// The pallet derives its `TotalUnbondingPools` bound as `StakeAdapter::bonding_duration() +
/// PostUnbondingPoolsWindow`, and `StakeAdapter::bonding_duration()` resolves to
/// `StakingInterface::nominator_bonding_duration()`, which drops from `BondingDuration` (28) to
/// `NominatorFastUnbondDuration` (2) the moment `AreNominatorsSlashable` is set from `true` to
/// `false`. With a fixed window the bound would shrink 32 -> 6, making any oversized historical
/// `with_era` map undecodable; the next `unbond` then overwrites it with an empty `Default`,
/// destroying per-era unbonding accounting (bugbounty report #90).
///
/// We pin the bound at `BondingDuration + 4 = 32` by computing the window as `MAX -
/// nominator_bonding_duration()`. Subtracting the same value the pallet adds keeps
/// `TotalUnbondingPools == MAX` by construction, regardless of the flag. Post-flip this also widens
/// the effective merge window to `32 - 2 = 30` eras, keeping each per-era pool on its correct
/// points-to-balance ratio long enough for deferred pre-flip slashes (`SlashDeferDuration = 27`) to
/// still be applied.
///
/// TODO: this is an interim runtime fix, meant to be superseded by the in-pallet decoupling in
/// polkadot-sdk.
pub struct PostUnbondingPoolsWindow;
impl Get<u32> for PostUnbondingPoolsWindow {
	fn get() -> u32 {
		// Historical maximum number of unbonding sub-pools: the validator bonding duration plus the
		// legacy 4-era post-unbonding window. `BondingDuration` is the upper bound of
		// `nominator_bonding_duration()`, so the subtraction below never saturates.
		let max_unbonding_pools = BondingDuration::get().saturating_add(4);
		max_unbonding_pools
			.saturating_sub(<Staking as sp_staking::StakingInterface>::nominator_bonding_duration())
	}
}

	#[test]
	fn nomination_pools_bound_survives_nominator_unslashable_flip() {
		use frame_support::traits::Get;
		use sp_staking::StakingInterface;

		sp_io::TestExternalities::new(Default::default()).execute_with(|| {
			// The bound the pallet actually uses for `SubPools::with_era`.
			let total_unbonding_pools = || {
				<Staking as StakingInterface>::nominator_bonding_duration() +
					<Runtime as pallet_nomination_pools::Config>::PostUnbondingPoolsWindow::get()
			};

			// Pre-flip: nominators slashable, so the nominator bonding duration is the full
			// `BondingDuration` and the post-unbonding window is the legacy 4. Set explicitly
			// rather than relying on the storage default so the test pins both flag states
			// itself.
			pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(true);
			assert_eq!(<Staking as StakingInterface>::nominator_bonding_duration(), 28);
			assert_eq!(
				<Runtime as pallet_nomination_pools::Config>::PostUnbondingPoolsWindow::get(),
				4
			);
			assert_eq!(total_unbonding_pools(), 32);

			// The flip: nominators become non-slashable, so the nominator bonding duration drops to
			// `NominatorFastUnbondDuration` (2). The window must widen to 30 so the bound stays 32.
			pallet_staking_async::AreNominatorsSlashable::<Runtime>::put(false);
			assert_eq!(<Staking as StakingInterface>::nominator_bonding_duration(), 2);
			assert_eq!(
				<Runtime as pallet_nomination_pools::Config>::PostUnbondingPoolsWindow::get(),
				30
			);
			assert_eq!(total_unbonding_pools(), 32);
		});
