### Title
Webhook signature verification is keyed to `repository.owner.login` while `AssignedHandler` (and its siblings) trust the independent `repository.full_name` field, allowing cross-tenant `PullRequest` mutation when any configured org lacks a `webhook_secret` - (File: app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/secret to check against using `params.dig('repository','owner','login')`, and `GitHubApp#verify_webhook_signature` auto-passes (`return true unless webhook_secret`) whenever that org has no secret configured. Once verification passes, `Shipit::Webhooks.for_event(event)` dispatches to `AssignedHandler` (and other pull_request handlers) with the raw, unconstrained `params`, and `AssignedHandler#repository` independently re-derives the target repository from `params.repository.full_name` - a field never checked against the org used for verification.

### Finding Description
The broken binding is: `verifying_org (params.dig('repository','owner','login'))` should equal `mutated_repository_owner (params.repository.full_name.split('/').first)`. Nothing in the code enforces this equality.

- `app/controllers/shipit/webhooks_controller.rb:24-30` computes `repository_owner` from `repository.owner.login` (or `organization.login`) and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) 
- `lib/shipit/github_app.rb:76-83` `verify_webhook_signature` returns `true` unconditionally when `@webhook_secret` is blank for that org's config. [2](#0-1) 
- `app/models/shipit/webhooks.rb:39-41` `for_event` dispatches purely by the `X-Github-Event` header string, with no org parameter at all. [3](#0-2) 
- `app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb:41-69` `process`/`repository`/`pull_request` use `params.repository.full_name` (a separate JSON field from the one checked in `verify_signature`) to look up the target `Repository`/`PullRequest`, then calls `pull_request.update(github_pull_request: params.pull_request)`. [4](#0-3) 

Exploit flow (requires a multi-org Shipit deployment where at least one configured org, `weak-org`, has no `webhook_secret` set - a supported, non-error configuration state since `verify_webhook_signature` explicitly treats a missing secret as "no verification needed"):
1. Attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a body where `repository.owner.login = "weak-org"` (so `verify_signature` resolves `Shipit.github(organization: 'weak-org')`, whose `webhook_secret` is blank, and the signature check auto-passes regardless of the `X-Hub-Signature` header contents) but `repository.full_name = "victim-org/victim-repo"`.
2. `verify_signature` passes; `for_event('pull_request')` returns the default handler list (including `AssignedHandler`) with no org filtering. [5](#0-4) 
3. `AssignedHandler.new(params).process` resolves `repository` via `Repository.from_github_repo_name(params.repository.full_name)` = the real `victim-org/victim-repo`, finds the matching `PullRequest` by `number`, and calls `pull_request.update(github_pull_request: params.pull_request)` with attacker-supplied assignee/label/PR data - a write to a different tenant's record that was never subject to any signature check tied to that tenant. [6](#0-5) 

`AssignedHandler`'s own `params` schema only requires `repository.full_name`, not `repository.owner.login`, so nothing prevents an attacker from including both an `owner.login` (used solely by the controller for secret lookup) and a divergent `full_name` (used by the handler for the actual mutation) in the same payload. [7](#0-6) 

Existing guards do not close this gap: `drop_unhandled_event` and `check_if_ping` only gate on the event type; `verify_signature`'s `GithubOrganizationUnknown` rescue only rejects fully-unrecognized org names, not a mismatch between the verifying org and the mutated repository; `ExplicitParameters` in the handler enforces field *presence/type*, not cross-field consistency with the field used for signature verification.

### Impact Explanation
An attacker who can compute a request against a Shipit-configured org with no `webhook_secret` (or send any bytes as `X-Hub-Signature` if literally no secret exists) can cause `AssignedHandler` to write attacker-controlled `github_pull_request` data (assignees, labels, title, state, etc.) onto a `PullRequest` belonging to an entirely different, unrelated org/repository. The same disconnect between "org used to verify" and "org whose data is mutated" applies to every other handler in `default_handlers` that derives its target repository from `params.repository.full_name` (`OpenedHandler`, `ClosedHandler`, `ReopenedHandler`, `EditedHandler`, `LabeledHandler`, `UnlabeledHandler`, `LabelCapturingHandler`), so the blast radius extends to stack provisioning/archival actions triggered by those handlers, not just `PullRequest#update`. This is repeatable per request and matches "authentication bypass -> cross-tenant record mutation for a repository that did not authenticate the payload."

### Likelihood Explanation
Exploitation requires the specific precondition of a multi-org Shipit deployment with at least one configured org lacking `webhook_secret` - the code permits and silently accepts this configuration rather than rejecting it, so it is a plausible real-world state (e.g., an org added without completing secret setup) rather than a purely theoretical one. Given that precondition, the attacker needs no Shipit credentials, no knowledge of any secret, and only needs to know the name of the weakly-configured org and the target `owner/repo` full name (both are public/observable) - cost is a single unauthenticated HTTP POST, fully repeatable against any tracked repository/stack.

### Recommendation
In `WebhooksController#verify_signature`, after signature verification succeeds, additionally verify that the organization used for verification matches the owner encoded in every repository-bearing field of the payload (e.g., `params.dig('repository','full_name')`'s owner segment) before dispatching to handlers, and reject (422) on mismatch. Separately, treat a missing `webhook_secret` for a configured org as a hard misconfiguration error (refuse to boot / reject all webhooks for that org) rather than silently disabling signature verification in `GitHubApp#verify_webhook_signature`.

### Proof of Concept
```ruby
# test/models/shipit/webhooks/handlers/pull_request/assigned_handler_test.rb (extension)
test "process mutates a PullRequest for a repository unrelated to any verifying org" do
  pull_request = shipit_pull_requests(:review_stack_review)
  pull_request.assignees.clear

  payload = payload_parsed(:pull_request_assigned)
  payload["number"] = pull_request.number
  payload["pull_request"]["number"] = pull_request.number
  # repository.full_name here is fully attacker controlled and independent
  # of whatever org name was used by WebhooksController#verify_signature
  payload["repository"]["full_name"] = pull_request.stack.repository.github_repo_name
  payload["repository"]["owner"] = { "login" => "completely-unrelated-org" }

  AssignedHandler.new(payload).process

  assert_equal [shipit_users(:codertocat)], pull_request.reload.assignees
end
```
This demonstrates that `AssignedHandler` performs the write purely based on `params.repository.full_name`, with zero binding to `params.repository.owner.login` (the field the controller uses to select the verifying org's secret), confirming the missing equality check described above.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def process
            return unless respond_to_assignee_change?

            pull_request.update(github_pull_request: params.pull_request) if pull_request.present?

          private

          def respond_to_assignee_change?
            %w[assigned unassigned].include?(params.action)
          end

          def pull_request
            @pull_request ||= Shipit::PullRequest

                                      id: repository.id
                                    }

          end
