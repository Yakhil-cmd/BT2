### Title
Signature-verification organization selector is taken from request params independent of the signed body, allowing bypass via an unconfigured/secret-less org — (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp` (and therefore the `webhook_secret`) used to authenticate a webhook based on `repository_owner`, which reads from Rails' `params` helper (query string + body merged) before the `create` action runs. The actual event-processing code in `create` re-parses `request.raw_post` into a local `params` variable and dispatches it to handlers, using whatever organization/repository the *body* claims — not necessarily the organization whose secret was used for verification. [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
This is a direct analog of the reported bug class: a field ("which organization authenticates this request") that is *acted upon* to select the trust anchor (`webhook_secret`), but is not itself bound to the data covered by the signature.

- `repository_owner` is computed from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` using the framework's `params`, which is the union of query-string and body parameters (query params survive whenever the corresponding top-level key, e.g. `organization` or `repository`, is absent from the JSON body). [5](#0-4) 
- `verify_signature` uses that attacker-influenceable `repository_owner` to select which `GitHubApp` (and thus which `webhook_secret`) is used to validate `X-Hub-Signature` against `request.raw_post`. [6](#0-5) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever the selected organization's `webhook_secret` is blank/unset. [7](#0-6) 
- `create` then re-parses the raw body independently (`params = JSON.parse(request.raw_post)`) and dispatches the event to `Shipit::Webhooks.for_event(event)` handlers using whatever organization/repository the body itself states — with no re-check that this matches the organization used for the signature check. [8](#0-7) 

Equality that is broken: `organization that authenticated (verify_signature's repository_owner, derived from query+body-merged params, selecting webhook_secret)` should equal `organization/repository the handlers actually act on (create's freshly-parsed body params)` — but nothing enforces this. In a multi-organization deployment (documented "Using Multiple GitHub Applications" configuration, exercised by `Shipit.github_app_config`/`github_organizations`), any org lacking a `webhook_secret` (shown as the default in `config/secrets.development.example.yml` and `config/secrets.development.shopify.yml`) becomes a universal bypass key: an attacker sends an unsigned/arbitrary-signed POST to `/webhooks?organization[login]=<org-without-secret>` with an `X-Github-Event: membership` body whose JSON claims `organization.login` = the real, team-gated organization. Because the body has no top-level `repository` or `organization` key that would collide with the query-string value used for `repository_owner`... actually to be precise: since the JSON body legitimately contains its own `organization` key (required by `MembershipHandler`), the attacker instead supplies the bypass hint via a `repository[owner][login]` query parameter (not present in a `membership` event body), so `repository_owner` resolves to the secret-less org for verification while `create`'s body-derived `params.organization.login` targets the victim org. [9](#0-8) [10](#0-9) 

### Impact Explanation
A successful forged `membership` event lets an unauthenticated attacker call `team.add_member(member)` for any GitHub login, adding an arbitrary user to a `Team` tied to `Shipit.github_teams`. Since `User#authorized?` grants application access based on membership in `Shipit.github_teams`, this is escalation into `Shipit.github_teams` authorization — meeting the High-impact bar defined in the rules. Other events (`push`, `status`, `check_suite`) forged the same way could similarly trigger unauthorized `GithubSyncJob`, fabricate commit statuses, or fake CI check results feeding into deploy/merge gating for a targeted stack, without ever possessing that stack's real `webhook_secret`. [2](#0-1) [11](#0-10) 

### Likelihood Explanation
Requires no credentials, tokens, or repository access — only that the deployment uses the documented multi-organization GitHub App configuration with at least one configured organization missing a `webhook_secret` (the example/onboarding config files ship with `webhook_secret: # nil` by default). This is a realistic, easy-to-overlook misconfiguration rather than a theoretical one, and the endpoint (`/webhooks`) is intentionally unauthenticated by design (it must accept GitHub's calls), so the only defense is the per-organization signature check that this flaw undermines.

### Recommendation
- Derive the organization used for signature verification and the organization/repository actually processed in `create` from the exact same parsed body object (parse `request.raw_post` once, before `verify_signature`, and reuse it) — never let Rails' merged `params` (which can include query-string-only keys) influence which secret is selected.
- Reject any webhook whose resolved `GitHubApp` has a blank `webhook_secret` in a multi-organization configuration, rather than treating an absent secret as an implicit pass.
- After signature verification, assert that the organization actually referenced by the verified body matches the organization used to select the verifying secret before dispatching to handlers.

### Proof of Concept
1. Deploy Shipit with a multi-organization `github` config where `victim-org` has `oauth.teams` configured (grants `Shipit.github_teams`) and a second configured org `no-secret-org` has `webhook_secret` unset (default/onboarding state).
2. Send: `POST /webhooks?repository[owner][login]=no-secret-org` with headers `X-Github-Event: membership` and `X-Hub-Signature: sha1=deadbeef` (arbitrary/invalid), and JSON body:
```json
{"action":"added","team":{"id":1,"name":"Cooks","slug":"cooks","url":"https://example.com"},"organization":{"login":"victim-org"},"member":{"login":"attacker"}}
```
3. `verify_signature` computes `repository_owner` from merged params → `no-secret-org` (query-string only, absent from body) → `Shipit.github(organization: 'no-secret-org').verify_webhook_signature(...)` returns `true` because `webhook_secret` is blank.
4. `create` re-parses the raw body and dispatches to `MembershipHandler`, which adds `attacker` to the `victim-org` team referenced in the body, granting the attacker `Shipit.github_teams` authorization on the real Shipit instance.

module Shipit
  module Webhooks
    module Handlers
      class MembershipHandler < Handler
        params do
          requires :action, String
          requires :team do
            requires :id, Integer
            requires :name, String
            requires :slug, String
            requires :url, String
          end
          requires :organization do
            requires :login, String
          end
          requires :member do
            requires :login, String
          end
        end
        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
      end
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
