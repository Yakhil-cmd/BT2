### Title
`GetCurrentLogin` performs `httpClient.Do(req)` with no context deadline or timeout, allowing a stalling attacker-controlled host to hang `gh auth login` indefinitely - ([File: pkg/cmd/auth/shared/login_flow.go])

### Summary
`GetCurrentLogin` builds its GraphQL request via `http.NewRequest` and calls `httpClient.Do(req)` with no `context.WithTimeout`/`context.WithDeadline` and no per-request cancellation, so if the resolved host accepts the TCP connection but never sends a response, the call blocks forever. Because `--hostname` lets a user point `gh auth login` at an arbitrary (including attacker-controlled) endpoint, this is a reachable, unbounded hang in a documented attack surface ("host the victim points gh at").

### Finding Description
In `pkg/cmd/auth/shared/login_flow.go`: [1](#0-0) 

`GetCurrentLogin` constructs the request with `http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))` and never calls `req.WithContext(ctx)` with a bounded context, nor is there any `context.WithTimeout` wrapping the call site. It then directly calls `httpClient.Do(req)`. If the resulting `*http.Client` (`opts.HTTPClient`, ultimately from `f.HttpClient()`) has no `Timeout` field configured, Go's standard library will wait indefinitely for the server to write a response as long as the TCP connection stays open — a classic "slow-loris"/stalling-server condition. Since `Login` in the same file calls `GetCurrentLogin(httpClient, hostname, authToken)` after all interactive prompts (protocol choice, SSH key generation/upload prompts, token entry) have already completed, a hang here strands the whole `gh auth login` process after the user has already provided sensitive input (token) and consumed resources (open SSH key file descriptor via `sshKeyUpload`, terminal state, etc.). [2](#0-1) 

The `hostname` fed into `ghinstance.GraphQLEndpoint(hostname)` and thus the endpoint host itself is attacker-influenced when a user runs `gh auth login --hostname <attacker-host>` (e.g., an "enterprise" endpoint suggested by a malicious setup guide) — this matches the rules' allowed precondition "controls responses from a host the victim points gh at." No existing safeguard (`safeurl.JoinPathWithHostPrefix` only normalizes/validates the URL shape, it does not impose a network timeout) mitigates this.

### Impact Explanation
This is a client-side, self-inflicted-but-attacker-triggerable Denial of Service: the `gh auth login` process hangs indefinitely, tying up the terminal session and any resources acquired earlier in the flow (open SSH key file, entered token still only in memory). It does not lead to code execution, credential exfiltration, or file write outside intended paths — it is a pure availability/resource-exhaustion issue scoped to the invoking process, not a persistent server-side or cross-user resource-consumption vector. This maps to a low-severity "unbounded resource consumption" / DoS class rather than a compromise class (no execution, no credential leak, no auth bypass).

### Likelihood Explanation
Requires the victim to explicitly authenticate against a hostname that the attacker controls or influences (via `--hostname`), and requires `opts.HTTPClient` to lack a client-level `Timeout`. This is fully reproducible: any TCP listener that accepts connections and never writes a response will trigger the hang. Likelihood of the victim pointing `gh auth login` at an attacker's endpoint is comparatively low for `github.com` users, but realistic for GHE/enterprise-onboarding-style social engineering scenarios explicitly permitted by the rules.

### Recommendation
Add a request-scoped timeout to `GetCurrentLogin` (and similarly `HasMinimumScopes`/`sshKeyUpload` if they share the pattern), e.g. wrap the request with `context.WithTimeout` and `req = req.WithContext(ctx)` before calling `httpClient.Do(req)`, or ensure the `http.Client` used throughout the auth flow has a sane default `Timeout` (and/or `http.Transport` dial/response-header timeouts) set centrally when constructed via `f.HttpClient()`/`api.NewHTTPClient`.

func GetCurrentLogin(httpClient httpClient, hostname, authToken string) (string, error) {
	query := `query UserCurrent{viewer{login}}`
	reqBody, err := json.Marshal(map[string]interface{}{"query": query})
	if err != nil {
		return "", err
	}
	result := struct {
		Data struct{ Viewer struct{ Login string } }
	}{}
	apiEndpoint, err := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))
	if err != nil {
		return "", err
	}
	req, err := http.NewRequest("POST", apiEndpoint.String(), bytes.NewBuffer(reqBody))
	if err != nil {
		return "", err
	}
	req.Header.Set("Authorization", "token "+authToken)
	res, err := httpClient.Do(req)
	if err != nil {
		return "", err
	}
