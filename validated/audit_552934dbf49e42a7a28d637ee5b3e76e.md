### Title
`_diff_pathspec` treats any repo-relative path beginning with the two literal characters `..` as an out-of-repo traversal, silently dropping legitimately in-scope touched files from the review diff - ([File: plugins/security-guidance/hooks/gitutil.py])

### Summary
`_diff_pathspec` in `plugins/security-guidance/hooks/gitutil.py` filters candidate diff paths with `if r.startswith(".."): continue`, intending to drop paths that `os.path.relpath` resolved to outside the repo root (which always start with `../`). However this check also matches any in-repo file or directory whose repo-relative path literally begins with the two characters `..` (e.g. a file named `..cfg`, `..hidden.py`, or a top-level directory `..stuff/`), which is a fully valid git/POSIX filename. Such a path is silently excluded from the pathspec passed to `git diff`, so edits Claude makes to that path never enter the reviewed diff even though the file is genuinely inside the repository and was legitimately touched during the session.

### Finding Description
`_diff_pathspec` is called from `get_git_diff` (`plugins/security-guidance/hooks/gitutil.py:391-414`) to restrict `git diff` to a specific set of touched paths for the Stop-hook security review: [1](#0-0) 

The intent, per the docstring, is: "Paths outside cwd... are dropped," using `os.path.realpath` on both `cwd` and each candidate path so that filesystem symlinks (e.g. macOS `/var` ↔ `/private/var`) don't falsely mark an in-repo path as external. That symlink-normalization logic is correct — for a symlink pointing genuinely outside the repo, `os.path.realpath(p)` will resolve to the real external target, and `os.path.relpath(..., cwd_abs)` will correctly produce a string starting with `../`.

The bug is in the escape test itself: `r.startswith("..")` is a raw string-prefix check, not a path-component check. `os.path.relpath` only ever prefixes with `..` followed immediately by `os.sep` (e.g. `../foo`) when the target is genuinely outside `cwd_abs`; it will never return a bare `..` string unless the target *is* the parent directory. But this same string prefix also matches perfectly legitimate repo-relative paths whose first path component simply starts with two literal dots, such as `..config`, `..hidden.py`, or a directory `..scratch/notes.py`. Such filenames are valid under POSIX and git (only the exact names `.` and `..` are reserved).

An attacker who can get such a filename into the victim's clone (e.g. by contributing/merging a file named `..payload.py`, or by having Claude create/rename a file to that name during a session) causes that specific touched path to be silently dropped from the pathspec built by `_diff_pathspec`. Because `get_git_diff` only returns an empty/unrestricted-avoidance result when **all** paths are dropped (`if paths and not pathspec: return ""`), a mix of normal touched files plus one `..`-prefixed file still produces a non-empty pathspec — the review proceeds normally for the other files, but the malicious/attacker-named file's changes are quietly excluded from the diff that is sent to the LLM security reviewer and Stop-hook analysis. No error, warning, or metric is produced; the omission is completely silent.

This breaks the stated invariant ("git path scoping must never escape the intended repo target") in the opposite direction from the one guarded against: instead of leaking outside-repo content in, it leaks a legitimate in-repo file out of the review scope while the mechanism continues to "work" for everything else — exactly the "review call still proceeds but with a gap" pattern the question describes.

### Impact Explanation
This is a security-control bypass: it allows specific, chosen file paths to be permanently excluded from the Stop-hook / commit-review diff-based LLM security scan without disabling the plugin or triggering any visible skip/error signal. An attacker who can influence file/directory naming in a repository that a Claude Code session will operate in (via a merged PR, a scaffold template, or a crafted repository the victim clones) can hide vulnerable or malicious code changes made to a `..`-prefixed path from ever being reviewed by the pattern-based and LLM-based review pipelines, while the rest of the session's review continues to look "healthy" (other files still reviewed, no exit code / metrics indicating something was skipped).

### Likelihood Explanation
Preconditions are low-friction: the attacker only needs to get a file or directory whose name begins with `..` into the target repository (via normal contribution flow, a template/scaffold, or a submodule/vendor drop) and have that path be among the "touched paths" scoped into a `get_git_diff(cwd, paths=...)` call. No admin privilege, no symlink tricks, and no interaction with git internals beyond a plain file name are required — this is fully reachable through the "repo-controlled file paths" attacker surface named in the question. The condition is deterministic and 100% reproducible given such a path exists.

### Recommendation
Fix the escape check in `_diff_pathspec` to test path-component boundaries rather than a raw string prefix, e.g.:
```python
if r == ".." or r.startswith(".." + os.sep):
    continue
```
This preserves the outside-repo drop behavior (relpath only ever returns `..` or `../...`) while no longer misclassifying legitimate paths such as `..config` or `..scratch/file.py`. Additionally, consider logging/metric-emitting when a candidate path is dropped so silent exclusions are observable instead of failing invisibly.

### Proof of Concept
Unit test to add to the gitutil test suite:
```python
import os
from gitutil import _diff_pathspec

def test_diff_pathspec_does_not_drop_dotdot_prefixed_filenames(tmp_path):
    repo = tmp_path / "repo"
    repo.mkdir()
    # legitimate in-repo file whose name happens to start with ".."
    target = repo / "..config.py"
    target.write_text("secret = 1")

    result = _diff_pathspec(str(repo), [str(target)])

    # Expected (correct) behavior: the file stays in scope.
    assert result == ["--", "..config.py"], (
        f"expected '..config.py' to remain in the pathspec, got {result}"
    )

def test_diff_pathspec_still_drops_real_outside_repo_paths(tmp_path):
    repo = tmp_path / "repo"
    repo.mkdir()
    outside = tmp_path / "outside.py"
    outside.write_text("x = 1")

    result = _diff_pathspec(str(repo), [str(outside)])
    assert result == []  # correctly dropped, unrestricted-diff-avoidance path
```
Currently the first assertion fails: `_diff_pathspec` returns `[]` for the `..config.py` case (or, when mixed with other legitimately touched files, silently omits it from the returned pathspec), demonstrating that the touched file is excluded from the git diff pathspec used to scope the security review, even though it is genuinely inside the repository.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
