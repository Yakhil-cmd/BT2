### Title
`NonTransfer` proxy on Polkadot/Westend/Rococo relay chains falsely claims superset of `Auction`, letting it self-escalate to `Registrar::swap` - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
The GitLab CVE (BIT-gitlab-2024-1250 / CVE-2024-1250) is a case where a scoped permission grant (`manage_group_access_tokens`) let a role holder mint a *new credential* with privileges wider than the role's own effective permissions. The FRAME analog is `pallet_proxy`'s `add_proxy`/`remove_proxy` gate: a delegate holding a limited `ProxyType` may only create sub-proxies whose `ProxyType` is a `filter()`-consistent subset of its own, enforced via `ProxyType::is_superset`. On the Polkadot/Westend/Rococo relay-chain runtimes, `ProxyType::NonTransfer::is_superset` unconditionally returns `true` for every other variant, but `NonTransfer::filter` explicitly *denies* `Registrar::swap` while `ProxyType::Auction::filter` admits *all* `Registrar` calls including `swap`. This is the exact bug class that was already found and fixed once in this codebase for `NonTransfer`/`Governance` on Asset Hub Westend (see `prdoc/pr_12769.prdoc`, tracking paritytech/polkadot-sdk#12724) — the same mismatch survives, unfixed, in the relay-chain `ProxyType` implementations.

### Finding Description
`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` purely on `def.proxy_type.is_superset(proxy_type)`, not on a per-call comparison of the two filters: [1](#0-0) 

On `polkadot/runtime/westend/src/lib.rs`, `is_superset` declares `NonTransfer` a superset of every other `ProxyType`: [2](#0-1) 

But `NonTransfer::filter` explicitly omits `Registrar::swap` (comment: `// Specifically omitting Registrar 'swap'`), while `Auction::filter` admits the entire `Registrar` call family unrestricted: [3](#0-2) 

The identical pattern exists on Rococo: [4](#0-3) 

This is the precise bug class already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend: [5](#0-4) [6](#0-5) 

The fix and its regression test (`proxy_type_superset_relation_matches_call_filters`, `non_transfer_proxy_is_not_a_superset_of_governance`) were applied only to `asset-hub-westend`'s `ProxyType`, not to the relay-chain (`polkadot/runtime/westend`, `polkadot/runtime/rococo`) `ProxyType` implementations, which retain the same class of `is_superset`/`filter` inconsistency for the `NonTransfer`→`Auction` edge.

### Impact Explanation
An account that delegates only a `NonTransfer` proxy to an attacker-controlled delegate believes that delegate cannot ever move Registrar ownership beyond `register`/`deregister`/`reserve` (swap is explicitly denied). Because `is_superset(NonTransfer, Auction) = true`, the `NonTransfer` delegate can call `Proxy::add_proxy(real, Auction, delay)` on behalf of the delegator's account, then use that self-granted `Auction` proxy to execute `Registrar::swap` on the delegator's account — a call the delegator's `NonTransfer` grant was designed to withhold. This breaks the confinement invariant of `pallet_proxy` (a proxy "cannot add or remove a proxy with more permissions than it already has", per the pallet's own doc comment) and lets a limited delegate exceed its granted authority over the real account's parachain registration/ownership state, matching the "manage_group_access_tokens → Owner token" escalation pattern from the CVE.

### Likelihood Explanation
High reachability, no privileged prerequisite: any account can grant a `NonTransfer` proxy to any delegate (a normal, encouraged usage pattern), and the delegate needs only two ordinary signed extrinsics (`proxy(add_proxy{Auction})` then `proxy(Registrar::swap)`) to reach the excluded call. No governance, root, or validator involvement is required.

### Recommendation
Apply the same fix already used for Asset Hub Westend's `NonTransfer`/`Governance` pair: either (a) remove the blanket `(ProxyType::NonTransfer, _) => true` arm and enumerate only the subsets whose `filter` is fully dominated by `NonTransfer::filter` (as done for `Collator`/`Staking`/`NominationPools`/`StakingOperator` on Asset Hub), or (b) extend `Auction::filter` to also omit `Registrar::swap`, restoring the invariant that `is_superset(X, Y) ⇒ ∀c: Y.filter(c) ⇒ X.filter(c)`. Additionally, port the lattice-wide regression test (`proxy_type_superset_relation_matches_call_filters`) from `asset-hub-westend/tests/tests.rs` to the relay-chain runtime test suites (`polkadot/runtime/westend`, `polkadot/runtime/rococo`) to prevent recurrence.

### Proof of Concept
Guard analyzed: `pallet_proxy::do_proxy`'s `add_proxy`/`remove_proxy` filter closure at `substrate/frame/proxy/src/lib.rs:1005-1013`, which relies solely on `T::ProxyType::is_superset`. Failed guard: `ProxyType::is_superset` in `polkadot/runtime/westend/src/lib.rs:1022-1030` (and mirrored in `polkadot/runtime/rococo/src/lib.rs`) returns `true` for `(NonTransfer, Auction)` even though `Auction::filter` (lines 1004-1010) admits unrestricted `Registrar(..)` while `NonTransfer::filter` (lines 954-982) explicitly excludes `Registrar::swap`.

Minimal reproduction sketch (not executed in this session — no sandbox/terminal access available to run it):

assert_ok!(Proxy::proxy(RuntimeOrigin::signed(DELEGATE), REAL, Some(ProxyType::Auction), swap_call));

title: 'asset-hub-westend: fix `NonTransfer` proxy falsely claiming `Governance` containment'
doc:
- audience: Runtime User
  description: |-
    On Asset Hub Westend, the `NonTransfer` proxy type declared itself a superset of the
    `Governance` proxy type while its call filter denied the `Treasury`, `ConvictionVoting`,
    `Referenda` and `Whitelist` calls that `Governance` admits.

    Because `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `is_superset`, a
    `NonTransfer` proxy could add a `Governance` proxy for its delegator and thereby reach calls
    that its own filter denies. `NonTransfer` no longer declares `Governance` as a subset, so this
    is rejected.

    Existing `Governance` proxies are unaffected; only the ability of a `NonTransfer` proxy to
    create or remove one changes. The `Collator`, `Staking`, `NominationPools` and
    `StakingOperator` subsets of `NonTransfer` are unchanged.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
