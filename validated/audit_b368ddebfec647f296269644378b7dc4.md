Based on my investigation, I found a concrete analog to the reported bug class in `initialize_with_permission.rs`.

### Title
Missing zero-address validation on the `creator` account in `initialize_with_permission` permanently freezes creator fees - ([File: programs/cp-swap/src/instructions/initialize_with_permission.rs])

### Summary
`InitializeWithPermission::creator` is declared as an `UncheckedAccount` with no signer requirement and no constraint preventing it from being the system-owned default pubkey (`11111111111111111111111111111111...`). Its key is stored verbatim as `pool_creator` in `PoolState`, and every subsequent creator-fee-collection instruction trusts that value without validating it is a real, controllable address.

### Finding Description
In `InitializeWithPermission`, the `creator` field has no `address`, `constraint`, or signer requirement: [1](#0-0) 

This unchecked pubkey is passed straight into pool initialization and stored as `pool_creator` in the newly-created `PoolState` account (mirroring the pattern used in `initialize.rs`, which passes `ctx.accounts.creator.key()` into `pool_state.initialize(...)`): [2](#0-1) 

Downstream, two instructions rely on `pool_creator` being a meaningful address:
- `CollectCreatorFee` requires the `creator` account to be a **signer** whose key equals `pool_state.pool_creator`: [3](#0-2) 
- `CollectCreatorFeePermissionless` allows **anyone** to trigger fee collection, requiring only that the `creator` account (an `UncheckedAccount`, no signature) matches `pool_state.pool_creator`, and it auto-creates an associated token account owned by that `creator` to receive the fees: [4](#0-3) [5](#0-4) 

If a permissioned pool creator (or an attacker exploiting a misconfiguration) sets the `creator` account to `Pubkey::default()` during pool creation, no private key exists to sign the `CollectCreatorFee` path, and `CollectCreatorFeePermissionless` will happily create an ATA owned by the zero pubkey and irrevocably transfer all accumulated `creator_fees_token_0`/`creator_fees_token_1` into it: [6](#0-5) 

Because the zero pubkey is a valid `SystemAccount`-owned address but has no corresponding keypair, tokens sent to an ATA of that owner are permanently unrecoverable — a classic freezing-of-funds outcome directly analogous to the reported "lack of zero-address validation" bug class (owner/authority parameters silently accepted without a non-zero check).

### Impact Explanation
This does not corrupt pool solvency accounting or LP shares, but it permanently locks the pool's ongoing creator-fee stream (`creator_fees_token_0`/`creator_fees_token_1`) in an unrecoverable, unowned token account every time `collect_creator_fee_permissionless` is invoked for such a pool. Given `creator_fee_on` can route fees from swaps/deposits into these accumulators indefinitely, this is a persistent freezing-of-funds vulnerability, not a one-off compute-only issue, and it requires no privileged signer beyond a normal pool-creation call.

### Likelihood Explanation
The path is reachable through `initialize_with_permission`, one of the explicitly in-scope pool-creation instructions, purely by the caller choosing a zero-value account for `creator` — no additional exploit conditions are required. The `CollectCreatorFeePermissionless` instruction is deliberately permissionless (any payer can invoke it), so once such a pool exists, anyone (or an automated fee-sweeper) triggering fee collection irreversibly burns the accrued fees.

### Recommendation
Add an explicit non-zero check on the `creator` account in `InitializeWithPermission` (and defensively in `initialize.rs`, even though `creator` there is a `Signer`), e.g. `require_keys_neq!(ctx.accounts.creator.key(), Pubkey::default())`, before storing it as `pool_creator`. Consider also validating that `creator` is not a program-owned/non-standard account that could similarly be unable to receive an ATA-based transfer.

### Proof of Concept
1. Attacker (or any account holding a valid `Permission` PDA) calls `initialize_with_permission`, supplying `creator = Pubkey::default()` (the all-zero pubkey) as the `creator` account — this is legal because the field is an `UncheckedAccount` with no constraint.
2. `pool_state.pool_creator` is stored as the zero pubkey.
3. Swaps/deposits accrue `creator_fees_token_0`/`creator_fees_token_1` in `PoolState` over time.
4. Anyone calls `collect_creator_fee_permissionless`, passing `creator = Pubkey::default()`; the `address = pool_state.load()?.pool_creator` constraint passes trivially, an ATA owned by the zero pubkey is created via `init_if_needed`, and the accrued fees are transferred into it.
5. Because no keypair controls the zero pubkey, the tokens in that ATA can never be withdrawn — the creator-fee funds are permanently frozen.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;
```
