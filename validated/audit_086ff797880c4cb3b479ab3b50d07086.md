### Title
Webhook signature is verified against the organization named in `repository.owner.login`, but event handlers act on the unrelated `repository.full_name` field from the same attacker-supplied JSON body - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In multi-organization Shipit deployments, `WebhooksController#verify_signature` selects which GitHub App config (and therefore which `webhook_secret`) to use for HMAC verification based on `repository.owner.login` (or `organization.login`) taken directly from the unauthenticated JSON body. Once the signature is deemed valid, the actual event handlers locate the `Repository`/`Stack` to mutate using a *different* field of the very same body — `repository.full_name` — with no check that its owner segment matches the organization whose secret validated the signature. This breaks the intended binding "organization that authenticated == repository being written."

### Finding Description
`verify_signature` derives the verifying organization purely from payload content: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` resolves per-organization config from `secrets.github` in multi-tenant setups (as demonstrated by `test/dummy/config/secrets_double_github_app.yml`, which configures independent `webhook_secret`s for `OrgOne` and `OrgTwo`): [3](#0-2) 

After signature verification succeeds, `create` dispatches the same raw payload to handlers: [4](#0-3) 

Every handler resolves the target `Repository`/`Stack` from `repository.full_name`, a field completely independent of `repository.owner.login`: [5](#0-4) [6](#0-5) [7](#0-6) 

`Repository.from_github_repo_name` simply splits `owner/name` out of that field and looks the record up, with no cross-check against the organization used for signature verification: [8](#0-7) 

Nothing in the code compares `repository.owner.login` (used to pick the HMAC secret) to the owner segment of `repository.full_name` (used to select which tracked repository/stack is mutated). An attacker who can produce a validly-signed delivery for *any* organization configured in the same Shipit instance (e.g. an org they administer whose GitHub App has `webhook_secret: nil`, which makes `verify_webhook_signature` return `true` unconditionally) can set `repository.owner.login` to that org while setting `repository.full_name` to `"OtherOrg/target-repo"`. The signature check passes against the attacker's own (possibly secret-less) organization, but `PushHandler`, the pull-request handlers, and other handlers then execute against `OtherOrg/target-repo` — a repository/stack that belongs to a completely different, unrelated organization tracked by the same Shipit deployment. [9](#0-8) 

### Impact Explanation
This crosses the "organization that authenticated versus the repository that is written" trust boundary called out as in-scope. Depending on which handler is reached, an attacker can:
- Trigger `GithubSyncJob`/`sync_github` on a stack belonging to an organization they have no access to (`PushHandler`).
- Archive/unarchive review stacks or capture arbitrary PR labels on another organization's repository (`ClosedHandler`, `LabelCapturingHandler`, `LabeledHandler`, `UnlabeledHandler`).
- Forge commit statuses on commits belonging to a foreign repository's stack.

These are unauthorized cross-repository/cross-organization writes performed without any Shipit session, API token, or GitHub write access to the victim organization/repository — matching the "cross-repository writes" / "unauthorized deploy" impact bar.

### Likelihood Explanation
Exploitability requires the attacker to control (or have a validly-signed delivery for) at least one organization configured on the same Shipit instance — realistic for any multi-tenant/shared Shipit deployment (explicitly supported per `secrets_double_github_app.yml` and `Shipit.github_organizations`) where one tenant org's webhook secret is weak, leaked, or left blank (`webhook_secret: nil` is an accepted, valid config value per `lib/shipit/github_app.rb:76-77`). No additional privilege inside Shipit itself is needed once a validly-signed payload for any tracked org can be produced.

### Recommendation
After signature verification, re-derive the organization from the resolved `Repository`/`Stack` (or from `repository.full_name`'s owner segment) and require it to match the organization whose secret validated the signature; reject the webhook otherwise. Alternatively, bind handler repository resolution to the already-verified `repository_owner` rather than trusting an independent field of the same unauthenticated body.

### Proof of Concept
1. Configure Shipit with two orgs, `AttackerOrg` (`webhook_secret: nil`) and `VictimOrg` (tracks stack `VictimOrg/target-repo`), as supported by `test/dummy/config/secrets_double_github_app.yml`.
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "AttackerOrg" },
    "full_name": "VictimOrg/target-repo"
  }
}
```
3. `verify_signature` resolves `Shipit.github(organization: "AttackerOrg")`, whose `webhook_secret` is `nil`, so `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`) regardless of any `X-Hub-Signature` header.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("victimorg/target-repo")` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) and triggers `sync_github` on the victim's stack — a write the attacker was never authorized to perform.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
