### Title
Webhook signature check binds HMAC verification to `repository.owner.login`, not to the repository actually mutated - unauthenticated cross-org webhook forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization's `webhook_secret` to validate against using `repository_owner`, which is read straight from the untrusted JSON body before any authentication occurs. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that resolved organization has no `webhook_secret` configured, regardless of whether a signature header was even sent. Because the org used for verification and the org/repository actually operated on by the downstream handler are two independently attacker-controlled fields of the same forged payload, an attacker can pass verification "for free" via a secret-less org while pointing the payload's `repository.full_name` at a repository belonging to a different, secret-protected org.

### Finding Description
The broken binding, stated as an equality that must hold but does not:

`organization_used_for_HMAC_check == organization_that_owns(repository.full_name)` in the payload — this is asserted only informally, not enforced by any code.

Trace:
- `verify_signature` computes `repository_owner = params.dig('repository', 'owner', 'login')` [1](#0-0)  — this comes from the raw, unauthenticated JSON body parsed by Rails' params, before any signature check.
- It then does `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)`, using `head(422) unless verified` as the only gate [2](#0-1) .
- `GitHubApp#verify_webhook_signature` short-circuits: `return true unless webhook_secret` [3](#0-2) . So for any organization configured in `Shipit.github_apps`/`Shipit.github` without a `webhook_secret`, *every* request "verifies" successfully, header absent or not.
- After `verify_signature` passes (or even fails to halt — `head(422)` does not itself `return`, though the exception path does `head(422)` then continues to log, not aborting subsequent before_actions execution boundary issues aside, the intended halt relies on `head` short-circuiting the filter chain), `create` re-parses `request.raw_post` and dispatches to `Shipit::Webhooks.for_event(event)` handlers with the full, attacker-supplied `params`, including `repository.full_name`, `head` sha, `state`, etc.
- Handlers such as the status/check-suite handlers locate the target `Stack`/`Commit`/`Repository` by `repository.full_name` (e.g. `"victim-org/victim-repo"`) taken from that same payload, completely independent of the `repository.owner.login` value used earlier for signature routing.

Exploit: attacker POSTs to `/webhooks` with `X-Github-Event: status` (or `check_suite`), no `X-Hub-Signature` header, and a JSON body where `repository.owner.login = "no-secret-org"` (any org configured in Shipit with no `webhook_secret`) while `repository.full_name = "secret-org/victim-repo"`. `verify_signature` resolves `no-secret-org`'s `GitHubApp`, which has no secret, so `verify_webhook_signature` returns `true` unconditionally — no header needed. The handler then processes the payload against `secret-org/victim-repo`'s real `Stack`/`Commit` records, mutating state (`Status`/`CheckRun` records feeding into deploy blocking/unblocking) for a fully-secured org, with zero possession of that org's secret.

Existing guards do not prevent this: `drop_unhandled_event` only filters unknown event types, not payload consistency; `GithubOrganizationUnknown` is only raised if the org name isn't configured at all, not if it's configured without a secret; there is no validator anywhere comparing `repository.owner.login` to `repository.full_name`'s owner segment.

### Impact Explanation
An unauthenticated attacker can inject forged GitHub webhook events (`status`, `check_suite`, etc.) that mutate `Commit`/`Stack`-related records belonging to any repository, as long as (a) that repository's payload `full_name` is guessable/known (public info) and (b) at least one other organization in the Shipit deployment is configured without a `webhook_secret`. This is a cross-tenant authentication bypass: a payload nominally "authenticated" for org A is used to write state for org B. Depending on which handler is targeted, this can flip commit statuses/check-suite conclusions that gate automated deploys, i.e., an unauthorized influence on deploy behavior for a repository the attacker never proved they control. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task ... or an unauthorized deploy."

### Likelihood Explanation
Preconditions: the Shipit deployment must host at least two GitHub orgs/apps where one has no `webhook_secret` configured (multi-tenant Shipit installs commonly have only some orgs with secrets set, e.g. during migration, or orgs added for read-only sync). No possession of any org's secret, no session, no API token is required — the attacker only needs to know the login of a secret-less org (discoverable, e.g., orgs without secrets are often not overtly secured) and the `owner/repo` full name of the target. The request is a single unauthenticated POST, fully repeatable and scriptable against any repository full name.

### Recommendation
Bind the organization used to select the `webhook_secret` to the same organization that will actually be mutated, and never trust unsigned data to select a secret. Verify the signature using the raw body's HMAC and only afterward parse the org from the (now-verified) payload; if any deployment has orgs without secrets, either require all configured orgs to have a `webhook_secret` or reject requests whose `repository.owner.login` does not match the owner segment of `repository.full_name`, and reject any org's resolved `GitHubApp` lacking a `webhook_secret` outright (fail closed instead of `return true unless webhook_secret`). Additionally, ensure `head(422)` in `verify_signature` actually halts the filter chain (explicit `return` after `head`) rather than relying on implicit behavior.

### Proof of Concept
Minitest plan under `test/controllers/webhooks_controller_test.rb`:
1. Configure two orgs in `Shipit.github_apps`/secrets fixture: `"secret-org"` with a `webhook_secret`, `"no-secret-org"` with none.
2. Create a `Stack`/`Commit` owned by `secret-org/victim-repo` with known current state (e.g., a `Status` record).
3. POST to `/webhooks` with headers `X-Github-Event: status`, no `X-Hub-Signature` header, and JSON body: `repository.owner.login = "no-secret-org"`, `repository.full_name = "secret-org/victim-repo"`, plus valid `status` handler fields (`sha`, `state`, `context`).
4. Assert `response.status` is NOT `422` (verification passed) — binding-left side check: `github_app_for("no-secret-org").verify_webhook_signature(nil, raw_post) == true`.
5. Assert the `Commit`/`Status` record for `secret-org/victim-repo` was mutated as if authenticated — binding-right side check: the mutated record's owning org (`secret-org`) differs from the org used for verification (`no-secret-org`), proving `organization_used_for_verification != organization_actually_mutated`, i.e., the claimed binding is broken.     def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
