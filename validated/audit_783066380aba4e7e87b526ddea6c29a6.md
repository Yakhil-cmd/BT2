### Title
Single-Step `governance.governingnode` Transfer Without New-Address Council Validation Permanently Freezes Chain Governance — (File: `kaiax/gov/headergov/impl/header.go`)

---

### Summary

In `single` governance mode (Mainnet/Kairos), the governing node can vote to transfer `governance.governingnode` to any arbitrary address. The consistency check in `checkConsistency` validates only that the **current** governing node is in the council — it never validates that the **proposed new** governing node address is also in the council. If the new address is not a council member, it can never become a block proposer, so it can never cast a vote, permanently freezing all governance parameters with no recovery path short of a hard fork.

---

### Finding Description

In `kaiax/gov/headergov/impl/header.go`, the `checkConsistency` function handles `GovernanceGoverningNode` votes as follows:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {  // checks CURRENT node
        return nil
    }
    return ErrGovNodeNotInValSetList
``` [1](#0-0) 

The check `slices.Contains(council, params.GoverningNode)` validates that the **current** governing node is in the council (a voter-eligibility check), but `vote.Value()` — the **new** governing node address — is never checked against the council. The `GovernanceGoverningNode` parameter's `FormatChecker` only verifies the value is a valid `common.Address`, with no membership constraint:

```go
GovernanceGoverningNode: {
    Canonicalizer: addressCanonicalizer,
    FormatChecker: func(cv any) bool {
        _, ok := cv.(common.Address)
        return ok
    },
    ...
},
``` [2](#0-1) 

Once the vote is ratified at the next epoch block and takes effect at `(k+1)*epoch`, the new governing node is written to the persistent governance history. In `single` mode, the chain invariant is:

> Only the governing node can vote. The governing node must be the block proposer to cast a vote. Only council members can be proposers. [3](#0-2) 

If the new governing node is not in the council, it can never be selected as a proposer, so it can never write `header.Vote`, so no governance vote can ever be ratified again. The `applyVote` function in `kaiax/valset` also confirms that the governing node is protected from removal from the council, but this protection only applies to the **current** governing node — once the parameter is changed to a non-council address, the new address has no such protection and no path to participation: [4](#0-3) 

---

### Impact Explanation

**Impact: High.** All mutable governance parameters — `reward.mintingamount`, `reward.ratio`, `governance.unitprice`, `istanbul.committeesize`, `governance.govparamcontract`, validator set additions/removals, and all KIP-71 base-fee parameters — are permanently frozen. No further governance votes can be ratified. The chain continues to operate but becomes ungovernable, with no on-chain recovery mechanism. A hard fork is the only remedy. [5](#0-4) 

---

### Likelihood Explanation

**Likelihood: Low.** The trigger requires the governing node operator to submit a `governance_vote("governance.governingnode", <wrong_address>)` call with a typo, a retired address, or an address not yet added to the council. The `governance_vote` API performs no membership check on the new value at the API layer either: [6](#0-5) 

The epoch on Mainnet/Kairos is 604,800 blocks (~1 week), so the operator has one full epoch to notice and cancel the pending vote before it is ratified — but there is no explicit warning or rejection at vote-submission time.

---

### Recommendation

1. **Validate the new value in `checkConsistency`**: For `GovernanceGoverningNode` votes in `single` mode, add a check that `vote.Value().(common.Address)` is present in the council at `blockNum - 1` before accepting the vote.

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if !slices.Contains(council, params.GoverningNode) {
        return ErrGovNodeNotInValSetList
    }
    // NEW: also validate the proposed new governing node is in the council
    newGovNode, ok := vote.Value().(common.Address)
    if !ok || !slices.Contains(council, newGovNode) {
        return ErrNewGovNodeNotInValSetList
    }
    return nil
```

2. **Consider a two-step transfer pattern**: Require the new governing node to cast a confirming vote (or use a pending-acceptance mechanism) before the transfer takes effect, analogous to the two-step ownership transfer pattern.

---

### Proof of Concept

1. Chain is in `single` mode; `governance.governingnode = 0xABCD` (in council); epoch = 604,800.
2. The governing node operator calls:
   ```
   governance_vote("governance.governingnode", "0x1234")
   ```
   where `0x1234` is **not** in the council (e.g., a typo or a future address not yet added).
3. `checkConsistency` passes: `slices.Contains(council, 0xABCD)` is `true`. The new value `0x1234` is never checked.
4. The vote is stored in `groupedVotes` for the current epoch.
5. At the next epoch block, `getExpectedGovernance` collects the vote and `VerifyGov` / `HandleGov` ratifies it, writing `governance.governingnode = 0x1234` to persistent storage. [7](#0-6) 

6. From `(k+1)*epoch` onward, `GetParamSet` returns `GoverningNode = 0x1234`.
7. `0x1234` is not in the council → it is never selected as a proposer → it can never write `header.Vote` → no governance vote is ever ratified again.
8. All governance parameters are permanently frozen. The chain is ungovernable.

func applyVote(header *types.Header, council *valset.AddressSet, governingNode common.Address) bool {
	voteKey, addresses, ok := parseValidatorVote(header)
	if !ok {
		return false
	}

	originalSize := council.Len()
	for _, address := range addresses {
		if address == governingNode {
			continue
		}
		switch voteKey {
		case gov.AddValidator:
			if !council.Contains(address) {
				council.Add(address)
			}
		case gov.RemoveValidator:
			if council.Contains(address) {
				council.Remove(address)
			}
		}
	}
	return originalSize != council.Len()

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}
