### Title
Unvalidated swap route can inject unauthorized token transfers into the caller’s signed authorization tree - ([File: contracts/controller/src/strategies/swap.rs])

### Summary
Controller strategy entrypoints accept an opaque caller-controlled `StrategySwap` and forward it to the configured router. Because route-selected contracts execute underneath the caller’s controller authorization, a malicious route can cause an unrelated token transfer to be recorded and authorized as a child invocation of the victim’s strategy call. [1](#0-0) [2](#0-1) 

### Finding Description
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, `multiply`, and `flash_position` all accept caller-controlled swap data or callback data. For router-backed strategies, `swap_tokens` snapshots token balances, authorizes only the exact input-token transfer to the router, invokes `router.execute_strategy(&controller, &amount_in, swap)`, and then checks measured spend and positive output. [3](#0-2) 

Those checks constrain controller-held input and output, but do not restrict which contracts the encoded route can invoke or which additional authorization requirements those contracts create. A malicious venue can invoke `token.transfer(victim, attacker, amount)` while processing the route; simulation records that transfer beneath the victim’s `swap_collateral` authorization, and submitting the resulting authorization tree executes it. [2](#0-1) [4](#0-3) 

### Impact Explanation
A malicious route can steal unrelated wallet tokens from the user while still returning enough swap output for the controller’s balance-delta and account-risk checks to pass. The exercised proof transfers the victim’s entire unrelated token balance to the attacker while crediting the expected swapped collateral. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
The attacker must induce the victim to submit a crafted opaque route and sign the simulated authorization tree containing the extra transfer. This is plausible when routes are obtained from an off-chain quote or another untrusted party because the controller itself does not decode, allowlist, or bound the contracts reached by the route. [7](#0-6) [8](#0-7) 

### Recommendation
Restrict strategy routes to a protocol-controlled route manifest or venue allowlist that cannot introduce arbitrary contract calls. At minimum, decode the route at the controller boundary and reject routes that can create user authorization requirements beyond the expected input movement; alternatively require the router to execute only allowlisted venue contracts and expose a verifiable authorization manifest for signing. [9](#0-8) 

### Proof of Concept
1. The attacker deploys a malicious contract exposing the venue swap interface and configures it to call `token.transfer(victim, attacker, amount)` for a token held by the victim. [10](#0-9) 
2. The attacker supplies a `swap_collateral` route that references the malicious contract while promising fair output. [11](#0-10) 
3. The victim invokes `swap_collateral(caller, account_id, current, amount, new, route)`; the controller forwards `route` to the router. [12](#0-11) [7](#0-6) 
4. Simulation records the malicious unrelated-token transfer as a child of the victim’s `swap_collateral` authorization. [8](#0-7) 
5. Submitting that signed authorization tree completes the fair swap and moves the victim’s unrelated token balance to the attacker. [6](#0-5)

fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
