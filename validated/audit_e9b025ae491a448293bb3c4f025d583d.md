Confirmed vulnerability. `Shipit.github(organization: repository_owner)` selects the `GitHubApp` config purely from `params.dig('repository','owner','login')`, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that config's `webhook_secret` is blank [1](#0-0) [2](#0-1) . Meanwhile `OpenedHandler#repository` (and every other PR handler) resolves the actual `Shipit::Repository`/stack to mutate strictly from `params.repository.full_name`, with no cross-check against `repository_owner` [3](#0-2) [4](#0-3) .

### Title
Webhook signature verification is keyed on `repository.owner.login` while the acted-upon repository is resolved from `repository.full_name`, letting an attacker route a forged payload through an unsecreted org config to hit a secret-protected org's repo - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the `GitHubApp` (and thus the `webhook_secret` used for HMAC verification) using `repository_owner`, defined as `params.dig('repository','owner','login')`. `OpenedHandler` and sibling PR handlers instead resolve the target `Repository`/`Stack` using `params.repository.full_name` via `Repository.from_github_repo_name`. These two payload fields are never cross-validated, so an attacker can set `repository.owner.login` to an organization with no configured `webhook_secret` (or an org config that doesn't exist and isn't in `Shipit.github_teams`) while setting `repository.full_name` to `"secured-org/repo"` that belongs to an org that *does* have a `webhook_secret`.

### Finding Description
The intended binding is: `repository_owner == owner_of(repository.full_name)`. Trace:
- `verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner = params.dig('repository','owner','login') || params.dig('organization','login')` [5](#0-4) .
- `Shipit.github` looks up per-organization config via `github_app_config(organization)`, keyed strictly by the organization name string passed in, with no relation enforced to `repository.full_name` [6](#0-5) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally (`return true unless webhook_secret`) whenever the selected org's config has no `webhook_secret` [2](#0-1) .
- After signature "verification" passes (or a 422 doesn't halt execution — note `head(422)` in `verify_signature` does not `return`, so the `before_action` chain does NOT necessarily stop unless Rails treats `head` as halting the filter chain; this needs runtime confirmation, but in a passing case where the unsecreted org's config validates true, control reaches `create`), `WebhooksController#create` dispatches to `OpenedHandler.call(params)` [7](#0-6) .
- `OpenedHandler#repository` looks up `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which splits solely on `full_name` and does a DB lookup by `owner`/`name` — entirely independent of `repository_owner` used above [3](#0-2) [4](#0-3) .
- If `provision?` conditions are met (`review_stacks_enabled` and provisioning behavior), `ReviewStackAdapter#find_or_create!` creates a new `ReviewStack`/`PullRequest` for that secured repo [8](#0-7) .

No existing guard (`drop_unhandled_event`, `ExplicitParameters` schema, `Repository` validations) checks that `repository_owner` equals the owner segment of `repository.full_name`; the `ExplicitParameters` schema for `OpenedHandler` only requires `repository.full_name` to be a `String`, with no format or ownership constraint [9](#0-8) .

### Impact Explanation
An attacker who controls (or can name) any GitHub organization with a Shipit config lacking a `webhook_secret` — or exploits any org whose secret is unset — can forge a `pull_request` `opened` webhook naming the secret-protected org's repo in `repository.full_name`, bypassing that org's HMAC entirely. This creates/unarchives a `ReviewStack` and a `PullRequest` record for the victim's protected repository without ever presenting a valid signature for it, i.e., a payload for one (unauthenticated) tenant mutating another (authenticated) tenant's stack — matching the "Critical: payload for one repository mutating another's stack" and "authentication bypass" categories. This is repeatable against any repository whose owner appears in `Shipit.github_organizations` with a blank `webhook_secret`, for every PR-event handler that resolves repository the same way (`ClosedHandler`, `LabeledHandler`, `AssignedHandler`, `EditedHandler`, etc.), all sharing the identical `Repository.from_github_repo_name(params.repository.full_name)` pattern.

### Likelihood Explanation
Requires only that at least one configured GitHub org in the multi-org config has no `webhook_secret` set (a documented/allowed configuration per `config/secrets.development.example.yml`/`secrets.development.shopify.yml`, which explicitly show `webhook_secret: # nil` as a valid per-org value) while a different org's repo is targeted via `full_name`. No Shipit session, API token, or GitHub credentials are required — only knowledge of the target org names, which an attacker can often discover from a public deploy/webhook 422 log message revealing "Webhook from unknown organization" or by simple probing (`unknown_organization=...` messages leak org names) [10](#0-9) . This is a single unauthenticated HTTP POST, fully repeatable.

### Recommendation
In `WebhooksController#verify_signature`, after selecting `github_app` and verifying the signature, additionally assert that the `repository_owner` used for the HMAC lookup matches the owner parsed from `params.dig('repository','full_name')` (and `organization.login` fallback), rejecting the request (422) on mismatch. Alternatively, derive `repository_owner` from `full_name`'s owner segment rather than the separate `repository.owner.login` field, so the two can never diverge.

### Proof of Concept
minitest plan (`test/controllers/webhooks_controller_test.rb`):
```ruby
test "rejects pull_request payload naming an unsecreted org as owner but a secreted org's repo as full_name" do
  Shipit.stubs(:secrets).returns(OpenStruct.new(github: {
    "unsecured-org" => { webhook_secret: nil },
    "secured-org"   => { webhook_secret: "s3cr3t" }
  }.with_indifferent_access))

  payload = {
    action: "opened",
    number: 2,
    pull_request: { id: 1, number: 2, url: "u", title: "t", state: "open",
                     additions: 1, deletions: 1,
                     head: { sha: "abc", ref: "feature" },
                     user: { login: "attacker" }, assignees: [], labels: [] },
    repository: { owner: { login: "unsecured-org" }, full_name: "secured-org/repo" },
    sender: { login: "attacker" }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  # No X-Hub-Signature header at all

  assert_difference -> { Shipit::Stack.count }, 1 do
    post :create, body: payload, as: :json
  end
  assert_response :ok
end
```
Assert both sides of the binding explicitly before/after: `repository_owner == "unsecured-org"` (drives `verify_webhook_signature` -> `true`) while `Shipit::Repository.from_github_repo_name("secured-org/repo").owner == "secured-org"` — unequal, and a stack is still created for `secured-org/repo` despite the absent signature, proving the divergence and its exploitability. Note: reproducing this exactly requires confirming in a live/test run that `head(422)` inside a `before_action` halts the filter chain in this Rails version — if it does not halt for the ping-style `head` calls used elsewhere, the bypass is even more direct; this specific control-flow detail could not be fully confirmed from static reading and should be verified by actually running the described test.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
