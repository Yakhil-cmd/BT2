### Title
Front-running bad-debt socialization lets a supplier escape the supply-index write-down and shift the entire loss onto remaining suppliers - (File: contracts/pool/src/interest.rs)

### Summary
`clean_bad_debt` (and the automatic cleanup inside `liquidate`) applies an instantaneous, pro-rata write-down of the market's `supply_index` via `apply_bad_debt_to_supply_index`. Because the write-down is divided only over shares present at execution time, a supplier who observes a pending cleanup/liquidation can withdraw at the pre-write-down index first, collecting its full claim in cash while the fixed loss is re-concentrated on the suppliers who remain. This is the same bug class as the DODO `adjustPrice` sandwich: a state transition that abruptly reprices a claim can be sandwiched by an unprivileged actor, and the extracted value is paid by other LPs.

### Finding Description
`clean_bad_debt` is permissionless — any authenticated caller may invoke it whenever `total_debt > total_collateral` and collateral is at most the fixed $5 dust cap ( [1](#0-0) ). Liquidation also promotes residual debt to socialization inside the same call. Both paths end in `apply_bad_debt_to_supply_index`, which scales `supply_index` down by `remaining / total_supplied_value` computed **at execution time** ( [2](#0-1) ).

A normal `withdraw` on a debt-free account skips the post-action risk gate entirely (INV-RISK-01: debt-free accounts skip the numerical gates), and the pool leg only requires tracked cash, utilization headroom, and supply-backing after the debit ( [3](#0-2) ). Nothing ties withdrawal timing to a pending write-down: an attacker holding shares in the debt market simply calls `withdraw` in the transaction ordered before the cleanup, receives `shares × supply_index_before`, and the subsequent cleanup divides the same bad debt over a smaller `supplied` base — so every remaining supplier's index falls further than its fair pro-rata share.

Since the loss `min(bad_debt, total_supplied_value)` is fixed, the attacker's withdrawal at the unwritten-down index is paid for by a deeper write-down on everyone else. The attacker can even re-supply afterward at the depressed index; while this alone is value-neutral, the withdraw leg already extracted `(index_before − index_fair_share) × shares` from the pool's cash that should have been haircut.

### Impact Explanation
Theft of value from other liquidity suppliers: the attacker exits at the pre-write-down exchange rate, forcing the identical bad-debt loss to be socialized across fewer shares. Remaining suppliers lose strictly more than pro-rata; in a thin market a large supplier can transfer nearly its entire expected share of the write-down to a small residual supplier base. Unlike the DODO case no privileged actor is even needed to trigger the repricing — `clean_bad_debt` is permissionless and `liquidate` is callable by anyone, so the attacker can both predict and cause the state transition once the gate opens.

### Likelihood Explanation
The dust gate (`collateral ≤ $5`) bounds each individual cleanup's size, but the write-down equals the account's entire remaining debt, which can be large relative to a small or recently-drained market — and repeated liquidations create repeated write-down events (`liquidate` auto-socializes the residual). The gate opens purely from an oracle price move (`clean_bad_debt_gate_never_opens_before_liquidation_does` shows price alone flips it), so the pending repricing is publicly observable on-chain/off-chain before anyone submits the cleanup. On Stellar/Soroban, transaction ordering and inclusion are observable to validators and RPC frontends, so a supplier (or a liquidation bot itself, which can withdraw its own shares first) can order its `withdraw` ahead of the `liquidate`/`clean_bad_debt` it submits. Medium likelihood: requires an open write-down event and orderable transactions, but no privilege.

### Recommendation
Treat socialization as a repricing event and remove the atomicity between "observable pending write-down" and "unhaircut withdrawal". Options:

- In the same transaction, evaluate the withdrawal at the post-cleanup index: have the withdraw path detect accounts eligible for bad-debt socialization in that market (or force the controller to process pending socialization before honoring withdrawals), so exits always pay the fair share.
- Failing that, socialize-at-read: compute each withdrawal's share value against a `supply_index` adjusted for already-realized but unapplied bad debt, so exiting early gives the same value as staying.
- Alternatively, make write-down granularity account-level rather than index-level for exits racing the cleanup — e.g., block `withdraw` in a market while a permissionless cleanup is admissible (`is_socializable_bad_debt` is cheap to evaluate in the controller context), pushing the exit to after the write-down where it is value-neutral.

```rust
// Setup: BOB and EVE supply ETH; ALICE supplies USDC dust and borrows ETH.
t.supply(BOB, "ETH", 100.0);
t.supply(EVE, "ETH", 900.0);          // attacker is the dominant supplier
t.supply(ALICE, "USDC", 4.0);         // <= $5 collateral after crash
t.borrow(ALICE, "ETH", 0.003);

let eve_before = t.token_balance(EVE_ADDR, "ETH");
let (si_before, _) = get_indexes(&t, "ETH");

// Oracle move opens the dust gate: debt > collateral, collateral <= $5.
t.set_price("USDC", usd_cents(1));

// FRONT-RUN: EVE withdraws her whole position at the pre-write-down index.
// Debt-free account -> no HF gate; pool cash check only.
t.withdraw(EVE, "ETH", /* all */);

// The repricing event itself, callable by anyone (EVE can submit it herself):
t.clean_bad_debt_by_id(alice_id);

let (si_after, _) = get_indexes(&t, "ETH");
let bob_after = t.supply_balance_raw(BOB, "ETH");

// EVE kept full value; the entire bad-debt loss now sits on BOB's 100 ETH
// worth of shares instead of being split 10/90 with EVE.
// bob_loss == full bad_debt, instead of bad_debt * 100/1000.
assert!(t.token_balance(EVE_ADDR, "ETH") - eve_before ≈ 900.0);
assert!(bob_loss == alice_debt_value); // concentrated, not pro-rata
```

```rust
/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}
```

```rust
pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}
```

```rust
pub(crate) fn accounting(
    env: &Env,
    is_liquidation: bool,
    entry: &PoolWithdrawEntry,
) -> WithdrawOutcome {
    require_nonneg_amount(env, entry.protocol_fee);
    let (mut cache, position) = ops::load_leg(env, &entry.action);

    let (burned, gross_amount) = resolve_close_or_partial(&cache, entry.action.amount, position);
    // Burn first: `protocol_fee_shares` caps the fee mint at `i128::MAX - supplied`.
    let remaining = burn_position(env, &mut cache, position, burned);
    let net_transfer = withhold_liquidation_fee(
        env,
        &mut cache,
        gross_amount,
        is_liquidation,
        entry.protocol_fee,
    );

    // A footprint-only close must not add a utilization gate to same-market
    // net settlement: it burns no shares and moves no cash.
    let empty_close = position.raw() == 0 && entry.action.amount == i128::MAX;
    gate_and_debit(env, &mut cache, net_transfer, is_liquidation || empty_close);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(remaining, gross_amount);
    WithdrawOutcome {
        cache,
        mutation,
        snapshot,
        net_transfer,
    }
}

/// Maps requested amount and position to shares burned and gross asset amount.
/// Panics if a nonzero gross amount would burn zero shares.
fn resolve_close_or_partial(cache: &Cache, amount: i128, position: Ray) -> (Ray, i128) {
    let (burned, gross_amount) = cache.resolve_withdrawal(amount, position);
    assert_with_error!(
        cache.env(),
        gross_amount == 0 || burned.raw() > 0,
        GenericError::WithdrawRoundsToZeroShares
    );
    (burned, gross_amount)
}

/// Burns `burned` from market supply and returns the user's remaining scaled position.
fn burn_position(env: &Env, cache: &mut Cache, position: Ray, burned: Ray) -> Ray {
    cache.burn_supply(burned);
    position.checked_sub(env, burned)
}

/// Enforces reserve, utilization, and solvency guards, then debits cash for
/// the net transfer. Liquidations and footprint-only closes skip utilization.
fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);
    cache.debit_cash(net_transfer);
}
```
