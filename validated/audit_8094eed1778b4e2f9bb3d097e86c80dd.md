### Title
Webhook signature check is keyed on attacker-controlled `repository.owner.login`, letting an event signed for one (secret-less) GitHub organization mutate another organization's stacks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks *which* `GithubApp`/`webhook_secret` to validate a delivery against by reading `repository_owner` straight out of the untrusted, attacker-suppliable JSON body, while every downstream handler resolves the record to mutate from a *different* field of the same body (`repository.full_name`). The two fields are never cross-checked, so the organization whose credential authenticated the request is not bound to the repository whose `Stack`/`Commit` is actually written — the exact "authenticated-organization vs. written-repository" binding called out as an analog target.

### Finding Description
`verify_signature` resolves the signing secret this way: [1](#0-0) [2](#0-1) 

`repository_owner` is taken verbatim from the JSON payload (`repository.owner.login`, falling back to `organization.login`), and it is used to select a per-organization `GithubApp` config: [3](#0-2) 

`Shipit.github(organization:)` looks up per-org configuration, each of which can independently define a `webhook_secret` (multi-tenant schema documented in `config/secrets.development.example.yml`): [4](#0-3) 

Critically, `webhook_secret` is optional, and when it is absent the check is a no-op: [5](#0-4) 

Meanwhile every event handler ignores `repository_owner` entirely and resolves the target `Repository`/`Stack` from `repository.full_name` in the same JSON body: [6](#0-5) [7](#0-6) [8](#0-7) 

Equality that should hold but doesn't: `organization authenticated by signature == owner(repository.full_name written to)`. Before the attack, GitHub itself guarantees this equality because it always signs and delivers events for the actual `repository.full_name`'s owner. After the attack (a directly-forged POST to `/webhooks`, not a GitHub-originated delivery), an attacker sets `repository.owner.login`/`organization.login` to any organization configured in Shipit with no `webhook_secret` (a supported, documented configuration — see `docs/setup.md` "Webhook secret (optional)"), so `verify_webhook_signature` short-circuits to `true` for that request regardless of its actual body, while `repository.full_name` is set to a *different*, secret-protected organization's tracked repository. `Repository.from_github_repo_name(repository_name)` then resolves that unrelated organization's `Stack`, and the handler mutates it (e.g. `PushHandler` enqueues `sync_github`, `StatusHandler` writes a fabricated commit `Status`, `check_suite`/`pull_request` handlers create memberships, provision review stacks, etc.) with no relationship at all to the organization that "authenticated" the call.

### Impact Explanation
This breaks the deployment-trust binding between the GitHub organization whose signature gated the webhook and the repository/stack that the resulting side effects are applied to. An attacker who only needs to know that *some* organization onboarded to the Shipit instance has an unset `webhook_secret` (visible only as an operational/config fact, not a secret) can inject arbitrary, unauthenticated `status`, `push`, `check_suite`, or `pull_request` events against any other organization's stacks tracked by the same Shipit instance. Forged `status` events (`StatusHandler#process` → `commit.create_status_from_github!`) can flip CI state to `success` for a targeted commit, and forged `push` events can trigger `GithubSyncJob` — both of which feed the same signals that continuous-delivery/auto-merge and deploy-eligibility logic rely on, creating a path to an unauthorized deploy on a repository the attacker has no relationship to. This satisfies the "unauthorized deploy" High/Critical impact category.

### Likelihood Explanation
Likelihood is moderate-to-high wherever the multi-organization GitHub config schema is used (which the engine explicitly documents and supports) and at least one onboarded organization has left `webhook_secret` unset — an intentionally supported, "optional" setting per `docs/setup.md`. No GitHub identity, `ApiClient` token, session, or knowledge of any actual secret is required; the attacker only needs to POST directly to the public `/webhooks` endpoint with a crafted JSON body and the correct `X-Github-Event` header.

### Recommendation
Bind the signature-verifying organization to the repository actually mutated: after resolving `repository_owner` for the purpose of `Shipit.github(organization:)`, verify that it matches the owner segment of `repository.full_name` (or `organization.login` when no `repository` object is present) before processing; reject the request otherwise. Additionally, treat an org with no configured `webhook_secret` as "verification not possible" (fail closed) rather than "verification passes," or require that every organization configured in a multi-tenant setup define a `webhook_secret`.

### Proof of Concept
1. Configure Shipit with the multi-org schema: `OrgUnprotected` (no `webhook_secret`) and `OrgVictim` (`webhook_secret: "s3cr3t"`), both with GitHub Apps installed, `OrgVictim/private-repo` tracked as a Shipit stack.
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: status` and body:
```json
{
  "sha": "<victim-commit-sha>",
  "state": "success",
  "repository": { "owner": { "login": "OrgUnprotected" }, "full_name": "OrgVictim/private-repo" }
}
```
No `X-Hub-Signature` (or any arbitrary value) is required, since `Shipit.github(organization: "OrgUnprotected")` resolves a `GithubApp` whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-78`).
3. `verify_signature` passes, `StatusHandler#process` runs against `Commit.where(sha: ...)` for `OrgVictim/private-repo`, writing a forged "success" status the attacker never had rights to create.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
