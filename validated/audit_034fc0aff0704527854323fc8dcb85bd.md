### Title
Permanently Stuck KAIA in Source Bridge When `handleKLAYTransfer` Recipient Reverts — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

The Kaia service-chain bridge's `handleKLAYTransfer` function performs the KLAY transfer to the recipient with a bare `require(ok, ...)` after already emitting the `HandleValueTransfer` event and updating nonce state. If the recipient is a contract that always reverts on receiving KLAY, the on-chain transaction reverts (rolling back state), the nonce is never marked handled, and the Value Transfer Recovery (VTR) loop retries indefinitely — permanently locking the user's KAIA in the source bridge with no refund or redirect path.

---

### Finding Description

`handleKLAYTransfer` in `BridgeTransferKLAY.sol` executes the following sequence:

1. Nonce guard (`_lowerHandleNonceCheck`)
2. Multi-operator vote (`_voteValueTransfer`)
3. State writes: `_setHandledRequestTxHash`, `handleNoncesToBlockNums[nonce]`, `_updateHandleNonce`
4. Emit `HandleValueTransfer`
5. Low-level call: `(bool ok, ) = _to.call.value(_value)(""); require(ok, ...);` [1](#0-0) 

If step 5 reverts (e.g., `_to` is a contract without a payable fallback, or one that explicitly reverts), the entire transaction reverts — rolling back steps 3–4. The nonce is therefore **never** recorded in `handleNoncesToBlockNums`, so `lowerHandleNonce` never advances past it. [2](#0-1) 

The off-chain Go operator in `processingPendingRequestEvents` submits the handle transaction and, on submission success, moves to the next event. It does not observe the on-chain revert synchronously. [3](#0-2) 

The VTR (`valueTransferRecovery`) periodically scans for unhandled nonces and re-adds them to the pending queue via `AddRequestValueTransferEvents`. [4](#0-3) 

However, `retrievePendingEventsFrom` uses `isHandledEvent` — which checks `HandleNoncesToBlockNums` on-chain — to decide whether to retry. Since the nonce is never written (every attempt reverts), the event is re-queued on every VTR cycle. [5](#0-4) 

There is **no escape hatch**: no operator API to redirect the transfer to a different address, no refund path back to the source chain, and no mechanism to skip a permanently failing nonce. The KAIA locked in the source bridge on the child chain is irrecoverable.

The same structural issue exists in `handleERC20Transfer` (lock/unlock mode): if `safeTransfer` reverts because `_to` is blacklisted by the token contract, the nonce is never marked handled and the tokens are permanently locked in the source bridge. [6](#0-5) 

In mint/burn mode the severity escalates: the source-chain tokens are **burned** in `_requestERC20Transfer` before the handle is attempted. If `mint` on the destination always fails, the tokens are destroyed on the source chain and never recreated — a net loss of supply

// processingPendingRequestEvents handles pending request value transfer events of the bridge.
func (bi *BridgeInfo) processingPendingRequestEvents() {
	ReadyEvent := bi.GetReadyRequestValueTransferEvents()
	if ReadyEvent == nil {
		return
	}

	logger.Trace("Get ready request value transfer event", "len(readyEvent)", len(ReadyEvent), "len(pendingEvent)", bi.pendingRequestEvent.Len())

	for idx, ev := range ReadyEvent {
		if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
			logger.Trace("handled requests can be ignored", "RequestNonce", ev.GetRequestNonce(), "lowerHandleNonce", bi.lowerHandleNonce)
			continue
		}

		if err := bi.handleRequestValueTransferEvent(ev); err != nil {
			bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
			logger.Error("Failed handle request value transfer event", "err", err, "len(RePutEvent)", len(ReadyEvent[idx:]))
			return
		}
	}

	}

func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))
	}

	vtHandleEventMeter.Mark(int64(len(vtr.parentEvents)))
	events = make([]IRequestValueTransferEvent, len(vtr.parentEvents))
	for i, event := range vtr.parentEvents {
		events[i] = event
	}
	vtr.cBridgeInfo.AddRequestValueTransferEvents(events)

	return nil
}
