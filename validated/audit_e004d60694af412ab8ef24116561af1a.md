### Title
Untracked-file "unchanged since baseline" check trusts stale `st_mtime_ns` instead of content, letting a pre-placed untracked file be swapped and permanently excluded from Stop-hook review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`_unchanged_since_baseline` in `compute_v2_review_set` treats an untracked file as "unchanged since baseline" purely by comparing its current `st_mtime_ns` to the value captured at UPS in `untracked_at_baseline`, with no content/size/hash comparison. An attacker who controls filesystem timestamps (e.g., via a Bash tool call or a build script run during the turn) can overwrite the file's content and then restore the exact nanosecond-precision mtime, causing the modified file to be folded into `preexisting_unchanged` and permanently excluded from `review_set`, silently evading the security review.

### Finding Description
`_list_untracked` (`plugins/security-guidance/hooks/diffstate.py:319-351`) snapshots untracked files at UPS as `{repo-relative path: st_mtime_ns}`. At Stop time, `compute_v2_review_set` (`diffstate.py:353-438`) calls `_unchanged_since_baseline` (`diffstate.py:390-397`):
```python
def _unchanged_since_baseline(p):
    base_mtime = untracked_at_baseline.get(p)
    if base_mtime is None:
        return False
    try:
        return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
    except OSError:
        return False
```
This is the *only* signal used to decide `preexisting_unchanged` (`diffstate.py:399`), which is then subtracted from `dirty_now`/`review_set` (`diffstate.py:400-401,426`), i.e. these files never enter `review_paths`.

Because the check is mtime-only, any actor able to run a shell command in the workspace during the turn (normal Bash tool usage, or a build/test script the agent is instructed to run — including via prompt-injected instructions embedded in repo content, issues, or PR text) can: (1) read the file's current mtime, (2) overwrite its content with malicious payload, (3) restore the exact nanosecond mtime with `os.utime(path, ns=(atime_ns, mtime_ns))` or `touch -d`. The restored file then satisfies `st_mtime_ns == base_mtime` and is silently excluded from `review_set`, even though its content changed. No git-status or content-hash cross-check exists to catch this, since untracked files are outside `git diff`'s baseline coverage entirely (as the code comments note, `git stash create` doesn't capture untracked files — that's the whole reason this heuristic exists).

### Impact Explanation
This is a trust-boundary bypass of the security-guidance review pipeline: a maliciously modified untracked file (e.g., a script, config, or credential-bearing file) can be smuggled through a Claude Code turn without ever appearing in `review_paths`, defeating the Stop-hook's diff/review-set integrity guarantee that "the review set reflects true content changes." This maps to unauthorized-file-mutation-evading-review / workspace-confinement bypass impact.

### Likelihood Explanation
Requires only: (a) a pre-existing untracked file in the repo at UPS time (common — build artifacts, scratch files, `.env`-style files that are `.gitignore`d), and (b) the ability to run a shell command that both edits the file and resets its mtime with nanosecond precision before Stop fires — trivially achievable via the Bash tool or a script the agent is induced to run. This is a deterministic, repeatable bypass, not a race condition, so likelihood is high whenever an untracked file at that path can be targeted.

### Recommendation
Replace or augment the mtime-only check in `_unchanged_since_baseline` with a content-based comparison (e.g., size + content hash, or file size alone as a cheap first filter followed by a hash) captured at `_list_untracked` time and re-verified at Stop, rather than relying solely on `st_mtime_ns` equality, which is attacker-controllable.

### Proof of Concept
Unit test in the style of existing `diffstate`/hook tests:
1. Create a git repo with a `.gitignore`d untracked file `f` containing `"benign"`.
2. Call `_list_untracked(cwd)` to build `untracked_at_baseline` (captures `st_mtime_ns`).
3. Read `os.stat(f).st_mtime_ns` as `orig_ns`.
4. Overwrite `f` with `"malicious payload"`.
5. Call `os.utime(f, ns=(orig_ns, orig_ns))` to restore the exact mtime.
6. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)`.
7. Assert `f` is **not** present in the returned `review_paths` (bug reproduced) despite its content differing from what was snapshotted — expected/fixed behavior is that `f` **is** included in `review_paths`.
