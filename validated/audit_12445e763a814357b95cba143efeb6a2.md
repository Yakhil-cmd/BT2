### Title
Governance Vote of `kip71.gastarget = 0` Causes Panic in `NextMagmaBlockBaseFee`, Halting Block Validation — (`params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter uses `noopFormatChecker`, which accepts any `uint64` value including `0`. When `GasTarget` is set to `0` via a governance vote and any subsequent block has non-zero gas used, `NextMagmaBlockBaseFee` performs an integer division by zero (`big.Int.Div` panics on zero divisor). This panic propagates through `VerifyMagmaHeader` → `validateHeader` → `ValidateHeader`, causing every honest node to crash when processing or validating any block with non-zero gas usage, permanently halting the chain.

---

### Finding Description

**Root cause — missing zero guard on `Kip71GasTarget`:**

In `kaiax/gov/param.go`, the `Kip71GasTarget` parameter entry uses `noopFormatChecker`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // accepts ANY uint64, including 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

Compare this with `Kip71BaseFeeDenominator`, which explicitly rejects zero:

```go
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // zero explicitly rejected
    },
``` [2](#0-1) 

The `checkConsistency` function in `VerifyVote` also returns `nil` unconditionally for `Kip71GasTarget`, performing no additional range validation: [3](#0-2) 

**Crash site — unguarded division by `gasTarget` in `NextMagmaBlockBaseFee`:**

In `params/kip71_config.go`, `NextMagmaBlockBaseFee` uses `gasTarget` as a divisor in two places without a zero guard:

```go
gasTarget := kc.GasTarget   // could be 0 after governance vote

parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
if parentGasUsed == gasTarget {          // only safe if parentGasUsed is also 0
    return makeEvenByFloor(parentBaseFee)
} else if parentGasUsed > gasTarget {   // true for ANY non-zero parentGasUsed when gasTarget=0
    ...
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // PANIC: big.Int.Div panics on zero
``` [4](#0-3) 

The same unguarded division occurs in the `else` branch: [5](#0-4) 

Note that `BaseFeeDenominator == 0` is explicitly handled with a fallback value at lines 71–76, but `GasTarget == 0` has no such guard. [6](#0-5) 

**Propagation — panic in block validation:**

`VerifyMagmaHeader` calls `NextMagmaBlockBaseFee` and is invoked from `validateHeader` in `BlockValidator`:

```go
govParamSet := v.mGov.GetParamSet(header.Number.Uint64())
if err := govParamSet.ToKip71Config().VerifyMagmaHeader(
    header.BaseFee, parent.Number, parent.BaseFee, parent.GasUsed); err != nil {
    return err
}
``` [7](#0-6) 

A Go `panic` from `big.Int.Div` is unrecovered here, crashing the node process.

---

### Impact Explanation

Once `kip71.gastarget = 0` takes effect (at the start of the next epoch after ratification), every block where `parentGasUsed > 0` causes a panic in `NextMagmaBlockBaseFee`. Since virtually every Kaia block contains transactions with non-zero gas usage, this means:

1. **Block proposers** cannot compute the correct `BaseFee` for the next block — their node panics.
2. **Validators** cannot validate incoming blocks — `validateHeader` panics, crashing the node.
3. The chain halts permanently. No recovery is possible without a hard fork or governance intervention to restore `GasTarget` to a non-zero value — but governance itself requires block production to ratify a new vote.

This is an **invalid state transition / consensus divergence** impact: honest nodes crash and cannot reach consensus on any new block.

---

### Likelihood Explanation

The trigger requires the governing node (in `single` mode, the sole governance authority on Mainnet and Kairos) to cast a vote of `kip71.gastarget = 0`. This is a semi-trusted actor — the same class as the "owner" in the external bug report. The vote passes all existing validation gates (`noopFormatChecker`, `checkConsistency` returns nil). The parameter takes effect one epoch later with no further checks. No majority-validator collusion is required; a single governance key suffices.

---

### Recommendation

1. **Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`** in `kaiax/gov/param.go`, mirroring the existing guard on `Kip71BaseFeeDenominator`:
   ```go
   FormatChecker: func(cv any) bool {
       v, ok := cv.(uint64)
       return ok && v > 0
   },
   ```

2. **Add a zero guard in `NextMagmaBlockBaseFee`** in `params/kip71_config.go` before using `gasTarget` as a divisor, analogous to the existing `BaseFeeDenominator == 0` fallback:
   ```go
   if gasTarget == 0 {
       gasTarget = kc.GasTarget  // or return lowerBoundBaseFee as a safe fallback
   }
   ```

3. **Add a consistency check** in `checkConsistency` for `Kip71GasTarget` to reject zero values at vote time.

---

### Proof of Concept

1. On a Magma-enabled Kaia network in `single` governance mode, the governing node calls:
   ```
   governance_vote("kip71.gastarget", 0)
   ```
2. The vote passes `NewVoteData` (noopFormatChecker returns true) and `VerifyVote` (checkConsistency returns nil for `Kip71GasTarget`).
3. At the next epoch boundary, the vote is ratified and `GasTarget = 0` takes effect.
4. The next block with any transactions (non-zero `GasUsed`) triggers:
   ```
   NextMagmaBlockBaseFee(..., parentGasUsed=21000)
   // parentGasUsed (21000) > gasTarget (0) → enters the increase branch
   // x.Div(x, new(big.Int).SetUint64(0)) → panic: division by zero
   ```
5. Every node calling `validateHeader` on this block panics and crashes. The chain halts.
