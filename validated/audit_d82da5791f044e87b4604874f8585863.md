### Title
`claim-staker-rewards-for-signer` bypasses the `rewards-paused` guard enforced by `claim-rewards` - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`pox-5.clar`'s `claim-rewards` (the signer-level reward pull) refuses to run while `rewards-paused` is true: `(asserts! (not (var-get rewards-paused)) ERR_REWARDS_PAUSED)` [4](#0-3) . However, `claim-staker-rewards-for-signer`, the function that settles and zeroes a staker's unclaimed-rewards ledger entry and is called by external `signer-manager` contracts (e.g. `contrib/core-contract-tests/contracts/signer-manager.clar#claim-staker-rewards`) to actually pay sBTC out to a staker, contains no such pause check [5](#0-4) .

### Finding Description
`claim-rewards` computes `total-rewards` for a signer and, only after asserting `not rewards-paused`, transfers sBTC to the signer manager and decrements `last-accounted-rewards-only` [6](#0-5) . This is the "outer" pause gate meant to freeze reward flows during a SIP-controlled pause window (mirroring `rewards-paused`'s purpose of stopping cash movement out of the reserve).

`claim-staker-rewards-for-signer`, by contrast, calls `settle-staker-rewards` to compute `earned` for the staker and then `map-set`s the staker's `staker-unclaimed-rewards-for-cycle` entry to `u0`, i.e. it commits/settles the staker's claim of an amount that a signer manager previously pulled via `claim-rewards` [5](#0-4) . Nothing in this function or its private helper `settle-staker-rewards` checks `rewards-paused` [7](#0-6) .

The `signer-manager.clar` reference implementation's `claim-staker-rewards` invokes `claim-staker-rewards-for-signer` unconditionally and then transfers sBTC (or initiates an L1 withdrawal) to the staker based on its result [8](#0-7) . Since the signer manager's sBTC balance for a cycle is only replenished via `claim-rewards`, and `claim-rewards` blocks new inflows while paused, the direct impact of `rewards-paused` on `claim-staker-rewards-for-signer` alone is limited when the signer-manager already holds unclaimed sBTC from before the pause was set — that balance can still be distributed to individual stakers through `claim-staker-rewards-for-signer` even while the protocol-level pause is active, mirroring the `PSM._redeem()` analog exactly: an internal accounting/payout function reachable through a second entry point that omits the check enforced at the "normal" entry point.

### Impact Explanation
This breaks the equality the pause is meant to enforce: "no sBTC reward payouts happen while `rewards-paused` is true." If a SIP-triggered pause is meant to freeze all reward distribution (e.g. because of a detected accounting bug or an ongoing hard-fork remediation via `transfer-stranded-rewards`/`transfer-from-reserve`), stakers can still drain already-pulled, unclaimed sBTC out of any signer-manager contract via `claim-staker-rewards-for-signer` during the pause window. This is a temporary-freezing/pause-bypass class issue rather than unbacked minting, since the sBTC being moved was already earned and held by the signer manager — but it defeats the operational control the pause is designed to provide over reward fund movement.

### Likelihood Explanation
Likelihood is Medium: it requires (a) a signer manager to have previously called `claim-rewards` and be holding an sBTC balance for a cycle, and (b) `rewards-paused` becoming true afterward. Given `rewards-paused` exists specifically as an emergency control (paired with `transfer-stranded-rewards`/`transfer-from-reserve` as consensus-level catch-alls), an admin is likely to set it precisely when funds are already in flight, making the bypass window realistic.

### Recommendation
Add `(asserts! (not (var-get rewards-paused)) ERR_REWARDS_PAUSED)` inside `claim-staker-rewards-for-signer` (and/or `settle-staker-rewards`) so pause enforcement is self-contained and cannot be bypassed via signer-manager pass-through, consistent with the recommendation to enforce checks at the shared internal function rather than only at one entry point.

### Proof of Concept
1. Signer manager `SM` calls `pox-5.claim-rewards` for cycle `N`, pulling `total-rewards` sBTC into `SM`'s balance [6](#0-5) .
2. Protocol admin sets `rewards-paused` to `true` (emergency pause).
3. Staker calls `SM.claim-staker-rewards(staker, N, bond-index)`, which internally calls `pox-5.claim-staker-rewards-for-signer` [9](#0-8) .
4. `claim-staker-rewards-for-signer` has no `rewards-paused` check, so it settles the staker's earned amount and zeroes their unclaimed balance [10](#0-9) , after which `SM` transfers sBTC to the staker — succeeding despite the active pause, unlike a direct call attempting a fresh `claim-rewards` pull which would revert with `ERR_REWARDS_PAUSED`.

(define-public (claim-staker-rewards
        (staker principal)
        (reward-cycle uint)
        (bond-index (optional uint))
    )
    (let (
            ;; `unwrap-panic` is ok here: there is no `err` type returnable
            (rewards-info (unwrap-panic (contract-call? 'ST000000000000000000002AMW42H.pox-5
                claim-staker-rewards-for-signer staker reward-cycle
                bond-index
            )))
            (prev-fees (var-get earned-fees))
            (gross (get earned rewards-info))
            (fees (/ (* gross (get-fee-bips-for-cycle reward-cycle bond-index))
                MAX_BIPS
            ))
            (earned (- gross fees))
            (unclaimed-rewards (var-get unclaimed-staker-rewards))
        )
        (asserts! (> earned u0) ERR_NO_CLAIMABLE_REWARDS)
        (asserts! (>= unclaimed-rewards gross) ERR_NO_CLAIMABLE_REWARDS)
        (asserts!
            (>
                (unwrap-panic (contract-call?
                    'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                    get-balance current-contract
                ))
                u0
            )
            ERR_NO_CLAIMABLE_REWARDS
        )
        (var-set earned-fees (+ prev-fees fees))
        ;; This staker's share is being distributed now so release it from
        ;; the unclaimed count recorded when `claim-rewards` pulled it in.
        (var-set unclaimed-staker-rewards (- unclaimed-rewards gross))
        ;; Bind the request-id surfaced when the payout was routed to L1 via
        ;; `initiate-withdrawal-request`, `none` when the staker was paid
        ;; directly in sBTC.
        (let ((withdrawal-request (try! (as-contract?
                ((with-ft 'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                    "sbtc-token" earned
                ))
                (match (get-pox-addr staker)
                    l1-info (let (
                            (amount (try! (if (>= earned (get max-fee l1-info))
                                (ok (- earned (get max-fee l1-info)))
                                ERR_NO_CLAIMABLE_REWARDS
                            )))
                            (withdrawal-request (try! (contract-call?
                                'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-withdrawal
                                initiate-withdrawal-request amount
                                (get pox-addr l1-info) (get max-fee l1-info)
                            )))
                        )
                        (print {
                            topic: "claim-staker-rewards",
                            amount-sats: earned,
                            l1-withdrawal: (some (merge l1-info {
                                withdrawal-request: withdrawal-request,
                                amount: amount,
                            })),
                            staker: staker,
                            reward-cycle: reward-cycle,
                            bond-index: bond-index,
                        })
                        (map-set withdrawal-requests withdrawal-request staker)
                        ;; `amount + max-fee` == `earned` left the balance into the
                        ;; sBTC withdrawal system; record it as staker liability.
                        (var-set withdrawal-liability
                            (+ (var-get withdrawal-liability) amount
                                (get max-fee l1-info)
                            ))

                        (some withdrawal-request)
                    )
                    (begin
                        (print {
                            topic: "claim-staker-rewards",
                            amount-sats: earned,
                            l1-withdrawal: none,
                            staker: staker,
                            reward-cycle: reward-cycle,
                            bond-index: bond-index,
                        })
                        (try! (contract-call?
                            'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                            transfer earned tx-sender staker none
                        ))
                        ;; Direct sBTC payout: there is no L1 withdrawal to track.
                        none
                    )
                )))))
            (ok {
                earned: earned,
                withdrawal-request: withdrawal-request,
            })
        )
    )
)
