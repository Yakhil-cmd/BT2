### Title
`SwapFirstAssetTrader` caches only the last fee-paying asset, causing refunds to be swapped into the wrong asset when a single XCM program pays weight with more than one asset - ([File: cumulus/primitives/utility/src/lib.rs])

### Summary
`SwapFirstAssetTrader` in `cumulus/primitives/utility/src/lib.rs` accumulates the swapped `Target` fee in a single `total_fee` credit, but tracks only a single `last_fee_asset` field that is overwritten on every `buy_weight` call [1](#0-0) . When an XCM program executes more than one `BuyExecution` with different origin assets in the holding register, `refund_weight` blindly swaps the unspent portion of `total_fee` back into whatever asset happened to be used in the *last* `buy_weight` call, rather than the asset(s) that actually funded the unspent weight [2](#0-1) . This is the same class of bug as the OracleMulti report: a value ("last_fee_asset" / cached rate context) computed for one circuit/pair is silently reused for a different, incompatible pair/context.

### Finding Description
`buy_weight` takes the *first* fungible asset present in the XCM holding register, swaps it via `SwapCredit` into the configured `Target` asset, accumulates the result into `self.total_fee`, and unconditionally overwrites `self.last_fee_asset` with the id of the asset just consumed [3](#0-2) .

Because XCM programs can legitimately contain multiple `BuyExecution` instructions (e.g. a message that funds weight first from one asset, then tops up from a second asset present in the holding register, or nested execution contexts that invoke `buy_weight` more than once with different assets), `total_fee` can be an aggregate that mixes contributions swapped in from two (or more) distinct source assets, while `last_fee_asset` only remembers the most recent one.

`refund_weight` then computes the refund amount in `Target` terms, extracts it from the aggregate `total_fee`, and swaps the extracted amount back exclusively into `last_fee_asset` [4](#0-3) . There is no bookkeeping that ties any specific slice of `total_fee` back to the asset that produced it — exactly analogous to `OracleMulti` caching the last Chainlink pair's rate and reusing it to finalize a Uniswap pair that requires a different pair's rate.

The existing unit tests only exercise the case where the *same* asset is used across repeated `buy_weight`/`refund_weight` calls (`holding_asset_swap_for_target_twice`, `buy_and_refund_twice_for_target`) [5](#0-4) ; no test exists that calls `buy_weight` with two different source assets and then checks which asset the refund is issued in, so this cross-asset mismatch is unverified by the test suite.

This trader is wired into real, live runtime configurations, not just test/mock code: `asset-hub-rococo`, `asset-hub-westend`, `penpal`, and `staking-async` parachain runtimes all reference `SwapFirstAssetTrader` in their `xcm_config.rs` [6](#0-5) .

### Impact Explanation
If an XCM program (constructed by any ordinary, non-privileged sender) buys weight twice using two distinct assets from the holding register within one execution, an eventual `refund_weight` call (issued by the executor when actual weight used is less than purchased) will convert the whole unspent portion back into only the *second* asset, even if part of that unspent amount was originally paid in the *first* asset. The practical effects are:
- The refund is denominated in the wrong asset relative to what actually funded it, which can silently mis-credit downstream instructions in the same program that expect the refunded asset to match a specific asset id (e.g. a subsequent `DepositAsset` filtering by asset).
- Depending on liquidity/price differences between the two swap pools involved, the refunded value can diverge from what the correctly-attributed asset should have received, so the party effectively bears an unintended currency-conversion instead of getting back the exact asset it overpaid with.

This mirrors the original report's classification: it is a real, demonstrable logic defect in production code, but the loss is confined to value already inside the same XCM program's own holding register (self-contained mis-accounting), not a cross-user theft, unbacked issuance, or unauthorized dispatch. Consistent with the reference report's own "Risk Accepted / Medium" resolution for the analogous OracleMulti issue, this should be reported as Medium rather than inflated to Critical/High.

### Likelihood Explanation
Triggering the bug only requires an ordinary XCM program with multiple `BuyExecution` instructions funded by different assets present in the holding register before the message is executed — no privileged origin, governance, validator/collator collusion, or forged proof is needed. Because `SwapFirstAssetTrader` is actively configured in shipped Cumulus asset-hub and penpal runtimes, the reachable entry point (arbitrary incoming/outgoing XCM `Xcm::execute`/message execution invoking the configured `Trader`) exists in production configurations. However, constructing a message that deliberately buys weight twice with two different assets in the same execution context, and that also ends up under-using purchased weight so a refund actually occurs, is a non-trivial, specific message shape, which limits how often this path is hit in practice.

### Recommendation
Track fee contributions per-asset (e.g. a `Vec<(AssetId, Balance)>` or per-asset sub-ledger) instead of a single scalar `last_fee_asset`, and have `refund_weight` swap back proportionally into each asset that actually contributed to the unspent `total_fee`, or restrict refunds to only the asset used in the specific `buy_weight` call being refunded (mirroring `TakeFirstAssetTrader`'s single-asset invariant). At minimum, add an explicit doc/code comment (as Angle did for OracleMulti) stating that `SwapFirstAssetTrader` assumes at most one distinct asset is used to buy weight per program instance, and add a guard that rejects/errors a second `buy_weight` call using a different asset than `last_fee_asset` rather than silently overwriting it.

### Proof of Concept
No executable PoC was run against a live network or test harness; this analysis is based on static code review of `cumulus/primitives/utility/src/lib.rs` and its existing unit tests in `cumulus/primitives/utility/src/tests/swap_first.rs`. The missing guard is directly visible: `self.last_fee_asset = Some(id.clone());` unconditionally overwrites the previous value on every `buy_weight` call [7](#0-6) , and `refund_weight` only ever references `self.last_fee_asset`, never any earlier asset id, when reconstituting the refund [8](#0-7) . A concrete local reproduction (constructing a two-asset `buy_weight`/`buy_weight`/`refund_weight` sequence analogous to `holding_asset_swap_for_target_twice` but with `CLIENT_ASSET` then `CLIENT_ASSET_2`, and asserting `last_fee_asset` after the refund) was not executed in this session; the test scaffolding already present in `cumulus/primitives/utility/src/tests/swap_first.rs` (mock pools, `Trader` type alias, `CLIENT_ASSET_2` constant already defined but unused for this scenario) is the natural harness for such a reproduction and is recommended as the next concrete verification step.

	fn buy_weight(
		&mut self,
		weight: Weight,
		mut payment: AssetsInHolding,
		_context: &XcmContext,
	) -> Result<AssetsInHolding, (AssetsInHolding, XcmError)> {
		log::trace!(
			target: "xcm::weight",
			"SwapFirstAssetTrader::buy_weight weight: {:?}, payment: {:?}",
			weight,
			payment,
		);
		let Some((id, given_credit)) = payment.fungible.first_key_value() else {
			return Err((payment, XcmError::AssetNotFound));
		};
		let id = id.clone();
		let given_credit_amount = given_credit.amount();
		let first_asset: Asset = (id.clone(), given_credit_amount).into();
		let Ok((fungibles_id, _)) = FungiblesAssetMatcher::matches_fungibles(&first_asset) else {
			log::trace!(
				target: "xcm::weight",
				"SwapFirstAssetTrader::buy_weight asset {:?} didn't match",
				first_asset,
			);
			return Err((payment, XcmError::AssetNotFound));
		};

		let swap_asset = fungibles_id.clone().into();
		if Target::get().eq(&swap_asset) {
			log::trace!(
				target: "xcm::weight",
				"SwapFirstAssetTrader::buy_weight Asset was same as Target, swap not needed.",
			);
			// current trader is not applicable.
			return Err((payment, XcmError::FeesNotMet));
		}
		// Subtract required from payment
		let Some(imbalance) = payment.fungible.remove(&first_asset.id) else {
			return Err((payment, XcmError::TooExpensive));
		};
		// "manually" build the concrete credit and move the imbalance there.
		let mut credit_in = fungibles::Credit::<AccountId, Fungibles>::zero(fungibles_id);
		credit_in.saturating_subsume(imbalance);

		let fee = WeightToFee::weight_to_fee(&weight);
		// swap the user's asset for the `Target` asset.
		let (credit_out, credit_change) = match SwapCredit::swap_tokens_for_exact_tokens(
			vec![swap_asset, Target::get()],
			credit_in,
			fee,
		) {
			Ok(a) => a,
			Err((credit_in, error)) => {
				log::trace!(
					target: "xcm::weight",
					"SwapFirstAssetTrader::buy_weight swap couldn't be done. Error was: {:?}",
					error,
				);
				// put back the taken credit
				let taken =
					AssetsInHolding::new_from_fungible_credit(id.clone(), Box::new(credit_in));
				payment.subsume_assets(taken);
				return Err((payment, XcmError::FeesNotMet));
			},
		};

		match self.total_fee.subsume(credit_out) {
			Err(credit_out) => {
				// error may occur if `total_fee.asset` differs from `credit_out.asset`, which does
				// not apply in this context.
				defensive!(
					"`total_fee.asset` must be equal to `credit_out.asset`",
					(self.total_fee.asset(), credit_out.asset())
				);
				return Err((payment, XcmError::FeesNotMet));
			},
			_ => (),
		};
		self.last_fee_asset = Some(id.clone());

		if credit_change.peek() != Zero::zero() {
			let unspent = AssetsInHolding::new_from_fungible_credit(id, Box::new(credit_change));
			payment.subsume_assets(unspent);
		}
		Ok(payment)
	}

	fn refund_weight(&mut self, weight: Weight, _context: &XcmContext) -> Option<AssetsInHolding> {
		log::trace!(
			target: "xcm::weight",
			"SwapFirstAssetTrader::refund_weight weight: {:?}, self.total_fee: {:?}",
			weight,
			self.total_fee,
		);
		if weight.is_zero() || self.total_fee.peek().is_zero() {
			// noting to refund.
			return None;
		}
		let refund_asset = if let Some(asset) = &self.last_fee_asset {
			// create an initial zero refund in the asset used in the last `buy_weight`.
			(asset.clone(), Fungible(0)).into()
		} else {
			return None;
		};
		let refund_amount = WeightToFee::weight_to_fee(&weight);
		if refund_amount >= self.total_fee.peek() {
			// not enough was paid to refund the `weight`.
			return None;
		}

		let refund_swap_asset = FungiblesAssetMatcher::matches_fungibles(&refund_asset)
			.map(|(a, _)| a.into())
			.ok()?;

		let refund = self.total_fee.extract(refund_amount);
		let refund = match SwapCredit::swap_exact_tokens_for_tokens(
			vec![Target::get(), refund_swap_asset],
			refund,
			None,
		) {
			Ok(refund_in_target) => refund_in_target,
			Err((refund, _)) => {
				// return an attempted refund back to the `total_fee`.
				let _ = self.total_fee.subsume(refund).map_err(|refund| {
					// error may occur if `total_fee.asset` differs from `refund.asset`, which does
					// not apply in this context.
					defensive!(
						"`total_fee.asset` must be equal to `refund.asset`",
						(self.total_fee.asset(), refund.asset())
					);
				});
				return None;
			},
		};

		let refund = AssetsInHolding::new_from_fungible_credit(refund_asset.id, Box::new(refund));
		Some(refund)
	}

#[test]
fn holding_asset_swap_for_target_twice() {
	let client_asset_total = 20;
	let fee1 = 5;
	let fee2 = 6;

	setup_pool(CLIENT_ASSET, 1000, TARGET_ASSET, 1000);

	let holding_asset = create_holding_asset(CLIENT_ASSET, client_asset_total);
	let holding_change1 = create_holding_asset(CLIENT_ASSET, client_asset_total - fee1);
	let holding_change2 = create_holding_asset(CLIENT_ASSET, client_asset_total - fee1 - fee2);

	let target_total = Fungibles::total_issuance(TARGET_ASSET);
	let client_total = Fungibles::total_issuance(CLIENT_ASSET);

	let mut trader = Trader::new();
	let change1 = trader.buy_weight(weight_worth_of(fee1), holding_asset, &xcm_context()).unwrap();
	assert_eq!(&change1, &holding_change1);
	let change2 = trader
		.buy_weight(weight_worth_of(fee2), holding_change1, &xcm_context())
		.unwrap();
	assert_eq!(&change2, &holding_change2);

	assert_eq!(trader.total_fee.peek(), fee1 + fee2);
	assert_eq!(trader.last_fee_asset, Some(create_asset_id(CLIENT_ASSET)));

	assert_eq!(Fungibles::total_issuance(TARGET_ASSET), target_total);
	assert_eq!(Fungibles::total_issuance(CLIENT_ASSET), client_total);
}
