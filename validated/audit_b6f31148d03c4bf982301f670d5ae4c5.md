### Title
`initialize_with_permission` lets the caller set an unvalidated, non-signer `pool_creator` address, permanently freezing accumulated creator fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`InitializeWithPermission`'s `creator` account is declared as an `UncheckedAccount` with no signer requirement and no constraint tying it to `payer` or any other verified key. This attacker-chosen value is stored verbatim as `pool_state.pool_creator`, the address that later gates the privileged `collect_creator_fee` instruction. If `creator` is set to an address that can never produce a valid signature (e.g. `system_program::ID`, a PDA of an unrelated program, or any burn-style address), the pool's accumulated `creator_fees_token_0`/`creator_fees_token_1` become permanently uncollectible through the signer-gated path, and any fees paid out through the permissionless path are sent to an ATA nobody can ever withdraw from.

### Finding Description
In `Initialize` (the standard, non-permissioned pool-creation path), `creator` is a `Signer<'info>` [1](#0-0) , which guarantees `pool_state.pool_creator` is always an address capable of signing future transactions.

In `InitializeWithPermission`, however, `creator` is declared with no signer or address constraint at all: [2](#0-1) 

This unchecked value is passed directly into `PoolState::initialize`, which stores it as `pool_creator` without any validation: [3](#0-2) [4](#0-3) 

`pool_creator` subsequently becomes the sole authority that can call the signer-gated `collect_creator_fee`: [5](#0-4) 

and is also the destination authority used to create the ATA in the permissionless collection path: [6](#0-5) 

This mirrors the structure of the referenced bug class: a state-transition function accepts an unvalidated destination/authority address (analogous to `delegate(address(0))`), which is written into a critical accounting field without checking that the value is a usable, signable address. Once set, the system has no recovery path — exactly as the ERC721Votes bug permanently zeroed the checkpoint balance with no way to restore it, here the `pool_creator` field can be permanently set to an address with no controllable private key, with no way to update it afterward (no `set_pool_creator`/`update_creator` instruction exists in the reachable instruction set).

### Impact Explanation
Every swap that occurs against the pool while `enable_creator_fee = true` accumulates `creator_fees_token_0`/`creator_fees_token_1` in `PoolState` via `update_fees`: [7](#0-6) 

If `pool_creator` is an address without a known private key:
- `collect_creator_fee` can never succeed, because it requires `creator: Signer` to equal `pool_state.pool_creator` — an address that can never sign.
- `collect_creator_fee_permissionless` will still execute, but it creates/uses an ATA owned by that unownable `creator` address; any tokens sent there are irrecoverable since nobody controls that authority.

Either way, all creator fees accrued by the pool become permanently frozen/lost. This is a permanent freezing of protocol/LP-facing fee funds, which are real assets segregated in the pool vaults, satisfying the "permanent freezing of user or LP funds" bar.

### Likelihood Explanation
Reaching this requires calling `initialize_with_permission`, which is gated by a `Permission` PDA tied to the `payer` (created via the admin-only `create_permission_pda` instruction) [8](#0-7) . This means the caller must already be a permissioned pool creator — a normal, expected actor in scope (analogous to the "pool creator" role explicitly allowed by the rules), not an admin or leaked-key attacker. Any such permissioned creator can trivially pass an arbitrary, non-signing `creator` pubkey (accidentally or deliberately) in a single transaction with attacker-chosen account inputs, with no additional privilege needed beyond what the permissioned-pool-creation flow already grants. This makes the bug reachable by an in-scope, minimally-privileged actor.

### Recommendation
Constrain `creator` in `InitializeWithPermission` the same way it is constrained in `Initialize`: either require it to be a `Signer<'info>`, or add an explicit check that the passed-in `creator` pubkey is not the default `Pubkey::default()` / `system_program::ID`, and ideally verify it is capable of holding SPL accounts (not a program-owned/PDA address unless intentionally supported). Alternatively, add an instruction allowing `pool_creator` to be reassigned only by the current `pool_creator` (with the same restriction), giving a recovery path if a bad address is ever set.

### Proof of Concept
1. An address `P` obtains a `Permission` PDA via the admin-gated `create_permission_pda` flow (standard onboarding for permissioned pool creators).
2. `P` calls `initialize_with_permission`, supplying `payer = P` and `creator = system_program::ID` (or any other address with no known private key) as the `creator` account — no signature or relationship check is enforced on this field.
3. `pool_state.pool_creator` is set to `system_program::ID` via `PoolState::initialize`.
4. Swaps occur against the pool, accumulating nonzero `creator_fees_token_0`/`creator_fees_token_1` in `PoolState` via `update_fees`.
5. Calling `collect_creator_fee` always fails: the `creator: Signer` constraint requires the signer to equal `pool_state.pool_creator` (`system_program::ID`), which can never sign a transaction.
6. Calling `collect_creator_fee_permissionless` succeeds but sends the accumulated fees to an ATA owned by `system_program::ID`; since no private key exists for that authority, the tokens in that ATA are permanently unrecoverable.

    pub fn update_fees(
        &mut self,
        protocol_fee: u64,
        fund_fee: u64,
        creator_fee: u64,
        direction: TradeDirection,
    ) -> Result<()> {
        if !self.enable_creator_fee {
            require_eq!(creator_fee, 0)
        }
        let is_creator_fee_on_input = self.is_creator_fee_on_input(direction)?;
        match direction {
            TradeDirection::ZeroForOne => {
                self.protocol_fees_token_0 = self
                    .protocol_fees_token_0
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_0 = self.fund_fees_token_0.checked_add(fund_fee).unwrap();

                if is_creator_fee_on_input {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                }
            }
            TradeDirection::OneForZero => {
                self.protocol_fees_token_1 = self
                    .protocol_fees_token_1
                    .checked_add(protocol_fee)
                    .unwrap();
                self.fund_fees_token_1 = self.fund_fees_token_1.checked_add(fund_fee).unwrap();
                if is_creator_fee_on_input {
                    self.creator_fees_token_1 =
                        self.creator_fees_token_1.checked_add(creator_fee).unwrap();
                } else {
                    self.creator_fees_token_0 =
                        self.creator_fees_token_0.checked_add(creator_fee).unwrap();
                }
            }
        };
