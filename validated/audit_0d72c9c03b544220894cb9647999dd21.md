### Title
KIP-71 Base Fee Bounds Consistency Bypass via Same-Epoch Dual Governance Votes — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` validates each governance vote individually against the **current** effective parameter set, but never cross-validates pending votes within the same epoch against each other. Two votes for `kip71.lowerboundbasefee` and `kip71.upperboundbasefee` can each pass their individual checks yet, when ratified together at the epoch boundary, produce `LowerBoundBaseFee > UpperBoundBaseFee`. The resulting inconsistent state causes `NextMagmaBlockBaseFee` to return a base fee that exceeds the upper bound, overcharging users on every block.

---

### Finding Description

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` enforces the bound relationship at vote time:

```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {   // checked against CURRENT upper
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {   // checked against CURRENT lower
        return ErrUpperBoundBaseFee
    }
``` [1](#0-0) 

Each check reads `GetParamSet(blockNum)` — the **already-effective** parameter set — not the set of pending votes in the current epoch. When both parameters are voted on in the same epoch, neither vote sees the other's pending value.

At the epoch boundary, `getExpectedGovernance` collects all votes and writes them to `header.Governance` with no cross-parameter validation:

```go
for _, voteBlock := range sortedVoteBlocks {
    vote := prevEpochVotes[voteBlock]
    govs.Add(string(vote.Name()), vote.Value())   // no cross-check
}
``` [2](#0-1) 

`VerifyGov` only checks that the ratified governance data matches the locally-derived map; it performs no cross-parameter consistency check either. [3](#0-2) 

`PartialParamSet.Add` likewise only runs the per-parameter `FormatChecker`, not any cross-parameter invariant: [4](#0-3) 

---

### Impact Explanation

After ratification, `NewRewardConfig` / `ToKip71Config` assembles the broken `KIP71Config` and passes it to `NextMagmaBlockBaseFee`: [5](#0-4) 

Inside `NextMagmaBlockBaseFee`, with `LowerBoundBaseFee = 600 gwei` and `UpperBoundBaseFee = 100 gwei`:

```go
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
    parentBaseFee = upperBoundBaseFee   // clamp to 100
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee   // clamp to 600
}
``` [6](#0-5) 

When gas usage is below target, the code reaches:

```go
if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
    return makeEvenByFloor(lowerBoundBaseFee)   // returns 600 gwei
}
``` [7](#0-6) 

This returns **600 gwei** as the base fee — 6× the governance-set upper bound of 100 gwei. Every transaction in every subsequent block is charged at this inflated rate. The excess fee is burnt (Magma+), so the overcharge is a permanent loss to users. `VerifyMagmaHeader` enforces that `header.BaseFee` equals this computed value, so all honest nodes accept the overcharged blocks — there is no fork, but the KIP-71 fee-cap invariant is permanently broken until a corrective governance vote takes effect in the next epoch. [8](#0-7) 

---

### Likelihood Explanation

**In `none` governance mode** (any GC member can vote): a single validator can cast two votes in the same epoch — one for `kip71.lowerboundbasefee` and one for `kip71.upperboundbasefee` — with no coordination required. Each vote is individually valid; the inconsistency only materialises at ratification.

**In `single` governance mode** (Mainnet/Kairos): the governing node must cast both votes in the same epoch. This requires the governing node to be misconfigured or malicious, which is a higher bar, but the code provides no safety net to prevent it.

The `FormatChecker` for both parameters is `noopFormatChecker`, so there is no per-parameter range guard either: [9](#0-8) 

---

### Recommendation

In `checkConsistency`, when validating a `kip71.lowerboundbasefee` vote, also check it against any **pending** `kip71.upperboundbasefee` vote already queued in the current epoch (and vice versa). Alternatively, add a cross-parameter consistency check inside `getExpectedGovernance` / `VerifyGov` before the ratified governance data is written to `header.Governance`, rejecting the epoch block if the combined parameter set violates `LowerBoundBaseFee ≤ UpperBoundBaseFee`.

---

### Proof of Concept

Assume `epoch = 604800`, current params: `LowerBoundBaseFee = 25 gwei`, `UpperBoundBaseFee = 750 gwei`.

**Step 1** — Block 100 (within epoch 0): governing node (or any GC member in `none` mode) casts:
```
governance_vote("kip71.lowerboundbasefee", 600_000_000_000)  // 600 gwei
```
`checkConsistency`: `600 ≤ 750` → **passes**.

**Step 2** — Block 200 (same epoch): same or different GC member casts:
```
governance_vote("kip71.upperboundbasefee", 100_000_000_000)  // 100 gwei
```
`checkConsistency`: `100 ≥ 25` → **passes**.

**Step 3** — Block 604800 (epoch boundary): `getExpectedGovernance` collects both votes, writes `header.Governance = {"kip71.lowerboundbasefee": 600, "kip71.upperboundbasefee": 100}`. No cross-check. `VerifyGov` accepts it.

**Step 4** — Block 604801 onward: `GetParamSet` returns `LowerBoundBaseFee = 600 gwei`, `UpperBoundBaseFee = 100 gwei`. `NextMagmaBlockBaseFee` with any `parentGasUsed < gasTarget` returns `600 gwei`. `VerifyMagmaHeader` enforces this value. All nodes accept blocks with `BaseFee = 600 gwei`, which is 6× the intended upper bound. Users are overcharged on every transaction until a corrective vote takes effect one full epoch later.

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (p PartialParamSet) Add(name string, value any) error {
	param, ok := Params[ParamName(name)]
	if !ok {
		return ErrInvalidParamName
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		return err
	}

	if !param.FormatChecker(cv) {
		return ErrInvalidParamValue
	}

	p[ParamName(name)] = cv
	return nil
}

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
