### Title
Full replacement of asset attestor list can strand already-attested spenders' funds mid-flight - (File: `validation.js`, `storage.js`)

### Summary
Assets with `spender_attested=true` restrict who may issue/spend the asset to addresses appearing in the asset's *attestor list* at the time of validation. That list, however, is not additive/versioned per still-pending spends — every new `asset_attestors` message posted by the asset definer completely replaces which list is considered "current," and validation of any in-flight payment always looks up only the single latest stable list. If the definer legitimately rotates the attestor list (dropping a previously attested spender) between when a spender built a valid, attested private-payment chain and when that unit's `last_ball` stabilizes, the spender's already-prepared unit becomes permanently unspendable, exactly mirroring the `RewardDistributor` bug where overwriting `merkleRoot`/proof metadata before a user claims causes irrecoverable loss.

### Finding Description
`storage.readAsset()` resolves the attestor list for a `spender_attested` asset by finding only the most recent stable `asset_attestors` unit and using its list, with no accounting for spends that were already built/broadcast against an older list: [1](#0-0) 

`validateAttestorListUpdate()` allows the asset definer to submit a brand-new attestor list at any time, with no restriction preventing them from dropping addresses that currently hold unspent, attested balances or have transactions already composed against the old list: [2](#0-1) 

`validatePayment()` then rejects a spend from an address absent from whatever the *latest* attestor list happens to be at `last_ball_mci`, regardless of the list that was valid when the spending unit was signed and broadcast: [3](#0-2) 

This is structurally the same defect as the reported `RewardDistributor.updateRewardsMetadata()` issue: a privileged party (there, `bribeVault`; here, the asset `definer_address`) can overwrite state (`merkleRoot`/proof vs. attestor list) that other unprivileged parties' already-prepared claims/spends depend on, and there is no mechanism ensuring pending claims/spends are honored against the version of the state they were built against before it is superseded.

### Impact Explanation
A spender who is legitimately attested and holds balance of a `spender_attested` asset can have a fully valid, signed spend permanently invalidated if the definer posts a routine attestor-list update (e.g., adding a new attestor or removing a stale one) before the spend's `last_ball` stabilizes. Because the spender cannot re-attest themselves (only the definer can update the list — `if (objUnit.authors[0].address !== objAsset.definer_address) return callback("attestor list can be edited only by definer")`), and because there's no grandfather/versioning window, their coins become stuck: any output on that address cannot be spent again until/unless the definer re-adds them. This is a fund-freezing condition directly reachable by any ordinary user holding a spender-attested asset balance, triggered by ordinary (non-malicious) administrative action by the asset issuer.

### Likelihood Explanation
`spender_attested` assets and attestor-list updates are a normal, documented feature (not a rare edge case), and any definer performing routine attestor rotation (revoking one attestor, adding another) while any attested address has a payment in flight will trigger this. Given typical multi-second-to-minute stabilization delays on ocore, race conditions between a spend being composed/broadcast and a list update stabilizing are realistic, especially for actively managed attestor lists.

### Recommendation
Do not treat the attestor list as a single overwritable "latest" snapshot for the purposes of validating already-broadcast/in-flight spends. Options: (1) validate spender attestation against the list that was current when the spending unit's inputs were selected/signed (e.g., pin to `last_ball_mci` known to the composer at compose time, and accept if the address was attested at any point between that mci and current, or) (2) require attestor-list changes to be additive-only (never remove an address that still has an unspent attested balance) or provide a time-locked removal so pending spends have a chance to clear, mirroring the recommended fix of not rotating reward metadata while unclaimed distributions remain outstanding.

### Proof of Concept
1. Definer creates asset X with `spender_attested: true` and attests address A via `asset_attestors`/`attestors` list (list L1 containing A).
2. Address A receives units of asset X and later composes+broadcasts a spend of that balance; the spend is validated as attested per L1 while unstable.
3. Before A's spend unit's `last_ball` stabilizes, the definer posts a new `asset_attestors` message replacing the attestor list with L2 that does not include A (e.g., legitimate attestor rotation, unrelated to A).
4. L2 stabilizes before A's spend's `last_ball_mci`. `storage.readAsset()`'s `addAttestorsIfNecessary` now returns only L2's attestors, so `validatePayment()`'s check `objAsset.arrAttestedAddresses.indexOf(issuer_address) === -1` fails for A: `"issuer is not attested"`.
5. A's spend is permanently rejected; A cannot re-attest themselves; the balance on A's address is stranded until the definer, at their own discretion, re-adds A to the attestor list.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}
