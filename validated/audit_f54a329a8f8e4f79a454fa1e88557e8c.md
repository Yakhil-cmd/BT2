### Title
Webhook signature verification silently bypassed for any organization configured without a `webhook_secret` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` resolves the `GitHubApp` instance for the organization named in the request body's `repository.owner.login` (or `organization.login`), and delegates signature checking to `GitHubApp#verify_webhook_signature`. That method has an early-return `return true unless webhook_secret` at [1](#0-0)  that treats a blank/absent `webhook_secret` config as "verification passed" instead of "verification impossible," so any organization deployed without a configured secret accepts unsigned, attacker-forged webhooks.

### Finding Description
Broken binding: the code assumes `webhook_secret.present? == true` for every configured organization, but the actual precondition enforced anywhere is only `github_app_config(organization).present? == true` — i.e. the org must exist in `Shipit.github_app_config`, not that it has a secret. Once `config[:webhook_secret]` is blank/nil, `@webhook_secret = @config[:webhook_secret].presence` at [2](#0-1)  becomes `nil`, and `verify_webhook_signature` unconditionally returns `true` regardless of the `X-Hub-Signature` header or payload contents [3](#0-2) .

Path: an unauthenticated POST to `/webhooks` is handled by `before_action :check_if_ping, :drop_unhandled_event, :verify_signature`, then `create` [4](#0-3) . `verify_signature` computes `repository_owner` straight from attacker-controlled JSON (`params.dig('repository', 'owner', 'login')`) [5](#0-4) , looks up `Shipit.github(organization: repository_owner)` [6](#0-5) , which calls `github_app_config(organization)` — a case-insensitive lookup keyed only by whether the org exists in `secrets.github`, with no requirement that a secret is set [7](#0-6) . If that org's config lacks `webhook_secret`, `verify_webhook_signature` returns `true` and the handler is invoked on fully attacker-supplied payload data, regardless of signature header value or absence.

This is a genuine engine-code defect, not merely a test artifact: the vulnerable branch (`return true unless webhook_secret`) lives in `lib/shipit/github_app.rb`, which is shipped application code, and is reachable for any real deployment that lists an organization in `Shipit.github` without setting its `webhook_secret` (a plausible misconfiguration, especially in multi-org GitHub App setups where an operator forgets one org's secret). No other guard intercepts this: `drop_unhandled_event` only filters by event type, not repository ownership, and only returns 204 for unhandled events, allowing handled ones (`push`, `pull_request`, `status`, `membership`, `check_suite`) through [8](#0-7) . `GithubOrganizationUnknown` is only raised when the organization isn't configured at all, not when its secret is blank [9](#0-8) .

### Impact Explanation
For any misconfigured organization, an attacker can forge arbitrary webhook payloads (push, pull_request, status, check_suite, membership) naming any repository under that org, causing handlers such as `GithubSyncJob` or PR/status handlers to run based entirely on attacker-controlled JSON, with no cryptographic proof the request originated from GitHub. This is an authentication bypass matching the "Critical" category (forged webhook accepted) and can lead to a payload for one repository mutating another's stack/commit/task state, or unauthorized sync/deploy-triggering behavior, scoped to whichever organization(s) are missing a `webhook_secret`.

### Likelihood Explanation
Exploitability is entirely conditioned on operator misconfiguration: the org must be present in `Shipit.github_app_config` (so `GithubOrganizationUnknown` isn't raised) but have `webhook_secret` blank/nil. Given a multi-org GitHub App setup (`TOP_LEVEL_GH_KEYS` distinguishes single- vs multi-org schemas at [10](#0-9) ), it is plausible for an operator to add a new org and omit the secret. Attacker cost is trivial — an unauthenticated POST to `/webhooks` with a crafted body naming the vulnerable org — and it is fully repeatable against every repository under that org.

### Recommendation
Change `GitHubApp#verify_webhook_signature` to treat a missing `webhook_secret` as a hard failure (return `false`) rather than an implicit pass, and/or fail closed at startup/config-load time if any configured organization lacks a `webhook_secret`, so misconfiguration cannot silently disable signature verification.

### Proof of Concept
In `test/controllers/webhooks_controller_test.rb` (existing suite already stubs `Shipit.github`):
1. Stub `Shipit.github(organization: 'OrgOne')` to return a `GitHubApp.new('OrgOne', config_without_webhook_secret)` where `config_without_webhook_secret[:webhook_secret]` is `nil`.
2. POST `/webhooks` with header `X-Github-Event: push`, no `X-Hub-Signature` header (or garbage value), and a JSON body with `repository.owner.login == 'OrgOne'` and `repository.full_name` naming a real stack.
3. Assert binding before fix: `github_app.webhook_secret.present? == false` yet `github_app.verify_webhook_signature(garbage_or_nil_signature, body) == true`.
4. Assert response is `200 OK` (not `422`) and that the corresponding handler (e.g., `GithubSyncJob.jobs`) was enqueued — proving an unsigned/forged webhook was processed.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
