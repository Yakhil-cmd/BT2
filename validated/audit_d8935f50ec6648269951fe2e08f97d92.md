### Title
Untracked-file exclusion in `compute_v2_review_set` relies solely on forgeable mtime equality, letting content changes evade the Stop-hook LLM review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`_list_untracked` snapshots untracked files as `{path: mtime_ns}` at `UserPromptSubmit`, and `compute_v2_review_set` later excludes an untracked file from the review set solely by comparing its current mtime to the snapshotted value, with no content/hash check. Because the "unchanged" decision is based purely on `st_mtime_ns`, any actor able to run shell commands (e.g. via Bash tool use, including in response to injected instructions from repo/tool content) can modify the file's bytes and then restore its original mtime (`os.utime`, `touch -r`, `cp --preserve=timestamps`), causing the file to be permanently excluded from the Stop hook's git-diff-derived `review_set` even though its content changed during the turn.

### Finding Description
`_list_untracked` in [1](#0-0)  snapshots repo-root-relative untracked paths to `mtime_ns` at UPS and is invoked from `handle_user_prompt_submit`, stored into session state as `untracked_at_baseline` under `with_locked_state` [2](#0-1) .

At Stop time, `compute_v2_review_set` decides which untracked files are "pre-existing and unchanged" purely by mtime equality: [3](#0-2) 
There is no content hash or `git diff`-based check for untracked files — `git stash create` (used for `baseline_sha`) never captures untracked content at all, per the function's own docstring [4](#0-3) , so the mtime comparison is the *only* signal used to decide whether an untracked file needs review. Files classified `preexisting_unchanged` are subtracted from `new_untracked`, which in turn is excluded from both `dirty_now` and `changed_since`, so they never enter `review_set` regardless of actual content drift [5](#0-4) .

The design explicitly assumes any in-place edit bumps mtime ("mtime is captured so an in-place edit during the turn is still reviewed" [6](#0-5) ), but this assumption doesn't hold against an actor with Bash access who deliberately restores the original mtime after writing malicious content (e.g. `touch -r` or `os.utime`). Since Claude's Bash tool routinely has unrestricted filesystem access within the workspace during a turn, and its behavior can be steered by attacker-controlled content (prompt injection from files/issues/tool output read during the session), this is reachable through the normal automation flow without any elevated privilege.

Tracked files are unaffected — `_git_status_porcelain`/`_git_name_only` are content-based (`git diff`/`git status`) — so this weakness is scoped to untracked files only, but that is precisely the class of file `_list_untracked`/`compute_v2_review_set` was built to guard.

### Impact Explanation
An untracked file whose bytes are altered mid-turn but whose mtime is restored to the UPS-baseline value is silently dropped from the Stop hook's `review_paths`/`review_set`, meaning `get_git_diff` never surfaces it to the LLM vulnerability scan [7](#0-6) . This is a direct bypass of the plugin's core security guarantee ("Only code Claude actually changed is reviewed" per the module docstring [8](#0-7) ): a maliciously modified file escapes the Stop-hook LLM review entirely, letting an injected vulnerability persist undetected across turns.

### Likelihood Explanation
Exploitation requires only ordinary Bash tool capability already available during a normal session (no root/admin, no leaked credentials) plus the ability to influence what commands run — either directly, or via prompt-injected content that instructs Claude to perform a mtime-preserving edit. Standard Unix tools (`touch -r`, `cp -p`, `rsync -t`, `os.utime`) make this trivial and fully repeatable every turn.

### Recommendation
Replace or augment the mtime-equality check in `_unchanged_since_baseline` (`plugins/security-guidance/hooks/diffstate.py`) with a content-based comparison (e.g., a hash of file bytes/size captured at UPS and compared at Stop), so an untracked file is only excluded from `review_set` when its actual content is verified unchanged, not merely when its mtime matches.

### Proof of Concept
Integration test in the diffstate/security_reminder_hook test suite:
1. Create a git repo with a commit; create an untracked file `evil.txt` with benign content `"safe"`.
2. Call `_list_untracked(cwd)` to obtain `untracked_at_baseline = {"evil.txt": mtime_ns}` (simulating UPS capture); persist via `with_locked_state` as in `handle_user_prompt_submit`.
3. Record `orig_stat = os.stat("evil.txt")`.
4. Overwrite `evil.txt` with malicious payload content, then call `os.utime("evil.txt", ns=(orig_stat.st_atime_ns, orig_stat.st_mtime_ns))` to restore the original mtime (simulating `touch -r`).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline)`.
6. Assert: `os.path.join(repo, "evil.txt")` IS present in the returned `review_paths` (expected/desired behavior) — the test currently fails because the file is excluded via `preexisting_unchanged`, proving the mtime-only gate lets attacker-controlled content changes bypass the Stop-hook review.

```python
def _list_untracked(cwd):
    """Repo-root-relative untracked (and not-ignored) path → mtime_ns, or {}
    on error. Used at UPS to snapshot the pre-turn untracked set so the Stop
    hook can exclude unchanged pre-existing untracked files from review.
    mtime is captured so an in-place edit during the turn is still reviewed.

    Uses ls-files (not status) for the UPS path: the index diff isn't needed,
    and ls-files --others only walks the worktree against .gitignore."""
    try:
        repo = _git_toplevel(cwd) or cwd
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "ls-files",
             "--others", "--exclude-standard", "-z"],
            cwd=repo, capture_output=True, text=True, timeout=15,
        )
        if r.returncode != 0:
            debug_log(f"_list_untracked rc={r.returncode}: {r.stderr[:200]}")
            return {}
        out = {}
        for p in r.stdout.split("\0"):
            if not p:
                continue
            try:
                out[p] = os.stat(os.path.join(repo, p)).st_mtime_ns
            except OSError:
                out[p] = 0
            if len(out) >= UNTRACKED_BASELINE_CAP:
                debug_log(f"_list_untracked: capped at {UNTRACKED_BASELINE_CAP}")
                break
        return out
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_list_untracked error: {e}")
        return {}
```

```python
    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```

```python
## How the git baseline works

On each UserPromptSubmit, the plugin runs `git stash create` to get a SHA representing
the current working tree state (HEAD + any uncommitted changes). This SHA is saved to
the session state file. When the Stop hook fires, it runs `git diff <baseline_sha>` to
get only the changes made since that snapshot. After analysis, the baseline is updated
so the next Stop hook iteration only sees new changes.

This means:
- Only code Claude actually changed is reviewed (not pre-existing code)
- Mid-session commits are handled correctly (diff is against the snapshot, not HEAD)
- Each turn only reviews new changes (baseline updates after each stop hook)
```

```python
    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
    with_locked_state(session_id, _save)
```
