### Title
`light/dry_run_aa` lets any client pre-simulate a real trigger (including embedded signed orders) before committing, enabling frontrunning of AA trades - (File: `network.js`, `aa_composer.js`)

### Summary
The `light/dry_run_aa` network command runs `aa_composer.dryRunPrimaryAATrigger()` on an arbitrary, unsigned trigger object supplied by the caller and returns the full simulated result (state-var changes, response messages, computed payment amounts) to the requester before any real unit is ever composed or broadcast. This is the same "pre-process and reveal" pattern flagged in the Gladius `quote()` finding: a caller can preview the exact effect of an intended action — including one that embeds a real signed order — without committing to it, and the party that services the preview (or anyone able to observe that traffic) learns enough to beat the original submitter to the punch.

### Finding Description
`network.js` exposes `light/dry_run_aa` as a normal, unprivileged light-client RPC: [1](#0-0) 

It only requires `params.address` to be a valid address and `params.trigger` to pass `validateAATriggerObject`, which merely checks structural shape (`outputs`, `address`, `data` size limits) — it does **not** require any signature binding the trigger to a real committed unit: [2](#0-1) 

The handler then calls `dryRunPrimaryAATrigger`, which executes the AA logic for real against the live state (rolled back afterward) and returns `arrResponses` containing the AA's computed outputs, bounced/not-bounced status, and updated state vars: [3](#0-2) 

Many production AA patterns embed a user's real signed order/intent inside `trigger.data` and execute it atomically against on-chain state, e.g. the order-matching AA in the test fixtures: [4](#0-3) 

This AA is inherently first-come-first-served: it checks `var['executed_' || $id1]` / `var['amount_left_' || $id1]` to decide whether an order can still be matched. A user who wants to know in advance whether their order (or a counter-order pairing) would succeed, and at what price/amount, has every incentive to call `light/dry_run_aa` with their real signed order package as `trigger.data` before spending the fee to actually post the unit — exactly mirroring how `GladiusOrderQuoter.quote()` calls `executeWithCallback` on a real signed order to preview execution. The full node (or anything observing/relaying that RPC call) now knows the exact order parameters, computed match amount, and price before the real trigger unit is ever broadcast to the DAG.

### Impact Explanation
Whoever services or observes the `light/dry_run_aa` request learns the complete details of a not-yet-committed, potentially profitable trade (counterparties, amounts, computed match price) ahead of time. That information can be used to:
- Submit a competing/matching order first, consuming the available `var[$sell_key]`/`amount_left` balance so the original submitter's later real unit bounces (losing bounce fees) or receives a worse partial fill.
- Extract the price/quantity edge intended for the original submitter, i.e. classic frontrunning/MEV extraction against an AA-based order book or auction pattern.

This causes AA fund loss (bounce fees paid for a trade that no longer executes as expected) and unfair execution for the honest trigger sender — the same class of impact described in the original report (opportunistic traders gaining an advantage from leaked order details).

### Likelihood Explanation
Any light client can call `light/dry_run_aa` with no privilege beyond a normal peer connection, and any AA author is free to build first-come-first-served matching logic (as the shipped `order_book_exchange.oscript` sample demonstrates), so this pattern is directly reachable by an ordinary AA trigger sender who wants to preview their trade, and by anyone positioned to see that RPC traffic.

### Recommendation
- Do not allow arbitrary, fully-detailed trigger previews that reveal computed match amounts/counterparties for state-dependent, first-come-first-served AA logic via a network-exposed RPC.
- Consider requiring the dry-run trigger's sensitive fields (e.g., embedded signed order packages) to be redacted/hashed for preview purposes, or restrict preview responses to coarse-grained success/failure rather than full computed outputs/state deltas.
- Alternatively, document clearly for AA authors that `dry_run_aa` previews leak full execution details, and advise against designing FCFS matching AAs whose correctness depends on the trigger data being secret prior to commitment.

### Proof of Concept
1. AA author deploys an order-matching AA equivalent to `test/samples/order_book_exchange.oscript`, which matches `trigger.data.order1`/`order2` (containing signed order packages) on a first-come-first-served basis against `var[$sell_key]`.
2. Alice signs order1 (sell X for Y at price P) and, before broadcasting the real trigger unit, calls `light/dry_run_aa` with `trigger.data = {order1: aliceSignedOrder, order2: bobSignedOrder}` to preview the match.
3. The full node servicing the request (or an observer of that traffic) now knows the exact match amount/price about to be executed.
4. That party crafts and broadcasts its own competing trigger consuming the same `var[$sell_key2]`/`amount_left` balance first.
5. When Alice's real trigger unit lands, the AA's `if` condition or balance checks fail (`$amount_left1 > var[$sell_key1]`), the trigger bounces, and Alice loses the bounce fee while the frontrunner captures the favorable trade.

function validateAATriggerObject(trigger, handle) {
	if (!ValidationUtils.isNonemptyObject(trigger))
		return handle("no trigger");
	if (!ValidationUtils.isNonemptyObject(trigger.outputs))
		return handle("no trigger outputs");
	if (!ValidationUtils.isValidAddress(trigger.address))
		return handle("bad trigger address");
	if ("max_aa_responses" in trigger && (!ValidationUtils.isNonnegativeInteger(trigger.max_aa_responses) || trigger.max_aa_responses > constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER))
		return handle("bad trigger max_aa_responses");
	if (ValidationUtils.hasFieldsExcept(trigger, ["address", "data", "outputs", "max_aa_responses"])) // initial_address and initial_unit cannot be separately set in a primary trigger
		return handle("unexpected trigger fields");
	if (string_utils.isTooBigObj(trigger, { lengthLimit: 10e3 }))
		return handle("trigger data is too big");
	try {
		if (trigger.data)
			string_utils.getJsonSourceString(trigger.data);
	}
	catch (e) {
		return handle("invalid trigger data: " + e);
	}
	var arrAssets = Object.keys(trigger.outputs).filter(function(asset) {return asset !== 'base'});
	if (arrAssets.length >= constants.MAX_MESSAGES_PER_UNIT)
		return handle("too many assets");
	if (!ValidationUtils.isPositiveInteger(trigger.outputs.base))
		return handle("no base payment");
	if (!arrAssets.every(function(asset){return ValidationUtils.isPositiveInteger(trigger.outputs[asset])}))
		return handle("invalid output amount")

	function checkAddressIsNotAA() {
		db.query("SELECT 1 FROM aa_addresses WHERE address=?", [trigger.address], rows => {
			if (rows.length)
				return handle("trigger address must not be an AA");
			else
				return handle();
		});
	}

	if (arrAssets.length === 0)
		return checkAddressIsNotAA();
	// we have to check that assets exist otherwise foreign key constraint would fail when inserting fake outputs
	db.query("SELECT 1 FROM assets WHERE unit IN (?)", [arrAssets], function(rows) {
		if (rows.length !== arrAssets.length)
			return handle("unknown asset");
		else
			checkAddressIsNotAA();
	});
}

function dryRunPrimaryAATrigger(trigger, address, arrDefinition, onDone) {
	if (!onDone)
		return new Promise(resolve => dryRunPrimaryAATrigger(trigger, address, arrDefinition, resolve));
	console.log('dry run', address, trigger);
	db.takeConnectionFromPool(function (conn) {
		conn.query("BEGIN", function () {
			var batch = conf.bLight ? lightBatch : kvstore.batch();
			readLastStableMcUnit(conn, function (mci, objMcUnit) {
				trigger.unit = constants.GENESIS_UNIT; // objMcUnit.unit; // might cause duplicate trigger_unit in aa_triggers if objMcUnit is already a real trigger
				if (!trigger.address)
					trigger.address = objMcUnit.authors[0].address;
				trigger.initial_address = trigger.address;
				trigger.initial_unit = trigger.unit;
				var fPrepare = function (cb) {
					insertFakeOutputsIntoMcUnit(conn, objMcUnit, trigger.outputs, address, cb);
				};
				fPrepare(function () {
					var arrResponses = [];
					handleTrigger({
						bDryRun: true, // suppress events for a unit that will be rolled back
						conn, batch, trigger, params: {}, stateVars: {}, arrDefinition, address, mci, objMcUnit, bSecondary: false, arrResponses,
						onDone: function () {
							revertResponsesInCaches(arrResponses);
							batch.clear();
							conn.query("ROLLBACK", function () {
								conn.release();
								onDone(arrResponses);
							});
						},
					});
				});
			});
		});
	});
