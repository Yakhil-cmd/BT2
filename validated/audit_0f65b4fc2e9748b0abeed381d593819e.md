### Title
Inverted Trusted-Peer Guard in `handle()` Allows Peer-Slot Flooding to Partition Trusted Validator Peers — (`node/cn/handler.go`)

### Summary

`ProtocolManager.handle()` contains two sequential peer-limit checks. The first (line 547) is correct. The second (lines 580–584), which carries the same comment "Ignore maxPeers if this is a trusted peer," has its condition inverted: it fires **only when the peer IS trusted** and then rejects it. An attacker who fills all peer slots with non-trusted connections can permanently prevent any trusted validator peer from completing the application-layer handshake, partitioning the target node from its consensus peers.

### Finding Description

**Check 1 — correct** (line 547):
```go
// Ignore maxPeers if this is a trusted peer
if pm.peers.Len() >= pm.maxPeers && !p.GetP2PPeer().Info().Networks[p2p.ConnDefault].Trusted {
    return p2p.DiscTooManyPeers
}
```
Trusted peers pass through; non-trusted peers are rejected when full. [1](#0-0) 

**Check 2 — inverted / buggy** (lines 580–584):
```go
// Ignore maxPeers if this is a trusted peer
if p.GetP2PPeer().Info().Networks[p2p.ConnDefault].Trusted {
    if reject || pm.peers.Len() >= pm.maxPeers {
        return p2p.DiscTooManyPeers
    }
}
```
The outer `if` fires **only for trusted peers**, then rejects them when `peers.Len() >= maxPeers`. Non-trusted peers are never touched by this block. The comment is the exact opposite of what the code does. [2](#0-1) 

The identical inversion exists in `multiChannelPeer.Handle()`: [3](#0-2) 

**Execution path for a trusted peer when slots are full:**

| Step | Code | Result |
|---|---|---|
| P2P layer `encHandshakeChecks` | `!isTrustedOrStatic() && len(peers) >= max` | Trusted peer passes (correct) |
| App layer check 1 (line 547) | `peers.Len() >= max && !Trusted` → false | Trusted peer passes (correct) |
| App layer check 2 (line 580) | `Trusted == true` → enters block → `peers.Len() >= max` → true | **Trusted peer rejected** (bug) | [4](#0-3) 

### Impact Explanation

A trusted peer is typically a configured validator or a known consensus-critical node. The P2P server documentation explicitly states:

> "Trusted nodes are used as pre-configured connections which are always allowed to connect, even above the peer limit." [5](#0-4) 

Because the P2P layer correctly admits the trusted peer but the application layer immediately disconnects it with `DiscTooManyPeers`, the trusted peer will retry (static/trusted nodes reconnect automatically) but will be rejected every time as long as the attacker holds the non-trusted slots. The targeted validator node:

- Cannot receive new blocks from its trusted peers
- Cannot send consensus votes to them
- Falls behind the canonical chain
- Is effectively partitioned from the consensus network

This constitutes **durable loss of core chain functionality** (validator participation) and potential **consensus divergence** on the targeted honest node.

### Likelihood Explanation

- The P2P port is public and reachable by any remote peer.
- The attacker only needs to maintain `maxPeers` simultaneous connections (default is configurable; typical values are 25–50).
- No privileged keys, governance access, or validator collusion is required.
- The attack is persistent: as long as the attacker holds the slots, every trusted-peer reconnect attempt is rejected at the application layer.

### Recommendation

Invert the outer condition in the second check (both in `handle()` and `multiChannelPeer.Handle()`) to match the intent of the comment:

```go
// Ignore maxPeers if this is a trusted peer
if !p.GetP2PPeer().Info().Networks[p2p.ConnDefault].Trusted {
    if reject || pm.peers.Len() >= pm.maxPeers {
        return p2p.DiscTooManyPeers
    }
}
```

This mirrors the correct pattern already used at line 547 and in `MainBridge.handle()` / `SubBridge.handle()`. [6](#0-5) [7](#0-6) 

### Proof of Concept

```
Setup:
  maxPeers = 1
  trustedPeer = NodeID X (configured in TrustedNodes)

Step 1: Non-trusted peer A connects → accepted (peers.Len() = 1)

Step 2: Trusted peer X connects:
  - P2P encHandshakeChecks: !isTrustedOrStatic() && 1 >= 1 → false → passes
  - handle() line 547: 1 >= 1 && !Trusted → false → passes
  - handle() line 580: Trusted == true → enters block
  - handle() line 581: 1 >= 1 → true → returns DiscTooManyPeers ← BUG

Expected: trusted peer X is accepted (slot exemption)
Actual:   trusted peer X is rejected with DiscTooManyPeers

The existing test TestServerAtCap in networks/p2p/server_test.go verifies the
P2P-layer behavior is correct, but there is no equivalent test at the
application-layer handle() level, which is where the inversion occurs.
``` [8](#0-7)

// This test checks that connections are disconnected
// just after the encryption handshake when the server is
// at capacity. Trusted connections should still be accepted.
func TestServerAtCap(t *testing.T) {
	trustedID := randomID()
	srv := &SingleChannelServer{
		BaseServer: &BaseServer{
			Config: Config{
				PrivateKey:             newkey(),
				MaxPhysicalConnections: 10,
				NoDial:                 true,
				TrustedNodes:           []*discover.Node{{ID: trustedID}},
			},
		},
	}
	if err := srv.Start(); err != nil {
		t.Fatalf("could not start: %v", err)
	}
	defer srv.Stop()

	newconn := func(id discover.NodeID) *conn {
		fd, _ := net.Pipe()
		tx := newTestTransport(id, fd, nil, false)
		return &conn{fd: fd, transport: tx, flags: inboundConn, conntype: common.ConnTypeUndefined, id: id}
	}

	// Inject a few connections to fill up the peer set.
	for i := range 10 {
		c := newconn(randomID())
		if err := srv.handleAddPeerConn(c); err != nil {
			t.Fatalf("could not add conn %d: %v", i, err)
		}
	}
	// Try inserting a non-trusted connection.
	c := newconn(randomID())
	if err := srv.handlePostHandshake(c); err != DiscTooManyPeers {
		t.Error("wrong error for insert:", err)
	}
	// Try inserting a trusted connection.
	c = newconn(trustedID)
	if err := srv.handlePostHandshake(c); err != nil {
		t.Error("unexpected error for trusted conn @posthandshake:", err)
	}
	if !c.is(trustedConn) {
		t.Error("Server did not set trusted flag")
	}
}
