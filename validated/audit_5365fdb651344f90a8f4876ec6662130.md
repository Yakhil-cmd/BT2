### Title
Unauthorized `StackStxOp`/`DelegateStxOp`/`TransferStxOp` sender spoofing via unbound `PreStxOp` outputs - (File: `stackslib/src/chainstate/burn/operations/stack_stx.rs`, `stackslib/src/burnchains/burnchain.rs`)

### Summary
`PreStxOp::parse_from_tx` derives the future `sender`/stacker identity solely from output[0] of the PreStx Bitcoin transaction, with no requirement that output[1] (whose later spend authorizes the follow-on op) be controlled by the same key as output[0] [1](#0-0) . `StackStxOp::get_sender_txid` (and the `Delegate`/`TransferStx` equivalents) only checks that the spent output index is `1`, not that the spending key matches output[0]'s address [2](#0-1) , and `burnchain.rs` blindly assigns `sender = pre_stx.output` for whoever supplies that input [3](#0-2) .

### Finding Description
The broken equality: "the Stacks principal whose STX gets locked by `stack-stx` (`op.sender`)" must equal "the principal that cryptographically authorized this burnchain operation (i.e., controls the private key that can move value tied to it)." In the code, `op.sender` is set from `PreStxOp.output`, which is nothing more than the P2PKH address encoded in the *first* recipient of an arbitrary Bitcoin transaction [1](#0-0) . Anyone can construct a Bitcoin transaction that pays dust to victim V's hash160 as output[0] — no permission or key from V is required to *pay* an address. As long as this transaction also has an output[1] that the attacker controls, the attacker can later spend output[1] in a `StackStxOp` transaction. `get_sender_txid` (`vout != 1` check only) accepts this [2](#0-1) , and the burnchain op resolver looks up the PreStxOp purely by txid, then sets `sender = &pre_stack_stx.output` (= V) for the new `StackStxOp` regardless of who signed the spending input [3](#0-2) . `StackStxOp::parse_from_tx` never revalidates that the `sender` argument corresponds to any key used in the transaction [4](#0-3) ; it only encodes `data.stacked_ustx`, `num_cycles`, `signer_key`, etc., taken from the OP_RETURN payload and the attacker's own chosen `reward_addr` (their own first output) [5](#0-4) . Consequently, `stack-stx` executes with `tx-sender` effectively equal to V, without any signature from V anywhere in the Stacks or Bitcoin layers — the entire "unsigned" burnchain-stacking model's sole authorization anchor (spend of PreStxOp output[1]) is decoupled from the identity it is supposed to authorize (PreStxOp output[0]).

### Impact Explanation
An attacker who knows only victim V's Stacks/Bitcoin address can force `stack-stx` to lock V's unlocked STX for a chosen `lock-period`/`num_cycles`, while pointing the resulting PoX reward address (`reward_addr`, chosen entirely from the attacker's own `StackStxOp` transaction outputs) to a wallet the attacker controls. This is an unsigned/unauthorized stacking action against the victim's account and diverts stacking rewards away from V — matching the "an unsigned stacking action" High-severity category. It is repeatable against any address with an eligible unlocked balance (subject to the pox-4/pox-5 checks that the account is not already stacking/delegating), at the cost of a couple of low-value Bitcoin transactions per victim.

### Likelihood Explanation
Preconditions are minimal and fully attacker-controlled: (1) V must not already be actively stacking/delegating and must have an unlocked balance ≥ some `amount-ustx` the attacker chooses, (2) the reward cycle/`start-burn-ht` fields must line up with the *next* cycle boundary as pox-4/pox-5 require, and (3) the attacker needs their own signer key (no cooperation from V) to satisfy `consume-signer-key-authorization`, which only checks the signer key's ownership, not V's consent. All of this is achievable by an unprivileged attacker with ordinary Bitcoin UTXOs, at the cost of two small Bitcoin transactions (a PreStxOp dust payment + a StackStxOp spend), and can be repeated against many victims.

### Recommendation
Enforce that the address paying V in `PreStxOp` output[0] must be provably the same key that later spends output[1]. Concretely, when resolving `StackStxOp`/`DelegateStxOp`/`TransferStxOp` against a previously seen `PreStxOp`, additionally verify that the scriptPubKey/public-key-hash used to authorize the spending input of the follow-on transaction matches the hash160 encoded in `PreStxOp.output`'s address (i.e., recover or compare the spending key against output[0]'s hash160), rejecting the op if they diverge. This restores the intended security invariant that only the controller of `sender`'s own Bitcoin key can trigger stacking/transfer/delegation on that principal's behalf.

### Proof of Concept
Rust integration test (in `stackslib/src/burnchains/tests/db.rs` style):
1. Construct a `BitcoinTransaction` `pre_stx_tx` with opcode `PreStx`, `outputs[0].address = V_hash160` (attacker-funded dust payment to V's known address, no V key used), `outputs[1].address = attacker_hash160`.
2. Parse it via `PreStxOp::parse_from_tx`; assert `op.output == StacksAddress::from(V_hash160)`.
3. Construct `stack_stx_tx` with opcode `StackStx`, `inputs[0].tx_ref = (pre_stx_tx.txid(), 1)` signed/spendable only with the attacker's key, and attacker-chosen `reward_addr`.
4. Run it through `burnchain.rs`'s op-classification path (`Opcodes::StackStx` branch); assert the resulting `StackStxOp.sender == V` and `StackStxOp.reward_addr == attacker's own address`.
5. Feed this op through `process_stacking_ops`/pox-5 `stack-stx` execution against a chainstate where V has an unlocked balance ≥ `stacked_ustx`; assert V's `STXBalance` becomes locked and no Stacks transaction signed by V's key appears anywhere in the block, proving the lock was applied without V's authorization.

    pub fn get_sender_txid(tx: &BurnchainTransaction) -> Result<&Txid, op_error> {
        match tx.get_input_tx_ref(0) {
            Some((ref txid, vout)) => {
                if *vout != 1 {
                    warn!("Invalid tx: StackStxOp must spend the second output of the PreStxOp");
                    Err(op_error::InvalidInput)
                } else {
                    Ok(txid)
                }
            }
            None => {
                warn!("Invalid tx: StackStxOp must have at least one input");
                Err(op_error::InvalidInput)
            }
        }
    }

    pub fn parse_from_tx(
        block_height: u64,
        block_hash: &BurnchainHeaderHash,
        epoch_id: StacksEpochId,
        tx: &BurnchainTransaction,
        sender: &StacksAddress,
        pox_sunset_ht: u64,
    ) -> Result<StackStxOp, op_error> {
        // can't be too careful...
        let num_outputs = tx.num_recipients();

        if tx.num_signers() == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                num_outputs
            );
            return Err(op_error::InvalidInput);
        }

        if num_outputs == 0 {
            warn!(
                "Invalid tx: inputs: {}, outputs: {}",
                tx.num_signers(),
                num_outputs,
            );
            return Err(op_error::InvalidInput);
        }

        if tx.opcode() != Opcodes::StackStx as u8 {
            warn!("Invalid tx: invalid opcode {}", tx.opcode());
            return Err(op_error::InvalidInput);
        };

        let data = StackStxOp::parse_data(&tx.data()).ok_or_else(|| {
            warn!("Invalid tx data");
            op_error::ParseError
        })?;

        let outputs = tx.get_recipients();
        assert!(!outputs.is_empty());

        let first_output = outputs
            .get(0)
            .ok_or_else(|| {
                warn!("Invalid tx: no first output");
                op_error::InvalidInput
            })?
            .as_ref()
            .ok_or_else(|| {
                warn!("Invalid tx: failed to decode first output");
                op_error::InvalidInput
            })?;

        // coerce a hash mode for this address if need be, since we'll need it when we feed this
        // address into the .pox contract
        let reward_addr = first_output.address.clone().coerce_hash_mode();

        // check if we've reached PoX disable
        if PoxConstants::has_pox_sunset(epoch_id) && block_height >= pox_sunset_ht {
            debug!(
                "StackStxOp broadcasted after sunset. Ignoring. txid={}",
                tx.txid()
            );
            return Err(op_error::InvalidInput);
        }

        Ok(StackStxOp {
            sender: sender.clone(),
            reward_addr,
            stacked_ustx: data.stacked_ustx,
            num_cycles: data.num_cycles,
            signer_key: data.signer_key,
            max_amount: data.max_amount,
            auth_id: data.auth_id,
            txid: tx.txid(),
            vtxindex: tx.vtxindex(),
            block_height,
            burn_header_hash: block_hash.clone(),
        })
    }
