### Title
Unauthorized disclosure of private-payment data via spoofed `new_shared_address` device message - (File: `wallet_defined_by_addresses.js`)

### Summary
`handleNewSharedAddress()` in `wallet_defined_by_addresses.js` accepts a `new_shared_address` message from *any* paired correspondent device and inserts arbitrary `shared_address_signing_paths` records — including an attacker-chosen `device_address` — as soon as the message's oscript definition is syntactically valid and includes one of the recipient's own addresses. The handler never checks that the sender (`from_address`) is actually a party to the definition, nor does it require the normal `create_new_shared_address` / `approve_new_shared_address` consent handshake. This lets an unprivileged paired device register itself as a "cosigner" entitled to receive private-payment forwards for an address it does not control, mirroring the GitLab flaw where a low-privilege actor could reach content (test-report data here private-payment payloads) meant only for authorized parties.

### Finding Description
The wallet message handler dispatches `new_shared_address` directly to `walletDefinedByAddresses.handleNewSharedAddress(body, callbacks)` without binding it to `from_address` at all: [1](#0-0) 

`handleNewSharedAddress` only validates that (1) the definition hashes to the claimed address, (2) each signer's address matches the path it's assigned to in the definition, and (3) every address leaf has a corresponding signer — it never validates who sent the message or requires proof that the "cosigner" devices agreed to be added: [2](#0-1) 

`determineIfIncludesMeAndRewriteDeviceAddress` only rewrites `device_address` for paths that match *my own* addresses; any other signer's `device_address` (including one supplied by the attacker) is trusted verbatim: [3](#0-2) 

The comment on the sibling function `validateAddressDefinition` even flags the missing check explicitly ("fix: 1. check that my address is referenced in the definition"), confirming this is a known-incomplete authorization gate rather than a deliberate design: [4](#0-3) 

Once accepted, `addNewSharedAddress` persists the attacker-supplied `shared_address_signing_paths` rows (including the attacker's `device_address`) and, for light clients, immediately begins watching the new shared address: [5](#0-4) 

Later, whenever a private payment chain touches that shared address (either as payer or payee), the wallet automatically forwards the full private payload (amounts, addresses, blinding factors) to every device listed in `shared_address_signing_paths` — including the attacker's injected entry — with no re-verification of authorization: [6](#0-5) [7](#0-6) 

### Impact Explanation
This is a confidentiality/access-control violation over private-payment data, directly analogous to the GitLab bug: an authenticated-but-unprivileged principal (any paired correspondent device) can silently grant itself standing "cosigner" access over an address that includes the victim's real address, and thereby receive private-payment chain contents (private asset flows: amounts, output addresses, blinding factors) that it was never authorized to see. This does not require compromising keys or brute-forcing signatures — it only exploits the missing binding between the sender of `new_shared_address` and the definition/signers being registered.

### Likelihood Explanation
The `new_shared_address` device message is processed for any correspondent (paired device) without additional authorization, and the only "cost" to the attacker is knowing (or reusing) one of the victim's already-known addresses inside a crafted multisig definition — information routinely exchanged between counterparties in the normal course of payments. No cryptographic proof of the victim's actual consent to co-own the new shared address is required before the wallet starts tracking it and forwarding future private payment data to the attacker's device.

### Recommendation
In `handleNewSharedAddress`, require that the message be linked to a prior consent flow (e.g., match against a `pending_shared_addresses`/`pending_shared_address_signing_paths` record created by `create_new_shared_address`), and validate that `from_address` corresponds to one of the `device_address` values declared for non-local signing paths in `body.signers` before persisting `shared_address_signing_paths`. Additionally, before forwarding any private payment chain in `forwardPrivateChainsToOtherMembersOfAddresses`/`forwardPrivateChainsToOtherMembersOfSharedAddresses`, re-confirm that each target `device_address` was established through an approved shared-address creation flow, not merely present in the table.

### Proof of Concept
1. Attacker is a paired correspondent device of Victim.
2. Attacker learns one of Victim's real addresses `X` (e.g., from a previous payment).
3. Attacker crafts an `arrDefinition` such as `['and', [['address', X], ['sig', {pubkey: attacker_pubkey}]]]`, computes `shared_address = chash160(arrDefinition)`, and sends a `new_shared_address` device message with `body = {address: shared_address, definition: arrDefinition, signers: {..., <attacker_path>: {address: attacker_address, device_address: attacker_device_address}}}`.
4. Victim's `handleNewSharedAddress` accepts it (since `X` is one of Victim's own addresses via `determineIfIncludesMeAndRewriteDeviceAddress`), and `addNewSharedAddress` stores `shared_address_signing_paths` with the attacker's `device_address` as a legitimate cosigner, and (if light) starts watching `shared_address`.
5. Any subsequent private payment involving `shared_address` (paid by Victim or by an unrelated third party who reuses this multisig address) is forwarded by Victim's wallet to the attacker's device via `forwardPrivateChainsToOtherMembersOfAddresses`, disclosing the private payment payload to a party the true participants never authorized.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
