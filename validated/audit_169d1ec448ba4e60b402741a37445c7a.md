**Reasoning:** The `logs` vector is hard-capped by protocol-level limit config constants `max_number_logs` (100) and `max_total_log_length` (16384 bytes), enforced in `check_can_add_a_log_message` and `checked_push_log` before any log is pushed onto the execution state. [1](#0-0) 
Each log-emitting host function (`log_utf8`, `log_utf16`, AssemblyScript `abort`) already charges `log_base` per call plus `log_byte` per byte before the log is accepted, so the cost of producing logs is fully gas-metered. [2](#0-1) [3](#0-2) 

Given the hard-coded protocol limits (100 logs, 16 KiB total), `ExecutionOutcomeView::to_hashes` can never process more than 100 `hash()` calls over at most 16384 bytes total, regardless of attacker behavior. [4](#0-3) [5](#0-4) 

This is a bounded, negligible amount of compute (hashing 16 KiB with SHA-256-class hash, 100 times) — nowhere close to "unbounded/high CPU" and dramatically smaller than typical per-chunk compute already consumed by ordinary transaction/receipt processing. There is no way for an attacker to inflate these bounds via configuration, meta-transactions, or repeated calls beyond the fixed limit, since the limits are protocol constants checked at log-emission time, not per-transaction adjustable values. The claim that "gas cost for hashing doesn't correlate with charged gas" does not establish an exploitable DoS or metering-bypass condition because the absolute cost ceiling is trivial and already dominated by the `log_base`/`log_byte` gas charges taken during execution. No panic, no unbounded growth, and no metering bypass exists here.

    pub(crate) fn check_can_add_a_log_message(&self) -> Result<()> {
        if self.logs.len() as u64 >= self.config.limit_config.max_number_logs {
            Err(HostError::NumberOfLogsExceeded { limit: self.config.limit_config.max_number_logs }
                .into())
        } else {
            Ok(())
        }
    }

    pub(crate) fn checked_push_log(&mut self, message: String) -> Result<()> {
        let len = u64::try_from(message.len()).unwrap_or(u64::MAX);
        let Some(total_log_length) = self.total_log_length.checked_add(len) else {
            return self.total_log_length_exceeded(len);
        };
        self.total_log_length = total_log_length;
        if self.total_log_length > self.config.limit_config.max_total_log_length {
            return self.total_log_length_exceeded(len);
        }
        self.logs.push(message);
        Ok(())
    }
