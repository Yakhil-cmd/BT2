### Title
Permanent market freeze from unrepresentable accrued debt value - (File: `common/src/rates/simulate.rs`)

### Summary
An unprivileged caller can permanently freeze an oversized, highly utilized market by letting debt grow until `borrowed * borrow_index` exceeds the `i128`-backed `Ray` domain. The next accrual panics in `scaled_to_original` before the borrow-index ceiling can clamp growth, and because all market operations synchronize interest first, withdrawals, repayments, liquidations, and later accrual attempts become unusable. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` computes `borrowed_original` using `scaled_to_original(env, borrowed, borrow_index)`, where `borrowed` is stored in RAY-scaled shares and the result must fit in `Ray`. [3](#0-2)  `scaled_to_original` delegates directly to `scaled.mul(env, index)`, while fixed-point multiplication raises `MathOverflow` when the represented result exceeds the numeric domain. [4](#0-3) [5](#0-4) 

The configured borrow-index ceiling does not prevent this condition because `update_borrow_index` is reached only after the potentially overflowing `borrowed_original` multiplication. [6](#0-5) [7](#0-6)  Once the stored scaled debt and current index produce an unrepresentable value, `accrue_step` panics before committing a new index, leaving the same invalid state for every subsequent attempt. [8](#0-7) 

The permissionless controller path is `update_indexes(caller, assets)`: it authenticates `caller`, resolves the pool, and forwards the supplied `Vec<HubAssetKey>` to the pool’s owner-only `update_indexes`. [9](#0-8) [10](#0-9)  The pool operation loads each selected market and invokes `interest::global_sync`, which calls the same `accrue_step` implementation used by all mutating market flows. [11](#0-10) [12](#0-11) 

### Impact Explanation
This permanently freezes all funds and debt actions for the affected `(hub_id, asset)` market. Every pool operation loads a synchronized market through `synced_market`, which calls `global_sync` before the requested action can execute. [13](#0-12)  Consequently, suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce the dangerous position, and `update_indexes` itself cannot advance the market. [14](#0-13) [10](#0-9) 

The repository’s integration test demonstrates this end state: after the accrual overflow, both withdrawal and repayment revert with `MATH_OVERFLOW`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [15](#0-14) 

### Likelihood Explanation
Creating the vulnerable state requires a very large market and sustained high utilization, so it is not reachable with ordinary balances. [16](#0-15)  However, once such a book exists within configured caps, the trigger is permissionless: any authenticated caller can submit `update_indexes` for that `HubAssetKey`, and the arithmetic failure is deterministic rather than dependent on oracle manipulation or privileged behavior. [9](#0-8) [17](#0-16) 

### Recommendation
Bound the product represented by `borrowed * borrow_index`, not only the index itself. Before accrual, compare the scaled debt and next index against a conservative representable-value limit, clamp or otherwise safely handle the accrual before entering the unrepresentable domain, and ensure repayment and withdrawal paths retain a recovery route that does not require full-market interest valuation. At minimum, reorder accrual so index clamping occurs before total-debt multiplication and add checked preconditions around `scaled_to_original` for `borrowed` and `supplied`. [18](#0-17) [19](#0-18) 

### Proof of Concept
1. Create an 18-decimal market using the steep `xlm_curve`, lift its caps in the test deployment, and supply `1_000_000_000 * 10^18` base units through the normal supply path. [20](#0-19) 
2. Borrow 98% of that market using collateral from the same harness setup, creating extremely large stored `borrowed` scaled shares. [21](#0-20) 
3. Advance ledger time and repeatedly call `Controller::update_indexes(caller, vec![HubAssetKey { hub_id, asset }])` until `borrowed * borrow_index` exceeds the `Ray`/`i128` domain. [9](#0-8) [22](#0-21) 
4. The call reverts with `MathOverflow` before `MAX_BORROW_INDEX_RAY` is reached; subsequent `withdraw` and `repay` calls also revert because they must accrue the same market first. [15](#0-14)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```
