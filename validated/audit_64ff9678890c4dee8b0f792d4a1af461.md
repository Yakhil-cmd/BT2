### Title
`GitHubApp#verify_webhook_signature` accepts unsigned webhooks when `webhook_secret` is blank - ([File: lib/shipit/github_app.rb])

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when `@webhook_secret` is blank, so any organization configured with an empty `webhook_secret` (as shown by default in `config/secrets.development.example.yml`) will accept a forged `POST /webhooks` request with no valid `X-Hub-Signature`. This is a real authentication-bypass code path, though its blast radius is bounded by which organization/config is affected and by what `PushHandler` actually does with the payload.

### Finding Description
The broken binding is: `organization.webhook_secret.present? == verify_webhook_signature(signature, message) trusted`. In `GitHubApp#verify_webhook_signature`: [1](#0-0) 

`return true unless webhook_secret` means that when the configured org has no `webhook_secret`, signature verification is skipped entirely and the request is treated as authenticated. `WebhooksController#verify_signature` resolves the `GitHubApp` purely from the attacker-controlled `repository_owner` field of the JSON body: [2](#0-1) 

If `Shipit.github(organization: 'NoSecretOrg')` resolves to a configured app whose `webhook_secret` is blank, `verify_signature` passes regardless of the `X-Hub-Signature` header, and `create` dispatches the parsed body to registered handlers such as `PushHandler`: [3](#0-2) 

`PushHandler#process`, however, only affects **stacks that already exist** in the datastore matching that repository's branch — it does not create arbitrary state for repositories Shipit doesn't already track, and it can only trigger `sync_github`, not directly run privileged deploy commands: [4](#0-3) 

Existing guards (`drop_unhandled_event`, `check_if_ping`, `GithubOrganizationUnknown` rescue) don't prevent this because they only filter by event name/known-org, not by whether the org has a secret configured. There is no additional guard requiring `webhook_secret` to be present.

### Impact Explanation
For any organization whose `webhook_secret` config value is blank/nil, an attacker who knows (or guesses) that org's login and a tracked repository/branch name can forge a `push` webhook and cause `GithubSyncJob` to be enqueued for that stack, forcing an unauthenticated resync of stack state from GitHub HEAD. This matches "unauthorized deploy/rollback trigger" adjacent behavior for that org's stacks, but only if the operator has actually left `webhook_secret` blank in production, and only reaches stacks that already exist for that org/repo. It does not let the attacker forge webhooks for correctly-configured orgs (their `webhook_secret` present, so verification proceeds normally), and doesn't cross into an org other than the one with the missing secret.

### Likelihood Explanation
This requires the deploying operator to have misconfigured a real GitHub App entry in `config/secrets.yml` (a non-test, non-example environment) with `webhook_secret` blank, which the `config/secrets.development.example.yml` template shows as the default state before it's filled in for a real app. In a correctly-configured production Shipit instance, `webhook_secret` is required to be set by the setup docs, and `docs/setup.md`/`template.rb` (out of scope per the rules, but referenced in config) emphasize configuring it. The vulnerability is real as written in `lib/shipit/github_app.rb`, but it is fundamentally a documented/known configuration-dependent behavior gap, not a bypass of code that is supposed to enforce the secret in a correctly-configured deployment.

### Recommendation
Change `verify_webhook_signature` to fail closed when `webhook_secret` is blank (`return false unless webhook_secret`), and/or add a startup-time validation that raises when a configured GitHub App is missing `webhook_secret` in non-test environments.

### Proof of Concept
```ruby
test "webhook is accepted with a bogus signature when webhook_secret is blank" do
  github_app = Shipit::GitHubApp.new('NoSecretOrg', { 'webhook_secret' => nil })
  Shipit.stubs(:github).with(organization: 'NoSecretOrg').returns(github_app)

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=garbage'

  payload = { 'ref' => 'refs/heads/master', 'after' => 'deadbeef',
              'repository' => { 'owner' => { 'login' => 'NoSecretOrg' },
                                 'full_name' => 'NoSecretOrg/victim-repo' } }.to_json

  post :create, body: payload, as: :json
  assert_response :ok # binding broken: unsigned request treated as authenticated
end
```

Note: because `config/secrets.yml`, `docs/**`, and `template.rb` are out of scope per the rules, I cannot fully confirm from in-scope files alone whether the shipped default (non-example) production config path enforces a required `webhook_secret`; this assessment is based solely on `lib/shipit/github_app.rb` and `app/controllers/shipit/webhooks_controller.rb` behavior as written.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
```

```ruby
# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
```
