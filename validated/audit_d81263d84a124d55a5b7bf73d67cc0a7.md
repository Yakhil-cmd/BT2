### Title
`fillZeroed` Reads Post-Transaction State in Fork Block, Enabling Attacker-Triggered Over-Burn of KAIA — (`blockchain/system/rebalance.go`)

---

### Summary

`RebalanceTreasury` is called inside `FinalizeState`, which runs **after** all block transactions have been applied to `statedb`. `fillZeroed` reads the live post-transaction balance of each zeroed address. Any transaction in the fork block that transfers KAIA into a zeroed address inflates `totalZeroedAmount`, causing the rebalance to zero out and permanently burn more KAIA than the governance-approved rebalance contract intended.

---

### Finding Description

The execution order in `StateProcessor.Process` is:

1. All block transactions applied to `statedb`
2. `FinalizeState` → `SystemModule.FinalizeState` → `RebalanceTreasury(state, ...)` — using the same `statedb` [1](#0-0) 

Inside `RebalanceTreasury`, `fillZeroed` reads the current live balance: [2](#0-1) 

`result.Before.Zeroed[ret]` is set to `state.GetBalance(ret)` — the balance **after** all transactions in the block have executed. If a transaction in the fork block sent KAIA to a zeroed address, that extra KAIA is included.

`totalZeroedBalance()` sums these inflated values: [3](#0-2) 

The execution phase then zeros the address (burning the extra KAIA) and computes `Burnt` from the inflated `totalZeroedAmount`: [4](#0-3) 

The `remainder = totalZeroedAmount - totalAllocatedAmount` is inflated by exactly the amount transferred into the zeroed address, and that amount is added to `result.Burnt`.

This same code path is active for both KIP-103 and KIP-160 fork blocks: [5](#0-4) 

---

### Impact Explanation

An attacker submits a value-transfer transaction in the KIP-103 or KIP-160 fork block, sending KAIA to any address registered as "zeroed" in the public `TreasuryRebalance` contract. That KAIA is:

1. **Permanently burnt** — the zeroing step sets the address balance to 0, destroying the transferred amount.
2. **Counted as governance-approved burn** — `result.Burnt` is inflated, making the total supply reduction larger than what the governance process authorized.

The total supply is permanently corrupted beyond the governance-approved rebalance amount. The memo written to the contract records an incorrect `burnt` figure.

---

### Likelihood Explanation

- The zeroed addresses are publicly readable from the `TreasuryRebalance` / `TreasuryRebalanceV2` contract before the fork block.
- The fork block number is public (chain config).
- No privileged access is required — any account with KAIA can submit the transaction.
- The attacker sacrifices their own KAIA, but the motivation is to corrupt total supply accounting or to grief the rebalance event.

---

### Recommendation

Snapshot the zeroed-address balances **before** transaction execution (e.g., in `InitializeState` at the fork block), and pass those pre-block snapshots into `fillZeroed` instead of reading from the live post-transaction `statedb`. Alternatively, validate inside `fillZeroed` that the balance of each zeroed address has not changed since the block's parent state root.

---

### Proof of Concept

1. Identify the KIP-103 (or KIP-160) fork block number `F` and the list of zeroed addresses from the public contract.
2. Construct a signed value-transfer transaction sending `X` KAIA to zeroed address `Z`, with a nonce valid at block `F`.
3. Submit the transaction so it is included in block `F` before `FinalizeState` runs.
4. After block `F` is processed, observe:
   - `state.GetBalance(Z) == 0` (the `X` KAIA is gone).
   - `rebalanceResult.Burnt` equals the governance-intended burn amount **plus** `X`.
   - The total supply is reduced by `X` more than the rebalance contract authorized.

The assertion `result.Burnt == intendedBurnt + X` confirms the over-burn.

func (result *rebalanceResult) fillZeroed(contract RebalanceCaller, state *state.StateDB) error {
	numRetiredBigInt, err := contract.GetZeroedCount(nil)
	if err != nil {
		logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
		return err
	}

	for i := 0; i < int(numRetiredBigInt.Int64()); i++ {
		ret, err := contract.Zeroeds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Zeroeds from TreasuryRebalance contract", "err", err)
			return err
		}
		result.Before.Zeroed[ret] = state.GetBalance(ret)
		result.After.Zeroed[ret] = state.GetBalance(ret) // will be set as zero if rebalance succeeds
	}
	return nil
}
