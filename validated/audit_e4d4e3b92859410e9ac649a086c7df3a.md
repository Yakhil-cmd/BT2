### Title
Non-ancestor HEAD advance (amend/rebase/reset) causes committed dangerous changes to drop from the v2 review set and be silently baked into the next baseline - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` only folds committed changes into the reviewed set when `HEAD` advanced as a strict linear descendant of `head_at_capture` (checked via `_is_ancestor`). Ordinary git operations that move `HEAD` non-linearly — `git commit --amend`, `git rebase`, `git reset --hard` followed by re-commit, etc. — cause the committed dangerous content to be excluded from `dirty_now`, which is then intersected with `changed_since` and produces an empty/incomplete review set even though the content differs from the baseline. The next `UserPromptSubmit` (`save_baseline_sha` via `handle_user_prompt_submit`) then re-captures a baseline off the current (already-dangerous) tree, permanently absorbing the unreviewed change as "old."

### Finding Description
The review-set computation lives in `compute_v2_review_set`: [1](#0-0) 
This only unions in `head_at_capture..HEAD` commits when `_is_ancestor(repo, head_at_capture, current_head)` is true. `_is_ancestor` uses `git merge-base --is-ancestor`: [2](#0-1) 
`git commit --amend` produces a new commit object with the same parent as the old `HEAD`; the old `HEAD` (i.e. `head_at_capture`) is a sibling, not an ancestor, of the amended commit. `_is_ancestor` therefore returns `False`, so the amended commit's changed files never get added to `dirty_now`. Since the working tree is clean after the amend, `git status --porcelain` (feeding `tracked_dirty`/`untracked`) also reports nothing, so `dirty_now` is empty for that file.

The final review set is: [3](#0-2) 
Even though `changed_since` (diff against `baseline_sha`) would correctly show the dangerous file as changed, the intersection with the empty/incomplete `dirty_now` drops it — `review_set = dirty_now & changed_since` silently loses the file instead of surfacing it.

At the next `UserPromptSubmit`, `handle_user_prompt_submit` calls `capture_git_baseline` and `save_baseline_sha`, which snapshots the *current* tree (now containing the unreviewed dangerous amend) as the new baseline: [4](#0-3) [5](#0-4) 
The preservation guard only fires when `touched_paths` is non-empty; a Stop hook that ran and returned an (incorrectly) empty review set clears `touched_paths` via `consume_stop_state`, so the guard does not activate and the baseline moves forward past the dangerous content permanently. From that point on, the dangerous code is part of "baseline" and will never appear in any future diff-based review for that session — it is treated as pre-existing/old code.

This breaks the stated invariant that the review set must stay bound to the right repo, baseline, and touched paths: the review set desyncs from the true baseline‑to‑HEAD content delta whenever HEAD moves non-linearly.

### Impact Explanation
This is a logic-level bypass of a required security guard: a dangerous code change introduced via a normal, unprivileged git operation (amend/rebase/reset performed by the agent or an attacker-influenced workflow) is never sent to the Stop-hook LLM review and is subsequently absorbed into the trusted baseline, so it is permanently excluded from all future reviews in that session. This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — the plugin's core security control (mandatory diff review of Claude-authored changes) can be silently defeated without any privilege beyond normal repository/git operations.

### Likelihood Explanation
No special privileges, credentials, or social engineering are required — only the ability to run `git commit --amend`, `git rebase`, or `git reset` followed by a commit inside the working session, which are ordinary developer/agent operations that Claude Code routinely performs when "fixing up" a commit message or squashing work. The condition (`head_at_capture` not an ancestor of `HEAD`) is trivially and repeatably true for any amend, and the bug is deterministic, not racy — every amend during a turn reproduces it.

### Recommendation
Don't gate the committed-changes inclusion solely on strict ancestor/linear-history checks. When `current_head != head_at_capture`, always union in `_git_name_only(repo, head_at_capture)` (a full diff against the pre-turn HEAD) regardless of ancestry, and set `diff_base` to `head_at_capture` whenever HEAD moved at all (not just on fast-forward). This ensures amended/rebased/reset commits are still compared against the pre-turn state rather than silently falling out when `git status` shows a clean tree.

### Proof of Concept
Integration test in the spirit of the existing `compute_v2_review_set` test suite:
1. Init a repo, commit `app.py` with benign content, capture `head_at_capture = HEAD_0` and `baseline_sha = stash_create()` (clean tree → equals `HEAD_0`).
2. Simulate a turn: edit `app.py` to add `os.system(user_input)` (a dangerous sink), then `git commit -m "wip"`, then `git commit --amend -m "final"`.
3. Call `compute_v2_review_set(cwd, baseline_sha=HEAD_0, head_at_capture=HEAD_0)`.
4. Assert current failing behavior: `_is_ancestor(HEAD_0, amended_HEAD)` is `False`; `dirty_now` is empty (`git status --porcelain` clean); `review_set` does **not** contain `app.py` even though `changed_since` (`git diff --name-only HEAD_0`) does contain it.
5. Assert this violates the invariant: expected `review_set` should contain `app.py` (the dangerous file) but does not — confirming the bypass.
6. Regression assertion for the fix: after patching to union `head_at_capture..HEAD`/`_git_name_only(repo, head_at_capture)` unconditionally when `current_head != head_at_capture`, re-run and assert `app.py` is present in the resulting `review_paths`.

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
