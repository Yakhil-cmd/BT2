### Title
`compute_v2_review_set` drops amended-commit changes from the Stop-hook review set, silently skipping dangerous code review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the Stop-hook's review set as `dirty_now ∩ changed_since_baseline`, and only unions in commits made this turn when `head_at_capture` is a strict git ancestor of the current HEAD. A `git commit --amend` breaks that ancestor relationship (the amended commit is a sibling of the pre-amend commit, sharing the same parent, not its descendant), so the commit-union branch never fires and `dirty_now` ends up empty once the amend leaves the worktree clean. Intersecting an empty `dirty_now` with a non-empty `changed_since` yields an empty review set even though the amended content genuinely differs from the pre-turn baseline.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is invoked from `handle_user_prompt_submit` in `security_reminder_hook.py:446-515` on every `UserPromptSubmit`, storing a `git stash create` SHA as `baseline_sha` and the current `HEAD` as `head_at_capture` [1](#0-0) .

At Stop, `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) derives the review set as:
```
review_set = dirty_now ∩ changed_since_baseline   (fallback: dirty_now alone)
```
where `dirty_now` is `git status --porcelain` output, extended with commits-since-capture **only if** `head_at_capture` is a `merge-base --is-ancestor` of the current HEAD [2](#0-1) .

`git commit --amend` replaces `HEAD` with a new commit sharing the *same parent* as the pre-amend commit — the pre-amend commit is not reachable from (not an ancestor of) the amended commit, so `_is_ancestor(repo, head_at_capture, current_head)` returns `False` [3](#0-2) . Consequently the `dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD")` union never executes, `diff_base` stays `"HEAD"`, and after a clean amend `git status --porcelain` reports nothing dirty, so `dirty_now` is the empty set. Meanwhile `changed_since = _git_name_only(repo, baseline_sha)` (diff of the worktree against the pre-turn stash snapshot) correctly contains the amended file, since the file's committed content differs from the baseline snapshot [4](#0-3) . Intersecting `∅ ∩ {file}` yields `review_set = ∅`, silently excluding the dangerous change from the Stop-hook review — breaking the stated invariant that the review set must stay bound to the actual touched content.

This is reachable via ordinary, unprivileged git operations (`git commit`, then `git commit --amend`) executed inside the session's normal Bash tool use — no elevated access or repo/baseline tampering beyond standard git commands is required.

Mitigating factor: the separate commit-review path (`handle_commit_review_posttooluse` in `security_reminder_hook.py`) independently detects `git commit --amend` via `_GIT_COMMIT_RE`/`_resolve_amend_pre_sha` (`security_reminder_hook.py:517-573`) and reviews the amend diff against the correct pre-amend SHA via the reflog. When `ENABLE_COMMIT_REVIEW` is enabled (the default), that layer catches what `compute_v2_review_set` misses. The gap is only fully exploitable when commit review is disabled (`ENABLE_COMMIT_REVIEW=0`) while the Stop-hook diff review (`ENABLE_STOP_REVIEW=1`) remains the sole safety net, or in any future refactor that relies on `compute_v2_review_set` alone.

### Impact Explanation
When commit review is disabled and Stop-hook review is the only active gate, an amend during a turn causes the review set to be empty, so the LLM-based vulnerability scan never sees the dangerous diff. This lets attacker-influenced, dangerous code changes (e.g., injected via prompt content that drives Claude to run `git commit && git commit --amend`) pass through without triggering the `exit(2)` review-forcing behavior — a local security-control bypass of the plugin's approval/deny-guidance mechanism, matching "Unauthorized local command execution / control bypass" class impact, though scoped to the security-guidance review layer rather than Claude Code's core approval system.

### Likelihood Explanation
Preconditions: (1) the security-guidance plugin's Stop-hook review is relied upon without the compensating commit-review hook (`ENABLE_COMMIT_REVIEW=0`, a supported, documented configuration — see `security_reminder_hook.py:151-161`), and (2) the session performs a `git commit --amend` (a completely ordinary git operation Claude routinely runs when fixing up a commit message or amending in place). No special privileges, timing races, or malicious tooling are needed — this is deterministic given the config and the amend sequence, and is reproducible on every occurrence of an amend that leaves the tree clean.

### Recommendation
In `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py`), do not gate the commits-since-capture union strictly on `_is_ancestor`. Detect an amend (e.g., current HEAD's parent equals `head_at_capture`'s parent, or reflog subject `commit (amend)`) and, in that case, union in the file list from `git diff head_at_capture..HEAD` (or `git diff head_at_capture HEAD` treating them as unrelated trees) rather than relying on ancestor-only linear history. Alternatively, always union `changed_since` results directly into the review set when `head_at_capture != current_head`, instead of intersecting with a `dirty_now` that can go empty after a commit/amend.

### Proof of Concept
Unit test against `compute_v2_review_set` (mirroring existing test patterns in the plugin's test suite for `diffstate.py`):
1. Init a temp git repo, commit an initial file, capture `baseline_sha = capture_git_baseline(cwd)` and `head_at_capture = git rev-parse HEAD`.
2. Modify `dangerous.py` with unsafe code, `git add`, `git commit -m "wip"`.
3. Run `git commit --amend --no-edit` (no further changes) — HEAD now points to a new commit sharing the original parent, `dangerous.py`'s new content is only in the amended commit.
4. Call `review_paths, diff_base, repo, untracked, metrics = compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert: `dangerous.py` (absolute path) is present in `review_paths`. Expected/actual: the assertion fails — `review_paths` is empty because `dirty_now` is empty and intersects to `∅`, demonstrating the dangerous file drops out of the review set despite being new since baseline.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
