### Title
Webhook signature verification keys off `repository.owner.login` while the target Stack is resolved from the independent, attacker-controlled `repository.full_name` field, allowing cross-repository writes - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to validate a webhook using `repository_owner`, taken from `params.dig('repository', 'owner', 'login')` (or `organization.login`), and only checks that the signature matches that organization's `webhook_secret`. Downstream, `Shipit::Webhooks::Handlers::Handler#stacks` resolves the target `Repository`/`Stack` using a *different* JSON field, `payload.dig('repository', 'full_name')`. These two fields are independently attacker-controlled in the raw JSON body and are never cross-checked against each other.

### Finding Description
The binding that should hold is: **organization whose secret authenticated the request == organization owning the repository that gets written to**. In this engine that equality is never enforced.

- `verify_signature` in [1](#0-0)  computes `repository_owner` from the payload and fetches `Shipit.github(organization: repository_owner)` to get that org's `webhook_secret`, then calls `github_app.verify_webhook_signature(signature, request.raw_post)`.
- `GithubApp#verify_webhook_signature` in [2](#0-1)  just checks the HMAC-SHA1 of the *entire raw body* against the secret for whichever organization was resolved above — it proves "whoever signed this body knows organization X's secret," nothing more.
- The actual target of the webhook is computed separately, using `payload.dig('repository', 'full_name')`, in `Handler#repository_name` / `#stacks` at [3](#0-2) , which is then resolved to a `Repository`/`Stack` via `Repository.from_github_repo_name` in [4](#0-3) .
- `repository.owner.login` and `repository.full_name` are two independent strings inside the same attacker-supplied JSON payload (see the fixture at [5](#0-4) , where `owner.login` and `full_name`'s owner segment happen to match, but nothing enforces that).

Any actor who has installed the Shipit-integrated GitHub App on **their own** organization (e.g. by being an admin of some unrelated org, or via any deployment where the app is installed on multiple orgs, as documented for the "Using Multiple GitHub Applications" feature in [6](#0-5) ) knows their own org's `webhook_secret`. They can craft an arbitrary webhook body where:
- `repository.owner.login` = `"attacker-org"` (used only for secret selection/signature check), and
- `repository.full_name` = `"victim-org/victim-repo"` (used to select the Stack that gets mutated).

Since they know `attacker-org`'s secret, they can produce a valid `X-Hub-Signature` over the full crafted body. `verify_signature` passes because it only validates that the signer knows `attacker-org`'s secret — it never confirms that `attacker-org` actually owns `victim-org/victim-repo`. The event is then dispatched to handlers that trust `repository.full_name` unconditionally, e.g.:
- `PushHandler#process` in [7](#0-6)  calls `stack.sync_github(expected_head_sha: params.after)` for any stack matching the forged `full_name`.
- `StatusHandler#process` in [8](#0-7)  creates a GitHub `status` (e.g. `state: success`) on commits matched purely by `sha`, with no repository/org ownership check at all beyond the mis-scoped signature check.

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" binding called out in scope. Concretely, an attacker controlling one org's webhook secret can forge `status` events that mark arbitrary commits on a victim's stack as `success`, and forge `push` events that trigger `GithubSyncJob`/`sync_github` against a victim's stack — both without any credentials for the victim's repository or organization. If the victim stack has continuous deployment enabled and CI requirements are satisfied purely by forged `status` webhooks, this can lead to an **unauthorized deploy** being triggered on the victim's stack, which meets the High/Critical bar (unauthorized deploy) defined in scope.

### Likelihood Explanation
Requires the attacker to control the webhook secret of at least one organization for which the shared Shipit deployment is configured (a normal, low-privilege scenario in multi-org Shipit installs, which is an explicitly documented and supported configuration). No access to the victim's GitHub org, Shipit session, or API client token is needed — only knowledge of one's own org's webhook secret and the ability to POST to the public `/github/webhooks` (or engine-mounted) endpoint.

### Recommendation
After selecting the organization's secret for signature verification, cross-validate that the resolved `repository_owner` organization actually matches the owner segment of `repository.full_name` (and, more robustly, verify that the resolved `Repository`/`Stack`'s configured GitHub organization corresponds to the organization whose secret validated the signature) before dispatching to any handler that mutates state (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, etc.).

### Proof of Concept
1. Attacker is an admin of `attacker-org`, which has the Shipit GitHub App installed with a known `webhook_secret` (a supported multi-org configuration per `docs/setup.md`).
2. Attacker crafts a `status` webhook JSON body: `repository.owner.login = "attacker-org"`, `repository.full_name = "victim-org/victim-repo"`, `sha = "<victim commit sha>"`, `state = "success"`.
3. Attacker computes `X-Hub-Signature: sha1=HMAC-SHA1(attacker-org secret, body)` and POSTs to the webhooks endpoint with `X-Github-Event: status`.
4. `verify_signature` resolves `Shipit.github(organization: "attacker-org")` and validates the signature successfully (per `GithubApp#verify_webhook_signature`).
5. `StatusHandler#process` finds the real `Commit` by `sha` on `victim-org/victim-repo`'s stack and creates a `success` status, potentially unblocking deploys, despite the attacker having no relationship to `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
