### Title
Unvalidated `creator` account in `initialize_with_permission` allows `pool_creator` to be set to the zero address (or any uncontrolled address), permanently freezing creator fees - (File: `programs/cp-swap/src/instructions/initialize_with_permission.rs`)

### Summary
`initialize_with_permission` accepts a `creator` account with no ownership, signer, or non-default-address check and stores its raw pubkey directly as `PoolState.pool_creator`. Because creator-fee withdrawal paths gate on this stored address, a permissioned pool creator can set it to `Pubkey::default()` (or any address nobody controls), permanently locking all accrued creator fees for that pool.

### Finding Description
In `InitializeWithPermission`, the `creator` field is declared as a bare `UncheckedAccount` with only a doc comment (`/// CHECK: creator of pool`) and no Anchor constraint at all: [1](#0-0) 

Unlike `payer` (which is required to be the transaction `Signer`), `creator` is never checked to be non-zero, to be a signer, or to be controlled by anyone. Its raw key is passed straight into `pool_state.initialize(...)` and persisted as `pool_creator`: [2](#0-1) 

This differs from the non-permissioned `initialize` instruction, where the pool creator is the transaction `Signer` itself and thus cannot practically be a zero/uncontrolled address.

The stored `pool_creator` is later used as the sole authorization gate for the creator-fee-collection instructions:
- `collect_creator_fee` requires the `creator` signer's address to equal `pool_state.pool_creator`: [3](#0-2) 
- `collect_creator_fee_permissionless` sends the accrued fees to an ATA whose authority is `pool_state.pool_creator`, with `creator` again unchecked beyond an `address` constraint: [4](#0-3) 

If `pool_creator` is set to `Pubkey::default()` (or any address with no known private key), nobody can ever sign as `creator` in `collect_creator_fee`, and the `collect_creator_fee_permissionless` path will forever route fees into a token account owned by that unreachable address.

### Impact Explanation
Creator fees accrue in `PoolState.creator_fees_token_0` / `creator_fees_token_1` on every swap (per the trade-fee split logic) and are only recoverable via `collect_creator_fee`/`collect_creator_fee_permissionless`. Setting `pool_creator` to the zero address (or any uncontrolled address) at pool-creation time permanently freezes 100% of the pool's future creator-fee revenue — funds are moved out of the vault into an ATA that no private key can ever authorize spending from, meeting the "permanent freezing of user/LP funds" bar for Medium/High severity.

### Likelihood Explanation
`initialize_with_permission` is reachable by any account holding a valid `Permission` PDA (permissioned pool creators), who fully controls all instruction data including the `creator` account. Passing `Pubkey::default()` (or any burn address) as `creator` requires no special privilege beyond what is already needed to call this instruction, and there is no on-chain check preventing it, making the issue trivially and reliably triggerable by that actor.

### Recommendation
Add a validation constraint on the `creator` account in `InitializeWithPermission`, e.g. `constraint = creator.key() != Pubkey::default() @ ErrorCode::InvalidCreator`, mirroring the `require_keys_neq!(new_owner, Pubkey::default())` checks already used for `protocol_owner`/`fund_owner` in `set_new_protocol_owner`/`set_new_fund_owner`: [5](#0-4) 

### Proof of Concept
1. Attacker (or any account with a valid `Permission` PDA) calls `initialize_with_permission`, supplying `payer` as their own signer but passing `creator = Pubkey::default()` (or any address they don't control).
2. `pool_state.initialize(...)` stores `pool_creator = Pubkey::default()`. [2](#0-1) 
3. Swaps against the pool accrue `creator_fees_token_0`/`creator_fees_token_1` on `PoolState` over time.
4. `collect_creator_fee` can never be called because no signer can produce the `Pubkey::default()` key. [3](#0-2) 
5. Anyone invoking `collect_creator_fee_permissionless` moves the fees into an ATA owned by `Pubkey::default()`, which is unspendable by any real key, permanently locking those funds. [6](#0-5)
