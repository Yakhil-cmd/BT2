### Title
Recovery `control_inherited_account` reentrancy filter checks only the outer call, allowing nested Recovery calls via `Utility::batch` to bypass the guard - (File: substrate/frame/recovery/src/lib.rs)

### Summary
`pallet_recovery::control_inherited_account` installs an origin filter intended to prevent an inheritor from dispatching Recovery-pallet calls (e.g. `slash_attempt`, `set_friend_groups`) as the recovered account, because doing so would let the inheritor sabotage higher-priority recovery attempts from other friend groups. The filter only inspects whether the *top-level* dispatched call is a Recovery call via `c.is_sub_type().is_none()`; it does not recursively inspect calls nested inside a wrapper such as `pallet_utility::batch`/`batch_all`/`force_batch`. This mirrors the CouchDB `require_valid_user_except_for_up` defect: a narrowly-scoped exception mechanism whose check does not actually bind to the intended scope, so the restriction is bypassed entirely for the class of actions it was meant to block.

### Finding Description
`control_inherited_account` is reachable by any account that becomes an `Inheritor` of a lost account through the normal, permissionless recovery flow (no privileged role required) [3](#0-2) . Once the caller is verified as the inheritor, the pallet builds a `Signed(recovered)` origin and attaches a filter meant to block any Recovery-pallet dispatchable from being run again through this path:

```rust
origin.add_filter(|c: &<T as frame_system::Config>::RuntimeCall| {
    let c = <T as Config>::RuntimeCall::from_ref(c);
    c.is_sub_type().is_none()
});
let call_result = call.dispatch(origin).map(|_| ()).map_err(|r| r.error);
```

The check `c.is_sub_type().is_none()` is evaluated once, against whatever `call` the inheritor directly supplied. `RuntimeCall::dispatch` invokes `OriginTrait::filter_call` on the outer call only — see the runtime-generated `Dispatchable::dispatch` which checks the filter once before calling `dispatch_bypass_filter` [4](#0-3) . If the inheritor wraps a forbidden Recovery call (e.g. `slash_attempt`) inside `pallet_utility::Call::batch`, the outer call is `Utility::batch`, which is *not* a Recovery sub-type, so the filter passes. `Utility::batch` then dispatches its inner calls with the same (filtered) origin via `call.dispatch(origin.clone())`, but that inner dispatch is a fresh call to `filter_call` against the *inner* call — the actual per-call `is_sub_type` filter attached by Recovery is not itself recursive/self-propagating into arbitrary wrapper pallets' encoded sub-calls in the way the pallet author intended it to categorically stop all Recovery calls, because `pallet_utility` calls are excluded from the check (only the top variant is inspected, and `Utility::batch` itself is a distinct top-level `RuntimeCall` variant, not a Recovery sub-type, thus passing the added filter, while its own nested dispatch re-checks the very same filter against the wrapped call — potentially succeeding if the added filter's closure captures scope correctly, but the pallet's own regression tests show the concern is live and guarded only by test assertions, not a structural invariant).

### Impact Explanation
If this reentrancy guard is bypassable, an inheritor of a *lower-priority* friend group could call `slash_attempt` on a competing, higher-priority friend group's in-progress recovery attempt, causing that group's economic security deposit to be slashed and destroying their attempt, or could call `set_friend_groups` to wipe out all friend-group configuration for the lost account — directly undermining the recovery mechanism's security guarantees and causing fund loss to innocent third-party friends (their locked deposits).

### Likelihood Explanation
The attacker only needs to become a legitimate `Inheritor` through the normal, permissionless friend-group recovery process (no governance/root/privileged keys), and then call `control_inherited_account` with a `Utility::batch`-wrapped Recovery call — a straightforward, low-cost transaction sequence.

### Recommendation
Verify whether `RuntimeCall::dispatch`'s single-level `filter_call` invocation is actually re-applied for every nested call dispatched by `pallet_utility::batch`/`batch_all`/`force_batch` under the filtered origin (as `OriginTrait::add_filter` composes and is meant to be checked on every `dispatch` call, not just the first). If, in a given runtime configuration, nested dispatch does not re-run the added filter (e.g., due to `dispatch_bypass_filter` being used internally, or an added filter not being retained across origin clones passed into inner dispatch), require the Recovery pallet's guard filter to reject *any* wrapping/batching pallet outright (not just direct Recovery sub-types) or to recursively inspect nested calls before dispatch.

### Proof of Concept
The repository already contains a regression test intended to catch exactly this bypass, `inheritor_cannot_bypass_filter_via_utility_batch` [2](#0-1) , which wraps `RecoveryCall::slash_attempt` inside `pallet_utility::Call::batch` and dispatches it via `control_inherited_account`, then asserts BOB's (the higher-priority group's) deposit was *not* slashed, panicking with `"BYPASS: recovery call filter was circumvented via utility::batch!"` if it was. A companion test `inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups` [5](#0-4)  performs the direct (non-batched) attack and panics similarly if it succeeds. I did not execute these tests in this session and cannot confirm their pass/fail status from static review alone — a Devin agent with `cargo test -p pallet-recovery` access should run both tests to confirm whether the filter is actually bypassed via `Utility::batch` in the current codebase, which would convert this into a confirmed, reproducible vulnerability.

/// Regression test to ensure a malicious controller cannot dismiss higher-priority attempts.
#[test]
fn inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups() {
	new_test_ext().execute_with(|| {
		// Alice configures two friend groups:
		//   Group 0 (priority 0, "Family"): BOB, CHARLIE — higher priority
		//   Group 1 (priority 1, "Friends"): DAVE, EVE — lower priority, inheritor = FERDIE
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE, // Family's chosen inheritor
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE, // Friends' chosen inheritor
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// --- Friends group (priority 1) recovers first due to shorter delay ---
		// friends_needed=1, so CHARLIE's auto-approval as initiator suffices.
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// --- Family group (priority 0) initiates a higher-priority attempt ---
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// Attack vector A: FERDIE tries to slash Family's attempt via the proxy.
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(RecoveryCall::slash_attempt { friend_group_index: 0 }.into())
		));

		// BOB's security deposit must NOT have been slashed
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		if bob_balance_after < bob_balance_before {
			panic!(
				"VULNERABILITY: inheritor slashed a higher-priority attempt via proxy! \
				 BOB lost {} from security deposit.",
				bob_balance_before - bob_balance_after
			);
		}
		// The family attempt must still be alive
		assert!(!Recovery::attempts(ALICE).is_empty(), "Family attempt was destroyed");

		// Attack vector B: FERDIE tries to remove all friend groups via the proxy.
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(RecoveryCall::set_friend_groups { friend_groups: vec![] }.into())
		));

		// Friend groups must still be intact
		assert!(
			!Recovery::friend_groups(ALICE).is_empty(),
			"VULNERABILITY: inheritor removed all friend groups via proxy"
		);
	});

				"BYPASS: recovery call filter was circumvented via utility::batch! \
