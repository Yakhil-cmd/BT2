### Title
Stale secondary oracle observation can inflate collateral and enable undercollateralized borrowing - ([File: contracts/price-aggregator/src/engine.rs](contracts/price-aggregator/src/engine.rs))

### Summary
A dual-source price can blend a fresh primary observation with a much older secondary observation when the secondary is still inside its own staleness limit. An attacker can supply the affected asset and call `Controller::borrow` while the midpoint remains inflated, borrowing more than the fresh market price supports and leaving the pool with bad debt.

### Finding Description
The aggregator stores each source leg’s price, timestamp, staleness flag, and `FeedNature` before constructing a combined `Outcome`; `Outcome::failure` rejects the resolved result only for resolution errors, a stale aggregate flag, deviation, a nonpositive price, or sanity-band violation. [1](#0-0) [2](#0-1)  The intended validation includes a bound on the age spread between two market legs, but anchor-style feeds are handled as a distinct feed nature. [3](#0-2) [1](#0-0) 

The in-repository security regression demonstrates the reachable condition: the Reflector leg is updated to a fresh `$0.91` XLM price while the RedStone leg retains a `$1.00` observation from `82,800` seconds earlier, below its configured `86,400`-second staleness limit. [4](#0-3)  With a 10% tolerance, the `$1.00` stale leg and `$0.91` fresh leg remain within the configured band, so the midpoint inflates the collateral valuation by more than 4%. [5](#0-4)  The attacker then enters through `borrow(caller, account_id, borrows, to)`, which authorizes the caller and releases the borrowed assets to the requested recipient after valuation-dependent checks pass. [6](#0-5) 

### Impact Explanation
This permits theft of user funds through protocol insolvency. In the regression scenario, an attacker supplies `100,000 XLM` and borrows `$70,000` of USDC; the fresh-price control run rejects the identical borrow with `INSUFFICIENT_COLLATERAL`, while the stale-anchor run succeeds. [7](#0-6) [8](#0-7)  Once the stale leg is refreshed or removed, the minted debt remains against collateral valued below the amount withdrawn, transferring the shortfall to suppliers or requiring bad-debt socialization.

### Likelihood Explanation
The attacker does not need an oracle key or privileged role: they can monitor an adapter whose accepted secondary observation has become old relative to the primary feed, open or reuse an account, supply the affected collateral, and submit a normal signed `borrow`. [6](#0-5)  Exploitation requires a stale-but-individually-valid secondary feed whose price stays inside tolerance; oracle outages or delayed publishing create that window, while tightly synchronized feeds prevent it.

### Recommendation
Apply the cross-leg timestamp consistency check to every dual-source resolution, including anchor-nature feeds, or bound the secondary leg’s age relative to both ledger time and the primary observation. If either leg exceeds the configured age spread, mark the outcome stale or unsafe so `Outcome::failure` rejects it before valuation. [2](#0-1)  The maximum permitted leg-age spread should also be materially smaller than the source disagreement tolerance’s ability to move the midpoint.

### Proof of Concept
1. Configure XLM with a fresh Reflector primary and a RedStone secondary anchor with `max_stale_seconds = 86,400` and tolerance `1,000` bps. [9](#0-8) 
2. Publish a fresh Reflector observation at `$0.91`; leave the RedStone observation at `$1.00` with timestamp `now - 82,800` seconds. [4](#0-3) 
3. Attacker calls `supply(attacker, 0, spoke_id, [(XLM, 100_000)])`, receives account id `A`.
4. Attacker calls `borrow(attacker, A, [(USDC, 70_000)], Some(attacker))`.
5. The stale-anchor transaction succeeds and pays USDC to the attacker; the same call with a fresh `$0.91` secondary reverts with `INSUFFICIENT_COLLATERAL`. [10](#0-9)

    /// any. Checks, in order: an error already carried on the outcome, a missing
    /// oracle, staleness, deviation, a non-positive price, and the oracle's
    /// sanity price bounds. Returns `None` when none of these apply.
    fn failure(&self, oracle: Option<&AssetOracle>) -> Option<OracleError> {
        if let Some(err) = self.err {
            return Some(err);
        }
        let Some(oracle) = oracle else {
            return Some(OracleError::OracleNotConfigured);
        };
        if self.stale {
            return Some(OracleError::PriceFeedStale);
        }
        if self.deviation {
            return Some(OracleError::UnsafePriceNotAllowed);
        }
        if self.price_wad <= 0 {
            return Some(OracleError::InvalidPrice);
        }
        if self.price_wad < oracle.min_sanity_price_wad
            || self.price_wad > oracle.max_sanity_price_wad
        {
            return Some(OracleError::SanityBoundViolated);
        }
        None
