## Title
Cross-organization webhook forgery via mismatched signature-org and payload-repository binding - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to validate the request signature against based on `repository_owner`, a value read directly out of the untrusted JSON body (`repository.owner.login` or `organization.login`). The handlers that actually act on the payload (`Shipit::Webhooks::Handlers::Handler#repository_name`) instead key off a *different* field of the same body, `repository.full_name`. Nothing ties these two fields together, so in a multi-organization Shipit deployment, an operator who legitimately controls Org A's GitHub App (and therefore knows Org A's `webhook_secret`) can sign a payload whose `repository.owner.login`/`organization.login` is `"OrgA"` (to pass signature verification) while `repository.full_name` claims a repository belonging to `"OrgB"`.

### Finding Description
`app/controllers/shipit/webhooks_controller.rb:24-30` computes:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where `repository_owner` (lines 59-62) is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` — fully attacker-controlled JSON content, not derived from any authenticated source. `Shipit.github(organization:)` (`lib/shipit.rb:170-181`) looks up per-org config, and each org has its own independent `webhook_secret` (`lib/shipit/github_app.rb:44-57`, illustrated by `test/dummy/config/secrets_double_github_app.yml` and `docs/setup.md` "Using Multiple GitHub Applications").

Once `verify_signature` passes, `create` (`app/controllers/shipit/webhooks_controller.rb:10-15`) dispatches the *entire* raw payload to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. Every handler resolves its target `Repository`/`Stack` using `payload.dig('repository', 'full_name')` (`app/models/shipit/webhooks/handlers/handler.rb:33-38`, reused by `PushHandler`, `pull_request/*_handler.rb`, etc.) — a field that is never cross-checked against `repository_owner`/the org whose secret validated the signature.

Because the HMAC is computed over the whole raw body, this is not a "missing field coverage" bug in the cryptographic sense — the attacker must be able to produce a valid signature over their crafted body. But since each org in a multi-org Shipit install has its own independently-configured `webhook_secret`, an admin of Org A (an unprivileged party with respect to Org B) knows Org A's secret and can self-sign an arbitrary payload with `repository.owner.login: "OrgA"` while setting `repository.full_name: "OrgB/victim-repo"`. The check binds "organization authenticated" (Org A, via its own secret) to a completely different value: "repository written" (OrgB's repo, acted on by the handler).

### Impact Explanation
This breaks the deployment-trust binding between the authenticated organization and the repository actually operated on, enabling cross-repository/cross-organization actions: e.g. `PushHandler#process` (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`) will call `stack.sync_github(expected_head_sha: params.after)` on OrgB's stacks; pull-request handlers can archive/unarchive/provision OrgB's review stacks (`app/models/shipit/webhooks/handlers/pull_request/*_handler.rb`). This is an unauthorized cross-repository write triggered by an entity that only legitimately controls a different, unrelated organization's GitHub App — matching the Critical "cross-repository writes" impact bucket.

### Likelihood Explanation
Requires a Shipit deployment configured with multiple GitHub organizations sharing one instance (explicitly documented and supported, `docs/setup.md` "Using Multiple GitHub Applications"), and requires the attacker to control (be an admin of) at least one of the configured orgs — a realistic multi-tenant scenario, not requiring compromise of the target org.

### Recommendation
In `WebhooksController#verify_signature` / the handler base class, validate that `repository.owner.login` (used to select the signing org) matches the owner segment of `repository.full_name` (used by handlers to select the target repository/stack) before dispatching to handlers, rejecting any payload where they diverge.

### Proof of Concept
1. Deploy Shipit with two orgs configured, `OrgA` and `OrgB`, each with distinct `webhook_secret`s (per `docs/setup.md` multi-org config).
2. As the admin of `OrgA` (who legitimately knows `OrgA`'s webhook secret), craft a `push` payload:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker chosen sha>",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" }
}
```
3. Sign it with `OrgA`'s `webhook_secret` using the same HMAC-SHA1 scheme as `Hook::DeliverySigner`/`GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`), and send it to `POST /github/webhooks` with `X-Github-Event: push` and the computed `X-Hub-Signature`.
4. `verify_signature` resolves `Shipit.github(organization: 'OrgA')` and validates successfully against `OrgA`'s secret.
5. `PushHandler` resolves the target via `payload.dig('repository', 'full_name')` = `"OrgB/victim-repo"` and triggers `sync_github` on `OrgB`'s stack, despite the attacker having no legitimate relationship to `OrgB`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end
