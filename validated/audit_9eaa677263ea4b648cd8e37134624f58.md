### Title
Unbounded pagination loop driven entirely by attacker-controlled `Link` header allows resource-exhaustion DoS - (File: pkg/cmd/run/shared/artifacts.go)

### Summary
`ListArtifacts` fetches workflow-run artifacts from the GitHub REST API in a `for {}` loop with no upper bound on the number of iterations or on the size of the accumulated `results` slice. The loop's only exit condition is that the server-returned `Link` response header contains no `rel="next"` entry.

### Finding Description
`ListArtifacts` builds an initial request URL and then loops indefinitely, appending every page's `Artifacts` to `results` and re-issuing a request against whatever `nextURL` the server supplies via `findNextPage`: [1](#0-0) 

There is no caller-supplied `limit`, no cap on total items collected, and no cap on the number of loop iterations — termination depends entirely on the remote host eventually returning a response without a `next` link. `findNextPage` simply regex-extracts whatever URL appears in the `Link` header and hands it straight back into `safeurl.NewImmutableSafeURL(nextURL)` for the next request, with no validation that it terminates or is well-formed beyond basic parsing, matching the pattern documented for `ImmutableSafeURL` (trusted-source assumption only): [2](#0-1) 

This is functionally the same bug class as the Visor Finance report: an attacker who controls the responding host (e.g. a malicious/compromised GitHub Enterprise Server instance, or any endpoint `gh` is configured to talk to) can keep the loop alive forever by always returning a `Link: <url>; rel="next"` header — optionally pointing back to itself or to an ever-growing chain of pages — causing `gh` to keep issuing requests and appending data to an unbounded, dynamically-growing slice, exactly analogous to the unbounded iteration over dynamically sized arrays/sets flagged in the Solidity report.

Other pagination helpers in the codebase (`ListCodespaces`, `ListDevContainers`, `lister.List`, GraphQL `listLabels`/`listOrgs`/issue list) mitigate this by checking `len(results) >= limit` on every iteration, giving the loop a caller-controlled upper bound even when the server keeps sending `next` links: [3](#0-2) [4](#0-3) 
`ListArtifacts` has no equivalent `limit`/`opts.Limit` parameter at all, so it lacks this safety net entirely.

### Impact Explanation
A malicious or compromised host that `gh` is pointed at (e.g., a self-hosted/enterprise instance, or any server the CLI is configured to trust for a given command) can force `gh run download` / `gh run view` (both consumers of `ListArtifacts`) to loop indefinitely, growing memory unboundedly and/or hanging the CLI process — a client-side denial of service. This does not require the local user to be an admin/operator of the CLI, only that they run a normal `gh` command (`run download`/`run view`) against a repo/host controlled by the attacker. [5](#0-4) 

### Likelihood Explanation
Any unprivileged attacker who can host (or has compromised) the GitHub-compatible endpoint that `gh` is configured against — a realistic scenario for GitHub Enterprise Server deployments or any custom `GH_HOST` — can trivially trigger this by returning a `Link` header with `rel="next"` on every response to the artifacts-listing endpoint. No authentication bypass or privileged access is required beyond controlling the response of an endpoint the victim already queries as part of normal `gh run download`/`gh run view` usage.

### Recommendation
Add a maximum-iteration/maximum-item cap (and/or a maximum total pages) to `ListArtifacts`, mirroring the `limit` checks already used by `ListCodespaces`, `ListDevContainers`, and the GraphQL-based `listLabels`/`listOrgs`/pr `lister.List` implementations, so the loop terminates deterministically regardless of how many `next` links a malicious or misbehaving host returns.

### Proof of Concept
1. Point `gh` at a malicious/compromised host (`GH_HOST` pointing to an attacker-controlled GHES-like server, or an attacker-controlled repo API endpoint the CLI is configured to use).
2. Have that host respond to `GET /repos/{owner}/{repo}/actions/runs/{runID}/artifacts` with a valid JSON body plus a `Link: <same-or-generated-url>; rel="next"` header on every response.
3. Run `gh run download <runID>` or `gh run view <runID>` against that host.
4. Observe `ListArtifacts` never exits its `for {}` loop in `pkg/cmd/run/shared/artifacts.go:45-57`, continuously issuing requests and growing the `results` slice, exhausting memory/network resources and hanging the CLI indefinitely.

func ListArtifacts(httpClient *http.Client, repo ghrepo.Interface, runID string) ([]Artifact, error) {
	var results []Artifact

	perPage := 100
	u, err := safeurl.JoinPath("repos", repo.RepoOwner(), repo.RepoName(), "actions", "artifacts")
	if err != nil {
		return nil, err
	}
	if runID != "" {
		u, err = safeurl.JoinPath("repos", repo.RepoOwner(), repo.RepoName(), "actions", "runs", runID, "artifacts")
		if err != nil {
			return nil, err
		}
	}
	u.SetQuery("per_page", strconv.Itoa(perPage))
	var pageURL safeurl.SafeURL = u

	// TODO(api-client-rollout)
	// This line of code is part of a mechanical roll out of the api client.
	// As a follow up, consider whether the api client can be injected to this call site, rather than constructed
	client := api.NewClientFromHTTP(httpClient)

	for {
		var payload artifactsPayload
		nextURL, err := client.RESTWithNext(repo.RepoHost(), http.MethodGet, pageURL.String(), nil, &payload)
		if err != nil {
			return nil, err
		}
		results = append(results, payload.Artifacts...)

		if nextURL == "" {
			break
		}
		pageURL = safeurl.NewImmutableSafeURL(nextURL)
	}

	return results, nil

// ImmutableSafeURL is a SafeURL that renders a fixed URL string verbatim. It exists
// so that a URL which was not built from percent-encoded components, such as a full
// URL returned by the server (a pagination "next" link, an asset download URL, and
// the like), can still flow through the SafeURL typed code paths. Because the stored
// value is rendered as given without any encoding, it is only safe to wrap a URL that
// was created from trusted components or received from a trusted source.
type ImmutableSafeURL struct {
	url string
}

// NewImmutableSafeURL returns an ImmutableSafeURL that renders url verbatim. Only pass
// a URL you built yourself from trusted components or received from a trusted source,
// such as a server response; this bypasses all percent-encoding, so passing a value
// that embeds unescaped user or third party input reintroduces the injection risk that
// SafeURL exists to prevent.
func NewImmutableSafeURL(url string) *ImmutableSafeURL {
	return &ImmutableSafeURL{url: url}
}
