### Title
Unsanitized repo.Description allows tview color-tag injection to spoof gh's own "(official)"/"(installed)" UI badges - ([File: pkg/cmd/extension/browse/browse.go])

### Summary
`gh extension browse` renders each extension's description directly from the GitHub search API (`repo.Description`) into `tview.List` items without any escaping of tview's markup syntax. Because the extension's own trust badges ("(official)"/"(installed)") are rendered using the exact same `[color]...[-]` tview markup, an attacker can craft a repo description containing tags like `[yellow](official)` to visually forge gh's own trust indicator next to their unofficial/malicious extension.

### Finding Description
`getExtensions` copies `repo.Description` (attacker-controlled, taken verbatim from the GitHub search results for repos tagged `gh-extension`) into `extEntry.description` with no sanitization: [1](#0-0) 

`extEntry.Description()` returns this string unmodified: [2](#0-1) 

It is then passed straight into `tview.List.AddItem` in both `Reset()` and `Filter()`: [3](#0-2) [4](#0-3) 

Crucially, the application itself relies on tview's dynamic-color/markup syntax (`[green]`, `[yellow]`, `[-:-:-]`, `[::b]`) to render its own trust badges for installed/official extensions: [5](#0-4) 

Since these badges are rendered through the same `tview.List` item text channel that also carries the untrusted `Description()` string, and tview interprets `[...]`-style region/color tags in list item text by default, a malicious repo owner can set `Description` to something like `A cool tool [yellow](official)[-:-:-]` (or include `[green](installed)`), causing the rendered list entry to visually display gh's own "(official)"/"(installed)" markers next to an attacker-controlled, non-official extension. There is no call to `tview.Escape()` or any stripping of `[`...`]` sequences anywhere on this path, so the untrusted field is not distinguished from gh-generated trusted text at the rendering layer.

### Impact Explanation
This is a UI/output-spoofing issue: a victim browsing extensions in the interactive `gh extension browse` TUI could be visually misled into believing an attacker's extension is GitHub/cli-official or already vetted/installed, increasing the likelihood they choose to install it via the `i` keybinding, which calls `opts.Em.Install(repo, "")`. The actual security decision (which extension is "official") is still computed correctly by `getExtensions` based on `repo.Owner.Login`, so the underlying `ee.Official` boolean is not corrupted — only the rendered text can be spoofed to *appear* official even when `ee.Official` is false. This matches a social/visual spoofing impact class (forging trusted UI chrome to influence installation of untrusted code), rather than a direct code-execution or credential-exfiltration bug.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: publish any public GitHub repository named `gh-*`, tag it with topic `gh-extension` so it appears in search results, and set its description to include a tview markup substring such as ` [yellow](official)`. Every user who runs `gh extension browse` and whose search results include the malicious repo will see the spoofed rendering. This is fully repeatable and requires no interaction from the attacker beyond publishing the repo.

### Recommendation
Escape any untrusted text (`repo.Description`, and ideally `repo.FullName`/`Name` too) before passing it to tview widgets, using `tview.Escape()` (which converts `[` into `[[` so tview does not interpret it as a markup tag) in `extEntry.Description()`/`Title()` or at the point where `description` is assigned in `getExtensions`. Alternatively, disable dynamic color parsing for the list body text and only apply color codes to the trusted, gh-generated suffix strings by composing the item text from separately-escaped and trusted segments.

### Proof of Concept
```go
func TestExtEntryDescriptionEscapesMarkup(t *testing.T) {
    ee := extEntry{
        FullName:    "attacker/gh-evil",
        description: "totally safe tool [yellow](official)[-:-:-]",
    }

    got := ee.Description()

    // Expect the literal tview tag to be escaped (e.g. "[[yellow]") so tview
    // renders it as plain text rather than interpreting it as a color region.
    if strings.Contains(got, "[yellow]") && !strings.Contains(got, "[[yellow]") {
        t.Fatalf("attacker-controlled description was not escaped, tview will render forged badge: %q", got)
    }
}
```
Expected (current, vulnerable) behavior: the test fails because `Description()` returns the raw, unescaped string containing `[yellow](official)`, which `tview.List.AddItem` (in `Reset`/`Filter`) will render as a colored "(official)" label indistinguishable from the genuine badge produced by `Title()` for repos owned by `cli`/`github`.

func (e extEntry) Title() string {
	var installed string
	var official string

	if e.Installed {
		installed = " [green](installed)"
	}

	if e.Official {
		official = " [yellow](official)"
	}

	return fmt.Sprintf("%s%s%s", e.FullName, official, installed)
}

func (el *extList) Filter(text string) {
	el.filter = text
	if text == "" {
		return
	}
	el.ui.List.Clear()
	for _, ee := range el.extEntries {
		if strings.Contains(ee.Title()+ee.Description(), text) {
			el.ui.List.AddItem(ee.Title(), ee.Description(), rune(0), func() {})
		}
	}
}
