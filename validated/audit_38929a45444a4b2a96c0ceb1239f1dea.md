### Title
Liquidator can seize a borrower's collateral for zero debt repayment via rounding-to-zero in scaled-debt conversion - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`scale-debt-for-liquidation` converts a liquidator-chosen debt-repay amount into scaled units using `mul-div-down`, then decides whether to proportionally reduce the seized collateral only if `scaled-to-remove < scaled-debt`. When the raw debt amount is small enough that division by the (interest-inflated) borrow index rounds `scaled-debt` down to `0`, the "capped" branch is never entered, so the borrower's full expected collateral (`coll-actual`) is seized while the actual debt removed from storage (`debt-to-repay`) rounds to `0`. This is a direct instance of the report's "Multiplication/Division Rounding to Zero" pattern (Pattern 1/3) applied to a liquidation seizure, where the harmed party is a third-party borrower, not the caller.

### Finding Description
In the liquidation flow, the liquidator picks `debt-amount` (repay amount), which flows through `process-debt-asset` → `calc-final-liquidation-amounts` → `scale-debt-for-liquidation`: [1](#0-0) 

```
(scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
(scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
(debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
(coll-final (if (< scaled-to-remove scaled-debt)
                (mul-div-down coll-actual scaled-to-remove scaled-debt)
                coll-actual))
```

Once the vault has accrued interest, `borrow-index` grows above `INDEX-PRECISION` [2](#0-1) . For any `debt-final` small enough that `debt-final * INDEX-PRECISION < borrow-index`, `mul-div-down` truncates `scaled-debt` to `0`. Because `scaled-to-remove` (`0`) is then compared with `scaled-debt` (`0`) via strict `<`, the "cap" branch is false, so `coll-final` is left equal to the **full** `coll-actual` computed earlier in `process-collateral-asset` from the (uncapped) `debt-actual-usd` [3](#0-2) , while `debt-to-repay` (derived from `scaled-to-remove=0`) is `0`.

The debt-amount the liquidator supplies is entirely attacker-controlled, and `debt-final` is a deterministic function of it (via price/decimals conversions in `process-debt-asset` / `calc-final-liquidation-amounts`), so a liquidator can pick an input that lands exactly on the zero-rounding boundary for the target borrower's asset/index state. The borrower who is being liquidated is a distinct, unprivileged principal from the liquidator, and the shared state exploited is the borrower's stored scaled-debt / collateral balance in `v0-market-vault`.

### Impact Explanation
This is direct theft of another user's funds at rest: the liquidator receives the borrower's collateral (`coll-final = coll-actual`) while the borrower's recorded debt is not reduced by any economically meaningful amount (`debt-to-repay` truncates to `0`, or to a value far smaller than the collateral seized). This is a "seizure exceeding its bound" scenario explicitly listed as in-scope, and the effect is theft of user funds at rest — a Critical impact.

### Likelihood Explanation
Exploitability requires the attacker to choose a `debt-amount` that produces a `debt-final` on the rounding boundary relative to the current `borrow-index`/`INDEX-PRECISION` ratio for the target vault, and requires `borrow-index` to have grown past `INDEX-PRECISION` (true for any vault with accrued interest, which happens naturally over time). The attacker only needs public read access to current price, decimals, and index state (all readable via `get-cached-indexes` and asset registry calls) to compute the exact `debt-amount` producing the zero-rounding condition, so this is a Low-difficulty, unprivileged, single-transaction attack once a target position is liquidatable.

### Recommendation
Add an explicit floor check in `scale-debt-for-liquidation` (and equivalently in any other seizure/rounding path) requiring `debt-to-repay > 0` (or `scaled-to-remove > 0`) whenever `coll-final` is left un-scaled, e.g. mirroring the report's recommendation `require(ask(wad) > 0)`:
```
(asserts! (> debt-to-repay u0) ERR-DEBT-ZERO)
```
Additionally, ensure `coll-final` is always computed as a strict function of `debt-to-repay` (rounding proportionally down), not defaulted to the pre-rounding `coll-actual`, so no seizure can occur without a correspondingly non-zero debt reduction.

### Proof of Concept
1. Let a vault's `borrow-index` be `> INDEX-PRECISION` (true after any interest accrual with non-zero utilization) — verified by `accrue`/`next-index` logic in e.g. [2](#0-1) .
2. Attacker (liquidator) picks a borrower with a liquidatable position and computes a `debt-amount` input to `liquidate` such that the resulting `debt-final` (from `calc-final-liquidation-amounts`, [4](#0-3) ) satisfies `debt-final * INDEX-PRECISION < borrow-index`.
3. Calling `liquidate`/`call-liquidate` [5](#0-4)  triggers `scale-debt-for-liquidation`, where `scaled-debt` rounds to `0`, `debt-to-repay` becomes `0`, and `coll-final` remains the full `coll-actual` computed for the borrower [1](#0-0) .
4. The attacker's collateral transfer executes for `coll-final` while the borrower's on-chain scaled debt is reduced by `0`, resulting in free collateral extraction from the victim borrower.

(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))
