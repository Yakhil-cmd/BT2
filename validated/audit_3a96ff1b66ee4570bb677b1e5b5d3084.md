This confirms the vulnerability. `verify_webhook_signature` in `lib/shipit/github_app.rb` line 76-83 returns `true` unconditionally when `webhook_secret` is blank/nil (`return true unless webhook_secret`), so any org configured without a `webhook_secret` (e.g. `test/dummy/config/secrets_double_github_app.yml` shows this is a legitimate deployment pattern with multiple orgs, some with `webhook_secret: # nil`) accepts any signature. The signature check in `Shipit::WebhooksController#verify_signature` selects the org via `repository_owner`, which reads only `params.dig('repository','owner','login')`, while `Shipit::Webhooks::Handlers::PullRequest::ClosedHandler#repository` (and all sibling PR handlers) independently resolves the target repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. These two fields are both attacker-controlled and never cross-checked.

### Title
Forged `pull_request`/`closed` webhook using mismatched `repository.owner.login` vs `repository.full_name` archives a victim org's review stack - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb, lib/shipit/github_app.rb)

### Summary
`WebhooksController#verify_signature` selects which org's `webhook_secret` to verify against using `params.dig('repository','owner','login')`, but `PullRequest::ClosedHandler` (and sibling handlers) resolve the repository to mutate using the independent, attacker-controlled `params.repository.full_name` field via `Shipit::Repository.from_github_repo_name`. Because `GitHubApp#verify_webhook_signature` returns `true` unconditionally for any org with no configured `webhook_secret`, an attacker can pick a no-secret org for `repository.owner.login` while pointing `repository.full_name` at any other tracked repository, causing the handler to archive that victim repository's review stack with no valid signature for that org.

### Finding Description
The broken invariant, stated as an equality that must hold but doesn't: `org_that_verified_signature(params.repository.owner.login) == org_that_owns_repository_mutated(params.repository.full_name)`.

Path:
1. `Shipit::WebhooksController#verify_signature` (app/controllers/shipit/webhooks_controller.rb:24-30) computes `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` (line 59-62) is `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`.
2. `github_app.verify_webhook_signature(signature, raw_post)` in `lib/shipit/github_app.rb:76-83` does `return true unless webhook_secret` — if the selected org has no `webhook_secret` configured (a documented, legitimate configuration, see `test/dummy/config/secrets_double_github_app.yml:7,46` and `config/secrets.development.shopify.yml:9,18`), the signature check trivially passes for ANY payload/signature.
3. `Shipit::Webhooks.for_event('pull_request')` (app/models/shipit/webhooks.rb:9-18) fans the same JSON body out to all PR handlers including `Shipit::Webhooks::Handlers::PullRequest::ClosedHandler`.
4. `ClosedHandler#repository` (app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb:49-53) resolves the target repo via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — a completely separate field from `repository.owner.login` used in step 1, with no validation that the two agree.
5. `ClosedHandler#process` calls `review_stack.archive!`, which (via `ReviewStackAdapter#archive!`) deprovisions and archives the matched stack on the victim repository — app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb:23-35.

Exploit: attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request`, a `pull_request`/`closed` JSON body where `repository.owner.login` = `"no-secret-org"` (any org configured without `webhook_secret`) and `repository.full_name` = `"victim-org/victim-repo"`, plus `number` matching a real open PR/environment (`pr<number>`) on the victim's tracked repo, and any `X-Hub-Signature` value (verification is skipped due to the missing secret). The request passes `verify_signature` because `Shipit.github(organization: 'no-secret-org').verify_webhook_signature` short-circuits to `true`, yet `ClosedHandler` archives the review stack belonging to `victim-org/victim-repo`.

None of the existing guards catch this: `drop_unhandled_event` only checks the event has handlers registered; `verify_signature` checks a signature against the wrong org's (or no) secret; nothing compares `repository.owner.login` to the owner segment of `repository.full_name`; `ExplicitParameters` schemas (`closed_handler.rb:8-39`) validate types/presence, not cross-field consistency; `Shipit::Repository.from_github_repo_name` performs no ownership/tenant check against the verified org.

### Impact Explanation
An unauthenticated attacker can archive (deprovision) an arbitrary tracked review stack belonging to any other organization/repository configured in the same Shipit instance, as long as at least one configured org has no `webhook_secret`. This is a cross-tenant state mutation — one org's (attacker-controlled, secret-less) identity is used to authorize writes against another org's repository records — matching the "Critical: a payload for one repository mutating another's stack" category. The same owner/full_name divergence pattern also reaches `OpenedHandler`, `ReopenedHandler`, `EditedHandler`, `LabeledHandler`, `UnlabeledHandler`, `AssignedHandler`, and `LabelCapturingHandler`, all of which resolve `repository` the same way, so the blast radius covers the full PR-driven review-stack lifecycle, not just close/archive. This is repeatable against any repository tracked by Shipit.

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one configured GitHub org/app with no `webhook_secret` set (or use `Shipit.github(organization: unset)`/legacy no-secret config), which the project's own template and documentation (`config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`) show as a normal/expected multi-org configuration option, not a misconfiguration. Given that precondition, exploitation is trivial: a single unauthenticated HTTP POST with a crafted JSON body, no valid secret, token, or GitHub session required. Fully repeatable against any number of victim repositories in one request each.

### Recommendation
Bind the signature-verifying org to the repository actually mutated: after resolving `repository = Shipit::Repository.from_github_repo_name(params.repository.full_name)` inside each PR handler (or centrally before dispatch), verify that `repository.owner`/organization equals the `repository_owner` used to select `github_app` in `verify_signature`, and reject the event (422) on mismatch. Additionally, treat a missing `webhook_secret` for an org as "reject unsigned webhooks" rather than "accept all", or require an explicit opt-in flag for secret-less orgs used only in trusted/dev environments, never in multi-tenant production configs.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure two orgs in `Shipit.github` config: `"NoSecretOrg"` with `webhook_secret: nil`, and `"VictimOrg"` with a real `webhook_secret`.
2. Create a tracked `Shipit::Repository` for `VictimOrg/victim-repo` with an open `Shipit::ReviewStack` at `environment: "pr42"`, asserting `review_stack.archived? == false` (LHS/RHS of the invariant before: `verifying_org = "VictimOrg"` should equal `mutated_repo_org = "VictimOrg"`, but attacker will break this).
3. POST `/webhooks` with `X-Github-Event: pull_request`, body: `{"action":"closed","number":42,"pull_request":{...valid required fields...},"repository":{"owner":{"login":"NoSecretOrg"},"full_name":"VictimOrg/victim-repo"},"sender":{"login":"attacker"}}`, and any garbage `X-Hub-Signature` header.
4. Assert `response.status == 200` (no 422), proving verification passed against `NoSecretOrg`'s absent secret.
5. Reload `review_stack` and assert `review_stack.reload.archived? == true`, proving `VictimOrg`'s stack was mutated by a request whose signature was verified (trivially) against `NoSecretOrg` — i.e. `verifying_org ("NoSecretOrg") != mutated_repo_org ("VictimOrg")`, confirming the broken binding.
