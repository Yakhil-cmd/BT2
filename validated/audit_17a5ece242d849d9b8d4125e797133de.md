### Title
Webhook signature is verified against `repository.owner.login`'s GitHub App secret while the write target is resolved from the unrelated `repository.full_name` field, enabling cross-organization stack writes - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/handler.rb)

### Summary
In multi-organization Shipit deployments, `WebhooksController#verify_signature` selects the HMAC secret used to authenticate an inbound webhook based on `repository.owner.login` (or `organization.login`), but the handler that actually mutates state (`PushHandler`, via `Handler#repository_name`) resolves the target `Repository`/`Stack` from a completely different, uncorrelated field: `repository.full_name`. An admin of one configured GitHub organization, who legitimately knows their own org's `webhook_secret`, can forge a POST to the public `/webhooks` endpoint that authenticates as their own org while writing to another org's stack.

### Finding Description
`Shipit.github(organization: repository_owner)` in `lib/shipit.rb` (`def github`) picks the `GitHubApp` instance—and therefore the `webhook_secret` used for HMAC verification—keyed by whichever organization name is present in the payload: [1](#0-0) 

`WebhooksController#verify_signature` derives that organization purely from attacker-supplied JSON, never cross-checked against anything else in the request: [2](#0-1) 

Once the signature check passes, `create` dispatches the *same raw params* to the event handler: [3](#0-2) 

`Handler#repository_name`, used by every handler (e.g. `PushHandler`) to locate the `Repository`/`Stack` to act on, reads `repository.full_name`—a different JSON field from the one used for signature-org selection: [4](#0-3) 

`PushHandler#process` then syncs the resolved stack using an attacker-controlled `after` SHA: [5](#0-4) 

The binding that should hold is:
`organization whose webhook_secret authenticated the request == organization owning the repository/stack that gets written`

Because `repository_owner` (used for auth) and `repository.full_name` (used for the write) are independent, attacker-controlled fields inside the same unsigned-until-verified JSON body, an attacker who legitimately administers **OrgA**'s GitHub App (and therefore knows OrgA's `webhook_secret`, per the setup instructions that require the org's App creator to record and keep this secret) can craft:

```json
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>"
}
```

sign it with OrgA's real `webhook_secret`, and POST it directly to `/webhooks`. `verify_signature` resolves `Shipit.github(organization: "OrgA")` and successfully validates the signature using OrgA's secret. `PushHandler` then resolves the target via `full_name = "OrgB/victim-repo"`, an org whose secret was never checked, and queues `GithubSyncJob` for `OrgB`'s stack with an attacker-chosen `expected_head_sha`.

### Impact Explanation
This is a cross-organization write into another tenant's `Stack`/`Repository` state (queuing sync jobs with an attacker-chosen SHA) triggered by a request that only proves possession of a *different, unrelated* organization's webhook secret. This matches the Critical "cross-repository writes" impact category: an org with no relationship to `OrgB` can force `OrgB`'s stacks to sync against an arbitrary commit SHA of the attacker's choosing, corrupting deployed-revision tracking and commit history for repositories the attacker has no access to, purely because Shipit's authentication of the *sender* and its resolution of the *target repository* are keyed off two independent, unverified payload fields.

### Likelihood Explanation
Requires only that the Shipit deployment uses the documented multi-organization GitHub App configuration (`docs/setup.md`, "Using Multiple Github Applications") and that the attacker administers at least one of the configured organizations (a normal, unprivileged-with-respect-to-other-tenants scenario, not requiring compromise of the Shipit host, `api_clients_secret`, or any victim credential). The `/webhooks` endpoint is public and unauthenticated aside from the per-org HMAC, making this directly reachable.

### Recommendation
Cross-check that the organization used to select the webhook secret matches the owner embedded in `repository.full_name` (and any other repository-identifying field consumed by handlers) before dispatching to handlers, e.g. reject the webhook if `repository.full_name.split('/').first` does not match `repository_owner`/`organization.login` used in `verify_signature`.

### Proof of Concept
1. Configure Shipit with two orgs, `OrgA` and `OrgB`, each with its own `webhook_secret` (per `docs/setup.md` multi-org section).
2. As the administrator of `OrgA`'s GitHub App (who legitimately knows `OrgA`'s `webhook_secret`), craft:
   ```json
   {"repository":{"owner":{"login":"OrgA"},"full_name":"OrgB/victim-repo"},"ref":"refs/heads/master","after":"deadbeef..."}
   ```
3. Compute `X-Hub-Signature: sha1=<hmac(webhook_secret_OrgA, body)>`.
4. POST to `/webhooks` with header `X-Github-Event: push`.
5. `verify_signature` succeeds (using `OrgA`'s secret) per `app/controllers/shipit/webhooks_controller.rb#verify_signature`; `PushHandler#process` resolves and syncs `OrgB/victim-repo`'s stacks with the attacker-supplied `after` SHA, per `app/models/shipit/webhooks/handlers/handler.rb#repository_name` and `app/models/shipit/webhooks/handlers/push_handler.rb#process`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
```
