### Title
Unbounded `reward.mintingamount` Governance Parameter Allows Arbitrary KAIA Minting Per Block — (`kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`)

---

### Summary

The `reward.mintingamount` governance parameter accepts any non-negative `*big.Int` value with no upper-bound validation. A compromised or malicious governing node can vote to set this parameter to an astronomically large value. Once ratified, every subsequent block mints that unbounded amount of KAIA and distributes it to validators and funds, constituting an unfair and unauthorized reward distribution affecting all KAIA holders.

---

### Finding Description

The `RewardMintingAmount` entry in the `Params` map uses `noopFormatChecker`, which unconditionally returns `true` for any canonical value: [1](#0-0) 

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts any *big.Int, no upper bound
    ...
    DefaultValue: big.NewInt(0),
},
``` [2](#0-1) 

The `checkConsistency` function in `VerifyVote` / `Vote` explicitly returns `nil` (no error) for `RewardMintingAmount` without any cross-parameter or range check: [3](#0-2) 

The `Vote` API path in `kaiax/gov/headergov/impl/api.go` calls `NewVoteData` (which runs `FormatChecker`) and then `checkConsistency`, and neither rejects an extreme minting amount: [4](#0-3) 

Once the vote is ratified at an epoch block, `NewRewardConfig` reads the parameter directly from `GetParamSet` with no additional validation: [5](#0-4) 

The minting amount is then used verbatim in every block's reward calculation: [6](#0-5) 

---

### Impact Explanation

`reward.mintingamount` is listed as a **mutable** governance parameter: [7](#0-6) 

It is **not** in `AlwaysDeprecated` or `PermissionlessDeprecated`, so it remains voteable on mainnet: [8](#0-7) 

Setting `reward.mintingamount` to e.g. `2^200` causes `getDeferredRewardFullKore` / `getDeferredRewardFullFlex` to distribute that amount every block to validators and funds: [9](#0-8) 

This constitutes **unauthorized minting and unfair reward distribution** affecting KAIA — matching the allowed impact gate. All existing KAIA holders are diluted to near-zero value. The corrupted reward amounts are written to state via `FinalizeState`, permanently altering balances.

---

### Likelihood Explanation

Exploitation requires the `GoverningNode` (in `single` governance mode, which is Mainnet's mode) to be compromised or act maliciously. This is a low-likelihood event, analogous to the external report's rating of Likelihood: 1. However, no technical safeguard exists in the codebase to prevent it — the protection is entirely social/operational.

---

### Recommendation

Add an upper-bound `FormatChecker` for `RewardMintingAmount`, for example rejecting values above a protocol-defined maximum (e.g., `1e27` wei, ~1 billion KAIA per block). Additionally, add a consistency check in `checkConsistency` for `RewardMintingAmount` analogous to the existing cross-parameter checks for `Kip71LowerBoundBaseFee` / `Kip71UpperBoundBaseFee`: [10](#0-9) 

---

### Proof of Concept

1. Chain is running in `single` governance mode (Mainnet configuration).
2. The `GoverningNode` calls:
   ```
   governance_vote("reward.mintingamount", "999999999999999999999999999999999999999999999999999999999999")
   ```
3. `NewVoteData` canonicalizes the string to a `*big.Int` via `bigIntCanonicalizer`. `noopFormatChecker` returns `true`. `checkConsistency` returns `nil`. The vote is stored.
4. At the next epoch block, the vote is ratified and written to `header.Governance`.
5. `PostInsertBlock` → `HandleGov` persists the new parameter.
6. From the following epoch, `GetParamSet` returns the extreme `MintingAmount`.
7. `NewRewardConfig` sets `rc.MintingAmount` to the extreme value.
8. Every block's `FinalizeState` calls `GetDeferredReward` → `getDeferredRewardFullKore`, which distributes the extreme minting amount to validators and funds, crediting their state balances with an astronomically large KAIA amount per block. [1](#0-0) [3](#0-2) [5](#0-4) [11](#0-10)

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil

// getDeferredRewardFullKore is for non-Simple policy and after Kore.
func getDeferredRewardFullKore(config *reward.RewardConfig, execFee, burntFee, blobFee *big.Int, si *staking.StakingInfo) (*reward.RewardSpec, error) {
	var (
		spec             = reward.NewRewardSpec()
		minted           = new(big.Int).Set(config.MintingAmount)
		distributableFee = new(big.Int).Sub(execFee, burntFee)
	)

	// Distribute using RewardRatio first. Unlike Legacy, fees are not distributed here
	// because fees are exclusively allocated to proposer. By the way, remainder goes to KIF.
	validators, kif, kef := config.RewardRatio.Split(minted)
	proposer, stakers := config.Kip82Ratio.Split(validators)
	ratioRemainder := calcRemainder(minted, proposer, stakers, kif, kef)
	kif.Add(kif, ratioRemainder)

	// Further distribute using Kip82Ratio. By the way, remainder goes to proposer.
	// After Prague, if the CLStaking is not nil, the proposer and staking rewards are proportionally distributed to both CN and CL.
	// For proposer rewards, see `specWithProposerAndFunds`.
	stakersAlloc, kip82Remainder := assignStakingRewards(config, stakers, si)
	proposer.Add(proposer, kip82Remainder)
	stakers.Sub(stakers, kip82Remainder)

	// Proposer gets the fees.
	proposer.Add(proposer, distributableFee)

	spec.Minted = minted
	spec.TotalFee = new(big.Int).Add(execFee, blobFee)
	spec.BurntFee = new(big.Int).Add(burntFee, blobFee)
	spec.Stakers = stakers
	for addr, amount := range stakersAlloc {
		spec.IncRecipient(addr, amount)
	}
	spec = specWithProposerAndFunds(spec, config, proposer, kif, kef, si)
	return spec, nil
```
