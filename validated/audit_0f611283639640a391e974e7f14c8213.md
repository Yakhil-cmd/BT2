### Title
Webhook authentication can be bypassed entirely for any GitHub organization configured without a `webhook_secret`, allowing forged `membership` events to grant `Shipit.github_teams` authorization - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which organization's secret to validate a webhook against by reading an unauthenticated field straight out of the request body, and `GitHubApp#verify_webhook_signature` unconditionally accepts any request for an organization whose `webhook_secret` is blank. Because the multi-organization config format explicitly supports leaving `webhook_secret` unset per-org (shown in the engine's own config templates), an attacker can forge a webhook body that claims to originate from such an organization and have it processed as fully authenticated, with no valid `X-Hub-Signature` required.

### Finding Description
`repository_owner` — the value used to pick which GitHub App/secret governs verification — is read directly from the raw, unauthenticated JSON body, before any signature has been checked: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` resolves a `GitHubApp` for that attacker-supplied org name, and `verify_webhook_signature` returns `true` unconditionally whenever that org's `webhook_secret` is blank — no signature comparison happens at all in that case: [3](#0-2) 

The multi-org config schema (documented and shipped in the engine's own templates) allows `webhook_secret` to be left blank per organization: [4](#0-3) [5](#0-4) 

The binding that should hold is: *"the organization whose secret cryptographically authenticated this request" == "the organization content the engine trusts when mutating authorization state."* This equality breaks because the first value is attacker-chosen (an unauthenticated payload field) and, for orgs with blank secrets, no cryptographic check is performed at all — the second value (team/organization content acted on by handlers) is taken from the same untrusted body.

Once `verify_signature` passes, `create` dispatches the entire untrusted body to registered handlers: [6](#0-5) 

The `membership` event handler creates/loads a `Team` and adds an arbitrary user (looked up or created purely by GitHub login, no possession of GitHub credentials required) as a member: [7](#0-6) 

`Team#add_member` simply appends the membership record: [8](#0-7) 

Application-wide authorization is gated on exactly this `Team`/`Membership` state: [9](#0-8) [10](#0-9) 

So a forged `membership` webhook for an organization with a blank `webhook_secret` can add any login (including the attacker's real GitHub login) to a `Team` whose id is one of `Shipit.github_teams`, which are derived from the OAuth-configured `teams` for a (possibly different) organization: [11](#0-10) 

### Impact Explanation
This crosses the "escalation into `Shipit.github_teams` authorization" boundary explicitly called out as High-severity impact. An unauthenticated, unprivileged attacker who knows only that some configured GitHub organization has a blank `webhook_secret` (a supported, documented configuration state) can grant themselves (or any known GitHub login) membership in a team that gates access to the entire Shipit instance, then complete a normal OAuth login to obtain a fully authorized session.

### Likelihood Explanation
Requires: (1) the deploying application uses the documented multi-organization GitHub App configuration, and (2) at least one configured organization has no `webhook_secret` set — a state the engine's own example/test configs demonstrate as valid and which webhook_secret handling explicitly tolerates (`return true unless webhook_secret`). No session, API token, or GitHub write access is needed to hit `WebhooksController#create`, which is intentionally public.

### Recommendation
- Do not derive the organization used for signature verification from unauthenticated payload fields; verify against all configured secrets, or require every configured organization to have a mandatory, non-blank `webhook_secret`.
- Remove or gate the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature`, and instead reject/log the request if no secret is configured.
- After signature verification succeeds against organization X, ensure any organization/team fields acted upon inside handler payloads are consistent with X, rather than trusting arbitrary values in the same untrusted body.

### Proof of Concept
1. Deploy Shipit with a multi-org `github:` config where `OrgWithoutSecret` has `webhook_secret:` unset (matches `test/dummy/config/secrets_double_github_app.yml`).
2. POST to `/webhooks` with header `X-Github-Event: membership` and no valid `X-Hub-Signature`, body:
```json
{
  "action": "added",
  "team": { "id": <id_of_a_team_in_Shipit.github_teams>, "name": "x", "slug": "x", "url": "http://x" },
  "organization": { "login": "OrgWithoutSecret" },
  "member": { "login": "<attacker-github-login>" },
  "repository": { "owner": { "login": "OrgWithoutSecret" } }
}
```
3. `verify_webhook_signature` returns `true` (blank secret), `MembershipHandler#process` runs and adds/creates the attacker's user as a member of the privileged team (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-43`).
4. Attacker completes normal GitHub OAuth login (`app/controllers/shipit/github_authentication_controller.rb:30-34`); `User.find_or_create_from_github` matches by `github_id`, and `current_user.authorized?` now returns `true` (`app/models/shipit/user.rb:80-82`), granting full access to the Shipit instance.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
