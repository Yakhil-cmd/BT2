### Title
Bad-debt wipeout clamps `supply_index` up to `SUPPLY_INDEX_FLOOR`, leaving unburned supply shares with a phantom claim that drains fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
The kernel bug class is stale metadata on reused memory: `krealloc` reused spare allocation space without resetting the tag, so stale bookkeeping described memory it no longer matched. In XOXNO Lending the same shape exists in the share/index model: `apply_bad_debt_to_supply_index` "zeroes" supplier value by shrinking `supply_index`, but when the write-down exceeds total supplied value the index is clamped **up** to `SUPPLY_INDEX_FLOOR_RAW` instead of reaching zero, and the outstanding scaled supply shares are never burned or reset. The stale shares keep a positive residual claim (`scaled * RAY/1000`) on a market whose backing was fully written down — spare capacity that should be zero still carries a nonzero "tag", and the next depositor's cash becomes withdrawable by the holder of those stranded shares.

### Finding Description
`apply_bad_debt_to_supply_index` in `contracts/pool/src/interest.rs` caps the write-down at `total_supplied_value` and then floors the result:

```rust
let new_supply_index = cache
    .supply_index()
    .mul_floor(cache.env(), reduction_factor);
cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
``` [1](#0-0) 

On a full wipeout (`bad_debt >= total_supplied_value`) the reduction factor is 0, so the index is raised to `RAY/1000` while `cache.supplied()` — total scaled supply shares — is untouched. The borrow side is burned (`cache.burn_debt(position)` in `ops/seize.rs`), but no supply share is burned or zeroed. [2](#0-1) 

Every wiped supplier's `scaled_amount` therefore retains a positive floor claim of `scaled * RAY/1000`, which `resolve_withdrawal`/`unscale_supply_floor` honor as long as `require_reserves` finds cash (`cache/scale.rs:97`, `cache/cash.rs`). [3](#0-2) 

The in-repo tests already demonstrate both drains at cache level: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` and `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` show a stranded claim paying out exactly a fresh deposit and leaving the pool insolvent (`cash < bob_claim`). [4](#0-3) 

Reachability: an unprivileged caller drives this via `liquidate`/`clean_bad_debt` (controller builds a `PoolSeizeEntry` with `AccountPositionType::Borrow`, routed to `seize::apply`) on a small/dust-threshold position whose debt equals or exceeds the market's supplied value — easiest on a thin market or one already near-wiped. Any holder of stranded supply shares (the wiped suppliers themselves, or an attacker who deliberately self-liquidates into bad debt on a market they supply) then calls `withdraw` after any new `supply` credits cash.

### Impact Explanation
Theft of user funds / protocol insolvency. Stranded shares mint a claim against cash they were supposed to have forfeited; when fresh deposits land, the stranded holder withdraws first and the honest depositor's claim exceeds remaining pool cash. The effect is deterministic — the phantom claim is `scaled * RAY/1000`, large enough when scaled supply is large (shares are RAY-scaled, so even a wiped market's shares yield material units).

### Likelihood Explanation
Requires a bad-debt event where written-down debt ≥ total supplied value — i.e., a full wipeout. That happens when `clean_bad_debt` socializes uncovered debt on a market whose collateral leg under-covers the borrow, or on a tiny/dust market where a single undercollateralized borrow exceeds supply. The exploit leg needs only permissionless entrypoints (`liquidate`/`clean_bad_debt` to trigger, `supply` by a victim, `withdraw` by the stranded holder). No privileged role, oracle manipulation, or timing race is needed. The main caveat: if a higher-level supply guard in `ops`/`controller` zeroes positions on wipeout, the drain is blocked — the existing tests are explicitly written at raw-cache level "without supply_guard", and `seize::apply`/`withdraw` show no such reset, so the residual path appears live.

### Recommendation
On full write-down, reset rather than clamp: when `remaining == 0` (reduction factor zero), burn all outstanding `supplied`/`revenue` scaled shares to zero instead of flooring `supply_index` at `SUPPLY_INDEX_FLOOR_RAW`. Alternatively, track a "wiped" flag that zeroes `unscale_supply` results until shares are reissued. A minimal fix is to compute `new_supply_index` without the `.max(floor)` when the reduction factor is zero and simultaneously clear `cache.supplied`/`cache.revenue` share totals so no stranded claim survives.

### Proof of Concept
1. Attacker supplies `S` and borrows dust past the bad-debt cleanup threshold on a thin market (or arranges HF < 1 via own trades on a listed venue), becoming the bad-debt position.
2. Keeper/anyone calls `clean_bad_debt`/`liquidate`; controller emits a `PoolSeizeEntry{side: Borrow}`; `seize::apply` calls `apply_bad_debt_to_supply_index`, index clamps to `RAY/1000`, debt burned, supply shares intact.
3. Victim calls `supply(amount)`; `credit_cash` adds tokens; victim's scaled shares price at the floored index.
4. Attacker (still holding `scaled_amount = S`) calls `withdraw(i128::MAX)`; `resolve_withdrawal` yields `gross = S * RAY/1000` claim paid from the victim's cash; `require_reserves` passes.
5. Victim's `withdraw` now fails `require_reserves` — `cash < victim_claim`; the stranded claim drained exactly the fresh deposit, matching `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` (`contracts/pool/tests/interest.rs:430-494`).

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

#[test]
fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });
}
