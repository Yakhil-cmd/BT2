## Finding

### Title
Reused L1 Bitcoin lockup outpoints can be re-credited across separate `register-for-bond` calls, double-counting BTC collateral - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`pox-5`'s L1 bond-registration path credits a staker with `sats-total` uSTX-backing based on a Bitcoin merkle-proof of a locked UTXO, but the only replay/duplicate protection (`seen-outpoints`) is a list local to a single `register-for-bond` call. There is no persistent, contract-level map recording which Bitcoin `(txid, output-index)` pairs have already been credited to a prior bond registration. This mirrors the reported bug class: a check meant to prevent re-use of an already-consumed proof is scoped/reset in a way that permits the same proof to be replayed and re-credited.

### Finding Description
`register-for-bond` accepts an `(response ...)` `btc-lockup` argument; on the L1 branch it calls `verify-l1-lockups`, which folds `validate-l1-lockup` over the caller-supplied list of Bitcoin outputs: [1](#0-0) 

The fold's accumulator seeds `seen-outpoints: (list)` fresh on every call, and `validate-l1-lockup` only rejects an outpoint that repeats *within that same list*: [2](#0-1) 

Nothing in `validate-l1-lockup` or `register-for-bond` persists the outpoint to a durable map (e.g. `used-l1-lockup-outpoints`) once it has been accepted and credited. The script check (`construct-lockup-output-script`) only verifies that the on-chain Bitcoin output belongs to the calling `staker` and satisfies the *current* bond's `early-unlock-bytes`/`unlock-burn-height` gate; it does not verify the output hasn't already backed an earlier bond registration: [3](#0-2) 

A staker holds at most one `protocol-bond-memberships` entry at a time, so a single principal cannot register two bonds *concurrently* with the same proof. But once that first membership ends (bond matures/rolls over, or the staker unstakes and the entry is cleared), the staker can call `register-for-bond` again for a *new, later* bond, resubmitting the exact same Bitcoin lockup transaction/output as proof. Because the on-chain BTC timelock's `unlock-burn-height` is attacker-chosen up front (only bounded below by the bond's minimum via `ERR_INVALID_UNLOCK_HEIGHT`, and above by `BITCOIN_LOCKTIME_THRESHOLD`), a staker can pick a single far-future unlock height once, lock BTC exactly once, and then reuse that identical proof to register for bond after bond as each prior membership concludes — each time the contract credits `sats-total` from the proof as if new BTC had been locked: [4](#0-3) 

`sats-total` feeds directly into `protocol-bonds-total-staked` and the per-cycle share accounting (`add-staker-to-bond-cycles`), which determines the staker's/signer's proportional claim on sBTC rewards. Since the real Bitcoin collateral is a single, still-existing (or eventually spendable) UTXO, each additional registration backed by the same proof inflates the staker's counted commitment without any corresponding new BTC lockup — a double-counted commitment identical in kind to the report's "successfulMessages" replay: a stateful de-dup check that should span the life of the proof was instead scoped only to a single invocation (there, contract storage wiped across a migration boundary; here, the `seen-outpoints` accumulator reset on every call), so the same underlying value-backing event is credited more than once.

### Impact Explanation
This breaks the equality "sats credited by an L1 proof == sats actually newly locked on Bitcoin for that registration." A staker can accrue `amount-sats`-weighted bond membership/signer-weight and sBTC reward share for multiple, non-concurrent bond periods while only ever having locked BTC once — and can eventually spend that BTC via the timelock/early-exit path after having already been credited for a later bond, leaving that later bond's counted collateral completely unbacked. This is double-counting of a commitment backing sBTC rewards, which the rules classify as Critical impact.

### Likelihood Explanation
Exploitation requires no privileged role: any allowlisted staker who legitimately performs one real Bitcoin lockup can retain the raw proof bytes (`tx`, `header`, merkle path) and resubmit them verbatim in a subsequent `register-for-bond` call once their prior membership has ended. The only gating checks in the current code (`ERR_ALREADY_REGISTERED`, the per-call `seen-outpoints` dedup, and the script/amount/merkle checks) all pass identically on replay because they were designed to catch same-call duplication or altogether different outputs, not proof reuse across calls over time.

### Recommendation
Add a persistent map (e.g. `used-l1-lockup-outpoints: {txid: (buff 32), output-index: uint} -> bool`) that `validate-l1-lockup` checks and sets (via `map-insert`, failing with a new `ERR_LOCKUP_OUTPOINT_ALREADY_USED` on a second use) for every credited outpoint, independent of the per-call `seen-outpoints` list, so that a given Bitcoin lockup output can only ever be credited to one `register-for-bond` call for the lifetime of the contract.

### Proof of Concept
1. Staker locks BTC once into the canonical P2WSH timelock script with a generously far-future `unlock-burn-height` (still `< BITCOIN_LOCKTIME_THRESHOLD`), satisfying the minimum L1 unlock height of several future bonds.
2. Staker calls `register-for-bond` for bond 0 with a valid merkle proof of that single output; `verify-l1-lockups`/`validate-l1-lockup` accept it, credit `sats-total`, and set `protocol-bond-memberships`.
3. Bond 0 matures (or staker unstakes); `protocol-bond-memberships` entry for the staker is cleared.
4. Staker calls `register-for-bond` again for a later bond (bond N), submitting the *identical* proof (`tx`, `header`, `leaf-hashes`, `output-index`) from step 1. `seen-outpoints` is freshly `(list)` for this new call, `ERR_ALREADY_REGISTERED` doesn't fire (no current membership), and all per-output checks pass again, crediting `sats-total` a second time for bond N even though no new BTC was locked.
5. The Bitcoin UTXO from step 1 can later be spent by the staker (via the timelock or early-exit witness) — leaving bond N's counted `amount-sats` collateral fully unbacked, having already been "spent" against bond 0 and never renewed for bond N.

        (bond-index uint)
        (signer-manager <signer-manager-trait>)
        (amount-ustx uint)

        ;; this is a list of outputs corresponding to their timelocks.
        ;; If the response is `err`, this is the amount of sBTC (in sats)

                    output-index: uint,

                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        }
            uint
        ))
        (signer-calldata (optional (buff 500)))
    )
    (let (
            (signer (contract-of signer-manager))
            ;; Compute the sats being staked for this bond.
            (sats-total (try! (match btc-lockup
                l1-lockups (verify-l1-lockups tx-sender bond-index l1-lockups)
                sbtc-amount (ok sbtc-amount)
            )))
            ;; Any bond the staker is currently a member of. Some value here
            ;; means this is a roll-over from an ending bond into a later one.
            (existing-membership (map-get? protocol-bond-memberships tx-sender))
            ;; sBTC currently custodied for the staker's existing bond (0 if
            ;; they have none, or if the existing bond is an L1 lock).
            (old-sbtc (get-staker-custodied-sbtc tx-sender))
            ;; sBTC this new bond needs custodied (0 on the L1 path).
            (new-sbtc (if (is-ok btc-lockup)
                u0
                sats-total
            ))
            ;; Any STX-only stake the staker has. Present means this
            ;; `register-for-bond` is a roll-over from an ending stx-only
            ;; stake into a bond.
            (existing-stake (map-get? staker-info tx-sender))
            (bond (unwrap! (map-get? protocol-bonds bond-index) ERR_BOND_NOT_FOUND))
            (allowance (unwrap!
                (map-get? protocol-bond-allowances {
                    staker: tx-sender,
                    bond-index: bond-index,
                })
                ERR_NOT_ALLOWLISTED
            ))
            (first-reward-cycle (bond-period-to-reward-cycle bond-index))
            (bond-start-height (bond-period-to-burn-height bond-index))
            ;; the first cycle in which their stx are unlocked
            (unlock-cycle (+ first-reward-cycle BOND_LENGTH_CYCLES))
            (current-total-staked (get-total-shares-staked-for-cycle first-reward-cycle
                (some bond-index)
            ))
            (stx-balance (stx-account tx-sender))
            (total-balance (+ (get locked stx-balance) (get unlocked stx-balance)))
        )
        ;; Reject during the prepare phase since next-cycle data is mutated
        (try! (verify-not-prepare-phase))
        ;; Verify that they're sending enough STX
        (asserts!
            (>= amount-ustx
                (min-ustx-for-sats-amount sats-total (get stx-value-ratio bond)
                    (get min-ustx-ratio bond)
                ))
            ERR_INSUFFICIENT_STX
        )

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
