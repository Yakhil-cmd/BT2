### Title
Deregistered Bridge Operator's Stale Votes Persist, Enabling Unauthorized Bridge Value Transfer Execution — (`contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator()` removes an operator from the `operators` mapping and `operatorList` array but does **not** clear that operator's existing vote entries from the `votes` storage mapping. Any vote the deregistered operator cast before removal remains counted in `voteCounts`, and a subsequent vote from a still-active operator on the same nonce can push `voteCounts` to the threshold, executing a bridge value transfer (KLAY/ERC20/ERC721) with the effective participation of an operator whose authority has been revoked.

### Finding Description

`deregisterOperator()` performs only two state mutations:

```solidity
delete operators[_operator];          // removes from operators map
operatorList[i] = operatorList[...];  // removes from operatorList array
operatorList.length--;
``` [1](#0-0) 

The `votes` mapping — `votes[voteType][nonce].voted[operator]` and `votes[voteType][nonce].voteCounts[voteKey]` — is never touched. The contract itself documents this gap:

> "Note that outstanding votes by the deregistered operator are not revoked. … In this case the request was executed with A's vote after A is deregistered." [2](#0-1) 

`_voteCommon()` checks only `voteCounts[voteKey] >= operatorThresholds[voteType]`: [3](#0-2) 

Because the deregistered operator's count contribution is never decremented, the threshold can be reached with fewer currently-authorized operators than intended.

The value-transfer execution path (`handleERC20Transfer`, `handleKLAYTransfer`, `handleERC721Transfer`) calls `_voteValueTransfer` → `_voteCommon` and, on threshold, immediately mints/transfers tokens or sends KLAY: [4](#0-3) [5](#0-4) 

### Impact Explanation

A bridge value transfer (KLAY, ERC20, or ERC721) is executed on the destination chain using the vote weight of a deregistered operator. This constitutes an **unauthorized transfer of bridged assets**: the owner revoked the operator's authority, yet the operator's vote still counts toward the threshold that unlocks the asset release. The corrupted value is `votes[ValueTransfer][N].voteCounts[voteKey]`, which remains `≥ 1` for the deregistered operator's key after deregistration, allowing threshold satisfaction with fewer live operators than the policy requires.

### Likelihood Explanation

The scenario requires:
1. Operator A votes on nonce N (normal operation).
2. Owner calls `deregisterOperator(A)` — a routine key-rotation or incident-response action.
3. Any remaining active operator B votes on nonce N with the same calldata.

Step 3 is the normal bridge-relay flow. The window between steps 1 and 2 is non-zero in any real deployment. No attacker capability beyond being a registered operator is needed for step 3; the deregistered operator does not need to act after removal.

### Recommendation

In `deregisterOperator()`, iterate over all open (non-closed) nonces for both `VoteType.ValueTransfer` and `VoteType.Configuration` and decrement `voteCounts` for the deregistered operator's recorded `voted[_operator]` key, then zero out `voted[_operator]`. Alternatively, add a check inside `_voteCommon` that skips (or subtracts) votes from addresses no longer in `operators` before comparing against the threshold.

### Proof of Concept

Setup: threshold = 2, operators = {A, B, C}.

1. Operator A calls `handleKLAYTransfer(…, nonce=5, …)`.  
   → `votes[ValueTransfer][5].voted[A] = keccak256(calldata)`, `voteCounts[key] = 1`. Transfer not yet executed.

2. Owner calls `deregisterOperator(A)`.  
   → `operators[A] = false`, A removed from `operatorList`.  
   → `votes[ValueTransfer][5].voteCounts[key]` **remains 1**.

3. Operator B calls `handleKLAYTransfer(…, nonce=5, …)` with identical arguments.  
   → `_voteCommon` increments `voteCounts[key]` to **2**.  
   → `2 >= threshold(2)` → `closedValueTransferVotes[5] = true` → KLAY transferred to `_to`.

The transfer executes with A's revoked vote counting toward the threshold, violating the invariant that only currently-authorized operators may authorize bridge transfers. [6](#0-5)

    // _voteCommon handles common functionality for voting.
    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }
```

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
