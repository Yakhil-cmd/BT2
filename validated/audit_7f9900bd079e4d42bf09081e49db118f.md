### Title
Stop-hook review bypass via `git commit --amend` desyncs `dirty_now` from `changed_since`, causing malicious edits to be silently skipped from review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the Stop-hook review set as the intersection of `dirty_now` (files differing from *current HEAD*) and `changed_since` (files differing from the turn-start stash baseline). When a turn's edit is folded into the existing HEAD commit via `git commit --amend` (rather than a new child commit), `dirty_now` collapses to empty while `changed_since` still contains the file, so the intersection is empty and the Stop hook exits via the "empty review set" skip path, silently dropping the dangerous change from review.

### Finding Description
In `compute_v2_review_set` [1](#0-0) , `dirty_now` is derived from `_git_status_porcelain(repo)`, which reports files differing from the *current* HEAD [2](#0-1) . There is a special-case branch intended to catch files committed mid-turn:

```
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
```

`_is_ancestor` checks that `head_at_capture` is reachable from `current_head` via `git merge-base --is-ancestor` [3](#0-2) , i.e. it only fires for a strictly linear forward commit (child of `head_at_capture`). A `git commit --amend` on the commit that was HEAD at `head_at_capture` produces a new commit that is a *sibling* of `head_at_capture` (same parent), not a descendant — `_is_ancestor` returns `False`, so this branch never fires, `diff_base` stays `"HEAD"`, and no name-only diff is unioned into `dirty_now`.

Meanwhile `changed_since` is computed from `_git_name_only(repo, baseline_sha)`, i.e. `git diff --name-only <baseline_sha>` against the working tree [4](#0-3)  — this still reports the amended file because the baseline stash predates the edit.

After the amend, the working tree matches the new (amended) HEAD, so `git status --porcelain` reports it as clean: `tracked_dirty` is empty and (assuming no other pending edits) `dirty_now` is empty. The final line:

```
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```

intersects an empty `dirty_now` with a non-empty `changed_since`, yielding an empty `review_set`. The caller then treats this as "no changes to review" and skips entirely [5](#0-4) , with `debug_log("Stop hook: empty review set")` followed by `_skip(9, ...)` — no LLM security review, no diff sent, no blocking exit(2).

The attack path: repository-controlled content (e.g. instructions in `CLAUDE.md`, a README, or any file Claude reads) that steers Claude toward an "amend the last commit to keep history clean" workflow after introducing a vulnerability causes exactly this sequence — edit dangerous code, then `git commit --amend` — using only ordinary git commands available to any session. No elevated privilege, mocks, or direct state mutation is required; it is triggered purely through the normal Stop-hook flow and standard git operations.

### Impact Explanation
This is a security-control bypass: the plugin's core enforcement mechanism (the Stop-hook LLM security review that would otherwise force Claude to fix flagged issues via `exit(2)`) is silently skipped for a class of common git workflows (amend, and by extension any operation that replaces HEAD with a non-ancestor commit while leaving the working tree clean, e.g. rebase/reset+recommit). The dangerous code change is never surfaced to the reviewer, and the session proceeds as if nothing needed review — directly matching the "Security-control bypass that silently disables or routes around blocking/review boundaries" impact category.

### Likelihood Explanation
Preconditions are minimal and realistic: a single-commit turn where the edited file is folded into the existing HEAD via `--amend` instead of a new commit. This is a common, unremarkable git habit (and can be nudged via ordinary repo content/instructions), requires no special privileges, and is fully reproducible deterministically from the git state machine (not timing-dependent). No error suppression or partial mitigation exists for this branch — `_is_ancestor` correctly identifying "not a descendant" is precisely what causes the failure.

### Recommendation
Do not rely solely on `dirty_now` (working-tree-vs-current-HEAD) intersected with `changed_since` (baseline-vs-working-tree). Instead, always union in the set of paths that differ between `baseline_sha` and `current_head` (not just `head_at_capture..HEAD` restricted to the ancestor case), or drop the ancestor-only fast path and instead directly diff `baseline_sha` against `current_head`'s tree content plus the working tree, so that any HEAD movement (linear commit, amend, rebase, reset+recommit) that changes the committed content of a file relative to baseline is still captured in `dirty_now`. Concretely, compute `changed_since_head = _git_name_only(repo, baseline_sha + ".." + "HEAD")` unconditionally (not gated on `_is_ancestor`) and union it into `dirty_now`, or simplify by making `review_set` just `changed_since` (baseline vs. current working tree) intersected with a "not pre-existing untracked" filter, removing the fragile ancestor-gated special case entirely.

### Proof of Concept
Integration test plan:
1. Init a git repo with an initial commit containing `safe.py`.
2. Simulate UPS: call `capture_git_baseline(cwd)` to get `baseline_sha`, record `head_at_capture = _git_rev_parse_head(cwd)`.
3. Simulate Claude's turn: write a dangerous pattern into `safe.py` (e.g. `os.system(user_input)`), then run `git add -A && git commit --amend --no-edit` (amending the existing HEAD commit rather than creating a new commit).
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline={})`.
5. Assert (currently failing, demonstrating the bug): `review_paths` is expected to contain the absolute path to `safe.py`, but it is empty — `dirty_now_count == 0` and `changed_since_count >= 1` in the returned metrics, proving the dangerous file was excluded from `review_set` despite genuinely differing from baseline.
6. Contrast with the non-amend control case (`git commit -m "..."` creating a new child commit) where the same edit correctly appears in `review_paths`, confirming the bypass is specific to the amend (non-ancestor HEAD) path.

def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}

    try:
        if not include_untracked:
            return _run(None)
        with _temp_index(cwd) as env:
            return _run(env)
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_name_only({base!r}) error: {e}")
        return None
```

def _git_status_porcelain(cwd):
    """One `git status --porcelain=v1 -z` → (tracked_dirty, untracked) sets of
    repo-root-relative paths, or (None, None) on error. Replaces the
    `_temp_index + git diff HEAD --name-only` pair for the v2 dirty_now
    computation: faster in large repos, and yields the
    untracked set separately so the later get_git_diff can do a targeted
    `add -N -- <files>` instead of a whole-tree `add -N .`.

    -uall: list individual files inside untracked directories (default
    collapses to `dir/`). Required so the untracked set subtracts cleanly
    against the UPS-time `_list_untracked` snapshot, which uses ls-files and
    therefore always lists individual files."""
    try:
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "status",
             "--porcelain=v1", "-uall", "-z"],
            cwd=cwd, capture_output=True, text=True, timeout=30,
        )
        if r.returncode != 0:
            debug_log(f"_git_status_porcelain rc={r.returncode}: {r.stderr[:200]}")
            return None, None
        tracked, untracked = set(), set()
        entries = r.stdout.split("\0")
        i = 0
        while i < len(entries):
            e = entries[i]
            if not e:
                i += 1
                continue
            xy, path = e[:2], e[3:]
            if xy == "??":
                untracked.add(path)
            else:
                tracked.add(path)
                # Rename/copy entries are XY old\0new\0 — second NUL field is
                # the origin path; consume it so it isn't misparsed as a new
                # 2-char-status entry.
                if "R" in xy or "C" in xy:
                    i += 1
            i += 1
        return tracked, untracked
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"_git_status_porcelain error: {e}")
        return None, None
```

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
