Based on my investigation, the reported bug class (fair LP token pricing formula treating pooled token reserves as if all had identical/fixed decimals) does not have a live, unfixed analog in this Polkadot SDK repo:

- `pallet_oracle` (`substrate/frame/honzon/oracle/src/lib.rs`) is a raw key-value price feed with no implicit fixed-decimals contract on `OracleValue`; it does not compute any derived price from mixed-decimal reserves. [1](#0-0) 
- `pallet-asset-conversion`'s `get_reserves`, `quote`, `get_amount_out`/`get_amount_in`, and `quote_price_*` functions operate purely on raw balances of two specific assets without ever mixing them into a single "LP fair value" figure assuming 18-decimal normalization; there is no sqrt-based combined pricing formula analogous to UniV2LPOracle. [2](#0-1) [3](#0-2) 
- The one pallet that explicitly deals with cross-asset decimal precision, `pallet-psm`, already implements decimal-aware conversion helpers (`external_to_internal`/`internal_to_external`) with recorded decimal snapshots, drift guards (`DecimalsMismatch`), and overflow checks — this is the closest conceptual analog to the reported bug class, and it has already been hardened against decimals mismatches via [4](#0-3)  and the drift-protection tests in `substrate/frame/psm/src/tests.rs` (e.g. `mint_uses_snapshot_when_asset_decimals_drift`, `redeem_uses_snapshot_when_asset_decimals_drift`). [5](#0-4) 

There is no FRAME pallet in this repo that derives a single price/value by combining two differently-decimaled asset reserves through an unnormalized formula (the specific pattern the Sherlock report targets), so no demonstrable analog exists to report.

		/// Convert an amount denominated in external-asset units into internal units.
		///
		/// Scales by `10^(ext_decimals - internal_decimals)` — multiplies up when internal has more
		/// decimals, floor-divides when it has fewer. Returns [`Error::ConversionOverflow`] if
		/// the scaling factor or the product does not fit in the balance type.
		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}
