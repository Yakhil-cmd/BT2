### Title
Terminal escape-sequence injection via unsanitized certificate/statement fields in `gh attestation inspect` - ([File: pkg/cmd/attestation/inspect/inspect.go])

### Summary
`printInspectionSummary` prints `iB.Certificate.SourceRepositoryURI`, `iB.Certificate.SubjectAlternativeName`, and `iB.Certificate.RunInvocationURI` — values taken verbatim from the attacker-supplied Sigstore bundle's certificate — via `logger.OutPrintf`, which writes directly to `h.IO.Out` with no ANSI/control-character sanitization. Unlike other code paths in the CLI that treat external content as untrusted, this path never wraps the values in `iostreams.Untrusted` or routes them through `IO.ContentOut`, so terminal escape sequences embedded in a malicious bundle reach the victim's terminal unfiltered.

### Finding Description
`gh attestation inspect <path-to-bundle>` reads a local bundle file and, without any trust verification (an explicit "unsafe" Sigstore policy is used, `verify.NewPolicy(verify.WithoutArtifactUnsafe(), verify.WithoutIdentitiesUnsafe())`), extracts the leaf certificate and summarizes it with `certificate.SummarizeCertificate` [1](#0-0) . The resulting `CertificateInspection` (embedding `certificate.Summary`, which includes `SourceRepositoryURI`, `SubjectAlternativeName`, and `RunInvocationURI`) is fully attacker-controlled because it is derived from Fulcio certificate extensions/SAN fields in a bundle the attacker crafted and the user is only *inspecting*, not verifying.

These fields are printed via:
```go
logger.OutPrintf("%s:%s %s\n", scheme.Bold(colName), strings.Repeat(".", dots), pair[1])
``` [2](#0-1) 

`OutPrintf` is implemented as a raw `fmt.Fprintf(h.IO.Out, f, v...)` with no filtering: [3](#0-2) 

The CLI has an established pattern for exactly this scenario — the `iostreams.Untrusted` type, whose `String()` method sanitizes ANSI escape sequences automatically on any `fmt` print path, and is used for gist/HTTP/log content [4](#0-3) . `IOStreams.Out` is the raw stdout writer, separate from the sanitizing `ContentOut` writer that other commands use for external content [5](#0-4) . The `inspect` command's certificate/statement fields are never wrapped in `Untrusted` nor routed through `ContentOut`/`asciisanitizer`, unlike `pr diff`, `gist view`, and `pkg/cmd/api` which explicitly guard against this class of injection [6](#0-5) [7](#0-6) .

`formatNwo` only reformats `SourceRepositoryURI` when it happens to parse as a valid `OWNER/REPO` via `ghrepo.FromFullName`; on parse failure (or for any of the other two fields, which are never passed through `formatNwo`) the raw attacker-controlled string is returned/used unchanged [8](#0-7) .

### Impact Explanation
An attacker who publishes a malicious Sigstore bundle (e.g., as a repo file, release asset, or artifact) can embed ANSI/terminal control sequences (e.g., OSC sequences to set terminal title, CSI sequences to move cursor / hide text, or screen/tmux escape injection sequences as demonstrated in this codebase's own test suite for a related issue) inside the certificate's SAN, source-repository-URI, or run-invocation-URI fields. When the victim downloads the bundle and runs `gh attestation inspect <path>`, these bytes are written unsanitized to the terminal, enabling terminal spoofing/UI redress (e.g., faking subsequent output, hiding text, manipulating terminal title) or, on vulnerable/legacy terminal emulators, more severe consequences depending on terminal escape sequence support. This matches a "terminal escape sequence injection" bounty class (output/UI integrity issue) rather than direct code execution.

### Likelihood Explanation
Highly feasible and repeatable: no authentication or special privileges are needed. The attacker only needs to craft a bundle JSON with a certificate/SAN containing raw ESC bytes and get the victim to run `gh attestation inspect` on it (a documented, user-facing command, currently `Hidden: true` but still reachable) — the same trust model already anticipated by the tool's own doc comment: "we ditch the verificationResult... you can't meaningfully 'verify' a bundle with such an Unsafe policy" [9](#0-8) . The command is explicitly designed to inspect untrusted/unverified bundles, so this is the primary threat model it should defend against.

### Recommendation
Sanitize all certificate- and statement-derived fields before printing in `printInspectionSummary`, e.g. wrap `SourceRepositoryURI`, `SubjectAlternativeName`, `RunInvocationURI` (and any other bundle-derived string fields, including `PredicateType`) with `iostreams.NewUntrusted(...)` (or run them through the `asciisanitizer` transform used elsewhere in the codebase) before formatting/printing, and/or route `printInspectionSummary` output through `logger.IO.ContentOut` instead of `IO.Out` directly.

    outputStr := out.String()
    // Expected to FAIL on current code: raw ESC byte reaches the output.
    require.NotContains(t, outputStr, "\x1b",
        "output should not contain raw ESC (0x1b) bytes; got: %q", outputStr)

func printInspectionSummary(logger *io.Handler, bundles []BundleInspection) {
	logger.Printf("Inspecting bundles…\n")
	logger.Printf("Found %s:\n---\n", text.Pluralize(len(bundles), "attestation"))

	bundleSummaries := make([][][]string, len(bundles))
	for i, iB := range bundles {
		bundleSummaries[i] = [][]string{
			{"Authentic", formatAuthentic(iB.Authentic, iB.Certificate.CertificateIssuer)},
			{"Source Repo", formatNwo(iB.Certificate.SourceRepositoryURI)},
			{"PredicateType", iB.Statement.GetPredicateType()},
			{"SubjectAlternativeName", iB.Certificate.SubjectAlternativeName},
			{"RunInvocationURI", iB.Certificate.RunInvocationURI},
			{"CertificateNotBefore", iB.Certificate.NotBefore.Format(time.RFC3339)},
		}
	}

	// "SubjectAlternativeName" has 22 chars
	maxNameLength := 22

	scheme := logger.ColorScheme
	for i, bundle := range bundleSummaries {
		for _, pair := range bundle {
			colName := pair[0]
			dots := maxNameLength - len(colName)
			logger.OutPrintf("%s:%s %s\n", scheme.Bold(colName), strings.Repeat(".", dots), pair[1])
		}
		if i < len(bundleSummaries)-1 {
			logger.OutPrintln("---")
		}
	}
}

// Untrusted wraps string content the application did not author: HTTP response
// bodies, file contents fetched from a remote, anything that originates outside
// the CLI. The raw bytes are unexported so the only ways out are the methods
// below.
//
// Untrusted satisfies fmt.Stringer, and String sanitizes, so any fmt print path
// (Fprint, Fprintf with %s or %v, Sprint) renders the content with ANSI escape
// sequences neutralized. The only way to reach the raw bytes is Raw, which is
// deliberately easy to grep for and is intended for non-terminal uses such as
// hashing, writing to a file, or piping to another program.
type Untrusted struct {
	raw string
}

// NewUntrusted labels a string as untrusted external content.
func NewUntrusted(s string) Untrusted {
	return Untrusted{raw: s}
}

// NewUntrustedBytes labels a byte slice as untrusted external content.
func NewUntrustedBytes(b []byte) Untrusted {
	return Untrusted{raw: string(b)}
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
