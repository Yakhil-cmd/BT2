### Title
Unauthenticated P2P StakingInfo Injection During Fast Sync Corrupts Reward-Distribution Database — (`datasync/downloader/queue.go`)

---

### Summary

During fast sync, staking information received over P2P from any connected peer is accepted and written to the local database with **zero content validation**. The `validate` callback inside `queue.DeliverStakingInfos` is a stub that unconditionally returns `nil` (marked `TODO`). A malicious peer can therefore inject arbitrary `StakingInfo` — including fabricated `RewardAddrs`, `StakingAmounts`, and treasury-fund addresses (`KIFAddr`/`KEFAddr`/`KPFAddr`) — which is then persisted via `PutStakingInfoToDB` and later consumed by `FinalizeState` to distribute KAIA block rewards.

---

### Finding Description

**Root cause — empty validation in `queue.DeliverStakingInfos`:**

```go
// datasync/downloader/queue.go  line 956-958
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [1](#0-0) 

Compare with `DeliverReceipts`, which validates every receipt against the header's `ReceiptHash`:

```go
validate := func(index int, header *types.Header) error {
    if types.DeriveReceiptsRoot(...) != header.ReceiptHash {
        return errInvalidReceipt
    }
    return nil
}
``` [2](#0-1) 

No equivalent cryptographic anchor exists for staking info.

**Write path — unvalidated data reaches persistent storage:**

`commitFastSyncData` and `commitPivotBlock` both call `PutStakingInfoToDB` directly on the peer-supplied `result.StakingInfo`:

```go
if result.StakingInfo != nil {
    d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
}
``` [3](#0-2) [4](#0-3) 

**P2P entry point — any connected peer can send `StakingInfoMsg`:**

```go
case p.GetVersion() >= kaia65 && msg.Code == StakingInfoMsg:
    if err := handleStakingInfoMsg(pm, p, msg); err != nil { ... }
```

`handleStakingInfoMsg` decodes the message and calls `pm.downloader.DeliverStakingInfos` with no further authentication:

```go
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
    var stakingInfos []*staking.P2PStakingInfo
    if err := msg.Decode(&stakingInfos); err != nil { ... }
    pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos)
    return nil
}
``` [5](#0-4) 

**What `StakingInfo` controls:**

`StakingInfo` is the sole input to `FinalizeState`'s reward distribution. It contains `RewardAddrs` (where per-validator KAIA rewards are sent), `StakingAmounts` (determines proportional staking rewards), and `KIFAddr`/`KEFAddr`/`KPFAddr` (treasury fund recipients). If any of these are forged, `FinalizeState` computes a different state root. [6](#0-5) [7](#0-6) 

**Scope boundary:** The DB-backed staking info path is active only before the Kaia hardfork (`SourceNum(num) = RoundDown(num-1, StakingInterval) - StakingInterval`). After the Kaia hardfork, staking info is re-derived from the previous block's EVM state, so the corrupted DB entry is bypassed for post-fork blocks. [8](#0-7) 

---

### Impact Explanation

A node performing fast sync to a pre-Kaia-hardfork pivot block will store the attacker-supplied `StakingInfo` in its local database. When it subsequently processes new blocks (which still use the DB path), `FinalizeState` distributes KAIA rewards according to the forged `RewardAddrs` and `StakingAmounts`, producing a state root that diverges from the canonical chain. The node will reject all honest peers' blocks, causing **persistent consensus divergence** on the affected node. Additionally, if `KIFAddr`/`KEFAddr`/`KPFAddr` are replaced with attacker-controlled addresses, the node's local accounting credits treasury rewards to the attacker.

---

### Likelihood Explanation

Any peer that completes the kaia/65+ handshake can send `StakingInfoMsg`. No stake, no special role, and no cryptographic credential is required beyond being a connected P2P peer. The attack is triggered automatically whenever a node initiates fast sync, which is the default sync mode for new nodes. The only constraint is that the target node must be syncing to a block before the Kaia hardfork.

---

### Recommendation

1. **Implement content validation in `queue.DeliverStakingInfos`**: Derive the expected staking info from the canonical block state (via `getFromState`) and compare it against the peer-supplied data, analogous to how `DeliverReceipts` validates against `header.ReceiptHash`.

2. **Remove the `TODO` stub**: Replace the no-op `validate` function with a real check that verifies at minimum the `BlockNum` field and the hash of the serialized staking info against a commitment stored in the block header or a trusted local source.

3. **Alternatively**, refuse to write peer-supplied staking info to the DB during fast sync and instead re-derive it from the downloaded state trie after the pivot block is committed.

---

### Proof of Concept

1. Attacker runs a kaia/65 node and connects to a victim node that is fast-syncing to a pre-Kaia-hardfork block.
2. Victim node sends `StakingInfoRequestMsg` for block hashes it needs.
3. Attacker responds with `StakingInfoMsg` containing a crafted `P2PStakingInfo` where `RewardAddrs[i]` is replaced with attacker-controlled addresses and `StakingAmounts` are set to maximize attacker's share.
4. `handleStakingInfoMsg` → `DeliverStakingInfos` → `queue.DeliverStakingInfos` (validate returns `nil`) → `commitFastSyncData` → `PutStakingInfoToDB` writes the forged data.
5. After fast sync completes, the victim node processes new blocks using the forged staking info. `FinalizeState` distributes rewards to attacker addresses and produces a wrong state root.
6. The victim node diverges from the canonical chain and rejects all honest peers' blocks. [9](#0-8) [10](#0-9) [11](#0-10)

func (d *Downloader) commitFastSyncData(results []*fetchResult, stateSync *stateSync) error {
	// Check for any early termination requests
	if len(results) == 0 {
		return nil
	}
	select {
	case <-d.quitCh:
		return errCancelContentProcessing
	case <-stateSync.done:
		if err := stateSync.Wait(); err != nil {
			return err
		}
	default:
	}
	// Retrieve the a batch of results to import
	first, last := results[0].Header, results[len(results)-1].Header
	logger.Debug("Inserting fast-sync blocks", "items", len(results),
		"firstnum", first.Number, "firsthash", first.Hash(),
		"lastnumn", last.Number, "lasthash", last.Hash(),
	)
	blocks := make([]*types.Block, len(results))
	receipts := make([]types.Receipts, len(results))
	for i, result := range results {
		blocks[i] = types.NewBlockWithHeader(result.Header).WithBody(result.Transactions)
		receipts[i] = result.Receipts
		if result.StakingInfo != nil {
			d.stakingModule.PutStakingInfoToDB(result.StakingInfo.BlockNum, staking.ToStakingInfo(result.StakingInfo))
			logger.Info("Imported new staking information", "number", result.StakingInfo.BlockNum)
		}
	}
	if index, err := d.blockchain.InsertReceiptChain(blocks, receipts); err != nil {
		logger.Debug("Downloaded item processing failed", "number", results[index].Header.Number, "hash", results[index].Header.Hash(), "err", err)
		return fmt.Errorf("%w: %v", errInvalidChain, err)
	}
	return nil

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
}
