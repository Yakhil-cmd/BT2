### Title
Attacker-controlled `SourceRepositoryURI` in a self-signed attestation bundle causes `gh attestation inspect` to silently drop the actual host, spoofing a `github.com`-looking "owner/repo" NWO - (File: pkg/cmd/attestation/inspect/inspect.go)

### Summary
`formatNwo` in `pkg/cmd/attestation/inspect/inspect.go` feeds the certificate's `SourceRepositoryURI` — a value taken verbatim from an attacker-controlled, self-signed leaf certificate — into `ghrepo.FromFullName`, and then discards the parsed host by calling `ghrepo.FullName(repo)`, which only prints `owner/repo`. An attacker can set `SourceRepositoryURI` to `https://attacker.com/org/repo`, and the tool will render it as `org/repo`, exactly as it would for a legitimate `https://github.com/org/repo` value, hiding the fact that the certificate does not actually reference GitHub.

### Finding Description
In `runInspect` (`pkg/cmd/attestation/inspect/inspect.go:184-204`), the bundle's leaf certificate is summarized via `certificate.SummarizeCertificate(leafCert)` without any host or authenticity check — this happens regardless of whether the bundle is "Authentic" (`inspectedBundle.Authentic` is only informational and does not gate whether/how the certificate summary is displayed). [1](#0-0) 

`printInspectionSummary` then passes `iB.Certificate.SourceRepositoryURI` directly to `formatNwo`: [2](#0-1) 

`formatNwo` calls `ghrepo.FromFullName(longUrl)` and, on success, returns `ghrepo.FullName(repo)`: [3](#0-2) 

`ghrepo.FromFullName` delegates to `FromFullNameWithHost` → `repository.ParseWithHost`, which is documented/used elsewhere in the codebase to accept `"OWNER/REPO"`, `"HOST/OWNER/REPO"`, or a full URL and extract `Owner`, `Name`, and `Host` separately: [4](#0-3) 

Critically, `ghrepo.FullName` only formats `owner/name` and never includes the host: [5](#0-4) 

So for an attacker-supplied `SourceRepositoryURI` of `https://attacker.com/org/repo`, `ParseWithHost` would parse `Host=attacker.com`, `Owner=org`, `Name=repo`, and `formatNwo` returns the string `"org/repo"` — visually indistinguishable from what would be printed for a genuine `https://github.com/org/repo` value. This silently drops the host information that would otherwise flag the certificate as not GitHub-issued, presenting the row `Source Repo: org/repo` in a way that a victim would reasonably read as "the real GitHub repo `org/repo`." No code path re-injects or displays the parsed host anywhere in `printInspectionSummary`. This is possible because inspecting a bundle does not require the bundle to be "Authentic"; `inspect` explicitly always displays the certificate summary even for self-signed/untrusted bundles, per the comment in `runInspect`: "we ditch the verificationResult to avoid even implying that it is 'verified' ... but you can't meaningfully 'verify' a bundle with such an Unsafe policy!" [6](#0-5) 

Regarding the escape-sequence-injection half of the question: I was unable to fully verify the `io.Handler.OutPrintf` implementation and whether it applies any ANSI/control-character sanitization to interpolated values (`pkg/cmd/attestation/io/handler.go` exists but its `Printf`/`OutPrintf` bodies were not retrieved before the tool budget ran out), nor could I confirm the internals of `repository.ParseWithHost` (external dependency `github.com/cli/go-gh/v2/pkg/repository`) regarding how it handles malformed/control-character-laden input. Those two sub-claims are therefore unconfirmed and should not be treated as established findings; only the host-dropping/spoofing behavior of `formatNwo`/`ghrepo.FullName` is confirmed by the code above.

### Impact Explanation
This enables a spoofing/misleading-output issue: an attacker who publishes a crafted, self-signed Sigstore bundle (e.g., as an artifact, gist, or release asset) can cause `gh attestation inspect` to display a `Source Repo` field that looks like a normal GitHub `owner/repo` reference even though the certificate's actual `SourceRepositoryURI` points to an entirely different, attacker-controlled host. This falls into the "trust/authenticity misrepresentation" bucket — it does not achieve code execution or credential theft, but it can mislead a user reviewing `inspect` output (a tool specifically meant to let users manually judge trustworthiness of a bundle) into believing an untrusted, non-GitHub-issued certificate refers to a legitimate GitHub source repository.

### Likelihood Explanation
Preconditions are attacker-cheap: the attacker only needs to craft a self-signed Sigstore bundle file (JSON) with an X.509 leaf certificate containing a custom Fulcio `SourceRepositoryURI` OID extension, and get a victim to run `gh attestation inspect <bundle>` on it — no valid signature, no trusted CA chain, and no "Authentic" status are required, since `inspect` displays the certificate summary unconditionally. This is straightforward and fully reproducible offline with `certificate.SummarizeCertificate`/`ghrepo.FromFullName`.

### Recommendation
In `formatNwo`, preserve and clearly render the host component before dropping it — e.g., print `host/owner/repo` (or flag explicitly when the host is not `github.com`/the configured hostname) instead of only `owner/repo`. Additionally, `printInspectionSummary` should visually distinguish/warn when `iB.Authentic` is false, since currently the certificate fields (including `SourceRepositoryURI`) are displayed with the same formatting regardless of trust status.

        t.Errorf("formatNwo silently dropped non-github.com host: got %q", got)
    }
    // Expected safe behavior: host should be preserved or the value flagged, e.g.
    // "attacker.com/org/repo" or "org/repo (host: attacker.com)"

// FromFullName extracts the GitHub repository information from the following
// formats: "OWNER/REPO", "HOST/OWNER/REPO", and a full URL.
func FromFullName(nwo string) (Interface, error) {
	return FromFullNameWithHost(nwo, defaultHost())
}

// FromFullNameWithHost is like FromFullName that defaults to a specific host for values that don't
// explicitly include a hostname.
func FromFullNameWithHost(nwo, fallbackHost string) (Interface, error) {
	repo, err := repository.ParseWithHost(nwo, fallbackHost)
	if err != nil {
		return nil, err
	}
	return NewWithHost(repo.Owner, repo.Name, repo.Host), nil
}
