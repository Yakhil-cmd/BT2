### Title
Stop-hook review-set computation (`compute_v2_review_set`) silently drops committed dangerous changes when HEAD is moved to a non-descendant commit - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` computes the Stop-hook review set as `dirty_now ∩ changed_since`, where `dirty_now` is derived from `git status` against the *current* `HEAD` plus (conditionally) the diff between `head_at_capture` and `HEAD`. That conditional supplement only fires when `head_at_capture` is an ancestor of the current `HEAD` [1](#0-0) . A normal, unprivileged sequence of git operations within the same turn (commit a dangerous change, then move `HEAD` sideways to a commit that is not a descendant of `head_at_capture`, e.g. via `git checkout --orphan` + commit) makes the file "clean" against the new `HEAD` while breaking the ancestor relationship, so `dirty_now` becomes empty for that file even though it is genuinely new/changed relative to the turn's baseline.

### Finding Description
`consume_stop_state` snapshots `baseline_sha` and `head_at_capture` (the `HEAD` recorded at `UserPromptSubmit`) and hands them to `compute_v2_review_set` [2](#0-1) .

`compute_v2_review_set` builds:
- `dirty_now` = `tracked_dirty ∪ new_untracked` from `git status --porcelain` against the *current* `HEAD`, unioned with `head_at_capture..HEAD` names **only if** `head_at_capture` is an ancestor of the current `HEAD` [3](#0-2) .
- `changed_since` = `git diff --name-only <baseline_sha>` (content diff against the turn-start stash), independent of ancestry [4](#0-3) .
- `review_set = dirty_now ∩ changed_since` [5](#0-4) .

`_is_ancestor` uses `git merge-base --is-ancestor` [6](#0-5) , which returns `False` whenever `HEAD` moved "sideways" instead of strictly forward (e.g., to an orphan branch, or a detached commit not reachable from the pre-turn `HEAD`).

Exploit flow (all normal git commands, no privilege beyond editing files and running git in the cloned repo):
1. Turn starts; UPS records `head_at_capture = A`, `baseline_sha` = stash of `A`.
2. Dangerous edit is written, `git add`, `git commit` → `HEAD = B` (child of `A`).
3. `git checkout --orphan new-branch && git add -A && git commit` → `HEAD = C`, a root commit with the same tree as `B` (dangerous file present) but with **no ancestor relationship to `A`**.
4. At Stop: `git status` vs `C` shows the working tree clean (`dirty_now` for that file = ∅), and since `_is_ancestor(A, C)` is `False`, the `head_at_capture..HEAD` supplement is skipped — `dirty_now` never contains the dangerous file.
5. `changed_since` (content diff against `baseline_sha`≈`A`) still contains the file, but the intersection with the empty `dirty_now` for that path yields an empty `review_set` entry for it.
6. If the resulting `review_set` (across all files) ends up empty, `handle_stop_hook` calls `_skip(9)` and exits 0 without ever invoking the LLM review [7](#0-6) ; if other files remain dirty, the dangerous file specifically is simply absent from `review_paths` and never appears in the diff sent to the LLM.

This breaks the stated invariant that the review set must stay bound to the correct baseline and touched paths — the review-set computation assumes `HEAD` only moves forward (`commit`/`merge`) relative to `head_at_capture`, but nothing in the Stop hook enforces that assumption, and ordinary git history rewriting (orphan checkout, detached-HEAD reset to an unrelated commit, `rebase --onto` a disjoint base, etc.) violates it while leaving the dangerous content permanently committed in the repo.

### Impact Explanation
This is a logic-level bypass of the mandatory security review guard: a genuinely new, harmful, permanently-committed change is excluded from the Stop-hook's LLM vulnerability scan, defeating the plugin's core security invariant ("only code Claude actually changed is reviewed" / no dangerous change escapes review) [8](#0-7) . This matches the "Logic-level service disruption caused by bypassing a required guard or misbinding security state" impact class — the guard (Stop-hook review) is silently skipped for a legitimate, in-scope dangerous change due to baseline/HEAD misbinding.

### Likelihood Explanation
No special privilege is required beyond normal git command usage inside the cloned working tree, which is exactly the level of control Claude/an agentic session already has in a coding session. The sequence (commit → checkout --orphan → commit) is a small number of ordinary git invocations achievable within a single turn, and is deterministic/repeatable — it does not depend on timing races, resource limits, or environment-specific behavior.

### Recommendation
Do not gate the `head_at_capture..HEAD` diff supplement on strict ancestry alone. Instead, always include the symmetric diff between `head_at_capture` and current `HEAD` (e.g. `git diff --name-only head_at_capture HEAD`, which works regardless of ancestry direction) when `head_at_capture` differs from the current `HEAD`, so that any content difference between the turn-start `HEAD` and the turn-end `HEAD` — whether reached by forward commits or by checkout/reset/rebase to an unrelated tip — is captured in `dirty_now`. Alternatively, compute `dirty_now` purely from content diff against `baseline_sha`/`head_at_capture` rather than `git status` against the possibly-swapped current `HEAD`.

### Proof of Concept
Integration test plan (extends existing Stop-hook / `compute_v2_review_set` test suite):
1. Initialize a temp git repo with one commit `A` containing a benign file.
2. Simulate UPS: call `capture_git_baseline(cwd)` and `_git_rev_parse_head(cwd)` to get `baseline_sha`/`head_at_capture = A`.
3. Write a dangerous file (e.g. containing `os.system(user_input)`), `git add`, `git commit` → `B`.
4. `git checkout --orphan tmp && git add -A && git commit -m orphan` → `C` (same tree as `B`, unrelated to `A`).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture=A)`.
6. **Expected (secure) assertion**: the dangerous file path is present in the returned `review_paths`.
7. **Actual (vulnerable) behavior**: `review_paths` is empty or omits the dangerous file, because `dirty_now` for that path is empty (clean vs `C`) and `_is_ancestor(A, C)` is `False`, so the intersection with `changed_since` drops it — demonstrating the bypass.

def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap

    return with_locked_state(session_id, _snap) or {
        "touched_paths": [], "baseline_sha": None, "head_at_capture": None,
        "untracked_at_baseline": {},
        "fire_count": 0, "fire_count_expired": False, "previous_findings": [],
    }

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False

## How the git baseline works

On each UserPromptSubmit, the plugin runs `git stash create` to get a SHA representing
the current working tree state (HEAD + any uncommitted changes). This SHA is saved to
the session state file. When the Stop hook fires, it runs `git diff <baseline_sha>` to
get only the changes made since that snapshot. After analysis, the baseline is updated
so the next Stop hook iteration only sees new changes.

This means:
- Only code Claude actually changed is reviewed (not pre-existing code)
- Mid-session commits are handled correctly (diff is against the snapshot, not HEAD)
- Each turn only reviews new changes (baseline updates after each stop hook)
