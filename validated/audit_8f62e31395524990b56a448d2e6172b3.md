### Title
Missing request timeout in `GetRawGistFile` allows indefinite hang on attacker-controlled gist raw URL - (File: pkg/cmd/gist/shared/shared.go)

### Summary
`GetRawGistFile` builds a plain `http.NewRequest` (no `context.Context`) and calls `httpClient.Do(req)` with no deadline, then reads the entire body with `io.ReadAll` with no size or time bound. Since the `RawURL` fetched comes from the `raw_url` field of a gist file object returned by GitHub's gist API — content that is influenced by whoever created the gist file/truncation — a slow or stalling response can hang `gh gist view`/`gh gist edit` indefinitely.

### Finding Description
`GetRawGistFile` is invoked from `pkg/cmd/gist/view/view.go` when a gist file is `Truncated`, using `gf.RawURL` taken directly from the gist API response: [1](#0-0) 
The function itself performs no timeout/context wiring: [2](#0-1) 
`http.NewRequest` (not `http.NewRequestWithContext`) is used, so there is no way to bound the request via a `context.Context` deadline, and `httpClient.Do` / `io.ReadAll` will block for as long as the remote server keeps the connection open and trickles bytes (slow-loris style). The `*http.Client` passed in (`f.HttpClient()` from `api.NewHTTPClient`) is constructed via `ghAPI.NewHTTPClient` in `api/http_client.go` with no `Timeout` field set on the resulting `http.Client`, and no default transport-level read/response timeouts are configured in that constructor: [3](#0-2) 
Because `raw_url` for a gist file is a GitHub-hosted gist raw content URL, an attacker cannot arbitrarily redirect to any host through this specific field without GitHub's own gist raw-content redirect behavior, but the underlying network fetch (whichever host ultimately serves the byte stream, including via redirects the client follows) has no enforced deadline in this code path.

### Impact Explanation
A stalling/slow response causes `gh gist view`/`gh gist edit` to hang indefinitely on `GetRawGistFile`, consuming a goroutine/connection and blocking the invoking process — this matches an unbounded resource consumption / denial-of-service impact on the victim's machine, which is especially harmful in CI pipelines that lack manual interruption.

### Likelihood Explanation
Preconditions are low: an attacker only needs to publish a gist with a file whose content triggers `Truncated: true` (large gist file) and have the `raw_url` content served slowly. Any victim running `gh gist view <id>` (or `edit`) against that gist reaches the vulnerable, timeout-less code path. This is straightforward and repeatable.

### Recommendation
Use `http.NewRequestWithContext` in `GetRawGistFile` with a bounded `context.Context` (e.g., `context.WithTimeout`), and/or set an explicit `Timeout` on the `http.Client` used for this call, and bound `io.ReadAll` with `io.LimitReader` to also cap response size.

### Proof of Concept
Go test sketch using `httptest.Server` that stalls the response body:
```go
func TestGetRawGistFile_HangsWithoutTimeout(t *testing.T) {
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.WriteHeader(http.StatusOK)
        flusher, _ := w.(http.Flusher)
        for {
            w.Write([]byte("x"))
            flusher.Flush()
            time.Sleep(500 * time.Millisecond) // slow-loris style trickle
        }
    }))
    defer srv.Close()

    done := make(chan error, 1)
    go func() {
        _, err := shared.GetRawGistFile(http.DefaultClient, safeurl.NewImmutableSafeURL(srv.URL))
        done <- err
    }()

    select {
    case <-done:
        // expected: should complete or error out within a bounded deadline
    case <-time.After(3 * time.Second):
        t.Fatal("GetRawGistFile did not return within expected deadline — no timeout enforced")
    }
}
```
Expected (fixed) behavior: the call returns (with a timeout error) within the configured deadline instead of hanging indefinitely.

func GetRawGistFile(httpClient *http.Client, rawURL safeurl.SafeURL) (iostreams.Untrusted, error) {
	req, err := http.NewRequest("GET", rawURL.String(), nil)
	if err != nil {
		return iostreams.Untrusted{}, err
	}

	resp, err := httpClient.Do(req)
	if err != nil {
		return iostreams.Untrusted{}, err
	}

	defer resp.Body.Close()

	if resp.StatusCode != http.StatusOK {
		return iostreams.Untrusted{}, api.HandleHTTPError(resp)
	}

	body, err := io.ReadAll(resp.Body)

	if err != nil {
		return iostreams.Untrusted{}, err
	}

	return iostreams.NewUntrustedBytes(body), nil
}
