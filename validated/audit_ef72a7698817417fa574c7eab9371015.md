### Title
Unchecked division by zero in `token_price_x32` causes swap DoS when output vault is fully drained via `swap_base_output` - (File: `programs/cp-swap/src/states/pool.rs`)

### Summary
`PoolState::token_price_x32` computes the token price ratios using raw integer division (`/`) instead of a checked operation. If either post-fee vault balance is exactly `0`, this line panics with a runtime "divide by zero" error instead of returning a graceful `Result::Err`. This function is invoked on every `swap_base_input` and `swap_base_output` call via `get_swap_params`, so once a vault balance hits `0` (net of accumulated fees), every subsequent swap touching the pool aborts.

### Finding Description
`token_price_x32` divides using the plain `/` operator: [1](#0-0) 

This is called unconditionally from `get_swap_params`, which both swap instructions call before computing curve results: [2](#0-1) 

In `swap_base_output`, the amount removed from the output vault (`actual_output_amount`) is derived directly from the user-supplied `amount_out_received`/`out_transfer_fee`, not from a curve formula that mathematically guarantees the remaining balance stays positive: [3](#0-2) 

The resulting subtraction in `CurveCalculator::swap_base_output` uses `checked_sub`, which permits the result to be exactly `0` (not just `>0`): [4](#0-3) 

By contrast, in `swap_base_input`, the output amount is derived from the constant-product formula `output_amount = floor(input_amount_less_fees * output_vault_amount / (input_vault_amount + input_amount_less_fees))`, which is mathematically bounded strictly below `output_vault_amount` for any positive `input_vault_amount`, so that path can never zero out a vault. `swap_base_output` has no equivalent structural guarantee — a user can specify an output amount equal to the entire remaining post-fee output balance and successfully drive `new_output_vault_amount` to exactly `0`. [5](#0-4) 

Once one side's `vault_amount_without_fee` result is `0`, any later call (by any user) to `swap_base_input` or `swap_base_output` on this pool invokes `token_price_x32` with that zero as a divisor, causing a runtime panic that aborts the transaction. This differs from the codebase's normal error-handling convention (returning `Result`/`Option` and mapping to `ErrorCode`s such as `ZeroTradingTokens`); here the panic is unrecoverable and not gracefully converted into an Anchor error.

### Impact Explanation
This is a Denial-of-Service on core swap functionality for the affected pool: any attacker can force one output vault balance (net of fees) to zero via a single `swap_base_output` call, after which every other user's `swap_base_input`/`swap_base_output` instruction against that pool will panic and revert, rather than fail gracefully. This blocks trading on the pool until a deposit restores a positive balance on the drained side (deposits directly increase raw vault balance, so this is recoverable but requires LP action, and in the interim swaps for arbitrary unrelated users are denied). This matches the "Medium" severity class of the referenced report: an oracle/price ratio permitted to reach zero causing a division-by-zero DoS in downstream calculations, rather than direct fund theft.

### Likelihood Explanation
Reaching this state requires only a single unprivileged `swap_base_output` transaction with attacker-chosen `amount_out_received` equal to (or engineered to produce, after fee/transfer-fee accounting, exactly) the pool's remaining post-fee output balance. No privileged signer, special build flags, or off-chain component is needed — it is directly reachable by any swapper through the public `swap_base_output` instruction and standard account constraints.

### Recommendation
Add an explicit check in `token_price_x32` (and/or in `vault_amount_without_fee`/the swap instructions) to reject `token_0_amount == 0 || token_1_amount == 0`, returning a proper `ErrorCode` (e.g. reuse `ZeroTradingTokens`) instead of performing the raw division. Additionally, consider constraining `swap_base_output` so `actual_output_amount` cannot equal the full `total_output_token_amount`, matching the implicit guarantee that `swap_base_input` already provides.

### Proof of Concept
1. Note the pool's current output-side balance net of fees: `total_output_token_amount = vault_amount_without_fee(...).1` (or `.0` depending on direction).
2. Call `swap_base_output` with `amount_out_received` (plus its transfer-fee adjustment via `get_transfer_inverse_fee`) chosen so that `actual_output_amount == total_output_token_amount` exactly — i.e., request the entire remaining post-fee balance of the output token. `CurveCalculator::swap_base_output`'s `checked_sub` permits `new_output_vault_amount == 0`.
3. The instruction succeeds and completes normally, leaving `vault_amount_without_fee` for that token at exactly `0`.
4. Any subsequent call to `swap_base_input` or `swap_base_output` on this pool (by any user) reaches `pool_state.get_swap_params(...)` → `token_price_x32(...)`, which executes `token_0_amount as u128 * Q32 / token_1_amount as u128` (or the mirrored expression) with a zero divisor, causing a runtime panic and transaction failure — denying swaps on the pool until a deposit restores the balance. pub fn swap_base_output(
    ctx: Context<Swap>,
    max_amount_in: u64,
    amount_out_received: u64,

    require_gt!(amount_out_received, 0);
    let block_timestamp = solana_program::clock::Clock::get()?.unix_timestamp as u64;
    let pool_id = ctx.accounts.pool_state.key();
    let pool_state = &mut ctx.accounts.pool_state.load_mut()?;
    if !pool_state.get_status_by_bit(PoolStatusBitIndex::Swap)
        || block_timestamp < pool_state.open_time
    {
        return err!(ErrorCode::NotApproved);
    }
    let out_transfer_fee = get_transfer_inverse_fee(
        &ctx.accounts.output_token_mint.to_account_info(),
        amount_out_received,
    )?;
    let amount_out_with_transfer_fee = amount_out_received.checked_add(out_transfer_fee).unwrap();

    let SwapParams {
        trade_direction,
        total_input_token_amount,
        total_output_token_amount,
        token_0_price_x64,
        token_1_price_x64,
        is_creator_fee_on_input,
    } = pool_state.get_swap_params(
        ctx.accounts.input_vault.key(),
        ctx.accounts.output_vault.key(),
        ctx.accounts.input_vault.amount,
        ctx.accounts.output_vault.amount,
    )?;

    pub fn swap_base_input_without_fees(
        input_amount: u128,
        input_vault_amount: u128,
        output_vault_amount: u128,
    ) -> u128 {
        // (x + delta_x) * (y - delta_y) = x * y
        // delta_y = (delta_x * y) / (x + delta_x)
        let numerator = input_amount.checked_mul(output_vault_amount).unwrap();
        let denominator = input_vault_amount.checked_add(input_amount).unwrap();
        let output_amount = numerator.checked_div(denominator).unwrap();
        output_amount
    }

    pub fn swap_base_output_without_fees(
        output_amount: u128,
        input_vault_amount: u128,
        output_vault_amount: u128,
    ) -> u128 {
        // (x + delta_x) * (y - delta_y) = x * y
        // delta_x = (x * delta_y) / (y - delta_y)
        let numerator = input_vault_amount.checked_mul(output_amount).unwrap();
        let denominator = output_vault_amount.checked_sub(output_amount).unwrap();
        let input_amount = numerator.checked_ceil_div(denominator).unwrap();
        input_amount
    }
