## Finding: Multisig approval bypass via feature-gated payload verification in `validate_multisig_transaction`

### Summary
`multisig_account.move`'s `validate_multisig_transaction`, which the VM invokes during mempool admission and transaction prologue for `MultisigTransaction` execution, only enforces that the payload actually being executed matches the payload the owners voted on when the feature flag `abort_if_multisig_payload_mismatch_enabled` is turned on. When that flag is disabled, an owner with sufficient approval count can substitute a completely different execution payload from the one that was approved by quorum, and the substituted payload will still pass admission and be committed.

### Finding Description
`validate_multisig_transaction` binds approvals to a specific stored transaction (`payload_hash`/`payload`) and to the caller-supplied `payload` bytes that are actually going to be executed: [1](#0-0) 

- If the on-chain record stores only a `payload_hash` (line 1365), the caller-supplied `payload` is verified against that hash — this path is unconditional and correct.
- If the on-chain record stores the *full* `payload` (line 1373-1384), the equality check between the caller-supplied `payload` and the approved, stored payload is **gated behind `features::abort_if_multisig_payload_mismatch_enabled()`**. If this feature is disabled, the block is skipped entirely, and no comparison happens between what owners approved (`transaction.payload`) and what is about to execute (the `payload` argument, which comes from the submitted transaction and is the code path the VM will actually run).

This breaks the "approval validation accepting the wrong approval set" invariant: quorum was collected for payload A (`transaction.payload`), but with the feature disabled, an executing owner can pass payload B as the `payload` argument and it will run under the multisig account's authority as long as sequence number, quorum count, and timelock checks pass — none of which depend on the payload contents.

### Impact Explanation
This allows an owner (who is a legitimate multisig participant, but not necessarily privileged in the sense of governance) to execute an arbitrary, unapproved transaction payload under the multisig account's signer authority, as long as the quorum threshold on *some* pending sequence number is met. This is a state-transition/authorization bypass: a transaction that should fail admission (there was no quorum approval for this exact payload) is instead admitted and executed to completion, moving funds or invoking arbitrary modules as the multisig account.

### Likelihood Explanation
Reachable purely through normal use of `multisig_account::create_transaction` (full-payload path) plus a standard `execute` call with owner-controlled `payload` bytes, requiring only that `abort_if_multisig_payload_mismatch_enabled` is not turned on for the given network/epoch. No privileged governance action or key compromise is required to trigger this class of bug once the feature is off — only ordinary owner participation in the multisig.

### Recommendation
Make the payload-equality check unconditional whenever `transaction.payload.is_some()` and a non-empty `payload` is supplied, rather than gating it behind the `abort_if_multisig_payload_mismatch_enabled` feature flag. The check should always fail closed (reject execution) on mismatch instead of being a best-effort/feature-toggle safeguard.

### Proof of Concept
1. Owner A creates a multisig transaction with `create_transaction(multisig_account, payload_A)`, which stores full `payload_A` in `transaction.payload`.
2. Owners collect enough approvals for that pending sequence number (approvals are recorded against the sequence number, not against payload bytes directly).
3. With `abort_if_multisig_payload_mismatch_enabled` disabled, executing owner submits the actual transaction with a different payload `payload_B` (e.g. calling `execute` with `payload_B` bytes instead of `payload_A`).
4. `validate_multisig_transaction` passes: `transaction.payload_hash` is `none` (full payload flow) so the hash check at line 1365-1371 is skipped, and the equality check at line 1375-1384 is bypassed because the feature is disabled.
5. `payload_B`, never approved by quorum, executes under the multisig account. [2](#0-1)

    fun validate_multisig_transaction(
        owner: &signer, multisig_account: address, payload: vector<u8>) {
        assert_multisig_account_exists(multisig_account);
        assert_is_owner(owner, multisig_account);
        let sequence_number = last_resolved_sequence_number(multisig_account) + 1;
        assert_transaction_exists(multisig_account, sequence_number);

        if (features::multisig_v2_enhancement_feature_enabled()) {
            assert!(
                can_execute(address_of(owner), multisig_account, sequence_number),
                error::invalid_argument(ENOT_ENOUGH_APPROVALS),
            );
        }
        else {
            assert!(
                can_be_executed(multisig_account, sequence_number),
                error::invalid_argument(ENOT_ENOUGH_APPROVALS),
            );
        };

        // Count approvals, including the executing owner's implicit vote.
        let (num_approvals, _) = num_approvals_and_rejections(multisig_account, sequence_number);
        if (!has_voted_for_approval(multisig_account, sequence_number, address_of(owner))) {
            num_approvals += 1;
        };
        assert!(num_approvals >= num_signatures_required(multisig_account), error::invalid_argument(ENOT_ENOUGH_APPROVALS));

        // Timelock check — separate from quorum so the error is unambiguous.
        assert!(
            can_execute_with_timelock(multisig_account, sequence_number, num_approvals),
            error::invalid_state(ETIMELOCK_NOT_EXPIRED),
        );

        // If the transaction payload is not stored on chain, verify that the provided payload matches the hashes stored
        // on chain.
        let multisig_account_resource = borrow_global<MultisigAccount>(multisig_account);
        let transaction = multisig_account_resource.transactions.borrow(sequence_number);
        if (transaction.payload_hash.is_some()) {
            let payload_hash = transaction.payload_hash.borrow();
            assert!(
                sha3_256(payload) == *payload_hash,
                error::invalid_argument(EPAYLOAD_DOES_NOT_MATCH_HASH),
            );
        };

        // If the transaction payload is stored on chain and there is a provided payload,
        // verify that the provided payload matches the stored payload.
        if (features::abort_if_multisig_payload_mismatch_enabled()
            && transaction.payload.is_some()
            && !payload.is_empty()
        ) {
            let stored_payload = transaction.payload.borrow();
            assert!(
                payload == *stored_payload,
                error::invalid_argument(EPAYLOAD_DOES_NOT_MATCH),
            );
        }
    }
