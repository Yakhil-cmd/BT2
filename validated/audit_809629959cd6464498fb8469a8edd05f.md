### Title
Bridge Owner Can Instantly Manipulate Operator Set and Threshold Without Timelock, Enabling Immediate Unauthorized Asset Drain — (File: `contracts/service_chain/bridge/BridgeOperator.sol`)

---

### Summary

`BridgeOperator.sol` allows the bridge owner to add/remove operators and change the voting threshold with zero delay. A compromised or malicious owner can atomically lower the `ValueTransfer` threshold to 1, register a malicious operator, and have that operator call `handleKLAYTransfer` / `handleERC20Transfer` with a fabricated request to drain all KAIA and bridged ERC20/ERC721 assets from the bridge in a single block. No grace period exists for users or honest operators to react.

---

### Finding Description

Three `onlyOwner` functions in `BridgeOperator` take effect immediately with no timelock:

**`registerOperator`** — adds an operator instantly: [1](#0-0) 

**`deregisterOperator`** — removes an operator instantly. The contract's own comment acknowledges the timing hazard: [2](#0-1) 

**`setOperatorThreshold`** — changes the vote threshold instantly: [3](#0-2) 

The threshold is read at vote-execution time inside `_voteCommon`: [4](#0-3) 

Because `operatorThresholds` is read live, a threshold reduction takes effect immediately on all in-flight votes for any nonce. The existing test `TestMultiBridgeKLAYTransferMixConfig1` explicitly confirms that lowering the threshold mid-vote allows a single operator to complete a transfer that previously required 2 votes: [5](#0-4) 

The `handleKLAYTransfer` function that releases KAIA is gated only by `onlyOperators` and the vote threshold — both of which the owner can manipulate instantly: [6](#0-5) 

Similarly for ERC20 assets via `handleERC20Transfer`: [7](#0-6) 

The Go-layer bridge manager exposes both `RegisterOperator` and `SetValueTransferOperatorThreshold` with no additional delay: [8](#0-7) 

---

### Impact Explanation

A compromised or malicious bridge owner can drain all KAIA and bridged ERC20/ERC721 assets locked in the bridge contract in a single block:

1. Call `setOperatorThreshold(ValueTransfer, 1)` — threshold drops to 1 immediately.
2. Call `registerOperator(attackerAddr)` — attacker is now a valid operator.
3. Attacker calls `handleKLAYTransfer(fakeHash, victim, attacker, bridgeBalance, freshNonce, blockNum, "")` — bridge sends its entire KAIA balance to the attacker.

The bridge operators are the sole trust anchor for cross-chain value transfer authenticity; there is no on-chain verification that a request actually occurred on the counterpart chain. Whoever controls the operator set controls all bridge funds.

---

### Likelihood Explanation

Requires the owner's private key to be compromised or the owner to act maliciously. However, the complete absence of any timelock means the window for detection and response is zero — all funds can be drained in the same block as the operator manipulation. This is the exact risk the external report identifies: without a grace period, a single key compromise results in total, immediate loss.

---

### Recommendation

Implement a two-step timelock pattern for `registerOperator`, `deregisterOperator`, and `setOperatorThreshold`:

1. **Queue** the change with a timestamp.
2. **Execute** only after a mandatory delay (e.g., 24–48 hours).
3. Allow honest operators or a guardian to **cancel** a queued change during the delay window.

This mirrors the TimeLock pattern referenced in the external report and gives bridge users and honest operators time to react to a compromised owner.

---

### Proof of Concept

```solidity
// Attacker controls owner key.

// Step 1: Lower threshold to 1 (instant, no delay)
bridge.setOperatorThreshold(uint8(VoteType.ValueTransfer), 1);

// Step 2: Register attacker-controlled operator (instant, no delay)
bridge.registerOperator(attackerOperator);

// Step 3: Attacker operator fabricates a value-transfer request
// and drains the bridge's entire KLAY balance in one call.
bridge.handleKLAYTransfer(
    bytes32(0xdeadbeef...),   // fake request tx hash (not verified on-chain)
    victimAddress,            // _from (irrelevant)
    attackerAddress,          // _to — receives funds
    address(bridge).balance,  // _value — entire bridge balance
    unusedNonce,              // _requestedNonce — any nonce above lowerHandleNonce
    block.number,             // _requestedBlockNumber
    ""                        // _extraData
);
// Result: all KAIA in the bridge is transferred to attackerAddress.
```

The same sequence applies to ERC20 assets via `handleERC20Transfer` with `modeMintBurn = true` (minting arbitrary tokens) or `false` (transferring locked tokens).

// TestMultiBridgeKLAYTransferMixConfig1 checks the following:
// - set threshold to 2.
// - the first tx is done.
// - set threshold to 1.

func TestMultiBridgeKLAYTransferMixConfig1(t *testing.T) {
	info := prepareMultiBridgeEventTest(t)
	defer info.sim.Close()

	acc := info.accounts[0]
	to := common.Address{100}

	opts := &bind.TransactOpts{From: acc.From, Signer: acc.Signer, GasLimit: DefaultBridgeTxGasLimit}
	tx, err := info.b.SetOperatorThreshold(opts, voteTypeValueTransfer, 2)
	assert.NoError(t, err)
	info.sim.Commit()
	assert.NoError(t, bind.CheckWaitMined(info.sim, tx))

	nonceOffset := uint64(17)
	sentNonce := nonceOffset
	transferAmount := uint64(100)
	sentBlockNumber := uint64(100000)

	tx = SendHandleKLAYTransfer(info.b, acc, to, transferAmount, sentNonce, sentBlockNumber, t)
	info.sim.Commit()
	assert.NoError(t, bind.CheckWaitMined(info.sim, tx))

	opts = &bind.TransactOpts{From: acc.From, Signer: acc.Signer, GasLimit: DefaultBridgeTxGasLimit}
	tx, err = info.b.SetOperatorThreshold(opts, voteTypeValueTransfer, 1)
	assert.NoError(t, err)
	info.sim.Commit()
	assert.NoError(t, bind.CheckWaitMined(info.sim, tx))

	acc = info.accounts[1]
	tx = SendHandleKLAYTransfer(info.b, acc, to, transferAmount, sentNonce, sentBlockNumber, t)
	info.sim.Commit()
	assert.NoError(t, bind.CheckWaitMined(info.sim, tx))

	for {
		select {
		case ev := <-info.handleCh:
			assert.Equal(t, nonceOffset, ev.HandleNonce)
			return
		case err := <-info.handleSub.Err():
			t.Fatal("Contract Event Loop Running Stop by sub.Err()", "err", err)
		case <-time.After(timeOut):
			t.Fatal("Contract Event Loop Running Stop by timeout")
		}
	}
}

func (bm *BridgeManager) RegisterOperator(bridgeAddr, operatorAddr common.Address) (common.Hash, error) {
	bi, exist := bm.GetBridgeInfo(bridgeAddr)

	if !exist {
		return common.Hash{}, ErrNoBridgeInfo
	}

	bi.account.Lock()
	defer bi.account.UnLock()
	tx, err := bi.bridge.RegisterOperator(bi.account.GenerateTransactOpts(), operatorAddr)
	if err != nil {
		return common.Hash{}, err
	}
	bi.account.IncNonce()

	return tx.Hash(), nil
}

func (bm *BridgeManager) GetOperators(bridgeAddr common.Address) ([]common.Address, error) {
	bi, exist := bm.GetBridgeInfo(bridgeAddr)

	if !exist {
		return nil, ErrNoBridgeInfo
	}

	return bi.bridge.GetOperatorList(nil)
}

func (bm *BridgeManager) SetValueTransferOperatorThreshold(bridgeAddr common.Address, threshold uint8) (common.Hash, error) {
	bi, exist := bm.GetBridgeInfo(bridgeAddr)

	if !exist {
		return common.Hash{}, ErrNoBridgeInfo
	}

	bi.account.Lock()
	defer bi.account.UnLock()
	tx, err := bi.bridge.SetOperatorThreshold(bi.account.GenerateTransactOpts(), voteTypeValueTransfer, threshold)
	if err != nil {
		return common.Hash{}, err
	}
	bi.account.IncNonce()

	return tx.Hash(), nil
}
