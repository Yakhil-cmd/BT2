### Title
Webhook organization used for signature verification is never bound to the repository/commit actually mutated, enabling cross-organization forged commit statuses and unauthorized deploys - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which `GitHubApp` (and therefore which `webhook_secret`) to verify a webhook's HMAC against using an **unverified** field of the very payload it is about to validate — `repository.owner.login` (or `organization.login`). Once the signature check passes, the handlers that actually act on the payload (`PushHandler`, `StatusHandler`, etc.) use a *different* unverified field — `repository.full_name`, or in the case of `StatusHandler`, no repository scoping at all — to decide which `Stack`/`Commit` to mutate. The organization whose secret authenticated the request is never checked against the repository that is actually written to.

### Finding Description [1](#0-0)  `verify_signature` does:
```ruby
github_app = Shipit.github(organization: repository_owner)
verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
```
where `repository_owner` is read straight from the unverified body: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. [2](#0-1) 

`Shipit.github(organization:)` looks up per-organization config, which the docs explicitly allow to have a blank `webhook_secret` for any given org. [3](#0-2) [4](#0-3) 

`verify_webhook_signature` unconditionally returns `true` when the resolved app's `webhook_secret` is blank:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [5](#0-4) 

After the signature check passes, `create` re-parses the body and dispatches to handlers, which independently derive the target repository from `repository.full_name`: [6](#0-5) [7](#0-6) 

`StatusHandler` is even weaker: it does no repository binding at all and matches purely by commit SHA across every stack in the installation:
```ruby
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [8](#0-7) 

**Binding broken:** `organization authenticated by verify_signature (repository.owner.login) == repository/commit actually mutated by the handler (repository.full_name / global sha match)`. This equality is never enforced. The signature only proves the request was signed by *some* configured organization's secret (or, if that organization has no secret configured, proves nothing at all); it does not prove the signer controls the repository named later in the same payload.

### Impact Explanation
In a multi-GitHub-App deployment (a documented, supported configuration — `docs/setup.md` "Using Multiple Github Applications", and `test/dummy/config/secrets_double_github_app.yml` — where per-org `webhook_secret` is explicitly optional/nil), an attacker who knows or discovers that any configured organization has no `webhook_secret` set can send an unsigned POST to `/webhooks` with:
- `repository.owner.login` (or `organization.login`) set to that weakly-configured org, satisfying `verify_signature` unconditionally, and
- `repository.full_name` (for push/PR handlers) or just a `sha` (for `status`) pointing at a completely different, victim organization's stack.

For the `status` event this lets an unauthenticated party inject a `success` `Status` for an arbitrary existing commit SHA in any stack in the installation. `Status#schedule_continuous_delivery` → `Commit#schedule_continuous_delivery` triggers `ContinuousDeliveryJob` when `stack.continuous_deployment?` is enabled, which can lead to an **unauthorized deploy** of that commit. [9](#0-8) [10](#0-9) 

This falls squarely in the Critical impact bucket defined by the rules ("an unauthorized deploy, rollback or merge").

### Likelihood Explanation
This requires: (1) the operator to run the documented multi-organization GitHub App configuration, and (2) at least one configured organization to have a blank `webhook_secret` (explicitly shown as an accepted/optional value in the shipped example configs and setup docs) — an unusual but sponsor-disclosed-as-possible precondition, analogous to the "unusual precondition" downgrade language in the referenced report. No attacker credentials, GitHub App keys, or session are required.

### Recommendation
Verify the signature using the secret bound to the organization that owns the repository actually referenced by `repository.full_name` in every handler (not `repository.owner.login`/`organization.login` alone), and reject webhooks where these two organizations diverge. Additionally, `StatusHandler` (and any handler using global lookups) should scope commit/status lookups to the `Repository`/`Stack` derived from the verified organization, not a global `Commit.where(sha:)` scan. Do not allow `verify_webhook_signature` to return `true` when `webhook_secret` is blank if any organization other than the "no-secret" one exists in the same installation — instead treat a missing secret as "verification not possible" and reject webhooks for events touching cross-referenced repositories.

### Proof of Concept
1. Configure two orgs per `docs/setup.md`'s multi-app schema: `WeakOrg` (no `webhook_secret`), `VictimOrg` (has a `webhook_secret`, hosts stack `victim-org/app` with `continuous_deployment: true` and an existing commit SHA `abc123`).
2. POST to `/webhooks` with header `X-Github-Event: status`, no valid `X-Hub-Signature`, and body:
```json
{
  "repository": { "owner": { "login": "WeakOrg" } },
  "sha": "abc123",
  "state": "success",
  "context": "ci/required"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "WeakOrg")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (absent/invalid) signature header.
4. `StatusHandler` runs `Commit.where(sha: "abc123")`, finds the commit under `victim-org/app`, and creates a `success` `Status`, which — since `victim-org/app` has continuous deployment enabled — schedules an unauthorized deploy of that commit.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
