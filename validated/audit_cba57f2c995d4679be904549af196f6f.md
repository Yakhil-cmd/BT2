### Title
Governance vote of `kip71.gastarget = 0` causes division-by-zero panic in `NextMagmaBlockBaseFee`, halting all Magma-era nodes — (`params/kip71_config.go`)

### Summary

The `kip71.gastarget` governance parameter uses `noopFormatChecker` (accepts any value including zero), while `NextMagmaBlockBaseFee` performs an unchecked integer division by `gasTarget`. A governance vote setting `kip71.gastarget` to `0` causes a Go runtime panic (division by zero) on every subsequent block that has any gas usage, crashing all nodes and halting consensus.

### Finding Description

`Kip71GasTarget` is registered in `kaiax/gov/param.go` with `noopFormatChecker`, meaning any `uint64` value — including `0` — passes validation and can be committed to chain state via a governance vote:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // accepts 0
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` performs no additional cross-parameter check for `Kip71GasTarget` — it falls through to `return nil`:

```go
case gov.Kip71BaseFeeDenominator, gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee,
    ...
    return nil
``` [2](#0-1) 

Once the vote takes effect, every call to `NextMagmaBlockBaseFee` with `parentGasUsed > gasTarget` (i.e., `parentGasUsed > 0`) reaches the following unchecked division:

```go
gasTarget := kc.GasTarget                                          // == 0
...
} else if parentGasUsed > gasTarget {                              // true for any non-empty block
    ...
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))              // PANIC: division by zero
``` [3](#0-2) 

`NextMagmaBlockBaseFee` is invoked from `VerifyMagmaHeader` during block header validation:

```go
expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
``` [4](#0-3) 

The contrast with `Kip71BaseFeeDenominator` is instructive: that parameter has both a `FormatChecker` that rejects `0` **and** a runtime guard inside `NextMagmaBlockBaseFee`:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0          // zero explicitly rejected
    },
``` [5](#0-4) 

```go
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
}
``` [6](#0-5) 

`GasTarget` has neither protection.

### Impact Explanation

After the governance vote activates, `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` panics on every block whose parent had any gas usage and whose `parentBaseFee` is below `upperBoundBaseFee`. Because block header validation is on the critical path for both block import and block production, the Go runtime panic crashes every node. The result is a complete consensus halt: no new blocks can be produced or validated, all pending transactions are frozen, and all KAIA transfers and state transitions are blocked until the chain is manually recovered via an emergency governance fix or hard fork.

### Likelihood Explanation

In `single` governance mode (Mainnet), only the governing node can cast a vote. The governing node is a semi-trusted actor expected to adjust parameters within safe ranges. There is no on-chain or off-chain guard preventing it from voting `kip71.gastarget = 0` — the vote passes format checks, passes consistency checks, and is committed to chain state. An operator mistake (e.g., intending to set a very small target) or a compromised governing key is sufficient to trigger the halt.

### Recommendation

Add a non-zero check to the `FormatChecker` for `Kip71GasTarget`, mirroring the existing guard on `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // prevent division-by-zero in NextMagmaBlockBaseFee
    },
    ...
},
``` [1](#0-0) 

Optionally, add a defensive runtime guard in `NextMagmaBlockBaseFee` analogous to the `BaseFeeDenominator` guard:

```go
if gasTarget == 0 {
    gasTarget = kc.MaxBlockGasUsedForBaseFee  // or some safe fallback
}
``` [7](#0-6) 

### Proof of Concept

1. In `single` governance mode, the governing node casts a vote: `governance_vote("kip71.gastarget", 0)`.
2. The vote passes `NewVoteData` format checks (because `noopFormatChecker` returns `true` for `0`) and `checkConsistency` (falls through to `return nil`).
3. At the next epoch boundary, the parameter is committed: `GasTarget = 0`.
4. The next block `B` is produced with any transactions (`parentGasUsed > 0`).
5. Every node calls `VerifyMagmaHeader(B.BaseFee, B.ParentNumber, B.ParentBaseFee, B.ParentGasUsed)`.
6. Inside `NextMagmaBlockBaseFee`: `parentGasUsed > 0 == gasTarget`, so the `else if parentGasUsed > gasTarget` branch is taken.
7. `x.Div(x, new(big.Int).SetUint64(0))` — Go's `big.Int.Div` panics on a zero divisor.
8. All nodes crash. Consensus halts. [8](#0-7) [9](#0-8)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
