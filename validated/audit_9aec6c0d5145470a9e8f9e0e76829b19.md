## Title
Wallet Accepts and Permanently Registers Peer-Supplied Shared-Address Definitions Without Verifying They Actually Enforce Multi-Party Control - (File: wallet_defined_by_addresses.js)

## Summary
The Boba NFTBridge report describes a bridge that trusts a user-deployed, unauditable paired contract to gate token custody; once the pairing is registered it can never be revised, so hidden malicious logic in the paired contract lets an attacker steal the bridged asset permanently. The same "trust an externally supplied definition of custody, register it irreversibly, without verifying its actual security semantics" pattern exists in `ocore`'s multi-device "shared address" (multisig wallet) negotiation, reachable by any paired device.

## Finding Description
A shared (multisig) address in Obyte is nothing more than an address whose spending condition (`definition`) is an arbitrary boolean formula over member addresses (`and`, `or`, `r of set`, `weighted and`, `address`, etc.). When one device proposes a shared address, the counterpart device receives a `new_shared_address` message and processes it in `handleNewSharedAddress` [1](#0-0) .

The validation performed there only checks:
- that `body.address` matches `chash(body.definition)` [2](#0-1) 
- that every claimed signer's address is syntactically valid and matches the address leaf found at the same path in the definition tree via `extractAddressPathsFromDefinition` [3](#0-2) 
- that the local device is a genuine member (`determineIfIncludesMeAndRewriteDeviceAddress`) [4](#0-3) 
- generic structural/complexity validity of the definition via `Definition.validateDefinition`, called from `validateAddressDefinition` [5](#0-4) 

Nowhere is it verified that the boolean logic of the definition actually requires the co-signer's (victim's) participation to authorize a spend — i.e., that the top-level combinator is an `and`/`r of set` with an adequate threshold rather than an `or` that lets any single listed address (including one wholly controlled by the remote peer) spend unilaterally. The code even contains an acknowledged, unaddressed gap: `// fix: 1. check that my address is referenced in the definition` directly above `validateAddressDefinition` [6](#0-5) .

Once accepted, the definition is written permanently to `shared_addresses` via `addNewSharedAddress` [7](#0-6) , and there is no mechanism afterward to revise or pause that address's semantics — exactly the "registration is permanent, checklist-only defense" failure mode from the report.

## Impact Explanation
Because the wallet only confirms that a listed leaf address is "present" in the formula rather than that it is required, an attacker acting as a paired device can construct a `definition` such as `["or", [["address","VICTIM"], ["address","ATTACKER"]]]` and present it, together with a `signers` map that satisfies the path-matching checks, as a "shared/multisig address." The victim's wallet passes all current checks and registers the address as a legitimate shared address. Any funds subsequently sent to that address (e.g., by the victim believing multi-party approval is required, as used in arbiter/prosaic contract flows via `arbiter_contract.js` `createSharedAddressAndPostUnit`) can be spent unilaterally by the attacker's own key at any time, with no way to reverse the registration or protect already-deposited funds — a direct funds-loss outcome analogous to the bridge's "permanently unbridgeable / stolen tokens" scenario.

## Likelihood Explanation
This is reachable by any device that has paired with the victim (the report's explicit "paired device" actor) simply by sending a crafted `new_shared_address` message — no special privileges, no on-chain cost, and no cooperation from a third party is required. The only friction is that a victim (or victim's software) must choose to fund the resulting address, which is the normal, expected flow for shared/multisig addresses (e.g., arbiter escrow, joint wallets).

## Recommendation
`validateAddressDefinition`/`handleNewSharedAddress` should not merely confirm that the local member's address appears somewhere in the tree; they must verify that the effective authorization requires genuine cooperation of all expected co-signers — e.g., reject definitions whose local member path is reachable through a disjunction (`or`) that also has an always-satisfiable, attacker-controlled alternative branch, or otherwise compute/display the true minimal quorum needed to spend and require explicit user confirmation of that computed quorum (not just the raw signer list) before the address is registered and funded.

## Proof of Concept
1. Attacker pairs with victim's device (standard chat pairing).
2. Attacker sends `new_shared_address` with:
   - `definition = ["or", [["address","VICTIM_ADDR"], ["address","ATTACKER_ADDR"]]]`
   - `address = chash(definition)`
   - `signers = { "r.0": {address: VICTIM_ADDR, device_address: VICTIM_DEV}, "r.1": {address: ATTACKER_ADDR, device_address: ATTACKER_DEV} }`
3. `handleNewSharedAddress` passes all checks (chash matches, each signer address matches its path leaf, every leaf has a signer, victim's own address is present) and calls `addNewSharedAddress`, permanently persisting the address as a "shared address" [8](#0-7) .
4. Victim (or an application built on top, e.g. an arbiter contract escrow) sends funds to this address believing both parties must cosign.
5. Attacker alone signs and spends all funds from the address, since the actual definition only requires `ATTACKER_ADDR`'s signature via the `or` branch — no cooperation from the victim is needed, and the registration cannot be altered or paused afterward.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function extractAddressPathsFromDefinition(arrDefinition) {
	var result = {};
	function traverse(arr, path) {
		if (!Array.isArray(arr) || arr.length < 2) return;
		var op = arr[0];
		var args = arr[1];
		switch (op) {
			case 'or':
			case 'and':
				if (Array.isArray(args))
					for (var i = 0; i < args.length; i++)
						traverse(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				result[path] = args;
				break;
			case 'hash':
				result[path] = 'secret';
				break;
			case 'in merkle':
				result[path] = ''; // empty address
				break;
		}
	}
	traverse(arrDefinition, 'r');
	return result;
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
