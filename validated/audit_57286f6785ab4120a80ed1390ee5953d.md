### Title
Open redirect via unfiltered `omniauth.origin` enabling forced OAuth completion redirect - (File: app/controllers/shipit/github_authentication_controller.rb)

### Summary
`GithubAuthenticationController#callback` takes `request.env['omniauth.origin']`, which is attacker-controllable via the `origin` query parameter on Shipit's own `/github/auth` OmniAuth entry point, and passes it unfiltered to `redirect_to`. No same-host/relative-path validation is performed before the redirect, allowing an attacker to redirect an authenticating victim's browser to an arbitrary external host immediately after a real, successful GitHub OAuth login.

### Finding Description
The broken binding is: `return_url` (used in `redirect_to(return_url)`) should be constrained to `return_url ∈ {relative paths within Shipit::Engine routes}`, but in fact `return_url == request.env['omniauth.origin']`, which is fully attacker-controlled and unconstrained.

Code path: [1](#0-0)  shows `callback` reading `return_url = request.env['omniauth.origin'] || root_path`, then unconditionally calling `redirect_to(return_url)` after setting `session[:user_id]` and `session[:authenticated] = true`.

The `origin` value is populated by the OmniAuth middleware from the `origin` request parameter used when the OAuth flow is initiated. Shipit mounts `OmniAuth::Builder` with the standard `:github` strategy at `/github/auth` in [2](#0-1) , and Shipit's own `force_github_authentication` code legitimately builds `origin` from `request.original_url` (always same-host) in [3](#0-2) . However, nothing prevents an attacker from directly sending a victim a link to `/github/auth?origin=//evil.example.com` (or `https://evil.example.com`) instead of relying on the app-generated origin. Once the victim completes the real GitHub OAuth handshake, control returns to `GithubAuthenticationController#callback`, which sets the Shipit session cookie and then redirects the victim's browser to the attacker-supplied `return_url` with no validation that it is a same-host relative path.

No existing guard checks this: `force_github_authentication` only affects how `origin` is generated for *internally generated* redirects, it does not prevent an attacker from supplying their own `origin` value directly to `/github/auth`; there is no sanitization in `callback` itself.

### Impact Explanation
After completing a legitimate OAuth login, the victim's browser is redirected off Shipit's domain to an attacker-chosen host while the Shipit session cookie has just been set. This matches the "session fixation / forced OAuth completion" High-severity category: an attacker can force completion of the victim's OAuth login and control the post-login navigation to stage further phishing or social-engineering steps (e.g., presenting a page that appears to continue the Shipit flow). The vulnerability is repeatable against any victim who clicks such a link and does not itself expose the Shipit session cookie (cookie remains scoped to Shipit's domain), but it does allow arbitrary open redirect from a trusted OAuth completion flow.

### Likelihood Explanation
Attacker cost is low: they need only craft and distribute a link of the form `https://<shipit-host>/github/auth?origin=//evil.example.com` (or an absolute external URL) to a victim who has (or is willing to grant) GitHub OAuth access to Shipit. No Shipit secrets, privileged role, or repository access are required — this is exploitable by any unprivileged internet user able to get a victim to click a link, satisfying the attacker model in scope.

### Recommendation
Validate `return_url` before redirecting: only allow relative paths beginning with a single `/` (reject scheme-relative `//` and absolute URLs), e.g. via `URI.parse` host-check or Rails' safe-redirect helpers, falling back to `root_path` for anything that doesn't match Shipit's own routes.

### Proof of Concept
In `test/controllers/github_authentication_controller_test.rb` (existing suite location), add a minitest case:
1. Set `@request.env['omniauth.origin'] = '//evil.example.com'` and a valid `omniauth.auth` hash.
2. Call `get :callback`.
3. Assert `response.location` (or `@response.headers['Location']`) does NOT equal `'//evil.example.com'` and instead resolves to a same-host Shipit path (e.g. `assert_no_match(%r{\A//}, response.redirect_url)` and/or `assert response.redirect_url.start_with?(root_url)`).

This test currently fails against the unmodified `callback` method, proving the open redirect / forced OAuth completion behavior described.

    def callback
      return_url = request.env['omniauth.origin'] || root_path
      auth = request.env['omniauth.auth']

      return render('failed', layout: false) if auth.blank?

      session[:user_id] = sign_in_github(auth)

      # We need to set this so that the /events and /sidekiq endpoint
      # which leverage `UserRequiredMiddleware` will recognize the user
      # is authenticated.
      session[:authenticated] = true

      redirect_to(return_url)
    end
