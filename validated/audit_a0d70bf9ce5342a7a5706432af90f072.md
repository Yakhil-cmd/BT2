### Title
`ClosedHandler` archives a `ReviewStack` resolved solely from attacker-controlled `repository.full_name`, independent of the org used to verify the webhook signature - ([File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App/`webhook_secret` to verify against based on `repository.owner.login` (or `organization.login`), while `ClosedHandler` (via `ReviewStackAdapter`) resolves and tears down the `Stack`/`ReviewStack` using an entirely separate, independently attacker-controlled field: `repository.full_name`. Because these two fields are never cross-checked, an attacker who owns any onboarded org (or an org configured with no `webhook_secret`) can forge a `pull_request` `closed` webhook whose `repository.owner.login` matches their own org (satisfying signature verification) but whose `repository.full_name` names a different org's repository, causing that other org's active `ReviewStack` to be archived/deprovisioned.

### Finding Description
The binding that should hold is: `verifying_org` (the org whose `webhook_secret` successfully validated `X-Hub-Signature`) `==` `owning_org` (the org that owns the `Repository`/`Stack` being mutated by `params.repository.full_name`).

Code path:
- `WebhooksController#verify_signature` derives the org for signature verification from `repository_owner`, which reads `params.dig('repository', 'owner', 'login')` (fallback `organization.login`), and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [1](#0-0) .
- `Shipit.github(organization:)` looks up the per-org config (including `webhook_secret`) keyed by that org name [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally if that org's `webhook_secret` is blank/nil [3](#0-2) .
- Once verified, `WebhooksController#create` dispatches the raw parsed JSON to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [4](#0-3) .
- `ClosedHandler#process` calls `review_stack.archive!`, and `#repository`/`#review_stack` resolve the target purely from `params.repository.full_name` — with no reference back to which org's secret verified the request [5](#0-4) .
- `Repository.from_github_repo_name` does a plain DB lookup by `owner`/`name` parsed out of `full_name`, with no relation to the verifying org [6](#0-5) .
- `ReviewStackAdapter#archive!` unconditionally deprovisions and archives the resolved stack for a legitimate, unarchived `stack` [7](#0-6) .

Attacker's exact request: a `POST /webhooks` with header `X-Github-Event: pull_request`, a valid `X-Hub-Signature` computed with the attacker's own org's `webhook_secret` (or any value if that org's `webhook_secret` is unset), and a JSON body where `repository.owner.login` = attacker's own org (e.g., `"attacker-org"`) but `repository.full_name` = the victim org's actual tracked repo (e.g., `"victim-org/victim-repo"`), `action: "closed"`, and a `number`/`pull_request` matching (or not even matching, since `ReviewStackAdapter#stack` is looked up by `environment` derived from PR number, so the attacker only needs to guess/know the victim's open PR number) an active review stack's PR number.

Existing guards do not close this gap: `verify_signature` only proves the request was signed by *some* org's secret, not that it's authorized for the specific `repository.full_name` in the body; `drop_unhandled_event` and `ExplicitParameters` schema only check shape, not cross-tenant ownership; there is no `Repository`-level check that `owner` matches `repository_owner` used for signature verification anywhere in this chain.

### Impact Explanation
An unprivileged GitHub user who owns/administers any org onboarded to the same Shipit instance (or any org configured without a `webhook_secret`) can force teardown of another org's active `ReviewStack` (deprovisioning its instance and archiving the stack) by simply naming the victim's `repository.full_name` in a forged payload verified through their own org. This is a cross-tenant "payload for one repository mutating another's stack" — matching the Critical impact category. It is fully repeatable against any tracked repository/review stack whose full name the attacker knows (public repo names), across arbitrary victim orgs sharing the Shipit instance.

### Likelihood Explanation
Preconditions: multi-tenant Shipit deployment with more than one org configured under `secrets.github` (as documented/supported per `config/secrets.development.shopify.yml` showing `somegithuborg`/`someothergithuborg`), and the attacker being an onboarded member of at least one of those orgs (or any org with `webhook_secret` unset — which the docs' example templates show as a valid/default state, `webhook_secret: # nil`). No Shipit session, API token, or GitHub App private key is needed — only the ability to compute an HMAC with a secret the attacker legitimately possesses (their own org's) or to send an unsigned/blank-secret request. This is a low-cost, purely-HTTP attack requiring no privileged access to the victim org.

### Recommendation
In `WebhooksController` (or a shared handler concern), after verifying the signature against `repository_owner`, ensure the resolved `Repository`/`Stack` for `repository.full_name` actually belongs to that same verified org (i.e., add an explicit check `repository.owner == repository_owner` before any handler mutates state), and reject/no-op the event if they diverge instead of trusting `params.repository.full_name` unconditionally.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "cross-org forged pull_request closed cannot archive another org's review stack" do
  # Setup: victim org "victimorg" owns repo victimorg/victim-repo with an active ReviewStack.
  # Attacker org "attackerorg" has no configured webhook_secret (or attacker knows its secret).
  victim_repo = shipit_repositories(:shipit) # owner: "victimorg" in this scenario
  victim_repo.update!(owner: "victimorg", name: "victim-repo", review_stacks_enabled: true,
                       provisioning_behavior: :allow_all)
  stack = create_review_stack_for(victim_repo, pr_number: 42) # active, unarchived

  request.headers['X-Github-Event'] = 'pull_request'
  forged_payload = payload_parsed(:pull_request_closed)
  forged_payload["repository"]["owner"]["login"] = "attackerorg"     # verifying org
  forged_payload["repository"]["full_name"] = "victimorg/victim-repo" # owning org's repo
  forged_payload["number"] = 42

  Shipit.github(organization: "attackerorg").stubs(:verify_webhook_signature).returns(true)

  assert_no_difference -> { Shipit::Stack.not_archived.count } do
    post :create, body: forged_payload.to_json, as: :json
  end

  assert_not stack.reload.archived?, "victim org's stack must not be archived by a request verified via a different org"
end
```
Both sides of the binding: `verifying_org = "attackerorg"`, `owning_org = "victimorg"` — they diverge, and the test asserts the mutation must not occur; currently it does occur because no such check exists.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
