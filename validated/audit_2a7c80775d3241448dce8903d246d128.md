### Title
Unfiltered `machine.environment` from repository-controlled `shipit.yml` overwrites `GITHUB_TOKEN`/`GIT_ASKPASS` in spawned commands - (File: lib/shipit/task_commands.rb)

### Summary
`TaskCommands#env` merges `deploy_spec.machine_env` — a hash taken verbatim from the repository's `shipit.yml` (`machine.environment`) — directly into the environment hash passed to `Command.new`, with no key allowlist. Because this merge happens *after* the built-in `GITHUB_TOKEN`/`GIT_ASKPASS` values are set, a value in a PR/branch's `shipit.yml` can override these sensitive keys before `PTY.spawn` executes.

### Finding Description
The broken binding: the set of env **keys** Shipit intends to control/protect (`GITHUB_TOKEN`, `GITHUB_DOMAIN`, `GIT_ASKPASS`, `BUNDLE_PATH`, etc., set in `Commands#base_env` [1](#0-0)  and `TaskCommands#env` [2](#0-1) ) should equal the set of keys that remain those Shipit-controlled values in the final hash reaching `PTY.spawn`. In reality it does not: `TaskCommands#env` does `super.merge(@stack.env).merge({...fixed keys...}).merge(deploy_spec.machine_env).merge(@task.env)` — `deploy_spec.machine_env` is merged *last but one*, after `GITHUB_TOKEN`/`GIT_ASKPASS` are already in the hash, so any key collision lets the attacker's value win [2](#0-1) .

`deploy_spec.machine_env` is defined as `config('machine', 'environment') || {}` with no filtering [3](#0-2) , and `config` in `DeploySpec::FileSystem` is populated by parsing the repository's `shipit.yml` file located and loaded via `config_file_path`/`load_config`/`read_config` (`SafeYAML.load(path.read)`) [4](#0-3) [5](#0-4) . This is fundamentally different from `deploy_variables`/`rollback_variables`, which are explicitly allowlist-filtered via `filter_deploy_envs`/`filter_rollback_envs` using `EnvironmentVariables#permit` before being exposed [6](#0-5)  — no equivalent filter exists for `machine_env`.

The resulting hash flows into `Command.new(command_line, env:, chdir: steps_directory)` in `perform`/`install_dependencies` [7](#0-6) , then `Command#unbundled_env` does `BASE_ENV.merge('PATH' => ...).merge(@env.stringify_keys)` [8](#0-7) , and `Command#start` calls `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` [9](#0-8) . Since `@env.stringify_keys` is the last merge and is unrestricted, whatever key is in the attacker's `machine.environment` map — including `GITHUB_TOKEN`, `GIT_ASKPASS`, `BUNDLE_GEMFILE` — wins in the final `PTY.spawn` environment.

To trigger this, an attacker only needs to open a PR / push a branch containing a `shipit.yml` (or `.shipit/shipit.yml`) with:
```yaml
machine:
  environment:
    GITHUB_TOKEN: "attacker-value"
```
on a review-stack branch that Shipit deploys/builds using `DeploySpec::FileSystem` (constructed from `@task.working_directory`, i.e., the checked-out repository) [10](#0-9) . No webhook signature check, `verify_webhook_signature`, or `EnvironmentVariables#permit`-style guard applies to `machine.environment`, since it is a machine/deploy-host configuration key not covered by the deploy/rollback variable allowlist.

### Impact Explanation
An attacker who can merely open a PR or push a branch that Shipit builds as a review stack can overwrite `GITHUB_TOKEN` (redirecting git authentication to an attacker-controlled value/endpoint or causing token exfiltration through crafted `GIT_ASKPASS`/`credential.helper`-adjacent tricks), `GIT_ASKPASS` (arbitrary executable substituted for the askpass helper, achieving RCE on the deploy host during the next `git` invocation using this env), or `BUNDLE_GEMFILE`/`RUBYOPT`-style variables (redirecting Bundler/Ruby loading to attacker-controlled files for RCE). This matches the Critical category: "RCE on the deploy host via `Command`/`PTY.spawn`" and "exfiltration of `GITHUB_TOKEN`". It is repeatable per-PR/branch against any repository configured under this Shipit instance, since the flaw is in generic engine code (`TaskCommands#env`, `DeploySpec#machine_env`), not per-repo configuration.

### Likelihood Explanation
The only precondition is the ability to add/modify a `shipit.yml` on a branch/PR that gets deployed or has its dependencies/tasks run (e.g., review stacks), which the threat model explicitly grants to an unprivileged attacker (fork PR author). No secrets, sessions, or privileged roles are required. The attack is low-cost (a single YAML edit) and fully repeatable.

### Recommendation
Restrict `machine.environment` (and any repository-controlled env hash) to a fixed allowlist of safe variable names, or filter it through `EnvironmentVariables#permit` against an explicit list of permitted keys, disallowing overriding of any key already defined by `Commands#base_env`/`TaskCommands#env` (e.g., `GITHUB_TOKEN`, `GITHUB_DOMAIN`, `GIT_ASKPASS`, `BUNDLE_*`). Alternatively, merge `deploy_spec.machine_env` *before* the built-in sensitive keys so it can never clobber them, and additionally reject/strip any attacker-supplied key matching Shipit's reserved/base environment variable names in `Command#unbundled_env`.

### Proof of Concept
Minitest plan (in `test/lib/shipit/task_commands_test.rb`, illustrative — not executed here):
```ruby
test "#env does not allow machine_env to override GITHUB_TOKEN" do
  task = shipit_tasks(:cyclimse_deploy) # existing fixture task
  commands = TaskCommands.new(task)
  commands.deploy_spec.stubs(:machine_env).returns('GITHUB_TOKEN' => 'attacker-value')

  env = commands.env

  refute_equal 'attacker-value', env['GITHUB_TOKEN'],
    "machine_env from repository-controlled shipit.yml must not override GITHUB_TOKEN"
end
```
Assert on both sides of the binding: before the fix, `env['GITHUB_TOKEN'] == 'attacker-value'` (attacker-controlled value present in the hash reaching `Command#unbundled_env`/`PTY.spawn`); after a correct fix, `env['GITHUB_TOKEN']` must remain the value produced by `Commands#base_env` (`github.token`), proving the allowlist/ordering guard rejects the override.

      @out = @pid = nil

        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)

      rescue Errno::EACCES

      end
      @started = true
      self
    end
