### Title
Naming convention bypass of LLM-based diff review via `SKIP_PATH_PATTERNS`/`SKIP_FILE_SUFFIXES` in `_is_reviewable_source()` - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_is_reviewable_source()` unconditionally excludes any file whose path contains a component in `SKIP_PATH_PATTERNS` (e.g. `vendor/`, `node_modules/`) or whose name ends in a `SKIP_FILE_SUFFIXES` entry (e.g. `.min.js`, `_pb2.py`, `.pb.go`) from `extract_file_paths_from_diff` and `parse_diff_into_files`. Since these are the only two functions that feed diff content into the LLM-based review pipeline (Stop-hook diff review, commit review, push-sweep), an attacker who can get Claude to write or modify a file matching one of these naming conventions permanently removes that file's content from LLM security review.

### Finding Description
`_is_reviewable_source` gates content on path/suffix matching before extension checks: [1](#0-0)  This filter is applied identically in `extract_file_paths_from_diff` [2](#0-1)  and `parse_diff_into_files` [3](#0-2) , which are the sole extraction points feeding `get_git_diff` output into `analyze_code_security`/`agentic_review` in `security_reminder_hook.py` (Stop hook, commit-review, and push-sweep all reuse this pair). A file like `evil.min.js`, `payload_pb2.py`, `bar.pb.go`, or anything under a `vendor/` or `node_modules/` path segment written with real malicious logic is silently dropped before ever reaching the LLM reviewer — permanently, on every subsequent Stop/commit/push review, since the filter is name/path-based rather than content-based.

However, the companion pattern-based layer is NOT gated by this filter: `check_patterns(file_path, content)` is invoked directly from the PostToolUse handler on the raw `tool_input` content via `extract_content_from_input`, and its matching logic (`path_check`, `substrings`, `regex`) operates on the literal file path and content with no reference to `SOURCE_CODE_EXTENSIONS`, `SKIP_PATH_PATTERNS`, or `SKIP_FILE_SUFFIXES` [4](#0-3) . So any payload that matches a known `SECURITY_PATTERNS` regex/substring (hardcoded secrets, `os.system`, `eval`, SQL/command injection idioms, etc.) is still caught at write-time regardless of filename.

The exploitable gap is therefore narrower than "complete bypass of both layers": it is a complete and permanent bypass of the **LLM-based semantic review** (Stop hook, commit review, push-sweep) for any file matching the skip list, while the fast regex layer remains an independent backstop for the subset of malicious patterns it already knows to look for. Any malicious logic that is semantically dangerous but doesn't match a fixed regex (the entire reason the LLM layer exists) will never be reviewed if placed in a matching file.

### Impact Explanation
An attacker/compromised agent can durably hide a backdoor from the LLM diff-review layer purely via a naming convention — e.g. writing `child_process.exec(userInput)`-style logic disguised inside `dist/app.min.js`, or embedding a Python `os.system` call in a file named `foo_pb2.py`, or dropping a malicious script anywhere under a path containing `vendor/`. Because `extract_file_paths_from_diff`/`parse_diff_into_files` are shared by every LLM review surface (Stop hook, `handle_commit_review_posttooluse`, push-sweep), this exclusion is not a one-time miss but a standing blind spot for the session's/repo's lifetime. This is a real, scoped trust-boundary gap in the security-guidance plugin's defense-in-depth model, though it does not defeat the independent regex-based PostToolUse layer for patterns that layer already recognizes.

### Likelihood Explanation
Feasibility is high and requires no privilege beyond normal Write/Edit tool use: the attacker only needs to influence the file path/name used for a malicious write (e.g. via prompt injection steering Claude to "regenerate the protobuf stub" or "update the vendored minified bundle"). No approval bypass, workspace escape, or credential is needed — it is a pure filename/path choice at write time, fully within the existing tool surface.

### Recommendation
Do not use `SKIP_PATH_PATTERNS`/`SKIP_FILE_SUFFIXES` as a hard, unconditional exclusion from LLM review. Options: (1) restrict the skip-list exclusion to files that are provably vendored/generated (e.g. verify via `.gitattributes` `linguist-generated`, checksum against a known upstream, or only skip when the file existed identically before the session's baseline rather than when newly created/modified by Claude in-session); (2) at minimum, never skip a file that is newly created (untracked at baseline) or whose diff shows it was fully rewritten, since that is exactly the case where Claude/an attacker authored fresh content under a "trusted-looking" name; (3) route skip-list files through the pattern-based `check_patterns` layer even when excluded from the LLM layer, ensuring some form of review always applies.

### Proof of Concept
Unit test in `plugins/security-guidance/hooks/` test suite:
```python
from gitutil import parse_diff_into_files, extract_file_paths_from_diff

DIFF = """diff --git a/dist/evil.min.js b/dist/evil.min.js
new file mode 100644
index 0000000..1234567
--- /dev/null
+++ b/dist/evil.min.js
@@ -0,0 +1,2 @@
+// looks like build output
+require('child_process').exec(process.env.PAYLOAD);
"""

def test_min_js_backdoor_excluded_from_review():
    assert extract_file_paths_from_diff(DIFF) == []
    assert parse_diff_into_files(DIFF) == []
```
Expected assertion: both extraction functions return empty, confirming `dist/evil.min.js` (and analogously `foo_pb2.py`, `vendor/backdoor.py`) never reaches `analyze_code_security`/`agentic_review`. A companion assertion should show `check_patterns("dist/evil.min.js", content)` still fires for `exec(` if that substring is in `SECURITY_PATTERNS`, to demonstrate the pattern layer is the only remaining coverage and is limited to known signatures.

def _is_reviewable_source(file_path):
    # Normalize for component matching: a path like `.next/x.js` or
    # `pkg/node_modules/y.ts` should both be excluded; matching against
    # `'/' + path` lets each pattern be checked as `'/' + p in '/' + path`
    # without false-positiving on `rebuild/` matching `build/`.
    norm = "/" + file_path.replace("\\", "/")
    if any(("/" + p) in norm for p in SKIP_PATH_PATTERNS):
        return False
    if file_path.endswith(SKIP_FILE_SUFFIXES):
        return False
```

def check_patterns(file_path, content):
    """Check if file path or content matches any security patterns. Returns ALL matches."""
    normalized_path = file_path.lstrip("/")
    matches = []

    for pattern in list(SECURITY_PATTERNS) + extensibility.user_patterns():
        # path_filter is a gate: when present, the rule only applies to
        # matching paths. Distinct from path_check, which is itself a
        # positive match condition (e.g. .github/workflows/).
        if "path_filter" in pattern:
            try:
                if not pattern["path_filter"](normalized_path):
                    continue
            except Exception:
                continue

        matched = False

        if "path_check" in pattern:
            try:
                if pattern["path_check"](normalized_path):
                    matched = True
            except Exception:
                pass

        if not matched and "substrings" in pattern and content:
            for substring in pattern["substrings"]:
                if substring in content:
                    matched = True
                    break

        if not matched and "regex" in pattern and content:
            try:
                if re.search(pattern["regex"], content):
                    matched = True
            except Exception:
                pass

        if matched:
            matches.append((pattern["ruleName"], pattern["reminder"]))

    return matches
```
