### Title
Server-Side Request Forgery in arbiter contract flow — attacker-chosen counterparty can force unvalidated HTTP requests to arbitrary hosts (`File: arbiter_contract.js`)

### Summary
The BaSyx advisory describes an SSRF where a remote, unauthenticated party can cause the server to make blind outbound HTTP requests to a destination it does not validate. In `ocore`, `arbiter_contract.js` contains an analogous pattern: when handling an arbiter contract (initiated by a `peer_address`/counterparty who is not privileged), the wallet resolves an "arbstore" URL via the hub for the attacker-influenced `arbiter_address` and then issues a raw HTTP `POST` to that URL with no validation of scheme, host, or target (no allow-list, no blocking of private/internal/metadata IP ranges).

### Finding Description
`getArbstoreAddresses()` retrieves a URL string (`hub/get_arbstore_url`) for an `arbiter_address` supplied as part of a private-payment contract negotiation, and immediately passes that URL into `httpRequest()`: [1](#0-0) 

`httpRequest()` builds an `http.request`/`https` POST call directly from the resolved `host` with no validation that the destination is a legitimate, external, non-internal address (no blocking of `localhost`, RFC1918 ranges, or cloud metadata IPs such as `169.254.169.254`): [2](#0-1) 

`fillArbstoreAddresses()` is invoked as part of processing/creating an arbiter contract, where the `arbiter_address` field originates from the contract data exchanged between counterparties (`createAndSend`, `store`, `respond` all persist/forward `arbiter_address`, which is attacker-influenceable, being negotiated peer-to-peer over `arbiter_contract_offer` / `arbiter_contract_shared` device messages): [3](#0-2) [4](#0-3) [5](#0-4) 

Because the URL to be fetched is not pinned to a known-safe arbstore domain or otherwise validated (only its later JSON response is parsed for `error`), a party controlling the `arbiter_address`'s hub-published data can steer the victim's node into issuing outbound `POST` requests to arbitrary hosts — this is the same root cause as the BaSyx advisory (CWE-918): failure to validate the destination URI before dispatching an authenticated/privileged HTTP call.

### Impact Explanation
An attacker acting as the private-payment counterparty (or controlling/spoofing the arbstore metadata reachable via the hub for a chosen `arbiter_address`) can force a victim's wallet process to perform blind HTTP `POST` requests to internal services or cloud metadata endpoints (e.g., IMDS), potentially exfiltrating credentials/tokens reachable only from the victim's host/network, or interacting with internal APIs that trust requests originating from that host. This does not by itself cause unauthorized spending or double-spend, but it satisfies the "node/wallet unable to safely process untrusted destinations" class of impact via network pivoting, matching the reachable channel "private-payment counterparty."

### Likelihood Explanation
Likelihood is moderate: the flow requires the victim to be engaged in an arbiter-contract negotiation (a normal wallet feature) with a counterparty who controls or spoofs the `arbiter_address`'s hub-registered arbstore URL. No additional privilege beyond being a private-payment counterparty is required, and the request is triggered automatically by normal contract lifecycle calls (`getAppealFee`, `fillArbstoreAddresses`) without user confirmation of the destination.

### Recommendation
Validate the resolved arbstore URL before use in `httpRequest()`: enforce an `https://` scheme, resolve and reject requests to private/loopback/link-local IP ranges (including `169.254.169.254`) and non-public hostnames, and/or require the arbstore host to match an allow-list of known arbstore domains rather than trusting arbitrary hub-supplied data tied to a counterparty-chosen `arbiter_address`.

### Proof of Concept
1. Attacker sets up (or compromises) a hub-registered arbstore entry for an address they control, with `arbstore_url` pointing to `http://169.254.169.254/latest/meta-data/` or an internal-only service URL.
2. Attacker proposes/negotiates an arbiter contract with the victim using this `arbiter_address` (`createAndSend` → `arbiter_contract_offer` device message).
3. Victim's wallet later calls `fillArbstoreAddresses()` / `getAppealFee()`, which resolves the URL via `hub/get_arbstore_url` and calls `httpRequest(url, ...)` performing a `POST` with no destination validation, causing the victim's node to reach the attacker-chosen internal target. function getArbstoreAddresses(arbiter_address, cb) {
	device.requestFromHub("hub/get_arbstore_url", arbiter_address, function(err, url){
		if (err)
			return cb(err);
		device.requestFromHub("hub/get_arbstore_address", arbiter_address, function(err, arbstore_address){
			if (err) {
				return cb(err);
			}
			httpRequest(url, "/api/get_device_address", "", function(err, arbstore_device_address) {
				if (err) {
					console.warn("no arbstore_device_address", err);
					return cb(err);
				}
				cb(null, { arbstore_address, arbstore_device_address });
			});
		});
	});
}

function getAppealFee(hash, cb) {
	getByHash(hash, function(objContract){
		var command = "hub/get_arbstore_url";
		var address = objContract.arbiter_address;
		if (objContract.arbstore_address) {
			command = "hub/get_arbstore_url_by_address";
			address = objContract.arbstore_address;
		}
		device.requestFromHub(command, address, function(err, url){
			if (err)
				return cb("can't get arbstore url:", err);
			httpRequest(url, "/api/get_appeal_fee", "", function(err, resp) {
				if (err)
					return cb(err);
				cb(null, resp);
			});
		});
	});
}

function httpRequest(host, path, data, cb) {
	var reqParams = Object.assign(url.parse(host),
		{
			path: path,
			method: "POST",
			headers: {
				"Content-Type": "application/json",
				"Content-Length": (new TextEncoder().encode(data)).length
			}
		}
	);
	var req = http.request(
		reqParams,
		function(resp){
			var data = "";
			resp.on("data", function(chunk){
				data += chunk;
			});
			resp.on("end", function(){
				try {
					data = JSON.parse(data);
					if (data.error) {
						return cb(data.error);
					}
					cb(null, data);
				} catch (e) {
					cb(e);
				}
			});
		}).on("error", cb);
	req.write(data);
	req.end();
}
