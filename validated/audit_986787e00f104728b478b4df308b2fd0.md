### Title
Signature verification selects the GitHub App/webhook secret from an unverified `repository.owner.login`/`organization.login` field while handlers act on an independent, never-cross-checked `repository.full_name` field - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` picks which organization's `webhook_secret` to use for HMAC verification from a field taken out of the **unverified** request body, while the actual repository/stack that gets mutated is selected from a completely different, also-unverified field (`repository.full_name`) inside the handlers. The HMAC only proves the payload was signed by *some* configured organization's secret; it never proves that the organization whose secret validated the signature is the same organization/repository the handlers subsequently act on.

### Finding Description
`verify_signature` derives the signing organization purely from JSON content, before any signature check: [1](#0-0) [2](#0-1) 

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  # Fallback to the organization sub-object if repository isn't included in the payload
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 

`params` here is populated by Rails' automatic JSON body parsing of the raw, unverified request — the same content that will later be re-parsed and dispatched to handlers in `create`:

```ruby
def create

  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

end
``` [4](#0-3) 

Once dispatched, handlers select the target `Repository`/`Stack` using an entirely different JSON field, `repository.full_name`, which is never compared to `repository_owner`: [5](#0-4) [6](#0-5) 

```ruby

end

`verify_webhook_signature` also trivially returns `true` when the selected organization has no `webhook_secret` configured: [7](#0-6) 

```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  algorithm, signature = signature.split("=", 2)
  return false unless algorithm == 'sha1'
  SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
end
```

This means that in any deployment with multiple GitHub organizations configured (a documented, supported multi-tenant setup, e.g. `test/dummy/config/secrets_double_github_app.yml`), where at least one organization is configured with `webhook_secret: nil` (also the documented default, e.g. `config/secrets.development.shopify.yml`), an unprivileged external attacker can:

1. Craft an arbitrary webhook JSON body with `repository.owner.login` (or `organization.login`) set to the org that has no `webhook_secret` — this makes `verify_signature` select that org's `GithubApp` and `verify_webhook_signature` unconditionally returns `true`, regardless of the actual payload content or signature header.
2. In the same payload, set `repository.full_name` to any other repository/stack belonging to a *different*, properly secured organization.
3. Because the handler layer (`Handler#repository_name`, `Repository.from_github_repo_name`) resolves the target stack purely from `repository.full_name` and never checks it against `repository_owner`, the forged event is dispatched against the victim organization's stack — e.g. triggering `PushHandler#process` (`stack.sync_github`), archiving/unarchiving review stacks via `ReviewStackAdapter`, or capturing labels — with no valid credential for that organization ever presented.

### Impact Explanation
This breaks the binding "organization that authenticated == repository that is written." An attacker with no Shipit session, no `ApiClient` token, and no knowledge of the victim organization's `webhook_secret` can spoof GitHub webhook events against arbitrary stacks/repositories owned by a different, secured organization, as long as any other organization in the same Shipit installation is configured without a webhook secret. Depending on handler, this can force unarchival/archival of review stacks, trigger `sync_github` re-fetches, or manipulate PR label state on the victim's stack — i.e., an unauthorized state change on a repository the attacker has no access to, satisfying the "cross-repository writes" / "unauthorized deploy-adjacent action" impact bar (via `PushHandler` triggering `Stack#sync_github`, which can affect deploy candidacy).

### Likelihood Explanation
Requires a specific but realistic and documented configuration: multiple GitHub organizations configured in `Shipit.github`, with at least one lacking a `webhook_secret` (shown as the shipped default in both `config/secrets.development.shopify.yml` and `test/dummy/config/secrets_double_github_app.yml`). Given that webhook secrets are optional per-org and the engine explicitly supports multi-org configuration, this is a plausible production misconfiguration rather than a purely theoretical one. No authentication, session, or GitHub write access is needed by the attacker — only the ability to POST to the public `/webhooks` endpoint.

### Recommendation
Cross-check the organization used for signature verification against the repository actually acted upon: require that `repository.full_name`'s owner match `repository_owner`/`organization.login` before dispatching, or better, resolve the target `Repository`/`Stack` and re-verify that its `owner` equals the organization whose secret validated the signature. Additionally, disallow `webhook_secret` from being unset (`nil`) in any multi-organization deployment, or require it globally, so that an unsecured org cannot be used as a blanket signature bypass for events attributed to other organizations.

### Proof of Concept
Given a Shipit config with two orgs, `victim-org` (has `webhook_secret`) and `attacker-org` (no `webhook_secret`), and a repository `victim-org/secure-repo` with an active stack:

```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything   # ignored, no secret configured for attacker-org

{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/secure-repo"
  }
}
```

- `repository_owner` resolves to `"attacker-org"` → `Shipit.github(organization: "attacker-org")` has no `webhook_secret` → `verify_webhook_signature` returns `true` unconditionally (`lib/shipit/github_app.rb:76-77`).
- `create` dispatches the same payload to `PushHandler`, whose `repository_name` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`) resolves to `"victim-org/secure-repo"`, triggering `stack.sync_github(expected_head_sha: "deadbeef")` on the victim's stack (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`) — with no valid credential ever presented for `victim-org`.

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end
