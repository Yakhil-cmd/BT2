### Title
Division-by-Zero Panic in `consolidatedNode.Split` When Proposer Has Zero Total Staking — (`File: kaiax/staking/staking_info.go`)

---

### Summary

`consolidatedNode.Split()` divides by `totalAmount = StakingAmount + CLStakingAmount` without a zero-guard. When all validators are understaked (triggering the "none are demoted" fallback that qualifies all council members), a proposer with `StakingAmount == 0` and `CLStakingAmount == 0` but a non-nil `CLStakingInfo` causes a `big.Int.Div` panic during `FinalizeState`, halting block finalization on every honest node that processes the block.

---

### Finding Description

`consolidatedNode.Split` in `kaiax/staking/staking_info.go` computes the CN/CL reward split:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    cnAmountBig = big.NewInt(int64(c.StakingAmount))
    clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    ...
}
``` [1](#0-0) 

`Split` is called unconditionally for the block proposer inside `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` whenever `cn.CLStakingInfo != nil`:

```go
cnAmount, clAmount := cn.Split(proposer)   // line 633 / 583
``` [2](#0-1) [3](#0-2) 

Neither call site checks that `cn.StakingAmount + cn.CLStakingInfo.CLStakingAmount > 0` before delegating to `Split`.

The staking amounts stored in `StakingInfo` are in whole KAIA (rounded down from the contract balance). A validator whose CNStaking contract holds < 1 KAIA has `StakingAmount == 0`; a validator whose CL pool holds < 1 KAIA has `CLStakingAmount == 0`. Both can be simultaneously zero while `CLStakingInfo` remains non-nil (the validator is still registered in CLRegistry).

The critical enabler is the **"all understaked → none demoted" fallback** documented and tested in `getDemotedValidatorsIstanbul`:

```go
// "none mode, all demoted"
amounts: []uint64{0, 0, 0, aL, aL},
demoted: numsToAddrs(), // If all are demoted, none are demoted.
``` [4](#0-3) 

And confirmed for the proposer-selection path:

```go
// Note: validators can be qualified with zero stakes, if all are understaked.
amounts: []uint64{0, 0, 0, 0},
``` [5](#0-4) 

When this fallback fires, a validator with `StakingAmount == 0`, `CLStakingAmount == 0`, and `CLStakingInfo != nil` can be selected as proposer. `specWithProposerAndFunds` then calls `cn.Split(proposer)` with `totalAmount == 0`, and Go's `big.Int.Div` panics with "division by zero".

The panic propagates out of `getDeferredRewardFullKore` / `getDeferredRewardFullFlex` → `getDeferredRewardFull` → `GetDeferredReward` → `FinalizeState`. [6](#0-5) 

---

### Impact Explanation

`FinalizeState` is called on every node for every block. A panic there is an unrecovered runtime crash that terminates block processing. Every honest full node that attempts to import the affected block crashes, causing a **persistent chain halt / consensus divergence**: the proposer's node cannot finalize its own block, and all peers that try to sync it crash identically. No KAIA rewards are distributed for that block or any subsequent block until the node is restarted and the root cause resolved.

---

### Likelihood Explanation

Two independent conditions must coincide:

1. **All council validators are understaked** — this is a natural market event (mass unstaking, governance raising `minStake`, or a newly bootstrapped chain). The fallback is explicitly coded and tested.
2. **The selected proposer has `StakingAmount == 0` AND `CLStakingAmount == 0` AND `CLStakingInfo != nil`** — a validator registered in CLRegistry whose both staking contract and CL pool hold < 1 KAIA. This is achievable by any council member without any privileged action: register in CLRegistry, then withdraw all stake from both contracts.

Neither condition requires governance action, key compromise, or majority-validator collusion. A single council member who registers in CLRegistry and drains both pools to dust can trigger the crash the next time the "all understaked" fallback fires and they are selected as proposer.

---

### Recommendation

Add a zero-guard in `Split` before dividing:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount := new(big.Int).Add(cnAmountBig, clAmountBig)

    // Guard: if total staking is zero, all reward goes to CN (no CL split possible).
    if totalAmount.Sign() == 0 {
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount.Div(clAmount, totalAmount)
    return new(big.Int).Sub(amount, clAmount), clAmount
}
``` [1](#0-0)

### Proof of Concept

**Setup (Prague/Kore hardfork active, `istanbul.policy == 2`, `deferredTxFee == true`):**

1. Council = `[V1, V2, V3]`. All three have `StakingAmount == 0` (staking contracts hold < 1 KAIA each). `minStake = 5_000_000`.
2. `V1` is registered in CLRegistry; its CL pool also holds < 1 KAIA → `CLStakingAmount == 0`, `CLStakingInfo != nil`.
3. `getDemotedValidatorsIstanbul` demotes all three → fallback: demoted set is empty → all three are qualified.
4. `V1` is selected as block proposer for block N.
5. Block N is executed; `FinalizeState` calls `GetDeferredReward` → `getDeferredRewardFullKore` → `assignStakingRewards` (returns all stakers reward as remainder to proposer, safe) → `specWithProposerAndFunds`.
6. Inside `specWithProposerAndFunds`, the loop finds `cn` where `cn.RewardAddr == V1.RewardAddr` and `cn.CLStakingInfo != nil`.
7. `cn.Split(proposer)` is called: `totalAmount = big.NewInt(0) + big.NewInt(0) = 0`.
8. `clAmount.Div(clAmount, big.NewInt(0))` → **runtime panic: integer divide by zero**.
9. Every node processing block N crashes. Chain halts. [7](#0-6) [2](#0-1)
