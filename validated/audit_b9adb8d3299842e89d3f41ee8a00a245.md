### Title
Permanently frozen market: `i128` overflow in `scaled_to_original` during accrual panics every verb — ([File: contracts/pool/src/cache/scale.rs])

### Summary
The GPAC CVE is a crash (segfault) reachable on a routine code path. The analog here is an arithmetic-overflow panic reachable on the pool's mandatory accrual path: once a market's scaled balances and borrow index grow large enough, `Cache::calculate_utilization` panics inside `scaled_to_original` with `GenericError::MathOverflow` before the `MAX_BORROW_INDEX_RAY` cap can engage. Because every mutating entrypoint accrues first (`global_sync`), the market is permanently frozen — no withdraw, repay, or liquidation ever succeeds again.

### Finding Description
`global_sync` (`contracts/pool/src/interest.rs:20-33`) runs at the top of every market operation and calls `accrue_chunk` → `accrue_step`, which computes utilization via `Cache::calculate_utilization` (`contracts/pool/src/cache/scale.rs:19-27`). That function computes `scaled_to_original(&env, self.borrowed, self.borrow_index)` — `scaled * index` via `mul_div` — which panics with `GenericError::MathOverflow` when the RAY-scaled product exceeds `i128` (`common/src/math/fp_core.rs:108-118`). The borrow-index cap `MAX_BORROW_INDEX_RAY` is checked only after this multiplication, so the value ceiling is hit first. The repo's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-360`) demonstrates exactly this: after sustained ~98% utilization on the XLM rate curve, `update_indexes` reverts with `MATH_OVERFLOW`, and subsequent `try_withdraw_raw` and `try_repay` revert identically — "The market is frozen: exits and repayments accrue first and hit the same panic." [1](#0-0) [2](#0-1) [3](#0-2) 

### Impact Explanation
Permanent freezing of all user funds in the affected (hub, token) book: suppliers cannot withdraw, borrowers cannot repay or be liquidated, and `update_indexes` itself reverts, so no recovery path exists — the overflow is intrinsic to the stored `borrowed`/`borrow_index` state and recurs on every call. [4](#0-3) 

### Likelihood Explanation
Any unprivileged address can trigger it via `supply`/`borrow`/`update_indexes`, but it requires an extreme position (a whale-scale supply, in the test ~10²⁸ units of an 18-decimal asset with lifted caps) and sustained near-max utilization until the index grows ~170×. It needs a large-capital attacker or a very long-lived whale market, so likelihood is low — consistent with a Medium severity. Caps lifted in the test mirror governance-set caps; the bug is that the index cap ordering makes the overflow reachable before the intended bound. [5](#0-4) 

### Recommendation
Bound `borrowed`/`supplied` scaled totals and the borrow index so `scaled * index` cannot exceed `i128`: either clamp the borrow index to `MAX_BORROW_INDEX_RAY` *before* unscaled-value computations in `accrue_step`/`calculate_utilization`, or use saturating/I256 intermediate math in `scaled_to_original` for aggregate-value paths (utilization, HF) while keeping strict math for per-position settlements. [6](#0-5) [7](#0-6) 

### Proof of Concept
Existing harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-360`: list an 18-decimal market on the XLM curve, lift caps, supply ~10²⁸ units, borrow ~98% of it, then advance time in yearly steps calling `update_indexes`; once `borrowed * borrow_index` exceeds the `i128` RAY domain, `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`. [8](#0-7)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub fn mul_div_floor(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    require_nonzero_divisor(env, d);
    if let Some(quotient) = x
        .checked_mul(y)
        .and_then(|product| div_floor_i128(product, d))
    {
        return quotient;
    }
    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    let nonneg = quotient_is_nonnegative(x, y, d);
    to_i128(env, &div_floor_i256(env, &x256.mul(&y256), &d256, nonneg))
}
