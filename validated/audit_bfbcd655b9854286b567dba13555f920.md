## Analysis

`Rule.from_dict` in `plugins/hookify/core/config_loader.py` supports two independent ways of specifying what a rule checks: the **legacy** `pattern` field (which is converted into a single `Condition` with a `field` that is deterministically derived from `event`) and the **explicit** `conditions` list (where each item is parsed by `Condition.from_dict` with a completely free-form `field` string supplied by whoever wrote the frontmatter). [1](#0-0) 

In the legacy branch, the field is computed from `event` (`command` for `bash`, `new_text` for `file`, `content` otherwise), guaranteeing the field always resolves to a real, tool-supported value: [2](#0-1) 

In the explicit branch, `Condition.from_dict` accepts *any* string for `field` with no cross-check against `event`/tool type: [3](#0-2) 

At enforcement time, `RuleEngine._extract_field` only resolves a small, hardcoded set of `(tool_name, field)` combinations (e.g., `command` for `Bash`; `content`/`new_text`/`old_text`/`file_path` for `Write`/`Edit`); anything else returns `None`: [4](#0-3) 

`_check_condition` treats a `None` field value as an automatic non-match, and `_rule_matches` requires *all* conditions to match, and requires at least one condition to exist at all: [5](#0-4) 

**The differential:** a rule authored with `pattern: rm\s+-rf` for `event: bash` is guaranteed to check `command` and will correctly block. A logically-equivalent rule authored in the "advanced/explicit" `conditions:` form with the same intent but a mismatched `field` (e.g., `field: content` on a `bash` event, or any field not in the engine's hardcoded map) parses successfully, is stored as `action: block`/`enabled: true`, looks legitimate to a reviewer, but never actually matches — `_extract_field` returns `None` → `_check_condition` returns `False` → the rule silently never fires, regardless of how dangerous the command is.

Because `/hookify` rule generation (`plugins/hookify/commands/hookify.md`) and the `writing-rules` skill both instruct an LLM to produce either format based on detected "behaviors," and because `load_rules()` in `config_loader.py` unconditionally globs and loads *any* `.claude/hookify.*.local.md` file present in the working directory (including ones shipped/committed in a repo, despite the `.local.md` naming convention implying they shouldn't be checked in), an attacker who can influence rule-generation content (e.g., via indirect prompt injection in repository content analyzed for rule generation) or who ships such a rule file directly in a repository can produce a rule that displays as an active `action: block` guard but is a structural no-op — silently permitting the exact dangerous bash/file operations (e.g., `rm -rf`, editing `.env` secrets) it appears to forbid. [6](#0-5) 

This is a real code-level asymmetry: the legacy path is field-safe by construction; the explicit path has no field/event validation, breaking the stated invariant that legacy and explicit forms must yield equivalent security semantics.

### Title
Explicit-conditions rule field is unvalidated against event/tool, allowing a "block" rule to silently never match - (File: plugins/hookify/core/config_loader.py)

### Summary
`Rule.from_dict`/`Condition.from_dict` allow the "advanced" `conditions:` form to specify an arbitrary `field` name with no validation against the rule's `event`/tool, unlike the "legacy" `pattern` form which always derives a valid field from `event`. A crafted or subtly-miswritten explicit rule with a mismatched field parses as a valid `action: block` rule but the engine's `_extract_field` returns `None` for that field/tool combination, causing `_check_condition`/`_rule_matches` to permanently return `False`, silently neutralizing the intended block.

### Finding Description
`Rule.from_dict` (`plugins/hookify/core/config_loader.py:44-84`) builds either a single condition from `pattern`+`event` (field guaranteed valid) or a list of user-specified `Condition` objects via `Condition.from_dict` (`config_loader.py:22-29`), which places no constraint on `field`. `RuleEngine._extract_field` (`rule_engine.py:182-254`) only resolves a small hardcoded set of fields per tool (`command` for Bash; `content`/`new_text`/`old_text`/`file_path` for Write/Edit/MultiEdit). Any other field returns `None`, and `_check_condition`/`_rule_matches` (`rule_engine.py:96-180`) treat that as a guaranteed non-match, with the rule requiring all conditions to match to trigger. A `.claude/hookify.*.local.md` file with `event: bash`, `action: block`, and an explicit condition using an unsupported field (e.g., `field: content` or any typo'd/mismatched field) will load successfully (no validation at parse time), display as an enabled blocking rule, but never actually block the targeted dangerous command. Such a rule file can originate from `/hookify` generation output (LLM-authored, potentially steered via indirect prompt injection from analyzed repository content) or be committed directly into a repository's `.claude/` directory, since `load_rules()` (`config_loader.py:198-241`) loads any matching file unconditionally regardless of source or git tracking status.

### Impact Explanation
A user (or Claude Code session) that relies on a hookify block rule believing dangerous bash commands or sensitive file edits are prevented is actually unprotected, enabling unauthorized command execution or file read/write outside the intended safety scope, matching the "Unauthorized file read or write outside the user-approved workspace or target scope" impact category.

### Likelihood Explanation
Requires only ordinary repository content or hookify-generation output containing a malformed/mismatched `conditions:` field — no privileged access, credentials, or social engineering needed. The bug is deterministic and 100% reproducible given the crafted frontmatter.

### Recommendation
Validate `field` in `Condition.from_dict`/`Rule.from_dict` against an allow-list of fields known to be resolvable for the given `event`/tool combination, or have `RuleEngine._rule_matches`/`_check_condition` raise/log a hard warning (not just a bypass) when `_extract_field` returns `None` for a `block` rule, so misconfigured blocking rules fail loud (fail-closed with a visible warning) rather than silently no-op.

### Proof of Concept
Unit test in `plugins/hookify/core/rule_engine.py` test scope:
```python
rule = Rule.from_dict(
    {"name": "block-rm", "enabled": True, "event": "bash", "action": "block",
     "conditions": [{"field": "content", "operator": "regex_match", "pattern": r"rm\s+-rf"}]},
    "Dangerous rm blocked"
)
engine = RuleEngine()
result = engine.evaluate_rules([rule], {
    "hook_event_name": "PreToolUse",
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /important-data"}
})
assert result == {}  # BUG: expected a deny/block response, got none
```
Compare against the equivalent legacy-form rule (`pattern: rm\s+-rf`, same event/action), which correctly returns a `permissionDecision: deny` response for the same input — demonstrating the semantic divergence between legacy and explicit rule forms.

```python
    @classmethod
    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""
        # Handle both simple pattern and complex conditions
        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:
            cond_list = frontmatter['conditions']
            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event
            event = frontmatter.get('event', 'all')
            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:
                field = 'content'

            conditions = [Condition(
                field=field,
                operator='regex_match',
                pattern=simple_pattern
            )]

        return cls(
            name=frontmatter.get('name', 'unnamed'),
            enabled=frontmatter.get('enabled', True),
            event=frontmatter.get('event', 'all'),
            pattern=simple_pattern,
            conditions=conditions,
            action=frontmatter.get('action', 'warn'),
            tool_matcher=frontmatter.get('tool_matcher'),
            message=message.strip()
        )
```

```python
def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules
```

```python
    def _rule_matches(self, rule: Rule, input_data: Dict[str, Any]) -> bool:
        """Check if rule matches input data.

        Args:
            rule: Rule to evaluate
            input_data: Hook input data

        Returns:
            True if rule matches, False otherwise
        """
        # Extract tool information
        tool_name = input_data.get('tool_name', '')
        tool_input = input_data.get('tool_input', {})

        # Check tool matcher if specified
        if rule.tool_matcher:
            if not self._matches_tool(rule.tool_matcher, tool_name):
                return False

        # If no conditions, don't match
        # (Rules must have at least one condition to be valid)
        if not rule.conditions:
            return False

        # All conditions must match
        for condition in rule.conditions:
            if not self._check_condition(condition, tool_name, tool_input, input_data):
                return False

        return True
```

```python
    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
```
