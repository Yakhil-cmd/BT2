Confirmed: in the current code, `announce-l1-early-exit` performs its assertion sequence — `verify-not-prepare-phase`, `validate-no-reentrancy`, caller-identity, `asserts! (get is-l1-lock membership) ERR_CANNOT_ANNOUNCE_L1_EARLY_UNLOCK`, old-signer match, not-already-announced — entirely before `unstake-sats-from-bond-cycles` is invoked and before any `map-set` mutations to `protocol-bond-memberships` or `protocol-bonds-total-staked`. [1](#0-0) 

The equality the question requires — `amount-sats` before the call equals `amount-sats` after a reverted call on an sBTC-path membership — holds, because Clarity's transaction semantics revert *all* state changes (including any that would have occurred from `unstake-sats-from-bond-cycles`) when any `asserts!` in the same public-function call fails. Since `is-l1-lock` is `false` for sBTC members, the `asserts! (get is-l1-lock membership) ERR_CANNOT_ANNOUNCE_L1_EARLY_UNLOCK` at line 1224 fires before line 1230's `unstake-sats-from-bond-cycles` call is ever reached, and the whole transaction is unwound. This is exercised directly by the test `AnnounceL1EarlyExitErrCannotAnnounce`, which asserts the receipt error equals `ERR_CANNOT_ANNOUNCE_L1_EARLY_UNLOCK` and that `getBondMembership` and `getTotalSbtcStakedForBond` are byte-for-byte unchanged before/after. [2](#0-1) 

There is no "refactored call ordering" in the current codebase that moves `unstake-sats-from-bond-cycles` earlier than the asserts — the hypothesis in the question describes a regression that does not exist in the code as read. The related regression noted in comments (stacks-network/stacks-core#7295) concerned a different issue — the prepare-phase guard needing to fire before the `is-l1-lock` check reached — and is already fixed and tested. /**
 * Regression for stacks-network/stacks-core#7295. `announce-l1-early-exit`
 * also mutates next-cycle bond / signer shares (zeros the staker's

 * at the `is-l1-lock` assertion; post-fix the prepare-phase guard fires
 * first.

test('announce-l1-early-exit is rejected during the prepare phase', () => {
  const signer = testSigner.identifier;
  const aliceSbtc = 100000n;

  registerSigner();
  setupBondForAllowlist([{ maxSats: aliceSbtc, staker: alice }]);
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer,
      amountUstx: stxToUStx(50_000),
      btcLockup: err(aliceSbtc),
      signerCalldata: null,
    }),
    alice,
  );

  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) - 9n);
  expect(rov(pox5.isInPreparePhase(rov(pox5.currentPoxRewardCycle())))).toBe(
    true,
  );

  expect(txErr(pox5.announceL1EarlyExit(alice, signer), alice).value).toBe(
    pox5Errors.ERR_STAKE_IN_PREPARE_PHASE,
  );
});
