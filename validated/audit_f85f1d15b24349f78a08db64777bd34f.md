### Title
Bridge Operator Keystore Password Stored as World-Readable Plaintext Alongside Encrypted Keystore — (`File: node/sc/bridge_accounts.go`)

---

### Summary

`InitializeBridgeAccountKeystore` in `node/sc/bridge_accounts.go` auto-generates a random password for the bridge operator keystore and immediately writes it as plaintext to a file in the same directory as the encrypted keystore. The password file is written with `os.ModePerm` (0o777). Any attacker who can read the node's data directory can recover both the encrypted keystore and its password, decrypt the private key, and impersonate the bridge operator to call `handleKLAYTransfer`, `handleERC20Transfer`, or `handleERC721Transfer` — draining bridged assets to an arbitrary address.

---

### Finding Description

`InitializeBridgeAccountKeystore` is called for both the parent and child bridge operator accounts during service-chain startup: [1](#0-0) 

When no keystore exists yet, the function:

1. Generates a random password with `setup.RandStringRunes(params.PasswordLength)`.
2. Creates an encrypted keystore with that password via `ks.NewAccount(password)`.
3. **Immediately writes the password as plaintext** to a file named after the account address inside the same keystore directory: [2](#0-1) 

The `setup.WriteFile` helper writes with `os.ModePerm` (0o777 — world-readable/writable): [3](#0-2) 

On every subsequent startup, the code reads the plaintext password file back from disk and uses it to auto-unlock the keystore: [4](#0-3) 

The result is that the encrypted keystore and its decryption password sit side-by-side in the same directory, both world-readable. The encryption provides no security: anyone who can list the directory can decrypt the private key.

A TODO comment in the code acknowledges this is not production-ready: [5](#0-4) 

---

### Impact Explanation

The bridge operator private key is used to sign and submit `handleKLAYTransfer`, `handleERC20Transfer`, and `handleERC721Transfer` transactions to the bridge contract. These functions are gated by `onlyOperators` and directly transfer KAIA or tokens to an arbitrary `_to` address: [6](#0-5) [7](#0-6) 

The Go-side signing path uses the unlocked keystore directly: [8](#0-7) 

An attacker who steals the operator key can submit fraudulent `handleKLAYTransfer` / `handleERC20Transfer` calls with an attacker-controlled `_to`, draining all KAIA and ERC20 tokens held by the bridge contract. If the operator threshold is 1 (the default), a single stolen key is sufficient.

---

### Likelihood Explanation

The password file is written with `os.ModePerm` (0o777), making it readable by every user on the host. Any of the following common scenarios exposes it:

- A misconfigured web server, RPC endpoint, or monitoring agent running on the same host with a path-traversal or arbitrary-file-read vulnerability.
- An unencrypted disk backup or snapshot (S3, GCS, etc.) of the data directory.
- A compromised co-tenant in a shared or cloud environment.
- A developer or DevOps engineer with read access to the data directory who is not supposed to have key material.

The TODO comment confirms the developers are aware this is not a safe production pattern, yet the code ships and runs in production service-chain deployments.

---

### Recommendation

**Short term:**
- Remove the auto-generated plaintext password file. Require the operator to supply the password interactively or via a secrets manager at startup (analogous to the existing `UnlockParentOperator` / `UnlockChildOperator` RPC methods already present in `node/sc/api_bridge.go`).
- If a password file must be used, write it with `0o600` (owner-read-only) and store it outside the keystore directory.

**Long term:**
- Integrate with a secrets manager (HashiCorp Vault, AWS KMS, etc.) for bridge operator key material.
- Enforce a minimum operator threshold > 1 so that a single stolen key cannot unilaterally execute value transfers.

---

### Proof of Concept

```
# 1. Locate the bridge account directories on the service-chain node host
ls <dataDir>/parent_bridge_account/
# Output: UTC--2024-...--<address>   <address>
#         ^^^^ encrypted keystore    ^^^^ plaintext password

# 2. Read the plaintext password
cat <dataDir>/parent_bridge_account/<address>
# Output: e.g. "xK3~mP9$..."

# 3. Decrypt the keystore using the password (e.g. with web3.py or ethers.js)
python3 -c "
import json, eth_account
ks = json.load(open('<dataDir>/parent_bridge_account/UTC--...--<address>'))
pw = open('<dataDir>/parent_bridge_account/<address>').read()
key = eth_account.Account.decrypt(ks, pw)
print('Private key:', key.hex())
"

# 4. Use the recovered private key to call handleKLAYTransfer on the bridge contract,
#    directing the bridge's entire KAIA balance to an attacker-controlled address.
#    (Requires the operator to be registered and threshold == 1, which is the default.)
```

The stolen key gives the attacker a registered bridge operator identity. With threshold = 1 (default), a single `handleKLAYTransfer` call with an attacker-controlled `_to` and the bridge's full balance as `_value` drains all bridged KAIA in one transaction.

// InitializeBridgeAccountKeystore initializes a keystore, imports existing keys, and tries to unlock the bridge account.
// This returns the 1st account of the wallet, its address, the lock status and the error.
func InitializeBridgeAccountKeystore(keystorePath string) (*keystore.KeyStore, common.Address, bool, error) {
	ks := keystore.NewKeyStore(keystorePath, keystore.StandardScryptN, keystore.StandardScryptP)

	// If there is no keystore file, this creates a random account and the corresponded password file.
	// TODO-Kaia-Servicechain A test-option will be added and this routine will be only executed with it.
	if len(ks.Accounts()) == 0 {
		password := setup.RandStringRunes(params.PasswordLength)
		acc, err := ks.NewAccount(password)
		if err != nil {
			return nil, common.Address{}, true, err
		}
		setup.WriteFile([]byte(password), keystorePath, acc.Address.String())

		if err := ks.Unlock(acc, password); err != nil {
			logger.Error("bridge account wallet unlock is failed by created password file.", "address", acc.Address, "err", err)
			os.RemoveAll(keystorePath)
			return nil, common.Address{}, true, err
		}

		return ks, acc.Address, false, nil
	}

	// Try to unlock 1st account if valid password file exist. (optional behavior)
	// If unlocking failed, user should unlock it through API.
	acc := ks.Accounts()[0]
	pwdFilePath := path.Join(keystorePath, acc.Address.String())
	pwdStr, err := os.ReadFile(pwdFilePath)
	if err == nil {
		if err := ks.Unlock(acc, string(pwdStr)); err != nil {
			logger.Warn("bridge account wallet unlock is failed by exist password file.", "address", acc.Address, "err", err)
			return ks, acc.Address, true, nil
		}
		return ks, acc.Address, false, nil
	}

	return ks, acc.Address, true, nil
}

// SignTx signs a transaction with the accountInfo.
func (acc *accountInfo) SignTx(tx *types.Transaction) (*types.Transaction, error) {
	tx, err := acc.keystore.SignTx(accounts.Account{Address: acc.address}, tx, acc.chainID)
	if err != nil {
		return nil, err
	}

	if tx.Type().IsFeeDelegatedTransaction() {
		// Look up the wallet containing the requested signer
		account := accounts.Account{Address: acc.feePayer}

		wallet, err := acc.am.Find(account)
		if err != nil {
			return nil, err
		}
		// Request the wallet to sign the transaction
		return wallet.SignTxAsFeePayer(account, tx, acc.chainID)
	}
	return tx, nil
}
