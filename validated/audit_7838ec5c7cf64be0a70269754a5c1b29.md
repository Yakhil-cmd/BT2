## Title
Missing authorization check allows any paired device to inject a spoofed multisig ("shared address") definition, misleading the wallet into treating attacker-controlled or attacker-influenced addresses as trusted co-signed addresses - (File: wallet_defined_by_addresses.js)

### Summary
The Coolify CVE-2025-22611 root cause is a missing authorization check: any authenticated (but low-privileged) team member could send a role-change request that the server accepted without verifying the requester was allowed to grant that privilege to himself or others. The closest reachable analog in `ocore` is in the device-message handler for `new_shared_address`, processed by `handleNewSharedAddress()` in `wallet_defined_by_addresses.js`. Any paired correspondent device (an "unprivileged" peer relative to a wallet's real cosigner set) can push an arbitrary multisig/shared-address definition and be silently recorded as one of its signers, without the code ever verifying that the sending device (`from_address`) is actually one of the members entitled to define or forward that address.

### Finding Description
`handleNewSharedAddress()` is reached from `wallet.js` when a peer device sends the `new_shared_address` subject [1](#0-0) . The function:
- Validates that `body.definition` hashes to `body.address` [2](#0-1) .
- Validates that each `signers[path].address` matches the `["address", ...]` leaves extracted from the definition [3](#0-2) .
- Calls `determineIfIncludesMeAndRewriteDeviceAddress()`, which only checks that *some* signer address in the message belongs to the local wallet (`my_addresses`/`shared_addresses`) [4](#0-3) .
- Then calls `addNewSharedAddress()`, which persists the shared address, its full definition, and the full `assocSignersByPath` (including `device_address` for every path) into the `shared_addresses` / `shared_address_signing_paths` tables [5](#0-4) .

Nowhere in this call chain is the `from_address` (the actual sender of the device message, computed by the caller in `wallet.js`) checked against the `signers` map or the definition to prove that the sender is authorized to introduce or forward this shared-address record. The check `determineIfIncludesMeAndRewriteDeviceAddress` only ensures *my* address participates - it does not verify that the peer who sent the message is one of the signers it claims to represent, nor that it is entitled to assign arbitrary `device_address` values to other signing paths in the record. `handleNewSharedAddress` is also invoked with `forwarded: true` for indirect/relayed shared addresses, further widening exposure to non-direct correspondents.

This mirrors the Coolify bug class exactly: a message-processing function performs object/schema validation but omits the authorization step that ties the identity of the requester to the specific privileged action being requested (here: "become recorded as trusted co-signer/definition of a shared wallet address" instead of "become a team owner").

### Impact Explanation
Because `shared_address_signing_paths.device_address` records which device is trusted to be asked for a signature/co-signature on a given path, and this table drives which peers the wallet will request signatures from and display as legitimate co-signers (`readSharedAddressCosigners`, `getPeerAddressesFromSigners`) [6](#0-5) [7](#0-6) , an attacker who is merely a paired correspondent (not a real cosigner of any funds) can plant fabricated shared-address records claiming co-signer roles, addresses, and device mappings of their choosing (as long as they can craft a definition/address pair that hashes correctly). This can be leveraged for social-engineering/UI-spoofing attacks that make a victim believe a payment address is protected by known cosigners, and to poison the peer/cosigner metadata (`name`, `device_address`) used to route private-payment chains and signing requests (`forwardPrivateChainsToOtherMembersOfAddresses`) [8](#0-7) , potentially misdirecting private payment chain forwarding or triggering unwarranted signing-request UI prompts.

### Likelihood Explanation
Any device that has been paired with the victim (a very low trust bar - pairing itself does not imply co-ownership of any wallet) can send this message subject at will; `new_shared_address` is not restricted to already-known shared-address participants, and forwarded copies are accepted as well. No unit is broadcast to the DAG so no global consensus check applies; the entire trust decision rests on the local, insufficiently authorized handler.

### Recommendation
In `handleNewSharedAddress`, before calling `addNewSharedAddress`, verify that the `from_address` of the message is actually one of the `device_address` values already asserted as an authorized participant for that logical shared-address family (e.g., cross-check against `wallet_signing_paths`/existing pending offer records created via `createNewSharedAddressByTemplate`/`validateAddressDefinitionTemplate`), and reject unsolicited/forwarded `new_shared_address` messages that do not correspond to a shared-address creation the local wallet actually initiated or approved. At minimum, require that the sending device is present as one of the `device_address` entries in the very `signers` map it forwards, so a peer cannot assert arbitrary device/address bindings for other signing paths on the sender's behalf.

### Proof of Concept
1. Device A pairs with victim's device (ordinary correspondent, no wallet relationship).
2. Device A crafts a synthetic 2-of-2 (or larger) address definition `arrDefinition` where one leaf is an address it controls and another leaf is any valid address (can reuse the victim's own address to pass the "includes me" check), computes `address = getChash160(arrDefinition)`, and builds `signers` mapping paths to arbitrary `device_address` values (including its own).
3. Device A sends `{subject: "new_shared_address", body: {address, definition, signers}}` to the victim.
4. `handleNewSharedAddress` accepts it: address/definition hash matches, signer addresses match definition leaves, and the victim's own address satisfies `determineIfIncludesMeAndRewriteDeviceAddress`.
5. `addNewSharedAddress` stores the shared address and signing paths, and the victim's wallet UI now lists Device A (or any address Device A specified) as a legitimate co-signer/participant for that address, without the victim ever having authorized or created this relationship, and without any check that Device A itself was ever a rightful party to the definition.

Note: I could not verify from the indexed code alone whether any additional runtime UI-level confirmation gate exists before a user acts on a maliciously injected shared address (e.g., before actually funding or signing against it); a full Devin session with complete UI/wallet client code access would be needed to confirm end-to-end exploitability into unauthorized fund loss versus a spoofing/metadata-poisoning primitive only.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function readSharedAddressCosigners(shared_address, handleCosigners){
	db.query(
		"SELECT DISTINCT shared_address_signing_paths.device_address, name, "+db.getUnixTimestamp("shared_addresses.creation_date")+" AS creation_ts \n\
		FROM shared_address_signing_paths \n\
		JOIN shared_addresses USING(shared_address) \n\
		LEFT JOIN correspondent_devices USING(device_address) \n\
		WHERE shared_address=? AND device_address!=?",
		[shared_address, device.getMyDeviceAddress()],
		function(rows){
			if (rows.length === 0)
				throw Error("no cosigners found for shared address "+shared_address);
			handleCosigners(rows);
		}
	);
}
