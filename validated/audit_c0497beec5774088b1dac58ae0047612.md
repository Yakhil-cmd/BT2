### Title
Unauthenticated subscription to `/events` exposes live stack/task status pubsub channels - ([File: config/routes.rb])

### Summary
`config/routes.rb` mounts `Pubsubstub::StreamAction.new` at `/events` directly on `Shipit::Engine.routes.draw`, outside of any controller that includes `Shipit::Authentication`. Because `force_github_authentication` is a controller `before_action` defined in `app/controllers/concerns/shipit/authentication.rb` and only wired into `ShipitController`/`Api::BaseController`, the Rack-mounted `StreamAction` never runs it, so any unauthenticated client can subscribe to a stack's pubsub channel and receive live status events.

### Finding Description
The intended binding is: `subscription_to_channel(c) == true` should require `current_user.authorized? == true` (or `Shipit.authentication_disabled?`), enforced by `force_github_authentication` (`app/controllers/concerns/shipit/authentication.rb:20-34`). That guard is only invoked via `include Shipit::Authentication` in `ShipitController` (`app/controllers/shipit/shipit_controller.rb:4-18`) and `Api::BaseController`. `Pubsubstub::StreamAction` is a bare Rack endpoint mounted with `mount Pubsubstub::StreamAction.new, at: "/events", as: :events` (`config/routes.rb:9`) — it does not inherit from `ApplicationController`/`ShipitController`, so no `before_action` in this engine applies to it at all.

Stack-level events are published with predictable channel names of the form `"stack.#{stack.id}"`, confirmed by the app's own test helpers (`Pubsubstub.expects(:publish).with { |channel, ...| channel == "stack.#{stack.id}" }` in `test/models/status_test.rb:58-62`, `test/models/commits_test.rb:946-951`, `test/models/deploys_test.rb:1121-1126`). `Stack#id` is a sequential auto-increment primary key, trivially enumerable by an attacker with no session at all.

Exploit flow: an unauthenticated attacker sends `GET /events?channel=stack.1` (and iterates `stack.2`, `stack.3`, ...). Since the mounted `StreamAction` has no `Shipit::Authentication` before_action and no other guard declared in this engine's routes/controllers, the SSE/long-poll subscription is established and status-update events (task/deploy status transitions, commit status pushes, etc.) for that stack are streamed to the attacker, regardless of `Shipit.github_teams` membership or stack visibility settings.

### Impact Explanation
An unauthenticated attacker can read live stack/task/deploy state for any stack whose numeric id they guess or enumerate — this matches the High severity category "unauthenticated read of stack state, task streams or deploy output". It is repeatable against every stack on the instance (sequential integer ids), giving a full-instance information disclosure of deploy/task progress without any credential. No RCE or credential exfiltration is demonstrated here — only read access to live event streams.

### Likelihood Explanation
No preconditions beyond network access to the Shipit host are required: no session, no API token, no GitHub team membership. The only "cost" is guessing/enumerating small integer stack ids, which is trivial. This is fully exploitable purely through this engine's own `config/routes.rb`, independent of host-app configuration, since the mount and lack of authentication concern both live inside the engine.

### Recommendation
Wrap the `/events` mount with an authentication/authorization guard before the request reaches `Pubsubstub::StreamAction`, e.g. add a Rack middleware or a `constraints` block that validates `session[:user_id]`/`current_user.authorized?` and that the requested `channel` param corresponds to a stack the user is permitted to read, rejecting the request (401/403) before establishing the subscription if the check fails.

```ruby
# frozen_string_literal: true

module Shipit
  module Authentication
    extend ActiveSupport::Concern

    included do
      before_action :force_github_authentication
      helper_method :current_user
    end

    module ClassMethods
      def skip_authentication(*args)
        skip_before_action(:force_github_authentication, *args)
      end
    end

    private

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
