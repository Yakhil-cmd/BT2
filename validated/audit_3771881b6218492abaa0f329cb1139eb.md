### Title
Unsanitized tree/path rendering in `printTree` allows bidi/zero-width spoofing of skill file names - (File: pkg/cmd/skills/preview/preview.go)

### Summary
`printTree` in `pkg/cmd/skills/preview/preview.go` writes attacker-controlled file/directory names straight to the terminal with no control-character, bidi-override, or zero-width character stripping, unlike other skill-rendering code paths in the same codebase (e.g. `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal`) that explicitly sanitize such content before display.

### Finding Description
`renderFileTree` calls `buildTree(files)` and then `printTree(w, cs, root.children, "")`. The `files` come from `discovery.ListSkillFiles`/`DiscoverSkillFiles`, which populate `SkillFile.Path` directly from the `path` field of a GitHub `git/trees` API response [1](#0-0) . Since the repository, its branches, and its tree entries are fully attacker-controlled (an attacker publishes the skill repo), the `path` strings can contain any Unicode, including U+202E (RIGHT-TO-LEFT OVERRIDE), zero-width characters, or combining marks.

`buildTree` splits `f.Path` on `/` and stores each path segment verbatim as `treeNode.name` [2](#0-1) . `printTree` then prints `node.name` unmodified via `fmt.Fprintf`, with no transformation: [3](#0-2) 

This same unsanitized `f.Path` is also used to build the interactive file picker `choices` list shown via `opts.Prompter.Select` in `renderInteractive` [4](#0-3) .

By contrast, `pkg/cmd/skills/list/list.go` explicitly sanitizes comparable attacker-influenced frontmatter/source strings before rendering, using an ASCII/control-character sanitizer to prevent terminal-escape/control-character injection [5](#0-4) . No equivalent sanitization step exists in the `preview` package before `printTree` or the picker `choices` are written to the terminal. The codebase's general `iostreams.Untrusted`/`asciisanitizer` machinery is likewise not applied here [6](#0-5) ; note that even that sanitizer targets ANSI/control bytes, not Unicode bidi override or zero-width characters, so no layer in this path addresses the specific bidi/zero-width class of characters.

### Impact Explanation
An attacker who publishes a skill repository can name a file (e.g. `skills/foo/scripts/setup\u202Ehs.sh`) so that the rune sequence displayed by `printTree`/the file picker visually reverses the trailing characters, making a script appear to have an innocuous extension while it is something else (or vice versa). Combined with the interactive picker in `renderInteractive`, a victim could select an entry believing it is a benign file based on the spoofed rendered name. This is a terminal-output spoofing issue that can mislead a user's file-selection trust decision, matching the "Terminal output/prompt spoofing" impact class described in the target's expected impact. However, `gh skills preview` itself does not execute or install any file merely by rendering the tree or previewing content — it fetches the blob and renders/paginates it — so the concrete exploit is limited to display deception of the file tree/picker, not code execution or credential exfiltration by itself within this specific command.

### Likelihood Explanation
Feasible and fully attacker-controlled: any GitHub user can publish a repository/skill with adversarial file paths, since `SkillFile.Path` values are taken verbatim from the git tree API without validation for problematic Unicode [7](#0-6) . No special privileges, host compromise, or MITM needed — only that a victim runs `gh skill preview <attacker-repo>`.

### Recommendation
Sanitize `treeNode.name` (and the `choices` list built in `renderInteractive`) before display: strip or escape Unicode bidirectional control characters (U+202A–U+202E, U+2066–U+2069), zero-width characters (U+200B, U+200C, U+200D, U+FEFF), and other non-printable/combining sequences, in addition to the existing ASCII control-character handling used elsewhere (e.g. apply the same `sanitizeForTerminal`-style treatment used in `pkg/cmd/skills/list/list.go` to `printTree`'s `node.name` and to picker `choices`).

Expected (current) result: the assertion fails because `printTree` writes `node.name` unmodified, including `U+202E`. After applying sanitization, the character should be removed/escaped and the test should pass.

func DiscoverSkillFiles(client *api.Client, host, owner, repo, treeSHA, skillPath string) ([]SkillFile, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "trees", treeSHA)
	if err != nil {
		return nil, err
	}
	apiPath.SetQuery("recursive", "true")
	var tree treeResponse
	if err := client.REST(host, "GET", apiPath.String(), nil, &tree); err != nil {
		return nil, fmt.Errorf("could not fetch skill tree: %w", err)
	}

	if tree.Truncated {
		// Recursive fetch was truncated. Fall back to walking subtrees individually.
		return walkTree(client, host, owner, repo, treeSHA, skillPath, 0)
	}

	var files []SkillFile
	for _, entry := range tree.Tree {
		if entry.Type == "blob" {
			files = append(files, SkillFile{
				Path: skillPath + "/" + entry.Path,
				SHA:  entry.SHA,
				Size: entry.Size,
			})
		}
	}

	return files, nil
}

func buildTree(files []discovery.SkillFile) *treeNode {
	root := &treeNode{isDir: true}
	for _, f := range files {
		parts := strings.Split(f.Path, "/")
		current := root
		for i, part := range parts {
			isLast := i == len(parts)-1
			found := false
			for _, child := range current.children {
				if child.name == part {
					current = child
					found = true
					break
				}
			}
			if !found {
				node := &treeNode{name: part, isDir: !isLast}
				current.children = append(current.children, node)
				current = node
			}
		}
	}

func printTree(w io.Writer, cs *iostreams.ColorScheme, nodes []*treeNode, indent string) {
	for i, node := range nodes {
		isLast := i == len(nodes)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		if node.isDir {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(node.name+"/"))
			printTree(w, cs, node.children, indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), node.name)
		}
	}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}

// String returns the content with ANSI escape sequences neutralized. It is
// called automatically by the fmt package, so printing an Untrusted value is
// safe by default on every fmt path.
func (u Untrusted) String() string {
	sanitized, _, err := transform.String(&asciisanitizer.Sanitizer{}, u.raw)
	if err != nil {
		return stripControl(u.raw)
	}
	return sanitized
}
