### Title
Overflow in index accrual permanently freezes an oversized market - (File: `common/src/rates/simulate.rs`)

### Summary
RAY-scaled supply or debt shares can grow large enough that `scaled × index` exceeds `i128` before the configured index ceiling is reached. Because `accrue_step` performs this non-saturating conversion before applying the borrow-index cap, the next accrual panics with `MathOverflow`; every pool mutation loads and syncs the market first, permanently blocking withdrawals, repayments, liquidation, recapitalization, and further accrual for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`Controller::update_indexes(caller, assets)` is permissionless and forwards the assets to the pool. [3](#0-2) [4](#0-3)  The pool’s `update_indexes` calls `ops::market::accrue`, which calls `interest::global_sync` for each market. [5](#0-4) [6](#0-5) 

At the beginning of every accrual step, `accrue_step` computes `borrowed × borrow_index` and `supplied × supply_index` through `scaled_to_original`. [7](#0-6)  `scaled_to_original` delegates to `Ray::mul`, which uses non-saturating half-up multiplication and raises `MathOverflow` when the result does not fit in `i128`. [8](#0-7) [9](#0-8) 

The configured index ceilings are applied only after those total-value conversions, so they do not prevent the product from exceeding `i128`. [10](#0-9) [11](#0-10)  For example, a market with approximately `10^36` RAY shares reaches the raw-value boundary at an index near `170 × RAY`, while `MAX_BORROW_INDEX_RAY` is `10^36`, equivalent to `10^9 × RAY`. [12](#0-11) [13](#0-12) 

### Impact Explanation
Once `scaled × index` exceeds `i128`, the transaction reverts before `global_sync` can advance `last_timestamp` or commit a bounded index. [14](#0-13)  Supply, borrow, withdraw, repay, liquidation settlement, bad-debt seizure, and `update_indexes` all load a synced market through `load_leg`, `synced_market`, or `accrue`, so every subsequent operation touches the same panic. [2](#0-1) [15](#0-14) 

The result is permanent freezing of all supplier cash and debt operations in the affected `(hub_id, asset)` market, including inability to repay debt or liquidate unhealthy accounts. [16](#0-15) [17](#0-16) [18](#0-17) 

### Likelihood Explanation
The condition is reachable by ordinary users only in a very large, high-decimal market whose configured caps admit enough RAY-scaled shares and whose utilization keeps the indexes increasing. [19](#0-18) [20](#0-19)  No privileged action is needed after such a market exists: an unprivileged caller can create the position and later invoke `update_indexes`, while ordinary borrowers, suppliers, and liquidators trigger the same failure. [21](#0-20) [22](#0-21) 

The integration test demonstrates the concrete boundary using an 18-decimal market, `10^27` base units supplied, and 98% utilization; repeated permissionless index updates eventually panic with `MathOverflow` below `MAX_BORROW_INDEX_RAY`, after which both withdrawal and repayment fail. [23](#0-22) 

### Recommendation
Enforce a dynamic index bound before converting scaled totals, such as `index <= floor(i128::MAX × RAY / scaled)`, for both `borrowed` and `supplied`. When a computed index would exceed that bound, clamp the index to the largest value that keeps the market operable rather than allowing the next accrual to panic; alternatively, cap scaled supply and debt shares conservatively so every permitted balance remains representable at `MAX_SUPPLY_INDEX_RAY` and `MAX_BORROW_INDEX_RAY`. Add regression coverage proving that `update_indexes`, `withdraw`, `repay`, and liquidation remain callable at the configured share caps and index ceilings. [24](#0-23) [12](#0-11) 

### Proof of Concept
1. In an 18-decimal market whose caps permit the size, call `Controller::supply(attacker, 0, spoke_id, [(collateral_asset, collateral_amount), (target_asset, 1_000_000_000 × 10^18)])` to create an account holding enough collateral and approximately `10^36` target supply shares. [25](#0-24) [26](#0-25) 
2. Call `Controller::borrow(attacker, account_id, [(target_asset, 980_000_000 × 10^18)], Some(attacker))` to establish approximately 98% utilization. [27](#0-26) [28](#0-27) 
3. As ledger time advances, repeatedly call `Controller::update_indexes(attacker, [target_asset])`; once `borrowed × borrow_index` or `supplied × supply_index` exceeds `i128::MAX`, the call reverts before applying `MAX_BORROW_INDEX_RAY`. [3](#0-2) [10](#0-9) 
4. Subsequent `withdraw`, `repay`, `liquidate`, and `update_indexes` calls all revert at the mandatory market sync, leaving the market’s cash and accounting permanently inaccessible absent a contract change. [2](#0-1) [18](#0-17)

pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };

    t.supply_raw(BOB, "BIG18", principal);

    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let failure = loop {

        assert!(
            years <= 40,

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);

        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
