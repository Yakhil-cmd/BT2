### Title
`pallet-ranked-collective` does not purge a removed/demoted member's vote weight from ongoing polls, letting an expelled member's back-dated vote still decide the outcome - (File: `substrate/frame/ranked-collective/src/lib.rs`)

### Summary
The external report describes a DAO validator-voting system where voting power is captured at a snapshot when a vote is cast, and expelling/zeroing a validator's balance afterwards does not retroactively remove that validator's already-cast vote from an active proposal. `pallet-ranked-collective`, FRAME's rank-based voting membership pallet (used e.g. for the Polkadot Fellowship), exhibits the same structural weakness: `vote()` bakes the voter's *current rank-derived weight* into the `Voting` storage item and the poll's `Tally` at cast time [1](#0-0) , but `remove_member`/`demote_member` never touch `Voting` or the `Tally` of any ongoing poll the removed/demoted member already voted on [2](#0-1) [3](#0-2) .

### Finding Description
`vote()` reads the caller's current `MemberRecord.rank`, converts it into a vote weight via `rank_to_votes`, records it in `Voting::<T, I>` keyed by `(poll, who)`, and adds that weight into the poll's live `Tally` (`bare_ayes`/`ayes`/`nays`) [1](#0-0) .

When a member is later expelled via `remove_member` (any origin satisfying `T::RemoveOrigin`, e.g. because the member is misbehaving, compromised, or otherwise no longer trusted), the pallet calls `do_remove_member_from_rank`, which only mutates `MemberCount`, `IdToIndex`, `IndexToId`, and `Members` - it never iterates `Voting` or calls `T::Polls::access_poll` to subtract the removed member's contribution from any ongoing poll's `Tally`: [2](#0-1) 

The same is true for `demote_member` → `do_demote_member`, which reduces (or zeroes) the member's rank without rejigging the weight of votes they already cast at their prior (higher) rank on ongoing polls: [4](#0-3) 

Contrast this with `pallet-collective`, which handles exactly this scenario correctly: `ChangeMembers::change_members_sorted` actively walks every open `Proposals` entry and strips the `ayes`/`nays` of any outgoing member from `Voting`, so an expelled member's historical vote can no longer influence quorum or the final tally: [5](#0-4) 
This behavior is explicitly tested in `removal_of_old_voters_votes_works` / `removal_of_old_voters_votes_works_with_set_members`: [6](#0-5) 

`pallet-elections-phragmen` similarly actively purges a departing voter's stake-backed vote via `remove_voter`/`do_remove_voter` [7](#0-6) .

`pallet-ranked-collective` has no equivalent mechanism. Its `cleanup_poll` extrinsic only clears the `Voting` storage prefix *after* a poll has concluded (`ensure!(T::Polls::as_ongoing(poll_index).is_none(), ...)`) purely for storage-weight bookkeeping - it does not adjust an in-flight `Tally`, and it is inapplicable while the poll is `Ongoing`: [8](#0-7) 

Thus, if the Fellowship (or any consumer of `pallet-ranked-collective`, wired via `pallet-referenda`'s ranked-collective tally) removes/demotes a member specifically because that member cast an inappropriate vote or is compromised, the removed/demoted member's stale, higher-weighted vote remains locked into the tally of the currently-ongoing poll and can still push it over `support`/`approval` thresholds - the analog of Alice's back-dated 10% vote surviving her expulsion in the original report.

### Impact Explanation
This breaks the invariant that only currently-authorized, currently-ranked members should influence live governance decisions. A collective that removes a member specifically to stop them from steering an active decision (e.g., a compromised or misbehaving Fellowship member) cannot actually undo the damage: their previously-cast vote weight remains baked into the poll's `Tally` and can determine whether a referendum executes (e.g. via `pallet-referenda` + `pallet-ranked-collective`'s `VoteTally` used for track thresholds). This is a governance-integrity issue for any production runtime using `pallet-ranked-collective` (e.g. Fellowship/Ambassador collectives on Collectives parachain), potentially enabling unauthorized dispatch of a referendum's proposed call.

### Likelihood Explanation
Medium. It requires: (a) a member votes on an ongoing poll, and (b) the collective's `RemoveOrigin`/`DemoteOrigin` subsequently removes or demotes that member specifically hoping to stop their influence on that poll, while the poll is still ongoing. This is a realistic governance scenario (removing a member for casting a bad-faith or compromised vote) rather than a purely theoretical one, and no privileged attacker action is needed beyond the ordinary, permitted use of `remove_member`/`demote_member` by the collective's governance origin - the "vulnerability" is that this legitimate corrective action does not have the intended effect on in-flight tallies.

### Recommendation
When `do_remove_member_from_rank` or `do_demote_member` reduces a member's effective rank, iterate the member's outstanding votes on currently-`Ongoing` polls (mirroring `pallet-collective::change_members_sorted`) and subtract their previously-recorded vote weight from each poll's `Tally`, removing or re-weighting the corresponding `Voting` entry. Alternatively, document this as an explicitly accepted design trade-off (as Dexe did for `GovValidators`) if fixing on-chain is deemed undesirable, so downstream integrators (Fellowship, Ambassador collectives) are aware that removal/demotion does not retroactively affect ongoing polls.

### Proof of Concept
No executable PoC was run; this submission is based on static code-path analysis comparing `pallet-ranked-collective`'s `vote`/`remove_member`/`demote_member` against the deliberately-designed, tested cleanup behavior in `pallet-collective::change_members_sorted` and `pallet-elections-phragmen::remove_voter`. I could not find any test in `substrate/frame/ranked-collective/src/tests.rs` that exercises "vote on ongoing poll, then remove/demote the voter, and check the tally," which is consistent with the absence of such cleanup logic in the source reviewed above. I was unable to determine from the available index whether any downstream runtime configuration (e.g., Fellowship on Collectives parachain) adds a custom hook compensating for this gap; a Devin session with full repo/build access would be needed to write and execute an integration test (`vote` as a higher-rank member on an ongoing `pallet-referenda` ranked poll, call `remove_member`/`demote_member`, then assert whether the poll's `Tally`/support changed) to confirm exploitability end-to-end.

		pub fn vote(
			origin: OriginFor<T>,
			poll: PollIndexOf<T, I>,
			aye: bool,
		) -> DispatchResultWithPostInfo {
			let who = ensure_signed(origin)?;
			let record = Self::ensure_member(&who)?;
			use VoteRecord::*;
			let mut pays = Pays::Yes;

			let (tally, vote) = T::Polls::try_access_poll(
				poll,
				|mut status| -> Result<(TallyOf<T, I>, VoteRecord), DispatchError> {
					match status {
						PollStatus::None | PollStatus::Completed(..) => {
							Err(Error::<T, I>::NotPolling)?
						},
						PollStatus::Ongoing(ref mut tally, class) => {
							match Voting::<T, I>::get(&poll, &who) {
								Some(Aye(votes)) => {
									tally.bare_ayes.saturating_dec();
									tally.ayes.saturating_reduce(votes);
								},
								Some(Nay(votes)) => tally.nays.saturating_reduce(votes),
								None => pays = Pays::No,
							}
							let min_rank = T::MinRankOfClass::convert(class);
							let votes = Self::rank_to_votes(record.rank, min_rank)?;
							let vote = VoteRecord::from((aye, votes));
							match aye {
								true => {
									tally.bare_ayes.saturating_inc();
									tally.ayes.saturating_accrue(votes);
								},
								false => tally.nays.saturating_accrue(votes),
							}
							Voting::<T, I>::insert(&poll, &who, &vote);
							Ok((tally.clone(), vote))
						},
					}
				},
			)?;
			Self::deposit_event(Event::Voted { who, poll, vote, tally });

		#[pallet::call_index(5)]
		#[pallet::weight(T::WeightInfo::cleanup_poll(*max))]
		pub fn cleanup_poll(
			origin: OriginFor<T>,
			poll_index: PollIndexOf<T, I>,
			max: u32,
		) -> DispatchResultWithPostInfo {
			ensure_signed(origin)?;
			ensure!(T::Polls::as_ongoing(poll_index).is_none(), Error::<T, I>::Ongoing);

			let r = Voting::<T, I>::clear_prefix(
				poll_index,
				max,
				VotingCleanup::<T, I>::take(poll_index).as_ref().map(|c| &c[..]),
			);
			if r.unique == 0 {
				// return Err(Error::<T, I>::NoneRemaining)
				return Ok(Pays::Yes.into());
			}
			if let Some(cursor) = r.maybe_cursor {
				VotingCleanup::<T, I>::insert(poll_index, BoundedVec::truncate_from(cursor));
			}
			Ok(PostDispatchInfo {
				actual_weight: Some(T::WeightInfo::cleanup_poll(r.unique)),
				pays_fee: Pays::No,
			})
		}

		/// Demotes a member in the ranked collective into the next lower rank.
		///
		/// A `maybe_max_rank` may be provided to check that the member does not get demoted from
		/// a certain rank. Is `None` is provided, then the rank will be decremented without checks.
		fn do_demote_member(who: T::AccountId, maybe_max_rank: Option<Rank>) -> DispatchResult {
			let mut record = Self::ensure_member(&who)?;
			let rank = record.rank;
			if let Some(max_rank) = maybe_max_rank {
				ensure!(max_rank >= rank, Error::<T, I>::NoPermission);
			}

			Self::remove_from_rank(&who, rank)?;
			let maybe_rank = rank.checked_sub(1);
			match maybe_rank {
				None => {
					Members::<T, I>::remove(&who);
					Self::deposit_event(Event::MemberRemoved { who, rank: 0 });
				},
				Some(rank) => {
					record.rank = rank;
					Members::<T, I>::insert(&who, &record);
					Self::deposit_event(Event::RankChanged { who, rank });
				},
			}
			Ok(())
		}

#[test]
fn removal_of_old_voters_votes_works() {
	ExtBuilder::default().build_and_execute(|| {
		let proposal = make_proposal(42);
		let proposal_len: u32 = proposal.using_encoded(|p| p.len() as u32);
		let hash = BlakeTwo256::hash_of(&proposal);
		let end = 4;
		assert_ok!(Collective::propose(
			RuntimeOrigin::signed(1),
			3,
			Box::new(proposal.clone()),
			proposal_len
		));
		assert_ok!(Collective::vote(RuntimeOrigin::signed(1), hash, 0, true));
		assert_ok!(Collective::vote(RuntimeOrigin::signed(2), hash, 0, true));
		assert_eq!(
			Voting::<Test, Instance1>::get(&hash),
			Some(Votes { index: 0, threshold: 3, ayes: vec![1, 2], nays: vec![], end })
		);
		Collective::change_members_sorted(&[4], &[1], &[2, 3, 4]);
		assert_eq!(
			Voting::<Test, Instance1>::get(&hash),
			Some(Votes { index: 0, threshold: 3, ayes: vec![2], nays: vec![], end })
		);

		let proposal = make_proposal(69);
		let proposal_len: u32 = proposal.using_encoded(|p| p.len() as u32);
		let hash = BlakeTwo256::hash_of(&proposal);
		assert_ok!(Collective::propose(
			RuntimeOrigin::signed(2),
			2,
			Box::new(proposal.clone()),
			proposal_len
		));
		assert_ok!(Collective::vote(RuntimeOrigin::signed(2), hash, 1, true));
		assert_ok!(Collective::vote(RuntimeOrigin::signed(3), hash, 1, false));
		assert_eq!(
			Voting::<Test, Instance1>::get(&hash),
			Some(Votes { index: 1, threshold: 2, ayes: vec![2], nays: vec![3], end })
		);
		Collective::change_members_sorted(&[], &[3], &[2, 4]);
		assert_eq!(
			Voting::<Test, Instance1>::get(&hash),
			Some(Votes { index: 1, threshold: 2, ayes: vec![2], nays: vec![], end })
		);
	});
}
