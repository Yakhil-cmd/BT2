## Analysis

`Registrar::swap` requires `Self::ensure_root_para_or_owner` — Root, the para's owner, or the para's own origin [1](#0-0) , and it swaps lease-holding status, auction/lease data and the associated deposits between two `ParaId`s [2](#0-1) . Since `swap` is dispatched with a signed origin (the para owner's account, or the delegate acting for it via proxy), and `Registrar::swap` is a state-changing, deposit-affecting call deliberately excluded from `NonTransfer`'s allow-list, this is a genuine privileged capability being escalated.

### Title
`NonTransfer` proxy can self-escalate to `Auction`-proxy permissions and reach the denied `Registrar::swap` call - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
`pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` purely via `ProxyType::is_superset`, independent of `filter` [3](#0-2) . In `polkadot/runtime/westend/src/lib.rs`, `polkadot/runtime/rococo/src/lib.rs`, and `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, `ProxyType::NonTransfer` declares itself a superset of every other `ProxyType` (`(ProxyType::NonTransfer, _) => true`) [4](#0-3) , yet its own `filter` explicitly denies `Registrar::swap` ("Specifically omitting Registrar `swap`") while admitting `register`/`deregister`/`reserve` [5](#0-4) . `ProxyType::Auction`'s filter matches the entire `RuntimeCall::Registrar(..)` family with no variant restriction, so it does admit `swap` [6](#0-5) . This is the exact bug class that was already found and fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend in PR #19024-equivalent fix `pr_12769.prdoc` [7](#0-6)  and covered by a regression test [8](#0-7) , but the equivalent `NonTransfer`/`Auction` lattice violation over `Registrar::swap` was never patched in the relay-chain runtimes.

### Finding Description
A `NonTransfer` proxy delegate cannot directly dispatch `Registrar::swap` on behalf of the real account because `NonTransfer::filter` explicitly excludes it. However, `pallet_proxy`'s nested-call gate for privilege changes checks only `is_superset`, not `filter`:
```
Some(Call::add_proxy { ref proxy_type, .. }) | Some(Call::remove_proxy { ref proxy_type, .. })
    if !def.proxy_type.is_superset(proxy_type) => false,
``` [3](#0-2) 

Since `NonTransfer.is_superset(Auction)` returns `true` in the relay chain runtime configs [4](#0-3) , a `NonTransfer` proxy is permitted to call `Proxy::proxy(real, None, Proxy::add_proxy{delegate: attacker_account, proxy_type: Auction, delay})` on behalf of `real`. This grants the attacker's own account an `Auction`-type proxy delegation for `real`. The attacker can then call `Proxy::proxy(real, Some(Auction), Registrar::swap{id, other})`, which `Auction::filter` admits because it matches the whole `RuntimeCall::Registrar(..)` variant unconditionally [6](#0-5) . The attacker has thus reached a call (`Registrar::swap`) that their original `NonTransfer` grant deliberately excluded, without ever obtaining `Any` or governance/root privileges.

### Impact Explanation
`Registrar::swap` mutates `PendingSwap` and, once both sides confirm, swaps lease-holding status, auction data, and reserved deposits between two `ParaId`s [2](#0-1) . A delegate limited to `NonTransfer` (explicitly meant to be unable to perform this action) can nonetheless force it, provided they can get the "opposite" swap acknowledged by the counterparty para (per `ensure_root_para_or_owner`, they'd need the para itself, its owner, or Root to consent to the swap on the other side — the escalation only removes the `NonTransfer` delegate's own restriction on initiating/acknowledging the swap for their delegator's para). This is a permission-boundary violation directly analogous to the Snipe-IT CVE: a principal with restricted "edit" rights can grant itself an unauthorized broader capability by manipulating a permission-assignment endpoint whose authorization check is decoupled from the actual capability check.

### Likelihood Explanation
Moderate. It requires the victim to have already granted an attacker-controlled account a `NonTransfer` proxy (a common configuration, since `NonTransfer` is the typical "safe" delegation used for day-to-day account management) and requires cooperation of the swap counterparty for `swap` to fully execute (the `PendingSwap` two-sided confirmation), but the actual privilege-escalation step (self-granting an `Auction` proxy while restricted to `NonTransfer`) requires zero additional permission and is a single-transaction operation with no extra cost beyond the normal proxy deposit.

### Recommendation
Either (a) make `NonTransfer::filter` admit the full `RuntimeCall::Registrar(..)` family (dropping the deliberate `swap` exclusion) if `swap` is intended to be `NonTransfer`-safe, or (b) remove `(ProxyType::NonTransfer, _) => true` as a blanket rule and instead enumerate only the proxy types whose filters are true subsets of `NonTransfer`'s filter (mirroring the fix applied for `Governance` in `pr_12769.prdoc`), or (c) tighten `ProxyType::Auction`'s filter to exclude `Registrar::swap` specifically. Add a lattice-consistency regression test analogous to `proxy_type_superset_relation_matches_call_filters` for the relay-chain runtimes to catch future divergences [9](#0-8) .

### Proof of Concept
Not executed against a live/test harness (no terminal access in this ask-only session), but the reachable code path is fully traced through static analysis:
1. `real` grants `attacker` a `NonTransfer` proxy: `Proxy::add_proxy(real, attacker, NonTransfer, 0)`.
2. `attacker` calls `Proxy::proxy(real, None, Box::new(RuntimeCall::Proxy(Call::add_proxy{delegate: attacker2, proxy_type: Auction, delay: 0})))`. This passes `do_proxy`'s filter because `NonTransfer.is_superset(Auction) == true` [4](#0-3) , registering `attacker2` (which can be the same key as `attacker`, since `NoSelfProxy` only blocks `delegate == real`) as an `Auction` proxy of `real`.
3. `attacker2` calls `Proxy::proxy(real, Some(Auction), Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap{id, other})))`. `Auction::filter` admits this because it matches the unrestricted `RuntimeCall::Registrar(..)` pattern [6](#0-5) , executing `swap` on `real`'s behalf — a call `NonTransfer::filter` explicitly forbids.

I could not run this against `substrate/frame/proxy` test harness or a live westend/rococo node in this session; this should be validated with an integration test built on the existing `pallet_proxy`/`paras_registrar` mocks before filing to confirm end-to-end dispatch success and the exact CannotSwap/PendingSwap preconditions needed for `swap` to fully commit.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12724>.
///
/// `NonTransfer` used to claim `Governance` as a subset while denying the `Treasury`,
/// `ConvictionVoting`, `Referenda` and `Whitelist` calls that `Governance` admits, which let a
/// `NonTransfer` proxy add a `Governance` proxy and widen its own permissions.
#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));
