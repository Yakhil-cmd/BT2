## Finding: Uncaught exception in `chash.isChashValid` on malformed chash input (CVE-2020-35909 analog)

### Title
Unhandled panic (uncaught exception) in `chash.isChashValid` on malformed address/chash strings - (File: `chash.js`)

### Summary
`chash.isChashValid()` is documented (via its boolean return type and usage as a pure predicate) to safely validate arbitrary attacker-supplied chash/address strings, but it can throw an uncaught `Error` when the decoded byte length doesn't correspond to a supported chash length, exactly mirroring the `multihash::from_slice` panic pattern in the reported advisory: a function whose signature/usage implies "always returns a result," but which can throw on malformed untrusted input.

### Finding Description
`isChashValid(encoded)` only wraps the actual base32/base64 *decode* call in a `try/catch`: [1](#0-0) 

Once decoding succeeds, `binChash = buffer2bin(chash)` and `separateIntoCleanDataAndChecksum(binChash)` run **outside** the try/catch. `separateIntoCleanDataAndChecksum` throws a raw `Error` if the bit-length of the decoded buffer is not exactly 160 or 288: [2](#0-1) 

The 48-character (base64, 288-bit) branch is particularly exposed: `Buffer.from(encoded, 'base64')` in Node.js silently ignores invalid characters instead of throwing, so a 48-character string containing a mix of valid and invalid base64 characters can decode to a buffer whose length is not exactly 36 bytes (288 bits), triggering the uncaught `throw Error("bad length=...")` at chash.js:53.

Additionally, `validation_utils.isValidAddressAnyCase()` calls `isValidChash(address, 32)` directly without the strict `/^[A-Z2-7]{32}$/` character-class guard that `isValidAddress()` applies before calling into chash validation: [3](#0-2) 

This means any code path that validates an address via `isValidAddressAnyCase` (rather than `isValidAddress`) passes attacker-controlled strings straight into `chash.isChashValid`/`base32.decode` without first constraining them to the safe base32 alphabet, removing the implicit guarantee that the decoded length will always match 160 bits.

### Impact Explanation
An uncaught exception thrown deep inside chash/address validation, if not caught by an outer try/catch in the calling validation chain, propagates up through unit/definition/address validation. Depending on where the call originates (asynchronous callback context, event handler, etc.), this can crash the Node.js process handling unit or message validation — a denial-of-service against the node's ability to validate and confirm new units, network-visible and triggerable by any party able to submit a unit, attestation, or shared-address definition containing a malformed chash/address string.

### Likelihood Explanation
Reaching `isChashValid` for the 288-bit branch requires only supplying a 48-character string with invalid base64 characters wherever a chash288 value is validated (e.g., attestor/definition chash contexts), and reaching the 160-bit branch via the case-insensitive path requires code to call `isValidAddressAnyCase` with attacker input instead of `isValidAddress`. I was not able to fully confirm, within tool budget, the exact call site(s) in `validation.js` that invoke `isValidAddressAnyCase` on unit-derived data (a `grep_search` located one match in `validation.js` but I could not inspect its surrounding context before running out of iterations), so exploitability specifically through that path is unconfirmed. The 288-bit base64 branch, however, is directly demonstrable from the `chash.js` code alone.

### Recommendation
Move the length-consistency checks (`binChash.length === 160 || 288`) inside the existing `try/catch` in `isChashValid`, or wrap the calls to `buffer2bin`/`separateIntoCleanDataAndChecksum` in their own try/catch and return `false` on any thrown error instead of letting it propagate. Additionally, audit all callers of `isValidAddressAnyCase` to ensure they don't feed unfiltered attacker strings into chash decoding without the same character-class pre-check used by `isValidAddress`.

### Proof of Concept
```js
var chash = require('./chash.js');
// 48-char string, valid base64 alphabet but with a character combination
// that Buffer.from('base64') decodes to a length not divisible into 288 bits
// after ignoring/handling certain invalid runs -> triggers separateIntoCleanDataAndChecksum
// to throw an uncaught Error outside chash.js's try/catch.
try {
    chash.isChashValid("A".repeat(47) + "!"); // 48 chars, contains invalid base64 char
} catch (e) {
    console.log("uncaught exception, not a boolean return:", e);
}
```
