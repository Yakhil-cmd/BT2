### Title
Pre-Permissionless Single-Mode `VerifyVote` Missing Governing-Node Restriction Allows Unauthorized Governance Takeover — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

`VerifyVote` only enforces the single-mode governing-node restriction when `IsPermissionlessForkEnabled` is true. On chains where `PermissionlessCompatibleBlock=nil`, any council member who is selected as a block proposer can embed a vote for `governance.governingnode=self` in a block header, pass all validation, have the vote stored by `HandleVote`, and have it ratified at the epoch boundary — permanently transferring the `GoverningNode` parameter to themselves.

---

### Finding Description

The guard in `VerifyVote` is: [1](#0-0) 

```go
// In single mode, only the governing node can write header.Vote after Permissionless.
if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
    params.GovernanceMode == "single" &&
    vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
```

When `PermissionlessCompatibleBlock=nil`, `IsPermissionlessForkEnabled` returns `false` (standard `isForked(nil, num)` pattern), so the entire block is skipped. [2](#0-1) 

The remaining checks in `VerifyVote` do **not** compensate:

1. **Council membership check** — passes for any council member. [3](#0-2) 
2. **Proposer integrity check** — passes when the voter is the block proposer (normal consensus rotation). [4](#0-3) 
3. **`checkConsistency` for `GovernanceGoverningNode`** — in single mode, only verifies that the *current* `GoverningNode` (addrA) is in the council; it does **not** verify that the voter is the governing node, nor that the vote value is the current governing node. [5](#0-4) 

After `VerifyVote` passes, `PostInsertBlock` calls `HandleVote`, which stores the vote unconditionally (no voter-identity check): [6](#0-5) 

At the epoch boundary, `getExpectedGovernance` aggregates all stored votes from the previous epoch without filtering by voter identity, producing a `GovData` that includes `governance.governingnode=addrB`: [7](#0-6) 

The epoch block proposer (any node) embeds this `GovData` via `PrepareHeader`, `VerifyGov` confirms it matches the expected value, and `HandleGov` persists it — making `GetParamSet` return `GoverningNode=addrB` for all subsequent blocks. [8](#0-7) 

---

### Impact Explanation

`GoverningNode` is the sole authority for governance votes in single mode. Corrupting it transfers permanent governance control to the attacker: they can subsequently vote to change any governance parameter (minting amount, reward ratios, committee size, unit price, etc.) without restriction. This is a **governance privilege escalation** that changes protected chain state.

---

### Likelihood Explanation

The attacker must be a council member (a validator on the network). In Istanbul BFT, all council members rotate as block proposers — no special key or majority collusion is required. The attacker simply waits for their proposer turn and embeds the malicious vote. On any pre-Permissionless Kaia chain running the new `headerGovModule` code with `GovernanceMode=single`, this is exploitable by any single council member acting alone.

---

### Recommendation

Remove the `IsPermissionlessForkEnabled` gate from the single-mode restriction. The governing-node vote restriction is a property of `GovernanceMode=single`, not of the Permissionless fork:

```go
// In single mode, only the governing node can write header.Vote.
params := h.GetParamSet(blockNum)
if params.GovernanceMode == "single" &&
    vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
```

---

### Proof of Concept

```
Setup:
  PermissionlessCompatibleBlock = nil
  GovernanceMode = "single"
  GoverningNode = addrA
  Council = [addrA, addrB]

Step 1: addrB is selected as block proposer for block N (normal consensus rotation).
Step 2: addrB embeds Vote{voter=addrB, name="governance.governingnode", value=addrB} in header.Vote.
Step 3: VerifyVote(header):
  - IsPermissionlessForkEnabled → false → single-mode check skipped ✓
  - addrB ∈ council ✓
  - author(header) == addrB ✓
  - checkConsistency: addrA ∈ council → return nil ✓
  → VerifyVote returns nil (no error)
Step 4: PostInsertBlock → HandleVote stores vote at blockNum N.
Step 5: At block epoch*k, getExpectedGovernance collects {N: vote{governingnode=addrB}}.
Step 6: PrepareHeader embeds GovData{governingnode=addrB} in header.Governance.
Step 7: VerifyGov confirms match; HandleGov persists it.
Step 8: GetParamSet(epoch*k + 1).GoverningNode == addrB  ← governance hijacked
```

```go
func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}
```

```go
func (h *headerGovModule) HandleVote(blockNum uint64, vote headergov.VoteData) error {
	// if governance vote (i.e., not validator vote), add to vote
	if _, ok := gov.Params[vote.Name()]; ok {
		h.AddVote(blockNum, vote)
		InsertVoteDataBlockNum(h.ChainKv, blockNum)
	}

	// if the vote was mine, remove it.
	h.removeMyVote(vote)

	return nil
}
```
