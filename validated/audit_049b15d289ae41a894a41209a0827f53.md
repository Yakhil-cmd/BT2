## Analysis: Bad-debt socialization triggered by an imprecise "other collateral repayable" estimate

This is a genuine analog to the Reserve "basket range" bug class: an over-conservative estimation formula that decides between "recover value normally" vs. "write off value as a loss," where the estimate uses the wrong parameter and biases toward the loss-generating path — except here the loss lands on vault suppliers rather than RToken holders.

### Title
Bad-debt socialization decision uses `liq-penalty-max` instead of the actual applicable penalty, causing premature write-down of recoverable debt onto vault suppliers - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
In `liquidate()`, once the currently-liquidated collateral asset is exhausted, the contract decides whether the position has "no collateral left" (triggering bad-debt socialization across all vault suppliers) by estimating how much of the remaining debt the borrower's *other* collateral assets could still repay (`other-debt-repayable`). This estimate always uses the egroup's `liq-penalty-max` constant rather than the penalty that would actually apply to a subsequent liquidation of that other collateral. Because a higher assumed penalty divisor shrinks the computed repayable amount, this systematically *underestimates* real repay capacity, making `other-debt-repayable` more likely to be evaluated as `u0` and `no-collateral-left` to be wrongly set `true` even though the borrower still holds enough of another collateral asset to fully cover the remaining debt through a normal follow-up liquidation.

### Finding Description
`other-coll-usd` is the USD value of the borrower's collateral not part of the asset currently being liquidated: [1](#0-0) 

`other-debt-repayable` converts that value into an amount of debt it could satisfy, but always divides by `(+ BPS liq-penalty-max)` — the maximum possible liquidation penalty for the egroup — instead of whatever penalty would actually apply when that other collateral is eventually liquidated: [2](#0-1) 

This value directly gates whether the position is treated as fully drained of collateral: [3](#0-2) 

When `no-collateral-left` is `true`, the remaining scaled debt is folded into `socialize-debt-asset`, which calls `vault-socialize-debt` to write down the vault's `lindex` (and hence supplied principal/yield) for **every** current supplier of that vault — an irreversible mutualized loss: [4](#0-3) 

Because `liq-penalty-max` is used regardless of the true applicable penalty, `other-debt-repayable` is biased low. This is exactly the same class of defect as the Reserve report: an estimation formula that uses an extreme boundary value (there: min/max oracle price on the whole basket; here: the max liquidation penalty on the whole remaining collateral) instead of the value that actually reflects the recoverable amount, causing the protocol to take the costly "write-off" branch in cases where the deficit was in fact recoverable through ordinary means (here: a subsequent liquidation call against the borrower's other collateral).

### Impact Explanation
The attacker here is any unprivileged liquidator who calls `liquidate()` against one collateral leg of a multi-collateral position while the borrower still holds a materially different amount of another, healthy collateral asset. Due to the biased estimate, the liquidator's call can cause the contract to erroneously conclude the position has no more collateral, invoking `socialize-debt-asset` and permanently writing down `lindex` in the relevant vault(s). The victims are the vault's other suppliers/lenders — unprivileged principals who did not participate in this liquidation — whose deposited principal (via reduced `total-assets`/`lindex`) absorbs a loss that a correctly-computed estimate would have avoided, since the borrower's remaining collateral could have covered the debt in a normal follow-up liquidation instead. This is a permanent loss of supplier funds (falls under "permanent freezing/loss of funds", potentially contributing to protocol insolvency for the affected vault if repeated).

### Likelihood Explanation
This does not require any privileged access, oracle manipulation, or flashloans — only a position with more than one collateral asset type nearing/at the liquidation threshold and a normal liquidation call against the smaller/dust'd collateral leg first. The bias is deterministic (built into the formula, not just an edge case of rounding), so it manifests whenever the actual applicable penalty on the borrower's other collateral is below `liq-penalty-max`, which is a common state for any position that isn't at the worst end of the liquidation curve.

### Recommendation
Compute `other-debt-repayable` using the liquidation penalty that would actually apply to the borrower's other collateral (i.e., re-derive `calc-liquidation-params`/the applicable `liq-penalty` for the position's *current* LTV against that collateral's egroup) rather than unconditionally assuming `liq-penalty-max`. Alternatively, mirror the Reserve mitigation approach: first establish the true "floor" of recoverable value from all remaining collateral using accurate, per-asset penalty terms, and only socialize the debt that provably cannot be recovered after that more precise accounting.

### Proof of Concept
1. Borrower opens a position with two enabled collateral assets, A and B, plus debt in asset D, such that the position's current LTV is below `ltv-liq-full` (so the applicable penalty for a liquidation of B alone would be well below `liq-penalty-max`).
2. Liquidator calls `liquidate()` against collateral A with a `debt-amount` sized so that, after processing, collateral A becomes fully exhausted (`coll-removed` reduces A's balance to 0) while asset B remains with meaningful value and there is still remaining scaled debt to repay.
3. The contract computes `other-coll-usd` from B's USD value and then `other-debt-repayable` by dividing by `(+ BPS liq-penalty-max)`. If `liq-penalty-max` overstates the true applicable penalty enough that `other-debt-repayable` rounds to `u0` relative to the remaining debt, `no-collateral-left` evaluates `true`.
4. `socialize-debt-asset` is invoked, writing down `lindex` for D's vault, permanently reducing balances for all of that vault's suppliers — even though asset B, if liquidated in a follow-up call using its true (lower) applicable penalty, would have fully repaid the remaining debt without any loss to suppliers.
