### Title
Missing Trust-Level Authorization Check Allows Indirect Correspondent to Silently Register Attacker-Controlled Shared Address - (File: wallet.js)

### Summary
`wallet.js`'s `handleMessageFromHub` used to restrict which message subjects an **indirect correspondent** (a device automatically introduced as a cosigner peer, never explicitly paired/trusted by the user) was allowed to send. That guard is now commented out, so every message subject — including `new_shared_address`, which is processed **without any user confirmation** — is accepted from indirect correspondents. Combined with a missing sender-authorization check inside `handleNewSharedAddress`, an indirect correspondent can silently register a shared (multisig) address that includes one of the victim's real addresses, using a definition such as `"or"` where the attacker's own device is an independently sufficient signer.

### Finding Description
`handleMessageFromHub` previously enforced:
```js
//if (bIndirectCorrespondent && ["cancel_new_wallet", "my_xpubkey", "new_wallet_address"].indexOf(subject) === -1)
//    return callbacks.ifError("you're indirect correspondent, cannot trust "+subject+" from you");
``` [1](#0-0) 

This whitelist check is fully disabled, so `doHandle()` [2](#0-1)  now dispatches **every** subject, including `new_shared_address`, regardless of whether the sender is an indirect (unvetted) correspondent.

The `new_shared_address` handler, `handleNewSharedAddress`, validates internal consistency of the attacker-supplied definition (hash matches, signer addresses match definition leaves) but never checks that the actual message sender (`from_address`) is one of the parties named in `body.signers`: [3](#0-2) 

It only checks whether *one of my own addresses* happens to be referenced in the definition via `determineIfIncludesMeAndRewriteDeviceAddress`: [4](#0-3) 

If it is, `addNewSharedAddress` is invoked and the address is recorded **silently** — no UI confirmation dialog is fired, unlike other flows in this file that explicitly emit `create_new_shared_address` for user approval: [5](#0-4) 

Because indirect correspondents are introduced automatically as part of multi-device wallet setup (`device.addIndirectCorrespondents`, referenced from `wallet_defined_by_keys.js`) rather than through explicit user pairing, they are a lower-trust class of device — precisely the class the removed whitelist was meant to restrict.

### Impact Explanation
An indirect correspondent (already reachable as a "paired device" class of actor per the private messaging protocol, but never explicitly trusted by the wallet owner) can craft a `["or", [["address", VICTIM_ADDR], ["address", ATTACKER_ADDR]]]` definition, compute its c-hash, and send a forged `new_shared_address` message naming the victim's real address as one signer and the attacker's own address as the other. Because the sender-authorization check is absent, and the whitelist that would have blocked this subject for indirect correspondents is disabled, the victim's wallet silently records this as a legitimate shared/multisig address it is a member of. If the wallet subsequently offers this address for receiving funds (as a valid "shared address" belonging to the user), any coins sent to it can be unilaterally spent by the attacker alone via the `"or"` branch — resulting in concrete unauthorized loss of funds, matching the disclosed bug class of missing authorization enabling unauthorized modification of another party's financial resource.

### Likelihood Explanation
Indirect correspondents are added automatically whenever the user participates in any multi-device wallet or shared-address setup with any third party, without an explicit "do you trust this device" prompt from the user. Any such loosely-connected device can exploit this immediately by sending one crafted message; no race condition, network position, or additional social engineering beyond becoming an indirect correspondent (a byproduct of ordinary multisig/shared-wallet usage) is required.

### Recommendation
Restore (and generalize) the trust-level check in `handleMessageFromHub` so indirect correspondents can only trigger the originally intended small whitelist of subjects. Additionally, in `handleNewSharedAddress`, verify that the message sender's device address (`from_address`) actually appears among `body.signers` device addresses before accepting/recording the shared address, and require explicit user confirmation before calling `addNewSharedAddress`, mirroring the confirmation flow used for `create_new_shared_address`.

### Proof of Concept
1. Attacker device becomes an indirect correspondent of the victim (e.g., by being listed as `other_cosigners` in some unrelated wallet creation offered by a third device, per `wallet_defined_by_keys.js` `handleOfferToCreateNewWallet`).
2. Attacker crafts `arrDefinition = ["or", [["address", VICTIM_ADDR], ["address", ATTACKER_ADDR]]]`, computes `address = objectHash.getChash160(arrDefinition)`.
3. Attacker sends a device message:
```json
{
  "subject": "new_shared_address",
  "body": {
     "address": "<computed c-hash>",
     "definition": ["or", [["address", "VICTIM_ADDR"], ["address", "ATTACKER_ADDR"]]],
     "signers": {
        "r.0": {"address": "VICTIM_ADDR", "device_address": "VICTIM_DEVICE"},
        "r.1": {"address": "ATTACKER_ADDR", "device_address": "ATTACKER_DEVICE"}
     }
  }
}
```
4. Because the indirect-correspondent whitelist check is disabled, this message reaches `walletDefinedByAddresses.handleNewSharedAddress` (dispatch point not shown in the retrieved excerpt but implied by the `new_shared_address` case wiring alongside `create_new_shared_address` at [5](#0-4) ).
5. `handleNewSharedAddress` finds `VICTIM_ADDR` among `my_addresses`, passes validation, and calls `addNewSharedAddress` silently, registering the shared address with no user prompt.
6. If the victim's wallet later surfaces this shared address for receiving payments and the victim (or a third party paying them) sends funds there, the attacker can spend those funds unilaterally via the `"or"` clause, without the victim's cooperation.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
