### Title
Whale-market accrual overflows scaled values and permanently freezes the market - (File: common/src/rates/simulate.rs)

### Summary
Medium: a supported high-decimal, high-cap market can reach a state where every accrual attempts `scaled_shares * index / RAY` beyond `i128::MAX`, causing a permanent `MathOverflow` before any index is committed. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` converts both aggregate debt and aggregate supply from scaled RAY shares to their indexed values before calculating utilization or updating the indexes. [1](#0-0)  The conversion delegates to `scaled.mul`, and unrepresentable results raise `MathOverflow` rather than clamping or using a recoverable value. [3](#0-2) [4](#0-3) 

`update_borrow_index` caps only the index at `MAX_BORROW_INDEX_RAY`; it does not bound `borrowed * borrow_index / RAY` or `supplied * supply_index / RAY`. [5](#0-4)  Consequently, a book whose scaled aggregate is near the permitted balance ceiling can cross the `i128` value ceiling while its index remains below the protocol index cap. [6](#0-5) [7](#0-6) 

Once this state is reached, `global_sync` panics inside `accrue_step` before `mark_accrued` can run, so the stale `last_timestamp` remains committed and every later accrual retries the same overflowing product. [8](#0-7) [9](#0-8)  All ordinary pool legs load that synchronized market through `synced_market` or `load_leg`, and bad-debt seizure also calls `synced_market`, so supply, borrow, withdraw, repay, liquidation, cleanup, revenue, and recapitalization paths touching the market all inherit the panic. [10](#0-9) [11](#0-10) 

### Impact Explanation
This permanently freezes all funds and debt operations for the affected `(hub_id, asset)` book: suppliers cannot withdraw, borrowers cannot repay, and liquidators or bad-debt cleanup cannot pass the same pre-operation accrual. [10](#0-9) [12](#0-11)  The existing regression test demonstrates that `update_indexes` fails with `MathOverflow`, the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, and subsequent `withdraw` and `repay` calls fail with the same error. [13](#0-12) 

### Likelihood Explanation
Triggering the state requires a listed market whose spoke caps and token liquidity permit approximately one billion whole tokens, plus enough separate collateral to borrow about 98% of that liquidity under a steep configured rate curve. [14](#0-13) [15](#0-14)  The size is within the protocol’s explicit cap domain: an 18-decimal market can be configured for over 170 billion whole tokens, while governance validation otherwise enforces the cap ceiling. [16](#0-15) [17](#0-16)  The capital requirement and need for sustained high utilization make this less likely than a routine arithmetic failure, but the resulting freeze is deterministic and cannot be repaired through any permissionless controller entrypoint. [18](#0-17) [13](#0-12) 

### Recommendation
Bound each market’s usable index against its current scaled aggregate before calculating indexed totals, or perform utilization and accrual deltas in `I256` with explicit saturation at a safe committed index. [19](#0-18)  At minimum, compute `max_safe_index = min(protocol_index_cap, floor(i128::MAX * RAY / scaled_aggregate))` for both the borrow and supply books, clamp index growth before `scaled_to_original`, and preserve liveness by allowing repayments, withdrawals, liquidation, and bad-debt settlement after saturation. [20](#0-19) [10](#0-9)  Add a regression test proving that a maximum-cap, high-decimal market at the value ceiling can still accrue to its safe bound and subsequently repay, withdraw, liquidate, and clean bad debt. [2](#0-1)

```rust
    attacker,
    0,
    spoke_id,
    vec![(col, 3_000_000_000i128 * 10i128.pow(7))],

controller.borrow(
    attacker,
    borrower_id,
    vec![(big18.clone(), 980_000_000i128 * 10i128.pow(18))],
    Some(attacker),
);

// After sustained high-utilization accrual:
controller.update_indexes(attacker, vec![big18.clone()]); // MathOverflow

// Every later attempt that accrues the same market also reverts.
controller.withdraw(attacker, lender_id, vec![(big18.clone(), 1)], None);
controller.repay(attacker, borrower_id, vec![(big18, 1)]);
```

```rust
pub fn accrue_step(
    env: &Env,
    params: &MarketParams,
    borrowed: Ray,
    supplied: Ray,
    borrow_index: Ray,
    supply_index: Ray,
    delta_ms: u64,
) -> AccrualStep {
    let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
    let supplied_original = scaled_to_original(env, supplied, supply_index);
    let util = utilization(env, borrowed_original, supplied_original);
    let borrow_rate = calculate_borrow_rate(env, util, params);
    let interest_factor = compound_interest(env, borrow_rate, delta_ms);

    let new_borrow_index = update_borrow_index(env, borrow_index, interest_factor);

    let (supplier_rewards, protocol_fee) =
        calculate_supplier_rewards(env, params, borrowed, new_borrow_index, borrow_index);

    let new_supply_index = update_supply_index(env, supplied, supply_index, supplier_rewards);
    let supplier_shortfall = supply_index_reward_shortfall(
        env,
        supplied,
        supply_index,
        new_supply_index,
        supplier_rewards,
    );

    let protocol_reward = protocol_fee.checked_add(env, supplier_shortfall);
    // Shares are valued at the new supply index, which the caller stores for
    // this step.
    let revenue_shares = if protocol_reward == Ray::ZERO {
        Ray::ZERO
    } else {
        protocol_fee_shares(env, protocol_reward, new_supply_index, supplied)
    };
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
```

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
/// Returns the largest cap, in asset base units, whose ray-scaled form still
/// fits in `i128`.
///
/// Returns 0 when `asset_decimals > RAY_DECIMALS`, since the ray form is not
/// representable in that case. Enforced by
/// [`require_cap_within_asset_domain`], so stored caps can never overflow the
/// asset→ray rescale.
pub fn max_cap_for_decimals(asset_decimals: u32) -> i128 {
    let Some(exp) = RAY_DECIMALS.checked_sub(asset_decimals) else {
        return 0;
    };
    let upscale = 10i128
        .checked_pow(exp)
        .expect("10^(RAY_DECIMALS - asset_decimals) fits i128 for asset_decimals <= RAY_DECIMALS");
    i128::MAX / upscale
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
```
