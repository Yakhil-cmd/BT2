### Title
Cross-organization team hijack via global `github_id` lookup in `MembershipHandler#process` - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`MembershipHandler#process` resolves the `Team` to mutate solely by the numeric `params.team.id` (GitHub team ID) via `find_or_create_team!`, without ever checking that `params.organization.login` matches the team's actual `organization`. Webhook signature verification (`WebhooksController#verify_signature`) is scoped to whatever organization login appears *in the attacker-controlled payload*, not to the organization that actually owns the referenced team ID, so an attacker who controls a Shipit-configured GitHub organization can forge a `membership`/`removed` event naming a victim team's `github_id` and delete a real operator's `Membership`.

### Finding Description
The binding that should hold is: `Team.find_by(github_id: params.team.id).organization == params.organization.login` (the team resolved by the webhook must belong to the organization that the webhook signature actually authenticates). This binding is never checked.

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner` as `params.dig('repository','owner','login') || params.dig('organization','login')` [1](#0-0)  — for `membership` events there is no `repository` key, so it falls back to `params['organization']['login']`, a value fully controlled by the attacker's JSON body.
2. It then calls `Shipit.github(organization: repository_owner)` and verifies the HMAC signature using the config registered for *that named organization* [2](#0-1) . `Shipit.github` looks up per-organization config via `github_app_config(organization)` [3](#0-2) . This proves only that the attacker knows the webhook secret for the organization *named in their own payload* (their own org) — it says nothing about the team referenced inside the payload.
3. Once verified, `MembershipHandler#process` calls `find_or_create_team!`, which does `Team.find_or_create_by!(github_id: params.team.id)` [4](#0-3) . This is a global lookup keyed only on the numeric GitHub team ID, with no `organization` scoping/equality check against `params.organization.login`.
4. For `action == 'removed'`, it unconditionally executes `team.members.delete(member)` [5](#0-4) , deleting the `Membership` row for `member` regardless of which organization actually sent the event.

Attacker request: the attacker registers/controls their own GitHub organization ("attacker-org") that is configured in Shipit's `secrets.github` (a legitimate, low-privilege organization onboarding — nothing about Shipit prevents any organization from being configured this way, or the attacker could still know their own webhook secret for a hook they set up on a repo/org they own). They send `POST /webhooks` with header `X-Github-Event: membership`, body:
```json
{
  "action": "removed",
  "team": { "id": <victim_team_github_id>, "name": "...", "slug": "...", "url": "..." },
  "organization": { "login": "attacker-org" },
  "member": { "login": "<victim-operator-login>" }
}
```
signed with `X-Hub-Signature` computed using attacker-org's own webhook secret. `verify_signature` passes because it validates against `attacker-org`'s secret, matching the `organization.login` in the payload. `find_or_create_team!` then resolves the pre-existing `Team` row with `github_id == victim_team_github_id` (a team in `Shipit.github_teams` belonging to a completely different, legitimate organization), and `team.members.delete(member)` deletes the victim operator's real `Membership`.

No existing guard prevents this: `verify_signature` only proves knowledge of a secret tied to the organization name embedded in the same forged payload; `drop_unhandled_event` and `ExplicitParameters` schema only validate shape/presence of fields, not cross-object consistency; there is no `require_permission!`/authorization check in `MembershipHandler` at all, since webhook handlers implicitly trust the signature check as sole authentication and that check does not bind the payload's `team.id` to `organization.login`.

### Impact Explanation
A member of any single GitHub organization that Shipit is configured to trust (even one added only for legitimate purposes) can forcibly revoke another organization's operator's team membership by referencing that team's `github_id` in a forged `membership` webhook. This breaks the authorization state (`Shipit.github_teams`) that gates deploy/approve/admin permissions elsewhere in the app (`User#authorized?`), effectively a denial of legitimate access / unauthorized mutation of another tenant's authorization records — matching "escalation into `Shipit.github_teams` authorization" (High) since it directly tampers with the membership table backing team-based authorization, reachable from any org the attacker can get onboarded/registered in Shipit, not just the target org.

### Likelihood Explanation
Preconditions: Shipit must be configured with the multi-organization `secrets.github` schema (so `repository_owner`/`organization.login` drives per-org secret selection) and have at least one organization the attacker controls onboarded (a realistic operational setup for a Shipit host serving multiple GitHub orgs). The victim team's `github_id` must be known or guessable (GitHub team IDs are visible via public APIs/team URLs in many cases, or via prior `added`/other membership events, or brute-forcible small integers). The attacker needs no Shipit credentials, only their own organization's registered webhook secret, which they legitimately know as the org's admin. This is fully repeatable against any team ID for any organization Shipit tracks.

### Recommendation
In `find_or_create_team!`, require an exact match between the resolved team's `organization` and `params.organization.login` before mutating membership; reject (or create only under the correct organization scope) when they differ:
```ruby
def find_or_create_team!
  team = Team.find_by(github_id: params.team.id)
  if team && team.organization.casecmp(params.organization.login) != 0
    raise ArgumentError, "team/organization mismatch"
  end
  team || Team.create!(github_team: params.team, organization: params.organization.login)
end
```
Additionally, consider validating `params.organization.login == repository_owner` used for signature verification is authoritative and can't be spoofed for teams belonging to other orgs — i.e., always cross-check the org that authenticated the request against the org stored on the resolved record before performing any write.

### Proof of Concept
Minitest plan (`test/models/shipit/webhooks/handlers/membership_handler_test.rb` conceptually, or `test/controllers/webhooks_controller_test.rb`):
1. Create `victim_team = Team.create!(organization: 'victim-org', github_id: 555, slug: 'ops', name: 'Ops', api_url: '...')`.
2. Create `operator = User.find_or_create_by_login!('victim-operator')` and `Membership.create!(team: victim_team, user: operator)`. Assert `Membership.where(team: victim_team, user: operator).count == 1`.
3. Configure Shipit with two orgs in `secrets.github`: `victim-org` (secret A) and `attacker-org` (secret B), both known to the test.
4. POST to `/webhooks` with `X-Github-Event: membership`, body `{"action":"removed","team":{"id":555,...},"organization":{"login":"attacker-org"},"member":{"login":"victim-operator"}}`, signed only with attacker-org's secret B (never using secret A).
5. Assert response is `200`/`:ok` (signature accepted) and assert `Membership.where(team: victim_team, user: operator).count == 0` — proving the binding `team.organization == organization.login` was violated: the event was authenticated only for `attacker-org` yet mutated `victim-org`'s team membership.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
