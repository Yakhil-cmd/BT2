### Title
Signed-integer narrowing cast in `consolidatedNode.Split` corrupts CN/CL reward split — (`kaiax/staking/staking_info.go`)

### Summary

`consolidatedNode.Split` converts both `uint64` staking-amount fields to `*big.Int` via `big.NewInt(int64(...))`. The explicit `int64(...)` cast silently wraps any value above `math.MaxInt64` (≈ 9.22 × 10¹⁸ KAIA) to a large negative integer. When that happens the denominator `totalAmount` can become zero (panic / node crash) or negative (CN receives more than the full reward, CL pool receives a negative credit).

### Finding Description

`consolidatedNode.Split` is called every block (post-Prague) to divide each validator's staking reward between its CNStaking contract and its CLStaking pool:

```go
// kaiax/staking/staking_info.go  lines 174-177
cnAmountBig = big.NewInt(int64(c.StakingAmount))           // ← uint64 → int64 cast
clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount)) // ← same
totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
``` [1](#0-0) 

`c.StakingAmount` is declared `uint64` and is the **sum** of all staking-contract balances sharing the same reward address (accumulated without overflow guard at line 138):

```go
cn.StakingAmount += si.StakingAmounts[i]   // uint64 addition, no overflow check
``` [2](#0-1) 

Each individual `StakingAmounts[i]` is stored in KAIA (not kei), produced by:

```go
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
``` [3](#0-2) 

`Split` is invoked in four reward-distribution paths:

| Caller | Purpose |
|---|---|
| `assignStakingRewards` | per-staker reward split (Kore/Prague) |
| `assignStakingRewardsFlex` | per-staker reward split (Flex/Osaka) |
| `specWithProposerAndFunds` | proposer reward split |
| `specWithProposerAndFundsFlex` | proposer reward split (Flex) | [4](#0-3) [5](#0-4) [6](#0-5) 

### Impact Explanation

When `c.StakingAmount > math.MaxInt64` (≈ 9.22 × 10⁹ KAIA):

* `int64(c.StakingAmount)` wraps to a large negative value.
* `totalAmount = cnAmountBig + clAmountBig` becomes negative or zero.
* **Zero denominator** → `big.Int.Div` panics → every honest node crashes while finalising that block → consensus halt.
* **Negative denominator** → `clAmount = clAmountBig × reward / totalAmount` is negative → `cnAmount = reward − clAmount > reward` → the CN address receives more KAIA than the total staking-reward budget for that block; the CL pool address receives a negative credit (balance subtracted), constituting an unauthorized transfer of KAIA from the CL pool.

Both outcomes satisfy the allowed-impact gate: the first is an invalid block acceptance / consensus divergence; the second is an unauthorized transfer affecting KAIA and system-managed funds.

### Likelihood Explanation

`StakingAmounts` are stored in whole KAIA. `math.MaxInt64` ≈ 9.22 × 10⁹ KAIA. The current total circulating supply of KAIA is approximately 5.4 billion KAIA, so no single validator can currently accumulate a consolidated staking amount above the threshold. Likelihood is therefore **low under present supply**, but the defect is latent and will become exploitable as supply grows through minting (configurable via governance), or if the minimum-stake parameter is lowered and many contracts are consolidated under one reward address.

### Recommendation

Replace the narrowing `int64` cast with the correct arbitrary-precision constructor:

```go
// Before (buggy)
cnAmountBig = big.NewInt(int64(c.StakingAmount))
clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))

// After (correct)
cnAmountBig = new(big.Int).SetUint64(c.StakingAmount)
clAmountBig = new(big.Int).SetUint64(c.CLStakingInfo.CLStakingAmount)
```

Apply the same fix to the identical pattern in `consolidateNodes` line 138 (`cn.StakingAmount += si.StakingAmounts[i]`) and in `assignStakingRewards` / `assignStakingRewardsFlex` where `cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount` is performed in `uint64` without overflow detection. ### Proof of Concept

```
Precondition (post-Prague, UseFlexReward or Kore):
  Validator V has consolidated StakingAmount = 9_223_372_036_854_775_808 KAIA
  (= math.MaxInt64 + 1, achievable if total supply exceeds ~9.2 billion KAIA)
  CLStakingAmount = 1_000_000 KAIA

Execution of Split(reward = 1e18 kei):
  cnAmountBig = big.NewInt(int64(9_223_372_036_854_775_808))
             = big.NewInt(-9_223_372_036_854_775_808)   // wraps
  clAmountBig = big.NewInt(1_000_000)
  totalAmount = -9_223_372_036_854_775_808 + 1_000_000
             = -9_223_372_036_853_775_808               // negative

  clAmount = 1_000_000 * 1e18 / (-9_223_372_036_853_775_808)
           ≈ -108 kei                                   // negative

  cnAmount = 1e18 - (-108) = 1_000_000_000_000_000_108 kei
           > total reward budget

Result: CN reward address credited 108 kei more than the full staking-reward
        budget; CL pool address debited 108 kei (unauthorized balance reduction).
        If totalAmount == 0 (exact wrap), big.Int.Div panics → node crash.
```

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}
