### Title
Unprivileged PR labels become unfiltered environment variables reaching `PTY.spawn` (including `GIT_SSH_COMMAND` and `PATH`) - (File: app/models/shipit/review_stack.rb)

### Summary
`Shipit::ReviewStack#env` merges every GitHub PR label name (uppercased) as an environment variable with value `"true"` into the stack's environment, with no allow-list. This label-derived hash flows unfiltered through `TaskCommands#env` into `Command#unbundled_env` and finally into `PTY.spawn`, so a PR author can inject `GIT_SSH_COMMAND` and `PATH` into the git subprocess environment used for `TaskCommands#clone`/`#checkout`.

### Finding Description
The broken binding: the env passed to `PTY.spawn` for git invocations should equal `Shipit.env.merge(deploy_spec.machine_env)` (operator-controlled only), but instead it equals `Shipit.env.merge(deploy_spec.machine_env).merge(pull_request.labels-derived hash)`.

Path:
- `Shipit::Webhooks::Handlers::PullRequest::LabelCapturingHandler#capture_labels` writes `pull_request.update!(labels: params.pull_request.labels.map(&:name))` directly from the untrusted webhook payload, with no validation/allow-list on label names [1](#0-0) .
- `ReviewStack#env` unconditionally merges `pull_request.labels.each_with_object({}) { |label_name, labels| labels[label_name.upcase] = "true" }` on top of `Stack#env` [2](#0-1) .
- `TaskCommands#env` merges `@stack.env` (which for a `ReviewStack` is the label-poisoned hash) into the task environment used to build every `Command` for `clone`/`checkout` [3](#0-2) , [4](#0-3) .
- `Command#unbundled_env` computes `BASE_ENV.merge('PATH' => shell_paths+ENV['PATH']).merge(@env.stringify_keys)` — note `@env` (the label-derived hash) is merged **last**, so a label named `path` overrides the operator-configured `PATH`, and a label named `git_ssh_command` injects `GIT_SSH_COMMAND` [5](#0-4) .
- `Command#start` calls `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)`, so both injected variables reach the spawned git process [6](#0-5) .

No guard exists: `filter_task_envs`/`filter_deploy_envs` in `DeploySpec` only restrict the *user/API-supplied* `env:` argument passed to `Stack#trigger_task`/`#build_deploy` [7](#0-6) ; they never touch `Stack#env`/`ReviewStack#env`, which is merged separately and unconditionally in `TaskCommands#env`.

Exploit flow: An attacker who opened a PR (or pushed a label event) against a repository that has review stacks enabled adds labels `git_ssh_command` and `path` to their own PR via the GitHub UI/API (label add is an action any PR participant with the appropriate repo permission can trigger, and the webhook itself is unauthenticated content from GitHub's side, already covered by signature verification, so this is normal legitimate GitHub traffic reflecting attacker-controlled label metadata). When the review stack's next task (clone/checkout, or later deploy steps) runs, `GIT_SSH_COMMAND=true` and `PATH=<attacker-controlled-value>` are injected into the git subprocess environment.

### Impact Explanation
This is a Critical-class binding violation: an environment key (`GIT_SSH_COMMAND`, `PATH`) reaching `PTY.spawn` is attacker-controlled instead of being restricted to `Shipit.env`/`deploy_spec.machine_env`. Combined with the sibling `path`-label finding, an attacker who additionally controls a file executable named `true` reachable via their injected `PATH` (e.g. committed into their own PR branch content once checked out into `@task.working_directory`) can cause any subsequent git operation on that stack to execute an attacker-supplied program instead of `ssh`, achieving remote code execution on the Shipit deploy host under the deploy user. The blast radius is scoped to the review stack for that PR/repository, but since the injection point is generic label-to-env-var mapping with no allow-list, it applies to any repository using review stacks.

### Likelihood Explanation
Preconditions: the target repository must have review stacks enabled (a normal, documented Shipit feature) and the attacker must be able to open/label a PR against it. No secrets, sessions, or maintainer privileges are required — labeling one's own PR is a standard unprivileged GitHub action. The attack is fully repeatable per PR/stack.

### Recommendation
Do not derive arbitrary environment variable names/values from PR labels in `ReviewStack#env`. At minimum, restrict label-derived variables to a strict allow-list of names that cannot collide with sensitive variables like `GIT_SSH_COMMAND`, `PATH`, `BUNDLE_*`, `GIT_*`, etc., and never let label-derived data override `PATH`/`GIT_SSH_COMMAND`/other security-sensitive keys in `Command#unbundled_env`.

### Proof of Concept
```ruby
test "review stack labels inject GIT_SSH_COMMAND and PATH into Command env reaching PTY.spawn" do
  stack = shipit_stacks(:cyclimse_ios) # or any ReviewStack fixture
  stack.pull_request.update!(labels: ['git_ssh_command', 'path'])

  env = stack.env
  assert_equal 'true', env['GIT_SSH_COMMAND']
  assert_equal 'true', env['PATH']

  command = Shipit::Command.new('git', 'clone', env: env, chdir: '/tmp')
  final_env = command.unbundled_env

  assert_equal 'true', final_env['GIT_SSH_COMMAND']
  assert_equal 'true', final_env['PATH'] # overrides Shipit.shell_paths-prefixed PATH

  # Demonstrates PTY.spawn would be invoked with attacker-controlled GIT_SSH_COMMAND/PATH
end
```

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end
