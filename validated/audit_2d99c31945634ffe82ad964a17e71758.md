### Title
Webhook signature verification silently disabled when any configured organization has a null `webhook_secret`, allowing forged commit-status webhooks against any commit in the datastore - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) resolves the target `GitHubApp` purely from attacker-controlled JSON via `repository_owner` (`params.dig('repository','owner','login') || params.dig('organization','login')`), then calls `GitHubApp#verify_webhook_signature`, which unconditionally returns `true` when `webhook_secret` is blank (`lib/shipit/github_app.rb:76-77`, `return true unless webhook_secret`). `Shipit::Webhooks::Handlers::StatusHandler#process` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`) then updates statuses for `Commit.where(sha: params.sha)` globally, with no scoping to the resolved organization or repository at all.

### Finding Description
The broken binding: `verify_signature returned true == webhook bytes were HMAC-verified against organization X's secret`. In reality, for any organization configured with `webhook_secret: nil` (a supported, documented configuration - see `config/secrets.development.example.yml:11` and `docs/setup.md:194`, and matching `test/dummy/config/secrets.test.json:12`), `verify_webhook_signature` returns `true` for *any* signature header value, including none, per `lib/shipit/github_app.rb:76-77`.

Exploit path:
1. Attacker POSTs to `/webhooks` with `X-Github-Event: status` and body `{"organization":{"login":"no-secret-org"}, "sha":"<victim sha>", "state":"success", ...}` and an arbitrary/absent `X-Hub-Signature`.
2. `drop_unhandled_event` passes (status has a handler); `repository_owner` resolves to `"no-secret-org"` via the `organization.login` fallback (`app/controllers/shipit/webhooks_controller.rb:59-62`).
3. `Shipit.github(organization: 'no-secret-org')` resolves successfully (org is configured, so no `GithubOrganizationUnknown`) and returns a `GitHubApp` whose `@webhook_secret` is `nil` (`lib/shipit/github_app.rb:50`).
4. `verify_webhook_signature` hits `return true unless webhook_secret` and returns `true` regardless of the signature - no bytes are ever authenticated.
5. `#create` dispatches to `StatusHandler.call(params)`, whose `process` does `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` (`app/models/shipit/webhooks/handlers/status_handler.rb:20-24`) - this lookup is global across all stacks/organizations, not scoped by `no-secret-org` or any repository at all.
6. Any commit anywhere in the datastore sharing that sha gets a forged `Status` created via `Commit#create_status_from_github!` → `add_status` → `Status.replicate_from_github!` (`app/models/shipit/commit.rb:165-169`, `app/models/shipit/status.rb:24-33`).

Existing guards do not prevent this: `drop_unhandled_event` only checks event type; the `rescue Shipit::GithubOrganizationUnknown` path only fires when the organization is *not configured at all* - it does nothing when the organization is configured but simply lacks a secret; `ExplicitParameters` (`StatusHandler.params`) only validates payload shape, not provenance; there is no `force_github_authentication`, `require_permission!`, or stack/repository scoping anywhere in this call chain.

### Impact Explanation
A successful request creates a real `Status` row on any commit matching the given sha, regardless of which organization/repository that commit actually belongs to, because `StatusHandler#process` performs an unscoped `Commit.where(sha:)` lookup. This is an authentication bypass: the "WEBHOOK PROVENANCE" binding is never established, yet the write proceeds. Since `Status` creation can flip a commit to `success`, and `Commit#deployable?`/`blocked?` and continuous-delivery triggers (`schedule_continuous_delivery`, `ProcessMergeRequestsJob`) key off status state, this can unblock deploys, trigger merges, or falsify CI state for arbitrary tenants sharing the same Shipit instance - a payload nominally for one (secret-less) organization mutates another organization's commit/stack state. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task or team" and "authentication bypass (forged webhook ... accepted)".

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one GitHub organization configured with `webhook_secret` unset/null - which is an explicitly supported and documented configuration (`docs/setup.md` describes webhook secret as "optional"; the example secrets template and test dummy config both show `webhook_secret: nil`/`null`). Given that, the attacker needs no credentials, no session, no API token, and no knowledge of any secret - only the name of that one secret-less organization (discoverable, e.g., via GitHub org membership or public app config) and a target commit sha (visible on any public GitHub repo, including ones unrelated to that org). The request is a single unauthenticated POST, fully repeatable against any sha.

### Recommendation
Do not treat an absent `webhook_secret` as "verification passed." Either (a) require `webhook_secret` to be present for every configured organization/app at boot (fail-fast validation), or (b) change `verify_webhook_signature` to return `false` (reject) when `webhook_secret` is blank instead of `true`, and additionally scope `StatusHandler`/other handlers' commit lookups by the verified organization's repositories rather than a global `Commit.where(sha:)`.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Stub `Shipit.github(organization: 'no-secret-org')` to return a real `GitHubApp` built with `webhook_secret: nil` (mirroring `test/dummy/config/secrets.test.json`'s `"webhook_secret": null`), without stubbing `verify_signature` (remove/override the `GithubHook.any_instance.stubs(:verify_signature)` from `setup`).
2. Use an existing fixture commit belonging to a *different* org's stack, e.g. `commit = shipit_commits(:first)` (belongs to `shipit_stacks(:shipit)`, associated with org `shopify` per `repository_params`).
3. POST `:create` with `X-Github-Event: status`, body `{ "organization" => { "login" => "no-secret-org" }, "sha" => commit.sha, "state" => "success" }.to_json`, and `X-Hub-Signature` header either absent or set to a bogus value like `"sha1=deadbeef"`.
4. Assert both sides of the equality before/after:
   - Before: `assert_nil GitHubApp.new('no-secret-org', {webhook_secret: nil}).webhook_secret` (provenance never established).
   - After: `assert_difference('commit.statuses.count', 1) { post :create, body:, as: :json }` and `assert_response :ok` - proving a `Status` was written for a commit under `shopify`'s stack despite the request claiming to originate from unrelated org `no-secret-org` with no valid signature.
