### Title
Division-by-zero panic in `NextMagmaBlockBaseFee` when governance sets `GasTarget = 0` — (`params/kip71_config.go`)

---

### Summary

`NextMagmaBlockBaseFee` in `params/kip71_config.go` divides by `gasTarget` at two points (lines 102 and 120) without any zero-guard. The code explicitly protects against `BaseFeeDenominator == 0` (lines 71–76) but applies no analogous protection for `GasTarget == 0`. Because `GasTarget` is a live governance parameter (`Kip71GasTarget`), a governance vote setting it to zero causes every subsequent call to `NextMagmaBlockBaseFee` — including the call inside `VerifyMagmaHeader` during block validation — to panic with a division-by-zero, crashing all honest nodes.

---

### Finding Description

`NextMagmaBlockBaseFee` computes the EIP-1559-style base fee for Kaia's Magma hardfork. The formula normalises the gas-usage delta by dividing by `gasTarget`:

```go
// params/kip71_config.go  line 77
gasTarget := kc.GasTarget          // uint64, governance-controlled

// line 102 (parentGasUsed > gasTarget branch)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // ← panics if gasTarget == 0

// line 120 (parentGasUsed < gasTarget branch)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // ← panics if gasTarget == 0
```

The code already acknowledges this class of problem for `BaseFeeDenominator`:

```go
// lines 71-76
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
```

No equivalent guard exists for `gasTarget`. The only escape path is the early-return at line 90–91:

```go
if parentGasUsed == gasTarget {   // 0 == 0 only when parentGasUsed is also 0
    return makeEvenByFloor(parentBaseFee)
}
```

On a live network `parentGasUsed` is almost never 0, so the code falls through to the division.

`NextMagmaBlockBaseFee` is called from:
- `VerifyMagmaHeader` → `blockchain/block_validator.go` (block validation on every node)
- `work/worker.go` (block production)
- `blockchain/tx_pool.go` (tx-pool base-fee checks)
- `node/cn/gasprice/feehistory.go` (RPC `eth_feeHistory`)

The `KIP71Config` is obtained from live governance parameters (`pset.ToKip71Config()` in `feehistory.go`), so a governance update takes effect immediately for subsequent blocks.

---

### Impact Explanation

After governance sets `GasTarget = 0`:

1. Every honest node that calls `VerifyMagmaHeader` on a block whose parent had non-zero gas usage panics with a Go runtime division-by-zero.
2. Block validation halts on all nodes; the chain stops finalising new blocks.
3. Block production also panics in `work/worker.go`, so no new blocks are proposed.
4. The tx-pool base-fee check in `tx_pool.go` panics, preventing transaction acceptance.

The result is a **persistent chain halt** affecting all honest nodes simultaneously. Recovery requires a coordinated emergency governance vote to restore a non-zero `GasTarget` and a node restart — but because block validation itself panics, nodes cannot process the governance-fix block until the binary is patched or the parameter is corrected out-of-band.

---

### Likelihood Explanation

The trigger is a governance vote to set `GasTarget = 0`. In Kaia's "single" governance mode (the current Mainnet mode), a single governing node can submit this vote unilaterally. The parameter `Kip71GasTarget` in `kaiax/gov/param.go` is a `uint64` governance parameter; the existing format checkers for other KIP-71 parameters (e.g. `Kip71UpperBoundBaseFee`) use `noopFormatChecker`, which accepts any `uint64` value including 0. The code itself acknowledges the zero-denominator risk for `BaseFeeDenominator` but omits the same protection for `GasTarget`, making this an inconsistency that a governance actor could trigger intentionally or by misconfiguration.

---

### Recommendation

Apply the same zero-guard pattern already used for `BaseFeeDenominator`:

```go
// params/kip71_config.go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // Avoid division-by-zero; treat as if gas usage equals target (no fee change)
    return makeEvenByFloor(parentBaseFee)
}
```

Alternatively, add a positive-value constraint to the `Kip71GasTarget` format checker in `kaiax/gov/param.go` so that a governance vote setting it to 0 is rejected at the governance layer before it can take effect.

---

### Proof of Concept

1. Governance (single-mode governing node) submits a vote: `kip71.gastarget = 0`.
2. The vote is accepted (no format checker rejects `uint64(0)`).
3. The next block N is produced with `parentGasUsed > 0` (any normal block).
4. Every node calls `VerifyMagmaHeader(header_N)` → `NextMagmaBlockBaseFee(parent_N)`.
5. Inside `NextMagmaBlockBaseFee`: `gasTarget = 0`, `parentGasUsed > 0`, so `parentGasUsed > gasTarget` is true.
6. Line 102: `x.Div(x, new(big.Int).SetUint64(0))` → Go runtime panic: `integer divide by zero`.
7. All nodes crash. Chain halts.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {

	}

	}
	return nil
}
