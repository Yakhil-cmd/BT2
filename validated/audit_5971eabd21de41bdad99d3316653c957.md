### Title
`SetPriceAggregator` resolves to a governance self-operation instead of the controller’s oracle setter - (File: contracts/governance/src/op.rs)

### Summary
`AdminOperation::SetPriceAggregator` is encoded with governance as the invocation target, while the actual oracle setter exists only on the controller. A ready operation therefore cannot update the controller’s price-aggregator pointer through the normal governance execution path. [1](#0-0) [2](#0-1) 

### Finding Description
`resolve_op` maps `AdminOperation::SetPriceAggregator` to `self_operation(env, "set_price_aggregator", args)`, so the resolved target is `env.current_contract_address()` rather than `storage::get_controller(env)`. [1](#0-0)  This differs from the neighboring controller configuration operations, which explicitly resolve through `controller_operation` or `sensitive_controller_operation`. [3](#0-2)  The production governance contract has no deployed `set_price_aggregator` export; the only governance function with that name is compiled under `#[cfg(any(test, feature = "testing"))]` and writes governance’s own stored aggregator address. [4](#0-3)  The controller’s owner-only `set_price_aggregator` is a separate external entrypoint that stores the address used for subsequent oracle lookups. [2](#0-1) 

### Impact Explanation
Governance cannot successfully repoint the lending controller to a replacement price aggregator using the advertised `SetPriceAggregator` operation. The generic `execute` path rejects the resolved operation before invocation because its target is the governance contract itself. [5](#0-4)  The self-operation path can only execute it as a governance-local operation rather than as the controller call implied by the operation name. [6](#0-5)  If the existing aggregator must be rotated or replaced, price-dependent controller operations can remain bound to the old aggregator, causing a protocol-wide operational freeze until another administrative mechanism is available.

### Likelihood Explanation
This is not an attacker-controlled profitability exploit; it is a deterministic implementation error reachable whenever governance schedules and executes `AdminOperation::SetPriceAggregator`. [7](#0-6)  Any caller able to drive a ready operation through `execute` encounters the self-target rejection, and no arguments can make that entrypoint invoke the controller setter. [5](#0-4)  The operational impact becomes security-relevant when oracle migration is required to keep markets functioning.

### Recommendation
Resolve `AdminOperation::SetPriceAggregator` with `sensitive_controller_operation` or `controller_operation`, targeting `storage::get_controller(env)` and the controller’s `set_price_aggregator` function. [3](#0-2)  Add a timelock test that schedules `SetPriceAggregator`, executes it after the delay, and asserts that the controller-side aggregator address changed rather than only governance’s stored deployment address. [8](#0-7) 

### Proof of Concept
1. Deploy governance and controller, then propose `AdminOperation::SetPriceAggregator(new_aggregator)`.
2. `resolve_op` stores an operation whose `target` is governance and whose `function` is `set_price_aggregator`. [1](#0-0) 
3. After the delay, call `execute(executor, governance, "set_price_aggregator", args, predecessor, salt)`.
4. The call reverts before execution because `target == env.current_contract_address()`. [9](#0-8) 
5. Consequently, the controller’s owner-only `set_price_aggregator` entrypoint is never invoked, leaving its oracle configuration unchanged. [2](#0-1)

/// Builds a `ResolvedOperation` targeting the controller contract with the

fn controller_operation(env: &Env, function: &str, args: Vec<Val>) -> ResolvedOperation {
    ResolvedOperation {
        target: storage::get_controller(env),
        function: Symbol::new(env, function),
        args,
        delay_tier: DelayTier::Standard,
    }
}

/// Builds a `ResolvedOperation` targeting the controller contract with the
/// `Sensitive` delay tier.
fn sensitive_controller_operation(env: &Env, function: &str, args: Vec<Val>) -> ResolvedOperation {
    ResolvedOperation {
        delay_tier: DelayTier::Sensitive,
        ..controller_operation(env, function, args)
    }
