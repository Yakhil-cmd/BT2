### Title
Baseline re-capture silently absorbs unreviewed dirty changes into the new git stash baseline, permanently hiding them from `Stop` review - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`capture_git_baseline` uses `git stash create` to snapshot "HEAD + uncommitted changes" as the new review baseline on every `UserPromptSubmit`. If a dangerous edit lands in the working tree via a path that does not populate `touched_paths` (e.g. a raw `Bash` write rather than `Edit`/`Write`) and the `Stop` hook has not yet consumed it, the next `UserPromptSubmit` unconditionally re-baselines, folding that unreviewed dirty state into the new baseline SHA. Because `compute_v2_review_set` derives both `dirty_now` and `changed_since` purely from git diffs against this baseline, the file's content now matches the baseline exactly and is never surfaced again.

### Finding Description
`capture_git_baseline(cwd)` [1](#0-0)  creates a `git stash create` object capturing HEAD plus all current uncommitted (tracked) changes and returns that SHA as the new baseline, falling back to `HEAD` when the tree is clean. This is invoked from `handle_user_prompt_submit` on every user turn [2](#0-1) .

The only guard against re-baselining past unreviewed work is the `touched_paths`-based preservation check: [3](#0-2) 
This preserves the old `baseline_sha` only when `state["touched_paths"]` is non-empty. `touched_paths` is populated via `record_touched_path` [4](#0-3) , which is called from specific PostToolUse code paths (Edit/Write-oriented instrumentation) rather than from generic `Bash` file writes.

`compute_v2_review_set` then computes the review set purely from git state relative to `baseline_sha`/`head_at_capture`, intersecting `dirty_now` (current git status) with `changed_since` (diff vs. `baseline_sha`) [5](#0-4) . The function's own docstring acknowledges the mechanism: "a Bash-only turn that's interrupted before Stop fires leaves touched_paths empty, so the next UPS re-baselines past those edits" [6](#0-5) .

Exploit flow: an attacker-influenced turn (e.g. via prompt injection from repo content directing Claude to use `Bash` heredocs/`sed`/`cat >>` instead of the `Edit`/`Write` tools) writes a dangerous change to a tracked file, the turn ends without `Stop` consuming `touched_paths` (interrupted, follow-up prompt sent quickly, tool-reject, crash), and the next `UserPromptSubmit` fires. Because `touched_paths` was never populated for the Bash-authored edit, the preservation guard does not trigger, `capture_git_baseline` runs `git stash create` again, and the new baseline stash object now contains the dangerous edit as part of its "clean" state. From that point on, `git diff <new_baseline_sha>` shows no difference for that file — `changed_since` excludes it forever, and it is never sent to the Stop-hook LLM review or flagged again, even though it was never actually reviewed once.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths" — a dangerous, never-reviewed change becomes indistinguishable from pre-existing, already-reviewed code. This lets a malicious edit (e.g. a backdoor, credential exfiltration, or path-traversal payload) permanently evade the security-guidance Stop-hook review, i.e., an unauthorized modification persists outside the user-approved review scope, matching "Unauthorized file read or write outside the user-approved workspace or target scope."

### Likelihood Explanation
Requires: (1) attacker-influenced content or an interrupted/aborted turn that causes the dangerous edit to be written via a code path that doesn't call `record_touched_path` (raw `Bash` file writes rather than `Edit`/`Write`), and (2) the turn ending (interrupt, timeout, quick follow-up prompt) before `Stop` runs. Both are realistic in normal agent operation — prompt injection from repository content commonly directs shell-based file edits, and turn interruption is common. This is a documented "known limitation" in the code itself, indicating it is a real, acknowledged gap rather than a purely theoretical one, though it depends on the specific timing/tool-choice precondition rather than being trivially triggerable on every turn.

### Recommendation
Do not gate baseline preservation solely on `touched_paths` (which only reflects Edit/Write instrumentation). Instead, before capturing a new baseline, compare `git status` dirty state against the *previous* `baseline_sha`; if any file differs from the previous baseline and hasn't been recorded as reviewed (e.g., via `sg-reviewed-shas` or a similar ledger), preserve the old baseline (or union the unreviewed diff forward) regardless of how the edit was made. Alternatively, populate `touched_paths` generically for any git-visible working-tree diff detected between the previous baseline and current state at UPS time, not only from Edit/Write PostToolUse hooks.

### Proof of Concept
Integration test outline (pytest style, using a temp git repo):
1. Init a repo, commit an initial file, start a session; call `handle_user_prompt_submit` (turn 1) to capture `baseline_sha1` (clean tree → `HEAD`).
2. Simulate a Bash-only dangerous edit: write attacker payload into a tracked file directly on disk (no `record_touched_path` call), leaving `state["touched_paths"]` empty.
3. Simulate the turn ending without `Stop` running (do not call `consume_stop_state`).
4. Call `handle_user_prompt_submit` again (turn 2, simulating the next prompt). Assert: `preserved["value"]` is `False` and `state["baseline_sha"]` changes to a new `git stash create` SHA that includes the dangerous edit.
5. Call `compute_v2_review_set(cwd, new_baseline_sha, head_at_capture, untracked_at_baseline)`.
6. Expected (failing) assertion demonstrating the bug: the dangerous file path is **absent** from the returned `review_paths`, even though it was never actually reviewed by `Stop` — violating the invariant that all Claude-turn-authored, unreviewed changes remain in the review set.

```python
def record_touched_path(session_id, file_path):
    """Append a file path to the touched_paths list (deduped, capped at 200).

    Stop is the consumer and clears under the same lock it reads with; UPS
    no longer wipes. The cap is a defensive bound for sessions where Stop
    never fires (disabled mid-session, abort) — git diff naturally filters
    stale paths so over-retention is harmless, just wasteful.
    """
    def _record(state):
        paths = state.setdefault("touched_paths", [])
        if file_path not in paths:
            paths.append(file_path)
            if len(paths) > 200:
                del paths[:len(paths) - 200]
    with_locked_state(session_id, _record)
```

```python
def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None
```

```python
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```
