Based on my research, I found a valid structural analog to the reported bug class in the `gh` CLI. The Solidity bug is a "confused deputy" pattern: a security check (`_blockLocked`) is scoped to the wrong actor (`msg.sender` instead of the actual token holder), so the desired protection can be bypassed by routing the sensitive action through an indirect path (`transferFrom`). I found the same structural flaw in the Copilot Agent Task CAPI transport: the check that should gate whether a credential is attached to a request is applied to the *wrong* thing (cosmetic headers) instead of the credential attachment itself.

### Title
Copilot CAPI bearer token is attached unconditionally to every request on a shared HTTP client, regardless of destination host - ([File: pkg/cmd/agent-task/capi/client.go])

### Summary
`capiTransport.RoundTrip` sets the `Authorization: Bearer <CAPI token>` header on **every** request that flows through the wrapped `http.Client`, before it ever checks which host the request is going to. The host check (`req.URL.Host == ct.capiHost`) exists in the code, but it only gates the *cosmetic* `Copilot-Integration-Id` / `X-GitHub-Api-Version` headers — not whether the bearer credential itself should be attached.

### Finding Description [1](#0-0) 

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
```

The `Authorization` header is set unconditionally, on the same line that comments explicitly acknowledge "this RoundTrip is reused for both Copilot API and GitHub API requests" — i.e., the author knew multiple destinations use this same transport, yet only scoped the *secondary* headers to the CAPI host, not the credential itself.

This transport is installed by mutating the **same** `*http.Client` that the rest of the command already uses for normal GitHub API calls: [2](#0-1) 


The constructor's own docstring is a tacit admission of the risk: [3](#0-2) 

```go
// NewCAPIClient creates a new CAPI client. Provide a token, the user's GitHub
// host, the resolved Copilot API URL, and an HTTP client which will be used as
// the base transport for CAPI requests.
//
// The provided HTTP client will be mutated for use with CAPI, so it should not
// be reused elsewhere.
func NewCAPIClient(httpClient *http.Client, token string, host string, capiBaseURL string) *CAPIClient {
	httpClient.Transport = newCAPITransport(token, capiBaseURL, httpClient.Transport)
	...
}
```

This is structurally identical to the `SettV3` bug: the protection (deciding when a sensitive credential should be exposed) is enforced on the wrong scope (an `if` that only toggles auxiliary headers) instead of on the actual sensitive action (attaching the Authorization header), just as `_blockLocked` checked `msg.sender` instead of the account whose funds/tokens were actually moved.

### Impact Explanation
Because the check is scoped to the wrong operation, the Copilot bearer token is sent to **any** host reachable through this mutated client — for example any subsequent GitHub REST/GraphQL call made with the same `*http.Client` (which also carries the normal GH OAuth `AddAuthTokenHeader` transport underneath, per [4](#0-3) ), or any other endpoint reached during that command invocation. Since `CapiClient.GetPullRequestDatabaseID` accepts a `hostname` argument and the surrounding agent-task commands resolve PR/issue references that can point at different hosts (see the cross-host guard tests in `pkg/cmd/issue/edit`), and since `GetSessionLogs`/session data returned by the server can contain URLs, an unconditional `Authorization: Bearer` on outgoing requests is a credential-exfiltration risk if any of those code paths route a request to a host other than `capiHost` using this same client instance.

### Likelihood Explanation
This is a preview feature (`agent-task`, explicitly marked "(Preview)" in command help text), so exposure is currently limited to users of that subcommand. However, the vulnerable pattern is exercised on every invocation of `gh agent-task create/list/view`, and the bug does not require any local-attacker, MITM, or leaked-token precondition — it fires as a normal consequence of the transport's own unconditional header-setting logic. I was unable to fully trace every downstream call site that reuses this exact client instance (e.g. whether `GetSessionLogs` or `GetPullRequestDatabaseID` definitely dispatch a request to a non-`capiHost` destination within the same process) due to tool-call budget exhaustion, so full end-to-end exploitability (which host, under what conditions) is not fully confirmed from the code I was able to read — this should be verified directly by inspecting `pkg/cmd/agent-task/capi/sessions.go` and `job.go` in full.

### Recommendation
Move the host check so it also gates the credential attachment, not just the auxiliary headers:
```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	if req.URL.Host == ct.capiHost {
		req.Header.Set("Authorization", "Bearer "+ct.token)
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
```
Additionally, avoid mutating and reusing a shared `*http.Client` across CAPI and general GitHub API call sites; construct a dedicated client/transport for CAPI calls instead of relying on callers to "remember" not to reuse it, as the current docstring warning does not prevent misuse enforced only by convention.

### Proof of Concept
Not independently executed (ask-only mode, no execution environment). Code-level trace supporting the claim:
1. [5](#0-4)  obtains the shared `f.HttpClient()` and passes it into `NewCAPIClient`.
2. [6](#0-5)  mutates that same client's `Transport` in place.
3. [7](#0-6)  unconditionally sets the `Authorization: Bearer <token>` header before the host check that follows only gates unrelated headers, so any request made with this client — to any host — carries the CAPI bearer credential.

```go
func CapiClientFunc(f *cmdutil.Factory) func() (capi.CapiClient, error) {
	return func() (capi.CapiClient, error) {
		cfg, err := f.Config()
		if err != nil {
			return nil, err
		}

		httpClient, err := f.HttpClient()
		if err != nil {
			return nil, err
		}

		authCfg := cfg.Authentication()
		host, _ := authCfg.DefaultHost()
		token, _ := authCfg.ActiveToken(host)

		cachedClient := api.NewCachedHTTPClient(httpClient, time.Minute*10)
		capiBaseURL, err := resolveCapiURL(cachedClient, host)
		if err != nil {
			return nil, fmt.Errorf("failed to resolve Copilot API URL: %w", err)
		}

		return capi.NewCAPIClient(httpClient, token, host, capiBaseURL), nil
	}
}
```

```go
// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```
