### Title
Signing-org / mutated-repo binding is never checked - cross-tenant `PullRequest` write via forged `assigned`/`unassigned` webhook - (File: `app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to verify against using `repository_owner`, which is read from `params.dig('repository','owner','login')` (or `organization.login`) — a field that is completely independent of `params.repository.full_name`, the field `AssignedHandler` uses to locate the `PullRequest` to mutate. An attacker who legitimately owns a GitHub org/app configured in Shipit can therefore sign a payload with their own org's secret while pointing `repository.full_name` and `number` at a victim repo/PR, causing `pull_request.update(github_pull_request: params.pull_request)` to overwrite the victim's row.

### Finding Description
Binding claimed/expected: `verifying_org (params.dig('repository','owner','login'))` == `owning_org_of_mutated_pull_request (Repository.from_github_repo_name(params.repository.full_name).owner)`.

Tracing the code:
- `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and calls `Shipit.github(organization: repository_owner)` to fetch that org's configured `GithubApp` and verify `X-Hub-Signature` against its `webhook_secret`. [1](#0-0) [2](#0-1) 
- After signature verification passes, `Shipit::Webhooks.for_event('pull_request')` dispatches to `AssignedHandler.call(params)` → `AssignedHandler#process`, which resolves the target `PullRequest` using a *different* field, `params.repository.full_name`, via `Shipit::Repository.from_github_repo_name`, joined through `stack: :repository`, and unconditionally calls `pull_request.update(github_pull_request: params.pull_request)`. [3](#0-2) 
- The `ExplicitParameters` schema for `AssignedHandler` only requires `repository.full_name`; it never declares or validates `repository.owner.login`, so nothing enforces that the two fields agree. [4](#0-3) 

Root cause: the org used to select the verifying secret (`repository.owner.login`/`organization.login`) and the org used to select the mutated repository/PR (`repository.full_name`) are two independently attacker-controlled fields in the same POST body, and no code anywhere cross-checks them. `drop_unhandled_event` only checks that a handler is registered for the event type, and does no authorization; `ExplicitParameters` only validates shapes/types, not cross-field consistency.

Attacker request: an attacker who legitimately controls a Shipit-registered org ("attacker-org", with its own known `webhook_secret`) sends `POST /webhooks` with header `X-Github-Event: pull_request`, a valid `X-Hub-Signature` computed with the attacker-org secret, and a JSON body:
```json
{
  "action": "assigned",
  "number": <victim_pr_number>,
  "pull_request": { "... arbitrary fields ..." },
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" },
  "sender": { "login": "attacker" }
}
```
`verify_signature` validates against `attacker-org`'s secret (which the attacker knows) and passes; `AssignedHandler` then resolves and mutates the victim PR keyed on `victim-org/victim-repo` and `<victim_pr_number>`.

### Impact Explanation
The attacker overwrites `github_pull_request` (title, body-derived attributes, additions/deletions, head sha/ref, assignees, labels, etc.) on a `PullRequest` belonging to a repository/org the attacker has no relationship with — a payload signed and originated by one tenant mutating another tenant's `PullRequest` row. This is repeatable against any victim repo/PR number as long as the attacker can guess or observe the PR number, requires only one HTTP request per mutation, and the same flaw exists identically in the sibling handlers (`EditedHandler`, `OpenedHandler`, `ClosedHandler`, etc.) since they share the identical `repository`/`pull_request` resolution pattern. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task or team."

### Likelihood Explanation
Requires a multi-tenant Shipit deployment where more than one GitHub org/app is configured (each with its own webhook secret) — a supported configuration evidenced by `test/dummy/config/secrets_double_github_app.yml`. The attacker only needs to be a legitimate owner/administrator of one such org (their own, unprivileged with respect to the victim) so they know its `webhook_secret`; no GitHub App private key, Shipit session, or victim-org secret is needed. Cost is a single crafted HTTP POST with a signature computed from a secret the attacker legitimately possesses. Fully repeatable.

### Recommendation
Cross-validate the signing org against the repository actually referenced by the payload before dispatching to handlers: derive the owner from `params.repository.full_name` (or an authoritative `Repository` lookup) and require it to equal `repository_owner`/`organization.login` used for `verify_signature`, rejecting (422) on mismatch. Apply this centrally in `WebhooksController` rather than per-handler to avoid missing it in any of the pull_request handlers.

### Proof of Concept
```ruby
# test/models/shipit/webhooks/handlers/pull_request/assigned_handler_cross_org_test.rb
test "does not mutate a victim PullRequest signed under a different org" do
  victim_pr = shipit_pull_requests(:review_stack_review) # belongs to victim repo/org
  original_title = victim_pr.github_pull_request["title"]

  payload = payload_parsed(:pull_request_assigned)
  payload["number"] = victim_pr.number
  payload["pull_request"]["number"] = victim_pr.number
  payload["pull_request"]["title"] = "PWNED BY ATTACKER"
  payload["repository"]["full_name"] = victim_pr.stack.repository.full_name # victim
  payload["repository"]["owner"] = { "login" => "attacker-org" } # attacker's own signing org

  # signature verification is done by the controller with attacker-org's secret;
  # simulate that AssignedHandler is invoked post-verification exactly as the
  # controller would dispatch it:
  AssignedHandler.new(payload).process

  victim_pr.reload
  assert_equal original_title, victim_pr.github_pull_request["title"],
    "victim PullRequest must not be mutated by a payload signed under a different org"
end
```
This demonstrates the binding `verifying_org == owning_org_of_mutated_pull_request` is false and unenforced: the handler mutates `victim_pr` regardless of `repository.owner.login`.

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

          def process
            return unless respond_to_assignee_change?

            pull_request.update(github_pull_request: params.pull_request) if pull_request.present?
          end

          private

          def respond_to_assignee_change?
            %w[assigned unassigned].include?(params.action)
          end

          def pull_request
            @pull_request ||= Shipit::PullRequest
                              .joins(:stack, stack: :repository)
                              .find_by(
                                number: params.number,
                                stacks: {
                                  repositories:
                                    {
                                      id: repository.id
                                    }
                                }
                              )
          end

          def repository
            Shipit::Repository.from_github_repo_name(params.repository.full_name) || Shipit::NullRepository.new
          end
