### Title
Webhook signature verification is scoped to `repository.owner.login`, not to the repository actually processed — a payload for an unrelated (secret-less) organization can name any victim repository's `full_name` and drive `Stack#sync_github` for it - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` picks the HMAC secret to validate against using `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')` of the *same untrusted payload* that also carries `repository.full_name`, the field later used by `Handler#stacks` to select which `Stack` records get processed. Nothing binds these two fields together, so if any organization known to this Shipit instance has no `webhook_secret` configured, `GitHubApp#verify_webhook_signature` returns `true` unconditionally, and an attacker can set `repository.full_name` in the same forged payload to an arbitrary victim repo, causing `PushHandler#process` to call `stack.sync_github(expected_head_sha: params.after)` for that victim's real, non-archived stack.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`org_used_for_signature_check (params.dig('repository','owner','login'))` MUST equal `org_that_owns_the_stacks_being_mutated (Repository.from_github_repo_name(payload.dig('repository','full_name')).stacks.first.repository.owner)` — but no code enforces this.

Code path:
1. `WebhooksController#verify_signature` computes `repository_owner` purely from the payload body and looks up `github_app = Shipit.github(organization: repository_owner)`. [1](#0-0) [2](#0-1) 
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` when the resolved org has no configured `webhook_secret`: `return true unless webhook_secret`. [3](#0-2)  The secret itself is set from that org's config entry at construction time. [4](#0-3) 
3. Once verification "passes," `WebhooksController#create` dispatches the raw, attacker-controlled JSON to the handlers unchanged. [5](#0-4) 
4. `Handler#stacks` resolves the target using `payload.dig('repository', 'full_name')` — a completely separate field from the one used in step 1 — with no cross-check against `repository_owner`. [6](#0-5) 
5. `PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack, where `params.after` is the attacker's own unsigned claim of a commit SHA. [7](#0-6) 

Attacker request: a POST to `/webhooks` with header `X-Github-Event: push`, a body whose `repository.owner.login` is set to an org that this Shipit deployment has configured **without** a `webhook_secret` (satisfying step 2's bypass), but whose `repository.full_name` is set to `victim-org/victim-repo`, `ref` set to `refs/heads/main`, and `after` set to an arbitrary attacker-chosen SHA never pushed to the real repo.

Existing guards do not stop this: `drop_unhandled_event` only checks the event type is handled, not the payload's internal consistency; `verify_signature`'s only failure mode relevant here is `Shipit::GithubOrganizationUnknown` (422) for orgs not present in configuration at all — it does not fail for orgs that are configured but simply lack a secret, and it never inspects `full_name` for consistency with `owner.login`.

### Impact Explanation
A successful forged payload causes `Stack#sync_github` to run for the victim's stack using Shipit's own GitHub App/installation credentials scoped to the victim org, based purely on an unauthenticated, attacker-supplied `after` SHA and `ref`. This is a genuine cross-tenant authentication-bypass primitive: a payload that was only validated (trivially) against an unrelated no-secret organization is used to trigger GitHub-authenticated behavior against a repository/stack the attacker does not control. This matches the "forged webhook accepted" Critical category, and its blast radius extends to any non-archived stack whose branch matches the forged `ref`, repeatable per request with no rate limiting bypass required.

### Likelihood Explanation
Exploitability strictly depends on the precondition that at least one organization configured in this Shipit instance's `github_apps` settings has no `webhook_secret` set (the "no-secret-org" premise the question stipulates). Given that precondition, the attack costs the attacker nothing beyond crafting one raw HTTP POST — no session, API token, or GitHub secret is needed, and it is trivially repeatable against any repository/stack known to the instance by supplying different `full_name` values. If no such org exists, the attack is not exploitable, since every other org path enforces a real HMAC check.

### Recommendation
Do not let `repository.owner.login` and `repository.full_name` be independently attacker-controlled fields used for two different trust decisions. At minimum: (1) after selecting the GitHub App/secret via `repository_owner`, verify that `payload.dig('repository','full_name')`'s owner segment matches `repository_owner` before allowing any handler to run; (2) treat "no configured `webhook_secret`" as a fatal misconfiguration (refuse to serve, or restrict such orgs' payload processing to their own literal `full_name` only) rather than a silent bypass; (3) consider requiring `webhook_secret` for every configured organization.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "push webhook signed against a no-secret org cannot drive sync for a different repo" do
  victim_stack = shipit_stacks(:shipit) # non-archived stack for e.g. "victim-org/victim-repo"
  no_secret_org_login = "no-secret-org" # configured in test secrets.yml with no webhook_secret

  payload = {
    ref: "refs/heads/#{victim_stack.branch}",
    after: "deadbeef" * 5, # attacker-chosen SHA, never pushed by anyone
    repository: {
      owner: { login: no_secret_org_login }, # used only for signature org lookup
      full_name: victim_stack.repository.full_name # actual mutation target
    }
  }.to_json

  Shipit::Stack.any_instance.expects(:sync_github).never

  post :create, body: payload, params: {}, headers: {
    'X-Github-Event' => 'push',
    'X-Hub-Signature' => 'sha1=irrelevant-because-no-secret-org'
  }

  assert_response :ok
  # Assertion: sync_github must NOT be invoked for victim_stack solely because
  # signature check passed against an unrelated no-secret org.
end
```
Expected current (vulnerable) behavior: the `never` expectation fails because `sync_github` is invoked with `expected_head_sha: "deadbeefdeadbeefdeadbeefdeadbeefdeadbeef"` for `victim_stack`, proving the org used for signature verification (`no-secret-org`) is not bound to the org whose stack is mutated (`victim-org`).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
