### Title
No Minimum Transfer Amount in Service Chain Bridge Allows Off-Chain Operator Gas Drain — (`contracts/service_chain/bridge/BridgeFee.sol`, `contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

The Kaia Service Chain bridge contracts deploy with `feeOfKLAY = 0` and `feeReceiver = address(0)` as explicit defaults. The fee-collection guard requires **both** conditions to be true (`feeReceiver != address(0) && fee > 0`) before any fee is charged. When either is false — which is always the case at deployment and whenever the operator deliberately sets zero fees — no minimum transfer amount is enforced. Any unprivileged user can spam the bridge fallback with 1-wei KLAY requests, emitting a `RequestValueTransfer` event per call. The off-chain bridge operator (`BridgeInfo.handleRequestValueTransferEvent`) processes every event by submitting a signed `HandleKLAYTransfer` transaction on the counterpart chain, spending gas from the operator's system-managed wallet for each spam request.

---

### Finding Description

`BridgeFee.sol` declares its state variables with zero/null defaults:

```solidity
address payable public feeReceiver = address(0);
uint256 public feeOfKLAY = 0;
```

`BridgeTransfer.sol` passes `address(0)` explicitly to the `BridgeFee` constructor:

```solidity
constructor(bool _modeMintBurn) BridgeFee(address(0)) internal {
    modeMintBurn = _modeMintBurn;
}
```

The fee-collection function in `BridgeFee.sol` only collects a fee when **both** `feeReceiver != address(0)` and `fee > 0`:

```solidity
function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
    uint256 fee = feeOfKLAY;
    if (feeReceiver != address(0) && fee > 0) { ... return fee; }
    // falls through: no fee collected, no minimum enforced
    return 0;
}
```

The KLAY fallback function passes `feeOfKLAY` (which is `0` by default) as `_feeLimit`:

```solidity
function () external payable {
    _requestKLAYTransfer(msg.sender, feeOfKLAY, new bytes(0));
}
```

Inside `_requestKLAYTransfer`, the only guard is:

```solidity
require(msg.value > _feeLimit, "insufficient amount");
```

When `feeOfKLAY == 0`, this reduces to `require(msg.value > 0)`. A single wei satisfies it. The function then emits `RequestValueTransfer` and increments `requestNonce`.

The off-chain Go component (`handleRequestValueTransferEvent` in `node/sc/bridge_manager.go`) processes every emitted event unconditionally, calling `HandleKLAYTransfer` on the counterpart bridge and incrementing the operator account nonce:

```go
handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
...
bridgeAcc.IncNonce()
```

---

### Impact Explanation

- **Operator gas wallet drained**: Each spam 1-wei request forces the off-chain operator to submit a `HandleKLAYTransfer` transaction on the counterpart chain, consuming gas from the operator's system-managed account. With no minimum amount and no fee, the cost to the attacker per spam request is only the Kaia transaction gas fee, while the operator pays counterpart-chain gas for every event.
- **Bridge nonce consumed**: `requestNonce` is incremented for every spam request. The off-chain recovery system (`retrievePendingEventsFrom`) must scan and process all pending nonces in order, amplifying the processing burden.
- **Pending event queue saturation**: `AddRequestValueTransferEvents` has a cap of `maxPendingNonceDiff = 1000` events. Flooding this queue with dust requests can delay or displace legitimate high-value transfers.

---

### Likelihood Explanation

- The bridge deploys with `isRunning = true` and `isLockedKLAY = false` by default, making it immediately accessible to any user.
- The zero-fee default state is the initial state of every bridge deployment, before the operator has configured fees.
- Even after deployment, operators may intentionally set `feeOfKLAY = 0` (a tested and supported configuration), which re-enables the same attack surface.
- No access control restricts who can call the fallback or `requestKLAYTransfer`.

---

### Recommendation

1. Enforce a minimum transfer amount in `_requestKLAYTransfer` independent of the fee configuration, e.g.:
   ```solidity
   uint256 constant MIN_KLAY_TRANSFER = 1e9; // 1 Gkei
   require(msg.value.sub(_feeLimit) >= MIN_KLAY_TRANSFER, "amount below minimum");
   ```
2. Similarly enforce a minimum in `_requestERC20Transfer` beyond the existing `_value > 0` check.
3. Consider requiring `feeReceiver` to be set before the bridge is opened (`isRunning = true`), or gate `isRunning` on a non-zero fee configuration.

---

### Proof of Concept

```solidity
// Attacker script (pseudocode)
for (uint i = 0; i < 10_000; i++) {
    // Send 1 wei to the bridge fallback
    // feeOfKLAY == 0 → _feeLimit == 0 → require(1 > 0) passes
    // feeReceiver == address(0) → no fee collected
    // RequestValueTransfer emitted with valueOrTokenId = 1
    bridge.call{value: 1}("");
}
// Off-chain operator submits 10,000 HandleKLAYTransfer txs on counterpart chain
// Operator gas wallet drained; legitimate transfers delayed
```

**Exact corrupted value**: The operator's counterpart-chain account balance is decremented by `N × gas_cost(HandleKLAYTransfer)` for `N` spam requests, with no corresponding revenue (fee = 0). The bridge `requestNonce` advances by `N`, forcing the off-chain system to process all `N` nonces before legitimate transfers can be settled.     function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
