### Title
Webhook signature verification keyed to attacker-controlled `repository.owner.login` allows cross-tenant stack sync bypass - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to verify against using `repository_owner`, a value taken directly from the attacker-supplied JSON body (`repository.owner.login`, falling back to `organization.login`), rather than from any value tied to the repository that actually gets mutated. `PushHandler#process` then resolves and syncs the target `Stack` using other attacker-supplied fields (`repository.full_name`/`ref`), so the org whose secret validated the request is not bound to the org that owns the mutated stack.

### Finding Description
The broken binding: `organization_that_verified_secret` (derived from `params.dig('repository','owner','login') || params.dig('organization','login')`) must equal `organization_that_owns_the_mutated_stack` (derived from `repository.full_name` used to look up the `Stack`/`Repository` and drive `stack.sync_github`). Nothing in the code enforces this equality.

Trace:
- `verify_signature` computes `repository_owner` purely from the request body: [1](#0-0) .
- It fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature`: [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the resolved app has no configured `webhook_secret`: [3](#0-2) .
- `PushHandler#process` then locates stacks and calls `stack.sync_github`, using `branch` (derived from `params.ref`) against the scoped `stacks` (repository resolution independent of the `repository_owner` field checked earlier): [4](#0-3) .

Because the attacker fully controls the raw JSON body, they can submit a `repository` object where `owner.login` is `"attacker-org"` (an org they legitimately configured in this Shipit instance with no `webhook_secret`) while `full_name` (and any fields the stack-lookup path uses to resolve the actual `Repository`/`Stack`) names a victim's real repository, e.g. `"shopify/shipit-engine"`. The signature check is satisfied trivially (no secret configured for `attacker-org`, so `return true unless webhook_secret`), while the mutation proceeds against the real `shopify/...` stack. Existing guards do not prevent this: `check_if_ping` and `drop_unhandled_event` only gate on the event type, not the org/repo consistency; `ExplicitParameters` on `PushHandler` only validates presence of `ref`/`after`, not repository identity; there is no validator anywhere in this path cross-checking `repository.owner.login` against `repository.full_name`.

### Impact Explanation
An attacker who controls a "attacker-org" GitHub App/organization entry in this Shipit instance (with no webhook secret configured for it) can forge push events that trigger `sync_github` on any other tenant's stack in the same Shipit deployment, without possessing that tenant's webhook secret. This is a cross-tenant/cross-repository authentication bypass: a payload "authenticated" (trivially, due to absent secret) for one org causes mutation (`stack.sync_github`, which enqueues `GithubSyncJob`) on another org's stack. This matches the Critical category: "a payload for one repository mutating another's stack." The blast radius covers any Shipit installation configured to host multiple GitHub orgs/apps where at least one has no `webhook_secret` set.

### Likelihood Explanation
Preconditions: this Shipit installation must be configured for multiple GitHub organizations via `Shipit.github(organization:)`, and at least one org entry (which the attacker can register/control, e.g. their own org's app config) must have no `webhook_secret` set. If the deployment only wires a single global GitHub App/config regardless of the `organization:` argument, the organization string is effectively ignored and this specific confusion does not apply. Given the multi-org precondition holds, attacker cost is minimal — an unauthenticated `POST /webhooks` request with a hand-crafted JSON body and no `X-Hub-Signature` header, fully repeatable against any repository/stack known to the attacker.

### Recommendation
Bind webhook signature verification to the same repository identity used for the mutation: derive the GitHub App/secret lookup from `repository.full_name`'s owner (or from an authoritative `Stack`/`Repository` lookup) rather than trusting `repository.owner.login`/`organization.login` independently, and reject payloads where `repository.owner.login` is inconsistent with `repository.full_name`. Additionally, do not allow `verify_webhook_signature` to return `true` for an org with no secret when that org is not the one owning the target repository; consider requiring all configured orgs to have a non-blank `webhook_secret` in production configurations, or explicitly reject events where the verifying org does not match the mutated resource's org.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb`):
1. Configure `Shipit.github_apps` (or stub `Shipit.github`) so that `Shipit.github(organization: 'attacker-org')` returns a `GitHubApp` with `webhook_secret` blank/nil, and `Shipit.github(organization: 'shopify')` has a real secret configured.
2. Create a real `Stack` for `shopify/shipit-engine` with branch `master`.
3. POST to `/webhooks` with header `X-Github-Event: push`, no `X-Hub-Signature` header, and body:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "full_name": "shopify/shipit-engine",
    "owner": { "login": "attacker-org" }
  }
}
```
4. Assert response is `200 OK` (not `422`), and assert `GithubSyncJob` is enqueued for the victim `shopify/shipit-engine` stack — proving the binding `organization_verifying_signature ('attacker-org', no secret)` != `organization_owning_mutated_stack ('shopify')` was violated and the mutation still occurred.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
