### Title
Fork PR `machine.environment` entry in `shipit.yml` injects arbitrary `ENV` into the `dependencies.override` step, enabling RCE via env-var/PTY.spawn injection - (File: `app/models/shipit/deploy_spec.rb`)

### Summary
`DeploySpec#machine_env` reads `config('machine', 'environment')` verbatim from the checked-out `shipit.yml` and is merged, unfiltered, into the environment hash used by `Command`/`PTY.spawn` when running dependency-install steps. For review stacks, the `shipit.yml` is read from the fork branch's working directory, so a fork PR author fully controls this hash, including setting an `ENV` (or `BASH_ENV`) key that a subsequently-spawned shell will source on startup.

### Finding Description
The broken invariant is: `TaskCommands#env` for the `dependencies.override` step should equal a fixed, engine-controlled set of variables, **not** `TaskCommands#env == fixed_vars.merge(deploy_spec.machine_env)` where `deploy_spec.machine_env` is attacker-controlled.

Trace:
- `DeploySpec::FileSystem#load_config` reads the `shipit.yml`/`.shipit/shipit.yml` file from the task's checked-out working directory via `config_file_path`/`read_config` [1](#0-0) . For a `ReviewStack`, that working directory is a checkout of the fork PR's branch (the branch/commit the unprivileged PR author controls), so the whole config, including `machine.environment`, comes from the fork.
- `DeploySpec#machine_env` returns `config('machine', 'environment') || {}` with no validation, filtering, or allow-list, unlike `deploy_variables`/`filter_deploy_envs`, which run through `EnvironmentVariables#permit` [2](#0-1) [3](#0-2) .
- `TaskCommands#env` merges `deploy_spec.machine_env` directly into the environment hash used for both `install_dependencies` (`dependencies.override`) and `perform` steps, after the fixed engine-defined keys (`SHIPIT_USER`, `EMAIL`, `BUNDLE_PATH`, etc.) [4](#0-3) . Because `.merge(deploy_spec.machine_env)` runs after the fixed keys, an attacker-supplied key of the same name (or a brand-new key such as `ENV`/`BASH_ENV`) overrides or adds to the final hash.
- `Command.new(command_line, env:, chdir: steps_directory)` stores this hash as `@env` [5](#0-4) , and `Command#start` calls `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)`, where `unbundled_env` merges `BASE_ENV`, `PATH`, and `@env.stringify_keys` [6](#0-5) . The attacker-controlled `ENV`/`BASH_ENV` value is therefore present in the environment of every subsequently spawned process, including the dependency-install shell command.
- If any dependency-install step is (or invokes) a POSIX/bash shell, setting `ENV`/`BASH_ENV` to a path the attacker also controls in the checkout (e.g. a file inside the fork's own repo checkout) causes that shell to source and execute attacker code at shell startup — full command execution on the Shipit deploy host with the deploy host's privileges (access to `GITHUB_TOKEN`, deploy secrets, other stacks, etc.).

No existing guard filters this: `EnvironmentVariables#permit` is applied to `deploy_variables`/`rollback_variables` only, not to `machine_env`; provisioning gating (`provisioning_behavior`) only decides whether the review stack is provisioned automatically, it does not sanitize the checked-out `shipit.yml` content; and `Command#start`/`unbundled_env` performs no key-name filtering before handing the merged hash to `PTY.spawn`.

### Impact Explanation
An unprivileged fork PR author who can get a `ReviewStack` provisioned (repository configured with `provisioning_behavior=allow_all`, which auto-provisions review stacks for any incoming PR without maintainer approval) can execute arbitrary commands on the Shipit deploy host during the `dependencies.override` phase of that review stack's task. This is Critical: RCE on the deploy host via `Command`/`PTY.spawn`, with access to whatever secrets/credentials/network access the deploy host has (potentially `GITHUB_TOKEN`, other repositories' deploy state, etc.), i.e. blast radius extends beyond the attacker's own stack.

### Likelihood Explanation
Preconditions: the target repository must have `provisioning_behavior` set to auto-provision fork PR review stacks (`allow_all`), and dependency-install steps must invoke a shell that honors `ENV`/`BASH_ENV` (default for most shell-based dependency-install commands, e.g. `sh`/`bash` invoked non-interactively, or Ruby/bundler steps that shell out). Attacker cost is low: open a PR from a fork with a crafted `shipit.yml` containing a `machine: {environment: {ENV: "/path/to/malicious/file"}}` entry and a payload file in the same checkout; no Shipit credentials, session, or API token needed. This is fully repeatable against any repository configured this way.

### Recommendation
Sanitize/allow-list `machine.environment` the same way `deploy_variables`/`rollback_variables` are filtered via `EnvironmentVariables#permit`, and explicitly reject or strip dangerous keys (`ENV`, `BASH_ENV`, `PATH`, `LD_PRELOAD`, `IFS`, etc.) before merging into `TaskCommands#env`/`Command#env`. For review stacks specifically, consider not trusting the fork branch's `machine.environment` block at all (only the base/target branch's config), or require the block to go through the same variable-definition/permit mechanism as `deploy.variables`.

### Proof of Concept
minitest plan (models: `Shipit::DeploySpec`, `Shipit::TaskCommands`):
1. Build a `DeploySpec::FileSystem`-backed (or plain `DeploySpec.new(config)`) spec for a `ReviewStack`/`Task` where the underlying `shipit.yml` content includes:
   ```yaml
   dependencies:
     override:
       - "env"
   machine:
     environment:
       ENV: "/tmp/pwned.sh"
   ```
2. Assert the broken binding as an equality before tracing: expected invariant `task_commands.env.key?('ENV') == false`; actual: `deploy_spec.machine_env == { 'ENV' => '/tmp/pwned.sh' }` and `task_commands.env['ENV'] == '/tmp/pwned.sh'`.
3. Build the `install_dependencies` commands (`deploy_spec.dependencies_steps!.map { |c| Shipit::Command.new(c, env: task_commands.env, chdir: dir) }`) and assert `command.env['ENV'] == '/tmp/pwned.sh'`.
4. Assert that `command.unbundled_env['ENV'] == '/tmp/pwned.sh'` (the exact hash passed to `PTY.spawn`), proving the fork-controlled key reaches process spawn with no filtering.

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end
