### Title
`isRunning` Guard Missing from `handleERC20Transfer`, `handleERC721Transfer`, and `handleKLAYTransfer` — Operators Can Mint/Transfer Bridged Assets After Bridge Is Stopped - (File: `contracts/service_chain/bridge/BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`, `BridgeTransferKLAY.sol`)

---

### Summary

The bridge's emergency-stop flag `isRunning` is enforced on every outbound request path but is entirely absent from the three inbound handle functions. When the owner calls `setRunningStatus(false)` to halt the bridge, registered operators can still call `handleERC20Transfer`, `handleERC721Transfer`, and `handleKLAYTransfer` to mint bridged ERC-20/ERC-721 tokens or drain KLAY from the bridge contract.

---

### Finding Description

`BridgeTransfer.isRunning` is the sole emergency-stop control for the bridge. [1](#0-0) 

`setRunningStatus(false)` sets it to `false`. [2](#0-1) 

Every outbound request path correctly enforces this flag:

- `_requestERC20Transfer`: `require(isRunning, "stopped bridge")` [3](#0-2) 

- `_requestERC721Transfer`: `require(isRunning, "stopped bridge")` [4](#0-3) 

- `_requestKLAYTransfer`: `require(isRunning, "stopped bridge")` [5](#0-4) 

However, the three inbound handle functions carry **no** `isRunning` check:

`handleERC20Transfer` — only `onlyOperators`: [6](#0-5) 

When `modeMintBurn == true` it calls `ERC20Mintable.mint(_to, _value)`: [7](#0-6) 

`handleERC721Transfer` — only `onlyOperators`: [8](#0-7) 

When `modeMintBurn == true` it calls `ERC721MetadataMintable.mintWithTokenURI`: [9](#0-8) 

`handleKLAYTransfer` — only `onlyOperators` + `nonReentrant`: [10](#0-9) 

It unconditionally pushes KLAY to `_to`: [11](#0-10) 

---

### Impact Explanation

When the owner stops the bridge to respond to an incident (e.g., a compromised counterpart chain, an exploit in progress, or a governance emergency), operators can still:

1. **Mint unbacked ERC-20 bridged tokens** via `handleERC20Transfer` (mint-burn mode) — inflating supply of the bridged asset with no corresponding lock on the counterpart chain.
2. **Mint unbacked ERC-721 bridged NFTs** via `handleERC721Transfer` (mint-burn mode).
3. **Drain KLAY reserves** from the bridge contract via `handleKLAYTransfer` — transferring native KLAY to arbitrary addresses.

All three outcomes directly affect KAIA/bridged-asset balances and constitute unauthorized minting or transfer of system-managed funds, matching the allowed impact gate.

---

### Likelihood Explanation

Operators are registered by the owner (`onlyOwner` on `registerOperator`) and are semi-trusted. The scenario where this matters is precisely the emergency: the owner stops the bridge because something is wrong (e.g., a compromised operator key, a bug on the counterpart chain, or an ongoing exploit). The owner cannot atomically deregister all operators and stop the bridge in a single transaction. In the window between `setRunningStatus(false)` and individual `deregisterOperator` calls, any remaining operator can still execute handle transfers. The owner's reasonable expectation — that `isRunning = false` halts all asset movement — is violated.

---

### Recommendation

Add `require(isRunning, "stopped bridge")` at the top of each handle function, mirroring the pattern already used on the request side:

```solidity
// BridgeTransferERC20.sol
function handleERC20Transfer(...) public onlyOperators {
    require(isRunning, "stopped bridge");   // ADD THIS
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferERC721.sol
function handleERC721Transfer(...) public onlyOperators {
    require(isRunning, "stopped bridge");   // ADD THIS
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferKLAY.sol
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
    require(isRunning, "stopped bridge");   // ADD THIS
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}
```

### Proof of Concept

```
1. Owner deploys bridge with modeMintBurn = true.
2. Owner registers operator A and token T (with bridge as minter).
3. Owner calls setRunningStatus(false) — bridge is stopped.
   → isRunning == false
4. Operator A calls handleERC20Transfer(
       txHash, attacker, victim, T, 1_000_000e18,
       nonce=1, blockNum=1, ""
   )
   → No isRunning check fires.
   → ERC20Mintable(T).mint(victim, 1_000_000e18) executes.
   → 1,000,000 bridged tokens are minted with no corresponding lock
     on the counterpart chain.
5. Repeat for handleERC721Transfer (NFT minted) or handleKLAYTransfer
   (KLAY drained from bridge reserves) with the same stopped bridge.
```

The `_lowerHandleNonceCheck` only prevents replaying already-handled nonces; it does not enforce `isRunning`. Any fresh nonce passes through. [12](#0-11)
