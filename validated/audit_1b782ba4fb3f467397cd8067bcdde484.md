### Title

Interest accrual overflows the scaled-debt product before the borrow-index cap, freezing all market operations - (File: common/src/rates/simulate.rs)

### Summary

A market with sufficiently large scaled debt can reach an `i128` overflow while computing `borrowed * borrow_index` before `borrow_index` reaches `MAX_BORROW_INDEX_RAY`. [1](#0-0)  Once this occurs, every pool operation that performs interest synchronization fails, preventing withdrawals, repayments, liquidations, and other market operations. [2](#0-1)  The repository contains a regression test demonstrating that both `withdraw` and `repay` subsequently revert with `MATH_OVERFLOW`. [3](#0-2) 

### Finding Description

Each accrual step computes `borrowed_original` by passing the scaled debt and current borrow index to `scaled_to_original`, which directly multiplies the two `Ray` values. [4](#0-3)  `scaled_to_original` performs `scaled.mul(env, index)` without first checking whether `scaled` is already too large for the current index. [5](#0-4) 

The borrow-index ceiling is applied only after the product is produced: `update_borrow_index` multiplies `old_index` by `interest_factor` and then compares the result with `MAX_BORROW_INDEX_RAY`. [6](#0-5)  However, accrual computes the full scaled-debt value before reaching that index-cap comparison. [1](#0-0)  Consequently, a scaled balance above approximately `i128::MAX / borrow_index` causes the multiplication to trap even though the borrow index remains below its intended cap. [7](#0-6) 

`global_sync` executes this vulnerable step on every market synchronization and chunks long elapsed intervals before marking the market accrued. [2](#0-1)  Because pool operations perform synchronization before their state mutations, the trap becomes persistent rather than merely rejecting one malformed request. [8](#0-7) 

An unprivileged path is to create or use a very large market position, maintain high utilization, wait for the index to grow, and submit `update_indexes` with that market’s `HubAssetKey`. [9](#0-8)  The same condition then causes subsequent calls such as `withdraw` and `repay` to fail during their mandatory synchronization phase. [10](#0-9) 

### Impact Explanation

This permanently freezes funds in the affected market rather than merely denying an invalid transaction. [7](#0-6)  Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot perform the synchronization needed to resolve positions because each operation executes the same overflowing accrual path. [11](#0-10)  The test confirms that the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, so the intended cap cannot rescue the market. [12](#0-11) 

### Likelihood Explanation

The precondition is economically demanding: the market needs a very large scaled balance, sustained high utilization, and enough elapsed accrual for the index-product to approach `i128::MAX`. [13](#0-12)  The proof scenario uses one billion 18-decimal tokens at 98% utilization and advances time until synchronization fails. [14](#0-13)  No privileged action is needed for the triggering call or the resulting freeze, but actual feasibility depends on the deployed market’s cap, available token supply, and collateral needed to establish the debt. [15](#0-14) 

### Recommendation

Do not form `borrowed * borrow_index` or `supplied * supply_index` as an unchecked intermediate value during accrual. [16](#0-15)  Use wider intermediate arithmetic for utilization and index updates, or check `scaled <= i128::MAX / index` before multiplying and clamp the index/market in a controlled way. [5](#0-4)  Apply the borrow-index ceiling before it can make the scaled-value calculation overflow, and add regression coverage proving that `update_indexes`, `withdraw`, `repay`, and liquidation remain executable at the configured cap boundary. [6](#0-5) 

### Proof of Concept

1. Create a market for an 18-decimal asset with a steep high-utilization rate curve and sufficient caps for one billion whole tokens. [17](#0-16) 
2. Supply `1_000_000_000 * 10^18` units of that asset. [18](#0-17) 
3. Supply enough collateral in another market to borrow 98% of the target-asset supply. [19](#0-18) 
4. Advance time and call the controller’s `update_indexes` for the target `HubAssetKey` until `scaled_to_original` traps with `MATH_OVERFLOW`. [20](#0-19) 
5. Observe that `borrow_index` is still below `MAX_BORROW_INDEX_RAY`, while subsequent `withdraw` and `repay` calls also fail with `MATH_OVERFLOW`. [12](#0-11)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
