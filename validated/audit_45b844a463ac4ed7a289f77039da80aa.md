I found a solid analog: a token/stack authorization binding break in the CCMenu API endpoint.## Finding

### Title
CCMenu API token authorized for one stack can read build/deploy status of every stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
The CCMenu status endpoint bypasses the `ApiClient` stack-scoping mechanism entirely, so a token meant to expose one stack's CI/deploy status via a public monitoring URL can be replayed to read the deploy/status information of any stack in the Shipit installation.

### Finding Description
`Api::BaseController` implements stack scoping generically: `stacks` is filtered down to the token's own `stack_id` when one is set, and `stack` looks the requested resource up through that scoped relation: [1](#0-0) 

`Api::CCMenuController` overrides `stack` to bypass this scoping and instead resolves the requested stack directly against the global `Stack` relation using only the `params[:stack_id]` supplied by the caller: [2](#0-1) 

The controller's only gate is `require_permission :read, :stack`, which merely checks that the string `"read:stack"` is present in the authenticated `ApiClient`'s `permissions` array — it never checks which stack that permission is supposed to be bound to: [3](#0-2) 

The token that reaches this endpoint in practice is minted by `CCMenuUrlController#fetch`, which builds a public/unauthenticated monitoring URL (`ccmenu_url`) for one specific stack, but creates (or reuses) an `ApiClient` with `read:stack` permission and **no `stack:` association at all** (`stack_id` is left `nil`): [4](#0-3) 

So the equality that should hold — "the stack this token authorizes" == "the stack this token can touch" — is broken on both sides: the token itself carries no `stack_id` binding, and even if it did, `CCMenuController#stack` would ignore it. Any holder of one stack's `ccmenu_url` token can substitute a different `stack_id` in the request path and receive that other stack's `deploys_and_rollbacks.last` (build status, label, running state) rendered as CCTray XML.

### Impact Explanation
This is an unauthenticated read of stack state/deploy output: the CCMenu URL is designed to be embedded in third-party CI dashboards/CCTray clients without any Shipit session, using only the bearer `token` query parameter. A token generated to expose the CI status of a single, possibly low-sensitivity stack instead grants a caller who is not a Shipit user (and never went through the GitHub-team authorization gate `current_user must be a member of at least a Shipit.github_teams`) the ability to enumerate the deploy status of every stack in the installation, including ones the requester was never meant to see status for.

### Likelihood Explanation
Any user who can view a stack in the web UI can request its `ccmenu_url` (no elevated privilege required), obtain a `token`, and immediately reuse it against `/api/stacks/<other_stack_id>/cc.xml`. `stack_id` values are small sequential/slug identifiers, trivially guessable or enumerable, making exploitation straightforward once a single token is obtained.

### Recommendation
Have `Api::CCMenuController#stack` (and the token minted in `CCMenuUrlController#client`) go through the same scoped `stacks`/`stack_id` mechanism used by `Api::BaseController`: create the `ApiClient` with `stack:` set to the specific stack the URL is for, and have `CCMenuController#stack` resolve via `stacks.from_param!(params[:stack_id])` instead of the unscoped `Stack.from_param!`.

### Proof of Concept
1. As any authenticated Shipit user, visit `stack_ccmenu_url_path` (or trigger `CCMenuUrlController#fetch`) for `stack_a`, obtaining `ccmenu_url` containing `token=<T>`.
2. Note that `ApiClient` record `T` has `stack_id: nil` and `permissions: ["read:stack"]`.
3. Send `GET /api/stacks/<stack_b_id>/cc.xml?token=<T>` for an unrelated `stack_b` the requester should not have visibility into.
4. Observe a `200 OK` XML response containing `stack_b`'s `lastBuildStatus`/`lastBuildLabel`/`lastBuildTime`, proving the token authorized for `stack_a` reads `stack_b`'s state.
