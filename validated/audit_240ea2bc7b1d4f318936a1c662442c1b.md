### Title
KAIA Permanently Stuck in `Bridge` When `requestKLAYTransfer` / Fallback Is Called Before Counterpart Bridge Is Configured — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

`Bridge` starts with `isRunning = true` and `counterpartBridge = address(0)`. Neither `_requestKLAYTransfer` nor the payable fallback checks that a counterpart bridge has been configured before accepting KAIA. Any KAIA sent during this window is locked in the source bridge forever: the `RequestValueTransfer` event is emitted and `requestNonce` is incremented, but no operator on the counterpart chain can ever call `handleKLAYTransfer` to release the funds, and the contract exposes no owner-rescue or emergency-withdrawal path.

---

### Finding Description

`BridgeTransfer.sol` initialises `isRunning = true` at declaration: [1](#0-0) 

`BridgeFee.sol` initialises `feeReceiver = address(0)` and `feeOfKLAY = 0`: [2](#0-1) 

`BridgeCounterPart.sol` stores `counterpartBridge` but it starts as `address(0)` and is only set by the owner via `setCounterPartBridge`: [3](#0-2) 

`_requestKLAYTransfer` checks only `isRunning` and `msg.value > _feeLimit`. It never checks `counterpartBridge != address(0)`: [4](#0-3) 

The public-facing entry points that call `_requestKLAYTransfer` are the payable fallback and `requestKLAYTransfer`: [5](#0-4) 

`_payKLAYFeeAndRefundChange` with `feeReceiver == address(0)` and `feeOfKLAY == 0` and `_feeLimit == 0` simply returns 0 — the full `msg.value` stays in the contract: [6](#0-5) 

The only mechanism to release KAIA from the source bridge is `handleKLAYTransfer`, which is `onlyOperators`. There is no owner-rescue, `emergencyWithdraw`, or refund path anywhere in `Bridge`, `BridgeTransfer`, `BridgeTransferKLAY`, or `BridgeFee`. [7](#0-6) 

The test fixture confirms the bridge is fully functional (accepts KAIA) before `setCounterPartBridge` is called: [8](#0-7) 

---

### Impact Explanation

Any KAIA sent to the source bridge before `setCounterPartBridge` is called (or before operators are registered on the counterpart chain) is permanently locked. The `RequestValueTransfer` event is emitted and `requestNonce` is incremented, giving the user a false impression that the transfer is in flight. Because no counterpart bridge exists to call `handleKLAYTransfer`, and because the contract has no withdrawal path, the KAIA is irrecoverable. This is an unauthorized, permanent loss of user-controlled KAIA — a bridged-asset impact within the allowed scope.

---

### Likelihood Explanation

Bridge deployment is a multi-step process: deploy → `setCounterPartBridge` → register operators → set fee receiver → set thresholds. The contract is live and accepting KAIA from the moment it is deployed. Any user (or automated script) that interacts with the bridge address during the configuration window — or that interacts with a bridge whose counterpart was never properly configured — triggers the loss. No special privilege is required; any EOA can call `requestKLAYTransfer` or send KAIA to the fallback.

---

### Recommendation

Add a guard in `_requestKLAYTransfer` (and optionally in the fallback) that rejects calls when the counterpart bridge has not yet been configured:

```solidity
// In BridgeTransferKLAY.sol → _requestKLAYTransfer
require(counterpartBridge != address(0), "counterpart not configured");
```

Additionally, consider adding an owner-only emergency-withdrawal function so that KAIA sent before configuration can be recovered:

```solidity
function emergencyWithdraw(address payable _to, uint256 _amount) external onlyOwner {
    (bool ok, ) = _to.call.value(_amount)("");
    require(ok, "withdraw failed");
}
```

### Proof of Concept

```typescript
import { ethers } from "hardhat";
import { expect } from "chai";

describe("Bridge: KAIA stuck before counterpart configured", function () {
  it("PoC: KAIA locked with no recovery path", async function () {
    const [owner, user] = await ethers.getSigners();

    const BridgeFactory = await ethers.getContractFactory("Bridge");
    // Deploy bridge — counterpartBridge is address(0), isRunning is true
    const bridge = await BridgeFactory.connect(owner).deploy(false);
    await bridge.deployed();

    // Confirm counterpart is not set
    expect(await bridge.counterpartBridge()).to.equal(ethers.constants.AddressZero);
    // Confirm bridge is running
    expect(await bridge.isRunning()).to.equal(true);

    const depositAmount = ethers.utils.parseEther("10");

    // User sends KAIA — succeeds, emits RequestValueTransfer, increments nonce
    await bridge.connect(user).requestKLAYTransfer(
      user.address,
      depositAmount,
      "0x",
      { value: depositAmount }
    );

    // KAIA is now locked in the bridge
    const bridgeBal = await ethers.provider.getBalance(bridge.address);
    expect(bridgeBal).to.equal(depositAmount); // 10 KAIA stuck

    // requestNonce was incremented — user believes transfer is in flight
    expect(await bridge.requestNonce()).to.equal(1);

    // No counterpart can ever call handleKLAYTransfer — KAIA is permanently lost
    // No emergencyWithdraw exists — owner cannot recover funds
  });
});
```

    function _payKLAYFeeAndRefundChange(uint256 _feeLimit) internal returns(uint256) {
        uint256 fee = feeOfKLAY;

        if (feeReceiver != address(0) && fee > 0) {
            require(_feeLimit >= fee, "insufficient feeLimit");

            (bool ok, ) = feeReceiver.call.value(fee)("");
            require(ok, "transfer fee failed");

            uint256 feeRefund = _feeLimit.sub(fee);
            if (feeRefund > 0) {
                (bool ok, ) = msg.sender.call.value(feeRefund)("");
                require(ok, "refund fee failed");
            }

            return fee;
        }

        if (_feeLimit > 0) {
            (bool ok, ) = msg.sender.call.value(_feeLimit)("");
            require(ok, "refund fee failed");
        }
        return 0;
    }

    function _requestKLAYTransfer(address _to, uint256 _feeLimit,  bytes memory _extraData)
        internal
        unlockedKLAY
        nonReentrant
    {
        require(isRunning, "stopped bridge");
        require(msg.value > _feeLimit, "insufficient amount");

        uint256 fee = _payKLAYFeeAndRefundChange(_feeLimit);

        emit RequestValueTransfer(
            TokenType.KLAY,
            msg.sender,
            _to,
            address(0),
            msg.value.sub(_feeLimit),
            requestNonce,
            fee,
            _extraData
        );
        requestNonce++;
    }
