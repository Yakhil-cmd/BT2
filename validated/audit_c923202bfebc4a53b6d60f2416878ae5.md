### Title
Payload-named route venues are invoked without an allowlist, letting a rogue hop contract steal any token from the caller's wallet via their authorization tree - (contracts/swap-aggregator/src/venues/mod.rs)

### Summary
CVE-2019-1387 is a too-lax-name-validation bug: an attacker-controlled string inside a payload (`.gitmodules` submodule name) escapes validation and causes the victim's own process to run attacker code. The analog in XOXNO Lending is the swap-aggregator route program: pool/venue addresses inside the user-supplied `swap_xdr` are never checked against a registry or allowlist, so `dispatch_hop` hands execution to arbitrary attacker-deployed contracts *while the caller's `require_auth` entry is live on the stack*. A rogue pool can then issue `token.transfer(victim, attacker, X)` on any token the victim holds, which the host records as a child of the victim's authorization entry and executes once the victim signs the swap transaction — stealing the wallet, not just the routed amount.

### Finding Description
`execute_strategy(sender, total_in, swap_xdr)` decodes a packed route whose `assets` registry contains arbitrary pool addresses, and `venues::dispatch_hop` dispatches each hop to the named pool contract (e.g. `invoke_contract`/`invoke_pool_swap`) with no venue or pool allowlist [1](#0-0) . The threat model itself states the router "keeps no allowlist of them, so a route can put third-party code on the call stack below the caller's authorization" and that such a transfer "executes if the caller signs that tree" [2](#0-1) . The controller entrypoints (`multiply`, `swap_collateral`, `swap_debt`, `repay_debt_with_collateral`) call the configured router via `swap_tokens`, which only authorizes the exact input transfer but leaves the caller's root `require_auth` entry governing the whole nested tree [3](#0-2) . The harness PoC `rogue_hop_pool_transfer_joins_caller_auth_tree.rs` deploys `RogueHopPool` whose `swap()` calls `token::Client::transfer(&victim, &to, &amount)` on an unrelated wallet token, drives it through `swap_collateral`, and asserts the recorded auth tree attaches the theft as a child of Alice's `swap_collateral` entry and that Alice's wallet goes to zero while the attacker receives 77,770 units [4](#0-3) [5](#0-4) .

### Impact Explanation
Theft of user funds: any token balance in the victim's wallet (not the swap input, not collateral — any SAC token) can be transferred to the attacker during a single `swap_collateral`/`swap_debt`/`multiply`/`repay_debt_with_collateral` or direct `execute_strategy` call. The loss is unbounded by `total_in`, `min_out`, or the final account risk gate, exactly like the git bug where the payload's effect is unbounded by the clone operation itself.

### Likelihood Explanation
Exploitation requires the victim to sign a transaction whose simulated auth tree contains the malicious child transfer — i.e. the attacker must get a crafted route in front of a user (malicious quote server, phishing UI, or a wallet that hides sub-invocations). The git CVE likewise required user interaction (cloning a hostile repo), and source-account credentials bind the whole tree to one signature, so any client that does not diff the auth tree signs it wholesale. The protocol itself documents that the only mitigation is client-side route decoding, meaning every frontend/wallet that skips the check is an attack surface. Reachability by an unprivileged address is clear: routes are attacker-supplied bytes and the router is callable directly.

### Recommendation
Enforce a governance-managed allowlist of pool/venue contract addresses (or wasm hashes) inside `dispatch_hop`, or pin each `SwapVenue` opcode to a set of registered pool addresses so a payload cannot name arbitrary contracts. Alternatively, isolate venue calls so they cannot see the sender's auth (Soroban cannot fully do this today), or require the router to re-auth each hop only under invoker-contract auth and reject any hop that makes a `require_auth` call on `sender`. At minimum, surface the expected child-invocation count in the route header so wallets can refuse trees with extra children.

### Proof of Concept
`tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs` is a complete PoC: `UnlistedPoolRouter::execute_strategy` decodes `RoutedSwap { hop_pool, ... }` from the payload and calls `invoke_contract(&route.hop_pool, "swap")` [6](#0-5) ; `RogueHopPool::swap` then executes `token.transfer(alice → attacker, WALLET_BALANCE)` on an unrelated token [4](#0-3) , and the test asserts the stolen transfer is recorded under Alice's `swap_collateral` auth entry and her wallet is drained [7](#0-6) .

Note: `docs/explanation/threat-model.md` explicitly documents this exposure and assigns mitigation to the client, so a strict reading of the "documented choices" exclusion could disqualify this finding; it is reported because the theft mechanism (unvalidated payload-named code execution under the caller's auth) is the closest true analog to the CVE's bug class, and the protocol-side fix (venue allowlist) is actionable.

    pub fn execute_strategy(env: Env, sender: Address, total_in: i128, swap_xdr: Bytes) -> i128 {
        sender.require_auth();
        let route = RoutedSwap::from_xdr(&env, &swap_xdr).expect("route must decode");
        let router = env.current_contract_address();
        token::Client::new(&env, &route.token_in).transfer(&sender, &router, &total_in);
        let _: Val = env.invoke_contract(&route.hop_pool, &symbol_short!("swap"), vec![&env]);
        token::Client::new(&env, &route.token_out).transfer(&router, &sender, &route.min_out);
        route.min_out
    }

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}
