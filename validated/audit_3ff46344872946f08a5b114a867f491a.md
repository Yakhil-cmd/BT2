Found it. The `MergeStatusController#check` action explicitly skips authentication but, unlike `#show`, never re-checks `current_user.logged_in?`, so it returns live stack/merge-queue status to a fully anonymous, unauthenticated caller who only needs to control the HTTP `Referer` header.

### Title
Unauthenticated disclosure of stack merge/CI status via `MergeStatusController#check` — ([File: app/controllers/shipit/merge_status_controller.rb])

### Summary
`MergeStatusController` opts `:check` and `:show` out of the engine's mandatory GitHub authentication via `skip_authentication only: %i[check show]` [1](#0-0) . `#show` compensates by manually gating on `current_user.logged_in?` before rendering anything [2](#0-1) , but `#check` has no such guard and unconditionally renders `stack_status` [3](#0-2) . The stack being queried is resolved entirely from the attacker-controlled `referrer` query parameter, parsed by the internal `ReferrerParser` regex against a `https://github.com/OWNER/REPO/pull/NUMBER` shape, with no verification that the requester is affiliated with that repository in any way [4](#0-3) .

### Finding Description
The binding that should hold is: *authenticated Shipit session* == *access to a stack's live state*. `Authentication#force_github_authentication` enforces this globally by requiring `current_user.logged_in?` and `authorized?` before any controller action executes [5](#0-4) . `MergeStatusController` legitimately needs to expose the `/merge_status` badge to anonymous GitHub PR pages, so it opts `:check` and `:show` out of this global gate — but `#show` re-establishes the binding locally (`return render('logged_out') unless current_user.logged_in?`), while `#check` does not. This breaks the equality: an unauthenticated caller (no session, no `ApiClient` token, no GitHub identity at all) can hit `#check` and receive `stack.merge_status(backlog_leniency_factor: 1.0)` for any stack resolvable via the `referrer` parameter, including stacks whose repository the caller has no access to on GitHub, purely by supplying a forged `Referer`-shaped string identifying `owner/repo/pull/number`.

### Impact Explanation
This is an unauthenticated read of stack/merge-queue state — explicitly a High-severity outcome per the engine's own trust model (authentication is otherwise mandatory for all stack data). An attacker can enumerate whether any repository/branch pair is deployable, locked, or blocked on CI/merge-queue processing without needing a Shipit account, an `ApiClient` token, or any GitHub credential, which is a boundary the rest of the engine deliberately protects with `force_github_authentication` and `current_user.authorized?`.

### Likelihood Explanation
Trivial and remotely exploitable: a single unauthenticated HTTP GET to the `check` route (mounted at `merge_status_controller#check`, reachable without session cookies) with a `referrer` query string of the form `https://github.com/<owner>/<repo>/pull/<n>` is sufficient; `stack` scope selection additionally allows omitting the PR number and falling back to the `production` environment for the owner/repo pair [6](#0-5) , broadening the disclosure to "latest production stack status for any repo name."

### Recommendation
Add the same `return ... unless current_user.logged_in?` (or equivalent authorization check) to `#check` that `#show` already performs, or otherwise require session/authorization before computing and returning `stack_status` in the `check` action.

### Proof of Concept
1. Without any Shipit session cookie or GitHub OAuth, send:
   `GET /merge_status/check?referrer=https://github.com/some-private-org/some-repo/pull/1&format=json`
2. `skip_authentication only: %i[check show]` bypasses `force_github_authentication` entirely for this request [1](#0-0) .
3. `stack` resolves `some-private-org/some-repo`'s production stack via `ReferrerParser` [7](#0-6) .
4. `#check` returns `{"stack_status":"success"}` (or `pending`/`failure`/etc.) with no `current_user.logged_in?` check, unlike `#show` [3](#0-2) , disclosing live CI/merge/lock state for a repository the caller has no proven relationship to.

    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
