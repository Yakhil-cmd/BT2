### Title
Tokens sent directly to the `Controller` are permanently frozen — no rescue path exists and every measured-refund path preserves pre-existing balances - (File: contracts/controller/src/payments.rs)

### Summary
The original `PerpDepository` bug was "two managed tokens can be stuck forever because the contract has no rescue/withdraw function." XOXNO Lending's `Controller` has the identical shape: it holds token balances transiently during borrow/repay/migrate/swap flows, yet it exposes no owner or governance function that transfers arbitrary tokens out. Worse, every code path that could pay tokens out of the controller is explicitly written to preserve whatever balance existed before the call, so any token that lands on the controller outside a measured delta stays there permanently. The pool has the same shape for stray balances but offers a partial escape via `recapitalize`'s refund leg; the controller offers none.

### Finding Description
The controller accumulates real token balances at `env.current_contract_address()` during strategies: `borrow_into_controller` (migrate/flash/multiply debt legs), `blend_sweep_all` receipts in `process_migrate_blend` (contracts/controller/src/strategies/migrate_blend.rs:100-112), swap proceeds in `strategies/swap.rs`, and flash-position flows. All outbound payment helpers measure a **balance delta** and deliberately leave the pre-call balance untouched:

- `refund_controller_balance_delta` computes `balance - balance_before` and transfers only the positive excess to `refund_to` (contracts/controller/src/payments.rs:41-52). A pre-existing balance is preserved by construction.
- `reconcile_debt_refunds` in `migrate_blend` does the same: `balance_delta_since` against the pre-borrow snapshot, and the comment states "Pre-existing controller funds remain untouched" (contracts/controller/src/strategies/migrate_blend.rs:232-268).
- `deposit_withdrawn` deposits only positive deltas since the pre-withdraw snapshot (migrate_blend.rs:202-230).

A grep of `contracts/controller` shows no `sweep`, `rescue`, or `skim` entrypoint, and the controller's governance surface only executes defined ops (market params, pauses, etc.) — none of which move tokens held by the controller address itself. The test `test_migrate_refund_ignores_preexisting_controller_balance` pins this: ETH minted directly to the controller is still sitting there after `migrate_from_blend` completes, "not used as refund or swept" (tests/test-harness/tests/strategy/migrate_blend.rs:496-537).

Any holder can reach this state: a direct `token.transfer` to the controller address, or tokens pushed to the controller by an external venue (e.g., a Blend pool or Soroswap route refunding an asset that is not in `debt_caps`/`withdraw_assets`, since unlisted-asset receipts are never measured or returned). Once there, no controller entrypoint — `supply`, `repay`, `withdraw`, `recapitalize`, `flash_loan`, any swap strategy, or `governance` execution — will ever move them out.

### Impact Explanation
Permanent freezing of funds. Tokens at the controller address are irrecoverable by anyone, including governance and the sender — matching the source report's "lost forever" impact. For direct transfers this is the sender's own loss, but the same freeze applies to protocol-flow tokens delivered to the controller but never measured (unlisted assets returned by `blend_sweep_all` or a swap route), which are user/protocol funds lost through normal use rather than a mistaken donation.

### Likelihood Explanation
Medium-low for accidental donations; higher in strategy flows because the controller legitimately receives tokens from external contracts (Blend sweeps, router payouts) and only the exact asset lists passed by the caller are reconciled — any extra asset the venue returns is stranded silently. There is no recovery transaction at all, so any occurrence is permanent.

### Recommendation
Add a rescue entrypoint on the controller (gated the same way as `upgrade`/governance ops) that transfers an arbitrary token amount to a recipient, or extend `recapitalize`-style reconciliation so controller-held balances above zero for a marketable asset can be supplied into the pool as protocol revenue. At minimum, sweep unlisted-asset receipts in `process_migrate_blend` back to `caller` instead of leaving them on the controller.

### Proof of Concept
1. Deploy standard hub/market; note `token.balance(controller) == 0`.
2. `token.transfer(anyone, controller, X)` — an unprivileged, public call (or have a Blend pool return an asset not present in `collateral_assets`/`supply_assets` during `migrate_from_blend`).
3. Call `controller.migrate_from_blend` or any strategy; `reconcile_debt_refunds`/`deposit_withdrawn` measure deltas from a snapshot taken *after* the transfer, so `balance_delta_since` returns 0 for the pre-existing amount (payments.rs:16-20, migrate_blend.rs:213-219).
4. Enumerate every controller entrypoint: none transfers the stuck balance out. `token.balance(controller) == X` forever — confirmed by `test_migrate_refund_ignores_preexisting_controller_balance`, which asserts the pre-seeded controller balance is unchanged after migration. /// Refunds only the controller balance increase since `balance_before`,
/// preserving the pre-existing balance; no-op for a nonpositive delta.
pub(crate) fn refund_controller_balance_delta(
    env: &Env,
    asset: &Address,
    balance_before: i128,
    refund_to: &Address,
) {
    let controller = env.current_contract_address();
    let excess = balance_delta_since(env, asset, &controller, balance_before);
    if excess > 0 {
        token::Client::new(env, asset).transfer(&controller, refund_to, &excess);
    }
}

/// Repays hub debt using positive balances above the pre-borrow snapshot.
/// Pre-existing controller funds remain untouched.
fn reconcile_debt_refunds(
    env: &Env,
    account: &mut Account,
    cache: &mut Context,
    caller: &Address,
    hub_id: u32,
    debt_caps: &Vec<(Address, i128)>,
    before: &Map<Address, i128>,
) {
    let controller = env.current_contract_address();
    for (debt_asset, _max) in debt_caps.iter() {
        let prev = before.get(debt_asset.clone()).unwrap_or(0);

        let refund = balance_delta_since(env, &debt_asset, &controller, prev);
        if refund > 0 {
            let hub_debt = HubAssetKey {
                hub_id,
                asset: debt_asset.clone(),
            };
            let raw = expect_invariant(env, account.borrow_positions.get(hub_debt.clone()));
            let debt_pos = DebtPosition::from(&raw);
            repay_debt_from_controller(
                env,
                account,
                cache,
                caller,
                StrategyRepay {
                    debt: &hub_debt,
                    debt_available: refund,
                    debt_pos: &debt_pos,
                    action: PositionAction::Migrate,
                },
            );
        }
    }

#[test]
fn test_migrate_refund_ignores_preexisting_controller_balance() {
    let mut t = LendingTest::new().standard_two_asset().build();
    let caller = t.get_or_create_user(ALICE);
    let blend_addr = register_approved_blend(&t);
    seed_position(&t, &blend_addr, &caller, "USDC", KIND_COLLATERAL, 2000.0);
    seed_position(&t, &blend_addr, &caller, "ETH", KIND_LIABILITY, 0.5);

    let usdc = t.resolve_asset("USDC");
    let eth = t.resolve_asset("ETH");
    let eth_dec = t.resolve_market("ETH").decimals;
    let stuck = f64_to_i128(0.25, eth_dec);
    t.resolve_market("ETH")
        .token_admin
        .mint(&t.controller, &stuck);

    let cap = f64_to_i128(0.6, eth_dec);
    let account_id = t.ctrl_client().migrate_from_blend(
        &caller,
        &0u64,
        &1u32,
        &HARNESS_HUB,
        &blend_addr,
        &SorobanVec::from_array(&t.env, [usdc]),
        &empty_assets(&t),
        &SorobanVec::from_array(&t.env, [(eth.clone(), cap)]),
    );

    let borrow = t.borrow_balance_for(ALICE, account_id, "ETH");
    assert!(
        (0.49..=0.51).contains(&borrow),
        "debt must still reconcile to ~0.5, got {borrow}"
    );
    let controller_eth = t.env.as_contract(&t.controller, || {
        soroban_sdk::token::Client::new(&t.env, &eth).balance(&t.controller)
    });
    assert_eq!(
        controller_eth, stuck,
        "pre-existing controller ETH must remain (not used as refund or swept)"
    );
}
