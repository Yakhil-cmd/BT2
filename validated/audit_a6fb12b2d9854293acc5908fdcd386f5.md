### Title
Permanent market freeze from i128 value overflow in index accrual (`scaled_to_original` on `borrowed * borrow_index`) - (File: common/src/rates/scaling.rs)

### Summary
Buffer/integer-overflow analog: an unprivileged whale can push a market's scaled borrow total past the RAY value domain so that the next interest accrual computes `borrowed * borrow_index` exceeding `i128::MAX`. `scaled_to_original` calls `scaled.mul(env, index)` which panics with `GenericError::MathOverflow` (`common/src/math/fp_core.rs:108-118`, `common/src/rates/scaling.rs:14-16`). Every state-changing entrypoint accrues indexes first, so once the product crosses `i128::MAX` the market is permanently frozen: `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, and `update_indexes` all revert. The borrow-index ceiling `MAX_BORROW_INDEX_RAY` (`common/src/rates/index.rs:13-19`) does not prevent this because the value overflow occurs well before the index cap.

### Finding Description
Accrual derives total debt as `borrowed.mul(env, old_borrow_index)` and `borrowed.mul(env, new_borrow_index)` in `calculate_supplier_rewards` (`common/src/rates/index.rs:80-81`), and utilization derives it via `scaled_to_original` (`contracts/pool/src/cache/scale.rs:23`). `Ray::mul` delegates to `mul_div_half_up`, which widens to `I256` for the intermediate but returns `MathOverflow` when the quotient does not fit `i128` (`common/src/math/fp_core.rs:122-143`). Per `docs/reference/formulas.md` numeric limits, the token-to-RAY input maximum is `i128::MAX / 10^(27-d)` (~170 billion whole tokens at 18 decimals), and `scaled` shares themselves can approach `i128::MAX` through normal `supply`/`borrow` entrypoints — no privileged cap lifting is required if caps are configured high or a whale simply deposits/borrows the maximum admissible amount. Because `update_borrow_index` grows the index each accrual, the fixed `borrowed` share count multiplied by a growing index eventually overflows `i128`, and from that block onward every call that accrues panics. Debt shares cannot be burned (repay reverts), supply shares cannot be exited (withdraw reverts), and positions cannot be liquidated (liquidate accrues first), so all pooled cash is locked permanently.

### Impact Explanation
Permanent freezing of user funds and effective protocol insolvency for that market: supplier cash sits in the pool contract while every exit path reverts deterministically. The freeze cannot be unwound by any on-chain action since there is no way to reduce `borrowed` or `borrow_index` without first accruing.

### Likelihood Explanation
Requires a very large position (order of 10^29 native units for an 18-decimal asset) or a smaller position combined with sustained high-utilization accrual over a long horizon — feasible only for whale-scale capital on large markets, and only where supply/borrow caps admit such size. Once seeded, the cliff is deterministic; a motivated attacker can even accelerate it by holding near-100% utilization debt. Given the capital requirement and slow accrual, Medium.

### Recommendation
Cap scaled positions and accrual so `scaled * index` stays within `i128`: enforce `scaled <= i128::MAX / MAX_BORROW_INDEX_RAY` at `calculate_scaled_borrow`/`calculate_scaled_supply`, or switch value computation to a checked `I256` path that truncates/clamps rather than panicking, and let the index caps engage before the value domain does. At minimum, gate `supply`/`borrow` entry on the post-accrual worst-case product at `MAX_*_INDEX_RAY`.

### Proof of Concept
Existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`) demonstrates it end-to-end: supply ~10^27 BIG18 base units, borrow 98%, advance time, and `update_indexes` reverts with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`; subsequent `withdraw` and `repay` revert identically — permanent freeze.
