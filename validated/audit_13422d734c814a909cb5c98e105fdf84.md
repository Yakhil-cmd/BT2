### Title
Cross-tenant repository mutation via decoupled `repository.owner.login` (signature scope) and `repository.full_name` (mutation target) - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` used for HMAC verification based solely on `params.dig('repository', 'owner', 'login')`, while `LabeledHandler#repository` loads the record to mutate solely from `params.repository.full_name`. Because these are two independent, attacker-controlled fields of the same JSON body, an attacker can pass verification against any org configured without a `webhook_secret` while pointing `repository.full_name` at a completely different org's repository, causing that unrelated repository's review stack to be archived/unarchived.

### Finding Description
The broken binding is: the organization whose `GitHubApp` verified the signature (`repository_owner` = `params.dig('repository','owner','login')` at [1](#0-0) ) MUST equal the organization that owns the repository actually mutated (`params.repository.full_name` parsed to `owner/name` at [2](#0-1)  and used in `LabeledHandler#repository` at [3](#0-2) ). Nothing in the code enforces this equality — they are read from two independent JSON paths of the same attacker-supplied body.

`verify_signature` looks up `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature` [4](#0-3) . `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank [5](#0-4) . Thus if any org configured in `Shipit.github_apps`-equivalent config has no `webhook_secret`, an attacker can set `repository.owner.login` to that org's name and pass verification with no HMAC at all.

Once verification passes, `WebhooksController#create` parses the raw body again and dispatches to handlers with the *same* full payload [6](#0-5) . `LabeledHandler#repository` resolves the target repository from `params.repository.full_name`, a field completely independent of `repository.owner.login` used above [3](#0-2) . `Repository.from_github_repo_name` simply splits the string on `/` and does a DB lookup [2](#0-1)  — it performs no cross-check against the field that gated signature verification.

Exploit: attacker crafts a `pull_request`/`labeled` JSON body with `repository.owner.login = "no-secret-org"` (an org configured in Shipit with a blank `webhook_secret`) but `repository.full_name = "victim-org/victim-repo"` (a real, unrelated, secret-protected repo with review stacks enabled). POSTs it to `/webhooks` with header `X-Github-Event: pull_request` and any (or no) `X-Hub-Signature` value. `verify_signature` resolves the `no-secret-org` `GitHubApp`, which accepts unconditionally. `LabeledHandler#handle` then calls `stack.archive!`/`stack.unarchive!` on the `victim-org/victim-repo` review stack based on the label list the attacker supplied in the same payload [7](#0-6) .

Existing guards do not stop this: `drop_unhandled_event` only checks the event type; the `ExplicitParameters` schema only requires presence/type of fields, not cross-consistency between `repository.owner.login` and `repository.full_name`; there is no model validation linking a webhook's verifying org to the repository being written.

### Impact Explanation
An attacker with zero Shipit credentials can force archive/unarchive state changes on any review stack belonging to any repository configured in Shipit, as long as one org configured in the system happens to have no `webhook_secret` set. This is a cross-repository/cross-tenant write: a payload nominally "authenticated" for org A mutates org B's stack. Matches "Critical - a payload for one repository mutating another's stack" per the impact taxonomy. Because this pattern (verify by one field, act on another) is not limited to `LabeledHandler` — every `PullRequest` handler that resolves `repository` via `params.repository.full_name` (`opened_handler.rb`, `closed_handler.rb`, `reopened_handler.rb`, `unlabeled_handler.rb`, `assigned_handler.rb`, `edited_handler.rb`) shares the same decoupling, the blast radius extends to all pull-request-driven review-stack lifecycle actions.

### Likelihood Explanation
Preconditions: at least one org in Shipit's GitHub app configuration must have a blank `webhook_secret` (config-dependent, but the code explicitly supports this — `verify_webhook_signature` treats it as intentionally "no verification needed" rather than "deny"), and the target repository must have `review_stacks_enabled`. Attacker cost is a single crafted HTTP POST with no valid signature and no knowledge of any secret — fully repeatable and scriptable against any repository in the install.

### Recommendation
In `WebhooksController#verify_signature`/`create`, and in `Shipit::Webhooks::Handlers::Handler` base class, ensure the organization that authorized the webhook (`repository_owner`) is required to equal the owner segment of `repository.full_name` used to resolve any mutated `Repository`/`Stack`; reject the request otherwise. Additionally, reconsider treating a blank `webhook_secret` as "verified" — it should either be disallowed for orgs with mapped repositories or logged/alerted as an explicitly insecure configuration, and payload-derived owner/repo consistency should be validated for every handler that resolves a `Repository` by `full_name`.

### Proof of Concept
Minitest (webhooks_controller integration test), sketch:
1. Configure `Shipit.github_apps` (or equivalent) with org `"no-secret-org"` having `webhook_secret: nil`, and org `"victim-org"` having a real `webhook_secret`.
2. Create `Shipit::Repository.create!(owner: "victim-org", name: "victim-repo", review_stacks_enabled: true, provisioning_behavior: "allow_with_label")` and a `ReviewStack`/pull request fixture matching `pull_request.number`.
3. Build a `pull_request`/`action=labeled` JSON body with `repository.owner.login = "no-secret-org"`, `repository.full_name = "victim-org/victim-repo"`, and `pull_request.labels` set to trigger `archive?`.
4. `post shipit.webhooks_path, params: body.to_json, headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=deadbeef', 'Content-Type' => 'application/json' }`.
5. Assert response is `200`, and assert `victim_stack.reload.archived?` is now `true` (or the state flipped) — proving org `no-secret-org`'s (non-)verification wrote to `victim-org`'s stack, i.e. `repository_owner_used_for_verification != repository_owner_of_mutated_stack` while the request still succeeded.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
