#No vulnerability found for this question.

**Analysis:** `calculate_block_reward` at [1](#0-0)  is a pure, deterministic function of on-chain consensus state: the `Delegation` (stored in the stake account), `stake_history` (a sysvar), `rewarded_epoch`, and `reward_epoch_delegated_stakes` (derived once per epoch and stored in `AlpenglowEpochType`). `delegation_effective_stake` itself is a deterministic warmup/cooldown calculation with no attacker-supplied randomness [2](#0-1) .

The code comment explicitly documents that `stake > total_active_stake` can occur "during recalculation, if stake account has already received rewards" and states this is "harmless in practice," with the `.min(pending_delegator_rewards)` clamp added purely as a defensive measure against `u128`→`u64` overflow, not as a patch for a security hole [3](#0-2) . Because every input to this function (delegation state, stake history sysvar, epoch, and the pre-computed `reward_epoch_delegated_stakes` map) is part of validated, replicated consensus state, any two invocations of `calculate_block_reward` for the same stake/epoch (whether during initial "calculation" or "recalculation") will consume bit-identical inputs and therefore produce bit-identical outputs on every node — there is no mechanism by which an unprivileged attacker can cause the two passes to diverge from each other or between nodes. The scenario requires no attacker action beyond normal stake delegation/deactivation, which any user can already do, but doesn't introduce cross-node or cross-pass divergence since the computation is fully deterministic given identical consensus inputs.

No reachable attacker path produces non-deterministic reward totals, duplicated payouts, or lamport theft from this code as written; the "harmless in practice" comment reflects an intentional design tradeoff already accounted for by the clamp, not an unhandled overflow or accounting bug.

fn calculate_block_reward(
    rewarded_epoch: Epoch,
    delegation: &Delegation,
    stake_history: &StakeHistory,
    distribution_epoch_vote_accounts: &VoteAccounts,
    ag_epoch_type: &AlpenglowEpochType,
    new_warmup_cooldown_rate_epoch: Option<Epoch>,
    use_fixed_point_stake_math: bool,
) -> u64 {
    let vote_pubkey = delegation.voter_pubkey;
    let Some(vote_account) = distribution_epoch_vote_accounts.get(&vote_pubkey) else {
        debug!("could not find vote account {vote_pubkey} in cache");
        return 0;
    };
    let vote_state = vote_account.vote_state_view();
    let pending_delegator_rewards = vote_state.pending_delegator_rewards();
    // NOTE: during recalculation, `distribution_epoch_vote_accounts` already
    // includes updated stake activation values from after the new epoch
    // calculation, so we need to use `RewardEpochDelegatedStakes` for the exact
    // values at the end of the reward epoch.
    let (AlpenglowEpochType::Alpenglow {
        reward_epoch_delegated_stakes,
        ..
    }
    | AlpenglowEpochType::MigrationEpoch {
        reward_epoch_delegated_stakes,
        ..
    }) = ag_epoch_type
    else {
        debug!("Alpenglow must be enabled for block reward calculation");
        return 0;
    };
    let total_active_stake = reward_epoch_delegated_stakes
        .delegated_stakes
        .get(&vote_pubkey)
        .copied()
        .unwrap_or(0);
    if total_active_stake == 0 {
        0
    } else {
        let stake = delegation_effective_stake(
            delegation,
            rewarded_epoch,
            stake_history,
            new_warmup_cooldown_rate_epoch,
            use_fixed_point_stake_math,
        );
        // During recalculation, if stake account has already received rewards,
        // it's possible to have `stake > total_active_stake`. If
        // `pending_delegator_rewards` is a huge number, we could potentially
        // overflow a `u64`. We can also have individual rewards look greater
        // than the pending rewards. This is harmless in practice, but we
        // clamp it just to be safe
        (pending_delegator_rewards as u128 * stake as u128 / total_active_stake as u128)
            .try_into()
            .unwrap_or(u64::MAX)
            .min(pending_delegator_rewards)
    }
}

#[inline]
pub(crate) fn delegation_effective_stake<T: StakeHistoryGetEntry>(
    delegation: &Delegation,
    epoch: Epoch,
    history: &T,
    new_rate_activation_epoch: Option<Epoch>,
    use_fixed_point_stake_math: bool,
) -> u64 {
    if use_fixed_point_stake_math {
        delegation.stake_v2(epoch, history, new_rate_activation_epoch)
    } else {
        #[allow(deprecated)]
        delegation.stake(epoch, history, new_rate_activation_epoch)
    }
}
