### Title
Unchecked scaled-value overflow permanently freezes a market’s user exits - (File: `contracts/pool/src/cache/scale.rs`)

### Summary

`update_indexes` and every pool operation that touches a market run `interest::global_sync` before mutating or committing state. [1](#0-0)  When a sufficiently large high-decimal market sustains enough utilization for its indexes to grow beyond the `i128` value domain, accrual reverts with `MathOverflow` inside `scaled_to_original`. [2](#0-1)  The repository’s regression test confirms that subsequent `withdraw` and `repay` calls hit the same failure, leaving the affected market frozen rather than merely rejecting one malformed request. [3](#0-2) 

### Finding Description

`Controller::update_indexes` is caller-authenticated but otherwise permissionless and forwards the requested `Vec<HubAssetKey>` to the pool. [4](#0-3)  The pool loads each market and invokes `interest::global_sync`, which loops through accrued time and calls `accrue_step` for each bounded chunk. [5](#0-4) [6](#0-5)  `accrue_step` receives the market’s scaled borrow and supply totals together with the current indexes. [7](#0-6) 

Those scaled totals are converted back to asset values through `scaled_to_original` when utilization is calculated. [8](#0-7)  At a sufficiently large scaled balance and index, that conversion exceeds `i128`, so the transaction reverts before `last_timestamp` is advanced or the new index can be committed. [6](#0-5) [2](#0-1) 

This is the protocol-shaped analogue of CVE-2017-7659: a remotely supplied state transition reaches a crash condition in common request processing. Here the “request” is a normal `update_indexes`, `repay`, `withdraw`, or liquidation call, and the crash is deterministic checked-arithmetic failure rather than a native NULL dereference. [9](#0-8) 

### Impact Explanation

The affected `(hub_id, asset)` market becomes unable to process exits or debt reduction because those paths load an interest-synced cache before applying their operation. [9](#0-8)  The in-repository reproduction explicitly demonstrates `MathOverflow` on both withdrawal and repayment after the threshold is crossed. [10](#0-9)  Liquidation also routes through the pool’s synced market operations and therefore cannot rescue the account once accrual itself is the failing step. [2](#0-1) 

Because the overflow occurs before the new market state is committed, retrying later repeats the same overflow rather than advancing accrual past the bad interval. [6](#0-5)  Even replacing the rate model cannot bypass it because `replace_rate_model` first creates a renewed, interest-synced market. [11](#0-10)  Absent a privileged code upgrade or another recovery mechanism, supplier funds, borrower collateral backing the frozen debt, and unclaimed revenue in that market remain inaccessible. [9](#0-8) 

### Likelihood Explanation

An unprivileged account can create the prerequisite state using ordinary `supply` and `borrow` calls and later trigger the failure through permissionless `update_indexes`. [12](#0-11) [4](#0-3)  The caller needs a market whose caps and utilization configuration admit an extremely large high-decimal position, enough collateral to sustain high utilization, and enough elapsed accrual for the index to reach the value ceiling. [13](#0-12) 

Those requirements make the attack capital- and configuration-dependent, but not dependent on privileged access, malformed authorization, oracle manipulation, or a token semantic violation. [12](#0-11)  Once the threshold is reached, any user can trigger the freeze with `update_indexes`, and no unprivileged recovery path remains. [4](#0-3) [3](#0-2) 

### Recommendation

Bound the conversion before evaluating utilization and cap or safely saturate indexes at `MAX_BORROW_INDEX_RAY` before `scaled * index` can exceed `i128`. [8](#0-7)  Accrual should commit a capped terminal state instead of reverting before `last_timestamp` advances. [6](#0-5)  The terminal state should freeze further interest accrual while preserving repayment, liquidation, withdrawal order, and bad-debt settlement semantics. [9](#0-8) 

Add production-level regression coverage asserting that near-cap indexes still permit `repay`, `withdraw`, liquidation, `clean_bad_debt`, `recapitalize`, and rate-model replacement. [11](#0-10) [10](#0-9) 

### Proof of Concept

The repository already contains a deterministic harness reproduction in `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`. [13](#0-12)

```rust
// 3. borrow(caller, account_id, [(BIG18, principal * 98 / 100)], None)
```

The final call invokes the pool’s `update_indexes`, which loads `BIG18`, calls `global_sync`, and evaluates the overflowing scaled-value conversion. pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
```rust
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```
