### Title
Denial of Service via uncaught `throw Error` in AA remote-getter complexity check crashes full node - (File: formula/evaluation.js)

### Summary
`formula/evaluation.js`'s `checkMaxRemoteComplexity()` only special-cases two possible types for an evaluated `max_remote_complexity` formula result — `string` and `Decimal` — and falls back to a synchronous `throw Error(...)` for any other type [1](#0-0) . Since the generic oscript expression evaluator (`evaluate()`) freely returns booleans as first-class values without restriction [2](#0-1) , an AA author can write a remote-getter call whose max-complexity sub-formula evaluates to `true`/`false`, which reaches the unguarded `else throw Error("unknown type of max_remote_complexity: " + max_remote_complexity)` branch.

### Finding Description
`checkMaxRemoteComplexity` is invoked while an AA response is being composed for a trigger (deep inside `handleTrigger`/`evaluateAA`/formula evaluation, itself several async callback layers below `mutex.lock`/db-query callbacks in `aa_composer.js`) [3](#0-2) . Unlike essentially every other formula-evaluation failure path, which goes through `setFatalError(...)` and is surfaced to the caller as a formula error/bounce [4](#0-3) , this one branch throws a plain JS `Error` synchronously instead of calling back with an error.

Because this throw happens inside nested asynchronous callbacks (not inside a `try/catch` guarding the AA-trigger processing pipeline), it propagates as an uncaught exception all the way to Node's process-level handler. `network.js` installs a global handler that explicitly re-throws to crash the process: [5](#0-4) 
This is the same bug class as the reported `node-sass` issue: a crafted, attacker-supplied object/value reaches internal code that asserts/throws instead of gracefully failing, crashing the running process and causing Denial of Service.

### Impact Explanation
Any full node (including witnesses) that processes a trigger unit calling into an AA whose author wrote a remote-getter invocation with a boolean-valued max-complexity sub-formula will crash entirely once that AA is triggered. AAs are triggered by ordinary payments from any unprivileged unit poster, so a single crafted, otherwise-valid AA definition (posted once by its author) becomes a standing DoS device: anyone who sends a payment to it (or the AA's own scheduled/secondary logic triggering it) crashes every full node that processes that trigger, preventing the network from confirming further units — this matches the "network unable to confirm new units" impact bar.

### Likelihood Explanation
Reaching this code requires only writing an AA in oscript that includes a remote-getter call (a normal, documented AA feature for cross-AA `state`/getter access) where the max-complexity parameter is a formula that evaluates to a boolean instead of a string/number. `validateAADefinition` and `formula/validation.js` perform only static/syntactic validation of the formula (that it parses as a valid formula for that slot), not a runtime type check of what the sub-formula will evaluate to at trigger time, so this configuration is not rejected at definition time and is only discovered when actually evaluated during a trigger.

### Recommendation
In `checkMaxRemoteComplexity` (`formula/evaluation.js`), replace the trailing `throw Error(...)` with a call to `setFatalError(...)`/`cb(err)` so that an unexpected type for `max_remote_complexity` is treated as a normal formula evaluation failure (bounce) rather than a process-crashing exception. Audit other `throw Error(...)` statements inside `formula/evaluation.js` and `aa_composer.js` that are reachable from attacker/AA-author-controlled data during trigger processing and convert them to the standard `setFatalError`/callback-based error path.

### Proof of Concept
1. Publish an AA definition whose `messages`/`getters` include a remote-getter call of the form (schematically) `remote_aa_getter($remote_aa, "some_getter", true)` — i.e., supply a boolean literal (or any sub-formula that evaluates to a boolean) as the max-remote-complexity argument. This passes `validateAADefinition`'s static checks since it only checks that the argument is a syntactically valid formula.
2. Trigger the AA with a normal payment from any address.
3. During response composition, `evaluate()` resolves the max-complexity sub-formula to the JS boolean `true`, and `checkMaxRemoteComplexity` falls through to the `else throw Error("unknown type of max_remote_complexity: " + max_remote_complexity)` branch [6](#0-5) .
4. The exception is uncaught within the async `handleTrigger`/db-callback chain and is caught only by `network.js`'s `process.on('uncaughtException', ...)` handler, which re-throws to crash the Node process [5](#0-4) , taking down the full node that processed the trigger.

	function checkMaxRemoteComplexity(remote_aa, func_name, max_remote_complexity, cb) {
		if (max_remote_complexity === null)
			return cb();
		evaluate(max_remote_complexity, max_remote_complexity => {
			if (fatal_error)
				return cb(fatal_error);
			if (typeof max_remote_complexity === 'string') {
				storage.readAADefinition(conn, remote_aa, mci, arrDefinition => {
					if (!arrDefinition)
						return cb("no such remote AA: " + remote_aa);
					const base_aa = arrDefinition[1].base_aa;
					if (max_remote_complexity !== base_aa)
						return cb(max_remote_complexity + " is not base AA for remote AA " + remote_aa);
					cb();
				});
			}
			else if (Decimal.isDecimal(max_remote_complexity)) {
				max_remote_complexity = max_remote_complexity.toNumber();
				storage.readAAGetterProps(conn, remote_aa, func_name, mci, props => {
					if (!props)
						return cb("no such getter: " + remote_aa + "." + func_name);
					if (typeof props.complexity !== 'number')
						throw Error("bad complexity of " + remote_aa + "." + func_name + ": " + props.complexity);
					if (props.complexity > max_remote_complexity)
						return cb("getter " + remote_aa + "." + func_name + " has complexity " + props.complexity + " while called with max remote complexity " + max_remote_complexity);
					cb();
				});
			}
			else
				throw Error("unknown type of max_remote_complexity: " + max_remote_complexity);
		});
