### Title
`getRemoveVotesInInterval` Silently Discards Remove-Validator Votes When Any Non-Validator Governance Vote Exists in the Scan Range, Causing Removed Validators to Receive Unauthorized Block Rewards — (`kaiax/valset/impl/getter_proposers.go`)

### Summary

On the non-migrated path, `getRemoveVotesInInterval` returns `nil` and skips caching whenever a block in the scan range carries a non-validator governance vote (e.g., `governance.unitprice`). Because the nil result is never cached, every subsequent call for the same interval re-scans and returns nil again. `filteredProposerList` called on a nil `removeVoteList` silently returns the unfiltered base proposer list, so a validator that was removed via `RemoveValidator` vote remains in the proposer rotation for the entire interval and continues to receive KAIA block rewards.

### Finding Description

**`parseValidatorVote` returns `false` for non-validator votes — this is by design:** [1](#0-0) 

The function returns `("", nil, false)` for any vote whose key is not in `gov.ValidatorParams` (e.g., `governance.unitprice`, `reward.mintingamount`). This is the correct signal meaning "not a validator vote, skip it."

**`getRemoveVotesInInterval` misinterprets this signal as a hard error:** [2](#0-1) 

When `parseValidatorVote` returns `!ok` for a non-validator governance vote, the function logs an error and returns `nil` — instead of `continue`-ing to the next block. The correct caller pattern is shown in `applyVote`, which returns `false` (skip) on `!ok`: [3](#0-2) 

**The nil result is never cached:** [4](#0-3) 

The cache-store is guarded by `len(removeVotes) > 0`. Since `nil` is returned before this line is reached, every subsequent call for the same `pUpdateNum` re-scans the full interval and returns `nil` again.

**`filteredProposerList` on a nil `removeVoteList` returns the unfiltered list:** [5](#0-4) 

A nil `removeVoteList` is a nil Go slice. `isUniquelySorted` returns `true` for `len <= 1`, the range loop over `*r` does nothing, `removeAddrs.Len() == 0`, so `proposers` is returned unchanged — the `RemoveValidator` vote is never applied.

**The non-migrated path is active whenever migration is incomplete:** [6](#0-5) 

Any node where `pMinVoteNum == nil` or `*pMinVoteNum > pUpdateNum` uses the non-migrated path, which scans every block in `[pUpdateNum, pUpdateNum+pUpdateInterval)`. Non-validator governance votes are common on mainnet (the test data confirms votes like `governance.unitprice`, `reward.mintingamount`, `istanbul.committeesize` at many block numbers).

### Impact Explanation

A validator removed via `RemoveValidator` vote in an interval that also contains any non-validator governance vote will remain in the proposer list for the entire interval. Since proposer selection drives block reward distribution, the removed validator receives KAIA block rewards it is not entitled to — unauthorized reward distribution affecting system-managed funds.

### Likelihood Explanation

Non-validator governance votes are routine on Kaia mainnet. The non-migrated path is active on any node that has not completed migration. The combination is highly likely to occur in practice, and the bug is deterministic once triggered — it persists for the entire interval with no recovery path (nil is never cached, so the scan repeats on every block).

### Recommendation

In `getRemoveVotesInInterval`, replace the `return nil` on `!ok` with `continue` to match the semantics of `parseValidatorVote` (which returns `false` to mean "not a validator vote, skip"):

```go
voteKey, addresses, ok := parseValidatorVote(header)
if !ok {
    continue // not a validator vote; skip
}
```

Only return `nil` (or an error) for conditions that are genuinely unrecoverable (e.g., `getQualifiedPermissioned` failure or non-sequential add).

### Proof of Concept

1. Set up a chain on the non-migrated path (`pMinVoteNum == nil` or `> pUpdateNum`).
2. In interval `[U, U+interval)`, place a `RemoveValidator` vote at block `U+5` and a `governance.unitprice` vote at block `U+3`.
3. Call `getProposerList` for blocks `U+6`, `U+7`, `U+8` (after the remove vote).
4. Observe that the removed validator is present in the returned proposer list on all three blocks — the remove vote was never applied because the non-validator vote at `U+3` caused `getRemoveVotesInInterval` to return `nil`.
5. Confirm the nil result is not cached by verifying `removeVotesCache.Get(U)` returns nothing, and that each call re-scans the interval. [7](#0-6)

func (v *ValsetModule) getRemoveVotesInInterval(pUpdateNum, pUpdateInterval uint64) removeVoteList {
	// return early if removeVoteLists is found in cache
	if list, ok := v.removeVotesCache.Get(pUpdateNum); ok {
		return list.(removeVoteList)
	}

	// collect remove validator votes by scanning blocks between [pUpdateNum, pUpdateNum+pUpdateInterval)
	scanBlocks := v.scanBlocks(pUpdateNum, pUpdateInterval)
	removeVotes := make(removeVoteList, 0)
	for _, num := range scanBlocks {
		header := v.Chain.GetHeaderByNumber(num)
		if header == nil || len(header.Vote) == 0 {
			continue // skip nil header or vote
		}
		voteKey, addresses, ok := parseValidatorVote(header)
		if !ok {
			logger.Error("Failed to parse validator vote", "block", num)
			return nil
		}
		if len(addresses) > 0 && voteKey == gov.RemoveValidator {
			// demoted validators are not considered
			qualified, err := v.getQualifiedPermissioned(num)
			if err != nil {
				logger.Error("Failed to get qualified validators", "block", num, "err", err)
				return nil
			}
			if removeVotes.add(num, addresses, qualified) == false {
				logger.Error("remove vote is not added sequentially ascending order", "block", num)
				return nil
			}
		}
	}

	// Store to cache
	if len(removeVotes) > 0 {
		v.removeVotesCache.Add(pUpdateNum, removeVotes)
	}
	return removeVotes
}

func (r *removeVoteList) filteredProposerList(currentNum uint64, proposers []common.Address) []common.Address {
	if !(*r).isUniquelySorted() {
		logger.Error("removeVoteList are not sorted. create the list in ascending order.")
		return nil
	}

	removeAddrs := new(valset.AddressSet)
	for _, vote := range *r {
		if currentNum <= vote.voteBlkNum {
			break
		}
		for _, addr := range vote.removeAddrs {
			removeAddrs.Add(addr)
		}
	}

	if removeAddrs.Len() == 0 {
		return proposers
	}
