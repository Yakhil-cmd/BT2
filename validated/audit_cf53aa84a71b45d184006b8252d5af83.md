### Title
Emergency OP-list vote count is applied at write-time of an unstable `system_vote_count` unit instead of after that unit stabilizes - ([File: writer.js])

### Summary
`writer.js` triggers `main_chain.applyEmergencyOpListChange()` synchronously while saving a `system_vote_count` unit, before that unit itself is confirmed/stable. This mirrors the Gondi finding where a state-mutating action (`updateOfferHandler`) is executed at proposal time inside `setOfferHandler()` instead of being deferred to the confirmation step (`confirmOfferHandler()`) that runs after the waiting period elapses.

### Finding Description
When a unit carrying a `system_vote_count` message for the `op_list` subject is saved, and the unit's sequence is `'good'` at write time, `saveJoint()` immediately schedules `main_chain.applyEmergencyOpListChange(conn, objUnit.timestamp, cb)` as part of the same write transaction: [1](#0-0) 

`applyEmergencyOpListChange()` recomputes and REPLACEs `system_vars` for `op_list` (which drives the active witness/OP set used by the whole network) as soon as the timeout condition is met, based on the *unstable* votes collected from `assocUnstableMessages`: [2](#0-1) [3](#0-2) 

The `sequence='good'` flag checked in `writer.js` reflects only the *current, tentative* serial/non-serial classification determined during unit validation (`objValidationState.sequence`), not final stability. As shown in `validateAuthor()`, a unit can be temporarily `'good'` and only later reclassified to `'temp-bad'`/`'final-bad'` once conflicting units are found or as the DAG advances and stabilizes (`checkSerialAddressUse()`), and that determination itself changes again during `markMcIndexStable()`/`handleNonserialUnits()` at actual stabilization: [4](#0-3) [5](#0-4) 

Thus the OP-list emergency recount and the resulting global `system_vars.op_list` REPLACE (and the `system_vars_updated` event, which propagates the new OP set to light clients and updates `myWitnesses`) can fire off of a unit that is not yet stable and could subsequently become non-serial/`final-bad` — analogous to the Gondi bug where `getLoanManager.updateOfferHandler()` fired inside the "propose" step instead of after the delayed "confirm" step validated the waiting period and finality.

### Impact Explanation
The active order-provider (OP)/witness list is one of the most security-critical global parameters in ocore: it determines whose signatures/witnessing are trusted for stability calculations across the whole DAG. Applying an OP-list change based on an as-yet-unconfirmed unit's votes means the network could adopt a new OP list prematurely, before the underlying vote-triggering unit is guaranteed final. If that triggering unit is later invalidated (found non-serial/conflicting), nodes that already applied the emergency OP-list change diverge from nodes that have not yet processed it, causing disagreement on validity/stability of subsequent units — the same class of impact the rules require (network unable to agree on validity/stability).

### Likelihood Explanation
This code path is guarded by `objValidationState.bHasSystemVoteCount && objValidationState.sequence === 'good'` and an additional time-based gate inside `applyEmergencyOpListChange` (must exceed `EMERGENCY_OP_LIST_CHANGE_TIMEOUT` since the last stable unit), so it is not triggerable by an arbitrary unit at will — it requires the DAG to already be "stuck" for the emergency-recount timeout to pass and an author to post a `system_vote_count` message. That said, once that state is reached, any single unit poster who posts the qualifying `system_vote_count` message can trigger the recount at write time, without needing to wait for their own triggering unit to stabilize.

### Recommendation
Defer the `applyEmergencyOpListChange` call until the triggering `system_vote_count` unit is confirmed stable (i.e., invoke it from the stabilization path such as `markMcIndexStable`/`stabilizeMci`, or re-validate that the unit is still `sequence='good'` and stable before applying), rather than invoking it synchronously inside `saveJoint()` based on the unit's provisional sequence state.

### Proof of Concept
Not independently verified end-to-end (would require constructing a scenario where the DAG is stalled past `EMERGENCY_OP_LIST_CHANGE_TIMEOUT`, then posting a conflicting pair of units authored from the same address, one carrying `system_vote_count`, to show the OP list gets updated based on a unit that later becomes `final-bad`). This is noted as an open verification item; the code path described above (`writer.js:639-645` calling into `main_chain.js:1936-1946`, gated only by the provisional `objValidationState.sequence`) is confirmed by direct code inspection.

function getUnstableVotes(emergency_count_command_timestamp) {
	let votes = [];
	for (let unit in storage.assocUnstableMessages) {
		for (let m of storage.assocUnstableMessages[unit]) {
			if (m.app === 'system_vote' && m.payload.subject === 'op_list') {
				const { timestamp, author_addresses, sequence, level } = storage.assocUnstableUnits[unit];
				if (sequence !== 'good')
					continue;
				if (emergency_count_command_timestamp - timestamp < constants.EMERGENCY_COUNT_MIN_VOTE_AGE) {
					console.log('unstable vote from', author_addresses, 'is too young');
					continue;
				}
				const arrOPs = m.payload.value;
				votes.push({ timestamp, level, author_addresses, arrOPs });
			}
		}
	}
	return votes;
}

async function applyEmergencyOpListChange(conn, emergency_count_command_timestamp, cb) {
	// last stable unit
	const [{ timestamp, main_chain_index }] = await conn.query("SELECT timestamp, main_chain_index FROM units WHERE is_stable=1 AND is_on_main_chain=1 ORDER BY main_chain_index DESC LIMIT 1");
	if (emergency_count_command_timestamp < timestamp + constants.EMERGENCY_OP_LIST_CHANGE_TIMEOUT) {
		console.log(`too early to apply emergency OP list change yet`);
		return cb();
	}
	console.log(`applying emergency vote count after being stuck at mci ${main_chain_index}`);
	await countVotes(conn, main_chain_index - 1, 'op_list', 1, emergency_count_command_timestamp);
	cb();
}
