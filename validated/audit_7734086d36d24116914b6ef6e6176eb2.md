### Title
Wrong Address Checked in `checkConsistency` Allows Governing-Node Vote to Non-Council Address, Permanently Locking Governance - (File: `kaiax/gov/headergov/impl/header.go`)

---

### Summary

`checkConsistency` in `kaiax/gov/headergov/impl/header.go` validates a `governance.governingnode` vote by checking whether the **current** governing node (`params.GoverningNode`) is in the council, instead of checking whether the **proposed new** governing node (`vote.Value().(common.Address)`) is in the council. Because the current governing node is unconditionally qualified and always in the council under normal operation, the guard never rejects any governing-node vote. A vote nominating an address that is not a council member passes both the `governance_vote` API and `VerifyVote` block-header validation, gets ratified at the next epoch boundary, and permanently locks governance.

---

### Finding Description

In `checkConsistency` (`kaiax/gov/headergov/impl/header.go`, lines 159–178), the `GovernanceGoverningNode` branch reads:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {   // ← checks CURRENT node
        return nil
    }
    return ErrGovNodeNotInValSetList
``` [1](#0-0) 

`params.GoverningNode` is the **current** governing node retrieved from the active parameter set. The vote's payload — the **proposed new** governing node — is `vote.Value().(common.Address)`, as confirmed by the `addressCanonicalizer` registered for `GovernanceGoverningNode`: [2](#0-1) 

The intended invariant is: *the new governing node must already be a council member*, so that after ratification it can propose blocks and cast further governance votes. The code checks the wrong address: it verifies that the **current** governing node is in the council (which is always true in normal operation), not that the **new** governing node is.

The same `checkConsistency` function is called from both the `Vote` API path and the `VerifyVote` block-header validation path: [3](#0-2) [4](#0-3) 

Neither path catches the invalid vote. The vote is stored, ratified at the next epoch boundary, and written into `header.Governance`, after which `GetParamSet` returns the new (invalid) governing node for all subsequent blocks.

---

### Impact Explanation

After the bad vote is ratified:

1. `GetParamSet(N).GoverningNode` returns an address not in the council.
2. That address cannot be a block proposer (proposers are drawn from `QualifiedValidators`, which is a subset of the council).
3. Because votes are embedded in `header.Vote` only when the node is the proposer, the new governing node can never cast a governance vote.
4. In `single` mode, only the governing node may vote (`VerifyVote` enforces this post-Permissionless). No other council member can vote either.
5. Governance is permanently frozen: no parameter — minting amount, reward ratio, unit price, committee size, or the governing node itself — can ever be changed again.

The `valset` README confirms the governing node is unconditionally qualified (it can still be in `QualifiedValidators` even without stake), but qualification is irrelevant if the address is not in the council at all, because `VerifyVote` checks council membership: [5](#0-4) 

---

### Likelihood Explanation

The trigger requires the current governing node (a semi-trusted actor in `single` mode — Mainnet and Kairos both run in `single` mode) to call `governance_vote("governance.governingnode", <addr>)` where `<addr>` is not yet in the council. This can happen by:

- **Mistake**: a typo or copy-paste error in the target address.
- **Operational error**: voting for a new node before it has been added to the council via `governance.addvalidator`.
- **Malice**: a compromised governing-node key.

The check that was supposed to prevent this silently passes in all cases, so there is no on-chain safety net.

---

### Recommendation

Replace `params.GoverningNode` with `vote.Value().(common.Address)` in the council membership check:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    newGoverningNode := vote.Value().(common.Address)   // ← proposed new node
    if slices.Contains(council, newGoverningNode) {
        return nil
    }
    return ErrGovNodeNotInValSetList
```

Add a unit test that submits a `governance.governingnode` vote for an address absent from the council and asserts `ErrGovNodeNotInValSetList` is returned. The existing test at `header_test.go:81` only tests the happy path (voting for `validVoter`, which is already in the council): [6](#0-5) 

---

### Proof of Concept

**Setup**: `single` governance mode. Council = `[A]`. Current governing node = `A`. `B` is not in the council.

1. Node A calls `governance_vote("governance.governingnode", B)`.
2. `Vote()` → `checkConsistency(blockNum, vote)` → `params.GoverningNode = A`; `slices.Contains(council, A)` → `true` → returns `nil` (no error). Vote is accepted.
3. At the next epoch block, `getExpectedGovernance` collects the vote; `VerifyGov` passes (it only checks that the governance bytes match the locally derived ratification, not council membership of the new node).
4. `PostInsertBlock` calls `HandleGov`, storing `{governance.governingnode: B}` in history.
5. From `(k+1)*epoch` onward, `GetParamSet(N).GoverningNode = B`.
6. `B` is not in the council → cannot propose blocks → cannot embed votes in headers → governance is permanently frozen. [7](#0-6) [8](#0-7)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList
```
