### Title
`OpenedHandler#provision?` operator-precedence bug lets `review_stacks_enabled=false` be bypassed for `allow_with_label`/`prevent_with_label` repos - (File: `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb`)

### Summary
`OpenedHandler#provision?` is written as `enabled && allow_all? || (allow_with_label? && label) || (prevent_with_label? && !label)`. Because Ruby's `&&` binds tighter than `||`, `review_stacks_enabled` is only ANDed with the `allow_all?` branch, not with the `allow_with_label?`/`prevent_with_label?` branches, so a repository configured with `provisioning_behavior=prevent_with_label` (or `allow_with_label`) will auto-provision a `ReviewStack` from a fork PR even when `review_stacks_enabled` is `false`.

### Finding Description
The intended invariant should be `provision? == review_stacks_enabled && (allow_all? || (allow_with_label? && label) || (prevent_with_label? && !label))` — i.e. review stacks must be explicitly enabled regardless of which provisioning_behavior is configured. The actual code at [1](#0-0)  parses as `(review_stacks_enabled && allow_all?) || (allow_with_label? && label) || (prevent_with_label? && !label)`, so `review_stacks_enabled` is scoped only to the first disjunct.

`respond_to_pull_request_opened?` gates `process` purely on `params.action == "opened" && provision?` [2](#0-1) , and `process` calls `ReviewStackAdapter#find_or_create!`, which creates the `ReviewStack` using attacker-controlled `params.pull_request.head.ref` as the `branch` and enqueues it via `Shipit::ReviewStackProvisioningQueue.add(stack)` [3](#0-2) . None of the referenced guards (`verify_signature`, `ExplicitParameters` schema, `User#authorized?`) check `review_stacks_enabled` — that check exists solely inside the broken `provision?` expression.

An attacker who forks a tracked repository configured with `provisioning_behavior=prevent_with_label` and `review_stacks_enabled=false` (operator's intent: review stacks disabled) can open a PR with no provisioning label. `provision?` evaluates the third disjunct `(prevent_with_label? && !label)` = `true`, independent of `review_stacks_enabled`, so a `ReviewStack` is created and queued for provisioning/deployment of the fork's branch content.

### Impact Explanation
A `ReviewStack` created from an unprivileged fork branch is provisioned and deployed by the normal Shipit task pipeline, which checks out the PR's `shipit.yml` and executes its steps via `Command`/`PTY.spawn` on the deploy host. This is the review-stack RCE class: a repository whose operator explicitly disabled review stacks (`review_stacks_enabled=false`) is still exploitable so long as `provisioning_behavior` is `allow_with_label` or `prevent_with_label`, letting any fork contributor get their commands executed on the deploy host. This is repeatable against any repository matching that configuration.

### Likelihood Explanation
Preconditions: the target repository must be tracked by Shipit and have `provisioning_behavior` set to `allow_with_label` or `prevent_with_label` (these are the two non-default behaviors an operator would pick to restrict/gate provisioning) — combined with `review_stacks_enabled=false`, which an operator could plausibly set later to fully disable review stacks without also reverting `provisioning_behavior` to `allow_all`. The attacker needs no privileges beyond opening a PR from a fork (and omitting/including a label depending on which behavior is configured). Cost is a single webhook-triggering PR; fully repeatable.

### Recommendation
Fix the boolean grouping in `provision?` so `review_stacks_enabled` gates every branch, e.g.:
```ruby
def provision?
  repository.review_stacks_enabled &&
    (repository.provisioning_behavior_allow_all? ||
     (repository.provisioning_behavior_allow_with_label? && pull_request_has_provisioning_label?) ||
     (repository.provisioning_behavior_prevent_with_label? && !pull_request_has_provisioning_label?))
end
```

### Proof of Concept
In `test/models/shipit/webhooks/handlers/pull_request/opened_handler_test.rb`:
```ruby
test "does not create stacks for prevent_with_label repos when review_stacks_enabled is false" do
  repository = shipit_repositories(:shipit)
  configure_provisioning_behavior(
    repository:,
    provisioning_enabled: false,
    behavior: :prevent_with_label,
    label: "pull-requests-label"
  )
  payload = payload_parsed(:pull_request_opened)
  payload["pull_request"]["labels"] = []

  assert_no_difference -> { Shipit::Stack.count } do
    OpenedHandler.new(payload).process
  end
end
```
Assert both sides of the intended equality: `repository.review_stacks_enabled == false` AND `OpenedHandler.new(payload).send(:provision?) == false` (expected), versus current behavior where `provision?` returns `true` and a `ReviewStack` is created/queued despite `review_stacks_enabled == false`.
