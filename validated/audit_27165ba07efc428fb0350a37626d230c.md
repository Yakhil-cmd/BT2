## Analysis

The reported Jenkins issue is a **stale/implied-permission escalation**: a permission that was explicitly disabled could still be exercised because it was reachable through a different, broader permission that implied it, and the "implication" check was not kept consistent with the actual permission set.

The exact same bug class already existed once in this codebase and was fixed: `NonTransfer` on Asset Hub Westend falsely declared itself a superset of `Governance`, letting a `NonTransfer` proxy grant itself a `Governance` proxy and reach calls its own filter denied — fixed in [1](#0-0)  with a lattice-consistency regression test added at [2](#0-1) .

The same inconsistency is still present, unfixed, in the Polkadot relay-chain runtimes for Westend and Rococo, for the `NonTransfer` → `Auction` pair and the `Registrar::swap` call that `NonTransfer` deliberately excludes.

### Title
`ProxyType::NonTransfer` falsely claims superset of `ProxyType::Auction`, allowing a `NonTransfer` proxy to reach the excluded `Registrar::swap` call — ([File: polkadot/runtime/westend/src/lib.rs], [File: polkadot/runtime/rococo/src/lib.rs])

### Summary
`pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` sub-calls purely through `InstanceFilter::is_superset`, not through `filter` [3](#0-2) . In both the Westend and Rococo relay-chain runtimes, `ProxyType::is_superset` uses a blanket rule `(ProxyType::NonTransfer, _) => true` [4](#0-3) [5](#0-4) , declaring `NonTransfer` a superset of every other `ProxyType`, including `Auction`. However `NonTransfer`'s own `filter` explicitly excludes `Registrar::swap` ("Specifically omitting Registrar `swap`") [6](#0-5) [7](#0-6) , while `Auction`'s filter admits the entire `Registrar` call family, including `swap` [8](#0-7) [9](#0-8) . Because `is_superset(NonTransfer, Auction) == true`, a `NonTransfer` proxy can grant itself an `Auction` proxy and then use it to dispatch `Registrar::swap`, exactly the permission the delegator deliberately excluded — the identical class of bug as the Jenkins advisory (a disabled/excluded permission remains reachable through an improperly-declared implying permission).

### Finding Description
Any account can grant a `NonTransfer` proxy to another account via a normal signed `Proxy::add_proxy` extrinsic — this is standard, permission-less proxy delegation, not a privileged role. The delegate then dispatches through `Proxy::proxy`, which routes the inner call through `Pallet::do_proxy`: [10](#0-9) 

For an inner call of `add_proxy{ proxy_type: Auction }`, the guard is `!def.proxy_type.is_superset(proxy_type)`. With `def.proxy_type = NonTransfer` and `proxy_type = Auction`, `NonTransfer.is_superset(&Auction)` evaluates the catch-all arm `(ProxyType::NonTransfer, _) => true`, so the guard is `false` and the match falls through to `_ => def.proxy_type.filter(c)`. `NonTransfer.filter` admits `RuntimeCall::Proxy(..)` unconditionally, so the `add_proxy{Auction}` call is dispatched — the `NonTransfer` delegate has just granted itself an `Auction` proxy on the victim's account, with no further restriction.

The delegate now dispatches `Proxy::proxy(victim, None, Registrar::swap{..})` through the freshly-created `Auction` proxy. `Auction.filter` matches the whole `Registrar` call family (`RuntimeCall::Registrar { .. }` / `RuntimeCall::Registrar(..)`), so `Registrar::swap` is admitted and dispatched with origin `Signed(victim)`.

The net effect: a delegate who was only ever granted `NonTransfer` — whose filter comment explicitly states "Specifically omitting Registrar `swap`" — can nonetheless invoke `Registrar::swap` on the victim's behalf, purely because the `is_superset` relation was declared too broadly relative to the `filter` implementation. This mirrors the already-identified and fixed instance for `Governance` on Asset Hub Westend (`prdoc/pr_12769.prdoc`, addressing paritytech/polkadot-sdk#12724), which added the exact regression test class `proxy_type_superset_relation_matches_call_filters` [11](#0-10)  — that regression test and fix were only applied to the Asset Hub Westend runtime, not to the Westend/Rococo relay-chain runtimes.

I could not fully verify the exact preconditions/effects of `paras_registrar::Pallet::swap` (e.g., manager-matching requirements) within the available index; a background session with full repository access would be needed to confirm whether `swap`'s internal checks further constrain impact for a given `Signed(victim)` origin, though the filter-bypass itself is fully confirmed from the code shown.

### Impact Explanation
`Registrar::swap` is treated by the runtime authors as sensitive enough to deliberately exclude from `NonTransfer` (unlike ordinary `register`/`deregister`/`reserve`), presumably because it can swap para-id assignments/lifecycle state associated with a parachain deposit. A delegate granted only `NonTransfer` — intended as a "safe, no value-moving" trust level — can escalate to exercise this excluded capability on the delegator's account without the delegator's consent, via a lattice inconsistency the delegator has no visibility into. This is a permission-boundary violation (integrity break of the proxy trust model), matching CWE-281 in the referenced advisory.

### Likelihood Explanation
`NonTransfer` and `Auction` proxies are ordinary, non-privileged proxy types that any account can create; no governance, sudo, or validator access is required. The escalation path is a straightforward two-step `Proxy::proxy` call sequence using only the standard `pallet_proxy` API and requires only that a victim has granted a `NonTransfer` proxy to the attacker — a very common delegation pattern (e.g., automation/custody bots). Likelihood is therefore moderate: it requires an existing `NonTransfer` delegation from a victim, but no additional trust or privilege beyond that.

### Recommendation
Apply the same fix pattern used in `prdoc/pr_12769.prdoc` for Asset Hub Westend to the Westend and Rococo relay-chain runtimes (and audit any other runtime reusing this `ProxyType::is_superset` blanket rule): either remove the generic `(ProxyType::NonTransfer, _) => true` catch-all in favor of explicit, filter-consistent pairs, or extend `NonTransfer`'s `filter` to admit everything `Auction` admits (including `Registrar::swap`) if that is actually intended. Add a lattice-consistency test analogous to `proxy_type_superset_relation_matches_call_filters` for every runtime that implements `InstanceFilter<RuntimeCall> for ProxyType`.

### Proof of Concept
No test was executed; this is a static code-path proof based on the cited source. Reproduction outline for a background Devin session (Rust/FRAME integration test against the Westend or Rococo runtime, using existing `pallet_proxy` test harness patterns as seen in `substrate/frame/proxy/src/tests.rs`):
1. Victim account `A` signs `Proxy::add_proxy(B, ProxyType::NonTransfer, 0)`.
2. `B` signs `Proxy::proxy(A, None, Box::new(Proxy::add_proxy(C, ProxyType::Auction, 0)))` — expect this to succeed (asserting `Event::ProxyExecuted { result: Ok(()) }`), which is the actual/incorrect behavior since `NonTransfer.filter` admits `RuntimeCall::Proxy(..)` and `is_superset` guard is bypassed.
3. `C` (or `B`) signs `Proxy::proxy(A, None, Box::new(Registrar::swap{ .. }))` using the newly created `Auction` proxy — expect dispatch success with origin `Signed(A)`, demonstrating that a call `NonTransfer` explicitly excludes was executed on `A`'s behalf.
4. Expected/patched behavior: step 2 should fail (`is_superset(NonTransfer, Auction)` should be `false`, or `NonTransfer.filter` should admit exactly what `Auction.filter` admits) so that step 3 is unreachable.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}

	fn do_proxy(
		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});
