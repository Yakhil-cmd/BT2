### Title
Sustained high-utilization accrual overflows the RAY value domain before the borrow-index cap engages, permanently freezing a market — every verb accrues first and panics (File: `common/src/rates/index.rs`)

### Summary
The analog to the MySQL crash/hang DoS is a reachable arithmetic-overflow panic inside interest accrual. `global_sync` runs before every pool verb (supply, borrow, withdraw, repay, liquidate, flash). On a sufficiently large book at sustained high utilization, `borrowed.mul(borrow_index)` / `supplied.mul(supply_index)` exceed the `i128` RAY-value domain and panic with `MathOverflow` before `update_borrow_index`'s `MAX_BORROW_INDEX_RAY` cap can clamp the index. From that point the market is permanently frozen: no repayment, withdrawal, or liquidation on that `(hub, asset)` book can ever execute again.

### Finding Description
- `global_sync` chunks elapsed time and calls `accrue_chunk` → `accrue_step` for every market operation [1](#0-0) .
- The value multiplications `borrowed.mul(env, new_borrow_index)` and `supplied.mul(env, old_index)` are unchecked RAY×RAY products that must fit `i128` [2](#0-1) [3](#0-2) .
- The `i128` conversion panics with `GenericError::MathOverflow` on overflow [4](#0-3) .
- The index cap only clamps the *index*, not the *value*: `update_borrow_index` returns `MAX_BORROW_INDEX_RAY` after the multiplication, but the total-debt computation `borrowed * new_index` can overflow even at indexes far below the cap when `borrowed` is large [5](#0-4) .
- The project’s own harness test reproduces this: a whale market at ~98% utilization on a steep rate curve hits the RAY-value ceiling (panic #33) before `MAX_BORROW_INDEX_RAY` engages, after which `withdraw` and `repay` both revert with `MATH_OVERFLOW` — "the market is frozen: exits and repayments accrue first and hit the same panic" [6](#0-5) .
- The docs acknowledge the bound ("Finite RAY value capacity can be exhausted before the index ceiling") but no code path prevents it; supply/borrow caps are per-market config and do not bound `shares × index` growth [7](#0-6) .

### Impact Explanation
Permanent freezing of funds and a contract unable to operate for the affected market. Once the accrual overflows, `last_timestamp` can never advance because `global_sync` panics before `mark_accrued` writes, so the panic is self-perpetuating — every subsequent `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, `flash_loan`, or `update_indexes` touching that `(hub, asset)` book reverts with `MathOverflow` forever. Suppliers lose access to all deposits in that market; borrowers cannot repay; bad debt cannot be liquidated or socialized. Because the pool is shared physical custody, a frozen book also blocks the hub-level cash that backs it. This is not a fail-closed pause or a budget/memory limit — it is an arithmetic panic reachable through ordinary unprivileged entrypoints.

### Likelihood Explanation
**Medium.** Reachability requires (a) a market with caps set high enough to admit very large scaled positions (the test lifts caps on an 18-decimal asset, e.g. `lift_caps` + `supply_raw(BOB, "BIG18", BILLION * 1e18)`), and (b) sustained high utilization on a steep curve so the index compounds into the overflow region — the harness shows the cliff is reached within ~40 simulated years at 98% utilization, sooner on steeper curves. No privileged action, oracle manipulation, or flash loan is needed: any unprivileged address contributes via `supply` and `borrow`, and any caller can trigger the fatal accrual via `update_indexes`. The cost is capital (whale-scale supply or cumulative borrows) and time, not privilege. Severity is Medium because exploitation is slow and requires extreme book size rather than a single transaction.

### Recommendation
- Bound the value product, not just the index: in `accrue_step`/`update_*_index`, detect that `borrowed * new_index` or `supplied * new_index` would overflow `i128` and clamp the index to `i128::MAX / borrowed` (respectively `/ supplied`) instead of panicking — i.e., apply a *value-domain* cap in `common/src/rates/index.rs` alongside `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY`.
- Alternatively, make `global_sync` skip (rather than panic on) an accrual step whose product saturates, leaving `last_timestamp` advanced so exits and repayments remain live.
- Enforce listing-time caps in `max_cap_for_decimals`-style validation such that `cap_scaled * MAX_BORROW_INDEX_RAY` stays within the RAY value domain, so the cliff is unreachable by construction.

### Proof of Concept
Existing harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321`:

```rust
let principal = BILLION * 10i128.pow(18);          // whale-scale 18-dec supply
t.supply_raw(BOB, "BIG18", principal);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // ~98% utilization
// advance time year-by-year; eventually:
assert_contract_error(failed, errors::MATH_OVERFLOW);            // update_indexes panics
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
// last.borrow_index < MAX_BORROW_INDEX_RAY — cap never engaged
```

Sequence on-chain: an unprivileged actor (or organic market growth) supplies a large amount of a high-decimal asset and the market sustains high utilization; once `borrowed × borrow_index` approaches `i128::MAX` (~170×10²⁷ units at index 1.7×10²⁷ scale), the next call to `update_indexes` — permissionless — permanently bricks every operation on that market.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
