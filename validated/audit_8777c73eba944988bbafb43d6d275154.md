### Title
Cross-Organization Commit-Status Forgery via Signature/Target Mismatch in Webhook Handling - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController` verifies an inbound webhook's HMAC signature using the secret belonging to the organization named in the payload's `repository.owner.login` (or `organization.login`) field, but the event handlers that actually act on the payload (in particular `StatusHandler`) never re-check that this organization matches the repository/commit they operate on. This breaks the trust binding "organization that authenticated == repository/commit that is written."

### Finding Description
`Shipit::WebhooksController#verify_signature` selects which `GitHubApp`/`webhook_secret` to validate against based on a value taken directly from the unauthenticated payload body: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` supports a documented multi-tenant configuration where distinct organizations each have their own independently-configured `webhook_secret` in `secrets.yml`: [3](#0-2) [4](#0-3) 

Once signature verification succeeds (which only proves the request was signed by *some* org's secret, chosen by an attacker-controllable field in the same unauthenticated body), the raw parsed JSON is dispatched unmodified to event handlers: [5](#0-4) 

`Shipit::Webhooks::Handlers::StatusHandler#process` looks up commits **globally by SHA only**, with no scoping to the repository or organization that was verified: [6](#0-5) 

Because the HMAC signature covers the entire raw request body (which the requester fully controls and can shape however they like, as long as they know one org's secret), an administrator/operator of Organization B — who legitimately knows Org B's own `webhook_secret` (they configured or received it for their own GitHub App installation on the shared Shipit instance) — can craft a `status` event payload where:
- `repository.owner.login` = `"org-b"` (so `verify_signature` picks Org B's secret and passes), and
- `sha` = any commit SHA belonging to a *different* organization/repository hosted on the same Shipit instance (commit SHAs are public information on GitHub).

`StatusHandler` will then create a forged commit status on that victim commit, regardless of which organization it actually belongs to, because there is no equality check between "the org whose secret verified this webhook" and "the repository/commit being written."

Other handlers (`PushHandler`, `PullRequest::*`) at least resolve the target `Stack`/`Repository` via `repository.full_name` from the same unverified payload — also not cross-checked against `repository.owner.login`/`organization.login` used for signature selection, but only `StatusHandler` has literally zero repository scoping at all: [7](#0-6) [8](#0-7) 

### Impact Explanation
Commit statuses gate Shipit's CI/merge/deploy decisions (required/blocking statuses, continuous deployment triggers documented in `README.md`'s CI configuration section). An attacker who controls a legitimately onboarded, low-privilege organization on a shared multi-tenant Shipit instance can forge a "success" status for an arbitrary commit SHA belonging to a *different, victim* organization's repository, without any GitHub-side authorization on that victim repository. This can satisfy CI requirements Shipit relies on to unlock merges or deploys of a commit the attacker does not control and never had permission to affect — an unauthorized deploy/merge impact, and unauthenticated write of stack/task-relevant state belonging to another tenant.

### Likelihood Explanation
Requires: (1) a multi-organization Shipit deployment (documented, supported configuration), (2) attacker control of one onboarded organization's own webhook secret (a routine capability for any tenant admin, not a privileged Shipit role), and (3) knowledge of a target commit SHA (trivially obtainable from a public GitHub repo, or a private repo the attacker can otherwise observe). No compromise of the victim organization or Shipit's own GitHub App credentials is required. Likelihood is realistic in any deployment supporting multiple GitHub organizations against a shared Shipit instance.

### Recommendation
After signature verification selects an organization, enforce that the same organization/repository owner is what handlers act on: validate that `payload.dig('repository','owner','login')` (used to pick the signing secret) matches `payload.dig('repository','full_name')`'s owner, and thread that verified repository/organization context into every handler instead of re-deriving it from the unauthenticated body. In particular, `StatusHandler` should scope its `Commit` lookup to `stacks`/`Repository` derived from the verified organization, not a bare `Commit.where(sha:)` across the entire instance.

### Proof of Concept
1. Deploy Shipit configured for multiple GitHub organizations (`github: org-a: {webhook_secret: SECRET_A}, org-b: {webhook_secret: SECRET_B}`), as documented in `config/secrets.development.example.yml`.
2. Attacker is the legitimate administrator of `org-b` and therefore knows `SECRET_B`.
3. Attacker learns a commit SHA `deadbeef...` belonging to `org-a`'s repository (public on GitHub, or a stack the attacker can view via Shipit's own UI as an unrelated tenant).
4. Attacker builds a `status` webhook JSON body:
   ```json
   {
     "sha": "deadbeef...",
     "state": "success",
     "context": "ci/required-check",
     "repository": { "owner": { "login": "org-b" }, "full_name": "org-b/some-repo" }
   }
   ```
5. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(SECRET_B, body)>` and POSTs to `/webhooks` with `X-Github-Event: status`.
6. `verify_signature` resolves `Shipit.github(organization: "org-b")`, verifies successfully with `SECRET_B`, and `StatusHandler#process` writes a forged "success" status onto the `org-a` commit `deadbeef...` because `Commit.where(sha: params.sha)` is not scoped to `org-b`. [9](#0-8) [10](#0-9)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
end
