### Title
`Api::CCMenuController` overrides `#stack` to bypass an `ApiClient`'s stack scope, allowing a stack-scoped token to read status data for any stack - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Api::BaseController#stack` is the mechanism that binds "the stack(s) a token authorizes" to "the stack a request may touch": it resolves `params[:stack_id]` only from `stacks`, which is filtered down to `current_api_client.stack_id` when the client is scoped. [1](#0-0)  `Api::CCMenuController` re-implements `#stack` to instead call `Stack.from_param!(params[:stack_id])` directly on the unscoped `Stack` model, dropping the scoping check entirely. [2](#0-1)  This breaks the binding "stack a token authorizes == stack the request touches," analogous to the report's "adapter accepts a strategy pointer without validating it belongs to the intended trust boundary."

### Finding Description
`ApiClient` records can be scoped to a single `stack_id`, and permission checks are permission-string based only (`read:stack`, etc.), not stack-identity based - the actual stack restriction is enforced solely by the `stacks` scoping helper in `BaseController`. [3](#0-2) [1](#0-0) 

`CCMenuController` requires only the generic `read:stack` permission (not tied to a specific stack) and then overrides `#stack` to resolve the stack directly via `Stack.from_param!`, which queries `Stack.all` rather than the caller's authorized `stacks` scope. [4](#0-3) 

Before the fix (i.e., current state): an `ApiClient` created with `stack: shipit` and only `read:stack` permission — intended to see status information for that one stack only — can pass a different `stack_id` in the request to `Api::CCMenuController#show` and receive full CCMenu status/build data (`lastBuildStatus`, `lastBuildLabel`, `activity`, `webUrl`, etc.) for a stack it was never scoped to. [5](#0-4)  This is confirmed by the test suite itself, which demonstrates a scoped client (`here_come_the_walrus`, scoped to `:shipit`) is expected to only see that stack elsewhere in the API (e.g. `stacks_controller_test.rb`), but `ccmenu_controller_test.rb` never exercises the cross-stack case, and the controller code path clearly bypasses the `stacks` helper used everywhere else. [6](#0-5)  Compare to `Api::StacksController`, which inherits the correctly-scoped `stack`/`stacks` helpers and enforces per-stack authorization as intended. [7](#0-6) 

The root cause: `stack_id?`/`stack_id` scoping is a property of the `ApiClient`, enforced in exactly one place (`BaseController#stacks`), and `CCMenuController` re-implements the stack lookup without reusing that scoping logic.

### Impact Explanation
An attacker holding (or leaking) a low-privilege, stack-scoped API token — e.g., one meant only to expose CI-badge/build-status information for a single non-sensitive stack — can read deploy/build status metadata (`lastBuildStatus`, `lastBuildLabel`, `activity`, `webUrl`, deploy timestamps) for every other stack in the Shipit instance, including stacks they have no authorization for. This is an unauthenticated-scope-escalation / unauthorized read of stack state, matching the "High: escalation into authorization scoping, unauthenticated read of stack state" impact category, since the token's authorized scope (one stack) no longer matches the stack actually touched by the request.

### Likelihood Explanation
Likelihood is high for anyone who already possesses any valid, stack-scoped `ApiClient` token (a legitimate but low-privilege credential, e.g. one handed to a CI dashboard integration) since exploitation requires only substituting the `stack_id` request parameter — no additional secrets, signatures, or privileged access are needed beyond having any working token scoped to any single stack.

### Recommendation
Have `Api::CCMenuController#stack` reuse the inherited, scope-aware `stacks` helper (i.e., `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so a stack-scoped `ApiClient` cannot resolve stacks outside its authorized `stack_id`.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack: shipit` with permission `read:stack` only (mirrors fixture `here_come_the_walrus`). [8](#0-7) 
2. Authenticate as that client and request `GET /api/ccmenu/<other_stack_id>.xml` (or the equivalent CCMenu route) with `stack_id` set to a stack the client is not scoped to.
3. `authenticate_api_client` succeeds via `ApiClient.authenticate(params[:token])` or Basic Auth. [9](#0-8) 
4. `#show` calls `stack`, which resolves via `Stack.from_param!(params[:stack_id])` — bypassing the `current_api_client.stack_id` restriction — and returns full build/deploy status XML for the unauthorized stack. [10](#0-9)

# frozen_string_literal: true

module Shipit
  class ApiClient < Record
    InsufficientPermission = Class.new(StandardError)

    belongs_to :creator, class_name: 'User'
    belongs_to :stack, optional: true

    validates :creator, :name, presence: true

    serialize :permissions, coder: Shipit.serialized_column(:permissions, type: Array)
    PERMISSIONS = %w[
      read:stack
      write:stack
      deploy:stack
      lock:stack
      read:hook
      write:hook
    ].freeze
    validates :permissions, subset: { of: PERMISSIONS }

    class << self
      def authenticate(token)
        find_by(id: message_verifier.verify(token).to_i)
      rescue Shipit::SimpleMessageVerifier::InvalidSignature
      end

      def message_verifier
        @message_verifier ||= Shipit::SimpleMessageVerifier.new(Shipit.api_clients_secret)
      end
    end

    def authentication_token
      self.class.message_verifier.generate(id)
    end

    def check_permissions!(operation, scope)
      required_permission = "#{operation}:#{scope}"
      unless permissions.include?(required_permission)
        raise InsufficientPermission, "This operation requires the `#{required_permission}` permission"
      end

      true
    end
  end

module Shipit
  module Api
    class StacksController < BaseController
      require_permission :read, :stack, only: %i[index show]
      require_permission :write, :stack, only: %i[create update destroy]

        accepts :repo_owner, String
        accepts :repo_name, String

      def index
        @stacks = stacks
        if params[:repo_owner] && params[:repo_name]
          full_repo_name = [repo_owner, repo_name].join('/')
          @stacks = if (repository = Repository.from_github_repo_name(full_repo_name))
                      stacks.where(repository:)
                    else
                      Stack.none
                    end
        end
        render_resources(@stacks)
      end
