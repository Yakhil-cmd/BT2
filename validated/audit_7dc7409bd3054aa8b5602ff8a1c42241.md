### Title
Membership webhook handler grants team membership without verifying the signing organization owns the target team - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates a webhook only against the `webhook_secret` configured for the organization named in the payload, and `GitHubApp#verify_webhook_signature` treats a blank `webhook_secret` as verified (`return true unless webhook_secret`). `MembershipHandler#find_or_create_team!` looks up the `Team` purely by `github_id` and never checks that `params.organization.login` matches the team's stored `organization`, so a webhook "verified" for one organization can mutate a `Team`/`Membership` that belongs to a different organization.

### Finding Description
The binding that must hold is: `organization whose webhook_secret verified this payload (repository_owner from app/controllers/shipit/webhooks_controller.rb:59-61 and lib/shipit.rb:170-181) == organization that owns the github_id being mutated (Team#organization, set once in app/models/shipit/webhooks/handlers/membership_handler.rb:38-42)`.

Tracing the code:
- `verify_signature` resolves `github_app = Shipit.github(organization: repository_owner)` [1](#0-0) , where `repository_owner` is taken directly from attacker-controlled payload fields (`repository.owner.login` or `organization.login`) [2](#0-1) .
- `Shipit.github` resolves that organization's config from `secrets.github` and only raises `GithubOrganizationUnknown` if the name isn't a configured key; otherwise it returns a `GitHubApp` for whatever config exists for that key [3](#0-2) .
- `GitHubApp#verify_webhook_signature` short-circuits to `true` whenever that organization's `webhook_secret` is blank [4](#0-3) . `docs/setup.md` documents `webhook_secret` as "(optional)" [5](#0-4) , and `test/dummy/config/secrets_double_github_app.yml` shows a real multi-organization config where one org (`OrgTwo`) intentionally has `webhook_secret: # nil` [6](#0-5) , confirming multi-tenant deployments with a blank secret are a first-class supported configuration, not a hypothetical misconfiguration.
- Once signature verification passes (trivially, since the secret is blank), `WebhooksController#create` dispatches to `MembershipHandler.call(params)` [7](#0-6) .
- `MembershipHandler#find_or_create_team!` does `Team.find_or_create_by!(github_id: params.team.id)`, only setting `team.organization = params.organization.login` inside the `create` block, i.e. only on first creation. For any team that already exists (which is exactly the case for teams listed in `Shipit.github_teams`, since they're pre-created via `Shipit.github_teams`/`teams:fetch`), the lookup matches solely by `github_id` and never re-checks or re-validates `params.organization.login` against the team's real `organization` [8](#0-7) .
- `process` then unconditionally calls `team.add_member(User.find_or_create_by_login!(params.member.login))` for `action == 'added'` [9](#0-8) , creating a `Membership` row with no relation to the organization that actually authenticated the request.

Exploit flow: attacker sends `POST /webhooks` with `X-Github-Event: membership`, `organization.login` set to any org configured in Shipit whose `webhook_secret` is blank (this can be a legitimately onboarded but low-trust tenant org in a multi-org Shipit deployment, or simply any org string that happens to map to a blank-secret config entry), `team.id` set to the `github_id` of a `Shipit.github_teams` team belonging to a completely different organization, and `member.login` equal to the attacker's own GitHub login. `verify_signature` passes because that org's secret is blank; `MembershipHandler` finds the victim `Team` by `github_id` alone and adds the attacker as a member, ignoring that the request was "verified" for an unrelated organization.

Existing guards do not catch this: `drop_unhandled_event` only checks the event type is registered; `ExplicitParameters` schema only validates shapes/types, not cross-field organizational consistency; there is no `require_permission!`/session check on this unauthenticated endpoint by design; and `Team.find_or_create_by!` performs no post-lookup validation that `params.organization.login == team.organization`.

### Impact Explanation
Once a `Membership` row exists linking the attacker's `User` to a team present in `Shipit.github_teams`, `User#authorized?` becomes `true` (`teams.where(id: Shipit.github_teams.map(&:id)).exists?`) [10](#0-9) , granting the attacker authorization equivalent to a legitimate member of a privileged GitHub team, without ever needing that team's or that organization's real webhook secret. This is a High-severity escalation into `Shipit.github_teams` authorization as defined in the rules, and is repeatable against any team whose `github_id` the attacker can learn (team IDs/slugs are often discoverable via public GitHub API or via a prior legitimate webhook), across tenant boundaries in any multi-organization Shipit deployment.

### Likelihood Explanation
The precondition is that at least one organization configured in Shipit's multi-org `secrets.github` has a blank `webhook_secret` — an explicitly documented, optional, supported configuration state (see `docs/setup.md` and the `test/dummy/config/secrets_double_github_app.yml` fixture, which models exactly this: one org with a secret, one without). Given that precondition, the attacker's cost is a single unauthenticated HTTP POST with a fully-crafted JSON body; no GitHub-side action, no compromised secrets, and no privileged Shipit role are required. The attack is fully repeatable and scriptable against any `Shipit.github_teams` entry whose `github_id` is known.

### Recommendation
In `MembershipHandler#find_or_create_team!`, validate that `params.organization.login` matches the existing `Team#organization` before mutating membership, and reject/no-op the event if they diverge. More fundamentally, `GitHubApp#verify_webhook_signature` should not silently accept unsigned payloads (`return true unless webhook_secret`); require a `webhook_secret` to be configured for every organization, or fail closed if none is present.

### Proof of Concept
Minitest plan (integration/controller test, no live GitHub):
1. Configure two orgs via `secrets.github` fixture (as in `secrets_double_github_app.yml`): `OrgOne` with a real `webhook_secret`, `OrgTwo` with a blank `webhook_secret`.
2. Create `shipit_teams(:victim_team)` with `organization: 'OrgOne'`, `github_id: 555`, and add it to `Shipit.github_teams` (stub `Shipit.github_teams` to include it).
3. `post :create` with headers `X-Github-Event: membership`, no `X-Hub-Signature`, body:
   `{ action: 'added', team: { id: 555, name: 'Victim', slug: 'victim', url: '...' }, organization: { login: 'OrgTwo' }, member: { login: 'attacker' }, repository: { owner: { login: 'OrgTwo' } } }`.
4. Assert `response.status == 200` (verification passed because `OrgTwo`'s secret is blank).
5. Assert `Membership.exists?(user: User.find_by(login: 'attacker'), team_id: victim_team.id)` is `true`.
6. Assert `User.find_by(login: 'attacker').authorized?` is `true`.
7. Both assertions passing demonstrates the broken binding: the organization that verified the webhook (`OrgTwo`) differs from the organization owning the mutated team's `github_id` (`OrgOne`).

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)

    end
```
