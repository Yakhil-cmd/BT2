### Title
`ProxyType::NonTransfer` proxy can escalate to `Auction`/`ParaRegistration` sub-proxies and dispatch `Registrar::swap`, a call its own filter explicitly denies - ([File: polkadot/runtime/westend/src/lib.rs])

### Summary
On the Westend (and equivalently Rococo / staking-async `rc`) relay-chain runtime, `ProxyType::is_superset` unconditionally declares `NonTransfer` a superset of *every other* proxy type, while `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `is_superset` alone (not through `filter`). `NonTransfer`'s own `filter` explicitly *excludes* `Registrar::swap` ("Specifically omitting Registrar `swap`"), but `ProxyType::Auction`'s filter admits the entire, unrestricted `RuntimeCall::Registrar(..)` family, including `swap`. Because `is_superset` says `NonTransfer` is a superset of `Auction`, a delegate holding only a `NonTransfer` proxy can create/self-grant an `Auction` (or other) sub-proxy for the delegator and thereby dispatch `Registrar::swap` on the delegator's behalf — a privileged action the delegator's chosen `NonTransfer` policy was designed to deny. This is the exact analog of the Opencast bug class: a lower-privileged role is able to mint itself broader credentials because the "is this role a superset" check does not match the actual permitted-call set.

### Finding Description
`pallet_proxy::do_proxy` gates nested `add_proxy`/`remove_proxy` calls solely via `is_superset`, not `filter`: [1](#0-0) 

The Westend relay-chain `ProxyType` filter explicitly omits `Registrar::swap` from `NonTransfer`'s allowed calls, while admitting the rest of the `Registrar` pallet's non-swap calls and other pallets: [2](#0-1) 

Yet `ProxyType::Auction` grants the *entire, unrestricted* `Registrar` call family (which includes `swap`), and `is_superset` unconditionally treats `NonTransfer` as a superset of every other type, including `Auction`: [3](#0-2) 

The identical pattern (`NonTransfer` catch-all superset + unrestricted `Auction` filter over `Registrar(..)`) also exists in `substrate/frame/staking-async/runtimes/rc/src/lib.rs`: [4](#0-3) 

`Registrar::swap` is authorized by `ensure_root_para_or_owner`, i.e. it succeeds when the dispatch origin is the para's registered manager account — exactly the kind of account real users delegate to proxies for convenience: [5](#0-4) 

This is precisely the same bug class the Opencast advisory describes and the same class that was already found and fixed once in this codebase — for the `NonTransfer`/`Governance` pair on Asset Hub Westend (PR 12769, with a regression test proving the fix and a lattice-wide test to prevent recurrence): [6](#0-5) [7](#0-6) 

However, that fix and its lattice test only cover the Asset Hub Westend runtime's `ProxyType`. The relay-chain runtimes (`polkadot/runtime/westend`, and the staking-async `rc` runtime that mirrors it) retain the unconditional `(ProxyType::NonTransfer, _) => true` catch-all, so the same class of "declared superset does not admit everything the subset admits" bug is still present there for the `Auction` (and `SudoBalances`) pairs.

### Impact Explanation
A user who grants a third party a `NonTransfer` proxy — intending to withhold, among other things, the ability to call `Registrar::swap` on the "specifically omitting" list — can have that trust abused: the delegate adds itself (or an accomplice) an `Auction` proxy for the delegator via `add_proxy`, then uses that new proxy to call `Registrar::swap` as the delegator. If the delegator is a registered para manager, this lets the attacker initiate (and, in collusion with an owner of another para, finalize) a swap of the delegator's parachain/parathread slot — an unauthorized dispatch of a privileged, deposit/lease-bearing action that the delegator's proxy policy explicitly forbade. This is an authorization/integrity break (CWE-285, matching the Opencast CWE), potentially leading to loss of a valuable parachain lease slot.

### Likelihood Explanation
Requires only a normal, unprivileged `NonTransfer` proxy relationship (a common, non-privileged delegation many users set up) and no governance, root, or validator/collator control. The only additional step needed to fully realize loss is cooperation from (or control of) the owner of a second para for the confirming `swap` call, which is an ordinary user action, not a privileged one. The unauthorized `add_proxy`/`Registrar::swap` initiation itself succeeds unconditionally and immediately, regardless of the second step.

### Recommendation
Fix `ProxyType::is_superset` in `polkadot/runtime/westend/src/lib.rs` (and the equivalent in `substrate/frame/staking-async/runtimes/rc/src/lib.rs`, and audit `polkadot/runtime/rococo/src/lib.rs`) the same way PR 12769 fixed the `Governance` case: remove the blanket `(ProxyType::NonTransfer, _) => true` and instead only declare `NonTransfer` a superset of proxy types whose entire `filter` call-set is provably contained in `NonTransfer`'s own filter (as is already true for `ParaRegistration`, but not for `Auction` or `SudoBalances`). Add a lattice-wide regression test (mirroring `proxy_type_superset_relation_matches_call_filters`) to the relay-chain runtime test suites to catch future recurrences of this class across all `ProxyType` pairs.

### Proof of Concept
Not executed against a live network. Conceptual reproduction path, fully derivable from the cited code with no privileged prerequisites:
1. Alice (a registered para manager, `Paras::<T>::get(id).manager == Alice`) calls `Proxy::add_proxy(Alice, Bob, ProxyType::NonTransfer, 0)` — a normal, low-privilege delegation.
2. Bob calls `Proxy::proxy(Bob, Alice, None, Proxy::add_proxy(Bob_or_Carol, ProxyType::Auction, 0))`. `do_proxy` checks `def.proxy_type.is_superset(&Auction)` where `def.proxy_type == NonTransfer`; per the cited `is_superset` catch-all this returns `true`, so the nested `add_proxy` succeeds even though `NonTransfer`'s own `filter` denies `RuntimeCall::Proxy(add_proxy{ proxy_type: Auction, .. })`… no — actually the filter for `add_proxy`/`remove_proxy` calls is bypassed entirely by the dedicated match arm in `do_proxy` (lines 1005-1013), which checks only `is_superset`, not `filter`. The call succeeds.
3. Bob (or Carol, now an `Auction` proxy for Alice) calls `Proxy::proxy(delegate, Alice, None, RuntimeCall::Registrar(paras_registrar::Call::swap{ id: Alice's_para, other: attacker_para }))`. `ProxyType::Auction::filter` admits unrestricted `RuntimeCall::Registrar(..)`, so this passes, and dispatches `Registrar::swap` with origin `Signed(Alice)`, satisfying `ensure_root_para_or_owner` since Alice is the manager.
4. This is an action `ProxyType::NonTransfer::filter` explicitly denies ("Specifically omitting Registrar `swap`"), executed anyway due to the broken `is_superset` relation — mirroring the already-fixed `NonTransfer`/`Governance` bug (PR 12769) but on a different, still-unpatched runtime and proxy-type pair.

I did not run this against a test harness; the reasoning is derived directly from reading `substrate/frame/proxy/src/lib.rs::do_proxy`, `polkadot/runtime/westend/src/lib.rs::ProxyType::{filter,is_superset}`, and `polkadot/runtime/common/src/paras_registrar/mod.rs::swap`/`ensure_root_para_or_owner`, all cited above. A background Devin session with a Rust toolchain would be needed to write and execute a concrete `#[test]` (analogous to the existing `non_transfer_proxy_is_not_a_superset_of_governance` / `proxy_type_superset_relation_matches_call_filters` tests already present for Asset Hub Westend) against the relay-chain runtime to obtain pass/fail execution evidence.

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
