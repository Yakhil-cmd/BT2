## Title
`collect_creator_fee` and `collect_creator_fee_permissionless` bypass the pool's `status` pause flag, allowing fund transfers out of paused pool vaults - (File: `programs/cp-swap/src/instructions/collect_creator_fee.rs`, `programs/cp-swap/src/instructions/collect_creator_fee_permissionless.rs`)

### Summary
The `PoolState.status` bitmask is the analog of the referenced report's `marketsPaused`/`globalPause` mechanism: it is meant to let an admin halt state-changing/fund-moving flows on a pool via `update_pool_status`. However, only `deposit`, `withdraw`, `swap_base_input`, and `swap_base_output` check `get_status_by_bit`, while `collect_creator_fee` and `collect_creator_fee_permissionless` — which transfer tokens out of the pool's vaults — perform no status check at all.

### Finding Description
`PoolState` stores a `status: u8` bitmask with three bits defined in `PoolStatusBitIndex`: `Deposit`, `Withdraw`, `Swap` [1](#0-0) , and admins can flip it via `update_pool_status` [2](#0-1) .

`deposit`, `withdraw`, and both swap instructions all gate execution on `pool_state.get_status_by_bit(...)`, e.g. in `deposit`: [3](#0-2) 
and in `swap_base_output`: [4](#0-3) 

A repo-wide search confirms `get_status_by_bit`/`PoolStatusBitIndex` are referenced only in `pool.rs`, `deposit.rs`, `swap_base_input.rs`, `swap_base_output.rs`, and `withdraw.rs` — never in `collect_creator_fee.rs` or `collect_creator_fee_permissionless.rs`.

`collect_creator_fee` transfers `creator_fees_token_0`/`creator_fees_token_1` straight out of `token_0_vault`/`token_1_vault` to the creator's ATAs with no pause check whatsoever: [5](#0-4) 

`collect_creator_fee_permissionless` does the identical vault-draining transfer, and is callable by *any* signer (`payer`) — it is not even restricted to the creator, only the destination account is constrained to the recorded `pool_creator`: [6](#0-5) [7](#0-6) 

Both are exposed as public entrypoints in `lib.rs` with no additional guard: [8](#0-7) 

### Impact Explanation
If an admin sets `status` to disable deposit/withdraw/swap for a compromised or otherwise problematic pool (e.g., during incident response to an ongoing exploit or accounting bug affecting vault balances), `collect_creator_fee_permissionless` remains fully callable by anyone and still moves real tokens out of `token_0_vault`/`token_1_vault`. This is exactly the class of "unguarded fund-moving flow during pause" described in the referenced report: the pause mechanism cannot fully halt vault outflows, undermining the ability to freeze/recover pool state, and can worsen insolvency for a pool that is already unhealthy (fewer funds remain to back LP positions/protocol fees once operators try to intervene).

### Likelihood Explanation
The precondition (non-zero `creator_fees_token_0`/`creator_fees_token_1`, which accrue naturally from ordinary swaps when `enable_creator_fee` is set) is common, and the permissionless variant requires no privileged signer or special conditions — any account can submit the transaction at any time, including immediately after an admin pause, since no status check exists to block it.

### Recommendation
Add an explicit pause check (a dedicated `PoolStatusBitIndex` bit, or reuse `Withdraw`) in both `collect_creator_fee` and `collect_creator_fee_permissionless` before performing the vault-to-user transfers, mirroring the `get_status_by_bit` guard already present in `deposit`, `withdraw`, and the swap instructions. Audit all other instructions that move vault funds or mutate `PoolState` for the same gap.

### Proof of Concept
1. Admin calls `update_pool_status(pool_state, status=7)` to disable deposit/withdraw/swap on a pool [9](#0-8) .
2. Pool already has accrued `creator_fees_token_0`/`creator_fees_token_1` > 0 from prior swaps.
3. Any account submits `collect_creator_fee_permissionless` with `pool_state`, vaults, and (init-if-needed) creator ATAs as accounts.
4. The instruction executes unconditionally, transferring the accumulated creator fee amounts out of `token_0_vault`/`token_1_vault` [10](#0-9) , despite the pool being fully "paused".

```rust
pub fn update_pool_status(ctx: Context<UpdatePoolStatus>, status: u8) -> Result<()> {
    require_gte!(255, status);
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    pool_state.set_status(status);
    pool_state.recent_epoch = Clock::get()?.epoch;
    Ok(())
}
```

```rust
pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
```
