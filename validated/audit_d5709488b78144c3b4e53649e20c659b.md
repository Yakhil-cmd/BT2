### Title
Webhook signature verification keyed by `repository.owner.login` while PR mutation is keyed by `repository.full_name`, allowing cross-tenant PR title/body injection - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/edited_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the `GithubApp`/webhook secret to check against based on `repository.owner.login` in the JSON payload, but `Webhooks::Handlers::PullRequest::EditedHandler` (and its sibling handlers) resolve and mutate the actual `Repository`/`PullRequest` row using the independent `repository.full_name` field. Because these two fields are never cross-validated, an attacker can pick an organization with no `webhook_secret` for the "verifying" field while pointing the "acted upon" field at a different, secret-protected victim repository.

### Finding Description
The broken binding: the question claims `repository_owner (used to verify signature) == repository that gets mutated`. In this codebase that equality does **not** hold as an enforced invariant:

- `verify_signature` computes `repository_owner` as `params.dig('repository','owner','login') || params.dig('organization','login')` and does `Shipit.github(organization: repository_owner).verify_webhook_signature(...)`. [1](#0-0) [2](#0-1) 
- `GithubApp#verify_webhook_signature` short-circuits to `true` whenever no `webhook_secret` is configured for that organization: `return true unless webhook_secret`. [3](#0-2) 
- `EditedHandler#repository` resolves the repository from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`, and `#pull_request` looks up the `PullRequest` row scoped to that repository's `id`, then overwrites its `title`/`body`/etc via `pull_request.update(github_pull_request: params.pull_request)`. [4](#0-3) 
- `Repository.from_github_repo_name` simply splits `owner/name` out of the `full_name` string and does a DB lookup — it has no relationship to, or cross-check against, the top-level `repository.owner.login` field used by the controller. [5](#0-4) 
- `PullRequest#github_pull_request=` writes `title`, `state`, `additions`, `deletions`, etc. directly from the incoming payload with no sanitization. [6](#0-5) 

Exploit flow: attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request` and a body where `repository.owner.login = "no-secret-org"` (an org configured in Shipit with no `webhook_secret`) but `repository.full_name = "victim-org/victim-repo"` (a repo actually tracked by Shipit whose owning org does have a configured `webhook_secret`), `action: "edited"`, and `pull_request.title`/`pull_request.body` set to attacker-chosen strings. `verify_signature` looks up the GitHub App for `"no-secret-org"`, finds no secret, and returns `true` unconditionally — the request passes regardless of the `X-Hub-Signature` header content, which the attacker does not need to forge correctly. `EditedHandler` then ignores `repository.owner.login` entirely and instead resolves the target repository/PR using `repository.full_name = "victim-org/victim-repo"`, updating that PR row with the attacker's title/body.

None of the listed guards close this gap: `drop_unhandled_event` only filters by event type; the `ExplicitParameters` schema in `EditedHandler` only validates types/presence of fields, not cross-field consistency between `repository.owner.login` and `repository.full_name`; there is no `force_github_authentication`, `require_permission!`, or model validation anywhere in this path that checks the owner segment of `full_name` matches the `owner.login` value used for signature verification.

### Impact Explanation
The attacker achieves an unauthorized cross-tenant database write: a payload "authenticated" (trivially, due to `no-secret-org` having no secret) is used to overwrite `victim-org/victim-repo`'s `PullRequest#title`/`body` with attacker-chosen content, without ever satisfying `victim-org`'s actual `webhook_secret`. This matches the listed Critical category "a payload for one repository mutating another's stack, commit, task or team." If `victim-org`'s deploy pipeline later renders that PR's `title`/`body` into a shell-interpolated `Command` (a downstream trust assumption outside this engine, per the scenario), the injected content could reach `Command#start` unescaped, enabling RCE on the deploy host — but that hinges on unverified user-supplied deploy tooling code and could not be traced to a concrete `Command#start` call site within this engine, so that portion remains a real but unconfirmed possibility, not a proven RCE path in-repo. The confirmed, in-scope, repeatable impact is the cross-tenant DB write itself, exploitable against any repository whose org has a webhook_secret configured, as long as at least one other configured org in the same Shipit instance has no `webhook_secret`.

### Likelihood Explanation
Preconditions: (1) Shipit must have at least one organization configured with no `webhook_secret` (`no-secret-org`) reachable via `Shipit.github(organization: ...)`, and (2) the target `victim-org/victim-repo` must already be a tracked `Repository`/`Stack` in Shipit with an open PR matching `params.number`. The attacker needs no session, token, or secret — only the ability to send an arbitrary HTTP POST to `/webhooks` with a crafted JSON body and the correct `X-Github-Event` header, both of which are explicitly listed as available to an unprivileged attacker. This is fully repeatable against any repository whenever a no-secret org exists in the same deployment, making the attack cost very low and highly repeatable.

### Recommendation
Cross-validate that the repository/organization used to select the webhook secret is the same one being mutated: derive `repository_owner` for signature verification from the same `repository.full_name` field the handlers use (or vice versa), and reject the request if `repository.owner.login` does not match the owner segment of `repository.full_name`. Additionally, consider requiring that every configured GitHub organization have a non-blank `webhook_secret` in production, since `verify_webhook_signature`'s `return true unless webhook_secret` fallback allows any org without a secret to authenticate arbitrary payloads for itself.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "edited handler mutates victim repo PR using a no-secret org's verified webhook" do
  victim_pr = shipit_pull_requests(:review_stack_review) # belongs to an org WITH webhook_secret configured
  Shipit.stubs(:github).with(organization: 'no-secret-org').returns(
    stub(verify_webhook_signature: true)
  )

  attacker_payload = {
    action: 'edited',
    number: victim_pr.number,
    pull_request: {
      id: victim_pr.github_id, number: victim_pr.number, url: victim_pr.api_url,
      title: '`; rm -rf /`', body: '$(cat /etc/passwd)', state: 'open',
      additions: 0, deletions: 0,
      head: { sha: victim_pr.head.sha, ref: 'attacker-branch' },
      user: { login: 'attacker' }, assignees: [], labels: []
    },
    repository: { owner: { login: 'no-secret-org' }, full_name: victim_pr.stack.repository.full_name },
    sender: { login: 'attacker' }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = 'sha1=deadbeef' # arbitrary / unforged

  post :create, body: attacker_payload, as: :json

  assert_response :ok
  # Binding under test: verifying org ('no-secret-org') != PR-owning org (victim org)
  assert_equal '`; rm -rf /`', victim_pr.reload.title
end
```
Assertions to make on both sides of the binding: (a) `repository_owner` resolved by the controller equals `'no-secret-org'` (attacker-chosen, unprotected), while (b) the `Repository` actually mutated (`victim_pr.stack.repository.full_name`) belongs to a distinct, secret-protected org — showing the two are not required to match, and the PR row is overwritten regardless.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
