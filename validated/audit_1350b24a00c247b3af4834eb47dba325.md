### Title
Unbounded debt valuation overflow permanently freezes a pool market - (File: common/src/rates/simulate.rs)

### Summary

A very large borrowed position can cause `borrowed * borrow_index` to exceed `i128` before the borrow-index cap is reached, making every subsequent market operation fail during interest accrual. [1](#0-0) 

### Finding Description

`Controller::update_indexes` is permissionless and forwards the selected `HubAssetKey` values to the pool. [2](#0-1) 

The pool accrues each requested market by loading its cache and calling `interest::global_sync`. [3](#0-2) 

`global_sync` repeatedly calls `accrue_step` for each elapsed chunk. [4](#0-3) 

The first operation in `accrue_step` converts aggregate scaled debt back to an unscaled RAY amount through `scaled_to_original`, which multiplies scaled debt by the current borrow index. [1](#0-0) 

`scaled_to_original` uses `Ray::mul`, so a mathematically valid product whose result does not fit `i128` raises `MathOverflow` rather than clamping the valuation or bounding the stored debt/index pair. [5](#0-4) 

The borrow-index cap is applied only after calculating the next index and does not bound the pre-existing aggregate debt valuation consumed at the start of the next accrual. [6](#0-5) 

The project’s directed test demonstrates that a whale-scale, high-utilization market reaches this value ceiling while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`, after which repayment and withdrawal both revert with `MathOverflow`. [7](#0-6) 

### Impact Explanation

Once the aggregate scaled-debt valuation crosses the `i128` result domain, the market enters a persistent failure state because accrual is required before normal mutations. [4](#0-3) 

Depositors cannot withdraw, borrowers cannot repay, and liquidators cannot process the affected debt, so user funds and the market’s repayment path are frozen unless governance can intervene through a recovery or upgrade path. [8](#0-7) 

The administrative `update_params` path is not a reliable repair because it also accrues the market before replacing its rate model. [9](#0-8) 

### Likelihood Explanation

Triggering this condition requires an extremely large debt share base and sustained high utilization long enough for the borrow index to multiply that base past `i128`, making it a whale-scale long-horizon condition rather than an inexpensive instant attack. [10](#0-9) 

No privileged call is required at the trigger point: an attacker controlling enough assets can create one account supplying the borrowable asset, create a second account supplying collateral, borrow most of the market, and later call `update_indexes` publicly. [11](#0-10) 

### Recommendation

Add an explicit invariant and pre-accrual bound for `scaled_borrowed * borrow_index`, and reject market configurations, caps, deposits, or borrow amounts that can exceed the representable aggregate valuation before the index ceiling. [12](#0-11) 

For robustness, represent aggregate debt valuation in an `I256`-aware path or derive the maximum permitted scaled debt from `i128::MAX / borrow_index` before each accrual, rather than allowing the value calculation itself to panic. [13](#0-12) 

Add a regression test that verifies a market approaching the bound is rejected before entering the unrecoverable state and that withdraw, repay, liquidation, and `update_indexes` remain executable at the maximum accepted state. [14](#0-13) 

### Proof of Concept

1. Using one unprivileged caller, call `Controller::supply(caller, 0, spoke_id, [(borrow_asset, principal)])` to create a funding account and supply an extremely large amount of the target asset. [15](#0-14) 
2. Call `Controller::supply(caller, 0, spoke_id, [(collateral_asset, collateral)])` to create a second account controlled by the same caller, then call `Controller::borrow(caller, borrower_id, [(borrow_asset, debt)], None)` at sustained high utilization. [16](#0-15) 
3. Advance ledger time while utilization remains high; the existing directed test performs this sequence with a billion-unit, 18-decimal market and approximately 98% utilization. [17](#0-16) 
4. Call `Controller::update_indexes(caller, [borrow_asset])`; the call reaches `accrue_step`, where `scaled_to_original(borrowed, borrow_index)` overflows before the borrow-index cap can protect the market. [13](#0-12) 
5. Observe that the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, while `withdraw` and `repay` subsequently fail with `MathOverflow`, matching the repository’s regression scenario. [7](#0-6)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// capped at `MAX_BORROW_INDEX_RAY`.
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
