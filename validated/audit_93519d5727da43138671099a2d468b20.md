### Title
Webhook signature verification is keyed on `repository.owner.login` while every handler acts on the independent `repository.full_name` field, breaking the org-authenticated ↔ repo-written binding - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate the request against using `repository_owner`, a value pulled straight out of the untrusted JSON body (`params.dig('repository','owner','login')` or `params.dig('organization','login')`), before any signature has been checked. [1](#0-0)  Every handler, however, resolves the repository/stack to act on using a *different* field of the same payload, `repository.full_name`, via `Handler#repository_name`/`#stacks`. [2](#0-1)  In a multi-organization deployment (`Shipit.github(organization:)` looks up a per-org config, each with its own optional `webhook_secret`), nothing ties the organization whose secret validated the signature to the `repository.full_name` that is actually looked up and mutated. [3](#0-2) 

### Finding Description
`verify_webhook_signature` is a no-op when `webhook_secret` is blank for the resolved organization: `return true unless webhook_secret`. [4](#0-3)  The organization used to decide *which* secret (or lack thereof) applies is taken from `repository_owner`, itself read out of the same unauthenticated request body that is being validated:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [5](#0-4) 

Once `head(422)` is *not* triggered, `create` re-parses the same raw body and dispatches it to handlers keyed only by `X-Github-Event`:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [6](#0-5) 

Every built-in handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, the `PullRequest::*` handlers) resolves its target purely from `repository.full_name`:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [2](#0-1) 

This is exactly the class of bug described in the external report: the code checks an authenticator on **one** field (`permitSingle`/nonce in the original report; here, `repository.owner.login` used to select the signing secret) but then acts on a **different** field that was never re-validated against that authenticator (`order.inAmount`/fee split in the original; here, `repository.full_name` used to pick the Stack). The equality the code implicitly assumes — `organization that authenticated == organization owning the repository that gets written` — is never enforced. If any organization configured in `Shipit.secrets.github` has no `webhook_secret` set (an explicitly supported, documented configuration state, see `docs/setup.md`: "If you've set a webhook secret..."), an unauthenticated caller can send `{"repository": {"owner": {"login": "<org-without-secret>"}, "full_name": "<victim-org>/<victim-repo>"}, ...}` and have it processed as if it came from GitHub for the victim repository, because the signature check short-circuits to `true` for the attacker-chosen `repository_owner` while the handler acts on the unrelated `full_name`.

### Impact Explanation
This does not require compromising `webhook_secret`, an `ApiClient` token, or repository write access to the target — only that the Shipit instance has at least one configured GitHub organization without a `webhook_secret` (a supported/documented state). With that, an external, unprivileged attacker can forge events against any *other* repository already registered in the Shipit instance:
- `push` → triggers `GithubSyncJob`/`stack.sync_github` on arbitrary stacks. [7](#0-6) 
- `status` → forges commit statuses (`commit.create_status_from_github!`), which can influence deploy-gating logic for other teams' stacks. [8](#0-7) 
- `check_suite` → schedules check-run refreshes on arbitrary commits. [9](#0-8) 
- `membership` → creates/deletes `Team`/`Membership` records tied to `Shipit.github_teams` authorization, since the handler trusts the payload's `organization.login`/`team.id` outright. [10](#0-9) 

The `Team`/`Membership` write path is the most severe because `User#authorized?` is gated on `Shipit.github_teams` membership; forging `membership` "added" events lets an attacker enroll arbitrary GitHub users (or accounts they control) into a privileged team, escalating into `Shipit.github_teams` authorization — matching the High-severity criterion in scope.

### Likelihood Explanation
Requires: (a) a multi-org Shipit deployment, and (b) at least one configured organization without a `webhook_secret`. This is not a hypothetical misconfiguration outside the documented deployment model — `docs/setup.md` treats `webhook_secret` as optional per organization, and `GitHubApp#verify_webhook_signature` explicitly supports operating with no secret (`return true unless webhook_secret`). [11](#0-10)  Given that, exploitation requires no credentials at all — a single unauthenticated `POST /webhooks` (or whichever route the engine mounts this controller under) with a crafted JSON body and mismatched `repository.owner.login` vs `repository.full_name`.

### Recommendation
Bind the field used to select/verify the signing secret to the field used to resolve the affected repository/stack: after establishing `repository_owner`, verify that `repository.full_name`'s owner segment matches `repository_owner` before dispatching to handlers, or resolve the target repository via the same authenticated organization scope rather than trusting `repository.full_name` independently. Additionally, treat a missing `webhook_secret` as "this organization's webhooks are unauthenticated" and refuse to let such webhooks affect stacks/teams belonging to other, secured organizations (e.g., check that the resolved `Stack`'s `Repository` organization equals the verified `repository_owner`).

### Proof of Concept
1. Configure Shipit with two GitHub orgs in `secrets.github`: `victim-org` (has `webhook_secret` set) and `attacker-org` (no `webhook_secret`, e.g. left blank per the optional setup docs).
2. Register a stack for `victim-org/victim-repo` in Shipit.
3. As an unauthenticated attacker, POST to the webhooks endpoint with header `X-Github-Event: membership` and body:
```json
{
  "action": "added",
  "team": {"id": 1, "name": "Deployers", "slug": "deployers", "url": "https://example.com"},
  "organization": {"login": "attacker-org"},
  "member": {"login": "attacker-controlled-user"},
  "repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}
}
```
No `X-Hub-Signature` (or any value) is required because `attacker-org` has no `webhook_secret`, so `verify_webhook_signature` returns `true` unconditionally. [4](#0-3) 
4. `MembershipHandler` processes the request, creating/updating a `Team` and adding `attacker-controlled-user` as a member — with no binding back to `victim-org`'s actual GitHub membership or secret. [10](#0-9) 
5. If that `Team` is included in `Shipit.github_teams`, the attacker's account gains `authorized?` status for deploy/rollback actions gated on team membership. [12](#0-11)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
