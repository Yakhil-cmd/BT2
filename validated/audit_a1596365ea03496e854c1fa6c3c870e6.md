### Title
Git pathspec-magic filenames (leading `:`) bypass Stop-hook security review — (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`_diff_pathspec` and `_temp_index`/`get_git_diff` build `git diff`/`git add --intent-to-add` pathspecs directly from filesystem-derived filenames (tracked/untracked paths reported by `git status`/`ls-files`) without neutralizing git's pathspec "magic" syntax, and `GIT_CMD` never sets `core.literalPathspecs` or prefixes arguments with `:(literal)`. An attacker who can place a file whose name is interpreted as pathspec magic (e.g. begins with `:`) into the working tree can make the underlying `git diff`/`git add` invocation fail or match unintended files, causing `get_git_diff` to return `None`/empty output for the whole review set rather than just the offending path.

### Finding Description
`_diff_pathspec(cwd, paths)` converts absolute touched-paths into repo-relative strings and appends them after a bare `"--"` separator, with no escaping of leading `:` [1](#0-0) . `get_git_diff` then splices this pathspec list directly into the `git diff` command and calls it inside `_temp_index`, whose `add_args` also come straight from `untracked_paths`/review-set filenames without literal-pathspec escaping [2](#0-1) [3](#0-2) . Because `GIT_CMD` only sets `core.fsmonitor=false` and `core.hooksPath=/dev/null` [4](#0-3) , git's default pathspec-magic parsing (`:(exclude)`, `:(glob)`, `:!`, etc., triggered by a leading `:` in the pathspec string) remains active for every path argument constructed from a real, attacker-controlled filename.

An attacker who can commit or place an untracked file whose name begins with `:` (a valid character on Linux/macOS filesystems) into the repository being reviewed causes that filename to appear verbatim in `git status --porcelain`/`ls-files` output, get carried into `review_paths`/`untracked_paths` by `compute_v2_review_set` and `_list_untracked` (in `diffstate.py`), and finally get passed unescaped as a pathspec to `git diff` / `git add --intent-to-add` in `gitutil.py`. Depending on the exact string, git either (a) errors out ("unrecognized pathspec magic character") causing the whole `git diff`/`git add` invocation to fail non-zero, or (b) the magic keyword actually changes which paths are matched (e.g. exclude semantics), silently narrowing or nulling the diff output for the *entire* pathspec-restricted call — not just the crafted filename.

Because `get_git_diff` returns `None` on any git failure and `handle_stop_hook` treats an empty/`None` diff as "no changes since baseline," this failure mode propagates to `_skip(6)`, which exits the Stop hook with code 0 and skips the entire security review for that turn [5](#0-4) . Thus a single specially-named file dropped anywhere in the touched/review set can silently disable review of *all* files changed in the turn, not merely put itself out of scope — this is the "path scoping escapes the intended repo target" condition: the pathspec no longer scopes git's diff to the intended review set, and the failure is swallowed as a benign "no diff" skip rather than surfaced as an error that would fall back to an unrestricted or safe review path.

No existing check neutralizes this: `_diff_pathspec` only strips paths that resolve outside `cwd` via `os.path.realpath`/`relpath` [6](#0-5) , which defends against symlink/`..` escapes but does nothing about pathspec-magic characters embedded in an otherwise legitimately in-repo filename. `_temp_index`'s `add_args` similarly pass raw filenames after `--` with no `:(literal)` guard [7](#0-6) .

### Impact Explanation
This is a Security-control bypass: an attacker-controlled repository file (no privileges beyond normal repo-content authorship, e.g. contributing a PR file or letting Claude create/rename a file with that name during agentic use) can silently disable the Stop-hook's LLM-based vulnerability review for an entire turn, letting genuinely vulnerable diffs slip past the reviewer un-flagged. This matches the "Security-control bypass that silently disables or routes around blocking, review, or permission boundaries" impact category.

### Likelihood Explanation
Feasibility is moderate: the attacker needs only to get a file with a colon-prefixed (or otherwise pathspec-magic) name into the working tree that the Stop hook's review-set computation picks up — trivially achievable via an untracked file created by a prior Bash command, a checked-out branch, or repo content the agent is asked to process. Colons are valid in filenames on Linux and macOS (the primary Claude Code dev environments). The condition is deterministic and repeatable once the filename is present, and requires no special privilege or social engineering, only ordinary repository content.

### Recommendation
Prefix every path passed to `git diff`/`git add` pathspec arguments with the `:(literal)` magic signature (or globally set `-c core.literalPathspecs=true` in `GIT_CMD`) inside `_diff_pathspec` and wherever `_temp_index`'s `add_args`/`untracked_paths` are built, so filenames are always matched literally regardless of leading `:`/`!`/glob characters. Additionally, treat a non-zero/`None` result from `get_git_diff` as a hard error state distinct from "no changes," so review is retried or escalated rather than silently skipped via `_skip(6)`.

### Proof of Concept
1. In a git repo used by the security-guidance Stop hook, create an untracked file named `:(exclude)poc.py` (or another string that git's pathspec parser treats as magic) containing an obviously vulnerable pattern (e.g. `os.system(user_input)`).
2. Trigger a turn so `compute_v2_review_set`/`_list_untracked` includes this filename in `untracked_paths`/`review_paths`.
3. Call `get_git_diff(repo_root, baseline_sha, paths=review_paths, untracked_paths=untracked)` directly (unit test) and assert:
   - The underlying `git diff`/`git add --intent-to-add` subprocess returns non-zero (or matches unintended files), and
   - `get_git_diff` returns `None`/empty rather than a diff containing the legitimately vulnerable file.
4. Drive `handle_stop_hook` end-to-end with this fixture and assert it reaches `_skip(6)` (no findings reported) despite the vulnerable content being present, demonstrating the review-bypass. Expected fix: after adding `:(literal)` escaping, the same test should show the vulnerable file correctly appearing in `diff_output` and being flagged.

def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

@contextlib.contextmanager
def _temp_index(cwd, untracked_paths=None):
    """Yield an env dict pointing GIT_INDEX_FILE at a throwaway copy of the
    repo's index with `git add --intent-to-add` applied, so untracked files
    show up in subsequent `git diff` calls without touching the user's real
    index. Yields None if no index can be found (bare repo / not a repo); the
    caller should fall back to a plain diff. Always cleans up the temp file.

    Perf: when `untracked_paths` is given, only those paths are added (O(n)
    in untracked count). The default `add -N .` stats every file in the
    worktree — slow in large repos vs fast targeted scan. v2 callers
    already know the untracked set from `git status --porcelain`, so they
    pass it; v1 keeps the whole-tree scan since it has no prior list."""
    import shutil
    import tempfile

    real_index = _find_git_index(cwd)
    if not real_index:
        yield None
        return

    tmp_fd, tmp_index = tempfile.mkstemp(prefix="security_hook_idx_")
    os.close(tmp_fd)
    try:
        shutil.copy2(real_index, tmp_index)
        env = {**os.environ, "GIT_INDEX_FILE": tmp_index}
        if untracked_paths is None:
            add_args = ["."]
        elif untracked_paths:
            # `git add -N -- a b nonexistent` is atomic — one missing path
            # makes it exit 128 and add NOTHING, so a file removed between
            # `git status` and here would silently drop ALL untracked files
            # from the diff. --ignore-missing only works with --dry-run, so
            # filter to surviving paths (lexists so dangling symlinks count).
            surviving = [p for p in untracked_paths
                         if os.path.lexists(os.path.join(cwd, p))]
            add_args = ["--"] + surviving if surviving else None
        else:
            add_args = None
        if add_args:
            subprocess.run(
                [*GIT_CMD, "add", "--intent-to-add"] + add_args,
                cwd=cwd, capture_output=True, text=True, timeout=10,
                env=env,
            )
        yield env
    finally:
        try:
            os.unlink(tmp_index)
        except OSError:
            pass

def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
    try:
        with _temp_index(cwd, untracked_paths) as env:
            # env is None when no index could be found (bare repo / not a
            # repo) — diff still runs, just without untracked-file support.
            result = subprocess.run(cmd, cwd=cwd, capture_output=True, timeout=30, env=env)
        if result.returncode != 0:
            debug_log(f"git diff failed: {result.stderr[:200].decode('utf-8', errors='replace')}")
            return None
        # Decode with errors='replace' so binary diffs don't crash
        return result.stdout.decode("utf-8", errors="replace")
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"git diff error: {e}")
        return None
```
