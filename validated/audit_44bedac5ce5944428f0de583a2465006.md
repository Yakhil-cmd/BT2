### Title
Webhook signature verification is scoped to an attacker-chosen organization while event handlers act on an unrelated, unauthenticated repository/commit field — forged CI status can trigger an unauthorized deploy - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App's `webhook_secret` to validate the HMAC signature against based on `repository_owner`, a value read straight out of the *unauthenticated* JSON body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`). None of the downstream `Webhooks::Handlers` re-validate that the entity they act on (a `Repository`/`Stack`/`Commit`) actually belongs to that same authenticated organization. `StatusHandler` in particular ignores the repository entirely and matches commits globally by SHA. Because `webhook_secret` is explicitly optional per configured GitHub organization (`lib/shipit/github_app.rb` returns `true` unconditionally when no secret is set), any organization onboarded without a secret becomes a valid "master key" an unauthenticated attacker can use to forge webhook events that affect completely different, unrelated repositories — including forging a successful CI status that triggers continuous deployment.

### Finding Description
`app/controllers/shipit/webhooks_controller.rb`:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end

**Binding broken:** `organization authenticated (webhook_secret owner used for HMAC verification)` == `repository/commit actually written by the handler`. The controller only authenticates the *organization key selected from an attacker-supplied field*; it never authenticates that the *specific repository or commit acted upon* belongs to that organization.

### Impact Explanation
If any organization configured in a multi-org `secrets.yml` (a supported, documented configuration — see `docs/setup.md` "Using Multiple Github Applications") has `webhook_secret` unset (which is explicitly optional and shown as `nil` in the shipped sample configs), an unauthenticated network attacker who knows that organization's login name (public information) can:
1. POST to `/webhooks` with `X-Github-Event: status`, `repository.owner.login` (or `organization.login`) set to the secret-less org — passing `verify_signature` unconditionally.
2. Set `sha` to any commit SHA belonging to a **victim** stack in a completely different, properly-secured organization, and `state: success`.
3. `StatusHandler` matches the commit globally and creates a success status, which — if the victim stack has `continuous_deployment` enabled — triggers `ContinuousDeliveryJob` and results in an **unauthorized deploy**, satisfying the Critical impact bar ("an unauthorized deploy, rollback or merge").

Even for handlers that do use `repository.full_name` (push, pull_request, check_suite), the value is taken from the same unauthenticated JSON body and is never cross-checked against the org whose secret validated the request, so the same organization-vs-repository binding break applies broadly, not just to `status`.

### Likelihood Explanation
Exploitation requires only: (a) the Shipit instance is configured with at least one GitHub organization that has no `webhook_secret` set — a state the documentation explicitly presents as valid/optional, not a misconfiguration to avoid — and (b) knowledge of that org's public login and the victim stack's commit SHA (both discoverable via the public GitHub UI/API, no Shipit credentials needed). No `ApiClient` token, GitHub App private key, or Shipit session is required, matching the unprivileged-attacker constraint.

### Recommendation
- Require a `webhook_secret` for every configured GitHub organization (fail startup/config validation instead of defaulting to "always verified" when absent).
- After successfully verifying the signature for organization `O`, enforce that every entity resolved from the payload (`repository.full_name`, and — critically — the `Commit`/`Stack` looked up in `StatusHandler`, `CheckSuiteHandler`, etc.) actually belongs to `O` before acting on it, rather than trusting `repository.full_name`/`sha` in isolation.
- In `StatusHandler`, scope the `Commit` lookup by the repository declared in the (now-validated) payload rather than a bare, cross-repository `Commit.where(sha:)`.

### Proof of Concept
1. Configure Shipit with two GitHub organizations in `secrets.yml`: `attacker-org` (no `webhook_secret`) and `victim-org` (with a `webhook_secret`), both onboarded per `docs/setup.md`'s multi-org instructions.
2. Identify a commit SHA `S` belonging to a `victim-org` stack that has `continuous_deployment: true`.
3. Send:
```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=anything   # ignored, attacker-org has no secret

{
  "organization": { "login": "attacker-org" },
  "repository": { "owner": { "login": "attacker-org" } },
  "sha": "S",
  "state": "success",
  "context": "ci/travis"
}
```
4. `verify_signature` resolves `repository_owner` = `"attacker-org"`, calls `Shipit.github(organization: "attacker-org").verify_webhook_signature(...)`, which returns `true` unconditionally because `attacker-org` has no `webhook_secret`.
5. `StatusHandler#process` runs `Commit.where(sha: "S")`, finds the victim commit, and calls `create_status_from_github!`, marking it `success`.
6. The victim stack's continuous-deployment logic (`Deploy`/`Stack#trigger_continuous_delivery`) schedules and executes an unauthorized deploy, without the attacker ever knowing `victim-org`'s webhook secret.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
