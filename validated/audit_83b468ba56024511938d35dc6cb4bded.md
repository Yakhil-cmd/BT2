### Title
Cross-repository commit status forgery via unscoped `StatusHandler` lookup - (File: app/models/shipit/webhooks/handlers/status_handler.rb)

### Summary
The webhook signature check in `Shipit::WebhooksController#verify_signature` only proves that a payload was signed by the GitHub organization named in the payload's `repository.owner.login` (or `organization.login`) field; it does not bind that organization/repository to which `Commit` record the payload is ultimately allowed to mutate. `StatusHandler`, unlike `PushHandler` and `CheckSuiteHandler`, never scopes its lookup to the repository named in the signed payload, so a `status` event correctly signed by *any* GitHub organization onboarded to this Shipit instance can write a status onto a commit belonging to a *completely different* tracked repository/stack, as long as the commit SHA matches.

### Finding Description
`WebhooksController#verify_signature` selects which GitHub App/organization secret to verify the HMAC against using `repository_owner`, derived straight from the untrusted JSON payload: [1](#0-0) [2](#0-1) 

This only proves "this payload's HMAC matches organization X's webhook secret" — it says nothing about which repository the *handler* is permitted to mutate. The base `Handler` class defines a `stacks` helper that correctly scopes lookups to the repository named in the signed payload (`repository.full_name`): [3](#0-2) 

`PushHandler` and `CheckSuiteHandler` use this scoped `stacks` helper before touching any records: [4](#0-3) [5](#0-4) 

`StatusHandler`, however, ignores the `repository` field entirely and looks up commits globally by SHA across the whole Shipit instance: [6](#0-5) 

Because git commit SHA-1 is content-addressed (derived from tree, parents, author/committer, timestamps and message — not from any particular remote/org), an attacker who controls or forks a completely unrelated repository can reproduce a commit with an identical SHA to one that already exists in a victim stack tracked by the same Shipit instance (e.g., by mirroring/forking the public victim repo into their own org that also has the Shipit GitHub App installed, per the multi-org config documented in `docs/setup.md`). The attacker then pushes/triggers a `status` webhook from their own, legitimately-signed organization for that SHA. The signature check passes (it only validates against the attacker's own org secret), and `StatusHandler` applies the attacker-controlled `state`/`description`/`target_url` to the victim's `Commit` row via `Commit#create_status_from_github!`, because the lookup is not scoped by repository at all.

This is precisely the "organization authenticated versus the repository written" binding break: `organization_that_signed(payload) == organization_owning(payload.repository)` is enforced, but `repository_that_signed(payload) == repository_of_commit_mutated` is never enforced by `StatusHandler`.

### Impact Explanation
Commit statuses gate Shipit's deploy readiness UI/checks for a stack. An attacker able to forge a status on a commit belonging to a repository/stack they do not control can inject a false "success" status (or flip an existing check to failure to block legitimate deploys) for another team's tracked stack, without ever having write access to that repository or its webhook secret. This is a cross-repository write achieved purely by content-addressing a commit and triggering a webhook from an org the attacker legitimately controls, meeting the "cross-repository writes" / "unauthorized deploy" impact bar.

### Likelihood Explanation
Requires: (1) the target Shipit instance is configured with multiple GitHub organizations (documented, supported pattern in `docs/setup.md`), or the attacker has any repository (even one they solely admin) with the Shipit GitHub App installed; and (2) the attacker can produce/mirror a commit whose SHA collides with a target commit's SHA — trivially done for any public repository by simply forking/mirroring it (the SHA is identical because SHA-1 is deterministic over content, not remote origin). No stolen credentials, no privileged Shipit account, and no compromise of the target org's webhook secret are needed.

### Recommendation
Scope `StatusHandler#process` (and any other handler that doesn't already use `stacks`) to the repository asserted in the signed payload, mirroring `PushHandler`/`CheckSuiteHandler`:
```ruby
def process
  stacks.flat_map(&:commits).select { |c| c.sha == params.sha }.each do |commit|
    commit.create_status_from_github!(params)
  end
end
```
or equivalently join `Commit` through `Stack -> Repository` filtered by `repository_name` before applying the status, so a valid signature from organization X can never mutate commits belonging to a repository outside X.

### Proof of Concept
1. Shipit tracks `victim-org/app` (stack `victim-org/app@main`), with commit `abc123...` already synced.
2. Attacker creates `attacker-org/mirror`, installs their own GitHub App/webhook on the same Shipit instance (supported "Using Multiple Github Applications" config), and mirrors `victim-org/app` (or crafts a commit with identical tree/parents/author/committer/message/timestamps) so that the same commit `abc123...` exists in `attacker-org/mirror`.
3. Attacker pushes to `attacker-org/mirror`, or directly POSTs a forged-but-correctly-signed (using their own org's webhook secret) `status` event payload to `/webhooks`:
```json
{
  "sha": "abc123...",
  "state": "success",
  "context": "ci/required-check",
  "repository": {"full_name": "attacker-org/mirror", "owner": {"login": "attacker-org"}}
}
```
4. `WebhooksController#verify_signature` verifies against `attacker-org`'s secret and succeeds. `StatusHandler#process` runs `Commit.where(sha: 'abc123...')`, finds the victim's commit (belonging to `victim-org/app`), and calls `create_status_from_github!`, marking the victim stack's commit status as green — with no dependency on `victim-org`'s webhook secret or repository at all. module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end

# frozen_string_literal: true

module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
