### Title
Unverified `creator` account in `initialize_with_permission` lets the pool creator/fee-recipient be permanently unclaimable, freezing creator fees - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`initialize_with_permission` accepts a `creator` account that is only an `UncheckedAccount` with a doc-comment `/// CHECK: creator of pool` and no Anchor constraint tying it to a signer, to `payer`, or to any verifiable authority. Its raw pubkey is stored unconditionally as `PoolState.pool_creator`, which becomes the sole recipient of all future creator trading fees for the pool's lifetime.

### Finding Description
In `InitializeWithPermission<'info>` the `creator` field is declared: [1](#0-0) 
with no signer requirement and no constraint relating it to `payer` (the only account whose authorization is actually checked, via the `permission` PDA seeded on `payer.key()`): [2](#0-1) 

The instruction handler then commits this unverified key permanently into pool state: [3](#0-2) 
via `PoolState::initialize`, which stores it verbatim as `pool_creator`: [4](#0-3) 

`pool_creator` is later used as the fee-collection target with no additional validation of reachability: `CollectCreatorFee` requires the `creator` to sign and match `pool_state.pool_creator`, and `CollectCreatorFeePermissionless` allows anyone to trigger a transfer of accrued fees into an ATA owned by whatever address is recorded as `pool_creator`: [5](#0-4) [6](#0-5) 

By contrast, the non-permissioned `initialize` instruction requires the equivalent account to be a `Signer`, i.e., the party designated as pool creator must consent by co-signing the transaction: [7](#0-6) 

This is the same bug class as the referenced Mattermost advisory: a critical actor/identity field (`pool_creator`, analogous to "who created this action") is trusted from unauthenticated, attacker-supplied input instead of being cryptographically verified (signature or established relationship). Any permissioned `payer` can set `creator` to an arbitrary pubkey — including one with no known private key, such as a burn/incinerator address, `Pubkey::default()`, a random keypair the payer discards, or a PDA belonging to an unrelated program that never signs for a token account transfer.

### Impact Explanation
All trading (creator) fees generated by the pool accrue in `pool_state.creator_fees_token_0/1` and are only ever payable to the `pool_creator` address recorded at pool creation. If that address is unreachable (no controlling keypair), the funds sent via `collect_creator_fee_permissionless` land in an Associated Token Account whose authority nobody can sign for, permanently freezing that portion of the pool's fee revenue. This satisfies the "permanent freezing of user or LP/fee-ledger funds" impact bar. Because `collect_creator_fee_permissionless` is callable by anyone with no signature from `pool_creator`, the freeze is guaranteed to eventually occur once fees accrue, and cannot be reversed by governance/admin instructions (there is no admin override to reassign `pool_creator`).

### Likelihood Explanation
Every call to `initialize_with_permission` is made by a "permissioned" `payer`, but that permission only proves the payer is authorized to create pools — it says nothing about the `creator` account's legitimacy. A permissioned but careless or malicious payer needs no special privilege beyond calling the already-reachable, documented instruction with an arbitrary `creator` pubkey of their choosing; no additional accounts, race conditions, or unusual state are required. This makes the flaw trivially and reliably triggerable in a single transaction.

### Recommendation
Require `creator` to either (a) be a `Signer` (as in the un-permissioned `initialize` instruction), or (b) add an explicit Anchor constraint tying `creator` to `payer` (e.g., `address = payer.key()`), or (c) require a separate signature/authorization proof that the designated `creator` consents to being recorded as `pool_creator`. At minimum, disallow default/zero pubkeys and known-unspendable addresses for `creator`.

### Proof of Concept
1. Attacker (or any careless actor) obtains a valid `permission` PDA for their `payer` key via `create_permission_pda` (open to the configured `create_permission_pda_owner`/admin flow).
2. Attacker calls `initialize_with_permission` supplying `payer` (signer, funds initial liquidity) and `creator` = an arbitrary pubkey with no known private key (e.g., `Pubkey::default()` or a freshly generated keypair whose secret is discarded).
3. `pool_state.pool_creator` is set to this unreachable address: [3](#0-2) 
4. As swaps occur on the pool, `creator_fees_token_0/1` accrue in `pool_state`.
5. Anyone calls `collect_creator_fee_permissionless`, which succeeds (no signature from `creator` required) and transfers the accrued fees into an ATA owned by the unreachable `creator` address: [8](#0-7) 
6. The tokens are now permanently locked in an ATA no one can ever move, since `CollectCreatorFee` (the only path requiring `creator` as signer) can never be satisfied and no other instruction can debit that ATA.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```
