### Title
Debt-value overflow during accrual permanently freezes an overlarge market - (File: `contracts/pool/src/interest.rs`)

### Summary
An unprivileged borrower can drive an overlarge, high-utilization market into a state where the next accrual overflows while converting scaled debt to asset value, permanently blocking repayment, withdrawal, liquidation, and further index updates for that market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The permissionless `Controller::update_indexes` entrypoint forwards caller-selected hub assets to the pool. [4](#0-3)  The pool’s `update_indexes` calls `ops::market::accrue`, whose accrual path invokes `interest::global_sync` and repeatedly applies `accrue_step` to the stored borrow shares and borrow index. [5](#0-4) [1](#0-0) [6](#0-5) 

`accrue_step` must value the scaled debt at the newly projected index; when `borrowed_shares * new_borrow_index` exceeds the representable RAY-value range, the conversion reverts with `MATH_OVERFLOW` before the borrow-index ceiling can stop accrual. [7](#0-6)  The existing regression test constructs this state with a one-billion-token 18-decimal market at 98% utilization and demonstrates that the borrow index remains below `MAX_BORROW_INDEX_RAY` when accrual first fails. [8](#0-7) 

### Impact Explanation
Once the market crosses the representable-value cliff, every state-changing path that accrues the market first encounters the same arithmetic failure. [1](#0-0)  This blocks user withdrawals through `Controller::withdraw`, debt repayment through `Controller::repay`, liquidation through `Controller::liquidate`, and the keeper-style `Controller::update_indexes` path itself. [9](#0-8) [4](#0-3)  The regression test confirms that both a withdrawal and a repayment fail with `MATH_OVERFLOW` after the cliff is reached. [10](#0-9) 

The result is permanent freezing of supplier funds and inability to reduce or liquidate the market’s debt, which can leave the market insolvent while suppliers retain unredeemable share claims. [3](#0-2) 

### Likelihood Explanation
The attacker does not need privileged access: `supply`, `borrow`, and `update_indexes` are reachable by ordinary authenticated callers, although the attacker must control enough listed collateral and supplied liquidity to create the extreme scaled-debt book and must sustain accrual at high utilization until the valuation product overflows. [11](#0-10) [4](#0-3) [12](#0-11) 

The exploit is therefore capital-intensive and market-dependent, but it is not prevented by the configured borrow-index cap because the multiplication overflow occurs before that cap can bound the next accrual. [7](#0-6) 

### Recommendation
Represent debt and supply valuation during accrual with `I256` or an equivalent widened fixed-point type, then either safely reduce the result to `i128` or clamp index growth before the intermediate valuation can exceed `i128::MAX`. [2](#0-1)  Alternatively, enforce a market-level scaled-debt cap derived from the maximum safe `borrowed * MAX_BORROW_INDEX_RAY` product so a position can never enter the unrecoverable valuation domain. [1](#0-0) [13](#0-12) 

### Proof of Concept
1. An attacker supplies a very large amount of an 18-decimal market through `Controller::supply` and supplies sufficient separate collateral through another listed market. [14](#0-13) [15](#0-14) 
2. The attacker calls `Controller::borrow` until the target market has approximately 98% utilization, producing a scaled-debt total large enough that later index growth makes its RAY asset value exceed `i128::MAX`. [16](#0-15) [17](#0-16) 
3. Any caller repeatedly invokes `Controller::update_indexes` with the target `HubAssetKey`; once projected debt value crosses the representable bound, `accrue_step` reverts with `MATH_OVERFLOW`. [4](#0-3) [18](#0-17) [19](#0-18) 
4. Subsequent `Controller::withdraw`, `Controller::repay`, `Controller::liquidate`, and `Controller::update_indexes` calls on the market all execute accrual first and therefore remain unusable. [9](#0-8) [4](#0-3) [10](#0-9)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
