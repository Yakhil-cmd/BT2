### Title
Cross-Organization Webhook Forgery via Mismatched Signature-Key Selection and Repository Resolution - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
In a multi-tenant Shipit deployment (multiple GitHub organizations configured under `secrets.github`, each with its own `webhook_secret`), `WebhooksController#verify_signature` selects which organization's HMAC secret to verify the request against using `repository_owner`, taken from the untrusted JSON payload's `repository.owner.login` field [1](#0-0) , while the webhook handlers that actually act on the payload resolve the target repository from a *different* field in the same payload: `repository.full_name` [2](#0-1) . These two fields are never checked for consistency, so the identity used to select/verify the signing secret is not cryptographically bound to the identity of the repository whose stacks get modified.

### Finding Description
`Shipit.github(organization: repository_owner)` looks up the `GitHubApp`/`webhook_secret` for the organization named in `params.dig('repository','owner','login')` (or `organization.login`) [3](#0-2) [4](#0-3) . The controller then verifies the raw request body's `X-Hub-Signature` against that organization's `webhook_secret` only [5](#0-4) .

Once verification passes, `Shipit::Webhooks.for_event(event)` dispatches the same raw JSON body to handlers such as `PushHandler` and `StatusHandler`. These handlers never look at `repository.owner.login` again — they resolve the affected stacks purely from `payload.dig('repository', 'full_name')` via `Handler#repository_name`/`#stacks` [2](#0-1) , e.g. `PushHandler#process` triggers `stack.sync_github` for every matching stack [6](#0-5) , and `StatusHandler#process` writes a `Status` for any commit matching the `sha` field, independent of repository ownership [7](#0-6) .

The break-the-binding equality is:
`organization authenticated (repository.owner.login, used to select the verifying webhook_secret)` ≠ `repository written (repository.full_name, used by handlers to select target stacks)`.

Because a single Shipit instance can host multiple organizations, each with an independently-configured `webhook_secret` set by whoever created that org's GitHub App (as shown by the multi-org secrets layouts) [8](#0-7) [9](#0-8) , the operator/administrator of one tenant org ("OrgOne") legitimately knows their own `webhook_secret`. That party is an unprivileged attacker with respect to any other tenant ("OrgTwo") hosted on the same Shipit instance.

### Impact Explanation
An attacker who only controls one tenant organization's webhook secret can:
1. Craft a JSON body with `repository.owner.login = "OrgOne"` (so `verify_signature` selects and successfully validates against OrgOne's known secret) but `repository.full_name = "OrgTwo/victim-repo"`.
2. Sign the raw body with OrgOne's `webhook_secret` and POST it directly to the public, unauthenticated `/webhooks` endpoint with `X-Github-Event: push` or `status`.
3. The signature check passes (it only validates against OrgOne's secret), and the dispatched handler acts on OrgTwo's stacks: `push` forces `GithubSyncJob`/`sync_github` for OrgTwo's stack, and `status` forges arbitrary commit statuses (`state`, `context`, `description`) on OrgTwo's commits.

Forged commit statuses can flip CI/merge-gating checks (`ci.blocking`/`deployable?`) to green for a commit that never actually passed CI, letting the merge queue or continuous-deployment pipeline treat a bad commit as deployable — this is an unauthorized-deploy vector achieved purely by writes into another organization's repository state, satisfying the "cross-repository writes / unauthorized deploy" Critical impact bar.

### Likelihood Explanation
This requires only that the target Shipit deployment host more than one GitHub organization (a documented, supported configuration) and that the attacker be an administrator of any one of those tenant organizations — no access to the victim org, no Shipit session, no `ApiClient` token, and no host-app misconfiguration is needed. The `/webhooks` endpoint is intentionally public and unauthenticated by design (it relies solely on HMAC signature checking).

### Recommendation
Bind the verified organization to the acted-upon repository: after verifying the signature, re-derive `repository_owner` from `repository.full_name` (or explicitly require `repository.owner.login` to match the owner segment of `repository.full_name`) before dispatching to handlers, and reject the webhook if they diverge. Alternatively, pass the already-verified organization identity into each handler and have `Handler#stacks` filter/reject repositories whose owner doesn't match the organization that authenticated the request.

### Proof of Concept
```
POST /webhooks HTTP/1.1
X-Github-Event: status
X-Hub-Signature: sha1=<HMAC-SHA1(OrgOne_webhook_secret, body)>
Content-Type: application/json

{
  "repository": {
    "owner": { "login": "OrgOne" },
    "full_name": "OrgTwo/victim-repo"
  },
  "sha": "<victim-commit-sha-in-OrgTwo-stack>",
  "state": "success",
  "context": "ci/required-check",
  "description": "forged"
}
```
`verify_signature` resolves `Shipit.github(organization: "OrgOne")` and validates the HMAC against OrgOne's own known `webhook_secret`, succeeding. `StatusHandler#process` then creates a `success` `Status` record on the commit belonging to `OrgTwo/victim-repo`, without ever checking that `OrgOne` has any relationship to `OrgTwo`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
