### Title
Bridge `isRunning` Stop-Flag Bypassed by `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer` — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`)

### Summary

The Kaia service-chain bridge exposes an `isRunning` flag that the owner can set to `false` via `setRunningStatus()` to halt all value transfers. Every outgoing-request path enforces this flag, but all three incoming-handle paths (`handleKLAYTransfer`, `handleERC20Transfer`, `handleERC721Transfer`) do not, allowing registered operators to continue transferring KLAY and bridged tokens out of the bridge contract even while it is officially stopped.

### Finding Description

`BridgeTransfer.sol` declares `bool public isRunning = true` and the comment on `setRunningStatus` reads: *"can allow or disallow the value transfer request."*

**Protected paths (check `isRunning`):**

- `_requestKLAYTransfer()` — `require(isRunning, "stopped bridge");`
- `_requestERC20Transfer()` — `require(isRunning, "stopped bridge");`
- `_requestERC721Transfer()` — `require(isRunning, "stopped bridge");`

**Unprotected paths (no `isRunning` check):**

- `handleKLAYTransfer()` — guarded only by `onlyOperators` + `nonReentrant`
- `handleERC20Transfer()` — guarded only by `onlyOperators`
- `handleERC721Transfer()` — guarded only by `onlyOperators`

When `isRunning` is set to `false`, any registered operator can still call the three handle functions and cause the bridge to:
- send KLAY to an arbitrary `_to` address (`_to.call.value(_value)("")`)
- `safeTransfer` or `mint` ERC-20 tokens to `_to`
- `transferFrom` or `mintWithTokenURI` ERC-721 tokens to `_to`

The operator set is distinct from the owner and is managed separately; the owner may stop the bridge precisely because operator keys are suspected to be compromised, yet the stop flag provides no protection against those same operators draining the bridge via the handle functions.

### Impact Explanation

Operators can transfer KLAY and bridged ERC-20/ERC-721 assets out of a bridge that the owner has explicitly stopped. In `modeMintBurn = true` mode the handle functions mint new tokens; in `modeMintBurn = false` mode they transfer tokens held by the bridge. Either way, the stop flag fails to protect bridge-managed funds, directly matching the "unauthorized transfer of bridged assets" impact criterion.

### Likelihood Explanation

The trigger requires a registered operator, making it semi-privileged. However, the scenario where the owner stops the bridge is precisely the scenario where operator trust is in question (e.g., a security incident, a bug on the counterpart chain, or a suspected key compromise). The inconsistency is reachable by any of the `MAX_OPERATOR` registered operators without any additional preconditions.

### Recommendation

Add an `isRunning` guard to all three handle functions, mirroring the pattern already used in the request paths:

```solidity
// BridgeTransferKLAY.sol
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
    require(isRunning, "stopped bridge");   // add this
    ...
}

// BridgeTransferERC20.sol
function handleERC20Transfer(...) public onlyOperators {
    require(isRunning, "stopped bridge");   // add this
    ...
}

// BridgeTransferERC721.sol
function handleERC721Transfer(...) public onlyOperators {
    require(isRunning, "stopped bridge");   // add this
    ...
}
```

Alternatively, introduce a shared modifier in `BridgeTransfer` and apply it uniformly to all six transfer-touching functions.

### Proof of Concept

1. Owner calls `bridge.setRunningStatus(false)` — bridge is stopped; `isRunning = false`.
2. Any registered operator calls:
   ```solidity
   bridge.handleKLAYTransfer(txHash, from, attackerAddr, 1 ether, nonce, blockNum, "");
   ```
3. `_requestKLAYTransfer` would revert with `"stopped bridge"`, but `handleKLAYTransfer` has no such check.
4. The bridge sends `1 ether` to `attackerAddr` despite `isRunning == false`.
5. The same applies to `handleERC20Transfer` (mints or transfers ERC-20) and `handleERC721Transfer` (mints or transfers ERC-721).
