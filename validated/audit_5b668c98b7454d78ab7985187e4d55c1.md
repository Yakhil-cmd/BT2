### Title
Asset issuer can permanently freeze all holders' funds of a `spender_attested` asset by withholding/revoking attestor list, with no fallback path to spend own coins - (File: `validation.js`, `definition.js`)

### Summary
The reported bug class is: a privileged role (`guard`) can toggle a global pause switch that also blocks the *withdrawal* path, with no way for users to bypass that gate and recover their own funds. The closest reachable analog in ocore is the `spender_attested` asset mechanism: the asset issuer (definer) fully controls whether a payment message spending/transferring that asset validates at all, via the `attestations`/`attestors` list. If the issuer withdraws or never grants attestation to a legitimate holder, that holder's coins become permanently unspendable even though they otherwise satisfy all on-chain balance and signature rules.

### Finding Description
When an asset is created with `spender_attested: true`, every payment message that spends units of that asset (other than issuance) is validated in `validatePayment()`: [1](#0-0) 

This requires `objAsset.arrAttestedAddresses.length` to be non-zero, where `arrAttestedAddresses` is computed by `filterAttestedAddresses()`/`loadAssetWithListOfAttestedAuthors()` based on the current attestor list and matching `attestations` records: [2](#0-1) 

The attestor list itself is fully controlled by the asset definer through `asset_attestors` messages, checked in `validateAttestorListUpdate()`: [3](#0-2) 

Because only the definer can update this list (`if (objUnit.authors[0].address !== objAsset.definer_address) return callback("attestor list can be edited only by definer")`), a single privileged party — analogous to the `guard` in the reported bug — can unilaterally cut off the ability of every other holder to move coins they legitimately received, by removing all attestors or never issuing/renewing attestations for a given holder. There is no `whenNotPaused`-style bypass: `validatePaymentInputsAndOutputs`/`validatePayment` unconditionally reject the spend regardless of how correct the rest of the unit is (correct signatures, balanced inputs/outputs, valid parents), exactly mirroring the reported issue where a legitimate, fully-authorized withdrawal is blocked purely by an external, privileged on/off switch.

### Impact Explanation
Impact is High: holders of a `spender_attested` asset can have their funds permanently frozen at the sole discretion of the asset issuer/attestor, with zero way to move or exchange their own coins on-chain — no admin override, timeout, or self-help path exists in the protocol, unlike a normal address definition where the owner always retains at least one valid signing path.

### Likelihood Explanation
Likelihood is Low: this requires opting into a `spender_attested` asset (an explicit, disclosed feature of the asset), and requires the issuer to behave adversarially (or negligently, e.g. an attestation service going offline) after users already hold the asset — analogous to the original report's "guard turns malicious/unresponsive after users deposit" scenario.

### Recommendation
Consider documenting/enforcing that `spender_attested` assets cannot retroactively strip attestation from addresses that already hold a balance without a grace period, or provide an on-chain fallback (e.g., a timelocked recovery path) so that holders are not permanently locked out of already-acquired funds purely due to the issuer's/attestor's unilateral, unbounded control over the attestor list.

### Proof of Concept
1. Issuer defines an asset with `spender_attested: true` and an initial attestor list `A`.
2. Alice legitimately acquires units of this asset (e.g., via purchase or an AA payout) while attested by `A`.
3. Issuer sends an `asset_attestors` message removing all attestors (or attestor `A` stops attesting Alice).
4. Alice attempts to spend/transfer her existing balance; `validatePayment()` calls `loadAssetWithListOfAttestedAuthors`, finds `arrAttestedAddresses.length === 0` (or Alice not in the list), and rejects with `"none of the authors is attested"` per [4](#0-3) .
5. Alice's funds remain permanently locked in her address with no valid path to move them, as long as the issuer withholds attestation.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

// filter only those addresses that are attested (doesn't work for light clients)
function filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAddresses, handleAttestedAddresses){
	conn.query(
		"SELECT DISTINCT address FROM attestations CROSS JOIN units USING(unit) \n\
		WHERE attestor_address IN(?) AND address IN(?) AND main_chain_index<=? AND is_stable=1 AND sequence='good' \n\
			AND main_chain_index>IFNULL( \n\
				(SELECT main_chain_index FROM address_definition_changes JOIN units USING(unit) \n\
				WHERE address_definition_changes.address=attestations.address AND main_chain_index<=? AND is_stable=1 AND sequence='good' ORDER BY main_chain_index DESC LIMIT 1), \n\
			0)",
		[objAsset.arrAttestorAddresses, arrAddresses, last_ball_mci, last_ball_mci],
		function(addr_rows){
			var arrAttestedAddresses = addr_rows.map(function(addr_row){ return addr_row.address; });
			handleAttestedAddresses(arrAttestedAddresses);
		}
	);
}

// note that light clients cannot check attestations
function loadAssetWithListOfAttestedAuthors(conn, asset, last_ball_mci, arrAuthorAddresses, bAcceptUnconfirmedAA, handleAsset){
	if (arguments.length === 5) {
		handleAsset = bAcceptUnconfirmedAA;
		bAcceptUnconfirmedAA = false;
	}
	readAsset(conn, asset, last_ball_mci, bAcceptUnconfirmedAA, function(err, objAsset){
		if (err)
			return handleAsset(err);
		if (!objAsset.spender_attested)
			return handleAsset(null, objAsset);
		filterAttestedAddresses(conn, objAsset, last_ball_mci, arrAuthorAddresses, function(arrAttestedAddresses){
			objAsset.arrAttestedAddresses = arrAttestedAddresses;
			handleAsset(null, objAsset);
		});
	});
}
