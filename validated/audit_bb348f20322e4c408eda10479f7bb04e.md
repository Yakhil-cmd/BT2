### Title
Supply-index floor resurrects wiped suppliers and strands future deposits - ([File: contracts/pool/src/interest.rs])

### Summary
`apply_bad_debt_to_supply_index` fully consumes supplier claims but clamps the resulting supply index upward to `SUPPLY_INDEX_FLOOR_RAW`, leaving every existing scaled supply position redeemable despite the market having no backing. [1](#0-0) 

### Finding Description
The permissionless `clean_bad_debt` entrypoint reaches `execute_bad_debt_cleanup` after `socialize_bad_debt` verifies that the account has debt and satisfies the dust-capped insolvency gate. [2](#0-1) [3](#0-2) 

Cleanup sends the account's remaining supply positions to the pool as `Deposit` seizures and its debt positions as `Borrow` seizures. [4](#0-3)  For a borrow seizure, the pool converts the scaled debt at the borrow index, socializes that value through `apply_bad_debt_to_supply_index`, and burns the debt. [5](#0-4) 

When `bad_debt >= supplied * supply_index`, `capped` equals the entire supplier claim and `remaining` is zero, so the computed supply index is zero. [6](#0-5)  The subsequent `.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW))` raises that wiped index to `RAY / 1000` while leaving all suppliers' scaled share balances unchanged. [7](#0-6) 

This is the same structural failure as the kernel report: a location-sensitive claim was copied into a new execution context without rebasing it. Here, scaled supply shares are revalued after a complete write-down without rebasing or deleting them, so stale positions still resolve to assets at the artificial floor index.

### Impact Explanation
A complete bad-debt wipeout should leave existing supply claims with zero economic backing, but the floor preserves a nonzero claim equal to each position's scaled shares multiplied by `RAY / 1000`. [8](#0-7) 

The next supplier deposits real tokens into an ostensibly empty market, while old supply positions retain positive withdrawable claims. Those stale claims can withdraw the fresh cash before the new supplier, recreating protocol liabilities without backing and causing protocol insolvency or theft of the fresh deposit.

Because cleanup burns the debt but does not remove other accounts' supply shares or reduce `supplied`, the inconsistency is persistent rather than a temporary denial of service. [9](#0-8) [8](#0-7) 

### Likelihood Explanation
The trigger is permissionless once a position satisfies the protocol's own bad-debt admission gate, requiring only `clean_bad_debt(caller, account_id)`. [10](#0-9) 

The economic precondition is strong: the borrow position's accrued debt must be at least the total value represented by all supply shares in that market. It can be reached when borrowed liquidity was withdrawn and negative carry later makes residual debt exceed total supplier claims; liquidation does not prevent the state if the remaining collateral reaches the dust-gated cleanup condition.

No privileged call, oracle manipulation, leaked key, or contract upgrade is required for the corrupting write itself; the unprivileged cleanup path supplies the `Borrow` seizure that reaches the flawed floor clamp. [11](#0-10) 

### Recommendation
Do not clamp a fully wiped supply index upward while preserving scaled supply balances. For `remaining == 0`, either:

- allow the supply index to become zero and prevent further supply/withdrawal until the market is explicitly reset or recapitalized, or
- introduce a market-generation/reset mechanism that invalidates all pre-wipeout `scaled_amount` balances before accepting new supply.

If nonzero indexes are required for arithmetic, the cleanup must instead burn or rebase every outstanding scaled supply claim consistently with the remaining backing. Add an invariant that after `remaining == 0`, the aggregate `supplied * supply_index` claim is also zero.

### Proof of Concept
1. Let `M = HubAssetKey { hub_id: H, asset: A }` be an active market.
2. Account `S` holds `S_scaled > 0` supply shares in `M`.
3. Account `B` holds `D_scaled > 0` debt in `M`, with only dust-valued collateral remaining.
4. Time and accrual make `D_scaled * borrow_index >= supplied * supply_index`, so `B` satisfies the permissionless dust-capped bad-debt gate.
5. Call `Controller::clean_bad_debt(attacker, B)`.
6. `execute_bad_debt_cleanup` sends `B`'s debt as a `PoolSeizeEntry` with `side = AccountPositionType::Borrow`. [12](#0-11) 
7. The pool computes `remaining = 0`, obtains a zero index, then restores it to `SUPPLY_INDEX_FLOOR_RAW`. [8](#0-7) 
8. `S_scaled` remains stored and now has claim `S_scaled * (RAY / 1000)`, even though the bad debt consumed the entire prior supplied value.
9. A victim supplies `F` to `M`; the stale claim can withdraw against `F`, leaving the fresh supplier's recorded claim above the remaining cash.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

/// Authorizes permissionless dust-gated cleanup outside flash loans.
pub(crate) fn process_clean_bad_debt(env: &Env, caller: &Address, account_id: u64) {
    caller.require_auth();
    validation::require_not_flash_loaning(env);
    clean_bad_debt_standalone(env, account_id);
}

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
