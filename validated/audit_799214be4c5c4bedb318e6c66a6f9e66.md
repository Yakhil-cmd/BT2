### Title
Mass-assignment of unverified `shared_address` in `prosaic_contract_shared` allows a cosigner to substitute a fraudulent escrow address - (File: `prosaic_contract.js`)

### Summary
The `prosaic_contract_shared` device-message handler in `wallet.js` and the corresponding `store()` function in `prosaic_contract.js` persist an entire attacker-supplied contract object into the local `prosaic_contracts` table, including the `shared_address` field, without independently verifying that this address is the one actually derivable from the contract's parties. This mirrors the CVE-2024-10359 class of bug: the backend blindly saves whatever object fields the caller provides instead of validating/recomputing security-relevant attributes.

### Finding Description
`wallet.js`'s `prosaic_contract_shared` case only validates title/text/creation_date/hash/addresses, then calls straight into [1](#0-0)  `prosaic_contract.store(body)`.

`store()` unconditionally copies `objContract.shared_address` into the INSERT if present, with no re-derivation or cross-check against the contract's actual parties: [2](#0-1) .

This is inconsistent with the code's own "correct" pattern for accepting a shared address, `handleReceivedSharedAddress()`, which re-derives the expected shared address from the contract's `my_address`/`peer_address`/device addresses via `deriveSharedAddress()` and only accepts the value if it matches exactly: [3](#0-2)  and [4](#0-3) .

The `arbiter_contract.js` equivalent (`store`) at least gates the extra `shared_address`/`unit` fields behind `bFromCosigner`, and separately validates any subsequently-received `shared_address` value through `handleReceivedSharedAddress`, which performs the same address re-derivation check: [5](#0-4)  and [6](#0-5) . `prosaic_contract.store()` has no such gating at all — any caller of `store()` can smuggle in `shared_address`.

The `prosaic_contract_shared` message is only accepted from a device address confirmed to be a signing-path cosigner of the wallet that owns `my_address`: [7](#0-6) . This satisfies the "paired device" attack surface allowed by scope — a cosigner is a paired/authenticated peer, but is not necessarily trusted to assert facts about a *different* contract negotiated between the local user and a third-party counterparty.

### Impact Explanation
`shared_address` is meant to represent a 2-of-2 multisig address jointly controlled by the contract's offeror and acceptor (`deriveSharedAddress`, `["and",[["address",offeror],["address",acceptor]]]`). If a malicious cosigner can inject an arbitrary `shared_address` value via `prosaic_contract_shared` without the recomputation check that `handleReceivedSharedAddress` performs, the victim's wallet ends up associating a prosaic contract with an address that was never validated to actually require both parties' signatures. Any UI or automated flow that subsequently treats `contract.shared_address` as the address to fund/pay into (the same usage pattern as `arbiter_contract.js`'s `createSharedAddressAndPostUnit`, which sends `CHARGE_AMOUNT` funds to `contract.shared_address`) could be tricked into sending funds to an address the attacker fully or partially controls, resulting in fund loss/misdirected payment — an integrity/fund-safety impact analogous to the original CVE's UI-spoofing impact, but with a monetary consequence in this codebase.

### Likelihood Explanation
Exploitation requires the attacker to already be a confirmed cosigner (paired device with a signing path) on the wallet holding `my_address` used in the contract — this narrows the population of attackers but does not eliminate the class of bug, since cosigners are not automatically trusted with respect to contracts the wallet has with third parties. Given the explicit "trusted to reflect true status" comment in the analogous `arbiter_contract.js` code, this appears to be a known design pattern that was inconsistently hardened between the arbiter and prosaic contract implementations — `prosaic_contract.store()` lacks the `bFromCosigner` gating and shared-address re-derivation safeguard present elsewhere.

### Recommendation
In `prosaic_contract.js`'s `store()`, do not persist `objContract.shared_address` (or any other status-transition field) directly from an untrusted/received object. Require that `shared_address` only ever be set through `handleReceivedSharedAddress()`, which re-derives and compares the expected address, exactly as the update path in `wallet.js`'s `prosaic_contract_update` case already does. Strip `shared_address` (and any other sensitive field) from the object before calling `store()` in the `prosaic_contract_shared` handler, mirroring the `delete body.shared_address;` already done for `prosaic_contract_offer`.

### Proof of Concept
1. Attacker device B is a confirmed cosigner (signing path holder) of victim A's wallet that contains address `my_address`.
2. Victim A negotiates a prosaic contract with a legitimate counterparty C using `my_address`, and the contract is later shared to cosigner B via a `prosaic_contract_shared` message (the normal cosigner-sync flow), or attacker B directly sends a forged `prosaic_contract_shared` message to A's device with a matching hash/title/text/creation_date but a `shared_address` field set to an address B fully controls.
3. Because `wallet.js`'s `prosaic_contract_shared` handler performs no verification on `shared_address` and forwards the whole `body` to `prosaic_contract.store(body)`, and `store()` inserts `shared_address` unconditionally when present [8](#0-7) , victim A's local `prosaic_contracts` row is updated/created with the attacker-chosen `shared_address`.
4. Any subsequent flow paying into `contract.shared_address` (or displaying it as the verified escrow address) uses the forged value instead of the properly-derived 2-of-2 address, unlike the `handleReceivedSharedAddress` path that would have rejected a mismatched address.

function deriveSharedAddress(contract, bOfferor) {
	const offeror_address = bOfferor ? contract.my_address : contract.peer_address;
	const acceptor_address = bOfferor ? contract.peer_address : contract.my_address;
	const offeror_device_address = bOfferor ? device.getMyDeviceAddress() : contract.peer_device_address;
	const acceptor_device_address = bOfferor ? contract.peer_device_address : device.getMyDeviceAddress();
	var arrDefinition =
		["and", [
			["address", offeror_address],
			["address", acceptor_address]
		]];

	var assocSignersByPath = {
		"r.0": {
			address: offeror_address,
			member_signing_path: "r",
			device_address: offeror_device_address
		},
		"r.1": {
			address: acceptor_address,
			member_signing_path: "r",
			device_address: acceptor_device_address
		},
	};
	return { arrDefinition, assocSignersByPath };
}

function handleReceivedSharedAddress(contract, shared_address, retry_count = 0) {
	console.log(`received shared address ${shared_address} for prosaic contract ${contract.hash} from peer`);
	db.query("SELECT 1 FROM shared_addresses WHERE shared_address=?", [shared_address], function (rows) {
		if (rows.length === 0) {
			if (retry_count >= 10)
				return console.log(`shared address ${shared_address} not found in db after 10 retries, giving up`);
			console.log(`shared address ${shared_address} not yet in db, waiting for 30 seconds and trying again`);
			return setTimeout(handleReceivedSharedAddress, 30000, contract, shared_address, retry_count + 1);
		}
		console.log(`shared address ${shared_address} found in db, deriving shared address definition to verify it matches the received one`);
		const { arrDefinition } = deriveSharedAddress(contract, false);
		const expected_shared_address = objectHash.getChash160(arrDefinition);
		if (expected_shared_address !== shared_address)
			return console.log(`expected shared address ${expected_shared_address} does not match received from offeror ${shared_address}`, JSON.stringify(arrDefinition, null, 2));
		console.log(`shared address ${expected_shared_address} matches the received one, saving it to the contract`);
		setField(contract.hash, "shared_address", shared_address);
	});
}

function handleReceivedSharedAddress(hash, shared_address, from_cosigner, retry_count = 0) {
	console.log(`received shared address ${shared_address} for arbiter contract ${hash} from peer`);
	db.query("SELECT 1 FROM shared_addresses WHERE shared_address=?", [shared_address], function (rows) {
		if (rows.length === 0) {
			if (retry_count >= 10)
				return console.log(`shared address ${shared_address} not found in db after 10 retries, giving up`);
			console.log(`shared address ${shared_address} not yet in db, waiting for 30 seconds and trying again`);
			return setTimeout(handleReceivedSharedAddress, 30000, hash, shared_address, from_cosigner, retry_count + 1);
		}
		console.log(`shared address ${shared_address} found in db, deriving shared address definition to verify it matches the received one`);
		deriveSharedAddress(hash, false, function (err, arrDefinition, assocSignersByPath) {
			if (err) {
				if (retry_count >= 10)
					return console.log(`failed derivation of shared address ${shared_address} after 10 retries, giving up`, err);
				console.log("error deriving shared address definition, will retry in 30 seconds", err);
				return setTimeout(handleReceivedSharedAddress, 30000, hash, shared_address, from_cosigner, retry_count + 1);
			}
			const expected_shared_address = objectHash.getChash160(arrDefinition);
			if (expected_shared_address !== shared_address)
				return console.log(`expected shared address ${expected_shared_address} does not match received from offeror ${shared_address}`, JSON.stringify(arrDefinition, null, 2));
			console.log(`shared address ${expected_shared_address} matches the received one, setting it to the contract and sharing with cosigners`);
			setField(hash, "shared_address", shared_address, function (contract) {
				eventBus.emit("arbiter_contract_update", contract, "shared_address", shared_address);
			}, from_cosigner);
		});
	});
