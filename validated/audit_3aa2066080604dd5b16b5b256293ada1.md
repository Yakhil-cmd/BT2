### Title
Single-Step `governance.governingnode` Change Lacks New-Address Validation, Permanently Locking `single`-Mode Governance — (`kaiax/gov/headergov/impl/header.go`)

---

### Summary

In `single` governance mode (the mode used by Mainnet and Kairos), only the address stored in `governance.governingnode` may cast governance votes. The `checkConsistency` function that validates a `GovernanceGoverningNode` vote checks whether the **current** governing node is in the council, but never validates that the **new** governing node address (the vote value) is in the council or is otherwise a controllable address. If the current governing node votes to transfer itself to an address that no one controls, the governance system is permanently locked after the vote is ratified.

---

### Finding Description

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` handles the `GovernanceGoverningNode` case as follows:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    if slices.Contains(council, params.GoverningNode) {
        return nil
    }
    return ErrGovNodeNotInValSetList
``` [1](#0-0) 

The guard `slices.Contains(council, params.GoverningNode)` checks whether the **current** `GoverningNode` (`params.GoverningNode`) is in the council — it does not inspect `vote.Value()`, which is the **new** address being proposed. The `FormatChecker` for `GovernanceGoverningNode` only verifies the value is a valid `common.Address` type:

```go
GovernanceGoverningNode: {
    Canonicalizer: addressCanonicalizer,
    FormatChecker: func(cv any) bool {
        _, ok := cv.(common.Address)
        return ok
    },
    ...
    DefaultValue: common.HexToAddress("0x0000000000000000000000000000000000000000"),
},
``` [2](#0-1) 

Any non-zero 20-byte address passes both checks. There is no validation that the proposed new governing node is in the council, is a validator, or is an address anyone controls.

The `Vote` API enforces that only the current governing node may submit votes in `single` mode:

```go
if gMode == "single" && voter != gp.GoverningNode {
    return "", ErrVotePermissionDenied
}
``` [3](#0-2) 

And `VerifyVote` enforces the same constraint on-chain:

```go
if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
    params.GovernanceMode == "single" &&
    vote.Voter() != params.GoverningNode {
    return ErrVotePermissionDenied
}
``` [4](#0-3) 

Once a `governance.governingnode` vote for an uncontrollable address is ratified at epoch boundary `k`, the new governing node takes effect at epoch `k+1`. From that point, `ErrVotePermissionDenied` is returned for every governance vote from any real node, and no further governance parameter changes are possible.

---

### Impact Explanation

The corrupted protected-state value is `ParamSet.GoverningNode` (stored in `header.Governance` at epoch blocks and persisted in the node's governance database). Once set to an address no one controls:

- All governance parameter changes are permanently blocked: unit price, minting amount, committee size, epoch length, base fee bounds, reward ratios, `GovParamContract`, and `GovernanceMode` itself.
- Validator additions and removals via `governance.addvalidator` / `governance.removevalidator` are blocked.
- The mode cannot be changed back to `none` to restore open voting.
- Recovery requires a hard fork or full redeployment of the chain.

This matches the "Allowed Impact" gate: **governance privilege escalation that changes protected chain state** (the governing node address is the root of all `single`-mode governance authority).

---

### Likelihood Explanation

The current governing node must either make a typo/copy-paste error when specifying the new address, or be socially engineered into voting for an attacker-supplied address. The probability is low but non-zero — identical to the M-02 assessment. The impact is irreversible without a hard fork, making this a medium-risk finding (low probability × high impact).

---

### Recommendation

In `checkConsistency` for `GovernanceGoverningNode`, add a validation that the **vote value** (the proposed new governing node) is present in the current council before accepting the vote:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    // Existing check: current governing node must still be in council.
    if !slices.Contains(council, params.GoverningNode) {
        return ErrGovNodeNotInValSetList
    }
    // NEW: proposed new governing node must also be in council.
    newGovNode, ok := vote.Value().(common.Address)
    if !ok || !slices.Contains(council, newGovNode) {
        return ErrGovNodeNotInValSetList
    }
    return nil
```

This mirrors the two-step pattern recommended in M-02: the new address must already be a known, active council member before it can be designated as the governing node, ensuring the key is reachable.

---

### Proof of Concept

1. Chain is running in `single` governance mode with `governingNode = A` (a valid council member).
2. Node A calls `governance_vote("governance.governingnode", B)` where `B` is any 20-byte address not in the council (e.g., `0xdead...`).
3. `checkConsistency` runs: `params.GoverningNode == A`, `slices.Contains(council, A) == true` → returns `nil` (vote accepted). The vote value `B` is never checked.
4. The vote is inscribed in a block header at epoch `k`.
5. At epoch block `k`, the ratification is written to `header.Governance`.
6. Starting from epoch `k+1`, `GetParamSet` returns `GoverningNode = B`.
7. Any subsequent call to `governance_vote` from any real node returns `ErrVotePermissionDenied` because no one holds the key for `B`.
8. All governance-gated operations are permanently frozen. [5](#0-4) [2](#0-1) [6](#0-5)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}
