### Title
Unsanitized attacker-controlled alias names/expansions can inject terminal escape sequences during `gh alias import` - (File: pkg/cmd/alias/imports/import.go)

### Summary
`importRun` builds a status message from YAML map keys (alias names) and values (expansions) using `fmt.Fprintf` and `cs.Bold(alias)`, then writes it verbatim to `opts.IO.ErrOut` when stdout is a TTY. Neither the alias name nor the expansion is passed through the codebase's existing control-sequence sanitizer before being embedded in that message, unlike other places in the CLI that handle untrusted remote text.

### Finding Description
`importRun` reads a YAML file (`cmdutil.ReadFile`) and unmarshals it into `aliasMap` at [1](#0-0)  without any restriction on byte content of keys/values. For each alias, when validation fails (`!opts.validAliasName(alias)`) and the alias does not already exist, the raw alias string is written straight into `msg` via `cs.Bold(alias)`: [2](#0-1) . The same unsanitized embedding happens for the "name already taken", "expansion does not correspond..." and "Added/Changed alias" success messages: [3](#0-2) .

Critically, `ValidAliasNameFunc` only tokenizes the string with `shlex.Split` and checks whether it resolves to a non-runnable command; it does not reject non-printable or ANSI escape bytes (`\x1b[...`) — `shlex.Split` treats them as ordinary characters unless they interfere with quoting: [4](#0-3) . Because such an alias will almost always fail `rootCmd.Find`, it takes the "Could not import alias %s: already a gh command or extension" branch, which is reached without ever depending on the alias being a valid command — meaning **any arbitrary attacker-chosen byte string** (as long as it round-trips through `shlex.Split` without error) reaches the message buffer.

The buffer is only flushed if `opts.IO.IsStdoutTTY()` is true, via `fmt.Fprintln(opts.IO.ErrOut, msg.String())` at [5](#0-4) , with no call to the CLI's own control-sequence sanitizer. The codebase does have exactly this kind of sanitizer (`SanitizeControlSequences`) used elsewhere for untrusted remote text such as PR/issue titles, gist descriptions, and workflow/run names [6](#0-5) [7](#0-6) , confirming this is a known threat model the CLI otherwise defends against — but the alias-import path does not apply it.

### Impact Explanation
A victim who runs `gh alias import <attacker-file.yml>` (or pipes attacker content via `gh alias import -`, e.g. from a downloaded gist or repo file) with stdout attached to a terminal will have arbitrary escape sequences from the YAML content written to their terminal via stderr. This can be used for terminal/prompt spoofing, hiding or altering subsequent CLI output, or moving the cursor to overwrite prior trusted output — a terminal injection/output-spoofing issue. It does not achieve code execution or credential exfiltration on its own, so it maps to a low/moderate "spoofing/UI misrepresentation" impact class rather than a high-severity RCE or token-leak class.

### Likelihood Explanation
Exploitation requires the victim to explicitly run `gh alias import` against attacker-supplied YAML with a TTY stdout — a plausible but non-default action (unlike passive commands e.g. `gh repo view`). The escape payload just needs to be shlex-splittable (e.g., wrapped in quotes or using benign characters around the escape bytes), which is straightforward. No authentication, token, or elevated privilege is needed by the attacker; they only need to get the victim to import their YAML file.

### Recommendation
Sanitize `alias` and `expansion` (and any other externally-derived text) with the existing `text.SanitizeControlSequences` / iostreams sanitization helper before embedding them into `msg`, or strip non-printable characters from YAML keys/values immediately after `yaml.Unmarshal` and before any use, matching the pattern already applied to other untrusted text fields (issue titles, gist descriptions, etc.) in the codebase.

### Proof of Concept
```go

    ios, _, _, stderr := iostreams.Test()
    ios.SetStdoutTTY(true)
    ios.SetStderrTTY(true)

    yamlInput := fmt.Sprintf("%s: issue list\n", payload)

    opts := &ImportOptions{
        IO:       ios,
        Config:   func() (gh.Config, error) { return cfg, nil },
        Filename: "-",

        validAliasExpansion: func(s string) bool { return true },
    }
    ios.In = io.NopCloser(strings.NewReader(yamlInput))

    err := importRun(opts)
    assert.NoError(t, err)

    // Expected (failing) assertion: escape sequence should be stripped/escaped
    assert.NotContains(t, stderr.String(), "\x1b[2J")
}
```
Running this test against the current `importRun` implementation shows `stderr` contains the raw `\x1b[2J` sequence, confirming the injection reaches the terminal unsanitized.

func ValidAliasNameFunc(cmd *cobra.Command) func(string) bool {
	return func(args string) bool {
		split, err := shlex.Split(args)
		if err != nil || len(split) == 0 {
			return false
		}

		rootCmd := cmd.Root()
		foundCmd, foundArgs, _ := rootCmd.Find(split)
		if foundCmd != nil && !foundCmd.Runnable() && len(foundArgs) == 1 {
			return true
		}

		return false
	}
}
