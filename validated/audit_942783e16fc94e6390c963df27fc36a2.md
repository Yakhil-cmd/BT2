### Title
`ProxyType::NonTransfer` falsely claims superset containment of `ProxyType::Auction`, letting a `NonTransfer` proxy escalate to `Registrar::swap` — ([File: substrate/frame/staking-async/runtimes/rc/src/lib.rs])

### Summary
In `substrate/frame/staking-async/runtimes/rc/src/lib.rs` (a relay-chain runtime the file's own doc comment calls "The Westend runtime", built for the `pallet-staking-async` migration), `ProxyType::is_superset` uses a catch-all `(ProxyType::NonTransfer, _) => true` [1](#0-0)  that declares `NonTransfer` a superset of every other proxy type, including `Auction`. But `NonTransfer`'s own call filter explicitly *excludes* `Registrar::swap` [2](#0-1)  while `Auction`'s filter admits the entire `Registrar(..)` call family, `swap` included [3](#0-2) . This is the exact same bug class the project already fixed for `NonTransfer`/`Governance` on Asset Hub Westend (`prdoc/pr_12769.prdoc`) [4](#0-3) , but it is still present here for `NonTransfer`/`Auction`.

### Finding Description
`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` sub-calls executed *through* an existing proxy solely on `is_superset`, not on `filter`: [5](#0-4) 

Because `NonTransfer.is_superset(&Auction)` returns `true` in this runtime, a delegate holding only a `NonTransfer` proxy grant is permitted to call `Proxy::add_proxy` (or `remove_proxy`) with `proxy_type: ProxyType::Auction` on behalf of the real account, since that check only rejects the sub-call when `!def.proxy_type.is_superset(proxy_type)`. This is exactly the invariant violation described in the hexpm analog: a caller holding a restricted permission scope (`NonTransfer`, analogous to "api:read") is treated as authorized to grant/obtain a broader, differently-scoped credential (`Auction`, analogous to full "api") because a downstream check trusts a declared containment relationship (`is_superset`) instead of re-validating the concrete permitted-call set (`filter`).

Once the `Auction` proxy relation is registered for the real account, the delegate can subsequently dispatch calls under `ProxyType::Auction`, whose filter admits `Registrar::swap` — a call `NonTransfer`'s own filter deliberately omits (the source comment literally reads "Specifically omitting Registrar `swap`" [6](#0-5) ), demonstrating the runtime authors intended `swap` to be inaccessible to `NonTransfer` delegates.

This mirrors the already-patched `NonTransfer`/`Governance` bug in `asset-hub-westend-runtime` [7](#0-6) , whose fix and regression test explicitly document the invariant that any declared `is_superset` relation must be validated against the actual `filter` admission set [8](#0-7) . That lattice-consistency regression test (`proxy_type_superset_relation_matches_call_filters`) does not exist for the `staking-async` `rc` runtime, so the reintroduced instance of the bug class went undetected here.

### Impact Explanation
An account owner who grants only a `NonTransfer` proxy (intended to exclude value-moving and sensitive administrative calls such as `Registrar::swap`) is unknowingly exposed to a delegate who can self-escalate to `ProxyType::Auction` and execute `Registrar::swap`, a call the delegator never authorized and which the runtime's own filter comments flag as deliberately withheld from `NonTransfer`. This breaks the confidentiality/integrity guarantee of the proxy permission model: a strictly-scoped delegate obtains access to a functionally disjoint, more powerful scope, without the real account owner's consent — the same authorization-boundary violation pattern as the hexpm OAuth report (a restricted-scope credential silently escalating to a broader scope through a missing/incorrect check in the intermediate authorization layer).

### Likelihood Explanation
Reachable by any account owner who has granted a `NonTransfer` proxy — a common, legitimately advertised "safe" delegation type — to any third party. No governance, root, or validator/collator privilege is needed; the attacker only needs to already hold a `NonTransfer` proxy relationship (a normal, low-trust grant pattern) and issue two ordinary signed `Proxy::proxy` extrinsics. The check that fails is a pure runtime-configuration logic error (`is_superset` catch-all), deterministically triggered, not dependent on race conditions or external state.

### Recommendation
Remove the blanket `(ProxyType::NonTransfer, _) => true` arm and enumerate only the pairs where `NonTransfer`'s filter is provably a superset of the target type's filter (as was done for the `asset-hub-westend` fix), or add an automated lattice-consistency test (mirroring `proxy_type_superset_relation_matches_call_filters` in `asset-hub-westend`) to this runtime's test suite to catch `is_superset`/`filter` mismatches for every `ProxyType` pair, including `NonTransfer` vs `Auction`, `ParaRegistration`, `Staking`, `NominationPools`, etc.

### Proof of Concept
Reproduction path (integration-test-style, using the existing `pallet_proxy` test harness pattern already used in `substrate/frame/proxy/src/tests.rs` [9](#0-8) , adapted to this runtime's `ProxyType`):
1. Real account `R` calls `Proxy::add_proxy(delegate: D, proxy_type: NonTransfer, delay: 0)`.
2. `D` calls `Proxy::proxy(real: R, proxy_type: None, call: Proxy::add_proxy{ delegate: D, proxy_type: Auction, delay: 0 })`. This succeeds because `do_proxy`'s origin filter only rejects `add_proxy`/`remove_proxy` sub-calls when `!def.proxy_type.is_superset(proxy_type)`, and `NonTransfer.is_superset(&Auction) == true` per [10](#0-9) .
3. `D` calls `Proxy::proxy(real: R, proxy_type: Some(Auction), call: Registrar::swap{ id: ..., other: ..., other_para_info: ... })`. `ProxyType::Auction::filter` admits `RuntimeCall::Registrar(..)` unconditionally [3](#0-2) , so the call dispatches under `R`'s authority even though `R` only ever authorized `D` for `NonTransfer`, whose own filter explicitly denies `swap`.

I could not execute this against the live test harness within the available tool budget (read-only code inspection only), so this is a static-analysis-derived reproduction path, not an executed test run; the code paths and comments cited above directly support each step of the escalation. I was also unable to fully confirm from the index whether `substrate/frame/staking-async/runtimes/rc` is already deployed as a live network runtime or is still a pre-production reference runtime for the staking-async migration — its own doc comment calls it "The Westend runtime," but I could not verify current deployment status with the tools available, so program eligibility should be confirmed separately.

		def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
		real: T::AccountId,
		call: <T as Config>::RuntimeCall,
	) {
		use frame::traits::{InstanceFilter as _, OriginTrait as _};
		// This is a freshly authenticated new account, the origin restrictions doesn't apply.
		let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
		origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
			let c = <T as Config>::RuntimeCall::from_ref(c);
			// We make sure the proxy call does access this pallet to change modify proxies.
			match c.is_sub_type() {
				// Proxy call cannot add or remove a proxy with more permissions than it already
				// has.
				Some(Call::add_proxy { ref proxy_type, .. }) |
				Some(Call::remove_proxy { ref proxy_type, .. })
					if !def.proxy_type.is_superset(proxy_type) =>
				{
					false
				},
				// Proxy call cannot remove all proxies or kill pure proxies unless it has full
				// permissions.
				Some(Call::remove_proxies { .. }) | Some(Call::kill_pure { .. })
					if def.proxy_type != T::ProxyType::default() =>
				{
					false
				},
				_ => def.proxy_type.filter(c),
			}
		});

/// `pallet_proxy` authorizes `add_proxy`/`remove_proxy` through `ProxyType::is_superset`, so a
/// proxy type that *declares* itself a superset of another must also *admit* every call that other
/// type admits. Otherwise the "smaller" type is reachable as an escalation: the declared superset
/// can grant itself the subset proxy and thereby gain permissions its own filter denies.
///
/// This checks that property across the whole lattice rather than a single pair, so the class of
/// bug cannot silently reappear on another edge.
#[test]
fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
