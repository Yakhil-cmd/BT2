The Redstone bug relies on a permissionless, user-supplied off-chain price update to a local cache gated by a fixed cool-down (`maxCacheStaleness`) that can block legitimate refreshes during volatility. In this codebase, the closest analog is `pallet-oracle` under `substrate/frame/honzon/oracle/src/lib.rs`, but it does not share the vulnerable structure:

- `feed_values` is only callable by accounts in the permissioned `Members: SortedMembers` set (or root), not by an arbitrary unprivileged user, so there is no analog to Redstone's "anyone can push a verified off-chain price" entry point [1](#0-0) .
- The only submission restriction is "one feed per operator per block" via `HasDispatched`, which is cleared every block in `on_finalize`, so operators can always submit a fresh value on the very next block — there is no `maxCacheStaleness`-style cooldown that locks out legitimate price updates during high volatility [2](#0-1) .
- `Values`/`RawValues` are updated immediately once `CombineData` (median) produces a result, with no artificial delay window comparable to the Redstone `cacheUpdatedAt`/`maxCacheStaleness` gate [3](#0-2) .

Since the entry point is governance/membership-gated rather than open to an arbitrary attacker, and there is no staleness-based lockout mechanism blocking timely price refresh, this does not reproduce the violated invariant (permissionless update blocked by an artificial staleness window) required by the report, and no other price-caching/oracle pattern matching that structure was found in the indexed code.

	fn do_feed_values(who: T::AccountId, values: Vec<(T::OracleKey, T::OracleValue)>) {
		let now = T::Time::now();
		for (key, value) in &values {
			let timestamped = TimestampedValue { value: value.clone(), timestamp: now };
			RawValues::<T, I>::insert(&who, key, timestamped);

			// Update `Values` storage if `combined` yielded result.
			if let Some(combined) = Self::combined(key) {
				<Values<T, I>>::insert(key, combined);
			}

			T::OnNewData::on_new_data(&who, key, value);
		}
		Self::deposit_event(Event::NewFeedData { sender: who, values });
	}
