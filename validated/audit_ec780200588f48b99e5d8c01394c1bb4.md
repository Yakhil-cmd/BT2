### Title
Third-party supply top-up straddles the $5 dust gate and permanently blocks permissionless bad-debt cleanup — (File: contracts/controller/src/positions/supply.rs)

### Summary
`clean_bad_debt` is the permissionless path that socializes an insolvent account's residual debt, but it only admits accounts whose total collateral is at or below `BAD_DEBT_USD_THRESHOLD` (5 USD). Any unprivileged address can call `supply` on a foreign account to top up a collateral leg that account already holds (`require_third_party_existing_supply` only enforces that the asset is an existing supply position, per INV-AUTH-03). A ~$5 donation to a qualifying account pushes its collateral just above the cap, closing the dust gate while the account remains insolvent (`D > C`), so every subsequent `clean_bad_debt` reverts with `CannotCleanBadDebt` (#114). The gate is value-based, not count-based, but the cheapest blocking state is `BAD_DEBT_USD_THRESHOLD + 1` — confirmed symbolically by the `bad_debt_straddle_blocks_dust_gate` rule.

### Finding Description
CVE-2016-8327 is a denial-of-service class bug (hang/crash leaving the system unable to serve its function). The analog here is a reachable freeze of the protocol's bad-debt resolution path.

Two facts combine:

1. `is_socializable_bad_debt` requires `total_debt > total_collateral && total_collateral <= 5 WAD` (`curve.rs:25-27`), enforced for the permissionless gate in `socialize_bad_debt` (`mod.rs:229-235`).
2. `process_supply` permits a third party to add funds to any *existing* supply leg of an account it does not own (`supply.rs:61`, `78-97`; `scripts/permissionless_entrypoints.txt:69`).

An attacker (or the defaulting borrower themself) tops up the existing collateral leg with just over $5 of value. The account stays insolvent, but `clean_bad_debt` now reverts forever. The only remaining cleanup path is `force_socialize_bad_debt`, which is owner/governance-only behind the Sensitive timelock (`mod.rs:246-248`, `docs/reference/runbooks/force-socialize-bad-debt.md`). Ordinary liquidation is the nominal alternative, but dust-gate accounts are precisely the unprofitable residue liquidation leaves behind; the test `deep_underwater_account_still_liquidates_to_the_dust_gate` shows liquidation stalls exactly at this boundary.

### Impact Explanation
While the gate is blocked, the insolvent account's debt is never written down: the supply index is not adjusted, `PoolInsolvent` conditions persist for affected markets, and suppliers' displayed claims remain overstated relative to cash plus real debt. The bad debt, accrued interest, and corresponding supplier value stay frozen on the books until governance schedules and executes a forced cleanup — a temporary freezing of funds / protocol-insolvency persistence reachable by a single unprivileged transaction costing ~$5, repeatedly re-appliable after any forced cleanup cycle on new dust accounts.

### Likelihood Explanation
Fully permissionless: requires only `caller.require_auth`, a listed collateral asset the account already supplies, and ~$5 of tokens. The attacker can monitor for accounts approaching the dust gate and top them up ahead of keepers; a self-interested defaulting borrower can do it to their own account. Cost is bounded by the threshold plus margin, and the straddle is durable (collateral only shrinks via liquidation, which the account's unprofitability already deters).

### Recommendation
Make the dust gate robust to straddling, e.g. treat donated value above the threshold as part of the socialization (net it into the write-down), or replace the static `<= $5` cap with a check that collateral is immaterial relative to debt (e.g. `C < D / k`), so raising collateral past a fixed line cannot indefinitely defer cleanup.

### Proof of Concept
```rust
// Account V is insolvent at the dust gate: debt > collateral, collateral <= 5 USD.
// Attacker (or V's owner) tops up V's existing USDC supply leg:
controller.supply(attacker, v_account_id, v_spoke_id, vec![HubPayment {
    hub_asset: usdc_hub_asset, // must already be a supply position of V
    amount: 6 * USDC_UNIT,     // pushes total_collateral above 5 WAD
}]);
// Now: total_debt > total_collateral (still insolvent), but
// total_collateral > BAD_DEBT_USD_THRESHOLD, so:
controller.clean_bad_debt(keeper, v_account_id); // reverts CannotCleanBadDebt (#114)
// Only owner-gated force_socialize_bad_debt remains, behind the timelock.
```
