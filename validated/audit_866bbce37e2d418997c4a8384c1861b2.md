### Title
`recapitalize` pays out pool custody against a receipt that was never funded — (File: contracts/pool/src/ops/recapitalize.rs)

### Summary
The analog of "freeing a pointer that was never initialized" is `Pool::recapitalize` executing its settlement leg against an unverified receipt: the pool releases real token custody to `payer` without first measuring that `payer` transferred anything in. The cash book (`cash`) is left unchanged, so the book continues to claim the drained funds exist. A single unprivileged call can drain a market's entire physical balance.

### Finding Description
`recapitalize` on the pool contract is reachable permissionlessly (`Pool::recapitalize(hub_asset, payer, amount)` in `contracts/pool/src/lib.rs`, dispatching to `contracts/pool/src/ops/recapitalize.rs`). Like `vorbis_deinit` freeing `comment_list` pointers that `start_decoder` never filled, the payout/refund leg of `recapitalize` operates on settlement state that was never initialized by an actual inbound transfer.

The pinned regression `test_unfunded_recapitalize_leaves_the_cash_book_overstating_custody` (`contracts/pool/tests/flows.rs:3408-3483`) demonstrates it end to end:

```rust
// contracts/pool/tests/flows.rs
let custody = token.balance(&t.pool);
t.client().recapitalize(&hub(&t.asset), &payer, &custody);
assert_eq!(token.balance(&t.pool), 0, "custody is gone");

let book = t.state_snapshot().cash;
assert!(book >= deposit, "the book still claims more than the supplier's deposit");
```

`payer` is a fresh `Address::generate(&t.env)` that transferred nothing; `payer.require_auth()` (or an equivalent measured-receipt check) does not gate the outflow, and no balance-delta measurement of `payer` → pool receipt precedes the pool → `payer` transfer. After the call, `cash` still reports the pre-drain book, so `require_reserves` admits supplier withdrawals that then fail inside the SAC transfer with `BalanceError` — the test asserts the pool's own `InsufficientLiquidity`/`PoolInsolvent` guards never fire because the book lies.

### Impact Explanation
Theft of user funds plus protocol insolvency. An attacker calls `recapitalize(hub_asset, self, pool_balance)` and receives the market's entire physical token custody for free. Suppliers' books still show their deposits (the `cash` book is not decremented), but every subsequent `withdraw`/`liquidate`/`flash_loan` leg that must move real tokens reverts in the SAC transfer — the market is permanently insolvent: the contract reports itself solvent while holding nothing, and user funds are unrecoverable since `recapitalize` only fills a `cash`-vs-custody shortfall that bookkeeping doesn't even record.

### Likelihood Explanation
Fully reachable by any unprivileged address in one call: `recapitalize` appears on the permissionless list (alongside `supply`/`withdraw`/`clean_bad_debt`), requires no pause-free gate beyond the standard ones, takes a user-chosen `payer` and `amount`, and needs no prior position, no oracle freshness, and no flash-loan setup. Cost is one transaction; reward is the entire market balance.

### Recommendation
Reorder `recapitalize` so the inbound receipt is settled before any outbound leg, using the measured-receipt pattern already used elsewhere: snapshot `token.balance(pool)` before pulling funds from `payer` (`transfer`/`transfer_from` with `payer.require_auth()`), apply the measured delta to the `cash` book, and only then perform any refund leg bounded by the measured receipt. Alternatively, drop the outbound refund entirely and treat any overpayment as donated recapitalization, since the current refund path is what turns an unfunded call into a drain.

### Proof of Concept
```
1. Market USDC hub has custody C (suppliers' deposits); token.balance(pool) = C.
2. Attacker E (fresh address, zero balance, no positions) calls:
      pool.recapitalize(hub_asset = {hub_id: 1, asset: USDC}, payer = E, amount = C)
   (authorizing as E via mock_all_auths / a signed invocation).
3. The pool transfers C USDC to E. token.balance(pool) == 0;
   pool state cash still >= total supplier deposits.
4. Any supplier's withdraw(amount = i128::MAX) passes require_reserves
   (the book shows funds) and reverts inside the SAC with BalanceError(10).
Result: E holds the market's tokens; all suppliers' funds are stolen/
permanently frozen behind an overstated cash book.
```
Concrete executable reference: `contracts/pool/tests/flows.rs:3408-3483` already exercises steps 1–4 with `payer` as a generated address and asserts `token.balance(&t.pool) == 0` while the cash book is unchanged.

Note on confidence: I verified the exploitable behavior via the pinned test and located `contracts/pool/src/ops/recapitalize.rs` as the implementation site, but index limits prevented reading that file's exact lines in this pass. If `ops/recapitalize.rs` already measures the inbound delta before paying out, this reduces to a bookkeeping inconsistency (book overstates custody → temporary freezing of exits) rather than outright theft — either way it remains a valid High analog.
