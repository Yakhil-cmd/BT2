### Title
Shared-address definitions accepted without verifying the victim's key is actually required to spend - ([File: wallet_defined_by_addresses.js])

### Summary
`handleNewSharedAddress()` in `wallet_defined_by_addresses.js` only performs *structural* checks on a peer-supplied multi-signature address definition (hash matches, every `["address", ...]` leaf maps 1:1 to a declared signer) but never checks the *semantic* authorization logic of the definition tree — i.e., whether the victim's own address is actually a mandatory party to any spending path, as opposed to an optional branch of an `or`. This mirrors the Grav Flex Objects bug: a generic/coarse check (structural validity, general write permission) is substituted for the specific, security-relevant check (does this specific field/party control matter) that a dedicated/careful implementation would perform.

### Finding Description
When a device receives (or a local user is offered) a new shared/multi-sig address, `handleNewSharedAddress(body, callbacks)` is invoked: [1](#0-0) 

It verifies:
1. `body.address === objectHash.getChash160(body.definition)` — the address genuinely corresponds to the definition.
2. Every signer's `address` at a given `signing_path` matches the address extracted from the definition tree at that same path via `extractAddressPathsFromDefinition()`: [2](#0-1) 
3. Every `["address", ...]` leaf found in the definition has a corresponding signer entry.
4. `determineIfIncludesMeAndRewriteDeviceAddress()` merely confirms that *one of my addresses appears somewhere* in the signer map: [3](#0-2) 
5. `validateAddressDefinition()` only calls `Definition.validateDefinition()` for generic syntactic well-formedness (complexity limits, "each branch must have a signature", etc.) — not whether a *specific* address is actually required to authorize spending: [4](#0-3) 

None of these checks validate the boolean structure of the definition to ensure the local user's signature is mandatory. A malicious counterparty can craft a definition such as `['or', [["address", "$address@attacker"], ["address", "$address@victim"]]]` and present it as a shared/joint address. It passes every check above (hash matches, address-to-signer mapping is consistent, syntactically valid definition with "some branch has a signature"), yet spending from this address requires only the attacker's signature — the victim's cosigner role is cosmetic. The code comment at line 519 ("fix: 1. check that my address is referenced in the definition") itself flags that this verification is a known gap, but only checks *presence*, not *necessity* (mandatory-ness) of the address in the authorization logic — even that acknowledged fix would not catch the `or` case described above.

### Impact Explanation
A victim who is led to believe they co-control a newly-created shared address (e.g., an escrow, multisig wallet, or joint payment address) via the `new_shared_address` device message may fund it or accept counterparty funds into it under a false assumption of dual-control. Because the actual definition can allow the attacker to spend unilaterally, this results in concrete unauthorized spending / theft of funds sent to the address by the victim (or by a third party relying on the victim's participation), without any subsequent unit-level fraud — the loss occurs purely because the wallet layer accepted and stored a shared address whose real authorization semantics diverge from what was represented to the user.

### Likelihood Explanation
This is reachable by any paired device/counterparty simply by sending a shared-address proposal message (`new_shared_address` handled via `handleNewSharedAddress`), which is explicitly in the class of "wallet and contract message handling" reachable by a private-payment/paired-device counterparty. No special privilege is needed beyond being a paired device, and the checks that exist (hash match, address-to-path mapping) are the exact kind of surface-level checks that would make the acceptance look legitimate while the underlying `or` semantics silently give full control to the attacker.

### Recommendation
When validating an incoming shared-address definition in `handleNewSharedAddress()` / `validateAddressDefinition()`, additionally evaluate the boolean logic of the definition tree to confirm that every declared party's address (in particular, the local user's own address) is on a *conjunctive* (i.e., truly required) path rather than merely present in some disjunctive branch that can be satisfied without it. Concretely, walk the definition and reject it unless removing the victim's `["address", ...]` (or `["sig", ...]`) leaf would make every top-level `or`/`r of set` branch requiring the necessary signature threshold unsatisfiable, i.e., confirm the local address is present in **all** branches of every enclosing `or`/`r of set` up to the root (or otherwise required by the minimum-signature threshold), not just structurally referenced somewhere in the tree.

### Proof of Concept
1. Attacker device pairs with victim device.
2. Attacker sends `new_shared_address` with:
   - `definition = ['or', [ ['address', attacker_address], ['address', victim_address] ] ]`
   - `signers = { 'r.0': {address: attacker_address, device_address: attacker_device}, 'r.1': {address: victim_address, device_address: victim_device} }`
3. `handleNewSharedAddress()` passes: hash matches, `extractAddressPathsFromDefinition` returns `{r.0: attacker_address, r.1: victim_address}` which matches `signers` exactly, `determineIfIncludesMeAndRewriteDeviceAddress` succeeds because `victim_address` is present, and `validateAddressDefinition` succeeds because the definition is syntactically valid (`or` with each branch having a signature).
4. The shared address is stored in `shared_addresses` and displayed to the victim as a joint/multisig address.
5. Victim (or a third party) sends funds to this address believing both parties must cosign.
6. Attacker spends the funds alone by satisfying only the `['address', attacker_address]` branch — no victim signature is ever required.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){

function extractAddressPathsFromDefinition(arrDefinition) {
	var result = {};
	function traverse(arr, path) {
		if (!Array.isArray(arr) || arr.length < 2) return;
		var op = arr[0];
		var args = arr[1];
		switch (op) {
			case 'or':
			case 'and':
				if (Array.isArray(args))
					for (var i = 0; i < args.length; i++)
						traverse(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				result[path] = args;
				break;
			case 'hash':
				result[path] = 'secret';
				break;
			case 'in merkle':
				result[path] = ''; // empty address
				break;
		}
	}
	traverse(arrDefinition, 'r');
	return result;
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}
