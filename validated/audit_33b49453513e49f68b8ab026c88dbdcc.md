### Title
Webhook signature verification is keyed by an attacker-controlled `organization` field while the event is processed against an attacker-controlled `repository.full_name` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and thus which `webhook_secret`) to verify the signature against by reading `repository_owner` **out of the unauthenticated JSON body itself**, before any signature has been validated. The event is then dispatched with the *same* unauthenticated body to handlers that act on `repository.full_name` / `repository.owner.login` to locate a `Stack`. Because these two fields are read independently from the same untrusted payload, and because a tenant organization with no `webhook_secret` configured makes `verify_webhook_signature` unconditionally return `true`, an attacker can pick the "authenticating organization" field to point at an org with no secret while pointing the "repository being acted on" field at a different, secured org/repo whose stack they want to affect.

### Finding Description
`verify_signature` computes the organization used for verification purely from the request body: [1](#0-0) 

`repository_owner` is derived the same way, straight from JSON the attacker controls: [2](#0-1) 

The verification itself, in `GithubApp#verify_webhook_signature`, is a no-op whenever the resolved organization has no `webhook_secret` configured: [3](#0-2) 

`webhook_secret` is an explicitly supported, documented value that can be `nil` per tenant/org (see the sample multi-org secrets file, which lists `webhook_secret: # nil` for each org): [4](#0-3) 

Once `verify_signature` passes (trivially, because the *attacker-chosen* `repository.owner.login` mapped to an org with no secret), `create` re-parses the same raw, unauthenticated body and dispatches it to whichever handler is registered for `X-Github-Event`: [5](#0-4) 

Handlers (e.g. push/status handlers under `app/models/shipit/webhooks/handlers/`) locate the target `Stack`/`Repository` from `repository.full_name` (or equivalent) in that same body - a field that was never covered by any per-org signature check, since the signature check only used `repository.owner.login`/`organization.login` to pick a secret, not to constrain which repository the payload is allowed to describe.

This is exactly the "organization that authenticated versus the repository that is written" binding break: the equality that should hold is
`organization_whose_secret_verified_signature == organization_owning(repository.full_name)`,
but nothing in the controller enforces it. An attacker can satisfy the left side using an org with a blank `webhook_secret` while making the right side name an arbitrary other repository configured in the same Shipit instance.

### Impact Explanation
If any organization onboarded onto the Shipit instance has no `webhook_secret` set (a state the codebase and its own sample config treat as valid/expected, not a misconfiguration), an unauthenticated network attacker can forge arbitrary GitHub webhook events (`push`, `status`, `check_suite`, `deployment_status`, `membership`, `pull_request`, etc.) for **any repository/stack hosted on that Shipit instance**, not just the org lacking a secret. Depending on which handler processes the event, this can:
- Fabricate commit/status/check-run state used by continuous-delivery gating, potentially causing an unauthorized deploy to be triggered for a stack with `continuous_deployment: true`.
- Inject fabricated `push` events that drive `GithubSyncJob`/commit creation for a targeted stack's repository.
- Create teams/users via the `membership` handler under a targeted org's identity.

This crosses a credential/authentication boundary (webhook signature is supposed to prove the payload came from GitHub for that repository) and can produce an unauthorized deploy/rollback-adjacent state change, matching the Critical/High impact bar for "unauthorized deploy" or "escalation."

### Likelihood Explanation
Exploitability only requires: (1) the Shipit instance hosts more than one GitHub organization/App configuration, and (2) at least one of those has no `webhook_secret` configured - a state the shipped sample config explicitly demonstrates as normal (`webhook_secret: # nil`). No repository write access, no `ApiClient` token, and no authenticated session are needed; the request is a plain unauthenticated POST to `/webhooks`. The only precondition is operator configuration choice, which the engine itself permits and documents, so this is squarely an engine-code trust bug rather than a "host app not mounting the engine as documented" issue.

### Recommendation
Do not select the signature-verification secret from unauthenticated payload content. Instead:
- Verify the HMAC signature against every configured `webhook_secret`, or require a fixed shared/global secret independent of any field in the body, and only *then* trust `repository.owner.login` for routing.
- Alternatively, once a signature is verified for organization `O`, reject/ignore any handler action whose target repository does not belong to `O`.
- Treat a missing `webhook_secret` as "reject all payloads claiming this org" rather than "accept all payloads unconditionally," or require `webhook_secret` to be mandatory for any org configuration.

### Proof of Concept
1. Configure (or observe) a Shipit instance with two orgs in `Shipit.github`, e.g. `low-value-org` (no `webhook_secret`) and `victim-org` (has a stack, has `webhook_secret` set).
2. Send, without any valid `X-Hub-Signature`:
```
POST /webhooks
X-Github-Event: push
Content-Type: application/json

{
  "repository": {
    "owner": { "login": "low-value-org" },
    "full_name": "victim-org/victim-repo"
  },
  "after": "<attacker-chosen sha>",
  ...
}
```
3. `verify_signature` resolves `repository_owner` = `"low-value-org"`, calls `Shipit.github(organization: "low-value-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` unconditionally.
4. `create` dispatches the same JSON to the `push` handler, which resolves the target stack by `full_name: "victim-org/victim-repo"`, processing the forged event as if it legitimately came from GitHub for `victim-org`. [6](#0-5) [3](#0-2)

```ruby
# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
