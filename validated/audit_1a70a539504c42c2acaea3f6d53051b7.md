### Title
Signature-verification key is selected from the unverified payload, decoupling the "authenticated organization" from the repository whose data is mutated - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks which GitHub App/organization config to use for HMAC verification from a value taken out of the *unverified* request body, and `GitHubApp#verify_webhook_signature` trivially returns `true` whenever that selected organization has no `webhook_secret` configured. The handlers invoked afterwards (`StatusHandler`, `PushHandler`) then act on data (commit SHA, branch, repository) taken from the very same unverified body, with no re-check that the "authenticated" organization actually owns the repository being mutated. This breaks the intended binding: *the organization whose secret validated the request* must equal *the repository/stack whose state the request is allowed to change*.

### Finding Description
1. `verify_signature` is a `before_action` that runs before the body has been cryptographically validated: [1](#0-0) 

`repository_owner` is derived straight from `params.dig('repository','owner','login') || params.dig('organization','login')` — fields inside the JSON body itself: [2](#0-1) 

2. `Shipit.github(organization: repository_owner)` looks up the per-organization config for that attacker-chosen name, and `verify_webhook_signature` unconditionally accepts the request if that organization has no secret configured: [3](#0-2) 

The engine's own reference configuration explicitly supports organizations with a blank `webhook_secret`: [4](#0-3) 

3. Once "verified" this way, the event handlers operate on globally-scoped lookups that are **not** filtered by the organization that was used for verification: [5](#0-4) [6](#0-5) 

`StatusHandler#process` finds `Commit.where(sha: params.sha)` across the entire install and writes a CI status; `PushHandler#process` finds any non-archived `Stack` matching the branch and triggers `sync_github`. Neither is constrained to repositories owned by the `repository_owner`/`organization.login` value that was used to select the (unsecured) verification config.

**Broken binding (before vs. after):**
- Before: `organization_used_for_signature_selection == organization_that_owns_the_mutated_repository` is assumed but never enforced.
- After (attacker request): an attacker POSTs to `/webhooks` claiming `organization.login` (or `repository.owner.login`) = an org configured with no `webhook_secret`, while embedding a `sha`/`branch`/`repository.full_name` belonging to a *different*, real, secured stack. `verify_webhook_signature` returns `true` for the fake org with no secret, and the handler then mutates the real stack's commit status or triggers a sync — a cross-organization/cross-repository write with no valid signature over the effective target.

### Impact Explanation
Forged `status` events let an unauthenticated attacker set an arbitrary CI state/context/description on any tracked commit. Since `ci.require` in `shipit.yml` gates deploy safety on exactly these GitHub commit statuses, an attacker can mark a required check as `success` for a commit they do not control, enabling an unauthorized deploy of that stack — a Critical-tier outcome per the accepted-impact list ("unauthorized deploy"). Forged `push` events additionally let an attacker trigger arbitrary `sync_github` operations against stacks unrelated to the spoofed organization, a cross-repository write.

### Likelihood Explanation
Exploitation requires no authentication, no valid `webhook_secret`, and no `X-Hub-Signature` correctness — only that the Shipit deployment has at least one configured GitHub organization without a `webhook_secret` (a state the engine's own default/dev configuration explicitly allows and does not warn against at runtime). Any multi-organization install where one org is left without a secret (e.g., during onboarding, staging orgs, or low-trust orgs) exposes every other org's stacks to this cross-tenant confusion.

### Recommendation
Do not use attacker-supplied payload fields to select the verification secret before the signature has been checked. Verify the signature against every organization config that is a candidate (or key the signature check off of route/auth-boundary configuration, not the JSON body), and require `webhook_secret` to be present for all configured organizations (fail closed instead of `return true unless webhook_secret`). Additionally, handlers such as `StatusHandler`/`PushHandler` should validate that the mutated repository/commit actually belongs to the organization that passed verification.

### Proof of Concept
1. Configure two orgs in `Shipit.github`: `trusted-org` (with a real `webhook_secret`) and `untrusted-org` (left blank, as shown in the shipped example config).
2. POST to `/webhooks` with header `X-Github-Event: status` and any/garbage `X-Hub-Signature`, and body:
```json
{
  "organization": { "login": "untrusted-org" },
  "sha": "<sha of a commit belonging to trusted-org's stack>",
  "state": "success",
  "context": "required-ci-check"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "untrusted-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the bogus signature.
4. `StatusHandler#process` then finds the real commit by `sha` (owned by `trusted-org`) and creates a spoofed successful CI status on it, satisfying `ci.require` for a subsequent deploy the attacker did not otherwise have permission to green-light.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
end
```
