### Title
Silent Error Swallow in `fillAllocated` Causes Complete KAIA Burn Instead of Distribution During Treasury Rebalance — (File: `blockchain/system/rebalance.go`)

### Summary

`fillAllocated` in `RebalanceTreasury` returns `nil` instead of propagating the error when `GetAllocatedCount` fails. This causes the rebalance to proceed with an empty allocated-address map, silently burning the entire zeroed-address KAIA pool rather than distributing it to the intended recipients. The `result.After.Allocated` tracking map — the direct Kaia analog of `totalAllocatedTokens` — is left empty and permanently out of sync with the contract state.

### Finding Description

In `blockchain/system/rebalance.go`, `fillAllocated` has an inconsistent error-return path compared to its sibling `fillZeroed`:

`fillZeroed` (correct): [1](#0-0) 

`fillAllocated` (buggy — returns `nil` instead of `err`): [2](#0-1) 

Because `fillAllocated` swallows the error, the caller-side guard in `RebalanceTreasury` never fires: [3](#0-2) 

Execution continues with `result.After.Allocated` empty. The downstream consequences are:

1. `totalAllocatedBalance()` returns `0` (empty map): [4](#0-3) 

2. The KIP-103 guard `totalZeroedAmount.Cmp(0) < 0` is always `false` → no abort: [5](#0-4) 

3. Execution 1 still zeros every registered address (KAIA removed from state): [6](#0-5) 

4. Execution 2 iterates over an empty map → no KAIA is distributed to anyone: [7](#0-6) 

5. `remainder = totalZeroedAmount − 0 = totalZeroedAmount`; the entire zeroed pool is recorded as burnt, and `result.Success = true`: [8](#0-7) 

All KAIA that was supposed to be redistributed is permanently destroyed, and the memo records a false success.

### Impact Explanation

Unauthorized burn of KAIA from system-managed treasury funds. The zeroed addresses' entire balance (potentially hundreds of millions of KAIA in a KIP-103/KIP-160 rebalance) is permanently destroyed rather than transferred to the intended allocated addresses. The `result.Burnt` tracking value is also corrupted, causing downstream `kaiax/supply` total-supply calculations to report an incorrect circulating supply. [9](#0-8) 

### Likelihood Explanation

`GetAllocatedCount` fails only if the contract is absent at the configured address or its call reverts. In a correctly deployed network this is unlikely. However, the bug is a latent code defect: any future scenario where the contract call fails (misconfigured address, state corruption, out-of-gas on a complex contract upgrade) silently converts a redistribution into a total burn with no on-chain indication of failure beyond a log line. The KIP-160 path has no balance-sufficiency guard at all, making it additionally exposed.

### Recommendation

Change `return nil` to `return err` in `fillAllocated`, matching the behavior of `fillZeroed`:

```go
if err != nil {
    logger.Error("Failed to get AllocatedCount from TreasuryRebalance contract", "err", err)
    return err  // propagate instead of swallowing
}
```

### Proof of Concept

1. Configure a chain with KIP-103 or KIP-160 at block N.
2. At block N, arrange for `GetAllocatedCount` / `GetNewbieCount` to return an error (e.g., deploy a stub contract at the configured rebalance address that reverts on that selector).
3. `RebalanceTreasury` is invoked during block finalization.
4. `fillAllocated` logs the error and returns `nil`; `result.After.Allocated` remains empty.
5. `totalAllocatedAmount = 0`; the KIP-103 guard passes silently.
6. All zeroed addresses are set to balance 0 (KAIA removed from state).
7. No KAIA is distributed to any allocated address.
8. `result.Burnt = totalZeroedAmount`; `result.Success = true`.
9. The block is finalized; the KAIA is permanently burnt with a false-success memo written to the contract.

func (result *rebalanceResult) fillZeroed(contract RebalanceCaller, state *state.StateDB) error {
	numRetiredBigInt, err := contract.GetZeroedCount(nil)
	if err != nil {
		logger.Error("Failed to get ZeroedCount from TreasuryRebalance contract", "err", err)
		return err
	}

	for i := 0; i < int(numRetiredBigInt.Int64()); i++ {
		ret, err := contract.Zeroeds(nil, big.NewInt(int64(i)))
		if err != nil {
			logger.Error("Failed to get Zeroeds from TreasuryRebalance contract", "err", err)
			return err
		}
		result.Before.Zeroed[ret] = state.GetBalance(ret)
		result.After.Zeroed[ret] = state.GetBalance(ret) // will be set as zero if rebalance succeeds
	}
	return nil
}

func (result *rebalanceResult) fillAllocated(contract RebalanceCaller, state *state.StateDB) error {

		return nil
	}

			return err
		}

		result.After.Allocated[ret.Addr] = ret.Amount
	}
	return nil
}
