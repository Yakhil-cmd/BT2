### Title
Missing Zero-Guard on `GasTarget` Divisor in `NextMagmaBlockBaseFee` Causes Node Panic and Chain Halt — (`params/kip71_config.go`)

---

### Summary

`NextMagmaBlockBaseFee()` divides by `GasTarget` without a zero-check guard. The governance parameter `kip71.gastarget` accepts `0` as a valid value (its `FormatChecker` is `noopFormatChecker`), while the analogous parameter `kip71.basefeedenominator` explicitly rejects `0`. Once a governance vote sets `GasTarget = 0`, every subsequent block with non-zero gas used causes `big.Int.Div` to panic, crashing all nodes and halting the chain.

---

### Finding Description

**Missing guard in `NextMagmaBlockBaseFee`:**

`params/kip71_config.go` lines 70–76 contain an explicit zero-check for `BaseFeeDenominator`:

```go
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
``` [1](#0-0) 

But `GasTarget` has no such guard:

```go
gasTarget := kc.GasTarget   // line 77 — no zero-check
``` [2](#0-1) 

Then `gasTarget` is used as a divisor at two points:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // line 102
``` [3](#0-2) 

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // line 120
``` [4](#0-3) 

Go's `big.Int.Div` panics when the divisor is zero.

**`GasTarget = 0` is accepted by governance:**

In `kaiax/gov/param.go`, `Kip71GasTarget` uses `noopFormatChecker` (always returns `true`), while `Kip71BaseFeeDenominator` uses an explicit `v != 0` check:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // rejects 0
    },
    ...
},
Kip71GasTarget: {
    FormatChecker: noopFormatChecker,  // accepts 0
    ...
},
``` [5](#0-4) 

The `checkConsistency` function in `kaiax/gov/headergov/impl/header.go` places `gov.Kip71GasTarget` in the unconditional `return nil` case, performing no additional validation: [6](#0-5) 

**`NextMagmaBlockBaseFee` is called on every block header validation:**

`blockchain/block_validator.go` calls `VerifyMagmaHeader` → `NextMagmaBlockBaseFee` for every post-Magma block: [7](#0-6) 

---

### Impact Explanation

When `GasTarget = 0` is in effect and any block has `parentGasUsed > 0` (the normal case on a live network with transactions):

1. Line 90: `parentGasUsed == gasTarget` → `parentGasUsed == 0` is false (gas was used)
2. Line 92: `parentGasUsed > gasTarget` → `parentGasUsed > 0` is true
3. Line 102: `x.Div(x, new(big.Int).SetUint64(0))` → **panic: division by zero**

The panic propagates out of `validateHeader`, crashing the node process. Every honest node that attempts to import or validate any block after the governance change takes effect will crash. This is a **complete chain halt / consensus divergence** on all honest nodes.

---

### Likelihood Explanation

In `single` governance mode, the single governing node can unilaterally cast a vote for `kip71.gastarget = 0`. The vote passes all format and consistency checks. After one epoch, the parameter takes effect. This requires only one semi-trusted actor (the governing node), not majority-validator collusion. In `none` mode this is not triggerable. The asymmetry between the guarded `BaseFeeDenominator` and the unguarded `GasTarget` suggests this was an oversight.

---

### Recommendation

1. Add a zero-check guard for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    // Avoid division by zero; treat as if gas used equals target
    return makeEvenByFloor(parentBaseFee)
}
```

2. Add a non-zero `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
``` [8](#0-7) 

---

### Proof of Concept

1. Chain is running post-Magma with `GovernanceMode = "single"`.
2. Governing node submits a vote: `kip71.gastarget = 0`. The vote is accepted by `VerifyVote` (passes `noopFormatChecker` and `checkConsistency` returns `nil`).
3. At the next epoch boundary, the governance change is committed to the header's `Governance` field and takes effect.
4. The next block is produced with any transactions (`parentGasUsed > 0`).
5. All nodes call `BlockValidator.validateHeader` → `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee(...)`.
6. Inside `NextMagmaBlockBaseFee`: `parentGasUsed > 0 == gasTarget`, so the `parentGasUsed > gasTarget` branch is taken.
7. `x.Div(x, new(big.Int).SetUint64(0))` panics.
8. All nodes crash. Chain halts.
