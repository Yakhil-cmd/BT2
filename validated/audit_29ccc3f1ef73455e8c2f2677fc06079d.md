### Title
Webhook `repository.owner.login` used for signature verification is never bound to `repository.full_name` used by `UnlabeledHandler` to select the target repository - ([File: app/models/shipit/webhooks/handlers/pull_request/unlabeled_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates a webhook using the GitHub App config for the organization named in `params.dig('repository','owner','login')`, but `UnlabeledHandler#repository` (and the shared `LabelCapturingHandler`) independently resolves the target repository via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. Nothing enforces that the owner segment of `full_name` matches the verified `repository.owner.login`, so in a multi-org Shipit deployment where any one configured organization lacks a `webhook_secret`, an attacker can authenticate "as" that no-secret organization while pointing `full_name` at a victim repository belonging to a different, properly-secured organization.

### Finding Description
The intended binding is: `verified_org == Shipit::Repository.from_github_repo_name(params.repository.full_name).owner`, i.e., a webhook should only be able to mutate the repository/org it was cryptographically verified for.

In `app/controllers/shipit/webhooks_controller.rb:24-31`, `verify_signature` computes:
```
repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
Shipit.github(organization: repository_owner).verify_webhook_signature(sig, raw_body)
``` [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` explicitly no-ops when the org's `webhook_secret` is blank: `return true unless webhook_secret`. [3](#0-2) 

This is a supported, documented configuration for multi-org installations — the setup docs and example secrets files show per-organization config blocks where `webhook_secret` can legitimately be left `nil` for any given org. [4](#0-3) [5](#0-4) 

Separately, `UnlabeledHandler#repository` and the shared `LabelCapturingHandler#repository` resolve the actual `Shipit::Repository` (and hence the `ReviewStackAdapter`/`Stack` that gets archived/unarchived) purely from `params.repository.full_name`, with no reference back to the org used for signature verification:
```ruby
def repository
  @repository ||=
    Shipit::Repository.from_github_repo_name(params.repository.full_name) ||
    Shipit::NullRepository.new
end
``` [6](#0-5) [7](#0-6) 

Exploit flow: `POST /webhooks` with `X-Github-Event: pull_request`, `action: unlabeled`, `repository.owner.login = "org-without-secret"` (the org whose Shipit config has no `webhook_secret`), but `repository.full_name = "victim-org/victim-repo"` (a repository actually tracked by Shipit under a different, properly secured org). `verify_signature` looks up `Shipit.github(organization: "org-without-secret")`, which returns `true` unconditionally for any signature/body because that org's `webhook_secret` is blank. `UnlabeledHandler.process` then runs against `victim-org/victim-repo`'s `Shipit::Repository`/`ReviewStack`, evaluating `archive?`/`unarchive?` from the attacker-supplied `pull_request.labels`, and calls `stack.archive!`/`stack.unarchive!` (which enqueues/dequeues `Shipit::ReviewStackProvisioningQueue`) for that victim repository. [8](#0-7) [9](#0-8) 

None of the existing guards catch this: `drop_unhandled_event`/`check_if_ping` don't inspect payload contents, `ExplicitParameters` (`params do ... end`) only validates types/presence of fields, not cross-field org/full_name consistency, and `verify_signature` validates against whichever organization the attacker names in the body — a value fully independent of `full_name`.

### Impact Explanation
For an attacker who can send raw HTTP to `/webhooks` and knows (via reconnaissance of the Shipit instance's org list, e.g. through its team/org UI or error messages like the "unknown organization" 422) that at least one configured GitHub organization has no `webhook_secret`, this allows forging `pull_request` `unlabeled`/`labeled`/`opened`/`reopened` events that mutate `ReviewStack`/provisioning state for **any other tracked repository**, including ones belonging to organizations that do have a correctly configured secret. This is a cross-tenant write: a payload nominally "authenticated" for one organization mutates another organization's stack/provisioning state, matching the Critical impact category ("a payload for one repository mutating another's stack") even though this question scopes it as High (unauthorized provisioning-state flip). It is fully repeatable against any repository tracked in the same Shipit instance as long as the no-secret org exists.

### Likelihood Explanation
Requires: (1) a multi-organization Shipit deployment (`github_default_organization` non-nil, i.e., per-org config keys used), and (2) at least one configured organization with a blank `webhook_secret` — a state explicitly presented as valid in the engine's own example configs. Given that, the attack costs the attacker nothing beyond crafting one HTTP POST; no GitHub credentials, sessions, or Shipit secrets are needed. In a single-org deployment (no per-org keys) this specific full_name/org divergence is moot because the org check ignores the supplied organization entirely and only one org's repos exist, so likelihood is contingent on the multi-org + partially-missing-secret precondition; I was not able to determine from available context how common that misconfiguration is in real deployments, so this should be validated against target-specific configuration before treating it as a certainty.

### Recommendation
In `WebhooksController#verify_signature`, or in a shared base for the PullRequest handlers, cross-validate that the organization segment of `params.repository.full_name` matches the `repository_owner` used for signature verification before allowing any handler to act; alternatively, resolve the target `Shipit::Repository` using the verified organization rather than trusting `full_name`'s owner independently. Additionally, treat a blank `webhook_secret` for any organization as requiring the request's claimed owner to equal that organization exactly, and reject events where `Repository.from_github_repo_name(full_name)&.owner` doesn't match the verified org.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (proof sketch)
test "unlabeled event authenticated as no-secret org mutates a different org's repository" do
  victim_repo = shipit_repositories(:shipit) # owner "shopify", has webhook_secret configured
  configure_provisioning_behavior(repository: victim_repo, behavior: :prevent_with_label, label: "no-deploy")
  stack = create_stack_for(victim_repo) # provisioned, not archived, has label "no-deploy"

  # Org "org-without-secret" is configured in Shipit with webhook_secret: nil
  Shipit.stubs(:github).with(organization: "org-without-secret").returns(
    Shipit::GitHubApp.new("org-without-secret", { webhook_secret: nil })
  )

  request.headers['X-Github-Event'] = 'pull_request'
  body = {
    action: 'unlabeled',
    number: stack.pull_request.number,
    pull_request: { id: 1, number: stack.pull_request.number, url: 'x', title: 't',
                     state: 'open', additions: 0, deletions: 0,
                     head: { sha: 'a', ref: stack.branch },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { owner: { login: "org-without-secret" }, full_name: victim_repo.github_repo_name },
    sender: { login: 'attacker' }
  }.to_json

  post :create, body:, as: :json

  assert stack.reload.archived?, "victim stack was archived by a request never authenticated for its org"
end
```
Assertion pair (equality that should hold but doesn't): `verified_org ("org-without-secret") == Shipit::Repository.from_github_repo_name(params.repository.full_name).owner ("shopify")` — the test demonstrates the code proceeds and mutates `stack` despite this inequality.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
