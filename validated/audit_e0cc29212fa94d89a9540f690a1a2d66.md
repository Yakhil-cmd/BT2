**Rationale:**

The premise conflates two unrelated subsystems. `LimitExceededError::from_err` in `aptos-move/aptos-native-interface/src/errors.rs` is a generic classifier used by *all* natives to map gas-metering `PartialVMError`s into `SafeNativeError::LimitExceeded` vs. `SafeNativeError::InvariantViolation`, explicitly preserving (not remapping) speculative status codes so Block-STM can detect them correctly. [1](#0-0) 

The fee-payer authentication-key check itself is not implemented as a metered native routed through this error path at all — it is a plain Move-level resource read and equality `assert!` in `fee_payer_script_prologue`/`unified_prologue_fee_payer_v2`/`versioned_prologue`, which reads `account::get_authentication_key(fee_payer_address)` from on-chain state and compares it to the authenticator-derived hash supplied by the VM. [2](#0-1) [3](#0-2) 

Block-STM's correctness model already accounts for exactly the scenario described: if a resource read during speculative execution (e.g., the fee payer's account/auth-key resource) is invalidated by a later-observed write, the execution status is flagged (`SpeculativeExecutionAbortError` / read-set validation failure), and the transaction is forced to re-execute against the up-to-date version before it can be committed — the final committed incarnation is guaranteed not to be a speculative failure. [4](#0-3) [5](#0-4) 

Speculative-error status codes (`SPECULATIVE_EXECUTION_ABORT_ERROR`, `DELAYED_FIELD_OR_BLOCKSTM_CODE_INVARIANT_ERROR`) are explicitly carved out and passed through unchanged by all the epilogue/prologue error converters, ensuring Block-STM (not the VM) decides retry vs. commit — there is no path by which a stale/attacker-timed auth-key read can be silently committed as an admitted transaction. [6](#0-5) [7](#0-6) 

No unprivileged input path exists that causes the fee-payer authentication check to bind to a "different, attacker-timed" auth key and still commit — Block-STM's read-set validation (not the `errors.rs` classification) is precisely the mechanism guaranteeing this cannot happen, and it operates independently of how native gas-metering errors are classified.

impl LimitExceededError {
    pub fn from_err(err: PartialVMError) -> SafeNativeError {
        match err.major_status() {
            StatusCode::OUT_OF_GAS
            | StatusCode::EXECUTION_LIMIT_REACHED
            | StatusCode::DEPENDENCY_LIMIT_REACHED
            | StatusCode::MEMORY_LIMIT_EXCEEDED
            | StatusCode::TOO_MANY_TYPE_NODES
            | StatusCode::VM_MAX_VALUE_DEPTH_REACHED => SafeNativeError::LimitExceeded(
                LimitExceededError::LimitExceeded(MeteringError(err)),
            ),
            // Treat all other code as invariant violations and leave it for the VM to propagate
            // these further. Note that we do not remap the errors. For example, if there is a
            // speculative error returned (signaling Block-STM to stop executing this transaction),
            // we better not remap it.
            // TODO(Gas): Have a single method to convert partial VM error to safe native error.
            _ => SafeNativeError::InvariantViolation(err),
        }
    }
