### Title
Replayable L1 BTC lockup proof lets a staker re-register for new bond periods without any new Bitcoin ever being locked - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`register-for-bond`'s L1 path validates a Bitcoin lockup output by checking the block header, merkle proof, output script and amount, but never records that a given `(txid, output-index)` outpoint has already been consumed by a *previous, completed* bond registration. The de-duplication list (`seen-outpoints`) is scoped only to the single call's `fold`, so once a staker's earlier L1 bond ends (and `get-bond-membership` starts hiding it), the exact same lockup proof can be resubmitted to mint a brand-new bond membership, signer weight and reward eligibility — even if the underlying BTC has since been spent.

### Finding Description
`validate-l1-lockup` proves that a Bitcoin transaction output pays to the correct timelock script and matches the claimed amount, and rejects duplicate outpoints *within the same list*: [1](#0-0) 

The dedup state (`seen-outpoints`) is created fresh on every call to `verify-l1-lockups` and never persisted: [2](#0-1) 

`register-for-bond` calls `verify-l1-lockups` to compute `sats-total`, then credits the staker with a fresh `protocol-bond-memberships` entry, adds the sats to `protocol-bonds-total-staked`, and adds the staker to the signer's cycle shares — all driven purely by the proof's claimed amount, with no check that this particular outpoint hasn't already been used to satisfy an earlier (even already-ended) bond: [3](#0-2) [4](#0-3) 

There is no global map (e.g., `used-l1-outpoints`) anywhere in the contract that records consumed L1 proofs across transactions — a repo-wide search for such a construct (`used-l1-lockups`, `l1-lockup-used`, `used-outpoint`) returns no results.

The unit-test evidence confirms the lifecycle gap this bug exploits: after a bond fully expires, `get-bond-membership` stops reporting it even though the raw membership map entry and the original L1 proof were never invalidated, and a staker can freely `stake`/`register-for-bond` again once their prior bond's term is over: [5](#0-4) 

Because `verify-l1-lockups` only proves that a UTXO with the right script/amount existed in some historical Bitcoin block — not that it is still unspent/currently locked — a staker can:
1. Register for bond period N using a real L1 lockup (correctly locking BTC and being credited `sats-total`).
2. Let bond N's term end (or otherwise become an ex-member per `get-bond-membership`).
3. Spend the underlying Bitcoin UTXO on the Bitcoin chain (the timelock has since matured, or was never enforced beyond the original CLTV check at registration time).
4. Call `register-for-bond` again for a *new* bond period, resubmitting the *identical* Bitcoin transaction/output/header/merkle-proof from step 1. `validate-l1-lockup` re-verifies successfully (header hash, merkle proof, script, amount all still match historical data) and credits `sats-total` again — even though no new BTC is locked and the original BTC may already be spent elsewhere.

This breaks the intended equality "bond membership `amount-sats` / signer weight backed by BTC == BTC actually currently locked by the staker under this contract's timelock script," letting a staker double-count (or n-times count) a single Bitcoin lockup to repeatedly qualify for bond membership, reward shares, and signer set weight.

### Impact Explanation
This is a double-counting of a stacking commitment: reward-eligible signer weight and bond reward shares (sBTC waterfall distribution, per-bond `protocol-bonds-total-staked`) can be inflated using a single, possibly already-spent, Bitcoin lockup. Per the rubric this is Critical ("double-counting a commitment or reward") since it lets a staker manufacture bond memberships/signer weight not backed by any currently-locked BTC, diluting honest bond participants' share of rewards and potentially granting signer weight without a live BTC backing.

### Likelihood Explanation
Likelihood is moderate-to-high for any unprivileged staker who has ever completed one full L1 bond cycle: no special privileges, admin cooperation, or race conditions are needed — only retaining (or replaying from the public Bitcoin blockchain) the original lockup transaction, header, and merkle proof, all of which are permanently public once mined.

### Recommendation
Persist a global map (e.g. `used-l1-lockup-outpoints: { txid: (buff 32), output-index: uint } -> bool`) that is checked and set inside `validate-l1-lockup` (or immediately after `verify-l1-lockups` succeeds in `register-for-bond`), rejecting any outpoint that has ever been consumed by a prior successful bond registration, regardless of whether that earlier bond has since ended.

### Proof of Concept
1. Staker locks `sats-total` sats to the pox-5 timelock script and calls `register-for-bond(bond-index=0, ..., btc-lockup=(ok {outputs: [proof], ...}))`. This succeeds, crediting `amount-sats: sats-total` and adding the staker to bond 0's signer/reward shares (`stackslib/src/chainstate/stacks/boot/pox-5.clar` lines 642-841).
2. Bond 0's term ends; `get-bond-membership` no longer reports the staker as an active bond member (confirmed pattern in `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts` lines 5638-5644).
3. Staker spends the original Bitcoin UTXO however they like (it is no longer relevant to the Stacks contract's tracked state).
4. Staker calls `register-for-bond(bond-index=6, ..., btc-lockup=(ok {outputs: [SAME proof as step 1], ...}))`. `validate-l1-lockup` re-validates the (unchanged) header/merkle-proof/script/amount successfully, and `verify-l1-lockups` returns the same `sats-total` a second time, crediting a brand-new bond membership and signer/reward shares for bond 6 — with zero new BTC locked.

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)
