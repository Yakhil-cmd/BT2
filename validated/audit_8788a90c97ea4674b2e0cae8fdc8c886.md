### Title
Governance Vote `kip71.gastarget = 0` Accepted Without Validation Causes Division-by-Zero Panic in `NextMagmaBlockBaseFee`, Halting the Chain — (File: `params/kip71_config.go`, `kaiax/gov/param.go`)

---

### Summary

The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, accepting any `uint64` value including `0`. Once a vote of `kip71.gastarget = 0` is applied, every subsequent Magma-era block with non-zero gas usage causes `NextMagmaBlockBaseFee` to execute an integer division by zero (`big.Int.Div(..., 0)`), which panics in Go and crashes every node that attempts to produce or validate the block. The chain permanently halts. The sibling parameter `Kip71BaseFeeDenominator` already has an explicit non-zero guard; `GasTarget` does not.

---

### Finding Description

**Root cause — missing zero-check in `FormatChecker`:**

`Kip71GasTarget` is registered in `kaiax/gov/param.go` with `noopFormatChecker`, which unconditionally returns `true` for any canonicalized value:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,   // ← accepts uint64(0)
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

Compare with `Kip71BaseFeeDenominator`, which correctly rejects zero:

```go
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0   // ← explicit non-zero guard
    },
    ...
},
``` [2](#0-1) 

**Vote acceptance path:**

`NewVoteData` calls `FormatChecker` to validate the value. Because `noopFormatChecker` always returns `true`, a vote `{kip71.gastarget: uint64(0)}` passes. `VerifyVote` → `checkConsistency` also returns `nil` for `gov.Kip71GasTarget` with no additional range check:

```go
case gov.GovernanceDeriveShaImpl, ..., gov.Kip71GasTarget, ...:
    return nil
``` [3](#0-2) 

**Division-by-zero in `NextMagmaBlockBaseFee`:**

After the vote takes effect, every call to `NextMagmaBlockBaseFee` with `parentGasUsed > 0` reaches the branch where `gasTarget` is used as a divisor:

```go
gasTarget := kc.GasTarget   // == 0 after the vote
...
if parentGasUsed == gasTarget {   // 0 == 0 only if no txs
    return ...
} else if parentGasUsed > gasTarget {   // true for any non-zero gas
    ...
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // ← PANIC: Div by 0
``` [4](#0-3) 

Go's `big.Int.Div` panics on a zero divisor. The `BaseFeeDenominator` zero-case is explicitly handled (lines 71–76), but `GasTarget` has no such guard. [5](#0-4) 

`NextMagmaBlockBaseFee` is called from both block production (`makeHeader`) and block validation (`VerifyMagmaHeader`), so every node — proposer and validator alike — panics on the first block with any gas usage after the parameter takes effect. [6](#0-5) 

---

### Impact Explanation

Every honest node crashes with a Go runtime panic when processing or validating any Magma-era block that has non-zero gas usage after `GasTarget = 0` takes effect. This is a **permanent chain halt**: no new blocks can be produced or accepted, and no KAIA transfers, reward distributions, or state transitions can proceed. The corrupted governance parameter persists in the chain state and cannot be corrected without a coordinated hard fork.

---

### Likelihood Explanation

`kip71.gastarget` is listed as a **mutable** governance parameter in the README. In `"none"` governance mode any council member can cast the vote; in `"single"` mode the governing node can. The vote passes all existing validation layers (`NewVoteData`, `VerifyVote`, `checkConsistency`) without error. The value `uint64(0)` is a natural boundary value that an operator might set accidentally (e.g., intending to disable the dynamic fee mechanism) or that a malicious governing node could set deliberately.

---

### Recommendation

Add a non-zero guard to `Kip71GasTarget`'s `FormatChecker`, mirroring the existing guard on `Kip71BaseFeeDenominator`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```

Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` (analogous to the `BaseFeeDenominator` guard at lines 71–76) so that a misconfigured parameter cannot cause a runtime panic even if it somehow bypasses the vote-layer check.

---

### Proof of Concept

1. Deploy a Kaia network with Magma hardfork enabled and `governance.governancemode = "none"` (or use the governing node in `"single"` mode).
2. Cast a governance vote: `kip71.gastarget = 0` (passes `NewVoteData` and `VerifyVote` without error).
3. Wait for the vote to take effect (next epoch boundary).
4. Submit any transaction so that the next block has `GasUsed > 0`.
5. Every node calls `NextMagmaBlockBaseFee` → reaches `x.Div(x, new(big.Int).SetUint64(0))` → **Go runtime panic: `integer divide by zero`** → node process crashes.
6. All nodes crash on the same block; the chain halts permanently.
