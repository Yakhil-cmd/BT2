### Title
Stop-hook security review coverage is silently and permanently lost when `MAX_STOP_HOOK_FIRINGS` is hit, because `consume_stop_state` clears `touched_paths` without restoring it on that skip path - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
The security-guidance plugin's Stop hook (`handle_stop_hook`) is the mechanism that runs an LLM security review over code Claude changed in a turn and blocks (`exit(2)`) if vulnerabilities are found. Like the Derby `Game.rebalanceBasket`/`addToTotalRewards` bug — where a period counter (`lastRebalancingPeriod`) is advanced unconditionally while the reward accrual it's supposed to gate is only conditionally performed — this hook unconditionally consumes/clears `touched_paths` state at the start of every fire, but only restores it (so the *next* fire can still cover those edits) on one specific skip path. Every other early-exit path drops the tracking state permanently, silently degrading the security guarantee (review coverage) the hook exists to provide.

### Finding Description
`consume_stop_state()` snapshots and unconditionally clears `touched_paths` under a single lock, before any of the hook's gating checks run: [1](#0-0) 

The docstring for the companion function `restore_unreviewed_stop_state` explicitly documents the danger of this ordering: if Stop exits early without restoring, "the next UPS would see an empty list, fall through the preservation guard, and re-baseline past the unreviewed edits": [2](#0-1) 

In `handle_stop_hook`, the `_skip()` helper only calls `restore_unreviewed_stop_state` when explicitly passed `restore=True`: [3](#0-2) 

That flag is used for exactly one transient-failure case (`api.anthropic.com` unreachable, skip_reason=10): [4](#0-3) 

But the fire-count cap check — `MAX_STOP_HOOK_FIRINGS`, intended purely as an infinite-loop guard, not a "this content doesn't need review" decision — skips without restoring: [5](#0-4) 

Once `touched_paths` is cleared here and not restored, the "preservation guard" referenced in the docstring no longer fires on the next `UserPromptSubmit`, so the baseline can move forward past the unreviewed edits — meaning those file changes are never diffed against, never sent to `analyze_code_security`, and never flagged, even though the hook's own commentary treats that outcome as a known failure mode requiring the restore mechanism. This mirrors the Derby root cause precisely: a counter/state field (`lastRebalancingPeriod` / `touched_paths` emptiness) is advanced/cleared as a side effect of merely being *read*, decoupled from whether the corresponding effect (`addToTotalRewards` / LLM security review) actually executed for that cycle.

### Impact Explanation
This is a security-control bypass, not a cosmetic bug: edits made in a turn that happens to land after the hook has already fired `MAX_STOP_HOOK_FIRINGS` times within the 120s TTL window are permanently excluded from the Stop-hook's LLM vulnerability review, with no telemetry distinguishing "skipped and will be retried" from "skipped and dropped forever." In an iterative asyncRewake fix loop (vuln → exit(2) → fix → Stop again), it is plausible for the fire count to reach the cap while genuinely new, unreviewed edits exist, since the cap is a blunt per-turn firing count rather than a per-file coverage tracker. Those edits then silently skip both the commit-review and Stop-hook review paths that this plugin exists to enforce, allowing vulnerable code to pass through without the intended detection/blocking behavior.

### Likelihood Explanation
Moderate. It requires the asyncRewake Stop-review loop to fire 3+ times within 120 seconds (default `MAX_STOP_HOOK_FIRINGS=3`, `STOP_LOOP_STATE_TTL_SEC=120`) while the session continues to make new edits — a realistic scenario for a long agentic session iteratively fixing several flagged issues across multiple turns, or a user submitting a new prompt quickly after repeated Stop fires.

### Recommendation
Treat "skip without having performed a real review" as the general condition for restoring `touched_paths`, not an opt-in flag limited to the anthropic-unreachable case. Concretely, call `restore_unreviewed_stop_state` for any skip path prior to `analyze_code_security` actually running (fire-count cap, disabled review, missing credentials, missing cwd), or redesign the state so `touched_paths` is only cleared once a review has genuinely completed (successfully or with zero findings) for those paths — mirroring the report's recommendation to only advance the "period" counter in step with the corresponding accrual, not independently of it.

### Proof of Concept
1. In a session with `MAX_STOP_HOOK_FIRINGS=3` (default) and `STOP_LOOP_STATE_TTL_SEC=120`, cause the Stop hook to fire 3 times within 120s (e.g., 3 turns each ending in a real LLM review, each incrementing `stop_hook_fire_count`).
2. On a 4th turn within the same TTL window, make a new edit to a source file (recorded into `touched_paths` via `record_touched_path`).
3. Stop hook fires: `consume_stop_state()` snapshots and clears `touched_paths` (including the new edit's path) at `plugins/security-guidance/hooks/diffstate.py:106`.
4. `fire_count >= MAX_STOP_HOOK_FIRINGS` triggers `_skip(2)` with `restore=False`, so `restore_unreviewed_stop_state` is never called — the new edit's path is dropped from durable state with no LLM review having run over it.
5. On the next `UserPromptSubmit`, the "preservation guard" (referenced in `restore_unreviewed_stop_state`'s docstring) sees an empty `touched_paths` list and lets the baseline advance normally, permanently excluding the dropped edit from any future `compute_v2_review_set` diff — the file's vulnerable content, if any, is never reviewed by the plugin.

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
