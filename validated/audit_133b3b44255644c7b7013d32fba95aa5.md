### Title
`set-burnchain-parameters` in pox-5.clar has no access control, allowing any user to front-run configuration and corrupt reward-cycle/bond-period math - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`set-burnchain-parameters` is a `define-public` function guarded only by a one-shot `configured` flag, with no `contract-caller`/admin check, mirroring the Controller `__Controller_init()` bug class: whoever calls it first wins. [1](#0-0) 

### Finding Description
`set-burnchain-parameters` sets `first-burnchain-block-height`, `pox-prepare-cycle-length`, `pox-reward-cycle-length`, `first-pox-5-reward-cycle`, and `first-bond-period-cycle`, and it is only protected by the `configured` boolean, not by any authorization check on the caller. [1](#0-0) 
By contrast, every other privileged setter in the same contract (`set-bond-admin`, `set-pause-admin`, `pause-rewards`) explicitly asserts `contract-caller` equals the relevant admin var. [2](#0-1) 
The test helper `initPox5` shows the intended flow: the deployer calls `setBurnchainParameters` once immediately after boot, before `setBondAdmin`/`setPauseAdmin` are set. [3](#0-2) 
On a live chain, boot contracts (pox-5, sip-031, etc.) are deployed inside the epoch-4.0 transition, and `make_pox_5_body` bakes in `bond-admin`/`pause-admin` at deploy time, but `first-burnchain-block-height`/cycle-length parameters are left to be set by this unguarded call after boot. [4](#0-3) 
Because the mempool/block-inclusion window between contract deployment and the intended configuration call is public, any account (including one with only enough STX for the call fee) can race the intended admin and call `set-burnchain-parameters` first with attacker-chosen values for `prepare-cycle-length`, `reward-cycle-length`, and `begin-pox5-reward-cycle`.

### Impact Explanation
These parameters drive every reward-cycle and unlock-height computation used throughout pox-5 (reward-cycle-to-burn-height/unlock scheduling, bond-period gating for `setup-bond`/`register-for-bond`, and prepare-phase checks that block staking/unstaking near cycle boundaries). If an attacker sets `reward-cycle-length`/`prepare-cycle-length` to degenerate values (e.g., very small or mismatched with `BOND_LENGTH_CYCLES`/`BOND_GAP_CYCLES` constants), reward-cycle boundaries, unlock heights, and prepare-phase windows computed from these vars would be corrupted for the entire lifetime of the contract (the `configured` flag is one-shot and cannot be reset), leading to STX being locked/unlocked at the wrong burn heights, bond-period reward math misalignment, or stakers being denied/allowed staking actions outside intended windows. This is a permanent, contract-wide misconfiguration, not merely a loss local to the attacker.

### Likelihood Explanation
High. The call requires no special privilege, no admin key, and only a nominal STX fee; it is a straightforward front-run of the boot sequence and is explicitly anticipated as a manual step in the node's own boot/test tooling (`initPox5`/`initBootPox5`), meaning the race window genuinely exists in production deployment flow. [5](#0-4) 

### Recommendation
Add a `contract-caller` check to `set-burnchain-parameters` restricting it to the mainnet/testnet-configured `bond-admin` (or a dedicated boot-only principal), or bake all four burnchain parameters directly into the contract body at boot time (the same way `bond-admin`/`pause-admin` are baked in via `make_pox_5_body`) so no post-deploy public call is required at all.

### Proof of Concept
1. Node deploys `pox-5.clar` during the epoch-4.0 transition; `bond-admin`/`pause-admin` are baked in via `make_pox_5_body`, but `configured` is `false` and `first-burnchain-block-height`/cycle-length vars are unset defaults. [4](#0-3) 
2. Before the intended admin's transaction confirms, an attacker with any funded account submits a `set-burnchain-parameters` call with `prepare-cycle-length: u1, reward-cycle-length: u1, begin-pox5-reward-cycle: u999999999` (or any adversarial values). [6](#0-5) 
3. The `configured` flag flips to `true` and the intended admin's legitimate call now fails the `(if (var-get configured) (err false) (ok true))` guard, permanently locking in the attacker's corrupted parameters for the life of the contract, with no admin recovery path. [7](#0-6)

(define-public (set-burnchain-parameters
        (first-burn-height uint)
        (prepare-cycle-length uint)
        (reward-cycle-length uint)
        (begin-pox5-reward-cycle uint)
    )
    (begin
        (unwrap-panic (if (var-get configured)
            (err false)
            (ok true)
        ))
        (var-set first-burnchain-block-height first-burn-height)
        (var-set pox-prepare-cycle-length prepare-cycle-length)
        (var-set pox-reward-cycle-length reward-cycle-length)
        (var-set first-pox-5-reward-cycle begin-pox5-reward-cycle)
        (var-set first-bond-period-cycle begin-pox5-reward-cycle)

        (ok true)
    )
)

/// Generate the contract body for the pox-5 contract.
///
/// On mainnet the body is used verbatim, with the canonical sBTC token
/// contract literal and the mainnet `bond-admin` principal baked in. On
/// non-mainnet networks, every occurrence of the canonical sBTC token literal
/// is rewritten to point at the configured sBTC token contract via
/// [`set_pox_5_sbtc_contract`] (typically configured from the node config
/// file), falling back to a well-known testnet default when unset, and the
/// `bond-admin` initializer is rewritten via [`pox_5_bond_admin`] to the
/// configured admin or the testnet default. Calling this with
/// `is_mainnet = true` ignores both overrides entirely.
///
/// NB: We left multiple literals in the body instead of defining a constant
/// because the read-only checker only resolves the read-only-ness of
/// `(contract-call? <X> ...)` for *literal* contract principals — not for
/// `define-constant`s — and pox-5 has read-only functions that call the
/// sBTC token's `get-balance`.
pub fn make_pox_5_body(is_mainnet: bool) -> String {
    if is_mainnet {
        return POX_5_BODY.to_string();
    }
    let sbtc_contract = pox_5_sbtc_contract(is_mainnet);
    let bond_admin = pox_5_bond_admin(is_mainnet);
    let pause_admin = pox_5_pause_admin(is_mainnet);
    POX_5_BODY
        .replace(SBTC_TOKEN_MAINNET_CONTRACT, &sbtc_contract.to_string())
        .replacen(
            &format!("(define-data-var bond-admin principal '{POX_5_BOND_ADMIN_MAINNET})"),
            &format!("(define-data-var bond-admin principal '{bond_admin})"),
            1,
        )
        .replacen(
            &format!("(define-data-var pause-admin principal '{POX_5_PAUSE_ADMIN_MAINNET})"),
            &format!("(define-data-var pause-admin principal '{pause_admin})"),
            1,
        )
}
