### Title
Webhook signature scoped to `repository.owner.login` while archived Stack resolved by unrelated `repository.full_name` allows cross-tenant Stack archive - (File: app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate the HMAC using `repository_owner` (`params.dig('repository','owner','login')`), but `ClosedHandler#repository`/`#review_stack` resolve and mutate the target `Stack` using the completely independent `params.repository.full_name` field from the same JSON body. Since both fields are attacker-controlled parts of a single POST body, an operator who legitimately controls one organization's webhook secret (in Shipit's documented multi-organization configuration) can sign a payload claiming `repository.owner.login = "org-a"` while setting `repository.full_name = "org-b/protected-repo"`, causing `ReviewStackAdapter#archive!` to archive org B's live Stack without any authentication from org B.

### Finding Description
Broken binding: `organization_whose_secret_verified_signature (repository_owner = params.dig('repository','owner','login'))` == `organization_owning_the_mutated_Stack (params.repository.full_name.split('/').first)` — **false**, and nothing in the code enforces this equality.

Trace:
- `WebhooksController#verify_signature` picks the app/secret via `Shipit.github(organization: repository_owner)`, using only `repository.owner.login` (or `organization.login` fallback): [1](#0-0) [2](#0-1) 
- In the documented multi-org setup, `Shipit.github_app_config(organization)` looks up a per-organization `webhook_secret` keyed strictly by that owner login string: [3](#0-2)  This is a supported first-class configuration (`docs/setup.md` "Using Multiple Github Applications", exercised by `test/dummy/config/secrets_double_github_app.yml`).
- `GitHubApp#verify_webhook_signature` does a straightforward HMAC-SHA1 compare against the selected org's secret and the raw body bytes — it has no knowledge of, or connection to, `repository.full_name`: [4](#0-3) 
- Once the signature passes, the raw JSON is dispatched to handlers by event type: [5](#0-4) 
- `ClosedHandler#repository` resolves the actual `Shipit::Repository` (and thus the actual tenant to be mutated) purely from `params.repository.full_name`, with zero reference to `repository_owner` used for signing: [6](#0-5) 
- `Repository.from_github_repo_name` just splits `full_name` on `/` and does a DB lookup — no tie back to which secret verified the request: [7](#0-6) 
- `ClosedHandler#process`/`#review_stack` then call `ReviewStackAdapter#archive!`, which loads the live Stack by `environment: "pr#{params.number}"` scoped to that resolved (org B) Repository and unconditionally archives/deprovisions it: [8](#0-7) [9](#0-8) [10](#0-9) 

Attacker request: as the operator of org A (in a multi-org Shipit deployment, org A knows the webhook secret it configured for its own GitHub App), POST to `/webhooks` with header `X-Github-Event: pull_request`, a valid `X-Hub-Signature` computed with org A's secret over the exact raw body, and a JSON body where `repository.owner.login = "org-a"` but `repository.full_name = "org-b/protected-repo"` and `number`/`pull_request.number` matching org B's live review-stack PR number, `action: "closed"`. No knowledge of org B's secret, session, or API token is required.

Existing guards fail to prevent this because: `verify_signature` only proves "this byte stream was signed with org A's key" — it never asserts anything about which repository/org the payload's content claims to describe; `ExplicitParameters` schema in `ClosedHandler` only validates types/presence of `repository.full_name`, not that it matches `repository.owner.login` or the signing organization; `drop_unhandled_event`, `force_github_authentication`, and model validators (`Repository#owner` format) are irrelevant to this cross-field consistency check.

### Impact Explanation
An unauthenticated-with-respect-to-org-B request causes a live `Shipit::Stack` belonging to org B to be archived and deprovisioned (`stack.deprovision`, `stack.archive!`) — "a payload for one repository mutating another's stack," matching the Critical impact category. This is repeatable against any repository/Stack whose `owner/name` and PR number the attacker can guess or observe (e.g., from public GitHub PRs), for every org pair where the victim Shipit instance runs the multi-org webhook_secret configuration. Blast radius spans all tenants configured on the same Shipit instance under that mode — any org's PR-number/environment naming convention (`pr#{number}`) is predictable, so no secret information about org B is needed at all.

### Likelihood Explanation
Requires the target Shipit instance to run in the multi-organization webhook configuration (documented, supported feature — not exotic), and requires the attacker to control (or have set up) at least one organization's own GitHub App/webhook secret onboarded to that shared Shipit instance — a low bar for a SaaS-style multi-tenant Shipit deployment where organizations self-register their own GitHub App credentials. Cost is a single crafted HTTP POST with a correctly computed HMAC using a secret the attacker already legitimately possesses. Fully repeatable, no rate limiting or one-time tokens involved.

### Recommendation
Bind the resolved repository/stack to the organization that actually verified the signature: after `verify_signature` succeeds, pass the verified `repository_owner`/organization identity into the webhook dispatch pipeline, and have `ClosedHandler#repository` (and all other `full_name`-based handlers/`Handler#stacks`) reject or ignore payloads where `params.repository.full_name.split('/').first` does not case-insensitively equal the verified `repository_owner`.

### Proof of Concept
Minitest plan (controller-level, no live GitHub):
```ruby
test "cross-org signed payload cannot archive another org's stack" do
  # Setup: multi-org secrets fixture (OrgA, OrgB) like secrets_double_github_app.yml
  org_b_repo = shipit_repositories(:org_b_repo) # owner: "org-b"
  stack = create_review_stack(repository: org_b_repo, pr_number: 42) # live, not archived

  payload = payload_parsed(:pull_request_closed)
  payload["repository"]["owner"]["login"] = "org-a"     # drives signature org
  payload["repository"]["full_name"] = "org-b/protected-repo" # drives target Stack
  payload["number"] = 42
  payload["pull_request"]["number"] = 42
  body = payload.to_json

  signature = "sha1=" + OpenSSL::HMAC.hexdigest("sha1", org_a_webhook_secret, body)
  request.headers["X-Github-Event"] = "pull_request"
  request.headers["X-Hub-Signature"] = signature

  assert_equal "org-a", payload["repository"]["owner"]["login"]   # LHS of binding
  assert_equal "org-b", payload["repository"]["full_name"].split("/").first # RHS of binding
  refute_equal payload["repository"]["owner"]["login"], payload["repository"]["full_name"].split("/").first

  assert_not stack.reload.archived?

  post :create, body:, as: :json
  assert_response :ok

  assert stack.reload.archived?, "org B's stack was archived by a request signed only with org A's secret"
end
```
This asserts both sides of the claimed binding are unequal before the request, then shows the archive occurred anyway, proving the vulnerability.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
