### Title
Unsanitized branch names/URLs in `developRunList` allow bidi/zero-width Unicode terminal spoofing - (File: pkg/cmd/issue/develop/develop.go)

### Summary
`developRunList` fetches linked branch names and URLs from the GitHub API and passes them unmodified to `printLinkedBranches`, which writes them straight into a table with no stripping of bidirectional-override or zero-width characters. An attacker who creates a linked branch (or otherwise causes a `BranchName`/`URL` value to reach this API) with embedded `U+202E` (RIGHT-TO-LEFT OVERRIDE) or zero-width characters can visually reorder or hide parts of the branch name/URL when displayed to a victim running `gh issue develop --list`.

### Finding Description
`developRunList` calls `api.ListLinkedBranches` and forwards the results directly to `printLinkedBranches`: [1](#0-0) 
`printLinkedBranches` writes `branch.BranchName` and `branch.URL` straight into `tableprinter` fields with no text sanitization step: [2](#0-1) 

The repo's shared text-formatting helper `internal/text` only offers whitespace collapsing (`RemoveExcessiveWhitespace`), diacritic stripping, display-width computation, and truncation — there is no function anywhere in the codebase that strips bidi control characters (`U+202E`, `U+202D`, etc.) or zero-width characters (`U+200B`, `U+FEFF`) before output: [3](#0-2) 

Because `BranchName` originates from a linked-branch creation (attacker can name a branch, e.g. via `gh issue develop` on their own repo or a branch ref they control) and is later listed for anyone with access to view linked branches on an issue, an attacker-chosen string containing bidi-override sequences would render with reversed/obscured segments in the victim's terminal — e.g., making `evil-branch‮txt.hs` visually appear as `evil-branch.sh...` reversed, or hiding a malicious suffix.

### Impact Explanation
This is a terminal-output spoofing issue: it can mislead a victim about the actual content of a branch name or URL displayed by `gh issue develop --list`, matching the "Terminal output/prompt spoofing" impact class. It does not by itself grant code execution, credential exfiltration, or file write — the `--list` path only prints to the table via `tableprinter`; it does not feed the branch name into any git operation. The higher-severity scenarios described in the question (checkout, worktree, file extension confusion) occur in `developRunCreate`/`checkoutBranch`, not in `developRunList`.

### Likelihood Explanation
Feasible: an attacker with normal GitHub permissions can create a linked branch with a crafted name (subject to git ref-name restrictions, which do restrict some but not all Unicode control characters — git ref names do forbid many ASCII controls but Unicode bidi/zero-width codepoints are not restricted by git's ref grammar). The victim simply needs to run `gh issue develop --list` against an issue with such a linked branch.

### Recommendation
Sanitize `BranchName` and `URL` fields before display in `printLinkedBranches` — strip or escape Unicode bidirectional control characters (`U+202A`-`U+202E`, `U+2066`-`U+2069`) and zero-width characters (`U+200B`, `U+200C`, `U+200D`, `U+FEFF`) using a shared helper in `internal/text`, and apply the same treatment anywhere else attacker-controlled ref/branch/URL strings are printed to a TTY.

### Proof of Concept
Add a table test around `printLinkedBranches` (or a fuzz test on a new `text.SanitizeBidiControls` helper) similar to:
```go
func TestPrintLinkedBranches_StripsBidiControls(t *testing.T) {
    ios, _, out, _ := iostreams.Test()
    ios.SetStdoutTTY(true)
    branches := []api.LinkedBranch{
        {BranchName: "evil-branch\u202Etxt.hs", URL: "https://github.com/o/r/tree/evil"},
    }
    printLinkedBranches(ios, branches)
    require.NotContains(t, out.String(), "\u202E")
}
```
Expected (currently failing): the raw `U+202E` byte sequence appears unmodified in `out.String()`, demonstrating no sanitization occurs before display.

func developRunList(opts *DevelopOptions, apiClient *api.Client, issueRepo ghrepo.Interface, issue *api.Issue) error {
	opts.IO.StartProgressIndicatorWithLabel("Fetching linked branches")
	defer opts.IO.StopProgressIndicator()

	branches, err := api.ListLinkedBranches(apiClient, issueRepo, issue.Number)
	if err != nil {
		return err
	}
	opts.IO.StopProgressIndicator()

	if len(branches) == 0 {
		return cmdutil.NewNoResultsError(fmt.Sprintf("no linked branches found for %s#%d", ghrepo.FullName(issueRepo), issue.Number))
	}

	if opts.IO.IsStdoutTTY() {
		fmt.Fprintf(opts.IO.Out, "\nShowing linked branches for %s#%d\n\n", ghrepo.FullName(issueRepo), issue.Number)
	}

	printLinkedBranches(opts.IO, branches)

	return nil
}
```

func printLinkedBranches(io *iostreams.IOStreams, branches []api.LinkedBranch) {
	cs := io.ColorScheme()
	table := tableprinter.New(io, tableprinter.WithHeader("BRANCH", "URL"))
	for _, branch := range branches {
		table.AddField(branch.BranchName, tableprinter.WithColor(cs.ColorFromString("cyan")))
		table.AddField(branch.URL)
		table.EndRow()
	}
	_ = table.Render()
}
```
