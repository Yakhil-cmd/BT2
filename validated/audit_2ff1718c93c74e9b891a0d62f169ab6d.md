### Title
Unauthenticated disclosure of arbitrary stack merge status via `MergeStatusController#check` using attacker-controlled `referrer` param - (File: app/controllers/shipit/merge_status_controller.rb)

### Summary
`MergeStatusController` skips authentication for both `#check` and `#show`, but only `#show` re-adds an explicit `current_user.logged_in?` gate before rendering stack data. `#check` renders `stack_status` directly, so an anonymous caller can resolve an arbitrary victim `owner/repo`'s production `Stack` purely from an attacker-supplied `referrer` query parameter and read its merge status.

### Finding Description
Expected binding: `authorized? == true` (or at minimum `current_user.logged_in? == true`) must hold before any `Stack` record resolved from attacker-controlled input is disclosed to the caller.

Actual code:
- `skip_authentication only: %i[check show]` removes `force_github_authentication` for both actions. [1](#0-0) 
- `#show` re-adds the missing check: `return render('logged_out') unless current_user.logged_in?`. [2](#0-1) 
- `#check` has no such guard; it calls `stack_status` unconditionally and renders it (as plain text or JSON) to whoever requested it. [3](#0-2) 
- `stack` (used by `stack_status`) resolves via `Stack.from_param!` only when `params[:stack_id]` is present; otherwise it builds a scope filtered on `repositories.owner`/`repositories.name` taken from `referrer_parser.repo_owner`/`repo_name`, which are parsed and downcased straight out of `params[:referrer]`, then defaults to `environment: 'production'`. [4](#0-3) 
- `referrer_parser` is `ReferrerParser.new(params[:referrer])`, entirely attacker-supplied and unauthenticated — no relation to the actual HTTP `Referer` header or to any session/repository the caller is authorized against. [5](#0-4) [6](#0-5) 

Attacker request: `GET /merge_status/check?referrer=https://github.com/Victim-Org/Victim-Repo/pull/1` with no session cookie and no `stack_id`. `force_github_authentication` is skipped for `check`, `referrer_parser` yields `repo_owner="victim-org"`, `repo_name="victim-repo"`, the scope finds the production `Stack` for that repository, and `stack_status` (`stack.merge_status`) is rendered directly as plain text (`ok`/status text) or JSON (`{ stack_status: ... }`), with no `current_user.logged_in?` or `authorized?` check anywhere in the path.

This differs from `#show`, which explicitly blocks anonymous callers before disclosing `stack_status`, proving the omission in `#check` is a real divergence in this engine's own code rather than a framework-level protection.

### Impact Explanation
An unauthenticated, unprivileged internet user can, per request, learn whether a production `Stack` exists for any `owner/repo` pair and its current merge/deploy health status (`success`, `failure`, pending backlog state, etc.), without any Shipit session, API token, or GitHub credential. This is repeatable against arbitrary organizations/repositories by simply varying the `referrer` string, and works across every tenant/repository hosted by the Shipit instance since the lookup is keyed purely off attacker text with no ownership check. This matches the "High - unauthenticated read of stack state" impact category.

### Likelihood Explanation
Preconditions are minimal: a `Stack` must exist for the targeted `owner/repo` with `environment: 'production'` (the common default), and the attacker needs no Shipit account, GitHub App access, webhook secret, or team membership — only the ability to send an HTTP GET with a crafted `referrer` query string. `#check` is explicitly listed in `skip_authentication`, so this is trivially and repeatably reachable at will.

### Recommendation
Add the same authentication/authorization guard used in `#show` to `#check` (and audit `#enqueue`/`#dequeue`, which also lack it but are not covered by `skip_authentication` so are less exposed) — e.g. `return render(plain: 'unauthorized', status: :unauthorized) unless current_user.logged_in? && current_user.authorized?` before computing `stack_status`. Additionally, consider not allowing the fallback stack lookup (`referrer`-based scope without `stack_id`) to bypass authorization at all, since it lets any caller select a stack by owner/name without ever having proven access to that repository.

### Proof of Concept
```ruby
# test/controllers/merge_status_controller_test.rb
test "#check leaks merge status for arbitrary victim stack to anonymous caller" do
  victim_repo = shipit_repositories(:shipit) # or create_repository(owner: 'victim-org', name: 'victim-repo')
  victim_stack = create_stack(repository: victim_repo, environment: 'production')

  # no session set -> current_user.logged_in? == false
  get :check, params: { referrer: "https://github.com/#{victim_repo.owner}/#{victim_repo.name}/pull/1" }

  assert_response :success # or 503, either way stack_status was computed and exposed
  refute_includes response.body, 'logged_out' # unlike #show, no logged_out gate exists

  # Contrast with #show under identical unauthenticated conditions:
  get :show, params: { referrer: "https://github.com/#{victim_repo.owner}/#{victim_repo.name}/pull/1" }
  assert_template 'logged_out' # show correctly blocks anonymous disclosure
end
```
This demonstrates the equality `current_user.logged_in? == true` is enforced before disclosure in `#show` but not in `#check`, confirming the vulnerability is specific to `#check`'s missing guard.

    class ReferrerParser
      URL_PATTERN = %r{\Ahttps://github\.com/([^/]+)/([^/]+)/pull/(\d+)}

      attr_reader :repo_owner, :repo_name, :pull_request_number

      def initialize(referrer)
        unless (match_info = URL_PATTERN.match(referrer.to_s))
          raise ArgumentError, "Invalid referrer: #{referrer.inspect}"
        end

        @repo_owner = match_info[1].downcase
        @repo_name = match_info[2].downcase
        @pull_request_number = match_info[3].to_i
      end
