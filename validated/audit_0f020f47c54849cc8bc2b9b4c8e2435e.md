### Title
Unchecked scaled-value overflow during interest accrual permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary

High severity. A sufficiently large market can grow its borrow index until `borrowed * borrow_index` or `supplied * supply_index` exceeds the `i128` domain. Interest accrual panics before the configured index caps can take effect. Because every pool mutation loads the market through `synced_market`, which unconditionally runs `interest::global_sync` first, subsequent `borrow`, `withdraw`, `repay`, liquidation settlement, bad-debt cleanup, and recapitalization attempts for that market also revert. The shared harness demonstrates this path at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:315-356`.

### Finding Description

Each accrual step first converts aggregate scaled debt and supply into original RAY values:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
let supplied_original = scaled_to_original(env, supplied, supply_index);
```

`scaled_to_original` delegates to `Ray::mul`, which returns `MathOverflow` if the resulting RAY value cannot fit in `i128`. Later in the same step, `calculate_supplier_rewards`, `update_supply_index`, and `supply_index_reward_shortfall` perform additional checked `borrowed * index` and `supplied * index` calculations. Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, the cap is applied only after multiplication, and the surrounding aggregate-value calculations can overflow before the cap protects the market. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

The underlying `Ray::mul` intentionally panics on an unrepresentable result rather than saturating or reducing precision. [6](#0-5) [7](#0-6) 

### Impact Explanation

This causes permanent freezing of all funds and debt operations in the affected `(hub_id, asset)` market.

`interest::global_sync` invokes `accrue_step` before market state can be committed. Once the aggregate scaled-value multiplication overflows, the call aborts before `mark_accrued` or `commit`, leaving `last_timestamp` unchanged. The same overflow therefore recurs on every later operation. [8](#0-7) [9](#0-8) [10](#0-9) 

All ordinary market mutations use `synced_market` or `load_leg`, both of which accrue before applying the requested operation. [11](#0-10)  Consequently:

- suppliers cannot withdraw collateral;
- borrowers cannot repay;
- borrowers cannot obtain new debt;
- liquidators cannot settle positions;
- bad-debt cleanup and recapitalization cannot proceed;
- the pool cannot transition the market to a state where user funds are recoverable.

The impact is protocol insolvency in practice for the affected market and permanent freezing of user funds absent an out-of-band contract upgrade.

### Likelihood Explanation

An unprivileged caller can create the required market state through ordinary `supply` and `borrow` calls. The triggering condition requires large aggregate positions and sustained high utilization so that the borrow index grows enough for `borrowed * borrow_index` to cross the `i128` RAY-value ceiling.

The numeric bound is explicit in the codebase’s own boundary documentation: token units are normalized to RAY with `amount * 10^(27 - decimals)`, while aggregate value is `shares * index`. A billion-token, 18-decimal market starts near `10^36` RAY, so an index near `170` approaches the `i128::MAX ≈ 1.70e38` ceiling. The harness reproduces the condition with a billion-token supply, 98% utilization, the high-end XLM rate curve, and repeated accrual; once `update_indexes` fails, both withdrawal and repayment also fail with `MathOverflow` while the index remains below `MAX_BORROW_INDEX_RAY`. [12](#0-11) [13](#0-12) 

The attack requires substantial liquidity rather than privileged access, leaked keys, malformed parameters, or an off-chain dependency.

### Recommendation

Cap accrual before converting aggregate scaled positions back to original value.

At minimum:

1. In `accrue_step`, derive the largest `new_borrow_index` that keeps `borrowed * index` representable, and clamp the interest factor so `new_borrow_index <= min(MAX_BORROW_INDEX_RAY, floor(i128::MAX / borrowed))`.
2. Apply the corresponding safe cap to `new_supply_index`, using `supplied` before and after revenue-share minting.
3. Compute supplier rewards and shortfall from already-validated bounded values; avoid another `borrowed * new_index` overflow in `calculate_supplier_rewards`.
4. Consider storing aggregate debt/supply values in a wider representation, or maintain a market-level value ceiling that prevents new positions from entering the unsafe domain.
5. Add regression coverage proving that `update_indexes`, `withdraw`, `repay`, liquidation, `clean_bad_debt`, and `recapitalize` continue to work at the boundary and that the index cap engages before scaled-value multiplication overflows.

### Proof of Concept

The existing harness provides a concrete reproduction in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-356`:

1. Configure an 18-decimal `BIG18` market using `xlm_curve`, and a separate collateral market.
2. Lift caps in the test environment to permit the domain-boundary position.
3. Call `Controller::supply` for BOB with `[(BIG18, 1_000_000_000 * 10^18)]`.
4. Call `Controller::supply` for ALICE with enough `COL` collateral.
5. Call `Controller::borrow` for ALICE with `[(BIG18, 980_000_000 * 10^18)]`, producing approximately 98% utilization.
6. Advance ledger time and call `Controller::update_indexes([BIG18])` until accrual reverts with `MathOverflow`.
7. Attempt `withdraw(BOB, BIG18, 1)` and `repay(ALICE, BIG18, positive_amount)`.

Both subsequent calls load the same market and execute `global_sync` before the requested action, so both revert with `MathOverflow`. The stored borrow index remains below `MAX_BORROW_INDEX_RAY`, demonstrating that the aggregate-value overflow occurs before the intended index cap can contain it. [11](#0-10) [14](#0-13) [15](#0-14)

pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);

        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
