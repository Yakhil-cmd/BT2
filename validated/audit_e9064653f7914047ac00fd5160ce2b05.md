No vulnerability found for this question.

**Rationale:** The report describes a Solidity/OpenZeppelin-specific issue: a library version bump changed `Ownable`'s constructor to require an explicit owner argument instead of defaulting to `msg.sender`, and consuming contracts that didn't update their constructors ended up with `owner == address(0)`. This is a dependency-version/config-mismatch bug class specific to inherited Solidity library constructors.

Polkadot SDK's FRAME pallets don't use OpenZeppelin or an inherited "Ownable" base-contract pattern at all. Ownership/authorization in FRAME is expressed via explicit origin checks (`ensure_root`, `ensure_signed`, `T::ForceOrigin::ensure_origin`) and explicit storage items like `PalletOwner`, set through dedicated extrinsics such as `set_owner` in the bridges GRANDPA pallet [1](#0-0)  or explicit `owner` parameters passed into `force_create`/`do_create_collection` in `pallet-nfts` [2](#0-1) . There is no implicit "deployer becomes owner" default that could silently degrade to a zero-address/no-owner state due to a dependency upgrade.

The only place where Solidity's OZ `Ownable`-style contracts and their `owner()` semantics appear in this codebase is inside `pallet-revive`'s Solidity test fixtures (e.g. `CatchConstructorFoo`, `MyTokenExpensive.sol`), which are non-production example/test contracts compiled purely for pallet-revive's own test suite, not deployable production runtime code [3](#0-2) [4](#0-3) . Contracts *deployed by end users* through `pallet-revive` are arbitrary EVM/PVM bytecode supplied by the caller — the pallet has no dependency on any specific version of OpenZeppelin's `Ownable.sol`, so there is no wiring by which a polkadot-sdk-controlled dependency bump could silently zero out an owner in a way that maps to this report's root cause (an unversioned/mismatched inherited-constructor default).

There is no real user-entry-point, attacker-controlled input, or missing runtime check in polkadot-sdk that mirrors "OZ Ownable now requires explicit owner argument, contracts didn't update, owner defaults to zero." This is purely a Solidity-application-layer library-upgrade footgun with no FRAME/XCM/bridges analog.
