### Title
Webhook signature verification is bound to an attacker-chosen organization, not the repository the payload actually writes to - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App/organization secret to verify a webhook against by reading an **unverified** field out of the request body itself, then delegates verification to that organization's `GithubApp`. If that organization has no `webhook_secret` configured, verification is a no-op that accepts the request unconditionally. Nothing thereafter re-checks that the "authenticated" organization actually owns the repository the payload claims to describe, so a forged payload can drive writes (syncing commits, statuses, PR state, etc.) against a *different*, properly-secured organization/repository.

### Finding Description
`WebhooksController#verify_signature` derives `repository_owner` straight from the raw, not-yet-verified JSON body: [1](#0-0) 

That value is used to select which `GithubApp` instance (and therefore which `webhook_secret`) is used to validate the `X-Hub-Signature` header: [2](#0-1) 

`GithubApp#verify_webhook_signature` explicitly treats a missing/blank secret as "verified": [3](#0-2) 

and the secret itself is optional/nilable per-organization configuration: [4](#0-3) 

Once `verify_signature` passes (trivially, because the *attacker-chosen* organization has no secret), the controller dispatches the **entire unverified payload** to whichever webhook handlers are registered for that event type: [5](#0-4) 

Those handlers act on other fields of the same payload (e.g. `repository.full_name`, `sha`, `state`) to locate and mutate a `Stack`/`Commit`, completely independent of which organization was used for the signature check. This is exactly the "binding mismatch" bug class from the reference report: a value used to satisfy a security check (`repository.owner.login` used to pick the verification secret) is not the same value that is trusted for the actual state-mutating operation (the repository/stack the handler resolves and writes to from the rest of the same payload). The equality that should hold — `organization_used_for_signature_verification == organization_owning_the_repository_being_written` — does not, because both sides are read from the same untrusted body, and the check is skippable by choosing an org with no configured secret.

### Impact Explanation
An unprivileged attacker who can send an HTTP POST to `/webhooks` (no credentials required — this endpoint is explicitly designed to be called by GitHub, unauthenticated) can:
1. Set `repository.owner.login` (or `organization.login`) in the JSON body to any organization configured in `Shipit.github` that happens to have no `webhook_secret` set (a supported, documented configuration state — `webhook_secret` is `.presence`-checked and can be `nil`).
2. Populate the rest of the payload (`repository.full_name`, commit SHAs, statuses, PR data, etc.) to target a **stack belonging to a different, properly-secured organization**.
3. Because `verify_webhook_signature` short-circuits to `true` for the org with no secret, the request is accepted and dispatched to the real event handlers, which act on the (forged) repository data — e.g. triggering `GithubSyncJob` for an arbitrary stack, injecting fake commit `status` webhooks, or manipulating PR/merge-queue state — without ever presenting a valid signature for the actual target organization/repository.

This is a cross-repository write executed with no GitHub credentials, satisfying the "Critical: cross-repository writes / unauthorized deploy or rollback" bar, since injected commit/status data can influence continuous-deployment decisions on stacks the attacker has no legitimate access to.

### Likelihood Explanation
Requires only that the Shipit deployment be configured with multiple GitHub organizations (a supported and documented configuration, see the multi-org example config keeping `webhook_secret` optional per org) where at least one configured org lacks a `webhook_secret`. This is a plausible/likely misconfiguration since `webhook_secret` is optional by design and not all orgs onboarded to a shared Shipit instance may have it set consistently. No authentication, session, or GitHub token is needed to exploit it — a bare HTTP POST suffices.

### Recommendation
Do not select the verification secret/organization from unverified request data. Instead:
- Verify the signature against every configured organization's secret (or require a single, deployment-wide expected organization) rather than trusting `repository.owner.login`/`organization.login` from the body to pick the org.
- After verifying, cross-check that the resolved organization actually owns the `repository.full_name`/stack the payload claims to mutate, rejecting mismatches.
- Treat an organization with a blank `webhook_secret` as "verification required but impossible" (fail closed) rather than "verification not required" (fail open), removing the `return true unless webhook_secret` bypass in `GithubApp#verify_webhook_signature`.

### Proof of Concept
1. Configure Shipit with two orgs in `Shipit.github`, `OrgA` (no `webhook_secret`) and `OrgB` (has `webhook_secret`, owns the target stack/repository).
2. POST to `/webhooks` with header `X-Github-Event: push` (or `status`, `pull_request`, etc.) and a body such as:
```json
{
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/victim-repo" },
  "after": "<attacker-chosen sha>"
}
```
3. `WebhooksController#verify_signature` resolves `repository_owner` = `"OrgA"`, calls `Shipit.github(organization: "OrgA").verify_webhook_signature(...)`, which returns `true` unconditionally because `OrgA` has no `webhook_secret` (`app/controllers/shipit/webhooks_controller.rb:24-30`, `lib/shipit/github_app.rb:76-83`).
4. The request is accepted with `head(:ok)` and dispatched to the registered `push` handler(s), which act on `repository.full_name = "OrgB/victim-repo"` — a repository under the properly-secured `OrgB` — without any valid signature for `OrgB` ever being presented.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
