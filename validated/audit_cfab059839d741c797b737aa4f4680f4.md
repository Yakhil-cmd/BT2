### Title
`compute_v2_review_set` drops committed dangerous changes when normal git history rewrites break the linear-ancestor check - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` computes the reviewable file set as `dirty_now ∩ changed_since`, where `dirty_now` only picks up committed changes if `head_at_capture` is a strict linear ancestor of the current `HEAD` [1](#0-0) . Any ordinary git operation that advances `HEAD` non-linearly relative to `head_at_capture` (rebase, cherry-pick, reset+recommit, squash) makes `_is_ancestor` return false while the working tree is clean, so `dirty_now` becomes empty even though `changed_since` (diff against `baseline_sha`) still correctly shows the dangerous file as changed [2](#0-1) . Since the final `review_set` is an intersection, an empty `dirty_now` forces `review_set = ∅` regardless of `changed_since` content, silently skipping the Stop hook's LLM security review for that change [3](#0-2) .

### Finding Description
`capture_git_baseline` captures a `git stash create` (or `HEAD` if clean) SHA at `UserPromptSubmit` and stores it plus `head_at_capture` (the `HEAD` SHA at that moment) in session state [4](#0-3) . At `Stop`, `compute_v2_review_set` reconstructs the reviewable set as the intersection of two independently derived sets:
- `dirty_now`: current `git status` dirty/untracked files, plus files touched by commits made since `head_at_capture` — but this addition is gated by `_is_ancestor(head_at_capture, current_head)` [5](#0-4) .
- `changed_since`: `git diff --name-only <baseline_sha>` — a pure content diff, unaffected by ancestry [6](#0-5) .

`_is_ancestor` uses `git merge-base --is-ancestor`, which is false whenever the recorded `head_at_capture` commit is not reachable from the new `HEAD` — this happens under ordinary git workflows such as `git rebase`, `git pull --rebase`, interactive squash, or `git reset --hard <sha>` followed by a fresh commit, all of which create new commit objects that discard the old parent chain [2](#0-1) . When this happens with a clean working tree, `dirty_now` is empty (git status shows nothing dirty, and the ancestor-gated commit diff is skipped), so `review_set = dirty_now ∩ changed_since = ∅` even though `changed_since` still lists the dangerous file as differing from the pre-turn baseline. The dangerous change is never surfaced to `analyze_code_security`/the Stop hook's LLM review, and worse, the Stop hook then re-captures a fresh baseline from the now-clean tree, permanently losing the diff for future turns as well [7](#0-6) .

This is a real logic gap in the "review set must stay bound to repo/baseline/touched paths" invariant: the intersection design assumes `HEAD` only ever moves forward linearly, but nothing in `capture_git_baseline`/`handle_user_prompt_submit`/`handle_stop_hook` validates or re-derives that assumption before trusting an empty `dirty_now`. An unprivileged user driving Claude through ordinary git commands (which is exactly the normal workflow the hook is meant to support) can therefore get a genuinely dangerous, already-committed change silently excluded from security review.

### Impact Explanation
This is a logic-level bypass of a required security guard: the Stop hook's LLM-based vulnerability scan is the codebase's sole automated backstop for Claude-authored changes, and this flaw allows a dangerous diff to be committed and reviewed as if it never happened, purely through normal git operations (rebase/squash/reset+recommit) rather than any privilege escalation or direct state tampering. This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state" — the review set is misbound to a stale ancestry assumption instead of to the actual content delta from the baseline.

### Likelihood Explanation
No special privileges are required — an ordinary Claude Code session in a cloned repo where the user or a crafted prompt causes a rebase/squash/history-rewrite after a dangerous commit is enough to trigger the gap. This is a fairly common workflow (e.g., "please rebase onto latest main" or "squash my commits") and requires no exploitation of parsing bugs, no malicious input beyond standard git commands, and reproduces deterministically given the same sequence.

### Recommendation
Do not gate the commit-derived portion of `dirty_now` on `_is_ancestor`. Instead, always union `dirty_now` with the full `changed_since` set already computed from `baseline_sha` (or drop the ancestor-gated branch and just union `dirty_now` with `changed_since` directly, since `changed_since` already covers non-linear rewrites via content diff). Alternatively, when `_is_ancestor` is false, fall back to treating `changed_since` as authoritative (i.e., `review_set = changed_since` rather than `∅`) instead of relying on an intersection that silently zeroes out when `dirty_now` is empty.

### Proof of Concept
Integration test in the plugin's test suite for `diffstate.compute_v2_review_set`:
1. Init a git repo, create `README.md`, commit (`C0`).
2. Set `head_at_capture = C0`, `baseline_sha = C0` (simulating `capture_git_baseline` at UPS).
3. Write `danger.py` with an obviously vulnerable pattern (e.g., `os.system(user_input)`), `git add`, `git commit` → `HEAD = C1` (child of `C0`).
4. Simulate a history rewrite that breaks linear ancestry while preserving content: create a fresh orphan branch from an unrelated base, cherry-pick `C1`'s tree onto it (or use `git commit-tree` to fabricate a commit with the same tree as `C1` but a synthetic parent not equal to `C0`), and reset `HEAD` to that new commit `C2`. Working tree is clean.
5. Call `compute_v2_review_set(cwd, baseline_sha=C0, head_at_capture=C0)`.
6. Assert: `_is_ancestor(C0, C2)` is `False` (setup sanity check), but the current implementation returns `review_paths == []` even though `danger.py` differs from `baseline_sha` — i.e., `git diff --name-only C0 C2` still contains `danger.py`, but `review_set` is empty. This demonstrates the false negative: the dangerous file is excluded from review by `dirty_now ∩ changed_since` returning ∅ despite `changed_since` containing it, confirming the invariant "review set must stay bound to the right repo, baseline, and touched paths" is violated.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
