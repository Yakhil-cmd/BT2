### Title
Unbounded RAY debt valuation overflows during mandatory accrual and permanently freezes a market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large borrowed-share balance can make `borrowed * borrow_index` exceed `i128::MAX` before the configured borrow-index ceiling is reached. [1](#0-0)  Because every pool mutation runs `global_sync` before repayment, withdrawal, liquidation, or other market accounting, that overflow makes the affected market permanently unusable. [2](#0-1)  The result is permanent freezing of supplier funds and outstanding borrower collateral, satisfying the accepted impact class. [3](#0-2) 

### Finding Description
`accrue_step` first converts the stored scaled borrow balance into a RAY-denominated value with `scaled_to_original`, then computes utilization, updates the borrow index, and calculates accrued interest. [4](#0-3)  Both valuation steps use `Ray::mul`, which delegates to `mul_div_half_up` and panics with `MathOverflow` when the resulting RAY value cannot fit in `i128`. [5](#0-4) [6](#0-5) 

`calculate_supplier_rewards` separately multiplies the same `borrowed` scaled-share total by both the old and new borrow indexes. [7](#0-6)  Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, it does not bound the index by what the market's current scaled-debt balance can represent after multiplication. [8](#0-7)  Consequently, the debt-value domain can be exhausted before the index cap engages. [9](#0-8) 

The pool's normal flow performs `Cache::load`, `interest::global_sync`, mutation, guards, commit, and transfer in that order. [10](#0-9)  Once `global_sync` reaches the overflowing valuation, `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, `recapitalize`, and later `update_indexes` calls all revert before reaching their risk-reducing logic. [2](#0-1) 

### Impact Explanation
All token funds held for the affected market remain trapped because suppliers cannot withdraw and borrowers cannot repay through the affected market path. [11](#0-10)  Liquidators also cannot reduce the debt because liquidation still performs market accrual before planning or settlement. [12](#0-11)  The existing regression test explicitly demonstrates `MathOverflow` from `update_indexes`, followed by failed withdrawal and repayment attempts. [13](#0-12) 

This is stronger than an ordinary transaction revert because no later call can bypass the mandatory accrual and repair the market. [14](#0-13)  The accounting state itself remains representable, but the next required valuation is not, so the contract cannot transition back to an operating state. [15](#0-14) 

### Likelihood Explanation
Triggering the condition requires an unusually large market and sustained index growth, so it is not reachable with ordinary balances. [16](#0-15)  However, the only required user-facing actions are `supply`, `borrow`, and eventually `update_indexes`; where configured caps permit the position size, no privileged role is needed. [17](#0-16)  A market can also approach the boundary through many users' cumulative activity, after which any unprivileged caller can trigger the fatal accrual. [18](#0-17) 

The demonstrated scenario uses a one-billion-whole-token market at 98% utilization on the steep section of the tested curve and reaches the cliff before the protocol's index ceiling. [19](#0-18)  The capital requirement lowers practical likelihood, but it does not remove the permanent-freeze impact once the representable-value boundary is crossed. [9](#0-8) 

### Recommendation
Make the effective index bound depend on the market's current scaled-share totals rather than using only `MAX_BORROW_INDEX_RAY` and `MAX_SUPPLY_INDEX_RAY`. [8](#0-7)  Before applying a new borrow index, clamp it to the largest index satisfying `borrowed_scaled * index / RAY <= i128::MAX`; apply the equivalent bound for the supply index and supplied-share total. [20](#0-19)  If clamping is intentionally not desired, enforce a market-level scaled-share ceiling at every mint so the worst-case value at the configured index ceiling remains representable. [21](#0-20) 

Add a regression assertion that, after reaching the value ceiling, `update_indexes` clamps or performs a bounded no-op while `repay` and `withdraw` still reach their normal accounting paths. [13](#0-12) 

### Proof of Concept
1. Configure an 18-decimal borrowable market whose admitted supply and borrow caps allow approximately `1_000_000_000 * 10^18` base units, and provide sufficient collateral in a separate market. [22](#0-21) 
2. Call `supply(caller, account_id = 0, spoke_id, assets = [(target_hub_asset, 1_000_000_000 * 10^18)])` to create the large liquidity base. [23](#0-22) 
3. Call `borrow(caller, account_id, borrows = [(target_hub_asset, 980_000_000 * 10^18)], to = None)` from an account holding sufficient collateral, producing scaled debt near `1e36` RAY. [24](#0-23) 
4. Allow the market to remain at high utilization and repeatedly invoke `update_indexes` for `[target_hub_asset]` as ledger time advances. [25](#0-24) 
5. Once the index makes `borrowed_scaled * borrow_index / RAY > i128::MAX`, `scaled_to_original` or `calculate_supplier_rewards` panics with `MathOverflow`. [15](#0-14) [1](#0-0) 
6. Subsequent `withdraw(caller, supplier_account, [(target_hub_asset, 1)], None)` and `repay(caller, borrower_account, [(target_hub_asset, positive_amount)])` calls revert during mandatory accrual, leaving the market frozen. [2](#0-1) [26](#0-25)

    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
