### Title
Bad-debt write-down clamps the supply index to `SUPPLY_INDEX_FLOOR_RAW` instead of zeroing shares, resurrecting wiped-out suppliers as "ghost" claims that drain real deposits - (File: contracts/pool/src/interest.rs)

### Summary
`apply_bad_debt_to_supply_index` socializes unpaid debt by multiplying the supply index by `remaining / total_supplied_value`, but then clamps the result at `SUPPLY_INDEX_FLOOR_RAW` (`RAY / 1000`). When bad debt meets or exceeds total supplied value, every supply position is economically wiped out, yet the clamp leaves each holder's scaled shares multiplied by a nonzero index — a phantom claim that is later settled in real tokens against fresh deposits. This mirrors the fastssz bug class: invalid/dead state is silently reinterpreted as a valid object (a ghost block / ghost supply claim) and counted in downstream accounting.

### Finding Description
In `contracts/pool/src/interest.rs:73-89`:

```rust
let capped = bad_debt.min(total_supplied_value);
let remaining = total_supplied_value.checked_sub(cache.env(), capped);
let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
let new_supply_index = cache.supply_index().mul_floor(cache.env(), reduction_factor);
cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
```

When `bad_debt >= total_supplied_value`, `remaining = 0`, so the index should go to zero (wiping all supply claims). Instead it is clamped up to `RAY / 1000`. `total supplied` scaled shares are **not** burned or reset, so every former supplier retains `scaled_amount × RAY/1000` of claim value — roughly 0.1% of their original deposit — that did not exist after the write-down. The pool's own test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` (`contracts/pool/tests/interest.rs:372-427`) demonstrates the consequence: after a wipeout, the stranded claim is `> 0` while `cash == 0`; once a fresh supplier deposits `fresh_cash`, the ghost position's `resolve_withdrawal(i128::MAX, old_scaled)` pays out `gross == fresh_cash`, leaving `cash < fresh_claim` for the honest depositor.

The bad-debt write-down is reachable from unprivileged flows: `clean_bad_debt` / liquidation seize goes through `seize::apply` (`contracts/pool/src/ops/seize.rs:24-28`), which calls `apply_bad_debt_to_supply_index` for the `Borrow` side. Any liquidation that leaves residual debt triggers socialization; a large enough residual relative to `total_supplied_value` activates the clamp.

### Impact Explanation
Permanent loss of funds / protocol insolvency. Suppliers whose positions were wiped out by bad debt keep a nonzero floor-index claim that the pool treats as payable. When new liquidity arrives (new `supply` calls), ghost claimants withdraw real tokens — the test shows a ghost position draining exactly a fresh depositor's full deposit, leaving the pool unable to honor the honest claim (`cash < fresh_claim`). The stolen amount scales with the wiped supply base: ghost value ≈ 0.1% of total supplied value at the floor index, which can be arbitrarily large.

### Likelihood Explanation
Requires bad debt whose unpaid residual reaches the total supplied value of a market — achievable for an attacker who dominates a thin/spoke market: supply most of the pool, borrow to the cap, let the position go bad (price move or self-liquidation edge), and the socialize step clamps the index. `clean_bad_debt` and liquidation are unprivileged entrypoints. After the clamp, any subsequent deposit into that market is immediately exfiltrable by the ghost claimant. The defect is deterministic arithmetic, not a race.

### Recommendation
When `capped == total_supplied_value` (full wipeout), zero out `supplied` shares (and index bookkeeping consistently) instead of clamping the index to `SUPPLY_INDEX_FLOOR_RAW`; or track a tombstone flag so post-wipeout supply claims are unpayable. If the floor exists only to avoid a zero index breaking `calculate_scaled_supply` division, gate the floor on `remaining > 0` and handle the zero-supply case by resetting the market rather than resurrecting claims.

### Proof of Concept
Already encoded in `contracts/pool/tests/interest.rs:372-427`:

1. Seed pool state: `supplied = 1000 RAY` shares, `supply_index = RAY`, `cash = 0`.
2. Call `apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY))` — `supply_index` clamps to `SUPPLY_INDEX_FLOOR_RAW` instead of zero.
3. `cache.unscale_supply_floor(old_scaled) > 0` — the wiped position still has a claim ("ghost" balance).
4. A fresh deposit of `stranded` tokens mints `fresh_scaled` shares and credits cash.
5. The ghost position calls withdrawal (`resolve_withdrawal(i128::MAX, old_scaled)` → `burn_supply` + `debit_cash`): it receives `gross == fresh_cash`, and `cache.cash() < fresh_claim`, so the honest depositor's claim can no longer be covered — funds lost.
