### Title
Third-party collateral top-up straddles the $5 dust gate, permanently blocking `clean_bad_debt` on accounts whose insolvent quote seizes nothing - (File: contracts/controller/src/positions/supply.rs)

### Summary
`clean_bad_debt` is the only permissionless way to remove an insolvent account whose collateral can no longer be seized. It is gated by `is_socializable_bad_debt`: debt must exceed collateral **and** collateral must be at or below a fixed $5 WAD threshold. Because `supply` lets any third party top up an existing supply leg of any account (`require_third_party_existing_supply` only blocks *new* asset slots, not additions to existing ones), a single unprivileged address can repeatedly donate small amounts of an asset the insolvent account already supplies, pinning `total_collateral` just above $5. When the account's collateral is simultaneously too small to back one whole debt-token unit at the base bonus, every `liquidate` call reverts with `InvalidPayments`, so the straddle is not self-correcting: the account can neither be liquidated nor cleaned without the owner-gated `force_socialize_bad_debt`. Bad debt accrues interest against suppliers indefinitely in the meantime.

### Finding Description [1](#0-0) 
`require_third_party_existing_supply` admits any caller to add to supply positions the account already holds, with no owner consent and no solvency check on the target (supply skips post-flow risk checks entirely). [2](#0-1) 
`socialize_bad_debt` with the `DustCapped` gate (the permissionless path via `process_clean_bad_debt`) requires `is_socializable_bad_debt(total_debt, total_collateral)` — i.e., `total_debt > total_collateral && total_collateral <= 5 WAD`. Any state with collateral strictly above $5 reverts `CannotCleanBadDebt`.

On the liquidation side, the insolvency branch quotes `floor(C * WAD / (1 + base))` and trims each kept debt leg down to whole token units; a leg whose kept amount rounds to zero is dropped, and if no leg remains `liquidate` reverts with `InvalidPayments` (`docs/reference/formulas.md`, confirmed by `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote` where $9 collateral against a $10-unit debt token reverts every offer). So there is a live window — collateral between $5 and roughly one debt unit divided by `1 + base` — where an account is insolvent, unliquidatable, and un-cleanable. An attacker keeps the account inside this window for the cost of topping up an existing supply leg whenever accrual or price movement pushes collateral back under $5. [3](#0-2) 
The project's own Certora spec proves the primitive: `bad_debt_straddle_blocks_dust_gate` asserts that a single WAD unit above `BAD_DEBT_USD_THRESHOLD` shuts the permissionless gate while the account stays insolvent.

### Impact Explanation
While the straddle holds, the insolvent account's debt keeps accruing borrow interest that will ultimately be written down onto suppliers of that market via `apply_bad_debt_to_supply_index`, and the residual collateral cannot be converted to revenue. Since `liquidate` reverts and `clean_bad_debt` reverts, the only remaining escape is the privileged, timelocked `force_socialize_bad_debt` governance runbook — a permissionless cleanup path is permanently suppressed for as long as the attacker funds the top-ups (each top-up is capped near the width of the band: a few dollars). This is a protocol-level liveness failure on the bad-debt clearing path: funds owed to suppliers grow and the stuck account's debt legs cannot be exited by anyone.

### Likelihood Explanation
Medium. The attack requires (a) a victim account insolvent with collateral in the narrow unliquidatable band, and (b) a griefing attacker willing to donate a few dollars of collateral per upkeep round, losing each donation to protocol revenue when cleanup eventually succeeds. No oracle manipulation, privileged access, or timing is needed — `supply(caller, victim_id, spoke_id, [(existing_asset, dust)])` is fully permissionless for existing legs, and the attacker can compute the exact top-up size from `get_total_collateral_usd`. States in the band arise naturally whenever a low-decimal or high-unit-value debt token is listed and small accounts go underwater.

### Recommendation
Make the dust gate resistant to unilateral top-ups. Options: (1) evaluate `is_socializable_bad_debt` on collateral *excluding* supply legs created or grown by non-owner/non-delegate callers after the account first became insolvent (requires tracking provenance per leg); (2) raise the gate to a value-based test that also admits accounts whose insolvent liquidation quote backs less than one unit of every debt leg (i.e., admit when liquidation is provably impossible); or (3) simplest, let `clean_bad_debt` itself accept bundled repayments/third-party collateral receipts so a top-up cannot widen the gap — e.g., admit when `total_collateral <= BAD_DEBT_USD_THRESHOLD` measured at the *lowest* recorded collateral since insolvency. At minimum, treat "collateral just above the dust cap with an empty liquidation plan" as socializable, since the $5 cap exists only to bound cleanup cost, not to require a cleanable position.

### Proof of Concept
1. Victim account V supplies collateral token A and borrows a low-decimal/high-unit debt token D. A price move or accrual leaves V insolvent with `total_collateral_usd ≈ $6` and `total_debt_usd ≈ $9`, where one D unit is worth $10 — matching the fixture in `test_insolvent_liquidation_reverts_when_no_debt_unit_fits_the_backed_quote`.
2. Any liquidator call `liquidate(l, V, [(D_key, k)], SeizeMode::Transfer)` → reverts `InvalidPayments` (#16): the insolvency quote `floor($6/1+b)` backs less than one D unit, the leg is dropped, the plan is empty.
3. `clean_bad_debt(caller, V)` → reverts `CannotCleanBadDebt` (#114): `total_collateral` ($6) > `BAD_DEBT_USD_THRESHOLD` ($5).
4. Interest accrues; suppose accrual/price drift lowers `total_collateral_usd` to $4.90. Attacker calls `supply(attacker, V, V_spoke, [(A_key, $0.20)])` — permitted by `require_third_party_existing_supply` because V already holds an A supply leg. `total_collateral` returns above $5; step 3 still reverts.
5. Repeat step 4 indefinitely. Debt compounds onto A/D suppliers; the account is removed only if governance executes the timelocked `ForceSocializeBadDebt` operation, confirming the permissionless path is dead while the straddle is funded.

/// Admission condition for bad-debt socialization.
#[derive(Clone, Copy, PartialEq)]
enum BadDebtGate {
    /// Permissionless: insolvent *and* collateral at or below the dust threshold.
    DustCapped,
    /// Owner-only: insolvent alone, with no cap on the collateral left behind.
    InsolventOnly,
}

/// Requires open debt and the selected insolvency gate, then cleans up the account.
fn socialize_bad_debt(env: &Env, account_id: u64, gate: BadDebtGate) {
    let mut cache = Context::new(env);
    let account = storage::get_account(env, account_id);

    assert_with_error!(
        env,
        !account.borrow_positions.is_empty(),
        CollateralError::DebtPositionNotFound
    );

    let totals = risk::calculate_account_risk_totals(
        env,
        &mut cache,
        &account.supply_positions,
        &account.borrow_positions,
    );

    let admits = match gate {
        BadDebtGate::DustCapped => {
            is_socializable_bad_debt(totals.total_debt, totals.total_collateral)
        }
        BadDebtGate::InsolventOnly => totals.total_debt > totals.total_collateral,
    };
    assert_with_error!(env, admits, CollateralError::CannotCleanBadDebt);

    bad_debt::execute_bad_debt_cleanup(env, &mut cache, account_id, &account, &totals);
}

/// Straddle, first half. An attacker who raises `total_collateral` strictly above
/// `BAD_DEBT_USD_THRESHOLD` (`BAD_DEBT_USD_THRESHOLD + 1` is the cheapest such state) blocks
/// the permissionless dust-gated socialization path while staying insolvent. The gate is
/// value-based, not count-based, so one unit of a second collateral cannot block it: the
/// attacker must post value above the threshold and keep it there.
#[rule]
fn bad_debt_straddle_blocks_dust_gate(e: Env, debt_wad: i128, collateral_wad: i128) {
    let _ = e;
    cvlr_assume!(collateral_wad >= BAD_DEBT_USD_THRESHOLD + 1);
    cvlr_assume!(collateral_wad <= 1_000_000 * WAD);
    cvlr_assume!(debt_wad > collateral_wad && debt_wad <= 2_000_000 * WAD);

    // Symbolic straddle: anywhere strictly above the cap, the dust gate is shut.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(debt_wad),
        Wad::from(collateral_wad)
    ));

    // Explicit +1 witness: one raw WAD unit above the cap blocks it.
    cvlr_assert!(!is_socializable_bad_debt(
        Wad::from(BAD_DEBT_USD_THRESHOLD + 2),
        Wad::from(BAD_DEBT_USD_THRESHOLD + 1)
    ));
