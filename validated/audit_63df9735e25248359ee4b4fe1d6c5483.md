### Title
Non-linear HEAD movement (amend/rebase/reset) after a Claude commit collapses the Stop-hook review set to empty, permanently baselining the dangerous change - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only adds committed-but-clean changes to `dirty_now` when `head_at_capture` is a linear ancestor of the current `HEAD` [1](#0-0) . Any normal git operation that moves `HEAD` non-linearly relative to the UPS-captured `head_at_capture` (e.g. `git commit --amend`, `git rebase`, `git reset --hard` + recommit) makes `_is_ancestor` return false, so a clean working tree yields an empty `dirty_now`, which forces `review_set` to be empty regardless of what `changed_since` (diff vs. `baseline_sha`) contains [2](#0-1) . The Stop hook then exits via the "empty review set" skip path without ever updating `previous_findings`/flagging anything [3](#0-2) , and because `touched_paths` was already cleared by `consume_stop_state`, the very next `UserPromptSubmit` re-baselines fresh off the now-vulnerable `HEAD` via `capture_git_baseline`, since the preservation guard requires non-empty `touched_paths` [4](#0-3) . The vulnerable code is thereby folded into the new baseline and never surfaces to review again.

### Finding Description
The v2 review-set algorithm computes:
```
review_set = dirty_now ∩ changed_since   (or dirty_now alone if changed_since is None)
```
`dirty_now` comes purely from `git status --porcelain` (uncommitted tracked/untracked changes) plus, only in the linear-fast-forward case, `_git_name_only(head_at_capture..HEAD)` [5](#0-4) . If Claude (driven by attacker-controlled prompt/repo content) commits a vulnerable change and then performs any ordinary git rewrite of that commit — `git commit --amend`, `git rebase -i`, or `git reset` followed by a new commit — the resulting `HEAD` is no longer a descendant of `head_at_capture` in the ancestor sense the code checks for, so the `_is_ancestor` branch is skipped. With a clean working tree, `dirty_now` becomes the empty set. Since `review_set = dirty_now ∩ changed_since`, an empty `dirty_now` yields an empty `review_set` no matter how `changed_since` (which does correctly diff against `baseline_sha`) evaluates — the intersection with ∅ is always ∅. `handle_stop_hook` treats this as `_skip(9)` ("empty review set") and exits without any LLM review, finding recording, or baseline advance under the found-vulnerability code path [3](#0-2) .

Because `consume_stop_state` unconditionally clears `touched_paths` before this skip occurs [6](#0-5) , the next `UserPromptSubmit`'s preservation guard (`if state.get("touched_paths") and state.get("baseline_sha")`) does not fire, so `capture_git_baseline` overwrites `baseline_sha`/`head_at_capture` with the current (already-vulnerable) tree state [7](#0-6) . From that point on, the vulnerable file is part of the "baseline" and `changed_since` diffs will never show it as new, permanently excluding it from review while the review invariant claims only Claude-authored changes since baseline are reviewed.

### Impact Explanation
This is a security-control bypass: a dangerous code change that was actually introduced and committed by Claude in-session is silently excluded from the Stop-hook's LLM vulnerability scan and from `previous_findings` tracking, and the plugin's own baseline bookkeeping then treats that vulnerable state as pre-existing/"clean" for all future turns. This matches the "Security-control bypass that silently disables or routes around blocking, review, or permission boundaries" impact category — the review pipeline continues to run and report success/no-findings, giving a false sense of safety while the actual dangerous diff was never analyzed.

### Likelihood Explanation
No special privileges are needed beyond normal use of Claude Code on a git-backed project: any workflow where a commit is amended, rebased, or reset (all common developer/agent actions, and plausibly triggerable by prompt-injected repo content instructing "amend the last commit" or similar) reliably reproduces the empty-`dirty_now` condition. The bug is deterministic given the ancestor check and requires no race condition or timing precision, making it highly repeatable.

### Recommendation
Do not gate committed-change inclusion in `dirty_now` on strict linear ancestry of `head_at_capture`. Instead, whenever `current_head != head_at_capture` (regardless of ancestry), fold in `_git_name_only(f"{head_at_capture}...{current_head}")` (merge-base diff) or, more robustly, always compute `changed_since` (diff vs. `baseline_sha`) as the review set directly rather than intersecting with a `dirty_now` that can go empty after non-fast-forward history rewrites. At minimum, treat a non-ancestor `head_at_capture` as a signal to union `_git_name_only(baseline_sha)` unconditionally into `dirty_now` so amend/rebase/reset cannot zero out the review set.

### Proof of Concept
Integration test plan (pytest against `diffstate.compute_v2_review_set` / `security_reminder_hook.handle_stop_hook`):
1. Init a temp git repo with one commit.
2. Call `capture_git_baseline(cwd)` to simulate UPS; record `baseline_sha`, `head_at_capture = _git_rev_parse_head(cwd)`.
3. Write `evil.py` with an injected dangerous pattern (e.g. `os.system(user_input)`), `git add`, `git commit -m "vuln"`.
4. Run `git commit --amend --no-edit` (simulating an ordinary git rewrite) so `HEAD` changes but is not an ancestor-descendant of `head_at_capture` in the checked sense.
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})` and assert: **expected (secure) behavior** — `review_paths` contains `evil.py`; **actual (vulnerable) behavior** — `review_paths == []` because `dirty_now` is empty.
6. Drive it end-to-end through `handle_stop_hook` with a fake `input_data`, asserting the hook takes the `_skip(9)` path (`skip_reason == 9`) instead of invoking `analyze_code_security` on `evil.py`.
7. Simulate the next `UserPromptSubmit` (`handle_user_prompt_submit`) and assert `state["baseline_sha"]` is overwritten to the post-amend HEAD, then re-run `compute_v2_review_set` for a no-op turn and assert `evil.py` never appears in any subsequent review set.

    tracked_dirty, untracked = _git_status_porcelain(repo)
    if tracked_dirty is None:
        return [], "HEAD", repo, [], {"dirty_now_count": -1, "changed_since_count": -1, "review_set_count": 0}

    def _unchanged_since_baseline(p):
        base_mtime = untracked_at_baseline.get(p)
        if base_mtime is None:
            return False
        try:
            return os.stat(os.path.join(repo, p)).st_mtime_ns == base_mtime
        except OSError:
            return False

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
