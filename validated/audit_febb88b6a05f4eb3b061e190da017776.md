### Title
`deregisterOperator` Does Not Revoke Outstanding Votes, Allowing Deregistered Operator's Vote to Execute Bridge Value Transfers — (File: `contracts/service_chain/bridge/BridgeOperator.sol`)

### Summary

`BridgeOperator.deregisterOperator()` removes an operator from the active set but does not clear that operator's already-cast votes from the `votes` storage mapping. A remaining active operator can subsequently cast the final vote needed to reach `operatorThresholds`, causing the bridge to execute a KLAY/ERC20/ERC721 value transfer that was authorized in part by a deregistered operator.

### Finding Description

`deregisterOperator` removes the operator from `operators` and `operatorList` but leaves all entries in `votes[voteType][nonce].voted[operator]` and `votes[voteType][nonce].voteCounts[voteKey]` intact: [1](#0-0) 

The vote-counting logic in `_voteCommon` checks `voteCounts[voteKey] >= operatorThresholds[voteType]` at the moment each new vote is cast: [2](#0-1) 

Because the deregistered operator's `voteCounts` contribution is never decremented on deregistration, a single subsequent vote from any remaining active operator can push the count to or past the threshold, triggering `closedValueTransferVotes[nonce] = true` and executing the asset transfer: [3](#0-2) 

The contract's own comment acknowledges this behavior but treats it as an operator-management concern rather than fixing it: [4](#0-3) 

### Impact Explanation

A bridge value transfer (KLAY, ERC20, or ERC721) is executed on the destination chain using a vote that was partially authorized by an operator the owner has explicitly revoked. This constitutes an unauthorized asset transfer affecting bridged funds. Concretely:

- `handleKLAYTransfer` sends KLAY to `_to` after `_voteValueTransfer` returns `true`.
- `handleERC20Transfer` mints or transfers ERC20 tokens after the same vote check. [5](#0-4) [6](#0-5) 

### Likelihood Explanation

The scenario requires: (1) an operator casting a vote on a pending nonce, (2) the owner deregistering that operator (intending to block the transfer), and (3) a remaining operator casting the threshold-completing vote. This is a realistic operational sequence — the owner deregisters a compromised or misbehaving operator precisely to prevent a pending transfer from executing, but the stale vote defeats that intent. Likelihood is **Medium**.

### Recommendation

In `deregisterOperator`, iterate over all open nonces and decrement `voteCounts` for any vote the deregistered operator has cast, or set `vote.voted[_operator]` to `bytes32(0)` and decrement the corresponding `voteCounts` entry. Alternatively, add a `clearVotes(address _operator, VoteType _voteType, uint64[] calldata _nonces)` function that the owner can call before or atomically with deregistration to explicitly revoke outstanding votes.

### Proof of Concept

Setup: threshold = 2, operators = [Owner, A, B].

1. Operator A calls `handleKLAYTransfer(txHash, from, to, 1 ether, nonce=5, blockNum)` → `voteCounts[voteKey]` for nonce 5 becomes 1. Transfer not yet executed.
2. Owner calls `deregisterOperator(A)` → `operators[A]` deleted, `operatorList` shrunk to [Owner, B]. `voteCounts[voteKey]` for nonce 5 **remains 1**.
3. Operator B calls `handleKLAYTransfer(txHash, from, to, 1 ether, nonce=5, blockNum)` → `_voteCommon` increments `voteCounts[voteKey]` to 2, which equals `operatorThresholds[ValueTransfer]` (still 2). Returns `true`.
4. `closedValueTransferVotes[5]` is set to `true`, and `_to.call.value(1 ether)("")` executes — 1 KLAY is transferred using A's revoked vote. [2](#0-1) [7](#0-6)

    function _voteCommon(VoteType _voteType, uint64 _nonce, bytes32 _voteKey)
        private
        returns(bool)
    {
        VotesData storage vote = votes[uint8(_voteType)][_nonce];

        // If the same voter voted again, revoke previous vote.
        bytes32 oldVoteKeyOfVoter = vote.voted[msg.sender];
        if (oldVoteKeyOfVoter == bytes32(0)) {
            vote.voters.push(msg.sender);
        } else {
            vote.voteCounts[oldVoteKeyOfVoter]--;
        }

        // Either the current voter has voted before or not, update the vote data.
        vote.voted[msg.sender] = _voteKey;

        if (vote.voteCounts[_voteKey] == 0) {
            vote.voteKeys.push(_voteKey);
        }
        vote.voteCounts[_voteKey]++;

        if (vote.voteCounts[_voteKey] >= operatorThresholds[uint8(_voteType)]) {
            return true;
        }
        return false;
    }

    // _voteValueTransfer votes value transfer transaction with the operator.
    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }

    function deregisterOperator(address _operator)
    external
    onlyOwner
    {
        require(operators[_operator]);
        delete operators[_operator];

        for (uint i = 0; i < operatorList.length; i++) {
           if (operatorList[i] == _operator) {
               operatorList[i] = operatorList[operatorList.length-1];
               operatorList.length--;
               break;
           }
        }
        emit OperatorDeregistered(_operator);
    }
