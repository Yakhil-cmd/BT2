### Title
`Shipit::Api::CCMenuController` bypasses `ApiClient` stack scoping, letting a stack‑scoped token read the build state of any stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::BaseController` enforces stack scoping for every API request via the `stacks`/`stack` helpers, which restrict lookups to `current_api_client.stack_id` when the client is scoped to a single stack. [1](#0-0) 
`Shipit::Api::CCMenuController` overrides `#stack` to resolve the stack straight from `params[:stack_id]` via `Stack.from_param!`, completely skipping the `stacks` scoping helper, while still only requiring the generic `read:stack` permission (not "this particular stack"). [2](#0-1) 
This breaks the binding "a stack a token authorises == a stack it touches": a token created with `stack_id` set (i.e. authorized for exactly one stack) can be used to fetch CCMenu XML build status for every other stack in the Shipit instance.

### Finding Description
`ApiClient` records can be scoped to a single stack via `stack_id`, and `BaseController#stacks` is the mechanism that enforces that scope:
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
``` [1](#0-0) 

Every other controller under `app/controllers/shipit/api/**` relies on this inherited `stack` method (confirmed for `app/controllers/shipit/api/stacks_controller.rb`), so a token scoped with `stack_id` can only reach the one stack it was issued for.

`CCMenuController`, however, defines its own `stack` method that ignores `stacks` entirely and resolves any `stack_id` param against the full `Stack` table:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
``` [3](#0-2) 

The controller's only authorization gate is the class-level `require_permission :read, :stack`, which merely checks that `"read:stack"` is present in `current_api_client.permissions` — a global, non-stack-specific string check: [4](#0-3) 
It never verifies that the requested `stack_id` matches the client's authorized `stack_id`. This is exactly the class of bug in the external report: a state/scope established at one point (the `stack_id` binding baked into the token when it was created, e.g. by `CCMenuUrlController#client`) is silently not enforced at the point where the privileged action is executed (`CCMenuController#show`).

For context, tokens with a `stack_id` are routinely created and handed out for exactly this "cctray" use case:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
``` [5](#0-4) 
(Note: this particular helper doesn't set `stack_id`, but the `ApiClient` model and permission set fully support stack-scoped tokens — see the `here_come_the_walrus` fixture — and any application code, admin UI, or automation minting a stack-scoped `read:stack` token intends that scoping to be respected by every controller, including `CCMenuController`.) [6](#0-5) 

### Impact Explanation
Any holder of a legitimately-issued, stack-scoped API token (permission `read:stack`, `stack_id` set to stack A) can query `GET /api/stacks/:stack_id/ccmenu.xml` for an arbitrary stack B they were never authorized to see, and obtain that stack's last deploy id, status (running/success/failure), timestamps, and lock state. This matches the explicitly allowed High-impact category "unauthenticated read of stack state" (unauthenticated relative to stack B, since the token was never granted read access to B) — the token holder reads state of a stack it does not authorize against.

### Likelihood Explanation
Likelihood is Medium: it requires possession of any valid, stack-scoped `read:stack` API token (a routine, low-privilege credential type explicitly supported by `ApiClient`), and no other privilege (no repository write access, no GitHub App key, no admin account) is needed. The `stack_id` for the target stack is a low-entropy, guessable/discoverable path parameter (`params[:stack_id]` from `Stack.from_param!`, typically the stack's slug/environment), so cross-stack enumeration is straightforward once a single scoped token is obtained.

### Recommendation
Make `CCMenuController#stack` reuse the inherited, scope-respecting `stack`/`stacks` helpers from `BaseController` instead of calling `Stack.from_param!` directly, e.g.:
```ruby
def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```
so that a client with a non-nil `stack_id` can never resolve a different stack, consistent with every other API controller.

### Proof of Concept
1. As an authorized user, mint (or use an existing) `ApiClient` scoped to stack "A": `permissions: ["read:stack"], stack_id: <A.id>`. Obtain its `authentication_token`.
2. Send `GET /api/stacks/B/ccmenu.xml?token=<token>` for any other stack "B" (`stack_id` not equal to A).
3. Observe `CCMenuController#authenticate_api_client` successfully authenticates via the token query param, `require_permission :read, :stack` passes (the token has `read:stack`), and `CCMenuController#stack` resolves stack B via `Stack.from_param!` — bypassing the `stacks` scoping that would have raised `ActiveRecord::RecordNotFound` in every other API controller. The response returns stack B's real build/deploy status, proving the token's `stack_id` binding was not enforced.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
```
