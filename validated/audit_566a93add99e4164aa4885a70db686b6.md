## Analysis

`_diff_pathspec` in `plugins/security-guidance/hooks/gitutil.py` converts absolute touched-file paths into repo-relative strings and splices them directly after `--` for `git diff`, with no escaping of git pathspec "magic" syntax and no `--literal-pathspecs` / `core.literalPathspecs=true` set anywhere in `GIT_CMD`. [1](#0-0) 

`GIT_CMD` never enables literal pathspec mode: [2](#0-1) 

This pathspec list feeds directly into the `git diff` invocation that produces the text the LLM security reviewer analyzes: [3](#0-2) 

Touched-file paths originate from `tool_input.file_path` on `Write`/`Edit`/`MultiEdit`/`NotebookEdit` calls and are recorded verbatim, byte-for-byte, with no sanitization of pathspec-magic characters: [4](#0-3) [5](#0-4) 

By default (without `--literal-pathspecs`), `git` treats a pathspec string with a leading `!` (or `:!`) as a **negative/exclusion** pathspec rather than a literal filename, and treats `*`, `?`, `[...]` as fnmatch glob operators rather than literal characters. Since `_diff_pathspec` appends filenames unmodified to the pathspec list, a file whose actual on-disk path begins with `!` (a valid POSIX filename byte) — created or edited as a result of repo-controlled/prompt-injected instructions — turns the sole pathspec entry into an exclusion pattern instead of an inclusion pattern. `git diff -- '!evil.py'` does not select `evil.py`; it selects everything *except* paths matching `evil.py`. The result is that the very file the attacker caused to be touched is silently dropped from `diff_output`, so it never reaches `parse_diff_into_files` → `analyze_code_security`, and the Stop-hook / commit-review LLM security linter never sees the dangerous change: [6](#0-5) 

Filenames containing `*`, `?`, or `[...]` similarly get fnmatch-expanded rather than matched literally, which can cause the intended file to fail to match (and be excluded from review) while pulling in unrelated files instead. There is no code anywhere in `gitutil.py`/`security_reminder_hook.py` that quotes, escapes, or uses `:(literal)`/`--literal-pathspecs` to defeat this, and no test exercises pathspec-magic filenames.

Note on impact framing: the security-guidance hook is a *post-hoc advisory reviewer* (Stop/PostToolUse hooks that emit guidance and force Claude to continue fixing issues via `sys.exit(2)`), not a `PreToolUse` allow/deny gate. So this bug does not itself execute unauthorized shell commands or bypass Claude Code's permission system directly — its real, concrete impact is that it lets an attacker-controlled filename silently evade the LLM-based dangerous-change detector that this plugin exists to provide, which is a genuine break of the stated invariant ("reviewable-source filtering must not let attacker-crafted filenames hide dangerous source changes").

### Title
Git pathspec-magic filenames (`!`, `*`, `?`, `[`) let attacker-controlled paths escape diff review scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` passes touched-file paths to `git diff --` unescaped, so filenames beginning with `!` or containing glob metacharacters are interpreted as git pathspec magic (exclude/glob) instead of literal paths. A repo-controlled or prompt-injected file rename/creation with such a name causes the file's own changes to be excluded from the diff fed into `analyze_code_security`, hiding the dangerous edit from the security-guidance review.

### Finding Description
`_diff_pathspec` (`gitutil.py:70-88`) builds pathspec arguments from `os.path.relpath` output with no escaping, and `GIT_CMD` (`gitutil.py:25-29`) never sets `--literal-pathspecs`/`core.literalPathspecs=true`. Touched paths originate unsanitized from `tool_input.file_path` via `record_touched_path` (`diffstate.py:57-71`, `security_reminder_hook.py:2112-2122`). `get_git_diff` (`gitutil.py:391-414`) splices this pathspec directly after `git diff <base>`. Because git parses pathspec magic (`!`/`:!` = exclude, `*`/`?`/`[...]` = glob) even after `--`, a filename like `!payload.py` becomes an exclusion pattern rather than a match for the literal path, so the diff for that file is omitted from `diff_output`, which is what `parse_diff_into_files`/`analyze_code_security` inspect (`security_reminder_hook.py:1806-1827`).

### Impact Explanation
An attacker able to influence file naming (via repo content, injected task instructions, or a malicious PR causing the agent to write a maliciously-named file) can cause dangerous source changes to be silently excluded from the LLM-based security review that this plugin performs at Stop/commit-review time. This defeats the reviewable-source filtering invariant and lets a dangerous change go unflagged. It is not a bypass of Claude Code's PreToolUse permission/approval system since this hook is advisory, not a gate — the concrete impact is detection evasion for the security-guidance plugin, not direct unauthorized command execution.

### Likelihood Explanation
Requires only the ability to get a file created/renamed on disk with a pathspec-magic-prefixed name (`!`, or containing `*`/`?`/`[`), which is achievable via ordinary repo content or agent instructions and is valid on POSIX filesystems. No privilege escalation needed; fully repeatable.

### Recommendation
Use `--literal-pathspecs` (or set `GIT_LITERAL_PATHSPECS=1` / `core.literalPathspecs=true` in `GIT_CMD`) for all diff/status/add invocations in `gitutil.py`, or explicitly prefix each pathspec entry with `:(literal)` in `_diff_pathspec` before appending to the pathspec list.

### Proof of Concept
Unit test plan: create a temp git repo; create and commit an initial state; create a file named `!evil.py` and modify it (making it dirty); call `_diff_pathspec(repo, [abs_path_to_"!evil.py"])` and then `get_git_diff(repo, "HEAD", paths=[abs_path])`; assert the returned diff text does NOT contain the change to `!evil.py` (demonstrating exclusion) despite the file being the sole touched/dirty path — expected correct behavior is that the diff contains the change; the bug is confirmed if it's empty/missing. A second variant with a filename containing `*` (e.g. `a*b.py`) should assert the pathspec either fails to match the literal file or unexpectedly matches other files.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

```python
def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
```

```python
def record_touched_path(session_id, file_path):
    """Append a file path to the touched_paths list (deduped, capped at 200).

    Stop is the consumer and clears under the same lock it reads with; UPS
    no longer wipes. The cap is a defensive bound for sessions where Stop
    never fires (disabled mid-session, abort) — git diff naturally filters
    stale paths so over-retention is harmless, just wasteful.
    """
    def _record(state):
        paths = state.setdefault("touched_paths", [])
        if file_path not in paths:
            paths.append(file_path)
            if len(paths) > 200:
                del paths[:len(paths) - 200]
    with_locked_state(session_id, _record)
```
