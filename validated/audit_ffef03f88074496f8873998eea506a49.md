### Title
Panic (index out of range) in `getOrgAndRepo` when attestation predicate's `workflow.repository` lacks an org/repo path segment - ([File: pkg/cmd/attestation/inspect/bundle.go])

### Summary
`getAttestationDetail` parses the attacker-controlled `statement.Predicate` from an attestation bundle and passes `predicate.BuildDefinition.ExternalParameters.Workflow.Repository` into `getOrgAndRepo`. If that string, after prefix-stripping, does not contain a `/` (e.g. `"https://github.com/foo"` with no repo name, or `"https://github.com/"`), `strings.Split` returns a single-element slice and the subsequent `parts[1]` access panics with an index-out-of-range error, crashing the `gh attestation inspect` process.

### Finding Description
In `getAttestationDetail` (pkg/cmd/attestation/inspect/bundle.go:77-102), the predicate is unmarshaled from the attacker's bundle without any structural validation beyond JSON syntax: [1](#0-0) 

`getOrgAndRepo` then strips a known prefix (`https://github.com/` or the tenant equivalent) and blindly indexes into the split result: [2](#0-1) 

`found` only confirms the prefix matched — it does not guarantee an `/`-separated org/repo remains in `after`. If `Workflow.Repository` is e.g. `"https://github.com/onlyorg"` or exactly `"https://github.com/"`, `strings.Split(after, "/")` yields `["onlyorg"]` or `[""]` (length 1), and `parts[1]` panics with "index out of range [1] with length 1". Since `Workflow.Repository` is a plain string field fully controlled by whoever authored the attestation predicate/bundle that the victim points `gh attestation inspect` at, an attacker can trivially craft such a value. There is no recover/guard around this call path, so the panic propagates and crashes the CLI invocation.

### Impact Explanation
This is a denial-of-service against the victim's local `gh` CLI process: running `gh attestation inspect` (or any inspect flow reaching `getAttestationDetail`) against an attacker-supplied bundle/artifact with a malformed `workflow.repository` predicate field causes an unrecovered panic and process crash. This matches the "unbounded resource consumption/crash from a hostile input" class (DoS on the CLI invocation), not RCE or credential exposure.

### Likelihood Explanation
High feasibility and full attacker control: the attacker only needs to publish an attestation bundle/artifact with a crafted predicate (no privileges, tokens, or victim interaction beyond running an ordinary `gh attestation inspect` command against attacker-controlled content). The bug is deterministic and repeatable — any predicate whose `Workflow.Repository` string lacks a second `/`-delimited segment after the known prefix reliably panics.

### Recommendation
In `getOrgAndRepo`, validate `len(parts) == 2` (and both non-empty) after `strings.Split`, returning a descriptive error instead of indexing unconditionally, e.g.:
```go
parts := strings.Split(after, "/")
if len(parts) != 2 || parts[0] == "" || parts[1] == "" {
    return "", "", fmt.Errorf("failed to get org and repo from %s", repoURL)
}
return parts[0], parts[1], nil
```

func getOrgAndRepo(tenant, repoURL string) (string, string, error) {
	var after string
	var found bool
	if tenant == "" {
		after, found = strings.CutPrefix(repoURL, "https://github.com/")
		if !found {
			return "", "", fmt.Errorf("failed to get org and repo from %s", repoURL)
		}
	} else {
		after, found = strings.CutPrefix(repoURL,
			fmt.Sprintf("https://%s.ghe.com/", tenant))
		if !found {
			return "", "", fmt.Errorf("failed to get org and repo from %s", repoURL)
		}
	}

	parts := strings.Split(after, "/")
	return parts[0], parts[1], nil
}
