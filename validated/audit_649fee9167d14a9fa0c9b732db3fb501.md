### Title
Per-organization webhook signature verification is bypassed by a payload field the check never binds to — enables cross-repository status forgery and unauthorized merges (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` derives *which* GitHub App/organization secret to use for HMAC verification from `repository.owner.login` (or `organization.login`) in the untrusted payload, then calls the corresponding handler with the full, unvalidated payload. Handlers such as `StatusHandler` act on data (`sha`) that has no binding whatsoever to the organization that was used to validate the signature. When any configured organization has no `webhook_secret` set (a state the engine explicitly supports and documents as "optional"), `verify_webhook_signature` short-circuits to `true` for that organization [1](#0-0) . An attacker can then submit a "signed" (or entirely unsigned) webhook request that is only authenticated against the secret-less organization, while the payload's `sha`/effect targets a commit belonging to a completely different, secured repository/organization elsewhere in the same Shipit installation.

### Finding Description
The webhook flow is:
1. `WebhooksController#verify_signature` picks the `GitHubApp` instance to verify against using `repository_owner`, itself read straight out of the same JSON body being verified: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [2](#0-1) [3](#0-2) .
2. `Shipit.github(organization: repository_owner)` resolves per-organization config, and Shipit explicitly supports multiple GitHub Apps/organizations each with an independent, optional `webhook_secret` [4](#0-3) [5](#0-4) .
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's `webhook_secret` is blank/unset: `return true unless webhook_secret` [1](#0-0) . Every example/scaffolded config ships with `webhook_secret: # nil` and documents it as optional [6](#0-5) [7](#0-6) .
4. Once "verified," `WebhooksController#create` dispatches the raw payload to all handlers for the event, unconditionally: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [8](#0-7) .
5. `StatusHandler#process` never re-checks the repository/organization at all — it updates status for **any** commit in the entire database matching the attacker-supplied `sha`: `Commit.where(sha: params.sha).each { |commit| commit.create_status_from_github!(params) }` [9](#0-8) .

This is the same class of trust-binding failure as the SponsorVault report: the report used a spot price (an easily-manipulated value) as the sole check for a swap that affected an unrelated, unprotected value; here, the "check" (signature verification) is bound to an attacker-supplied field (`repository.owner.login`) that has no cryptographic or logical relationship to the field actually acted upon (`sha`, and in other handlers `repository.full_name`). The organization that "authenticated" the request is not the same as the repository/commit whose state is written. As long as the payload's owner/organization login corresponds to *any* org configured without a webhook secret, the signature check is trivially satisfied regardless of which commit `sha` is targeted.

### Impact Explanation
Forging a `status` event with `state: "success"` for a known commit `sha` of a *different, secured* repository can flip `Commit#status` for that commit. `MergeRequest#all_status_checks_passed?` relies on `StatusChecker` over exactly these statuses [10](#0-9) , and `ProcessMergeRequestsJob` automatically calls `merge_request.merge!` once checks pass [11](#0-10) , which invokes `stack.github_api.merge_pull_request(...)` against GitHub with the app's own installation token [12](#0-11) . This is a path to an **unauthorized merge** on a repository the attacker never authenticated against — meeting the Critical bar ("an unauthorized deploy, rollback or merge").

Beyond `StatusHandler`, the same "authenticated organization ≠ acted-upon repository" gap exists structurally in `Handler#stacks`, which resolves target stacks purely from `payload.dig('repository','full_name')` with no cross-check against the organization used for signature verification [13](#0-12) , so `PushHandler` and similar handlers can likewise trigger actions (e.g. `sync_github`) on a stack belonging to an org other than the one that "verified."

### Likelihood Explanation
Requires an unprivileged, unauthenticated attacker only to POST to the public `/webhooks` endpoint; no Shipit session, `ApiClient` token, or leaked secret is required. The only precondition is that at least one organization configured in the multi-org `github:` block has a blank `webhook_secret` — an explicitly supported and documented configuration in this engine (shown as the default in every example secrets file and in `docs/setup.md`), not a misconfiguration outside the engine's control. Multi-org Shipit installations that add a low-value/testing organization without bothering to set its webhook secret (since that org's webhooks feel unimportant) inadvertently open every other organization's stacks and commits to forgery.

### Recommendation
Never let the signature-verification key be chosen from an unauthenticated field that is also acted upon downstream. Concretely:
- Require every configured organization/app to have a non-blank `webhook_secret`; refuse to boot (or refuse all webhook traffic for that org) if one is missing, rather than silently returning `true`.
- After signature verification, bind the identified organization to the actual object being mutated: verify that `repository.full_name`'s owner matches the `repository_owner` used to select the secret, and that any `Commit`/`Stack` resolved from the payload belongs to a repository owned by that same, verified organization, before applying any state change (especially in `StatusHandler`, which currently performs no repository scoping at all).

### Proof of Concept
1. Configure Shipit with two organizations, e.g. `OrgLow` (no `webhook_secret`) and `OrgHigh` (secret configured), as shown supported in `test/dummy/config/secrets_double_github_app.yml`.
2. Obtain (via GitHub's public API, no auth needed for public repos) the `sha` of an open, unmerged PR head commit in a repository under `OrgHigh` that is pending CI.
3. POST to `/webhooks` with header `X-Github-Event: status` and body:
   ```json
   {
     "sha": "<OrgHigh PR head sha>",
     "state": "success",
     "context": "ci/forged",
     "repository": { "owner": { "login": "OrgLow" }, "full_name": "OrgLow/whatever" }
   }
   ```
   No `X-Hub-Signature` header is needed (or any garbage value works) because `verify_webhook_signature` for `OrgLow` returns `true` unconditionally [1](#0-0) .
4. `StatusHandler#process` looks up `Commit.where(sha: ...)` — matching the `OrgHigh` commit regardless of the `OrgLow` repository info in the payload — and records a passing status for it [9](#0-8) .
5. If that commit is the head of a pending `MergeRequest` on an `OrgHigh` stack, `ProcessMergeRequestsJob` will see all status checks passed and call `merge!`, merging the PR via `OrgHigh`'s GitHub App credentials without the attacker ever having authenticated against `OrgHigh`.

      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
