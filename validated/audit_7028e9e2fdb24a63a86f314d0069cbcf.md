### Title
`ProxyType::NonTransfer` proxies can self-escalate to `Auction` and invoke `Registrar::swap`, which `NonTransfer`'s own filter explicitly denies - ([File: polkadot/runtime/rococo/src/lib.rs], [File: polkadot/runtime/westend/src/lib.rs])

### Summary
The Polkadot/Rococo/Westend relay-chain runtimes declare `ProxyType::NonTransfer` as an unconditional superset of every other proxy type (`(ProxyType::NonTransfer, _) => true`), but `NonTransfer`'s call filter deliberately *excludes* `Registrar::swap` while `ProxyType::Auction`'s filter admits `Registrar { .. }` unrestricted (including `swap`). This is the same "overlapping/inconsistent authorizer" bug class as the reported GMX finding — one authorizer (`is_superset`) grants a permission that another authorizer (`filter`) is supposed to deny — and it was already identified and fixed for the analogous `NonTransfer`/`Governance` pair on Asset Hub Westend (PR [#12769](https://github.com/paritytech/polkadot-sdk/pull/12769)) but was not applied to the relay-chain runtimes for the `Auction` pair.

### Finding Description
`pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` solely on `ProxyType::is_superset`, not on `filter`: [1](#0-0) 

In `polkadot/runtime/rococo/src/lib.rs` and `polkadot/runtime/westend/src/lib.rs`, `is_superset` blanket-claims `NonTransfer` is a superset of every other proxy type: [2](#0-1) 

But `NonTransfer`'s `filter` explicitly omits `Registrar::swap` (comment: "Specifically omitting Registrar `swap`") while only admitting `register`/`deregister`/`reserve`: [3](#0-2) 

Meanwhile `ProxyType::Auction`'s filter admits the entire `Registrar` call family unrestricted, which includes `swap`: [4](#0-3) 

The identical pattern exists in `polkadot/runtime/westend/src/lib.rs`: [5](#0-4) [6](#0-5) [7](#0-6) 

This is exactly the class of vulnerability already fixed by `prdoc/pr_12769.prdoc` for the `NonTransfer`/`Governance` pair on Asset Hub Westend, and guarded there by a regression test (`non_transfer_proxy_is_not_a_superset_of_governance` / `proxy_type_superset_relation_matches_call_filters`): [8](#0-7) [9](#0-8) 

No equivalent regression test exists for the relay-chain runtimes' `NonTransfer`/`Auction` pair, and `is_superset` was never narrowed there.

The `Registrar::swap` extrinsic is origin-gated: it requires the caller to be Root, the para's registered owner, or the para's own sovereign origin: [10](#0-9) 

This materially limits the blast radius: the attack only matters for an account that both (a) delegates a `NonTransfer` proxy to another key, and (b) itself owns/manages a registered parachain slot. An attacker holding a `NonTransfer` proxy for such an account can use `Proxy::proxy(real, add_proxy{delegate: <self>, proxy_type: Auction})` (permitted because `NonTransfer.is_superset(Auction) == true`), then `Proxy::proxy(real, Registrar::swap{...})` under the new `Auction` grant — a call the delegator explicitly intended to withhold from this proxy (per the runtime's own inline comment).

### Impact Explanation
`swap` exchanges the on-chain parachain/parathread (lease-holding) status, auction information, and auction deposit between two `ParaId`s, while keeping code/head-data mapped to the same `ParaId`. A `NonTransfer` proxy that was never meant to touch parachain-slot economics (auction deposits, lease-holding status) can force such a swap for a para its delegator owns. This is a proxy-permission-boundary violation (privilege escalation within the delegation model), not a direct token theft, but it undermines the delegated-authority guarantee the runtime documents ("Specifically omitting Registrar `swap`"). Given `pallet-proxy` is a widely used delegation primitive across the relay chain, this is a Medium-severity authorization-integrity bug, analogous in kind (though narrower in practical reach, due to the owner/root/para-origin gate on `swap`) to the already-acknowledged and fixed `NonTransfer`/`Governance` escalation.

### Likelihood Explanation
Requires: (1) a delegator who is a registered parachain owner, (2) that delegator granting a `NonTransfer` proxy to some account, and (3) that delegate account choosing to exploit the two-step escalation (`add_proxy` then `swap`) rather than any legitimate action. This is a real, no-privilege-required path reachable purely through normal signed extrinsics (`Proxy::proxy`, `Proxy::add_proxy`, `Registrar::swap`) — no governance, no forged inherent, no relayer/collator collusion needed — but it is gated to a narrower population (parachain managers who use proxies) than a universal balance-draining bug, so likelihood is Medium.

### Recommendation
Apply the same fix pattern already used in PR #12769: remove `(ProxyType::NonTransfer, _) => true` as a blanket rule and enumerate only the proxy types whose filters are actually fully covered by `NonTransfer`'s filter (as Asset Hub Westend now does, listing `Collator | Staking | NominationPools | StakingOperator` explicitly). For Rococo/Westend, `Auction` (and, on Rococo, `OnDemandOrdering`, which is also not covered by `NonTransfer`'s filter) must be excluded from `NonTransfer`'s declared supersets, or `NonTransfer`'s filter must be extended to admit everything `Auction`/`OnDemandOrdering` admit. Add the same kind of lattice regression test used in `asset-hub-westend/tests/tests.rs` (`proxy_type_superset_relation_matches_call_filters`) to every runtime defining custom `ProxyType`/`is_superset` pairs, so this class of bug cannot silently reappear per the report's own recommendation to enforce authorizer independence.

### Proof of Concept
No test was executed in this session (no terminal/execution access available in this ask-only investigation); this is a static-analysis finding based on direct code inspection of the `filter`/`is_superset` implementations and the origin check in `Registrar::swap`, cross-referenced against the existing, already-merged fix (PR #12769) for the structurally identical bug on Asset Hub Westend. A concrete reproduction would extend `polkadot/runtime/common/src/paras_registrar/tests.rs` or a relay-chain integration test with:
1. Register two paras (`para_1` owned by delegator `real`, and a counterpart), and make `para_1` a lease-holding parachain.
2. `Proxy::add_proxy(real, delegate, ProxyType::NonTransfer, 0)`.
3. `Proxy::proxy(delegate, real, None, Call::Proxy(add_proxy{ delegate, proxy_type: Auction, delay: 0 }))` — expect `Ok`, since `NonTransfer.is_superset(Auction) == true`.
4. `Proxy::proxy(delegate, real, None, Call::Registrar(swap{ id: para_1, other: para_2 }))` — expect this to succeed under the newly-granted `Auction` proxy, despite `NonTransfer.filter` denying `Registrar::swap` directly, demonstrating the escalation. This mirrors the structure of the existing regression test `non_transfer_proxy_is_not_a_superset_of_governance` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs`, which validates the equivalent already-fixed case.

fn proxy_type_superset_relation_matches_call_filters() {
	use frame_support::traits::InstanceFilter;

	let calls = representative_proxy_calls();

	for superset in all_proxy_types() {
		for subset in all_proxy_types() {
			if !superset.is_superset(&subset) {
				continue;
			}

			for call in calls.iter() {
				if subset.filter(call) {
					assert!(
						superset.filter(call),
						"lattice violated: {superset:?} declares itself a superset of {subset:?}, \
						 but rejects {call:?} which {subset:?} admits",
					);
				}
			}
		}
	}
}
