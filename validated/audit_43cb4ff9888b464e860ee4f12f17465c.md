### Title
Unchecked index/scaled-debt product overflows `i128` during accrual, permanently freezing every position in a large market - (File: common/src/rates/index.rs)

### Summary
The borrow and supply indexes are clamped to `MAX_BORROW_INDEX_RAY`/`MAX_SUPPLY_INDEX_RAY` (1e9 RAY), but that bound is set without regard to the size of the scaled share balances they are later multiplied against. When a market accumulates enough scaled debt that `borrowed * borrow_index / RAY` no longer fits in `i128`, `scaled_to_original` panics with `MathOverflow` before the index cap can ever engage. Because every state-changing entrypoint accrues interest first, the panic is permanent: no repay, withdraw, borrow, liquidate, or clean-up can ever execute again, and all supplier cash in that market is frozen forever.

### Finding Description
`update_borrow_index` clamps the grown index at `MAX_BORROW_INDEX_RAY = 1_000_000_000_000_000_000_000_000_000_000_000_000` (1e36 raw, i.e. a 1e9x index), but performs no check that the resulting index remains compatible with the scaled balances it multiplies [1](#0-0) .

On the next accrual, `scaled_to_original(borrowed, borrow_index)` computes `borrowed.mul(index)` via `Ray::mul` → `mul_div_half_up`; the widened `I256` path still returns `None` when the *quotient* exceeds `i128`, producing a `MathOverflow` panic [2](#0-1) [3](#0-2) .

The same untrapped overflow exists in `update_supply_index` (`supplied.mul(old_index)`), `supply_index_reward_shortfall`, and `calculate_supplier_rewards` (`borrowed.mul(new_borrow_index)`), so there is no alternate accrual path that survives [4](#0-3) [5](#0-4) .

This is the same class as the reference buffer overflow: attacker-influenceable state (scaled debt size × compounding index) is allowed to grow past the representable bound of the storage arithmetic, and the overflow fires on a routine "describe/settle" call (interest accrual) rather than at the point where the state is inflated. The index ceilings were meant to be the guard rail, but they bound only the index, not the product.

The codebase's own harness test demonstrates the cliff: at 98% utilization on a steep rate curve, `borrowed * borrow_index` overflows `i128` *before* `MAX_BORROW_INDEX_RAY` is reached, after which `withdraw`, `repay`, and `update_indexes` all revert with `MATH_OVERFLOW` [6](#0-5) .

### Impact Explanation
Permanent freezing of funds for every participant in the affected market book. Once `borrowed * borrow_index / RAY > i128::MAX`:

- `withdraw` reverts (accrual runs first) — supplier principal is locked forever.
- `repay` and `liquidate` revert — the debt can never be reduced, so even the overflow condition cannot be walked back.
- `clean_bad_debt`/`recapitalize` revert for the same reason.
- The pool holds the physical tokens, so this is not a fail-closed pause that governance can fix by parameter change: no reachable code path skips accrual, and the accrual itself panics.

### Likelihood Explanation
Requires a large market: scaled debt on the order of `i128::MAX / index` (~1e11 RAY-scaled units at a 1e9x index, proportionally less as the index grows) and sustained high utilization so the borrow index keeps compounding. An unprivileged attacker can drive this by supplying large collateral, borrowing the target market to near-max utilization, and letting per-millisecond accrual run — each subsequent accrual is invoked permissionlessly via `update_indexes`. No privileged role, oracle manipulation, or leaked key is needed; the only mitigation is capital scale and time to compounding. Once tipped over, the state is irreversible, which raises the severity to Medium despite the capital requirement.

### Recommendation
In `update_borrow_index` (and analogously `update_supply_index`), clamp the new index not only to `MAX_BORROW_INDEX_RAY` but also to the largest index for which `borrowed * index / RAY` (resp. `supplied * index / RAY`) still fits in `i128` — i.e., cap at `min(MAX_BORROW_INDEX_RAY, i128::MAX * RAY / borrowed)` computed via the `I256` path or `mul_div_floor_saturating`/`try_mul_div_half_up` guards. Capping the index stops further interest accrual (a graceful degradation) while keeping every settlement path executable. Alternatively, make `scaled_to_original` saturate rather than panic inside accrual, so index growth freezes instead of bricking the market.

### Proof of Concept
Reproduced by the in-repo harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [7](#0-6) :

```rust
// BIG18 market, caps lifted, max_utilization disabled
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;            // 98% utilization
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

// Permissionlessly poke accrual each year; index compounds on steep curve
loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; } // MathOverflow
}

// Now every exit path reverts on the same accrual panic:
try_withdraw_raw(BOB, "BIG18", 1)  -> Error(Contract, MATH_OVERFLOW)
try_repay(ALICE, "BIG18", 1.0)     -> Error(Contract, MATH_OVERFLOW)
// and last.borrow_index < MAX_BORROW_INDEX_RAY — the cap never engaged.
```

An attacker replicates this on-chain with `supply` (collateral market), `borrow` (target market to ~98% utilization), and repeated public `update_indexes` calls until `scaled_to_original` overflows; thereafter all funds in the book are permanently frozen.

```rust
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

```rust
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {

    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
```
