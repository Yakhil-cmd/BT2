### Title
Unjournaled `SetCodeInfo` in `SetCodeToEOA` Leaves `codeInfo` Unrevertable, Causing Persistent Inconsistent Account State — (`blockchain/state/journal.go`, `blockchain/state/statedb.go`)

### Summary

The `codeChange` journal entry captures only `prevcode` and `prevhash`. When `SetCodeToEOA` calls `pa.SetCodeInfo(...)` on the underlying account object before calling `stateObject.SetCode(...)`, the `codeInfo` mutation is never appended to the journal. On `RevertToSnapshot`, `codeChange.revert` restores the code hash and bytecode but leaves `codeInfo` permanently set to the delegation format value. The account is then committed to the trie in an inconsistent state: empty code hash with a non-zero delegation `codeInfo`.

### Finding Description

`codeChange` is defined as:

```go
codeChange struct {
    account            *common.Address
    prevcode, prevhash []byte
}
``` [1](#0-0) 

Its `revert` method only restores code and hash:

```go
func (ch codeChange) revert(s *StateDB) {
    s.getStateObject(*ch.account).setCode(common.BytesToHash(ch.prevhash), ch.prevcode)
}
``` [2](#0-1) 

There is no `prevCodeInfo` field and no separate journal entry type for `codeInfo`. `SetCodeInfo` on `ExternallyOwnedAccount` directly mutates the struct field:

```go
func (e *ExternallyOwnedAccount) SetCodeInfo(ci params.CodeInfo) {
    e.codeInfo = ci
}
``` [3](#0-2) 

After a revert, `codeInfo` retains the delegation-format value while `codeHash` is restored to empty. The `shouldUseCompactEncoding()` check requires `hasDefaultCodeInfo` to be true for compact (EOA) encoding:

```go
hasDefaultCodeInfo := e.codeInfo == params.CodeInfo(0)
if isEmptyStorageRoot && hasEmptyCodeHash && hasDefaultCodeInfo {
    return true
}
``` [4](#0-3) 

With `codeInfo` non-zero but `codeHash` empty, `shouldUseCompactEncoding()` returns `false`, so the full encoding path is used and the corrupted `codeInfo` is serialized into the trie.

### Impact Explanation

The corrupted account is committed to the state trie with `codeInfo` indicating delegation format but an empty code hash. Any downstream logic that reads `codeInfo` to determine whether an account carries EIP-7702 delegation code (e.g., code-format validation, execution dispatch, or account-type guards) will observe an inconsistent state. This constitutes **persistent corruption of trie/state data** that can affect canonical execution for that account going forward. All honest nodes running the same code will produce the same corrupted state root, so there is no consensus divergence, but the account is permanently left in an invalid state that bypasses the invariant that `codeInfo` and `codeHash` must be consistent.

### Likelihood Explanation

The trigger requires: (1) an EIP-7702 SetCode authorization targeting an EOA with a non-legacy account key, (2) the EVM execution portion of the transaction reverting (e.g., out-of-gas or explicit revert in the called contract) after `applyAuthorization` has already run. Both conditions are reachable via a normal public RPC transaction submission with no privileged access required.

### Recommendation

Add a `prevCodeInfo` field to `codeChange` and restore it in `revert`:

```go
codeChange struct {
    account                    *common.Address
    prevcode, prevhash         []byte
    prevCodeInfo               params.CodeInfo
}

func (ch codeChange) revert(s *StateDB) {
    obj := s.getStateObject(*ch.account)
    obj.setCode(common.BytesToHash(ch.prevhash), ch.prevcode)
    obj.setCodeInfo(ch.prevCodeInfo)  // restore CodeInfo atomically
}
```

Alternatively, capture the full pre-call account state via `resetObjectChange` when `SetCodeToEOA` is called, which atomically reverts all sub-fields.

### Proof of Concept

```go
// 1. Snapshot before SetCodeToEOA
snap := statedb.Snapshot()

// 2. Apply SetCodeToEOA (sets codeInfo to delegation format, journals codeChange)
statedb.SetCodeToEOA(authorityAddr, delegationTarget)

// 3. Revert to snapshot (codeChange.revert restores codeHash but NOT codeInfo)
statedb.RevertToSnapshot(snap)

// 4. Assert inconsistency
code := statedb.GetCode(authorityAddr)
assert(len(code) == 0)  // passes: code hash reverted

obj := statedb.getStateObject(authorityAddr)
eoa := obj.account.(*account.ExternallyOwnedAccount)
assert(eoa.GetCodeFormat() == params.CodeFormatEVM)  // FAILS: codeInfo still delegation format
```
