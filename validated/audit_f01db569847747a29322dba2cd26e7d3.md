### Title
Reused Bitcoin L1 lockup outpoint can double-credit staked sats across multiple bond registrations - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`pox-5.clar`'s L1-lockup verification path (`verify-l1-lockups` / `validate-l1-lockup`) only prevents duplicate use of the same Bitcoin outpoint *within a single call* via a locally-scoped `seen-outpoints` accumulator. There is no persistent, contract-wide map that records which Bitcoin `(txid, output-index)` pairs have already been consumed to credit staked sats to a bond/staker. This is structurally the same class of bug as the TON outbound-tracker issue: an unprivileged party can present a proof of a single, real on-chain lock and have the contract credit it as backing stake more than once, breaking the equality between actually-locked BTC and the sats the contract believes are staked. [1](#0-0) 

### Finding Description
`verify-l1-lockups` folds over the caller-supplied `outputs` list with `validate-l1-lockup`, checking (per output): the script matches the expected timelock script for `staker`/`unlock-burn-height`, the Bitcoin block header and merkle proof are valid, the amount matches, and that the outpoint hasn't been seen already *in this fold* (`seen-outpoints`, an accumulator local to the single call). [2](#0-1) 

Critically, `seen-outpoints` is initialized fresh on every call to `verify-l1-lockups` (`seen-outpoints: (list)`), and is never persisted to a contract data map that would be checked/updated across separate calls or separate bond registrations. [3](#0-2) 

Because the same L1 lockup proof (real Bitcoin transaction + merkle proof + header) is fully self-contained and re-verifiable at any time (the block header/merkle proof does not get consumed or invalidated), a staker (or any principal who can construct/observe the proof for a given output) can resubmit the identical proof to a subsequent bond registration (a different `bond-index`, or the same bond-index if re-registration/rollover is permitted) and have `add-staker-to-bond-cycles` / `add-staker-to-bond-for-cycle` credit the same underlying sats again as `amount-sats` toward `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and `staker-shares-staked-for-cycle`. [4](#0-3) 

This exactly mirrors the TON root cause: the external report's `processOutboundTracker()` failed to bind an observed artifact (a TON tx hash) to the specific nonce/commitment it was meant to satisfy, allowing the same underlying event to be counted for an unintended, additional cctx. Here, `validate-l1-lockup`/`verify-l1-lockups` fail to bind a Bitcoin outpoint to a single, permanently-consumed commitment across the whole contract's lifetime — only within one fold call — allowing the same BTC lock to satisfy multiple bond/reward-cycle credit events.

### Impact Explanation
If reachable, this breaks the equality "sats credited to a staker in `*-shares-staked-for-cycle` maps == sats actually locked on Bitcoin by that staker for that stake." A staker's stake-weight, and thus their share of reward-per-token pool distributions from `calculate-rewards`/`get-signer-rewards-per-token-for-cycle`, would be inflated without any additional BTC being locked — this is double-counting a commitment and unbacked crediting of reward weight, i.e., theft of sBTC rewards from other legitimate stakers/signers who are diluted by the fabricated stake. This matches the "Critical: double-counting a commitment or reward" / "unlocking value never locked" category in scope.

### Likelihood Explanation
Likelihood depends on whether the wider `register-for-bond`/rollover flow (not fully inspected due to iteration limits) imposes some other global constraint — e.g., rejecting a bond-index/staker pair that is already active, or requiring monotonically increasing unlock heights that would make a second submission of the identical output for the same staker fail elsewhere. I was not able to fully confirm the entry-point logic that calls `verify-l1-lockups` (e.g., `register-for-bond`) within the available tool budget, so I cannot rule out an additional check outside the snippets reviewed that would prevent reuse across separate bond registrations. This is flagged explicitly as unverified.

### Recommendation
Persist consumed Bitcoin outpoints in a durable map (e.g., `used-l1-lockup-outpoints: {txid, output-index} -> bool`) that is checked and updated by `validate-l1-lockup` across all calls/bonds, not just within a single fold's local accumulator, so that any given Bitcoin lock output can only ever back one stake credit for its lifetime.

### Proof of Concept
Not executed — this requires driving `register-for-bond` (or equivalent public entry point invoking `verify-l1-lockups`) twice with the same Bitcoin lockup proof (same header, merkle proof, and output) against two different `bond-index` values (or the same bond after an eligible rollover), and observing that `staker-shares-staked-for-cycle`/`total-shares-staked-for-cycle` reflect the sats amount twice while only one Bitcoin lock exists on-chain. I was unable to complete this within the tool/iteration budget, since the full `register-for-bond` entry point and any surrounding uniqueness checks were not retrieved before the session ended.

;; Fold function for validating l1 lockup info
;;
;; - `staker` is the lockup owner committed to the timelock script.
;; - `minimum-unlock-height` is the earliest allowed L1 unlock height.
;; - `staker-unlock-bytes` is the subscript that must unlock every output.
;; - `early-unlock-bytes` is the bond's early-exit subscript.
;; - `sum` is the running total of sats from all valid lockups processed so far.
;; - `seen-outpoints` tracks every (txid, output-index) pair already credited
;;   in this call. Duplicate entries is rejected via
;;   ERR_DUPLICATE_LOCKUP_OUTPOINT.
(define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
)
