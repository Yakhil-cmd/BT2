### Title
Silent Failure in `ProcessParentBlockHash` Ignores EVM Call Return Value — (`blockchain/state_processor.go`)

### Summary

`ProcessParentBlockHash` in `blockchain/state_processor.go` calls `vmenv.Call` to store the parent block hash in the EIP-2935 history-storage system contract, but **completely discards all three return values** — including the error. The function signature declares `error` as its return type yet unconditionally returns `nil`, so any EVM-level failure (revert, out-of-gas, depth limit) is silently swallowed. The block continues to be accepted as valid while the history-storage contract's state is left uncorrupted from the node's perspective but actually missing the expected entry.

### Finding Description

In `blockchain/state_processor.go` at line 186, the call is:

```go
vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
statedb.Finalise(true, true)
return nil
``` [1](#0-0) 

All three return values `(ret []byte, leftOverGas uint64, err error)` from `vmenv.Call` are discarded. The function then calls `statedb.Finalise` and returns `nil` unconditionally. Compare this with `SystemTxCall` in the same file, which correctly captures and propagates the error:

```go
ret, _, err := vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
statedb.Finalise(true, true)
return ret, err
``` [2](#0-1) 

The two functions sit side-by-side in the same file, yet only one checks the call result. `ProcessParentBlockHash` is the direct Go analog of the Solidity `fallback` functions in the OVM report that executed `ovmCALL`/`ovmDELEGATECALL` and ignored the success flag.

### Impact Explanation

If the EVM call to `params.HistoryStorageAddress` fails for any reason:

1. The parent block hash is **not written** to the EIP-2935 history-storage contract.
2. `ProcessParentBlockHash` returns `nil` — the block-processing pipeline sees no error and accepts the block.
3. The history-storage trie entry for that block number is absent, so any subsequent `BLOCKHASH` opcode query for that historical slot returns `0x00…00` instead of the real hash.
4. Smart contracts that rely on `BLOCKHASH` for commit-reveal schemes, randomness, or cross-chain proof verification will receive a wrong (zero) value, potentially enabling manipulation of those protocols.
5. Because the state root is computed over the corrupted trie, the accepted block's state root encodes the missing entry — this is **persistent trie corruption** that cannot be corrected without a reorg.

This matches the gate criterion: *"Persistent corruption of trie/state/snapshot data that breaks canonical execution"* and *"Invalid state transition … on honest nodes"*.

### Likelihood Explanation

Triggering conditions include:

- The `HistoryStorageAddress` contract is not yet deployed (e.g., at the exact Prague activation block before the contract is installed, or on a misconfigured network).
- The EVM call depth limit (`params.CallCreateDepth = 1024`) is reached during block processing (unlikely but theoretically possible with deeply nested system calls).
- A future upgrade inadvertently introduces a revert path in the history-storage contract.
- A gas-accounting change causes the 30 M gas budget to be insufficient.

Because the history-storage contract is simple and pre-deployed, the likelihood under normal mainnet conditions is low. However, the **absence of any guard** means the failure mode is entirely invisible — no log, no error, no revert — making it impossible to detect or alert on without external monitoring.

### Recommendation

Capture and propagate the error from `vmenv.Call`, consistent with `SystemTxCall`:

```go
func ProcessParentBlockHash(header *types.Header, vmenv *vm.EVM, statedb vm.StateDB, rules params.Rules) error {
    ...
    _, _, err = vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
    statedb.Finalise(true, true)
    return err   // propagate instead of silently dropping
}
```

All callers of `ProcessParentBlockHash` already handle its `error` return, so propagating the error will cause block processing to abort cleanly rather than silently accepting a corrupted state.

### Proof of Concept

1. Deploy a test chain with Prague rules enabled.
2. Replace the bytecode at `params.HistoryStorageAddress` with a contract that unconditionally reverts (`REVERT 0 0`).
3. Mine a block — `ProcessParentBlockHash` is invoked, `vmenv.Call` returns a non-nil error, but the error is discarded and `nil` is returned.
4. Query `BLOCKHASH` for the parent block number from a contract — it returns `0x00…00` instead of the real hash.
5. Observe that the block was accepted with `ReceiptStatusSuccessful` and no error in the node logs, confirming the silent failure.

func ProcessParentBlockHash(header *types.Header, vmenv *vm.EVM, statedb vm.StateDB, rules params.Rules) error {
	var (
		from     = params.SystemAddress
		data     = header.ParentHash.Bytes()
		gasLimit = uint64(30_000_000)
	)

	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return err
	}

	msg := types.NewMessage(
		from,
		&params.HistoryStorageAddress,
		0,
		common.Big0,
		gasLimit,
		common.Big0,
		nil,
		nil,
		nil,
		data,
		false,
		intrinsicGas,
		nil,
		nil,
		nil,
		nil,
		nil,
	)

	vmenv.Reset(NewEVMTxContext(msg, header, vmenv.ChainConfig()), statedb)
	statedb.AddAddressToAccessList(params.HistoryStorageAddress)
	vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
	statedb.Finalise(true, true)
	return nil
}

// SystemTxCall executes a system transaction (e.g., state transition contract writes) within the EVM.
func SystemTxCall(
	msg *types.Transaction,
	from common.Address,
	header *types.Header,
	vmenv *vm.EVM,
	statedb vm.StateDB,
	rules params.Rules,
) ([]byte, error) {
	gasLimit := params.UpperGasLimit
	vmenv.Reset(NewEVMTxContext(msg, header, vmenv.ChainConfig()), statedb)
	statedb.AddAddressToAccessList(*msg.To())
	ret, _, err := vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
	statedb.Finalise(true, true)
	return ret, err
}
