### Title
Non-linear HEAD movement (branch checkout + commit) causes `compute_v2_review_set` to silently drop committed vulnerable files from Stop-hook review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes `review_set = dirty_now ∩ changed_since`, where `dirty_now` only includes the head-advance delta when `_is_ancestor(head_at_capture, current_head)` is true. Ordinary git operations during a turn (e.g., checking out a different branch and committing there, or any non-linear HEAD movement) make `_is_ancestor` return false, so a file that was genuinely committed during the turn — and is correctly detected by `changed_since` (diff against `baseline_sha`) — is excluded from `dirty_now` (because `git status` shows it clean) and therefore dropped from the intersection, escaping the Stop-hook security review entirely.

### Finding Description
The Stop hook derives its review set from `compute_v2_review_set` [1](#0-0) . It computes:

- `dirty_now` = `git status --porcelain` dirty tracked files ∪ new untracked files [2](#0-1) , extended with `head_at_capture..HEAD` name-only diff **only if** `_is_ancestor(head_at_capture, current_head)` holds [3](#0-2) .
- `changed_since` = `git diff --name-only <baseline_sha>` against the current worktree, i.e. files whose content differs from the pre-turn stash baseline [4](#0-3) , implemented via `_git_name_only` which runs `git diff --name-only base` (base vs. worktree, unconditionally correct) [5](#0-4) .
- `review_set = dirty_now & changed_since` [6](#0-5) .

`_is_ancestor` is explicitly documented as true only when "HEAD moved forward via commit/merge, not sideways via checkout" [7](#0-6) . If, during the turn, a `git checkout <other-branch>` (or any other non-linear HEAD transition not rooted at `head_at_capture`) is followed by `git commit` of the dangerous file, then:
- The file is fully committed, so `git status --porcelain` reports it clean → it is absent from `tracked_dirty`/`dirty_now`.
- `_is_ancestor(head_at_capture, current_head)` is false, so the `head_at_capture..HEAD` term is never unioned into `dirty_now`.
- `changed_since` still correctly contains the file (its content differs from `baseline_sha`), but the AND with the now file-less `dirty_now` drops it from `review_set`.

The result is that a dangerous, newly-committed change is treated as if it were pre-existing/"old" and is silently excluded from the file set sent to the LLM reviewer, even though `baseline_sha` (loaded via `load_baseline_sha`) is unchanged and technically still "correct." No approval prompt, allowlist, or repo/session-binding check catches this, because the intersection design assumes committed-this-turn changes are always linear descendants of `head_at_capture`.

### Impact Explanation
This breaks the stated invariant that the review set must capture "only code Claude actually changed" during the turn [8](#0-7) . A dangerous change (e.g., a command-injection or hardcoded-secret introduction) committed via a normal non-linear git workflow bypasses the Stop-hook LLM security review and pattern-warning sweep entirely, letting an unreviewed vulnerable commit stand — a real, silent security-gate bypass reachable purely through ordinary git usage in the cloned repo (no privileged access, no state-file tampering).

### Likelihood Explanation
The trigger is a normal, unprivileged sequence of git commands (`git checkout <branch>`, commit) that Claude or an attacker steering Claude's tool use can readily perform inside a session; no special permissions or exploitation of the plugin's locking/session-key logic is required. It is fully deterministic and reproducible: any turn where HEAD ends up not linearly descended from `head_at_capture` reproduces the drop.

### Recommendation
Do not gate the "committed this turn" term on `_is_ancestor`. Instead, always include files touched by any commit reachable from the pre-turn `touched_paths`/`baseline_sha` diff regardless of linearity — e.g., union `dirty_now` with `changed_since` restricted to files that are also members of `touched_paths` (files Claude actually wrote via tools), or simply drop the strict AND-intersection design in favor of `dirty_now | (changed_since ∩ touched_paths)`, so committed-and-clean files that were edited this turn are never excluded solely because HEAD moved non-linearly.

### Proof of Concept
Unit/integration test in the existing test suite (e.g., extending tests around `compute_v2_review_set`):
1. Init a repo, commit an initial file, capture `baseline_sha` via `capture_git_baseline` and `head_at_capture` via `_git_rev_parse_head`.
2. Simulate the "dangerous" edit: create a new branch not descending in a way that keeps ancestry (e.g., `git checkout -b other <root-commit>` where root differs from `head_at_capture`'s tip, or perform `git checkout --orphan tmp && git commit`), writing a file containing an obviously dangerous pattern (e.g., `os.system(user_input)`).
3. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
4. Assert: `_is_ancestor(cwd, head_at_capture, current_head)` is `False`, and the dangerous file path is present in `_git_name_only(repo, baseline_sha)` (i.e. `changed_since`), but **absent** from the returned `review_paths` — demonstrating the invariant violation ("review set must stay bound to ... touched paths") and that the dangerous change is silently skipped.

```python
def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd
```

```python
def _git_name_only(cwd, base, include_untracked=False):
    """Return the set of repo-root-relative paths that differ from `base`,
    or None if git failed (unresolvable ref, not a repo, timeout). Callers
    must distinguish None (error → don't trust as a filter) from set()
    (genuinely nothing changed). `-c core.quotePath=false -z` keeps non-ASCII
    and space-containing paths intact."""
    def _run(env):
        result = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "diff", "--name-only", "-z", base],
            cwd=cwd, capture_output=True, text=True, timeout=30,
            env=env,
        )
        if result.returncode != 0:
            debug_log(f"_git_name_only({base!r}) rc={result.returncode}: {result.stderr[:200]}")
            return None
        return {p for p in result.stdout.split("\0") if p}
```

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```

```python
## How the git baseline works

On each UserPromptSubmit, the plugin runs `git stash create` to get a SHA representing
the current working tree state (HEAD + any uncommitted changes). This SHA is saved to
the session state file. When the Stop hook fires, it runs `git diff <baseline_sha>` to
get only the changes made since that snapshot. After analysis, the baseline is updated
so the next Stop hook iteration only sees new changes.

This means:
- Only code Claude actually changed is reviewed (not pre-existing code)
- Mid-session commits are handled correctly (diff is against the snapshot, not HEAD)
- Each turn only reviews new changes (baseline updates after each stop hook)
```
