### Title
Stale stored `account.owner` lets the prior NFT holder retain spending authority after `position-nft::transfer` — authorization bypass via divergent ownership sources - (File: contracts/controller/src/account.rs)

### Summary
The controller keeps two notions of account ownership that can diverge: `Account.owner` stored in the account struct at mint time (`create_account`, `account.rs:64-66`), and the live NFT owner read through `storage::account_owner` (`account.rs:145`). The spending gate `require_owner_or_delegate` / `is_owner_or_delegate` (`account.rs:115-140`) authorizes `caller == account.owner` — the *stale stored* owner — while `require_account_owner` correctly checks the *current NFT* owner. `position-nft::transfer` moves the NFT without any callback into the controller, so `Account.owner` is never restamped. Analogous to GHSA-q547-gmf8-8jr7: a validation step (here, the ownership check guarding every fund-moving entrypoint) can be passed by an attacker who no longer satisfies the real authorization condition, because the check reads a stale/trust-once value instead of the authoritative one.

### Finding Description
`borrow`, `withdraw`, `multiply`, `flash_position`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, and `migrate_from_blend` all reach `require_owner_or_delegate(env, account_id, caller, &account.owner)` (per `permissionless_entrypoints.txt` and the guards in `positions/debt.rs`, `positions/supply.rs`, `positions/liquidation/mod.rs`, `strategies/*.rs`). That check passes whenever `caller == account.owner` (`account.rs:121-123`), where `account.owner` was fixed at `nft_mint_call` time and is only ever written there. Delegates are keyed by `(account_id, owner)` under that same stored owner (`account.rs:126`, `storage::add_delegate(env, account_id, caller, ...)` at `account.rs:261`). Nothing in `position-nft::transfer`/`transfer_from` calls back into the controller — the NFT contract only invokes it for `mint`/`burn` — so after a transfer, the seller remains `account.owner` and keeps full owner/delegate authority over all collateral and borrowing power the buyer just acquired. The system's own documentation acknowledges the two sources must agree ("The NFT owner is the account owner", `permissionless_entrypoints.txt:105`; "delegate grants from the previous owner go inactive", `:111`) — which holds only if `Account.owner` is restamped, and no code path does that.

### Impact Explanation
Theft of user funds: an attacker lists/sells (or "gifts") a position NFT holding supplied collateral, the victim becomes NFT owner, and the attacker — still `account.owner` — calls `withdraw(account_id, ...)` or `borrow` to drain the account's collateral. Because the auth check passes on the stale owner, this needs no signature from the victim and succeeds on any unprivileged call to `controller::withdraw`/`borrow`.

### Likelihood Explanation
Requires only that a victim accept or purchase a position NFT — a normal, documented operation (`position-nft::transfer` is an in-scope unprivileged entrypoint). No timing, oracle, or privileged preconditions. Severity is bounded by whether `storage::get_account` or a transfer hook silently refreshes `Account.owner`; I could not confirm or rule out such a refresh within my tool budget — if `account_owner`-style normalization is applied on every account load, the bug collapses to a new-owner lockout (fail-closed DoS) rather than theft.

### Recommendation
Derive authorization exclusively from the live NFT owner (`storage::account_owner`) inside `is_owner_or_delegate`/`require_owner_or_delegate`, or restamp `Account.owner` (and migrate/invalidate the delegate list keyed under the old owner) whenever the NFT ownership read differs from the stored value. Add a test: mint → supply → `transfer` NFT → assert the previous owner cannot `withdraw`.

### Proof of Concept
1. Alice calls `controller::supply(account_id=0, ...)` → account minted, `Account.owner = Alice`, collateral credited.
2. Alice calls `position-nft::transfer(Alice → Bob, token_id)`.
3. Bob is `owner_of(token_id)`; `Account.owner` still `= Alice`.
4. Alice calls `controller::withdraw(account_id, USDC, amount)` → `require_owner_or_delegate` sees `caller == account.owner` → collateral paid to Alice despite Bob owning the NFT.
