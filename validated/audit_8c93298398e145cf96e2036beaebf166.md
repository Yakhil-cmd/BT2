### Title
Webhook signature verification and stack resolution use unvalidated, independent fields from the payload, allowing cross-repository stack mutation - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/handler.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects which organization's `webhook_secret` to verify the HMAC against using `params.dig('repository', 'owner', 'login')`, while `Shipit::Webhooks::Handlers::Handler#stacks` resolves the target repository/stack using the independent field `payload.dig('repository', 'full_name')`. Nothing in the request path checks that these two fields refer to the same repository/owner, so a request signed with org A's secret can carry a `full_name` pointing at org B's repository.

### Finding Description
The broken binding: the equality the code implicitly assumes is
`organization_that_signed(repository.owner.login) == organization_owning(repository.full_name)`,
but this equality is never enforced, so it can be false.

Path traced:
- `verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner` via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` (line 59-62), fetches `Shipit.github(organization: repository_owner)`, and calls `verify_webhook_signature(signature, request.raw_post)` (`lib/shipit/github_app.rb:76-83`), which is a plain HMAC-SHA1 check against that organization's configured `webhook_secret`.
- Because the attacker owns org A and knows org A's own `webhook_secret` (it's their own webhook secret, not a Shipit or GitHub secret), they can freely compute a valid signature over any raw body, as long as `repository.owner.login` in that body is `org-A` (so `Shipit.github(organization: 'org-A')` is selected).
- `#create` (line 10-15) re-parses the same `raw_post` and dispatches to `Shipit::Webhooks.for_event(event)` handlers, e.g. `PushHandler` (`app/models/shipit/webhooks/handlers/push_handler.rb`).
- `Handler#stacks` (`app/models/shipit/webhooks/handlers/handler.rb:32-38`) resolves the target using `repository_name = payload.dig('repository', 'full_name')`, completely independent of `repository.owner.login`, and calls `Repository.from_github_repo_name(repository_name)` (`app/models/shipit/repository.rb:53-56`), which just splits on `/` and does a `find_by(owner:, name:)` lookup with no cross-check against the signature-verifying organization.
- `PushHandler#process` (line 12-17) then calls `stack.sync_github(expected_head_sha: params.after)` on any non-archived stack matching that branch for the resolved repository — org B's stack — despite the signature only ever having been checked against org A's secret.

None of the existing guards catch this: `drop_unhandled_event` only checks the event type exists; `ExplicitParameters` (`PushHandler.params`) only validates presence of `ref`/`after`, not repository identity; there is no `force_github_authentication`/session/API-token check on this controller (it's webhook-only, unauthenticated by design, relying entirely on HMAC signature to bind the payload to a specific org); `Repository`/`Stack` model validations only constrain character sets, not cross-request consistency.

### Impact Explanation
An attacker who registers their own GitHub organization (org A) as an authenticated Shipit-integrated org can forge a `push` (or any other handled event, e.g. `status`, `check_suite`, `pull_request`) webhook whose `repository.owner.login` is `org-A` (to pass signature verification) but whose `repository.full_name` is `org-B/some-repo` (a real target). This lets `stack.sync_github` (and other handler-triggered mutations, such as commit/status writes reachable through other handlers keyed the same way) execute against org B's stack without org B's `webhook_secret` ever being checked. This is a cross-tenant write triggered by another tenant's authentication, matching the Critical category "a payload for one repository mutating another's stack/commit/task."  This is repeatable against any repository/stack owned by any other `Shipit.github_organizations` entry, as long as the attacker can guess/know the target `full_name` (which is public information for public repos, or discoverable stack names).

### Likelihood Explanation
Preconditions are realistic and cheap for the attacker: they only need their own GitHub org (org A) configured in `Shipit.github_organizations` with its own `webhook_secret` (which they control, since it's their own org's webhook secret configured by a Shipit operator when onboarding org A) and knowledge of a target `full_name` for a stack in org B. No Shipit session, API token, or org B secret is required. Crafting the HTTP POST with a custom JSON body and a valid HMAC over that exact body (computed with org A's own secret) is trivial and fully within the "unprivileged internet attacker" threat model described.

### Recommendation
In `verify_signature`, after selecting `github_app` by `repository_owner`, additionally require that `payload.dig('repository', 'full_name')` (when present) starts with `"#{repository_owner}/"` (case-insensitively) before accepting the signature, or reject the request otherwise. More robustly, `Handler#stacks`/`Repository.from_github_repo_name` should not trust `full_name` independently of the verified owner — pass the verified `repository_owner` into the handler layer and assert equality with the owner segment of `full_name` before any stack lookup/mutation.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"

    rescue Shipit::GithubOrganizationUnknown => e

      ].join(' '))
    end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
