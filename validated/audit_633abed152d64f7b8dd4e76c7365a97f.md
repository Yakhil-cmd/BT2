### Title
CAPI Bearer Token Attached Without Host Validation on Redirects - (File: `pkg/cmd/agent-task/capi/client.go`)

### Summary
The Copilot API (CAPI) HTTP transport used by `gh agent-task` unconditionally attaches the user's bearer token to every outgoing request handled by its `RoundTrip`, without verifying that the request's destination host matches the intended CAPI host. This mirrors the residual-allowance bug class: a broad, standing credential/permission is granted to a code path and is never re-validated per-use, so if the trusted downstream endpoint changes the destination (e.g., via an HTTP redirect to an attacker-controlled host), the credential is sent along with it.

### Finding Description
`newCAPITransport` wraps the base HTTP transport used for CAPI/GitHub API calls: [1](#0-0) 

The `RoundTrip` method sets `Authorization: Bearer <token>` on **every** request that passes through it, with no check on `req.URL.Host`:
```go
func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)
	...
```
It only performs a host comparison (`req.URL.Host == ct.capiHost`) to decide whether to add the `Copilot-Integration-Id` and version headers — not to gate whether the bearer token itself should be attached. This is the same root cause pattern as the reported "residual allowance" bug: a credential (allowance / token) is set broadly up front (`_approve(..., _maxSendAmount)` in the original report) and then reused across the whole operation without being re-validated against the specific recipient, so if that recipient is compromised or redirects the flow, the credential is unnecessarily exposed.

Contrast this with the project's own general-purpose HTTP client, which explicitly implements the safe pattern by refusing to forward the auth token across a redirect that changes hostname: [2](#0-1) 

The `capiTransport` used for agent-task/CAPI calls does not implement this same hostname-change guard, and the base `httpClient` it wraps is mutated in place per `NewCAPIClient`'s own docstring ("The provided HTTP client will be mutated for use with CAPI, so it should not be reused elsewhere") [3](#0-2) , indicating the authors were aware of scoping/reuse hazards for this credential but did not apply the redirect-safety check used elsewhere in the codebase.

### Impact Explanation
If the CAPI service (`capiBaseURL`), which is an external, network-reachable, and independently operated trust boundary from the `gh` CLI, ever issues an HTTP redirect (e.g., a 3xx response with a `Location` pointing to a different host — whether due to compromise, misconfiguration, or a bug on the server side) the bearer token is sent verbatim to that new host by `http.Client`'s default redirect-following behavior, because nothing in `capiTransport.RoundTrip` strips the header when the destination host differs from `ct.capiHost`. This can result in exfiltration of the user's GitHub/Copilot bearer credential to an attacker-controlled host, matching the "credential exfiltration to attacker host during a normal command" acceptance criterion.

### Likelihood Explanation
Reachability requires the CAPI backend (attacker-controlled or compromised) to respond with a redirect during a normal `gh agent-task` invocation (e.g. `CreateJob`, `GetSessionLogs`, etc., all routed through this same client/transport) [4](#0-3) . This is plausible under the rules' "attacker-controlled host during a normal gh command" scenario since CAPI base URL / endpoints are configurable per host resolution and the transport itself performs no allow-listing of the redirect target before attaching the Authorization header.

### Recommendation
In `capiTransport.RoundTrip`, only attach the `Authorization: Bearer` header (and other CAPI-specific headers) when `req.URL.Host` matches the expected `ct.capiHost` (or an explicitly allow-listed set of hosts), mirroring the hostname-change guard already implemented in `AddAuthTokenHeader` (`api/http_client.go`). Additionally, consider constructing the underlying `http.Client` with a `CheckRedirect` function that refuses cross-host redirects for credentialed requests.

### Proof of Concept
1. A user runs any `gh agent-task` subcommand that uses `capi.CAPIClient` (e.g. `gh agent-task create`, `gh agent-task view`), which goes through `NewCAPIClient` and its `capiTransport` [5](#0-4) .
2. The CAPI base host (or an intermediary/proxy under attacker influence) responds to a request with an HTTP 3xx redirect pointing at `https://attacker.example/collect`.
3. Go's default `http.Client` transparently follows the redirect and re-invokes `capiTransport.RoundTrip` on the new request targeting `attacker.example`.
4. Because `RoundTrip` unconditionally executes `req.Header.Set("Authorization", "Bearer "+ct.token)` regardless of `req.URL.Host`, the bearer token is sent to `attacker.example`, completing the exfiltration.

// NewCAPIClient creates a new CAPI client. Provide a token, the user's GitHub
// host, the resolved Copilot API URL, and an HTTP client which will be used as

// The provided HTTP client will be mutated for use with CAPI, so it should not
// be reused elsewhere.
func NewCAPIClient(httpClient *http.Client, token string, host string, capiBaseURL string) *CAPIClient {
	httpClient.Transport = newCAPITransport(token, capiBaseURL, httpClient.Transport)
	return &CAPIClient{
		httpClient:  httpClient,
		host:        host,
		capiBaseURL: capiBaseURL,
	}
}

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}

// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
