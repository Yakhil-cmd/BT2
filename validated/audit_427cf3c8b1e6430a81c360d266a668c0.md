### Title
Unbounded SKILL.md/blob size in `gh skill preview` and `gh skill install` enables attacker-controlled resource-exhaustion (DoS) - (File: `internal/skills/discovery/discovery.go`)

### Summary
`internal/skills/discovery.FetchBlob` fetches a git blob's base64 content from an attacker-controlled repository and decodes it into memory with no upper bound on size, and its result is fed directly into `markdown.Render` for terminal rendering. Unlike the "extra files" fetch loop in `pkg/cmd/skills/preview/preview.go`, which explicitly enforces `maxFiles`/`maxTotalBytes` caps, the primary `SKILL.md` blob (and any single file selected in the interactive picker) has no size check at all before being fully read, base64-decoded, and rendered.

### Finding Description
`FetchBlob` performs an unbounded `io.ReadAll` over a base64 decoder with no size limit: [1](#0-0) 

This function is called for the `SKILL.md` content in `previewRun`: [2](#0-1) 

and again for any individually-selected file in the interactive picker, with no size gate before the fetch: [3](#0-2) 

Note that the sibling loop iterating over *extra* files does explicitly cap both the number of files (`maxFiles = 20`) and cumulative bytes (`maxTotalBytes = 512 * 1024`) before calling `FetchBlob`: [4](#0-3) 

but this cap is conspicuously absent for the primary `SKILL.md` blob and for the interactive single-file fetch path. Once fetched, the (unbounded) content is passed straight to the markdown renderer: [5](#0-4) 

The same unguarded `FetchBlob` call is reused by the installer (`internal/skills/installer/installer.go`) and by `pkg/cmd/skills/search/search.go`, meaning the missing size check propagates to `gh skill install` and skill discovery/description lookups as well.

This is directly analogous to the referenced Hats Protocol issue: an attacker (repository owner/publisher) controls a string field (`SKILL.md` content / a skill file) that is unboundedly large, and an unprivileged victim who merely runs a normal command (`gh skill preview owner/repo`, `gh skill install owner/repo`) is forced to fully download, base64-decode, buffer, and render/write that attacker-chosen content with no size ceiling — consuming attacker-controlled amounts of memory/CPU/bandwidth on the victim's machine, just as the Hats bug forced excessive gas consumption on any caller of `Hats.uri`.

### Impact Explanation
A malicious but otherwise unprivileged GitHub repository owner can publish a public repository containing a skill whose `SKILL.md` (or any file exposed via the interactive picker) is extremely large (e.g., tens to hundreds of MB, up to GitHub's blob API limits). Any user who runs `gh skill preview <attacker>/<repo>` or `gh skill install <attacker>/<repo>` against that repository will have their `gh` process fetch, decode, and attempt to render/write that entire blob without any cap, leading to excessive memory allocation and CPU usage (markdown rendering over huge input) — a client-side denial-of-service / resource-exhaustion condition triggered purely by content authored by an untrusted third party. This is a real but moderate-severity issue since it affects only the invoking user's local process (not server-side state), but it is trivially reachable via completely normal, expected `gh` usage against attacker-published content.

### Likelihood Explanation
Likelihood is high for exploitability (any public repo owner can trigger it against any victim who chooses to preview/install their skill) but the blast radius is limited to the local `gh` process of the user who runs the command — there is no privilege escalation or cross-user persistence. It requires the victim to intentionally point `gh skill preview`/`install` at the attacker's repository, which is the normal, documented workflow for discovering/installing third-party skills, so likelihood of accidental exposure is meaningful.

### Recommendation
Introduce a hard size cap (mirroring the `maxTotalBytes` pattern already used for the extra-files loop) in `FetchBlob` or its callers: check the tree-provided `size` field before fetching, and/or bound the `io.ReadAll`/base64 decode with `io.LimitReader`, rejecting or truncating blobs (including `SKILL.md` and interactively-selected files) that exceed a reasonable threshold (e.g., the same 512 KB order of magnitude already used elsewhere in this command).

### Proof of Concept
1. Publish a public repository with a skill directory containing a `SKILL.md` file that is very large (e.g., 50–200 MB of padding after valid frontmatter).
2. As a victim, run `gh skill preview <attacker>/<repo> <skill-name>`.
3. Observe `FetchBlob` (internal/skills/discovery/discovery.go:918-944) fully reading and base64-decoding the entire blob into memory with no size check, followed by `markdown.Render` processing the full content, causing disproportionate memory/CPU consumption relative to a normal skill preview.

func FetchBlob(client *api.Client, host, owner, repo, sha string) (iostreams.Untrusted, error) {
	apiPath, err := safeurl.JoinPath("repos", owner, repo, "git", "blobs", sha)
	if err != nil {
		return iostreams.Untrusted{}, err
	}
	var resp struct {
		SHA      string `json:"sha"`
		Content  string `json:"content"`
		Encoding string `json:"encoding"`
	}
	if err := client.REST(host, "GET", apiPath.String(), nil, &resp); err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not fetch blob: %w", err)
	}

	if resp.Encoding != "base64" {
		return iostreams.Untrusted{}, fmt.Errorf("unexpected blob encoding: %s", resp.Encoding)
	}

	// GitHub API returns base64 with embedded newlines; use the StdEncoding
	// decoder via a reader to handle them transparently.
	decoded, err := io.ReadAll(base64.NewDecoder(base64.StdEncoding, strings.NewReader(resp.Content)))
	if err != nil {
		return iostreams.Untrusted{}, fmt.Errorf("could not decode blob content: %w", err)
	}

	return iostreams.NewUntrustedBytes(decoded), nil
}

func renderMarkdownPreview(io *iostreams.IOStreams, filePath, content string) string {
	if filePath == "SKILL.md" {
		parsed, err := frontmatter.Parse(content)
		if err == nil {
			content = parsed.Body
		}
	}

	rendered, err := markdown.Render(content,
		markdown.WithTheme(io.TerminalTheme()),
		markdown.WithWrap(io.TerminalWidth()),
		markdown.WithoutIndentation())
	if err != nil {
		return content
	}

	return rendered
}
