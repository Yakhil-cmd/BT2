### Title
Missing error propagation in `handleSavedPrivatePayments()` after a failed payload hash causes duplicate async completion / crash on malformed private-payment payloads - ([File: network.js])

### Summary
`handleSavedPrivatePayments()` in `network.js` computes `objectHash.getBase64Hash(objHeadPrivateElement.payload, true)` on the payload of a locally-saved private-payment element that originated from an untrusted private-payment counterparty. If the hash function throws (analogous to `X509_issuer_and_serial_hash()` failing to correctly handle a malformed field), the `catch` block logs the error, deletes the row and invokes the `async.each` iteratee callback `cb`, but execution does **not** stop there — the function falls through and re-invokes `privatePayment.validateAndSavePrivatePaymentChain()` on the same, already-failed element, whose `ifOk`/`ifError`/`ifWaitingForChain` handlers call `cb()` (via `deleteHandledPrivateChain`) a second time.

### Finding Description
`getBase64Hash()` → `getJsonSourceString()` (`string_utils.js:220-257`) / `getSourceString()` (`string_utils.js:11-60`) throws `Error` on many structurally "legal JSON but semantically ill-formed" values that are trivially reachable from an attacker-controlled JSON payload: a `null` value anywhere in the object (`string_utils.js:223-224`), an empty object/array (unless `bAllowEmpty`), a `00`-byte or lone-surrogate string, a non-finite number, etc.

In `network.js:2467-2478` (`handleSavedPrivatePayments` → `validateAndSave`):
```
try {
    var json_payload_hash = objectHash.getBase64Hash(objHeadPrivateElement.payload, true);
}
catch (e) {
    console.log("getBase64Hash failed for private element", objHeadPrivateElement.payload, e);
    if (ws) sendResult(ws, {...});
    deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb);
}
var key = 'private_payment_validated-' + ... + json_payload_hash + ...;
privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {
    ifOk: function(){ ...; deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb); ... },
    ifError: function(error){ ...; deleteHandledPrivateChain(row.unit, row.message_index, row.output_index, cb); ... },
    ifWaitingForChain: function(){ cb(); }
});
```
There is no `return` statement after the `catch` block, so:
1. `json_payload_hash` is `undefined`, silently corrupting the emitted event key.
2. `deleteHandledPrivateChain(..., cb)` from the `catch` path already deletes the DB row and calls `cb()` once for this `async.each` iteration.
3. Immediately afterward, the same `arrPrivateElements` (which just failed to hash) is passed again into `privatePayment.validateAndSavePrivatePaymentChain()`, whose completion handlers call `deleteHandledPrivateChain(..., cb)` (or `cb()` directly) **a second time** for the same iteration.

This is a double invocation of the `async.each` iteratee callback for a single item, together with a duplicate/racing `DELETE` on `unhandled_private_payments` for an already-deleted row and duplicate event emission (`eventBus.emit('new_my_transactions', ...)`/`emit(key, ...)`), for an entry that a private-payment counterparty fully controls (its JSON is exactly what was received and saved to `unhandled_private_payments` by that peer, per `savePrivatePayments()` upstream).

### Impact Explanation
`handleSavedPrivatePayments()` is invoked from wallet-processing paths (e.g., after receiving/relaying private payments and on startup) and runs on the full node/wallet handling private chains. A double-fired callback into `async.each` can retrigger the overall completion handler prematurely/twice, corrupt bookkeeping in `assocNewUnits`, and — depending on the `async` library's internal callback-guard behavior — throw an uncaught "Callback was already called" error, crashing the node process that is processing private payments. Because this path runs for every unhandled private payment on the node (and is re-triggered via `eventBus`/on new units), a single malicious private-payment counterparty can reliably drive an unhandled/crash condition on any node/wallet that receives and stores the crafted private element, matching the reachable/allowed category "network unable to confirm new units" once the affected node's private-payment processing loop is corrupted or the process crashes. This is the direct structural analog of CVE-2021-23841: an unhandled/incorrectly-handled parsing error inside a hashing routine on attacker-supplied data leads to downstream misuse of an inconsistent state rather than aborting cleanly.

### Likelihood Explanation
High for a determined attacker: producing a payload for which `getJsonSourceString`/`getSourceString` throws is trivial (e.g. a `null` field, an embedded `00` byte, or a lone UTF‑16 surrogate in a string field of the private payment's `payload`), and private payment JSON is fully attacker-supplied and stored verbatim in `unhandled_private_payments.json` before this code executes on it (`network.js:2394-2401`, `2462`). No signature or hash check on the payload precedes this hashing attempt.

### Recommendation
Add a `return` (or restructure with early return / promise chain) inside the `catch` block at `network.js:2472-2477` so that the function does not fall through to re-run `validateAndSavePrivatePaymentChain()` and does not construct `key` using an `undefined` hash. Ensure `cb` is invoked exactly once per iteration and that a corrupted/unhashable payload results only in `deleteHandledPrivateChain` + a single `cb()` call.

### Proof of Concept
1. As a private-payment counterparty, craft a private-payment head element whose `payload` contains a field with an embedded value that makes `string_utils.getJsonSourceString`/`getSourceString` throw when `bJsonBased`/`getBase64Hash(..., true)` is called — e.g. a string field containing a lone UTF‑16 surrogate (`"\ud800"`) or an explicit `null` in a nested object (`string_utils.js:14-15,223-224`).
2. Send this private payment to the victim device/hub so it is stored via `savePrivatePayment` into `unhandled_private_payments` (`network.js:2390-2401`).
3. When `handleSavedPrivatePayments()` processes the row, `getBase64Hash` throws inside `validateAndSave` (`network.js:2469-2471`); the `catch` block calls `deleteHandledPrivateChain(..., cb)` (first `cb()` call) but execution continues to call `privatePayment.validateAndSavePrivatePaymentChain(arrPrivateElements, {...})` on the same data, whose `ifOk`/`ifError` handler calls `deleteHandledPrivateChain(..., cb)` again (second `cb()` call) for the same `async.each` iteration — verifiable by instrumenting/logging `cb` invocation count per row or observing duplicate `DELETE` queries and duplicate `eventBus.emit` calls for the same unit/message_index/output_index. function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);
}

function getJsonSourceString(obj, bAllowEmpty) {
	let cache = new WeakMap();  // object to stringified result
	function stringify(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				return toWellFormedJsonStringify(variable);
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
			case "boolean":
				return variable.toString();
			case "object":
				// return cached result if already processed
				if (cache.has(variable))
					return cache.get(variable);
				let result;
				if (Array.isArray(variable)){
					if (variable.length === 0 && !bAllowEmpty)
						throw Error("empty array in "+JSON.stringify(obj));
					result = '[' + variable.map(stringify).join(',') + ']';
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0 && !bAllowEmpty)
						throw Error("empty object in "+JSON.stringify(obj));
					result = '{' + keys.map(function(key){ return toWellFormedJsonStringify(key)+':'+stringify(variable[key]) }).join(',') + '}';
				}
				cache.set(variable, result);  // memoize for future references
				return result;
			default:
				throw Error("getJsonSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	return stringify(obj);
}

function getBase64Hash(obj, bJsonBased) {
	var sourceString = bJsonBased ? getJsonSourceString(obj) : getSourceString(obj)
	return crypto.createHash("sha256").update(sourceString, "utf8").digest("base64");
}
