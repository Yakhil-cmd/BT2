### Title
Non-idempotent `forgetUnit()` cache eviction can be invoked on an already-forgotten AA response unit, crashing the node during trigger revert - ([File: aa_composer.js])

### Summary
The CVE analog is the pinctrl `pctldev` double-free: a cleanup routine frees/tears down a resource that is (or may already have been) torn down by another owner, because the function does not check whether the resource is still valid before releasing it. In ocore, the structural analog is `storage.forgetUnit()` [1](#0-0) , which unconditionally dereferences and deletes `assocUnstableUnits[unit]` without checking whether the unit is still present in the cache, combined with `aa_composer.revertResponsesInCaches()` [2](#0-1)  which calls `forgetUnit` for every response unit collected during an AA trigger chain whenever that chain has to be rolled back (bounced) or dry-run.

### Finding Description
`forgetUnit(unit)` is not idempotent: it reads `assocUnstableUnits[unit].parent_units` before deleting the cache entries, and if called a second time on the same `unit` it will throw (`Cannot read properties of undefined`) because the entry no longer exists: [3](#0-2) 

`revertResponsesInCaches()` is the single choke point that is supposed to guarantee `forgetUnit` is called exactly once per response unit that was speculatively inserted into `assocUnstableUnits` while composing an AA response chain: [2](#0-1) 

This function is invoked from two structurally different call sites that both operate on the *same, mutable, shared* `arrResponses` array that is threaded by reference through the whole primary→secondary AA trigger call chain via `trigger_opts`:
- `dryRunPrimaryAATrigger()`'s `onDone` callback, always run at the very end of a dry run: [4](#0-3) 
- `handleTrigger()`'s internal `revert(err)` helper, which fires whenever a secondary AA in the chain bounces or `updateStorageSize` fails, and is reachable multiple times as `bounce()` → `sendUnit()` → potential secondary failures → `revert()` recurse through the trigger tree: [5](#0-4)  and [6](#0-5) 

`revert()` does clear `arrResponses` with `arrResponses.splice(0, arrResponses.length)` right after calling `revertResponsesInCaches(arrResponses)` [7](#0-6) , which is the guard that is supposed to prevent a second call from re-processing the same units. The correctness of the whole scheme hinges entirely on `arrResponses` always being fully emptied before any other path can call `revertResponsesInCaches` again with overlapping units, and on `forgetUnit` never being reached twice for the same unit — there is no defensive check inside `forgetUnit` or `revertResponsesInCaches` itself that would turn a double-invocation into a no-op instead of a crash. This mirrors the pinctrl bug: `pctldev` (the resource) is released a second time because the freeing code does not verify that the resource wasn't already freed by another code path (`devm_pinctrl_dev_release`), and here `assocUnstableUnits[unit]` (the resource) can be released a second time because `forgetUnit` does not verify the unit is still tracked.

### Impact Explanation
If `revertResponsesInCaches`/`forgetUnit` were ever reached twice for the same response unit — e.g., through a re-entrant call chain that an unprivileged AA-trigger author can construct via nested primary→secondary AA bounce/revert cascades — the uncaught `TypeError` thrown out of `forgetUnit` would crash the node process running the AA engine (`aa_composer.handleAATriggers`, invoked from the stabilization/write path in `writer.js` [8](#0-7) ). Because this code runs while the node is stabilizing an MCI and executing AA triggers as part of normal unit processing, a crash here means the network's node cannot confirm/process new units until restarted, which matches the "network unable to confirm new units" acceptance criterion.

### Likelihood Explanation
I was not able to conclusively prove, within the code reachable in this session, a concrete re-entrant path where `revertResponsesInCaches` is invoked a second time on an overlapping unit before `arrResponses` is cleared (the `splice` in `revert()` and the single terminal `onDone` in `dryRunPrimaryAATrigger` appear, on inspection, to guard against this in the common cases traced). The bug class (non-idempotent free of a cache-tracked resource, freed from more than one call site sharing mutable state) is present and structurally analogous to the CVE, but confirming an actual reachable double-invocation would require deeper tracing of all `handleTrigger`/`bounce`/`revert`/`sendUnit` recursion paths (including the `bAir`/`assocBalances` "air" mode and `dryRunPrimaryAATrigger` interleavings) than could be completed in the available tool budget.

### Recommendation
Make `storage.forgetUnit()` defensive/idempotent: return early (no-op) if `assocUnstableUnits[unit]` is already absent, rather than assuming the unit is always still cached, mirroring the kernel fix of removing the incorrect free entirely and relying on the sole legitimate owner to release the resource. Additionally, audit every call path that can lead to `revertResponsesInCaches` (`dryRunPrimaryAATrigger`, `handleTrigger`'s `revert()`, and any future callers) to guarantee `arrResponses` is cleared exactly once and cannot be revisited with stale entries after a partial revert.

### Proof of Concept
Not able to construct a concrete, verified trigger unit / AA definition sequence that forces a second invocation of `revertResponsesInCaches` on an already-forgotten unit within the scope of this analysis; a full PoC would require exercising nested secondary-AA bounce cascades combined with `bAir`/dry-run paths and tracing every `bounce()`/`sendUnit()`/`revert()` recursion, which needs interactive debugging beyond static code reading.

function revertResponsesInCaches(arrResponses) {
	// remove the rolled back units from caches and correct is_free of their parents if necessary
	console.log('will revert responses ' + JSON.stringify(arrResponses, null, '\t'));
	var arrResponseUnits = [];
	arrResponses.forEach(function (objAAResponse) {
		if (objAAResponse.response_unit)
			arrResponseUnits.push(objAAResponse.response_unit);
	});
	console.log('will revert response units ' + arrResponseUnits.join(', '));
	if (arrResponseUnits.length > 0) {
		var first_unit = arrResponseUnits[0];
		var objFirstUnit = storage.assocUnstableUnits[first_unit];
		var parent_units = objFirstUnit.parent_units;
		arrResponseUnits.forEach(storage.forgetUnit);
		storage.fixIsFreeAfterForgettingUnit(parent_units);
	}
}
