### Title
`InitializeWithPermission.creator` accepts unvalidated (zero) address, permanently freezing creator fees - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`initialize_with_permission` stores an arbitrary, unvalidated `creator` account as `pool_state.pool_creator` with no check that it is non-zero or otherwise a real signable address. Since accrued creator fees can only ever be withdrawn by a signer matching `pool_creator`, setting this field to the default/zero `Pubkey` permanently locks any creator fees the pool accrues.

### Finding Description
`InitializeWithPermission` declares `creator` as an `UncheckedAccount<'info>` with no `address`, `constraint`, or non-default check applied to it — it is only documented as `/// CHECK: creator of pool` [1](#0-0) . This unchecked value is passed directly into `pool_state.initialize(...)` and persisted as `pool_creator` [2](#0-1) , which is stored verbatim by `PoolState::initialize` [3](#0-2) .

The only gate on calling `initialize_with_permission` is the caller holding a `Permission` PDA seeded by `payer` [4](#0-3)  — nothing constrains `payer` from supplying `creator = Pubkey::default()` (or any other unsignable address such as another program's ID) for the pool it creates.

Once `pool_creator` is the zero/default address, the permissioned fee-collection path becomes unusable: `CollectCreatorFee.creator` requires both `address = pool_state.load()?.pool_creator` and `Signer<'info>` [5](#0-4) . The zero `Pubkey` has no corresponding private key, so no transaction can ever sign as that account, and `collect_creator_fee` becomes permanently uncallable for that pool.

The permissionless path does not require a signature — `CollectCreatorFeePermissionless.creator` is merely constrained by `address = pool_state.load()?.pool_creator` [6](#0-5)  — but it still creates ATAs with `associated_token::authority = creator` [7](#0-6)  and transfers the accrued `creator_fees_token_0`/`creator_fees_token_1` there [8](#0-7) . Any tokens sent to an ATA owned by the zero/default `Pubkey` (or any other non-owned address) are permanently unrecoverable, since nobody controls the corresponding keypair.

### Impact Explanation
Every swap that accrues a nonzero creator fee (`enable_creator_fee = true`, set unconditionally to `true` in `initialize_with_permission` [2](#0-1) ) increments `creator_fees_token_0`/`creator_fees_token_1` in `update_fees` [9](#0-8) . If `pool_creator` was initialized to an unsignable/unowned address, these fees can never be reclaimed by their intended owner and either get permanently stuck in the pool vaults (permissioned path) or get permanently swept to an inaccessible token account (permissionless path). This is a permanent freezing of protocol/creator funds tied to that pool.

### Likelihood Explanation
Any account calling `initialize_with_permission` with a valid `Permission` PDA (an already-permissioned pool creator role) can trivially pass `Pubkey::default()` or any other unsignable address as `creator` — the instruction never validates it, and doing so requires no special privilege beyond the existing permission gate needed to call the instruction at all.

### Recommendation
Add a constraint in `InitializeWithPermission` rejecting `creator == Pubkey::default()` (and ideally verifying it is a plausible externally-ownable address), mirroring standard zero-address checks recommended for admin/authority fields.

### Proof of Concept
1. Obtain (or already hold) a valid `Permission` PDA for `payer`.
2. Call `initialize_with_permission` supplying `creator = Pubkey::default()` along with legitimate mints/vaults.
3. The pool initializes successfully with `pool_state.pool_creator == Pubkey::default()`.
4. Perform swaps to accrue `creator_fees_token_0`/`creator_fees_token_1`.
5. Attempt `collect_creator_fee`: it requires a `Signer` matching `pool_creator`, which is impossible to produce for the zero address — fees stay locked in the vault forever.
6. Alternatively call `collect_creator_fee_permissionless`: it succeeds and sends the fees to an ATA owned by `Pubkey::default()`, which is permanently unrecoverable.
