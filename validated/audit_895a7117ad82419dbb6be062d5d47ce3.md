### Title
CCMenu token creation omits stack scoping, granting a "single-stack" token global `read:stack` access - ([File: app/controllers/shipit/ccmenu_url_controller.rb])

### Summary
`CCMenuUrlController#fetch` is meant to hand out a scoped, unauthenticated-going-forward token that lets a CI status widget (CCMenu/CCTray XML) read the state of **one** stack. The token is actually created without any stack binding, so it authenticates as a client with `read:stack` permission against **every** stack in the installation, not just the one the user requested.

### Finding Description
The controller builds the URL and the `ApiClient` used to authenticate it like this: [1](#0-0) 

```ruby
def fetch
  uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
  uri.query = { 'token' => client.authentication_token }.to_query
  render(json: { ccmenu_url: uri.to_s })
end

def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end

def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```

`stack` is only used to build the returned URL; it is never passed to `ApiClient.create_with(...)`. `ApiClient` has a `belongs_to :stack, optional: true` association, so any client created this way ends up with `stack_id == nil`. [2](#0-1) 

The authorization check performed by the general API (used by every `api/*` controller, including `Api::CCMenuController` and `Api::StacksController`) is: [3](#0-2) 

```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end

def stack
  @stack ||= stacks.from_param!(params[:stack_id])
end
```

Because the CCMenu client's `stack_id` is `nil`, `stack_id?` is `false`, so `stacks` resolves to `Stack.all`. Any endpoint gated only by `require_permission :read, :stack` (e.g. `Api::StacksController#index`/`#show`, `Api::CCMenuController#show` for arbitrary stacks) becomes reachable with this token, for any stack, not just the one the user asked for.

**Binding broken:** *the stack a token authorizes* (intended: exactly the one stack whose `ccmenu_url` was requested) *≠ the stack(s) it actually touches* (in practice: `Stack.all`, i.e. every stack managed by this Shipit instance).

### Impact Explanation
CCMenu/CCTray URLs are designed to be embedded in third-party tooling (CI dashboard aggregators, IDE plugins, status badges) and are commonly treated as "public enough to paste into a widget" because they are meant to expose only build-status data for one stack, without requiring a further login. Because the underlying `ApiClient` is unscoped, anyone who obtains one such URL/token (via the widget, a leaked README/dashboard config, browser history, etc.) gets **unauthenticated, standing `read:stack` access to every stack** in the Shipit deployment — including stacks the requesting user was never authorized to view, and including any stack an administrator considers private. This is unauthenticated read of stack state via the API, which matches the report's High-severity bucket ("unauthenticated read of stack state, task streams or deploy output").

### Likelihood Explanation
Any authenticated Shipit user who can view a single stack can trigger `CCMenuUrlController#fetch` for that stack via the normal "fetch CCMenu URL" UI action, immediately obtaining a globally-scoped token. No special privileges, admin action, or race condition are required — this is a straightforward, deterministic consequence of the missing `stack:` attribute on `ApiClient.create_with`. The token persists (`find_or_create_by!`) and is reusable indefinitely until manually revoked/deleted.

### Recommendation
Bind the created `ApiClient` to the requested stack, e.g.:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack], stack:)
                       .find_or_create_by!(creator: current_user, stack:, name: 'CCMenu Client')
end
```
so that `stack_id` is populated and `Api::BaseController#stacks` correctly restricts the client to `Stack.where(id: current_api_client.stack_id)`.

### Proof of Concept
1. As any authenticated Shipit user with visibility of `stack_a`, call the UI action backing `CCMenuUrlController#fetch` for `stack_a` (`GET /stacks/:stack_id/ccmenu_url`).
2. Observe the returned JSON contains `ccmenu_url` with a `token=` query parameter — this is `ApiClient#authentication_token` for a freshly created/looked-up `ApiClient` with `permissions: ["read:stack"]` and `stack_id: nil`.
3. Use that token as HTTP Basic auth (`Authorization: Basic base64(token)`) against unrelated endpoints, e.g.:
   - `GET /api/stacks` → returns **all** stacks, not just `stack_a`.
   - `GET /api/stacks/<owner>/<other_repo>/<env>/ccmenu` → returns build status for `stack_b`, a stack the token was never intended to expose.
4. Confirm via `ApiClient` record: `ApiClient.find_by(name: 'CCMenu Client').stack_id` is `nil`, while `Api::BaseController#stacks` falls back to `Stack.all` per [4](#0-3) .
