### Title
Post-callback solvency gate prices collateral on a stale pre-callback oracle snapshot that the receiver/swap can invalidate - (File: contracts/controller/src/strategies/flash_position.rs)

### Summary
The kernel bug class is deferred work consuming state captured before a transition window in which that state is torn down (page-reporting work running on deleted virtqueues). The XOXNO analog is the `Context` price snapshot in `flash_position` (and the same pattern in `multiply` / `swap_debt` / `swap_collateral`): `prefetch_strategy_prices` caches every relevant asset price *before* the attacker-controlled `execute_flash_position` callback (or before the attacker-chosen router swap), and `Context::fetch_prices`/`cached_price` retain that snapshot — the final LTV/health-factor gate in `strategy_finalize` therefore validates solvency against prices from before a window in which the attacker can move the very oracle inputs being priced (Aquarius LP reserves backing `AquariusLp`/`AquariusStableLp` sources).

### Finding Description
In `contracts/controller/src/strategies/flash_position.rs`:

- Line 117: `prefetch_strategy_prices(&mut cache, &account, &extra_assets)` loads prices for the debt asset, all declared collaterals, and (for a reused `account_id`) every existing account asset into `cache.token_prices`.
- Lines 120–143: inside `with_flash_guard`, debt is minted and forwarded, then `invoke_receiver` executes arbitrary attacker Wasm (`execute_flash_position`). The guard only blocks re-entry into the controller; the receiver may freely call Aquarius/Soroswap pools and token contracts.
- Lines 145–153: `collect_collateral_deposits`, `process_deposit`, and `strategy_finalize` → `enforce_post_pool_solvency` value the final position using `cache.cached_price` / `cached_market_index`. `Context::fetch_prices` (`contracts/controller/src/context.rs:142-151`) only fills *missing* keys and never re-reads a cached price, so the post-callback gate uses the pre-callback snapshot.

The same ordering exists in `multiply.rs` (line 65 prefetch, line 90 attacker-chosen `swap_tokens_or_passthrough`, line 112 `strategy_finalize`), `swap_debt.rs` (line 53 vs. line 65), and `swap_collateral.rs` (line 53 vs. line 55).

Oracle inputs that a callback/swap can mutate: `contracts/price-aggregator/src/providers/aquarius.rs:90-113` reads `aquarius_pool_reserves_call` and `aquarius_total_shares_call` live at resolution time and feeds them into `fair_lp_price_wad` (`common/src/oracle/lp.rs:57-87`), which is `2 * sqrt(v_a * v_b) / share_supply` — sensitive to reserve changes (e.g., token donations or liquidity adds) between snapshot and gate.

Attack shape (single transaction, single unprivileged address):
1. Attacker contract inflates the collateral's oracle-readable state (e.g., donates/adds reserves to the Aquarius pool backing an `AquariusLp` source for the collateral LP token, or acquires LP shares while pool value is pumped).
2. Calls `controller.flash_position` (or `multiply`) with that LP token as collateral; prefetch caches the inflated price.
3. Inside `execute_flash_position` (or the multiply swap route itself), unwinds the pump — withdraws the donated liquidity / swaps back, recovering the capital.
4. `strategy_finalize` validates HF ≥ 1 and LTV coverage against the stale inflated collateral value; the deposited collateral's real value is now far lower.
5. The account is left with real debt exceeding real collateral → bad debt socialized into the supply index (`clean_bad_debt` write-down), i.e., theft from suppliers.

This mirrors the kernel report exactly: a risk-computation "worker" was scheduled on a non-freezable snapshot; the environment changed underneath it during the callback window, and the stale snapshot is dereferenced afterward.

### Impact Explanation
Protocol insolvency / theft of supplier funds: the post-callback solvency gate is the only check that the minted debt is collateralized, and it is evaluated against a price snapshot the attacker can arrange to be inflated relative to end-of-transaction value. The resulting underwater position's loss is socialized to suppliers via the bad-debt supply-index write-down. Magnitude is bounded by the achievable reserve-skew factor of the referenced Aquarius pool and the account's LTV.

### Likelihood Explanation
Reachable by any address: `flash_position` accepts any deployed-Wasm receiver and any account the caller owns (`account_id = 0` or own account); `multiply` needs no receiver at all — its router swap steps are attacker-chosen and can trade on the same pool that feeds the oracle. The exploit requires (a) a collateral asset priced through an `AquariusLp`/`AquariusStableLp` source, and (b) that `get_reserves` reflects donated/unbalanced value the attacker can add before the call and recover inside the callback or unwind swap (recoverable cost is low when the attacker holds most of the pool's LP shares). Feeds on Reflector/RedStone legs are not attacker-mutable, so the exposure is confined to AMM-reserve-derived collateral pricing. Severity Medium–High depending on whether such a collateral listing exists; the stale-snapshot ordering itself is unconditional code.

Uncertainty I could not fully resolve: whether the production Aquarius pools' `get_reserves` returns cached reserves (sync-gated, donation-immune) or live balances (donation-sensitive). Under the former, the swap-preserves-`k` property of `fair_lp_price_wad` largely neutralizes the drain vector, which would lower exploitability; the stale-across-callback ordering bug stands regardless.

### Recommendation
Treat the callback/swap window like the kernel's freeze boundary: re-fetch prices for all account assets *after* the untrusted window rather than retaining the prefetch. Concretely, clear `cache.token_prices` (and `pool_sync_data`/`market_indexes` for touched markets) after `with_flash_guard` returns in `process_flash_position` and after `swap_tokens`/`swap_tokens_or_passthrough` in `multiply`, `swap_debt`, and `swap_collateral`, so `enforce_post_pool_solvency` observes post-window prices. Alternatively/additionally, value collateral on the floor of the pre- and post-window prices to fail closed. A sanity band on the oracle does not help here because the inflated price is within the band.

### Proof of Concept
1. Governance has listed `LP(A/B)` as collateral in the spoke, priced via `PriceSource::AquariusLp { pool: P, ... }`.
2. Attacker deploys a Wasm receiver contract holding most of `P`'s LP shares.
3. Attacker donates a large amount of token `A` to `P` (or adds liquidity), raising `2*sqrt(v_a*v_b)/shares`.
4. In one transaction: call `controller.flash_position(caller, account_id: 0, spoke_id, mode: Multiply, debt: USDC hub key, amount: X, receiver: attacker_contract, collaterals: [(LP key, min)], refund_assets: [], data)`. Prefetch caches the inflated `LP` price; `mint_and_forward` sends `X` USDC to the receiver; inside `execute_flash_position` the receiver withdraws its liquidity from `P` (collapsing the inflated reserves) and transfers the required `min` LP shares to the controller.
5. `strategy_finalize` computes HF from the stale inflated LP price and persists the position; the transaction commits.
6. The account's real collateral value (post-unwind LP price) is below its USDC debt. The attacker walks away with `X` USDC; the deficit becomes bad debt written down against the supply index.

Equivalent variant without a callback: `multiply(caller, 0, spoke_id, collateral: LP key, debt_to_flash_loan: X, debt: USDC, mode: Multiply, swap: route_that_unwinds_the_pump_on_P, ...)` — the swap route both converts debt→collateral and normalizes `P`'s reserves, while the final gate still reads the pre-swap cached LP price.
