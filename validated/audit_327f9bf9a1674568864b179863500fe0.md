### Title
GitHub token leaked to non-GitHub host via multi-hop redirect chain - ([File: api/http_client.go])

### Summary
`AddAuthTokenHeader` in `api/http_client.go` decides whether to re-attach the `Authorization: token …` header on a redirected request by comparing the current request's host only to the **immediately preceding hop's** host, instead of comparing it to the **original** request's host. Because of this, a two-step redirect chain that first leaves `github.com`/GHES and then issues a same-host follow-up redirect will cause the CLI's authentication token to be attached and sent to the non-GitHub host on the second hop.

### Finding Description
`AddAuthTokenHeader` wraps the transport used by every authenticated `gh` HTTP client (`api.NewHTTPClient`, used by `f.HttpClient()`), and Go's standard `net/http` client intentionally builds each redirect request with a brand-new, empty `Header` map (headers are not carried over automatically), so `gh` must manually decide whether to reattach the token on each hop: [1](#0-0) 

The intent, per the comment, is: "Only set header if an initial request or redirect request to the same host as the initial request." However the check does not compare against the initial/original request; it compares against `req.Response.Request`, which in Go's redirect loop is only the request from the *immediately preceding* hop: [2](#0-1) 

```go
var redirectHostnameChange bool
if req.Response != nil && req.Response.Request != nil {
    redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
}
if !redirectHostnameChange {
    hostname := ghauth.NormalizeHostname(getHost(req))
    if token, _ := cfg.ActiveToken(hostname); token != "" {
        req.Header.Set(authorization, fmt.Sprintf("token %s", token))
    }
}
```

Consider a 3-hop chain:
1. Hop 1: request to `github.com` (or a GHES host) — token attached (no `Response` yet).
2. Hop 2: server-issued redirect to `attacker.example` — `getHost(hop2)="attacker.example"` differs from `getHost(hop1)="github.com"`, so the token is correctly withheld.
3. Hop 3: `attacker.example` responds with its own redirect to a different path on the **same** host (`attacker.example/other`) — now `getHost(hop3)` is compared only against `getHost(hop2)` (`attacker.example`), which is identical, so `redirectHostnameChange` is `false` and the token is reattached and sent to `attacker.example` on hop 3.

The original github host is never consulted again once one hop has already changed hosts, so the "same host as the initial request" guarantee described in the comment is not actually enforced.

### Impact Explanation
Any `gh` command that performs an authenticated HTTP request and can be steered into following a multi-hop redirect where the intermediate/attacker-controlled host issues its own follow-up redirect will exfiltrate the user's GitHub token (`Authorization: token …`) to that attacker-controlled host. This is a credential-exfiltration primitive reachable during ordinary CLI usage of `gh api`/other commands that go through the shared authenticated HTTP client, without requiring any local access, MITM position, or privileged role — only control of the server/response at the far end of a redirect that `gh` is caused to follow.

### Likelihood Explanation
Exploitation requires the attacker to control (or influence) a redirect target reached from a `gh`-issued authenticated request and to have that target issue a second, same-host redirect. This is a realistic pattern for any HTTP redirect chain terminating on infrastructure the attacker operates (e.g., a URL an attacker gets `gh` to fetch, or a compromised/self-hosted GHES asset host), since the attacker fully controls the response headers/paths on their own host. The bug is a straightforward, purely logical flaw (comparison against the wrong reference point) rather than a timing- or race-dependent condition, making it reliably reproducible whenever the redirect pattern occurs.

### Recommendation
Compare the current request's host against the **original** request's host for the whole redirect chain (e.g., capture and thread through the initial host, or use the first entry of the client's internal request chain) rather than `req.Response.Request`, which only reflects the previous hop. Only reattach the `Authorization` header when the current hop's host equals that original host.

```go
// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}
```

```go
func TestHTTPClientRedirectAuthenticationHeaderHandling(t *testing.T) {
	var request *http.Request
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		request = r
		w.WriteHeader(http.StatusNoContent)
	}))
	defer server.Close()

	var redirectRequest *http.Request
	redirectServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		redirectRequest = r
		http.Redirect(w, r, server.URL, http.StatusFound)
	}))
	defer redirectServer.Close()

	client, err := NewHTTPClient(HTTPClientOptions{
		Config: tinyConfig{
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(redirectServer.URL, "http://")): "REDIRECT-TOKEN",
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(server.URL, "http://")):         "TOKEN",
		},
	})
	require.NoError(t, err)

	req, err := http.NewRequest("GET", redirectServer.URL, nil)
	require.NoError(t, err)

	res, err := client.Do(req)
	require.NoError(t, err)

	assert.Equal(t, "token REDIRECT-TOKEN", redirectRequest.Header.Get(authorization))
	assert.Equal(t, "", request.Header.Get(authorization))
	assert.Equal(t, 204, res.StatusCode)
}
```
