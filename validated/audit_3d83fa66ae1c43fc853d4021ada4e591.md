## Title
Webhook signature verification selects the GitHub App/secret from unsigned request parameters, letting one tenant forge webhooks impersonating another organization - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks *which* GitHub App config (and thus which HMAC `webhook_secret`) to verify a delivery against by reading `repository_owner` from Rails' `params`, not from the raw, HMAC-signed request body. In a multi-organization Shipit deployment (the `secrets.github` per-org schema exercised by `github_app_config`/`github_organizations`), `params` is the union of query-string and body parameters, and Rails only lets the JSON body's value win when the same top-level key exists in both. Several webhook payloads GitHub actually sends (e.g. `membership`) have no top-level `repository` key at all, so an attacker can smuggle a `repository[owner][login]=<their-own-org>` query parameter, causing the org used for signature *verification* to diverge from the org whose data is actually *processed* out of the signed body.

### Finding Description
`repository_owner` is computed as: [1](#0-0) [2](#0-1) 

This value is passed to `Shipit.github(organization: repository_owner)`, which, in the multi-org configuration, looks up a distinct `webhook_secret` per organization: [3](#0-2) 

`verify_webhook_signature` then HMACs `request.raw_post` with that specific secret: [4](#0-3) 

The problem: `params.dig(...)` in the controller reads from `ActionController::Parameters`, which Rails builds as `query_parameters.merge(request_parameters)` — i.e. the *body* only overrides the *query string* for keys that exist in **both**. If a webhook payload's JSON body has no top-level `repository` key (true for GitHub's real `membership` event, which only has `organization`, `team`, `member`, `sender`), a `repository[owner][login]=<attacker-org>` query parameter survives into `params` untouched, even though it is never covered by the HMAC signature (`request.raw_post` only contains the JSON body).

Meanwhile, the actual event processing is done independently on the untouched raw body: [5](#0-4) 

and the `MembershipHandler` trusts the body's `organization.login` and `member.login` fields to add a GitHub user to a `Team`: [6](#0-5) 

This is the equality the report's bug class maps to: the organization **authenticated** (selected via query-string-influenced `repository_owner`, used only to pick the verification secret) is not bound to the organization/repository whose data is **written** (taken solely from the signed JSON body). An attacker who legitimately administers their *own* GitHub App/org in this Shipit instance (and therefore knows their own `webhook_secret`) can:

1. Craft a `membership` JSON body with `organization.login = "victim-org"`, `action: "added"`, `member.login = "<attacker's GitHub login>"`, and a `team` object matching a team tied to `Shipit.github_teams`.
2. Sign that raw body with **their own** org's `webhook_secret` (`sha1=HMAC(their_secret, raw_body)`).
3. POST it to `/webhooks?repository[owner][login]=<their-own-org>`, with header `X-Github-Event: membership`.
4. `verify_signature` computes `repository_owner` = `"their-own-org"` from the query string (since the body lacks a `repository` key), fetches *their own* app's secret, and the signature check passes.
5. `create` re-parses the untouched raw body and dispatches it to `MembershipHandler`, which adds the attacker to the team associated with `"victim-org"`.

### Impact Explanation
Successfully forging this webhook lets an attacker who only controls one tenant's GitHub App escalate into `Shipit.github_teams` authorization for an unrelated organization, since `User#authorized?` is driven purely by `Team` membership: [7](#0-6) 

Team membership gates access to the entire Shipit UI/API for stacks belonging to the victim org (`Authentication#force_github_authentication`): [8](#0-7) 

This matches the High-impact category "escalation into `Shipit.github_teams` authorization."

### Likelihood Explanation
This requires a multi-organization Shipit deployment (supported and tested, see `test/dummy/config/secrets_double_github_app.yml` and `Shipit.github_app_config`) where the attacker administers at least one of the configured GitHub Apps/orgs — i.e. an unprivileged-relative-to-other-tenants attacker, not requiring any Shipit session, API token, or the victim's secret. The `/webhooks` endpoint is unauthenticated by design (only signature-gated) and reachable from the internet.

### Recommendation
Do not select the verification secret (or any org used later for authorization decisions) from `ActionController::Parameters`, which mixes query-string and body values. Instead:
- Parse `repository_owner` exclusively from `JSON.parse(request.raw_post)` (the same object used in `create`), never from Rails' merged `params`.
- Alternatively/additionally, after signature verification succeeds against org X's secret, assert that every organization-identifying field consumed later by handlers (`organization.login`, `repository.owner.login`, etc.) equals X, rejecting the request otherwise.

### Proof of Concept
```
POST /webhooks?repository[owner][login]=attacker-org
X-Github-Event: membership
X-Hub-Signature: sha1=<HMAC-SHA1(attacker-org secret, raw_body)>
Content-Type: application/json

{
  "action": "added",
  "team": {"id": 48, "name": "Ouiche Cooks", "slug": "ouiche-cooks", "url": "https://example.com"},
  "organization": {"login": "victim-org"},
  "member": {"login": "attacker-github-login"}
}
```
`verify_signature` resolves `repository_owner` to `"attacker-org"` from the query string (no `repository` key in body), verifies with the attacker's own secret, and then `MembershipHandler` adds `attacker-github-login` to the `ouiche-cooks` team scoped to `victim-org`, granting `authorized?` access to victim-org stacks.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
