### Title
Attacker-controlled AA formula can throw an uncaught JS exception in `evaluate()`, crashing the full node (DoS) - (File: formula/evaluation.js)

### Summary
CVE-2021-46540 describes a SEGV/crash in Cesanta MJS's `mjs_get_mjs` caused by a type-confusion assumption in the interpreter's builtin dispatch that isn't fully validated before use, letting a script (via `mjs_get_mjs`) reach an invalid-state code path and crash the process. The `ocore` analog is oscript's formula interpreter (`formula/evaluation.js`), which is exercised for every Autonomous Agent (AA) trigger. Several `evaluate()` branches assume a value has already been reduced to a "safe" oscript type and fall back to a bare `throw Error(...)` (instead of the controlled `setFatalError(...)` path) when that assumption is violated. Because `network.js` installs a global `process.on('uncaughtException', ...)` handler that deliberately re-throws to crash the whole node process, any oscript-evaluator code path that can be driven into one of these bare `throw Error()` statements is a full node-crashing DoS, reachable by any unprivileged unit poster who can trigger AA execution.

### Finding Description
`formula/evaluation.js`'s `evaluate()` function is the interpreter for oscript formulas used both in AA definitions/triggers and getters. Throughout the switch statement, most type mismatches are handled defensively via `setFatalError(...)`, which safely bounces the AA response without crashing the process. However, a number of branches instead perform a hard `throw Error(...)` when an internal invariant about the *shape* of an already-evaluated value is violated, e.g.:

- `ifelse`: after coercing `wrappedObject` to `true` and validating with `isValidValue(res)`, the code still has `else if (typeof res === 'object') throw Error("test evaluated to object " + res);` [1](#0-0) 
- `toOscriptType(x)` / `toJsType(x)` throw bare `Error` for any value that doesn't match the expected internal representations, and are called from `map`/`reduce`/`filter` callbacks and state-var (de)serialization helpers with values that originate from getter/remote-AA call results and JSON round-tripping. [2](#0-1) 
- The `map`/`filter`/`reduce` implementation builds `retValue`/`accumulator` and calls remote getters via `callGetter`, then re-wraps results with `toOscriptType`/`toJsType`; if a getter or local function returns a value whose type doesn't fit the expected set (e.g. `undefined`, or a nested structure the wrapping code didn't anticipate), the process hits the `throw Error("unknown type in toOscriptType:" ...)` path rather than a graceful `setFatalError`. [3](#0-2) 

This class of bug mirrors the MJS issue: the interpreter assumes a JS-side value has a specific, previously-validated shape/type after passing through several transformation layers, and when that assumption is wrong it hits an unguarded fatal path instead of a recoverable error path.

The consequence in `ocore` is worse than in MJS's embedded use case, because `network.js` explicitly converts *any* uncaught exception (not just formula-evaluator crashes) into a full process crash: [4](#0-3) 
This means that any oscript expression which triggers one of the bare `throw Error(...)` statements in `evaluation.js` — reachable from unprivileged AA triggers processed via `aa_composer.js`'s `handleTrigger` / `handlePrimaryAATrigger` — will bring down the entire full node, not just fail the single AA response.

### Impact Explanation
A crash of the node process qualifies as "a network unable to confirm new units" under this program's impact bar, since the crashed node stops processing/validating/confirming any units until manually restarted. If exploitable across the majority/quorum of full nodes (any node executing the malicious AA's trigger, since AA execution is deterministic and mandatory for consensus), this can halt confirmation network-wide, which is a High/Medium-severity DoS depending on reach — matching the CVSS AV:L/AC:L/PR:N/UI:R profile of the original CVE mapped onto "any unit poster who can get an AA to execute their formula."

### Likelihood Explanation
An attacker only needs to post a unit that triggers an AA (or define an AA themselves) whose formula uses the affected constructs (`ifelse`, `map`/`filter`/`reduce` with a getter/remote call that returns malformed data). No special privilege beyond posting a valid unit is required. `formula/validation.js` performs syntactic/semantic pre-validation, but the specific runtime-only type violations (e.g. attempting to make `toOscriptType`/`toJsType` see a value shape it doesn't expect after getter round-trips) are not fully enumerable by the static validator, so some of these runtime `throw Error()` paths can plausibly be reached with a valid, validation-passing formula.

### Recommendation
Audit every bare `throw Error(...)` inside `formula/evaluation.js`'s `evaluate()`/`toOscriptType`/`toJsType`/`map`/`filter`/`reduce` code paths and replace them with the existing `setFatalError(...)` mechanism (which bounces the AA response instead of throwing) wherever the offending value can originate from trigger data, AA state, or getter/remote-AA return values. Additionally, consider hardening `process.on('uncaughtException', ...)` in `network.js` so that AA-evaluation errors specifically are isolated (e.g., wrapped so they cannot propagate as uncaught exceptions) rather than relying on formula code to never throw.

### Proof of Concept
Concrete exploitation requires crafting an oscript formula/getter combination that forces a value into one of the un-guarded `throw Error` branches (e.g., an `ifelse` test resolving to a plain JS object bypassing the `wrappedObject`/`isValidValue` checks, or a `map`/`reduce` callback whose getter result fails `toOscriptType`'s type switch). Full verification of a specific input reaching these branches at runtime (rather than being rejected earlier by `formula/validation.js`) requires dynamic testing/execution of the AA formula evaluator, which is outside the scope of static code review; this is flagged as unverified/uncertain and should be confirmed by a Devin session with test execution capability.

function toOscriptType(x) {
	if (typeof x === 'string' || typeof x === 'boolean' || x instanceof wrappedObject)
		return x;
	if (typeof x === 'number')
		return createDecimal(x);
	if (Decimal.isDecimal(x))
		return toDoubleRange(x);
	if (typeof x === 'object' && x !== null)
		return new wrappedObject(x);
	throw Error("unknown type in toOscriptType:" + x);
}

function toJsType(x) {
	if (x instanceof wrappedObject)
		return x.obj;
	if (Decimal.isDecimal(x))
		return x.toNumber();
	if (typeof x === 'string' || typeof x === 'boolean' || typeof x === 'number' || (typeof x === 'object' && x !== null))
		return x;
	throw Error("unknown type in toJsType:" + x);
}
