### Title
Cross-tenant webhook forgery: `full_name` owner is never checked against the signature-verifying `repository.owner.login`, letting an attacker mutate a victim's stack with their own org's `webhook_secret` - ([File: app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb])

### Summary
`WebhooksController#verify_signature` derives the signing organization solely from `params.dig('repository','owner','login')` (or `organization.login`) [1](#0-0) , and looks up the corresponding `GitHubApp`/`webhook_secret` via `Shipit.github(organization: repository_owner)` [2](#0-1) . `OpenedHandler` (and its siblings) never re-reads `repository.owner.login`; instead they resolve the target repository purely from `params.repository.full_name` via `Repository.from_github_repo_name`, which just splits the string on `/` and does a DB lookup with no ownership/App cross-check [3](#0-2) [4](#0-3) . Nothing in the code enforces `repository.owner.login == full_name.split('/').first`.

### Finding Description
Broken binding: the code implicitly assumes `params.dig('repository','owner','login') == params.dig('repository','full_name').split('/').first`, but this equality is never validated anywhere in the request path.

Path traced:
1. Attacker owns `attacker-org/some-repo`, configured in Shipit with its own `GitHubApp` and real `webhook_secret` (a legitimate, separately-onboarded org — this is plausible in any multi-tenant Shipit deployment using the `github_app_config(organization)` per-org secrets scheme [5](#0-4) ).
2. Attacker crafts a `pull_request` `opened` webhook JSON body where `repository.owner.login = "attacker-org"` and `repository.full_name = "victim-org/repo"` (a real, tracked victim repository). Nothing prevents these two fields being unrelated in a hand-crafted HTTP POST to `/webhooks`.
3. Attacker computes `X-Hub-Signature` using **their own** legitimate `webhook_secret` for `attacker-org` over the raw JSON body.
4. `verify_signature` computes `repository_owner = "attacker-org"`, fetches `Shipit.github(organization: "attacker-org")` [6](#0-5) , and `verify_webhook_signature` succeeds because it's checking the signature against `attacker-org`'s own real secret [7](#0-6) . Signature check passes.
5. `WebhooksController#create` dispatches to `OpenedHandler#call(params)` for the `pull_request` event [8](#0-7) .
6. `OpenedHandler#repository` calls `Shipit::Repository.from_github_repo_name(params.repository.full_name)` = `from_github_repo_name("victim-org/repo")`, which resolves the **real victim Repository record** regardless of who signed the payload [3](#0-2) .
7. `process` then calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!`, creating/mutating a review stack scoped to the victim repository using entirely attacker-controlled PR data (branch ref, sha, labels, PR number) [9](#0-8) .

Existing guards do not catch this: `verify_signature` only proves the payload was signed by *some* configured org's secret — it never proves that org owns the repository named in `full_name`. `drop_unhandled_event` and the `ExplicitParameters` schema only validate shape/presence of fields, not cross-field consistency between `repository.owner.login` and `repository.full_name`. `Repository.from_github_repo_name` performs no ownership/App binding check at all.

### Impact Explanation
An attacker with a legitimately onboarded (but otherwise unrelated) Shipit-tracked org/App/`webhook_secret` can forge `pull_request` (and by the same code pattern, `closed`, `labeled`, `unlabeled`, `reopened`, `assigned`, `edited` — all of which call `Repository.from_github_repo_name` off `full_name` in the same unguarded way) events for ANY other tracked repository, as long as they know its `owner/name` string (public info). This creates/mutates review stacks belonging to the victim repository, causing unauthorized provisioning behavior, unwanted git checkouts/deploys of attacker-chosen refs, and stack state corruption for a tenant the attacker never authenticated against — a cross-tenant webhook forgery matching "payload for one repository mutating another's stack." The blast radius spans every repository tracked by the Shipit instance, not just the attacker's own.

### Likelihood Explanation
Requires the Shipit deployment to run in the documented multi-org mode (`github_app_config` per-organization secrets) and requires the attacker to control at least one legitimately onboarded org (a realistic scenario for any GitHub App marketplace/multi-tenant Shipit setup where organizations self-register). The victim's `owner/name` is public. No Shipit session, API token, or victim secrets are needed — only the attacker's own real `webhook_secret`, which they legitimately possess. The forgery is trivially repeatable against arbitrary tracked repositories.

### Recommendation
In `WebhooksController#verify_signature` (or in a shared `Handler` pre-check), after verifying the signature, assert that `params.dig('repository','owner','login')` matches the owner segment of `params.dig('repository','full_name')` (case-insensitively) before processing; reject (422) on mismatch. Alternatively, have `Repository.from_github_repo_name` / each handler cross-check that the resolved `Repository#owner` equals the signature-verified `repository_owner` passed down from the controller, rather than trusting `full_name` alone.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb
test "pull_request payload with mismatched owner/full_name is rejected" do
  victim = shipit_repositories(:shipit) # owner: 'shopify', name: 'shipit-engine' (tracked)
  attacker_org = 'attacker-org'
  Shipit.stubs(:github).with(organization: attacker_org).returns(
    Shipit::GitHubApp.new(attacker_org, { webhook_secret: 'attacker-secret' })
  )

  body = {
    action: 'opened',
    number: 1,
    pull_request: { id: 1, number: 1, url: 'https://x', title: 't', state: 'open',
                     additions: 1, deletions: 0, head: { sha: 'abc', ref: 'feature' },
                     user: { login: 'attacker' }, assignees: [], labels: [] },
    repository: { full_name: victim.full_name, owner: { login: attacker_org } },
    sender: { login: 'attacker' }
  }.to_json

  signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', 'attacker-secret', body)

  @request.headers['X-Github-Event'] = 'pull_request'
  @request.headers['X-Hub-Signature'] = signature

  assert_no_difference -> { victim.review_stacks.count } do
    post :create, body:, as: :json
  end
  # Currently FAILS: signature verifies via attacker-org's real secret,
  # and Repository.from_github_repo_name(victim.full_name) resolves the real victim repo,
  # so a review stack IS created for the victim — demonstrating the vulnerability.
end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
