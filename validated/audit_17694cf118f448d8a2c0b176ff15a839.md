### Title
`ProxyType::NonTransfer` on the Polkadot/Rococo relay chain falsely claims to be a superset of `ProxyType::Auction`, letting a `NonTransfer` proxy add an `Auction` proxy and reach `Registrar::swap`, which its own filter explicitly denies - ([File: polkadot/runtime/rococo/src/lib.rs])

### Summary
`pallet_proxy::do_proxy` authorizes `add_proxy`/`remove_proxy` sub-calls solely via `ProxyType::is_superset`, without re-checking the target type's `filter` [1](#0-0) . On the Rococo (and Westend) relay-chain runtimes, `is_superset` declares `(ProxyType::NonTransfer, _) => true`, i.e. `NonTransfer` is claimed to dominate every other proxy type [2](#0-1) . However, `ProxyType::Auction`'s `filter` admits the *entire* `Registrar` pallet unrestricted (`RuntimeCall::Registrar { .. }`), while `NonTransfer`'s own filter explicitly enumerates only `register`, `deregister` and `reserve`, with a comment stating it deliberately omits `swap` [3](#0-2) [4](#0-3) . This is the exact same bug class that was already found and fixed for the `NonTransfer`/`Governance` pair on Asset Hub Westend in `prdoc/pr_12769.prdoc`, but it survives here on a different pair (`NonTransfer`/`Auction`) and on the relay-chain runtimes.

### Finding Description
`pallet_proxy` gates the ability of a proxy to grant itself a broader proxy through `is_superset`, not `filter`:

```rust
Some(Call::add_proxy { ref proxy_type, .. }) | Some(Call::remove_proxy { ref proxy_type, .. })
    if !def.proxy_type.is_superset(proxy_type) => false,
``` [5](#0-4) 

This means whenever `is_superset(A, B) == true`, an `A`-type proxy delegate is trusted to be able to add a `B`-type proxy for the delegator, and it is assumed that everything `B`'s filter admits is already covered by `A`'s filter. Rococo/Westend declare this relation with a blanket rule instead of verifying every pair:

```rust
fn is_superset(&self, o: &Self) -> bool {
    match (self, o) {
        (x, y) if x == y => true,
        (ProxyType::Any, _) => true,
        (_, ProxyType::Any) => false,
        (ProxyType::NonTransfer, _) => true,
        _ => false,
    }
}
``` [2](#0-1) 

But `Auction`'s filter is broader than `NonTransfer`'s for the `Registrar` pallet:

```rust
ProxyType::Auction => matches!(
    c,
    RuntimeCall::Auctions { .. } |
        RuntimeCall::Crowdloan { .. } |
        RuntimeCall::Registrar { .. } |   // unrestricted: includes `swap`
        RuntimeCall::Multisig(..) |
        RuntimeCall::Slots { .. }
),
``` [4](#0-3) 

versus `NonTransfer`, which deliberately omits `Registrar::swap`:

```rust
RuntimeCall::Registrar(paras_registrar::Call::register {..}) |
RuntimeCall::Registrar(paras_registrar::Call::deregister {..}) |
// Specifically omitting Registrar `swap`
RuntimeCall::Registrar(paras_registrar::Call::reserve {..}) |
``` [6](#0-5) 

The same pattern (blanket `(NonTransfer, _) => true` plus unrestricted `Auction => RuntimeCall::Registrar(..)`) exists on Westend as well [7](#0-6) .

`Registrar::swap` is authorized for `Root`, the para manager, or the parachain itself via `ensure_root_para_or_owner`:
```rust
pub fn swap(origin: OriginFor<T>, id: ParaId, other: ParaId) -> DispatchResult {
    Self::ensure_root_para_or_owner(origin, id)?;
    ...
}
``` [8](#0-7) 
`ensure_root_para_or_owner` succeeds for a `Signed` origin that is the para's manager account [9](#0-8) . When executed through `do_proxy`, the inner call is dispatched with `origin = Signed(real)` [10](#0-9) , i.e. as the delegator/manager themselves — so `swap` succeeds whenever `real` is the para manager, exactly the account the `NonTransfer` proxy holder is supposed to be constrained from using for `swap`.

Attack path:
1. Manager `real` grants an account `D` a `NonTransfer` proxy (a commonly-used, supposedly restrictive proxy type that explicitly excludes `swap`).
2. `D`, having no other privilege, calls `Proxy::proxy(real, None, Proxy::add_proxy{ delegate: D2, proxy_type: Auction, delay: 0 })`. Inside `do_proxy`, the filter checks `NonTransfer.is_superset(Auction)`, which returns `true`, so the `add_proxy` call is not filtered out and executes as `Signed(real)`, creating a new `Auction` proxy relationship `real -> D2` (D2 can be an account `D` controls, or `D` itself for a second proxy type).
3. `D` (via `D2`) now calls `Proxy::proxy(real, Some(Auction), Registrar::swap{ id, other })`. `Auction`'s filter admits the unrestricted `RuntimeCall::Registrar{..}` pattern, so `swap` is dispatched as `Signed(real)`.
4. `ensure_root_para_or_owner` passes because `real` is the actual para manager, and the swap of para lifecycle/auction-slot data executes — a capability the delegator never intended to grant to a `NonTransfer` proxy and which `NonTransfer`'s filter comment explicitly says is withheld.

### Impact Explanation
This lets an attacker who only holds a `NonTransfer` proxy (the least-privileged, "safe" delegation commonly used for day-to-day account operations) escalate to executing `Registrar::swap` on behalf of the real account. `swap` mutates parachain lifecycle/slot-auction state (swapping lease-holding/parathread status, auction deposits, and associated bookkeeping) for a `ParaId` the real account manages — a capability with real economic and governance consequences for a parachain operator, reachable purely by an unprivileged proxy delegate, without any theft of keys or validator/governance role. It mirrors exactly the class of bug already fixed for `NonTransfer`/`Governance` in `prdoc/pr_12769.prdoc`.

### Likelihood Explanation
Moderate/High: the only prerequisite is that the attacker already holds any `NonTransfer` proxy grant, which is a normal, widely-used, low-trust delegation pattern (not privileged/governance access). `add_proxy` and the follow-up `proxy` call are ordinary signed extrinsics with standard fees; no special conditions, race window, or governance control is required. The escalation chain requires the delegator's account to actually be a para manager, which narrows real-world exploitability to accounts that both grant a `NonTransfer` proxy and are registered para managers — a plausible but not universal precondition.

### Recommendation
Do not use a coarse blanket rule for `is_superset`. Either:
- Derive `is_superset` for each declared pair by verifying every call admitted by the subset type is also admitted by the superset type's `filter` (as was done for `NonTransfer`/`Governance` in `prdoc/pr_12769.prdoc`), and add the missing `Registrar::swap` exclusion consistency check for `Auction`, or
- Restrict `Auction`'s filter to the same explicit `Registrar` call subset that `NonTransfer` allows (`register`, `deregister`, `reserve`), removing the unrestricted `RuntimeCall::Registrar { .. }` match, or
- Remove `(ProxyType::NonTransfer, _) => true` and enumerate only the pairs that are provably sound, matching the safer, explicit-lattice style already used in `asset-hub-westend`'s `is_superset`.

Additionally, add a lattice-wide regression test analogous to `proxy_type_superset_relation_matches_call_filters` (already present for asset-hub-westend) to the Rococo/Westend relay-chain runtime test suites to prevent recurrence.

### Proof of Concept
No PoC was executed against a live network or existing test harness for this specific pair; this analysis is based on static code inspection of the filter/`is_superset` implementations and the `paras_registrar::swap` authorization logic cited above. A concrete integration reproduction would need to: (1) instantiate the Rococo/Westend runtime test externalities, (2) register a para and set its manager to account `real`, (3) grant `real -> D` a `NonTransfer` proxy, (4) have `D` call `proxy(real, None, add_proxy{D2, Auction, 0})` and assert it succeeds (currently expected per `is_superset`), (5) have `D2` call `proxy(real, Some(Auction), Registrar::swap{...})` and assert it dispatches successfully as `Signed(real)`, confirming `swap` executes despite `NonTransfer`'s filter denying it directly. This mirrors the reproduction pattern already used in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs::non_transfer_proxy_is_not_a_superset_of_governance` [11](#0-10) , but was not run against the relay-chain runtimes as part of this analysis; I was unable to execute it here.

#[test]
fn non_transfer_proxy_is_not_a_superset_of_governance() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// `NonTransfer` denies every governance call family that `Governance` admits, except `Utility`.
	for call in [
		RuntimeCall::Treasury(pallet_treasury::Call::void_spend { index: 0 }),
		RuntimeCall::ConvictionVoting(pallet_conviction_voting::Call::remove_vote {
			class: None,
			index: 0,
		}),
		RuntimeCall::Referenda(pallet_referenda::Call::refund_decision_deposit { index: 0 }),
		RuntimeCall::Whitelist(pallet_whitelist::Call::remove_whitelisted_call {
			call_hash: Default::default(),
		}),
	] {
		assert!(ProxyType::Governance.filter(&call), "Governance must admit {call:?}");
		assert!(!ProxyType::NonTransfer.filter(&call), "NonTransfer must deny {call:?}");
	}

	// So it must not declare itself a superset of it. This is what stops a `NonTransfer` proxy
	// from granting itself a `Governance` proxy: `pallet_proxy` gates `add_proxy`/`remove_proxy`
	// on `is_superset` before it ever consults `filter`, which by itself does not deny `Proxy`
	// calls.
	assert!(!ProxyType::NonTransfer.is_superset(&ProxyType::Governance));

	// The other declared `NonTransfer` subsets are unaffected.
	for subset in [
		ProxyType::Collator,
		ProxyType::Staking,
		ProxyType::NominationPools,
		ProxyType::StakingOperator,
	] {
		assert!(ProxyType::NonTransfer.is_superset(&subset));
	}
}
