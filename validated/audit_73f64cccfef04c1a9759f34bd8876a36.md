### Title
Reward-distribution work-per-block is unbounded because `get_reward_distribution_num_blocks` only clamps the number of partitions, not the accounts-per-partition, allowing attacker-inflated `total_stake_accounts` to force `store_stake_accounts_in_partition` to process arbitrarily large batches every epoch - (File: `runtime/src/bank/partitioned_epoch_rewards/mod.rs`)

### Summary
`get_reward_distribution_num_blocks` caps the *number* of reward-distribution blocks to at most `slots_per_epoch / 10`, but does not cap the *number of stake accounts processed per block*. Because `hash_rewards_into_partitions` spreads `total_stake_accounts` roughly evenly across the (clamped) `num_partitions` buckets, once `total_stake_accounts` grows past `partitioned_rewards_stake_account_stores_per_block * (slots_per_epoch/10)`, every partition/block during the entire distribution window must process far more than `partitioned_rewards_stake_account_stores_per_block` accounts, with no additional bound.

### Finding Description
`get_reward_distribution_num_blocks` computes: [1](#0-0) 
The `num_chunks` value (`total_stake_accounts.div_ceil(stake_account_stores_per_block)`) is meant to express "one block handles `stake_account_stores_per_block` accounts," but it is then clamped to `slots_per_epoch / 10`. The comment above the clamp explicitly says this bounds "the reward credit interval," i.e. only the block *count*, not the per-block *account count*.

`hash_rewards_into_partitions` then assigns every reward index into one of `num_partitions` buckets via hashing, roughly uniformly: [2](#0-1) 

Each block subsequently calls `store_stake_accounts_in_partition`, which iterates over the entire partition's index list with no size limit or further chunking: [3](#0-2) 

Because `num_partitions` is capped at a fixed value (`slots_per_epoch/10`) independent of `total_stake_accounts`, the average partition size is `total_stake_accounts / num_partitions_capped`, which grows linearly and unboundedly with `total_stake_accounts`. The intended per-block budget, `MAX_PARTITIONED_REWARDS_PER_BLOCK = 4096` (baseline for `partitioned_rewards_stake_account_stores_per_block`), is only respected while `total_stake_accounts <= stake_account_stores_per_block * (slots_per_epoch/10)`: [4](#0-3) 

An unprivileged attacker with sufficient capital can repeatedly issue `CreateAccount` (stake) + `DelegateStake` transactions, each funded only to `get_minimum_delegation` (1 SOL post-feature, or effectively negligible pre-feature) plus the stake rent-exempt reserve: [5](#0-4) 
This requires no elevated privilege, authority over other accounts, or validator control - only ordinary system/stake instructions naming self-owned accounts.

### Impact Explanation
Once `total_stake_accounts` (network-wide, inflated by the attacker's delegations) exceeds `stake_account_stores_per_block * (slots_per_epoch/10)`, every distribution block for the rest of that epoch (and every subsequent epoch, since the accounts remain delegated) must process a work-per-block count exceeding `partitioned_rewards_stake_account_stores_per_block` by a factor that grows with the attacker's account count, with no upper bound in the code. This matches the "epoch-boundary halt / cluster-wide stall" bounty category: all validators execute this identical, deterministic, consensus-critical code path (`distribute_partitioned_epoch_rewards` → `store_stake_accounts_in_partition`) every epoch, so the additional per-block cost is incurred network-wide, potentially exceeding the 400ms slot budget and stalling block production during the reward-distribution phase every epoch thereafter.

### Likelihood Explanation
Feasibility is gated purely by capital and time: the attacker must fund `M` stake accounts each at `get_minimum_delegation` + rent-exempt reserve, and issue `CreateAccount`+`DelegateStake` for each, which can be spread across many epochs to accumulate `M` incrementally (delegations persist once made). No special access, authority-bypass, or arithmetic-overflow guard exists that limits total delegation count. Once the attacker's cumulative delegated accounts push `total_stake_accounts` above the interval cap's implicit per-block budget, the stall recurs automatically every subsequent epoch as long as the accounts remain delegated - it is fully repeatable and does not require re-executing the attack each epoch.

### Recommendation
Bound the *actual number of accounts stored per block* independent of the interval cap - e.g., increase `num_partitions` without an upper clamp (or clamp the interval separately) so that each partition never exceeds `partitioned_rewards_stake_account_stores_per_block`, or explicitly rechunk within `store_stake_accounts_in_partition`/`distribute_epoch_rewards_in_partition` to process at most `partitioned_rewards_stake_account_stores_per_block` accounts per block even if that means extending the distribution phase further, and/or introduce a protocol-level cap on total stake-account count or minimum delegation size to bound `total_stake_accounts` growth.

### Proof of Concept
Rust unit test extending the existing `get_reward_distribution_num_blocks` test suite (`runtime/src/bank/partitioned_epoch_rewards/mod.rs`):
```rust
#[test]
fn test_reward_distribution_work_per_block_unbounded() {
    // Use small epoch and small stake_account_stores_per_block to make the effect visible in a unit test.
    let (mut genesis_config, _mint_keypair) = create_genesis_config(1_000_000 * LAMPORTS_PER_SOL);
    genesis_config.epoch_schedule = EpochSchedule::custom(1000, 1000, false);
    let mut accounts_db_config: AccountsDbConfig = ACCOUNTS_DB_CONFIG_FOR_TESTING;
    let stake_account_stores_per_block = 10;
    accounts_db_config.partitioned_epoch_rewards_config =
        PartitionedEpochRewardsConfig::new_for_test(stake_account_stores_per_block);

    let bank = Bank::new_from_genesis(
        &genesis_config, Arc::new(RuntimeConfig::default()), Vec::new(), None,
        accounts_db_config, None, Some(SlotLeader::new_unique()), Arc::default(), None, None,
    );

    // Interval cap = slots_per_epoch / 10 = 100 blocks.
    let max_blocks = genesis_config.epoch_schedule.slots_per_epoch / 10;

    // Fuzz M far beyond stake_account_stores_per_block * max_blocks (= 1000).
    for m in [1_000u64, 10_000, 1_000_000] {
        let stake_rewards = (0..m)
            .map(|_| Some(PartitionedStakeReward::new_random()))
            .collect::<PartitionedStakeRewards>();
        let num_partitions = bank.get_reward_distribution_num_blocks(&stake_rewards);
        assert!(num_partitions <= max_blocks, "interval bound respected");

        // Expected average work per block, given the interval cap does NOT bound per-block work.
        let avg_accounts_per_block = m / num_partitions;
        // Assertion that SHOULD hold for a correctly bounded system but currently fails
        // as M grows: per-block work stays within a fixed multiple of the configured budget.
        assert!(
            avg_accounts_per_block <= stake_account_stores_per_block * 2,
            "per-block work ({avg_accounts_per_block}) exceeds bounded budget \
             ({stake_account_stores_per_block}) for M={m}: interval cap does not bound work-per-block"
        );
    }
}
```
Expected result: the assertion fails for large `m` (e.g., `m = 1_000_000`), demonstrating that `avg_accounts_per_block` grows unboundedly with `M` even though `num_partitions` stays capped at `max_blocks`, confirming that `store_stake_accounts_in_partition` will process unbounded work per block once total delegated stake accounts exceed `stake_account_stores_per_block * (slots_per_epoch/10)`.

    /// Calculate the number of blocks required to distribute rewards to all stake accounts.
    pub(super) fn get_reward_distribution_num_blocks(
        &self,
        rewards: &PartitionedStakeRewards,
    ) -> u64 {
        let total_stake_accounts = rewards.num_rewards();
        if self.epoch_schedule.warmup && self.epoch < self.first_normal_epoch() {
            1
        } else {
            const MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH: u64 = 10;
            let num_chunks = total_stake_accounts
                .div_ceil(self.partitioned_rewards_stake_account_stores_per_block() as usize)
                as u64;

            // Limit the reward credit interval to 10% of the total number of slots in a epoch
            num_chunks.clamp(
                1,
                (self.epoch_schedule.slots_per_epoch / MAX_FACTOR_OF_REWARD_BLOCKS_IN_EPOCH).max(1),
            )
        }
    }

pub(in crate::bank::partitioned_epoch_rewards) fn hash_rewards_into_partitions(
    stake_rewards: &PartitionedStakeRewards,
    parent_blockhash: &Hash,
    num_partitions: usize,
) -> Vec<Vec<usize>> {
    let hasher = EpochRewardsHasher::new(num_partitions, parent_blockhash);
    let mut indices = vec![vec![]; num_partitions];

    for (i, reward) in stake_rewards.enumerated_rewards_iter() {
        // clone here so the hasher's state is reused on each call to `hash_address_to_partition`.
        // This prevents us from re-hashing the seed each time.
        // The clone is explicit (as opposed to an implicit copy) so it is clear this is intended.
        let partition_index = hasher
            .clone()
            .hash_address_to_partition(&reward.stake_pubkey);
        indices[partition_index].push(i);
    }
    indices
}

    fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );

//! Code related to partitioned rewards distribution

/// Baseline number of stake accounts to store in one 400ms block during the
/// partitioned reward interval.
///
/// The target is 64 rewards per entry/tick. A block has a minimum of 64
/// entries/ticks, giving 4096 total rewards to store in one 400ms block. This
/// constant affects consensus; shorter slot-time targets scale this value down
/// in `Bank` state.
pub const MAX_PARTITIONED_REWARDS_PER_BLOCK: u64 = 4096;

/// Configuration options for partitioned epoch rewards.
#[derive(Debug, Clone, Copy)]
pub struct PartitionedEpochRewardsConfig {
    /// Baseline number of stake accounts to store in one block during the
    /// partitioned reward interval.
    ///
    /// This value is stored as the 400ms-slot baseline. Runtime `Bank` state
    /// derives the effective per-bank value from the active slot-time target.
    pub stake_account_stores_per_block: u64,
}
