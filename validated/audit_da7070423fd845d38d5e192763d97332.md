### Title
Revoked/rotated git credentials remain valid and continue to authenticate sync operations for up to 1 hour due to unconditional `credential.helper=cache --timeout 3600` — ([File: main.go])

### Summary
`git-sync` unconditionally configures git's `credential-cache` helper with a fixed one-hour timeout, and its credential-refresh path (`refreshCreds`) only ever *adds* new credentials via `git credential approve`; it never calls `git credential reject` or otherwise evicts a credential from the cache when that credential becomes invalid/revoked. This mirrors the Telcoin finding's root cause: a security control ("blacklist"/revocation) exists at the source of truth, but the consuming component keeps using the previously accepted, now-invalid, credential to keep "transacting" (fetching/authenticating against the remote) until the cache naturally expires.

### Finding Description
`SetupDefaultGitConfigs` unconditionally sets the git credential helper to a 1-hour cache, with no way to disable or shorten it via flags: [1](#0-0) 

Credentials are populated/refreshed once per sync period by `refreshCreds`, which calls `git.StoreCredentials` (static `--credential` entries), `git.CallAskPassURL` (dynamic auth-URL credentials), and `git.RefreshGitHubAppToken` (GitHub App tokens): [2](#0-1) 

`StoreCredentials` always performs `git credential approve`, which only stores/refreshes a credential in the cache — there is no corresponding `git credential reject` call anywhere in the codebase to invalidate a previously cached credential: [3](#0-2) 

`CallAskPassURL` re-fetches credentials from the operator-controlled askpass endpoint each cycle, but if that endpoint starts returning a non-200 (e.g., because the credential/service-account was just revoked or "blacklisted"), the function simply returns an error — it does not clear or reject the credential that was cached from a prior, successful call: [4](#0-3) 

Because `git credential-cache` is a separate daemon process keyed by host/protocol and is populated only through `approve`, the last-approved credential (username/password or GitHub App installation token) for a given host remains usable by any git operation on that host for the full `--timeout 3600` window, independent of whether the upstream authority that issued/approved it has since revoked or rotated it. This is the direct analog of the Telcoin bug: revocation ("blacklisting") of an authorization credential does not stop the already-approved credential from being used to keep "transacting" (i.e., fetching) until the cache times out.

### Impact Explanation
If an operator revokes a `--askpass-url`-issued credential, a GitHub App installation, or rotates a `--credential`/`--password-file` secret in response to a suspected compromise, `git-sync` (and the underlying git credential-cache daemon it configures) will continue to authenticate fetches against the remote using the stale, revoked credential for up to one hour after revocation. This is a persistence-of-access issue: a credential that should be dead continues to work, undermining the ability to promptly cut off a compromised or de-authorized sync process, and it can result in continued (unauthorized) polling/fetching from a repository the operator believed had been locked out.

### Likelihood Explanation
This triggers under the normal, unprivileged operation of `git-sync`: no special flags are needed to enable the credential cache (it is set unconditionally in `SetupDefaultGitConfigs`), and any deployment using `--askpass-url`, `--credential`, `--username`/`--password-file`, or GitHub App auth is affected. The only requirement is that a previously-approved credential is later revoked upstream while `git-sync` keeps running — a realistic operational scenario (key rotation, incident response, decommissioning access).

### Recommendation
- Make the credential-cache timeout configurable and default it much lower, or use `git credential-cache exit`/`git credential reject` to explicitly evict a credential entry whenever `CallAskPassURL`, `StoreCredentials`, or `RefreshGitHubAppToken` detects that the previous credential is no longer valid (e.g., before storing a new one, or when an auth attempt using the cached credential fails with 401/403).
- Consider using a non-persistent credential store (e.g., pass credentials directly per-invocation rather than through `credential-cache`) so that there is no window during which a de-authorized credential remains usable.

### Proof of Concept
1. Deploy `git-sync` with `--askpass-url` pointing at a controllable credential service returning `username=u`/`password=p1` for host `H`.
2. Let `git-sync` complete a sync — this results in `git credential approve` populating the `git credential-cache` daemon for host `H` with `p1` (per `SetupDefaultGitConfigs`, cache timeout 3600s).
3. At the askpass endpoint, revoke `p1` (return e.g. HTTP 500 or an unrelated/incorrect credential) to simulate "blacklisting" the credential upstream.
4. Observe that `refreshCreds`/`CallAskPassURL` now fails on subsequent cycles (returned error, metric `metricAskpassCount` incremented as error) as shown in `main.go:998-1006`, but git-sync does not call `git credential reject`.
5. Within the 3600s window, an internal git fetch that hits the cache directly (e.g., a submodule fetch or any git invocation against host `H` that consults `credential-cache` before consulting askpass) will still authenticate successfully with the old `p1`, proving that the revoked credential is still usable until the cache naturally times out.

func (git *repoSync) StoreCredentials(ctx context.Context, url, username, password string) error {
	git.log.V(1).Info("storing git credential", "url", redactURL(url))
	git.log.V(9).Info("md5 of credential", "url", url, "username", md5sum(username), "password", md5sum(password))

	creds := fmt.Sprintf("url=%v\nusername=%v\npassword=%v\n", url, username, password)
	_, _, err := git.RunWithStdin(ctx, "", creds, "credential", "approve")
	if err != nil {
		return fmt.Errorf("can't configure git credentials: %w", err)
	}

	return nil
}

func (git *repoSync) CallAskPassURL(ctx context.Context) error {
	git.log.V(3).Info("calling auth URL to get credentials")

	var netClient = &http.Client{
		Timeout: time.Second * 1,
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	httpReq, err := http.NewRequestWithContext(ctx, http.MethodGet, git.authURL, nil)
	if err != nil {
		return fmt.Errorf("can't create auth request: %w", err)
	}
	resp, err := netClient.Do(httpReq)
	if err != nil {
		return fmt.Errorf("can't access auth URL: %w", err)
	}
	defer func() {
		_ = resp.Body.Close()
	}()
	if resp.StatusCode != http.StatusOK {
		errMessage, err := io.ReadAll(resp.Body)
		if err != nil {
			return fmt.Errorf("auth URL returned status %d, failed to read body: %w", resp.StatusCode, err)
		}
		return fmt.Errorf("auth URL returned status %d, body: %q", resp.StatusCode, string(errMessage))
	}
	authData, err := io.ReadAll(resp.Body)
	if err != nil {
		return fmt.Errorf("can't read auth response: %w", err)
	}

	username := ""
	password := ""
	for line := range strings.SplitSeq(string(authData), "\n") {
		keyValues := strings.SplitN(line, "=", 2)
		if len(keyValues) != 2 {
			continue
		}
		switch keyValues[0] {
		case "username":
			username = keyValues[1]
		case "password":
			password = keyValues[1]
		}
	}

	if err := git.StoreCredentials(ctx, git.repo, username, password); err != nil {
		return err
	}

	return nil
}

// SetupDefaultGitConfigs configures the global git environment with some
// default settings that we need.
func (git *repoSync) SetupDefaultGitConfigs(ctx context.Context) error {
	configs := []keyVal{{
		// Never auto-detach GC runs.
		key: "gc.autoDetach",
		val: "false",
	}, {
		// Fairly aggressive GC.
		key: "gc.pruneExpire",
		val: "now",
	}, {
		// How to manage credentials (for those modes that need it).
		key: "credential.helper",
		val: "cache --timeout 3600",
	}, {
		// Never prompt for a password.
		key: "core.askPass",
		val: "true",
	}}

	for _, kv := range configs {
		if _, _, err := git.Run(ctx, "", "config", "--global", kv.key, kv.val); err != nil {
			return fmt.Errorf("error configuring git %q %q: %w", kv.key, kv.val, err)
		}
	}
	return nil
}
