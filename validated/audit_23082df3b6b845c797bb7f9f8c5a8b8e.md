### Title
Zero-debt `repay` refunds an unfunded “overpayment” out of pool custody - (File: contracts/pool/src/ops/repay.rs)

### Summary
The pool `repay` leg treats any declared amount above current debt as `overpayment` and sends it back with `transfer_out`, but that refund is not debited from `cash` and is not checked against reserves. On a market with no outstanding debt, the entire declared amount becomes refundable even though nothing was transferred in, so a caller can make the pool pay out real custody while the cash book remains unchanged.

### Finding Description
`repay::apply` first runs `accounting`, then unconditionally sends `outcome.overpayment` to `payer` via `outcome.cache.transfer_out(payer, outcome.overpayment)`. [1](#0-0)  In `accounting`, `resolve_repay` splits `action.amount` into burned debt and `overpayment`; only `net_repay = amount - overpayment` is credited to cash before `commit()`. [2](#0-1)  When `current_debt_ceil` is zero, the full-close branch makes `net_repay == 0` and the whole declared amount is `overpayment`; the `RepayRoundsToZeroShares` guard still passes because of its `net_repay == 0` disjunct. [3](#0-2)  The pinned test calls `repay` with no inbound transfer on a zero-debt market and shows the refund drains custody while the book stays in sync. [4](#0-3) 

### Impact Explanation
This is theft of user funds from pool custody. A payer can declare a repay amount equal to the pool’s token balance on a market with zero debt, receive the entire amount back as an “overpayment,” and leave `cash`, `borrowed`, and supplier shares untouched. Repeating or sizing to available liquidity drains the pool backing suppliers, creating insolvency rather than merely misaccounting.

### Likelihood Explanation
Likelihood is high if the pool `repay` entrypoint is reachable by an unprivileged payer in the deployed auth model, because it needs no position, no collateral, no oracle state, and no prior transfer: only a zero-debt market and a declared amount bounded by custody. If the deployment enforces controller-only access to this leg, the same code path is still the weak point to audit because funded controller flows rely on the pool never paying an unfunded refund; the pool test explicitly demonstrates the unfunded refund behavior at the pool layer. [3](#0-2) 

### Recommendation
Require every refund to be backed by an actual measured inbound receipt in the same call. In `repay`, compute `overpayment` from `min(received, amount) - applied_debt` or move `transfer_out` behind a check that the pool received at least `amount` during the call; alternatively debit `cash` for any outbound refund and run `require_reserves` after all token movements. Apply the same rule to `recapitalize`, which the pool tests describe as sharing the same declared-amount refund gap. [5](#0-4)  Add a regression asserting that `repay` on a zero-debt market with no inbound transfer leaves custody unchanged.

### Proof of Concept
1. List or use a market whose pool holds token balance `B` and whose total debt is `0`.
2. From an unprivileged payer address with no inbound token transfer, call the pool `repay` leg with `action.amount = B` for that market.
3. `resolve_repay` sees `current_debt_ceil == 0`, takes the full-close branch, returns `net_repay = 0` and `overpayment = B`.
4. `accounting` burns no shares, credits `0` to cash, commits the unchanged book, and returns `overpayment = B`. [6](#0-5) 
5. `apply` executes `transfer_out(payer, B)`, paying the full balance from custody. The repository’s own test documents this end state: credited amount is `0`, but the unfunded refund drains custody. [7](#0-6)

```rust
pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow));
    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
```

```rust
fn test_unfunded_repay_overpayment_refund_also_pays_out_of_custody() {
    let t = TestSetup::new();
    let token = token::Client::new(&t.env, &t.asset);
    let payer = Address::generate(&t.env);

    let custody_before = token.balance(&t.pool);
    let before = t.state_snapshot();
    assert_eq!(
        before.cash, custody_before,
        "fixture guard: book and custody must start in sync"
    );
    assert_eq!(before.borrowed, 0, "fixture must carry no debt");

    // Nothing transferred in, no debt to retire: the whole amount is "excess".
    let credited = t
        .client()
        .repay(&payer, &t.ract(0, custody_before))
        .get_unchecked(0)
        .actual_amount;
    assert_eq!(credited, 0, "no debt was retired, so nothing is credited");
    assert_unfunded_refund_drained_custody(&t, &payer, custody_before, &before);
}
```
