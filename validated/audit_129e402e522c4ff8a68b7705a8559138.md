### Title
Webhook signature verified against `repository.owner.login`-derived org while `PullRequest` handlers key off unrelated `repository.full_name`, letting a signature valid for ORG_A create a `ReviewStack` under ORG_B's repository - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the HMAC secret to check using `params.dig('repository','owner','login')`, while `OpenedHandler#repository` (and every other `pull_request` handler) resolves the target `Repository` from the unrelated `params.repository.full_name` field via `Repository.from_github_repo_name`. Nothing in the code cross-checks that these two independently-attacker-suppliable JSON fields refer to the same repository/organization, so a request correctly signed with ORG_A's webhook secret but carrying `repository.full_name = "ORG_B/repo"` passes verification yet operates on ORG_B's tracked `Repository`.

### Finding Description
Broken binding as an equality: `organization_that_verified_signature (derived from params['repository']['owner']['login'])` == `organization_owning_the_Repository_record_mutated (derived from params['repository']['full_name'])`. This equality is **not enforced** anywhere in the code, since the two lookups read two different, independently attacker-controlled JSON keys from the raw POST body.

Code path:
1. `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`), then calls `Shipit.github(organization: repository_owner)` and verifies the `X-Hub-Signature` HMAC against that organization's `webhook_secret`. [1](#0-0) 
2. If verification passes, `WebhooksController#create` dispatches the raw JSON to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` — the same parsed `params` hash, unmodified. [2](#0-1) 
3. `OpenedHandler#repository` independently parses `params.repository.full_name` and looks up `Shipit::Repository.from_github_repo_name(...)`, which merely splits `"owner/name"` and does a DB `find_by(owner:, name:)` with no relation back to `repository.owner.login`. [3](#0-2) [4](#0-3) 
4. If that repository has `review_stacks_enabled` and `provisioning_behavior_allow_all?`, `OpenedHandler#process` calls `ReviewStackAdapter.new(params, scope: repository.review_stacks).find_or_create!`, which creates a `ReviewStack` using attacker-controlled `pull_request.head.ref` (branch) and `environment` (`"pr#{params.number}"`). [5](#0-4) [6](#0-5) 

Attacker's exact request: a directly crafted HTTP `POST /webhooks` body (not a GitHub-delivered payload) where `repository.owner.login = "ORG_A"` (matching the org whose secret the attacker legitimately controls, e.g. their own tenant's GitHub App in a multi-org Shipit deployment as shown by the multi-org secrets format) and `repository.full_name = "ORG_B/repo"`. The `X-Hub-Signature` header is a valid HMAC-SHA1 of the raw body computed with ORG_A's real `webhook_secret`.

Existing guards do not catch this: `verify_signature` only checks the HMAC against whichever org's secret `repository_owner` happens to name — it never checks that `full_name`'s owner segment agrees with `owner.login`. `drop_unhandled_event` and the `ExplicitParameters` schema only validate presence/types of `repository.full_name` as a `String`, not its relationship to `owner.login`. `Repository.from_github_repo_name` and `Repository` validations only constrain characters/length of `owner`/`name`, not cross-organization consistency. [7](#0-6) [8](#0-7) 

### Impact Explanation
An attacker who legitimately controls one Shipit-integrated organization (ORG_A) in a shared, multi-tenant Shipit instance can create a `ReviewStack` row (and trigger its provisioning/deploy pipeline via `ReviewStackProvisioningQueue.add`) under any other tenant's tracked `Repository` (ORG_B), fully choosing the `branch` and `environment` values. This is a cross-tenant write that bypasses the intended per-organization isolation enforced by webhook signatures, matching the "payload for one repository mutating another's stack" Critical category. The action is repeatable against any `Repository` row with `review_stacks_enabled` + `provisioning_behavior_allow_all?` (or matching label conditions) across any organization tracked by the same Shipit instance, since nothing scopes the created record back to the signing organization.

### Likelihood Explanation
Requires: (a) a multi-organization Shipit deployment (per `config/secrets.yml` multi-org format) where the attacker legitimately administers one tenant/org (ORG_A) and thus can produce a validly-signed arbitrary raw body using ORG_A's own `webhook_secret`; (b) a target `Repository` for ORG_B already tracked in Shipit with `review_stacks_enabled` and a provisioning behavior that would admit the crafted PR (`allow_all`, or `allow_with_label`/`prevent_with_label` satisfied via attacker-controlled label list in the same payload). Given those preconditions the exploit is a single crafted HTTP POST, fully deterministic and repeatable.

### Recommendation
In `WebhooksController#verify_signature` (or in each handler's `repository` resolution), enforce that the organization used to verify the signature is the same organization that owns the `Repository` being mutated — e.g., derive `repository_owner` from the same field the handlers use (`repository.full_name`'s owner segment) rather than `repository.owner.login`/`organization.login`, or explicitly assert `params.dig('repository','owner','login').casecmp(full_name_owner) == 0` before dispatching to handlers, rejecting mismatches with 422.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_cross_org_test.rb
require 'test_helper'

module Shipit
  class WebhooksControllerCrossOrgTest < ActionController::TestCase
    tests WebhooksController

    setup do
      # ORG_B's tracked repository, review-stack provisioning open to all PRs
      @victim_repo = shipit_repositories(:shipit) # owner: e.g. "org_b"
      @victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)
    end

    test "signature valid for ORG_A must not create a ReviewStack under ORG_B's repository" do
      request.headers['X-Github-Event'] = 'pull_request'

      payload = JSON.parse(payload(:pull_request_opened))
      payload['repository']['owner']['login'] = 'org_a'          # signed org
      payload['repository']['full_name'] = @victim_repo.github_repo_name # "org_b/repo" (victim)
      body = payload.to_json

      signature = 'sha1=' + OpenSSL::HMAC.hexdigest('sha1', org_a_webhook_secret, body)
      request.headers['X-Hub-Signature'] = signature

      # binding under test: signing_org ('org_a') == owning_org_of_mutated_repository ('org_b') ?
      assert_no_difference -> { @victim_repo.review_stacks.count } do
        post :create, body: body, as: :json
      end
    end
  end
end
```
This test asserts the equality `signing_org == owning_org_of_mutated_repository` must hold (no `ReviewStack` created for ORG_B when signed by ORG_A); as written today the code creates the row, so the assertion fails, demonstrating the break.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
