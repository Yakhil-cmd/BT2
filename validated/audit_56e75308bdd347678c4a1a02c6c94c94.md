### Title
Terminal escape sequence injection via unsanitized attestation subject names in `gh release verify` - (File: pkg/cmd/release/verify/verify.go)

### Summary
`printVerifiedSubjects` in `pkg/cmd/release/verify/verify.go` prints the `Name` field of each `in-toto` statement `Subject` directly into a table via `table.AddField(name)` without passing it through the codebase's established `iostreams.Untrusted` sanitization wrapper, unlike other call sites in the same codebase (e.g. `pkg/cmd/skills/list/list.go`'s `sanitizeForTerminal`) that explicitly strip terminal control sequences from externally-sourced strings before display.

### Finding Description
`verifyRun` calls `printVerifiedSubjects(io, verified)` [1](#0-0) , which unmarshals the DSSE envelope payload into an in-toto `v1.Statement` and iterates `statementData.Subject`, taking `s.Name` and writing it straight into a `tableprinter.TablePrinter` field: [2](#0-1) 

The subject name for a release-predicate attestation originates from the artifact/asset name associated with the release on GitHub — data that is populated based on how the release/asset was created, not from a value that is cryptographically bound to be free of control characters. Nothing between `protojson.Unmarshal` and `table.AddField(name)` strips ANSI/OSC/C0 control sequences. Compare this to `internal/tableprinter`, which contains no ANSI-stripping logic itself [3](#0-2) , and to the codebase's own documented mitigation pattern for exactly this kind of externally-authored content: the `iostreams.Untrusted` type, whose doc comment states "HTTP response bodies, file contents fetched from a remote, anything that originates outside the CLI" should be wrapped so that `fmt` print paths sanitize automatically [4](#0-3) . Other display code in this same codebase applies exactly this kind of sanitization to externally-sourced strings before adding them as table fields (e.g. `sanitizeForTerminal` in `pkg/cmd/skills/list/list.go`) [5](#0-4) , and the repo has an explicit acceptance test asserting that raw ESC bytes from attacker-influenced text must never reach the terminal [6](#0-5) . `printVerifiedSubjects` has no equivalent guard.

However, I was not able to confirm within the available index whether GitHub's release-asset-attestation subject `Name` field can actually contain raw control bytes (e.g., whether GitHub's asset upload API enforces a restrictive filename charset that would prevent ESC/OSC bytes from ever appearing in this field). That server-side constraint, if present, would be the actual mitigating control, and no such validation exists in this client-side code path. Without confirming that GitHub's release asset naming API permits arbitrary bytes (including ESC 0x1B), I cannot fully validate that this path is reachable end-to-end by an unprivileged attacker using ordinary `gh release verify` usage against a victim who runs it on the attacker's own repo/release.

### Impact Explanation
If the subject `Name` can carry raw terminal escape sequences, `gh release verify` would render attacker-chosen OSC 8 hyperlinks, terminal title-set/report sequences, or bracketed-paste-break sequences to the victim's terminal. Depending on the victim's terminal emulator, this can range from terminal spoofing/phishing (OSC 8 masking a malicious URL) up to command execution if the terminal auto-executes reported/echoed content (classic "terminal escape sequence RCE" chains documented for some emulators). This would match a GitHub bounty "RCE in gh" / Immunefi "arbitrary code execution" class if the control-character injection is confirmed reachable.

### Likelihood Explanation
Preconditions: the victim must run `gh release verify` (or `gh release verify-asset`, which shares the same unsanitized pattern in `verifyAssetRun`, though that path doesn't print subject names) against a repository/release controlled or influenced by the attacker, and the attacker must be able to get a control-character-bearing string into the asset name field of a `release`-predicate-type attestation subject. The latter is the key unverified assumption — GitHub release asset filenames are typically constrained (sanitized) server-side, which would make this unreachable in practice. Without confirming that constraint is absent, likelihood cannot be assessed as more than speculative.

### Recommendation
Regardless of whether GitHub currently restricts asset filenames, defense-in-depth requires wrapping `s.Name`/`digestStr` in `iostreams.NewUntrusted(...)` (or applying the same `sanitizeForTerminal`-style ASCII sanitizer used in `pkg/cmd/skills/list/list.go`) before calling `table.AddField`, consistent with how the rest of the codebase treats externally-authored content.

// IsTTY gets whether the TablePrinter will render to a terminal.
func (t *TablePrinter) IsTTY() bool {
	return t.isTTY
}

// AddTimeField in TTY mode displays the fuzzy time difference between now and t.
// In non-TTY mode it just displays t with the time.RFC3339 format.
func (tp *TablePrinter) AddTimeField(now, t time.Time, c func(string) string) {
	var tf string
	if tp.isTTY {
		tf = text.FuzzyAgo(now, t)
	} else {
		tf = t.Format(time.RFC3339)
	}
	tp.AddField(tf, WithColor(c))
}

var (
	WithColor    = tableprinter.WithColor
	WithPadding  = tableprinter.WithPadding
	WithTruncate = tableprinter.WithTruncate
)

func renderTable(io *iostreams.IOStreams, skills []listedSkill) error {
	table := tableprinter.New(io, tableprinter.WithHeader("Name", "Agent", "Scope", "Source"))

	for _, skill := range skills {
		table.AddField(sanitizeForTerminal(skill.skillName))
		table.AddField(formatAgentHosts(skill.agentHostIDs))
		table.AddField(displayOrDash(skill.scope))
		table.AddField(displayOrDash(sanitizeForTerminal(skill.source)))
		table.EndRow()
	}

	return table.Render()
}

// sanitizeForTerminal replaces ASCII control characters in s with inert
// caret-style stand-ins so frontmatter values cannot inject terminal escapes.
func sanitizeForTerminal(s string) string {
	var buf bytes.Buffer
	r := transform.NewReader(bytes.NewReader([]byte(s)), &asciisanitizer.Sanitizer{})
	if _, err := io.Copy(&buf, r); err != nil {
		return "Unknown"
	}
	return buf.String()
}
