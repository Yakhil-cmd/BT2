The Frappe CVE describes a REST API failing to re-check permissions on linked DocType records accessed via dot-notation field selection — a bug class specific to a document-oriented ORM with per-record read ACLs. Polkadot SDK's on-chain storage has no analogous concept: all runtime storage is intentionally public and transparent, and RPC storage queries (`state_getStorage`, `state_queryStorage`, `chainHead_v1_storage`, etc.) are gated only by node-level `DenyUnsafe`/RPC-safety policy [1](#0-0) , not by any per-account or per-record authorization model, since there is no "read permission" boundary to bypass in the first place [2](#0-1) . Similarly, FRAME pallets like `pallet-nfts` enforce write/mutation permissions (owner/role checks) on specific extrinsics [3](#0-2)  but expose no REST-style API that assembles "linked" cross-record reads requiring re-validated read authorization. No demonstrable analog with attacker-controlled entry, missing check, and measurable state/integrity impact exists in this codebase.

/// Checks if the RPC call is safe to be called externally.
pub fn check_if_safe(ext: &jsonrpsee::Extensions) -> Result<(), UnsafeRpcError> {
	match ext.get::<DenyUnsafe>().map(|deny_unsafe| deny_unsafe.check_if_safe()) {
		Some(Ok(())) => Ok(()),
		Some(Err(e)) => Err(e),
		None => unreachable!("DenyUnsafe extension is always set by the substrate rpc server; qed"),
	}
}

/// Signifies whether a potentially unsafe RPC should be denied.
#[derive(Clone, Copy, Debug)]
pub enum DenyUnsafe {
	/// Denies only potentially unsafe RPCs.
	Yes,
	/// Allows calling every RPCs.
	No,
}

impl DenyUnsafe {
	/// Returns `Ok(())` if the RPCs considered unsafe are safe to call,
	/// otherwise returns `Err(UnsafeRpcError)`.
	pub fn check_if_safe(self) -> Result<(), UnsafeRpcError> {
		match self {
			DenyUnsafe::Yes => Err(UnsafeRpcError),
			DenyUnsafe::No => Ok(()),
