### Title
Unvalidated P2P Staking Info Delivery Allows Malicious Peer to Corrupt Reward Distribution — (`datasync/downloader/queue.go`)

---

### Summary

During fast sync, staking information received from peers is accepted and persisted to the local database without any content validation. The `validate` callback inside `queue.DeliverStakingInfos` is an explicit no-op, marked with a `TODO`. A malicious peer can respond to staking-info requests with fabricated `RewardAddrs` or `StakingAmounts` for any block being synced. Because `GetStakingInfo` trusts the database over the live state for pre-Kaia blocks, the poisoned data is later consumed by `FinalizeState` to distribute block rewards, redirecting KAIA to attacker-controlled addresses.

---

### Finding Description

`queue.DeliverStakingInfos` in `datasync/downloader/queue.go` is the delivery endpoint for staking info fetched from peers during fast sync. Its `validate` callback — which receives the matching block header and therefore has everything needed to re-derive the correct staking info — unconditionally returns `nil`:

```go
validate := func(index int, header *types.Header) error {
    // TODO-Kaia-Snapsync update validation logic
    return nil
}
``` [1](#0-0) 

The peer-supplied `P2PStakingInfo` (containing `CouncilRewardAddrs`, `CouncilStakingAmounts`, `CouncilNodeAddrs`) is written directly to the database via `PutStakingInfoToDB` with no cryptographic or state-derived check. [2](#0-1) 

`GetStakingInfo` for pre-Kaia blocks checks the database **first** and returns immediately on a hit, never falling back to the live state:

```go
if !isKaia {
    if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
        s.stakingInfoCache.Add(sourceNum, si)
        return si, nil   // ← poisoned DB entry returned here
    }
}
// Read from the state  ← never reached if DB hit
``` [3](#0-2) 

`FinalizeState` calls `GetDeferredReward`, which calls `GetStakingInfo`, and then calls `state.AddBalance(addr, amount)` for each address in the returned `RewardAddrs`: [4](#0-3) 

If `RewardAddrs` was replaced by the attacker, KAIA minted for that block is credited to attacker-controlled addresses.

---

### Impact Explanation

| Protected value | Corruption |
|---|---|
| KAIA block reward distribution | Redirected to attacker-controlled `RewardAddrs` |
| Validator staking amounts | Falsified `StakingAmounts` distort proposer-selection weights |
| KEF / KIF treasury addresses | Can be replaced, diverting treasury allocations |

The poisoned database entry persists after fast sync completes. Every subsequent call to `GetStakingInfo` for the affected pre-Kaia source block returns the attacker's data, affecting all blocks whose staking source maps to that poisoned entry (potentially thousands of blocks per staking interval).

---

### Likelihood Explanation

- Any node that connects as a peer is eligible to respond to staking-info requests; no special privilege is required.
- A new node fast-syncing from genesis (or from before the Kaia hardfork) will request staking info for every staking-interval block. An attacker operating a single peer that is selected for those requests can poison the entire pre-Kaia staking history.
- The `SyncStakingInfo` admin-RPC path (`datasync/downloader/downloader.go` lines 670–679) also writes peer-supplied data to the DB without content verification, but that path requires operator access and is separately out of scope. [5](#0-4) 

---

### Recommendation

Replace the no-op `validate` callback in `queue.DeliverStakingInfos` with a check that re-derives the staking info from the block's state root (using `getFromState`) and compares it against the peer-supplied data. If the state is unavailable at sync time, at minimum verify that `BlockNum` matches the header number and that address arrays are non-empty and self-consistent in length. The existing `header *types.Header` argument already provides the state root needed for full verification.

---

### Proof of Concept

1. Attacker runs a Kaia node and connects to a victim node that is fast-syncing pre-Kaia blocks.
2. Victim node calls `FetchStakingInfo` for block hashes it is syncing.
3. Attacker's `handleStakingInfoRequestMsg` handler returns a `P2PStakingInfo` with `CouncilRewardAddrs` replaced by attacker-controlled addresses for the requested block hash.
4. Victim's `handleStakingInfoMsg` → `downloader.DeliverStakingInfos` → `queue.DeliverStakingInfos` — the no-op `validate` passes; `PutStakingInfoToDB` writes the poisoned entry.
5. Fast sync completes. Victim begins processing new blocks. For any block `N` whose `sourceBlockNum(N)` maps to the poisoned entry, `GetStakingInfo(N)` returns the attacker's `RewardAddrs` from the DB.
6. `FinalizeState` → `GetDeferredReward` → `state.AddBalance(attackerAddr, mintedAmount)` — KAIA block rewards are credited to the attacker. [6](#0-5) [7](#0-6) [8](#0-7) [9](#0-8)

func (s *StakingModule) GetStakingInfo(num uint64) (*staking.StakingInfo, error) {
	isKaia := s.ChainConfig.IsKaiaForkEnabled(new(big.Int).SetUint64(num))
	sourceNum := sourceBlockNum(num, isKaia, s.stakingInterval)

	// Try cache first
	if si, ok := s.stakingInfoCache.Get(sourceNum); ok {
		return si.(*staking.StakingInfo), nil
	}

	// Only before Kaia, try the database
	if !isKaia {
		if si := ReadStakingInfo(s.ChainKv, sourceNum); si != nil {
			s.stakingInfoCache.Add(sourceNum, si)
			return si, nil
		}
	}

	// Read from the state
	si, err := s.getFromStateByNumber(sourceNum)
	if err != nil {
		return nil, err
	}

	// Only before Kaia, write to database
	if !isKaia {
		WriteStakingInfo(s.ChainKv, sourceNum, si)
	}

	// Cache it
	s.stakingInfoCache.Add(sourceNum, si)
	return si, nil
}

// handleStakingInfoMsg handles staking information response message.
func handleStakingInfoMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.chainconfig.Istanbul == nil || pm.chainconfig.Istanbul.ProposerPolicy != uint64(istanbul.WeightedRandom) {
		return errResp(ErrUnsupportedEnginePolicy, "the engine is not istanbul or the policy is not weighted random")
	}

	// A batch of stakingInfos arrived to one of our previous requests
	var stakingInfos []*staking.P2PStakingInfo
	if err := msg.Decode(&stakingInfos); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	// Deliver all to the downloader
	if err := pm.downloader.DeliverStakingInfos(p.GetID(), stakingInfos); err != nil {
		logger.Debug("Failed to deliver staking information", "err", err)
	}
	return nil
