### Title
Unvalidated user-controlled `max_aa_responses` inflates network-wide TPS-fee accounting - (File: storage.js, validation.js)

### Summary
`SpinLottery`'s bug is that a user-controlled input (`_prizeCount`) feeds a formula (`calculatePendingPrizesForRarity`) whose output is written into shared, persistent state (`prizePools[i].pendingCount`) without being validated against what will actually happen, letting one caller distort accounting that blocks/ affects everyone else. The same pattern exists in ocore's TPS-fee subsystem: the unit author freely declares `max_aa_responses` on a unit that triggers an AA, this value is used to compute `count_units` fed into the network-wide "current TPS" estimate, and that estimate raises the required `tps_fee` for *all other unstable units* until the trigger stabilizes and is reconciled — with no check that the declared value corresponds to the real number of AA responses that will occur.

### Finding Description
When composing a unit that outputs to an AA address, the author can set `max_aa_responses` (bounded only by `constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER`), independent of how many responses the AA will actually produce: [1](#0-0) 

This value is not required to reflect the AA's real logic; it is validated only for range, and it is even permitted for units whose actual trigger produces zero or one response. [2](#0-1) 

The declared `max_aa_responses` is converted into `count_units` and used both to determine the minimum `tps_fee` the unit itself must pay: [3](#0-2) [4](#0-3) 

and — critically — the same inflated `count_units` is summed for every unstable unit in `getCurrentTps`, which computes the network's live TPS estimate used to gate the `tps_fee` required from *all other, unrelated* units being validated concurrently: [5](#0-4) [6](#0-5) [7](#0-6) 

Only after the trigger unit's MCI stabilizes and the AA actually executes does `updateTpsFees` correct the fee based on the real `count_aa_responses`, crediting/debiting the `tps_fees_balances` table: [8](#0-7) 

This is structurally identical to the SpinLottery bug: a user-supplied count parameter (`max_aa_responses` / `_prizeCount`) is trusted to reflect a future, asynchronous outcome (AA execution / spin randomness) and is immediately baked into a shared pool (`getCurrentTps` accumulator / `prizePools[i].pendingCount`) that constrains everyone else, with correction only happening later (post-stabilization reconciliation vs. blocked future `spin`).

### Impact Explanation
An attacker can post a unit that outputs to an AA address (a trivial AA that does nothing) and set `max_aa_responses` to the maximum allowed value (`constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER`) even though the AA will produce zero or one response. While that unit remains unstable (which can span multiple main-chain advances under normal witnessing latency), `getCurrentTps`/`getCurrentTpsFee`/`getCurrentTpsFeeToPay` will report an artificially inflated network TPS, forcing all concurrently-submitted units (from unrelated users) to pay a much higher `tps_fee` or be rejected as `createTransientError` for insufficient fee. Repeating this with a handful of low-cost, self-authored trigger units can be used to grief the fee market network-wide, temporarily pricing out normal users from getting their units accepted — i.e., "a network unable to confirm new units [cheaply]." This matches the High/Medium-impact class described in the source report (a user-controlled count corrupting shared accounting used to gate future operations for other participants).

### Likelihood Explanation
Medium: any unprivileged unit author can trigger this by simply composing a payment to any AA address with a self-chosen `max_aa_responses`; no special privileges, cooperating AA logic, or race condition are required — only that the trigger unit remains unstable for a window, which is a normal occurrence given witness confirmation latency.

### Recommendation
Do not let the author-declared `max_aa_responses` count toward `getCurrentTps`/global fee-market accounting until it is known (or bounded) to correspond to real usage. Options: charge/account based on a conservative default (e.g., 1) for unstable units and only use the declared/actual count once the trigger is executed and `count_aa_responses` is known; or cap the influence of a single trigger's declared `max_aa_responses` on the *shared* current-TPS estimate (separate from what that unit itself must pay), so that one user's speculative declaration cannot inflate the fee required from unrelated units.

### Proof of Concept
1. Attacker composes and broadcasts unit U with a payment output to an existing AA address `A` (trivial AA needed) and sets `max_aa_responses = constants.MAX_RESPONSES_PER_PRIMARY_TRIGGER` (validation only checks the range, not correspondence to actual behavior — `validation.js:203-210`).
2. `validateAATrigger` accepts this without checking whether `A`'s logic would realistically produce that many responses (`validation.js:986-1024`).
3. While U is unstable, `storage.getCountUnitsPayingTpsFee(U)` returns `1 + 1 * max_aa_responses` (`storage.js:1351-1358`), and this inflated value is folded into `getCurrentTps` (`storage.js:1361-1395`) for every other concurrently validated unit via `getCurrentTpsFee`/`getCurrentTpsFeeToPay` (`storage.js:1397-1408`).
4. `validateTpsFee` for unrelated units now computes a higher `min_acceptable_tps_fee` and either rejects their unit as transient error or forces them to pay a much higher `tps_fee` (`validation.js:1074-1097`).
5. Repeating step 1 with several cheap trigger units sustains the fee inflation for as long as those units stay unstable, after which `updateTpsFees` (`storage.js:1247-1275`) reconciles the attacker's own fee down post-hoc — but the damage to other users' fees during the unstable window is already done.

function getCountUnitsPayingTpsFee(objUnitProps) {

		count_units += objUnitProps.count_primary_aa_triggers * max_aa_responses;
	}
	return count_units;

function getCurrentTps(shift = 0, count_units = 1) {
	if (last_stable_mci === null)
		throw Error(`getCurrentTps: last_stable_mci not set yet`);
	const since_mci = last_stable_mci + shift;
	let count = count_units; // include the current unit and its AA responses
	let since_timestamp = 0;
	const now = Math.ceil(Date.now() / 1000);
	for (let unit in assocUnstableUnits) {
		const objUnitProps = assocUnstableUnits[unit];
		if (objUnitProps.timestamp > now) continue; // skip future-timestamped units
		if (objUnitProps.main_chain_index > since_mci || objUnitProps.main_chain_index === null)
			count += getCountUnitsPayingTpsFee(objUnitProps);
		else if (shift > 0 && objUnitProps.main_chain_index === since_mci) {
			if (objUnitProps.timestamp > since_timestamp)
				since_timestamp = objUnitProps.timestamp;
		}
	}
	if (count === count_units)
		return 0;
	//	throw Error(`getCurrentTps: no unstable units`);
	if (shift === 0) {
		const arrLastStableUnitProps = assocStableUnitsByMci[last_stable_mci];
		if (!arrLastStableUnitProps)
			throw Error(`getCurrentTps: no stable units at last stable mci ${last_stable_mci}`);
		for (let { timestamp } of arrLastStableUnitProps) {
			if (timestamp > since_timestamp)
				since_timestamp = timestamp;
		}
	}
	if (since_timestamp === 0)
		throw Error(`since_timestamp = 0, shift=${shift}, last_stable_mci=${last_stable_mci}`)
	const elapsed = (Math.round(Date.now() / 1000) - since_timestamp) || elapsedTimeWhenZero;
	console.log(`getCurrentTps shift=${shift}, date ${new Date()}, diff ${Math.round(Date.now() / 1000) - since_timestamp} ${count}/${elapsed}`);
	return count / elapsed;
}

function getCurrentTpsFee(shift = 0, count_units = 1) {
	const tps = getCurrentTps(shift, count_units);
	console.log(`current tps with shift ${shift} ${tps}`);
	const base_tps_fee = getSystemVar('base_tps_fee', last_stable_mci);
	const tps_interval = getSystemVar('tps_interval', last_stable_mci);
	return Math.round(base_tps_fee * (exp(tps / tps_interval) - 1));
}

function getCurrentTpsFeeToPay(shift = 0, count_units = 1) {
	const tps_fee_multiplier = getSystemVar('tps_fee_multiplier', last_stable_mci);
	return Math.round(tps_fee_multiplier * getCurrentTpsFee(shift, count_units));
}
