### Title
Webhook signature check validates `repository.owner.login`/`organization.login`, not `repository.full_name`, allowing an unconfigured-secret org to forge events against a victim org's stack - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the `webhook_secret` used for HMAC verification) exclusively from `repository_owner` (`params.dig('repository','owner','login')` or `organization.login`), while the event handlers (e.g. `LabeledHandler`) resolve the actual `Repository`/`Stack` to mutate from the independent field `params.repository.full_name`. `GitHubApp#verify_webhook_signature` also returns `true` unconditionally when the selected organization has no `webhook_secret` configured. There is no code anywhere that enforces `repository.full_name` starts with `repository_owner`.

### Finding Description
The broken binding: the code implicitly assumes `repository_owner == owner(repository.full_name)`, but no equality check enforces this anywhere in `app/controllers/shipit/webhooks_controller.rb` or the handler layer.

Path:
1. `WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` [1](#0-0) .
2. It fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature` on that app instance [2](#0-1) .
3. `GitHubApp#verify_webhook_signature` returns `true` immediately if `webhook_secret` is blank for that org: `return true unless webhook_secret` [3](#0-2) .
4. On success, `WebhooksController#create` parses the raw body and dispatches to handlers for the event, passing the *entire* JSON payload unmodified [4](#0-3) .
5. `LabeledHandler#repository` resolves the target repository purely from `params.repository.full_name` via `Shipit::Repository.from_github_repo_name`, with no reference back to `repository_owner`/`organization.login` used for signature verification [5](#0-4) .
6. `LabeledHandler#handle` calls `stack.archive!`/`stack.unarchive!` based on label state, with the stack derived from that repository [6](#0-5) .

Exploit: attacker sends `POST /webhooks` with `X-Github-Event: pull_request`, JSON body containing `organization.login` (or `repository.owner.login`) set to an org configured in `secrets.github` with `webhook_secret: nil`/absent, while `repository.full_name` is set to `"victim-org/repo"` where `victim-org` has a configured secret and an existing labeled PR stack. No `X-Hub-Signature` header, or any garbage value, is required because `verify_webhook_signature` short-circuits to `true` for the no-secret org. The request then reaches `LabeledHandler`, which resolves `victim-org/repo`'s real `Repository`/`ReviewStack` and calls `archive!`/`unarchive!` on it.

Existing guards do not prevent this: `verify_signature` only rescues `GithubOrganizationUnknown` (unconfigured org name entirely) and checks the signature algorithm/HMAC, but it never checks that the org used for verification matches the org embedded in `repository.full_name` [7](#0-6) . `ExplicitParameters` schemas in the handler only validate types/presence of `repository.full_name`, not cross-consistency with the verifying org [8](#0-7) .

### Impact Explanation
An attacker who controls (or can register) any Shipit-configured GitHub org lacking a `webhook_secret` can forge webhook events that mutate stacks belonging to any other, fully-secured org/tenant, purely by setting `repository.full_name` in the JSON body. This is a cross-tenant/cross-repository authentication bypass: a payload nominally "authenticated" for org A (with no secret, trivially "verified") is used to write to org B's stack (archive/unarchive review stacks, and by the same mechanism, any other handler keyed off `repository.full_name` — push/status/check_suite handlers, etc.). This matches "Critical: a payload for one repository mutating another's stack" and "authentication bypass (forged webhook accepted)".

### Likelihood Explanation
Requires the Shipit deployment to have at least one configured GitHub org/app entry with `webhook_secret` blank/absent alongside at least one other org with a real secret and existing stacks — i.e. multi-org (`secrets.github` keyed by org name) configurations where secret configuration is inconsistent across orgs. This is a plausible operational misconfiguration but not guaranteed on every install; single-org (top-level `github` key) deployments are less affected since `github_default_organization` bypasses the per-org config path [9](#0-8) . Attacker cost is trivial once such a misconfigured org exists: no valid signature, no privileged role, and the request is repeatable against arbitrary victim repositories/stacks referenced by `full_name`.

### Recommendation
In `WebhooksController#verify_signature`, additionally verify that the organization used to select the `webhook_secret`/`GitHubApp` matches the owner embedded in `repository.full_name` (and/or `organization.login`) before dispatching to handlers, rejecting mismatches with `head(422)`. Also consider removing/hardening the `return true unless webhook_secret` bypass in `GitHubApp#verify_webhook_signature` so that an org without a configured secret cannot be used to authenticate arbitrary payloads targeting other orgs' repositories.

### Proof of Concept
```ruby
test "webhook verified for org without secret can archive a stack belonging to a different secured org" do
  # Arrange: org "no-secret-org" configured with webhook_secret: nil,
  # "victim-org" configured with a real webhook_secret and has repository/review stack fixtures.
  Shipit.stubs(:github_default_organization).returns('multi')
  Shipit.stubs(:github_app_config).with('no-secret-org').returns({ webhook_secret: nil })

  victim_repo = shipit_repositories(:victim_org_repo) # owner: 'victim-org'
  review_stack = shipit_review_stacks(:victim_labeled_pr_stack)

  payload = {
    action: 'labeled',
    number: review_stack.pull_request_number,
    pull_request: pull_request_payload_for(review_stack), # state open, labels causing archive?
    repository: { full_name: victim_repo.github_repo_name }, # "victim-org/repo"
    organization: { login: 'no-secret-org' }, # used only for signature org selection
    sender: { login: 'attacker' }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  # No X-Hub-Signature header at all, or an invalid one.

  assert_predicate review_stack.reload, :active? # binding LHS: not archived before

  post :create, body: payload, as: :json

  assert_response :ok
  assert_predicate review_stack.reload, :archived? # binding RHS: archived despite no valid signature for victim-org
end
```
This demonstrates the equality `repository_owner (verification target) == owner(repository.full_name) (mutation target)` does not hold and is never checked, letting an unauthenticated forged payload for `no-secret-org` archive a stack that belongs to `victim-org`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end
```
