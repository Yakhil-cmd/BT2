### Title
PR/issue title, body, and comment text bypass ANSI/OSC sanitization entirely because `gh pr view` writes server content to `IO.Out` instead of the sanitized `IO.ContentOut` - ([File: pkg/iostreams/iostreams.go])

### Summary
`(IOStreams).SetContentSanitization` only wires an `asciisanitizer` transform into `s.ContentOut`; it never touches `s.Out` [1](#0-0) . `gh pr view`'s renderers (`printRawPrPreview`, `printHumanPrPreview`) print `pr.Title`, `pr.Body`, and other attacker-controlled fields straight to `opts.IO.Out` via `fmt.Fprintf`/`fmt.Fprintln`, never through `IO.ContentOut` [2](#0-1) [3](#0-2) , so any control/ANSI/OSC bytes an attacker embeds in a PR title, body, or comment reach the terminal unsanitized regardless of the sanitization toggle.

### Finding Description
`IOStreams` maintains two separate output paths: `Out` (application-authored text, e.g. tables/prompts) and `ContentOut`, documented as the writer intended for "external content (HTTP response bodies, gist files, etc.) where the application is not the author of the bytes" [4](#0-3) . `SetContentSanitization` only rebuilds `ContentOut`, wrapping it with `asciisanitizer.Sanitizer` when enabled, or passing the raw writer through when disabled [5](#0-4) . It has no effect whatsoever on writes made to `Out`/`ErrOut`.

`gh pr view` (`pkg/cmd/pr/view/view.go`) never uses `ContentOut`. Both the non-TTY path (`printRawPrPreview`) and the TTY path (`printHumanPrPreview`) call `fmt.Fprintf(out, ...)`/`fmt.Fprintln(out, ...)` on `io.Out`/`opts.IO.Out` directly for `pr.Title`, `pr.Body`, milestone titles, project names, and other GraphQL-sourced fields [6](#0-5) [7](#0-6) . Comment bodies flow through `shared.CommentList`/`shared.RawCommentList`, which are likewise written to `out` (`IO.Out`), not `ContentOut`. This confirms that the sanitizer that `SetContentSanitization` enables/disables is architecturally not in the code path that `gh pr view` uses to print server-supplied text — the toggle only protects a small set of commands that were explicitly wired to `ContentOut` (e.g. `pkg/cmd/gist/view/view.go`, `pkg/cmd/pr/diff/diff.go`, `pkg/cmd/api/api.go`, `pkg/cmd/codespace/logs.go`, `pkg/cmd/release/download/download.go`, `pkg/cmd/repo/read-file/read_file.go`), while `pr view` (and `issue view`, which follows the identical `fmt.Fprint(opts.IO.Out, ...)` pattern) are not.

The only mitigating factor for the TTY/human preview path is that `pr.Body` is passed through `markdown.Render` (glamour-based) before printing [8](#0-7) , which may incidentally neutralize some raw control sequences depending on the markdown renderer's escaping behavior — this was not verified in the index available. However, `pr.Title` (printed in both TTY and non-TTY modes), milestone/project/label names, and the entire raw (`--json`-less, non-TTY) preview path bypass markdown rendering entirely and are written completely unsanitized.

### Impact Explanation
An attacker who authors a PR/issue title (or other short metadata field not passed through markdown rendering) containing OSC 52 (clipboard write), OSC 7 (working-directory/prompt manipulation), or other terminal escape sequences can have those sequences emitted verbatim to the victim's terminal when they run `gh pr view` (TTY header line, or any non-TTY `title:` line). This matches "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation" — a victim's terminal state, prompt, or clipboard could be manipulated by data they merely viewed via `gh pr view`.

### Likelihood Explanation
High feasibility and low precondition: any unprivileged GitHub user can set a PR/issue title or comment body on a repository they control (or a fork/PR against a public repo) and have the victim simply run `gh pr view <url>` against it. No special permissions, MITM, or social engineering beyond normal open-source collaboration are required. The bug is deterministic and repeatable — it is a structural gap (a writer path never wired to sanitization) rather than a race condition or edge case.

### Recommendation
Route all server-authored fields printed by `pr view`/`issue view` (title, body when not markdown-rendered, milestone/label/project names, comment authors/bodies) through `IO.ContentOut` instead of `IO.Out`, or apply the `asciisanitizer` transform unconditionally to these fields before writing. Alternatively, invert the architecture so that `Out` itself sanitizes by default and only bypasses sanitization for a small, explicitly-approved set of writes.

// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}
