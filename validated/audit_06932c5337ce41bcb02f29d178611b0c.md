### Title
RAY-denominated interest accrual can overflow `i128` before index caps, permanently freezing a market - ([File: common/src/rates/simulate.rs])

### Summary

`accrue_step` multiplies the market’s scaled borrow and supply totals by their respective indexes before enforcing the protocol index caps. Once either RAY-denominated product exceeds `i128::MAX`, accrual panics, and every controller operation that synchronizes that market becomes unusable.

### Finding Description

`accrue_step` computes `borrowed_original` and `supplied_original` through `scaled_to_original`, which performs the fixed-point `scaled * index / RAY` multiplication. [1](#0-0) [2](#0-1) 

The borrow index is capped only after `update_borrow_index` calculates its new value, while `calculate_supplier_rewards` subsequently multiplies the scaled debt by both the old and new indexes. [3](#0-2) [4](#0-3) 

For a sufficiently large market, `scaled * index` can exceed the `i128` domain before the borrow index reaches `MAX_BORROW_INDEX_RAY`; the repository’s regression test explicitly demonstrates that the configured cap does not engage first. [5](#0-4) 

The controller exposes `update_indexes(caller, assets)` to an authorized ordinary caller and forwards the requested hub assets to the pool. [6](#0-5)  The pool then loads each market and calls `interest::global_sync`, which executes one or more `accrue_step` chunks. [7](#0-6) [8](#0-7) [9](#0-8) 

### Impact Explanation

After the accrual enters this state, suppliers cannot withdraw and borrowers cannot repay because those paths synchronize the market before applying their position mutations; liquidation is likewise blocked according to the regression test’s documented behavior. [10](#0-9) 

The pool’s own mutating entrypoints perform the same synchronization and therefore cannot provide a repayment or withdrawal path that bypasses the overflow. [11](#0-10)  This permanently freezes the affected market absent a privileged code upgrade or other administrative intervention.

### Likelihood Explanation

A single unprivileged actor can create the prerequisite book by supplying a very large amount of a supported high-decimal asset and borrowing a high proportion of it from a separately collateralized account, as demonstrated by the test’s one-billion-token, ninety-eight-percent-borrowed setup. [12](#0-11) 

The attack requires substantial capital and sustained interest accrual on a sufficiently steep rate model, but no privileged role is needed for the deposits, borrow, or subsequent public index update. [13](#0-12) [6](#0-5) 

### Recommendation

Derive a market-specific maximum index from the current scaled totals before running the accrual step: for each scaled total `s`, the multiplication domain requires `index <= floor(i128::MAX * RAY / s)`. [2](#0-1) 

Clamp index progression to the lower of the configured protocol cap and that representable-value cap, or perform the accrual valuation in `I256` and persist a safely capped result, so `last_timestamp` can still advance and repayment, withdrawal, and liquidation remain executable. [14](#0-13)  Add regression coverage proving that the effective index cap engages before `scaled_to_original` can overflow for large markets. [15](#0-14) 

### Proof of Concept

The existing regression test constructs an 18-decimal market with the steep XLM rate curve and a separate collateral market, lifts the usage caps, supplies `1_000_000_000 * 10^18` raw units of `BIG18`, supplies collateral from another account, and borrows `98%` of that principal. [16](#0-15) [12](#0-11) 

```rust
// Simplified form of tests/test-harness/tests/controller/
// large_positions_and_long_horizons.rs.

let debt = principal / 100 * 98;

// Bob creates the debt-market liquidity.

// Alice creates a separately collateralized borrowing account.
controller.supply(alice, 0, spoke, vec![(collateral, required_collateral)]);
let account = /* Alice's account id */;
controller.borrow(alice, account, vec![(big18, debt)], None);

// After enough ledger time, any caller can trigger the failing accrual.
controller.update_indexes(attacker, vec![big18]);
```

That public index update returns `GenericError::MathOverflow`, while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [17](#0-16) 

Subsequent withdrawal and repayment attempts fail with the same `MathOverflow` before their mutations can execute, demonstrating that ordinary users cannot recover the market through repayment or exit. [18](#0-17)

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
