### Title
Webhook signature verification is silently bypassed when an organization's `webhook_secret` is unset, allowing unauthenticated forged GitHub events (including team membership grants) - ([File: app/controllers/shipit/webhooks_controller.rb], [File: lib/shipit/github_app.rb])

### Summary
### Finding Description
`WebhooksController#verify_signature` selects which GitHub App config to validate against based on `repository_owner`, a value read directly from the *unauthenticated* JSON body (`params.dig('repository', 'owner', 'login')` or `params.dig('organization', 'login')`), then calls `GithubApp#verify_webhook_signature` on that org's app: [1](#0-0) 

The verification method itself contains a bypass: if the resolved organization's config has no `webhook_secret` configured, it returns `true` unconditionally, with no signature check performed at all: [2](#0-1) 

Because `repository_owner` (the value that selects *which* app/secret is used) is itself taken from the unauthenticated body and is never itself covered by any signature, an attacker can pick any configured organization. If that organization was set up without a `webhook_secret` (the field is explicitly documented as optional in `docs/setup.md`, and is `nil` in the shipped example configs), `verify_webhook_signature` short-circuits to `true` and the entire raw POST body is accepted as a genuine GitHub-originated webhook — with zero authentication. This breaks the intended binding: "a payload claims to originate from organization X" == "the payload was actually signed by GitHub for X."

Once accepted, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` processes the attacker-controlled body as if it were an authentic GitHub event. The test suite confirms that a `membership` event can create/append/remove `Membership` records purely from webhook payload content, with no additional server-side authorization check beyond `verify_signature`: [3](#0-2) 

### Impact Explanation
For any organization configured without a `webhook_secret`, an unauthenticated, unprivileged attacker can:
- Forge `membership` events to add arbitrary GitHub logins to a `Shipit.github_teams`-backed `Team`, escalating access into the authorization system that gates `force_github_authentication` (`current_user.authorized?`), matching the "High - escalation into `Shipit.github_teams` authorization" impact category. [4](#0-3) 
- Forge `push`/`status`/`check_suite` events to inject fabricated commit/CI state that influences merge-queue processing and deploy readiness (`ProcessMergeRequestsJob`, `MergeRequest#reject_unless_mergeable!`), potentially contributing to an unauthorized merge/deploy path: [5](#0-4) 

### Likelihood Explanation
Likelihood depends entirely on deployment configuration: exploitation requires at least one configured GitHub organization in `Shipit.github` to have a blank/unset `webhook_secret`. Since the setup docs and shipped example secrets files (`config/secrets.development.example.yml`, `config/secrets.development.shopify.yml`, `test/dummy/config/secrets_double_github_app.yml`) all show `webhook_secret: # nil` as an accepted/example value, and no code path enforces that `webhook_secret` must be present, this is a realistic and easy-to-hit misconfiguration rather than a purely theoretical one. [6](#0-5) 

### Recommendation
- Fail closed instead of open: `verify_webhook_signature` should reject the request (return `false`/422) when no `webhook_secret` is configured, rather than treating a missing secret as automatically verified.
- Do not let an unauthenticated field (`repository_owner`/`organization.login` from the raw body) select the trust boundary (which app/secret to check against) before any cryptographic verification has occurred; instead, verify against every configured app's secret (or require an explicit `X-GitHub-Hook-Installation-Target-ID`/app id mapping) so that an attacker cannot choose a weakly configured organization to bypass validation.
- Document/enforce (e.g., via a startup check) that `webhook_secret` is mandatory for every configured GitHub App entry.

### Proof of Concept
1. Configure two organizations in `Shipit.github`, e.g. `OrgSecure` (with `webhook_secret` set) and `OrgOpen` (with `webhook_secret` left blank/nil), as the multi-org config format supports.
2. As an unauthenticated attacker, POST to `/webhooks` with header `X-Github-Event: membership` and no `X-Hub-Signature` header, with body:
   ```json
   { "action": "added", "organization": { "login": "OrgOpen" }, "team": { "id": 1, "name": "Some Team", "slug": "some-team" }, "member": { "login": "attacker-login" } }
   ```
3. `verify_signature` resolves `github_app = Shipit.github(organization: "OrgOpen")`, calls `verify_webhook_signature(nil, body)`, which returns `true` immediately because `OrgOpen`'s `webhook_secret` is blank.
4. `create` proceeds to run the `membership` handler, which creates a `Membership` for `attacker-login` in the target team — as demonstrated by the existing test asserting membership creation purely from webhook body content with no external signature validated: [7](#0-6) 
5. If that team is one of `Shipit.github_teams`, `attacker-login`'s corresponding `User` (created on the fly) is now `authorized?` in Shipit without ever authenticating via the real GitHub OAuth flow.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
