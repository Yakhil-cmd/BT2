### Title
Review set can silently drop a dangerous file after `git commit --amend` due to non-ancestor HEAD advance in `compute_v2_review_set` - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` builds its final review set as `dirty_now ∩ changed_since`, where `dirty_now` is derived from `git status` against the *current* HEAD and `changed_since` is derived from a diff against the pre-turn `baseline_sha`. When the working turn's commit is rewritten with `git commit --amend` (a normal, unprivileged git operation), the amended file becomes clean against current HEAD (so it drops out of `dirty_now`), while the `_is_ancestor(head_at_capture, current_head)` guard fails because `--amend` does not produce a linear/fast-forward history from `head_at_capture`. This causes the intersection to exclude the dangerous file even though its content still differs from the baseline.

### Finding Description
`compute_v2_review_set` at [1](#0-0)  computes `dirty_now` from `git status --porcelain` against current HEAD, optionally widened by `head_at_capture..HEAD` **only if** `_is_ancestor(head_at_capture, current_head)` holds (i.e., HEAD moved forward linearly via plain commits/merges). It then intersects `dirty_now` with `changed_since` (a diff of the current worktree against the stashed pre-turn `baseline_sha`, computed via `_git_name_only`).

If, during the turn, the dangerous edit is committed and then amended (`git commit -m wip` followed by `git commit --amend`), the following happens:
- The amended commit is a **sibling**, not a descendant, of the original `head_at_capture` commit in git's DAG (same parent, different tree), so `_is_ancestor(head_at_capture, current_head)` in [2](#0-1)  returns `False`.
- Because that guard fails, `diff_base` stays `"HEAD"` and the `head_at_capture..HEAD` diff is never unioned into `dirty_now`, so the amended file is not "dirty" (it is fully committed and clean vs. current HEAD).
- `changed_since = _git_name_only(repo, baseline_sha)` still correctly reports the file as changed relative to the original pre-turn baseline, since it's a straight tree comparison independent of commit history.
- The final line `review_set = dirty_now & changed_since` therefore intersects an empty (or file-missing) `dirty_now` with a `changed_since` containing the file, producing `∅` for that file — it is silently dropped from the review set even though it is a genuinely new, unreviewed change since baseline.

The docstring's own reasoning at [3](#0-2)  assumes the "dirty vs HEAD" term plus the "committed this turn when HEAD advanced linearly" term together cover all turn changes, but the linear-advance precondition is exactly what `--amend` violates while still being a routine, unprivileged git operation a coding agent would run (e.g., to fix a commit message or squash WIP).

### Impact Explanation
A file containing attacker-influenced dangerous content (e.g., introduced via prompt injection steering the agent to write malicious code, then have the agent "clean up" the commit with `--amend`) can bypass the Stop-hook's security review entirely. Since `compute_v2_review_set` feeds directly into what `Stop-hook reviewed file selection` treats as reviewable, an excluded file is never diffed or shown to the LLM reviewer, letting an unauthorized/unreviewed file write persist in the repository outside the review/approval boundary the plugin is meant to enforce.

### Likelihood Explanation
This requires no privilege beyond ordinary git usage inside the working repo during a Claude Code turn: `git commit` followed by `git commit --amend` (or any git operation that creates a non-fast-forward, non-ancestor rewrite of `head_at_capture`, e.g. `rebase`, `reset --hard` + recommit) is an extremely common and unsuspicious agent/developer workflow, making this readily reachable and repeatable, not a contrived edge case.

### Recommendation
Do not gate the extra committed-diff term on strict linear ancestry alone. Instead, always union `dirty_now` with the diff of `head_at_capture..HEAD` (or more robustly, directly union `changed_since` results without requiring the `dirty_now` term to independently "see" every committed file) whenever `head_at_capture != current HEAD`, regardless of ancestor relationship, since amends/rebases still represent turn-local changes that must remain reviewable. Alternatively, use `changed_since` as the sole source of truth for reviewability when `baseline_sha` exists, only using `dirty_now` to add currently-uncommitted-untracked files rather than to gate out committed ones.

### Proof of Concept
Unit/integration test plan in the existing `diffstate`/`security_reminder_hook` test suite:
1. Init a repo with an initial commit; capture `baseline_sha` via `capture_git_baseline` and `head_at_capture` via `_git_rev_parse_head`.
2. Write a dangerous change to `vuln.py`, `git add`, `git commit -m "wip"`.
3. Run `git commit --amend -m "final"` (no content change to the amend message, tree stays with the dangerous content).
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert `vuln.py` is present in the returned `review_paths`.
Expected (bug) result: `vuln.py` is absent from `review_paths` because `_is_ancestor(head_at_capture, current_head)` is `False` after the amend, `dirty_now` is empty for that file, and `review_set = dirty_now & changed_since` evaluates to empty for it, despite `changed_since` correctly containing it.

def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
