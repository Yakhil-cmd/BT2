### Title
Any signed Asset Hub account can obtain `RuntimeOrigin::root()` on the Relay Chain via `pallet_xcm::send` + `Transact{origin_kind: Superuser}` - (File: relay/polkadot/src/xcm_config.rs)

### Summary
The Relay Chain's `LocalOriginConverter` includes `LocationAsSuperuser<Equals<AssetHubLocation>, RuntimeOrigin>`, which grants root dispatch to *any* XCM whose transport-level origin equals `Parachain(ASSET_HUB_ID)` and whose `Transact` instruction specifies `OriginKind::Superuser`, with no distinction between an internal/privileged Asset Hub call and a message manually constructed by an ordinary signed account. Asset Hub's `pallet_xcm::Config::SendXcmOrigin` allows any signed account to call `send`, and the raw XCM content (including `Transact{Superuser, ...}`) is not filtered before being forwarded via UMP. Combined with the Relay's `AllowTopLevelPaidExecutionFrom<Everything>` barrier rule, this creates a reachable path for an unprivileged Asset Hub account to dispatch an arbitrary call as `RuntimeOrigin::root()` on the Relay Chain.

### Finding Description
- On the Relay Chain, `LocalOriginConverter` (used by `xcm_executor::Config::OriginConverter`) contains `LocationAsSuperuser<Equals<AssetHubLocation>, RuntimeOrigin>`, where `AssetHubLocation = Parachain(ASSET_HUB_ID).into_location()`. [1](#0-0) [2](#0-1) 

- `LocationAsSuperuser` only checks the message's *transport-level origin location* and the `OriginKind` field the sender chose for the `Transact` instruction. It does not check which pallet or account inside Asset Hub caused the message to be sent - it trusts the entire Asset Hub parachain as a monolithic principal.

- The barrier for the Relay Chain allows execution for essentially any origin as long as it pays for weight: `AllowTopLevelPaidExecutionFrom<Everything>`. This means a message does not need to come from a privileged internal AssetHub source or even from a system parachain plurality to be admitted — buying execution (`BuyExecution`) is sufficient. [3](#0-2) 

- On Asset Hub, `pallet_xcm::Config::SendXcmOrigin = EnsureXcmOrigin<RuntimeOrigin, LocalPalletOrSignedOriginToLocation>`, and `LocalPalletOrSignedOriginToLocation` includes `SignedToAccountId32<RuntimeOrigin, AccountId, RelayNetwork>` — explicitly documented as "Any local signed origin can send XCM messages." [4](#0-3) [5](#0-4) 

- `pallet_xcm::send` only validates that the calling origin is permitted to send at all (via `SendXcmOrigin::ensure_origin`); it does not filter or inspect the content of the user-supplied `Xcm` program. A signed account can therefore submit an arbitrary program, including `Transact{origin_kind: OriginKind::Superuser, call: <relay root call>}`, targeted at `Parent`.

- Since the outbound message is delivered via UMP, the Relay Chain sets the message's origin purely based on the sending parachain ID (`Parachain(ASSET_HUB_ID)`), independent of which account inside Asset Hub constructed the payload. As long as the attacker includes a fee-paying prefix (e.g. `WithdrawAsset`/`BuyExecution`), the Relay's `Barrier` (`AllowTopLevelPaidExecutionFrom<Everything>`) admits the message without any origin restriction, and execution proceeds to the `Transact` instruction where `LocationAsSuperuser<Equals<AssetHubLocation>>` converts `(origin = Parachain(ASSET_HUB_ID), OriginKind::Superuser)` into `RuntimeOrigin::root()`.

- The Relay's `xcm_executor::Config::SafeCallFilter = Everything` means no additional filtering of the dispatched call is applied once root origin is obtained. [6](#0-5) 

None of the checks in the pipeline (SendXcmOrigin, Barrier, OriginConverter, SafeCallFilter) distinguish "a privileged internal Asset Hub system call" from "an arbitrary signed account paying to send an XCM," because the trust boundary chosen (`Equals<AssetHubLocation>`) is at the whole-parachain granularity rather than at a specific internal-origin/plurality granularity.

### Impact Explanation
An ordinary signed Asset Hub account can force the Relay Chain to dispatch any `RuntimeCall` (e.g., `Balances::force_transfer`, staking/governance manipulation, `System::set_code`, etc.) with `RuntimeOrigin::root()`, completely bypassing every relay-chain permission model. This is full compromise of the Relay Chain's privilege boundary — unauthorized root-level dispatch triggered by an unprivileged user through Asset Hub.

### Likelihood Explanation
- Preconditions: attacker only needs a funded signed account on Asset Hub with enough DOT to pay for XCM execution/delivery fees (`pallet_xcm::send` is permissionless for any signed origin per `LocalPalletOrSignedOriginToLocation`).
- Feasibility: constructing `Xcm[WithdrawAsset, BuyExecution, Transact{Superuser, call}]` and calling `pallet_xcm::send(Parent, ...)` is a standard, well-documented XCM pattern requiring no special access.
- Repeatable: the exploit can be re-run any time and does not depend on any race condition or privileged timing window.

### Recommendation
Do not trust the entire `AssetHubLocation` (a whole-parachain location) as a superuser principal for `OriginKind::Superuser`. Instead:
- Restrict the Relay's `LocationAsSuperuser` matcher to a narrower, non-forgeable location that only an Asset Hub–internal privileged origin (e.g., a specific pallet/plurality location reachable only via Asset Hub's own root/governance track, analogous to `AssetHubPlurality`) can produce, and require the outbound message on Asset Hub to originate from that privileged origin rather than from `pallet_xcm::send` with a generic signed origin.
- Alternatively/additionally, restrict Asset Hub's `SendXcmOrigin`/`pallet_xcm::send` (or add a `SendXcmFilter`-equivalent check) so that ordinary signed accounts cannot construct outbound `Transact{origin_kind: Superuser}` XCM programs targeted at `Parent`.
- Ensure the Relay's Barrier requires the "system parachain acting as superuser" case to go through the unpaid/plurality-gated path (`AssetHubPlurality`) rather than being reachable via `AllowTopLevelPaidExecutionFrom<Everything>`.

### Proof of Concept
xcm-emulator integration test:
```rust
#[test]
fn asset_hub_signed_user_cannot_get_relay_root() {
    // Setup: AssetHub + Polkadot relay in emulated network, fund a plain signed AssetHub account.
    AssetHubPolkadot::execute_with(|| {
        let signer = AssetHubPolkadotSender::get(); // ordinary signed account, no special origin
        let root_call: RuntimeCall = RuntimeCall::Balances(pallet_balances::Call::force_transfer {
            source: victim_account.into(),
            dest: attacker_account.into(),
            value: STOLEN_AMOUNT,
        });
        let message: Xcm<()> = Xcm(vec![
            WithdrawAsset((Here, FEE_AMOUNT).into()),
            BuyExecution { fees: (Here, FEE_AMOUNT).into(), weight_limit: Unlimited },
            Transact {
                origin_kind: OriginKind::Superuser,
                call: root_call.encode().into(),
                fallback_max_weight: None,
            },
        ]);
        assert_ok!(pallet_xcm::Pallet::<AssetHubPolkadotRuntime>::send(
            RuntimeOrigin::signed(signer),
            Box::new(Location::parent().into()),
            Box::new(xcm::VersionedXcm::from(message)),
        ));
    });

    Polkadot::execute_with(|| {
        // Assert: the relay-chain root-only call must NOT have executed.
        assert_eq!(
            pallet_balances::Pallet::<PolkadotRuntime>::free_balance(&victim_account),
            ORIGINAL_BALANCE,
            "unauthorized root-level dispatch executed on the Relay Chain"
        );
        // Also assert no `Dmp`/`XcmPallet` event indicates a successful Transact with root origin.
    });
}
```
Expected (secure) result: the relay balance transfer must not occur; the message should either be rejected at Asset Hub's send path, fail origin conversion on the Relay (`LocationAsSuperuser` should not match a plain signed-account-initiated message), or be filtered before dispatch. As currently configured, the test is expected to fail (i.e., the unauthorized transfer succeeds), demonstrating the vulnerability.
