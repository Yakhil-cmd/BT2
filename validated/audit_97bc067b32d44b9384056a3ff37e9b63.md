## Finding: Same fix applied to Asset Hub Polkadot but not Asset Hub Kusama for the `TotalUnbondingPools` era-bound shrink bug

### Title
`PostUnbondingPoolsWindow` on Asset Hub Kusama is a static `ConstU32<4>` and does not track `AreNominatorsSlashable`, reproducing the already-patched Polkadot bug (destruction of per-era unbonding accounting on `unbond`) - (File: `system-parachains/asset-hubs/asset-hub-kusama/src/staking/nom_pools.rs`)

### Summary
The reported StRSR bug is a state-transition/accounting-loss class issue: a bound/index tied to a mutable "era" value shrinks after some state change, and subsequent writes silently truncate/overwrite historical per-era records, losing user funds already queued for withdrawal. This exact vulnerability class was already discovered in this codebase (referenced in-repo as "bugbounty report #90") and fixed for Asset Hub Polkadot, but the equivalent runtime configuration for Asset Hub Kusama still uses the vulnerable static bound.

### Finding Description
`pallet_nomination_pools::SubPools::with_era` is bounded by `TotalUnbondingPools = nominator_bonding_duration() + PostUnbondingPoolsWindow`. `nominator_bonding_duration()` drops from `BondingDuration` (28) to `NominatorFastUnbondDuration` (2) whenever `pallet_staking_async::AreNominatorsSlashable` flips from `true` to `false`.

On Asset Hub Polkadot, the runtime was patched with a dynamic `PostUnbondingPoolsWindow` implementation that computes the window as `BondingDuration + 4 - nominator_bonding_duration()`, keeping `TotalUnbondingPools` pinned at its historical maximum (32) regardless of the flag state, explicitly to prevent oversized `with_era` maps from becoming undecodable and being silently replaced by `Default` (empty) on the next `unbond` call: [1](#0-0) 

This mirrors the CHANGELOG entry documenting the original fix: [2](#0-1) 

However, Asset Hub Kusama's nomination pools config still uses a fixed `ConstU32<4>` for `PostUnbondingPoolsWindow`, with no dependency on `nominator_bonding_duration()`: [3](#0-2) 

Asset Hub Kusama's staking config does define `NominatorFastUnbondDuration`, gated on the same `AreNominatorsSlashable` flag from `pallet_staking_async`, with an in-code comment stating the flag is "intended to remain set to true and should not be modified via governance" — i.e., the flip path exists and is only prevented by convention, not by code: [4](#0-3) 

If `AreNominatorsSlashable` is ever set to `false` on Kusama (via the same governance/admin mechanism available on Polkadot), `nominator_bonding_duration()` drops to 2, `TotalUnbondingPools` shrinks from 32 to `2 + 4 = 6`, and any pool with unbonding sub-pools spanning more than 6 eras becomes undecodable. The next `unbond` call on such a pool will then overwrite `SubPoolsStorage` with an empty `Default`, permanently destroying the recorded per-era unbonding balances for all members of that pool — an exact repeat of the root cause already fixed for the Polkadot runtime.

### Impact Explanation
If triggered, users with pending unbonding requests older than the new (shrunk) window lose the accounting for their unbonded RSR-equivalent (KSM) stake inside nomination pools — funds become effectively unwithdrawable/lost, the same "withdrawals stuck / funds lost" impact as the original StRSR report. This is a direct, protocol-level fund-loss bug once the trigger condition occurs.

### Likelihood Explanation
The trigger (`AreNominatorsSlashable` flip) requires a governance/`StakingAdmin`-origin action, and Kusama's own code comments say this transition is not intended to happen. This mirrors the original C4 finding's disputed status: it requires an unusual, non-attacker-controlled state transition (analogous to `seizeRSR` wiping out a polity in the original report), not an arbitrary-user-triggered exploit. Given the project's own precedent of treating and fixing this exact scenario as a valid bug for Polkadot, the un-mirrored fix on Kusama represents a real regression/gap, but likelihood is lower than a directly attacker-triggerable bug because it depends on a governance decision to flip the flag.

### Recommendation
Apply the same dynamic `PostUnbondingPoolsWindow` implementation used in `asset-hub-polkadot/src/staking/nom_pools.rs` to `asset-hub-kusama/src/staking/nom_pools.rs`, pinning `TotalUnbondingPools` at its historical maximum regardless of `AreNominatorsSlashable`, so that Kusama is not left in an unsafe state if the flag is ever toggled.

### Proof of Concept
1. On Asset Hub Kusama, a nomination pool accumulates `SubPools::with_era` entries spanning close to the current maximum bound of 32 (`BondingDuration=28 + PostUnbondingPoolsWindow=4`).
2. Governance/`StakingAdmin` sets `pallet_staking_async::AreNominatorsSlashable::<Runtime>` to `false` (technically permitted, only discouraged by comment, not enforced in code) — see [5](#0-4) .
3. `nominator_bonding_duration()` now returns `NominatorFastUnbondDuration = 2` instead of 28.
4. `TotalUnbondingPools` computed by the pallet becomes `2 + 4 = 6` (using Kusama's static `ConstU32<4>`), down from 32.
5. The existing `SubPools::with_era` BoundedBTreeMap, which has more than 6 entries, fails to decode against the new bound.
6. The next `unbond` extrinsic on that pool overwrites `SubPoolsStorage` with `Default::default()`, wiping all recorded per-era unbonding balances for every member, exactly as documented and fixed for the Polkadot analog at [6](#0-5) .

```rust
/// Bound for `pallet_nomination_pools::SubPools::with_era`, frozen at its historical maximum so it
/// does not shrink when the nominator bonding duration drops.
///
/// The pallet derives its `TotalUnbondingPools` bound as `StakeAdapter::bonding_duration() +
/// PostUnbondingPoolsWindow`, and `StakeAdapter::bonding_duration()` resolves to
/// `StakingInterface::nominator_bonding_duration()`, which drops from `BondingDuration` (28) to
/// `NominatorFastUnbondDuration` (2) the moment `AreNominatorsSlashable` is set from `true` to
/// `false`. With a fixed window the bound would shrink 32 -> 6, making any oversized historical
/// `with_era` map undecodable; the next `unbond` then overwrites it with an empty `Default`,
/// destroying per-era unbonding accounting (bugbounty report #90).
///
/// We pin the bound at `BondingDuration + 4 = 32` by computing the window as `MAX -
/// nominator_bonding_duration()`. Subtracting the same value the pallet adds keeps
/// `TotalUnbondingPools == MAX` by construction, regardless of the flag. Post-flip this also widens
/// the effective merge window to `32 - 2 = 30` eras, keeping each per-era pool on its correct
/// points-to-balance ratio long enough for deferred pre-flip slashes (`SlashDeferDuration = 27`) to
/// still be applied.
///
/// TODO: this is an interim runtime fix, meant to be superseded by the in-pallet decoupling in
/// polkadot-sdk.
pub struct PostUnbondingPoolsWindow;
impl Get<u32> for PostUnbondingPoolsWindow {
	fn get() -> u32 {
		// Historical maximum number of unbonding sub-pools: the validator bonding duration plus the
		// legacy 4-era post-unbonding window. `BondingDuration` is the upper bound of
		// `nominator_bonding_duration()`, so the subtraction below never saturates.
		let max_unbonding_pools = BondingDuration::get().saturating_add(4);
		max_unbonding_pools
			.saturating_sub(<Staking as sp_staking::StakingInterface>::nominator_bonding_duration())
	}
```
