### Title
Webhook signature verification is bound to `repository.owner.login`, but event handlers act on unrelated `repository.full_name` / bare commit `sha` fields never covered by that signature - Cross-organization forgery of CI statuses/syncs - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb], [File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret used to authenticate a webhook purely from `params.dig('repository','owner','login')` (or `organization.login`) and never re-checks that field against the data the handler subsequently mutates. `Webhooks::Handlers::Handler#stacks` and `StatusHandler#process` instead act on `payload.dig('repository','full_name')` or a bare `sha`, fields that are not covered by that same signature check. This breaks the equality "organization that authenticated == repository/commit being written," letting a webhook that is validly signed for one configured GitHub organization mutate state belonging to a different repository/stack.

### Finding Description
`verify_signature` derives the signing organization exclusively from the payload: [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` resolves per-organization config (`webhook_secret`, `oauth`, etc.) via `github_app_config`, which is how a single Shipit instance can serve several GitHub organizations with independent secrets: [3](#0-2) 

`GitHubApp#verify_webhook_signature` only compares the signature against *that resolved organization's* secret, and explicitly returns `true` when no secret is configured for it: [4](#0-3) 

Once the request passes this per-`repository.owner.login` check, `WebhooksController#create` dispatches the *entire raw payload* to handlers, with no re-validation that `repository.owner.login` matches anything the handler will use: [5](#0-4) 

Handlers derive the target repository from a completely different, independently attacker-controlled field, `repository.full_name`: [6](#0-5) 

`StatusHandler` is worse: it performs no repository scoping at all, it matches by bare commit `sha` across the whole database: [7](#0-6) 

The broken equality is:
`organization_used_to_select_webhook_secret (payload.repository.owner.login / payload.organization.login)` **must equal** `organization/repository whose Stack/Commit state the handler mutates (payload.repository.full_name for PushHandler/CheckSuiteHandler; nothing at all for StatusHandler)`.

Before the fix analog would hold: this equality is never enforced anywhere in the request path, so it does not need "fixing" — it was never asserted.

### Impact Explanation
An attacker who controls, or can send webhooks as, any *one* organization configured in `Shipit.github` (including one with no `webhook_secret` set — `verify_webhook_signature` returns `true` unconditionally for such orgs, per `lib/shipit/github_app.rb` lines 76-77) can:
- Set `repository.owner.login` to that org (satisfying `verify_signature`), while setting `repository.full_name` to any other tracked repository, causing `PushHandler`/`CheckSuiteHandler` to run `stack.sync_github` or `schedule_refresh_check_runs!` against a stack/repository they were never authorized for.
- Send a `status` event where `sha` matches a real commit sha of a victim stack; `StatusHandler` will call `commit.create_status_from_github!` regardless of which organization authenticated the webhook, because no repository check exists at all in that handler.

Forged commit statuses can satisfy `required_statuses`/`blocking_statuses` gates used to compute `deployable?`, which combined with `continuous_deployment` can trigger an unauthorized automatic deploy of unreviewed/unintended code — this maps to the report's "Critical: unauthorized deploy" impact category.

### Likelihood Explanation
Exploitation requires only that the Shipit instance is configured for more than one GitHub organization (a documented, supported configuration — `TOP_LEVEL_GH_KEYS`/`github_app_config` in `lib/shipit.rb`) and that the attacker controls or can send webhooks purporting to be from at least one of them (their own legitimately-owned org, or any org whose `webhook_secret` is left unset, which `verify_webhook_signature` explicitly treats as always-valid). No GitHub App private key, `api_clients_secret`, or session is required — only the ability to POST to the public `/webhooks` endpoint with a crafted `X-Hub-Signature` for an org the attacker legitimately controls.

### Recommendation
In `WebhooksController#verify_signature` and in `Webhooks::Handlers::Handler`/`StatusHandler`, bind the organization used for signature verification to the same repository identity the handler subsequently acts on: derive `repository_owner` and `repository_name` from the same payload path, verify signature per matched `Repository`/`Stack` (not per raw `owner.login`), and scope `StatusHandler`'s `Commit.where(sha:)` lookup to commits belonging to the verified repository only.

### Proof of Concept
1. Configure Shipit for two organizations, `attacker-org` (attacker-controlled, or with `webhook_secret` left blank) and `victim-org` (hosts stack `victim-org/app`).
2. Attacker POSTs to the webhooks endpoint with `X-Github-Event: status`, a valid (or absent) signature for `attacker-org`, and body:
```json
{
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "attacker-org/app" },
  "sha": "<known sha of a commit in victim-org/app>",
  "state": "success",
  "context": "ci/required-check"
}
```
3. `verify_signature` resolves org via `repository_owner` = `attacker-org`, passes.
4. `StatusHandler#process` runs `Commit.where(sha: params.sha)` with no ownership check, attaching a forged "success" status to the victim commit, potentially satisfying `required_statuses` and enabling an unauthorized `continuous_deployment` deploy of that commit in `victim-org/app`.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
