### Title
Signing org for webhook signature is decoupled from the repository the handler mutates, allowing cross-org forgery of `pull_request` `closed` events - (File: `app/controllers/shipit/webhooks_controller.rb`, `lib/shipit/github_app.rb`, `app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to check HMAC against using `params.dig('repository','owner','login')`, while `ClosedHandler` (and all other `PullRequest` handlers) resolves the repository/stack to mutate using the independent `params.repository.full_name` field. Because these two fields are never cross-checked, and per the multi-org config schema `webhook_secret` is optional per organization [1](#0-0) , an attacker who can get a payload verified against a no-secret organization can point `repository.full_name` at an entirely different, victim-owned repository and have its `ReviewStack` archived.

### Finding Description
The broken binding: the code implicitly assumes `params.dig('repository','owner','login') == owner(params.repository.full_name)`, but nothing enforces this equality.

- `WebhooksController#verify_signature` builds `github_app = Shipit.github(organization: repository_owner)` where `repository_owner` reads `params.dig('repository', 'owner', 'login')` [2](#0-1) .
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's config has no `webhook_secret` set: `return true unless webhook_secret` [3](#0-2) .
- `Shipit.github(organization:)` looks up per-organization app config via `github_app_config(organization)`, raising `GithubOrganizationUnknown` (→ HTTP 422) only if that organization key is *not configured at all* [4](#0-3) . Multiple orgs with independently optional secrets is a documented, supported configuration [5](#0-4) .
- `ClosedHandler#repository` and `#review_stack` resolve the actual mutated repository/stack solely from `params.repository.full_name`, never from `repository_owner`: `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [6](#0-5) , then `review_stack.archive!` [7](#0-6) .

Exploit flow: with Shipit configured for ≥2 orgs (per `docs/setup.md`'s "Using Multiple Github Applications" scheme) where org `NoSecretOrg` has `webhook_secret: nil` and org `VictimOrg` (owning the real target repo) has its own secret configured, an attacker POSTs to `/webhooks` with header `X-Github-Event: pull_request`, any/garbage `X-Hub-Signature`, and body:
```json
{ "action": "closed", "number": 42,
  "repository": { "owner": {"login": "NoSecretOrg"}, "full_name": "VictimOrg/target-repo" },
  "pull_request": {...}, "sender": {"login": "attacker"} }
```
`verify_signature` resolves `Shipit.github(organization: "NoSecretOrg")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the bogus signature — no secret from `VictimOrg` is ever needed. `ClosedHandler` then resolves `Repository.from_github_repo_name("VictimOrg/target-repo")` and, if a `ReviewStack` exists for PR #42 in that repo, calls `archive!`, deprovisioning/archiving a stack belonging to a repository whose secret the attacker never authenticated against.

Existing guards do not stop this: `drop_unhandled_event`/`check_if_ping` only filter event types [8](#0-7) ; `ExplicitParameters` in `ClosedHandler` only validates JSON shape, not owner/full_name consistency [9](#0-8) ; there is no code anywhere comparing `repository_owner` against the owner segment of `params.repository.full_name`.

Regarding the "production environment" amplifier in the question: `ClosedHandler` operates only on `Shipit::ReviewStack` records, whose `environment` is programmatically fixed to `"pr#{params.number}"` at creation time [10](#0-9) , not `"production"`. There is no evidence in the reachable code path that a `ReviewStack`'s environment is ever set to `"production"`, so the "production environment" framing does not add distinct impact here — the underlying cross-org archive bypass is the real, demonstrable bug, independent of environment naming.

### Impact Explanation
An attacker can cause an unauthorized state mutation (archive/deprovision) of a `ReviewStack` belonging to a repository/organization whose webhook secret they never possessed, purely by choosing a differently-named, no-secret organization for `repository.owner.login` while pointing `repository.full_name` at the victim repo. This is a payload for one repository (the no-secret org) mutating another repository's stack — matching the Critical impact category "a payload for one repository mutating another's stack." It is repeatable against any repository configured on the same Shipit instance for as long as one org in the multi-org config lacks a webhook secret, and works for any PR number that has an active review stack.

### Likelihood Explanation
Requires: (1) Shipit deployed with the multi-organization GitHub App config schema (`secrets.github` keyed by org name), and (2) at least one configured organization with `webhook_secret` unset — both explicitly presented as supported/optional in `docs/setup.md`. Attacker cost is a single unauthenticated HTTP POST with no valid signature and no Shipit credentials. This is fully repeatable and requires no privileged role, matching the described unprivileged attacker capability.

### Recommendation
Enforce that `params.dig('repository','owner','login')` matches the owner segment of `params.repository.full_name` before dispatching to handlers, and/or verify the webhook using the App/secret associated with the organization that actually owns `full_name`, not the attacker-suppliable `owner.login` field. Additionally, do not treat an absent `webhook_secret` as automatic success — require an explicit "no verification" opt-in, and log/reject events where owner and full_name organizations diverge.

### Proof of Concept

```ruby
test "pull_request closed with owner/full_name org split archives victim repo's review stack via no-secret org" do
  secrets = ActiveSupport::OrderedOptions.new
  secrets.merge!(YAML.load_file('test/dummy/config/secrets_double_github_app.yml')) # OrgOne/OrgTwo, both webhook_secret nil per fixture
  secrets.deep_symbolize_keys!
  Shipit.stubs(:secrets).returns(secrets)

  victim_repo = Repository.create!(owner: 'orgtwo', name: 'target-repo', review_stacks_enabled: true)
  review_stack = victim_repo.review_stacks.create!(environment: 'pr42', branch: 'feature')

  # equality under test BEFORE: repository_owner ('OrgOne') != owner(full_name) ('orgtwo')
  payload = {
    action: 'closed', number: 42,
    repository: { owner: { login: 'OrgOne' }, full_name: 'orgtwo/target-repo' },
    pull_request: { id: 1, number: 42, url: 'u', title: 't', state: 'closed', additions: 1, deletions: 1,
                     head: { sha: 'x', ref: 'feature' }, user: { login: 'attacker' }, assignees: [], labels: [] },
    sender: { login: 'attacker' }
  }.to_json

  post shipit.webhooks_path, params: payload, headers: {
    'X-Github-Event' => 'pull_request',
    'X-Hub-Signature' => 'sha1=deadbeef',
    'Content-Type' => 'application/json'
  }

  assert_response :ok
  assert review_stack.reload.archived?, "victim org's review stack was archived despite no valid signature from its own org"
ensure
  Shipit.unstub(:secrets)
end
```
This demonstrates the signature check for `OrgOne` (no secret) passing trivially and the handler mutating a `ReviewStack` owned by `orgtwo`, whose secret was never presented.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
