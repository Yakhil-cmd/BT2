### Title
Scaled-debt accrual overflows `i128` before the borrow-index cap, permanently freezing a market - (File: `common/src/rates/simulate.rs`)

### Summary
A sufficiently large, highly utilized market can push `borrowed * borrow_index` beyond `i128::MAX` during interest accrual. Because accrual runs before `withdraw`, `repay`, `liquidate`, `borrow`, `supply`, and `update_indexes`, the first overflow permanently bricks that market and freezes all user funds in it.

### Finding Description
Every pool mutation loads the market and executes `interest::global_sync`, which applies `accrue_step` in chunks of at most one year. [1](#0-0) [2](#0-1) 

`accrue_step` first unscales the stored scaled debt with `scaled_to_original(env, borrowed, borrow_index)`. [3](#0-2)  `scaled_to_original` performs a checked RAY multiplication, so a product above `i128::MAX` traps with `MathOverflow`. [4](#0-3) [5](#0-4) 

The intended borrow-index cap is only applied afterward inside `update_borrow_index`. [6](#0-5)  Therefore, the protocol caps the index but not the earlier product `scaled_debt * old_index`; once that product reaches the `i128` ceiling, accrual panics before a capped index or new timestamp can be committed. [7](#0-6) 

The repository already contains a regression demonstrating the exact failure: a billion-token, 18-decimal market at 98% utilization on the XLM curve reaches the RAY-value ceiling before `MAX_BORROW_INDEX_RAY`, after which both withdrawal and repayment fail with `MathOverflow`. [8](#0-7) 

### Impact Explanation
This is a permanent freezing-of-funds condition for every supplier and borrower in the affected `(hub_id, asset)` market. The failed accrual occurs before any operation-specific state transition, so suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and permissionless index updates cannot advance the market. [9](#0-8) [10](#0-9) 

Because the panic happens before `cache.mark_accrued()` and `commit`, the stale index and timestamp remain stored; every subsequent transaction repeats the same overflowing calculation. [11](#0-10) [12](#0-11) 

### Likelihood Explanation
An unprivileged borrower can trigger the condition without privileged access by borrowing enough of a very large market and leaving utilization at the steep part of its rate curve until `borrowed * borrow_index` crosses `i128::MAX`. The attacker then calls `update_indexes(caller, vec![hub_asset])`; this entrypoint only requires caller authorization before forwarding the accrual request to the pool. [13](#0-12) 

The attack requires an extremely large market, substantial collateral-backed borrowing, and prolonged high utilization, making the capital requirement high but not relying on privileged parameters, oracle manipulation, or malformed input. The checked-in PoC shows that the configured rate curve reaches this state before the nominal index cap. [14](#0-13) 

### Recommendation
Bound the product, not only the index. Before each accrual step, derive an effective maximum borrow index such as `floor(i128::MAX / borrowed)` and clamp `new_borrow_index` to the lesser of that value and `MAX_BORROW_INDEX_RAY`, while ensuring all intermediate old/new debt calculations cannot overflow. Alternatively, compute the old and new debt values using `I256` and explicitly saturate or safely handle values exceeding the `Ray` domain. The safety invariant should be `borrowed.raw() * borrow_index.raw() <= i128::MAX * RAY` for every stored state, including the state immediately before accrual. [15](#0-14) 

### Proof of Concept
1. Use an existing 18-decimal market with the XLM-style rate curve and enough supplier liquidity, or seed it with a billion whole tokens.
2. The attacker supplies sufficient collateral in another listed market and borrows approximately 98% of the target market through `borrow(caller, account_id, spoke_id, assets)`.
3. Keep utilization near 98% and periodically invoke `update_indexes(caller, vec![target_hub_asset])` as ledger time advances.
4. When `borrowed * borrow_index` crosses the `i128` RAY-value ceiling, `accrue_step` traps at `scaled_to_original` before `update_borrow_index` can apply its cap.
5. The transaction rolls back with `MathOverflow`, leaving `last_timestamp` and the unsafe index unchanged.
6. Subsequent `withdraw`, `repay`, `liquidate`, `supply`, `borrow`, and `update_indexes` calls all repeat mandatory accrual and fail identically, permanently locking the market.

The repository's test implements this sequence with `principal = BILLION * 10^18`, `debt = 98%` of principal, repeated yearly index updates, and confirms that later withdrawal and repayment both fail with `MATH_OVERFLOW`. [16](#0-15)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
