### Title
Release asset `name` field is not sanitized before being joined into the download path, allowing path traversal writes outside `--dir` - ([File: pkg/cmd/release/download/download.go])

### Summary
`downloadRun` builds the on-disk destination path for each release asset using `filepath.Join(w.dir, name)` where `name` comes directly from the attacker-controlled `asset.Name` field returned by the GitHub API for the target release. `filepath.Join` does not confine the result to `w.dir`; a `name` containing `../` sequences can make the resulting path resolve outside the `--dir` destination, causing `gh release download` to write attacker-supplied content to an arbitrary path relative to the current working directory.

### Finding Description
In `downloadRun`, for every asset that isn't fetched via `--archive`, the code builds `downloadTarget{url: ..., name: a.Name}` directly from `release.Assets` returned by `shared.FetchRelease`/`shared.FetchLatestRelease` (`pkg/cmd/release/download/download.go:196-207`, `238-243`). No validation of `a.Name` occurs beyond an (optional) `--pattern` glob filter and a Windows-reserved-filename check (`pkg/cmd/release/download/download.go:197-207`).

This name flows to `downloadAsset` → `dest.Check(fileName)` and `dest.Copy(fileName, ...)`, both of which call `destinationWriter.makePath`:
```go
func (w destinationWriter) makePath(name string) string {
	if w.file == "" {
		return filepath.Join(w.dir, name)
	}
	return w.file
}
``` [1](#0-0) 

`filepath.Join` calls `filepath.Clean` on the concatenated path but performs no confinement check against `w.dir`. A `name` such as `"../../.ssh/authorized_keys"` joined with a `dir` of `"."` cleans to `"../../.ssh/authorized_keys"` — outside the destination directory (and even outside the current working directory). `Copy` then creates any missing parent directories via `os.MkdirAll(dir, 0755)` (`pkg/cmd/release/download/download.go:435-439`) and writes attacker-controlled asset bytes to that path with `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)` (`pkg/cmd/release/download/download.go:442`).

Because `asset.Name` is set by whoever uploads assets to a release — an unprivileged attacker who owns/controls the repository, e.g. via the API `POST /repos/{owner}/{repo}/releases/{id}/assets?name=...` — the attacker fully controls this string. No allowlist, `filepath.Base`, or `safepaths`-style confinement is applied to it anywhere in `download.go` or `shared/fetch.go`. The only sanitization present is on the *fallback* name derived from `Content-Disposition` (`filepath.Base(serverFileName)` at `pkg/cmd/release/download/download.go:344`), which is unrelated and only used when `fileName` is empty (i.e. `--archive` mode).

### Impact Explanation
This is an out-of-bounds file write: a victim running `gh release download <tag>` against an attacker-owned repository without a restrictive `--pattern` can have arbitrary attacker-controlled content written to paths outside the chosen `--dir`/`--output` destination, limited only by the victim's OS filesystem permissions (e.g. overwriting `~/.ssh/authorized_keys`, shell rc files, or other files reachable via relative traversal from the working directory). This matches GitHub's "file write outside intended path" bounty impact class.

### Likelihood Explanation
- Precondition: victim runs `gh release download` (with or without a tag) pointed at a repository/release controlled by the attacker, without a `--pattern` that would restrict matched names to safe values.
- The attacker only needs to upload a release asset with a crafted `name` (e.g. via the GitHub REST API's asset name parameter), which is standard, unprivileged repo-owner functionality.
- No authentication bypass, MITM, or victim misconfiguration beyond normal usage is required, making this readily reproducible.

### Recommendation
Sanitize/confine `asset.Name` before use: reject or strip path separators and `..` components (e.g. require `filepath.Base(name) == name`), and/or verify that `filepath.Join(dir, name)` remains lexically within `filepath.Clean(dir)` (using `filepath.Rel` and checking for a leading `..`) before calling `Check`/`Copy` in `destinationWriter.makePath`.

### Proof of Concept
```go
func TestDownloadRun_AssetNamePathTraversal(t *testing.T) {
	reg := &httpmock.Registry{}
	shared.StubFetchRelease(t, reg, "OWNER", "REPO", "v1.2.3", `{
		"tag_name": "v1.2.3",
		"assets": [
			{ "url": "https://api.github.com/assets/1234",
			  "name": "../../.ssh/authorized_keys",
			  "content_type": "text/plain" }
		]
	}`)
	reg.Register(
		httpmock.REST("GET", "assets/1234"),
		httpmock.StringResponse(`attacker-controlled-key-material`),
	)

	tmpDir := t.TempDir()
	safeDir := filepath.Join(tmpDir, "downloads")
	os.MkdirAll(safeDir, 0755)

	opts := &DownloadOptions{
		HttpClient: func() (*http.Client, error) { return &http.Client{Transport: reg}, nil },
		IO:         iostreams.Test(),
		BaseRepo:   func() (ghrepo.Interface, error) { return ghrepo.New("OWNER", "REPO"), nil },
		TagName:    "v1.2.3",
		Destination: safeDir,
		Concurrency: 1,
	}

	err := downloadRun(opts)
	require.NoError(t, err)

	// Assert: the file must NOT exist outside safeDir.
	escapedPath := filepath.Join(tmpDir, ".ssh", "authorized_keys")
	_, statErr := os.Stat(escapedPath)
	assert.True(t, os.IsNotExist(statErr), "expected no write outside destination, but found: %s", escapedPath)
}
```
Expected current (vulnerable) behavior: the test fails because `authorized_keys` is written outside `safeDir`. After applying the recommended fix, `downloadRun` should return an error (or confine the write inside `safeDir`), and the assertion should pass.
