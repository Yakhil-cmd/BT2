### Title
Stale Remote-Proxy Delegation Remains Usable After Revocation on the Remote Chain — (File: `pallets/remote-proxy/src/lib.rs`)

### Summary
`pallet-remote-proxy` lets an account act as a proxy for a "real" account by proving, via a Merkle proof against a *historical* relay-chain storage root, that a `pallet_proxy::ProxyDefinition` existed for it. Just like the LSP6 finding — where a permission grant is a "universal" fact independent of any owner/revocation epoch, so a stale grant remains exercisable after the underlying relationship should no longer apply — this pallet authorizes delegation based on a **cached historical root** rather than the **current** state of the remote proxy relationship, and the pallet's own documentation acknowledges the resulting window in which a revoked delegate can still act.

### Finding Description
`do_remote_proxy` looks up a storage root from the bounded `BlockToRoot` cache and verifies the supplied proof against that cached (potentially old) root, then extracts a `ProxyDefinition` and immediately dispatches the wrapped call as if the delegation were still current: [1](#0-0) 

The `BlockToRoot` storage is a bounded ring buffer of the last `MaxStorageRootsToKeep` roots: [2](#0-1) 

The pallet's own module documentation explicitly states the consequence: once a proxy is removed on the remote chain, it can still be used locally until the cached root referencing the old state ages out of `MaxStorageRootsToKeep`: [3](#0-2) 

This is the same vulnerability *class* as the LSP6 finding: authorization data ("the delegate has permission X") is checked against a snapshot that is not guaranteed to reflect the current, intended state of ownership/permissions, and the contract/pallet has no mechanism to invalidate historical proofs immediately upon revocation — there is no nonce/epoch tied to the revocation event that would make old proofs worthless, analogous to the LSP6 report's proposed mitigation ("add a nonce upon ownership transfer").

### Impact Explanation
An account that a user (the "real" account owner) has removed as a proxy on the remote (relay) chain can continue to submit `remote_proxy` / `remote_proxy_with_registered_proof` calls and successfully act on behalf of the "real" account on the local (system parachain) side, for as long as a storage root pre-dating the removal is still retained in `BlockToRoot`. The permission set exercised is bounded by `InstanceFilter` (`ProxyType::filter`) and the anti-escalation checks in `do_proxy`, so the residual access cannot exceed what the removed delegate already had — but within that scope it can still move funds, submit staking/governance actions, etc., depending on `ProxyType`. This mirrors the LSP6 concern: the previous authorized party retains meaningful control after the owner believes the relationship has ended.

### Likelihood Explanation
This requires no privileged role: any account previously delegated as a proxy on the relay chain can hold an old proof and replay it via a normal signed extrinsic (`remote_proxy`) at any time before `MaxStorageRootsToKeep` roots have rotated past the block at which the proxy still existed. The likelihood of an actual attack is tempered by the fact that this is a bounded, known-in-advance window (the code comment documents it as an accepted trade-off of the design, similar to how the LUKSO sponsor accepted the LSP6 issue as a known limitation of universal permission keys), and by the requirement that the malicious delegate already had proxy permissions in the first place — matching the judge's rationale in the referenced report that "the conditionals and the unfounded trust required... make the finding not eligible for High severity," while still being "eye-opening" because ordinary users removing a proxy would reasonably assume it is immediately revoked everywhere.

### Recommendation
Reduce the acceptable staleness window (or make `MaxStorageRootsToKeep` sufficiently small / configurable per risk tolerance) and, more importantly, follow the same mitigation pattern proposed for the LSP6 issue: tie proxy validity to a monotonically increasing epoch/nonce that is bumped locally whenever the real account observes/acts on a remote proxy removal, or require proofs to reference a root no older than a strict, short freshness bound rather than any of the `MaxStorageRootsToKeep` cached roots. Documented awareness alone does not eliminate the underlying "stale-permission-remains-valid" risk; consider requiring an explicit local acknowledgment/de-authorization extrinsic that immediately invalidates all older proofs for a given delegate once revocation is observed.

### Proof of Concept
1. Account `A` (owner) creates a pure/derived proxy account `P` on the relay chain and adds `D` as a proxy for `P` with `ProxyType::X`.
2. `D` obtains (or is given by `A`, e.g. during a period of legitimate cooperation) a Merkle proof of this `ProxyDefinition` anchored at relay-chain block `B`, which gets cached into `BlockToRoot` on the system parachain via `on_validation_data`. [2](#0-1) 
3. `A` removes `D` as a proxy for `P` on the relay chain.
4. As long as block `B`'s root has not yet rolled out of the `MaxStorageRootsToKeep` window, `D` can still call `remote_proxy(real: P, proof: <old proof for block B>, call: ...)` and have it succeed, because `do_remote_proxy` only checks the proof against the cached historical root, not against the current remote state. [4](#0-3) 
5. The call executes with `D`'s stale permissions via `do_proxy`, even though `A` believes the delegation has been revoked. [5](#0-4)

	impl<T: Config<I>, I: 'static> Pallet<T, I> {
		fn do_remote_proxy(
			who: T::AccountId,
			real: T::AccountId,
			force_proxy_type: Option<T::ProxyType>,
			call: <T as pallet_proxy::Config>::RuntimeCall,
			proof: RemoteProxyProof<RemoteBlockNumberOf<T, I>>,
		) -> DispatchResult {
			let Some(real_remote) = T::RemoteProxy::local_to_remote_account_id(&real) else {
				return Err(Error::<T, I>::CouldNotConvertLocalToRemoteAccountId.into());
			};

			let def = match proof {
				RemoteProxyProof::RelayChain { proof, block } => {
					let roots = BlockToRoot::<T, I>::get();

					let Ok(storage_root) = roots
						.binary_search_by(|(b, _)| b.cmp(&block))
						.map(|pos| roots[pos].1.clone())
					else {
						return Err(Error::<T, I>::UnknownProofAnchorBlock.into());
					};

					let key = T::RemoteProxy::proxy_definition_storage_key(&real_remote);

					let db =
						sp_trie::StorageProof::new(proof).into_memory_db::<RemoteHasherOf<T, I>>();
					let value = sp_trie::read_trie_value::<sp_trie::LayoutV1<_>, _>(
						&db,
						&storage_root,
						&key,
						None,
						None,
					)
					.ok()
					.flatten()
					.ok_or(Error::<T, I>::InvalidProof)?;

					let proxy_definitions = alloc::vec::Vec::<
						ProxyDefinition<
							RemoteAccountIdOf<T, I>,
							RemoteProxyTypeOf<T, I>,
							RemoteBlockNumberOf<T, I>,
						>,
					>::decode(&mut &value[..])
					.map_err(|_| Error::<T, I>::ProxyDefinitionDecodingFailed)?;

					let f = |x: &ProxyDefinition<
						T::AccountId,
						T::ProxyType,
						BlockNumberFor<T>,
					>|
					 -> bool {
						x.delegate == who &&
							force_proxy_type.as_ref().is_none_or(|y| &x.proxy_type == y)
					};

					proxy_definitions
						.into_iter()
						.filter_map(T::RemoteProxy::remote_to_local_proxy_defintion)
						.find(f)
						.ok_or(Error::<T, I>::DidNotFindMatchingProxyDefinition)?
				},
			};

			ensure!(def.delay.is_zero(), Error::<T, I>::Unannounced);

			Self::do_proxy(def, real, call);

		fn do_proxy(
			def: ProxyDefinition<T::AccountId, T::ProxyType, BlockNumberFor<T>>,
			real: T::AccountId,
			call: <T as pallet_proxy::Config>::RuntimeCall,
		) {
			use frame_support::traits::{InstanceFilter as _, OriginTrait as _};
			// This is a freshly authenticated new account, the origin restrictions doesn't apply.
			let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(real).into();
			origin.add_filter(move |c: &<T as frame_system::Config>::RuntimeCall| {
				let c = <T as pallet_proxy::Config>::RuntimeCall::from_ref(c);
				// We make sure the proxy call does not modify proxies.
				match c.is_sub_type() {
					// Proxy call cannot add or remove a proxy with more permissions than it already
					// has.
					Some(pallet_proxy::Call::add_proxy { ref proxy_type, .. }) |
					Some(pallet_proxy::Call::remove_proxy { ref proxy_type, .. })
						if !def.proxy_type.is_superset(proxy_type) =>
						false,
					// Proxy call cannot remove all proxies or kill pure proxies unless it has full
					// permissions.
					Some(pallet_proxy::Call::remove_proxies { .. }) |
					Some(pallet_proxy::Call::kill_pure { .. })
						if def.proxy_type != T::ProxyType::default() =>
						false,
					_ => def.proxy_type.filter(c),
				}
			});
			let e = call.dispatch(origin);
