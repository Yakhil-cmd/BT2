### Title
Cross-organization forgery of GitHub webhook events via mismatched signature-selection field vs. repository-lookup field - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In a multi-GitHub-organization Shipit deployment, `WebhooksController#verify_signature` selects the HMAC secret to validate a webhook against using `repository.owner.login` from the JSON body, while every event `Handler` (e.g. `StatusHandler`, `PushHandler`) resolves the target `Repository`/`Stack` using a *different* field, `repository.full_name`. Because the two fields are never cross-checked, an attacker who legitimately controls one configured organization's webhook secret can craft a payload whose `owner.login` matches their own org (so the signature validates) but whose `full_name` points at a repository/stack belonging to a completely different, victim organization tracked by the same Shipit instance.

`organization whose secret authenticated the request == organization that owns the repository the handler acts on`

Meanwhile, every `Handler` subclass resolves the `Stack`/`Repository` it operates on from a separate field of the same body: [3](#0-2) 

`Repository.from_github_repo_name` splits this string on `/` and looks up the repository by `owner`/`name` independently of whichever `owner.login` was used for signature selection: [4](#0-3) 

Shipit explicitly supports configuring one GitHub App (and thus one webhook secret) per organization when multiple orgs are onboarded: [5](#0-4) 

`docs/setup.md` documents this multi-org mode is a normal supported deployment topology. Any org owner who is issued a legitimate `webhook_secret` for their own org (e.g. `OrgOne`) can compute a valid `X-Hub-Signature` over an arbitrary raw JSON body, then set `repository.owner.login` to `"OrgOne"` (so `verify_signature` fetches `OrgOne`'s secret and the check passes) while setting `repository.full_name` to `"OrgTwo/victim-repo"` — a stack belonging to a different, victim organization. Nothing in the controller or in `Handler#repository_name`/`Repository.from_github_repo_name` requires that the two fields agree.

This directly satisfies the required binding-break pattern: "an organization that authenticated versus the repository that is written."

### Impact Explanation
Once the signature check is bypassed for a foreign repository, an attacker (who is not a collaborator, member, or install of the victim org at all) can drive any registered webhook `Handler` against the victim's `Stack`:
- `StatusHandler` writes an arbitrary commit `Status` (state, context, description, target_url) for any SHA already known to Shipit, purely from webhook fields with no call back to GitHub for verification: [6](#0-5)  — statuses are used by `Stack`/`Commit` to gate whether a commit is safe to deploy, so a forged "success" status can make an unreviewed/failing commit appear deployable, contributing to an unauthorized deploy.
- `PushHandler` can trigger `stack.sync_github(expected_head_sha:)` for the victim's stack/branch on attacker-chosen input: [7](#0-6) 
- `pull_request` handlers can create/close/unarchive review stacks and mutate PR label state for the victim repository, e.g. `OpenedHandler#repository`/`process`: [8](#0-7) 

This escalates an attacker who only holds credentials for one tenant org into acting on a different org's deployment state, matching the "High: escalation into authorization boundary / unauthorized deploy or rollback" impact class.

### Likelihood Explanation
The webhook endpoint is unauthenticated apart from the HMAC check (`skip_before_action :verify_authenticity_token`), so it is reachable by anyone who can send an HTTP POST: [9](#0-8) 

The attack requires:
1. Shipit is deployed in multi-org mode (documented as a normal configuration).
2. Attacker has legitimate webhook secret for at least one configured org (e.g., is an org owner or has been issued the secret).
3. Attacker knows the `full_name` of a victim repository tracked by the same Shipit instance (easily discoverable from public GitHub or from Shipit's own UI if it is exposed).

All three are realistic in a shared Shipit instance serving multiple organizations.

### Recommendation
In `WebhooksController#verify_signature`, after validating the signature, extract the `repository.owner.login` from the parsed payload and verify it matches the `organization` parameter passed to `Shipit.github()`. Reject the request (422) if they do not match.

Alternatively, require that all webhook handlers validate that the organization extracted from the signature check matches the organization of the repository they are about to act on, before proceeding.

### Proof of Concept
1. Set up Shipit with two GitHub organizations configured:
   - `OrgOne` with webhook secret `secret_one`
   - `OrgTwo` with webhook secret `secret_two`
   - Both have repositories and stacks tracked in Shipit.

2. Attacker (who controls `OrgOne` and knows `secret_one`) crafts a push webhook payload:
   ```json
   {
     "ref": "refs/heads/main",
     "after": "abc123def456...",
     "repository": {
       "full_name": "OrgTwo/victim-repo",
       "owner": {
         "login": "OrgOne"
       }
     }
   }
   ```

3. Attacker computes `X-Hub-Signature: sha1=<HMAC-SHA1(secret_one, raw_body)>` and POSTs to `/webhooks`.

4. `verify_signature` extracts `repository_owner = "OrgOne"`, fetches `secret_one`, validates the signature ✓, and allows the request through.

5. `PushHandler#process` calls `Handler#stacks`, which calls `Handler#repository_name` → `payload.dig('repository', 'full_name')` → `"OrgTwo/victim-repo"`.

6. `Repository.from_github_repo_name("OrgTwo/victim-repo")` finds the victim repository and returns its stacks.

7. `PushHandler` calls `stack.sync_github()` on the victim's stack, triggering a deploy sync for a branch the attacker does not control. [10](#0-9)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
