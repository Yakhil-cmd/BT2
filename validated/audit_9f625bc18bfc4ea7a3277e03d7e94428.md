### Verdict

### Title
Unauthenticated Bridge Peer Can Corrupt Parent Operator Nonce via Crafted `ServiceChainParentChainInfoResponseMsg` — (`node/sc/sub_bridge_handler.go`)

### Summary
Any P2P peer that connects to the SubBridge with the correct chain ID can send a crafted `ServiceChainParentChainInfoResponseMsg` containing an arbitrarily large `Nonce`. When the `bridgeTxPool` is empty (`poolNonce == 0`), `handleParentChainInfoResponseMsg` unconditionally writes the peer-supplied nonce into `accountInfo.nonce` with no on-chain validation. All subsequent anchoring and value-transfer transactions are then submitted with a nonce gap, causing them to be permanently stuck in the parent-chain mempool and locking bridged assets.

### Finding Description
`handleParentChainInfoResponseMsg` decodes `pcInfo.Nonce` from the wire and, in the `poolNonce == 0` branch, calls `setParentOperatorNonce(pcInfo.Nonce)` unconditionally. [7](#0-6) 

There is no comparison against the actual on-chain pending nonce (e.g., via `PendingNonceAt`). The peer authentication in `RegisterNewPeer` only checks chain ID, so any reachable node can inject this message. [4](#0-3) 

### Impact Explanation
- `genUnsignedChainDataAnchoringTx` uses `getParentOperatorNonce()` as the tx nonce.
- With a corrupted nonce of 1000 and an on-chain nonce of 5, every anchoring and value-transfer tx is submitted with nonce 1000, creating a gap of 995.
- The parent-chain mempool queues these txs indefinitely; they are never mined.
- Bridged assets awaiting confirmation are permanently locked. [5](#0-4) 

### Likelihood Explanation
The bridge P2P server accepts inbound connections from any peer presenting the correct chain ID. If the bridge P2P port is reachable (not firewalled), the attack requires only connecting and sending one crafted message. The attacker can maintain the corruption by staying connected and responding to every `SyncNonceAndGasPrice` broadcast before the legitimate MainBridge peer does.

### Recommendation
1. After decoding `pcInfo.Nonce`, validate it against the actual on-chain pending nonce via `PendingNonceAt` before accepting it.
2. Enforce that only the configured parent-chain bridge node (by node ID / static peer list) can send `ServiceChainParentChainInfoResponseMsg`.
3. Add a sanity bound: reject any received nonce that exceeds the current stored nonce by more than a configurable threshold.

### Proof of Concept
1. Start a SubBridge with `bridgeTxPool` empty and on-chain operator nonce = 5.
2. Connect a mock peer with the correct chain ID.
3. Send `ServiceChainParentChainInfoResponseMsg` with `Nonce = 1000`.
4. Assert `getParentOperatorNonce() == 1000`.
5. Trigger `generateAndAddAnchoringTxIntoTxPool`; assert the generated tx has `Nonce == 1000`.
6. Submit the tx to the parent chain; observe it queued but never mined due to the nonce gap.

func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
}
