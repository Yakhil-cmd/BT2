### Title
Webhook signature is validated against the organization named in `repository.owner.login`, but the handler acts on the unrelated `repository.full_name` field — allowing cross-tenant stack forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks which GitHub App/organization secret to validate a webhook's HMAC signature against based on `repository.owner.login` (or `organization.login`) taken directly from the unverified JSON body. Once the signature check passes, the event is dispatched to a handler (e.g. `PushHandler`) that resolves the target `Stack`/`Repository` using a completely different, independently attacker-controlled field: `repository.full_name`. Because these two fields are never cross-checked, an organization onboarded to a multi-tenant Shipit instance can forge a webhook that authenticates as itself but acts on any other organization's repository/stack.

### Finding Description
`verify_signature` derives the authenticating organization purely from body content and uses it to select the webhook secret: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` looks up that organization's own `webhook_secret` from the multi-tenant config and uses it to verify the HMAC signature: [3](#0-2) [4](#0-3) 

If the request truly originated from an org admin who owns `repository.owner.login`'s webhook secret, the signature check trivially passes for a payload they crafted themselves (they know their own secret).

After the signature check passes, `create` dispatches the same raw `params` hash to the matching handler: [5](#0-4) 

The base `Handler` class (used by `PushHandler`, `StatusHandler`, `CheckSuiteHandler`, `MembershipHandler`, and pull-request handlers) resolves the target stacks using `repository.full_name` — a field never checked against the `repository.owner.login`/`organization.login` used for authentication: [6](#0-5) 

`PushHandler` then triggers a real GitHub sync for any stack backed by that repository: [7](#0-6) 

This breaks the binding: *organization that authenticated (`repository.owner.login` → org's `webhook_secret`) ≠ repository that is written (`repository.full_name` → `Repository.from_github_repo_name` → `Stack#sync_github`)*.

### Impact Explanation
An organization/tenant that has legitimately configured its own webhook secret on this multi-tenant Shipit instance can forge a `push` (or other) webhook where `repository.owner.login` = its own org (to pass signature verification) but `repository.full_name` = a victim organization's repository. This causes `Stack#sync_github` to run against the victim's stack using expected head SHAs of the attacker's choosing, forcing out-of-band GitHub syncs, spurious commit ingestion, and potential deploy-pipeline state changes on repositories the attacker does not own or control — a cross-repository/cross-tenant write triggered without any credential belonging to the victim organization.

### Likelihood Explanation
Exploitable by any tenant/organization already onboarded with its own webhook secret in this multi-tenant deployment (`Shipit.github_organizations`/`github_app_config`) — no access to the victim's secret, `GITHUB_TOKEN`, or any privileged Shipit account is required. The only precondition is a multi-organization deployment, which is an explicitly supported configuration path (`github_default_organization`, `github_app_config`).

### Recommendation
Verify that `repository.owner.login` (or `organization.login`) used to select the webhook secret matches the owner embedded in `repository.full_name` before dispatching to handlers, or better, bind the authenticated organization identity to the `Repository`/`Stack` lookup path in `Handler#stacks` so a payload can only ever act on repositories belonging to the organization whose secret validated the signature.

### Proof of Concept
1. Deploy Shipit configured with two tenant organizations, `attacker-org` and `victim-org`, each with its own `webhook_secret` (multi-tenant `secrets.github` schema).
2. As an admin of `attacker-org`, craft a JSON payload for the `push` event:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Sign the raw body with `attacker-org`'s own `webhook_secret` using `sha1=HMAC-SHA1(secret, body)`, and POST it to `/webhooks` with header `X-Hub-Signature`.
4. `verify_signature` resolves `repository_owner` = `"attacker-org"`, fetches `attacker-org`'s secret, and the signature check passes (`app/controllers/shipit/webhooks_controller.rb:24-30,59-62`).
5. `PushHandler` (via `Handler#stacks`/`#repository_name`, `app/models/shipit/webhooks/handlers/handler.rb:32-38`) resolves `Repository.from_github_repo_name("victim-org/victim-repo")` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on `victim-org`'s stack — a write performed on a repository the attacker never authenticated for.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
