### Title
Unauthenticated Bridge Peer Can Corrupt `remoteGasPrice` to `uint64_max` via Crafted `ServiceChainParentChainInfoResponseMsg`, Draining Bridge Operator Funds and Halting Bridge Operations — (`node/sc/sub_bridge_handler.go`)

### Summary
A malicious node that connects to the sub-bridge as a P2P bridge peer (requiring only chainID knowledge and network access) can send a crafted `ServiceChainParentChainInfoResponseMsg` with `IsMagmaEnabled=true` and `KIP71Config.UpperBoundBaseFee=math.MaxUint64`. The `setRemoteChainValues` function assigns this value directly to `sbh.remoteGasPrice` without any validation. All subsequent anchoring transactions generated by `genUnsignedChainDataAnchoringTx` will carry `TxValueKeyGasPrice = math.MaxUint64`, draining the bridge operator's KAIA balance on the parent chain and halting all bridge operations.

### Finding Description
In `setRemoteChainValues`, when `pcInfo.IsMagmaEnabled` is true, `sbh.remoteGasPrice` is overwritten with the peer-supplied `pcInfo.KIP71Config.UpperBoundBaseFee` with no upper-bound validation:

```go
// node/sc/sub_bridge_handler.go:191
sbh.remoteGasPrice = pcInfo.KIP71Config.UpperBoundBaseFee
```

This value is then used verbatim in `genUnsignedChainDataAnchoringTx`:

```go
// node/sc/sub_bridge_handler.go:339
types.TxValueKeyGasPrice: new(big.Int).SetUint64(sbh.remoteGasPrice),
```

The only peer admission check is chainID equality in `RegisterNewPeer`. There is no allowlist, no cryptographic identity pinning, and no message-level authentication.

### Impact Explanation
- **Financial**: Every anchoring transaction submitted to the parent chain carries `GasPrice = math.MaxUint64`. If the bridge operator has sufficient balance, each transaction consumes `100000 * math.MaxUint64` gas-equivalent KAIA, rapidly draining the operator account.
- **Operational halt**: Once the operator balance is exhausted, all anchoring transactions and value-transfer handle transactions fail, permanently halting the bridge until manual intervention.
- This constitutes an unauthorized fee charge against system-managed bridge operator funds and persistent disruption of cross-chain asset transfers.

### Likelihood Explanation
The sub-bridge's P2P port is publicly reachable (required for it to connect to the parent chain). The chainID is public. An attacker needs only to:
1. Dial the sub-bridge's P2P port.
2. Complete the standard devp2p handshake with the correct chainID.
3. Send one crafted `ServiceChainParentChainInfoResponseMsg`.

No privileged access, no key compromise, no validator collusion required.

### Recommendation
In `setRemoteChainValues`, validate the peer-supplied `UpperBoundBaseFee` against a locally-derived or operator-configured maximum before assigning it to `remoteGasPrice`. At minimum, reject values that exceed a reasonable upper bound (e.g., the locally observed base fee multiplied by a safety factor). Additionally, consider pinning bridge peer identity to a configured allowlist of trusted parent-chain node IDs rather than relying solely on chainID matching.

### Proof of Concept
1. Craft a `parentChainInfo` struct: `{Nonce: 0, GasPrice: 1, KIP71Config: {UpperBoundBaseFee: math.MaxUint64, ...}, IsMagmaEnabled: true}`.
2. Connect a test node to the sub-bridge's P2P port with the correct chainID.
3. Send this struct as a `ServiceChainParentChainInfoResponseMsg`.
4. Trigger `generateAndAddAnchoringTxIntoTxPool` on the sub-bridge.
5. Assert that the generated anchoring transaction has `GasPrice() == math.MaxUint64`.

func (sbh *SubBridgeHandler) handleParentChainInfoResponseMsg(p BridgePeer, msg p2p.Msg) error {
	var pcInfo parentChainInfo
	if err := msg.Decode(&pcInfo); err != nil {
		logger.Error("failed to decode", "err", err)
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	sbh.LockParentOperator()
	defer sbh.UnLockParentOperator()

	poolNonce := sbh.subbridge.bridgeTxPool.GetMaxTxNonce(sbh.GetParentOperatorAddr())
	if poolNonce > 0 {
		poolNonce += 1
		// just check
		if sbh.getParentOperatorNonce() > poolNonce {
			logger.Error("parent chain operator nonce is bigger than the chain pool nonce.", "BridgeTxPoolNonce", poolNonce, "mainChainAccountNonce", sbh.getParentOperatorNonce())
		}
		if poolNonce < pcInfo.Nonce {
			// BridgeTxPool journal miss txs which already sent to parent-chain
			logger.Error("chain pool nonce is less than the parent chain nonce.", "chainPoolNonce", poolNonce, "receivedNonce", pcInfo.Nonce)
			sbh.setParentOperatorNonce(pcInfo.Nonce)
		} else {
			// BridgeTxPool journal has txs which don't receive receipt from parent-chain
			sbh.setParentOperatorNonce(poolNonce)
		}
	} else if sbh.getParentOperatorNonce() > pcInfo.Nonce {
		logger.Error("parent chain operator nonce is bigger than the received nonce.", "mainChainAccountNonce", sbh.getParentOperatorNonce(), "receivedNonce", pcInfo.Nonce)
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	} else {
		// there is no tx in bridgetTxPool, so parent-chain's nonce is used
		sbh.setParentOperatorNonce(pcInfo.Nonce)
	}
	sbh.setParentOperatorNonceSynced(true)
	sbh.setRemoteChainValues(pcInfo)
	logger.Info("ParentChainNonceResponse", "receivedNonce", pcInfo.Nonce, "gasPrice", pcInfo.GasPrice, "mainChainAccountNonce", sbh.getParentOperatorNonce())
	return nil
}
