### Title
Webhook signature verification is scoped to the payload-declared organization, but state-mutating handlers act on repositories/commits without re-validating that binding — ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App / `webhook_secret` to validate a webhook against using `repository_owner`, a value read directly out of the *unauthenticated* JSON body (`params.dig('repository','owner','login')`) [1](#0-0) [2](#0-1) . Once that check passes, the actual event handler that mutates data uses other, independent fields of the *same* payload to decide what to write — and at least one of them, `Shipit::Webhooks::Handlers::StatusHandler`, performs no repository/organization scoping at all: it matches by `sha` across the entire `commits` table [3](#0-2) . This breaks the equality "organization whose secret authenticated the request" == "repository/stack/commit that gets written," which is exactly the class of bug described in the external report (a value used for one authorization decision, not equal to the value that ends up being acted upon).

### Finding Description
`Shipit.github(organization:)` resolves a distinct `GitHubApp` (and its own `webhook_secret`) per organization, and Shipit explicitly documents and supports running multiple GitHub Apps for multiple organizations from one instance [4](#0-3) [5](#0-4) . `webhook_secret` is optional per organization — the shipped example configs explicitly show it left blank (`webhook_secret: # nil`) as a supported value [6](#0-5) [7](#0-6) , and `verify_webhook_signature` explicitly treats a blank secret as "always verified":
```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
``` [8](#0-7) 

`WebhooksController#verify_signature` picks the app/secret to check against using `repository_owner`, computed purely from the JSON body, before any cryptographic check has occurred:
```
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(...)
  ...
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
``` [1](#0-0) [2](#0-1) 

Only that one field — `repository.owner.login` — is bound to "which secret verified this request." Nothing ties the rest of the payload (the `sha`, the `repository.full_name`, `organization.login` used by other handlers) to that same organization. `StatusHandler`, which is dispatched for every `status` event that passes `verify_signature`, ignores `repository` entirely and matches globally:
```
def process
  Commit.where(sha: params.sha).each do |commit|
    commit.create_status_from_github!(params)
  end
end
``` [3](#0-2) 

`Commit` rows are global to the Shipit instance and can belong to stacks under any configured organization; `create_status_from_github!` creates a real `Status` record used for CI/deploy gating [9](#0-8) [10](#0-9) .

Concretely, the binding that should hold is:

`organization whose webhook_secret verified the request` == `organization owning the stack/commit that the handler mutates`

but is not enforced: `verify_signature` only checks the former against `repository.owner.login`; `StatusHandler` never checks the latter at all, and other handlers (e.g. `PushHandler`'s `Repository.from_github_repo_name(payload.dig('repository','full_name'))`) derive the target repository from a *different* field of the same unauthenticated JSON body that is never required to match `repository.owner.login` [11](#0-10) [12](#0-11) .

### Impact Explanation
An attacker with zero Shipit credentials can send an entirely unsigned (or trivially-passing) `status` webhook to `/webhooks` claiming `repository.owner.login` equal to any organization configured in `secrets.github` that has a blank `webhook_secret` (a supported, documented configuration). `verify_signature` will pass unconditionally for that organization [8](#0-7) , yet the attacker can put an arbitrary `sha` belonging to a commit under a completely different, properly-secured organization's stack in the same request body. `StatusHandler` will create a forged `Status` (any `state`, any `context`) on that commit with no ownership check [3](#0-2) . Because `ci.require` in `shipit.yml` gates deploys/merges on the presence of specific status contexts [13](#0-12) , an attacker can forge a passing status for a required context and unblock a deploy/merge on a stack they have no legitimate authorization over — an unauthorized deploy/merge, which the rules classify as Critical.

### Likelihood Explanation
No credentials, tokens, or knowledge of any secured organization's `webhook_secret` are required — only the existence of one configured organization (in a multi-org Shipit install, or the default single-org install where `webhook_secret` is left unset per the shipped example config) whose secret is blank. `POST /webhooks` is publicly reachable by design (it's the GitHub webhook endpoint) and the controller performs no other authentication before dispatching to handlers [14](#0-13) .

### Recommendation
Bind the handler's target resource to the organization that was actually cryptographically verified, not to an independent field of the unauthenticated payload:
- Pass the verified `repository_owner`/organization from `WebhooksController` into each handler and require handlers to scope their queries/mutations to that organization (e.g., `StatusHandler` should scope `Commit.where(sha:)` to commits whose `stack.repository.owner` matches the verified organization).
- Alternatively/additionally, require `repository.owner.login` used for verification to equal the owner portion of `repository.full_name` used by handlers before dispatching, rejecting mismatches.
- Treat organizations with a blank `webhook_secret` as unauthenticated sources whose payloads must not be allowed to reference/mutate resources belonging to other, secret-protected organizations.

### Proof of Concept
1. Deploy Shipit with two organizations configured in `secrets.github`: `OrgNoSecret` (no `webhook_secret`, per the documented supported config) and `OrgSecure` (has `webhook_secret` set and a stack tracking commit `abc123...` with `ci.require: ["ci/tests"]`).
2. Attacker sends, with no valid `X-Hub-Signature` for `OrgSecure`:
```
POST /webhooks
X-Github-Event: status

{
  "repository": {"owner": {"login": "OrgNoSecret"}},
  "sha": "abc123...",           // commit belongs to a stack under OrgSecure
  "state": "success",
  "context": "ci/tests",
  "target_url": "http://attacker.example"
}
```
3. `verify_signature` resolves `Shipit.github(organization: "OrgNoSecret")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (absent/invalid) signature header [8](#0-7) .
4. `StatusHandler#process` runs `Commit.where(sha: "abc123...")` and creates a `success`/`ci/tests` status on the `OrgSecure` commit, with no check that it belongs to `OrgNoSecret` [3](#0-2) .
5. The forged status satisfies `OrgSecure`'s `ci.require` gate, unblocking a deploy/merge that a legitimately-authenticated GitHub webhook for `OrgSecure` never approved.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
