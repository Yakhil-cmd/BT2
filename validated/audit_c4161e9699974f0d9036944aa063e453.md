Based on my analysis of the code, I need to trace the full attack path carefully.

**Attack path:**

1. `SubBridge.handleMsg` reads any message from a connected bridge peer and dispatches to `SubBridgeHandler.HandleMainMsg`
2. `HandleMainMsg` routes `ServiceChainInvalidTxResponseMsg` (code `0x09`) to `handleParentChainInvalidTxResponseMsg(msg)` — note: only `msg` is passed, not the peer `p`
3. `handleParentChainInvalidTxResponseMsg` decodes the payload, looks up each hash in `BridgeTxPool.Get()`, and if `ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error()`, calls `BridgeTxPool.RemoveTx(tx)` — **zero authentication, zero signature check**

**Peer admission check:**

`bridgePeerSet.Register` performs no identity/authorization check beyond the basic P2P handshake (network ID + protocol version match). Any peer that dials the sub-bridge's P2P port and passes the handshake is admitted and can send any protocol message.

**Impact on anchoring txs:**

The code comment at line 398–399 explicitly states:
> "For value transfer txs, Value Transfer Recovery will retry if enabled. For anchoring txs, there is no automatic retry mechanism;"

`valueTransferRecovery` works by scanning bridge contract `RequestValueTransfer` event logs — it has no mechanism to regenerate or re-queue anchoring txs. Once removed from `BridgeTxPool`, an anchoring tx is permanently gone.

**Impact on value transfer txs:**

VT Recovery (`VTRecovery` config flag) is optional. If disabled, value transfer txs are also permanently dropped.

### Title
Unauthenticated Bridge Peer Can Permanently Evict Anchoring Transactions from BridgeTxPool via Forged `ServiceChainInvalidTxResponseMsg` — (`node/sc/sub_bridge_handler.go`)

### Summary
Any peer that completes the sub-bridge P2P handshake can send a `ServiceChainInvalidTxResponseMsg` containing a forged `InvalidParentChainTx` whose `ErrStr` equals `blockchain.ErrGasPriceBelowBaseFee.Error()` and whose `TxHash` matches a pending anchoring or value-transfer tx. The handler removes the tx from `BridgeTxPool` with no authentication check. For anchoring txs, there is no retry mechanism, causing permanent loss of anchoring data.

### Finding Description

`handleParentChainInvalidTxResponseMsg` is invoked for every connected bridge peer without verifying the sender's identity or role: [1](#0-0) 

The handler decodes the attacker-supplied payload and unconditionally removes the matching tx: [2](#0-1) 

`bridgePeerSet.Register` performs no authorization check — any peer passing the basic P2P handshake (network ID + protocol version) is admitted: [3](#0-2) 

The handshake only validates `NetworkId` and `ProtocolVersion`, both of which are public/discoverable: [4](#0-3) 

### Impact Explanation

The code itself documents the asymmetric recovery situation: [5](#0-4) 

- **Anchoring txs**: Permanently evicted. `valueTransferRecovery` operates on bridge contract event logs and has no mechanism to regenerate anchoring txs. [6](#0-5) 
- **Value transfer txs**: Recoverable only if `VTRecovery` is enabled. If disabled, also permanently lost. [7](#0-6) 

Persistent loss of anchoring means the sub-chain's state is no longer provably committed to the parent chain — a durable loss of a core service-chain security guarantee.

### Likelihood Explanation

The sub-bridge P2P port is network-accessible. An attacker needs only to know the `NetworkId` and `SCProtocolVersion` (both public), dial the port, complete the handshake, and send the forged message. No privileged access, no key compromise, no validator collusion is required. [8](#0-7) 

### Recommendation

1. Authenticate `ServiceChainInvalidTxResponseMsg` senders: only accept this message from peers whose P2P node ID matches the configured parent-chain bridge node (i.e., the statically configured or operator-approved parent peer).
2. Add a cryptographic challenge-response or allowlist check in `bridgePeerSet.Register` for peers that are permitted to send pool-mutating messages.
3. For anchoring txs, implement a retry/regeneration mechanism so that a removed anchoring tx for a given block range is re-created on the next anchoring cycle rather than silently dropped.

### Proof of Concept

```
1. Populate BridgeTxPool with a signed TxTypeChainDataAnchoring tx (hash H).
2. Dial the sub-bridge P2P port; complete handshake with matching NetworkId + ProtocolVersion.
3. Send ServiceChainInvalidTxResponseMsg (code 0x09) containing:
     []InvalidParentChainTx{{ TxHash: H, ErrStr: "gas price is below baseFee" }}
4. Assert BridgeTxPool.Get(H) == nil  (tx evicted).
5. Assert no anchoring receipt is ever written for the corresponding block range.
``` [9](#0-8)

func (sbh *SubBridgeHandler) handleParentChainInvalidTxResponseMsg(msg p2p.Msg) error {
	var invalidTxs []InvalidParentChainTx
	if err := msg.Decode(&invalidTxs); err != nil && err != rlp.EOL {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	txPool := sbh.subbridge.GetBridgeTxPool()
	for _, invalidTx := range invalidTxs {
		if tx := txPool.Get(invalidTx.TxHash); tx != nil {
			logger.Error("A bridge tx was not executed", "err", invalidTx.ErrStr,
				"txHash", invalidTx.TxHash.String(),
				"txGasPrice", tx.GasPrice().Uint64())
			if invalidTx.ErrStr == blockchain.ErrGasPriceBelowBaseFee.Error() {
				logger.Info("[SC][HandleTxDropped] Request gasPrice and Magma values to parent chain")
				sbh.SyncNonceAndGasPrice()

				logger.Error("Bridge tx is removed which has lower gasPrice than UpperBoundBaseFee")
				// Remove the tx from the pool. For value transfer txs, Value Transfer Recovery
				// will retry if enabled. For anchoring txs, there is no automatic retry mechanism;
				if err := sbh.subbridge.GetBridgeTxPool().RemoveTx(tx); err != nil {
					logger.Error("Failed to remove bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				} else {
					logger.Info("Removed bridge tx",
						"txType", tx.Type(), "txNonce", tx.Nonce(), "txHash", tx.Hash().String())
				}
			} // TODO-ServiceChain: Consider other types of tx failures with else {}
		}
	}
	return nil
}

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}

// Start implements starting all internal goroutines used by the value transfer recovery.
func (vtr *valueTransferRecovery) Start() error {
	if !vtr.config.VTRecovery {
		return ErrVtrDisabled
	}

	// TODO-Kaia-Servicechain If there is no user API to start recovery, remove isRunning in Start/Stop.
	if vtr.isRunning {
		return ErrVtrAlreadyStarted
	}

	vtr.wg.Add(1)

	go func() {
		ticker := time.NewTicker(time.Duration(vtr.config.VTRecoveryInterval) * time.Second)
		defer func() {
			ticker.Stop()
			vtr.wg.Done()
		}()

		if err := vtr.Recover(); err != nil {
			logger.Warn("initial value transfer recovery is failed", "err", err)
		}

		vtr.isRunning = true

		for {
			select {
			case <-vtr.stopCh:
				logger.Info("value transfer recovery is stopped")
				return
			case <-ticker.C:
				if vtr.isRunning {
					if err := vtr.Recover(); err != nil {
						logger.Trace("value transfer recovery is failed", "err", err)
					}
				}
			}
		}
	}()

	return nil
}
