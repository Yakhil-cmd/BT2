## Analysis Result

### Title
Missing global replay-protection on L1 Bitcoin lockup outpoints allows the same locked-BTC proof to back multiple sequential sBTC bond positions - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`register-for-bond` accepts an SPV-style proof (`verify-l1-lockups` → `validate-l1-lockup`, `stackslib/src/chainstate/stacks/boot/pox-5.clar:1984-2113`) that a Bitcoin output is timelocked to a script committing to the staker's principal, and credits `sats-total` uSTX-collateral weight for bond-reward purposes. The only anti-replay check, `seen-outpoints`, is a `(list 10 ...)` accumulator that is initialized fresh (`seen-outpoints: (list)`) on every call to `verify-l1-lockups` [1](#0-0) . There is no contract-level map that durably records "this Bitcoin outpoint has already been consumed to open a bond position," unlike the analogous `used-signer-key-authorizations` map that pox-4 uses to prevent replay of signer authorizations [2](#0-1) .

### Finding Description
`validate-l1-lockup` verifies:
- the CLTV `unlock-burn-height` is `>=` the bond's minimum unlock height and below the Bitcoin locktime threshold,
- the output's script matches the P2WSH script committing to `(staker, unlock-burn-height, staker-unlock-bytes, early-unlock-bytes)`,
- the output amount matches the claimed amount,
- the outpoint is not already in the **call-local** `seen-outpoints` list,
- the block header hashes to the recorded burnchain header at `height`, and the tx is present via a merkle proof. [3](#0-2) 

None of these checks establish that this specific Bitcoin outpoint has never before been used to register a bond, or that the underlying UTXO is still unspent at the time of the call. `verify-block-header` only proves that a Bitcoin block at a given height was once part of the canonical chain and that the tx was included in it (`stackslib/src/chainstate/stacks/boot/pox-5.clar:3664-3672`) — it says nothing about whether the coin is still locked/unspent on Bitcoin today. Because `seen-outpoints` is reconstructed empty on every transaction, a staker can:

1. Call `register-for-bond` with a real, valid L1 lockup proof, earn `amount-sats` weight for bond N's reward distribution (`calculate-bond-rewards`, `protocol-bonds-total-staked`) [4](#0-3) .
2. Let the bond's term finish (or roll over) so `protocol-bond-memberships` for that principal is cleared/eligible again.
3. Submit the **exact same** `tx`/`header`/`output-index`/proof bytes again for a new bond registration. Since `seen-outpoints` never persists across transactions, and the underlying real Bitcoin UTXO may already have matured (spendable) or even already been spent by the staker in the real world, `validate-l1-lockup` will happily re-accept it, crediting `sats-total` again as if fresh BTC were newly locked.

This breaks the intended equality that pox-5's internal `amount-sats` / `protocol-bonds-total-staked` accounting (used to compute `target-yield` sBTC rewards and signer-weight in `calculate-bond-rewards`, `stackslib/src/chainstate/stacks/boot/pox-5.clar:2242-2337`) must correspond 1:1 to sats actually and currently locked on Bitcoin. Instead, one Bitcoin lockup can be "recycled" indefinitely to open new bond positions and draw sBTC rewards from the shared reserve without any new value being frozen.

### Impact Explanation
This falls in the "Critical" category described by the rules: sats credited by an L1 proof that were never (still) locked on Bitcoin, and double-counting a commitment/reward. Each replayed registration lets the attacker draw `target-yield` sBTC rewards (funded from the pool in `calculate-bond-rewards`) proportional to `sats-total`, while genuinely competing/legitimate stakers' shares are diluted, and the reserve/other stakers effectively subsidize unbacked "phantom" collateral.

### Likelihood Explanation
Exploitation requires only an unprivileged staker who already has a valid allowlist entry (`protocol-bond-allowances`) for a bond and possession of a Bitcoin lockup transaction they once broadcast (or found) whose timelock height happens to satisfy `get-bond-l1-unlock-height` for a later bond period — no admin/bond-pause key, miner cooperation, or third-party private key is needed. The `unlock-burn-height` embedded in the P2WSH script can be chosen arbitrarily large by the staker at the time they broadcast the original Bitcoin transaction, so a single locked output can be crafted up front to satisfy the minimum-unlock-height gate of many future bond periods, making repeated reuse straightforward once one L1 lockup transaction exists.

### Recommendation
Add a persistent map (e.g., `used-l1-outpoints { txid, output-index } → bool`) that is checked and set (`map-insert`, failing on duplicate) inside `validate-l1-lockup`, in addition to the existing per-call `seen-outpoints` list, so that once a specific Bitcoin outpoint has backed one bond registration it can never be presented again for a subsequent one. Consider also requiring proof that the outpoint is unspent as of a recent burn height (not achievable with only SPV inclusion proofs), or binding the credited sats to the outpoint's still-active CLTV window so it cannot be reused after its original bond term.

### Proof of Concept
1. Staker A gets allowlisted for bond 0 and bond 6 (`protocol-bond-allowances`).
2. Staker A broadcasts a real Bitcoin transaction locking sats to `construct-lockup-output-script(A, H, staker-unlock-bytes, early-unlock-bytes)` where `H` is chosen to be `>=` `get-bond-l1-unlock-height` of both bond 0 and bond 6.
3. Staker A calls `register-for-bond(bond-index=0, ..., btc-lockup=(ok {outputs: [lockup], ...}))`; `validate-l1-lockup` accepts it, credits `amount-sats`, and the position runs through bond 0's term, earning rewards, as shown in the existing test `check_pox_5_register_for_bond_l1_lockup_lifecycle` (`stacks-node/src/tests/pox_5_integrations.rs:1393-2024`), which also confirms membership is cleared after the bond and only per-call outpoint dedup exists (`ERR_DUPLICATE_LOCKUP_OUTPOINT` fires only on duplicates *within the same call*, per test comments at lines 1417-1420 and 1919-1926).
4. After bond 0's membership is cleared (naturally, at term end or rollover), staker A calls `register-for-bond(bond-index=6, ..., btc-lockup=(ok {outputs: [the same lockup tuple], ...}))`. Since `seen-outpoints` is re-initialized empty for this new call and there is no persistent outpoint map, `validate-l1-lockup` accepts the identical proof again, crediting `amount-sats` a second time for bond 6 from the same, single real Bitcoin lockup — with no new BTC ever frozen for bond 6. (define-private (validate-l1-lockup
        (lockup {
            height: uint,
            tx: (buff 100000),
            output-index: uint,
            header: (buff 80),
            leaf-hashes: (list 14 (buff 32)),
            tx-count: uint,
            tx-index: uint,
            amount: uint,
            unlock-burn-height: uint,
        })
        (accumulator-res (response {
            staker: principal,
            minimum-unlock-height: uint,
            staker-unlock-bytes: (buff 683),
            early-unlock-bytes: (buff 683),
            sum: uint,
            seen-outpoints: (list 10 {
                txid: (buff 32),
                output-index: uint,
            }),
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (block (try! (parse-block-header (get header lockup))))
            (unlock-burn-height (get unlock-burn-height lockup))
            (expected-script-hash (try! (construct-lockup-output-script (get staker accumulator)
                unlock-burn-height (get staker-unlock-bytes accumulator)
                (get early-unlock-bytes accumulator)
            )))
            (output (try! (get-bitcoin-tx-output? (get tx lockup) (get output-index lockup))))
            (reversed-txid (get txid output))
            (txid (reverse-buff32 reversed-txid))
            (outpoint {
                txid: txid,
                output-index: (get output-index lockup),
            })
            (seen-outpoints (get seen-outpoints accumulator))
        )
        (asserts! (>= unlock-burn-height (get minimum-unlock-height accumulator))
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (< unlock-burn-height BITCOIN_LOCKTIME_THRESHOLD)
            ERR_INVALID_UNLOCK_HEIGHT
        )
        (asserts! (is-eq (get script output) expected-script-hash)
            ERR_INVALID_LOCKUP_SCRIPT
        )
        (asserts! (is-eq (get amount output) (get amount lockup))
            ERR_INVALID_LOCKUP_AMOUNT
        )
        (asserts! (is-none (index-of? seen-outpoints outpoint))
            ERR_DUPLICATE_LOCKUP_OUTPOINT
        )
        (asserts! (verify-block-header (get header lockup) (get height lockup))
            ERR_INVALID_BTC_HEADER
        )
        ;; verify merkle proof
        (asserts!
            (or
                (is-eq (get merkle-root block) txid) ;; true, if the transaction is the only transaction
                (verify-merkle-proof reversed-txid
                    (reverse-buff32 (get merkle-root block))
                    (get tx-index lockup) (get tx-count lockup)
                    (get leaf-hashes lockup)
                )
            )
            ERR_INVALID_MERKLE_PROOF
        )
        (ok {
            staker: (get staker accumulator),
            minimum-unlock-height: (get minimum-unlock-height accumulator),
            staker-unlock-bytes: (get staker-unlock-bytes accumulator),
            early-unlock-bytes: (get early-unlock-bytes accumulator),
            sum: (+ (get sum accumulator) (get amount output)),
            seen-outpoints: (unwrap-panic (as-max-len? (append seen-outpoints outpoint) u10)),
        })
    )
