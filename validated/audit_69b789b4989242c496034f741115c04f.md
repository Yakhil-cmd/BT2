### Title
`GitHubApp#verify_webhook_signature` treats a missing `webhook_secret` as an automatic pass, permitting unauthenticated webhook forgery - (`File: lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is not configured for an organization's GitHub App, bypassing HMAC verification entirely. [1](#0-0)  Because `WebhooksController#verify_signature` resolves the app via `Shipit.github(organization: repository_owner)` using the attacker-controlled `repository.owner.login` field of the POST body, any org configured without a webhook secret accepts arbitrary unsigned/garbage-signed webhook payloads, which are then routed to real handlers like `PushHandler`, calling `stack.sync_github`. [2](#0-1) [3](#0-2) 

### Finding Description
Binding claimed to hold: `HMAC_valid(signature, body, org.webhook_secret) == true` should be **required** for `org.webhook_secret.present?` to be irrelevant to trust — i.e., "an org's webhook is authenticated by its secret" should mean *every* org's webhook traffic is checked against *some* secret. In code, the binding actually implemented is:

```
verify_webhook_signature(signature, message):
  return true unless webhook_secret   # <-- unconditional bypass
  ...HMAC compare...
``` [1](#0-0) 

When `@webhook_secret = @config[:webhook_secret].presence` is `nil` (organization configured with no `webhook_secret`, as shown to be a supported/documented configuration shape in `docs/setup.md` and `config/secrets.development.example.yml`), the method degenerates to always returning `true` regardless of the `X-Hub-Signature` header contents — absent, malformed, or garbage. [4](#0-3) [5](#0-4) 

Path: `WebhooksController#create` runs `before_action ... :verify_signature`, which resolves `github_app = Shipit.github(organization: repository_owner)` using `params.dig('repository','owner','login')` — a value fully controlled by the POST body of an unauthenticated request. [6](#0-5) [7](#0-6)  If that org has no `webhook_secret`, `verified` is `true` and the request proceeds to `create`, which dispatches to `Shipit::Webhooks.for_event(event)` handlers, e.g. `PushHandler#process`, which finds all non-archived stacks matching the ref's branch and calls `stack.sync_github(expected_head_sha: params.after)` — a real, unauthenticated side effect against production stack state. [8](#0-7) [3](#0-2) 

No other guard intercepts this: `drop_unhandled_event` only filters unknown event types, not authenticity; `check_if_ping` only special-cases the ping event; there is no additional signature or provenance check downstream in the handler. [9](#0-8) [10](#0-9) 

### Impact Explanation
For any organization whose Shipit deployment omits `webhook_secret` (a state the codebase's own example configs, docs, and even `test/dummy/config/secrets.yml` default to — `webhook_secret: # nil`), an unauthenticated internet attacker can POST arbitrary, unsigned JSON to `/webhooks` with `X-Github-Event` set to `push` (or any other supported event) and `repository.owner.login` set to that org, causing Shipit to execute the corresponding handler against real stacks — e.g. forcing `Stack#sync_github` for any repository belonging to that org, or other handler-driven state changes (status updates, team/member creation via `membership`, check-run refreshes, etc.). This matches the Critical category: authentication bypass allowing a forged webhook to be accepted and acted upon as if from GitHub. The blast radius covers every stack owned by any org lacking a configured secret; multi-org deployments with mixed configuration would have some orgs fully protected and others fully open.

### Likelihood Explanation
Exploitability requires only that a Shipit operator has configured (or left default/unset) `webhook_secret` for an org — a state explicitly reflected as the "nil" default in this repo's own example/dummy configs. [11](#0-10) [12](#0-11)  No GitHub secrets, sessions, tokens, or privileged roles are needed by the attacker — only knowledge of the target org's name/login, which is public. This is trivially repeatable and scriptable against any number of stacks under that org.

### Recommendation
Do not treat a missing `webhook_secret` as "verification not required." Instead:
- Fail closed: if `webhook_secret` is blank, reject the webhook (`return false`) rather than `return true`, or refuse to boot/register the GitHub App for webhook handling until a secret is configured.
- Alternatively, make `webhook_secret` a mandatory, validated configuration key at boot time (raise on nil/blank), removing the "optional" path entirely from `GitHubApp#initialize`.
- Update `docs/setup.md` and example secrets files so `webhook_secret` is presented as required, not optional.

### Proof of Concept
```ruby
# test/lib/shipit/github_app_test.rb (conceptual)
test "verify_webhook_signature returns true when no secret is configured, bypassing HMAC" do
  app = Shipit::GitHubApp.new('org-nosecret', {}) # no :webhook_secret key
  body = '{"ref":"refs/heads/master","after":"deadbeef","repository":{"owner":{"login":"org-nosecret"}}}'

  assert_equal true, app.verify_webhook_signature(nil, body)
  assert_equal true, app.verify_webhook_signature('sha1=garbage', body)
end

# test/controllers/webhooks_controller_test.rb (conceptual)
test "unsigned push webhook triggers sync_github for org without webhook_secret" do
  Shipit.stubs(:github).with(organization: 'org-nosecret').returns(
    Shipit::GitHubApp.new('org-nosecret', {})
  )
  stack = shipit_stacks(:some_stack_owned_by_org_nosecret)

  request.headers['X-Github-Event'] = 'push'
  body = { ref: "refs/heads/#{stack.branch}", after: 'deadbeef',
           repository: { owner: { login: 'org-nosecret' } } }.to_json

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: stack.id, expected_head_sha: 'deadbeef']) do
    post :create, body:, as: :json # no X-Hub-Signature header at all
  end
end
```
Both assertions demonstrate the equality `verify_webhook_signature(garbage_or_absent_signature, body) == true` holding when `webhook_secret` is unset, and that this directly drives an unauthenticated `sync_github` call — confirming the authentication bypass.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

### Using Multiple Github Applications

A Github application can only authenticate to the Github organization it's installed in. If you want to deploy code from multiple Github organizations the `github` section of your `config/secrets.yml` will need to be formatted differently. The top-level keys should be the name of each Github organization, and the following sub-keys are the Github app details for that particular organization.

For example:

```yml
production:
  github:
    somegithuborg:
      app_id:
      installation_id:
      webhook_secret:
      private_key:
      oauth:
        id:
        secret:
        teams:
    someothergithuborg:
      app_id:
      installation_id:
      webhook_secret:
      private_key:
      oauth:
        id:
        secret:
        teams:
```
