### Title
Unbounded `reward.mintingamount` Governance Vote Enables Arbitrary KAIA Minting Per Block — (`kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`)

### Summary
In `none` governance mode (the default for new chains), any council validator can cast a governance vote setting `reward.mintingamount` to an arbitrarily large value. The parameter's `FormatChecker` is `noopFormatChecker` (accepts any `*big.Int`), and `checkConsistency` returns `nil` for it unconditionally. Once ratified at the next epoch boundary, every subsequent block mints that unbounded amount of KAIA into the reward recipients, constituting unauthorized mass minting of the native token.

### Finding Description

`RewardMintingAmount` is registered in `kaiax/gov/param.go` with a `noopFormatChecker`:

```go
RewardMintingAmount: {
    Canonicalizer: bigIntCanonicalizer,
    FormatChecker: noopFormatChecker,   // accepts any *big.Int, no upper bound
    ...
}
``` [1](#0-0) 

`noopFormatChecker` is defined as:

```go
func noopFormatChecker(cv any) bool {
    return true
}
``` [2](#0-1) 

During block verification, `VerifyVote` calls `checkConsistency`, which explicitly returns `nil` for `RewardMintingAmount` without any value inspection:

```go
case gov.GovernanceDeriveShaImpl, ...,
    gov.RewardMintingAmount, ...:
    return nil
``` [3](#0-2) 

In `none` governance mode, the last vote cast by any council member in an epoch is ratified at the epoch boundary. The ratified value is written directly into `ParamSet.MintingAmount`:

```go
case RewardMintingAmount:
    if tmp, ok = cv.(*big.Int); ok {
        p.MintingAmount = new(big.Int).Set(tmp)
    }
``` [4](#0-3) 

`FinalizeState` then calls `GetDeferredReward`, which uses `config.MintingAmount` directly as the minted amount with no cap:

```go
minted = new(big.Int).Set(config.MintingAmount)
``` [5](#0-4) 

The minted amount is then split and credited to reward recipients via `state.AddBalance`:

```go
for addr, amount := range spec.Rewards {
    state.AddBalance(addr, amount)
}
``` [6](#0-5) 

The only guards in `VerifyVote` are: (a) voter must be in the council, (b) voter must be the block proposer, and (c) in `single` mode after the Permissionless fork, only the governing node may vote. There is no upper-bound guard on the minting amount value itself. [7](#0-6) 

### Impact Explanation

Once a malicious validator's vote for `reward.mintingamount = 2^255` (or any astronomically large value) is ratified at an epoch boundary, every block thereafter mints that amount of KAIA and distributes it to the proposer, stakers, KIF, KEF, and KPF addresses. This constitutes unauthorized mass minting of the native token, permanently inflating the KAIA supply and destroying token value. The corrupted state value is `ParamSet.MintingAmount`, which propagates into every subsequent block's `RewardSpec` and `state.AddBalance` calls.

### Likelihood Explanation

In `none` governance mode (the `DefaultValue` for `governance.governancemode`), any single council validator who becomes a block proposer can inscribe the malicious vote into a block header. The last vote in the epoch wins — no majority collusion is required. The attack requires only that the attacker controls one council node and waits to be selected as proposer. Kaia Mainnet and Kairos testnet use `single` mode (only the governing node can vote), but any chain deployed with the default `none` mode — including private networks, service chains, or new public chains — is directly exposed. [8](#0-7) 

### Recommendation

Add an upper-bound `FormatChecker` for `RewardMintingAmount` analogous to the existing cross-parameter check for `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`. For example, cap the minting amount at a reasonable maximum (e.g., the current value multiplied by a small factor, or an absolute ceiling). Additionally, add a consistency check in `checkConsistency` that compares the proposed value against the current `MintingAmount` and rejects changes exceeding a configurable percentage threshold — mirroring the resolution applied to the swETH `reprice()` bug.

### Proof of Concept

1. Deploy a chain with `governance.governancemode = "none"` (the default).
2. Control one council validator node.
3. Call `governance_vote("reward.mintingamount", "115792089237316195423570985008687907853269984665640564039457584007913129639935")` (i.e., `2^256 - 1` as a decimal string) via the node's RPC.
4. Wait for the node to become block proposer; the vote is inscribed in `header.Vote`.
5. At the next epoch boundary, the vote is ratified and written to `header.Governance`.
6. Starting from the following epoch, every block's `FinalizeState` mints `2^256 - 1` KAIA and distributes it to reward recipients, permanently corrupting the native token supply.

```go
func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
}
```

The ratification condition is determined by the `governance.governancemode` parameter. Mainnet and Kairos both operate in `single` mode. There are two governance modes:

- `none` mode: all members of the GC can vote. For each governance parameter, the last vote in the epoch will be ratified.
- `single` mode: only one member of the GC, stipulated in the parameter `governance.governingnode`, can vote. All valid votes from the governing node in the epoch are ratified in block order. For each governance parameter, the last vote in the epoch will be ratified.
