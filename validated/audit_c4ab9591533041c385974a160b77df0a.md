### Title
RAY-value overflow in `scaled_to_original` during interest accrual permanently freezes a market - (File: common/src/rates/scaling.rs)

### Summary
The Weaviate report is an incorrect-type-conversion bug (CWE-704) that panics and denies service. The analog here is an `i128` overflow when a `Ray` scaled position is converted back to its original RAY value inside `scaled_to_original`. Every controller verb accrues the market first, and accrual unscales `borrowed * borrow_index` in `i128`. Once the accrued debt value exceeds `i128::MAX`, `scaled_to_original` traps with `MathOverflow` on every subsequent call — the index cap at `MAX_BORROW_INDEX_RAY` never gets a chance to clamp, because the value overflow fires first.

### Finding Description
`scaled_to_original` multiplies a scaled `Ray` by an index in native `i128` via `Ray::mul` and panics on overflow: [1](#0-0) 

Accrual calls it unconditionally on the market totals before computing utilization and the rate: [2](#0-1) 

The same unscaling runs in the pool cache for utilization and for every position conversion: [3](#0-2) 

Because supply, borrow, repay, withdraw, liquidate, `clean_bad_debt`, and `update_indexes` all accrue first, a single overflow in `borrowed * borrow_index` bricks the entire market. `update_indexes` is a permissionless entrypoint, so no privileged guard can skip the accrual. The codebase itself proves reachability: the harness test drives a whale market (1e9 whole 18-decimal tokens supplied, 98% borrowed on a 175% max-rate curve) and shows `update_indexes` failing with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and confirms `withdraw` and `repay` then revert identically: [4](#0-3) 

The project's own reference acknowledges the gap: "valid caps and bounded indexes do not guarantee that future accrual fits. Value overflow can occur before the index ceiling and block repayment/withdrawal." [5](#0-4) 

### Impact Explanation
Permanent freezing of funds. Once `scaled_to_original(borrowed, borrow_index)` overflows, every operation on that market reverts forever — the index only grows, so the condition is monotone and unrecoverable. All suppliers' deposits (including uninvolved third parties and protocol revenue shares) are permanently locked, borrowers cannot repay, and liquidations cannot run, so the market's collateral backing also becomes unreachable. `recapitalize` cannot help because it too must accrue/settle through the same conversion path.

### Likelihood Explanation
Medium. An unprivileged attacker needs to seed a very large market (near the ~170B-whole-token RAY domain limit) and push utilization high so the steep tail of the rate curve compounds the index past the value ceiling. This requires significant capital and sustained high utilization over time — it cannot be triggered in a single transaction. However, it requires no special privilege, no oracle manipulation, and no third-party cooperation: `supply`, `borrow`, and `update_indexes` are all permissionless, and any natural whale market left at high utilization drifts into the cliff on its own since debt compounds faster than supply.

### Recommendation
Perform the `scaled * index` product in `I256` inside `scaled_to_original` (or in `accrue_step`'s utilization path) and clamp/saturate the result instead of panicking, so accrual can still complete and let `update_borrow_index` clamp at `MAX_BORROW_INDEX_RAY`. Alternatively, cap the utilization/rate inputs on the widened value and gate `update_indexes` to proceed with a saturated debt value. Emit an event when the saturation path engages so operators can wind the market down via `recapitalize`/`clean_bad_debt` before suppliers are permanently locked.

### Proof of Concept
Reproduced by the existing harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let mut t = LendingTest::new()
    .with_market(big("BIG18", 18, xlm_curve()))   // 175% max borrow rate, opt 75%
    .with_market(col())
    .with_max_utilization_disabled_all_markets()
    .build();
lift_caps(&t, "BIG18", 18);
let principal = BILLION * 10i128.pow(18);        // 1e9 whole 18-decimal tokens
t.supply_raw(BOB, "BIG18", principal);
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", principal / 100 * 98); // 98% utilization

loop {
    t.advance_time(YEAR_SECS);                    // permissionless update_indexes
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) { break e; }
}
// Panic: GenericError::MathOverflow from scaled_to_original, with
// borrow_index still < MAX_BORROW_INDEX_RAY (index cap never engaged).
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

After the overflow, `update_indexes`, `withdraw`, `repay`, and `liquidate` on the `BIG18` market all revert with `MathOverflow`; BOB's 1e9-token deposit and ALICE's collateral are permanently frozen.

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
