### Title
Bad-debt wipeout clamps the supply index to a floor but never burns the stranded scaled shares, so wiped suppliers retain a residual claim that withdraws fresh depositors' cash - ([File: contracts/pool/src/interest.rs])

### Summary
When bad debt is socialized, `apply_bad_debt_to_supply_index` reduces the supply index pro-rata but clamps it upward at `SUPPLY_INDEX_FLOOR_RAW` (`RAY/1000`) instead of letting it reach zero. The scaled supply shares of wiped-out suppliers are never burned or zeroed — an incomplete cleanup of the shared per-market books. Those stranded shares keep unscaling to a positive floor amount, and once any new depositor adds cash to the emptied market, the stranded holder can withdraw real tokens through the normal `withdraw` path, draining the fresh deposit.

### Finding Description
`apply_bad_debt_to_supply_index` computes `new_supply_index = supply_index * (1 - bad_debt/total_supplied)` and then applies `max(SUPPLY_INDEX_FLOOR_RAW)`. [1](#0-0)  On a full wipeout (`bad_debt >= total_supplied_value`) the index is floored at `RAY/1000` rather than zero, so `unscale_supply_floor(position)` still returns a positive asset claim for every pre-wipeout supplier. [2](#0-1) 

The withdraw leg only requires `burned > 0`, `cash >= net_transfer` (`require_reserves`), and `require_supply_for_debt` (vacuously true with zero debt) — there is no check that the market was wiped or that the residual claim exceeds what socialization intended to leave. [3](#0-2)  The pool's own test suite demonstrates the primitive: `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` shows a wiped supplier extracting exactly a subsequent depositor's full deposit, leaving the books insolvent (`owed > cash`). [4](#0-3) 

This mirrors CVE-2022-21123's bug class: shared state (the market's scaled-share book) is not fully cleaned on the wipeout path, so stale residual data leaks value to whoever reads it later.

### Impact Explanation
Theft of user funds / protocol insolvency. Every supplier present at the wipeout retains a phantom claim proportional to their scaled shares at the floor index. Any subsequent `supply` (permissionless) credits pool cash; the stranded holder then calls controller `withdraw` and pulls out real tokens up to the residual amount. Post-withdraw, the market owes more than it holds, so honest depositors cannot be paid — the stranded claims socialize the theft onto new entrants. The residual per holder is bounded by `scaled_shares * RAY/1000`, roughly 0.1% of the wiped face value scaled by share denomination, but it is extracted entirely from fresh cash.

### Likelihood Explanation
Reachable by an unprivileged address. Bad debt is created permissionlessly through `liquidate` (insolvent accounts leave unpaid debt that seizes collateral) and `clean_bad_debt` on dust positions; a severe price move or a thinly collateralized market can push socialization to the cap. An attacker can also be on both sides: supply, run an undercollateralized borrow that goes bad, and let the wipeout floor the index. The exploit then only needs one later depositor in the same `(hub, asset)` market — plausible on reusable markets and after recapitalization attempts. Requirements are a near-total wipeout and survivor shares, which keeps this out of the top severity band.

### Recommendation
On wipeout, burn or tombstone the stranded scaled supply instead of relying on the index floor — e.g., reduce `supplied` proportionally to the floor clamp (`supplied_new = supplied * new_index / old_index` semantics) or record a per-market "wiped" flag that forces `resolve_withdrawal` to return `(position, 0)` until the market is re-seeded. Alternatively, gate withdrawals with an explicit `total_supplied_value` solvency check (owed scaled-by-floor vs cash) so residual claims can never exceed book equity. Add a regression asserting `cash >= unscale_supply_floor(supplied)` after `apply_bad_debt_to_supply_index`.

### Proof of Concept
1. Alice calls `supply` on market `(hub, T)` for `A` units (scaled shares `sA`).
2. A borrower's position goes insolvent; anyone calls `liquidate`/`clean_bad_debt`. Socialization calls `apply_bad_debt_to_supply_index` with `bad_debt >= supplied * supply_index`, clamping `supply_index` to `SUPPLY_INDEX_FLOOR_RAW` while `sA` and `supplied` are unchanged.
3. Bob calls `supply` for `C = unscale_supply_floor(sA)` units; the pool now holds `C` cash.
4. Alice calls `withdraw(amount = i128::MAX)`. `resolve_withdrawal` returns `(sA, C)`; `require_reserves(C)` passes; Alice receives Bob's `C` tokens; the market owes `C` to Bob with `cash = 0`.

This is exactly the scenario encoded in `contracts/pool/tests/interest.rs` (`test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard`), which confirms the stranded-claim payout and resulting insolvency at the cache layer the production withdraw path uses.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn gate_and_debit(env: &Env, cache: &mut Cache, net_transfer: i128, skip_utilization_check: bool) {
    cache.require_reserves(net_transfer);

    if !skip_utilization_check {
        guards::require_utilization_below_max(env, cache);
    }
    guards::require_supply_for_debt(env, cache);

fn test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let alice_scaled_raw = 1_000 * RAY;
        let borrowed_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: alice_scaled_raw,
            borrowed: borrowed_scaled_raw,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let alice_scaled = Ray::from(alice_scaled_raw);
        let borrow_scaled = Ray::from(borrowed_scaled_raw);

        let bad_debt = cache.unscale_borrow_ceil_ray(borrow_scaled);
        apply_bad_debt_to_supply_index(&mut cache, bad_debt);
        cache.burn_debt(borrow_scaled);

        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "seize wipeout clamps supply_index UP to RAY/1000, leaving unburned shares a residual"
        );

        let alice_stranded = cache.unscale_supply_floor(alice_scaled);
        assert!(alice_stranded > 0, "wiped survivor keeps a stranded claim");
        assert_eq!(
            cache.cash(),
            0,
            "empty market: claim masked by require_reserves"
        );

        let deposit = alice_stranded;
        let bob_scaled = cache.calculate_scaled_supply(deposit);
        cache.mint_supply(bob_scaled);
        cache.credit_cash(deposit);

        let total_owed = cache.unscale_supply_floor(cache.supplied());
        assert!(
            total_owed > cache.cash(),
            "post-deposit books insolvent: owed {} > cash {}",
            total_owed,
            cache.cash()
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, alice_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "wiped position pays out real cash");
        assert_eq!(gross, deposit, "Alice extracts exactly Bob's fresh deposit");

        let bob_claim = cache.unscale_supply_floor(bob_scaled);
        assert!(
            cache.cash() < bob_claim,
            "cash {} cannot cover Bob's honest claim {}: fresh depositor lost funds",
            cache.cash(),
            bob_claim
        );
    });
