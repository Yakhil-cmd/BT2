Confirmed: `set_authorized_withdrawer` and `authorize`/`set_new_authorized_voter` in the vote program accept an arbitrary `Pubkey` (including `Pubkey::default()`, the all-zero pubkey with no corresponding private key) with no zero/burn-address check.

### Title
Vote program `Authorize`/`AuthorizeChecked` instructions accept a zero (default) pubkey as new voter/withdraw authority, permanently freezing the vote account - (File: programs/vote/src/vote_state/mod.rs, programs/vote/src/vote_state/handler.rs)

### Summary
The vote program's `authorize` function, which backs the `VoteInstruction::Authorize`, `AuthorizeChecked`, `AuthorizeWithSeed`, and `AuthorizeCheckedWithSeed` instructions, sets the new authorized voter or withdrawer to whatever `Pubkey` is supplied by the caller, without checking that it is not `Pubkey::default()` (the all-zero address, for which no private key is known to exist).

### Finding Description
`vote_state::authorize` handles both `VoteAuthorize::Voter` and `VoteAuthorize::Withdrawer` cases. For `Withdrawer`, it directly calls `vote_state.set_authorized_withdrawer(*authorized)` [1](#0-0)  with no validation on `authorized`. The underlying setter simply overwrites state: [2](#0-1) . For `Voter`, `vote_state.set_new_authorized_voter(authorized, ...)` similarly inserts the given pubkey with no zero check [3](#0-2) , and the handler stores it verbatim [4](#0-3) .

The processor entry points that dispatch to `authorize` (`VoteInstruction::Authorize` and `VoteInstruction::AuthorizeChecked`) only check signer requirements, not the value of the new authority [5](#0-4) [6](#0-5) .

Because `Pubkey::default()` (all-zero bytes) is not a valid ed25519 public key with a known/derivable private key, once it becomes the sole `authorized_withdrawer` or the currently-effective authorized voter, no one can ever produce a valid signature for it. This is directly analogous to the reported "missing zero checks" bug class: an owner/authority parameter (here, `authorized_withdrawer`/`authorized_voter`) is settable to a "zero" value with no validation, permanently locking the account and any funds/authority tied to it — exactly the "MapleLoan.setBorrower(address(0))" scenario cited in the report, translated to Solana's vote program authority-transfer instructions.

### Impact Explanation
If a validator operator (or any legitimate/authorized withdrawer/voter signer — an unprivileged actor with respect to protocol-level roles, simply the current key-holder of the vote account) issues an `Authorize`/`AuthorizeChecked` instruction with `new_authorized_pubkey = Pubkey::default()` (e.g., due to a front-end bug, a script bug, or an uninitialized-variable mistake, as described in the analog report's exploit scenario), the vote account's authorized withdrawer becomes permanently unset (no key can withdraw lamports from that vote account ever again), or the authorized voter for future epochs becomes fixed to an address nobody controls (the validator can never vote again once that epoch arrives), each amounting to a permanently frozen account and effectively lost funds/validator functionality. This matches the "permanently frozen accounts" acceptance criterion.

### Likelihood Explanation
This requires an operator/user error rather than a malicious remote attacker, so likelihood is low but plausible — the CLI code that constructs these instructions performs no client-side zero-address validation either [7](#0-6) , so a scripting mistake, malformed automation, or (per the original report's exploit scenario) a front-end bug could realistically submit an all-zero pubkey.

### Recommendation
Add an explicit check in `vote_state::authorize` (and in `set_authorized_withdrawer`/`set_new_authorized_voter`) that rejects `Pubkey::default()` (and any other pubkey known to have no accessible private key) for both `VoteAuthorize::Voter` and `VoteAuthorize::Withdrawer`, returning `InstructionError::InvalidInstructionData` or a dedicated `VoteError` if it is supplied. Apply the same validation to `AuthorizeWithSeed`/`AuthorizeCheckedWithSeed` paths, and add client-side validation in `cli/src/vote.rs`'s `parse_vote_authorize`.

### Proof of Concept
1. Create and initialize a vote account with a valid authorized withdrawer/voter.
2. Submit `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)` signed by the current authorized withdrawer, via `programs/vote/src/vote_processor.rs`'s `VoteInstruction::Authorize` arm [5](#0-4) .
3. The instruction succeeds and `set_authorized_withdrawer` stores `Pubkey::default()` as `authorized_withdrawer` [2](#0-1) .
4. Any subsequent `Withdraw` instruction requires a signature matching `authorized_withdrawer`; since no private key exists for the all-zero pubkey, the vote account's lamports (beyond rent-exempt minimum, up to its full balance) become permanently inaccessible, and the same logic applies to `Voter` for future voting rights.

Note: I was unable to fully inspect `vote_state::withdraw`'s exact signer-check code path in this session (not directly re-verified beyond the `authorize` logic already cited), so the exact downstream failure mode for withdrawal should be double-checked in a follow-up session if further confirmation is desired.

    pub(crate) fn set_new_authorized_voter<F>(
        &mut self,
        authorized_pubkey: &Pubkey,
        current_epoch: Epoch,
        target_epoch: Epoch,
        bls_pubkey: Option<&[u8; BLS_PUBLIC_KEY_COMPRESSED_SIZE]>,
        verify: F,
    ) -> Result<(), InstructionError>
    where
        F: Fn(Pubkey) -> Result<(), InstructionError>,
    {
        let epoch_authorized_voter = self.get_and_update_authorized_voter(current_epoch)?;
        verify(epoch_authorized_voter)?;

        match &mut self.target_state {
            TargetVoteState::V4(v4) => {
                // The offset in slots `n` on which the target_epoch
                // (default value `DEFAULT_LEADER_SCHEDULE_SLOT_OFFSET`) is
                // calculated is the number of slots available from the
                // first slot `S` of an epoch in which to set a new voter for
                // the epoch at `S` + `n`
                if v4.authorized_voters.contains(target_epoch) {
                    return Err(VoteError::TooSoonToReauthorize.into());
                }

                v4.authorized_voters
                    .insert(target_epoch, *authorized_pubkey);

                if bls_pubkey.is_some() {
                    v4.bls_pubkey_compressed = bls_pubkey.copied();
                }

                Ok(())
            }
        }
    }
