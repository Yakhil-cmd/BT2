### Title
Unauthenticated P2P-to-RPC Proxy in `MainBridge.handleCallMsg` Allows Any Bridge Peer to Invoke `kaia_sendRawTransaction` and `kaia_sendTransaction` — (`node/sc/main_bridge_handler.go`, `node/sc/mainbridge.go`)

---

### Summary

`MainBridge` creates an internal `rpc.Server` and registers all `Public` `kaia`/`klay` APIs into it, including `KaiaTransactionAPI` (`kaia_sendRawTransaction`, `kaia_sendTransaction`, `kaia_sendTransactionAsFeePayer`). The `handleCallMsg` handler forwards raw bytes from any connected bridge P2P peer directly into that RPC server's pipe with no content validation, method allowlist, or caller authorization. The bridge handshake only checks `NetworkId` and `ProtocolVersion`, omitting the `ChainID` and genesis-hash checks present in the main-chain peer handshake. Any peer that can reach the `MainBridgePort` and knows those two public values can therefore invoke any registered `kaia`/`klay` public RPC method, bypassing all HTTP-layer controls (CORS, vhosts, IP allowlists) that protect the normal JSON-RPC endpoint.

---

### Finding Description

**Step 1 – Internal RPC server construction and API registration**

In `NewMainBridge`, a fresh `rpc.Server` is created and connected to `mb.rpcConn` via `net.Pipe()`: [1](#0-0) 

`SetComponents` then iterates every API passed in from the CN service and registers those that are `Public` and in the `kaia`/`klay` namespace — including `KaiaTransactionAPI` — into that server: [2](#0-1) 

**Step 2 – Unauthenticated forwarding in `handleCallMsg`**

When a bridge peer sends a `ServiceChainCall` message, `handleCallMsg` decodes the raw bytes and writes them verbatim to the RPC server pipe: [3](#0-2) 

There is no check on which JSON-RPC method is being called, no per-caller authorization, and no allowlist.

**Step 3 – Weak bridge handshake**

The bridge peer `readStatus` only validates `NetworkId` and `ProtocolVersion`: [4](#0-3) 

Compare with the main-chain peer handshake, which additionally enforces `GenesisBlock` and `ChainID`: [5](#0-4) 

Any peer that knows the two public values (`NetworkId`, `ProtocolVersion`) passes the bridge handshake.

**Step 4 – Registered methods with asset impact**

`KaiaTransactionAPI.SendRawTransaction` submits a signed transaction directly to the tx pool: [6](#0-5) 

`KaiaTransactionAPI.SendTransaction` signs and submits a transaction using a **node-unlocked account**: [7](#0-6) 

Both are registered as `Public: true` in the CN's API list: [8](#0-7) 

---

### Impact Explanation

| Scenario | Corrupted value |
|---|---|
| Node has unlocked bridge-operator account | Attacker calls `kaia_sendTransaction` → transaction signed and submitted from the unlocked account → unauthorized KAIA transfer or contract call |
| Node has no unlocked accounts | Attacker calls `kaia_sendRawTransaction` with a self-signed tx → tx injected into the main-chain pool, bypassing all HTTP-layer access controls (CORS, vhost, IP allowlist) that protect the public RPC port |
| `kaia_sendTransactionAsFeePayer` | Attacker submits a fee-payer-signed tx consuming the node's unlocked fee-payer account's KAIA balance |

The primary protected-state impact is **unauthorized transaction submission from a node-unlocked account** (unauthorized KAIA transfer / nonce consumption) and **bypass of the HTTP security perimeter** for `kaia_sendRawTransaction`.

---

### Likelihood Explanation

- The `MainBridgePort` is a separate TCP listener; if exposed beyond the intended sub-bridge peer (e.g., on a public IP without firewall), any attacker can reach it.
- `NetworkId` and `ProtocolVersion` are public constants discoverable from documentation or by connecting to any public node.
- The RLPx layer requires knowing the server's node ID (public key). This is a partial barrier, but node IDs are often published in configuration files, ENR records, or discoverable via the same node's main P2P port.
- Service-chain operators commonly run with unlocked bridge-operator accounts, making the `kaia_sendTransaction` path directly exploitable.

---

### Recommendation

1. **Add a method allowlist in `handleCallMsg`**: parse the JSON-RPC `method` field before writing to the pipe and reject anything outside a narrow set of explicitly permitted methods (e.g., only `kaia_getBalance`, `kaia_getTransactionCount`).
2. **Remove transaction-submission APIs from the internal bridge RPC server**: `kaia_sendRawTransaction`, `kaia_sendTransaction`, and `kaia_sendTransactionAsFeePayer` should not be registered in `mb.rpcServer`; the bridge's `SetComponents` filter should use a stricter allowlist than `api.Public && namespace == "kaia"`.
3. **Strengthen the bridge handshake**: add `ChainID` and genesis-hash checks to `baseBridgePeer.readStatus`, matching the main-chain peer handshake.
4. **Firewall `MainBridgePort`**: document and enforce that the bridge port must only be reachable by the known sub-bridge peer IP.

---

### Proof of Concept

```
# 1. Discover the MainBridge node ID (e.g., from the operator's published enode URL or
#    by connecting to the main P2P port and reading the peer's ID).

# 2. Connect to MainBridgePort using the SC protocol (NetworkId=8217, ProtocolVersion=1).
#    The RLPx handshake uses the discovered node ID.

# 3. Send a StatusMsg with matching NetworkId and ProtocolVersion to pass readStatus().

# 4. Send a ServiceChainCall P2P message whose payload is the RLP-encoded bytes of:
#    {"jsonrpc":"2.0","id":1,"method":"kaia_sendTransaction",
#     "params":[{"from":"<unlocked-bridge-operator-addr>",
#                "to":"<attacker-addr>",
#                "value":"0xDE0B6B3A7640000"}]}

# 5. handleCallMsg writes those bytes to mb.rpcConn (the net.Pipe write end).
#    The internal rpc.Server reads them, dispatches KaiaTransactionAPI.SendTransaction,
#    signs with the unlocked account, and submits to the main-chain tx pool.

# 6. The response is read back from the pipe and forwarded to the attacker peer
#    via SendRPCResponseData → peer.SendResponseRPC.
#    The attacker receives the transaction hash confirming success.
```

The exact corrupted value is the **nonce of the unlocked bridge-operator account** (incremented without authorization) and the **KAIA balance** (reduced by the transferred amount plus gas fees).

func (mbh *MainBridgeHandler) handleCallMsg(p BridgePeer, msg p2p.Msg) error {
	logger.Trace("mainbridge writes the rpc call message to rpc server", "msg.Size", msg.Size, "msg", msg)
	data := make([]byte, msg.Size)
	err := msg.Decode(&data)
	if err != nil {
		logger.Error("error in mainbridge message handler", "err", err)
		return err
	}

	// Write to RPC server pipe
	_, err = mbh.mainbridge.rpcConn.Write(data)
	if err != nil {
		logger.Error("failed to write to the rpc server pipe", "err", err)
		return err
	}
	return nil
}

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()
	if err != nil {
		return err
	}
	if msg.Code != StatusMsg {
		return errResp(ErrNoStatusMsg, "first msg has code %x (!= %x)", msg.Code, StatusMsg)
	}
	if msg.Size > ProtocolMaxMsgSize {
		return errResp(ErrMsgTooLarge, "%v > %v", msg.Size, ProtocolMaxMsgSize)
	}
	// Decode the handshake and make sure everything matches
	if err := msg.Decode(&status); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}
	if status.NetworkId != network {
		return errResp(ErrNetworkIdMismatch, "%d (!= %d)", status.NetworkId, network)
	}
	if int(status.ProtocolVersion) != p.version {
		return errResp(ErrProtocolVersionMismatch, "%d (!= %d)", status.ProtocolVersion, p.version)
	}
	return nil
}

func (s *KaiaTransactionAPI) SendTransaction(ctx context.Context, args SendTxArgs) (common.Hash, error) {
	if args.AccountNonce == nil {
		// Hold the addresse's mutex around signing to prevent concurrent assignment of
		// the same nonce to multiple accounts.
		s.nonceLock.LockAddr(args.From)
		defer s.nonceLock.UnlockAddr(args.From)
	}

	signedTx, err := s.SignTransaction(ctx, args)
	if err != nil {
		return common.Hash{}, err
	}

	return submitTransaction(ctx, s.b, signedTx.Tx)
