## Title
Attacker-controlled skill filenames/frontmatter reach terminal output unsanitized via `printFileTree` - (File: pkg/cmd/skills/install/install.go)

### Summary
`printFileTree` (and its helper `printTreeDir`) at `pkg/cmd/skills/install/install.go:1151-1185` walks the on-disk skill directory after install and prints each directory/file name directly to the terminal with no stripping of C0/C1 control or ANSI/OSC escape sequences. The filenames printed originate from GitHub tree entry paths (`file.Path`) fetched during install, which are attacker-controlled since the attacker publishes the skill repository/archive.

### Finding Description
`installSkill` in `internal/skills/installer/installer.go:251-309` fetches the tree listing from the attacker's repo via `discovery.DiscoverSkillFiles` and writes each blob to disk using `relPath := strings.TrimPrefix(file.Path, skill.Path+"/")`, then joins it through `safepaths` which only guards against **path traversal** (`../` segments), not against embedded control/escape bytes. Git tree entry names can legally contain arbitrary bytes other than `/` and NUL, so a filename such as `"\x1b]52;c;<base64>\x07innocuous.txt"` (OSC 52 clipboard write) or an OSC 7/DCS sequence can be committed to the attacker's skill repo and will be written to disk as a literal filename via `os.WriteFile(destPath, ...)` at `internal/skills/installer/installer.go:303`.

After install, `printFileTree` (`pkg/cmd/skills/install/install.go:1151`) is invoked to show the user what was installed. It calls `printTreeDir` (`install.go:1163`), which does `os.ReadDir(dir)` and for each `entry.Name()` prints it verbatim:
```go
fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)
```
(`install.go:1182`). `cs.Muted`/`cs.Bold` (`pkg/iostreams/color.go:60-80`) only wrap the string with ANSI SGR color codes; they never sanitize or strip the input string. No sanitization function is applied anywhere between reading attacker-controlled tree data and printing it to the user's terminal.

Since the CLI's output is typically written straight to the terminal, an attacker-crafted filename embedding OSC 52 can silently overwrite the victim's clipboard, and OSC/DCS title or hyperlink sequences can spoof terminal prompts or hide subsequent output — a classic terminal escape sequence injection.

### Impact Explanation
This matches "Terminal output/prompt spoofing leading to credential capture or unintended destructive confirmation." An attacker who publishes a skill repository (no privileges required) can have `gh skills install` render attacker-chosen escape sequences to the victim's terminal, enabling: clipboard exfiltration/poisoning (OSC 52), terminal title/spoofing, or obscuring of subsequent warning text (e.g. the "Skills are not verified..." disclaimer printed right after via `printPreInstallDisclaimer`), increasing the chance a victim runs or trusts a malicious skill.

### Likelihood Explanation
High feasibility: the attacker only needs to publish a public repository/skill with a maliciously named file (git allows arbitrary non-`/`/non-NUL bytes in filenames), and get a victim to run `gh skills install <attacker-repo>`. No MITM, no token, no social engineering beyond normal skill discovery/installation is required, and the vulnerable code path (`printFileTree`) runs unconditionally after every install.

### Recommendation
Sanitize all attacker-derived text before writing it to any writer that reaches the terminal:
- Strip or escape C0/C1 control characters and ANSI/OSC/DCS sequences from `entry.Name()` in `printTreeDir` and from `name` in `printFileTree` before printing (e.g., a helper that replaces `\x1b`, other control bytes, and non-printable runes with a placeholder like `?` or `\xNN`).
- Apply the same sanitization to any other locations that echo repo-supplied strings (skill display names, frontmatter-derived source names in `existingSkillPrompt`, registry metadata).
- Consider validating/rejecting filenames containing control characters at extraction time in `installSkill`/`installLocalSkill`, in addition to sanitizing for display.

// printFileTree renders a text tree of the on-disk contents of each skill directory.
func printFileTree(w io.Writer, cs *iostreams.ColorScheme, dir string, skillNames []string) {
	if len(skillNames) == 0 {
		return
	}
	fmt.Fprintln(w)
	for _, name := range skillNames {
		skillDir := filepath.Join(dir, filepath.FromSlash(name))
		fmt.Fprintf(w, "  %s\n", cs.Bold(name+"/"))
		printTreeDir(w, cs, skillDir, "  ")
	}
}

func printTreeDir(w io.Writer, cs *iostreams.ColorScheme, dir, indent string) {
	entries, err := os.ReadDir(dir)
	if err != nil {
		fmt.Fprintf(w, "%s%s\n", indent, cs.Muted("(could not read directory)"))
		return
	}
	for i, entry := range entries {
		isLast := i == len(entries)-1
		connector := "├── "
		childIndent := "│   "
		if isLast {
			connector = "└── "
			childIndent = "    "
		}
		name := entry.Name()
		if entry.IsDir() {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), cs.Bold(name+"/"))
			printTreeDir(w, cs, filepath.Join(dir, name), indent+cs.Muted(childIndent))
		} else {
			fmt.Fprintf(w, "%s%s%s\n", indent, cs.Muted(connector), name)
		}
	}
}

func (c *ColorScheme) Muted(t string) string {
	// Fallback to previous logic if accessible colors preview is disabled.
	if !c.Accessible {
		return c.Gray(t)
	}

	// Muted text is only stylized if color is enabled.
	if !c.Enabled {

	}
