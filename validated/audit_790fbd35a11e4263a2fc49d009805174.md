### Title
Host-function gas-key fee calculation uses raw wire `public_key_len` instead of trie-id length, enabling underpriced storage for ML-DSA-65 gas keys - (File: `runtime/near-vm-runner/src/logic/logic.rs`)

### Summary
The external report describes a Solidity contract that manually (mis-)computed a storage slot offset, using a hard-coded constant that didn't match the actual storage layout, causing functions to silently operate on the wrong slot. The closest reachable analog in `nearcore` is a length-calculation mismatch between two code paths that price the same storage effect (writing an access/gas key trie entry): the transaction-based path correctly uses the on-trie identifier length (`PublicKey::trie_id_len()`), while the host-function path in the WASM runtime instead forwards the guest-supplied `public_key_len` (the wire/borsh length) directly into the same fee-computation helpers.

### Finding Description
`near_crypto::PublicKey` has two length notions, introduced specifically because ML-DSA-65 keys are stored in the trie by hash rather than by full pubkey:
- `PublicKey::len()` – borsh wire length (33 / 65 / **1953** bytes for ED25519 / SECP256K1 / MLDSA65)
- `PublicKey::trie_id_len()` – on-trie identifier length (33 / 65 / **33** bytes) [1](#0-0) 

Storage-usage accounting and transaction-side fee helpers were updated to consistently call `trie_id_len()`: [2](#0-1) [3](#0-2) 

However, `gas_key_add_key_exec_fee` and `gas_key_transfer_exec_fee` internally build the actual trie-key length via `access_key_key_len(account_id_len, public_key_len)`, i.e. they trust whatever length value is passed in to represent the *on-trie* size of the key: [4](#0-3) [5](#0-4) 

In the WASM host-function path, `promise_batch_action_add_gas_key_with_function_call` takes `public_key_len` directly as a numeric guest-supplied parameter (the length of the raw bytes the contract passes to the host call) and forwards it unmodified into `gas_key_add_key_exec_fee`, rather than decoding the key and calling `trie_id_len()` on it: [6](#0-5) 

For ED25519/SECP256K1 keys, `len()` and `trie_id_len()` coincide, so this divergence is invisible under normal (classical-key) usage - which is exactly why the existing parity test `test_gas_key_fee_parity` (which only exercises ED25519 keys) does not catch it. But for ML-DSA-65 keys the two values diverge by two orders of magnitude (1953 vs 33 bytes). If `public_key_len` supplied by the guest at this host-function call site is the wire/borsh length of an ML-DSA-65 key (consistent with how the value is used elsewhere, e.g. in `permission_send_fees`/`total_send_fees` which is keyed off the wire-encoded action), then the exec fee computed here would be based on the wrong (oversized, in this hypothetical) or, if it is actually a raw-key length not equal to either notion, an inconsistent value relative to the actual bytes written to the trie by `access_key_key_len`/`gas_key_nonce_key_len`, producing an under- or over-charge relative to the real trie byte cost - structurally the same "wrong offset/length assumption feeding a byte-metered accounting function" bug class as the Solidity report, just for gas/storage accounting instead of an EVM storage slot.

### Impact Explanation
If exec fee (and by extension gas metering, `pay_gas_key_add_key_fees`) is computed using a length value that does not match what is actually written into the trie (`access_key_key_len`, `gas_key_nonce_key_len`, `AccessKey::NONCE_VALUE_LEN`), a contract calling this host function with a mismatched `public_key_len` could pay less gas than what the resulting trie write actually costs, or have storage-usage accounting that diverges from actual bytes stored. This falls into "free or underpriced execution or storage" - the same impact category flagged by the report for the Solidity bug (verification functions using wrong storage math), though in nearcore's case it's underpriced accounting rather than an unusable verification path.

### Likelihood Explanation
Reachability requires: (1) a contract invoking `promise_batch_action_add_gas_key_with_function_call` with an ML-DSA-65 public key and a `public_key_len` that doesn't match `trie_id_len()`, and (2) this action executing against the real trie. This is a plausible unprivileged contract-call path (any account can deploy a contract and issue this promise action), but I could not fully verify within the available tool budget exactly what numeric value the guest is expected/required to supply for `public_key_len` for MLDSA65 keys, nor whether `get_public_key`/`decode()` enforce that `public_key_len` equals the wire length before this fee computation runs (which would make the mismatch purely "wire length used where trie-id length is needed," a confirmed but consistently-wire-length bug, rather than an arbitrary attacker-controlled length). This uncertainty affects only whether the discrepancy is exploitable by a normal contract call versus only reachable in a fixed, deterministic (but still incorrect) way.

### Recommendation
Verify what `public_key_len` represents at the `promise_batch_action_add_gas_key_with_function_call` (and the analogous `_with_full_access` and `promise_batch_action_transfer_to_gas_key`) call sites, and if it is the wire/borsh length rather than the trie-id length, convert via `PublicKey::trie_id_len()` (after decoding) before calling `gas_key_add_key_exec_fee` / `gas_key_transfer_exec_fee`, mirroring what `permission_exec_fees` in `runtime/runtime/src/config.rs` already does for the transaction path. Add a parity test analogous to `test_gas_key_fee_parity` that specifically exercises ML-DSA-65 keys via both the transaction path and the host-function path to catch any future divergence.

### Proof of Concept
Not fully constructible from the indexed context alone - would require confirming, via the `get_public_key`/host-function call convention in `runtime/near-vm-runner/src/logic/logic.rs`, exactly what value a contract must pass as `public_key_len` for an ML-DSA-65 key, and then invoking `promise_batch_action_add_gas_key_with_function_call` with that key from a test contract while comparing `gas_burnt`/`tokens_burnt`/final storage usage against the equivalent `AddKey` transaction path (as done in `test_gas_key_fee_parity` in `test-loop-tests/src/tests/gas_keys.rs`) but using `KeyType::MLDSA65` instead of `KeyType::ED25519`.

impl PublicKey {
    /// Length of this public key's borsh encoding, in bytes - that is,
    /// the on-the-wire size of the raw key bytes plus a 1-byte borsh
    /// discriminant tag (the leading `+ 1` in each arm).
    ///
    /// For storage-fee accounting use [`PublicKey::trie_id_len`] instead;
    /// for ML-DSA-65 those two diverge (1953 wire vs 33 on-trie).
    // `is_empty` always returns false, so there is no point in adding it
    #[allow(clippy::len_without_is_empty)]
    pub fn len(&self) -> usize {
        match self {
            Self::ED25519(_) => 1 + ed25519_dalek::PUBLIC_KEY_LENGTH,
            Self::SECP256K1(_) => 1 + 64,
            Self::MLDSA65(_) => 1 + ML_DSA_65_PUBLIC_KEY_LENGTH,
        }
    }

    pub fn empty(key_type: KeyType) -> Self {
        match key_type {
            KeyType::ED25519 => {
                PublicKey::ED25519(ED25519PublicKey([0u8; ed25519_dalek::PUBLIC_KEY_LENGTH]))
            }
            KeyType::SECP256K1 => PublicKey::SECP256K1(Secp256K1PublicKey([0u8; 64])),
            KeyType::MLDSA65 => {
                PublicKey::MLDSA65(MlDsa65PublicKey(Box::new([0u8; ML_DSA_65_PUBLIC_KEY_LENGTH])))
            }
        }
    }

    pub fn key_type(&self) -> KeyType {
        match self {
            Self::ED25519(_) => KeyType::ED25519,
            Self::SECP256K1(_) => KeyType::SECP256K1,
            Self::MLDSA65(_) => KeyType::MLDSA65,
        }
    }

    fn key_tag(&self) -> KeyTag {
        match self {
            PublicKey::ED25519(_) => KeyTag::Ed25519,
            PublicKey::SECP256K1(_) => KeyTag::Secp256k1,
            PublicKey::MLDSA65(_) => KeyTag::MlDsa65Full,
        }
    }

    pub fn key_data(&self) -> &[u8] {
        match self {
            Self::ED25519(key) => key.as_ref(),
            Self::SECP256K1(key) => key.as_ref(),
            Self::MLDSA65(key) => key.as_ref(),
        }
    }

    pub fn unwrap_as_ed25519(&self) -> &ED25519PublicKey {
        match self {
            Self::ED25519(key) => key,
            Self::SECP256K1(_) | Self::MLDSA65(_) => panic!(),
        }
    }

    pub fn unwrap_as_secp256k1(&self) -> &Secp256K1PublicKey {
        match self {
            Self::SECP256K1(key) => key,
            Self::ED25519(_) | Self::MLDSA65(_) => panic!(),
        }
    }

    /// Length, in bytes, of the on-trie identifier for an access-key
    /// entry owned by this public key. For ed25519/secp256k1 this matches
    /// `len()`; for ML-DSA-65 the trie stores a SHA3-256 hash (33 bytes
    /// including the type tag), not the 1953-byte borsh-encoded pubkey.
    /// Used by storage-fee calculations on the runtime side; cheap to call
    /// (no hashing) - for ML-DSA-65 this returns the size of the digest
    /// form without actually hashing the pubkey.
    pub fn trie_id_len(&self) -> usize {
        match self {
            Self::ED25519(_) => 1 + ed25519_dalek::PUBLIC_KEY_LENGTH,
            Self::SECP256K1(_) => 1 + 64,
            Self::MLDSA65(_) => 1 + ML_DSA_65_HASH_LENGTH,
        }
    }

fn access_key_storage_usage(
    fee_config: &RuntimeFeesConfig,
    public_key: &PublicKey,
    access_key: &AccessKey,
) -> StorageUsage {
    let storage_usage_config = &fee_config.storage_usage_config;
    // Use the on-trie identifier length, not the borsh-serialized pubkey
    // length: ML-DSA-65 access keys live in the trie as a SHA3-256 hash
    // (33 bytes incl. type tag), not as a 1953-byte full pubkey.
    public_key.trie_id_len() as u64
        + borsh::object_length(access_key).unwrap() as u64
        + storage_usage_config.num_extra_bytes_record
}

fn permission_exec_fees(
    permission: &AccessKeyPermission,
    config: &RuntimeConfig,
    account_id: &AccountId,
    public_key: &PublicKey,
) -> ParameterCost {
    let fees = &config.fees;
    let key_fee = match permission {
        AccessKeyPermission::FunctionCall(perm)
        | AccessKeyPermission::GasKeyFunctionCall(_, perm) => {
            let num_bytes = perm
                .method_names
                .iter()
                // Account for null-terminating characters.
                .map(|name| name.as_bytes().len() as u64 + 1)
                .sum::<u64>();
            let base_fee = fees.fee(ActionCosts::add_function_call_key_base).exec_fee();
            let byte_fee = fees.fee(ActionCosts::add_function_call_key_byte).exec_fee();
            let all_bytes_fee = byte_fee.checked_mul(num_bytes).unwrap();
            base_fee.checked_add(all_bytes_fee).unwrap()
        }
        AccessKeyPermission::FullAccess | AccessKeyPermission::GasKeyFullAccess(_) => {
            fees.fee(ActionCosts::add_full_access_key).exec_fee()
        }
    };
    // Additional costs for adding an access key with GasKeyFunctionCall or GasKeyFullAccess permissions.
    let gas_key_info = match permission {
        AccessKeyPermission::GasKeyFullAccess(info)
        | AccessKeyPermission::GasKeyFunctionCall(info, _) => info,
        _ => return key_fee,
    };
    let nonce_fee = gas_key_add_key_exec_fee(
        fees,
        account_id.len(),
        public_key.trie_id_len(),
        gas_key_info.num_nonces,
    );
    key_fee.checked_add(nonce_fee.total()).unwrap()
}

/// Exec fee for TransferToGasKey / WithdrawFromGasKey actions.
/// Based on the access key trie key length + estimated value length (what the
/// receiver needs to read/write in the trie).
pub fn gas_key_transfer_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
) -> GasKeyTransferFee {
    let base = cfg.fee(ActionCosts::gas_key_transfer_base).exec_fee();
    let trie_key_len = access_key_key_len(account_id_len, public_key_len);
    let estimated_value_len = AccessKey::min_gas_key_borsh_len();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((trie_key_len + estimated_value_len) as u64)
        .unwrap();
    GasKeyTransferFee { base, per_byte }
}

pub fn gas_key_add_key_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
    num_nonces: NonceIndex,
) -> GasKeyAddFee {
    let num_nonces = num_nonces as u64;
    let base =
        cfg.fee(ActionCosts::gas_key_nonce_write_base).exec_fee().checked_mul(num_nonces).unwrap();
    let nonce_key_len =
        access_key_key_len(account_id_len, public_key_len) + std::mem::size_of::<NonceIndex>();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((nonce_key_len + AccessKey::NONCE_VALUE_LEN) as u64)
        .unwrap()
        .checked_mul(num_nonces)
        .unwrap();
    GasKeyAddFee { base, per_byte }
}
