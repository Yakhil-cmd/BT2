### Title
Unauthenticated Parent Bridge Peer Can Corrupt KIP71 Gas Price Config via Crafted `ServiceChainParentChainInfoResponseMsg` — (`node/sc/sub_bridge_handler.go`)

### Summary

`SubBridgeHandler.HandleMainMsg` accepts `ServiceChainParentChainInfoResponseMsg` (0x04) from any connected bridge peer and passes the decoded `parentChainInfo` struct directly into `setRemoteChainValues` → `SetParentKIP71Config` with **no bounds validation** and **no peer authentication** beyond a NetworkId/ProtocolVersion handshake. An attacker who can establish a bridge P2P connection to the SubBridge node can permanently corrupt `pAccount.kip71Config.UpperBoundBaseFee` and `remoteGasPrice` to any `uint64` value, causing all subsequent bridge transactions to use an attacker-controlled gas price.

### Finding Description

**Code path:**

`HandleMainMsg` dispatches on message code 0x04: [1](#0-0) 

`handleParentChainInfoResponseMsg` RLP-decodes the raw peer message into `parentChainInfo` with no field validation: [2](#0-1) 

It then unconditionally calls `setRemoteChainValues`: [3](#0-2) 

`setRemoteChainValues` writes the attacker-supplied `UpperBoundBaseFee` directly into `remoteGasPrice` and into `pAccount.kip71Config` with no bounds check: [4](#0-3) 

`SetParentKIP71Config` is a bare assignment with no validation: [5](#0-4) 

**Downstream use of the corrupted value:**

`GenerateTransactOpts` (used for all bridge value-transfer transactions) uses `kip71Config.UpperBoundBaseFee` as the gas price when it is non-zero: [6](#0-5) 

`genUnsignedChainDataAnchoringTx` uses `sbh.remoteGasPrice` directly as the gas price for anchoring transactions: [7](#0-6) 

**Authentication gap:**

The P2P handshake (`readStatus`) only validates `NetworkId` and `ProtocolVersion`: [8](#0-7) 

`RegisterNewPeer` only checks that the peer's self-reported `chainID` matches the configured parent chain ID — a value the attacker supplies in the handshake `statusData`: [9](#0-8) 

There is no cryptographic proof that the connecting peer is a legitimate parent chain node.

### Impact Explanation

- **`UpperBoundBaseFee = math.MaxUint64`**: Every anchoring and value-transfer bridge transaction is submitted with gas price `2^64 - 1`. Each transaction drains the bridge operator's KAIA balance by orders of magnitude more than intended. The operator account is drained rapidly, halting all bridge operations.
- **`UpperBoundBaseFee = 1` (below parent chain base fee)**: All bridge transactions are rejected by the parent chain mempool (`ErrGasPriceBelowBaseFee`), permanently halting anchoring and value transfers until the SubBridge is restarted and reconnects to a legitimate peer.
- **`GasPrice = 0` with `IsMagmaEnabled = false`**: `setRemoteGasPrice` sets `pAccount.gasPrice` to 0, causing the same rejection scenario via the non-Magma path.

The corrupted state persists in memory for the lifetime of the SubBridge process. If the attacker maintains the connection, they can re-send the message after any legitimate peer corrects the value.

### Likelihood Explanation

The SubBridge's bridge P2P port accepts incoming connections from any peer that can complete the RLPx handshake. The only application-layer checks are `NetworkId` (public) and `ProtocolVersion` (public). The parent chain ID is public information. An attacker who can reach the SubBridge's P2P port (which is often exposed for parent chain connectivity) can exploit this without any privileged access, key material, or validator collusion.

### Recommendation

1. **Bounds-check KIP71Config fields** in `setRemoteChainValues` before applying them. Reject or clamp `UpperBoundBaseFee` and `LowerBoundBaseFee` to governance-approved ranges (e.g., read from local chain config or a trusted on-chain source).
2. **Authenticate the responding peer** — only accept `ServiceChainParentChainInfoResponseMsg` from peers whose identity was verified against a configured allowlist (e.g., static parent node enodes), not from any peer that passes the NetworkId check.
3. **Rate-limit and deduplicate** info-response processing so a single peer cannot repeatedly overwrite the gas price config.

### Proof of Concept

```go
// Attacker connects to SubBridge P2P port, completes RLPx + status handshake
// with correct NetworkId and ProtocolVersion, then sends:
craftedMsg := parentChainInfo{
    Nonce:          0,
    GasPrice:       math.MaxUint64,
    IsMagmaEnabled: true,
    KIP71Config: params.KIP71Config{
        LowerBoundBaseFee:        0,
        UpperBoundBaseFee:        math.MaxUint64, // or 1 to halt
        GasTarget:                0,
        MaxBlockGasUsedForBaseFee: 0,
        BaseFeeDenominator:       1,
    },
}
p2p.Send(rw, ServiceChainParentChainInfoResponseMsg, craftedMsg)
// SubBridge now uses MaxUint64 as gas price for all bridge txs,
// draining pAccount on every anchoring/value-transfer submission.
```
