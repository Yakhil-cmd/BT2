### Title
Webhook signature is verified against an organization taken from an unverified payload field while handlers act on a different, independently-controlled repository field, enabling cross-organization forged deploy-triggering webhooks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/`webhook_secret` to validate a webhook against using `repository_owner`, itself read straight from the untrusted, attacker-supplied JSON body (`repository.owner.login`, or `organization.login`) [1](#0-0) [2](#0-1) . Every event handler, however, resolves the actual `Repository`/`Stack` to act on from a completely different field in the same body, `repository.full_name` [3](#0-2) [4](#0-3) . Because Shipit supports multiple independently-configured GitHub Apps/organizations, each with its own `webhook_secret` [5](#0-4) [6](#0-5) , an attacker who legitimately controls one onboarded organization (and therefore knows that organization's own `webhook_secret`) can forge a JSON body where `repository.owner.login` names their own org (so the correct secret is selected and the HMAC they compute themselves verifies) while `repository.full_name` names a victim organization's repository. The two fields are never cross-checked against each other.

### Finding Description
`verify_webhook_signature` computes an HMAC over the entire raw request body using the secret belonging to whatever organization the attacker names in `repository.owner.login`/`organization.login` [7](#0-6) . Since the attacker fully controls the body and legitimately knows this secret for their own org, they can produce a validly-signed payload for any content, including a `repository.full_name` pointing at a repository they do not own. `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` then dispatches the full, unmodified `params` to the registered handlers [8](#0-7) , and every handler resolves its target repository purely via `Repository.from_github_repo_name(params.repository.full_name)` [9](#0-8) [10](#0-9) , with no requirement that this repository belong to the organization whose secret validated the signature.

This breaks the intended binding: **organization that authenticated the request == organization that owns the repository being acted upon**. The signature only proves "the sender knows organization A's secret"; it proves nothing about the `repository` sub-object's authenticity.

### Impact Explanation
Using the `pull_request` `opened`/`reopened`/`labeled`/`unlabeled` handlers, an attacker can drive `ReviewStackAdapter#unarchive!`/`#find_or_create!`, which calls `Shipit::ReviewStackProvisioningQueue.add(stack)` and enqueues `GithubSyncJob`, ultimately invoking `stack.provisioner.up` (real provisioning/deploy machinery) for a stack belonging to a victim repository the attacker has no legitimate access to [11](#0-10) [12](#0-11) . This is an unauthorized deploy/provisioning action triggered on another organization's stack purely from a forged webhook that only had to be signed with the attacker's own, unrelated organization's secret. Other handlers (status, closed/archive, membership team-add) similarly act on payload fields unverified against the authenticating organization, allowing cross-organization state tampering (archiving stacks, injecting fabricated commit statuses, or team membership changes) on repositories/stacks not owned by the signing organization.

### Likelihood Explanation
Exploitation requires only that the attacker be a legitimate admin/owner of any one GitHub organization already configured as a Shipit GitHub App (a routine, low-privilege setup step for any organization wanting to use the shared Shipit instance in a multi-org deployment, as documented in `docs/setup.md`). No access to the victim's secret, session, or repository is required — only the ability to POST a crafted JSON body with a self-computed HMAC to the public `/webhooks` endpoint.

### Recommendation
After signature verification succeeds, cross-check that the repository/organization actually referenced by the payload's business fields (`repository.full_name`, or `organization.login` for membership events) belongs to the same organization whose secret validated the request, rejecting the webhook otherwise. Alternatively, derive the repository/stack strictly from the same field used to select the verifying secret, or embed and verify the expected organization identity as part of route/config binding rather than trusting attacker-supplied JSON.

### Proof of Concept
1. Legitimately register/administer an organization `attacker-org` as a Shipit GitHub App with its own `webhook_secret` in a Shipit deployment configured for multiple organizations (per `docs/setup.md`'s "Using Multiple Github Applications" section).
2. Craft a `pull_request` webhook JSON body:
```json
{
  "action": "opened",
  "number": 1,
  "pull_request": { "id": 1, "number": 1, "url": "...", "title": "x", "state": "open",
    "additions": 0, "deletions": 0, "head": { "sha": "deadbeef", "ref": "feature" },
    "user": { "login": "attacker" }, "assignees": [], "labels": [] },
  "repository": { "full_name": "victim-org/victim-repo", "owner": { "login": "attacker-org" } },
  "sender": { "login": "attacker" }
}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(attacker-org webhook_secret, body)>` using the attacker's own known `webhook_secret` for `attacker-org`.
4. POST to `/webhooks` with `X-Github-Event: pull_request`. `verify_signature` calls `Shipit.github(organization: 'attacker-org')` and validates successfully against the attacker's own secret [1](#0-0) .
5. `OpenedHandler` resolves the repository from `repository.full_name = "victim-org/victim-repo"` [4](#0-3)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
