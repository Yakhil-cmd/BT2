### Title
Stale delegate authorization reactivates after an account NFT returns to its prior owner - (File: contracts/controller/src/storage/account.rs)

### Summary

An account delegate removed from authority by an NFT ownership change can regain spending authority if the position NFT later returns to the original owner. The delegate can then withdraw the reacquired account’s collateral or borrow against it to themself. [1](#0-0) 

### Finding Description

The position NFT’s `owner_of` value is the lending account’s owner, while spending authority may also come from an active delegated position manager. [2](#0-1) [3](#0-2) 

Delegate grants are stored under `ControllerKey::Delegates(account_id)` and are returned whenever the grant’s `granted_by` equals the account’s currently resolved NFT owner. [1](#0-0)  The grant contains no ownership generation, transfer count, or other value that distinguishes one ownership tenure from a later tenure by the same address. [4](#0-3) 

Consequently, when owner Alice grants delegate Mallory and transfers the NFT to Bob, Mallory is temporarily rejected because `granted_by == Alice` does not equal current owner Bob. [1](#0-0)  If Bob transfers the NFT back to Alice without first calling `remove_delegate`, the same stored grant satisfies `granted_by == Alice` again and Mallory is treated as Alice’s current delegate. [1](#0-0) 

The code recognizes this stale-grant reactivation risk: `remove_delegate` deletes a grant whose `granted_by` differs from the caller-owner specifically so it cannot reactivate if the NFT returns to its original owner. [5](#0-4)  However, this cleanup is voluntary and requires the intermediate owner to invoke `remove_delegate`; the NFT transfer path does not automatically delete or version the grant. [6](#0-5) [7](#0-6) 

A reactivated delegate can call `withdraw` because `require_owner_or_delegate` accepts an active manager listed in the revived grant, and can direct the collateral payout to itself through the `to` argument. [8](#0-7)  The same stale authority also permits `borrow`, whose proceeds can likewise be paid to a delegate-selected external recipient. [9](#0-8) 

### Impact Explanation

This is theft of user funds. After the NFT round trip, the stale delegate can withdraw all debt-free collateral to itself, or withdraw and borrow up to the account’s solvency limit and leave the new owner with the resulting liabilities. [8](#0-7) [10](#0-9) 

The unauthorized party can monitor ownership changes and execute immediately when the NFT returns to the grantor, before the owner has an opportunity to inspect or revoke the reactivated grant. [1](#0-0) 

### Likelihood Explanation

The exploit requires three conditions: the original owner previously delegated to an active position manager, the account NFT is transferred to another owner, and the NFT is later transferred back without the intermediate owner deleting the stale grant. [11](#0-10) [12](#0-11) 

Those conditions do not require privileged protocol access, leaked keys, invalid parameters, or a contract upgrade; they use the supported delegate flow and ordinary position-NFT transfers. [13](#0-12) [7](#0-6) 

Because NFT transfers occur outside the controller and no transfer hook clears `Delegates(account_id)`, relying on the intermediate owner to perform optional cleanup leaves the stale authorization reachable. [12](#0-11) 

### Recommendation

Bind delegate grants to an ownership epoch rather than only to the owner address. Maintain a per-token owner-change counter in `position-nft`, increment it on every transfer, include that epoch in `DelegateGrant`, and require both `granted_by` and the current epoch in `get_delegates`.

Alternatively, make the position NFT notify the controller on every ownership change so the controller can delete `ControllerKey::Delegates(token_id)` atomically. The epoch design is safer because it prevents reactivation even if an intervening owner never invokes the controller.

### Proof of Concept

Assume Mallory is an active registered position manager and Alice controls a debt-free account holding collateral:

```rust
// Alice creates and funds account `account_id`.
let account_id = controller.supply(
    alice,
    0,
    spoke_id,
    vec![(collateral_hub_asset, collateral_amount)],
);

// Alice delegates to active manager Mallory.
controller.add_delegate(alice, account_id, mallory);

// Alice transfers the position NFT to Bob.
// This makes Mallory inactive only while Bob is owner.
position_nft.transfer(alice, bob, account_id as u32);

// Bob later transfers the same NFT back to Alice without calling
// controller.remove_delegate(bob, account_id, mallory).
position_nft.transfer(bob, alice, account_id as u32);

// The stale Alice-stamped grant satisfies get_delegates(account_id, alice).
// A zero withdrawal requests the full collateral position.
controller.withdraw(
    mallory,
    account_id,
    vec![(collateral_hub_asset, 0)],
    Some(mallory),
);
```

The final call resolves Alice as current owner, but `is_owner_or_delegate` still finds Mallory in the Alice-stamped grant and allows the withdrawal to Mallory’s recipient address. [14](#0-13) [8](#0-7)

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

/// Removes a live delegate and reports whether it changed the list.
/// Deletes stale grants but returns false, preventing those grants from
/// reactivating if the NFT returns to their original owner.
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}
