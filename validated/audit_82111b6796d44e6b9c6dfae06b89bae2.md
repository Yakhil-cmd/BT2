### Title
Sustained high-utilization accrual overflows the RAY value ceiling before the borrow-index cap engages, permanently freezing a market - (File: common/src/rates/index.rs)

### Summary
CVE-2024-21203 is a hang/repeatable-crash DoS class. The lending analog is a permanent market freeze: interest accrual multiplies total scaled debt by the borrow index in `Ray` (fixed point with RAY = 1e27). When `borrowed * new_borrow_index` exceeds `i128::MAX`, `Ray::mul` panics with `MathOverflow` inside `calculate_supplier_rewards`/`scaled_to_original`. The documented safety bound `MAX_BORROW_INDEX_RAY` is applied only to the index value itself in `update_borrow_index`, never to the debt value product, so on a large market the value ceiling is hit first. Because every mutating entrypoint runs `interest::global_sync` before doing anything, the panic permanently bricks the market — no `repay`, `withdraw`, `liquidate`, `clean_bad_debt`, or even `update_indexes` can succeed.

### Finding Description
`global_sync` (`contracts/pool/src/interest.rs:20-33`) runs on every market mutation and loops `accrue_chunk`, which calls `accrue_step`. Inside `accrue_step` the split of accrued interest computes `borrowed.mul(env, new_borrow_index)` (`common/src/rates/index.rs:80-83`) and the supply side computes `supplied.mul(env, old_index)` (`common/src/rates/index.rs:34`). `Ray::mul` uses checked i128 arithmetic and panics on overflow (`common/src/rates/scaling.rs:14-16` delegates to it). The index cap in `update_borrow_index` (`common/src/rates/index.rs:13-19`) clamps the index, not the product, so a book whose `borrowed` is large enough (e.g., a billion-unit 18-decimal market ⇒ ~1e36 RAY base) overflows the value domain while `borrow_index` is still far below its cap. The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`) demonstrates exactly this: `update_indexes` fails with `MATH_OVERFLOW`, then `withdraw` and `repay` fail identically, and `last.borrow_index < MAX_BORROW_INDEX_RAY` confirms the cap never engaged.

### Impact Explanation
Permanent freezing of funds and protocol insolvency for the affected market. All supplier claims and the pool cash backing them become unreachable, all borrower debt can neither be repaid nor liquidated, and bad debt cannot be cleaned or recapitalized — every path accrues first and hits the same panic. The freeze is irreversible because accrual is monotone in time: there is no entrypoint that skips `global_sync`.

### Likelihood Explanation
Fully reachable by unprivileged addresses with no privileged call required after market listing: `supply` (anyone deposits), `borrow` (anyone with collateral drives utilization into the curve's steep segment), and `update_indexes` (permissionless) to advance accrual. The preconditions are a high-decimal market with caps large enough to admit whale-scale books and sustained high utilization — both are legitimate, non-error configurations (`xlm_curve` at 98% utilization in the test). Cost is capital-heavy but requires no privilege, no leaked key, and no oracle manipulation. One caveat I could not fully verify within the iteration limit: whether market supply/debt caps as configured at listing always bound `borrowed * index` below `i128::MAX` — the test had to lift caps, so exploitability depends on caps permitting ~1e36 RAY-scale books, which the code does not itself guarantee.

### Recommendation
Make the value ceiling fail-closed rather than panic: in `update_borrow_index`/`accrue_step`, when `borrowed * new_index` would overflow, clamp `new_index` to `floor(i128::MAX / borrowed)` (and analogously clamp `supply_index` growth in `update_supply_index` against `supplied`), so accrual saturates instead of reverting. Alternatively, validate at market creation that `supply_cap_in_asset * MAX_BORROW_INDEX_RAY` cannot exceed `i128::MAX`, enforcing the documented bound.

### Proof of Concept
The repository's own test reproduces it end-to-end (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-361`):

1. Attacker/supplier `supply`s a billion whole units on an 18-decimal market; a collateralized `borrow` takes utilization to 98%.
2. Anyone calls `update_indexes` once per year; accrual compounds the borrow index past ~170x RAY.
3. The next accrual panics in `Ray::mul` with `MathOverflow`.
4. `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and `update_indexes` all revert with the same error, and `borrow_index < MAX_BORROW_INDEX_RAY` shows the cap never protected the value domain. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
