### Title
Missing reward settlement (`settle-rewards`/`settle-staker-rewards`) before mutating bond-cycle shares in `add-staker-to-bond-for-cycle` - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`add-staker-to-bond-for-cycle` mutates `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and `staker-shares-staked-for-cycle` for a bond-index cycle, but — unlike its STX-only-staking twin `add-staker-to-signer-for-cycle` — it never calls `settle-rewards`/`settle-staker-rewards` before doing so. This is the same bug class as the yETH `updateWeights` finding: a function changes the "weights"/shares that a reward accumulator depends on without first synchronizing that accumulator, leaving it stale.

### Finding Description
In `add-staker-to-signer-for-cycle` (STX-only staking path), the contract explicitly settles rewards *before* touching any share balances: [1](#0-0) 

This ordering matters: `settle-rewards` updates the signer's global rewards-per-token (`rpt`) accumulator using the *pre-mutation* total shares, and `settle-staker-rewards` credits the existing staker's earned rewards using their *pre-mutation* share balance and the just-updated `rpt`. Only after this settlement does the function increase `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and set the new staker's `staker-rewards-per-token-settled-for-cycle` marker: [2](#0-1) 

`add-staker-to-bond-for-cycle` (sBTC bond path) performs the analogous mutations of `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and `staker-shares-staked-for-cycle`, but with **no call to `settle-rewards` or `settle-staker-rewards` at all**: [3](#0-2) 

It directly sets the new staker's `staker-rewards-per-token-settled-for-cycle` marker to whatever `get-signer-rewards-per-token-for-cycle` currently returns (a stored, possibly stale value), and bumps `total-shares-staked-for-cycle`/`signer-shares-staked-for-cycle` *before* that global `rpt` value is ever brought up to date for the rewards that accrued against the *old* (smaller) share total.

This breaks the reward-accounting equality that `rewards_paid_to_staker = staker_shares * (rpt_at_withdrawal - rpt_at_join)` is supposed to preserve for shares that existed while a given tranche of rewards accrued. Because the global `rpt` for the bond-index cycle is never advanced to reflect the smaller pre-join share total before the new staker's shares are folded in, the next party that eventually calls `settle-rewards` for that cycle (whenever it happens) will compute the accrued-reward delta and divide it by the *inflated* (post-join) total-shares figure, instead of the total that actually existed while those rewards were being earned. The new staker's settled-marker was pinned to the old `rpt`, so they end up sharing in a `rpt` delta that was diluted by their own added shares — i.e., they retroactively collect a portion of rewards that accrued for the signer/bond pool before they ever staked, at the expense of the stakers who were already there.

### Impact Explanation
This lets a staker who joins a bond's reward-cycle share pool receive sBTC/STX reward credit for a period during which their capital was not locked, at the expense of existing stakers whose realized share of `rpt` is diluted. That is a reward being paid that was not earned by the recipient (and, conversely, under-paid to the stakers who actually earned it) — this falls under the explicitly in-scope impact category "sBTC rewards paid that were not earned or counted twice." Because this happens purely through the ordinary `stake-sbtc`/bond-registration flow (which reaches `add-staker-to-bond-cycles` → `add-staker-to-bond-for-cycle`), no privileged role is needed to trigger it.

### Likelihood Explanation
High. This occurs on every ordinary path that adds a staker to a bond's share tracking for a cycle where rewards have already begun accruing for existing signer/bond participants — i.e., any bond join/roll-over/registration update that isn't the very first staker in that cycle. No special timing or attacker coordination is required beyond staking into an existing bond mid-cycle.

### Recommendation
Mirror the STX-only-staking path: call `(settle-rewards signer reward-cycle (some bond-index))` (and `settle-staker-rewards` for the staker's own prior bond shares, if any, guarded the same way `add-staker-to-signer-for-cycle` guards on `prev-staker-shares > u0`) at the top of `add-staker-to-bond-for-cycle`, *before* mutating `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, or `staker-shares-staked-for-cycle`, so the `rpt` accumulator is synchronized against the pre-mutation share totals prior to admitting the new shares.

### Proof of Concept
1. Signer `S` has an existing bond cycle with `total-shares-staked-for-cycle = X` sats and accrued but unsettled rewards `R` pending (i.e., `settle-rewards` has not been called since `R` began accruing).
2. Staker `A` (new) calls the bond-staking entry point, which invokes `add-staker-to-bond-cycles` → `add-staker-to-bond-for-cycle`. This immediately sets `total-shares-staked-for-cycle = X + A_amount` and sets `A`'s `staker-rewards-per-token-settled-for-cycle` to the currently-stored (stale) `rpt`, without ever calling `settle-rewards` to account for `R` against the pre-existing total `X`.
3. Later, when `settle-rewards` is eventually invoked (e.g., by another staker joining or a reward-claim path) for this signer/bond-index/cycle, it computes the `rpt` delta for `R` using the now-inflated total `X + A_amount` instead of `X`.
4. When `A` claims rewards later, `A`'s earned amount is computed from `A`'s shares times the `rpt` delta that includes reward `R` (which accrued before `A` staked), so `A` receives a share of `R` that should have gone entirely to the pre-existing stakers who held shares `X` during that period. (define-private (add-staker-to-signer-for-cycle
        (cycle-index uint)
        (accumulator-res (response {
            signer: principal,
            staker: principal,
            amount-ustx: uint,
            first-reward-cycle: uint,
            is-stx-staking: bool,
        }
            uint
        ))
    )
    (let (
            (accumulator (try! accumulator-res))
            (cycle (+ cycle-index (get first-reward-cycle accumulator)))
            (signer (get signer accumulator))
            ;; Get the total uSTX delegated (through protocol bonds and STX-only
            ;; staking) to this signer.
            (cur-delegated-for-signer (get-amount-delegated-for-signer signer cycle))
            (amount (get amount-ustx accumulator))
            (stake-amount (if (get is-stx-staking accumulator)
                amount
                u0
            ))
            (staker (get staker accumulator))
            (prev-staked (get-signer-pending-staked-ustx-per-cycle signer cycle))
            (prev-total-shares-staked (get-total-shares-staked-for-cycle cycle none))
            (new-delegated (+ cur-delegated-for-signer amount))
            (prev-staker-shares (get-staker-shares-staked-for-cycle staker cycle none signer))
        )
        ;; Crystallize STX-only rewards before mutating anything
        (settle-rewards signer cycle none)
        ;; When zero, this is a no-op (`earned = shares * (rpt - rpt-paid) = 0`). In this case,
        ;; we skip calling `settle-staker-rewards` to reduce cost.
        (if (> prev-staker-shares u0)
            (settle-staker-rewards signer cycle none staker)
            {
                earned: u0,
                rewards-per-token: u0,
            }
        )
