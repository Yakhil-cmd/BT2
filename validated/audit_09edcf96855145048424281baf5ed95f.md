### Title
`repository.owner.login` used to select webhook signature verification org while `repository.full_name` selects the mutated `PullRequest`/`Stack`, allowing an unauthenticated forged `pull_request` `unassigned` event on a no-secret org to update a victim repository's `PullRequest` record - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` picks the `GitHubApp` used to authenticate the webhook via `repository_owner`, which is `params.dig('repository', 'owner', 'login')`, but every `pull_request` handler (including `AssignedHandler`) resolves the `Repository`/`Stack`/`PullRequest` it mutates via `params.repository.full_name`. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org has no `webhook_secret` configured. Because the two fields are never checked for consistency, an attacker who names a no-secret org in `repository.owner.login` while pointing `repository.full_name` at an unrelated (secret-protected) organization's repository can get the forged payload accepted and applied to that other repository's `PullRequest`.

### Finding Description
The broken invariant is: `repository.owner.login` (used to select the authenticating `GitHubApp`) SHOULD equal the owner encoded in `repository.full_name` (used to resolve the mutated `Repository`). The code never enforces this equality.

- `verify_signature` calls `Shipit.github(organization: repository_owner)` and `repository_owner` reads only `params.dig('repository', 'owner', 'login')` (or `organization.login` as fallback): [1](#0-0) [2](#0-1) 
- `GitHubApp#verify_webhook_signature` short-circuits to `true` when the resolved org's config has no `webhook_secret`: [3](#0-2)  — confirmed as a supported configuration by the test fixture with `webhook_secret: # nil` for `OrgOne`/`OrgTwo`: [4](#0-3) 
- Once past `verify_signature`, `WebhooksController#create` dispatches the raw JSON to the handler: [5](#0-4) 
- `AssignedHandler#process` runs for `action` in `[assigned, unassigned]` and calls `pull_request.update(github_pull_request: params.pull_request)`: [6](#0-5) 
- `pull_request` and `repository` are both derived exclusively from `params.repository.full_name`, never from `repository.owner.login`: [7](#0-6) 
- `Repository.from_github_repo_name` simply splits `full_name` on `/` and does a `find_by(owner:, name:)`, with no cross-check against the authenticating org: [8](#0-7) 

Exploit flow: attacker sends `POST /webhooks` with `X-Github-Event: pull_request`, body `{"action":"unassigned","number":<N>,"pull_request":{...},"repository":{"owner":{"login":"no-secret-org"},"full_name":"victim-org/victim-repo"},"sender":{"login":"attacker"}}`. `verify_signature` selects the `no-secret-org` `GitHubApp` (configured without `webhook_secret`), which accepts any/no signature. The handler then resolves `victim-org/victim-repo` and, if a matching open `PullRequest` with that `number` exists for a stack of that repository, overwrites its `github_pull_request` column with attacker-controlled JSON (title, state, assignees, labels, sha/ref, additions/deletions) — a write to a resource belonging to a repository/org that never authenticated this request.

Existing guards do not stop this: `drop_unhandled_event` and `check_if_ping` only gate on event type; `verify_signature` never compares `repository_owner` to the owner segment of `repository.full_name`; `ExplicitParameters` schema only validates types/presence, not owner consistency; there is no model validation tying `PullRequest`/`Stack`/`Repository` lookups back to the authenticating org.

### Impact Explanation
An attacker can overwrite the persisted `github_pull_request` JSON blob for an arbitrary open `PullRequest` belonging to any repository/stack in the Shipit instance, as long as (a) there exists at least one org in `Shipit.github` config without a `webhook_secret`, and (b) a `PullRequest` with the guessed/known `number` exists for the targeted repository's stack. This is a payload for one repository (the no-secret org) being used to mutate another repository's (victim's) stack data — matching the Critical category "a payload for one repository mutating another's stack, commit, task or team." The attack is fully repeatable against any repository/stack whose PR number is known, and scales across every stack hosted by the instance since `full_name` is fully attacker-controlled per request.

### Likelihood Explanation
Precondition: the Shipit deployment must have at least one GitHub organization configured in `Shipit.github` without a `webhook_secret` (documented/supported configuration, evidenced by the double-app test fixture). No GitHub credentials, session, API token, or team membership is required — this is a raw unauthenticated `POST /webhooks`. The attacker only needs to know/guess a target `owner/repo` and a PR `number`; PR numbers are small integers and repo names are typically public. Cost is a single HTTP request; the attack is trivially repeatable.

### Recommendation
In `WebhooksController#verify_signature`, after resolving the `GitHubApp` from `repository_owner`, verify that the owner segment of `repository.full_name` (and/or `organization.login` when present) matches `repository_owner` before proceeding; reject (422) on mismatch. Additionally, each handler that resolves a `Repository`/`Stack` via `full_name` should confirm that the resolved repository's `owner` matches the org that authenticated the webhook, rather than trusting `full_name` unconditionally.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "pull_request unassigned forged via no-secret org mutates a different org's PullRequest" do
  # Setup: configure Shipit.github with two orgs -- "no-secret-org" (no webhook_secret)
  # and "victim-org" (has webhook_secret). Create victim_repo owned by "victim-org",
  # a stack for it, and a PullRequest with number: 7 and known github_pull_request state.

  victim_repo = shipit_repositories(:victim) # owner: victim-org
  stack = shipit_stacks(:victim_stack)
  pr = Shipit::PullRequest.create!(stack: stack, number: 7, github_pull_request: { "title" => "original" })

  forged_payload = {
    action: "unassigned",
    number: 7,
    pull_request: {
      id: 1, number: 7, url: "http://x", title: "ATTACKER OVERWRITE",
      state: "open", additions: 0, deletions: 0,
      head: { sha: "a" * 40, ref: "attack" },
      user: { login: "attacker" },
      assignees: [], labels: []
    },
    repository: { owner: { login: "no-secret-org" }, full_name: "victim-org/#{victim_repo.name}" },
    sender: { login: "attacker" }
  }.to_json

  @request.headers['X-Github-Event'] = 'pull_request'
  # No X-Hub-Signature header, or an arbitrary/invalid one.

  post :create, body: forged_payload, as: :json

  assert_response :ok
  pr.reload
  # Equality broken: repository_owner ("no-secret-org") != owner of full_name ("victim-org"),
  # yet the write to victim's PullRequest succeeded.
  assert_equal "ATTACKER OVERWRITE", pr.github_pull_request["title"]
end
```
This demonstrates the binding `repository_owner == owner(repository.full_name)` is not enforced: signature verification is authorized by `no-secret-org` while the actual database mutation lands on `victim-org`'s `PullRequest`.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
