## Title
`MergeStatusController#dequeue` allows any authenticated, org-authorized user to cancel another repository's queued `MergeRequest` - (File: `app/controllers/shipit/merge_status_controller.rb`)

## Summary
`dequeue` only checks `merge_request.waiting?` before calling `merge_request.cancel!`, with no check that the acting `current_user` owns the PR or maintains the target `stack`'s repository. Any logged-in user who passes the global `Shipit.github_teams` gate in `force_github_authentication` can cancel a merge request queued by an unrelated team on an unrelated repository.

## Finding Description
The broken binding is: `merge_request.stack.repository == repository the current_user maintains/owns`. This is never checked. The relevant guard is `force_github_authentication` in `app/controllers/concerns/shipit/authentication.rb` (lines 20-34), which only enforces `current_user.logged_in?` and `current_user.authorized?` — the latter (`app/models/shipit/user.rb` lines 80-82) merely checks membership in `Shipit.github_teams` globally, not membership tied to any specific repository/stack. `dequeue` itself (`app/controllers/shipit/merge_status_controller.rb` lines 32-37) does:

```ruby
def dequeue
  if (merge_request = stack.merge_requests.find_by_number(params[:number])) && merge_request.waiting?
    merge_request.cancel!
  end
  render(stack_status, layout: !request.xhr?)
end
```

`stack` is resolved from `params[:stack_id]` via `Stack.from_param!` (line 63-64) with no ownership/team-membership check against that specific stack's repository — it is a totally attacker-controlled route parameter (`DELETE /merge_status/*stack_id/pull/:number`). Once any team member is authenticated (satisfies `authorized?` globally), they can supply any `stack_id`/`number` pair belonging to a different, unrelated repository whose `MergeRequest` is `waiting?`, and `cancel!` fires unconditionally. Existing guards (`skip_authentication`, `authorized?`, `stack` lookup) never validate that the caller has any relationship — maintainer, contributor, or PR author — to the target stack's repository.

## Impact Explanation
An authenticated org member can silently cancel a legitimately queued/pending merge for any stack in the Shipit instance, including stacks belonging to teams/repos they have no relation to. This is a cross-tenant, unauthorized mutation of another repository's merge-queue state (denial of a scheduled ship), matching the "payload for one repository mutating another's stack" Critical category. The action is repeatable against arbitrary stacks/PR numbers as long as the target `MergeRequest` is in `waiting?` state.

## Likelihood Explanation
Preconditions: the attacker must have a Shipit session and be a member of at least one team in `Shipit.github_teams` (the global authorization gate) — this is a real but modest barrier since `Shipit.github_teams` is often a broad organization-wide team list rather than per-repository ACLs, so many org members satisfy it without being maintainers of the specific target repo. No secrets, tokens, or webhook forgery are required, and the request is a simple authenticated `DELETE`. This aligns with the question's precondition of "minimally-authorized team member with no relation to the target repo."

## Recommendation
Add an authorization check in `dequeue` (and `enqueue`) that verifies `current_user` maintains/is authorized on `stack.repository` specifically (e.g., via a `require_permission!`/`stack.repository.maintainers.include?(current_user)`-style check, or restrict to the PR's own author matching `merge_request.merge_requested_by`), rather than relying solely on the global `Shipit.github_teams` membership check.

## Proof of Concept
```ruby
# test/controllers/shipit/merge_status_controller_test.rb (minitest)
test '#dequeue cancels a merge request on a stack the current user does not maintain' do
  attacker = shipit_users(:walrus) # any authorized team member, no relation to target repo/stack
  other_stack = shipit_stacks(:shipit) # belongs to a different repo/team
  mr = other_stack.merge_requests.create!(number: 42, merge_status: 'pending')

  session[:user_id] = attacker.id

  # Binding under test: mr.stack.repository != any repository attacker maintains
  refute attacker.teams.joins(:repositories).where(repositories: { id: other_stack.repository_id }).exists?

  delete "/merge_status/#{other_stack.to_param}/pull/42"

  assert mr.reload.canceled?, "attacker with no relation to the target repo was able to cancel another team's merge request"
end
