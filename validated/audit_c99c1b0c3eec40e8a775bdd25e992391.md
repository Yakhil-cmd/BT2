### Title
`collectStakingAmounts()` Ignores `CLStakingAmount` in Permissioned Demotion Logic, Causing Invalid Validator Demotion — (`File: kaiax/valset/impl/getter_demote.go`)

### Summary

In the window between the Prague hardfork (which introduces consensus-liquidity / CLStaking) and the Permissionless hardfork, the permissioned validator-demotion path calls `collectStakingAmounts()`, which only reads `cn.StakingAmount` (CNStaking from AddressBook) and silently ignores `cn.CLStakingInfo.CLStakingAmount`. A validator whose CNStaking alone is below `minStake` but whose combined CNStaking + CLStaking meets or exceeds `minStake` is incorrectly demoted, producing an invalid active-validator-set state transition.

### Finding Description

`getDemotedValidatorsIstanbul()` is the permissioned demotion function. It calls `collectStakingAmounts()` to build a per-node staking map, then demotes every node whose mapped amount is below `pset.MinimumStake`. [1](#0-0) 

`collectStakingAmounts()` iterates over `ConsolidatedNodes()` and assigns only `cn.StakingAmount` — the CNStaking balance — to each node. It never reads `cn.CLStakingInfo.CLStakingAmount`: [2](#0-1) 

By contrast, `consolidatedNode` carries a `CLStakingInfo` pointer that is populated after Prague: [3](#0-2) 

The reward-distribution functions (`assignStakingRewards`, `assignStakingRewardsFlex`) correctly add `cn.CLStakingInfo.CLStakingAmount` to the total when computing staking-proportional rewards: [4](#0-3) 

The demotion path does not. The fork ordering is `Randao ≤ Kaia ≤ Prague ≤ Permissionless`. Between Prague activation and Permissionless activation, `GetDemotedValidators()` routes to the permissioned path: [5](#0-4) 

During this window, `GetStakingInfo()` already returns `CLStakingInfos` populated from the CLRegistry: [6](#0-5) 

But `collectStakingAmounts()` discards that data, so the effective staking amount seen by the demotion logic is `CNStaking` only, not `CNStaking + CLStaking`.

### Impact Explanation

A validator with `CNStaking < minStake` but `CNStaking + CLStaking ≥ minStake` is incorrectly added to the demoted set and excluded from the active validator set. This is an invalid state transition: the canonical active-validator set does not reflect the true on-chain staking state. Consensus operates with fewer validators than the protocol requires, weakening liveness and safety thresholds. Because all nodes run the same code, the incorrect set is agreed upon deterministically, but it diverges from the intended protocol invariant.

### Likelihood Explanation

The bug is reachable on any network that activates Prague before Permissionless (the documented and intended ordering). It requires at least one validator to hold CLStaking that, combined with CNStaking, crosses `minStake`. This is an expected configuration under KIP-226 (consensus liquidity). No privileged access or majority-validator collusion is needed; the incorrect demotion fires automatically during normal block processing.

### Recommendation

In `collectStakingAmounts()`, add `CLStakingAmount` to the node's staking total when `CLStakingInfo` is non-nil, mirroring the logic already present in `assignStakingRewards()`:

```go
func collectStakingAmounts(nodes []common.Address, si *staking.StakingInfo) map[common.Address]float64 {
    cns := si.ConsolidatedNodes()
    stakingAmounts := make(map[common.Address]float64, len(nodes))
    for _, node := range nodes {
        stakingAmounts[node] = 0
    }
    for _, cn := range cns {
        total := float64(cn.StakingAmount)
        if cn.CLStakingInfo != nil {
            total += float64(cn.CLStakingInfo.CLStakingAmount)
        }
        for _, node := range cn.NodeIds {
            if _, ok := stakingAmounts[node]; ok {
                stakingAmounts[node] = total
            }
        }
    }
    return stakingAmounts
}
```

### Proof of Concept

Setup (Prague active, Permissionless not yet active, `minStake = 5_000_000 KAIA`):

| Validator | CNStaking | CLStaking | Total |
|-----------|-----------|-----------|-------|
| V1 | 4_999_999 | 1 | 5_000_000 |
| V2 | 6_000_000 | 0 | 6_000_000 |

1. `GetDemotedValidators(num)` routes to `getDemotedPermissioned` because Permissionless is not yet active. [7](#0-6) 
2. `getDemotedValidatorsIstanbul` calls `collectStakingAmounts`. [8](#0-7) 
3. `collectStakingAmounts` assigns `stakingAmounts[V1] = 4_999_999` (CLStaking ignored). [9](#0-8) 
4. `uint64(4_999_999) < 5_000_000` → V1 is added to `demoted`. [10](#0-9) 
5. V1 is excluded from the active validator set despite having sufficient total stake (`4_999_999 + 1 = 5_000_000 ≥ minStake`). This is an invalid state transition affecting consensus participation.
