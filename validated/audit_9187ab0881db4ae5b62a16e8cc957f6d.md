**Rationale:**

The reported CVE concerns JavaScript prototype pollution in `fast-json-patch`, where JSON-Patch operations (e.g., paths containing `__proto__`) can write into `Object.prototype` because JS objects have a mutable prototype chain. This bug class has no structural analog in Rust/`serde_json`: `serde_json::Value::Object` is backed by a `Map`/`BTreeMap`, has no prototype chain, and there is no mechanism by which merging untrusted JSON keys could escalate to modifying shared/global object behavior [1](#0-0) .

The only comparable "JSON patch merge" logic in this repo is `sc_chain_spec::json_patch::merge`, used exclusively in developer/node tooling: genesis config preset testing, `chain-spec-builder` CLI commands (`ConvertToRaw`, code updates), and the `benchmarking-cli` overhead command for constructing genesis state from user-supplied files [2](#0-1) [3](#0-2) [4](#0-3) . This is not a live runtime entry point reachable via a signed extrinsic, enabled contract call, or XCM message; it is invoked offline by node operators/CI when building chain specs or genesis state, before a chain is live. There is no attacker-controlled, on-chain reachable path into this function, and it does not process untrusted network input at runtime.

Per the analog-scan methodology, dependency-only/config-only findings and prerequisites requiring privileged/tooling access rather than an actual on-chain entry point are explicitly out of scope, and no user-entry-point wiring exists to justify a Polkadot SDK analog to this npm prototype-pollution advisory.
