### Title
Unprivileged user can permanently freeze a market via RAY-value overflow in accrual — (`File: common/src/rates/simulate.rs`)

### Summary
Analogous to the Squid DoS (crafted input reaching a code path that crashes request processing), any unprivileged address can drive a pool market into a state where every subsequent accrual panics on `i128` overflow inside `scaled_to_original`. Because every mutating verb accrues interest first (`global_sync` → `accrue_chunk` → `accrue_step`), the overflow permanently bricks supply, withdraw, repay, borrow, liquidation, and bad-debt cleanup for that market — the index ceiling that is supposed to bound growth never engages.

### Finding Description
- `simulate_update_indexes_body` / `accrue_chunk` call `accrue_step`, which computes `scaled_to_original(env, borrowed, borrow_index)` and `scaled_to_original(env, supplied, supply_index)` at the top of every step. `scaled_to_original` is a plain `Ray::mul` that panics on overflow — there is no saturation or clamp. [1](#0-0) [2](#0-1) 
- `global_sync` runs this before every pool mutation, so once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, every entry path reverts. [3](#0-2) 
- `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY` (10^36 raw), but the value ceiling is hit first: the docs themselves bound a position at ~170.14B whole tokens / ~170x index growth, while a whale book near the admitted cap maximum overflows accrual long before the index cap. [4](#0-3) 
- The harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates this end-to-end: at 98% utilization on a steep rate curve, `update_indexes` fails with `MATH_OVERFLOW` and subsequently `withdraw` and `repay` both revert with the same error — a permanent freeze, since indexes are monotone and only grow. [5](#0-4) 

### Impact Explanation
Permanent freezing of funds for every supplier and borrower in the affected market: no withdraw, repay, liquidation, or `clean_bad_debt` can ever execute, and `recapitalize` also accrues first, so the book cannot be repaired. All tokens held by the pool for that (hub, token) book are locked forever. A single unprivileged address can manufacture the preconditions by supplying near-cap size and borrowing ~98% through its own collateral position (caps up to the admitted maximum are permissionless entries).

### Likelihood Explanation
Medium. The path is fully permissionless (`supply`/`borrow`/`update_indexes`), requires no privileged role and no external failure, and is proven by an in-repo test. The cost is high — it needs a book whose RAY value approaches `i128::MAX` (on the order of 170B whole tokens at 18 decimals, or proportionally less at lower decimals/scaled-share counts) plus sustained high utilization — and the freeze develops over accrual time rather than instantly. The borrow index is monotone, so once utilization stays high the outcome is a matter of when, not if; nobody can repay or exit to defuse it once the cliff is crossed, and approaching the cliff already discourages rescue because early repayment also accrues.

### Recommendation
Make accrual fail-safe instead of panicking: clamp `borrowed_original`/`supplied_original` (e.g., saturate like `calculate_scaled_cap`) or short-circuit accrual once a market's scaled value exceeds a computed safe bound, storing a "saturated" flag that lets withdraw/repay proceed against the last-good index. Alternatively, enforce a scaled-value ceiling at entry (`supply`/`borrow`/liquidation credit) sized so that `value * MAX_BORROW_INDEX_RAY` cannot overflow before the index cap engages. Add a regression gate so `MAX_BORROW_INDEX_RAY` is always reachable before any `scaled_to_original` overflow.

### Proof of Concept
The existing test is the PoC (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-361`): deploy an 18-decimal market with the XLM stress curve, lift caps, `supply_raw(BOB, BIG18, 1e9 * 1e18)`, `borrow_raw(ALICE, BIG18, 98% of principal)`, then advance time yearly and call controller `update_indexes(&[BIG18])`. Within the 40-year bound it reverts with `MATH_OVERFLOW`, after which `try_withdraw_raw` and `try_repay` revert identically — the market is permanently frozen while `borrow_index < MAX_BORROW_INDEX_RAY`, proving the cap never engages.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
