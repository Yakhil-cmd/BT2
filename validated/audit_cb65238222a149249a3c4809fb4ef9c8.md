### Title
Borrower can permanently block their own liquidation by supplying a dust amount of a `no_seize` collateral asset - ([File: contracts/controller/src/positions/liquidation/plan.rs](contracts/controller/src/positions/liquidation/plan.rs))

### Summary
The Symmio report describes a user front-running liquidation to invalidate a signature-bound input (the nonce). XOXNO Lending has no signatures or nonces, but the same bug class — a borrower mutating their own account state to make every liquidation transaction revert — exists through the pro-rata seizure design. Because collateral is seized pro-rata across *all* of an account's supply positions, and the `SeizureLeg` policy panics on any leg flagged `no_seize`, a borrower can add a dust supply position in a collateralizable asset that carries the `no_seize` flag and become permanently unliquidatable.

### Finding Description
`build_liquidation_plan` computes a pro-rata seizure over every supply position and then enforces `FreezePolicy::SeizureLeg` on each seized leg:

```rust
// contracts/controller/src/positions/liquidation/plan.rs
for entry in seized_collaterals.iter() {
    enforce_spoke_asset_flags(env, cache, account.spoke_id, &entry.hub_asset, FreezePolicy::SeizureLeg);
}
```

`SeizureLeg` reverts with `SpokeAssetSeizureHalted` whenever the spoke asset's `no_seize` flag is set (`contracts/controller/src/positions/mod.rs`, `enforce_spoke_asset_flags`). The same check is repeated in `apply_liquidation_seizures` and `apply_liquidation_share_credit`, so both `SeizeMode::Transfer` and `SeizeMode::Credit` are blocked.

Meanwhile `no_seize` does not block entry: the test `no_seize_does_not_block_entry_or_exit` in `contracts/controller/tests/positions/flags.rs` explicitly proves `BlockOnEntry` and `AllowOnExit` pass with `no_seize = true`. `upsert_spoke_asset` (`contracts/controller/src/config/asset.rs`) performs no validation preventing `can_collateral = true` together with `no_seize = true`.

Attack path reachable by a single unprivileged address (the account owner):

1. Borrower opens a leveraged position (`supply` + `borrow`).
2. A collateralizable asset in the same spoke carries `no_seize = true` (e.g., an asset being wound down via the flag-ratchet path `set_spoke_asset_flags`, which can only tighten).
3. When the position approaches HF < 1, the borrower calls `supply(caller=owner, account_id, spoke_id, [(hub_asset_no_seize, dust_amount)])` — front-running or pre-empting any liquidation. Adding a new supply asset requires owner/delegate auth, which the borrower holds; third-party `supply` is restricted to existing assets but the owner is not.
4. Every subsequent `liquidate(liquidator, account_id, debt_payments, seize_mode)` call panics with `SpokeAssetSeizureHalted` (#318) during plan building, before any repayment is pulled. There is no way for a liquidator to exclude the poisoned leg — seizure is pro-rata over the whole collateral set, and `debt_payments` only selects debt legs.
5. The borrower can keep the dust position indefinitely; withdrawing it is voluntary. Even `clean_bad_debt` cannot help: it only socializes debt when residual collateral is at/below the dust threshold, and the unseizable collateral remains.

This mirrors the Symmio finding's shape exactly: a state element the victim controls (here, the set of supply positions feeding pro-rata seizure instead of a signature nonce) is mutated to make the liquidation call revert, at negligible cost.

### Impact Explanation
Permanent prevention of liquidation for the affected account. A borrower who is underwater can ride out adverse price moves while keeping upside, leaving the protocol to absorb bad debt: if collateral value falls below debt, the account is insolvent yet cannot be liquidated, and `clean_bad_debt` cannot clear it because real collateral remains on the books. This converts to protocol insolvency / socialized loss to suppliers. It matches the accepted impact classes (protocol insolvency; a contract unable to operate for the targeted account).

### Likelihood Explanation
Requires a spoke listing that is simultaneously `is_collateralizable` and `no_seize`. Nothing in `upsert_spoke_asset` forbids that combination, and the flag ratchet (`require_flag_ratchet`) is designed so that governance tightening `no_seize` during an asset wind-down is a supported operation — precisely the moment an asset is risky and borrowers are most likely to be liquidated. The attack cost is one dust `supply` call; the position-limit cap only permits it when a slot is free, but a borrower can keep one slot open deliberately.

Uncertainty: this is exploitable only while such a listing exists in the account's spoke; if governance never co-sets `can_collateral` and `no_seize`, the attack surface is latent rather than live. Whether that combination is considered a "bad parameter" misconfiguration versus a code-level missing invariant is a judgment call, but the contract enforces no invariant preventing it, and the ADR-0008 design comments show seizure-blocking was only considered for `paused`, not for user-opt-in `no_seize`.

### Recommendation
Enforce at listing/edit time that a collateralizable asset cannot carry `no_seize` (`upsert_spoke_asset` in `contracts/controller/src/config/asset.rs`), or make `require_can_supply` reject supplying assets flagged `no_seize`, so users cannot opt into seizure immunity. Alternatively, exclude `no_seize` positions from the pro-rata seizure set in `calculate_seized_collateral` rather than reverting, though that changes the documented all-or-nothing seizure semantics.

### Proof of Concept
1. Governance lists asset X in spoke S with `can_collateral = true`, `no_seize = true` (or later tightens `no_seize` via `set_spoke_asset_flags` while X remains collateralizable).
2. Bob: `supply` 10,000 USDC, `borrow` ETH near max LTV in spoke S.
3. ETH price rises; Bob's HF < 1.
4. Bob front-runs the liquidator: `supply(bob, account_id, S, [(X, 1 unit)])`. Entry gates (`BlockOnEntry`) ignore `no_seize`, so this succeeds.
5. Liquidator calls `liquidate(carol, account_id, [(ETH_debt, amt)], SeizeMode::Transfer)`. `build_liquidation_plan` includes X in `seized_collaterals` (pro-rata over all supply positions), `enforce_spoke_asset_flags(.., SeizureLeg)` hits `sa.no_seize == true` and panics with `SpokeAssetSeizureHalted`.
6. Repeat forever — every liquidation attempt reverts. Bob waits for prices to revert or lets the debt go bad.
