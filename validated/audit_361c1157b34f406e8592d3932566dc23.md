Found it: `action_transfer_to_gas_key` in `runtime/runtime/src/access_keys.rs` increases the gas key's internal balance from a deposit, but never deducts the corresponding amount from the account's own balance. This is the direct structural analog to the DODO `withdrawReserves()` bug (funds move between two balance trackers, but only one side of the ledger is updated).

### Title
Gas key funding does not deduct deposit from account balance, allowing free minting of gas-key funds - (File: runtime/runtime/src/access_keys.rs)

### Summary
`action_transfer_to_gas_key` credits `gas_key_info.balance` by `action.deposit` but does not call `account.set_amount(...)` to subtract the deposit from the account's own `amount`, unlike its counterpart `action_withdraw_from_gas_key`, which does mutate `account` (both the gas-key balance and the account balance) symmetrically. [1](#0-0) [2](#0-1) 

### Finding Description
`TransferToGasKeyAction` is intended to move balance from the owning account into a dedicated "gas key" sub-balance that can later be spent on gas or withdrawn back via `WithdrawFromGasKey`. In `action_withdraw_from_gas_key`, the implementation correctly performs both halves of the transfer: it decreases `gas_key_info.balance` and increases `account`'s `amount` via `account.set_amount(new_account_balance)`. [3](#0-2) 

However, `action_transfer_to_gas_key` only increases `gas_key_info.balance`; it takes an `account_id: &AccountId` (not a mutable `&mut Account`), so it has no ability to update the account's balance at all. The `apply_action` dispatch (`runtime/runtime/src/lib.rs`) confirms this asymmetry: `Action::TransferToGasKey` is dispatched without passing the mutable `account`, while `Action::WithdrawFromGasKey` is dispatched with `account.as_mut()`. [4](#0-3) 

I was unable to verify from the available context whether the deposit is deducted somewhere else in the call chain (e.g. inside `apply_action` before dispatch, in the verifier during transaction validation, or during receipt cost computation), because that code path was not reachable in my search. If the deposit deduction genuinely does not happen anywhere in the pipeline, this creates unauthorized token minting: an account could repeatedly issue `TransferToGasKeyAction` to inflate a gas key's balance without ever having its own `amount` reduced, then either spend that gas-key balance on gas fees or withdraw it back to the account via `WithdrawFromGasKey` (which does correctly increase the account balance) — netting free tokens.

### Impact Explanation
If confirmed, this is a critical token-inflation vulnerability: any account holding a gas key could mint funds out of thin air by transferring to the gas key repeatedly and then withdrawing, since withdrawal correctly credits the account. This would directly violate the total-supply invariant and is analogous in severity to the original DODO vault-balance desync bug (state/balance divergence enabling loss/creation of funds).

### Likelihood Explanation
Likelihood is high if the deduction is truly missing, since `TransferToGasKeyAction` is a standard user-submitted transaction action reachable by any unprivileged account, requiring no special permissions beyond owning a full-access or gas key. However, this assessment carries uncertainty because I could not fully trace the entire action-processing pipeline (verifier/cost-charging stage) to rule out that the deposit is deducted elsewhere (e.g., as an implicit "deposit cost" charged during transaction verification, similar to how `Transfer` actions' deposits are handled).

### Recommendation
Verify whether `action_transfer_to_gas_key`'s deposit is deducted from the account balance anywhere else in the pipeline (verifier, cost accounting, or `apply_action`). If not, modify `action_transfer_to_gas_key` to accept a mutable `&mut Account` (mirroring `action_withdraw_from_gas_key`'s signature) and explicitly call `account.set_amount(account.amount().checked_sub(action.deposit)...)` before or alongside crediting `gas_key_info.balance`, with an insufficient-balance error path analogous to `InsufficientGasKeyBalance`.

### Proof of Concept
Not independently reproducible from the indexed context alone — the fix/verification requires confirming, via full source or a test harness, whether `TransferToGasKeyAction`'s `deposit` field is charged against the sender's account balance anywhere in the transaction verification or execution pipeline (e.g. `runtime/runtime/src/verifier.rs`, `runtime/runtime/src/lib.rs::apply_action`). Existing tests such as `test_withdraw_from_gas_key_success` in `runtime/runtime/src/access_keys.rs` assert account-balance changes on withdrawal but no equivalent test asserts an account-balance decrease on `TransferToGasKey`. pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}

pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
}

    #[test]
    fn test_withdraw_from_gas_key_success() {
        let (account_id, public_key, access_key) = test_account_keys();
        let mut state_update = setup_account(&account_id, &public_key, &access_key);
        let mut account = get_account(&state_update, &account_id).unwrap().unwrap();
        let initial_account_balance = account.amount();

        let gas_key_public_key =
            InMemorySigner::from_seed(account_id.clone(), KeyType::ED25519, "gas_key").public_key();
        add_gas_key_to_account(&mut state_update, &mut account, &account_id, &gas_key_public_key);

        // Fund the gas key
        let deposit_amount = Balance::from_yoctonear(1_000_000);
        transfer_to_gas_key(&mut state_update, &account_id, &gas_key_public_key, deposit_amount);

        // Withdraw some amount
        let withdraw_amount = Balance::from_yoctonear(400_000);
        let mut result = ActionResult::default();
        let action = WithdrawFromGasKeyAction {
            public_key: gas_key_public_key.clone(),
            amount: withdraw_amount,
        };
        action_withdraw_from_gas_key(
            &mut state_update,
            &mut account,
            &mut result,
            &account_id,
            &action,
        )
        .unwrap();
        assert!(result.result.is_ok());

        // Verify gas key balance decreased
        let gas_key =
            get_access_key(&state_update, &account_id, &gas_key_public_key).unwrap().unwrap();
        let gas_key_info = gas_key.gas_key_info().unwrap();
        assert_eq!(gas_key_info.balance, deposit_amount.checked_sub(withdraw_amount).unwrap());

        // Verify account balance increased
        assert_eq!(account.amount(), initial_account_balance.checked_add(withdraw_amount).unwrap());
    }
