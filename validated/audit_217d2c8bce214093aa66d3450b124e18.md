### Title
Cross-organization CI-status forgery via unbound webhook signature — unauthorized deploy trigger ([File: app/models/shipit/webhooks/handlers/status_handler.rb])

### Summary
`WebhooksController#verify_signature` authenticates an inbound GitHub webhook against the `GitHubApp` configuration keyed by `repository_owner`, a field taken directly from the unauthenticated JSON payload (`repository.owner.login` or `organization.login`). The webhook HMAC only proves that *some* organization's registered secret was used to sign the whole request body — it does not, and cannot, bind that organization identity to the specific commit/repository the payload subsequently manipulates. `StatusHandler#process` then updates commit statuses purely by matching a `sha` value across the *entire* `Commit` table, with no check that the commit belongs to a stack owned by the authenticated organization.

### Finding Description
The signature check happens in `app/controllers/shipit/webhooks_controller.rb`: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` picks the `GitHubApp`/`webhook_secret` for whatever organization name is embedded in the payload, then `verify_webhook_signature` checks the HMAC over the raw body: [3](#0-2) 

Crucially, this only proves the request was signed by *an* organization Shipit trusts — the org identified by `repository_owner` — not that the payload's other fields (in particular the commit `sha` being updated) actually belong to that organization's repositories.

`StatusHandler` then acts on the payload without any repository/organization scoping at all: [4](#0-3) 

It looks up `Commit.where(sha: params.sha)` **globally**, across every stack/repository tracked by the Shipit instance, and calls `commit.create_status_from_github!(params)` on every match. Unlike `PushHandler`, which scopes to `Repository.from_github_repo_name(repository_name)` via `Handler#stacks`: [5](#0-4) 

`StatusHandler` never uses `repository_name`/`stacks` at all, so the "organization that authenticated" (used to pick the webhook secret) and "the repository that is written" (any commit row matching the given sha, regardless of owning stack) are two independent, unbound values from the same untrusted payload.

### Impact Explanation
Any organization onboarded to a multi-tenant Shipit instance — i.e., any org for which Shipit has a `webhook_secret` configured, which the org's own admins legitimately know since they configure their own repo webhooks pointing at Shipit — can sign a `status` event payload with its own secret while setting `sha` to a commit SHA belonging to a **different** organization's stack. Because `StatusHandler` matches commits globally by SHA, this forged, correctly-signed request creates a `Status` (e.g., `state: success`, matching a `context` in that victim stack's `ci.require` list) on the victim's commit. Since Shipit's deploy readiness/continuous-delivery logic gates on `Commit` status records (`ci.require`), this can satisfy CI requirements Shipit believes are green, enabling an unauthorized deploy to be triggered on a stack the attacker does not own or have any access to — a cross-organization write with deploy-authorization impact.

### Likelihood Explanation
Requires only that the attacker controls (or is an admin of) any organization already onboarded with a working webhook secret in the target Shipit instance — no compromise of the victim org, no repository write access to the victim repo, and no Shipit session/API token is needed. Commit SHAs are not secrets (visible via GitHub UI/API for any repo the attacker can view). This is a realistic and low-effort attack path in any Shipit deployment serving more than one organization.

### Recommendation
`StatusHandler` (and any other handler acting on payload data) must scope its lookups to the repository identified via `Handler#repository_name`/`stacks`, verifying that `repository_owner` used for signature verification matches the repository that owns the commit being updated — analogous to how `PushHandler` scopes through `stacks`. Concretely, restrict `Commit.where(sha: params.sha)` to commits belonging to stacks under `Repository.from_github_repo_name(payload.dig('repository','full_name'))`, and reject/ignore updates where that repository's owning organization differs from `repository_owner`.

### Proof of Concept
1. Attacker controls "attacker-org", onboarded into the shared Shipit instance with `webhook_secret_A` configured for it.
2. Attacker observes (via public GitHub UI) a commit SHA `deadbeef...` on `victim-org/victim-repo`, which is tracked as a stack in the same Shipit instance and requires CI context `ci/tests` per its `shipit.yml`.
3. Attacker POSTs to `/webhooks` with header `X-Github-Event: status`, `X-Hub-Signature` computed with `webhook_secret_A`, and body:
```json
{
  "sha": "deadbeef...",
  "state": "success",
  "context": "ci/tests",
  "repository": { "owner": { "login": "attacker-org" } }
}
```
4. `WebhooksController#verify_signature` resolves `repository_owner` = `attacker-org`, verifies successfully against `webhook_secret_A`.
5. `StatusHandler#process` runs `Commit.where(sha: "deadbeef...")`, finds the victim's commit, and creates a `success` status for `ci/tests` — satisfying `ci.require` for `victim-org/victim-repo` and enabling continuous delivery / manual deploy to proceed as if CI passed. [6](#0-5)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
module Shipit
  module Webhooks
    module Handlers
      class StatusHandler < Handler
        params do
          requires :sha, String
          requires :state, String
          accepts :description, String
          accepts :target_url, String
          accepts :context, String
          accepts :created_at, String

          accepts :branches, Array do
            requires :name, String
          end
        end

        def process
          Commit.where(sha: params.sha).each do |commit|
            commit.create_status_from_github!(params)
          end
        end
      end
    end
  end
```
