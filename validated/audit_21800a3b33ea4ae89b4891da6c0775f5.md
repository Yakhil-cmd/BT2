### Title
Unescaped colon-prefixed filenames enable git pathspec-magic injection to exclude files from security-review diff scope - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`GIT_CMD` does not set `core.literalPathspecs=true`/`GIT_LITERAL_PATHSPECS`, and `_diff_pathspec` / `_temp_index` pass repo-controlled filenames verbatim after a `--` separator into `git diff` and `git add --intent-to-add` invocations. A file whose literal name begins with `:` (e.g. `:(exclude)other.py` or `:!other.py`) is interpreted by git as pathspec magic rather than a literal path, letting attacker-controlled repository content alter which touched files are matched/excluded in the diff that feeds the Stop-hook's LLM security review.

### Finding Description
`_diff_pathspec` builds the pathspec list purely from `os.path.relpath`/`os.path.realpath` output with no escaping for git's pathspec-magic syntax: [1](#0-0) 

`_temp_index` similarly forwards `untracked_paths` (derived from real on-disk/`git status` filenames) straight into `git add --intent-to-add -- <surviving>` without any `./`-prefixing or `:(literal)` wrapping: [2](#0-1) 

`GIT_CMD` only disables `core.fsmonitor` and `core.hooksPath`; it never sets `core.literalPathspecs=true` (or `GIT_LITERAL_PATHSPECS=1`), which is the documented way to force git to treat all pathspec arguments as literal: [3](#0-2) 

Per git's pathspec grammar, any argument that begins with `:` is parsed as a "magic" pathspec (e.g. `:(exclude)pattern`, `:(glob)pattern`, `:!pattern`) unless the caller escapes it. An attacker who can place a file in the repository worktree (e.g. via a malicious PR, a prompt-injected `Write`/`Bash` command, or content Claude itself is asked to create during a session) with a name starting with `:` — and containing a syntactically valid magic signature — causes that entry, when it lands in `review_paths`/`untracked_paths` and is spliced into the `git diff … -- <pathspec>` or `git add --intent-to-add -- <pathspec>` argument list, to be interpreted as a matching rule rather than a literal filename. A crafted `:(exclude)<victim_path>` (or short form `:!<victim_path>`) entry can cause a legitimately-touched, security-relevant file (`<victim_path>`) to be dropped from the diff output entirely, even though `compute_v2_review_set` correctly identified it as changed this turn.

`compute_v2_review_set` (in `diffstate.py`) computes `review_paths` from git state and passes them through unmodified to `get_git_diff`, which calls `_diff_pathspec` then runs `git diff … pathspec` under a `_temp_index` context: [4](#0-3) 

None of the existing checks (`_diff_pathspec`'s `..`-prefix drop, `os.path.lexists` filter in `_temp_index`, `core.quotePath=false` for unicode/space handling) address pathspec-magic escaping — they only handle path traversal outside `cwd` and non-ASCII/whitespace quoting, not the leading-`:` magic-syntax case.

### Impact Explanation
This lets repo-controlled content suppress the visibility of an actually-modified, potentially malicious file from the Stop-hook's LLM security diff review (`handle_stop_hook` → `get_git_diff` → `analyze_code_security`), effectively bypassing the plugin's "required guard" — the automated security review gate that is supposed to force Claude to fix flagged issues (`sys.exit(2)` path). This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state": the diff/pathspec scoping invariant ("git path scoping must never escape the intended repo target") is broken because the pathspec no longer means what the caller intended, letting the effective review scope diverge from the true touched-file set.

### Likelihood Explanation
Preconditions: the attacker needs a file with a colon-prefixed name containing valid git pathspec magic syntax (e.g. `:(exclude)`, `:(glob)`, `:!`) to exist in the working tree and be counted among `touched_paths`/`untracked_paths` in the same turn as the file it aims to hide. This is filesystem-legal on Linux/macOS (colons and parentheses are valid filename characters), reachable purely through repo content or a single `Write`/`Bash` tool call performed during an agent session (no privileged access required), and is deterministic/repeatable — the same crafted filename will always trigger git's magic-pathspec parsing.

### Recommendation
- Add `-c core.literalPathspecs=true` to `GIT_CMD` in `plugins/security-guidance/hooks/gitutil.py` (or set `env["GIT_LITERAL_PATHSPECS"] = "1"` wherever pathspecs are passed), forcing git to treat every argument after `--` as a literal path.
- Alternatively/additionally, in `_diff_pathspec` and the `surviving` list construction in `_temp_index`, prefix any relative path that begins with `:` with `./` (or wrap it as `:(literal)<path>`) before appending it to the pathspec list.
- Add a regression test asserting that a file literally named `:(exclude)victim.py` (or `:!victim.py`) still appears in `get_git_diff` output when both files are touched in the same turn.

### Proof of Concept
Unit/integration test plan (pytest, using a real temp git repo since `_temp_index`/`get_git_diff` shell out to `git`):
1. Init a git repo, commit an initial `victim.py` with `print(1)`.
2. Modify `victim.py` to `os.system(user_input)` (the "malicious" change that should be flagged).
3. Create a second file literally named `:(exclude)victim.py` (untracked) in the same worktree.
4. Call `compute_v2_review_set`/`get_git_diff(repo, baseline_sha, paths=[victim_path, decoy_path], untracked_paths=[decoy_relpath])`.
5. Assert (expected pre-fix, demonstrating the bug): `victim.py`'s changed content (`os.system`) is **absent** from the returned diff text — i.e., the malicious edit is invisible to `parse_diff_into_files`/`analyze_code_security` even though `victim.py` was genuinely modified and included in `review_paths`.
6. After applying the recommended `core.literalPathspecs=true` fix, re-run the same test and assert `victim.py`'s diff content **is present** in the output, and the decoy file is treated as a literal (harmless) untracked file.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

```python
@contextlib.contextmanager
def _temp_index(cwd, untracked_paths=None):
    """Yield an env dict pointing GIT_INDEX_FILE at a throwaway copy of the
    repo's index with `git add --intent-to-add` applied, so untracked files
    show up in subsequent `git diff` calls without touching the user's real
    index. Yields None if no index can be found (bare repo / not a repo); the
    caller should fall back to a plain diff. Always cleans up the temp file.

    Perf: when `untracked_paths` is given, only those paths are added (O(n)
    in untracked count). The default `add -N .` stats every file in the
    worktree — slow in large repos vs fast targeted scan. v2 callers
    already know the untracked set from `git status --porcelain`, so they
    pass it; v1 keeps the whole-tree scan since it has no prior list."""
    import shutil
    import tempfile

    real_index = _find_git_index(cwd)
    if not real_index:
        yield None
        return

    tmp_fd, tmp_index = tempfile.mkstemp(prefix="security_hook_idx_")
    os.close(tmp_fd)
    try:
        shutil.copy2(real_index, tmp_index)
        env = {**os.environ, "GIT_INDEX_FILE": tmp_index}
        if untracked_paths is None:
            add_args = ["."]
        elif untracked_paths:
            # `git add -N -- a b nonexistent` is atomic — one missing path
            # makes it exit 128 and add NOTHING, so a file removed between
            # `git status` and here would silently drop ALL untracked files
            # from the diff. --ignore-missing only works with --dry-run, so
            # filter to surviving paths (lexists so dangling symlinks count).
            surviving = [p for p in untracked_paths
                         if os.path.lexists(os.path.join(cwd, p))]
            add_args = ["--"] + surviving if surviving else None
        else:
            add_args = None
        if add_args:
            subprocess.run(
                [*GIT_CMD, "add", "--intent-to-add"] + add_args,
                cwd=cwd, capture_output=True, text=True, timeout=10,
                env=env,
            )
        yield env
    finally:
        try:
            os.unlink(tmp_index)
        except OSError:
            pass
```

```python
def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
    try:
        with _temp_index(cwd, untracked_paths) as env:
            # env is None when no index could be found (bare repo / not a
            # repo) — diff still runs, just without untracked-file support.
            result = subprocess.run(cmd, cwd=cwd, capture_output=True, timeout=30, env=env)
        if result.returncode != 0:
            debug_log(f"git diff failed: {result.stderr[:200].decode('utf-8', errors='replace')}")
            return None
        # Decode with errors='replace' so binary diffs don't crash
        return result.stdout.decode("utf-8", errors="replace")
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"git diff error: {e}")
        return None
```
