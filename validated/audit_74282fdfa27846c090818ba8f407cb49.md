### Title
Interest accrual `i128` overflow permanently freezes a whale market before the borrow-index cap engages - (File: contracts/pool/src/cache/scale.rs)

### Summary
Every state-mutating pool entrypoint runs `global_sync` accrual first. Accrual computes utilization via `scaled_to_original(borrowed_scaled, borrow_index)`, an `i128` multiply that overflows for a sufficiently large scaled book well before `MAX_BORROW_INDEX_RAY` is reached. Once the index crosses that cliff, the accrual panics with `MathOverflow`, and because accrual precedes every mutation — `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `update_indexes`, `seize` — the market is bricked permanently: no repayment, no exit, no liquidation. This is the same bug class as CVE-2022-2719 (an assertion/panic on a reachable state producing denial of service), except here the DoS is persistent rather than per-transaction: all supplier and collateral funds in that market are frozen forever.

### Finding Description
- `Cache::calculate_utilization` in `contracts/pool/src/cache/scale.rs` unscales the aggregate book by multiplying the scaled Ray totals by the live indexes via `scaled_to_original` [1](#0-0) .
- `global_sync` in `contracts/pool/src/interest.rs` is called at the top of every market mutation ("entrypoint → Cache::load → interest::global_sync → mutate → guards") [2](#0-1) .
- `scaled_to_original` is `scaled * index` in RAY fixed point on `i128`. With a scaled supply of ~`10^9 * 10^18 * RAY` the product overflows `i128` (`checked` arithmetic → `panic_with_error!(MathOverflow)`) at an index multiplier of ~x170, while `MAX_BORROW_INDEX_RAY` is far above that, so the intended index-cap guard never engages [3](#0-2) .
- This is proven, not hypothetical: the repo's own stress test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` constructs a 1-billion-whole-token, 18-decimal market at 98% utilization on a 175%-max-rate curve, advances time, observes `try_update_indexes` fail with `MATH_OVERFLOW`, and then shows both `withdraw` and `repay` of a single unit fail with the same error [4](#0-3) .
- Root cause: utilization/accrual operates on the unbounded aggregate `borrowed * index` product instead of clamping the index at `MAX_BORROW_INDEX_RAY` first or saturating the multiplication, so a domain that the index cap was designed to bound is reachable through the `i128` multiplication ceiling instead.

### Impact Explanation
Permanent freezing of user funds (an accepted impact class). Once the cliff is crossed, every permissionless verb touching that market — `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `update_indexes` — reverts inside `global_sync` before any mutation runs. Suppliers cannot exit, borrowers cannot repay, liquidators cannot clear the position, and bad-debt socialization cannot run. The pool's `cash` bookkeeping still holds the tokens, but no code path can release them; this is not a transient fail-closed rejection of bad input but a permanent liveness failure of the market holding real deposits.

### Likelihood Explanation
The preconditions are extreme but fully permissionless: a listed 18-decimal market with caps lifted high enough to hold ~1B whole tokens of supply, a borrower drawing ~98% of it, and the market left near the steep end of its rate curve for years of accrual so the index compounds to ~x170. No privileged action, leaked key, or oracle manipulation is required — any unprivileged whale pair of supplier+borrower (or one actor using two accounts) can create the book, after which passive time alone triggers the freeze. The steep stress curve used in the test (175% max borrow rate) accelerates this to a few years. Likelihood is Low-Medium given the capital and duration required, but the impact is total for that market, consistent with a Medium finding.

### Recommendation
- Clamp `borrow_index` (and `supply_index`) at `MAX_BORROW_INDEX_RAY` *before* the value unscaling in accrual/utilization, so the cap actually bounds the domain it was introduced to bound.
- Alternatively make `scaled_to_original`/`unscale_*` saturate or use a widened (e.g., 256-bit-style two-limb) intermediate for the aggregate book product, returning a saturated utilization rather than panicking.
- At minimum, split accrual so a `MathOverflow` on the utilization-dependent rate computation does not block index progression and repayment: a repay/withdraw path should be able to run with a capped or last-good index rather than reverting inside `global_sync`.

### Proof of Concept
Existing executable PoC in the repo: `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs`, test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` [5](#0-4) .

Sequence (all calls permissionless):
1. List market `BIG18` (18 decimals) with the steep XLM-style curve (`max_borrow_rate = 175%`, `slope3 = 150%`, optimal at 75%) and disable the max-utilization guard / lift supply-borrow caps via governance listing params.
2. `pool.supply`/controller `supply`: BOB deposits `1_000_000_000 * 10^18` BIG18.
3. ALICE supplies cheap collateral and `borrow`s 98% of the book.
4. Advance ledger time (~a few years on that curve; the test loops up to 40 years in yearly steps).
5. `update_indexes` (or any verb) panics with `MathOverflow` inside `scaled_to_original` while `borrow_index < MAX_BORROW_INDEX_RAY`.
6. Subsequently `withdraw(BOB, 1)` and `repay(ALICE, 1.0)` both revert with `MATH_OVERFLOW` — permanently.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```

```rust
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
}
```
