### Title
API token scoped to a single stack can read CI status of any stack via CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::Api::CCMenuController` overrides the `stack` accessor to bypass the stack-scoping enforced by `Shipit::Api::BaseController`. An `ApiClient` token that is authorized only for a single `stack_id` (a common configuration for third-party CI dashboard integrations) can be used to read the CCMenu XML status — including build/deploy status, last build label, and web URL — of **any** stack in the Shipit instance, not just the one it was scoped to.

### Finding Description
`Shipit::Api::BaseController` defines stack lookup so that when an `ApiClient` is scoped to a specific stack, all stack-dependent actions are restricted to that stack: [1](#0-0) 

This is the binding: `ApiClient#stack_id` (what the token authorizes) must equal the stack the request ultimately touches. Every other API controller (`CommitsController`, `TasksController`, `HooksController`, etc.) inherits `stack` from `BaseController` and thus respects this binding via the `stacks` scope, which filters `Stack.where(id: current_api_client.stack_id)` when a `stack_id` is set: [2](#0-1) 

`CCMenuController`, however, overrides `stack` to bypass this scope entirely, resolving directly against the full `Stack` table: [3](#0-2) 

The `require_permission :read, :stack` check only validates that the token carries the `read:stack` permission string; it never checks that `current_api_client.stack_id` matches the requested `stack_id`: [4](#0-3) 

So a client whose `stack_id` restricts it to Stack A can request `/api/stacks/<owner>/<repo-B>/<env-B>/ccmenu` for a completely unrelated Stack B and receive its deploy/status data as long as the token has the generic `read:stack` permission. This directly parallels the reported bug class: a capability the code is supposed to check (`onERC1155Received`'s correct selector / the token's `stack_id` binding) is overridden with the wrong value/logic and never actually enforced on this code path.

### Impact Explanation
This is an authorization escalation: a token deliberately scoped to a single stack (the documented mechanism for restricting third-party integrations, per the test `"an api client scoped to a stack will only see that one stack"` in `test/controllers/api/stacks_controller_test.rb`) gains unauthenticated-relative read access to CI/build status, last build label/time, and web URL of every other stack in the deployment, including private or sensitive stacks the token owner was never meant to see. This matches the High-severity category "escalation into `Shipit.github_teams` authorization" / "unauthenticated read of stack state" defined in scope.

### Likelihood Explanation
Any holder of a stack-scoped `ApiClient` token (issued, e.g., to embed a CCMenu badge for one project) can trivially exploit this by changing the `stack_id` path segment to another stack's owner/repo/environment — no privilege escalation, secret guessing, or additional access is required beyond the token they already legitimately hold.

### Recommendation
Change `Shipit::Api::CCMenuController#stack` to use the scoped `stacks` collection inherited from `BaseController` (i.e., `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so the `stack_id` authorization binding is enforced consistently with every other API controller. Add a regression test mirroring `"an api client scoped to a stack will only see that one stack"` for `CCMenuController`.

### Proof of Concept
1. Create an `ApiClient` scoped to Stack A (`stack_id` set) with `permissions: ['read:stack']`.
2. Using that client's `authentication_token`, issue `GET /api/stacks/<owner-B>/<repo-B>/<env-B>/ccmenu` for unrelated Stack B.
3. Observe the response renders Stack B's CCMenu XML (`name`, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`, `webUrl`) even though the token is not authorized for Stack B, as demonstrated by `app/controllers/shipit/api/ccmenu_controller.rb:27-31` resolving `Stack.from_param!` unscoped, unlike `app/controllers/shipit/api/base_controller.rb:74-80`.
