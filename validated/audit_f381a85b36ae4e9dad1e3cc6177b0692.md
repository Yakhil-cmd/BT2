### Title
Stack-scoped API tokens can read the status of arbitrary stacks via the CCMenu endpoint - (File: app/controllers/shipit/api/ccmenu_controller.rb)

### Summary
`Shipit::ApiClient` records can be scoped to a single stack (`stack_id` present), and the intended authorization model — implemented in `Shipit::Api::BaseController#stacks`/`#stack` — restricts such a client to only ever resolve `Stack.where(id: current_api_client.stack_id)`. `Shipit::Api::CCMenuController` bypasses this binding by redefining `stack` to resolve `Stack.from_param!(params[:stack_id])` directly against all stacks, so the equality "stack a token authorizes == stack the request touches" is never enforced for this endpoint.

### Finding Description
In `app/controllers/shipit/api/base_controller.rb`, stack-scoped authorization is centralized: [1](#0-0) 

Any controller that uses `stack` (which delegates to `stacks.from_param!`) is correctly limited to the api client's own `stack_id` when one is set. `Shipit::Api::CCMenuController`, however, overrides both `authenticate_api_client` (to accept the token from a query-string `params[:token]` instead of Basic Auth) and `stack` (to bypass the scoped `stacks` collection entirely): [2](#0-1) 

The only authorization check performed is `require_permission :read, :stack`, which calls `ApiClient#check_permissions!`, an operation-level check against the `permissions` array — it never checks whether `params[:stack_id]` matches `current_api_client.stack_id`: [3](#0-2) 

So the binding that should hold — `current_api_client.stack_id == stack.id` (when `stack_id?` is true) — is broken specifically in this controller: any `ApiClient` with `read:stack` permission, regardless of its assigned `stack_id`, can pass an arbitrary `stack_id` in the URL and receive that other stack's CI status feed.

Before the design intent (as enforced elsewhere, e.g. `Shipit::Api::StacksController` via inherited `stacks`/`stack`): a client scoped to stack A can only ever resolve stack A. After hitting `CCMenuController#show` with `stack_id=B` (any other stack the attacker knows the slug of): the same token now resolves and renders stack B's build/deploy status.

### Impact Explanation
The disclosed data (`stack.merge_status`, latest deploy `id`, `started_at`/`ended_at`, running state, and the `stack_url`) is deploy/build state for a stack the token was never authorized to access. This matches the accepted High-impact category of unauthorized read of stack state/deploy output, achieved purely by supplying a different `stack_id` query parameter with a token meant for one specific stack.

### Likelihood Explanation
Exploitation only requires possession of any valid stack-scoped `read:stack` API token (these are routinely created and shared, e.g. by `CCMenuUrlController#fetch`, and embedded in third-party CI dashboard tools) and knowledge/guess of another stack's `to_param` (owner/repo/environment/branch), which is not itself secret information within a Shipit deployment. No privileged access or session is needed beyond the token itself.

### Recommendation
Have `Shipit::Api::CCMenuController#stack` resolve through the scoped `stacks` collection (i.e., `stacks.from_param!(params[:stack_id])`) instead of `Stack.from_param!`, so the api client's `stack_id` scoping is enforced consistently with every other API controller.

### Proof of Concept
1. Create/obtain a stack-scoped `ApiClient` bound to Stack A with `read:stack` permission (as fixture `here_come_the_walrus` demonstrates: `stack: shipit`, `permissions: ['read:stack']`) and derive its token via `ApiClient#authentication_token`.
2. Request `GET /api/<stack_B_id>/ccmenu?token=<stack_A_token>` where stack B is a different, unrelated stack.
3. Observe that `CCMenuController#show` renders `shipit/ccmenu/project` with stack B's `merge_status`, latest deploy id, and timestamps, even though the token is scoped only to stack A — proving the token-to-stack binding is not enforced in this controller.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
  end
end
```
