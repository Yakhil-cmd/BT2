### Title
Uncaught `Error` (crash) from unvalidated `amount` field in indivisible private-payment chains reachable by a private-payment counterparty - (File: indivisible_asset.js)

### Summary
CVE-2023-45931 describes a NULL-pointer dereference in `check_xshm()` triggered by an unchecked error/state value, with disputed reachability. The analogous bug class in `ocore` is a missing field-validation before dereferencing/using attacker-supplied data, which results in an unhandled `throw Error(...)` deep inside async database-callback code that cannot be caught by any surrounding `try/catch`, crashing the Node.js process. Unlike the disputed Mesa CVE, this path is concretely reachable by an unprivileged private-payment counterparty (i.e., anyone who sends you, or a hub relaying you, a hand-crafted private-payment chain).

### Finding Description
When validating a private, fixed-denomination (indivisible) asset transfer, `validatePrivatePayment()` reads the amount of the previous (hidden) output supplied by the counterparty and copies it verbatim into `objValidationState.src_coin.amount` without checking that it is a positive integer: [1](#0-0) 

Specifically, `prev_hidden_output` is taken from `objPrevPrivateElement.payload.outputs[input.output_index]` — fully attacker-controlled JSON received from a private-payment counterparty or a hub relaying it — and only checked for existence (`if (!prev_hidden_output) return callbacks.ifError("no prev hidden output");`), never for `amount` being a valid positive integer, before it is placed into `objValidationState.src_coin`.

This `objValidationState` is then passed into `validation.validatePayment()` → `validatePaymentInputsAndOutputs()`, where the transfer-input branch for private fixed-denomination assets unconditionally asserts the shape of `src_coin` and throws hard `Error`s (not soft validation-callback errors) if the fields are missing or malformed: [2](#0-1) 

Because `src_coin.amount` is never sanity-checked before this point, a maliciously crafted previous private element with a missing, non-numeric, zero, or negative `amount` field causes:
```
if (!isPositiveInteger(src_coin.amount))
    throw Error("no src coin amount");
```
to fire. This `throw` occurs inside a `conn.query(...)` callback nested several levels deep (`validatePrivatePayment` → `async.series` → `validation.validatePayment` → `validatePaymentInputsAndOutputs` → `async.eachSeries` input-processing callback → `conn.query` callback in `readAsset`/`loadAssetWithListOfAttestedAuthors`/etc.), i.e., in asynchronous callback context. A synchronous `throw` inside an asynchronous callback cannot be caught by any `try/catch` in the calling function stack; it propagates to `process`'s `uncaughtException`, crashing the affected node.

### Impact Explanation
This is invoked from `network.js:handleSavedPrivatePayments()` for every private-payment chain a peer (a private-payment counterparty) sends over the network, and by any wallet processing a private-payment chain handed to it directly or via a hub: [3](#0-2) [4](#0-3) 

Any node (hub or wallet) that receives and processes such a crafted private chain for a fixed-denomination private asset can be crashed by an unauthenticated peer, without any prior relationship other than being sent a private payment. Repeated or targeted crashing of hubs/wallets that route or receive private payments is a concrete availability impact: it can prevent those nodes from confirming/relaying new units for as long as the process keeps restarting and reprocessing the same malicious payload (the chain remains queued in `unhandled_private_payments` until successfully validated or explicitly rejected), satisfying the "network unable to confirm new units" impact criterion.

### Likelihood Explanation
Likelihood is high: the attacker only needs to construct a private-payment element chain for a fixed-denomination private asset with an `outputs[]` entry that lacks/mismatches an `amount` field, and send it to a hub or directly to the victim wallet as an ordinary private payment. No signatures, special privileges, or coordination with other units/AAs are required — this matches the allowed threat actor "private-payment counterparty."

### Recommendation
In `indivisible_asset.js:validatePrivatePayment()`, validate `prev_hidden_output.amount` (must be `ValidationUtils.isPositiveInteger`) immediately after retrieving it and before assigning it to `objValidationState.src_coin`, returning `callbacks.ifError(...)` on failure instead of allowing it to reach `validation.js`'s hard `throw`. As defense in depth, convert the `throw Error(...)` assertions in `validatePaymentInputsAndOutputs()` (lines 2416-2424 of `validation.js`) for `src_coin` fields into calls to `cb(...)`/`callback(...)` with a validation error, since this data ultimately originates from network input and should never cause an unrecoverable process crash regardless of upstream checks.

### Proof of Concept
1. As a private-payment counterparty, construct a private-payment chain of two elements for an existing fixed-denomination (`fixed_denominations: true`) private asset:
   - `objPrevPrivateElement` (the earlier element in the chain) with `payload.outputs[output_index]` containing a valid `output_hash`/`blinding` but with `amount` omitted (or set to `0`/negative/non-numeric).
   - `objPrivateElement` (the head element) with `payload.inputs[0]` of type transfer referencing `objPrevPrivateElement`'s unit/message_index/output_index.
2. Send this chain to a hub or directly to the victim's wallet as a normal private payment (`private_payment` network message / `sendPrivatePayments`).
3. The victim node calls `private_payment.validateAndSavePrivatePaymentChain` → `indivisible_asset.validatePrivatePayment`, which copies the unchecked `amount` into `objValidationState.src_coin.amount`.
4. `validation.js`'s transfer-input handling hits `if (!isPositiveInteger(src_coin.amount)) throw Error("no src coin amount");` inside the `conn.query` callback, producing an uncaught exception that crashes the receiving node's process.

	if (!ValidationUtils.isNonemptyArray(arrPrivateElements))
		return callbacks.ifError("no priv elements array");
	var headElement = arrPrivateElements[0];
	if (!headElement.payload)
		return callbacks.ifError("no payload in head element");
	var asset = headElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in head element");
	if (!ValidationUtils.isNonnegativeInteger(headElement.message_index))
		return callbacks.ifError("no message index in head private element");
	
	var validateAndSave = function(){
		storage.readAsset(db, asset, null, function(err, objAsset){
			if (err)
				return callbacks.ifError(err);
			if (objAsset.is_private !== 1)
				return callbacks.ifError("asset is not private");
			if (!!objAsset.fixed_denominations !== !!headElement.payload.denomination)
				return callbacks.ifError("presence of denomination field doesn't match the asset type");
			if (!!objAsset.fixed_denominations !== ("output" in headElement))
				return callbacks.ifError("divisible asset must not have output field, indivisible must");
			db.takeConnectionFromPool(function(conn){
				conn.query("BEGIN", function(){
					var transaction_callbacks = {
						ifError: function(err){
							conn.query("ROLLBACK", function(){
								conn.release();
								callbacks.ifError(err);
							});
						},
						ifOk: function(){
							conn.query("COMMIT", function(){
								conn.release();
								callbacks.ifOk();
							});
						}
					};
					// check if duplicate
					var sql = "SELECT address, denomination, amount, blinding FROM outputs WHERE unit=? AND asset=? AND message_index=?";
					var params = [headElement.unit, asset, headElement.message_index];
					if (objAsset.fixed_denominations){
						if (!ValidationUtils.isNonnegativeInteger(headElement.output_index))
							return transaction_callbacks.ifError("no output index in head private element");
						sql += " AND output_index=?";
						params.push(headElement.output_index);
					}
					conn.query(
						sql, 
						params, 
						function(rows){
							if (rows.length > 1)
								throw Error("more than one output "+sql+' '+params.join(', '));
							if (rows.length > 0 && rows[0].address){ // we could have this output already but the address is still hidden
								const stored = rows[0];
								const payload = headElement.payload;
								let bDuplicate = false;
								if (objAsset.fixed_denominations){ // the row we selected is exactly headElement.output_index, filtered in sql above
									const claimed_output = payload.outputs?.[headElement.output_index];
									const revealed_output = headElement?.output;
									bDuplicate =

										&& ValidationUtils.isNonemptyObject(revealed_output)

										&& stored.amount === claimed_output.amount
										&& stored.address === revealed_output.address
										&& stored.blinding === revealed_output.blinding;
								}
								else // divisible outputs are never hidden individually and sql has no output_index filter, so match against any of them
									bDuplicate = (payload.outputs || []).some(output => {
										return ValidationUtils.isNonemptyObject(output)
											&& stored.denomination === 1
											&& stored.amount === output.amount
											&& stored.address === output.address
											&& stored.blinding === output.blinding;
									});
								if (bDuplicate) {

									return transaction_callbacks.ifOk();

							var assetModule = objAsset.fixed_denominations ? indivisibleAsset : divisibleAsset;
							assetModule.validateAndSavePrivatePaymentChain(conn, arrPrivateElements, transaction_callbacks);
						}

				});
			});
		});
	};
