### Title
Amend delta-review bypass lets unreviewed dangerous commits escape detection permanently - (File: `plugins/security-guidance/hooks/security_reminder_hook.py`)

### Summary
`_resolve_amend_pre_sha` correctly guards against cross-repo confusion and non-amend reflog entries, but its caller in `handle_commit_review_posttooluse` never verifies that the resolved pre-amend SHA was ever actually reviewed before switching to delta-only review. An attacker (or a compromised agent turn) can land dangerous content in a commit whose review is skipped/suppressed, then `--amend` it with a trivial change so only the delta is analyzed — permanently hiding the dangerous content from the Stop hook, commit-review, and push-sweep.

### Finding Description
`handle_commit_review_posttooluse` decides to use delta-only review purely from reflog shape, not from review history: [1](#0-0) 

`_resolve_amend_pre_sha` only checks that HEAD@{0} is a `commit (amend)`, HEAD@{1} isn't itself an amend, and that the caller's `expected_post_sha` matches HEAD@{0} (cross-repo guard) — it has no notion of whether HEAD@{1} (the pre-amend SHA) was ever put through `analyze_code_security`: [2](#0-1) 

When the delta path is taken, only `git diff pre_amend_sha sha` is analyzed instead of the full `git show -p sha`, and if that delta is empty the review is skipped outright with `skip_reason=35`: [3](#0-2) 

After the (possibly empty) review runs, the *full* amended SHA is unconditionally recorded into `.git/sg-reviewed-shas` as reviewed, with `vulns_found` reflecting only what the delta scan found (0 if the delta didn't touch the dangerous lines): [4](#0-3) 

`sg-reviewed-shas` is the same file consulted by push-sweep to decide which commits still need review (via `_load_reviewed_shas`, referenced in the reflog-fallback path): [5](#0-4) 

**Exploit flow:**
1. Attacker gets dangerous code into a commit whose PostToolUse review is skipped or suppressed (e.g., the per-hour LLM cap `MAX_COMMIT_REVIEWS_PER_HOUR` is exhausted, `COMMIT_REVIEW_ENABLED` was off at that moment, the LLM call errored, or `commit_succeeded` detection failed for that call). None of these paths block the underlying `git commit` from succeeding — they only skip the *review*.
2. Attacker (or the agent, on a later turn) runs `git commit --amend --no-edit` or amends with an unrelated trivial change (e.g., touching a comment/whitespace in a different file, or fixing the commit message only).
3. `_resolve_amend_pre_sha` happily resolves the pre-amend SHA (reflog shape checks pass — nothing here checks "was this previously reviewed").
4. The delta review diffs pre-amend→post-amend; the dangerous lines from step 1 are unchanged and thus absent from the diff. If the amend touched nothing security-relevant, `diff_files` may be empty → `skip_reason=35`, review skipped entirely.
5. The full amended SHA (which still contains the original dangerous content) is written to `sg-reviewed-shas` as reviewed with 0 vulns found, which also suppresses future push-sweep review of that SHA.
6. The dangerous content is now permanently unreviewable through commit-review, Stop-hook (already fired past this file), or push-sweep, and can be pushed without ever surfacing a warning.

The existing guards (`not _reflog_shas`, `len(all_shas) <= 1`, `commit_invocations <= 1`, and the cross-repo/amend-subject checks inside `_resolve_amend_pre_sha`) address orthogonal correctness concerns (multi-commit ambiguity, cross-repo reflog pollution) but do nothing to ensure the pre-amend content was actually reviewed, which is the load-bearing assumption stated explicitly in the docstring/comment ("code already reviewed on the original commit") but never enforced in code.

### Impact Explanation
This breaks the stated security invariant that "dangerous edits and commands must stay reviewable and blockable even across retries, amends, and pushes." A dangerous change can be committed once under conditions that suppress review (rate limit, transient LLM failure, flag toggling), then laundered via a trivial `--amend` into a permanently "reviewed, clean" state that also blocks re-detection at push time via the shared `sg-reviewed-shas` dedup store. This is a workspace-level compromise: it allows dangerous code to reach the repository/remote without any Claude Code security review ever seeing it, and it also poisons cross-surface state (`sg-reviewed-shas`) shared between commit-review, push-sweep, and other consumers of the file.

### Likelihood Explanation
This requires no special privilege beyond normal repository/commit access, which the attacker/agent already has by definition in this threat model. Triggering the review-skip precondition is realistic: rate limiting (`MAX_COMMIT_REVIEWS_PER_HOUR`) is a deterministic, attacker-triggerable condition (spam a few commits within the window), and transient LLM/API failures are common in practice. The amend step is a completely ordinary git operation. No parser or approval bypass is needed — the bypass lives entirely in the trust assumption baked into `_resolve_amend_pre_sha`'s caller.

### Recommendation
Before enabling the delta-review path, verify that `pre_amend_sha` is actually present in `sg-reviewed-shas` (i.e., it was previously reviewed by this same tooling). If it is not present/verified, fall back to full `git show -p` review of the post-amend commit instead of the delta. Additionally, when marking the post-amend SHA as reviewed in `_append_reviewed_shas`, only propagate a "0 vulns" / reviewed status if the *entire* commit content (not just the delta) was actually analyzed, to avoid falsely marking unreviewed dangerous content as clean in the shared review-state file consumed by push-sweep.

### Proof of Concept

1. Init a git repo; disable/stub `analyze_code_security` (or exhaust `MAX_COMMIT_REVIEWS_PER_HOUR`) to simulate a suppressed review.
2. Commit a file containing an obviously dangerous pattern (e.g., `os.system(user_input)`) via `git commit -m "wip"`; assert (by stubbing) that the PostToolUse hook call for this commit exits with `skip_reason` indicating a skipped/rate-limited review (i.e., `sg-reviewed-shas` does NOT contain this SHA).
3. Re-enable review, then run `git commit --amend -m "wip: fix typo"` with no code changes (or a change in an unrelated file).
4. Invoke `handle_commit_review_posttooluse` for the amend Bash call.
5. Assert that `_resolve_amend_pre_sha` returns the pre-amend SHA and the handler takes the delta path (`amend_delta_review: True` in metrics).
6. Assert `diff_files` is empty (or lacks the dangerous line) and the hook exits via `skip_reason=35` (or similar) with `vulns_found=0`, WITHOUT ever surfacing the dangerous `os.system` call to the LLM or the user.
7. Assert `sg-reviewed-shas` now contains the amended SHA with `vulns_found=0`.
8. Simulate `git push` / push-sweep consuming `sg-reviewed-shas` and assert the dangerous commit is treated as already-reviewed and not re-flagged.

Expected (post-fix) behavior: step 5 should fall back to full-commit review (`git show -p`) because the pre-amend SHA was never in `sg-reviewed-shas`, and the dangerous `os.system` line should be flagged, causing exit code 2 with stderr findings.

```python
def _resolve_amend_pre_sha(repo_root, expected_post_sha=None):
    """For a `git commit --amend` we just ran, return the pre-amend SHA via
    reflog, or None if it can't be safely determined.

    expected_post_sha: the post-amend SHA the caller parsed from bash stdout
    (or reflog). If provided, HEAD@{0} of `repo_root` must match it (prefix
    compare — bash stdout SHAs are abbreviated, reflog %H is 40 chars) before
    we trust the reflog-derived pre-amend SHA. This guards against the
    cross-repo case (`cd ../other && git commit --amend && cd -`) where
    `repo_root` happens to have its own recent amend that's unrelated to
    the bash command we're reviewing.

    We require HEAD@{0}'s reflog subject to start with `commit (amend)` —
    otherwise our `--amend` regex matched something that didn't actually
    perform an amend (e.g., `git commit --amend --dry-run`, aliased commands,
    aborted amends), and HEAD@{1} would be the wrong commit. Also requires
    HEAD@{1} to NOT itself be an amend, since back-to-back amends would have
    HEAD@{1} as the previous-amend's post state — the original commit we
    want to compare against is then HEAD@{2}, but at that point we're
    reaching and fall back to a full review.

    Bytes + decode('utf-8', errors='replace'): reflog subjects embed commit
    subjects, which git stores as raw bytes (commit messages may be latin-1
    / cp1252 / etc.). text=True would raise UnicodeDecodeError (a
    ValueError, not OSError) on non-UTF8 bytes and crash the hook.
    """
    if not repo_root:
        return None
    try:
        r = subprocess.run(
            [*GIT_CMD, "log", "-g", "-2", "--format=%H|%gs", "HEAD"],
            cwd=repo_root, capture_output=True, timeout=5,
        )
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
    if r.returncode != 0:
        return None
    stdout_text = r.stdout.decode("utf-8", errors="replace")
    lines = [ln for ln in stdout_text.splitlines() if "|" in ln]
    if len(lines) < 2:
        return None
    head0_sha, _, head0_subj = lines[0].partition("|")
    head1_sha, _, head1_subj = lines[1].partition("|")
    if not head0_subj.startswith("commit (amend)"):
        return None
    if head1_subj.startswith("commit (amend)"):
        return None
    # Cross-repo guard: the post-amend SHA the caller is about to review must
    # match HEAD@{0} of repo_root. Otherwise the bash command was likely run
    # in a different repo than repo_root, and the reflog we just read is
    # unrelated. Prefix-compare: expected_post_sha is typically the 7-char
    # abbreviated SHA captured from bash stdout by _COMMIT_SHA_RE (git's
    # default core.abbrev floor), while head0_sha is the full 40-char %H —
    # strict equality would always fail and silently disable the delta path.
    if expected_post_sha and not head0_sha.startswith(expected_post_sha):
        return None
    return head1_sha or None
```

```python
    diff_files = []
    resolved = 0
    for sha in shas:
        try:
            if pre_amend_sha:
                # Delta review: pre-amend → post-amend. `git diff` (not show)
                # so the output is a pure unified diff with no commit header.
                result = subprocess.run(
                    [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", pre_amend_sha, sha, "--"],
                    cwd=repo_root, capture_output=True, timeout=15
                )
            else:
                result = subprocess.run(
                    [*GIT_CMD, "show", "-p", "--no-color", "--no-ext-diff", sha, "--"],
                    cwd=repo_root, capture_output=True, timeout=15
                )
        except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
            _cmd = "git diff" if pre_amend_sha else "git show"
            debug_log(f"Commit review: {_cmd} {sha} error: {e}")
            continue
        if result.returncode != 0:
            # SHA not in this repo (cross-repo commit) or already gc'd. Better
            # to skip than to fall back to HEAD and review the wrong commit.
            _cmd = "git diff" if pre_amend_sha else "git show"
            debug_log(f"Commit review: {_cmd} {sha} rc={result.returncode}")
            continue
        resolved += 1
        diff_files.extend(parse_diff_into_files(
            result.stdout.decode("utf-8", errors="replace")))

    # Dedup by path. The widened reflog scan can return >1 SHA (e.g.
    # `git commit && git commit --amend` within 120s); a path that appears in
    # both diffs would consume two MAX_DIFF_FILES slots and be re-analyzed.
    # `shas` is newest-first so the first occurrence is the most recent
    # version of the file — keep it.
    if len(shas) > 1:
        _seen = set()
        diff_files = [
            (fp, c) for fp, c in diff_files
            if not (fp in _seen or _seen.add(fp))
        ]

    if resolved == 0:
        debug_log("Commit review: no parsed SHA resolved in cwd repo")
        emit_metrics({"skipped": True, "skip_reason": 28, **_base,
                      "shas_found": len(shas)})
        sys.exit(0)

    # Empty amend delta = message-only amend (or whitespace-only that the
    # diff already collapses). No code to review; skip cleanly. skip_reason=35.
    # Gated on resolved > 0 so subprocess failures (caught with `continue`
    # above) don't get mislabeled as message-only — they fall through to
    # skip_reason=28 correctly.
    if pre_amend_sha and not diff_files:
        debug_log("Commit review: --amend produced empty delta (message-only?), skipping")
        emit_metrics({"skipped": True, "skip_reason": 35, **_base,
                      "files_reviewed": 0})
        sys.exit(0)
```
