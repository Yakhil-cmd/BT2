### Title
VRankCandidate BLS Key Lookup Uses Wrong Block Number, Enabling Incorrect CFS Scoring and Validator State Corruption — (File: kaiax/vrank/impl/handler.go)

---

### Summary

`HandleVRankCandidate` verifies a candidate's BLS signature by looking up the registered BLS public key at `currentHead + 1`, regardless of the message's `msg.BlockNumber`. Because the handler accepts messages for future blocks (within `maxWindow`), a candidate whose BLS key changes between `currentHead` and `msg.BlockNumber − 1` will have their valid, correctly-signed message rejected. The rejected message is never stored in the collector, so `EvaluateCandidates` marks the candidate as failed, inflating their CFS score. At epoch transition, a CFS score at or above the threshold causes the candidate to be demoted from `CandTesting` → `Registered`, an incorrect validator-set state transition.

---

### Finding Description

In `HandleVRankCandidate`:

```go
// kaiax/vrank/impl/handler.go  line 148-155
blsNum := big.NewInt(0).Add(v.Chain.CurrentHeader().Number, big.NewInt(1)) // head + 1
blsPub, err := v.Randao.GetBlsPubkey(sender, blsNum)
if err != nil {
    return fmt.Errorf("%w: %v", vrank.ErrInvalidCandidateBlsSig, err)
}
ok, err := bls.VerifySignature(msg.BlsSig, sigHash, blsPub)
if err != nil || !ok {
    return vrank.ErrInvalidCandidateBlsSig
}
```

`blsNum` is always `currentHead + 1`. `GetBlsPubkey(sender, blsNum)` reads the BLS key from the state at `blsNum − 1 = currentHead` (the Randao module always reads from the parent block's state).

The handler accepts messages for future blocks:

```go
// kaiax/vrank/impl/handler.go  line 133
if msg.BlockNumber > prepreparedSeqNum+maxWindow {
    return vrank.ErrTooFar
}
```

Tests confirm `maxWindow ≥ 1` — a message for `prepreparedSeqNum + 1` is accepted without error. The epoch-boundary test explicitly stores a message for `DefaultVRankEpoch` while the preprepared view is at `DefaultVRankEpoch − 1`.

When `msg.BlockNumber > currentHead + 1`, the key used for verification is from state at `currentHead`, but the semantically correct key is from state at `msg.BlockNumber − 1`. If the candidate's BLS registration in KIP-113 changes between those two blocks, the two keys diverge:

| Phase | Block number queried | Key returned |
|---|---|---|
| Receive-time BLS check | `currentHead` | K1 (old) |
| Semantically correct key for `msg.BlockNumber` | `msg.BlockNumber − 1` | K2 (new) |

A candidate who updates their KIP-113 BLS registration at block `currentHead + 1` and then signs a `VRankCandidate` for block `currentHead + 2` with the new key K2 will have that message rejected: the validator looks up K1 at `currentHead`, K2 ≠ K1, `VerifySignature` returns false, and `ErrInvalidCandidateBlsSig` is returned.

`EvaluateCandidates` performs no BLS re-verification; it only checks whether a stored message arrived with the correct block hash before the timeout:

```go
// kaiax/vrank/impl/getter.go  line 131-137
for _, addr := range candidates {
    msgWithTime, arrived := viewMap[addr]
    if !arrived ||
        msgWithTime.Msg == nil ||
        msgWithTime.Msg.BlockHash != expectedBlockHash ||
        msgWithTime.ReceivedAt.Sub(prepreparedAt).Milliseconds() > candidateMsgTimeoutMs {
        cfReport = append(cfReport, addr)
    }
}
```

Because the message was never stored (rejected at receive time), `arrived` is false, and the candidate is added to `cfReport`. This inflated cfReport is written into `header(N+1).VRank` and accumulated into the CP matrix. At epoch transition, `applyEpochTransition` calls `isPassVrankTest`:

```go
// kaiax/valset/impl/transition_context.go  line 241-246
func (ctx *TransitionContext) isPassVrankTest(addr common.Address) bool {
    cfs, ok := ctx.CFS[addr]
    if !ok {
        return true
    }
    return cfs < ctx.CfsThreshold
}
```

A candidate whose CFS reaches `CfsThreshold` due to the spurious failures is demoted: `CandTesting → Registered` (T2 transition), losing their testing slot.

---

### Impact Explanation

The corrupted value is the candidate's CFS score in the CP matrix, which is persisted to the DB at every `scoreCheckpointInterval` blocks. An inflated CFS causes an incorrect `CandTesting → Registered` state transition at epoch boundary, removing the candidate from the validator pipeline. This is a persistent, on-chain validator-set state corruption: the candidate's `Node.State` in the AddressBookV2 contract is written incorrectly, and the candidate must re-enter the `CandReady → CandTesting` cycle to recover.

---

### Likelihood Explanation

The trigger requires two conditions to coincide:
1. A candidate updates their KIP-113 BLS registration (a normal, self-service operation).
2. A `VRankCandidate` message for a future block (within `maxWindow`) arrives at validators before the key-update transaction is committed.

Condition 2 is a natural race: candidates broadcast `VRankCandidate` messages as soon as they receive `VRankPreprepare`, and network propagation can deliver the candidate message to validators before the key-update transaction is mined. The window is small but non-zero, and the impact is permanent until the candidate completes a full epoch cycle.

---

### Recommendation

Replace the fixed `currentHead + 1` lookup with the message's own block number:

```go
// Before (wrong):
blsNum := big.NewInt(0).Add(v.Chain.CurrentHeader().Number, big.NewInt(1))

// After (correct):
blsNum := new(big.Int).SetUint64(msg.BlockNumber)
```

This ensures the BLS key used for verification is the key registered at `msg.BlockNumber − 1`, which is the state that was authoritative when the candidate was expected to respond. For messages about the current block this is identical to the existing behaviour; for future messages within `maxWindow` it uses the correct future state once that state is available, or returns `ErrNoBlsPub` / `ErrPrunedAncestor` if the state is not yet committed — which is the correct conservative behaviour (defer acceptance until the key can be verified against the right state).

---

### Proof of Concept

```
Setup:
  currentHead = H
  candidate C has BLS key K1 registered in KIP-113 at block H
  C submits a tx to update their BLS key to K2 (mined at block H+1)
  C signs VRankCandidate for block H+2 with K2 (the key that will be valid at H+1)

Sequence:
  1. C broadcasts VRankCandidate{BlockNumber: H+2, ..., BlsSig: Sign(K2, sigHash)}
  2. Validator V receives the message when currentHead == H
  3. V computes blsNum = H+1, calls GetBlsPubkey(C, H+1)
  4. Randao reads KIP-113 state at block H → returns K1
  5. VerifySignature(BlsSig, sigHash, K1) → false  (message was signed with K2)
  6. HandleVRankCandidate returns ErrInvalidCandidateBlsSig; message not stored
  7. EvaluateCandidates(H+2, round) → C not in viewMap → C added to cfReport
  8. header(H+3).VRank encodes cfReport containing C
  9. CP matrix accumulates C's failure; CFS(C) increments
  10. At epoch boundary: isPassVrankTest(C) → false if CFS(C) >= CfsThreshold
  11. applyEpochTransition: C transitions CandTesting → Registered (T2)

// EvaluateCandidates computes the cfReport for block blockNum at the given round from in-memory collector state.
// To fill `header(N).VRank`, the proposer of block N must use `EvaluateCandidates(N-1, last round of N-1)`.
// Returns ErrNotPermissionless if header(blockNum+1) is before the permissionless fork.
func (v *VRankModule) EvaluateCandidates(blockNum, round uint64) ([]common.Address, error) {
	if !v.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum + 1)) {
		return nil, vrank.ErrNotPermissionless
	}

	// epoch header's VRank should be nil
	if (blockNum+1)%v.vrankEpoch() == 0 {
		return []common.Address{}, nil
	}
	if round > maxRound {
		// Candidate messages above maxRound are dropped on receipt, though the
		// preprepare timestamp may still be recorded. Evaluating this view would
		// then see no candidate responses and mark every candidate as failed, so
		// return an empty report instead of that spurious result.
		return []common.Address{}, nil
	}

	vk := vrank.ViewKey{N: blockNum, R: uint8(round)}
	prepreparedAt, expectedBlockHash, viewMap := v.collector.GetViewData(vk)
	if prepreparedAt.IsZero() {
		// No preprepare data — either this node was not a validator for blockNum,
		// or it missed the PREPREPARE message. Either way, nothing to report.
		return []common.Address{}, nil
	}
	candidates, err := v.Valset.GetCandTesting(blockNum)
	if err != nil {
		logger.Error("GetCandTesting failed", "blockNum", blockNum, "err", err)
		return nil, vrank.ErrGetCandidateFailed
	}
	if len(candidates) == 0 {
		return []common.Address{}, nil
	}
	var cfReport []common.Address
	for _, addr := range candidates {
		msgWithTime, arrived := viewMap[addr]
		if !arrived ||
			msgWithTime.Msg == nil ||
			msgWithTime.Msg.BlockHash != expectedBlockHash ||
			msgWithTime.ReceivedAt.Sub(prepreparedAt).Milliseconds() > candidateMsgTimeoutMs {
			cfReport = append(cfReport, addr)
		}
	}

	slices.SortFunc(cfReport, func(a, b common.Address) int { return bytes.Compare(a.Bytes(), b.Bytes()) })
	return cfReport, nil
}

```go
func (r *RandaoModule) GetBlsPubkey(proposer common.Address, num *big.Int) (bls.PublicKey, error) {
	infos, err := r.getAllCached(num)
	if err != nil {
		return nil, err
	}

	info, ok := infos[proposer]
	if !ok {
		return nil, randao.ErrNoBlsPub
	}
	if info.VerifyErr != nil {
		return nil, info.VerifyErr
	}
	return bls.PublicKeyFromBytes(info.PublicKey)
}
