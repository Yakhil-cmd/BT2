### Title
Attacker-controlled branch/remote/ref names reach git subcommands as unguarded positional arguments without a `--` separator, enabling git option injection (e.g. `--upload-pack=`) - (File: git/client.go)

### Summary
`git.Client.Fetch` and `git.Client.AddRemote` build git command argument slices where the `remote`/`name` value is placed as the first positional token after the git subcommand, with no `--` end-of-options marker, before being handed to `run.PrepareCmd(cmd).Run()`. Other functions in the same file (`ShowRefs`, `WorktreeRemove`, `RemoteURL`, `IsIgnored`) explicitly insert a `--` separator before untrusted values, showing the maintainers are aware of this argument-injection class but did not apply the same mitigation consistently to `Fetch`/`AddRemote`/`CheckoutNewBranch`.

### Finding Description
`Client.Fetch` constructs `args := []string{"fetch", remote}` then appends `refspec` if non-empty, and passes the result straight to `AuthenticatedCommand` -> `Command` -> `exec.CommandContext`, which is ultimately executed via `run.PrepareCmd(cmd).Run()`: [1](#0-0) 

`Client.AddRemote` similarly builds `args := []string{"remote", "add"}`, optionally appends `-t <branch>` pairs, then appends `name, urlStr` directly as positional tokens with no `--` terminator: [2](#0-1) 

Because git's `parse-options` machinery (used by `git fetch`, `git remote add`, etc.) does not stop parsing options after the first non-flag token unless a literal `--` is present, a `remote`, `refspec`, or `name` value beginning with `-` can be reinterpreted as a git option instead of a positional value. `git fetch` in particular exposes `--upload-pack=<command>` (and `-o`/`--server-option`), which specifies an arbitrary program to be executed as the "upload-pack" program for local/`ssh`-style transports — a classic git argument-injection RCE primitive.

Contrast this with the same file's hardened call sites, which already insert `--` before untrusted positional values: [3](#0-2) [4](#0-3) [5](#0-4) 

`run.PrepareCmd` performs no argument-boundary sanitization; it only wraps `exec.Cmd` for error/verbose reporting, executing whatever `Args` it is given: [6](#0-5) 

`CheckoutNewBranch` is less clearly exploitable because `branch` is consumed as the explicit argument to `-b` and `track` is prefixed with `remoteName + "/"`, so neither token can itself begin with `-` in a way git's option parser would reinterpret: [7](#0-6) 

The remaining open question — which I could not fully verify given tool-call limits — is the exact call chain from `gh repo clone`, `gh pr checkout`, or `gh repo sync` into `Fetch`/`AddRemote` with a fully attacker-controlled string (e.g., a PR head branch name or fork owner used as remote name). I located callers in `pkg/cmd/repo/fork/fork.go`, `pkg/cmd/issue/develop/develop.go`, and `pkg/cmd/repo/clone/clone.go` but did not have remaining budget to confirm whether the values passed there can begin with `-` (e.g., whether GitHub's username/branch-name validation would block a literal leading-dash owner name, while still permitting a leading-dash branch/ref name).

### Impact Explanation
If a `remote`/`refspec` value reaching `Client.Fetch` can be attacker-influenced (e.g., derived from a fork/branch/ref name published by the attacker), this maps to local arbitrary command execution via git's `--upload-pack=`/`-o` style options — matching GitHub's "Remote code execution" bounty class for the `gh` CLI, scoped specifically to victims who clone/checkout/sync attacker-published refs.

### Likelihood Explanation
Exploitability is contingent on whether GitHub's naming rules for repos/branches/remotes permit a leading-dash value to survive unmodified into `remote` or `refspec` positions of `Fetch`, or into `name` for `AddRemote`. Branch/ref names on GitHub are less restricted than usernames (which cannot start with `-`), making a leading-dash branch name (e.g., `--upload-pack=touch$IFS/tmp/pwned`) plausible as a refspec value. This needs to be confirmed against the actual call sites in `pkg/cmd/repo/clone`, `pkg/cmd/pr/checkout`, and `pkg/cmd/repo/sync` (not fully traced here) before treating this as conclusively exploitable end-to-end.

### Recommendation
Insert an explicit `--` end-of-options separator immediately before any attacker-influenced positional value in `Client.Fetch`, `Client.AddRemote`, `Client.Pull`, and `Client.Push`, mirroring the pattern already used in `ShowRefs`, `WorktreeRemove`, `RemoteURL`, and `IsIgnored`. Additionally, add a shared validation helper that rejects/normalizes any git ref, remote, or branch name beginning with `-` before it is placed into an `args` slice destined for `exec.Cmd`.

### Proof of Concept
Add a git-stub test in `git/client_test.go` asserting that `Fetch`/`AddRemote`/`CheckoutNewBranch` always place a `--` before an untrusted value, or reject dash-prefixed inputs outright:
```go
func TestFetchRejectsOrEscapesDashPrefixedRemote(t *testing.T) {
    cs, restore := run.Stub()
    defer restore(t)
    cs.Register(`git fetch -- --upload-pack=touch/tmp/pwned refspec`, 0, "")

    client := &Client{}
    err := client.Fetch(context.Background(), "--upload-pack=touch /tmp/pwned", "refspec")
    // Expect either: (a) the stubbed command matches only when "--" is inserted,
    // proving Fetch escapes the boundary, or (b) client.Fetch returns a validation
    // error before invoking run.PrepareCmd.
    assert.NoError(t, err)
}
```
Expected assertion: the git-stub only matches (and the test only passes) if a `--` separator precedes the dash-prefixed `remote`/`name` argument, or if `Fetch`/`AddRemote` return an error for such input prior to reaching `run.PrepareCmd`. Currently, per the code at `git/client.go` lines 866-879 and 831-843, no such separator or validation exists, so the stub would need to match `git fetch --upload-pack=... refspec` (without `--`), demonstrating the unguarded positional placement.

var PrepareCmd = func(cmd *exec.Cmd) Runnable {
	return &cmdWithStderr{cmd}

// cmdWithStderr augments exec.Cmd by adding stderr to the error message
type cmdWithStderr struct {
	*exec.Cmd
}

func (c cmdWithStderr) Output() ([]byte, error) {
	if isVerbose, _ := utils.IsDebugEnabled(); isVerbose {
		_ = printArgs(os.Stderr, c.Cmd.Args)
	}
	out, err := c.Cmd.Output()
	if c.Cmd.Stderr != nil || err == nil {
		return out, err
	}
	cmdErr := &CmdError{
		Args: c.Cmd.Args,
		Err:  err,
	}
	var exitError *exec.ExitError
	if errors.As(err, &exitError) {
		cmdErr.Stderr = bytes.NewBuffer(exitError.Stderr)
	}
	return out, cmdErr
}

func (c cmdWithStderr) Run() error {
	if isVerbose, _ := utils.IsDebugEnabled(); isVerbose {
		_ = printArgs(os.Stderr, c.Cmd.Args)
	}
	if c.Cmd.Stderr != nil {
		return c.Cmd.Run()
	}
	errStream := &bytes.Buffer{}
	c.Cmd.Stderr = errStream
	err := c.Cmd.Run()
	if err != nil {
		err = &CmdError{
			Args:   c.Cmd.Args,
			Err:    err,
			Stderr: errStream,
		}
	}
	return err
}
