### Title
Unsanitized attacker-controlled Jupyter server URL printed to terminal enables ANSI/OSC escape sequence injection - (File: pkg/cmd/codespace/jupyter.go)

### Summary
The Jupyter server URL returned by the codespace's internal gRPC service (`invoker.StartJupyterServer`) is written directly to the terminal via `fmt.Fprintln(a.io.Out, targetUrl)` with no stripping of control/escape bytes. Since the codespace environment (and therefore the internal `JupyterServerHostService` gRPC responder) can be provisioned by an attacker-authored devcontainer/repo that the victim opens as a codespace, the `ServerUrl` field is effectively attacker-controlled content reaching the victim's terminal.

### Finding Description
`App.Jupyter` in `pkg/cmd/codespace/jupyter.go` calls `invoker.StartJupyterServer(ctx)` to obtain `serverPort` and `serverUrl` [1](#0-0) . It then rewrites the port in the returned string and prints the result unmodified to standard output: [2](#0-1) 

There is no sanitization step between receiving `serverUrl` from the gRPC response and printing it — validation logic referenced elsewhere in the invoker layer is described (per the question) as checking only scheme/host, which does not preclude embedding raw C0/C1 control bytes or OSC/CSI escape sequences inside the string (e.g. in the path, query, or fragment component, or simply as extra unparsed bytes appended to the value depending on how the field is validated). Because `serverUrl` is a plain string field returned over gRPC by the codespace-side service (not enforced to be a strictly parsed/re-serialized `net/url.URL`), any bytes the attacker's codespace-side service places in that field can survive into `targetUrl` and reach `fmt.Fprintln`.

The reachable attack path is: attacker publishes a repo/devcontainer that the victim opens as a codespace → the codespace's internal service (which the attacker controls via their devcontainer image) implements `JupyterServerHostService.StartJupyterServer` and returns a crafted `ServerUrl` containing an OSC 8 hyperlink sequence or other terminal control sequences → gh's `invoker.StartJupyterServer` passes this value back to `App.Jupyter` → `App.Jupyter` performs only a string `Replace` on the port number and prints the value unsanitized to the user's terminal via `a.io.Out`.

### Impact Explanation
An attacker who controls the codespace's internal service response (achievable by publishing a malicious devcontainer/repo that the victim opens with `gh codespace jupyter`) can inject terminal escape sequences into the printed output. This can be used to spoof terminal content (e.g., render a fake, trusted-looking URL or message while hiding the real, potentially malicious one), or hide portions of output, which can facilitate follow-on social-engineering / risky actions by the victim. This maps to a terminal/output injection (spoofing) class of impact — generally a low-to-moderate severity issue since it does not directly achieve code execution or credential exfiltration on its own, but it undermines output integrity that the user relies on to trust `gh`'s output.

### Likelihood Explanation
Requires the victim to run `gh codespace jupyter` against a codespace whose internal Jupyter/RPC service is influenced by attacker-supplied devcontainer configuration/content (a plausible unprivileged attacker capability per the given threat model: attacker publishes a repo/devcontainer, victim opens a codespace from it). It also requires the victim's terminal emulator to interpret ANSI/OSC sequences, which is the default for most terminals. No admin rights, tokens, or MITM are required.

### Recommendation
Sanitize `targetUrl` before printing (and before use in `a.browser.Browse`) by stripping/rejecting any non-printable/control characters (C0/C1 control codes, ESC sequences, OSC/CSI introducers) and by validating the value with `net/url.Parse` and re-serializing only the safe, expected fields (scheme, host, port, path, and the token query parameter) rather than printing the raw string returned by the RPC. Reject or escape any URL containing bytes outside the RFC 3986 allowed character set for URLs.

### Proof of Concept
```go
func TestJupyterPrintedURLIsSanitized(t *testing.T) {
    // Simulate a malicious ServerUrl returned by the codespace's internal
    // JupyterServerHostService with an embedded OSC 8 hyperlink escape sequence.
    malicious := "http://localhost:8888/?token=abc\x1b]8;;http://evil.example\x07CLICK\x1b]8;;\x07"

    out := &bytes.Buffer{}
    // targetUrl mirrors the strings.Replace done in App.Jupyter
    targetUrl := strings.Replace(malicious, "8888", "9999", 1)
    fmt.Fprintln(out, targetUrl)

    printed := out.String()
    if strings.Contains(printed, "\x1b]8;;") {
        t.Fatalf("terminal escape sequence reached output unsanitized: %q", printed)
    }
}
```
Expected (current, vulnerable) behavior: the assertion fails because `\x1b]8;;` survives into the printed string, confirming that `App.Jupyter`'s `fmt.Fprintln(a.io.Out, targetUrl)` call at `pkg/cmd/codespace/jupyter.go:97` does not sanitize control/escape sequences from an RPC-supplied `ServerUrl`.
