### Title
Below-threshold signer's rewards snapshot gets advanced by a bond co-claim, causing STX-only stakers to be credited rewards their signer never earned - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
The Hats `checkAfterExecution()` bug class is about an invariant check whose supporting values can be mutated mid-flight so the check is satisfied even though the true invariant (threshold ↔ owner count correspondence) was violated. The `pox-5.clar` reward-settlement logic has the analogous property: the "correctness" of a signer's `signer-rewards-per-token-for-cycle` snapshot depends on `settle-rewards` only being allowed to move the global `rewards-per-token` marker onto a signer's per-cycle record when that signer actually has shares (`> shares u0`), but a separate, related state field (`signer-rewards-per-token-settled-for-cycle`) is unconditionally advanced regardless of shares, and multiple call paths into `settle-rewards` for the *same* signer/cycle/bond-index tuple (STX-only path `bond-index: none` vs. bond-claim path) interact so that a below-minimum signer's snapshot ends up advanced as a side effect of an unrelated bond claim.

### Finding Description
`settle-rewards` in `stackslib/src/chainstate/stacks/boot/pox-5.clar` (around lines 2530-2574) is the function meant to "crystallize" a signer's earned rewards before any mutation of `signer-shares-staked-for-cycle`: [1](#0-0) 

It computes `earned` from the signer's current shares, the global `rewards-per-token`, and the signer's previously settled snapshot, then always writes `signer-unclaimed-rewards-for-cycle` and `signer-rewards-per-token-settled-for-cycle`, but only writes `signer-rewards-per-token-for-cycle` (the value stakers read to compute their own earned rewards) when `shares > u0`. This conditional was clearly intended to prevent a signer that currently has zero (or below-minimum) shares from having its staker-facing snapshot advanced — i.e., to preserve the invariant "a signer's stakers cannot be credited rewards for a cycle the signer was not a qualifying member of."

However, the unit test `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts` (test `'below-threshold signer leaks phantom stx-only rewards via bond co-claim'`) demonstrates that this invariant is broken in practice: [2](#0-1) 

In the scenario:
1. Signer1 is below `SIGNER_SET_MIN_USTX` for cycle 1 for STX-only staking (Alice's stake plus a tiny sBTC-bond amount from Bob still leaves it under the minimum), so `isSignerInCycle` is `false` and `getSignerSharesStakedForCycle(signer1, 1, null)` is `0`.
2. Signer2 is independently above the minimum, so the *global* STX-only `rewards-per-token` for cycle 1 legitimately advances once rewards are calculated.
3. `getEarned(signer1, 1, null)` is confirmed to be `0` and Alice's `getEarnedStakerRewards` is `0`, both correctly reflecting that signer1 earned nothing.
4. A **bond claim** (`claimRewards([0], 1)`, which is unrelated to STX-only staking) is executed for signer1. This claim path also invokes `settle-rewards signer1 1 none` internally (as documented in the comment "settle-rewards runs on signer1's STX-only cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle").
5. After the bond claim, the test's witnessing assertion — that Alice must still not be owed any STX-only rewards for cycle 1 — fails on the unfixed code, because the STX-only snapshot (`signer-rewards-per-token-for-cycle`) for signer1/cycle1/`bond-index none` was advanced to the current global rate as an unintended side effect of settling the *bond*-indexed reward stream for that same signer/cycle.

This is directly analogous to the Hats issue: the checked invariant ("signer1's stakers cannot earn STX-only rewards for a cycle in which signer1 was below the qualifying threshold") depends on a piece of state (`shares`) at the moment `settle-rewards` runs, but a *different, unrelated action* (claiming bond rewards for the same signer/cycle) causes the guarded state transition to fire in a way that was not intended, breaking the equality "staker's earned rewards == rewards actually generated by their signer's participation."

### Impact Explanation
This breaks the equality "sBTC/STX rewards paid == rewards earned," letting stakers under a signer that never qualified for the STX-only reward pool for a given cycle claim rewards that were never earned by that signer — i.e., rewards paid that were not earned, drawn from the shared reward pool at the expense of legitimately-qualifying signers/stakers. This falls squarely into the allowed impact category of "sBTC/STX rewards paid that were not earned or counted twice," which the rules classify as Critical/High depending on scale. Because the leaked amount tracks the *global* `rewards-per-token` (not bounded to signer1's own tiny contribution), the size of the phantom credit scales with the reward pool's total payout rather than with the disqualified signer's stake, which can materially drain reward funds meant for qualifying participants.

### Likelihood Explanation
This requires no privileged role. Any staker or signer manager acting normally (staking below `SIGNER_SET_MIN_USTX`, and any account triggering a bond reward claim for that signer/cycle — which can be the attacker themselves or even an unrelated third party) can trigger the sequence. The test in the repository shows this is reproducible with an ordinary sequence of `setupBond`, `registerForBond`, `stake`, `calculateRewards`, and `claimRewards` calls — no special permissions, admin/bond-pause authority, or another user's key are needed, satisfying the "unprivileged account" requirement.

### Recommendation
`settle-rewards` should not let claiming/settling one bond-index's reward stream implicitly promote the "settled" checkpoint used by a different bond-index (in particular the STX-only `none` stream) for the same signer/cycle. The snapshot advance for `signer-rewards-per-token-for-cycle` must remain strictly scoped and gated on that specific stream's own current shares at settlement time, and the interaction between bond-index-specific claims and the STX-only settlement path needs to be decoupled (or the STX-only snapshot should only ever be updated from a call site that is itself scoped to `bond-index: none` and driven by STX-only stake changes, never as a side effect of a bond-index-specific claim on the same signer/cycle).

### Proof of Concept
The repository's own regression test at `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts:6064-6157` (`'below-threshold signer leaks phantom stx-only rewards via bond co-claim'`) is a working proof of concept:
1. Deploy a bond and register Bob into it under `signer1`, sized so Bob's bond-ustx alone is far below `SIGNER_SET_MIN_USTX`.
2. Alice stakes STX-only to `signer1` with an amount such that `aliceStake + bobBondUstx < SIGNER_SET_MIN_USTX`, keeping `signer1` out of the cycle-1 signer set (`isSignerInCycle` false, `getSignerSharesStakedForCycle` = 0).
3. Charlie stakes a large STX-only amount to an independent `signer2` that is above the threshold, so the cycle-1 global STX-only `rewards-per-token` legitimately advances once rewards are funded and calculated.
4. Fund the contract with sBTC and call `pox5.calculateRewards([0])`; confirm `signer1`'s STX-only earned is 0 and Alice's earned is 0.
5. Call `testSigner.claimRewards([0], 1)` to settle signer1's bond-index-0 rewards for cycle 1.
6. Observe that Alice's STX-only earned rewards for cycle 1 becomes non-zero even though `signer1` never qualified for or earned any STX-only rewards in that cycle — the assertion `expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n)` fails on the unfixed contract.

(define-private (settle-rewards
        (signer principal)
        (reward-cycle uint)
        (bond-index (optional uint))
    )
    (let (
            (shares (get-signer-shares-staked-for-cycle signer reward-cycle bond-index))
            (rewards-per-token (get-rewards-per-token-for-cycle reward-cycle bond-index))
            (earned (compute-earned-rewards
                shares
                rewards-per-token
                (get-signer-rewards-per-token-settled-for-cycle signer reward-cycle bond-index)
                (get-signer-unclaimed-rewards-for-cycle signer reward-cycle bond-index)
            ))
        )
        (map-set signer-unclaimed-rewards-for-cycle {
            reward-cycle: reward-cycle,
            bond-index: bond-index,
            signer: signer,
        }
            earned
        )
        (map-set signer-rewards-per-token-settled-for-cycle {
            reward-cycle: reward-cycle,
            bond-index: bond-index,
            signer: signer,
        }
            rewards-per-token
        )
        (if (> shares u0)
            (map-set signer-rewards-per-token-for-cycle {
                signer: signer,
                reward-cycle: reward-cycle,
                bond-index: bond-index,
            }
                rewards-per-token
            )
            true
        )
        {
            earned: earned,
            rewards-per-token: rewards-per-token,
        }
    )
)

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
