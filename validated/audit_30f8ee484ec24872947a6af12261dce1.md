### Title
RAY-denominated market totals can overflow accrual and permanently freeze a market - ([File: common/src/rates/simulate.rs])

### Summary
High-severity denial of service. `accrue_step` multiplies scaled market totals by their indexes before the borrow-index ceiling is reached. For sufficiently large markets, this RAY value exceeds `i128::MAX` even though the index remains below `MAX_BORROW_INDEX_RAY`, causing every later accrual-dependent operation to revert.

### Finding Description
`global_sync` processes every elapsed interval through `accrue_step` before mutating market state. [1](#0-0)  The step converts `borrowed` and `supplied` shares to RAY-denominated values with `scaled_to_original` before updating the indexes. [2](#0-1)  `scaled_to_original` is a non-saturating `Ray::mul`, which reaches `mul_div_half_up`. [3](#0-2) [4](#0-3)  When `scaled * index / RAY` does not fit `i128`, `mul_div_half_up` panics with `MathOverflow`. [5](#0-4) 

`update_borrow_index` caps the next index at `MAX_BORROW_INDEX_RAY`, but that cap is applied only after `accrue_step` has already multiplied the potentially oversized scaled total by the current index. [6](#0-5) [7](#0-6)  Consequently, a large book can cross the representable-value boundary while its borrow index is still far below the index ceiling.

An unprivileged user can reach the affected state through `Controller::borrow` after supplying collateral; later, `repay`, `withdraw`, `liquidate`, or index synchronization all require the same accrual path. [8](#0-7)  The repository’s regression test demonstrates this condition: an 18-decimal market holding `1e36` scaled supply and `9.8e35` scaled debt fails `update_indexes`, then both withdrawal and repayment fail with `MathOverflow` while the stored borrow index remains below the cap. [9](#0-8) 

### Impact Explanation
Once the scaled debt or supply value crosses the `i128` boundary, accrual cannot complete, so ordinary repayment, collateral withdrawal, liquidation, bad-debt processing, and parameter/index updates that accrue first cannot execute for that market. User deposits and protocol revenue in the affected market remain frozen absent a contract upgrade or externally coordinated state repair. [1](#0-0) [10](#0-9) 

If the oversized debt was borrowed against the attacker’s collateral, the borrower can retain the borrowed assets while liquidation and repayment are blocked, leaving the market permanently under-collateralized. This can result in permanent freezing of supplier funds and protocol insolvency.

### Likelihood Explanation
The trigger requires a very large high-decimal market and sustained high utilization: approximately `1e36` scaled debt reaches the value boundary when the borrow index exceeds roughly `1.7e29`, far below the `1e36` index cap. The repository’s supported XLM-style steep curve and maximum utilization configuration demonstrate that this does not rely on malformed storage or an invalid market object, although it does require whale-scale liquidity, sufficient collateral, and elapsed ledger time. [11](#0-10) [12](#0-11) 

### Recommendation
Do not allow market state where `scaled * index / RAY` can become unrepresentable while later mutations still require that product. Enforce a per-market index ceiling derived from total scaled supply/debt, reject new supply or borrow once the configured maximum index could overflow, and use saturating or widened arithmetic for utilization and aggregate-value calculations. Add the existing whale-market scenario as a regression test covering `update_indexes`, `repay`, `withdraw`, `liquidate`, `recapitalize`, and parameter updates.

### Proof of Concept
The checked-in test constructs the vulnerable state:

```rust
// tests/test-harness/tests/controller/large_positions_and_long_horizons.rs
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);
```

It then advances ledger time until `update_indexes` fails, verifies that `borrow_index < MAX_BORROW_INDEX_RAY`, and confirms that both withdrawal and repayment fail with `MathOverflow`. [13](#0-12)  In deployment, the borrower can use an existing supplier-funded market rather than supplying the debt liquidity themselves, provided listing caps and collateral requirements admit the position.

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
