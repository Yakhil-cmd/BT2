### Title
Webhook signature verification binds to an attacker-chosen organization while the payload consumed by handlers can target a different organization's stack - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App configuration (and therefore which `webhook_secret`) to verify a webhook against based on a value taken directly from the unauthenticated JSON body (`repository.owner.login` / `organization.login`), and `GitHubApp#verify_webhook_signature` unconditionally returns `true` when that organization has no `webhook_secret` configured. The remainder of the payload used by event handlers to decide which `Stack`/repository to act on is read from the very same untrusted body, so the "which credential authenticated this request" binding and the "which repository gets written to" binding are established from two independently attacker-controlled fields of one unsigned JSON document.

### Finding Description
`repository_owner` is computed straight from request JSON before any cryptographic check occurs: [1](#0-0) 

It is then used to pick the `GitHubApp` instance (and its secret) that will "verify" the request: [2](#0-1) 

`Shipit.github` supports per-organization configuration, so different organizations can have entirely independent `webhook_secret` values (or none at all): [3](#0-2) 

Crucially, `verify_webhook_signature` treats a missing `webhook_secret` as automatic success, not as a failure: [4](#0-3) 

`docs/setup.md` documents the webhook secret as *optional*, so this is a supported, expected configuration state rather than a misuse: [5](#0-4) 

Once `verify_signature` passes (using the secret resolved for the attacker-supplied `repository_owner`), the full unauthenticated body is dispatched, unchanged, to every registered handler for the event: [6](#0-5) 

The equality that should hold is: `organization whose secret authenticated the request == organization that owns the repository/stack the handler subsequently mutates`. Because both the authenticating field (`repository.owner.login`/`organization.login`) and the effective target used later by handlers are read from the same attacker-controlled JSON body rather than being cryptographically bound together, an attacker can pick an authenticating organization that has no `webhook_secret` configured (satisfying `verify_signature`) while shaping the rest of the payload to reference a different, protected stack/repository. I was not able to open `app/models/shipit/webhooks/handlers/push_handler.rb` in this session (tool errors) to confirm the exact field it uses to resolve the target `Stack`, so the precise mechanics of the second half of this split (which field the handler trusts to select the `Stack`) remain unconfirmed from static inspection; this is flagged as an open verification item.

### Impact Explanation
If confirmed, this allows an unauthenticated actor to forge GitHub webhook events (`push`, `status`, `check_suite`, `membership`, etc.) against a stack belonging to an organization that does enforce a webhook secret, by authenticating as any other configured organization that does not set one. Depending on which handler is reached, this could trigger unauthorized `GithubSyncJob` runs, fabricate commit statuses that gate deploy safety checks, or manipulate team/membership state used for authorization (`Shipit.github_teams`) — i.e., escalation into deploy-gating logic without holding any credential for the targeted organization.

### Likelihood Explanation
Requires only network access to the public `/webhooks` endpoint (no session, no `ApiClient` token, no GitHub App key) and knowledge that at least one configured organization in a multi-tenant Shipit deployment has an empty/absent `webhook_secret` — an explicitly documented, supported configuration. The dependency on the unverified `push_handler` field-selection logic (not confirmed in this session) is the main source of uncertainty on exploitability in a single-organization deployment.

### Recommendation
- Do not resolve the verifying organization from unauthenticated payload content; instead require every configured organization to set a non-empty `webhook_secret`, and reject the request outright if one is missing rather than defaulting to `verified = true`.
- After signature verification, re-derive the effective repository/organization used by handlers strictly from the same field that was cryptographically covered by the verified organization, and reject the request if the two disagree.

### Proof of Concept
Unconfirmed end-to-end due to inability to inspect `push_handler.rb` in this session. Conceptually: configure two organizations in `secrets.github`, one (`org-a`) without a `webhook_secret`; POST to `/webhooks` with `X-Github-Event: push`, `X-Hub-Signature` arbitrary, and a JSON body whose `repository.owner.login` is `org-a` (so `verify_signature` passes unconditionally via `lib/shipit/github_app.rb:76-83`) while other repository-identifying fields reference a stack under a different, secret-protected organization.

#### Verification note
Due to tool errors in the final turn, `app/models/shipit/webhooks/handlers/push_handler.rb` (and sibling handlers) could not be read to confirm whether they resolve the target `Stack` from a field independent of `repository.owner.login`. This should be verified directly in a full session before treating this as conclusively exploitable end-to-end.

```ruby
  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
