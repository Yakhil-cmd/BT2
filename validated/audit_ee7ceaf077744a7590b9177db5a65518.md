Based on my research, the closest analog in ocore to the "pause blocks withdraw, locking funds" bug class is the `spender_attested` asset mechanism, where an asset issuer can gate all transfers of an asset behind an attestor whitelist and later revoke that whitelist, freezing already-issued holdings with no recovery path — functionally identical to a pause switch that also blocks withdrawals.

### Title
Asset issuer can freeze already-held asset funds by revoking/changing the attestor list on a `spender_attested` asset - (File: `validation.js`)

### Summary
An asset defined with `spender_attested: true` requires every spending address to be currently attested by one of the asset's attestors, checked at validation time on every payment, not just at issuance time. The attestor list itself can be freely replaced later by the asset definer via an `asset_attestors` message. Because the check is re-evaluated against the *latest* attestor list on every spend, a definer can, after users have legitimately acquired and held the asset, publish a new attestor list that drops the attestor who attested those users. This immediately and permanently blocks those users from spending/withdrawing coins they already own, with no way for them to recover access — the same "pause blocks withdraw, locks user funds" impact described in the reference report.

### Finding Description
The `spender_attested` flag is checked in `validatePayment` and again per-input in `validatePaymentInputsAndOutputs`: [1](#0-0) [2](#0-1) 

The attestor list used for this check is always the *latest* one, resolved dynamically in `storage.readAsset`/`addAttestorsIfNecessary`, which queries for the most recent `asset_attestors` unit before last ball: [3](#0-2) 

The attestor list can be updated at any time solely by the asset definer, with no restriction preventing it from removing attestors that previously attested existing holders: [4](#0-3) 

Nothing in `checkAttestorList` or `validateAttestorListUpdate` requires the new list to still cover addresses that already hold the asset: [5](#0-4) 

As a result, once the definer swaps out an attestor (or shrinks the list) after distribution has happened, any holder whose attestation came only from the removed attestor becomes permanently unable to pass the `spender_attested` check for outputs they already own — even though those outputs were validly acquired while attested. There's no unpause/whitelist-restoration path enforced by protocol; the definer has full unilateral control, and the freeze applies retroactively to existing balances, not just future issuance.

### Impact Explanation
This is a fund-freezing bug for holders of a `spender_attested` asset (a common asset type used for KYC-gated tokens, ICOs, etc.): a single asset-issuer action (publishing a new `asset_attestors` unit) can lock arbitrary existing holders out of coins they already legitimately own, with no fallback. This matches the Medium-severity impact class from the reference finding — user funds become inaccessible due to a state change unrelated to the ownership of those funds ("AA/asset fund freezing").

### Likelihood Explanation
The attestor-list update message (`asset_attestors`) requires only a single signature from the asset definer, and is validated with no restriction tying the new list to currently-held balances. Any asset issuer who wants to (intentionally, through a bug in their own tooling, or via compromised definer key) republish an attestor list will immediately freeze the funds of previously-attested holders on their next payment attempt. No coordination with witnesses or other privileged actors is required beyond the definer authoring one unit.

### Recommendation
Consider one or more of:
- Grandfathering already-attested addresses so that spend-time attestation is checked against the attestor list that was current when the output was created, rather than always the latest list.
- Requiring a time-locked/multi-step attestor list change so holders have advance notice and an opportunity to move funds before the new list takes effect.
- Documenting explicitly that `spender_attested` assets carry issuer-controlled freeze risk on existing balances, and providing a standard `oscript`/wallet warning when interacting with such assets.

### Proof of Concept
1. Asset definer creates asset A with `spender_attested: true` and attestor list `[Attestor1]` (`validateAssetDefinition`, `validation.js:2725-2755`).
2. `Attestor1` attests `Holder`'s address (`attestation` message, `writer.js:205-217`).
3. `Holder` receives/holds units of asset A; `validatePayment` allows this because `Holder` is in `arrAttestedAddresses` at that time (`validation.js:2115-2122`).
4. Definer publishes a new `asset_attestors` message for asset A listing `[Attestor2]` only, signed solely by the definer (`validateAttestorListUpdate`, `validation.js:2829-2848`); this passes validation since nothing checks existing holders.
5. `Holder` attempts to spend/withdraw their existing (already-owned) coins of asset A. `storage.readAsset` now resolves the attestor list to `[Attestor2]` (`storage.js:1917-1946`), `Holder` is no longer in `arrAttestedAddresses`, and `validatePaymentInputsAndOutputs` rejects the input with "owner address is not attested" (`validation.js:2506-2507`).
6. `Holder`'s previously legitimate funds are now permanently unspendable unless re-attested by `Attestor2`, which is entirely outside their control.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}

function checkAttestorList(arrAttestors){
	if (!isNonemptyArray(arrAttestors))
		return "attestors not defined";
	if (arrAttestors.length > constants.MAX_ATTESTORS_PER_ASSET)
		return "too many attestors";
	var prev="";
	for (var i=0; i<arrAttestors.length; i++){
		if (!isValidAddress(arrAttestors[i]))
			return "invalid attestor address: "+JSON.stringify(arrAttestors[i]);
		if (arrAttestors[i] <= prev)
			return "attestors not sorted";
		prev = arrAttestors[i];
	}
	return null;
}
