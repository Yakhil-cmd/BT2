### Title
Borrow index cap fails to prevent `scaled_to_original` RAY-value overflow, permanently freezing a saturated market - (common/src/rates/index.rs)

### Summary
`update_borrow_index` clamps the borrow *index* at `MAX_BORROW_INDEX_RAY` (1e9 RAY), but the value ceiling that actually traps is `i128::MAX` on `scaled × index` inside `scaled_to_original`. For a market whose scaled debt is large enough, `borrowed × borrow_index` overflows `i128` while `borrow_index` is still far below the cap, so accrual panics with `MathOverflow` instead of saturating. Because every verb accrues before acting, the market freezes irreversibly.

### Finding Description
In `common/src/rates/index.rs:13-19`, `update_borrow_index` computes `old_index.mul(interest_factor)` and clamps the *index*, not the *value* it will later multiply. The cap `MAX_BORROW_INDEX_RAY = 1e36` raw units (`common/src/constants/pool.rs:19`) only bounds the index; it says nothing about `borrowed * borrow_index`. When accrual runs, `calculate_supplier_rewards` (`common/src/rates/index.rs:80-81`) computes `borrowed.mul(env, new_borrow_index)`, and `Cache::calculate_utilization` calls `scaled_to_original(borrowed, borrow_index)` (`contracts/pool/src/cache/scale.rs:23`). `Ray::mul` panics with `MathOverflow` when the product exceeds `i128::MAX`. The representable value ceiling is `i128::MAX / RAY ≈ 1.7e11` whole-token units; a market holding scaled debt near that ceiling crosses the product overflow at an index of only ~170× — roughly 5 orders of magnitude below `MAX_BORROW_INDEX_RAY`, so the cap never engages.

### Impact Explanation
Every state-changing entrypoint accrues interest first (`update_indexes` is also callable directly by anyone). Once `borrowed * borrow_index` overflows, `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `recapitalize`, and `flash_*` all panic in accrual for that market — permanently. The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-356`) demonstrates exactly this: `update_indexes` panics with `MATH_OVERFLOW` while `borrow_index < MAX_BORROW_INDEX_RAY`, and subsequent `withdraw`/`repay` fail with the same error. All supplier and collateral funds in the market are frozen forever; outstanding debt can never be repaid or liquidated.

### Likelihood Explanation
Requires a single market whose scaled debt approaches the RAY value ceiling and sustained high borrow rate so the index compounds to the overflow point — reachable only after substantial time at high utilization, and only in a whale-scale market (debt value ≈1.7e11 whole-token-equivalent units at the cap-lifted configuration). An unprivileged attacker can seed the condition via `supply` + `borrow` and nudge it with periodic `update_indexes` calls, but cannot compress the compounding time. Realistic only for high-decimals, high-rate markets with lifted caps; likelihood is low-to-moderate, severity is permanent freeze of an entire market's funds.

### Recommendation
Clamp on value, not just index. In `update_borrow_index` (and the supply-index path), cap the new index at `min(MAX_BORROW_INDEX_RAY, i128::MAX / borrowed.raw())` — i.e., pass the current scaled debt into index update and bound the index so `borrowed * index` stays representable. Alternatively, make `scaled_to_original`/`Ray::mul` saturate to `i128::MAX` on the accrual path so accrual degrades gracefully instead of panicking, and add the same ceiling-awareness to `update_supply_index`'s `supplied * old_index` product (`common/src/rates/index.rs:34`).

### Proof of Concept
Reproduced by the existing harness test `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:320-356`:

```rust
let principal = BILLION * 10i128.pow(18);       // scaled debt near the RAY ceiling
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;                 // 98% utilization on the XLM curve
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop { t.advance_time(YEAR_SECS); t.try_update_indexes_for(&["BIG18"]) } // -> MathOverflow
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

The test asserts `borrow_index < MAX_BORROW_INDEX_RAY` at the moment of failure, proving the index cap is miscalibrated against the `i128` value ceiling, and that the freeze is permanent for all verbs that accrue.
