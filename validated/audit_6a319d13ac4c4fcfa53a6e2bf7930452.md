### Title
Attacker-controlled release asset filename enables path traversal write outside the download destination - (`File: pkg/cmd/release/download/download.go`)

### Summary
`gh release download` uses the release asset's `Name` field (or a Content-Disposition-derived filename for `--archive`) directly as the file name to write to disk, joining it with the destination directory via `filepath.Join` without validating that the resulting path stays confined to the destination. A malicious release/asset can contain `..` path segments to write outside the intended download directory.

### Finding Description
`downloadRun` builds `downloadTarget{name: a.Name}` directly from the `shared.ReleaseAsset.Name` field [1](#0-0)  which is populated straight from the GitHub API JSON `name` property of each asset with no sanitization [2](#0-1) .

`downloadAsset` only invokes `filepath.Base` on the filename derived from the `Content-Disposition` header (the `--archive` path), but when `fileName` is already non-empty (the normal, non-archive asset path) it is passed through unmodified straight to `dest.Copy` — no `filepath.Base`/traversal check is ever applied to `a.Name`: [3](#0-2) 

`destinationWriter.makePath` then does a raw `filepath.Join(w.dir, name)`: [4](#0-3) 

`filepath.Join` calls `filepath.Clean`, which collapses `..` segments arithmetically rather than rejecting them, so a name such as `../../evil.sh` combined with `w.dir` (e.g. `.` or a shallow destination) resolves to a path outside the destination directory. `Copy` then creates any needed parent directories with `os.MkdirAll` and opens/truncates the file with `os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)`, writing attacker-controlled asset bytes to that path: [5](#0-4) 

For the `--archive` case, the same lack of confinement applies to the `filename` parameter parsed out of the `Content-Disposition` response header — `filepath.Base` is applied there, which does strip directory components, so that specific sub-path is not exploitable. The exploitable path is the ordinary (non-archive) asset-name path, since `a.Name` bypasses the `filepath.Base` call entirely (it's only reached when `fileName == ""`).

No `--pattern` matching, `filepath.Base`, `filepath.Clean`-with-rejection, or "is-path-inside-destination" check exists anywhere between the API response and `os.OpenFile`.

### Impact Explanation
An attacker who can publish (or control the API response for) a release with an asset named e.g. `../../.bashrc` or `../../../.ssh/authorized_keys` can, when the victim runs `gh release download` (with or without `--pattern`, since `--pattern` matching is done against the raw untrusted `a.Name` and does not prevent traversal), cause the CLI to write the asset's contents to an arbitrary path under ancestors of the destination directory, up to and including files outside the intended download tree (e.g., under the victim's home directory or working-directory ancestors). This matches GitHub's "arbitrary file write outside intended path" bounty impact class and could lead to further compromise (e.g., overwriting shell rc files, SSH config, or CI files depending on where `gh` is invoked).

### Likelihood Explanation
This requires only that the victim run `gh release download <tag>` (optionally with `--pattern`) against a repository/release controlled by the attacker (public repo release, or any release the victim is instructed/tricked into downloading, including one they don't control the content of e.g. a fork's release advertised to them). No token leakage, MITM, or local access is required — publishing a release asset with a crafted `name` is achievable by any repository collaborator/owner via the REST upload API, which is a normal unprivileged action for that attacker's own repository. The exploit is fully deterministic and repeatable.

### Recommendation
In `downloadAsset`/`destinationWriter`, sanitize every asset filename (not just the Content-Disposition-derived one) with `filepath.Base` before using it, and additionally verify in `makePath`/`Copy` that the resolved path (`filepath.Clean(filepath.Join(w.dir, name))`) remains within `w.dir` (e.g., using `filepath.Rel` and rejecting results starting with `..`, or comparing against `filepath.EvalSymlinks`-resolved boundaries), returning an error instead of writing when traversal is detected.

### Proof of Concept
```go
func TestDownloadAssetPathTraversal(t *testing.T) {
    tmpDest := t.TempDir()
    outsideDir := t.TempDir() // simulate ancestor outside destination

    ios, _, _, _ := iostreams.Test()
    dest := destinationWriter{dir: tmpDest, stdout: ios.ContentOut}

    // Malicious asset name crafted to escape tmpDest
    maliciousName := "../" + filepath.Base(outsideDir) + "/evil.sh"

    err := dest.Copy(maliciousName, strings.NewReader("attacker payload"))
    require.NoError(t, err) // currently succeeds -- demonstrates the bug

    escapedPath := filepath.Join(outsideDir, "evil.sh")
    _, statErr := os.Stat(escapedPath)
    require.NoError(t, statErr, "file was written outside destination directory")
}
```
Expected (fixed) behavior: `dest.Copy` (or `downloadAsset`) should return an error rejecting the traversal, and no file should be created outside `tmpDest`. An equivalent end-to-end test can stub `shared.FetchRelease` via `httpmock` to return a release asset JSON with `"name": "../../evil.sh"` and assert that `downloadRun` errors out or that no file appears outside `opts.Destination`.

func (w destinationWriter) Copy(name string, r io.Reader) (copyErr error) {
	fp := w.makePath(name)
	if fp == "-" {
		if w.allowEscapes {
			_, copyErr = io.Copy(w.stdout, r)
			return
		}
		copyErr = iostreams.CopyGuardedContent(w.stdout, r, w.isTTY)
		if binErr, ok := errors.AsType[iostreams.BinaryTerminalError](copyErr); ok {
			copyErr = fmt.Errorf("%w; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway", binErr)
		} else if errors.Is(copyErr, iostreams.ErrEscapeSequence) {
			copyErr = errors.New("the asset contains terminal escape sequences; use `--output` to save it to a file, or pass --allow-escape-sequences to output it anyway")
		}
		return
	}
	if copyErr = w.check(fp); copyErr != nil {
		return
	}

	if dir := filepath.Dir(fp); dir != "." {
		if copyErr = os.MkdirAll(dir, 0755); copyErr != nil {
			return
		}
	}

	var f *os.File
	if f, copyErr = os.OpenFile(fp, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644); copyErr != nil {
		return
	}

	defer func() {
		if err := f.Close(); copyErr == nil && err != nil {
			copyErr = err
		}
	}()

	_, copyErr = io.Copy(f, r)
	return
}
