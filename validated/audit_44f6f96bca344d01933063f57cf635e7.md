### Title
Unchecked share-index multiplication can permanently freeze a lending market - (File: common/src/rates/simulate.rs)

### Summary

An unprivileged borrower can create market conditions where ordinary interest accrual causes `scaled_amount * index` to exceed `i128::MAX` before the configured index ceiling is reached. Once that state is committed, every subsequent market operation accrues first and deterministically reverts, permanently blocking repayments, withdrawals, liquidations, and further index updates absent an upgrade.

### Finding Description

The controller exposes the necessary unprivileged `supply` and `borrow` paths, while `repay`, `withdraw`, and `liquidate` remain available only if pool synchronization succeeds. [1](#0-0) [2](#0-1) 

Pool mutation helpers call `interest::global_sync` before executing the requested operation. [3](#0-2)  `global_sync` then applies one or more accrual chunks and commits the resulting indexes and revenue shares. [4](#0-3) 

During each accrual step, the code first unscales the stored scaled debt and supply using their current indexes. [5](#0-4)  It subsequently grows the borrow index and applies the nominal `MAX_BORROW_INDEX_RAY` bound, but that bound only constrains the index itself and does not ensure that `borrowed * borrow_index` or `supplied * supply_index` fits in `i128`. [6](#0-5) [7](#0-6) 

An accrual can therefore successfully commit an index for which the stored scaled balances can no longer be safely unscaled. On the next call, `accrue_step` panics while evaluating `scaled_to_original` before the index ceiling can engage. [5](#0-4)  Because the failing synchronization precedes debt reduction, neither repayment nor withdrawal can restore a safe state. [8](#0-7) 

The repository’s long-horizon integration test demonstrates this exact failure: after repeated accruals, `update_indexes` reverts with `MATH_OVERFLOW`, and subsequent `withdraw` and `repay` calls hit the same failure while the borrow index remains below its nominal cap. [9](#0-8) 

### Impact Explanation

This is a permanent market-level denial of service and freezing of user funds. Suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot reduce the unsafe debt because all of those paths need to accrue the already-overflowing market state first. [8](#0-7) [10](#0-9) 

The failure affects more than the borrower that created the position: the market’s aggregate `borrowed` and `supplied` values are used during accrual, so all suppliers and borrowers in that hub-asset market are blocked. [11](#0-10) 

### Likelihood Explanation

No oracle manipulation, privileged execution, leaked key, or malformed token is required. A borrower only needs sufficient collateral and a market whose configured debt limits and utilization policy permit pushing the scaled debt high enough for index growth to reach the share-aware overflow threshold. [12](#0-11) [13](#0-12) 

The likelihood is configuration- and balance-dependent rather than an immediate one-transaction attack. The demonstrated scenario uses a large 18-decimal market at high utilization, after which normal accrual crosses the value ceiling while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [14](#0-13) 

### Recommendation

Apply a share-aware bound in addition to the fixed index ceilings before committing a new index:

```rust
let max_safe_borrow_index = min(
    MAX_BORROW_INDEX_RAY,
    i128::MAX / borrowed.raw(),
);
let max_safe_supply_index = min(
    MAX_SUPPLY_INDEX_RAY,
    i128::MAX / supplied.raw(),
);
```

The accrual step should clamp the new indexes to these bounds or use wider/intermediate-safe `mul_div` arithmetic so utilization and accrued interest can be computed without materializing overflowing RAY products. [13](#0-12) 

Before committing an accrual, explicitly prove that `scaled_to_original(borrowed, new_borrow_index)` and `scaled_to_original(supplied, new_supply_index)` remain representable. A regression test should assert that after reaching the bound, `update_indexes`, `repay`, `withdraw`, and liquidation remain executable rather than reverting during synchronization. [15](#0-14) 

### Proof of Concept

The following distilled scenario uses ordinary controller operations after a victim supplies liquidity and the attacker supplies sufficient collateral to borrow the market to high utilization:

```rust
let principal = 1_000_000_000 * 10i128.pow(18);
let debt = principal * 98 / 100;

// Victim liquidity in the debt market.
t.supply_raw(BOB, "BIG18", principal);

// Attacker collateral and borrow through normal controller paths.
t.supply_raw(ALICE, "COL", required_collateral);
t.borrow_raw(ALICE, "BIG18", debt);

// Advance ledger time and accrue until the stored scaled value can no
// longer be unscaled on the next synchronization.
loop {
    t.advance_time(YEAR_SECS);
    if t.try_update_indexes_for(&["BIG18"]).is_err() {
        break;
    }
}

// The committed state is now permanently unusable: even debt reduction
// and supplier exit must accrue first.
assert_contract_error(
    t.try_repay(ALICE, "BIG18", 1.0),
    errors::MATH_OVERFLOW,
);
assert_contract_error(
    t.try_withdraw_raw(BOB, "BIG18", 1),
    errors::MATH_OVERFLOW,
);
```

The corresponding checked-in test uses the same sequence and confirms that the borrow index never reaches `MAX_BORROW_INDEX_RAY` before both repayment and withdrawal fail with `MATH_OVERFLOW`. [14](#0-13)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }

    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"

    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
```
