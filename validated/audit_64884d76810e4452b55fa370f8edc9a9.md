### Title
Division-by-Zero Panic in `consolidatedNode.Split` When Both CN and CL Staking Amounts Are Zero — (`kaiax/staking/staking_info.go`)

### Summary

`consolidatedNode.Split()` divides by `totalAmount = StakingAmount + CLStakingAmount` without a zero-guard. When both fields round to zero (each is stored in KAIA units, truncated from kei), Go's `big.Int.Div` panics at runtime. This panic propagates through the deferred-reward path (`specWithProposerAndFunds` / `specWithProposerAndFundsFlex` → `getDeferredRewardFullKore` / `getDeferredRewardFullFlex` → `FinalizeState`), crashing any node that finalizes such a block.

### Finding Description

`consolidatedNode.Split` is the function that proportionally divides a reward amount between a validator's CN staking contract and its CL pool (KIP-226, Prague hardfork):

```go
// kaiax/staking/staking_info.go:169-187
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    ...
}
``` [1](#0-0) 

Both `StakingAmount` and `CLStakingInfo.CLStakingAmount` are stored in **KAIA units** (truncated from kei by dividing by `params.KAIA = 10^18`):

```go
// kaiax/staking/impl/getter.go:287,299
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64(),
``` [2](#0-1) 

If a validator's CN staking contract holds fewer than `10^18` kei (1 KAIA) **and** the CL pool also holds fewer than `10^18` kei, both truncate to `0`, making `totalAmount = 0`.

`Split` is called unconditionally for the block proposer in both `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` whenever `cn.CLStakingInfo != nil`:

```go
// kaiax/reward/impl/getter.go:583 (specWithProposerAndFundsFlex)
cnAmount, clAmount := cn.Split(proposer)
``` [3](#0-2) 

```go
// kaiax/reward/impl/getter.go:633 (specWithProposerAndFunds)
cnAmount, clAmount := cn.Split(proposer)
``` [4](#0-3) 

There is **no zero-guard** before the division in either call site, unlike the staking-reward distribution paths (`assignStakingRewards`, `assignStakingRewardsFlex`) which gate entry on `cn.StakingAmount >= minStake`:

```go
// kaiax/reward/impl/getter.go:438
if cn.StakingAmount < minStake {
    continue
}
``` [5](#0-4) 

The proposer path has no equivalent guard.

### Impact Explanation

Go's `big.Int.Div` panics on a zero divisor. The panic propagates unrecovered through `getDeferredRewardFullKore` / `getDeferredRewardFullFlex` → `getDeferredRewardFull` → `GetDeferredReward` → `FinalizeState`. Every node that processes the block containing this proposer crashes. Because `FinalizeState` runs on all validating nodes, a single such block can halt the chain.

The corrupted value is the KAIA reward distribution: the proposer's reward is never credited to either the CN reward address or the CL pool address, and the block cannot be finalized.

### Likelihood Explanation

The trigger requires three simultaneous conditions after the Prague hardfork:

1. A validator is registered in both the AddressBook and the CLRegistry.
2. Both the CN staking contract balance and the CL pool balance are below 1 KAIA (10^18 kei) at the staking snapshot block, causing both to truncate to 0.
3. That validator is selected as a block proposer.

Condition 3 is reachable: `generateProposerListWeighted` assigns a minimum weight of 1 to every qualified validator regardless of staking amount, so a zero-staked validator can be selected as proposer:

```go
// kaiax/valset/impl/getter_proposers.go:241-244
weight := uint64(math.Round(stakingAmounts[addr] * 100 / totalStakes))
if weight <= 0 {
    weight = 1
}
``` [6](#0-5) 

The staking info test suite explicitly includes a node with `StakingAmount = 0` paired with a non-nil `CLStakingInfo`, confirming the data model permits this state:

```go
// kaiax/staking/staking_info_test.go:177
{[]common.Address{n4}, []common.Address{s4}, r4, a0, &CLStakingInfo{n4, clPool2, clStakingAmount2}},
``` [7](#0-6) 

### Recommendation

Add a zero-guard in `consolidatedNode.Split` before dividing:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }

    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount := new(big.Int).Add(cnAmountBig, clAmountBig)

    // Guard: if both amounts are zero, assign everything to CN (no CL share).
    if totalAmount.Sign() == 0 {
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
```

This mirrors the fix pattern from the external report: when the reference quantity is zero, clamp the derived value rather than dividing by it.

### Proof of Concept

1. Deploy a Prague-hardfork chain.
2. Register a validator in the AddressBook with a CN staking contract holding < 1 KAIA (e.g., 1 kei). The parsed `StakingAmount` truncates to 0.
3. Register the same validator's node ID in the CLRegistry with a CL pool holding < 1 KAIA. The parsed `CLStakingAmount` truncates to 0.
4. Wait for the validator to be selected as a block proposer (guaranteed eventually since minimum weight = 1).
5. Observe that `FinalizeState` panics with a division-by-zero in `consolidatedNode.Split`, crashing all nodes that attempt to finalize the block.
