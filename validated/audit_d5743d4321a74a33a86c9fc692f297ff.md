### Title
Attacker can indefinitely stall bad-debt socialization by draining collateral in dust-sized partial liquidations, leaving other suppliers exposed to uncollectible debt - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`liquidate()` only triggers `socialize-debt-asset` (the write-down that removes uncollectible debt and marks the loss against the vault's liquidity index) when the computed `no-collateral-left` flag is `true`. That flag requires the borrower's collateral balance for the liquidated asset to be reduced to **exactly zero** in this call (`is-eq coll-removed u0`). Any unprivileged caller invoking `liquidate()` with a small `debt-amount` can leave a residual, non-zero collateral balance on purpose, which permanently prevents `no-collateral-left` from becoming true and therefore prevents socialization of the borrower's other outstanding debt. This is structurally the same bug class as the referenced report: a shared aggregate operation ("hedge"/"socialize bad debt") is gated on an exact-zero/exact-state check that any third-party caller can repeatedly avoid by triggering the code path with a partial, dust-sized operation, blocking the necessary aggregate step for as long as the attacker keeps repeating the pattern.

### Finding Description
In `liquidate()`, after the debt/collateral is repaid and removed, the contract computes: [1](#0-0) 

`no-collateral-left` is only `true` when `coll-removed` (the *remaining* balance in that collateral asset after this call) is exactly `u0`, and either this was the borrower's only collateral asset, or the other collateral asset(s) cannot cover any more debt (`other-debt-repayable` is `u0`). Only when `no-collateral-left` is `true` does the contract socialize bad debt across **all** of the borrower's remaining debt entries: [2](#0-1) 

`debt-amount` is fully attacker-controlled (any liquidator/unprivileged caller supplies it), and the only floor is `> u0` (`ERR-ZERO-LIQUIDATION-AMOUNTS`). This means any caller can perform a liquidation sized to leave exactly `1` unit of collateral remaining rather than draining it to `0`, so `coll-removed` is never `u0` and `no-collateral-left` never fires — the borrower's other outstanding debt entries are never passed into `socialize-debt-asset`, and the corresponding vault's `lindex`/`total-borrowed` are never written down: [3](#0-2) 

The protocol's own comment on `liquidate-multi` acknowledges this exact risk class ("Prevents front-running attacks that prevent bad debt socialization"), but that mitigation only protects multiple *simultaneous* liquidations bundled in one call — it does nothing to stop a caller from repeatedly invoking single-position `liquidate()` across separate transactions/blocks with dust-sized `debt-amount` values, always leaving a non-zero remainder: [4](#0-3) 

### Impact Explanation
Victim: all depositors/suppliers of the debt-asset vault(s) backing the borrower's uncollectible debt (a shared party distinct from the attacker/caller).
Shared state: the vault's `principal-scaled` / `total-borrowed` / `lindex`, and the borrower's obligation registry in `market-vault.clar`, all of which are written only through the gated `no-collateral-left` branch.

- Without the attacker's dust-liquidation pattern: once a position's collateral is fully exhausted, `socialize-debt-asset` immediately marks the uncollectible debt and writes down `lindex`, so the loss is recognized promptly and fairly distributed across all current suppliers.
- With the attacker repeatedly leaving a non-zero remainder: the write-down never fires. The borrower's uncollectible debt keeps accruing interest in `total-borrowed`/`index` as if it were good debt, inflating the vault's `total-assets`/exchange rate. Depositors who redeem while this phantom accrual persists exit at an inflated share price, shifting the eventual loss (once socialization finally occurs) onto later depositors — an unclaimed-yield/temporary-freezing-of-funds harm to a stranger (the socialization victim class), consistent with the "socialization charged to all suppliers" analog category.

### Likelihood Explanation
Any address can call the public `liquidate()` function once a position is liquidatable; no special privilege is required, and the attacker only needs to choose `debt-amount` small enough to leave `coll-final < user-coll-balance` on the collateral asset. This can be repeated indefinitely across blocks at low cost (gas plus the small debt/collateral swapped in each dust liquidation, which the attacker recovers with the liquidation bonus anyway), making the griefing pattern cheap and repeatable, analogous to the counter-based griefing in the referenced report.

### Recommendation
Do not gate bad-debt socialization on an exact `coll-removed == u0` condition. Instead, evaluate whether the borrower's *total* collateral value across all assets is insufficient to cover remaining debt (already partially computed via `other-debt-repayable`) independent of whether the *current* liquidation call happens to zero out the specific collateral asset. Alternatively, allow/require socialization checks to run based on the borrower's post-liquidation total position health, so that a liquidator cannot avoid triggering the check merely by leaving a residual dust balance in one asset.

### Proof of Concept
1. Borrower's position becomes liquidatable with two debt assets (Debt A, Debt B) and one collateral asset.
2. Attacker (any address) calls `liquidate()` requesting a `debt-amount` for Debt A sized so that `coll-final = user-coll-balance - 1` (leaving 1 unit of collateral).
3. `collateral-remove` returns `remaining = 1`, so `coll-removed = 1 != u0` ⇒ `no-collateral-left` is `false` ⇒ `socialize-debt-asset` is never invoked for Debt B, even though the borrower has effectively no meaningful collateral left to cover it.
4. Attacker repeats step 2 in a later block with a new dust `debt-amount`, again leaving `remaining = 1`.
5. Debt B's `total-borrowed`/`index` keep accruing as "good debt" in its vault indefinitely, inflating the vault's exchange rate for depositors who redeem in the interim, while the real loss is only recognized whenever (if ever) the attacker (or someone else) finally fully drains the collateral, at which point remaining depositors absorb the deferred loss.

        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))

        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
