### Title
Tokens sent to the controller by a `flash_position` callback that are neither declared collateral nor refund-listed are permanently locked — ([File: contracts/controller/src/strategies/flash_position.rs](contracts/controller/src/strategies/flash_position.rs))

### Summary
The reference bug is a settlement executed with `address(0)` as owner: funds are committed, but the failure path (`redeemSettlement` / `_retrySettlement`) rejects ownerless settlements, so a delivery failure permanently locks user tokens. The XOXNO Lending analog lives in `flash_position`: the controller settles a callback by measuring its own balance deltas, crediting only declared `collaterals` and refunding only declared `refund_assets`. Any token the receiver delivers to the controller that is in neither list is silently kept — and the controller exposes no sweep, rescue, or re-credit endpoint. Like the ownerless Maia settlement, the tokens are accounted as "settled" but are unreachable by their owner forever.

### Finding Description
`process_flash_position` mints debt, forwards it to a caller-chosen `receiver` contract, then invokes `execute_flash_position` on it (`flash_position.rs:120-143`). The callback settles by pushing tokens to the controller. After the callback returns, settlement is strictly whitelist-based:

- `collect_collateral_deposits` iterates only over the declared `collaterals` list and deposits each positive measured delta (`flash_position.rs:325-352`).
- `refund_listed_assets` iterates only over the declared `refund_assets` list and calls `refund_controller_balance_delta` to push positive deltas back to `caller` (`flash_position.rs:372-384`).

`validate_refund_assets` additionally forbids a refund asset from also being a collateral asset (`flash_position.rs:248-255`), so the two sets are disjoint by construction. There is no third branch: a token transferred to the controller during the callback that is absent from both lists is neither deposited to any account nor refunded. The controller's public surface (`contracts/controller/src/lib.rs`) contains no sweep/rescue/withdrawal of stray controller-held balances — the only sweep found in the repo is on the out-of-scope swap-aggregator. Docs confirm this behavior is intentional-shaped but absolute: "Undeclared callback assets receive neither credit nor refunds. There is no controller sweep endpoint" (`docs/reference/endpoints.md:86`; INV-STRAT-04, `docs/reference/invariants.md:679-689`).

This is reachable by a single unprivileged address: the caller chooses `receiver` (any deployed Wasm contract other than controller/pool, `flash_position.rs:69-84`), provides `data`, and the receiver can push arbitrary extra tokens during the callback — e.g., a receiver that fat-tails an amount, delivers a token the caller forgot to declare, or delivers a collateral token in a hub that later becomes ineligible so it cannot be declared.

### Impact Explanation
Permanent freezing of user funds. Tokens pushed to the controller but not declared remain in contract custody with zero crediting path: no account owns them, no function transfers them out, and subsequent `flash_position` calls cannot claim them — baselines are snapshotted per-call (`snapshot_balances`, `flash_position.rs:125-130`), so even a later caller declaring the same asset would have the stranded amount included in *its* baseline rather than receivable. The funds are as unrecoverable as the ownerless Maia settlement: an admin could conceivably only recover them via upgrade, not through any on-chain path.

### Likelihood Explanation
Medium likelihood, self-inflicted — matching the judged severity of the reference. It requires the receiver (chosen and funded by the caller) to deliver an undeclared asset, or the caller to mis-declare. Realistic triggers: the receiver returns dust of a route intermediate token; the caller omits the debt token from `refund_assets` after an over-minted swap leaves unspent debt tokens on the controller (explicitly documented: refunding the debt token does not repay the minted debt, and undeclared leftover debt stays locked, `docs/reference/invariants.md:685-689`); or a token delivered in a hub where the asset isn't listed, which `validate_refund_assets` rejects at `require_listed_active_config` (`flash_position.rs:241-247`), meaning the user cannot even declare it for refund.

### Recommendation
Add a recovery path symmetric to the report's mitigation (attach a real owner instead of `address(0)`). Options: (a) auto-refund any positive measured delta on the controller for assets the callback touched, or at minimum for listed assets, using the same snapshot/refund machinery already applied to `refund_assets`; (b) add a permissionless `claim_stranded(caller, asset)` endpoint that lets the account owner/delegate who initiated the locking `flash_position` recover it (requires recording sender attribution, analogous to recording a settlement owner); (c) cheapest: extend `refund_listed_assets` to also sweep the debt asset and any asset in `collaterals`/`refund_assets` unconditionally, and document that undeclared assets are permanently forfeited.

### Proof of Concept
1. Deploy a Wasm flash receiver that, inside `execute_flash_position`, transfers `collateral_amount` of declared collateral USDC to the controller **and** an extra `X` units of a listed token T that the caller does not include in `collaterals` or `refund_assets` (or the leftover unspent debt token with `refund_assets` empty).
2. `caller` invokes `flash_position(caller, 0, spoke_id, Multiply, debt_key, amount, receiver, data, collaterals=[(USDC_key, min)], refund_assets=[])`.
3. Transaction succeeds: collateral deposited, solvency gates pass, `account_id` returned.
4. Observe `token::balance(controller, T)` increased by `X` permanently. Enumerate every controller entrypoint — no call attributes `X` to any account or transfers it back. Calling `flash_position` again with T declared in `refund_assets` fails too: the pre-callback `snapshot_balances` baseline already contains `X`, so `balance_delta_since` yields zero and nothing is refunded (and a third party declaring T would face the same baseline problem — `X` can never be measured as a delta again unless *new* T arrives).

Invariants broken analogously to the report: the controller's token custody exceeds all accounted claims (no supply shares, no revenue, no recorded owner), a permanent custodial surplus that no entrypoint can release.
