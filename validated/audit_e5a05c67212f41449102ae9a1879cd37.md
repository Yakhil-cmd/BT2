### Title
CCMenuUrlController#client mints a stack-unscoped, reusable ApiClient token, granting global stack read access - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`CCMenuUrlController#client` looks up/creates an `ApiClient` keyed only by `(creator, name: 'CCMenu Client')`, never by stack, and never assigns `stack:` on creation, so the resulting token always has `stack_id == nil`. Because `Shipit::Api::BaseController#stacks` treats `stack_id.nil?` as "unscoped" (falls back to `Stack.all`), this "single-stack" CCMenu token is actually a global read token for every stack in the installation, and it is silently reused across every stack the user ever requests a CCMenu URL for.

### Finding Description
Broken binding: expected `token_for(A).stack_id == A.id` and `token_for(A).stack_id != token_for(B).stack_id`; actual is `token_for(A).stack_id == nil == token_for(B).stack_id`.

Code path: `app/controllers/shipit/ccmenu_url_controller.rb:15-18`
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
end
``` [1](#0-0) 

`find_or_create_by!` only matches on `creator` and `name`, so calling `fetch` for stack A then stack B returns the identical `ApiClient` row both times; the `stack` association is never set (`create_with` only sets `permissions`), and `belongs_to :stack, optional: true` allows `stack_id` to remain `nil` permanently. [2](#0-1) 

Root cause / downstream impact: `Shipit::Api::BaseController#stacks` uses `stack_id?` to decide scoping:
```ruby
def stacks
  @stacks ||= current_api_client.stack_id? ? Stack.where(id: current_api_client.stack_id) : Stack.all
end
``` [3](#0-2) 
When `stack_id` is `nil`, this branch returns **all stacks**, not zero stacks — so a nil-scoped token is broader, not narrower. The attacker's request is simply: authenticated Shipit user visits the "CCMenu URL" feature for stack A, copies the URL/token, then later (or an attacker who obtains this token pasted into a public CI dashboard) uses it against `stacks`-scoped endpoints (e.g., `Api::StacksController#index`) to enumerate/read every stack in the instance, not just A.

Existing guards do not prevent this: `require_permission :read, :stack` only checks the client's permission list (`read:stack`), not which stack it applies to [4](#0-3) ; there is no validation forcing `ApiClient#stack` to be present for CCMenu-purpose clients; and `ApiClient` model validations only check `creator`/`name`/`permissions`, not `stack` presence [5](#0-4) .

### Impact Explanation
A leaked CCMenu URL (token) exposes read access to the CCMenu status of every stack in the Shipit instance (via any endpoint gated by `BaseController#stacks`), not just the single repository the user intended to expose on a dashboard. This is a same-tenant/instance-wide blast radius: any of the operator's other stacks' build/deploy status becomes readable through the leaked token. This matches the "High — unauthorized/escalated read of stack state" category since it is a scope-escalation from single-stack to all-stacks read access, not merely metadata leakage.

### Likelihood Explanation
No special privileges are required beyond being a legitimate Shipit user with read access to at least one stack (precondition already satisfied by normal use of the CCMenu URL feature). The bug is deterministic and triggers on the very first call (since `stack_id` is never set), and is 100% repeatable — every user who has ever used the "CCMenu Client" feature has exactly this over-broad token. No GitHub/Shipit secrets are needed to trigger it; only the ordinary UI flow of requesting a CCMenu URL.

### Recommendation
Scope the `ApiClient` lookup/creation to the target stack, e.g. `find_or_create_by!(creator: current_user, name: 'CCMenu Client', stack: stack)` and enforce `stack` presence, so `stack_id` is always set and matches `stacks.from_param!` scoping. Additionally, fix `BaseController#stacks` (or callers) so a nil `stack_id` never implicitly expands to `Stack.all` for tokens that are supposed to be stack-scoped (e.g., require an explicit "global" flag rather than inferring it from `nil`).

### Proof of Concept
```ruby
test "CCMenu client is not shared across stacks and is stack-scoped" do
  user = shipit_users(:walrus)
  stack_a = shipit_stacks(:shipit)
  stack_b = shipit_stacks(:cyclimse)

  sign_in(user)
  get :fetch, params: { stack_id: stack_a.to_param } # CCMenuUrlController
  get :fetch, params: { stack_id: stack_b.to_param }

  clients = ApiClient.where(name: 'CCMenu Client', creator: user)
  assert_equal 1, clients.count # currently 1 (shared) — should be 2 (one per stack)

  client = clients.first
  assert_nil client.stack_id # currently nil — should equal stack_a.id or stack_b.id, never both/nil
end
```
