### Title
Unbounded JSON response body read in `GetCurrentLogin` allows memory-exhaustion DoS from attacker-controlled host - ([File: pkg/cmd/auth/shared/login_flow.go])

### Summary
`GetCurrentLogin` decodes the HTTP response body directly with `json.NewDecoder(res.Body).Decode(&result)` without ever wrapping `res.Body` in an `io.LimitReader` or otherwise bounding its size. A host that the victim points `gh auth login` at (e.g. via `--hostname`, or a spoofed GHES instance) can stream an arbitrarily large or never-terminating JSON body in response to the `UserCurrent` GraphQL query, causing the `gh` process to buffer unbounded memory while decoding.

### Finding Description
In `GetCurrentLogin` [1](#0-0) , the function issues a POST to `apiEndpoint := safeurl.JoinPathWithHostPrefix(ghinstance.GraphQLEndpoint(hostname))` and reads the response via:
```go
decoder := json.NewDecoder(res.Body)
err = decoder.Decode(&result)
```
`res.Body` is a raw `io.ReadCloser` from `http.Client.Do`, and `json.Decoder.Decode` will keep reading from it until a complete JSON value is parsed or an error/EOF occurs. There is no `io.LimitReader`, no `http.MaxBytesReader`, and no size cap anywhere in the repository (confirmed via search — no `LimitReader`/`MaxBytesReader` usage exists in the codebase). A malicious server can send a `Content-Length`-less chunked response containing a very large JSON string for `data.viewer.login` (or simply never terminate the JSON stream while continuously flushing bytes), causing the decoder to keep allocating buffer memory as it scans the token stream.

`hostname` here is attacker-influenceable only insofar as the victim explicitly directs `gh auth login --hostname <attacker-host>` (e.g., targeting what they believe is a GitHub Enterprise Server instance) — this matches the allowed attacker capability "controls responses from a host the victim points gh at." `ghinstance.GraphQLEndpoint` and `safeurl.JoinPathWithHostPrefix` only validate/construct the URL scheme and host prefix; neither imposes a response body size limit, so this defense does not stop the unbounded read.

### Impact Explanation
This is a resource-exhaustion (memory-based) Denial-of-Service on the victim's local `gh` process/machine during the `gh auth login` flow when logging into a host that is attacker-controlled or compromised. It matches GitHub's bounty impact class of "denial of service" via resource exhaustion, though it is scoped to the CLI process running on the victim's machine (crash/OOM of `gh`), not a remote-service DoS.

### Likelihood Explanation
Requires the victim to actively authenticate against an attacker-controlled or attacker-spoofed hostname (e.g., a lookalike or compromised "Enterprise" endpoint) using `gh auth login --hostname`. It does not affect the default `github.com`/`api.github.com` flow. Given that precondition, exploitation is trivial and fully repeatable — a simple malicious HTTP handler streaming an unbounded JSON body is sufficient.

### Recommendation
Wrap `res.Body` in a size-bounded reader before decoding, e.g.:
```go
const maxLoginResponseSize = 1 << 20 // 1MB
decoder := json.NewDecoder(io.LimitReader(res.Body, maxLoginResponseSize))
```
and treat truncation/unexpected-EOF as an error. Consider applying the same pattern to other JSON-decoding call sites that read `res.Body` from GraphQL/REST responses across the codebase, since none currently apply a body size cap.

### Proof of Concept
```go
func TestGetCurrentLogin_UnboundedBody(t *testing.T) {
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        w.WriteHeader(http.StatusOK)
        flusher, _ := w.(http.Flusher)
        io.WriteString(w, `{"data":{"viewer":{"login":"`)
        buf := make([]byte, 1<<20)
        for i := range buf { buf[i] = 'a' }
        for { // stream indefinitely
            w.Write(buf)
            if flusher != nil { flusher.Flush() }
        }
    }))
    defer srv.Close()

    // point ghinstance/hostname resolution at srv.URL host
    // call GetCurrentLogin(httpClient, hostFromTestServer, "token")
    // Expected (desired) behavior: call returns an error quickly (e.g. "response too large")
    // Actual (current) behavior: call blocks and process memory grows unbounded until OOM/killed.
}
```
Assertion for the fix: `GetCurrentLogin` should return an error such as `"response body too large"` once a fixed byte threshold (e.g. 1MB) is exceeded, rather than reading indefinitely.

	}{}

		return "", err
	}

	if err != nil {
		return "", err
	}

	if err != nil {
		return "", err
	}

		return "", api.HandleHTTPError(res)
	}

		return "", err
	}
