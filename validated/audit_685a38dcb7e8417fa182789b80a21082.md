### Title
Stale `account.owner` lets the prior NFT holder retain withdraw/borrow authority after `position_nft.transfer` — (File: contracts/controller/src/account.rs)

### Summary
`require_owner_or_delegate` authorizes against `Account.owner`, a field written once at account creation in `create_account` and never resynced to the position NFT's current owner. Because `position_nft.transfer` is a stock OpenZeppelin `NonFungibleToken` method with no hook back into the controller, transferring an account NFT does not update `account.owner`. The previous owner therefore keeps full owner-or-delegate authority over the account — including `withdraw` and `borrow` — while the new NFT owner is denied those paths. This is the direct analog of the GitLab CVE-2024-8114 class: authority is bound to a stale credential instead of the live token that defines ownership.

### Finding Description
- `create_account_with` stores `Account { owner: owner.clone(), .. }` at mint time [1](#0-0) 
- `require_owner_or_delegate` accepts `caller == owner` where `owner` is the stored `account.owner`, or an entry in `storage::get_delegates(account_id, owner)` keyed under that same stale address [2](#0-1) 
- `load_or_create_account` applies this guard for `Migrate` and `Multiply` guards [3](#0-2) , and `require_owner_or_delegate` / `require_account_owner` are the gates used by `borrow`, `withdraw`, `swap_debt`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`, and `flash_position` per the permissionless-entrypoints analysis [4](#0-3) 
- By contrast, `require_account_owner` reads the live NFT owner via `storage::account_owner` [5](#0-4) , so two different definitions of "owner" coexist in the same contract.
- The NFT is stock OZ enumerable; `transfer`/`transfer_from` only call `from.require_auth()` inside the NFT contract and emit no callback to the controller [6](#0-5) . Nothing in `account.rs` writes `account.owner` after creation.

The result: after `position_nft.transfer(token_id = account_id)` to a buyer/victim, `account.owner` still equals the seller. `is_owner_or_delegate` returns `true` for the seller, so `withdraw(caller = seller, account_id, ...)` and `borrow` pass authorization and drain collateral / create debt against an account the seller no longer owns. Delegates the seller granted also remain active (`get_delegates` is keyed by the stale `owner`), compounding the exposure.

### Impact Explanation
Theft of user funds: any account whose NFT is transferred (OTC sale, marketplace trade, gift, or a phished `approve` + `transfer_from`) remains fully drainable by the prior owner, who can withdraw all supply positions and borrow up to the account's thresholds, delivering the proceeds to themselves via the `to`/`receiver` arguments. The new owner paid for an NFT that conveys no exclusive control.

### Likelihood Explanation
Requires only that an NFT change hands — a supported, advertised operation. The attacker needs no privileges beyond having once owned the account. One caveat I could not fully verify within the available tools: whether any code path resyncs `account.owner` on transfer or whether `withdraw`/`borrow` additionally call `require_account_owner` (the live-NFT check). If `get_account` or a position-flow entrypoint re-derives ownership from `account_owner`, the stored-field divergence may be narrower than described; however nothing in `account.rs` or the storage layer read performs such a resync, and the existence of two distinct owner definitions strongly suggests the divergence is real.

### Recommendation
Derive the owner in `is_owner_or_delegate`/`require_owner_or_delegate` from `storage::account_owner(account_id)` (the live NFT owner) rather than the stored `Account.owner` field, or remove `Account.owner` entirely and key `get_delegates` under the current NFT owner on each lookup. Alternatively, have the controller reject or hook NFT transfers, though that conflicts with stock OZ semantics.

### Proof of Concept
1. Alice calls `supply(caller=alice, account_id=0, ...)` → account `id` minted, `account.owner = alice`.
2. Alice calls `position_nft.transfer(alice → bob, id)`. `account.owner` remains `alice`.
3. Alice calls `withdraw(caller=alice, account_id=id, ...)` → `require_owner_or_delegate` sees `caller == account.owner` and passes; collateral is sent to Alice's chosen receiver despite Bob owning the NFT.
4. Symmetrically, `bob` calling `withdraw` fails `require_owner_or_delegate` (`bob != account.owner`, no delegate), locking the rightful owner out of owner-gated flows.

pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}

/// Requires the owner or a registered, active manager delegated by that owner.
pub(crate) fn require_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) {
    if is_owner_or_delegate(env, account_id, caller, owner) {
        return;
    }
    panic_with_error!(env, GenericError::NotAuthorized);
}
