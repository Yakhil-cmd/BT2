### Title
Accrual overflow permanently freezes a market: `borrowed × borrow_index` exceeds `i128` before the borrow-index cap can engage — (File: common/src/rates/simulate.rs)

### Summary
The bug class behind CVE-2021-46539 is a crash (SEGV) weaponized as Denial of Service. The analog in XOXNO Lending is a permanent, unrecoverable arithmetic panic in interest accrual. Every mutating and most read entrypoints accrue first via `interest::global_sync` → `accrue_step`, which computes `scaled_to_original(borrowed, borrow_index)` — a `borrowed * borrow_index / RAY` multiply that panics with `MathOverflow` once the product leaves `i128`. `update_borrow_index` caps the *index* at `MAX_BORROW_INDEX_RAY` (10^36), but the cap only bounds the index; the *value* overflow on `borrowed × index` can be reached first on a large market, and once reached there is no path back: accrual panics forever, so no verb touching that market (supply, borrow, withdraw, repay, liquidate, seize, claim_revenue) can ever execute again. The repo's own harness test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates exactly this and notes "the index cap did not engage before the value overflow ... the market is frozen: no repay, no withdraw, no liquidation." ### Finding Description
`accrue_step` in `common/src/rates/simulate.rs` begins by unscaling the scaled debt:

```rust
let borrowed_original = scaled_to_original(env, borrowed, borrow_index);
```

`scaled_to_original` is `scaled.mul(env, index)` → `mul_div_half_up`, which panics with `GenericError::MathOverflow` when `borrowed * borrow_index` exceeds `i128::MAX` (`common/src/math/fp_core.rs:108-118`). The index itself is safe — `update_borrow_index` clamps to `MAX_BORROW_INDEX_RAY` *after* multiplying — but nothing bounds the product of scaled debt and index. For a market whose scaled `borrowed` is large enough, `borrowed × MAX_BORROW_INDEX_RAY` overflows, and the panic actually fires at an index far below the cap because accrual re-reads the product at the top of *every* step, including steps where the index no longer grows.

Compounding the problem, `global_sync` in `contracts/pool/src/interest.rs:20-33` runs this accrual at the head of every pool mutation (`Cache::load` → `interest::global_sync` → mutate, per `contracts/pool/README.md:159-168`), and controller verbs route through the same pool calls. Once the product overflows, the panic is state-dependent and permanent — no user or admin call can lower `borrowed` or the index without first passing accrual, which is the thing that panics. `apply_bad_debt_to_supply_index` only touches the supply index and is also unreachable for the same reason. ### Impact Explanation
Permanent freezing of all funds in the affected market: every supplier's deposit and every borrower's collateral-seizable debt becomes unreachable. `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `seize_positions`, `claim_revenue`, and even `update_indexes` all revert on `MathOverflow` forever. This is a protocol-level liveness failure, not a fail-closed rejection of a bad input — the state itself is poisoned and no input exists that unpoisons it. The accepted-impact class is "permanent freezing of funds." [6](#0-5) 

### Likelihood Explanation
An unprivileged attacker needs to push a market's scaled debt close to the overflow point and keep utilization high so the borrow index keeps growing. Concretely (per the harness test): list or use an 18-decimal hub asset, supply ~10^9 whole tokens' worth, borrow to ~98% utilization (requires collateral in a second market, which the attacker also supplies), then let the steep-segment borrow rate compound. The test reaches the cliff within 40 years at the XLM-style curve; with `max_borrow_rate` near the 200% cap the index ceiling math shows ~12 yearly chunks to the cap, and the value cliff arrives earlier. The capital requirement is large but the attack is fully permissionless — `supply`, `borrow`, and `update_indexes` are all open entrypoints — and importantly, the condition can also arise *organically* on any high-decimal, high-utilization market, after which the freeze is irreversible regardless of who triggered it. The cost is capital, not exploitation skill, and a griefer can also simply supply large liquidity to a borrowed market to push `borrowed` over the cliff. This warrants Medium severity: high impact, non-trivial but achievable cost. [7](#0-6) 

### Recommendation
Make accrual saturate instead of panic when the unscaled debt value leaves `i128`:

- In `accrue_step`, replace the panicking `scaled_to_original` for `borrowed`/`supplied` with a saturating variant (`mul_div_floor_saturating` already exists in `common/src/math/fp_core.rs:180`) so utilization and interest computation clamp at `i128::MAX` rather than trap.
- Additionally, clamp `borrowed * new_borrow_index` inside `calculate_supplier_rewards` (`common/src/rates/index.rs:80-83`) with the saturating path so interest accrual degrades to zero at the representable ceiling instead of reverting.
- Alternatively/additionally, enforce a per-market scaled-debt ceiling at `borrow` time such that `borrowed_scaled × MAX_BORROW_INDEX_RAY` always fits `i128` — this makes the overflow state unreachable and is the cleaner invariant, complementing the existing `UtilizationAboveMax` and cap checks.

### Proof of Concept
The repository already contains a working demonstration. In `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:321-360`:

```rust
let principal = BILLION * 10i128.pow(18);      // ~1e9 whole tokens of an 18-dec asset
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);            // ~98% utilization
// advance time year by year; try_update_indexes_for eventually returns
// Error(Contract, MATH_OVERFLOW) inside scaled_to_original
assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

Both assertions pass: withdraw and repay revert permanently once `borrowed_scaled × borrow_index > i128::MAX`, with `borrow_index < MAX_BORROW_INDEX_RAY` — proving the index cap does not protect the value product. An attacker reaches this state using only the permissionless `supply`, `borrow`, and `update_indexes` entrypoints. [8](#0-7)

pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}
