The reported bug is a UUPS "uninitialized implementation" issue specific to Solidity's proxy/implementation separation: an implementation contract deployed behind a proxy has its own storage and its own `initializer` state that, if left uncalled, lets any caller become "admin" and then `delegatecall` into a `selfdestruct`. This requires the specific EVM primitives of separate proxy/implementation contracts, `delegatecall`, and `SELFDESTRUCT` combined with a missing constructor guard.

Polkadot SDK's FRAME pallets have no analogous structure: a pallet's logic is compiled directly into the runtime binary, not deployed as a separately-initializable "implementation" contract behind a proxy. Runtime code changes go through `frame_system::Pallet::set_code` / `authorize_upgrade` + `apply_authorized_upgrade`, which are `Root`-only (or explicitly authorized-hash-gated for the two-phase path) rather than callable by an arbitrary uninitialized "admin" [1](#0-0) [2](#0-1) . There is no unauthenticated "initialize" entry point that lets an attacker seize an admin role over runtime code.

The closest EVM-analog primitive that does exist in this codebase is `pallet-revive`'s Solidity-compatibility layer, which implements real `SELFDESTRUCT`/`terminate` semantics for EVM contracts running on-chain (with EIP-6780 same-tx semantics, delegate-call restrictions, and delayed destruction) [3](#0-2) [4](#0-3) . However, `terminate` there operates on the contract's own account/frame state — it is not an "implementation contract shared by many proxies" pattern, and initialization/admin-setting is a property of the user-deployed Solidity contract's own constructor logic, not something core `pallet-revive` or FRAME infrastructure fails to guard. `pallet-contracts`/`pallet-revive` also explicitly gate `delegate_call` and `terminate` (e.g. `PrecompileDelegateDenied`, `TerminatedInConstructor` checks) [5](#0-4) .

Since the underlying root cause (an unguarded, callable-by-anyone `initializer` on a shared implementation contract that can then be upgraded/delegatecalled into a `selfdestruct`) has no structural equivalent in FRAME's pallet/runtime-upgrade model — which is privileged-origin-gated rather than proxy/implementation-based — there is no demonstrable Polkadot SDK analog to this finding.

/// Implements the SELFDESTRUCT instruction.
///
/// Halt execution and register account for later deletion.
pub fn selfdestruct<'ext, E: Ext>(interpreter: &mut Interpreter<'ext, E>) -> ControlFlow<Halt> {
	if interpreter.ext.is_read_only() {
		return ControlFlow::Break(Error::<E::T>::StateChangeDenied.into());
	}
	let [beneficiary] = interpreter.stack.popn()?;
	let charged = interpreter.ext.charge_or_halt(RuntimeCosts::Terminate { code_removed: true })?;
	let dispatch_result = interpreter.ext.terminate_if_same_tx(&beneficiary.into_address());

	match dispatch_result {
		Ok(code_removed) => {
			// halt execution on successful selfdestruct
			if matches!(code_removed, crate::CodeRemoved::No) {
				let actual_cost = RuntimeCosts::Terminate { code_removed: false };
				interpreter
					.ext
					.adjust_gas(charged, <RuntimeCosts as Token<E::T>>::weight(&actual_cost));
			}
			ControlFlow::Break(Halt::Return(Vec::default()))
		},
		Err(e) => {
			log::debug!(target: LOG_TARGET, "Selfdestruct failed: {:?}", e);
			ControlFlow::Break(Halt::Err(e))
		},
	}
}

	fn terminate_caller(&mut self, beneficiary: &H160) -> Result<(), DispatchError> {
		ensure!(self.top_frame().delegate.is_none(), Error::<T>::PrecompileDelegateDenied);

		// EIP-7702: delegated EOAs cannot be destroyed via the system precompile.
		ensure!(

			Error::<T>::CannotTerminateDelegatedAccount,
		);

		let trie_id = info.trie_id.clone();
		let code_hash = info.code_hash;
		let beneficiary = T::AddressMapper::to_account_id(beneficiary);
