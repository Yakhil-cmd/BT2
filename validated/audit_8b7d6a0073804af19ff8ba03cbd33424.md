## Title
Multi-organization webhook signature bypass allows forging events for stacks owned by other organizations - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
The bug-class hint concerns a value that is checked against one piece of state but then used to act on a different, unverified piece of state (an "authorized X vs. acted-on Y" mismatch). In Shipit's multi-GitHub-app deployment, the field used to *select which secret verifies* a webhook (`repository.owner.login` / `organization.login`) is not the same field used to *select which repository/stack the webhook acts on* (`repository.full_name`). When any configured GitHub organization has no `webhook_secret` (a supported, documented configuration), this breaks the binding: `organization authenticated == repository acted upon`.

### Finding Description
`WebhooksController#verify_signature` picks the GitHub App/secret to validate the HMAC signature based on `repository_owner`, which is read straight from the untrusted JSON body (`repository.owner.login`, falling back to `organization.login`): [1](#0-0) [2](#0-1) 

`Shipit.github(organization:)` resolves this attacker-supplied name to a per-organization config (case-insensitively), and `GitHubApp#verify_webhook_signature` **unconditionally returns `true` whenever that organization's `webhook_secret` is blank**: [3](#0-2) [4](#0-3) 

This is not a theoretical config path: Shipit's own multi-app secrets fixture shows organizations configured with `webhook_secret: # nil`: [5](#0-4) 

Once signature verification is bypassed this way, `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` runs the handlers, and **every handler resolves the target repository/stack from a completely different JSON key, `repository.full_name`**, with no cross-check against `repository.owner.login`: [6](#0-5) [7](#0-6) [8](#0-7) 

Since the entire request body is attacker-supplied when no secret enforces integrity, an attacker can set `repository.owner.login`/`organization.login` to an org with no `webhook_secret` while setting `repository.full_name` to `"other-org/other-repo"` belonging to a *different*, secret-protected organization also configured on the same Shipit instance. The equality the system relies on — "the organization whose secret authenticated this request" == "the repository this request is allowed to mutate" — never holds, because nothing ties `repository.owner.login` to `repository.full_name`.

### Impact Explanation
With this mismatch, an unauthenticated attacker can forge arbitrary webhook events (`push`, `status`, `pull_request`, `commit_status`, etc.) for any repository/stack hosted under any other organization on the same Shipit instance, as long as at least one configured organization lacks a `webhook_secret`. This enables cross-repository writes: e.g. forging `status`/`commit_status` payloads to mark arbitrary commits as CI-green (satisfying `deployable?`/`StatusChecker`) or forging `push` events to force `GithubSyncJob` to resync a branch head, potentially feeding an unauthorized/malicious revision into continuous-deployment stacks, or archiving/unarchiving/merging review-stack pull requests belonging to unrelated repositories. This meets the High-severity bar ("escalation... unauthorized deploy").

### Likelihood Explanation
Requires only that the Shipit deployment operates in multi-organization mode (`secrets.github` keyed by org) with at least one organization configured without a `webhook_secret` — a configuration explicitly present in the engine's own multi-app test fixtures, indicating it is a realistically supported setup rather than a misconfiguration unique to a single deployer. No credentials, tokens, or GitHub access are required — a bare unauthenticated POST to `/webhooks`.

### Recommendation
Require every configured GitHub organization to define a non-blank `webhook_secret` (fail closed rather than `return true unless webhook_secret`), and additionally verify that `repository.owner.login` (or `organization.login`) matches the owner segment of `repository.full_name` before dispatching to handlers, so the organization that authenticated the request is cryptographically and logically tied to the repository the request is permitted to affect.

### Proof of Concept
1. Configure Shipit with two organizations: `OrgA` (no `webhook_secret`) and `OrgB` (has `webhook_secret`, hosts the target stack `OrgB/victim-repo`).
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": { "full_name": "OrgB/victim-repo", "owner": { "login": "OrgA" } }
}
```
3. `verify_signature` computes `repository_owner` = `"OrgA"`, looks up `OrgA`'s `GitHubApp`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` regardless of the (missing/arbitrary) `X-Hub-Signature` header.
4. `PushHandler` resolves the target stack via `payload.dig('repository','full_name')` = `"OrgB/victim-repo"`, and calls `stack.sync_github(expected_head_sha: params.after)` on a stack that belongs to `OrgB`, whose secret was never checked. [8](#0-7)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```
