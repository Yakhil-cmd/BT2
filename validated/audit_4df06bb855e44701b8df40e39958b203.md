### Title
Interest accrual permanently freezes an oversized market after `scaled_to_original` overflows `i128` - ([File: common/src/rates/simulate.rs](common/src/rates/simulate.rs))

### Summary

Medium severity. A market with sufficiently large scaled debt can reach a point where `borrowed * borrow_index / RAY` exceeds `i128::MAX`; because every market mutation accrues interest before acting, the resulting `MathOverflow` permanently prevents repayment, withdrawal, liquidation, bad-debt cleanup, recapitalization, and further index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description

`accrue_step` begins by converting the market's total scaled debt into its current RAY-denominated value through `scaled_to_original`. [3](#0-2)  `scaled_to_original` delegates to `Ray::mul`, which uses `mul_div_half_up`. [4](#0-3)  Although `mul_div_half_up` uses an exact `I256` intermediate, it converts the final quotient back to `i128` and panics with `MathOverflow` when the result is unrepresentable. [5](#0-4) [6](#0-5) 

The borrow-index ceiling does not prevent this condition because it is applied inside `update_borrow_index`, after the already-overflowing pre-accrual debt valuation has been evaluated. [7](#0-6) [8](#0-7)  Once `borrowed * borrow_index / RAY` is larger than `i128::MAX`, the next chunk cannot be evaluated and `last_timestamp` is never advanced. [9](#0-8) 

All ordinary pool mutation legs call `synced_market`, which loads the market and invokes `global_sync` before applying the operation. [2](#0-1)  For example, withdrawal calls `ops::load_leg`, which reaches `synced_market` before resolving or burning the position. [10](#0-9)  Repayment follows the same accrual-first path before burning debt. [11](#0-10)  The permissionless controller `update_indexes` entrypoint also forwards to pool accrual and therefore hits the same panic. [12](#0-11) [13](#0-12) 

### Impact Explanation

This causes permanent freezing of all funds and debt accounting for the affected hub asset: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot seize collateral, bad debt cannot be cleaned, and recapitalization cannot proceed because those paths accrue the market first. [2](#0-1) [13](#0-12)  The repository's directed regression test demonstrates that after the overflow, both `withdraw` and `repay` fail with `MATH_OVERFLOW`. [14](#0-13) 

### Likelihood Explanation

Exploitation requires an existing market whose caps admit a very large balance and sustained high utilization long enough for the index to grow past the representable market-value bound. [15](#0-14)  Those conditions are economically demanding and configuration-dependent, but they do not require a privileged action once such a market is admitted. [16](#0-15)  The permissionless `update_indexes` call provides a direct trigger for the first failing accrual. [12](#0-11) [17](#0-16) 

### Recommendation

Do not materialize market totals as an `i128` RAY value during accrual. Keep debt and supply totals in a wider internal representation, or combine index multiplication and token-decimal downscaling into a single `I256` multiply-divide whose final native-token result is the only value narrowed to `i128`. [18](#0-17)  Alternatively, enforce a market-wide admission bound based on the maximum representable accrued value before `MAX_BORROW_INDEX_RAY` is reached, and make the invariant explicit in supply and borrow validation. [8](#0-7)  The regression test at `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs` should remain as the boundary case, with the expected outcome changed from a persistent `MathOverflow` to a successfully accrued, repayable, withdrawable, and liquidatable market. [19](#0-18) 

### Proof of Concept

The repository already contains a deterministic reproduction. It creates an 18-decimal market, supplies `1_000_000_000 * 10^18` base units, borrows 98% of that principal against separate collateral, advances ledger time yearly, and calls the permissionless `update_indexes` path until accrual returns `MATH_OVERFLOW`. [20](#0-19)  The test then verifies that the borrow-index cap did not engage and that both withdrawal and repayment subsequently fail with the same overflow. [21](#0-20) 

```text
supply(caller, account_id, spoke_id, [(BIG18, 1_000_000_000 * 10^18)])
supply(collateral_owner, debt_account, spoke_id, [(COL, sufficient_collateral)])
borrow(collateral_owner, debt_account, [(BIG18, 980_000_000 * 10^18)], to)
repeat while borrow_index < MAX_BORROW_INDEX_RAY:
    advance ledger time
    update_indexes(caller, [BIG18])
withdraw(...)   // reverts MathOverflow
repay(...)      // reverts MathOverflow
liquidate(...)  // accrual-first pool leg also reverts
```

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
