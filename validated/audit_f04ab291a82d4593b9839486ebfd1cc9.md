The `hub/get_arbstore_url` mechanism resolves an arbitrary `arbiter_address` (a value fully attacker/peer-controlled in a private payment contract flow) into a URL that is then dereferenced with an unvalidated `http.get`/`http.request` call, with no scheme/host allow-list or private-IP filtering.

### Title
Server-Side Request Forgery in Arbiter Contract HTTP Requests via Attacker-Controlled ArbStore URL - (File: arbiter_contract.js, arbiters.js)

### Summary
A private-payment counterparty can propose an arbiter contract naming an arbitrary `arbiter_address` [1](#0-0) . When the local wallet later interacts with that contract (e.g. `getInfo`, `getArbstoreInfo`, `appeal`, `getAppealFee`), the code resolves the arbiter's URL via `hub/get_arbstore_url`/`hub/get_arbstore_url_by_address` and then issues an outbound HTTP(S) request directly to whatever URL is returned, without validating that it is not a local/internal network target [2](#0-1) [3](#0-2) .

### Finding Description
`arbiters.getInfo` and `arbiters.getArbstoreInfo` fetch the ArbStore URL for a given `arbiter_address` and immediately call `requestInfoFromArbStore(url + '/api/...')`, which performs `http.get(url, ...)` with no host/IP validation [4](#0-3) . Similarly, `arbiter_contract.appeal` and `getAppealFee` fetch the URL through the hub and pass it straight into `httpRequest`, which builds request params via `url.parse(host)` and performs `http.request(...)` [5](#0-4) . The `arbiter_address` that drives this URL lookup originates from the arbiter contract object created by `createAndSend` or received via the `store` function from an untrusted peer (`bFromCosigner`/`arbiter_contract_offer` device message), and is inserted into `wallet_arbiter_contracts` without validating that it corresponds to a vetted, trusted arbiter [6](#0-5) . Because the hub is only asked to resolve whatever address is supplied, and no code path verifies the returned URL's host is a public, non-local address, a party that controls (or successfully registers as) an "arbiter" for a chosen address can point the resolved ArbStore URL at an internal address (e.g., `127.0.0.1`, cloud metadata IP, internal service), causing the victim's wallet to make outbound requests to that internal target when handling the arbiter contract.

### Impact Explanation
This matches the CWE-918 SSRF bug class from the report: unvalidated resolution and dereferencing of an externally-supplied endpoint URL. The victim wallet (acting as payer/payee in a private arbiter contract) is induced to send HTTP GET/POST requests — potentially carrying contract metadata and pairing information (`device.getOrGeneratePermanentPairingInfo`, contract details) in the POST body for `appeal` — to an attacker-chosen internal endpoint, which can lead to information disclosure to/about internal network services reachable from the wallet's host.

### Likelihood Explanation
Reachable by any private-payment counterparty who proposes/accepts an arbiter contract and can influence which `arbiter_address` is used, plus registration of a corresponding ArbStore URL with the hub for that address; the local wallet automatically performs the HTTP calls once the contract enters `appeal`, `getAppealFee`, or `getInfo`/`getArbstoreInfo` flows, requiring only normal user interaction with the contract (no privileged access needed).

### Recommendation
Before dereferencing any ArbStore URL obtained via `hub/get_arbstore_url*`, validate that the resolved hostname/IP is a public address (reject loopback, link-local, private RFC1918/RFC4193, and metadata service ranges), enforce HTTPS with a fixed/allow-listed port, and re-validate after DNS resolution (not just on the string) to avoid TOCTOU/DNS-rebinding bypasses, in both `arbiters.js` (`requestInfoFromArbStore`) and `arbiter_contract.js` (`httpRequest`).

### Proof of Concept
1. Attacker (or malicious arbiter) registers with the hub via `hub/get_arbstore_url` resolution logic to return `http://127.0.0.1:<internal-port>` (or another internal address) for their `arbiter_address`.
2. Attacker proposes an arbiter contract to the victim naming this `arbiter_address`, via `createAndSend`/the `arbiter_contract_offer` device message, which is persisted via `store` [6](#0-5) .
3. Victim later calls `getInfo`/`getArbstoreInfo` (e.g., to display arbiter details) or attempts `appeal`/`getAppealFee` on the contract.
4. The wallet resolves the arbiter address to the attacker-supplied internal URL and issues `http.get`/`http.request` directly to it [7](#0-6) [8](#0-7) , causing an SSRF against the victim's internal network with no destination validation.

function httpRequest(host, path, data, cb) {
	var reqParams = Object.assign(url.parse(host),
		{
			path: path,
			method: "POST",
			headers: {
				"Content-Type": "application/json",
				"Content-Length": (new TextEncoder().encode(data)).length
			}
		}
	);
	var req = http.request(
		reqParams,
		function(resp){
			var data = "";
			resp.on("data", function(chunk){
				data += chunk;
			});
			resp.on("end", function(){
				try {
					data = JSON.parse(data);
					if (data.error) {
						return cb(data.error);
					}
					cb(null, data);
				} catch (e) {
					cb(e);
				}
			});
		}).on("error", cb);
	req.write(data);
	req.end();
}

function getInfo(address, cb) {
	cb = cb || function() {};
	db.query("SELECT device_pub_key, real_name FROM wallet_arbiters WHERE arbiter_address=?", [address], function(rows){
		if (rows.length && rows[0].real_name) { // request again if no real name
			cb(null, rows[0]);
		} else {
			device.requestFromHub("hub/get_arbstore_url", address, function(err, url){
				if (err) {
					return cb(err);
				}
				if (!validationUtils.isNonemptyString(url))
					return cb("invalid url received from hub");
				requestInfoFromArbStore(url+'/api/arbiter/'+address, function(err, info){
					if (err) {
						return cb(err);
					}
					if (!validationUtils.isNonemptyObject(info))
						return cb("invalid arbiter info received from arbstore");
					db.query("REPLACE INTO wallet_arbiters (arbiter_address, device_pub_key, real_name) VALUES (?, ?, ?)", [address, info.device_pub_key, info.real_name], function() {cb(null, info);});
				});
			});
		}
	});
}

function requestInfoFromArbStore(url, cb){
	http.get(url, function(resp){
		var data = '';
		resp.on('data', function(chunk){
			data += chunk;
		});
		resp.on('end', function(){
			try {
				cb(null, JSON.parse(data));
			} catch(ex) {
				cb(ex);
			}
		});
	}).on("error", cb);
}
