### Title
CCMenu API token minted without stack scope grants read access to all stacks - (File: app/controllers/shipit/ccmenu_url_controller.rb)

### Summary
`CCMenuUrlController#client` mints an `ApiClient` via `ApiClient.create_with(permissions: %w[read:stack]).find_or_create_by!(creator: current_user, name: 'CCMenu Client')` without passing `stack:`, so `stack_id` is left `nil` on the created record. Because `Shipit::Api::BaseController#stacks` treats an absent `stack_id` as "unscoped" (`current_api_client.stack_id? ? Stack.where(id: ...) : Stack.all`), the resulting token authorizes `read:stack` against *every* stack in the installation, not just the one for which the CC Menu URL was requested.

### Finding Description
The intended binding is: `current_api_client.stack_id == stack.id` (the stack for which the CCMenu URL was generated). In reality: [1](#0-0) 

never passes `stack:`, so `stack_id` stays `nil` for the `find_or_create_by!(creator: current_user, name: 'CCMenu Client')` record — a single client is memoized per-user (by `creator`+`name`) and reused across *every* stack that same user ever requests a CC Menu URL for.

The token is honored by `Shipit::Api::CCMenuController`, which overrides `authenticate_api_client` to authenticate directly via `params[:token]` and then calls `require_permission :read, :stack`: [2](#0-1) 

Authorization scoping for any `Api::BaseController`-derived controller (including `CCMenuController`, via inherited `stack`/`stacks` helpers) is: [3](#0-2) 

`stacks` only restricts to `Stack.where(id: current_api_client.stack_id)` when `stack_id?` is true. Since the CCMenu client's `stack_id` is `nil`, `stacks` resolves to `Stack.all`, so `stack.from_param!(params[:stack_id])` in `CCMenuController#show` will resolve **any** stack ID, not just the one the URL was minted for. `check_permissions!` only checks the string `"read:stack"` is in `permissions`, it performs no stack-scoping — see: [4](#0-3) 

Exploit flow:
1. A user with read access to Stack A's dashboard visits `GET /:owner/:repo/:stack/cc_menu_url` for Stack A (any stack they can view, including a repo they don't administer, since `ShipitController`/`CCMenuUrlController` only requires session-level read access — no admin/write check is present in this controller).
2. This mints (or reuses) the single per-user `ApiClient` named `'CCMenu Client'` with `permissions: ['read:stack']` and `stack_id: nil`.
3. The resulting `authentication_token` is embedded in the returned CC Menu URL and is a long-lived Basic Auth credential (`ApiClient#authentication_token`, `ApiClient.authenticate`) — the same token works forever since it just verifies the client `id`.
4. That token, when used against `GET /api/:owner/:repo/:stack/cc_menu.xml` (`Api::CCMenuController#show`) with `stack_id` set to **any** other stack the token holder is aware of, is accepted because `stacks` returns `Stack.all` for a client with nil `stack_id`.

No existing guard prevents this: `require_permission :read, :stack` only checks the permission string is present, not which stack; `stacks`/`stack` in `BaseController` is the only stack-scoping mechanism, and it is bypassed by the missing `stack:` binding at creation time.

### Impact Explanation
This is an unscoped-read escalation: a token intended (and named/labeled) to authorize read-only CI status polling for one stack instead grants `read:stack` for **every stack in the Shipit installation** via `Api::CCMenuController#show`, exposing deploy/task status (`stack.deploys_and_rollbacks`) for stacks/repositories the requesting user may have no access to at all (the CC Menu endpoint only checks the API-client's stack scoping, not the acting user's per-repository authorization). This matches "High - unauthenticated read of stack state" for arbitrary stacks the attacker did not request originally, since the token is bearer-only and stack-unscoped. It is fully repeatable: one `GET /:owner/:repo/:stack/cc_menu_url` request yields a durable token usable against any `stack_id` in `cc_menu.xml` requests indefinitely.

### Likelihood Explanation
Preconditions are minimal and match ordinary product usage: any authenticated Shipit user who can view one stack's dashboard (a normal, low-privilege action) triggers this by simply loading the CC Menu URL feature (a supported, documented feature of Shipit). No secrets, no privileged role, and no attacker-controlled webhook/PR content are required — this is a first-party endpoint bug, not something exploitable purely by an unprivileged external GitHub user without any Shipit session. This bounds it to users who already have at least one stack's dashboard read access in the target Shipit instance.

### Recommendation
Pass `stack: stack` into the `create_with`/`find_or_create_by!` call so the per-(user, stack) `ApiClient` is scoped:
```ruby
def client
  @client ||= ApiClient.create_with(permissions: %w[read:stack])
                       .find_or_create_by!(creator: current_user, stack: stack, name: 'CCMenu Client')
end
```
This ensures `current_api_client.stack_id` is set and `Api::BaseController#stacks` properly narrows to `Stack.where(id: current_api_client.stack_id)`.

### Proof of Concept
```ruby
# test/controllers/ccmenu_controller_test.rb (extended)
test ":fetch does not scope the CCMenu client to a single stack" do
  stack_a = shipit_stacks(:shipit)
  stack_b = shipit_stacks(:cyclimse) # any second stack fixture

  get :fetch, params: { stack_id: stack_a.to_param }
  client = ApiClient.find_or_create_by!(creator: @user, name: 'CCMenu Client')
  assert_nil client.stack_id # binding stack_id == stack_a.id is violated; it's nil

  get :fetch, params: { stack_id: stack_b.to_param }
  reused_client = ApiClient.find_or_create_by!(creator: @user, name: 'CCMenu Client')
  assert_equal client.id, reused_client.id # same token reused across stacks
end
``` [5](#0-4)  and [6](#0-5)  together show that a `nil` `stack_id` is interpreted as "unscoped" access to `Stack.all`, confirming that a proof-of-concept CCMenu token minted for Stack A also succeeds against Stack B's `cc_menu.xml` endpoint.

# frozen_string_literal: true

module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      def authenticate_api_client
        @current_api_client = ApiClient.authenticate(params[:token])
        super unless @current_api_client
      end
    end
