## Title
`initialize_with_permission` allows setting `pool_creator` to an arbitrary/unowned address (including the zero-address), permanently freezing all future creator fees - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`InitializeWithPermission::creator` is declared as an `UncheckedAccount` with no signer requirement and no `address`/non-zero constraint, unlike the equivalent `Initialize::creator`, which is a `Signer`. [1](#0-0) [2](#0-1)  This value is stored verbatim into `pool_state.pool_creator` at pool creation. [3](#0-2) [4](#0-3) 

### Finding Description
`pool_creator` is later used as the sole recipient authority for accumulated creator fees. `collect_creator_fee` requires the caller to be a `Signer` whose key equals `pool_state.pool_creator`, and `collect_creator_fee_permissionless` lets *anyone* trigger the payout but still routes the funds to an ATA whose `authority` is `pool_state.pool_creator`. [5](#0-4) [6](#0-5) [7](#0-6) 

Because `creator` in `InitializeWithPermission` is neither a signer nor constrained to be non-zero/valid, the account that is permitted to call `initialize_with_permission` (a permissioned pool creator, gated by the `Permission` PDA seeded on `payer`) can pass `Pubkey::default()` (or any other address nobody controls) as `creator`. [8](#0-7)  This is analogous to the reported Taurus issue: a fee-recipient field is never validated to be non-zero/controllable before funds are routed to it, so protocol fees end up unclaimable.

Every swap accrues a `creator_fee` component into `pool_state.creator_fees_token_0/1` via `update_fees`, regardless of who the recorded creator is. [9](#0-8)  Once `pool_creator` is `address(0)` (or any address whose private key nobody holds), those accumulated fees can never be spent by `collect_creator_fee` (impossible to produce a valid signature for `Pubkey::default()`), and `collect_creator_fee_permissionless` will simply keep forwarding token to a token account whose owner nobody can control, permanently locking the funds. [10](#0-9) 

### Impact Explanation
This is a permanent freezing of protocol/creator funds: creator fees accrued from every swap against the pool become unrecoverable because the designated “owner” of those fees is an address with no corresponding signer. This matches the Medium-severity class of the original report (fees routed to an unusable/zero address), applied here to the `pool_creator` fee-recipient field rather than a fee-splitter address.

### Likelihood Explanation
Any account holding a valid `Permission` PDA (granted for permissioned pool creation) can call `initialize_with_permission` in a single transaction and set `creator` to an arbitrary unchecked pubkey, since there is no `Signer`, `address =`, or non-default constraint on that field. This requires no elevated/admin privilege beyond the pool-creation permission already contemplated as a normal, reachable actor in this analysis (the pool creator role), making the path realistically reachable.

### Recommendation
Add a constraint on `InitializeWithPermission::creator`, e.g. `require_keys_neq!(creator.key(), Pubkey::default())`, and/or require it to be a `Signer` (mirroring `Initialize::creator`) so the recorded `pool_creator` is guaranteed to be a controllable address before it is persisted into `pool_state.pool_creator`.

### Proof of Concept
1. Attacker (or any account already granted a `Permission` PDA) calls `initialize_with_permission`, supplying `creator = Pubkey::default()` (or any address they do not control) while being the legitimate `payer`/signer for pool creation. [11](#0-10) 
2. `pool_state.initialize(...)` stores this value into `pool_creator` with no validation. [3](#0-2) 
3. Users swap against the pool; each swap accrues `creator_fee` into `pool_state.creator_fees_token_0/1`. [9](#0-8) 
4. `collect_creator_fee` can never be called successfully (no one can sign as `Pubkey::default()`), and `collect_creator_fee_permissionless` will forward the tokens into an ATA owned by `Pubkey::default()`, permanently freezing all accumulated creator fees. [12](#0-11)

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;
```
