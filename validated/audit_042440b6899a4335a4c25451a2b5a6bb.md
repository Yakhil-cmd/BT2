### Title
Webhook signature verification is keyed by `repository.owner.login` while the acted-upon repository is resolved from the unverified `repository.full_name` field, allowing cross-organization forged webhooks - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
In a multi-organization Shipit deployment, `WebhooksController#verify_signature` selects the GitHub App/secret to verify a webhook's signature against using `repository.owner.login` (or `organization.login`) from the JSON body, but every event handler resolves the `Stack`/`Repository` it actually writes to from the separate `repository.full_name` field of the same, unauthenticated body. Because verification for an organization configured with no `webhook_secret` trivially succeeds for *any* payload, an attacker who can deliver an HTTP POST naming that organization as the "authenticating" owner but naming a *different*, secret-protected organization's repo in `full_name` can make Shipit act (sync commits, archive/unarchive review stacks, capture PR labels, update commit statuses, etc.) on that other organization's stacks without ever presenting a valid signature for it.

### Finding Description
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) computes `repository_owner` from the request body itself: `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` (line 59-62), and uses it to fetch the corresponding `GitHubApp` via `Shipit.github(organization: repository_owner)`.
- `Shipit.github` / `github_app_config` (`lib/shipit.rb:170-200`) look up a per-organization config keyed by that same attacker-supplied name, each with its own independently-configured (possibly blank) `webhook_secret` — this multi-org, per-org-secret schema is a first-class, documented feature (`test/dummy/config/secrets_double_github_app.yml`).
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`) returns `true` unconditionally when that organization's `webhook_secret` is blank — i.e., verification is a no-op for orgs without a configured secret.
- After "verification" passes, `WebhooksController#create` dispatches the **entire, unauthenticated body** to handlers (`app/controllers/shipit/webhooks_controller.rb:10-15`).
- Every handler ignores `repository.owner.login` entirely and instead resolves the write target from `repository.full_name`, e.g. `Handler#repository_name` (`app/models/shipit/webhooks/handlers/handler.rb:36-38`), `PullRequest::OpenedHandler#repository` (`app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb:50-53`), `ClosedHandler`, `LabelCapturingHandler`, etc., all via `Repository.from_github_repo_name(params.repository.full_name)` (`app/models/shipit/repository.rb:53-56`).

The equality the design implicitly relies on — `organization used to verify signature == owner of repository.full_name that gets mutated` — is never enforced. The two are read from independent JSON keys in the same untrusted body, so they can be set to different values.

### Impact Explanation
This is a cross-repository/cross-organization write: a request that is only "authenticated" (trivially, due to a blank secret) for organization A can cause writes against organization B's stacks — triggering `GithubSyncJob`, archiving/unarchiving review stacks, capturing PR labels, updating commit statuses, and creating memberships/teams/users — none of which required a valid signature for organization B. This matches the "cross-repository writes" / "unauthorized deploy" impact class, since `PushHandler#process` (`app/models/shipit/webhooks/handlers/push_handler.rb:12-17`) drives `stack.sync_github`, which can advance a stack's deployable commit state and enable an unauthorized deploy/rollback pipeline trigger for a repository the attacker does not control.

### Likelihood Explanation
Requires only that the Shipit instance be configured for more than one GitHub organization (a supported, documented configuration) with at least one organization lacking a `webhook_secret` (also an explicitly supported, non-error configuration per `docs/setup.md` and `verify_webhook_signature`'s `return true unless webhook_secret`). No GitHub credentials, session, or `ApiClient` token are needed — only the ability to send an HTTP POST to the public `/webhooks` endpoint with `X-Github-Event` set and a crafted JSON body.

### Recommendation
Bind the verified identity to the acted-upon repository: after selecting the `GitHubApp`/secret via `repository_owner`, require that `repository.full_name`'s owner segment equals `repository_owner` (or `organization.login`) before dispatching to handlers, and reject (422) on mismatch. Additionally, consider disallowing/warn on organizations configured with a blank `webhook_secret` in multi-organization mode, since a blank secret degrades verification to a no-op for that organization.

### Proof of Concept
1. Configure Shipit with two GitHub orgs, e.g. `OrgA` (no `webhook_secret`) and `OrgB` (real `webhook_secret`, `OrgB/protected-repo` has a `Stack` configured), mirroring `test/dummy/config/secrets_double_github_app.yml`.
2. POST to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "OrgA" },
    "full_name": "OrgB/protected-repo"
  }
}
```
No `X-Hub-Signature` header (or an arbitrary one) is required.
3. `verify_signature` resolves `repository_owner = "OrgA"`, fetches `OrgA`'s `GitHubApp`, and `verify_webhook_signature` returns `true` immediately because `OrgA.webhook_secret` is blank.
4. `PushHandler#process` (via `Handler#repository_name` reading `full_name`) resolves stacks under `OrgB/protected-repo` and invokes `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")`, mutating `OrgB`'s stack state without ever presenting a signature valid for `OrgB`.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

module Shipit
  module Webhooks
    module Handlers
      class PushHandler < Handler
        params do
          requires :ref
          requires :after
        end

        def process
          stacks
            .not_archived
            .where(branch:)
            .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
        end

        private

        def branch
          params.ref.gsub('refs/heads/', '')
        end
      end
    end
  end
