Confirmed: `Repository.from_github_repo_name` looks up purely by `owner`/`name` parsed from `params.repository.full_name` [1](#0-0) , with no relationship whatsoever to the org used for signature verification.

### Title
Cross-org webhook signature confusion allows attacker-controlled `repository.full_name` to write arbitrary labels onto a victim repository's `PullRequest` - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/label_capturing_handler.rb`)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to validate a webhook against using `repository_owner`, which is read from `params.dig('repository','owner','login')`, while every downstream handler (including `LabelCapturingHandler`) resolves the actual `Shipit::Repository`/`Stack` to mutate using the independent field `params.repository.full_name`. Because these two payload fields are never cross-validated, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org has no configured `webhook_secret`, an attacker who controls a repository in a secret-less org can send a forged webhook whose `repository.full_name` names a victim repository/stack, causing `capture_labels` to call `pull_request.update!(labels: params.pull_request.labels.map(&:name))` against the victim's `PullRequest` row.

### Finding Description
The broken binding: the org whose secret verified the request bytes (`repository_owner` = `params.repository.owner.login`) must equal the org that owns the repository being mutated (derived from `params.repository.full_name`). It does not — they are independent, attacker-controlled JSON fields in the same payload.

Path:
1. `WebhooksController#verify_signature` computes `github_app = Shipit.github(organization: repository_owner)` and calls `github_app.verify_webhook_signature(signature, raw_post)` [2](#0-1) . `repository_owner` is parsed from `params.dig('repository', 'owner', 'login')` [3](#0-2) .
2. `GitHubApp#verify_webhook_signature` returns `true` immediately if `webhook_secret` is blank for that org's config [4](#0-3) . In a multi-org deployment (`config.github` keyed by org name, as documented) some orgs can legitimately have no `webhook_secret` configured, e.g. per the shipped example config [5](#0-4) .
3. If verification passes, `Shipit::Webhooks.for_event('pull_request').each { |handler| handler.call(params) }` dispatches the **entire raw JSON body**, including `repository.full_name`, to handlers such as `LabelCapturingHandler` [6](#0-5) .
4. `LabelCapturingHandler#repository` resolves the target using `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [7](#0-6) , which is a plain DB lookup by `owner`/`name` columns parsed from that string, independent of which org's secret verified the request [1](#0-0) .
5. `capture_labels` then runs `pull_request.update!(labels: params.pull_request.labels.map(&:name))` on the real, victim `Stack`'s `PullRequest` if an open review-stack PR with the matching number exists [8](#0-7) .

Attacker request: a `pull_request` webhook body with `X-Github-Event: pull_request`, `repository.owner.login` = an org configured in Shipit with no `webhook_secret` (attacker knows/controls this org, e.g. their own GitHub org added to Shipit's multi-org config, or any org that an operator forgot to set a secret for), `repository.full_name` = `"victim-org/victim-repo"`, `pull_request.number` = an existing open review-stack PR number on the victim stack, `pull_request.labels` = attacker-chosen strings, and any `X-Hub-Signature` value (or omit — irrelevant since `webhook_secret` is blank for the impersonated org).

Why existing guards fail: `verify_signature` only proves the bytes were signed (or that no secret was required) by *some* org named in the payload's `repository.owner.login` — it never proves that this org is the *actual owner* of the repository subsequently acted upon in `repository.full_name`. `drop_unhandled_event` and the `ExplicitParameters` schema (`params do ... end` in `LabelCapturingHandler`) only validate the shape/types of fields, not cross-field consistency between `repository.owner.login` and `repository.full_name`. There is no model-level or handler-level check tying the two together.

### Impact Explanation
An attacker can overwrite the `labels` column of an arbitrary victim `Shipit::PullRequest` record for any repository already onboarded in Shipit, as long as: (a) that PR is open and mapped to an active review stack, and (b) at least one org in Shipit's multi-org `github` config has no `webhook_secret` set. This is a genuine cross-repository/cross-tenant write of attacker-controlled data (Rule: "a payload for one repository mutating another's stack"), matching **Critical** severity. Labels feed into `archive?`/`unarchive?`/`provisioning_label_name` gating logic in the sibling `LabeledHandler` [9](#0-8) , so attacker-controlled label strings could influence archive/unarchive/deploy-gating decisions for a stack the attacker does not own, and are also rendered in the Shipit UI. The attack is repeatable against any onboarded repository/PR number combination and requires no privileges beyond ownership of a repo in a secret-less org (or knowledge that one exists).

### Likelihood Explanation
Requires: (1) Shipit configured with the documented multi-org `github` schema, and (2) at least one configured org with `webhook_secret` blank/unset — a configuration explicitly shown as valid/example in this repo's own docs and secrets templates [10](#0-9) [5](#0-4) . Given that precondition, exploitation cost is a single unauthenticated `POST /webhooks` HTTP request with a crafted JSON body — no GitHub signature needed for the secret-less org, no Shipit session, no API token. It is trivially repeatable and scriptable.

### Recommendation
In `WebhooksController#verify_signature`, after successful signature verification, re-derive the repository owner independently for every event and validate that `params.dig('repository','full_name')`'s owner segment matches `repository_owner` (the value verified against). Alternatively/additionally, in `Shipit::Repository.from_github_repo_name` or in each handler's `repository` method, reject/ignore payloads where the resolved `Repository#owner` does not match the org that was actually used to verify the webhook signature (thread this org through from the controller into the handler dispatch). Also flag as a config anti-pattern (warn/refuse startup) when any org in a multi-org `github` config has no `webhook_secret`, since it silently disables signature verification for that org and, per this finding, for every org's data via the full_name field.

### Proof of Concept
Minitest plan (`test/controllers/webhooks_controller_test.rb` style, illustrative — not to be placed under `test/` per scope, but describing the exact assertions):
1. Configure `Shipit.stubs(:secrets).returns(...)` with two orgs: `"victim-org"` (with `webhook_secret: "victim-secret"`) and `"attacker-org"` (with `webhook_secret: nil`).
2. Create `victim_repo = Shipit::Repository.create!(owner: "victim-org", name: "victim-repo", ...)`, an active (unarchived) `Stack` for it via `OpenedHandler`, producing `stack.pull_request` with `labels == []`.
3. Build a `pull_request` webhook payload with `repository.owner.login = "attacker-org"`, `repository.full_name = "victim-org/victim-repo"`, `pull_request.number` matching the victim stack's PR, `pull_request.labels = [{ "name" => "attacker-controlled-label" }]`, action `"labeled"`.
4. `post :create, headers: { 'X-Github-Event' => 'pull_request', 'X-Hub-Signature' => 'sha1=deadbeef' }, body: payload.to_json` (no valid signature, since `attacker-org` has `webhook_secret: nil`).
5. Assert `response` is not `:unprocessable_entity` (i.e., verification passed).
6. Assert `victim_repo.stacks.last.reload.pull_request.labels == ["attacker-controlled-label"]` — i.e., **the victim's `PullRequest#labels` equals the attacker-chosen array**, proving `Binding: repository_owner_verified == repository.full_name.owner` is violated (`"attacker-org" != "victim-org"` yet the write succeeded).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
