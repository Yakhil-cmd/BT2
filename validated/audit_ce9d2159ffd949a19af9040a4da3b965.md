### Title
Unbounded accrued-debt valuation permanently freezes an oversized market - (File: common/src/rates/index.rs)

### Summary
Pool accrual converts scaled debt into a RAY-denominated value with fallible `i128` multiplication before supplier rewards are calculated. [1](#0-0) [2](#0-1)  Once `borrowed * new_borrow_index / RAY` exceeds `i128::MAX`, accrual panics with `MathOverflow`, even though `update_borrow_index` would otherwise clamp the index itself. [3](#0-2) [4](#0-3) 

### Finding Description
`accrue_step` first unscales the stored debt, updates the borrow index, and then computes old and new aggregate debt values. [1](#0-0)  Both debt calculations use `Ray::mul`, whose result must fit in `i128`; there is no saturation, chunking, or recovery branch when the debt value crosses the representation limit. [4](#0-3) [2](#0-1)  Consequently, the market can reach an irrecoverable arithmetic state before `MAX_BORROW_INDEX_RAY` protects it. [3](#0-2)  A regression test demonstrates that a billion-token, 18-decimal market at 98% utilization reaches this cliff and then fails `update_indexes`, `withdraw`, and `repay` with `MathOverflow`. [5](#0-4) 

### Impact Explanation
This is permanent freezing of funds and protocol insolvency handling failure for the affected market: suppliers cannot withdraw, borrowers cannot repay, and liquidation paths that accrue the market cannot proceed. [6](#0-5)  The permissionless `update_indexes` entrypoint lets any caller synchronize the market and reach the failing accrual state, while `repay`, `withdraw`, and `liquidate` remain publicly reachable subject to their normal authorization. [7](#0-6) [8](#0-7)  Once the stored scaled debt and index combination crosses the representable boundary, subsequent calls repeat the same panic rather than allowing a bounded accrual or debt write-down. [1](#0-0) [9](#0-8) 

### Likelihood Explanation
Likelihood is constrained because the trigger requires an extremely large market and sustained high-utilization accrual, rather than a small malformed amount. [10](#0-9)  However, an attacker does not need to supply the entire vulnerable book: they can wait for an existing large market to approach the boundary and submit only `update_indexes(caller, vec![hub_asset])`. [11](#0-10)  The issue is nevertheless Medium rather than Critical because governance caps and realistic token supply constrain how easily the required state can be reached, and the panic does not directly transfer funds to the attacker. [12](#0-11) 

### Recommendation
Cap the debt-value calculation itself or maintain accrual arithmetic in `I256` until a protocol-defined terminal state can be committed safely. [13](#0-12)  At minimum, cap scaled borrowing so `borrowed * MAX_BORROW_INDEX_RAY / RAY` remains representable, and enforce that bound on both direct borrows and strategy-created debt. [14](#0-13)  Add a regression proving `update_indexes`, repayment, withdrawal, liquidation, bad-debt cleanup, and recapitalization remain callable at the configured maximum debt-value boundary. [6](#0-5) 

### Proof of Concept
1. Create an 18-decimal market with a steep permitted interest curve and sufficient spoke caps, then supply `1_000_000_000 * 10^18` base units. [15](#0-14) 
2. Supply separate collateral and borrow 98% of the market principal. [16](#0-15) 
3. Advance ledger time in yearly steps and call the permissionless controller `update_indexes` for the market. [17](#0-16) [8](#0-7) 
4. The call eventually returns `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`, proving that aggregate debt-value overflow precedes the intended index cap. [18](#0-17) 
5. Subsequent `withdraw` and `repay` calls fail with the same error because both paths load and accrue the market before applying their state changes. [19](#0-18) [20](#0-19)

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
