### Title
Webhook signature verified against `repository.owner.login`'s org while PR handlers act on `repository.full_name`'s repo, enabling cross-tenant review-stack forgery - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`Shipit::WebhooksController#verify_signature` selects the GitHub App/webhook secret to check via `repository_owner`, which is read from `params.dig('repository', 'owner', 'login')`, but the PR handlers that actually mutate state resolve the target repository from the independent `repository.full_name` field via `Repository.from_github_repo_name`. Because these two fields are never cross-checked, and because `GitHubApp#verify_webhook_signature` unconditionally returns `true` when the selected org has no configured `webhook_secret`, an attacker can pick a no-secret org for `owner.login` while pointing `full_name` at a victim's repo, so the PR handler creates/archives a `ReviewStack` for a repository whose organization never authenticated the event.

### Finding Description
The invariant that should hold is:
`org(secret) used in verify_signature == org that owns the repository the handler mutates`, i.e. `repository_owner == Repository.from_github_repo_name(repository.full_name).owner`. This is broken because these two values come from two different, independently attacker-controlled JSON fields in the same payload.

Path:
1. `WebhooksController#create` runs `before_action :verify_signature` [1](#0-0) , which computes `repository_owner` purely from `params.dig('repository', 'owner', 'login')` (or `organization.login`) [2](#0-1) .
2. It fetches `Shipit.github(organization: repository_owner)` and calls `verify_webhook_signature` on that org's `GitHubApp` instance [3](#0-2) .
3. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org has no `webhook_secret` configured: `return true unless webhook_secret` [4](#0-3) . This is documented/expected behavior for orgs without a secret configured (see multi-org example configs with `webhook_secret: # nil` for each org) [5](#0-4) .
4. Once signature verification "passes" (or is bypassed because the chosen org has no secret), `Webhooks.for_event('pull_request')` fans out the *same, unmodified* payload to all PR handlers [6](#0-5) .
5. Handlers ignore `repository.owner.login` entirely and instead resolve the target repository via `Repository.from_github_repo_name(params.repository.full_name)` (e.g. `OpenedHandler#repository`) [7](#0-6) , or via `Handler#stacks` which does the same lookup [8](#0-7) .
6. `ReviewStackAdapter#find_or_create!`/`archive!`/`unarchive!` then create, archive, or unarchive a `ReviewStack` belonging to whatever repository `full_name` names [9](#0-8) .

Exploit: attacker sends `POST /webhooks` with header `X-Github-Event: pull_request`, body `{"action":"synchronize", ..., "repository": {"owner": {"login": "no-secret-org"}, "full_name": "victim-org/victim-repo"}, ...}`. If `no-secret-org` is configured in Shipit with no `webhook_secret` (or Shipit runs single-org mode with no secret set — the common/documented default, see `config/secrets.development.example.yml` showing `webhook_secret: # nil`) [10](#0-9) , signature verification trivially passes for any signature (or absence thereof), yet the handler mutates `victim-org/victim-repo`'s review stack. Existing guards (`drop_unhandled_event`, `ExplicitParameters` schema, model validations) never check that `repository.owner.login` matches the owner implied by `repository.full_name`, so none of them close this gap.

### Impact Explanation
An attacker with no Shipit credentials can forge `pull_request` events (`opened`, `closed`, `labeled`, etc.) that create, archive, or unarchive `ReviewStack` records for a completely different organization's repository, as long as any org configured in Shipit (or the single default org) lacks a `webhook_secret`. This is a cross-tenant state-manipulation primitive: one repository's payload mutates another repository's stack/records, matching the "Critical" category described (payload for one repository mutating another's stack). Repeated requests can spam-create or archive review stacks for the victim repository. Blast radius is bounded to whatever organizations are configured without a webhook secret and reachable from the deployment.

### Likelihood Explanation
Preconditions: Shipit must have at least one configured GitHub org (or the sole/default org) with no `webhook_secret` set — this is the documented default value in example configs and is plausible in real deployments, especially during initial setup or when only some orgs configure secrets in a multi-org setup. No other privileges are required: the attacker just needs to be able to send an HTTP POST to `/webhooks` with an arbitrary JSON body naming any no-secret org as `repository.owner.login` and any target repo as `repository.full_name`. This is trivially repeatable against any tracked repository in Shipit.

### Recommendation
Verify that the organization owning `repository.full_name` (or the resolved `Repository` record's owner) matches `repository_owner` used for signature verification, and reject events where they diverge, before dispatching to handlers. Additionally, consider requiring a `webhook_secret` to be present for all configured orgs (fail closed rather than `return true unless webhook_secret`) or at minimum warn/alert when an org has no secret configured.

### Proof of Concept
Minitest plan (in `test/controllers/webhooks_controller_test.rb` style, no live GitHub):
1. Configure two orgs in test secrets: `no-secret-org` (no `webhook_secret`) and `victim-org` (any secret, or none). Seed a `Repository` for `victim-org/victim-repo` with `review_stacks_enabled: true` and provisioning behavior allowing all.
2. Build a `pull_request` payload: `action: "opened"`, `repository: { owner: { login: "no-secret-org" }, full_name: "victim-org/victim-repo" }`, valid `pull_request`/`sender` sub-objects satisfying `ExplicitParameters`.
3. Set `X-Github-Event: pull_request`; send an arbitrary/garbage `X-Hub-Signature` (or omit it).
4. Assert response is `:ok` (not `422`), proving verification passed for `no-secret-org`.
5. Assert `Shipit::ReviewStack.where(repository: victim_repository, environment: "pr#{number}")` was created — i.e., a record was written for `victim-org/victim-repo` despite the signature only being checked against `no-secret-org`.
6. Equality check to assert violated: `repository_owner` (= `"no-secret-org"`) `!=` owner of `Repository.from_github_repo_name(payload.dig('repository','full_name')).name/owner` (= `"victim-org"`), yet the write still occurred.

          def find_or_create!
            stack || create!
          end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
