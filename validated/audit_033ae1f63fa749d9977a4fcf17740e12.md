### Title
i128 overflow in Ray-value multiplication during interest accrual permanently freezes a saturated market - (File: contracts/pool/src/interest.rs)

### Summary
The bug class of the external report is an integer overflow leading to invalid state access. In XOXNO Lending the analogous primitive is `i128` overflow in the RAY-scaled value computation `scaled * index` performed inside every accrual step. Once `borrowed * borrow_index` (or `supplied * supply_index`) exceeds `i128::MAX`, `Ray::mul` panics with `GenericError::MathOverflow`, and because `global_sync` runs before every state-changing pool verb, the entire market becomes permanently uncallable.

### Finding Description
`contracts/pool/src/interest.rs::accrue_chunk` invokes `accrue_step` (`common/src/rates/index.rs`, `common/src/rates/simulate.rs`), which evaluates `borrowed.mul(env, new_borrow_index)` inside `calculate_supplier_rewards` and `supplied.mul(env, old_index)` inside `update_supply_index` [1](#0-0) . `Ray::mul` widens to `I256` only for the intermediate product; the result must still fit `i128`, otherwise `to_i128` returns `None` and the code panics with `MathOverflow` [2](#0-1) .

The index cap `MAX_BORROW_INDEX_RAY` (10^36, applied in `update_borrow_index`) is intended to bound index growth, but it caps the *index*, not the *product* `borrowed * index`. With a large token book (e.g., a billion-unit 18-decimal market) the scaled `borrowed` is already ~10^35+ raw RAY, so the value overflows at an index far below the cap [3](#0-2) .

Because `global_sync` is invoked at the top of every mutation — supply, borrow, withdraw, repay, liquidate, clean_bad_debt, recapitalize — the panic poisons all entry points simultaneously; even `update_indexes` itself reverts [4](#0-3) . The repo's own harness test demonstrates this end-to-end: after the cliff is reached, `try_update_indexes_for`, `try_withdraw_raw`, and `try_repay` all fail with `MATH_OVERFLOW`, and the comment notes "no repay, no withdraw, no liquidation. The index cap never engages" [5](#0-4) . The same test asserts the bound documented in `docs/reference/formulas.md` is wrong — the cliff arrives earlier than the docs claim.

### Impact Explanation
Permanent freezing of funds for every participant of the affected market. Once the overflow condition is reached, no supplier can withdraw, no borrower can repay or be liquidated, and bad-debt cleanup (`clean_bad_debt`) and `recapitalize` also accrue first and revert. There is no escape hatch because the panic occurs inside accrual before any guard or index-cap correction can run. All supplied tokens in the hub book for that (hub, token) are bricked, and healthy collateral positions routed through that market are frozen with it.

### Likelihood Explanation
Reachable by unprivileged addresses: an attacker supplies a large principal into an 18-decimal market (`supply`), borrows near maximum utilization (`borrow`) to sit on the steep segment of the rate curve, and then only needs to wait while anyone's calls keep accrual progressing toward the cliff. The required scale is large (whale-scale principal and sustained high utilization over years in the tested curve), so likelihood is moderate-low in capital terms but requires no privileged role, no oracle manipulation, and no cooperation — any borrower reaching the same utilization profile triggers it. Once crossed, the state is irreversible since `borrow_index` only grows monotonically.

### Recommendation
Cap the RAY *value* domain, not just the index: in `accrue_step`/`update_borrow_index`, clamp so that `borrowed * borrow_index` and `supplied * supply_index` stay within `i128` (e.g., derive a per-book effective index ceiling `i128::MAX / scaled`, or cap scaled supply/borrow at mint time via supply/borrow caps sized to `i128::MAX / MAX_SUPPLY_INDEX_RAY`). Alternatively, detect the overflow inside `global_sync` and freeze index growth (set index to the last safe value / cap) instead of panicking, so exits remain possible. Align `docs/reference/formulas.md`'s stated bound with the enforced cap.

### Proof of Concept
Already encoded in `tests/test-harness/tests/controller/large_positions_and_long_horizons.rs::a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap`:

1. Create market `BIG18` (18 decimals, XLM rate curve), lift caps.
2. `BOB` supplies `BILLION * 10^18`; `ALICE` supplies `COL` collateral and borrows 98% of `BIG18`.
3. Advance time yearly, calling `update_indexes`. After the index passes ~170x — well below `MAX_BORROW_INDEX_RAY` — `accrue_step` panics with `MATH_OVERFLOW` inside `scaled_to_original`/`Ray::mul`.
4. Subsequent `withdraw(BOB, BIG18, 1)` and `repay(ALICE, BIG18, ...)` both revert with `MATH_OVERFLOW`, confirming all supplier and borrower funds are permanently locked.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
