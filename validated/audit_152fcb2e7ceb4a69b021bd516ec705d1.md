CVE-2020-7922 concerns X.509 certificates generated by the MongoDB Enterprise Kubernetes Operator improperly scoping access, allowing a cluster-privileged attacker to gain unauthorized MongoDB access. The required analog must be a real Polkadot SDK entry point (signed extrinsic, permitted XCM, contract call, or public proof submission) reachable by an unprivileged attacker, exhibiting the same broken-authorization pattern: a certificate/credential issued by the system that fails to properly scope the holder's access.

The only certificate-generation code found in scope is the WebRTC DTLS certificate derivation in `substrate/client/network/src/webrtc.rs`, which deterministically derives a self-signed P-256 certificate from the node's ed25519 identity key purely to bind a `/certhash` to the node's `Multiaddr` for transport identification [1](#0-0) . This certificate does not authenticate a client against a privileged resource, nor does it grant differentiated access scopes the way MongoDB's X.509 auth certificates do — it exists solely so a WebRTC peer can pin the DTLS transport to the known node identity [2](#0-1) . There is no over-broad-permission or improper-scoping analog here: no signed extrinsic, XCM message, or contract call consumes this certificate to grant access to a protected asset or account.

No other certificate/credential-issuance code path (RPC servers, bridges relay client, libp2p noise handshake) exhibits an analogous "operator-issued credential grants improper access scope" pattern reachable by an unprivileged, non-governance actor [3](#0-2) . Since no real FRAME/XCM/contract entry point maps to the CVE's violated invariant (credential-based authorization scope), this does not meet the reporting bar.
