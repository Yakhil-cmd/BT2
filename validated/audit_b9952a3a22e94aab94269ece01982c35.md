### Title
Stale delegate grants reactivate when the position NFT returns to the granting owner, restoring a revoked manager's spending authority - (File: contracts/controller/src/storage/account.rs)

### Summary
The controller's account-authorization model has an analog of the OpenEMR `zhAclCheck` flaw: a delegation "allow" is stored as a `DelegateGrant` stamped with `granted_by`, and authorization is decided purely by whether a matching grant exists — the implicit revocation caused by transferring the position NFT away is never persisted. `get_delegates` filters grants by `grant.granted_by == *owner`, where `owner` is resolved live from the position NFT (`account.rs:176-181`). When the NFT is transferred away and later returns to the original owner, the stale grant still stamped with that owner's address matches again, and the delegate regains full owner-equivalent authority — borrow, withdraw, swap_collateral, swap_debt, repay_debt_with_collateral, multiply — over the account without any new grant.

### Finding Description
`is_owner_or_delegate` (`contracts/controller/src/account.rs:115-127`) admits a caller when the stored `DelegateGrant` for `ControllerKey::Delegates(account_id)` was stamped by the *current* owner. `get_delegates` returns the stored delegate list whenever `grant.granted_by == *owner` (`storage/account.rs:176-181`). Nothing deletes the grant on NFT transfer: `position-nft` has no transfer hook into the controller, and `remove_account_entry` (which clears `Delegates`) only runs when the account becomes empty (`account.rs:159-170`).

The only stale-grant cleanup lives in `remove_delegate` (`storage/account.rs:226-247`): if the stored `granted_by` differs from the caller, it deletes the entry — but only when someone actually calls `remove_delegate`. The doc comment there ("Deletes stale grants ... preventing those grants from reactivating if the NFT returns to their original owner") acknowledges the reactivation hazard, yet the deletion is opt-in. `add_delegate` also does not purge stale grants; it reads `get_delegates(account_id, owner)` which returns an empty list for a mismatched stamp, then `set_delegates` overwrites — but only if the new owner adds a delegate.

Attack path (all in-scope, unprivileged): Alice owns `account_id` and grants delegate `M` (an active position manager) via `controller::add_delegate`. Alice transfers the position NFT to Bob via `position-nft::transfer` — the grant stays in storage, still stamped `granted_by = alice`. Bob (or anyone) transfers the NFT back to Alice. `get_delegates` now matches the stale stamp, so `is_owner_or_delegate(env, account_id, M, alice)` returns true. `M` calls `controller::withdraw` / `controller::borrow` on `account_id`, passing `require_owner_or_delegate`, and drains collateral or draws debt to a recipient it chooses (`to` parameter, subject only to `require_external_recipient`), with solvency re-proven post-hoc — which does not help since `M` controls the destination of withdrawn funds.

### Impact Explanation
Theft of user funds: a previously-revoked delegate silently regains owner-equivalent authority over the victim's account and can withdraw all collateral via `withdraw` or extract value via `borrow`. The intended security property — transferring the position NFT revokes the old owner's grants (asserted in `transfer_revokes_prior_owner_and_delegates` only for the *transferee's* ownership window) — is violated on return of the NFT. Bob, the intermediate holder, cannot strip the stale grant without knowing it exists and calling `remove_delegate`, and has no incentive to protect Alice.

### Likelihood Explanation
Requires: (a) the account had an active delegate grant under owner A, (b) the NFT moves to B and back to A (direct sale-and-return, or OTC trades, or A regaining the NFT through a marketplace purchase of the same token id), and (c) the delegate is still an active registered position manager. All conditions are reachable by ordinary users through in-scope entrypoints; no admin action is needed to trigger it. The window is bounded by the manager remaining active in the position-manager registry, but manager activation is common for delegated strategies (multiply, migrate_from_blend).

### Recommendation
Invalidate delegate grants on ownership change rather than filtering by stamp. Options: have the position-nft `transfer`/`approve` path notify the controller to delete `ControllerKey::Delegates(account_id)`; or store an owner-generation nonce inside `DelegateGrant` that is bumped whenever `account_owner` is observed to differ from `granted_by` (clear the grant lazily on the next `get_account`/`is_owner_or_delegate` call, not just inside `remove_delegate`). At minimum, make `get_delegates` delete a mismatched-stamp entry on first read after an ownership change so the grant cannot later re-match.

### Proof of Concept
1. Alice calls `controller::supply` (`account_id = 0`) creating account `N`, then `controller::add_delegate(caller=alice, account_id=N, delegate=M)` where `M` is an active position manager. Storage now holds `Delegates(N) = DelegateGrant { granted_by: alice, delegates: [M] }`.
2. Alice calls `position-nft::transfer(from=alice, to=bob, token_id=N)`. The grant entry is untouched.
3. Bob calls `position-nft::transfer(from=bob, to=alice, token_id=N)` (or sells it back through any channel). `account_owner(N)` is again `alice`.
4. `get_delegates(env, N, alice)` returns `[M]` because `granted_by == alice` — the stale allow overrides the revocation that step 2 implied.
5. `M` calls `controller::withdraw(caller=M, account_id=N, withdrawals=[(hub_asset, 0 /*all*/)], to=Some(M))`. `require_owner_or_delegate` passes via `is_owner_or_delegate`, and the pool pays out Alice's collateral to `M`.

```rust
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
```

```rust
pub(crate) fn remove_delegate(
    env: &Env,
    account_id: u64,
    owner: &Address,
    delegate: &Address,
) -> bool {
    let key = ControllerKey::Delegates(account_id);
    let Some(grant) = get_user::<DelegateGrant>(env, &key) else {
        return false;
    };
    if grant.granted_by != *owner {
        env.storage().persistent().remove(&key);
        return false;
    }
    let mut delegates = grant.delegates;
    let Some(index) = delegates.first_index_of(delegate) else {
        return false;
    };
    delegates.remove(index);
    set_delegates(env, account_id, owner, &delegates);
    true
}
```

```rust
pub(crate) fn is_owner_or_delegate(
    env: &Env,
    account_id: u64,
    caller: &Address,
    owner: &Address,
) -> bool {
    if caller == owner {
        return true;
    }
    let active_manager =
        storage::get_position_manager(env, caller).is_some_and(|config| config.is_active);
    active_manager && storage::get_delegates(env, account_id, owner).contains(caller)
}
```
