### Title
`initialize_with_permission` accepts an unchecked, unvalidated `creator` account that is never checked against `address(0)`, allowing pool creator fees to be permanently frozen - (File: programs/cp-swap/src/instructions/initialize_with_permission.rs)

### Summary
`InitializeWithPermission::creator` is declared as a plain `UncheckedAccount<'info>` with no signer requirement and no non-zero-address / ownership constraint [1](#0-0) . The `payer` (any unprivileged caller holding a valid `Permission` PDA) fully controls which arbitrary pubkey is written as `pool_creator` into `PoolState`, and the instruction never rejects `Pubkey::default()` (the analog of `address(0)` in this Solana/Anchor codebase).

### Finding Description
This mirrors the Sherlock finding in `ChainlinkAdapterOracle.setTokenRemappings()`, where a value written into on-chain state is validated for `!= address(0)` on one side (`tokens_[idx]`) but not on the mapped-to value (`remappedTokens_[idx]`), enabling a valid entry to be mapped to the zero address with no way to recover it.

Here, the same pattern occurs in `pool_state.initialize(...)`, which stores `ctx.accounts.creator.key()` as `pool_creator` in `PoolState` without any validation [2](#0-1)  and [3](#0-2) . Unlike `Initialize` (used by the standard `initialize` instruction), where `creator` is a `Signer<'info>` and therefore cannot realistically be the zero pubkey (no private key exists for it) [4](#0-3) , `InitializeWithPermission::creator` is only an `UncheckedAccount`, so the `payer` can supply `Pubkey::default()` or any address they don't control as the `creator` account key, and it will be written verbatim into `pool_creator`.

Both fee-collection paths key off `pool_state.pool_creator`:
- `CollectCreatorFee` requires `creator` to be a `Signer` whose key equals `pool_state.pool_creator` [5](#0-4) .
- `CollectCreatorFeePermissionless` allows anyone to trigger the payout, but the destination ATA authority is still forced to equal `pool_state.pool_creator` [6](#0-5)  and [7](#0-6) .

If `pool_creator` is set to `Pubkey::default()`, no one can ever sign as that key, and the permissionless path can still execute (it doesn't require `creator` to sign), but the resulting associated token account is owned by `Pubkey::default()` — an address nobody controls. Any creator fees accrued to `creator_fees_token_0` / `creator_fees_token_1` and swept via `collect_creator_fee_permissionless` [8](#0-7)  would land in tokens accounts that are permanently unrecoverable, since the zero pubkey cannot sign a transaction to move the tokens out again.

### Impact Explanation
This results in permanent freezing of pool creator fee funds accumulated for that pool: any swap that routes `creator_fee_on` fees to that pool will forever be unrecoverable once collected to the zero-authority ATA. This satisfies the "permanent freezing of user/LP funds" criterion for Medium severity. It does not enable theft of other users' principal, but it does destroy value that would otherwise belong to the (attacker-controlled or negligent) pool creator, and more importantly permanently locks fees inside the protocol's accounting once the permissionless collector is invoked.

### Likelihood Explanation
The `initialize_with_permission` instruction is only reachable by accounts holding a valid `Permission` PDA (created via `create_permission_pda`), so it is not fully open to any anonymous caller, unlike plain `initialize`. However, once a caller has permission to create pools, nothing prevents them from setting an unrelated/zero `creator` account by mistake or maliciously (e.g., to intentionally "burn" creator fees or grief future integrations depending on `pool_creator` liveness). Because the check is a single missing `require_keys_neq!(creator.key(), Pubkey::default())`-style validation, exploitation requires no unusual capability beyond calling the already-permissioned instruction with a chosen `creator` account.

### Recommendation
Add an explicit non-default check on the `creator` account in `InitializeWithPermission`, mirroring the fix recommended for `setTokenRemappings`:
```rust
require_keys_neq!(creator.key(), Pubkey::default(), ErrorCode::InvalidAddress);
```
or express it as an Anchor account constraint (`constraint = creator.key() != Pubkey::default()`) directly on the `creator: UncheckedAccount<'info>` field in `programs/cp-swap/src/instructions/initialize_with_permission.rs` before `pool_state.initialize(...)` is called with `ctx.accounts.creator.key()`.

### Proof of Concept
1. Acquire (or be granted) a `Permission` PDA for `payer` via `create_permission_pda`.
2. Call `initialize_with_permission` supplying `creator = Pubkey::default()` (an `UncheckedAccount`, so no signature is required for this field).
3. `pool_state.initialize(...)` stores `pool_creator = Pubkey::default()` [9](#0-8) .
4. Trade against the pool so `creator_fees_token_0/1` accrue (if `enable_creator_fee` is set true, as it is unconditionally for this instruction) [10](#0-9) .
5. Anyone calls `collect_creator_fee_permissionless`, which creates an ATA owned by `Pubkey::default()` and transfers the accrued fees into it [7](#0-6) .
6. The tokens are now held by an account whose authority (`Pubkey::default()`) can never sign a transaction, permanently locking those funds.

```rust
pub fn collect_creator_fee_permissionless(
    ctx: Context<CollectCreatorFeePermissionless>,
) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

```
