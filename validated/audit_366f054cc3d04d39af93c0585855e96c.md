### Title
Permanent KLAY Lock in Service Chain Bridge When `_to` Rejects Native Token Transfer — (File: `contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

When a user bridges KLAY through the Kaia service-chain bridge and the destination address `_to` is a contract that rejects native-token transfers, the `handleKLAYTransfer` call on the destination bridge permanently reverts. Because no cancellation or refund path exists anywhere in the bridge contract suite, the user's KLAY is irreversibly locked in the source bridge.

---

### Finding Description

`handleKLAYTransfer` delivers KLAY to the recipient via a bare low-level call:

```solidity
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [1](#0-0) 

If `_to` is a contract without a `payable` fallback (or one that explicitly reverts on receipt), `ok` is `false` and the entire operator transaction reverts.

On the source chain, the user's KLAY was already committed when `requestKLAYTransfer` was called: the value is held by the bridge contract, a `RequestValueTransfer` event is emitted, and `requestNonce` is incremented. [2](#0-1) 

The Value-Transfer Recovery (VTR) subsystem (`vt_recovery.go`) detects the gap between `requestNonce` and `lowerHandleNonce` and continuously re-submits the same event: [3](#0-2) 

Because `_to` permanently rejects KLAY, every retry reverts. No function in `BridgeTransfer.sol`, `BridgeTransferKLAY.sol`, or `Bridge.sol` provides a `dropMessage`, `cancelRequest`, or user-refund path. [4](#0-3) 

---

### Impact Explanation

The user's KLAY is permanently locked inside the source bridge contract. The locked value is real on-chain KAIA. There is no owner-callable rescue function and no upgrade mechanism in the deployed contracts. The invariant that "every locked asset is either delivered or refundable" is broken.

---

### Likelihood Explanation

Any user who sets `_to` to a contract address that does not accept native tokens (multisig wallets, DAO treasuries, ERC-4337 accounts, or any contract without a `payable` fallback) triggers this condition. This is a realistic user mistake, not a contrived attack. The trigger requires only a standard `requestKLAYTransfer` call — no special privilege.

---

### Recommendation

1. Add a `cancelRequest` / `dropRequest` function callable by the original sender (or by operators after a timeout) that unlocks and returns the KLAY to `_from`.
2. Alternatively, in `handleKLAYTransfer`, replace the hard `require` with a try/catch pattern: if the transfer to `_to` fails, send the KLAY back to `_from` on the source chain (analogous to Scroll's planned refund feature).
3. At minimum, document that `_to` must be a payable address and add an on-chain check (e.g., reject EOA-less contracts at request time, or use a whitelist).

---

### Proof of Concept

1. Alice calls `requestKLAYTransfer(nonPayableContract, 1 ether, "")` on the source bridge.
2. Source bridge holds `1 ether`; `RequestValueTransfer` event is emitted; `requestNonce` increments.
3. Operators observe the event and call `handleKLAYTransfer(..., nonPayableContract, 1 ether, ...)` on the destination bridge.
4. `nonPayableContract.call.value(1 ether)("")` returns `(false, ...)`.
5. `require(ok, "handleKLAYTransfer: transfer failed")` reverts the operator transaction.
6. VTR detects `requestNonce > lowerHandleNonce`, re-queues the event, and retries — every attempt reverts identically.
7. Alice's `1 ether` is permanently locked in the source bridge with no recovery path. [5](#0-4) [6](#0-5)

func (vtr *valueTransferRecovery) recoverPendingEvents() error {
	defer func() {
		vtr.childEvents = []IRequestValueTransferEvent{}
		vtr.parentEvents = []IRequestValueTransferEvent{}
	}()

	if len(vtr.childEvents) > 0 {
		logger.Warn("VT Recovery : Child -> Parent Chain", "cBridge", vtr.cBridgeInfo.address.String(), "events", len(vtr.childEvents))
	}

	vtRequestEventMeter.Mark(int64(len(vtr.childEvents)))
	vtRecoveredRequestEventMeter.Mark(int64(len(vtr.childEvents)))

	events := make([]IRequestValueTransferEvent, len(vtr.childEvents))
	for i, event := range vtr.childEvents {
		events[i] = event
	}
	vtr.pBridgeInfo.AddRequestValueTransferEvents(events)

	if len(vtr.parentEvents) > 0 {
		logger.Warn("VT Recovery : Parent -> Child Chain", "pBridge", vtr.pBridgeInfo.address.String(), "events", len(vtr.parentEvents))
	}

	vtHandleEventMeter.Mark(int64(len(vtr.parentEvents)))
	events = make([]IRequestValueTransferEvent, len(vtr.parentEvents))
	for i, event := range vtr.parentEvents {
		events[i] = event
	}
	vtr.cBridgeInfo.AddRequestValueTransferEvents(events)

	return nil
}
