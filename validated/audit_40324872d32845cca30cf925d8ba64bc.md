### Title
Zero-Value Handle Calls Permanently Consume Bridge Nonces Without Transferring Bridged Assets — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `contracts/service_chain/bridge/BridgeTransferERC20.sol`)

---

### Summary

`handleKLAYTransfer` and `handleERC20Transfer` accept `_value = 0` without any guard. A single malicious operator (the default threshold is 1) can call either function with `_value = 0` for a legitimate pending nonce, permanently closing that nonce via `closedValueTransferVotes[nonce] = true` while transferring zero assets to the recipient. The user's KAIA or ERC20 tokens locked in the source-chain bridge can never be released, because every subsequent attempt to handle the same nonce with the correct value reverts with `"closed vote"`.

---

### Finding Description

**Request side (protected):** `_requestERC20Transfer` enforces `require(_value > 0, "zero ERC20 token amount")` before emitting a `RequestValueTransfer` event and incrementing `requestNonce`. [1](#0-0) 

**Handle side (unprotected):** Neither `handleKLAYTransfer` nor `handleERC20Transfer` contains any equivalent check.

`handleKLAYTransfer` (lines 62–100): [2](#0-1) 

`handleERC20Transfer` (lines 32–73): [3](#0-2) 

**Vote key includes `_value`:** `_voteValueTransfer` computes `voteKey = keccak256(msg.data)`, so a zero-value call produces a different vote key than the legitimate call. When the operator threshold is 1 (the default set in the constructor), a single operator's zero-value call immediately reaches threshold and closes the nonce. [4](#0-3) [5](#0-4) 

**Nonce permanently closed:** After `closedValueTransferVotes[nonce] = true` is set, any subsequent call with the correct `_value` reverts at `require(!closedValueTransferVotes[_requestNonce], "closed vote")`. [6](#0-5) 

**`_updateHandleNonce` advances `lowerHandleNonce`:** If the attacker also supplies a nonzero `_requestedBlockNumber`, `handleNoncesToBlockNums[nonce]` is set and the sliding window advances, making the nonce additionally unreachable via `_lowerHandleNonceCheck`. [7](#0-6) 

---

### Impact Explanation

A malicious operator calls `handleKLAYTransfer(txHash, from, to, 0, N, blockNum, data)` for a nonce `N` that corresponds to a real user deposit. The call:

1. Passes `_lowerHandleNonceCheck` (nonce is still open).
2. Passes `_voteValueTransfer` (threshold reached with zero-value key), setting `closedValueTransferVotes[N] = true`.
3. Executes `_to.call.value(0)("")` — succeeds, transfers 0 KAIA.
4. Emits `HandleValueTransfer` with `valueOrTokenId = 0`.

The user's KAIA (or ERC20 tokens) locked in the source bridge are permanently irrecoverable. The off-chain `VTRecovery` mechanism cannot help because the nonce is already marked closed on-chain. This constitutes an unauthorized nonce consumption affecting bridged assets.

---

### Likelihood Explanation

The default `operatorThresholds[ValueTransfer]` is 1, meaning a single operator can execute this unilaterally without any collusion. Operators are semi-trusted (analogous to `MATCH_EXECUTOR` in the original report). A compromised or malicious operator key is a realistic threat. The attack requires no special on-chain state beyond being a registered operator.

---

### Recommendation

Add a zero-value guard in both handle functions, mirroring the existing guard on the request side:

```solidity
// In handleKLAYTransfer:
require(_value > 0, "zero KLAY transfer amount");

// In handleERC20Transfer:
require(_value > 0, "zero ERC20 transfer amount");
```

Additionally, consider validating that `_requestedBlockNumber > 0` to prevent the nonce from being silently excluded from the `_updateHandleNonce` sliding window.

---

### Proof of Concept

```
Setup:
  - Bridge deployed with modeMintBurn = false, threshold = 1 (default)
  - User calls requestKLAYTransfer on source chain, locking 1 KAIA, emitting nonce N=0
  - Bridge holds 1000 KAIA liquidity on destination chain

Attack (single malicious operator):
  operator.handleKLAYTransfer(
      txHash,   // any valid bytes32
      user,     // _from
      user,     // _to
      0,        // _value  ← zero, no guard
      0,        // _requestedNonce = N
      blockNum,
      ""
  )

Result:
  - closedValueTransferVotes[0] = true
  - 0 KAIA transferred to user
  - Legitimate call handleKLAYTransfer(..., 1 KAIA, 0, ...) reverts: "closed vote"
  - User's 1 KAIA locked in source bridge is permanently unrecoverable
``` [8](#0-7) [9](#0-8)

    function _voteValueTransfer(uint64 _requestNonce)
        internal
        returns(bool)
    {
        require(!closedValueTransferVotes[_requestNonce], "closed vote");

        bytes32 voteKey = keccak256(msg.data);
        if (_voteCommon(VoteType.ValueTransfer, _requestNonce, voteKey)) {
            closedValueTransferVotes[_requestNonce] = true;
            return true;
        }

        return false;
    }
