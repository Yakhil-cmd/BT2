### Title
Unrestricted SSRF via `definition` URL fetch in `parseUri` — ([File: uri.js])

### Summary
`uri.js`'s `parseUri` function handles `byteball:`/`obyte:` URIs, including a `data` request type where `app === 'definition'`. If the `definition` value starts with `https://`, the code fetches that URL directly with no restriction on target host, exactly mirroring the Mattermost SSRF bug class ("fails to properly restrict requests to localhost/intranet").

### Finding Description
When `parseUri` encounters a URI of the form `byteball:data?app=definition&definition=https://...`, it calls `fetchUrl` on the attacker-supplied URL with no validation of the target host/IP: [1](#0-0)

```

`fetchUrl` itself performs a raw `https.get(url, ...)` with no allow-list, no DNS/IP filtering, and no restriction against private/loopback/link-local addresses (e.g. `127.0.0.1`, `169.254.169.254` cloud metadata, or internal LAN hosts): [2](#0-1) 

Such a URI can be delivered to a victim in ways fully reachable by an unprivileged, untrusted party: e.g. embedded in a plain `text` device message from any paired correspondent (device messages of subject `"text"` are emitted to the wallet UI's link/URI handlers via `eventBus.emit("text", from_address, body, message_counter)`), a QR code, or any pasted string that a wallet UI passes into `parseUri`. The wallet/GUI layer that consumes `ocore`'s exported `parseUri`/`fetchUrl` has no independent host validation either, so the SSRF constraint (or lack thereof) originates entirely in `ocore`. [3](#0-2) 

### Impact Explanation
An attacker (any paired device correspondent, or anyone who can get a victim to open a `byteball:`/`obyte:` link) can force the victim's node/wallet process to issue outbound HTTP(S) requests to arbitrary hosts, including localhost, internal network services, or cloud metadata endpoints. This is a classic blind SSRF: the response is parsed and partially reflected back into the `definition` field of the resulting request object, which can be used to probe internal services, exfiltrate metadata (e.g. cloud IAM credentials), or interact with unauthenticated internal admin endpoints reachable only from the victim's host/network — matching the "limited blind SSRF" impact class described in the Mattermost advisory.

### Likelihood Explanation
Likelihood is high: no special privileges are needed to craft the malicious URI, delivery vectors (chat text message from any correspondent, pasted/QR-scanned links) are trivially reachable, and there is zero validation of the target host before the request is issued.

### Recommendation
Restrict `fetchUrl` (and any other outbound-URL logic reachable from untrusted input) to a strict allow-list of expected hosts/schemes, or explicitly resolve and block requests to private, loopback, link-local, and reserved IP ranges (RFC1918, 127.0.0.0/8, 169.254.0.0/16, ::1, etc.) both for the initial hostname and after DNS resolution (to prevent DNS-rebinding). Consider disabling automatic following of the `definition` URL entirely, or requiring explicit user confirmation with the resolved destination shown before fetching.

### Proof of Concept
1. Attacker pairs with or is already a correspondent of the victim's wallet device.
2. Attacker sends a `text` device message (or shares a link/QR code) containing:
   `byteball:data?app=definition&definition=https://169.254.169.254/latest/meta-data/iam/security-credentials/`
3. When the victim's wallet/UI passes this string to `uri.parseUri`, the `app === 'definition'` branch triggers `fetchUrl` unconditionally against the attacker-chosen host, issuing the request from the victim's environment and returning the fetched body as `assocParams.definition` to the UI, disclosing internal data via the SSRF.

function fetchUrl(url, cb) {
	var https = require('https');
	var bDone = false;
	function returnError(err) {
		console.log(err);
		if (bDone)
			return;
		bDone = true;
		cb(err);
	}
	try {
		https.get(url, function (resp) {
			if (resp.statusCode !== 200)
				return returnError("non-200 response while trying to fetch " + url);
			var data = '';

			// A chunk of data has been recieved.
			resp.on('data', function(chunk) {
				data += chunk;
			});

			// aborted before the whole response has been received
			resp.on('aborted', function () {
				returnError("connection aborted while trying to fetch " + url);
			});

			// The whole response has been received
			resp.on('end', function () {
				if (bDone)
					return;
				bDone = true;
				cb(null, data);
			});
		}).on("error", function(err) {
			returnError("non-200 response while trying to fetch " + url + ": " + err.message);
		});
	}
	catch(err) {
		returnError(err.message);
	}
}
```
