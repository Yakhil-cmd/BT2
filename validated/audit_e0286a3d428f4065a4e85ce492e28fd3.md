### Title
CheckoutBranch/CheckoutNewBranch in git/client.go lack centralized leading-dash validation for branch arguments - (File: git/client.go)

### Finding Description
`Client.CheckoutBranch` builds `args := []string{"checkout", branch}` [1](#0-0)  and `Client.CheckoutNewBranch` builds `args := []string{"checkout", "-b", branch, "--track", track}` [2](#0-1) . Neither function checks whether `branch` begins with `-`, which would let a crafted branch name (e.g. `-B` or `--orphan=x`) be interpreted by `git` as a flag rather than a positional ref argument.

Validation against this exists only at one call site: `pkg/cmd/pr/checkout/checkout.go` explicitly rejects `pr.HeadRefName` starting with `-` before constructing its own raw command queue (`cmdsForExistingRemote`/`cmdsForMissingRemote`, which build `[]string{"checkout", localBranch}` and `[]string{"checkout", "-b", localBranch, "--track", remoteBranch}` directly, not via `CheckoutBranch`/`CheckoutNewBranch`) [3](#0-2) , [4](#0-3) . This means the guard is caller-local and does not apply to the actual `git/client.go` functions named in the question.

Other call sites that do invoke `Client.CheckoutBranch`/`CheckoutNewBranch` directly include `pkg/cmd/issue/develop/develop.go`, `pkg/cmd/pr/merge/merge.go`, `pkg/cmd/pr/close/close.go`, and `pkg/cmd/extension/git.go`/`manager.go` (confirmed via grep matches), but I was not able to fully verify within the available tool budget whether `develop.go` (which handles issue-linked branch names, themselves derived from user/attacker-influenced issue titles) performs an equivalent leading-dash check before calling `CheckoutBranch`/`CheckoutNewBranch`. This is a gap in my verification, not a claim that develop.go is safe.

### Impact Explanation
If any caller passes an attacker-influenced branch name to `CheckoutBranch`/`CheckoutNewBranch` without first checking for a leading `-`, `git checkout` would parse that value as a flag (e.g. `-B`, `--orphan`), potentially altering repository state (force-branch-reset, orphan branch creation) or invoking git hooks. This falls under command/flag-injection-driven repository state tampering, GitHub bounty class "arbitrary file write/state modification via crafted input," scoped to local repo checkout behavior.

### Likelihood Explanation
Exploitability depends entirely on whether an as-yet-unverified caller (most notably `gh issue develop`, since issue-derived branch names can be attacker-influenced) passes unvalidated branch names to these two functions. Since `checkout.go` needed its own explicit fix, the architecture demonstrates the developers already recognize this as a real risk class but implemented it non-centrally, which is fragile and likely to regress in other/new call sites.

### Recommendation
Move the leading-dash (and other shell/flag-metacharacter) validation directly into `git/client.go`'s `CheckoutBranch` and `CheckoutNewBranch` (and other functions taking ref/branch parameters), e.g. reject any branch argument matching `^-` before constructing `args`, or always pass `--` before the branch name to `git checkout` to force positional-argument parsing. This removes reliance on each call site remembering to validate.

}

func TestCheckoutNewBranchRejectsFlagLikeName(t *testing.T) {

    defer restore(t)
    client := Client{commandContext: cs.commandContext}

Expected: both currently fail (no rejection occurs; `git` is invoked with `checkout -B` / `checkout -b --orphan --track origin/--orphan`), demonstrating the missing centralized guard. Further confirmation of exploitability requires verifying `pkg/cmd/issue/develop/develop.go`'s call sites lack an equivalent check to `checkout.go:150`.

func cmdsForExistingRemote(remote *cliContext.Remote, pr *api.PullRequest, opts *CheckoutOptions, reuseWorktree bool) [][]string {
	var cmds [][]string
	remoteBranch := fmt.Sprintf("%s/%s", remote.Name, pr.HeadRefName)

	refSpec := fmt.Sprintf("+refs/heads/%s", pr.HeadRefName)
	if !opts.Detach {
		refSpec += fmt.Sprintf(":refs/remotes/%s", remoteBranch)
	}

	localBranch := pr.HeadRefName
	if opts.BranchName != "" {
		localBranch = opts.BranchName
	}

	remoteBranchRef := fmt.Sprintf("refs/remotes/%s", remoteBranch)
	fetchCmd := []string{"fetch", remote.Name, refSpec, "--no-tags"}

	if opts.Detach {
		return append(cmds, detachCmds(fetchCmd, opts.Worktree, reuseWorktree)...)
	}

	cmds = append(cmds, fetchCmd)

	switch {
	case opts.Worktree != "":
		worktreeCmds, branchExists := shared.WorktreeCheckoutCommands(
			opts.GitClient,
			shared.WorktreeTarget{Path: opts.Worktree, Reuse: reuseWorktree},
			localBranch,
			remoteBranch,
		)
		cmds = append(cmds, worktreeCmds...)
		if branchExists {
			cmds = append(cmds, syncBranchCmds(opts.Worktree, remoteBranchRef, opts.Force)...)
		}
	case opts.GitClient.HasLocalBranch(context.Background(), localBranch):
		cmds = append(cmds, []string{"checkout", localBranch})
		cmds = append(cmds, syncBranchCmds("", remoteBranchRef, opts.Force)...)
	default:
		cmds = append(cmds, []string{"checkout", "-b", localBranch, "--track", remoteBranch})
	}
