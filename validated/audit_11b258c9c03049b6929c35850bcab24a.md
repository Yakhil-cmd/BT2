The Squidex SSRF report hinges on a web-application pattern that has no structural analog in the Polkadot SDK: a user-configurable "webhook URL" that the server fetches over HTTP as part of normal application logic, then exposes the raw response back to that same (or another) user through an API.

Substrate/FRAME's consensus-critical dispatch path is deterministic and never performs outbound network I/O as part of extrinsic execution — pallets cannot make HTTP requests during block execution, which would break determinism across validators. The only place HTTP requests exist in this codebase is the offchain worker subsystem, exposed through `sp_io::offchain::http_request_start` [1](#0-0)  and the `Externalities::http_request_start` trait method [2](#0-1) , implemented by `HttpApi::request_start` in the client [3](#0-2) .

This mechanism is not a matching analog because:
- Offchain workers are code chosen and run locally by the node operator/validator itself (not attacker-supplied dispatch logic executed on their behalf), so there is no "permissionless attacker" triggering the fetch against the operator's own infrastructure the way an unprivileged Squidex user configures a webhook that the shared server backend fetches.
- Any URL passed to `http_request_start` originates from the offchain worker's own runtime/host code, not from an arbitrary signed extrinsic parameter that an unprivileged network participant fully controls and that gets executed as consensus state, so it doesn't fit the "real user entry: signed extrinsic... no privileged role" requirement.
- There is no equivalent of the Squidex `lastDump` field — a consensus-visible, API-readable storage of a fetched response body keyed by an attacker's URL — anywhere in FRAME pallets, XCM, or bridge code.

I also checked relay-chain RPC client and telemetry endpoint configuration [4](#0-3) [5](#0-4) , both of which are node-operator-configured (CLI/config file), not attacker-reachable through any signed extrinsic, XCM message, or public proof submission.

Since no unprivileged, attacker-controlled entry point exists that causes the chain's consensus state machine to perform an outbound HTTP fetch to an attacker-chosen URL and then expose the response to that or another untrusted party, this bug class does not have a demonstrable analog in the Polkadot SDK.

	pub fn request_start(&mut self, method: &str, uri: &str) -> Result<HttpRequestId, ()> {
		// Start by building the prototype of the request.
		// We do this first so that we don't touch anything in `self` if building the prototype
		// fails.
		let (body_sender, receiver) = mpsc::channel(0);
		let body = StreamBody::new(receiver);
		let body = BoxBody::new(body);
		let mut request = hyper::Request::new(body);
		*request.method_mut() = hyper::Method::from_bytes(method.as_bytes()).map_err(|_| ())?;
		*request.uri_mut() = hyper::Uri::from_maybe_shared(uri.to_owned()).map_err(|_| ())?;

		let new_id = self.next_id;
		debug_assert!(!self.requests.contains_key(&new_id));
		match self.next_id.0.checked_add(1) {
			Some(new_id) => self.next_id.0 = new_id,
			None => {
				tracing::error!(
					target: LOG_TARGET,
					"Overflow in offchain worker HTTP request ID assignment"
				);
				return Err(());
			},
		};
		self.requests
			.insert(new_id, HttpApiRequest::NotDispatched(request, body_sender));

		tracing::trace!(
			target: LOG_TARGET,
			id = %new_id.0,
			%method,
			%uri,
			"Requested started",
		);

		Ok(new_id)
	}

/// Format url and force addition of a port
fn url_to_string_with_port(url: Url) -> Option<String> {
	// This is already validated on CLI side, just defensive here
	if (url.scheme() != "ws" && url.scheme() != "wss") || url.host_str().is_none() {
		tracing::warn!(target: LOG_TARGET, ?url, "Non-WebSocket URL or missing host.");
		return None;
	}

	// Either we have a user-supplied port or use the default for 'ws' or 'wss' here
	Some(format!(
		"{}://{}:{}{}{}",
		url.scheme(),
		url.host_str()?,
		url.port_or_known_default()?,
		url.path(),
		url.query().map(|query| format!("?{}", query)).unwrap_or_default()
	))
}
