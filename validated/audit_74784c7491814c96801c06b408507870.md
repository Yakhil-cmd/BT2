### Title
Unsanitized extension release tag_name/URL printed to terminal enables ANSI/OSC escape injection - (File: pkg/cmd/root/extension.go)

### Summary
`NewCmdExtension` in `pkg/cmd/root/extension.go` prints `releaseInfo.Version` and `releaseInfo.URL` directly to `io.ErrOut` via `fmt.Fprintf` with no control-character or ANSI/OSC stripping. [1](#0-0)  These values originate from the GitHub Releases API `tag_name`/repository URL for the extension the victim has installed, which is fully attacker-controlled content when the victim installs/uses an attacker-published `gh-*` extension repository.

### Finding Description
`NewCmdExtension`'s `PostRun` callback reads a `*update.ReleaseInfo` from `checkExtensionReleaseInfo` (default `checkForExtensionUpdate` → `update.CheckForExtensionUpdate`) and writes it straight to the terminal:
```go
fmt.Fprintf(stderr, "\n\n%s %s → %s\n",
    cs.Yellowf("A new release of %s is available:", ext.Name()),
    cs.Cyan(strings.TrimPrefix(ext.CurrentVersion(), "v")),
    cs.Cyan(strings.TrimPrefix(releaseInfo.Version, "v")))
...
fmt.Fprintf(stderr, "%s\n\n", cs.Yellow(releaseInfo.URL))
``` [1](#0-0) 

`ReleaseInfo.Version` is populated from `ext.LatestVersion()`, which for binary extensions is derived from the GitHub Releases API JSON field `tag_name` fetched from the extension's own repository (`repos/{owner}/{name}/releases/latest`). [2](#0-1) [3](#0-2)  The attacker fully controls this repository (and thus its release tag names) as the extension publisher, and GitHub does not restrict tag names from containing arbitrary bytes including ANSI/OSC/C0 escape sequences. There is no call to any sanitizer (e.g. the `text` package's whitespace/ANSI helpers referenced elsewhere in the codebase such as `pkg/cmd/gist/shared/shared.go`, `pkg/cmd/issue/shared/display.go`) before this text reaches `fmt.Fprintf`. `cs.Cyan`/`cs.Yellow` only wrap the string with ANSI color codes; they do not strip or escape any embedded control sequences.

### Impact Explanation
An attacker who publishes an extension repository can craft a release `tag_name` containing OSC sequences (e.g., OSC 52 clipboard write, OSC 7/8 hyperlink spoofing, or cursor-manipulation escapes) that get rendered verbatim to the victim's terminal every time the victim runs the installed extension and an update is available. This matches "Terminal output/prompt spoofing" impact — potential clipboard hijack, hidden/faked prompts, or misleading text that could lead a victim to run unintended commands.

### Likelihood Explanation
Preconditions: victim must install the attacker's `gh-*` extension (a normal, expected extension-install workflow) and run it while stdout/stderr are a TTY and 24 hours have elapsed since the last update check (`ShouldCheckForExtensionUpdate`/`CheckForExtensionUpdate` state file logic). [4](#0-3)  This is fully within the attacker's control since they define the extension, its releases, and tags. No privileged access is required beyond publishing the repository/releases, matching the described unprivileged attacker model.

### Recommendation
Sanitize all remote/attacker-controlled strings (`releaseInfo.Version`, `releaseInfo.URL`, and similarly `ext.Name()`/`ext.CurrentVersion()`) by stripping C0/C1 control characters and ANSI/OSC/DCS escape sequences before passing them to `fmt.Fprintf` in `NewCmdExtension`'s `PostRun`. Apply this centrally, e.g., a `text.SanitizeControlSequences` helper used consistently wherever remote-controlled text (release tag, URL) is written to the terminal.

### Proof of Concept
Go test sketch (in `pkg/cmd/root/extension_test.go`):
```go
func TestNewCmdExtension_SanitizesReleaseInfo(t *testing.T) {
    io, _, _, stderr := iostreams.Test()
    io.SetStdoutTTY(true)
    ext := &extensions.ExtensionMock{
        NameFunc: func() string { return "gh-evil" },
        OwnerFunc: func() string { return "attacker" },
        CurrentVersionFunc: func() string { return "v1.0.0" },
        IsPinnedFunc: func() bool { return false },
    }
    em := &extensions.ExtensionManagerMock{}
    maliciousRelease := &update.ReleaseInfo{
        Version: "v1.0.1\x1b]52;c;ZXZpbA==\x07", // OSC 52 clipboard write
        URL:     "https://github.com/attacker/gh-evil/releases/v1.0.1",
    }
    checkFn := func(extensions.ExtensionManager, extensions.Extension) (*update.ReleaseInfo, error) {
        return maliciousRelease, nil
    }
    cmd := root.NewCmdExtension(io, em, ext, checkFn)
    cmd.SetArgs([]string{})
    _ = cmd.Execute()

    out := stderr.String()
    assert.NotContains(t, out, "\x1b]52") // expected to fail today — escape passes through unsanitized
}
```
Expected: the assertion fails on current code because the OSC 52 sequence embedded in the attacker-controlled release tag is written verbatim to `stderr`, confirming the passthrough.

// ShouldCheckForExtensionUpdate decides whether we check for updates for GitHub CLI extensions based on user preferences and current execution context.
// During cli/cli#9934, this logic was split out from ShouldCheckForUpdate() because we envisioned it going in a different direction.
func ShouldCheckForExtensionUpdate() bool {
	if os.Getenv("GH_NO_EXTENSION_UPDATE_NOTIFIER") != "" {
		return false
	}
	if os.Getenv("CODESPACES") != "" {
		return false
	}
	return !ci.IsCI() && IsTerminal(os.Stdout) && IsTerminal(os.Stderr)
}

		return nil, nil
