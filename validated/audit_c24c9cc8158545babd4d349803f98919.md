### Title
Definer can update an asset's attestor list at any time, permanently freezing already-issued coins held by addresses attested only by the removed attestors - ([File: storage.js])

### Summary
For assets defined with `spender_attested: true`, the set of trusted attestors is not fixed at asset-definition or coin-receipt time. Instead, `readAsset()` in [1](#0-0)  always looks up the *latest* `asset_attestors` unit before `last_ball_mci` and uses only that list as `objAsset.arrAttestorAddresses`. The definer of the asset can post a new `asset_attestors` message at any time — validated only by `validateAttestorListUpdate()` in [2](#0-1)  — which fully replaces the previous attestor set with no continuity guarantee and no timelock/grace period for existing holders.

### Finding Description
When a user receives a `spender_attested` asset, they typically only qualify to spend/transfer it because some attestor in the *current* attestor list has attested their address (via `attestations`, checked in `filterAttestedAddresses()` at [3](#0-2) ). Both issuing/transferring and spending re-check attestation live, at validation time, against `objAsset.arrAttestorAddresses` — not against whatever attestor set was valid when the coins were received:
- On payment validation, `objAsset.arrAttestedAddresses` is computed fresh via `loadAssetWithListOfAttestedAuthors()` and checked against authors/outputs in `validatePayment()` and `validatePaymentInputsAndOutputs()`, e.g. [4](#0-3)  and [5](#0-4) .
- Per-input ownership also re-checks attestation at spend time: [6](#0-5) .

The definer alone controls this list and can swap it out unilaterally: `validateAttestorListUpdate()` only checks that the sender is the asset definer and that the new list is well-formed [2](#0-1) , with no restriction preventing removal of attestors whose attestations are currently backing live, unspent outputs. Because `readAsset()` always resolves to the single latest attestor-list unit (ORDER BY level/rowid DESC LIMIT 1) rather than tracking a grandfathered/legacy set [7](#0-6) , any holder whose spending eligibility depended solely on an attestor that has since been dropped becomes permanently unable to satisfy `spender_attested` for that asset — their existing balance in that asset is frozen, exactly like the "reward token removed" analog: earned/held value becomes inaccessible once the trust set is changed, with no timelock or migration path for affected holders.

### Impact Explanation
This is a fund-freezing bug reachable by a single privileged-but-expected actor (the asset definer) acting entirely within their allowed message set (`asset_attestors`). Any address holding units of a `spender_attested` asset, whose only qualifying attestation came from an attestor later removed by the definer, loses the ability to transfer or spend those coins — permanent freezing of already-issued, already-owned funds. This matches the "Medium/High: freezing of user funds" impact class used for the reference report (loss of access to rightfully owned/earned assets due to unilateral removal with no timelock).

### Likelihood Explanation
Any asset can be defined with `spender_attested: true` and any number of attestors up to `MAX_ATTESTORS_PER_ASSET`; the definer routinely updates the attestor list as part of normal asset lifecycle management (e.g., rotating KYC providers). Because the check is against only the current/latest list, this is a naturally-occurring path, not a contrived edge case — every attestor rotation risks freezing coins of holders attested solely by the removed attestor(s).

### Recommendation
When updating an asset's attestor list, do not fully discard historical attestor validity for outputs that already exist and were validly attested under the previous list. Options: (1) grandfather existing balances by checking attestation against the attestor list in effect at the mci the output was created, not just the latest list; (2) require a timelock/grace period between posting a new attestor list and it taking effect for spending (as opposed to issuing) existing coins, giving holders time to move funds while still attested; (3) allow multiple concurrently-valid attestor-list "generations" to satisfy the `spender_attested` check for outputs created while they were active.

### Proof of Concept
1. Definer `D` issues asset `A` with `spender_attested: true` and initial `attestors: [X]`.
2. Attestor `X` attests address `H`. `H` receives a payment of asset `A` (validated fine since `H` is in `arrAttestedAddresses` computed from attestor `X`, per `loadAssetWithListOfAttestedAuthors`/`filterAttestedAddresses`).
3. Definer `D` posts `asset_attestors` message replacing the attestor list with `[Y]` (validated by `validateAttestorListUpdate`, which only checks that `D` is the definer and the list is well-formed — no check on existing holders/outputs).
4. `readAsset()` now resolves `arrAttestorAddresses` to `[Y]` only, since it always takes the latest attestor-list unit.
5. `H` attempts to spend/transfer their asset `A` balance. `filterAttestedAddresses` finds no attestation from `Y` for `H`, so `objAsset.arrAttestedAddresses` is empty; `validatePayment` rejects with "none of the authors is attested" ( [8](#0-7) ) and per-input check would also fail ( [9](#0-8) ).
6. `H`'s balance of asset `A` is now permanently frozen with no on-chain mechanism to recover access unless `D` chooses to re-add `X` (or attest `H` under `Y`), which `H` cannot compel or predict.

function validateAttestorListUpdate(conn, payload, objUnit, objValidationState, callback){
	if (objUnit.authors.length !== 1)
		return callback("attestor list must be single-authored");
	if (!isNonemptyObject(payload))
		return callback("attestor update must be a non-empty object");
	if (hasFieldsExcept(payload, ['asset', 'attestors']))
		return callback("foreign fields in attestor list update");
	storage.readAsset(conn, payload.asset, objValidationState.last_ball_mci, false, function(err, objAsset){
		if (err)
			return callback(err);
		if (!objAsset.spender_attested)
			return callback("this asset does not require attestors");
		if (objUnit.authors[0].address !== objAsset.definer_address)
			return callback("attestor list can be edited only by definer");
		err = checkAttestorList(payload.attestors);
		if (err)
			return callback(err);
		callback();
	});
}
