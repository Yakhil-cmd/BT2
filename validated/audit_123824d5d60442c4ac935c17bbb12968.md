### Title
Webhook signature verification keys off `repository.owner.login` while every event handler acts on `repository.full_name` — an unauthenticated org can trigger stack actions on another org's repository ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/`webhook_secret` to validate the request signature against using `repository_owner`, which is read from the untrusted JSON body (`params.dig('repository', 'owner', 'login')`), not from any authenticated value. [1](#0-0) [2](#0-1)  Every event `Handler`, however, resolves the actual `Repository`/`Stack` to act on using a *different* field of the same body: `repository.full_name`. [3](#0-2)  Because the HMAC signature only covers the raw byte string and is checked against the secret picked from `repository.owner.login`, nothing binds `repository.owner.login` to `repository.full_name`. An attacker who can get any single request accepted (e.g. an organization configured with no `webhook_secret`) can set `repository.full_name` to point at a completely different, unrelated organization/repository and have the handler act on that target.

### Finding Description
`Shipit.github(organization:)` looks up per-organization app configuration, including `webhook_secret`, in a multi-org deployment (`config/secrets.yml` `github:` keyed by org). [4](#0-3)  `GitHubApp#verify_webhook_signature` unconditionally returns `true` when no `webhook_secret` is configured for that org: `return true unless webhook_secret`. [5](#0-4)  This is a documented, supported configuration state — the shipped example configs for multi-org setups explicitly show `webhook_secret: # nil` per organization. [6](#0-5) 

The controller selects which org's secret/app to check against solely from `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`), a value taken straight from the unauthenticated JSON body before any signature check occurs: `params = JSON.parse(request.raw_post)` happens in `#create`, but `repository_owner` is read from `params` inside `verify_signature`, which runs as a `before_action`. [7](#0-6) [2](#0-1) 

Once `verify_signature` passes (trivially, for the no-secret org), `WebhooksController#create` dispatches the *same full raw params* to the handler chain: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`. [8](#0-7)  The base `Handler` class resolves the target repository/stacks from `payload.dig('repository', 'full_name')`, not from `repository.owner.login`: [3](#0-2)  `Repository.from_github_repo_name` splits this `full_name` on `/` to find the `owner`/`name` row. [9](#0-8)  `PushHandler`, `CheckSuiteHandler`, and the `PullRequest` handlers (e.g. `ClosedHandler`) all follow this same pattern of trusting `repository.full_name` from the body to select and act on stacks/review-stacks. [10](#0-9) [11](#0-10) [12](#0-11) 

This breaks the binding: `org authenticated by verify_signature (repository.owner.login) == org whose repository is acted upon (repository.full_name)`. The two are independent, attacker-supplied strings inside the same JSON body, and the request signature (when present) only proves the raw bytes came from someone possessing the secret of the org named in `repository.owner.login` — it says nothing about which repository the payload's `full_name` claims to target.

### Impact Explanation
If any organization configured on the Shipit instance has no `webhook_secret` set (an explicitly documented/supported configuration, as shown in the shipped multi-org example configs), an unauthenticated attacker can submit a forged webhook body with:
- `repository.owner.login` / `organization.login` = the org with no secret (to pass `verify_signature` trivially, since `return true unless webhook_secret`), and
- `repository.full_name` = `"<targetOrg>/<targetRepo>"` for any *other* org/repo tracked by the Shipit instance (even ones that do have a properly configured `webhook_secret`).

This lets the attacker trigger handler-side effects against stacks that belong to organizations they were never able to authenticate as, e.g.:
- `PushHandler` forcing `stack.sync_github(expected_head_sha:)` for an attacker-chosen SHA on a target stack. [10](#0-9) 
- `CheckSuiteHandler` scheduling check-run refreshes against a target stack's commits. [11](#0-10) 
- `PullRequest::ClosedHandler` archiving a target org's review stack. [13](#0-12) 

This is a cross-organization/cross-repository write through the webhook trust boundary — the confused-deputy pattern the task asks for (org authenticated vs. repository acted on), reachable with zero credentials against the target org, only requiring that *some* configured org lack a webhook secret.

### Likelihood Explanation
Requires a specific, but explicitly supported and documented, deployment configuration: multiple GitHub organizations configured on one Shipit instance, at least one of which has `webhook_secret` unset (`nil`). The shipped example dummy config (`secrets_double_github_app.yml`) and the multi-org documentation (`docs/setup.md` "Using Multiple Github Applications") both show `webhook_secret` as an optional/blank field per org, so this is a realistic operational state rather than a contrived edge case. [6](#0-5)  No credentials, tokens, or prior access are required — only knowledge (or guessing) of the unsecured org's `login` name, which is often discoverable (org names are public on GitHub).

### Recommendation
Bind webhook authentication to the same field the handlers act on: after signature verification succeeds, re-derive/validate that `repository.full_name`'s owner matches the `repository_owner`/organization whose secret validated the request, and reject mismatches. Alternatively, do not allow `webhook_secret` to be blank as a silent bypass (`return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`) — require an explicit opt-out flag instead of treating "unset" as "always trusted."

### Proof of Concept
1. Operator configures two orgs in `config/secrets.yml`: `OrgA` (no `webhook_secret`) and `OrgB` (with `webhook_secret` set), matching the pattern in `test/dummy/config/secrets_double_github_app.yml`.
2. Attacker (unauthenticated, no GitHub App install, no token) POSTs to `/webhooks` with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "OrgA" }, "full_name": "OrgB/target-repo" }
}
```
No `X-Hub-Signature` header is required to be valid, because `WebhooksController#verify_signature` resolves `Shipit.github(organization: "OrgA")`, whose `verify_webhook_signature` returns `true` unconditionally (`return true unless webhook_secret`). [5](#0-4) 
3. `WebhooksController#create` passes the full parsed body to `PushHandler`, which resolves stacks via `payload.dig('repository', 'full_name')` = `"OrgB/target-repo"` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` on `OrgB`'s stack — an org the attacker never authenticated against. [3](#0-2) [10](#0-9)

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
