## Confirmed vulnerability

### Title
Attacker-chosen `repository.owner.login` selects the HMAC key used to validate the webhook, letting a payload for an unrelated repository be authenticated with a different organization's (or an unconfigured) secret - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` derives which GitHub App/organization configuration (and thus which `webhook_secret`) to use for HMAC verification directly from the **unverified** JSON body, via `repository_owner`, which reads `params.dig('repository', 'owner', 'login')` (falling back to `organization.login`). Only after selecting that config does it verify the signature against that org's secret. The handlers that actually act on the payload (`PushHandler`, `StatusHandler`, etc.) then resolve the target repository from a *different* field of the same untrusted body, `repository.full_name` (`app/models/shipit/webhooks/handlers/handler.rb`), with no cross-check that this repository actually belongs to the organization whose secret validated the request.

### Finding Description
The binding that should hold is: **organization authenticated == organization owning the repository written**. It is broken because:

- `verify_signature` in `app/controllers/shipit/webhooks_controller.rb` (lines 24-30, 59-62) picks `Shipit.github(organization: repository_owner)` where `repository_owner` comes straight out of the raw, unauthenticated JSON body.
- `Shipit.github` (`lib/shipit.rb`, `github` method) looks up per-organization config via `github_app_config(organization)`. In multi-org deployments each org can have its own (or no) `webhook_secret`.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb` lines 76-83) explicitly does `return true unless webhook_secret` — i.e., if the org resolved from the attacker-supplied `repository.owner.login` has no `webhook_secret` configured, **any signature (or none) is accepted**.
- After "verification" passes, `WebhooksController#create` calls `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` with the *entire* raw JSON — including the `repository.full_name` field used by `Handler#repository_name` (`app/models/shipit/webhooks/handlers/handler.rb` line 36-38) to resolve `Repository.from_github_repo_name(repository_name)` and thus the `Stack`s to act on.

Because the org used for signature selection (`repository.owner.login`) and the repository actually acted upon (`repository.full_name`) are read from independent, unauthenticated fields of the same JSON body, an attacker only needs to know (or control) one organization in the Shipit configuration that has no `webhook_secret` set (or a leaked/guessable one) to forge a webhook whose `repository.full_name` points at a completely different, unrelated, "protected" repository/stack. Verification silently passes because it validated against the *wrong* organization's key, not the organization actually being written to.

### Impact Explanation
`PushHandler` triggers `stack.sync_github(expected_head_sha:)` for any stack under the spoofed `repository.full_name` (`app/models/shipit/webhooks/handlers/push_handler.rb`). `StatusHandler` creates commit statuses (`app/models/shipit/webhooks/handlers/status_handler.rb`), which influence whether commits are deployable/mergeable in the merge queue. Since continuous deployment/merge-queue logic elsewhere in the engine trusts commit statuses and CI signals recorded via webhooks, an attacker who can make the engine accept forged events for a target repository can influence sync/deploy state and status-gated merges without ever needing that repository's own webhook secret — an authentication-bypass class issue that can lead to an unauthorized deploy/merge decision for a repository the attacker does not control.

### Likelihood Explanation
Exploitability requires the Shipit deployment to be configured with the multi-organization GitHub config schema (`github: <org>: {...}`) and at least one configured organization lacking a `webhook_secret` (explicitly supported/expected per `docs/setup.md`, which lists `webhook_secret` as "optional"). Given that omitting `webhook_secret` is a documented, supported configuration (not a misconfiguration outside the app's design), and the endpoint (`/webhooks`) is unauthenticated and public by design, this is directly reachable by an unprivileged external attacker with no credentials, matching the required unprivileged-attacker/no-session criteria.

### Recommendation
Do not use attacker-supplied payload data to select the verification key before the signature is verified. Either:
1. Verify the signature against every configured organization's secret (or a global secret) rather than the one keyed by the unverified `repository.owner.login`, or
2. After selecting an org config by `repository_owner`, cross-validate that `repository.full_name`'s owner matches `repository_owner` before dispatching to handlers, and reject (or require a non-empty `webhook_secret`) rather than treating a missing secret as automatic success.

### Proof of Concept
1. Configure Shipit (as documented) with two organizations, e.g. `trusted-org` (has `webhook_secret` set, owns the real target repo/stack) and `weak-org` (no `webhook_secret` configured — a supported/optional setting).
2. POST to `/webhooks` with header `X-Github-Event: push` and JSON body:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": {"login": "weak-org"},
    "full_name": "trusted-org/protected-repo"
  }
}
```
No `X-Hub-Signature` header (or any arbitrary value) is required.
3. `verify_signature` resolves `Shipit.github(organization: 'weak-org')`, whose `verify_webhook_signature` returns `true` immediately because `webhook_secret` is blank (`lib/shipit/github_app.rb` line 77).
4. `PushHandler#process` resolves `Repository.from_github_repo_name('trusted-org/protected-repo')` and calls `stack.sync_github(expected_head_sha: '<attacker-chosen sha>')` on stacks belonging to `trusted-org`, despite the request never being authenticated by `trusted-org`'s own webhook secret.     def verify_webhook_signature(signature, message)
```ruby
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
