### Title
`mint_pre_signed` voucher can be replayed after `burn()` to remint the same item with the original issuer signature - ([File: substrate/frame/nfts/src/features/create_delete_item.rs])

### Summary
`pallet-nfts`'s pre-signed mint mechanism (`mint_pre_signed` / `do_mint_pre_signed`) is the FRAME analog of the reported `MerkleReserveMinter` bug: an issuer signs a one-time minting authorization (`PreSignedMint`) instead of a merkle proof, and a caller redeems it. The redemption uniqueness check is not tied to any persistent "used" flag on the signed payload — it is only tied to whether `Item::<T,I>` currently contains an entry for that `(collection, item)` pair. Because `do_burn` unconditionally removes that `Item` entry, the exact same signed voucher (`mint_data` + `signature` + `signer`) can be redeemed, burned, and redeemed again indefinitely (until the `deadline` block is reached), reproducing the report's core flaw: "no check if this ... proof has been already used before" combined with "burning ... clears the mapping that the reuse-check relies on."

### Finding Description
`mint_pre_signed` is a public, signed extrinsic [1](#0-0) . It validates the issuer's signature over the `PreSignedMint` payload and then calls `do_mint_pre_signed(origin, *mint_data, signer)`, where `origin` (i.e. whoever calls the extrinsic) becomes `mint_to` [2](#0-1) .

`do_mint_pre_signed` only checks:
- attribute count limit,
- `only_account` matches the caller (optional),
- `deadline >= now`,
- signer has `Issuer` role,

and then calls `do_mint`, which is the only place item uniqueness is enforced [3](#0-2) .

`do_mint`'s uniqueness guard is:
```rust
ensure!(!Item::<T, I>::contains_key(collection, item), Error::<T, I>::AlreadyExists);
``` [4](#0-3) 

This is exactly the transient-state check pattern flagged in the original report (`owners[_tokenId] != address(0)`). There is no separate "voucher consumed" storage item keyed by the `PreSignedMint` payload/signature (no nonce, no `Attribute::Pallet` marker analogous to `PalletAttributes::UsedToClaim` that the regular `MintType::HolderOf` mint path uses for its own replay protection [5](#0-4) ).

`do_burn` removes the `Item` entry that gates re-mint:
```rust
Item::<T, I>::remove(&collection, &item);
Account::<T, I>::remove((&owner, &collection, &item));
``` [6](#0-5) 

Once the item is burned, `Item::contains_key` becomes false, and the identical `mint_data`/`signature`/`signer` triple that was already spent can be resubmitted successfully via `mint_pre_signed`, minting the item again to the caller. The pallet's own test suite demonstrates the intermediate state transition (`mint_pre_signed` → `AlreadyExists` on retry → `burn` clears state) without asserting that the original signature is invalidated afterward [7](#0-6) .

### Impact Explanation
Impact is bounded by the fact that the caller who redeems the voucher is also the only one who can burn the resulting item (the caller becomes the owner, and `burn` requires the origin be the item owner or `ForceOrigin`) [8](#0-7) . Consequently this is not third-party fund theft or unbacked-issuance-to-others: it lets the holder of one issuer-signed voucher redeem it, burn it, and redeem it again repeatedly (bounded only by the `deadline`), each time:
- getting the deposit back on burn (net-neutral for deposits),
- re-triggering `Issued`/`AttributeSet`/`ItemMetadataSet` events and any `mint_price` transfer to the collection owner (if configured, cost is paid again — net cost to attacker, not free),
- but crucially bypassing the issuer's intended single-use authorization semantics for that item id — e.g. defeating a "burn to redeem an off-chain benefit" mechanism, re-claiming any off-chain reward tied to repeated `Issued` events, or circumventing per-voucher scarcity assumptions the issuer relied on when signing the message once.

This mirrors the report's stated impact category ("allow users to get their tokens back after being burnt for whatever reason ... breaks the whole intention of the burn functionality") but without a direct value-extraction primitive against third parties, so it is best characterized as Medium rather than High/Critical.

### Likelihood Explanation
High likelihood of triggering: the flow requires no privileged role and no stolen keys — only possession of one legitimately issued `PreSignedMint` message (which by design is meant to be shared/redeemable, e.g. handed to an allowlisted address) and the ability to call two already-permissionless extrinsics, `mint_pre_signed` then `burn`, repeated at will before `deadline`.

### Recommendation
Track voucher consumption independently of item existence, e.g. store a persistent "used" marker (hash of `mint_data`+`signer`, or a dedicated `Attribute::Pallet` marker analogous to `PalletAttributes::UsedToClaim`) that is set on first successful `do_mint_pre_signed` and is never cleared by `do_burn`, and check/reject on subsequent redemption attempts regardless of whether the underlying item was later burned.

### Proof of Concept
Not independently executed in this session (index-only inspection; no local Rust/FRAME test harness was run). Reasoning is based on direct code inspection of the existing `pre_signed_mints_should_work` test, which already demonstrates the constituent steps (`mint_pre_signed` succeeds → repeat attempt fails with `AlreadyExists` → `burn` clears the item and refunds deposit) [7](#0-6) ; a follow-up `mint_pre_signed` call reusing the *original* `mint_data`/`signature`/`signer` after that `burn` was not asserted to fail in the existing suite, and per the traced `do_mint`/`do_burn` logic above it would succeed since the only guard (`Item::contains_key`) was just cleared. A background engineering session with Rust toolchain access would be needed to actually execute this exact sequence and confirm the `Ok(())` result empirically.

	pub(crate) fn do_mint_pre_signed(
		mint_to: T::AccountId,
		mint_data: PreSignedMintOf<T, I>,
		signer: T::AccountId,
	) -> DispatchResult {
		let PreSignedMint {
			collection,
			item,
			attributes,
			metadata,
			deadline,
			only_account,
			mint_price,
		} = mint_data;
		let metadata = Self::construct_metadata(metadata)?;

		ensure!(
			attributes.len() <= T::MaxAttributesPerCall::get() as usize,
			Error::<T, I>::MaxAttributesLimitReached
		);
		if let Some(account) = only_account {
			ensure!(account == mint_to, Error::<T, I>::WrongOrigin);
		}

		let now = T::BlockNumberProvider::current_block_number();
		ensure!(deadline >= now, Error::<T, I>::DeadlineExpired);

		ensure!(
			Self::has_role(&collection, &signer, CollectionRole::Issuer),
			Error::<T, I>::NoPermission
		);

		let item_config = ItemConfig { settings: Self::get_default_item_settings(&collection)? };
		Self::do_mint(
			collection,
			item,
			Some(mint_to.clone()),
			mint_to.clone(),
			item_config,
			|collection_details, _| {
				if let Some(price) = mint_price {
					T::Currency::transfer(
						&mint_to,
						&collection_details.owner,
						price,
						ExistenceRequirement::KeepAlive,
					)?;
				}
				Ok(())
			},
		)?;
