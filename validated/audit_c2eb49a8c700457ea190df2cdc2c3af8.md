### Title
LP-collateral price inflation via reserve donation to the Aquarius pool — sole-source fair-value oracle trusts manipulable `get_reserves` — (File: contracts/price-aggregator/src/providers/aquarius.rs)

### Summary
The Value DeFi May-2021 incident class is "pool-value / share-price manipulation": the protocol priced a claim from pool reserves an attacker could shift, letting them mint/borrow more than fair value. XOXNO Lending prices Aquarius LP share collateral with `fair_lp_price_wad` / `fair_stable_lp_price_wad`, which read the pool's **live raw reserves** via `aquarius_pool_reserves_call` (`get_reserves`) and divide by `total_shares`. A direct token transfer to the Aquarius pool raises reserves without minting shares, inflating the LP price. LP oracles are forced to be **sole-source** (`has_lp && sources.len() != 1` panics with `SourceCountOutOfRange`), so the dual-leg tolerance check and second-source disagreement gate are waived — the sanity band is the only bound. An attacker who holds LP shares can inflate their collateral value and borrow beyond the pool's real worth, leaving the hub market with bad debt.

### Finding Description
- `read` in `contracts/price-aggregator/src/providers/aquarius.rs:90-114` fetches `(reserve_a, reserve_b)` and `total_shares` from the pool contract and feeds them directly into `fair_lp_price_wad` (`common/src/oracle/lp.rs:57-87`), which computes `2 * sqrt(value_a * value_b) * WAD / share_supply_wad`, or `fair_stable_lp_price_wad` (`common/src/oracle/lp_stable.rs:80-110`), which computes `D * min_price / share_supply_wad`.
- `get_reserves` on a Soroban AMM reflects token balances; permissionless `token.transfer(attacker → pool)` raises a reserve while `total_shares` is unchanged. Both formulas increase monotonically in reserves: constant-product inflates by `sqrt(1 + donated_value / leg_value)`, and stable-swap `D` grows roughly linearly with the donated coin.
- `validate_asset_oracle` in `contracts/price-aggregator/src/admin.rs:181-196` rejects a second source for LP oracles and skips `validate_oracle_tolerance` for them, so there is no independent price to disagree with; only `[min_sanity_price_wad, max_sanity_price_wad]` and `min_pool_value_wad` bound the move — and `pool_value_wad` itself is computed from the same inflated reserves, so it is self-consistent.
- The controller consumes this WAD price for collateral valuation/health factor; supplying the LP token and calling `borrow` settles at the manipulated price.

### Impact Explanation
Attacker path, all unprivileged: deposit into a listed Aquarius pool to acquire LP shares (cheap if the pool is thin — `min_pool_value_wad` only enforces a floor), supply the LP token as collateral via the controller, transfer underlying tokens directly to the Aquarius pool to inflate `fair_lp_price_wad` up to the sanity-band ceiling, then `borrow` (optionally flash-funded via `flash_loan`) up to the inflated LTV and walk away. The protocol holds LP collateral worth materially less than the debt; `clean_bad_debt` socializes the shortfall across suppliers via `apply_bad_debt_to_supply_index` — theft of user funds / protocol insolvency, the same loss shape as the Value DeFi incident. With attacker share fraction `f` near 1, most of the donation is recovered through their own LP claim, so net cost is small relative to the inflated borrow.

### Likelihood Explanation
Requires a listed LP-token collateral market whose Aquarius pool is shallow enough that a donation moves `sqrt(reserve_a * reserve_b)` meaningfully while staying inside the sanity band. Because only the sanity band backstops the price (no second source, no tolerance), profitability depends on configured band width — the tighter the band, the smaller the extractable premium. Conditions are plausible on a permissionless deployment listing newer LP collateral, so Medium-to-High likelihood; impact qualifies as Critical (theft of supplier funds). Overall severity: High.

### Recommendation
Do not compute LP fair value from live `get_reserves` alone. Options: (a) use manipulation-resistant share pricing — e.g., value LP shares from `total_shares`-weighted underlying amounts priced at external leg prices with reserves only bounding redemption, or use the pool's own `get_virtual_price`-style measure if resistant; (b) require reserve-ratio sanity: reject when `reserve_a * price_a` vs `reserve_b * price_b` deviates beyond a tight band from the pool's expected ratio (donation skews the value ratio even though the sqrt product resists swaps); (c) tighten `min_sanity_price_wad`/`max_sanity_price_wad` for LP keys toward the invariant-derived fair price; (d) require a second independent source for LP collateral by relaxing the sole-source restriction for LP oracles.

### Proof of Concept
1. Governance lists Aquarius pool P (reserves 100k USDC / 100k XLM-value) LP token as collateral at 80% LTV; oracle = sole `AquariusLp` source, sanity band ±10%.
2. Attacker deposits into P, acquiring 90% of `total_shares`; supplies all LP to the controller as collateral.
3. Attacker (flash) transfers USDC directly to P so `reserve_a` rises ~21% (price `×sqrt(1.21) ≈ ×1.10`), exactly at the band ceiling — still a "valid" price.
4. Attacker borrows the borrow asset at the inflated collateral value (~10% more than fair LTV allows on the real claim), then abandons the position.
5. Liquidators seize LP whose redemption value covers less than the debt; residual bad debt is written down onto suppliers via `clean_bad_debt` / `apply_bad_debt_to_supply_index`.

Caveat not fully verified within tool budget: the exact cap applied by `validate_lp_sanity_band` for LP oracles (it may bound the band tighter than `MAX_SINGLE_SOURCE_SANITY_BAND_BPS`); profitability scales with whatever width is registered.
