### Title
Attacker-controlled extension release Version/URL are written to stderr unsanitized in `NewCmdExtension` PostRun, allowing terminal escape-sequence injection - (File: pkg/cmd/root/extension.go)

### Summary
`ext.LatestVersion()` (a GitHub release `tag_name` for binary extensions, or an `ls-remote` HEAD SHA for git extensions) and `ext.URL()` are attacker-controlled when the attacker owns the extension's GitHub repo, and both values flow unsanitized into `fmt.Fprintf(stderr, ...)` in the `PostRun` handler of `NewCmdExtension`. Unlike other output paths in this codebase (`gist/view`, `read-file`, `release/download`, `pkg/cmd/api`) which route untrusted external content through `iostreams.Untrusted`/`CopyGuardedContent`/asciisanitizer before writing to a terminal, this code path writes raw strings directly to `io.ErrOut` with only color wrapping (`cs.Yellow`, `cs.Cyan`), which does not strip escape sequences.

### Finding Description
The call chain is: `NewCmdExtension` PreRun → `checkForExtensionUpdate` → `update.CheckForExtensionUpdate` (`internal/update/update.go:51-78`), which builds `ReleaseInfo{Version: ext.LatestVersion(), URL: ext.URL()}`.

- For `BinaryKind` extensions, `LatestVersion()` (`pkg/cmd/extension/extension.go:116-148`) calls `fetchLatestRelease`, which does a raw `json.Unmarshal` of the GitHub API `releases/latest` response into `release{Tag string \`json:"tag_name"\`}` (`pkg/cmd/extension/http.go:73-144`) — the attacker fully controls this via their own repo's release tag name, and it is not restricted to a semver/plain format at this layer.
- `URL()` for `BinaryKind` is derived from the stored manifest (owner/name/host, generally safe), but for `GitKind` extensions it comes directly from `git config remote.origin.url` (`pkg/cmd/extension/extension.go:59-86`), which an attacker with control of the repo cannot directly set (this is the local clone's configured remote, set by the CLI at install time from the parsed repo — likely not attacker-influenced beyond owner/name).
- The `Version` field (release tag name) is the most direct injection point since GitHub allows almost arbitrary tag names, and these bytes are decoded straight from JSON with no character filtering.
- In `pkg/cmd/root/extension.go:55-76` (`PostRun`), these values are written via `fmt.Fprintf(stderr, "\n\n%s %s → %s\n", ..., cs.Cyan(strings.TrimPrefix(ext.CurrentVersion(), "v")), cs.Cyan(strings.TrimPrefix(releaseInfo.Version, "v")))` and `fmt.Fprintf(stderr, "%s\n\n", cs.Yellow(releaseInfo.URL))`. `cs.Cyan`/`cs.Yellow` (`pkg/iostreams/color.go`) only wrap the string in ANSI color codes; they perform no escape-sequence stripping.
- This contrasts with the codebase's established pattern for handling untrusted external strings: `pkg/iostreams/untrusted.go` provides `Untrusted.String()` which sanitizes via `asciisanitizer.Sanitizer` specifically so that `fmt.Fprintf`/`Fprint` paths cannot leak raw escape bytes. The extension PostRun path bypasses this pattern entirely — `releaseInfo.Version` and `releaseInfo.URL` are plain `string` fields, not wrapped in `iostreams.Untrusted`, and are printed directly to the raw `io.ErrOut` `fileWriter`, not through the sanitizing `ContentOut` writer.

### Impact Explanation
This allows a remote GitHub repo owner (publishing an extension release with a crafted tag name) to inject arbitrary ANSI/terminal escape sequences into the victim's terminal the next time the victim invokes `gh <their-extension>` and the CLI performs its background update check. This maps to a terminal/output injection class of issue: a malicious actor can rewrite terminal titles, move the cursor, overwrite prior lines, or attempt to visually forge prompt-like text in the victim's terminal. However, this is limited to visual spoofing in the terminal buffer — it cannot execute code, exfiltrate credentials, or programmatically inject keystrokes/answers into gh's actual interactive prompts (gh's real prompts use its own I/O flow via a prompter, not driven by parsing terminal escape output), so it does not on its own bypass `gh`'s authorization/consent checks for installing a different, "official" extension. The exploit chain described in the question (tricking the user into "approving a subsequent malicious official-extension-stub install") would require a separate user action and is not proven to be forced or automated by this escape-sequence output alone.

### Likelihood Explanation
Preconditions are realistic and low-privilege: any attacker who can get a victim to install their extension (extension names/repos are arbitrary, no official vetting required for third-party extensions) can control the release tag name returned by `GET /repos/{owner}/{repo}/releases/latest`. The update check runs automatically in the background (`PreRun`) any time the victim runs the extension command with `ShouldCheckForExtensionUpdate()` true (interactive TTY, not CI, no opt-out env vars), and is not gated by any user confirmation before printing the release info in `PostRun`.

### Recommendation
Wrap `releaseInfo.Version` and `releaseInfo.URL` (and any other externally-sourced strings printed here) in `iostreams.Untrusted` before formatting them into the `PostRun` `fmt.Fprintf` calls in `pkg/cmd/root/extension.go`, consistent with how `pkg/cmd/gist/view/view.go` and other call sites already treat externally-sourced/API-derived content. Alternatively, sanitize `ReleaseInfo.Version`/`URL` at the point of construction in `internal/update/update.go` and `pkg/cmd/extension/http.go` before they are stored/propagated.

### Proof of Concept
```go
// pkg/cmd/root/extension_test.go
func TestNewCmdExtension_PostRun_SanitizesEscapeSequences(t *testing.T) {
    ios, _, _, stderr := iostreams.Test()
    em := &extensions.ExtensionManagerMock{
        DispatchFunc: func(args []string, stdin io.Reader, stdout, stderr io.Writer) (bool, error) {
            return true, nil
        },
    }
    ext := &extensions.ExtensionMock{
        CurrentVersionFunc: func() string { return "v1.0.0" },
        IsPinnedFunc:       func() bool { return false },
        NameFunc:           func() string { return "gh-evil" },
        OwnerFunc:          func() string { return "" },
    }
    malicious := "\x1b]0;Would you like to install it now? (y/N)\x07\x1b[2K\rgh: fake trusted prompt"
    checkFunc := func(em extensions.ExtensionManager, ext extensions.Extension) (*update.ReleaseInfo, error) {
        return &update.ReleaseInfo{Version: "v1.0.0" + malicious, URL: "https://github.com/attacker/gh-evil" + malicious}, nil
    }
    cmd := root.NewCmdExtension(ios, em, ext, checkFunc)
    _, err := cmd.ExecuteC()
    require.NoError(t, err)

    // EXPECTED (currently fails): stderr must not contain raw ESC bytes.
    assert.NotContains(t, stderr.String(), "\x1b")
}
```
This test currently fails because `PostRun` in `pkg/cmd/root/extension.go` writes `releaseInfo.Version`/`releaseInfo.URL` unsanitized, demonstrating that ESC (0x1b) bytes reach `io.ErrOut`.
