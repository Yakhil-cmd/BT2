### Title
`Stop`-hook diff selection permanently excludes uncommitted dangerous edits introduced by Bash-only, interrupted turns - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`load_baseline_sha`/`capture_git_baseline` and `compute_v2_review_set` derive the security-review diff purely from git state (`baseline_sha`, `head_at_capture`, current `git status`). The `touched_paths` guard meant to prevent re-baselining past unreviewed edits is populated only for tool-tracked edits, not for arbitrary Bash writes, so a Bash-only turn that is interrupted before `Stop` fires gets its dangerous, still-uncommitted content silently absorbed into the *next* baseline snapshot and is thereafter treated as pre-existing code that is never diffed or reviewed.

### Finding Description
`handle_user_prompt_submit` decides whether to advance `baseline_sha` on every turn: [1](#0-0) 
It only *preserves* the old baseline (protecting unreviewed edits) when `state.get("touched_paths")` is non-empty. `touched_paths` is written by `record_touched_path`, which is invoked from tool-specific hooks (Edit/Write/MultiEdit); it is not a general "worktree got dirty" signal.

`capture_git_baseline` snapshots whatever is currently in the working tree — tracked dirty content and all — via `git stash create` (falling back to `HEAD` when clean): [2](#0-1) 

The Stop-hook review set is then computed as the intersection of "currently dirty vs HEAD" and "changed since `baseline_sha`": [3](#0-2) 

The function's own docstring documents the exact gap: a Bash-only turn interrupted before `Stop` fires leaves `touched_paths` empty, so the next `UserPromptSubmit` re-baselines past those edits: [4](#0-3) 

Exploit flow: Claude (or an attacker steering it, e.g. via prompt injection in repo content) writes dangerous code purely through `Bash` (e.g. `cat >> file.py <<EOF ... EOF`, `sed -i`, `printf > file`) instead of the `Edit`/`Write` tools tracked by `record_touched_path`. If that turn ends or is interrupted before the asyncRewake `Stop` hook completes (user sends a follow-up prompt, session abort, tool-reject, model crash — all attacker-reachable via ordinary interaction), the next `UserPromptSubmit` fires `capture_git_baseline`, which stashes the dirty tree *including the dangerous, unreviewed content* as the new `baseline_sha` (because the `touched_paths`-based preserve-guard did not fire). From that point, `compute_v2_review_set`'s `changed_since = _git_name_only(repo, baseline_sha)` shows no difference for that file relative to the new baseline, so it is intersected out of `review_set` on every subsequent `Stop` fire — the dangerous change is now permanently "old" and never sent to the LLM security reviewer or gated by the `exit(2)` enforcement.

### Impact Explanation
The security-guidance Stop-hook review is Claude Code's sole automated last-line gate for flagging dangerous code/commands introduced in a session (SQL injection, command injection, path traversal, secrets, etc.). Losing coverage for Bash-authored content means dangerous code can persist in the repo and be committed/pushed without ever appearing in a review or triggering the `exit(2)` continuation-forcing guidance, effectively letting locally-executed or committed dangerous content bypass the plugin's approval/deny signal to the user. This matches "Unauthorized local command execution that bypasses Claude Code approval or deny controls" in spirit — the *review* control, not tool permission itself, is what's bypassed.

### Likelihood Explanation
No elevated privileges are required — only ordinary use of the `Bash` tool for file edits (already a supported and common Claude Code workflow) combined with a turn ending/interrupting before the asyncRewake `Stop` hook completes, which routinely happens (new user message sent quickly, session timeout, tool-reject, crash). The maintainers' own docstring acknowledges this exact scenario as a known limitation, indicating it is a real and reachable code path, not a hypothetical.

### Recommendation
Make the "preserve baseline" decision based on actual git dirtiness at UPS time rather than solely on the tool-specific `touched_paths` list — e.g., compare the newly captured stash/HEAD SHA against the previous baseline's diff to detect any uncommitted delta (regardless of which tool produced it) before deciding to advance `baseline_sha`, or always union the previous `baseline_sha`'s outstanding diff into the new capture rather than overwriting it when `touched_paths` happens to be empty.

### Proof of Concept
Integration test plan (pytest style) in the plugin's existing hook-state test suite:
1. Init a git repo with one commit; call `handle_user_prompt_submit` (turn 1) to establish `baseline_sha` = `B0`.
2. Simulate a Bash-only edit: write dangerous content (e.g., `os.system(user_input)`) to a tracked file directly on disk, without calling `record_touched_path` (mirrors a `Bash` tool write).
3. Simulate the turn being interrupted: do NOT call `consume_stop_state`/`Stop` handler; instead call `handle_user_prompt_submit` again (turn 2, simulating a follow-up prompt).
4. Assert: `load_baseline_sha(session_id)` now equals a new SHA that already contains the dangerous content (verify via `git show <new_baseline>:file.py` contains the payload).
5. Call `compute_v2_review_set(cwd, new_baseline_sha, head_at_capture, untracked_at_baseline)` and assert the dangerous file is **absent** from the returned `review_set`, demonstrating it will never reach `analyze_code_security`/the LLM reviewer despite never having been reviewed.

```python
def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError) as e:
        debug_log(f"Failed to capture git baseline: {e}")
        return None
```
