### Title
Webhook signature verification is silently bypassed when `webhook_secret` is unset, allowing unauthenticated actors to forge GitHub events and escalate into `Shipit.github_teams` authorization — ([File: lib/shipit/github_app.rb])

### Summary
The reported bug class ("a critical operation is executed while trusting an unchecked/unverified precondition") maps directly onto `WebhooksController#verify_signature`. That method authorizes *all* incoming webhook processing based on `GitHubApp#verify_webhook_signature`, but that method treats "no secret configured" as "signature verified," `return true unless webhook_secret`. Because `webhook_secret` is documented and shipped as an *optional* setting, this reproduces the report's exact pattern: an operation (dispatching attacker-supplied webhook payloads to internal handlers) proceeds on an unchecked assumption ("secret must have been used to sign this") that is never actually enforced when the secret is absent.

### Finding Description
`WebhooksController#create` unconditionally dispatches the parsed JSON body to every registered handler for the event type before any authentication other than `verify_signature`: [1](#0-0) 

`verify_signature` determines *which* GitHub App/organization config to check against by reading the organization name straight out of the untrusted request body (`repository.owner.login` or `organization.login`), then calls `verify_webhook_signature`: [2](#0-1) [3](#0-2) 

The actual verification in `lib/shipit/github_app.rb` breaks the trust binding "request is authenticated" == "signature cryptographically verified" by returning `true` whenever no `webhook_secret` is configured for that organization: [4](#0-3) 

`webhook_secret` is explicitly documented as optional, and every shipped configuration template/example leaves it `nil` by default: [5](#0-4) [6](#0-5) 

With no secret configured (the documented default), `head(422) unless verified` never fires, so any unauthenticated party who can reach `/webhooks` can submit a fabricated `X-Github-Event: membership` payload. The `membership` handler creates/attaches `Team`/`Membership` records straight from the untrusted payload with no further check that the request actually came from GitHub: [7](#0-6) 

Because `User#authorized?` is gated purely by membership in `Shipit.github_teams`: [8](#0-7) 

an attacker can forge a `membership` webhook to add an arbitrary (attacker-controlled) GitHub login to a team listed in `Shipit.github_teams`, then complete normal GitHub OAuth login as that account to pass `force_github_authentication`'s `current_user.authorized?` check: [9](#0-8) 

### Impact Explanation
This breaks the binding "GitHub-authenticated webhook == organization-authorized event," letting an unprivileged, uncredentialed network attacker escalate into `Shipit.github_teams` authorization — one of the explicitly listed High-impact outcomes. It can also be used to forge `push`/`status`/`pull_request`/`check_suite` events (triggering `GithubSyncJob`, commit status writes, and check-run refreshes) against any repository whose owning organization has not set a `webhook_secret`, none of which require holding any Shipit session, `ApiClient` token, or GitHub credential.

### Likelihood Explanation
Likelihood is high wherever an installation follows the documented/example configuration and leaves `webhook_secret` unset (an explicitly "optional" field in `docs/setup.md` and left blank in the shipped `config/secrets.development.example.yml`). No credentials, sessions, or write access to any repository are required — only network reachability to the public `/webhooks` endpoint, which is required to exist for GitHub to deliver real events.

### Recommendation
- Do not treat an absent `webhook_secret` as automatic verification success. Require `webhook_secret` to be present for every configured GitHub organization, and fail closed (`head(422)`/refuse to boot) if it is missing, rather than defaulting to `return true unless webhook_secret` in `GitHubApp#verify_webhook_signature`.
- Update `docs/setup.md` and the shipped example secrets files to mark `webhook_secret` as required, not optional.
- Add a startup/config validation check (analogous to a "checked return value") that raises if any organization in `Shipit.github_teams`-gating configuration lacks a webhook secret, rather than silently allowing unsigned webhook traffic through.

### Proof of Concept
1. Deploy Shipit using the documented default configuration (`webhook_secret` left blank, per `docs/setup.md` line 30 and `config/secrets.development.example.yml`).
2. As an unauthenticated attacker, `POST /webhooks` with header `X-Github-Event: membership` and a JSON body:
   ```json
   {
     "action": "added",
     "team": {"id": <id-of-a-Shipit.github_teams-team>, "name": "Developers", "slug": "developers", "url": "https://example.com"},
     "organization": {"login": "<victim-org>"},
     "member": {"login": "attacker-github-login"}
   }
   ```
   No `X-Hub-Signature` header is required because `verify_webhook_signature` returns `true` when `webhook_secret` is unset, matching the behavior exercised in `test/controllers/webhooks_controller_test.rb` lines 129-149 (with signature verification stubbed to always pass, mirroring the real unset-secret code path).
3. `Membership` record is created for `attacker-github-login` on a team included in `Shipit.github_teams`.
4. Attacker completes normal GitHub OAuth login via `/github/auth/github` as `attacker-github-login`; `User#authorized?` now returns `true` because of the forged membership, bypassing the intended team-based authorization gate in `Authentication#force_github_authentication`.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```

```ruby
    def force_github_authentication
      if current_user.logged_in? && current_user.requires_fresh_login?
        Rails.logger.warn("User #{current_user.id} requires a fresh login, logging out...")
        reset_session
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      elsif Shipit.authentication_disabled? || current_user.logged_in?
        unless current_user.authorized?
          team_handles = Shipit.github_teams.map(&:handle)
          team_list = team_handles.to_sentence(two_words_connector: ' or ', last_word_connector: ', or ')
          render(plain: "You must be a member of #{team_list} to access this application.", status: :forbidden)
        end
      else
        redirect_to(Shipit::Engine.routes.url_helpers.github_authentication_path(origin: request.original_url))
      end
    end
```
