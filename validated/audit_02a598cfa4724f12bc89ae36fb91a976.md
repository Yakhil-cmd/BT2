### Title
RAY-domain overflow permanently freezes an oversized accrued market - (File: common/src/rates/scaling.rs)

### Summary
Interest accrual converts total scaled supply and debt back into RAY-denominated value before applying the borrow-index cap. Once `scaled_amount * index / RAY` exceeds `i128::MAX`, `scaled_to_original` panics with `MathOverflow`; because every market mutation synchronizes first, the market can no longer repay, withdraw, liquidate, recapitalize, or update indexes. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` calls `scaled_to_original` on both `borrowed` and `supplied` before calling `update_borrow_index`. [2](#0-1)  `scaled_to_original` performs half-up `scaled * index / RAY` arithmetic, which safely widens the intermediate product but still requires the resulting RAY value to fit `i128`. [4](#0-3)  The intended `MAX_BORROW_INDEX_RAY` cap therefore cannot save the market, because the overflow occurs while measuring the pre-update totals, not while applying the new index. [5](#0-4) 

The repository's stress test demonstrates the reachable boundary: an 18-decimal market holding one billion whole tokens has an initial RAY value of `1e36`, and an index above approximately 170 times the initial index produces a value above `i128::MAX`. [6](#0-5)  At 98% utilization under the test's configured 175%-maximum XLM curve, yearly accrual eventually reaches that boundary while `borrow_index` remains below `MAX_BORROW_INDEX_RAY`. [7](#0-6) 

### Impact Explanation
The result is permanent freezing of all funds represented by that market's book: suppliers cannot withdraw, borrowers cannot repay or close debt, and liquidators cannot reach the market through flows that synchronize interest. [8](#0-7)  `update_indexes` cannot advance the market because it uses the same accrual routine, while `update_params` also synchronizes under the old model before replacing parameters. [9](#0-8)  Direct token transfers or `recapitalize` do not provide a recovery path because the cash operation still loads an interest-synced cache first. [3](#0-2) 

The condition also freezes protocol revenue booked in the affected market, since revenue is part of `supplied` and is included in the overflowing supplied-value conversion. [10](#0-9) 

### Likelihood Explanation
Reaching the condition requires an extremely large market—approximately `i128::MAX`-scale RAY exposure—and sustained interest growth before any successful synchronization. [11](#0-10)  No privileged call is needed at trigger time once a listed market's caps, token liquidity, collateral backing, and rate configuration admit enough supply and borrowing; ordinary `supply`, `borrow`, and waiting are sufficient. [12](#0-11)  The scale and configuration dependence reduce practical likelihood, but the post-condition is deterministic and irreversible once crossed.

### Recommendation
Prevent any market from entering a state whose aggregate RAY value can exceed `i128::MAX`; enforce a conservative scaled-value headroom during `supply` and debt minting, accounting for configured index growth and reserve-share accrual. [13](#0-12)  Alternatively, make `accrue_step` use saturating or bounded aggregate valuation and clamp the affected index before calculating rewards, while preserving conservative debt accounting. [14](#0-13)  Add an explicit recovery path that can synchronize or rate-cap an over-range market without first unscaling its aggregate positions. [9](#0-8) 

### Proof of Concept
The existing test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` provides a concrete reproduction. [15](#0-14) 

1. Create an 18-decimal `BIG18` market using the XLM stress curve and a separate `COL` collateral market. [16](#0-15) 
2. Have one address supply `1_000_000_000 * 10^18` base units of `BIG18`. [17](#0-16) 
3. Have another account post sufficient `COL` and borrow 98% of that `BIG18` liquidity. [18](#0-17) 
4. Advance ledger time yearly and call `update_indexes`; the first call after the RAY-value ceiling is crossed returns `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [7](#0-6) 
5. Subsequent calls to withdraw 1 unit and repay a normal amount both fail with `MathOverflow`, demonstrating that the state cannot be unwound through the ordinary exit paths. [8](#0-7)

    let new_index = old_index.mul(env, interest_factor);

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );

| Bound | Consequence |
|---|---|
| Asset decimals 0..=18 | Exact token-to-RAY upscaling. Below 3: collateral only, no flash loans, no liquidation fee, its account's only supply position, at least 2 whole units while in debt |
| Both indexes initially RAY; ceiling 10^36 | 10^9 times initial index; protocol constants |
| Supply-index floor 10^24 | At most 1,000 times the shares minted at index one for the same deposit |
| Borrow APR maximum 2 RAY | 200% annual rate; not a bound on balance growth alone |
| Token-to-RAY input maximum `i128::MAX / 10^(27-d)` | About 170.14 billion whole tokens, before other limits |
| Deposit conversion at the supply-index floor | About 170.14 million whole tokens before scaled-share overflow |

The token-to-RAY maximum is also the admitted cap maximum. Accrued position
values and market totals must independently fit the RAY domain; valid caps and
bounded indexes do not guarantee that future accrual fits. Value overflow can
occur before the index ceiling and block repayment/withdrawal because those
operations accrue first. At the borrow-index ceiling, further accrual produces
no borrower interest. No dedicated ceiling alarm is emitted.
