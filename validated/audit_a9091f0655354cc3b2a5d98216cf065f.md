### Title
Creator fees become permanently unrecoverable if the pool creator's associated token account is frozen/blacklisted - ([File: programs/cp-swap/src/instructions/collect_creator_fee.rs])

### Summary
`collect_creator_fee` and `collect_creator_fee_permissionless` always route the accumulated `creator_fees_token_0`/`creator_fees_token_1` to the associated token account owned by the immutable `pool_state.pool_creator` address. If that account (or the mint's token account for that specific owner) becomes frozen/blacklisted (e.g. via a Token-2022 freeze extension or SPL Token freeze authority), the fees are locked in the vault forever with no alternative withdrawal path, since only the `protocol_fees` and `fund_fees` buckets have admin-callable collection instructions (`collect_protocol_fee.rs`, `collect_fund_fee.rs`); `creator_fees` have none.

### Finding Description
The `CollectCreatorFee` accounts struct constrains the `creator` signer to `pool_state.load()?.pool_creator` [1](#0-0) , and the receiving token accounts `creator_token_0`/`creator_token_1` are derived deterministically as the associated token accounts of that fixed `creator` address [2](#0-1) . The permissionless variant is identical in that the destination is still hard-pinned to `pool_state.pool_creator`, only the fee payer differs [3](#0-2) [4](#0-3) .

`PoolState` has no field or setter to reassign `pool_creator`; it is set once at `initialize` time via `pool_state.initialize(...)` [5](#0-4)  and there is no `update_pool_creator`/`set_new_creator` instruction anywhere in the program (confirmed via search). `creator_fees_token_0`/`creator_fees_token_1` are tracked as a distinct bucket from `protocol_fees_token_0/1` and `fund_fees_token_0/1` [6](#0-5) , and only the protocol/fund buckets have admin-callable rescue instructions (`admin/collect_protocol_fee.rs`, `admin/collect_fund_fee.rs`); no equivalent exists for `creator_fees`.

Both collection functions unconditionally attempt `transfer_from_pool_vault_to_user` to `creator_token_0`/`creator_token_1` and only zero out the fee counters after a successful transfer [7](#0-6) . If the underlying mint enforces a freeze/blacklist on the creator's token account (e.g., a Token-2022 mint with `DefaultAccountState`/freeze extension, or a standard SPL mint whose freeze authority freezes that specific account, or via `create_support_mint_associated.rs`-style Token-2022 mints supported by the program), every transfer attempt reverts, so `creator_fees_token_0`/`creator_fees_token_1` can never be reset to zero and the corresponding vault balance is permanently unreachable by any code path.

### Impact Explanation
This is a permanent freezing of funds: the accrued creator fee amount is subtracted from `vault_amount_without_fee` accounting [8](#0-7)  yet can never be distributed to anyone because the only two entry points that can move it (`collect_creator_fee`, `collect_creator_fee_permissionless`) are hard-coded to a single, unrecoverable destination address, and no admin sweep exists for this bucket unlike `protocol_fees`/`fund_fees`. The funds are effectively locked in the pool's token vault forever, growing over time as more creator fees accrue on every swap.

### Likelihood Explanation
Likelihood depends on the creator's token account becoming frozen after pool creation — either because the pool supports a Token-2022 mint with freeze/default-frozen-state extensions, or because the underlying SPL mint's freeze authority freezes that account (e.g. for compliance/blacklist reasons on stablecoin-like tokens). Given the program explicitly supports Token-2022 mints (`token_0_program`/`token_1_program`, `create_support_mint_associated.rs`) and creator fees accrue automatically without creator opt-in, this is a realistic operational scenario rather than a contrived edge case.

### Recommendation
Add an admin/pool-manager-callable rescue instruction (mirroring `collect_protocol_fee`/`collect_fund_fee`) that allows sending the accumulated `creator_fees_token_0`/`creator_fees_token_1` to an alternate, admin-specified destination account when the creator's own account cannot receive the transfer, or add a way to update `pool_state.pool_creator` (with appropriate authorization) so fees can be redirected to a non-frozen account.

### Proof of Concept
1. Pool is created with a Token-2022 mint (or SPL mint) as `token_0_mint`, `pool_creator = C`.
2. Swaps occur, accruing `creator_fees_token_0 > 0`.
3. Mint's freeze authority (or Token-2022 default-frozen extension) freezes `C`'s associated token account for `token_0_mint`.
4. Any call to `collect_creator_fee` or `collect_creator_fee_permissionless` now fails inside `transfer_from_pool_vault_to_user` targeting `creator_token_0`, because the destination is frozen — the instruction reverts before `creator_fees_token_0` is ever zeroed.
5. No other instruction in the program can move `creator_fees_token_0` out of the vault or reset the counter, permanently locking that value.

pub fn collect_creator_fee(ctx: Context<CollectCreatorFee>) -> Result<()> {
    let mut pool_state = ctx.accounts.pool_state.load_mut()?;
    let creator_fees_token_0 = pool_state.creator_fees_token_0;
    let creator_fees_token_1 = pool_state.creator_fees_token_1;
    if creator_fees_token_0 == 0 && creator_fees_token_1 == 0 {
        return err!(ErrorCode::NoFeeCollect);
    }

    let signer_seeds: &[&[u8]] = &[crate::AUTH_SEED.as_bytes(), &[ctx.bumps.authority]];

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_0_vault.to_account_info(),
        ctx.accounts.creator_token_0.to_account_info(),
        ctx.accounts.vault_0_mint.to_account_info(),
        ctx.accounts.token_0_program.to_account_info(),
        creator_fees_token_0,
        ctx.accounts.vault_0_mint.decimals,
        &[signer_seeds],
    )?;

    transfer_from_pool_vault_to_user(
        ctx.accounts.authority.to_account_info(),
        ctx.accounts.token_1_vault.to_account_info(),
        ctx.accounts.creator_token_1.to_account_info(),
        ctx.accounts.vault_1_mint.to_account_info(),
        ctx.accounts.token_1_program.to_account_info(),
        creator_fees_token_1,
        ctx.accounts.vault_1_mint.decimals,
        &[signer_seeds],
    )?;

    pool_state.creator_fees_token_0 = 0;
    pool_state.creator_fees_token_1 = 0;
    pool_state.recent_epoch = Clock::get()?.epoch;

    Ok(())
}
