### Title
Prosaic Contract Shared Address Has No Timeout/Arbitration Fallback, Permanently Freezing Deposited Funds — ([File: prosaic_contract.js])

### Summary
`prosaic_contract.js` lets two wallet users set up a "prosaic contract" backed by a shared address whose spending condition is a bare 2-of-2 `and` of the two parties' addresses, with no arbiter, no data-feed escape hatch, and no time-based fallback. This mirrors the reported bug class: once liquidity/funds are locked behind a condition that requires a counterparty's cooperation to release, and that counterparty has no incentive (or is unresponsive) to cosign, the funds stay locked indefinitely and there is no permissionless or time-boxed mechanism for the depositor to recover them.

### Finding Description
`deriveSharedAddress()` builds the spending definition for the shared address of a prosaic contract as a plain 2-of-2 multisig: [1](#0-0) 

Unlike `arbiter_contract.js`, which offers an arbitration escape (`openDispute`/`appeal`, resolved via `["in data feed", ...]` conditions tied to an arbiter address) when the counterparty won't cooperate: [2](#0-1) [3](#0-2) 

the prosaic-contract shared address definition contains **no such fallback**: it is strictly `["and", [["address", offeror_address], ["address", acceptor_address]]]` with no `"in data feed"`, `"cosigned by"`, or timestamp-based clause that would allow either party (or anyone) to unilaterally reclaim or force-release funds after some grace period. The shared address is created and registered via `wallet_defined_by_addresses.createNewSharedAddress`, and both parties are expected to co-sign any future spend from it: [4](#0-3) 

If a user (payer/depositor) sends funds — the contract charge or any negotiated payment tied to the "prosaic contract" — to this 2-of-2 address, and the counterparty simply refuses (or is unable) to sign a release transaction, there is no code path in `prosaic_contract.js` that lets the depositor recover the funds on their own or after a timeout. This is directly analogous to the reported issue: `repayFloat()`/`repay()` require the borrower's voluntary cooperation to unlock float, with no time restriction forcing release, putting the burden (and locked capital) on the counterparty.

### Impact Explanation
Any unprivileged wallet user who funds a prosaic-contract shared address risks permanent freezing of those funds if the counterparty stops cooperating (goes offline, disputes informally without using the arbiter flow, or simply has no incentive to sign — e.g., the deal no longer favors them). Because the address definition is a rigid `and` of two addresses with no arbiter clause and no expiry/timeout branch, there is no way for the depositor (or any third party) to force a release. This is a concrete "AA/shared-address fund freezing" outcome — capital becomes permanently unspendable, matching the accepted impact category of AA fund loss or freezing.

### Likelihood Explanation
Likelihood is significant: creating and funding a prosaic-contract shared address is a normal, unprivileged wallet flow (`createSharedAddressAndPostUnit`/`deriveSharedAddress` in `prosaic_contract.js`) available to any two correspondent wallet users. No special privileges, network position, or peer misbehavior beyond simple non-cooperation (a very plausible business/dispute scenario) is required to trigger the freeze.

### Recommendation
Add a time-boxed or arbitrated escape hatch to the prosaic-contract shared address definition, similar to `arbiter_contract.js`'s data-feed/arbiter branch: e.g., allow either party to reclaim their contribution unilaterally after a defined timeout using a `["and", [["address", X], ["not", ["in data feed", ...]]]]`-style timestamp/data-feed condition, or require prosaic contracts that move real value to be built on top of the existing arbiter-contract mechanism rather than the bare 2-of-2 definition.

### Proof of Concept
1. Alice and Bob create a prosaic contract; `prosaic_contract.deriveSharedAddress()` generates definition `["and", [["address", Alice], ["address", Bob]]]`, and `wallet_defined_by_addresses.createNewSharedAddress` registers it as `shared_address` [1](#0-0) .
2. Alice sends funds to `shared_address` as part of the agreed contract terms.
3. Bob refuses to co-sign any subsequent spend from `shared_address` (e.g., because the deal no longer favors him).
4. There is no arbiter clause, no `"in data feed"` fallback, and no timeout logic anywhere in `prosaic_contract.js`; Alice's only exit is Bob's voluntary cooperation, which never comes — the funds remain permanently locked in `shared_address`.

function deriveSharedAddress(contract, bOfferor) {
	const offeror_address = bOfferor ? contract.my_address : contract.peer_address;
	const acceptor_address = bOfferor ? contract.peer_address : contract.my_address;
	const offeror_device_address = bOfferor ? device.getMyDeviceAddress() : contract.peer_device_address;
	const acceptor_device_address = bOfferor ? contract.peer_device_address : device.getMyDeviceAddress();
	var arrDefinition =
		["and", [
			["address", offeror_address],
			["address", acceptor_address]
		]];

	var assocSignersByPath = {
		"r.0": {
			address: offeror_address,
			member_signing_path: "r",
			device_address: offeror_device_address
		},
		"r.1": {
			address: acceptor_address,
			member_signing_path: "r",
			device_address: acceptor_device_address
		},
	};
	return { arrDefinition, assocSignersByPath };
}

function createNewSharedAddress(arrDefinition, assocSignersByPath, callbacks){
	if (!includesMyDeviceAddress(assocSignersByPath))
		return callbacks.ifError("my device address not mentioned");
	var address = objectHash.getChash160(arrDefinition);
	handleNewSharedAddress({address: address, definition: arrDefinition, signers: assocSignersByPath}, {
		ifError: callbacks.ifError,
		ifOk: function(){
			// share the new address with all cosigners
			var arrDeviceAddresses = [];
			for (var signing_path in assocSignersByPath){
				var signerInfo = assocSignersByPath[signing_path];
				if (signerInfo.device_address !== device.getMyDeviceAddress() && arrDeviceAddresses.indexOf(signerInfo.device_address) === -1)
					arrDeviceAddresses.push(signerInfo.device_address);
			}
			arrDeviceAddresses.forEach(function(device_address){
				sendNewSharedAddress(device_address, address, arrDefinition, assocSignersByPath);
			});
			callbacks.ifOk(address);
		}
	});
}
