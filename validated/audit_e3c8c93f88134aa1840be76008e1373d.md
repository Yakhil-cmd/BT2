### Title
Hardcoded mainnet `definer_address` for the base asset breaks `asset['base'].definer_address` on testnet - ([File: formula/common.js])

### Summary
`formula/common.js` defines `objBaseAssetInfo`, the object oscript uses to answer `asset['base']....` queries in AA formulas. The `definer_address` field is hardcoded to the mainnet Obyte distribution-fund address `'MZ4GUQC7WUKZKKLGAS3H3FSDKLHI7HFO'` with no `constants.bTestnet` branch, unlike other network-dependent constants in the codebase (e.g. `constants.GENESIS_UNIT` and `constants.BLACKBYTES_ASSET`, which both branch on `bTestnet`, and `tools/supply.js`, which explicitly uses a different address, `'5ZPGXCOGRGUUXIUU72JIENHXU6XU77BD'`, for testnet). [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The oscript/AA formula evaluator implements the `asset[...]` operator by looking up static metadata for `'base'` from `objBaseAssetInfo` when the queried field is one it knows about (`cap`, `is_private`, `definer_address`, etc.): [4](#0-3) 

The `definer_address` value baked into that object is the real mainnet address of the Obyte distribution fund, which happens to be the definer of the base ("bytes") asset on mainnet. On testnet, the actual base-asset definer is a different address (confirmed by `tools/supply.js`, which uses the mainnet list only when `!process.env.testnet` and a distinct testnet address otherwise). Because `objBaseAssetInfo.definer_address` is a plain constant with no `bTestnet` conditional, any AA deployed on testnet (or any environment other than the specific mainnet the constant matches) that evaluates `asset['base'].definer_address` will receive the wrong, mainnet-only address instead of the correct network-specific definer address. [5](#0-4) 

This is the same bug class as the reported analog: a chain/network-specific constant is hardcoded into shared logic instead of being parameterized per deployment, so functionality that depends on it silently produces incorrect results on every network except the one the constant was written for.

### Impact Explanation
Any AA logic that relies on `asset['base'].definer_address` — for example to verify authenticity/ownership of the base asset, gate privileged behavior to "the real bytes issuer", or compare it against a trigger/stored value — will evaluate to the wrong address on testnet. This can cause:
- Incorrect AA authorization decisions (a check intended to require `asset['base'].definer_address == X` never matching, or an equality check against a supposed "official" address behaving inconsistently between networks), leading to funds being locked/frozen (permanently unreachable state in the AA) or logic bypasses depending on how the AA uses the comparison.
- Because AA byte code and its state-transition logic must be deterministic and consistent with the network's actual DAG data, returning a value that does not correspond to reality on that network is a correctness bug in the shared oscript execution engine itself (`ocore` is the library that all light/full nodes and AAs run), not an isolated app-level mistake — it silently diverges from the real database, which the rule set requires me to treat as at least a "node disagreement on / incorrect validity of a fundamental fact" class issue.

### Likelihood Explanation
Any oscript/AA author can trigger this simply by including `asset['base'].definer_address` in an AA formula and deploying/running it on testnet (or any non-mainnet ocore deployment that reuses this constant). No special privileges are needed — this is reachable purely through normal AA definition/oscript evaluation, which is exactly the "AA definitions and triggers / oscript evaluation" surface listed as in-scope.

### Recommendation
Make `objBaseAssetInfo.definer_address` network-aware instead of a single hardcoded constant, mirroring the pattern already used for `constants.GENESIS_UNIT` / `constants.BLACKBYTES_ASSET` and `tools/supply.js`:

```js
var objBaseAssetInfo = {
    ...
    definer_address: constants.bTestnet ? '5ZPGXCOGRGUUXIUU72JIENHXU6XU77BD' : 'MZ4GUQC7WUKZKKLGAS3H3FSDKLHI7HFO',
};
```

or better, source it from a single already-existing constant if one exists for the base asset definer, so mainnet/testnet values cannot drift independently across files.

### Proof of Concept
1. Run ocore in testnet mode (`constants.bTestnet === true`).
2. Deploy/execute an AA whose oscript contains: `asset['base'].definer_address`.
3. The evaluator resolves this via `objBaseAssetInfo.definer_address` [6](#0-5)  which always returns `'MZ4GUQC7WUKZKKLGAS3H3FSDKLHI7HFO'`, the mainnet distribution-fund address, regardless of `bTestnet`.
4. Compare against the testnet base-asset definer used elsewhere in the codebase, `'5ZPGXCOGRGUUXIUU72JIENHXU6XU77BD'` [7](#0-6)  — confirming the value returned to the AA is wrong for the network it is running on.
