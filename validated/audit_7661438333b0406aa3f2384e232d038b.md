### Title
Bad-debt wipeout leaves scaled supply shares with a live claim because the supply index is floored at `SUPPLY_INDEX_FLOOR_RAW` instead of zeroing positions, letting wiped suppliers drain fresh deposits - (File: contracts/pool/src/interest.rs)

### Summary
CVE-2021-28701 is a missing-enforcement bug: pages freed on a v2→v1 grant-table switch could still be mapped by a parallel request, so guests retained access to resources that were logically freed and reused. The analog here is the same shape: `apply_bad_debt_to_supply_index` "frees" supplier value by writing the supply index down when bad debt is socialized, but clamps the index at `SUPPLY_INDEX_FLOOR_RAW = RAY/1000` instead of driving it (and the position claims) to zero. Because the controller keeps each supplier's `scaled_amount` unchanged, every wiped supplier retains a positive token claim — a stale reference into a pool whose backing was already consumed — which is then paid out of whatever cash arrives next.

### Finding Description
Bad-debt socialization happens in `ops::seize::apply`: for `AccountPositionType::Borrow` entries it computes the unpaid debt in asset units and calls `interest::apply_bad_debt_to_supply_index`, then burns the debt shares. [1](#0-0) 

Inside `apply_bad_debt_to_supply_index`, `bad_debt` is capped at `total_supplied_value`, the reduction factor can reach zero, and the new index is `max(new_supply_index, SUPPLY_INDEX_FLOOR_RAW)`. [2](#0-1)  The floor is `RAY / 1_000`. [3](#0-2) 

The critical detail: the write-down never touches `cache.supplied` (total scaled shares) and never zeroes any controller-side `scaled_amount`. On a full wipeout the market is left with `supplied > 0`, `supply_index = RAY/1000`, and `cash = 0` — i.e., every position still unscale_supplys to a positive amount. The pool's own test proves the stranded-claim shape: after a wipeout clamp, `unscale_supply_floor(old_scaled) > 0`, a fresh deposit mints fresh shares, and `resolve_withdrawal` on the old position pays out exactly the fresh deposit, leaving the fresh supplier's claim unbacked. [4](#0-3) 

This is reachable by unprivileged callers: `liquidate` and `clean_bad_debt` both route through `seize_positions` → `ops::seize::apply`. Debt grows with the borrow index while utilization is only capped at borrow time, so accumulated interest can push `bad_debt` above `total_supplied_value` and trigger the clamp; a wipeout clamp is already exercised end-to-end in `test_bad_debt_index_floored_at_safety_floor`. [5](#0-4) 

### Impact Explanation
Theft of user funds / protocol insolvency. After the clamp, total live supply claims equal `supplied × RAY/1000`, which is nonzero while backing is zero. Any subsequent `supply` mints a well-collateralized claim (`fresh_claim == fresh_cash` at the floored index), but a wiped supplier's `withdraw` resolves a gross payout against the still-nonzero scaled position and `require_reserves(gross)` passes against the fresh cash — the phantom claim drains the new depositor's tokens, after which the market is permanently insolvent and the last withdrawers' funds are frozen.

### Likelihood Explanation
High-impact but requires a deep wipeout: `bad_debt >= total_supplied_value`. That happens when accrued debt (unbounded borrow-index growth, up to `MAX_BORROW_INDEX_RAY`) outruns supply value — e.g., a long-idle illiquid market, or a price crash on a market whose debt was already near the utilization cap. No privileged action is needed; any keeper or liquidator triggers the socialization, and the victim pool is whoever supplies afterward plus suppliers whose claims get stuck. The attacker doesn't need to be the wiped supplier to cause the insolvency, though a wiped supplier can also be the attacker (their position is what remains payable).

### Recommendation
On `capped == total_supplied_value`, treat the market as wiped rather than flooring the index: either drive `supply_index` to zero and zero the `supplied` share total (reclassifying or writing off the remainder), or keep the floor but reduce `supplied`/`revenue` so that `supplied × floor ≤ cash`. Alternatively, block new `supply` while `cash == 0 && supplied > 0` so fresh deposits cannot be drained by stranded claims. The floor currently exists only to avoid a zero index — the comment says interest accrual doesn't apply it — so the clamp should be paired with a share write-off.

### Proof of Concept
1. Supplier `S` supplies `X` of asset A; borrower `B` supplies cheap collateral and borrows near the utilization cap.
2. Time/price moves until `B`'s debt unscale-ceil exceeds total supplied value of A (interest accrual or a collateral crash); an unprivileged `liquidate`/`clean_bad_debt` on `B` invokes `seize_positions` → `ops::seize::apply` → `apply_bad_debt_to_supply_index` with `capped == total_supplied_value`, setting `supply_index = RAY/1000` while `supplied` and every `scaled_amount` stay nonzero.
3. New supplier `D` calls `supply` of `Y` tokens; the market mints `Y / floor`-scaled shares and credits `cash = Y`.
4. `S` calls `withdraw`; `resolve_withdrawal(i128::MAX, pos_scaled)` returns `gross = scaled × RAY/1000 > 0`, `require_reserves(gross)` passes against `D`'s cash, and `debit_cash` pays `S` out of `D`'s deposit — `D`'s position is now unbacked and permanently frozen.

This mirrors the existing unit proof in `contracts/pool/tests/interest.rs` (`test_raw_cache_floor_clamp_strands_claim_without_supply_guard`), which asserts `gross == fresh_cash` and `cash < fresh_claim` after exactly this sequence.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

fn test_raw_cache_floor_clamp_strands_claim_without_supply_guard() {
    let t = TestSetup::new();
    t.as_contract(|| {
        let old_scaled_raw = 1_000 * RAY;
        let mut cache = t.fresh_cache(PoolStateRaw {
            supplied: old_scaled_raw,
            borrowed: 0,
            revenue: 0,
            borrow_index: RAY,
            supply_index: RAY,
            last_timestamp: 0,
            cash: 0,
        });
        let old_scaled = Ray::from(old_scaled_raw);

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
    });

fn test_bad_debt_index_floored_at_safety_floor() {
    let mut t = setup();

    t.supply(BOB, "ETH", 0.01);

    t.supply(ALICE, "USDC", 100.0);
    t.borrow(ALICE, "ETH", 0.005);

    t.set_price("USDC", usd_cents(1));

    t.liquidate(LIQUIDATOR, ALICE, "ETH", 0.001);

    let (si_after, _) = get_indexes(&t, "ETH");

    assert!(
        si_after >= controller::constants::SUPPLY_INDEX_FLOOR_RAW,
        "supply index should be floored at {}, got {}",
        controller::constants::SUPPLY_INDEX_FLOOR_RAW,
        si_after
    );
}
