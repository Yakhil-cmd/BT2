### Title
Hookify PreToolUse hook fails open on any parse/import/rule-evaluation error, silently allowing dangerous Bash/Edit/Write/MultiEdit operations - (File: plugins/hookify/hooks/pretooluse.py)

### Summary
`plugins/hookify/hooks/pretooluse.py` wraps the entire rule-loading and rule-evaluation pipeline (including `json.load(sys.stdin)`, `load_rules`, and `RuleEngine.evaluate_rules`) in a blanket `try/except Exception` that always prints a `systemMessage` and unconditionally calls `sys.exit(0)` in a `finally` block. Likewise, the module-level `hookify.core` imports are wrapped in a `try/except ImportError` that also always exits 0. Because Claude Code hooks communicate deny decisions via the JSON payload rather than the process exit code, any exception anywhere in the pipeline — malformed stdin JSON, a broken/missing rule file, a regex error inside `RuleEngine`, or an import failure — causes the hook to emit no deny decision at all and exit success, which Claude Code treats as "allow."

### Finding Description
The control flow is: [1](#0-0) [2](#0-1) 

`tool_name` from `input_data` is mapped to `event` (`bash` for `Bash`, `file` for `Edit/Write/MultiEdit`), which then selects the rule set via `load_rules(event=event)` and is evaluated by `RuleEngine.evaluate_rules`. This is the exact "event classification maps tool to rule set" invariant referenced in the question. However, every failure mode in that pipeline — a corrupted `.claude/hookify.*.local.md` rule file causing a parser exception in `config_loader`, a `KeyError`/`AttributeError` inside `evaluate_rules`, or malformed/edge-case JSON on stdin — is caught generically and converted into a benign `systemMessage` printed to stdout, followed by `sys.exit(0)` in the `finally` block. No deny/block field is emitted in these failure paths, so Claude Code's hook consumer sees a normal, non-blocking response and proceeds to execute the tool call (Bash command, Edit, Write, MultiEdit) unchecked. The same fail-open pattern exists for the module import failure path, which similarly emits a message and exits 0 before any rule ever runs.

### Impact Explanation
Any condition that triggers an exception in the hook pipeline (corrupted rule config, parser bug, unexpected input shape) silently disables all Hookify enforcement for that tool call, allowing an otherwise-denied `Bash`, `Edit`, `Write`, or `MultiEdit` operation to execute without approval. This matches "Unauthorized local command execution that bypasses Claude Code approval or deny controls," since the security control degrades to a no-op instead of failing closed.

### Likelihood Explanation
The failure path is trivially reachable — any malformed rule file, any bug in `config_loader`/`rule_engine`, or any unexpected shape of `input_data` triggers it deterministically, and the `except Exception` / `finally: sys.exit(0)` structure guarantees the fail-open outcome every time such an error occurs, with no code path available to fail closed.

### Recommendation
Do not default to allow on error. On import failure, config-load failure, or rule-evaluation exception, emit a deny/block decision (or a `systemMessage` combined with a blocking exit code / `"permissionDecision": "deny"`) rather than silently permitting the operation. Fail closed for `Bash`, `Edit`, `Write`, and `MultiEdit` events specifically, since these are the highest-risk operations that Hookify is meant to gate.

```python
def main():
    """Main entry point for PreToolUse hook."""
    try:
        # Read input from stdin
        input_data = json.load(sys.stdin)

        # Determine event type for filtering
        # For PreToolUse, we use tool_name to determine "bash" vs "file" event
        tool_name = input_data.get('tool_name', '')

        event = None
        if tool_name == 'Bash':
            event = 'bash'
        elif tool_name in ['Edit', 'Write', 'MultiEdit']:
            event = 'file'

        # Load rules
        rules = load_rules(event=event)

        # Evaluate rules
        engine = RuleEngine()
        result = engine.evaluate_rules(rules, input_data)

        # Always output JSON (even if empty)
        print(json.dumps(result), file=sys.stdout)

    except Exception as e:
        # On any error, allow the operation and log
        error_output = {
            "systemMessage": f"Hookify error: {str(e)}"
        }
        print(json.dumps(error_output), file=sys.stdout)

    finally:
        # ALWAYS exit 0 - never block operations due to hook errors
        sys.exit(0)
```
