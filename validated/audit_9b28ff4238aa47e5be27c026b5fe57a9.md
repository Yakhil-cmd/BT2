### Title
Stale/inactive stake accounts permanently lose inflation rewards once their vote account's `epoch_credits` history evicts unredeemed entries - ([File: programs/vote/src/vote_state/handler.rs])

### Summary
`VoteStateHandler::increment_credits` caps the vote account's `epoch_credits` list at `MAX_EPOCH_CREDITS_HISTORY` entries, evicting the oldest entry whenever the cap is exceeded. The stake reward calculation path (`tower_epoch_credits_iter` / `calc_earned_credits` in `runtime/src/inflation_rewards/points.rs`) can only compute earned points from whatever epoch-credit entries are still present in the vote account at the time a stake redeems rewards. A delegated stake that is not touched (i.e., not part of the reward redemption path, analogous to a MasterChef pool that never calls `updatePool`) for longer than `MAX_EPOCH_CREDITS_HISTORY` epochs while its validator keeps voting will have its earliest unredeemed epoch-credit entries evicted from the vote account before it ever gets to observe them, exactly like the MasterChef `endBlock` bug where a stale pool's un-accrued rewards silently disappear once a boundary is crossed.

### Finding Description
Reward accrual for a stake account works by comparing `stake.credits_observed` against the vote account's recorded `epoch_credits` history: [1](#0-0) 
`tower_epoch_credits_iter` walks the vote account's `epoch_credits_iter` and, for every historical `(epoch, final_epoch_credits, initial_epoch_credits)` entry that the stake hasn't already observed, adds `stake_amount * earned_credits` to the running point total: [2](#0-1) 

Critically, this iterator only has access to whatever entries are currently stored on the vote account. The vote account itself trims its own history independently of any particular stake's redemption status: [3](#0-2) 

Specifically, once `self.epoch_credits().len() > MAX_EPOCH_CREDITS_HISTORY`, the oldest entry is unconditionally removed (`self.epoch_credits_mut().remove(0)`), regardless of whether any delegated stake has redeemed rewards for that entry yet. If a stake account's owner never submits a transaction that triggers reward redemption (this happens automatically at epoch boundaries via `calculate_stake_rewards`/`redeem_stake_rewards` in `runtime/src/inflation_rewards/mod.rs`, but a stake that has been fully paid up to some `credits_observed` and then goes multiple epochs without new activity relative to the vote account's *push* rate) can fall behind: the vote account keeps incrementing/rotating its bounded history, evicting the oldest un-redeemed epoch-credit entry for that particular delegator before `calc_earned_credits` (`runtime/src/inflation_rewards/points.rs:158-181`) ever gets to sum it into `earned_credits`.

This mirrors the MasterChef `updatePool` bug exactly: in MasterChef, a pool that doesn't call `updatePool()` before `block.number >= endBlock` permanently loses the reward accrual for the blocks between its last update and `endBlock`. Here, a stake delegation that isn't redeemed before its earliest pending epoch-credit entry ages out of the vote account's fixed-size history (`MAX_EPOCH_CREDITS_HISTORY`) permanently loses the points/rewards for that evicted epoch, while a delegation to the same validator that redeems every epoch never experiences this loss. Both bugs are boundary-crossing loss-of-yield issues that unfairly penalize inactive/stale accounts relative to actively-maintained ones, using the same "someone else's independent counter moved past my window" root cause.

### Impact Explanation
This is a quantifiable and reproducible loss of stake-holder rewards (loss of yield), not merely a theoretical concern — it directly reduces the lamports a staker (an unprivileged user, not a validator/operator) is owed for legitimately-earned voting credits, purely because they (or the redemption path acting on their behalf) fell behind the vote account's fixed epoch-credit retention window. This matches the accepted severity class from the analogous MasterChef finding (quantifiable loss of yield due to a stale-account boundary condition), classified Medium in the original report.

### Likelihood Explanation
Likelihood depends on how large `MAX_EPOCH_CREDITS_HISTORY` is relative to how long a stake can go without having its `credits_observed` advanced. Reward redemption normally happens automatically for every active delegation at each epoch boundary through the bank's rewards pipeline, so under normal conditions this window is unlikely to be exceeded. However, edge cases (e.g., stakes with zero effective stake for extended periods, stakes excluded from a reward calculation pass, or long-running forks/snapshot-restore paths that skip reward epochs) could allow the gap to grow. I was not able to fully confirm the exact numeric value of `MAX_EPOCH_CREDITS_HISTORY` or enumerate every code path that might cause a stake to fall behind more than that many epochs within the available context, so likelihood should be validated further with a live/test-net reproduction.

### Recommendation
Ensure the reward-eligible epoch-credit window is never trimmed from the vote account faster than delegated stakes can redeem it, e.g., by tracking the minimum `credits_observed` across the vote account's active delegators before evicting the oldest `epoch_credits` entry, or by making `calc_earned_credits`/`tower_epoch_credits_iter` reconcile against a persisted higher-capacity/checkpointed credits ledger rather than relying solely on the vote account's own bounded, delegation-agnostic history buffer.

### Proof of Concept
Conceptual reproduction (exact repro steps would need a live bank/test harness):
1. Create a validator/vote account and a delegated stake account to it.
2. Advance epochs, incrementing the vote account's credits every epoch via `increment_credits` (`programs/vote/src/vote_state/handler.rs:425-456`), without ever letting that specific stake redeem rewards for `> MAX_EPOCH_CREDITS_HISTORY` consecutive epochs (e.g. by keeping the delegation's effective stake amount at zero to prevent it from participating in the reward compute pass, or by simulating a bank/branch that repeatedly skips reward computation for that stake).
3. Once the vote account's `epoch_credits` list exceeds `MAX_EPOCH_CREDITS_HISTORY`, the oldest entries are evicted (`self.epoch_credits_mut().remove(0)`).
4. Now let the stake redeem rewards normally; `tower_epoch_credits_iter`/`calc_earned_credits` (`runtime/src/inflation_rewards/points.rs:158-234`) will only sum over the entries still present, permanently omitting the rewards for the evicted epochs — even though the vote account did in fact earn/record those credits at the time.
5. Compare the total lamports the stake receives against what it would have received had it redeemed every epoch (i.e., against a "control" stake that redeems on time) — the late/stale stake's total will be strictly lower for the evicted epochs, demonstrating the quantifiable loss of yield.

fn calc_earned_credits(
    stake: &Stake,
    final_epoch_credits: u64,
    initial_epoch_credits: u64,
    new_credits_observed: &mut u64,
) -> u128 {
    let credits_in_stake = stake.credits_observed;

    // figure out how much this stake has seen that
    //   for which the vote account has a record
    let earned_credits = if credits_in_stake < initial_epoch_credits {
        // the staker observed the entire epoch
        final_epoch_credits - initial_epoch_credits
    } else if credits_in_stake < final_epoch_credits {
        // the staker registered sometime during the epoch, partial credit
        final_epoch_credits - *new_credits_observed
    } else {
        // the staker has already observed or been redeemed this epoch
        //  or was activated after this epoch
        0
    };
    *new_credits_observed = (*new_credits_observed).max(final_epoch_credits);
    u128::from(earned_credits)
}

fn tower_epoch_credits_iter(
    stake: &Stake,
    epoch_credits_iter: impl Iterator<Item = (Epoch, u64, u64)>,
    stake_history: &StakeHistory,
    inflation_point_calc_tracer: Option<impl Fn(&InflationPointCalculationEvent)>,
    new_rate_activation_epoch: Option<Epoch>,
    use_fixed_point_stake_math: bool,
) -> (u128, u64, bool) {
    let mut points = 0;
    let credits_in_stake = stake.credits_observed;
    let mut new_credits_observed = credits_in_stake;
    let mut saw_marker = false;

    for entry in epoch_credits_iter {
        if entry == AG_MIGRATION_EPOCH_CREDIT {
            saw_marker = true;
            break;
        }
        let (epoch, final_epoch_credits, initial_epoch_credits) = entry;
        let earned_credits = calc_earned_credits(
            stake,
            final_epoch_credits,
            initial_epoch_credits,
            &mut new_credits_observed,
        );
        let stake_amount = u128::from(delegation_effective_stake(
            &stake.delegation,
            epoch,
            stake_history,
            new_rate_activation_epoch,
            use_fixed_point_stake_math,
        ));

        // finally calculate points for this epoch
        let earned_points = stake_amount * earned_credits;
        points += earned_points;

        if let Some(inflation_point_calc_tracer) = inflation_point_calc_tracer.as_ref() {
            inflation_point_calc_tracer(&InflationPointCalculationEvent::CalculatedPoints(
                epoch,
                stake_amount,
                earned_credits,
                earned_points,
            ));
        }
    }
    (points, new_credits_observed, saw_marker)
}

    pub fn increment_credits(&mut self, epoch: Epoch, credits: u64) {
        // increment credits, record by epoch

        // never seen a credit
        if self.epoch_credits().is_empty() {
            self.epoch_credits_mut().push((epoch, 0, 0));
        } else if epoch != self.epoch_credits().last().unwrap().0 {
            let (_, credits, prev_credits) = *self.epoch_credits().last().unwrap();

            if credits != prev_credits {
                // if credits were earned previous epoch
                // append entry at end of list for the new epoch
                self.epoch_credits_mut().push((epoch, credits, credits));
            } else {
                // else just move the current epoch
                self.epoch_credits_mut().last_mut().unwrap().0 = epoch;
            }

            // Remove too old epoch_credits
            if self.epoch_credits().len() > MAX_EPOCH_CREDITS_HISTORY {
                self.epoch_credits_mut().remove(0);
            }
        }

        self.epoch_credits_mut().last_mut().unwrap().1 = self
            .epoch_credits()
            .last()
            .unwrap()
            .1
            .saturating_add(credits);
    }
