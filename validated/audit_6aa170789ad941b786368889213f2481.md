Based on my investigation, the CVE-2020-28361 pattern (a header-removal function that performs naive/exact matching on a textual identifier, which an attacker can defeat by injecting whitespace, causing an entry that should be stripped/filtered to survive and be processed twice — leading to accounting/billing corruption) does not have a demonstrable analog in this codebase.

The closest candidates I inspected were call-filtering mechanisms that resemble "removal/filtering by identity":

- `pallet-recovery`'s reentrancy guard in `control_inherited_account`, which adds an origin filter rejecting any call that `is_sub_type()` of the Recovery pallet's own `Call` enum [1](#0-0) . This filter is type-based (`IsSubType`), not string/text based, so there is no whitespace-style bypass surface analogous to Kamailio's `remove_hf`. It is also checked recursively for every nested call (e.g. via `utility::batch`) through `OriginTrait::filter_call`, and the accompanying test confirms the filter is preserved rather than bypassed [2](#0-1) .
- FRAME's generic dispatch filtering (`RuntimeCall::dispatch` calling `OriginTrait::filter_call` before `dispatch_bypass_filter`) is also identity/type based, not string-based [3](#0-2) .
- The only textual header-matching code found (`sp_runtime::offchain::http::Headers::find`) does exact byte-for-byte comparison and is only used client-side by offchain workers reading HTTP responses — it is not part of consensus-critical dispatch, extrinsic validation, or any accounting mechanism, and is not attacker-reachable through a signed extrinsic, XCM, or contract call [4](#0-3) .

None of these constitute a "removal via naive text matching, bypassed via whitespace, causing double-processing/loss" analog reachable by an unprivileged signed extrinsic, XCM message, or contract call. Filtering, uniqueness, and identity checks across the pallets I reviewed (proxy/multisig/recovery/utility) rely on strongly-typed enum/`IsSubType` comparisons or SCALE-encoded equality rather than raw string parsing, so the invariant violated by CVE-2020-28361 (whitespace-defeatable string match in a security-relevant removal function) has no structurally equivalent, exploitable counterpart in the scanned production code.

	/// Retrieve a single header from the list of headers.
	///
	/// Note this method is linearly looking from all the headers
	/// comparing them with the needle byte-by-byte.
	/// If you want to consume multiple headers it's better to iterate
