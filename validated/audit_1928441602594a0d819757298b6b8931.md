### Title
Zero-Denominator Panic in `consolidatedNode.Split` Corrupts Block Finalization Reward Distribution — (`File: kaiax/staking/staking_info.go`)

---

### Summary

`consolidatedNode.Split()` divides by `totalAmount = StakingAmount + CLStakingAmount` without guarding against the case where both fields are zero. When the block proposer has a registered `CLStakingInfo` but both their CN-staking contract and CL pool balances round down to 0 KAIA, `FinalizeState` panics with a Go runtime division-by-zero, making every block that validator proposes impossible to finalize.

---

### Finding Description

`consolidatedNode.Split` in `kaiax/staking/staking_info.go` computes the CN/CL reward split as:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    cnAmount := big.NewInt(0).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0) 

`Split` is called unconditionally for the block proposer inside `specWithProposerAndFunds` and `specWithProposerAndFundsFlex` whenever `cn.CLStakingInfo != nil`:

```go

    break
}

``` [2](#0-1) [3](#0-2) 

Both `StakingAmount` and `CLStakingAmount` are stored in whole KAIA units, truncated from wei:

```go
stakingAmounts[i] = big.NewInt(0).Div(a, big.NewInt(params.KAIA)).Uint64()
// ...
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64(),
``` [4](#0-3) 

If a validator's CN-staking contract holds < 1 KAIA **and** their CL pool holds < 1 KAIA, both truncate to `uint64(0)`. With `CLStakingInfo != nil` (the pool is registered in CLRegistry), `totalAmount = 0 + 0 = 0`, and `big.Int.Div` panics unconditionally.

The staking-reward distribution paths (`assignStakingRewards`, `assignStakingRewardsFlex`) are **not** affected because they gate entry on `cn.StakingAmount >= minStake`, which prevents zero-total nodes from reaching `Split`. The proposer path has no such guard. [5](#0-4) 

The full call chain during block finalization:

```
FinalizeState
  → GetDeferredReward
    → getDeferredRewardFull
      → getDeferredRewardFullKore / getDeferredRewardFullFlex
        → specWithProposerAndFunds / specWithProposerAndFundsFlex
          → cn.Split(proposer)   ← panic: runtime error: integer divide by zero
```

---

### Impact Explanation

A Go `big.Int.Div` with a zero divisor raises an unrecovered runtime panic. During `FinalizeState`, this aborts block finalization for every block the affected validator proposes. The corrupted value is the **proposer's KAIA reward distribution** — the entire minted + fee reward for that block is never credited to any address. Depending on whether the panic is recovered upstream, the node either crashes or rejects its own proposed block, causing a consensus-round failure and a denial of service for that validator slot.

---

### Likelihood Explanation

The condition requires:
1. A validator registered in CLRegistry (has `CLStakingInfo != nil`).
2. Their CN-staking contract balance < 1 KAIA at the staking-snapshot block (rounds to 0).
3. Their CL pool balance < 1 KAIA at the same snapshot block (rounds to 0).
4. They are selected as block proposer.

Staking amounts are snapshotted 86 400 blocks in the past. A validator who registered a CL pool but whose balances have been nearly fully withdrawn — or who registered with dust amounts — satisfies conditions 2–3 while remaining in the active validator set until the next rotation. This is an edge case but requires no privileged access and no majority collusion; it is a valid on-chain state reachable by any registered validator.

---

### Recommendation

Add a zero-denominator guard in `consolidatedNode.Split`:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    cnAmountBig := big.NewInt(int64(c.StakingAmount))
    clAmountBig := big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
    totalAmount  := new(big.Int).Add(cnAmountBig, clAmountBig)

    // Guard: if both amounts are zero, give everything to CN (no CL split).
    if totalAmount.Sign() == 0 {
        return amount, big.NewInt(0)
    }

    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount   = clAmount.Div(clAmount, totalAmount)
    cnAmount  := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0)

### Proof of Concept

```
Setup (Prague hardfork active, reward.deferredtxfee = true):

1. Validator V registers in CLRegistry → CLStakingInfo{CLNodeId: V, CLPoolAddr: P, CLStakingAmount: 0}
   (CL pool balance = 0.4 KAIA < 1 KAIA → rounds to 0)

2. V's CN-staking contract balance = 0.3 KAIA < 1 KAIA → StakingAmount = 0

3. StakingInfo snapshot at block N contains:
     consolidatedNode{StakingAmount: 0, CLStakingInfo: &{CLStakingAmount: 0}}

4. V is selected as block proposer at block N + 86400.

5. FinalizeState calls getDeferredRewardFullKore → specWithProposerAndFunds:
     cn.RewardAddr == config.Rewardbase  ✓
     cn.CLStakingInfo != nil             ✓
     → cn.Split(proposer)
       totalAmount = big.NewInt(0) + big.NewInt(0) = 0
       clAmount.Div(clAmount, totalAmount)
       → panic: runtime error: integer divide by zero

6. Block finalization aborts. V's block is never committed.
   Every subsequent block V proposes triggers the same panic.
```
