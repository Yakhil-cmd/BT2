### Title
Interest accrual i128 overflow permanently bricks a market once debt value exceeds the RAY value ceiling — ([File: common/src/rates/scaling.rs])

### Summary
The reported class — a degenerate borrow rate that makes accrual revert and bricks the market — does not port verbatim: `calculate_annual_borrow_rate` already clamps utilization to `Ray::ONE` and caps the rate at `params.max_borrow_rate`, which is exactly the report's recommendation. However, the same *effect* (accrual panics on every verb → permanent market freeze) exists through a different root cause: interest accrual converts scaled debt to its original value with `scaled_to_original`, a `Ray::mul` that panics on i128 overflow. Once `borrowed_scaled × borrow_index` exceeds `i128::MAX` — reachable before `MAX_BORROW_INDEX_RAY` on any market whose debt value approaches ~1.7e38 RAY-raw — `accrue_step` panics, `global_sync` runs first on every pool verb, and the market freezes permanently with no admin or user escape hatch.

### Finding Description
`global_sync` in `contracts/pool/src/interest.rs` calls `accrue_step`, which computes the new debt value as `scaled_to_original(borrowed, borrow_index)`. `scaled_to_original` is `scaled.mul(env, index)` in `common/src/rates/scaling.rs` — it panics on overflow rather than saturating. The borrow-index cap `MAX_BORROW_INDEX_RAY = 1e36` is applied to the *index*, but the product `borrowed × index` is an unbounded RAY-raw value that must fit `i128` (~1.7e38). On a market with ≳1e27 raw debt units (e.g., ~1e9 tokens at 18 decimals, or a whale-scale 7-decimal market), the index reaches the value ceiling well before the index cap — at roughly 170× on the reference test. The in-repo test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` (`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361`) demonstrates exactly this: `update_indexes`, `withdraw`, and `repay` all revert with `MATH_OVERFLOW`, and the comment confirms "no repay, no withdraw, no liquidation" because every verb accrues first. `require_utilization_below_max` in `contracts/pool/src/guards.rs` itself multiplies `borrowed().mul_ceil(borrow_index)` and would hit the same panic, but accrual runs earlier. Unlike the Malda report, this is not fixable by an admin — `update_params`/recapitalize also accrue first.

### Impact Explanation
Permanent freezing of all funds in the affected (hub, token) book: suppliers cannot withdraw, borrowers cannot repay, liquidations cannot execute, bad debt cannot be cleaned (`clean_bad_debt` accrues), and revenue cannot be claimed. The freeze is total and irreversible — the panic is inside pure math on stored state, so no transaction ordering or parameter change bypasses it.

### Likelihood Explanation
An unprivileged attacker can drive a market toward this state by borrowing up to `max_utilization` and keeping utilization pinned near the cap (re-borrowing whenever repayments or liquidations lower it), maximizing rate-driven index growth. The precondition is a market large enough that ceiling-rounded debt value can approach 1.7e38 RAY-raw — a billion-scale 18-decimal market or an equivalently massive 7-decimal market — sustained at high utilization long enough for ~170× index growth. That requires an existing whale market and extended time, so the likelihood is low, but the state is reachable purely through permitted `borrow`/`supply`/`update_indexes` calls with no privileged action.

### Recommendation
Make the accrual path overflow-tolerant instead of panicking: saturate `scaled_to_original` (or the `borrowed × index` products in `accrue_step` and `require_utilization_below_max`) at `i128::MAX`, and/or clamp `borrowed` growth so the market can keep accruing — capped interest at the ceiling is strictly better than a permanent freeze. At minimum, ensure a non-accruing escape verb (e.g., bad-debt write-down or liquidation) remains callable after the ceiling is hit.

### Proof of Concept
`tests/test-harness/tests/controller/large_positions_and_long_horizons.rs:316-361` is already a working PoC:

1. Build a market (`BIG18`, 18 decimals) with `with_max_utilization_disabled_all_markets`, supply `principal = 1e9 × 1e18` raw units, borrow ~98% via `borrow_raw`.
2. Advance time in `YEAR_SECS` steps calling `update_indexes` until it returns `MATH_OVERFLOW` (observed in the low tens of years at the XLM curve's steep segment, before `MAX_BORROW_INDEX_RAY` engages).
3. Assert the freeze: `try_withdraw_raw(BOB, "BIG18", 1)` and `try_repay(ALICE, "BIG18", 1.0)` both revert with `MATH_OVERFLOW`; every other verb that calls `global_sync` reverts identically.

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
