### Title
Bad-debt wipeout clamps supply index up to `SUPPLY_INDEX_FLOOR_RAW`, leaving wiped suppliers a residual claim that drains future deposits - (File: contracts/pool/src/interest.rs)

### Summary
The ASN.1 "negative zero" bug class maps onto a zero-that-isn't-zero: a value that should be zero but is represented as a small positive, and is later interpreted as real. `apply_bad_debt_to_supply_index` produces exactly that shape. When a bad-debt seizure equals or exceeds the entire supplied value, `reduction_factor` is 0, so the computed index is 0 — but instead of zeroing supplier claims, the code clamps the index **up** to `SUPPLY_INDEX_FLOOR_RAW = RAY/1000`. Every pre-wipeout supply share keeps a positive floor-valued claim against a market that has no backing. The claim is only masked by `require_reserves` while cash is 0; the moment anyone supplies fresh tokens, the wiped position withdraws real cash, stealing the fresh deposit.

### Finding Description
In `apply_bad_debt_to_supply_index`, `capped = bad_debt.min(total_supplied_value)` and `remaining = total_supplied_value - capped`, so a full wipeout yields `remaining = 0` and `reduction_factor = 0`. The code then sets `supply_index = max(0, SUPPLY_INDEX_FLOOR_RAW)` = `RAY/1000` rather than resetting share supply to zero [1](#0-0) . The README states the index "falls on bad debt" and is "floored at `SUPPLY_INDEX_FLOOR_RAW`" [2](#0-1) , and invariants acknowledge the floor "can preserve an unbacked residual claim" [3](#0-2)  — but the contract contains no mechanism to retire the stranded shares, and `unscale_supply_floor` still values them at `scaled * RAY/1000` [4](#0-3) .

The exploit path is fully reachable by unprivileged addresses: `clean_bad_debt` on the controller (an in-scope entrypoint) seizes debt positions via `seize_positions`, whose Borrow side calls `apply_bad_debt_to_supply_index` and `burn_debt` [5](#0-4) . A wipeout is triggered whenever `unscale_borrow_ceil_ray(seized_scaled) >= supplied * supply_index` — e.g., a heavily undercollateralized market where the debt's accrued value meets the (shrunken, e.g., post-cascade or low-liquidity) total supply value.

The codebase's own tests prove the drain: `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` shows a wiped supplier's stranded claim equals exactly the next depositor's deposit, and after their withdrawal "pool cash can no longer cover fresh supplier claim" [6](#0-5) ; `test_raw_cache_seizure_residual_would_drain_fresh_cash_without_supply_guard` shows `gross == deposit` — "Alice extracts exactly Bob's fresh deposit" [7](#0-6) .

### Impact Explanation
Theft of user funds / protocol insolvency. After a total bad-debt wipeout, all pre-wipeout `supplied` shares retain claims worth `scaled * 10^24` — a non-zero residual on a zero-backing market. The first honest depositor's cash funds the wiped suppliers' withdrawals one-for-one until cash is exhausted. Magnitude: the stranded claim per share is 1/1000 of the pre-wipeout unit value, so a wiped supplier whose balance was, e.g., 1,000,000 USDC at index 1.0 keeps a ~1,000-USDC claim and every wiped supplier races to withdraw it from the recapitalized pool. New depositors lose funds they just deposited.

### Likelihood Explanation
Requires a full bad-debt wipeout: `seized debt value ≥ total supplied value`. This happens when a market's suppliers have largely exited (low liquidity), collateral prices collapse, and `clean_bad_debt`/liquidation writes off the remaining debt. It is a tail event but does not require privileged action — liquidations and `clean_bad_debt` are permissionless. The dormant stranded claim then executes automatically on the next `supply`+`withdraw` pair, which any wiped supplier can submit.

### Recommendation
On full wipeout (`remaining == 0`), reset `supplied`, `revenue`, and each outstanding position's scaled amount to zero (or set `supply_index` to 0 and treat zero-index markets as burned) instead of clamping the index up. At minimum, when `capped == total_supplied_value`, burn all supply and revenue shares atomically in the same seize path so no `scaled_amount` survives with a positive `unscale_supply_floor` value. Also gate `supply` on markets whose index is at `SUPPLY_INDEX_FLOOR_RAW` with nonzero `supplied` unless the residual is first burned.

### Proof of Concept
1. Market M has supplier Bob with `S` shares at `supply_index = Is`; Alice's bad debt `D` satisfies `unscale_borrow_ceil(D) ≥ S * Is` (deeply insolvent account, e.g., after a price crash on thin liquidity).
2. Keeper calls `clean_bad_debt` → `seize_positions(Borrow, D)` → `apply_bad_debt_to_supply_index`: `capped = total_value`, `remaining = 0`, `supply_index := max(0, RAY/1000) = RAY/1000` [8](#0-7) .
3. Bob's shares are not burned; his claim is now `floor(S * 10^24 / 10^(27-d))` > 0 tokens against `cash = 0`.
4. Fresh depositor Carol calls `supply` → `mint_supply` + `credit_cash` [9](#0-8) .
5. Bob calls `withdraw` with `WITHDRAW_ALL` → `resolve_withdrawal` burns all shares and pays `floor` gross; `require_reserves` passes because Carol's cash is present [10](#0-9) .
6. Bob receives Carol's deposit; Carol's own claim is now unbacked — `cash < unscale_supply_floor(Carol_shares)` (per the in-repo test asserting `cash < bob_claim`) [11](#0-10) .
