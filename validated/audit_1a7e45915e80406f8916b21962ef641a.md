### Title
Protocol revenue minted on uncollectible interest can be claimed as real cash before bad-debt write-down — ([File: contracts/pool/src/interest.rs])

### Summary
`update_indexes` accrues interest on all outstanding `borrowed` shares — including debt that is already hopelessly insolvent and will never be repaid — and mints a `reserve_factor` cut of that interest as protocol revenue shares (`accrue_step` → `protocol_fee_shares` → `accrue_revenue`). `claim_revenue` is permissionless and pays out `min(cash, revenue_claim)` in real tokens to the accumulator before any cleanup. When `clean_bad_debt`/`seize_positions` later writes the debt down, `apply_bad_debt_to_supply_index` socializes the **gross accrued debt** (principal + phantom interest) across suppliers. The result mirrors the reported bug class: fees are charged on an assumed value that includes defaulted debt, are paid out for real, while the corresponding deficit is pushed entirely onto suppliers.

### Finding Description
In `common/src/rates/simulate.rs::accrue_step`, the fee split `calculate_supplier_rewards` computes `protocol_fee` from `borrowed × (new_borrow_index − old_borrow_index)` with no check that the debt is collectible [1](#0-0) . `accrue_chunk` then mints `revenue_shares` into both `revenue` and `supplied` [2](#0-1) .

`burn_claimable_revenue` pays out `min(cash, floored revenue claim)` in real tokens [3](#0-2) , reached via the controller's `claim_revenue`, which only requires `require_authorized_caller` (i.e., `caller.require_auth()`) and forwards to the accumulator [4](#0-3) . `update_indexes` is likewise callable by any signer [5](#0-4) .

Separately, bad-debt cleanup writes off the debt at its full accrued value: `apply_bad_debt_to_supply_index` reduces the supply index by `bad_debt / total_supplied_value` where `bad_debt` is the ceiled debt **including** the accrued interest on which fees were already minted [6](#0-5) . ADR-0021 confirms cleanup socializes gross debt without netting [7](#0-6) .

### Impact Explanation
Theft of user funds / protocol insolvency in bounded amount. The treasury extracts `reserve_factor × accrued_interest_on_bad_debt` in real tokens, while suppliers later absorb a write-down computed on the entire accrued debt (principal + interest). The fee portion of the phantom interest is thus paid twice from the suppliers' perspective: once to the accumulator in cash, once inside the socialized loss. With a large reserve factor and a debt left to accrue (e.g., a position whose collateral is `no_seize`-flagged or priced to make liquidation unprofitable, so cleanup is delayed), the extractable amount grows with time until the borrow index cap.

### Likelihood Explanation
Any unprivileged address can (1) create a borrow position, (2) wait while calling `update_indexes` so interest — and revenue shares — accrue on debt that becomes unpayable after a price move, (3) call `claim_revenue` to push the minted fee to the accumulator as real cash, and (4) let `clean_bad_debt` (permissionless once collateral ≤ $5 dust, INV-LIQ-04) socialize the gross debt. No privileged action is required at any step; the only constraint is that a real accumulator must be configured.

### Recommendation
Exclude demonstrably uncollectible interest from the fee base, or net it during cleanup: e.g., on `seize_positions`/write-down, claw back the revenue shares minted from interest on the written-off tranche of debt (tracked per debt share cohort, or approximated by burning `reserve_factor × written_off_interest / supply_index` revenue shares before applying the index reduction). Alternatively, gate `claim_revenue` on `backing_shortfall == 0` so revenue cannot be paid out of a market carrying a shortfall.

### Proof of Concept
1. BOB supplies 1,000 USDC. ALICE supplies ETH collateral and borrows 100 USDC.
2. ETH price crashes; ALICE's debt is unpayable but cleanup is delayed (collateral above $5 dust, or liquidators unprofitable).
3. Over time, anyone calls `update_indexes([USDC])`: `accrue_step` grows `borrow_index`, mints `revenue_shares = reserve_factor × accrued_interest / supply_index`.
4. Anyone calls `claim_revenue([USDC])`: `burn_claimable_revenue` pays `min(cash, revenue_claim)` real USDC to the accumulator — cash backed by interest ALICE will never pay.
5. `clean_bad_debt(alice_account)` → `execute_bad_debt_cleanup` → `seize_positions` writes down the supply index by the full accrued debt (principal + the same interest already paid out as fees). Suppliers' claims are reduced by more than the true loss; the treasury keeps the extracted fee cash.

pub(crate) fn apply_bad_debt_to_supply_index(cache: &mut Cache, bad_debt: Ray) {
    let total_supplied_value = cache.supplied().mul(cache.env(), cache.supply_index());

    if total_supplied_value == Ray::ZERO {
        return;
    }

    let capped = bad_debt.min(total_supplied_value);
    let remaining = total_supplied_value.checked_sub(cache.env(), capped);

    let reduction_factor = remaining.div_floor(cache.env(), total_supplied_value);
    let new_supply_index = cache
        .supply_index()
        .mul_floor(cache.env(), reduction_factor);

    cache.set_supply_index(new_supply_index.max(Ray::from(SUPPLY_INDEX_FLOOR_RAW)));
}

    pub(crate) fn burn_claimable_revenue(&mut self) -> i128 {
        let treasury_actual = self.unscale_supply_floor(self.revenue);
        let amount = self.cash.min(treasury_actual);
        if amount <= 0 {
            return 0;
        }
        let scaled_to_burn = if amount >= treasury_actual {
            self.revenue
        } else {
            self.revenue
                .mul_ratio_ceil(&self.env, amount, treasury_actual)
        };

        assert_with_error!(
            self.env,
            scaled_to_burn != Ray::ZERO,
            GenericError::InternalError
        );
        self.revenue = self.revenue.checked_sub(&self.env, scaled_to_burn);
        self.supplied = self.supplied.checked_sub(&self.env, scaled_to_burn);
        amount
    }

Cleanup converts remaining account supply to protocol revenue, then socializes
