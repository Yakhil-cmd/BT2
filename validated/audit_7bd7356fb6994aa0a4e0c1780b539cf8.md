### Title
Webhook signature verification binds to the payload's `organization`/`repository.owner`, but downstream handlers act on the payload's `repository.full_name` — allowing a different org's webhook secret to authorize writes to any repository - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/`webhook_secret` used for HMAC verification based on `repository_owner`, computed as `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`. Once the signature is accepted, every webhook `Handler` (via the shared `Handler#repository_name` method) resolves the target `Stack` from a *different* field of the same untrusted JSON body: `payload.dig('repository', 'full_name')`. Nothing ties these two fields together, so a signature computed with organization A's secret can be replayed with `repository.full_name` pointing at organization B's repository.

### Finding Description
Shipit supports configuring multiple independent GitHub Apps/organizations, each with its own `webhook_secret` [1](#0-0) . The webhook signature check picks the app/secret to verify against solely from the "owner" fields of the raw JSON body: [2](#0-1) [3](#0-2) 

`verify_webhook_signature` then simply HMACs the raw body with that resolved organization's own `webhook_secret` and compares it to `X-Hub-Signature`: [4](#0-3) 

After this check passes, every concrete handler (push, status, check_suite, membership, pull_request, etc.) resolves which `Repository`/`Stack` to mutate using a *separate* field of the same body: [5](#0-4) 

There is no code anywhere that checks `payload['repository']['full_name']`'s owner segment against `repository_owner` used for signature verification. Consequently, an attacker who legitimately controls a GitHub App/organization installation of Shipit (e.g., their own org "attacker-org", with a webhook secret they know because they installed it themselves) can:

1. Build a raw JSON webhook body where `organization.login` / `repository.owner.login` = `"attacker-org"` (so `Shipit.github(organization: "attacker-org")` picks attacker-org's own known `webhook_secret`), while `repository.full_name` = `"victim-org/victim-repo"`.
2. Sign that raw body with attacker-org's own `webhook_secret` and set `X-Hub-Signature` accordingly — this passes `verify_signature` because verification only ever checks against attacker-org's secret.
3. Because `stacks`/`repository_name` in `Handler` reads `repository.full_name` — not `repository_owner` — from the same body, the event is dispatched against the victim's `Stack`.

This breaks the equality that should hold: `organization authenticated by X-Hub-Signature == owner of the repository the handler mutates`. Concretely, `PushHandler` would call `stack.sync_github` for the victim's stack [6](#0-5) , and `StatusHandler`/`CheckSuiteHandler` would create/refresh CI status data for a victim commit found via the same `full_name`-derived stack scope [7](#0-6) .

### Impact Explanation
An attacker with no privileges on the victim's repository or organization — only a legitimate, independently-configured GitHub App installation of Shipit for their own org — can inject arbitrary GitHub events (push notifications, commit statuses, check-suite refreshes, membership/team changes) against any other org's stack tracked by the same Shipit instance. If a targeted commit's required CI status is spoofed to `success` via the `StatusHandler` path, an otherwise-unreviewed/failing commit can become `deployable?` for continuous delivery or manual deploy, resulting in an **unauthorized deploy** — one of the accepted Critical impacts.

### Likelihood Explanation
This requires: (a) the target Shipit instance to be configured for multiple GitHub organizations (a documented, supported configuration [8](#0-7) ), and (b) the attacker to control at least one of those organizations' GitHub App installations (which they may legitimately own/administer without any relation to the victim org). No Shipit session, API token, or victim webhook secret is required — only knowledge of a webhook secret the attacker legitimately possesses for their own onboarded organization.

### Recommendation
When resolving the target repository/stack in `Handler#repository_name` (and all handlers), verify that the repository's owner matches the organization whose secret validated the signature (i.e., pass the authenticated `repository_owner` through to handlers and assert it equals the owner segment of `repository.full_name`/`repository.owner.login` before acting), rather than trusting two independently-controlled fields of the same unauthenticated JSON body.

### Proof of Concept
1. Configure Shipit with two orgs, `attacker-org` (secret `S_A`, known to attacker) and `victim-org` (tracks a real `Stack`).
2. Attacker crafts:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha, e.g. a passing commit>",
  "organization": { "login": "attacker-org" },
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
}
```
3. Attacker computes `X-Hub-Signature: sha1=HMAC-SHA1(S_A, body)` and POSTs to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` resolves `repository_owner` → `"attacker-org"`, fetches `Shipit.github(organization: "attacker-org")`, and validates the HMAC successfully against `S_A`.
5. `PushHandler#process` uses `repository_name = payload.dig('repository','full_name') == "victim-org/victim-repo"` to find and sync `victim-org`'s stack — an event fully controlled by the attacker was accepted and applied to a repository the attacker's authenticated organization does not own.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

**File:** lib/shipit/github_app.rb (L76-83)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
