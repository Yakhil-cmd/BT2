Missing sender-authorization check in `new_shared_address` handling lets any paired correspondent register a bogus co-signed address that the victim's wallet treats as its own — (File: wallet_defined_by_addresses.js)

### Summary
The `"new_shared_address"` device-message handler validates only that the supplied definition's c-hash matches the supplied address and that the declared signer addresses match the leaves of the definition. It never verifies that the message sender (`from_address`, an arbitrary paired correspondent) is actually one of the parties named in the definition it is proposing, nor that the victim previously agreed to this specific address grouping via the `create_new_shared_address` / template-approval flow. This is the same class of bug as the askbot report: an authenticated-but-unprivileged party can act on/modify an object (here, register a "shared address" bound to the victim's own real address) that should require the counterpart's explicit consent.

### Finding Description
The wallet message dispatcher accepts `"new_shared_address"` from any known correspondent and forwards straight to `handleNewSharedAddress`: [1](#0-0) 

`handleNewSharedAddress` only checks structural validity of the definition/signers, not that the sender is entitled to declare this grouping: [2](#0-1) 

The only "ownership" check performed is `determineIfIncludesMeAndRewriteDeviceAddress`, which merely confirms that *some* address referenced in the definition happens to belong to the victim (`my_addresses`/`shared_addresses`) — it does not confirm that the victim (or any legitimate cosigner) ever agreed to combine that address with the attacker's address under this particular boolean definition, and it does not touch the attacker-supplied `device_address` mappings for the other signing paths at all: [3](#0-2) 

`validateAddressDefinition` itself is explicitly annotated as incomplete ("fix: 1. check that my address is referenced in the definition") and is additionally run with `bAllowUnresolvedInnerDefinitions: true`, further weakening the checks that would normally reject an inconsistent/unauthorized grouping: [4](#0-3) 

Once `addNewSharedAddress` inserts the row into `shared_addresses`/`shared_address_signing_paths`, the synthetic address is treated by the rest of the wallet exactly like a genuinely negotiated multi-sig address: it is included in `readMyAddresses()` (used to decide what belongs to the user across balance/payment-detection logic) and in `readSharedAddressesOnWallet()` (used to compute shared balances shown in the UI): [5](#0-4) [6](#0-5) 

The proper, consent-based path for creating a shared address is `create_new_shared_address` → `validateAddressDefinitionTemplate`, which explicitly requires that the sender's own device address is one of the negotiated template placeholders: [7](#0-6) 

`handleNewSharedAddress` bypasses this negotiation entirely — the attacker can construct the final `definition`/`address` themselves and push it directly, skipping the template-approval consent step.

### Impact Explanation
An attacker who is merely a paired correspondent (no special privilege) can craft a definition such as `["or", [["address","VICTIM_REAL_ADDRESS"], ["address","ATTACKER_ADDRESS"]]]`, compute its c-hash, and send it as `new_shared_address`. Because `VICTIM_REAL_ADDRESS` is genuinely one of the victim's addresses, `determineIfIncludesMeAndRewriteDeviceAddress` succeeds, and the victim's node silently records this synthetic address as a legitimate shared address it participates in. The address is then folded into `readMyAddresses`/shared-balance views used elsewhere in the wallet for output/fund selection. If the victim (or anyone) later sends value to this synthetic "shared" address — e.g., believing it's a protected multi-party address surfaced by their own wallet — the `"or"` condition allows the attacker to spend those funds unilaterally, with no cooperation from the victim. This is unauthorized spending / fund loss stemming from an inexhaustive authorization check, matching the CWE-639 class of the reference advisory.

### Likelihood Explanation
Any two devices that are paired correspondents (a very low bar — pairing is a routine, low-trust operation in this wallet system) can trigger this: the attacker only needs to know one of the victim's real on-chain addresses (addresses are inherently public once used) and send a single crafted device message. No cryptographic signature over the *combination* is required, and the flow explicitly documents ("fix: ... check that my address is referenced") that this validation gap is a known incompleteness rather than a one-off oversight.

### Recommendation
In `handleNewSharedAddress`, require proof that every device address mapped in `body.signers` is either (a) the actual sender authenticated via the device-message signature and directly proven to control the corresponding member address, or (b) obtained through the already-negotiated `pending_shared_addresses`/`pending_shared_address_signing_paths` approval flow (`create_new_shared_address` → `approve_new_shared_address`), rather than accepted as an unauthenticated assertion in an unsolicited `new_shared_address` message. Reject `new_shared_address` messages that don't correspond to a `pending_shared_addresses` record the local device itself initiated or approved. Also complete the TODO in `validateAddressDefinition` to enforce that the local user's address is referenced and that the definition was mutually agreed, and avoid `bAllowUnresolvedInnerDefinitions: true` for externally supplied definitions.

### Proof of Concept
1. Attacker device pairs with victim device (ordinary pairing, no special trust).
2. Attacker learns `VICTIM_ADDRESS` (any of victim's addresses visible from the DAG).
3. Attacker builds `arrDefinition = ["or", [["address","VICTIM_ADDRESS"], ["address","ATTACKER_ADDRESS"]]]`, computes `address = chash160(arrDefinition)`.
4. Attacker sends device message `{subject: "new_shared_address", body: {address, definition: arrDefinition, signers: {"r.0": {address: "VICTIM_ADDRESS"}, "r.1": {address: "ATTACKER_ADDRESS", device_address: ATTACKER_DEVICE}}}}`.
5. Victim's `handleNewSharedAddress` accepts it (definition hashes match, signer addresses match leaves, `VICTIM_ADDRESS` is in `my_addresses`) and calls `addNewSharedAddress`, persisting the record with no consent step.
6. The new address now appears via `readMyAddresses()`/shared-balance queries as belonging to the victim; if the victim (or a third party) funds this address, the attacker can spend it alone via the `"or"` branch, without any victim signature.

// It is possible that my device address is not mentioned in the definition if I'm a member of multisig address, one of my cosigners is mentioned instead
function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function readSharedAddressesOnWallet(wallet, handleSharedAddresses){
	db.query("SELECT DISTINCT shared_address_signing_paths.shared_address FROM my_addresses \n\
			JOIN shared_address_signing_paths USING(address) \n\
			LEFT JOIN prosaic_contracts ON prosaic_contracts.shared_address = shared_address_signing_paths.shared_address \n\
			WHERE wallet=? AND prosaic_contracts.hash IS NULL", [wallet], function(rows){
		var arrSharedAddresses = rows.map(function(row){ return row.shared_address; });
		if (arrSharedAddresses.length === 0)
			return handleSharedAddresses([]);
		readSharedAddressesDependingOnAddresses(arrSharedAddresses, function(arrNewSharedAddresses){
			handleSharedAddresses(arrSharedAddresses.concat(arrNewSharedAddresses));
		});
	});
}
