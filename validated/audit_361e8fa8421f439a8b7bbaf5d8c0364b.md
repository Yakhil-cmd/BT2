## Tracing the Exploit Path

**State:** committed state nonce for sender = N; non-gasless tx at nonce N is in pending pool; sender has **no allowance** set for the router.

### Step 1 — Swap tx admission (`checkBalanceForSwap`) [1](#0-0) 

`senderNonce = getCurrentStateNonce(sender)` reads from `currentState`, which is the **committed** (post-block) state, not the pending state. [2](#0-1) 

With state nonce = N and swap nonce = N+1:
- `noApproveTxPreceeds = (N+1 == N)` → **false**
- The allowance check block is **skipped entirely**
- The token balance check still runs (passes if sender holds tokens)
- Swap tx is admitted to the queue

### Step 2 — Promotion check (`isSwapTxReady`) [3](#0-2) 

With state nonce = N and swap nonce = N+1:
- Enters the `swapTx.Nonce() == nonce+1` branch
- Checks `!g.IsApproveTx(prevTx)` — the non-gasless tx is **not** an ApproveTx → **returns false**
- Swap tx stays in queue; not promoted yet

### Step 3 — Non-gasless tx at nonce N is mined [4](#0-3) 

`PostInsertBlock` updates `currentState` to the new committed state. State nonce is now N+1. The txpool resets and re-evaluates the swap tx.

### Step 4 — Re-promotion after block (`isSwapTxReady` again)

Now state nonce = N+1, swap nonce = N+1:
- Enters the `swapTx.Nonce() == nonce` branch → `approveTx = nil`
- Calls `IsExecutable(nil, swapTx)` → `VerifyExecutable(nil, swapTx)` [5](#0-4) 

`VerifyExecutable` with `approveTxOrNil = nil` only checks: state nonce matches swap nonce, and `amountRepay == repayAmount(nil, swapTx)`. **There is no allowance check here.** The swap tx is promoted to pending.

Critically, `GetCheckBalance` / `checkBalanceForSwap` is **not called again** during re-promotion — it is only called at initial tx admission.

### Step 5 — Bundle extraction and execution [6](#0-5) 

`ExtractTxBundles` sees `approveTxs[addr] = nil`, `IsExecutable(nil, swapTx)` passes, and builds bundle `[LendTx, SwapTx]`. [7](#0-6) 

LendTx sends `lendAmount` KAIA to the sender. Then SwapTx calls `swapForGas` on the router. The router attempts `transferFrom(sender, router, amountIn)` — **no allowance was ever set** — the router reverts. The lend amount is not recovered. The lender (proposer/CN) loses `lendAmount` KAIA.

---

## Verdict

The allowance bypass is real and the lender loss is real. The attack is fully permissionless (public RPC, two ordinary transactions). The only precondition is that the sender holds sufficient token balance (to pass the balance check at admission) but has set no allowance.

### Title
Stale committed-state nonce in `checkBalanceForSwap` allows allowance check bypass, causing lender KAIA loss — (`kaiax/gasless/impl/tx_pool.go`)

### Summary
`checkBalanceForSwap` uses `getCurrentStateNonce` (committed state) to decide whether to verify allowance. When a non-gasless tx occupies nonce N in pending, a swap tx at nonce N+1 is admitted without an allowance check. After the non-gasless tx is mined, the swap tx is re-promoted as a swap-only bundle without re-running the allowance check, causing the lender to lose `lendAmount` KAIA when the router reverts.

### Finding Description
`getCurrentStateNonce` reads from `g.currentState`, which is updated only in `PostInsertBlock` (committed state). When a non-gasless tx at nonce N is pending and a swap tx at nonce N+1 is submitted:

1. `noApproveTxPreceeds = (N+1 == N)` → false → allowance check skipped at admission.
2. `isSwapTxReady` rejects promotion (prevTx is not ApproveTx).
3. After the non-gasless tx is mined, state nonce = N+1; `isSwapTxReady` now treats the swap as a swap-only bundle (`approveTx = nil`) and promotes it — without re-running `checkBalanceForSwap`.
4. `VerifyExecutable(nil, swapTx)` has no allowance check.
5. Bundle `[LendTx, SwapTx]` is built and executed; the router reverts due to missing allowance; lender loses `lendAmount`.

### Impact Explanation
The lender (proposer/CN node) loses `lendAmount` KAIA per exploited bundle. `lendAmount = ApproveTx.Fee + SwapTx.Fee` (or just `SwapTx.Fee` for swap-only). This is an unauthorized transfer of KAIA from the lender with no recovery path.

### Likelihood Explanation
The attack requires only two public RPC transactions (a non-gasless tx at nonce N and a crafted swap tx at nonce N+1) and token balance ≥ `amountIn`. No privileged access, governance keys, or validator collusion is needed. The attacker can repeat this for each gasless-enabled block proposer.

### Recommendation
In `checkBalanceForSwap`, use the **pending** nonce (i.e., the txpool's pending nonce for the sender) rather than the committed state nonce to determine `noApproveTxPreceeds`. Alternatively, re-run `checkBalanceForSwap` (or at minimum the allowance check) inside `isSwapTxReady` / `VerifyExecutable` when `approveTx == nil`, so that allowance is always verified before a swap-only bundle is promoted.

### Proof of Concept
1. Sender holds `amountIn` tokens, allowance for router = 0.
2. Submit non-gasless tx (e.g., self-transfer) at nonce N via public RPC.
3. Submit swap tx at nonce N+1 with `amountRepay = repayAmount(nil, swapTx)` via public RPC.
4. Observe: swap tx admitted (allowance check skipped), stays in queue.
5. Wait for non-gasless tx to be mined (state nonce → N+1).
6. Observe: swap tx promoted as swap-only bundle; bundle `[LendTx, SwapTx]` included in next block.
7. Assert: lender balance decreased by `lendAmount`; swap tx receipt shows revert; sender token allowance still 0.

```go
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}
```
