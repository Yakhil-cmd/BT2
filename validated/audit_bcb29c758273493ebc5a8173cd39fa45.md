### Title
CCMenu status endpoint bypasses per-token stack scoping, allowing read of any stack's build status - (File: `app/controllers/shipit/api/ccmenu_controller.rb`)

### Summary
`Shipit::Api::BaseController` enforces a binding between an `ApiClient` token and the stack(s) it is allowed to touch: whenever a client has a `stack_id` set, `#stacks`/`#stack` restrict the visible `Stack` to that one record. `Shipit::Api::CCMenuController` overrides `#stack` and looks the stack up directly from `Stack.from_param!(params[:stack_id])`, discarding that scoping. Any valid `read:stack` token — including one deliberately scoped to a single stack — can therefore be used to read the CCTray/CCMenu status (deploy history, last build status/label/time) of **any** stack in the installation.

### Finding Description
The base controller defines the intended binding "token authorises stack X" ⇔ "controller touches stack X": [1](#0-0) 

`stacks` filters to `Stack.where(id: current_api_client.stack_id)` when the client is stack-scoped, and `stack` looks the requested `params[:stack_id]` up only within that filtered relation, raising a not-found error if the client tries to access a different stack.

`CCMenuController`, however, defines its own `#stack` method that ignores this scoping entirely and resolves the record from the full `Stack` table: [2](#0-1) 

The permission check only verifies that the token carries the `read:stack` permission string, never that the token's `stack_id` (if any) matches the requested `params[:stack_id]`: [3](#0-2) [4](#0-3) 

So the equality that should hold — `current_api_client.stack_id ∈ {nil, requested_stack.id}` — is checked for every other API endpoint via `BaseController#stack`, but is silently dropped for this one endpoint. Any correctly-signed, non-expired `read:stack` token (e.g. the `here_come_the_walrus` fixture scoped to the `shipit` stack, or a real client created through `ApiClientsController` with a specific `stack_id`) authenticates successfully via `authenticate_api_client` (which just calls `ApiClient.authenticate(params[:token])`), passes the `require_permission :read, :stack` check, and then can supply an arbitrary `stack_id` in the URL to view a completely different stack's CI/deploy status.

### Impact Explanation
This is a read-only escalation: a token that was only ever authorized (by its creator) to interact with one specific stack can be used to read the build/deploy status of every other stack in the Shipit instance via the CCMenu XML feed. This matches the in-scope High-impact category of "unauthenticated [w.r.t. that resource]/unauthorized read of stack state, task streams or deploy output" — the token authorizes stack A but the controller lets it touch stack B, breaking the trust boundary that the rest of the API enforces.

### Likelihood Explanation
Likelihood is high for any deployment that issues stack-scoped `ApiClient` tokens (a normal, documented feature: `ApiClient belongs_to :stack, optional: true`, exercised e.g. by the `here_come_the_walrus` fixture and by `ApiClientsController`). No special privilege beyond possessing one legitimately-scoped `read:stack` token is required, and exploitation is a single unauthenticated-parameter GET request (`?token=...&stack_id=<other-stack>`).

### Recommendation
Make `CCMenuController#stack` use the scoped `stacks` relation from `BaseController` (i.e. `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so the same `current_api_client.stack_id` binding enforced everywhere else in the API is also enforced for the CCMenu endpoint.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to `stack: shipit_stack_A` with permission `read:stack` and note its `authentication_token`.
2. Request `GET /shipit/stacks/:owner/:repo/:env/ccmenu.xml` equivalent API route `api_stack_ccmenu_url` but substitute `stack_id` for `stack_B` (a different, unrelated stack) while keeping `token=<stack_A's token>`.
3. Observe the response returns `stack_B`'s CCMenu project XML (name, `lastBuildStatus`, `lastBuildLabel`, `lastBuildTime`), even though the token was only ever authorized for `stack_A`, because `CCMenuController#stack` (`app/controllers/shipit/api/ccmenu_controller.rb:29-31`) resolves the stack unscoped instead of via `BaseController#stacks` (`app/controllers/shipit/api/base_controller.rb:74-80`).
