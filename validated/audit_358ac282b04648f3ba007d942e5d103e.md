### Title
Unauthenticated webhook signature bypass allows forging `membership` events that grant `Shipit.github_teams` authorization - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` picks which GitHub organization's webhook secret to validate a delivery against by reading an attacker-controlled field out of the very payload it is about to verify, and `GithubApp#verify_webhook_signature` treats a missing/blank secret as "verified." Combined with the `membership` webhook handler, which creates `Team`/`Membership` records straight from payload data, an attacker who knows (or guesses) that any configured organization in `Shipit.github` has no `webhook_secret` set can forge a `membership` webhook that is accepted as authentic and use it to grant an arbitrary GitHub login membership in a team matching `Shipit.github_teams`, escalating that account into Shipit's privileged team authorization with no GitHub credentials, session, or API token at all.

### Finding Description
The webhook entrypoint determines which org's secret to check against using data taken from the unauthenticated request body itself: [1](#0-0) [2](#0-1) 

`repository_owner` is computed from `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` — both fully attacker-supplied for events (like `membership`) that carry an `organization` object but no `repository` object.

`Shipit.github(organization: repository_owner)` then resolves to a per-org `GithubApp` instance configured in `Shipit.github` (see `config/secrets.development.shopify.yml`, where `webhook_secret` can legitimately be left `nil`). Signature verification in that app instance is: [3](#0-2) 

`return true unless webhook_secret` means any organization entry configured without a webhook secret makes verification a no-op — any payload claiming to be from that organization is accepted regardless of its actual origin or content.

The `membership` webhook handler (exercised by `test/controllers/webhooks_controller_test.rb`) then creates `Team` and `Membership` records directly from the (now-unverified) payload: [4](#0-3) 

Authorization in the app is ultimately gated by team membership: [5](#0-4) 

`User#authorized?` returns true if the user belongs to any team whose id is present in `Shipit.github_teams`. Because the `membership` handler creates memberships purely from attacker-controlled `team` and `member` fields in the webhook body, and the org used to "authenticate" that webhook can be one with no configured secret, an attacker can add any GitHub login to a `Team` object matching a `Shipit.github_teams` entry — without ever touching the org that actually owns that team, and without any GitHub App private key, session, or `ApiClient` token.

### Impact Explanation
This breaks the binding between "the organization the webhook signature authenticates" and "the team/membership state that gets written," letting an unauthenticated network attacker forge team membership data that Shipit's own authorization model (`User#authorized?`) trusts. This directly matches the High-severity category of "escalation into `Shipit.github_teams` authorization" called out in scope, since gaining membership in a recognized team elevates a user account to be treated as authorized to deploy/ship within the engine.

### Likelihood Explanation
Exploitation requires only that at least one organization entry in the operator's `Shipit.github` configuration has a blank/nil `webhook_secret` — a state the codebase and documentation explicitly support (`config/secrets.development.shopify.yml` ships with `webhook_secret: # nil`, and `docs/setup.md` treats it as optional). Any Shipit instance run with such a configuration (e.g. during rollout, multi-org setups where one org's secret was never set) is exploitable by a fully unprivileged, unauthenticated network attacker sending a single crafted HTTP POST — no credential, session, or prior access of any kind is needed.

### Recommendation
Do not select the verifying organization/secret from unauthenticated, attacker-controlled payload fields; instead require every configured organization to have a non-blank `webhook_secret` (fail closed, not open, when one is missing) and reject webhooks whose claimed organization does not match a verifiable secret. Additionally, do not let the `membership` handler write `Membership`/`Team` records for teams contained in `Shipit.github_teams` without corroborating that the webhook truly originated from the GitHub organization that owns that team.

### Proof of Concept
1. Operator configures two orgs in `Shipit.github`: `trusted-org` (has `webhook_secret` set, owns a team present in `Shipit.github_teams`) and `throwaway-org` (no `webhook_secret` configured, as shown to be a supported state in `config/secrets.development.shopify.yml`).
2. Attacker sends `POST /github/webhooks` with header `X-Github-Event: membership` and body:
```json
{
  "action": "added",
  "organization": { "login": "throwaway-org" },
  "team": { "id": <id-of-privileged-team>, "name": "Deployers", "slug": "deployers" },
  "member": { "login": "attacker-github-login" }
}
```
3. `repository_owner` resolves to `throwaway-org` (`app/controllers/shipit/webhooks_controller.rb:59-62`); `Shipit.github(organization: "throwaway-org").verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is blank (`lib/shipit/github_app.rb:76-77`).
4. The membership handler creates a `Membership` linking `attacker-github-login` to the privileged team (mirrors `test/controllers/webhooks_controller_test.rb:142-149`).
5. `attacker-github-login`, upon logging in via OAuth (`app/controllers/shipit/github_authentication_controller.rb`), now satisfies `User#authorized?` (`app/models/shipit/user.rb:80-82`), gaining Shipit's privileged authorization despite never being granted access by the actual trusted organization.

**File:** lib/shipit/github_app.rb (L76-83)
```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
