### Title
`GovernanceGoverningNode` vote consistency check validates the wrong address, allowing governance to be permanently locked — (`kaiax/gov/headergov/impl/header.go`)

### Summary
The `checkConsistency` function for `GovernanceGoverningNode` votes checks whether the *current* governing node is in the council, but never verifies that the *new* governing node (the vote value) is in the council. A vote to change the governing node to an address not in the council passes all validation and is ratified at the epoch block. After ratification, the new governing node cannot cast votes (not in council), permanently locking governance in single mode.

### Finding Description
Header governance is a 2-step process: (1) a vote is cast in `header.Vote`, and (2) the vote is ratified at an epoch block in `header.Governance`. The consistency check at vote time (`checkConsistency`) for `GovernanceGoverningNode` votes is:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    ...
    if slices.Contains(council, params.GoverningNode) {  // checks CURRENT governing node
        return nil
    }
    return ErrGovNodeNotInValSetList
```

The check verifies that `params.GoverningNode` (the *current* governing node) is in the council. The vote value `vote.Value().(common.Address)` (the *new* governing node) is never checked against the council. Since the voter must already be in the council (checked earlier in `VerifyVote` at line 88), this consistency check is effectively a no-op — it always passes when the voter is in the council. [1](#0-0) 

At ratification time, `VerifyGov` only verifies that `header.Governance` matches the expected votes from the previous epoch — it does not validate that the resulting parameter set is valid (e.g., that the new governing node is in the council). [2](#0-1) 

The same defect is present in the `Vote` API, which calls the same `checkConsistency`: [3](#0-2) 

### Impact Explanation
After ratification, the new governing node is an address not in the council. In single mode:
- `VerifyVote` rejects any vote from an address not in the council (`slices.Contains(council, vote.Voter())`)
- Only the governing node can vote in single mode (post-Permissionless)
- The new governing node cannot vote → governance is permanently locked
- No governance parameters (unit price, minting amount, minimum stake, reward ratio, etc.) can ever be changed again

This is an invalid state transition: the ratified governance state violates the invariant that the governing node must be in the council in single mode. The `getDemotedValidatorsIstanbul` function explicitly protects the governing node from demotion, but this protection is bypassed when the governing node is set to a non-council address. [4](#0-3) [5](#0-4) 

### Likelihood Explanation
The governing node is the only actor who can trigger this in single mode. Two realistic scenarios:

1. **Direct mistake**: The governing node votes `(governance.governingnode, 0xNewAddr)` where `0xNewAddr` is not in the council. The check passes because it only validates the current governing node, not the vote value.

2. **Conflicting votes in the same epoch**: The governing node votes to change to address X (currently in council), then votes to remove X from the council. The `RemoveValidator` consistency check only checks the *current* governing node, not the *future* one. Both votes are ratified together at the epoch block, resulting in a governing node not in the council. [6](#0-5) 

### Recommendation
In `checkConsistency` for `GovernanceGoverningNode`, check the *new* governing node (the vote value) against the council, not the current governing node:

```go
case gov.GovernanceGoverningNode:
    params := h.GetParamSet(blockNum)
    if params.GovernanceMode != "single" {
        return nil
    }
    council, err := h.ValSet.GetCouncil(blockNum - 1)
    if err != nil {
        return err
    }
    newGoverningNode := vote.Value().(common.Address) // check the NEW governing node
    if slices.Contains(council, newGoverningNode) {
        return nil
    }
    return ErrGovNodeNotInValSetList
```

Additionally, `VerifyGov` should validate that the resulting parameter set is consistent (e.g., new governing node is in the council) before accepting the ratification.

### Proof of Concept
1. Chain is in single mode with governing node A (in council `[A, B, C]`)
2. Governing node A calls `governance_vote("governance.governingnode", "0xDeadAddress")` where `0xDeadAddress ∉ [A, B, C]`
3. `checkConsistency` evaluates `slices.Contains([A, B, C], A)` = `true` → vote passes
4. Vote is inscribed in `header.Vote` at block N within epoch k
5. At epoch block `(k+1)*epoch`, `VerifyGov` confirms the ratification matches the expected votes → passes
6. New governing node = `0xDeadAddress` takes effect at block `(k+1)*epoch`
7. `0xDeadAddress ∉ council` → `VerifyVote` rejects any vote from `0xDeadAddress`
8. No one else can vote in single mode → governance permanently locked; all on-chain governance parameters (unit price, minting amount, minimum stake, reward ratios) are frozen forever [7](#0-6)

// checkConsistency checks if vote values are consistent with chain states such as other parameters and validator set.
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		// we'll use blockNum-1 for the blocknumber of GetCouncil since blockNum cannot be available(eg. vote)
		// it's definite that the valSet vote is not included in this block
		// so the council(blockNum - 1) and council(blockNum) should be same
		council, err := h.ValSet.GetCouncil(blockNum - 1)
		if err != nil {
			return err
		}

		if slices.Contains(council, params.GoverningNode) {
			return nil
		}
		return ErrGovNodeNotInValSetList

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
