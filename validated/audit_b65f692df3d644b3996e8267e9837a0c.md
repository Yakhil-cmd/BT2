### Title
Hand-rolled YAML frontmatter parser silently drops indented `action: block` fields, downgrading rules to default `warn` and breaking deny-means-deny enforcement - (File: plugins/hookify/core/config_loader.py)

### Finding Description
`extract_frontmatter` in [1](#0-0)  implements a hand-rolled state machine instead of a real YAML parser. Top-level keys are only recognized when `indent == 0`: [2](#0-1) 

If a frontmatter line such as `action: block` has *any* leading whitespace (a single space, a tab, or is accidentally aligned under a preceding `conditions:`/list block), it fails the `indent == 0` top-level check, is not a `-`-prefixed list item, and is only captured by the dict-continuation branch when `indent > 2 and in_dict_item` (i.e., only inside a multi-line list-item dict). In any other indentation state the line matches none of the `if/elif` branches and is **silently discarded** — no exception, no warning.

Because `Rule.from_dict` reads the action with a default fallback: [3](#0-2) 
a dropped `action` key resolves to `action = "warn"` instead of the intended `"block"`. `RuleEngine.evaluate_rules` treats any rule whose `action != 'block'` as a warning-only rule that does not deny the tool call: [4](#0-3) 

`load_rule_file` only flags the file as invalid when frontmatter is completely empty; it performs no schema validation and never warns that a specific expected key like `action` failed to parse: [5](#0-4) .

Exploit flow: an attacker submitting a PR to a repo whose review workflow relies on hookify rules (`.claude/hookify.*.local.md`) can add/modify a rule file where the visible text reads `action: block` but is prefixed with a single stray space/tab (easy to miss in a diff, especially in a long frontmatter block). A human reviewer approving the PR sees "block" and assumes dangerous Bash patterns (e.g. `rm -rf`) will be denied by the `PreToolUse` hook (`plugins/hookify/hooks/pretooluse.py`). At runtime the parser drops the malformed key, the rule silently becomes `action: warn`, and any subsequent matching dangerous Bash command during automated PR review executes with only a cosmetic `systemMessage`, never a `permissionDecision: deny`.

### Impact Explanation
This breaks the deny-means-deny guarantee of a security-relevant hook enforcement mechanism: a rule that reads as blocking in the committed file is silently downgraded to non-blocking with no error surfaced anywhere (no stderr warning, no exception), letting Bash commands matched by the rule's own pattern (e.g. destructive `rm -rf`, credential exfiltration commands, etc.) execute unblocked during PR review automation. This is a workspace-safety / unauthorized-command-execution class impact within Claude Code's hook enforcement path, scoped to environments using the hookify plugin.

### Likelihood Explanation
Feasibility is high and fully deterministic: the bug is a pure parsing defect, requiring only a single misplaced whitespace character in a committed `.local.md` file — trivially reachable by any contributor who can add files to `.claude/` in a repo being reviewed via `review-pr.md`'s cloned-repo workflow, with no privilege beyond normal PR submission. The defect reproduces 100% of the time for any indented top-level key, not just `action`, making it a repeatable, low-effort bypass rather than a probabilistic race.

### Recommendation
Replace the hand-rolled parser with a real, well-tested YAML parser (e.g. `yaml.safe_load` from PyYAML, which is already a common dependency) for frontmatter parsing, eliminating the ad-hoc indentation state machine entirely. If a dependency-free parser must be kept, make it strict: normalize/reject tabs, only allow indentation multiples of a fixed unit, and raise a hard error (fail closed, not silently swallow) for any line that cannot be attributed to a known state, especially for security-critical keys like `action`. Additionally, `load_rule_file`/`Rule.from_dict` should validate that critical fields like `action` are one of the expected literal values and warn/error loudly if a key is unexpectedly absent from a file that appears to define it.

### Proof of Concept
Unit test against `extract_frontmatter` in `plugins/hookify/core/config_loader.py`:

```python
from plugins.hookify.core.config_loader import extract_frontmatter, Rule

def test_indented_action_block_is_silently_downgraded():
    content = """---
name: block-dangerous-rm
enabled: true
event: bash
pattern: rm\\s+-rf
 action: block
---

Should be blocked.
"""
    fm, msg = extract_frontmatter(content)
    rule = Rule.from_dict(fm, msg)
    # BUG: expected rule.action == 'block' (as written in file),
    # actual: silently resolves to default 'warn'
    assert rule.action == "block", (
        f"action field with leading whitespace was silently dropped; "
        f"resolved to {rule.action!r} instead of intended 'block'"
    )
```

Fuzz test plan: generate frontmatter blocks with `action: block` under randomized indentation (0–4 spaces, tabs, mixed), randomized preceding list/dict context (`conditions:` present or absent), and assert for every variant that either (a) `Rule.from_dict(...).action == 'block'` matching the literal intent in the source text, or (b) `extract_frontmatter`/`load_rule_file` raises/logs a detectable error rather than silently defaulting to `warn`. Currently case (a) fails for indent ∈ {1,2,4,tab} outside a dict-continuation context, and (b) never triggers, confirming the silent downgrade.

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule
