### Title
Webhook payload's `repository.full_name` is trusted to select the target stack while signature verification only binds to `repository.owner.login`/`organization.login` - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/organization config (and thus which HMAC secret) to validate a webhook against using only `repository.owner.login` (or `organization.login`) from the unauthenticated JSON body, then hands the *entire* raw payload to the event handlers. [1](#0-0) [2](#0-1)  Every handler, however, resolves the `Repository`/`Stack` it acts on from a *different* field of the same payload, `repository.full_name`, via `Repository.from_github_repo_name`. [3](#0-2) [4](#0-3)  The signature check and the repository-selection logic are bound to two independent, attacker-controlled fields of the unauthenticated body, not to each other.

### Finding Description
`Shipit.github(organization:)` resolves per-organization webhook secrets from `Rails.application.credentials.github`; if an organization has no entry (or Shipit is run in the legacy single-org config where `github_default_organization` is `nil`), `GitHubApp#verify_webhook_signature` returns `true` unconditionally when `webhook_secret` is blank. [5](#0-4) [6](#0-5) 

The controller derives the organization used for that lookup purely from the request body:
```ruby
def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

An attacker who is not a GitHub App/webhook holder for the victim org can craft an arbitrary POST to `/webhooks` (no session, no `ApiClient` token, no repository write access needed — it's a public, unauthenticated endpoint by design) with:
- `repository.owner.login` = an organization for which no `webhook_secret` is configured (so `verify_webhook_signature` short-circuits to `true`), or the single-org legacy mode with no secret set, and
- `repository.full_name` = `"victim-org/victim-repo"` — the actual target used by every handler (`PushHandler`, `OpenedHandler`, `ClosedHandler`, `LabeledHandler`, etc.) via `Repository.from_github_repo_name(params.repository.full_name)`. [7](#0-6) [8](#0-7) 

This is the exact class of bug the external report describes: a field that is *displayed/acted upon* is not the field that is *validated*. Here the "validated" field (`repository.owner.login`, used to pick the signing org) and the "acted upon" field (`repository.full_name`, used to pick the concrete `Stack`) are independent strings in the same unauthenticated JSON body — the equality `organization authenticated == repository written` is never enforced.

### Impact Explanation
For a `push` event this lets an unprivileged remote attacker force `stack.sync_github(expected_head_sha: params.after)` on any stack whose repository is tracked by the Shipit instance, injecting an attacker-chosen `after` SHA as the "expected head" for a victim repository/branch they do not control, without ever authenticating against that repository's real GitHub webhook secret. [9](#0-8)  For `pull_request` events (`opened`, `labeled`, `closed`, `reopened`), the same mismatch lets the attacker create, archive, or unarchive review stacks tied to a victim repository by supplying a `pull_request` payload of their choosing while only needing signature validity for an unrelated/unsecured organization. [10](#0-9)  This crosses the "unauthenticated read/write of stack state" and "unauthorized deploy/rollback trigger" boundary defined as High/Critical impact, since `sync_github` can advance the commit that later gets deployed.

### Likelihood Explanation
Exploitability depends entirely on whether at least one configured (or default/legacy) GitHub organization has no `webhook_secret` set — a documented, supported configuration state in `lib/shipit.rb#github`/`github_app_config`, not a misconfiguration requiring privileged access. Where a secret is configured, this exact analog requires knowing that org's `webhook_secret`, which is explicitly out of scope. The likelihood is therefore conditional on deployment configuration rather than universal, but the vulnerable code path (organization-based signature routing decoupled from `full_name`-based repository routing) exists unconditionally in `app/controllers/shipit/webhooks_controller.rb` and `app/models/shipit/webhooks/handlers/handler.rb`.

### Recommendation
Bind the signature/organization check to the same repository identity the handlers act on: derive `repository_owner` from `repository.full_name.split('/').first` (or otherwise verify `repository.owner.login` is a substring-consistent prefix of `full_name`) so the org used to select the webhook secret is provably the org whose repository is being mutated. Additionally, reject webhooks when no `webhook_secret` is configured for an organization that has trackable repositories, instead of silently treating unset secrets as "verified."

### Proof of Concept
1. Ensure the Shipit instance tracks a repository `victim-org/victim-repo` as a `Stack`.
2. Identify (or set up) any organization entry — e.g. `no-secret-org` — in `Rails.application.credentials.github` that has no `webhook_secret` configured (or run in legacy single-org mode with no `webhook_secret`).
3. Send:
```
POST /webhooks
X-Github-Event: push
X-Hub-Signature: sha1=anything

{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "full_name": "victim-org/victim-repo",
    "owner": { "login": "no-secret-org" }
  }
}
```
4. `verify_signature` calls `Shipit.github(organization: "no-secret-org")`, whose `webhook_secret` is blank, so `verify_webhook_signature` returns `true` and the request passes. [5](#0-4) 
5. `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, which resolves the stack via `repository.full_name = "victim-org/victim-repo"` and calls `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on the victim's real stack — despite the signature only ever having been checked against `no-secret-org`. [9](#0-8)

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
