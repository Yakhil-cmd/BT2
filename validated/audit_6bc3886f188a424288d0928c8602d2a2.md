### Title
Unbounded memory read of attacker-controlled OCI referrer layer in `GetAttestations` - ([File: pkg/cmd/attestation/artifact/oci/client.go])

### Finding Description
`LiveClient.GetAttestations` fetches referrer manifests from a registry (`remote.Referrers`), then for each descriptor whose `ArtifactType` matches the `application/vnd.dev.sigstore.bundle` prefix, it resolves `refDesc.Digest` against `ref.Context()` and pulls the image (`remote.Image`), reads the first layer (`layers[0].Uncompressed()`), and loads its entire content into memory with `io.ReadAll(layer0)` before any size check or bundle validation occurs, at [1](#0-0) . Since `ref.Context()` is derived from the reference the victim already pointed `gh` at, and `refDesc.Digest` is simply appended as a digest reference within that same repository context, an attacker-controlled registry cannot redirect resolution to an unrelated repository/tag outside of what the victim already targeted — the `name.Reference` package constrains `.Context().Digest(...)` to the same registry/repository namespace, so the "wrong-repository routing" portion of the question does not hold up. However, the attacker-controlled registry (per the accepted precondition that the victim explicitly points `gh` at a self-hosted/attacker registry) can return an arbitrarily large or a decompression-bomb-style layer blob for `layers[0]`, and `io.ReadAll` has no size cap, so the full decompressed content is buffered in memory with no bound.

Separately, downstream cryptographic verification (`verifyAttestations` → `sgVerifier.Verify` → sigstore-go's `verify.Verifier.Verify`) enforces the real security invariant: the bundle's DSSE subject digest must match the artifact's actual on-disk/registry digest via `verify.WithArtifactDigest` built in `BuildDigestPolicyOption`, at [2](#0-1) , and the bundle's signature must chain to a trusted Fulcio/Rekor root, at [3](#0-2) . An attacker who only controls the OCI registry response cannot forge a validly-signed bundle for an arbitrary digest, so no verification/authentication bypass is achievable through this path — a malicious registry can only cause `GetAttestations` to fail (bad JSON) or to feed a bundle that then fails cryptographic verification.

### Impact Explanation
The only concrete, exploitable impact is a client-side denial-of-service: an attacker-controlled registry (which the victim explicitly configured `gh attestation verify` to talk to) can return an oversized or highly-compressible ("zip bomb") referrer layer, causing `io.ReadAll(layer0)` to consume unbounded memory on the victim's machine and potentially crash/hang the `gh` process. This is a resource-exhaustion issue, not an authentication or artifact-verification bypass, since `verify.WithArtifactDigest` and Fulcio/Rekor chain validation still gate whether any attestation is accepted as valid.

### Likelihood Explanation
This requires the victim to intentionally run `gh attestation verify oci://<attacker-host>/...` against a registry the attacker fully controls (an explicit, self-hosted scenario), which is a narrow but permitted precondition per the rules. Given that precondition, triggering the unbounded read is trivial and fully repeatable (no auth, no race conditions).

### Recommendation
Wrap the layer reader with `io.LimitReader` (e.g., capping at a few MB, consistent with expected Sigstore bundle sizes) before calling `io.ReadAll` in `LiveClient.GetAttestations`, and reject/error out if the limit is exceeded, at [4](#0-3) .

### Proof of Concept
Using `oci.LiveClient` with injected `get`/mocked `remote.Referrers`/`remote.Image` transports (or an `httptest` OCI registry stub) that:
1. Returns a valid referrer manifest with `ArtifactType: "application/vnd.dev.sigstore.bundle+json"`.
2. Serves a layer blob that gzip-decompresses to, e.g., 2 GB of repeated bytes from a small compressed payload.
3. Assert that `GetAttestations` either errors out with a "layer too large" error (after the fix) rather than allocating multiple GB of memory, or, on the current code, observe unbounded memory growth via `runtime.MemStats` during the call, confirming the missing size bound at `io.ReadAll(layer0)`.

// BuildDigestPolicyOption builds a verify.ArtifactPolicyOption
// from the given artifact digest and digest algorithm
func BuildDigestPolicyOption(a artifact.DigestedArtifact) (verify.ArtifactPolicyOption, error) {
	// sigstore-go expects the artifact digest to be decoded from hex
	decoded, err := hex.DecodeString(a.Digest())
	if err != nil {
		return nil, err
	}
	return verify.WithArtifactDigest(a.Algorithm(), decoded), nil
}
