Based on my investigation, I found a native analog in the Kaia service-chain bridge code.

### Title
Unauthenticated `ServiceChainCall` P2P Message Injects Arbitrary JSON-RPC into MainBridge Internal RPC Server — (File: `node/sc/main_bridge_handler.go`)

---

### Summary

Any P2P peer that connects to the `MainBridge`'s bridge port and passes the basic protocol handshake can send a `ServiceChainCall` message containing arbitrary JSON-RPC payload. The handler writes this payload directly into the internal RPC server pipe with no signature, timestamp, or identity check. The internal RPC server has all public `klay`/`kaia` namespace APIs registered on it, including `kaia_sendRawTransaction`.

### Impact Explanation

The internal RPC server exposes the full public `kaia`/`klay` API surface. An attacker who connects to the bridge port can:

1. **Inject `kaia_sendRawTransaction`** — submit any pre-signed transaction (e.g., a replayed or front-run transaction) directly into the parent-chain tx pool, bypassing any IP-based firewall that guards the public JSON-RPC port.
2. **Enumerate chain state** — call `kaia_getBalance`, `kaia_getStorageAt`, etc. on accounts and contracts that the operator intended to keep behind a restricted RPC endpoint.
3. **Consume bridge operator nonce** — by injecting a `kaia_sendRawTransaction` carrying a transaction signed by the bridge operator account at the correct nonce, the attacker can advance the operator's on-chain nonce, causing all pending bridge value-transfer transactions queued in `BridgeTxPool` to fail with `nonce too low`, halting KAIA and ERC-20/ERC-721 cross-chain transfers.

The third sub-impact is the most severe: it directly corrupts the bridge operator's nonce state, which is the key consumed to authorize every `HandleKLAYTransfer` / `HandleERC20Transfer` call on the parent-chain bridge contract. [8](#0-7) 

---

### Likelihood Explanation

- The `MainBridgePort` (default `50505`) is a publicly reachable TCP port.
- The only barrier is the protocol handshake, which requires knowing the network ID and chain ID — both are public.
- No cryptographic proof of the peer's identity is required beyond the RLPx session key, which any node can generate.
- The attack requires only a standard Go/Node.js RLPx client and knowledge of the target's network parameters.

---

### Recommendation

1. **Authenticate `ServiceChainCall` senders.** Maintain an allowlist of permitted SubBridge node IDs (derived from their ECDH public keys, already available as `p.ID()` after the RLPx handshake). Reject `ServiceChainCall` messages from peers whose node ID is not in the allowlist.
2. **Require a signed envelope.** The `ServiceChainCall` payload should include a signature over `(rpc_payload || timestamp || nonce)` verifiable against the SubBridge operator's registered public key, analogous to the fix recommended in the Shardus Core report.
3. **Restrict the internal RPC surface.** The internal `rpcServer` should only register the minimal set of methods actually needed by the SubBridge (e.g., block/receipt queries), not the entire public `kaia` namespace.

### Proof of Concept

```go
// attacker.go — connects to MainBridge bridge port and injects an RPC call
package main

import (
    "github.com/kaiachain/kaia/networks/p2p"
    // ... standard RLPx dial helpers
)

func main() {
    // 1. Dial the MainBridge bridge port (e.g. :50505)
    conn := dialRLPx("192.168.1.10:50505", attackerKey)

    // 2. Complete the SC protocol handshake with matching networkId + chainID
    doSCHandshake(conn, networkId, chainId, currentBlockHash)

    // 3. Send ServiceChainCall with arbitrary JSON-RPC payload
    payload := []byte(`{"jsonrpc":"2.0","method":"kaia_sendRawTransaction",` +
        `"params":["0x<signed_tx_hex>"],"id":1}`)
    p2p.Send(conn, ServiceChainCall, payload)

    // 4. Read the RPC response forwarded back by SendRPCResponseData
    resp := readMsg(conn) // contains the JSON-RPC result
}
```

Steps:
1. Obtain the MainBridge's bridge port from the node's `--mainbridgeport` flag (default `50505`).
2. Dial with any valid RLPx key; complete the SC handshake using the public network ID and chain ID.
3. Emit a `ServiceChainCall` message whose body is a valid JSON-RPC request (e.g., `kaia_sendRawTransaction` with a pre-signed transaction, or `kaia_getBalance` for reconnaissance).
4. The `handleCallMsg` function writes the payload to `rpcConn`; the internal RPC server processes it and the response is returned to the attacker via `SendRPCResponseData`. [1](#0-0) [9](#0-8)

func (mb *MainBridge) handle(p BridgePeer) error {
	// Ignore maxPeers if this is a trusted peer
	if mb.peers.Len() >= mb.maxPeers && !p.GetP2PPeer().Info().Networks[p2p.ConnDefault].Trusted {
		return p2p.DiscTooManyPeers
	}
	p.GetP2PPeer().Log().Debug("Kaia peer connected", "name", p.GetP2PPeer().Name())

	// Execute the handshake
	var (
		head   = mb.blockchain.CurrentHeader()
		hash   = head.Hash()
		number = head.Number.Uint64()
		td     = mb.blockchain.GetTd(hash, number)
	)

	err := p.Handshake(mb.networkId, mb.getChainID(), td, hash)
	if err != nil {
		p.GetP2PPeer().Log().Debug("Kaia peer handshake failed", "err", err)
		return err
	}

	// Register the peer locally
	if err := mb.peers.Register(p); err != nil {
		// if starting node with unlock account, can't register peer until finish unlock
		p.GetP2PPeer().Log().Info("Kaia peer registration failed", "err", err)
		return err
	}
	defer mb.removePeer(p.GetID())

	p.GetP2PPeer().Log().Info("Added a P2P Peer", "peerID", p.GetP2PPeerID())

	// main loop. handle incoming messages.
	for {
		if err := mb.handleMsg(p); err != nil {
			p.GetP2PPeer().Log().Debug("Klaytn message handling failed", "err", err)
			return err
		}
	}
}

			return err
