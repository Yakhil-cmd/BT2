### Title
Cross-stack authorization bypass in `Api::CCMenuController#stack` — a stack an API token authorizes vs the stack it touches - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Api::BaseController` scopes an `ApiClient`'s access to the single `stack_id` it was issued for, but `Api::CCMenuController` overrides the `stack` lookup method with a version that ignores that scoping entirely, letting any token with a bare `read:stack` permission read the deploy status/output of *any* stack in the installation, not just the one it was authorized for.

### Finding Description
In `Api::BaseController`, the scoping logic that binds an `ApiClient` to a specific stack is: [1](#0-0) 

`stacks` is deliberately restricted to `current_api_client.stack_id` when the client is scoped, and `stack` is derived from that restricted `stacks` relation — this is the intended binding: `token.stack ↔ requested stack`.

`Api::CCMenuController`, however, defines its own `stack` method that completely bypasses this scoping and queries the global `Stack` table directly: [2](#0-1) 

Specifically:
```ruby
def stack
  @stack ||= Stack.from_param!(params[:stack_id])
end
```
This does not go through `stacks`/`current_api_client.stack_id?`, so `require_permission :read, :stack` (declared at the top of the controller) only verifies that `"read:stack"` is present in `current_api_client.permissions` — it never checks that the requested `stack_id` matches the token's `stack_id`: [3](#0-2) 

The controller also overrides `authenticate_api_client` to accept the token from a query parameter instead of the `Authorization` header (since CCMenu/CI clients fetch XML without basic auth):

```ruby
def authenticate_api_client
  @current_api_client = ApiClient.authenticate(params[:token])
  super unless @current_api_client
end
```

So the equality that should hold — `token.stack_id == requested stack_id` (when the token is stack-scoped) — is broken: any token carrying `read:stack`, even one explicitly scoped by a stack owner to a single low-value stack, can be replayed against the `:stack_id` route parameter for a completely different stack to read that other stack's latest deploy status.

### Impact Explanation
This lets a caller holding any `read:stack`-permissioned `ApiClient` token (regardless of the `stack_id` it was scoped to when created) read deploy state (`running?`, `ended_at`, latest build status) for any stack managed by the Shipit instance, not just the one the token owner explicitly authorized. This is an unauthorized cross-stack read of stack/deploy state, matching the "High" impact bucket for "unauthenticated read of stack state, task streams or deploy output" — the confidentiality boundary intended by per-token stack scoping is broken.

### Likelihood Explanation
Likelihood is Medium-High: it requires possession of any valid `ApiClient` token with the `read:stack` permission (these are routinely issued and are treated as low-privilege, scoped-to-one-stack credentials via `stack_id`), and the vulnerable endpoint is reachable simply by changing the `stack_id` route segment while replaying that token as a query parameter — no special network position, no signature forgery, and no privileged account needed beyond having any scoped read token.

### Recommendation
Remove the `Api::CCMenuController#stack` override, or reimplement it to reuse the scoped `stacks` relation from `Api::BaseController` (i.e. `stacks.from_param!(params[:stack_id])`) so that a stack-scoped token cannot resolve stacks outside its `stack_id`.

### Proof of Concept
1. Create an `ApiClient` with `permissions: ['read:stack']` scoped to `stack_id: A` (Stack A).
2. Obtain its `authentication_token`.
3. Issue `GET /api/stacks/:B_id/ccmenu.xml?token=<token>` where `B_id` is a different stack the token was never scoped to.
4. `Api::CCMenuController#stack` resolves Stack B directly via `Stack.from_param!`, bypassing the `current_api_client.stack_id` scoping enforced elsewhere, and the response renders Stack B's latest deploy/rollback status — despite the token only ever having been authorized for Stack A. module Shipit
  module Api
    class CCMenuController < BaseController
      require_permission :read, :stack

      class NoDeploy
        def id
          0
        end

        def ended_at
          Time.now.utc
        end

        def running?
          false
        end
      end

      def show
        latest_deploy = stack.deploys_and_rollbacks.last || NoDeploy.new
        render('shipit/ccmenu/project', formats: [:xml], locals: { stack:, deploy: latest_deploy })
      end

      private

      def stack
        @stack ||= Stack.from_param!(params[:stack_id])
      end

      end
    end

end
