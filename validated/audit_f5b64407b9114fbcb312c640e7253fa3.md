### Title
Alpenglow epoch inflation reward budget is locked in before the VAT burn reduces capitalization, allowing payouts above the intended inflation ceiling - (File: `runtime/src/block_component_processor/vote_reward/epoch_inflation_account_state.rs`)

### Summary
Agave's Alpenglow inflation reward accounting computes and permanently records a fixed `max_possible_validator_reward` "budget" for an epoch at epoch-boundary time, using the capitalization observed *before* the epoch's Validator Admission Ticket (VAT) burn to the incinerator executes. Because vote-account credits accrued during the epoch are later redeemed against this pre-burn budget rather than a budget recomputed from the post-burn capitalization, the actual amount paid out in stake/vote rewards can exceed what the inflation formula would allow once the capitalization decrease from the burn is accounted for — the same "stale rate/capitalization used across a boundary" defect described in the Backd `_executeInflationRateUpdate` finding.

### Finding Description
`EpochInflationState::new_from_bank` computes the epoch's reward ceiling from `epoch_start_capitalization + additional_rewards` and stores it verbatim for the whole epoch: [1](#0-0) 

This value is written into the on-chain `EpochInflationAccountState` via `new_epoch_update_account` and later looked up as the authoritative epoch-start inflation budget used to redeem rewards for that epoch: [2](#0-1) [3](#0-2) 

Separately, each epoch boundary burns a fixed VAT amount from every staked vote account to the incinerator, which reduces total capitalization *after* the reward budget above has already been fixed: [4](#0-3) 

The reward-calculation path for Tower/migration epochs uses `EpochInflationAccountState::inflation_rewards_for_epoch` (the stale, pre-burn budget) rather than recomputing `calculate_epoch_inflation_rewards` from the current (post-burn) capitalization: [5](#0-4) 

`calculate_epoch_inflation_rewards` itself is the formula that should represent the enforced inflation ceiling for a given capitalization/epoch: [6](#0-5) 

The repository's own regression test demonstrates the exact defect: it records the epoch-start budget, has a validator accrue enough vote credits to redeem the *entire* pre-burn budget, freezes the bank (which burns the VAT and reduces capitalization), then shows that the recalculated ceiling using post-burn capitalization is *smaller* than what actually gets paid out — and asserts that the excess is paid anyway: [7](#0-6) 

This is structurally identical to the Backd `_executeInflationRateUpdate` bug: a reward/inflation "budget" is computed using state that is stale relative to a decay/burn boundary (`block.timestamp >= lastInflationDecay + _INFLATION_DECAY_PERIOD` in Backd vs. "epoch-start capitalization before VAT burn" in Agave), and the total distributed is allowed to exceed the amount the updated (post-boundary) state would justify.

### Impact Explanation
This allows validators, purely by submitting normal vote transactions during an epoch (accruing maximum vote credits), to have the protocol redeem rewards computed against a budget that is provably larger than what the post-burn capitalization formula would allow. This constitutes reward/inflation accounting corruption: the total lamports minted as staking/voting rewards for an epoch can exceed the value that the documented inflation-rate formula would produce for that epoch's actual (post-burn) capitalization, silently inflating the token supply beyond the intended schedule. Because this affects capitalization and reward bookkeeping that must be identical and deterministic across all validators, and because the discrepancy is baked into consensus-relevant state (the `EpochInflationAccountState` account and the resulting `EpochRewards` sysvar), it falls into the "stake or reward corruption" impact category.

### Likelihood Explanation
The trigger conditions are entirely within reach of standard, unprivileged protocol usage: a validator operator simply votes on every slot of an epoch (maximizing accrued vote credits) as they normally would. No special leader, snapshot, or network-layer access is required — the repository's own test reproduces the discrepancy using only account state manipulation equivalent to normal vote-credit accrual and the standard `bank.freeze()` VAT-burn path that runs on every epoch boundary when Alpenglow is active. This makes the condition mechanically likely to occur whenever a validator's accrued credits are close to the epoch's theoretical maximum.

### Recommendation
Recompute (or clamp) the effective reward ceiling used at redemption time against the *current* (post-VAT-burn) capitalization rather than relying solely on the value latched in `EpochInflationAccountState` at epoch start, mirroring the Backd mitigation of splitting accrual across the boundary: apply the pre-boundary rate/capitalization up to the burn point and the post-boundary rate/capitalization afterward, or cap total redemption at `calculate_epoch_inflation_rewards` evaluated with capitalization after all burns for the epoch have been applied.

### Proof of Concept
The existing unit test `test_alpenglow_partitioned_rewards_use_epoch_start_budget_after_burn` is a self-contained PoC: [8](#0-7) 
It (1) captures the epoch-start `recorded_budget`, (2) credits a validator's vote account with exactly enough credits to redeem that full budget, (3) freezes the bank (triggering the VAT burn that lowers capitalization), (4) shows `calculate_epoch_inflation_rewards` on the new, lower capitalization (`recalculated_ceiling`) is less than `recorded_payout`, and (5) confirms the protocol still pays out the full stale `recorded_payout`, exceeding the recalculated inflation ceiling.

    /// Computes a new version of `Self` for `bank.epoch` and serializes it into accounts in the `bank`.
    ///
    /// At the start of a new epoch, over several slots we pay the inflation rewards from the
    /// previous epoch.  This is called Partitioned Epoch Rewards (PER).  As such, the
    /// capitalization keeps increasing in the first slots of the epoch.  Vote rewards are
    /// calculated as a function of the capitalization and we do not want voting in the initial
    /// slots to earn less rewards than voting in the later rewards.  As such this function is
    /// called with [`additional_rewards`] which should be the total rewards that will
    /// be paid by PER and we use the capitalization from the previous epoch plus this value to
    /// compute the vote rewards.
    pub(crate) fn new_epoch_update_account(
        bank: &Bank,
        epoch_start_capitalization: u64,
        additional_rewards: u64,
    ) {
        let prev = Self::new_from_bank(bank).map(|s| s.current);
        let current = EpochInflationState::new_from_bank(
            bank,
            epoch_start_capitalization,
            additional_rewards,
        );
        let state = Self { prev, current };
        state.set_state(bank);
    }

    /// Burn the Validator Admission ticket from each vote account if Alpenglow is enabled
    ///
    /// Note: This must ONLY be called after the vote accounts have been filtered (`clone_and_filter_for_vat`)
    /// to the top `MAX_ALPENGLOW_VOTE_ACCOUNTS` that contain enough balance for admission.
    fn maybe_burn_vat_from_staked_accounts(&mut self, epoch_stakes: &VersionedEpochStakes) {
        let feature_snapshot = self.feature_set.snapshot();
        if !feature_snapshot.alpenglow {
            return;
        }

        let vat_to_burn_per_epoch = self.vat_to_burn_per_epoch();
        let vote_accounts = epoch_stakes.stakes().vote_accounts();
        debug_assert!(vote_accounts.len() <= 2000);
        // +1 for the incinerator account
        let mut accounts_to_store: Vec<(Pubkey, AccountSharedData)> =
            Vec::with_capacity(vote_accounts.len() + 1);
        let mut total_vat = 0u64;

        // Vote accounts have already been filtered by clone_and_filter_for_vat to only include
        // accounts with non-zero stake and sufficient balance.
        for (vote_pubkey, _stake) in vote_accounts.delegated_stakes() {
            let mut account = self.get_account(vote_pubkey).unwrap();
            total_vat += vat_to_burn_per_epoch;
            account.set_lamports(
                account
                    .lamports()
                    .checked_sub(vat_to_burn_per_epoch)
                    .expect(
                        "Vote accounts should have already been filtered to contain enough \
                         balance for the VAT",
                    ),
            );
            accounts_to_store.push((*vote_pubkey, account));
        }

        // Per SIMD-0357, transfer collected VAT to the incinerator account.
        let mut incinerator_account = self.get_account(&incinerator::id()).unwrap_or_default();
        incinerator_account.set_lamports(
            incinerator_account
                .lamports()
                .checked_add(total_vat)
                .unwrap(),
        );
        accounts_to_store.push((incinerator::id(), incinerator_account));

        self.store_accounts((self.slot, accounts_to_store.as_slice()), None);
        info!(
            "Transferred total VAT of {total_vat} lamports to incinerator from staked vote \
             accounts"
        );
    }

    /// For a given `capitalization` (total_supply in lamports) and `epoch`, returns the
    /// `epoch inflation rewards` in lamports.
    pub(crate) fn calculate_epoch_inflation_rewards(
        &self,
        capitalization: u64,
        epoch: Epoch,
    ) -> u64 {
        let slot_in_year = self.slot_in_year_for_inflation();
        let validator_rate = self.inflation.read().unwrap().validator(slot_in_year);
        let epoch_duration_in_years = self.epoch_duration_in_years(epoch);
        (validator_rate * capitalization as f64 * epoch_duration_in_years) as u64
    }

    #[test]
    fn test_alpenglow_partitioned_rewards_use_epoch_start_budget_after_burn() {
        let validator_keypairs = vec![genesis_utils::ValidatorVoteKeypairs::new_rand()];
        let GenesisConfigInfo {
            mut genesis_config, ..
        } = genesis_utils::create_genesis_config_with_alpenglow_vote_accounts(
            1_000_000_000 * LAMPORTS_PER_SOL,
            &validator_keypairs,
            vec![100 * LAMPORTS_PER_SOL],
        );
        genesis_config.epoch_schedule = EpochSchedule::new(SLOTS_PER_EPOCH);
        let features_to_deactivate = crate::slot_params::slot_time_feature_ids().to_vec();
        deactivate_features(&mut genesis_config, &features_to_deactivate);

        let (bank, bank_forks) =
            Bank::new_for_tests(&genesis_config).wrap_with_bank_forks_for_tests();
        let bank = Bank::new_from_parent_with_bank_forks(
            bank_forks.as_ref(),
            bank,
            SlotLeader::default(),
            SLOTS_PER_EPOCH,
        );
        assert_eq!(bank.epoch(), 1);

        let recorded_budget = EpochInflationAccountState::new_from_bank(&bank)
            .and_then(|state| state.inflation_rewards_for_epoch(bank.epoch()))
            .expect("epoch-start inflation budget must be persisted");
        // Alpenglow rewards are rounded down once per slot, so this is the largest
        // payout that can actually have been recorded during the epoch.
        let recorded_payout = recorded_budget / SLOTS_PER_EPOCH * SLOTS_PER_EPOCH;

        let vote_pubkey = validator_keypairs[0].vote_keypair.pubkey();
        let mut vote_account = bank.get_account(&vote_pubkey).unwrap();
        let VoteStateVersions::V4(mut vote_state) = vote_account
            .deserialize_data::<VoteStateVersions>()
            .unwrap()
        else {
            panic!("unexpected vote state version");
        };
        let last_credits = vote_state
            .epoch_credits
            .last()
            .map(|(_epoch, final_credits, _initial_credits)| *final_credits)
            .unwrap_or_default();
        vote_state
            .epoch_credits
            .push((bank.epoch(), last_credits + recorded_payout, last_credits));
        vote_account
            .serialize_data(&VoteStateVersions::V4(vote_state))
            .unwrap();
        bank.store_account(&vote_pubkey, &vote_account);

        // Freezing burns the VAT transferred to the incinerator at the epoch
        // boundary, reducing capitalization after the reward budget was fixed.
        bank.freeze();
        let recalculated_ceiling =
            bank.calculate_epoch_inflation_rewards(bank.capitalization(), bank.epoch());
        assert!(
            recorded_payout > recalculated_ceiling,
            "the test must reproduce a payout above the post-burn ceiling: \
             recorded_payout={recorded_payout}, recalculated_ceiling={recalculated_ceiling}"
        );

        let bank = Bank::new_from_parent(
            bank,
            SlotLeader::default(),
            SLOTS_PER_EPOCH.saturating_mul(2),
        );
        assert_eq!(bank.epoch(), 2);

        let epoch_rewards = bank.get_epoch_rewards_sysvar();
        let EpochRewardStatus::Active(EpochRewardPhase::Calculation(calculation_status)) =
            &bank.epoch_reward_status
        else {
            panic!("{:?} not active calculation", bank.epoch_reward_status);
        };
        let stake_rewards = calculation_status
            .all_stake_rewards
            .enumerated_rewards_iter()
            .map(|(_index, reward)| reward.inflation.stake_reward)
            .sum::<u64>();
        assert_eq!(epoch_rewards.total_rewards, recorded_budget);
        assert_eq!(
            epoch_rewards.distributed_rewards + stake_rewards,
            recorded_payout,
            "every recorded reward lamport must still be paid"
        );
    }
