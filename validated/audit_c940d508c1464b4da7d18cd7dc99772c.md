### Title
Raw pip/venv stderr tail leaks embedded credentials into `sdk_bootstrap_err` telemetry - ([File: plugins/security-guidance/hooks/ensure_agent_sdk.py])

### Summary
When `pip install` fails for an uncategorized reason, `main()` takes the last non-empty line of raw subprocess stderr and embeds it verbatim (up to 60 chars) into the `other:<tail>` error-kind string, which is then printed as a `sdk_bootstrap_err` metric. If the failing pip command targets a credentialed private index (Basic-Auth URL such as `https://user:TOKEN@pip.internal/...`) and pip's error output isn't stripped of the credential on that failure path, the secret is copied into a telemetry value that an unprivileged observer of logs/metrics can read without any shell access to the victim machine.

### Finding Description
`main()` runs `pip install` inheriting the ambient index configuration rather than pinning `--index-url`, explicitly noting it "inherit[s] that default" from the machine's pip config [1](#0-0) . On `CalledProcessError`, stderr is decoded and matched against a fixed keyword list (`dns_fail`, `proxy_auth`, `ssl_verify`, etc.); anything not matching those specific substrings falls through to the `else` branch, which extracts the last non-empty stderr line and truncates it to 60 characters as `err_kind = f"other:{tail}"` with no redaction of URLs or credentials [2](#0-1) . That `err_kind` is passed straight through as `sdk_bootstrap_err` in the JSON metrics blob printed to stdout [3](#0-2) , which per the code's own comment is "forwarded to the hook metrics event" — i.e., a telemetry sink outside the normal shell/file boundary. If a victim's pip is configured with a private index whose URL embeds Basic-Auth credentials, and the specific failure text (e.g. a 401/index-not-found variant that doesn't contain the words "proxy", "authent", "tunnel", or "407") isn't caught by any categorized branch, the raw credential-bearing line is copied unmodified into telemetry. None of the existing keyword checks perform generic credential scrubbing (no regex for `://[^/@]+@` or similar), so this is a genuine gap rather than a defense that merely needs tightening.

### Impact Explanation
This allows secret disclosure of private-index credentials (tokens/passwords embedded in pip index URLs) to whoever can read the emitted hook metrics (log aggregator, metrics dashboard, or CC's telemetry pipeline), without requiring any privilege escalation or direct file/shell access on the victim machine — matching a "sensitive data exposure via diagnostic/telemetry channel" impact class.

### Likelihood Explanation
Requires: (1) the victim machine has a private pip index configured with embedded Basic-Auth credentials (a realistic and common enterprise pattern), and (2) that install fails in a way whose stderr text doesn't match any of the eight categorized branches. This is plausible for many real 401/404/handshake variants from private registries that don't literally contain "proxy", "authent", "tunnel", or "407". The bootstrap runs unconditionally at SessionStart whenever the SDK isn't already importable, so the failure path is easily and repeatably triggered (e.g., a broken/misconfigured index) rather than requiring a contrived attack.

### Recommendation
Before constructing `other:<tail>`, scrub the extracted line (and ideally the whole `stderr_str` prior to keyword matching) with a generic URL-credential redaction, e.g. replace `scheme://user:pass@` with `scheme://***@` (mirroring pip's own `redact_auth_from_url`), or drop any token matching common secret patterns. Alternatively, avoid embedding raw stderr content in telemetry entirely and use only the fixed categorized buckets, falling back to a static `"other"` value with no tail when no keyword matches.

### Proof of Concept
Unit test: construct `stderr = b"ERROR: HTTP error 401 while getting https://user:S3cr3tTok3n@pip.internal/simple/claude-agent-sdk/"`, wrap it in a `subprocess.CalledProcessError(returncode=1, cmd=[...], stderr=stderr)`, and monkeypatch `subprocess.run` (for the pip-install call) to raise that exception inside `main()`. Assert that the returned `err_kind` (and thus what would become `metrics["sdk_bootstrap_err"]`) does not contain the substring `"S3cr3tTok3n"`. As written, the current `else` branch matches (no "proxy"/"authent"/"407" keywords present) and returns `other:ERROR: HTTP error 401 while getting https://user:S3cr3tTok3n@pip` — demonstrating the credential leaks into the tail before the 60-char truncation cuts it off.
