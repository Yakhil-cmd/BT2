### Title
Gas key storage-staking undercounts real trie bytes per nonce (missing account_id + separator length) - ([File: runtime/runtime/src/access_keys.rs])

### Summary
`gas_key_storage_cost` in `runtime/runtime/src/access_keys.rs` computes the per-nonce billed storage size as only `public_key.trie_id_len() + size_of::<NonceIndex>()`, but the actual `TrieKey::GasKeyNonce` entry written to the trie is `1 (col prefix) + account_id.len() + 1 (separator) + key_handle.trie_id_len() + size_of::<NonceIndex>()` bytes. This omits `account_id.len() + 2` bytes per nonce from the billed `storage_usage`, letting an attacker under-pay storage staking for every gas-key nonce they create.

### Finding Description
`add_gas_key` (`runtime/runtime/src/access_keys.rs:194-228`) calls `gas_key_storage_cost` to increment `account.storage_usage()` after writing `num_nonces` `TrieKey::GasKeyNonce` entries via `set_gas_key_nonce`: [1](#0-0) 

`gas_key_storage_cost` computes:
```rust
let per_nonce_key_size = public_key.trie_id_len() as u64 + size_of::<NonceIndex>() as u64;
num_nonces as u64 * (per_nonce_key_size + per_nonce_value_size + storage_config.num_extra_bytes_record)
    + access_key_storage_usage(fee_config, public_key, access_key)
``` [2](#0-1) 

Each nonce, however, is stored at `TrieKey::GasKeyNonce`, whose real length (`gas_key_nonce_key_len`) is `access_key_key_len(account_id.len(), key_handle.trie_id_len()) + size_of::<NonceIndex>()`, i.e. `1 (col) + account_id.len() + 1 (separator) + trie_id_len + size_of::<NonceIndex>()`: [3](#0-2) [4](#0-3) 

And the actual bytes written on the trie confirm this layout — `col::ACCESS_KEY`, `account_id`, separator, key handle, nonce index: [5](#0-4) 

So `gas_key_storage_cost`'s `per_nonce_key_size` is missing `account_id.len() + 2` bytes compared to the real on-trie key size. By contrast, the *gas fee* calculation for the same operation (`gas_key_add_key_exec_fee` in `core/parameters/src/cost.rs`) correctly uses `access_key_key_len(account_id_len, public_key_len)` (which includes the account_id length and both marker bytes) plus the `NonceIndex` size: [6](#0-5) 

This shows the gas-burn accounting and the storage-staking accounting diverge: the gas fee formula bills the full key length, while `gas_key_storage_cost` (which drives `storage_usage`, the value that gates storage staking — an account must hold enough balance to cover `storage_usage * storage_byte_cost`) bills a shorter length. The account is therefore permitted to write more trie bytes than its locked balance actually covers.

An unprivileged attacker can exploit this by using an account with a long `account_id` (near-max length, e.g. 64 bytes) and submitting `AddKey` actions with `GasKeyFullAccess`/`GasKeyFunctionCall` permission and a large `num_nonces`, repeated across many keys, to accumulate uncounted trie growth proportional to `num_nonces * (account_id.len() + 2)` per key while paying storage-staking rent for a smaller `storage_usage` value.

### Impact Explanation
This is an unpriced/underpriced state-growth bug: an ordinary account holder can grow real trie storage (disk/state size on all validators/chunk producers) beyond what their locked NEAR balance for storage staking accounts for, since `Account::storage_usage()` (the value checked against the account's balance for storage staking, per `storage_amount_per_byte` in the runtime config) is smaller than the true persisted bytes. This matches the "state/storage metering bypass leading to unpriced state growth" impact class — it degrades validator disk/trie resources without proportional payment, though the per-key magnitude (bounded by `account_id.len() + 2` bytes, at most ~66 bytes per nonce) means the practical growth rate is modest and requires the attacker to specifically choose long account IDs and large `num_nonces` values, and to add many such gas keys, to accumulate meaningfully unpriced state.

### Likelihood Explanation
The bug is deterministic and always present — no privileged access or race is needed. Preconditions are minimal: any funded account can submit `AddKey` with `GasKeyInfo { num_nonces > 0 }`; the discrepancy triggers every single time `add_gas_key` runs, on every protocol version that supports gas keys. It's fully repeatable and requires only standard RPC/transaction access, and the exploit is bounded but real for accounts that intentionally pick long `account_id` strings and large nonce counts across many keys.

### Recommendation
Fix `gas_key_storage_cost` in `runtime/runtime/src/access_keys.rs` to bill the true per-nonce key size using the same primitive as the trie key encoding and the gas-fee calculation, e.g.:
```rust
let per_nonce_key_size = near_primitives::trie_key::gas_key_nonce_key_len(account_id, &public_key.into()) as u64;
```
or equivalently `access_key_key_len(account_id.len(), public_key.trie_id_len()) + size_of::<NonceIndex>()`, ensuring `storage_usage` charged in `add_gas_key`/`delete_gas_key` matches the real bytes written/removed for `TrieKey::GasKeyNonce` entries. This requires a protocol-version-gated fix since it changes storage_usage accounting for existing accounts.

### Proof of Concept
Add a unit test in `runtime/runtime/src/access_keys.rs` (alongside `test_add_gas_key`) that:
1. Uses an account_id with maximal length (64 bytes) and a public key.
2. Calls `add_gas_key` (via `action_add_key`) with `num_nonces = N`.
3. Computes `expected_real_bytes = N * gas_key_nonce_key_len(&account_id, &public_key.into()) + access_key_storage_usage(...)`.
4. Asserts `account.storage_usage() - storage_before == expected_real_bytes`, which will FAIL against current code (billed value is smaller by `N * (account_id.len() + 2)` bytes), demonstrating the undercounting.
5. Additionally, iterate the trie/state_update after `add_gas_key` and sum `TrieKey::gas_key_nonce(account_id, public_key, i).len()` for `i in 0..N` plus the `AccessKey` entry length, and assert this equals `gas_key_storage_cost(...)` — expected to fail, confirming the billed `storage_usage` mismatches real trie key lengths.

fn gas_key_storage_cost(
    fee_config: &RuntimeFeesConfig,
    public_key: &PublicKey,
    access_key: &AccessKey,
    num_nonces: NonceIndex,
) -> StorageUsage {
    let storage_config = &fee_config.storage_usage_config;
    let per_nonce_value_size = borsh::object_length(&(0 as Nonce)).unwrap() as u64;
    let per_nonce_key_size = public_key.trie_id_len() as u64 + size_of::<NonceIndex>() as u64;

        * (per_nonce_key_size + per_nonce_value_size + storage_config.num_extra_bytes_record)

}

/// Exec fee when adding a gas key with `num_nonces` nonces, split into base
/// and per-byte components. Each nonce writes a trie entry of
/// (access_key_key_len + NonceIndex) key bytes and NONCE_VALUE_LEN value bytes.
pub fn gas_key_add_key_exec_fee(
    cfg: &RuntimeFeesConfig,
    account_id_len: usize,
    public_key_len: usize,
    num_nonces: NonceIndex,
) -> GasKeyAddFee {
    let num_nonces = num_nonces as u64;
    let base =
        cfg.fee(ActionCosts::gas_key_nonce_write_base).exec_fee().checked_mul(num_nonces).unwrap();
    let nonce_key_len =
        access_key_key_len(account_id_len, public_key_len) + std::mem::size_of::<NonceIndex>();
    let per_byte = cfg
        .fee(ActionCosts::gas_key_byte)
        .exec_fee()
        .checked_mul((nonce_key_len + AccessKey::NONCE_VALUE_LEN) as u64)
        .unwrap()
        .checked_mul(num_nonces)
        .unwrap();
    GasKeyAddFee { base, per_byte }
}
