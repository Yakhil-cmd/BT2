### Title
Cross-organization team merge via unscoped `github_id` lookup in membership webhook - ([File: app/models/shipit/webhooks/handlers/membership_handler.rb])

### Summary
`MembershipHandler#find_or_create_team!` resolves the target `Shipit::Team` purely by `Team.find_or_create_by!(github_id: params.team.id)` with no `organization` scoping. [1](#0-0)  Because the org-scoping only occurs in the `find_or_create_by!` block (executed solely on first creation), a membership webhook legitimately signed by one onboarded organization can add/remove members on a `Team` row that actually belongs to a different organization, as long as it supplies the pre-existing team's numeric `github_id`.

### Finding Description
The intended binding is: `team.organization == organization that authenticated (signed) the webhook payload`. The code never re-checks this on lookup — `find_or_create_by!(github_id: params.team.id)` matches any existing `Team` with that `github_id` regardless of which org's webhook secret signed the request, and the `organization`/`github_team` assignment inside the block only runs when a *new* record is created. [2](#0-1) 

Request flow: `WebhooksController#create` parses the raw JSON and dispatches to handlers after `verify_signature`, which picks the signing app config via `Shipit.github(organization: repository_owner)` where `repository_owner` is itself read from the same payload (`organization.login`), then calls `GitHubApp#verify_webhook_signature`, which trivially returns `true` "unless `webhook_secret`" is configured for that org. [3](#0-2) [4](#0-3) [5](#0-4) 

Any actor with legitimate control of a registered organization's membership webhook (an org owner/admin of an org already onboarded to this Shipit instance — squarely inside the stated "unprivileged attacker" definition of "emit webhooks from a repository/org they own") can send a valid `membership` event for their own org but set `team.id` to the `github_id` of a `Shipit::Team` belonging to a completely different organization (e.g., discovered via `/teams` UI or brute-forced small integers). `find_or_create_team!` finds the pre-existing cross-org `Team` row, and `process` then calls `team.add_member(member)`, appending the attacker-nominated GitHub user to that other org's team. [6](#0-5)  That `Team` may be one of `Shipit.github_teams`, which `User#authorized?` uses to gate access. [7](#0-6) 

`verify_signature` does not prevent this: it only proves the request came from *some* correctly-configured org, not that the `team.id` inside the payload belongs to that org. Nothing in `MembershipHandler`'s `ExplicitParameters` schema constrains `team.id` to the signing organization's teams. [8](#0-7) 

### Impact Explanation
A member is added to (or removed from) a `Shipit::Team` that legitimately belongs to a different, unrelated GitHub organization onboarded to the same Shipit instance. If that team is part of `Shipit.github_teams`, this is a direct escalation into Shipit's authorization system (`User#authorized?`), letting an attacker who controls one onboarded org's webhook grant themselves or an accomplice membership in a protected team from another tenant — matching the "High: escalation into `Shipit.github_teams` authorization" category. The action is repeatable against any `github_id` the attacker can enumerate/guess, and the "removed" branch also lets them evict a legitimate member from another org's team.

### Likelihood Explanation
Requires: (1) attacker controls (or can trigger) a legitimate, correctly-signed `membership` webhook for some organization already registered in the host Shipit config, and (2) knowledge of the target `Team`'s numeric `github_id` (visible via GitHub's own team API/UI or Shipit's team listing) belonging to a different org. No Shipit secrets, sessions, or API tokens are required — only the ability to control membership events for one onboarded org, which is explicitly within the given threat model ("emit webhooks from a repository/org they own"). It does not require `Shipit.authentication_disabled?` or an unset `webhook_secret`; it works even when signature verification functions correctly, since verification is per-org, not per-`team.id`.

### Recommendation
Scope the lookup by organization, e.g. `Team.find_or_create_by!(github_id: params.team.id, organization: params.organization.login)`, and additionally verify on every request (not just at creation) that an existing matched `Team#organization` equals `params.organization.login` before performing `add_member`/`members.delete`, raising/dropping the event otherwise.

### Proof of Concept
```ruby
# test/models/shipit/webhooks/handlers/membership_handler_test.rb
test "membership webhook cannot merge teams across organizations" do
  shopify_team = Shipit::Team.create!(
    organization: 'shopify', github_id: 999, name: 'infra', slug: 'infra', api_url: 'https://api.github.com/teams/999'
  )

  payload = {
    'action' => 'added',
    'team' => { 'id' => 999, 'name' => 'infra', 'slug' => 'infra', 'url' => 'https://api.github.com/teams/999' },
    'organization' => { 'login' => 'attacker-org' },
    'member' => { 'login' => 'attacker-user' }
  }

  Shipit::User.stubs(:find_or_create_by_login!).with('attacker-user').returns(shipit_users(:walrus))

  Shipit::Webhooks::Handlers::MembershipHandler.new.call(payload)

  # Broken binding: shopify_team.organization ('shopify') != payload organization ('attacker-org'),
  # yet the attacker-controlled member is now a member of shopify's team.
  assert_includes shopify_team.reload.members, shipit_users(:walrus)
end
```

        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
