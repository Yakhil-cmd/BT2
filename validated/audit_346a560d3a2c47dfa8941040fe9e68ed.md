### Title
Webhook signature verification is bound to `repository.owner.login`, but event handlers act on the unrelated `repository.full_name` field, allowing cross-repository/cross-organization webhook forgery - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`Shipit::WebhooksController#verify_signature` selects which GitHub App/organization secret to check the HMAC signature against using `repository_owner`, a field read straight from the unauthenticated JSON body. Once the signature check passes, the entire raw `params` hash (not just the verified `repository_owner`) is handed to the event handlers, which independently derive the *target* repository from a completely different, unvalidated field: `payload.dig('repository', 'full_name')` in `Shipit::Webhooks::Handlers::Handler#repository_name`. Nothing ties these two fields together, so the organization whose secret authenticated the request is not necessarily the organization/repository that is actually acted upon.

### Finding Description
The relevant binding that should hold is:
`organization authenticated by verify_signature == organization/repository written to by the handler`

In `app/controllers/shipit/webhooks_controller.rb`:
```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [1](#0-0) [2](#0-1) 

The signature is verified using `Shipit.github(organization: repository_owner).verify_webhook_signature`, which only proves the request was signed with the secret configured for *that particular organization key* in `secrets.github` (this engine explicitly supports one secret per GitHub organization, per `lib/shipit.rb#github`/`github_app_config`) [3](#0-2) . Critically, `GitHubApp#verify_webhook_signature` returns `true` unconditionally whenever `webhook_secret` is not configured for that organization:
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
``` [4](#0-3) 
and the documented/example multi-org configuration explicitly ships with `webhook_secret: # nil` for each organization [5](#0-4) .

After `verify_signature` passes, `create` forwards the *entire raw payload* to handlers:
```ruby
def create
  params = JSON.parse(request.raw_post)
  Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }
  head(:ok)
end
``` [6](#0-5) 

`Handler#repository_name`/`#stacks`, used by `PushHandler` and all `PullRequest::*Handler`s, resolves the target `Repository`/`Stack` from a *different* JSON field that was never covered by the organization-scoped signature check:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [7](#0-6) 

`PushHandler` then directly triggers a resync against whatever stack is resolved:
```ruby
def process
  stacks
    .not_archived
    .where(branch:)
    .find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [8](#0-7) 

`PullRequest::OpenedHandler`/`ReopenedHandler`/`LabeledHandler`/`UnlabeledHandler` similarly resolve `repository` from `params.repository.full_name` and call `stack.archive!`/`unarchive!`/`ReviewStackAdapter#find_or_create!` on it [9](#0-8) [10](#0-9) .

Because `repository.owner.login` (used for signature/org selection) and `repository.full_name` (used for target resolution) are two independent, attacker-controlled fields in the same unauthenticated JSON body, and are never cross-checked against each other, an attacker who can produce a validly-signed (or unsigned, when `webhook_secret` is unset) request for **any one** configured organization can set `repository.full_name` to point at a **completely different** organization's repository/stack.

### Impact Explanation
This breaks the deployment-trust boundary between "the organization that authenticated this webhook" and "the repository the engine mutates." A forged webhook aimed at organization A (which is a legitimate configured organization in `secrets.github`, possibly with `webhook_secret` unset per the documented default) can carry `repository.full_name` for organization B's repository, causing:
- `PushHandler` to force a `sync_github` on an arbitrary stack belonging to an unrelated, potentially higher-privilege organization/repository, driving stack state that downstream deploy/merge automation relies on.
- PR handlers to archive/unarchive or provision review stacks for repositories the attacker has no access to.

This matches the "cross-repository writes" impact bucket, since the attacker is causing state-changing engine actions to be applied against a repository/stack outside the trust domain that was actually verified by the HMAC check.

### Likelihood Explanation
Likelihood depends on deployment configuration: the multi-organization webhook binding-confusion is only exploitable when (a) more than one GitHub organization is configured (a documented, supported configuration), and (b) at least one configured organization does not set `webhook_secret` (the documented default in `docs/setup.md` and `config/secrets.development.shopify.yml`), or the attacker otherwise possesses a valid signature for one org. Given the engine ships this exact insecure default in its own setup documentation, the precondition is plausible in real deployments, though it is a configuration-dependent likelihood rather than guaranteed in every install.

### Recommendation
Bind the resolved target repository to the same field/organization that was cryptographically verified: after `verify_signature` succeeds, validate that `payload.dig('repository', 'full_name')` (and `payload.dig('organization', 'login')` for org-scoped events) actually belongs to `repository_owner`/the organization whose secret validated the signature, before invoking any handler. Additionally, treat `webhook_secret: nil` as "signature verification is disabled" and require operators to set a real secret for every configured organization, or refuse to boot/serve webhooks for organizations without one.

### Proof of Concept
Not independently executed; based on static code tracing since Ask mode has no code-execution access. Conceptual PoC given the engine's documented configuration:
1. Configure Shipit with two orgs, `OrgA` (attacker-affiliated, `webhook_secret: nil` as shown in `docs/setup.md`) and `OrgB` (victim org with a real Shipit stack).
2. POST directly to `/github/webhooks` (bypassing GitHub) with header `X-Github-Event: push` and body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": {"login": "OrgA"},
    "full_name": "OrgB/victim-repo"
  }
}
```
3. `verify_signature` calls `Shipit.github(organization: "OrgA").verify_webhook_signature(...)`, which returns `true` unconditionally because `OrgA`'s `webhook_secret` is `nil`.
4. `PushHandler#process` resolves `stacks` via `Repository.from_github_repo_name("OrgB/victim-repo")`, unrelated to `OrgA`, and calls `stack.sync_github(expected_head_sha: ...)` on the victim's stack — an action the attacker was never authorized to trigger.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
