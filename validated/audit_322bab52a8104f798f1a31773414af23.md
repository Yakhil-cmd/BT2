### Title
`HistoryStorageCode` Contains PUSH0 Opcode Executed Without Shanghai Guard — (`blockchain/state_processor.go`, `params/config.go`)

### Summary

`params.HistoryStorageCode` (the EIP-2935 history storage contract bytecode) contains the `PUSH0` (0x5f) opcode, which is only valid after the Shanghai hardfork. `ProcessParentBlockHash` is invoked every block once Prague is active, but neither `InitializeState` nor `ProcessParentBlockHash` checks that Shanghai is also active. Critically, `CheckConfigForkOrder` has a structural gap that silently permits `PragueCompatibleBlock` to be set while `ShanghaiCompatibleBlock` is `nil`. On such a chain, every post-Prague block silently fails to store the parent block hash, producing an incorrect state root.

---

### Finding Description

**Step 1 — The bytecode dependency.**

The test in `blockchain/blockchain_test.go` explicitly documents the constraint:

```go
chainConfig = &params.ChainConfig{
    ShanghaiCompatibleBlock: common.Big0,
    // Shanghai fork is necesasry because `params.HistoryStorageCode` contains `PUSH0(0x5f)` instruction
}
``` [1](#0-0) 

`PUSH0` (opcode `0x5f`) is only added to the EVM jump table in `newShanghaiInstructionSet`:

```go
func newShanghaiInstructionSet() JumpTable {
    instructionSet := newKoreInstructionSet()
    enable3855(&instructionSet) // PUSH0 opcode
    ...
}
``` [2](#0-1) 

Without Shanghai, `jt[PUSH0]` is `nil`, so any call into `HistoryStorageCode` hits an invalid opcode and the EVM call reverts.

---

**Step 2 — The call site has no Shanghai guard.**

`InitializeState` triggers `ProcessParentBlockHash` on every block once Prague is active, with no check that Shanghai is also active:

```go
func (p *StateProcessor) InitializeState(header *types.Header, statedb *state.StateDB) {
    if p.bc.chainConfig.IsPragueForkEnabled(header.Number) {
        context := NewEVMBlockContext(header, p.bc, nil)
        vmenv := vm.NewEVM(context, vm.TxContext{}, statedb, p.bc.chainConfig, &vm.Config{})
        ProcessParentBlockHash(header, vmenv, statedb, p.bc.chainConfig.Rules(header.Number))
    }
    ...
}
``` [3](#0-2) 

`ProcessParentBlockHash` calls `HistoryStorageAddress` and **ignores the return value**, so a revert due to invalid opcode is silently swallowed:

```go
vmenv.Call(vm.AccountRef(from), *msg.To(), msg.Data(), gasLimit, common.Big0)
statedb.Finalise(true, true)
return nil
``` [4](#0-3) 

---

**Step 3 — `CheckConfigForkOrder` does not enforce Shanghai before Prague.**

The ordering check tracks only the last *non-nil* fork via `lastFork`. When a fork is `nil`, `lastFork` is not updated:

```go
// If it was not set, then ignore it
if cur.block != nil {
    lastFork = cur
}
``` [5](#0-4) 

The guard `lastFork.block == nil && cur.block != nil` is therefore **never reachable in practice** — once any non-nil fork has been seen, `lastFork.block` is always non-nil. Tracing through a config with `Kore=100, Shanghai=nil, Prague=200`:

| Iteration | cur | lastFork after |
|---|---|---|
| koreBlock=100 | 100 | {kore, 100} |
| shanghaiBlock=nil | nil | {kore, 100} (unchanged) |
| cancunBlock=nil | nil | {kore, 100} (unchanged) |
| randaoBlock=nil | nil | {kore, 100} (unchanged) |
| kaiaBlock=nil | nil | {kore, 100} (unchanged) |
| pragueBlock=200 | 200 | check: 100 > 200? NO → **no error** | [6](#0-5) 

The `homi` tool exposes `--prague-compatible-blocknumber` and `--shanghai-compatible-blocknumber` as independent flags, so a private-network or service-chain operator can trivially produce this configuration. [7](#0-6) 

---

### Impact Explanation

On a chain where `PragueCompatibleBlock` is set but `ShanghaiCompatibleBlock` is `nil`:

1. At every block ≥ Prague activation, `ProcessParentBlockHash` calls `HistoryStorageAddress`.
2. The EVM executes `HistoryStorageCode`, hits `PUSH0` (0x5f), finds `jt[PUSH0] == nil`, and reverts.
3. The revert is silently discarded; the parent block hash is **never written** to the history storage contract.
4. `statedb.Finalise` computes a state root that omits the EIP-2935 storage update.
5. Any node that later syncs with a corrected config (Shanghai active) computes a **different state root** for every post-Prague block, causing a permanent consensus split.
6. Contracts relying on `BLOCKHASH` for historical blocks (via EIP-2935) receive stale/zero values, corrupting any protocol logic that depends on them.

The corrupted value is the storage slot in `HistoryStorageAddress` that should hold `header.ParentHash` — it remains zero instead of the correct hash.

---

### Likelihood Explanation

- Mainnet and Kairos are not affected: both have `ShanghaiCompatibleBlock` set well before `PragueCompatibleBlock`.
- Private networks and service chains configured with `homi` or a hand-crafted `genesis.json` are at risk. The `CheckConfigForkOrder` gap means the misconfiguration passes all built-in validation silently.
- The failure is completely silent at runtime (no log, no error, no revert propagated), making it very hard to detect without explicit monitoring of the history storage contract.

---

### Recommendation

1. **Fix `CheckConfigForkOrder`** to explicitly require that `ShanghaiCompatibleBlock` is non-nil whenever `PragueCompatibleBlock` is non-nil (and similarly for every fork that depends on a prior fork's opcodes):

```go
// After the loop, add explicit dependency checks:
if c.PragueCompatibleBlock != nil && c.ShanghaiCompatibleBlock == nil {
    return fmt.Errorf("pragueBlock requires shanghaiBlock to be enabled")
}
```

2. **Add a Shanghai guard in `InitializeState`** as a defence-in-depth measure:

```go
if p.bc.chainConfig.IsPragueForkEnabled(header.Number) &&
   p.bc.chainConfig.IsShanghaiForkEnabled(header.Number) {
    ...
    ProcessParentBlockHash(...)
}
```

3. **Propagate the error** from `ProcessParentBlockHash` so that a failed call causes block processing to fail rather than silently producing an incorrect state root.

---

### Proof of Concept

The existing test already documents the dependency:

```go
chainConfig = &params.ChainConfig{
    ShanghaiCompatibleBlock: common.Big0,
    // Shanghai fork is necesasry because `params.HistoryStorageCode` contains `PUSH0(0x5f)` instruction
}
``` [1](#0-0) 

To reproduce the silent failure:

1. Create a `ChainConfig` with `KoreCompatibleBlock: big.NewInt(0)`, `ShanghaiCompatibleBlock: nil`, `PragueCompatibleBlock: big.NewInt(0)`.
2. Confirm `CheckConfigForkOrder()` returns `nil` (no error).
3. Run `InitializeState` for a block at Prague height.
4. Observe that `HistoryStorageAddress` storage slot for `header.Number-1` remains zero (parent hash not stored).
5. Compute the state root — it differs from the root produced by the same block on a chain with Shanghai active.

func (c *ChainConfig) CheckConfigForkOrder() error {
	type fork struct {
		name  string
		block *big.Int
	}
	var lastFork fork
	for _, cur := range []fork{
		{name: "istanbulBlock", block: c.IstanbulCompatibleBlock},
		{name: "londonBlock", block: c.LondonCompatibleBlock},
		{name: "ethTxTypeBlock", block: c.EthTxTypeCompatibleBlock},
		{name: "magmaBlock", block: c.MagmaCompatibleBlock},
		{name: "koreBlock", block: c.KoreCompatibleBlock},
		{name: "shanghaiBlock", block: c.ShanghaiCompatibleBlock},
		{name: "cancunBlock", block: c.CancunCompatibleBlock},
		{name: "randaoBlock", block: c.RandaoCompatibleBlock},
		{name: "kaiaBlock", block: c.KaiaCompatibleBlock},
		{name: "pragueBlock", block: c.PragueCompatibleBlock},
		{name: "osakaBlock", block: c.OsakaCompatibleBlock},
		{name: "permissionlessBlock", block: c.PermissionlessCompatibleBlock},
	} {
		if lastFork.name != "" {
			// Next one must be higher number
			if lastFork.block == nil && cur.block != nil {
				return fmt.Errorf("unsupported fork ordering: %v not enabled, but %v enabled at %v",
					lastFork.name, cur.name, cur.block)
			}
			if lastFork.block != nil && cur.block != nil {
				if lastFork.block.Cmp(cur.block) > 0 {
					return fmt.Errorf("unsupported fork ordering: %v enabled at %v, but %v enabled at %v",
						lastFork.name, lastFork.block, cur.name, cur.block)
				}
			}
		}
		// If it was not set, then ignore it
		if cur.block != nil {
			lastFork = cur
		}
	}
	return nil
}
