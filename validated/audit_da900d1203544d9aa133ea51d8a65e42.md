### Title
Webhook signature org binding uses `repository.owner.login` while stack resolution uses `repository.full_name`, allowing cross-tenant `ReviewStack` archive/deprovision - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb`, `app/models/shipit/repository.rb`)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp`/`webhook_secret` to validate the HMAC using `params.dig('repository', 'owner', 'login')`, but `ClosedHandler#repository` (and `Repository.from_github_repo_name`) resolves the target `Repository`/`ReviewStack` using the separate `params.repository.full_name` field. Because these two JSON fields are independently attacker-controlled in a self-crafted payload, an attacker who owns `OrgA/forked-repo` can sign a payload with OrgA's secret while pointing the business-logic fields at `OrgB/protected-repo`, causing `ReviewStackAdapter#archive!` to deprovision and archive a stack that belongs to OrgB.

### Finding Description
The broken binding, stated as an equality that must hold but does not:

`organization_used_for_signature_verification (params.repository.owner.login) == organization_used_for_stack_resolution (params.repository.full_name.split('/').first)`

Trace:
1. `WebhooksController#verify_signature` computes `repository_owner` via `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` and fetches `Shipit.github(organization: repository_owner)`, then calls `github_app.verify_webhook_signature(signature_header, raw_body)` which HMACs the **entire raw body** with that organization's `webhook_secret` [3](#0-2) , [4](#0-3) .
2. If verification succeeds, `WebhooksController#create` dispatches the same raw `params` hash to `ClosedHandler#process` unchanged [5](#0-4) .
3. `ClosedHandler#repository` resolves the target repo via `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, which is a completely separate field from `repository.owner.login` used in step 1 [6](#0-5) , [1](#0-0) .
4. `ClosedHandler#review_stack` builds a `ReviewStackAdapter` scoped to `repository.review_stacks` (OrgB's stacks) and calls `.archive!`, which removes the stack from the provisioning queue, deprovisions it, and archives it [7](#0-6) , [8](#0-7) .

Attacker request: a JSON body where `repository.owner.login = "OrgA"` and `repository.full_name = "OrgB/protected-repo"`, `number` = the target PR number, `action = "closed"`, signed with `X-Hub-Signature: sha1=HMAC(OrgA_webhook_secret, raw_body)`. `verify_signature` looks up OrgA's app config (which the attacker legitimately controls/knows because it's their own org's webhook secret), verifies successfully, and the request proceeds to `ClosedHandler`, which acts on OrgB's `ReviewStack` because it only reads `full_name`.

None of the existing guards catch this: `verify_signature` never checks that the organization it authenticated against matches the repository the handler will act on; `ExplicitParameters` only validates types/presence of `repository.full_name`, not cross-consistency with `repository.owner.login`; `drop_unhandled_event` and `check_if_ping` are irrelevant to this path; there is no `Repository` lookup or ownership check performed before dispatch in `WebhooksController#create`.

### Impact Explanation
An unauthenticated GitHub user in a completely unrelated organization can force an unauthorized deprovision/archive of any other organization's active `ReviewStack` (identified only by guessable/public repo full name and PR number), causing a denial of that org's deploy pipeline. This is a payload from one repository (attacker's) mutating another repository's/organization's stack state, matching the "Critical: a payload for one repository mutating another's stack" impact category. It is repeatable against any repository/organization configured in `Shipit.secrets.github`, as long as the attacker also controls at least one onboarded organization (to obtain a valid `webhook_secret` for signing).

### Likelihood Explanation
Requires the multi-org `github:` secrets configuration (per `docs/setup.md`) where OrgA and OrgB have distinct `webhook_secret` values, and OrgB must have an active non-archived `ReviewStack` for a PR number the attacker knows/guesses. The attacker needs no privileges beyond being onboarded (or being any legitimate user) in OrgA — they can trivially trigger `closed` webhooks from their own repo and capture/replay the signature, or self-craft the HMAC directly since they know their own org's secret. This is low-cost and fully repeatable/scriptable.

### Recommendation
In `WebhooksController#verify_signature`, or in the dispatch path, ensure the organization used to select the `webhook_secret` is the same organization the handler will act against — e.g., cross-check `params.dig('repository', 'owner', 'login')` against the owner parsed from `params.dig('repository', 'full_name')` and reject (422) if they differ, or better, derive both values from a single canonical field. Additionally, `Handler`/`ReviewStackAdapter` should independently verify that the resolved `Repository.owner` matches the organization that was cryptographically verified for that request, rather than trusting `full_name` in isolation.

```ruby
test "cross-org closed webhook cannot archive another org's review stack" do
  # Arrange: two orgs with distinct webhook_secret configs
  Shipit.stubs(:secrets).returns(OpenStruct.new(github: {
    orga: { webhook_secret: "orga-secret", app_id: 1, installation_id: 1, private_key: TEST_PRIVATE_KEY },
    orgb: { webhook_secret: "orgb-secret", app_id: 2, installation_id: 2, private_key: TEST_PRIVATE_KEY }
  }))

  repo_b = shipit_repositories(:shipit) # owner: "orgb"
  stack = create_review_stack(repo_b, environment: "pr42")
  stack.update!(provision_status: :provisioned)
  refute stack.archived?

  payload = payload_parsed(:pull_request_closed)
  payload["repository"]["owner"]["login"] = "orga"      # used for signature org lookup
  payload["repository"]["full_name"] = "orgb/protected-repo" # used by ClosedHandler
  payload["number"] = 42
  raw = payload.to_json
  signature = "sha1=#{OpenSSL::HMAC.hexdigest('sha1', 'orga-secret', raw)}"

  @request.headers["X-Github-Event"] = "pull_request"
  @request.headers["X-Hub-Signature"] = signature

  post :create, body: raw, as: :json
  assert_response :ok

  # Assert: WEBHOOK_PROVENANCE binding must hold (signing org == target repo owner);
  # if it fails, stack ends up archived despite being signed by an unrelated org.
  refute stack.reload.archived?, "OrgA's webhook must not archive OrgB's ReviewStack"
end
```
If run against the current code, `verify_signature` succeeds using OrgA's secret (since `repository.owner.login == "orga"`), `ClosedHandler` resolves the repository via `full_name == "orgb/protected-repo"`, and `stack.archived?` becomes `true`, proving the cross-tenant mutation.

```ruby
      return true unless webhook_secret
```
