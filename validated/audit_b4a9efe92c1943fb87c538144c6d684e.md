### Title
Unbounded recursion in shared-address definition parsing causes stack overflow (DoS) before validation limits apply - ([File: wallet_defined_by_addresses.js])

### Summary
`handleNewSharedAddress()` in `wallet_defined_by_addresses.js` processes an incoming `new_shared_address` device message and, before running the properly complexity/depth-limited `Definition.validateDefinition()`, calls `extractAddressPathsFromDefinition(body.definition)` — a synchronous, unbounded recursive tree-walker with no depth or complexity limit. A paired device can craft a definition consisting of thousands of nested `and`/`or` operators to blow the JS call stack of the recipient's wallet process, analogous to the Apache Traffic Server PROXY-protocol parser overflowing the stack while handling attacker-controlled input before proper bounds checking.

### Finding Description
`handleNewSharedAddress` only performs a shallow structural check on the incoming definition: [1](#0-0) 

It then immediately calls `extractAddressPathsFromDefinition(body.definition)`, whose `traverse()` function recurses into every `or`/`and`/`r of set`/`weighted and` node with **no depth limit and no complexity counter**, unlike the equivalent recursive evaluator in `definition.js`, which enforces `MAX_COMPLEXITY`/`MAX_OPS` on every recursive step: [2](#0-1) [3](#0-2) 

The properly bounded validation (`validateAddressDefinition` → `Definition.validateDefinition`, which does check `MAX_COMPLEXITY`/`MAX_OPS`) only runs *after* `extractAddressPathsFromDefinition` has already fully recursed through the attacker-supplied structure: [4](#0-3) 

Because `body.definition` comes directly from a device-to-device message (reachable by any paired device without further privilege), an attacker can nest `["and", [ ["and", [ ... ] ] ]]` to an arbitrary depth. Each level only adds a small, constant amount of work in `traverse()`, so a message of a few hundred KB to a few MB can encode tens of thousands of nesting levels, which is enough to exhaust the V8 call stack and crash the Node.js process with `RangeError: Maximum call stack size exceeded` (an unhandled exception, since `traverse` has no error handling), well before `Definition.validateDefinition`'s `MAX_COMPLEXITY`/`MAX_OPS`/incremental-async recursion (which yields via `async.eachSeries`/`setImmediate` to avoid deep native stacks) ever gets a chance to reject it.

The similarly-structured `getMemberDeviceAddressesBySigningPaths()` used in `validateAddressDefinitionTemplate()` (the shared-address *template* creation flow) has the identical unbounded-recursion pattern and is reachable the same way (crafted `create_new_shared_address` proposal from a device peer): [5](#0-4) 

### Impact Explanation
This is a remotely triggerable crash of a peer's wallet process, reachable by any device that is or can become paired with the victim (a paired-device message path, which is in scope per the analog rules). Since incoming device messages are typically queued/redelivered by the hub until acknowledged, a poisoned `new_shared_address` payload can cause a persistent crash loop each time the victim's wallet starts up and re-processes its pending messages, effectively denying the victim wallet's normal operation (including access to any funds managed through that wallet instance) until the offending message is manually purged — a node/wallet availability impact analogous to "freezing" funds/functionality.

### Likelihood Explanation
Likelihood is high for any attacker who can get paired with a victim device (a routine, low-barrier action in this wallet's device-pairing model) — no special node/hub privilege, no valid signatures, and no on-chain unit is required. The payload is a plain JS array structure trivially constructed and requires no cryptographic material.

### Recommendation
- Add an explicit recursion-depth (and/or node-count) limit inside `traverse()` in `extractAddressPathsFromDefinition()` and in `evaluate()` inside `getMemberDeviceAddressesBySigningPaths()`, mirroring the `MAX_DEPTH`/`MAX_COMPLEXITY`/`MAX_OPS` protections already used in `definition.js`/`aa_validation.js`, and reject/abort processing once the limit is exceeded.
- Alternatively, reuse the existing `isTooDeeplyNestedOrHasTooManyNodes()` / `isTooBigObj()` helpers from `string_utils.js` to pre-screen `body.definition` (and `arrDefinitionTemplate`) for excessive depth/size before any recursive processing, exactly as is done elsewhere for other untrusted structures.
- Ensure this pre-check happens before *any* recursive walk of attacker-supplied definitions in the device-message handlers (`handleNewSharedAddress`, `validateAddressDefinitionTemplate`), not only inside the final `Definition.validateDefinition` call.

### Proof of Concept
1. Attacker pairs with victim's wallet (or is already paired, e.g., as a shared-wallet co-signer candidate).
2. Attacker sends a `new_shared_address` device message where `body.definition` is a deeply nested structure such as:
   `["and", [ ["and", [ ["and", [ ... /* repeated ~50,000 times */ ... ["sig", {pubkey: "..."}] ] ] ] ] ] ]`
   and `body.address` set to the correct `objectHash.getChash160()` c-hash of that definition (trivial to compute locally), with a minimal `body.signers` map satisfying the shallow checks.
3. On receipt, `handleNewSharedAddress()` passes the definition to `extractAddressPathsFromDefinition()`, whose `traverse()` recurses ~50,000 levels deep with no depth check, crashing the victim's wallet process with a stack overflow before `Definition.validateDefinition`'s complexity limits are ever consulted.

// Returns a map of signing_path -> address for every ["address", ...] leaf in the definition
function extractAddressPathsFromDefinition(arrDefinition) {
	var result = {};
	function traverse(arr, path) {
		if (!Array.isArray(arr) || arr.length < 2) return;
		var op = arr[0];
		var args = arr[1];
		switch (op) {
			case 'or':
			case 'and':
				if (Array.isArray(args))
					for (var i = 0; i < args.length; i++)
						traverse(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				result[path] = args;
				break;
			case 'hash':
				result[path] = 'secret';
				break;
			case 'in merkle':
				result[path] = ''; // empty address
				break;
		}
	}
	traverse(arrDefinition, 'r');
	return result;
}
