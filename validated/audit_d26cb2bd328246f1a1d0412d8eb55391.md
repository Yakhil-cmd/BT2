Based on my research, I found a concrete analog in the AA (Autonomous Agent) message-handling logic that mirrors the OpenQ bug class: a deposit path exists into a contract-like entity, but the corresponding withdrawal/claim path silently fails for the same asset type, permanently trapping funds.

### Title
Fixed-denomination (indivisible/NFT-like) assets sent to an AA are permanently locked because AAs can accept them as trigger payments but can never send them back out - ([File: aa_composer.js])

### Summary
An Autonomous Agent (AA) can receive a payment denominated in a `fixed_denominations` asset (ocore's indivisible, NFT-like asset type) as part of a trigger unit, and the framework credits that asset to the AA's balance. However, when the AA's own bytecode later attempts to send a `payment` message for that same asset back out (e.g., to return or forward it to a user), the message is silently dropped by the AA composer instead of being executed or causing a bounce.

### Finding Description
`getTrigger()` aggregates all `payment` outputs sent to the AA address regardless of asset type, with no exclusion for fixed-denomination assets: [1](#0-0) 

`updateInitialAABalances()` (called from `handleTrigger`) then unconditionally credits `trigger.outputs[asset]` — including fixed-denomination assets — to `aa_balances` for the AA address: [2](#0-1) 

There is no earlier validation step (in `validateAATrigger` in `validation.js`, or in `checkAAOutputs` in `aa_addresses.js`) that rejects or bounces a trigger carrying a fixed-denomination asset; both only check bounce fees and output cardinality per address/asset, not asset divisibility type: [3](#0-2) [4](#0-3) 

When the AA's `messages` template subsequently includes a `payment` message for that fixed-denomination asset (e.g., an author intending to forward or refund the NFT-like coin), `sendUnit()` explicitly detects `objAsset.fixed_denominations` and skips completing the message ("will skip it later"): [5](#0-4) 

The message is then unconditionally filtered out of the outgoing unit before it is ever built: [6](#0-5) 

If this filtering removes the only substantive message, the AA silently produces an empty response ("no messages after removing fixed denominations") instead of bouncing the trigger or reporting failure to the user; the state-update formula and balance bookkeeping still proceed as if the trigger were accepted. This is analogous to the OpenQ finding: the deposit path (`receiveNft`/trigger payment) exists and is fully validated, but the corresponding claim/withdrawal path (payment `messages`) is a no-op for the exact same asset class, so value that enters has no code path to leave.

### Impact Explanation
Any indivisible/fixed-denomination asset (ocore's closest analog to an NFT — non-fungible, denominated coins) sent to an AA address is permanently and irrecoverably locked in that AA's balance. This is not a mistake confined to one poorly written AA contract; it is a protocol-level limitation baked into `aa_composer.js` that silently defeats any AA author's attempt to accept, escrow, or forward such assets, with no bounce or error surfaced to the trigger sender. Funds (indivisible asset coins) are trapped in the AA with no method — neither via AA-authored `oscript`/`ojson` logic nor any other described interface — to release them, constituting a permanent freezing of user assets.

### Likelihood Explanation
Likelihood is driven purely by any unprivileged user or AA author choosing to send a fixed-denomination asset to any AA address, which is a completely permissionless action requiring no special privilege — an ordinary payment message to an AA address. Because ocore's AA validation layer performs no asset-divisibility check on triggers, and because AA authors have no way to know in advance that indivisible-asset payment messages will be dropped (the drop happens deep inside `aa_composer.js` internals, not surfaced during AA definition validation in `aa_validation.js`), any AA that is (mistakenly or intentionally) sent such an asset, or that is designed to interact with one, will silently lose the ability to return it.

### Recommendation
Either (a) reject/bounce triggers that include `fixed_denominations` asset payments to AA addresses at validation time (in `validateAATrigger` in `validation.js` or in `getTrigger`/`updateInitialAABalances` in `aa_composer.js`), so senders are immediately informed the AA cannot hold such assets, or (b) implement genuine support for sending fixed-denomination assets from an AA (extending `sendUnit()` to build valid indivisible-asset payment messages with proper denomination/input selection) so that assets accepted into an AA's balance can actually be forwarded back out. At minimum, `sendUnit()` should bounce the entire trigger with an explicit error when a templated message attempting to send a fixed-denomination asset is dropped, rather than silently emitting `handleSuccessfulEmptyResponseUnit`.

### Proof of Concept
1. Deploy an AA whose `messages` template includes, upon receiving any payment, a `payment` message intended to forward the same asset back to `trigger.address` (e.g., an escrow/marketplace AA design similar to OpenQ's `OngoingBounty`).
2. Issue a `fixed_denominations` (indivisible) asset via a normal `asset` definition and payment (see `indivisible_asset.js`).
3. Send a payment of that indivisible asset to the AA's address as a trigger unit; the trigger is accepted by `getTrigger()`/`updateInitialAABalances()` and `aa_balances` for the AA is credited with the asset.
4. Observe that when the AA processes the trigger and attempts to emit the return/forward `payment` message for that asset, `sendUnit()` filters it out at [6](#0-5)  and the AA response completes with no such payment ever sent; the indivisible asset coin remains stuck in the AA's balance with no method in the AA's `oscript`/`ojson` interface capable of releasing it.

function getTrigger(objUnit, receiving_address) {
	var trigger = { address: objUnit.authors[0].address, unit: objUnit.unit, outputs: {} };
	if ("max_aa_responses" in objUnit)
		trigger.max_aa_responses = objUnit.max_aa_responses;
	objUnit.messages.forEach(function (message) {
		if (message.app === 'data' && !trigger.data) // use the first data message, ignore the subsequent ones
			trigger.data = message.payload;
		else if (message.app === 'payment' && message.payload) {
			var payload = message.payload;
			var asset = payload.asset || 'base';
			payload.outputs.forEach(function (output) {
				if (output.address === receiving_address) {
					if (!trigger.outputs[asset])
						trigger.outputs[asset] = 0;
					trigger.outputs[asset] += output.amount; // in case there are several outputs
				}
			});
		}
	});
	if (Object.keys(trigger.outputs).length === 0)
		throw Error("no outputs to " + receiving_address);
	return trigger;
}

function checkAAOutputs(arrPayments, handleResult) {
	var assocAmounts = {};
	arrPayments.forEach(function (payment) {
		var asset = payment.asset || 'base';
		payment.outputs.forEach(function (output) {
			if (!assocAmounts[output.address])
				assocAmounts[output.address] = {};
			if (!assocAmounts[output.address][asset])
				assocAmounts[output.address][asset] = 0;
			assocAmounts[output.address][asset] += output.amount;
		});
	});
	var arrAddresses = Object.keys(assocAmounts);
	readAADefinitions(arrAddresses, function (err, rows) {
		if (err)
			return handleResult(err);
		if (rows.length === 0)
			return handleResult();
		var arrMissingBounceFees = [];
		rows.forEach(function (row) {
			var arrDefinition = JSON.parse(row.definition);
			var bounce_fees = arrDefinition[1].bounce_fees;
			if (!bounce_fees)
				bounce_fees = { base: constants.MIN_BYTES_BOUNCE_FEE };
			if (!bounce_fees.base)
				bounce_fees.base = constants.MIN_BYTES_BOUNCE_FEE;
			for (var asset in bounce_fees) {
				var amount = assocAmounts[row.address][asset] || 0;
				if (amount < bounce_fees[asset])
					arrMissingBounceFees.push({ address: row.address, asset: asset, missing_amount: bounce_fees[asset] - amount, recommended_amount: bounce_fees[asset] });
			}
		});
		if (arrMissingBounceFees.length === 0)
			return handleResult();
		handleResult(new MissingBounceFeesErrorMessage({ error: "The amounts are less than bounce fees", missing_bounce_fees: arrMissingBounceFees }));
	});
}
