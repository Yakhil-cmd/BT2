**Analysis:**

The premise doesn't hold up against the actual code. The `AltFr` conversion in [1](#0-0)  is a straightforward, deterministic, lossless bijection between `ark_bn254::Fr` and the `neptune`-compatible `AltFr` type: both share the exact same field modulus, and the conversion round-trips through the canonical little-endian byte representation of a field element that is always already reduced mod the prime. `Fr::from_le_bytes_mod_order` on a canonical (already-reduced) 32-byte representation is a no-op reduction, not a truncation — there is no "conversion inconsistency" that could cause two distinct logical inputs to map to the same `Fr`/`AltFr` value.

`hash_public_inputs` itself, in [2](#0-1) , packs a large, role-specific set of fields into the Poseidon hash: the ephemeral public key, the account's `IdCommitment` (derived from `aud`/`uid`/pepper — unique per signer/account), expiration data, `iss`, JWT header hash, JWK hash, and override-aud fields. Sender and fee-payer authenticators are verified independently against their own `KeylessPublicKey`/`KeylessSignature`/JWK via `get_public_inputs_hash` ( [3](#0-2) ), and each proof verification in [4](#0-3)  requires a valid Groth16 proof tied to that specific hash — a proof the attacker cannot forge without the corresponding witness (JWT signature over the real `iss`/`aud`/`sub`, valid RSA JWK signature, etc.).

Even under the hypothetical of a Poseidon hash collision between two independently-computed public-input sets (cryptographically infeasible, not something achievable by "attacker-chosen exp/epk fields" alone since idc/iss/jwk are also baked in), the fee-payer/sender role binding is not determined by the `public_inputs_hash` value at all — it's determined by the transaction authenticator structure and the account address that owns the keyless key, which is independent of this hash. There is no code path shown where a matching `public_inputs_hash` value would cause the VM to rebind gas-payer to the wrong address.

This is speculative and not grounded in an identified code defect.

pub fn get_public_inputs_hash(
    sig: &KeylessSignature,
    pk: &KeylessPublicKey,
    jwk: &RSA_JWK,
    config: &Configuration,
) -> anyhow::Result<Fr> {
    if let EphemeralCertificate::ZeroKnowledgeSig(proof) = &sig.cert {
        hash_public_inputs(
            config,
            &sig.ephemeral_pubkey,
            &pk.idc,
            sig.exp_date_secs,
            proof.exp_horizon_secs,
            &pk.iss_val,
            proof.extra_field.as_deref(),
            &sig.jwt_header_json,
            jwk,
            proof.override_aud_val.as_deref(),
        )
    } else {
        bail!("Can only call `get_public_inputs_hash` on keyless::Signature with Groth16 ZK proof")
    }
}
