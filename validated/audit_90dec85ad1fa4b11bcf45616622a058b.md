### Title
Webhook authenticity is bound to an attacker-controlled `repository.owner.login` field instead of the actual repository being written to - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App's `webhook_secret` to validate a payload against by reading `repository.owner.login` (or `organization.login`) straight out of the untrusted JSON body, and `Hook`/`GithubApp#verify_webhook_signature` returns `true` unconditionally whenever that resolved app has no `webhook_secret` configured — a state the project's own docs mark as optional. This breaks the intended binding "organization whose secret verified the request == organization owning the repository/stack the handler subsequently writes to," because the field used to pick the verifying secret and the field used to select the target `Stack`/`Repository` (`repository.full_name`) are independent, attacker-controlled fields inside the same unauthenticated payload.

### Finding Description
`verify_signature` computes the signing org purely from payload content: [1](#0-0) [2](#0-1) 

and `GithubApp#verify_webhook_signature` short-circuits to `true` when no secret is configured for that resolved org: [3](#0-2) 

`webhook_secret` is explicitly documented and shipped as optional (`webhook_secret: # nil` in the example secrets, "Webhook secret (optional)" in the setup guide), so a Shipit install that follows the documented, supported configuration can have no webhook secret set for one or more configured GitHub organizations: [4](#0-3) [5](#0-4) 

Once `verify_signature` passes (either because the secret is absent, or because the attacker matches it to an org whose secret they legitimately hold), `create` re-parses the same raw body and dispatches purely on `X-Github-Event` to handlers (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, membership/pull_request handlers) with no re-check that the `repository.full_name` in the body actually belongs to the org that was used to authenticate the request: [6](#0-5) 

The equality the code should enforce — `organization whose webhook_secret verified the signature == organization that owns the repository/stack the handler acts on` — is never checked; only a free-text field chosen by the sender (`repository.owner.login`) participates in verification, while the actual target resource is selected from a sibling field in the same unauthenticated JSON body.

### Impact Explanation
An unauthenticated remote attacker (no Shipit session, no GitHub credentials, no `ApiClient` token) who can reach the shared `/webhooks` endpoint of a Shipit instance configured per the documented, supported setup (no webhook secret, or a multi-org config where one org's secret is unset/known) can forge arbitrary GitHub event payloads for any `Stack`/`Repository` tracked by that Shipit instance. This includes forging `status` events that create passing CI `Status` records for arbitrary commits/branches, and `push`/`check_suite` events that drive Shipit's sync and check-run pipelines. On stacks with continuous deployment/merge automation enabled, injecting a fabricated "success" status for a commit that never actually passed CI can cause Shipit to treat that commit as deployable/mergeable, resulting in an unauthorized deploy or merge — matching the Critical impact bar ("unauthorized deploy, rollback or merge").

### Likelihood Explanation
Likelihood is high in any deployment that follows the project's own documented configuration guidance, since `webhook_secret` is explicitly optional and the fallback behavior (`return true unless webhook_secret`) silently disables authenticity checking rather than failing closed. No privileged access, GitHub App private key, or session is required — only network reachability to the public `/webhooks` endpoint, which is the documented integration point.

### Recommendation
- Make webhook signature verification fail-closed: reject requests when no `webhook_secret` is configured, or require operators to explicitly opt into an unauthenticated mode with a loud warning, rather than silently trusting all payloads.
- Do not derive the verifying GitHub App/organization from attacker-controlled payload fields (`repository.owner.login`/`organization.login`). If multi-org support is required, verify the signature against every configured org's secret (or bind delivery to org via a GitHub App installation ID / delivery header) and reject if none matches, rather than trusting the payload to self-select its verifier.
- After signature verification succeeds, cross-check that `repository.full_name`/`repository.owner.login` used by downstream handlers actually corresponds to the organization whose secret validated the request before mutating any `Stack`/`Repository`/`Commit` state.

### Proof of Concept
1. Deploy Shipit with `config/secrets.yml` following the documented example, leaving `github.webhook_secret` blank (a supported, documented configuration).
2. As an unauthenticated attacker, `POST /webhooks` with header `X-Github-Event: status` and a JSON body targeting a victim stack's repository/commit:
```json
{
  "sha": "<victim commit sha>",
  "state": "success",
  "context": "ci/forged",
  "branches": [{"name": "master"}],
  "repository": {"full_name": "victim-org/victim-repo", "owner": {"login": "victim-org"}}
}
```
3. `verify_signature` resolves `Shipit.github(organization: "victim-org")`; since `webhook_secret` is unset, `verify_webhook_signature` returns `true` without checking `X-Hub-Signature` at all.
4. `StatusHandler` processes the forged payload and records a passing `Status` for the targeted commit, as exercised by the existing test flow: [7](#0-6) 
5. If the targeted stack has continuous deployment configured to act on green CI status, this forged status can trigger an unauthorized deploy of a commit that never passed real CI.

```ruby
    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e

        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
