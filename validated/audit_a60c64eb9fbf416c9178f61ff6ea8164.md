## Finding: OTW single-instantiation verifier can be bypassed via `FnInfoKey` collision across modules in the same package [1](#0-0) 

### Summary
`FnInfoKey`, the key used by `is_test_fun` to decide whether a function is test-only, is defined as:
```rust
pub struct FnInfoKey {
    pub fn_name: String,
    pub mod_addr: AccountAddress,
}
``` [1](#0-0) 

This key contains only the function name and the *address*, not the module name. Because every module in a published Move package shares the same on-chain address (the package ID), this key cannot distinguish between two different modules of the same package that happen to define a function with the identical name. `verify_module` in `one_time_witness_verifier.rs` calls `is_test_fun(fn_name, module, fn_info_map)` and, if it returns `true`, entirely skips `verify_no_instantiations`, which is the only guard preventing a module from `Pack`-ing its own one-time-witness (OTW) struct more than once [2](#0-1) .

### Finding Description
The intended semantics of `FnInfoMap` are "for a given module (identified by address+name) and function name, is this function test-only." Since `FnInfoKey` drops the module-name component, all functions sharing a name across every module of the same package address collapse into one BTreeMap entry. If a package publisher defines:
- Module `A` with `#[test_only] fun foo(...)`, and
- Module `B` (same package/address) with a *non*-test `fun foo(...)` that `Pack`s module `B`'s OTW struct,

the single `FnInfoKey{ fn_name: "foo", mod_addr: <package address> }` entry (populated as `is_test: true` because of module `A`'s attribute) is what `is_test_fun` returns for module `B`'s `foo` as well, since the lookup key is identical. The verifier then believes module `B::foo` is test code and skips `verify_no_instantiations` for it [3](#0-2) , even though `B::foo` is reachable in production/non-test code and freely instantiates the OTW struct via `Bytecode::Pack` [4](#0-3) .

### Impact Explanation
The single-instantiation guarantee of OTW types is foundational to Sui Move security patterns (`sui::types::is_one_time_witness`, `coin::create_currency`, `package::claim`/`Publisher`, `display::new`, etc.), all of which assume the caller can only ever obtain one instance of the OTW, created exactly once at module `init`. If this guarantee is bypassable, a malicious publisher can grant themselves (or any caller of `B::foo`) unlimited fresh instances of module `B`'s OTW type at runtime, enabling forged `Publisher` objects and duplicate/forged one-time-witness-gated coin/currency creation, matching the "unauthorized object creation" / "verifier bypass chained to theft" Critical impact category.

### Likelihood Explanation
This is directly reachable through the public package-publish path: the attacker is an ordinary package publisher, no privileged actor is required, and both modules with the colliding function name can be constructed entirely by an unprivileged Move source/bytecode. The `FnInfoMap` population and the `is_test_fun` check both occur during standard publish-time verification.

### Recommendation
`FnInfoKey` should be scoped per-module, not merely per-address, e.g., include the module name (or full `ModuleId`) in the key:
```rust
pub struct FnInfoKey {
    pub fn_name: String,
    pub mod_addr: AccountAddress,
    pub mod_name: String, // or use ModuleId directly
}
```
And the population logic (in `crates/sui-move-build/src/lib.rs`) and lookup call sites (`one_time_witness_verifier.rs`, `entry_points_verifier.rs`, `verifier.rs`) must be updated to key/query by full module identity instead of address alone.

### Proof of Concept
1. Author a package with two modules at the same address:
   - `module pkg::a { #[test_only] public fun foo() {} }`
   - `module pkg::b { public struct B has drop { dummy: bool } public fun foo(ctx: &mut TxContext) { let _w = B { dummy: true }; /* Pack B repeatedly */ } }`
2. Compile/publish; the Move compiler's test-info collection marks `("foo", pkg_address)` as test-only (from module `a`'s attribute).
3. During bytecode verification of module `b`, `is_test_fun("foo", module_b, fn_info_map)` looks up the same collapsed key and returns `true`, so `verify_no_instantiations` is skipped for `b::foo`.
4. `b::foo` is now a normal (non-test) entry/public function that can be invoked in any transaction, `Pack`-ing the `B` OTW struct arbitrarily many times.

Note: I was not able to fully read the body of `is_test_fun` or the code in `crates/sui-move-build/src/lib.rs` that populates `FnInfoMap` (tool budget was exhausted before I could confirm exactly how `FnInfoKey` values are constructed and inserted). The conclusion above rests on the confirmed, directly-read definition of `FnInfoKey` (only `fn_name` + `mod_addr`, no module-name field) and the confirmed call site in `one_time_witness_verifier.rs`. If it turns out the population logic actually incorporates the module name into the `fn_name` string (e.g., via a fully-qualified string key) or `mod_addr` is somehow made module-unique, the collision would not occur — this should be verified by reading `crates/sui-move-build/src/lib.rs` and the `is_test_fun` implementation directly in a follow-up session before treating this as fully confirmed.

/// Checks if this module function does not contain instantiation of the one-time witness type
fn verify_no_instantiations(
    module: &CompiledModule,
    fn_def: &FunctionDefinition,
    struct_name: &str,
    struct_def: &StructDefinition,
) -> Result<(), String> {
    if fn_def.code.is_none() {
        return Ok(());
    }
    for bcode in &fn_def.code.as_ref().unwrap().code {
        let struct_def_idx = match bcode {
            Bytecode::Pack(idx) => idx,
            _ => continue,
        };
        // unwrap is safe below since we know we are getting a struct out of a module (see
        // definition of struct_def_at)
        if module.struct_def_at(*struct_def_idx) == struct_def {
            let fn_handle = module.function_handle_at(fn_def.function);
            let fn_name = module.identifier_at(fn_handle.name);
            return Err(format!(
                "one-time witness type {}::{} is instantiated \
                         in the {}::{} function and must never be",
                module.self_id(),
                struct_name,
                module.self_id(),
                fn_name,
            ));
        }
    }
```
