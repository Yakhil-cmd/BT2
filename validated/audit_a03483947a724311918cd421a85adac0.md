### Title
Unchecked RAY value overflow freezes a high-utilization market before index caps engage - (File: `common/src/rates/index.rs`)

### Summary
Interest accrual multiplies scaled market totals by the current indexes before enforcing the configured borrow- and supply-index ceilings. A sufficiently large high-decimal market can therefore overflow `i128` while its stored indexes remain below their caps, causing every operation that first synchronizes the market to revert with `MathOverflow`.

### Finding Description
Each accrual calls `accrue_step`, which calculates `borrowed * borrow_index` and `supplied * supply_index` through `scaled_to_original` before computing utilization and interest. [1](#0-0)  `scaled_to_original` delegates to `Ray::mul`, which panics on an `i128` overflow rather than saturating. [2](#0-1)  Although `update_borrow_index` caps its result at `MAX_BORROW_INDEX_RAY`, that cap is checked only after `old_index.mul(interest_factor)` has already executed. [3](#0-2)  The supplier-reward calculation also multiplies the scaled borrow balance by both indexes before subtracting accrued interest. [4](#0-3) 

An unprivileged account can create the required state through `Controller::supply(caller, account_id, spoke_id, assets)` and `Controller::borrow(caller, account_id, borrows, to)`, then trigger accrual through the public index-update path that reaches `Pool::update_indexes(env, hub_assets)`. [5](#0-4) [6](#0-5)  Pool accrual invokes `global_sync`, which repeatedly calls `accrue_chunk` and `accrue_step`. [7](#0-6) 

### Impact Explanation
Once `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, accrual reverts before committing updated indexes. Every pool mutation loads a synchronized market through `synced_market`, so supply, borrow, withdraw, repay, liquidation-related legs, and other market mutations all hit the same overflow before executing their intended logic. [8](#0-7)  Even replacing the interest-rate model first commits a renewed, synchronized market, so changing the curve cannot bypass the failing accrual. [9](#0-8)  The result is freezing of supplier withdrawals, borrower repayments, and liquidation processing for the affected market absent a contract-code recovery path. The existing regression test demonstrates that stored indexes remain below their caps while withdrawals and repayments revert with `MathOverflow`. [10](#0-9) 

### Likelihood Explanation
The condition requires an exceptionally large high-decimal market and sustained high utilization, but it does not require privileged access once protocol configuration permits the position size. The reproduction uses one billion 18-decimal tokens supplied by `BOB` and 98% borrowed by `ALICE`, then advances ledger time and calls index updates until accrual fails. [11](#0-10)  A single funded attacker can establish the supply and borrow positions using the normal controller entrypoints, while a naturally grown market can later be pushed over the boundary by any caller able to invoke index accrual. The time-dependent and balance-dependent prerequisites reduce likelihood, but the market-wide freeze makes the remaining risk material.

### Recommendation
Bound the scaled-value multiplication before accrual instead of relying only on index caps. In particular:

- Make `Ray` market-total calculations saturate at `i128::MAX` or use the existing `I256` path where feasible before checking index bounds.
- Evaluate whether `borrow_index * interest_factor` would exceed `MAX_BORROW_INDEX_RAY` using checked division or widened arithmetic before multiplying.
- Add a regression assertion that `update_indexes`, `withdraw`, `repay`, and liquidation continue operating at the market-total value ceiling.
- Prefer a recovery-safe cap on total scaled debt or accrued debt value, because a revert during mandatory accrual prevents both exits and administrative rate-model changes.

### Proof of Concept
The repository already contains a deterministic reproduction:

```rust
let principal = BILLION * 10i128.pow(18);
t.supply_raw(BOB, "BIG18", principal);
let debt = principal / 100 * 98;
t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
t.borrow_raw(ALICE, "BIG18", debt);

loop {
    t.advance_time(YEAR_SECS);
    if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
        break e;
    }
}
```

The test asserts that the failing call returns `MathOverflow`, that `borrow_index < MAX_BORROW_INDEX_RAY`, and that subsequent `withdraw` and `repay` calls also fail with `MathOverflow`. [12](#0-11)

```rust
/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}
```

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
```

```rust
/// Loads a market cache and accrues interest through the current ledger time.
pub(crate) fn synced_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    let mut cache = Cache::load(env, hub_asset);
    interest::global_sync(env, &mut cache);
    cache
}

/// Renews instance TTL, then loads and accrues the market.
pub(crate) fn renewed_market(env: &Env, hub_asset: &HubAssetKey) -> Cache {
    renew_instance(env);

}

/// Validates `action.amount ≥ 0`, syncs the market, and returns (cache, scaled position).
```

```rust
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
