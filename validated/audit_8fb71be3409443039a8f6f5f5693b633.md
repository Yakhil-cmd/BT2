### Title
Bridge KLAY Transfer to `address(0)` Burns Destination Bridge Liquidity — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

`BridgeTransferKLAY.requestKLAYTransfer()` accepts `_to = address(0)` without validation. The bridge operator's off-chain relay automatically processes every `RequestValueTransfer` event, calling `handleKLAYTransfer` with `_to = address(0)`, which executes a low-level `.call.value()` that succeeds and permanently burns KLAY from the destination bridge's liquidity pool.

---

### Finding Description

`requestKLAYTransfer` is a public, permissionless function that accepts an arbitrary `_to` address and emits a `RequestValueTransfer` event: [1](#0-0) 

Neither `requestKLAYTransfer` nor the internal `_requestKLAYTransfer` contains a `require(_to != address(0))` guard. The emitted event is consumed by the bridge relay daemon (`bridge_manager.go`), which unconditionally calls `HandleKLAYTransfer` on the counterpart bridge for every event it observes: [2](#0-1) 

`handleKLAYTransfer` then executes:

```solidity
(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");
``` [3](#0-2) 

In the EVM, a low-level `.call` to `address(0)` with value succeeds — the value is credited to `address(0)`'s balance and the call returns `true`. There is no revert. The KLAY is permanently burned from the destination bridge's liquidity pool.

---

### Impact Explanation

An unprivileged attacker calls:

```
requestKLAYTransfer(address(0), X, extraData)  // msg.value = X + fee
```

on the source bridge. The relay daemon observes the event and calls `handleKLAYTransfer(..., address(0), X, ...)` on the destination bridge. `X` KLAY is transferred to `address(0)` and burned. The destination bridge's liquidity is reduced by `X`. Repeated calls drain the bridge pool, preventing legitimate users from withdrawing their bridged assets.

This is an **unauthorized burn of system-managed bridge funds** triggered by any unprivileged caller.

---

### Likelihood Explanation

- `requestKLAYTransfer` is callable by any address with KLAY.
- The bridge relay (`handleRequestValueTransferEvent`) processes all events without filtering `_to == address(0)`.
- The attacker's cost is 1:1 with the bridge's loss (they burn their own KLAY to burn the bridge's KLAY), making this a viable griefing/DoS attack against bridge liquidity.
- No privileged access, no key compromise, no validator collusion required.

---

### Recommendation

Add a zero-address guard in both the request and handle paths:

In `_requestKLAYTransfer`:
```solidity
require(_to != address(0), "invalid recipient: zero address");
```

In `handleKLAYTransfer`:
```solidity
require(_to != address(0), "invalid recipient: zero address");
```

The same guard should be applied to `_requestERC20Transfer` and `handleERC20Transfer` for consistency, even though ERC20 `safeTransfer` would revert at the token level.

---

### Proof of Concept

1. Deploy source and destination bridges with liquidity (e.g., 1000 KLAY in destination bridge).
2. Attacker calls `sourceBridge.requestKLAYTransfer(address(0), 100, "0x")` with `msg.value = 100 + fee`.
3. Bridge relay observes `RequestValueTransfer(KLAY, attacker, address(0), ..., 100, ...)`.
4. Relay calls `destBridge.handleKLAYTransfer(txHash, attacker, address(0), 100, nonce, blockNum, "0x")`.
5. `address(0).call.value(100)("")` succeeds; 100 KLAY is burned from destination bridge.
6. Destination bridge balance drops from 1000 to 900 KLAY.
7. Repeat until bridge is drained; legitimate withdrawals fail. [4](#0-3) [5](#0-4)

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
