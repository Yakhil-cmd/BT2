### Title
Forged `pull_request closed` webhook via `organization.login` fallback lets a lenient-org signature verify a cross-tenant repository mutation - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the `GitHubApp` (and thus the HMAC secret) to validate `X-Hub-Signature` using `repository_owner`, which falls back to `organization.login` whenever `repository.owner.login` is absent from the JSON body. `Shipit::Webhooks::Handlers::PullRequest::ClosedHandler`, however, only requires `repository.full_name` (no `owner` sub-key) and resolves/mutates a `Shipit::Repository`/`ReviewStack` from that field. Because these two fields are independently attacker-controlled, an attacker who can trigger webhook delivery for one (lenient, secretless) organization can have the payload's `repository.full_name` point at a stack owned by a different organization and have `ClosedHandler` archive it.

### Finding Description
The broken binding is:

`org_used_for_verification (= repository_owner => organization.login fallback)` MUST equal `org_that_owns(params.repository.full_name)` used by the handler — but nothing enforces this.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
