### Title
`TaskCommands#env` merges attacker-controlled `deploy_spec.machine_env` after `GITHUB_TOKEN`/`GIT_ASKPASS` are set, letting an unprivileged PR author override them - ([File: lib/shipit/task_commands.rb])

### Summary
`Commands#base_env` sets trusted `GITHUB_TOKEN`, `GITHUB_DOMAIN`, and (optionally) `GIT_ASKPASS` [1](#0-0) . `TaskCommands#env` merges `deploy_spec.machine_env` — sourced from `machine.environment` in the repository's own `shipit.yml` — *after* that base env and before final result is used to spawn the process [2](#0-1) , and `Command#unbundled_env`/`Command#start` pass the resulting `@env` straight into `PTY.spawn` with no allowlist [3](#0-2) .

### Finding Description
Broken binding: the set of keys in the env hash reaching `PTY.spawn` for `GITHUB_TOKEN`, `GIT_ASKPASS`, `GITHUB_DOMAIN` must equal exactly the values `Commands#base_env` set, i.e. `Command#env['GITHUB_TOKEN'] == github.token` (the app's own token), never a value read from a repo-controlled `shipit.yml`.

Trace:
- `Commands#base_env` builds `Shipit.env.merge('GITHUB_DOMAIN' => github.domain, 'GITHUB_TOKEN' => github.token)`, plus `GIT_ASKPASS` if `Shipit.use_git_askpass?` [1](#0-0) .
- `TaskCommands#env` (used by `DeployCommands`, task runners, etc.) does `super.merge(@stack.env).merge({...}).merge(deploy_spec.machine_env).merge(@task.env)` [2](#0-1) . `deploy_spec.machine_env` reads `config('machine', 'environment')` directly from the parsed `shipit.yml` with **no key allowlist**, unlike `deploy.variables`, which is filtered through `EnvironmentVariables#permit`/`filter_deploy_envs` [4](#0-3) [5](#0-4) [6](#0-5) .
- `deploy_spec` is `DeploySpec::FileSystem.new(@task.working_directory, @stack)`, checked out at the commit being run [7](#0-6) . For a review stack, that working directory is checked out from the PR branch the attacker controls.
- The merged hash is passed as `env:` into `Command.new`, and `Command#unbundled_env` does `BASE_ENV.merge('PATH'=>...).merge(@env.stringify_keys)` — `@env` (the attacker-influenced hash) wins over `BASE_ENV` (only the OS/Bundler environment, not `GITHUB_TOKEN`) [8](#0-7) . `Command#start` spawns `PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)` [9](#0-8) .

Exploit flow: attacker opens/updates a PR whose branch is used to build/refresh the review stack's `DeploySpec::FileSystem` (e.g. via `StackCommands#build_cacheable_deploy_spec`, `fetch_deployed_revision`, or task working-directory checkout for a running review-stack task) and sets `machine.environment.GITHUB_TOKEN` (or `GIT_ASKPASS`) in their own `shipit.yml`. When any task/deploy runs for that commit, `TaskCommands#env` merges `deploy_spec.machine_env` after `base_env`, so the attacker's value for `GITHUB_TOKEN`/`GIT_ASKPASS` becomes the value actually used by `PTY.spawn` for git/other commands, exfiltrating the token or substituting a malicious `GIT_ASKPASS` script for credential/command injection.

Existing guards that fail to prevent this: `EnvironmentVariables#permit` is only applied to `deploy.variables`/`rollback.variables`/task `variables` (`filter_deploy_envs`, `filter_rollback_envs`, `TaskDefinition#filter_envs`) — none of these paths touch `machine_env`, so there is no allowlist filtering `machine.environment` keys at all [10](#0-9) [11](#0-10) .

### Impact Explanation
An attacker who can influence a stack's `shipit.yml` (via a review-stack PR branch or any workflow where the deploy spec is loaded from a repo-controlled ref before merge) can overwrite `GITHUB_TOKEN`/`GIT_ASKPASS`/`GITHUB_DOMAIN` for any command run through `TaskCommands`/`DeployCommands` for that stack/task. This can exfiltrate the app's real `GITHUB_TOKEN` (by pointing `GIT_ASKPASS` at an attacker script, or reading env in a deploy step) or substitute credentials, enabling RCE / credential theft on the deploy host — matching the Critical category (exfiltration of `GITHUB_TOKEN` / deploy-time secrets, unauthorized command execution).

### Likelihood Explanation
Requires a stack configuration (typically review stacks) where the deploy spec is refreshed/executed against an attacker-controlled branch/PR prior to any merge or maintainer review — a documented and common Shipit feature. No privileged Shipit role, secret, or session is needed; the attacker only needs to control `shipit.yml` content on their own branch/fork, which is exactly the capability granted to any contributor able to open a PR against a repo using Shipit review stacks.

### Recommendation
Apply an explicit allowlist to `machine.environment` similar to `EnvironmentVariables#permit` for `deploy.variables`, and/or ensure `TaskCommands#env`/`Command#unbundled_env` reserve and re-assert the trusted keys (`GITHUB_TOKEN`, `GITHUB_DOMAIN`, `GIT_ASKPASS`) after all repo-controlled env merges, so they cannot be overridden by `deploy_spec.machine_env` or `@task.env`.

### Proof of Concept
Minitest plan (in `test/lib/shipit/task_commands_test.rb` style):
```ruby
test "#env does not allow machine_env to override GITHUB_TOKEN" do
  stack = shipit_stacks(:review_stack)
  task = shipit_tasks(:shipit_restart)
  task.stack = stack

  commands = Shipit::TaskCommands.new(task)
  commands.stubs(:deploy_spec).returns(stub(machine_env: { 'GITHUB_TOKEN' => 'attacker-token' }))

  trusted_token = Shipit.github(organization: stack.repository.owner).token
  env = commands.env

  assert_equal trusted_token, env['GITHUB_TOKEN'], "attacker-controlled machine_env overrode GITHUB_TOKEN"
end
```
Both sides of the binding (`env['GITHUB_TOKEN']` vs. the app's real token) currently diverge because `deploy_spec.machine_env` is merged after `base_env` with no allowlist, confirming the vulnerability.

    def start(&block)
      return if @started

      @control_block = block
      @out = @pid = nil
      FileUtils.mkdir_p(@chdir)
      begin
        @out, child_in, @pid = PTY.spawn(unbundled_env, *interpolated_arguments, chdir: @chdir)
        child_in.close
      rescue Errno::ENOENT
        raise NotFound, "#{Shellwords.split(interpolated_arguments.first).first}: command not found"
      rescue Errno::EACCES
        raise Denied, "#{Shellwords.split(interpolated_arguments.first).first}: Permission denied"
      end
      @started = true
      self
    end

    def unbundled_env
      BASE_ENV.merge('PATH' => "#{Shipit.shell_paths.join(':')}:#{ENV['PATH']}").merge(@env.stringify_keys)
    end
