### Title
Unsanitized PR body/comments written directly to `IOStreams.Out` bypass ANSI/OSC escape stripping, enabling OSC 52 clipboard injection - ([File: pkg/cmd/pr/view/view.go])

### Summary
`gh pr view` renders the PR title, body, and comments through `printHumanPrPreview`, which writes to `opts.IO.Out` directly rather than the sanitizing `opts.IO.ContentOut` writer. Because the human-preview path never routes attacker-controlled body/comment text through the `asciisanitizer`-wrapped `ContentOut`, an OSC 52 payload embedded in a PR body reaches the terminal (or the pager's stdin, since `StartPager` swaps `s.Out` for the pager pipe but `ContentOut` is a separate field) unmodified.

### Finding Description
`(IOStreams).StartPager` at [1](#0-0)  replaces `s.Out` with a pipe to the pager process and separately rebuilds `s.ContentOut` as a sanitizing wrapper over the new `s.Out` via `newContentWriter` [2](#0-1) . The sanitization only takes effect for code paths that write through `ContentOut`.

In `pkg/cmd/pr/view/view.go`, `viewRun` calls `opts.IO.StartPager()` and then, for a TTY, calls `printHumanPrPreview` [3](#0-2) . That function captures `out := opts.IO.Out` (line 183) and uses it for every write, including the markdown-rendered PR body (`fmt.Fprintf(out, "\n%s\n", md)`) and the review/comment list (`fmt.Fprint(out, comments)`) [4](#0-3) . `pr.Body` and comment bodies are attacker-controlled (an issue/PR author can put arbitrary bytes there via the GitHub API), and `markdown.Render` (a thin wrapper over `glamour`) does not strip raw escape bytes from code blocks or inline text [5](#0-4) .

The codebase does have a deliberate sanitization architecture: `IOStreams.ContentOut`, `SetContentSanitization`, and the `Untrusted` wrapper type exist specifically to strip ANSI/OSC escape sequences from externally-authored content before it reaches a terminal [6](#0-5) [7](#0-6) . Other commands (`pr diff`, `release download`, `run view --log`, `repo read-file`) explicitly route untrusted content through `ContentOut`/`CopyGuardedContent`/`Untrusted` before printing [8](#0-7) [9](#0-8) . `pr view`'s human-preview path does not use any of these mechanisms — it prints raw markdown output straight to `IO.Out`, so OSC 52 (`\x1b]52;c;<base64>\x07`) or other terminal-manipulating sequences embedded in a PR/issue body or comment pass through untouched.

### Impact Explanation
An attacker who authors a PR/issue body or comment can embed an OSC 52 sequence that, when the victim runs `gh pr view` (or `gh pr view --comments`) against that PR/issue, writes attacker-chosen text to the victim's system clipboard. Combined with common shell auto-execute-on-paste terminal configurations or simple social engineering to paste-and-run, this can lead to command execution on the victim's machine — matching a Critical/RCE-class impact for GitHub CLI (arbitrary code execution via terminal escape injection).

### Likelihood Explanation
Highly feasible and repeatable: any unprivileged GitHub user can set a PR/issue title, body, or comment containing raw bytes; no privileged action or MITM is required. The victim only needs to run an ordinary `gh pr view` on that content while connected to an OSC-52-capable terminal (widely supported, including over SSH/tmux). This is a direct, reachable path with no gating check in the `printHumanPrPreview` function.

### Recommendation
Route all attacker-controlled text in `printHumanPrPreview` (and `printRawPrPreview`, and `shared.CommentList`/`RawCommentList` outputs) through `opts.IO.ContentOut` (or wrap the body/comments in `iostreams.Untrusted` and print via its sanitizing `String()`), instead of writing to `opts.IO.Out` directly. Alternatively, sanitize the string returned by `markdown.Render` and any comment text before formatting/printing.

func (s *IOStreams) StartPager() error {
	if s.pagerCommand == "" || s.pagerCommand == "cat" || !s.IsStdoutTTY() {
		return nil
	}

	pagerArgs, err := shlex.Split(s.pagerCommand)
	if err != nil {
		return err
	}

	pagerEnv := os.Environ()
	for i := len(pagerEnv) - 1; i >= 0; i-- {
		if strings.HasPrefix(pagerEnv[i], "PAGER=") {
			pagerEnv = append(pagerEnv[0:i], pagerEnv[i+1:]...)
		}
	}
	if _, ok := os.LookupEnv("LESS"); !ok {
		pagerEnv = append(pagerEnv, "LESS=FRX")
	}
	if _, ok := os.LookupEnv("LV"); !ok {
		pagerEnv = append(pagerEnv, "LV=-c")
	}

	pagerExe, err := safeexec.LookPath(pagerArgs[0])
	if err != nil {
		return err
	}
	pagerCmd := exec.Command(pagerExe, pagerArgs[1:]...)
	pagerCmd.Env = pagerEnv
	pagerCmd.Stdout = s.Out
	pagerCmd.Stderr = s.ErrOut
	pagedOut, err := pagerCmd.StdinPipe()
	if err != nil {
		return err
	}
	s.Out = &fdWriteCloser{
		fd:          s.Out.Fd(),
		WriteCloser: &pagerWriter{pagedOut},
	}
	s.ContentOut = newContentWriter(s.Out, s.sanitizeContent)
	err = pagerCmd.Start()
	if err != nil {
		return err
	}
	s.pagerProcess = pagerCmd.Process
	return nil
}

// SetContentSanitization toggles ANSI escape sanitization on ContentOut.
// Commands should call this with false when an explicit opt-out flag (e.g.
// --allow-escape-sequences) is set, so subsequent writes of external content
// pass through unmodified.
func (s *IOStreams) SetContentSanitization(enabled bool) {
	s.sanitizeContent = enabled
	s.ContentOut = newContentWriter(s.Out, enabled)
}

// newContentWriter returns the writer to wire up as ContentOut. When
// sanitize is true it inserts an asciisanitizer in front of the underlying
// writer; otherwise it returns the underlying writer directly so writes
// reach stdout unchanged.
func newContentWriter(out io.Writer, sanitize bool) io.Writer {
	if !sanitize {
		return out
	}
	return transform.NewWriter(out, &asciisanitizer.Sanitizer{})
}

// CopyGuardedContent writes external content from r to w under the safety model
// used by byte-moving commands: binary content is refused when w targets a
// terminal and streamed verbatim otherwise, while textual content is refused when
// it carries terminal escape sequences. Binary content streams without buffering;
// only textual content is buffered, so its escapes are caught before any byte is
// written. On refusal the output stream is left untouched; otherwise it receives
// the full content. isTTY reports whether w targets the user's terminal.
//
// It returns [BinaryTerminalError] or [ErrEscapeSequence] so callers can add
// command-specific guidance. Callers that must stream verbatim (an explicit
// opt-out, or output bound for a file) should copy directly instead.
func CopyGuardedContent(w io.Writer, r io.Reader, isTTY bool) error {
	head := make([]byte, contentSniffLen)
	n, err := io.ReadFull(r, head)
	if err != nil && !errors.Is(err, io.EOF) && !errors.Is(err, io.ErrUnexpectedEOF) {
		return err
	}
	head = head[:n]

	if mime, ok := BinaryContentType(head); ok {
		if isTTY {
			return BinaryTerminalError{MIME: mime}
		}
		if _, err := w.Write(head); err != nil {
			return err
		}
		_, err := io.Copy(w, r)
		return err
	}

	rest, err := io.ReadAll(r)
	if err != nil {
		return err
	}
	content := append(head, rest...)
	if ContainsEscapeSequence(content) {
		return ErrEscapeSequence
	}
	_, err = w.Write(content)
	return err
}
