### Title
Unvalidated open redirect via `omniauth.origin` in OAuth callback - (File: `app/controllers/shipit/github_authentication_controller.rb`)

### Summary
`GithubAuthenticationController#callback` redirects to `request.env['omniauth.origin']` without validating that the URL belongs to `Shipit.host`, allowing an attacker to craft a login link whose `origin` param is an absolute external URL, causing the victim's browser to be redirected off-site immediately after a real, successful GitHub authentication.

### Finding Description
The broken binding is: `redirect_target_host == Shipit.host` is expected but never enforced; instead `return_url = request.env['omniauth.origin'] || root_path` is passed straight to `redirect_to` at [1](#0-0) .

`omniauth.origin` is populated by the OmniAuth gem during the request phase from the `origin` query parameter (OmniAuth's default `origin_param` behavior), and it is carried through the OAuth flow into the callback phase's Rack env. Shipit mounts OmniAuth via `OmniAuth::Builder` with the GitHub strategy configured at `/github/auth`, with no custom `origin_param` validation or allowlist added on top: [2](#0-1) .

Attack flow:
1. Attacker sends victim a link like `/github/auth/github?origin=https://evil.example`.
2. Victim completes the real GitHub OAuth login (their credentials, their consent).
3. `auth` is populated from `omniauth.auth`; `session[:user_id] = sign_in_github(auth)` and `session[:authenticated] = true` are set on the victim's *own*, legitimate session — this part is correctly scoped to the victim.
4. `redirect_to(return_url)` sends the victim's browser to `https://evil.example` right after authentication completes.

No component in this call path validates the host of `omniauth.origin`: `sign_in_github` only touches `User` records for the authenticating user and doesn't touch redirect target; there is no `force_github_authentication`, `User#authorized?`/`require_permission!`, or model validator in this controller that inspects `return_url`. The CSRF/`state` param that OmniAuth validates protects against forged callback state, not against attacker-supplied same-origin redirect targets — it does not restrict the arbitrary absolute URL in `origin`.

### Impact Explanation
The attacker gains a way to redirect any victim, right after they complete an authenticated GitHub OAuth login against the real Shipit host, to an arbitrary attacker-controlled URL. This is a classic post-auth open redirect: the victim's browser trusts the Shipit domain during the flow (cookies, `Referer` header, and any URL fragments/query on the redirect target are then sent to the attacker's page), which can be leveraged for phishing or to leak Referer-based tokens/state if any are echoed into `return_url` handling elsewhere. It does not, by itself, expose `github_access_token`, session cookies (which remain `HttpOnly`/scoped to the Shipit domain and aren't sent to the external site), or allow forging of webhooks/API tokens. This is repeatable against any user who clicks a crafted link, for any number of victims, but the direct blast radius is limited to redirect-chaining/phishing rather than credential exfiltration or cross-tenant mutation — matching a "High" severity open-redirect class as described in the prompt's own impact categories.

### Likelihood Explanation
Preconditions are minimal: GitHub OAuth must be configured (`Shipit.github.oauth?` true, which is the documented normal production configuration), and the attacker only needs to get a victim to click a link containing `?origin=<external-url>` pointed at the `/github/auth/github` OmniAuth request path — no secrets, no privileged role, and no interaction with webhooks or the API required. The victim must actually complete a real GitHub login for the redirect to trigger, which is a mild attacker cost but a plausible one for a phishing-style login lure test-verifiable with `request.env['omniauth.origin'] = 'https://evil.example'` in a controller test as suggested in the prompt.

### Recommendation
Validate `return_url` before redirecting: only allow relative paths or URLs whose host matches `Shipit.host`/`request.host`, e.g. reject absolute URLs or compare `URI.parse(return_url).host` against the configured Shipit host, falling back to `root_path` otherwise.

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test ":callback redirects to attacker-controlled origin (open redirect)" do
  auth = OmniAuth::AuthHash.new(
    credentials: OmniAuth::AuthHash.new(token: 's3cr3t'),
    extra: OmniAuth::AuthHash.new(
      raw_info: OmniAuth::AuthHash.new(
        id: 44, name: 'Shipit User', email: 'shipit-user@example.com',
        login: 'shipit-user', avatar_url: 'https://example.com',
        api_url: 'https://github.com/api/v3/users/shipit-user'
      )
    )
  )
  @request.env['omniauth.auth'] = auth
  @request.env['omniauth.origin'] = 'https://evil.example'

  get :callback

  # Binding under test: redirect_target_host == Shipit.host
  redirected_host = URI.parse(response.location).host
  assert_not_equal Shipit.host, redirected_host
  assert_equal 'evil.example', redirected_host # demonstrates unfiltered open redirect
  assert session[:authenticated]
end
```
