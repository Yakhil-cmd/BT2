### Title
Unauthenticated forged webhook accepted and used to archive/deprovision a live ReviewStack when an org's `webhook_secret` is blank - (File: `lib/shipit/github_app.rb`)

### Summary
`GitHubApp#verify_webhook_signature` unconditionally returns `true` when the configured organization has no `webhook_secret` set, and `WebhooksController#verify_signature` treats that `true` as a valid signature check before dispatching the payload to `Shipit::Webhooks::Handlers::PullRequest::ClosedHandler`. An attacker who can send an unsigned/arbitrarily-signed HTTP POST to `/webhooks` for such an organization can trigger `review_stack.archive!`, which deprovisions and archives a real `Shipit::ReviewStack` with no authentication of any kind.

### Finding Description
The broken binding: the code implicitly asserts `verified == (HMAC(webhook_secret, raw_post) == X-Hub-Signature)` for every organization, but when `Shipit.github_apps[org][:webhook_secret]` is blank, the actual binding degenerates to `verified == true` regardless of `X-Hub-Signature` or `raw_post` content — i.e. `authorized == presence_of_secret` rather than `authorized == valid_signature`.

Code path:
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-30`) resolves `github_app = Shipit.github(organization: repository_owner)` from the attacker-controlled `repository.owner.login` field in the JSON body, then calls `github_app.verify_webhook_signature(...)`.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`):
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```
If `@webhook_secret = @config[:webhook_secret].presence` (`lib/shipit/github_app.rb:50`) is `nil` (key absent or empty string), this method returns `true` for **any** payload/signature.
- `Shipit.github(organization:)` (`lib/shipit.rb:170-181`) only raises `GithubOrganizationUnknown` when the organization key is entirely absent from config (`github_app_config` returns `nil`); it does **not** raise when the org exists but lacks a `webhook_secret`. So an org that is onboarded but not yet given a secret passes straight through with `verified = true`.
- `WebhooksController#create` then dispatches to `Shipit::Webhooks.for_event(event)`, which for `pull_request` includes `ClosedHandler` (`app/models/shipit/webhooks/handlers/pull_request/closed_handler.rb:41-45`):
```ruby
def process
  return unless respond_to_pull_request_closed?
  review_stack.archive!
end
```
- `ReviewStackAdapter#archive!` (`app/models/shipit/webhooks/handlers/pull_request/review_stack_adapter.rb:23-35`) looks up the live stack by `environment` (derived from attacker-supplied `params.number`/`repository.full_name`) and, if found and not already archived, calls `stack.remove_from_provisioning_queue`, `stack.deprovision`, and `stack.archive!(user)` — all state-changing operations — using `user = Shipit::User.find_or_create_by_login!(params.sender["login"])`, an arbitrary attacker-chosen login.

Attacker request: a raw HTTP POST to `/webhooks` with header `X-Github-Event: pull_request`, arbitrary/absent `X-Hub-Signature`, and a JSON body with `action: "closed"`, `repository.full_name` set to the real org/repo, `number` matching a live PR/environment, and `sender.login` set to any string. No GitHub-issued signature is required because `verify_webhook_signature` short-circuits to `true`.

Existing guards fail: `drop_unhandled_event` doesn't apply (pull_request has a handler); `ExplicitParameters` schema in `ClosedHandler` only validates types/shape, not authenticity; there is no `force_github_authentication` or session/API-token check on `/webhooks` (it's explicitly unauthenticated by design, relying entirely on signature verification); `verify_signature`'s only real protection — the HMAC check — is bypassed by the blank-secret shortcut.

### Impact Explanation
Any unauthenticated attacker able to reach the Shipit host over HTTP can force deprovisioning and archival of a live, real `Shipit::ReviewStack` belonging to any organization/repository configured in `Shipit.github_apps` without a `webhook_secret`, causing loss of a legitimate deploy environment (state-changing operation: `deprovision` + `archive!`). This is repeatable against every stack/PR-environment in that org, and against every org configured without a secret (multi-tenant blast radius). This matches "Critical: authentication bypass (forged webhook accepted)" and "an unauthorized deploy/rollback" class of impact, since it performs unauthorized destructive state changes on infrastructure records the attacker never authenticated against.

### Likelihood Explanation
Preconditions: an org in `Shipit.github_apps` (or single-org `secrets.github`) config that has no `webhook_secret` set (blank/nil) — e.g., a newly onboarded org before secret provisioning, or an operator who left it unset — and a live non-archived `Shipit::ReviewStack` for that org/repo/PR. Attacker cost is trivial: a single unauthenticated HTTP POST with a known/guessable repository full name and PR number; no credentials, tokens, or GitHub interaction is strictly required (though opening/closing a real PR is one avenue; direct POST spoofing is another explicitly named by the attacker model). This is fully repeatable and requires no timing tricks.

### Recommendation
Do not allow `verify_webhook_signature` to succeed when `webhook_secret` is blank. Instead, treat a missing/blank `webhook_secret` as a hard misconfiguration that always fails verification (return `false`, not `true`), and/or make `Shipit.github_app_config`/onboarding require a non-blank `webhook_secret` before an org is considered active for webhook processing. At minimum, change `lib/shipit/github_app.rb:76-78` from `return true unless webhook_secret` to `return false unless webhook_secret`, and add operational alerting/validation to catch orgs with blank secrets before they go live.

### Proof of Concept
minitest plan (e.g., in `test/controllers/webhooks_controller_test.rb` or a new test file under `test/`):
```ruby
test "unsigned pull_request closed webhook archives stack when org has no webhook_secret" do
  org = "acme-no-secret"
  config = { app_id: 1, installation_id: 1, private_key: nil, webhook_secret: nil, oauth: {} }
  Shipit.stubs(:github_app_config).with(org).returns(config)

  repository = shipit_repositories(:shipit) # or create one owned by `org`
  repository.update!(owner: org)
  stack = create_review_stack_for(repository) # live, non-archived ReviewStack

  payload = {
    action: "closed",
    number: stack.pull_request_number,
    pull_request: { ... head: { ref: stack.branch }, user: { login: "attacker" } },
    repository: { full_name: repository.github_repo_name, owner: { login: org } },
    sender: { login: "totally-unauthorized-user" }
  }.to_json

  request.headers["X-Github-Event"] = "pull_request"
  # deliberately NOT setting X-Hub-Signature, or setting a bogus one

  assert_changes -> { stack.reload.archived? }, from: false, to: true do
    post :create, body: payload, as: :json
  end
  assert_response :ok
end
```
Assert both sides of the binding: before the request, `stack.archived? == false` and no valid `X-Hub-Signature` was supplied for `payload`; after the request, `stack.reload.archived? == true` despite `verified` having been computed with no cryptographic check performed (`Shipit::GitHubApp#verify_webhook_signature` returning `true` via the `return true unless webhook_secret` branch, confirmable via a `Mocha` expectation that `OpenSSL::HMAC.hexdigest` / `SecureCompare.secure_compare` were never invoked).       return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)

  end
