Based on my research, the strongest analog to the "unbounded array growth causes gas limit exceeded" bug class in ocore is the unbounded private payment chain length in the indivisible (blackbytes-style) private asset protocol.

### Title
Unbounded private-payment chain length allows a counterparty to DoS a victim's ability to spend or forward private coins - ([File: indivisible_asset.js])

### Summary
The private indivisible-asset payment protocol represents a coin's provenance as a chain of `Group`-like private elements linked back to the original issuance. Every retransfer of the same coin appends one more link to this chain. There is no limit on how many times a coin may be re-transferred before being sent to a victim, so an attacker who controls both ends of a series of transfers can make the chain arbitrarily long before finally sending it to the victim, analogous to the unbounded `Group[]` array in the reported Solidity bug.

### Finding Description
`buildPrivateElementsChain` in `indivisible_asset.js` walks backwards from a given output through `inputs`/`outputs` tables, recursively calling `readPayloadAndGoUp` for every hop until it reaches the original `issue`, pushing one element into `arrPrivateElements` per hop with no maximum depth check: [1](#0-0) 

When a chain is received or needs to be validated/saved, `parsePrivatePaymentChain` iterates the entire array serially, and for every element performs a full `validatePrivatePayment` (including a DB round-trip for the spend proof and a `graph.determineIfIncluded` traversal for unstable inputs): [2](#0-1) [3](#0-2) 

`validateAndSavePrivatePaymentChain` then loops over the same array again to build and execute a database query per input/output of every link: [4](#0-3) 

None of these code paths — `buildPrivateElementsChain`, `parsePrivatePaymentChain`, `validateAndSavePrivatePaymentChain`, or the network/wallet entry points that call them (`handleOnlinePrivatePayment`/`handleSavedPrivatePayments` in `network.js`, `handlePrivatePaymentChains` in `wallet.js`) — enforce any maximum chain length. [5](#0-4) [6](#0-5) 

Unlike public payments, where `MAX_INPUTS_PER_PAYMENT_MESSAGE`/`MAX_OUTPUTS_PER_PAYMENT_MESSAGE` bound array sizes inside a single unit [7](#0-6) , the private-chain length spans across an unbounded number of *separate* units/transfers, so no single-unit limit constrains it.

### Impact Explanation
A private-payment counterparty (an unprivileged actor reachable via this protocol) can bounce a small denomination of a private indivisible asset back and forth between colluding addresses thousands of times to build an artificially long chain, then send the final transfer to the victim. Because the victim's wallet/node must reconstruct and revalidate the entire chain (`buildPrivateElementsChain` → `parsePrivatePaymentChain` → `validateAndSavePrivatePaymentChain`) every time it processes, forwards, or spends that coin, the attacker can impose unbounded, linearly-growing CPU/DB work and recursive DB round-trips on the victim's node. This can stall the mutex-protected `handleJoint`/`private_write` locks used during validation (`mutex.lock(["private_write"], ...)` in `validation.js`), degrading or freezing the victim's ability to process further private payments, effectively locking the received coin's usability (denial of service), matching the report's "locks tokens in the contract" impact but in ocore's private-asset context.

### Likelihood Explanation
Building such a chain requires only ordinary wallet operations (repeated private-asset transfers between attacker-controlled addresses), no special privileges, and is entirely available to a private-payment counterparty. The recursive nature of `readPayloadAndGoUp` and the per-link DB queries make cost grow linearly (or worse, given nested `determineIfIncluded` graph walks for unstable inputs) with chain length, so a moderately determined attacker spending modest fees can construct a chain long enough to cause significant processing delay.

### Recommendation
- Impose a maximum chain length (number of hops since issuance) that `buildPrivateElementsChain`/`parsePrivatePaymentChain` will accept, rejecting or refusing to further relay elements once the limit is exceeded.
- Consider tracking chain depth as metadata alongside spend proofs so subsequent transfers/validations can reject chains beyond the depth limit without re-walking the whole history.
- Add pagination/batching or asynchronous chunked processing for very long chains so a single validation call cannot block the `private_write`/`handleJoint` mutex for an extended period.

### Proof of Concept
1. Attacker controls addresses A and B and issues (or otherwise obtains) a private indivisible-asset coin at A.
2. Attacker repeatedly transfers the coin A→B→A→B... N times (e.g., N = 5,000), each transfer creating one more `inputs`/`outputs` link referencing the previous transfer, as saved by `validateAndSaveDivisiblePrivatePayment`/`validateAndSavePrivatePaymentChain`.
3. Attacker finally transfers the coin to the victim's address and sends the private payment chain (via `handlePrivatePaymentChains` in `wallet.js` or `handleOnlinePrivatePayment` in `network.js`).
4. The victim's node calls `buildPrivateElementsChain`/`parsePrivatePaymentChain`, which must recursively walk and validate all N links (`indivisible_asset.js:619-721`, `186-236`), each requiring separate DB queries and, for unstable inputs, `graph.determineIfIncluded` traversals — consuming excessive time/resources and blocking further processing of that coin (and potentially other private payments queued behind the same mutex).

function parsePrivatePaymentChain(conn, arrPrivateElements, callbacks){
	var bAllStable = true;
	var issuePrivateElement = arrPrivateElements[arrPrivateElements.length-1];
	if (!issuePrivateElement.payload || !issuePrivateElement.payload.inputs || !issuePrivateElement.payload.inputs[0])
		return callbacks.ifError("invalid issue private element");
	var asset = issuePrivateElement.payload.asset;
	if (!asset)
		return callbacks.ifError("no asset in issue private element");
	var denomination = issuePrivateElement.payload.denomination;
	if (!denomination)
		return callbacks.ifError("no denomination in issue private element");
	async.forEachOfSeries(
		arrPrivateElements,
		function(objPrivateElement, i, cb){
			if (!objPrivateElement.payload || !objPrivateElement.payload.inputs || !objPrivateElement.payload.inputs[0])
				return cb("invalid payload");
			if (!objPrivateElement.output)
				return cb("no output in private element");
			if (objPrivateElement.payload.asset !== asset)
				return cb("private element has a different asset");
			if (objPrivateElement.payload.denomination !== denomination)
				return cb("private element has a different denomination");
			var prevElement = null; 
			if (i+1 < arrPrivateElements.length){ // excluding issue transaction
				var prevElement = arrPrivateElements[i+1];
				if (prevElement.unit !== objPrivateElement.payload.inputs[0].unit)
					return cb("not referencing previous element unit");
				if (prevElement.message_index !== objPrivateElement.payload.inputs[0].message_index)
					return cb("not referencing previous element message index");
				if (prevElement.output_index !== objPrivateElement.payload.inputs[0].output_index)
					return cb("not referencing previous element output index");
			}
			validatePrivatePayment(conn, objPrivateElement, prevElement, {
				ifError: cb,
				ifOk: function(bStable, input_address){
					objPrivateElement.bStable = bStable;
					objPrivateElement.input_address = input_address;
					if (!bStable)
						bAllStable = false;
					cb();
				}
			});
		},
		function(err){
			if (err)
				return callbacks.ifError(err);
			callbacks.ifOk(bAllStable);
		}
	);
}

function buildPrivateElementsChain(conn, unit, message_index, output_index, payload, handlePrivateElements){
	var asset = payload.asset;
	var denomination = payload.denomination;
	var output = payload.outputs[output_index];
	var hidden_payload = _.cloneDeep(payload);
	hidden_payload.outputs.forEach(function(o){
		delete o.address;
		delete o.blinding;
		// output_hash was already added
	});
	var arrPrivateElements = [{
		unit: unit,
		message_index: message_index,
		payload: hidden_payload,
		output_index: output_index,
		output: {
			address: output.address,
			blinding: output.blinding
		}
	}];
	
	function readPayloadAndGoUp(_unit, _message_index, _output_index){
		conn.query(
			"SELECT src_unit, src_message_index, src_output_index, serial_number, denomination, amount, address, asset, \n\
				(SELECT COUNT(*) FROM unit_authors WHERE unit=?) AS count_authors \n\
			FROM inputs WHERE unit=? AND message_index=?", 
			[_unit, _unit, _message_index],
			function(in_rows){
				if (in_rows.length === 0)
					throw Error("building chain: blackbyte input not found");
				if (in_rows.length > 1)
					throw Error("building chain: more than 1 input found");
				var in_row = in_rows[0];
				if (!in_row.address)
					throw Error("readPayloadAndGoUp: input address is NULL");
				if (in_row.asset !== asset)
					throw Error("building chain: asset mismatch");
				if (in_row.denomination !== denomination)
					throw Error("building chain: denomination mismatch");
				var input = {};
				if (in_row.src_unit){ // transfer
					input.unit = in_row.src_unit;
					input.message_index = in_row.src_message_index;
					input.output_index = in_row.src_output_index;
				}
				else{
					input.type = 'issue';
					input.serial_number = in_row.serial_number;
					input.amount = in_row.amount;
					if (in_row.count_authors > 1)
						input.address = in_row.address;
				}
				conn.query(
					"SELECT address, blinding, output_hash, amount, output_index, asset, denomination FROM outputs \n\
					WHERE unit=? AND message_index=? ORDER BY output_index", 
					[_unit, _message_index], 
					function(out_rows){
						if (out_rows.length === 0)
							throw Error("blackbyte output not found");
						var output = {};
						var outputs = out_rows.map(function(o){
							if (o.asset !== asset)
								throw Error("outputs asset mismatch");
							if (o.denomination !== denomination)
								throw Error("outputs denomination mismatch");
							if (o.output_index === _output_index){
								output.address = o.address;
								output.blinding = o.blinding;
							}
							return {
								amount: o.amount,
								output_hash: o.output_hash
							};
						});
						if (!output.address)
							throw Error("output not filled");
						var objPrivateElement = {
							unit: _unit,
							message_index: _message_index,
							payload: {
								asset: asset,
								denomination: denomination,
								inputs: [input],
								outputs: outputs
							},
							output_index: _output_index,
							output: output
						};
						arrPrivateElements.push(objPrivateElement);
						(input.type === 'issue') 
							? handlePrivateElements(arrPrivateElements)
							: readPayloadAndGoUp(input.unit, input.message_index, input.output_index);
					}
				);
			}
		);
	}
	
	var input = payload.inputs[0];
	(input.type === 'issue') 
		? handlePrivateElements(arrPrivateElements)
		: readPayloadAndGoUp(input.unit, input.message_index, input.output_index);
}
