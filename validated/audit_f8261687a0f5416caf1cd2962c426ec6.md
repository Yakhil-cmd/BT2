This confirms the multi-org configuration schema exists in `Shipit.github` where each org can have its own independent `webhook_secret`, allowing one org to be secret-less while another is secret-protected.

The trace confirms the vulnerability: `WebhooksController#verify_signature` at `app/controllers/shipit/webhooks_controller.rb:24-30` calls `Shipit.github(organization: repository_owner)` using `repository_owner` derived solely from `params.dig('repository','owner','login')` [1](#0-0) . If that org has no `webhook_secret` configured, `GitHubApp#verify_webhook_signature` returns `true` unconditionally via `return true unless webhook_secret` [2](#0-1) . Meanwhile `OpenedHandler#repository` independently resolves `Shipit::Repository.from_github_repo_name(params.repository.full_name)` [3](#0-2) , and `Repository.from_github_repo_name` simply splits the string on `/` and does a `find_by(owner:, name:)` with no relation back to who verified the signature [4](#0-3) . There is no code anywhere in this chain asserting `repository_owner == params.repository.full_name.split('/').first`.

### Title
Webhook signature verified against `repository.owner.login`'s org while `ReviewStack` mutation targets `repository.full_name`'s (different) org's repository - (File: app/controllers/shipit/webhooks_controller.rb, app/models/shipit/webhooks/handlers/pull_request/opened_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the webhook secret to check using `repository.owner.login` from the JSON body, while `OpenedHandler#repository` (and `ReviewStackAdapter`) independently resolve the target `Shipit::Repository`/`ReviewStack` using `repository.full_name` from the same body, with no assertion that these two fields agree. In a multi-org Shipit deployment where at least one configured org has no `webhook_secret`, an attacker can craft a payload where `repository.owner.login` names that secret-less org (bypassing signature verification unconditionally) while `repository.full_name` names a different, secret-protected victim org's repository, causing an unauthorized `ReviewStack` to be created and provisioned against the victim's repository.

### Finding Description
The broken binding: `repository_owner` (used to select the verifying `GitHubApp`/secret) must equal `params.repository.full_name.split('/').first` (used to select the mutated `Shipit::Repository`). No code enforces this equality.

Path:
1. `WebhooksController#verify_signature` computes `repository_owner` via `params.dig('repository','owner','login')` and calls `Shipit.github(organization: repository_owner).verify_webhook_signature(...)` [5](#0-4) .
2. `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that org's `webhook_secret` is blank [2](#0-1) .
3. On success, `WebhooksController#create` dispatches to handlers with the full raw `params` (including `repository.full_name`), unmodified [6](#0-5) .
4. `OpenedHandler#repository` resolves `Shipit::Repository.from_github_repo_name(params.repository.full_name)`, ignoring `repository.owner.login` entirely [3](#0-2) .
5. `ReviewStackAdapter#create!` creates the `ReviewStack` under that resolved (victim) repository and enqueues `Shipit::ReviewStackProvisioningQueue.add(stack)`, scheduling provisioning [7](#0-6) .

Attacker request: POST `/webhooks` with `X-Github-Event: pull_request`, body containing `action: "opened"`, `repository.owner.login: "<secret-less-org>"`, `repository.full_name: "<victim-org>/<victim-repo>"`, and a well-formed `pull_request` object. No valid `X-Hub-Signature` is required because the secret-less org's check short-circuits to `true`. This bypasses `drop_unhandled_event` (pull_request is a handled event) and `check_if_ping`.

Existing guards fail because: `drop_unhandled_event` only checks event type, not repository identity; `verify_signature` never re-reads or cross-checks `full_name`; `ExplicitParameters` schema in `OpenedHandler` only validates presence/type of `repository.full_name`, not its consistency with any other field; no model validation in `Repository`/`ReviewStack` ties the record back to the verifying org.

### Impact Explanation
An attacker with no privileges over the victim org can force creation of an unauthorized `Shipit::ReviewStack` under the victim's `Shipit::Repository`, which is immediately queued for provisioning (`Shipit::ReviewStackProvisioningQueue.add`), eventually invoking review-stack provisioning commands (`lib/shipit/review_stack_commands.rb`) against the victim's real GitHub repository/branch using Shipit's GitHub App credentials for that org. This is a payload for one repository (secret-less org) causing mutation of another org's (victim's) stack — matching "Critical: a payload for one repository mutating another's stack." The attack is repeatable against any victim repository whose owner name is known, as long as any org in the deployment lacks a webhook secret.

### Likelihood Explanation
Requires: (1) a multi-org Shipit deployment (`secrets.github` keyed by organization, per `Shipit.github_app_config`), and (2) at least one configured org with `webhook_secret` left blank — a state explicitly supported and documented as optional in `docs/setup.md` and `config/secrets.development.example.yml` (`webhook_secret: # nil`). Given that precondition, the attack costs a single crafted HTTP POST with no secrets, no GitHub App installation, and no signature — fully feasible and repeatable.

### Recommendation
In `OpenedHandler#repository` (and all other handlers resolving repository from `params.repository.full_name`, e.g. `AssignedHandler`, `Handler#stacks`), assert that `params.repository.full_name.split('/').first.downcase == repository_owner.downcase` before creating or mutating any stack; alternatively, have `WebhooksController` derive and pass along a verified organization identity and require handlers to check the resolved `Shipit::Repository#owner` matches it, rejecting the request (e.g., `head(422)`) on mismatch.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "cross-org owner/full_name mismatch allows unauthorized ReviewStack on victim repo" do
  # Setup: two orgs in secrets.github; "attacker-org" has webhook_secret: nil, "victim-org" has a real secret.
  victim_repo = shipit_repositories(:shipit) # owner: "shopify" (secret-protected org), name: "shipit-engine"
  victim_repo.update!(review_stacks_enabled: true, provisioning_behavior: :allow_all)

  request.headers['X-Github-Event'] = 'pull_request'
  payload = payload_parsed(:pull_request_opened)
  payload["repository"]["owner"]["login"] = "attacker-org" # secret-less org, verify_webhook_signature -> true unconditionally
  payload["repository"]["full_name"]      = victim_repo.full_name # "shopify/shipit-engine" - secret-protected org

  # No X-Hub-Signature header sent at all.
  assert_difference -> { Shipit::ReviewStack.count }, 1 do
    post :create, body: payload.to_json, as: :json
  end
  assert_response :ok

  stack = victim_repo.review_stacks.last
  assert_equal victim_repo.id, stack.repository_id
  # Binding check: the org that verified the signature ("attacker-org") != the org owning the mutated stack ("shopify")
  refute_equal "attacker-org", victim_repo.owner
end
```
