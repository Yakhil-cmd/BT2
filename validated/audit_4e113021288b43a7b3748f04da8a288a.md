### Title
Bridge `handle*Transfer` Functions Execute Asset Transfers Without Checking `isRunning` Protected State — (`contracts/service_chain/bridge/BridgeTransferKLAY.sol`, `BridgeTransferERC20.sol`, `BridgeTransferERC721.sol`, `node/sc/bridge_manager.go`)

---

### Summary

The bridge contract exposes an `isRunning` flag as a circuit-breaker that the owner can set to `false` to halt all value transfers. However, only the *request* path checks this flag. The *handle* path — `handleKLAYTransfer`, `handleERC20Transfer`, and `handleERC721Transfer` — executes asset transfers to recipients without ever checking `isRunning`. The Go-layer relay (`processingPendingRequestEvents` / `handleRequestValueTransferEvent`) also never inspects `bi.isRunning` before submitting handle transactions. As a result, stopping the bridge does not prevent asset outflows from the bridge contract.

---

### Finding Description

`BridgeTransfer.isRunning` is the bridge's protected-state flag. When the owner calls `setRunningStatus(false)`, the intent is to freeze all cross-chain value movement.

The *request* side correctly enforces this:

```solidity
// BridgeTransferKLAY.sol line 108
require(isRunning, "stopped bridge");
```

```solidity
// BridgeTransferERC20.sol line 88
require(isRunning, "stopped bridge");
```

But the *handle* side — which actually transfers KAIA/ERC20/ERC721 to recipients — contains no such check:

```solidity
// BridgeTransferKLAY.sol handleKLAYTransfer (lines 62–100)
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
    _lowerHandleNonceCheck(_requestedNonce);
    if (!_voteValueTransfer(_requestedNonce)) { return; }
    // ... no isRunning check ...
    (bool ok, ) = _to.call.value(_value)("");
    require(ok, "handleKLAYTransfer: transfer failed");
}
```

```solidity
// BridgeTransferERC20.sol handleERC20Transfer (lines 32–73)
function handleERC20Transfer(...) public onlyOperators {
    _lowerHandleNonceCheck(_requestedNonce);
    if (!_voteValueTransfer(_requestedNonce)) { return; }
    // ... no isRunning check ...
    IERC20(_tokenAddress).safeTransfer(_to, _value);
}
```

```solidity
// BridgeTransferERC721.sol handleERC721Transfer (lines 29–71)
function handleERC721Transfer(...) public onlyOperators {
    _lowerHandleNonceCheck(_requestedNonce);
    if (!_voteValueTransfer(_requestedNonce)) { return; }
    // ... no isRunning check ...
    IERC721(_tokenAddress).transferFrom(address(this), _to, _tokenId);
}
```

The Go relay's `processingPendingRequestEvents` fires on every new block event and on a 1-second ticker, calling `handleRequestValueTransferEvent` unconditionally:

```go
// bridge_manager.go lines 240–259
func (bi *BridgeInfo) processingPendingRequestEvents() {
    ReadyEvent := bi.GetReadyRequestValueTransferEvents()
    ...
    for idx, ev := range ReadyEvent {
        if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(...) {
            continue
        }
        if err := bi.handleRequestValueTransferEvent(ev); err != nil { // no isRunning check
            ...
        }
    }
}
```

`bi.isRunning` is read from the contract in `UpdateInfo()` and stored in the struct, but it is never consulted before submitting handle transactions. The value transfer recovery path (`recoverPendingEvents` → `handleRequestValueTransferEvent`) has the same omission.

---

### Impact Explanation

When the bridge owner stops the bridge (e.g., in response to a security incident, a compromised operator key, or an exploit on the counterpart chain), the `isRunning = false` state is supposed to freeze all asset movement. Because `handle*Transfer` ignores this flag:

- The automated Go relay continues to drain the bridge's KAIA balance and ERC20/ERC721 holdings by processing every pending `RequestValueTransfer` event already queued.
- Any operator can directly call `handleKLAYTransfer` / `handleERC20Transfer` / `handleERC721Transfer` to transfer assets out of a stopped bridge.
- The circuit-breaker provides no protection against asset loss during an incident response window.

The corrupted value is the bridge contract's KAIA balance and token holdings: they are transferred to arbitrary `_to` addresses even while `isRunning == false`.

---

### Likelihood Explanation

The Go relay runs automatically on every node operating a service-chain bridge. No attacker action is required — the relay will continue processing pending events the moment the owner stops the bridge. Any operator (a semi-trusted role) can also call `handle*Transfer` directly. The trigger is reachable by the normal relay loop without any special conditions.

---

### Recommendation

Add `require(isRunning, "stopped bridge")` to all three handle functions:

```diff
// BridgeTransferKLAY.sol
function handleKLAYTransfer(...) public onlyOperators nonReentrant {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferERC20.sol
function handleERC20Transfer(...) public onlyOperators {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}

// BridgeTransferERC721.sol
function handleERC721Transfer(...) public onlyOperators {
+   require(isRunning, "stopped bridge");
    _lowerHandleNonceCheck(_requestedNonce);
    ...
}
```

In the Go relay, guard `processingPendingRequestEvents` with the cached flag:

```diff
// bridge_manager.go
func (bi *BridgeInfo) processingPendingRequestEvents() {
+   if !bi.isRunning {
+       return
+   }
    ReadyEvent := bi.GetReadyRequestValueTransferEvents()
    ...
}
```

---

### Proof of Concept

1. Deploy a bridge pair (child ↔ parent) with the Go relay running.
2. User calls `requestKLAYTransfer` on the child bridge; the event is queued in the relay's pending pool.
3. Bridge owner detects an anomaly and calls `bridge.start(false)` (i.e., `setRunningStatus(false)`).
4. Observe: `isRunning` is now `false`; new `requestKLAYTransfer` calls revert with `"stopped bridge"`.
5. Observe: the Go relay's `processingPendingRequestEvents` fires on the next tick, calls `handleRequestValueTransferEvent`, which submits `handleKLAYTransfer` to the parent bridge.
6. `handleKLAYTransfer` executes without checking `isRunning` and transfers KAIA to the recipient — asset outflow occurs despite the bridge being stopped.

The same path applies to ERC20 and ERC721 tokens via `handleERC20Transfer` and `handleERC721Transfer`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7)

func (bi *BridgeInfo) loop() {
	ticker := time.NewTicker(time.Second)
	defer ticker.Stop()

	logger.Info("start bridge loop", "addr", bi.address.String(), "onChildChain", bi.onChildChain)

	for {
		select {
		case <-bi.newEvent:
			bi.processingPendingRequestEvents()

		case <-ticker.C:
			bi.processingPendingRequestEvents()

		case <-bi.closed:
			logger.Info("stop bridge loop", "addr", bi.address.String(), "onChildChain", bi.onChildChain)
			return
		}
	}
}

func (bi *BridgeInfo) processingPendingRequestEvents() {
	ReadyEvent := bi.GetReadyRequestValueTransferEvents()
	if ReadyEvent == nil {
		return
	}

	logger.Trace("Get ready request value transfer event", "len(readyEvent)", len(ReadyEvent), "len(pendingEvent)", bi.pendingRequestEvent.Len())

	for idx, ev := range ReadyEvent {
		if ev.GetRequestNonce() < bi.lowerHandleNonce || bi.handledEvent.Exist(ev.GetRequestNonce()) {
			logger.Trace("handled requests can be ignored", "RequestNonce", ev.GetRequestNonce(), "lowerHandleNonce", bi.lowerHandleNonce)
			continue
		}

		if err := bi.handleRequestValueTransferEvent(ev); err != nil {
			bi.AddRequestValueTransferEvents(ReadyEvent[idx:])
			logger.Error("Failed handle request value transfer event", "err", err, "len(RePutEvent)", len(ReadyEvent[idx:]))
			return
		}
	}
}

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
}
