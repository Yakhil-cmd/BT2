### Title
L1 BTC-lockup proof can be replayed across non-overlapping bonds to double-count locked sats without a second Bitcoin lock - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`register-for-bond` accepts an L1 BTC lockup proof (`btc-lockup`) and credits `amount-sats` of stacked BTC based on `verify-l1-lockups` / `validate-l1-lockup`. Deduplication of Bitcoin outpoints (`seen-outpoints`) is scoped only to the *single call's* fold accumulator, not persisted anywhere globally, so the same on-chain BTC output can be presented again in a later `register-for-bond` call (for a different, non-overlapping bond period) and be credited again as new locked collateral.

### Finding Description
`verify-l1-lockups` (`pox-5.clar:1984-2019`) initializes `seen-outpoints: (list)` fresh on every call, and `validate-l1-lockup` only checks `(is-none (index-of? seen-outpoints outpoint))` against that same call's accumulator (`pox-5.clar:2072-2088`), rejecting only intra-call duplicates via `ERR_DUPLICATE_LOCKUP_OUTPOINT`. There is no persistent map recording previously-consumed `(txid, output-index)` pairs across separate `register-for-bond` invocations (confirmed by grep — no `l1-lockup-used`/`outpoint` tracking map exists in the contract, unlike the analogous one-shot guard `protocol-bond-l1-early-exit-announced` used elsewhere).

`register-for-bond` (`pox-5.clar:642-840`) only guards against *overlapping* bond memberships via `bond-overlaps-new-position?` (`pox-5.clar:764-770`), explicitly allowing a rollover into a later, non-overlapping bond (e.g., bond N → bond N+6, as exercised by the roll-sbtc tests at `pox-5.test.ts:5166-5268`). For the L1-lock path, `roll-sbtc` is a no-op since L1-locked stakers never have contract-custodied sBTC (`old-sbtc`/`new-sbtc` are both `u0`), so nothing on the sBTC-transfer side flags a repeat use.

Because the same signed Bitcoin transaction remains valid forever on L1 (the `unlock-burn-height` only needs to be `>= minimum-unlock-height` for the *new* bond), a staker can:
1. Register for bond 0 with L1 lockup tx X (sats S), get credited S sats of stake / shares for bond 0's cycles.
2. After bond 0 concludes (or is rolled forward), register for a later, non-overlapping bond (e.g., bond 7) presenting the *identical* transaction X and output index again.
3. `verify-l1-lockups` re-validates the same Bitcoin proof successfully (fresh `seen-outpoints` list) and returns `sats-total = S` again, crediting S sats of new stake for the new bond period — despite no additional BTC ever being locked.

This inflates `protocol-bonds-total-staked`, `total-shares-staked-for-cycle`, and `signer-shares-staked-for-cycle` for the new bond/cycle with sats that are not backed by a fresh Bitcoin timelock, breaking the equality that stacking shares (and thus reward-per-token/signing weight) must correspond 1:1 to actually-locked BTC.

### Impact Explanation
This falls under "signing weight or reward slots exceeding locked value" / "double-counting a commitment or reward" (High/Critical per the rubric): the staker's sBTC-denominated share of rewards for the replayed bond is unbacked by any real BTC lock, letting them earn sBTC/PoX rewards proportional to sats that were never (re-)locked for that period. If repeated across many bonds, an attacker's stake weight (and hence reward share and signer-set influence) can be multiplied arbitrarily from a single real BTC lockup.

### Likelihood Explanation
Requires only an ordinary staker holding one valid L1 BTC lockup transaction and no privileged role — they simply call `register-for-bond` again in a later bond's registration window with the same lockup proof. The registration-window and rollover checks (`verify-bond-rollover-window`, `bond-overlaps-new-position?`) are designed to gate legitimate rollovers and do not defend against BTC-proof replay, making this reachable under normal operation once a bond's window reopens.

### Recommendation
Persist consumed L1 outpoints in a durable map (e.g., `l1-lockup-outpoints-used: {txid, output-index} -> bool`) that is checked/set across all `register-for-bond` calls (not just within one call's fold), so a given Bitcoin output can only ever back one active bond/stake credit at a time, and cannot be replayed once its associated bond has ended unless the underlying BTC is demonstrably still time-locked and unclaimed.

### Proof of Concept
Conceptual sequence (cannot be executed here, but derivable from the code paths cited above):
1. Staker builds one valid L1 lockup Bitcoin tx X locking `S` sats, satisfying `construct-lockup-output-script` for `bond-index=0`.
2. Staker calls `register-for-bond(bond-index=0, ..., btc-lockup=err({outputs:[X], ...}))` — credited `S` sats for bond 0 (`pox-5.clar:642-840`, `verify-l1-lockups` at `1984`).
3. Bond 0 concludes; a later bond (e.g., `bond-index=7`) opens its registration window with `bond-period-to-reward-cycle(7) - 2*L <= burn-block-height` and `unlock-burn-height` of tx X still `>= get-bond-l1-unlock-height(7)`.
4. Staker calls `register-for-bond(bond-index=7, ..., btc-lockup=err({outputs:[X], ...}))` reusing the *same* tx X/output — `bond-overlaps-new-position?` passes (non-overlapping), `verify-l1-lockups` re-validates X successfully because `seen-outpoints` was reset for this call, and the staker is credited `S` sats again for bond 7, without a second BTC lock ever occurring. (define-public (register-for-bond
        (bond-index uint)
        (signer-manager <signer-manager-trait>)
        (amount-ustx uint)
        ;; Their BTC lockup info. If the response is `ok`, then
        ;; this is a list of outputs corresponding to their timelocks.
        ;; If the response is `err`, this is the amount of sBTC (in sats)
        ;; that they want to lock.
        (btc-lockup (response {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        }
            uint
        ))
        (signer-calldata (optional (buff 500)))
    )
    (let (
            (signer (contract-of signer-manager))
            ;; Compute the sats being staked for this bond.
            (sats-total (try! (match btc-lockup
                l1-lockups (verify-l1-lockups tx-sender bond-index l1-lockups)
                sbtc-amount (ok sbtc-amount)
            )))
            ;; Any bond the staker is currently a member of. Some value here
            ;; means this is a roll-over from an ending bond into a later one.
            (existing-membership (map-get? protocol-bond-memberships tx-sender))
            ;; sBTC currently custodied for the staker's existing bond (0 if
            ;; they have none, or if the existing bond is an L1 lock).
            (old-sbtc (get-staker-custodied-sbtc tx-sender))
            ;; sBTC this new bond needs custodied (0 on the L1 path).
            (new-sbtc (if (is-ok btc-lockup)
                u0
                sats-total
            ))
            ;; Any STX-only stake the staker has. Present means this
            ;; `register-for-bond` is a roll-over from an ending stx-only
            ;; stake into a bond.
            (existing-stake (map-get? staker-info tx-sender))
            (bond (unwrap! (map-get? protocol-bonds bond-index) ERR_BOND_NOT_FOUND))
            (allowance (unwrap!
                (map-get? protocol-bond-allowances {
                    staker: tx-sender,
                    bond-index: bond-index,
                })
                ERR_NOT_ALLOWLISTED
            ))
            (first-reward-cycle (bond-period-to-reward-cycle bond-index))
            (bond-start-height (bond-period-to-burn-height bond-index))
            ;; the first cycle in which their stx are unlocked
            (unlock-cycle (+ first-reward-cycle BOND_LENGTH_CYCLES))
            (current-total-staked (get-total-shares-staked-for-cycle first-reward-cycle
                (some bond-index)
            ))
            (stx-balance (stx-account tx-sender))
            (total-balance (+ (get locked stx-balance) (get unlocked stx-balance)))
        )
        ;; Reject during the prepare phase since next-cycle data is mutated
        (try! (verify-not-prepare-phase))
        ;; Verify that they're sending enough STX
        (asserts!
            (>= amount-ustx
                (min-ustx-for-sats-amount sats-total (get stx-value-ratio bond)
                    (get min-ustx-ratio bond)
                ))
            ERR_INSUFFICIENT_STX
        )

        ;; Verify that the bond hasn't started
        (asserts! (< burn-block-height bond-start-height)
            ERR_BOND_ALREADY_STARTED
        )

        ;; An existing STX-only stake is allowed only if its term ends no
        ;; later than this bond's first reward cycle (no overlap). A stx-only
        ;; stake has no L1 collateral, so there's no L1-unlock-window gate
        ;; here -- the lock just extends forward via the node-side handler.
        (asserts!
            (match existing-stake
                stake-info (<=
                    (+ (get first-reward-cycle stake-info)
                        (get num-cycles stake-info)
                    )
                    first-reward-cycle
                )
                true
            )
            ERR_ALREADY_STAKED
        )

        ;; Cannot stake more sats than their allowance
        (asserts! (<= sats-total allowance) ERR_TOO_MUCH_SATS)

        ;; Must have enough unlocked STX
        ;;  the Staker must have sufficient total funds (locked + unlocked).
        ;;  On a roll-over the staker's STX is still locked by the ending
        ;;  bond; the node-side handler extends that lock to the new amount,
        ;;  so checking only `stx-get-balance` (unlocked) would falsely fail.
        (asserts! (>= total-balance amount-ustx) ERR_INSUFFICIENT_STX)

        ;; Validate that the staker can join this signer
        (try! (signer-manager-validate-stake signer-manager tx-sender bond-index u1
            amount-ustx sats-total true signer-calldata
        ))

        ;; The signer must have been registered already, and its signer key
        ;; grant must still be active.
        (try! (verify-signer-key-grant signer
            (unwrap! (get-signer-info signer) ERR_SIGNER_NOT_FOUND)
        ))

        ;; Reject if an existing membership *overlaps* this bond. An existing
        ;; bond whose staking term ends no later than this bond's first cycle
        ;; (e.g. rolling from bond N into bond N+6) is allowed.
        (asserts!
            (not (bond-overlaps-new-position? existing-membership first-reward-cycle))
            ERR_ALREADY_REGISTERED
        )

        (if (> new-sbtc old-sbtc)

;; Verify l1 lockup information for a staker. This asserts that each lockup
;; corresponds to the right timelock script for this staker, and that the lockup
;; occurred on-chain. If everything is valid, this returns the sum of all lockups in sats.
(define-private (verify-l1-lockups
        (staker principal)
        (bond-index uint)
        (lockups {
            outputs: (list 10
                {
                    height: uint,
                    tx: (buff 100000),
                    output-index: uint,
                    header: (buff 80),
                    leaf-hashes: (list 14 (buff 32)),
                    tx-count: uint,
                    tx-index: uint,
                    amount: uint,
                    unlock-burn-height: uint,
                }
            ),
            staker-unlock-bytes: (buff 683),
        })
    )
    (let (
            (bond (unwrap! (get-protocol-bond bond-index) ERR_BOND_NOT_FOUND))
            (accumulation (try! (fold validate-l1-lockup (get outputs lockups)
                (ok {
                    sum: u0,
                    staker: staker,
                    minimum-unlock-height: (get-bond-l1-unlock-height bond-index),
                    staker-unlock-bytes: (get staker-unlock-bytes lockups),
                    early-unlock-bytes: (get early-unlock-bytes bond),
                    seen-outpoints: (list),
                })
            )))
        )
        (ok (get sum accumulation))
    )
)
