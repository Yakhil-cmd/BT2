This external report describes a bug in `Converter.sol`, an Ethereum smart contract from the unrelated "illuminate" protocol, where a user-supplied `c` address is trusted to implement `POOL()`/`redeem()`/`unwrap()` interfaces, letting an attacker deploy a malicious contract to redirect `Safe.transfer` proceeds to themselves. To find a genuine analog in `polkadot-sdk`, I looked for FRAME/pallet-revive/XCM code exhibiting the same root cause — an entry point that (a) is callable by any unprivileged account, (b) accepts an attacker-controlled address, (c) performs a series of try/fallback external calls against that address, and (d) transfers a balance to the caller based on the outcome of those calls.

Searches across `pallet-revive`, `pallet-contracts`, XCM transactors (e.g. `erc20_transactor.rs`), and asset-conversion precompiles did not surface an equivalent pattern:
- `erc20_transactor.rs`'s `deposit_asset_with_surplus` calls a fixed `TransfersCheckingAccount` origin against an asset contract resolved via `Matcher::matches_fungibles`, not an arbitrary caller-supplied address chosen for fund destination. [1](#0-0) 
- `pallet-revive`'s `call`/`bare_call` dispatch simply forwards a caller-specified `dest`/`value`/`data` for direct contract calls — this mirrors normal EVM `CALL` semantics rather than any FRAME-specific chained fallback logic that would leak protocol-held funds to an arbitrary caller. [2](#0-1) 
- The various Solidity fixtures found (`Caller.sol`, `CatchConstructor.sol`, `Stipends.sol`, `TerminateCaller.sol`) are test fixtures under `substrate/frame/revive/fixtures/contracts/` used to validate pallet-revive's EVM-compatibility semantics (call/delegatecall/staticcall, termination, stipends, try/catch) — they are test/mock infrastructure, not production pallet logic exposed to real user funds. [3](#0-2) 

No production FRAME pallet, XCM transactor, or precompile in this codebase implements a "convert-style" flow that trusts an attacker-supplied contract's interface responses to redirect asset custody, so there is no demonstrable analog to file.
