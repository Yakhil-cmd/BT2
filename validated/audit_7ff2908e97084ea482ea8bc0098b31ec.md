### Title
`InitializeWithPermission::creator` is never validated as a signer or non-default `Pubkey`, permanently locking creator fees - ([File: programs/cp-swap/src/instructions/initialize_with_permission.rs])

### Summary
`initialize_with_permission` stores an attacker-controlled `creator` account into `PoolState.pool_creator` without requiring it to sign the transaction or be a non-default address, unlike the analogous `initialize` instruction where the equivalent role must sign.

### Finding Description
In `Initialize` (the permissionless entry point), the `creator` field is a `Signer<'info>` [1](#0-0) , so it is impossible to record a `Pubkey::default()` (or any address without a corresponding private key) as the pool creator there.

However, `InitializeWithPermission` declares `creator` as an `UncheckedAccount<'info>` with no signer check and no constraint on its value [2](#0-1) . The payer (the account actually paying/signing) is a separate field, and the raw `ctx.accounts.creator.key()` is passed straight into `pool_state.initialize(...)` as `pool_creator` with no validation [3](#0-2) , and `PoolState::initialize` simply stores whatever key is given [4](#0-3) .

Any caller who has been granted a `Permission` PDA can therefore submit `initialize_with_permission` with `creator = Pubkey::default()` (or any other address with no corresponding keypair, e.g. `11111111111111111111111111111111`). This is directly analogous to the reported `Timelock` bug: an unvalidated "owner/admin"-style parameter is accepted, permanently crippling functionality tied to that address.

### Impact Explanation
Once `pool_creator` is a default/unreachable pubkey, the accrued `creator_fees_token_0`/`creator_fees_token_1` (a real share of swap fees taken from users, tracked in `PoolState` and enforced via `vault_amount_without_fee`) can never be claimed through the signer-gated path:
- `CollectCreatorFee` requires `creator: Signer<'info>` constrained by `address = pool_state.load()?.pool_creator` [5](#0-4)  — no one can produce a valid signature for the default pubkey.
- `CollectCreatorFeePermissionless` avoids the signer requirement but still creates the payout ATA with `associated_token::authority = creator` [6](#0-5) ; if `creator` is the default pubkey, the resulting ATA's authority is likewise unreachable, so the swept tokens land in an account nobody can ever move funds out of.

Either way, the accumulated creator-fee revenue becomes permanently frozen for the life of the pool, which is a genuine loss of funds (not merely a UX inconvenience), qualifying as Medium severity per the same rationale as the original report (an unvalidated address parameter permanently disables an intended code path).

### Likelihood Explanation
The path is reachable in a single transaction by any account holding a `Permission` PDA (a legitimate but non-privileged "pool creator" role explicitly in scope), by simply supplying `creator = Pubkey::default()` (or any other unreachable/unowned address) as an instruction account — no admin privileges over `AmmConfig` or the protocol are needed, and no other constraint currently prevents it.

### Recommendation
Add a constraint on `InitializeWithPermission::creator` requiring it not equal `Pubkey::default()` (e.g. `constraint = creator.key() != Pubkey::default() @ ErrorCode::InvalidInput`), and/or require `creator` to co-sign the transaction as is already done in the plain `Initialize` instruction, so that a claimable creator fee recipient is guaranteed at pool-creation time.

### Proof of Concept
1. Attacker (or any account previously granted a `Permission` PDA) calls `initialize_with_permission` supplying:
   - `payer` = their own signer,
   - `creator` = `Pubkey::default()` (`11111111111111111111111111111111`), unchecked and unsigned.
2. `pool_state.pool_creator` is set to `Pubkey::default()` [7](#0-6) .
3. Normal swaps occur against the pool, accruing `creator_fees_token_0`/`creator_fees_token_1`.
4. `CollectCreatorFee` can never succeed because no keypair exists for `Pubkey::default()` to satisfy the `Signer` + `address` constraint.
5. `CollectCreatorFee_permissionless` can be called, but the ATA it creates has `authority = Pubkey::default()`, meaning the swept tokens are now held by an account with no controlling keypair — permanently unrecoverable.
