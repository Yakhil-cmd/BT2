### Title
Forged `push` webhook bypasses signature check via no-secret org and mutates another organization's stack - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub organization's `webhook_secret` to validate against using `repository.owner.login` from the attacker-controlled JSON body, while `PushHandler` (via `Handler#stacks`) resolves the target `Stack`/`Repository` from a *different* field of the same body, `repository.full_name`. Nothing ties these two fields together, and `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected organization has no `webhook_secret` configured, letting an attacker "verify" against a harmless/no-secret org while pointing the payload at a victim org's repository.

### Finding Description
The invariant that should hold is: `organization_whose_secret_verified_request == organization_that_owns_the_repository/stack_the_handler_mutates`.

Trace:
1. `Shipit::WebhooksController#verify_signature` computes `repository_owner` from `params.dig('repository', 'owner', 'login')` (or `organization.login`) and looks up `Shipit.github(organization: repository_owner)`. [1](#0-0) [2](#0-1) 
2. `GitHubApp#verify_webhook_signature` short-circuits to `true` when that organization has no configured `webhook_secret`, and otherwise only accepts `sha1=` signatures computed with that org's secret: [3](#0-2) 
3. If `create` proceeds, `Shipit::Webhooks.for_event('push')` dispatches to `PushHandler`, whose `process` resolves the target stacks not via `repository.owner.login` but via `Handler#repository_name`, which reads `payload.dig('repository', 'full_name')` — an independent, attacker-controlled string: [4](#0-3) [5](#0-4) 

Because these two lookups read two different, independently attacker-controlled JSON fields from the same body, an attacker who knows (or can discover) that at least one organization configured in this Shipit instance has no `webhook_secret` set can craft:
```json
{
  "repository": {
    "owner": { "login": "org-with-no-secret" },
    "full_name": "victim-org/victim-repo"
  },
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>"
}
```
with header `X-Github-Event: push` and any (even garbage) `X-Hub-Signature` value. `verify_signature` resolves the GitHub app for `org-with-no-secret`, whose `verify_webhook_signature` returns `true` unconditionally (line 77 short-circuit), independent of the signature header's algorithm or value. `PushHandler` then runs against `victim-org/victim-repo`'s non-archived stacks matching `master`, calling `stack.sync_github(expected_head_sha: params.after)` for a repository never authenticated by any secret the attacker controls.

None of the existing guards prevent this: `drop_unhandled_event` only checks the event name is registered; `ExplicitParameters` only validates presence of `ref`/`after`, not their relationship to `repository.owner.login`; there is no code anywhere that checks `repository.full_name`'s owner segment matches `repository.owner.login`, nor that the organization used for signature verification matches the organization owning the target `Repository`/`Stack`.

### Impact Explanation
An unprivileged attacker can drive `Shipit::Webhooks::Handlers::PushHandler#process` against any repository/stack tracked by the Shipit instance, as long as the instance has at least one configured GitHub organization without a `webhook_secret`. This lets the attacker trigger `stack.sync_github(expected_head_sha:)` for arbitrary victim stacks/branches with an attacker-chosen `after` SHA, without holding any secret for the victim org — a cross-tenant write where one (spoofed, secret-less) organization's "verified" request mutates another organization's stack state. This matches the Critical category: "a payload for one repository mutating another's stack, commit, task or team."

### Likelihood Explanation
Preconditions: the Shipit deployment must have at least one GitHub organization configured without `webhook_secret` (a realistic misconfiguration for internal/dev/test orgs, and explicitly anticipated by the question's "no-secret org" framing and the code's `return true unless webhook_secret` behavior). Attacker cost is a single unauthenticated `POST /webhooks` with a crafted JSON body — no secrets, tokens, or sessions required, and repeatable against any tracked stack by varying `repository.full_name`.

### Recommendation
- Verify the webhook signature using the same organization/repository binding that the handler will act on: derive the organization strictly from `repository.full_name`'s owner segment (or require it to equal `repository.owner.login`) and reject on mismatch.
- Do not treat "no webhook_secret configured" as an automatic pass; either require every configured organization to define a `webhook_secret`, or fail closed (422) for organizations without one instead of returning `true`.
- Support and prefer `X-Hub-Signature-256` (sha256) verification.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (conceptual addition)
test "push payload with mismatched owner/full_name mutates a different org's stack" do
  # Precondition: 'no-secret-org' is configured in Shipit.github without webhook_secret
  victim_stack = shipit_stacks(:shipit) # belongs to 'shopify/shipit-engine', has a webhook_secret configured

  body = {
    repository: { owner: { login: 'no-secret-org' }, full_name: victim_stack.repository.full_name },
    ref: "refs/heads/#{victim_stack.branch}",
    after: 'deadbeef' * 5
  }.to_json

  request.headers['X-Github-Event'] = 'push'
  request.headers['X-Hub-Signature'] = 'sha1=not-a-real-signature'

  assert_enqueued_with(job: GithubSyncJob, args: [stack_id: victim_stack.id, expected_head_sha: 'deadbeef' * 5]) do
    post :create, body:, as: :json
  end
  assert_response :ok
end
```
Assertions on both sides of the binding: `Shipit.github(organization: 'no-secret-org')` is the organization that "verified" the request (trivially, no secret), while `victim_stack.repository.full_name`'s owner (`shopify`) is the organization whose stack is mutated — these differ, proving the invariant is broken.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
