### Title
Unchecked index-growth multiplication can permanently freeze an oversized market - ([File: common/src/rates/index.rs](common/src/rates/index.rs))

### Summary
A sufficiently large borrowing market can reach a borrow index at which calculating `borrowed * new_borrow_index` overflows `i128` before the protocol’s index ceiling is reached. [1](#0-0)  Because market operations synchronize interest before mutating positions, the overflow prevents subsequent withdrawals, repayments, liquidations, and index updates for that market. [2](#0-1) 

### Finding Description
`update_borrow_index` multiplies the old index by the interest factor and only afterward applies `MAX_BORROW_INDEX_RAY`; it does not bound the resulting index by the value domain of the market’s current scaled debt. [3](#0-2)  During accrual, `calculate_supplier_rewards` computes both the old and new total debt with `borrowed.mul(index)`, so once scaled debt approaches `i128::MAX / new_borrow_index`, the multiplication panics even though the index itself remains below its configured ceiling. [4](#0-3) 

An unprivileged caller can reach this path through `update_indexes`, which the controller forwards to the pool through `pool_update_indexes_call`. [5](#0-4)  The pool then accrues every requested market in `ops::market::accrue`. [6](#0-5)  `global_sync` performs the accrual before the state is marked current, while supply, borrow, withdrawal, repayment, and liquidation operations all load and synchronize the market before committing their mutations. [7](#0-6) 

The repository’s harness demonstrates the concrete state: an 18-decimal market supplied with one billion whole tokens and borrowed at 98% eventually fails `update_indexes` with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`; subsequent withdrawal and repayment attempts fail with the same error. [8](#0-7) 

### Impact Explanation
Once the market crosses the representable debt-value boundary, every operation that must accrue the market reverts, so suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot reduce the position. [9](#0-8)  Administrative parameter replacement also accrues first, so it does not provide an in-protocol recovery path without upgrading the code. [10](#0-9)  The result is permanent freezing of all cash and yield backing the affected market absent a contract upgrade. [11](#0-10) 

### Likelihood Explanation
The trigger requires a very large market and sustained borrowing long enough for the index to approach the market-specific value ceiling, so ordinary balances are unlikely to reach it accidentally. [12](#0-11)  However, the admitted cap domain can accommodate approximately 170 billion whole tokens before the token-to-RAY limit, while the demonstrated attack uses a debt position large enough to cross the value ceiling before the global index cap engages. [13](#0-12)  Any user can submit `update_indexes` once ledger time has advanced sufficiently, making the final transition permissionless. [5](#0-4) 

### Recommendation
Bound index growth by both the global index ceiling and the maximum index representable for the market’s current scaled balances. [3](#0-2)  In particular, calculate a per-market effective borrow ceiling such as `floor(i128::MAX * RAY / borrowed)` before applying interest, cap `new_borrow_index` to that value, and treat further accrual as zero-interest once the effective ceiling is reached. [1](#0-0)  Apply the same capacity check to `update_supply_index` before evaluating `supplied * old_index` or `supplied * new_index`. [14](#0-13)  Add regression coverage that verifies withdrawals, repayments, liquidations, and `update_indexes` remain executable at the saturation boundary. [8](#0-7) 

### Proof of Concept
The existing regression test constructs the vulnerable state directly:

1. Configure an 18-decimal market and a collateral market, with utilization limits disabled. [15](#0-14) 
2. Raise the market caps to their admitted maximum and supply `1_000_000_000 * 10^18` base units of the debt asset. [16](#0-15) 
3. Borrow 98% of that principal against sufficient collateral. [17](#0-16) 
4. Advance ledger time and call `update_indexes` until `MathOverflow` is returned. [18](#0-17) 
5. Observe that the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, while `withdraw` and `repay` both revert during the mandatory accrual. [19](#0-18)

```rust
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;

    let new_value = total_supplied_value.checked_add(env, rewards_increase);

    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))
```

```rust
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```

```rust
/// Accrues borrow/supply indexes from `last_timestamp` to the cache's current time.
///
/// No-op when no time has elapsed. Splits long gaps into max-sized compound
/// windows, then sets `last_timestamp` to `current_timestamp`.
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
```
