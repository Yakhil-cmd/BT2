### Title
Webhook signature verification is scoped by an attacker-controlled organization field that is decoupled from the Team/authorization record actually written, allowing escalation into `Shipit.github_teams` - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App secret to verify a webhook against using an organization name taken directly from the untrusted JSON body, and `GitHubApp#verify_webhook_signature` treats a missing secret as automatically valid. Because the `membership` webhook handler resolves and mutates `Team`/`Membership` records using different, independently-attacker-controlled fields of the same payload (`team.id`, `member.login`), an attacker who only needs one configured-but-secretless GitHub organization in a documented multi-org Shipit deployment can forge a `membership` webhook that adds an arbitrary GitHub login to a `Team` that gates `Shipit.github_teams` authorization.

### Finding Description
`WebhooksController#verify_signature` picks the GitHub App/secret to validate against solely from `repository_owner`, which is read straight out of the untrusted request body (`repository.owner.login` or `organization.login`), before any signature has been checked: [1](#0-0) [2](#0-1) 

`GitHubApp#verify_webhook_signature` returns `true` unconditionally when that organization's `webhook_secret` is blank: [3](#0-2) 

Running multiple GitHub Apps, each with its own optional `webhook_secret`, is a documented, supported configuration: [4](#0-3) [5](#0-4) 

The `membership` event handler then trusts the payload's `team.id`, `organization.login`, and `member.login` to look up or create a `Team` and add the named member to it, independent of which organization's secret (or lack thereof) was used to pass `verify_signature`: [6](#0-5) 

Crucially, `Team.find_or_create_by!(github_id: params.team.id)` only sets `organization` when *creating* a new record; if the numeric `team.id` already matches an existing authorized `Team`, the lookup succeeds without re-validating that the request came from that team's real organization. That `Team` is exactly what gates application-wide authorization: [7](#0-6) [8](#0-7) 

This breaks the binding: *organization whose secret authenticated the webhook* == *organization/team actually written to and later used for authorization*. The signing organization field and the authorization-relevant `team.id`/`member.login` fields are two independent, attacker-supplied pieces of the same unsigned-when-secretless JSON body.

### Impact Explanation
By sending a forged `membership` webhook naming any configured organization that has no `webhook_secret` set (a documented, valid option for one of several configured GitHub Apps) but supplying the numeric GitHub team ID of a team present in `Shipit.github_teams`, an unprivileged attacker can add their own GitHub login as a member of that authorizing team. After a normal OAuth login with that GitHub account, `User#authorized?` returns true, granting full access to the Shipit UI/API — an escalation into `Shipit.github_teams` authorization, matching the accepted High-severity impact category (escalation into `Shipit.github_teams` authorization).

### Likelihood Explanation
Requires: (a) a multi-org Shipit deployment where at least one configured organization has no `webhook_secret` (a documented, supported configuration, not a misconfiguration outside the engine's design), and (b) knowledge or guessing of the numeric `github_id` of an authorized `Team`. No Shipit session, `ApiClient` token, or GitHub credentials of the victim organization are required — only the ability to send an unauthenticated POST to `/webhooks`.

### Recommendation
- Reject `verify_webhook_signature` when `webhook_secret` is blank instead of auto-passing, or require every configured organization to have a non-blank secret.
- Cross-validate that the `organization`/`repository` field used to select the signing secret matches the organization actually referenced by mutating handlers (e.g., require `MembershipHandler` to confirm `params.organization.login` equals the `Team#organization` of an existing team before adding members).
- Do not let `Team.find_or_create_by!(github_id:)` short-circuit organization validation on an existing record.

### Proof of Concept
1. Deploy Shipit with two GitHub Apps configured under `secrets.yml`: `shopify` (has `webhook_secret`, owns an authorized team, e.g. `github_id: 555`) and `attacker-org` (no `webhook_secret` set, per documented optional config).
2. POST to `/webhooks` with header `X-Github-Event: membership` and no valid `X-Hub-Signature`, body:
```json
{
  "action": "added",
  "team": { "id": 555, "name": "developers", "slug": "developers", "url": "https://api.github.com/teams/555" },
  "organization": { "login": "attacker-org" },
  "member": { "login": "attacker-github-login" }
}
```
3. `repository_owner` resolves to `attacker-org`; `Shipit.github(organization: "attacker-org").verify_webhook_signature` returns `true` because `webhook_secret` is blank for that org.
4. `MembershipHandler#process` finds the existing `Team` with `github_id: 555` (the real `shopify/developers` team) and calls `team.add_member(User.find_or_create_by_login!("attacker-github-login"))`, granting that login membership in an authorizing team.
5. Attacker completes GitHub OAuth login as `attacker-github-login`; `User#authorized?` now returns true via `Shipit.github_teams` membership.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

        def process
          team = find_or_create_team!
          member = User.find_or_create_by_login!(params.member.login)

          case params.action
          when 'added'
            team.add_member(member)
          when 'removed'
            team.members.delete(member)
          else
            raise ArgumentError, "Don't know how to perform action: `#{action.inspect}`"
          end
        end

        private

        def find_or_create_team!
          Team.find_or_create_by!(github_id: params.team.id) do |team|
            team.github_team = params.team
            team.organization = params.organization.login
          end
        end
