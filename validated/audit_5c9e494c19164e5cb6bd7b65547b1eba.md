### Title
Unauthenticated Bridge P2P Peer Can Zero `remoteGasPrice` via Spoofed `ServiceChainParentChainInfoResponseMsg`, Permanently Halting Anchoring — (`node/sc/sub_bridge_handler.go`)

### Summary

Any P2P node that can reach the SubBridge's listening port can connect, pass the bridge handshake (which only checks `NetworkId` and `ProtocolVersion`), and send a `ServiceChainParentChainInfoResponseMsg` with `IsMagmaEnabled=false` and `GasPrice=0`. This unconditionally sets `sbh.remoteGasPrice = 0` and `pAccount.gasPrice = 0`. All subsequent anchoring transactions are built with `gasPrice=0`, rejected by the parent chain with `ErrGasPriceBelowBaseFee`, removed from the bridge pool with no automatic retry, and the attacker can sustain the corruption by responding to every `SyncNonceAndGasPrice` request with another zeroed message.

### Finding Description

**Step 1 — Unauthenticated peer admission.**
`baseBridgePeer.readStatus` validates only `NetworkId` and `ProtocolVersion`. It does not check `ChainID`, `GenesisBlock`, or any cryptographic identity. The `RegisterNewPeer` chain-ID guard reads `p.GetChainID()`, which is the attacker's own self-reported value from the status message — trivially spoofed. [1](#0-0) 

**Step 2 — Unsolicited response accepted.**
`HandleMainMsg` on the SubBridge side dispatches `ServiceChainParentChainInfoResponseMsg` (code `0x04`) to `handleParentChainInfoResponseMsg` for any connected peer, with no check that the message was solicited or that the sender is the legitimate parent chain node. [7](#0-6) 

**Step 3 — Unvalidated gas price written.**
`handleParentChainInfoResponseMsg` calls `setRemoteChainValues(pcInfo)` unconditionally. `setRemoteChainValues` calls `setRemoteGasPrice(pcInfo.GasPrice)` first, which writes `pcInfo.GasPrice` (0) to both `sbh.remoteGasPrice` and `pAccount.gasPrice`. The `IsMagmaEnabled=false` branch does not override this value, leaving `remoteGasPrice = 0`. [4](#0-3) 

**Step 4 — Anchoring txs built with gasPrice=0.**
`genUnsignedChainDataAnchoringTx` reads `sbh.remoteGasPrice` directly into `TxValueKeyGasPrice`. With `remoteGasPrice = 0`, every anchoring tx is built with `gasPrice=0`. [5](#0-4) 

**Step 5 — Tx rejected, removed, no retry.**
The parent chain's `handleServiceChainTxDataMsg` calls `txPool.AddRemote(tx)`, which rejects the tx with `ErrGasPriceBelowBaseFee`. The parent chain sends `ServiceChainInvalidTxResponseMsg`. The child chain's `handleParentChainInvalidTxResponseMsg` calls `SyncNonceAndGasPrice()` and then removes the tx. The code comment explicitly states: "For anchoring txs, there is no automatic retry mechanism." [6](#0-5) 

**Step 6 — Sustained attack.**
`SyncNonceAndGasPrice()` broadcasts a new `ServiceChainParentChainInfoRequestMsg` to all peers. The attacker responds again with `GasPrice=0`, re-zeroing `remoteGasPrice` before or after the legitimate peer responds. The attacker can also send unsolicited `ServiceChainParentChainInfoResponseMsg` messages at any time to continuously reset the value. [8](#0-7) 

### Impact Explanation

Anchoring is the core cross-chain data integrity mechanism of the Kaia service chain. With `remoteGasPrice` zeroed, every anchoring transaction is permanently rejected by the parent chain and removed from the bridge pool with no recovery path. This constitutes a durable loss of core chain functionality: the child chain can no longer anchor block data to the parent chain, breaking the security guarantee of the service chain.

### Likelihood Explanation

The SubBridge P2P port is reachable by any network peer. The bridge handshake has no chain ID or genesis block check, so any node knowing the `NetworkId` and protocol version (both public) can connect. No private key, governance privilege, or validator majority is required. The attack is repeatable and self-sustaining.

### Recommendation

1. **Validate gas price floor**: In `setRemoteChainValues` / `setRemoteGasPrice`, reject or ignore any `GasPrice` of 0 (or below a configured minimum).
2. **Authenticate the peer**: In `baseBridgePeer.readStatus`, add a `ChainID` check matching the regular Kaia peer handshake, and optionally a genesis block check.
3. **Restrict message acceptance**: Only process `ServiceChainParentChainInfoResponseMsg` from peers whose node ID matches the configured parent chain peer list.
4. **Add retry for anchoring txs**: When an anchoring tx is removed due to `ErrGasPriceBelowBaseFee`, re-generate it after the gas price is re-synced.

### Proof of Concept

1. Attacker node connects to the SubBridge P2P port, sends a `StatusMsg` with the correct `NetworkId` and `ProtocolVersion`, and any `ChainID` matching the configured parent chain ID.
2. Attacker sends `ServiceChainParentChainInfoResponseMsg` encoding `parentChainInfo{Nonce: 0, GasPrice: 0, IsMagmaEnabled: false}`.
3. `handleParentChainInfoResponseMsg` decodes it, calls `setRemoteChainValues`, which calls `setRemoteGasPrice(0)` → `sbh.remoteGasPrice = 0`.
4. On the next anchoring period, `genUnsignedChainDataAnchoringTx` builds a tx with `gasPrice=0`.
5. The tx is broadcast to the parent chain, rejected with `ErrGasPriceBelowBaseFee`, and removed from the bridge pool.
6. `SyncNonceAndGasPrice()` is called; attacker responds again with `GasPrice=0`.
7. Anchoring is permanently halted.

func (p *baseBridgePeer) readStatus(network uint64, status *statusData) error {
	msg, err := p.rw.ReadMsg()

	if msg.Code != StatusMsg {

	if int(status.ProtocolVersion) != p.version {

	}
	return nil
}
