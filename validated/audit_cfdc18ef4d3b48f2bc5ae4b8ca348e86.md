### Title

Accrual unscale overflow permanently freezes an oversized high-utilization market - ([File: common/src/rates/scaling.rs])

### Summary

RAY-scaled market balances are multiplied by the current index inside `scaled_to_original`, and the multiplication panics once the resulting RAY value exceeds `i128::MAX`. [1](#0-0)  Every accrual step calculates both unscaled borrowed and supplied totals before computing utilization, so a sufficiently large market can cross the value ceiling before the borrow index reaches its own 10^36 ceiling. [2](#0-1) [3](#0-2) 

### Finding Description

The pool accrues interest on every market mutation through `ops::synced_market`, which calls `interest::global_sync`. [4](#0-3)  `global_sync` repeatedly invokes `accrue_step`, and `accrue_step` calls `scaled_to_original` for both `borrowed` and `supplied`. [5](#0-4) [6](#0-5) 

`scaled_to_original` performs `scaled.mul(index)` rather than bounding the product by the market/index caps. [1](#0-0)  Although caps bound the asset-to-RAY input to approximately 170.14 billion whole tokens, accrued value is the product of scaled shares and index and can overflow before the index reaches `MAX_BORROW_INDEX_RAY`. [7](#0-6) [8](#0-7) 

An unprivileged caller reaches the trigger through `Controller::update_indexes(caller, assets)`, which requires only caller authorization and calls the pool’s `update_indexes`. [9](#0-8) [10](#0-9)  Once the stored share balance times the next index exceeds `i128::MAX`, the transaction reverts before `last_timestamp` advances, leaving the same elapsed interval to hit the same overflow on every retry. [11](#0-10) [12](#0-11) 

### Impact Explanation

This permanently freezes the affected market: repayments and withdrawals load the same accrual path, and liquidation-related pool mutations also synchronize before operating. [13](#0-12) [14](#0-13)  The repository’s dedicated regression demonstrates that a billion-unit, 18-decimal market at sustained high utilization reverts with `MathOverflow`, after which even a one-unit withdrawal and a repayment fail. [15](#0-14) 

The consequence is permanent freezing of supplier funds and an inability to repay or liquidate debt in that market, which also prevents normal bad-debt resolution that depends on synchronized pool mutations. [16](#0-15) [17](#0-16) 

### Likelihood Explanation

Likelihood is Medium: the attack is permissionless only after the market already has a very large representable balance and sustained high utilization, and it requires enough collateral and time for interest to push a scaled total past the `i128` value domain. [18](#0-17)  The repository test reaches the condition under admitted caps and ordinary `supply`/`borrow` flows, then triggers it with the permissionless index keeper path, so no privileged call, leaked key, oracle dishonesty, or invalid parameter is required. [19](#0-18) [9](#0-8) 

### Recommendation

Do not let accrual reach an unrecoverable `scaled * index` overflow: bound admitted aggregate scaled balances against a future-index safety margin, or perform accrual valuation in widened arithmetic and add an explicit recoverable market-halt/settlement state for unrepresentable balances. At minimum, cap total scaled supply and debt below `i128::MAX / MAX_INDEX` rather than only bounding token input, and keep a repayment/exit path that does not depend on recomputing an overflowing utilization projection. [20](#0-19) [21](#0-20) 

### Proof of Concept

A concrete sequence is:

1. On a high-decimal market with sufficient configured caps, have suppliers deposit enough tokens that the scaled supply approaches the representable RAY domain.
2. An unprivileged borrower supplies sufficient collateral through `Controller::supply` and borrows most of that market through `Controller::borrow`, keeping utilization high.
3. Let ledger time advance while utilization remains high.
4. Any address calls `Controller::update_indexes(caller, [hub_asset])`; `accrue_step` evaluates `scaled_to_original(borrowed, borrow_index)` and panics when the accrued value exceeds `i128::MAX`. [22](#0-21) [23](#0-22) 
5. Subsequent `update_indexes`, `repay`, `withdraw`, and liquidation paths all synchronize first and hit the same panic, leaving the market permanently frozen. [24](#0-23) [25](#0-24)

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);

/// Returns the largest cap, in asset base units, whose ray-scaled form still
/// fits in `i128`.
///
/// Returns 0 when `asset_decimals > RAY_DECIMALS`, since the ray form is not
/// representable in that case. Enforced by
/// [`require_cap_within_asset_domain`], so stored caps can never overflow the
/// asset→ray rescale.
pub fn max_cap_for_decimals(asset_decimals: u32) -> i128 {
    let Some(exp) = RAY_DECIMALS.checked_sub(asset_decimals) else {
        return 0;
    };
    let upscale = 10i128
        .checked_pow(exp)
        .expect("10^(RAY_DECIMALS - asset_decimals) fits i128 for asset_decimals <= RAY_DECIMALS");
    i128::MAX / upscale
}

/// Panics with `CollateralError::AssetDecimalsTooHigh` if `asset_decimals`
/// exceeds `RAY_DECIMALS`, or with `CollateralError::InvalidBorrowParams` if
/// `cap` exceeds the value returned by `max_cap_for_decimals`.
pub fn require_cap_within_asset_domain(env: &Env, cap: i128, asset_decimals: u32) {
    if RAY_DECIMALS.checked_sub(asset_decimals).is_none() {
        panic_with_error!(env, CollateralError::AssetDecimalsTooHigh);
    }
    assert_with_error!(
        env,
        cap <= max_cap_for_decimals(asset_decimals),
        CollateralError::InvalidBorrowParams
    );

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
