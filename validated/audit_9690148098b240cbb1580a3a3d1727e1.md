Based on the evidence gathered, `pox-5.clar`'s `roll-sbtc` private function contains the direct analog of this bug class.

### Title
sBTC stake accounting assumes exact transfer amounts, breaking custody/share equality on fee-on-transfer or non-standard `sbtc-token` implementations - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`roll-sbtc` in `pox-5.clar` computes a `delta` between a staker's old and new sBTC lockup amount, calls `sbtc-token transfer` for exactly that `delta`, and then unconditionally credits/debits `total-sbtc-staked` (and, via its caller, `staker-shares-staked-for-cycle`) by the same nominal `delta` — without ever checking that the contract's actual sBTC balance changed by that amount. [1](#0-0) 

### Finding Description
When a staker increases their sBTC lockup, `roll-sbtc` calls `(contract-call? sbtc-token transfer delta tx-sender current-contract none)` and then does `(var-set total-sbtc-staked (+ (var-get total-sbtc-staked) delta))` regardless of the actual sats received by the contract. [2](#0-1) 
When decreasing, it performs the inverse: it transfers `delta` back to the staker `as-contract?` using `with-ft`, then decrements `total-sbtc-staked` by the nominal `delta`. [3](#0-2) 

This mirrors exactly the reported bug class: the contract assumes the token transferred is a standard, non-fee, non-rebasing asset where `amount sent == amount received`. `staker-shares-staked-for-cycle`, `total-sbtc-staked`, and reward-yield calculations (`bond-target-yield`) are all driven by this nominal `delta`, not by an actually-measured balance delta. If `sbtc-token` (or any future token substituted for it — note the sBTC token address is a hardcoded constant, not validated at each call) ever deducts a fee on transfer, rebases, or otherwise fails to deliver exactly `delta` sats:
- On the increase path, the staker is credited (`staker-shares-staked-for-cycle`, `total-sbtc-staked`) for more sats than the pox-5 contract actually custodies, breaking the equality "credited stake == actual custodied sBTC" and letting the staker earn bond rewards on sats never actually locked.
- On the decrease path, the contract could pay out more sBTC than it received back in the underlying accounting, since `total-sbtc-staked` is reduced by the nominal amount rather than the amount actually leaving the contract's real balance, risking a reserve/custody shortfall for other stakers' locked sBTC.

### Impact Explanation
This breaks the equality between "sats credited to a staker for reward-earning/share purposes" and "sats actually locked in the pox-5 contract's custody" — i.e., unbacked crediting of staked sats or permanent freezing/shortfall of other stakers' custodied sBTC, both explicitly listed impact categories (double-counting a commitment, or unlocking/crediting value never actually locked). This is a High/Critical-class issue per the rules, contingent entirely on the sBTC token deviating from the strict 1:1 transfer assumption baked into `roll-sbtc`.

### Likelihood Explanation
Likelihood is currently low-to-moderate: the in-repo sBTC token stub used in tests is a simple wrapped fungible token with no fee logic, so under the current stub, `delta` transferred always equals `delta` received. [4](#0-3)  However, `pox-5.clar` hardcodes the sBTC contract as a fixed principal (`SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token`) with no runtime verification that the actual custody balance changed by `delta` before updating accounting state, so any future upgrade or bug in the real sBTC token implementation (fee, pause-partial-transfer, rounding, or rebasing behavior) would silently desynchronize `total-sbtc-staked`/share accounting from real custody, with no code path currently guarding against it.

### Recommendation
In `roll-sbtc`, measure the contract's actual sBTC balance before and after each `transfer`/`with-ft` call and use the measured delta (not the nominal `delta` parameter) to update `total-sbtc-staked` and `staker-shares-staked-for-cycle`. This is analogous to the "check actual amounts received" recommendation from the original report, and would ensure pox-5's staked-sats accounting can never diverge from the sBTC actually held by the contract.

### Proof of Concept
1. Assume/introduce a variant of `sbtc-token` (e.g., via a protocol upgrade) that deducts a fee on `transfer`, e.g. `transfer` moves `amount - fee` to `recipient`.
2. Staker calls `register-for-bond`/`update-bond-registration` to increase their `btc-lockup` from `old-sbtc` to `new-sbtc`, computing `delta = new-sbtc - old-sbtc`.
3. `roll-sbtc` calls `sbtc-token transfer delta tx-sender current-contract none`; only `delta - fee` sats actually reach pox-5's custody. [5](#0-4) 
4. `roll-sbtc` nonetheless sets `total-sbtc-staked` and (via the caller) `staker-shares-staked-for-cycle` using the full `delta`, crediting the staker for `fee` more sats than were actually custodied. [6](#0-5) 
5. The staker earns bond yield (via `bond-target-yield`/`calculate-rewards`) proportional to the inflated sats figure, and on a later full `unstake-sbtc`, the contract attempts to pay out the nominal amount, which can exceed its real sBTC balance, freezing other stakers' funds.

(define-private (roll-sbtc
        (staker principal)
        (old-sbtc uint)
        (new-sbtc uint)
    )
    (begin
        (if (> new-sbtc old-sbtc)
            (let ((delta (- new-sbtc old-sbtc)))
                (try! (contract-call?
                    'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                    transfer delta tx-sender current-contract none
                ))
                (var-set total-sbtc-staked (+ (var-get total-sbtc-staked) delta))
            )
            (if (< new-sbtc old-sbtc)
                (let ((delta (- old-sbtc new-sbtc)))
                    (try! (as-contract?
                        ((with-ft
                            'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                            "sbtc-token" delta
                        ))
                        (try! (contract-call?
                            'SM3VDXK3WZZSA84XXFKAFAF15NNZX32CTSG82JFQ4.sbtc-token
                            transfer delta tx-sender staker none
                        ))
                    ))
                    (var-set total-sbtc-staked
                        (- (var-get total-sbtc-staked) delta)
                    )
                )
                ;; new-sbtc == old-sbtc, no transfer needed
                true
            )
        )
        (ok true)
    )
