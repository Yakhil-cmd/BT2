### Title
Webhook signature is verified against `repository.owner.login`, but handlers act on `repository.full_name` from the same unverified payload - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the HMAC signature against using one field of the attacker-supplied JSON body (`repository.owner.login`, falling back to `organization.login`), while every event handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, etc.) decides which `Stack`/`Repository` to mutate using a different field of that same body (`repository.full_name`). Because these two fields are never cross-checked against each other, a party who legitimately controls the webhook secret for one GitHub organization configured in this Shipit instance can forge a validly-signed webhook whose `repository.owner.login` matches their own org (so the signature check passes) but whose `repository.full_name` points at a repository belonging to a different organization also hosted on the same Shipit instance.

### Finding Description
`verify_signature` looks up the secret with: [1](#0-0) 
using `repository_owner`, which is derived purely from the JSON body: [2](#0-1) 

`verify_webhook_signature` HMACs the *entire raw body* against the secret for that one organization: [3](#0-2) 

Once the signature is accepted, `WebhooksController#create` dispatches the parsed body to handlers without any further binding to the organization that was authenticated: [4](#0-3) 

Every handler resolves the target repository/stack from a *different* field of the same body — `repository.full_name` — completely independent of `repository.owner.login`: [5](#0-4) 

For example, `PushHandler` triggers `stack.sync_github` for whatever stacks match `repository.full_name`: [6](#0-5) 

and `StatusHandler` writes a commit status sourced entirely from the payload for any commit matching `params.sha`, with no repository/organization check at all: [7](#0-6) 

**Binding broken (as an equality):** the engine implicitly assumes
`organization_that_signed_the_request == organization_that_owns_the_repository_being_acted_on`,
but the code only ever checks
`HMAC(body, secret_for(payload["repository"]["owner"]["login"])) == signature`,
never
`payload["repository"]["owner"]["login"] == owner_of(payload["repository"]["full_name"])`.
Since a single Shipit deployment can serve multiple GitHub organizations (`Shipit.github(organization: ...)`, per-org `webhook_secret` config in `lib/shipit/github_app.rb`), the two sides of this equality can diverge, and nothing enforces them being equal.

### Impact Explanation
An attacker who is a legitimate GitHub admin of any single repository/organization tracked by this Shipit instance (and therefore knows/can rotate that org's `webhook_secret` via normal GitHub repo/org settings — no Shipit session, `ApiClient` token, or GitHub App private key required) can forge a signed HTTP POST directly to `/webhooks` that:
- Sets `repository.owner.login`/`organization.login` to their own org (so `verify_signature` passes using a secret they legitimately hold), and
- Sets `repository.full_name` (and other free-form fields like `sha`, `state`, `context`, `target_url` for `status` events, or `ref`/`after` for `push` events) to target a repository/stack belonging to a *different* organization hosted on the same Shipit instance.

This lets the attacker: inject arbitrary/fake commit statuses onto another org's commits via `StatusHandler` (potentially unblocking CI-gated deploy conditions), or force `stack.sync_github` on another org's stack via `PushHandler`, or trigger check-run refresh via `CheckSuiteHandler` — all cross-organization actions that should be impossible without that other organization's own webhook secret. This maps to the "unauthorized deploy" / cross-repository-write category, since faking commit statuses/push events can influence which commits are eligible to deploy on a stack the attacker has no legitimate access to.

### Likelihood Explanation
Requires only that the attacker be a legitimate admin of one org/repo integrated with the target Shipit instance (a low, commonly-available privilege in multi-tenant CI setups) and knowledge of that org's webhook secret, which they control directly. No Shipit credentials, GitHub App keys, or TLS interception are needed — only crafting a raw HTTP request with a correct HMAC using a secret they legitimately own.

### Recommendation
After verifying the signature against the secret selected via `repository_owner`, re-derive the "owner" from `repository.full_name` (or the `repository.owner.login`) and require it to match the organization whose secret validated the signature before dispatching to handlers. Alternatively, bind handler-level repository/stack resolution to the same organization value used in `verify_signature`, rejecting payloads where `repository.owner.login` disagrees with the owner segment of `repository.full_name`.

### Proof of Concept
1. Attacker is an admin of `org-a/some-repo`, which is configured in Shipit with `webhook_secret = S`.
2. Attacker crafts a JSON body:
```json
{
  "sha": "<commit-sha-in-org-b-stack>",
  "state": "success",
  "context": "ci/tests",
  "repository": { "owner": { "login": "org-a" }, "full_name": "org-b/target-repo" }
}
```
3. Attacker computes `signature = "sha1=" + HMAC_SHA1(S, body)` and sends:
```
POST /webhooks
X-Github-Event: status
X-Hub-Signature: sha1=<signature>
```
4. `WebhooksController#verify_signature` calls `Shipit.github(organization: "org-a")` and successfully validates the signature against secret `S` [1](#0-0) .
5. `StatusHandler` runs, matching `Commit.where(sha: ...)` for `org-b/target-repo` and writes a forged "success" status on a commit the attacker never had access to [7](#0-6) , without `org-b`'s webhook secret ever being checked.

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
