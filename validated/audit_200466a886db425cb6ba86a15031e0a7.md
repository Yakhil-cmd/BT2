### Title
Hash Collision in Prosaic/Arbiter Contract Text Hashing via Unsafe Field Concatenation - (File: prosaic_contract.js, arbiter_contract.js)

### Summary
`prosaic_contract.js` and (for contracts created before `NEW_HASH_DATE`) `arbiter_contract.js` compute the contract's identifying hash by concatenating variable-length, counterparty-controlled strings (`title`, `text`, party names, amount, asset) without any delimiter, exactly the "hash-collision via unbounded concatenation" class described in the external report. This lets a private-payment counterparty construct two different sets of contract terms that hash to the same value, undermining the integrity guarantee the hash is relied upon for.

### Finding Description
`prosaic_contract.js` builds the hash as a plain string concatenation with no delimiter and no length prefixing: [1](#0-0) 

`arbiter_contract.js`'s `getHashSrc` uses a delimiter (`exports.DELIMITER`) only for contracts created after `NEW_HASH_DATE`; for older contracts it falls back to the same unsafe pattern, `.join("")`, over `title`, `text`, `creation_date`, `payer_name`, `arbiter_address`, `payee_name`, `amount`, `asset`: [2](#0-1) 

This is the same root cause pattern flagged in the external report (`bytes.concat` of variable-length arguments causing ambiguous encodings): here, `title`, `text`, and party names are attacker-supplied strings of arbitrary length and content, so shifting characters across the `title`/`text` boundary (e.g., `title="AB", text="C"` vs `title="A", text="BC"`) yields an identical concatenated string and therefore an identical SHA-256 hash — no brute-force search is required, this is a direct, deterministic collision.

Notably, the codebase's own canonical hashing utility, `string_utils.getSourceString`, explicitly defends against exactly this ambiguity by type-prefixing every field and rejecting the join character inside values: [3](#0-2) 
This shows the pattern used in `prosaic_contract.js`/`arbiter_contract.js` is a known-anti-pattern deviation from the project's own safe hashing convention.

### Impact Explanation
The resulting `contract.hash` is not merely a display id — it gates the flow of escrowed on-chain funds:
- It is embedded as the data-feed key `"CONTRACT_" + contract.hash` inside the shared (multisig) address `arrDefinition` that the appointed arbiter uses to release escrowed funds to the winning party: [4](#0-3) , and the winner is determined by matching this exact key: [5](#0-4) 
- It is sent to the arbstore as part of the dispute/appeal payload together with the actual `title`/`text`, which the arbiter uses to adjudicate the dispute and thereby who receives the escrowed funds: [6](#0-5) [7](#0-6) 
- It is embedded in the on-chain `data` message (`contract_text_hash`) used to prove the counterparty's on-chain signature corresponds to the agreed contract terms in both `prosaic_contract.js` and `arbiter_contract.js`: [8](#0-7) [9](#0-8) 

Because the hash can collide across different `(title, text, amount, party_name)` combinations, a malicious offeror can present one set of terms to their counterparty/arbiter while a different, colliding set of terms was actually agreed/committed, breaking the cryptographic binding that the arbitration/escrow-release mechanism depends on. This can result in an arbiter releasing escrowed funds based on a disputed/forged version of the contract text that hashes identically to the version shown to the victim, i.e., concrete fund loss/misdirection for one of the escrow counterparties.

### Likelihood Explanation
Exploitable by any unprivileged counterparty to a prosaic or arbiter contract (an ordinary wallet user), with no special access needed — only the ability to choose the `title`/`text`/party-name strings when creating or responding to the contract offer, which is a normal step of using this feature. For `prosaic_contract.js` this affects all contracts (no delimiter fix exists at all); for `arbiter_contract.js` it affects contracts with `creation_date <= NEW_HASH_DATE` (2026-11-01), i.e., a bounded but still exploitable window given the codebase evidently already recognized and partially patched this exact issue for arbiter contracts but left `prosaic_contract.js` unfixed.

### Recommendation
Replace the raw string concatenation in `prosaic_contract.getHash`/`getHashV1` and the pre-`NEW_HASH_DATE` branch of `arbiter_contract.getHashSrc` with the project's existing safe canonical hashing helper (`object_hash.getBase64Hash`/`string_utils.getSourceString`), which type-prefixes fields and rejects the join-character inside values, eliminating boundary-shift collisions. If backward compatibility with the old hash format must be preserved for historical records, mark it deprecated and refuse fund-affecting operations (dispute resolution, escrow release) based on it.

### Proof of Concept
1. Party A creates a prosaic (or pre-`NEW_HASH_DATE` arbiter) contract with `title="AB"`, `text="C"`, `creation_date=D`. Hash `H = sha256("AB"+"C"+D)`.
2. Party A separately prepares an alternate version with `title="A"`, `text="BC"`, same `creation_date=D`. Since `"AB"+"C" === "A"+"BC"`, the hash is identical: `H`.
3. Party A sends the first version to Party B for signature/acceptance (`createAndSend` in prosaic_contract.js / arbiter_contract.js), obtaining B's on-chain co-signature and the `contract_text_hash=H` data message.
4. During a later dispute, Party A submits the second (altered) version with matching `hash=H` to the arbstore (`openDispute`/`appeal`), which cannot distinguish it from the version B actually agreed to, since both hash to `H`.
5. The arbiter's ruling — which drives fund release via the `CONTRACT_H` data-feed condition in the shared address definition (`deriveSharedAddress`) — is thus based on unverifiable/forged terms, enabling Party A to bias or falsify the dispute outcome and the resulting fund distribution.

function getHashSrc(contract) {
	const payer_name = contract.me_is_payer ? contract.my_party_name : contract.peer_party_name;
	const payee_name = contract.me_is_payer ? contract.peer_party_name : contract.my_party_name;
	const payer_address = contract.me_is_payer ? contract.my_address : contract.peer_address;
	const payee_address = contract.me_is_payer ? contract.peer_address : contract.my_address;
	const src = contract.creation_date > exports.NEW_HASH_DATE
		 ? [contract.title, contract.text, contract.creation_date, payer_address, payer_name || '', contract.arbiter_address, payee_address, payee_name || '', contract.amount, contract.asset || 'null'].join(exports.DELIMITER)
		 : [contract.title, contract.text, contract.creation_date, payer_name || '', contract.arbiter_address, payee_name || '', contract.amount, contract.asset || 'null'].join("");
	return src;
}

function getHash(contract) {
	return crypto.createHash("sha256").update(getHashSrc(contract), "utf8").digest("base64");
}

function parseWinnerFromUnit(contract, objUnit) {
	if (objUnit.authors[0].address !== contract.arbiter_address) {
		return;
	}
	var key = "CONTRACT_" + contract.hash;
	var winner;
	objUnit.messages.forEach(function(message){
		if (message.app !== "data_feed" || !message.payload || !message.payload[key]) {
			return;
		}
		winner = message.payload[key];
	});
	if (!winner || (winner !== contract.my_address && winner !== contract.peer_address)) {
		return;
	}
	return winner;
}

function getSourceString(obj) {
	var arrComponents = [];
	function extractComponents(variable){
		if (variable === null)
			throw Error("null value in "+JSON.stringify(obj));
		switch (typeof variable){
			case "string":
				if (variable.includes(STRING_JOIN_CHAR))
					throw Error("00 byte in string value in " + JSON.stringify(obj));
				arrComponents.push("s", variable);
				break;
			case "number":
				if (!isFinite(variable))
					throw Error("invalid number: " + variable);
				arrComponents.push("n", variable.toString());
				break;
			case "boolean":
				arrComponents.push("b", variable.toString());
				break;
			case "object":
				if (Array.isArray(variable)){
					if (variable.length === 0)
						throw Error("empty array in "+JSON.stringify(obj));
					arrComponents.push('[');
					for (var i=0; i<variable.length; i++)
						extractComponents(variable[i]);
					arrComponents.push(']');
				}
				else{
					var keys = Object.keys(variable).sort();
					if (keys.length === 0)
						throw Error("empty object in "+JSON.stringify(obj));
					keys.forEach(function(key){
						if (typeof variable[key] === "undefined")
							throw Error("undefined at "+key+" of "+JSON.stringify(obj));
						if (key.includes(STRING_JOIN_CHAR))
							throw Error("00 byte in object key in " + JSON.stringify(obj));
						arrComponents.push(key);
						extractComponents(variable[key]);
					});
				}
				break;
			default:
				throw Error("getSourceString: unknown type="+(typeof variable)+" of "+variable+", object: "+JSON.stringify(obj));
		}
	}

	extractComponents(obj);
	return arrComponents.join(STRING_JOIN_CHAR);
}
