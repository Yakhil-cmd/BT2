### Title
Open redirect via unchecked `omniauth.origin` in `GithubAuthenticationController#callback` enabling forced-OAuth-completion phishing - (File: app/controllers/shipit/github_authentication_controller.rb)

### Summary
`Shipit::GithubAuthenticationController#callback` redirects the browser to `request.env['omniauth.origin']` with no validation that its host matches Shipit's own host. An attacker can craft a login link with `origin=https://evil.example`, and after the victim completes GitHub OAuth, Shipit redirects the authenticated browser straight to the attacker-controlled site, disclosing successful authentication and enabling forced-OAuth-completion phishing.

### Finding Description
The intended binding is: `URI(return_url).host == Shipit.host`. In `#callback`:
```ruby
return_url = request.env['omniauth.origin'] || root_path
...
redirect_to(return_url)
``` [1](#0-0) 

`omniauth.origin` is populated by the OmniAuth middleware from the `origin` request parameter supplied to the `/github/auth` (request-phase) endpoint configured in `lib/shipit/engine.rb`:
```ruby
if Shipit.github.oauth?
  OmniAuth::Strategies::GitHub.configure(path_prefix: '/github/auth')
  app.middleware.use(OmniAuth::Builder) do
    provider(:github, *Shipit.github.oauth_config)
  end
end
``` [2](#0-1) 

OmniAuth does not itself constrain `origin` to same-host values by default — it is stored verbatim and echoed back on callback. Nothing in `GithubAuthenticationController` checks the host/path of `return_url` before calling `redirect_to`. This is a genuine divergence: the two sides of the equality (`return_url` host vs `Shipit.host`) are never compared, so an attacker-supplied external host passes through untouched.

Attack flow:
1. Attacker sends victim a link: `GET /github-authentication?origin=https://evil.example/steal` (or directly to `/github/auth?origin=https://evil.example/steal`).
2. Victim, an authenticated Shipit operator or new user, completes GitHub OAuth.
3. `#callback` sets `session[:user_id]` and `session[:authenticated] = true`, then executes `redirect_to('https://evil.example/steal')`, sending the victim's browser to the attacker's page immediately after a successful login.

No existing guard (`verify_signature`, `force_github_authentication`, `User#authorized?`) applies here since this is not a webhook or API path — it's the OAuth callback itself, and no host allowlist exists in this controller.

### Impact Explanation
This is a forced-OAuth-completion / open-redirect issue matching the "High - session fixation / forced OAuth completion" impact category. Per request, an attacker can confirm that a targeted victim has valid Shipit/GitHub credentials and has completed authentication (timing/behavioral signal), and can drive victims to attacker-controlled pages immediately post-login, which can be leveraged for further phishing (e.g., convincing the victim their session "expired" and prompting credential re-entry, or chaining with other flows). It does not by itself leak the session cookie or `github_access_token` (those aren't placed in the URL), so it stops short of Critical, but it is repeatable against any victim who clicks a maliciously crafted authentication link, for any Shipit deployment with OAuth enabled.

### Likelihood Explanation
Preconditions: Shipit must have GitHub OAuth enabled (`Shipit.github.oauth?`), which is the standard authentication mode. The attacker cost is trivial: crafting a URL with an `origin` query parameter and social-engineering a click — no secrets, tokens, or privileged roles required, consistent with the "unprivileged internet user" threat model. This is fully repeatable per victim/per link.

### Recommendation
Validate `return_url` before redirecting: parse it and only allow redirect if it's a same-host relative path (or matches `Shipit.host`), otherwise fall back to `root_path`. For example:
```ruby
def callback
  return_url = safe_return_url(request.env['omniauth.origin'])
  ...
  redirect_to(return_url)
end

private

def safe_return_url(origin)
  return root_path if origin.blank?
  uri = URI.parse(origin) rescue nil
  return root_path if uri.nil?
  return uri.to_s if uri.host.nil? # relative path, safe
  return uri.to_s if uri.host == Shipit.host
  root_path
end
```

### Proof of Concept
```ruby
# test/controllers/github_authentication_controller_test.rb
test "callback rejects external omniauth.origin and redirects to root_path" do
  request.env['omniauth.origin'] = 'https://evil.example/steal'
  request.env['omniauth.auth'] = OmniAuth::AuthHash.new(
    provider: 'github',
    uid: '123',
    extra: { raw_info: { login: 'bob', id: 123 } },
    credentials: { token: 'x' }
  )

  get :callback

  assert_redirected_to shipit.root_path
  refute_equal 'https://evil.example/steal', response.location
end
```
Assertion binds both sides of the equality explicitly: `URI(response.location).host` must equal `Shipit.host` (or be root_path), never the attacker-supplied `evil.example`.
