### Title
Uncaught TypeError in `json_parse()` Size-Check Crashes the Node — Unprivileged AA-Trigger DoS - (File: formula/evaluation.js)

### Summary
The GitLab advisory describes a DoS where a validation/size-limit middleware could be bypassed by malformed input, letting an unauthenticated actor exhaust CPU/memory. The ocore analog is in the oscript `json_parse()` opcode: its object-size guard, `isTooBigObj()`, is called with a missing required argument, so instead of enforcing the size limit it throws an uncaught `TypeError` whenever the parsed JSON is an object or array. Any unprivileged user who can get an AA trigger/formula evaluated (poster of a unit that triggers an AA, or an AA author whose formula runs during response composition) can reach this code path and crash the evaluating node process.

### Finding Description
`isTooBigObj` is declared with a required destructured second parameter that has no default: [1](#0-0) 

Because the whole options object itself has no `= {}` default (only its inner properties do), calling `isTooBigObj(x)` with a single argument makes JavaScript attempt to destructure `undefined`, which throws `TypeError: Cannot destructure property 'depthLimit' of 'undefined' as it is undefined.`

The `json_parse` opcode in the oscript evaluator calls it exactly this way, with only one argument, right after `JSON.parse`: [2](#0-1) 

The surrounding `try/catch` only wraps `JSON.parse(res)`; the subsequent `isTooBigObj(json)` call — and the exception it throws — is outside that `try` block, so the `TypeError` is not caught here. `typeof json === 'object'` is true for both plain objects and arrays returned by `JSON.parse`, so any string that parses into an object or array (e.g. `'{"a":1}'` or `'[1]'`) triggers the crash path, not just intentionally huge payloads.

`json_parse` is a normal, unprivileged oscript function usable in AA definitions/trigger data formulas evaluated via `formula/evaluation.js`'s `evaluate()`, which is invoked during AA trigger processing (`aa_composer.js`) whenever a message/unit references an AA. Reaching it requires nothing more than posting a unit that triggers an AA containing (or whose response formula contains) a `json_parse()` call on a string that parses to an object/array — well within reach of "an unprivileged unit poster" or "AA trigger sender."

### Impact Explanation
An uncaught synchronous exception thrown deep inside the asynchronous AA-evaluation callback chain is not guaranteed to be caught by any surrounding handler; in Node.js such throws inside callback continuations typically surface as unhandled exceptions, which crash the process by default. Since AA trigger processing happens on every full node that validates/executes the same unit (and light nodes that request AA responses), a single crafted trigger unit can crash every node that attempts to process it — a network-wide denial of service preventing confirmation of AAs (and potentially the whole node process, affecting confirmation of new units generally), which matches the "node disagreement on validity/stability" and "network unable to confirm new units" impact categories.

### Likelihood Explanation
Trivial to trigger: any oscript formula containing `json_parse('{}')`, `json_parse('[]')`, or similar, evaluated as part of an AA trigger or response, hits the vulnerable call unconditionally — no large payload or special crafting beyond a syntactically valid unit and AA definition is required. This makes exploitation low-effort and repeatable by any address capable of sending a unit.

### Recommendation
Fix the call site to always pass an options object (even empty) so defaults apply, e.g. `isTooBigObj(json, {})`, and/or give `isTooBigObj`'s second parameter a top-level default (`function isTooBigObj(obj, { depthLimit = 100, nodesLimit = 10000, lengthLimit = 1000000 } = {})`). Additionally, widen the `try/catch` in the `json_parse` handler to cover the `isTooBigObj` call (and any other post-parse processing) so that any unexpected exception degrades gracefully via `setFatalError` instead of propagating as an uncaught exception.

### Proof of Concept
1. Define/trigger an AA whose formula includes:
   `json_parse('{"a":1}')`
   or embed it directly in a unit's data/trigger that an AA formula evaluates.
2. Post the triggering unit to the network.
3. When a full node evaluates the AA trigger, `formula/evaluation.js`'s `json_parse` case successfully parses the JSON into an object, then calls `isTooBigObj(json)` with a single argument.
4. `isTooBigObj`'s destructuring of the missing second parameter throws `TypeError`, uncaught by the local `try/catch` (which only wraps `JSON.parse`), propagating out of the async evaluation chain and crashing the node process handling the trigger.
