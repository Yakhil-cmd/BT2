### Title
Unrestricted, instant vote account commission increases via `UpdateCommissionBps` bypass epoch-boundary protections relied on by delegators - ([File: programs/vote/src/vote_state/mod.rs])

### Summary
The legacy `update_commission` instruction handler enforces an epoch-boundary rule (`is_commission_update_allowed`) that prevents a vote account's authorized withdrawer from raising commission late in an epoch, giving delegators a safety window before rewards are computed. The newer `update_commission_bps` instruction (SIMD-0291/SIMD-0249) removes this rule entirely, allowing the authorized withdrawer to raise the commission (inflation-rewards or block-revenue) to any value at any point in the epoch, including immediately before the epoch-rewards partitioned distribution runs, with no floor, cap, cooldown, or timing restriction.

### Finding Description
`update_commission` computes `enforce_commission_update_rule` and rejects a commission increase unless `is_commission_update_allowed(clock.slot, epoch_schedule)` returns true, i.e., unless the change happens early enough in the epoch: [1](#0-0) 

In contrast, `update_commission_bps` explicitly documents and implements the removal of any such guard ("No commission update rule, per SIMD-0249 and SIMD-0291") and only requires the authorized withdrawer's signature before mutating `inflation_rewards_commission_bps` or `block_revenue_commission_bps`: [2](#0-1) 

This is directly analogous to the reported rage-quit bug class: a single privileged authority (there, the party host; here, the vote account's authorized withdrawer) can arbitrarily and instantly override a previously-relied-upon parameter that other, unprivileged stakeholders (party members / stake delegators) depend on for predictable outcomes, with no minimum notice period, no cap on the magnitude of change, and no restriction on how often it can be changed. Delegators who stake to a vote account under an advertised low commission have no analogous protection once BPS commission control is in effect — the withdrawer can raise commission to the maximum right before the epoch rewards are calculated and distributed, extracting a larger share of inflation/block-revenue rewards than delegators expected when they delegated, and can repeat this indefinitely.

### Impact Explanation
This enables misattributed rewards: delegators' expected share of inflation and block-revenue rewards can be reduced without warning or delay by a unilateral, instantaneous action of the vote account's withdraw authority, functionally reallocating lamports from delegators to the validator operator for that epoch's distribution. Because `update_commission_bps` has no epoch-boundary cutoff (unlike the legacy path), this can be done right up to the reward-calculation point, maximizing extracted value and minimizing delegators' ability to react (e.g., by deactivating stake in time).

### Likelihood Explanation
Any vote account authorized withdrawer can invoke this at will using the standard `VoteInstruction::UpdateCommissionBps` instruction with no special preconditions besides their own signature, so likelihood is high once SIMD-0291's commission_bps mechanism is enabled and no rate/timing rule is reintroduced.

### Recommendation
Reinstate an epoch-boundary (or similar) restriction for `update_commission_bps` analogous to `is_commission_update_allowed` used in `update_commission`, or otherwise bound commission increases (e.g., cap increase magnitude per epoch, enforce a cooldown, or restrict increases to only the early portion of an epoch) so delegators retain a guaranteed window of stable commission before reward distribution.

### Proof of Concept
1. Delegate stake to a vote account advertising a low `inflation_rewards_commission_bps`.
2. Near the end of the epoch, have the vote account's authorized withdrawer submit `VoteInstruction::UpdateCommissionBps { commission_bps: MAX, kind: InflationRewards }`.
3. Per `update_commission_bps`, the change is applied immediately with no epoch-timing check (contrast with `update_commission`'s `is_commission_update_allowed` gate). [3](#0-2) 
4. When partitioned epoch rewards are calculated for that epoch, the newly-raised commission is used, reducing the delegator's realized reward share versus what was in effect when they delegated.

/// Update the vote account's commission
pub fn update_commission<S: std::hash::BuildHasher>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    commission: u8,
    signers: &HashSet<Pubkey, S>,
    epoch_schedule: &EpochSchedule,
    clock: &Clock,
    disable_commission_update_rule: bool,
) -> Result<(), InstructionError> {
    let vote_state_result = get_vote_state_handler_checked(vote_account, target_version);
    let enforce_commission_update_rule = !disable_commission_update_rule
        && match vote_state_result.as_ref() {
            Ok(decoded_vote_state) => commission > decoded_vote_state.commission(),
            Err(_) => true,
        };

    if enforce_commission_update_rule && !is_commission_update_allowed(clock.slot, epoch_schedule) {
        return Err(VoteError::CommissionUpdateTooLate.into());
    }

    let mut vote_state = vote_state_result?;

    // current authorized withdrawer must say "yay"
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;

    vote_state.set_commission(commission);

    vote_state.set_vote_account_state(vote_account)
}

/// Update the vote account's commission in basis points (SIMD-0291, SIMD-0123).
pub fn update_commission_bps<S: std::hash::BuildHasher>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    commission_bps: u16,
    kind: CommissionKind,
    signers: &HashSet<Pubkey, S>,
    block_revenue_sharing_enabled: bool,
) -> Result<(), InstructionError> {
    // Per SIMD-0291: BlockRevenue returns InvalidInstructionData unless
    // SIMD-0123 (block_revenue_sharing) is enabled.
    if matches!(kind, CommissionKind::BlockRevenue) && !block_revenue_sharing_enabled {
        return Err(InstructionError::InvalidInstructionData);
    }

    let mut vote_state = get_vote_state_handler_checked(vote_account, target_version)?;

    // No commission update rule, per SIMD-0249 and SIMD-0291.

    // Require authorized withdrawer to sign.
    verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;

    match kind {
        CommissionKind::InflationRewards => {
            vote_state.set_inflation_rewards_commission_bps(commission_bps);
        }
        CommissionKind::BlockRevenue => {
            vote_state.set_block_revenue_commission_bps(commission_bps);
        }
    }

    vote_state.set_vote_account_state(vote_account)
}
