### Title
Webhook signature verification authenticates the sending organization while event handlers act on a different, attacker-controlled `repository.full_name` field, enabling cross-organization writes - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/`webhook_secret` used for HMAC verification from `params.dig('repository', 'owner', 'login')`, but every webhook `Handler` resolves the `Stack`/`Repository` to mutate from a completely separate JSON field, `payload.dig('repository', 'full_name')`. Because HMAC verification only proves the raw request body was signed with *some* configured organization's secret, and does not bind that secret to the `full_name` field the handlers actually trust, an attacker who controls (or knows the webhook secret for) any single organization configured on a shared Shipit instance can forge a validly-signed webhook whose `repository.full_name` names a stack belonging to a different, unrelated organization.

### Finding Description
`verify_signature` computes the org to authenticate against solely from the unverified payload: [1](#0-0) [2](#0-1) 

`Shipit.github(organization: repository_owner)` looks up the `GitHubApp` instance (and thus `webhook_secret`) configured for that particular organization (Shipit supports multiple independently configured GitHub Apps/orgs, each with its own `webhook_secret`), and `GitHubApp#verify_webhook_signature` only checks that the raw body HMAC matches that org's secret — it has no knowledge of, or constraint on, any other field inside the payload: [3](#0-2) 

Once the signature check passes, `WebhooksController#create` hands the *entire* (attacker-controlled) JSON body to the matching event handler: [4](#0-3) 

Every handler (`PushHandler`, `StatusHandler`, `CheckSuiteHandler`, the `PullRequest::*` handlers, etc.) inherits `Handler#stacks`/`#repository_name`, which look up the target `Repository` using a *different* field, `repository.full_name`, independent of `repository.owner.login`: [5](#0-4) 

`Repository.from_github_repo_name` splits `full_name` on `/` to derive owner/name and performs a plain `find_by`, again with no cross-check against the field used for signature verification: [6](#0-5) 

`PushHandler` then acts on every matching stack: [7](#0-6) 

The binding that should hold is: **organization authenticated by the signature == organization whose repository/stack is written**. Before the attack, that equality is only accidentally true because GitHub always sends `repository.owner.login` and `repository.full_name` consistently. After the attacker's request, `repository.owner.login = "attacker-org"` (whose secret they know) while `repository.full_name = "victim-org/some-repo"` — the equality is broken, but the signature check still passes because it never inspects `full_name`.

### Impact Explanation
This is a cross-repository/cross-organization write inside a single shared Shipit instance hosting multiple GitHub organizations (a documented, supported configuration where each org has its own `app_id`/`installation_id`/`webhook_secret`). An org whose GitHub App/webhook secret is known to an unprivileged attacker (e.g. because the attacker administers that org's own low-trust GitHub App installation) can forge webhooks that:
- Trigger `stack.sync_github` on a victim organization's stack via `PushHandler`, forcing unauthorized GitHub sync/state changes on stacks the attacker has no GitHub write access to.
- Create `Status` records, close/label/open pull-request state, or otherwise mutate `Stack`/`ReviewStack`/`Commit` state belonging to a repository the attacker does not own, via `StatusHandler`, `CheckSuiteHandler`, and the `PullRequest::*` handlers, all of which share the same `Handler#repository_name` resolution.

This falls under the "cross-repository writes" Critical impact category defined in scope, since the write boundary crossed is organizational/repository ownership, not merely stale cache data.

### Likelihood Explanation
Likelihood is bounded by the precondition that the attacker must know a webhook secret for *some* organization already configured on the shared Shipit instance (per `docs/setup.md`'s "Using Multiple Github Applications" pattern) — but crucially this does not require any Shipit session, `ApiClient` token, or privileged account on the *victim* organization. Any organization admin/operator that sets up their own GitHub App integration against a shared Shipit deployment inherently knows their own webhook secret, and nothing in `WebhooksController` prevents them from using it to target a different org's `repository.full_name`.

### Recommendation
In `WebhooksController#verify_signature` (or in `Handler#repository_name`), after resolving `repository_owner` for signature verification, assert that it matches the owner segment of `payload.dig('repository', 'full_name')` (and any other org identifier used later, e.g. by `MembershipHandler`) before dispatching to handlers; reject the request (422) on mismatch.

### Proof of Concept
1. Shipit is configured with two organizations, `attacker-org` and `victim-org`, each with its own GitHub App and `webhook_secret` (per the multi-org config pattern).
2. Attacker knows `attacker-org`'s webhook secret (they administer that GitHub App).
3. Attacker crafts a `push` webhook JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/private-repo"
  }
}
```
4. Attacker computes `X-Hub-Signature: sha1=HMAC(attacker-org secret, body)` and POSTs to `/webhooks`.
5. `verify_signature` resolves `repository_owner = "attacker-org"`, fetches `attacker-org`'s `GitHubApp`, and the HMAC check passes. [8](#0-7) 
6. `PushHandler#process` resolves `repository_name = "victim-org/private-repo"` and runs `stack.sync_github` on `victim-org`'s stack. [9](#0-8) [5](#0-4)

```ruby
    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
