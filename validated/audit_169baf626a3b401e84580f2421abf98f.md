### Title
`do_claim_revenue` discards rounding-down remainder as unrecoverable dust when the last InstaPool contributor claims - ([File: substrate/frame/broker/src/dispatchable_impls.rs])

### Summary
`pallet-broker`'s `do_claim_revenue` (invoked via the public, permissionless `claim_revenue` extrinsic) computes each contributor's payout share using rounding-down integer division: `p = total_payout * contributed_parts / private_contributions`. When the claiming contributor is the last one able to claim from a given `InstaPoolHistoryRecord` (i.e., `private_contributions` reaches zero after their claim), the code discards the `remaining_payout` (the rounding-down remainder) instead of paying it out, and deletes the storage record. The transferred `Balance` behind that dust remains permanently stuck in the Broker pallet account with no code path left to reclaim it, matching the exact bug class described in the report: rounding-down division on payment splitting leaves token units behind, and the recommended fix is to give the last/final claimant the full remaining amount instead of a rounded-down proportional share.

### Finding Description
`InstaPoolContribution` entries are created via the permissionless `pool`/`do_pool` call [1](#0-0) , and revenue is claimed via `do_claim_revenue`, reachable from the public `claim_revenue` extrinsic [2](#0-1) .

For each timeslice `r` in the claimed range, the code fetches `InstaPoolHistory::<T>::get(r)` which stores `private_contributions` (total remaining unclaimed contribution parts for that timeslice) and `maybe_payout` (total revenue payout for that timeslice) [3](#0-2) . The contributor's share is computed as:

```rust
let p = total_payout
    .saturating_mul(contributed_parts.into())
    .checked_div(&pool_record.private_contributions.into())
    .unwrap_or_default();
``` [4](#0-3) 

This is integer (rounding-down) division. The remainder is computed as `remaining_payout = total_payout.saturating_sub(p)`. If `remaining_payout` is non-zero **and** `pool_record.private_contributions` (after being reduced by the current claim) is still greater than zero, the remainder is correctly carried forward for the next claimant via `InstaPoolHistory::<T>::insert`. But if `private_contributions` has been reduced to zero (i.e., this is the last outstanding claim for that timeslice), the `else` branch fires and the record is simply removed — the non-zero `remaining_payout` dust is dropped on the floor, never added to `payout`, and never transferred to anyone:
```rust
if !remaining_payout.is_zero() && pool_record.private_contributions > 0 {
    pool_record.maybe_payout = Some(remaining_payout);
    InstaPoolHistory::<T>::insert(r, &pool_record);
} else {
    InstaPoolHistory::<T>::remove(r);
}
``` [5](#0-4) 

Because the `InstaPoolHistoryRecord` for timeslice `r` is deleted in this branch, there is no remaining state that references the leftover balance; the tokens corresponding to that dust remain in `Self::account_id()` (the Broker pallet account) but are permanently unreachable by any dispatchable — they are neither refunded to the last claimant nor to any treasury/burn destination. This is the same rounding-down "leftover funds stuck in contract" class described in the report; the fix suggested there ("give the last payment the full remaining amount instead of computing it via rounded division") directly maps onto giving the final claimant `total_payout` (not the rounded `p`) whenever `private_contributions` reaches zero.

### Impact Explanation
Each occurrence permanently locks a small amount of native/relay currency inside the Broker pallet's account, unbacked by any claimable entitlement — effectively a slow, permanent loss of funds for legitimate InstaPool contributors and an unaccounted discrepancy between total issuance the pallet is holding versus what is claimable. It requires no privileged role or malicious input; it is triggered purely by the natural arithmetic of dividing `total_payout` across parts that don't evenly divide it, which is a common/likely occurrence given `private_contributions` and `contributed_parts` are arbitrary core-mask bit counts. This is a Low/Medium severity fund-locking issue (per-instance loss is bounded by rounding error size, i.e., less than `private_contributions` planck units), not a large-scale theft or unbacked-issuance bug.

### Likelihood Explanation
High likelihood of occurrence in normal operation: any time `total_payout * contributed_parts` is not evenly divisible by `private_contributions` (which is the common case for arbitrary integer contributions), and the claiming contributor happens to be the last one to claim from that timeslice's pool record, the remainder is silently dropped. No attacker action, timing, or privilege is required — it is a deterministic consequence of normal, permissionless `claim_revenue` usage by legitimate InstaPool contributors.

### Recommendation
When `pool_record.private_contributions` reaches zero after the current claim (i.e., this is the final outstanding contributor for timeslice `r`), pay out the *full* `total_payout` to the current claimant instead of the rounded-down `p`, mirroring the pattern already used elsewhere in the codebase (e.g., `nomination-pools` migration code explicitly pays "leftover" dust to the depositor rather than losing it, see [6](#0-5) ). Concretely, change:
```rust
if !remaining_payout.is_zero() && pool_record.private_contributions > 0 {
    ...
} else {
    InstaPoolHistory::<T>::remove(r);
}
```
to accrue `remaining_payout` into `payout` whenever `private_contributions == 0`, before removing the record.

	pub(crate) fn do_claim_revenue(
		mut region: RegionId,
		max_timeslices: Timeslice,
	) -> DispatchResult {
		ensure!(max_timeslices > 0, Error::<T>::NoClaimTimeslices);
		let mut contribution =
			InstaPoolContribution::<T>::take(region).ok_or(Error::<T>::UnknownContribution)?;
		let contributed_parts = region.mask.count_ones();

		Self::deposit_event(Event::RevenueClaimBegun { region, max_timeslices });

		let mut payout = BalanceOf::<T>::zero();
		let last = region.begin + contribution.length.min(max_timeslices);
		for r in region.begin..last {
			region.begin = r + 1;
			contribution.length.saturating_dec();

			let Some(mut pool_record) = InstaPoolHistory::<T>::get(r) else { continue };
			let Some(total_payout) = pool_record.maybe_payout else { break };
			let p = total_payout
				.saturating_mul(contributed_parts.into())
				.checked_div(&pool_record.private_contributions.into())
				.unwrap_or_default();

			payout.saturating_accrue(p);
			pool_record.private_contributions.saturating_reduce(contributed_parts);

			let remaining_payout = total_payout.saturating_sub(p);
			if !remaining_payout.is_zero() && pool_record.private_contributions > 0 {
				pool_record.maybe_payout = Some(remaining_payout);
				InstaPoolHistory::<T>::insert(r, &pool_record);
			} else {
				InstaPoolHistory::<T>::remove(r);
			}
			if !p.is_zero() {
				Self::deposit_event(Event::RevenueClaimItem { when: r, amount: p });
			}
		}

		if contribution.length > 0 {
			InstaPoolContribution::<T>::insert(region, &contribution);
		}
		// The steps above removed the contribution and reduced the stored payouts. If the
		// transfer fails, the error must revert them. The storage changes and the payment
		// must both happen, or neither.
		T::Currency::transfer(&Self::account_id(), &contribution.payee, payout, Expendable)?;
		let next = if last < region.begin + contribution.length { Some(region) } else { None };
		Self::deposit_event(Event::RevenueClaimPaid {
			who: contribution.payee,
			amount: payout,
			next,
		});
		Ok(())
	}

/// A per-timeslice bookkeeping record for tracking Instantaneous Coretime Pool activity and
/// making proper payments to contributors.
#[derive(Encode, Decode, Clone, Default, PartialEq, Eq, Debug, TypeInfo, MaxEncodedLen)]
pub struct InstaPoolHistoryRecord<Balance> {
	/// The total amount of Coretime (measured in Core Mask Bits minus any contributions which have
	/// already been paid out.
	pub private_contributions: CoreMaskBitCount,
	/// The total amount of Coretime (measured in Core Mask Bits contributed by the Polkadot System
	/// in this timeslice.
	pub system_contributions: CoreMaskBitCount,
	/// The payout remaining for the `private_contributions`, or `None` if the revenue is not yet
	/// known.
	pub maybe_payout: Option<Balance>,
}
pub type InstaPoolHistoryRecordOf<T> = InstaPoolHistoryRecord<BalanceOf<T>>;
