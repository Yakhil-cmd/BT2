### Title
Accrual overflow in `scaled_to_original` permanently freezes a whale market before the borrow-index cap engages - (File: common/src/rates/scaling.rs)

### Summary
Every pool mutation runs `interest::global_sync` → `accrue_step`, whose first operation is `scaled_to_original(borrowed, borrow_index)` — a `Ray::mul` that panics with `MathOverflow` when `borrowed × borrow_index` exceeds `i128::MAX`. `update_borrow_index` clamps the index at `MAX_BORROW_INDEX_RAY = 1e36`, but the *value* product hits `i128::MAX` (~1.7e38) when the index is only ~170× on a billion-whole-token market. Once crossed, every verb that accrues first — `supply`, `withdraw`, `borrow`, `repay`, `liquidate`, `clean_bad_debt`, `update_indexes` — reverts, permanently freezing all supplier funds in that market. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` unscale multiplies `borrowed` (raw RAY-scaled shares) by `borrow_index` (RAY-scaled index) before computing utilization, the borrow rate, and the new index. The multiply panics on overflow rather than saturating. The index cap `MAX_BORROW_INDEX_RAY` is intended to bound index growth, but it only clamps the index itself — it does not bound the product `borrowed × index`. For a market with ~1e9 whole tokens at 18 decimals (`borrowed ≈ 1e36` raw ray), the product overflows when `borrow_index` exceeds ~170× RAY, far below the 1e36 cap. The test `a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap` demonstrates the freeze: `update_indexes`, `withdraw`, and `repay` all revert with `MathOverflow` while `borrow_index < MAX_BORROW_INDEX_RAY`. [4](#0-3) 

An unprivileged attacker can construct this state: supply a very large amount to a high-decimals market, post collateral elsewhere, borrow to near-100% utilization (the harness uses 98% on the steep XLM curve), and simply let the position sit — utilization stays pinned near max because nobody can repay or liquidate once the cliff is close, and the rate curve is steepest exactly there. After a few years of accrual the market is unrecoverable: no repay, no withdraw, no liquidation, no `clean_bad_debt`, no `recapitalize` (which also syncs). [5](#0-4) 

### Impact Explanation
Permanent freezing of all supplier funds in the affected market and permanent freezing of the borrower's collateral positions (they cannot be liquidated or exited through that market's verbs). The collateral leg is also impaired: a liquidate call accrues every touched market, so the frozen debt market blocks liquidation of the position entirely. This maps to the accepted impact classes "permanent freezing of funds" and "temporary freezing of funds" escalating to permanent since no recovery path exists — the panic is in the read path of accrual itself, before any state write or cap check. [6](#0-5) 

### Likelihood Explanation
Requires (a) a listed market whose total borrowed raw-ray value is large enough that `borrowed × index` can reach 1.7e38 — i.e., raw borrowed ≥ ~1e36, achievable only on high-decimals or very large TVL markets; and (b) sustained near-max utilization for a multi-year accrual period on a steep rate curve. Both are reachable by a single unprivileged address through `supply` + `borrow`, and the cliff is self-reinforcing: as utilization drifts up (debt compounds faster than supply), rates steepen, and once near the cliff no counterparty action can reverse it. The repository's own harness proves reachability within the modeled 40-year bound at 98% utilization on the steep segment. No privileged action, leaked key, or oracle manipulation is needed. [7](#0-6) 

### Recommendation
Make accrual fail-safe at the value ceiling instead of panicking. Options: saturate `scaled_to_original` inside `accrue_step`'s utilization read (utilization is already clamped to ≤1.0, so an over-MAX value only needs to read as "100%+"), clamp the pre-clamp `borrow_index × factor` product, or cap accrued interest at the point where the debt value saturates `i128::MAX` and mark the market frozen-for-accrual while still permitting repay/withdraw with the last good index. The narrowest fix: in `accrue_step`, compute `borrowed_original` via a saturating multiply (`mul_div_floor_saturating`) since only the utilization ratio is consumed from it, so the panic can never block exits. [8](#0-7) [9](#0-8)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
    std::println!(
        "ray-value cliff reached after {years} years at 98 percent utilization on the XLM curve; last index x{:.1}",
        last.borrow_index as f64 / RAY as f64
    );
```
