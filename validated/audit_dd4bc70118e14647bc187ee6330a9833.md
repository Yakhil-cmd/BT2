### Title
CCMenu API endpoint bypasses per-stack `ApiClient` scoping, allowing a stack-scoped token to read any stack - ([File: app/controllers/shipit/api/ccmenu_controller.rb])

### Summary
`Shipit::Api::BaseController` scopes which stacks a token may touch via `current_api_client.stack_id`, but `Shipit::Api::CCMenuController` overrides the `stack` lookup with an unscoped query, breaking that binding.

### Finding Description
`Shipit::Api::BaseController#stacks` restricts the set of visible stacks to the one the `ApiClient` is bound to when `stack_id` is present on the client record: [1](#0-0) 
This is the binding: `ApiClient#stack_id` (the stack the token authorizes) must equal the stack that the resolved `stack` object touches.

`Shipit::Api::CCMenuController` overrides `#stack` and calls `Stack.from_param!(params[:stack_id])` directly, completely bypassing the `stacks` scoping helper: [2](#0-1) 

Because `require_permission :read, :stack` only checks the `permissions` array via `ApiClient#check_permissions!` and never checks `stack_id`: [3](#0-2) [4](#0-3) 
a client that only holds `read:stack` and is scoped to a single stack (e.g. the `here_come_the_walrus` fixture, `stack: shipit`) can supply any `stack_id` in the CCMenu request URL and successfully read that other stack's data. [5](#0-4) 

This is exactly the "a stack a token authorises versus a stack it touches" binding class: before the request, `ApiClient#stack_id == "shipit"` while the URL param requests a different stack; after the request, the controller serves data for the URL's stack rather than enforcing equality with `ApiClient#stack_id`.

The sibling `Shipit::Api::StacksController` correctly relies on the inherited scoped `stack`/`stacks` helpers (it does not override them), confirming `CCMenuController`'s override is the deviation. [6](#0-5) 

### Impact Explanation
This matches the High-severity bucket "unauthenticated read of stack state, task streams or deploy output": a stack-scoped API token, intended by its creator (e.g. via `CCMenuUrlController`, which also derives the token per-stack usage) to only view one stack, can be used to enumerate/read the deploy status (name, last build status/label/time, deploy URL) of every stack in the Shipit instance, including stacks the token holder was never granted access to. [7](#0-6) 

### Likelihood Explanation
Exploitation only requires possessing any valid `read:stack` API token (even one deliberately scoped to a single stack) and knowledge/guessing of another stack's `stack_id` (owner/name/environment), which is often predictable or discoverable. No privileged account or session is required beyond the pre-existing token — consistent with the rule set's requirement that the analog not need a fresh privileged credential beyond what's already assumed available (an existing, narrowly-scoped `ApiClient` token).

### Recommendation
Have `Shipit::Api::CCMenuController#stack` reuse the inherited, scope-aware `stacks` helper (i.e. `stacks.from_param!(params[:stack_id])`) instead of querying `Stack` directly, so the `ApiClient#stack_id` binding is enforced identically to every other API controller.

### Proof of Concept
1. Create/obtain an `ApiClient` scoped to stack A with only `read:stack` permission (mirrors fixture `here_come_the_walrus`, `stack: shipit`).
2. Compute `client.authentication_token`.
3. Request `GET /api/stacks/<owner>/<repo-B>/<env-B>/ccmenu?token=<token>` for stack B, a stack the client was never scoped to.
4. Observe `200 OK` with stack B's deploy/build XML data returned, because `CCMenuController#stack` resolves `Stack.from_param!(params[:stack_id])` unconditionally rather than through `stacks` (which would raise/`Stack.none` for out-of-scope IDs), as shown by contrasting `app/controllers/shipit/api/base_controller.rb:74-80` with `app/controllers/shipit/api/ccmenu_controller.rb:27-31`.

```ruby
# frozen_string_literal: true

module Shipit
  module Api
    class StacksController < BaseController
      require_permission :read, :stack, only: %i[index show]
      require_permission :write, :stack, only: %i[create update destroy]

      params do
        accepts :repo_owner, String
        accepts :repo_name, String
      end
      def index
        @stacks = stacks
        if params[:repo_owner] && params[:repo_name]
          full_repo_name = [repo_owner, repo_name].join('/')
          @stacks = if (repository = Repository.from_github_repo_name(full_repo_name))
                      stacks.where(repository:)
                    else
                      Stack.none
                    end
        end
        render_resources(@stacks)
      end
```

```ruby
# frozen_string_literal: true

require 'uri'

module Shipit
  class CCMenuUrlController < ShipitController
    def fetch
      uri = URI(api_stack_ccmenu_url(stack_id: stack.to_param))
      uri.query = { 'token' => client.authentication_token }.to_query
      render(json: { ccmenu_url: uri.to_s })
    end

    private

    def client
      @client ||= ApiClient.create_with(permissions: %w[read:stack])
                           .find_or_create_by!(creator: current_user, name: 'CCMenu Client')
    end

    def stack
      @stack ||= Stack.from_param!(params[:stack_id])
    end
  end
end
```
