### Title
Unauthenticated `ServiceChainReceiptResponseMsg` Allows Any P2P Peer to Forge Anchoring Confirmations and Corrupt SubBridge State — (`node/sc/sub_bridge_handler.go`)

### Summary

Any peer that can connect to the SubBridge's bridge P2P port and pass the trivially-satisfiable handshake can send a forged `ServiceChainReceiptResponseMsg`. The handler `handleParentChainReceiptResponseMsg` applies no per-message ECDSA signature check and no receipt status validation. It directly calls `WriteReceiptFromParentChain` and `WriteAnchoredBlockNumber` with attacker-controlled data, then removes the corresponding anchoring transaction from the `BridgeTxPool`, permanently suppressing its retry.

### Finding Description

**Entry point — P2P handshake (no identity authentication):**

The bridge P2P handshake in `readStatus` only validates `NetworkId` and `ProtocolVersion`: [1](#0-0) 

`RegisterNewPeer` adds one more check — the peer's self-reported `chainID` must match the configured parent chain ID: [2](#0-1) 

Both values (`NetworkId`, `ProtocolVersion`, `chainID`) are public. An attacker who knows them can complete the handshake and become a registered bridge peer.

**Pending tx hash disclosure:**

Once registered, the SubBridge immediately broadcasts all pending anchoring tx hashes to every connected peer via `broadcastServiceChainReceiptRequest`: [3](#0-2) 

The attacker now knows the exact `TxHash` values of pending anchoring transactions.

**Unauthenticated receipt handler:**

`handleParentChainReceiptResponseMsg` decodes the incoming `[]*types.ReceiptForStorage` and passes them directly to `writeServiceChainTxReceipts` with no signature or authenticity check: [4](#0-3) 

**State corruption in `writeServiceChainTxReceipts`:**

For each receipt whose `TxHash` matches a pending pool entry, the function:
1. Calls `WriteReceiptFromParentChain` — writes a false receipt to the child chain DB keyed by the anchored block hash.
2. Calls `WriteAnchoredBlockNumber` — persistently advances the anchored block number in the DB.
3. Calls `RemoveTx` — removes the anchoring tx from the pool, preventing any legitimate retry. [5](#0-4) 

There is no check on `receipt.Status`. The `ReceiptForStorage` struct carries a `Status` field (lines 96–106 of `blockchain/types/receipt.go`), but `writeServiceChainTxReceipts` ignores it entirely. [6](#0-5) 

**Persistent DB writes:**

`WriteAnchoredBlockNumber` writes to `chainDB` unconditionally (subject only to the monotonicity guard, which the attacker can satisfy by using the correct block number embedded in the anchoring tx data): [7](#0-6) 

`WriteReceiptFromParentChain` writes to `bridgeServiceDB`: [8](#0-7) 

### Impact Explanation

- **Persistent anchoring state corruption**: The SubBridge records a false "anchored block number" and a false parent-chain receipt. Downstream consumers (e.g., service chain clients querying `GetReceiptFromParentChain`) receive fabricated confirmation data.
- **Anchoring tx silently dropped**: The anchoring tx is removed from `BridgeTxPool` and never actually executed on the parent chain. The service chain data for the affected block is never truly anchored, but the SubBridge believes it is.
- **No self-healing**: Because `WriteAnchoredBlockNumber` is monotonically increasing and the tx is gone from the pool, the SubBridge will not re-anchor the affected block. The corruption is durable.

### Likelihood Explanation

The bridge P2P port is a separate listener. An attacker needs only the parent chain's `NetworkId`, `ProtocolVersion`, and `chainID` — all public. No key material, validator access, or operator privilege is required. The attacker does not need to MitM the legitimate MainBridge; they only need to connect as an additional peer before or alongside it.

### Recommendation

1. **Authenticate receipt responses**: Add a per-message ECDSA signature (signed by the MainBridge operator key) to `ServiceChainReceiptResponseMsg`. Verify the signature in `handleParentChainReceiptResponseMsg` before processing.
2. **Check `receipt.Status`**: In `writeServiceChainTxReceipts`, reject receipts where `receipt.Status != types.ReceiptStatusSuccessful` before writing any state.
3. **Restrict bridge peer connections**: Enforce an allowlist of trusted MainBridge node IDs at the P2P layer, rejecting connections from unknown peers before the handshake completes.

### Proof of Concept

```
1. Attacker node starts with matching NetworkId, ProtocolVersion, and parent chainID.
2. Attacker connects to SubBridge bridge P2P port and completes handshake.
3. SubBridge calls broadcastServiceChainReceiptRequest → attacker receives pending anchoring tx hashes [H1, H2, ...].
4. Attacker sends ServiceChainReceiptResponseMsg containing:
     []*ReceiptForStorage{ { TxHash: H1, Status: 1, ... } }
5. handleParentChainReceiptResponseMsg decodes without verification → writeServiceChainTxReceipts runs.
6. BridgeTxPool.Get(H1) returns the pending anchoring tx.
7. WriteReceiptFromParentChain(blockHash, forgedReceipt) → false receipt written to bridgeServiceDB.
8. WriteAnchoredBlockNumber(blockNum) → anchored block number advanced in chainDB.
9. BridgeTxPool.RemoveTx(tx) → anchoring tx removed; no retry possible.
10. Assert: ReadAnchoredBlockNumber() returns the forged block number; the anchoring tx is gone from the pool; the parent chain never executed it.
```

func (sbh *SubBridgeHandler) writeServiceChainTxReceipts(bc *blockchain.BlockChain, receipts []*types.ReceiptForStorage) {
	for _, receipt := range receipts {
		txHash := receipt.TxHash
		if tx := sbh.subbridge.GetBridgeTxPool().Get(txHash); tx != nil {
			if tx.Type().IsChainDataAnchoring() {
				data, err := tx.AnchoredData()
				if err != nil {
					logger.Error("failed to get anchoring data", "txHash", txHash.String(), "err", err)
					continue
				}
				decodedData, err := types.DecodeAnchoringData(data)
				if err != nil {
					logger.Warn("failed to decode anchoring tx", "txHash", txHash.String(), "err", err)
					continue
				}
				sbh.WriteReceiptFromParentChain(decodedData.GetBlockHash(), (*types.Receipt)(receipt))
				sbh.WriteAnchoredBlockNumber(decodedData.GetBlockNumber().Uint64())
			}
			// TODO-Kaia-ServiceChain: support other tx types if needed.
			sbh.subbridge.GetBridgeTxPool().RemoveTx(tx)
		} else {
			logger.Trace("received service chain transaction receipt does not exist in sentServiceChainTxs", "txHash", txHash.String())
		}
		logger.Trace("received service chain transaction receipt", "anchoring txHash", txHash.String())
	}
}
