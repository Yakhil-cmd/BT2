### Title
Overflow in interest accrual permanently freezes an oversized market - (File: common/src/rates/scaling.rs)

### Summary
A market can grow until `scaled * index` exceeds the `i128` domain before either index ceiling engages. Once that happens, the mandatory accrual performed before pool mutations panics with `MathOverflow`, permanently blocking withdrawals, repayments, liquidations, recapitalization, and index updates for that market. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` computes both outstanding debt and supplied value by calling `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)`. [3](#0-2)  `scaled_to_original` performs a direct fixed-point multiplication and does not saturate or provide a recovery path when the represented value exceeds `i128::MAX`. [1](#0-0) 

Although `update_borrow_index` caps the index at `MAX_BORROW_INDEX_RAY`, it caps the computed index only after multiplying; separately, the total represented borrow or supply value can exceed `i128::MAX` while the index is still below its cap. [4](#0-3) [5](#0-4) 

Every pool mutation loads the market through `synced_market`, which invokes `interest::global_sync` before performing the requested operation. [6](#0-5)  `global_sync` chunks elapsed time and calls `accrue_step`, so the overflowing value conversion executes before repayment, withdrawal, seizure, or other corrective accounting can occur. [7](#0-6) [8](#0-7) 

The controller exposes permissionless `supply`, `borrow`, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, `flash_loan`, and related paths that route into these synchronized pool operations. [9](#0-8)  The pool’s explicit `update_indexes` path likewise loads each market and calls `global_sync`, so even an accrual-only rescue attempt reverts. [10](#0-9) 

The repository already contains a deterministic regression demonstrating the condition: a one-billion whole-token, 18-decimal market at 98% utilization eventually fails inside `scaled_to_original` with `MathOverflow` before `MAX_BORROW_INDEX_RAY` is reached, after which both withdraw and repay fail with the same error. [11](#0-10) 

### Impact Explanation
All token liquidity and user claims in the affected market become permanently inaccessible through the protocol: suppliers cannot withdraw, borrowers cannot repay, liquidators cannot liquidate, and recapitalization or index updates cannot repair the state because each path performs the same overflowing accrual first. [6](#0-5) [12](#0-11) [13](#0-12) 

Because the stored `last_timestamp` is not advanced until all chunks complete, a later transaction retries the same overflowing calculation rather than skipping over it. [7](#0-6)  This is permanent freezing of funds and protocol insolvency risk, not merely a temporary reject caused by unavailable liquidity or oracle data. [14](#0-13) 

### Likelihood Explanation
An unprivileged account can establish the required state through ordinary `supply` and `borrow` calls if the market admits sufficiently large amounts and sustained utilization. [15](#0-14) [16](#0-15)  Any later unprivileged call to `update_indexes` can trigger the overflow; no privileged action is required to cross the boundary. [17](#0-16) [18](#0-17) 

The economic prerequisite is substantial because the represented RAY value must exceed `i128::MAX`, and the demonstrated fixture uses one billion whole 18-decimal tokens at 98% utilization. [19](#0-18)  Nevertheless, admitted caps and index bounds do not prevent this state, so the issue is a reachable arithmetic boundary rather than an impossible input validation failure. [5](#0-4) 

### Recommendation
Prevent a market from entering a state whose index-scaled supply or debt cannot be represented, and add an explicit bounded-overflow recovery path before freezing all market operations. Relevant mitigations include:

- Enforce dynamic caps based on `i128::MAX / index` instead of only admission-time asset-domain caps. [20](#0-19) 
- Make `global_sync` advance safely at a capped index or stop accrual once the represented market value reaches a configured safety bound. [7](#0-6) 
- Allow debt repayment and withdrawal using saturated or bounded aggregate valuation where exact market totals overflow, while preserving exact per-position accounting within the representable domain. [21](#0-20) [12](#0-11) 
- Reject new supply or borrows when the post-operation `scaled * index` would exceed a conservative threshold below `i128::MAX`. [1](#0-0) 

### Proof of Concept
The production test demonstrates a complete reproduction:

```rust
let principal = 1_000_000_000 * 10i128.pow(18);
supply(BOB, "BIG18", principal);
borrow(ALICE, "BIG18", principal * 98 / 100);

// Advance ledger time until the next accrual exceeds i128::MAX.
update_indexes(["BIG18"]); // MathOverflow

// Every synchronized path now fails:
withdraw(BOB, "BIG18", 1); // MathOverflow
repay(ALICE, "BIG18", amount); // MathOverflow
```

The test asserts that `update_indexes` fails with `MATH_OVERFLOW`, that `borrow_index < MAX_BORROW_INDEX_RAY`, and that subsequent `withdraw` and `repay` calls hit the same error. [22](#0-21)

/// capped at `MAX_BORROW_INDEX_RAY`.

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// per market.
///
/// Always commits state so same-ledger simulation records the write footprint

        interest::global_sync(env, &mut cache);
        events::emit_market_state(env, cache.commit());

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);

pub(crate) fn accounting(env: &Env, action: &PoolAction) -> RepayOutcome {
    let (mut cache, position) = ops::load_leg(env, action);
    let amount = action.amount;

    let (burned, overpayment) = cache.resolve_repay(amount, position);
    let net_repay = amount
        .checked_sub(overpayment)

    assert_with_error!(
        env,
        net_repay == 0 || burned.raw() > 0,
        GenericError::RepayRoundsToZeroShares
    );

    let position = position.checked_sub(env, burned);
    cache.burn_debt(burned);

    cache.credit_cash(net_repay);

    let snapshot = cache.commit();
    let mutation = cache.position_mutation(position, net_repay);
