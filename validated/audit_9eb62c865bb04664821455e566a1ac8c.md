### Title
Stale delegate authorization is revived when account NFT returns to its prior owner - (File: contracts/controller/src/storage/account.rs)

### Summary
Delegate grants are keyed by account ID and stamped only with `granted_by`; an NFT transfer hides the grant but does not delete it. If the NFT later returns to that owner without an intervening `add_delegate` or `remove_delegate` write, the same stored delegate list becomes active again. The delegate can then call owner-level controller paths such as `withdraw` or `borrow` and select its own recipient.

### Finding Description
`get_delegates` returns a stored `DelegateGrant` whenever its `granted_by` equals the current NFT owner; ownership changes do not clear the entry [1](#0-0) . `remove_delegate` deletes a stale grant only when a different current owner invokes it [2](#0-1) . If no intervening owner performs that write, the old grant remains dormant rather than revoked.

Once the NFT returns to `granted_by`, `is_owner_or_delegate` again accepts a globally active position manager listed in that stale grant [3](#0-2) . `withdraw` uses that authorization and sends the pool payout to the optional `to` recipient, defaulting to the delegate [4](#0-3) . `borrow` does the same for borrowed funds [5](#0-4) .

### Impact Explanation
A stale delegate can withdraw transferable collateral or borrow up to the account’s post-operation solvency limit and direct the proceeds to itself. This permits theft of user collateral and can leave the returning owner with protocol debt. The mechanism is a lifecycle-authorization analog of use-after-free: security authority attached to the account survives logical revocation-by-transfer and is dereferenced again after ownership restoration.

### Likelihood Explanation
The attack requires:

1. The original owner previously granted an active position manager.
2. The NFT is transferred away.
3. No intervening owner overwrites or removes the delegate entry.
4. The NFT returns to the original owner while the delegate remains globally active.

These conditions are reachable through ordinary `transfer`/`transfer_from` and controller calls. The stale grant is only purged by explicit storage mutation; the NFT transfer itself does not touch controller delegate storage [6](#0-5) . Consequently, routine marketplace sale-and-return or accidental round-trip ownership can revive authority the returning owner reasonably believed ended at transfer.

### Recommendation
Version delegate grants with an ownership epoch incremented on every NFT transfer, or delete controller delegate state atomically during transfer notification/hook if feasible. Without a transfer hook, add an owner-authenticated `clear_delegates` path and mandate calling it during account reacquisition; preferably include an NFT transfer epoch or ownership nonce in `DelegateGrant` so a grant can never match a later ownership period.

### Proof of Concept
1. Alice owns account `A`, backed by account NFT token ID `A`.
2. Governance has activated contract `M` as a position manager.
3. Alice calls controller `add_delegate(caller=alice, account_id=A, delegate=M)`, storing `DelegateGrant { granted_by: alice, delegates: [M] }`.
4. Alice calls position NFT `transfer(from=alice, to=bob, token_id=A)`. The grant remains stored but is filtered out while Bob owns the token.
5. Bob neither calls `add_delegate` nor `remove_delegate`, so the stale entry remains.
6. Bob transfers token `A` back to Alice.
7. `M` calls controller `withdraw(caller=M, account_id=A, withdrawals=[(collateral_hub_asset, 0)], to=Some(M))`. `get_account` resolves Alice as owner, `get_delegates(A, alice)` returns `[M]`, and the withdrawal pays `M` after post-withdrawal solvency checks.
8. Alternatively, `M` calls `borrow(caller=M, account_id=A, borrows=[(debt_hub_asset, amount)], to=Some(M))`, receiving borrowed assets while leaving debt on Alice’s restored account.

/// Returns grants stamped by `owner`, or an empty list. Ownership changes
/// invalidate a previous owner's grants without deleting them.
pub(crate) fn get_delegates(env: &Env, account_id: u64, owner: &Address) -> Vec<Address> {
    get_user::<DelegateGrant>(env, &ControllerKey::Delegates(account_id))
        .filter(|grant| grant.granted_by == *owner)
        .map(|grant| grant.delegates)
        .unwrap_or_else(|| Vec::new(env))

pub(crate) fn is_owner_or_delegate(

    account_id: u64,
    caller: &Address,
    owner: &Address,

        return true;

}
