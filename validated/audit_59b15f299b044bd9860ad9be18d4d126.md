### Title
Admin-controlled `pause-admin` can permanently freeze all unclaimed signer rewards via `pause-rewards` - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`pox-5.clar` gives a single "restricted" `pause-admin` principal unilateral, irreversible power to call `pause-rewards`, which permanently blocks all signers/stakers from claiming their already-earned but unclaimed sBTC rewards, with no recovery path short of a hard fork. This mirrors the Napier `BaseLSTAdapter` pattern where a restricted admin role (via `setRebalancer`/`setTargetBufferPercentage`) can unilaterally and permanently prevent users from accessing assets that are rightfully theirs, causing a stuck/frozen-funds condition that is not "stealing" in the direct sense but is a permanent freeze caused solely by an admin action.

### Finding Description
`pox-5.clar` defines `pause-admin` as a settable role (`set-pause-admin`) and exposes a public function that is gated only by that one signer: [1](#0-0) 

The comment explicitly documents the finality of the action: "Permanently prevent signers from claiming rewards from this contract. This is one-way: there is no unpause function. Once paused, rewards can keep accumulating here, and recovery requires a hard fork." Once `rewards-paused` is set `true`, any reward-claim code path gated on this flag will revert for every staker/signer, indefinitely, with no on-chain remedy — an equality break between "rewards earned/accrued by a staker" and "rewards actually claimable/redeemable by that staker," permanently forced to zero, exactly analogous to the Napier scenario where the admin permanently starves the redemption path (there via `rebalancer = address(0)` + minimal buffer; here via `pause-rewards`).

The role transfer function `set-pause-admin` is similarly single-key admin-controlled: [2](#0-1) 

There is no time-lock, no multisig requirement enforced at the contract level, no minimum threshold, and no permissionless fallback (unlike the report's suggested remediation of making the analogous function "permissionless"). Any principal holding the `pause-admin` role at the moment of the call can invoke `pause-rewards()` and instantly and irrevocably strand every staker's/signer's earned-but-unclaimed sBTC rewards in the contract.

### Impact Explanation
This maps to a **Critical** impact category under the given rubric — "permanent freezing of staked STX or sBTC" — because the frozen asset is sBTC reward accrual owed to signers/stakers, and the freeze is total, permanent, and irreversible on-chain (explicitly documented as requiring a hard fork to recover). Unlike a temporary DoS, this is a one-way, unrecoverable state transition triggered by a single privileged call, with no way for any unprivileged staker to work around it, replenish it, or force a claim before/after the pause.

### Likelihood Explanation
Likelihood is bounded by trust in the `pause-admin` key/process; this is a single-signer/short-lived privileged capability with no on-chain checks-and-balances (no vote, no delay, no multisig enforced in Clarity), so likelihood depends entirely on the honesty and key-security of whoever holds `pause-admin` at any given time (which can be transferred without their predecessor's ability to block/veto). Because the finding requires the actor to *hold the pause-admin role* rather than any unprivileged account, this sits at the boundary of the "malicious restricted-admin" class the referenced Napier report was ultimately judged Medium for — the equivalent finding here would need the same "admin/pause-admin is RESTRICTED but not TRUSTED to be non-malicious" framing to be in-scope.

### Recommendation
- Add a time-locked or two-step process for invoking `pause-rewards` (e.g., a delay period during which stakers can force-claim outstanding rewards before the pause takes effect).
- Consider requiring a multisig/threshold signature for `pause-admin` actions rather than a single principal.
- Provide an on-chain recovery/emergency-claim path (e.g., a grace-period claim window) instead of relying solely on a hard fork for recovery.
- Alternatively, restrict `pause-rewards` to only apply prospectively (future accruals) while guaranteeing already-accrued reward balances remain claimable indefinitely.

### Proof of Concept
1. `pause-admin` (initially set via `POX5_BOOTSTRAP_ADMIN` per test helpers) calls `set-pause-admin` to consolidate/keep control, or is compromised. [3](#0-2) 
2. Signers/stakers accrue sBTC rewards over multiple reward cycles via normal staking/bonding operations in `pox-5.clar`.
3. `pause-admin` calls `pause-rewards()`: [4](#0-3) 
4. `rewards-paused` becomes permanently `true`; all subsequent and pending reward-claim transactions revert for every staker/signer with no path to reverse the flag on-chain.
5. Result: every staker's already-earned sBTC reward balance is permanently frozen in the contract — an unrecoverable loss of assets identical in effect to the Napier `BaseLSTAdapter` scenario, caused entirely by a single restricted-admin action.
