### Title
Webhook signature verification is scoped to `organization.login`/`repository.owner.login` while the mutated stack is chosen from a different field (`repository.full_name`), allowing a secret-less org's identity to authorize writes to any repository's stack - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/secret to check against using `repository_owner`, which falls back to `params.dig('organization', 'login')` when no `repository.owner.login` is present [1](#0-0) . `GitHubApp#verify_webhook_signature` returns `true` unconditionally when that selected app has no `webhook_secret` configured, i.e. it doesn't even check the HMAC in that case [2](#0-1) . Meanwhile, the actual repository whose stacks get mutated is derived from a completely independent field, `payload.dig('repository', 'full_name')`, read by `Handler#repository_name` and used by `PushHandler#process` to look up and sync stacks [3](#0-2) [4](#0-3) .

### Finding Description
The binding the system implicitly assumes is: `repository_owner (used to pick the verifying GitHub App)` == `owner(repository_name) (whose stack gets mutated)`. In fact these are read from two independently attacker-controlled JSON paths in the same POST body: `organization.login` (verification) vs `repository.full_name` (mutation target), and nothing ties them together.

Path traced:
1. `POST /webhooks` reaches `WebhooksController#create`, which runs `before_action :verify_signature` first [5](#0-4) .
2. `verify_signature` calls `Shipit.github(organization: repository_owner)`, and `repository_owner` reads `params.dig('repository','owner','login') || params.dig('organization','login')` [6](#0-5) . If the payload omits `repository` entirely (as the question's preconditions state) but includes an `organization.login` for a secret-less configured org, this resolves to that org.
3. `GitHubApp#verify_webhook_signature` short-circuits `return true unless webhook_secret` — for a secret-less org this means **no signature is checked at all**, and `verify_signature` passes regardless of the actual `X-Hub-Signature` header [7](#0-6) .
4. `create` then dispatches the full raw payload to handlers: `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` [8](#0-7) .
5. `PushHandler#process` computes `stacks` from `Repository.from_github_repo_name(repository_name)`, where `repository_name` is `payload.dig('repository', 'full_name')` — a field never inspected by `verify_signature` [3](#0-2) . For every matching, non-archived stack on that branch, it calls `stack.sync_github(expected_head_sha: params.after)` [4](#0-3) , which enqueues `GithubSyncJob`, fetching commits and appending them to that stack [9](#0-8) .

Exploit request: a body such as `{"organization": {"login": "secretless-org"}, "repository": {"full_name": "victim-org/victim-repo"}, "ref": "refs/heads/main", "after": "<sha>"}` with `X-Github-Event: push` and any (or no valid) `X-Hub-Signature`. Because `secretless-org` has no `webhook_secret` configured, step 3 passes trivially, and step 5 mutates `victim-org/victim-repo`'s stacks — a repository/org completely unrelated to the one that "authenticated" the request.

Why existing guards don't help: `drop_unhandled_event` only checks the event name is registered, not payload consistency [10](#0-9) . `ExplicitParameters` (`PushHandler`'s `params do ... end`) only validates presence of `ref`/`after`, not `repository.full_name` consistency with the verified owner [11](#0-10) . There is no code anywhere that compares `repository_owner` (verification identity) against `repository_name`'s owner (mutation identity).

### Impact Explanation
An attacker who can reach `POST /webhooks` (no session, no secrets required) can forge a `push` webhook naming any repository in `full_name`, as long as any org configured in `Shipit.github_apps` lacks a `webhook_secret`. This causes `GithubSyncJob` to fetch commits (via that victim stack's own configured GitHub API credentials) and write commit records/state onto the victim's stack — a cross-tenant write triggered by an unauthenticated, unverified payload. This matches the Critical category: "a payload for one repository mutating another's stack." Repeatable indefinitely and against any repository as long as one secret-less org exists in the deployment's config.

### Likelihood Explanation
Requires the specific precondition explicitly given: at least one org in `Shipit.github_apps` with no `webhook_secret` set (a fairly common misconfiguration/legacy-app scenario, and not enforced against by any validation in `lib/shipit/github_app.rb` or `lib/shipit.rb`). Given that precondition, the attack costs a single unauthenticated HTTP POST with no valid GitHub signature needed at all — trivial and fully repeatable.

### Recommendation
- Do not treat `webhook_secret.blank?` as automatic verification success; either require a webhook secret for every configured app, or reject webhooks for secret-less orgs unless the payload's actual `repository.owner.login` matches that org.
- Bind verification to the same repository identity used for mutation: derive `repository_owner` and the handler's `repository_name`/stack lookup from the same, single field (prefer `repository.full_name`/`repository.owner.login`), and reject payloads where `organization.login` (if present) doesn't match `repository.owner.login`.
- Reject webhooks lacking a `repository` key outright for events that mutate a specific repository's stacks (e.g. `push`), rather than falling back to `organization`.

### Proof of Concept
Minitest plan (no live GitHub):
1. In `test/models/shipit/webhooks/handlers/push_handler_test.rb` or a new test, configure `Shipit.github_apps` with two orgs: `"secretless-org"` (no `webhook_secret`) and `"victim-org"` (has a `webhook_secret`), and create a `Stack`/`Repository` for `victim-org/victim-repo`.
2. Assert the equality is violated:
   ```ruby
   payload = {
     "organization" => { "login" => "secretless-org" },
     "repository" => { "full_name" => "victim-org/victim-repo" },
     "ref" => "refs/heads/main",
     "after" => victim_sha
   }
   controller_repo_owner = payload.dig('repository','owner','login') || payload.dig('organization','login')
   handler_repo_name_owner = payload.dig('repository','full_name').split('/').first
   assert_not_equal controller_repo_owner, handler_repo_name_owner
   # controller_repo_owner == "secretless-org", handler_repo_name_owner == "victim-org"
   ```
3. Post to `/webhooks` with `X-Github-Event: push` and an invalid/absent `X-Hub-Signature`; assert response is `200 OK` (not `422`) because `secretless-org` has no secret.
4. Assert `Shipit::GithubSyncJob` was enqueued for the `victim-org/victim-repo` stack (e.g. via `assert_enqueued_with(job: Shipit::GithubSyncJob, args: [hash_including(stack_id: victim_stack.id)])`), proving cross-tenant mutation authorized by an unrelated org's (secret-less) identity.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

    def perform(params)
      @stack = Stack.find(params[:stack_id])
      expected_head_sha = params[:expected_head_sha]
      retry_count = params[:retry_count] || 0
      head_before_sync = spec_cache_target
      appended_commits = []

      handle_github_errors do
        new_commits, shared_parent = fetch_missing_commits { stack.github_commits }

        # Retry on Github eventual consistency: webhook indicated new commits but we found none
        if expected_head_sha && new_commits.empty? && !commit_exists?(expected_head_sha) &&
           retry_count < MAX_RETRY_ATTEMPTS
          GithubSyncJob.set(wait: RETRY_DELAY * retry_count).perform_later(params.merge(retry_count: retry_count + 1))
          return
        end

        stack.transaction do
          shared_parent&.detach_children!
          appended_commits = new_commits.map do |gh_commit|
            append_commit(gh_commit)
          end
          stack.lock_reverted_commits! if appended_commits.any?(&:revert?)
        end
      end
      sync_changed_nothing = appended_commits.empty? &&
                             spec_cache_target == head_before_sync &&
                             stack.cached_deploy_spec.present?
      return if sync_changed_nothing && !params[:force_spec_cache]

      CacheDeploySpecJob.perform_later(stack)
    end
