### Title
Webhook signature verification is bypassed for any GitHub org/app configured without `webhook_secret` - ([File: lib/shipit/github_app.rb])

### Summary
`Shipit::WebhooksController#verify_signature` delegates signature checking entirely to `GitHubApp#verify_webhook_signature`, which unconditionally returns `true` when the resolved app's config has no `webhook_secret`. An attacker who knows (or guesses) that an organization is configured this way can POST an unsigned, fully forged webhook body to `/webhooks` and have it processed by handlers such as `MembershipHandler`, mutating `Team`/`Membership` records.

### Finding Description
The broken binding: `verified == true` is claimed to imply "an authenticated org-specific HMAC was checked", but in `lib/shipit/github_app.rb:76-83`:
```
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```
`verified` becomes `true` whenever `webhook_secret` is blank/absent for the resolved `GitHubApp`, with zero bytes of `message` or `signature` ever compared. `webhook_secret` is set from `@config[:webhook_secret].presence` in the constructor (`lib/shipit/github_app.rb:50`) — if the operator's `github` secrets entry for that organization omits `webhook_secret`, this is `nil`, and the guard clause returns `true` for literally any signature (including `nil`).

Path in `app/controllers/shipit/webhooks_controller.rb`:
1. `repository_owner` (line 61) reads `params.dig('organization', 'login')` from the raw attacker-controlled JSON body when no `repository` key is present.
2. `verify_signature` (line 24) calls `Shipit.github(organization: repository_owner)` which resolves a `GitHubApp` for that org via `github_app_config` (`lib/shipit.rb:196-200`), then calls `verify_webhook_signature(header, raw_post)`.
3. If that org's config lacks `webhook_secret`, `verified` is `true` unconditionally, `head(422)` is skipped, and `create` runs `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }`.
4. For `X-Github-Event: membership`, `MembershipHandler#process` (`app/models/shipit/webhooks/handlers/membership_handler.rb:22-43`) runs `find_or_create_team!` → `Team.find_or_create_by!(github_id: params.team.id)` and `team.add_member`/`team.members.delete`, all sourced from the unauthenticated body.

No other guard intervenes: `drop_unhandled_event` only checks the event name is registered; `ExplicitParameters` (the `params do ... end` schema in the handler) validates shape/types, not provenance; there is no `force_github_authentication`, `current_user`, or session check on this controller at all — it's designed to be hit anonymously by GitHub, secured only by the signature check that this code path defeats.

This is not a divergence between "should validate" and "did not validate" caused by a coding slip elsewhere — it is the literal, intended behavior of `verify_webhook_signature`, which anyone with read access to `lib/shipit/github_app.rb` can see returns `true` for orgs with no configured secret.

### Impact Explanation
Any organization entry in Shipit's github secrets config that omits `webhook_secret` allows unauthenticated, fully forged webhooks for that org to be accepted and processed by any handler in `Shipit::Webhooks` (membership, push, pull_request, status, etc. — whatever is registered), not just membership. For the membership case specifically, an attacker can create arbitrary `Team` rows and add/remove arbitrary `User` records as team members purely by guessing/knowing an org name with no secret. Since `Shipit.github_teams` (`lib/shipit.rb:256-258`) is used for OAuth authorization gating (`lib/shipit.rb`), forging team membership can be a path to escalating a user into an authorized team — this crosses into authentication/authorization bypass territory (Critical, matching "authentication bypass (forged webhook ... accepted)"). The blast radius is scoped to whichever organizations are misconfigured without a secret, but is repeatable indefinitely and requires no credentials.

### Likelihood Explanation
Exploitability is entirely gated on operator configuration: it only fires if a `Shipit.github(organization: X)` entry exists with a missing/blank `webhook_secret`. Given multi-org GitHub App setups (`TOP_LEVEL_GH_KEYS`, `github_app_config`), and that `webhook_secret` is optional in the config schema (no validation forces its presence), this is a plausible, easy-to-hit misconfiguration — nothing prevents an operator from omitting it, and the code intentionally treats absence as "no verification needed" rather than "reject". Attacker cost is a single unauthenticated HTTP POST with a guessed org name; fully repeatable.

### Recommendation
Do not treat a missing `webhook_secret` as "verification passed." Either (a) require `webhook_secret` to be present for every configured organization at boot/config-validation time and raise if missing, or (b) change `verify_webhook_signature` to return `false` (reject) when `webhook_secret` is blank instead of `true`, forcing operators to explicitly opt into an "unsigned" mode if ever desired (and log/alert loudly if so).

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
