Based on my investigation, I found the closest analog to the reported "unauthorized fund transfer via arbitrary `from` parameter" bug class within `Jortegata/cli--020` (GitHub CLI): the `capiTransport.RoundTrip` in `pkg/cmd/agent-task/capi/client.go` attaches the user's Copilot/GitHub bearer token to **every** outgoing request on the shared `http.Client`, regardless of the request's destination host, unlike the analogous and properly host-scoped `AddAuthTokenHeader` in `api/http_client.go`.

### Title
Copilot bearer token attached to requests regardless of destination host, enabling token exfiltration via redirect - (File: pkg/cmd/agent-task/capi/client.go)

### Summary
The `gh agent-task` subsystem builds its Copilot API client by wrapping the user's shared `*http.Client` transport with `capiTransport`, whose `RoundTrip` unconditionally sets the `Authorization: Bearer <token>` header on **every** request that flows through that client, with no check that the request is actually destined for the Copilot API host.

### Finding Description
`NewCAPIClient` mutates the passed-in `httpClient.Transport` by wrapping it in `capiTransport`, and explicitly documents that "the provided HTTP client will be mutated for use with CAPI, so it should not be reused elsewhere" [1](#0-0) . Inside `RoundTrip`, the token is attached unconditionally before any host check: `req.Header.Set("Authorization", "Bearer "+ct.token)`, and only the Copilot-specific headers (`Copilot-Integration-Id`, `X-GitHub-Api-Version`) are gated on `req.URL.Host == ct.capiHost` [2](#0-1) .

This contrasts with the general-purpose GitHub API transport, `AddAuthTokenHeader`, which explicitly guards against sending the auth token to a different host after a redirect: `redirectHostnameChange = getHost(req) != getHost(req.Response.Request)` and only sets the header `if !redirectHostnameChange` [3](#0-2) . The corresponding test `TestHTTPClientRedirectAuthenticationHeaderHandling` confirms this host-scoping behavior is a deliberate security control on the general API client [4](#0-3) .

The CAPI client is constructed by wrapping the same `f.HttpClient()` instance used elsewhere for general GitHub API calls, via `capi.NewCAPIClient(httpClient, token, host, capiBaseURL)` [5](#0-4) . If a response served by `api.githubcopilot.com` (or the GitHub API, sharing the transport) returns an HTTP redirect (e.g. 301/302/307) to an attacker-influenced or third-party host, Go's default `http.Client` redirect handling will follow it and re-invoke `RoundTrip`, at which point `capiTransport` will still attach the `Authorization: Bearer <token>` header to the request going to the new (potentially attacker-controlled) host, since there is no host-equality check comparable to `AddAuthTokenHeader`'s.

### Impact Explanation
If exploited, this would leak the user's active GitHub/Copilot OAuth token to a host outside GitHub's control, enabling account takeover to the extent of the token's scopes. It is a direct, unprivileged, remote-attacker-triggerable credential exfiltration, matching the "token handling and host trust, HTTP client and redirects" category called out in the rules. The impact is bounded by the requirement that some server response along the CAPI/GitHub API path issue a redirect — this depends on server behavior not under the user's control, but such redirects are a normal HTTP feature and the `funcTripper`/`http.Client` machinery in this codebase elsewhere treats them as a real, tested threat vector (see `TestHTTPClientRedirectAuthenticationHeaderHandling`).

### Likelihood Explanation
Likelihood is moderate: it requires the Copilot API (or whatever endpoint the shared client is later used against) to emit a redirect to an off-host location, which is not something an arbitrary external attacker can directly force without also compromising or influencing that response (e.g., via a compromised CDN, open redirect on the API surface, or a malicious/misconfigured Copilot endpoint value returned by `resolveCapiURL`'s GraphQL response). It is a real code-level gap versus the hardened pattern already implemented once elsewhere in the same codebase, but I could not verify an end-to-end externally-triggerable exploitation path within the available context (e.g., confirmation that `api.githubcopilot.com` or GHE Copilot endpoints can be coerced into issuing a cross-host redirect).

### Recommendation
Add the same redirect/host-scoping guard used in `AddAuthTokenHeader` (`api/http_client.go`) to `capiTransport.RoundTrip` in `pkg/cmd/agent-task/capi/client.go`: only attach the `Authorization` header when the request's host equals `ct.capiHost` (or the original request host before any redirect), mirroring the `redirectHostnameChange` check, rather than setting it unconditionally for every request that flows through the shared transport.

### Proof of Concept
Not fully demonstrated end-to-end; based on static code review only. A reproduction would require: (1) constructing an `http.Client` via `capi.NewCAPIClient`, (2) pointing `capiBaseURL`/the initial request at a test server that responds with an HTTP redirect (301/302/307) to a second "attacker" test server, and (3) asserting that the "attacker" server receives the `Authorization: Bearer <token>` header — analogous to the existing `TestHTTPClientRedirectAuthenticationHeaderHandling` test pattern in `api/http_client_test.go`, which is notably absent for `capiTransport`.

func (ct *capiTransport) RoundTrip(req *http.Request) (*http.Response, error) {
	req.Header.Set("Authorization", "Bearer "+ct.token)

	// Since this RoundTrip is reused for both Copilot API and
	// GitHub API requests, we conditionally add the integration
	// ID only when performing requests to the Copilot API.
	if req.URL.Host == ct.capiHost {
		req.Header.Add("Copilot-Integration-Id", "copilot-4-cli")

		// Ensure we are not using GitHub API versions while targeting CAPI.
		req.Header.Set("X-GitHub-Api-Version", "2026-01-09")
	}
	return ct.rp.RoundTrip(req)
}

// AddAuthTokenHeader adds an authentication token header for the host specified by the request.
func AddAuthTokenHeader(rt http.RoundTripper, cfg tokenGetter) http.RoundTripper {
	return &funcTripper{roundTrip: func(req *http.Request) (*http.Response, error) {
		// If the header is already set in the request, don't overwrite it.
		if req.Header.Get(authorization) == "" {
			var redirectHostnameChange bool
			if req.Response != nil && req.Response.Request != nil {
				redirectHostnameChange = getHost(req) != getHost(req.Response.Request)
			}
			// Only set header if an initial request or redirect request to the same host as the initial request.
			// If the host has changed during a redirect do not add the authentication token header.
			if !redirectHostnameChange {
				hostname := ghauth.NormalizeHostname(getHost(req))
				if token, _ := cfg.ActiveToken(hostname); token != "" {
					req.Header.Set(authorization, fmt.Sprintf("token %s", token))
				}
			}
		}
		return rt.RoundTrip(req)
	}}
}

func TestHTTPClientRedirectAuthenticationHeaderHandling(t *testing.T) {
	var request *http.Request
	server := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		request = r
		w.WriteHeader(http.StatusNoContent)
	}))
	defer server.Close()

	var redirectRequest *http.Request
	redirectServer := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		redirectRequest = r
		http.Redirect(w, r, server.URL, http.StatusFound)
	}))
	defer redirectServer.Close()

	client, err := NewHTTPClient(HTTPClientOptions{
		Config: tinyConfig{
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(redirectServer.URL, "http://")): "REDIRECT-TOKEN",
			fmt.Sprintf("%s:oauth_token", strings.TrimPrefix(server.URL, "http://")):         "TOKEN",
		},
	})
	require.NoError(t, err)

	req, err := http.NewRequest("GET", redirectServer.URL, nil)
	require.NoError(t, err)

	res, err := client.Do(req)
	require.NoError(t, err)

	assert.Equal(t, "token REDIRECT-TOKEN", redirectRequest.Header.Get(authorization))
	assert.Equal(t, "", request.Header.Get(authorization))
	assert.Equal(t, 204, res.StatusCode)
}

func CapiClientFunc(f *cmdutil.Factory) func() (capi.CapiClient, error) {
	return func() (capi.CapiClient, error) {
		cfg, err := f.Config()
		if err != nil {
			return nil, err
		}

		httpClient, err := f.HttpClient()
		if err != nil {
			return nil, err
		}

		authCfg := cfg.Authentication()
		host, _ := authCfg.DefaultHost()
		token, _ := authCfg.ActiveToken(host)

		cachedClient := api.NewCachedHTTPClient(httpClient, time.Minute*10)
		capiBaseURL, err := resolveCapiURL(cachedClient, host)
		if err != nil {
			return nil, fmt.Errorf("failed to resolve Copilot API URL: %w", err)
		}

		return capi.NewCAPIClient(httpClient, token, host, capiBaseURL), nil
	}
