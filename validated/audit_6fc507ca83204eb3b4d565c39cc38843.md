### Title
`GitHubApp#verify_webhook_signature` returns `true` (bypassing signature verification) when no `webhook_secret` is configured for an organization, allowing unauthenticated forged webhooks - (File: lib/shipit/github_app.rb)

### Summary
`GitHubApp#verify_webhook_signature` short-circuits with `return true unless webhook_secret`, meaning any organization configured without a `webhook_secret` (documented as an "optional" setting) accepts any POST to `/webhooks` as authentic regardless of the `X-Hub-Signature` header. Combined with `WebhooksController#verify_signature`, this lets an unauthenticated attacker dispatch arbitrary webhook payloads (e.g. `push`, `pull_request`) for that org's repositories to the real handlers.

### Finding Description
The broken binding is: **"a request accepted by `verify_signature` implies the request body originated from GitHub"** — i.e. `verified == true` should imply `HMAC-SHA1(webhook_secret, raw_post) == signature`. This equality is violated whenever `webhook_secret` is blank/nil for the resolved organization.

Code path:
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-30`) resolves `github_app = Shipit.github(organization: repository_owner)` from the attacker-controlled `params.dig('repository','owner','login')` (`repository_owner`, line 59-62), then calls `github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)` and only rejects with `head(422)` if `verified` is falsy.
- `GitHubApp#verify_webhook_signature` (`lib/shipit/github_app.rb:76-83`):
```ruby
def verify_webhook_signature(signature, message)
  return true unless webhook_secret
  ...
end
```
If the resolved org's config has no `webhook_secret` (`@webhook_secret = @config[:webhook_secret].presence`, line 50), this immediately returns `true` without ever inspecting `signature` or `message`. No HMAC computation, no `X-Hub-Signature` header requirement.
- Control then proceeds to `WebhooksController#create` (line 10-15), which parses `request.raw_post` as JSON and dispatches to `Shipit::Webhooks.for_event(event)` handlers (e.g. push handler enqueuing `GithubSyncJob`, or PR/review-stack handlers), using entirely attacker-supplied JSON.

Existing guards do not prevent this:
- `drop_unhandled_event` only filters on `X-Github-Event` type, not authenticity.
- `verify_signature` itself is the exact control being bypassed by design of `verify_webhook_signature`'s early return.
- `repository_owner` is read straight from the untrusted JSON body before any authentication occurs, so the attacker fully controls which org's (secret-less) `GitHubApp` is used to "verify" the forged payload.
- There is no global fallback secret requirement; per-organization `webhook_secret` is optional per `docs/setup.md`, and `Shipit.github_app_config` raises only on completely unknown organizations, not on organizations with a blank secret.

Attacker request: `POST /webhooks` with header `X-Github-Event: push`, no `X-Hub-Signature` header, and a JSON body naming an org/repo whose `Shipit.github(organization:)` config has `webhook_secret` unset. The request is accepted as authentic and dispatched to real handlers.

### Impact Explanation
For any organization operators forgot to (or chose not to) set `webhook_secret`, an unauthenticated attacker can inject arbitrary, unsigned webhook events processed as genuine GitHub events — e.g. triggering `push` handling that enqueues `GithubSyncJob` for a stack, or driving PR/review-stack handler logic, with fully attacker-controlled JSON (commit SHAs, branch names, PR numbers, labels, etc.). This is a full authentication-bypass on the webhook ingress for that tenant, matching the "Critical: authentication bypass (forged webhook ... accepted)" category. Blast radius is scoped to organizations lacking a configured secret, but is complete and repeatable against any/all such orgs, and against every repository they own.

### Likelihood Explanation
Precondition is solely operator-side: the org's `webhook_secret` entry in Shipit config/secrets is nil/blank, which the code and docs explicitly allow ("optional"). No attacker secrets, sessions, or privileges are required — cost is a single unauthenticated HTTP POST, fully repeatable and scriptable against any repository under such an org.

### Recommendation
Do not allow an absent `webhook_secret` to bypass verification. Require `webhook_secret` to be present for any organization exposed to `/webhooks`, and fail closed (return `false`/422) when it is missing, e.g.:
```ruby
def verify_webhook_signature(signature, message)
  return false if webhook_secret.blank?
  ...
end
```
Additionally, treat `webhook_secret` as a mandatory configuration key (raise at boot/config-validation time if absent) rather than documenting it as optional.

### Proof of Concept
Minitest plan (no live GitHub):
```ruby
test "unsigned push webhook is accepted when org has no webhook_secret configured" do
  org = "no-secret-org"
  github_app = Shipit::GitHubApp.new(org, { app_id: 1, installation_id: 1, private_key: nil }) # no webhook_secret key
  Shipit.stubs(:github).with(organization: org).returns(github_app)

  payload = {
    repository: { owner: { login: org }, full_name: "#{org}/repo" },
    ref: "refs/heads/master",
    after: "deadbeef"
  }.to_json

  assert_enqueued_with(job: GithubSyncJob) do
    post shipit.github_webhooks_path,
      params: payload,
      headers: { "X-Github-Event" => "push", "Content-Type" => "application/json" }
      # deliberately no X-Hub-Signature header
  end

  assert_response :ok
end
```
Assertion on both sides of the binding: before fix, `github_app.verify_webhook_signature(nil, payload)` returns `true` (right side of "authenticated" equality is `true` despite no valid HMAC existing — left side, i.e. actual signature validity, is `false`), and the job is enqueued; after applying the recommended fix, `verify_webhook_signature` returns `false`, the controller responds `422`, and no job is enqueued.     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
