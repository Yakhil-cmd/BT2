### Title
Malicious `_to` Address Permanently Blocks KLAY Bridge Transfer and Locks Bridged Assets — (File: `contracts/service_chain/bridge/BridgeTransferKLAY.sol`)

---

### Summary

`BridgeTransferKLAY.handleKLAYTransfer()` sends native KAIA to a user-controlled `_to` address using a low-level `.call.value()` and hard-requires success. If `_to` is a contract that reverts on receiving KAIA, the entire transaction reverts on every operator attempt. Because the nonce is never consumed, the transfer is permanently uncompletable, the source-bridge KAIA is permanently locked, and the bridge's `lowerHandleNonce` / `recoveryBlockNumber` are frozen.

---

### Finding Description

In `BridgeTransferKLAY.handleKLAYTransfer()`, after all nonce-accounting state is written, the function performs a raw KAIA transfer to the caller-supplied `_to` address:

```solidity
// contracts/service_chain/bridge/BridgeTransferKLAY.sol  lines 81-99
_setHandledRequestTxHash(_requestTxHash);
handleNoncesToBlockNums[_requestedNonce] = _requestedBlockNumber;
_updateHandleNonce(_requestedNonce);

emit HandleValueTransfer(...);

(bool ok, ) = _to.call.value(_value)("");
require(ok, "handleKLAYTransfer: transfer failed");   // ← hard revert
```

Because `require(ok, ...)` causes the entire transaction to revert, **all preceding state writes are also rolled back**. Specifically:
- `handledRequestTx[_requestTxHash]` is never set to `true`
- `handleNoncesToBlockNums[_requestedNonce]` is never written
- `closedValueTransferVotes[_requestedNonce]` is never set to `true`
- `lowerHandleNonce` never advances past the stuck nonce

A user who calls `requestKLAYTransfer` on the source bridge and specifies `_to` as a contract whose `receive()` / fallback always reverts will cause every subsequent `handleKLAYTransfer` call by bridge operators to revert. There is no mechanism to skip or override a stuck nonce.

The `feeReceiver` path in `BridgeFee._payKLAYFeeAndRefundChange()` has the same pattern but is owner-controlled and therefore out of scope.

---

### Impact Explanation

1. **Permanent KAIA lock in source bridge.** The user's KAIA was transferred into the source bridge when `requestKLAYTransfer` was called. There is no refund path. If the destination transfer can never complete, that KAIA is permanently locked.

2. **Bridge nonce state frozen.** `lowerHandleNonce` is advanced only when `handleNoncesToBlockNums[i] > 0` for consecutive nonces. A stuck nonce at position N means `lowerHandleNonce` never advances past N, `recoveryBlockNumber` never advances past the block of nonce N−1, and `closedValueTransferVotes` entries for all subsequently processed nonces accumulate without being cleaned up (unbounded storage growth).

3. **Recovery mechanism degraded.** The SubBridge recovery scanner uses `recoveryBlockNumber` as its start block. With it frozen at block 1 (or the block of the last successfully processed nonce), the scanner re-scans the entire chain history on every recovery cycle, causing severe performance degradation.

---

### Likelihood Explanation

Any unprivileged user who initiates a KLAY bridge transfer can trigger this by specifying `_to` as:
- A contract they deploy with a reverting `receive()` function, or
- Any existing contract on the destination chain whose fallback reverts (e.g., a multisig, a proxy, or a contract that has been self-destructed and redeployed).

The `_to` address is freely chosen by the requester in `requestKLAYTransfer(_to, _value, _extraData)` and is faithfully forwarded to `handleKLAYTransfer` by the bridge operator without any validation that `_to` can accept KAIA.

---

### Recommendation

Mirror the pattern used in the external report's resolution: do not hard-require that the raw KAIA transfer to `_to` succeeds. Instead, either:

1. **Wrap KAIA to WKAIA before sending** — convert the KAIA to WKAIA (an ERC-20) and transfer the token, which cannot be blocked by a reverting `receive()`.
2. **Use a pull-payment pattern** — record the owed amount in a mapping and let `_to` claim it separately, so a reverting recipient cannot block nonce advancement.
3. **Soft-fail and mark the nonce as handled** — if the transfer to `_to` fails, emit a `TransferFailed` event, mark the nonce as handled, and allow the KAIA to be claimed later via a separate function, preventing the nonce from being permanently stuck.

---

### Proof of Concept

```
1. Deploy MaliciousReceiver on the destination chain:
   contract MaliciousReceiver { receive() external payable { revert(); } }

2. On the source chain, call:
   sourceBridge.requestKLAYTransfer{value: 1 ether}(
       address(MaliciousReceiver), 1 ether, ""
   );
   → Source bridge emits RequestValueTransfer(nonce=N, to=MaliciousReceiver, value=1e18)
   → Source bridge balance += 1 KAIA (locked)

   → MaliciousReceiver.receive() reverts

   → All state writes are rolled back; nonce N is unconsumed

4. Every subsequent operator retry produces the same revert.
   → handledRequestTx[txHash] remains false
   → lowerHandleNonce remains at N
   → recoveryBlockNumber remains frozen
   → 1 KAIA is permanently locked in the source bridge

    // _updateHandleNonce increases lower and upper handle nonce after the _requestedNonce is handled.
    function _updateHandleNonce(uint64 _requestedNonce) internal {
        if (_requestedNonce > upperHandleNonce) {
            upperHandleNonce = _requestedNonce;
        }

        uint64 limit = lowerHandleNonce + 200;
        if (limit > upperHandleNonce) {
            limit = upperHandleNonce;
        }

        uint64 i;
        for (i = lowerHandleNonce; i <= limit && handleNoncesToBlockNums[i] > 0; i++) {
            recoveryBlockNumber = handleNoncesToBlockNums[i];
            delete handleNoncesToBlockNums[i];
            delete closedValueTransferVotes[i];
        }
        lowerHandleNonce = i;
    }

// handleRequestValueTransferEvent handles the given request value transfer event.
func (bi *BridgeInfo) handleRequestValueTransferEvent(ev IRequestValueTransferEvent) error {
	var (
		tokenType                         = ev.GetTokenType()
		tokenAddr, from, to, contractAddr = ev.GetTokenAddress(), ev.GetFrom(), ev.GetTo(), ev.GetRaw().Address
		txHash                            = ev.GetRaw().TxHash
		valueOrTokenId                    = ev.GetValueOrTokenId()
		requestNonce, blkNumber           = ev.GetRequestNonce(), ev.GetRaw().BlockNumber
		extraData                         = ev.GetExtraData()
	)

	ctpartTokenAddr := bi.GetCounterPartToken(tokenAddr)
	// TODO-Kaia-Servicechain Add counterpart token address in requestValueTransferEvent
	if tokenType != KAIA && ctpartTokenAddr == (common.Address{}) {
		logger.Warn("Unregistered counter part token address.", "addr", ctpartTokenAddr.Hex())
		ctTokenAddr, err := bi.counterpartBridge.RegisteredTokens(nil, tokenAddr)
		if err != nil {
			return err
		}
		if ctTokenAddr == (common.Address{}) {
			return errors.New("can't get counterpart token from bridge")
		}
		if err := bi.RegisterToken(tokenAddr, ctTokenAddr); err != nil {
			return err
		}
		ctpartTokenAddr = ctTokenAddr
		logger.Info("Register counter part token address.", "addr", ctpartTokenAddr.Hex(), "cpAddr", ctTokenAddr.Hex())
	}

	bridgeAcc := bi.account

	bridgeAcc.Lock()
	defer bridgeAcc.UnLock()

	auth := bridgeAcc.GenerateTransactOpts()

	var handleTx *types.Transaction
	var err error

	switch tokenType {
	case KAIA:
		handleTx, err = bi.bridge.HandleKLAYTransfer(auth, txHash, from, to, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[KAIA], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC20:
		handleTx, err = bi.bridge.HandleERC20Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, extraData)
		if err != nil {
			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC20], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	case ERC721:
		uri := GetURI(ev)
		handleTx, err = bi.bridge.HandleERC721Transfer(auth, txHash, from, to, ctpartTokenAddr, valueOrTokenId, requestNonce, blkNumber, uri, extraData)

			return err
		}
		handleValueTransferLog(bi.onChildChain, handleVTmethods[ERC721], handleTx.Hash().String(), requestNonce, from, to, valueOrTokenId)
	default:
		logger.Error("Got Unknown Token Type ReceivedEvent", "bridge", contractAddr, "nonce", requestNonce, "from", from)
		return nil
	}

	bridgeAcc.IncNonce()

	bi.bridgeDB.WriteHandleTxHashFromRequestTxHash(txHash, handleTx.Hash())
	return nil
