### Title
Division by Zero in `consolidatedNode.Split` Causes Block Finalization Panic When Both Staking Amounts Are Zero — (`kaiax/staking/staking_info.go`)

### Summary

`consolidatedNode.Split()` divides by `totalAmount = cnAmountBig + clAmountBig`. When both `c.StakingAmount == 0` and `c.CLStakingInfo.CLStakingAmount == 0` while `c.CLStakingInfo != nil`, `totalAmount` is zero and the `big.Int.Div` call panics. This is reachable through the proposer reward path in `specWithProposerAndFunds` / `specWithProposerAndFundsFlex`, which call `cn.Split(proposer)` without any guard on the staking amounts.

### Finding Description

`consolidatedNode.Split` in `kaiax/staking/staking_info.go`:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)   // ← panics if totalAmount == 0
    cnAmount := big.NewInt(0).Sub(amount, clAmount)
    return cnAmount, clAmount
}
``` [1](#0-0) 

The only guard is `c.CLStakingInfo == nil`. There is no guard for the case where both staking amounts are zero.

**Callers with implicit guards (safe):**

- `assignStakingRewards` calls `cn.Split` only when `cnTotalStakingAmount > minStake`, so if `minStake > 0`, `StakingAmount > 0` and `totalAmount > 0`. [2](#0-1) 
- `assignStakingRewardsFlex` calls `cn.Split` only when `excessInt[cn.RewardAddr] > 0`, which implies `amount > threshold ≥ 0`, so `totalAmount > 0`. [3](#0-2) 

**Caller without a guard (vulnerable):**

`specWithProposerAndFunds` and `specWithProposerAndFundsFlex` call `cn.Split(proposer)` for the block proposer with no check on staking amounts:

```go
cnAmount, clAmount := cn.Split(proposer)
``` [4](#0-3) [5](#0-4) 

These functions are called from `getDeferredRewardFullKore` and `getDeferredRewardFullFlex`, which are invoked by `FinalizeState` every block. [6](#0-5) 

**Trigger condition:**

The governance parameter `reward.minimumstake` (`minStake`) is settable to `0`. When `minStake == 0`, a validator with `StakingAmount == 0` passes the qualification check (`StakingAmount >= minStake` → `0 >= 0`). If that validator also has a registered CL pool (`CLStakingInfo != nil`) with `CLStakingAmount == 0` (a valid on-chain state — a pool can be registered with zero balance), and is selected as proposer, `cn.Split(proposer)` is called with `totalAmount = 0`, causing a panic in `FinalizeState`. [7](#0-6) 

### Impact Explanation

A panic in `FinalizeState` aborts block finalization. In Go, an unrecovered panic crashes the goroutine/process. Every honest node attempting to finalize the same block will panic, causing a network-wide chain halt. No KAIA rewards are distributed for that block or any subsequent block until the node is restarted and the condition is resolved. This matches the allowed impact: **invalid state transition / persistent block processing failure on honest nodes**.

### Likelihood Explanation

Requires governance to set `minStake == 0` (a semi-trusted trigger, not a single privileged actor). Once `minStake == 0`, any validator with zero CNStaking and a registered-but-empty CL pool that is selected as proposer triggers the panic. The CL pool registration with zero balance is a valid on-chain state. Likelihood is low under normal governance but non-negligible if governance is compromised or misconfigured.

### Recommendation

Add a zero-total guard in `consolidatedNode.Split`:

```go
func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
    if c.CLStakingInfo == nil {
        return amount, big.NewInt(0)
    }
    var (
        cnAmountBig = big.NewInt(int64(c.StakingAmount))
        clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
        totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
    )
    if totalAmount.Sign() == 0 {
        // Both staking amounts are zero; assign all to CN, nothing to CL.
        return amount, big.NewInt(0)
    }
    clAmount := new(big.Int).Mul(clAmountBig, amount)
    clAmount = clAmount.Div(clAmount, totalAmount)
    cnAmount := new(big.Int).Sub(amount, clAmount)
    return cnAmount, clAmount
}
```

### Proof of Concept

1. Governance sets `reward.minimumstake = 0`.
2. Validator V registers a CL pool via CLRegistry (making `CLStakingInfo != nil`) but deposits 0 KAIA (`CLStakingAmount == 0`).
3. V has 0 CNStaking (`StakingAmount == 0`). With `minStake == 0`, V is a qualified validator.
4. V is selected as block proposer.
5. `FinalizeState` → `GetDeferredReward` → `getDeferredRewardFullKore` → `specWithProposerAndFunds` → `cn.Split(proposer)`.
6. Inside `Split`: `totalAmount = 0 + 0 = 0`. `clAmount.Div(clAmount, totalAmount)` → **panic: integer divide by zero**.
7. All nodes processing this block crash. Chain halts. [8](#0-7)
