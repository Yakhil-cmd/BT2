### Title
i128 Ray-value overflow permanently freezes an entire lending market - (File: common/src/rates/simulate.rs)

### Summary
A sufficiently large market can make `borrowed * borrow_index` exceed the `i128` result domain during ordinary interest accrual, causing `GenericError::MathOverflow`. [1](#0-0)  Because `accrue_step` calculates this value before updating utilization, indexes, or any user mutation, the panic permanently blocks every operation that first synchronizes the market. [2](#0-1)  The protocol’s own regression test demonstrates that `update_indexes`, `withdraw`, and `repay` all fail after the overflow while the borrow index remains below its configured ceiling. [3](#0-2) 

### Finding Description
Pool balances are stored as scaled RAY shares and converted to current value with `scaled_to_original`, which multiplies the scaled balance by the relevant index. [4](#0-3)  The underlying multiply-divide helper uses `I256` only for intermediate arithmetic and still requires the final result to fit `i128`; otherwise it panics with `GenericError::MathOverflow`. [5](#0-4)  At the start of every accrual step, `accrue_step` computes both `borrowed_original` and `supplied_original` using these products. [6](#0-5) 

Once either market aggregate exceeds `i128::MAX` in current RAY terms, the transaction aborts before `last_timestamp` advances. [7](#0-6)  The pool’s shared `synced_market` helper makes this ordering systemic: it loads market state and calls `interest::global_sync` before borrow, supply, withdraw, repay, and other market legs execute. [2](#0-1)  `global_sync` then invokes `accrue_step` for each elapsed time chunk, so every later attempt hits the same overflowing product before it can reduce debt or supply. [8](#0-7) [9](#0-8) 

An unprivileged caller can reach this state through `Controller::supply` to create scaled supply, `Controller::borrow` to create scaled debt, and `Controller::update_indexes` to force accrual after time passes. [10](#0-9) [11](#0-10)  After the threshold is crossed, `withdraw`, `repay`, `liquidate`, `clean_bad_debt`, and later `supply`, `borrow`, or `update_indexes` calls all route through the same pre-mutation accrual and revert. [12](#0-11) 

### Impact Explanation
The affected `(hub_id, asset)` market is permanently frozen because the panic occurs before any state transition that could reduce the overflowing scaled balance or index. [2](#0-1)  Suppliers cannot withdraw, borrowers cannot repay or unwind, liquidators cannot seize collateral, and governance or users cannot recover the market through the normal entrypoints. [13](#0-12)  Since transaction rollback restores `last_timestamp`, the next call repeats the same elapsed-time accrual and overflow instead of progressing past it. [14](#0-13) 

The regression test specifically demonstrates a market with one billion 18-decimal tokens and approximately 98% utilization, where sustained compounding pushes the current-debt product beyond `i128::MAX` before `MAX_BORROW_INDEX_RAY` is reached. [15](#0-14)  It then proves that even a permissionless index update, a one-unit withdrawal, and a repayment all revert with `MathOverflow`. [16](#0-15) 

### Likelihood Explanation
The trigger requires an unusually large aggregate position or substantial index growth, but it lies within the documented protocol domain rather than depending on malformed input. [17](#0-16)  Asset caps can admit roughly 170 billion whole tokens depending on decimals, while the demonstrated trigger uses one billion 18-decimal tokens. [17](#0-16)  The overflow is market-wide, so it can arise from aggregate usage rather than one accounting position, although a sufficiently funded single caller can create the demonstrated state using only public `supply`, `borrow`, and `update_indexes` calls. [10](#0-9) [11](#0-10) 

Once the market is near the numeric boundary, any caller can finalize the freeze by submitting `update_indexes(caller, assets)` after enough ledger time has elapsed. [11](#0-10)  No privileged role, leaked key, oracle manipulation, upgrade, or malformed calldata is required. [12](#0-11) 

### Recommendation
Do not represent intermediate or aggregate market value in an `i128` when the product is already calculated safely in `I256`. [18](#0-17)  Change the accrual path to retain `I256` valuations for utilization and accrued-interest calculations, or enforce a conservative global scaled-balance/index bound such that every reachable `scaled * index / RAY` result remains below `i128::MAX`. [19](#0-18)  Any cap must account for protocol revenue shares and aggregate supply, not just individual positions, because accrual values the full market. [9](#0-8)

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

/// Computes `x * y / d` rounded half up. Returns `None` if `x < 0`, `y < 0`, `d <= 0`, or the
/// result does not fit in `i128`.
pub fn try_mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> Option<i128> {
    if x < 0 || y < 0 || d <= 0 {
        return None;
    }
    let half = d / 2;

    // Fast path: the biased product fits `i128`, so the whole computation is
    // native. `x * y + half` is non-negative here, so `/` is the floor the
    // widened path would produce.
    if let Some(biased) = x
        .checked_mul(y)
        .and_then(|product| product.checked_add(half))
    {
        return Some(biased / d);
    }

    let (x256, y256, d256) = to_i256_operands(env, x, y, d);
    x256.mul(&y256)
        .add(&I256::from_i128(env, half))
        .div(&d256)
        .to_i128()
}
```

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

        env,

        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
