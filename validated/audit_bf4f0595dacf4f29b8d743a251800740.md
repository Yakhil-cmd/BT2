### Title
Bad-debt supply-index floor clamp leaves phantom supply claims that drain later deposits - (File: contracts/pool/src/cache/scale.rs, exercised via `clean_bad_debt`)

### Summary
`apply_bad_debt_to_supply_index` does not zero out residual scaled supply when the write-down exceeds what the index can absorb. Instead it clamps `supply_index` up to `SUPPLY_INDEX_FLOOR_RAW` (RAY/1000), leaving old scaled supply shares as live claims. The next depositor's cash is then withdrawable by the holder of those stranded shares. This is the on-chain analog of the CVE class: residual state (DRAM contents / scaled shares) surviving a "reset" boundary because an edge case — the wipeout exceeding representable write-down — is mishandled rather than zeroed.

### Finding Description
When bad debt is cleaned, the pool writes the loss into the supply index. `apply_bad_debt_to_supply_index` computes a reduced index but enforces a floor at `SUPPLY_INDEX_FLOOR_RAW`. If the write-down would push the index below the floor, the index is clamped instead of the corresponding scaled supply being cleared. The pool's own unit test pins the consequence: after a wipeout that clamps to the floor, `unscale_supply_floor(old_scaled)` still returns a positive claim against zero cash (`contracts/pool/tests/interest.rs:372-429`). Once a fresh supplier deposits, `resolve_withdrawal` lets the stranded share burn `gross` equal to the fresh deposit, leaving `cash() < fresh_claim` — the new supplier's funds are drained by a claim that should have been destroyed. [1](#0-0) 

The trigger path is reachable by an unprivileged address: `clean_bad_debt` is permissionless (it burns the position NFT and applies the write-down, per `tests/test-harness/tests/controller/position_nft.rs:299-317`), and the subsequent withdraw is an ordinary owner action.

### Impact Explanation
Theft of user funds / protocol insolvency. Any supplier depositing into a market after a clamped write-down can have their principal extracted by holders of the residual scaled shares, and the pool ends with cash below outstanding claims.

### Likelihood Explanation
Requires a bad-debt event large enough that the index write-down hits `SUPPLY_INDEX_FLOOR_RAW` while nonzero scaled supply remains. That is an extreme-loss scenario (bad debt exceeding ~all backing), which keeps likelihood low-to-medium; once it occurs the loss to subsequent depositors is deterministic.

### Recommendation
When the write-down saturates at `SUPPLY_INDEX_FLOOR_RAW`, clear the residual scaled supply (burn `supplied`) rather than preserving it as a claim, or treat saturated write-down as full wipeout and block further supply into the market until recapitalized.

### Proof of Concept
The pool's own unit test `test_raw_cache_floor_clamp_strands_claim_without_supply_guard` demonstrates the sequence:

1. Cache with `supplied = 1000*RAY`, `supply_index = RAY`, `cash = 0`.
2. `apply_bad_debt_to_supply_index(cache, 5000*RAY)` clamps `supply_index` to `SUPPLY_INDEX_FLOOR_RAW`; `unscale_supply_floor(old_scaled)` returns a positive stranded claim.
3. Fresh deposit `fresh_cash` mints `fresh_scaled`; old holder calls `resolve_withdrawal(i128::MAX, old_scaled)` and receives `gross == fresh_cash`, leaving `cash() < fresh_claim`.

On-chain path: crash prices → permissionless `clean_bad_debt` socializes the loss and clamps the index → attacker (or stranded holder) `supply`s/`withdraw`s while a new supplier deposits → the stranded claim withdraws the new deposit.

Caveat: the demonstration is at the cache layer; I did not fully verify whether the production `clean_bad_debt` path can push `supplied` below the floor while retaining nonzero scaled supply, or whether `require_reserves` gates the stranded withdrawal in all real flows — the test comments note the invariant is "only masked by require_reserves" when cash is zero, but the drain occurs once real cash arrives.

        apply_bad_debt_to_supply_index(&mut cache, Ray::from(5_000 * RAY));
        assert_eq!(
            cache.supply_index().raw(),
            SUPPLY_INDEX_FLOOR_RAW,
            "wipeout clamps supply_index UP to RAY/1000 instead of resetting shares to 0",
        );

        let stranded = cache.unscale_supply_floor(old_scaled);
        assert!(stranded > 0, "floor clamp leaves S_old a phantom claim");
        assert_eq!(
            cache.cash(),
            0,
            "no cash yet: invariant only masked by require_reserves"
        );

        let fresh_cash = stranded;
        let fresh_scaled = cache.calculate_scaled_supply(fresh_cash);
        cache.mint_supply(fresh_scaled);
        cache.credit_cash(fresh_cash);

        let fresh_claim = cache.unscale_supply_floor(fresh_scaled);
        assert_eq!(
            fresh_claim, fresh_cash,
            "fresh supplier's claim equals deposit"
        );

        let (burn, gross) = cache.resolve_withdrawal(i128::MAX, old_scaled);
        cache.require_reserves(gross);
        cache.burn_supply(burn);
        cache.debit_cash(gross);

        assert!(gross > 0, "stranded wiped position pays out real tokens");
        assert_eq!(gross, fresh_cash, "S_old drains exactly the fresh deposit");
        assert!(
            cache.cash() < fresh_claim,
            "pool cash ({}) can no longer cover fresh supplier claim ({}): funds lost",
            cache.cash(),
            fresh_claim,
        );
