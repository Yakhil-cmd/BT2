### Title
Non-fast-forward history rewrite (`git reset --hard`/rebase) causes `compute_v2_review_set` to produce an empty review set, silently skipping Stop-hook security review of committed malicious content - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`_is_ancestor` in `gitutil.py` correctly reports non-ancestry after a `git reset --hard`/rebase to an unrelated commit, but the caller `compute_v2_review_set` in `diffstate.py` uses that correct answer in a way that causes the review set to become empty rather than falling back to a safe, non-empty set. Because `review_set = dirty_now ∩ changed_since` and `dirty_now` is derived only from `git status` versus the *current* HEAD (not the reviewed baseline), any content that was committed via history rewrite so that the working tree is clean relative to the new HEAD is excluded from `dirty_now`, even though `changed_since` (diff against `baseline_sha`) correctly shows it as changed. The intersection then drops it entirely, so `handle_stop_hook` sees `review_paths == []` and skips the LLM security review for that turn.

### Finding Description
`_is_ancestor(cwd, maybe_ancestor, descendant)` [1](#0-0)  is only used inside `compute_v2_review_set` to decide whether to widen `dirty_now` with the linear commit range `head_at_capture..HEAD`: [2](#0-1) 

The rest of the function computes:
- `tracked_dirty, untracked = _git_status_porcelain(repo)` — a `git status` snapshot relative to *current* HEAD, not the baseline.
- `changed_since = _git_name_only(repo, baseline_sha)` — a tree diff of `baseline_sha` vs the current worktree, which is ancestry-independent and always reflects true content drift from the reviewed snapshot.
- `review_set = dirty_now & changed_since` (or `dirty_now` alone if `changed_since` is `None`). [3](#0-2) 

Attack flow:
1. At `UserPromptSubmit`, the plugin stashes state: `baseline_sha` (stash-create SHA) and `head_at_capture` (current HEAD). [4](#0-3) 
2. During the turn, the attacker (via ordinary Bash access) runs `git reset --hard <commit-with-malicious-content>` where that commit is not a descendant of `head_at_capture`. After this, the working tree is byte-identical to the new HEAD, so `git status` is clean: `tracked_dirty` and `untracked` are both empty.
3. At Stop, `current_head != head_at_capture` and `_is_ancestor(head_at_capture, current_head)` correctly returns `False` (not reachable) — so the `head_at_capture..HEAD` name-only union is *not* added to `dirty_now`. `dirty_now` therefore stays empty.
4. `changed_since = _git_name_only(repo, baseline_sha)` still correctly lists the malicious files as changed (tree diff is history-agnostic).
5. `review_set = dirty_now (∅) & changed_since ({malicious files}) = ∅`.
6. `handle_stop_hook` sees `review_paths == []` and exits via `_skip(9, ...)` — "empty review set" — before ever building a diff or invoking the Haiku/LLM security review. [5](#0-4) 

No existing check catches this: `_is_ancestor` behaves correctly (it truthfully reports non-ancestry), but the design implicitly assumes that whenever `changed_since` is non-empty for a file, `dirty_now` (status-based) will also include it — an assumption that only holds for linear, fast-forward history. A `reset --hard`/rebase to a foreign commit breaks that assumption and turns a "correct" ancestry answer into a silent bypass of the entire review pipeline for that turn, rather than a degraded-but-safe fallback.

### Impact Explanation
This allows an attacker with ordinary Bash access inside the workspace to smuggle secrets or vulnerable code that Claude wrote (or that the attacker introduces through Claude's tool-driven git operations) past the Stop-hook LLM security review entirely for that turn, by simply committing the content and then resetting the branch tip so HEAD becomes non-linear relative to `head_at_capture`. The review is not merely scoped incorrectly — it is skipped outright (`skip_reason 9`), meaning no vulnerability/secret scan runs on genuinely new, unreviewed content. This matches "security review computed against the wrong (empty) range, omitting newly introduced secrets/vulnerabilities."

### Likelihood Explanation
Preconditions are minimal and match the stated threat model: normal Bash access to run `git reset --hard`, `rebase`, or `checkout` to a divergent/foreign commit within the workspace during an active session — no elevated privileges required. The sequence (commit malicious content elsewhere, then `git reset --hard` to it mid-turn) is simple, deterministic, and repeatable every turn.

### Recommendation
Do not gate `dirty_now` widening solely on `_is_ancestor`. When `current_head != head_at_capture` and they are not in an ancestor relationship (history rewritten), fall back to unioning `dirty_now` with the full `_git_name_only(repo, baseline_sha)` result (i.e., treat `review_set` as `changed_since` alone, not an intersection) instead of leaving `dirty_now` unexpanded — mirroring the existing safe fallback already used when `baseline_sha` is missing (`review_set = dirty_now` alone). Additionally, `_skip(9)` ("empty review set") should be distinguished/logged when `changed_since` was non-empty but `dirty_now` was empty, since that specific combination indicates the intersection dropped real changes rather than there being nothing to review.

### Proof of Concept
Integration test in the plugin's test suite (e.g., alongside existing `compute_v2_review_set` tests):
1. Init a git repo, commit an initial file, capture `baseline_sha = git stash create` (or empty state) and `head_at_capture = HEAD`.
2. Create a second, unrelated commit on a detached branch that adds a file containing a fake secret (`SECRET_KEY=...`), not descending from `head_at_capture`.
3. `git reset --hard <that unrelated commit>` to simulate the attacker rewriting history mid-turn.
4. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture, {})`.
5. Assert: `_is_ancestor(repo, head_at_capture, "HEAD")` returns `False` (correct ancestry check), but assert that `review_paths` returned by `compute_v2_review_set` is **not** empty and includes the newly committed secret file — i.e., `changed_since` non-empty must not be silently intersected away to `∅`.
6. Also assert end-to-end via `handle_stop_hook` (with API mocked) that `skip_reason == 9` is never hit when `changed_since_count > 0` in `v2_metrics`.

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
