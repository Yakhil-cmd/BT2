### Title
Borrow-index overflow permanently freezes a highly utilized market - ([File: `common/src/rates/index.rs`])

### Summary
A market whose scaled debt multiplied by its borrow index exceeds the `i128` range causes every subsequent pool operation to revert with `MathOverflow`, permanently blocking withdrawals, repayments, liquidations, and further index updates. [1](#0-0) [2](#0-1) 

### Finding Description
Every market mutation loads the market through `load_leg`, which calls `synced_market` before processing the operation. [3](#0-2)  `synced_market` invokes `interest::global_sync`, which applies every pending accrual chunk through `accrue_step` before user accounting proceeds. [4](#0-3) 

During accrual, `calculate_supplier_rewards` computes both the previous and new total debt as `borrowed * borrow_index`. [1](#0-0)  `scaled_to_original` similarly returns `scaled.mul(index)`, while debt-position resolution also unscale debt using the borrow index. [5](#0-4) [6](#0-5) 

Although `update_borrow_index` caps the stored index at `MAX_BORROW_INDEX_RAY`, the cap is applied only after calculating `old_index * interest_factor`; neither the index update nor total-debt calculation first verifies that `borrowed * new_index` remains representable. [7](#0-6) [8](#0-7) 

The repository’s own harness demonstrates the condition with a one-billion-token, 18-decimal market at 98% utilization on the XLM rate curve. [9](#0-8)  After repeated one-year accrual intervals, `update_indexes` fails with `MathOverflow` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`, proving that value overflow occurs before the intended cap can protect the market. [10](#0-9) 

The same test then shows both a withdrawal and repayment reverting with `MathOverflow`, because both paths accrue before touching the position. [11](#0-10) [12](#0-11) [13](#0-12) 

### Impact Explanation
Once the unrepresentable debt state is reached, suppliers cannot withdraw, borrowers cannot repay, liquidators cannot reduce the debt, and permissionless index updates cannot advance the market. [3](#0-2) [11](#0-10) 

This permanently freezes all funds held in the affected `(hub, asset)` market and prevents normal resolution of its outstanding debt. [4](#0-3) [1](#0-0) 

### Likelihood Explanation
An unprivileged borrower can create the prerequisite state through the ordinary controller `borrow` path by borrowing most of a sufficiently large 18-decimal market, after which an unprivileged `update_indexes` call eventually triggers the overflow. [14](#0-13) [15](#0-14) 

The attack requires exceptional market scale, high sustained utilization, and a long accrual horizon, so it is less immediately reachable than a simple input-validation bug but remains a demonstrated state transition rather than a hypothetical host or memory failure. [2](#0-1) 

### Recommendation
Enforce a market-level bound that guarantees `borrowed * MAX_BORROW_INDEX_RAY` and `supplied * MAX_SUPPLY_INDEX_RAY` remain representable, or perform the accrual calculations with a wider intermediate representation and atomically bound market shares before committing an index that would make total debt unrepresentable. [16](#0-15) [8](#0-7) 

Borrow creation should additionally reject or clamp scaled debt using a conservative ceiling derived from `i128::MAX / MAX_BORROW_INDEX_RAY`, rather than only validating the immediate `amount` conversion. [17](#0-16) [18](#0-17) 

### Proof of Concept
1. Establish a large 18-decimal market and lift its caps, as the harness does with `BIG18`. [19](#0-18) 
2. Supply enough collateral and borrow approximately 98% of the market through the ordinary controller `borrow` entrypoint. [14](#0-13) [20](#0-19) 
3. Advance ledger time and call the permissionless `update_indexes` path until accrual returns `MathOverflow`. [21](#0-20) 
4. Attempt `withdraw`, `repay`, liquidation, or another index update on the same `HubAssetKey`; each first executes `global_sync` and fails again before any market mutation can complete. [3](#0-2) [22](#0-21)

/// Applies `interest_factor` to `old_index` to produce the new borrow index,
/// capped at `MAX_BORROW_INDEX_RAY`.
pub fn update_borrow_index(env: &Env, old_index: Ray, interest_factor: Ray) -> Ray {
    let new_index = old_index.mul(env, interest_factor);
    if new_index.raw() > MAX_BORROW_INDEX_RAY {
        return Ray::from(MAX_BORROW_INDEX_RAY);
    }
    new_index
}

/// Grows `old_index` by distributing `rewards_increase` over the total value
/// currently supplied (`supplied * old_index`). The division rounds down.
///
/// Returns `old_index` unchanged if `supplied` or `rewards_increase` is zero,
/// or if the total supplied value is zero. Clamps the result between
/// `old_index` (itself capped at `MAX_SUPPLY_INDEX_RAY`) and
/// `MAX_SUPPLY_INDEX_RAY`, so the returned index never decreases and never
/// exceeds the cap.
pub fn update_supply_index(env: &Env, supplied: Ray, old_index: Ray, rewards_increase: Ray) -> Ray {
    if supplied == Ray::ZERO || rewards_increase == Ray::ZERO {
        return old_index;
    }

    let total_supplied_value = supplied.mul(env, old_index);

    if total_supplied_value == Ray::ZERO {
        return old_index;
    }

    let new_value = total_supplied_value.checked_add(env, rewards_increase);
    let grown = fp_core::mul_div_floor_saturating(env, new_value.raw(), RAY, supplied.raw());

    let bounded_old = old_index.raw().min(MAX_SUPPLY_INDEX_RAY);
    Ray::from(grown.min(MAX_SUPPLY_INDEX_RAY).max(bounded_old))

/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {

        }

        last.borrow_index as f64 / RAY as f64

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
