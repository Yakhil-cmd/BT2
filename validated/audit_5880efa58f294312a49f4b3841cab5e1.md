### Title
Webhook signature binds only to the attacker's own organization, not to the repository the handler actually writes to - allowing cross-organization stack sync/writes - (File: `app/controllers/shipit/webhooks_controller.rb`, `app/models/shipit/webhooks/handlers/handler.rb`)

### Summary
`WebhooksController#verify_signature` selects which organization's `webhook_secret` to validate a delivery against using `repository.owner.login` (or `organization.login`) taken from the *same* JSON body it is about to verify. [1](#0-0)  Once the HMAC check passes, every webhook handler resolves the actual `Repository`/`Stack` to mutate using a completely different field of that same body, `repository.full_name`, with no check that this repository belongs to the organization that was used to select the verification secret. [2](#0-1)  In a multi-organization Shipit deployment (a supported, documented configuration [3](#0-2) ), an attacker who legitimately administers one onboarded GitHub organization (and therefore legitimately knows that organization's own `webhook_secret`) can sign an arbitrary payload whose `repository.owner.login` matches their own org, while setting `repository.full_name` to a victim organization's repository. The signature check only binds the payload to "the org whose secret was used," never to "the repository the handler is about to act on."

### Finding Description
- `verify_signature` picks the org/secret to check against from attacker-controlled JSON: `repository_owner = params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')`, then `github_app = Shipit.github(organization: repository_owner)` and `github_app.verify_webhook_signature(header, raw_post)`. [4](#0-3) 
- `verify_webhook_signature` only proves the raw body was HMAC-signed with *some org's* configured `webhook_secret` — it says nothing about which repository inside that body is legitimate for that org. [5](#0-4) 
- Every handler (`PushHandler`, etc.) then independently derives the target repository from `payload.dig('repository', 'full_name')`, ignoring `repository.owner.login` entirely: `Repository.from_github_repo_name(repository_name)&.stacks`. [2](#0-1) 
- `PushHandler#process` uses that unchecked repository/stack scope to force a stack sync to an attacker-chosen commit: `stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }`. [6](#0-5) 

Equality that should hold but doesn't: `organization_used_for_signature_verification == owner(repository_the_handler_writes_to)`. The code enforces `organization_used_for_signature_verification == payload['repository']['owner']['login']` (trivially true, it's the same field) but never enforces that `payload['repository']['full_name']`'s owner is the same organization.

### Impact Explanation
This breaks the binding between "which organization authenticated this delivery" and "which repository/stack gets written to," which is exactly the trust boundary this endpoint exists to enforce. On a multi-org Shipit instance, any organization admin who has (legitimately) registered their own GitHub App/webhook secret with the Shipit instance can forge deliveries that: enqueue `GithubSyncJob` with an attacker-chosen `expected_head_sha` for any other onboarded organization's stacks, spoof `check_suite`/`status`/`commit_status` state for other orgs' commits, or fabricate `membership`/team data — all cross-organization writes performed with a credential that has no legitimate relationship to the victim organization. This matches the "cross-repository writes" impact bucket.

### Likelihood Explanation
Requires only a normal, documented Shipit multi-org configuration and possession of a webhook secret the attacker legitimately owns for their own onboarded org (not a stolen/privileged credential of the victim, not a Shipit session, not an `ApiClient` token, not the victim's `GITHUB_TOKEN`). No social engineering or host compromise is needed — the attacker crafts and POSTs the payload directly to the public `/webhooks` endpoint.

### Recommendation
After signature verification succeeds, re-derive the org from `repository.full_name`/`organization.login` used by the handler and assert it matches the org (`repository_owner`) whose secret validated the signature; reject with 422 on mismatch. Alternatively, resolve the target `Repository`/`Stack` only within the organization that was authenticated, rather than trusting `repository.full_name` in isolation.

### Proof of Concept
1. Configure Shipit with two orgs, `attacker-org` (attacker is a legitimate GitHub org admin, knows `webhook_secret_A`) and `victim-org` (has an onboarded stack, e.g. `victim-org/victim-repo`).
2. Craft body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen-sha>",
  "repository": { "owner": { "login": "attacker-org" }, "full_name": "victim-org/victim-repo" }
}
```
3. Compute `X-Hub-Signature: sha1=<HMAC-SHA1(webhook_secret_A, body)>` and POST to `/webhooks` with `X-Github-Event: push`.
4. `verify_signature` resolves `repository_owner = "attacker-org"`, verifies successfully against `webhook_secret_A`. [7](#0-6) 
5. `PushHandler` resolves the stack via `repository.full_name = "victim-org/victim-repo"` [2](#0-1)  and calls `stack.sync_github(expected_head_sha: "<attacker-chosen-sha>")` for the victim's stack, despite the delivery only having been authenticated as belonging to `attacker-org`. [6](#0-5)

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
