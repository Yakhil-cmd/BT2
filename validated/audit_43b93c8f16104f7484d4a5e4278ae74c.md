### Title
Unauthenticated device can register attacker-controlled shared-address bindings for the victim's own addresses via `handleNewSharedAddress` - ([File: wallet_defined_by_addresses.js])

### Summary
Any paired correspondent device (an unprivileged peer, no application role required) can send a `new_shared_address` message to a wallet. `handleNewSharedAddress()` in `wallet_defined_by_addresses.js` accepts an arbitrary `definition`, verifies only that the address hashes correctly to the definition and that named `signers` are consistent with the definition's `["address", ...]` leaves, but never checks that the sender (`from_address`) is actually one of the intended members/cosigners of the new shared address, nor that the "member address" entries the sender is claiming (which can include the *victim's own* address) were ever solicited by the victim. This mirrors the reported bug class: an endpoint that performs object/record creation and mutation without verifying the caller is authorized to act on the referenced entity (here, the local wallet's `shared_addresses` / `shared_address_signing_paths` tables, which drive cosigning and private-payment forwarding decisions).

### Finding Description
In `wallet.js`, the hub message handler for `"new_shared_address"` simply forwards the body to the wallet logic with no additional authorization gate: [1](#0-0) 

`handleNewSharedAddress()` performs:
1. `address === chash160(definition)` check.
2. That named `signers[path].address` fields match `["address", ...]` leaves extracted from the definition.
3. That every `["address", ...]` leaf has a corresponding signer entry.
4. `determineIfIncludesMeAndRewriteDeviceAddress()` — checks that at least one of the "member addresses" in `signers` is one of *my* addresses (`my_addresses` or `shared_addresses`), and if my device isn't already listed as a signer, it rewrites the device_address for that member to my own device.
5. `validateAddressDefinition()` — only runs `Definition.validateDefinition` structural/complexity checks; does **not** verify anything about who initiated the request.
6. Finally calls `addNewSharedAddress()`, which unconditionally inserts rows into `shared_addresses` and `shared_address_signing_paths`. [2](#0-1) [3](#0-2) [4](#0-3) 

Critically, `from_address` (the sender/device that sent the `new_shared_address` message) is **never checked against anything in `body.signers`** — it is only used by `wallet.js`'s outer dispatcher to identify who sent the message, but `handleNewSharedAddress` itself takes no `from_address` parameter and applies no restriction tying the message sender to a specific signing path or device_address in the payload. This means any correspondent (or any peer that gets paired, even briefly) can construct a definition such as `["and", [["address", "<victim_own_address>"], ["address", "<attacker_address>"]]]`, list themselves as the signer for the attacker leaf and the victim's real address as the other leaf, and submit it. Since `determineIfIncludesMeAndRewriteDeviceAddress` only requires that *some* member address in the definition belongs to the victim (which is trivially satisfiable by citing any of the victim's known/public addresses), the record is accepted and written to the victim's local `shared_addresses`/`shared_address_signing_paths` tables — establishing that the victim is now nominally a cosigner of a multisig address that also includes the attacker, and that the attacker's device is a legitimate cosigner/device for that shared address, without any consent or genuine multi-party handshake (the "pending" approval flow with `create_new_shared_address`/`approve_new_shared_address` exists for genuine consensual creation, but `new_shared_address` bypasses it entirely and is reachable directly).

This shared-address bookkeeping subsequently drives:
- `forwardPrivateChainsToOtherMembersOfAddresses()` and `readAllControlAddresses()`, which use `shared_address_signing_paths` to decide which devices private payment chains and control addresses are forwarded to [5](#0-4) .
- Cosigning/signing-request flows that treat the attacker's device as a legitimate signer for the newly injected shared address.

### Impact Explanation
An attacker who is (or briefly becomes) a paired correspondent device of the victim can inject fabricated "shared address" configurations that falsely bind the victim's own address as a cosigner in a multisig scheme also containing an attacker-controlled address, entirely without the victim's consent or any real multi-device approval handshake. This can:
- Cause the victim's wallet to forward private payment chains involving that address to the attacker's device (information disclosure of amounts/blinding factors for that address's outputs).
- Cause the victim's wallet UI/logic to treat outputs sent to that "shared address" as spendable/controlled jointly with the attacker, potentially leading the victim to include the attacker as a required cosigner for future spends from that fabricated relationship, or to leak control-address information (`readAllControlAddresses`) that maps out victim addresses to attacker devices.
This corresponds to unauthorized modification of wallet state ("objects") that should require verified multi-party consent — analogous to the reported issue where an unauthorized party could create/modify object-management records without proper authorization checks.

### Likelihood Explanation
Requires the attacker to be a paired correspondent device of the victim (a much lower bar than compromising a private key — device pairing typically only needs a pairing code/QR exchanged once, and hubs/relays are semi-trusted transport). No application role or asset-type configuration is required; a single crafted `new_shared_address` message is sufficient. The victim's real address only needs to be known publicly (addresses in this ecosystem are frequently shared for receiving payments), so the "includes me" check is trivially satisfiable by an attacker who knows any one of the victim's addresses.

### Recommendation
- Require that `handleNewSharedAddress`/`addNewSharedAddress` only accept and store shared-address definitions that were explicitly solicited by the local user (e.g., via the existing `create_new_shared_address` → `approve_new_shared_address` handshake using `pending_shared_addresses`), and reject unsolicited `new_shared_address` messages that reference addresses not already staged as pending.
- Tie `from_address` to the specific signing path/device_address it claims in `body.signers`, and verify that the claimed `device_address` for that signing path matches the actual sender's `from_address` before trusting the association.
- Add explicit user confirmation before writing any new shared-address binding that includes one of the user's own addresses, rather than silently accepting and persisting the record whenever a hash check and structural definition check pass.

### Proof of Concept
1. Attacker device pairs with victim device (or is a temporary correspondent).
2. Attacker learns victim's real address `V` (from a public payment receipt, invoice, etc.) and controls address `A`.
3. Attacker crafts `arrDefinition = ["and", [["address", V], ["address", A]]]`, computes `address = chash160(arrDefinition)`, and sends:
```
{"subject": "new_shared_address",
 "body": {
   "address": address,
   "definition": arrDefinition,
   "signers": {
     "r.0": {"address": V, "device_address": "<victim_device_address, arbitrary/omitted>"},
     "r.1": {"address": A, "device_address": "<attacker_device_address>"}
   }
 }}
```
4. `handleNewSharedAddress` passes all checks (hash matches, signer addresses match definition leaves, victim's address is present so `determineIfIncludesMeAndRewriteDeviceAddress` succeeds) and calls `addNewSharedAddress`, inserting rows into `shared_addresses` and `shared_address_signing_paths` binding `V` and `A` as members of `address`, with the attacker's device recorded as a legitimate signer/device for that shared address — all without any consent flow or the victim's approval.

function determineIfIncludesMeAndRewriteDeviceAddress(assocSignersByPath, handleResult){
	var assocMemberAddresses = {};
	var bHasMyDeviceAddress = false;
	for (var signing_path in assocSignersByPath){
		var signerInfo = assocSignersByPath[signing_path];
		if (signerInfo.device_address === device.getMyDeviceAddress())
			bHasMyDeviceAddress = true;
		if (signerInfo.address)
			assocMemberAddresses[signerInfo.address] = true;
	}
	var arrMemberAddresses = Object.keys(assocMemberAddresses);
	if (arrMemberAddresses.length === 0)
		return handleResult("no member addresses?");
	db.query(
		"SELECT address, 'my' AS type FROM my_addresses WHERE address IN(?) \n\
		UNION \n\
		SELECT shared_address AS address, 'shared' AS type FROM shared_addresses WHERE shared_address IN(?)", 
		[arrMemberAddresses, arrMemberAddresses],
		function(rows){
		//	handleResult(rows.length === arrMyMemberAddresses.length ? null : "Some of my member addresses not found");
			if (rows.length === 0)
				return handleResult("I am not a member of this shared address");
			var arrMyMemberAddresses = rows.filter(function(row){ return (row.type === 'my'); }).map(function(row){ return row.address; });
			// rewrite device address for my addresses
			if (!bHasMyDeviceAddress){
				for (var signing_path in assocSignersByPath){
					var signerInfo = assocSignersByPath[signing_path];
					if (signerInfo.address && arrMyMemberAddresses.indexOf(signerInfo.address) >= 0)
						signerInfo.device_address = device.getMyDeviceAddress();
				}
			}
			handleResult();
		}
	);
}

// {address: "BASE32", definition: [...], signers: {...}}
function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function readAllControlAddresses(conn, arrAddresses, handleLists){
	conn = conn || db;
	conn.query(
		"SELECT DISTINCT address, shared_address_signing_paths.device_address, (correspondent_devices.device_address IS NOT NULL) AS have_correspondent \n\
		FROM shared_address_signing_paths LEFT JOIN correspondent_devices USING(device_address) WHERE shared_address IN(?)", 
		[arrAddresses], 
		function(rows){
			if (rows.length === 0)
				return handleLists([], []);
			var arrControlAddresses = rows.map(function(row){ return row.address; });
			var arrControlDeviceAddresses = rows.filter(function(row){ return row.have_correspondent; }).map(function(row){ return row.device_address; });
			readAllControlAddresses(conn, arrControlAddresses, function(arrControlAddresses2, arrControlDeviceAddresses2){
				handleLists(_.union(arrControlAddresses, arrControlAddresses2), _.union(arrControlDeviceAddresses, arrControlDeviceAddresses2));
			});
		}
	);
}
