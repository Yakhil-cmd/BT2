## Title
Cross-organization webhook signature confusion allows unauthorized deploy/rollback via forged `PushHandler` events - ([File: app/controllers/shipit/webhooks_controller.rb])

### Summary
`WebhooksController#verify_signature` picks the GitHub App configuration (and thus the `webhook_secret` used to validate `X-Hub-Signature`) using `repository.owner.login` from the *attacker-controlled* JSON body, while the downstream event handlers (e.g. `PushHandler`) select the actual `Repository`/`Stack` to act on using the independent, also attacker-controlled `repository.full_name` field from the same body. Because these two fields are never cross-checked against each other, an attacker who knows (or is a member of) an organization configured in `Shipit.github` with its own `webhook_secret` can sign a payload with that organization's secret while setting `repository.full_name` to point at a *different, victim* organization's repository, and the engine will process it as if GitHub had endorsed the victim's event.

### Finding Description
`Shipit` supports multiple GitHub App configurations, one per organization, each with its own `webhook_secret` [1](#0-0) . The webhook signature is verified as:

```ruby
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(
    request.headers['X-Hub-Signature'],
    request.raw_post
  )
  head(422) unless verified
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [2](#0-1) 

`repository_owner` is read directly from the untrusted JSON body and used solely to select which organization's `webhook_secret` to verify the HMAC signature against [3](#0-2) . Once verification passes, `create` dispatches the entire raw payload to the registered handler for the event [4](#0-3) .

`Handler#stacks` (used by `PushHandler`, the handler for `push` events that triggers deploy-relevant syncs) resolves the target repository independently, from `payload.dig('repository', 'full_name')`:
```ruby
def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end

def repository_name
  payload.dig('repository', 'full_name')
end
``` [5](#0-4) 

`PushHandler#process` then calls `stack.sync_github(expected_head_sha: params.after)` for every matching, non-archived stack on the matching branch [6](#0-5) .

The equality that should hold but doesn't:
`organization used to verify signature (repository_owner) == owner(repository.full_name used to select the Stack that gets synced)`

Because `repository.owner.login` and `repository.full_name` are two separate JSON keys under attacker control in the raw POST body, an attacker can set them to different values. If the attacker signs the payload with the `webhook_secret` of an organization they control (or an org whose secret is `nil`/misconfigured, for which `verify_webhook_signature` unconditionally returns `true` — see `GitHubApp#verify_webhook_signature`, `return true unless webhook_secret` [7](#0-6) ), the signature check passes, yet `repository.full_name` can name a completely unrelated victim repository/stack, whose `sync_github` gets triggered from a forged `ref`/`after` (commit SHA).

### Impact Explanation
This breaks the "organization that authenticated versus the repository that is written" trust binding explicitly called out as a valid analog class. An attacker controlling one configured GitHub organization (or exploiting one with no `webhook_secret` configured) can trigger `GithubSyncJob`/`sync_github` against a completely different, victim organization's `Stack`, effectively forcing an unauthorized sync/deploy pipeline action using attacker-chosen `ref`/`after` values without ever needing write access to the victim's actual GitHub repository. This qualifies as an unauthorized deploy-pipeline trigger (High/Critical per the Impact rubric: "unauthorized deploy" class).

### Likelihood Explanation
Requires the deployment to have more than one GitHub organization configured under `Shipit.github` (a documented, supported configuration per `config/secrets.development.shopify.yml` [8](#0-7) ), and that the attacker controls (or can forge signatures for) at least one of them, or that one configured organization has no `webhook_secret` set (`webhook_secret: # nil` is shown as a valid/expected value in the sample secrets file). No authenticated Shipit session or API token is needed — only the ability to POST to the public `/github/webhooks` endpoint with a crafted body and a valid signature for any one configured org.

### Recommendation
Bind the organization used for signature verification to the same repository owner value used to resolve the target `Stack`/`Repository`, and additionally verify that `repository.owner.login` matches the owner portion of `repository.full_name` before dispatching to handlers. Reject the webhook if these two derived organizations disagree.

### Proof of Concept
1. Configure two orgs in `Shipit.github`, e.g. `attacker-org` (attacker controls/knows `webhook_secret`) and `victim-org` (hosts a real `Stack`).
2. Craft a `push` webhook payload:
```json
{
  "ref": "refs/heads/main",
  "after": "<attacker-chosen-sha>",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Sign the raw body with `attacker-org`'s `webhook_secret` and set `X-Hub-Signature` accordingly; set `X-Github-Event: push`.
4. POST to the webhooks endpoint. `verify_signature` looks up `Shipit.github(organization: "attacker-org")` and verifies successfully [9](#0-8) .
5. `PushHandler#stacks` resolves `Repository.from_github_repo_name("victim-org/victim-repo")` [5](#0-4)  and triggers `sync_github(expected_head_sha: "<attacker-chosen-sha>")` on `victim-org`'s stacks [6](#0-5) , an unauthorized action against a repository the attacker never authenticated for.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
```
