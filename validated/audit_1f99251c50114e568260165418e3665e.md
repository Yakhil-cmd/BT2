### Title
`ProxyType::NonTransfer` deny-list fails open on Asset Hub Rococo, permitting a `NonTransfer` proxy to move the delegator's assets - (File: `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs`)

### Summary
On Asset Hub Rococo, `ProxyType::NonTransfer` is implemented as a deny-list (`!matches!(c, ...)`), which fails open: any pallet call not explicitly named is permitted. The same class of bug was found and fixed on Asset Hub Westend via [`prdoc/pr_12771.prdoc`](prdoc/pr_12771.prdoc), which added `ForeignAssets`, `PoolAssets`, `AssetConversion`, `Psm`, `PolkadotXcm`, `Revive`, and `Indices::{transfer,force_transfer}` to the deny-list, and shipped a regression test `non_transfer_proxy_rejects_value_moving_calls` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs`. Asset Hub Rococo's `ProxyType::NonTransfer` filter still only denies `Balances`, `Assets`, `NftFractionalization`, `Nfts`, and `Uniques`, and has no equivalent regression test.

### Finding Description
The invariant documented on `ProxyType::NonTransfer` is "can execute any call that does not transfer funds or assets" [1](#0-0) . Because the filter is implemented as a negated `matches!` (a deny-list) rather than an allow-list, every pallet/call variant added to the runtime that is not explicitly listed is silently permitted through a `NonTransfer` delegate — this is the exact "fails open" root cause called out in the fix commit for Westend: [2](#0-1) 

On Asset Hub Rococo the `NonTransfer` arm still only lists: [3](#0-2) 

But the runtime instantiates `ForeignAssets`, `PoolAssets`, `AssetConversion`, `PolkadotXcm`, and `Revive` pallets (confirmed via their `construct_runtime` instantiation lines), all of which move the caller's funds/assets:
- `ForeignAssets::transfer` / `PoolAssets::transfer` — move the other `pallet-assets` instances' tokens, exactly like `Assets::transfer`, which *is* denied.
- `AssetConversion::swap_exact_tokens_for_tokens` / liquidity calls — move the caller's assets.
- `PolkadotXcm::transfer_assets` / `teleport_assets` / `send` / `execute` — move assets off-chain or express arbitrary XCM.
- `Revive::call` / `instantiate` — carry a `value` that transfers native currency.
- `Indices::transfer` / `force_transfer` — repatriate the index's reserved deposit.

None of these are present in the Rococo deny-list, and no regression test analogous to `non_transfer_proxy_rejects_value_moving_calls` exists under `cumulus/parachains/runtimes/assets/asset-hub-rococo/` to catch this drift.

This is structurally the same bug class as the reNFT `Guard.sol` finding: an incomplete negative check (deny-list of disallowed selectors/pallets) that is bypassed by any call not on the list (`burn`/`burnFrom` in the Solidity case; `ForeignAssets`/`PoolAssets`/`AssetConversion`/`PolkadotXcm`/`Revive`/`Indices::transfer` in the FRAME case), letting an attacker who only holds a restricted delegation move assets the delegator never authorized for transfer.

### Impact Explanation
A `NonTransfer` proxy is intended as a safety boundary: a delegator can grant this role expecting the delegate cannot move funds/assets. On Asset Hub Rococo, a delegate with only `NonTransfer` proxy rights can still call `ForeignAssets::transfer`, `PoolAssets::transfer`, swap through `AssetConversion`, teleport/transfer via `PolkadotXcm`, transfer native value through `Revive::call`, or reclaim the deposit via `Indices::transfer`/`force_transfer` — moving the delegator's assets out of their control despite the documented guarantee. This is a direct violation of an access-control invariant leading to unauthorized asset movement.

### Likelihood Explanation
No privileged role or governance action is required: any account that has been granted (or announces via `pallet-proxy`) a `NonTransfer` proxy relationship — the intended low-trust delegation — can immediately dispatch these calls as the proxied account. The bug is purely in `InstanceFilter::filter`, reached on every `Proxy::proxy`/`proxy_announced` dispatch for this `ProxyType`, so it is trivially and deterministically triggerable by the delegate with no special preconditions.

### Recommendation
Apply the same fix already merged for Asset Hub Westend (`prdoc/pr_12771.prdoc`) to Asset Hub Rococo: extend the `ProxyType::NonTransfer` deny-list in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` to also deny `RuntimeCall::ForeignAssets`, `RuntimeCall::PoolAssets`, `RuntimeCall::AssetConversion`, `RuntimeCall::PolkadotXcm`, `RuntimeCall::Revive`, `RuntimeCall::Vesting(vested_transfer)`, and `RuntimeCall::Indices(transfer|force_transfer)`. Longer term, consider converting `NonTransfer` to an explicit allow-list (as done for the relay-chain `ProxyType::NonTransfer` in `polkadot/runtime/westend/src/lib.rs`) so newly added pallets are denied by default instead of silently permitted, and port the `non_transfer_proxy_rejects_value_moving_calls`-style regression test to `asset-hub-rococo`.

/// Regression test for <https://github.com/paritytech/polkadot-sdk/issues/12466>.
///
/// `ProxyType::NonTransfer` is documented as permitting "any call that does not transfer funds or
/// assets", but it is implemented as a deny-list and so fails open. `ForeignAssets` and
/// `PoolAssets` transfers were reachable, as were swaps, XCM transfers, contract calls carrying a
/// value, and index transfers (which repatriate the reserved deposit).
#[test]
fn non_transfer_proxy_rejects_value_moving_calls() {
	use asset_hub_westend_runtime::ProxyType;
	use frame_support::traits::InstanceFilter;

	// Collected rather than asserted one by one, so a regression reports every call that slipped
	// through instead of only the first.
	let mut leaked = Vec::new();
	for (name, call) in value_moving_calls() {
		if ProxyType::NonTransfer.filter(&call) {
			leaked.push(name);
		}
		// The call is otherwise well-formed and reachable by a fully permissioned proxy.
		assert!(ProxyType::Any.filter(&call), "Any must permit {name}");
	}

	assert!(
		leaked.is_empty(),
		"NonTransfer must reject calls that move funds or assets, but permitted: {leaked:?}",
	);
}
