### Title
Webhook signature scoped to `repository.owner.login`, but handlers act on unrelated `repository.full_name` — cross-org review stack archive/unarchive - ([File: app/controllers/shipit/webhooks_controller.rb], [File: app/models/shipit/webhooks/handlers/pull_request/labeled_handler.rb])

### Summary
`WebhooksController#verify_signature` selects the GitHub App/`webhook_secret` used to validate the HMAC signature based on `params.dig('repository','owner','login')`, but `LabeledHandler` resolves the target `Stack` from `params.repository.full_name`, an entirely separate, independently attacker-controlled field in the same JSON body. [1](#0-0) [2](#0-1)  Since the attacker crafts the raw POST body themselves (this is a direct HTTP request to `/webhooks`, not a GitHub-relayed webhook), nothing enforces that `repository.owner.login` and the owner segment of `repository.full_name` refer to the same organization.

### Finding Description
The intended binding is: **verifying org (used to pick `webhook_secret`) == org owning the `Stack` being mutated**. Concretely this should mean `params.repository.owner.login == params.repository.full_name.split('/').first`.

Tracing the code:
- `WebhooksController#repository_owner` reads `params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')` directly from the raw JSON body the attacker POSTs. [3](#0-2) 
- `verify_signature` uses that value to select `Shipit.github(organization: repository_owner)` and validate the signature against that org's `webhook_secret`. [4](#0-3) 
- `GitHubApp#verify_webhook_signature` returns `true` unconditionally when the selected org has no `webhook_secret` configured (`return true unless webhook_secret`). [5](#0-4)  This is also documented as an explicit "(optional)" config in `docs/setup.md`, confirming orgs without a secret are supported/expected.
- Once signature verification passes, `Shipit::Webhooks.for_event('pull_request').each { |handler| handler.call(params) }` dispatches the **same, unmodified `params`** (including the independently-controlled `repository.full_name`) to `LabeledHandler`. [6](#0-5) 
- `LabeledHandler#repository` resolves the target `Repository` via `Shipit::Repository.from_github_repo_name(params.repository.full_name)` — using only `full_name`, never cross-checking `repository.owner.login`. [2](#0-1) 
- `handle` then calls `stack.archive!`/`stack.unarchive!` on the `ReviewStackAdapter` wrapping that repository's `review_stacks`, gated only by that repository's own `provisioning_behavior`/`provisioning_label_name` config and the labels/state in the payload — none of which involve org identity. [7](#0-6) [8](#0-7) 
- `Repository.from_github_repo_name` just does `find_by(owner:, name:)` from the split `full_name` string — no relation at all to the `repository.owner.login` value used for signing. [9](#0-8) 

No existing guard checks the two org-identifying fields for equality: `drop_unhandled_event` only checks event type presence, `check_if_ping` only checks event name, and there is no `ExplicitParameters` validation tying `repository.owner.login` to `repository.full_name`. The `LabeledHandler` params schema requires `repository.full_name` but does not even require `repository.owner`. [10](#0-9) 

**Attacker's exact request**: POST `/webhooks` with header `X-Github-Event: pull_request`, body:
```json
{
  "action": "labeled",
  "number": 1,
  "pull_request": { ..., "state": "open", "labels": [{"name": "<org-B-provisioning-label>"}] , "head": {"ref": "...", "sha": "..."}, "user": {"login": "attacker"} },
  "repository": { "full_name": "orgB/repoB", "owner": { "login": "orgA-no-secret" } },
  "sender": { "login": "attacker" }
}
```
If `orgA-no-secret` is any org configured in Shipit's `github:` config without a `webhook_secret` (or one whose secret the attacker legitimately has because they own that org's app), signature verification trivially passes (`verify_webhook_signature` returns `true`), while the mutation targets org B's (`orgB/repoB`) already-archived `ReviewStack`, flipping `archived?` to `false` and re-queuing it for provisioning via `Shipit::ReviewStackProvisioningQueue.add(stack)`. [11](#0-10) 

### Impact Explanation
This is a payload for one organization's webhook (org A, unauthenticated or self-controlled) mutating another organization's `Stack`/`ReviewStack` record — this matches the Critical category "a payload for one repository mutating another's stack." An attacker can reactivate (unarchive) a decommissioned review stack belonging to an org they do not control, causing `Shipit::ReviewStackProvisioningQueue.add(stack)` and `stack.unarchive!` to run, which can lead to re-provisioning and later accepting deploys/pushes on infrastructure the attacker has no legitimate access to. It is repeatable against any target repository that has `review_stacks_enabled` and a known `provisioning_label_name`/`full_name`, as long as any org in the Shipit deployment has no `webhook_secret` configured (a documented, optional setting) or the attacker legitimately controls a second org's app registered in the same Shipit instance.

### Likelihood Explanation
Preconditions: (1) the Shipit deployment must have at least one configured GitHub org with no `webhook_secret` (explicitly supported/optional per `docs/setup.md` and the default templates ship it blank), or the attacker controls a second org's GitHub App registered on the same Shipit host; (2) the target org/repository must have `review_stacks_enabled` with a known `provisioning_label_name` (discoverable via public repo labels) and an existing archived `ReviewStack` for a given PR number/environment. Given multi-org Shipit deployments are an explicitly documented supported configuration (`docs/setup.md` "Using Multiple Github Applications"), and webhook secrets are optional, this is operationally realistic and requires only a single crafted HTTP POST with no GitHub or Shipit credentials.

### Recommendation
In `WebhooksController#verify_signature`/`#create`, or in `Shipit::Webhooks::Handlers::Handler`, enforce that the organization used to verify the signature matches the organization implied by every repository reference processed by the handler (i.e., validate `params.repository.owner.login == params.repository.full_name.split('/').first` before dispatch, or better, derive `full_name`'s owner solely from the already-verified `repository_owner` rather than trusting a second independent field). Reject the webhook (422) on mismatch.

### Proof of Concept
```ruby
# test/controllers/webhooks_controller_test.rb (new test)
test "cross-org payload cannot unarchive another org's review stack via an org with no webhook_secret" do
  org_a = "org-a-no-secret" # configured in test github config w/o webhook_secret
  repo_b = shipit_repositories(:shipit) # owner: "shopify", name: "shipit-engine"
  repo_b.update!(review_stacks_enabled: true, provisioning_behavior: :allow_with_label,
                 provisioning_label_name: "deploy-me")
  stack = create_archived_review_stack_for(repo_b) # archived? == true

  request.headers['X-Github-Event'] = 'pull_request'
  payload = {
    "action" => "labeled",
    "number" => stack.pull_request_number,
    "pull_request" => {
      "id" => 1, "number" => stack.pull_request_number, "url" => "https://api.github.com/x",
      "title" => "x", "state" => "open", "additions" => 1, "deletions" => 1,
      "head" => { "sha" => "abc123", "ref" => "feature" },
      "user" => { "login" => "attacker" },
      "assignees" => [],
      "labels" => [{ "name" => "deploy-me" }]
    },
    "repository" => { "full_name" => repo_b.full_name, "owner" => { "login" => org_a } },
    "sender" => { "login" => "attacker" }
  }.to_json

  post :create, body: payload, as: :json

  assert_response :ok
  assert_not stack.reload.archived?, "org A's webhook must not be able to unarchive org B's stack"
end
```
Before the fix: the assertion fails (`archived?` becomes `false`, `Shipit::ReviewStackProvisioningQueue.add` is invoked) because `repository_owner` (`org-a-no-secret`) and `repository.full_name`'s owner (`repo_b.owner`) are never compared. After adding the equality check, the request should be rejected with `422` and the stack must remain archived.

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end

          def archive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no Stack exists. Ignoring."
              )
              return true
            end
            return if stack.archived?

            stack.remove_from_provisioning_queue
            stack.deprovision
            stack.archive!(user, *args, &block)
          end

          def unarchive!(*args, &block)
            if stack.blank?
              Rails.logger.info(
                "Processing #{action} event for #{repo_name} PR #{pr_number} but no ReviewStack exists. Creating."
              )
              return create!
            end
            return unless stack.archived?

            stack.transaction do
              Shipit::ReviewStackProvisioningQueue.add(stack)
              stack.unarchive!(*args, &block)
            end
          end
