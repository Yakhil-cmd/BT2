### Title
Cross-organization webhook signature confusion allows unauthorized triggering of syncs/deploys on repositories belonging to a different GitHub organization - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/organization secret to validate the HMAC signature against using `repository_owner` (parsed from the same untrusted JSON body it is trying to authenticate), while the event handlers that actually act on the payload (e.g. `PushHandler`) resolve the target repository from a completely different field, `repository.full_name`. In multi-organization Shipit deployments, this breaks the binding "organization whose secret authenticated the request == repository that is written to," letting an attacker who legitimately controls one configured organization's webhook secret forge events that mutate stacks belonging to a different organization.

### Finding Description
Shipit supports hosting multiple GitHub organizations from a single instance, each with its own `webhook_secret`, configured under `github.<org>.webhook_secret` [1](#0-0) . At runtime, `Shipit.github(organization:)` looks up the app config by organization name and instantiates a `GitHubApp` scoped to that org/secret [2](#0-1) .

The webhook signature check derives the organization purely from the incoming payload:
```
def verify_signature
  github_app = Shipit.github(organization: repository_owner)
  verified = github_app.verify_webhook_signature(request.headers['X-Hub-Signature'], request.raw_post)
  ...
end

def repository_owner
  params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
end
``` [3](#0-2) 

This only proves the request was signed with the secret belonging to whatever organization `repository.owner.login` claims — it does not constrain which repository the event is allowed to reference. The actual dispatched handler, e.g. `PushHandler`, resolves the target purely from `repository.full_name`:
```
def repository_name
  payload.dig('repository', 'full_name')
end

def stacks
  @stacks ||= Repository.from_github_repo_name(repository_name)&.stacks || Stack.none
end
``` [4](#0-3) 
```
def process
  stacks.not_archived.where(branch:).find_each { |stack| stack.sync_github(expected_head_sha: params.after) }
end
``` [5](#0-4) 

The same pattern (`Repository.from_github_repo_name(params.repository.full_name)`) is used across all pull-request handlers to select the repository/review-stack acted on, independent of `repository.owner.login` [6](#0-5) .

**The trust binding broken:** `organization authenticated (via webhook_secret keyed off repository.owner.login) == repository written (resolved via repository.full_name)`. Nothing in `WebhooksController` or the handlers verifies that `repository.full_name`'s owner segment matches `repository.owner.login`, i.e. the organization whose secret validated the HMAC.

An attacker who is a legitimate GitHub org admin/webhook configurator for one of the organizations onboarded onto a shared Shipit instance (`OrgA`, with a valid `webhook_secret` they know because they configured the GitHub App webhook themselves) can craft an arbitrary payload, set `repository.owner.login: "OrgA"` (so `verify_signature` selects and validates against `OrgA`'s secret, which they possess and can correctly HMAC-sign), but set `repository.full_name: "OrgB/some-repo"` where `OrgB` is a different, unrelated organization also hosted on the same Shipit instance. Since the signature only proves knowledge of OrgA's secret and never re-validates that `full_name`'s owner matches the signing organization, the forged event is accepted and dispatched to handlers that act on `OrgB/some-repo`.

### Impact Explanation
For the `push` event this triggers `GithubSyncJob`/`stack.sync_github` on stacks belonging to a repository the attacker does not control, which can trigger unauthorized deploy/rollback pipelines to sync to an attacker-chosen `expected_head_sha` for a victim organization's stack — an unauthorized deploy trigger across organizational trust boundaries, satisfying the Critical bar for "cross-repository writes / unauthorized deploy." For `pull_request` events, the attacker can spoof opened/closed/reopened/labeled actions against `OrgB`'s review stacks (create/archive/unarchive review stacks) despite having no relationship to `OrgB`'s repository.

### Likelihood Explanation
This is only exploitable on Shipit instances configured with the multi-organization github config (`github.<org1>`, `github.<org2>`, ...) that also host stacks for organizations the attacker does not control — a supported, documented configuration [1](#0-0) . The attacker needs no Shipit account, session, or API token — only knowledge of one onboarded org's webhook secret (which they legitimately hold as that org's own GitHub App/webhook configurator), satisfying the "unprivileged attacker relative to the other organization's resources" requirement.

### Recommendation
In `WebhooksController#verify_signature`, after successfully verifying the signature against `repository_owner`'s secret, additionally assert that every repository referenced elsewhere in the payload (`repository.full_name`, and any repos referenced by handler-specific fields) belongs to that same verified organization before dispatching to handlers. Equivalently, handlers should derive the organization solely from the already-authenticated `repository_owner` rather than trusting `repository.full_name` in isolation, or reject payloads where the owner segment of `full_name` differs from `repository.owner.login`.

### Proof of Concept
1. Configure Shipit with two organizations, `OrgA` and `OrgB`, each with its own `webhook_secret` (multi-org config as in `docs/setup.md`).
2. As a legitimate admin of `OrgA`'s GitHub App, obtain `OrgA`'s `webhook_secret` (you configured it yourself).
3. Craft a push-webhook JSON body:
```json
{
  "ref": "refs/heads/master",
  "after": "<attacker-chosen sha>",
  "repository": {
    "owner": { "login": "OrgA" },
    "full_name": "OrgB/victim-repo"
  }
}
```
4. Compute `X-Hub-Signature: sha1=HMAC-SHA1(OrgA_webhook_secret, body)`.
5. POST to `/webhooks` with `X-Github-Event: push`.
6. `verify_signature` calls `Shipit.github(organization: "OrgA")` and validates successfully against the attacker-known `OrgA` secret [7](#0-6) .
7. `PushHandler` resolves `Repository.from_github_repo_name("OrgB/victim-repo")` and, if a matching branch/stack exists, invokes `stack.sync_github(expected_head_sha: "<attacker-chosen sha>")` on `OrgB`'s stack [5](#0-4)  — an action never authorized by `OrgB`.

  def github(organization: github_default_organization)
    # Backward compatibility
    # nil signifies the single github app config schema is being used
    if github_default_organization.nil?
      config = secrets.github
    else
      config = github_app_config(organization)
      raise GithubOrganizationUnknown, organization if config.nil?
    end
    @github ||= {}
    @github[organization] ||= GitHubApp.new(organization, config)
  end

  def github_default_organization
    return nil unless secrets&.github

    org = secrets.github.keys.first
    TOP_LEVEL_GH_KEYS.include?(org) ? nil : org
  end

  def github_organizations
    return [nil] unless github_default_organization

    secrets.github.keys
  end

  def github_app_config(organization)
    github_config = secrets.github.deep_transform_keys(&:downcase)
    github_organization = organization.downcase.to_sym
    github_config[github_organization]
  end
```

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
