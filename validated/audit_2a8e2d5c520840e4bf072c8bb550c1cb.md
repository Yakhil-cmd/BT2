### Title
Position NFT buyers can be scammed by sellers draining collateral before transfer — (File: contracts/position-nft/src/contract.rs)

### Summary
A lending account's entire collateral and debt travel with its position NFT (`account_id == token_id`), and the controller resolves ownership live via `owner_of` on every owner-gated call. There is no lock/escrow mechanism tying the NFT to the account's collateral. A seller can list a collateral-rich position on a secondary marketplace, then call `withdraw` (or `borrow`/`swap_collateral`/`repay_debt_with_collateral` to arbitrary recipients) at any moment up to — or atomically ordered just before — the marketplace transfer executes, leaving the buyer with an empty or debt-laden NFT.

### Finding Description
The position-nft README states: "Transferring the token transfers the whole position. Nothing in the controller changes on transfer... Collateral and debt both move with the token." The controller stores no owner; `try_account_owner` resolves the holder live through `owner_of`. `withdraw` is owner/delegate-gated only and remains callable even during global pause ("open" in the pause column). A delegate can also `withdraw`/`borrow` `to` arbitrary recipients, and stale `DelegateGrant`s re-arm if the token returns to `granted_by`.

Concretely:
1. Seller supplies large collateral to account `N`, lists token `N` for sale.
2. Buyer submits a purchase transaction expecting the collateral shown by `get_account_positions`/`get_collateral_amount` (a snapshot view; `Enumerable` reads are explicitly "a snapshot").
3. Seller calls `controller.withdraw(seller, N, [(market, 0)], to)` — amount `0` means full withdrawal — in a transaction sequenced before the sale (or inside a malicious marketplace/settlement flow where the seller's leg executes first).
4. Buyer receives token `N` owning an account with no collateral, or worse, with debt the seller max-borrowed against it (`borrow` to an arbitrary `to` recipient is permitted while HF stays ≥ 1).

Unlike the source report, Soroban has no public mempool to frontrun in the classic sense, but the vulnerability does not depend on mempool sniping: nothing prevents the seller from draining the position in any transaction ordered before the atomic transfer, and there is no protocol-level lock, so the same "buy an empty club" scam is fully reachable by an unprivileged address.

### Impact Explanation
Buyers on secondary markets pay for a position whose value is its collateral, then receive a drained NFT — direct theft of buyer funds at the social/settlement layer, plus reputational damage identical to the source report. Acquired debt also travels with the token, so a buyer can receive a near-liquidatable account.

### Likelihood Explanation
Any position holder can do this with one `withdraw` call; no privileges, no timing window tighter than normal transaction ordering, and it can be repeated across listings. The only mitigations are off-chain (buyer-side atomic verification inside the purchase transaction), which generic NFT marketplaces do not perform.

### Recommendation
Add a lock/locker mechanism analogous to the source recommendation: a per-account `locked` flag in the controller that blocks `withdraw`, `borrow`, `swap_collateral`, `repay_debt_with_collateral`, `migrate_from_blend`, and `update_account_threshold`-risk changes while set; allow the NFT `transfer`/`transfer_from` path (or an explicit `lock(account_id)` entrypoint) to set it, and let the new owner unlock after a short timelock. Alternatively, expose a controller view that marketplace contracts can call atomically within the purchase transaction to assert minimum collateral and maximum debt, and document that settlement contracts must enforce it.

### Proof of Concept
1. `controller.supply(seller, 0, spoke, [(hub_asset(USDC), 1_000_000e7)])` → returns `account_id = N` (NFT minted to seller).
2. Seller lists token `N` on a marketplace at a price reflecting $1M collateral.
3. Seller submits `controller.withdraw(seller, N, [(hub_asset(USDC), 0)], to = seller)` (zero = full withdrawal; `withdraw` is open even under global pause) sequenced ahead of the sale, or uses a delegate grant (`add_delegate`) that withdraws to an arbitrary `to`.
4. Marketplace executes `position_nft.transfer_from(...)`; buyer now owns token `N` with zero collateral — `get_account_positions(N)` is empty — and no recourse, since all seller actions were authorized at execution time (`owner_of` resolved to the seller until the transfer).
