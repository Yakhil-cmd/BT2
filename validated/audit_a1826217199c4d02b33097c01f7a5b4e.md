### Title
Skill search ranking can be manipulated via cheap name-matching and star-count signals, promoting attacker-controlled skills for installation - (File: pkg/cmd/skills/search/search.go)

### Summary
`gh skill search` ranks results using `relevanceScore`, which awards large, easily-gamed point bonuses for exact/partial skill-name matches and repository star counts fetched directly from the GitHub REST API, with no verification of the repository's authenticity, ownership, or content safety. [1](#0-0) 
An attacker publishes a public repository containing a `SKILL.md` whose skill name exactly matches a popular search query, and inflates the repo's star count (a cheap, unprivileged, sybil-style action), guaranteeing the malicious skill ranks first or near first among genuine results.

### Finding Description
`relevanceScore` computes a ranking score from four signals: exact name match (3000 pts), partial match (1000 pts), namespace match (500 pts), description match (100 pts), and a `sqrt(stars)*30` bonus. [2](#0-1) 
None of these signals reflect the trustworthiness, safety, or provenance of the code being installed — they are all directly and cheaply controllable by the repository's own author: the skill name is chosen by the attacker, and stars can be trivially inflated with throwaway/bot accounts (an unprivileged, remote, sybil-style action analogous to spamming near-zero trades to skew `Pricing.recordTrade`'s average). `rankByRelevance` then sorts purely by this manipulable score. [3](#0-2) 

The ranked, attacker-influenced list is presented directly to the user in `promptInstall`, which displays the star count as a trust signal ("★ 1.7k") next to each option and lets the user multi-select entries to install. [4](#0-3) 
Selected results are installed by shelling out to `gh skills install <repo> <skill>`, i.e., fetching and installing the attacker's skill content for execution by an AI agent. [5](#0-4) 

This matches the reported bug class precisely: just as spamming self-matched, near-zero trades let an attacker skew `Pricing`'s hourly average price with no real economic cost, spamming stars/crafting an exact-name-match repo lets an attacker skew the search ranking's "trust" signal with negligible cost, steering unprivileged victims toward installing and executing attacker-controlled code.

### Impact Explanation
A user running `gh skill search <popular-term>` can be shown a malicious, attacker-controlled skill as the top or a highly-ranked result, ahead of legitimate skills, purely because the attacker crafted a matching skill name and/or inflated stars. If the user trusts the ranking/star display and installs it, this leads to installation and execution of attacker-supplied instructions/code within the user's AI agent environment — directly hitting the "extension or skill install and execution" attack surface called out in the rules.

### Likelihood Explanation
Likelihood is moderate to high: creating a public repo with a chosen skill name and inflating star counts via bot/sybil accounts requires no privileges and no interaction with GitHub CLI internals — it's a standard, low-cost technique already used for supply-chain/typosquatting attacks on package registries and extension marketplaces. The `gh` tool provides no additional trust verification (e.g., signing, allow-listing, provenance checks) for skills beyond this gameable relevance score.

### Recommendation
Do not let attacker-controlled signals (self-chosen names, raw star counts) dominate ranking or be presented as an implicit trust indicator. At minimum:
- De-weight or remove the star-count bonus from `relevanceScore`, or replace it with a metric less trivially inflatable (e.g., normalized/verified engagement, or an explicit "unverified" warning).
- Clearly label results as unverified/untrusted regardless of ranking, and avoid displaying stars as an implicit safety signal in `promptInstall`.
- Consider requiring explicit confirmation showing full repo owner/URL before installation, and/or integrating allow-listing or provenance/attestation checks for skills analogous to the `gh attestation verify` flow already in the codebase.

### Proof of Concept
1. Attacker creates public repo `attacker/gh-terraform` containing `skills/terraform/SKILL.md` (exact name match for the common query "terraform").
2. Attacker uses sybil/bot GitHub accounts to star the repo heavily (cheap, unprivileged).
3. Victim runs `gh skill search terraform`.
4. `relevanceScore` grants the attacker's entry 3000 (exact name match) + `sqrt(stars)*30` points, `rankByRelevance` places it at/near the top of results shown by `promptInstall` with a prominent star badge. [6](#0-5) 
5. Victim selects the top-ranked result, triggering `exec.Command(opts.ExecutablePath, "skills", "install", s.Repo, installArg, ...)`, installing the attacker's `SKILL.md` for use by an AI agent. [7](#0-6)

// relevanceScore computes a numeric ranking score for a search result.
// Higher scores rank first. Signals (in priority order):
//   - Exact skill name match (3 000 points)
//   - Partial skill name match (1 000 points)
//   - Namespace match (500 points)
//   - Description contains query (100 points)
//   - Repository stars (sqrt bonus, ~2 400 for 6k stars)
func relevanceScore(s skillResult, query string) int {
	term := strings.ToLower(query)
	termHyphen := strings.ReplaceAll(term, " ", "-")
	score := 0

	// Name match. Normalize spaces to hyphens since skill directory names
	// use hyphens as word separators (e.g. query "mcp apps" > "mcp-apps").
	skillLower := strings.ToLower(s.SkillName)
	if skillLower == term || skillLower == termHyphen {
		score += 3_000
	} else if strings.Contains(skillLower, term) || strings.Contains(skillLower, termHyphen) {
		score += 1_000
	}

	// Namespace match.
	if s.Namespace != "" && strings.Contains(strings.ToLower(s.Namespace), term) {
		score += 500
	}

	// Description match.
	if strings.Contains(strings.ToLower(s.Description), term) {
		score += 100
	}

	// Stars bonus: use √n scaling so popular repos rank meaningfully higher
	// without completely drowning out less-popular but more relevant results.
	if s.Stars > 0 {
		score += int(math.Sqrt(float64(s.Stars)) * 30)
	}

	return score
}

// rankByRelevance sorts results by multi-signal score, highest first.
func rankByRelevance(skills []skillResult, query string) {
	sort.SliceStable(skills, func(i, j int) bool {
		return relevanceScore(skills[i], query) > relevanceScore(skills[j], query)
	})
}
