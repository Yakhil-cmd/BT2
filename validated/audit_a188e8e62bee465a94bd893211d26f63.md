### Title
Position NFT can be transferred to an address that can never authorize, permanently freezing the position's collateral and debt - ([File: contracts/position-nft/src/contract.rs](https://github.com/Jortegata/rs-lending-xlm--020))

### Summary
The `transfer` / `transfer_from` entrypoints on the position NFT perform no validation that the recipient is an address capable of acting on the position. A position token can be sent to a Stellar account address that was never created (and may never be created — e.g., a random or mis-keyed `G...`/`C...` address). Because the controller resolves ownership exclusively via `owner_of(account_id)` and every owner-gated controller verb calls `require_auth` on that owner, the account's collateral and debt become permanently unreachable once the holder cannot sign. This is the direct analog of the bullvbear `transferPosition` finding: no check that the recipient can receive, resulting in assets stuck in the contract.

### Finding Description
`PositionNft` exports the stock OpenZeppelin `NonFungibleToken` trait unchanged; `contract.rs` defines no `transfer`/`transfer_from` overrides and no recipient sanity check anywhere (contracts/position-nft/src/contract.rs:131-173). The README confirms there is no owner record in the controller — "the controller stores no owner address for an account; it calls `owner_of(account_id)` on this contract every time" (contracts/position-nft/README.md:5). All owner-gated verbs (`withdraw`, `borrow`, `multiply`, `supply` on behalf, `add_delegate`, etc.) authenticate the NFT owner. On Soroban/Stellar, an `Address` is just a typed identifier: any ed25519 pubkey or contract id is a valid recipient, including addresses that can never produce `require_auth` (a `G...` account that is never created/funded, or a `C...` contract id under which no auth-capable contract is ever deployed). There is no holder-facing burn and no rescue path: `burn` is controller-only and only runs when an account is emptied through owner actions or liquidation (contract.rs:88-95; README.md:145-150). A solvent account cannot be liquidated, so once the holder cannot sign, its collateral is stuck in the pool forever.

### Impact Explanation
Permanent freezing of user funds: the transferred position's supplied collateral can never be withdrawn, and the account can never be deleted because emptying it requires owner authorization. This matches the accepted severity of the source finding (Medium) — the loss is self-inflicted but total and unrecoverable for that position.

### Likelihood Explanation
Requires a user (or a buggy wallet/marketplace contract integrating the standard NFT interface — the README explicitly advertises the position as "an ordinary transferable non-fungible token" for wallets/marketplaces, README.md:6-9) to transfer to an address that cannot authorize. Integrating contracts and scripted ops can hit this more plausibly than a careful wallet (e.g., forwarding `to` computed from an uninitialized field or a contract id with no auth). Self-inflicted, so Medium-Low.

### Recommendation
Override `transfer` and `transfer_from` in `PositionNft` to reject recipients that cannot act, or at minimum document/whitelist-check: e.g., reject contract addresses with no deployed contract is hard on-chain, but a practical mitigation is to emit/validate or require the recipient to have already interacted (e.g., `balance`/`Balance` entry presence is insufficient). The robust protocol-level mitigation is a claim-style flow (`transfer` to pending + `accept` by recipient `require_auth`), which guarantees the new holder can authorize before ownership moves.

### Proof of Concept
```rust
// contracts/position-nft/src/test.rs pattern
#[test]
fn transfer_to_never_created_address_freezes_position() {
    let env = Env::default();
    env.mock_all_auths();
    let (_controller, client) = setup(&env);
    let alice = Address::generate(&env);
    // A "dead" recipient: any G/C address that can never produce require_auth
    // (e.g., a mistyped pubkey or an undeployed contract id).
    let dead = Address::generate(&env); // stands in for an unusable address
    let token_id = client.mint(&alice);

    client.transfer(&alice, &dead, &token_id);
    assert_eq!(client.owner_of(&token_id), dead);

    // In production (no mock_all_auths): every controller call resolving
    // owner_of(token_id) -> dead and calling dead.require_auth() now fails.
    // withdraw, borrow, add_delegate, and even repay-into-self flows gated on
    // the owner are unreachable; the account is solvent so it cannot be
    // liquidated; burn is controller-only on account deletion. Collateral is
    // permanently locked in the pool.
}
```
