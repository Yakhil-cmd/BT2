### Title
Non-ASCII/quoted filenames silently bypass diff-based security review via header regex in `parse_diff_into_files` - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`parse_diff_into_files` (and its sibling `extract_file_paths_from_diff`) parses `git diff` output by matching the literal pattern `^a/(.+?) b/(.+)$` against the `diff --git ...` header line. `get_git_diff` invokes git via `GIT_CMD`, which does **not** set `-c core.quotePath=false`, so filenames containing non-ASCII bytes (or embedded quotes/backslashes/tabs) are emitted by git as C-quoted strings (e.g. `diff --git "a/\346\226\207.py" "b/\346\226\207.py"`) rather than raw `a/...  b/...` text.

### Finding Description
`get_git_diff` in `plugins/security-guidance/hooks/gitutil.py` builds its diff command from `GIT_CMD` [1](#0-0) , which lacks `core.quotePath=false` — unlike `_git_name_only`, which explicitly sets it for the same reason (`-c core.quotePath=false -z` "keeps non-ASCII and space-containing paths intact") [2](#0-1) . Because `core.quotePath` defaults to `true` in git, any path containing bytes ≥0x80 (i.e., non-ASCII/unicode filenames) or special characters is rendered as a double-quoted, C-escaped string in the `diff --git` header. `parse_diff_into_files` then matches that header line against `^a/(.+?) b/(.+)$` [3](#0-2) , which anchors on a literal `a/` at the start of the line and fails to match a quoted header (which starts with `"a/...`). When the match fails, `continue` is executed and the entire file's diff block — including all `+`/`-` hunk lines — is dropped from the returned `files` list, meaning no diff content for that file is ever surfaced to the LLM security reviewer or to `filter_preexisting_from_diff`. The identical regex/logic exists in `extract_file_paths_from_diff` [4](#0-3) , so the file also silently disappears from the list of "touched" reviewable paths used elsewhere in the pipeline.

An attacker who can influence repository content (e.g., an agent writing a file with a unicode name, or a crafted PR/commit containing a unicode-named source file) can name a malicious source file with any non-ASCII character to guarantee its diff block is dropped from `parse_diff_into_files`'s output, hiding the change from the Stop-hook LLM review and commit/push review pipelines in `security_reminder_hook.py` that consume `parse_diff_into_files`/`extract_file_paths_from_diff`.

### Impact Explanation
This is a real gap in the **security-guidance plugin's own review coverage**: dangerous code changes hidden behind unicode-quoted filenames are never sent to the Stop-hook LLM reviewer, `analyze_code_security`, or the commit/push review, weakening the "reviewable-source filtering must not let attacker-crafted filenames hide dangerous source changes" invariant. However, I could not confirm that this plugin performs any hard `PreToolUse` deny/approval gating over Bash or file-write tool calls — everything examined here (`emit_metrics`, `exit(2)` continuation flow, `additionalContext` injection) is advisory: it nags Claude to continue and address findings, not a blocking permission control. The actual approval/deny mechanism for local command execution in Claude Code is a separate, core permission system unrelated to this file. I was unable to verify within this module that bypassing this diff-parsing filter directly disables or bypasses any hard approval/deny gate, so the specific claimed impact — "Unauthorized local command execution that bypasses Claude Code approval or deny controls" — is not substantiated by the code reachable from `parse_diff_into_files`. The concretely demonstrable impact is reduced/bypassed **security review coverage**, not bypassed command-execution authorization.

### Likelihood Explanation
Preconditions are low: any attacker who can get a source file with a non-ASCII filename into the diff (trivial — just choose a filename with a unicode character) will trigger this behavior every time, since git's default `core.quotePath=true` quoting is deterministic. This is highly repeatable and requires no special git config, symlinks, or worktree tricks beyond a plain unicode filename.

### Recommendation
Add `-c core.quotePath=false` to `GIT_CMD` (or specifically to the `git diff` invocation in `get_git_diff`), and update the header-parsing regex in `parse_diff_into_files`/`extract_file_paths_from_diff` to also handle quoted (`"a/... b/..."`) headers as a defense-in-depth fallback, mirroring the existing handling in `_git_name_only`.

def extract_file_paths_from_diff(diff_output):
    """
    Extract file paths from unified diff output (without content).
    Only includes files with source code extensions.
    Returns a list of file paths.
    """
    if not diff_output or not diff_output.strip():
        return []

    paths = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue
        file_path = header_match.group(2) or header_match.group(1) or ''
        if not _is_reviewable_source(file_path):
            continue
        paths.append(file_path)

    return paths
