**Analysis:**

The transaction-argument construction path treats `FixedPoint32::create_from_raw_value` and `FixedPoint64::create_from_raw_value` as whitelisted constructors invoked through the real Move VM (`validate_and_construct` → `load_constructor_function` → `execute_pack_function`), so the raw value is deserialized from BCS strictly according to the declared parameter width — 8 bytes for the `u64` argument of `FixedPoint32::create_from_raw_value`, 16 bytes for the `u128` argument of `FixedPoint64::create_from_raw_value` — via `read_n_bytes` in `recursively_construct_arg`, matching the `U64`/`U128` cases in the type-size table. [1](#0-0) [2](#0-1) 

`create_from_raw_value` is intentionally unchecked by design in both Move modules — its own spec explicitly states `aborts_if false; ensures result.value == value;`, meaning any value representable by the underlying integer type (`u64` for `FixedPoint32`, `u128` for `FixedPoint64`) is a legitimate construction, not a corrupted or out-of-range one. [3](#0-2) [4](#0-3) 

Passing `raw_value = u128::MAX` to `FixedPoint64::create_from_raw_value` is simply the maximum value of the `u128` field — there is no narrower "valid range" being bypassed; the field itself is a `u128`, so any `u128` value is in-range by construction. Downstream arithmetic operations that consume a `FixedPoint64`/`FixedPoint32` (`add`, `sub`, `multiply_u128`, `divide_u128`, etc.) perform their own explicit bounds checks with `assert!` before doing unsafe casts, causing a well-defined Move abort (reverting the transaction) rather than silent overflow or corruption if an extreme value is later misused. [5](#0-4) [6](#0-5) 

There is no path here where this reaches "privileged accounting logic" via a bypassed admission check — `legacy_is_valid_txn_arg` only validates the *type* is whitelisted, and the actual value construction runs through normal, gas-metered, type-safe Move VM execution of the real framework function, with no numeric range omitted that the Move spec itself requires. [7](#0-6) 

This does not meet the admission-impact bar: no sender/signer/sequence/fee-payer/chain-id binding is broken, and no privileged operation is unlocked — the behavior is the intended, specified semantics of the constructor, with overflow protection correctly deferred to (and enforced by) the arithmetic functions that actually operate on the value.

    /// Multiply a u128 integer by a fixed-point number, truncating any
    /// fractional part of the product. This will abort if the product
    /// overflows.
    public fun multiply_u128(val: u128, multiplier: FixedPoint64): u128 {
        // The product of two 128 bit values has 256 bits, so perform the
        // multiplication with u256 types and keep the full 256 bit product
        // to avoid losing accuracy.
        let unscaled_product = (val as u256) * (multiplier.value as u256);
        // The unscaled product has 64 fractional bits (from the multiplier)
        // so rescale it by shifting away the low bits.
        let product = unscaled_product >> 64;
        // Check whether the value is too large.
        assert!(product <= MAX_U128, EMULTIPLICATION);
        (product as u128)
    }
