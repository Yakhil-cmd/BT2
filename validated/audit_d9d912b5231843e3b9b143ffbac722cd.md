### Title
Cross-organization webhook impersonation via unverified `repository.full_name` binding - (File: `app/controllers/shipit/webhooks_controller.rb`)

### Summary
`WebhooksController#verify_signature` selects which GitHub App/webhook secret to validate a request against using `repository.owner.login` (or `organization.login`) from the *unverified* JSON body, then checks the HMAC signature over the raw request body with that secret. Once verification passes, every webhook handler (`PushHandler`, the `PullRequest::*` handlers, etc.) independently re-reads a *different* field from the same body — `repository.full_name` — to resolve the target `Repository`/`Stack` to act on. Nothing cross-checks that `repository.full_name`'s owner segment actually matches the `repository.owner.login`/`organization.login` value that was used to pick the signing secret. This breaks the trust binding "organization that authenticated" == "repository that is written."

### Finding Description
`verify_signature` resolves the signing GitHub App from a value taken directly out of the JSON payload: [1](#0-0) [2](#0-1) 

The signature check itself only proves the body was HMAC-signed with the secret belonging to whatever organization `repository_owner` resolves to — it does not bind or constrain any other field inside that same body: [3](#0-2) 

After signature verification succeeds, `params = JSON.parse(request.raw_post)` is dispatched unmodified to handlers: [4](#0-3) 

Every handler determines which repository/stack to act on via `payload.dig('repository', 'full_name')`, a field entirely separate from the one used for signature-org selection: [5](#0-4) 

This pattern repeats in concrete handlers that trigger real actions, e.g. `PushHandler#process` syncs a stack from an arbitrary `full_name`-resolved repository: [6](#0-5) 

and `PullRequest::OpenedHandler#process` creates/archives review stacks keyed off `params.repository.full_name`: [7](#0-6) 

In a genuine GitHub-generated webhook, `repository.owner.login` and the owner segment of `repository.full_name` always originate from the same repository object and are therefore consistent. However, nothing in `WebhooksController` or `Handler` enforces that consistency; an attacker who can produce a validly-signed but hand-crafted JSON body (i.e., anyone who legitimately administers one GitHub App installation onboarded onto the same multi-tenant Shipit instance, and thus knows that installation's `webhook_secret`) can set `repository.owner.login` to their own org (so signature verification passes) while setting `repository.full_name` to point at a completely different organization's repository that is also tracked by this Shipit instance.

### Impact Explanation
An attacker who controls one legitimate org's GitHub App webhook secret in a multi-tenant Shipit deployment (`docs/setup.md`'s "Using Multiple Github Applications" configuration) can forge signed webhook deliveries whose `repository.full_name` targets any other onboarded repository. Confirmed reachable effects include:
- Forcing `stack.sync_github` (`PushHandler`) against a victim org's stack.
- Creating/archiving/unarchiving review stacks and mutating pull-request state (`PullRequest::OpenedHandler`, `ClosedHandler`, `ReopenedHandler`, `Labeled/UnlabeledHandler`) for a victim org's repository, without holding any GitHub or Shipit permission on that repository.

This is a cross-repository write across an organization boundary that the signature check was supposed to enforce, satisfying the "cross-repository writes" / authorization-escalation impact bar.

### Likelihood Explanation
Requires the attacker to be an administrator of at least one legitimate GitHub App installation that is configured in the same Shipit instance's multi-organization `secrets.yml` (per `docs/setup.md`), i.e., they know one valid `webhook_secret` but have no access to other orgs' repositories or Shipit accounts. This is a realistic scenario for any Shipit deployment shared across several orgs/teams (a common configuration explicitly documented in `docs/setup.md`).

### Recommendation
In `WebhooksController#verify_signature`/`Handler`, after determining `repository_owner`, require that every field used later to resolve a `Repository`/`Stack` (`repository.full_name`, `organization.login`) is consistent with the organization whose secret validated the signature — e.g., reject the request if `repository.full_name.split('/').first` does not case-insensitively match `repository_owner`/`organization.login`.

### Proof of Concept
1. Shipit is configured for two organizations, `attacker-org` and `victim-org`, each with its own GitHub App and `webhook_secret` (per the documented multi-org config).
2. Attacker (who owns/administers `attacker-org`'s GitHub App and therefore knows its `webhook_secret`) crafts:
```json
{
  "ref": "refs/heads/master",
  "after": "deadbeef",
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  }
}
```
3. Attacker computes `sha1=HMAC(attacker-org secret, body)` and POSTs to `/webhooks` with `X-Github-Event: push` and that signature.
4. `verify_signature` resolves `repository_owner` to `attacker-org`, verifies against `attacker-org`'s secret — passes.
5. `PushHandler` resolves the target stack via `payload.dig('repository','full_name') == "victim-org/victim-repo"` and calls `stack.sync_github` on `victim-org`'s stack, even though the request was authenticated as `attacker-org`.

**Uncertainty**: I could not open `app/models/shipit/webhooks/handlers/status_handler.rb` in this session (tool call failed) or trace `Shipit.github`'s organization-lookup implementation in `lib/shipit.rb`, so I cannot confirm whether forged `status`/`check_suite` events could additionally be used to spoof commit-status gating for deploy safety checks — the finding above is demonstrated concretely through `PushHandler` and the `PullRequest::*` handlers, which were fully verified.

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
