### Title
RAY-domain market-value overflow permanently freezes a heavily utilized market - (File: common/src/rates/simulate.rs)

### Summary
Medium: interest accrual converts total scaled debt and supply into `i128`-bounded RAY values before enforcing the borrow-index ceiling, so a sufficiently large market can enter a state where every subsequent accrual reverts with `MathOverflow`. [1](#0-0) [2](#0-1) 

### Finding Description
`accrue_step` first computes `scaled_to_original(borrowed, borrow_index)` and `scaled_to_original(supplied, supply_index)` to derive utilization, then updates the indexes. [1](#0-0)   
`scaled_to_original` delegates to `Ray::mul`, whose result must fit `i128` and otherwise raises `GenericError::MathOverflow`. [3](#0-2) [4](#0-3)   
Although `update_borrow_index` caps the index, the cap is applied only to the index itself and does not bound `borrowed * index / RAY`; `calculate_supplier_rewards` then computes the old and new total debt in the same bounded `i128` domain. [2](#0-1) [5](#0-4)   
The pool accrues before changing `last_timestamp`, so once the next valuation exceeds `i128::MAX`, the accrual transaction reverts atomically and every later attempt repeats the same overflowing computation. [6](#0-5) 

### Impact Explanation
The affected `(hub_id, asset)` market becomes unable to accrue, which prevents withdrawals, repayments, liquidations, new borrows, further supplies, revenue claims, and recapitalization paths that load and synchronize the market. [7](#0-6)   
The repository's own regression test demonstrates that `withdraw` and `repay` both fail with `MATH_OVERFLOW` after `update_indexes` reaches the cliff, while the stored borrow index remains below its cap. [8](#0-7)   
Because the panic occurs before `last_timestamp` advances, reducing the requested amount or choosing a different unprivileged exit path cannot avoid the overflowing aggregate valuation; absent a privileged upgrade, third-party supplied funds remain frozen. [6](#0-5) 

### Likelihood Explanation
An unprivileged caller can reach the condition through ordinary `supply` and `borrow` calls on admitted markets, and `update_indexes` is explicitly permissionless. [9](#0-8) [10](#0-9)   
The preconditions are capital-intensive: the market must permit a very large scaled balance, sustain high utilization, and accrue enough index growth for its aggregate RAY value to exceed `i128::MAX`, which supports a Medium severity rather than a higher rating. [11](#0-10) 

### Recommendation
Enforce market-level scaled supply and debt ceilings that keep `shares * maximum_index / RAY` representable in `i128`, rather than relying only on token-unit caps and index caps. [2](#0-1) [1](#0-0)   
Also add a non-panicking checked valuation or explicit `MAX_RAY_VALUE` gate in `accrue_step`, so entry attempts fail before a market enters an unrecoverable accrual state. [12](#0-11) 

### Proof of Concept
1. The attacker calls `supply(attacker, 0, spoke_id, [(HubAssetKey { hub_id, asset: TARGET }, P), (HubAssetKey { hub_id, asset: COLLATERAL }, C)])`, where `P` is a very large admitted amount and `C` provides sufficient borrowing capacity; `account_id = 0` creates the position account. [13](#0-12) 
2. The attacker calls `borrow(attacker, account_id, [(HubAssetKey { hub_id, asset: TARGET }, P * 98 / 100)], Some(attacker))`. [14](#0-13) 
3. After sufficient interest accrues, the attacker or any other user calls `update_indexes(caller, [HubAssetKey { hub_id, asset: TARGET }])`; the pool invokes `global_sync`, `accrue_step`, and overflowing `scaled_to_original` calls. [15](#0-14) [16](#0-15) 
4. The repository test uses `P = 1_000_000_000 * 10^18`, borrows 98% of it, repeatedly advances the ledger until `update_indexes` returns `MATH_OVERFLOW`, and verifies that the index cap has not been reached. [17](#0-16) 
5. The same test then proves `withdraw(BOB, TARGET, 1)` and `repay(ALICE, TARGET, …)` both revert with `MATH_OVERFLOW`, leaving the market's funds inaccessible through those exits. [18](#0-17)

    params: &MarketParams,
    borrowed: Ray,

/// Computes `x * y / d` rounded half up. Requires `x >= 0`, `y >= 0`, and `d > 0`; a
/// `debug_assert` checks this in debug builds. Panics with `GenericError::DivisionByZero` if
/// `d == 0`, and with `GenericError::MathOverflow` if any other precondition is violated or if
/// the result does not fit in `i128`.
pub fn mul_div_half_up(env: &Env, x: i128, y: i128, d: i128) -> i128 {
    // The zero check runs first so debug and release builds agree on a zero
    // divisor: both surface `DivisionByZero` rather than tripping the assert.
    require_nonzero_divisor(env, d);
    debug_assert!(
        x >= 0 && y >= 0 && d > 0,
        "mul_div_half_up: non-negative x, y and positive d"
    );
    try_mul_div_half_up(env, x, y, d)
        .unwrap_or_else(|| panic_with_error!(env, GenericError::MathOverflow))
}

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
