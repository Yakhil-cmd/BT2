### Title
Extension/skill update logic treats any version difference as an "update," enabling silent downgrade to attacker-controlled releases - ([File: pkg/cmd/extension/extension.go])

### Summary
The Solidity finding describes a class of bug where a monotonic assumption about externally-reported values (that they only increase) is not actually enforced in code, so any decrease from the trusted source silently causes incorrect, unrecoverable state. The closest reachable analog in this `gh` CLI codebase is in the extension-update mechanism: `Extension.UpdateAvailable()` treats *any* difference between the locally installed version and the "latest" version reported by a remote, extension-owner-controlled GitHub repository as grounds to upgrade — with no check that the reported "latest" is actually newer.

### Finding Description
`Extension.UpdateAvailable()` only checks for inequality, not ordering: [1](#0-0) 

Contrast this with the equivalent logic used for `gh`'s own self-update check, which correctly parses semver and requires the candidate to be strictly greater than the current version before treating it as an update: [2](#0-1) [3](#0-2) 

For binary extensions, `LatestVersion()` fetches the tag from the extension repository's `/releases/latest` GitHub API response — content fully controlled by the extension's (potentially compromised or malicious) owner: [4](#0-3) 

That untrusted "latest" tag flows directly into `UpdateAvailable()`, and if true, `gh extension upgrade` calls `upgradeBinExtension`, which unconditionally installs whatever release is returned, with no re-validation that it represents forward progress: [5](#0-4) [6](#0-5) 

Because the check is `CurrentVersion() != LatestVersion()` rather than "LatestVersion is newer than CurrentVersion," an extension repository owner (or anyone able to influence what `releases/latest` returns for that repo, e.g. after account compromise, or by deleting/republishing an older release as "latest") can cause `gh extension upgrade` to replace an up-to-date, patched extension binary with an older, vulnerable, or backdoored one — and the CLI will present this to the user as a normal forward "upgrade."

### Impact Explanation
This is a version-rollback/downgrade primitive reachable purely through content the extension publisher controls (the GitHub Releases API response for their own repo), during the normal `gh extension upgrade` flow that users run routinely and often non-interactively (e.g. in CI, via `gh extension upgrade --all`). A successful downgrade can reintroduce a previously-patched vulnerability in the extension or install a maliciously "reverted" binary, resulting in code execution under the user's/CI's privileges the next time the extension runs. Severity is bounded by the fact that the extension repository itself is already a trust boundary the user opted into, but the missing ordering check removes an implicit safety property (upgrades never go backwards) that users and tooling reasonably rely on — directly mirroring the audited Solidity bug where decreases from a trusted-but-not-fully-verified source were silently accepted instead of rejected or flagged.

### Likelihood Explanation
Exploitation requires the attacker to control (or compromise) the `releases/latest` response of a `gh` extension repository that a victim has already installed — no MITM, no local access, and no privileged `gh` role is needed; it is triggered by the victim's own routine `gh extension upgrade` invocation. This fits within the "extension install and execution" attack surface named in scope. It is not a purely local-attacker, admin-only, or dependency-only issue, since the attacker-controlled host (GitHub API response for that specific repo/release) is the only thing needed to trigger the flawed path.

### Recommendation
Mirror the self-update logic: parse both `CurrentVersion()` and `LatestVersion()` as semantic versions (or otherwise verifiable, monotonic identifiers) and only report `UpdateAvailable() == true` when the candidate is strictly greater than the current version (reusing/exporting `versionGreaterThan` from `internal/update`). For binary extensions in particular, reject or explicitly warn on any "latest" release whose version compares as older-than-or-equal-to the installed version, rather than treating any string difference as an upgrade signal.

### Proof of Concept
1. Install a binary extension, e.g. `gh extension install owner/gh-foo`, which pins `manifest.Tag = v2.0.0` locally (`CurrentVersion()` reads this from the manifest: `pkg/cmd/extension/extension.go:88-114`).
2. The extension owner (or an attacker who compromises the owner's account/repo) deletes the `v2.0.0` GitHub Release and marks an older release, e.g. `v1.0.0` (containing a known vulnerability or backdoored binary), as the repository's "latest" release.
3. On the victim's next `gh extension upgrade owner/gh-foo` (or `gh extension upgrade --all`), `LatestVersion()` returns `"v1.0.0"` from `/repos/owner/gh-foo/releases/latest` (`extension.go:116-148`).
4. `UpdateAvailable()` only checks `CurrentVersion() != LatestVersion()` (`"v2.0.0" != "v1.0.0"` → `true`) — it never checks that `v1.0.0` is actually newer (`extension.go:214-222`).
5. `upgradeExtension` → `upgradeBinExtension` → `installBin` downloads and installs the `v1.0.0` binary asset, overwriting the previously-patched `v2.0.0` install (`manager.go:520-576`), and `gh` reports this to the user/CI as a successful "upgrade."

func (e *Extension) LatestVersion() string {
	e.mu.RLock()
	if e.latestVersion != "" {
		defer e.mu.RUnlock()
		return e.latestVersion
	}
	e.mu.RUnlock()

	var latestVersion string
	switch e.kind {
	case LocalKind:
	case BinaryKind:
		repo, err := ghrepo.FromFullName(e.URL())
		if err != nil {
			return ""
		}
		release, err := fetchLatestRelease(e.httpClient, repo)
		if err != nil {
			return ""
		}
		latestVersion = release.Tag
	case GitKind:
		if lsRemote, err := e.gitClient.CommandOutput([]string{"ls-remote", "origin", "HEAD"}); err == nil {
			latestVersion = string(bytes.SplitN(lsRemote, []byte("\t"), 2)[0])
		}
	}

	e.mu.Lock()
	e.latestVersion = latestVersion
	e.mu.Unlock()

	return e.latestVersion
}

func (e *Extension) UpdateAvailable() bool {
	if e.IsLocal() ||
		e.CurrentVersion() == "" ||
		e.LatestVersion() == "" ||
		e.CurrentVersion() == e.LatestVersion() {
		return false
	}
	return true
}

// CheckForUpdate checks whether an update exists for the GitHub CLI based on recency of last check within past 24 hours.
func CheckForUpdate(ctx context.Context, client *http.Client, stateFilePath, repo, currentVersion string) (*ReleaseInfo, error) {
	stateEntry, _ := getStateEntry(stateFilePath)
	if stateEntry != nil && time.Since(stateEntry.CheckedForUpdateAt).Hours() < 24 {
		return nil, nil
	}

	releaseInfo, err := getLatestReleaseInfo(ctx, client, repo)
	if err != nil {
		return nil, err
	}

	err = setStateEntry(stateFilePath, time.Now(), *releaseInfo)
	if err != nil {
		return nil, err
	}

	if versionGreaterThan(releaseInfo.Version, currentVersion) {
		return releaseInfo, nil
	}

	return nil, nil
}

func versionGreaterThan(v, w string) bool {
	w = gitDescribeSuffixRE.ReplaceAllStringFunc(w, func(m string) string {
		idx := strings.IndexRune(m, '-')
		n, _ := strconv.Atoi(m[0:idx])
		return fmt.Sprintf("%d-pre.0", n+1)
	})

	vv, ve := version.NewVersion(v)
	vw, we := version.NewVersion(w)

	return ve == nil && we == nil && vv.GreaterThan(vw)
}

func (m *Manager) upgradeExtension(ext *Extension, force bool) error {
	if ext.IsLocal() {
		return localExtensionUpgradeError
	}
	if !force && ext.IsPinned() {
		return pinnedExtensionUpgradeError
	}
	if !ext.UpdateAvailable() {
		return upToDateError
	}
	var err error
	if ext.IsBinary() {
		err = m.upgradeBinExtension(ext)
	} else {
		// Check if git extension has changed to a binary extension
		var isBin bool
		repo, repoErr := repoFromPath(m.gitClient, filepath.Join(ext.Path(), ".."))
		if repoErr == nil {
			isBin, _ = isBinExtension(m.client, repo)
		}
		if isBin {
			if err := m.Remove(ext.Name()); err != nil {
				return fmt.Errorf("failed to migrate to new precompiled extension format: %w", err)
			}
			return m.installBin(repo, "")
		}
		err = m.upgradeGitExtension(ext, force)
	}
	return err
}
