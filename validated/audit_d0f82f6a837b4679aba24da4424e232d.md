### Title
Unvalidated P2P-Delivered `StakingInfo` Corrupts Validator Reward Distribution and Proposer Selection — (`datasync/downloader/queue.go`, `datasync/downloader/downloader.go`)

---

### Summary

The `DeliverStakingInfos` path in the downloader accepts `StakingInfo` structs from any registered P2P peer and writes them directly to the persistent database with **no content validation**. The validation callback is explicitly left as a no-op (`// TODO-Kaia-Snapsync update validation logic`). A malicious peer can inject fabricated `StakingAmounts` for any pre-Kaia-hardfork block, permanently corrupting the DB values that drive KAIA staking reward distribution and weighted-random proposer selection.

---

### Finding Description

**Root cause — `queue.go`:** [1](#0-0) 

The `validate` callback always returns `nil`. No check is made that the delivered `StakingInfo` content matches the actual on-chain AddressBook state for the requested block hash.

**Root cause — `downloader.go` fast-sync commit path:** [2](#0-1) 

`PutStakingInfoToDB` is called unconditionally for every `result.StakingInfo != nil` delivered by a peer, overwriting any previously correct value.

**Root cause — `SyncStakingInfo` admin recovery path:** [3](#0-2) 

The only guard is a `BlockNum` equality check. The content of `StakingAmounts`, `RewardAddrs`, `KIFAddr`, `KEFAddr`, etc. is never verified against the canonical chain state.

**How the corrupted value propagates:**

`StakingAmounts` is the sole input to `assignStakingRewards`, which computes each validator's share of KAIA staking rewards: [4](#0-3) 

It is also the sole input to `generateProposerListWeighted`, which determines how often each validator is selected as block proposer: [5](#0-4) 

The `StakingInfo` is sourced from DB for all pre-Kaia-hardfork blocks: [6](#0-5) 

**Attack flow:**

1. Attacker operates a standard P2P node and connects to a victim node that is performing fast sync (or an operator invokes `admin_syncStakingInfo` pointing at the attacker's node).
2. When the victim requests staking info for block hashes, the attacker responds with `P2PStakingInfo` structs that have correct `BlockNum` values but inflated `StakingAmounts` for the attacker's own validator address.
3. `DeliverStakingInfos` → `queue.DeliverStakingInfos` accepts the data without validation and stores it via `PutStakingInfoToDB`.
4. On subsequent calls to `GetStakingInfo` for those blocks, the corrupted amounts are returned and used in `assignStakingRewards` and `generateProposerListWeighted`.

---

### Impact Explanation

- **Unauthorized reward distribution**: Inflated `StakingAmounts` for the attacker's reward address cause `assignStakingRewards` to allocate a disproportionate share of KAIA staking rewards to the attacker, directly reducing the KAIA received by honest validators.
- **Proposer selection skew**: `generateProposerListWeighted` uses the same staking amounts to compute percentage weights; inflated values increase the attacker's proposer frequency, giving them more block rewards and fee income.
- **Persistent DB corruption**: `WriteStakingInfo` overwrites the key-value entry with no rollback mechanism outside of a full re-sync. [7](#0-6) 

---

### Likelihood Explanation

Any node that connects to the Kaia P2P network qualifies as a registered peer. Fast sync is the default mode for new nodes joining the network. The `admin_syncStakingInfo` API is exposed to node operators who may point it at an untrusted peer. No cryptographic proof, Merkle proof, or state-root cross-check is required to pass the validation gate (which is a no-op). The attack requires only that the victim performs fast sync or invokes the recovery API against the attacker's node.

---

### Recommendation

1. **Implement content validation in `DeliverStakingInfos`**: For each delivered `StakingInfo`, verify that the `StakingAmounts` match the native token balances of the `StakingContracts` at the block's state root. The header's `Root` field is available in the `fetchResult` and can be used to open a state trie and call the AddressBook contract, or at minimum cross-check against a locally computed value.

2. **Remove the unconditional overwrite in `commitFastSyncData`**: Add an existence check analogous to the one in `SyncStakingInfo` (`GetStakingInfoFromDB(i) != nil`) before calling `PutStakingInfoToDB`.

3. **Resolve the TODO**: The comment `// TODO-Kaia-Snapsync update validation logic` in `queue.go` line 957 must be resolved before the fast-sync path is considered production-safe.

---

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}
