### Title
Webhook signature is verified against an attacker-chosen `repository.owner.login`, letting an unprivileged POST forge events for an unrelated `repository.full_name` - (File: app/controllers/shipit/webhooks_controller.rb)

### Summary
This is the same class of bug as H-1: a value used to select/derive the trust binding (`inflationMultiplier`) is decoupled from the value actually acted upon during the privileged operation. In `WebhooksController`, the field used to pick *which* GitHub App secret validates the HMAC signature (`repository.owner.login`) is read from the same untrusted JSON body as the field the downstream handlers use to decide *which repository/stack to write to* (`repository.full_name`), and nothing enforces that the two agree.

### Finding Description
`WebhooksController#verify_signature` selects the signing key to check against using attacker-supplied JSON, not any authenticated context: [1](#0-0) [2](#0-1) 

`repository_owner` is computed purely from `params.dig('repository', 'owner', 'login')`/`organization.login` — fields inside the same POST body the attacker fully controls — and is used only to pick which `Shipit::GitHubApp` (and therefore which webhook secret) validates the signature: `Shipit.github(organization: repository_owner)`.

Separately, `verify_webhook_signature` explicitly treats a missing/nil `webhook_secret` as automatically verified: [3](#0-2) 

The engine's own documented setup examples show `webhook_secret` left blank/nil as a valid configuration: [4](#0-3) 

Once `verify_signature` passes, `create` re-parses the raw body and dispatches it to event handlers keyed only by the `X-Github-Event` header — with no re-validation that `repository.owner.login` matches `repository.full_name`: [5](#0-4) 

Downstream handlers (e.g. push/status handlers) resolve the target `Stack`/`Repository` from `repository.full_name` inside that same untrusted payload — a field never covered by any check that ties it back to the organization whose secret validated the signature.

Because `repository.owner.login` (used to pick/validate the signing key) and `repository.full_name` (used to select the repository actually written to) are independent, unauthenticated JSON fields, they can diverge: an attacker can address the check to an app configuration with `webhook_secret: nil` (or one they otherwise control) while pointing `repository.full_name` at a completely different, victim-owned stack.

### Impact Explanation
This breaks the deployment-trust binding: "organization that authenticated" (via `repository_owner` → HMAC check) versus "repository that is written" (via `repository.full_name` → Stack lookup/mutation). If the Shipit deployment has any GitHub App configuration with no `webhook_secret` set (a state the project's own example configs treat as normal), an unauthenticated POST to the public `/webhooks` endpoint can forge `push`, `status`, `check_suite`, `pull_request`, or `membership` events against arbitrary tracked stacks — creating fake commits, marking commits as CI-passing, or otherwise manipulating state that feeds `continuous_deployment`/merge-queue logic, all without ever holding valid credentials for the target repository/org. That reaches "unauthorized deploy" territory (High/Critical per the rules) since forged `status`/`push` events can influence `Stack#trigger_continuous_delivery` and merge-queue processing.

### Likelihood Explanation
Requires no session, API token, or webhook secret for the *victim* repository — only that some GitHub App entry in the Shipit installation's config has a blank/nil `webhook_secret` (a state explicitly shown as acceptable in the project's own example secrets files/docs), or that the attacker legitimately controls one org's app while targeting a different org's stack in a multi-org configuration. `WebhooksController` is intentionally unauthenticated (`ActionController::Base`, no `Shipit::Authentication`) and reachable by anyone who can POST to the host.

### Recommendation
Do not let any JSON body field select which secret validates that same body's signature. Bind webhook verification to the specific `Repository`/`Stack` record being mutated (e.g., verify against the secret configured for the resolved `Repository.owner`, and reject if `repository.owner.login` does not match `repository.full_name`'s owner segment). Additionally, disallow/loudly warn on `webhook_secret` being nil in any non-test environment so a missing secret can never mean "signature auto-passes."

### Proof of Concept
1. Deploy Shipit with two GitHub App entries in `secrets.yml`: `victim-org` (has a real `webhook_secret`) and `attacker-org` (misconfigured with `webhook_secret: nil`, matching the documented example config).
2. POST to `/webhooks` with header `X-Github-Event: push`, no valid `X-Hub-Signature`, and a JSON body:
```json
{
  "repository": {
    "owner": { "login": "attacker-org" },
    "full_name": "victim-org/victim-repo"
  },
  "after": "<attacker-chosen sha>",
  "ref": "refs/heads/master"
}
```
3. `verify_signature` calls `Shipit.github(organization: "attacker-org")`, whose `verify_webhook_signature` returns `true` unconditionally because `webhook_secret` is nil.
4. `create` dispatches the payload to the push handler, which resolves `victim-org/victim-repo`'s tracked `Stack` from `repository.full_name` and processes the forged push — with the signature check never having validated anything about `victim-org`. [6](#0-5)

# frozen_string_literal: true

module Shipit
  class WebhooksController < ActionController::Base
    skip_before_action :verify_authenticity_token, raise: false
    before_action :check_if_ping, :drop_unhandled_event, :verify_signature

    respond_to :json

    def create
      params = JSON.parse(request.raw_post)
      Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }

      head(:ok)
    end

    private

    def drop_unhandled_event
      # Acknowledge, but do nothing
      head(204) unless Shipit::Webhooks.for_event(event).present?
    end

    def verify_signature
      github_app = Shipit.github(organization: repository_owner)
      verified = github_app.verify_webhook_signature(
        request.headers['X-Hub-Signature'],
        request.raw_post
      )
      head(422) unless verified

      Rails.logger.info([
        'WebhookController#verify_signature',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "signature=#{request.headers['X-Hub-Signature']}",
        "status=#{status}"
      ].join(' '))
    rescue Shipit::GithubOrganizationUnknown => e
      head(422)
      Rails.logger.warn([
        'WebhookController#verify_signature',
        'Webhook from unknown organization',
        "event=#{event}",
        "repository_owner=#{repository_owner}",
        "unknown_organization=#{e.message}",
        "status=#{status}"
      ].join(' '))
    end

    def check_if_ping
      head(:ok) if event == 'ping'
    end

    def event
      request.headers.fetch('X-Github-Event')
    end

    def repository_owner
      # Fallback to the organization sub-object if repository isn't included in the payload
      params.dig('repository', 'owner', 'login') || params.dig('organization', 'login')
    end
  end
end

    def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
