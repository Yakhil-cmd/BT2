### Title
Incorrect signer-permission binding in shared-address handling lets a co-signer device redirect an unrelated signing branch to itself, causing wallet auto-signing outside the true definition - ([File: wallet_defined_by_addresses.js])

### Summary
The GitLab advisory describes a case where invited groups could be assigned an incorrect permission level due to a validation gap when applying membership metadata separately from the actual permission grant. The analogous pattern in ocore is `handleNewSharedAddress` in `wallet_defined_by_addresses.js`, which stores a `signers` map (signing_path → address/device_address) into `shared_address_signing_paths` largely independent from the actual `["address", ...]` leaves of the received `definition`.

### Finding Description
`handleNewSharedAddress` [1](#0-0)  is reached whenever a paired device sends a `new_shared_address` message (via `createNewSharedAddress`/`sendNewSharedAddress`), i.e. from an unprivileged paired correspondent. It cross-checks `body.signers` against `extractAddressPathsFromDefinition(body.definition)`, but that helper only maps `signing_path -> address` for `"address"`, `"hash"`, and `"in merkle"` leaves [2](#0-1) . Plain `"sig"` leaves (a raw pubkey signature, not a nested member address) are **not** captured in `assocDefinitionAddresses`.

The validation loop:
```
for (let signing_path in body.signers) {
    const signerInfo = body.signers[signing_path];
    if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
        return callbacks.ifError(...);
}
``` [3](#0-2) 
only fails when `signerInfo.address` disagrees with a mapped address leaf. If the sender supplies a `signing_path` that corresponds to a `"sig"` branch of the definition (no `address` field, i.e. `signerInfo.address` is falsy/undefined), `assocDefinitionAddresses[signing_path]` is also `undefined`, so the check passes trivially — the attacker can freely set `signerInfo.device_address` to any device address (including their own) for that path.

That entry is then written verbatim into `shared_address_signing_paths (shared_address, signing_path, device_address, ...)` in `addNewSharedAddress` [4](#0-3) . This table subsequently drives which device is treated as authoritative to sign for a given branch, both for outbound "which device holds this key" resolution (`findAddress`, `readFullSigningPaths`) [5](#0-4) [6](#0-5)  and for inbound "sign" requests where the wallet checks only `other_device_addresses.includes(from_address)` before forwarding/acting on a signing offer [7](#0-6) . Because the recorded mapping can misassign a signing branch's permission (device authority) to the wrong device, a device that was never actually granted that branch in the true multi-sig definition can be recorded in `shared_address_signing_paths` as the holder of that path — the same class of bug as GitLab granting an invited group the wrong permission level due to inconsistent application of membership records versus the real access-control definition.

### Impact Explanation
If the mis-mapped signing_path is later exercised (e.g., because `readFullSigningPaths`/`findAddress` resolves signing responsibility using this table when constructing a shared-address payment or an arbiter contract shared address), the local wallet could send signing offers to, or accept forwarded "you are a cosigner" claims from, a device that is not really authorized by the on-chain definition for that path — increasing risk of unauthorized signing offers, denial of the correct multisig flow, or misdirected/failed transaction construction against a shared address. This can translate into fund-loss/freezing risk for a shared/multisig wallet if the mismatch is exploited to trick a peer's wallet into misrouting a co-signing branch.

### Likelihood Explanation
Reachable purely from a paired device (a `new_shared_address` message from a correspondent), which is one of the allowed unprivileged actors per the current scope. No special node/hub compromise is required — only an already-paired device willing to send a maliciously crafted `signers` map alongside a `definition` containing a raw `"sig"` branch.

### Recommendation
`extractAddressPathsFromDefinition` should also record `"sig"`/other terminal ops (not just `"address"`/`"hash"`/`"in merkle"`) so `handleNewSharedAddress` can validate that no unauthorized/extra `signing_path` entries — pointing at arbitrary device addresses — are inserted into `shared_address_signing_paths` for paths that don't correspond to a genuine external "address" member. Reject any `signing_path` in `body.signers` that isn't a legitimate address/hash/merkle leaf of the definition, and validate that the full set of accepted signing paths in `signers` is exactly the set of extracted leaves (already partially done for the reverse direction at lines 402-405, but not for the forward "must exist in definition" direction for non-address leaves).

### Proof of Concept
Not fully verified end-to-end (would require confirming `readFullSigningPaths`/`findAddress` is actually invoked against `shared_address_signing_paths` rows for `"sig"`-only paths inserted this way, and tracing an exploitable transaction path). Conceptually:
1. Attacker (a paired device) proposes a shared-address `definition` such as `["and", [["sig", {pubkey: victimPubkey}], ["address", attackerAddress]]]`.
2. In the `signers` map sent alongside it, attacker adds an entry for the `"sig"` leaf's path with `device_address` set to their own device and no `address` field.
3. `handleNewSharedAddress`'s check at lines 397-401 passes because `assocDefinitionAddresses[path]` is `undefined` and `signerInfo.address` is also `undefined`.
4. The row is persisted in `shared_address_signing_paths`, associating the `"sig"` branch's path with the attacker's device address.
5. Downstream signing-path resolution logic that trusts this table (`findAddress`, `readFullSigningPaths`) may now treat the attacker's device as an authorized party for that path.

Because full confirmation of exploitability requires tracing further call sites and runtime state not fully covered by the available index, this should be validated hands-on in a Devin session with the full repository available.

// Returns a map of signing_path -> address for every ["address", ...] leaf in the definition
function extractAddressPathsFromDefinition(arrDefinition) {
	var result = {};
	function traverse(arr, path) {
		if (!Array.isArray(arr) || arr.length < 2) return;
		var op = arr[0];
		var args = arr[1];
		switch (op) {
			case 'or':
			case 'and':
				if (Array.isArray(args))
					for (var i = 0; i < args.length; i++)
						traverse(args[i], path + '.' + i);
				break;
			case 'r of set':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i], path + '.' + i);
				break;
			case 'weighted and':
				if (args && Array.isArray(args.set))
					for (var i = 0; i < args.set.length; i++)
						traverse(args.set[i].value, path + '.' + i);
				break;
			case 'address':
				result[path] = args;
				break;
			case 'hash':
				result[path] = 'secret';
				break;
			case 'in merkle':
				result[path] = ''; // empty address
				break;
		}
	}
	traverse(arrDefinition, 'r');
	return result;
}

function handleNewSharedAddress(body, callbacks){
	if (!ValidationUtils.isArrayOfLength(body.definition, 2))
		return callbacks.ifError("invalid definition");
	if (typeof body.signers !== "object" || Object.keys(body.signers).length === 0)
		return callbacks.ifError("invalid signers");
	try {
		var addr = objectHash.getChash160(body.definition);
	}
	catch (e) {
		return callbacks.ifError("invalid definition: " + e);
	}
	if (body.address !== addr)
		return callbacks.ifError("definition doesn't match its c-hash");
	for (var signing_path in body.signers){
		var signerInfo = body.signers[signing_path];
		if (signerInfo.address && signerInfo.address !== 'secret' && !ValidationUtils.isValidAddress(signerInfo.address))
			return callbacks.ifError("invalid member address: " + JSON.stringify(signerInfo.address));
	}
	const assocDefinitionAddresses = extractAddressPathsFromDefinition(body.definition);
	for (let signing_path in body.signers) {
		const signerInfo = body.signers[signing_path];
		if (assocDefinitionAddresses[signing_path] !== signerInfo.address)
			return callbacks.ifError("signer address at path " + signing_path + " doesn't match definition");
	}
	for (let def_path in assocDefinitionAddresses) {
		if (!body.signers[def_path])
			return callbacks.ifError("no signer for definition address at path " + def_path);
	}
	determineIfIncludesMeAndRewriteDeviceAddress(body.signers, function(err){
		if (err)
			return callbacks.ifError(err);
		validateAddressDefinition(body.definition, function(err){
			if (err)
				return callbacks.ifError(err);
			addNewSharedAddress(body.address, body.definition, body.signers, body.forwarded, callbacks.ifOk);
		});
	});
}

function readFullSigningPaths(conn, address, arrSigningDeviceAddresses, handleSigningPaths){
	
	var assocSigningPaths = {};
	
	function goDeeper(member_address, path_prefix, onDone){
		// first, look for wallet addresses
		var sql = "SELECT signing_path FROM my_addresses JOIN wallet_signing_paths USING(wallet) WHERE address=?";
		var arrParams = [member_address];
		if (arrSigningDeviceAddresses && arrSigningDeviceAddresses.length > 0){
			sql += " AND device_address IN(?)";
			arrParams.push(arrSigningDeviceAddresses);
		}
		conn.query(sql, arrParams, function(rows){
			rows.forEach(function(row){
				assocSigningPaths[path_prefix + row.signing_path.substr(1)] = 'key';
			});
			if (rows.length > 0)
				return onDone();
			// next, look for shared addresses, and search from there recursively
			sql = "SELECT signing_path, address FROM shared_address_signing_paths WHERE shared_address=?";
			arrParams = [member_address];
			if (arrSigningDeviceAddresses && arrSigningDeviceAddresses.length > 0){
				sql += " AND device_address IN(?)";
				arrParams.push(arrSigningDeviceAddresses);
			}
			conn.query(sql, arrParams, function(rows){
				if(rows.length > 0) {
					async.eachSeries(
						rows,
						function (row, cb) {
							if (row.address === '') { // merkle
								assocSigningPaths[path_prefix + row.signing_path.substr(1)] = 'merkle';
								return cb();
							} else if (row.address === 'secret') {
								assocSigningPaths[path_prefix + row.signing_path.substr(1)] = 'secret';
								return cb();
							}

							goDeeper(row.address, path_prefix + row.signing_path.substr(1), cb);
						},
						onDone
					);
				} else {
					sql = "SELECT signing_paths FROM peer_addresses WHERE address=?";
					arrParams = [member_address];
					if (arrSigningDeviceAddresses && arrSigningDeviceAddresses.length > 0){
						sql += " AND device_address IN(?)";
						arrParams.push(arrSigningDeviceAddresses);
					}
					conn.query(sql, arrParams, function(rows){
						if (!rows.length) {
							assocSigningPaths[path_prefix] = 'key';
							return onDone();
						}
						JSON.parse(rows[0].signing_paths).forEach(function(signing_path){
							assocSigningPaths[path_prefix + signing_path.substr(1)] = 'key';
						});
						return onDone();
					});
				}
			});
		});
	}
	
	goDeeper(address, 'r', function(){
		handleSigningPaths(assocSigningPaths); // order of signing paths is not significant
	});
}
