### Title
Unchecked fixed-point growth permanently freezes an oversized high-utilization market - (File: `contracts/pool/src/interest.rs`)

### Summary
A market can grow its scaled borrow value until a subsequent interest accrual exceeds `i128`, causing `update_indexes`, `repay`, `withdraw`, `borrow`, liquidation-related pool actions, and other market operations to revert before accounting can execute.

The issue maps the reported buffer-overflow class to Soroban’s bounded-integer equivalent: the protocol calculates `scaled_debt * borrow_index` without a domain guard or saturation path. Once the product exceeds `i128::MAX`, every later accrual attempt fails before `last_timestamp` is advanced, so the failure is persistent rather than recoverable.

### Finding Description
Each pool operation loads the market through `synced_market`, which unconditionally calls `interest::global_sync` before the operation-specific logic runs. [1](#0-0)  `global_sync` applies accrued interest for the full elapsed period and only calls `mark_accrued` after all chunks complete. [2](#0-1) 

Interest calculations convert scaled debt and scaled supply to original token values using `scaled_to_original`, which multiplies the scaled RAY amount by the index. [3](#0-2)  The shared conversion is a checked `Ray::mul`, so a result outside `i128` reverts rather than saturating or clamping the market at a maximum index. [4](#0-3) 

The regression test demonstrates the reachable boundary: with a one-billion-token market at 18 decimals and a 98% borrow position, repeated annual `update_indexes` calls eventually fail with `MathOverflow` while the stored borrow index remains below `MAX_BORROW_INDEX_RAY`. [5](#0-4) 

### Impact Explanation
The affected market permanently loses access to withdrawals, repayments, borrowing, liquidation accounting, revenue accounting, and index synchronization because all of those paths first execute `global_sync`. [6](#0-5) 

This is a permanent freezing-of-funds condition: the timestamp is only advanced after the overflowing accrual completes, so retrying the same operation continues to include the elapsed period and hits the same overflow. [7](#0-6)  The existing test specifically proves that both `withdraw` and `repay` continue to revert with `MathOverflow` after the boundary is crossed. [8](#0-7) 

### Likelihood Explanation
Likelihood is limited by the extreme size requirement: the test uses `1_000_000_000` whole tokens at 18 decimals, 98% utilization, and a steep interest-rate segment sustained for years before the RAY-value product crosses the `i128` ceiling. [9](#0-8) 

No privileged action is required after such a market exists: an unprivileged borrower can establish the debt position, and any address can later trigger the failure through `update_indexes(caller, assets)` or a position operation such as `repay(caller, account_id, payments)`. [10](#0-9)  Market configuration must permit the required cap, utilization, and rate profile, so deployment parameters materially affect feasibility.

### Recommendation
Bound the domain before multiplying scaled balances by indexes.

- Cap the borrow and supply indexes before any `scaled * index` conversion can exceed `i128`.
- In `accrue_step`, compare `scaled_balance` against `i128::MAX / index` and clamp the index or reject earlier with a dedicated typed error.
- Prefer saturating index progression at the configured maximum rather than leaving the timestamp unadvanced.
- Add a recovery path that can advance `last_timestamp` without performing an overflowing unscale, or perform index-growth checks independently of total scaled balance.
- Add production-parameter regression coverage for markets whose `scaled_balance * index` approaches `i128::MAX`.

### Proof of Concept
1. Configure an 18-decimal market that permits a one-billion-token supply and 98% utilization under the high-rate curve used by the existing regression test.
2. Supply `1_000_000_000 * 10^18` raw units to the market.
3. Supply sufficient collateral to a second market and borrow `980_000_000 * 10^18` raw units of the first asset.
4. Advance ledger time and repeatedly call:

```rust
controller.update_indexes(attacker, vec![big18_hub_asset]);
```

5. Once `scaled_borrowed * borrow_index` exceeds `i128::MAX`, `update_indexes` reverts with `MathOverflow` before `last_timestamp` is committed.
6. Verify that later calls also fail:

```rust
controller.withdraw(supplier, supplier_account, withdrawals, None);
controller.repay(borrower, borrower_account, payments);
controller.update_indexes(attacker, vec![big18_hub_asset]);
```

The existing deterministic regression constructs this exact state and asserts the persistent overflow on `update_indexes`, `withdraw`, and `repay`. [11](#0-10)

```rust
pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
```

```rust
/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);
```
