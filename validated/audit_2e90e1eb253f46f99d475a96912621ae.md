### Title
No comparison exists between webhook signature-verification org and the mutation-target org in `full_name` - (File: app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb)

### Summary
`WebhooksController#verify_signature` selects the GitHub App/webhook secret to validate against using `repository_owner` (`params.dig('repository','owner','login')`), while `AssignedHandler` (and every other `PullRequest` handler) resolves the record to mutate using `Shipit::Repository.from_github_repo_name(params.repository.full_name)`. These are two independently attacker-controlled fields inside the same JSON body, and no code anywhere in the traced call path ever asserts they refer to the same organization.

### Finding Description
The claimed binding is: `repository_owner` (`params.dig('repository','owner','login')` in `app/controllers/shipit/webhooks_controller.rb:61`) `==` owner-segment of `params.repository.full_name` used in `app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb:68` (`Shipit::Repository.from_github_repo_name`, which simply does `github_repo_name.downcase.split('/')` and a DB lookup, `app/models/shipit/repository.rb:53-56`).

Tracing the path:
- `WebhooksController#verify_signature` (`app/controllers/shipit/webhooks_controller.rb:24-49`) picks `github_app = Shipit.github(organization: repository_owner)` and verifies the HMAC signature against that org's configured `webhook_secret`.
- `create` then dispatches raw `params` to `Shipit::Webhooks.for_event(event).each { |handler| handler.call(params) }` (`app/controllers/shipit/webhooks_controller.rb:10-15`), passing the same JSON hash, unmodified.
- `Handler#initialize`/`Handler.call` (`app/models/shipit/webhooks/handlers/handler.rb:15-24`) only runs `ExplicitParameters` type/presence validation (`requires :repository do requires :full_name, String end`) — it never re-derives or compares an owner value.
- `AssignedHandler#repository` (`app/models/shipit/webhooks/handlers/pull_request/assigned_handler.rb:67-69`) calls `Repository.from_github_repo_name(params.repository.full_name)`, which does a pure DB lookup by `owner`/`name` columns split out of `full_name`, with zero reference to `repository_owner`.
- Nowhere in `Handler#stacks`, `Repository.from_github_repo_name`, or any handler is `repository_owner` (the signature-verification org) compared against the owner segment of `full_name` (the mutation-target org).

Both fields are attacker-supplied in the same POST body: an attacker can submit `"repository": {"owner": {"login": "attacker-org"}, "full_name": "victim-org/victim-repo"}`. `verify_signature` looks up and verifies against `attacker-org`'s GitHub App config, while `AssignedHandler` resolves and mutates `victim-org/victim-repo`'s `Shipit::PullRequest` row via `pull_request.update(github_pull_request: params.pull_request)` (`assigned_handler.rb:44`, `53-65`).

### Impact Explanation
If any organization configured in Shipit has no `webhook_secret` set (in which case `GithubApp#verify_webhook_signature` returns `true` unconditionally — `lib/shipit/github_app.rb:76-83`), or if the attacker otherwise controls a valid signature for the org named in `repository.owner.login`, they can freely set `repository.full_name` to any other tenant's `owner/repo` and have `AssignedHandler`/`OpenedHandler`/`ClosedHandler`/`LabeledHandler`/etc. mutate that tenant's `Shipit::PullRequest`, `ReviewStack`, or `Stack` records (archive/unarchive, overwrite `github_pull_request` JSON, create/destroy review stacks). This is a cross-tenant write driven by an unauthenticated field, matching the "payload for one repository mutating another's stack" Critical category — provided the signature-verification precondition for the attacker's chosen `repository.owner.login` org is satisfiable.

### Likelihood Explanation
The finding that "no comparison exists" is unconditionally true and code-confirmed. Exploitability, however, is gated entirely by whether the attacker can pass `verify_signature` for the org they name in `repository.owner.login`. That requires either: (a) that org has no `webhook_secret` configured in Shipit (an operator/config condition, not a code guarantee), or (b) the attacker already knows a valid `webhook_secret`/signature for some onboarded org — which the rules explicitly place out of scope ("no webhook_secret ... attacker holds no secrets"). Without a demonstrated org lacking a secret or a leaked secret, the attacker cannot produce a request that passes `verify_signature` in the first place, so the missing-comparison gap alone does not constitute a complete, self-contained exploit under the stated attacker capabilities.

### Recommendation
In `Handler#initialize` or a shared before-hook, assert that the owner segment of `params.repository.full_name` matches `payload.dig('repository','owner','login')` (or `organization.login`) before calling `process`, raising/dropping the event on mismatch. Alternatively, have `WebhooksController#verify_signature` re-derive the org strictly from `full_name`'s owner segment so the same field is used for both authentication and mutation targeting.

### Proof of Concept
Not produced as a complete end-to-end exploit: the missing-comparison code fact is demonstrable via a unit test on `AssignedHandler` alone (construct a payload with `repository.full_name` = "victim/repo" and any differing `repository.owner.login`, call `AssignedHandler.new(payload).process`, observe no error and a lookup against "victim/repo"), but that test bypasses `WebhooksController#verify_signature` entirely (as the engine's own handler tests already do, e.g. `test/models/shipit/webhooks/handlers/pull_request/assigned_handler_test.rb:14-40`), so it does not prove an attacker can reach this state through the actual authenticated webhook endpoint without an additional, out-of-scope precondition (a secretless or already-compromised org).     def verify_webhook_signature(signature, message)
      return true unless webhook_secret

      algorithm, signature = signature.split("=", 2)
      return false unless algorithm == 'sha1'

      SecureCompare.secure_compare(signature, OpenSSL::HMAC.hexdigest(algorithm, webhook_secret, message))
    end
