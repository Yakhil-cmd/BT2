### Title
Silent block-rule bypass via malformed explicit `conditions` entries in `Rule.from_dict`/`Condition.from_dict` - ([File: plugins/hookify/core/config_loader.py])

### Summary
`Rule.from_dict` and `Condition.from_dict` treat the legacy `pattern:` field and the explicit `conditions:` list as equivalent inputs, but only the legacy path guarantees a valid, non-empty `field`/`pattern` pair. The explicit path silently accepts malformed or incomplete condition dicts (defaulting missing `field`/`pattern` to empty strings) and, combined with the engine's all-conditions-must-match (AND) semantics, this can silently neuter a `block` rule so it never fires, without any error or warning being surfaced.

### Finding Description
`Condition.from_dict` (plugins/hookify/core/config_loader.py:22-29) uses `.get(..., default)` for every key, so a `conditions:` list entry missing `field` or `pattern` produces `Condition(field='', operator='regex_match', pattern='')` instead of raising an error.

`Rule.from_dict` (plugins/hookify/core/config_loader.py:44-84) only falls back to the legacy single-pattern behavior "if `simple_pattern` and `not conditions`" (line 58). This means:
- The legacy path (lines 56-73) always infers a correct, non-empty `field` from `event` (`command`/`new_text`/`content`) and uses the author-supplied non-empty `pattern`, guaranteeing a condition that can actually match.
- The explicit path (lines 51-54) trusts whatever `field`/`pattern` values are present in attacker/generator-controlled frontmatter with zero validation, and as soon as `conditions` is a non-empty list (even with a single malformed entry), the legacy fallback is disabled (`not conditions` becomes `False`), so the broken explicit condition becomes the *only* enforcement mechanism.

In `RuleEngine._rule_matches` (plugins/hookify/core/rule_engine.py:96-125), **all** conditions in `rule.conditions` must match (AND semantics, line 121-123). `_check_condition`/`_extract_field` (lines 144-254) return `None`/`False` for an empty `field` string (it matches none of the explicit `tool_name`/`field` branches), which makes that single condition permanently unsatisfiable. Since conditions are ANDed, a `block` rule containing even one malformed condition entry can never match — it is silently disabled — yet `load_rules`/`load_rule_file` (config_loader.py:198-275) report no error for this case (Condition creation never raises), so the loader treats the file as a valid, "enabled" rule that in practice enforces nothing.

Because frontmatter for `.claude/hookify.*.local.md` rule files can originate from `/hookify` generation (which may translate free-form intent into `conditions:` entries) or be shipped directly in repository content, an attacker who controls repository content consumed by `/hookify rule creation` can supply/influence a `conditions:` list with a subtly incomplete entry (e.g. omitting `field:` or leaving `pattern:` empty due to a YAML-parsing quirk in `extract_frontmatter`), causing a rule that is *displayed/believed* to be a working `block` rule (with a proper warning `message`) to never actually trigger, while the equivalent legacy `pattern:` form of the same policy would have worked correctly. This breaks the stated invariant that legacy and explicit forms must produce equivalent effective security semantics.

### Impact Explanation
A repository-shipped or generator-produced hookify rule intended to `block` dangerous Bash commands or file edits (e.g. `rm -rf`, secret exfiltration patterns, etc.) can be silently rendered inert by a malformed explicit `conditions` entry, while `enabled: true` and the rule continuing to load without any surfaced error. This allows the exact dangerous operation the rule was meant to block to proceed unchecked (`PreToolUse`/`PostToolUse`/`Stop` hooks all just fall through to the "no matches - allow operation" path, `rule_engine.py:93-94`). This is a trust-boundary/enforcement bypass with real security impact: a security control the user believes is active is not actually active, enabling unauthorized command execution or file mutation that the block rule was designed to prevent.

### Likelihood Explanation
The precondition is limited to authoring or influencing the frontmatter of a `.claude/hookify.*.local.md` file — either through `/hookify` rule generation or by having a repo-shipped rule file loaded via `load_rules()`'s glob over `.claude/hookify.*.local.md`. No special privilege on the victim machine is required; this is squarely within "repository-controlled content and standard command inputs." The bug is deterministic and trivially reproducible: any `conditions` list entry lacking a `field` key (or where the multi-line dict/inline-dict mini-YAML parser in `extract_frontmatter` fails to populate `field`/`pattern`, e.g. through unusual indentation) reproduces the silent-bypass condition every time.

### Recommendation
- In `Condition.from_dict`, validate that `field` and `pattern` are non-empty strings and `operator` is one of the supported operators; raise a `ValueError` (caught and logged by `load_rule_file`/`load_rules`, which already handle `ValueError`) rather than silently defaulting to `''`.
- In `Rule.from_dict`, reject/log rules whose `conditions` list contains any invalid entries instead of allowing an all-empty/inert condition to become the sole (and permanently non-matching) gate for a `block` rule.
- Consider treating a `block` action rule with zero effectively-matchable conditions as invalid at load time (refuse to load, print a clear warning) rather than loading it as "enabled" with no way to ever trigger.
- Document/enforce whether `conditions` is AND or OR combined, and align legacy-vs-explicit fallback logic so that both forms fail closed (raise/log) rather than fail open (silently no-op) on malformed input.

### Proof of Concept
Unit test to add to `plugins/hookify` test suite:
```python
from hookify.core.config_loader import Rule
from hookify.core.rule_engine import RuleEngine

def test_malformed_explicit_condition_silently_disables_block_rule():
    frontmatter = {
        "name": "block-rm-rf",
        "enabled": True,
        "event": "bash",
        "action": "block",
        # Malformed: missing 'field', simulating attacker/generator-controlled
        # frontmatter or a parser quirk in extract_frontmatter().
        "conditions": [{"operator": "regex_match", "pattern": r"rm\s+-rf"}],
    }
    rule = Rule.from_dict(frontmatter, "Dangerous rm command blocked!")

    engine = RuleEngine()
    input_data = {
        "hook_event_name": "PreToolUse",
        "tool_name": "Bash",
        "tool_input": {"command": "rm -rf /"},
    }
    result = engine.evaluate_rules([rule], input_data)

    # Expected (intended) behavior: block rule should deny the dangerous command.
    # Actual behavior: result == {} because the empty-field condition never matches,
    # silently allowing the operation despite action == "block".
    assert result != {}, "Block rule was silently bypassed due to malformed condition"
```
Compare against the equivalent legacy form (`{"pattern": r"rm\s+-rf", "event": "bash", "action": "block", ...}`) which correctly infers `field="command"` and blocks the same input — demonstrating the semantic divergence between legacy and explicit rule forms.     @classmethod
    def from_dict(cls, frontmatter: Dict[str, Any], message: str) -> 'Rule':
        """Create Rule from frontmatter dict and message body."""
        # Handle both simple pattern and complex conditions
        conditions = []

        # New style: explicit conditions list
        if 'conditions' in frontmatter:
            cond_list = frontmatter['conditions']
            if isinstance(cond_list, list):
                conditions = [Condition.from_dict(c) for c in cond_list]

        # Legacy style: simple pattern field
        simple_pattern = frontmatter.get('pattern')
        if simple_pattern and not conditions:
            # Convert simple pattern to condition
            # Infer field from event
            event = frontmatter.get('event', 'all')
            if event == 'bash':
                field = 'command'
            elif event == 'file':
                field = 'new_text'
            else:
                field = 'content'

            conditions = [Condition(
                field=field,
                operator='regex_match',
                pattern=simple_pattern
            )]

        return cls(
            name=frontmatter.get('name', 'unnamed'),
            enabled=frontmatter.get('enabled', True),
            event=frontmatter.get('event', 'all'),
            pattern=simple_pattern,
            conditions=conditions,
            action=frontmatter.get('action', 'warn'),
            tool_matcher=frontmatter.get('tool_matcher'),
            message=message.strip()
        )

def load_rules(event: Optional[str] = None) -> List[Rule]:
    """Load all hookify rules from .claude directory.

    Args:
        event: Optional event filter ("bash", "file", "stop", etc.)

    Returns:
        List of enabled Rule objects matching the event.
    """
    rules = []

    # Find all hookify.*.local.md files
    pattern = os.path.join('.claude', 'hookify.*.local.md')
    files = glob.glob(pattern)

    for file_path in files:
        try:
            rule = load_rule_file(file_path)
            if not rule:
                continue

            # Filter by event if specified
            if event:
                if rule.event != 'all' and rule.event != event:
                    continue

            # Only include enabled rules
            if rule.enabled:
                rules.append(rule)

        except (IOError, OSError, PermissionError) as e:
            # File I/O errors - log and continue
            print(f"Warning: Failed to read {file_path}: {e}", file=sys.stderr)
            continue
        except (ValueError, KeyError, AttributeError, TypeError) as e:
            # Parsing errors - log and continue
            print(f"Warning: Failed to parse {file_path}: {e}", file=sys.stderr)
            continue
        except Exception as e:
            # Unexpected errors - log with type details
            print(f"Warning: Unexpected error loading {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
            continue

    return rules

    def _rule_matches(self, rule: Rule, input_data: Dict[str, Any]) -> bool:
        """Check if rule matches input data.

        Args:
            rule: Rule to evaluate
            input_data: Hook input data

        Returns:
            True if rule matches, False otherwise
        """
        # Extract tool information
        tool_name = input_data.get('tool_name', '')
        tool_input = input_data.get('tool_input', {})

        # Check tool matcher if specified
        if rule.tool_matcher:
            if not self._matches_tool(rule.tool_matcher, tool_name):
                return False

        # If no conditions, don't match
        # (Rules must have at least one condition to be valid)
        if not rule.conditions:
            return False

        # All conditions must match
        for condition in rule.conditions:
            if not self._check_condition(condition, tool_name, tool_input, input_data):
                return False

        return True

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
