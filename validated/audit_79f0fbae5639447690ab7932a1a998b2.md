Zest v2's position representation fundamentally differs from Panoptic's: positions are tracked via a bitmask (one bit per asset id) rather than a user-supplied list of `tokenId`s validated against a stored XOR-hash fingerprint. In `market-vault.clar`, each account's `mask` is stored on-chain and asset lists are derived deterministically from it via `mask-to-list-collateral`/`mask-to-list-debt`, which iterate a fixed range and test individual bits [1](#0-0)  — a bit is either set or not, so no duplicate-entry construction analogous to Panoptic's `positionIdList` is possible. The `get-assets` helper in `market.clar` likewise derives the asset list strictly from the enabled/user mask intersection, with no externally supplied list that must be checked against a stored fingerprint [2](#0-1) . Since there is no user-controlled list-plus-hash-matching mechanism analogous to `_validatePositionList()`/`updatePositionsHash()`, the "duplicate tokenId inflates collateral/premium accounting to fake solvency" bug class has no reachable analog in this codebase.

  (let ((init { mask: mask, offset: offset, result: (list) })

(define-private (mask-to-list-iter (p uint) (acc {mask: uint, offset: uint, result: (list 64 uint)}))
  (let ((mask (get mask acc))
        (offset (get offset acc)))
    (if (> (bit-and mask (pow u2 p)) u0)
      ;; Bit is set - add to result
      (let ((result (get result acc))
            (value (if (is-eq offset u0) p (- p offset)))
            (new (as-max-len? (append result value) u64)))
        (merge acc { result: (unwrap-panic new) }))
      ;; Bit not set - skip
      acc)))

(define-private (mask-to-list-collateral (mask uint))
  (mask-to-list-internal mask u0 ITER-UINT-64))
