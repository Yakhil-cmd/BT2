### Title
`ProxyType::NonTransfer` on Polkadot/Westend relay chain falsely claims itself a superset of `Auction`, letting a `NonTransfer` proxy grant an `Auction` sub-proxy that reaches the `Registrar::swap` call `NonTransfer` itself is denied - (File: polkadot/runtime/westend/src/lib.rs)

### Summary
`polkadot/runtime/westend/src/lib.rs` defines `ProxyType::is_superset` with a catch-all `(ProxyType::NonTransfer, _) => true`, i.e. `NonTransfer` declares itself a superset of *every* other `ProxyType`, including `Auction`. But `ProxyType::Auction`'s `filter` admits `RuntimeCall::Registrar(..)` unconditionally (any `paras_registrar` call, including `swap`), while `NonTransfer`'s own `filter` explicitly excludes `Registrar::swap` (comment: "Specifically omitting Registrar `swap`"). Because `pallet_proxy::do_proxy` gates `add_proxy`/`remove_proxy` solely on `is_superset` (not on `filter`) before dispatching, a delegate holding only a `NonTransfer` proxy can use it to add an `Auction` proxy on the delegator's account and thereby reach `Registrar::swap`, a capability `NonTransfer` itself does not admit. This is exactly the bug class already identified and fixed for `NonTransfer`/`Governance` on Asset Hub Westend (see `prdoc/pr_12769.prdoc` and the regression test in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2518-2559`), but the relay-chain runtime (`polkadot/runtime/westend/src/lib.rs`) still uses the old unconditional `(ProxyType::NonTransfer, _) => true` rule and was not covered by that fix or its lattice-wide regression test.

### Finding Description
`pallet_proxy::do_proxy` (`substrate/frame/proxy/src/lib.rs:994-1023`) enforces privilege containment for nested proxy management calls purely through `ProxyType::is_superset`, independent of `filter`:

```rust
match c.is_sub_type() {
    Some(Call::add_proxy { ref proxy_type, .. }) |
    Some(Call::remove_proxy { ref proxy_type, .. })
        if !def.proxy_type.is_superset(proxy_type) =>
    {
        false
    },
    ...
    _ => def.proxy_type.filter(c),
}
``` [1](#0-0) 

On `polkadot/runtime/westend/src/lib.rs`:
```rust
fn is_superset(&self, o: &Self) -> bool {
    match (self, o) {
        (x, y) if x == y => true,
        (ProxyType::Any, _) => true,
        (_, ProxyType::Any) => false,
        (ProxyType::NonTransfer, _) => true,
        _ => false,
    }
}
``` [2](#0-1) 

`Auction`'s filter:
```rust
ProxyType::Auction => matches!(
    c,
    RuntimeCall::Auctions(..) |
        RuntimeCall::Crowdloan(..) |
        RuntimeCall::Registrar(..) |
        RuntimeCall::Slots(..)
),
``` [3](#0-2) 

`NonTransfer`'s filter explicitly excludes `Registrar::swap`:
```rust
RuntimeCall::Registrar(paras_registrar::Call::register{..}) |
RuntimeCall::Registrar(paras_registrar::Call::deregister{..}) |
// Specifically omitting Registrar `swap`
RuntimeCall::Registrar(paras_registrar::Call::reserve{..}) |
``` [4](#0-3) 

Because `is_superset(NonTransfer, Auction) == true`, `do_proxy`'s guard `!def.proxy_type.is_superset(proxy_type)` never triggers for `NonTransfer` adding/removing an `Auction` proxy, so the call falls through to `def.proxy_type.filter(c)`. `NonTransfer` admits `RuntimeCall::Proxy(..)` unconditionally, so `add_proxy(delegate, Auction, delay)` passes. The delegate can then dispatch `Registrar::swap` through the newly-granted `Auction` proxy against the delegator's account, a call `NonTransfer` itself is barred from reaching directly. This exactly mirrors the already-patched `NonTransfer`/`Governance` bug (`prdoc/pr_12769.prdoc`) — the lattice check the asset-hub fix added (`proxy_type_superset_relation_matches_call_filters` in `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2493-2516`) was never applied to `polkadot/runtime/westend/src/lib.rs`, so the same defect class survives there for `Auction`.

### Impact Explanation
This breaks the intended containment guarantee of `pallet_proxy`'s permission lattice: a proxy holder with a restricted `NonTransfer` delegation obtains a path to `Registrar::swap`, a registrar-privileged operation over parachain/parathread registrations, which `NonTransfer` was deliberately designed to deny (as the "Specifically omitting Registrar `swap`" comment shows the designers considered `swap` sensitive enough to carve out). This is an unauthorized-dispatch / authorization-bypass bug matching CWE-269/CWE-276 (incorrect trust/permission management, analogous to the referenced Amplify CLI advisory), though the concrete blast radius (parachain deregistration/manager swap rather than direct fund theft) is narrower than the AWS case.

### Likelihood Explanation
The trigger requires only a standard, unprivileged flow already wired in production: a delegator adds a `NonTransfer` proxy for a delegate via `pallet_proxy::add_proxy` (a normal signed extrinsic), and the delegate then calls `pallet_proxy::proxy` to dispatch `Proxy::add_proxy(target, Auction, 0)` on the delegator's behalf, followed by a second `proxy` call dispatching `Registrar::swap` through the new `Auction` sub-proxy. No governance, root, or stolen keys are needed — only that some account has already granted a `NonTransfer` proxy, which is a widely used, ordinary proxy type.

### Recommendation
Apply the same fix used for `NonTransfer`/`Governance` on Asset Hub Westend (`prdoc/pr_12769.prdoc`) to `polkadot/runtime/westend/src/lib.rs` (and check the sibling Rococo/`substrate/bin/node/runtime` definitions using the same unconditional `(ProxyType::NonTransfer, _) => true` pattern): replace the catch-all with explicit, verified pairs, excluding `Auction` (and any other type whose `filter` admits calls `NonTransfer` denies) from `NonTransfer`'s declared supersets. Extend the lattice regression test (`proxy_type_superset_relation_matches_call_filters`) to the relay-chain runtime crates to prevent regressions.

### Proof of Concept
Not executed against a live network. A minimal FRAME integration test (using `substrate/frame/proxy/src/tests.rs` harness patterns or the westend runtime test scaffolding) would:
1. `Proxy::add_proxy(delegator, delegate, ProxyType::NonTransfer, 0)`.
2. `Proxy::proxy(delegate, delegator, None, Box::new(RuntimeCall::Proxy(Call::add_proxy{ delegate: delegate2, proxy_type: ProxyType::Auction, delay: 0 })))` — expected under correct containment: `Err(DispatchError::BadOrigin)`/filtered; actual (per current `is_superset`): `Ok`, `ProxyExecuted{result: Ok(())}`.
3. `Proxy::proxy(delegate2, delegator, None, Box::new(RuntimeCall::Registrar(paras_registrar::Call::swap{ .. })))` — succeeds despite `NonTransfer` denying `Registrar::swap` directly.

I did not run this in a sandbox; the guard logic and filter/`is_superset` mismatch are demonstrated directly from the cited source, mirroring the already-confirmed and fixed analog on Asset Hub Westend (`prdoc/pr_12769.prdoc`, test at `cumulus/parachains/runtimes/assets/asset-hub-westend/tests/tests.rs:2518-2559`), which is strong circumstantial evidence the same defect is live and unpatched on the relay-chain runtime. This should be verified with an actual `#[test]` execution before filing, and the `Registrar::swap` semantics (impact on deposits/managers) should be double-checked in `polkadot/runtime/common/src/paras_registrar/mod.rs` to size the exact severity.
