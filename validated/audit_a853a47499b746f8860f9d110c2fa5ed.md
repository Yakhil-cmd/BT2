Let me look at the `GasTarget` usage as a divisor and the `checkConsistency` path more carefully.### Title
Missing lower-bound validation on `kip71.gastarget` governance parameter causes division-by-zero panic in `NextMagmaBlockBaseFee`, halting consensus on all honest nodes — (File: `params/kip71_config.go`)

---

### Summary

The `kip71.gastarget` governance parameter is registered with `noopFormatChecker`, accepting any `uint64` value including `0`. Once a `gasTarget = 0` vote is ratified, every subsequent call to `NextMagmaBlockBaseFee` with a non-zero `parentGasUsed` performs an integer division by zero, panicking all validating nodes and permanently halting the chain. The sibling parameter `kip71.basefeedenominator` has an explicit non-zero guard in both its `FormatChecker` and in `NextMagmaBlockBaseFee`, confirming the authors were aware of the risk — but the same protection was never applied to `kip71.gastarget`.

---

### Finding Description

**Root cause 1 — missing `FormatChecker` in `kaiax/gov/param.go`:**

`Kip71BaseFeeDenominator` correctly rejects zero:

```go
Kip71BaseFeeDenominator: {
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0          // zero explicitly rejected
    },
```

`Kip71GasTarget` uses `noopFormatChecker`, which always returns `true`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker, // any uint64, including 0, accepted
    ...
    DefaultValue: uint64(30000000),
},
``` [1](#0-0) 

**Root cause 2 — missing zero-guard in `params/kip71_config.go`:**

`NextMagmaBlockBaseFee` explicitly guards `BaseFeeDenominator == 0` with a fallback value, but has no equivalent guard for `GasTarget == 0`:

```go
var baseFeeDenominator *big.Int
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget   // ← no zero-guard here
```

When `parentGasUsed > gasTarget` (i.e., `parentGasUsed > 0`), the code reaches:

```go
y := x.Div(x, new(big.Int).SetUint64(gasTarget))  // integer division by zero → panic
```

Both the increase path (line 102) and the decrease path (line 120) divide by `gasTarget`. [2](#0-1) 

**Root cause 3 — `checkConsistency` returns `nil` for `Kip71GasTarget` without any bounds check:**

```go
case gov.GovernanceDeriveShaImpl, ..., gov.Kip71GasTarget, gov.Kip71MaxBlockGasUsedForBaseFee, ...:
    return nil
``` [3](#0-2) 

**Execution path to panic:**

`validateHeader` → `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee(...)` → division by zero. [4](#0-3) 

---

### Impact Explanation

Once the ratified `gasTarget = 0` takes effect at epoch boundary `(k+1)*epoch`, every honest node that attempts to validate the first block of that epoch calls `VerifyMagmaHeader`, which calls `NextMagmaBlockBaseFee`. Because real blocks almost always have `parentGasUsed > 0`, the division-by-zero panic fires unconditionally. In Go, an unrecovered panic in a validation goroutine crashes the process. The result is a **permanent consensus halt**: no node can import or produce a valid block, and the chain is irrecoverably stalled until a coordinated emergency patch and restart.

This matches the allowed impact: **consensus divergence / invalid block acceptance on honest nodes**.

---

### Likelihood Explanation

**Trigger:** In `none`-mode governance (any council member may vote; the last vote in the epoch is ratified), a single semi-trusted validator can cast `governance_vote("kip71.gastarget", 0)`. The vote passes `NewVoteData` (format check: `noopFormatChecker` → `true`), passes `checkConsistency` (returns `nil`), is written into `header.Vote`, and is ratified at the next epoch block.

In `single`-mode governance (Mainnet/Kairos), only the governing node can vote, making this a privileged operation. The finding is directly exploitable on any Kaia-compatible chain running `none`-mode governance.

**Likelihood: Low** — requires a malicious or misconfigured council member in `none`-mode governance.

---

### Recommendation

1. **Add a non-zero `FormatChecker` for `Kip71GasTarget`** in `kaiax/gov/param.go`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v > 0   // mirror the BaseFeeDenominator guard
    },
    ...
},
```

2. **Add a defensive zero-guard in `NextMagmaBlockBaseFee`** in `params/kip71_config.go`, mirroring the existing `BaseFeeDenominator` guard:

```go
gasTarget := kc.GasTarget
if gasTarget == 0 {
    gasTarget = DefaultGasTarget  // or return lowerBoundBaseFee
}
```

3. **Add a `checkConsistency` bounds check** for `Kip71GasTarget` in `kaiax/gov/headergov/impl/header.go`, similar to the existing `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` cross-checks.

---

### Proof of Concept

1. Deploy a Kaia-compatible chain with `governance.governancemode = "none"` and Magma fork enabled.
2. As any council member, call:
   ```
   governance_vote("kip71.gastarget", 0)
   ```
3. The vote is accepted — `NewVoteData` succeeds (`noopFormatChecker`), `checkConsistency` returns `nil`, and the vote is written into `header.Vote`.
4. At the next epoch block, the vote is ratified and `GasTarget` is set to `0` in the effective `ParamSet`.
5. The first block of the following epoch has `parentGasUsed > 0` (any block with transactions).
6. `validateHeader` calls `govParamSet.ToKip71Config().VerifyMagmaHeader(header.BaseFee, parent.Number, parent.BaseFee, parent.GasUsed)`.
7. `VerifyMagmaHeader` calls `NextMagmaBlockBaseFee` with `kc.GasTarget = 0`.
8. `parentGasUsed > gasTarget` (i.e., `parentGasUsed > 0`) is true; execution reaches line 102:
   ```go
   y := x.Div(x, new(big.Int).SetUint64(0))  // panic: division by zero
   ```
9. All nodes crash. The chain halts permanently.
