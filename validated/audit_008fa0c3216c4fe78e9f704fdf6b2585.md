### Title
`ValPaused` Top-N Winner Wrongly Demoted to `ValInactive` via Expired `PausedTimeout` on Epoch Block — (`kaiax/valset/impl/transition_context.go`)

### Summary

In `applyEpochTransition`, when a `ValPaused` node wins the top-N stake competition, the branch that clears `PausedTimeout` is intentionally skipped. If that node's `PausedTimeout` is already expired at the epoch block, `applyTimeoutTransition` — which runs unconditionally after the epoch step — immediately demotes it to `ValInactive`. The node ends the pipeline excluded from block production and reward distribution despite having won the stake competition.

### Finding Description

`ApplyAllTransitions` runs three steps in fixed order:

```
applyEpochTransition → applyViolationTransition → applyTimeoutTransition
``` [1](#0-0) 

**Step 1 — `applyEpochTransition`:** `ValPaused` nodes with sufficient stake enter `activeValCompetitors` via `competeOrDemote`. For winners (idx < `MaxValActivePausedCount`), the code guards the `ValActive` assignment:

```go
if potentialActiveVal.State != valset.ValPaused {
    potentialActiveVal.State = valset.ValActive
    potentialActiveVal.IdleTimeout = time.Time{}
    potentialActiveVal.PausedTimeout = time.Time{}   // ← skipped for ValPaused
}
``` [2](#0-1) 

A `ValPaused` winner exits this step still `ValPaused`, with its original `PausedTimeout` untouched.

**Step 3 — `applyTimeoutTransition`:** For every `ValPaused` node, if `PausedTimeout` is non-zero and `BlockTime >= PausedTimeout`, the node is demoted:

```go
case valset.ValPaused:
    if val.PausedTimeout.IsZero() {
        val.PausedTimeout = ctx.BlockTime.Add(ctx.PauseTimeout)
    }
    if !ctx.BlockTime.Before(val.PausedTimeout) {
        val.State = valset.ValInactive   // ← fires on expired timeout
        ...
    }
``` [3](#0-2) 

Because `applyEpochTransition` did not clear `PausedTimeout`, the timeout check fires and the node lands in `ValInactive` — the opposite of what the stake competition result requires.

### Impact Explanation

- The validator is excluded from block production for the entire next epoch despite holding top-N stake.
- Block rewards for that epoch are lost to the validator — an incorrect reward distribution outcome.
- `epochVACountForWrite` (line 140) is computed from `CountByState(ValActive)` immediately after `applyEpochTransition` and before `applyTimeoutTransition`, so the on-chain epoch VA count is written with the node counted as absent from `ValActive`, compounding the state corruption across the epoch boundary. [4](#0-3) 

### Likelihood Explanation

The trigger condition is: a `ValPaused` node's `PausedTimeout` expires on the same block that is an epoch block. Since `applyTimeoutTransition` runs every block, the timeout fires on the first block where `BlockTime >= PausedTimeout`. If that block is an epoch block (determined by block number modulo epoch interval), the bug activates. With typical epoch intervals and `PauseTimeout` durations both being governance parameters, this coincidence is not rare and requires no attacker — it is a deterministic outcome of the state machine for any qualifying `ValPaused` node.

### Recommendation

In `applyEpochTransition`, when a `ValPaused` node wins the top-N competition, either:

1. **Promote it to `ValActive`** (remove the `!= ValPaused` guard and always assign `ValActive` + clear both timeouts), or
2. **Reset `PausedTimeout`** so the node gets a fresh pause window rather than carrying an expired one into `applyTimeoutTransition`.

Option 1 is more consistent with the invariant that top-N stake winners should be active. Option 2 preserves the pause semantics but prevents the immediate demotion.

### Proof of Concept

```go
// Construct a ValPaused node with high stake and an already-expired PausedTimeout.
nodes := valset.NodeMap{
    addr: &valset.Node{
        State:         valset.ValPaused,
        StakingAmount: 1_000_000,                          // above MinStake, wins top-N
        PausedTimeout: blockTime.Add(-time.Second),        // already expired
    },
}

ctx := NewTransitionContext()
ctx.SetBlockCtx(header, true /*isEpoch*/)
ctx.SetGovCtx(gov.ParamSet{MinimumStake: big.NewInt(1000)})
ctx.SetABv2TransitionParam(system.ABv2TransitionParam{
    MaxValActivePausedCount: 10,
    IdleTimeout:             24 * time.Hour,
    PauseTimeout:            1 * time.Hour,
})
ctx.SetSlotsCtx(5, 3)
ctx.SetVRankCtx(nil, nil, nil)

result := ctx.ApplyAllTransitions(nodes)

// Bug: node is ValInactive, not ValActive or ValPaused-with-fresh-timeout.
assert.Equal(t, valset.ValInactive, result.Nodes[addr].State)
// Should be: assert.Equal(t, valset.ValActive, result.Nodes[addr].State)
```
