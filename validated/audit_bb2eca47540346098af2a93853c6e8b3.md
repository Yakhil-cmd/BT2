### Title
Sustained high utilization can permanently freeze a market through index-value `i128` overflow - (File: `common/src/rates/simulate.rs`)

### Summary
Accrual multiplies total scaled debt and supply by their RAY indexes before the configured borrow-index ceiling can take effect. Once a sufficiently large, highly utilized market reaches the resulting `i128` value ceiling, `accrue_step` panics inside `scaled_to_original`; because user exits, repayments, liquidations, and explicit index updates all accrue first, the market can become permanently unusable. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`accrue_step` first calculates `borrowed_original` and `supplied_original` with `scaled_to_original`, and `scaled_to_original` is a checked `Ray` multiplication rather than a saturating or index-capped operation. [4](#0-3) [2](#0-1)  The borrow-index cap is only applied later by `update_borrow_index`, after these total-value calculations have already run. [5](#0-4) [6](#0-5) 

The permissionless `Controller::update_indexes` endpoint forwards to the pool's owner-gated `update_indexes`, which invokes `ops::market::accrue`; pool accrual then calls `accrue_step` for each compound interval. [7](#0-6) [8](#0-7) [9](#0-8) [10](#0-9)  The repository's boundary test demonstrates that a one-billion-token, 18-decimal market at sustained 98% utilization reaches the checked-value ceiling before `MAX_BORROW_INDEX_RAY`, after which both withdrawal and repayment fail with `MathOverflow`. [3](#0-2) 

### Impact Explanation
This is permanent freezing of user funds in the affected market. Once the scaled-debt or scaled-supply product exceeds `i128::MAX`, any subsequent accrual aborts before the capped replacement index can be stored; state then remains at the already-overflowing boundary, so calls that synchronize the market continue to fail. [1](#0-0) [6](#0-5) [11](#0-10) 

The impact is not limited to the attacker's position: suppliers cannot withdraw, borrowers cannot repay, and liquidators cannot service the market. The in-repo test explicitly demonstrates `withdraw` and `repay` reverting with `MathOverflow` after the cliff. [12](#0-11) 

### Likelihood Explanation
The attack requires substantial funded positions and sustained high utilization, but no privileged call. An unprivileged account can supply assets through `Controller::supply`, establish collateral and borrow through `Controller::borrow`, and then repeatedly advance accrual through permissionless `Controller::update_indexes`. [13](#0-12) [7](#0-6)  Ordinary utilization caps constrain new borrows, but interest accrual can raise utilization and the borrow index after the position is opened; the demonstrated reproduction uses ordinary supply and borrow flows before invoking index updates. [14](#0-13) 

### Recommendation
Make accrual bounded before value multiplication rather than assuming the index cap is reached first. In `accrue_step`, compute utilization and rewards through a saturating or widened path, or clamp `borrow_index`/`supply_index` before `scaled_to_original` can produce more than `i128::MAX`. More generally, apply the index cap before evaluating `scaled * index`, and add a regression test proving that `update_indexes`, `withdraw`, `repay`, and `liquidate` remain callable at the maximum representable total-value boundary. [15](#0-14) [6](#0-5) 

### Proof of Concept
1. In an 18-decimal market using a steep borrow curve, an attacker supplies a very large asset balance and supplies sufficient collateral to borrow approximately 98% of that market's liquidity. The repository test instantiates this as `principal = 1_000_000_000 * 10^18` and `debt = principal * 98 / 100`. [16](#0-15) 
2. The attacker repeatedly calls permissionless `Controller::update_indexes(caller, vec![hub_asset])` as ledger time advances. Each call reaches pool accrual through `markets::update_indexes`, `pool.update_indexes`, `ops::market::accrue`, `global_sync`, and `accrue_step`. [8](#0-7) [9](#0-8) [10](#0-9) 
3. When `borrowed * borrow_index` or `supplied * supply_index` exceeds `i128::MAX`, `scaled_to_original` panics before `update_borrow_index` stores the capped index. [1](#0-0) [6](#0-5) 
4. Thereafter `Controller::withdraw` and `Controller::repay` both fail with `MathOverflow`; the repository's regression test asserts exactly those failures and verifies that the stored index never reached `MAX_BORROW_INDEX_RAY`. [17](#0-16)

/// The cliff. A billion whole tokens is `1e36` raw ray; the value ceiling is
/// `i128::MAX`, 170 times that. At the XLM curve's steep segment the index
/// grows past 170x in a few years, and the next accrual panics inside
/// `scaled_to_original`. Every verb accrues first, so the market freezes:
/// no repay, no withdraw, no liquidation. The index cap never engages.
#[test]
fn a_whale_market_at_sustained_high_utilization_hits_the_ray_value_ceiling_before_the_index_cap() {
    let mut t = LendingTest::new()
        .with_market(big("BIG18", 18, xlm_curve()))
        .with_market(col())
        .with_max_utilization_disabled_all_markets()
        .build();
    lift_caps(&t, "BIG18", 18);
    lift_caps(&t, "COL", 7);
    let principal = BILLION * 10i128.pow(18);
    t.supply_raw(BOB, "BIG18", principal);
    let debt = principal / 100 * 98;
    t.supply_raw(ALICE, "COL", BILLION * 10_000_000 * 3);
    t.borrow_raw(ALICE, "BIG18", debt);

    let mut years = 0u32;
    let failure = loop {
        years += 1;
        assert!(
            years <= 40,
            "no cliff within 40 years; the bound in docs/reference/formulas.md is wrong"
        );
        t.advance_time(YEAR_SECS);
        if let Err(e) = t.try_update_indexes_for(&["BIG18"]) {
            break e;
        }
    };
    let failed: Result<(), soroban_sdk::Error> = Err(failure);
    assert_contract_error(failed, errors::MATH_OVERFLOW);
    let last = book(&t, "BIG18");
    assert!(
        last.borrow_index < MAX_BORROW_INDEX_RAY,
        "the index cap did not engage before the value overflow"
    );
    // The market is frozen: exits and repayments accrue first and hit the same panic.
    assert_contract_error(t.try_withdraw_raw(BOB, "BIG18", 1), errors::MATH_OVERFLOW);
    assert_contract_error(t.try_repay(ALICE, "BIG18", 1.0), errors::MATH_OVERFLOW);

pub(crate) fn global_sync(env: &Env, cache: &mut Cache) {
    if !cache.needs_accrual() {
        return;
    }

    let mut remaining = cache.elapsed_ms();
    while let Some(nonzero) = NonZeroU64::new(remaining) {
        let chunk = nonzero.get().min(MAX_COMPOUND_DELTA_MS);
        accrue_chunk(env, cache, chunk);
        remaining = remaining.saturating_sub(chunk);
    }

    cache.mark_accrued();
}

/// Applies one compound step of `delta_ms` to indexes and protocol revenue.
///
/// The arithmetic lives in [`accrue_step`], shared with the read-only
/// `simulate_update_indexes` so the view and the mutator cannot drift.
fn accrue_chunk(env: &Env, cache: &mut Cache, delta_ms: u64) {
    let step = accrue_step(
        env,
        cache.params(),
        cache.borrowed(),
        cache.supplied(),
        cache.borrow_index(),
        cache.supply_index(),
        delta_ms,
    );

    cache.set_borrow_index(step.borrow_index);
    cache.set_supply_index(step.supply_index);
    cache.accrue_revenue(step.revenue_shares);
}
